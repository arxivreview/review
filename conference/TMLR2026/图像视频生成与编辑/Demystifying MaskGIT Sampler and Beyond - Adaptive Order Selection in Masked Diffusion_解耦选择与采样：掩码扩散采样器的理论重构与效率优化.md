> 离散掩码扩散模型在少步采样中面临计算冗余与质量退化的双重困境，现有启发式方法缺乏理论解释。本文切入点在于揭示 MaskGIT 采样器隐含的温度采样机制，将其转化为可解释的“先选后采”（Choose-Then-Sample, CTS）框架，并通过部分缓存与混合调度策略提升效率。其价值在于为离散扩散加速提供了理论基石与实用工具，但温度采样导致的多样性损失在文本域仍未完全解决。

## 研究背景

掩码扩散模型通过逐步替换掩码 token 生成数据，其采样效率取决于去掩码顺序与 token 选择策略。传统方法如 MaskGIT 采用“先采后选”策略，即先对每个位置采样 token 并计算置信度，再选择高置信度位置进行更新。这种策略在少步采样中表现优异，但随步数增加性能显著退化，且缺乏理论解释。理解这一退化机制的关键在于识别采样过程中的隐式偏差，以及探索更高效的去掩码顺序优化方法。

离散扩散模型的采样加速研究长期依赖启发式调度或蒸馏技术，但 MaskGIT 作为代表性方法，其性能随步数增加而下降的现象未被充分解释。主流路线如自适应 token 选择（Kim et al., 2025）和 Halton 调度（Besnier et al., 2025）分别聚焦于利用或探索去掩码顺序，但缺乏统一的理论框架来平衡两者。本文切入点在于通过理论分析揭示 MaskGIT 的隐式温度采样机制，将其转化为可解释的 CTS 框架，并在此基础上提出部分缓存与混合调度策略，以在少步采样中同时提升效率与质量。

## 核心方法

### 方法参照系

掩码扩散采样通常采用“先采后选”策略，即对每个位置独立采样 token 并计算置信度，再选择高置信度位置更新。本文问题与该通用流程的关键差异在于：MaskGIT 的 Gumbel-top-k 机制隐含了温度采样，导致随步数增加性能退化，且无法直接应用部分缓存等效率优化技术。

### Moment Sampler：从隐式温度采样到显式 CTS

MaskGIT 的 Gumbel-top-k 采样机制在 $N \gg k$ 条件下可近似为对 $\beta$-范数加权的分布采样，其中 $\beta = 1 + 1/\alpha$。这一发现揭示了 MaskGIT 隐含的温度采样机制，解释了其随步数增加性能退化的原因。本文提出 Moment Sampler，采用“先选后采”策略，先基于 $\beta$-范数选择去掩码位置，再对选定位置进行温度采样。

$$
(i_1, \dots, i_k) = \arg\top_k_{i \in [N]} \{ \log \|p_i\|_\beta^\beta + \xi_i \}
$$

该公式表明，位置选择基于 $\beta$-范数加权，而非原始置信度，从而解耦了位置选择与 token 采样。这一设计解决了 MaskGIT 中位置选择与 token 采样耦合导致的隐式偏差，使采样过程更可解释且易于优化。

### Partial Caching 与 Hybrid 调度

CTS 框架允许对部分位置进行缓存，以近似更长轨迹而不增加计算成本。Partial Caching 将去掩码集合 $I$ 分为 $A$ 和 $B$，对 $A$ 进行全量计算，对 $B$ 使用缓存的 Key-Value 向量进行近似计算。

$$
\text{Cost}(B) \approx \frac{|I|}{D} \times \text{Cost}(\text{Full})
$$

该公式表明，Partial Caching 的计算成本与去掩码比例成正比，而非全量计算。Hybrid 调度则结合 Halton 序列（探索）与置信度排序（利用），平衡去掩码顺序的多样性与准确性。这一设计解决了单一策略在少步采样中效率或质量不足的问题，实现了 1.5-2 倍加速。

## 实验评估

实验在 ImageNet 512（图像）和 OpenWebText（文本）上进行，基线包括 MaskGIT、Halton 调度和自适应 token 选择。本文方法在 8 步采样时 FID 优于 MaskGIT，且计算时间加速 1.5-2 倍。在文本域，禁用温度采样（$\gamma=1$）后，Hybrid 策略在保持质量的同时提升了多样性。

消融实验显示，Partial Caching 在 GPU 依赖下效率增益存在波动，而 Hybrid 调度对质量提升贡献稳定。温度采样在图像域是性能主导因素，但在文本域显著降低多样性，表明温度参数需根据任务特性调整。

评估边界方面，论文未报告置信区间，且 Partial Caching 的效率增益依赖硬件特性。代码未公开，超参数细节有限，可复现性受限。

## 关联研究分析

从问题动机看，本文与连续扩散的调度优化（如 HSO）不同，后者聚焦于时间步分配，而本文聚焦于离散去掩码顺序。这一差异源于离散扩散的顺序依赖特性，连续扩散的数值积分理论无法直接迁移。从方法设计看，本文的 Partial Caching 与连续扩散的特征缓存（如 DeepCache）类似，但前者针对 Transformer 的 Key-Value 冗余，后者针对 U-Net 的中间层特征。这一差异反映了离散与连续扩散在架构上的本质区别，离散扩散的并行化潜力更依赖于注意力机制的局部性。

## 总结

本文要解决的核心矛盾是离散掩码扩散模型在少步采样中计算冗余与质量退化的权衡。本文抓住 MaskGIT 隐含温度采样机制这一被忽略的点，通过理论分析将其转化为可解释的 CTS 框架，并提出 Partial Caching 与 Hybrid 调度策略。实验证明，该方法在 8 步采样时 FID 优于 MaskGIT，且计算时间加速 1.5-2 倍。本文的边界在于温度采样在文本域导致的多样性损失未完全解决，且 Partial Caching 的效率增益依赖硬件特性。当温度参数 $\alpha$ 随步数动态调整时，能否在保持多样性的同时维持质量，论文未给出回答。
