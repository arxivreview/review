# ACL-Findings2026最新论文 ｜HiRAS: A Hierarchical Multi-Agent Framework for Paper-to-Code Generation and Execution ｜层级监督多智能体框架

作者：Hanhua Hong、Yizhi LI、Jiaoyan Chen 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_8d47401e236b)

> 科研复现任务要求智能体从论文文本生成可执行代码并验证结果，但现有顺序流水线缺乏全局纠错机制，导致早期错误在后续阶段不可逆地传播。HIRAS 通过引入主动检查中间产物的层级管理器，将固定调用序列改造为动态监督循环，解决了执行阶段因依赖关系错误导致的崩溃问题。该框架在开源模型上实现了超越专有模型基线的复现准确率，但其评估协议修正与计算开销的权衡仍需进一步审视。

## 研究背景

实验复现是科学累积的基础，然而仅约 20% 的论文发布完整代码，迫使研究者依赖 LLM 智能体自动重建实验管线。这一过程涉及从自然语言描述到结构化代码的转换，以及代码在复杂目录结构中的执行验证，核心难点在于跨文件依赖的一致性。

主流方案如 PaperCoder 和 AutoReproduce 采用固定顺序的多智能体流水线，将任务分解为规划、分析、编码等阶段。这种设计的瓶颈在于缺乏全局监督：早期阶段的细微错误（如依赖分析遗漏）会直接导致后续编码或执行失败，且系统无法回溯修正。相比之下，层级架构在强化学习和具身智能中已证明能有效管理复杂多智能体协作，但此前未应用于科研复现场景。HIRAS 的切入点在于将管理器从被动的消息中继转变为主动的监督者，通过检查共享工作区中的中间产物，动态决定何时重调用特定智能体以纠正错误。

## 核心方法

### 方法参照系

本文问题属于多智能体协作中的任务分解与协调问题。标准流程通常采用扁平化或顺序调用，各智能体独立执行后传递结果。本文的关键差异在于引入层级结构，并赋予管理器对中间产物的检查权与重调用权，打破了单向信息流。

### 层级监督架构

设计动机在于解决顺序流水线中错误传播不可逆的问题。HIRAS 定义智能体元组 $A = (LLM, Mem, T, E, K)$，其中 $E$ 为共享工作区，$T = \{list\_dir, read\_file, write\_file\}$ 为文件系统工具。管理器通过调用 $invoke(A_{sub}, p)$ 启动子智能体，并在子智能体完成后执行检查函数：

$$
Check(A_{mgr}, A_{sub}) = \begin{cases}
Reinvoke(A_{sub}, p') & \text{if } Artifact_{sub} \text{ is incomplete or erroneous} \\
Proceed(A_{next}) & \text{otherwise}
\end{cases}
$$

该公式表明，管理器并非简单传递消息，而是基于工作区状态动态决定流程走向。当检测到产物缺失或幻觉时，管理器生成修正提示 $p'$ 并重调用子智能体，从而在错误扩散前将其拦截。

### 细粒度阶段分解

设计动机在于降低单次调用的认知负荷，提升错误定位精度。HIRAS 将复现流程分解为规划、分析、编码、执行四个细粒度阶段，每个阶段由专用智能体处理。规划阶段进一步拆分为总体计划、架构设计、依赖分析和配置生成四个子任务，形成计划集 $Pln = \{Pln_{overall}, Pln_{arch}, Pln_{dep}, Pln_{config}\}$。这种分解使得管理器能够针对特定阶段的失败（如依赖分析错误）精准重调用对应智能体，而非重启整个流程。

## 实验评估

实验在 PaperBench 和 Paper2Code 基准上进行，使用 Qwen3-Coder-480B 和 DeepSeek-v3.1-Terminus 作为骨干模型。基线包括 PaperCoder 和 AutoReproduce，但缺乏基于强化学习训练的智能体对比，这可能低估了训练派方法在长程任务中的潜力。

| 方法 | 骨干模型 | PaperBench-CodeDev (%) | PaperBench 全量 (%) |
| :--- | :--- | :--- | :--- |
| PaperCoder | DeepSeek-v3.1 | 40.8 | 34.9 |
| AutoReproduce | DeepSeek-v3.1 | 41.5 | 35.8 |
| HIRAS | DeepSeek-v3.1 | 57.4 | 43.1 |
| HIRAS | Qwen3 | 45.7 | 34.3 |

HIRAS 在 DeepSeek-v3.1 上取得 57.4% 的 PaperBench-CodeDev 成绩，较最强基线提升 15.9 个百分点，且在全量 PaperBench 上超越使用专有模型的先前最佳结果 51.1%。

消融实验显示，仅引入层级监督即可带来约 10% 的性能提升，而细粒度分解与迭代精炼的边际收益相对较小。值得注意的是，从 CodeDev 子集到全量基准的性能大幅下降（如 DeepSeek-v3.1 从 57.4% 降至 43.1%），表明执行阶段的依赖错误仍是主要瓶颈，而非代码生成质量。

评估协议方面，HIRAS 提出 P2C-Ex 修正 Paper2Code 的无参考评估，通过引入仓库文件计数和结构图示，将评估指标与人类专家标注的皮尔逊相关系数从 0.423 提升至 0.862。然而，论文未报告计算开销，且仅在 8 块 H200 GPU 上验证，限制了可复现性评估。

## 关联研究分析

从问题动机看，HIRAS 与 ASearcher 等强化学习路线形成鲜明对比。ASearcher 通过端到端 RL 优化搜索策略，依赖大规模训练数据提升泛化能力；而 HIRAS 采用架构派思路，通过显式监督机制提升鲁棒性。两者的差异根源在于任务特性：科研复现具有明确的中间产物（代码文件），适合结构化检查；而开放式搜索任务缺乏此类可验证的中间状态，更依赖策略优化。

从方法设计看，HIRAS 与 WebWeaver 等双智能体框架同属架构派，但 HIRAS 引入了更复杂的层级结构。WebWeaver 通过规划者与执行者分离解决证据结构化问题，而 HIRAS 通过多级管理器解决执行一致性问题。这种差异反映了任务复杂度的不同：科研复现涉及多阶段依赖，需要更精细的控制粒度；而报告生成任务更关注整体连贯性，双智能体架构已足够。

## 总结

HIRAS 针对科研复现中错误传播不可逆的核心矛盾，通过引入主动监督的层级管理器，将固定流水线改造为动态纠错循环。该方法在开源模型上实现了 57.4% 的 PaperBench-CodeDev 成绩，超越专有模型基线，证明了架构优化在提升复现鲁棒性上的有效性。然而，实验暴露出执行阶段仍是主要瓶颈，且计算开销未量化。当骨干模型能力进一步提升时，层级监督的边际收益是否递减，论文未给出回答。
