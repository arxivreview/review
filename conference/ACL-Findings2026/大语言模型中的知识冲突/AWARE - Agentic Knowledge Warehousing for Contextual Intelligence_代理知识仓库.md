# ACL-Findings2026最新论文 ｜AWARE: Agentic Knowledge Warehousing for Contextual Intelligence ｜代理知识仓库

研究机构：香港科技大学、中国人民大学

作者：Hongjin Qian、Siqi Bao、Zhao Cao 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_d9c104e9df1a)

> 复杂信息检索任务中，答案相关证据稀疏地嵌入在海量异构文本中，导致大语言模型（LLM）在有限上下文预算内无法组装出足够解决任务的证据链。传统检索增强生成（RAG）单次注入缺乏深度，工具集成推理受限于上下文膨胀，均无法应对这种低知识密度下的“数据混乱”。AWARE 将检索重构为代理知识构建过程，通过离线文档结构化与在线多线程探索，将原始文本转化为紧凑的任务条件化知识表示。该框架在 GAIA 等基准上显著优于基线，但其性能增益究竟源于检索策略优化还是底层 LLM 推理能力的差异，尚存疑。

## 研究背景

当 LLM 处理需要多步推理的复杂查询时，其参数化知识因训练语料固定而滞后，必须依赖外部检索。然而，真实世界数据呈现“数据混乱”特征：网页、PDF 等源文件长且噪声大，答案相关信息稀疏分布。这种低知识密度意味着每增加一个 token，对答案的边际信息贡献极小，导致 LLM 上下文窗口迅速被无关内容饱和，无法在预算内隔离并组装关键证据。

现有主流路线在此瓶颈下均显乏力。经典 RAG 在推理前一次性注入检索结果，缺乏处理多层依赖关系的深度；工具集成推理（如 ReAct）虽通过迭代检索增加深度，但所有中间证据均保留在上下文中，随步骤增加导致上下文长度线性增长，限制了广度与可扩展性。AWARE 的切入点在于重新定义检索目标：不再关注如何调用现有检索工具，而是构建一个“知识仓库”，将异构非结构化数据转化为 LLM 可直接消费的最小充分知识子集，从而在有限预算内实现深度与广度的平衡。

## 核心方法

### 方法参照系

本文问题可置于“检索架构优化”类别下，与标准 RAG 流程的关键差异在于：标准 RAG 假设单次检索即可覆盖所需证据，而 AWARE 针对证据稀疏且分散的场景，引入了离线结构化预处理与在线动态探索机制，将“检索-注入”解耦为“结构化-探索-集成-上下文化”四个阶段。

### 离线文档结构化与访问控制

针对原始文本低密度导致的上下文浪费，AWARE 在离线阶段为每个文档 $D$ 生成紧凑的文档头部 $H_D$，编码高层语义范围与结构组织，省略细粒度内容。这一设计动机是解决传统方法中“全量文本暴露”导致的预算无效消耗问题。形式化地，系统将语料库交互解耦为结构化控制与内容访问两个阶段：

$$
\text{Structured control: } \{H_D\} \to C, \quad \text{Content access: } C \to D
$$

其中 $C$ 为文档级控制状态。通过仅检查 $H_D$ 即可评估文档相关性、识别冗余并确定是否深入检查，实现了粗粒度导航与细粒度提取的解耦，避免了在低密度文本上的盲目计算。

### 分层知识构建与 Map-Reduce 集成

在线阶段，AWARE 将任务分解为意图序列 $\{I_i\}$，每个意图 $I_i$ 进一步分解为原子子查询 $\{q_{i,j}\}$。针对意图对齐偏差（即初始子查询未能覆盖所有相关证据），AWARE 采用多线程探索：基于当前证据状态与文档头部信号，动态生成新子查询以填补未覆盖的语义面。为解决证据池扩大后的处理瓶颈，引入 Map-Reduce 证据集成机制：

$$
K_i = \mathcal{R} \left( \{ \mathcal{E}(D) \mid D \in \mathcal{F}(D_i, I_i, \{H_D\}) \} \right)
$$

其中 $\mathcal{F}$ 为基于头部的筛选器，$\mathcal{E}$ 为并行证据提取器，$\mathcal{R}$ 为聚合器。该设计将粗粒度筛选与细粒度提取分离，通过并行处理在推理循环外完成证据聚合，显著降低了推理延迟并提升了可扩展性。最终，各意图子空间 $K_i$ 被组织为任务感知的紧凑上下文 $C$，其有效信息密度 $\delta(C)$ 远高于原始证据 $\delta(R)$，确保 LLM 在有限预算内获得高信噪比输入。

## 实验评估

实验在 GAIA、WebWalkerQA 和 BrowseComp-Plus 三个复杂信息检索基准上进行，基线涵盖 Vanilla RAG、Iterative RAG、ReAct 及 WebThinker 等代表性方法。AWARE 使用 QwQ-32B 作为骨干模型，在 GAIA 平均准确率上达到 53.1%，显著优于 ReAct (QwQ-32B) 的 24.1% 和 WebThinker-32B 的 41.9%；在 WebWalkerQA 上同样取得 53.1% 的最高分，领先 WebThinker-32B 的 41.9%。

| 方法 | GAIA Level 1 | GAIA Level 2 | GAIA Level 3 | GAIA Avg. | WebWalkerQA |
|---|---|---|---|---|---|
| ReAct (QwQ-32B) | 48.7 | 34.6 | 16.7 | 37.8 | 24.1 |
| WebThinker-32B | 53.8 | 44.2 | 16.7 | 44.7 | 41.9 |
| AWARE (QwQ-32B) | 61.5 | 46.2 | 33.3 | 50.5 | 53.1 |

AWARE 在 GAIA Level 3（最难层级）上表现尤为突出，达到 33.3%，而 ReAct 仅为 16.7%，表明其分层知识构建机制在处理深层依赖关系时具有显著优势。然而，论文未提供消融实验数据，无法量化离线文档结构化、多线程探索与 Map-Reduce 集成各组件的独立贡献。此外，BrowseComp-Plus 基准仅报告了准确率与搜索调用次数，未提供具体数值对比，限制了该基准上的性能评估深度。

评估边界方面，论文未报告置信区间或多次运行的方差，数值比较需谨慎。代码仓库已公开，但超参数配置（如文档头部生成模型、筛选阈值）未详细披露，可能影响复现性。指标上，GAIA 使用 Exact Match (EM)，WebWalkerQA 使用 LLM Equivalence Accuracy，两者均侧重最终答案正确性，未评估中间推理步骤的忠实度或证据利用效率。

## 关联研究分析

从问题动机看，AWARE 与知识库中关注的“知识冲突仲裁”存在本质差异。后者聚焦于参数化记忆与外部证据矛盾时的优先级选择，而 AWARE 关注的是证据稀疏性导致的上下文预算不足。这种差异源于任务特性：知识冲突通常发生在事实性问答中，证据相对集中；而 AWARE 处理的复杂信息检索任务中，证据分散且需多步聚合。AWARE 未处理参数知识与外部证据的冲突，而是假设外部证据是唯一的可靠来源，通过结构化手段提升其可用性。

从方法设计看，AWARE 与 ReAct 等工具集成推理方法共享迭代检索逻辑，但关键差异在于上下文管理策略。ReAct 将所有中间观察保留在上下文中，导致长度随步骤线性增长；AWARE 通过离线文档头部筛选与 Map-Reduce 集成，在推理循环外完成证据压缩，仅将紧凑的子空间 $K_i$ 注入上下文。这一设计解决了 ReAct 在长程任务中的上下文膨胀问题，但引入了新的信息丢失风险：文档头部筛选可能误删包含关键细节的文档，且 Map-Reduce 聚合过程可能丢失证据间的细微关联。论文未提供证据支持其偏离“全量上下文保留”共识的理由，也未评估头部筛选的召回率与精确率。

## 总结

AWARE 旨在解决复杂信息检索中低知识密度导致的上下文预算瓶颈，通过离线文档结构化与在线多线程探索，将原始文本转化为紧凑的任务条件化知识表示。实验显示，AWARE 在 GAIA 平均准确率上达到 50.5%，在 WebWalkerQA 上达到 53.1%，显著优于 ReAct 和 WebThinker 等基线。然而，论文未提供消融实验，无法确定性能增益主要源于检索策略优化还是底层 LLM 推理能力的差异。此外，文档头部筛选可能引入信息丢失风险，且未评估其在证据高度分散或噪声极大场景下的鲁棒性。当文档头部筛选的召回率下降时，AWARE 的性能是否仍优于全量上下文保留的 ReAct，论文未给出回答。
