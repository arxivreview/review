# ACL-Findings2026最新论文 ｜InferPilot: Autonomous Inference Attacks Against ML Services With LLM-Based Agents ｜自动化推理攻击代理

作者：Yixin Wu、Rui Wen、Chi Cui 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_739487a9ea85)

> 机器学习服务部署后，非专家难以独立完成成员推断、模型窃取等推理攻击以评估隐私与知识产权风险，而现有通用代理框架在复杂配置搜索中频繁失效。InferPilot 通过多代理隔离架构与任务特定动作空间，将黑盒推理攻击自动化，使非专家能以极低门槛获得接近专家水平的风险评估报告。该工作验证了大语言模型代理在安全评估领域的可行性，但其对目标服务内部结构的依赖与对特定攻击类型的覆盖局限，限制了其在真实异构环境中的泛化能力。

## 研究背景

推理攻击旨在通过黑盒查询推断训练数据成员身份、窃取模型参数或重构敏感属性，是评估机器学习服务鲁棒性的核心手段。然而，执行此类攻击需解决数据集选择、模型架构匹配及超参数调优等组合爆炸问题，这对缺乏专业知识的审计人员构成极高门槛。

传统自动化代理如 MLAgentBench 虽能处理通用机器学习任务，但在安全评估场景中表现出严重的计划错误、指令遵循失败及上下文丢失，导致任务完成率仅 26.3%。现有方法未能将安全评估特有的决策逻辑（如影子模型与目标模型的语义对齐）封装为可执行的动作，导致代理在复杂配置空间中盲目搜索。InferPilot 的切入点在于将安全评估的关键决策步骤显式化为动作空间，并通过多代理架构隔离不同攻击类型的执行上下文，从而在保持黑盒访问限制的同时，实现接近人类专家的攻击精度。

## 核心方法

### 多代理隔离架构

InferPilot 采用 ControllerAgent 与 AttackAgent 的分层设计。ControllerAgent 负责解析用户输入的目标服务信息，确定可执行的攻击类型，并并发初始化独立的 AttackAgent。每个 AttackAgent 仅负责单一攻击类型，拥有独立的记忆空间，避免了单代理长上下文中常见的任务混淆与状态污染。这种隔离机制解决了通用代理在处理多任务时因记忆过载导致的计划崩溃问题，确保各攻击类型互不干扰，即使某一攻击陷入死循环也不影响其他攻击的执行。

### 任务特定动作空间

针对安全评估中数据集、模型及超参数选择的组合爆炸问题，InferPilot 将关键决策封装为原子动作。例如，`Choose Shadow Dataset` 动作接收目标任务描述与输入输出格式，返回语义最相似的候选数据集；`Set Parameters` 动作则根据攻击类型自动设定学习率、批次大小等超参数。这些动作内部集成了领域知识引导，LLM 无需从零推理，只需在预定义的动作空间中选择参数。该设计将复杂的组合搜索转化为序列化的动作调用，显著降低了决策复杂度。

$$
\text{Search Space} = \prod_{i=1}^{|D|} L_{Di} \times |M| \times \prod_{j=1}^{n} k_j
$$

上述公式描述了传统方法中数据集标签、模型架构与超参数的组合空间规模。InferPilot 通过动作封装，将这一高维搜索空间降维为线性动作序列，使 LLM 能在有限步数内完成配置选择。

### 动态策略自适应

InferPilot 并非硬编码工作流，而是允许 LLM 在动作执行过程中根据实时反馈动态调整策略。例如，当目标服务存在查询限制时，代理会自动优化查询策略以最大化信息获取效率。这种动态性源于动作空间的设计：每个动作返回详细的观察结果（如 API 响应、脚本执行日志），LLM 据此决定下一步动作及参数。相比静态脚本，该机制使代理能应对不同目标服务的异构特性，提升了评估的鲁棒性。

## 实验评估

实验在 20 个基于 CIFAR10、STL10、CelebA 等数据集构建的目标服务上进行，涵盖 Xception、ResNet18 等四种架构。基线包括 MLAgentBench（通用代理）与使用 ML-Doctor 框架的人类专家。InferPilot 使用 GPT-4o 作为骨干模型，任务完成率达到 100.0%，显著优于 MLAgentBench 的 26.3%。在成员推断攻击精度上，InferPilot 平均比人类专家低 1.0%，表明其达到了接近专家水平的性能。

| 模型架构 | InferPilot (MI Acc) | Expert (MI Acc) | 差异 |
| :--- | :--- | :--- | :--- |
| Xception | 0.855±0.014 | 0.867±0.005 | -0.012 |
| ResNet18 | 0.855±0.015 | 0.859±0.007 | -0.004 |
| ResNet50 | 0.850±0.006 | 0.855±0.001 | -0.005 |

消融实验显示，引入多代理架构将任务完成率从单代理的 64.9% 提升至 78.0%（在随机选择配置下），而结合任务特定动作空间后进一步达到 100.0%。这表明动作空间的设计对性能提升贡献最大，多代理隔离主要解决了稳定性问题。在模型窃取攻击中，InferPilot 的精度（0.723）显著高于 MLAgentBench（0.531），验证了领域知识引导的有效性。

评估边界方面，实验仅覆盖图像分类任务，未涉及文本或时序数据；目标服务均为本地部署的 Flask API，未测试真实云服务的网络延迟与限流策略。代码已开源，但超参数配置依赖预置脚本，缺乏对未知攻击类型的泛化验证。

## 关联研究分析

从问题动机看，InferPilot 与 GCG 等自动化对抗攻击方法存在本质差异。GCG 聚焦于通过梯度优化生成对抗后缀以突破 LLM 安全对齐，属于白盒或灰盒攻击，目标是破坏模型安全性；而 InferPilot 聚焦于黑盒推理攻击的自动化执行，目标是评估模型隐私与知识产权风险。两者均利用自动化手段降低攻击门槛，但 GCG 依赖模型内部梯度信息，InferPilot 仅依赖黑盒 API 响应，这决定了前者适用于模型开发阶段的安全测试，后者适用于部署后的风险评估。

从方法设计看，InferPilot 与 MLAgentBench 同属 LLM 代理框架，但动作空间设计截然不同。MLAgentBench 采用通用动作（如代码执行、文件操作），依赖 LLM 的通用推理能力解决任务；InferPilot 则采用任务特定动作（如 `Choose Shadow Dataset`），将领域知识硬编码到动作定义中。这种设计牺牲了通用性，换取了安全评估场景下的可靠性。MLAgentBench 在复杂配置搜索中失败，根源在于通用动作无法捕捉安全评估特有的语义对齐需求，而 InferPilot 通过动作封装解决了这一问题。

## 总结

InferPilot 解决了非专家难以独立完成机器学习服务推理攻击评估的核心矛盾，通过多代理隔离与任务特定动作空间，将复杂的组合搜索转化为可执行的原子动作序列。实验证明，该框架在 20 个目标服务上实现了 100.0% 的任务完成率，成员推断精度仅比人类专家低 1.0%，验证了 LLM 代理在安全评估领域的可行性。然而，其性能高度依赖预置的领域知识脚本与特定攻击类型，对未知攻击或异构数据类型的泛化能力未经验证。当目标服务涉及非图像模态或动态变化的 API 接口时，预定义的动作空间是否仍能保持有效的配置选择，论文未给出回答。
