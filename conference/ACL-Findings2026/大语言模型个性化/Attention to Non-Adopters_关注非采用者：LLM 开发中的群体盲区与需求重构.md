# ACL-Findings2026最新论文 ｜Attention to Non-Adopters ｜关注非采用者：LLM 开发中的群体盲区与需求重构

研究机构：美国斯坦福大学、美国约翰斯·霍普金斯大学

作者：Kaitlyn Zhou、Kristina Gligorić、Myra Cheng 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.15951)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.15951)

> 大语言模型（LLM）的个性化研究长期聚焦于如何适配现有用户的风格与偏好，却系统性忽视了占美国人口 66% 的“非采用者”群体。现有基于交互日志和偏好数据的开发范式，将技术能力锁定在数字素养较高的采用者需求上，导致基础数字服务导航、护理协调等高频痛点被边缘化。本文通过定性访谈与定量调查，论证了将非采用者需求纳入设计、评估与部署闭环的必要性，并提出了“能力增强”评估范式。该立场论文揭示了 LLM 普及中的结构性不平等，但其定性结论向量化训练目标的转化路径尚不明确。

## 研究背景

理解本文需厘清“采用者中心”开发范式的局限。LLM 迭代依赖交互日志与用户研究，这些数据天然偏向高频使用者，即采用者。这种数据偏差导致模型优化目标与潜在用户（非采用者）的真实需求脱节。非采用者并非技术抵制者，而是受限于学习成本与界面障碍，其需求具有情境依赖性与低结构化特征，无法被现有基于事实问答或代码生成的基准所捕捉。

当前 LLP 个性化领域主流路线分为参数化适配（如 LoRA）与非参数化检索（如 RAG），二者均假设用户具备基本的数字交互能力，且偏好是静态或可推断的。LaMP 等基准暴露了长程一致性问题，但仍未触及用户群体覆盖的公平性维度。现有评估指标（如 ROUGE）衡量的是文本重叠度，而非用户任务完成度，这使得模型在“回答正确”但“用户无法使用”的场景中得分虚高。本文切入点在于挑战这一默认假设：LLM 的广泛效用不应仅由早期采用者定义，而需通过参与式设计方法，将非采用者的认知负荷与具体生活场景纳入开发闭环，从而避免技术红利向高数字素养群体集中。

## 核心方法

### 参与式需求挖掘框架

本文未提出新的模型架构，而是建立了一套从用户痛点到任务定义的转化流程。参照系为传统 HCI 用户研究，但本文将其与 NLP 任务设计深度耦合。核心差异在于，传统研究止步于需求描述，而本文要求将需求映射为可评估的 LLM 任务。该框架包含两个阶段：基于扎根理论的定性编码，以及基于人口统计学代表性的定量验证。

### 需求-任务映射机制

定性阶段通过 23 名非采用者访谈，识别出 21 项独特需求，并聚类为“缺失任务”与“错位任务”。定量阶段通过 230 人调查，验证了需求的人口统计学分布。关键创新在于提出“能力增强”（Capability Augmentation）评估范式，其核心逻辑可形式化为：

$$
\text{Score}_{task} = f(\text{Human\_Goal}, \text{Model\_Output}, \text{Context})
$$

其中 $f$ 不再是简单的词重叠函数，而是评估模型输出是否帮助用户完成端到端的生活任务（如“获得新诊断后的支持”而非“列出癌症分期”）。这一设计解决了现有基准中“模型能力”与“用户效用”脱节的失效问题，将评估重心从模型内部状态转向外部用户结果。

### 非采用者任务本体构建

基于访谈数据，本文构建了非采用者任务本体，包括非平凡信息检索（如保险条款解读）、国内劳动协调（如护理排班）及物理任务规划。这些任务与现有 NLP 基准（如 SQuAD、HumanEval）存在本质差异：前者要求情境化推理与情感共鸣，后者仅要求事实准确性或代码正确性。本文指出，现有 RAG 方法返回的长文本对低数字素养用户构成认知障碍，需通过界面简化与输出结构化来适配。这一发现揭示了当前个性化方法在“可理解性”维度的缺失，即模型虽能检索正确信息，但未能以用户可消化的形式呈现。

## 实验评估

该论文为立场论文，未提供模型性能对比数据，实验部分主要呈现用户研究的统计结果。

| 统计指标 | 非采用者 vs 采用者 | Z-score | P-value |
| :--- | :--- | :--- | :--- |
| 物理任务重要性选择率 | 高 4 倍 | 6.13 | < 0.001 |
| 护理任务重要性选择率 | 高 60% | 2.35 | < 0.05 |
| 无两年制学位者采用率 | 低 3 倍 | -3.96 | < 0.001 |
| 农村居住者采用率 | 低 40% | -2.16 | < 0.05 |

统计检验显示，非采用者在任务优先级上与采用者存在显著差异，物理任务与护理任务的权重远高于采用者。同时，人口统计学数据证实了采用率的阶层化分布，低学历、农村及女性群体采用率显著偏低。

在评估边界方面，本文的定性研究样本量（n=23）符合 HCI 领域惯例，但缺乏跨文化验证，结论主要基于美国英语使用者。定量调查虽达到 n=230，但通过 Prolific 招募，可能存在样本偏差，尽管使用了代表性抽样功能。此外，本文未提供具体的模型实现或代码，因此无法复现其提出的“能力增强”评估指标的具体计算过程。

## 关联研究分析

从问题动机看，本文与 LaMP 等个性化基准形成互补。LaMP 关注“如何更好地服务现有用户”，通过 RAG 或 PEFT 提升风格匹配度；而本文关注“谁被服务”，指出现有用户群体本身存在结构性偏差。这种差异源于任务定义的根本不同：前者假设用户已具备使用 LLM 的能力，后者假设用户需要 LLM 来克服数字素养障碍。若将 LaMP 的评估指标直接应用于非采用者场景，可能会高估模型效用，因为非采用者更关注信息的可操作性与情感支持，而非文本的风格一致性。

从方法设计看，本文与智能体架构（如 IBA-Agent）存在潜在张力。智能体架构强调自主规划与工具调用，通常假设用户能清晰表达目标；而非采用者往往面临目标模糊与情境复杂的问题，需要模型主动进行意图澄清与情境补全。本文提出的“非平凡信息检索”任务，要求模型在缺乏明确查询词的情况下，通过上下文推断用户真实需求，这与现有智能体基于明确指令的规划逻辑不同。这种差异暗示，未来的个性化智能体需引入更强的交互式发现机制，以适配低数字素养用户的模糊表达。

## 总结

本文核心矛盾在于 LLM 开发的数据闭环与用户群体的广泛性之间的断裂。现有方法依赖采用者数据，导致模型能力向高数字素养群体倾斜，而本文通过参与式设计方法，将非采用者的认知负荷与生活场景纳入开发流程，提出了“能力增强”评估范式。统计数据显示，非采用者在物理任务与护理任务上的优先级显著高于采用者（Z=6.13, P<0.001），证实了需求群体的异质性。然而，本文的边界在于缺乏具体的模型实现与量化评估指标，其定性结论如何转化为可训练的损失函数或可计算的评估分数，仍是一个未解的技术难题。当非采用者的模糊需求被形式化为训练目标时，如何避免模型在追求“用户友好”的同时牺牲事实准确性，是后续研究必须面对的具体挑战。
