# ACL-Findings2026最新论文 ｜ExaGPT: Example-Based Machine-Generated Text Detection for Human Interpretability ｜基于示例检索的可解释AI文本检测

研究机构：日本东京科学大学、日本国立情报学研究所

作者：Ryuto Koike、Masahiro Kaneko、Ayana Niwa 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2502.11336)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_e06fc3ec5ec3)

> 高利害场景下的AI文本检测面临误判风险，现有高精度检测器多为黑盒，无法提供用户可验证的证据以判断预测可靠性。本文切入点在于模拟人类直觉——通过比对文本与已知来源库中相似片段的分布来判定作者，而非依赖参数化分类器的概率输出。ExaGPT利用k-NN检索获取语义相似片段作为证据，并通过动态规划优化片段分割以平衡长度与可靠性。该方法在可解释性上显著优于基线，且在低假阳性率下检测精度达到或超过监督学习模型，但其性能高度依赖数据店的质量与覆盖度，对未见领域的泛化能力存疑。

## 研究背景

当检测器面对新生成模型时，其训练域与测试域的数据分布出现系统性差异——这一现象称为分布偏移。分布偏移导致传统分类器决策边界失效，而实际场景中往往能获取少量目标域样本，这恰好构成了小样本学习的条件：仅凭每个类别极少量标注样本泛化到新任务。解决此类问题的经典框架是原型网络，它计算各类别支持样本的特征均值作为"原型"，再通过距离度量完成分类。

AI生成文本检测的核心任务是在人机文本分布边界日益模糊的背景下，构建兼具跨域泛化能力与对抗鲁棒性的识别框架。主流路线分为零样本统计检测与监督深度学习检测：前者依赖困惑度或似然比等统计特征，模型无关但易受改写攻击影响；后者基于预训练编码器微调，分布内精度高但泛化能力弱。然而，无论哪条路线，现有检测器大多输出单一概率分数，缺乏可解释性。在学术诚信等高风险场景中，误判可能导致严重后果，用户需要能够自行判断预测可靠性的证据，而非仅依赖模型的黑盒输出。

## 核心方法

### 方法参照系

本文问题属于零样本统计检测与细粒度定位的交叉领域。标准零样本方法（如DetectGPT）通过扰动似然计算全局分数，输出文档级标签；标准细粒度方法（如GigaCheck）依赖监督学习进行Span定位。本文的关键差异在于：不训练参数化模型，而是利用外部数据店（Datastore）中的统计相似性进行判断，并将文档级分类转化为Span级证据展示。

### Span评分与k-NN检索

设计动机：传统n-gram重叠证据（如DNA-GPT）仅捕捉字面匹配，无法识别语义相似但词汇不同的片段，导致证据缺乏说服力。ExaGPT将目标文本分割为n-gram Span，通过BERT嵌入将目标Span与数据店中所有Span映射到同一向量空间，利用FAISS执行k-NN检索获取最相似的k个Span。对于每个目标Span $x_{i:i+n}$，计算三个指标：长度分数 $L(x_{i:i+n}) = n$，可靠性分数 $R(x_{i:i+n}) = \frac{1}{k}\sum_{j=1}^{k} c_j$（其中 $c_j$ 为相似度），以及预测分数 $P(x_{i:i+n}) = \frac{1}{k}\sum_{j=1}^{k} \mathbb{1}(l_j = \text{LLM})$。预测分数反映该Span在数据店中更相似于人类还是LLM文本，直接对应人类“比对相似片段”的直觉。

### 动态规划Span分割

设计动机：随机或固定长度的Span分割可能导致证据碎片化，用户难以从短小片段中判断整体来源。ExaGPT采用动态规划算法优化Span边界，最大化整体得分 $S(T) = \sum_{h=1}^{H} \{\alpha L_{std}(t_h) + (1-\alpha) R_{std}(t_h)\}$，其中 $L_{std}$ 和 $R_{std}$ 为归一化后的长度与可靠性分数，$\alpha$ 为插值系数。该公式平衡了Span长度（长Span更具代表性）与可靠性（高相似度Span更可信），确保最终输出的Span分割既连贯又具有高证据价值。整体检测基于平均预测分数 $\bar{P} = \frac{1}{H}\sum_{h=1}^{H} P(t_h)$，若 $\bar{P}$ 超过阈值 $\epsilon$ 则判定为LLM生成。

## 实验评估

实验基于M4数据集英文子集，涵盖Wikipedia、Reddit、WikiHow、arXiv四个领域及ChatGPT、GPT-4、Dolly-v2三个生成器，每个组合3000对文本。基线包括RoBERTa（监督）、LR-GLTR（统计特征）、DNA-GPT（n-gram重叠），缺失DetectGPT、Binoculars等最新零样本SOTA。

| 生成器 | 领域 | RoBERTa AUROC/Acc@1%FPR | LR-GLTR AUROC/Acc@1%FPR | DNA-GPT AUROC/Acc@1%FPR | ExaGPT AUROC/Acc@1%FPR |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ChatGPT | Wikipedia | 100.0 / 77.1 | 95.0 / 60.0 | 84.8 / 49.4 | 98.6 / 92.3 |
| GPT-4 | arXiv | 100.0 / 68.6 | 98.1 / 89.8 | 57.3 / 55.3 | 99.0 / 92.3 |
| Dolly-v2 | WikiHow | 100.0 / 82.8 | 85.3 / 67.5 | 72.0 / 66.9 | 90.4 / 70.8 |

ExaGPT在Acc@1%FPR指标上平均达到92.7，显著优于DNA-GPT的66.4，且在所有生成器上均取得最佳平均性能。消融实验显示，$\alpha$ 值增大导致性能下降，最低AUROC为98.5%，表明可靠性分数比长度分数对检测性能贡献更大。

评估边界：指标仅包含AUROC与Acc@1%FPR，未报告计算效率或内存占用；数据店构建依赖训练集，未测试数据店动态更新机制；代码开源但超参数（如k=10、n-gram范围1-20）固定，未提供不同配置下的敏感性分析。

## 关联研究分析

从问题动机看，ExaGPT与DNA-GPT同属可解释检测路线，但DNA-GPT依赖字面n-gram重叠，而ExaGPT采用语义k-NN检索。这一差异源于任务特性：字面重叠在改写攻击下易失效，而语义相似性更鲁棒。然而，ExaGPT未显式评估改写攻击下的鲁棒性，其语义检索是否真正抵抗改写仍存疑问。

从方法设计看，ExaGPT与DetectGPT同为零样本方法，但DetectGPT依赖扰动似然计算，需多次前向传播，计算成本高；ExaGPT依赖外部数据店，推理时仅需一次嵌入与k-NN检索，效率更高。但数据店构建成本是否抵消了零样本的训练优势，论文未给出回答。此外，ExaGPT的DP分割算法复杂度随文本长度线性增加，实时性受限，与“快速部署”共识存在张力。

## 总结

ExaGPT要解决的核心矛盾是高精度检测与可解释性之间的权衡。现有方法要么黑盒输出概率，要么提供字面重叠证据，均无法支持用户自主判断预测可靠性。ExaGPT抓住人类“比对相似片段”的直觉，通过k-NN检索语义相似Span作为证据，并用动态规划优化分割以平衡长度与可靠性。实验证明其在Acc@1%FPR上平均达到92.7，显著优于基线，且人类判断正确率提升至61.5%。但本文边界在于：数据店质量决定性能上限，未见领域泛化能力未验证，且计算效率未评估。当数据店覆盖度不足或文本领域发生偏移时，k-NN检索的可靠性是否急剧下降，论文未给出回答。
