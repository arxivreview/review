# ACL-Findings2026最新论文 ｜From If-Statements to ML Pipelines: Revisiting Bias in Code-Generation ｜代码生成中的隐性偏见：从条件语句到机器学习管道

研究机构：美国科罗拉多大学博尔德分校

作者：Minh Duc Bui、Xenia Heilmann、Mattia Cerrato 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.21716)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_1c07c93183ff)

> 代码生成模型在构建决策系统时，常将敏感属性作为预测特征，导致隐性歧视。现有评估仅检测显式条件语句，严重低估了实际部署中的偏见风险。本文通过对比条件语句与完整机器学习管道的特征选择行为，量化了这一评估盲区。该工作揭示了评估范式的结构性缺陷，但未提供去偏方案，其结论对模型内部机制的解释力仍待检验。

## 研究背景

当大型语言模型（LLM）被用于生成招聘或信贷决策代码时，其输出的特征选择直接决定了算法的公平性。算法公平性中的“公平通过无知”（Fairness Through Unawareness）原则要求决策过程不得显式使用敏感属性（如种族、性别）。然而，在机器学习管道中，偏见往往不表现为显式的 `if-else` 逻辑，而是隐藏在特征选择阶段：模型将敏感属性作为预测变量输入，从而在看似中立的统计模型中嵌入歧视性关联。这种隐性歧视比显式歧视更难被现有安全机制捕获，且在实际部署中更为普遍。

现有代码偏见评估研究主要聚焦于显性歧视，即通过提示词诱导模型生成包含敏感属性判断的条件语句。Liu et al. (2023) 首先建立了这一范式，后续工作如 CodeGenBias (Qin et al., 2024) 和 FairCoder (Du et al., 2025) 均沿此路径扩展。这些方法假设条件语句是代码偏见的代表性形式，但忽略了真实软件工程中更常见的机器学习管道结构。本文的切入点在于：条件语句仅覆盖了偏见的一小部分，而特征选择这一关键环节的偏见风险被系统性低估。通过对比两种代码形式的偏见率，本文旨在量化现有评估基准的盲区。

## 核心方法

### 评估范式重构

本文的核心方法是将偏见评估对象从条件语句扩展至完整机器学习管道。传统方法通过提示词要求模型生成包含敏感属性判断的条件语句，并计算 Code Bias Score (CBS) 作为偏见指标。本文保留 CBS 指标，但改变其计算对象：不再检测条件语句中的敏感属性，而是检测生成的机器学习管道中，敏感属性是否被选为预测特征。这一重构的关键在于，机器学习管道更接近真实部署场景，其特征选择过程是隐性歧视的主要载体。

### 偏见量化与对照设计

为准确量化偏见，本文设计了包含敏感属性、非敏感属性和无关属性的混合数据集。无关属性（如“最喜欢的颜色”）作为对照，用于验证模型是否具备基本的特征过滤能力。偏见率定义为敏感属性被选为预测特征的比例，公式如下：

$$
CBS_i = \frac{N_i^b}{N} \times 100\%
$$

其中 $N_i^b$ 为包含敏感属性 $i$ 的生成函数数量，$N$ 为总生成函数数量。该公式的物理含义是：在模型有自由选择特征的情况下，敏感属性被选中的频率。若模型具备正常的特征过滤能力，敏感属性与无关属性应被同等对待（即均被排除），但本文发现模型对敏感属性的保留率显著高于无关属性，表明偏见源于对敏感属性的系统性偏好，而非过滤能力缺失。

## 实验评估

实验在7个公平性敏感数据集（如Adult Income、COMPAS）上进行，评估9个LLM（包括Gemma 3 27B、Llama 3.3 70B、CodeGemma 7B等）。基线为条件语句偏见率，对比方法为机器学习管道偏见率。

| 模型 | 条件语句偏见率 (%) | 机器学习管道偏见率 (%) |
| :--- | :--- | :--- |
| CodeGemma 7B | 41.3 | 98.6 |
| Llama 3.3 70B | 43.0 | 89.1 |
| Gemma 3 27B | 64.4 | 71.2 |
| 平均 | 58.7 | 88.3 |

核心发现是机器学习管道偏见率（88.3%）显著高于条件语句偏见率（58.7%），相对增加24.6%。在200个模型-数据集-属性组合中，178个（89%）显示机器学习管道偏见更高，其中165个具有统计显著性（p < 0.05）。

消融实验表明，即使仅要求模型选择特征（最低难度级别），敏感属性出现频率仍比条件语句高16%。这排除了任务难度作为偏见差异的解释，指向模型对机器学习管道与条件语句的概念化差异。提示词缓解策略（如指令模型避免敏感属性）未能显著降低偏见，表明偏见源于模型内部表示而非表面遵循指令。

评估边界方面，本文使用Gemini 3 27B作为偏见提取器，其准确率经人工标注验证为98%。但评估未覆盖多语言代码或不同编程范式，且未提供去偏方法。代码已开源，但超参数与GPU配置仅在附录中简要提及，复现性依赖附录细节。

## 关联研究分析

从问题动机看，本文与Liu et al. (2023) 共享“检测代码偏见”的目标，但根本差异在于偏见形式的定义。Liu et al. 将偏见等同于显式条件语句，而本文将其扩展至特征选择这一隐性环节。这一差异源于对真实软件工程的观察：实际决策系统很少使用显式条件语句，而是通过机器学习模型间接实现决策。本文的评估范式更贴近部署场景，但这也意味着其结论可能受限于机器学习管道的特定结构，无法推广至其他代码形式（如规则引擎）。

从方法设计看，本文与投影去偏（Projection-based Debiasing）等表示空间干预方法形成互补。投影去偏旨在修改模型内部表示以消除偏见，而本文仅检测偏见，未提供干预方案。这种分工表明，检测与干预是偏见研究的两个独立环节。本文的检测结果可作为投影去偏等方法的评估基准，但本文未验证这些方法在代码生成场景中的有效性。一个未探索的问题是：特征选择偏见是否可通过修改预训练语料中的代码示例来缓解，本文未给出回答。

## 总结

本文要解决的核心矛盾是代码偏见评估的显式性与实际部署中隐性歧视的普遍性之间的脱节。现有方法通过条件语句评估偏见，但忽略了特征选择这一关键环节。本文通过对比条件语句与机器学习管道的偏见率，量化了这一盲区：机器学习管道偏见率（88.3%）显著高于条件语句（58.7%）。这一发现挑战了现有基准的有效性，表明当前评估严重低估了代码生成的偏见风险。本文的边界在于，它仅揭示了问题，未提供解决方案，且评估局限于机器学习管道这一特定代码形式。当模型被明确指令避免使用敏感属性时，偏见率是否仍保持高位，本文的提示词缓解实验仅提供了初步证据，其长期稳定性与泛化性仍待验证。
