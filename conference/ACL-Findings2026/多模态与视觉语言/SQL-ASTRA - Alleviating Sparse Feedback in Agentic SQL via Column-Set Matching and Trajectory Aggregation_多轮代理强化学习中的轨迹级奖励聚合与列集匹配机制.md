> 文本到SQL任务正从单轮静态生成向多轮动态交互演进，但现有强化学习方法受限于最终轮次的二值反馈，导致中间步骤的信用分配模糊且奖励信号稀疏。本文切入点在于构建一个双层奖励机制，通过列集匹配提供步级密集信号，并利用非对称转移矩阵聚合轨迹级奖励以激励单调改进。该方法将SQL生成建模为有限时域马尔可夫决策过程，结合Lyapunov稳定性理论证明策略的无环收敛性。尽管在7B小模型上验证了多轮代理范式的有效性并超越单轮基线，但其绝对性能仍低于当前SOTA，且多轮交互带来的推理延迟与部署成本问题未被充分量化。

## 研究背景

当大语言模型（LLM）试图解决复杂SQL查询时，单轮生成范式假设模型能一次性输出正确代码，这忽略了人类数据分析师通过多次试探性查询获取上下文并修正策略的动态过程。这种静态范式导致模型在面对模式链接错误或复杂逻辑时缺乏自我修正能力，进而限制了其在真实企业数据库中的鲁棒性。为突破这一瓶颈，研究重心转向代理式强化学习（Agentic RL），允许模型与环境进行多轮交互。然而，多轮交互引入了新的优化难题：传统RL依赖最终结果的正确性作为唯一奖励信号，这种“全有或全无”的评估方式使得模型无法区分哪些中间步骤对最终成功有贡献，即信用分配问题。

现有单轮RL方法如SQL-R1和Reasoning-SQL虽利用执行反馈提升逻辑一致性，但奖励信号仍局限于二值（0/1），忽略了“部分正确”查询中包含的丰富结构信息。这种稀疏反馈导致梯度方差大，训练效率低，且易陷入局部最优。与此同时，多轮代理框架如MTIR-SQL虽引入了交互能力，但未解决轨迹级奖励的聚合与信用分配机制，导致模型在长序列中表现不稳定。本文旨在通过设计一种通用的双层奖励机制，同时解决步级奖励稀疏性和轨迹级信用分配模糊这两个核心矛盾，从而推动文本到SQL任务向更鲁棒的多轮代理范式演进。

## 核心方法

### 有限时域马尔可夫决策过程建模

本文将交互式文本到SQL任务形式化为有限时域马尔可夫决策过程（MDP），定义为元组 $M = \langle S, A, P, R \rangle$。与单轮RL仅优化单次响应期望奖励不同，该框架要求策略 $\pi_\theta$ 通过生成交互轨迹 $\tau = (s_0, a_0, \dots, s_K)$ 来最大化基于过程奖励函数 $R$ 的累积期望奖励。这一建模的关键差异在于将SQL生成视为一个动态探索过程，其中状态 $s_t$ 包含当前数据库上下文与历史查询结果，动作 $a_t$ 为生成的SQL代码，而奖励 $R$ 则分解为步级密集信号与轨迹级聚合信号两部分，以支持更细粒度的策略优化。

### 列集匹配奖励 (CSMR)

针对传统二值奖励忽略部分正确信息的缺陷，本文提出列集匹配奖励（Column-Set Matching Reward, CSMR）作为步级密集奖励。CSMR的核心思想是放弃行级元组比较，转而比较预测结果表 $P$ 与金标准表 $G$ 中各列的值集合。具体而言，算法首先对 $G$ 和 $P$ 进行行去重，提取每列的唯一值集合 $D_G$ 和 $D_P$，计算匹配列数 $M$。奖励分数定义为：

$$ R_{CSMR} = \frac{M}{N_c^G \times N_c^P} \times \alpha $$

其中 $N_c^G$ 和 $N_c^P$ 分别为金标准和预测结果的列数，$\alpha < 1$ 为缩放因子。该公式的物理含义是：奖励与列值集合的结构重叠度成正比，同时通过 $\alpha$ 惩罚“伪完美”匹配（即列值匹配但行组合错误的情况），从而将0/1信号转化为[0, 1]范围内的密集梯度信号，为策略提供逐步引导。

### 聚合轨迹奖励 (ATR) 与 Lyapunov 稳定性

为解决多轮轨迹中的信用分配问题，本文设计聚合轨迹奖励（Aggregated Trajectory Reward, ATR）。ATR并非逐步更新，而是在回合结束时提供一个标量奖励，以激励连续改进并抑制振荡。其核心在于使用非对称转移矩阵 $M$ 对步级CSMR信号进行加权聚合，其中 $|R_{High \to Low}| > |R_{Low \to High}|$，确保系统具有严格的耗散性。基于Lyapunov稳定性理论，本文将CSMR分数转化为语义误差能量 $V(s_t)$，并证明ATR作为能量耗散算子，能保证策略 $\pi^*$ 沿单调能量下降路径收敛至平衡点（正确SQL），从而在数学上确保无环策略与渐近稳定性。

## 实验评估

实验在BIRD-Dev、Spider-Dev及Spider2.0-Lite数据集上进行，基线涵盖GPT-4o、DeepSeek-V3、SQL-R1、Reasoning-SQL、OmniSQL及MTIR-SQL等。值得注意的是，基线中缺少提示工程类SOTA方法（如DAIL-SQL、CHESS）及最新多轮基线（如Track-SQL），这可能影响对RL路线相对于提示工程路线优势的全面评估。

| 模型 | 骨干模型 | BIRD (Greedy) | Spider-Dev (Greedy) | Spider2.0-Lite (Mj@8) |
| :--- | :--- | :--- | :--- | :--- |
| Qwen2.5-7B-Instruct | Qwen2.5-7B-Instruct | 47.5 | 74.7 | 5.1 |
| SQL-R1 + Qwen2.5-Coder-7B | Qwen2.5-Coder-7B | 63.1 | 84.5 | - |
| OmniSQL-7B | Qwen2.5-Coder-7B | 64.1 | 85.0 | 12.6 |
| Agentic SQL + CSMR + ATR | Qwen2.5-7B-Instruct | 64.2 | 82.9 | 8.8 |
| Agentic SQL + CSMR + ATR | OmniSQL-7B | 69.1 | 88.8 | 17.7 |

在Qwen2.5-7B-Instruct骨干上，Agentic SQL + CSMR + ATR在BIRD上达到64.2，较单轮二值GRPO（58.5）提升5.7%，但在Spider-Dev上（82.9）低于OmniSQL-7B（85.0）。在OmniSQL-7B骨干上，该方法在BIRD（69.1）和Spider-Dev（88.8）上均超越单轮GRPO（67.4/87.4）及SQL-R1（66.6/87.6），并在Spider2.0-Lite上达到17.7，显著优于OmniSQL基线的12.6。

消融实验显示，非对称矩阵设计至关重要：使用对称矩阵时，BIRD性能从64.2降至60.1，表明对称奖励导致模型陷入重复生成的极限环。此外，移除轨迹聚合（Step-wise Update）导致BIRD性能降至61.3，证实了ATR在缓解信用分配问题中的有效性。CSMR对缩放因子 $\alpha$ 不敏感，验证了其鲁棒性。

评估指标主要依赖执行准确率（EX），未报告有效效率分数（VES）或推理延迟，这使得多轮交互带来的计算成本无法量化。代码未公开，但实验在32块NVIDIA A800 GPU上完成，超参数细节见附录。由于缺乏提示工程基线对比，RL路线在部署灵活性上的劣势未被直接验证。

## 关联研究分析

从问题动机看，本文与SQL-R1和Reasoning-SQL同属RLVR路线，但关键差异在于交互范式与奖励粒度。SQL-R1和Reasoning-SQL聚焦单轮生成，奖励信号虽引入n-gram等细粒度机制，但仍受限于单次执行结果；本文则通过多轮MDP建模，将奖励分解为步级CSMR与轨迹级ATR，直接回应了多轮交互中的信用分配难题。这一差异源于任务特性的变化：单轮任务假设模型具备一次性推理能力，而多轮任务承认模型的探索性与错误修正需求。然而，本文未探讨多轮交互在简单查询上的边际收益，即对于无需修正的简单SQL，多轮机制是否引入不必要的计算开销，论文未给出回答。

从方法设计看，本文与MTIR-SQL同属多轮代理框架，但奖励机制设计存在根本分歧。MTIR-SQL依赖最终轮次反馈，而本文引入非对称转移矩阵与Lyapunov稳定性证明，从理论上保证了策略的单调收敛性。这一设计选择源于对“奖励黑客”（reward hacking）现象的防范：对称奖励可能导致模型通过振荡来利用奖励函数，而非对称耗散性则强制策略沿能量下降路径前进。相比之下，提示工程方法如DAIL-SQL通过检索增强解决泛化问题，无需参数更新，但缺乏显式的逻辑验证机制。本文的RL路线虽在复杂推理上展现潜力，但其训练成本与部署灵活性之间的权衡，相较于提示工程路线，仍是未充分解决的工程挑战。

## 总结

本文旨在解决多轮代理强化学习中因最终轮次二值反馈导致的信用分配模糊与奖励稀疏问题。其切入点在于构建双层奖励机制：CSMR通过列集匹配提供步级密集信号，ATR通过非对称转移矩阵聚合轨迹级奖励并证明Lyapunov稳定性，从而在理论上保证策略的无环收敛。实验表明，该方法在OmniSQL-7B骨干上BIRD执行准确率达69.1，Spider2.0-Lite达17.7，均优于单轮RL基线。然而，其绝对性能仍低于当前SOTA（如BIRD上的72.9），且多轮交互带来的推理延迟与部署成本未被量化。当支持集增大或查询复杂度降低时，多轮机制的边际收益是否递减，论文未给出回答。
