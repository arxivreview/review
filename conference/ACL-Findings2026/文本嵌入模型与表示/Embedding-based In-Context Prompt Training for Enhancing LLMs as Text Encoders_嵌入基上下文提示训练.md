# ACL-Findings2026最新论文 ｜Embedding-based In-Context Prompt Training for Enhancing LLMs as Text Encoders ｜嵌入基上下文提示训练

研究机构：日本东京科学大学

作者：Ailiang Lin、Zhuoyun Li、Keyu Mao 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_3d4c1ff535b3)

> 导读 文本嵌入模型在检索增强生成（RAG）等场景中需平衡语义精度与推理延迟，而基于大语言模型（LLM）的嵌入方法常因引入离散文本演示导致序列长度膨胀，显著增加计算开销。现有方案或牺牲精度换取速度，或依赖双向注意力改造破坏LLM原生指令跟随能力，难以兼顾效率与表示质量。本文提出EPIC，将离散文本演示压缩为连续向量嵌入，在保留因果注意力的同时实现高效上下文学习。该方法在公开检索数据上刷新MTEB基准，但其在低资源语言及非检索任务上的泛化能力尚待验证。

## 研究背景

当LLM被适配为文本编码器时，因果注意力机制限制了全局语义捕获，而直接引入双向注意力会破坏模型预训练建立的指令跟随能力。这一矛盾导致现有方法在提升嵌入质量时往往伴随计算开销激增，例如bge-en-icl通过前置离散查询-段落对实现上下文学习，但序列长度随演示数量线性增长，在延迟敏感的检索场景中难以部署。

LLM嵌入适配路线的核心在于解决因果注意力与全局语义需求的冲突。主流方案如LLM2Vec通过移除因果掩码引入双向注意力，虽提升表示能力但损失生成特性；NV-Embed等模型则依赖复杂预训练策略，训练成本高昂。bge-en-icl尝试在保留因果注意力的前提下，通过离散文本演示增强上下文学习能力，但其token开销问题未被解决。本文切入点在于：能否将演示信息从离散文本空间迁移至连续向量空间，在不改变注意力机制的前提下压缩序列长度？

## 核心方法

### 方法参照系

本文问题属于LLM嵌入适配中的上下文学习优化。标准流程为：LLM通过因果注意力处理输入序列，取EOS token隐藏状态作为嵌入，结合对比学习微调。关键差异在于：本文不修改注意力机制或池化策略，而是在输入端将离散演示压缩为连续向量，以解决序列长度膨胀问题。

### 嵌入基上下文提示构造

传统ICL将k个查询-段落对$D = \{D_1, ..., D_k\}$作为文本前置，导致序列长度增加$\sum |Q_i| + |P_i|$。本文创新在于将每个演示对压缩为两个连续向量：

$$q_i = g(f_{EOS}^\theta([I; Q_i; [[EOS]]])), \quad p_i = g(f_{EOS}^\theta([I; P_i; [[EOS]]]))$$

其中$g(\cdot)$为两层线性变换加GELU激活的MLP，$f_{EOS}^\theta$返回EOS token隐藏状态。该设计动机在于：离散文本演示迫使模型重复处理相同语义信息，而连续向量直接编码语义，使模型需同时学习对齐正样本与解读自身生成的演示嵌入，从而在压缩token的同时增强表示能力。

### 训练与推理策略

训练时，从同一批次随机采样0-5个(query, positive)对构造演示，EPIC增强查询嵌入为：

$$e_X^{EPIC} = f_{EOS}^\theta([E_1; E_2; ...; E_k; I; X; [[EOS]]])$$

损失函数采用InfoNCE，温度$\tau=0.05$。推理时，演示嵌入预计算并复用，避免重复注意力计算。该策略解决了离散ICL在推理时无法预计算的问题，使EPIC在无需演示时仍优于基线，因训练过程迫使模型内化演示嵌入的语义结构，缓解注意力沉陷现象。

## 实验评估

实验在MTEB 56数据集子集上进行，基线覆盖E5、LLM2Vec、NV-Embed、bge-en-icl等主流方法，但缺失Conan-Embedding-v2等从头训练模型。主结果显示，Mistral-7B上EPIC得分66.37，超越bge-en-icl的66.18及NV-Embed的65.80；Qwen2.5-7B上EPIC得65.97，LLaMA-3.1-8B上得66.10。

| 模型 | 基线 | EPIC w/o ICD | EPIC w/ ICD |
| :--- | :--- | :--- | :--- |
| Qwen2.5-7B | 65.05 | 65.68 | 65.97 |
| LLaMA-3.1-8B | 65.25 | 65.89 | 66.10 |
| Mistral-7B | 65.33 | 66.11 | 66.37 |

消融实验表明，移除查询或段落嵌入均导致性能下降（71.31/71.17 vs 71.50），证明完整演示格式必要性。压缩策略中，仅压缩查询得分71.35，仅压缩段落71.42，均低于完整压缩的71.50，显示联合压缩对模型理解自身嵌入的促进作用。

评估边界方面，实验仅使用公开检索数据，未覆盖私有数据或低资源语言；代码未公开，LoRA超参数（rank 64, alpha 32）固定，未探索其他配置。MTEB分数未报告置信区间，数值比较需谨慎。

## 关联研究分析

从问题动机看，EPIC与bge-en-icl同属ICL增强嵌入路线，但前者将演示从离散文本迁移至连续向量，根源在于序列长度对推理延迟的制约。bge-en-icl的离散演示在数据充足时可能提供更丰富的上下文，但EPIC通过向量压缩证明语义信息可被更紧凑地编码，这一差异是否源于任务特性（检索vs分类）还是通用规律，论文未给出回答。

从方法设计看，EPIC保留因果注意力，与LLM2Vec的双向化改造形成对比。LLM2Vec通过架构修改提升全局语义捕获，但EPIC通过输入端压缩实现类似效果，暗示因果注意力下的EOS池化在特定训练策略下已足够有效。NV-Embed依赖复杂预训练，而EPIC仅用LoRA微调，显示轻量级适配在公开数据上的可行性。EPIC未探索双向注意力与向量演示的结合，这一盲区可能限制其在长文本任务上的表现。

## 总结

EPIC解决的核心矛盾是LLM嵌入中上下文学习增益与计算开销的冲突。其切入点在于将离散演示压缩为连续向量，利用模型自身生成嵌入的能力实现语义压缩，而非修改注意力机制。方法通过MLP对齐演示嵌入，在InfoNCE训练中迫使模型内化演示结构，使Mistral-7B在MTEB上达66.37，超越bge-en-icl的66.18。边界在于实验仅限公开检索数据，未验证低资源语言或非检索任务，且未探索双向注意力与向量演示的结合。当演示数量从5-shot增至10-shot时，向量压缩的边际收益是否递减，论文未给出回答。
