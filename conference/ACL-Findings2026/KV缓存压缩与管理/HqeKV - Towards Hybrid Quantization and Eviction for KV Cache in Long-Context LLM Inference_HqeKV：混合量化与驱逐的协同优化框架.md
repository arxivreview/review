# ACL-Findings2026最新论文 ｜HqeKV: Towards Hybrid Quantization and Eviction for KV Cache in Long-Context LLM Inference ｜HqeKV：混合量化与驱逐的协同优化框架

研究机构：美国东北大学

作者：He Wang、Yu Gu、Fangfang Li 等 8 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_22fd1e0098b0)

> 长上下文大语言模型推理中，键值缓存（KV Cache）的线性增长导致显存溢出，现有单一量化或驱逐策略因压缩粒度粗糙及重要性评估偏差，难以在固定内存预算下最大化生成质量。HqeKV 提出一种混合压缩框架，通过联合 K-V 重要性指标与分比特宽度量化策略，将缓存对分配至 FP16、4-bit、2-bit、1-bit 及驱逐五种状态。该方法在相同内存约束下将 LongBench 平均准确率从 40.53 提升至 49.98，但其离线搜索依赖校准集，在线自适应能力存疑。

## 研究背景

自回归生成中，解码阶段每生成一个新 Token 需读取整个历史 KV 缓存，受限于内存带宽而非算力，成为长上下文推理的主要延迟瓶颈。KV 缓存大小随序列长度线性增长，往往超过模型参数本身的内存占用，迫使研究者从“丢弃哪些 Token”转向“以何种精度存储所有 Token”。量化压缩通过降低数值精度减少存储，但单一低比特格式无法适应不同缓存对的信息密度差异；驱逐策略通过丢弃低价值 Token 避免量化开销，但往往导致显著的质量退化。

现有混合压缩方法通常仅使用两种低精度格式，且统一应用单一量化策略，忽视了不同比特宽度下最优转换策略的差异。更关键的是，当前重要性评估指标仅基于 Key 向量的累积注意力权重，忽略了 Value 向量对注意力输出的直接贡献，导致边界决策不准，加剧了转换损失。HqeKV 的切入点在于：通过引入 Value 向量范围修正重要性评估，并针对高/低比特宽度分别采用均匀/归一化量化，实现更细粒度的自适应压缩。

## 核心方法

### 混合压缩参照系

混合压缩的标准流程是基于重要性排序，将 KV 对分配至不同精度层级。本文问题与该通用流程的关键差异在于：传统方法假设单一量化策略适用于所有比特宽度，且重要性评估仅依赖 Key 侧信息，而 HqeKV 引入了分比特策略适配与联合 K-V 评估机制。

### 联合 K-V 重要性指标

现有方法仅使用累积注意力权重评估 Key 的重要性，忽略了 Value 向量在注意力计算中的乘法作用。HqeKV 观察到推理质量退化与 Value 向量范围（Range）呈正相关，因此提出联合指标：Key 的重要性由累积注意力权重决定，Value 的重要性由累积注意力权重与 Value 向量范围的乘积决定。该设计解决了仅基于 Key 的评估在 Value 分布差异大时的偏差问题，使边界决策更准确。

$$
\text{Importance}_V = \text{CumulativeAttention} \times (\max(V) - \min(V))
$$

该公式表明，Value 向量的极值范围直接决定了量化转换损失，将其纳入重要性评估可更精确地识别高损失风险缓存对。

### 分比特宽度量化策略

现有混合精度方法统一应用单一量化策略，忽视了不同比特宽度下最优转换策略的差异。HqeKV 发现高比特宽度（4-bit、2-bit）适用均匀量化，低比特宽度（1-bit）适用归一化量化。均匀量化将数值置于等长区间中心，适合分布稳定的高比特场景；归一化量化将数值映射至标准正态分布分位数，适合分布波动大的低比特场景。该策略解决了统一量化在极端压缩率下的精度损失问题。

$$
\Xi_{dq} = C[\Xi_q] \cdot s + m
$$

该公式表示归一化量化的反量化过程，其中 $C$ 为标准正态分布分位数，$s$ 和 $m$ 为均值和标准差，确保低比特下数值映射更贴近原始分布。

## 实验评估

实验在 Llama-3.1-8B-Instruct 和 Qwen3-8B 上进行，评估基准为 LongBench 和 AIME-2025，基线包括 KIVI、OTT、ZipCache、KVTuner 和 CAKE。HqeKV 在 LongBench 上实现了 50.33 的平均准确率（Llama-3.1-8B，3.25-bit），显著优于 CAKE 的 40.53 和 KIVI 的 48.96。在 AIME-2025 上，HqeKV-2 达到 0.20 的准确率，高于 KIVI-2 的 0.17。

| 方法 | LongBench Avg (Llama-3.1-8B) | AIME-2025 (Qwen3-8B) |
| :--- | :--- | :--- |
| HqeKV-3.25 | 50.33 | — |
| KIVI-2 | 48.96 | 0.17 |
| CAKE-3.25 | 40.53 | — |
| ZipCache-3.2 | 50.98* | — |

*注：ZipCache 的 50.98 为非 OOM 列平均值。

消融实验显示，HqeKV 在 3.2-bit 下比 ZipCache 高 0.51 分，在 3.25-bit 下比 KVTuner 高 0.39 分。分比特量化策略的贡献体现在 1-bit 层级：归一化量化在 1-bit 下的转换损失（37.44）显著低于均匀量化（92.06），验证了策略适配的必要性。

评估边界方面，实验仅使用 NVIDIA RTX A6000 GPU，未报告多 GPU 或不同硬件下的表现。AIME-2025 的 0.20 准确率与领域综述中 ThinKV 的 77.8% 存在量级差异，可能源于评估协议（如 Pass@1 vs Pass@k）不同，论文未明确说明。代码已开源，但超参数设置依赖离线 TPE 搜索，校准集选择可能影响泛化能力。

## 关联研究分析

从问题动机看，HqeKV 与 KIVI 同属非对称量化路线，但 KIVI 仅使用 2-bit 单一精度，而 HqeKV 扩展至 5 级混合精度。差异根源在于任务特性：KIVI 针对长上下文通用场景，HqeKV 针对内存预算严格且质量敏感的场景。HqeKV 的联合 K-V 指标解决了 KIVI 中 Value 侧评估缺失的问题，但引入了离线搜索开销，这在实时性要求高的服务场景中可能成为瓶颈。

从方法设计看，HqeKV 与 CAKE 同属动态资源调度路线，但 CAKE 仅使用驱逐策略，而 HqeKV 结合量化与驱逐。差异根源在于压缩粒度：CAKE 的驱逐是二元的（保留/丢弃），HqeKV 的混合精度是连续的（5 级）。HqeKV 在 LongBench 上比 CAKE 高 9.45 分，证明了混合策略在精度上的优势，但 CAKE 在实时性上可能更优，因为驱逐无需量化/反量化计算。

## 总结

HqeKV 要解决的核心矛盾是固定内存预算下 KV 缓存压缩的精度-效率权衡。现有方法因压缩粒度粗糙和重要性评估偏差，无法在严格约束下最大化生成质量。HqeKV 通过联合 K-V 指标与分比特量化策略，实现了更细粒度的自适应压缩，在 LongBench 上将平均准确率从 40.53 提升至 49.98。其边界在于离线 TPE 搜索依赖校准集，在线自适应能力未验证。当校准集分布与测试集分布差异较大时，TPE 搜索的最优比例是否仍能保持精度优势，论文未给出回答。
