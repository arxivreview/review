# ACL-Findings2026最新论文 ｜Know Thy Enemy: Securing LLMs Against Prompt Injection via Diverse Data Synthesis and Instruction-Level Chain-of-Thought Learning ｜指令级思维链对齐防御提示注入

研究机构：中国科学院、中国科学院大学

作者：Zhiyuan Chang、Mingyang Li、Yuekai Huang 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.04666)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.04666)

> 提示注入（Prompt Injection, PI）防御的核心困境在于模型无法区分系统指令与外部数据，且现有模型增强方法仅依赖隐式的角色边界学习，难以应对语义边界模糊的复杂注入。本文切入点在于将防御任务从“区分来源”转化为“分析指令冲突”，通过构建覆盖多向量、多位置的合成数据集，并引入基于情境意识模型的指令级思维链（Instruction-Level Chain-of-Thought, IL-CoT）进行监督微调。该方法在四个开源大语言模型（LLM）上实现了92.5%至98.0%的防御率，但未在标准代理基准上验证其泛化性，且推理时的计算开销未量化。

## 研究背景

当LLM代理处理包含外部检索数据的上下文时，攻击者可将恶意指令嵌入看似良性的数据流中，导致模型执行非预期行为。这一现象源于LLM架构中指令与数据缺乏明确的信任边界，即提示注入。传统防御依赖外部检测器拦截恶意输入，但误报率高且增加延迟；另一种路线是模型增强，通过微调让模型内部识别并拒绝恶意指令。然而，现有模型增强方法（如StruQ, ISE）主要训练模型区分“用户区”与“数据区”的角色边界，当注入指令在语义上与周围内容高度融合时，这种基于位置的启发式规则失效。

该领域正从静态规则向动态语义感知演进。主流模型增强防御（如MetaSec, ISE）假设攻击向量是离散的、可定位的，但现代攻击往往通过多向量注入（Multi-vector Injection）和语义混淆（Ambiguous Semantic Boundaries）绕过这些假设。本文针对这一瓶颈，提出不依赖角色边界，而是直接对上下文中的每条指令进行语义冲突分析。通过构建包含多场景、多位置注入的合成数据，并引入结构化推理过程，使LLM具备“感知-理解-预测”的认知能力，从而在指令层面建立防御机制。

## 核心方法

### 方法参照系

本文属于模型增强防御路线，其标准流程为：收集/合成对抗数据 → 定义训练目标（如角色分离） → 监督微调（SFT）。与StruQ等仅训练模型区分输入来源的方法不同，本文的关键差异在于训练目标从“识别来源”转向“分析指令意图”，并显式引入推理链作为中间监督信号。

### 多向量合成与上下文归约

针对现有数据集注入位置单一、场景覆盖不足的局限，本文设计了三阶段合成框架。首先，基于Wu et al. (2025)的风险分类，生成行为偏差、隐私泄露、有害输出三类恶意指令。其次，借鉴程序分析中的数据流思想，将LLM应用框架归约为四个上下文区域：用户区、数据区、用户+数据区、空上下文区。通过向这些区域注入不同偏离程度的指令，确保训练数据覆盖真实攻击向量。该设计解决了传统方法仅针对数据区注入导致的直接攻击防御薄弱问题。

### 指令级思维链生成

为解决语义边界模糊导致的检测失效，本文引入Endsley情境意识模型，构建三阶段IL-CoT推理框架。第一阶段“指令感知”要求模型穷尽提取上下文中所有指令，避免确认偏误；第二阶段“违规理解”对每条指令进行二元冲突评估，判断其是否违反系统提示；第三阶段“响应预测”基于理解结果生成具体响应。CoT内容通过以下公式生成：

$$ CoT = LLM(T_{cot}, P_{sys}, P_{con}) $$

其中 $T_{cot}$ 为结构化提示模板，$P_{sys}$ 为系统提示，$P_{con}$ 为输入上下文。该公式的物理含义是：利用LLM自身的推理能力，将隐式的指令冲突判断转化为显式的、可监督的文本序列，使模型在微调过程中学习“先分析后响应”的决策范式。

### 监督微调与损失函数

在合成数据与IL-CoT增强后，本文采用全参数SFT进行训练。训练目标是最小化负对数似然：

$$ \mathcal{L}(\theta) = -\sum_{i=1}^{N} \log P_\theta(y_i | x_i) $$

其中 $x_i = (P_{sys}, P_{con})$，$y_i = (CoT_i, R_i)$ 包含CoT推理内容与最终响应。该损失函数迫使模型不仅学习正确的响应，还学习生成正确的推理路径，从而强化其对指令冲突的语义理解能力，而非仅记忆表面模式。

## 实验评估

实验在Llama3-8B、Llama3.1-8B、Qwen2.5-7B、Qwen3-8B四个模型上进行，评估维度包括行为偏差、隐私泄露、有害输出。基线覆盖检测式（PromptArmor）与模型增强式（ISE, MetaSec, IP, InSFT）。

| 威胁场景 | 方法 | 行为偏差 DR (%) | 隐私泄露 DR (%) | 有害输出 DR (%) |
| :--- | :--- | :--- | :--- | :--- |
| 平均 | Clean | 10.3 / 12.4 | 47.1 / 54.5 | 56.4 |
| 平均 | ISE | 60.5 / 72.9 | 91.2 / 91.3 | 67.8 |
| 平均 | MetaSec | 51.0 / 85.9 | 73.7 / 58.9 | 80.2 |
| 平均 | PromptArmor | 51.7 / 49.8 | 56.3 / 60.2 | 70.8 |
| 平均 | InSFT | 53.5 / 60.1 | 78.6 / 86.0 | 83.5 |
| 平均 | **InstruCoT** | **91.5 / 93.4** | **97.6 / 98.4** | **90.9** |

注：行为偏差与隐私泄露列分别对应直接注入与间接注入的平均DR。InstruCoT在行为偏差上较基线提升25.8%-82.5%，在隐私泄露上提升6.7%-47.2%。

消融实验显示，移除IL-CoT仅保留SFT（InSFT）时，行为偏差DR从91.5%降至53.5%，隐私泄露DR从97.6%降至78.6%，表明显式推理链对防御性能贡献显著。在有害输出场景，PromptArmor表现接近模型增强方法，归因于其使用GPT-4作为护栏，但该优势在复杂语义混淆场景下不稳定。

评估边界方面，本文使用自建合成基准，未在AgentDojo等标准代理基准上验证，导致结果与领域SOTA（如IsolateGPT的0.12% ASR）不可直接比较。此外，论文未报告推理延迟与吞吐量，IL-CoT引入的额外计算开销未量化，限制了其在资源受限场景的部署评估。代码已公开，但超参数细节需查阅附录。

## 关联研究分析

从问题动机看，本文与StruQ、ISE等模型增强方法的核心差异在于防御粒度。StruQ通过结构化角色分离训练模型区分用户与数据，假设攻击向量具有明确的位置特征；而本文指出，当注入指令在语义上与上下文融合时，位置特征失效。本文通过指令级CoT将防御粒度从“区域”细化到“指令”，解决了语义边界模糊问题。这一差异源于任务特性：代理场景中外部数据动态变化，静态位置规则难以适应，而语义分析更具鲁棒性。

从方法设计看，本文与检测式防御（如PromptArmor）形成互补。PromptArmor在有害输出场景表现接近模型增强方法，但其在行为偏差与隐私泄露场景下波动较大（DR范围14.4%-89.0%），表明基于外部检测器的方法在复杂语义混淆下不稳定。本文通过内部对齐实现更一致的防御，但代价是增加了推理时的计算复杂度。与系统级防御（如IsolateGPT）相比，本文属于模型级防御，未涉及架构隔离，因此在面对多向量注入时，其鲁棒性可能受限于模型本身的语义理解能力，而非系统层面的信任域隔离。

## 总结

本文针对提示注入防御中语义边界模糊的问题，提出通过指令级思维链对齐增强LLM的指令冲突识别能力。其切入点在于将隐式的角色边界学习转化为显式的指令语义分析，通过多向量合成数据与IL-CoT监督微调，使模型具备“感知-理解-预测”的认知过程。实验表明，该方法在四个开源LLM上实现了92.5%-98.0%的防御率，显著优于现有基线，且未损害效用性能。然而，本文的边界在于评估仅在自建合成基准上进行，缺乏在标准代理基准（如AgentDojo）上的验证，且未量化IL-CoT引入的推理开销。当面对真实代理环境中动态变化的多模态注入时，仅依赖文本指令级语义分析的防御机制是否足够鲁棒，论文未给出回答。
