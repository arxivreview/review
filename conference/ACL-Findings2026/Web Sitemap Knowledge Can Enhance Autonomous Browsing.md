# 中国人民大学团队提出WASP协议：预构建站点地图注入上下文，无需训练提升Web智能体导航

研究机构：中国人民大学

作者：Yuyao Zhang、Hongyu Lu、Jiajie Jin 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_1f6f66507cc6)

> 现有LLM Web智能体在真实开放网络中因缺乏网站结构先验，导致导航低效与接地误差，任务成功率远低于人类水平。主流路线聚焦于增强模型内部推理或构建动态世界模型，但忽视了静态结构化知识对长程规划的支撑作用。WASP通过预构建双粒度站点地图，将全局导航结构与局部交互指引作为外部知识注入智能体上下文，无需额外训练即可提升鲁棒性与效率。该方案在WebVoyager上取得58.3%成功率，但依赖静态快照，未验证网页动态更新下的时效性。

## 研究背景

Web智能体执行任务时，需将自然语言指令映射到具体DOM节点或像素坐标，这一过程称为感知接地（Grounding）。接地精度直接决定动作有效性，而复杂UI布局下，纯文本输入缺乏空间信息，视觉快照又无法暴露隐藏组件，导致定位模糊。为克服单步接地的局限，智能体需维持多步任务的全局视野，避免“迷失在中间”，这要求对网站整体结构有先验理解，即长程规划（Long-horizon Planning）能力。

当前领域面临的核心矛盾是：智能体在动态、开放网络中缺乏对网站结构的系统性认知。主流路线如ReAct框架通过推理-行动循环优化内部策略，WebWorld等世界模型通过模拟状态转移预测环境变化，但前者受限于上下文窗口爆炸，后者存在预测误差累积问题。这些方法均假设智能体需从原始观察中实时推断结构，忽略了网站本身已存在的、可被结构化提取的静态先验知识。WASP的切入点在于：将传统Web开发中的Sitemap概念改造为Agent-oriented协议，通过预构建结构化知识库，将结构理解从推理时移至构建时，从而解耦感知与规划的计算负担。

## 核心方法

### 方法参照系

WASP置于“外部知识增强”方法类别下，与动态世界模型（如WebWorld）和纯内部推理（如ReAct）形成对比。关键差异在于：WASP不模拟状态转移，而是提供静态、预构建的网站结构摘要，作为智能体推理时的查询接口，而非训练时的环境模拟器。

### 双粒度站点地图协议

WASP的核心创新是双粒度设计，将网站知识分解为全局级与局部级。全局级存储核心页面的树状导航关系，支持长程规划；局部级提供页面摘要、内容块描述及交互指引，解决细粒度接地问题。这一设计解决了此前方法中“全局导航”与“局部交互”耦合导致的上下文噪声问题。全局结构通过页面重要性评分筛选核心页面，公式为：

$$s(p) = \text{Score}(p)$$

其中$\text{Score}(\cdot)$综合点击深度、URL模式等启发式因子，保留高价值页面，过滤冗余内容。局部级通过多模态融合生成结构化标注：

$$h = \text{Fuse}(\text{Enc}_T(T), \text{Enc}_I(I))$$

该公式将页面文本$T$与截图$I$编码后融合，确保语义与空间信息统一，为后续块级描述提供基础。

### LightASM构建框架

LightASM负责高效生成WASP合规的站点地图，包含三阶段：核心页面识别、动态内容捕获、语义标注。设计动机在于解决静态爬取无法获取动态渲染内容的问题。Simulated User Explorer通过模拟用户交互（如点击展开、滚动）触发隐藏内容，记录状态变化：

$$S(p) = \{(D_k, I_k)\}_{k=1}^{K(p)}$$

其中$D_k$为DOM树，$I_k$为对应截图，捕获交互引发的结构与视觉变化。Page Content Annotator基于多模态表示$h$生成页面摘要$S$、工作流$W$及块级描述$D$，公式为：

$$(S, W, D) \sim P_\theta(\cdot | h, I)$$

该过程将原始网页转化为可查询的结构化知识，使智能体在推理时能直接获取导航与交互先验，而非从原始HTML中实时解析。

## 实验评估

实验在WebWalker（教育/会议域，275任务）与WebVoyager（127任务）上进行，基线包括Direct与ReAct，使用Qwen2.5-72B及Qwen2.5-VL-72B作为骨干。基线覆盖缺失多模态专用方法（如Avenir-Web）及记忆机制方法（如WebCoach），限制了与SOTA的直接对比。

| 方法 | WebWalker Edu. | WebWalker Conf. | WebWalker Total | WebVoyager Avg. |
| :--- | :--- | :--- | :--- | :--- |
| Qwen2.5-72B + ReAct | 16.9 | 3.8 | 16.0 | 44.1 |
| Qwen2.5-VL-72B + ReAct | 20.5 | 7.5 | 18.2 | 45.7 |
| WASP (Qwen2.5-VL-72B) | 28.9 | 7.5 | 25.8 | 58.3 |

WASP在WebVoyager上达58.3%，显著高于ReAct基线的45.7%，验证了外部结构化知识对接地与导航的增益。消融实验显示，移除全局知识导致WebWalker性能从25.8%降至27.1%（注：原文数据为w/o Global 27.1%，w/o Local 29.9%，此处需修正：原文Table 4显示w/o Global为27.1%，w/o Local为29.9%，WASP为36.1%？不，原文Table 4是WebVoyager的消融：WASP 36.1, w/o Global 27.1, w/o Local 29.9。WebWalker无消融数据。修正：消融仅在WebVoyager进行，WASP 36.1%，移除全局知识降至27.1%，移除局部知识降至29.9%。全局知识对导航任务影响更大，局部知识对交互任务影响显著。

评估采用LLM-as-a-Judge，与人工评估一致性超80%，但未报告置信区间。代码未公开，LightASM构建框架的超参数（如评分函数权重）未详细披露，可复现性受限。

## 关联研究分析

从问题动机看，WASP与WebWorld形成鲜明对比。WebWorld通过动态模拟训练智能体适应环境变化，而WASP依赖静态预构建知识，假设网站结构在任务执行期间保持稳定。这一差异源于任务特性：WebWalker与WebVoyager任务多为信息检索，结构变化频率低，静态先验有效；但在高动态网站（如新闻、电商促销）中，WASP的时效性存疑，论文未提供证据支持其在频繁更新场景下的鲁棒性。

从方法设计看，WASP与VOIX同属结构化交互协议，但VOIX需网站开发者部署，WASP通过LightASM自动爬取生成，降低了落地门槛。然而，WASP的自动构建依赖启发式评分与模拟用户交互，可能遗漏非标准导航路径或动态加载的深层内容。VOIX的开发者主导模式虽成本高，但能确保结构完整性，WASP的自动化路径在结构复杂网站上的覆盖率未量化，这是其方法设计的潜在盲区。

## 总结

WASP解决的核心矛盾是LLM Web智能体在真实网络中缺乏结构先验导致的导航低效与接地误差。其切入点在于将结构理解从推理时移至构建时，通过双粒度站点地图提供全局导航与局部交互的静态知识。实验证明，在WebVoyager上，WASP将成功率从45.7%提升至58.3%，验证了外部结构化知识的增益。然而，其边界在于依赖静态快照，未验证网页动态更新下的时效性，且基线缺失多模态SOTA对比。当网站结构在任务执行期间发生显著变化时，预构建的站点地图是否仍能提供有效引导，论文未给出回答。
