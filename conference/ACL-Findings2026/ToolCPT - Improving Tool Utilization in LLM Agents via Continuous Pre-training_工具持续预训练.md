# ACL-Findings2026最新论文 ｜ToolCPT: Improving Tool Utilization in LLM Agents via Continuous Pre-training ｜工具持续预训练

作者：Yifan Yang、Jinghui Lu、Evadeng 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_b7952d3e0eb5)

> 大语言模型智能体在分布外工具调用中表现受限，根源在于现有后训练与测试时方法仅让模型学习调用模式，而非内化工具功能知识。ToolCPT 将工具知识获取前移至持续预训练阶段，通过挖掘真实代码库构建代理工具并合成结构化知识语料，使模型在权重层面建立对工具实现、交互协议及错误反馈的深层理解。该方法在 7B/8B 基座模型上验证了预训练内化工具知识的有效性，但其静态模拟特性与缺乏真实执行反馈的局限，使其在动态环境适应性与长程任务泛化上仍存疑。

## 研究背景

智能体调用工具时，模型需理解工具的功能边界、参数约束及与其他工具的协作关系。若仅通过接口签名学习，模型只能进行模式匹配，无法推理工具内部逻辑或创造性组合。这种浅层理解导致在未见过的工具或复杂组合场景中，智能体频繁出现参数幻觉或调用失败。

当前提升智能体工具使用能力的主流路线分为两类：后训练微调与测试时上下文增强。后训练方法（如 ToolACE, SealTools）依赖人工设计的轨迹或在线交互，但受限于工具集规模小、分布偏差大（如 Toucan 数据集中 36.41% 的工具从未被调用），模型难以泛化到分布外工具。测试时方法通过检索历史轨迹辅助决策，虽提升了即时准确率，却引入了系统复杂度与安全漏洞风险，且未解决模型底层知识缺失问题。

ToolCPT 的切入点在于识别出“工具知识内化”这一被忽视的训练阶段。它主张在持续预训练（CPT）阶段注入大规模、结构化的工具功能知识，而非仅在微调阶段学习调用格式。这一策略旨在从根源上弥补模型对工具实现细节的认知空白，从而提升其在开放环境中的鲁棒性与泛化能力。

## 核心方法

### 方法参照系

传统智能体训练遵循“数据收集-后训练-测试时检索”流程，工具知识以轨迹形式隐式存在。ToolCPT 的关键差异在于将工具知识显式化并前移至预训练阶段，通过代码挖掘构建“代理工具”（Proxy Tools），替代传统合成 API，使模型在基础能力构建期即建立工具功能图谱。

### 代理工具挖掘与标准化

该环节解决传统合成工具分布偏差问题。ToolCPT 从 47 万亿 token 的高质量代码库中筛选自包含函数，利用 LLM 基于六项标准（清晰接口、外部信息获取、环境变更、无干预、清晰反馈、应用场景）进行评分。筛选出的 510 万个函数被标准化为符合 MCP 格式的代理工具。其核心在于通过代码语义而非接口签名定义工具，确保工具集覆盖真实世界功能的多样性。

$$
S_{tool} = \sum_{i=1}^{6} w_i \cdot \mathbb{1}[\text{Feature}_i \text{ is present}]
$$

其中 $S_{tool}$ 为工具评分，$\mathbb{1}[\cdot]$ 为指示函数，$w_i$ 为特征权重。该公式量化了代码片段作为“代理工具”的资格，确保挖掘出的工具具备智能体调用的必要属性。

### 工具 Playbook 合成与模板化

仅学习静态接口不足以支撑动态交互。ToolCPT 为每个代理工具生成结构化 Playbook，涵盖实现规范、背景知识、调用方法（含正反例）及错误分析。Playbook 从 5 个维度、12 个视角描述工具行为，特别是包含错误反馈机制，弥补了轨迹数据中错误样本稀缺的缺陷。最终，通过 10 种排列组合模板将代码、接口与 Playbook 组装成 180 亿 token 的预训练语料，其中 30% 数据包含双序列以增强顺序理解。

$$
\mathcal{D}_{CPT} = \bigcup_{t \in \mathcal{T}} \{ \text{Template}_k(\text{Code}_t, \text{API}_t, \text{Playbook}_t) \mid k \in \{1, \dots, 10\} \}
$$

该公式表示持续预训练数据集 $\mathcal{D}_{CPT}$ 由所有代理工具 $t$ 经不同模板 $k$ 组装而成。多模板设计旨在通过结构多样性防止模型过拟合特定排列，提升知识内化的鲁棒性。

## 实验评估

实验基于 Qwen2.5-7B 和 Llama3.1-8B 基座，使用 100B token 的 Dolma 3 语料进行 CPT，替换 5%-20% 比例为工具知识数据。基线仅包含不同比例的 CPT 变体及无 CPT 基线，缺失与 Tool-R0、MiroFlow 等当前 SOTA 方法的直接对比，限制了性能上限的评估。

| 模型 | 工具知识比例 | GAIA v2 | BFCL v3 | TauBench v1 | Avg. |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen2.5-7B | 0% | 25.00% | 20.00% | 24.24% | 17.04% |
| Qwen2.5-7B | 10% | 30.68% | 27.00% | 27.88% | 24.19% |
| Llama3.1-8B | 0% | 25.00% | 20.86% | 29.09% | 19.01% |
| Llama3.1-8B | 10% | 32.95% | 24.46% | 36.36% | 24.69% |

10% 混合比例下，Qwen 和 Llama 的平均性能分别提升 7.15% 和 5.68%。然而，20% 比例导致性能下降，表明过量单任务数据稀释了通用训练信号。消融实验显示，Playbook 与多模板设计对性能提升贡献显著，仅代码挖掘不足以达到最佳效果。

评估边界存在明显局限：代理工具为静态模拟，无法捕捉连续调用中的环境状态变化；错误反馈基于代码推断而非真实执行，可能引入幻觉。此外，论文未报告计算效率指标（如 Token 消耗、延迟），且未提供代码开源链接，可复现性受限。

## 关联研究分析

从问题动机看，ToolCPT 与 Tool-R0 形成鲜明对比。Tool-R0 依赖强化学习在合成环境中通过可验证奖励优化策略，解决长程信用分配问题；而 ToolCPT 主张在预训练阶段内化静态工具知识，解决分布外泛化问题。两者差异源于对“工具知识”定义的不同：Tool-R0 视工具为交互对象，ToolCPT 视工具为知识实体。ToolCPT 的静态知识内化能否适应动态变化的工具接口，是其与 RL 路线的根本分歧点。

从方法设计看，ToolCPT 与 Toolformer 存在阶段差异。Toolformer 通过自监督学习在 SFT 阶段内化工具调用格式，侧重“何时调用”；ToolCPT 在 CPT 阶段内化工具功能知识，侧重“如何理解”。ToolCPT 引入 Playbook 提供细粒度错误反馈，弥补了 Toolformer 仅学习成功轨迹的缺陷。然而，ToolCPT 未探索 CPT 内化知识与运行时动态检索的结合，其静态知识在开放世界中的适应性仍存疑问。

## 总结

ToolCPT 针对智能体在分布外工具调用中因知识内化不足导致的泛化失效，提出在持续预训练阶段注入结构化工具知识。通过挖掘 510 万个真实代码代理工具并合成 180 亿 token 的 Playbook 语料，该方法在 7B/8B 模型上实现了 GAIA v2 和 BFCL v3 等基准的显著提升，验证了预训练内化工具知识的有效性。然而，其代理工具缺乏真实执行反馈，错误描述基于代码推断，无法捕捉环境状态动态变化，且未解决长程任务中的信用分配问题。当工具接口在运行时发生动态变更时，预训练内化的静态知识能否通过轻量级微调快速适应，论文未给出回答。
