# ACL-Findings2026最新论文 ｜Seer Self-Consistency: Advance Budget Estimation for Adaptive Test-Time Scaling ｜预分配预算的自适应测试时扩展

作者：Shiyu Ji、Yixuan Wang、Yijun Liu 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_0814b8f15d6f)

> 测试时扩展（Test-Time Scaling, TTS）旨在通过增加推理计算提升大语言模型（LLM）性能，但固定预算导致简单任务算力浪费，动态预算方法又因串行估计产生高延迟。现有自适应一致性方法在生成过程中实时停止，无法利用现代推理引擎的并行优势，导致Token效率与延迟无法同时优化。SeerSC 引入快速直觉推理（System 1）预估答案熵，在深思推理（System 2）执行前预分配采样预算，实现了并行生成下的动态扩展。该方法在保持精度的同时显著降低计算成本，但其熵估计在复杂多步推理中的预测稳定性尚存疑。

## 研究背景

当 LLM 面对难度分布不均的推理任务时，固定采样预算的自一致性（Self-Consistency, SC）策略面临两难：简单问题因过度采样浪费算力，复杂问题因采样不足导致准确率瓶颈。这种算力分配与任务难度的错配，催生了自适应计算分配（Adaptive Compute Allocation）的需求，即根据问题复杂度动态调整推理资源。然而，早期自适应方法如自适应一致性（Adaptive Consistency, AC）和早停自一致性（Early-Stopping Self-Consistency, ESC）采用串行生成机制，在生成过程中实时评估答案多样性并决定停止。这种串行特性与现代推理引擎（如 vLLM）的并行批处理架构冲突，导致延迟随采样数线性增加，无法利用硬件并行优势。

TTS 领域的核心矛盾在于：并行采样能降低延迟但缺乏动态性，串行动态性能节省 Token 但牺牲延迟。AC 和 ESC 通过滑动窗口或频率阈值实现动态停止，解决了 Token 浪费问题，却引入了串行延迟瓶颈。在长推理轨迹场景下（如 AIME 2024），AC 和 ESC 的延迟甚至超过固定预算的 SC，因为串行等待抵消了提前停止的收益。SeerSC 的切入点在于将“预算估计”与“预算执行”解耦：利用低成本的 System 1 快速生成直接答案并计算熵，作为 System 2 并行执行的预算控制器，从而在保持动态性的同时恢复并行效率。

## 核心方法

### 方法参照系

动态自一致性方法的标准流程是：生成推理轨迹 → 实时评估答案分布 → 决定继续或停止。AC 和 ESC 的关键差异在于评估时机：AC 基于全局频率阈值，ESC 基于滑动窗口收敛性。本文问题与该通用流程的关键差异在于，评估发生在生成过程中（串行），导致无法预知总预算，进而无法利用并行采样引擎的批处理优势。

### System 1 熵估计

AC 和 ESC 在生成过程中计算答案多样性，导致必须串行等待前序结果。SeerSC 将评估前置，利用 System 1 直接生成 $M$ 个答案，计算置信度加权熵 $E(X)$ 作为预算指标。设计动机是解决串行估计导致的延迟瓶颈，使预算分配在 System 2 执行前完成。

$$
E(X) = -\sum_{c \in C} \tilde{W}(c) \log \tilde{W}(c)
$$

其中 $\tilde{W}(c)$ 是类别 $c$ 的归一化置信度权重，由成员答案的 Token 概率指数平均计算得出。该公式的物理含义是：答案分布越分散（熵越高），问题越复杂，需要更多采样；答案越集中（熵越低），问题越简单，可少采样。

### 并行预算分配

基于熵值，SeerSC 将采样预算 $B(X)$ 分为三档：低熵分配 $N/2$，中熵分配 $N/2$，高熵分配 $N$。设计动机是通过离散化预算档位，简化调度逻辑，同时保留动态性。

$$
B(X) = \begin{cases}
N/2, & E(X) < \tau_1 \\
N/2, & \tau_1 \le E(X) < \tau_2 \\
N, & \text{otherwise}
\end{cases}
$$

其中 $\tau_1 = \frac{1}{10}\log M$，$\tau_2 = \frac{1}{3}\log M$。该分配规则确保了高熵样本获得最大预算，低熵样本节省算力，且所有样本可并行执行，消除了串行等待。

## 实验评估

实验在 MATH500、AIME 2024/2025、AMC 2023 和 GPQA-D 上评估，基线包括 CoT、SC、AC 和 ESC。基线覆盖动态 SC 主流路线，但缺失 BoM、Logit Averaging 等最新聚合策略，也未对比树搜索类方法。

| 模型 | 数据集 | 方法 | 准确率 (%) | Token (×10³) | 延迟 (s) |
|---|---|---|---|---|---|
| DS-R1-Qwen-7B | MATH500 | SC | 93.9 | 29.8 | 8.4 |
| DS-R1-Qwen-7B | MATH500 | SeerSC | 93.0 | 17.7 | 5.3 |
| DS-R1-Qwen-7B | AIME2024 | SC | 74.4 | 344.4 | 158.6 |
| DS-R1-Qwen-7B | AIME2024 | SeerSC | 74.1 | 315.6 | 151.8 |
| Qwen3-4B (non-thinking) | GPQA-D | SC | 57.6 | 24.4 | 6.5 |
| Qwen3-4B (non-thinking) | GPQA-D | SeerSC | 57.1 | 13.0 | 3.7 |

SeerSC 在 MATH500 上比 SC 降低 37% 延迟，在 GPQA-D 上降低 43% 延迟，Token 消耗减少 47%。准确率波动在 ±1 个百分点内，验证了熵估计的有效性。

消融实验显示，System 1 延迟占比不足 1%（如 Qwen3-4B 上 0.56%），证明预估计开销可忽略。阈值敏感性分析表明，$\tau_1$ 和 $\tau_2$ 的设定对结果影响较小，但高熵样本的预算分配对准确率贡献最大。

评估边界：论文未报告置信区间，且未对比同等骨干模型下的 BoM 等无训练聚合策略。可复现性方面，代码已开源，超参数（如 $N$、阈值）在附录中详细列出，实验在 A100-80GB GPU 上进行。

## 关联研究分析

从问题动机看，SeerSC 与 AC/ESC 的核心差异在于预算分配时机。AC 和 ESC 在生成过程中实时停止，本质是“边生成边评估”，导致串行依赖。SeerSC 将评估前置，本质是“先评估后生成”，解耦了估计与执行。这一差异的根源是任务特性：数学推理任务的答案分布具有早期可预测性（System 1 熵与 System 2 熵一致性高），使得前置估计可行。但在开放域任务中，答案分布可能随推理深度剧烈变化，前置估计的稳定性是否足够，论文未给出回答。

从方法设计看，SeerSC 与 SCALE 等自适应分配方法同属难度感知路线，但 SCALE 基于问题特征预测计算量，SeerSC 基于答案熵预测采样数。SCALE 的评估器需要额外训练，SeerSC 利用模型内部 Token 概率，无需外部验证器。这一差异暗示：内部置信度作为难度代理，在可验证任务（如数学）上有效，但在缺乏明确验证信号的任务上，其鲁棒性可能低于基于问题特征的评估器。

## 总结

SeerSC 要解决的核心矛盾是动态自一致性中 Token 效率与延迟的不可兼得。现有 AC/ESC 方法因串行估计无法利用并行引擎，SeerSC 凭借 System 1 熵估计的前置性，实现了预算预分配与并行执行的解耦。该方法在 MATH500 上比 SC 降低 37% 延迟，在 GPQA-D 上降低 43% 延迟，同时保持精度稳定。其边界在于：熵估计依赖 System 1 与 System 2 答案分布的一致性，这一假设在复杂多步推理中可能失效。当推理轨迹长度超过 10,000 Token 时，System 1 的早期熵是否仍能准确预测 System 2 的最终答案分布，论文未给出回答。
