> 大语言模型在处理需要回溯与例外处理的逻辑任务时，常因自回归生成的线性特性陷入逻辑不一致或计算冗余。现有神经符号方法多依赖单调逻辑（如SMT），无法表达默认推理与信念撤销，且需大量人工领域知识。本文提出 LLM+ASP 框架，通过自动自修正循环将自然语言转化为答案集规划（Answer Set Programming, ASP）程序，利用稳定模型语义处理非单调推理。该框架在六个基准上显著优于基线，但其在常识推理任务上的增益有限，且高度依赖底层模型的代码生成能力。

## 研究背景

当模型面对“鸟会飞，但企鹅不会”这类包含例外规则的逻辑问题时，传统的单调逻辑框架（如 Satisfiability Modulo Theories, SMT）一旦推导出“鸟会飞”的结论，便无法在引入“企鹅”这一新信息后撤销该结论。这种逻辑刚性导致模型在处理默认推理（Default Reasoning）时失效。答案集规划（ASP）基于稳定模型语义，将默认否定与替代可能世界作为一等公民，允许在证据不足时假设某事为假，从而天然适配人类认知中的非单调推理过程。

神经符号推理旨在结合 LLM 的自然语言理解能力与符号求解器的逻辑严谨性，以突破纯 LLM 在复杂约束满足与规划任务上的瓶颈。然而，现有方法如 LLM-Modulo 或基于 SMT 的框架，往往依赖人工编写的领域模式、特定任务的提示工程或人工知识模块，导致其泛化能力受限，难以跨任务复用。此外，纯 LLM 推理在问题复杂度超过阈值后性能急剧下降，且长思维链中常出现中间步骤与最终答案的逻辑断裂。

本文的切入点在于利用 ASP 的非单调语义优势，并解决 LLM 生成符号代码时的错误累积问题。不同于以往将 LLM 视为一次性翻译器的做法，本文引入自动自修正循环，利用求解器反馈迭代优化 ASP 程序，实现了无需特定任务工程的任务无关推理。

## 核心方法

### 方法参照系

本文问题属于神经符号推理中的“自然语言到形式化逻辑转换”范畴。标准流程通常涉及 LLM 生成符号表示、求解器执行及结果反馈。本文的关键差异在于摒弃了单调逻辑（SMT/FOL），采用非单调的 ASP，并引入基于求解器反馈的迭代自修正机制，替代了传统方法中依赖人工知识模块或静态提示的设计。

### 非单调 ASP 程序生成

设计动机在于解决单调逻辑无法表达默认推理与例外规则的局限。LLM 接收自然语言问题描述，生成 ASP 程序。ASP 规则形式为 $A \leftarrow B, \text{not } C$，其中 $\text{not}$ 表示默认否定，意为“若可推导 $B$ 且不可推导 $C$，则推导 $A$”。例如，$flies(X) \leftarrow bird(X), \text{not } penguin(X)$ 表达了“除非是企鹅，否则鸟会飞”的默认规则。这种语义允许模型在缺乏反证时做出假设，并在新证据出现时撤销假设，从而处理逻辑冲突与偏好排序。

### 基于求解器反馈的自修正循环

设计动机在于 LLM 初始生成的 ASP 代码常存在语法错误或逻辑缺陷，而一次性生成无法保证正确性。框架引入 CLINGO 求解器执行生成的程序，输出稳定模型或错误信息。LLM 根据反馈决定执行“UPDATE”（重写程序）或“PASS”（接受结果）。该过程可形式化为迭代优化：

$$ P_{t+1} = \text{LLM}(P_t, \text{Feedback}(P_t)) $$

其中 $P_t$ 为第 $t$ 轮生成的 ASP 程序，$\text{Feedback}(P_t)$ 为求解器返回的执行状态或错误日志。循环持续直至程序通过验证或达到最大迭代次数。这一机制将 LLM 的推理能力从直接遍历解空间转向生成引导符号搜索的紧凑程序，显著提升了计算效率与逻辑一致性。

## 实验评估

实验在六个基准上进行，包括约束满足（ZebraLogic, SudokuBench）、规划（Mystery Blocksworld）及非单调推理（MultiLogicNMR, BoardgameQA）。基线涵盖 Gemini 2.5 Pro/Flash、o4-mini、DeepSeek R1-0528 及 DeepSeek V3。对比方法包括独立 LLM 推理及 LLM+SMT 框架。

| 方法 | ZL-XL (%) | ZL-XXL (%) | SudokuBench (%) | MysteryBW (%) | MultiLogicNMR Skeptical (%) | BoardgameQA (%) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Baseline Avg | 65.3 | 24.2 | 8.4 | 64.2 | 59.0 | 84.7 |
| LLM+ASP Avg | 88.5 | 71.3 | 59.8 | 72.6 | 90.5 | 82.4 |
| LLM+SMT Avg | 84.0 | 72.2 | 60.0 | 60.6 | 35.8 | 60.1 |

LLM+ASP 在平均准确率上达到 78.0%，较基线提升 52.1%。在非单调推理任务 MultiLogicNMR 上，LLM+ASP 的 Skeptical 准确率为 90.5%，而 LLM+SMT 仅为 35.8%，接近随机猜测水平，验证了 ASP 语义在处理信念撤销时的理论优势。

消融实验显示，自修正循环是性能提升的主要驱动力，无修正时平均准确率为 54.6%，有修正时升至 78.0%。紧凑参考指南（2.6k tokens）优于标准参考（22k tokens），揭示了“上下文腐烂”现象：过长的上下文反而干扰了约束遵循。

评估边界方面，论文未报告计算延迟与 Token 消耗的详细对比，仅定性指出 LLM+ASP 在难题上 Token 效率更高。代码已开源，但超参数（如最大迭代次数）未完全披露。BoardgameQA 上 LLM+ASP 未超越基线，作者归因于任务结构允许 LLM 通过模式匹配解决冲突，而非真正的非单调推理，且可能存在数据污染。

## 关联研究分析

从问题动机看，本文与 RLVR（Reinforcement Learning with Verifiable Rewards）路线形成互补。RLVR 依赖可验证奖励信号优化策略，适用于数学、代码等可验证领域；而 LLM+ASP 利用符号求解器反馈作为外部奖励，适用于缺乏明确数值奖励但具有逻辑约束的非单调推理任务。两者的核心差异在于奖励信号的来源：RLVR 依赖任务特定的验证器，LLM+ASP 依赖通用逻辑求解器。这暗示在可验证领域，符号反馈可能无法替代 RLVR 的策略优化能力，但在逻辑密集型任务上具有独特优势。

从方法设计看，本文与 LLM-Modulo 框架同属神经符号推理，但 LLM-Modulo 依赖人工编写的正确初始模型，而 LLM+ASP 通过自修正循环自动生成并修复程序。这一差异源于对 LLM 代码生成能力的信任程度不同：LLM-Modulo 假设 LLM 无法可靠生成符号代码，需人工兜底；LLM+ASP 假设 LLM 具备足够的代码生成能力，仅需反馈修正。这种设计选择使得 LLM+ASP 更具泛化性，但牺牲了对底层模型代码能力的鲁棒性，如 DeepSeek V3 在 LLM+ASP 中表现显著弱于推理模型。

## 总结

本文旨在解决 LLM 在非单调推理任务中的逻辑不一致与计算低效问题，切入点在于利用 ASP 的稳定模型语义表达默认推理，并通过自修正循环克服 LLM 生成代码的错误。实验证明，LLM+ASP 在 MultiLogicNMR 上达到 90.5% 的 Skeptical 准确率，远超 LLM+SMT 的 35.8%，验证了非单调逻辑的优势。然而，框架在 BoardgameQA 上未超越基线，且性能高度依赖底层模型的代码生成能力，非推理模型表现较差。当底层模型缺乏足够的代码生成能力时，自修正循环能否通过增加迭代次数弥补这一缺陷，论文未给出明确答案。
