# ACL-Findings2026最新论文 ｜EXPO-SQL: Execution-based Clause-level Policy Optimization for Text-to-SQL ｜执行反馈的子句级信用分配：EXPO-SQL

研究机构：韩国成均馆大学

作者：Jaehoon Lee、CheolWon Na、Suyoung Bae 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_68ec44f7fa34)

> 文本到SQL任务中，强化学习（RL）方法长期依赖查询级二元奖励，导致模型无法区分SQL中正确与错误的子句，产生粗糙的信用分配。现有方案在复杂查询上因惩罚正确部分而收敛缓慢，本文切入点在于利用SQL逻辑执行顺序与差异类型分析，将奖励细化至子句粒度。通过增量执行定位错误子句并设计差异化奖励，EXPO-SQL在BIRD基准上超越最佳RL基线2.4个百分点。该方法验证了细粒度监督对复杂推理的有效性，但其依赖执行环境稳定性的假设在模糊问题场景下是否依然成立，尚存疑。

## 研究背景

当模型生成包含多个子句的SQL查询时，执行结果仅反馈整体正确与否。若WHERE子句错误而SELECT正确，查询级奖励会将负信号施加于所有子句，迫使模型同时修正正确与错误部分，这一现象称为信用分配粗糙。为缓解此问题，研究者尝试引入过程奖励模型或语法有效性奖励，但这些方法仍停留在查询级或步骤级，未能触及SQL内部子句结构的细粒度差异。

文本到SQL领域的主流路线已从序列翻译转向基于大语言模型（LLM）的提示工程与强化学习。提示工程路线通过分解任务与检索增强实现零样本高性能，但缺乏参数更新带来的深度推理能力；强化学习路线利用执行反馈优化策略，却受限于二元反馈的稀疏性。SQL-R1等早期RL方法证明了执行反馈的有效性，但其查询级奖励机制在复杂查询（如嵌套子查询、多表连接）上表现不佳，因为错误往往局限于特定子句，全局惩罚导致学习信号噪声大。

EXPO-SQL针对这一瓶颈，提出基于执行的子句级策略优化。其核心假设是：SQL子句具有确定的逻辑执行顺序，且每个子句对结果的影响可通过增量执行量化。通过解析执行结果中的差异类型与错误消息，该方法能精准定位错误子句，从而提供细粒度的学习信号，解决查询级奖励无法区分正确与错误部分的失效问题。

## 核心方法

### 方法参照系

本文问题置于基于执行反馈的强化学习框架下。标准流程中，策略模型生成SQL，执行器返回二元结果，奖励函数将该结果均匀分配至所有token。本文的关键差异在于：奖励分配粒度从查询级降至子句级，且错误定位依赖执行过程的中间状态而非最终结果。

### 子句级错误定位

针对查询级奖励无法区分子句正确性的问题，EXPO-SQL引入子句级增量执行机制。对于可执行但结果错误的查询，方法依据SQL逻辑执行顺序（FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT）逐步添加子句并执行。通过比较相邻执行结果 $R_{i-1}$ 与 $R_i$ 的差异类型 $d_i$，并与最终差异 $D^* = \text{diff}(R_{\text{pred}}, R_{\text{gold}})$ 匹配，识别错误子句集合 $C_{\text{err}}$。

$$
C_{\text{err}} = \{ c_i \mid d_i \in D^* \}
$$

该公式表明，若某子句引入的差异类型出现在最终结果差异中，则该子句被判定为错误。此设计解决了直接token匹配因SQL一对多性质导致的误判，利用执行过程的确定性实现精准归因。

### 差异化奖励设计

基于错误子句集合，EXPO-SQL设计三种情况的子句级奖励。对于正确结果，所有子句获正奖励；对于错误结果，错误子句获负奖励，正确子句获正奖励；对于执行错误，错误子句获强负奖励，其他子句获弱负奖励。策略优化损失函数定义为：

$$
\mathcal{L} = -\mathbb{E} \left[ \sum_{c \in O} \sum_{t_i \in c} \left( r_c - \beta D_{KL}^{(i)} \right) \log \pi_\theta(t_i | t_{<i}) \right]
$$

其中 $r_c$ 为子句 $c$ 的奖励，$D_{KL}^{(i)}$ 为KL散度惩罚。该公式确保同一子句内所有token共享相同奖励，不同子句间奖励差异化，使模型能选择性修正错误子句而保留正确部分。

## 实验评估

实验在Spider与BIRD基准上进行，基线覆盖SFT（OmniSQL）、提示工程（DAIL-SQL）及RL（SQL-R1, Arctic-SQL-R1）三类方法。缺失CHESS等多智能体架构在BIRD上的直接对比，可能影响对方法相对优势的全面评估。

| 方法 | 骨干模型 | Spider (Dev) | BIRD (Dev) |
| :--- | :--- | :--- | :--- |
| SQL-R1 | Qwen2.5-Coder-7B | 87.6 | 66.6 |
| Arctic-SQL-R1 | Qwen2.5-Coder-7B | 87.3 | 68.9 |
| EXPO-SQL | Qwen2.5-Coder-7B | 88.5 | 71.3 |

EXPO-SQL在BIRD-Dev上以71.3%的执行准确率超越Arctic-SQL-R1的68.9%，提升2.4个百分点，验证了子句级奖励在复杂查询上的优势。

| 配置 | BIRD (Dev) |
| :--- | :--- |
| Query-level reward | 69.6 |
| + Diff Types | 70.1 |
| + Clause-wise Incr. Exec. | 71.3 |

消融实验显示，移除错误结果情况的子句级奖励导致性能下降2.4个百分点，大于移除执行错误情况的1.7个百分点，表明错误结果场景对细粒度监督依赖更强。

评估指标仅采用执行准确率（EX），未报告有效效率分数（VES）或置信区间。代码已开源，但训练细节如超参数与GPU配置未在正文详述，可复现性依赖附录补充。

## 关联研究分析

从问题动机看，EXPO-SQL与VET（可验证执行追踪）均关注执行反馈的细粒度利用，但VET侧重推理时的自我验证，而EXPO-SQL聚焦训练时的奖励设计。这一差异源于任务阶段不同：VET解决推理阶段的幻觉问题，EXPO-SQL解决训练阶段的信用分配问题。EXPO-SQL的子句级增量执行算法与VET的执行追踪思路相近，但前者更依赖SQL逻辑执行顺序的确定性，后者更依赖LLM的自我反思能力。

从方法设计看，EXPO-SQL与SQL-R1同属RL路线，但奖励机制存在根本差异。SQL-R1使用查询级二元奖励，EXPO-SQL使用子句级差异化奖励。这一差异导致EXPO-SQL在复杂查询上表现更优，因为复杂查询中错误往往局限于特定子句，细粒度奖励能提供更精准的学习信号。然而，EXPO-SQL依赖执行环境的稳定性，若数据库存在模糊列名或歧义关系，增量执行可能产生噪声，这一局限在SQL-R1中因查询级奖励而部分缓解。

## 总结

EXPO-SQL要解决的核心矛盾是查询级奖励在复杂SQL生成中信用分配粗糙的问题。其切入点在于利用SQL逻辑执行顺序的确定性，通过增量执行与差异类型分析实现子句级错误定位，这是查询级方法因缺乏中间状态信息而做不到的。方法通过设计差异化子句级奖励，使模型能选择性修正错误子句，在BIRD-Dev上以71.3%的执行准确率超越最佳RL基线2.4个百分点。本文的边界在于依赖执行环境的稳定性，当数据库存在模糊性或歧义时，增量执行可能引入噪声。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
