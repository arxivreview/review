# ACL-Findings2026最新论文 ｜Polaris: A Gödel Agent Framework for Small Language Models through Experience-Abstracted Policy Repair ｜POLARIS：基于经验抽象的小语言模型递归策略修复

作者：Aditya Kakade、Vivek Srivastava、Shirish Karande

论文原文见 [arXiv](https://arxiv.org/abs/2603.23129)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.23129)

> 递归自我改进旨在让智能体通过检查自身策略与执行轨迹来持续优化能力，但现有框架如 Gödel Agent 依赖大模型容量，在 7B 参数的小语言模型（SLM）上因上下文膨胀导致内存溢出（OOM）而失效。POLARIS 通过“经验抽象”机制，将失败案例压缩为最小代码补丁，在资源受限条件下实现可追溯的策略持久化更新。该方法证明了 SLM 具备递归改进的可行性，但其性能增益依赖于特定骨干模型的元推理能力，且缺乏对补丁泛化性的量化评估。

## 研究背景

语言智能体的自我改进通常分为响应级纠正与参数级更新两类。响应级方法如 Self-Refine 和 Reflexion 通过迭代批评与修订优化单次输出，但改进仅局限于当前实例，无法持久化；参数级方法如 Task Arithmetic 直接修改模型权重，但难以定位具体修改内容及其作用范围。这种“改进不可追溯”与“更新不持久”的矛盾，促使研究者将策略视为可显式检查与修订的对象。Gödel Agent 框架（Yin et al., 2024）将这一思想形式化为递归自我改进：智能体在测试循环中检查自身策略 $\pi$ 与执行轨迹，并通过运行时代码变异更新策略。然而，该框架依赖大上下文窗口存储验证样本与历史演化步骤，导致 7B 模型在迭代过程中迅速耗尽内存，无法完成完整的自我改进循环。

现有自博弈与自纠正研究多聚焦于大模型在可验证任务（如数学、代码）中的能力突破，通过挑战者-求解者机制或噪声对比估计（NCE）维持训练稳定性。然而，这些方法假设模型具备足够的元推理能力来生成高质量反思，且通常依赖外部验证器提供确定性奖励。对于资源受限的 SLM，上下文窗口限制与工具调用能力不足使得直接应用上述框架不可行。POLARIS 的切入点在于：不追求全量策略重写，而是通过“经验抽象”将失败转化为紧凑、可复用的修复策略，以最小代码补丁的形式集成到当前策略中，从而在控制上下文增长的同时保持更新的持久性与可追溯性。

## 核心方法

### 递归自我改进参照系

Gödel Agent 框架定义了递归自我改进的标准流程：内省（Self-Inspect）、交互（Interact）、自我修改（Self-Improve）与递归延续（Continue-Improve）。智能体通过内省获取当前策略表示，通过交互收集执行轨迹，通过自我修改生成候选代码编辑，并通过递归延续重新进入内省阶段。该流程的核心假设是模型具备足够的上下文容量来存储历史反思与验证样本，从而支持高质量的元推理。POLARIS 的关键差异在于：它不存储全量历史，而是通过经验抽象机制压缩失败信息，仅保留必要的修复策略与最小代码补丁，以适应 SLM 的有限上下文窗口。

### 经验抽象与策略合成

经验抽象是 POLARIS 的核心创新，旨在将实例特定的失败转化为策略级别的通用修复原则。对于验证集中的每个失败任务 $\tau_i$，智能体调用 `AnalyzeFailure` 生成结构化反思 $A_i = (\text{diagnosis}_i, \text{revision}_i, \text{prevention}_i)$，其中诊断识别错误原因，修订计划提出代码级调整，预防规则泛化洞察以指导未来迭代。随后，`StrategySynthesis` 算子跨反思集合 $A = \{A_i\}$ 抽象出紧凑的修复指令集 $\delta = \{\delta_j\}$。每个 $\delta_j$ 捕获如分解、归一化或控制流调整等通用修复原则，可解决多个失败案例。该过程通过以下公式形式化：

$$
\delta = \text{StrategySynthesis}(\pi_t, s, A)
$$

其中 $\pi_t$ 为当前策略，$s$ 为智能体状态，$A$ 为反思集合。设计动机在于：SLM 难以从大量原始反思中直接提取通用策略，而经验抽象通过压缩信息密度，降低了元推理的认知负荷，使 SLM 能够生成可迁移的修复原则。

### 最小代码补丁生成与集成

基于合成策略 $\delta_j$，`PatchGeneration` 算子实例化最小代码补丁 $p_j$，仅修改实现 $\delta_j$ 所需的行，排除解释性文本。补丁通过 `UpdatePolicy` 集成到当前策略 $\pi_t$，生成候选策略 $\pi_{t+1}$。集成过程包含语法与执行检查，若补丁失败，智能体最多重试三次。若持续失败，补丁及其上下文被归档至内存以供后续分析。更新后的策略通过以下公式表示：

$$
\pi_{t+1} = \pi_t \oplus \Delta\pi
$$

其中 $\Delta\pi$ 为补丁集 $P = \{p_j\}$ 的累积效应。设计动机在于：全量策略重写易引入不可控变化，而最小补丁确保每次修改局部、可验证且可追溯，避免了 SLM 因上下文饱和导致的幻觉工具调用与无效更新。

## 实验评估

实验在 MGSM、DROP、GPQA 和 LitBench 四个基准上进行，覆盖算术推理、离散推理、研究生级问答与创意写作。基线包括 Chain-of-Thought Self-Consistency（COT-SC）与 Gödel Agent。POLARIS 使用 Qwen2.5-7B-Instruct 模型，在两个 NVIDIA V100 GPU 上运行，每个实验允许自主演化 10 小时。

| 数据集 | 指标 | COT-SC | POLARIS (N=3) | POLARIS (N=5) |
|---|---|---|---|---|
| MGSM | Accuracy (%) | 68.0 | 72.0 | 71.6 |
| DROP | F1 (%) | 74.0 | 77.9 | 78.7 |
| GPQA | Accuracy (%) | 45.0 | 54.0 | 54.0 |
| LitBench | Accuracy (%) | 40.0 | 48.8 | 45.2 |

POLARIS 在所有数据集上均优于 COT-SC 基线，其中 GPQA 提升幅度最大（+9.0%），表明经验抽象在复杂推理任务中更有效。N=3 与 N=5 的性能差异较小，但 N=3 的方差更大，反映 SLM 在抽象多样化反思时的不稳定性。

消融实验显示，Gödel Agent 在 k=5（保留 5 条工具调用消息）时全部因 OOM 失败，而在 k=3 时虽减少 OOM 但陷入重复工具调用模式，无法实现有效自我改进。POLARIS 通过限制验证样本数（N=3 或 5）与工具调用历史（6 条消息），成功避免了 OOM，并在 10 次独立运行中实现了 40%-60% 的成功率（成功定义为策略更新提升测试性能）。

评估边界方面，论文未报告置信区间，且未与 SPIN、R-Zero 等自博弈 SOTA 方法直接对比，因后者依赖大模型与可验证奖励。代码未公开，但提供了详细的提示模板与算法伪代码，可复现性中等。

## 关联研究分析

从问题动机看，POLARIS 与 Self-Refine 和 Reflexion 同属响应级纠正路线，但关键差异在于更新粒度。Self-Refine 通过迭代批评优化单次输出，改进不持久；POLARIS 将失败抽象为代码补丁，实现策略级持久更新。这一差异源于任务特性：Self-Refine 适用于开放域生成，而 POLARIS 针对可执行策略的修复，要求更新可追溯且可复用。然而，POLARIS 未评估补丁在未见任务上的泛化率，仅在同一基准的测试集上验证性能，这限制了其结论的普适性。

从方法设计看，POLARIS 与 Gödel Agent 共享递归自我改进框架，但核心差异在于上下文管理。Gödel Agent 存储全量验证样本与历史演化步骤，导致上下文膨胀；POLARIS 通过经验抽象压缩信息，仅保留修复策略与最小补丁。这一设计解决了 SLM 的 OOM 问题，但牺牲了反思的多样性。当 N 增大时，抽象策略变得更通用，但性能增益未显著提升，表明 SLM 的元推理能力限制了从多样化反思中提取有效策略的能力。

## 总结

POLARIS 解决了 SLM 在递归自我改进中因上下文膨胀导致的 OOM 问题，通过经验抽象将失败转化为最小代码补丁，实现了可追溯的策略持久化更新。实验表明，该方法在 MGSM、DROP、GPQA 和 LitBench 上均优于 COT-SC 基线，其中 GPQA 提升 9.0%。然而，其性能增益依赖于骨干模型的元推理能力，且未量化补丁在未见任务上的泛化性。当验证集失败案例多样性增加时，经验抽象是否仍能生成有效修复策略，论文未给出回答。
