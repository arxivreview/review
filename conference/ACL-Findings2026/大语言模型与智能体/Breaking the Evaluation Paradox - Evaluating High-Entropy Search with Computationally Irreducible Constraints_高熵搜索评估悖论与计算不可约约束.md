# ACL-Findings2026最新论文 ｜Breaking the Evaluation Paradox: Evaluating High-Entropy Search with Computationally Irreducible Constraints ｜高熵搜索评估悖论与计算不可约约束

作者：Juntao Wu、Wei Wen、Xianting Huang 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_a63e276d803a)

> 高熵搜索（High-Entropy Queries, HEQs）要求模型在开放网络空间中枚举大量候选项，但验证完整性所需的真值集在任务定义上不可获得，导致现有基准系统性惩罚超额正确项。现有基于人工标注答案池的评估范式无法解决这一悖论，本文切入点是通过引入计算不可约的哈希约束，将枚举任务转化为稀疏答案搜索。具体做法是利用密码学哈希函数构建可自动验证且语义不可优化的约束，使模型必须执行真实的遍历搜索。该范式在理论上证明了与全量枚举的计算等价性，但在实证中暴露出对前沿模型区分度不足及缺乏语义歧义性模拟的局限。

## 研究背景

当智能体面对“列出某艺术家所有歌曲”这类请求时，其核心困境并非逻辑推导，而是搜索空间的遍历与停止决策。这种任务被称为高熵查询（High-Entropy Queries, HEQs），其成功依赖于对广阔候选空间的召回率，而非单一“最佳”答案的匹配。HEQs 的评估面临一个根本性矛盾：验证答案完整性需要完整的真值集，但 HEQs 的开放本质使得人工标注者无法确认证实所有有效项，导致标注池必然不完整。

现有 Web 搜索基准如 GAIA 和 BrowseComp 主要聚焦于“难找但易验证”的单答案问题，而 WideSearch 等虽尝试覆盖广度，但仍依赖部分标注的答案池。这种设计导致评估性能被标注覆盖度而非模型真实搜索能力所限制，模型发现标注池之外的有效项时会被误判为幻觉。本文指出，解决这一悖论不能依靠更详尽的人工标注，而需重构评估问题本身，将评估目标从“精确枚举”解耦为“系统性搜索与校准不确定性”。

## 核心方法

### 方法参照系

本文问题属于 Web 智能体评估范畴，与 GAIA 等基准共享工具调用接口（Search, Visit, Exec Python, Answer）。关键差异在于验证机制：传统基准依赖人工标注的完整答案集进行匹配，而 VERITAS 摒弃人工标注，采用自动生成的稀疏约束目标，将评估重心从“答案匹配”转移至“搜索过程的有效性”。

### 计算等价性论证

设计动机在于消除语义捷径。传统 HEQs 中，模型可利用搜索引擎的索引机制直接过滤语义约束（如“2012年发行的歌曲”），从而绕过全量遍历。本文引入非优化约束，使搜索成本与全量枚举等价。设搜索空间大小为 $N$，满足约束的目标项数为 $k$，智能体搜索预算为 $T$。在均匀分布假设下，找到所有 $k$ 个目标项的成功概率近似为：

$$ P_{success}(k, T, N) \approx \left( \frac{T}{N} \right)^k $$

该公式表明，当 $k$ 固定时，成功概率随 $T/N$ 呈指数衰减；当 $T \ll N$ 时，即使 $k=1$，成功概率也仅为 $T/N$。这证明了在有限预算下，寻找稀疏哈希目标在计算复杂度上与全量枚举 $O(N)$ 等价，迫使模型执行真实的遍历而非语义检索。

### 哈希约束实现

设计动机在于确保约束的“语义空性”与“单向验证性”。语义约束（如风格、时长）可被搜索引擎优化，而密码学哈希函数（如 MD5）的输出与输入语义无关联，且具备雪崩效应，使得哈希值无法作为检索信号。VERITAS 通过计算候选项标识符或衍生属性（如 Git commit SHA）的哈希值，并与目标哈希比对来验证答案。这种机制使得模型无法通过查询哈希值缩小搜索范围，必须枚举候选项并逐一验证，从而隔离了枚举能力与语义理解能力，实现了评估的纯粹性。

## 实验评估

实验在 VERITAS 基准的三个难度层级（Medium, Hard, Extra Hard）上评估了 9 个模型，包括 GPT-5、Gemini-3-Pro 等前沿模型及 GLM-4、Kimi-K2 等开源模型。基线覆盖广泛，但缺失 CRAFT、GlobalRAG 等专注于推理轨迹忠实度或检索优化的 RAG 专用方法，这些方法在 HEQs 中的表现未被测试。

| 模型 | Medium Pass@4 (%) | Hard Pass@4 (%) | Extra Hard Pass@4 (%) |
| :--- | :--- | :--- | :--- |
| GPT-5 | 47.5 | 32.7 | 20.0 |
| Gemini-3-Pro | 30.0 | 36.7 | 6.7 |
| GLM-4 | 17.9 | 12.2 | 3.3 |
| Kimi-K2 | 2.5 | 10.2 | 0.0 |

GPT-5 在 Medium 层级以 47.5% 的成功率领先，但在 Extra Hard 层级下降至 20.0%，降幅达 2.4 倍。Gemini-3-Pro 在 Hard 层级表现优于 GPT-5（36.7% vs 32.7%），但在 Extra Hard 层级急剧下降至 6.7%。大多数开源模型在 Extra Hard 层级成功率降至 0-3.6%，其中 GPT-4o 和 Kimi-K2 为 0%。这一结果验证了 $(T/N)^k$ 框架的有效性：随着有效搜索空间 $N$ 的扩大，固定预算下的成功概率崩溃。

VERITAS 迫使模型进行真实遍历的证据体现在工具调用量上。与 WideSearch 相比，VERITAS 诱发了 1.4 至 4.2 倍的工具调用次数，但成功率依然较低。例如，GLM-4 平均每次查询发出 31.3 次工具调用（19.8 次 Search，10.0 次 Visit），远超 GAIA 的 <10 次，但成功率仍低于 12%。这表明模型识别了探索需求，但未能实现足够的覆盖度，揭示了当前模型在系统性搜索策略上的缺陷。

评估边界方面，VERITAS 依赖哈希约束的自动验证，避免了人工标注偏差，但缺乏对语义歧义性的模拟。Pass@4 指标虽能区分前沿模型，但未能深入分析失败模式是源于注意力分散还是搜索策略缺陷。代码未公开，且实验未报告置信区间，数值比较需谨慎。

## 关联研究分析

从问题动机看，VERITAS 与 CRAFT 均关注评估的忠实性，但路径截然不同。CRAFT 通过双奖励设计优化推理轨迹的结构化与可审计性，旨在解决“答案对但理由错”的捷径学习问题，其核心假设是推理链可被外部验证。VERITAS 则从源头消除捷径，通过哈希约束使语义优化失效，强制模型执行遍历。差异根源在于任务特性：CRAFT 针对的是逻辑推导中的中间步骤错误，而 VERITAS 针对的是空间遍历中的覆盖度不足。VERITAS 未探索语义歧义性，这是否限制了其在真实 Web 场景中的泛化能力，论文未给出回答。

从方法设计看，VERITAS 与 WideSearch 同属广度搜索基准，但验证机制存在根本冲突。WideSearch 依赖人工标注的实体池，存在“标注覆盖度上限”问题，可能惩罚发现新实体的模型。VERITAS 采用计算不可约约束，实现了真值的自动扩展与精确验证。这一冲突暗示了评估范式的转变：从“模拟现实的不完美”转向“构建计算纯粹的挑战”。VERITAS 的哈希约束虽然解决了验证悖论，但可能过度简化了真实 Web 搜索中的语义关联，导致评估结果与真实场景的偏差。

## 总结

本文要解决的核心矛盾是高熵搜索评估中真值不可获得与验证完整性需求之间的悖论。现有方法依赖部分标注，导致评估被标注覆盖度限制，而本文通过引入计算不可约的哈希约束，将枚举任务转化为稀疏搜索，实现了真值的自动验证与难度控制。VERITAS 证明了寻找稀疏哈希目标与全量枚举的计算等价性，实验显示 GPT-5 在 Extra Hard 层级成功率降至 20.0%，揭示了前沿模型在系统性搜索上的局限。本文的边界在于哈希约束消除了语义捷径，但可能忽略了真实 Web 搜索中的语义歧义性与动态性。当搜索空间中存在大量语义相似但哈希不同的干扰项时，模型的搜索策略是否仍能有效区分目标，论文未给出回答。
