# ACL-Findings2026最新论文 ｜DeepSynth-Eval: Objectively Evaluating Information Consolidation in Deep Survey Writing ｜深度合成评估基准

作者：Hongzhi Zhang、Yuanze Hu、Tinghai Zhang 等 12 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_07078d88d367)

> 深度研究智能体（Deep Research Agents, DRA）的核心瓶颈已从信息检索转移至海量证据的结构化整合，但现有评估体系因混淆检索噪声与合成能力、依赖主观评分而失效。本文通过逆向工程高质量综述，构建隔离检索的“Oracle Context”与细粒度清单指标，将开放式报告评估转化为可验证的客观任务。实验表明，多轮智能体工作流显著优于单轮生成，但百篇级文献的综合仍是当前模型的硬瓶颈。该基准填补了“检索后合成”的评估空白，但其封闭世界设定是否高估了开放环境下的真实能力，尚存争议。

## 研究背景

当智能体面对百万词级的参考文献时，其上下文窗口限制导致早期关键证据丢失，且长文本生成缺乏唯一标准答案，使得传统问答指标失效。这一困境催生了“检索后合成”（Post-Retrieval Synthesis）概念：在给定完整证据集的前提下，模型需将碎片化信息重组为连贯、结构化的长报告。该过程区别于简单的信息抽取，要求模型具备跨文档推理与全局逻辑重构能力，是深度研究任务中“最后一公里”的核心挑战。

现有评估路线存在两个根本缺陷。端到端基准（如 GAIA、BrowseComp）将检索与生成耦合，无法区分模型是“搜得准”还是“写得对”，且动态网络环境导致结果不可复现。长上下文基准（如 LongBench）多局限于“大海捞针”式的信息定位，未考察对分散证据的逻辑整合。针对这一空白，本文提出 DeepSynth-Eval (DSE)，通过剥离检索环节、引入结构化约束，专门量化模型在封闭证据集下的深度合成能力。

## 核心方法

### 方法参照系

DSE 属于基准评测体系路线，其参照系为基于 LLM-as-Judge 的开放式报告评估。与 ReportBench 等端到端评估不同，DSE 的关键差异在于引入“Oracle Context”（从综述参考文献重建的完整证据集），强制模型在已知全部正确证据的条件下进行合成，从而隔离检索噪声，专攻综合质量。

### 逆向工程与清单构建

设计动机在于解决开放式写作中“结构主观性”导致的评估不可比问题。通常做法是直接对比生成报告与参考综述，但长文本比对计算昂贵且指标不可靠。本文采用“逆向工程”策略：从高质量综述 $R$ 反推研究请求 $q_{gen}$，并提取两类清单。通用清单 $C_{gen}$ 覆盖核心事实，约束清单 $C_{con}$ 则从综述中提取特定分类法或表格结构，作为显式指令 $q_{con}$ 加入提示。这种设计将“自由写作”转化为“约束遵循”，使结构组织变得可验证。

### 容错分组评分机制

设计动机在于防止长清单组因项目数量多而主导最终分数，导致评估偏向“列举”而非“综合”。传统归一化 $S_k/N_k$ 会过度惩罚长组。本文引入饱和阈值 $\theta_k \le N_k$，定义分组得分：

$$
Score_k = \max\left(0, \min\left(1, \frac{S_k}{\theta_k}\right)\right)
$$

其中 $S_k = \sum_{c \in G_k} r(c)$ 为组内累积奖励，$r(c) \in \{1, 0, -1\}$ 分别对应正确、遗漏、错误。该公式意味着，当组内正确项数达到阈值 $\theta_k$ 时，该组即视为“完全覆盖”，后续项不再增加分数。例如，若一组含 15 项且 $\theta_k=10$，则答对 10 项即得满分。最终总分 $S_{all}$ 在组级别进行等权聚合，确保不同长度的清单组对最终得分贡献公平，从而更准确地反映模型的综合能力而非记忆广度。

## 实验评估

实验在 DSE 的 96 个任务上进行，基线覆盖 Qwen3-30B、Qwen3-235B、DeepSeek-V3.2 及 GPT-5.2，采用单轮端到端（E2E）与多轮智能体（Agentic）两种工作流。基线缺失专门的 DRA 智能体（如 ASearcher），因本文仅测合成阶段。

| 模型 | 工作流 | Overall (%) | General (%) | Constraint (%) | Precision (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Reference Survey | - | 96.1 | 95.5 | 98.9 | 99.6 |
| Qwen3-30B-A3B | E2E | 6.3 | 4.8 | 11.4 | 69.5 |
| Qwen3-235B-A22B | E2E | 24.8 | 24.7 | 23.3 | 79.9 |
| Qwen3-235B-A22B | Agentic | 35.5 | - | - | - |
| GPT-5.2 | E2E | 28.3 | - | - | - |
| GPT-5.2 | Agentic | 33.3 | - | - | - |

*注：表中数值逐字取自论文实验数据区。Agentic 工作流下 General/Constraint/Precision 具体数值未在数据区提供，故留空。*

核心发现是 Agentic 工作流在所有模型上均显著优于 E2E：Qwen3-30B 从 6.3% 提升至 17.3%，Qwen3-235B 从 24.8% 提升至 35.5%，GPT-5.2 从 28.3% 提升至 33.3%。这表明“规划-写作-润色”的多阶段流程能有效缓解长上下文下的信息丢失与结构混乱。然而，即便最强的 GPT-5.2 在 Agentic 模式下 Overall 仅 33.3%，远低于参考综述的 96.1%，证实百篇级文献的深度综合仍是当前 LLM 的硬瓶颈。

评估边界方面，DSE 依赖 LLM-as-Judge 进行清单验证，虽通过细粒度项降低了主观性，但 Judge 模型自身的偏见仍可能影响结果。此外，Oracle Context 的构建依赖 Semantic Scholar 与 arXiv API，长尾文献通过 PDF 解析恢复，可能存在元数据缺失导致的上下文不完整。论文未报告计算成本与 GPU 资源，且未提供置信区间，数值比较需谨慎。

## 关联研究分析

从问题动机看，DSE 与 ReportBench 均基于“逆向工程综述”思路，但 ReportBench 评估端到端系统，混淆了检索与合成能力；DSE 通过 Oracle Context 隔离检索，专攻合成质量。这一差异源于任务特性：ReportBench 关注系统整体鲁棒性，而 DSE 关注模型内在的认知整合能力。DSE 的封闭世界设定虽提高了可复现性，但可能高估模型在开放网络中面对噪声与冲突信息时的表现，因为真实场景中模型需自行筛选证据，而非被动接收“完美”上下文。

从方法设计看，DSE 的约束清单机制与 WebWeaver 的双智能体框架在“结构感知”上异曲同工，但 WebWeaver 通过动态大纲优化在生成过程中实时调整结构，而 DSE 将结构约束前置为静态指令。DSE 的静态约束更易于评估，但可能限制了模型的创造性组织方式；WebWeaver 的动态规划更灵活，但难以客观量化其结构质量。DSE 的饱和阈值设计解决了长清单主导分数的问题，但阈值 $\theta_k$ 的设定缺乏理论依据，不同任务的最优阈值可能差异巨大，论文未探讨其对评估公平性的影响。

## 总结

DSE 解决了深度研究评估中“检索与合成耦合”及“主观评分不稳定”的核心矛盾，通过逆向工程综述构建 Oracle Context 与细粒度清单，将开放式报告评估转化为可验证的客观任务。实验证明，Agentic 工作流在长上下文合成中显著优于单轮生成，但即便最强模型 Overall 仅 33.3%，揭示百篇级文献综合仍是瓶颈。其边界在于封闭世界设定可能高估开放环境下的真实能力，且约束清单的静态性可能限制模型的组织灵活性。当 Oracle Context 中引入噪声或冲突信息时，模型的合成能力是否会发生断崖式下跌，论文未给出回答。
