# ACL-Findings2026最新论文 ｜Improving LLM Code Reasoning via Semantic Equivalence Self-Play with Formal Verification ｜基于形式化验证的语义等价自博弈训练

研究机构：英国爱丁堡大学

作者：Antonio Valerio Miceli Barone、Poon Tsz Nok

论文原文见 [arXiv](https://arxiv.org/abs/2604.17010)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.17010)

> 现有LLM在代码生成中常因缺乏深层语义理解而产生逻辑错误，传统测试套件无法覆盖所有边界情况，导致程序重构与优化中的等价性判定不可靠。本文切入点在于利用Haskell语言的纯函数特性与Liquid Haskell的形式化证明能力，构建一个生成器与评估器对抗的自博弈闭环，通过形式化证明作为确定性监督信号来训练模型识别程序语义等价性。该方法在EquiBench上实现了最高13.3个百分点的准确率提升，并验证了等价性证明监督对语义推理能力的独特贡献。然而，该方法局限于Haskell生态，且在小模型规模下证明生成率极低，其跨语言泛化能力与大规模系统适用性仍存疑。

## 研究背景

当LLM生成的代码通过单元测试却仍隐藏逻辑缺陷时，问题根源在于测试用例无法穷尽所有输入空间。解决这一困境需要引入形式化验证，即通过数学逻辑证明程序行为符合规格说明。然而，通用程序语义等价性判定被Rice定理证明为不可判定问题，传统符号执行因状态空间爆炸而失效。Liquid Haskell通过精炼类型（Refinement Types）将逻辑属性嵌入语言，利用SMT求解器自动验证点态相等性，为特定子集的程序提供了机器可检查的等价性证明，从而绕过了通用不可判定性的限制。

当前LLM代码生成领域的主流路线是“生成-验证-修复”闭环，其中验证器（如Dafny、Verus）作为真理裁判过滤幻觉。但这一范式主要关注代码的正确性（Correctness），即代码是否符合预设规格，而非代码之间的等价性（Equivalence）。对于程序重构、优化等下游任务，核心需求是判断两个不同实现是否语义一致。现有方法如DeepSeekProver侧重于定理证明能力的微调，而Miceli-Barone et al. (2025)提出的SINQ框架仅利用执行反例进行不等价性训练，缺乏对等价性正例的深层逻辑监督。本文旨在填补这一空白，将形式化等价性证明引入自博弈训练，使模型不仅学会“找错”，更学会“证同”。

## 核心方法

### 方法参照系

本文问题属于神经符号集成中的验证器引导优化范畴，但与传统“生成-验证-修复”流程的关键差异在于：传统流程中验证器用于修正单次生成的错误，而本文将验证结果转化为自博弈中的难度评分与训练数据筛选信号，通过对抗迭代提升模型的语义判别能力，而非直接修复代码。

### 双任务对抗博弈框架

在标准自博弈中，生成器与评估器通常基于执行反馈或人类偏好进行交互。本文引入Liquid Haskell作为外部Oracle，构建了SEQ（语义等价）与SINQ（语义不等价）双任务机制。设计动机在于解决纯执行反馈无法提供深层逻辑推理轨迹的问题，通过形式化证明强制模型理解等价性的数学本质。在SEQ任务中，生成器Alice需生成等价变体 $Q$ 及证明 $\pi$，评估器Bob需判断 $P$ 与 $Q$ 等价；在SINQ任务中，Alice需生成不等价变体及反例输入。

难度评分机制是课程学习的关键。Bob对每对 $(P, Q)$ 采样 $N$ 次，其正确率 $N_{success}$ 决定难度分数 $\hat{d}$：

$$ \hat{d} = 1 - \frac{N_{success}}{N} $$

该公式表明，Bob越难判断的样本，其难度分数越高，越应被保留用于训练。通过阈值 $\tau$ 筛选高难度样本，确保训练数据聚焦于模型当前的认知边界，避免低难度样本导致的过拟合。

### 形式化证明监督与数据筛选

传统SFT训练依赖静态数据集，缺乏动态难度适应。本文创新点在于将Liquid Haskell验证结果直接转化为训练信号。设计动机在于解决小模型生成形式化证明成功率低导致的数据稀缺问题。Alice生成的SEQ样本必须通过Liquid Haskell验证，证明脚本 $\pi$ 作为监督信号的一部分，训练Alice内部化证明义务 $\forall x. P(x) = Q(x)$。

训练数据构建采用拒绝采样SFT。对于Alice，保留高难度样本及20%的低难度样本以维持课程平衡，并额外引入“难度预测”实例，训练Alice自我评估生成难度。对于Bob，仅保留其判断正确的样本，覆盖全难度范围以增强鲁棒性。这种机制确保了训练数据的高保真度：SEQ样本由形式化证明保证逻辑正确，SINQ样本由执行反例保证行为差异，从而消除了LLM幻觉对训练数据的污染。

## 实验评估

实验基于DeepSeek-R1-Distill-Qwen-7B基座模型，使用LoRA适配器微调。主实验 $E_0$ 采用50/50的SEQ/SINQ比例，对比基线为未微调的Base Model。基线审计显示，本文未对比AxDafny等前沿SOTA方法，也未在DafnyBench等标准基准上测试，评估范围局限于Haskell及跨语言迁移任务。

| 基准 | 指标 | Base | Trained | Δ |
| :--- | :--- | :--- | :--- | :--- |
| EquiBench (OJ_A) | Accuracy (%) | 50.2 | 69.8 | +19.6 |
| EquiBench (OJ_V) | Accuracy (%) | 51.9 | 55.8 | +3.9 |
| HumanEval (Haskell) | Pass@1 (%) | 17.7 | 26.4 | +8.7 |
| MBPP (Haskell) | Pass@1 (%) | 26.7 | 36.9 | +10.2 |

EquiBench上的显著提升（OJ_A +19.6%）表明Haskell语义推理训练能有效迁移到Python算法重构任务，但OJ_VA（混合变化）提升有限，暗示模型对复杂结构变化的泛化能力不足。Haskell代码生成任务的Pass@1提升（+8.7%至+10.2%）及编译错误减少（-20至-47次）证实了语义理解对代码质量的正向影响。

消融实验 $E_1$-$E_3$ 解耦了监督类型与数据量的影响。$E_1$（纯SINQ）验证对数最多（1839对），但语义推理性能低于 $E_0$（937对）。$E_2$（96% SEQ）因证明生成率低导致验证对数骤降至140对，性能全面退化。$E_3$（纯SINQ，量控）与 $E_2$ 对比显示，在相同数据量下，SEQ监督在结构推理任务上仍具优势。这证实了等价性证明提供的逻辑深度是执行反例无法替代的，但数据量仍是性能瓶颈。

评估边界方面，本文未报告置信区间，且 $E_2$/$E_3$ 样本量过小（约150对），统计显著性存疑。代码与数据集已开源，但依赖Haskell编译器与Liquid Haskell工具链，复现门槛较高。跨语言迁移仅在Python/C++的特定任务上验证，未覆盖系统级依赖或并发场景。

## 关联研究分析

从问题动机看，本文与AlphaVerus等端到端验证代码生成方法存在根本差异。AlphaVerus旨在生成通过验证器检查的新代码，关注“正确性”；本文旨在评估现有代码对的等价性，关注“语义理解”。这一差异源于任务特性：代码生成需要验证器作为最终裁决，而等价性判定需要验证器提供训练信号。本文未探索将验证器反馈直接用于代码修复，而是将其转化为自博弈的难度评分，这暗示在数据稀缺的小模型场景下，课程学习比直接修复更能提升泛化能力。

从方法设计看，本文与DeepSeekProver同属形式化证明微调路线，但DeepSeekProver聚焦于Lean定理证明，本文聚焦于Haskell等价性证明。DeepSeekProver证明了证明微调能提升推理能力，但未区分等价性与不等价性监督的贡献。本文通过消融实验揭示了SEQ监督的独特价值，弥补了DeepSeekProver在监督信号细粒度分析上的缺失。然而，本文局限于Haskell的纯函数特性，而DeepSeekProver的Lean生态更通用，这限制了本文方法在命令式语言中的直接迁移。

## 总结

本文核心矛盾在于LLM缺乏深层语义理解导致代码等价性判定不可靠，现有测试套件无法覆盖边界情况。切入点在于利用Haskell的纯函数特性与Liquid Haskell的形式化证明，构建自博弈闭环，通过形式化证明作为确定性监督信号训练模型。方法上，引入SEQ/SINQ双任务与难度评分机制，确保训练数据聚焦于模型认知边界。实验证明，该方法在EquiBench OJ_A上实现19.6%的准确率提升，并验证了等价性证明监督对语义推理的独特贡献。边界在于，7B小模型证明生成率极低（SEQ验证对数仅937），导致数据量受限，且方法局限于Haskell生态，跨语言迁移仅在特定任务上有效。当模型规模扩大至70B以上时，证明生成率是否足以支撑大规模自博弈训练，从而消除数据量瓶颈，论文未给出回答。
