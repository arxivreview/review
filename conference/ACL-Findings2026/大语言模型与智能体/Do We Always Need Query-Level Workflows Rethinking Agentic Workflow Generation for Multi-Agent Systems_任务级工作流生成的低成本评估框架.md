# ACL-Findings2026最新论文 ｜Do We Always Need Query-Level Workflows? Rethinking Agentic Workflow Generation for Multi-Agent Systems ｜任务级工作流生成的低成本评估框架

研究机构：中国科学院、中国科学院大学

作者：Zixu Wang、Bingbing Xu、Yige Yuan 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.11147)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.11147)

> 多智能体系统（MAS）的工作流生成面临高昂的计算开销，任务级方法需对每个候选工作流执行全量验证集评估，而查询级方法则为每个输入生成独立工作流，两者均存在显著的资源浪费。本文指出，任务级方法中全量执行评估既昂贵又不可靠，且查询级生成并非总是必要。SCALE 框架通过引入“自预测+少样本校准”机制替代全量执行，在保持性能的同时大幅降低 Token 消耗。该研究揭示了现有评估范式的低效性，但其结论是否适用于所有任务分布仍需进一步验证。

## 研究背景

当 LLM 智能体处理复杂推理或代码生成任务时，单一模型往往难以胜任，需通过多智能体协作（MAS）将任务分解为多个交互步骤。这种协作结构被称为智能体工作流（Agentic Workflow），其生成方式主要分为任务级与查询级两类。任务级方法旨在生成一个通用工作流以覆盖整个任务分布，而查询级方法则为每个具体输入定制独立的工作流结构。

现有主流路线在成本与性能之间均存在显著瓶颈。任务级方法如 AFlow 和 AgentPrune 依赖蒙特卡洛树搜索（MCTS）或强化学习，但每个候选工作流的评估需在全量验证集上执行，导致 Token 消耗随搜索轮次急剧增长，且在高性能区间，不同候选工作流的排名差异极小，评估的区分度有限。查询级方法如 ScoreFlow 虽能实现细粒度适应，但每个查询均需生成新工作流，引入了巨大的推理开销，且对于简单或相似输入，这种适应性带来的收益远低于其计算成本。本文切入点在于重新审视这两种范式的必要性：任务级评估是否必须全量执行？查询级生成是否总是优于任务级？

## 核心方法

### 方法参照系

本文基于 AFlow 的 MCTS 搜索框架，该框架包含选择、扩展、评估、回溯四个步骤。与标准流程的关键差异在于，本文将评估环节从“全量验证集执行”替换为“自预测+少样本校准”，旨在降低评估成本并提升评估可靠性。

### 自预测与少样本校准机制

在 MCTS 循环中，评估环节通常通过执行工作流 $W$ 在验证集 $D_{val}$ 上计算平均得分 $S_{exec}(W, D_{val})$。本文提出，在预热阶段（Warm-up Stage）执行 $M$ 轮全量评估后，后续迭代采用校准自预测分数 $\hat{S}_i$ 作为代理评估。具体而言，首先利用优化器 LLM $\phi$ 在专用评估提示 $P_{eval}$ 下生成自预测分数 $S_{pred}$，该分数反映模型对工作流性能的估计。随后，通过少样本执行校准，从验证集中采样极小子集 $D_{few}$（通常为 1-3%），计算执行分数 $S_{few}$，并基于两者差异进行校准。校准公式为：

$$
\hat{S}_i = S_{pred} + \alpha \cdot (S_{few} - S_{pred})
$$

其中 $\alpha$ 为校准系数，用于平衡自预测的偏差与少样本执行的高方差。这一设计解决了全量执行评估成本过高且区分度低的问题，通过结合模型的内在评估能力与少量真实执行信号，实现了低成本且可靠的性能估计。

### 动态评估提示与采样策略

为减少自预测的过度自信，本文将评估提示 $P_{eval}$ 与优化提示 $P_{optimizer}$ 分离，避免提示纠缠。少样本子集 $D_{few}$ 的采样基于预热阶段收集的统计信息，将验证集查询按预热工作流的平均得分 $s(\bar{q})$ 分箱，优先采样得分分布不均的查询，以提升校准信号的多样性。这一策略确保了少样本执行能够捕捉工作流性能的关键变化点，而非随机采样导致的噪声。

## 实验评估

实验在 DROP、HotpotQA、GSM8K、MATH、HumanEval 和 MBPP 六个基准上进行，基线包括任务级方法 AFlow、AgentPrune 和查询级方法 ScoreFlow。SCALE 在保持性能的同时，将 Token 消耗降低 54%-83%。

| 方法 | GSM8K Perf (%) | GSM8K Cost (Tokens) | HumanEval Perf (%) | HumanEval Cost (Tokens) |
| :--- | :--- | :--- | :--- | :--- |
| AFlow | 96.58 | 1.11e7 | 99.24 | 5.26e6 |
| SCALE | 95.83 | 4.04e6 | 98.47 | 1.09e6 |
| ScoreFlow | 97.79 | 2.83e7 | 98.91 | 3.86e6 |

SCALE 在 GSM8K 上性能下降 0.75%，Token 消耗降低 63%；在 HumanEval 上性能下降 0.77%，Token 消耗降低 79%。消融实验显示，未校准的自预测（SCALE S_pred）性能显著下降，少样本执行（SCALE S_few）成本较高，而校准自预测（SCALE）在成本与性能间取得最佳平衡。

评估边界方面，本文未报告置信区间，且未评估跨域泛化能力。代码未公开，超参数（如预热轮数 $M$、少样本比例）未详细披露，可复现性受限。

## 关联研究分析

从问题动机看，本文与 DAAO 均关注成本-性能平衡，但路径不同。DAAO 通过查询难度估计动态调整工作流深度与模型路由，属于查询自适应策略；而 SCALE 聚焦于任务级评估机制优化，通过降低评估成本实现效率提升。两者的差异源于任务特性：DAAO 假设查询难度分布不均，需动态适应；SCALE 假设任务级工作流已具备足够覆盖性，仅需优化评估过程。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从方法设计看，本文与 AFlow 同属 MCTS 搜索框架，但评估环节不同。AFlow 依赖全量执行评估，而 SCALE 引入自预测校准。这一差异源于对评估可靠性的质疑：本文发现全量执行在高性能区间区分度低，而自预测校准能更稳定地反映工作流质量。AFlow 的评估机制在低性能区间可能更可靠，但在高性能区间，SCALE 的校准策略更具优势。

## 总结

本文核心矛盾在于任务级工作流生成中全量执行评估的高成本与低区分度。SCALE 通过自预测+少样本校准替代全量执行，在 GSM8K 上性能下降 0.75% 的同时将 Token 消耗降低 63%。其边界在于未评估跨域泛化，且校准系数 $\alpha$ 的敏感性未充分探讨。当验证集规模增大时，少样本采样的代表性是否仍能维持校准精度，论文未给出回答。
