# ACL-Findings2026最新论文 ｜1,729 vs. 1729: The Effect of Scripts and Formats on LLM Numeracy ｜书写系统与格式对大语言模型算术能力的影响

研究机构：美国麻省理工学院

作者：Varshini Reddy、Craig W Schmidt、Seth Ebner 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_63bf8444c8f6)

> 大语言模型在标准阿拉伯数字下的算术表现优异，但一旦数字的书写系统或排版格式偏离训练语料的主流约定，其推理能力便出现断崖式下跌。现有鲁棒性评估多聚焦于数值本身的扰动，忽视了符号系统层面的表征偏差。本文通过构建覆盖21种数字脚本与6种排版格式的受控数据集，量化了这种“脚本税”的规模，并验证了提示工程在缓解该缺陷上的有效性。该研究揭示了多语言数值推理中被长期忽视的盲区，但其结论受限于未测试专门优化的数学模型，且仅通过外部提示而非内部表征修改来应对问题。

## 研究背景

当模型处理非阿拉伯数字（如天城文或波斯-阿拉伯数字）时，其内部子词切分器（Tokenizer）往往将单个数字拆分为多个子词单元，这种离散化过程破坏了数值的几何连续性。这种表征缺陷导致模型在处理多位数运算时，无法像处理标准阿拉伯数字那样高效地执行进位与借位操作，从而引发系统性错误。

大语言模型在数学基准上的高分往往掩盖了其推理的脆弱性，模型严重依赖表面模式匹配而非深层逻辑结构。主流鲁棒性评估路线，如GSM-Symbolic，通过改变问题中的数字值或实体名称来测试模型，但这类方法默认数字的书写系统保持不变。然而，预训练语料中阿拉伯数字占比高达72.4%，其他脚本占比极低，导致模型对非主流脚本存在系统性盲区。本文的切入点在于将扰动维度从“数值内容”扩展至“数值符号系统”，通过隔离脚本与格式变量，量化这种分布偏差对算术准确率的统计贡献。

## 核心方法

### 受控变量评估框架

本文采用静态基准变体测试鲁棒性，与GSM-Symbolic等动态生成方法不同，其核心差异在于保持算术逻辑恒定，仅改变数字的视觉呈现。这种设计旨在隔离“符号识别”与“逻辑推理”两个环节，明确性能下降是源于无法识别符号，还是源于识别后的计算失败。

### 混合效应模型量化脚本税

为量化脚本、格式及分词效率对准确率的独立影响，本文构建了一个广义线性混合效应模型（GLMER）。该模型将准确率作为二元响应变量，固定效应包括操作数总位数、算术运算类型、数字脚本、每数字Token数及提示策略，随机效应则涵盖模型与题目索引，以处理同一题目在不同脚本下的重复测量问题。模型公式如下：

$$
\text{response} \sim \text{total\_digits} + \text{operation} + \text{script} + \text{tokens\_per\_digit} + \text{prompt} + (1 | \text{model}) + (1 | \text{index})
$$

该公式的物理含义是，在控制模型个体差异和题目难度后，评估各表征因素对算术成功率的边际贡献。其中，“脚本税”被定义为非阿拉伯脚本相对于阿拉伯脚本参考水平的负向系数总和，反映了因训练数据稀缺导致的系统性性能惩罚。

### 提示工程缓解表征差距

针对脚本税，本文测试了多种提示策略，包括显式脚本名称提示、算子语言本地化以及阿拉伯-非阿拉伯数字映射表。实验发现，仅提供脚本名称无明显改善，而将算子翻译为对应脚本的语言，或提供完整的数字映射表，能显著提升准确率。这表明模型并非缺乏跨脚本的数值理解能力，而是缺乏将非标准符号映射到熟悉计算框架的显式桥梁。这种提示级干预无需修改模型参数，通过减少跨脚本干扰，部分弥补了内部表征的缺陷。

## 实验评估

实验基于336道基础算术题，覆盖21种脚本与6种格式，对比了9个大语言模型。基线审计显示，本文未包含DeepSeek-R1或Qwen-Math等专门针对数学优化的模型，这限制了结论在前沿数学模型上的普适性。

| 脚本 | 数据占比 (%) | GLMER系数 | p-Value |
| :--- | :--- | :--- | :--- |
| Hindu-Arabic | 72.4 | 0 (Ref) | - |
| Chinese | 0.3 | -3.544 | < 1e−8 |
| Tamil | 0.1 | -3.406 | < 1e−8 |
| Malayalam | 0.4 | -3.118 | < 1e−8 |
| Ol Chiki | 6e−4 | -3.09 | < 1e−8 |

数据显示，所有非阿拉伯脚本均产生显著的负向系数，其中中文数字（-3.544）和泰米尔数字（-3.406）的惩罚最大。每数字Token数（Tokens per Digit）的系数为-0.198（p < 1e−8），证实了分词效率与准确率的强负相关。Gemini 2.5 Pro因采用逐字Token化策略，在非阿拉伯脚本上表现最差，验证了离散化缺陷的假设。

消融实验表明，提示策略对性能有显著影响。在格式任务中，Few-shot提示的系数高达1.694（p < 1e−8），远超其他策略。在脚本任务中，“表达式+原生提示+映射”策略的系数为0.581，显著优于仅使用原生提示（0.238）。这一发现表明，显式的符号映射比隐式的上下文学习更能有效桥接表征差距。

评估边界方面，本文未报告置信区间，且部分低资源脚本（如Adlam, Osmanya）因准确率接近零而被排除在回归分析之外。代码与数据集将在Hugging Face发布，但超参数细节未在正文中完全披露。

## 关联研究分析

从问题动机看，本文与GSM-Symbolic同属鲁棒性评估路线，但扰动对象不同。GSM-Symbolic通过改变数字值测试逻辑泛化，而本文通过改变数字符号测试表征鲁棒性。这种差异揭示了模型脆弱性的两个独立维度：逻辑推理的稳定性与符号识别的稳定性。本文发现，即使逻辑正确，符号识别失败也会导致算术错误，这与GSM-Symbolic中“逻辑正确但数值错误”的失效模式形成互补。

从方法设计看，本文与BitTokens等内部表征优化方法形成对比。BitTokens旨在通过修改Token嵌入解决数值离散化问题，而本文仅通过外部提示缓解。这种差异暗示，提示工程可能只是掩盖了内部表征的根本缺陷，而非解决它。当模型面对未见过的脚本组合或更复杂的排版格式时，提示策略的泛化能力存疑。此外，本文未测试专门针对数学优化的模型，这些模型可能通过预训练或微调已部分缓解了脚本税，导致本文结论在SOTA模型上可能不成立。

## 总结

本文要解决的核心矛盾是LLM在标准数字下的高准确率与在非标准数字下的性能崩塌之间的反差。现有方法多关注数值逻辑的鲁棒性，忽视了符号系统层面的表征偏差。本文通过构建受控数据集与GLMER模型，量化了“脚本税”的规模，并证明提示工程能部分缓解该缺陷。实验显示，非阿拉伯脚本导致66-87%的性能下降，而Few-shot提示能带来1.694的系数提升。本文的边界在于未测试专门优化的数学模型，且仅通过外部提示而非内部表征修改来应对问题。当模型规模扩大或预训练数据包含更多多语言数字时，这种脚本税是否会自动消失，还是需要通过专门的数值几何重构来解决，论文未给出回答。
