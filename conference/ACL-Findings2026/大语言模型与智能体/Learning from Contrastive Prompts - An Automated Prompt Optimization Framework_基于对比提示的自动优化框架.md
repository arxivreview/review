# ACL-Findings2026最新论文 ｜Learning from Contrastive Prompts: An Automated Prompt Optimization Framework ｜基于对比提示的自动优化框架

作者：Mingqi Li、Karan Aggarwal、Yong Xie 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_89818f07c015)

> 自动提示优化（APO）旨在通过算法在离散指令空间中搜索最优提示，以解决闭源模型参数不可访问与人工试错效率低下的矛盾。现有反馈驱动方法如 ProTeGi 和 OPRO 主要依赖错误样本或历史排名列表，缺乏对“成功”与“失败”提示间结构性差异的显式建模，导致优化易陷入局部最优或过拟合特定错误模式。LCP 引入对比学习机制，通过直接分析高性能与低性能提示的语义差异来生成新候选，从而提取更具泛化性的提示设计原则。该方法在 Big-Bench Hard 基准上取得了显著的性能提升，但其高昂的计算成本与对特定模型家族的依赖限制了其通用性。

## 研究背景

当 LLM 面对复杂推理任务时，提示措辞的微小变化可能导致性能剧烈波动，这种现象被称为提示敏感性。为应对这一挑战，研究者将提示视为可优化的离散变量，形成了自动提示优化（APO）领域。然而，早期方法如 APE 依赖盲目搜索，效率低下；随后的 ProTeGi 引入“文本梯度”概念，通过 LLM 分析错误案例生成自然语言反馈，确立了反馈驱动优化的主流范式。

尽管反馈驱动方法提升了优化效率，但现有方案存在两个关键瓶颈：一是仅从错误样本中学习，忽略了成功提示中蕴含的正向结构信息，导致优化方向单一；二是依赖历史排名列表（如 OPRO）进行迭代，缺乏对提示间相对优劣的显式对比，难以捕捉细微的语义差异。LCP 的切入点在于利用 LLM 固有的对比推理能力，通过同时分析高、低性能提示，提取区分有效与无效指令的底层模式，从而克服单一错误反馈的局限性。

## 核心方法

### 方法参照系

LCP 属于反馈驱动的迭代优化路线，其标准流程包含候选生成、评估与选择三个环节。与 ProTeGi 仅基于错误样本生成反馈、OPRO 仅依赖历史排名列表不同，LCP 的关键差异在于引入了“对比提示生成”步骤，即利用 Top-K 和 Bottom-K 提示的差异作为优化信号，而非仅依赖绝对性能分数或单一错误分析。

### 候选生成与多样性注入

在候选生成阶段，LCP 首先从训练集中采样错误样本，利用 LLM 生成失败原因并总结为提示反馈。为避免过拟合特定错误模式，LCP 采用高温度设置（1.0）并生成 $N=10$ 个候选提示，以增强搜索空间的多样性。这一设计解决了 AutoHint 等早期方法因聚合单一提示候选而导致的泛化性不足问题。候选生成过程可形式化为：

$$
\mathcal{C}_t = \{ P_i \mid P_i = \text{LLM}(\text{Summarize}(\text{Reasons}(S_i)), H_{t-1}), i=1..N \}
$$

其中 $S_i$ 为第 $i$ 次采样的错误样本集，$H_{t-1}$ 为历史提示库。该公式表明，新候选不仅依赖当前错误反馈，还融合了历史迭代中的知识积累，从而在探索新方向的同时保持优化的连续性。

### 对比提示生成与模式提取

在候选评估后，LCP 根据训练集性能对候选进行排序，选取 Top-$K$ 和 Bottom-$K$ 提示作为对比对。核心创新在于利用 LLM 分析这两组提示的结构性与语义性差异，生成新提示 $P_{t+1}$。这一过程可表示为：

$$
P_{t+1} = \text{LLM}(\text{Contrast}(\text{Top}_K, \text{Bottom}_K), \text{MetaPrompt})
$$

其中 $\text{Contrast}(\cdot)$ 函数指示 LLM 识别区分高、低性能提示的底层模式，并生成遵循该模式的新指令。与 OPRO 仅依赖排名列表不同，LCP 通过显式对比，将优化信号从“哪个更好”提升为“为什么更好”，从而提取出更具普适性的提示设计原则，如结构化步骤或特定任务方法论。

## 实验评估

LCP 在 Big-Bench Hard（BBH）的 17 个任务上进行了评估，基线包括 AutoHint、OPRO、ProTeGi 和 DSPy。实验设置采用 50 个训练样本和 200 个测试样本，温度设为 1.0，最大迭代次数为 50。在 Claude-3-Sonnet 上，LCP 的整体胜率（Win Rate）达到 87.5%（最佳提示），显著高于 OPRO 的 42.19% 和 AutoHint 的 55.77%。在 Claude-4-Sonnet 上，LCP 的整体胜率为 75.7%（最佳提示），仍优于 OPRO 的 72.06%。

| 模型 | 方法 | 整体胜率 (Best %) | 整体胜率 (Last %) |
| :--- | :--- | :--- | :--- |
| Claude-3-Sonnet | LCP | 87.50 | 82.81 |
| Claude-3-Sonnet | OPRO | 42.19 | 45.31 |
| Claude-3-Sonnet | AutoHint | 55.77 | 57.69 |
| Claude-4-Sonnet | LCP | 75.74 | 89.71 |
| Claude-4-Sonnet | OPRO | 72.06 | 61.76 |

消融实验显示，对比学习机制对性能提升至关重要。当移除对比学习模块时，胜率从 87.5% 下降至 76%。此外，增加候选提示数量 $N$ 从 2 到 10 能持续提升性能，但 $N=10$ 后边际收益递减，且计算成本显著增加。LCP 在 DeepSeek-R1 上的整体胜率为 88.2%（最佳提示），高于 AutoHint 的 11.8%，表明其具有一定的模型无关性。

评估边界方面，LCP 主要依赖 BBH 和 SuperGLUE 基准，缺乏对多目标优化（如成本与准确率权衡）的评估。计算成本较高，LCP 平均需要约 28K 次 LLM 调用，耗时约 5 小时，远高于 OPRO 的 22K 次和 4 小时。代码未公开，且实验主要基于 Claude 系列模型，缺乏在 GPT 系列模型上的对比验证，限制了结论的普适性。

## 关联研究分析

从方法设计看，LCP 与 ProTeGi 的核心差异在于反馈信号的来源。ProTeGi 仅从错误样本中提取“文本梯度”，隐含假设错误分析足以指导优化；而 LCP 通过对比高、低性能提示，显式建模了“成功”与“失败”的边界。这一差异源于 LCP 认为单一错误反馈缺乏正向结构信息，可能导致提示过拟合特定错误模式。然而，LCP 未探讨当错误样本分布高度集中时，对比学习是否仍能提供有效的优化信号，这一场景下的有效性尚不明确。

从问题动机看，LCP 与 OPRO 均旨在自动化提示搜索，但 OPRO 依赖历史排名列表作为优化记忆，而 LCP 引入对比学习作为优化机制。OPRO 的排名列表仅反映相对优劣，缺乏对差异原因的解析；LCP 则通过 LLM 的对比推理能力，将排名转化为语义层面的模式提取。这一改进是否源于 LLM 对对比任务的天然敏感性，还是依赖于特定的元提示设计，论文未给出深入分析。此外，LCP 未考虑计算成本约束，而 GEPA 等方法已探索多目标优化，LCP 在资源受限场景下的表现未知。

## 总结

LCP 旨在解决反馈驱动提示优化中单一错误反馈导致的过拟合与泛化性不足问题。其切入点在于利用 LLM 的对比推理能力，通过显式分析高、低性能提示的差异，提取更具普适性的提示设计原则。LCP 在 BBH 基准上取得了 87.5% 的整体胜率（Claude-3-Sonnet），显著优于 OPRO 和 AutoHint。然而，其高昂的计算成本（约 28K 次 LLM 调用）和对 Claude 系列模型的依赖限制了其通用性。当计算预算受限或模型家族切换时，对比学习机制的边际收益是否依然显著，论文未给出回答。
