# ACL-Findings2026最新论文 ｜ENPMR-Bench: Benchmarking Proactive Memory Retrieval for Emotional Support Agents ｜情感需求感知主动记忆检索基准

作者：Xing Fu、Yulin Hu、Mengtong Ji 等 8 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_1e278c652254)

> 情感支持智能体面临的核心矛盾是用户情绪表达的间接性与记忆检索的语义表面性之间的错位。现有记忆基准假设用户能明确表达需求，导致检索目标与情感共鸣脱节，无法评估智能体推断潜在需求并匹配记忆类型的能力。本文通过构建基于马斯洛需求层级的结构化映射框架，将情感需求推断与记忆类型选择解耦为可评估的独立环节。该基准揭示了当前检索范式在情感场景下的系统性失效，但缺乏对动态记忆演化机制的验证，其结论的泛化性存疑。

## 研究背景

情感支持对话中，用户往往不直接陈述情绪需求，而是通过间接表达（如“没人对我的新零食感兴趣”）隐含孤独感或归属缺失。这种表达模式要求智能体超越表面语义相似度，推断潜在情感需求（Emotional Need-aware Proactive Memory Retrieval, ENPMR），并检索能引发情感共鸣的记忆类型（如关系型记忆而非偏好型记忆）。传统检索增强生成（Retrieval-Augmented Generation, RAG）依赖向量相似度匹配，无法捕捉“孤独感”与“关系型记忆”之间的语义鸿沟，导致检索结果虽语义相关但情感错位，削弱共情效果。

现有记忆基准（如LoCoMo、LongMemEval）聚焦事实检索与多跳推理，采用问答范式预设用户能明确指定检索目标。这一假设在情感支持场景中失效：用户无法清晰表述“我需要一段关于朋友支持我的记忆”，智能体必须从对话历史中推断需求并自主匹配记忆类型。Mem0、MemOS等智能体记忆系统虽实现了记忆整合，但其检索逻辑仍基于语义相关性，未建立情感需求与记忆类型的结构化映射。本文切入点在于将情感需求推断形式化为独立评估环节，通过马斯洛需求层级定义需求-记忆类型映射规则，构建首个系统评估ENPMR能力的基准。

## 核心方法

### 方法参照系

本文问题属于存储与检索优化路线，但改造了检索目标函数。通用RAG流程为：对话历史 $H$ → 向量嵌入 → 相似度检索 → 响应生成。本文关键差异在于：检索目标从“语义相关”变为“情感需求匹配”，引入需求推断模块作为检索前置条件，且记忆库按情感功能类型（而非语义主题）结构化组织。

### 需求-记忆类型映射框架

传统RAG中，检索评分函数仅依赖语义相似度：$s(m, H) = \cos(\mathbf{e}_m, \mathbf{e}_H)$，其中 $\mathbf{e}_m, \mathbf{e}_H$ 为记忆与对话历史的嵌入向量。该函数无法区分“语义相关但情感错位”的记忆（如用户表达孤独时检索到“喜欢烹饪”的偏好记忆）。本文引入马斯洛需求层级作为检索先验，定义需求推断函数 $\phi(H) \in \mathcal{N}$，其中 $\mathcal{N} = \{PN, LB, EN, SA\}$ 分别为生理、归属、尊重、自我实现需求。检索评分函数扩展为：

$$
s(m, H) = \alpha \cdot \cos(\mathbf{e}_m, \mathbf{e}_H) + \beta \cdot \mathbb{I}[\tau(m) = \psi(\phi(H))]
$$

其中 $\tau(m)$ 为记忆 $m$ 的情感功能类型，$\psi(\phi(H))$ 为需求 $\phi(H)$ 对应的目标记忆类型（如 $LB \rightarrow \{Relationship\}$），$\mathbb{I}[\cdot]$ 为指示函数。该公式将情感需求匹配作为硬约束引入评分，确保检索结果在情感功能上与推断需求对齐，解决语义相似度无法捕捉情感共鸣的失效。

### 结构化记忆库构建

记忆库构建遵循“需求-类型”映射原则，而非语义聚类。每条记忆 $m_i$ 标注情感功能类型 $\tau(m_i) \in \{Highlight, Power, Relationship, Goal, Preference\}$，并关联至特定生活主题。对话生成时，基于用户画像采样目标记忆 $m^*$，同时引入负采样：选取同主题但细节不同的记忆作为干扰项，迫使模型区分“语义相似但情感错位”的记忆。该设计将记忆检索从“找相关”转化为“找情感匹配”，使评估能分离需求推断错误与记忆选择错误，揭示智能体在情感推理环节的具体瓶颈。

## 实验评估

实验在自建ENPMR-Bench上进行，包含1,872段情感支持对话和11,846条记忆条目。基线覆盖三类路线：嵌入模型（Qwen3-Embedding-8B、gte-Qwen2-7B-instruct等）、智能体记忆系统（Mem0、MemOS、Memu）、LLM（GPT-4o、DeepSeek-V3等）。缺失知识图谱类方法（如HippoRAG），无法验证结构化表示在情感场景的优势。

| 方法 | Recall@10 | Precision@10 | nDCG@10 |
|---|---|---|---|
| Qwen3-Embedding-8B | 46.42 | 4.64 | 25.44 |
| doubao-embedding | 44.82 | 4.48 | 24.62 |
| gte-Qwen2-7B-instruct | 40.87 | 4.09 | 21.15 |
| text-embedding-3-large | 40.76 | 4.08 | 21.67 |

最佳嵌入模型Qwen3-Embedding-8B的Recall@10为46.42%，Top-1准确率均低于10%，表明语义相似度在情感记忆检索中严重失效。LLM评估中，DeepSeek-V3在base设置下共情得分4.38，w/Golden设置下提升至4.91，差距0.53分证实检索质量是主要瓶颈。CoT推理带来边际提升（如GPT-4o从4.18至4.17），但远未达w/Golden水平（4.58），说明需求推断能力仍不足。

| LLM | 设置 | TMR | Emp. (GPT) | Emp. (Human) |
|---|---|---|---|---|
| DeepSeek-V3 | base | 0.52 | 4.16 | 3.93 |
| DeepSeek-V3 | w/CoT | 0.59 | 4.23 | 4.20 |
| DeepSeek-V3 | w/Golden | – | 4.68 | 4.47 |
| GPT-4o | base | 0.50 | 4.34 | 4.12 |
| GPT-4o | w/Golden | – | 4.77 | 4.58 |

TMR（记忆类型匹配率）显示，即使CoT推理，模型在受限检索空间内最大TMR仅0.53，表明需求推断存在系统性偏差。Sankey图分析揭示，模型对“归属需求”系统性过度选择“Highlight”记忆而非“Relationship”记忆，导致该维度共情得分最低（如GPT-4o在LB维度3.82，显著低于EN维度4.56）。

评估协议采用LLM-as-Judge（GPT-4o）与人工标注双轨制，人工标注一致性达90%-95%。局限包括：记忆库静态，未验证动态巩固机制；仅评估单轮检索，未覆盖多轮交互中的记忆演化；缺乏跨语言泛化验证（基准为中文）。代码已开源，但超参数与GPU配置未在正文详述。

## 关联研究分析

从问题动机看，本文与Mem0等智能体记忆系统的核心差异在于检索目标函数。Mem0的检索逻辑基于事实相关性与冲突解决，其评分函数隐含假设“相关即有用”。本文揭示在情感场景中，该假设失效：语义相关的记忆可能情感错位，导致共情效果下降。这一差异源于任务特性：情感支持要求记忆不仅“正确”且“共鸣”，而事实检索仅需“正确”。论文未探索是否可通过调整Mem0的冲突解决机制（如引入情感权重）缓解此问题，仅将其作为基线对比。

从方法设计看，本文与HippoRAG的图谱检索路线形成潜在对比。HippoRAG通过知识图谱编码实体关系，支持多跳推理，其优势在于结构显式性。本文采用扁平向量+LLM推理的混合模式，未验证图谱在情感场景的优势。这一选择可能源于情感需求与记忆类型的映射是语义层面的（如“孤独”→“关系”），而非实体关系层面的（如“A帮助B”→“B感激A”）。但论文未提供证据支持扁平向量在情感场景优于图谱，也未分析图谱构建成本在情感记忆库中的可行性。查询侧增强（如CoT）在数据充足时是否仍有增益，论文未给出回答。

## 总结

ENPMR-Bench解决的核心矛盾是情感支持场景中用户需求表达的间接性与记忆检索语义表面性之间的错位。现有方法因假设用户能明确表达需求而失效，本文通过马斯洛需求层级建立需求-记忆类型映射，将情感需求推断形式化为可评估环节。实验证实当前检索范式在情感场景下严重失效：最佳Recall@10仅46.42%，LLM共情得分在w/Golden设置下仍比base设置高0.53分。本文边界在于记忆库静态、仅评估单轮检索、缺乏跨语言验证。当记忆库规模扩大至万级时，需求推断的延迟是否成为瓶颈，论文未给出回答。
