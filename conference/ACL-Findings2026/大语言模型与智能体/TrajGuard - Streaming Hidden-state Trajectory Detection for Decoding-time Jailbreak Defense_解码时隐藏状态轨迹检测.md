> 大语言模型（LLM）面临越狱攻击时，静态输入过滤常因语义伪装而失效，且后处理检测无法阻止有害内容生成。现有解码时防御多依赖额外训练的安全探针，成本高且仅做单点判断，忽略了风险在解码过程中的动态累积。TrajGuard 提出免训练的流式几何监控与条件触发的语义裁判级联框架，在解码过程中实时追踪隐藏状态轨迹以拦截越狱。该方法在开源模型上实现了高拦截率与低延迟，但其对黑盒 API 的适用性及免训练几何统计在分布外攻击下的鲁棒性仍存疑。

## 研究背景

当攻击者通过编码混淆或多轮对话隐藏恶意意图时，输入提示在潜在空间中往往与良性提示重叠，导致基于输入文本的分类器难以区分。这种静态表征的模糊性源于模型在提示阶段对语义的软化处理，而真正的风险信号往往在模型开始生成具体步骤时才逐渐显现。要捕捉这一动态过程，需监控解码过程中隐藏状态的演化轨迹，而非仅依赖单步激活值或最终输出。

越狱防御领域长期存在静态过滤与动态监控的路线之争。静态输入过滤（如 Llama Guard 3）部署简单，但在面对混淆攻击时漏检率高，且结合后处理过滤会显著增加端到端延迟。解码时防御路线（如 SafeDecoding、ShieldHead）虽能介入生成过程，但大多依赖额外训练的安全模型或奖励网络，不仅增加了数据与计算成本，还将安全对齐简化为二分类任务，忽略了风险随上下文累积的动态特性。TrajGuard 的切入点在于利用基础模型自身在解码时暴露的隐藏状态几何漂移，通过免训练的统计监控替代昂贵的训练探针，从而在低延迟约束下实现实时拦截。

## 核心方法

### 方法参照系

解码时防御的通用流程是在生成过程中对候选 token 或前缀进行安全评分，并据此调整解码概率或截断生成。本文问题与该通用流程的关键差异在于：不修改解码概率分布，不依赖额外训练的安全头，而是直接监控基础模型隐藏状态的几何轨迹，将防御逻辑从“概率重加权”转变为“轨迹异常检测”。

### 流式几何监控（SGS）

SGS 模块解决了单步激活值判断易受噪声干扰且无法捕捉长期漂移的问题。它首先通过均值向量差（MVD）指标筛选出越狱特征最显著的 $K=8$ 个关键层，并在这些层上构建良性与有害的高斯分布参考区域。对于每个解码步 $t$，计算隐藏状态 $h_{l,t}$ 到良性与有害质心的马氏距离，定义瞬时风险对比 $r_{l,t} = d_{l,t}^{[B]} - d_{l,t}^{[M]}$。为抑制局部波动，SGS 采用滑动窗口截断均值与指数加权移动平均（EWMA）进行时空聚合，得到流式风险分数 $s_t$。当 $s_t$ 连续 $k=3$ 步超过阈值 $\gamma$ 时，触发拦截警报。这一设计确保了只有持续的风险漂移才会激活昂贵的后续验证，而非瞬时的几何噪声。

$$ s_t = \alpha \cdot \text{Agg}(r_{l,t}) + (1-\alpha) s_{t-1} $$

该公式通过 EWMA 平滑瞬时风险对比，使 $s_t$ 反映系统性的风险偏移而非局部波动，从而在低延迟下稳定追踪解码路径的几何演化。

### 条件触发语义裁判（PAIR-Judge）

PAIR-Judge 模块解决了几何距离不等于语义恶意性的问题，即几何漂移可能由良性但敏感的查询引起。当 SGS 触发警报时，解码暂停，系统将当前提示 $x$ 与已生成前缀 $y_{\le t}$ 封装为语义假设，交由安全对齐的 LLM 裁判进行判断。裁判输出离散的 SAFE 或 UNSAFE 决策。若判定为 UNSAFE，则终止生成；若判定为 SAFE，则执行状态重置，将 SGS 的风险动量 $S_t$ 复位至初始安全值，清除历史积累的误报信号。这种闭环反馈机制防止了系统因遗留的几何偏差而反复触发警报，确保了良性交互中的“静默”运行。

$$ d = M_{\text{judge}}(P(x, y_{\le t})) \in \{\text{SAFE}, \text{UNSAFE}\} $$

该公式表明 PAIR-Judge 不依赖校准的概率阈值，而是利用 LLM 的内在安全对齐能力进行自主语义裁决，将高维内部信号转化为可解释的安全决策。

## 实验评估

实验在 Llama-2-7B、Llama-3.1-8B、Mistral-7B 和 Vicuna-7B 上进行，使用 HarmBench 生成 100 个有害行为，XSTest 和 Alpaca 评估误报率。基线覆盖 Llama Guard 3、Self-Guard、Goal Prioritization 和 Qwen3Guard，但未包含检索增强防御（如 RAD）或解码时概率重加权方法（如 SafeDecoding）。

| 防御方法 | XSTest FPR (%) | Alpaca FPR (%) | 延迟 (ms/token) |
| :--- | :--- | :--- | :--- |
| Llama Guard 3 | 8.40 | 0.00 | <0.1 |
| Self-Guard | 14.80 | 7.50 | 24.6 |
| Qwen3Guard | 12.40 | 0.00 | 42.8 |
| **TrajGuard** | **1.50** | **0.00** | **5.2** |

TrajGuard 在 XSTest 上的 FPR 为 1.50%，显著低于 Llama Guard 3 的 8.40% 和 Self-Guard 的 14.80%，同时延迟仅为 5.2 ms/token，远低于 Qwen3Guard 的 42.8 ms/token。在 HarmBench 上，TrajGuard 平均 ASR 为 0.02-0.10，优于 Llama Guard 3 的 0.20-0.26。

| 配置 | XSTest FPR (%) | 延迟 (ms/token) |
| :--- | :--- | :--- |
| w/o PAIR-Judge | 18.4 | 0.8 |
| w/o SGS | 1.0 | 750.2 |
| **TrajGuard (Full)** | **1.0** | **189.9** |

消融实验显示，移除 PAIR-Judge 导致 FPR 飙升至 18.4%，证明几何监控单独使用误报率高；移除 SGS 则导致延迟激增至 750.2 ms，证明条件触发机制对降低计算开销至关重要。完整配置在保持低 FPR 的同时，将延迟控制在 189.9 ms/token（注：此处为 per-sample 平均，与 per-token 5.2 ms 不同，原文 Table 4 报告的是 per-sample 平均墙钟时间，而 Table 2 报告的是 per-token 开销）。

评估边界方面，实验仅覆盖开源模型，无法验证黑盒 API 场景。ASR 评估依赖 GPT-4o 作为离线裁判，未报告置信区间。代码未公开，超参数如阈值 $\gamma$ 和窗口大小 $w$ 的敏感性分析仅在 Figure 5 中展示 Pareto 前沿，未提供具体数值表。

## 关联研究分析

从问题动机看，TrajGuard 与 AdaSteer 同属内部表征利用路线，但 AdaSteer 依赖训练探针引导解码，而 TrajGuard 采用免训练的几何统计。这一差异源于对“风险信号来源”的不同假设：AdaSteer 假设风险可通过线性探针从静态激活中提取，而 TrajGuard 假设风险在解码轨迹中动态累积。TrajGuard 的免训练设计降低了部署成本，但牺牲了对特定攻击模式的精细适应能力，其几何参考区域仅基于良性/恶意指令构建，未包含越狱回复，这可能限制了其对复杂多轮攻击的捕捉能力。

从方法设计看，TrajGuard 与 Constitutional Classifiers 的级联架构思想一致，但将计算重心从生成后移至解码中。Constitutional Classifiers 通过线性探针初筛加外部分类器复核，降低生成后的计算开销；TrajGuard 则通过 SGS 初筛加 PAIR-Judge 复核，降低解码时的计算开销。两者的核心差异在于监控对象：前者监控输出文本，后者监控内部状态。TrajGuard 在混淆攻击（如 Cipher）上表现更优，因为内部状态能重构被加密的语义，而文本分类器无法识别非自然分布的输入。然而，TrajGuard 的 PAIR-Judge 依赖目标模型自身或外部 LLM 的语义判断能力，若模型本身安全对齐较弱，裁判的可靠性可能下降，这一点在论文中未充分探讨。

## 总结

TrajGuard 旨在解决静态过滤在语义伪装下的失效与解码时防御的高训练成本之间的矛盾。它抓住了解码过程中隐藏状态从良性区域向有害区域漂移的动态特性，通过免训练的流式几何监控与条件触发的语义裁判级联，实现了实时拦截。实验证明其在开源模型上平均检测率达 95%，延迟仅 5.2 ms/token，FPR 低于 1.5%。然而，其几何参考区域仅基于指令构建，未包含越狱回复，且 PAIR-Judge 依赖模型自身的安全对齐能力。当面对针对特定防御机制优化的白盒自适应攻击时，免训练几何统计的鲁棒性是否仍能保持，论文未给出回答。
