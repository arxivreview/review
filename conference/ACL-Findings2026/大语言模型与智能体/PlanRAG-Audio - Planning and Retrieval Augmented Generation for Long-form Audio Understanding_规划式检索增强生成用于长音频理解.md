研究机构：美国卡内基梅隆大学

作者：Masao Someki、Chien-yu Huang、Siddhant Arora 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.20414)

> 长音频理解面临的核心矛盾是输入序列长度与模型上下文窗口的指数级冲突，导致现有大型音频语言模型在处理小时级录音时性能急剧衰减。传统端到端生成范式无法在有限算力下保留跨模态的时序依赖，而纯文本转录又丢失了副语言信息。本文提出 PlanRAG-Audio，通过“规划-检索-生成”三阶段框架，将长音频理解转化为结构化数据库查询问题，从而解耦推理成本与音频时长。该方法在零样本条件下实现了跨模态组合推理，但在语义泛化能力与标准短音频基准上的表现尚未验证。

## 研究背景

长音频理解的困境源于声学信号的时间延展性。当一段一小时讲座被转化为文本时，仅产生约 12k 个文本 token，但对应的语音 token 超过 100k。这种数量级的差异使得直接输入大型语言模型（LLM）成为计算瓶颈。为缓解此问题，检索增强生成（RAG）在文本领域通过选择性检索外部证据来缩小输入范围，但其核心假设是信息以离散文档形式存在。在音频领域，信息并非离散文档，而是连续的时间流，且语义分布在语音内容、说话人身份、情绪及非言语声音事件等多个模态中。这种多模态、时间对齐的特性使得直接套用文本 RAG 的向量相似度检索失效，因为简单的嵌入匹配无法捕捉跨模态的时序依赖与组合逻辑。

现有长音频理解方案主要依赖自动语音识别（ASR）管道或音频-文本对比嵌入。ASR 管道将语音转为文本后处理，虽解决了长度问题，但彻底丢弃了语调、背景噪声等非言语线索，导致在需要联合考虑语音与声学事件的组合推理任务上表现不佳。对比嵌入方法（如 CLAP）虽保留了声学特征，但受限于短片段处理，无法建模长程依赖。PlanRAG-Audio 的切入点在于将长音频理解重构为结构化信息检索问题：不直接处理原始音频流，而是预先将音频分解为时间对齐的多模态数据流，存储于结构化数据库中，再通过 LLM 规划检索策略，仅提取与查询相关的片段进行推理。

## 核心方法

### 方法参照系

本文问题属于长上下文推理中的信息筛选问题。通用 RAG 流程为“检索-生成”，即通过向量相似度从文档库中召回相关片段。本文的关键差异在于：音频数据具有严格的时间连续性与多模态异构性，无法通过单一向量空间表示。因此，PlanRAG-Audio 将“检索”前置为“规划”，并引入结构化数据库作为中间表示，替代了传统的向量索引库。

### 结构化音频数据库构建

设计动机在于解决多模态数据的时间对齐难题，使不同模态（如语音文本与说话人标签）能通过简单的时间戳连接，而非复杂的语义匹配。PlanRAG-Audio 首先通过说话人分离（Diarization）确定时间边界，随后在这些边界上并行执行语音识别、情绪识别与声音事件检测。所有流共享相同的时间戳结构，存储为包含起始时间、结束时间及标签-分数对的记录。这种设计使得跨模态查询（如“找出说话人 A 在情绪激动时提到的关键词”）可以通过时间重叠（temporal overlap）直接实现，无需训练专门的跨模态对齐模型。

### 规划驱动的 SQL 检索

设计动机在于解决 LLM 直接处理长序列时的注意力稀释与幻觉问题，通过显式规划将复杂推理分解为确定性的数据库操作。给定查询 $q$，规划 LLM 生成结构化检索计划 $\Theta(q)$，指定所需模态、过滤条件、融合策略及输出格式。该计划被编译为 SQL 查询 $Q(\Theta(q))$，执行后返回相关片段 $R(q, a)$：

$$ R(q, a) = \text{Exec}(Q(\Theta(q)), D(a)) $$

其中 $D(a)$ 为音频 $a$ 的结构化数据库。SQL 查询通过公共表表达式（CTE）定义各模态流，并通过时间连接实现融合。例如，查询“音乐何时开始”会被规划为检索声音事件流中“Music”标签的起始时间。这种机制将 LLM 的角色从“处理长序列”转变为“规划查询逻辑”，显著降低了输入 token 数量。

## 实验评估

实验在 LibriSQA、AMI、MSP-Podcast 等公开数据集上构建长音频评测集，时长覆盖 10 至 540 分钟。基线包括 Qwen3-4B、Gemini 2.5 Flash 及 Voxtral，对比直接处理与 PlanRAG-Audio 增强后的性能。

| 任务 | 模型 | 指标 | 无 PlanRAG | + PlanRAG |
| :--- | :--- | :--- | :--- | :--- |
| Speaker Count | Gemini | Acc (%) | 14.20 | 69.40 |
| Event Order | Gemini | Spearman | 0.30 | 0.68 |
| Speaker-Constrained QA | Gemini | Abst. Acc (%) | 0.54 | 94.90 |
| MCQA (60min) | Gemini | Avg. Tokens | 115.2k | 0.9k |

核心数字对比显示，PlanRAG-Audio 在 Gemini 上将说话人计数准确率从 14.20% 提升至 69.40%，事件排序相关性从 0.30 提升至 0.68。在说话人约束问答中，弃权准确率从 0.54% 跃升至 94.90%，表明模型能准确识别并仅检索指定说话人的片段。输入 token 数从 115.2k 降至 0.9k，验证了推理成本与音频时长的解耦。

消融分析表明，性能提升主要源于检索规划对外部化时序结构的作用。在说话人计数任务中，检索结果直接提供说话人标识，将复杂推理简化为标签计数；在事件排序中，时间戳显式提供，将排序简化为数值比较。Qwen 在 PlanRAG-Audio 下的提升幅度小于 Gemini，暗示规划机制对长上下文能力较弱的模型增益有限，但仍未解决其基础感知能力的瓶颈。

评估边界方面，实验仅使用自建长音频数据集，未在与 MMAU 或 AudioCaps 等标准短音频基准上的表现进行验证。代码与数据声明将在接收后发布，当前可复现性受限。指标采用任务特定标准（如 DER、F1），但未报告置信区间，数值比较需谨慎。

## 关联研究分析

从方法设计看，PlanRAG-Audio 与 Audio Flamingo Next 的时间对齐思维链（CoT）形成鲜明对比。AF-Next 在模型内部通过生成中间推理步骤来锚定时间戳，依赖 LLM 的长上下文注意力机制；而 PlanRAG-Audio 将时间结构外化至数据库，通过 SQL 查询直接获取时间对齐的片段。这种差异源于任务特性：AF-Next 面向通用理解，需保留模型内部的推理灵活性；PlanRAG-Audio 面向结构化检索，追求确定性与可扩展性。然而，PlanRAG-Audio 依赖关键词匹配的 SQL 检索，其语义泛化能力可能受限，例如对同义词或隐含语义的查询可能失效，这一点在论文中未深入探讨。

从问题动机看，PlanRAG-Audio 与 CLAP 等对比学习方法在检索机制上存在根本分歧。CLAP 通过共享嵌入空间实现零样本检索，依赖大规模配对数据训练，适用于短片段分类与检索；PlanRAG-Audio 则通过结构化数据库实现跨模态组合检索，无需训练对齐模型，适用于长音频复杂推理。这种分歧反映了领域内对“检索”定义的不同理解：前者是语义相似度匹配，后者是结构化信息提取。PlanRAG-Audio 的优势在于无需大规模标注数据，但其局限在于依赖预定义的模态流与 SQL 模板，难以处理未预见的查询类型。

## 总结

PlanRAG-Audio 解决了长音频理解中上下文窗口与计算成本的矛盾，通过规划式检索将小时级音频处理转化为结构化数据库查询。其核心创新在于将多模态时间对齐外化至数据库，并通过 LLM 规划 SQL 查询，实现了零样本条件下的跨模态组合推理。实验证明，该方法在 Gemini 上将说话人计数准确率提升至 69.40%，并将输入 token 数降低两个数量级。然而，其依赖关键词匹配的检索机制与预定义的模态流结构，限制了其在开放域查询中的泛化能力。当查询涉及隐含语义或未预见的模态组合时，SQL 模板的覆盖率是否足以支撑推理，论文未给出回答。
