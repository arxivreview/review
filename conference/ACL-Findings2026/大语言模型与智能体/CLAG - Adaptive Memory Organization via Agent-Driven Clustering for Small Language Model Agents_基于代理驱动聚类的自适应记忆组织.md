# ACL-Findings2026最新论文 ｜CLAG: Adaptive Memory Organization via Agent-Driven Clustering for Small Language Model Agents ｜基于代理驱动聚类的自适应记忆组织

研究机构：韩国高丽大学

作者：Taeyun Roh、Wonjune Jang、Junha Jung 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.15421)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.15421)

> 长程任务中，大语言模型（LLM）智能体依赖外部记忆维持连贯性，但传统全局检索池随记忆增长导致语义干扰与更新污染，小语言模型（SLM）对此尤为脆弱。现有代理记忆框架虽引入自进化机制，却仍在全局无结构存储中运行，无法隔离主题混杂带来的噪声。CLAG通过SLM代理在线路由将记忆划分为语义一致的簇，并在簇内执行局部演化与两阶段检索，以轻量级结构抑制跨主题干扰。该框架在SLM场景下显著提升了鲁棒性，但其对大模型骨干的增益边际递减，且未覆盖隐私合规与多模态对齐等生产级约束。

## 研究背景

智能体记忆系统需解决LLM无状态性与长程任务需求间的矛盾，核心在于平衡检索精度与存储效率。当记忆以扁平向量库形式存储时，检索依赖语义相似度，但无法区分“语义相关”与“任务相关”，导致SLM在长上下文下易被无关记忆误导。为缓解此问题，代理记忆框架（如A-mem、GAM）引入反思与重写机制，实现记忆的动态更新，但这些操作仍在全局池中进行，新记忆的演化可能污染无关主题，形成跨主题干扰。

该领域的演进主线从静态检索转向动态管理，但结构化表示的引入方式存在分歧。知识图谱方法（如HippoRAG）通过显式实体关系提升多跳推理，但构建成本高且依赖重型LLM；层级索引方法（如SwiftMem）优化检索复杂度，但未解决记忆演化中的语义漂移。CLAG的切入点在于：将聚类视为代理控制的在线操作，而非离线预处理，通过SLM路由建立轻量级语义邻域，使记忆演化局限于局部簇内，从而在保留自进化能力的同时抑制全局噪声。

## 核心方法

### 方法参照系

标准代理记忆流程包含写入、管理与读取闭环，通常采用全局向量检索与统一演化策略。CLAG的关键差异在于：将全局无结构存储替换为代理驱动的动态簇结构，写入时通过SLM路由分配簇，读取时执行两阶段检索，演化仅在簇内局部进行。

### 代理驱动路由与簇结构

传统方法在写入时直接追加至全局池，导致主题混杂。CLAG引入SLM代理路由，将新记忆 $m_{new}$ 分配至语义一致的簇。路由过程分为冷启动与在线阶段：当处理记忆数 $N_{processed} < n$ 时，缓冲记忆并初始化簇结构；否则，通过向量距离筛选Top-$k$候选簇，再由SLM代理评估簇画像选择最终簇 $C_{routed}$。若余弦相似度低于阈值 $\tau$，则创建新簇。该设计解决了全局池中主题混杂导致的更新误导问题，使每个簇成为自组织的语义单元。

$$
C_{routed} = \text{SLM.SelectCluster}(m_{new}, C_{topK})
$$

该公式表示SLM代理基于候选簇的语义画像（摘要、标签、代表性片段）选择最匹配簇，而非仅依赖向量距离，从而捕捉高层语义一致性。

### 局部演化与两阶段检索

簇内演化通过链接与重写提升记忆密度。新记忆 $m_{new}$ 分配至 $C_{routed}$ 后，系统计算簇内Top-$k$邻居 $M_{local}$，由SLM分析细粒度关系（因果、时序）生成链接 $L_{new}$，并更新邻居属性以反映新信息。检索阶段采用两阶段策略：第一阶段通过查询嵌入与簇质心距离筛选候选簇，再由SLM代理选择相关簇子集 $C_{selected}$；第二阶段仅在 $C_{selected}$ 内检索细粒度记忆。该机制将检索空间从全局缩小至局部，抑制SLM对干扰项的敏感度。

$$
M_{local} = \{ m_j \in C_{routed} \mid s_{new,j} = \cos(\mathbf{m}_{new}, \mathbf{m}_j) \geq \theta \}
$$

该公式定义簇内局部邻居集合，仅保留与 $m_{new}$ 余弦相似度高于阈值 $\theta$ 的记忆，确保演化操作局限于语义一致的邻域。

## 实验评估

实验在LoCoMo、HotpotQA与BioASQ三个基准上评估，骨干模型为Qwen3-0.6B、Llama-3.2-1B-Instruct与DeepSeek-R1-Distill-Qwen-1.5B。基线覆盖RAG、A-mem、GAM与MemoryOS，但缺失Mem0、SwiftMem等2025-2026年前沿方法，且未包含大模型骨干（如GPT-4）的对比，限制了通用性评估。

| 方法 | LoCoMo F1 (Qwen3-0.6B) | HotpotQA F1 (Qwen3-0.6B) | BioASQ F1 (Qwen3-0.6B) |
|---|---|---|---|
| RAG | 12.9 | 11.75 | 2.4 |
| A-mem | 14.29 | 12.04 | 3.61 |
| GAM | 16.05 | 7.81 | 3.40 |
| MemoryOS | 4.30 | 9.02 | 3.12 |
| CLAG | 20.99 | 15.50 | 20.99 |

CLAG在Qwen3-0.6B骨干下于所有基准取得最高F1，其中BioASQ提升幅度最大（20.99 vs. 3.61），验证了代理聚类在专业领域噪声抑制中的有效性。消融实验显示，非代理聚类（K-Means）在BioASQ上F1为15.64，低于CLAG的22.01，表明几何相似度不足以捕捉专业术语的语义一致性，代理路由的语义理解是关键增益来源。

评估边界方面，论文未报告置信区间，且BioASQ为HotpotQA风格改编，可能引入格式偏差。代码已开源，但超参数（如簇大小阈值 $\tau_{split}$）的敏感性分析缺失，可复现性依赖附录细节。

## 关联研究分析

从问题动机看，CLAG与HippoRAG均针对全局检索的语义干扰，但HippoRAG依赖知识图谱的显式实体关系，构建成本高且需重型LLM提取；CLAG采用轻量级代理聚类，无需预定义实体类型，更适合SLM场景。差异根源在于任务特性：HippoRAG面向多跳推理，需结构化关系；CLAG面向长程对话，需主题一致性。CLAG未探索图谱与聚类的混合结构，可能在复杂关系推理中受限。

从方法设计看，CLAG与SwiftMem同属检索优化，但SwiftMem侧重索引结构（O(log N)时间复杂度），CLAG侧重语义组织（代理聚类）。SwiftMem的查询感知索引可视为CLAG两阶段检索的底层实现，二者可互补：CLAG提供语义过滤，SwiftMem提供高效检索。论文未测试CLAG与SwiftMem的组合效果，查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

CLAG解决的核心矛盾是SLM在全局记忆池中的干扰脆弱性，其切入点在于将聚类作为代理控制的在线操作，通过轻量级语义邻域隔离跨主题噪声。方法上，CLAG引入代理路由、局部演化与两阶段检索，在Qwen3-0.6B骨干下于BioASQ取得20.99 F1，较A-mem提升17.38点。边界在于：大模型骨干（Qwen3-8B）下增益边际递减，且未覆盖隐私合规、多模态对齐等生产级约束。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
