# ACL-Findings2026最新论文 ｜SrDetection: A Self-Referential Framework for Data Leakage Detection in Code Large Language Models ｜自参照代码泄漏检测

作者：Shuaimin Li、Liyang Fan、Zeyang li 等 12 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_6686f600bfa8)

> 代码大语言模型（Code LLMs）在公开基准上的高分常源于预训练阶段对测试集的隐性记忆，而非真实泛化能力。现有检测手段或依赖不可得的私有训练语料，或依赖在代码复用场景下失效的时间戳启发式，且普遍需要外部参考集校准阈值。本文提出 SrDetection，通过生成语义等价变体并与原样本进行内部对比，实现无需外部锚点的自参照泄漏检测。该方法在受控测试床上显著优于基线，但其对变体生成质量的依赖及在真实复杂预训练分布下的鲁棒性仍存疑。

## 研究背景

当评估器试图区分模型是“记住了”还是“推理出”代码答案时，核心障碍在于缺乏一个干净的参照系。传统成员推断攻击（Membership Inference Attacks, MIAs）通常依赖外部参考集来校准决策阈值，但在代码领域，由于代码片段广泛复用、继承和 Fork，基于时间戳的数据划分假设往往不成立，导致外部参考集本身可能已受污染或分布偏移。这种分布偏移使得基于自然语言校准的阈值在代码结构上失效，迫使研究者寻找不依赖外部锚点的检测机制。

代码泄漏检测的核心矛盾在于：模型对训练数据的记忆表现为对特定表面形式的低困惑度，但语义等价的变体应具有相似的语义难度。主流的概率统计路线（如 Min-K% Prob）虽然避免了语料访问，但仍需外部参考集确定“低”的绝对阈值，这在代码这种高结构冗余的领域中缺乏泛化性。本文的切入点在于将检测问题转化为相对比较：如果模型记忆了原样本，它对该特定表面形式的预测置信度应显著高于其语义等价变体。通过自生成变体集内部对比，SrDetection 消除了对外部阈值校准的依赖，直接利用样本自身的语义一致性作为检测基准。

## 核心方法

### 方法参照系

标准泄漏检测流程通常包含特征提取与阈值判定两步，其中阈值判定依赖外部参考集分布。本文的关键差异在于摒弃了外部参考集，将阈值判定转化为样本内部原样本与变体集的相对排序比较，从而实现了阈值无关（threshold-free）的检测。

### 语义保持代码变换

设计动机在于解决传统 n-gram 匹配无法识别语义改写污染的问题，同时避免引入改变程序语义的重大结构变化。本文通过三个局部化操作生成变体集 $V = \{x_1, \dots, x_n\}$：函数重命名 $\tau_f$、变量重命名 $\tau_v$ 和测试用例变换 $\tau_t$。变换后的变体 $x_i$ 满足语义等价约束：

$$ S(x_0) = S(x_i) = (\tau_t \circ \tau_v \circ \tau_f)(x_0) $$

其中 $S(\cdot)$ 表示程序执行行为。这种最小化局部编辑确保了变体与原样本在词汇和结构上保持高相似度，使得模型行为的差异更可能归因于对原表面形式的记忆，而非语义漂移。

### 自参照泄漏决策

设计动机在于消除外部阈值校准的脆弱性，利用自生成集的内部统计特性进行判定。在灰盒设置下，检测分数定义为困惑度 $S_M(x) = \text{PPL}(x)$，判定规则为原样本困惑度是否小于所有变体困惑度的最小值：

$$ \text{Leakage}_{gray}(x_0) = \mathbb{I} \left[ S_M(x_0) < \min_{x_i \in V} S_M(x_i) \right] $$

在黑盒设置下，检测分数定义为生成后缀与真实后缀的 n-gram 重叠率（NGO），判定规则为原样本 NGO 是否大于所有变体 NGO 的最大值。这种相对排序机制使得检测不再依赖绝对概率值，而是依赖模型对“原形”与“变体”的相对偏好差异，从而在缺乏外部参考分布的情况下实现鲁棒判定。

## 实验评估

实验在通过继续预训练构造的受控泄漏测试床上进行，基线覆盖了灰盒（PPL, Min-K% Prob, Zlib 等）和黑盒（VeilProbe, DPDLLM）两类主流方法。由于论文未提供完整的逐字数值表格，仅能依据正文描述进行定性评估：SrDetection 在灰盒设置下平均 F1 提升 21.52 点，黑盒设置下提升 14.46 点。在 Qwen2.5-7B 上，黑盒 F1 从 1 epoch 的 53.09 提升至 5 epochs 的 82.06，显示出随记忆强度增加检测性能的提升趋势。

设计决策验证显示，自参照机制对训练阶段的鲁棒性优于传统阈值法。Min-K%++ 和 Lowercase 等基线在特定 epoch 出现性能波动，而 SrDetection 保持稳定，这归因于其内部参考机制避免了外部阈值随模型状态变化而失效的问题。测试用例变换 $\tau_t$ 的执行验证机制确保了变体的语义保真度，防止了因测试用例错误导致的假阳性。

评估边界方面，实验仅在 7B/8B 规模的开源模型上验证，未涉及 RL 后训练模型，而领域共识指出 RL 优化可能改变污染信号分布。此外，测试床通过继续预训练模拟泄漏，其记忆强度可能高于真实预训练中的复杂记忆模式。代码已开源，但变体生成的 LLM 辅助步骤引入了额外的计算开销和潜在的语义偏差风险，论文未报告变体生成失败率对最终检测性能的影响。

## 关联研究分析

从方法设计看，SrDetection 与 Min-K% Prob 的核心差异在于阈值来源。Min-K% Prob 依赖外部参考集确定“低概率”的绝对阈值，这在代码复用导致的数据分布偏移下易失效；SrDetection 通过自生成变体集内部对比，将阈值转化为相对排序，解决了外部参考集缺失或污染的问题。这一改进源于代码领域时间戳启发式失效的特性，使得基于时间划分的外部参考集不可靠。

从问题动机看，SrDetection 与 CDD（Contamination Detection via Distribution）均属于黑盒/灰盒行为统计检测，但 CDD 依赖多次采样输出分布的峰值度，而 SrDetection 依赖语义变体对比。CDD 假设污染导致分布坍缩，但在小模型或 RL 模型上可能接近随机猜测；SrDetection 的自参照机制不依赖分布坍缩假设，而是依赖模型对表面形式的记忆偏好。然而，SrDetection 对变体生成质量的依赖可能成为新的瓶颈，若变体未能完全保持语义等价，检测信号将被噪声淹没。

## 总结

本文旨在解决代码 LLM 泄漏检测中外部参考集缺失与时间戳启发式失效的矛盾。通过自生成语义等价变体并进行内部相对对比，SrDetection 实现了阈值无关的检测，在受控测试床上灰盒 F1 提升 21.52 点、黑盒提升 14.46 点。其边界在于仅在 7B/8B 模型上验证，未涵盖 RL 后训练场景，且依赖 LLM 辅助的变体生成质量。当预训练语料中的代码记忆模式更加复杂且非局部化时，基于局部表面编辑的自参照机制是否仍能捕捉到深层语义记忆，论文未给出回答。
