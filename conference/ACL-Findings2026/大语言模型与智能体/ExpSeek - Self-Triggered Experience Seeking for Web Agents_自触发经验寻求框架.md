# ACL-Findings2026最新论文 ｜ExpSeek: Self-Triggered Experience Seeking for Web Agents ｜自触发经验寻求框架

研究机构：中国科学院、中国科学院大学

作者：Wenyuan Zhang、Xinghua Zhang、Haiyang Yu 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.08605)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.08605)

> 开放网络中的搜索智能体常因证据稀疏与噪声干扰而在多轮交互中迷失，现有经验注入方法将历史教训作为全局上下文一次性喂给模型，无法适应交互过程中动态变化的认知状态。本文切入点在于利用模型自身的输出熵作为内在置信度信号，在智能体真正“困惑”时才主动检索并生成针对性经验指导。ExpSeek 通过基于 Bootstrap 重采样的熵阈值估计确定介入时机，并由独立经验模型生成步级指导，实现了从被动全局注入到主动步级寻求的范式转换。该框架在四个搜索基准上验证了有效性，但其依赖离线构建的经验库与特定骨干模型，在跨域泛化与实时性上存在边界。

## 研究背景

Web 搜索智能体需在开放网络中通过多轮检索与访问获取证据以回答复杂查询，这一过程受限于环境的噪声与部分可观测性。智能体在交互中常出现探索低效或过早响应，导致答案不可靠。解决此问题的关键在于利用历史交互轨迹中积累的经验，但经验的有效利用依赖于对智能体当前认知状态的精准把握。

现有经验干预方法主要分为离线精炼与在线自进化两类，但均将经验作为全局上下文在任务执行前被动注入。这种静态注入方式无法适应智能体与环境交互时持续变化的上下文观察，导致经验指导与当前步骤决策脱节。当智能体在交互中陷入困惑时，初始注入的全局经验往往无法提供针对性的纠正，甚至可能因信息过载而干扰推理。

本文针对这一时机错配问题，提出自触发经验寻求框架。其核心假设是模型自身的输出熵能反映其内在置信度，高熵步骤表明智能体处于不确定状态，此时介入经验指导能最大化收益。通过动态判断“何时寻求”与“寻求什么”，ExpSeek 将经验利用从静态背景信息转化为动态交互信号，解决了被动注入在噪声环境下的适应性不足问题。

## 核心方法

### 经验干预参照系

经验干预通常包含构建与利用两阶段：从训练轨迹中提取经验库，并在推理时检索相关经验作为额外输入。传统方法将经验拼接在查询前，形成静态上下文。本文的关键差异在于将经验利用从任务级全局注入下沉至步级动态寻求，使经验指导能响应智能体在交互过程中的实时状态变化。

### 基于熵的自触发机制

传统方法缺乏对介入时机的精细控制，往往在每步或固定频率介入，导致效率与效果失衡。本文利用步熵作为自触发信号，通过 Logistic 回归与 Bootstrap 重采样估计阈值区间，仅在模型置信度低时介入。步熵定义为响应中所有 token 熵的均值：

$$ \bar{H}_t = \frac{1}{|R_t|} \sum_{i=1}^{|R_t|} H(x_i) $$

该公式量化了智能体在第 $t$ 步的内在不确定性。基于训练集正确/错误步骤的熵分布，拟合 Logistic 回归模型 $P(y_t=0|\bar{H}_t) = \sigma(w\bar{H}_t + b)$，其中 $y_t=0$ 表示错误步骤。通过 Bootstrap 重采样 $N$ 次，计算阈值区间 $[\theta_{lower}, \theta_{upper}]$，当 $\bar{H}_t$ 落入该区间时以概率 $p_{intervene}$ 触发介入。这一设计解决了全局注入无法区分“高置信正确步骤”与“低置信错误步骤”的问题，避免了无效介入带来的计算开销与推理干扰。

### 步级经验指导生成

确定介入时机后，需生成与当前步骤匹配的具体指导。传统方法直接检索相似经验，但静态文本无法适应动态上下文。本文设计经验模型 $M_e$，读取当前步历史上下文 $h_t$，从经验库中选取最相关的三个主题，并基于经验三元组（行为-错误-指导）生成定制化指导 $e_t$。对于过程步骤，$e_t$ 附加到环境观察 $O_t$；对于答案步骤，$e_t$ 作为 $O_T$ 注入，允许智能体在 $T+1$ 步继续推理或修正答案。为防止过度干预，若第 $t$ 步发生介入，则第 $t+1$ 步禁用介入。该机制将经验从静态文本转化为动态生成的上下文，解决了检索式指导无法融合当前推理状态的问题。

## 实验评估

实验在 GAIA、WebWalkerQA、xbenchDeepSearch 和 SEALHARD 四个基准上进行，使用 Qwen3-8B 和 32B 作为骨干智能体，Qwen3-235B-A22B-Instruct-2507 作为经验模型。基线包括 Training-Free GRPO 和 ReasoningBank+，均为全局经验注入方法。缺失与本文同属步级干预但不同触发机制的强基线对比，如基于奖励模型的步级评估方法。

| 方法 | Qwen3-8B Avg. | Qwen3-32B Avg. |
| :--- | :--- | :--- |
| No Experience | 32.23 | 37.79 |
| Training-Free GRPO | 33.79 | 38.12 |
| ReasoningBank+ | 34.80 | 40.81 |
| ExpSeek (Ours) | 41.50 | 45.32 |

ExpSeek 在 8B 和 32B 模型上分别取得 41.50% 和 45.32% 的平均准确率，较无经验基线提升 9.3% 和 7.5%。相比全局注入基线，ExpSeek 在 8B 上领先 6.7%，在 32B 上领先 4.5%，验证了步级自触发优于全局静态注入。

消融实验显示，仅引导过程步骤或仅引导答案步骤均导致性能下降。在 8B 模型上，仅过程步骤引导比完整方法低 4.91%，仅答案步骤低 2.44%；在 32B 模型上，分别低 4.51% 和 4.12%。这表明过程与答案步骤的协同引导是必要的，且答案步骤的熵分布分离度更高（AUC=0.7187 vs 0.6223），使其成为更可靠的触发信号。效率分析表明，基于熵的触发在 GAIA 上比规则触发减少 1.7 倍步骤和 2.6 倍时间开销，实现了性能与效率的平衡。

评估采用 LLM-as-a-Judge 方法，报告五次独立运行的平均准确率。该协议在搜索任务上可能引入评估偏差，且未报告置信区间。代码已开源，但经验库构建依赖特定训练集（WebWalkerQA 25% 样本），跨域泛化能力未充分验证。

## 关联研究分析

从问题动机看，ExpSeek 与 WebCoach 同属记忆增强路线，但 WebCoach 侧重跨会话持久化记忆，解决长程任务中的信息丢失问题；而 ExpSeek 聚焦单任务内的步级动态引导，解决交互过程中的认知状态错配问题。这一差异源于任务特性：Web 搜索任务强调单任务内的多轮推理连贯性，而 Web 交互任务更依赖跨任务的经验积累。ExpSeek 未探索跨会话记忆与步级触发的结合，其经验库在任务结束后是否保留及如何更新，论文未给出回答。

从方法设计看，ExpSeek 与 ReasoningBank 同属经验检索框架，但 ReasoningBank 将经验作为系统提示的一部分全局注入，而 ExpSeek 通过熵阈值动态控制介入时机。这一差异揭示了全局注入在噪声环境下的局限性：当智能体在高置信步骤时，全局经验可能引入无关信息，干扰推理。ExpSeek 的熵触发机制本质上是一种置信度校准，但其阈值估计依赖离线训练集，若测试集分布发生偏移，阈值可能失效。论文未探讨阈值在线自适应更新的机制，这在动态变化的真实网络环境中可能是关键瓶颈。

## 总结

本文要解决的核心矛盾是经验注入的静态性与智能体交互状态的动态性之间的错配。现有方法将经验作为全局上下文一次性注入，无法响应智能体在交互中实时变化的置信度状态，导致经验指导与当前步骤决策脱节。ExpSeek 抓住模型输出熵作为内在置信度信号这一切入点，通过 Bootstrap 重采样估计阈值区间，仅在智能体真正困惑时主动寻求经验指导。该方法在四个搜索基准上验证了有效性，Qwen3-8B 和 32B 模型分别取得 9.3% 和 7.5% 的绝对提升。本文的边界在于经验库构建依赖特定训练集，且阈值估计为离线静态过程，未探索在线自适应机制。当测试集分布发生显著偏移时，基于离线数据估计的熵阈值是否仍能准确区分正确与错误步骤，论文未给出回答。
