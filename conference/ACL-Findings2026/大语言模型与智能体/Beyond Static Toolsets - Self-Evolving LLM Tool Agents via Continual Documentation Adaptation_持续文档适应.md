# ACL-Findings2026最新论文 ｜Beyond Static Toolsets: Self-Evolving LLM Tool Agents via Continual Documentation Adaptation ｜持续文档适应

研究机构：英国伦敦大学学院

作者：Bin Wu、Edgar Meij、Emine Yilmaz

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_f2667bbb2c89)

> 导读 工具使用大语言模型（LLM）在部署中面临工具集动态增删导致的性能波动，现有静态文档优化方法无法应对这种环境漂移。本文提出 ContDa，通过关系引导探索与关系感知调整，在不更新模型权重的前提下持续重构工具文档。该方法在 StableToolBench 动态扩展实验中，将平均性能从基线的 8.67% 提升至 11.20%，同时控制了旧任务遗忘。其价值在于验证了文档作为轻量级进化载体的可行性，但缺乏与参数化方法的横向对比，且未量化文档更新对模型内部表征的潜在干扰。

## 研究背景

当企业基础设施更新导致 API 接口变更时，代理必须区分“保留旧能力”与“发现新能力”的边界。这一矛盾被称为稳定性-适应性困境（Stability-Adaptation Dilemma），其根源在于工具文档的静态假设：传统方法如 DRAFT 和 EasyTool 假设工具集在训练或提示优化阶段固定，当新工具引入功能重叠或旧工具移除时，代理陷入选择混淆或能力缺失。

主流路线通过监督微调或强化学习优化模型权重以适配工具调用，但这些方法隐含静态工具宇宙假设，且重训练成本高、易引发灾难性遗忘。非参数化反思路线（如 Reflexion）虽灵活，但多聚焦于任务轨迹记忆，未针对工具文档结构进行系统性重构。本文切入点在于将进化对象从模型权重或任务记忆转向工具文档本身，利用工具间的功能关系作为锚点，实现无重训练下的持续适应。

## 核心方法

### 方法参照系

本文问题属于非参数化 Harness 进化范畴，但区别于静态工具集下的文档优化。关键差异在于：标准流程假设工具集固定，而本文处理工具集随时间 $t$ 动态变化 $\{T_0, T_1, \dots, T_T\}$，且无版本元数据，要求文档适应必须在线、增量且保持关系一致性。

### 关系引导探索

针对新工具 $t_i$ 文档不完整导致的探索盲区，本文引入关系锚点机制。设计动机是解决仅依赖新工具自身文档生成探测查询时，因描述过时或遗漏而陷入局部假设空间的问题。算法首先计算新工具与旧工具集 $T_{t-1}$ 的相似度，筛选出相似度 $s(t_i, t_j) \ge \tau$ 的工具作为候选集 $N_i$，再从中采样 $k$ 个工具构成关系集 $R_i$：

$$
R_i = \text{Sample}_k(\{t_j \in T_{t-1} \setminus \{t_i\} \mid s(t_i, t_j) \ge \tau\})
$$

该公式确保 $R_i$ 包含功能相关但非冗余的工具，为后续探测提供对比基准。基于 $R_i$ 的文档，代理生成三类探测查询：验证 $t_i$ 声明能力、测试 $R_i$ 暗示的替代能力、探索两者之外的潜在能力。执行查询后，根据响应迭代更新 $t_i$ 的文档 $d_{i,t}$，直至收敛。此过程将探索从“盲目试错”转向“关系引导的假设验证”，显著提升了新工具能力发现的准确性。

### 关系感知调整

针对功能重叠工具导致的代理选择混淆，本文引入聚类与关系标注机制。设计动机是解决单独优化单个工具文档无法消除组内歧义的问题。算法将功能相似的工具聚类为 $C_t = \{C_1, C_2, \dots\}$，对每个簇内的工具对 $(t_i, t_j)$，代理生成关系注释，明确回退选项（Fallback）与功能互补性（Overlap/Complementarity）。例如，若 $t_i$ 失败，文档中显式标注“使用 $t_j$ 作为替代”。这些注释被追加至工具文档 $d_{i,t}$，形成更新后的文档集 $D_t^*$。该机制将隐性的工具竞争关系显性化为文档结构，使代理在检索与选择阶段能依据文档中的关系提示做出更鲁棒的决策，从而在保留旧任务能力的同时降低新工具引入带来的干扰。

## 实验评估

实验基于 StableToolBench 的 I2-I 子集（330 任务）与 RestBench（117 任务），模拟三种工具进化模式：仅扩展、仅缩减、混合。基线包括 Original（无优化）、EasyTool 和 DRAFT，均为静态文档优化方法，未包含参数化方法（如 EvolveR）或多智能体协同方法（如 CoMAS），这限制了与主流自进化路线的直接对比。

| 进化模式 | 方法 | 平均性能 (%) | 遗忘 (%) | 发现 (%) |
| :--- | :--- | :--- | :--- | :--- |
| 混合进化 | Original | 8.67±0.45 | 3.69±0.13 | 5.36±0.18 |
| 混合进化 | DRAFT | 9.49±0.72 | 3.59±0.42 | 5.58±0.36 |
| 混合进化 | ContDa | 11.20±0.94 | 5.19±0.43 | 7.38±0.55 |
| 仅扩展 | ContDa | 10.48±0.85 | 4.17±0.36 | 5.78±0.46 |
| 仅缩减 | ContDa | 11.65±0.47 | 4.68±0.25 | 7.18±0.44 |

在混合进化模式下，ContDa 的平均性能 11.20% 显著高于 DRAFT 的 9.49% 和 Original 的 8.67%（p < 0.01）。消融实验显示，移除关系引导探索（w/o Disc.）导致平均性能下降，尽管遗忘率未显著增加，表明性能损失主要源于新能力发现不足。移除关系感知调整则导致选择混淆增加，验证了聚类标注对稳定性的贡献。

评估边界方面，论文未报告计算效率指标（如 API 调用次数或延迟），且未提供置信区间以外的统计检验细节。代码已开源，但超参数 $\tau$ 和 $k$ 的敏感性分析显示，$\tau$ 过低或过高均导致性能下降，表明关系筛选阈值需精细调优。此外，实验仅基于 gpt-4o-mini，未验证在不同骨干模型上的泛化性。

## 关联研究分析

从问题动机看，ContDa 与 A-Evolve 均聚焦于 Harness 进化，但 A-Evolve 强调通用理论框架下的参数化与持久化状态区分，而 ContDa 将进化限制在工具文档这一特定外部组件。差异根源在于任务特性：A-Evolve 面向广泛推理与软件工程任务，需处理权重更新；ContDa 针对工具调用场景，利用文档的文本可编辑性实现轻量级适应。这种选择牺牲了参数化内化的深度，但换取了部署灵活性与无重训练优势，符合非参数化路线在闭源模型场景下的共识。

从方法设计看，ContDa 与 DRAFT 同属文档优化，但 DRAFT 假设工具独立且静态，而 ContDa 引入关系引导探索与聚类调整。DRAFT 在工具重叠时易产生选择混淆，因其未显式建模工具间功能关系；ContDa 通过关系标注将隐式竞争显性化，解决了这一盲区。然而，ContDa 未探索文档更新对模型内部表征的潜在干扰，例如文档中回退选项的频繁变更是否会导致代理形成错误的工具调用习惯，这一影响在静态文档优化中不存在，但在持续适应中可能累积。

## 总结

ContDa 针对工具集动态变化下的稳定性-适应性困境，提出通过关系引导探索与关系感知调整持续重构工具文档，避免模型重训练。在 StableToolBench 混合进化实验中，其平均性能达 11.20%，较基线 DRAFT 提升 1.71 个百分点，同时保持遗忘率在 5.19% 的可控范围。该方法的边界在于仅验证了单一骨干模型（gpt-4o-mini）上的效果，且未量化文档更新频率对代理长期行为稳定性的影响。当工具进化频率从每步一次增加到每步多次时，文档重构的计算开销与代理适应速度之间的平衡点是否会发生偏移，论文未给出回答。
