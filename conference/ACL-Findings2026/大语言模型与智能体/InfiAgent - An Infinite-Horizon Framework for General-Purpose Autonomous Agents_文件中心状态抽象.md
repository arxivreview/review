# ACL-Findings2026最新论文 ｜InfiAgent: An Infinite-Horizon Framework for General-Purpose Autonomous Agents ｜文件中心状态抽象

研究机构：香港理工大学

作者：Chenglin Yu、Yuchen Wang、Songmiao Wang 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.03204)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.03204)

> 长时域智能体（Long-Horizon Agent）面临的核心困境是上下文窗口的无限增长导致推理稳定性崩塌。现有方案依赖截断或摘要，但无法解决状态与推理上下文的纠缠问题。InfiAgent 提出将持久状态外化为文件系统，通过有界上下文重建实现无限时域执行。该框架在 20B 模型上实现了与大型专有模型相当的 DeepResearch 性能，但其串行执行架构带来的延迟开销限制了实时场景的适用性。

## 研究背景

当智能体执行多步研究任务时，对话历史、工具轨迹与中间计划不断累积，导致提示词长度呈线性增长。这种增长迫使系统采用截断或摘要机制以适配有限窗口，但由此引发的信息丢失与干扰项累积，构成了长时域执行中的“状态幻觉”（Illusion of State）：模型看似拥有完整记忆，实则因上下文稀释而丧失对关键状态的感知能力。

长上下文大语言模型（Long-Context LLM）研究长期聚焦于扩展窗口长度与优化注意力机制，如 RoPE 变体与稀疏注意力，旨在提升有效上下文长度。然而，这些架构级改进仍受限于预训练分布与计算复杂度，且未能解决智能体特有的状态管理问题。检索增强生成（RAG）虽引入外部记忆，但检索文本仍被注入推理上下文，导致长期任务状态与短期推理信号纠缠，认知负载随执行步数增加而线性上升。InfiAgent 的切入点在于彻底解耦持久任务状态与有界推理上下文，将文件系统作为权威记录，从而消除上下文无限增长的根本原因。

## 核心方法

### 状态解耦形式化

InfiAgent 将智能体执行建模为状态条件决策过程，核心差异在于将传统提示词中心的状态表示替换为文件中心的状态抽象。在常规框架中，状态 $c_t$ 由累积观察 $o_t$ 构成，随时间 $t$ 无限增长。InfiAgent 引入持久状态 $S_t$，其核心组件为工作区文件集合 $F_t$，该集合不受上下文窗口约束，可随任务复杂度自由扩展。

### 有界上下文重建机制

设计动机在于消除长时域下因上下文膨胀导致的注意力稀释与早期错误累积。InfiAgent 在每步 $t$ 通过确定性函数 $g(\cdot)$ 从持久状态中重建有界推理上下文 $c_t^{bounded}$：

$$ c_t^{bounded} = g(F_t, a_{t-k}:t-1) $$

其中 $a_{t-k}:t-1$ 为最近 $k$ 个动作的固定窗口（如 $k=10$）。该公式确保 $|c_t^{bounded}| = O(1)$，即上下文大小与任务时域无关。与摘要方法不同，此机制不丢弃持久状态中的任何信息，而是通过动态状态检查在每步确定相关性，从而在保持推理连贯性的同时，将长期记忆负担转移至文件系统。

### 层级化执行与外部注意力

为解决扁平多智能体系统中的“工具调用混乱”与错误传播，InfiAgent 采用树状层级架构：Level 3（Alpha Agent）负责高层规划，Level 2（Domain Agents）执行特定工作流，Level 1（Atomic Agents）处理原子工具调用。高层智能体将低层智能体视为可调用工具（Agent-as-a-Tool），强制串行执行以维持状态一致性。此外，外部注意力管道（External Attention Pipeline）将重型文档处理（如阅读 80 篇论文）卸载至隔离的临时 LLM 进程，仅将提取的答案注入主智能体状态，避免上下文膨胀。

## 实验评估

实验在 DeepResearch 基准与自定义 80 篇文献综述任务上进行，基线包括 Claude Code、Cursor 等商业智能体，但缺失 RLM、HiCI 等架构级长上下文基线。DeepResearch 得分 41.45（20B 模型），在效率-性能前沿上优于依赖更大模型的专有系统。文献综述任务中，InfiAgent 使用 Gemini-3-Flash 与 Claude-4.5-Sonnet 均实现 80.0 的平均覆盖率，而 Cursor 使用相同模型仅得 0.1，Claude Code 得 29.1，表明文件中心状态对长时域稳定性的关键作用。

| 设置 | 模型 | Max | Min | Avg |
|---|---|---|---|---|
| InfiAgent | Gemini-3-Flash | 80 | 80 | 80.0 |
| InfiAgent | Claude-4.5-Sonnet | 80 | 80 | 80.0 |
| Claude Code | Claude-4.5-Sonnet | 80 | 11 | 29.1 |
| Cursor | Claude-4.5-Sonnet | 5 | 0 | 1.0 |
| No File State | Gemini-3-Flash | 25 | 20 | 21.1 |
| No File State | Claude-4.5-Sonnet | 77 | 11 | 27.7 |

消融实验显示，移除文件中心状态并改用压缩长上下文提示后，覆盖率显著下降且方差增大。例如，Claude-4.5-Sonnet 从 80.0 降至 27.7，Gemini-3-Flash 从 80.0 降至 21.1。这表明长上下文压缩无法替代显式状态外化，二者在长时域执行中扮演定性不同的角色。

评估边界存在局限：DeepResearch 缺乏与 SOTA 模型的直接数值对比；文献综述任务为自定义，未覆盖实时交互或具身场景；串行执行导致延迟开销，论文未报告具体延迟数据。代码已开源，但超参数与 GPU 配置未在正文中详细披露，可复现性依赖仓库文档。

## 关联研究分析

从问题动机看，InfiAgent 与 MemGPT 同属记忆机制路线，但 MemGPT 依赖虚拟内存分页与摘要压缩，而 InfiAgent 采用文件系统作为权威记录，实现“零上下文压缩”。这一差异源于任务特性：MemGPT 侧重对话历史管理，InfiAgent 侧重多步研究任务中的工件持久化。InfiAgent 的串行执行策略虽确保状态一致性，但牺牲了并行效率，这与 MAKER 的极端分解思想形成对比——MAKER 依赖预定义子任务边界，InfiAgent 则通过层级化 DAG 支持开放域任务，但延迟开销是否限制了其在实时场景的适用性，论文未给出回答。

从方法设计看，InfiAgent 的外部注意力管道与 RAG 存在本质区别：RAG 将检索文本注入上下文，InfiAgent 仅在工具层处理文档并返回答案，避免无关 Token 干扰。这一设计直接对抗知识库中提到的“干扰项非线性影响”，但论文未量化干扰项密度与性能下降的关系。与 RLM 相比，InfiAgent 不依赖代码递归，而是通过层级化智能体实现任务分解，避免了自由形式代码生成的失败模式，但引入了额外的智能体协调开销。

## 总结

InfiAgent 解决的核心矛盾是长时域智能体中持久状态与有界推理上下文的纠缠。其切入点在于将文件系统作为权威记录，通过有界上下文重建消除上下文无限增长，从而在 20B 模型上实现与大型专有模型相当的 DeepResearch 性能（41.45 分）与 80.0 的文献综述覆盖率。然而，串行执行架构带来的延迟开销与幻觉累积风险，限制了其在实时交互与高风险场景的适用性。当任务时域进一步延长至数千步时，文件系统中的错误工件是否会被层级化验证机制有效拦截，论文未提供足够证据。
