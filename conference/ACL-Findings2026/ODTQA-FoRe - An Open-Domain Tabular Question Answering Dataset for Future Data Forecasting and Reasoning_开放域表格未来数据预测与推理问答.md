# ACL-Findings2026最新论文 ｜ODTQA-FoRe: An Open-Domain Tabular Question Answering Dataset for Future Data Forecasting and Reasoning ｜开放域表格未来数据预测与推理问答

作者：Zhensheng Wang、Xiaole Liu、Wenmian Yang 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.02433)

> 开放域表格问答长期局限于静态历史数据的检索与提取，无法响应用户对“未来趋势”的预测性询问。现有大语言模型缺乏时序建模机制，且开放域场景下用户无法提供连续历史数据，导致预测任务在数据获取与数值生成两端均存在断点。本文提出 ODTQA-FoRe 任务与 TimeFore 框架，通过 SQL 自主检索历史数据、调用外部时序模型生成预测值、再由 LLM 进行标准化推理，填补了表格问答中动态预测的空白。该工作确立了垂直领域预测问答的基准，但受限于单一房地产数据源，其跨域泛化能力与 LLM 内生预测能力的边界尚待厘清。

## 研究背景

开放域表格问答（Open-Domain Tabular Question Answering, ODTQA）要求系统从大规模候选表中定位目标数据并执行推理。传统范式依赖检索增强生成（Retrieval-Augmented Generation, RAG）将自然语言查询映射为 SQL 或代码，以解决静态数据库中的事实核查与数值计算问题。然而，当查询涉及未来时间戳（如“下个月均价”）时，静态数据库中不存在对应记录，RAG 的检索机制失效。此时，问题转化为时序预测（Time Series Forecasting, TSF）：系统需先获取历史序列，再外推未来值。大语言模型（Large Language Models, LLMs）虽具备强大的语义理解能力，但其训练数据主要为静态文本，缺乏对动态时序分布的建模机制，直接通过上下文学习（In-Context Learning, ICL）进行数值预测时误差显著高于专用时序模型。

表格问答领域的主流路线分为结构表示重构与推理机制增强两类。前者如 TABGR 和 TAMO 通过图或超图结构保留二维拓扑，解决复杂表格的解析问题；后者如 TableMind 和 MATA 通过智能体框架与代码执行提升多步推理的可靠性。这些方法均假设数据是已知且静态的，未涉及数据缺失情况下的生成性预测。现有开放域基准如 NQ-TABLES 和 RETQA 仅覆盖历史查询，缺乏对预测类问题的评估。本文的切入点在于识别出“预测”这一被静态问答范式忽略的子任务，指出 LLM 在数值预测上的固有缺陷，并主张通过外部专用模型弥补这一短板，从而将 ODTQA 从“信息提取”扩展至“信息生成”。

## 核心方法

### 智能体协作架构

TimeFore 属于智能体推理框架路线，其标准流程为规划-执行-反思。与 TableMind 等侧重代码纠错的智能体不同，TimeFore 的关键差异在于将“预测”这一非确定性环节解耦，交由外部时序模型处理，LLM 仅负责编排与语义对齐。该框架由 Retriever、Forecaster 和 Analyzer 三个角色组成，分别解决数据获取、数值预测和答案标准化问题。

### 基于 SQL 反馈循环的数据检索

Retriever 负责从 288 张候选表中定位目标表并提取历史数据。通常做法是直接使用 BM25 或向量检索匹配表名，但开放域查询的语义多样性导致匹配率低。TimeFore 采用两阶段策略：首先利用 LLM 将用户查询摘要为规范化的表标题（Caption），尝试直接匹配；若失败，则回退至 BM25 检索。确定目标表后，LLM 通过少样本提示生成 SQL 查询。为确保 SQL 的正确性，系统引入执行反馈循环：

$$
SQL_{final} = \text{Refine}(SQL_{prev}, \text{ErrorFeedback}(SQL_{prev}))
$$

该公式表示，若 SQL 执行报错，LLM 根据错误信息迭代修正查询，直至成功或达到最大迭代次数（25 次）。这一机制解决了 LLM 生成 SQL 时常见的语法错误与逻辑漏洞，确保历史数据获取的确定性。

### 外部时序模型调用的预测模块

Forecaster 处理 LLM 无法胜任的数值预测任务。直接让 LLM 预测价格序列时，其 MSE 高达 $6.69 \times 10^7$（Qwen3 30B），远高于专用模型。TimeFore 利用 LLM 的函数调用能力，封装 `imputationThenPredictionTool`，内部串联 TimesNet（用于数据填补）和 TimeXer（用于预测）。

$$
\hat{Y}_{future} = \text{TimeXer}(\text{TimesNet}(Y_{hist}))
$$

其中 $Y_{hist}$ 为 Retriever 获取的 24 个月历史价格序列，$\hat{Y}_{future}$ 为预测的 12 个月价格。该设计动机在于承认 LLM 在数学计算上的局限性，通过“LLM 编排 + 专用模型计算”的分工，将预测误差从 $6.69 \times 10^7$ 降低至 $2.50 \times 10^7$（TimeXer），显著提升了下游推理的准确性。

## 实验评估

实验在自建 ODTQA-FoRe 数据集上进行，包含 28,507 个 QA 对，涵盖 8,042 个预测问题和 20,465 个基于预测的推理问题。基线包括 Vanilla（BM25 + ICL 直接预测）及五个主流 LLM（Qwen3 30B, Qwen3 Next 80B, GPT-OSS 20B, GPT-OSS 120B, GLM 4.5 Air）。由于 ODTQA-FoRe 为新基准，缺乏 TABGR、TAMO 等结构表示方法的直接对比，评估重点在于 TimeFore 相对于 Vanilla 基线的增益。

| 模型 | 方法 | 预测 MSE | 预测 MAE | 推理 F1 |
|---|---|---|---|---|
| Qwen3 30B | Vanilla | 40385720.95 | 3698.36 | 24.87 |
| Qwen3 30B | TimeFore | 31572410.36 | 2788.20 | 60.25 |
| GLM 4.5 Air | Vanilla | 139922250.13 | 3324.41 | 48.72 |
| GLM 4.5 Air | TimeFore | 90865440.59 | 2709.25 | 61.24 |

TimeFore 在所有模型上均显著优于 Vanilla。以 GLM 4.5 Air 为例，预测 MSE 从 $1.39 \times 10^8$ 降至 $9.08 \times 10^7$，推理 F1 从 48.72 提升至 61.24。消融实验表明，提供真实未来数据（GH+GF）时性能达到上限，而仅提供真实历史数据（GH+PF）时增益有限，证实预测精度是下游推理的主要瓶颈。

评估边界方面，数据集局限于中国房地产垂直领域，缺乏跨域验证；未报告计算效率指标；代码已开源，但时序模型（TimeXer）的超参数配置未在正文中详述，复现时需参考附录。

## 关联研究分析

从问题动机看，本文与 RETQA 同属开放域表格问答，但 RETQA 聚焦于历史数据的检索与事实核查，而本文引入了时间维度的外推。这一差异源于任务定义的根本不同：静态问答假设答案存在于数据库中，而预测问答假设答案需通过模型生成。本文未对比 RETQA 的检索模块，而是直接采用 SQL 生成，这暗示在预测任务中，检索的精度要求可能低于事实核查，因为错误的历史数据会导致预测偏差，但错误的表选择会导致任务失败，两者对检索错误的敏感度不同。

从方法设计看，TimeFore 与 TableMind 同属智能体框架，但 TableMind 通过代码执行和反思机制解决逻辑推理错误，而 TimeFore 通过调用外部时序模型解决数值预测错误。这一差异反映了 LLM 能力边界的划分：TableMind 认为 LLM 具备足够的逻辑推理能力，只需工具辅助执行；TimeFore 则认为 LLM 缺乏时序建模能力，必须依赖专用模型。这种“外包”策略是否削弱了 LLM 的端到端泛化性，特别是在数据分布发生漂移时，论文未给出回答。

## 总结

本文针对开放域表格问答中静态数据无法支持未来预测的矛盾，提出 ODTQA-FoRe 任务与 TimeFore 框架。其核心在于识别 LLM 在时序预测上的固有缺陷，通过 SQL 反馈循环确保历史数据获取的准确性，并调用 TimeXer 等专用模型生成预测值，再由 LLM 进行标准化推理。实验显示，TimeFore 在 GLM 4.5 Air 上实现了 61.24 的推理 F1，显著优于 Vanilla 基线的 48.72，验证了“LLM 编排 + 专用模型预测”架构的有效性。然而，该框架依赖外部时序模型，当历史数据稀疏或分布异常时，TimeXer 的预测误差可能传导至下游推理。此外，数据集局限于房地产领域，未验证框架在金融、医疗等其他垂直领域的泛化能力。当历史序列长度缩短至 6 个月以下时，TimeXer 的预测稳定性如何，论文未给出回答。
