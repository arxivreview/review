> 现有图表转代码基准局限于静态二维图与单一绘图库，无法评估模型在三维、动画及跨框架场景下的真实生成能力。PlotGen-Bench 通过构建涵盖 30 种图表类型、5 个 Python 库及 3 类任务（复制、转换、多库生成）的基准，填补了动态可视化评估空白。其核心贡献在于引入混合评估协议，结合执行率与视觉相似度评分。该基准揭示了通用视觉语言模型在复杂时序与跨库语法泛化上的显著短板，但缺乏专用图表模型的对比，限制了结论的普适性。

## 研究背景

当视觉语言模型（VLM）尝试将图表图像转化为可执行代码时，其输出必须同时满足语法正确性与视觉保真度。然而，传统评估仅关注代码是否运行（执行率），忽略了渲染结果与原始图像在布局、颜色及数据映射上的细微偏差。这种“可执行但不可信”的现象源于视觉编码器对密集布局特征的压缩损失，以及训练数据中缺乏对复杂拓扑结构的显式监督。

图表理解领域正从静态问答向动态交互与代码生成演进。主流路线如 ChartMimic 和 Plot2Code 虽确立了代码生成的评估范式，但均局限于 Matplotlib 等单一库的静态二维图，且未覆盖三维、动画等现代可视化形式。这些基准无法捕捉用户在实际科研或商业场景中常见的“图表类型转换”（如柱状图转折线图）或“跨库复现”需求。PlotGen-Bench 的切入点在于将评估维度从“单库静态复现”扩展至“多库动态生成”，通过引入 Plotly、Seaborn 等交互式库及 GIF 动画，迫使模型处理更复杂的时序一致性与语法泛化问题。

## 核心方法

### 多源异构数据构建与任务定义

PlotGen-Bench 的数据构建突破了单一来源限制，整合了 arXiv 论文、Stack Overflow 及官方教程中的 710 个精选样本。数据涵盖 9 大类、30 种具体图表类型，其中“增强类”（含 3D 和组合图）占比超过 28%，动画类占比约 5%。这种分布设计旨在测试模型对非标准布局的泛化能力。任务定义包含三个层级：Plot Replication（像素级复现）、Plot Transformation（保留数据语义的图表类型转换）以及 Multi-library Generation（跨库语法迁移）。与仅关注静态复现的基准不同，Transformation 任务要求模型理解底层数据逻辑，而非仅匹配视觉外观。

### 混合评估协议与动态一致性检查

针对代码生成评估中“执行率”与“视觉质量”脱节的问题，PlotGen-Bench 设计了双轨评估机制。首先，通过受控 Python 环境计算代码执行通过率（Pass Rate, PR），确保语法正确性。其次，引入 GPT-4o 作为自动裁判，从图表类型准确性、元素完整性、位置对齐、比例缩放、颜色风格、文本对应及整体结构七个维度计算视觉相似度得分（GPT-Score, GS）。对于动画 GIF，引入基于感知哈希（pHash）的时序一致性检查，通过计算首尾帧及中间帧的哈希距离，惩罚缺乏真实动态变化的“伪动画”。

$$
GS = \frac{1}{7} \sum_{i=1}^{7} w_i \cdot s_i
$$

其中 $s_i$ 为第 $i$ 个维度的评分（0-100），$w_i$ 为权重（论文中默认等权）。该公式将多维视觉特征聚合为单一标量，弥补了仅靠执行率无法量化视觉保真度的缺陷。

$$
D_{temporal} = \frac{1}{N} \sum_{j=1}^{N} d_{pHash}(f_j, f_{j+1})
$$

其中 $f_j$ 为第 $j$ 帧，$d_{pHash}$ 为感知哈希距离。该指标用于检测动画是否具备真实的时序动态，若距离过小则判定为伪动画并扣分。

## 实验评估

实验评估了 19 个开源与闭源 VLM，参数规模从 7B 到 235B。基线覆盖广泛，包括 GPT-5、Claude-Sonnet-4、Qwen3-VL 等，但缺失 ChartCoder、ChartVLM 等专用图表模型，这可能高估了通用模型的相对优势。

| 模型 | Matplotlib PR | Matplotlib GS | Plotly PR | Plotly GS | NetworkX PR | NetworkX GS |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-5-2025-08-07 | 93.5 | 82.7 | 88.3 | 76.9 | 86.1 | 72.1 |
| Claude-Sonnet-4 | 97.8 | 74.4 | 83.7 | 59.3 | 100.0 | 81.1 |
| Qwen3-VL-235B | 93.5 | 87.8 | 58.1 | 63.2 | 72.0 | - |
| InternVL3-78B | 71.7 | 43.1 | 81.4 | 52.0 | 86.1 | 56.5 |

数据显示，闭源模型在 Matplotlib 和 NetworkX 上表现稳健，但在 Plotnine（声明式语法）上性能骤降，例如 Claude-Sonnet-4 的 PR 从 97.8 跌至 36.8。开源模型中，Qwen3-VL-235B 在 Matplotlib 上 GS 达 87.8，优于 GPT-5 的 82.7，但在 Plotly 上 PR 仅 58.1，暴露出跨库泛化的不均衡性。

| 模型 | Distribution GS | Animation GS | Overall GS |
| :--- | :--- | :--- | :--- |
| GPT-5-2025-08-07 | 78.7 | 45.2 | 79.7 |
| Claude-Sonnet-4 | 76.7 | 44.5 | 74.1 |
| Qwen3-VL-235B | 64.7 | 38.1 | 64.6 |
| InternVL3-78B | 43.4 | 33.2 | 48.3 |

在复杂任务上，所有模型在 Animation 类别上表现最差，GPT-5 的 GS 仅为 45.2，远低于其在 Distribution 类别的 78.7。这表明当前 VLM 难以维持动画的时序逻辑与样式一致性。Plot Transformation 任务中，GPT-5 的 Consistency Score 为 90%，但 Element Accuracy 仅 63%，说明模型能生成可运行代码，但常丢失关键数据元素。

评估边界方面，GS 依赖 GPT-4o 的主观判断，可能存在裁判偏差；动画评估基于 pHash，对微小视觉变化敏感但缺乏语义理解。代码已开源，但超参数与 GPU 配置细节未完全披露，复现成本较高。

## 关联研究分析

从问题动机看，PlotGen-Bench 与 ChartMimic 的核心差异在于对“动态性”与“多库性”的强调。ChartMimic 聚焦于静态图表的精确复现，其评估指标侧重于代码与图像的静态匹配；而 PlotGen-Bench 引入 GIF 动画和 Plotly 交互式库，要求模型处理时序状态和声明式语法。这一差异源于任务特性的变化：现代可视化不仅是静态快照，更是交互过程。PlotGen-Bench 的 Transformation 任务进一步要求模型理解数据语义而非仅视觉形式，这与 ChartEdit 的局部编辑不同，前者涉及全局结构重构。

从方法设计看，PlotGen-Bench 的混合评估协议与 MMCode 的隐藏测试思路相似，但侧重点不同。MMCode 通过运行代码并比对输出结果来验证正确性，适用于逻辑推理任务；PlotGen-Bench 则通过 GPT-4o 评分视觉相似度，适用于生成任务。这种设计选择反映了图表生成对“视觉保真度”的更高要求。然而，PlotGen-Bench 未对比专用图表模型（如 ChartCoder），这可能掩盖了通用 VLM 在特定图表结构上的劣势。查询侧增强在数据充足时是否仍有增益，论文未给出回答，这限制了其在专用模型对比中的结论强度。

## 总结

PlotGen-Bench 旨在解决现有基准无法评估动态与跨库可视化代码生成的问题。通过构建涵盖 30 种图表类型、5 个库及 3 类任务的基准，并引入执行率与视觉相似度混合评估，该工作揭示了通用 VLM 在动画时序一致性与声明式语法泛化上的显著短板。实验显示，GPT-5 在 Matplotlib 上 GS 达 82.7，但在 Plotnine 上 PR 仅 36.8，且所有模型在 Animation 类别上 GS 均低于 50。其边界在于缺乏专用图表模型对比，且 GS 依赖单一裁判模型。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
