研究机构：北京航空航天大学、中国人民大学

作者：Jian Yang、Shuyue Guo、Linzheng Chai 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_3f7842f1f2e0)

> 通用自然语言缩放定律假设数据同质，无法指导多语言代码库中不同编程语言的令牌分配，导致资源浪费与性能预测偏差。现有代码缩放研究仅关注单语言或整体数据量，忽略了语言间的语法异构性与跨语言迁移效应。本文通过1000+次从头训练实验，建立比例依赖的多语言缩放模型，量化各语言独立缩放指数与协同增益。该工作填补了代码域多语言资源分配的理论空白，但其最优分配策略在极端数据受限下的鲁棒性存疑。

## 研究背景

预训练损失 $L$ 随模型参数量 $N$、数据量 $D$ 呈幂律下降，其中不可约损失 $L_{\infty}$ 代表数据噪声下限。在通用文本中，$L_{\infty}$ 被视为常数，但在代码领域，不同编程语言的语法约束与类型系统导致 $L_{\infty}$ 存在显著差异。这种差异意味着，若将多语言代码视为同质数据流，基于单一幂律拟合的缩放指数将系统性偏离各语言的实际性能极限，使得计算最优分配策略失效。

主流代码缩放研究沿袭 Chinchilla 定律，假设数据无限且同质，指出代码预训练比自然语言更“数据饥饿”（Luo et al., 2025）。然而，现代软件开发涉及 Python、Java、Rust 等异构语言，其类型严格度、范式差异直接影响模型学习难度。现有方法未量化语言比例 $p$ 对缩放指数的影响，也未解释为何混合训练能提升低资源语言性能。本文切入点在于将语言比例作为显式变量引入缩放公式，通过控制变量实验分离单语言缩放特性与跨语言协同效应，从而建立可操作的多语言资源分配指南。

## 核心方法

### 方法参照系

本文基于 Chinchilla 缩放定律框架，但关键差异在于引入语言比例向量 $p$ 作为显式变量。传统方法假设数据同质，而本文针对代码域的语言异构性，将损失函数扩展为比例依赖形式，以捕捉不同编程语言对模型性能的非均匀贡献。

### 语言特定缩放定律

针对各编程语言独立缩放行为，本文拟合 Chinchilla 风格幂律，揭示解释型语言（如 Python）比编译型语言（如 Rust）从规模扩展中获益更多。设计动机在于解决通用缩放定律无法区分语言内在复杂度的问题，通过独立拟合获取各语言的 $\alpha_N, \alpha_D$ 与 $L_{\infty}$。

$$ L_k(N, D) = A_k N^{-\alpha_{N,k}} + B_k D^{-\alpha_{D,k}} + L_{\infty,k} $$

该公式中 $k$ 表示特定编程语言，$L_{\infty,k}$ 量化该语言的内在可预测性下限。实验显示 C# 的 $L_{\infty}$ 最低，Python 最高，反映严格类型系统语言更易学习。

### 比例依赖多语言缩放

在单语言定律基础上，本文引入跨语言转移系数 $\tau_{ij}$，构建比例依赖缩放模型。设计动机在于解决均匀分配令牌导致高效用语言（如 Python）资源不足、低效用语言（如 Rust）资源过剩的问题。

$$ L(N, D; p) = A \cdot N^{-\alpha_N(p)} + B \cdot D^{-\alpha_D(p) \cdot x} + L_{\infty}(p) $$

其中 $\alpha_N(p) = \sum_k p_k \alpha_{N,k}$，$x$ 项通过 $\tau_{ij}$ 捕捉跨语言协同效应。该模型允许根据语言效用与协同性动态调整 $p$，实现全局性能最优。

## 实验评估

实验在 0.2B 至 14B 参数、1T 令牌规模下进行，基线包括单语言重复、均匀混合与平行配对策略。缺失与 CAMEL 等容量感知混合策略的直接对比，但内部对比显示平行配对在零样本翻译上显著优于基线。

| 语言对 | 基线损失 | 平行配对损失 | 相对改进 |
| :--- | :--- | :--- | :--- |
| Java→Go | 0.80 | 0.61 | 23.75% |
| Python→Java | 0.71 | 0.87 | -22.54% |
| C#→Go | 0.81 | 1.73 | -113.58% |

平行配对在多数方向上降低损失，但 Python 作为源语言时出现性能下降，表明跨语言迁移存在方向性不对称。

消融实验显示，Java 与 C# 混合训练带来最大协同增益（$\Delta=0.186$），而 Python 与多数语言混合产生负迁移（$\Delta=-0.021$）。这一反直觉发现揭示 Python 作为枢纽语言，其自身性能对混合策略敏感，需单独优化比例。

评估边界受限于自建 900B 代码语料，缺乏与通用 SOTA 模型的横向对比。代码未公开，超参数细节有限，复现性依赖作者提供的拟合参数。指标仅覆盖验证损失与 MultiPL-E 生成准确率，未包含推理时计算开销。

## 关联研究分析

从问题动机看，本文与 CAMEL（Li et al., 2026）均关注数据混合优化，但 CAMEL 侧重模型容量对数据利用效率的影响，而本文聚焦语言间语法协同。差异根源在于任务特性：代码语言具有明确的语法边界，允许通过平行配对建立显式对齐，而通用文本缺乏此类结构化对齐信号。

从方法设计看，本文与 Practical Scaling Laws（Bryant & Liu, 2026）均扩展 Chinchilla 定律，但后者引入过拟合项以应对数据受限，而本文未显式建模多轮训练惩罚。这一差异暗示本文假设数据充足，未探索在 1T 令牌以下、高重复率场景下的缩放行为，可能限制其在小模型训练中的适用性。

## 总结

本文核心矛盾在于通用缩放定律无法处理代码语言异构性，导致资源分配低效。切入点在于将语言比例作为显式变量，通过 1000+ 次实验量化各语言独立缩放指数与协同增益。方法上建立比例依赖缩放模型，证明最优分配需优先高效用语言（Python）与高协同对（JS-TS），同时减少快速饱和语言（Rust）的令牌。实验显示平行配对在 Java→Go 方向将损失从 0.80 降至 0.61，但 Python 作为源语言时性能下降 22.54%。边界在于未建模数据受限下的过拟合效应，且缺乏与容量感知混合策略的对比。当训练令牌降至 100B 以下时，比例依赖缩放定律的预测精度是否仍保持，论文未给出回答。
