# ACL-Findings2026最新论文 ｜Dynamic Graph Navigation via Triplet Chains for Structure-Aware Retrieval-Augmented Generation ｜结构感知检索增强生成

作者：Feng Zhao、Yufei Wu、Xianggan Liu 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_e4de6fdb08b0)

> 检索增强生成（RAG）旨在通过外部知识缓解大语言模型（LLM）的幻觉，但传统RAG在简单问题上引入噪声，在复杂问题上缺乏结构。现有方法往往孤立处理文本或图谱，未能有效协同。本文提出Trig-Nav，通过三元组链分解问题并动态构建子图，实现多视角知识检索。该方法在开放域问答上优于基线，但其对动态子图构建质量的依赖及在多跳推理中的局限尚存疑。

## 研究背景

当LLM面对超出训练数据时效性的复杂查询时，其参数化知识往往失效，导致事实幻觉。检索增强生成（RAG）通过引入外部文档缓解此问题，但检索到的非结构化文本常包含大量无关噪声，干扰模型判断。对于涉及多实体关联的复杂问题，扁平文本难以呈现实体间的逻辑依赖，LLM难以从中提取关键推理路径。知识图谱（KG）虽能提供结构化关系，但静态KG存在语义稀疏性，且传统KG检索方法多关注“如何检索”，忽视了“何种知识适合图谱检索”这一根本问题。

RAG领域的主流优化方向包括查询重写、重排序及自适应检索时机判断，如Adaptive-RAG通过分类器决定检索深度，SimGRAG通过量化查询与子图对齐度优化检索。然而，这些方法大多将文本与图谱视为独立模态，缺乏针对知识类型的细粒度区分机制。文本检索擅长获取事实性细节，但难以捕捉长程因果链；图谱检索擅长关联关系，但缺乏具体语境。这种模态割裂导致在复杂推理中，单一模态检索往往顾此失彼。本文的切入点在于，将复杂问题分解为三元组推理链，并据此动态构建目标子图，通过区分事实、关联与因果三类知识，实现文本语义与图谱结构的协同推理。

## 核心方法

### 方法参照系

标准RAG流程为：接收查询→检索相关文档→LLM生成答案。本文的关键差异在于，在检索前引入问题分解与知识类型分类，在检索后引入动态子图构建，将“检索-生成”转变为“分解-构建-多视角推理-生成”的闭环。

### 三元组链构建与知识类型分类

针对复杂问题中LLM难以直接定位关键信息的问题，本文首先将用户查询 $x_q$ 分解为 $L$ 个子问题 $X_L = \{x_1, ..., x_L\}$。每个子问题被映射为三元组 $\langle S, P, A \rangle$，其中 $A$ 为待求解项。基于三元组间的实体链接关系 $T_k.A = T_{k+1}.S$，构建推理链 $L_j = [T_1 \to T_2 \to \dots \to T_m]$。设计动机在于，通过显式化推理路径，将复杂的多跳问题转化为序列化的单步查询，降低LLM的认知负荷。

根据三元组的拓扑结构，本文定义了三类知识及其形式化判别函数：

1.  **事实知识**：对应单三元组结构，判别函数为 $f_{fact}(S) = I(|S| = 1)$。

2.  **关联知识**：对应链式传递结构，判别函数为 $f_{assoc}(S) = \frac{1}{|S|-1} \sum_{i=1}^{|S|-1} I(o_i = s_{i+1})$，其中 $o_i, s_{i+1}$ 分别为前后三元组的客体与主体。

3.  **因果知识**：对应星形聚合结构，判别函数为 $f_{causal}(S) = \frac{\max_{o \in O} \sum_{i=1}^{|S|} I(o_i = o)}{|S|}$，衡量指向同一实体的证据集中度。

该分类机制使系统能根据问题结构动态选择检索策略，避免盲目检索带来的噪声。

### 动态子图构建与多视角推理

针对静态KG语义稀疏及文本检索结构缺失的问题，本文提出从检索文本中动态构建目标知识图谱 $G_i$。对于每个子问题 $x_i$，检索支持文档 $D_i$，并通过 $G_i = \text{KG-Construct}(\text{Triple-Extract}(D_i))$ 提取三元组构建子图。设计动机在于，动态构建的子图仅包含与当前子问题相关的实体与关系，既保留了文本的语义丰富性，又提供了图谱的结构约束。

在推理阶段，系统执行多视角检索与链式推理。对于每个三元组 $T_i = \langle S_i, P_i, A_i \rangle$，结合图谱查询与文本检索获取增强知识表示 $K = G \cup D$。具体公式为：

$$ A_i = \text{LLM} \left( \text{KG-Query}(S_i, P_i) \oplus \text{Retrieve}(D_i | S_i, P_i) \right) $$

该公式表明，答案 $A_i$ 由LLM基于图谱查询结果与文本检索结果的融合生成。图谱结构用于引导文本理解，文本内容用于验证图谱推理的合理性。最终，通过整合所有子问题的答案，生成原始问题的最终答案。

## 实验评估

实验在NQ、TriviaQA、HotpotQA和2WikiMultiHopQA四个开放域问答数据集上进行，使用LLaMa3-8B作为主模型，Qwen2.5-7B用于对比验证。基线涵盖传统LLM、Direct RAG、Adaptive-RAG、SimGRAG等文本与图谱RAG方法。

| 方法 | NQ (EM) | TriviaQA (EM) | HotpotQA (EM) | 2WikiMultiHopQA (EM) |
| :--- | :--- | :--- | :--- | :--- |
| Vanilla LLM | 25.80 | 46.40 | 23.00 | 25.20 |
| Direct RAG | 50.42 | 62.02 | 34.80 | 29.60 |
| Adaptive-RAG | 37.80 | 52.20 | 42.00 | 40.60 |
| SimGRAG | 44.07 | 59.03 | 28.03 | 33.20 |
| **Trig-Nav** | **56.85** | **67.00** | **43.80** | **34.80** |

Trig-Nav在NQ和TriviaQA上显著优于Direct RAG和Adaptive-RAG，尤其在TriviaQA上达到67.00的EM，表明其结构感知机制在组合复杂查询中有效。然而，在2WikiMultiHopQA上，Trig-Nav（34.80）低于Adaptive-RAG（40.60），显示其在长程多跳推理中的局限性。

| 消融模块 | NQ (EM) | TriviaQA (EM) | HotpotQA (EM) | 2WikiMultiHopQA (EM) |
| :--- | :--- | :--- | :--- | :--- |
| w/o. retrieval | 31.52 | 26.40 | 20.44 | - |
| w/o. text | 55.64 | 63.20 | 37.40 | - |
| w/o. graph | 54.83 | 65.50 | 35.60 | - |
| w/o. multi-link | 52.45 | 63.40 | 39.60 | - |
| w/o. decompose | 50.42 | 62.02 | 34.80 | - |
| **Ours** | **56.85** | **67.00** | **43.80** | **34.80** |

消融实验显示，移除检索模块导致性能大幅下降（NQ从56.85降至31.52），验证了外部知识的必要性。移除分解模块导致NQ性能下降6.43个点，表明问题分解对降低推理难度至关重要。移除图谱或文本模块均导致性能轻微下降，证实了双模态融合的协同效应。

评估指标仅包含EM和F1，缺乏对幻觉率、推理延迟及可执行性的细粒度评估。论文未提供代码仓库，且实验仅采样500个样本，统计显著性未报告。此外，论文未对比KBQA专用基准（如WebQSP），限制了其在结构化查询领域的可比性。

## 关联研究分析

从问题动机看，Trig-Nav与SimGRAG（Cai et al., 2025）均关注图谱检索，但SimGRAG侧重于查询与预构建子图的静态对齐，而Trig-Nav强调从文本中动态构建子图以适配当前查询。这一差异源于任务特性：SimGRAG假设KG已完备，而Trig-Nav针对KG稀疏或文本主导的场景。然而，动态构建子图可能引入新的噪声源，如三元组提取错误，论文未对此进行量化分析。

从方法设计看，Trig-Nav与Adaptive-RAG（Jeong et al., 2024）均引入自适应机制，但Adaptive-RAG基于查询复杂度分类决定检索深度，而Trig-Nav基于知识类型（事实/关联/因果）决定检索路径。Trig-Nav的细粒度分类理论上更精准，但在2WikiMultiHopQA上的表现落后于Adaptive-RAG，暗示其多跳推理能力可能受限于三元组链的线性结构，未能充分处理非线性的复杂依赖。

## 总结

Trig-Nav旨在解决RAG中单一模态检索的噪声与结构缺失矛盾，通过三元组链分解与动态子图构建，实现事实、关联与因果知识的协同检索。该方法在NQ和TriviaQA上分别取得56.85和67.00的EM，优于Direct RAG和SimGRAG。然而，其在2WikiMultiHopQA上的表现（34.80）低于Adaptive-RAG（40.60），暴露了其在长程多跳推理中的局限。当问题涉及非线性依赖或深层因果链时，基于线性三元组链的推理是否足以捕捉复杂逻辑，论文未给出回答。
