研究机构：阿联酋扎耶德大学、香港城市大学

作者：Yingxu Wang、Jiaxin Huang、Mengzhu Wang 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_37dd064c7f6b)

> 多跳知识图谱问答（KGQA）要求模型在关系路径上维持语义连贯，但现有智能体方法常将每步决策孤立处理，导致推理漂移与重复探索。TRACE 通过动态生成自然语言叙事维持上下文一致性，并将历史探索轨迹抽象为可复用先验，以双反馈重排序机制融合局部语义与全局经验。该框架在 WebQSP 上取得 91.6 的 Hits@1，但在 CWQ 复杂组合推理上落后于最新记忆优化方法，其经验先验机制的泛化边界尚待验证。

## 研究背景

当 LLM 在知识图谱（KG）上进行多跳推理时，每一步的关系选择若仅依赖当前实体状态，极易偏离原始问题意图。这种局部决策的孤立性导致推理路径出现逻辑断裂，即“上下文引导缺失”。为维持语义连贯，需将已遍历的关系序列转化为自然语言叙事，作为后续决策的条件输入。然而，单纯依赖当前路径叙事仍无法避免重复探索，因为模型缺乏对历史失败或低效路径的抽象记忆，这构成了“探索泛化”难题。

多跳 KGQA 的主流路线已从语义解析转向 LLM 与 KG 的动态交互。ToG (2023) 和 RoG (2023) 确立了基于 Beam Search 的逐步探索范式，但二者均将每步关系选择视为独立事件，未显式整合前序路径的语义信息。近期方法如 DP (2025) 和 RwT (2025) 虽引入了问题特定先验，但仍缺乏对探索轨迹本身的经验抽象机制。TRACE 的切入点在于同时解决这两个被忽略的问题：通过动态上下文生成（Dynamic Context Generation）维持路径内的语义连贯，通过探索泛化（Exploration Generalization）将历史轨迹转化为全局先验，从而在长程推理中实现连贯性与效率的平衡。

## 核心方法

### 方法参照系

TRACE 基于 LLM 驱动的逐步探索框架，其标准流程为：在 KG 上执行 Beam Search，每步由 LLM 从当前实体的邻域中选择下一关系。与 ToG 等基线不同，TRACE 在每步决策中显式注入两类信息：当前路径的自然语言叙事（局部上下文）和历史探索轨迹的抽象先验（全局经验），并通过双反馈重排序机制融合二者。

### 动态上下文生成

在标准 Beam Search 中，第 $t$ 步的关系选择仅依赖当前实体 $e_t$ 和问题 $q$，忽略了前序路径 $R^{(t)}_q$ 的语义累积。TRACE 引入动态上下文生成模块，将关系序列转化为自然语言叙事 $C^{(t)}_q$，作为后续检索的条件。其核心公式为：

$$ C^{(t)}_q = f_{ctx}(q, R^{(t)}_q) $$

其中 $f_{ctx}$ 为 LLM 生成函数。该设计解决了孤立决策导致的逻辑漂移问题，确保每步关系选择与原始问题意图保持语义对齐，避免推理路径偏离目标。

### 探索泛化与双反馈重排序

动态上下文生成仅处理当前路径，无法利用历史探索中的失败或低效模式。TRACE 引入探索泛化模块，将终止轨迹 $T$ 摘要为 $D_q$，并抽象为可复用先验 $F$：

$$ F = f_{gen}(\{D_q \mid P^{(t)}_q \in T\}) $$

其中 $f_{gen}$ 识别重复探索模式。在关系选择时，LLM 检索器基于 $C^{(t)}_q$ 生成候选集 $C_t$，随后通过双反馈重排序融合局部叙事与全局先验：

$$ s(r) = f_{rank}(q, R^{(t)}_q, r, F) $$

保留得分超过阈值 $\zeta$ 的关系以扩展新轨迹。该机制通过抽象历史经验减少冗余探索，同时利用局部叙事维持语义连贯，解决了长程推理中重复探索与逻辑断裂的双重问题。

## 实验评估

TRACE 在 WebQSP 和 CWQ 上评估，基线覆盖语义解析、检索、通用 LLM 及 LLM+KG 四类方法，但未对比 2026 年最新的 CLAUSE 或 EvoMemKG 等智能体记忆方法。主实验显示，TRACE 在 WebQSP 上以 91.6 的 Hits@1 超越 DP (87.5) 和 RwT (87.0)，但在 CWQ 上以 76.9 的 Hits@1 低于 EvoMemKG 和 KG-Hopper 的 87.00（据领域综述），表明其在复杂组合推理上的局限性。

| 方法 | WebQSP Hits@1 | WebQSP F1 | CWQ Hits@1 | CWQ F1 |
| :--- | :--- | :--- | :--- | :--- |
| DP | 87.5 | 81.4 | 75.8 | 69.4 |
| RwT | 87.0 | 79.7 | 72.4 | 66.7 |
| TRACE | 91.6 | 81.7 | 76.9 | 72.9 |

消融实验表明，移除动态上下文生成（w/o CT）导致 WebQSP Hits@1 从 91.6 降至 89.0，移除探索泛化（w/o ER）降至 88.6，同时移除两者（w/o ALL）降至 87.5。这证实了两个模块的互补性：上下文生成维持语义连贯，探索泛化减少冗余探索，二者共同贡献于性能提升。

| 变体 | WebQSP Hits@1 | CWQ Hits@1 |
| :--- | :--- | :--- |
| TRACE w/o CT | 89.0 | 74.1 |
| TRACE w/o ER | 88.6 | 74.8 |
| TRACE w/o ALL | 87.5 | 73.6 |

评估边界方面，TRACE 使用 GPT-4.1 作为骨干，而部分基线使用开源模型，导致直接对比存在偏差。论文未报告置信区间，且未提供代码，可复现性受限。超参数 $k$、$L$、$\zeta$ 的敏感性分析显示，$k=3$（WebQSP）/4（CWQ）、$L=4$、$\zeta=0.5$ 为最优配置，但参数选择依赖数据集特性，缺乏通用性。

## 关联研究分析

从问题动机看，TRACE 与 EvoMemKG (2025) 均关注长程推理中的经验复用，但 EvoMemKG 通过工作记忆（WM）和长期记忆（EM）的双记忆机制管理信息，而 TRACE 通过轨迹摘要抽象为全局先验 $F$。EvoMemKG 的记忆更新是动态的，能根据推理结果实时调整策略，而 TRACE 的先验 $F$ 在推理过程中保持静态，仅在轨迹终止时更新。这一差异源于任务特性：EvoMemKG 针对多跳深度推理，需实时记忆管理；TRACE 针对路径连贯性，侧重经验抽象。TRACE 在 CWQ 上落后于 EvoMemKG，可能源于静态先验无法适应复杂组合推理中的动态变化。

从方法设计看，TRACE 与 ToG (2023) 共享 Beam Search 框架，但 ToG 仅依赖当前实体状态选择关系，而 TRACE 引入动态上下文生成和探索泛化。ToG 的局限在于缺乏对前序路径语义的整合，导致推理漂移；TRACE 通过叙事 $C^{(t)}_q$ 解决此问题。然而，TRACE 的叙事生成依赖 LLM 的语义理解能力，若 LLM 对 KG 模式（Schema）理解不足，可能引入语义偏差。论文未讨论叙事生成的鲁棒性，也未验证在模式不完整 KG 上的表现，这是其方法设计的潜在盲区。

## 总结

TRACE 旨在解决多跳 KGQA 中推理连贯性与经验复用的矛盾，通过动态上下文生成维持路径语义一致，通过探索泛化抽象历史轨迹为全局先验。该框架在 WebQSP 上以 91.6 的 Hits@1 超越 DP 和 RwT，但在 CWQ 上以 76.9 的 Hits@1 落后于 EvoMemKG 的 87.00，暴露其在复杂组合推理上的局限。TRACE 的静态先验机制无法适应动态变化的推理需求，且叙事生成依赖 LLM 的语义理解能力，缺乏对模式不完整 KG 的鲁棒性验证。当 KG 模式定义不完整或动态更新时，探索泛化模块的抽象先验是否仍能有效引导推理，论文未给出回答。
