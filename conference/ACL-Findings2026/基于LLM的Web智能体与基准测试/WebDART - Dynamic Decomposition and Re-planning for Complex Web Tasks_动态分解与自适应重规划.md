> 长程网页任务中，智能体因需同时处理导航、信息提取与约束推理而陷入“认知过载”，导致成功率在复杂基准上骤降。现有线性推理-行动架构无法解耦这些异构能力，致使错误在步骤间级联放大。WEBDART 将任务强制拆解为导航、提取、执行三个串行子任务，并引入动态重规划机制以利用新发现的界面元素优化路径。该框架在复杂任务上显著提升了成功率，但其纯文本设定与串行解耦是否牺牲了实时反馈耦合，仍存疑。

## 研究背景

当智能体面对“找出价格区间内评论数前三的产品”这类任务时，它必须在浏览页面的同时追踪已访问项、筛选价格并计算排名。这种多目标并行处理导致上下文窗口迅速饱和，即“认知过载”。认知过载使得模型在长程任务中频繁遗忘指令或遗漏关键数据，而传统的 ReAct 框架将推理与行动交织在单一轨迹中，无法隔离这种负荷，导致早期导航错误直接污染后续分析。

当前主流 Web 智能体架构主要依赖线性 ReAct 循环或基于轨迹的强化学习，它们在简单导航任务上表现尚可，但在需要跨页面记忆与结构化数据分析的复杂任务上性能崩溃。WebChoreArena 基准显示，GPT-4o 驱动的现有智能体在复杂任务上仅达 8.0% 准确率，远低于其在 WebArena 简单任务上的 46.6%。这一差距揭示了现有方法在处理约束密集型任务时的结构性缺陷：它们试图在单次推理流中完成所有操作，而非像人类专家那样将任务分解为独立的导航、提取与分析阶段。

## 核心方法

### 方法参照系

本文问题属于 LLM 智能体架构设计，标准流程为基于 ReAct 的线性推理-行动循环。关键差异在于，本文拒绝在单一轨迹中混合异构能力，而是引入显式的任务分解层，将导航、信息提取与执行解耦为串行模块，并允许在导航阶段动态修正计划。

### 任务分解与保守策略

针对初始分解可能因未知界面元素而次优的问题，WEBDART 采用“保守分解”策略，将过滤、排序等数据操作默认分配至执行阶段，导航仅负责页面发现。分解过程由 LLM 基于任务描述 $T$ 与初始观察 $o_0$ 生成三个子目标：

$$ (T_{nav}, T_{ie}, T_{exec}) = f(T, o_0) $$

该公式表明，分解是条件于初始环境的函数，而非静态模板。这种设计解决了线性架构中“导航与分析耦合”导致的错误传播问题：当导航路径错误时，保守策略确保分析阶段仍拥有完整的数据集，避免了因过早过滤而丢失关键信息。

### 动态重规划机制

在导航执行过程中，智能体每步输出推理 $r_t$ 与动作 $a_t$，并维护交互历史 $\mathbf{h}_t$。当检测到新出现的界面元素（如过滤器、排序按钮）能直接满足部分约束时，触发动态重规划，更新导航目标 $T_{nav}$：

$$ T_{nav}^{new} = \text{Replan}(T_{nav}, o_t, \mathbf{h}_t) $$

此机制允许智能体在发现“价格过滤器”后，立即跳过无关页面，将原本需遍历所有页面的任务转化为仅访问筛选后页面的任务。这一改动直接降低了导航步数，同时通过减少冗余探索提升了最终答案的准确性，解决了静态分解无法适应动态网页环境的问题。

## 实验评估

实验在 WebChoreArena（主）与 WebArena（辅）上进行，基线包括 SteP、BrowserGym、AWM 和 AgentOccam，覆盖轨迹复用、数据合成与接口优化路线，但缺失多模态及长期记忆增强类基线。

| 模型 | 方法 | Shopping | Reddit | Admin | GitLab | Overall |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-5 | AgentOccam | 15.4 | 26.5 | 27.6 | 21.3 | 21.6 |
| GPT-5 | WEBDART | 35.0 | 26.4 | 34.1 | 29.1 | 31.2 |
| GPT-4o | AgentOccam | 10.3 | 1.8 | 5.5 | 3.2 | 8.0 |
| GPT-4o | WEBDART | 18.8 | 19.8 | 12.9 | 9.4 | 15.2 |

在 GPT-5 骨干下，WEBDART 整体成功率达 31.2%，较 AgentOccam 提升 9.6 个百分点；在 GPT-4o 下提升 7.2 个百分点。Shopping 域提升最为显著（GPT-5 下 +19.6），表明分解策略对约束密集型任务增益最大。

| 域 | 准确率 (无重规划) | 准确率 (有重规划) | 平均步数 (无重规划) | 平均步数 (有重规划) |
| :--- | :--- | :--- | :--- | :--- |
| Shopping | 18.8 | 26.5 | 32.9 | 18.2 |
| Reddit | 19.8 | 20.9 | 25.1 | 21.1 |
| Admin | 12.9 | 13.6 | 16.7 | 17.7 |
| GitLab | 9.4 | 11.1 | 23.3 | 21.2 |

动态重规划在 Shopping 域将平均步数从 32.9 降至 18.2，同时准确率提升 7.7 个百分点，验证了利用界面元素优化路径的有效性。Admin 域步数微增（16.7 至 17.7），因该网站任务本身依赖大量过滤器，重规划未带来显著效率提升，但准确率仍小幅上升。

评估指标仅为端到端成功率，缺乏步骤级正确性或规划质量的细粒度诊断。代码已开源，但论文未报告计算延迟或内存占用，无法评估动态重规划带来的额外推理开销。

## 关联研究分析

从方法设计看，WEBDART 与 Branch-and-Browse 均针对长程任务脆弱性，但 B&B 采用树结构回溯以应对早期错误，而 WEBDART 采用线性分解加动态重规划。B&B 的树搜索在错误恢复上更灵活，但计算开销大且实时性差；WEBDART 的串行解耦牺牲了导航与分析的实时反馈耦合，换取了模块化的可诊断性与更低的单步认知负荷。这种取舍在任务结构高度可预测时更优，但在需要频繁回溯的非线性环境中可能受限。

从问题动机看，WEBDART 与 AgentOccam 共享简化 DOM 观察空间的设计，但 AgentOccam 聚焦于接口优化以提升单步准确率，而 WEBDART 聚焦于任务结构优化以缓解长程认知过载。AgentOccam 在 WebArena 简单任务上表现强劲，但在 WebChoreArena 复杂任务上仅达 8.0%（GPT-4o），表明接口优化无法解决多步骤推理的结构性缺陷。WEBDART 通过分解将复杂任务转化为多个简单子任务，从而在复杂基准上超越 AgentOccam，但在简单任务上仅提升 1.5 个百分点，暗示分解机制对简单任务存在冗余开销。

## 总结

WEBDART 旨在解决长程网页任务中因认知过载导致的性能崩溃，其切入点在于将异构能力解耦为串行子任务，并通过动态重规划适应环境变化。该框架在 WebChoreArena 上将 GPT-5 骨干的成功率从 21.6% 提升至 31.2%，并在 Shopping 域通过重规划减少 14.7 步导航。然而，其纯文本设定与串行解耦设计限制了在多模态复杂 UI 下的适用性，且动态重规划在 Admin 域未带来效率提升，暴露了其对界面元素依赖性的局限。当任务结构高度非线性且需要频繁回溯时，线性分解加重规划是否仍优于树结构搜索，论文未给出回答。
