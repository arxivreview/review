> 软件测试的核心痛点在于如何精准覆盖高风险执行路径，而非仅追求代码行数覆盖。现有基于大语言模型（LLM）的测试生成方法依赖提示工程启发式，受限于模型随机性，难以稳定命中特定分支。GLMTest 提出将代码属性图（CPG）结构嵌入与 LLM 文本语义在共享空间联合训练，实现分支定向生成。该方法在 TestGenEval 上将分支准确率从 27.4% 提升至 50.2%，但仅验证了 Python 单语言场景，且未对比专用测试生成 SOTA，其泛化边界尚存疑。

## 研究背景

测试用例的有效性取决于其能否触发特定控制流路径。执行分支（Execution Branch）定义为程序在给定输入下实际执行的有序语句序列，它是衡量测试覆盖深度的基本单元。然而，LLM 生成的测试用例往往基于文本语义推测，缺乏对程序内部数据依赖与控制流结构的显式感知，导致生成结果难以精确对齐目标分支。这种“文本-结构”解耦的缺陷，使得模型在面临复杂逻辑分支时，即使语法正确，也常因输入值不匹配而无法进入预期路径。

自动测试生成领域长期存在两条主流路线：微调（Fine-tuning）与提示工程（Prompt Engineering）。微调方法通过代码-测试对训练模型，但受限于数据分布，难以泛化到未见过的分支结构；提示工程方法通过注入签名或控制流信息引导冻结 LLM，但缺乏原则性优化机制，无法保证生成用例必然执行目标分支。现有工作如 Chen et al. (2025) 虽尝试结合代码图与 LLM，但仅将图特征作为辅助知识丰富提示，未实现结构信息与生成过程的深度耦合。GLMTest 的切入点在于，将程序结构视为一等公民，通过图神经网络（GNN）提取分支感知的结构嵌入，并将其直接注入 LLM 的解码过程，从而建立从静态结构到动态执行路径的可控映射。

## 核心方法

### 方法参照系

传统 LLM 测试生成遵循“文本输入-文本输出”范式，将程序源码与指令提示作为纯文本序列输入，依赖模型内部隐式学习代码结构。本文问题的关键差异在于，要求生成结果必须满足特定的执行分支约束，这超出了纯文本语义推理的能力边界，需要显式的结构条件化机制。

### 异构图神经网络分支嵌入

在参照系中，程序结构通常被扁平化为文本或仅作为静态分析结果附加于提示。GLMTest 在此环节引入 K 层异构图神经网络，专门提取目标分支的结构上下文。设计动机在于解决纯文本表示无法捕捉代码对象间依赖关系的问题，使模型能理解“哪些语句共同构成了目标路径”。

$$
h_v^{[K]} = \text{pool}\left\{ h_{v,j}^{[K]} \right\}_{j=1}^{r}
$$

该公式表示在 GNN 最后一层，将节点 $v$ 在所有 $r$ 种关系类型下的嵌入进行池化，得到统一的结构嵌入。随后，通过堆叠目标分支 $b$ 涉及的所有节点嵌入，生成分支嵌入 $e_b$。这一过程将离散的分支掩码转化为连续的高维向量，保留了执行路径上的细粒度结构信息，为后续 LLM 提供明确的结构条件。

### 结构-文本联合注入与端到端训练

在 LLM 模块中，GLMTest 未采用传统的序列级查询，而是引入图标记 `<|graph_pad|>` 作为占位符，将分支嵌入 $e_b$ 直接替换该标记的嵌入向量，形成输入嵌入 $e_{inp}$。设计动机在于，结构信号需影响所有后续解码步骤，而非仅在初始提示中提供一次性参考。

$$
\mathcal{L}(\theta) = \sum_{(G, p_i, m_i, t_i) \in \mathcal{D}} \ell(f_{lm}(e_{inp}), t_i) + \lambda \|\theta\|_2^2
$$

该损失函数表明，GNN 参数与 LLM 参数 $\theta$ 通过反向传播联合优化，分支嵌入的拼接操作保持完全可微。这种端到端训练策略确保了结构嵌入与文本语义在共享空间中对齐，使模型能根据结构条件生成精确命中目标分支的测试用例，而非仅生成语法正确的通用测试。

## 实验评估

实验基于 TestGenEval 基准，该数据集源自 SWE-bench，包含 40,868 个（程序，分支，测试）三元组。基线选择为 Claude-Sonnet-4.5 和 GPT-4o-mini，均为通用企业级 LLM，采用提示工程策略。缺失的强基线包括专用测试生成模型（如 Tufano et al., 2021 的微调方法）及其他图-LLM 结合框架，这限制了性能对比的全面性。

| 方法 | Pass@1 | BranchAcc | BranchCov |
| :--- | :--- | :--- | :--- |
| GLMTest (7B) | 0.85 | 50.2% | 16.91% |
| Claude-Sonnet-4.5 | 0.71 | 27.4% | - |
| GPT-4o-mini | 0.67 | 26.5% | - |

GLMTest 在分支准确率上显著优于基线，且 Pass@1 保持高位，表明结构条件化未牺牲测试用例的可执行性。消融实验显示，移除分支嵌入后 BranchAcc 降至 39.9%，证实结构信息的关键作用。模型规模对比中，14B 模型 BranchAcc 为 49.3%，略低于 7B 的 50.2%，但 BranchCov 提升至 17.63%，暗示参数扩展主要增益于覆盖广度而非定向精度。

评估边界方面，实验仅覆盖 Python 语言，且未报告推理延迟与 GPU 内存开销，工业部署成本未知。可复现性方面，论文提供了代码与数据集链接，训练使用 4×A100 GPU，耗时约 48 小时，成本约 $119.56，具备较高复现可行性。

## 关联研究分析

从问题动机看，GLMTest 与 SWE-Tester (Soni et al., 2026) 同属测试生成领域，但前者聚焦分支定向，后者聚焦 Issue 复现。SWE-Tester 依赖自然语言 Issue 描述生成复现测试，未显式利用程序结构，因此在分支精确性上缺乏机制保障。GLMTest 的结构嵌入机制解决了“生成测试能否命中特定路径”的问题，而 SWE-Tester 解决的是“生成测试能否复现特定 Bug”的问题，两者在测试目标粒度上存在本质差异。

从方法设计看，GLMTest 与 RAVEN (Gadey et al., 2026) 均试图增强 LLM 的上下文感知能力，但路径截然不同。RAVEN 采用智能体检索增强生成（Agentic RAG），通过外部知识库动态检索相关代码片段，属于非参数化知识增强；GLMTest 则通过 GNN 学习内部结构嵌入，属于参数化结构增强。RAVEN 的优势在于能引入最新项目知识，但受限于检索噪声；GLMTest 的优势在于结构信息内化于模型，推理时无需外部检索，但受限于训练时见过的分支模式。这种“外部检索”与“内部结构”的取舍，反映了领域内对知识来源可靠性的不同假设。

## 总结

GLMTest 旨在解决 LLM 测试生成中分支命中率低的核心矛盾，其切入点在于将程序结构从提示辅助升级为生成条件。通过异构 GNN 与 LLM 的联合训练，该方法在 TestGenEval 上将分支准确率从 27.4% 提升至 50.2%，证明了结构条件化对定向测试生成的有效性。然而，实验仅验证了 Python 单语言场景，且未与专用测试生成 SOTA 对比，其性能优势是否源于结构机制还是数据规模尚不明确。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
