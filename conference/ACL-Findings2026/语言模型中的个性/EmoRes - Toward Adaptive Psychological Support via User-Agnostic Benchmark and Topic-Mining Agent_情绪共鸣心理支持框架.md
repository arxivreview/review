作者：Zhengwei Zou、Xuanming Jiang、Baoyi An 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_a9181e30ba41)

> 心理支持对话系统面临的核心矛盾是维持治疗连贯性与适应个体差异之间的平衡，现有递归上下文拼接方法导致对话停滞与情感碎片化。EmoRes 通过引入基于焦点解决短期治疗（Solution-Focused Brief Therapy, SFBT）的多智能体架构，将主题挖掘与自我反思解耦为两个协同代理，在推理时动态调节对话流向。该框架在自建基准 VeilEval 上实现了约 3 倍的性能提升，但其依赖合成数据与 LLM 评估的闭环验证，使得临床效度的外部泛化性存疑。

## 研究背景

心理支持对话（Psychological Health Support, PHS）要求模型在长程交互中保持情感连续性，这首先依赖于对对话状态的精确建模。传统方法采用递归上下文拼接，将历史对话直接输入模型，但这种方式导致上下文窗口迅速饱和，引发模板化重复与情感线索丢失。为突破此局限，研究界转向显式状态管理，即通过中间模块提取对话的潜在结构，再基于该结构生成响应。这一转变要求系统不仅具备语言生成能力，还需具备临床理论指导下的主题追踪与情感对齐能力。

当前 PHS 领域的主流路线分为两类：一是基于监督微调（Supervised Fine-Tuning, SFT）的专用模型，如 Crispers-7B 和 PsychoCounsel-8B，它们通过大规模心理对话数据训练，但缺乏对单一会话内动态变化的适应能力；二是通用大语言模型（Large Language Models, LLMs）直接提示，如 GPT-4o-mini，它们具备强大的通用推理能力，但缺乏临床理论约束，易产生过早干预或理论错位。这两类方法均未能解决“治疗一致性”与“用户适应性”的平衡问题，即如何在保持 SFBT 目标导向的同时，响应用户即时的情感波动。EmoRes 的切入点在于将 SFBT 的结构化原则转化为可计算的多智能体协同机制，通过外部状态管理替代内部权重调整，实现推理时的动态控制。

## 核心方法

### 多智能体协同架构参照系

EmoRes 属于应用层多智能体编排范式，与激活工程（Activation Engineering）等白盒控制方法形成鲜明对比。其核心差异在于：激活工程通过操纵模型内部表示空间中的向量实现人格或风格控制，而 EmoRes 通过操纵外部对话流中的主题状态与反思反馈实现治疗连贯性。这种黑盒路径避免了模型重训练的高昂成本，但牺牲了对底层认知机制的可解释性。

### 主题挖掘情感代理（TEAgent）

TEAgent 负责动态识别并追踪对话主题，解决传统方法中主题漂移导致的对话停滞问题。其核心机制是将对话结构化为树状主题图，每个节点代表一个目标对齐的主题抽象。TEAgent 在每一轮 $t$ 产生一个潜在状态 $S_t$，定义为：

$$ S_t = A(H_{t-1}, u_t) $$

其中 $S_t = \{(\tau_{t,i}, \sigma_{t,i})\}$ 包含主题标签 $\tau_{t,i}$ 及其重要性权重 $\sigma_{t,i}$。该公式的物理含义是：TEAgent 基于历史对话 $H_{t-1}$ 和当前用户输入 $u_t$，推断出当前对话的情感与主题状态，为后续生成提供结构化锚点。这一设计解决了递归上下文拼接中“长程情感线索丢失”的失效，通过显式状态变量 $S_t$ 确保每轮响应都紧扣当前治疗焦点。

### 自我反思代理（Self-Reflection Agent）

Self-Reflection Agent 负责迭代优化 Doctor Agent 生成的响应，解决单轮生成中情感对齐不足的问题。其核心机制是从医生和用户双视角评估响应的相关性（Relevance）与深度（Depth），并通过递归反思机制 $R$ 进行修正：

$$ R_t^{(i+1)} = R(R_t^{(i)}, H_{t-1}, S_{\leq t}) $$

该公式表明，第 $i+1$ 次反思基于第 $i$ 次响应、历史对话及累积主题状态 $S_{\leq t}$ 进行迭代，直至收敛或达到最大迭代次数 $k$。这一设计解决了单轮生成中“情感碎片化”的失效，通过多轮自我修正确保响应在逻辑严谨性与情感共鸣之间取得平衡，从而提升临床可解释性。

## 实验评估

实验在自建基准 VeilEval 上进行，该基准通过合成临床量表变量生成隐私保护的对话数据，覆盖抑郁、焦虑等多种心理构念。基线包括 SFT 模型（Crispers-7B, PsychoCounsel-8B）和通用 LLM（GPT-4o-mini, DeepSeek-V3）。主实验结果显示，EmoRes 在开源和商用模型上均显著提升平均得分，从约 3.1 提升至 7.3-8.8。

| 模型 | 方法 | VeilEvalEN 平均分 | VeilEvalCH 平均分 |
| :--- | :--- | :--- | :--- |
| Qwen3-8B | Raw | 3.20 | 3.08 |
| Qwen3-8B | + EmoRes | 7.93 | 8.04 |
| DeepSeek-V3 | Raw | 3.11 | 3.10 |
| DeepSeek-V3 | + EmoRes | 8.81 | 8.67 |

DeepSeek-V3 在 EmoRes 增强下达到最高分 8.81（EN）和 8.67（CH），表明该框架在强基线模型上具有显著的增益能力。消融实验显示，移除 Self-Reflection 模块导致平均分下降 0.39，移除 Topic-Selection 模块导致 Helpfulness 指标从 8.53 降至 7.67，证实了各模块的协同必要性。

评估边界方面，VeilEval 依赖 GPT-4o-mini 作为评估者，可能存在评估者偏好偏差；合成数据虽保证隐私，但可能无法完全反映真实临床对话的复杂性；多智能体协调增加了计算开销，论文未报告实时性指标。

## 关联研究分析

从问题动机看，EmoRes 与激活工程路线（如 CAA, Persona Vectors）形成黑盒与白盒的对比。激活工程通过操纵内部表示实现人格控制，强调几何正交性与解耦，而 EmoRes 通过外部状态管理实现治疗连贯性，强调临床理论约束。两者的根本差异在于：激活工程假设人格特质在表示空间中线性可分，而 EmoRes 假设治疗过程可通过结构化对话流显式建模。这种差异源于任务特性：人格控制需要细粒度的内部状态调节，而心理支持对话更关注宏观的治疗流程与情感共鸣。

从方法设计看，EmoRes 与 MentalAgora 等多智能体心理系统同属应用层编排，但耦合方式不同。MentalAgora 采用松散辩论机制，多个虚拟咨询师独立生成响应后聚合，而 EmoRes 采用 TEAgent 与 Self-Reflection Agent 的一对一协同，前者提供主题锚点，后者进行质量修正。这种紧密耦合旨在提升情感连贯性，但可能限制多视角的多样性。EmoRes 未探索多智能体辩论机制，其一对一协同是否在复杂心理情境中优于群体辩论，论文未给出回答。

## 总结

EmoRes 旨在解决心理支持对话中治疗连贯性与用户适应性的矛盾，通过 SFBT 理论约束的多智能体架构，将主题挖掘与自我反思解耦为协同代理，在推理时动态调节对话流向。实验在 VeilEval 上验证了该框架的有效性，DeepSeek-V3 增强后平均分达 8.81，较基线提升约 5.7 分。然而，其依赖合成数据与 LLM 评估的闭环验证，使得临床效度的外部泛化性存疑。当 VeilEval 的合成数据分布与真实临床对话存在系统性偏差时，EmoRes 的性能增益是否仍能保持，论文未给出回答。
