# ACL-Findings2026最新论文 ｜ARISE: An Adaptive Resolution-Aware Metric for Test-Time Scaling Evaluation in Large Reasoning Models ｜自适应分辨率感知扩展评估指标

研究机构：复旦大学、南京大学

作者：Zhangyue Yin、Qiushi Sun、Zhiyuan Zeng 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.06014)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.06014)

> 测试时扩展（Test-Time Scaling, TTS）旨在通过增加推理算力提升大语言模型性能，但现有评估手段无法量化“算力投入与准确率提升”的真实效率，且对性能随算力增加而下降的负向扩展现象视而不见。Muennighoff et al. (2025) 提出的斜率指标在负向扩展时存在病理行为，且仅关注全局准确率，忽略了样本级的错误转化。本文提出 ARISE 指标，通过样本级轨迹追踪与基于方差的动态采样机制，实现对 TTS 效率的细粒度、稳定量化。该指标在区分模型扩展能力上优于传统斜率指标，但其分数与实际任务准确率的直接映射关系尚未建立。

## 研究背景

理解本文需厘清 TTS 评估中的两个核心概念：扩展效率与负向扩展。扩展效率指单位算力投入带来的准确率边际增益，是衡量模型“思考性价比”的关键。然而，随着推理链长度增加，模型可能陷入过度思考（Overthinking），导致原本正确的答案被推翻，即负向扩展。这一现象使得传统的“算力越多越好”假设失效，要求评估指标不仅能奖励正确率提升，还需惩罚算力浪费。

TTS 领域的主流评估路线长期依赖 Pass@1 或 Pass@k 等准确率指标，以及基于斜率的扩展曲线分析。Pass@1 仅反映最终结果，无法区分模型是“一次做对”还是“多次尝试后碰巧做对”；斜率指标（Muennighoff et al., 2025）虽尝试量化效率，但其基于全局平均准确率的计算方式存在两大缺陷：一是无法捕捉单个样本从错到对或从对到错的转化过程，二是当性能下降时，斜率指标反而可能给出高分，产生误导。本文切入点在于构建一个对样本级状态变化敏感、且能统计稳定地量化负向扩展惩罚的评估框架。

## 核心方法

### 方法参照系

本文问题属于 TTS 评估指标设计，最接近的通用流程是基于扩展曲线（Scaling Curve）的斜率计算。该流程通常绘制准确率随 Token 消耗变化的曲线，并计算平均梯度作为效率指标。本文与通用流程的关键差异在于：将评估粒度从“全局曲线”下沉至“单个样本的相邻迭代对”，并引入动态采样以解决高温度采样带来的测量方差问题。

### 样本级轨迹追踪与负向扩展惩罚

传统斜率指标在性能下降时失效，是因为其未区分“算力增加导致正确率提升”与“算力增加导致正确率下降”两种截然不同的物理过程。ARISE 通过追踪每个样本在相邻扩展迭代 $j-1$ 和 $j$ 之间的准确率变化 $\Delta a_{[i][j]} = a_{[i][j]} - a_{[i][j-1]}$，并引入非对称权重函数 $W_{[i][j]}$ 来量化效率：

$$
\text{ARISE}_i = \sum_{j=1}^{J} \text{sign}(\Delta a_{[i][j]}) \cdot \frac{|\Delta a_{[i][j]}|}{\log(t_{[i][j]}) - \log(t_{[i][j-1]})}
$$

其中 $t_{[i][j]}$ 为第 $j$ 次迭代的 Token 消耗。该公式的物理含义是：当准确率提升时，奖励与 Token 对数增量成反比，即“用更少算力做对”获得更高奖励；当准确率下降时，符号函数取 -1，惩罚项同样与 Token 对数增量相关，且由于负向扩展通常伴随算力浪费，惩罚力度会随 Token 消耗增加而放大。这种设计直接解决了斜率指标在负向扩展时“越浪费越高分”的病理行为，使指标能够真实反映模型在算力增加时的净收益。

### 基于方差的动态采样机制

高温度采样导致准确率和 Token 消耗存在显著随机波动，固定次数的评估会产生不稳定的指标值。ARISE 引入动态采样机制，通过监测每个样本-迭代组合的变异系数（Coefficient of Variation, CV）来自适应分配评估算力。设 $m_{min}$ 为初始探测次数，$m_{max}$ 为最大采样次数，收敛阈值 $\tau$ 为 0.5。采样过程持续进行，直到 CV 低于 $\tau$ 或达到 $m_{max}$：

$$
CV_{[i][j]} = \frac{\sigma_a}{\mu_a} + \frac{\sigma_t}{\mu_t + \epsilon}
$$

其中 $\sigma_a, \mu_a$ 和 $\sigma_t, \mu_t$ 分别为准确率和 Token 消耗的统计量。该机制的设计动机是解决固定预算下“稳定样本浪费算力、不稳定样本采样不足”的资源错配问题。通过优先为高方差样本分配额外采样，ARISE 在相同总预算下实现了比朴素多次采样更高的方差降低率，确保了跨模型比较的统计可靠性。

## 实验评估

实验覆盖数学（AIME, HMMT）、科学（GPQA-Diamond, MMLU-Pro）、代码（SWE-bench, LiveCodeBench）及智能体任务，对比基线为 Muennighoff et al. (2025) 的斜率指标（Scaling Metric, SM）。

| 模型 | AIME ARISE | AIME SM×1000 | GPQA-Diamond ARISE | GPQA-Diamond SM×1000 |
|---|---|---|---|---|
| Claude Opus 4.1 | 0.4529 | 0.1462 | 0.4454 | 0.1416 |
| Qwen3-235B-A22B | 0.3915 | 0.0819 | 0.4069 | 0.0762 |
| GPT-5 | 0.1566 | 0.0259 | 0.2185 | 0.0263 |
| DeepSeek-R1 | -0.0318 | 0.0072 | -0.0493 | 0.0033 |

ARISE 在区分模型扩展能力上显著优于 SM：Claude Opus 4.1 在 AIME 上的 ARISE 分数（0.4529）约为 SM（0.1462）的 3 倍，而 DeepSeek-R1 的 ARISE 为负值（-0.0318），SM 却为正值（0.0072），揭示了 SM 对负向扩展的盲视。

消融实验显示，动态采样机制对稳定性提升至关重要。在固定预算下，自适应采样相比朴素多次采样，方差降低率从 31.4% 提升至 57.5%；在全自适应模式下，ARISE 的方差降低率达 76.1%，远超 SM 的 54.2%。这表明样本级追踪与方差感知采样的结合，是 ARISE 稳定性的核心来源。

评估边界方面，ARISE 分数与最终任务准确率（如 AIME 94.5%）无直接线性映射，仅反映扩展效率。论文未提供代码，但超参数（$m_{min}=3, m_{max}=10, \tau=0.5$）已公开，可复现性主要受限于各模型 API 的采样温度设置一致性。

## 关联研究分析

从问题动机看，ARISE 与 DeepPrune 等关注 Token 冗余的方法形成互补。DeepPrune 旨在通过剪枝减少无效计算以提升推理效率，而 ARISE 旨在量化这种效率提升的“质量”。DeepPrune 假设“剪枝后准确率不变”，而 ARISE 通过样本级追踪能检测出剪枝是否导致部分样本从对变错，从而提供更严格的效率评估。这种差异源于任务特性：推理加速方法关注吞吐量，而评估指标关注准确率-成本权衡的净效应。

从方法设计看，ARISE 与 Self-Consistency 等并行采样策略存在潜在冲突。Self-Consistency 依赖多数投票聚合，其隐含假设是“多数答案更可能正确”，但 ARISE 的负向扩展惩罚机制表明，增加采样次数可能导致原本正确的答案被错误多数票覆盖。ARISE 未直接对比 Self-Consistency 在不同采样次数下的 ARISE 分数变化，仅将其作为隐含的方差来源。查询侧增强在数据充足时是否仍有增益，论文未给出回答，这限制了 ARISE 对特定聚合策略有效性的直接评估能力。

## 总结

本文核心矛盾在于 TTS 评估指标无法区分“有效扩展”与“算力浪费”，且对负向扩展不敏感。ARISE 通过样本级轨迹追踪与动态采样，首次实现了对负向扩展的量化惩罚，证明了其在多模型上的区分度（如 Claude Opus 4.1 ARISE 0.4529 vs DeepSeek-R1 -0.0318）。其边界在于：ARISE 分数仅反映扩展效率，未建立与最终任务准确率的直接映射，且动态采样机制可能引入对高方差样本的过度关注，导致对低方差但稳定错误模型的评估偏差。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
