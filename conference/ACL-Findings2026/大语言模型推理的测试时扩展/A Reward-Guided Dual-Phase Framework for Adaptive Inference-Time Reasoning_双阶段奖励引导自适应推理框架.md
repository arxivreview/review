# ACL-Findings2026最新论文 ｜A Reward-Guided Dual-Phase Framework for Adaptive Inference-Time Reasoning ｜双阶段奖励引导自适应推理框架

研究机构：美国密歇根州立大学、美国宾夕法尼亚州立大学

作者：Yingqian Cui、Zhenwei Dai、Pengfei He 等 12 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_45e989c92b7a)

> 测试时扩展（Test-Time Scaling, TTS）旨在通过增加推理阶段计算量提升大语言模型（LLM）的复杂任务表现，但现有基于过程奖励模型（Process Reward Model, PRM）的树搜索方法通常将规划与执行视为单一节点，导致资源分配与错误传播特性不匹配。本文指出规划步骤的不确定性与执行步骤的错误致命性存在本质差异，统一搜索策略在此结构下效率次优。DREAM 框架将推理显式解耦为规划与执行两个独立搜索阶段，并引入基于实时奖励反馈的动态预算分配机制，在数学与代码生成任务上实现了准确率与计算效率的双重优化。该框架在中等规模骨干模型上验证了阶段解耦的有效性，但其对大规模强化学习训练模型的适用性及理论边界尚存疑。

## 研究背景

当 LLM 处理多步数学或代码任务时，推理过程天然包含高层策略制定（规划）与低层具体推导（执行）两个认知阶段。规划阶段负责确定子目标，其输出直接决定后续路径的可行性；执行阶段负责具体计算或代码实现，其错误会直接污染后续步骤的输入。这种结构差异意味着两个阶段对计算资源的敏感度不同：规划错误可能导致整条路径无效，而执行错误则具有累积性。

现有 TTS 方法主要沿两条路线演进：基于分布的采样（如 Self-Consistency）和基于奖励的搜索（如 RAP、rStar）。后者利用 PRM 对中间步骤评分以剪枝低质量候选，成为提升推理效率的主流范式。然而，这些方法普遍将“规划-执行”对视为一个原子节点进行统一评分和扩展，忽略了两个阶段在难度分布和错误后果上的异质性。这种统一处理导致简单规划步骤浪费预算，而关键执行步骤探索不足，尤其在长程推理中加剧了错误累积。

DREAM 的切入点在于识别并量化这种阶段异质性。通过初步探索发现，规划步骤的困惑度显著高于执行步骤，表明模型对规划更不确定；同时，执行步骤的错误比规划错误更难被后续步骤纠正。基于此，本文提出将搜索过程显式拆分为两个阶段，并针对每个阶段设计独立的奖励模型和预算分配策略，以解决统一搜索在异构认知结构下的效率瓶颈。

## 核心方法

### 双阶段束搜索架构

标准束搜索在每一步采样固定数量的候选，利用 PRM 评分后保留 Top-k 进行扩展。DREAM 的关键差异在于将每个推理步骤拆解为规划节点（红色）和执行节点（蓝色）两层。在规划阶段，采样 $N_1$ 个候选子目标，经规划奖励模型 $PRM_{plan}$ 评分后保留 $n_1$ 个；在执行阶段，基于选定的规划生成 $N_2$ 个具体推导，经执行奖励模型 $PRM_{exec}$ 评分后保留 $n_2$ 个。这种解耦允许在规划阶段早期剪除错误策略，同时为正确规划提供多次执行尝试，避免单一执行错误导致整条路径被丢弃。

### 动态预算分配机制

固定预算分配无法适应不同步骤的难度差异。DREAM 引入双阈值规则实现自适应采样。对于规划阶段，若已有 $n_1$ 个候选的奖励值超过高阈值 $\tau_{p1}$，则提前终止采样；若耗尽预算后无候选超过低阈值 $\tau_{p2}$，则追加 $m_1$ 个采样以深入探索困难步骤。执行阶段同理，使用 $\tau_{e1}$ 和 $\tau_{e2}$。该机制的核心公式为奖励函数：

$$
\text{Reward}(x) = \frac{\exp(\ell_+(x))}{\exp(\ell_+(x)) + \exp(\ell_-(x))}
$$

其中 $\ell_+(x)$ 和 $\ell_-(x)$ 是奖励模型预测“+”（正确）和“-”（错误）的 logits。该函数将二分类输出转化为概率值，作为动态预算分配的决策依据。通过实时监测奖励分布，DREAM 能在简单步骤上节省计算，在困难步骤上增加探索，从而优化整体准确率-效率权衡。

## 实验评估

实验在 GSM8K 和 MATH500 基准上进行，使用 LLaMA-3/3.1-8B-Instruct 和 Qwen-2.5-MATH-1.5B 作为推理模型，对比 Majority Vote、Beam Search 和 REBASE。DREAM 在 GSM8K 上达到 94.62% 准确率，显著优于 Majority Vote 的 87.34% 和 Beam Search 的 93.53%。在 MATH 数据集上，DREAM 同样展现出优于基线的准确率-效率前沿，特别是在高 token 预算下优势更为明显。

| 方法 | GSM8K Acc (%) | GSM8K Tokens | MATH Acc (%) | MATH Tokens |
| :--- | :--- | :--- | :--- | :--- |
| DREAM | 94.62 | 2442.21 | - | - |
| Beam Search | 93.53 | 2339.38 | - | - |
| REBASE | 93.86 | 2426.49 | - | - |
| Majority Vote | 87.34 | 2598.10 | - | - |

消融实验显示，动态预算分配（DREAM+）相比固定预算的 DREAM 进一步提升了效率。在 GSM8K 上，DREAM+ 使用更少的 token（1508.04）达到了与 DREAM 相近的准确率（93.86%），验证了自适应机制在减少冗余计算方面的有效性。此外，奖励模型的大小对性能有显著影响，32B 奖励模型在准确率-效率权衡上优于 7B 版本，表明更大的指令微调模型能更精准地捕捉步骤正确性的细微信号。

评估边界方面，实验主要聚焦于中等规模骨干模型（1.5B-8B），未与基于大规模强化学习训练的 SOTA 模型（如 PaCoRe、DeepSeek-R1）直接对比，限制了结论在大规模模型上的泛化性。此外，论文未提供代码开源链接，且动态预算的阈值 $\tau$ 设置依赖于具体数据集，缺乏跨数据集的通用性验证。

## 关联研究分析

从问题动机看，DREAM 与 SCALE 等自适应计算分配方法同属解决“固定预算低效”问题，但 SCALE 基于问题难度预测进行轨迹级分配，而 DREAM 基于实时奖励反馈进行步骤级分配。这一差异源于任务结构的认知：SCALE 假设难度在问题层面是静态的，而 DREAM 认为难度在推理步骤层面是动态变化的。DREAM 的细粒度控制更适合长程推理中难度波动大的场景，但其依赖实时奖励计算，引入了额外的前向传播开销，这在延迟敏感的实际部署中可能成为瓶颈。

从方法设计看，DREAM 与 REBASE 等树搜索方法共享 PRM 评分框架，但 DREAM 引入了阶段解耦。REBASE 将规划-执行视为单节点，其 PRM 评分反映的是整体步骤质量，无法区分是规划错误还是执行错误。DREAM 的双 PRM 设计使得搜索算法能更精准地定位错误来源：若规划奖励低，则回溯规划；若执行奖励低，则重试执行。这种设计在理论上提高了搜索的收敛速度，但在实践中依赖于 PRM 对两个阶段独立评分的准确性，若 PRM 存在校准偏差，可能导致错误的剪枝决策。

## 总结

DREAM 针对现有 TTS 方法中规划与执行统一处理导致的资源错配问题，提出了双阶段解耦搜索与动态预算分配框架。通过独立评估规划与执行步骤，并基于实时奖励反馈调整采样预算，DREAM 在 GSM8K 和 MATH 基准上实现了优于传统束搜索和 Majority Vote 的准确率-效率权衡。其核心贡献在于揭示了推理过程中认知阶段的异质性，并提供了相应的算法解决方案。然而，实验仅在中等规模骨干模型上进行，且动态预算的阈值设置缺乏跨数据集的通用性验证。当骨干模型规模扩大至 70B 以上时，DREAM 的搜索增益是否会被模型自身的隐式推理能力所抵消，论文未给出回答。
