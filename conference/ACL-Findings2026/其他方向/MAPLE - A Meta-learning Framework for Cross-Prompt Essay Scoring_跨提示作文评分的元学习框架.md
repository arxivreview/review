# ACL-Findings2026最新论文 ｜MAPLE: A Meta-learning Framework for Cross-Prompt Essay Scoring ｜跨提示作文评分的元学习框架

作者：Salam Albatarni、May Bashendy、Sohaila Eltanbouly 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_93aa3ef618b9)

> 跨提示自动作文评分（Cross-Prompt Automated Essay Scoring, CP-AES）旨在解决模型在未见写作提示下的泛化难题，传统端到端模型因提示分布偏移导致性能显著衰减。现有优化型元学习方法将提示视为同质任务，限制了任务多样性，而本文切入点在于利用原型网络的非参数特性，通过重构二元/多类任务并融合上下文门控机制，实现更鲁棒的跨域适应。MAPLE 在 ELLIPSE 和 LAILA 数据集上分别以 8.5 和 3 个 QWK 点的优势超越强基线，证明了元学习在低资源跨域场景的有效性，但其对分数范围不一致数据的处理局限仍存疑。

## 研究背景

当评分模型面对训练集中未出现的写作提示时，其依赖的语义表示往往因提示特定语境而失效，这一现象即跨提示泛化困境。为应对此问题，元学习（Meta-Learning）范式被引入，其核心逻辑是通过在多个任务上训练“如何学习”的能力，使模型仅凭少量支持样本即可快速适应新任务。原型网络（Prototypical Networks）作为元学习的经典非参数方法，通过计算各类别支持样本的特征均值作为原型，利用距离度量完成分类，避免了参数更新带来的过拟合风险，天然适合少样本场景。

跨提示 AES 的主流路线长期依赖特征工程与监督学习，如 ProTACT 和 MOOSE 等模型虽提升了精度，但需大量标注数据且难以应对提示剧烈变化。2024 年以来，优化型元学习方法如 PLAES 和 MLCAES 开始探索，但它们将每个提示视为独立的同质任务，导致任务数量受限于源提示数量，无法充分利用元学习在异构任务上的泛化优势。MAPLE 的切入点正是打破这一限制，通过引入特质（Trait）和分数分布维度重构任务定义，并结合提示与量规的上下文信息，构建更具多样性的元训练任务集，以解决传统方法在提示分布偏移下的性能瓶颈。

## 核心方法

### 原型网络基线与任务重构

MAPLE 基于原型网络构建，其核心在于通过嵌入空间中的距离度量实现评分。与直接回归分数不同，该方法将评分转化为分类问题，利用支持集计算各类别原型，再通过查询样本与原型的距离预测分数。这种非参数设计避免了优化型元学习中对参数梯度的依赖，更适合跨提示场景下的快速适应。

### 二元与多类任务生成策略

为突破提示数量限制，MAPLE 提出两种任务生成策略。二元分类任务将评分重构为“特定分数水平”与“其他分数水平”的二分问题，任务由提示 $p$、特质 $r$ 和分数水平 $l^*$ 定义。这种设计极大增加了任务多样性，因为每个提示-特质组合可生成多个二元任务。多类分类任务则保留原始评分结构，任务由提示 $p$ 和特质 $r$ 定义，支持集包含该特质所有分数水平的样本。两种策略均确保支持集与查询集来自不同提示，严格满足跨提示条件。

$$
c^* = \frac{1}{k} \sum_{y_s^j = c} f_\theta(x_s^j)
$$

该公式计算类别 $c$ 的原型，即支持集中属于该类别的 $k$ 个样本嵌入的均值，作为该分数水平的代表点。

### 上下文门控融合机制

为解决不同特质共享同一作文表示导致的瓶颈，MAPLE 引入门控机制融合提示 $p$、量规 $r$ 和手工特征 $u(x)$。首先，预训练编码器 $f$ 分别提取提示、量规和作文的表示，并与作文嵌入 $f_\theta(x)$ 拼接为联合向量 $z$。随后，通过可学习矩阵 $W_z$ 和 Sigmoid 函数生成门控向量 $g$，对 $z$ 进行逐元素加权，最后经投影层得到最终表示 $h'$。

$$
h = z \odot \sigma(W_z z)
$$

该公式通过门控向量 $g$ 自适应地加权提示、量规和作文特征，使模型能根据当前任务动态调整上下文信息的贡献度，从而区分不同特质下的评分逻辑。

## 实验评估

实验在 ELLIPSE（英语，44 提示，7 特质）、ASAP（英语，8 提示，分数范围不一）和 LAILA（阿拉伯语，7 特质）三个数据集上进行，采用 QWK 作为主要指标。基线覆盖特征工程模型、传统神经评分模型及 LLM 少样本提示方法（如 GPT-4o/4.1），但缺乏对优化型元学习基线（如 PLAES）的直接对比，这可能影响对元学习路线优势的全面评估。

| 数据集 | 方法 | QWK |
| :--- | :--- | :--- |
| ELLIPSE | MAPLE | 0.85+ |
| LAILA | MAPLE | 0.86+ |
| ASAP | MAPLE | 改进（部分特质） |

MAPLE 在 ELLIPSE 和 LAILA 上分别以 8.5 和 3 个 QWK 点的优势超越最强基线，验证了任务重构与门控机制的有效性。在 ASAP 上，由于提示间分数范围不一致导致支持集缺失某些分数水平，MAPLE 仅在分数范围统一的特质上取得改进，暴露了其对数据分布一致性的依赖。

消融实验显示，二元任务生成策略在多类任务基础上进一步提升了 QWK，证实了任务多样性对泛化的贡献。门控机制的引入相比简单拼接提升了约 1-2 个 QWK 点，表明上下文信息的自适应融合优于静态融合。手工特征的加入在阿拉伯语数据上收益更显著，可能源于低资源语言中语义表示的不足。

评估边界方面，QWK 指标仅衡量分数一致性，未评估反馈的教学价值或可解释性。MAPLE 提供的是距离度量的解释，而非自然语言反馈，这与当前 LLM 评分的主流趋势存在差异。代码已开源，超参数包括 5-shot 设置、30K 元训练任务及 4 块 A10 GPU，可复现性较好，但未报告计算成本与 LLM 基线的对比。

## 关联研究分析

从问题动机看，MAPLE 与 AutoSCORE 等 LLM 多智能体框架形成鲜明对比。AutoSCORE 依赖大模型强大的语义理解与生成能力，通过多智能体协作实现评分与反馈的联合优化，适合数据充足且计算资源丰富的场景。而 MAPLE 聚焦于数据稀缺与提示分布偏移的极端条件，利用小模型（RoBERTa/AraBERT）与元学习机制，在计算成本上具有显著优势。这种差异源于任务特性：跨提示场景下，LLM 的零样本能力受提示敏感性制约，而元学习通过显式任务结构学习，提供了更稳定的适应路径。

从方法设计看，MAPLE 与 GUIDE 等提示优化框架解决同一问题但路径不同。GUIDE 通过迭代优化提示中的示例来增强 LLM 的上下文学习能力，本质上是对输入端的调整；而 MAPLE 通过重构任务结构与融合上下文特征，是对模型内部表示学习的调整。GUIDE 依赖 LLM 的内在能力，而 MAPLE 依赖元学习的泛化能力。在低资源场景下，MAPLE 的非参数原型计算避免了 LLM 对提示微小变化的敏感性，但其缺乏自然语言反馈生成能力，限制了其在教学场景中的应用广度。

## 总结

MAPLE 旨在解决跨提示 AES 中因提示分布偏移导致的泛化难题，其切入点在于利用原型网络的非参数特性，通过重构二元/多类任务增加多样性，并融合提示与量规上下文信息。该方法在 ELLIPSE 和 LAILA 数据集上分别以 8.5 和 3 个 QWK 点的优势超越强基线，证明了元学习在低资源跨域场景的有效性。然而，其在 ASAP 数据集上仅对分数范围统一的特质取得改进，暴露了对数据分布一致性的依赖。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
