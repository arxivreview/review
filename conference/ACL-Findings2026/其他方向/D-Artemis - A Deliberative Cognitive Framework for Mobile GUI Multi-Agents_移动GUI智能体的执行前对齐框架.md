# ACL-Findings2026最新论文 ｜D-Artemis: A Deliberative Cognitive Framework for Mobile GUI Multi-Agents ｜移动GUI智能体的执行前对齐框架

研究机构：天津大学、香港中文大学

作者：Hongze Mi、Yibo Feng、Wenjie Lu 等 15 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.21799)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.21799)

> 移动GUI智能体在长程任务中面临单步错误导致轨迹偏离的累积效应，现有框架多依赖执行后反思，无法在动作生效前拦截失效。D-Artemis通过引入执行前对齐阶段，在动作执行前校验思维与动作的一致性并主动修正，解决了延迟检测带来的高恢复成本。该框架无需大规模轨迹数据训练，仅通过轻量级模块增强通用多模态大语言模型（MLLM）的GUI操作能力。其在AndroidWorld上取得75.8%的成功率，但相比在线强化学习（RL）方法仍存差距，且未验证极端分布外场景下的泛化边界。

## 研究背景

GUI智能体通过像素级截图理解并操作数字设备，其核心挑战在于部分可观测环境中的状态追踪。当智能体执行多步任务时，单步定位错误或逻辑偏差会引发后续轨迹偏离，这种错误累积效应使得仅依赖当前屏幕状态的决策机制难以维持长程任务的稳定性。为应对此问题，智能体需具备历史感知与自我纠错能力，但现有方法多将纠错置于执行后，导致错误动作已改变环境状态，恢复成本高昂。

视觉感知GUI智能体的主流路线分为框架增强与端到端训练两类。框架方法通过多智能体协作与记忆模块提升推理能力，如Mobile-Agent-v2引入记忆模块解决上下文丢失，但其反思机制滞后于动作执行；端到端方法如UI-TARS依赖大规模监督微调（SFT）与RL优化决策，但受限于轨迹数据多样性不足，跨应用泛化能力受限。D-Artemis的切入点在于将纠错时机前移至执行前，通过主动对齐机制在动作生效前拦截错误，同时避免通用提示在不同应用间产生逻辑冲突，从而在不依赖大规模轨迹训练的前提下提升通用模型的GUI操作鲁棒性。

## 核心方法

### 方法参照系

D-Artemis属于多智能体协作框架，其标准流程包含规划、执行与反思三阶段。与Mobile-Agent-v2等现有框架的关键差异在于，本文将反思阶段拆分为执行前对齐与执行后反思两个独立环节，并在执行前引入一致性校验与主动修正机制，改变了传统“执行-观察-修正”的被动响应模式。

### 执行前对齐机制

执行前对齐阶段由思维-动作一致性（TAC）检查模块与动作修正智能体（ACA）协同完成。TAC模块基于Qwen2.5-VL-7B微调，对思维-动作对进行二分类，判断动作是否与思维逻辑一致且视觉定位准确。其决策函数定义为：

$$
\hat{y} = \mathbb{1}[\text{Consistency}(\text{Thought}, \text{Action}, \text{Screenshot}) > \tau]
$$

其中 $\hat{y}=1$ 表示动作有效，$\tau$ 为分类阈值。当 $\hat{y}=0$ 时，触发ACA对错误动作进行诊断与修正。该设计解决了执行后反思无法阻止错误状态转移的问题，将错误拦截在环境状态改变之前。TAC模块的推理延迟仅为380ms，以轻量级计算换取高安全性，确保对齐过程不显著增加单步耗时。

### 应用特定提示检索与执行后反思

为消除通用提示在不同应用间的逻辑冲突，D-Artemis采用应用特定提示检索机制，从知识库中获取当前应用的操作性指导。该机制通过匹配应用名称与任务类型，检索细粒度提示，避免跨应用提示引入矛盾指令。执行后，状态反思智能体（SRA）评估动作结果并生成战略指导，其反馈不仅包含成功/失败判断，还包含环境状态变化与下一步建议，形成闭环学习。SRA的贡献在完整框架中达到15.9%的性能增益，显著高于基线模型中的3.8%，表明执行前对齐与执行后反思存在协同效应。

## 实验评估

实验在AndroidWorld（116个动态任务）与ScreenSpot-V2（1272个定位任务）上进行，基线覆盖通用模型（Qwen2.5-VL-72B）、GUI专用模型（UI-TARS、Mobile-Agent-v3）及RL方法（UI-Venus）。D-Artemis在AndroidWorld上取得75.8%成功率，高于Mobile-Agent-v3的73.3%；在ScreenSpot-V2上取得96.8%平均准确率，超越UI-Venus-Ground-72B。

| 基准 | 方法 | 模型 | 成功率 (%) |
| :--- | :--- | :--- | :--- |
| AndroidWorld | D-Artemis | GUI-Owl-32B | 75.8 |
| AndroidWorld | Mobile-Agent-v3 | GUI-Owl-32B | 73.3 |
| AndroidWorld | UI-Venus | Qwen2.5-VL-72B-Instruct | 65.9 |
| ScreenSpot-V2 | D-Artemis | Qwen2.5-VL-72B | 96.8 |
| ScreenSpot-V2 | UI-TARS-72B | Qwen2.5-VL-72B | 91.2 |

消融实验显示，移除执行前对齐导致AndroidWorld成功率从68.1%降至44.0%，降幅达24.1个百分点，表明该机制是性能提升的核心来源。TAC模块单独贡献22.4%增益，ACA贡献8.6%，提示检索贡献6.9%。TAC模块在450个测试样本上取得90.97%准确率，对有效动作的召回率达98.85%，确保不误拦截正确操作。

评估边界方面，论文未报告置信区间，且未对比在线RL方法（如MobileRL）的直接性能差异。代码未开源，但提供了完整超参数配置（DeepSpeed ZeRO-3，BF16精度，16 GPU）。ScreenSpot-V2仅使用移动端子集，未验证桌面端泛化能力。

## 关联研究分析

从错误处理时机看，D-Artemis与Mobile-Agent-v2形成鲜明对比。Mobile-Agent-v2依赖执行后反思，错误动作已改变环境状态，恢复需回溯多步；D-Artemis通过TAC在执行前拦截，将错误恢复成本从“多步回溯”降至“单步修正”。这一差异源于任务特性：GUI环境状态转移不可逆，执行前拦截在理论上具有更低的恢复开销，但论文未量化执行前对齐在极端错误（如思维本身错误）下的失效率。

从训练范式看，D-Artemis与UI-TARS代表两种路线。UI-TARS依赖大规模SFT与RL，通过数据驱动提升模型内在能力；D-Artemis通过框架增强提升通用模型的外在表现，无需轨迹数据训练。D-Artemis在ScreenSpot-V2上超越UI-TARS-72B（96.8% vs 91.2%），表明框架增强在定位精度上有效；但在AndroidWorld上，D-Artemis（75.8%）低于MobileRL（80.2%，据领域综述），暗示框架增强在动态适应性上可能受限于骨干模型的内在能力，而非框架本身。

## 总结

D-Artemis解决的核心矛盾是GUI智能体长程任务中错误累积与恢复成本高昂的问题。其切入点在于将纠错时机前移至执行前，通过TAC模块在动作生效前拦截错误，避免了执行后反思的状态不可逆性。该框架通过应用特定提示检索与执行后反思形成闭环，在无需大规模轨迹训练的情况下，使通用MLLM在AndroidWorld上取得75.8%成功率，在ScreenSpot-V2上取得96.8%准确率。其边界在于：TAC模块仅校验思维-动作一致性，无法纠正思维本身的逻辑错误；且框架增强在动态环境中的性能仍低于在线RL方法，表明其泛化能力可能受限于骨干模型的内在能力。当骨干模型在分布外场景下的思维质量下降时，执行前对齐的拦截率是否随之降低，论文未给出回答。
