论文原文见 [arXiv](https://arxiv.org/abs/2604.27974)

> 现有 GUI 定位基准仅验证“点击是否命中控件”，忽略了点击后界面状态是否精确达成目标值，导致模型在滑块调节、日期选择等连续交互任务中看似成功实则失效。本文切入点在于将定位任务解耦为“控件定位”与“操作核心命中”两个独立阶段，并引入精确目标状态标签进行验证。通过构建包含双区域标注的静态基准与阶段式诊断指标，量化了视觉定位误差对最终状态达成的可恢复增益。该工作揭示了当前 SOTA 模型在细粒度状态控制上的巨大盲区，但其单步静态协议是否足以反映动态交互中的状态漂移，仍存疑。

## 研究背景

GUI 智能体执行原子操作时，常面临“定位正确但状态错误”的困境。例如，指令要求将滑块调整至 74%，模型可能准确点击了滑块控件（Locate 成功），但点击点未落在对应数值的核心区域（Interact 失败），导致最终状态偏离目标。这一现象源于传统评估协议将“控件边界框”作为唯一成功标准，未区分控件的可见范围与触发状态变化的可交互核心区域。

主流 GUI 定位研究（如 ScreenSpot、SeeClick）确立了纯视觉驱动的坐标预测范式，其核心假设是“命中边界框即完成定位”。然而，在高分辨率专业软件或密集布局中，控件边界往往包含非交互区域（如滑块轨道的空白部分），仅命中边界无法保证状态精确设置。现有基准缺乏对目标状态的显式定义与验证机制，导致无法区分“定位失败”与“操作精度不足”两类错误，使得模型在连续控件上的性能被高估。

本文针对这一评估盲区，提出 FineState-Bench，一个专注于单步、细粒度状态条件化 GUI 状态设置的跨平台基准。其核心贡献不在于提出新的定位模型，而在于重新定义评估协议：通过双区域标注（Locate Box 与 Interact Box）和精确目标状态标签，将定位任务分解为可诊断的阶段，从而揭示现有模型在“从粗粒度定位到细粒度操作”这一关键过渡中的性能瓶颈。

## 核心方法

### 方法参照系

标准 GUI 定位流程为：输入截图 $I$ 与指令 $T$，预测目标控件的边界框 $B$ 或中心点 $P$，成功标准定义为 $P \in B$。本文的关键差异在于，将单一边界框 $B$ 解耦为两个嵌套区域：覆盖控件可见范围的定位框 $B_{loc}$ 和触发状态变化的可交互核心框 $B_{int}$，并引入目标状态 $s_{goal}$ 作为最终验证条件。

### 双区域标注与阶段式诊断

传统方法将定位成功定义为预测点 $p$ 落入控件边界框 $B$，即 $I(p \in B)$。本文指出，对于滑块、旋钮等连续控件，$B$ 往往远大于实际改变状态的核心区域，导致 $p \in B$ 但状态未达标的假阳性。为此，本文定义实例 $\tau = (x, I_0, I_1, c^*, s_{goal}, B_{loc}^{[0]}, B_{int}^{[0]}, B_{loc}^{[1]}, B_{int}^{[1]})$，其中 $B_{loc}$ 覆盖控件当前可见范围，$B_{int}$ 标记操作相关核心区域。预测点 $p_0$ 对应定位指令 $I_0$，$p_1$ 对应操作指令 $I_1$。阶段式成功指标定义为：

$$
SR@Loc = \frac{1}{N} \sum_{i=1}^{N} I(p_0^{(i)} \in B_{loc}^{[0](i)} \lor p_0^{(i)} \in B_{loc}^{[1](i)})
$$

$$
SR@Int = \frac{1}{N} \sum_{i=1}^{N} I(p_1^{(i)} \in B_{int}^{[0](i)} \lor p_1^{(i)} \in B_{int}^{[1](i)})
$$

该设计将“找到控件”与“找到操作点”分离，使得 $SR@Loc \gg SR@Int$ 的现象可被量化，直接暴露了模型在可交互核心定位上的精度不足。

### 视觉诊断助手（VDA）

为量化视觉定位误差对最终状态达成的贡献，本文引入 VDA 作为诊断工具。VDA 基于 GPT-4o，执行“描述-定位”两步流程：首先生成目标控件的结构化描述 $d$，再预测定位提示框 $\hat{B}_1$。在评估时，将 $\hat{B}_1$ 作为额外输入注入待测模型，保持模型参数与解码策略不变。视觉定位瓶颈的量化指标定义为：

$$
\Delta_{vis} = ES\text{-}SR@Int(w/ \text{VDA}) - ES\text{-}SR@Int(w/o \text{VDA})
$$

该公式的物理含义是：在提供精确视觉提示后，模型性能的提升幅度直接反映了原始预测中因视觉定位不准而导致的可恢复错误比例。若 $\Delta_{vis}$ 较大，说明模型具备状态设置能力，但受限于视觉感知精度；若 $\Delta_{vis}$ 较小，则说明模型缺乏状态理解或操作逻辑能力。

## 实验评估

实验在 FineState-Bench 的 2,209 个实例上进行，覆盖桌面、Web 和移动平台。基线包括 3 个闭源 LVLM（GPT-4o, Claude-3.5-Sonnet, Gemini-2.5-Flash）和 5 个开源 GUI 专用模型（OS-Atlas-7B, CogAgent-9B, UGround-7B, Jedi-7B-1080p, ShowUI-2B）。值得注意的是，基线未包含 2025-2026 年最新的 SOTA 模型（如 GUI-AIMA-3B, UI-Ins-32B），这可能因这些模型未适配本文的双区域标注协议或单步点预测接口。

| 模型 | Mobile (ES-SR@Int) | Web (ES-SR@Int) | Desktop (ES-SR@Int) | AVG (ES-SR@Int) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-4o | 6.2 | 4.5 | 2.2 | 4.3 |
| Gemini-2.5-Flash | 17.6 | 11.8 | 0.7 | 10.0 |
| UGround-7B | 19.6 | 32.8 | 16.0 | 22.8 |
| OS-Atlas-7B | 12.8 | 7.5 | 9.8 | 10.0 |

最强模型 UGround-7B 的平均 ES-SR@Int 仅为 22.8%，远低于其在 ScreenSpot-v2 上 80%+ 的定位准确率，证实了“定位正确”与“状态正确”之间存在巨大鸿沟。Gemini-2.5-Flash 在桌面平台表现极差（0.7%），而在移动平台相对较好（17.6%），表明平台布局差异对细粒度状态设置的影响显著。

| VDA 配置 (Gemini-2.5-Flash) | Mobile | Web | Desktop |
| :--- | :--- | :--- | :--- |
| w/o VDA | 17.6 | 11.8 | 0.7 |
| w/ Localization Hint | 26.1 | 24.7 | 13.1 |
| w/ Description + Hint | 29.8 | 27.2 | 15.4 |

消融实验显示，仅提供描述（w/ Description, w/o Hint）几乎无增益，而提供定位提示（w/ Hint）带来显著提升，平均增益达 14.9%（Web 平台）。这表明视觉定位精度是主要瓶颈，而非语义理解或状态逻辑。然而，即使加入 VDA，ES-SR@Int 仍低于 30%，说明模型在精确操作核心定位上仍存在根本性缺陷。

评估协议局限在于仅采用静态单步设置，未模拟动态交互中的状态漂移。代码已开源，但双区域标注依赖人工验证，可能存在主观偏差。未报告计算效率指标，VDA 引入额外推理延迟，实际部署成本需进一步评估。

## 关联研究分析

从问题动机看，ScreenSpot-Pro 聚焦高分辨率下的定位精度，而 FineState-Bench 聚焦定位后的状态达成精度。ScreenSpot-Pro 的 SOTA 模型（如 GUI-AIMA-3B）在定位任务上表现优异，但若应用于 FineState-Bench，其“命中边界框”的成功标准将导致大量假阳性。这揭示了现有 SOTA 模型在连续控件操作上的潜在失效：它们可能擅长“找到滑块”，但不擅长“找到滑块上对应 74% 的精确点”。

从方法设计看，GUI-Spotlight 通过迭代裁剪提升定位精度，属于“感知增强”路线；而 FineState-Bench 通过双区域标注和 VDA 进行“诊断归因”，属于“评估增强”路线。GUI-Spotlight 假设定位精度是主要瓶颈，通过扩大视野解决小目标混淆；FineState-Bench 则证明，即使定位到控件，操作核心定位仍是独立瓶颈。两者互补：GUI-Spotlight 可提升 $SR@Loc$，而 FineState-Bench 的指标可量化 $SR@Int$ 的剩余缺口。SafeGround 通过不确定性量化识别高风险操作，与 VDA 的 $\Delta_{vis}$ 指标异曲同工，但 SafeGround 关注预测置信度，VDA 关注视觉定位误差的可恢复性。

## 总结

本文核心矛盾在于现有 GUI 定位基准无法区分“定位失败”与“操作精度不足”，导致模型在细粒度状态设置任务中的真实能力被高估。切入点在于将定位任务解耦为“控件定位”与“操作核心命中”两个阶段，并引入精确目标状态标签进行验证。通过构建 FineState-Bench 与阶段式诊断指标，证明了当前 SOTA 模型在可交互核心定位上存在巨大盲区，最强模型 UGround-7B 的 ES-SR@Int 仅为 22.8%。本文边界在于单步静态协议未覆盖动态交互中的状态漂移，且基线未包含最新 SOTA 模型。当模型在 $SR@Loc$ 上已接近饱和时，$SR@Int$ 的剩余缺口是否可通过视觉 Token 压缩或注意力对齐策略进一步缩小，论文未给出回答。
