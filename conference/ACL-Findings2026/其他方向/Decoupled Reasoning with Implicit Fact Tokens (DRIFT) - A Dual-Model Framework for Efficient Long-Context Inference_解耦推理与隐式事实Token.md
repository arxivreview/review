# ACL-Findings2026最新论文 ｜Decoupled Reasoning with Implicit Fact Tokens (DRIFT): A Dual-Model Framework for Efficient Long-Context Inference ｜解耦推理与隐式事实Token

研究机构：复旦大学、同济大学

作者：Wenxuan Xie、Yujia Wang、Xin Tan 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.10021)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.10021)

> 长上下文推理面临计算复杂度与有效信息利用率的双重瓶颈，现有静态压缩方法在极端压缩比下易丢失任务关键信息，而参数化知识编辑又面临灾难性遗忘风险。DRIFT 通过双模型架构将知识提取与核心推理解耦，利用轻量级知识模型将文档压缩为查询感知的隐式事实Token，再投影至推理模型嵌入空间。该设计在保持推理模型参数冻结的前提下实现了32倍压缩比下的性能提升，但其对大规模模型扩展性及隐式表示的可解释性边界尚存疑。

## 研究背景

Transformer 自注意力的二次方复杂度导致长文本推理延迟激增，且模型存在“中间迷失”现象，即对序列中部信息利用率显著下降。为缓解此问题，上下文压缩技术旨在精简输入序列，但硬压缩（如 LLMLingua-2）通过剔除冗余 Token 虽保留了人类可读性，却易造成指代悬空与逻辑链断裂；软压缩（如 ICAE）将上下文映射为连续向量，虽实现了高压缩比与语义平滑，但早期方法多为静态、查询无关的通用压缩，在极端压缩比下常丢失特定任务的关键语义。

当前领域共识认为，任务感知或查询条件化的压缩策略优于通用压缩，能更精准地保留任务相关语义。然而，现有软压缩方法多采用单模型端到端训练，压缩与推理任务耦合紧密，导致单一模型难以同时兼顾高保真压缩与复杂推理，尤其在面对长程智能体或知识密集型任务时，静态压缩无法应对动态上下文累积。DRIFT 的切入点在于将“知识阅读”与“逻辑推理”显式分离，通过双模型协作解决单模型在极端压缩比下的性能退化问题，并引入动态压缩机制以适配查询特异性。

## 核心方法

### 双模型解耦架构参照系

DRIFT 属于软提示压缩路线，其标准流程参照 ICAE 等自编码器架构，但关键差异在于将压缩器与解码器解耦为两个独立模型。传统单模型架构中，压缩与推理共享参数，导致在极端压缩比下，模型需同时优化信息保留与逻辑生成，易产生梯度冲突。DRIFT 引入轻量级知识模型 $\psi_{kno}$ 负责提取查询相关信息，大型推理模型 $\theta_{rea}$ 负责基于压缩表示进行推理，二者通过 MLP 投影层在潜在空间交互，从而将冗余背景知识的处理负担从推理模型中剥离。

### 分桶压缩策略

固定比率压缩假设信息均匀分布，但在实际文档中，关键证据往往稀疏分布，导致均匀压缩丢失核心语义。DRIFT 提出分桶压缩（Bucketed Compression），将输入 Token 长度映射至预定义的区间桶（如 64-128, 128-256），并基于区间上界确定输出 Token 数量。该策略打破了输出长度与输入长度的线性比例关系，允许模型根据信息密度动态调整压缩粒度。其数学表达为：

$$
\xi = b(n)
$$

其中 $b(n)$ 为包含 $n$ 个 Token 的桶的上界。这一设计迫使模型在编码前识别并抽象核心内容，而非机械地按比率截断，从而在稀疏证据场景下提升了语义保真度。

### 查询感知动态压缩训练

静态压缩无法区分不同查询下的关键信息，导致在特定任务上性能下降。DRIFT 通过三阶段训练实现查询感知动态压缩：第一阶段 LFRP（潜在事实重建预训练）使用静态压缩指令，以重建损失训练知识模型生成高保真潜在表示；第二阶段 QAFT-DC（查询感知微调-动态压缩）引入查询 $Q$，以证据 $X_{evi}$ 为监督信号，训练知识模型提取查询相关子集；第三阶段 QAFT-QA 解冻推理模型，基于压缩嵌入生成答案。动态压缩的核心损失函数为：

$$
\mathcal{L}_{QAFT-QA} = -\sum_{l=1}^{L} \log P(a_l | E_{dyn}, E(Q), a_{<l}; \theta_{rea})
$$

其中 $E_{dyn}$ 为查询感知的隐式事实嵌入。该机制利用证据的稀疏性，使动态压缩比（默认32倍）远高于静态压缩比（8倍），同时通过证据监督确保压缩表示仅保留对回答至关重要的信息，解决了静态压缩在极端比率下的信息丢失问题。

## 实验评估

DRIFT 在 BAMBOO、L-Eval、LongBench-v2 及 LoCoMo 等长上下文基准上进行评估，基线涵盖硬压缩（LLMLingua-2）、软压缩（ICAE, COCOM, xRAG）及朴素 RAG。实验设置中，知识模型固定为 Qwen2.5-Instruct-3B，推理模型默认使用 Mistral-7B-Instruct-v0.2。

| 方法 | 压缩比 | BAMBOO (Avg) | LongBench-v2 (Avg) | LoCoMo (Avg) |
| :--- | :--- | :--- | :--- | :--- |
| LLMLingua-2 | 3× | 57.89 | 20.68 | 22.86 |
| ICAE | 4× | 20.30 | 25.00 | 25.58 |
| COCOM | 4× | 42.11 | 27.04 | 27.43 |
| xRAG | 128× | 43.86 | 25.00 | 27.43 |
| **DRIFT** | **32×** | **60.15** | **29.22** | **57.73** |
| **DRIFT** | **128×** | **56.89** | **26.24** | **26.44** |

在同等 Mistral-7B 骨干下，DRIFT 在 32 倍压缩比时，LongBench-v2 准确率达 29.22%，较基线 Mistral-7B 的 20.87% 提升 8.35 个百分点，且显著优于 ICAE 与 COCOM。值得注意的是，DRIFT 在 128 倍极端压缩比下仍保持 26.24% 的准确率，展现出对高压缩比的强鲁棒性，而 xRAG 在相同压缩比下性能骤降。

| 消融配置 | BAMBOO (Avg) | LongBench-v2 (Avg) | LoCoMo (Avg) |
| :--- | :--- | :--- | :--- |
| **DRIFT (32×)** | **60.15** | **29.22** | **57.73** |
| w/o LFRP | 57.64 | 26.84 | 52.68 |
| w/o QAFT-DC | 56.64 | 25.84 | 57.36 |
| w/o QAFT-QA | 45.14 | 18.05 | 36.89 |

消融实验显示，移除 QAFT-QA 阶段导致性能大幅下降（LongBench-v2 降至 18.05），表明推理模型对压缩表示的适配至关重要；移除 LFRP 阶段则导致 LoCoMo 性能下降 5.05 分，验证了静态预训练对潜在空间语义完整性的基础作用。QAFT-DC 的移除对 LoCoMo 影响较小（0.37 分），但在 LongBench-v2 上下降 3.38 分，说明查询感知动态压缩在多文档推理任务中贡献显著。

评估边界方面，DRIFT 主要验证了 7B 至 14B 参数规模的模型，未探索更大规模模型的扩展律；隐式事实 Token 缺乏人类可读性，限制了其在需要审计场景中的应用；此外，实验未报告端到端延迟的具体数值对比，仅定性描述了 256k Token 文档上的 7 倍加速，缺乏在资源受限环境下的统一基准测试。

## 关联研究分析

从方法设计看，DRIFT 与 ICAE 的核心差异在于压缩与推理的解耦程度。ICAE 采用单模型自编码器架构，压缩与推理共享参数，导致在极端压缩比下，模型需同时优化信息保留与逻辑生成，易产生梯度冲突。DRIFT 通过双模型架构将这一冲突外化，知识模型专注信息提取，推理模型专注逻辑生成，中间通过 MLP 投影对齐。这种解耦设计是否可推广至单模型架构，即通过内部模块隔离实现类似效果，论文未给出回答。

从问题动机看，DRIFT 与 COCOM 均基于 RAG 范式，但 COCOM 侧重于检索文档的静态压缩，而 DRIFT 强调查询感知的动态压缩。COCOM 的压缩过程独立于查询，导致在特定任务下可能保留无关信息或丢失关键证据。DRIFT 通过 QAFT-DC 阶段引入证据监督，使压缩过程依赖于查询，解决了静态压缩在任务特定场景下的信息丢失问题。然而，DRIFT 依赖预标注的证据数据，这在无监督或弱监督场景下的泛化能力尚不明确，查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

DRIFT 旨在解决长上下文推理中静态压缩丢失任务关键信息与参数化编辑导致灾难性遗忘的矛盾。其切入点在于将知识提取与推理解耦，利用轻量级知识模型进行查询感知的动态压缩，生成隐式事实 Token 供推理模型使用。实验证明，在 32 倍压缩比下，DRIFT 在 LongBench-v2 上较基线提升 8.35 个百分点，且在 128 倍极端压缩比下仍保持竞争力。然而，该框架主要验证于 14B 以下模型，隐式表示的可解释性缺失限制了其在高风险领域的应用。当支持集增大或任务复杂度进一步提升时，双模型解耦带来的额外推理延迟是否抵消了压缩收益，论文未给出回答。
