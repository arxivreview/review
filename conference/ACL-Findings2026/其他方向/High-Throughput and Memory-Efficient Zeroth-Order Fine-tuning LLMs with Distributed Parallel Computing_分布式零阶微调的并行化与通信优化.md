> 大语言模型全参数微调受限于显存与算力，零阶优化（ZO）虽通过消除反向传播降低显存占用，但单卡执行导致吞吐量瓶颈，且现有分布式框架无法利用其双前向结构。DistZO2 提出扰动并行（PertP）与适配标量梯度的数据并行，结合硬件感知通信切片，将 ZO 微调扩展至 CPU+多 GPU 异构系统。该方法在 OPT-175B 上实现了 3 倍加速，但缺乏与一阶优化在同等资源约束下的公平对比，其收敛性边界仍存疑。

## 研究背景

零阶优化（ZO）通过仅执行前向传播来估计损失函数的方向导数，从而避免存储中间激活值和梯度张量。给定损失函数 $L(\theta)$ 和随机方向向量 $z \sim \mathcal{N}(0, I)$，投影梯度被近似为 $g = \frac{L(\theta + \epsilon z) - L(\theta - \epsilon z)}{2\epsilon}$。这一机制使得模型参数可以驻留在 CPU 内存中，仅在计算时传输至 GPU，从而突破单卡显存限制。然而，ZO 需要执行两次独立的前向传播（分别对应 $\theta + \epsilon z$ 和 $\theta - \epsilon z$），在单卡上必须串行执行，导致计算吞吐量显著低于一阶方法。

现有分布式训练框架如数据并行（DDP）和张量并行（TP）均依赖反向传播产生的高维梯度张量进行同步，无法直接应用于仅产生标量投影梯度的 ZO 场景。简单地将 DDP 应用于 ZO 不仅忽略了双前向结构的并行潜力，还因 CPU 向多 GPU 重复传输完整参数块而加剧 PCIe 带宽瓶颈。DistZO2 的切入点在于利用 ZO 双前向的结构独立性，将其映射为跨设备的并行任务，并针对异构硬件特性重新设计通信路径，以解决单卡 ZO 的吞吐瓶颈。

## 核心方法

### 方法参照系

传统分布式微调基于一阶优化，通过反向传播获取梯度张量，并利用 AllReduce 同步。ZO 微调的关键差异在于：无梯度张量，仅有标量投影梯度；计算依赖两次前向而非一次前向加一次反向。因此，标准 DDP 的同步逻辑与通信模式在 ZO 场景下失效，需重新设计并行维度与通信策略。

### 扰动并行（Perturbation Parallelism）

PertP 将 ZO 的两次前向传播分配至两个不同的 GPU，以消除单卡串行执行的延迟。设计动机在于利用双前向的结构独立性，将计算瓶颈转化为并行优势。每个 GPU 独立从 CPU 加载参数块，执行其分配的前向计算（$W_D^1 = W_H + \epsilon z$ 或 $W_D^2 = W_H - \epsilon z$），并异步卸载结果。

$$
g = \frac{L_1^+ - L_2^-}{2\epsilon}
$$

该公式表明，两个 GPU 仅需交换标量损失值 $L_1^+$ 和 $L_2^-$，即可计算全局投影梯度 $g$。由于 $g$ 和 $z$ 在所有设备上同步，参数更新 $W_D^k \leftarrow W_D^k - \eta \cdot g \cdot z$ 无需额外通信，从而在保持低显存占用的同时，将双前向计算时间减半。

### 硬件感知通信与 2D 并行

PertP 仅支持 2 路并行，且 CPU 向多 GPU 传输完整参数块会饱和 PCIe 带宽。DistZO2 引入通信优化策略：CPU 将参数块切片为 $n$ 份，每份通过 PCIe 发送至对应 GPU，剩余切片通过 NVLink 在 GPU 间对等传输。

$$
T_{comm} = \frac{M}{n} \cdot t_{PCIe} + \frac{(n-1)M}{n} \cdot t_{NVLink}
$$

此设计将 PCIe 负载降低 $n$ 倍，并利用高速 NVLink 隐藏传输延迟。在此基础上，DistZO2 提出 2D 并行，将 $n$ 个 GPU 组织为 $n_b \times n_p$ 网格，其中 $n_p=2$ 为扰动维度，$n_b$ 为数据并行组。PertP 作为内层并行处理双前向，DDP 作为外层并行处理数据批次，通过 AllReduce 同步各组的标量梯度，实现跨多 GPU 的高效扩展。

## 实验评估

实验在 4×NVIDIA H20 GPU（96GB）和 AMD Milan CPU 上进行，使用 OPT 系列模型（1.3B-175B）和 SST-2 数据集，对比 MeZO 和 ZO2 基线。主实验结果显示，DistZO2 在所有模型规模上均优于单卡基线，且在 OPT-175B 上实现了 3 倍加速。

| 模型 | 显存 (MB/GPU) | 吞吐量 (tokens/sec) |
| :--- | :--- | :--- |
| OPT-175B (ZO2) | 18713 | 18713 |
| OPT-175B (DistZO2 2D) | 18713 | 18713 |
| OPT-66B (ZO2) | 13263 | 13263 |
| OPT-66B (DistZO2 2D) | 14775 | 14775 |

注：原文 Table 1 中 ZO2 与 DistZO2(2D) 在 OPT-175B 上的吞吐量数值相同，但摘要声称 3 倍加速，此处存在数据矛盾或单位差异，需核实。通信优化消融实验表明，切片重分布策略将上传吞吐量从 4.73 B/s 提升至 19.24 B/s（OPT-1.3B），卸载吞吐量从 1.79 B/s 提升至 8.32 B/s，验证了 NVLink 重分布在缓解 PCIe 瓶颈中的关键作用。

评估边界方面，实验仅关注吞吐量与显存，未报告收敛速度或最终模型性能。缺乏与一阶优化（如 AdamW+ZeRO）在同等显存约束下的对比，无法判断 ZO 在精度-效率权衡上的实际优势。代码未公开，且实验限于单节点 4 GPU，未验证跨节点扩展性。

## 关联研究分析

从问题动机看，DistZO2 与 DiLoCo 等低通信优化器均旨在突破带宽限制，但 DiLoCo 针对预训练中的梯度同步，而 DistZO2 针对微调中的参数卸载。DiLoCo 通过减少同步频率降低通信量，DistZO2 通过硬件感知切片降低单次传输延迟。这一差异源于任务特性：预训练数据量大，同步频率是关键；微调数据量小，参数传输延迟是关键。

从方法设计看，DistZO2 与 MeZO 同属 ZO 框架，但 MeZO 聚焦单卡显存优化，DistZO2 聚焦多卡吞吐优化。MeZO 通过前向-only 训练减少显存，DistZO2 通过 PertP 并行化双前向提升吞吐。两者结合可进一步扩展 ZO 的适用场景，但 DistZO2 未探索 MeZO 的稀疏化策略与 PertP 的兼容性，这可能是一个未开发的优化空间。

## 总结

DistZO2 解决了 ZO 微调在单卡上的吞吐瓶颈，通过 PertP 并行化双前向和硬件感知通信优化，在 OPT-175B 上实现了 3 倍加速。其核心创新在于利用 ZO 的结构独立性设计新的并行维度，并针对异构硬件特性重新设计通信路径。然而，实验仅验证了吞吐量提升，未证明 ZO 在精度-效率权衡上的优势，且缺乏与一阶优化的公平对比。当模型规模进一步扩大至 1T 参数时，标量梯度同步的收敛稳定性是否仍能保持，论文未给出回答。
