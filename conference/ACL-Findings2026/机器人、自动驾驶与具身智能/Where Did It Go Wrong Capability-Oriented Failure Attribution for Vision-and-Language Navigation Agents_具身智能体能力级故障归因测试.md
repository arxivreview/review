# ACL-Findings2026最新论文 ｜Where Did It Go Wrong? Capability-Oriented Failure Attribution for Vision-and-Language Navigation Agents ｜具身智能体能力级故障归因测试

研究机构：中国科学院、中国科学院大学

作者：Jianming Chen、Yawen Wang、Junjie Wang 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.25161)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.25161)

> 具身智能体在视觉语言导航（Vision-Language Navigation, VLN）等安全关键任务中，因感知、记忆、规划与决策能力的强耦合导致错误级联，传统系统级测试无法定位具体失效环节。现有模糊测试框架仅能判定任务失败，缺乏对能力级错误的独立评估与归因机制，阻碍了针对性修复。CanTest 通过自适应指令变异生成测试用例，构建独立能力预言机（Oracle）并引入反事实归因机制，实现了从任务失败到具体能力错误的精准映射。该方法在三个先进 VLN 模型上发现了比最强基线多 23.34% 至 33.70% 的故障案例，但预言机对端到端模型内部状态的捕捉准确性及真实世界无监督测试的可行性仍存疑。

## 研究背景

具身智能体的可靠性依赖于感知、记忆、规划与决策四个核心能力的协同。当智能体在未知环境中执行长时程导航任务时，单一能力的微小偏差会沿时间步传播并放大，例如感知错误导致记忆更新错误，进而引发规划偏差与决策失误。这种错误级联效应使得传统将智能体视为黑盒的测试方法失效，开发者无法区分是视觉编码器未识别地标，还是语言模型误解了指令，从而难以实施针对性优化。

当前 VLN 领域的研究重心集中在提升导航成功率（Success Rate, SR）与路径长度效率（Success weighted by Path Length, SPL），主流方法如 ABot-N0 和 OMNINAV 通过大规模预训练或分层架构优化性能指标。然而，这些方法普遍缺乏对系统内部状态的可解释性验证，且现有测试基准（如 Habitat Challenge）仅关注最终任务完成状态，无法揭示中间过程的失效根源。软件测试领域的模糊测试（Fuzzing）虽能生成多样化输入以暴露系统漏洞，但传统方法针对单体软件设计，未考虑具身智能体多模态输入与多能力耦合的特性，导致生成的测试用例难以触发特定能力缺陷。

CanTest 的切入点在于将软件测试中的能力级故障归因思想迁移至具身智能体领域。它不直接优化导航策略，而是构建一套自动化测试框架，通过独立评估每个能力的输出质量，将任务失败精准归因到具体的能力模块。这一视角转换使得测试目标从“是否到达目标”转变为“哪个能力环节出错”，为具身智能体的安全认证与迭代修复提供了可操作的技术路径。

## 核心方法

### 自适应测试用例生成

CanTest 基于经典搜索式模糊测试范式，维护一个种子语料库，每个种子对应一个测试用例及其反馈分数。与随机生成不同，该模块利用大语言模型（LLM）结合 HM3D 数据集的房间与物体语义标注，生成具有挑战性的自然语言指令作为测试用例。其核心创新在于自适应变异策略：根据反馈分数动态选择轻微变异（保留失败相关语义）或激进变异（多样化轨迹以暴露新弱点），平衡故障保持与搜索空间探索。

$$
p_{cs_i} = \frac{f_i}{\sum_{j=1}^{n} f_j}
$$

其中 $p_{cs_i}$ 为种子 $i$ 的选择概率，$f_i$ 为其反馈分数。该公式确保高价值种子（更可能暴露能力缺陷）被优先选中进行变异，从而提升测试效率。

### 能力预言机构建

针对 VLN 智能体的四种核心能力，CanTest 自动构建独立的预言机以评估输出正确性。感知预言机使用加权交并比（IoU）度量视觉标注偏差；记忆预言机通过 LLM 计算当前记忆内容与历史视觉标注的语义相似度；规划预言机采用归一化动态时间规整（nDTW）评估规划轨迹与专家最优路径的对齐度；决策预言机直接比较实际动作与规划动作的差异。

$$
E_{pl} = nDTW(\tau_t^{pl}, \tau_{t,...,n}^{gt})
$$

其中 $E_{pl}$ 为规划能力误差，$\tau_t^{pl}$ 为目标智能体在时间步 $t$ 规划的轨迹，$\tau_{t,...,n}^{gt}$ 为专家模型提供的真值轨迹。nDTW 同时考虑空间接近度与时间对齐，解决了传统欧氏距离无法处理轨迹长度差异的问题。

### 能力导向与故障导向反馈

CanTest 引入反事实推理机制，从检测到的能力错误中识别真正导致任务失败的“故障诱导错误”。反馈分数综合了故障导向（任务是否失败）与能力导向（哪个能力出错）两个维度，指导下一轮测试用例生成。该机制解决了长时程轨迹中错误传播导致的归因模糊问题，确保反馈信号既反映任务结果，又指向具体能力缺陷。

## 实验评估

实验在 Habitat3 仿真环境中进行，针对 ApexNav、MGDM 和 Mem2Ego 三个先进 VLN 模型，对比 Random、BehAVExplor 和 VLATest 三个基线。VLATest 是当前最先进的模糊测试框架，但缺乏能力级归因能力。

| 方法 | ApexNav 感知故障数 | MGDM 规划故障数 | Mem2Ego 决策故障数 |
| :--- | :--- | :--- | :--- |
| Random + OA | 20.4 | 35.6 | 52.1 |
| BehAVExplor + OA | 40.9 | 43.2 | 50.4 |
| VLATest + OA | 51.8 | 52.1 | 58.1 |
| CanTest (Ours) | 72.2 | 49.3 | 63.4 |

CanTest 在所有能力维度上均发现最多故障案例，相对最强基线 VLATest 提升 23.34% 至 33.70%。例如，在 ApexNav 的感知能力上，CanTest 发现 72.2 个故障，而 VLATest 仅发现 51.8 个。

| 模型 | 感知修复率 | 记忆修复率 | 规划修复率 | 决策修复率 |
| :--- | :--- | :--- | :--- | :--- |
| ApexNav | 84.35% | 81.30% | 87.05% | 95.13% |
| MGDM | 83.53% | 82.35% | 86.41% | 94.90% |
| Mem2Ego | 85.83% | 83.64% | 89.71% | 96.69% |

修复率实验验证了预言机的保真度：当用预言机提供的期望输出替换错误能力输出后，81.30% 至 96.69% 的故障案例被成功修复，表明预言机准确识别了故障根源。消融实验显示，移除故障导向或能力导向反馈均导致故障发现数下降，证实两种反馈信号的互补性。

评估边界方面，实验仅覆盖仿真环境，未验证真实世界无 Ground Truth 场景下的预言机有效性。代码已开源，但超参数配置与 GPU 需求未详细披露，可复现性受限。

## 关联研究分析

从问题动机看，CanTest 与 VLATest 同属模糊测试框架，但 VLATest 聚焦于任务完成状态的判定，而 CanTest 引入能力级预言机实现故障归因。这一差异源于具身智能体多能力耦合的特性：任务失败可能是感知、记忆或规划中任一环节的错误，仅判定任务失败无法指导修复。VLATest 的简单预言机无法区分这些环节，而 CanTest 的独立预言机通过反事实推理实现了精准归因。

从方法设计看，CanTest 借鉴了 MoDitector 的模块级测试思想，但将其扩展至能力级。MoDitector 针对软件模块建立错误-故障关系，而 CanTest 针对具身智能体的感知、记忆等能力构建预言机。关键差异在于 CanTest 利用仿真环境的专家模型（如全局地图、RAM 标注）生成期望输出，这在真实世界中不可用。这种对 Ground Truth 的依赖限制了 CanTest 的泛化能力，也引发了一个问题：当专家模型本身存在偏差时，预言机的归因结果是否可靠？

## 总结

CanTest 解决了具身智能体测试中故障归因模糊的核心矛盾，通过构建独立能力预言机与反事实归因机制，实现了从任务失败到具体能力错误的精准映射。该方法在三个 VLN 模型上发现比最强基线多 23.34% 至 33.70% 的故障案例，修复率达 81.30% 至 96.69%，验证了预言机的有效性。然而，其依赖仿真环境 Ground Truth 生成期望输出，在真实世界无监督测试场景下的适用性未经验证。当专家模型存在系统性偏差时，预言机归因的可靠性如何保障，论文未给出回答。
