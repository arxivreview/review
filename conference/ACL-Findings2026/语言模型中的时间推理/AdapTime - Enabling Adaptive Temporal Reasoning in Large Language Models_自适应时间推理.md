# ACL-Findings2026最新论文 ｜AdapTime: Enabling Adaptive Temporal Reasoning in Large Language Models ｜自适应时间推理

研究机构：香港城市大学、西湖大学

作者：Yimin Deng、Yejing Wang、Zhenxi Lin 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.24175)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.24175)

> 时间推理任务要求模型在静态文档中解析时间约束并定位事实，但现有方法依赖固定流水线或外部工具，导致简单问题过度处理、复杂问题推理不足。AdapTime 通过 LLM Planner 动态选择“重构、重写、审查”三个推理动作，实现了无外部依赖的自适应推理。该方法在 DeepSeek-V3 上将 TempReason-L3 的 F1 从 48.3 提升至 53.2，证明了动态规划的有效性，但其性能上限仍受限于骨干模型自身的时间感知能力。

## 研究背景

时间推理的核心困境在于时间表达的隐式性与多义性。文档中的时间信息常通过时态、副词或话语结构隐含表达，如“在他任期内”或“战争结束后”，这种隐式性使得模型难以直接定位事件的时间锚点。当问题涉及多跳依赖时，如询问某人在特定时间段内的职位，模型需同时处理时间区间重叠与事件排序，这要求推理过程具备对时间拓扑结构的显式建模能力，而非简单的语义匹配。

现有主流路线分为两类：一类依赖外部工具，如 QAaP 使用 Python 代码执行器，TG-LLM 构建时间图并需人工修正；另一类采用固定提示策略，如 Time-CoT 强制提取时间参数。这些方法的共同瓶颈在于“一刀切”的执行逻辑：简单问题被强制走复杂流程，增加计算开销；复杂问题因缺乏针对性分解而推理断裂。AdapTime 的切入点在于将推理策略的选择权交给模型自身，通过 LLM Planner 根据问题复杂度动态决定执行哪些动作，从而在无需外部工具的前提下实现策略适配。

## 核心方法

### 方法参照系

本文问题属于基于提示的时间推理框架，其标准流程为“输入文档与问题→执行固定推理步骤→输出答案”。与 TG-LLM 等依赖外部符号引擎或人工干预的方法不同，AdapTime 的关键差异在于完全依赖 LLM 内部能力进行决策，不引入任何外部检索器、代码解释器或人工标注规则，将推理控制逻辑内化于模型提示中。

### 动态动作选择机制

固定流水线无法区分问题复杂度，导致资源错配。AdapTime 引入 LLM Planner 作为控制器，其决策过程可形式化为：

$$ d_i = \text{Planner}(Q, C, A_{prev}, \text{step}_i) \in \{\text{execute, skip}\} $$

其中 $d_i$ 表示第 $i$ 步动作（重构、重写、审查）的执行决策。该公式的物理含义是：Planner 基于问题语义、上下文结构及中间答案置信度，输出二值决策。这一设计解决了固定流水线在简单问题上冗余计算、在复杂问题上推理不足的问题，使模型能针对“时间区间重叠”类问题优先执行重构，而对“时间线模糊”类问题优先执行重写。

### 结构化时间重写

隐式时间表达阻碍了精确的时间算术运算。Rewrite 模块将自然语言文本转换为时间锚点结构，其核心操作可表示为：

$$ C' = \text{Rewrite}(C) = \{(s_j, r_j, o_j, t_{start}^j, t_{end}^j)\}_{j=1}^n $$

其中 $C'$ 为结构化时间图，$t_{start}^j, t_{end}^j$ 为事件 $j$ 的显式时间边界。该公式将“在他任期内”等模糊表达映射为具体日期区间，使下游模块能直接进行区间重叠判断。这一改进解决了 TG-LLM 中人工修正时间图的高成本问题，通过 LLM 自主重写实现了时间结构的标准化，显著提升了多事件重叠场景下的推理准确性。

## 实验评估

实验在 TimeQA 和 TempReason 数据集上进行，基线覆盖 ICL、CoT、Step-back、Self-refinement 及 QAaP、TG-LLM 等外部工具方法，但缺失 STAIR、ODL-TempLLM 等最新神经符号 SOTA。主实验显示，AdapTime 在 DeepSeek-V3 上取得 TempReason-L3 F1 53.2，较 ICL 基线 48.3 提升 4.9 点；在 Qwen-3-8B 上，TimeQA-Easy EM 从 67.5 提升至 72.7。

| 模型 | TimeQA-Easy EM | TimeQA-Hard EM | TempReason-L2 EM | TempReason-L3 EM |
| :--- | :--- | :--- | :--- | :--- |
| DeepSeek-V3-ICL | 80.8 | 68.8 | 45.1 | 43.6 |
| DeepSeek-V3-AdapTime | 85.4 | 77.7 | 48.0 | 49.8 |
| Qwen-3-8B-ICL | 67.5 | 56.9 | 23.9 | 23.1 |
| Qwen-3-8B-AdapTime | 72.7 | 66.5 | 29.1 | 28.8 |

消融实验表明，移除 Rewrite 模块导致 TempReason-L2 F1 从 52.1 降至 49.8，降幅最大，证实结构化重写对多事件推理的关键作用。移除 Planner 后，模型执行固定步骤，TempReason-L3 EM 从 49.8 降至 48.9，说明动态规划对复杂问题的必要性。计算成本方面，AdapTime 平均消耗 4873.64 tokens，略高于 CoT 的 4584.17，但远低于 Self-refinement 的 >10000 tokens。

评估边界方面，论文未报告置信区间，且仅在 1000 个采样实例上测试，统计显著性有限。代码已开源，但超参数（如 top-k=10, temperature=0.7）未提供敏感性分析。评估协议未包含跨日历或实时场景，局限于静态文档问答。

## 关联研究分析

从方法设计看，AdapTime 与 TG-LLM 的核心差异在于时间图构建方式。TG-LLM 依赖人工修正确保时间图准确性，而 AdapTime 的 Rewrite 模块由 LLM 自主生成，牺牲了部分结构精确性以换取泛化性。这一取舍源于任务特性：TG-LLM 面向高精度结构化问答，而 AdapTime 面向多样化问题类型，人工修正在大规模场景中不可行。然而，LLM 自主重写在时间边界模糊时可能引入错误，论文未量化此类错误的比例。

从问题动机看，AdapTime 与 Time-CoT 同属提示工程路线，但 Time-CoT 强制提取时间参数，而 AdapTime 通过 Planner 动态决定是否重构。这一差异反映了问题复杂度的异质性：Time-CoT 假设所有问题均需时间参数提取，而 AdapTime 承认简单问题可直接回答。这种自适应机制是否在所有问题类型上均优于固定策略，论文仅在 TimeQA 和 TempReason 上验证，未覆盖更复杂的长程依赖场景。

## 总结

AdapTime 针对固定流水线在时间推理中策略错配的问题，通过 LLM Planner 动态选择重构、重写、审查动作，实现了无外部依赖的自适应推理。实验证明其在 DeepSeek-V3 上将 TempReason-L3 F1 提升至 53.2，较 ICL 基线提升 4.9 点，验证了动态规划的有效性。然而，其性能上限受限于骨干模型的时间感知能力，且未与最新神经符号 SOTA 进行同协议对比。当问题涉及跨文档时间依赖或实时时间感知时，纯 LLM 自适应规划是否仍能维持逻辑一致性，论文未给出回答。
