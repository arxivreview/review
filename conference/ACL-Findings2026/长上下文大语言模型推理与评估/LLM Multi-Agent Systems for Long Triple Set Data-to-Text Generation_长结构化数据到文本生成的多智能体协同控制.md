# ACL-Findings2026最新论文 ｜LLM Multi-Agent Systems for Long Triple Set Data-to-Text Generation ｜长结构化数据到文本生成的多智能体协同控制

作者：Chinonso Cynthia Osuji、Simon Mille、Mark Andrade 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_4b41760fecd9)

> 数据到文本（Data-to-Text, D2T）生成旨在将结构化数据转化为连贯自然语言，但现有基准多聚焦短文本，难以评估大语言模型（LLM）在长输入下的语义完整性与话语连贯性。随着模型上下文窗口扩展至32k以上，单步生成在长序列中易出现信息遗漏与幻觉，且缺乏对中间推理过程的有效控制。本文提出一种模块化多智能体框架，通过内容排序、文本结构化与表面实现的角色分工，结合监督与校验机制，解决长结构化数据生成的控制难题。该框架在英语与爱尔兰语上展示了连贯性优势，但统计显著性不足，且LLM评估在长文本与低资源场景下可靠性存疑。

## 研究背景

当LLM处理包含数百个事实的结构化输入时，单步前向传播难以同时维持全局逻辑流与局部事实准确性。这种困境源于注意力机制在长序列中的稀释效应，导致模型对中间位置信息的利用率下降，即“中间迷失”现象。为缓解此问题，研究界引入了多智能体系统，通过任务分解与递归调用将长上下文处理转化为子问题序列，但现有D2T多智能体工作多局限于短输入，未针对文档级长文本生成进行优化。

现有D2T基准如E2E（22.67 tokens）和WebNLG（22.69 tokens）主要关注句子或段落级生成，输入规模远小于当代LLM的能力上限。尽管RotoWire等数据集提供了较长输出，但其依赖内容选择组件，增加了直接生成的复杂性。本文切入点在于构建一个包含多达199个三元组的长输入数据集，并设计一种具备显式中间表示与校验机制的多智能体架构，以解决长结构化数据生成中语义完整性与话语连贯性的协同控制问题。

## 核心方法

### 方法参照系

本文问题可置于“多智能体与递归推理”路线下，该路线通过任务分解突破单一模型上下文限制。与Recursive Language Models（RLM）将长提示视为外部环境并允许自由代码生成不同，本文强调结构化中间表示（内容计划与大纲）的显式构建，以强制忠实性并减少错误累积。

### 模块化角色分工与状态管理

设计动机在于解决单步生成中缺乏对中间推理过程的控制，导致长输入下幻觉与遗漏增加。本文构建由Orchestrator、Content Ordering (CO)、Text Structuring (TS)、Surface Realisation (SR)、Guardrail及Finalizer组成的有向图工作流。Orchestrator维护全局迭代计数器 $n$ 与每个worker的调用上限，防止无限递归。CO接收完整三元组集 $X$，生成有序内容计划 $CO$；TS将 $CO$ 转化为段落级大纲；SR仅访问大纲而非原始三元组，生成目标语言 $\ell$ 的文本 $Y_\ell$。该解耦设计通过限制SR的信息访问范围，强制其忠实于计划内容，从而降低事实性错误。

$$
Y_\ell = SR(TS(CO(X)), \ell)
$$

此公式表明最终文本是嵌套函数调用的结果，其中SR的输入被严格限定为TS的输出，切断了SR与原始数据 $X$ 的直接连接。

### 监督校验与近极限短路机制

设计动机在于防止中间步骤的错误在递归调用中累积，即对抗“上下文腐烂”。Guardrail评估中间输出是否满足约束，如每个三元组是否映射到 $CO$ 或标记为未使用，以及 $TS$ 大纲是否符合模式。若检测到违规，Guardrail生成结构化反馈，Orchestrator据此将状态路由回相关worker进行修订。此外，引入近极限短路机制：当执行到达倒数第二个全局迭代 $n-1$ 时，SR与Guardrail的输出直接路由至Finalizer，绕过正常路径以保留可用输出。

$$
\text{Route}(S, n) = \begin{cases}
\text{Finalizer}(SR, Guardrail) & \text{if } n = N-1 \\
\text{Orchestrator}(S, \text{history}) & \text{otherwise}
\end{cases}
$$

该机制在计算资源受限或迭代次数接近上限时，优先保证输出完整性而非完美性，避免了因无限修订导致的资源耗尽。

## 实验评估

实验基于自建DBpedia三元组数据集（8-199 triples，平均98.37 triples/input），对比三种系统：三worker多智能体（Mul）、单worker多任务（Sng）及端到端基线（e2e），均使用GPT-4.1作为骨干。评估涵盖英语与爱尔兰语，采用人类评估（30个样本，6名双语者）与LLM-as-judge（claude-sonnet-4-5）。

| 系统 | 英语语法 (Mean) | 英语流畅 (Mean) | 爱尔兰语法 (Mean) | 爱尔兰流畅 (Mean) |
| :--- | :--- | :--- | :--- | :--- |
| Mul | 4.75 | 4.32 | 4.07 | 3.75 |
| e2e | 4.70 | 4.10 | 3.97 | 3.60 |
| Sng | 4.60 | 4.07 | 3.90 | 3.80 |

Mul在英语连贯性上略高于e2e，但所有差异均不具统计显著性（Tukey’s HSD, p>0.05）。LLM-as-judge在No-Omissions指标上显示，随着输入规模增加，e2e分数下降更明显，而Mul/Sng保持相对稳定，表明多智能体架构对长输入更具鲁棒性。然而，LLM与人类评分在英语和爱尔兰语上均呈现弱且非显著的相关性（Pearson r=0.1），且在>100 triples时，LLM对缺失内容的检测能力显著下降。

消融分析显示，Sng（单worker）在爱尔兰语流畅性上（3.80）略高于Mul（3.75），但在英语流畅性上（4.07 vs 4.32）显著低于Mul，表明角色分工在资源充足语言中更能提升连贯性，而在低资源语言中可能因提示复杂度增加而引入噪声。Guardrail的引入未直接体现在主表格中，但其通过路由修订机制间接影响了最终输出的质量，具体贡献需通过移除Guardrail的消融实验进一步量化，本文未提供该数据。

评估边界方面，人类评估样本量仅30个，限制了统计功效；LLM-as-judge在长文本与低资源语言下的可靠性存疑，且未报告置信区间。代码与数据已开源，但实验未对比RAG或长上下文专用模型基线，限制了与领域SOTA的直接比较。

## 关联研究分析

从问题动机看，本文与Recursive Language Models（RLM）均旨在突破单一模型上下文限制，但RLM通过自由代码生成处理任意长度输入，而本文通过结构化中间表示（CO/TS）解决D2T生成中的语义完整性问题。差异根源在于任务特性：D2T生成要求严格的事实覆盖与话语连贯，自由代码生成易引入不可控的幻觉，而结构化大纲提供了显式的约束边界。RLM在处理数十亿令牌任务上优于原生模型，但成本较高且依赖编程接口；本文在199三元组规模下展示了多智能体架构的可行性，但未探索更大规模下的扩展性。

从方法设计看，本文与Contextual Drag研究形成对照。Contextual Drag揭示批评-验证-修订循环中错误推理对后续步骤的锚定效应，而本文的Guardrail机制旨在通过显式校验防止错误累积。然而，本文未量化Guardrail在防止“上下文拖拽”方面的具体效果，仅通过定性描述其功能。此外，本文使用GPT-4.1作为唯一骨干，未对比开源长上下文模型，这与领域共识中“开源模型在复杂推理上落后”的观点一致，但限制了方法在不同骨干上的泛化性验证。

## 总结

本文核心矛盾在于长结构化数据生成中语义完整性与话语连贯性的协同控制，单步生成因注意力稀释导致信息遗漏与幻觉。本文通过模块化多智能体架构，利用结构化中间表示与Guardrail校验机制，实现了长输入下的可控生成。实验显示Mul在英语连贯性上略优于e2e，但差异不具统计显著性，且LLM评估在长文本与低资源场景下可靠性不足。本文边界在于样本量小、未对比RAG基线及低资源语言评估的局限性。当输入规模扩展至数千三元组时，多智能体架构的递归调用成本与错误累积风险是否可控，论文未给出回答。
