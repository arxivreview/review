> 大语言模型在数学任务上的评估长期受制于静态基准的饱和与数据污染，导致高分掩盖了推理能力的真实瓶颈。现有动态生成基准虽能规避记忆化，但多依赖算法变换，难以触及奥林匹克级别的深层逻辑复杂度。AMO-Bench 通过人工原创 50 道 IMO 级难度题目并辅以自动评分机制，填补了高难度竞赛级评估的空白。该基准揭示了当前 SOTA 模型在极端推理任务上的显著局限，但其仅评估最终答案的设计可能掩盖了过程层面的逻辑缺陷。

## 研究背景

评估大语言模型（LLM）的数学推理能力时，静态基准如 GSM8K 和 MATH 已迅速饱和，且因公开数据集被广泛纳入训练语料而面临严重的数据污染。这种污染使得模型的高分往往源于对表面模式的统计记忆，而非深层逻辑结构的掌握。为区分“记忆”与“推理”，研究者转向动态评估路线，通过程序化生成反事实问题（如 MatheMagic）或引入对抗性扰动（如 GSM-Symbolic）来测试模型的泛化能力。然而，这些方法多聚焦于规则变换或表面扰动，未能充分覆盖需要复杂直觉与多步推导的奥林匹克级别数学问题。

IMO 级问题通常要求完整的证明过程，依赖专家人工验证，导致自动化评分困难，阻碍了大规模评估的实施。AMO-Bench 的切入点在于构建一个兼具极高难度与可自动评分特性的基准。它通过人工原创题目确保原创性，通过仅要求最终答案的设计实现高效自动评分，从而在规避数据污染的同时，提供了对前沿模型推理极限的精准诊断。

## 核心方法

### 基准构建参照系

动态数学基准的通用流程通常包含题目生成、难度筛选与自动评分三个环节。传统方法如 MatheMagic 采用算法生成反事实变换，而 AMO-Bench 的关键差异在于采用纯人工原创题目，并引入 LLM 辅助的难度过滤，以平衡原创性、难度与可评分性。

### 原创性与难度保障机制

题目生成环节通常依赖算法模板，但 AMO-Bench 要求由具备 IMO 获奖或命题经验的专家独立设计，以消除算法生成的模式化局限。为确保原创性，系统执行 10-gram 匹配与网络搜索，排除与现有竞赛题高度相似的内容。难度筛选采用双重标准：专家交叉验证确保达到 IMO 标准，同时利用 GPT、DeepSeek 等前沿模型进行初步评估，要求至少两个模型在三次采样中均无法正确解题。这一机制解决了静态基准中“过易题目”对 SOTA 模型区分度不足的问题，其核心筛选逻辑可形式化为：

$$
\text{Keep}(q) = \mathbb{1}[\text{Expert}(q) \geq \text{IMO}] \cdot \mathbb{1}[\sum_{m \in \mathcal{M}} \mathbb{1}[\text{Fail}(m, q)] \geq 2]
$$

其中 $\mathcal{M}$ 为前沿模型集合，$\text{Fail}(m, q)$ 表示模型 $m$ 在题目 $q$ 上的三次采样均失败。该设计确保了题目对当前最强模型具有足够的挑战性。

### 混合自动评分策略

传统评分多依赖单一解析器或 LLM 裁判，前者适用于数值答案但缺乏灵活性，后者通用但效率低且准确性不稳定。AMO-Bench 根据答案类型实施混合评分：39 道数值、集合或变量表达式题目采用基于解析器的评分，利用 math-verify 工具解析 $\boxed{\text{answer}}$ 格式并验证等价性；11 道描述性题目采用 LLM 评分，使用 o4-mini (Low) 进行五次独立采样并采用多数投票机制。该策略解决了复杂答案类型下自动评分的准确性与效率矛盾，其评分函数定义为：

$$
S(a, y) = \begin{cases}
\text{Parser}(a, y) & \text{if } y \in \{\text{Num, Set, Expr}\} \\
\text{Majority}(\text{LLM}(a, y)^5) & \text{if } y \in \{\text{Desc}\}
\end{cases}
$$

其中 $a$ 为模型答案，$y$ 为真值答案。这种分类处理确保了在保持自动评分效率的同时，最大化了不同答案类型下的评分可靠性。

## 实验评估

实验在 26 个主流 LLM 上进行，采样温度设为 1.0（推理模型）或 0.7（非推理模型），top-k=50，top-p=0.95，每个模型采样 32 次并报告 AVG@32 指标。基线覆盖 OpenAI、DeepSeek、Qwen 等主流厂商的推理与非推理模型，但未包含针对数值表示优化或工具增强（如 PAL）的特定方法，这可能限制了对其在精确计算任务上表现的全面评估。

| 模型 | AVG@32 (%) | 平均输出 Token |
| :--- | :--- | :--- |
| GPT-5-Thinking (High) | 52.4 | ~37,000 |
| Qwen3-235B-A22B-Thinking-2507 | 47.8 | - |
| DeepSeek-V3.1-Thinking | 47.6 | - |
| GPT-5-Thinking (Medium) | 47.3 | - |
| LongCat-Flash-Thinking | 43.6 | - |
| o4-mini (High) | 40.2 | - |
| Gemini-2.5-Pro | 38.7 | - |
| Qwen3-Max-Instruct | 34.8 | - |

GPT-5-Thinking (High) 以 52.4% 的准确率领先，但多数模型得分低于 40%，证实了 IMO 级难度对当前模型的挑战性。值得注意的是，高性能模型伴随极高的 Token 消耗，GPT-5-Thinking (High) 在 AMO-Bench 上平均生成约 37K 输出 Token，远高于其在 AIME25 上的 7K，表明更难的基准迫使模型进行更冗长的推理尝试。

消融分析显示，模型性能与输出长度呈近线性增长趋势，表明测试时扩展（test-time scaling）在 AMO-Bench 上仍有效。Top-tier 模型的 pass@32 超过 70%，暗示模型具备解题的初始能力，但缺乏稳定识别正确路径的一致性。这一发现揭示了当前模型在“能力存在”与“稳定表现”之间的差距，而非单纯的能力缺失。

评估边界方面，AMO-Bench 仅包含 50 道题，样本量较小，统计显著性受限。评分准确性经 1,000 次人工检查验证达到 99.2%，但描述性答案的 LLM 评分仍可能存在主观偏差。代码与数据已公开，但缺乏对推理过程的细粒度标注，限制了其在过程奖励模型（PRM）训练中的应用。

## 关联研究分析

从问题动机看，AMO-Bench 与 MatheMagic 同属动态评估路线，但二者解决的数据污染机制不同。MatheMagic 通过算法改变算术规则生成反事实问题，侧重于测试模型对规则变化的泛化能力，其题目难度通常低于 IMO 级。AMO-Bench 则通过人工原创确保题目在逻辑复杂度上达到奥林匹克标准，其核心动机是突破静态基准的“难度天花板”，而非仅仅规避记忆化。这种差异源于任务特性的不同：MatheMagic 关注“规则理解”，而 AMO-Bench 关注“深层逻辑推导”。

从方法设计看，AMO-Bench 与 Hard2Verify 在评估粒度上存在显著差异。Hard2Verify 构建步骤级验证基准，旨在诊断推理过程中的逻辑缺陷，而 AMO-Bench 仅评估最终答案。这种设计选择牺牲了过程忠实性的诊断能力，换取了自动评分的可行性与可扩展性。AMO-Bench 提供的人工标注推理路径虽可作为后续过程监督的数据源，但当前基准本身并未利用这些路径进行步骤级评估。这种“结果导向”的设计是否掩盖了模型在中间步骤上的系统性错误，如“幸运猜测”现象，是其在评估深度上的主要局限。

## 总结

AMO-Bench 旨在解决静态数学基准饱和与数据污染导致的评估失效问题，通过人工原创 IMO 级难度题目与混合自动评分机制，实现了对前沿模型推理极限的精准诊断。该基准证明了当前 SOTA 模型在极端数学任务上的显著局限，GPT-5-Thinking (High) 仅取得 52.4% 的准确率，且伴随极高的 Token 消耗。其边界在于仅评估最终答案，缺乏对推理过程忠实性的细粒度诊断，且 50 道题的样本量限制了统计稳健性。当模型在 AMO-Bench 上 pass@32 超过 70% 但 AVG@32 仅 52.4% 时，这种“能力存在但不稳定”的现象是否源于推理路径的多样性而非逻辑能力的缺失，论文未给出回答。
