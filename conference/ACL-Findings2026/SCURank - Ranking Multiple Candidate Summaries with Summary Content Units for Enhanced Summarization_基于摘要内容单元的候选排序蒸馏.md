# ACL-Findings2026最新论文 ｜SCURank: Ranking Multiple Candidate Summaries with Summary Content Units for Enhanced Summarization ｜基于摘要内容单元的候选排序蒸馏

研究机构：国立成功大学、国立清华大学

作者：Bo-Jyun Wang、Ying-Jia Lin、Hung-Yu Kao

论文原文见 [arXiv](https://arxiv.org/abs/2604.19185)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.19185)

> 摘要蒸馏训练依赖候选摘要的质量排序来构建对比学习信号，但现有基于大语言模型（LLM）的直接排序方法存在严重的输入顺序敏感性与评估不一致性，而传统词汇重叠指标无法捕捉语义丰富度。本文提出 SCURank，通过提取摘要内容单元（Summary Content Units, SCUs）并利用聚类频率量化信息重要性，实现了对候选摘要的稳定排序。该方法在 CNN/DailyMail 和 XSum 数据集上显著优于 GPTRank 基线，但仅验证了词汇与语义相似度指标的提升，未直接证明事实一致性（Factual Consistency）的改善。

## 研究背景

当小语言模型（SLM）通过蒸馏学习大语言模型（LLM）的摘要能力时，训练信号的质量直接决定了模型的泛化上限。对比学习框架（如 BRIO）要求对候选摘要进行排序以区分正负样本，但 LLM 在文本比较任务中表现出对输入顺序的强烈依赖，导致排序结果在多次运行中波动剧烈。这种不稳定性源于 LLM 的注意力机制在处理长上下文时的位置偏差，使得基于 LLM 直接打分的排序函数（如 GPTRank）无法提供可靠的监督信号。

摘要生成领域的核心矛盾在于，模型在提升文本流畅度的同时引入了与源文档不一致的“幻觉”内容，而早期依赖词汇重叠的评估指标无法捕捉这一深层缺陷。随着研究深入，评估重心从表面语义相似度转向基于自然语言推理（NLI）的原子事实分解，确立了“事实一致性”作为核心标准。然而，在蒸馏训练阶段，主流方法仍沿用 ROUGE 或 LLM 直接排序，前者奖励提取式复制，后者缺乏稳定性。本文的切入点在于将排序目标从“文本比较”回归到“信息保留”，利用摘要内容单元（SCUs）作为中间表示，通过跨摘要的共识频率来量化信息价值，从而绕过 LLM 直接比较的不稳定性。

## 核心方法

### 方法参照系

本文问题属于对比学习蒸馏中的排序信号构建环节。标准流程（如 BRIO）要求一个排序函数 $R: S \rightarrow \mathbb{R}$ 对候选摘要集合 $S$ 进行打分，以最大化高质量摘要与低质量摘要之间的概率差异。本文的关键差异在于，不依赖 LLM 的直接比较或 n-gram 重叠，而是引入语义聚类作为排序的中介层。

### SCU 提取与语义向量化

设计动机在于解决 LLM 直接排序对输入顺序敏感的问题。SCURank 首先利用 LLM（gpt-4o-mini）从每个候选摘要 $s_i$ 中提取 SCUs，每个 SCU 代表一个独立的事实单元。随后，使用 all-mpnet-base-v2 编码器将 SCU 映射为向量空间中的点，以捕捉语义相似性而非表面词汇匹配。

$$ \mathbf{v}_{i,j} = \text{Encoder}(u_{i,j}) $$

其中 $u_{i,j}$ 是摘要 $s_i$ 中的第 $j$ 个 SCU，$\mathbf{v}_{i,j}$ 是其对应的语义向量。此步骤将离散的文本单元转化为可计算的几何对象，为后续聚类奠定基础。

### 聚类聚合与重要性评分

设计动机在于利用多模型生成的共识来过滤噪声并量化信息重要性。SCURank 将所有摘要的 SCU 向量聚合，使用 HDBSCAN 算法进行密度聚类。假设信息被越多模型选中，其重要性越高，因此簇的大小 $|C_k|$ 反映了该语义信息的共识程度。

$$ \phi(u_{i,j}) = |C_k|, \quad \text{if } u_{i,j} \in C_k $$

$$ \Phi(s_i) = \frac{\sum_{j=1}^{m_i} \phi(u_{i,j})}{\sqrt{\|s_i\|}} $$

其中 $\Phi(s_i)$ 是摘要 $s_i$ 的最终得分，$\|s_i\|$ 是摘要长度。分母中的平方根项用于惩罚冗长摘要，防止模型通过堆砌低价值信息获得高分。该评分机制将排序问题转化为信息丰富度的量化问题，避免了 LLM 比较中的主观偏见。

## 实验评估

实验在 CNN/DailyMail 和 XSum 数据集上进行，对比基线包括 ROUGE、BERTScore、BLANC 和 GPTRank。基线覆盖了词汇重叠、语义嵌入和 LLM 直接排序三条路线，但缺失了领域内常用的 NLI 事实性指标（如 SummaC、MiniCheck）作为排序基线，这可能限制了结论在事实一致性维度的普适性。

| 数据集 | 方法 | ROUGE-1 | ROUGE-2 | BLEURT | BERTScore |
| :--- | :--- | :--- | :--- | :--- | :--- |
| CNN/DM (LLMs-9) | GPTRank | 43.8±1.12 | 20.0±1.66 | 51.4±1.36 | 69.7±0.66 |
| CNN/DM (LLMs-9) | **SCURank** | **44.8±0.28** | **20.5±0.81** | 51.7±0.78 | **70.0±0.27** |
| XSum (LLMs-9) | GPTRank | 43.0±0.35 | 19.8±0.75 | 51.2±0.81 | 69.1±0.38 |
| XSum (LLMs-9) | **SCURank** | **44.3±0.87** | **20.8±0.96** | **51.7±0.67** | **69.9±0.50** |

SCURank 在两个数据集上均优于 GPTRank，且在 CNN/DM 上 ROUGE-1 提升 1.0 分，XSum 上提升 1.3 分。稳定性测试显示，SCURank 的 Krippendorff’s $\alpha$ 达到 0.846，远超 GPTRank 在随机顺序下的表现，验证了其排序的一致性。

消融实验表明，多 LLM 数据源（LLMs-9）相比单 LLM 数据源（BASE）能提升模型的抽象性（Abstractiveness），降低覆盖率和密度。然而，SCURank 在 XSum 上的 BLEURT 得分（51.7）与 GPTRank（51.2）差距较小，且未显著超越 UnRank（MLE-only）在部分指标上的表现，暗示对比学习带来的增益可能部分源于数据多样性而非排序机制本身。

评估边界方面，论文主要依赖 ROUGE 和 BERTScore 等词汇/语义指标，未报告事实一致性（如 FActScore、SummaC）指标。代码已开源，但 SCU 提取依赖 gpt-4o-mini，其成本与性能平衡仅在附录中简要提及，缺乏不同 LLM 提取器对最终排序影响的系统性消融。

## 关联研究分析

从问题动机看，SCURank 与 FActScore 共享“原子事实分解”的核心思想，但应用阶段截然不同。FActScore 用于生成后的事实性验证，通过 NLI 模型判断每个原子事实是否被源文档支持；而 SCURank 用于生成前的训练信号构建，通过聚类频率判断信息的重要性。这种差异源于任务目标的不同：验证需要精确的逻辑蕴含判断，而排序需要鲁棒的信息量估计。SCURank 的聚类机制本质上是一种软投票，它容忍了单个 LLM 提取 SCU 时的噪声，这在训练数据构建中比验证任务更为关键，因为训练信号需要大规模且稳定。

从方法设计看，SCURank 与 GPTRank 同属 LLM 辅助排序，但 SCURank 将 LLM 的角色从“裁判”降级为“提取器”。GPTRank 依赖 LLM 直接比较两个摘要的优劣，这引入了 LLM 自身的偏见和顺序敏感性；SCURank 仅利用 LLM 提取语义单元，排序逻辑由确定性的聚类算法完成。这一设计解决了 LLM-as-Judge 在细粒度比较中的不稳定性，但引入了新的依赖：SCU 提取的质量直接决定了排序的上限。若 LLM 提取的 SCU 遗漏了关键信息或产生了幻觉单元，聚类频率将错误地放大这些噪声，导致排序偏差。

## 总结

本文要解决的核心矛盾是蒸馏训练中 LLM 直接排序的不稳定性与传统词汇指标的低效性。SCURank 通过引入摘要内容单元（SCUs）和聚类频率评分，将排序问题转化为信息丰富度的量化，从而绕过了 LLM 比较的顺序敏感性。实验证明该方法在 CNN/DailyMail 和 XSum 上显著优于 GPTRank，ROUGE-1 提升 1.0-1.3 分，且排序稳定性（Krippendorff’s $\alpha$ 0.846）远超基线。然而，论文仅验证了词汇与语义相似度指标的提升，未提供事实一致性指标的对比，且 SCU 提取依赖特定 LLM，其鲁棒性未充分探索。当候选摘要数量增加或源文档领域发生偏移时，SCU 聚类频率是否仍能准确反映信息重要性，论文未给出回答。
