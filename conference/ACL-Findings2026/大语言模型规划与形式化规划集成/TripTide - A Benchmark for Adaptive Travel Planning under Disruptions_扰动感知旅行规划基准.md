> 导读 大语言模型（Large Language Model, LLM）在旅行规划中常假设理想无扰动环境，导致生成的计划缺乏现实鲁棒性。现有基准如 TravelPlanner 和 TripCraft 仅评估静态约束满足，忽略了航班取消、天气突变等动态扰动对计划执行的影响。TripTide 通过引入扰动严重性等级与旅行者容忍度画像，构建首个动态扰动响应基准，并设计意图保留、响应性与适应性三维评估指标。该工作填补了 LLM 在动态环境规划评估上的空白，但缺乏符号验证机制，其逻辑可行性在长程任务中面临挑战。

## 研究背景

当 LLM 生成旅行计划时，其核心挑战在于将模糊的自然语言意图转化为满足多重硬约束（如预算、时间）的可行方案。这一过程通常依赖 LLM 的常识推理与模式匹配，但在面对现实世界中的突发状况（如航班取消、景点关闭）时，LLM 缺乏显式的状态追踪与逻辑验证机制，导致生成的修订计划往往违反前置条件或产生幻觉。为解决这一问题，神经符号集成范式引入外部符号规划器（如 PDDL 求解器）进行逻辑校验，但该范式在开放世界旅行规划中因建模复杂度过高而难以直接应用。

当前旅行规划基准主要聚焦于静态约束满足，如 TravelPlanner 评估预算与时间合规性，TripCraft 评估个性化偏好匹配。然而，这些基准假设计划一旦生成即可完美执行，忽略了旅行过程中不可避免的动态扰动。LLM 在长程规划中本就存在状态一致性衰减问题，若再叠加动态扰动，其规划可靠性将显著下降。现有研究缺乏对 LLM 在扰动下“重规划”能力的系统评估，导致无法判断 LLM 是否真正具备适应动态环境的规划能力，还是仅依赖静态模式匹配。

## 核心方法

### 方法参照系：动态扰动下的重规划流程

本文解决的问题属于开放世界自适应规划范畴，但区别于主流“自然语言 -> PDDL -> 符号求解”的神经符号流程，本文采用纯 LLM 驱动的“自然语言 + 扰动 -> LLM 生成修订计划 -> 多维评估”流程。该流程的关键差异在于省略了符号中间表示，直接依赖 LLM 的语义理解与生成能力处理扰动，并通过自定义指标评估修订质量，而非依赖符号验证器的逻辑正确性判定。

### 扰动建模与容忍度画像

传统基准将扰动视为单一事件，本文将其细化为严重性等级与用户容忍度两个维度。严重性分为 Step-Level（单活动影响）、Day-Level（单日影响）和 Plan-Level（整体计划影响）；容忍度分为 Flexi-Venturer（开放重路由）和 Plan-Bound（最小化变更）。这一设计动机在于解决现有方法无法区分“轻微调整”与“彻底重构”的评估盲区。通过元数据标注，TripTide 能够系统评估 LLM 在不同扰动强度与用户偏好下的响应策略，例如 Plan-Bound 用户期望 LLM 仅替换受影响的 POI，而 Flexi-Venturer 用户允许 LLM 重新优化整个日程。

### 三维适应性评估指标体系

为量化修订计划的质量，本文提出 Preservation of Intent、Responsiveness 和 Adaptability 三类指标。其中 Adaptability 进一步分解为语义、空间与序列三个子指标。语义适应性 $A_{sem}$ 通过 BERT 嵌入计算初始与修订计划中 POI 与用户画像的余弦相似度差异，衡量主题一致性：

$$ A_{sem} = |S_{ps}[i] - S_{ps}[r]| $$

其中 $S_{ps}[i]$ 和 $S_{ps}[r]$ 分别为初始与修订计划的画像得分。该公式的物理含义是：若修订计划的主题与用户偏好偏离过大，则得分高，表明语义漂移严重。空间适应性 $A_{spa}$ 基于 POI 与最近公共交通站点的距离衰减函数，评估空间便利性变化；序列适应性 $A_{seq}$ 使用归一化编辑距离衡量 POI 顺序的变动。这一指标体系的设计动机在于解决传统成功率指标无法捕捉“计划结构变化”的缺陷，能够区分 LLM 是进行了保守的局部修复还是激进的全局重构。

## 实验评估

实验在 TripTide 基准上进行，对比 GPT-4o、Qwen2.5-7B-Instruct 和 Phi-4-mini-Instruct 在 3 天、5 天、7 天计划中的表现。基线覆盖审计显示，本文未对比 LLM+P 等符号混合架构，导致无法直接评估纯 LLM 在逻辑严谨性上的具体劣势。主实验结果显示，GPT-4o 在 5 天计划中 Final Pass Rate 达到 41.98%，但在 7 天计划中降至 32.54%，表明长程扰动处理能力随复杂度下降。Qwen2.5-7B 在 7 天计划中 Hard Constraint Pass Rate (HCPR) 降至 25.16%，显示其在长程动态约束下易失效。

| 模型 | 计划时长 | Final Pass Rate (%) | HCPR Micro (%) | Responsiveness (%) | $A_{seq}$ |
| :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-4o | 3-day | 29.37 | 50.93 | 89.53 | 10.89 |
| GPT-4o | 5-day | 41.98 | 67.38 | 81.79 | 1.86 |
| GPT-4o | 7-day | 32.54 | 55.59 | 79.82 | 5.58 |
| Qwen2.5-7B | 7-day | 16.27 | 25.16 | 88.67 | 24.04 |

消融分析显示，Phi-4-mini 在 7 天计划中 Responsiveness 达到 100.00%，但 Final Pass Rate 仅为 3.06%，表明其能识别扰动但无法生成可行修订。GPT-4o 在 5 天计划中 $A_{seq}$ 仅为 1.86，显示其倾向于保守的序列保持策略，而 Qwen2.5-7B 的 $A_{seq}$ 高达 24.04，表明其进行激进重排。评估边界方面，本文依赖 LLM-as-a-Judge 和人工评估，缺乏形式化验证，且未报告计算效率指标，可复现性依赖匿名代码库。

## 关联研究分析

从问题动机看，TripTide 与 TravelPlanner 均聚焦旅行规划，但 TravelPlanner 假设静态环境，TripTide 引入动态扰动，这一差异源于对“现实鲁棒性”的不同定义。TravelPlanner 的 SOTA 方法如 LLM-Modulo 依赖符号验证器保证逻辑正确性，而 TripTide 完全省略符号层，导致其在长程任务中 HCPR 显著低于混合架构预期。这一冲突暗示：在开放世界旅行规划中，纯 LLM 的语义灵活性可能以牺牲逻辑严谨性为代价，尤其是在 7 天以上长程任务中。

从方法设计看，TripTide 与 SCOPE 均处理开放环境适应，但 SCOPE 通过符号世界模型演化实现闭环反馈，TripTide 通过自然语言反馈实现。SCOPE 的符号世界模型能显式追踪状态变化，而 TripTide 依赖 LLM 内部隐式状态表示，这导致 TripTide 在长程计划中空间偏差随计划长度增加而减小（GPT-4o 7 天 $A_{spa}$ 为 0.30），但序列保持能力下降。这一差异表明：纯 LLM 在长程规划中可能通过牺牲局部序列一致性来换取全局空间合理性，但这一权衡机制尚未被显式建模。

## 总结

TripTide 针对 LLM 旅行规划中“静态假设”与“动态现实”的矛盾，通过引入扰动严重性与用户容忍度画像，构建了首个动态扰动响应基准。其核心贡献在于设计了语义、空间、序列三维适应性指标，量化了 LLM 在扰动下的重规划行为。实验证明 GPT-4o 在 5 天计划中 Final Pass Rate 达 41.98%，但 7 天计划中 HCPR 降至 25.16%，显示纯 LLM 在长程动态约束下逻辑可行性显著衰减。该工作的边界在于缺乏符号验证机制，无法保证修订计划的硬约束合规性。当计划长度超过 7 天时，LLM 是否必然因状态追踪失效而陷入“响应性高但可行性低”的困境，仍需进一步验证。
