# ACL-Findings2026最新论文 ｜Learning from Failures: Error Notebook-guided Secure Code Generation ｜错误笔记引导的安全代码生成

研究机构：中南大学

作者：Xinyu Zhong、Peng Lan、Zhifang Liao

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_968c13d1a977)

> 大语言模型（LLM）在生成代码时面临功能正确性与安全性的内在冲突，现有检索增强生成（RAG）方法仅注入静态安全指南，缺乏对模型自身历史失败经验的动态利用，导致在未见过的漏洞类型上泛化能力不足。SAFENOTE 通过构建安全与功能双维度的错误笔记，将模型的历史失败转化为对比性指导，在不重新训练模型的前提下提升安全性。该方法在 GPT-4o-mini 上将 CodeGuard+ 基准的 SecurePass@1 从 60.21% 提升至 66.70%，但其在部分开源模型上的功能性能出现显著退化，暴露了经验积累机制对模型基线能力的依赖。

## 研究背景

当 LLM 生成代码时，安全漏洞与功能缺陷往往同时存在，且二者在模型内部表示中相互制约。安全约束要求代码避免特定模式（如 SQL 注入），而功能逻辑要求代码满足特定行为，这种冲突导致单纯优化安全性常以牺牲功能为代价。为在不修改模型参数的前提下缓解此矛盾，RAG 成为主流范式，它通过检索外部安全知识注入提示词，引导模型生成安全代码。然而，标准 RAG 仅关注“做什么”（安全指南），忽略了“避免什么”（模型自身的历史错误），且检索机制常优先安全语义而牺牲任务特定的功能意图，导致安全与功能的平衡处于次优状态。

安全代码生成领域的研究已从静态模式匹配转向动态执行与经验学习。早期方法如 SafeCoder 和 ProSec 通过微调将安全意识嵌入参数，但训练成本高且难以适应新漏洞；RESCUE 等 RAG 方法虽降低了训练成本，但其知识库是静态的，无法吸收模型在开放环境中产生的新失败经验。这种静态性导致模型在面对未见过的 Common Weakness Enumeration (CWE) 类型时，仍会重复相同的错误模式。SAFENOTE 的切入点在于，将模型的历史失败经验显式化、结构化，并作为动态检索源，使模型能够从自身的错误中学习，从而在保持功能正确性的同时提升安全性。

## 核心方法

### 方法参照系

SAFENOTE 属于 RAG 路线，其基础流程与 RESCUE 相似：从层级知识库中检索安全指南和代码样本，注入提示词以指导生成。关键差异在于，标准 RAG 仅依赖静态的外部知识，而 SAFENOTE 引入了“错误笔记”机制，将模型自身的历史失败转化为动态的、可检索的对比性指导，从而弥补了静态知识在特定失败模式上的覆盖不足。

### 双维度错误笔记构建

SAFENOTE 的核心创新在于构建安全错误笔记（Security Error Notebook, $N_{sec}$）和功能错误笔记（Function Error Notebook, $N_{func}$），将抽象的安全规则转化为具体的失败案例。每条安全错误笔记 $e_s$ 定义为五元组：

$$ e_s = \langle T, C_{err}, D, S, G \rangle $$

其中 $T$ 为任务描述，$C_{err}$ 为含漏洞的生成代码，$D$ 为通过 Semgrep 静态分析提取的漏洞摘要，$S$ 为从 SafeCoder 数据集切片得到的安全代码，$G$ 为修正指导。这一设计解决了标准 RAG 仅提供“正确示例”而缺乏“错误警示”的问题，使模型能直观识别其历史错误模式。功能错误笔记 $e_f$ 则记录执行失败的代码、运行时回溯和修复建议，确保功能正确性不被安全优化牺牲。

### 动态进化与语义合并

为避免笔记库冗余并适应新错误模式，SAFENOTE 设计了基于语义相似度的动态合并机制。对于新失败实例 $x$ 和现有笔记 $e$，计算余弦相似度：

$$ S(x, e) = \frac{\phi(x) \cdot \phi(e)}{\|\phi(x)\| \|\phi(e)\|} $$

其中 $\phi(\cdot)$ 为 BAAI/bge-base-en-v1.5 编码器。若 $S(x, e)$ 超过阈值 $\tau_{sim}$，新失败被合并至现有笔记，增加其频率计数；否则创建新笔记。这一机制确保了笔记库的紧凑性，同时通过频率计数突出常见陷阱，为后续对比性指导提供权重依据。在线进化阶段，SAFENOTE 通过 CodeQL 进行安全验证，通过单元测试进行功能验证，将新失败实时固化至笔记库，实现持续自适应改进。

## 实验评估

实验在 CodeGuard+（安全+功能）和 LiveCodeBench (LCB)（纯功能）上进行，对比基线包括 LLM alone 和 RESCUE。缺失 SafeCoder 等微调方法和 SecCoderX 等强化学习方法的对比，限制了与训练式方法的直接比较。

| 模型 | 方法 | CodeGuard+ SP@1 | CodeGuard+ SR | CodeGuard+ Pass@1 | LCB Pass@1 |
|---|---|---|---|---|---|
| GPT-4o-mini | LLM alone | 60.21 | 70.21 | 82.23 | 37.96 |
| GPT-4o-mini | RESCUE | 65.68 | 78.07 | 80.23 | 36.25 |
| GPT-4o-mini | SAFENOTE | 66.70 | 81.38 | 78.40 | 33.98 |
| Qwen3-8B | LLM alone | 50.53 | 63.95 | 79.68 | 18.86 |
| Qwen3-8B | RESCUE | 56.70 | 73.19 | 76.92 | 24.09 |
| Qwen3-8B | SAFENOTE | 61.60 | 76.44 | 79.89 | 34.30 |
| Llama-3-8B | LLM alone | 53.72 | 62.87 | 86.28 | 14.55 |
| Llama-3-8B | RESCUE | 49.26 | 61.28 | 80.75 | 12.61 |
| Llama-3-8B | SAFENOTE | 50.64 | 75.21 | 69.68 | 10.34 |

在 GPT-4o-mini 上，SAFENOTE 的 SP@1 达到 66.70%，高于 RESCUE 的 65.68% 和 LLM alone 的 60.21%。然而，在 Llama-3-8B 上，SAFENOTE 的 LCB Pass@1 从 14.55% 降至 10.34%，表明功能性能出现显著退化。这一结果与论文声称的“最小或无功能退化”存在矛盾，暗示错误笔记机制对模型基线能力的依赖：在能力较弱的模型上，动态检索可能引入噪声，导致功能性能下降。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码未公开，超参数（如 $\tau_{sim}$）未详细说明，可复现性受限。LCB 评估仅依赖单元测试，未涉及多轮交互或供应链安全，评估协议较为单一。

## 关联研究分析

从问题动机看，SAFENOTE 与 RESCUE 同属 RAG 路线，但 RESCUE 依赖静态知识库，而 SAFENOTE 引入动态错误笔记。这一差异源于对“模型自身失败”的利用：RESCUE 假设外部知识足够覆盖所有漏洞，而 SAFENOTE 认为模型在特定任务上的失败模式是独特的，需通过经验积累来弥补。然而，SAFENOTE 未对比 SafeCoder 等微调方法，无法证明 RAG 路线在安全性上的优越性，仅能证明其在 RAG 框架内的改进。

从方法设计看，SAFENOTE 与 CodeGuarder 同属 RAG 路线，但 CodeGuarder 侧重查询分解和根因注入，而 SAFENOTE 侧重失败经验记录。CodeGuarder 通过结构化“安全课程”提升检索粒度，而 SAFENOTE 通过对比性指导避免重复错误。这一差异反映了两种不同的知识利用策略：CodeGuarder 强调知识的结构化呈现，SAFENOTE 强调知识的动态积累。SAFENOTE 未探索查询侧增强，其检索精度可能受限于笔记库的覆盖范围，这在数据充足时是否仍有增益，论文未给出回答。

## 总结

SAFENOTE 旨在解决 LLM 代码生成中功能与安全性的权衡难题，通过构建双维度错误笔记，将模型的历史失败转化为动态对比性指导，弥补了标准 RAG 缺乏经验积累的缺陷。该方法在 GPT-4o-mini 上将 CodeGuard+ SP@1 从 60.21% 提升至 66.70%，证明了经验积累的有效性。然而，其在 Llama-3-8B 上的 LCB Pass@1 从 14.55% 降至 10.34%，暴露了动态检索对模型基线能力的依赖，暗示错误笔记机制在能力较弱模型上可能引入噪声。当模型基线能力较弱时，错误笔记的动态更新是否会导致功能性能的持续退化，论文未给出回答。
