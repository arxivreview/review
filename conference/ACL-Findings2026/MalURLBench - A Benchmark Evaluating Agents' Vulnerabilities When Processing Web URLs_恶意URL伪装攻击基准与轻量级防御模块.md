# ACL-Findings2026最新论文 ｜MalURLBench: A Benchmark Evaluating Agents' Vulnerabilities When Processing Web URLs ｜恶意URL伪装攻击基准与轻量级防御模块

研究机构：浙江大学、重庆大学

作者：Dezhang Kong、Zhuxi Wu、Shiqi Liu 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.18113)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.18113)

> 大语言模型（LLM）驱动的Web智能体在访问网页前需判断URL合法性，但现有安全基准仅关注网页内容中的提示注入，忽略了URL结构本身被操纵的风险。本文指出LLM对伪装URL的识别能力极弱，导致智能体入口失守。通过构建包含61,845个实例的MalURLBench并微调轻量级模型URLGuard，证明了该威胁的普遍性及微调防御的有效性。尽管验证了前置过滤的可行性，但缺乏与系统级沙箱的横向对比及误报率评估，其实际部署中的任务成功率影响仍存疑。

## 研究背景

Web智能体的工作流分为两个阶段：LLM首先判断用户提供的URL是否可信，随后调用工具访问并解析网页内容。URL由子域名、二级域名（SLD）、顶级域名（TLD）、路径和参数组成，其中SLD和TLD标识网站身份，其余部分可被攻击者操纵以伪装合法来源。这种结构特性使得URL成为比自然语言指令更隐蔽的攻击向量，因为LLM通常缺乏对URL语义结构的深度理解，易将“official-link.***.com”误判为官方链接。

现有Web智能体安全研究聚焦于第二阶段，即网页内容中的恶意提示注入（如WAInjectBench、MUZZLE），假设URL本身是可信的。然而，一旦LLM在阶段一接受恶意URL，攻击者即可利用后续网页内容实施更复杂的操纵，这使得入口安全成为整个工作流的关键瓶颈。尽管已有研究揭示URL操纵可提升攻击成功率，但缺乏系统化的基准来量化LLM对此类威胁的脆弱性，导致防御机制设计缺乏数据支撑。

本文切入点在于将安全评估前置至URL接受阶段，定义了一种新的威胁模型：攻击者仅操纵子域名、路径或参数，而SLD和TLD固定为已知恶意网站。通过构建MalURLBench，本文旨在回答LLM对恶意URL的识别能力、影响攻击效果的因素以及如何通过轻量级模块增强安全性，填补了Web智能体安全评估中入口环节的空白。

## 核心方法

### 方法参照系

本文问题属于Web智能体安全防御中的输入过滤环节。通用流程为：接收用户输入（场景提示+URL）→ LLM判断风险 → 执行或拒绝。与现有针对网页内容注入的防御不同，本文仅处理URL字符串，不涉及DOM解析或页面渲染，因此其参照系是文本分类任务而非多模态内容检测。

### 基准构建与变异优化

MalURLBench的构建核心在于自动化生成高质量攻击样本。传统红队测试依赖人工设计攻击模板，效率低且覆盖度有限。本文引入变异优化算法，利用Textual Gradient分析攻击失败原因，并基于Exemplar Optimization生成新模板。设攻击模板集合为 $T$，风险分数函数为 $F_s(M)$，优化目标为最大化 $F_s(M)$ 直至超过阈值 $Thd$。具体而言，对于未达标模板 $t$，算法读取评估日志，通过DeepSeek-Coder计算文本梯度得到失败原因 $reason$，结合成功示例 $E$ 和约束 $C$ 生成新模板 $t'$。这一过程将攻击样本生成从静态人工设计转变为动态迭代优化，显著提升了基准对LLM盲区的覆盖能力。

### URLGuard防御机制

URLGuard是一个基于QLoRA微调的轻量级前置过滤模块，旨在解决LLM缺乏恶意URL知识的问题。其设计动机在于：若LLM本身无法识别恶意URL，则需外部模块介入。URLGuard选择Llama2-7B-chat-hf作为骨干，因其原始ASR高且参数量小，适合独立部署。训练数据仅包含280个实例（140恶意+140良性），来自单一场景（在线购物）的模板扩展。微调采用4-bit NF4量化和LoRA适配器（rank=16, alpha=32），在查询、键、值及输出注意力投影上训练。防御有效性定义为 $E = F(M) - F(D(M))$，其中 $D(M)$ 表示受URLGuard保护的模型。该公式量化了防御模块对原始风险分数的降低幅度，验证了微调在极小数据量下对URL识别能力的提升。

## 实验评估

实验在12个流行LLM上进行，包括GPT-4o、Llama-3-70B、DeepSeek-Coder等，使用MetaGPT作为智能体系统。基线覆盖闭源与开源模型，但未对比系统级沙箱（如ceLLMate）或页面内容检测器（如WebSentinel），限制了防御路线的横向比较。

| 模型 | 平均风险分数 $F(M)$ | 优化后 $F(M)$ | URLGuard后 $F(D(M))$ |
| :--- | :--- | :--- | :--- |
| Mixtral-8x7b | 1.00 | 1.00 | / |
| Llama2-7B-chat-hf | 0.94 | 0.94 | 0.05 |
| GPT-4o-mini | 0.97 | 0.97 | / |
| DeepSeek-coder | 0.33 | 0.33 | / |

数据显示，MoE模型（如Mixtral-8x7b）风险分数高达1.00，而Dense模型（如Llama-3-70B）较低，表明MoE架构因专家激活依赖训练数据分布，对URL结构理解更脆弱。URLGuard在Llama2-7B上将风险分数从0.94降至0.05，降幅达94.7%，证明微调有效。然而，URLGuard在GPT-4o-mini等闭源模型上未提供数据，且未报告误报率，无法评估其对合法URL的拦截影响。

消融实验显示，模型规模与风险分数呈负相关，但MoE模型在同等规模下风险更高，暗示专家路由机制在缺乏对抗样本训练时的缺陷。变异优化算法将部分模型的风险分数提升（如GPT-3.5-turbo从0.01升至0.23），验证了基准质量的提升。

评估边界方面，本文仅关注URL接受率，未评估端到端任务成功率，无法判断URLGuard是否因过度拦截导致正常任务失败。代码已开源，但训练数据仅280条，超参数固定，复现性受限于数据规模。

## 关联研究分析

从问题动机看，本文与WebSentinel（Wang et al., 2026）均利用LLM语义理解检测恶意内容，但WebSentinel分析页面DOM和文本，针对阶段二的内容注入，而本文仅分析URL字符串，针对阶段一的入口欺骗。这一差异源于任务特性：URL是结构化文本，无需多模态解析，因此轻量级模型即可胜任；而页面内容复杂，需更强语义理解。本文未探索URL与页面内容的联合防御，可能忽略攻击者通过URL诱导访问后，再在页面中实施二次注入的组合攻击。

从方法设计看，本文与ceLLMate（Meng et al., 2025）同属系统级防御，但ceLLMate在HTTP层强制执行权限策略，属于硬性隔离，而URLGuard在LLM输入层进行软性过滤，依赖模型判断。ceLLMate不依赖模型对齐，安全性更高，但可能限制智能体灵活性；URLGuard灵活但依赖微调质量，存在被绕过风险。本文未对比两者在相同场景下的效率-安全权衡，URLGuard的误报率未知，若其拦截合法URL，则整体任务成功率可能低于ceLLMate的硬性策略。

## 总结

本文核心矛盾在于LLM对URL结构语义的解析脆弱性导致Web智能体入口失守，而现有基准仅关注页面内容注入。本文通过构建MalURLBench和URLGuard，证明了恶意URL伪装的高攻击成功率（32.9%-99.9%）及微调防御的有效性（降低30%-99%）。其边界在于仅评估URL接受率，未验证端到端任务成功率，且缺乏与系统级沙箱的对比。当URLGuard部署在真实环境中，其误报率对正常任务成功率的影响如何，论文未给出回答。
