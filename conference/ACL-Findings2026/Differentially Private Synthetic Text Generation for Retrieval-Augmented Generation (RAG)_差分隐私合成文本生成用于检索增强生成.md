# ACL-Findings2026最新论文 ｜Differentially Private Synthetic Text Generation for Retrieval-Augmented Generation (RAG) ｜差分隐私合成文本生成用于检索增强生成

研究机构：日本东京科学大学、日本理化学研究所

作者：Junki Mori、Kazuya Kakizaki、Taiki Miyagawa 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.06719)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.06719)

> 检索增强生成（Retrieval-Augmented Generation, RAG）在敏感数据场景下面临隐私泄露风险，现有基于查询时差分隐私（Differential Privacy, DP）的方法因隐私预算随查询次数线性消耗，导致多轮交互下效用急剧下降。本文提出 DP-SynRAG，通过离线生成具备 DP 保证的合成知识库，将隐私成本从“每次查询”转移至“一次性生成”，从而在固定预算下支持无限次查询。该方法结合 DP 软聚类与私有预测机制，在医疗等垂直领域显著优于查询时 DP 基线，但其对动态知识库的适应性及长尾知识保留能力尚存疑。

## 研究背景

当 RAG 系统处理包含患者姓名或交易记录的敏感数据库时，即使面对良性查询，大语言模型（LLM）也可能在生成回答中复述检索到的原始文档片段，导致个人信息意外泄露。这种泄露风险源于检索机制将敏感上下文直接注入 LLM 的生成条件中，而传统的模型对齐或提示工程无法从数学上阻断这种信息流。为提供形式化保证，差分隐私（DP）被引入 RAG 防御体系，其核心思想是通过注入噪声限制单条记录对输出的影响。然而，现有 DP-RAG 方法（如 Grislain, 2025; Koga et al., 2025）通常在每次用户查询时执行私有预测，即对 LLM 的输出 token 分布进行扰动。这种“查询时噪声注入”范式导致隐私预算 $\epsilon$ 随查询数量 $Q$ 线性累积，在典型的多轮对话场景中，固定预算迅速耗尽，迫使系统要么拒绝服务，要么大幅降低回答质量。

RAG 隐私保护的主流路线分为查询时 DP 与数据预处理两类。查询时 DP 虽实现简单，但受限于预算消耗速率，难以支撑高频交互；数据预处理路线（如 Zeng et al., 2025 的文档改写）虽可避免在线噪声，但缺乏 DP 保证或仅保留全局统计特性，丢失了 RAG 所需的细粒度事实细节。本文切入点在于利用 LLM 的生成能力，在离线阶段一次性生成具备 DP 保证的合成文本库。由于合成数据生成后的检索与生成过程属于 DP 的后处理（post-processing），不再消耗额外隐私预算。这一设计将隐私保护从“在线防御”前移至“离线数据合成”，解决了多查询场景下预算线性增长的瓶颈，同时通过聚类机制保留了原始数据的局部语义结构。

## 核心方法

### 方法参照系

本文问题属于 DP 合成数据生成范畴，但区别于通用的 DP 文本生成（如 Amin et al., 2024），其目标不是生成符合全局分布的通用文本，而是生成能支撑 RAG 检索准确性的“局部性保留”文本。通用私有预测方法仅捕获数据集的平均特性，导致合成文本缺乏特定主题的事实细节，无法作为有效的 RAG 上下文。

### DP 软聚类与局部知识保留

为克服私有预测仅保留全局平均特性的局限，DP-SynRAG 在生成前引入 DP 软聚类阶段。该阶段首先利用 LLM 从每篇文档中提取 $K$ 个代表性关键词，构建关键词直方图 $h(D)$，并添加高斯噪声 $\mathcal{N}(0, \sigma_h^2 I)$ 以满足 DP：

$$ h'(D) = h(D) + \mathcal{N}(0, \sigma_h^2 I) $$

随后，基于噪声直方图选取 Top-$R$ 关键词作为聚类中心，文档被分配至至多 $L$ 个簇，以控制重叠度。设计动机在于：通过语义相似的文档分组，使私有预测在簇内执行时，生成的合成文本能保留该簇特有的主题知识（如特定疾病名称），而非整个数据集的模糊平均。此外，利用文档嵌入均值 $\mu(C_r)$ 进行基于相似度的检索，进一步剔除簇内离群点，确保子集 $S_r$ 的语义一致性。

### 并行私有预测与自过滤

在聚类完成后，DP-SynRAG 对每个子集 $S_r$ 并行执行私有预测。对于子集中的每篇文档 $d_i$，LLM 生成重述文本的 logit，将其裁剪至 $[-c, c]$ 并求和，通过 softmax 采样 token。该过程等价于指数机制，敏感度为 $c$。由于各簇操作并行，总隐私预算通过重叠并行组合定理控制，而非简单相加。最后，引入 LLM 自过滤步骤，基于下游任务相关性剔除低质量合成文本。设计动机在于：小样本子集的私有预测易产生随机噪声文本，自过滤作为后处理步骤，在不消耗隐私预算的前提下提升合成库的检索效用，弥补了 DP 噪声导致的效用损失。

## 实验评估

实验在 Medical Synth、Movielens 和 SearchQA 三个数据集上进行，对比基线包括 Non-RAG、DP-Synth（全局私有预测）和 DP-RAG（查询时 DP）。基线覆盖审计显示，本文缺失与加密检索（如 p2RAG）或投毒防御方法的对比，仅聚焦于 DP 路线内部的效用比较。

| 数据集 | 方法 | Phi-4-mini | Gemma-2-2B | Llama-3.1-8B |
| :--- | :--- | :--- | :--- | :--- |
| Medical Synth | DP-SynRAG | 67.26 | 67.06 | 61.26 |
| Medical Synth | w/o Retrieval | 65.92 | 61.46 | 57.74 |
| Medical Synth | Hard clustering | 42.52 | 51.40 | 29.38 |
| SearchQA | DP-SynRAG | 89.61 | 85.10 | 91.18 |
| SearchQA | w/o Self-filtering | 89.61 | 85.10 | 91.18 |

主结果显示，DP-SynRAG 在 Medical Synth 上显著优于 DP-Synth，证明聚类对保留局部事实（如虚构疾病名）至关重要。在 SearchQA 上，自过滤步骤未带来提升，表明该数据集问题类型多样，过滤阈值可能不适配。消融实验揭示，硬聚类（$L=1$）导致准确率大幅下降（如 Llama-3.1 从 61.26 降至 29.38），证实软聚类对避免文档被无关高频词主导的关键作用。

评估边界方面，论文未报告计算延迟与内存开销，仅关注准确率。隐私评估通过统计患者姓名泄露次数，但未提供形式化的成员推断攻击（MIA）成功率对比。代码未公开，超参数（如 $\epsilon$ 分配、$K, R, L$）仅在附录中给出，复现性依赖对 DP 组合定理实现的精确理解。

## 关联研究分析

从问题动机看，DP-SynRAG 与 Private-RAG（Wu et al., 2025）均旨在解决 DP 预算消耗问题，但路径截然不同。Private-RAG 通过每文档隐私过滤器在线控制预算，适用于动态更新的知识库；而 DP-SynRAG 依赖离线合成，一旦生成，知识库即固定。这种差异源于任务特性：Private-RAG 假设数据源持续变化，需在线适应；DP-SynRAG 假设数据源静态，追求一次性成本最小化。若知识库频繁更新，DP-SynRAG 需重新生成合成库，其计算成本可能超过 Private-RAG 的在线过滤开销，论文未对此进行量化对比。

从方法设计看，DP-SynRAG 与 Amin et al. (2024) 的私有预测框架共享核心机制，但引入了聚类以解决局部性缺失。Amin et al. 的方法适用于生成通用合成数据用于训练，不要求保留特定实例的细节；DP-SynRAG 则通过 DP 聚类将数据空间分割，使私有预测在局部子空间执行。这一改进的根源在于 RAG 对“检索准确性”的依赖：全局平均文本无法提供足够的区分度以支持 Top-k 检索。然而，聚类本身引入了新的隐私-效用权衡：簇划分的质量直接影响合成文本的语义纯度，而 DP 噪声可能扭曲簇边界，导致语义漂移。论文通过软聚类缓解此问题，但未分析簇数量 $R$ 对隐私预算分配的具体影响。

## 总结

DP-SynRAG 解决了 RAG 系统中 DP 预算随查询次数线性增长的核心矛盾，通过离线生成具备 DP 保证的合成知识库，将隐私成本固定化。其关键在于利用 DP 软聚类保留局部语义，使私有预测生成的文本具备 RAG 所需的细粒度事实细节。实验证明，在 Medical Synth 上，该方法在固定预算下显著优于查询时 DP 基线，且软聚类对性能提升至关重要。然而，其边界在于假设知识库静态，且合成过程可能丢失长尾知识。当知识库包含大量低频但关键的实体时，DP 聚类是否会导致这些实体被归入噪声簇而丢失，论文未给出回答。
