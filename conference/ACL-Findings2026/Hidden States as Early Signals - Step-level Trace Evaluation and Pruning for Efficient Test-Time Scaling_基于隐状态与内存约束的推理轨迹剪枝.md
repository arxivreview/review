> 并行采样通过生成多条推理路径提升准确率，但长轨迹与多路径叠加导致算力成本与端到端延迟激增，且现有剪枝信号（相似度、置信度）无法可靠区分正确与错误轨迹。本文切入点在于发现隐状态在推理早期即包含质量判别信号，且延迟瓶颈主要来自 GPU 内存饱和引发的排队而非 Token 生成本身。STEP 训练轻量级评分器评估步骤质量，并以内存饱和为触发条件动态剪枝低分轨迹。该方法在降低延迟 45%–70% 的同时提升准确率，但其效果高度依赖特定硬件配置与内存压力场景，通用性存疑。

## 研究背景

并行采样的效率瓶颈源于两个相互纠缠的因素：轨迹长度与系统调度。Self-Consistency (SC) 生成 $N$ 条独立轨迹后通过多数投票聚合答案，其计算成本随 $N$ 线性增长。当单条轨迹包含数千 Token 时，$N=64$ 的总 Token 量可达数十万，直接推高推理延迟。更隐蔽的问题在于，错误轨迹往往比正确轨迹更长——模型在逻辑断裂后倾向于继续生成以“挽救”推理，导致资源被浪费在注定失败的分支上。

现有加速方案主要沿两条路径展开：一是基于文本相似度的剪枝（如 Slim-SC），通过移除表面相似的轨迹保留答案多样性；二是基于内部置信度的早期停止（如 DeepConf），假设高置信度对应正确性。前者面临根本性缺陷：多条有效路径可收敛至同一正确答案，文本相似性不等于推理冗余，可能误删正确轨迹。后者受制于模型校准问题，LLM 常对事实错误输出表现出高置信度（miscalibration），导致剪枝信号不可靠。这两类方法均聚焦于减少 Token 生成数量，却忽视了推理系统层面的行为：当 KV Cache 耗尽 GPU 内存时，推理引擎（如 vLLM）将未完成轨迹抢占至等待队列，其 KV Cache 被释放或卸载，待其他轨迹完成后重建。这一过程引入大量非计算性延迟，成为端到端延迟的主要来源。

本文的切入点在于同时解决信号可靠性与系统瓶颈问题。作者观察到，推理步骤边界处的隐状态已包含足够的质量判别信息，且早期步骤的信号即可区分有希望与无希望的轨迹。基于此，STEP 将隐状态评分与 GPU 内存状态耦合，不再依赖固定阈值或时间调度，而是以内存饱和为触发条件，在系统层面消除排队延迟。

## 核心方法

### 方法参照系

本文问题属于并行采样中的动态剪枝范畴，标准流程为：生成 $N$ 条轨迹 → 评估质量 → 剪枝低质轨迹 → 聚合答案。本文的关键差异在于：评估信号从外部（文本/置信度）转向内部（隐状态），触发机制从算法预设（阈值/时间）转向系统状态（内存饱和）。

### 隐状态步骤评分器

传统方法在轨迹完成后或基于固定间隔评估质量，而 STEP 在每步结束时实时评估。设计动机在于解决置信度信号不可靠的问题：隐状态编码了模型对当前推理状态的内部表征，比表面置信度更直接反映推理质量。

对轨迹 $t = (s_1, s_2, \dots, s_N)$，提取每步结束 Token 的最后一层隐状态 $\mathbf{h}_n \in \mathbb{R}^d$。步骤评分器 $f_\theta$ 为两层 MLP，将 $\mathbf{h}_n$ 映射为正确性概率：

$$\hat{y}_n = \sigma(\mathbf{W}_2 \cdot \text{ReLU}(\mathbf{W}_1 \mathbf{h}_n + \mathbf{b}_1) + \mathbf{b}_2)$$

其中 $\sigma(\cdot)$ 为 sigmoid 函数。训练采用加权二元交叉熵损失，权重 $\alpha = K_-/K_+$ 补偿步骤级不平衡（错误轨迹更长，产生更多负样本）。轨迹级分数定义为所有已生成步骤分数的均值：

$$S(t) = \frac{1}{n} \sum_{i=1}^{n} \hat{y}_{i[t]}$$

该聚合方式比单步分数更稳定，捕捉推理过程的连贯性演化，缓解单步评分的方差。

### 内存感知剪枝触发

现有方法依赖预设置信度阈值或固定时间调度触发剪枝，但未考虑推理系统行为。设计动机在于解决 KV Cache 抢占导致的排队延迟：当内存饱和时，继续生成低分轨迹只会加剧内存压力，延长所有轨迹的等待时间。

STEP 的触发机制为：当 GPU 内存满且无法调度下一步解码时，立即剪枝当前轨迹级分数最低的轨迹，释放其 KV Cache。这一设计无需额外超参数，且完全消除等待队列。与 DeepConf 的“低于阈值即停止”不同，STEP 的剪枝时机由系统状态决定，而非算法预设，从而将算法优化与系统调度深度耦合。

## 实验评估

实验在 Qwen3-4B-Thinking-2507、DeepSeek-R1-0528-Qwen3-8B、Phi-4-reasoning-plus(14B) 三个模型上，于 AIME-25、HMMT-24/25、GPQA-Diamond 四个基准上评估。基线覆盖 CoT、SC、Slim-SC、DeepConf，但未对比 BoM、Logit Averaging 等纯算法优化方法，也未包含依赖 RL 训练的 SOTA 方法（如 PaCoRe）。

| 模型 | 基准 | 方法 | 准确率 (%) | Token (×10³) | 延迟 (s) |
|---|---|---|---|---|---|
| DeepSeek-R1-8B | AIME-25 | SC | 83.3 | 1691.0 | 2259 |
| DeepSeek-R1-8B | AIME-25 | DeepConf | 81.7 | 916.4 | 1475 |
| DeepSeek-R1-8B | AIME-25 | STEP | 85.0 | 989.7 | 891 |
| Phi-4-14B | HMMT-24 | SC | 56.7 | 1356.4 | 2405 |
| Phi-4-14B | HMMT-24 | STEP | 58.3 | 579.8 | 630 |

STEP 在 DeepSeek-R1-8B 的 AIME-25 上以 85.0% 准确率超越 SC 的 83.3% 和 DeepConf 的 81.7%，同时延迟从 2259s 降至 891s（降低 60.6%）。在 Phi-4-14B 的 HMMT-24 上，STEP 以 58.3% 准确率在 630s 内完成，较 SC 的 2405s 实现 3.8× 加速。准确率提升与延迟降低同时出现，表明剪枝不仅节省计算，还通过消除排队改善了系统效率。

消融实验显示，GPU 内存利用率从 0.5 变化至 0.9 时，HMMT-25 上的准确率保持在 70.1 ± 1.8%，表明方法对内存预算不敏感。这一结果与隐状态早期信号的有效性一致：即使内存压力导致更早剪枝，评分器仍能准确识别有希望轨迹。然而，论文未报告不同 $N$ 值下的详细消融，也未分析剪枝轨迹数量对最终准确率的影响，难以判断准确率提升中有多少来自剪枝本身、多少来自加权投票。

评估边界方面，所有实验在单张 96GB NVIDIA GH200 GPU 上进行，代码已开源。但论文未报告置信区间，且仅在数学与科学推理任务上验证，未测试开放域生成任务。评估协议未区分训练成本与推理成本，STEP 的评分器需离线训练（5,000 正/5,000 负轨迹），这一成本在端到端评估中被忽略。

## 关联研究分析

从问题动机看，STEP 与 LATTS 均解决自适应计算分配问题，但切入点不同。LATTS 基于接受-拒绝采样机制，利用验证器对每步评分决定接受、拒绝或重试，实现步骤级粒度控制。STEP 则不依赖外部验证器，而是利用模型内部隐状态作为质量信号，且将剪枝触发与系统内存状态耦合。这一差异源于任务特性：LATTS 假设推理步骤质量可通过局部验证器有效评估，适用于可验证任务；STEP 的隐状态信号更通用，但依赖模型内部表征的质量，对模型校准程度敏感。

从方法设计看，STEP 与 DeepConf 同属早期停止路线，但触发机制存在根本差异。DeepConf 基于置信度阈值停止低分轨迹，属于算法预设；STEP 基于内存饱和触发剪枝，属于系统状态驱动。这一差异导致两者在效率维度上的表现不同：DeepConf 通过减少 Token 生成降低延迟，但无法消除排队延迟；STEP 通过消除排队直接降低端到端延迟，即使 Token 生成量与 DeepConf 相当（如 DeepSeek-R1-8B AIME-25 上，STEP 989.7k vs DeepConf 916.4k），延迟仍显著更低（891s vs 1475s）。这表明在内存受限场景下，系统级优化比算法级优化更具决定性。

## 总结

STEP 要解决的核心矛盾是并行采样中准确率与端到端延迟的权衡，现有方法因信号不可靠与系统瓶颈忽视而未能同时优化两者。本文抓住的切入点是隐状态的早期判别能力与内存饱和作为自然触发条件，前者解决了信号可靠性问题，后者解决了系统排队延迟问题。方法上，STEP 训练轻量级 MLP 评分器评估步骤质量，并以内存饱和为触发条件动态剪枝低分轨迹。实验证明，在 DeepSeek-R1-8B 的 AIME-25 上，STEP 以 85.0% 准确率实现 891s 延迟，较 SC 的 2259s 降低 60.6%。本文的边界在于：实验仅在单张 96GB GPU 上进行，未验证多卡或分布式场景；评分器需离线训练，成本未被纳入端到端评估；且仅在可验证任务上测试，开放域泛化性未知。当 GPU 内存充足、排队延迟占比低于 20% 时，内存触发机制的增益是否仍显著，论文未给出回答。
