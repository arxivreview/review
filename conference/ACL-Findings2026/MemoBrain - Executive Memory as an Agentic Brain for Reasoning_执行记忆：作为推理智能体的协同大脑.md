# ACL-Findings2026最新论文 ｜MemoBrain: Executive Memory as an Agentic Brain for Reasoning ｜执行记忆：作为推理智能体的协同大脑

研究机构：中国人民大学

作者：Hongjin Qian、Zhao Cao、Zheng Liu

论文原文见 [arXiv](https://arxiv.org/abs/2601.08079)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.08079)

> 工具增强智能体在长时程推理中因上下文窗口受限导致认知过载与任务对齐失效，现有跨任务持久记忆无法适应单任务内动态演化的推理结构。MemoBrain 提出“执行记忆”范式，将记忆从被动存储重构为主动控制机制，通过独立协同模型异步构建依赖感知记忆图并执行折叠与冲刷操作，在有界预算下维持推理连贯性。该方法在 BrowseComp-Plus 等基准上显著提升了基线智能体性能，但其仅限单任务生命周期且依赖独立模型部署，是否适用于跨会话经验复用尚存疑。

## 研究背景

工具增强智能体在执行复杂推理任务时，需交替进行逻辑推导与外部工具调用，这一过程产生大量瞬态执行痕迹（如原始搜索输出、代码报错日志）。这些痕迹迅速累积并占据大语言模型（LLM）有限的上下文窗口，导致关键任务证据被噪声淹没，引发认知过载。为缓解此问题，研究界引入了记忆机制，但现有方案多聚焦于跨任务持久化（如用户偏好存储）或长文档摘要，缺乏对单任务内推理轨迹实时结构化管理的能力。

现有上下文管理方法如 AgentFold 和 DeepAgent 虽能压缩冗余步骤，但将记忆控制内嵌于主推理模型中，导致记忆管理与推理执行耦合，且仅作为效率优化手段，未建模推理步骤间的逻辑依赖。这种被动压缩无法在长时程任务中维持全局任务对齐，当推理路径出现分支或回溯时，简单摘要会丢失关键依赖关系。MemoBrain 的切入点在于将记忆解耦为独立的协同模型（Co-pilot），将其定义为“执行记忆”——一种任务内、在线演化、专门用于控制信息流的认知组件，而非静态知识库。

## 核心方法

### 方法参照系

本文问题属于智能体上下文管理范畴，但区别于传统的检索增强生成（RAG）或长短期记忆分层架构。通用流程通常由主模型自行决定何时压缩或丢弃上下文，而本文的关键差异在于引入独立于主推理模型的执行记忆模块，通过显式的图结构建模推理依赖，并异步执行记忆操作，实现推理与记忆管理的解耦。

### 依赖感知记忆构建

传统方法将推理步骤视为线性序列，难以捕捉中间结论间的因果依赖。MemoBrain 将每个完成的推理片段（Episode）抽象为“思维单元”（Thought），并显式建模其依赖关系。设计动机在于解决线性压缩导致的逻辑断裂问题，确保后续推理能准确回溯前置条件。思维单元 $v_t$ 由主模型异步生成，其依赖集 $Dep(v_t)$ 指向支撑当前结论的前置思维单元，形成有向记忆图 $G_t = (V_t, E_t)$：

$$
E_t = E_{t-1} \cup \{ (v_i, v_t) \mid v_i \in Dep(v_t) \}
$$

该公式表明，新思维单元不仅记录自身结果，还通过边连接至其依赖的前置节点，从而在图中保留推理的逻辑骨架，而非仅保留时间顺序。

### 预算约束下的主动记忆管理

当上下文接近预算上限时，主模型无法自行判断哪些信息可安全丢弃。MemoBrain 引入两种显式操作：折叠（FOLD）与冲刷（FLUSH）。设计动机在于区分“已解决子任务”与“无效探索路径”，避免简单截断导致的语义丢失。对于已得出结论的子轨迹 $T_{i:j}$，执行折叠操作将其压缩为单一摘要节点 $\bar{v}$：

$$
\bar{v} = \text{Fold}(T_{i:j}), \quad \text{where } T_{i:j} \text{ is resolved}
$$

对于无效或过时的思维单元 $v_k$，执行冲刷操作将其替换为紧凑表示 $\hat{v}_k$，保留其存在性但移除执行细节。这种区分处理确保了在有限预算下，既保留了已验证结论的完整性，又清除了噪声干扰，使工作上下文始终聚焦于高价值的推理主干。

## 实验评估

实验在 GAIA、WebWalker 和 BrowseComp-Plus 三个长时程推理基准上进行，基线涵盖直接推理、RAG 及工具集成推理方法，包括 AgentFold、DeepAgent 等上下文管理代表工作。MemoBrain-8B 作为插件集成至 GLM-4.6 和 DeepResearch-30B-A3B 中。

| 方法 | BrowseComp-Plus Acc (%) | Search Calls |
|---|---|---|
| DeepResearch-30B-A3B | 51.93 | 17.14 |
| MemoBrain w/ DeepResearch-30B-A3B | 60.36 | 27.12 |
| GLM-4.6 | 48.19 | 25.60 |
| MemoBrain w/ GLM-4.6 | 55.06 | 24.62 |

MemoBrain 在两个基线智能体上均带来显著提升，其中 DeepResearch-30B-A3B 提升 8.43 个点，表明执行记忆模块具有跨架构通用性。

消融实验显示，移除折叠或冲刷任一操作均导致性能下降，而随机删除或简单截断则严重损害推理连贯性。使用 8B 模型作为记忆模块时，性能与 14B 模型相当，但显著优于 4B 模型，表明记忆管理需要一定的语义理解能力，但无需超大模型。

评估边界方面，论文未报告置信区间，且仅在文本任务上验证，未涉及多模态记忆。代码已开源，但记忆模型的训练数据构造细节（如教师模型 DeepSeek V3.2 的标注协议）未在正文中详述，可能影响复现性。

## 关联研究分析

从问题动机看，MemoBrain 与 MemGPT 均借鉴操作系统虚拟内存思想，但 MemGPT 聚焦跨会话状态持久化，通过页面交换管理长期记忆，而 MemoBrain 聚焦单任务内推理轨迹的即时控制。这一差异源于任务特性：跨会话记忆需处理用户偏好的稳定性，而单任务推理需处理逻辑依赖的动态演化。MemoBrain 的依赖图结构更适合捕捉推理步骤间的因果链，而 MemGPT 的分层存储更适合处理静态知识检索。

从方法设计看，MemoBrain 与 AgentFold 均使用折叠操作，但 AgentFold 将折叠逻辑内嵌于主模型，导致记忆管理与推理执行共享计算资源，而 MemoBrain 采用独立协同模型异步执行。这种解耦设计避免了主模型因记忆操作产生的延迟，但引入了模型间通信开销。论文未量化该开销对端到端延迟的影响，仅报告了搜索调用次数增加，这可能暗示独立模型部署在实时性要求极高的场景中面临挑战。

## 总结

MemoBrain 解决了工具增强智能体在长时程推理中因上下文过载导致的任务对齐失效问题，其核心在于将记忆从被动存储重构为主动控制机制，通过独立协同模型构建依赖感知记忆图并执行预算约束下的折叠与冲刷操作。实验表明，该方法在 BrowseComp-Plus 上将 DeepResearch-30B-A3B 的性能从 51.93% 提升至 60.36%，验证了执行记忆范式的有效性。然而，其记忆生命周期严格限定于单任务，且依赖独立模型部署，未探索跨任务经验复用或轻量化集成方案。当任务复杂度进一步增加或部署资源受限时，独立协同模型的通信开销与主模型推理延迟之间的权衡，是否会导致整体效率下降，论文未给出回答。
