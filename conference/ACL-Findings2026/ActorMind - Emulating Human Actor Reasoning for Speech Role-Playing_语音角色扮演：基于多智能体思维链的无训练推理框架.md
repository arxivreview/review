# ACL-Findings2026最新论文 ｜ActorMind: Emulating Human Actor Reasoning for Speech Role-Playing ｜语音角色扮演：基于多智能体思维链的无训练推理框架

研究机构：香港科技大学

作者：Xi Chen、Wei Xue、Yike Guo

论文原文见 [arXiv](https://arxiv.org/abs/2604.11103)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.11103)

> 语音角色扮演旨在让模型以特定角色的音色、情感与语调自发地生成对话，而非仅合成文本。现有大语言-音频模型（LLAMs）受限于极小的音色库，而文本转语音（TTS）模型缺乏对场景与角色情感的深层推理能力，导致生成的语音虽清晰却缺乏“人格”。本文提出 ActorMind，一个模拟人类演员表演过程的多智能体思维链（CoT）推理框架，通过“眼-耳-脑-口”四个智能体协同工作，在无训练条件下实现语音角色的情感自发表达。该框架在自建基准上显著优于基线，但其有效性高度依赖特定剧集数据，跨场景泛化能力存疑。

## 研究背景

语音是日常情感与态度传达的主导模态，直接揭示人物性格。然而，当前角色扮演研究几乎完全局限于文本模态，忽视了语音中蕴含的韵律、语调等副语言信息。当模型尝试进行语音角色扮演时，面临两个核心困境：一是大语言-音频模型（LLAMs）如 Qwen-Omni 和 GPT-4o 虽然具备多模态理解能力，但其支持的音色库通常仅有数个至十个，无法精细模仿特定角色（如“哈利·波特”）；二是 TTS 模型如 SparkTTS 虽具备零样本音色克隆能力，但缺乏角色扮演的推理机制，难以根据场景动态调整说话风格以响应上下文。

文本角色扮演领域已形成“记忆+微调”或“检索增强生成（RAG）”的主流范式，旨在解决长程对话中的身份漂移问题。然而，这些方法直接迁移至语音模态时面临根本性障碍：文本 RAG 依赖语义相似度检索，而语音情感表达更依赖于韵律特征与上下文情绪的动态耦合。现有工作缺乏针对语音模态的标准化评估基准，也缺乏能够解耦“角色身份”与“情感状态”的推理框架。本文切入点在于将人类演员的表演认知过程形式化，构建一个无需参数更新、可即插即用的多智能体推理系统，以弥补现有模型在语音角色情感自发表达上的空白。

## 核心方法

### 方法参照系

本文问题属于多模态角色扮演中的语音生成子任务。通用流程通常涉及角色知识注入、上下文理解与语音合成。与文本角色扮演不同，语音角色扮演需同时处理离散的角色身份（音色）与连续的情感状态（韵律），且要求生成过程具备自发性。本文未采用微调或参数更新策略，而是将推理过程外化为多智能体协作，利用 LLM 的推理能力与 TTS 的生成能力解耦。

### 多智能体感知与情感推理

Eye Agent 负责读取角色档案 $R_k$ 与场景描述 $S_j^{desc}$，建立静态身份锚点。Ear Agent 利用语音情感描述工具（SECAP）提取对话序列 $(U_p^s, \dots, U_{q-1}^s)$ 中的情感线索 $E_p, \dots, E_{q-1}$。Brain Agent 作为核心推理单元，结合静态身份与动态情感线索，推断下一句台词 $U_q^t$ 的目标情感状态 $\hat{E}_q$。其推理过程可形式化为：

$$ \hat{E}_q = \text{Brain}(R_k, S_j^{desc}, \{U_i^t\}_{i=p}^{q-1}, \{E_i\}_{i=p}^{q-1}) $$

该公式表明，目标情感状态是角色身份、场景上下文、历史文本及历史语音情感的联合函数。这一设计解决了 TTS 模型无法自主判断“何时该用何种情感说话”的问题，将情感决策从生成模型中剥离，交由 LLM 进行显式推理。

### 基于检索的语音合成

Mouth Agent 利用检索增强生成（RAG）机制，从角色专属数据库 $Database_{U_k}$ 中检索情感状态与 $\hat{E}_q$ 最相似的语音片段 $U_x^s$。随后，利用 TTS 模型的上下文学习能力，以 $U_x^s$ 为参考，合成目标文本 $U_q^t$ 的语音：

$$ U_q^s = \text{TTS}(U_q^t, U_x^s) $$

此步骤的关键在于将抽象的情感描述 $\hat{E}_q$ 转化为具体的声学特征参考。通过检索具有相似情感的历史语音，Mouth Agent 能够引导 TTS 模型复现特定的语调、节奏与强度，从而在保持角色音色一致性的同时，实现情感的自然表达。这种“检索-模仿”机制避免了直接训练 TTS 模型理解复杂情感指令的高昂成本。

## 实验评估

实验基于自建基准 ActorMindBench，数据源自《老友记》第一季，包含 7,653 个话语、313 个场景及 6 个角色。基线覆盖 Qwen-Omni（LLAM）及 CosyVoice、SparkTTS、IndexTTS、YourTTS、F5-TTS 等 TTS 模型。由于缺乏统一的语音角色扮演公开基准，本文未与文本角色扮演 SOTA 方法直接对比，也未包含其他语音角色扮演专用模型。

| 方法 | 配置 | 相对性能 (RP-MOS 差值) |
| :--- | :--- | :--- |
| ActorMind | F5-TTS | 1.00 ± 0.00 |
| ActorMind | CosyVoice | 0.75 ± 0.29 |
| ActorMind | SparkTTS | 0.50 ± 0.58 |
| ActorMind | IndexTTS | 0.88 ± 0.25 |
| ActorMind | YourTTS | 0.75 ± 0.29 |

ActorMind 结合 F5-TTS 时取得最高相对性能 1.00，表明该框架与高质量非自回归 TTS 模型兼容性最佳。消融实验显示，移除角色档案（w/o Role Profile）导致性能下降最大（-0.37 ± 0.21），证实角色身份锚定的重要性；移除 Brain Agent（w/o All）导致性能下降最显著（-0.51 ± 0.56），验证了情感推理环节的核心地位。

评估指标 RP-MOS 由 6 名英语评估者打分，范围 1-5，侧重“精确交付”与“情感表达”。该指标依赖主观评价，缺乏客观声学指标（如 MOS 的客观代理）的交叉验证。代码已开源，但实验仅基于单一剧集，未报告跨剧集或跨语言的泛化结果，且未提供训练/部署的具体超参数细节，限制了可复现性的深度审计。

## 关联研究分析

从问题动机看，本文与 Generative Agents 共享“记忆流”思想，但将记忆从文本事实转向语音情感状态。Generative Agents 依赖反思机制维持长程一致性，而 ActorMind 通过 Brain Agent 的即时情感推理应对短程对话的情感动态。差异根源在于模态特性：文本一致性可通过检索事实维持，而语音情感一致性需实时感知上下文韵律。本文未探索长程对话中情感状态的累积漂移问题，其“即时推理”机制在数十轮对话后是否仍能保持情感连贯，缺乏实验支撑。

从方法设计看，本文与 CoSER 等指令微调方法形成鲜明对比。CoSER 通过微调内化角色知识，而 ActorMind 采用无训练推理框架。这种差异源于计算成本与灵活性的权衡：微调方法在固定角色上性能稳定，但适配新角色需重新训练；ActorMind 通过 RAG 检索历史语音，理论上可零成本适配新角色，但依赖高质量的角色专属语音数据库。若角色数据库覆盖不全，检索失败将导致情感表达失真，这一数据依赖性是本文未充分讨论的盲区。

## 总结

本文核心矛盾在于语音生成模型缺乏角色情感推理能力，导致语音角色扮演流于表面。切入点是将人类演员的“眼-耳-脑-口”认知过程解耦为多智能体系统，利用 LLM 推理情感、TTS 合成语音，实现无训练条件下的角色语音生成。实验证明 ActorMind 结合 F5-TTS 时相对性能达 1.00，显著优于基线，且各智能体组件均必要。然而，其边界在于数据依赖单一剧集，且评估依赖主观 RP-MOS，缺乏客观声学验证。当角色数据库覆盖不全或对话轮次增加时，检索失败与情感累积漂移是否会导致角色人格崩塌，论文未给出回答。
