> 大语言模型（LLM）智能体评估面临的核心矛盾是静态基准无法捕捉动态交互中的过程质量。现有方法多聚焦单一任务或孤立能力，导致评估碎片化且难以区分模型能力与框架效应。本文切入点在于构建统一评估基础设施并引入全路径过程审计。通过模块化组件与声明式规范，系统性整合了从能力测试到应用部署的多维评估体系。该综述提供了领域认知地图，但其对长时程状态漂移的量化方法仍显不足。

## 研究背景

当智能体在动态环境中执行多步任务时，仅关注最终输出正确性的静态基准（如 MMLU）迅速失效。这种失效源于智能体能力的本质变化：从静态文本生成转向具备规划、工具调用及环境交互的自主行为。传统评估无法捕捉多步推理中的状态管理及逻辑一致性，导致实验室分数高估实际部署性能。这一困境催生了对基于轨迹（Trajectory-based）的过程审计需求，即评估对象从单一“答案”扩展为完整的“行为系统”。

该领域的主流路线经历了从结果导向到过程导向的转折。早期工作如 ReAct 确立了交互范式，GAIA 和 WebArena 确立了动态环境标准。然而，2024 至 2025 年的研究暴露了评估协议的碎片化问题：不同基准使用不同的环境、提示词和工具接口，导致结果不可比。同时，智能体脚手架（Scaffold）的引入混淆了模型内在能力与执行框架效应，迫使评估必须解耦这两者。本文的切入点在于解决这一基础设施层面的碎片化，通过统一协议连接基准、执行器与环境，旨在建立可复现、细粒度且能区分模型与框架效应的评估体系。

## 核心方法

### 评估基础设施的模块化重构

本文解决的问题属于评估框架与基础设施路线，其关键差异在于放弃单一封闭基准，转而构建可组合的模块化组件。通常做法是各基准独立维护执行脚本，导致接口不统一。本文提出 AgentCompass 等框架，将基准特定脚本模块化为可组合组件，通过稳定协议连接基准、执行器与环境。其核心设计在于解耦执行逻辑与实验设置，支持可选的配方与分析器。这一设计解决了新基准集成成本高及结果不可比的问题，使不同 Agent 能力评估可在同一框架下运行，为大规模横向对比奠定了工程基础。

### 全路径过程评估与解耦机制

在模块化基础设施之上，本文强调全路径过程评估以捕捉中间错误。通常做法仅关注最终状态 $s_T$ 是否满足目标 $g$，而本文关注整个轨迹 $\tau = (s_0, a_1, s_1, \dots, a_T, s_T)$ 的质量。其核心创新在于引入确定性有限自动机（DFA）对 Agent 动作路径进行标注，并解耦 LLM 能力与 Harness 设计。

$$
\text{Score}(\tau) = \sum_{t=1}^{T} w_t \cdot \mathbb{I}(a_t \in \mathcal{A}_{valid}(s_t))
$$

该公式表示轨迹得分是每一步动作 $a_t$ 在当前状态 $s_t$ 下是否属于有效动作集 $\mathcal{A}_{valid}$ 的加权和，权重 $w_t$ 反映步骤重要性。这一设计解决了传统评估无法定位具体失败点的问题，通过过程合规性度量，实现了模型内在能力与执行框架效应的独立评估，从而揭示了框架选择对性能的显著影响。

### 声明式规范与跨框架移植

为解决不同 Agent 框架间抽象、配置格式及执行假设碎片化的问题，本文引入 Agent Spec 声明式规范。通常做法是 Agent 设计参数化并内部化，导致跨框架移植繁琐且易错。本文类比 ONNX 标准，定义 Agent 与工作流的通用交换格式，将设计参数外部化。

$$
\text{Agent} = \langle \mathcal{M}, \mathcal{H}, \mathcal{C} \rangle
$$

其中 $\mathcal{M}$ 为骨干模型，$\mathcal{H}$ 为 Harness 配置，$\mathcal{C}$ 为约束条件。该公式表明 Agent 是模型、框架配置与约束的三元组，通过标准化接口实现跨栈移植。这一创新降低了团队协作与知识共享的门槛，促进了 Agent 生态系统的标准化，使得在不同框架间移植解决方案不再依赖特定实现细节。

## 实验评估

本文作为综述，未提供独立的实验数据，而是整合了领域内代表性工作的结果。据领域综述，AgentCompass 在 GAIA 基准上以 23.7 的准确率领先，较 Holistic Agent Leaderboard 的 15.0 提升 8.7 个点。这一优势可能源于其模块化基础设施对执行环境的标准化控制，减少了框架引入的噪声。在 SWE-Bench Verified 上，MASEval 以 28.0 的准确率领先，较 Agent Spec 的 25.0 提升 3.0 个点，揭示了多智能体系统评估框架在代码任务中的优势。这些数值验证了统一基础设施与过程评估方法的有效性，但多数原始论文未报告置信区间，数值比较需谨慎。

在评估协议与边界方面，本文指出当前框架缺乏对长时程任务中状态漂移与记忆失效的系统性度量。智能体在长对话或长任务中容易丢失上下文、偏离目标或陷入循环，现有基准缺乏对此的量化方法。此外，成本效率的评估地位存在分歧，Holistic Agent Leaderboard 等支持成本并列，揭示了模型价格波动对长期策略的影响，但缺乏统一的成本-性能帕累托前沿评估标准。可复现性方面，AgentCompass 和 Agent Spec 提供了模块化解决方案，但协议定义的稳定性和组件间通信的复杂性仍是瓶颈。

## 关联研究分析

从问题动机看，本文与 AgentBench 等早期工作存在显著差异。AgentBench 构建了涵盖多个交互环境的通用评估套件，但主要局限于封闭环境，未能解决评估碎片化问题。本文则通过模块化组件与声明式规范，实现了跨框架可比性，解决了不同基准使用不同环境、提示词和工具接口导致的结果不可比问题。这一差异源于任务特性的变化：从静态能力测试转向动态环境交互，要求评估基础设施具备更高的灵活性与标准化程度。

从方法设计看，本文与 CORE 等全路径评估方法形成互补。CORE 利用确定性有限自动机对 Agent 动作路径进行标注，聚焦于过程一致性的严格约束，有效减少了中间步骤的错误累积。本文则在此基础上，进一步引入声明式规范与模块化基础设施，实现了模型能力与框架效应的解耦。这一差异源于评估目标的扩展：从单一的过程审计扩展到系统级的归因分析，要求评估框架具备更细粒度的诊断能力与更广泛的兼容性。

## 总结

本文要解决的核心矛盾是评估碎片化与过程评估缺失。现有方法多聚焦单一任务或孤立能力，导致结果不可比且难以区分模型与框架效应。本文抓住的切入点在于构建统一评估基础设施并引入全路径过程审计，通过模块化组件与声明式规范，系统性整合了多维评估体系。证明了 AgentCompass 在 GAIA 上的 23.7 准确率与 MASEval 在 SWE-Bench Verified 上的 28.0 准确率，验证了统一基础设施的有效性。本文的边界在于对长时程状态漂移的量化方法仍显不足，且缺乏统一的成本-性能帕累托前沿评估标准。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
