分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_83217a6cfeee)

> 现有结构化越狱方法依赖单一编程语言和静态模板，导致攻击面受限且易被防御机制识别。本文指出不同编程语言对同一模型的安全对齐强度存在显著差异，且静态模板缺乏适应性。MultiCodeAttack 通过多臂老虎机动态选择语言，结合语义保持变异与响应感知反馈，实现了跨语言的迭代优化攻击。该方法在恶意代码生成任务上取得了 92.51% 的攻击成功率，但其在推理增强模型上的鲁棒性验证仍显单薄。

## 研究背景

当大语言模型（LLM）处理代码生成请求时，其安全对齐机制往往基于自然语言或特定编程语言的训练分布构建。这种对齐并非均匀分布，而是呈现出语言依赖性：模型对主流语言（如 Python）的安全过滤较强，而对长尾语言（如 JavaScript 或特定方言）的约束较弱。这一现象构成了越狱攻击的潜在突破口，即通过切换编程语言来规避对齐机制。然而，单纯的语言切换缺乏系统性，无法应对模型对特定模板格式的识别能力。

结构化越狱（Structured Jailbreak）是应对此问题的主流路线，其核心是将恶意意图嵌入代码模板中，利用 LLM 对代码语法的强遵循性绕过安全过滤。QueryAttack（Zou et al., 2025）和 CodeAttack（Ren et al., 2024）等代表性方法确立了这一范式，但它们均局限于单一编程语言和静态模板设计。这种局限性导致两个瓶颈：一是无法利用跨语言对齐差异带来的互补攻击效果；二是静态模板一旦暴露，防御机制可迅速学习并阻断。MultiCodeAttack 的切入点在于将语言选择建模为在线决策问题，并引入模板的动态进化机制，以解决静态攻击策略的脆弱性。

## 核心方法

### 方法参照系

结构化越狱的标准流程包含意图提取、模板实例化和单次查询。本文问题与该通用流程的关键差异在于：意图提取后的模板选择不再是固定的，而是需要根据模型响应进行动态调整，且模板本身需在保持语义的前提下进行变异以维持攻击有效性。

### 多臂老虎机语言选择

传统方法固定使用一种语言，忽略了不同语言对模型安全边界的差异化影响。MultiCodeAttack 将语言选择建模为多臂老虎机（Multi-Armed Bandit, MAB）问题，每个编程语言对应一个“臂”，奖励信号为攻击有效性。采用 UCB1 算法平衡探索与利用，其选择公式为：

$$
UCB_i = \hat{\mu}_i + \sqrt{\frac{2 \ln t}{n_i}}
$$

其中 $\hat{\mu}_i$ 为语言 $L_i$ 的历史平均奖励，$n_i$ 为选择次数，$t$ 为当前轮次。该公式确保在早期探索未测试语言，后期聚焦高奖励语言，从而自适应地定位模型最薄弱的语言对齐环节。

### 语义保持变异与响应感知反馈

静态模板易被识别，且单次攻击无法利用模型响应的细微信号。MultiCodeAttack 引入双源种子初始化与语义保持变异。变异过程由受害者模型执行，约束占位符不变且语法有效，仅改变风格或结构。响应评估采用两阶段决策：首先检测显式拒绝（$F=1$），若未拒绝，则通过自反思判断（Self-Reflective Judgment）计算困惑度 $J$。最终奖励 $R$ 定义为：

$$
R = \begin{cases}
1.0, & \text{if } F = 1 \\
50 - J, & \text{if } F = 0 \land \text{Yes} \\
J, & \text{if } F = 0 \land \text{No}
\end{cases}
$$

该奖励机制将“承认有害性”的高置信度（低 $J$）映射为高奖励，驱动幸存者池（Survivor Pool）保留高效模板，形成闭环优化。

## 实验评估

实验在 AdvBench（520 条有害指令）和 RMCBench（182 条恶意代码提示）上进行，对比了 Base64、BitBypass、RLBreaker、CodeAttack、PAIR、TAP 和 QAttack 等基线。基线覆盖了编码混淆、结构化攻击和强化学习路线，但缺失了图搜索（GAP）和 LoRA 专家选择（Red-Bandit）等近期方法。

| 方法 | Avg ASR (%) | Avg HS | GPT-4o ASR (%) | DeepSeek-Coder-7B ASR (%) |
| :--- | :--- | :--- | :--- | :--- |
| QAttack | 72.28 | 3.98 | 63.65 | 59.62 |
| MultiCodeAttack | 93.37 | 4.76 | 95.19 | 100.00 |

MultiCodeAttack 在有害文本生成任务上平均 ASR 达 93.37%，显著高于最强基线 QAttack 的 72.28%。在恶意代码生成任务上，其平均 ASR 为 92.51%，相比最强基线提升 59.93%。值得注意的是，在 DeepSeek-Coder-7B 上，MultiCodeAttack 实现了 100.00% 的 ASR，而 QAttack 仅为 59.62%，表明多语言策略在代码专用模型上更具优势。

消融实验显示，移除多语言选择或变异机制会导致性能显著下降。在防御鲁棒性测试中，MultiCodeAttack 在 Paraphrasing 和 Retokenization 防御下，HS 仅下降 6.79% 和 2.63%，而基线 QAttack 下降幅度更大（如 RandomPatchPerturbation 下下降 37.53%）。这表明动态变异机制增强了攻击对表面扰动的鲁棒性。

评估边界方面，实验主要依赖 ASR 和 HS 指标，缺乏对攻击计算成本（查询次数）的精细化分析，尽管文中提及了查询成本图表，但未在正文中给出具体数值对比。代码已开源，但超参数（如 $\alpha=0.5$, $\beta=0.1$）的敏感性分析未充分展开。

## 关联研究分析

从问题动机看，MultiCodeAttack 与 RLBreaker（Chen et al., 2024b）均旨在解决静态攻击的适应性不足，但路线截然不同。RLBreaker 通过训练强化学习策略来优化提示，属于“训练后攻击”，计算成本高且依赖模型反馈的稳定性。MultiCodeAttack 则是“训练-free”的在线优化，利用多臂老虎机在测试时自适应选择语言，避免了训练开销。这一差异源于任务特性：代码越狱中语言维度的离散性使得 MAB 比连续空间的 RL 搜索更高效，且无需修改模型参数。

从方法设计看，MultiCodeAttack 与 Red-Bandit（Ziakas et al., 2025）都使用了多臂老虎机框架，但选择对象不同。Red-Bandit 选择的是离线训练的 LoRA 攻击专家，而 MultiCodeAttack 选择的是编程语言。这一差异反映了攻击粒度的不同：Red-Bandit 关注攻击风格的多样性，MultiCodeAttack 关注对齐分布的语言依赖性。MultiCodeAttack 的设计更贴合代码生成模型的特性，因为代码模型的对齐机制往往与训练数据中的语言分布强相关，而通用文本模型的对齐更多依赖于语义内容而非语言形式。

## 总结

MultiCodeAttack 旨在解决结构化越狱中单语言静态模板导致的攻击面受限问题。其切入点在于揭示并利用 LLM 安全对齐的语言依赖性，通过多臂老虎机动态选择语言并结合语义变异实现迭代优化。该方法在 19 个 LLM 上验证了有效性，恶意代码生成 ASR 达 92.51%，有害文本生成 ASR 达 93.37%。然而，实验主要聚焦于传统对齐模型，对推理增强模型（如 o1 系列）的鲁棒性验证仅涉及 DeepSeek-7B 和 Qwen3-14B 等有限样本，且未深入分析推理能力对越狱抵抗的具体机制。当模型具备更强的逻辑推理和代码审计能力时，基于表面语法的变异策略是否仍能维持高攻击成功率，论文未给出充分回答。
