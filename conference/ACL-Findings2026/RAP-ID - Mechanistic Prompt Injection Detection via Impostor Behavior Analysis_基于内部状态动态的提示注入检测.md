# ACL-Findings2026最新论文 ｜RAP-ID: Mechanistic Prompt Injection Detection via Impostor Behavior Analysis ｜基于内部状态动态的提示注入检测

作者：Yuchen Yang、Lei Peng、Yujie He 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_6ec8d7052439)

> 大语言模型（LLM）在代理系统中难以区分系统指令与外部数据，导致提示注入攻击频发。现有外部护栏模型引入高延迟，而单一内部启发式方法误报率过高。RAP-ID 将注入攻击形式化为“语义模仿”与“注意力劫持”双过程，通过单次前向传播融合三个内部信号实现无训练检测。该方法在直接注入场景下表现优异，但在复杂代理间接注入场景中的防御能力仍显不足，其通用性边界尚待厘清。

## 研究背景

当 LLM 处理包含恶意指令的外部数据时，其内部注意力机制可能从系统提示转向用户输入，这一现象被称为注意力劫持。劫持成功的前提是攻击输入在语义空间中模仿系统指令的特征，即语义模仿。仅监控注意力异常无法区分良性指令覆盖与恶意注入，因为两者均可能引起注意力转移，必须结合语义相似度与潜在风险信号才能准确识别攻击意图。

提示注入防御的主流路线分为外部护栏与内部状态分析两类。外部护栏如 Llama Guard 虽检测能力强，但需额外模型推理，显著增加延迟；内部方法如 Attention Tracker 仅监控注意力分布，导致在复杂良性指令上产生高达 62.45% 的误报率。现有内部方法缺乏对攻击“模仿”本质的量化，无法有效区分良性覆盖与恶意劫持。RAP-ID 的切入点在于将攻击行为机制化，通过同时捕捉语义模仿、注意力劫持与潜在风险冲突三个维度，在单次前向传播中完成检测，旨在解决内部方法误报率高与外部方法延迟大的双重瓶颈。

## 核心方法

### 方法参照系

RAP-ID 属于内部状态分析防御路线，其标准流程是在 LLM 前向传播过程中提取内部激活或注意力特征，通过阈值判断异常。与仅监控单一注意力异常的传统方法不同，RAP-ID 的关键差异在于引入了语义空间与 Logit 空间的联合分析，将检测从“异常检测”升级为“行为机制验证”。

### 语义模仿与注意力劫持量化

传统内部方法仅关注注意力权重的绝对值变化，忽略了攻击输入是否具备系统指令的语义特征。RAP-ID 引入指令相似度（Directive Likeness, DL）与反事实增益（Counterfactual Gain, CG）两个信号。DL 计算用户 Token 的 Key 向量与系统锚点向量的余弦相似度，量化语义模仿程度；CG 计算用户输入与系统提示的注意力权重比值，量化注意力劫持程度。两者通过乘积关系融合，确保只有同时具备高语义相似性与高注意力转移的输入才被标记为潜在攻击，从而过滤掉仅引起注意力波动但语义无关的良性输入。

$$
PE_i = DL_i \times \log(1 + CG_i)
$$

该公式表明，特权升级信号（PE）是语义模仿与注意力劫持的乘积，任一信号缺失都会导致 PE 值趋近于零，体现了双条件验证的设计逻辑。

### 潜在风险冲突检测

仅依赖结构信号（DL 和 CG）无法捕捉那些语义连贯但意图恶意的攻击，如隐喻式越狱。RAP-ID 引入策略冲突（Policy Conflict, PC）信号，监控模型内部对风险词汇的采样概率变化。PC 不仅关注风险词出现的绝对概率，更关注其概率相对于基线的动态激增，从而捕捉被表面文本掩盖的潜在恶意意图。最终检测分数为 PE 与 PC 的加权和，通过阈值判断实现攻击拦截。

$$
S_i = \alpha \cdot PE_i + \beta \cdot PC_i
$$

该公式将结构信号（PE）与语义风险信号（PC）加权融合，$\alpha$ 和 $\beta$ 的设定确保两类信号在量级上可比，使检测器能同时应对结构型注入与内容型越狱。

## 实验评估

RAP-ID 在 Qwen3-8B 和 Qwen2-1.5B 上进行了评估，数据集涵盖 BIPIA、InjecAgent、PromptInj 等攻击集及 Alpaca、Dolly 等良性集。基线包括 Llama Guard、Prompt Guard 2 等外部护栏及 Attention Tracker 等内部方法。在 BIPIA 数据集上，RAP-ID 的 TPR 达到 98.62%，显著优于 Llama Guard 的 10.85% 和 Prompt Guard 2 的 0.12%；在 Alpaca 良性集上，RAP-ID 的 FPR 为 1.35%，远低于 Attention Tracker 的 62.45%，验证了其在安全与效用间的平衡能力。

| 方法 | BIPIA (TPR) | InjecAgent (TPR) | Alpaca (FPR) |
| :--- | :--- | :--- | :--- |
| RAP-ID (Qwen3-8B) | 0.9862 | 0.2615 | 0.0135 |
| Llama Guard 4 (12B) | 0.1085 | 0.5512 | 0.0072 |
| Attention Tracker | 0.9998 | 0.8082 | 0.6245 |

消融实验显示，移除 DL 导致 F1 分数从 0.8382 骤降至 0.1770，攻击 TPR 跌至 25.00%，证明语义模仿是检测的必要条件；移除 CG 导致良性 FPR 飙升至 98.45%，表明 CG 是区分良性覆盖与恶意注入的关键门控。移除 PC 使攻击 TPR 下降 5.65%，说明 PC 在捕捉低语义模仿攻击中起补充作用。

评估协议存在局限：InjecAgent 上 RAP-ID 的 TPR 仅为 26.15%，远低于 Llama Guard 的 55.12%，表明内部状态分析在复杂代理间接注入场景下失效。论文未报告计算延迟的具体数值，仅定性描述为“可忽略”，且未提供代码开源，限制了可复现性。

## 关联研究分析

从问题动机看，RAP-ID 与 IsolateGPT 等系统级隔离方法形成互补。IsolateGPT 通过架构隔离阻断数据流，在 AgentDojo 上实现 0.12% 的 ASR，但部署成本高且可能限制模型功能。RAP-ID 作为模型级防御，无需修改系统架构，适合资源受限场景，但其对代理工具调用上下文的感知缺失导致在 InjecAgent 上表现不佳。这暗示内部状态检测需结合工具调用轨迹才能有效应对代理场景，这是当前内部防御方法的盲区。

从方法设计看，RAP-ID 与 Attention Tracker 同属内部状态分析，但后者仅监控注意力异常，缺乏语义验证。RAP-ID 引入 DL 信号解决了 Attention Tracker 高误报的问题，但 DL 依赖系统锚点向量的静态计算，可能无法适应动态变化的系统提示。相比之下，CaMeL 等基于策略的形式化方法通过显式规则约束行为，不依赖内部状态统计，但计算开销大。RAP-ID 的静态锚点设计在系统提示频繁变化的场景中是否仍具鲁棒性，论文未给出回答。

## 总结

RAP-ID 旨在解决 LLM 内部防御中误报率高与外部防御延迟大的矛盾，通过形式化“语义模仿”与“注意力劫持”双过程，在单次前向传播中融合 DL、CG、PC 三信号实现检测。实验证明其在直接注入场景下 TPR 达 98.62% 且 FPR 仅 1.35%，显著优于外部护栏与单一内部方法。然而，其在 InjecAgent 上 TPR 仅 26.15%，暴露了内部状态分析对复杂代理间接注入的感知局限。当系统提示动态变化或攻击采用低语义模仿策略时，静态锚点与 PC 信号的协同有效性是否依然成立，论文未给出回答。
