> 工具增强大语言模型（Tool-Augmented LLMs）的训练依赖高质量“用户查询-工具调用链”配对数据，但现有合成方法受限于深度优先搜索（DFS）的高昂计算成本与低通过率，导致数据稀缺且分布偏差。ToolGrad 提出“答案优先”范式，先通过迭代链式构建有效工具工作流，再反推用户查询，以近乎 100% 的通过率生成复杂轨迹。该方法将文本梯度概念迁移至数据合成，验证了小模型在特定数据下可超越专有大模型，但其缺乏记忆机制导致数据多样性受限，规模化扩展存在性能饱和风险。

## 研究背景

工具调用本质上是模型与外部 API 的交互过程，其核心挑战在于如何从数万级 API 库中筛选出能解决特定任务的组合。传统方法采用“查询优先”策略，即先生成用户指令，再通过智能体搜索工具路径。这一过程类似在巨大搜索空间中盲目探索，不仅计算开销巨大，且常因 API 不可用或逻辑错误导致标注失败。为提升效率，研究者引入文本梯度（Textual Gradients）概念，利用大语言模型（LLM）作为批评者提供反馈，指导提示词优化。然而，现有工作多将文本梯度用于提示工程，未将其应用于数据集本身的构建过程。

工具使用数据集的生成效率与质量直接决定下游模型的性能上限。主流路线如 ToolBench 依赖 DFS 搜索，虽能覆盖复杂场景，但通过率仅 63.8%，且生成的轨迹常包含无效步骤，造成数据污染。另一类方法如 τ-bench 侧重多轮交互模拟，但缺乏对单步工具调用逻辑的严格验证。ToolGrad 的切入点在于反转生成顺序：不依赖查询去搜索答案，而是先构建已验证有效的工具链，再逆向生成查询。这种“答案优先”策略从源头保证了轨迹的逻辑一致性，将标注失败率降至 0.2%，为低成本、高质量数据合成提供了新路径。

## 核心方法

### 方法参照系

ToolGrad 属于数据合成路线，其参照系为基于 LLM 的迭代优化框架。与 TextGrad 优化提示词不同，ToolGrad 的目标是生成训练数据集 $D = \{(q, W, r)\}$，其中 $q$ 为用户查询，$W$ 为 API 工作流，$r$ 为响应。关键差异在于，ToolGrad 不直接优化模型参数，而是通过 LLM 反馈迭代构建工作流 $W$，再反推 $q$ 和 $r$，形成“前向构建-反向标注”的闭环。

### 迭代链式构建机制

传统 DFS 在每一步需探索所有可能分支，导致计算爆炸。ToolGrad 引入 API Proposer 模块，从批量 API 中筛选出 $m$ 个最相关候选，大幅减少执行开销。其核心公式为：

$$ \{(API_i, inst_i)\}_{i=0}^{m-1} = LLM_{pr}(\{API\}_{bs}, W_t) $$

该公式表示，给定当前工作流 $W_t$ 和批量 API $\{API\}_{bs}$，LLM Proposer 输出 $m$ 个带指令的 API 提案。设计动机在于，随机采样的 API 中大部分与当前任务无关，通过 LLM 预筛选可避免冗余调用，将计算资源集中于高价值路径。

### 文本梯度选择与逆向标注

API Selector 模块执行“梯度下降”操作，从执行报告中选择最优 API 以扩展工作流。其选择过程定义为：

$$ j, k = LLM_{sel}(\{rep_i\}_m, W_t) $$

其中 $rep_i$ 为 API 执行报告，$j$ 为选中 API ID，$k$ 为插入链 ID。此步骤将 LLM 的评估能力转化为离散选择信号，替代了传统优化中的连续梯度。随后，Workflow Updater 执行 $W_{t+1} \leftarrow W_t.add(API_j, C_k)$，并调用 LLM Updater 逆向生成查询与响应：

$$ q_{t+1}, r_{t+1} = LLM_{updater}(W_{t+1}) $$

这一逆向过程将复杂的工具链映射为自然语言查询，确保了数据在逻辑上的自洽性，避免了正向搜索中常见的“查询-答案”错位问题。

## 实验评估

实验在 ToolBench 和 BFCL 基准上进行，对比基线包括 ToolBench（DFS）、ToolACE、Hammer 及 Gemini-2.5、GPT-5 等专有模型。ToolGrad 生成的数据集在通过率、工具使用复杂度和成本上均优于 DFS。

| 指标 | DFS (ToolBench) | ToolGrad |
| :--- | :--- | :--- |
| 通过率 (%) | 63.8 | 99.8 |
| 平均工具使用数 | 2.1 | 3.4 |
| LLM 成本 | 64.5 | 63.9 |
| 工具成本 | 34.3 | 20.0 |

ToolGrad 以 99.8% 的通过率显著优于 DFS 的 63.8%，且生成的工具链平均长度从 2.1 步增至 3.4 步，表明其能捕捉更复杂的多步依赖。在模型性能上，基于 ToolGrad-500 微调的 Gemma-3-12B 在 BFCL 单轮任务中表现优于 ToolACE 和 Gemini-2.5-flash-lite，验证了数据质量对模型泛化能力的决定性作用。

消融实验显示，迭代次数对性能影响显著。当迭代次数从 4 增至 10 时，通过率趋于饱和，而唯一工具使用比例下降，表明框架在缺乏记忆机制时易生成重复轨迹。样本规模扩展实验表明，Gemma-3-4B 在 500 样本时性能达到峰值，继续增加至 2k 样本后性能反而下降，揭示了当前框架在数据多样性上的瓶颈。

评估边界方面，本文仅评估单轮工具调用，未覆盖多轮交互场景。代码与模型已开源，但生成过程依赖 Gemini-2.5-flash-lite，其成本与延迟特性可能限制框架在资源受限环境中的部署。此外，逆向生成的查询可能缺乏真实用户的模糊性，导致模型在噪声输入下的鲁棒性未被充分验证。

## 关联研究分析

从问题动机看，ToolGrad 与 ToolBench 均旨在解决工具使用数据稀缺问题，但 ToolBench 依赖 DFS 搜索，其本质是“试错-验证”范式，导致高成本与低通过率。ToolGrad 通过“答案优先”策略，将搜索空间从指数级压缩至线性迭代，其根源在于利用了 LLM 的语义理解能力进行预筛选，而非依赖穷举。这种范式转换使得数据生成成本与复杂度解耦，但代价是生成的查询可能过于“完美”，缺乏真实场景中的歧义性。

从方法设计看，ToolGrad 借鉴了 TextGrad 的文本梯度概念，但将其应用对象从提示词优化迁移至数据集构建。与 TOUCAN 等侧重 MCP 环境的数据合成框架不同，ToolGrad 聚焦于通用 API 库的链式构建，其核心创新在于将 API 选择类比为梯度下降，通过 LLM Selector 执行离散优化。然而，ToolGrad 缺乏记忆机制，导致数据重复，而 TOUCAN 通过环境交互引入多样性。这暗示在大规模数据生成中，记忆机制与迭代优化需协同设计，以平衡效率与多样性。

## 总结

ToolGrad 解决了工具使用数据合成中“高成本-低通过率”的核心矛盾，通过“答案优先”范式反转生成顺序，利用文本梯度迭代构建有效工具链，再以近乎 100% 的通过率生成复杂轨迹。实验证明，基于该数据微调的小模型在单轮任务上可超越专有大模型，验证了数据质量优于规模的有效性。然而，框架缺乏记忆机制导致数据多样性受限，样本扩展后性能出现饱和甚至下降。当支持集增大到 2k 样本时，模型性能为何不升反降，是否源于生成轨迹的重复性，论文未给出明确解释。
