# ACL-Findings2026最新论文 ｜Multilingual Tokenization through the Lens of Indian Languages: Challenges and Insights ｜印度语言多语言分词：正字法归一化与词汇表聚类策略

研究机构：印度理工学院、印度理工学院孟买分校

作者：Maharaj Brahma、N J Karthika、Rajat Verma 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_40a63e8a95c3)

> 多语言分词器在低资源语言上常因高资源语言主导词汇表分配而导致分词碎片化，进而推高计算成本并削弱模型对形态结构的捕捉能力。现有静态分词方法虽能处理开放词汇，但难以应对印度语言特有的正字法变体与复杂形态结构，导致同一语义单元被映射为多个冗余 Token。本文通过引入脚本/正字法归一化预处理，并采用基于语言家族的聚类策略构建多语言词汇表，系统评估了 17 种印度语言的分词效率与下游任务表现。该研究提供了针对形态丰富语言的实证指导，但其结论局限于静态分词框架，未探索动态分词架构在解决此类结构性不公上的潜在优势。

## 研究背景

当多语言大模型处理印度语言时，主流分词器往往将同一语义单元因正字法细微差异（如 Anusvara 替换）映射为不同 Token，造成词汇表容量浪费与序列长度增加。这种冗余直接推高了 Fertility（生育率，即单词被分割的平均 Token 数），而 Fertility 是衡量分词效率的核心指标，其数值越高意味着模型处理相同语义内容所需的计算资源越多。为缓解这一问题，研究者通常关注子词算法的选择与多语言词汇表的构建策略，其中 Byte Pair Encoding (BPE) 和 Unigram Language Model (ULM) 是两种最广泛采用的基线方法，前者基于频率合并，后者基于概率剪枝，二者在形态边界保留能力上存在显著差异。

多语言分词的核心矛盾在于共享词汇表在高资源语言与低资源语言之间的分配失衡。主流联合训练策略（Joint Method）通过简单拼接所有语言数据构建单一词汇表，导致高资源语言占据过多 Token 槽位，低资源语言被迫使用更细粒度的子词，从而加剧了分词碎片化。尽管 Chung et al. (2020) 提出基于词汇重叠的聚类方法以优化分配，但现有研究多聚焦于欧洲语言，对印度语言特有的 11 种书写系统、黏着性形态及正字法变体缺乏系统性评估。本文的切入点在于，印度语言不仅面临资源不均，还面临正字法标准化缺失导致的表面形式冗余，这要求分词器设计必须同时考虑语言学结构（如词素边界）与预处理规则（如正字法归一化），而非仅依赖统计频率优化。

## 核心方法

### 多语言分词基线参照

本文基于 BPE 与 ULM 两种主流子词算法构建多语言分词器，参照系为标准的联合训练流程：将 17 种印度语言的语料拼接后，直接训练单一共享词汇表。该流程的关键假设是语言间存在足够的词汇重叠以支持跨语言迁移，但本文指出，对于正字法差异显著的印度语言，这种假设导致低资源语言的 Token 被高资源语言“挤出”，造成 Fertility 上升。本文的核心差异在于引入了两个前置干预：一是基于 IndicNLP 库的正字法归一化，二是基于语言家族的聚类词汇表构建，旨在从数据预处理和词汇分配两个层面同时优化分词效率。

### 正字法归一化与 Fertility 优化

针对印度语言中常见的正字法变体（如 Hindi 中 `andara` 与 `aṁdara` 的混用），本文在分词训练前应用脚本特定的归一化规则。这一设计动机在于，统计分词器无法区分语义相同的不同表面形式，导致同一词素被拆分为多个独立 Token，浪费词汇表容量。归一化通过统一 Unicode 字符与变音符号，将语义相同的变体映射为同一表面形式，从而减少 Token 冗余。其效果可通过 Fertility 的变化量化：

$$ F_{norm} = \frac{1}{|W|} \sum_{w \in W} \frac{|T(w)|}{|w|} $$

其中 $T(w)$ 为归一化后单词 $w$ 被分词器分割的 Token 数，$|w|$ 为字符数。归一化通过降低 $|T(w)|$ 的方差，直接减小 $F_{norm}$。实验显示，在 128k 词汇表下，BPE 的 Fertility 从非归一化的 1.717 降至 1.664，ULM 从 1.695 降至 1.663，表明正字法标准化是提升分词效率的关键预处理步骤，其效果独立于子词算法的选择。

### 基于语言家族的聚类词汇表构建

为缓解联合训练中高资源语言对词汇表的挤占，本文提出基于语言家族（Indo-European 与 Dravidian）的聚类策略。与 Chung et al. (2020) 基于词汇重叠的自动聚类不同，本文采用手动定义的语言家族分组，并结合 K-means 对语言特异性向量进行聚类，以平衡语言学先验与数据驱动。该策略的核心在于，将词汇表容量 $V_{total}$ 按语言簇的比例 $p_i$ 分配给各簇，而非全局竞争：

$$ |V_{C_i}| = p_i \times V_{total}, \quad p_i = \frac{\sum_{l \in C_i} |D_l|}{\sum_{l \in L} |D_l|} $$

其中 $C_i$ 为第 $i$ 个语言簇，$D_l$ 为语言 $l$ 的语料。通过为每个簇独立训练 ULM 分词器并合并词汇表，该策略确保了低资源语言簇拥有足够的 Token 槽位，避免其被高资源语言“稀释”。实验表明，Clusterlf（语言家族聚类）在 17 种语言中的 13 种上实现了比联合方法更低的 Fertility，且在下游 NLI 微调任务中，平均 F1 从联合方法的 64.42% 提升至 65.65%，验证了语言学结构引导的词汇分配对模型性能的积极影响。

## 实验评估

实验在 17 种印度语言上进行，使用 Sangraha 语料库训练分词器，并在 FLORES-200 dev 集上评估 Fertility，在 IndicXNLI 和 Naamapadam 数据集上评估下游 NLI 与 NER 任务。基线覆盖 BPE、ULM、PickyBPE 和 OBPE，但缺失 MorphBPE 等形态感知方法及 HAT 等无分词架构，限制了与最新动态分词技术的横向对比。

| 方法 | 词汇表大小 | Fertility (Avg.) | NLI Fine-tuned F1 (%) | NER Fine-tuned F1 (%) |
| :--- | :--- | :--- | :--- | :--- |
| Joint (ULM) | 128k | 1.663 | 64.42 | 74.27 |
| Clusterlf (ULM) | 128k | 1.658 | 65.65 | 75.35 |
| Joint (BPE) | 128k | 1.664 | - | - |
| PickyBPE | 128k | 1.609 | - | - |

Clusterlf 在 Fertility 和下游任务上均优于 Joint，但 PickyBPE 的 Fertility (1.609) 显著低于 ULM 基线，表明单纯优化词汇表膨胀可能比语言学聚类更直接地降低序列长度。然而，PickyBPE 未报告下游任务性能，其 Fertility 优势是否转化为模型性能提升尚不明确。

消融实验显示，正字法归一化对 Fertility 的降低在所有词汇表大小（32k-256k）和算法（BPE/ULM）上均统计显著（p < 0.05），但幅度较小（约 0.03-0.05）。聚类策略中，语言家族手动聚类（Clusterlf）优于自动 K-means 聚类，尤其在 Dravidian 语言上，但 3 种 Dravidian 语言的 Fertility 仍高于联合方法，暗示语言家族内部存在资源不均导致的分配 trade-off。MorphScore 评估发现，ULM 在 Hindi 和 Marathi 上优于 BPE，但在 Tamil 和 Gujarati 上，随着词汇表增大，MorphScore 反而下降，作者推测这是由于二元分割数据集无法捕捉黏着性语言的复杂词素结构，导致评估指标失真。

评估边界方面，本文仅使用 Fertility 和 MorphScore 作为内在指标，未量化 Token Tax 的经济成本，也未评估分词器对模型鲁棒性的影响。可复现性上，论文未提供代码 URL，但详细列出了超参数（如 BERT 架构、学习率调度）和 GPU 配置（A6000, 8 cores, 48 hours），且使用 SentencePiece 库，便于复现。然而，缺乏与 MorphBPE 等形态感知方法的对比，使得 ULM 在形态对齐上的优势是否优于显式形态约束方法存疑。

## 关联研究分析

从问题动机看，本文聚焦于印度语言特有的正字法变体与形态复杂度，而 MUTANT 等多语言公平性优化方法主要关注数据平衡与课程学习，未涉及预处理规则对分词效率的影响。本文发现正字法归一化能系统性降低 Fertility，这印证了 Pre-tokenization Ceiling Analysis 的结论，即预分词/预处理规则构成了不可通过数据增强解决的效率天花板。然而，MUTANT 等方法的评估协议通常包含更广泛的语言集合和下游任务，本文仅局限于 17 种印度语言，其结论的普适性需进一步验证。

从方法设计看，本文的聚类策略与 Chung et al. (2020) 的词汇重叠聚类不同，后者基于数据驱动的 Token 共享度，而本文基于语言学先验（语言家族）。这种差异源于印度语言的正字法差异远大于词汇重叠差异，导致数据驱动聚类可能将正字法相似但语言家族不同的语言错误分组。相比之下，MorphBPE 通过引入词素边界约束直接优化形态对齐，而本文仅通过 ULM 的概率机制间接保留形态结构。ULM 在 MorphScore 上的优势是否足以替代显式形态约束，论文未给出回答，尤其在缺乏高质量形态学数据集的低资源语言上，这种间接方法的有效性可能受限。

## 总结

本文旨在解决多语言分词器在印度语言上因正字法变体与资源不均导致的分词碎片化问题。其切入点在于，现有联合训练策略忽视了预处理规则对 Token 冗余的贡献，且数据驱动聚类无法有效处理正字法差异显著的语言。通过引入正字法归一化与基于语言家族的聚类策略，本文在 17 种印度语言上实现了 Fertility 的降低（1.663 vs 1.664）和下游 NLI 微调 F1 的提升（65.65% vs 64.42%）。然而，其边界在于，PickyBPE 的 Fertility 优势未被转化为下游性能验证，且 ULM 在黏着性语言上的 MorphScore 下降揭示了评估指标的局限性。当语言家族内部资源差异极大时，基于语言家族的聚类是否仍能保持对低资源语言的公平性，论文未给出回答。
