> 高成本仿真驱动设计面临的核心矛盾是：将模糊的自然语言需求转化为可执行数学模型的过程高度依赖专家，而验证模型正确性的求解器反馈因仿真成本过高无法用于数据筛选。现有提示工程方法在复杂约束下易产生语义偏差，微调方法则受限于缺乏低成本的数据质量过滤机制。本文提出 APF 框架，通过测试实例排序一致性替代求解器反馈进行数据筛选，并结合数据增强对开源大语言模型进行监督微调。该框架在特定工业场景下实现了小模型超越大模型提示的效果，但其验证机制的通用性与理论边界尚待检验。

## 研究背景

高成本仿真驱动设计（如天线、航空航天）中，设计参数 $x$ 通过黑盒仿真器 $S$ 映射为性能分布 $P_x(z)$，优化算法需基于此分布求解。然而，工程师通常以非结构化自然语言描述需求，将其转化为包含目标函数与约束的数学模型 $E$ 是连接业务意图与算法执行的关键瓶颈。这一转化过程涉及语义理解与逻辑推导，且由于仿真器 $S$ 的计算成本极高，无法像线性规划那样通过频繁调用求解器获取反馈来验证模型 $E$ 的正确性。

传统 LLM 优化建模研究多聚焦于线性规划（LP）或混合整数规划（MILP），其核心假设是求解器反馈廉价且即时可用。Chain-of-Experts (CoE) 和 OptiMUS 等提示工程方法通过多智能体协作缓解长程依赖，但在面对高成本仿真场景时，无法利用求解器反馈进行数据过滤或错误修正。ORLM 和 LLMOPT 等微调方法虽提升了建模准确率，但其数据合成与筛选流程严重依赖执行验证，这在单次仿真耗时数小时甚至数天的工业场景中不可行。因此，如何在缺乏求解器反馈的条件下构建高质量微调数据集，成为高成本仿真驱动设计自动化的核心难题。本文切入点在于解耦“模型生成”与“模型验证”，利用 LLM 自身的推理能力替代求解器进行数据质量评估。

## 核心方法

### 方法参照系

本文问题属于 LLM 自动化问题建模中的微调路线，与 ORLM 等基于求解器反馈的数据合成范式不同。关键差异在于验证机制：传统方法依赖求解器执行结果过滤数据，而本文在仿真成本极高的约束下，必须构建一种无需执行求解器、仅基于 LLM 推理即可评估公式语义正确性的机制。

### 测试实例标注与排序一致性验证

传统数据筛选依赖求解器返回的可行解或最优值，但在高成本仿真中，每次验证都意味着巨大的计算开销。本文引入测试实例集 $I = \{I_1, I_2, \dots, I_m\}$ 作为中介，将语义对齐问题转化为排序一致性问题。对于给定的需求集 $R$，测试实例 $I$ 的性能响应决定了其满足设计意图的程度，从而形成一个参考排序 $\pi_R$。生成的公式 $E$ 若在 $I$ 上诱导出的排序 $\hat{\pi}$ 与 $\pi_R$ 高度一致，则 $E$ 被视为高质量样本。参考排序 $\pi_{LLM}$ 通过 LLM 在结构化提示 $P$ 下的后验概率最大化获得：

$$
\pi_{LLM} = \arg \max_{\pi} P_{\theta}(\pi | P)
$$

该公式表明，LLM 基于需求上下文 $R$ 和实例数据 $\psi_{tab}(I)$，直接生成实例的优劣排序，而非计算具体数值。这一设计消除了对昂贵仿真器的依赖，使得数据筛选可以在离线阶段通过 LLM API 调用完成，解决了高成本场景下数据质量过滤不可行的问题。

### 数据增强与监督微调

在获得高质量数据集 $D_{HQ}$ 后，本文采用监督微调（SFT）提升开源 LLM 的建模能力。为增强模型对输入变异的鲁棒性，数据增强策略结合语义改写与顺序置换。对于基础样本 $(R_i, E_i)$，生成 $l$ 个增强样本 $\{(R'_{i,j}, E_i)\}_{j=1}^l$，其中 $R'_{i,j}$ 通过 LLM 改写保持语义不变但改变表述，同时随机置换需求与方程的顺序以消除位置偏差。最终训练集 $D$ 由基础数据与增强数据组成：

$$
D = D_{base} \cup \bigcup_{i=1}^{N} \{(R'_{i,j}, E_i)\}_{j=1}^{l}
$$

此公式体现了数据规模的扩展逻辑，通过语义多样性与结构多样性提升模型泛化能力。SFT 阶段使用 Llama-3.1-8B、Qwen2.5-7B 等开源模型，使其在特定领域任务上超越通用大模型的提示性能。

## 实验评估

实验基于自建天线设计数据集，包含 2,300 个历史仿真样本，其中 2,000 个用于训练，300 个用于测试。基线覆盖 GPT-4o、DeepSeek-V3、Claude-sonnet-4.5 等通用大模型，以及 CoE 和 OptiMUS 等提示工程方法。由于高成本仿真限制，ORLM 等依赖求解器反馈的微调方法被排除在对比之外。

| 方法 | Aobj | Acon | A |
| :--- | :--- | :--- | :--- |
| GPT-4o | 0.6055 (0.2425) | 0.7075 (0.2270) | 0.6651 (0.1879) |
| Chain-of-Experts | 0.7426 (0.2410) | 0.7453 (0.1865) | 0.7252 (0.2309) |
| APF (Llama-3.1-8B) | 0.8012 (0.1059) | 0.7969 (0.1720) | 0.7976 (0.1228) |
| APF (Qwen2.5-7B) | 0.7990 (0.1106) | 0.7959 (0.1739) | 0.7961 (0.1243) |

APF 微调后的 Llama-3.1-8B 在总分 A 上达到 0.7976，显著优于 GPT-4o 的 0.6651 和 CoE 的 0.7252。标准差从 GPT-4o 的 0.1879 降至 0.1228，表明微调不仅提升了平均性能，还增强了输出的稳定性。

| 配置 | Aobj | Acon | A |
| :--- | :--- | :--- | :--- |
| w/o Augmentation | 0.7656 | 0.7555 | 0.7553 |
| w/o Selection | 0.7603 | 0.7800 | 0.7653 |
| APF (Full) | 0.8009 | 0.7971 | 0.7976 |

消融实验显示，移除数据增强模块导致总分下降 0.0423，移除数据选择模块导致下降 0.0323。数据增强的贡献大于数据选择，说明语义多样性对模型泛化能力的提升更为关键。此外，评估阈值在 0.6 至 0.8 范围内变化时，性能波动极小（A 值在 0.7967 至 0.7976 之间），表明该框架对超参数不敏感，鲁棒性较好。

评估指标 Aobj 采用 Spearman 秩相关系数衡量目标函数排序一致性，Acon 采用 L1 范数衡量约束可行性分类准确率。该评估协议完全依赖 LLM 生成的参考排序，缺乏独立的人工或物理真值验证。论文未提供代码开源链接，且仅在单一天线设计任务上验证，未报告跨领域泛化结果。

## 关联研究分析

从验证机制看，本文与 ORLM 形成鲜明对比。ORLM 依赖求解器反馈进行数据过滤，其假设是求解器执行成本低廉且即时可用，这在 LP/MILP 场景中成立，但在高成本仿真中失效。本文通过测试实例排序一致性替代求解器反馈，本质上是用 LLM 的推理能力模拟求解器的验证功能。这一设计的根源在于任务特性：高成本仿真无法提供高频反馈，迫使研究者寻找离线、低成本的代理指标。然而，LLM 排序一致性作为代理指标，其理论边界尚不明确，特别是在需求高度冲突或测试实例分布稀疏时，排序一致性是否仍能准确反映语义正确性，论文未给出理论保证。

从数据构建看，本文与 LLMOPT 同属微调路线，但数据生成策略不同。LLMOPT 结合多指令学习与对齐技术，数据合成依赖专家标注与 LLM 增强，仍隐含对执行验证的依赖。本文则完全基于历史仿真记录提取需求，并通过 LLM 生成方程与测试实例，实现了全流程的自动化数据构建。这种差异源于数据可用性：高成本仿真场景中，专家标注稀缺且昂贵，历史仿真记录成为唯一可靠的数据源。本文利用 LLM 改写与置换增强数据多样性，弥补了原始样本量有限的不足，但这也引入了 LLM 幻觉风险，即生成的方程可能看似合理但物理上不可行，而排序一致性验证可能无法捕捉此类深层错误。

## 总结

本文针对高成本仿真驱动设计中求解器反馈缺失导致的建模瓶颈，提出 APF 框架，通过测试实例排序一致性替代求解器验证，实现低成本数据筛选与模型微调。实验表明，微调后的 Llama-3.1-8B 在总分上达到 0.7976，超越 GPT-4o 的 0.6651，证明了小模型在特定工业任务上的潜力。然而，该框架仅在单一天线设计任务上验证，且评估依赖 LLM 生成的参考排序，缺乏独立真值校验。当测试实例分布与真实设计空间存在偏差时，排序一致性验证是否仍能可靠地识别语义错误，论文未给出回答。
