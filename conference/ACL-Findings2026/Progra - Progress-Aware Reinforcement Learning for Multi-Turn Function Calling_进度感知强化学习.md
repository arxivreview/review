# ACL-Findings2026最新论文 ｜Progra: Progress-Aware Reinforcement Learning for Multi-Turn Function Calling ｜进度感知强化学习

研究机构：上海交通大学

作者：Huacan Chai、Zijie Cao、Maolin Ran 等 14 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_23175b7799fb)

> 多轮函数调用面临的核心困境是模型无法维持对任务全局状态的连贯表征，导致局部动作与全局目标脱节。现有方法要么将多轮轨迹拆解为独立单轮样本训练，要么依赖端到端强化学习却缺乏显式的进度建模，两者均无法解决长程依赖中的状态追踪失效。本文提出PROGRA框架，通过合成包含历史摘要与未来规划的“进度感知”数据，并将其作为条件变量注入基于GRPO的强化学习训练中。该框架在τ-bench和BFCL-V3上显著优于基线，但其性能增益是否完全源于进度感知机制本身，还是受限于特定骨干模型的预训练质量，仍需更严格的控制实验来验证。

## 研究背景

多轮函数调用要求模型在连续交互中维持对任务状态的准确追踪。当对话轮次增加时，原始上下文长度线性增长，导致注意力稀释，模型难以从冗长的历史中提炼出关键约束。这种信息碎片化使得模型在后续轮次中容易重复调用已执行的函数或遗漏必要参数，即“进度感知缺失”。为应对此问题，主流路线分为两类：一是监督微调（SFT），通过将多轮对话拆解为单轮样本训练，但此举切断了时间连续性，使模型无法学习跨轮次的规划能力；二是端到端强化学习（RL），虽能优化长程回报，但缺乏显式的状态表征，导致策略在复杂工作流中陷入局部最优或循环。

PROGRA的切入点在于将“进度感知”显式化为可训练的结构化信号。它不依赖外部记忆模块，而是通过数据合成管线生成包含历史摘要与未来规划的文本，使模型在训练阶段即学会生成这种紧凑的任务状态表征。这一设计将隐性的上下文丢失转化为显性的生成任务，从而在强化学习阶段为策略提供稳定的条件输入，解决单轮SFT缺乏规划能力与端到端RL缺乏状态表征的双重缺陷。

## 核心方法

### 方法参照系

多轮函数调用通常被建模为马尔可夫决策过程（MDP），策略 $\pi_\theta$ 基于完整对话前缀 $S_{i,j}$ 生成动作。标准流程直接利用原始历史进行决策，但PROGRA的关键差异在于引入中间变量“进度感知” $S_a$，将状态空间从原始文本压缩为结构化的摘要与规划，以此作为策略的条件输入。

### 进度感知生成（PAG）

PAG阶段旨在合成高质量数据集以预热策略模型。其核心创新在于“模型感知验证”机制：生成器 $LLM_{gen}$ 为每个轨迹片段生成进度感知文档 $S_a$，随后冻结的目标策略 $LLM_{ver}$ 仅依据 $S_a$ 尝试重构函数调用。若重构结果与真实调用在模式层面等价，则保留该样本。这一设计解决了合成数据中“摘要信息不足”导致的训练噪声问题，确保 $S_a$ 包含重建动作所需的全部关键信息。

$$
\hat{a}_{fc} = LLM_{ver}(S_a, \text{info}_{meta}), \quad Eq(\hat{a}_{fc}, a_{fc}) = \mathbb{I}[\text{schema\_equal}(\hat{a}_{fc}, a_{fc})]
$$

该公式表明，只有当基于摘要重构的函数调用与真实调用在参数顺序、空白字符及集合元素上完全一致时，样本才被保留，从而保证了进度感知文档的信息完备性。

### 进度感知引导强化学习（PAG-RL）

PAG-RL阶段将进度感知集成到GRPO训练中。在每次rollout中，策略模型首先基于当前上下文生成进度感知 $S_{a_{i,j}}$，再以此条件生成动作 $A_{i,j+1}$。奖励函数 $r_{i,j}$ 包含格式、模式、任务成功及效率惩罚四项，其中任务成功奖励 $r_{acc}$ 仅在环境状态达到目标时给予。通过组内相对优势估计，GRPO优化策略以最大化轨迹级回报，同时KL散度项防止策略偏离SFT参考模型。

$$
r_{i,j} = \alpha_{fmt}\mathbb{I}[\text{TEMPLATE}(A_{i,j})] + \alpha_{schema}\mathbb{I}[\text{SCHEMA}(A_{i,j})] + \alpha_{acc}\mathbb{I}[\text{SUCCESS}(SE_{i,j} \Rightarrow SE_{i,j+1})] - \lambda\mathbb{I}[A_{i,j} \neq \emptyset]
$$

该奖励设计将局部动作的规范性与全局任务完成度耦合，进度感知作为条件变量减少了上下文冗余，使策略能更专注于关键决策点，从而提升长程任务中的决策效率与一致性。

## 实验评估

实验在BFCL-V3 MultiTurn和τ-Bench（Airline/Retail）上进行，基线包括SFT、ST-GRPO、MT-GRPO及Dr.GRPO变体。PROGRA在xLAM-2-8B骨干上表现最佳，τ-Bench Overall得分51.85%，显著高于Base Model的46.70%和MT-GRPO的49.52%。在Qwen2.5-7B上，PROGRA得分31.52%，同样领先于所有基线。

| 模型 | 方法 | τ-Bench Overall | BFCL-V3 Overall |
| :--- | :--- | :--- | :--- |
| xLAM-2-8B | Base Model | 46.70 | 69.25 |
| xLAM-2-8B | MT-GRPO | 49.52 | 64.56 |
| xLAM-2-8B | PROGRA | 51.85 | 69.56 |
| Qwen2.5-7B | Base Model | 35.20 | 46.70 |
| Qwen2.5-7B | MT-GRPO | 39.33 | 49.52 |
| Qwen2.5-7B | PROGRA | 38.00 | 51.85 |

消融实验显示，移除PAG阶段导致性能下降1.0%至1.8%，而移除PAG-RL则下降0.5%至1.8%，表明两阶段均有贡献，但PAG-RL的边际收益在强骨干上更显著。在xLAM-2-8B上，将PAG-RL替换为MT-GRPO导致性能下降10.69%，证实了进度感知引导对RL优化的关键作用。

评估边界方面，实验未报告置信区间，且缺乏与结构化记忆方法（如MemGPT）的直接对比。代码已开源，但超参数搜索范围较窄（LoRA rank 8-16），可能限制了对最优配置的探索。

## 关联研究分析

从问题动机看，PROGRA与PARL-MT均关注多轮工具调用中的进度感知，但PARL-MT侧重全局任务进度的隐式建模，而PROGRA将其显式化为文本摘要与规划。这一差异源于任务特性：函数调用具有明确的模式约束，使得文本化的进度表征更易验证与优化；而在开放式对话中，进度边界模糊，文本摘要可能无法充分捕捉非线性依赖。

从方法设计看，PROGRA与ACR同属上下文治理路线，但ACR采用动态重构策略，根据任务需求实时调整保真度，而PROGRA的PAG阶段是静态的预训练过程。PROGRA的优势在于计算效率更高，无需在线重构开销；但其局限在于无法适应训练时未见的复杂对话结构。当对话出现非线性话题切换时，预训练的进度感知模板是否仍能保持有效性，论文未给出回答。

## 总结

PROGRA旨在解决多轮函数调用中因进度感知缺失导致的长程依赖失效。其切入点在于将隐性的状态追踪转化为显式的文本生成任务，并通过模型感知验证确保数据质量。方法上，PROGRA结合PAG数据合成与PAG-RL强化学习，在τ-Bench上取得51.85%（xLAM-2-8B）和31.52%（Qwen2.5-7B）的成绩，显著优于SFT与标准GRPO。然而，实验局限于函数调用场景，未涉及开放式对话或情感交互，且缺乏与动态上下文重构方法的对比。当对话结构超出训练分布时，静态进度感知模板的泛化能力是否足够，仍是待验证的关键问题。
