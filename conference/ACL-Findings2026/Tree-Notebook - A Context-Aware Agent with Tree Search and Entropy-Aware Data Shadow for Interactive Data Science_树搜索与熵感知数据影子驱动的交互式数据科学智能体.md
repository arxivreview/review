> 数据科学智能体在长链推理中常因无法感知内存状态而陷入“静默失败”，即代码执行无错但数据已受损。现有线性框架缺乏回溯机制，导致早期错误沿任务链不可逆地传播。Tree-Notebook 将代码生成形式化为部分可观测马尔可夫决策过程（POMDP），通过树状拓扑与数据影子机制实现非线性探索与状态监控。该架构在基准测试中超越了线性基线，但其高昂的计算开销与对骨干模型能力的强依赖，限制了其在资源受限场景下的通用性。

## 研究背景

当智能体执行 `df.dropna()` 时，若该操作意外丢弃了 90% 的关键数据，传统基于标准输出（stdout）的反馈机制无法捕捉这一语义层面的灾难。这种状态不可见性（State Invisibility）导致智能体基于错误假设继续执行，形成“静默失败”。为缓解此问题，部分可观测马尔可夫决策过程（POMDP）框架被引入，它承认智能体无法直接访问物理状态，必须通过观测函数获取代理信息。然而，POMDP 在数据科学场景下的核心挑战在于如何定义观测函数，使其既能反映数据分布变化，又不会因提取原始数据而耗尽上下文窗口。

数据科学工作流具有强烈的探索性与试错特征，要求智能体能够并行测试多种假设（如不同的特征工程策略）并在失败时干净地回溯。主流线性智能体（如 Data Interpreter, TaskWeaver）采用“思考-行动-观察”的串行循环，一旦进入错误的特征工程路径，缺乏在不污染上下文的前提下回溯到历史状态的能力。JUPITER 虽引入了蒙特卡洛树搜索（MCTS），但其仅将树搜索用于瞬时的轨迹优化，且依赖文本日志推断状态，未能解决数据语义感知的根本缺失。Tree-Notebook 的切入点在于将 Jupyter Notebook 单元格本身重构为持久化的树状拓扑，并引入专门针对数据分布的观测机制，从而在结构上支持非线性探索与状态回滚。

## 核心方法

### 方法参照系

本文问题属于结构化编排中的搜索增强智能体。与 JUPITER 等仅将树搜索作为推理时优化手段不同，Tree-Notebook 将树结构作为上下文管理的持久化载体。关键差异在于状态感知机制：前者依赖文本反馈（如错误日志），后者依赖结构化的数据元信息投影，这使得智能体能够区分“语法正确”与“语义有效”。

### 熵正则化轨迹优化

传统代码生成聚焦于语法正确性，但在数据科学中，代码可能运行无误却违反语义完整性（如错误地删除关键列）。为量化这种“隐性幻觉”风险，Tree-Notebook 引入独立评估器计算主观语义熵（Subjective Semantic Entropy）。该机制将当前状态下的动作后果映射为三个互斥类别：有效（逻辑收敛）、无效（无实质变化）和破坏性（信息丢失）。

$$ h_t(s_t) = -\sum_{i=1}^{3} P(y_i) \log P(y_i) $$

其中 $P(y_i)$ 是评估器对第 $i$ 个语义类别的置信度分布。该公式的物理含义是：当模型对当前操作后果的确定性高时（熵低），系统倾向于原子扩展；当不确定性高时（熵高），系统触发防御性分支搜索。这种熵正则化项 $\lambda \cdot h_t(s_t)$ 被加入目标函数，作为对高风险不确定性的惩罚，从而在探索效率与执行风险之间取得平衡。

### 数据影子与同构合并

为解决状态不可见性，Tree-Notebook 在每次执行后注入“数据探针”，提取 DataFrame 的维度、模式语义、类型分布及统计摘要，重构为轻量级状态表示 $o_t$，即“数据影子”（Data Shadow）。这一机制不仅作为智能体理解环境转移的唯一证据，还用于状态空间压缩。

$$ s_i \cong s_j \iff o_i \equiv o_j $$

当两个节点的观察影子完全相同时，它们被视为观察等价，系统执行合并操作，将指数级增长的树结构压缩为有向无环图（DAG）。这一设计消除了计算冗余，避免了在相同数据状态下重复生成探索代码，从而在保持语义感知的同时降低了推理成本。

## 实验评估

在 InfiAgent-DABench 和 DSBench 上，Tree-Notebook 对比了 ReAct、AutoGen、TaskWeaver、Datawise Agent 及 JUPITER 等基线。基线覆盖了线性执行、多智能体协作及搜索增强路线，但缺失了针对安全部署或异构数据处理的最新基线。

| 方法 | 平均 Token 消耗 | 准确率 (%) |
| :--- | :--- | :--- |
| ReAct | 3,937 | 81.32 |
| AutoGen | 3,850 | 73.54 |
| TaskWeaver | 15,069 | 85.99 |
| Datawise Agent | 8,557 | 85.99 |
| Tree-Notebook | 14,977 | 89.49 |

Tree-Notebook 在 InfiAgent-DABench 上以 89.49% 的准确率超越 TaskWeaver 和 Datawise Agent（均为 85.99%），尽管其 Token 消耗（14,977）与 TaskWeaver（15,069）相当，但显著高于 ReAct（3,937）。在 DSBench 建模任务中，Tree-Notebook 使用 GPT-4o 取得 54.20 的相对性能差距（RPG）分数，优于 Datawise Agent 的 53.18，表明其在复杂建模流程中的稳定性。

| 变体 | 基础准确率 (%) | 噪声准确率 (%) |
| :--- | :--- | :--- |
| Tree-Notebook (Full) | 89.49 | 80.54 |
| w/o Dynamic Branching | 85.99 | 73.15 |
| w/o Spatio-Temporal Back | 87.55 | 77.82 |
| w/o Data Shadow | 86.38 | 76.65 |

消融实验显示，移除动态分支导致准确率下降最显著（从 89.49% 降至 85.99%），验证了非线性探索对逃离局部最优的重要性。移除时空回溯机制使噪声环境下的准确率从 80.54% 降至 77.82%，证实了检查点回滚在防止状态污染中的作用。数据影子的移除则导致基础准确率下降至 86.38%，表明结构化状态感知对减少幻觉至关重要。

评估边界方面，实验主要基于 GPT-4o 等商业大模型，未充分验证在开源小模型（如 Qwen3）上的表现，这与领域内对本地部署安全性的关注存在差距。代码已开源，但树搜索的超参数（如分支因子 K、熵阈值 δ）对性能的影响未做详细敏感性分析。

## 关联研究分析

从问题动机看，Tree-Notebook 与 JUPITER 均试图解决线性智能体的错误传播问题，但 JUPITER 依赖文本反馈推断状态，而 Tree-Notebook 通过数据影子直接感知数据分布。这一差异源于任务特性：数据科学中的“正确性”不仅取决于代码语法，更取决于数据语义的完整性，文本日志无法捕捉 `df.dropna()` 造成的数据丢失。JUPITER 的局限在于其搜索空间是瞬时的，无法支持跨步骤的状态回溯，而 Tree-Notebook 的持久化树结构使得回溯成为可能。

从方法设计看，Tree-Notebook 与 Datawise Agent 同属结构化编排，但 Datawise Agent 采用有限状态机（FST）进行线性规划，而 Tree-Notebook 采用 POMDP 树搜索。Datawise Agent 在噪声环境下的准确率保留率为 0.8145，低于 Tree-Notebook 的 0.9000。这一差距表明，线性状态机在面对环境噪声（如无关文件干扰）时，缺乏足够的灵活性来调整执行路径。Tree-Notebook 的分支机制允许智能体在不确定时并行探索多种策略，从而在噪声环境中表现出更强的鲁棒性。

## 总结

Tree-Notebook 旨在解决数据科学智能体中状态不可见性导致的静默失败与错误传播问题。其切入点在于将 Notebook 单元格重构为持久化树拓扑，并通过数据影子机制实现语义层面的状态监控，从而支持非线性回溯与分支探索。实验证明，该架构在 InfiAgent-DABench 上达到 89.49% 的准确率，且在噪声环境下保持 0.9000 的性能保留率，优于线性基线。然而，其高昂的 Token 消耗（14,977）和对 GPT-4o 等强骨干模型的依赖，限制了其在资源受限或隐私敏感场景中的应用。当骨干模型替换为开源小模型时，数据影子机制的语义评估能力是否依然有效，论文未给出回答。
