# ACL-Findings2026最新论文 ｜Human-Agent Collaborative Paper-to-Page Crafting ｜学术网页自动生成

研究机构：上海交通大学

作者：Qianli Ma、Siyu Wang、Chen Yilin 等 10 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_8fdd22e897b1)

> 学术项目页的构建长期依赖人工模板适配，耗时且质量不一。现有端到端大语言模型（LLM）直接生成网页时，常出现布局混乱与事实幻觉，且缺乏对作者意图的响应机制。AutoPage 提出一种粗到细的多智能体协作框架，通过叙事规划、多模态内容生成与交互式渲染三阶段流水线，嵌入事实校验与可选人工干预，实现高保真网页的自动化构建。该框架在自建基准 PageBench 上显著优于基线模型，但其评估体系局限于单一数据集，跨领域泛化能力尚待检验。

## 研究背景

学术项目页是论文传播的关键载体，其核心挑战在于将长文档压缩为结构化、可交互的网页，同时保持事实严谨性与视觉吸引力。这一过程涉及两个关键概念：一是**内容压缩保真度**，即在大幅缩减文本量的同时，确保关键信息（如实验数据、方法细节）不丢失；二是**交互式 DOM 构建**，区别于静态海报的固定画布，网页需支持响应式布局与非线性导航，这对布局生成的动态性提出了更高要求。

当前主流方法分为两类：一是基于规则或模板的早期系统，灵活性不足，难以处理复杂学术内容；二是基于 LLM 的端到端生成方法，如 GPT-4o 直接转换 PDF 为 HTML，但实验表明其生成的页面常出现布局不合理、内容冗余或事实错误。这些方法的共同瓶颈在于缺乏对生成过程的细粒度控制与质量校验机制。AutoPage 的切入点在于将网页生成重构为“粗到细”的协作过程：先建立全局叙事结构，再逐步填充多模态内容，最后进行交互式渲染，并在每个阶段嵌入 LLM/VLM 校验器以抑制幻觉，同时提供可选的人工检查点以对齐作者意图。

## 核心方法

### 方法参照系

本文问题可归类为“基于 LLM 的结构化视觉内容生成”，与海报布局生成（如 PosterLlama）或设计代码合成（如 DesignAsCode）共享“语义推理→代码输出”的基本范式。关键差异在于：本文处理的是长文档到动态网页的转换，需同时解决内容压缩保真、多模态对齐与交互式 DOM 构建三重约束，而现有布局生成方法主要关注静态画布内的元素排列。

### 多阶段叙事规划与内容生成

叙事规划阶段的核心创新在于引入“Page Content Planner”智能体，其作用是将论文原始章节映射为网页叙事大纲，而非简单的一一对应。该智能体基于解析后的资产库（包含文本摘要与视觉元素链接），生成一个优化后的逻辑结构，确保网页叙事符合人类阅读习惯。设计动机在于解决端到端 LLM 直接生成时常见的“结构混乱”问题——即模型倾向于按论文顺序堆砌内容，而非构建连贯的网页叙事。形式化地，设论文章节集合为 $\mathcal{S} = \{s_1, s_2, ..., s_N\}$，Page Content Planner 的输出为网页大纲 $\mathcal{O} = \{o_1, o_2, ..., o_M\}$，其中 $o_j$ 是 $\mathcal{S}$ 中一个或多个章节的重组与摘要，满足叙事连贯性约束 $\text{Coherence}(\mathcal{O}) > \tau$。这一设计使得后续内容生成阶段能在一个结构清晰的框架内进行，避免了局部生成导致的整体不一致。

### 多模态内容生成与事实校验

内容生成阶段采用“文本优先”原则，即先生成每个大纲节点的文本内容，再基于文本选择并渲染相关视觉元素。这一设计解决了视觉元素与文本脱节的问题——在端到端方法中，图像常作为独立对象插入，缺乏与叙事的语义关联。形式化地，设大纲节点 $o_j$ 的文本生成为 $T_j = f_{\text{text}}(o_j, \mathcal{A})$，其中 $\mathcal{A}$ 为资产库；视觉元素选择为 $V_j = f_{\text{vis}}(T_j, \mathcal{A})$，满足语义对齐约束 $\text{Sim}(T_j, V_j) > \sigma$。随后，Content Checker 智能体验证 $T_j$ 与 $V_j$ 的一致性，并检查文本是否忠实于源论文。设计动机在于抑制 LLM 幻觉——实验表明，移除 Content Checker 后，语义保真度从 0.739 降至 0.695，视觉内容准确率从 3.13 降至 2.75，证明该机制对事实严谨性的关键作用。

## 实验评估

实验在自建基准 PageBench 上进行，该基准包含 1,500+ 篇 ICML/ICLR/NeurIPS 论文及其对应项目页，测试集通过聚类采样选取 100 个代表性页面。基线方法包括 GPT-4o、Gemini-2.5-Flash、Qwen3-235B 等端到端 LLM，以及 AutoGen 框架下的多智能体变体。主实验结果显示，AutoPage 在所有指标上均优于对应基线模型。例如，AutoPage-Gemini-2.5-Flash 的美学分数为 2.69，而 Gemini-2.5-Flash 端到端仅为 2.48；AutoPage-Qwen 的视觉内容准确率为 3.01，而 Qwen 端到端为 2.52。

消融实验揭示了各组件的贡献。移除 Page Content Planner 导致布局与连贯性从 2.15 降至 1.80，压缩感知信息准确率从 1.744 降至 1.523，证明全局结构规划对网页组织的关键作用。移除 Text Content Generator 后，压缩率从 9.168 骤降至 4.326，表明保留原始文本虽提高了表面相似度，但损害了内容的简洁性与可用性。移除所有校验器（Content Checker 与 HTML Checker）导致美学分数从 2.69 降至 1.90，视觉内容准确率从 3.13 降至 2.75，证实迭代校验机制对质量提升的必要性。

评估边界方面，PageBench 为自建基准，缺乏与现有布局生成基准（如 CGL、PKU）的交叉验证，限制了跨领域泛化能力的评估。指标体系依赖 LLM/VLM-as-Judge，可能存在评分噪声，且未报告置信区间。代码与数据集已开源，但超参数与 GPU 配置细节未在正文中完整披露，可复现性依赖于附录补充。

## 关联研究分析

从问题动机看，AutoPage 与 PosterLlama 同属 LLM 驱动的视觉内容生成，但前者聚焦于长文档到动态网页的转换，后者关注静态海报的布局生成。关键差异在于：PosterLlama 假设布局解空间有限，可通过语义推理直接生成坐标或代码；而 AutoPage 面临内容压缩保真与交互式 DOM 构建的双重约束，需通过多阶段规划与校验机制来管理复杂性。这一差异源于任务特性——网页的非线性导航与响应式布局要求生成过程具备全局结构感知能力，而非局部元素排列。

从方法设计看，AutoPage 与 DesignAsCode 均强调 HTML/CSS 代码生成与可编辑性，但后者采用“Plan-Implement-Reflect”流水线，通过视觉反馈修正像素级错误；前者则引入“Checker Agents”进行事实与美学双重校验，并支持可选的人工干预。设计差异的根源在于：DesignAsCode 的目标是视觉保真度，而 AutoPage 更关注学术内容的严谨性与作者意图对齐。AutoPage 的校验机制不仅检查视觉布局，还验证文本与源论文的一致性，这一设计在 DesignAsCode 中未体现，可能源于学术网页对事实准确性的更高要求。

## 总结

AutoPage 要解决的核心矛盾是学术长文档到交互式网页的转换中，内容压缩保真、视觉质量与作者意图对齐难以同时满足。现有端到端 LLM 方法因缺乏细粒度控制与质量校验，常产生布局混乱与事实幻觉；AutoPage 通过粗到细的多智能体流水线，嵌入叙事规划、多模态生成与交互式渲染三阶段，并在每阶段引入 LLM/VLM 校验器与可选人工检查点，实现了高保真网页的自动化构建。实验表明，AutoPage-Gemini-2.5-Flash 的美学分数达 2.69，视觉内容准确率为 3.13，显著优于基线。然而，其评估局限于自建基准 PageBench，缺乏跨领域泛化验证，且依赖 LLM/VLM-as-Judge 的评分机制可能存在噪声。当测试集扩展到非学术领域（如商业落地页）时，该框架的叙事规划与校验机制是否仍能保持有效性，论文未给出回答。
