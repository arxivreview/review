# ACL-Findings2026最新论文 ｜Efficient Hallucination Detection in Automatic Code Generation ｜代码生成中的行级幻觉检测

作者：Georgii Andriushchenko、Roman Garaev、Lyudmila Rvanova 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_973296e57410)

> 大语言模型生成的代码常出现语法正确但逻辑错误的“幻觉”，现有检测手段多停留在整段代码层面，无法定位具体错误行，阻碍了自动化调试与自我修正。本文切入点在于利用模型内部表征构建行级监督检测器，通过Diff算法自动标注训练数据，以Transformer编码器聚合Token特征至行级。该方法在多个开源代码模型上显著优于无监督基线，但其对代码风格差异的敏感性限制了泛化能力，且未验证在闭源模型上的有效性。

## 研究背景

当检测器面对新生成模型时，其训练域与测试域的数据分布出现系统性差异——这一现象称为分布偏移。分布偏移导致传统分类器决策边界失效，而实际场景中往往能获取少量目标域样本，这恰好构成了小样本学习的条件：仅凭每个类别极少量标注样本泛化到新任务。解决此类问题的经典框架是原型网络，它计算各类别支持样本的特征均值作为"原型"，再通过距离度量完成分类。

在自然语言生成领域，幻觉检测已从黑盒采样转向白盒内部表征探测，SAPLMA等工作证明隐藏状态包含线性可分的幻觉信号。然而，代码生成领域的幻觉检测仍主要依赖执行反馈或整段代码分类，缺乏对单行代码逻辑错误的细粒度定位。现有方法如CodeBERT仅利用代码Token特征，无法捕捉LLM内部对逻辑一致性的隐式判断，且缺乏公开的行级标注数据集。本文旨在填补这一空白，提出基于内部表征的行级幻觉检测框架，解决代码调试中“错误定位难”的核心痛点。

## 核心方法

### 方法参照系

本文问题属于内部表征探测路线，但任务粒度从自然语言的Token/Sentence级细化至代码行级。与SAPLMA等单层线性探针不同，本文需处理代码行的结构性依赖，因此采用多层Transformer编码器聚合Token特征，而非简单的池化操作。关键差异在于标注方式：代码领域缺乏语义一致性标签，本文引入Diff算法基于代码差异生成行级Ground Truth。

### Diff-based 行级标注流水线

传统代码幻觉检测依赖执行测试，但测试覆盖率有限且无法定位具体错误行。本文提出基于Diff的自动标注算法：将生成代码与正确代码按行分割，计算行级Diff，标记所有被删除的行（"-"）及紧随新增行（"+"）之后的第一行为幻觉行。该设计解决了代码领域缺乏细粒度Ground Truth的瓶颈，使得监督学习成为可能。标注过程无需人工干预，成本低廉，但存在对代码风格差异敏感的局限，即语法等价但风格不同的代码可能被误标为幻觉。

### Transformer 行级不确定性估计器

在特征聚合环节，通常做法是对Token特征进行平均池化，但这忽略了代码行内Token的顺序依赖关系。本文引入可学习的行位置嵌入 $E_s$，将每个Token的投影特征 $\tilde{f}_t$ 与 $E_s$ 相加，得到上下文感知特征 $\tilde{f}_{t,s} = \tilde{f}_t + E_s$。随后，通过Transformer编码器 $T$ 处理整行Token序列，并取平均得到行级表示 $h_s = \frac{1}{|s|} \sum_{t \in s} T(\{\tilde{f}_{t,s}\}_{t \in x \circ y})$。最后，通过MLP分类器输出行级不确定性 $U(s) = \sigma(\text{MLP}_{\text{clf}}(h_s))$。该设计通过位置嵌入和自注意力机制捕捉行内逻辑结构，相比线性探针能更有效地区分“语法正确但逻辑错误”的代码行，解决了单层探针在复杂代码结构上检测精度不足的问题。

## 实验评估

实验在DeepSeek-Coder（1.3B, 6.7B, 33B）、CodeLlama 7B和Llama-3-8B-Instruct上进行，数据集涵盖Python代码合成（MBPP, HumanEval）和Java代码修复（HumanEval Java, Defects4J）。基线覆盖无监督UQ（MSP, Perplexity, Attention Score）、监督探针（SAPLMA, Linear Probe）及代码专用模型（CodeBERT）。

| 方法 | DSC 1.3B | DSC 6.7B | DSC 33B | CL 7B | Average |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Attention Score | 0.493 ±.054 | 0.336 ±.047 | 0.303 ±.045 | 0.454 ±.055 | 0.397 ±.050 |
| CodeBERT | 0.539 ±.038 | 0.359 ±.034 | 0.339 ±.037 | 0.471 ±.040 | 0.472 ±.037 |
| SAPLMA (MLP HS) | 0.669 ±.071 | 0.570 ±.069 | 0.579 ±.089 | 0.735 ±.056 | 0.638 ±.056 |
| Transformer (TP, AW, HS) | 0.719 ±.085 | 0.606 ±.068 | 0.575 ±.085 | 0.811 ±.044 | 0.678 ±.071 |

Transformer检测器在CodeLlama 7B上PR-AUC达0.811，显著优于SAPLMA的0.735和无监督基线Attention Score的0.454。在DeepSeek-Coder 6.7B上，Transformer检测器（0.606）较SAPLMA（0.570）提升0.036，较最佳无监督方法（0.336）提升0.27。消融实验显示，隐藏状态（HS）特征贡献最大（0.572 PR-AUC），注意力权重（AW）次之（0.493），Token概率（TP）贡献较低（0.213）。模型规模增大导致PR-AUC下降，表明大模型产生的幻觉更细微，检测难度增加。

评估指标采用PR-AUC以应对类别不平衡问题。局限在于Diff标注对代码风格敏感，可能导致语法等价代码被误标；实验仅覆盖开源模型，未验证闭源API模型；SWE-bench因OOM被排除，限制了长上下文场景的评估。代码与预训练检测器已开源，超参数通过贝叶斯优化确定，训练时间在单卡A100上小于1小时。

## 关联研究分析

从方法设计看，本文与SAPLMA的核心差异在于特征聚合方式。SAPLMA使用单层线性探针在最后一层隐藏状态上预测幻觉，适用于自然语言中Token级信号的独立假设。而代码行具有强结构依赖，本文引入Transformer编码器和行位置嵌入，捕捉行内Token的顺序关系。这一差异源于任务特性：代码逻辑错误往往由多行交互产生，单层探针难以建模这种长程依赖。然而，Diff标注算法未考虑代码语义等价性，可能导致风格差异被误判为幻觉，这是任务特性决定的固有局限，而非方法设计缺陷。

从问题动机看，本文与SelfCheckGPT等黑盒方法形成互补。SelfCheckGPT通过多次采样一致性检测幻觉，计算成本高且无法定位具体错误行，适用于自然语言生成。本文采用白盒内部表征，单次前向传播即可获取行级不确定性，效率更高且定位更精确。但本文未对比SelfCheckGPT，隐含假设白盒方法在代码领域必然优于黑盒方法。这一假设在闭源模型场景下可能失效，因为无法访问内部状态时，黑盒采样仍是唯一选择。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文要解决的核心矛盾是代码生成中幻觉检测的粒度不足与标注缺失。现有方法依赖执行反馈或整段分类，无法定位具体错误行，且缺乏公开的行级标注数据集。本文抓住的切入点是利用Diff算法自动标注行级幻觉，并基于LLM内部表征训练轻量级Transformer检测器。实验证明，该方法在CodeLlama 7B上PR-AUC达0.811，显著优于无监督基线和SAPLMA。本文的边界在于Diff标注对代码风格差异敏感，可能导致语法等价代码被误标，且实验仅覆盖开源模型，未验证闭源场景下的有效性。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
