# ACL-Findings2026最新论文 ｜AJ-Bench: Benchmarking Agent-as-a-Judge for Environment-Aware Evaluation ｜环境感知智能体评估基准

研究机构：中国科学技术大学、新加坡国立大学

作者：Wentao Shi、Yu Wang、Yuyang Zhao 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.18240)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.18240)

> 随着强化学习（RL）在长程智能体训练中的规模化应用，如何在新环境中可靠验证智能体行为成为核心瓶颈。现有规则验证器无法泛化至复杂场景，而 LLM-as-a-Judge 仅依赖表面文本信号，缺乏对环境状态的直接访问。本文提出 AJ-Bench，首个系统评估 Agent-as-a-Judge 能力的多域基准，通过赋予评估者工具与环境交互权限，实现从静态文本判断到动态证据获取的范式转变。该基准填补了评估者能力量化空白，但其绝对性能（平均 F1 0.72）仍远未饱和，揭示了当前评估智能体在复杂多步行为验证中的显著局限。

## 研究背景

当智能体在复杂环境中执行多步任务时，其轨迹的正确性往往无法仅通过最终输出或静态文本比对来判定。例如，验证一个搜索智能体是否准确回答了“LongCat-Flash 技术报告发布日期”，仅凭模型内部知识可能产生幻觉，而必须通过浏览器工具访问 arXiv 页面获取真实证据。这种对“可验证证据”的需求，催生了 Agent-as-a-Judge 范式：评估者本身也是一个具备工具调用与环境交互能力的智能体，能够重放轨迹、检查中间状态并主动获取外部信息以做出判断。

传统评估体系存在双重断裂。一方面，规则验证器（Rule-based Verifiers）在狭窄任务中有效，但面对科学假设验证或长文事实核查等开放场景时，手工编写的规则无法覆盖所有边界情况。另一方面，LLM-as-a-Judge 虽具备泛化性，但其判断锚定于表面文本信号，无法区分“看似合理但事实错误”与“事实正确但表述冗余”的响应。更关键的是，现有针对 LLM-as-a-Judge 的基准（如 RewardBench, JudgeBench）均未要求评估者与环境交互，导致无法量化评估者在“何时需要交互”、“如何有效利用工具”以及“何种证据构成充分验证”等核心能力上的表现。AJ-Bench 的切入点正是这一空白：将评估对象从“被评估智能体的任务完成度”转向“评估智能体的证据获取与状态验证能力”，构建首个支持环境感知的多域评估基准。

## 核心方法

### 方法参照系

本文问题可置于“评估者能力基准”类别下，但与传统 LLM-as-a-Judge 基准的关键差异在于：传统基准假设评估者仅接收静态输入（轨迹文本），而本文要求评估者在隔离环境中主动执行工具调用以获取 Ground Truth 证据。这一差异使得评估指标从“文本对齐度”转向“环境交互有效性”。

### 三域任务设计与环境重放机制

AJ-Bench 覆盖搜索（Search）、数据系统（DS）和图形用户界面（GUI）三个域，共 155 个任务与 516 条标注轨迹。设计动机在于解决单一域评估无法捕捉评估者通用能力的问题：搜索域测试信息获取（Information Acquisition），DS 域测试状态验证（State Verification），GUI 域测试过程验证（Process Verification）。核心创新在于环境重放（Replay）机制：对于 DS 和 GUI 域，基准通过顺序执行轨迹中的动作序列，在隔离环境（本地或 AWS 实例）中重建任务的最终状态。评估者在此“活”环境中交互，而非仅读取静态日志。该机制的数学形式可表述为状态重建函数：

$$ S_{final} = \mathcal{R}(S_{initial}, A_1, A_2, \dots, A_T) $$

其中 $\mathcal{R}$ 为环境重放算子，$A_i$ 为轨迹动作序列。这一设计确保了评估者能访问与原始执行一致的环境状态，从而验证中间步骤的正确性，解决了静态文本评估无法检测“状态漂移”的问题。

### 多模态证据融合与 F1 评估协议

在 GUI 域，评估者需融合可访问性树（Accessibility Tree）与截图（Screenshot）两种模态的证据。论文通过消融实验发现，混合模态（Mixed）配置在 Excel 任务中表现最佳，但在 Word 任务中截图单独使用更优，表明模态有效性具有任务依赖性。评估指标采用 F1 分数，其计算依赖于二元标签（成功/失败）的预测准确性。对于搜索域，F1 基于单项（Item-level）评估聚合；对于 DS 和 GUI 域，基于轨迹级（Trajectory-level）评估。该协议的设计动机是避免单一准确率指标掩盖评估者在“部分正确”场景下的性能差异，例如在搜索任务中，评估者可能正确识别部分链接但遗漏关键引用，F1 能更敏感地反映这种不平衡。

## 实验评估

实验在 AJ-Bench 上进行，基线覆盖 SOTA 闭源模型（GPT-5, Claude-Opus-4.5, Gemini-3-Pro）与开源模型（DeepSeek-V3.2, Qwen3-235B）。关键发现是：Agent-as-a-Judge 在相同基座模型上显著优于 LLM-as-a-Judge。例如，GPT-5-mini-low 作为 LLM-as-a-Judge 时 Overall F1 为 59.00，而作为 Agent-as-a-Judge 时提升至 72.41，提升幅度达 13.41 个点。DeepSeek-V3.2 的提升更为显著，从 64.49 升至 77.34，提升 12.85 个点。这表明，赋予评估者环境交互权限比提升基座模型规模更能改善评估准确性。

| 模型 | 模式 | Search (Wide/Deep) | DS (FS/PG) | GUI (PPT/Word/Excel) | Overall |
| :--- | :--- | :--- | :--- | :--- | :--- |
| gpt-5-mini-low | LLM-as-a-Judge | 60.84 / 68.42 | 60.41 / 65.52 | 45.05 / 48.41 / 64.36 | 59.00 |
| gpt-5-mini-low | Agent-as-a-Judge | 65.93 / 75.69 | 67.54 / 67.30 | 76.28 / 72.22 / 81.89 | 72.41 |
| deepseek-v3.2 | LLM-as-a-Judge | 63.65 / 62.91 | 60.31 / 66.31 | 58.38 / 69.77 / 70.12 | 64.49 |
| deepseek-v3.2 | Agent-as-a-Judge | 72.47 / 82.14 | 72.60 / 72.70 | 83.14 / 78.64 / 79.71 | 77.34 |

消融实验揭示了两个反直觉发现。首先，推理努力（Reasoning Effort）并非单调提升性能：GPT-5-mini 的 medium 设置优于 low，但 high 设置并未持续优于 medium；DeepSeek-V3.2 的 thinking 模式甚至劣于 no-thinking 模式。这表明，更强的内在推理能力并不等同于更有效的工具调用与决策能力。其次，交互轮次（Interaction Turns）与性能正相关，但收益边际递减，且任务域敏感性不同：Word 和 PPT 任务对扩展交互更敏感，表明其更依赖迭代信息获取。

评估边界方面，AJ-Bench 存在两个主要局限。一是任务多样性受限，多数任务改编自现有基准（Mind2Web2, OSWorld, MCPMark），而非完全原创，可能引入分布偏差。二是环境稳定性问题，搜索域依赖外部网络，网络波动可能影响评估可靠性。此外，论文未报告计算成本（Token 消耗、延迟），而成本效率是评估智能体部署可行性的关键指标，这一缺失限制了结果在实际生产环境中的直接应用。

## 关联研究分析

从问题动机看，AJ-Bench 与 CORE（Michelakis et al., 2025）均强调过程验证，但对象不同：CORE 验证被评估智能体的动作路径，而 AJ-Bench 验证评估智能体的证据获取路径。这一差异源于任务特性的根本不同：CORE 关注“智能体是否做对了”，AJ-Bench 关注“评估者是否看对了”。AJ-Bench 的环境重放机制是解决“看对了”的关键，因为它允许评估者访问动态状态，而 CORE 的确定性有限自动机（DFA）标注主要依赖静态轨迹分析。这种差异暗示，评估者的能力评估必须包含环境交互维度，而不仅是轨迹匹配。

从方法设计看，AJ-Bench 与 AgentCompass（Chen et al., 2026）在基础设施层面有相似性，均致力于标准化评估协议，但焦点不同：AgentCompass 聚焦被评估智能体的执行环境标准化，AJ-Bench 聚焦评估者的交互环境标准化。AJ-Bench 的 MCPMark 框架选择体现了对“工具调用自主性”的重视，即评估者需自行决定何时调用工具，而非遵循预设工作流。这与 ReAct 框架的显式推理-行动交替形成对比，论文消融实验显示，MCPMark 与 ReAct 框架下的 Agent-as-a-Judge 均优于 LLM-as-a-Judge，但性能存在框架依赖性，表明执行框架的选择对评估者能力有实质性影响，这一发现呼应了领域共识中“脚手架混淆模型能力”的观点。

## 总结

AJ-Bench 解决了评估者能力量化缺乏环境感知维度的核心矛盾，通过环境重放机制与多域任务设计，首次系统验证了 Agent-as-a-Judge 范式的有效性。实验证明，赋予评估者工具权限比提升基座模型规模更能改善评估准确性，GPT-5-mini-low 的 F1 从 59.00 提升至 72.41，DeepSeek-V3.2 从 64.49 提升至 77.34。然而，评估者的绝对性能仍远未饱和，平均 F1 仅为 0.72，且在复杂多步行为验证中表现不稳定。推理努力与性能的非单调关系、模态有效性的任务依赖性，以及环境重放对网络稳定性的依赖，均表明当前评估智能体在动态、非结构化环境中的鲁棒性仍存疑。当评估者面对长时程、高噪声的真实部署环境时，其证据获取策略是否仍能保持可靠性，论文未给出回答。
