# ACL-Findings2026最新论文 ｜MT-OSC: Path for LLMs that Get Lost in Multi-Turn Conversation ｜一次性顺序压缩框架

作者：Jyotika Singh、Fang Tu、Miguel Ballesteros 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_0c6fc0e88a13)

> 多轮对话中，用户指令与关键上下文分散在多个轮次，导致大语言模型（LLM）性能显著衰减，而全量追加历史又迅速耗尽上下文窗口并增加延迟。现有压缩方法依赖微调、复杂层级结构或实时检索，难以在不牺牲信息保真度的前提下实现低延迟部署。MT-OSC 提出一种后台异步执行的一次性顺序压缩框架，通过少样本提示的 Condenser 与基于重叠度规则的 Decider 动态精简历史，在 10 轮对话中实现最高 72% 的 Token 削减，同时保持或提升任务准确率。该方案在工程集成上具有显著优势，但其压缩保真度边界与 Decider 规则的泛化能力仍存疑。

## 研究背景

多轮对话的核心困境源于上下文窗口的有限性与信息分布的非线性。当用户将完整指令拆分为多个轮次逐步披露时，模型面临“信息碎片化”挑战：早期轮次的关键约束在后续轮次中被噪声稀释，导致注意力机制无法有效锁定核心意图。这种失效并非简单的长度问题，而是由上下文漂移（Context Drift）引发的系统性错误累积。为应对此问题，主流方案分为两类：一是基于微调的摘要模型，如 Bae et al. (2022) 使用 T5 保留关键对话，但需额外训练且难以适应新领域；二是基于检索或层级编码的方法，如 Zhang et al. (2022) 利用注意力机制迭代精炼历史，但计算开销大且实时性差。这些方法往往在保真度与效率之间做出极端取舍，或依赖复杂的架构修改，限制了其在通用聊天系统中的即插即用能力。

MT-OSC 的切入点在于将上下文压缩从“实时推理路径”剥离至“后台异步进程”。它不修改主模型架构，也不依赖微调，而是利用一个独立的 LLM Agent 在对话间隙对历史进行一次性压缩。这种设计解决了现有方法中“压缩延迟影响用户体验”与“全量追加导致 Token 爆炸”的双重矛盾。通过引入 Decider 模块，MT-OSC 在压缩前评估信息冗余度，避免了在信息密集对话中盲目压缩导致的关键细节丢失，从而在工程可行性与信息保真度之间找到了新的平衡点。

## 核心方法

### 方法参照系

多轮上下文管理的通用流程通常涉及历史状态的显式存储与动态检索。标准做法是将所有历史轮次线性拼接至 Prompt，或通过 RAG 检索相关片段。MT-OSC 的关键差异在于其“一次性顺序”（One-off Sequential）策略：它不维护复杂的记忆树或图结构，而是将历史按固定窗口 $w$ 进行不可逆的压缩替换，且压缩过程完全异步，不阻塞当前轮次的生成。

### Condenser 与 Decider 协同机制

Condenser 模块负责执行实际的压缩操作，其设计动机在于解决通用摘要器容易遗漏关键指令（如否定词、实体名）的问题。Condenser 采用少样本提示（Few-shot Prompting），通过精心构造的示例展示不同压缩策略（如保留原文、综合合并、剔除无关轮次），使 LLM 能够根据对话语境动态调整压缩粒度。形式化地，对于窗口内的 $w$ 轮对话 $\{(u_i, a_i)\}_{i=0}^w$，Condenser 生成压缩后的用户-助手对 $C_j = (C_{ju}, C_{ja})$：

$$
C_j = \text{Condense}(\{(u_i, a_i)\}_{i=0}^w)
$$

这一过程将冗长的原始历史转化为紧凑的语义表示，直接减少了后续轮次所需的上下文 Token 数。

Decider 模块则作为安全阀，决定何时执行压缩。其设计动机在于防止在信息高度重复或密集引用的对话中，压缩导致关键约束丢失。Decider 采用基于词重叠度的规则函数，计算助手回复中新增词汇与用户查询的重叠比例。若平均重叠率超过阈值 $\gamma$ 且用户内容 Token 数超过 $\tau$，则跳过压缩，保留原始历史：

$$
D_w = \begin{cases}
\text{False} & \text{if } \text{Overlap}(a_0, a_w) > \gamma \text{ and } \text{UserTokens}(H_w) > \tau \\
\text{True} & \text{otherwise}
\end{cases}
$$

其中 $\text{Overlap}$ 衡量助手回复中未被用户提及的新词比例。该机制确保了在信息密度高的场景下，模型能访问完整的原始上下文，从而在 Token 效率与信息保真度之间实现自适应权衡。

### 异步顺序执行策略

MT-OSC 的执行策略是“一次性顺序”压缩。在对话进行到第 $w+2$ 轮时，系统使用压缩后的历史 $C_1$ 替换前 $w$ 轮的原始记录，而最近一轮保持原样。随着对话推进，每当累积 $w$ 轮新对话，系统再次触发压缩。这种策略避免了每次查询都重新压缩的开销，且由于压缩在后台异步执行，其结果在下一轮对话开始时即可用，对用户无感知延迟。

## 实验评估

| 数据集 | 指标 | MT-baseline | MT-OSC (w=4) |
| :--- | :--- | :--- | :--- |
| BFCLshrd | Accuracy (%) | 81.13 | 86.79 |
| GSMshrd | Accuracy (%) | 83.45 | 84.80 |
| HEvalshrd | Accuracy (%) | 74.67 | 77.33 |
| Spidershrd | Accuracy (%) | 76.95 | 79.44 |
| ToTToshrd | BLEU | 0.19 | 0.19 |
| SoHshrd | Joint Score | 0.13 | 0.13 |
| refinemte | 10-point Rating | 5.39 | 5.35 |
| followmte | 10-point Rating | 8.47 | 8.47 |
| recollmte+ | Accuracy (%) | 94.22 | 92.22 |
| expanmte+ | 10-point Rating | 8.61 | 7.9 |

实验在 10 个多轮数据集上进行，涵盖代码、数学、问答及开放式对话。基线为 MT-baseline（全量追加历史）。结果显示，MT-OSC 在 BFCL、GSM、HumanEval 和 Spider 等任务上显著提升了准确率，例如 BFCL 从 81.13% 提升至 86.79%。在 ToTTo 和 SoH 上，性能持平，表明压缩未造成信息丢失。在 MT-Eval 的 recollection 和 expansion 任务上，性能略有下降（如 recollection 从 94.22% 降至 92.22%），这可能源于压缩过程中对细节记忆的轻微损失。

消融实验表明，Decider 模块在防止信息丢失方面至关重要。在 ToTTo 和 SoH 数据集上，移除 Decider 后性能显著下降（ToTTo 从 0.19 降至 0.18，SoH 从 0.13 降至 0.08），验证了其在信息密集对话中的保护作用。此外，将 Condenser 替换为简单摘要器导致性能全面下降，证明少样本提示在保留关键指令方面的必要性。

评估边界方面，实验主要使用 Llama-3.3-70B-Instruct 作为 Condenser，虽在附录中测试了其他模型，但主实验未涵盖所有架构。代码未公开，但提供了详细的 Prompt 模板和超参数设置（$\gamma=0.2, \tau=1000$），具备较高的可复现性。

## 关联研究分析

从方法设计看，MT-OSC 与 ACR（Adaptive Context Reconstruction）同属上下文重构路线，但 ACR 强调自适应治理与模块化自进化，而 MT-OSC 侧重异步执行与零延迟。ACR 可能通过更复杂的机制动态调整保真度，但 MT-OSC 的 Decider 规则更为轻量，适合实时性要求高的场景。与 MemGPT 相比，MT-OSC 无需修改模型架构或引入操作系统式内存层级，集成成本更低，但可能牺牲了对长程依赖的精细控制。

从问题动机看，MT-OSC 直接回应了 Lost in Conversation 现象中“信息碎片化”导致的性能衰减，但其解决方案是工程化的压缩，而非诊断性的机制分析。与 ICPO 等强化学习方法不同，MT-OSC 不优化策略本身，而是优化输入上下文的质量。这种差异源于任务特性：MT-OSC 适用于指令明确但分散的场景，而 ICPO 适用于意图模糊需动态推断的场景。MT-OSC 的 Decider 规则是否能在意图高度模糊的对话中有效区分关键信息，论文未给出回答。

## 总结

MT-OSC 旨在解决多轮对话中上下文窗口耗尽与信息碎片化导致的性能衰减矛盾。其切入点是后台异步压缩，通过少样本 Condenser 与规则化 Decider 实现高效且保真的历史精简。实验证明，该方法在 10 轮对话中实现最高 72% 的 Token 削减，同时在 BFCL 等任务上提升准确率至 86.79%。其边界在于 Decider 规则对信息密集对话的依赖，以及在 recollection 等细节记忆任务上的轻微性能损失。当对话轮次进一步增加或意图高度模糊时，基于重叠度的 Decider 规则是否仍能准确识别关键信息，论文未给出回答。
