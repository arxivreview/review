# ACL-Findings2026最新论文 ｜Robustness via Referencing: Defending against Prompt Injection Attacks by Referencing the Executed Instruction ｜指令引用过滤防御

作者：Yulin Chen、Haoran Li、Yuan Sui 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2504.20472)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_254d4f83bdb4)

> 提示注入攻击利用大语言模型（LLM）无法区分指令与数据的缺陷，导致模型执行恶意指令。现有防御多采用抑制策略，强行约束模型遵循原始指令，但实验表明这种抑制往往失效且损害通用能力。本文切入点在于利用而非抑制模型的指令遵循能力，通过提示模型显式引用所执行指令的标签，再基于标签过滤无关响应。该方法在QA场景下将攻击成功率（ASR）降至接近0%，但未验证代理工具调用场景下的鲁棒性，其依赖模型正确生成引用的假设在复杂交互中是否成立存疑。

## 研究背景

当LLM处理包含外部检索数据的任务时，若数据中嵌入恶意指令，模型可能将其视为有效指令执行，这一现象称为提示注入。直接注入源于用户输入，间接注入则来自网页等外部数据源，后者因攻击者无需控制用户输入而更具隐蔽性。攻击成功的关键在于模型将数据内容误判为指令，并基于其生成响应。

提示注入防御的主流路线分为提示工程与微调两类。提示工程方法如Sandwich通过追加提醒强化原始指令，Hines et al. (2024)使用特殊Token分隔数据区；微调方法如StruQ通过训练赋予授权指令特权地位。这些方法的共同假设是模型倾向于执行注入指令，因此需通过外部约束或内部对齐来抑制这种倾向。然而，实验显示抑制策略难以彻底阻断攻击，且可能降低模型在标准任务上的性能。本文观察到，在部分成功攻击案例中，模型会显式引用注入指令（如“For the second instruction...”），这提示了一种新路径：不抑制指令执行，而是通过引用机制识别并过滤非原始指令的响应。

## 核心方法

### 方法参照系

提示工程防御的标准流程是修改系统提示以强化原始指令的优先级，如Sandwich在提示前后添加提醒。本文问题与该流程的关键差异在于：不试图改变模型对指令的响应倾向，而是利用模型生成响应时引用指令源的特性，将防御转化为后处理过滤问题。

### 标签化指令定位

传统方法将数据内容作为整体处理，无法区分其中嵌入的指令位置。本文首先将数据内容分割为多行，每行前缀唯一标签（如`[L 1]`），原始输入指令固定置于第一行并标记为`[L 1]`。这一设计解决了注入指令位置未知的问题，使模型在生成响应时能明确标识所执行指令的来源。标签化将模糊的指令-数据边界转化为离散的位置标识，为后续过滤提供结构化依据。

### 引用生成与过滤机制

模型被提示在生成响应时，先识别并重复所执行指令的标签，再输出对应答案，最后以`[end]`结束。响应结构化为元组集合 $R = \{(t_i, I_i, r_i)\}_{i=1}^N$，其中 $t_i$ 为标签，$I_i$ 为指令，$r_i$ 为响应。过滤函数保留仅关联原始指令标签的响应：

$$\hat{R} = \{(t_i, I_i, r_i) \mid t_i = t_{ori}\}_{i=1}^N$$

该公式的物理含义是：仅当响应引用的标签与原始指令标签一致时，该响应才被保留。这一机制将防御从“阻止模型执行注入指令”转化为“移除执行注入指令的响应”，利用了模型指令遵循能力而非对抗它。为应对标签泄露风险，本文引入动态标签机制，每次交互从标签词汇表中随机选择参考标签，使基于静态标签的自适应攻击失效。

## 实验评估

实验在AlpacaFarm（直接注入，208样本）和Inj-SQuAD/Inj-TriviaQA（间接注入，各900样本）上进行，基线包括提示工程方法（Sandwich, Reminder, Spotlight）和微调方法StruQ。本文方法在Inj-SQuAD上对Llama3.1-8B-Instruct的ASR最低达0.11%，在AlpacaFarm上对Qwen2-7B-Instruct的ASR为0.00%，显著优于StruQ（ASR 0.96%-30.29%）和提示工程基线（ASR 19.67%-84.13%）。

| 防御方法 | Llama3.1-8B-Instruct (Inj-SQuAD) ASR (%) | Qwen2-7B-Instruct (AlpacaFarm) ASR (%) |
| :--- | :--- | :--- |
| None | 84.00 | 84.13 |
| Sandwich | 42.22 | 26.44 |
| StruQ | 56.00 | 10.10 |
| Ours | 0.22 | 2.88 |

消融实验显示，窗口大小对防御性能影响极小（Llama3-8B-Instruct上最佳与最差ASR差1.11%），表明方法不依赖特定分割粒度。移除上下文学习示例导致Qwen2-7B-Instruct在TriviaQA上性能显著下降，证实示例对维持结构化输出的必要性。仅应用行分割而无其他机制时，防御效果有限，说明引用生成与过滤是核心贡献。

评估边界方面，本文未报告计算延迟或Token消耗，动态标签机制的推理开销未知。评估协议基于QA任务，未覆盖代理工具调用场景，且假设攻击者不知晓防御策略，未测试完全自适应攻击。代码已开源，但超参数细节（如标签词汇表大小）未在正文中明确。

## 关联研究分析

从问题动机看，本文与CaMeL（Ji et al., 2025）均针对间接提示注入，但CaMeL采用系统级隔离，通过信息流控制强制区分信任域，而本文依赖模型级引用生成。CaMeL在AgentDojo上ASR达0.0%，本文在Inj-SQuAD上ASR 0.11%，差异源于任务场景：AgentDojo涉及工具调用与多轮交互，Inj-SQuAD为单轮QA。本文方法在代理场景中是否因工具调用复杂性导致引用生成失效，论文未给出回答。

从方法设计看，本文与Suo (2024)的签名验证逻辑相似，均通过标记区分授权与非授权指令，但Suo在模型执行前验证签名，本文在执行后过滤响应。这一差异源于对模型指令遵循能力的不同假设：Suo假设模型可被约束仅执行签名指令，本文假设模型会执行所有指令但可事后识别来源。当模型幻觉导致引用错误时，本文防御失效，而Suo的预验证机制可能更鲁棒，但两者在模型能力边界上的权衡未被量化比较。

## 总结

本文要解决的核心矛盾是提示注入防御中抑制策略的失效与效用损失。现有方法通过约束模型行为来阻断攻击，但难以彻底抑制且损害通用能力；本文利用模型指令遵循能力，通过引用-过滤机制将防御转化为后处理问题，在QA场景下将ASR降至0.11%-2.88%。其边界在于依赖模型正确生成引用，且仅在单轮QA任务中验证，未覆盖代理工具调用场景。当模型在复杂交互中生成错误引用时，过滤机制是否仍能保持鲁棒性，论文未给出回答。
