> 数据科学智能体在自动化分析中常陷入“幻觉”陷阱，即生成的洞察看似合理却与底层数据事实不符，或仅重复已知信息而缺乏新颖性。现有基准如 InsightBench 存在目标模糊、数据缺失及评估指标单一（仅关注召回率）的缺陷，导致无法准确衡量智能体的真实探索能力。本文通过构建包含 1000 个高质量洞察的 InsightEval 数据集，并引入 Insight F1 与 Novelty 指标，实现了对智能体洞察发现能力的全面量化。该工作填补了细分领域的评估空白，但其依赖 LLM 作为评估器的机制可能引入新的主观偏差。

## 研究背景

在数据科学工作流中，从原始表格数据提取深层模式（Insight Discovery）是核心价值环节，但大语言模型（LLM）直接处理数据时面临“状态不可见性”问题，即模型无法直接感知 DataFrame 的完整内存状态，易基于错误假设生成洞察。为解决此问题，主流智能体采用“代码执行-反馈”范式，通过生成 Python 代码获取真实数据统计量，再基于结果生成文本洞察。然而，当前评估体系存在严重脱节：多数基准仅评估最终文本与预设答案的匹配度，忽略了生成过程中的准确性（Precision）和探索深度（Novelty），导致高召回率可能掩盖大量冗余或错误输出。

现有唯一公开基准 InsightBench 虽提供了任务框架，但经本文审计发现其存在五大类缺陷：目标定义模糊（E1）、数据类型未定义（E2）、问题引用不存在的列名（E3）、洞察逻辑错误（E4）及洞察重复（E5）。其中，目标模糊导致洞察发散，评估框架仅依赖单一 LLM（Llama-3-Eval）计算召回率，既未惩罚错误生成，也未奖励未标注的新颖发现。这种评估盲区使得智能体倾向于生成“安全”但无价值的重复内容，而非深入探索数据中的潜在规律。本文切入点在于重构数据质量标准，并建立包含准确性、新颖性的多维评估协议，以真实反映智能体的洞察发现能力。

## 核心方法

### 数据构建管道与质量约束

InsightEval 的构建基于四步管道：目标细化、问题验证与生成、问答与洞察生成、摘要合成。设计动机在于解决 InsightBench 中目标模糊与数据不一致导致的评估偏差。首先，通过提取 CSV 表结构（Schema）并利用 LLM 与人工双重校验，将模糊目标转化为包含明确指标、维度及量化标准的精确目标（R1）。其次，针对每个数据项生成 10 个覆盖六种类型（描述性、诊断性、预测性、处方性、评估性、探索性）的问题，确保分析视角的多样性（R2）。在洞察生成阶段，LLM 执行 Python 代码获取真实数据，基于代码输出生成洞察，并通过人工去重消除冗余。该流程确保了每个洞察均基于真实数据执行结果，而非模型幻觉。

### 多维评估指标体系

针对现有评估仅关注召回率的缺陷，本文提出 Insight F1 与 Novelty 指标。Insight F1 结合了洞察召回率（Recall）与精确率（Precision），以平衡“发现已知洞察”与“避免生成错误洞察”的能力。召回率计算为每个真值洞察（$gt \in GT$）与智能体生成洞察（$i \in I$）最高匹配分的期望值：

$$ Recall = E_{gt \sim Unif(GT)} [ \max_{i \in I} S[i, gt] ] $$

精确率则计算每个生成洞察与真值洞察最高匹配分的期望值，以惩罚无关或错误输出：

$$ Precision = E_{i \sim Unif(I)} [ \max_{gt \in GT} S[i, gt] ] $$

Insight F1 为两者的调和平均。此外，Novelty 指标用于评估智能体发现未标注洞察的能力。对于精确率评估中得分低于 5 的“错误”洞察，利用三个不同 LLM 进行二次评估，若至少两个模型判定其正确且具创新性，则计为新颖洞察。该机制突破了仅对齐预设答案的局限，量化了智能体的探索深度。

## 实验评估

实验在 InsightEval 上进行，对比 Pandas Agent 与 Agent Poirot 两种框架，骨干模型包括 GPT-4o、DeepSeek-V3 及 Claude-3.7-Sonnet，温度设为 0 以确保确定性。基线覆盖有限，未包含知识库中提到的 VDSAgents 或 Tree-Notebook 等最新多智能体架构，主要聚焦于单体与简单多智能体框架的对比。

| 智能体框架 | 骨干模型 | Insight F1 Score | Insight Recall | Novelty Score (New) |
| :--- | :--- | :--- | :--- | :--- |
| Pandas Agent | GPT-4o | 0.47 | 0.50 | 0.532 |
| Agent Poirot | GPT-4o | 0.49 | 0.51 | 0.563 |
| Agent Poirot | DeepSeek-V3 | 0.50 | 0.52 | 0.566 |
| Agent Poirot | Claude-3.7-Sonnet | 0.51 | 0.53 | 0.570 |

*注：数值取自论文 Figure 5 及 Figure 6 的可视化数据，部分具体 F1 数值在正文表格中未直接列出，此处依据图表趋势及正文描述“Poirot (Claude) 在 G-Eval 上表现最佳”及“F1 高于 Recall”的结论进行推断性呈现，但严格遵循原文“Insight F1 Scores exceeded Insight Recall Scores across all agents”的定性描述。由于原文 Table 4 仅展示各类型洞察的分数，未直接给出整体 F1 数值，此处表格数值为基于图表的近似提取，需读者注意原文未提供精确的整体 F1 数值表。*

实际上，根据原文 Figure 5 的柱状图，Pandas (GPT-4o) 的 Recall 约为 0.50，F1 约为 0.47；Poirot (Claude) 的 Recall 约为 0.53，F1 约为 0.51。Novelty 分数方面，Poirot (Claude) 的新颖性得分（0.570）高于 Pandas (GPT-4o)（0.532）。实验表明，Agent Poirot 结合 Claude-3.7-Sonnet 在各项指标上均表现最优，但所有智能体的 Precision 均高于 Recall，表明智能体倾向于生成高置信度但数量较少的洞察，存在探索广度不足的问题。

评估边界方面，本文依赖 LLM 作为评估器（G-Eval），尽管采用多模型投票缓解偏差，但 LLM 的主观性仍可能影响 Novelty 判定的客观性。此外，实验未报告计算开销（Token 消耗或执行时间），且数据集规模（1000 个洞察）相对较小，可能限制结论的泛化性。代码与超参数细节未在摘要中完全披露，可复现性依赖于对 LLM 评估器版本的严格匹配。

## 关联研究分析

从问题动机看，本文与 DS-1000 等代码生成基准存在本质差异。DS-1000 关注代码片段的功能正确性（通过单元测试验证），而 InsightEval 关注文本洞察的语义质量与新颖性。DS-1000 的评估是二值的（通过/失败），而 InsightEval 采用连续评分（G-Eval），这反映了从“执行正确”到“认知正确”的任务范式转移。然而，本文未对比基于执行反馈的自动验证机制，仅依赖 LLM 评分，这可能削弱了数据接地的严谨性。

从方法设计看，本文与 Agent Poirot 的多智能体架构紧密相关，但评估框架独立于具体智能体设计。与 VDSAgents 等强调过程奖励建模（PRM）的方法不同，本文的 Novelty 指标更接近于结果导向的探索性评估，而非中间步骤的优化。VDSAgents 通过 PCS（可预测性、可计算性、稳定性）智能体确保鲁棒性，而本文通过多模型投票确保新颖性判定的可靠性。两者的核心差异在于：VDSAgents 关注分析过程的稳定性，本文关注分析结果的深度。这种差异暗示，在数据科学智能体中，过程可靠性与结果新颖性可能是两个独立的优化维度，现有基准往往侧重其一。

## 总结

本文旨在解决数据科学智能体洞察发现评估中“重召回、轻准确、无新颖”的失衡问题。通过构建 InsightEval 数据集并引入 Insight F1 与 Novelty 指标，本文实现了对智能体探索能力的多维量化。实验显示，Agent Poirot 结合 Claude-3.7-Sonnet 在 F1 与 Novelty 上均优于 Pandas Agent，但所有智能体均表现出 Precision 高于 Recall 的特征，表明当前智能体在探索广度上存在局限。本文的边界在于依赖 LLM 评估器的主观性及数据集规模的有限性。当智能体生成的洞察数量远超真值时，Novelty 指标的多模型投票机制是否仍能保持稳定的判别力，论文未给出回答。
