# ACL-Findings2026最新论文 ｜Text-to-TrajVis: Enabling Trajectory Data Visualizations from Natural Language Questions ｜自然语言轨迹可视化查询

研究机构：吉林大学、香港科技大学

作者：Tian Bai、Huiyan Ying、Kailong Suo 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_e0fa0feabc2d)

> 轨迹数据可视化长期依赖专业数据库查询语言与编程技能，非专家用户难以直观表达分析需求。现有自然语言到可视化（NL2VIS）方法虽能处理通用图表，但缺乏针对轨迹时空语义的结构化解析能力，导致地理实体与时间表达解析错误频发。本文提出 Text-to-TrajVis 任务，定义轨迹可视化语言（TVL）作为中间表示，并构建首个基准数据集 TrajVL。通过引入检索增强与标准化后处理框架 TRCAT，显著提升了大语言模型在复杂时空查询下的代码生成准确率，但该方法依赖外部检索库，其泛化边界尚待验证。

## 研究背景

轨迹数据查询的核心困境在于自然语言语义与结构化数据库查询之间的映射鸿沟。用户以自然语言描述时空范围时，地理名称往往存在别名、层级嵌套或非标准表述，时间表达则包含相对时间、模糊区间等变体。这种语义模糊性直接导致大语言模型（LLM）生成的 SQL 查询或可视化代码无法执行，或返回错误数据。解决这一问题需要一种能够显式承载地理、时间、变换操作的结构化中间表示，将自然语言的模糊性转化为可计算的精确参数。

NL2VIS 领域已发展出多种基于 LLM 的生成框架，如 Chat2vis 和 ChartGPT，它们通过提示工程或微调将自然语言映射到 Vega-Lite 等通用可视化规范。然而，这些方法主要面向静态表格数据，缺乏对轨迹数据特有的时空连续性与地理拓扑结构的建模能力。当查询涉及“某街道在特定时间段内的轨迹分布”时，通用模型难以准确解析地理边界与时间锚点，导致生成的可视化代码在地理定位或时间筛选上出现系统性偏差。

本文的切入点在于将轨迹可视化查询从通用 NL2VIS 中剥离，定义专用的轨迹可视化语言（TVL）作为中间表示。TVL 显式分离了可视化类型、地理区域、时间区间、数据变换与排序操作，为 LLM 提供了结构化的生成目标。通过构建包含 9,608 个（问题，TVL）对的基准数据集 TrajVL，并设计针对地理与时间标准化的后处理框架，本文旨在验证结构化中间表示与领域特定后处理能否弥补 LLM 在时空语义解析上的不足。

## 核心方法

### TVL 结构化表示与生成范式

轨迹可视化查询的通用流程是将自然语言直接映射到可视化代码，但轨迹数据特有的时空约束使得直接映射极易出错。本文引入 TVL 作为中间表示，其结构定义为：

$$
\text{TVL} = \langle \text{VISUALIZE}, \text{AREA}, [\text{ST}, \text{ET}], \text{TRANSFORM}, \text{ORDER BY} \rangle
$$

其中 VISUALIZE 指定输出类型（地图、柱状图等），AREA 为地理实体，[ST, ET] 为时间闭区间，TRANSFORM 包含聚合与统计操作。这一设计将模糊的自然语言解析分解为离散的结构化字段填充任务，降低了 LLM 一次性生成完整代码的认知负荷。

### TVL-RAG Chain 模块

TVL-RAG Chain 模块解决 LLM 在缺乏领域上下文时生成 TVL 结构不一致的问题。该模块采用检索增强生成（RAG）机制，但不同于直接拼接检索结果，它从检索到的相似查询中提取结构化知识，包括可视化类型、地理区域、抽象 SQL 草图及参数填充后的完整 TVL。这些组件被组织为动态分解提示序列，引导 LLM 按步骤生成 TVL。其核心公式为：

$$
\mathcal{K}_{\text{struct}} = \{ \langle \nu_i, g_i, \text{SQL}_{\text{sketch}}(t), \text{TVL}_{\text{full}} \rangle \mid i \in \text{Top-K} \}
$$

其中 $\mathcal{K}_{\text{struct}}$ 为从 Top-K 检索结果中提取的结构化知识集合。这种分阶段生成策略使 LLM 能够先确定可视化类型与地理区域，再构建 SQL 草图，最后填充参数，从而确保生成 TVL 的结构完整性与语义一致性。

### Area-Time Standardization 模块

Area-Time Standardization 模块针对 LLM 生成的地理与时间参数可能存在的非标准表述进行后处理校正。该模块采用混合匹配策略，结合精确字符串匹配与基于地理词典的模糊语义匹配，将 LLM 输出的地理名称标准化为数据库中的规范实体。对于时间表达，模块利用 LLM 解析模糊时间描述并转换为精确时间戳。其标准化过程可表示为：

$$
g_{\text{std}} = \arg\max_{g \in \mathcal{G}} \text{Sim}(g_{\text{raw}}, g), \quad t_{\text{std}} = \text{Parse}(t_{\text{raw}})
$$

其中 $\mathcal{G}$ 为地理词典，$\text{Sim}$ 为相似度函数，$\text{Parse}$ 为时间解析函数。这一后处理步骤显著提升了 TVL 的可执行性，特别是在处理“某省某市某街道”等层级嵌套地理名称及“去年夏天”等模糊时间表达时，有效避免了因参数错误导致的查询失败。

## 实验评估

实验在自建 TrajVL 数据集上进行，该数据集包含 1,746 个训练 TVL、1,500 个验证 TVL 和 1,558 个测试 TVL。基线方法包括 GPT-4o-mini、LLaMA3-8B、Qwen2.5-7B 和 Gemma-7B，均采用最优 few-shot 提示策略。对比方法覆盖了主流开源与闭源 LLM，但缺乏针对轨迹数据专用的生成模型（如 InsTraj）作为基线，这可能限制了结果在轨迹生成领域的直接可比性。

| 模型 | TrajVLnormal TVL Acc (%) | TrajVLcomplex TVL Acc (%) |
|---|---|---|
| GPT-4o-mini (Baseline) | 74.52 | 18.55 |
| GPT-4o-mini (TRCAT) | 81.39 | 53.59 |
| LLaMA3 (Baseline) | 68.87 | 15.21 |
| LLaMA3 (TRCAT) | 67.33 | 48.27 |
| Qwen2.5 (Baseline) | 69.19 | 18.55 |
| Qwen2.5 (TRCAT) | 70.67 | 53.59 |
| Gemma (Baseline) | 39.41 | 7.25 |
| Gemma (TRCAT) | 64.63 | 54.75 |

TRCAT 框架在所有模型上均带来显著提升，尤其在 TrajVLcomplex 子集上，GPT-4o-mini 的 TVL 准确率从 18.55% 提升至 53.59%，提升了 35.04 个百分点。这一结果表明，结构化 RAG 与标准化后处理能有效缓解复杂时空表达带来的解析困难。

消融实验显示，移除 TVL-RAG Chain 模块导致性能大幅下降，例如 Gemma 在 TrajVLcomplex 上的 TVL 准确率从 54.75% 降至 25.83%，说明结构化知识引导对生成一致性至关重要。移除 Area-Time Standardization 模块后，GPT-4o-mini 的准确率从 53.59% 降至 40.96%，表明后处理校正对地理与时间参数的准确性有显著贡献。值得注意的是，LLaMA3 在 TRCAT 加持下超越了 Qwen2.5，暗示该框架对特定模型架构的解析能力有差异化增益。

评估指标主要关注 TVL 准确率、可视化类型准确率、坐标轴准确率及数据准确率，但未报告生成代码的执行成功率或可视化结果的视觉质量评估。数据集地理覆盖局限于中国 9 个省份，缺乏跨大陆或跨语言地理实体的测试，限制了泛化结论的普适性。论文未提供代码开源链接，且未报告训练或推理的计算开销，可复现性存在一定障碍。

## 关联研究分析

从问题动机看，本文与 InsTraj 均利用语义引导轨迹数据处理，但 InsTraj 聚焦于从自然语言意图生成轨迹坐标序列，而本文聚焦于从自然语言查询生成可视化代码。这一差异源于任务目标的不同：InsTraj 需解决物理一致性约束下的轨迹合成，而本文需解决结构化查询语言的正确生成。本文的 TVL 中间表示更接近于数据库查询优化中的逻辑计划，而非轨迹生成中的潜在空间表示，因此其评估指标侧重于结构准确性而非分布拟合度。

从方法设计看，本文与 AgentMob 均涉及 LLM 工具调用，但 AgentMob 通过智能体动态决定是否调用移动性分析工具以获取额外证据，而本文的 TVL-RAG Chain 是静态的检索增强流程，不涉及动态决策。这种差异反映了任务复杂度的不同：AgentMob 需处理预测任务中的不确定性，而本文的查询解析任务具有更明确的确定性目标。本文的 Area-Time Standardization 模块类似于 AgentMob 中的证据接地过程，但前者是后处理校正，后者是推理过程中的动态信息获取。

## 总结

本文旨在解决自然语言轨迹可视化查询中时空语义解析不准确的问题，通过定义 TVL 中间表示与构建 TrajVL 基准，将模糊的自然语言查询转化为结构化的可视化代码生成任务。TRCAT 框架通过 TVL-RAG Chain 与 Area-Time Standardization 模块，在 GPT-4o-mini 上将 TrajVLcomplex 的 TVL 准确率从 18.55% 提升至 53.59%，验证了结构化检索与后处理校正的有效性。然而，该方法依赖预构建的地理词典与检索库，当面对词典未覆盖的新地理实体或检索库中缺乏相似示例时，其性能边界尚不明确。当测试集包含完全未见过的地理区域名称时，Area-Time Standardization 模块的模糊匹配策略是否仍能保持高准确率，论文未给出回答。
