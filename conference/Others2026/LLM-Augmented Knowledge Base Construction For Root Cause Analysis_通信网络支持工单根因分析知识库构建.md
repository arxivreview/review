> 通信网络故障排查长期依赖人工阅读海量非结构化支持工单，传统机器学习方法难以捕捉文本中的语义细微差别与上下文知识。现有 LLM 直接生成诊断报告的方法存在幻觉风险且无法沉淀为可复用的结构化资产，本文切入点在于将 LLM 从“实时诊断器”转变为“离线知识提取器”，通过微调、检索增强生成（RAG）及混合策略从历史工单中自动构建关联规则知识库。该方法在内部数据集上验证了混合策略在语义相似度指标上的优势，但其泛化能力受限于单一文本模态输入及缺乏外部基准验证。

## 研究背景

当网络运维人员面对客户提交的故障报告时，核心挑战在于从非结构化的自由文本（如日志片段、用户投诉、专家分析）中提取出结构化的因果逻辑。这一过程涉及两个关键概念：一是**关联规则挖掘**，即从数据集中发现形如“若出现症状 A，则根因为 B，解决方案为 C”的确定性模式；二是**大语言模型（LLM）的领域适配**，即如何让通用语言模型理解通信网络特有的术语体系与故障传播逻辑。传统方法依赖人工编写规则或基于关键词匹配，无法处理同义词替换与复杂语境，而直接调用通用 LLM 则因缺乏领域知识而产生事实性错误。

云系统与通信网络的根因分析（RCA）正从基于统计相关性的图遍历向基于语义理解的智能体推理演进。主流路线如 OpsAgent 和 PRAXIS 侧重于实时诊断，通过多智能体协作或程序依赖图（PDG）在故障发生瞬间定位源头，其输出是一次性的诊断报告。然而，这种“单次诊断”模式忽略了历史故障数据的复用价值，导致每次故障都需重新进行高成本的推理。本文的研究问题因此聚焦于“知识沉淀”：如何自动化地从海量历史支持工单中提炼出可复用的 RCA 知识库，以加速未来故障的响应。这一方向与实时诊断路线形成互补，旨在解决可解释性与自动化闭环脱节的问题，通过结构化规则库实现从“事后分析”到“事前预防”的转变。

## 核心方法

### 方法参照系

本文任务属于 LLM 驱动的知识提取范畴，与标准的实时 RCA 智能体流程存在关键差异。标准流程（如 GALA 或 StableRCA）以实时观测数据（指标、追踪）为输入，输出概率排名或诊断文本，强调实时性与因果严谨性。本文则以历史工单文本为输入，输出结构化的关联规则知识库，强调离线构建的完整性与可复用性，不涉及实时拓扑更新或动态因果图学习。

### Prompt-Aware Text Chunking

长文本处理是 LLM 应用中的常见瓶颈，通常做法是将文本按固定长度截断，但这会破坏语义完整性。本文设计了 Prompt-Aware Text Chunking 算法，将预定义提示词（Prompt）的长度纳入分块计算，确保每个分块在包含提示词后仍不超过模型的最大上下文窗口。设提示词长度为 $|p|$，最大 token 限制为 $max\_token$，则每个数据分块的最大长度 $r$ 计算为：

$$ r = max\_token - |p| $$

该公式的物理含义是，通过预留提示词空间，确保 LLM 在处理每个数据片段时，既能接收完整的指令约束，又能处理尽可能多的上下文信息，从而避免关键故障描述被截断。这一设计解决了传统固定长度分块在长工单场景下导致的语义丢失问题，提升了信息提取的完整性。

### 混合知识提取策略

单一微调或 RAG 策略各有局限：微调模型缺乏外部知识访问能力，易产生幻觉；RAG 模型依赖检索质量，且无法内化领域特定模式。本文提出混合策略，结合微调后的领域感知能力与 RAG 的实时知识检索。设输入工单文本为 $x$，微调模型 $M_{ft}$ 生成初步规则 $r_{ft}$，RAG 模块检索相关历史案例 $S_{rag}$ 并生成补充规则 $r_{rag}$，最终知识库规则 $K$ 通过融合函数 $F$ 生成：

$$ K = F(M_{ft}(x), RAG(x, S_{rag})) $$

该公式表明，混合策略并非简单拼接，而是通过融合函数整合两种来源的规则，利用微调模型捕捉深层语义模式，同时利用 RAG 引入外部事实知识以抑制幻觉。这一设计解决了纯微调模型在长尾故障场景下泛化能力弱的问题，以及纯 RAG 模型在复杂语境理解上的不足，提升了知识库的准确性与鲁棒性。

## 实验评估

实验基于 1,049 张真实通信网络支持工单，涵盖 13 类故障，数据划分为 80% 训练集与 20% 测试集。基线方法包括纯微调 LLM 和纯 RAG 策略，缺失传统机器学习基线（如 SVM）及通用 LLM 直接推理基线（如 GPT-4 Zero-shot），导致无法全面评估 LLM 策略相对于传统方法的绝对优势。

| 方法 | 词汇相似度 (BLEU/ROUGE/METEOR) | 语义相似度 (BERTScore) | 流畅性 |
| :--- | :--- | :--- | :--- |
| Fine-Tuning | 较高 | 较低 | 较差 |
| RAG | 中等 | 中等 | 中等 |
| Hybrid | 最高 | 最高 | 最好 |

混合策略在词汇与语义相似度指标上均优于单一方法，表明其有效整合了领域知识与外部信息。然而，论文未提供具体数值，仅定性描述“Hybrid 方法在几乎所有指标上表现最佳”，这使得量化比较难以进行。消融实验缺失，无法确定微调与 RAG 各自对最终性能的贡献比例，以及 Prompt-Aware Chunking 算法的具体增益幅度。

评估边界存在显著局限：首先，指标仅关注文本相似度（BLEU, ROUGE, BERTScore），未评估规则的正确性、覆盖率或在实际故障诊断中的准确率，导致无法验证知识库的实际效用。其次，数据集为内部私有数据，缺乏外部基准（如 RCAEval 或 AIOps 2022）验证，泛化能力存疑。最后，论文未报告计算开销、推理延迟或模型大小，无法评估其在生产环境中的实时性可行性。代码与超参数未公开，可复现性受限。

## 关联研究分析

从问题动机看，本文与 OpsAgent 等实时诊断智能体形成鲜明对比。OpsAgent 侧重于在故障发生瞬间通过多智能体协作模拟人类 SRE 的假设-验证过程，输出实时诊断报告，其核心假设是“实时推理可模拟人类专家”。本文则假设“历史知识可沉淀为结构化规则”，将 LLM 用于离线知识构建而非实时推理。这一差异源于任务特性：通信网络故障往往具有重复性，历史工单蕴含大量可复用模式，而微服务架构故障更具动态性，需实时适应拓扑变化。本文未探索如何将离线构建的知识库与实时诊断智能体结合，以应对动态网络环境中的新故障模式。

从方法设计看，本文与 StableRCA 在鲁棒性处理上存在根本分歧。StableRCA 通过局部马尔可夫毯估计实现图无关的鲁棒因果推断，强调在拓扑错误下的稳定性。本文则依赖 LLM 的语义理解能力，通过 RAG 引入外部知识以抑制幻觉，但未提供形式化的鲁棒性保证。在数据充足且模式稳定的场景下，本文的混合策略可能优于 StableRCA 的统计方法；但在数据稀疏或模式漂移的场景下，StableRCA 的局部因果推断可能更可靠。本文未评估在数据分布偏移或长尾故障场景下的性能退化情况，其混合策略的鲁棒性边界尚不明确。

## 总结

本文旨在解决通信网络 RCA 中历史知识复用不足的问题，通过 LLM 自动化构建关联规则知识库，弥补了实时诊断方法在知识沉淀上的空白。其核心创新在于 Prompt-Aware Chunking 与混合提取策略，有效提升了文本信息提取的完整性与准确性。实验表明混合策略在语义相似度上优于单一方法，但缺乏具体数值与外部基准验证。本文的边界在于仅处理文本模态，未整合指标与追踪数据，且未评估知识库在动态网络环境中的时效性。当网络拓扑频繁变化或出现新型故障模式时，离线构建的静态知识库如何保持其诊断有效性，论文未给出回答。
