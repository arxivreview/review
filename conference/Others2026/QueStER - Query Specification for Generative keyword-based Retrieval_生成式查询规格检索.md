# EACL2026最新论文 ｜QueStER: Query Specification for Generative keyword-based Retrieval ｜生成式查询规格检索

研究机构：法国巴黎萨克雷大学、法国国家科学研究中心

作者：Arthur Satouf、Yuxuan Zong、Habiboulaye Amadou-Boubacar 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2511.05301)

> 信息检索模型需在语义理解与计算效率间取得平衡，传统词汇匹配模型受限于词汇不匹配问题，而神经检索器因索引维护成本高难以动态更新。现有基于大语言模型的查询重写方法虽提升了效果，但依赖庞大参数与复杂提示，导致推理延迟高且结果不稳定。QUESTER 将生成式检索的目标从文档标识符转向关键词查询规格，利用强化学习微调轻量级大语言模型生成检索指令，由标准倒排索引执行。该方法在保持毫秒级检索延迟的同时，显著超越了基线词汇模型，但在域内绝对精度上仍低于专用神经检索器，其泛化边界尚待复杂查询场景验证。

## 研究背景

当用户查询中的关键词未出现在相关文档中时，基于词袋模型的检索系统会因词汇不匹配而失效。解决该问题的传统手段是查询重写，即通过统计反馈或大语言模型生成同义词以扩展查询。然而，依赖大语言模型提示工程的重写方法（如 HyDE、MuGI）往往需要调用数十亿参数模型并多次采样，导致单次查询延迟超过 100 毫秒，且输出具有随机性，难以在大规模搜索系统中稳定部署。

信息检索领域长期存在效率与效果的权衡困境。神经双编码器（如 SPLADEv2、ColBERTv2）虽在精度上占据优势，但其向量或稀疏索引体积庞大（如 MS MARCO 密集索引需 13 GiB），且模型更新后必须重建索引，这在动态语料库中代价高昂。生成式检索（Generative Retrieval, GR）试图将索引内化于模型参数，直接生成文档标识符，但早期方法依赖任意聚类 ID，泛化能力差；基于元数据（如 URL、标题）的 GR 虽改善了泛化，却受限于元数据的信息密度。本文切入点在于重新定义生成目标：不生成文档标识，而是生成可被成熟倒排索引执行的“搜索规格”（Search Specification），从而兼得神经模型的语义理解能力与词汇索引的高效性。

## 核心方法

### 方法参照系

本文问题属于查询重写与生成式检索的交叉领域。标准查询重写流程为：输入查询 → 模型生成扩展文本 → 检索器执行。本文的关键差异在于，生成目标被约束为结构化关键词集合，而非自然语言伪文档，且训练信号直接来自检索质量指标而非人工标注。

### 基于 GRPO 的策略优化

传统查询重写依赖监督微调或启发式规则，缺乏对检索效果的直接优化信号。本文采用 Group Relative Policy Optimization (GRPO) 训练策略模型 $p_\theta$。对于每个查询 $q$，模型采样 $m$ 个候选查询 $\{q_i\}_{i=1}^m$，计算其对应的奖励 $\{r_i\}$，并基于组内相对优势 $a_i = r_i - \bar{r}$ 更新策略。该设计动机在于消除对绝对奖励标定的依赖，通过组内对比提升训练稳定性，同时避免了显式 KL 散度惩罚对探索空间的限制。

$$
\nabla_\theta J(\theta) = \mathbb{E}_{q \sim \mathcal{D}, \{q_i\} \sim p_\theta} \left[ \frac{1}{m} \sum_{i=1}^m \left( \frac{a_i}{\sigma_a} \right) \log p_\theta(q_i | q) \right]
$$

其中 $\sigma_a$ 为组内优势的标准差，标准化操作确保了不同查询难度下的梯度尺度一致。

### SoftRank 奖励与交叉编码器蒸馏

直接以 nDCG 作为奖励会导致梯度稀疏，因为 nDCG 对排名微小变化不敏感。本文引入 SoftRank 计算期望 nDCG，假设检索分数服从正态分布 $S(q, d) \sim \mathcal{N}(se(q, d), \nu I_d)$。SoftNDCG 对分数差异的敏感度由超参数 $\nu$ 控制：$\nu \to 0$ 时退化为 HardNDCG，$\nu \to \infty$ 时分数失去影响。此外，为缓解 MS MARCO 数据集中大量假阴性（False Negatives）导致的奖励为零问题，本文采用交叉编码器（Cross-Encoder, CE）对 Top-100 检索结果进行相关性蒸馏，生成连续值相关性标签，确保奖励信号在查询微小改进时仍能产生非零梯度。

$$
\text{SoftNDCG} = \mathbb{E}_{K} \left[ \frac{\sum_{i=1}^N \frac{2^{rel(d_i)} - 1}{\log_2(1 + K_i)}}{\sum_{i=1}^N \frac{2^{rel(d_i)} - 1}{\log_2(1 + i)}} \right]
$$

该公式通过概率化排名 $K_i$ 平滑了离散排名的不连续性，使奖励函数对查询质量的边际变化具备连续可导性。

## 实验评估

实验在 MS MARCO v1（8.8M 段落）、TREC DL'19/'20 及 BEIR 数据集上进行。基线覆盖神经双编码器（ANCE, SPLADEv2, ColBERTv2）、传统词汇模型（BM25, RM3）及 LLM 重写方法（HyDE, MuGI, LameR）。QUESTER 使用 Qwen3-4B 作为骨干，经 GRPO 训练后，在 TREC DL'19 上取得 63.1 nDCG@10，较 BM25（50.6）提升 12.5 点，但低于 SPLADEv2（72.9）和 MuGI/GPT4（70.4）。在 BEIR 域外测试中，QUESTER 平均 nDCG@10 超越所有神经基线，显示出更强的泛化能力。

| 模型 | TREC DL'19 nDCG@10 | TREC DL'20 nDCG@10 | MS MARCO Dev R@1K |
| :--- | :--- | :--- | :--- |
| BM25 | 50.6 | 48.0 | 85.3 |
| SPLADEv2 | 72.9 | 68.7 | 97.9 |
| MuGI (GPT4) | 70.4 | 64.4 | — |
| QUESTER | 63.1 | 60.8 | 92.1 |

消融实验显示，模型规模从 0.6B 增至 4B 时，nDCG@10 持续上升，但 1.7B 已接近 4B 的性能，而延迟更低。引入 SFT 预热虽提升基线，但后续 GRPO 训练未能超越直接 GRPO 训练的 QUESTER，假设 SFT 限制了重写空间的探索。效率方面，QUESTER 检索延迟约为 28 ms/query，比 MuGI 和 LameR（>100 ms）快 4-7 倍，接近 BM25 的 16.3 ms。

评估协议存在局限：域内测试依赖 MS MARCO 的点击日志，虽经 CE 蒸馏缓解假阴性，但仍可能遗漏长尾相关文档。代码与模型权重已公开，训练在单张 NVIDIA RTX A6000 上耗时约 2 天，复现成本低。未报告端到端生成延迟，仅比较检索阶段耗时，这在评估 LLM 重写方法时可能低估了实际系统延迟。

## 关联研究分析

从方法设计看，QUESTER 与 MuGI、LameR 等提示工程方法的核心差异在于参数化策略优化替代了零样本提示。MuGI 依赖 GPT-4 的复杂提示与多次采样，其性能上限受限于大模型的推理能力与 API 成本；QUESTER 通过 GRPO 将检索反馈内化至 4B 小模型参数中，实现了确定性解码（温度 $\tau=0$），消除了提示方法的随机性。这一差异根源在于任务特性：查询重写是高频、低延迟敏感任务，参数化小模型在边际成本上优于大模型 API 调用，但牺牲了对复杂语义结构的即时理解能力。

从问题动机看，QUESTER 与 CoSearch 等智能体搜索框架存在路线分歧。CoSearch 强调检索器与生成器的联合优化以解决多步推理中的证据整合，而 QUESTER 坚持单步检索的有效性，认为在多数场景下，高质量的关键词生成足以弥补词汇不匹配，无需引入多步规划开销。这种分歧暗示了领域内对“检索复杂度”认知的差异：CoSearch 假设复杂查询需非线性调查，QUESTER 则假设线性关键词扩展已足够。当查询涉及多跳逻辑或隐含约束时，单步关键词生成是否仍能保持优势，论文未提供针对性实验证据。

## 总结

QUESTER 旨在解决神经检索器索引维护成本高与 LLM 重写方法效率低之间的矛盾，其切入点是将生成式检索的目标从文档标识符重构为可执行的关键词规格，从而复用成熟的倒排索引基础设施。通过 GRPO 与 SoftRank 奖励的结合，该方法在 4B 参数规模下实现了 TREC DL'19 63.1 nDCG@10 的性能，较 BM25 提升 12.5 点，且检索延迟控制在 28 ms。然而，实验暴露出其在域内精度上仍显著低于 SPLADEv2（72.9 nDCG@10），且未验证在复杂多跳查询场景下的有效性。当查询意图包含隐含逻辑约束或需跨文档综合时，单步关键词生成能否替代多步智能体规划，仍是该方法泛化边界的关键疑问。
