# 自适应Web渗透测试框架

作者：Akshat Singh Jaswal、Ashish Baghel

论文原文见 [arXiv](https://arxiv.org/abs/2603.00960)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.00960)

> 现代Web应用开发速度远超传统安全工具的静态检测能力，导致注入类漏洞在快速部署中持续存在。现有基于模式的扫描器缺乏推理能力，而通用LLM智能体虽具推理力但成本高、行为不稳定且缺乏领域特异性。AWE通过嵌入漏洞专用分析流水线与持久记忆机制，在LLM编排下实现目标化、可解释的漏洞发现。该框架在注入类漏洞上显著优于通用智能体，但其整体覆盖率仍受限于专用架构的泛化边界。

## 研究背景

Web安全评估的核心困境在于攻击面的动态扩展与防御工具的静态滞后。当无代码平台与AI辅助生成工具允许低安全专业度的开发者快速部署应用时，输入处理逻辑的复杂性急剧增加。传统动态应用安全测试（Dynamic Application Security Testing, DAST）工具依赖预定义的签名库与模式匹配，面对非标准过滤或自适应Web应用防火墙（WAF）时，无法合成新颖Payload或进行多步上下文推理，导致漏报率居高不下。

主流LLM渗透测试系统如MAPTA采用通用多智能体架构，通过沙箱内任意代码执行实现广泛探索。然而，这种“通用推理”范式存在两个瓶颈：一是缺乏领域特定的利用逻辑，难以解读细微的服务端反馈（如类型强制转换、模板引擎语义）；二是缺乏持久记忆，无法在多步利用中跟踪已尝试的Payload与过滤行为变化，导致重复无效尝试与资源浪费。AWE的切入点在于将LLM从“通用决策者”降级为“辅助生成器”，将核心利用逻辑硬编码为专用智能体的状态机，从而在资源受限下实现高确定性的漏洞挖掘。

## 核心方法

### 方法参照系

AWE置于“LLM驱动的多智能体渗透测试”类别下，与MAPTA等通用架构的关键差异在于：MAPTA依赖LLM在沙箱中自由探索并生成代码，而AWE将漏洞利用分解为预定义的专用智能体流水线，LLM仅负责Payload生成与策略选择，不直接执行任意代码。

### 专用智能体与状态化利用

通用LLM智能体在处理复杂注入时，往往因缺乏对服务端过滤逻辑的细粒度理解而生成通用Payload，导致被WAF拦截后过早放弃。AWE的专用智能体层通过结构化状态机解决此问题。以XSS智能体为例，其执行五阶段流水线：首先通过并行Canary注入映射输入反射行为，区分DOM上下文（如引号属性、JS字符串）；随后推断服务端过滤策略（如字符转换、标签黑名单）。这一过程可形式化为上下文推断函数：

$$ C_{ctx} = f_{infer}(R_{resp}, P_{canary}) $$

其中 $R_{resp}$ 为HTTP响应，$P_{canary}$ 为Canary Payload，$C_{ctx}$ 为推断出的上下文约束。LLM基于 $C_{ctx}$ 生成针对性Payload，而非盲目猜测。这种设计将“探索”转化为“假设-验证”循环，显著减少了无效尝试。

### 持久记忆与浏览器验证

长程利用中的状态丢失是通用智能体的另一失效点。AWE引入持久记忆系统，区分短期扫描状态（当前会话的已试Payload、推断过滤）与长期跨目标学习（历史绕过模式、特征签名）。记忆更新机制可表示为：

$$ M_{t+1} = M_t \cup \{ (p_i, o_i, \Delta t) \} $$

其中 $p_i$ 为Payload，$o_i$ 为观察结果，$\Delta t$ 为时间戳。该机制避免重复尝试，并允许智能体利用历史经验加速新目标的利用。此外，针对XSS等无法通过HTTP响应直接验证的漏洞，AWE集成Headless Chromium浏览器验证引擎，通过观察DOM变更或脚本执行信号，消除假阳性，确保报告漏洞的可利用性。

## 实验评估

AWE在XBOW基准（104个容器化Web挑战，26类漏洞）上与MAPTA对比，基线选择合理但缺乏传统扫描器（如sqlmap）的参照。实验设置采用10分钟时间预算，AWE使用Claude Sonnet 4，MAPTA使用GPT-5。

| 系统 | 解决率 | 平均时间 (s) | Token用量 | API成本 |
| :--- | :--- | :--- | :--- | :--- |
| AWE | 51.9% (54/104) | 53.1 | 1.12M | $7.73 |
| MAPTA | 76.9% (80/104) | 190.8 | 54.9M | $21.38 |

AWE在整体解决率上落后，但在效率上优势显著：Token用量减少98%，速度提升4.4倍，成本降低63%。在注入类漏洞细分中，AWE表现突出：XSS解决率87%（MAPTA 57%），盲SQL注入66.7%（MAPTA 33.3%）。这表明专用架构在特定漏洞类别上能超越通用推理，但牺牲了非注入类漏洞的覆盖率。

消融实验显示，模型选择对性能影响显著。在DVWA上，Claude Sonnet 4在盲SQL注入（70%）和CSP强制存储XSS（67%）上优于GPT-4o（60%/67%）和Gemini 2.0 Flash（55%/50%）。迭代效率方面，Claude收敛于10-40次尝试，GPT-4o多20%，Gemini多40%。这验证了“架构+模型”协同的重要性，但也暗示AWE的性能高度依赖特定LLM的推理稳定性。

评估边界方面，AWE仅对比MAPTA，未包含传统DAST工具，无法量化其相对于静态扫描器的增量价值。此外，XBOW基准的容器化环境可能简化了真实网络中的动态噪声，且AWE的长期记忆在跨目标迁移时的安全性（如记忆投毒风险）未作讨论。代码已开源，但超参数配置（如记忆容量上限）未详细披露，可复现性受限。

## 关联研究分析

从方法设计看，AWE与Branch-and-Browse的树结构回溯思想存在同构性，均通过结构化状态管理提升长程决策稳定性。但Branch-and-Browse面向任务执行，其回溯基于任务目标；AWE面向漏洞利用，其状态管理基于过滤逻辑推断。AWE的专用智能体硬编码了领域知识，这提升了注入类漏洞的确定性，但限制了面对未知漏洞类型（如业务逻辑缺陷）的泛化能力。相比之下，MAPTA的通用沙箱执行虽效率低，但能探索AWE未覆盖的漏洞类别，揭示了“专用性”与“通用性”的根本权衡。

从问题动机看，AWE回应了知识库中“高效且可泛化的训练数据稀缺”问题，通过持久记忆积累绕过模式，减少对新数据的依赖。然而，AWE未讨论长期记忆在对抗环境下的鲁棒性。若恶意网站故意诱导智能体存储错误绕过模式，可能导致后续攻击失效。这种“记忆投毒”风险在知识库中被指出，但AWE作为攻击系统，其记忆机制的安全性验证缺失，构成潜在盲区。

## 总结

AWE旨在解决Web安全评估中开发速度与静态防御能力的失衡，通过专用智能体架构与持久记忆机制，在资源受限下实现高确定性的注入类漏洞挖掘。实验证明，AWE在XSS（87%）和盲SQL注入（66.7%）上显著优于MAPTA，且Token用量减少98%，验证了架构专业化对效率的提升。然而，AWE的整体解决率（51.9%）低于MAPTA（76.9%），暴露了专用架构在泛化覆盖上的局限。当面对非注入类漏洞或动态变化的WAF策略时，AWE的硬编码流水线是否仍能保持有效性，论文未给出回答。
