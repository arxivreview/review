# 新西兰奥克兰团队新研究：基于关系预言的大语言模型测试

研究机构：新西兰奥克兰大学

作者：Valerio Terragni

论文原文见 [arXiv](https://arxiv.org/abs/2603.24774)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.24774)

> 大语言模型（LLM）嵌入软件系统后，其输出开放、非确定且缺乏标准答案，导致传统基于人工标注的测试预言（Test Oracle）在规模上不可行。现有自动化测试方法多依赖执行反馈或文档断言，难以覆盖 LLM 行为中的细微逻辑违背。本文切入点在于利用元测试（Metamorphic Testing, MT）中的关系预言，通过定义输入变换与输出预期关系，实现无需 Ground Truth 的大规模自动化验证。该方法通过 LLMORPH 框架在三个主流 LLM 上执行了 56 万次测试，暴露了平均 18% 的故障率，但 62% 的真阳性率揭示了语义歧义带来的假阳性瓶颈，其作为 CI 流水线回归信号的有效性仍受限于输出比较器的精度。

## 研究背景

测试 LLM 驱动的软件系统面临的核心困境是预言缺失。传统软件测试依赖 Ground Truth 标签，即人工标注的“正确输出”，但在 LLM 场景中，输入短语的微小变化可能导致输出剧烈波动，且同一输入可能存在多个有效响应。这种特性使得人工标注不仅成本高昂，且在语义层面缺乏一致性，人类标注者往往无法就“正确”达成共识。因此，测试预言必须从“绝对正确性”转向“相对一致性”，即验证系统在输入变化时输出是否符合预期逻辑，而非验证输出是否等于某个固定值。

主流自动化测试路线在 LLM 场景下均存在局限。基于执行反馈的强化学习（RL）方法（如 BoostAPR）依赖明确的崩溃信号或测试通过/失败状态，但 LLM 的幻觉往往表现为语义错误而非程序崩溃，缺乏明确的执行反馈信号。基于文档或注释生成断言的方法（如 LLM-Driven Test Oracle Generation）依赖开发者文档的完整性，而实际部署中 LLM 常处理未覆盖的新领域任务，文档缺失导致断言生成失效。本文的切入点在于引入元测试（Metamorphic Testing, MT），这是一种早在 1998 年提出的测试技术，其核心思想是不验证单个输出的正确性，而是验证输入变换后输出变化的规律性。通过定义元关系（Metamorphic Relations, MRs），MT 将测试预言从“点”扩展为“关系”，从而在缺乏 Ground Truth 的情况下实现可扩展的自动化测试。

## 核心方法

### 元测试参照系

元测试（MT）的标准流程包含三个步骤：生成源输入（Source Input）、应用输入变换生成后续输入（Follow-up Input）、执行系统并比较输出。与基于断言的传统测试不同，MT 不预设具体输出值，而是预设输入与输出之间的约束关系。本文将该流程迁移至 LLM 场景，关键差异在于输出比较从精确匹配转变为语义或结构相似度比较，以应对 LLM 输出的非确定性。

### 关系预言定义与自动化实现

本文的核心创新在于构建了一套针对 LLM 的元关系库及自动化执行框架 LLMORPH。设计动机在于解决人工定义 MR 效率低且难以覆盖 LLM 复杂行为的问题。作者系统回顾了 1,024 篇 NLP 论文，提取了 191 个 MR，并实现了其中 36 个。MR 的形式化定义为：若输入满足关系 $R_i$，则输出必须满足关系 $R_o$，即：

$$ R_i \implies R_o $$

例如，若输入被否定（$R_i$: Negation），则情感分析输出应翻转（$R_o$: Flip）。LLMORPH 框架自动执行这一过程：生成源输入 $x_1$，应用变换 $T$ 得到 $x_2$，调用 LLM 获取 $y_1, y_2$，并计算输出相似度 $S(y_1, y_2)$。若 $S$ 违背 $R_o$ 定义的阈值，则报告故障。这一机制将“一次定义”转化为“无限次测试”，解决了 Ground Truth 标注不可扩展的经济性问题。

### 语义歧义下的输出比较

针对 LLM 输出开放性的挑战，本文采用 BERT 基于的相似度分数作为输出比较器。设计动机在于精确匹配无法处理 LLM 的语义等价性（如“很好”与“不错”）。然而，这一设计引入了新的不确定性：相似度分数本身成为预言的一部分。若变换意外改变了语义（如拼写错误导致含义改变），或两个输出均有效但表述不同，MT 将产生假阳性。本文通过手动分析 937 个违规案例，量化了这一局限，发现真阳性率（TPR）约为 62%，表明语义歧义是 MT 在 LLM 上应用的主要噪声源。

## 实验评估

实验在 GPT-4、LLAMA 3 和 HERMES-2 三个 LLM 上进行，共执行 560,000 次元测试。基线审计显示，本文未对比传统的基于断言的测试方法或 RL 驱动的修复方法，因为任务目标不同（行为验证 vs. 代码修复）。主结果如下表所示：

| 指标 | 数值 |
| :--- | :--- |
| 平均故障率 (36 MRs) | 18% |
| 单个 MR 最大故障率 | 80% |
| 手动分析违规案例数 | 937 |
| 真阳性率 (TPR) | 62% |

核心数字对比表明，MT 能有效暴露 LLM 的故障行为，但 62% 的 TPR 意味着近四成的报告故障为假阳性。这一结果揭示了 MT 在 LLM 上的双重性：它提供了大规模检测能力，但受限于语义比较的模糊性，无法提供高置信度的故障定位。

消融分析未提供详细数据，但文中指出任务无关的 MR（如“改写输入，输出应保持不变”）在多个任务上有效，而语义细微的 MR（如“交换不对称实体，关系应翻转”）假阳性更高。这表明 MR 的通用性与精度之间存在权衡：越通用的 MR 越容易执行，但越容易因语义漂移产生误报。

评估边界方面，本文未报告计算成本（Token 消耗与时间），也未提供 LLMORPH 的开源代码链接（仅提及引用 [9]）。指标完备性上，TPR 是核心指标，但缺乏与人工测试或传统自动化测试在成本-效益比上的直接对比。可复现性受限于 LLM 的非确定性，不同运行可能产生不同的故障集合，需多次运行取平均。

## 关联研究分析

从问题动机看，本文与 SWE-Tester 和 LLM-Driven Test Oracle Generation 均解决测试预言缺失问题，但路径截然不同。SWE-Tester 生成复现 Bug 的测试用例，依赖 Issue 描述与代码库的映射，适用于已知缺陷的回归测试；而本文生成验证行为一致性的测试，依赖预定义的 MR，适用于未知缺陷的探索性测试。差异根源在于任务特性：SWE-Tester 针对确定性 Bug，而 LLM 幻觉是概率性且分布广泛的，无法通过单一复现测试覆盖。LLM-Driven Test Oracle Generation 依赖文档生成断言，而本文依赖逻辑变换，前者在文档缺失时失效，后者在语义歧义大时失效。

从方法设计看，本文与 Agentic Testing 均涉及自动化测试闭环，但反馈机制不同。Agentic Testing 利用执行反馈（覆盖率、失败率）驱动智能体调整策略，属于动态优化；本文利用静态 MR 定义预期关系，属于静态验证。Agentic Testing 能自适应发现新测试，但依赖执行环境的稳定性；本文能大规模生成测试，但依赖 MR 的覆盖度。差异根源在于 LLM 测试的瓶颈：Agentic Testing 假设测试生成是主要瓶颈，而本文假设测试预言是主要瓶颈。在 LLM 场景中，由于输出非确定性，执行反馈（如是否崩溃）往往不可用，因此静态关系验证比动态执行反馈更可靠。

## 总结

本文要解决的核心矛盾是 LLM 输出非确定性与测试预言可扩展性之间的冲突。现有方法依赖 Ground Truth 或文档，无法应对 LLM 的开放输出与语义歧义。本文通过引入元测试（MT），将测试预言从“绝对值”转化为“关系”，利用 LLMORPH 框架实现了 56 万次自动化测试，暴露了平均 18% 的故障率。然而，62% 的真阳性率揭示了语义比较器带来的假阳性瓶颈，限制了其作为高置信度回归信号的能力。本文的边界在于 MR 的覆盖度与语义歧义的权衡：通用 MR 易执行但易误报，精细 MR 精度高但难定义。当 MR 的语义变换导致输入含义意外改变时，MT 的假阳性率是否会显著上升，论文未给出量化回答。
