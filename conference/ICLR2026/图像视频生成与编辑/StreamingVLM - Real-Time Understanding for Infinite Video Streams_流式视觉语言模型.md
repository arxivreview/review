# ICLR2026最新论文 ｜StreamingVLM: Real-Time Understanding for Infinite Video Streams ｜流式视觉语言模型

研究机构：美国麻省理工学院

作者：Ruyi Xu、Guangxuan Xiao、Yukang Chen 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.09608)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.09608)

> 流式视频理解要求模型在无限输入下维持低延迟响应，但全注意力导致显存溢出，简单滑动窗口则破坏长程语义连贯性。现有方法在训练与推理的注意力模式上存在错位，导致长视频推理时性能崩塌。StreamingVLM 通过重叠分块全注意力训练对齐推理时的 KV 缓存复用策略，实现了无限流下的稳定实时理解。该框架在 2 小时以上的体育解说任务上显著优于基线，但其记忆机制缺乏显式语义分层，长程推理能力的上限尚存疑。

## 研究背景

实时交互应用如自动驾驶与 AI 眼镜要求模型处理近乎无限的视频流，核心约束是流式因果性：模型在时间 $t$ 仅能访问 $t$ 之前的观测。这一约束下，全注意力机制因 $O(T^2)$ 的计算复杂度与无界显存占用而失效，无法支持实时推理。为缓解此问题，滑动窗口注意力成为主流方案，但无重叠窗口频繁重置上下文导致语义断裂，有重叠窗口则因重复计算注意力而引入高延迟。

流式视频理解领域的核心矛盾在于无限输入与有限上下文窗口的物理冲突。2025 年，StreamingLLM 等文本模型引入注意力沉没（Attention Sink）机制，通过保留少量初始 Token 稳定长序列解码，但直接迁移至多模态场景时，视觉 Token 的高冗余性与文本 Token 的语义重要性差异未被充分处理。现有 KV 缓存驱逐策略往往缺乏与训练阶段的对齐，导致模型在短视频上训练良好，却在长视频流中因位置编码漂移或上下文丢失而性能骤降。StreamingVLM 的切入点在于解决训练-推理不一致性：通过设计一种在短重叠分块上应用全注意力的训练策略，使其有效注意力模式与推理时的 Sink+窗口复用结构相匹配，从而在无需训练超长视频的前提下实现无限流稳定推理。

## 核心方法

### 方法参照系

本文问题归属于流式视频理解的内存管理路线，标准流程通常采用滑动窗口截断或压缩历史 KV 缓存以控制显存。本文与通用流程的关键差异在于：不仅优化推理时的缓存结构，更通过训练策略显式对齐推理时的注意力分布，解决了传统方法中训练使用全注意力、推理使用局部窗口导致的分布偏移问题。

### 流式感知 KV 缓存与连续 RoPE

推理阶段，StreamingVLM 维护一个紧凑的 KV 缓存，由三部分构成：长度为 $T_{sink}$ 的注意力沉没 Token（包含系统提示与早期文本）、长度为 $T_{window}$ 的近期文本窗口、以及长度为 $V_{window}$ 的近期视觉窗口。当新帧到达时，较早的视觉 Token 优先被驱逐，而早期文本仅在超出预算时被移除。这种非对称保留策略避免了重复计算，同时保留了足够的上下文以维持生成连贯性。为防止 Token 驱逐后的位置漂移，引入连续 RoPE（Contiguous RoPE）：

$$
\text{RoPE}_{new}(i) = \text{RoPE}_{old}(i) - \Delta_{evicted}
$$

其中 $\Delta_{evicted}$ 为被驱逐 Token 的索引偏移量。该公式确保剩余 Token 的位置索引在数值上保持连续，且始终处于训练分布范围内，从而稳定长程流式推理。设计动机在于解决传统滑动窗口中位置索引随视频长度无限增长导致的 RoPE 外推失效问题，使模型在无限流中保持与短视频训练时一致的位置感知能力。

### 重叠分块全注意力训练

训练阶段，将长视频流分割为长度为 $W$ 帧、重叠 $O$ 帧的连续分块 $\{C_1, C_2, \dots\}$。每个分块内，视觉与文本 Token 以 1 秒间隔交错排列，并应用全注意力机制。损失函数仅在文本位置计算，无解说的秒位插入占位符 "..."。

$$
\mathcal{L} = -\sum_{t \in \mathcal{T}_{text}} \log P(y_t | y_{<t}, x_{chunk})
$$

该公式表明，模型在短分块内学习全注意力下的文本生成，其有效注意力模式（Sink+近期文本+近期视觉）与推理时的 KV 缓存结构高度近似。设计动机在于避免直接模拟推理掩码的复杂性，通过重叠分块的全注意力监督，隐式教会模型预期的近期偏置（recency bias），从而在推理时自然表现出稳定的流式行为，无需在训练阶段处理二次方成本的超长上下文。

## 实验评估

实验在 Inf-Streams-Eval（平均时长 2.12 小时）与 Livecc-Sports-3K CC 上进行，基线包括 GPT-4o mini、Livecc-7B-Instruct 及 ReKV。基线覆盖流式推理与离线模型，但缺失 VST、ThinkStream 等 2026 年 SOTA 方法，限制了横向对比的全面性。

| 模型 | Inf-Streams-Eval (vs GPT-4o mini) | Livecc-Sports-3K CC (vs LLaVA) |
| :--- | :--- | :--- |
| Qwen-2.5-VL-7B-Instruct | 0.01 | 24.50 |
| Livecc-7B-Instruct (∞) | 1.82 | 41.50 |
| StreamingVLM (∞) | 66.18 | 47.33 |

StreamingVLM 在无限流设置下以 66.18% 的胜率大幅领先 Livecc-7B-Instruct 的 1.82%，表明训练-推理对齐策略对长程稳定性的关键作用。

| 配置 | Inf-Streams-Eval (vs GPT-4o mini) |
| :--- | :--- |
| Native RoPE (∞) | 25.09 |
| Contiguous RoPE (∞) | 66.18 |
| + High-Quality Annealing Data | 66.18 |

消融实验显示，连续 RoPE 相比原生 RoPE 在无限流上提升 41.09 个百分点，验证了位置编码稳定性对长程推理的决定性影响。高质量退火数据进一步提升了实时动作解说的质量，但边际收益相对较小。

评估边界方面，Inf-Streams-Eval 采用 GPT-5 作为裁判进行成对比较，缺乏绝对分数与置信区间，且仅覆盖体育解说单一领域。代码已开源，训练算力为 128 H100-days，超参数（$T_{sink}=512, T_{window}=512, V_{window}=16s$）明确，可复现性良好。

## 关联研究分析

从方法设计看，StreamingVLM 与 StreamingLLM 共享注意力沉没思想，但后者仅处理文本，而本文扩展至多模态视频。关键差异在于视觉 Token 的处理：StreamingLLM 依赖文本 Sink 稳定注意力，而本文引入短视觉窗口（16s）以跟踪即时动作，同时通过连续 RoPE 解决视觉 Token 驱逐后的位置漂移。这一差异源于视频流中视觉信息的时空局部性，单纯依赖文本 Sink 无法捕捉快速变化的动作细节。

从问题动机看，与 VST 等 2026 年方法相比，StreamingVLM 聚焦于架构级的内存管理，而非上层推理决策。VST 通过“边看边想”构建双记忆系统以提升推理深度，而 StreamingVLM 仅依赖文本窗口作为长期记忆，缺乏显式的语义摘要或事件级记忆。这种设计选择使得 StreamingVLM 在低延迟实时解说任务上表现优异，但在需要复杂长程推理的 VQA 任务上，其性能提升（LongVideoBench +4.30）相对有限，暗示缺乏语义分层记忆可能限制了其在高认知负荷任务上的潜力。

## 总结

StreamingVLM 旨在解决无限视频流中训练-推理注意力模式错位导致的长程推理不稳定问题。通过重叠分块全注意力训练对齐推理时的 KV 缓存复用结构，并引入连续 RoPE 防止位置漂移，该框架在 2 小时以上的体育解说任务上实现了 66.18% 的胜率，显著优于基线。然而，其记忆机制仅依赖固定长度的文本窗口，缺乏显式的语义分层或事件级记忆，导致在需要复杂长程推理的 VQA 任务上提升有限。当视频时长进一步增加至数小时级别时，仅靠 512 个文本 Token 的窗口能否维持足够的语义连贯性，论文未给出回答。
