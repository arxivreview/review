# ICLR2026最新论文 ｜C-EVOLVE: CONSENSUS BASED EVOLUTION FOR PROMPT GROUPS ｜共识驱动进化

研究机构：浙江大学、西湖大学

作者：Tiancheng Li、Yuhang Wang、Zhiyang Chen 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_21635728)

> 自动提示优化（APO）旨在通过算法自动搜索最优自然语言指令，以在无需修改模型权重的前提下提升大语言模型（LLM）性能。现有进化算法如 GEPA 和 AlphaEvolve 均聚焦于寻找单一最优提示，忽略了多提示协同中通过输出共识抵消个体表达局限的潜力。本文提出 C-Evolve，将适应度函数从个体性能改为群体共识贡献的指数移动平均（EMA）投票分数，利用岛屿模型维持提示多样性以驱动协同进化。该方法在 MATH 和 HotPotQA 等基准上超越了单提示进化基线，但其性能增益高度依赖任务难度分布，且在低耦合度任务上的优势是否显著仍存疑。

## 研究背景

闭源 LLM 仅通过 API 接口访问，参数微调不可行，提示成为适配下游任务的唯一杠杆。然而，单一提示受限于自然语言的表达带宽，难以同时覆盖复杂任务的多维约束。传统集成学习通过组合多个分类器提升鲁棒性，但在 LLM 提示优化中，直接聚合多个提示的输出往往因提示间缺乏协同设计而失效。

进化算法是黑盒提示优化的主流范式。GEPA 采用反思式遗传算法优化单提示，AlphaEvolve 利用岛屿模型进化代码程序，两者均将“寻找全局最优个体”作为唯一目标。这种单点优化策略在任务复杂度增加时暴露出瓶颈：最优提示可能在特定子任务上表现优异，但在其他维度上存在系统性盲区，且无法通过自身变异修复。现有工作缺乏对“提示组协同性能”的系统性优化机制，导致多提示聚合仅停留在推理时的简单投票，未反馈至进化过程。

C-Evolve 的切入点在于将“共识质量”内化为进化信号。它不再评估单个提示的孤立性能，而是评估该提示在与其他岛屿提示组成群体后，对最终共识结果的贡献度。这一转变将优化目标从 $\max_{\Pi} \mu(\Phi(x; \Pi))$ 转变为 $\max_{G} \mu(C(\Phi(x; G)))$，其中 $G$ 为提示组，$C$ 为共识聚合器。通过显式优化群体协同性，C-Evolve 旨在发现一组互补性强的提示，使其在多数投票或 LLM 聚合下产生比任何单一提示更优的结果。

## 核心方法

### 岛屿模型进化参照系

C-Evolve 继承 AlphaEvolve 的岛屿模型架构，初始化 $|G|$ 个独立岛屿，每个岛屿维护一个提示种群。进化循环包含采样、生成和评估三步：基于适应度分布采样父代，利用 LLM 作为 Evolver 结合反馈生成新提示，评估后更新种群。关键差异在于，C-Evolve 引入了两阶段进化：Warm-up 阶段基于个体性能进化，Voting 阶段基于群体共识性能进化，且适应度计算引入了跨岛屿的群体交互。

### 基于 EMA 投票分数的适应度机制

在 Voting 阶段，C-Evolve 从每个岛屿采样一个提示形成 $n_c$ 个群体 $G_k$。每个群体独立生成输出，经共识聚合器 $C$ 得到最终答案 $y_{final}$，并在验证集 $D_{met}$ 上计算指标 $\mu$。个体 $\Pi$ 的投票分数定义为：

$$ s_{\Pi, voting} = \frac{1}{n_c} \sum_{k=1}^{n_c} I(\Pi \in G_k) \mathbb{E}_{(x,m) \sim D_{met}} [\mu(y_{final}^k, m)] $$

该公式计算个体 $\Pi$ 所在所有群体的平均共识性能。为避免早期被淘汰群体对当前评估的干扰，C-Evolve 采用指数移动平均（EMA）更新适应度：

$$ s_{\Pi, EMA} = \alpha \cdot s_{\Pi, EMA}^{old} + (1 - \alpha) \cdot s_{\Pi, voting} $$

其中 $\alpha \in [0, 1]$ 为平滑因子。设计动机在于解决单提示进化中“局部最优陷阱”问题：高个体分数的提示可能在群体中因缺乏互补性而拉低共识质量。EMA 投票分数通过加权近期群体表现，确保进化方向指向那些能稳定提升群体共识的提示，而非仅自身表现优异的提示。

### 群体反馈驱动的进化循环

Evolver LLM 在生成新提示时，不仅接收个体自身的执行反馈，还接收其所在群体的完整反馈，包括其他提示的输出、共识结果及真值对比。这种群体反馈使 Evolver 能够识别个体提示在协同中的具体缺陷（如“在问题 1 中，个体 A 的输出与共识偏差较大”），从而生成更具互补性的新提示。Warm-up 阶段确保每个提示具备基础质量，Voting 阶段则通过群体反馈细化提示间的分工与互补，最终从每个岛屿选出 EMA 分数最高的提示组成最终推理群体。

## 实验评估

实验在 Qwen3-8B 和 GPT-4.1-mini 上进行，覆盖 HotPotQA、IFBench、HoVer、MATH 和 GPQA 五个基准。基线包括 GEPA（反思式进化）和 AlphaEvolve（岛屿模型进化），但缺失 ProTeGi 和 APE 等反馈驱动类基线，限制了与不同优化范式的全面对比。

| 模型 | 任务 | Baseline | GEPA | AlphaEvolve | C-Evolve |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3-8B | HotPotQA | 50.03 | 65.72 | 65.31 | **70.67** |
| Qwen3-8B | IFBench | 31.29 | 34.01 | 41.15 | **43.88** |
| Qwen3-8B | MATH | 67.66 | 43.33 | - | **85.33** |
| GPT-4.1-mini | MATH | 78.66 | 39.00 | - | **95.33** |
| GPT-4.1-mini | IFBench | 40.13 | 46.59 | 45.24 | **47.96** |

C-Evolve 在 Qwen3-8B 上平均提升 13.85%，在 GPT-4.1-mini 上提升 16.09%，显著优于 GEPA 和 AlphaEvolve。在 MATH Level 5 高难度子集上，C-Evolve 达到 68.33%，而单提示最高仅为 66.66%，表明共识机制在困难样本上具有显著增益。

| 消融项 | IFBench 准确率 (%) | MATH Level 5 准确率 (%) |
| :--- | :--- | :--- |
| 无 Warm-up | 41.83 | 83.00 |
| 有 Warm-up | **42.85** | **85.33** |
| Group Average | 41.16 | - |
| EMA ($\alpha=0.8$) | **42.85** | - |
| LLM-summary | 38.66 | - |
| LLM-selection | **42.85** | - |

消融实验显示，Warm-up 阶段带来约 1% 的提升，验证了个体基础质量对群体协同的必要性。EMA 平滑因子 $\alpha=0.8$ 优于简单平均（41.16% vs 42.85%），证实了近期群体表现对适应度评估的重要性。LLM-selection 聚合器优于 LLM-summary（42.85% vs 38.66%），因为选择机制保留了原始输出的保真度，避免了摘要生成的幻觉。

评估边界方面，论文未报告计算效率的详细对比，仅指出 C-Evolve 推理时间从 0.68s 增至 0.79s/题，进化时间每迭代增加 0.8 分钟。可复现性方面，论文提供了数据集划分、提示模板和超参数，但未开源代码。指标体系以 Accuracy 为主，缺乏对提示长度或推理成本的显式优化，与多目标优化共识存在偏差。

## 关联研究分析

从问题动机看，C-Evolve 与 Self-Consistency 共享“多输出聚合”思想，但 Self-Consistency 是推理时策略，不改变提示本身，而 C-Evolve 将共识质量作为进化信号，实现了提示的协同优化。这一差异源于任务特性：Self-Consistency 适用于提示固定但推理不稳定的场景，而 C-Evolve 针对提示本身存在表达局限的场景。然而，当任务耦合度较低时，提示间的互补性可能有限，共识机制的增益是否仍能覆盖其额外计算成本，论文未给出回答。

从方法设计看，C-Evolve 与 GEPA 同属进化范式，但 GEPA 优化单提示的反思式变异，C-Evolve 优化提示组的协同性。GEPA 的帕累托选择机制关注单提示的多目标权衡，而 C-Evolve 的 EMA 投票分数关注群体共识质量。这一设计差异暗示，在复杂多步骤任务中，提示间的依赖关系可能比单提示的内部优化更重要。但 C-Evolve 未提供诊断工具来判断何时需要联合优化，其优势是否普遍适用于所有复合 AI 系统，仍需更多实证支持。

## 总结

C-Evolve 解决了单提示进化在复杂任务中表达局限与多提示协同机制缺失的矛盾。其切入点在于将共识质量内化为进化适应度，通过 EMA 投票分数显式优化提示间的互补性，这是单提示进化方法无法做到的。方法上，它结合岛屿模型维持多样性，Warm-up 阶段确保个体基础质量，Voting 阶段通过群体反馈驱动协同进化。实验证明，C-Evolve 在 Qwen3-8B 上 HotPotQA 达到 70.67%，GPT-4.1-mini 上 MATH 达到 95.33%，显著超越 GEPA 和 AlphaEvolve。其边界在于，性能增益高度依赖任务难度，在低难度任务上优势不明显，且未显式优化计算成本。当任务耦合度降低时，共识机制的边际收益是否递减，论文未给出回答。
