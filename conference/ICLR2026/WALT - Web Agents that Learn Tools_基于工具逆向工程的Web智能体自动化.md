# ICLR2026最新论文 ｜WALT: Web Agents that Learn Tools ｜基于工具逆向工程的Web智能体自动化

研究机构：Salesforce AI研究院

作者：Viraj Prabhu、Yutong Dai、Matthew Fernandez 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.01524)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.01524)

> 导读 当前Web智能体依赖逐步UI交互，在动态布局与长程任务中因元素定位失效而频繁中断，且推理开销巨大。现有技能挖掘方法仅复现成功轨迹，缺乏对网站底层功能的抽象，导致执行脆弱且效率低下。WALT通过离线逆向工程将网站固有功能转化为确定性工具，使智能体从“模拟点击”转向“调用接口”。该方法在VisualWebArena与WebArena上刷新了成功率纪录，但其离线工具发现机制对网站动态更新的适应性仍存疑。

## 研究背景

**预备知识**
Web智能体执行任务时，需将自然语言意图映射为具体的DOM操作或像素坐标，这一过程称为感知接地（Grounding）。接地误差会导致动作失效，而长程任务中累积的上下文信息会超出LLM窗口限制，引发状态漂移。为缓解此问题，智能体需具备规划鲁棒性，即在部分步骤失败后能回溯或重规划。然而，传统ReAct范式将规划与执行耦合在线，每一步都依赖LLM实时推理，既增加了计算负担，又因缺乏对网站底层逻辑的抽象，使得智能体在面对复杂UI时如同“盲人摸象”，无法利用网站本身提供的稳定功能接口。

**研究脉络**
领域主流路线分为在线探索与离线技能挖掘两类。在线方法如TreeSearch通过测试时搜索提升规划质量，但计算成本高且无法复用经验；离线方法如SkillWeaver从成功轨迹中挖掘Python函数，但仅编码了“已发生的行为”，未触及网站设计者预设的功能逻辑，且技能实现仍依赖脆弱的UI序列。WALT的切入点在于区分“智能体想象的技能”与“网站提供的功能”。它认为网站本身已内置了搜索、过滤、排序等稳健自动化机制，智能体的目标不应是模仿人类点击，而是逆向工程这些隐含功能，将其封装为可复用的确定性工具，从而将计算负担从低层执行转移至高层规划。

## 核心方法

### 方法参照系

WALT将浏览器自动化重构为工具发现与调用问题。与标准ReAct循环中智能体在线生成动作序列不同，WALT引入离线阶段：智能体首先探索网站，识别潜在功能点，随后通过“演示-生成-验证”闭环构建工具。这一流程的关键差异在于，工具的实现不依赖LLM实时推理，而是基于逆向工程得到的确定性脚本或URL操作，仅在动态元素处保留智能体步骤。

### 工具逆向工程与多目标优化

工具构建被形式化为多目标优化问题，旨在最小化失败率、步骤数与智能体依赖比例。对于候选工具 $u$，其优化目标为：

$$ \min_{u} \lambda_1 \text{FailRate}(u) + \lambda_2 \text{StepCount}(u) + \lambda_3 \text{AgenticRatio}(u) $$

该公式的物理含义是：在确保功能正确（低失败率）的前提下，优先选择执行步骤少（高效率）且依赖LLM推理少（高确定性）的实现。设计动机在于解决现有技能挖掘方法中“技能过于具体且脆弱”的问题。WALT通过两遍生成策略实现优化：第一遍将执行轨迹映射为包含导航、提取、UI交互及智能体步骤的动作脚本；第二遍尝试逆向工程URL参数，将多步UI操作替换为单次URL调用。例如，搜索功能从“点击搜索框-输入-点击按钮”简化为 `search(query='kayak')`。这种URL提升（URL Promotion）显著降低了 $\text{StepCount}$ 和 $\text{AgenticRatio}$，使工具在UI微调下仍保持稳定。

### 闭环验证与模式化执行

工具注册前需通过闭环验证，由测试智能体执行预检输入，反馈结构化错误（如选择器漂移、枚举值缺失）。验证通过后，工具以原子动作形式暴露给智能体，并附带输入模式（Schema）验证。设计动机在于防止“一次性脚本提取”导致的隐蔽错误。WALT还引入多模态DOM解析器，将HTML转为交错文本-图像输入，解决纯文本在复杂布局下的接地误差；同时配备外部验证工具，由独立LLM核对任务结果，弥补智能体自我报告的幻觉。这种“确定性执行+智能体兜底”的混合架构，确保了在工具失效时智能体仍能通过Agentic Fallback恢复，平衡了效率与鲁棒性。

## 实验评估

**实验设置与主结果**
实验在VisualWebArena（910任务）与WebArena（812任务）上进行，基线覆盖SGV、ASI、SkillWeaver等SOTA方法，但未包含基于强化学习的TGPO等近期工作。WALT在VisualWebArena上取得52.9%的平均成功率，超越SGV（50.2%）2.7个百分点；在WebArena上达到50.1%，大幅领先Branch-and-Browse（35.8%）14.3个百分点。

| 方法 | VisualWebArena Avg. (%) | WebArena Avg. (%) |
| :--- | :--- | :--- |
| SGV | 50.2 | - |
| ASI | - | 40.4 |
| Branch-and-Browse | - | 35.8 |
| WALT | 52.9 | 50.1 |

**消融与设计决策验证**
消融实验显示，工具发现是性能提升的核心。在VisualWebArena-Classifieds上，使用发现工具相比无工具基线，GPT-5-mini的成功率从57.5%提升至61.5%，步骤数减少27%。多模态DOM解析带来+2.6%增益，外部验证带来+3.3%增益，但后者增加了步骤数。人工演示工具的上限为66.0%，WALT自主发现工具达到64.1%，仅差1.9个百分点，证明自动逆向工程接近人类专家水平。

| 配置 | SR (%) | Avg #Steps |
| :--- | :--- | :--- |
| GPT-5-mini (无工具) | 57.5 | 8.9 |
| GPT-5-mini (发现工具) | 61.5 | 6.5 |
| GPT-5-mini (人工演示) | 66.0 | 7.4 |
| GPT-5-mini (全组件) | 64.1 | 7.0 |

**评估边界与可复现性**
评估仅依赖端到端成功率，缺乏对中间推理步骤的细粒度诊断。代码未公开，但基于browser-use库实现，超参数如相似度阈值0.3、最大30步等已披露。由于工具发现依赖特定网站快照，评估结果的可复现性受网站动态更新影响，未报告跨时间点的稳定性测试。

## 关联研究分析

从问题动机看，WALT与SkillWeaver（Zheng et al., 2025）均致力于技能复用，但根源差异在于技能来源。SkillWeaver从成功轨迹中挖掘，本质是“行为克隆”，受限于智能体已探索的路径，无法发现未被执行的功能；WALT则逆向工程网站功能，本质是“功能抽象”，能覆盖智能体未曾尝试但网站支持的交互。这种差异源于对“智能体能力边界”的不同假设：前者假设智能体应学习如何操作，后者假设智能体应利用网站已有的操作接口。

从方法设计看，WALT与SGV（Andrade et al., 2025）同属多模态智能体框架，但执行策略迥异。SGV依赖在线视觉推理定位元素，每一步都需VLM处理截图，计算密集且易受布局变化影响；WALT通过离线工具将高频操作（如搜索、排序）固化为URL调用，仅对低频或动态操作保留视觉推理。这种“离线固化+在线灵活”的设计，解释了WALT在Classifieds子集上大幅领先SGV（64.1% vs 52.0%）的原因，但也暗示其对网站功能稳定性的依赖。当网站频繁重构UI时，WALT的工具失效风险是否高于SGV的在线推理，论文未提供对比数据。

## 总结

WALT解决的核心矛盾是Web智能体在长程任务中因逐步UI交互导致的效率低下与脆弱性。其切入点在于识别网站本身已内置的稳健功能，通过逆向工程将其转化为确定性工具，从而将智能体从低层执行中解放出来。方法上，WALT构建了“演示-生成-验证”闭环，结合URL优化与多模态解析，实现了工具的高效构建与可靠调用。实验证明，该范式在VisualWebArena与WebArena上分别取得52.9%与50.1%的成功率，显著超越现有SOTA。然而，其边界在于离线工具发现对网站静态性的假设：当网站动态更新导致URL参数或DOM结构变化时，工具可能失效，而Agentic Fallback的恢复成本是否可控，论文未给出量化评估。当网站功能频繁迭代时，工具重发现的频率与成本如何平衡，仍是该范式落地的关键未知数。
