# ICLR2026最新论文 ｜CHATINJECT: ABUSING CHAT TEMPLATES FOR PROMPT INJECTION IN LLM AGENTS ｜聊天模板结构滥用下的间接提示注入攻击

作者：Hwan Chang、Yonghyun Jun、Hwanhee Lee

论文原文见 [arXiv](https://arxiv.org/abs/2509.22830)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_14926976)

> 间接提示注入（Indirect Prompt Injection, IPI）旨在通过污染外部数据劫持大语言模型（LLM）代理的行为，但现有攻击多局限于纯文本操纵，忽视了模型对结构化输入格式的深层依赖。ChatInject 指出，代理系统为防御 IPI 而建立的基于聊天模板的角色层级（Role Hierarchy）本身存在结构性漏洞，攻击者可通过伪造高优先级角色标签绕过信任边界。该方法将恶意载荷格式化为目标模型的原生聊天模板，并引入虚拟多轮对话机制以增强说服力，在 AgentDojo 和 InjecAgent 基准上显著提升了攻击成功率。这一发现揭示了当前基于模板解析的防御机制在应对结构化攻击时的脆弱性，但其跨模型迁移性对闭源模型的实际威胁程度仍需更严格的验证。

## 研究背景

当 LLM 代理调用外部工具（如搜索、API）时，返回的数据可能包含隐藏的恶意指令，即间接提示注入（IPI）。为抵御 IPI，主流防御策略引入了指令层级（Instruction Hierarchy），通过聊天模板中的特殊标记（如 `<system>`、`<user>`）区分指令与数据，强制模型遵循“系统 > 用户 > 工具输出”的优先级约束。然而，这种基于 token 的分割机制依赖于模型对特定符号的语义解析，若攻击者能在低优先级的工具输出中伪造高优先级标签，模型可能误将恶意数据视为系统指令，从而绕过安全过滤。

IPI 研究已从手动构造转向自动化优化，如 GCG 等梯度引导方法，但这些工作主要关注文本内容的语义对抗，忽略了 LLM 输入的结构化特性。现有防御假设模板解析是安全的，但 ChatInject 指出，模板本身成为新的攻击面：攻击者无需优化文本内容，只需利用模型对角色标签的依赖，即可在单次注入中模拟多轮说服过程。这一切入点将 IPI 的威胁模型从“内容混淆”扩展至“结构劫持”，揭示了代理系统在解析多源输入时的根本性缺陷。

## 核心方法

### 方法参照系

传统 IPI 攻击将恶意指令 $I_a$ 作为纯文本嵌入工具响应 $R_{T_u}$，依赖注意力前缀（如 "Ignore all previous instructions"）吸引模型注意。本文问题与该通用流程的关键差异在于：攻击载荷不再以自然语言形式存在，而是被重构为符合目标模型聊天模板语法的结构化数据，利用模型对角色标签的解析逻辑实现权限提升。

### 模板格式化载荷生成

ChatInject 的核心创新在于定义模板函数 $T_{model}$，将恶意指令 $I_a$ 或对话历史 $C_a$ 包裹在目标模型的原生角色标签中。设计动机是解决纯文本注入易被上下文一致性检查拦截的问题，通过伪造高优先级角色（如 `<system>`）使模型误判指令来源。

$$
\text{Payload} = T_{model}(I_a) = \langle \text{system\_tag} \rangle \text{Prefix} \langle \text{eos} \rangle \langle \text{user\_tag} \rangle I_a \langle \text{eos} \rangle
$$

该公式表示，攻击者将注意力前缀置于系统角色标签内，将恶意指令置于用户角色标签内。当模型解析工具输出时，若检测到这些标签，会将其视为高优先级指令，从而执行 $I_a$。相比纯文本注入，此方法利用了模型对模板结构的内在依赖，无需复杂的语义优化即可实现权限提升。

### 虚拟多轮对话构造

针对单次注入缺乏交互说服力的局限，ChatInject 引入多轮变体，通过伪造对话历史 $C_a = \{(r_{a,i}, m_{a,i})\}_{i=1}^n$ 模拟多轮交互。设计动机是解决 IPI 单次交互无法逐步引导模型接受恶意请求的问题，利用 LLM 对对话状态的追踪机制增强说服力。

$$
\text{Payload}_{MT} = T_{model}(C_a) = \bigoplus_{i=1}^n \langle r_{a,i} \text{\_tag} \rangle m_{a,i} \langle \text{eos} \rangle
$$

该公式表示，攻击者将多轮对话中的每个角色-消息对包裹在对应的角色标签中，并通过行级拼接（$\bigoplus$）形成单一载荷。例如，伪造 `<user>` 询问需求，`<assistant>` 解释必要性，最终 `<user>` 请求执行恶意操作。这种虚拟多轮结构激活了模型的多轮对话依赖，使恶意指令在上下文中显得合理，显著提升了攻击成功率。

## 实验评估

实验在 AgentDojo 和 InjecAgent 基准上进行，对比 Default InjecPrompt（纯文本）和 Default Multi-turn（纯文本多轮）基线。基线覆盖传统 IPI 攻击，但未包含 GCG 等自动化优化攻击或 IsolateGPT 等系统级防御，限制了与前沿防御方法的直接对比。

| 基准 | 模型 | Default InjecPrompt ASR (%) | ChatInject ASR (%) | Multi-turn + ChatInject ASR (%) |
| :--- | :--- | :--- | :--- | :--- |
| AgentDojo | Qwen-3 | 17.5 | 69.4 | 80.5 |
| AgentDojo | GPT-oss | 0.3 | 51.4 | 55.5 |
| InjecAgent | Qwen-3 | 8.5 | 42.1 | 65.9 |
| InjecAgent | GLM-4.5 | 0.0 | 72.2 | 71.5 |

ChatInject 在 AgentDojo 上的平均 ASR 从 5.18% 提升至 32.05%，在 InjecAgent 上从 15.13% 提升至 45.90%。多轮变体在 InjecAgent 上达到 52.33% 的平均 ASR，表明虚拟多轮对话显著增强了攻击效果。Grok-2 的 ASR 提升较小（+1.2%），因其模板缺乏强角色分隔符，削弱了伪造标签的权威性。

消融实验显示，工具调用钩子（Tool-calling hook）对 ASR 提升贡献最大，尤其在 AgentDojo 上，即使未明确命名工具，匹配代理行为模板仍能显著增强攻击效果。推理钩子（Reasoning hook）的收益相对较小，表明模型对工具调用格式的依赖强于对推理过程的依赖。

评估边界方面，论文未报告计算效率指标，且跨模型迁移实验仅使用开源模板代理闭源模型，未直接获取闭源模型的模板结构。代码已开源，但超参数细节（如 GPT-4.1 生成对话的具体提示）仅在附录中提供，复现性依赖对附录的完整理解。

## 关联研究分析

从问题动机看，ChatInject 与 Greshake et al. (2023) 的 IPI 奠基工作不同，后者关注外部数据中的文本混淆，而本文聚焦于结构化模板的解析漏洞。这一差异源于 LLM 代理架构的演进：早期代理主要处理纯文本，而现代代理依赖聊天模板进行角色区分，使得模板成为新的攻击面。ChatInject 揭示了防御机制从“内容过滤”向“结构解析”转移时引入的新风险，这一风险在纯文本 IPI 研究中未被充分探讨。

从方法设计看，ChatInject 与 Crescendo (2024) 的多轮越狱攻击共享“逐步说服”的策略，但 Crescendo 依赖真实的多轮交互，而 ChatInject 在单次注入中伪造多轮历史。这一差异源于 IPI 的被动性：攻击者无法与代理交互，只能通过工具输出嵌入载荷。ChatInject 的虚拟多轮机制解决了这一约束，但其有效性依赖于模型对对话状态的追踪能力，若模型不依赖角色标签进行状态管理，该攻击可能失效。

## 总结

ChatInject 针对 IPI 中基于聊天模板的防御机制存在的结构性漏洞，提出通过伪造角色标签和虚拟多轮对话实现权限提升的攻击方法。该方法在 AgentDojo 和 InjecAgent 上显著提升了攻击成功率，证明了模板解析层面的信任边界失效。然而，其跨模型迁移性主要基于开源模板的相似性假设，对闭源模型的实际威胁程度未得到直接验证。当闭源模型的模板结构与开源模型存在显著差异时，ChatInject 的迁移效果是否仍具有一致性，论文未给出回答。
