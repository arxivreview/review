# ICLR2026最新论文 ｜Speculative Speculative Decoding ｜推测性推测解码

研究机构：丰田研究所、美国斯坦福大学

作者：Tanishq Kumar、Tri Dao、Avner May

论文原文见 [arXiv](https://arxiv.org/abs/2603.03251)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.03251)

> 自回归解码的串行瓶颈已被投机解码（Speculative Decoding, SD）通过“草稿-验证”范式部分缓解，但草稿生成与验证之间的同步等待仍构成新的串行依赖。现有并行化尝试仅覆盖特定验证结果或受限于小批量场景，无法在通用条件下消除该等待。本文提出推测性推测解码（Speculative Speculative Decoding, SSD）框架，让草稿模型在验证期间预测可能的验证结果并预生成对应草稿，从而将草稿开销与验证时间重叠。该框架在特定硬件配置下实现了显著加速，但其性能高度依赖异卡部署与缓存命中率，对单卡或高并发场景的普适性存疑。

## 研究背景

自回归解码中，目标模型每生成一个 token 需执行一次完整前向传播，其延迟受限于内存带宽而非计算能力。投机解码通过引入轻量级草稿模型并行预测多个候选 token，再由目标模型单次并行验证，将串行生成转化为并行验证，从而在不改变输出分布的前提下提升吞吐量。验证阶段的目标模型不仅决定接受多少个草稿 token，还会从残差分布中采样一个“奖励 token”（bonus token），该 token 的分布依赖于草稿与目标模型的概率差，这使得验证结果具有随机性，无法被简单预测。

早期并行化研究如 DSI（Timor et al., 2025）和 SwiftSpec（Zhang et al., 2025）尝试在验证期间生成下一轮草稿，但仅针对“全部接受”这一特定结果，或采用即时回退策略，导致在大批量或高温度下缓存命中率骤降，异步优势被抵消。树状验证方法（如 SpecInfer）通过增加验证计算换取更高接受率，但并未解决草稿与验证间的同步等待。本文切入点在于：将验证结果预测建模为缓存命中问题，通过预生成多种可能结果的草稿，将草稿开销完全隐藏于验证时间内，从而在保持无损性的前提下消除串行依赖。

## 核心方法

### 方法参照系

标准 SD 流程为：草稿生成 → 目标验证 → 草稿生成，两阶段严格串行。本文问题与该通用流程的关键差异在于：草稿模型需在验证进行期间，基于对验证结果的预测，并行预生成下一轮草稿，而非等待验证完成后再开始生成。

### 验证结果预测与推测缓存

草稿模型需预测验证结果 $v_T = (k, t^*)$，其中 $k$ 为接受 token 数，$t^*$ 为奖励 token。本文定义推测缓存 $\mathcal{S}_T$ 为从验证结果集合 $\mathcal{V}_T$ 到预计算草稿序列的映射。为最大化缓存命中率，本文提出基于扇出（fan-out）策略的缓存构建方法：在每个前瞻位置 $k$，选取草稿 logits 中 top-$F_k$ 的 token（排除已发送验证的 token）作为候选奖励 token。扇出值 $F_k$ 的优化基于幂律缓存命中率假设，即缓存未命中概率与扇出 $F$ 呈 $1/F^r$ 关系，通过约束优化求解最优扇出分布，使缓存命中率在计算约束下最大化。该设计解决了此前方法仅预测单一结果导致缓存命中率低的问题，将验证结果预测转化为可控的缓存命中概率优化。

### Saguaro 采样与动态回退

缓存命中率与草稿接受率存在权衡：降低草稿分布中缓存 token 的概率可提升残差分布中这些 token 的质量，从而提高缓存命中率，但会降低接受率。本文提出 Saguaro 采样方案 $\sigma_{F,C}(z)$，通过下加权常数 $C$ 调节草稿分布，在缓存命中率与接受率间取得平衡。$$ \sigma_{F,C}(z)_t = \frac{\exp(z_t / C) \cdot \mathbb{1}[t \in \text{cache}]}{\sum_{t'} \exp(z_{t'} / C) \cdot \mathbb{1}[t' \in \text{cache}]} $$ 该公式通过降低缓存 token 的草稿概率，使残差分布 $r(t) \propto \max(p_{\text{target}}(t) - p_{\text{draft}}(t), 0)$ 集中于缓存 token，从而提升缓存命中率。对于缓存未命中，本文提出动态回退策略：当批量大小 $b < b^*$ 时，使用主草稿模型即时生成；当 $b \geq b^*$ 时，切换为低延迟备份草稿模型（如随机 token 或 n-gram 模型），避免整个批次因等待主草稿而停滞。该策略解决了高批量下缓存未命中导致的同步阻塞问题，确保异步架构在不同批量规模下的稳定性。

## 实验评估

实验在 Llama-3.1-70B 目标模型与 Llama-3.2-1B 草稿模型上进行，使用 4×H100 部署目标模型，1×H100 部署草稿模型，覆盖 HumanEval、GSM8K、Alpaca 等数据集，采用贪心解码。基线包括自回归解码（AR）、标准 SD、SGLang（SD/EAGLE-3），但缺失 EAGLE-2、HASS 等特征对齐类 SOTA 基线，且未与 DSI、SwiftSpec 等并行化方法直接对比。

| 方法 | 平均加速比 (vs AR) | 相对最强 SD 基线提升 |
| :--- | :--- | :--- |
| SSD (Saguaro) | 5.6x | 30% |
| SD (Ours) | 4.0x | — |
| AR (Ours) | 1.0x | — |

SSD 在平均加速比上达到 5.6x，比最强 SD 基线快 30%，但此结果依赖于异卡部署与贪心解码协议。消融实验显示，Saguaro 采样在低 $C$ 值下缓存命中率提升但接受率下降，高 $C$ 值则相反，表明缓存命中率与接受率的权衡是性能的关键调节器。动态回退策略在批量大小超过临界值 $b^*$ 时显著降低延迟，验证了备份草稿模型选择的必要性。

评估边界方面，实验仅覆盖贪心解码，未测试高温度采样下的性能；硬件配置固定为 4×H100+1×H100，未探索单卡或异构硬件场景；代码已开源，但超参数（如 $C$、$b^*$）的敏感性分析未在正文中详细展开，可复现性依赖于附录中的完整配置。

## 关联研究分析

从问题动机看，SSD 与 DSI（Timor et al., 2025）均旨在消除草稿与验证的同步等待，但 DSI 侧重多序列并行验证，通过逻辑副本重叠不同序列的草稿与验证，而 SSD 聚焦单序列异步，通过预测验证结果预生成草稿。这一差异源于任务特性：DSI 适用于高并发批处理，SSD 适用于低延迟单序列场景。SSD 的缓存命中机制在低批量下优势明显，但在高批量下需依赖动态回退，而 DSI 的多序列并行天然适配高批量，两者在批量规模上的适用性存在互补而非替代关系。

从方法设计看，SSD 与 EAGLE（Li et al., 2024）在草稿模型架构上存在根本差异：EAGLE 通过特征对齐提升接受率，草稿与目标模型耦合紧密；SSD 使用独立草稿模型，通过采样方案调节分布以优化缓存命中率。SSD 的 Saguaro 采样故意降低草稿接受率以提升缓存命中率，这与领域共识“高接受率即最优”相悖，暗示在异步架构下，接受率与缓存命中率的权衡可能比同步架构更复杂。SSD 框架可兼容 EAGLE 类特征对齐草稿，但论文未实验验证这种组合的性能增益，特征对齐草稿的高接受率是否会导致缓存命中率下降，论文未给出回答。

## 总结

SSD 要解决的核心矛盾是投机解码中草稿生成与验证的同步等待，现有方法因仅预测单一结果或受限于小批量而无法在通用条件下消除该等待。本文抓住验证结果的随机性可被预测这一被忽略的点，通过推测缓存与 Saguaro 采样将草稿开销隐藏于验证时间内，实现了 5.6x 平均加速比与 30% 相对提升。本文的边界在于性能高度依赖异卡部署与贪心解码协议，未验证高温度采样或单卡场景下的有效性。当批量大小超过临界值 $b^*$ 时，动态回退策略的性能增益是否随硬件间通信延迟增加而递减，论文未给出回答。
