# ICLR2026最新论文 ｜VitaBench: Benchmarking LLM Agents with Versatile Interactive Tasks in Real-world Applications ｜真实世界交互智能体基准

研究机构：美团

作者：Wei He、Yueqing Sun、Hongyan Hao 等 16 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.26490)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.26490)

> 现有智能体评估基准多局限于静态环境或单一领域，无法捕捉真实部署中多工具依赖、动态用户交互及跨场景推理的复杂性。VitaBench 通过构建包含 66 个工具、400 个任务的跨场景生活服务平台，并引入基于评分标准的滑动窗口评估器，解决了长轨迹评估中的上下文截断与多解路径判定难题。该基准揭示了当前最先进模型在跨场景任务中仅 30.0% 的成功率，验证了真实世界交互对智能体能力的严峻挑战，但其去策略化设计对评估方差的影响尚需进一步消融验证。

## 研究背景

当智能体在真实应用中执行“预订河景酒店并安排浪漫晚餐”这类复合任务时，它必须同时处理数据库中的海量候选项、工具间的执行依赖（如修改订单前需获取详情）以及用户模糊且动态变化的意图。这种复杂性无法用单一维度的指标衡量，需从信息处理量、工具图结构及交互动态性三个层面共同定义，构成了智能体任务复杂度的核心框架。

早期工具使用基准主要关注单轮 API 调用的参数准确性，通过增加工具数量或干扰项来提升难度，但忽视了工具间的内在依赖关系及与用户的动态交互。随后的交互式基准如 τ-bench 引入了状态执行与用户模拟，但往往依赖冗长的领域策略文档来约束智能体行为，限制了其在开放环境中的自主探索能力。此外，多数基准将用户视为静态输入，未能充分模拟真实用户中存在的偏好不确定性、情绪波动及信息渐进披露等动态特征。VitaBench 的切入点在于摒弃显式策略文档，将领域规则内化为工具依赖图的先决条件与后置条件，并构建跨场景任务，以评估智能体在复杂、非结构化环境中的综合应对能力。

## 核心方法

### 三维任务复杂度形式化

本文基于部分可观测马尔可夫决策过程（POMDP）框架，将智能体任务形式化为状态空间 $S = S_{db} \otimes S_{user}$ 与观测空间 $O = O_{db} \otimes O_{user}$ 的联合演化。区别于传统基准仅关注最终状态 $s_T$ 是否满足目标，VitaBench 引入三维复杂度向量 $C_{task} = \langle C_{reason}, C_{tool}, C_{interact} \rangle$ 来量化环境挑战。其中，工具复杂度 $C_{tool}$ 通过将工具集建模为有向图 $G=(V, E)$ 来捕捉结构复杂性，其核心公式为：

$$ \rho = \frac{|E|}{|V|(|V|-1)} $$

该公式计算工具依赖图的边密度，反映了智能体在导航动作空间时需处理的逻辑关联强度。这一设计动机在于解决现有基准中工具依赖关系隐式存在、难以量化且易被策略文档掩盖的问题，使得环境复杂度可被独立于模型能力进行度量。

### 基于评分标准的滑动窗口评估器

针对长轨迹评估中上下文长度溢出及多解路径判定的难题，本文提出了一种基于评分标准（Rubric）的滑动窗口评估机制。评估器将轨迹划分为重叠窗口 $W_i$，每个窗口包含 $w$ 轮对话，相邻窗口共享 $\delta$ 轮以确保信息连贯。评估器维护一个状态向量 $\mathbf{s} \in \{0, 1\}^k$，其更新逻辑为：

$$ s_j = \max(s_j, \mathbb{I}[r_j \text{ satisfied in } W_i]) $$

其中 $r_j$ 为第 $j$ 个原子评分标准，$\mathbb{I}[\cdot]$ 为指示函数。该公式的物理含义是，一旦某个评分标准在任意窗口中被满足，其状态即被永久标记为真，从而实现了跨窗口的状态持久化跟踪。这一创新解决了传统基于最终状态对比的评估方法无法捕捉中间推理错误、推荐行为及规划过程的问题，使得评估器能够处理远超上下文长度的复杂轨迹，同时通过原子化标准支持细粒度的错误归因。

## 实验评估

实验在 VitaBench 的 400 个任务上进行，涵盖配送、店内消费及在线旅游代理（OTA）三个领域，其中 100 个为跨场景任务。基线模型包括 GPT-4.1、Claude-4.1-Opus、o3 等主流大语言模型，分为思考与非思考两类配置。评估指标包括 Avg@4（平均成功率）、Pass@4（至少一次成功）及 Pass^4（全部成功）。

| 模型类别 | 代表模型 | Cross-Scenario Avg@4 (%) | Single-Scenario Avg@4 (%) |
| :--- | :--- | :--- | :--- |
| Thinking | o3 (high) | 30.0 | 53.5 |
| Thinking | Claude-4.1-Opus (w/ thinking) | 29.0 | 52.5 |
| Non-thinking | Claude-4.1-Opus (w/o thinking) | 21.8 | 46.0 |
| Non-thinking | GPT-4.1 | 17.0 | 40.3 |

跨场景任务中，最佳模型 o3 (high) 的 Avg@4 仅为 30.0%，显著低于单场景任务中的 53.5%，表明跨域协调与工具选择是主要瓶颈。思考模型普遍优于非思考模型，如 Claude-4.1-Opus 从 21.8% 提升至 29.0%，且思考模型在更少轮次（61.1 vs 69.9）下达到更高性能，验证了推理机制对效率与效果的同步提升。

消融实验显示，移除滑动窗口机制导致 Cohen’s $\kappa$ 从 0.828 降至 0.604，而移除评分标准则使任务准确率从 95.0% 骤降至 22.0%，证实了评分标准在捕捉细粒度要求中的关键作用。用户模拟器在信息保真度上得分 9.48/10，人格一致性得分 9.34/10，表明模拟环境具有较高的可靠性。然而，Pass^4 指标显示即使顶级模型的一致性也接近零，揭示了当前智能体在长程任务中缺乏稳定性，探索性采样（Pass@k）虽能提升成功率，但未能解决根本性的状态漂移问题。

评估边界方面，VitaBench 依赖 LLM 作为用户模拟器与评估器，尽管进行了可靠性验证，但模型偏差仍可能引入噪声。代码与数据已公开，但跨场景任务的构建成本较高，限制了基准的快速扩展。此外，论文未报告计算资源消耗，成本效率维度缺失，难以评估其在大规模部署中的经济可行性。

## 关联研究分析

从问题动机看，VitaBench 与 τ-bench 均关注交互式环境中的状态一致性，但 τ-bench 依赖显式策略文档来约束智能体行为，而 VitaBench 将规则内化为工具依赖图，允许智能体自主探索。这一差异源于任务特性的不同：τ-bench 聚焦于客服场景的合规性，而 VitaBench 旨在模拟真实生活服务的开放性。去策略化设计可能导致评估方差增大，因为智能体可能采取多种有效路径，但论文通过滑动窗口评估器缓解了这一问题，其具体影响需进一步消融验证。

从方法设计看，VitaBench 与 UserBench 均引入用户模拟，但 UserBench 侧重偏好驱动的交互，任务复杂度较低，而 VitaBench 扩展至多域跨场景交互，并引入工具图结构量化环境复杂性。VitaBench 的三维复杂度框架提供了更系统的环境难度度量，而 UserBench 缺乏对工具依赖的显式建模。这种差异反映了评估目标的不同：UserBench 关注用户理解能力，VitaBench 关注综合环境应对能力。VitaBench 的工具图密度指标 $\rho$ 为环境复杂度提供了量化基础，但其在不同领域间的可比性尚未充分验证。

## 总结

VitaBench 旨在解决真实世界智能体评估中环境静态性与动态性脱节的核心矛盾，通过构建包含 66 个工具、400 个任务的跨场景基准，并引入基于评分标准的滑动窗口评估器，实现了长轨迹的细粒度评估。实验表明，当前最先进模型在跨场景任务中仅 30.0% 的成功率，揭示了智能体在复杂环境中的显著局限。其边界在于去策略化设计可能引入的评估方差，以及 LLM 模拟器与评估器固有的模型偏差。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
