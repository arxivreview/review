# ICLR2026最新论文 ｜HARNESSING TEMPORAL DATABASES FOR - SYSTEMATIC EVALUATION OF FACTUAL TIME SENSITIVE QUESTION-ANSWERING IN LLMS ｜基于时序数据库的系统化时间敏感问答评估

研究机构：韩国科学技术院、微软研究院

作者：Soyeon Kim、Jindong Wang、Xing Xie 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_79496664)

> 时间敏感问答（TSQA）旨在验证大语言模型（LLM）对动态事实的掌握，但现有基准依赖人工策展，难以覆盖多样时间语境且维护成本高。TDBench 利用时序数据库技术自动构建 QA 对，并引入时间准确率指标，解决了评估粒度粗与更新滞后的问题。该框架通过 SQL 查询生成 13 种 Allen 关系约束，实现了从静态模板到动态生成的范式转换。其价值在于揭示了模型在答案正确但时间引用错误上的系统性盲区，但评估范围局限于结构化数据，未涵盖非结构化叙事中的复杂时序推理。

## 研究背景

当 LLM 回答“谁是美国现任总统”时，其准确性取决于对时间切片的感知。传统关系数据库仅存储实体最新状态，无法表达“2001-2009 年间布什是总统”这一历史事实，而时序数据库通过为每行数据附加 `start` 和 `end` 时间戳，保留了实体的完整生命周期。这种结构使得“在任意时间点 t，某国某职位由谁担任”这一逻辑成为可计算属性，该属性在数据库理论中被称为时序函数依赖（Temporal Functional Dependency, TFD）。TFD 确保了在时间区间重叠时，特定属性组合能唯一确定目标值，为自动提取时间敏感事实提供了形式化基础。

现有 TSQA 基准如 RealTimeQA 和 TimeQA 主要依赖人工设计问题模板或手动策展新闻，导致时间语境多样性受限（通常仅覆盖 4-6 种关系）且更新滞后。随着 LLM 应用深入法律、医疗等垂直领域，静态 Wikipedia 数据已无法反映真实场景的时效性需求。TDBench 的切入点在于将基准构建从“人工写作”转变为“数据库查询”，利用 TFD 自动选择可问属性，通过时序 SQL 生成无限多样的时间约束，从而在降低人工成本的同时，实现对 LLM 时间推理能力的细粒度、可扩展评估。

## 核心方法

### 方法参照系

TSQA 评估的标准流程通常包含问题生成、模型作答与答案匹配。传统方法依赖固定模板（如“[Year] 年的总统是？”）填充实体，导致问题分布狭窄。TDBench 的关键差异在于将问题生成解耦为“逻辑约束生成”与“自然语言转换”两个阶段，前者由数据库引擎保证逻辑完备性，后者由 LLM 保证语言多样性，从而在保持答案唯一性的前提下扩展了时间语境的覆盖范围。

### 基于 TFD 的知识选择与 SQL 约束生成

TFD 机制解决了传统模板法中“哪些属性适合提问”的筛选难题。给定 TFD $X \xrightarrow{T} Y$，TDBench 自动将 $X$ 属性作为问题条件，$Y$ 属性作为答案目标。例如，依赖关系 `country, role → name` 直接映射为“某国某职位的担任者”这一问法。在此基础上，Genqueries 算法利用 Allen 区间代数生成 13 种互斥时间关系。对于关系 $r(a, b)$，其中 $a$ 为实体有效期，$b$ 为随机采样时间区间，SQL 条件定义为：

$$
\begin{cases}
a.end < b.start & \text{if } r = \text{before} \\
a.end = b.start & \text{if } r = \text{meet} \\
a.start < b.start \land a.end > b.start & \text{if } r = \text{overlap}
\end{cases}
$$

该设计动机在于消除人工设计时间语境时的遗漏与偏差，确保评估覆盖所有拓扑关系。通过 SQL 执行获取答案，保证了 ground truth 的绝对正确性，避免了人工标注错误。

### 时间准确率（Time Accuracy）验证机制

传统评估仅检查最终答案，忽略了模型解释中的时间幻觉。TDBench 引入时间准确率（T）指标，要求模型在回答中显式提供推理所用的时间引用（如开始或结束日期）。验证过程利用生成问题时的 SQL 约束作为基准，通过 LLM Judge 判断模型提供的引用是否满足约束。设期望时间引用集合为 $R_{exp}$，模型输出引用为 $R_{out}$，则时间准确率定义为：

$$
T = \frac{1}{|R_{exp}|} \sum_{t \in R_{exp}} \mathbb{I}(\text{Judge}(t, R_{out}) = \text{True})
$$

其中 $\mathbb{I}$ 为指示函数。这一机制解决了“答案正确但理由错误”的评估盲区，例如模型答对现任君主但错误陈述其登基年份。通过关联特定关系（如 `before` 关系仅验证结束日期），实现了细粒度的逻辑一致性检查。

## 实验评估

TDBench 在 Wikipedia 和 Kaggle 数据集上评估了 GPT-4o、Llama3.1-70B 等 8 个主流 LLM。基线覆盖通用 LLM，但未包含专门的时序推理模型（如 STAIR 或 ODL-TempLLM），这限制了与神经符号方法在复杂逻辑推理上的直接对比。实验设置采用零温度采样以排除随机性，数据涵盖法律、环境、文化等垂直领域，共生成 7,881 个问题。

| 模型 | Wikipedia A | Wikipedia AT | Δ (A-AT) |
| :--- | :--- | :--- | :--- |
| GPT-4o | 73.9 | 48.8 | 25.1 |
| Llama3.1-70B | 64.6 | 56.7 | 7.9 |
| Gemma2-27B | 69.3 | 32.8 | 36.5 |
| Average | 56.9 | 35.2 | 21.7 |

核心发现是答案准确率（A）与答案-时间准确率（AT）之间存在显著差距，平均下降 21.7%。Gemma2-27B 的差距最大（36.5%），表明其时间引用幻觉严重；而 Llama3.1-70B 差距最小（7.9%），显示其在时间逻辑一致性上更具优势。在多跳推理任务中，GPT-4o 在 3-hop 设置下 A 达 90.4%，但 H1（第一跳正确第二跳错误的概率）为 26.3%，揭示了模型在长程依赖中的脆弱性。

消融实验显示，引入 RAG 或 CoT 对多跳任务影响不一。GPT-4 在 Time-CoT 下得分从 67.2 提升至 93.9，但 GPT-3.5 在 RAG 下从 63.1 降至 35.4，表明检索增强可能引入噪声干扰弱模型的推理。TDBench 自身正确性经人工验证，F1 分数在 0.87-0.97 之间，证明数据库驱动生成的 QA 对具有高度可靠性。

评估边界方面，TDBench 依赖结构化时序数据库，未覆盖非结构化文本中的隐式时间线索（如“在奥运会期间”需外部知识关联）。LLM Judge 的验证准确率仅为 91.1%，存在约 9% 的误判风险。代码已开源，但超参数设置（如 SQL-to-text 提示词）未详细公开，可能影响复现一致性。

## 关联研究分析

从问题动机看，TDBench 与 RealTimeQA 均关注知识时效性，但 RealTimeQA 依赖人工每周更新新闻，导致更新停滞；TDBench 通过数据库自动同步，解决了维护成本问题。然而，RealTimeQA 涵盖非结构化新闻文本，而 TDBench 局限于结构化实体，这导致 TDBench 无法评估模型在长文本叙事中的时间定位能力，这是任务特性决定的边界，而非技术缺陷。

从方法设计看，TDBench 的 Allen 关系生成与 TempReason 的多跳推理在逻辑覆盖上有重叠，但 TempReason 侧重静态文本中的逻辑链，TDBench 侧重动态事实的时效性。TDBench 未测试神经符号方法（如 STAIR），而 STAIR 在 TimeQA 上 F1 达 65.1，远高于通用 LLM。若将 STAIR 引入 TDBench，其符号约束可能显著降低 AT 与 A 的差距，但论文未提供此对比，暗示 TDBench 当前主要服务于通用 LLM 的基准测试，而非专门推理模型的优化验证。

## 总结

TDBench 旨在解决 TSQA 基准人工维护成本高与时间语境覆盖窄的矛盾。其切入点在于利用时序数据库的 TFD 和 SQL 引擎，将问题生成从人工模板转变为自动化查询，从而实现了 13 种 Allen 关系的全面覆盖。实验证明，该框架揭示了 LLM 在时间引用上的系统性幻觉，平均 AT 较 A 下降 21.7%，且不同模型在时间一致性上差异显著。然而，TDBench 的评估局限于结构化数据，未涵盖非结构化叙事中的隐式时间推理，且未对比神经符号方法。当评估对象从通用 LLM 扩展至具备符号约束的时序推理模型时，TDBench 揭示的“时间引用幻觉”是否会被符号逻辑彻底消除，论文未给出回答。
