# ICLR2026最新论文 ｜GRAPHPLANNER: GRAPH MEMORY-AUGMENTED AGENTIC ROUTING FOR MULTI-AGENT LLMS ｜图记忆增强的智能体路由

研究机构：美国伊利诺伊大学厄巴纳-香槟分校

作者：Tao Feng、Haozhen Zhang、Zijie Lei 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_72478744)

> 多智能体大语言模型（LLM）协作中，异构模型的能力与成本差异导致简单任务浪费资源、复杂任务表现不足，而现有单轮或多轮路由器无法显式建模智能体间的协作依赖与历史交互记忆。GraphPlanner 将工作流生成形式化为马尔可夫决策过程（MDP），通过异构图 GARNet 整合工作流与历史记忆，联合决策 LLM 骨干与智能体角色，以强化学习优化任务效用与计算成本的权衡。该方法在 14 个任务上平均准确率提升 9.3%，GPU 成本从 186.26 GiB 降至 1.04 GiB，但角色空间固定为 3 种且未验证动态扩展能力，其图结构在超大规模模型池下的可扩展性存疑。

## 研究背景

当 LLM 处理复杂查询时，单一模型难以兼顾简单子任务的效率与复杂推理的质量，这催生了多智能体协作范式：将任务分解为规划、执行、总结等角色，由不同 LLM 承担。然而，现有路由器仅能选择模型骨干，无法决定激活哪个智能体角色，导致协作缺乏结构化，产生冗余调用与上下文冲突。

LLM 路由领域已从单点选择演进至系统编排，但主流方法仍局限于简化或静态设置。单轮路由器（如 RouterDC）基于查询嵌入做一次性分配，缺乏多步推理能力；多轮路由器（如 Router-R1）虽引入历史上下文，却将每次调用视为独立事件，未显式建模 LLM 间的互补性与协作依赖。这种设计导致长程任务中累积成本失控，且无法利用历史交互中的成功协作模式。GraphPlanner 的切入点在于将路由从“模型选择”升级为“工作流生成”，通过图结构显式捕获查询、智能体、响应间的异构依赖，解决多智能体场景下的全局预算控制与历史记忆利用问题。

## 核心方法

### 方法参照系

多智能体路由的标准流程是序列决策：路由器根据当前查询与历史上下文，逐步选择 LLM 骨干。本文的关键差异在于，不仅选择模型，还联合决策智能体角色（Planner/Executor/Summarizer），并将工作流建模为异构图，使路由决策能感知协作结构与历史记忆。

### 工作流生成的 MDP 形式化

传统多轮路由将状态定义为查询与上下文的序列，无法捕捉子查询间的分支与依赖关系。GraphPlanner 将工作流生成形式化为 MDP，状态 $s_t$ 为当前待解决的查询，动作 $a_t = (\alpha_t, m_t)$ 同时指定角色 $\alpha_t$ 与 LLM 骨干 $m_t$，动作空间大小为 $3K$（$K$ 为模型池规模）。奖励函数平衡任务效用与计算成本：

$$
r_t = U(\hat{y}, y^*) - \alpha C(a_t)
$$

其中 $U$ 为任务特定效用（如准确率），$C(a_t)$ 为动作 $a_t$ 的计算成本，$\alpha$ 为权衡系数。该设计解决了多轮路由中延迟奖励导致的信用分配难题：早期错误分配会级联影响下游推理质量，而标量预测无法捕捉这种长程依赖。通过 PPO 优化策略，GraphPlanner 直接对齐决策质量而非预测精度，避免了小预测误差导致的排序翻转。

### 异构图 GARNet 的记忆整合

现有路由器将历史交互作为文本摘要或检索片段注入提示，信息密度低且易丢失结构。GraphPlanner 提出 GARNet，将工作流记忆图 $G_{workflow}$ 与历史记忆图 $G_{history}$ 整合为异构图 $G_t = G_{workflow} \cup G_{history}$。节点包括查询嵌入 $x_q$、响应嵌入 $x_r$ 与角色枢纽节点 $x_m = [e_{role}; U; C]$，其中 $x_m$ 拼接 LLM-角色文本嵌入、任务效用与成本。消息传递采用残差连接：

$$
h_v = h_v^{(0)} + \beta \cdot \text{AGG}_{u \in N(v)} h_u^{(0)}
$$

共享的角色枢纽节点作为 $G_{workflow}$ 与 $G_{history}$ 的结构锚点，使当前决策能同时访问局部工作流与累积历史经验。该设计解决了历史记忆利用不足的问题：通过图结构显式编码协作模式（如“Planner 分解后由小模型执行”），路由器能复用成功路径，避免重复探索。

## 实验评估

实验覆盖 6 个领域 14 个任务，基线包括单轮路由器（Router-KNN、RouterDC、GraphRouter）与多轮路由器（R2-Reasoner、Router-R1）。GraphPlanner 在 Phase 2（工作流生成）中平均准确率 63.6%，较 Router-R1 的 51.8% 提升 11.8 个百分点，GPU 成本 605.0 对比 Router-R1 的 76.3，实现性能与成本的双重优化。

| 方法 | Math Acc | Code Acc | CS Acc | WK Acc | Popular Acc | Avg Acc | GPU Cost |
|---|---|---|---|---|---|---|---|
| Router-R1 | 45.3% | 52.0% | 81.2% | 28.6% | 37.2% | 51.8% | 76.3 |
| GraphPlanner | 67.0% | 76.0% | 78.0% | 38.0% | 52.0% | 63.6% | 605.0 |

消融实验显示，替换 GARNet 为 GAT 或 GraphTransformer 后，Math 准确率从 0.670 降至 0.643/0.647，Code 从 0.760 降至 0.739/0.743，表明异构图结构对性能增益有实质贡献。历史记忆处理策略中，GraphPlanner 的图记忆优于 History-retrieval（0.46/0.62/0.73/0.12/0.39）与 History-summary（0.51/0.62/0.75/0.14/0.36），验证了结构化合并优于文本摘要或检索。

评估边界方面，实验使用 12 个 LLM 但仅 3 种角色，未验证角色动态扩展；零样本泛化测试中，AIME 数据集准确率 14.7%，虽高于基线 7.56%，但绝对值偏低，反映竞赛级数学推理的迁移难度。代码已开源，训练使用单张 NVIDIA A6000 GPU，PPO 超参数（$\gamma=0.99, \epsilon=0.2$）已公开，可复现性良好。

## 关联研究分析

从问题动机看，GraphPlanner 与 Router-R1 均针对多轮路由，但 Router-R1 将历史上下文作为序列输入，无法区分查询分支与响应依赖，导致冗余调用；GraphPlanner 通过异构图显式建模协作结构，使路由器能识别“何时分解”“何时总结”，减少无效调用。这一差异源于任务特性：多智能体协作中，子查询间的依赖关系是树状或图状，而非线性序列，序列模型无法有效捕捉这种结构。

从方法设计看，GraphPlanner 与 MoMA 共享智能体角色定义，但 MoMA 采用静态编排（意图识别后固定路由），GraphPlanner 通过 RL 动态生成工作流，适应查询复杂度变化。MoMA 的静态设计在简单任务上高效，但面对复杂查询时无法调整协作深度；GraphPlanner 的 MDP 形式化允许路由器根据当前状态动态选择角色与模型，实现自适应协作。这种动态性是否在所有任务类型上均优于静态编排，论文未提供细粒度对比。

## 总结

GraphPlanner 解决的核心矛盾是多智能体 LLM 协作中，异构模型的能力成本差异与协作结构复杂性之间的失衡。现有单轮/多轮路由器无法显式建模智能体角色与工作流依赖，导致长程任务成本失控；GraphPlanner 通过 MDP 联合决策角色与模型，并用 GARNet 整合历史记忆，使路由决策能感知协作结构与累积经验。实验证明其在 14 个任务上平均准确率提升 9.3%，GPU 成本降低 99.4%。但角色空间固定为 3 种，未验证动态扩展能力；零样本泛化在竞赛级数学任务上准确率仅 14.7%，反映图结构在极端复杂推理上的迁移局限。当模型池规模扩大至 50 个以上时，GARNet 的消息传递开销是否抵消路由效率收益，论文未给出回答。
