# ICLR2026最新论文 ｜ResWorld: Temporal Residual World Model for End-to-End Autonomous Driving ｜时间残差世界模型

研究机构：北京航空航天大学

作者：Jinqing Zhang、Zehua Fu、Zelin Xu 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.10884)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.10884)

> 端到端自动驾驶框架旨在从原始传感器数据直接生成规划轨迹，但现有世界模型在预测未来场景时，往往对静态背景进行冗余建模，且预测结果与轨迹规划缺乏深度交互，导致动态物体预测精度不足。本文切入点在于利用场景表征的时间残差显式分离动态物体信息，并通过未来场景特征反向修正先验轨迹。具体做法是构建时间残差世界模型（TR-World）提取动态分布，并设计未来引导轨迹精炼（FGTR）模块实现轨迹与场景的双向交互。该框架在移除辅助感知任务的前提下实现了SOTA规划精度，但其对多模态不确定性的处理及长尾场景泛化能力仍存疑。

## 研究背景

当自动驾驶系统从模块化感知转向端到端规划时，核心挑战在于如何在不依赖昂贵标注的辅助任务（如3D检测、地图分割）的情况下，准确理解动态交通环境。传统方法通过独立模块提取物体状态，但信息在模块间传递时存在损失。世界模型（World Model）通过预测未来场景表征作为代理任务，旨在增强模型对时空动态的理解，从而直接优化规划性能。然而，场景表征中大部分信息属于静态物体（如地面、建筑），其在未来时刻的空间分布基本不变，无需重复预测；而动态物体（如车辆、行人）的精确建模才是规划安全的关键，且在不依赖检测任务时难以从原始特征中直接分离。

主流端到端框架如UniAD和PARA-Drive依赖大量辅助任务标注，限制了数据利用效率。近期工作如SSR和LAW尝试用世界模型替代辅助任务，但它们通常对整个场景进行统一预测，导致计算资源被静态背景占用，动态物体预测精度受限。此外，现有方法中世界模型预测的未来场景仅作为隐式优化信号，未与轨迹规划模块进行显式交互，无法利用未来环境信息修正潜在碰撞。本文针对这一瓶颈，提出通过时间残差提取动态信息，并建立轨迹与未来场景的显式反馈机制，以在感知无关（perception-free）条件下实现高精度规划。

## 核心方法

### 方法参照系

本文基于SSR的稀疏查询架构，但摒弃其全场景预测范式。标准流程中，世界模型接收当前BEV特征并预测未来完整场景；本文的关键差异在于仅预测动态物体的未来分布，并将静态信息保留在当前特征中，同时引入轨迹对场景特征的显式查询。

### 时间残差动态建模

设计动机在于解决全场景预测中静态物体冗余建模导致的动态信息稀释问题。通常做法是将当前BEV特征直接输入世界模型预测未来，本文改为计算相邻时间戳场景查询的差值以提取动态残差。设当前及历史BEV特征为 $\{B_t, B_{t-1}, ..., B_{t-k}\}$，通过TokenLearner提取稀疏场景查询 $S_i$，时间残差 $R_i$ 定义为 $R_i = S_i - S_{i-1}$。该残差表征同一空间位置在不同时刻的变化，即动态物体信息。TR-World对残差序列进行自注意力聚合得到动态未来表征 $\hat{R}$，再通过TokenFuser将其映射回BEV空间，与融合后的当前BEV特征 $B_{fuse}$ 结合，生成仅包含动态物体未来分布的 $B_{future}$。此设计使模型聚焦于变化量，避免了对不变静态背景的重复计算。

### 未来引导轨迹精炼

设计动机在于解决世界模型预测结果与规划模块解耦、以及缺乏监督导致的模型坍塌问题。通常做法中，轨迹仅由当前场景决定，本文引入先验轨迹 $T_{prior}$ 作为参考点，引导Waypoint Queries对 $B_{future}$ 执行可变形注意力。公式表达为 $T_{final} = MLP(W, B_{future}, T_{prior})$，其中 $W$ 为Waypoint Queries。该操作允许轨迹查询未来场景中自车位置周边的环境信息，验证先验轨迹是否碰撞或偏离可行驶区域，从而修正轨迹。同时，轨迹与未来场景的交互提供了稀疏时空监督信号，迫使世界模型预测具有空间多样性的未来特征，防止其将所有场景映射为相同表征（即模型坍塌）。

## 实验评估

| 方法 | 辅助任务 | L2 Avg (m) ↓ | 备注 |
| :--- | :--- | :--- | :--- |
| SSR | None | 0.74 | 基线 |
| ResWorld | None | 0.65 | 无Ego Status |
| ResWorld♢ | None | 0.59 | 有Ego Status |
| LAW | None | 0.61 | 对比方法 |
| DiffusionDrive | Det&Map | 0.57 | 对比方法 |

在nuScenes基准上，ResWorld在无辅助任务且不使用Ego Status的情况下，平均L2误差为0.65m，优于SSR（0.74m）和LAW（0.61m）。当引入Ego Status时，L2误差降至0.59m，接近依赖检测任务的DiffusionDrive（0.57m）。在NAVSIM闭环评估中，ResWorld使用历史帧数据时PDMS达到89.0%，超越Hydra-MDP（88.1%）和DiffusionDrive（88.1%），验证了时间残差机制在闭环场景下的有效性。

消融实验显示，TR-World与FGTR模块的协同作用显著。仅使用TR-World时，L2误差从基线0.71m降至0.65m；加入FGTR后进一步降至0.59m（有Ego Status）。值得注意的是，对TR-World施加未来真实数据监督反而导致性能下降（L2从0.59m升至0.61m），这是因为固定时间戳的监督限制了模型对未来时段动态分布的独立优化能力。FGTR模块通过可视化验证有效缓解了模型坍塌，其预测的未来BEV特征在空间分布上展现出更高的多样性。

评估边界方面，nuScenes实验基于12 epochs训练，NAVSIM基于100 epochs，均使用8块RTX 3090 GPU。指标主要关注L2误差和PDMS，未报告计算效率（FPS）或推理延迟，这在实时自动驾驶部署中是关键缺失。代码已开源，但超参数配置（如学习率、Batch Size）在不同数据集间差异较大，复现时需严格遵循论文设定。

## 关联研究分析

从问题动机看，ResWorld与SSR、LAW同属感知无关的端到端规划路线，但核心差异在于动态信息的提取方式。SSR和LAW依赖世界模型预测完整未来场景，隐含假设场景整体演化对规划同等重要；ResWorld则基于“静态背景不变”的物理先验，通过时间残差显式分离动态物体。这一差异源于对计算资源分配的不同假设：ResWorld认为静态预测是冗余开销，而SSR认为全场景预测有助于建立完整的时空上下文。在复杂交互场景中，这种分离是否会导致对静态障碍物（如临时路障）的漏检，论文未提供消融证据。

从方法设计看，ResWorld的FGTR模块与DiffusionDrive的扩散规划形成对比。DiffusionDrive通过生成多模态轨迹分布来应对不确定性，而ResWorld采用确定性轨迹修正，依赖未来场景特征提供单一最优路径的反馈。ResWorld的优势在于计算效率更高且无需迭代采样，但其输出为单模态轨迹，缺乏对行为随机性的显式建模。在知识库中，多模态预测被视为处理不确定性的核心机制，ResWorld的确定性输出在长尾场景或高交互密度下，可能因无法覆盖多种潜在行为而导致规划保守或激进，这一局限性在NAVSIM的碰撞率指标中未得到充分区分。

## 总结

ResWorld旨在解决端到端自动驾驶中世界模型冗余建模静态物体及与规划解耦的矛盾。其切入点在于利用时间残差显式分离动态信息，并通过FGTR模块建立轨迹与未来场景的显式交互，从而在移除辅助感知任务的前提下实现高效规划。实验证明，该框架在nuScenes上将L2误差降至0.59m（有Ego Status），在NAVSIM上PDMS达到89.0%，均优于SSR和LAW等感知无关基线。然而，论文实验未报告推理延迟，且FGTR模块的稀疏监督机制在极端遮挡或传感器失效场景下的鲁棒性未经验证。当动态物体密度极高或静态背景发生剧烈变化（如施工区域）时，时间残差假设是否依然成立，论文未给出回答。
