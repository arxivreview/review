# ICLR2026最新论文 ｜BiasBusters: Uncovering and Mitigating Tool Selection Bias in Large Language Models ｜工具选择偏差的量化与缓解

研究机构：英国牛津大学

作者：Thierry Blankenstein、Jialin Yu、Zixuan Li 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.00307)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.00307)

> 工具增强大语言模型（Tool-Augmented LLMs）在调用外部 API 时，常因元数据或位置产生系统性偏好，导致功能等价的服务商竞争失衡。现有研究聚焦于调用准确率与泛化性，却忽视了选择过程中的公平性维度，导致偏差来源不明且缺乏量化标准。本文构建了功能等价 API 集群基准，提出基于总变差距离的偏差度量，并通过元数据扰动与持续预训练实验定位偏差根源，最后提出“筛选-均匀采样”策略进行缓解。该工作填补了工具选择公平性的评估空白，但去偏策略对任务最终成功率的潜在影响尚未被验证。

## 研究背景

当大语言模型面对多个功能等价的 API 时，其选择往往并非基于真实效用，而是受工具名称、描述或列表位置等表层特征驱动。这种非理性偏好被称为工具选择偏差（Tool-Selection Bias），它直接导致用户反复调用低效服务，并在按次计费的市场中造成对特定服务商的不公平倾斜。理解这一偏差需先厘清工具调用的多阶段流程：从大规模工具库中检索候选集，将元数据插入提示词，再由模型推理并选定最终工具。传统研究关注“能否正确调用”，而本文聚焦于“在多个正确选项中，模型为何偏向某一个”。

工具增强范式的主流演进路径是从行为克隆转向基于可验证奖励的强化学习（RLVR），旨在提升模型在分布外任务上的泛化能力与鲁棒性。然而，这些方法均假设工具选择是基于语义相关性的理性决策，未考虑模型内部存在的系统性偏见。现有评估基准如 BFCL 和 ToolBench 主要衡量调用准确率，无法区分“选对了”与“选得公平”。因此，如何量化并解释模型在功能等价工具间的非理性偏好，成为工具生态规模化部署前必须解决的公平性问题。

## 核心方法

### 偏差度量框架

工具选择偏差的量化需区分 API 级偏好与位置级偏好。本文定义工具选择偏差为模型因与真实效用无关的原因而系统性偏好某些 API 的倾向。为了精确度量，本文引入总变差距离（Total Variation Distance, TVD）作为核心指标，将模型的经验选择分布与理想均匀分布进行比较。

$$
\delta_{API} = \frac{1}{2} \sum_{i=1}^{K} |P_i[API] - \frac{1}{K}|
$$

该公式计算模型在集群内各 API 上的选择概率与均匀分布 $1/K$ 之间的偏差总和，$\delta_{API}$ 值越高，表明模型对特定 API 的固化偏好越强。此外，本文还定义了位置偏差 $\delta_{pos}$，用于捕捉模型对列表中靠前位置的依赖，最终通过 $\delta_{model} = \delta_{API} + 2\delta_{pos}$ 综合评估整体偏差水平。

### 偏差归因与去偏策略

在确认偏差存在后，本文通过受控实验定位其根源。设计动机在于区分语义对齐、元数据扰动与预训练暴露对选择行为的不同贡献。实验发现，查询与工具描述的语义相似度是选择的最强预测因子，但仅能解释部分方差（$R^2 < 0.4$）。更关键的是，对工具描述的微小扰动即可显著改变选择分布，且对单一端点的持续预训练（CPT）能放大服务商级偏差。

针对上述发现，本文提出一种轻量级去偏模块，将“识别”与“选择”解耦。该模块首先利用小模型（Qwen3-14B）从候选集中筛选出能解决查询的相关 API 子集，随后在该子集内进行均匀随机采样。

$$
P_{final}(API) = \begin{cases} \frac{1}{|S|}, & \text{if } API \in S \\ 0, & \text{otherwise} \end{cases}
$$

其中 $S$ 为筛选出的相关 API 子集。这一设计通过消除位置与元数据对采样概率的影响，确保每个有效 API 具有相同的被选概率，从而在保持任务覆盖率的同时，从根本上抑制了系统性偏好。

## 实验评估

实验基于自建基准，包含 10 个功能等价 API 集群，每集群 5 个 API 和 100 个查询，共 1,000 个集群-查询对。评估涵盖 GPT-3.5-turbo、GPT-4.1-mini、Claude 3.5 Sonnet、DeepSeek-V3.2-Exp、Gemini 2.5 Flash、ToolLLaMA-2-7B 及 Qwen3 系列模型。基线审计显示，本文未对比 RLVR 类方法（如 Tool-R1），因为偏差研究独立于策略优化，但这也意味着无法评估去偏对复杂多步任务成功率的影响。

| 模型 | $\delta_{API}$ | $\delta_{pos}$ | $\delta_{model}$ |
| :--- | :--- | :--- | :--- |
| Gemini 2.5 Flash | 0.365±.003 | 0.306±.005 | 0.335±.002 |
| Claude 3.5 Sonnet | 0.370±.005 | 0.325±.005 | 0.347±.001 |
| DeepSeek-V3.2-Exp | 0.249±.003 | 0.504±.003 | 0.377±.001 |
| Qwen3 235B | 0.330±.006 | 0.168±.004 | 0.249±.001 |
| ToolLLaMA | 0.277±.002 | 0.391±.002 | 0.334±.002 |
| GPT-3.5-turbo | 0.320±.022 | 0.336±.012 | 0.328±.005 |
| GPT-4.1 mini | 0.331±.008 | 0.423±.002 | 0.377±.004 |

所有模型均表现出显著偏差，$\delta_{model}$ 值在 0.249 至 0.377 之间，意味着约 30%-40% 的选择概率质量需重新分配才能实现公平。Qwen3-235B 偏差最低，而 GPT-4.1-mini 与 DeepSeek-V3.2-Exp 偏差最高。消融实验表明，描述扰动对选择分布的影响远大于名称或参数扰动，Gemini 对元数据变化的敏感度（平均 TV 0.310）高于 GPT-3.5（0.234）。

评估边界方面，本文仅使用 100 个合成查询和 7 个特征维度，且局限于 RapidAPI 的英文工具，可能限制结论的普适性。代码与基准已公开，但去偏策略未报告对任务最终成功率的负面影响，存在“公平性提升以牺牲最优性为代价”的潜在风险。

## 关联研究分析

从问题动机看，本文与 CoHyDE 等检索增强方法形成互补。CoHyDE 关注大规模工具库下的检索精度，旨在通过迭代协同训练提升召回率，其核心假设是“找到最相关的工具”。而本文指出，即使检索到了功能等价的工具，模型在选择阶段仍存在系统性偏差，导致“找对了但选偏了”。这种差异源于任务特性的不同：CoHyDE 解决的是信息获取的效率问题，本文解决的是信息利用的公平性问题。语义匹配在 CoHyDE 中是优化目标，在本文中却是偏差的主要驱动因素，这揭示了语义相似度在工具选择中的双重角色：既是相关性信号，也是偏见来源。

从方法设计看，本文与 Tool-R1 的 RLVR 路线存在根本分歧。Tool-R1 通过强化学习优化策略，旨在提升模型在复杂约束下的泛化能力与任务成功率，其奖励函数聚焦于最终答案的正确性。本文则通过外部模块（筛选+均匀采样）干预选择过程，旨在消除分布偏差。Tool-R1 假设模型可以通过试错学习最优策略，而本文证明模型存在固有的、难以通过训练消除的表层偏好。这种分歧暗示，仅靠优化策略可能无法解决公平性问题，需要引入结构性的去偏机制。然而，均匀采样是否会在复杂多步任务中降低整体性能，因缺乏与 RLVR 方法的直接对比而难以判断。

## 总结

本文旨在解决工具增强 LLM 在功能等价 API 选择中的系统性偏差问题，这一矛盾源于现有研究对“调用准确率”的过度关注而忽视了“选择公平性”。本文通过构建功能等价集群基准，量化了偏差的存在与程度，并证明语义对齐与元数据扰动是主要驱动因素。提出的“筛选-均匀采样”策略在保持任务覆盖率的同时，有效降低了选择偏差。实验显示，所有测试模型均存在显著偏差，其中 Qwen3-235B 表现最佳（$\delta_{model}=0.249$），而 GPT-4.1-mini 偏差最高（$\delta_{model}=0.377$）。本文的边界在于未验证去偏策略对复杂多步任务成功率的潜在负面影响，且评估局限于合成查询与单一语言环境。当工具生态扩展到多语言、动态变化的真实场景时，均匀采样策略是否仍能维持公平性与任务效率的平衡，论文未给出回答。
