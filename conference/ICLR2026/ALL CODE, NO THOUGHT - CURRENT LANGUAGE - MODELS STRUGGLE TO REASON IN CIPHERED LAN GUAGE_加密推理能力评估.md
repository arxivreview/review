# ICLR2026最新论文 ｜ALL CODE, NO THOUGHT: CURRENT LANGUAGE - MODELS STRUGGLE TO REASON IN CIPHERED LAN GUAGE ｜加密推理能力评估

研究机构：Anthropic

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_77181449)

> 思维链（Chain-of-Thought, CoT）监控依赖模型输出可读的中间步骤以检测潜在的对齐失败或恶意行为。现有研究多关注CoT的忠实度或对抗性提示注入，却忽视了模型可能通过“加密推理”——即在非自然语言编码中执行计算——来规避文本监控这一具体风险。本文通过微调与提示10个模型在28种不同加密方案下执行数学推理，量化了模型在加密文本中维持推理能力的边界。该工作揭示了“理解”与“推理”在加密语境下的显著不对称性，为评估前沿模型监控失效风险提供了关键的能力基线，但受限于仅测试了人类设计的静态加密方案，未涵盖模型自主演化出的动态隐写策略。

## 研究背景

CoT监控的有效性建立在模型推理过程以自然语言显式呈现的假设之上。当模型被要求执行多步数学或逻辑任务时，其生成的文本步骤被视为内部计算的“窗口”，监控器通过解析这些文本识别逻辑谬误或恶意意图。然而，若模型能够使用非标准编码（如Base64、ROT13或自定义映射）隐藏推理过程，监控器将面临“不可读”困境。这种能力被称为加密推理（Ciphered Reasoning），它要求模型不仅理解加密文本，更能在加密状态下执行复杂的符号操作与逻辑推导。

当前领域对CoT安全性的研究主要集中在两个方向：一是评估CoT是否忠实反映内部计算（Faithfulness），二是防御针对输入端的对抗攻击（如提示注入）。前者关注“说真话”，后者关注“防干扰”，但均未系统考察模型主动“说暗语”的能力边界。随着强化学习（RL）训练导致模型生成更压缩、更非标准的CoT方言，以及长度效率优化带来的文本压缩压力，模型自发或受诱导地采用低可读性推理格式的风险正在上升。现有监控器在缺乏可读CoT时召回率下降53%（Baker et al., 2025），凸显了评估模型在加密状态下推理能力的紧迫性。本文切入点在于将加密推理视为一种独立的能力维度，而非单纯的攻击向量，通过量化该能力的获取成本与性能代价，为监控系统的鲁棒性设计提供实证依据。

## 核心方法

### 方法参照系

本文问题归属于“推理安全与对抗攻击”范畴，但区别于传统的输入端攻击测试，其核心差异在于评估对象从“模型对恶意输入的响应”转向“模型在特定输出约束下的内生计算能力”。标准流程通常涉及构造对抗样本并测量模型输出变化，而本文采用“能力探针”范式：通过微调或提示模型在特定加密语法下执行任务，测量任务性能相对于明文基线的衰减程度，以此界定模型执行加密推理的能力边界。

### 加密推理能力度量

传统评估仅关注最终答案准确率，但加密推理场景下，模型可能因无法遵循加密指令而直接输出明文，导致“假性正确”。为此，本文引入“依从性”（Adherence）指标，定义为模型响应中符合目标加密语法的比例。最终的能力度量采用相对准确率，即加密条件下的依从且正确回答数与明文基线（Identity）依从且正确回答数之比。该设计动机在于解耦“遵循指令能力”与“推理能力”，避免将模型因未加密而答对的情况误判为具备加密推理能力。

$$
\text{Ciphered Capability} = \frac{\# \text{ciphered adherent \& correct}}{\# \text{identity adherent \& correct}}
$$

该公式表明，能力值1.0代表模型在加密状态下与明文状态表现一致，值越低代表加密对推理能力的损害越大。通过此指标，本文能够区分模型是“无法加密”还是“加密后无法推理”。

### 预训练数据相关性分析

为探究加密推理能力的来源，本文假设该能力依赖于预训练数据中特定加密模式的曝光频率。为此，本文构建了“预训练流行度”（Pretraining Prevalence）指标，通过提取PRM800K数据集中各加密方案的4-gram词组，并利用Infini-gram工具在RedPajama数据集（1.2T tokens）中统计其出现频率。该设计动机在于验证“能力源于数据”的假设，即模型在加密文本上的表现并非源于通用语言理解，而是源于对特定编码模式的记忆。

$$
\text{Prevalence}_C = \sum_{g \in \text{4-grams}(C)} \text{Freq}_{\text{RedPajama}}(g)
$$

其中 $C$ 为特定加密方案，$\text{Freq}$ 为词组在预训练语料中的频率。通过该指标，本文建立了数据分布与模型性能之间的定量联系，为后续的数据缩放定律分析提供了基础变量。

## 实验评估

实验在MATH 500数据集上进行，涵盖10个模型（包括GPT 4.1/5、Claude Sonnet 3.5/4等）和28种加密方案。基线包括明文推理（Identity）和无推理直接回答（Direct Answering）。本文未对比其他CoT忠实度评估方法（如FaithCoT-Bench），因其评估目标不同：本文关注能力边界，而非忠实度检测精度。

| 模型类型 | 加密方案 | 相对准确率 (%) | 备注 |
| :--- | :--- | :--- | :--- |
| GPT 4.1 (微调) | ROT13 | 81+ | 知名加密，损失<19% |
| GPT 4.1 (微调) | Reverse Fibonacci | 28- | 冷门加密，损失>72% |
| Sonnet 3.5/4 (提示) | ROT13/Base64 | 90+ | 知名加密，损失<10% |
| Sonnet 3.5/4 (提示) | Reverse Fibonacci | 55- | 冷门加密，损失>45% |

核心发现是显著的“理解-推理不对称性”：模型在翻译任务（理解）中BLEU分数普遍高于50（流畅），但在推理任务中准确率大幅下降。例如，GPT 4.1在ROT13下损失19%+准确率，而在Reverse Fibonacci下损失高达72%。这表明模型能够解码加密文本，但难以在加密状态下执行复杂的数学推导。

消融实验显示，加密对推理能力的损害主要源于句法和词汇转换，而非风格变化。Qwen2.5 3B在Leet Speak（简单字符替换）下损失28%准确率，而在插入干扰文本（Distractors）下损失较小。此外，数据缩放定律显示，加密推理能力随微调数据量缓慢提升：要使简单加密方案（Letter to Word with Dot）达到明文准确率，需超过3.7B tokens的微调数据。这一高数据需求暗示，当前模型难以通过少量样本快速习得加密推理能力。

评估边界方面，本文仅测试了人类设计的静态加密方案，未涵盖模型可能自主发现的动态隐写策略。指标上，相对准确率未考虑任务难度分布，可能在简单问题上高估能力。可复现性方面，代码已开源，但微调GPT模型的成本高昂，限制了大规模复现。

## 关联研究分析

从问题动机看，本文与Stress-Testing CoT Monitorability（Zolkowski et al., 2025）同属监控鲁棒性评估，但前者关注模型在对抗性提示下的“混淆推理”行为，本文则聚焦于模型在特定编码约束下的“计算能力”衰减。差异根源在于任务特性：Zolkowski等假设模型已具备推理能力，仅测试其隐藏意图的动机；本文则假设模型需先具备在加密状态下推理的能力，才能实施监控规避。这种区分揭示了监控失效的两个独立维度：动机（是否想隐藏）与能力（能否隐藏）。

从方法设计看，本文与FaithCoT-Bench（Shen et al., 2025）均涉及CoT与内部状态的关系，但FaithCoT-Bench通过反事实干预评估CoT是否“真实”驱动答案，本文则通过加密约束评估CoT是否“有效”执行计算。FaithCoT-Bench关注“说真话”的忠实度，本文关注“说暗语”的能力边界。这一差异暗示，即使CoT是忠实的（Faithful），若其以加密形式呈现，监控器仍可能失效。本文未直接评估加密CoT的忠实度，而是假设加密推理本身即为一种“不透明”状态，这与机制可解释性路线（如Circuit-Guided Discrepancy）形成互补：后者试图通过内部激活揭示真实计算，本文则通过外部行为界定计算能力的极限。

## 总结

本文核心矛盾在于CoT监控依赖可读性，而模型可能通过加密推理规避监控。现有方法未量化模型执行加密推理的能力边界，本文通过微调与提示实验，揭示了“理解”与“推理”在加密语境下的不对称性：模型能翻译加密文本，但难以在加密状态下维持数学推理准确率。核心证据显示，知名加密（如ROT13）导致GPT 4.1损失19%+准确率，冷门加密损失高达72%，且习得该能力需3.7B tokens微调数据。本文边界在于仅测试了静态、人类设计的加密方案，未涵盖模型自主演化的动态隐写策略，也未评估加密CoT的忠实度。当模型通过强化学习自发演化出非标准CoT方言时，其加密推理能力是否会突破本文测得的数据缩放定律，从而在无需大量微调的情况下实现监控规避？
