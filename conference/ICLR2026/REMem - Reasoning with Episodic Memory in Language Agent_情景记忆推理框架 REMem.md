# ICLR2026最新论文 ｜REMem: Reasoning with Episodic Memory in Language Agent ｜情景记忆推理框架 REMem

研究机构：美国俄亥俄州立大学

作者：Yiheng Shu、Saisri Padmaja Jonnalagedda、Xiang Gao 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.13530)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.13530)

> 语言智能体长期依赖语义记忆范式，导致其无法在时空轴上精确重构具体事件并进行跨事件逻辑推理。现有方法或丢失连贯情境，或仅做简单相似度匹配，缺乏显式的事件建模与复杂推理能力。REMem 通过构建包含时间感知摘要与事实的混合记忆图，并引入代理式多步工具调用推理，解决了这一瓶颈。该框架在时间推理基准上取得突破，但其在通用对话记忆任务上的表现仍落后于当前最先进系统，且多步推理带来的计算开销尚未被充分量化。

## 研究背景

当智能体需要回答“上周三下午在公园发生了什么”这类问题时，它必须将时间、地点、参与者等情境维度绑定到具体的事件实例上，这一能力被称为情景记忆（Episodic Memory）。与存储通用概念和知识的语义记忆不同，情景记忆依赖于对特定经历的重构，是智能体实现个性化持续学习的基础。然而，当前大语言模型（LLM）的记忆系统主要基于参数化权重或扁平向量检索，前者缺乏对具体经验的上下文锚定，后者则脱离了时空语境，导致智能体难以区分“发生过的事”与“知道的事”。

现有非参数化记忆系统试图通过知识图谱或摘要来改进检索，但大多侧重于结构化世界知识而非交互特定的经历。例如，Mem0 和 Graphiti 虽然引入了图结构，但前者通过选择性丢弃细节来简化记忆，后者以实体为中心构建时间图谱，均丢失了连贯的事件上下文。HippoRAG 2 虽支持关联检索，但缺乏对时间维度的显式建模。这些方法的共同缺陷在于缺乏显式事件建模，无法将时间、地点、参与者等情境维度整合到交互历史中，导致在需要跨事件关系、序数约束或极值查询的复杂推理任务中表现不佳。REMem 的切入点正是填补这一空白，将记忆形式化为时间感知的事件表示，并赋予智能体在记忆图上执行复杂逻辑组合的能力。

## 核心方法

### 混合记忆图构建

REMem 的索引阶段将原始话语转化为混合记忆图，该图同时包含概念层（Concept-level）和上下文层（Context-level）信息。设计动机在于解决单一表示无法兼顾事件整体叙事与细粒度事实关联的问题。对于每个事件陈述，系统首先提取 Gist（摘要），即带有解析后绝对时间戳的原子事件描述，涵盖参与者、动作、对象、地点等情境维度。随后提取 Fact（事实），表示为带有 Wikidata 风格限定符（point_time, start_time, end_time）的三元组 $(s, p, o)$。

$$
G = (V_g, V_f, E_c, E_s)
$$

其中 $V_g$ 为 Gist 节点集合，$V_f$ 为短语节点集合，$E_c$ 为概念层边（连接事实中的主客体），$E_s$ 为同义词边（连接嵌入相似度超过阈值 $\tau=0.8$ 的 Gist 节点）。这种混合结构确保了 Gist 提供连贯的情境背景，而 Fact 提供精确的时间锚点，二者通过图结构相互链接，支持从宏观叙事到微观事实的双向检索。

### 代理式推理机制

推理阶段采用 ReAct 风格的代理式推理（Agentic Inference），取代了传统 RAG 的一次性静态检索。设计动机在于解决简单语义匹配无法处理时间范围过滤、邻居探索等复杂逻辑组合的问题。代理配备三类工具：检索工具（semantic_retrieve, lexical_retrieve）、图探索工具（find_gist_contexts, find_entity_contexts）和流控制工具（output_answer）。

$$
\mathcal{A}_{t+1} = \mathcal{T}(\mathcal{A}_t, \mathcal{M}, q)
$$

其中 $\mathcal{A}_t$ 为第 $t$ 步的代理状态，$\mathcal{T}$ 为工具调用函数，$\mathcal{M}$ 为混合记忆图，$q$ 为查询。代理通过迭代调用工具，例如先通过语义检索获取种子节点，再使用 find_entity_contexts 结合时间条件（如 start_time < "17 Jan 2024"）过滤相关事实，最终在置信度足够时输出答案。这种机制实现了“心理时间旅行”（Mental Time Travel），即根据时间条件动态过滤记忆条目，从而支持跨事件的时序推理。

## 实验评估

实验在 LoCoMo、REALTALK、Complex-TR 和 Test of Time 四个基准上进行，对比了 Qwen3-Embed-8B、NV-Embed-v2、Mem0、Graphiti、HippoRAG 2 等基线。REMem-I（迭代式）在情景推理任务上表现显著，尤其在 Test of Time 上取得 93.1% 的精确匹配（EM）分数，是唯一超过 90% 的方法。

| 方法 | LoCoMo (LLM-J) | Complex-TR (LLM-J) | Test of Time (EM) |
| :--- | :--- | :--- | :--- |
| NV-Embed-v2 | 73.0 | 80.4 | 68.9 |
| Mem0 | 49.7 | 41.0 | - |
| HippoRAG 2 | 74.0 | 81.5 | 66.9 |
| REMem-I | 76.2 | 89.6 | 93.1 |

消融实验显示，移除 Gist 导致 LoCoMo 上的 LLM-J 从 76.2 降至 48.9，表明 Gist 承载了主要的情境元素；移除 Fact 则对 Complex-TR 影响较小（89.6 降至 87.2），说明 Fact 主要起辅助多跳推理的作用。值得注意的是，REMem-I 在 LoCoMo 上的表现（76.2）低于领域综述中提到的 MemCog（95.8），这可能源于 LoCoMo 中跨会话问题占比仅 14.2%，单步检索的 REMem-S 在某些场景下更具优势，而迭代式推理在简单任务上可能引入额外噪声。

评估边界方面，论文使用 GPT-4.1-mini 作为默认 LLM，未报告不同骨干模型下的性能差异。代码已开源，但多步推理的最大步数（3 或 5）基于小验证集选择，缺乏对步数敏感性的详细分析。此外，论文未量化代理式推理带来的延迟增加，尽管其 token 消耗（9k）远低于 Full-Context（26k），但计算时间的效率对比缺失。

## 关联研究分析

从问题动机看，REMem 与 HippoRAG 2 均致力于解决扁平向量检索丢失结构关系的问题，但二者对“结构”的定义存在根本差异。HippoRAG 2 侧重于实体间的语义关联，通过个性化 PageRank 实现多跳推理，其图结构是静态的知识网络。而 REMem 强调“时间感知的事件建模”，其图结构是动态的时间轴，Gist 和 Fact 均绑定绝对时间戳。这一差异源于任务特性的不同：HippoRAG 2 面向通用知识问答，而 REMem 面向情景记忆，后者要求精确的时间定位和序数推理。REMem 引入的同义词边机制虽借鉴自 HippoRAG 2，但其阈值设定（0.8）和连接对象（Gist 节点）均服务于事件聚类而非实体链接。

从方法设计看，REMem 与 Mem0 在记忆管理策略上形成鲜明对比。Mem0 采用“选择性记忆”策略，通过 LLM 判断丢弃不重要的细节，以简化记忆库。REMem 则选择保留所有潜在矛盾的记录，包括 Gist 和 Fact，以支持历史回溯和完整性。这一设计选择反映了两种不同的哲学：Mem0 追求记忆的简洁性和高效性，而 REMem 追求记忆的丰富性和可追溯性。在大规模场景下，REMem 的保留策略可能导致检索噪声增加，而 Mem0 的丢弃策略可能导致关键细节丢失。论文未探讨这两种策略在记忆库规模扩大时的性能权衡，也未分析矛盾记录对检索精度的具体影响。

## 总结

REMem 旨在解决语言智能体在情景记忆上的核心矛盾：如何在保持高效检索的同时，实现记忆与推理的深度交织，并建立可验证的安全与隐私保障。其切入点在于显式事件建模，通过混合记忆图将时间、地点、参与者等情境维度绑定到具体事件，并通过代理式推理实现复杂逻辑组合。实验证明，REMem 在 Test of Time 上取得 93.1% 的 EM 分数，显著优于基线，验证了时间感知事件建模的有效性。然而，其在 LoCoMo 上的表现（76.2）低于当前 SOTA（95.8），暴露了迭代式推理在简单任务上的潜在劣势。当记忆库规模扩大且包含大量矛盾记录时，REMem 的检索精度是否会因噪声增加而下降，论文未给出回答。
