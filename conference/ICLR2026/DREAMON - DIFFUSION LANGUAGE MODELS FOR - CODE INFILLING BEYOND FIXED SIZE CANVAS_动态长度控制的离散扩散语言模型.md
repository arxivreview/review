# ICLR2026最新论文 ｜DREAMON: DIFFUSION LANGUAGE MODELS FOR - CODE INFILLING BEYOND FIXED SIZE CANVAS ｜动态长度控制的离散扩散语言模型

研究机构：快手、北京大学

作者：Zirui Wu、Lin Zheng、Zhihui Xie 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_89186530)

> 扩散语言模型（DLMs）在代码填充任务中因固定长度掩码限制而严重受损，当预定义掩码长度与真实解长度不匹配时，性能平均下降38%。现有DLM无法动态调整输出长度，导致过生成或欠生成。本文提出DREAMON，通过引入[expand]和[delete]两个特殊状态，使模型在去噪过程中自主伸缩序列长度，无需架构修改。该方法在HumanEval-Infilling上平均提升26.4%，达到或超越同级自回归模型，但其有效性是否泛化至非代码任务仍存疑。

## 研究背景

代码填充要求模型根据前后文生成缺失片段，解的长度在不同样本间差异巨大。自回归模型通过重排目标片段至序列末端来适配填充任务，破坏了自然上下文结构且需专用提示。扩散语言模型（DLMs）通过多步去噪实现任意顺序生成，天然适合填充，但当前实现强制要求输入输出序列长度一致，即使用固定长度掩码画布。这一约束导致DLM无法动态确定输出长度，当掩码长度与真实解长度偏差较大时，模型要么因空间不足而生成不完整代码，要么因空间冗余而生成无关代码片段。

离散扩散语言模型（DLMs）的核心瓶颈在于变长生成的长度偏差。主流掩码扩散范式（如MDLM）在固定长度画布上操作，训练目标与推理过程均假设序列长度恒定。这种假设在代码生成中尤为致命，因为函数体、循环体等结构的长度高度可变。DreamCoder-7B等现有DLM在HumanEval-Infilling上因长度不匹配导致性能显著下降，暴露了固定长度画布对实际部署的阻碍。本文切入点在于打破长度固定约束，使DLM具备原生长度控制能力，从而在保留双向上下文优势的同时解决变长生成的核心障碍。

## 核心方法

### 掩码扩散参照系

标准离散掩码扩散模型定义前向过程 $q(\mathbf{x}_t | \mathbf{x}_0) = \alpha_t \mathbf{x}_0 + (1 - \alpha_t) \text{[mask]}$，逆向过程学习 $p_\theta(\mathbf{x}_{t-1} | \mathbf{x}_t)$ 以恢复数据。训练采用加权交叉熵损失，仅在掩码位置计算。该框架假设序列长度 $N$ 恒定，所有去噪步骤在固定维度向量空间进行。本文问题与该通用流程的关键差异在于：需允许序列长度在去噪过程中动态变化，同时保持扩散过程的马尔可夫性与训练目标的稳定性。

### 增强状态与长度控制

为突破固定长度限制，本文在词表中引入两个特殊状态：[expand] 和 [delete]。设计动机在于解决固定画布无法适配变长输出的失效。前向增强过程从原始序列 $\mathbf{x}_0$ 构建增强潜变量 $\mathbf{z}_0$，通过合并随机token跨度为[expand]并插入[delete]，实现序列长度的随机扰动。逆向去噪时，模型预测[expand]则将其扩展为两个[mask]，预测[delete]则移除该位置。训练损失需校准[delete]与[mask]的权重失衡，因每个[delete]对应单个[mask]，而多个[mask]合并为一个[expand]。加权损失定义为：

$$
\mathcal{L}(\theta) = \sum_{n=1}^{N} w_n \mathbb{1}[\mathbf{z}_{t,n} = \text{[mask]}] \cdot \text{CE}(p_\theta(\cdot | \mathbf{z}_t), \mathbf{z}_{t-1,n})
$$

其中 $w_n$ 为每token权重，确保[delete]预测的总权重与单个[mask]预测相当。此设计使模型在标准扩散目标下学习长度控制，无需架构修改。

### 动态推理与删除广播

推理阶段，模型每步预测所有掩码位置，并根据预测熵选择性去噪。关键创新在于直接控制每步去噪的掩码数量 $n$，而非使用固定调度器，以支持动态长度建模。当预测[expand]时立即扩展，预测[delete]时移除。为防止无限增长，设置最大长度 $L_{max}$。此外，引入“删除广播”机制：当预测[delete]时，若其右侧所有token均为[mask]，则一并移除。该机制加速收敛，将生成步数减少2.1倍，且无需额外训练。此设计解决了初始掩码长度与目标长度差异大时，模型需多次前向传播调整长度的低效问题。

## 实验评估

实验基于DreamCoder-7B和DiffuCoder-7B微调，在HumanEval-Infilling（单行/多行）和SantaCoder-FIM上评估。基线覆盖自回归模型（Qwen2.5-Coder-7B、Deepseek-Coder-6.7B）和扩散模型（LLaDA-8B、Dream-7B）。DREAMON在HumanEval-Infilling单行Pass@1达92.1%，多行达79.0%，平均绝对提升26.4%。与Qwen2.5-Coder-7B（多行59.3%）相比，DREAMON在多行任务上显著领先，证明动态长度机制对复杂代码结构的适配优势。

| 模型 | HumanEval-Infilling Single-line (Pass@1) | HumanEval-Infilling Multi-line (Pass@1) | SantaCoder-FIM (EM) |
| :--- | :--- | :--- | :--- |
| Qwen2.5-Coder-7B | 92.6 | 59.3 | 79.8 |
| DreamCoder-7B | 55.5 | 45.0 | 59.3 |
| DreamCoder-7B + DREAMON | 92.1 | 79.0 | 63.8 |
| DiffuCoder-7B + DREAMON | 92.2 | 73.8 | 58.0 |

消融实验显示，移除[delete]导致长掩码性能骤降，移除[expand]损害短掩码性能，证实两者互补。损失平衡机制至关重要，移除后平均Pass@1降至84.6%。删除广播机制提升效率2.1倍，且对性能影响微小（-0.6%）。合并调度器方面，静态与动态逆调度器1:1混合效果最佳，单一调度器在特定长度区间表现受限。

评估边界方面，实验仅聚焦代码填充，未验证通用文本变长生成。指标限于Pass@1和Exact Match，缺乏多样性或鲁棒性评估。可复现性良好，提供代码仓库，训练仅需8 H800 GPU约5小时，计算量仅为预训练的0.15%。超参数如 $L_{max}=128$、温度0.2已明确，便于复现。

## 关联研究分析

从问题动机看，DREAMON与Fast-dLLM均关注DLM推理效率，但路径迥异。Fast-dLLM通过KV缓存和并行解码加速固定长度生成，解决“慢”的问题；DREAMON通过动态长度控制解决“错”的问题，即长度不匹配导致的性能下降。两者互补而非竞争，Fast-dLLM可应用于DREAMON的固定长度阶段以进一步加速。差异根源在于任务特性：代码填充对长度敏感度远高于通用文本生成，故长度控制成为首要瓶颈。

从方法设计看，DREAMON与Block Diffusion均涉及块级处理，但Block Diffusion固定块大小，仅改变解码顺序；DREAMON动态调整块内token数，改变序列结构。DREAMON的[expand]/[delete]机制本质上是序列长度的在线优化，而Block Diffusion是静态分块策略。与LLaDA等基线相比，DREAMON证明动态长度可弥补固定画布的性能短板，但LLaDA未探索长度自适应，故无法直接对比。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

DREAMON解决的核心矛盾是DLM固定长度画布与变长代码生成需求之间的冲突。现有方法因无法动态调整长度而在长度不匹配时性能骤降，本文通过引入[expand]和[delete]特殊状态，使模型在去噪过程中自主伸缩序列，无需架构修改。实验证明该方法在HumanEval-Infilling上平均提升26.4%，多行任务超越Qwen2.5-Coder-7B。边界在于评估仅限代码填充，未验证通用文本变长生成，且删除广播机制在极端长度差异下的稳定性未充分探讨。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
