# ICLR2026最新论文 ｜BOAD: Discovering Hierarchical Software Engineering Agents via Bandit Optimization ｜基于多臂老虎机优化的层级化软件工程智能体自动发现

研究机构：美国麻省理工学院

作者：Iris Xu、Guangtao Zeng、Zexue He 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2512.23631)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2512.23631)

> 软件工程智能体在长程任务中因单链推理累积无关上下文而泛化能力受限，现有手动设计的多智能体系统依赖人工直觉且难以适应大语言模型（LLM）的实际行为。本文切入点在于将智能体架构发现重构为在线决策问题，通过多臂老虎机（MAB）机制自动探索子智能体组合。该方法在分布外基准上验证了层级化架构的泛化优势，但其跨模型迁移能力与协调开销的量化评估仍存疑。

## 研究背景

软件工程智能体解决真实 GitHub Issue 时，需处理定位、编辑、测试等子任务，每个子任务仅依赖部分信息。单智能体在单一推理链中保留全部历史交互，导致无关上下文引入虚假相关，使模型在分布外任务上性能退化。为缓解此问题，层级化强化学习（HRL）通过时间抽象将长程任务分解为子策略，但传统 HRL 依赖预定义的动作空间，而软件工程环境中的子任务边界是动态且未知的。

当前主流路线分为两类：一是手动设计多智能体系统，如 AgentForge 和 Agyn，通过预定义角色（规划、编码、测试）分工协作，但人工分解常与 LLM 实际推理行为错位，导致工作流失效；二是单智能体加记忆机制，如 SWE-MeM，通过外部存储缓解上下文爆炸，但缺乏对子任务间依赖关系的显式建模。本文针对手动设计的僵化性与单智能体的上下文冗余，提出自动化发现层级化架构，将架构设计本身转化为可优化的决策问题，而非依赖先验知识定义角色。

## 核心方法

### 层级化智能体架构参照系

本文问题可置于 HRL 的时间抽象框架下：编排器（Orchestrator）选择子智能体（Sub-agent）作为选项（Option），每个子智能体执行特定子任务直至完成，控制权返回编排器。与标准 HRL 的关键差异在于，子智能体不是预定义的固定策略，而是从候选池中动态发现的可复用技能单元，且发现过程需在高评估成本约束下高效进行。

### 多臂老虎机优化框架

传统联合搜索（如进化算法）需评估所有子智能体组合，计算成本随子智能体数量指数增长。BOAD 将子智能体发现重构为 MAB 问题：每个臂对应一个候选子智能体 $\omega_i$，奖励为其在协作中的贡献度。UCB 策略平衡探索与利用，选择 Top-K 子智能体组成团队进行评估。

$$
\text{UCB}_\omega(t) = \hat{\mu}_\omega(t-1) + \sqrt{\frac{2 \ln t}{n_\omega(t-1)}}
$$

该公式中，第一项为子智能体的历史平均贡献度，第二项为未充分探索的乐观奖励，确保算法在有限预算内高效发现有效子智能体。设计动机在于解决组合爆炸问题：通过线性增长搜索空间（而非指数），使自动发现在高评估成本的软件工程任务中可行。

### 事后信用分配机制

团队成功无法直接归因于单个子智能体，存在“搭便车”问题：某子智能体可能因与强子智能体共现而显得有效。BOAD 引入事后信用分配，使用 LLM-as-a-judge 评估每个子智能体在轨迹中的实际贡献，而非依赖二元成功/失败信号。

$$
u_\omega = \frac{1}{|T_\omega[t]|} \sum_{\tau \in T_\omega[t]} \text{LLMJudge}(\omega, \tau)
$$

该公式计算子智能体 $\omega$ 在第 $t$ 轮所有参与轨迹 $\tau$ 中的平均贡献度，由 LLM 基于行为轨迹评估。设计动机在于解决信用分配模糊性：通过细粒度贡献度信号，避免强子智能体掩盖弱子智能体的缺陷，使 MAB 能准确识别真正有用的子智能体。

## 实验评估

实验在 SWE-bench Verified（500 个验证 Issue）和 SWE-bench Live（分布外近期 Issue）上进行，基线覆盖单智能体（SWE-agent）、手动多智能体（Manual Sub-agent）及进化搜索（Evolutionary Search）。

| 模型 | 脚手架 | Verified Resolved (%) | Live Resolved (%) |
|---|---|---|---|
| Seed-OSS-36B-Instruct | SWE-agent (baseline) | 49.8 | 12.3 |
| Seed-OSS-36B-Instruct | SWE-agent + Manual Sub-agent | 47.4 | 14.0 |
| Seed-OSS-36B-Instruct | SWE-agent + Evolutionary Search | 46.0 | 17.0 |
| Seed-OSS-36B-Instruct | SWE-agent + BOAD | 53.2 | 20.0 |

BOAD 在 Live 基准上取得 20.0% 解决率，较基线提升 63%，超越 GPT-4o（10.0%）和 DeepSeek-V3（13.3%）等大模型系统。消融实验显示，事后信用分配（helpfulness）比成功率（success rate）选择更优：Top-2 子智能体在 helpfulness 下达 20.0%，而 success rate 下仅 15.3%。子智能体数量存在非单调性：Top-2 优于 Top-3（16.3%）和 Top-5（13.7%），表明过多子智能体引入协调噪声。

评估边界方面，论文未报告置信区间，且 Live 基准的分布外特性可能放大架构优势。可复现性上，代码已开源，但超参数（如 UCB 探索系数、CRP 浓度参数 $\theta$）未详细披露，跨模型迁移实验仅用 Claude 3.7 Sonnet 验证，未覆盖更多骨干网络。

## 关联研究分析

从问题动机看，BOAD 与 Agyn 均解决多智能体协调问题，但 Agyn 依赖经理协调固定工作流，角色分工由人工定义，而 BOAD 自动发现子智能体，摆脱了对人工直觉的依赖。差异根源在于任务特性：软件工程子任务边界动态变化，人工预定义角色难以适应 LLM 实际行为，而 MAB 的在线探索能发现非显而易见的有效组合。

从方法设计看，BOAD 与 SWE-RL 均利用执行反馈优化智能体，但 SWE-RL 通过强化学习更新单智能体策略，而 BOAD 通过 MAB 优化多智能体架构。差异在于优化对象：SWE-RL 假设架构固定，优化策略；BOAD 假设策略可复用，优化架构。当子任务间依赖关系复杂时，固定架构可能限制泛化能力，而动态发现的层级化架构能更好地解耦子任务，但 MAB 的探索-利用平衡是否足以应对非平稳环境分布，论文未给出回答。

## 总结

本文核心矛盾在于单智能体上下文冗余与手动多智能体僵化性的冲突。BOAD 抓住的切入点是架构发现的可优化性：通过 MAB 将组合搜索转化为线性探索，通过事后信用分配解决团队归因模糊性。实验证明，自动发现的层级化架构在分布外任务上比单智能体提升 63%（Live 基准 20.0% vs 12.3%），比手动多智能体提升 43%（20.0% vs 14.0%）。边界在于，子智能体跨模型迁移仅部分有效，且编排器无条件接受子智能体输出导致错误传播。当子智能体数量超过 2 时，性能反而下降，表明协调开销随团队规模非线性增长，MAB 的探索预算是否足以在更大设计空间中维持这种效率，论文未给出回答。
