# ICLR2026最新论文 ｜ScaleCUA: Scaling Open-Source Computer Use Agents with Cross-Platform Data ｜跨平台数据管道与统一动作空间驱动的开源计算机使用智能体

作者：Zhaoyang Liu、Jingjing Xie、Zichen Ding 等 30 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.15221)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.15221)

> 计算机使用智能体（Computer Use Agent, CUA）旨在通过像素级截图自主操作数字设备，其核心瓶颈在于高质量交互轨迹数据的稀缺与跨平台泛化能力的缺失。现有方案或依赖封闭专有数据集，或局限于单一平台，导致模型在异构环境中的迁移性能显著下降。本文切入点在于构建覆盖六大操作系统的交互式数据管道，并设计统一动作空间以标准化异构环境交互。通过双循环数据合成与端到端监督微调，ScaleCUA在接地与理解任务上取得开源SOTA，但其在长程动态任务上的表现仍受限于纯监督微调范式，缺乏强化学习带来的错误恢复机制。

## 研究背景

当智能体面对Windows、Android与Web等异构界面时，其底层交互逻辑存在本质差异——这一现象称为界面异构性。界面异构性导致单一动作空间无法直接映射到所有平台，而实际部署中往往需要跨平台通用能力，这恰好构成了统一动作空间设计的条件：将点击、输入等核心操作抽象为平台无关的语义指令，同时保留平台特定动作的扩展接口。解决此类问题的经典框架是模块化智能体，它通过规划器与接地器的分离实现功能解耦，但受制于推理延迟与错误累积，难以应对长程任务。

GUI智能体领域长期面临数据稀缺与标注成本高的双重困境。主流路线分为两类：一是基于提示工程的模块化框架，如ReAct与Reflexion，通过组合通用大语言模型与外部工具实现任务执行，但受限于推理延迟与错误累积，难以处理多步规划；二是原生模型驱动路线，通过大规模监督微调（SFT）训练端到端策略，如UI-TARS与SeeClick，但现有工作多依赖单一平台数据或专有数据集，跨平台泛化能力不足。本文的切入点在于，通过构建覆盖Windows、macOS、Linux、Android、iOS与Web六大平台的交互式数据管道，结合自动智能体探索与人类专家标注的双循环机制，生成大规模跨平台训练语料，并设计统一动作空间以消除异构环境间的交互不一致性，从而在开源条件下实现通用计算机使用智能体的规模化训练。

## 核心方法

### 方法参照系

本文问题属于原生模型驱动路线，其标准流程为：基于视觉-语言模型（VLM）骨干，通过大规模GUI截图与指令对进行监督微调，使模型直接从像素输入生成可执行动作。本文与该通用流程的关键差异在于，其训练数据并非来自单一平台或静态截图，而是通过动态交互式管道生成的跨平台轨迹，且动作空间经过统一抽象以支持异构环境间的无缝迁移。

### 双循环交互式数据管道

数据管道的设计动机在于解决现有数据集在覆盖范围与质量间的失衡：纯自动探索产生大量噪声轨迹，纯人工标注成本高昂且难以规模化。本文在数据收集环节引入双循环机制，其中Agent-Environment Interaction Loop通过规则驱动的随机游走智能体执行深度优先搜索（DFS），在每一步从可用动作空间中随机选择动作并应用启发式剪枝，以最大化GUI状态覆盖；Agent-Human Hybrid Data Acquisition Loop则整合专家标注的领域特定目标轨迹，确保数据质量与任务多样性。该管道的数据生成过程可形式化为：

$$
\mathcal{D} = \mathcal{D}_{auto} \cup \mathcal{D}_{human}, \quad \mathcal{D}_{auto} = \{ (s_t, a_t, s_{t+1}) \mid a_t \sim \pi_{DFS}(s_t) \}
$$

其中 $\mathcal{D}_{auto}$ 为自动探索生成的轨迹集合，$\pi_{DFS}$ 为基于深度优先搜索的策略，$\mathcal{D}_{human}$ 为专家标注轨迹。这一设计带来的具体改进是，在保持数据规模可扩展性的同时，通过人工标注弥补自动探索在高层目标语义上的缺失，最终生成包含471K GUI理解样本、17.1M接地样本与19K任务完成轨迹的跨平台语料。

### 统一动作空间与多模式推理

统一动作空间的设计动机在于解决异构平台间动作语义不一致导致的泛化障碍。本文在动作表示环节将核心操作（如click、write）抽象为平台无关的语义指令，同时保留平台特定动作（如mobile的long_press、open_app）作为扩展，形成跨平台统一控制模式。该设计使模型能够在学习核心行为的同时保留环境特定动作的灵活性，简化了数据标注与下游策略学习。在此基础上，ScaleCUA支持三种推理模式：接地模式（Grounding Mode）仅定位UI元素，直接动作模式（Direct Action Mode）直接生成低层可执行动作，推理动作模式（Reasoned Action Mode）在生成动作前显式输出思维链。直接动作模式的输出格式为：

$$
\hat{a}_t = f_\theta(s_t, h_{t-1}, I_t) \in \mathcal{A}_{unified}
$$

其中 $f_\theta$ 为模型参数，$s_t$ 为当前屏幕观测，$h_{t-1}$ 为历史上下文，$I_t$ 为任务指令，$\mathcal{A}_{unified}$ 为统一动作空间。这一设计带来的具体改进是，通过消除中间推理步骤的token消耗，降低推理延迟，同时通过低层指令的自然语言描述维持多步交互的上下文连贯性，使模型在实时任务中实现高效的感知-动作循环。

## 实验评估

实验在MMBench-GUI、ScreenSpot-V2、ScreenSpot-Pro、OSWorld-G、AndroidControl、OSWorld、WindowsAgentArena、MacOSArena与WebArena-Lite-v2等基准上进行，基线覆盖UI-TARS、Qwen2.5-VL、GPT-4o、Claude-3.7等开源与专有模型，但缺失MobileRL、UI-S1等强化学习方法。

| 基准 | 方法 | 指标 | 数值 |
| :--- | :--- | :--- | :--- |
| MMBench-GUI L1-Hard | ScaleCUA-32B | Overall | 94.4 |
| ScreenSpot-V2 | ScaleCUA-32B | Avg | 92.4 |
| ScreenSpot-Pro | ScaleCUA-32B | OS Avg | 59.2 |
| OSWorld-G | ScaleCUA-32B | Overall | 60.6 |
| WebArena-Lite-v2 | ScaleCUA-32B | 50 Steps | 47.4 |

ScaleCUA-32B在MMBench-GUI L1-Hard上取得94.4%的准确率，较GPT-4o的93.3%高出1.1个百分点；在ScreenSpot-V2上取得92.4%的平均点击准确率，较UI-TARS-7B的91.6%高出0.8个百分点。在WebArena-Lite-v2的50步预算下，ScaleCUA-32B取得47.4%的成功率，较UI-TARS-7B-SFT的26.0%高出21.4个百分点，显示出跨平台数据合成在网页导航任务上的显著增益。

消融实验显示，数据增强对接地性能有正向影响：Qwen2.5-VL-3B在ScreenSpot-Pro上，使用数据增强后准确率从37.8%提升至41.3%。坐标类型消融表明，原始坐标（Raw）比归一化坐标（Norm.）在ScreenSpot-Pro上表现更优（42.3% vs 37.9%），暗示归一化过程可能引入精度损失。通用能力保持实验显示，ScaleCUA-3B在75%通用数据比例下，MathVista-MINI得分59.3%，较0%通用数据的52.8%提升6.5个百分点，但较基座Qwen2.5-VL-3B的62.3%下降3.0个百分点，表明GUI专用训练对通用视觉-语言能力存在轻微负迁移。

评估边界方面，本文所有模型均在纯视觉观测下评估，未使用Accessibility Tree或DOM等结构化数据，符合领域共识但限制了与结构化方法的直接对比。在线基准的步数预算设置不一（AndroidWorld为预定义步数，其他为15或50步），且多数结果未报告置信区间。代码与模型已开源，但数据管道的具体超参数（如DFS剪枝阈值、专家标注比例）未在正文中详细披露，可能影响可复现性。

## 关联研究分析

从问题动机看，ScaleCUA与SeeClick（Cheng et al., 2024）均聚焦视觉接地数据基础，但SeeClick局限于单一平台静态截图，而ScaleCUA通过双循环管道生成跨平台动态轨迹，其数据规模（17.1M接地样本）远超SeeClick的763K元素。这一差异的根源在于任务特性：SeeClick的目标是提升单步定位精度，而ScaleCUA的目标是跨平台通用操作，后者需要更丰富的状态覆盖与动作多样性。ScaleCUA与UI-TARS（Qin et al., 2025）同属原生模型路线，但UI-TARS依赖专有数据集，而ScaleCUA完全开源，其数据管道设计（自动探索+人工标注）与UI-TARS的纯自动探索形成对比，前者在数据质量上更具优势，但计算成本更高。

从方法设计看，ScaleCUA与MobileRL（据领域综述）在训练范式上存在根本差异：MobileRL采用在线强化学习，通过环境交互获取奖励信号以优化长程任务策略，而ScaleCUA仅使用监督微调，缺乏错误恢复机制。这一差异导致ScaleCUA在OSWorld上取得29.7%的成功率（50步），显著低于MobileRL的80.2%（据领域综述），表明纯SFT在动态环境中的局限性。ScaleCUA与OS-Atlas（Xie et al., 2024）同属接地模型，但OS-Atlas专注于桌面平台，而ScaleCUA通过统一动作空间覆盖六大平台，其跨平台泛化能力更强，但在单平台深度优化上可能不及专用模型。

## 总结

ScaleCUA要解决的核心矛盾是GUI智能体训练数据的跨平台稀缺性与模型泛化能力不足。本文抓住的切入点在于，通过双循环交互式数据管道生成大规模跨平台轨迹，并设计统一动作空间消除异构环境间的交互不一致性，从而在开源条件下实现通用计算机使用智能体的规模化训练。本文构建了覆盖六大平台的17.1M接地样本与19K任务轨迹语料，训练出支持三种推理模式的ScaleCUA模型，在MMBench-GUI L1-Hard上取得94.4%的准确率，在WebArena-Lite-v2上取得47.4%的成功率。本文的边界在于，其纯监督微调范式缺乏强化学习带来的错误恢复机制，导致在OSWorld等动态长程任务上的表现显著落后于RL方法；同时，数据管道中自动探索与人工标注的比例对最终性能的影响未通过消融实验量化。当数据管道中人工标注比例降低时，自动探索产生的噪声轨迹是否会导致模型在长程任务上的错误累积加剧，论文未给出回答。
