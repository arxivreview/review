# ICLR2026最新论文 ｜EventFlash: Towards Efficient MLLMs for Event-Based Vision ｜事件流多模态大语言模型的高效时空稀疏化

研究机构：西安电子科技大学、清华大学

作者：Shaoyu Liu、Jianing Li、Guanghui Zhao 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.03230)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.03230)

> 事件相机视觉感知需处理微秒级异步数据流，但现有基于多模态大语言模型（MLLM）的方法将其转化为密集帧或体素，导致计算冗余与长序列推理瓶颈。EventFlash 针对这一效率瓶颈，提出密度感知的时空 Token 稀疏化策略，在保留事件物理特性的同时压缩 Token 体积。该方法通过自适应时间窗口聚合与稀疏密度引导注意力实现 12.4 倍吞吐量提升，支持 1000 个时间 bins 的长程理解。其价值在于突破了事件 MLLM 的实时性限制，但缺乏跨数据集泛化验证，且稀疏化对语义完整性的影响未获定量评估。

## 研究背景

事件相机通过记录像素级亮度变化生成异步事件流，其微秒级时间分辨率与高动态范围（HDR）特性使其在高速运动与低光照场景下优于传统帧相机。然而，事件流仅包含相对亮度变化，缺乏绝对光照与语义信息，且其稀疏异步特性与依赖规则网格的稠密深度学习架构存在根本不兼容。多模态大语言模型（MLLM）在处理常规帧与语言时表现优异，但直接处理事件流需先将其转换为密集图像表示，这一过程引入了大量冗余 Token，限制了长序列理解的效率与扩展性。

事件视觉领域早期聚焦于将事件流转换为体素网格或帧以适配卷积神经网络，虽降低了开发门槛，但牺牲了时间保真度并产生计算冗余。随着 MLLM 的引入，研究重心转向利用生成式先验解决语义缺失，但现有事件 MLLM（如 EventGPT、EventVL）仍依赖密集图像式处理范式，导致在长事件序列上推理延迟高、吞吐量低。EventFlash 的切入点在于利用事件流固有的时空稀疏性，通过 Token 稀疏化策略直接处理原始事件流，而非先密集化再处理，旨在解决时间效率、空间效率与数据集局限三大挑战。

## 核心方法

### 方法参照系

事件 MLLM 的标准流程是将事件流转换为密集体素或帧，经视觉编码器提取特征后与文本 Token 对齐，输入 LLM 解码器。EventFlash 的关键差异在于在视觉编码器前引入时空稀疏化模块，直接对原始事件流进行自适应压缩，避免密集化带来的冗余计算，同时保留微秒级时间分辨率与空间稀疏特性。

### 自适应时间窗口聚合（ATWA）

ATWA 模块解决事件流微秒级分辨率导致的 Token 体积过大问题。传统方法将事件流均匀分箱，但固定分箱在低活动区域产生大量空 Token。ATWA 首先将事件流划分为细粒度 bins，基于极性感知时空点过程的强度函数 $\lambda_B$ 计算相邻 bins 的相似度距离 $D(B_i, B_{i+1}) = \|\lambda_{B_i} - \lambda_{B_{i+1}}\|_2$。当距离低于阈值 $\tau$ 时，迭代合并相邻 bins 形成元事件窗口。随后，通过事件编码器提取每个窗口的 CLS Token 表示 $z_i$，计算语义相似度 $S_i$，并结合归一化事件密度因子 $r_i$ 计算密度感知合并分数 $A_i = S_i \cdot \exp(-\alpha \cdot r_i)$。该公式表明，语义相似且事件密度低的窗口优先合并，从而在保留关键运动动态的同时压缩时间维度 Token 数量。

### 稀疏密度引导注意力（SDGA）

SDGA 模块解决事件流空间分布不均导致的空 Token 计算开销问题。传统自注意力机制对所有 Patch 均匀分配计算资源，但事件流中大量区域无事件或事件密度极低。SDGA 对每个聚合后的事件 bin，通过 ViT 编码器提取 Patch 级特征，并引入密度编码单元计算每个 Patch 的事件密度。在多头自注意力机制中，密度信息被融入 Key 向量，使得高信息量区域（高事件密度或高语义显著性）的 Token 获得更高注意力权重，而空或低密度区域的 Token 被抑制。该设计通过动态选择信息丰富区域，减少无效 Token 的参与，提升空间维度的计算效率。

## 实验评估

EventFlash 在自建 EventMind 数据集（500k 指令集）上评估，对比基线包括 EventGPT（事件 MLLM）及 Qwen2.5-VL、VideoChat2-Flash 等视频 MLLM。基线覆盖事件与视频两类路线，但缺乏 E2VID、Voxel Grid 等底层表征基线，且未包含其他事件 MLLM 如 EventVL。主实验显示，EventFlash-7B 在 EventMind 上 GDC 74.1、FGQA 79.5、HAQA 87.6、MCQA 63.1，优于 EventGPT-7B 的 71.2 与 78.2（仅 GDC 与 FGQA 可比），且吞吐量达 28.5 tokens/s，为基线 EventFlash-Zero（2.3 tokens/s）的 12.4 倍。

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| EventGPT-7B | 7B | 5 | 42.2 | – | – | – | – |
| EventFlash-Zero | 3B | 1,000 | 2.3 | 45.3 | 60.4 | 85.0 | 58.2 |
| EventFlash-3B | 3B | 1,000 | 28.5 | 46.8 | 61.1 | 84.9 | 60.0 |
| EventFlash-7B | 7B | 1,000 | 24.0 | 52.3 | 64.2 | 87.6 | 63.1 |

消融实验表明，时间稀疏化单独贡献 6.1 倍加速（14.0 tokens/s），空间稀疏化单独贡献 2.3 倍加速（5.3 tokens/s），两者结合实现 12.4 倍加速。聚合间隔从 5ms 增至 30ms 时，吞吐量从 15.8 提升至 63.3 tokens/s，但 GDC 从 47.1 降至 36.8，表明时间分辨率与效率存在权衡。密度衰减因子 $\alpha$ 从 0.1 增至 0.4 时，FGQA 与 MCQA 保持稳定，但 GDC 与 HAQA 下降，说明依赖时序细节的任务对稀疏化更敏感。

评估边界方面，EventMind 为自建数据集，缺乏 DSEC、N-Caltech101 等标准基准验证，泛化性存疑。指标仅涵盖 GDC、FGQA、HAQA、MCQA，未包含重建保真度（PSNR/SSIM）或 3D 几何精度。代码未公开，超参数（如 $\tau$、$\alpha$）固定，可复现性受限。

## 关联研究分析

从问题动机看，EventFlash 与 Spiking Patches 均关注事件稀疏性，但 Spiking Patches 侧重 Transformer 原生适配，通过异步稀疏注意力降低计算复杂度，而 EventFlash 侧重 MLLM 输入端的 Token 压缩，通过密度感知合并减少 Token 数量。差异根源在于任务特性：Spiking Patches 面向分类/分割等底层任务，需保留细粒度时空特征；EventFlash 面向高层语义理解，可容忍部分时间精度损失以换取长序列处理能力。EventFlash 未探索 Spiking Patches 的异步注意力机制，是否结合两者可进一步提升效率，论文未给出回答。

从方法设计看，EventFlash 与 REALM 均涉及跨模态对齐，但 REALM 采用潜空间对齐/蒸馏弥合事件与 RGB 模态鸿沟，而 EventFlash 仅通过 Event-Language Projector 对齐事件与文本空间，未利用 RGB 参考帧。差异根源在于数据可用性：REALM 依赖高质量 RGB 教师模型，适合数据充足场景；EventFlash 仅使用事件流，适合无 RGB 辅助的纯事件场景。EventFlash 未评估引入 RGB 模态对语义完整性的影响，在纹理缺失场景下，纯事件稀疏化是否导致语义退化，论文未给出回答。

## 总结

EventFlash 解决的核心矛盾是事件流微秒级时间分辨率与 MLLM 长序列推理效率之间的冲突。现有方法通过密集化适配 MLLM，但引入冗余 Token 限制长程理解；EventFlash 抓住事件流固有的时空稀疏性，通过 ATWA 与 SDGA 模块直接压缩原始事件流，实现 12.4 倍吞吐量提升与 1000 bins 长程处理。实验证明其在 EventMind 上保持可比精度，但边界在于自建数据集缺乏跨域验证，且稀疏化对依赖时序细节的任务（GDC、HAQA）存在性能损失。当事件流密度极低或场景动态剧烈时，ATWA 的合并阈值 $\tau$ 是否需动态调整以避免关键运动信息丢失，论文未给出回答。
