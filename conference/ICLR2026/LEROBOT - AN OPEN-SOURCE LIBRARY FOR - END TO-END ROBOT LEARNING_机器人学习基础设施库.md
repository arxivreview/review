# ICLR2026最新论文 ｜LEROBOT: AN OPEN-SOURCE LIBRARY FOR - END TO-END ROBOT LEARNING ｜机器人学习基础设施库

研究机构：Hugging Face、英国牛津大学

作者：Remi Cadene、Simon Alibert、Francesco Capuano 等 17 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_44103865)

> 机器人学习生态因硬件接口碎片化与数据格式不统一而阻碍了算法的可复现性与规模化应用。现有工具链通常针对特定机器人定制，导致研究资源大量消耗在系统集成而非核心算法创新上。本文提出 LeRobot，一个垂直整合的开源库，通过统一中间件、标准化数据集格式及异步推理栈，打通从数据采集到策略部署的全链路。该工作降低了入门门槛并促进了社区数据共享，但其价值主要体现为工程基础设施而非算法性能突破，且对世界模型等复杂动力学预测架构的支持仍显薄弱。

## 研究背景

机器人控制正从依赖解析式物理方程的显式模型转向基于数据驱动的隐式模型。显式模型在结构化环境中有效，但难以应对非结构化动态场景中的接触力学复杂性，且扩展至新场景需大量专家手工调参。隐式模型通过端到端学习直接映射观测到动作，其性能随数据规模与算力增加而提升，这要求底层基础设施能高效处理大规模多模态交互数据。

主流机器人学习算法如行为克隆（BC）与强化学习（RL）已展现出强大潜力，但生态碎片化严重。中间件通常绑定特定硬件，数据集缺乏通用模式，导致不同实验室的贡献难以复用。例如，TensorFlow Datasets 与 ROS bags 等格式互不兼容，阻碍了跨本体数据的聚合。这种碎片化使得研究者需重复开发底层接口，分散了对核心算法优化的精力。

LeRobot 的切入点在于构建一个垂直整合的开源栈，解决上述工程瓶颈。它不追求单一算法的 SOTA 性能，而是通过统一 Python 中间件 API、定义 LeRobotDataset 标准格式以及优化推理延迟，使低成本机器人（如 SO-10X）与大规模预训练模型（如 $\pi_0$）能在同一框架下运行。这一设计旨在将机器人学习从“手工定制”推向“标准化复用”，加速真实世界数据的积累与算法迭代。

## 核心方法

### 统一中间件与数据标准化

LeRobot 的核心在于消除硬件与数据层的异构性。传统做法中，每个机器人需独立的驱动脚本，数据以私有格式存储。本文引入统一的 Python 中间件，直接对接 FeeTech 与 Dynamixel 等低成本执行器 SDK，实现跨平台遥操作与策略控制。数据层定义 LeRobotDataset 格式，支持高频传感器读数、多路相机流及遥操作状态信号的自包含存储。该格式内置元数据（如任务描述、本体参数、帧率），并原生支持流式读取，允许用户在不下载完整语料的情况下处理远程大规模数据集。这一设计解决了数据孤岛问题，使 16K+ 数据集与 2.2K+ 贡献者能在同一生态中协作。

### 异步解耦推理架构

针对大模型推理延迟与控制频率不匹配的问题，LeRobot 提出物理与逻辑双重解耦的推理栈。物理上，推理进程运行于远程高算力机器，通过流式传输动作块至机器人端；逻辑上，采用异步生产者-消费者模式，推理进程以超前视野 $H$ 并行预测动作序列，控制进程以固定频率消费动作。重叠预测通过聚合函数 $f$ 合并，确保动作队列非空。该机制解决了 $\pi_0$ 等大模型在嵌入式设备上无法实时推理的瓶颈，使策略预测与低层控制并行执行，提升了部署鲁棒性。

$$
a_{t:t+H-1} = \text{Infer}(o_t, \theta)
$$

其中 $a_{t:t+H-1}$ 为预测的动作块，$o_t$ 为当前观测，$\theta$ 为策略参数。控制循环以频率 $\omega_c$ 消费动作，推理进程以频率 $\omega_i$ 更新预测，$\omega_i < \omega_c$ 但通过重叠聚合保证实时性。

## 实验评估

LeRobot 的实验重点在于验证基础设施的可行性与效率，而非算法性能对比。实验覆盖 ACT、Diffusion Policy、$\pi_0$ 及 SmolVLA 等主流策略，在 MacBook Pro M1、RTX 4090 及 A100 上测试峰值内存与推理延迟。基线覆盖 BC 与 RL 范式，但缺乏世界模型类基线（如 DreamerV3），这反映了其作为通用工具链的定位，而非针对特定算法路线的优化。

| 模型 | 参数量 | A100 峰值内存 | A100 平均推理延迟 (ms) |
| :--- | :--- | :--- | :--- |
| ACT | 52M | 211.24 MB | 13.77 ± 0.445 |
| Diffusion Policy | 263M | 1.12 GB | 613.893 ± 10.173 |
| $\pi_0$ | 3.5B | 13.32 GB | 568.978 ± 2.937 |
| SmolVLA | 450M | 1.75 GB | 278.833 ± 1.886 |

数据显示，轻量级模型 ACT 在 A100 上实现 13.77ms 的低延迟，适合实时控制；而 $\pi_0$ 虽参数量大，但推理延迟与 Diffusion Policy 相当，表明其计算瓶颈不在参数量而在架构复杂度。CPU 与 MPS 后端因内存交换导致延迟波动，凸显了硬件解耦的必要性。

评估边界方面，论文未报告 LIBERO 或 MetaWorld 上的任务成功率，仅展示推理效率。这意味着无法直接判断集成算法的性能是否因工程化而受损。可复现性得益于开源代码与标准数据集，但缺乏超参数细节与 GPU 配置的统一规范，跨平台复现仍需用户自行调整。

## 关联研究分析

从问题动机看，LeRobot 与 Dreamer 系列（Hafner et al., 2020）形成鲜明对比。Dreamer 聚焦于潜空间动力学预测以提升样本效率，其核心贡献在于算法层面的“想象”机制；而 LeRobot 聚焦于工程层面的“落地”机制，解决的是数据碎片化与硬件异构性问题。两者并非竞争关系，而是互补：Dreamer 提供了高效的学习范式，LeRobot 提供了部署该范式的标准化环境。然而，LeRobot 对世界模型的支持仅限于作为黑盒算法集成，未针对长时程预测误差累积等核心科学问题提供特定优化，这暗示其在处理复杂动力学任务时可能缺乏针对性。

从方法设计看，LeRobot 的异步推理栈与 TD-MPC（Hansen et al., 2022）的模型预测控制存在本质差异。TD-MPC 在决策时进行实时 MPC 计算，计算开销随规划时域增加而线性增长，限制了实时性；LeRobot 通过预计算动作块与异步执行，将计算开销摊薄到控制周期之外。这种设计牺牲了部分在线适应性，换取了部署稳定性。对于需要高频动态调整的任务（如快速避障），这种预计算模式可能引入滞后，论文未对此进行量化评估，仅强调其在静态或慢速任务中的优势。

## 总结

LeRobot 旨在解决机器人学习生态中硬件接口碎片化与数据格式不统一导致的复现性难题。其切入点在于构建垂直整合的开源栈，通过统一中间件与标准化数据集，将研究重心从系统集成转移至算法创新。该库实现了从低成本遥操作到大规模预训练模型部署的全链路支持，验证了 ACT 在 A100 上 13.77ms 的推理延迟与 $\pi_0$ 在 13.32GB 内存下的可行性。然而，其边界在于缺乏对任务成功率的量化评估，且对世界模型等复杂动力学架构的支持仍停留在黑盒集成层面。当面对需要长时程预测与实时动态调整相结合的复杂操作任务时，异步预计算架构的滞后性是否成为性能瓶颈，论文未给出回答。
