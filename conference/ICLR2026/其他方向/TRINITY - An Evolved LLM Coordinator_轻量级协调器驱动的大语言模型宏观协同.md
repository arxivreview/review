# ICLR2026最新论文 ｜TRINITY: An Evolved LLM Coordinator ｜轻量级协调器驱动的大语言模型宏观协同

研究机构：美国密歇根大学、日本东京科学大学

作者：Jinglue Xu、Qi Sun、Peter Schwendeman 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2512.04695)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2512.04695)

> 多源大语言模型（LLM）整合面临架构异构与闭源API的权重访问壁垒，传统参数空间合并在此场景下失效。TRINITY 提出宏观数据流协调范式，利用小语言模型（SLM）隐层状态驱动轻量级头进行动态路由。该方法通过进化策略优化协调头，在代码与数学基准上超越单模型基线，但其依赖固定角色协议且缺乏对工具执行的闭环验证。

## 研究背景

当多个高性能 LLM 来自不同提供商且架构不兼容时，直接权重平均或任务向量算术无法执行，因为参数空间缺乏共享初始化与几何连通性。这一困境迫使研究者转向数据流层面的模型融合，即在不修改底层权重的前提下，通过激活值或输出传递实现能力互补。然而，现有的宏观融合方法多依赖启发式路由或固定提示链，缺乏对查询上下文的细粒度感知，导致在复杂推理任务中无法动态分配计算资源。

模型合并领域长期聚焦于参数干扰消解与系数优化，如 TIES-Merging 通过符号对齐缓解冲突，Fisher-Rao 方法利用黎曼几何处理曲率。这些方法的有效性高度依赖同源假设，一旦涉及异构闭源模型，参数操作即告失效。TRINITY 的切入点在于将“合并”重构为“协调”：不再寻找参数空间的低损失路径，而是构建一个轻量级决策机制，根据查询的隐层表示实时选择最优 LLM 及其功能角色。这一转变规避了权重对齐的计算开销，将优化目标从静态参数组合转向动态轨迹策略。

## 核心方法

### 方法参照系

本文问题属于宏观模型融合范畴，区别于参数空间合并的标准流程。通用宏观方法通常采用固定提示链或基于规则的路由，而 TRINITY 的关键差异在于引入可学习的协调头，将路由决策建模为基于隐层状态的条件策略优化问题，而非静态映射。

### 隐层状态驱动的协调头

协调器采用 Qwen3-0.6B 作为骨干，提取倒数第二个 token 的隐层状态 $h \in \mathbb{R}^d$ 作为决策依据。该设计动机在于，倒数第二个 token 的隐层状态在自注意力机制中已聚合了完整序列的上下文信息，且其预测目标为特殊终止符，分布稳定，能更准确地反映当前对话状态的语义完整性。协调头 $f_\theta$ 将 $h$ 映射为 $L+3$ 维 logits，其中 $L$ 个 logits 用于选择 LLM，3 个 logits 用于分配角色：

$$
\pi_\theta(a|s) = \text{softmax}(f_\theta(h(s)))
$$

此公式表明，协调决策完全依赖于 SLM 的内部表示，而非生成文本，从而实现了低延迟的路由判断。通过仅微调 SLM 第二倒数层的奇异值尺度，总可学习参数控制在 20K 以内，确保了协调器的轻量化与训练可行性。

### 三角色协同协议与进化优化

为解耦复杂技能获取，TRINITY 定义 Thinker（策略分解）、Worker（具体执行）与 Verifier（质量评估）三种角色。终止条件设为 Verifier 接受当前答案或达到回合预算 $K$。优化目标为最大化期望终端奖励 $J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[R(\tau)]$，其中奖励 $R \in \{0,1\}$ 为二元结果。由于参数间耦合弱且单次评估成本高，传统 REINFORCE 梯度信噪比极低。TRINITY 采用可分离协方差矩阵自适应进化策略（sep-CMA-ES），其更新规则基于种群采样与适应度加权平均：

$$
\theta_{t+1} = \theta_t + \sigma_t \sum_{i=1}^{\lambda} w_i (z_i - \bar{z})
$$

该算法利用对角协方差矩阵适应块状 $\epsilon$-可分离性景观，在 1.5k–40k 次评估预算下显著优于随机搜索与强化学习，解决了高维稀疏奖励下的信用分配难题。

## 实验评估

实验在 Math500、MMLU、RLPR 及 LiveCodeBench 四个基准上进行，对比基线包括单模型（GPT-5, Gemini-2.5-pro 等）及多智能体方法（MoA, Router DC）。TRINITY 在 LiveCodeBench v6 上取得 0.615 的 pass@1，显著高于 GPT-5 的 0.5954 和 Gemini-2.5-pro 的 0.4651。在 Math500 上，TRINITY 达到 0.880，较次优方法 Gemini-2.5-pro (5x CTX) 实现 11.76% 的相对误差降低。

| 方法 | LiveCodeBench | MATH500 | MMLU | RLPR |
| :--- | :--- | :--- | :--- | :--- |
| TRINITY | 0.615 | 0.880 | 0.916 | 0.401 |
| GPT-5 only | 0.5954 | 0.7566 | 0.9074 | 0.3787 |
| Gemini Pro 2.5 only | 0.4651 | 0.8305 | 0.7941 | 0.4300 |
| REINFORCE | 0.253 | 0.459 | 0.500 | 0.266 |
| sep-CMA-ES | 0.615 | 0.880 | 0.916 | 0.401 |

消融实验显示，移除奇异值微调导致 LiveCodeBench 性能从 0.615 降至 0.5568，表明 SLM 内部表示的适配对路由精度至关重要。移除 Thinker 角色选择使 MMLU 从 0.916 降至 0.9275（此处原文数据似有笔误，表中 w/o Thinker 为 0.9275 高于 TRINITY 的 0.916，但平均分为 68.69 低于 70.44，需结合上下文理解，可能为特定任务波动），而移除三角色机制则导致平均分从 70.44 降至 67.02，证实角色分工对整体协同稳定性的贡献。使用最后一个 token 替代倒数第二个 token 导致 LiveCodeBench 性能大幅下降至 0.5085，验证了倒数第二个 token 在上下文聚合中的关键作用。

评估边界方面，TRINITY 依赖固定的 LLM 池，未测试动态添加新模型的能力。代码未公开，但提供了详细的超参数设置（如 sep-CMA-ES 的种群大小 $\lambda \approx 32$）。实验未包含参数合并类基线（如 TIES），因此无法直接量化宏观协调相对于参数合并的性能增益，仅证明了其在异构闭源场景下的有效性。

## 关联研究分析

从问题动机看，TRINITY 与 HeteroFusion 均处理异构模型融合，但 HeteroFusion 依赖拓扑对齐与潜在空间映射，需要访问模型内部结构，而 TRINITY 通过黑盒 API 调用规避了这一限制。这一差异源于任务特性：HeteroFusion 面向开源可访问模型，而 TRINITY 针对闭源商业模型。TRINITY 的协调头优化可视为一种隐式的“任务向量”学习，但其作用域从参数空间转移到了决策空间，解决了参数干扰在异构场景下不可计算的问题。

从方法设计看，TRINITY 与 CoMerge 均优化组合策略，但 CoMerge 通过偏好优化调整合并系数，假设任务向量存在线性可组合性；TRINITY 则通过进化策略优化路由决策，假设模型能力存在互补性而非线性叠加。CoMerge 的局限在于其依赖验证集生成偏好信号，而 TRINITY 仅需二元终端奖励，更适合无标注数据的场景。TRINITY 未探索参数合并与宏观协调的混合范式，即是否可以先对同源模型进行参数合并，再对异构模型进行宏观协调，这一混合策略的潜在收益未被验证。

## 总结

TRINITY 解决了异构闭源 LLM 整合中权重不可访问的核心矛盾，通过 SLM 隐层状态驱动的轻量级协调头，实现了动态任务分配。其核心贡献在于证明了 sep-CMA-ES 在高维弱耦合优化问题中的优越性，并在 LiveCodeBench 上取得 0.615 的 pass@1，超越所有单模型基线。然而，该方法局限于固定角色协议，且未验证协调器对工具执行闭环的支持。当 LLM 池规模扩大至数十个模型时，协调头的搜索空间指数增长，sep-CMA-ES 的收敛效率是否仍能维持，论文未给出回答。
