# ICLR2026最新论文 ｜HUME: MEASURING THE HUMAN-MODEL PERFORMANCE GAP IN TEXT EMBEDDING TASKS ｜人类评估框架：量化嵌入任务中的人机性能差距

研究机构：美国斯坦福大学、丹麦奥胡斯大学

作者：Adnan El Assadi、Isaac Chung、Roman Solomatin 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.10062)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_93463174)

> 文本嵌入模型在检索与推荐中依赖 MTEB 等基准进行排名，但现有分数缺乏人类性能参照，导致高分可能源于拟合噪声标签而非真实语义能力。HUME 通过多标注者实验量化了 16 个 MTEB 数据集上的人类表现，发现人类平均得分 77.6%，低于最佳模型的 80.1%，但在低资源语言任务上显著优于模型。该框架揭示了部分基准数据集存在严重的标注歧义，并证明当前 LLM 尚无法完全替代人类判断。其价值在于为基准可靠性提供了诊断工具，但受限于小样本标注与单一标注者协议，结论的普适性存疑。

## 研究背景

嵌入模型将变长文本映射为固定维度向量，其性能通常通过 MTEB 等基准上的自动化指标（如 MAP、Accuracy）衡量。然而，这些指标以理论最大值为参照，假设任务结果存在完美共识。当任务本身包含固有歧义时，模型的高分可能仅反映了对噪声标签模式的拟合，而非语义理解的进步。这种“盲优化”风险使得分数难以解释：一个在重排序任务上达到 0.85 MAP 的模型，其表现究竟优于还是劣于人类标注者？

主流评估路线长期依赖自动化指标，缺乏人类性能基线。TREC 等检索基准收集人类相关性判断，但仅作为金标准而非在模型指标下的人类性能基准；GLUE 等基准报告人类基线，但主要限于分类任务，未覆盖嵌入特有的聚类与语义相似度任务。这导致 MTEB 分数缺乏上下文解释力。HUME 的切入点在于将人类表现视为诊断信号而非上限，通过多标注者一致性分析识别任务质量缺陷，并直接对比模型与人类在相同实例上的表现，从而区分“真实能力”与“噪声拟合”。

## 核心方法

### 基于 MTEB 协议的人类评估参照系

HUME 构建于 MTEB 框架之上，复用其 16 个数据集与评估指标，但将评估主体从模型扩展至人类标注者。与标准 MTEB 流程不同，该方法要求标注者使用与模型完全一致的指标（如重排序用 MAP，分类用 Accuracy）计算性能，确保人机结果可直接比较。这一设计的关键差异在于引入多标注者一致性分析，将标注者间的分歧量化为任务质量指标，而非简单取多数投票作为金标准。

### 多标注者一致性诊断与 LLM 代理评估

针对 MTEB 缺乏人类基线的问题，HUME 引入任务适配的一致性度量作为数据质量诊断工具。对于分类任务，使用 Fleiss' kappa ($\kappa$) 衡量标注者间的一致性；对于聚类任务，使用成对调整兰德指数 (ARI)；对于语义相似度 (STS) 与重排序任务，使用 Spearman 相关系数 ($\rho$)。一致性指标不仅量化人类表现的离散度，更用于识别任务歧义：当 $\kappa < 0.4$ 或 $\rho < 0.6$ 时，表明任务定义存在根本性模糊，模型的高分可能源于拟合噪声。

$$ \text{Human Performance} = \frac{1}{N} \sum_{i=1}^{N} \text{Metric}_i(\text{Annotator}_i, \text{Gold}) $$

该公式计算人类在 $N$ 个任务实例上的平均性能，其中 $\text{Metric}_i$ 为任务特定指标。与模型评估不同，人类性能需结合一致性指标解读：高一致性下的高分代表可靠能力，低一致性下的高分则可能反映标签噪声。

为评估 LLM 作为人类代理的可行性，HUME 在相同任务实例上测试 9 个 LLM（GPT-5, GPT-4.1, Gemini 等），使用与人类标注者相同的指令与评分协议。LLM 在分类与 STS 任务上接近人类表现，但在重排序任务上显著落后，表明 LLM 难以捕捉人类在高一致性任务上的细微相关性判断。这一发现揭示了 LLM 作为标注代理的系统性偏差，尤其在需要细粒度语义区分时。

## 实验评估

实验在 16 个 MTEB 数据集上进行，覆盖重排序、分类、聚类与 STS 四类任务，语言包括英语、阿拉伯语、俄语、挪威语与丹麦语。基线包含 13 个嵌入模型，参数规模从 22M 到 7B，架构涵盖编码器与解码器，但缺失 2026 年最新 SOTA 模型（如 KaLM-Embedding-V2），可能影响人机差距的最新解读。

| 任务类别 | 人类平均性能 | 最佳模型性能 | 人类一致性指标 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 重排序 | 87.2 (MAP) | 96.4 | $\rho$ = 0.64–0.85 | 高一致性，可靠基准 |
| 分类 | 70.3 (Acc) | 87.1 | $\kappa$ = 0.39–0.55 | 低一致性任务存在歧义 |
| 聚类 | 67.4 (V-measure) | 85.1 | ARI = -0.001–0.91 | ArXiv 任务歧义严重 |
| STS | 83.2 (Spearman) | 88.5 | $\rho$ = 0.58–0.77 | 俄语子集性能骤降 |

人类整体排名第 4（77.6），低于 3 个大型模型但高于 10 个较小模型。在阿拉伯语语义相似度任务上，人类表现（67.5%）显著优于最佳模型（40.9%），差距达 26.6 个百分点，揭示模型在低资源语言上的文化语境理解缺陷。LLM 标注实验中，最佳 LLM（GPT-4.1-mini）平均得分 76.1%，低于人类 81.2%，在重排序任务上差距达 10 个百分点，表明 LLM 无法可靠替代人类进行高一致性任务的标注。

评估边界受限于小样本标注（每任务 30–50 条）与单一标注者协议（多语言任务仅 1 名标注者），可能无法代表 MTEB 全量数据的分布特性。代码与数据已开源，但标注者均为男性 NLP 从业者，年龄 20–35 岁，文化多样性有限，可能引入标注偏差。

## 关联研究分析

从问题动机看，HUME 与 MTEB 基准本身形成互补而非替代关系。MTEB 关注模型性能的横向比较，HUME 则聚焦评估基准的纵向可靠性。与 TREC 等检索基准不同，HUME 将人类判断转化为嵌入任务的可比指标（如 MAP），而非仅作为金标准。这一差异源于嵌入任务的特性：嵌入模型在向量空间中的距离计算与人类的相关性判断存在本质映射关系，使得人机直接比较成为可能。然而，HUME 未探讨嵌入空间几何性质（如各向异性）与人类一致性之间的关联，这一盲区可能限制其对模型内部机制的解释力。

从方法设计看，HUME 的 LLM 代理评估与 LLM-as-Judge 范式存在显著差异。LLM-as-Judge 通常用于生成任务的质量评估，而 HUME 将其应用于判别式嵌入任务，发现 LLM 在重排序任务上的系统性偏差。这一差异源于生成式 LLM 与判别式评估任务之间的架构不匹配：LLM 擅长生成连贯文本，但不擅长进行细粒度的相关性排序。HUME 未探索混合标注策略（如 LLM 初筛 + 人类复核），这一未探索的方向可能影响其在大规模基准开发中的实用性。

## 总结

HUME 要解决的核心矛盾是 MTEB 分数缺乏人类参照导致的解释力缺失。其切入点在于将人类表现视为诊断信号，通过多标注者一致性分析识别任务歧义，而非简单设定人类上限。方法上，HUME 复用 MTEB 协议，引入任务适配的一致性指标，并对比 13 个模型与 9 个 LLM 的表现。实验证明人类平均得分 77.6%，低于最佳模型 80.1%，但在阿拉伯语 STS 任务上以 67.5% 显著优于最佳模型的 40.9%。其边界在于小样本标注与单一标注者协议，可能限制结论的普适性。当标注样本量扩大至全量 MTEB 数据时，人类一致性指标是否仍能稳定识别任务歧义，论文未给出回答。
