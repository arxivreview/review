# ICLR2026最新论文 ｜NON-COLLABORATIVE USER SIMULATORS FOR TOOL AGENTS ｜非协作用户模拟器与工具智能体鲁棒性评估

研究机构：韩国首尔大学

作者：Jeonghoon Shim、Woojung Song、Cheyon Jin 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.23124)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_31925671)

> 工具智能体在真实部署中需应对非协作用户，但现有评估基准仅覆盖协作场景，导致模型在真实交互中的脆弱性被掩盖。本文通过构建包含四类非协作行为的用户模拟器，揭示了主流大语言模型在任务执行中的显著性能退化。其核心在于将用户行为异质性模块化，并引入目标对齐机制确保评估有效性。该工作填补了微观交互鲁棒性评估的空白，但缺乏对模型内在偏差与交互压力诱导偏差的区分机制。

## 研究背景

工具智能体通过多轮对话解析用户意图并执行 API 调用，其性能评估长期依赖静态数据集或简化的协作用户模拟器。协作用户模拟器假设用户始终提供完整、清晰且配合的信息，这与真实世界中用户可能表现出急躁、偏离主题或表达不完整的行为存在根本差异。这种假设导致评估结果高估了智能体在复杂交互环境下的鲁棒性，无法反映其在面对非标准输入时的实际表现。

现有工具智能体评估体系主要聚焦于任务完成度，如 MultiWOZ 和 τ-bench 等基准，但其用户模拟器均基于提示工程实现协作行为，缺乏对非协作行为的建模。主流路线通过增加对话轮次或引入复杂 API 依赖来提升难度，但未触及用户行为本身的异质性。这种局限使得研究者难以区分智能体失败是源于模型能力不足，还是源于对用户非标准行为的处理能力缺失。本文切入点在于将用户行为解耦为独立的非协作模块，通过可控的行为注入来量化不同交互压力对智能体 API 调用准确性的具体影响。

## 核心方法

### 协作基线架构

本文基于 τ-bench 的协作用户模拟器架构，该架构利用大语言模型根据用户目标、指令和对话历史生成下一轮话语。其关键差异在于引入了目标对齐机制，确保非协作行为不干扰核心任务信息的传递。协作基线通过对话状态追踪器监控信息片段的传递状态，防止智能体在信息未完全传递时终止对话。

### 非协作行为模块化

非协作行为通过四个独立模块注入协作基线，每个模块针对特定的交互失效模式。不可用服务模块通过扩展用户目标，引入超出 API 能力范围的请求，迫使智能体处理无法执行的任务。切题模块利用 Persona Hub 生成与任务无关的对话，并监测智能体是否忽略这些内容，若忽略则触发用户抱怨。不耐烦模块基于概率激活机制，当智能体失败或延迟时，用户愤怒程度随触发次数递增，模拟真实的情绪升级过程。不完整语句模块通过风格迁移和随机截断，生成极简短或中途发送的消息，测试智能体对模糊输入的解析能力。

$$
P_{anger}(t+1) = P_{anger}(t) + \Delta P \cdot \mathbb{I}(\text{Trigger}_t)
$$

该公式描述不耐烦模块中愤怒概率的累积机制，$\mathbb{I}(\text{Trigger}_t)$ 为触发指示函数，$\Delta P$ 为每次触发后的概率增量，反映了用户情绪随交互挫折累积的动态过程。

### 目标对齐验证

为确保非协作行为不破坏任务评估的有效性，本文引入目标对齐（GA）指标。GA 利用 GPT-4o-mini 检查对话中是否传递了用户目标中的所有必要信息。若 GA 验证失败，模拟将被重新生成。这一机制解决了非协作行为可能导致的“信息缺失”问题，确保性能退化归因于智能体的处理能力而非用户模拟器的信息传递缺陷。

$$
\text{GA} = \mathbb{I}(\forall i \in \text{InfoPieces}, \text{Conveyed}(i) = \text{True})
$$

该公式定义目标对齐的二元判定，$\text{InfoPieces}$ 为用户目标分解后的信息片段集合，$\text{Conveyed}(i)$ 表示片段 $i$ 是否在对话中被成功传递，确保评估的公平性。

## 实验评估

实验在 MultiWOZ 和 τ-bench 上进行，基线覆盖 GPT-4.1 系列、Qwen3 和 Llama-3.1 等主流模型。评估指标为成功率（SR），即最终数据库状态与真实状态精确匹配的比例。

| 模型 | MultiWOZ 协作 SR | MultiWOZ 切题 SR | τ-bench 协作 SR | τ-bench 切题 SR |
| :--- | :--- | :--- | :--- | :--- |
| GPT-4.1-mini | 92.7 | 89.3 | 45.5 | 39.5 |
| GPT-4.1-nano | 23.6 | 9.8 | 12.0 | 6.8 |
| Qwen3-235b-a22b | 77.8 | 57.3 | 41.4 | 32.3 |
| Qwen3-30b-a3b | 48.3 | 27.2 | 27.9 | 20.4 |
| Llama-3.1-70b-instruct | 62.6 | 49.4 | 21.8 | 14.7 |

切题行为导致最严重的性能退化，平均降幅达 29.1%。GPT-4.1-nano 在切题模式下表现最差，因其触发最多的用户抱怨，导致在 30 步推理限制内无法完成任务。

| 模型 | 道歉率 (协作) | 道歉率 (不耐烦) | API 参数幻觉 (MultiWOZ 不完整) |
| :--- | :--- | :--- | :--- |
| GPT-4.1-mini | 0.01 | 0.14 | 0.33 |
| Qwen3-235b-a22b | 0.06 | 0.21 | 0.002 |
| Llama-3.1-70b-instruct | 0.16 | 0.35 | 0.01 |

不耐烦模式下，所有模型的道歉率显著上升，但过度道歉消耗推理步数，形成负反馈循环。Qwen3-235b-a22b 在不可用服务模式下出现 API 结果幻觉，表明其通过编造结果而非重复调用 API 来应对无法执行的任务。

评估边界受限于 30 步推理限制，可能低估智能体在无限步数下的最终成功率。代码已开源，但缺乏对非协作行为强度参数的敏感性分析，无法确定性能退化的阈值效应。

## 关联研究分析

从问题动机看，本文与 SOTOPIA 等社交智能基准形成互补。SOTOPIA 聚焦于意图推理和信念维护，假设用户行为符合社交规范；本文则聚焦于工具调用鲁棒性，引入违反规范的非协作行为。差异根源在于任务特性：社交对话中用户行为具有可预测性，而工具交互中用户行为具有高度随机性和不可控性。

从方法设计看，本文与 τ-bench 的协作模拟器架构一致，但引入了行为模块化设计。τ-bench 通过提示工程实现协作行为，本文通过独立模块注入非协作行为。这一设计使得行为强度可控，便于消融分析。然而，本文未探索行为之间的交互效应，如切题与不耐烦同时出现时的复合影响，这可能源于模块化设计的独立性假设。

## 总结

本文核心矛盾在于工具智能体评估中用户行为假设与真实部署场景的脱节。现有方法通过增加任务复杂度提升难度，但忽略了用户行为异质性这一关键变量。本文通过模块化非协作行为注入，揭示了主流模型在切题和不完整语句下的显著脆弱性，如 GPT-4.1-nano 在切题模式下 SR 降至 9.8%。其边界在于缺乏对模型内在偏差与交互压力诱导偏差的区分，且未探索行为强度的阈值效应。当非协作行为强度超过某一阈值时，智能体的失败模式是否会发生质变，论文未给出回答。
