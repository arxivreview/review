# ICLR2026最新论文 ｜UI-Ins: Enhancing GUI Grounding with Multi-Perspective Instruction-as-Reasoning ｜指令即推理：GUI 定位中的多视角语义解析

研究机构：中国人民大学、阿里巴巴集团

作者：Liangyu Chen、Hanzhang Zhou、Chenglin Cai 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.20286)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.20286)

> GUI 定位旨在将自然语言指令映射至屏幕特定像素坐标，是 GUI 智能体执行原子操作的基础。现有方法通常将指令视为静态输入，忽视了指令表述的多样性与质量对定位精度的决定性影响，导致模型在模糊或抽象指令下性能显著退化。本文提出“指令即推理”范式，通过 SFT+RL 两阶段训练，使模型将不同视角的指令作为动态推理路径并自主选择最优路径。该范式在指令敏感型基准上刷新了 SOTA，但在高分辨率细粒度感知上仍受限于骨干网络能力，其优势是否完全源于推理机制而非参数规模尚存疑。

## 研究背景

GUI 定位的核心挑战在于语义空间到像素空间的非刚性映射。多模态大语言模型（MLLMs）虽具备强大的语言理解能力，但缺乏原生空间感知，且对指令的语义解析往往局限于单一模式。当用户指令从具体的视觉描述（如“点击红色 X”）转变为抽象的功能意图（如“关闭窗口”）时，模型难以建立稳定的语义-视觉关联。这种指令表述的多样性（Diversity）与数据集中的标注噪声（Quality Flaws）构成了定位失败的主要来源，而现有研究多聚焦于视觉编码器分辨率或坐标生成机制，对指令这一关键输入变量的系统性研究不足。

主流 GUI 定位路线分为视觉增强与推理增强两类。视觉增强路线如 GUI-Spotlight 通过迭代裁剪解决高分辨率小目标混淆，推理增强路线如 UI-R1 引入强化学习提升复杂场景性能。然而，这些方法均假设指令是清晰且固定的，未利用指令本身蕴含的多视角信息。本文切入点在于揭示指令多样性被忽视的潜力：实验表明，仅通过推理时选择最优指令视角，即可在无训练条件下获得高达 76% 的相对性能提升。这促使研究重心从“如何看得清”转向“如何理解得准”，将指令从静态标签转化为动态推理路径。

## 核心方法

### 方法参照系

本文问题属于推理增强定位路线，标准流程为 SFT 预训练后接 RL 微调。关键差异在于，传统 RL 通常以坐标正确性为唯一奖励，导致策略崩溃；本文将指令视角选择纳入推理过程，构建了“视角-坐标”联合优化机制，解决了单一指令映射下的语义歧义问题。

### 数据清洗与多视角指令合成

设计动机在于现有数据集存在 23.3% 的指令缺陷（如歧义匹配或无对应元素），直接训练会引入噪声并限制模型泛化。本文构建了一个自动化流水线，首先利用 OmniParser 检测 UI 元素边界框，随后调用 GPT-4.1 从外观（Appearance）、功能（Functionality）、位置（Location）和意图（Intent）四个视角生成指令。为确保质量，引入验证阶段，通过 VLM 判断生成指令与真实边界框的精确对齐性，剔除不匹配样本。该流程将原始数据中的错误率从 23.3% 降至 8% 以下，并显著扩充了指令多样性，为后续多视角推理提供了高质量数据基础。

### 指令即推理训练框架

设计动机在于 SFT 阶段若仅以坐标为监督信号，模型响应趋于单一，导致 RL 阶段探索不足和策略崩溃。本文提出两阶段训练：第一阶段 SFT 显式教导模型使用不同视角作为推理路径。对于每个样本，随机选取两个视角，一个作为输入指令，另一个作为推理中间态。训练目标如下：

$$
\mathcal{L}_{SFT} = -\sum_{t=1}^{T} \log P(y_t | y_{<t}, I, S, V_{reason})
$$

其中 $I$ 为输入指令，$S$ 为截图，$V_{reason}$ 为推理视角，$y_t$ 为输出坐标 Token。第二阶段采用 Group Relative Policy Optimization (GRPO) 进行 RL 训练。在 RL 阶段，提示中不指定推理视角，鼓励模型自主探索。奖励函数基于坐标预测的准确性，但通过 GRPO 的组内相对优势计算，模型学习到在不同情境下选择最优推理视角的策略。该机制使模型在 RL 阶段能生成多样化的 Rollout，避免了策略崩溃，并实现了视角选择的动态优化。

## 实验评估

实验在 MMBench-GUI L2、UI-I2E-Bench、ScreenSpot-Pro、ScreenSpot-V2 和 Showdown 五个基准上进行，基线覆盖 UI-TARS、GTA1、UGround 等主流模型，但缺失 GUI-Spotlight 等自适应聚焦类方法的直接对比。UI-Ins-32B 在指令敏感型基准上表现突出，UI-I2E-Bench 准确率达 87.3%，MMBench-GUI L2 达 84.9%，均超越同规模及更大规模基线。

| 基准 | UI-Ins-32B | UI-TARS-72B | GTA1-32B | Qwen2.5-VL-32B |
| :--- | :--- | :--- | :--- | :--- |
| UI-I2E-Bench | 87.3 | 73.7 | 76.3 | 78.2 |
| MMBench-GUI L2 | 84.9 | 74.3 | 83.4 | 72.1 |
| ScreenSpot-Pro | 57.0 | 38.1 | 53.6 | 50.5 |

消融实验显示，SFT 与 RL 阶段缺一不可。仅 SFT 时 MMBench-GUI L2 准确率为 76.3%，仅 RL 时为 72.4%，两者结合后提升至 83.1%。在 RL 阶段，自由形式推理（FFR）导致性能下降（Qwen2.5-VL-7B 从 36.4% 降至 36.4% 无增益，UI-TARS-1.5-7B 从 50.1% 降至 46.9%），而指令即推理（IR）则带来显著提升（Qwen2.5-VL-7B 从 47.5% 升至 52.2%）。这表明结构化指令推理比自由 CoT 更能有效引导模型探索，且 IR 机制有效缓解了 SFT 后的策略崩溃问题。

评估边界方面，论文未报告置信区间，且未控制骨干网络变量以剥离参数规模效应。代码与模型权重已开源，但数据清洗流水线依赖 GPT-4.1，可能引入外部模型偏差。ScreenSpot-Pro 上 UI-Ins-32B 的 57.0% 低于 GUI-AIMA-3B 的 61.5%，提示在高分辨率细粒度感知上，推理增强未能完全弥补视觉编码器的分辨率限制。

## 关联研究分析

从问题动机看，本文与 UI-R1 同属 RL 增强路线，但 UI-R1 侧重基于规则的奖励函数以提升低资源场景性能，而本文聚焦指令语义解析。UI-R1 的奖励机制主要验证坐标正确性，未涉及指令视角的选择，因此在模糊指令场景下可能缺乏鲁棒性。本文通过引入多视角推理，将指令的语义丰富性转化为推理优势，解决了 UI-R1 未触及的指令歧义问题。两者的差异根源在于对“推理”定义的不同：UI-R1 视推理为动作序列的优化，本文视推理为语义视角的动态选择。

从方法设计看，本文与 GUI-Spotlight 形成互补。GUI-Spotlight 通过迭代裁剪解决高分辨率小目标定位，属于视觉空间上的细化；本文通过指令视角选择解决语义空间上的歧义，属于语义空间上的细化。GUI-Spotlight 未考虑指令多样性，可能在抽象指令下失效；本文未集成视觉聚焦机制，在 4K 屏幕密集布局下性能受限。这种差异反映了 GUI 定位中“看得清”与“理解准”两个维度的独立性。本文未探索两者结合的可能性，即是否能在视觉聚焦的同时进行指令视角推理，以同时解决高分辨率感知与语义歧义问题。

## 总结

本文核心矛盾在于 GUI 定位中指令语义解析的单一性与用户指令多样性的不匹配。现有方法将指令视为静态输入，忽视了其作为动态推理路径的潜力，导致在模糊或抽象指令下性能退化。本文通过“指令即推理”范式，利用 SFT 教导多视角推理，RL 优化视角选择，在 UI-I2E-Bench 和 MMBench-GUI L2 上刷新 SOTA，证明了结构化指令推理的有效性。然而，实验暴露了其在高分辨率细粒度感知上的局限，ScreenSpot-Pro 上低于 GUI-AIMA-3B，且未控制骨干网络变量，无法完全剥离参数规模对性能的影响。当指令视角数量增加或引入未见过的视角类型时，模型的泛化能力是否仍能保持，论文未给出回答。
