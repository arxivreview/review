# ICLR2026最新论文 ｜MARS A FOUNDATIONAL MAP AUTO REGRESSOR ｜地图自回归生成器

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_51066102)

> 从遥感影像生成矢量地图面临栅格像素与几何图元间的结构鸿沟，传统“分割+后处理”范式因启发式规则差异导致泛化性差且误差累积。MARS 将矢量地图元素形式化为序列语言，通过自回归 Transformer 直接生成坐标 Token，实现了多类别地图的端到端统一建模。该框架验证了大规模预训练在矢量生成中的必要性，但其串行解码机制在长序列拓扑保持上的鲁棒性仍存疑。

## 研究背景

矢量地图生成需将非结构化的点、线、面转化为计算机可处理的离散表示。这一过程的核心难点在于几何图元的变长特性与像素网格的固定维度不匹配，导致基于张量的生成模型（如扩散模型）难以直接适用。为弥合这一差距，主流方案采用两阶段流水线：先进行像素级语义分割，再通过关键点提取或边缘连接等启发式后处理生成矢量。然而，道路网络（多折线、复杂交叉口）与建筑物（非重叠多边形）的后处理逻辑截然不同，使得此类方法通常仅支持单一地图类别，且超参数（如 NMS IoU 阈值）的调优限制了性能上限。

现有研究在车载在线建图领域已确立 BEV 特征提取与 DETR-like 并行解码的主流范式，但卫星遥感离线建图仍受限于数据规模与类别单一性。Cityscale 和 SpaceNet 等基准仅包含道路标注，AICrowd 仅包含建筑标注，缺乏多类别联合训练的大规模数据集。MARS 的切入点在于打破类别壁垒，将地图生成视为语言建模问题，通过统一的序列表示消除后处理依赖，并构建包含 300 万图像的多类别数据集 MAP-3M，以支撑基础模型的预训练与泛化。

## 核心方法

### 方法参照系

MARS 属于端到端矢量预测架构，但其解码机制与车载建图主流的 DETR-like 并行解码存在本质差异。车载建图（如 MapTR）通过分层查询嵌入并行预测点集，依赖 BEV 空间的全局一致性；MARS 则采用自回归串行解码，将地图元素转化为 Token 序列，依赖视觉编码器提供的上下文特征，无需显式构建 BEV 空间。

### 地图到序列转换

针对道路网络中复杂的交叉口与合并结构，标准图遍历算法难以保证语义连续性。MARS 引入基于笔画的分解算法，将边度大于 3 的交叉口作为分割点，将多折线网络分解为单折线路径，并在角度容差（<30°）内合并连续线段。这一设计将非结构化的图结构转化为可序列化的折线集合，解决了自回归模型无法直接处理复杂拓扑的问题。转换后的序列表示为：

$$
S = \langle C_1, x_{1,1}, y_{1,1}, ..., x_{1,n_1}, y_{1,n_1}, \langle SEP \rangle, C_2, ... \rangle
$$

其中 $C_i$ 为类别 Token（如道路 $R$、建筑 $B$），$x_{i,j}, y_{i,j}$ 为第 $i$ 个对象的第 $j$ 个顶点坐标。该公式将几何图元映射为离散 Token 流，使模型能像生成文本一样生成地图。

### 自回归解码架构

MARS 采用 Swin-L 作为视觉编码器，通过最小化卷积特征聚合器将四层特征上采样并展平，经交叉注意力注入解码器。解码器使用单向因果注意力，基于教师强制训练，通过交叉熵损失同时监督类别 Token 与离散化坐标 Token。为确保解码一致性，所有地图对象按距图像中心的距离排序，距离相近时按顺时针角度排序，形成螺旋顺序。解码词汇表 $D \in \mathbb{R}^{B_o + B_c}$ 共享 $x, y$ 维度坐标 Token，其中 $B_o$ 为语义类别数，$B_c$ 为像素位置数（如 224）。这种设计消除了后处理超参数，实现了从像素到矢量的直接映射。

## 实验评估

实验在 Cityscale、SpaceNet、AICrowd 及 MAP-3M-VAL 上进行，基线覆盖分割类（Seg-UNet）、图检测类（RNGDet++）及分割+后处理类（SamRoad）。MARS 在道路提取上表现突出，Cityscale F1 达 82.88%，较 RNGDet++ 的 78.44% 提升 4.44 个百分点；SpaceNet F1 为 82.05%，略低于 RNGDet++ 的 82.51%。在建筑提取上，MARS 的 AP 为 87.30%，低于专用模型 GeoFormer 的 91.5%，但 N-ratio 指标（0.4542）优于 PolyMapper（1.29），表明其生成的多边形更简洁。

| 数据集 | 方法 | P | R | F1 | IoU |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Cityscale | RNGDet++ | 85.65 | 72.58 | 78.44 | - |
| Cityscale | MARS | 84.28 | 81.53 | 82.88 | - |
| SpaceNet | RNGDet++ | 91.34 | 75.24 | 82.51 | - |
| SpaceNet | MARS | 79.68 | 84.56 | 82.05 | - |
| AICrowd | GeoFormer | 91.5 | 97.8 | - | 98.1 |
| AICrowd | MARS | 87.30 | 97.94 | - | 97.32 |

消融实验显示，MAP-3M 预训练对性能至关重要。无预训练时 SpaceNet F1 仅为 70.45%，预训练后提升至 82.05%，增幅达 11.6 个百分点。这表明自回归模型对数据稀缺敏感，大规模预训练是弥补小数据集优化困难的关键。Chat with MARS 功能通过提供 1-2 个提示点，在 Cityscale 上将 F1 从 82.88% 提升至 84.13%，验证了交互式修正的有效性。

评估边界方面，论文未报告计算效率指标，且建筑提取精度低于专用模型，暗示通用架构在特定几何形状上的局限性。代码与数据集已开源，但超参数细节（如角度容差具体值）未在正文中完全披露，可能影响复现精度。

## 关联研究分析

从方法设计看，MARS 的自回归串行解码与 MapTR 的并行解码形成鲜明对比。MapTR 依赖 BEV 特征的全局一致性，通过分层查询嵌入并行预测点集，适合车载在线建图的实时性需求；MARS 则通过序列语言建模，牺牲推理速度换取多类别通用性。这一差异源于任务特性：车载建图需实时处理连续帧，而遥感建图可离线处理单帧。MARS 未采用 BEV 空间，而是直接利用 Swin 编码器特征，这可能限制了其对道路拓扑关系的深层理解，但简化了架构复杂度。

从问题动机看，MARS 与 GeoFormer 等专用建筑提取模型存在互补关系。GeoFormer 针对多边形几何优化，在 AICrowd 上 AP 达 91.5%，但仅支持单一类别；MARS 作为通用模型，在建筑提取上 AP 为 87.30%，但能同时处理道路与建筑。这种权衡反映了通用性与专用性的矛盾：MARS 的通用架构通过统一序列表示消除了后处理差异，但在特定类别的几何精度上略逊于专用模型。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但 MAP-3M 的规模优势可能弥补了这一差距。

## 总结

MARS 解决了多类别矢量地图生成中后处理逻辑差异导致的泛化性瓶颈，通过将地图元素形式化为序列语言，实现了端到端统一建模。在 Cityscale 上 F1 达 82.88%，较基线提升 4.44 个百分点，验证了自回归范式的有效性。然而，建筑提取精度低于专用模型，且串行解码在长序列拓扑保持上的鲁棒性未充分验证。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
