# ICLR2026最新论文 ｜WAVE: Learning Unified & Versatile Audio-Visual Embeddings with Multimodal LLM ｜统一视听嵌入的多模态大语言模型

研究机构：清华大学

作者：Changli Tang、Qinfan Xiao、Ke Mei 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.21990)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.21990)

> 视听嵌入领域长期受困于静态图像与动态音频-视频流的表征割裂，现有多模态大语言模型（MLLM）嵌入方法多聚焦视觉，难以处理同步视听信号。WAVE 通过双音频编码器与层级特征融合，将文本、音频、静默视频及同步视听流映射至单一语义空间。其核心价值在于验证了 MLLM 统一嵌入在动态模态上的可行性，但长序列处理与音频细粒度对齐的边界仍需审视。

## 研究背景

当检索系统需要匹配“视频中狗吠叫的片段”时，传统双编码器架构（如 CLIP）将视觉与听觉特征分别编码后在浅层拼接，导致语义鸿沟难以弥合。这种割裂迫使模型依赖文本作为中介，无法直接建立视听信号间的深层对应。为解决此问题，研究者转向多模态大语言模型（MLLM），利用其指令跟随能力生成任务感知的嵌入。然而，现有 MLLM 嵌入工作（如 VLM2Vec、LamRA）主要集中于静态图像或视频，对同步视听流的处理近乎空白，导致“真正通用的视听嵌入空间”尚未实现。

视听嵌入的核心矛盾在于：专用编码器（如 CLAP）计算高效但语义浅层，LLM 统一嵌入语义深刻但计算昂贵且易受模态偏置影响。2023 年后，随着 Qwen2.5-Omni 等原生多模态模型的成熟，领域共识转向利用 LLM 的世界知识对齐模态，但缺乏针对动态音频-视频同步的架构设计。WAVE 的切入点在于：首次将 MLLM 统一嵌入范式扩展至同步视听流，通过双音频编码器捕捉语音与环境声的互补线索，并采用层级特征融合保留低层感知与高层语义，从而在 MMEB-v2 视频赛道上超越工业级模型 Seed-1.6-Embedding，证明统一嵌入在动态模态上的有效性。

## 核心方法

### 方法参照系

WAVE 属于 MLLM 统一嵌入路线，与 VLM2Vec、LamRA 等视觉主导方法共享“单模型多模态对齐”范式。关键差异在于：本文处理同步视听流，需解决音频-视频时间对齐与音频内部语义解耦问题，而现有方法多假设模态独立或仅处理静默视频。

### 双音频编码器与时间对齐

传统音频编码器（如 BEATs）仅输出单一特征流，无法区分语音与环境声，导致在“语音引导视频检索”任务中语义混淆。WAVE 引入双编码器架构：语音编码器（源自 Qwen2.5-Omni）与环境声编码器（BEATs + 可训练对齐器）分别生成 token，并按 1:1 频率交错形成统一听觉序列。为确保时间同步，采用时间对齐多模态旋转位置编码（TMRoPE），使同一帧的视觉、语音、环境声 token 共享相同位置编码。该设计解决了此前方法中音频-视频时间漂移导致的检索失效，使模型能精确捕捉“第 3 秒的狗吠”等细粒度时空对应。

$$
\text{TMRoPE}(t) = \text{Rotary}(t, \theta), \quad \theta = \text{frame\_index} \times \Delta t
$$

其中 $\Delta t$ 为帧间隔，确保跨模态 token 的时间一致性。

### 层级特征融合与对比训练

单取 LLM 最后一层隐藏状态（Last-token pooling）会丢失低层感知细节，而平均池化则稀释语义焦点。WAVE 提出层级特征融合策略：提取 LLM 所有层的最后输出 token，拼接后通过两层 MLP（GELU 激活）压缩为统一嵌入。该设计动机在于：低层编码保留纹理、音色等感知线索，高层编码捕捉语义抽象，融合后嵌入在检索与问答任务上均优于单层提取。训练采用对称 InfoNCE 损失，结合检索任务（通用提示）与问答任务（问题感知提示），实现任务无关与任务感知的统一。

$$
\mathcal{L}_{\text{retrieval}} = -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp(\text{sim}(e_{s_i}, e_{t_i})/\tau)}{\sum_{j=1}^{N} \exp(\text{sim}(e_{s_i}, e_{t_j})/\tau)}
$$

其中 $\tau=0.01$，$e_{s_i}, e_{t_i}$ 为源-目标嵌入，$\text{sim}$ 为余弦相似度。

## 实验评估

实验在 MMEB-v2、AudioCaps、VGGSound 等基准上进行，基线覆盖 LamRA、GME、CAFe 等开源 MLLM 嵌入模型及工业级 Seed-1.6-Embedding，但缺失纯音频专用编码器（如 CLAP）的直接对比，可能高估统一嵌入的优势。

| 模型 | MMEB-v2-Video Overall | AudioCaps R@1 | VGGSound R@1 |
| --- | --- | --- | --- |
| LamRA 7B | 35.0 | - | - |
| Seed-1.6-Embedding | 60.9 | - | - |
| WAVE 7B | 59.9 | 44.2 | 25.0 |

WAVE 在 MMEB-v2 视频赛道整体得分 59.9，略低于 Seed-1.6-Embedding 的 60.9，但在音频检索（AudioCaps R@1 44.2）与视听检索（VGGSound R@1 25.0）上显著优于分离式编码器基线，验证了统一嵌入在动态模态上的优势。

消融实验显示，联合训练（Joint）比分离训练（Separate）在 MMEB-v2 视频 QA 子任务上提升 0.9 点（72.5 vs 71.6），在 AudioCaps 检索上提升 1.7 点（44.2 vs 42.5），证明跨模态正迁移的有效性。层级融合（All-layer MLP）比单层 Last-token 在视频检索平均 R@1 上提升 0.9 点（50.5 vs 49.6），但提升幅度有限，暗示 LLM 高层语义已主导嵌入质量。

评估边界：指标仅覆盖检索与 QA，未评估嵌入的线性可分性或下游分类性能；视频采样上限 128 帧（64 秒），长视频泛化能力未验证；代码与超参数已开源，但 BEATs 对齐器预训练细节（如 WavCaps 数据清洗）未完全披露，可复现性存在轻微不确定性。

## 关联研究分析

从问题动机看，WAVE 与 CLAP 形成鲜明对比：CLAP 采用双编码器对齐音频-文本，计算高效但无法处理视频-音频直接检索；WAVE 通过 MLLM 统一空间实现任意模态对检索，但计算成本更高。差异根源在于任务特性：CLAP 面向零样本音频分类，WAVE 面向跨模态检索，前者无需视频理解，后者依赖 LLM 的时空推理能力。

从方法设计看，WAVE 与 LamRA 同属 MLLM 嵌入框架，但 LamRA 侧重视觉检索与重排序，WAVE 扩展至同步视听流。关键差异在于音频处理：LamRA 未引入专用音频编码器，依赖 LLM 内置音频模块，而 WAVE 通过双编码器显式解耦语音与环境声。这一设计是否必要，取决于音频语义复杂度——在纯环境声检索中，双编码器的增益可能小于语音主导场景，论文未提供分场景消融。

## 总结

WAVE 要解决的核心矛盾是 MLLM 统一嵌入在动态视听流上的缺失，其切入点在于利用 Qwen2.5-Omni 的感知能力，通过双音频编码器与层级融合弥补音频表达不足。方法上，WAVE 将异构模态映射至单一语义空间，实现任意模态对检索与任务感知嵌入。实验证明其在 MMEB-v2 视频赛道达到 SOTA 水平（59.9），音频检索性能显著优于分离式架构。边界在于：视频采样上限 128 帧限制了长序列处理，且缺失纯音频专用编码器基线对比，可能高估统一嵌入的相对优势。当视频长度超过 64 秒时，TMRoPE 的时间对齐精度是否衰减，论文未给出回答。
