# ICLR2026最新论文 ｜TUMIX: Multi-Agent Test-Time Scaling with Tool-Use Mixture ｜工具混合多智能体测试时扩展

研究机构：美国麻省理工学院、谷歌DeepMind

作者：Yongchao Chen、Jiefeng Chen、Rui Meng 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.01279)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.01279)

> 测试时扩展（Test-Time Scaling, TTS）旨在通过增加推理阶段计算量提升复杂任务性能，但纯文本推理在精确计算与实时知识获取上存在固有短板。现有方法要么依赖单一模态，要么在固定预算下导致过度思考与多样性坍缩，无法动态适配不同难度问题的算力需求。本文提出 TUMIX，通过并行运行具备代码解释器与搜索能力的异构智能体，并引入 LLM 驱动的动态终止机制，在保持准确率的同时将推理成本降低至 49%。该方法在 HLE 等基准上显著优于纯文本 TTS 基线，但其对工具调用环境的依赖及智能体设计的泛化性仍存疑。

## 研究背景

当大语言模型（LLM）面对需要精确算术或最新事实查询的任务时，纯文本推理往往因缺乏执行环境而失效。这种局限催生了工具增强推理，即通过调用代码解释器（Code Interpreter）和搜索引擎（Search）来弥补语义推理的不足。然而，如何决定何时使用何种工具、以及如何在多个工具调用路径间进行有效聚合，构成了新的决策难题。

TTS 的主流路线包括并行采样与串行搜索。并行采样（如 Self-Consistency）通过生成多条独立轨迹并利用多数投票聚合，虽能提升覆盖率，但受限于模型的模式坍缩，导致轨迹高度相似；串行搜索（如 Tree of Thoughts）引入回溯机制，但依赖过程奖励模型（Process Reward Models, PRM）且延迟较高。2024 年以来，随着 OpenAI o1 等模型引入强化学习训练长链推理，固定预算分配导致的“过度思考”现象日益突出，即简单问题消耗过多算力，复杂问题资源不足。现有工具增强方法如 SciMaster 虽采用多智能体精炼，但缺乏对工具多样性的系统利用，且终止策略僵化，无法在性能与成本间取得最优平衡。

本文切入点在于将工具使用策略本身作为智能体多样性的来源。不同于传统 TTS 仅依赖采样温度或提示词变化，TUMIX 将代码、搜索与纯文本推理封装为不同能力的智能体，通过多轮消息传递实现答案精炼。其核心假设是：异构工具组合能产生比单一强智能体重复采样更高的答案覆盖率，且通过 LLM 判断终止时机可避免过度精炼导致的准确率下降。

## 核心方法

### 方法参照系

TUMIX 属于并行采样与自适应计算分配的混合范式。标准 TTS 流程为：生成 $N$ 条轨迹 $\{y_1, ..., y_N\}$，聚合得到 $\hat{y}$。本文的关键差异在于：轨迹生成器不再是同构 LLM，而是具备不同工具访问权限的异构智能体集合 $\mathcal{S} = \{s_1, ..., s_K\}$，且聚合过程包含多轮迭代精炼而非单次投票。

### 异构智能体并行生成

传统并行采样中，所有轨迹来自同一模型分布，导致多样性受限。TUMIX 设计 15 个预定义智能体，涵盖纯 CoT、代码生成、搜索查询及工具组合策略。每个智能体 $s_i$ 在每轮 $r$ 基于问题 $q$ 和前一轮所有智能体的答案集合 $\mathcal{A}_{r-1}$ 生成新答案 $Y_{i,r}$。智能体能力 $p_i(q) = \mathbb{P}\{Y_i = a^* | q\}$ 因工具而异，例如代码智能体在算术任务上 $p_i$ 更高，而搜索智能体在事实查询上占优。这种设计动机在于：通过工具异构性打破单一 LLM 的模式坍缩，使答案空间覆盖更广泛。

$$
\text{Coverage}(\mathcal{S}) = 1 - \prod_{i \in \mathcal{S}} (1 - p_i(q))
$$

该公式表明，当智能体间相关性为正时，实际覆盖率低于独立假设下的理论值，但工具异构性通过引入负相关或低相关路径，有效提升了整体覆盖率。

### LLM 驱动的动态终止

固定轮次精炼会导致过度思考，即后续轮次不仅无增益，反而因错误传播降低准确率。TUMIX 引入 LLM-as-Judge 机制，在每轮结束后查询 LLM 判断是否停止精炼。终止条件定义为：当预期边际收益 $\Delta_r$ 低于边际成本 $\lambda \cdot c$ 时停止，其中 $\Delta_r$ 基于当前轮次的答案熵、投票边际及覆盖率下降率估计。

$$
\text{Stop if } \Delta_r \leq \lambda \cdot \text{marginal cost}
$$

此设计解决了固定预算下简单问题算力浪费的问题。实验显示，该策略在保持准确率的同时，将推理成本降至固定轮次策略的 49%。其有效性依赖于 LLM 对“答案收敛”状态的准确判断，而非外部 PRM 的细粒度评分，降低了校准成本。

## 实验评估

实验在 HLE（2,500 题）、GPQA Diamond（198 题）及 AIME 24&25（60 题）上进行，基线包括 Self-MoA、Symbolic-MoE、DEI、SciMaster 等，覆盖纯文本 TTS 与工具增强 TTS 两类路线。缺失纯搜索或纯代码基线，可能高估工具组合的相对优势。

| 方法 | HLE | GPQA | AIME 24&25 | Ave. Norm. |
|---|---|---|---|---|
| w/o TTS | 21.6 | 84.6 | 87.3 | 64.5 |
| Majority Vote | 28.4 | 84.9 | 94.3 | 69.2 |
| Self-MoA | 29.3* | 85.5 | 94.7 | 69.8 |
| SciMaster | 26.9 | 86.9 | 94.1 | 69.3 |
| TUMIX | 32.3 | 87.9 | 96.7 | 72.3 |
| TUMIX+ | 34.1 | 88.3 | 96.7 | 73.0 |

TUMIX 在 Gemini-2.5-Pro 上平均准确率较最佳基线提升 3.55%，其中 HLE 提升 3.0%（32.3% vs 29.3%），AIME 提升 2.0%（96.7% vs 94.7%）。TUMIX+ 通过增加推理成本进一步将 HLE 提升至 34.1%，但边际收益递减。

消融实验表明，智能体数量从 1 增至 15 时，覆盖率与平均分数显著提升，验证了多样性价值。工具访问对比显示，同时具备代码与搜索的智能体组（Code_Search_Text）覆盖率高于仅代码或仅搜索组，证明工具互补性。终止策略对比中，Term_LLM（LLM 判断）优于 Term_Rule（规则判断），后者在多数答案稳定后过早终止，导致准确率下降。

评估边界方面，HLE 为本文主基准，缺乏外部参照，且部分基线（如 Self-MoA）在 HLE 上使用了 Gemini-2.5-Pro 选择智能体，存在数据泄露风险。代码执行限制为 60 秒，可能影响复杂代码任务的性能。论文未提供代码，可复现性受限。

## 关联研究分析

从问题动机看，TUMIX 与 SciMaster 均解决多智能体精炼问题，但 SciMaster 依赖单一预设计智能体的重复采样，而 TUMIX 强调工具异构性。差异根源在于任务特性：HLE 等跨学科基准中，不同子任务对工具需求差异大，单一智能体无法覆盖所有场景，而工具异构性提供了更细粒度的能力匹配。这与 Self-MoA 的结论（单一最佳 LLM 优于多样 LLM）形成冲突，暗示在工具增强场景下，多样性收益可能源于工具本身的不可预测性，而非 LLM 参数差异。

从方法设计看，TUMIX 与 CodeSteer 均涉及工具选择，但 CodeSteer 作为全局引导模型决定模态切换，而 TUMIX 将工具使用封装为智能体属性，通过并行执行实现隐式选择。这种设计避免了 CodeSteer 中引导模型可能引入的额外延迟与错误传播，但牺牲了全局协调性。TUMIX 的终止策略与 LATTS 的局部自适应扩展类似，但 LATTS 依赖验证器评分，而 TUMIX 使用 LLM 判断，后者在开放域任务上更鲁棒，但缺乏理论最优性保证。

## 总结

TUMIX 解决的核心矛盾是工具增强 TTS 中性能与成本的权衡，现有方法因固定预算或单一模态导致过度思考或覆盖不足。本文通过异构智能体并行生成与 LLM 动态终止，在 HLE 上实现 32.3% 准确率（较基线 +3.0%）并将成本降至 49%。其边界在于：HLE 基准缺乏外部参照，且智能体设计依赖人工预定义，未探索 LLM 自动优化智能体组合的泛化性。当任务分布发生显著变化时，预定义智能体集合的覆盖率是否仍能保持优势，论文未给出回答。
