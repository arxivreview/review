# ICLR2026最新论文 ｜GRO-RAG: GRADIENT AWARE RE RANK OPTIMIZA - TION FOR MULTI SOURCE RETRIEVAL-AUGMENTED GENERATION ｜多源检索增强生成中的梯度感知重排

研究机构：英国布里斯托大学、中国科学院

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_96036288)

> 多源检索增强生成（Multi-Source RAG, MS-RAG）旨在通过整合异构数据源提升复杂问答的准确性，但现有方法往往静态聚合所有源或仅依赖查询-文档相似度进行重排，忽视了源间语义冗余及文档对下游生成任务的实际效用。本文提出 GRO-RAG，一种无需训练、基于生成损失梯度的动态源选择与文档重排框架，通过单次前向-反向传播量化文档贡献。该方法在多个多跳问答基准上显著优于静态基线，但其对冻结模型内部梯度的依赖在对抗性投毒场景下的鲁棒性尚未得到验证。

## 研究背景

多源 RAG 的核心困境在于上下文预算有限性与信息分布异构性的矛盾。当系统从维基百科、新闻及论坛等多个源检索时，直接拼接会导致上下文窗口被冗余信息填满，而单一源选择又可能遗漏互补证据。解决这一矛盾需要两个层面的决策：一是选择哪些源组合以最大化信息互补性，二是从候选池中筛选出对生成目标贡献最大的文档。

传统 RAG 范式（Lewis et al., 2020）确立了“检索-生成”双模块架构，但早期多源方法如 CRAG（Yan et al., 2024）和 ReAct（Yao et al., 2023）多采用静态回退或启发式规则，缺乏对源间语义重叠的显式建模。更关键的是，主流重排策略（如 BM25 或密集检索器）仅基于查询-文档相似度打分，这种检索级信号与生成级目标存在本质错位：高相似度的文档未必能降低生成损失。GRO-RAG 的切入点在于打破这种错位，将文档选择问题重构为生成损失的最小化问题，利用模型内部梯度作为效用信号，实现从“检索相关性”到“生成效用”的范式转移。

## 核心方法

### 方法参照系

标准多源 RAG 流程包含源检索、文档重排和生成三个阶段。本文问题与通用流程的关键差异在于：传统流程将源选择视为静态配置，将重排视为独立的相似度匹配任务；而 GRO-RAG 将两者统一为基于生成目标的动态优化过程，且全程无需更新模型参数。

### 源组合子模优化

源选择环节通常采用均匀聚合或单一源静态选择，导致冗余信息浪费或互补证据缺失。GRO-RAG 引入相关性-冗余度权衡函数，通过贪心算法求解子模最大化问题。设计动机在于解决多源数据中“信息重叠”导致的上下文效率低下问题。定义源子集 $A$ 的评分函数为：

$$ f(A) = \sum_{s \in A} \langle \mathbf{q}, \mathbf{s} \rangle - \lambda \sum_{s_i, s_j \in A, i < j} \text{sim}(\mathbf{s}_i, \mathbf{s}_j) $$

其中第一项衡量查询相关性，第二项惩罚源间语义冗余，$\lambda$ 为权衡系数。该函数具有子模性，贪心算法可提供 $(1-1/e)$ 的近似保证，从而在计算可行范围内选出信息互补且相关的源组合。

### 梯度感知文档重排

文档重排环节通常依赖交叉编码器或查询-文档相似度，忽略文档对生成损失的实际影响。GRO-RAG 利用冻结 LLM 的生成损失梯度进行重排。设计动机在于直接对齐下游生成目标，避免检索信号与生成效用的错位。通过一阶泰勒展开近似，文档 $d_i$ 的重要性得分定义为：

$$ \phi_i = \langle \mathbf{h}_i, -\nabla_{\mathbf{h}} \mathcal{L} \rangle $$

其中 $\mathbf{h}_i$ 为文档嵌入，$\nabla_{\mathbf{h}} \mathcal{L}$ 为生成损失对输入表示的梯度。该得分估计了移除文档 $d_i$ 后损失的增加量（Leave-One-Out 上界），选择 Top-k 高分文档即可最大化生成质量，且仅需单次前向-反向传播。

## 实验评估

实验在 HotpotQA、2WikiMultihopQA 和 MuSiQue 三个多跳问答基准上进行，使用 Llama3.1-8B 和 GLM-4 作为冻结生成模型。基线覆盖无检索、单源 RAG（Self-RAG, FLARE）及多源 RAG（CRAG），但缺乏针对对抗性鲁棒性的安全基线（如 PRA-RAG）。

| LLM | 方法 | HotpotQA F1 | 2WikiMQA F1 | MuSiQue F1 |
| :--- | :--- | :--- | :--- | :--- |
| Llama3.1-8B | CRAG | 34.2 | 27.3 | 15.9 |
| Llama3.1-8B | **GRO-RAG** | **39.1** | **28.9** | **18.6** |
| GLM-4 | CRAG | 38.1 | 27.4 | 17.4 |
| GLM-4 | **GRO-RAG** | **42.8** | **30.3** | **21.1** |

GRO-RAG 在所有数据集和模型上均显著优于 CRAG，尤其在难度最高的 MuSiQue 上提升幅度最大，验证了梯度信号在复杂推理场景下的有效性。

| 方法 | HotpotQA nDCG@10 | MuSiQue nDCG@10 |
| :--- | :--- | :--- |
| BGE-M3 | 0.6892 | 0.3922 |
| GRO-RAG (Llama) | 0.6442 | 0.4039 |

在纯检索指标上，GRO-RAG 的 nDCG@10 低于强密集检索器 BGE-M3，但在 MuSiQue 上略高。这表明 GRO-RAG 并非旨在最大化检索精度，而是优化生成效用，其检索性能是生成优化的副产品。

消融实验显示，移除源选择模块（w/o SCS）或梯度重排模块（w/o GR）均导致性能下降，其中移除梯度重排在 MuSiQue 上造成最大损失（F1 从 18.6 降至 16.2），证实了生成感知重排对复杂推理任务的关键作用。

评估边界方面，论文未报告计算延迟，仅提及“单次前向-反向传播”，未量化其相对于密集检索器的开销。代码未公开，超参数 $\lambda$ 的敏感性分析缺失。实验未涉及对抗性投毒场景，无法评估梯度信号在恶意文档干扰下的鲁棒性。

## 关联研究分析

从问题动机看，GRO-RAG 与 PRA-RAG（Tan et al., 2026）在文档选择环节存在根本目标冲突。PRA-RAG 旨在通过可证明鲁棒聚合限制投毒文档的影响，侧重安全保证；而 GRO-RAG 旨在最大化生成效用，侧重性能提升。这种冲突暗示，在对抗性环境中，基于梯度的效用最大化可能反而放大恶意文档的影响，因为攻击者可能构造高梯度贡献的对抗样本。GRO-RAG 未探索这种安全性与效用的权衡，其方法在静态、可信数据源假设下有效，但在动态、对抗性多源环境中可能失效。

从方法设计看，GRO-RAG 与 Self-RAG（Asai et al., 2023）均利用 LLM 内部信号进行自适应检索，但机制不同。Self-RAG 使用反思 token 进行离散决策，依赖模型训练时的特殊标记；GRO-RAG 使用连续梯度信号，无需额外训练。这种差异源于任务特性：Self-RAG 侧重单源内的动态检索，而 GRO-RAG 侧重多源间的组合优化。梯度信号在连续空间中的优化能力使其更适合处理源组合的复杂组合爆炸问题，但其对模型内部状态的可访问性要求限制了其在黑盒 API 场景下的适用性。

## 总结

GRO-RAG 解决了多源 RAG 中源选择静态化与重排信号错位的核心矛盾，通过子模优化和梯度感知重排实现了生成效用的动态最大化。实验证明其在多跳问答任务上显著优于静态基线，MuSiQue F1 达到 18.6%（Llama3.1-8B）。然而，其方法依赖于冻结模型内部梯度的可访问性，且未考虑对抗性投毒场景下的鲁棒性。当外部知识库中存在精心构造的对抗性文档时，基于生成损失梯度的重排机制是否会被利用来放大恶意内容的影响，论文未给出回答。
