# ICLR2026最新论文 ｜VOG: ENHANCING LLM REASONING THROUGH STEP WISE VERIFICATION ON KNOWLEDGE GRAPHS ｜基于逐步验证与自适应上下文选择的图推理框架

研究机构：香港科技大学、日本筑波大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_96819363)

> 大语言模型（LLM）在知识密集型多跳推理中常因缺乏外部事实校验而产生幻觉与错误累积。现有图增强框架多采用静态检索或固定参数探索，无法在推理过程中动态修正中间步骤的逻辑偏差。本文提出 Verify-on-Graph (VoG) 框架，通过引入逐步验证机制与多臂老虎机（MAB）驱动的自适应上下文选择，实现推理计划的迭代修正。该框架在多个基准上优于现有智能体基线，但其性能提升主要依赖于特定骨干模型，且未解决大规模动态图下的实时性瓶颈。

## 研究背景

当 LLM 处理多跳知识图谱问答（KGQA）时，其参数化知识往往滞后于现实世界，且推理过程缺乏透明性。为弥补这一缺陷，引入知识图谱（KG）作为外部结构化知识源成为主流方案。然而，将图结构转化为 LLM 可理解的文本序列时，拓扑信息的线性化失真导致模型难以准确捕捉实体间的复杂逻辑关系，进而引发推理路径断裂。

该领域的主流路线分为“规划优先”与“检索优先”两类。规划方法如 SPARQL 生成虽结构清晰，但依赖昂贵的微调且易受检索错误影响；检索方法如 Think-on-Graph (ToG) 虽具备动态探索能力，但通常基于固定深度或宽度参数进行图搜索，缺乏对中间推理步骤的事实校验。这种静态集成机制导致错误在后续步骤中不断累积，且模型往往忽略全局上下文，仅在局部三元组上推理，造成早期终止或逻辑不一致。VoG 的切入点在于打破“检索即终止”的单向流程，将验证与修正嵌入推理循环，使 LLM 能够根据 KG 反馈动态调整推理策略。

## 核心方法

### 智能体推理参照系

VoG 建立在 ReAct 框架的基础上，将 LLM 视为智能体，通过“思考-行动-观察”循环与 KG 交互。与标准 ReAct 不同，VoG 的核心差异在于引入了显式的“验证-修正”闭环。标准流程中，智能体基于观察结果直接生成下一步行动；而 VoG 在每一步行动后，先通过验证机制判断当前推理是否与 KG 事实一致，若不一致则触发计划修正，而非盲目继续。

### 逐步 KG 验证机制

在标准智能体流程中，检索到的三元组直接作为观察结果输入 LLM，缺乏对中间步骤正确性的独立校验。VoG 在此环节引入验证智能体（Verify Agent），将检索到的 KG 反馈 $O_t$ 与计划中预测的观察 $Pred_O_t$ 进行比对。设计动机在于阻断错误传播：若当前步骤基于错误的实体或关系，后续推理必然失效。验证信号 $V$ 定义为：

$$
V(Q, s_t, O_t) = \mathbb{I}(\text{LLM\_verify}(Q, s_t, O_t) \land \text{DeBERTa\_verify}(Q, s_t, O_t))
$$

其中 $\mathbb{I}$ 为指示函数，当 LLM 与预训练 DeBERTa 模型均判定不一致时，$V=1$ 触发修正。这种双重校验机制利用 DeBERTa 的轻量级特性提供独立于 LLM 的事实锚点，降低了单一模型幻觉导致的误判风险。

### 基于 MAB 的自适应上下文选择

验证触发修正后，如何为修正智能体提供最优上下文成为关键。固定策略（如仅使用局部反馈或全局历史）在不同推理阶段表现差异巨大。VoG 将上下文选择建模为多臂老虎机（MAB）问题，定义三种策略臂：Local（仅当前反馈）、Lookahead（含未来关系）、Global（含全部历史）。设计动机在于解决 LLM 对上下文输入的敏感性：不同推理阶段需要不同粒度的信息，静态策略无法适应这种动态变化。UCB 评分函数定义为：

$$
\text{UCB}_c = \frac{R_c}{N_c} + \alpha \sqrt{\frac{\ln N}{N_c}} + B_{ent}(H_t) + B_{KG}(t, E_{rep}) + B_{div}(c)
$$

其中 $R_c/N_c$ 为平均奖励，$\alpha$ 为探索系数，$B_{ent}$ 为基于答案分布熵的探索奖励，$B_{KG}$ 为惩罚重复检索的 KG 感知奖励，$B_{div}$ 为策略多样性奖励。该公式通过平衡探索与利用，动态选择当前步骤信息量最大的上下文子集，避免全量历史输入导致的窗口溢出与噪声干扰。

## 实验评估

实验在 CWQ、WebQSP 和 WebQuestions 三个基于 Freebase 的 KGQA 数据集上进行，主要指标为 Exact Match (EM) 和 F1。基线覆盖 LLM-only（如 CoT）、微调方法（如 RoG）及智能体框架（如 ToG、PoG）。缺失 2025 年后基于 GNN 或强化学习的最新 SOTA 方法（如 G-reasoner），导致绝对数值对比受限。

| 方法 | CWQ EM | WebQSP EM | WebQuestions EM |
| :--- | :--- | :--- | :--- |
| ToG (GPT-3.5) | 58.9 | 76.2 | 54.5 |
| PoG (GPT-3.5) | 63.2 | 82.0 | 61.7 |
| **VoG (GPT-3.5)** | **64.7** | **83.2** | **63.0** |
| ToG (GPT-4) | 67.6 | 82.6 | 57.9 |
| **VoG (GPT-4)** | **77.6** | **88.7** | **72.3** |

VoG 在 GPT-3.5 和 GPT-4 骨干上均优于 ToG 和 PoG，表明验证机制的有效性不依赖于模型规模。在 GPT-4 上，VoG 在 CWQ 上比 ToG 提升 10.0 个百分点，显示强模型更能利用验证反馈进行有效修正。

| 变体 | CWQ EM | WebQSP EM | WebQuestions EM |
| :--- | :--- | :--- | :--- |
| **VoG** | **64.7** | **83.2** | **63.0** |
| w/o Verify+Revise | 51.7 | 72.1 | 55.8 |
| w/o Context Selector (Local) | 60.1 | 80.6 | 58.2 |
| w/o Context Selector (Global) | 60.2 | 80.3 | 60.6 |

消融实验显示，移除验证与修正模块导致性能大幅下降（CWQ 下降 13.0 点），证实了闭环反馈的核心作用。固定上下文策略中，Local 策略在 WebQSP 上表现最佳，但在全局任务上不如 Global，验证了 MAB 动态选择的必要性。

评估边界方面，论文未报告推理延迟与计算开销，仅定性提及 VoG 比 ToG 更高效。代码已开源，但超参数配置（如 UCB 系数 $\alpha$）未详细披露，可能影响复现性。指标仅包含 EM 和 F1，缺乏对推理路径忠实性的细粒度评估。

## 关联研究分析

从方法设计看，VoG 与 ToG 的核心差异在于对“错误处理”的机制。ToG 依赖固定深度/宽度的图搜索，错误一旦产生即被固化；VoG 通过验证信号触发计划修正，将错误视为可修正的状态而非终止条件。这一差异源于任务特性：多跳推理中，中间步骤的错误往往导致后续路径完全偏离，而 ToG 的静态参数无法适应这种动态偏差。VoG 的 MAB 机制进一步解决了修正时的上下文选择问题，避免了 PoG 中固定上下文策略在复杂查询下的失效。

从问题动机看，VoG 与 G-reasoner 等基础模型化路线形成对比。G-reasoner 通过 GNN 内化图结构，追求跨域泛化；VoG 则坚持外部检索与动态交互，强调推理过程的透明性与可解释性。两者在“结构保真度”与“计算效率”之间做出不同取舍：VoG 牺牲了部分效率（多轮 LLM 调用），换取了对中间推理步骤的显式控制。这种取舍在需要高可靠性、可审计的场景中更具优势，但在实时性要求高的应用中可能受限。

## 总结

VoG 针对 KG 增强 LLM 推理中错误累积与静态检索局限的核心矛盾，通过引入逐步验证与 MAB 驱动的自适应上下文选择，实现了推理计划的动态修正。实验表明，该框架在 GPT-3.5 和 GPT-4 骨干上均优于 ToG 和 PoG，尤其在 GPT-4 上 CWQ 准确率提升 10.0 个百分点，验证了闭环反馈机制的有效性。然而，论文未报告计算开销，且基线缺失 2025 年后的最新 SOTA 方法，限制了绝对性能的评估。当 KG 规模扩大至百万级实体时，MAB 的探索开销与 LLM 调用延迟是否成为主要瓶颈，论文未给出回答。
