> 边缘设备部署大语言模型（LLM）面临算力与功耗的双重瓶颈，传统单加速器部署导致资源错配与高延迟。现有框架多聚焦算法压缩，忽视异构硬件特性与统一内存架构（UMA）下的数据搬运开销。本文提出 NANOMIND，通过模块级动态卸载与软硬协同设计，将视觉编码器与语言模型分别映射至 NPU 与 GPU。该方案在电池供电设备上实现了 20.8 小时续航，但动态调度开销与跨 SoC 泛化性仍存疑。

## 研究背景

边缘端部署多模态大模型（LMM）的核心困境在于硬件资源的极度受限与模型计算需求的刚性增长。现代移动 SoC 采用统一内存架构（UMA），CPU、GPU 与 NPU 共享同一物理 DRAM，这消除了传统服务器架构中独立内存空间带来的 DMA 隔离，但也要求加速器间进行精细的内存访问协调。若将 LMM 视为单体负载部署于单一加速器，不仅无法利用 NPU 在低比特张量运算上的优势，还会因 GPU 处理浮点运算时的低效导致整体延迟激增。

主流边缘推理框架如 llama.cpp 和 MLC-LLM 主要依赖软件层优化，如低比特量化与层间卸载，但这些方法大多沿用服务器架构的设计假设，未针对 UMA 特性进行重构。llama.cpp 在 GPU 可用时仍依赖 CPU 管理数据搬运，导致内存开销增加；MLC-LLM 基于 TVM 编译，资源占用过高，难以在小型设备上运行。此外，现有工作往往只解决量化或调度中的单一环节，缺乏端到端的软硬件协同设计，导致设备无法充分利用可用资源，且功耗管理被长期忽视。NANOMIND 的切入点在于打破“单体模型-单一加速器”的映射范式，利用 LMM 内部组件（视觉编码器、投影层、语言解码器）的相对独立性，实现模块级动态卸载，并通过定制硬件与系统级调度，在严格功耗约束下最大化推理效率。

## 核心方法

### 模块级异构调度参照系

LMM 推理通常遵循“视觉编码-投影-语言解码”的串行流程。传统方法将整个流程绑定于单一加速器，或仅做静态层间划分。本文的关键差异在于将 LMM 解耦为独立可执行模块，并基于各模块的计算特性（计算密集 vs 内存带宽密集）与加速器优势（NPU 擅长低比特整型运算，GPU 擅长大规模浮点并行）进行动态匹配，而非静态绑定。

### 零拷贝令牌感知缓冲管理

传统层间卸载依赖 CPU 进行数据中转，在 UMA 架构下产生冗余内存拷贝与 CPU 瓶颈。NANOMIND 引入令牌感知缓冲管理器（TABM），通过轻量级环形缓冲区实现 NPU 与 GPU 间的零拷贝数据交换。其核心机制是绕过 CPU，直接在共享内存中完成视觉嵌入向量向语言模型输入层的传递。该设计的物理含义是：视觉编码器输出的嵌入向量直接写入 GPU 可访问的共享内存区域，语言模型解码器直接从该区域读取，消除了中间缓冲区分配与数据复制开销。这一机制解决了传统框架中 CPU 作为数据搬运瓶颈导致的延迟累积问题，特别是在高吞吐场景下，显著降低了内存带宽压力。

### 电池感知动态执行策略

静态功耗管理无法适应实时负载波动与电池状态变化。NANOMIND 引入基于电源管理单元（PMU）实时数据的三态动态执行策略。其决策函数可形式化为：

$$
S(t) = \begin{cases}
\text{Full Performance} & \text{if } B(t) > T_{high} \\
\text{Proportional Throttling} & \text{if } T_{low} < B(t) \le T_{high} \\
\text{Low-Power Standby} & \text{if } B(t) \le T_{low}
\end{cases}
$$

其中 $B(t)$ 为实时电池电量，$T_{high}$ 与 $T_{low}$ 为预设阈值。该公式的物理含义是：系统根据电池剩余电量动态调整加速器频率与内存时钟，在高电量时并行卸载以最大化吞吐，在低电量时按比例节流以延长续航。这一设计解决了传统框架在电池供电场景下因固定频率运行导致的过早耗尽问题，实现了性能与寿命的实时权衡。

## 实验评估

实验在基于 RK3566 SoC 的定制电池供电原型机上进行，对比基线包括 llama.cpp、MLC-LLM 和 PowerInfer-2。基线覆盖了主流开源框架与 NPU-CPU 协作方案，但缺失针对 NPU 静态形状限制的专用优化框架（如 llm.npu）的直接对比，可能低估了 NANOMIND 在特定 NPU 场景下的相对优势。

| Qwen2-VL-2B | 4-bit | NANOMIND | 35.7 | - | 0.375 |

*注：NANOMIND 在吞吐量上与 Jetson Nano 持平，但端到端延迟比 Orange Pi 5 Ultra 低 36.2%。功耗数据仅在低功耗模式下报告。*

消融实验显示，零拷贝 TABM 相比传统 CPU 拷贝显著降低了视觉编码阶段的 CPU 利用率与内存占用。混合量化策略中，视觉编码器采用 FP16/8-bit 而 LLM 采用 4-bit 的配置，在精度损失可忽略的前提下，实现了内存占用的最优平衡。线性注意力替换二次注意力未带来统计显著的精度下降，但稳定了长序列解码延迟。

评估边界方面，论文未报告置信区间，数值比较需谨慎。实验仅在 RK3566 与 RK3588 上验证，缺乏在 Apple Silicon 或 Qualcomm 高端 SoC 上的跨平台泛化性测试。代码未公开，且硬件定制（PMU、并行 LPDDR4x）限制了结果的可复现性，其他研究者难以在通用设备上复现相同的能效比。

## 关联研究分析

从问题动机看，NANOMIND 与 PowerInfer-2 均关注 NPU 与 CPU 的协作，但 PowerInfer-2 基于神经元激活密度进行静态卸载，而 NANOMIND 引入了基于电池状态的动态调度。这一差异源于任务特性：PowerInfer-2 面向云端或插电设备，追求峰值吞吐；NANOMIND 面向电池供电设备，追求能效比。根源在于 PowerInfer-2 未将功耗作为一等公民，而 NANOMIND 将 PMU 数据纳入调度决策，这是边缘部署场景下的必要适配。

从方法设计看，NANOMIND 与 SpikeMLLM 均追求极致能效，但 SpikeMLLM 依赖神经形态硬件的脉冲神经网络（SNN）架构，而 NANOMIND 基于通用 SoC 的 GPU/NPU 异构调度。SpikeMLLM 的 25.8 倍功耗优势源于硬件范式的根本改变，而 NANOMIND 的 42.3% 能耗降低源于系统级优化。这一差异暗示：在通用硬件上，软件-硬件协同设计的能效提升存在上限，若需突破该上限，可能需要更激进的硬件架构变革，如 SNN 或专用加速器。

## 总结

NANOMIND 解决了边缘设备部署 LMM 时硬件资源错配与功耗失控的核心矛盾。其切入点在于利用 LMM 的模块独立性，通过模块级动态卸载与软硬协同设计，打破了传统单体部署的局限。该方法在 RK3566 平台上实现了 35.7 tok/s 的吞吐量与 0.375 W 的低功耗，证明了在通用 SoC 上通过系统优化即可显著提升能效。然而，其边界在于硬件定制依赖性强，且动态调度在高频切换下的上下文开销未充分量化。当 SoC 的 NPU 与 GPU 性能差距缩小，或电池技术突破导致功耗约束放宽时，模块级动态调度的边际收益是否递减，论文未给出回答。
