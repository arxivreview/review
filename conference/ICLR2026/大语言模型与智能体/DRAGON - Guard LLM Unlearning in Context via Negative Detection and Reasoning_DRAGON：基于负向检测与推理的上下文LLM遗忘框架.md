> 导读 大语言模型（LLM）在部署后面临持续到达的遗忘请求，但现有基于微调的方法依赖保留数据且计算成本高昂，难以应用于黑盒模型。DRAGON 提出一种无需修改模型权重、不依赖保留数据的上下文干预框架，通过前置检测模块识别敏感查询，并动态生成思维链（Chain-of-Thought, CoT）指令引导模型拒绝回答。该方法在 TOFU 和 WMDP 基准上实现了低偏差分数与高拒绝质量，但其行为抑制机制是否真正擦除了内部知识表征，仍缺乏对抗性验证。

## 研究背景

当 LLM 接收用户查询时，系统需判断该查询是否涉及需遗忘的隐私或有害内容。这一判断过程称为遗忘提示检测，其难点在于真实查询往往经过改写或语义变体，导致基于精确匹配的过滤失效。为应对分布偏移，检测器需结合语义相似度与分类置信度，形成统一的置信分数。若检测通过，系统需生成符合安全策略的拒绝响应，而非简单替换为静态模板，以维持对话的上下文连贯性。

主流 LLM 遗忘方法分为训练基与无训练两类。训练基方法如负偏好优化（Negative Preference Optimization, NPO）通过梯度更新平衡遗忘与保留，但需访问保留集数据且计算开销大，无法适配 GPT-4 等专有黑盒模型。无训练方法如 Guardrail+ 通过提示工程引导模型拒绝，但静态模板导致响应与查询上下文脱节，一致性分数差距达 0.44。DRAGON 的切入点在于构建“检测-推理”双模块系统，利用轻量级检测器拦截敏感查询，并通过专用守卫模型动态生成 CoT 指令，在推理时实现软约束遗忘，规避了参数更新对通用能力的损害。

## 核心方法

### 方法参照系

本文问题属于无训练 LLM 遗忘范畴，与标准参数微调流程的关键差异在于：不修改模型权重 $\theta$，而是通过输入侧的上下文干预 $U(x)$ 改变模型输出分布，适用于黑盒 API 场景。

### 双层级遗忘提示检测

检测模块位于推理流程前端，通常做法是使用单一分类器判断查询是否属于遗忘集。本文创新在于采用“评分模型+相似度指标”的双信号融合机制，解决单一分类器在改写攻击下的鲁棒性不足问题。给定用户查询 $x$ 和遗忘存储库 $D_u$，置信分数 $f(x, D_u)$ 计算如下：

$$ f(x, D_u) = \alpha \cdot \text{Score}_{model}(x) + (1-\alpha) \cdot \max_{d \in D_u} \text{CosSim}(x, d) $$

其中 $\text{Score}_{model}$ 为训练评分模型的输出，$\text{CosSim}$ 为查询与存储库中改写提示的最大余弦相似度。当 $f(x, D_u) > \tau$ 时触发干预。该设计通过相似度项捕捉语义变体，通过评分项抑制误报，在 WMDP-bio 数据集上检测准确率达 98.9%，优于 RoBERTa 分类器的 84.2%。

### 动态 CoT 守卫指令生成

检测通过后，系统需生成引导模型拒绝的指令。通常做法是预存静态拒绝模板，但会导致响应缺乏上下文相关性。本文创新在于使用微调的守卫模型动态生成 CoT 指令，解决静态模板导致的上下文脱节问题。设查询 $x$ 和检索到的安全策略 $p$，守卫模型生成指令 $g(x, p)$，最终输入为：

$$ \tilde{x} = \text{Context}(p) \oplus \text{Instruction}(g(x, p)) \oplus x $$

其中 $\oplus$ 表示拼接，$\text{Context}(p)$ 为策略上下文，$\text{Instruction}(g)$ 为“逐步思考”引导的 CoT 指令。该机制利用 LLM 固有的指令跟随能力，使拒绝响应与查询语义对齐。消融实验显示，移除 CoT 后一致性分数差距（CS gap）从 0.01 恶化至 0.29，证明动态推理对维持上下文连贯性的关键作用。

## 实验评估

实验在 TOFU（虚构作者遗忘）、WMDP（危险知识遗忘）和 MUSE（版权内容遗忘）三个基准上进行，基线覆盖梯度上升（GA）、NPO、RMU 等训练基方法及 Filter-Prompting、ICUL+ 等无训练方法，但缺失 SAE-Guided 等机制级编辑方法对比。

| 方法 | TOFU-1% DS (↓) | TOFU-1% MU (↑) | WMDP-bio ProbAcc (↓) | WMDP-bio RQ (↑) |
| :--- | :--- | :--- | :--- | :--- |
| NPO-RT | 46.4 | 0.6329 | 54.9 | 0.342 |
| Filter-Prompting | 43.5 | 0.6337 | 48.0 | 0.342 |
| ICUL+ | 58.1 | 0.6337 | 63.6 | 0.424 |
| DRAGON | 21.4 | 0.6337 | 26.2 | 0.921 |

DRAGON 在 TOFU-1% 上取得最低偏差分数 21.4，显著优于 NPO-RT 的 46.4，且模型效用（MU）保持 0.6337 不变。在 WMDP-bio 上，DRAGON 的概率准确率（ProbAcc）降至 26.2，拒绝质量（RQ）达 0.921，远高于 RMU 的 0.411，表明其在抑制危险知识输出的同时维持了响应连贯性。

| 方法 | TOFU-1% CS (Δ) | TOFU-5% CS (Δ) | TOFU-10% CS (Δ) |
| :--- | :--- | :--- | :--- |
| Guardrail+ | 0.44 | 0.44 | 0.43 |
| DRAGON w/o CoT | 0.29 | 0.28 | 0.25 |
| DRAGON | 0.01 | 0.03 | 0.02 |

消融实验揭示 CoT 指令对上下文一致性的决定性影响。Guardrail+ 的静态模板导致 CS gap 高达 0.44，而 DRAGON 的动态 CoT 将差距压缩至 0.01-0.03。移除 CoT 后，CS gap 回升至 0.25-0.29，说明推理过程是维持响应与查询语义对齐的关键，而非简单的拒绝标签。

评估边界方面，论文未报告重学习攻击或 Top-k 采样下的泄露率，无法验证遗忘的机制深度。代码未公开，但提供了详细的提示模板和超参数设置（$\beta=0.5$），具备可复现性。指标设计引入了动态偏差分数（DDS）和动态效用分数（DUS），弥补了静态指标在持续遗忘场景下的不足，但未与领域共识中的鲁棒性评估协议（如 Leak@k）对齐。

## 关联研究分析

从问题动机看，DRAGON 与 NPO 等训练基方法的核心差异在于数据依赖性与部署场景。NPO 需访问保留集以平衡遗忘与保留，适用于白盒模型的全参数微调；DRAGON 仅依赖改写后的负向数据，适用于黑盒 API 的推理时干预。这一差异源于任务特性：NPO 追求参数级的知识擦除，而 DRAGON 追求行为级的输出抑制。DRAGON 在 WMDP 上的高 RQ 分数表明，对于合规性要求较高的场景，行为抑制可能比参数擦除更具性价比，但其是否满足 GDPR 对“不可逆擦除”的严格定义，论文未给出理论证明。

从方法设计看，DRAGON 与 Guardrail+ 同属无训练路线，但 Guardrail+ 采用静态模板替换，DRAGON 采用动态 CoT 生成。Guardrail+ 的 CS gap 0.44 暴露了静态模板在上下文理解上的缺陷，而 DRAGON 通过守卫模型动态生成指令，将 CS gap 降至 0.01。这一改进的根源在于 LLM 的指令跟随能力：动态 CoT 使模型能够根据具体查询调整拒绝策略，而非机械执行固定模板。然而，DRAGON 的检测模块依赖预构建的遗忘存储库，当遗忘请求涉及全新概念时，存储库需更新，这可能引入延迟。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

DRAGON 解决了黑盒 LLM 在缺乏保留数据条件下的可部署遗忘问题，通过“检测+推理”双模块实现推理时干预，规避了参数微调的高昂成本。在 TOFU 上，DRAGON 的偏差分数 21.4 显著低于 NPO-RT 的 46.4，且在 WMDP 上取得 0.921 的拒绝质量，证明了其在行为抑制层面的有效性。然而，论文未进行重学习攻击或概率解码下的泄露测试，无法验证内部知识是否真正擦除，仅证明了输出层面的合规性。当遗忘请求涉及语义高度纠缠的概念时，动态 CoT 指令是否仍能精准区分目标知识与良性知识，论文未给出回答。
