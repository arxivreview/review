# ICLR2026最新论文 ｜TOOLS ARE UNDER DOCUMENTED: SIMPLE DOCU MENT EXPANSION BOOSTS TOOL RETRIEVAL ｜工具文档扩充提升检索性能

研究机构：上海交通大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_26233469)

> 工具检索面临查询与文档语义重叠不足的瓶颈，现有方法多通过查询重写或模型优化绕开问题，却忽视了工具文档本身的不标准化与信息缺失。本文提出 TOOL-REX 框架，通过 LLM 管道系统性扩充工具文档的结构化字段，并基于此训练专用检索器与重排器。该方案在 TOOL-REX 基准上刷新了 SOTA，但其收益高度依赖扩充字段的质量，且未验证在动态噪声环境下的鲁棒性。

## 研究背景

当 LLM 面对数千个 API 时，准确选择工具的前提是检索模型能理解用户意图与工具功能的映射。然而，用户查询往往模糊且口语化，而工具文档多为技术化、碎片化的描述，两者间存在显著的语义鸿沟。这种不匹配导致检索模型难以捕捉真实相关性，尤其是在分布外（OOD）场景下，模型泛化能力急剧下降。

工具检索作为智能体能力的前置瓶颈，其精度直接决定后续编排的输入质量。主流路线如 Re-Invoke 和 EASYTOOL 试图通过生成伪查询或简化文档来缓解这一矛盾，但这些方法本质上是在“修补”数据，而非“修复”数据源。它们假设文档是完整的，只是表达形式不佳，却忽略了大量文档缺失关键的使用场景、限制条件等核心信息。这种数据源层面的缺陷构成了现有检索模型的性能天花板，使得即使使用更大的骨干网络，也难以突破语义对齐的局限。

本文的切入点在于将问题根源从“检索模型能力不足”转向“工具文档质量缺陷”。通过引入 LLM 驱动的文档扩充管道，本文旨在从源头补全缺失的结构化信息，为检索模型提供更丰富、更一致的语义监督信号。这一视角转换不仅解释了为何现有方法在 OOD 任务上表现脆弱，也为构建大规模、高质量的检索训练语料提供了可行路径。

## 核心方法

### 方法参照系

标准工具检索流程通常包含查询嵌入、向量相似度计算及可选的重排阶段。该流程假设输入文档已具备足够的语义完整性，模型仅需学习查询与文档间的映射关系。本文的关键差异在于，在检索流程之前插入一个“文档扩充”前置步骤，将原始文档转化为包含结构化字段的增强文档，从而改变检索的输入分布。

### 文档扩充管道

设计动机在于解决原始文档中“when-to-use”场景缺失和描述不标准化导致的检索失败。本文构建了一个四阶段管道：首先使用 Qwen3-32B 生成包含功能描述、标签、使用场景、限制条件和示例用法的结构化档案；随后利用 LLaMa-3.1-70B 进行语义忠实性判断，确保无幻觉内容；对约 1.5% 的失败案例使用 GPT-4o 进行精炼；最后通过人工验证确认质量。扩充后的文档定义为原始文档与生成档案的并集：

$$ d_{expansion} = d_{original} \cup d_{profile} $$

这一设计通过补充缺失的语义钩子，使文档从“静态描述”转变为“动态功能说明书”，显著提升了与多样化查询的匹配潜力。

### 专用模型训练

基于扩充文档，本文训练了检索器 Tool-Embed 和重排器 Tool-Rank。Tool-Embed 采用 Qwen3-Embedding 系列作为骨干，使用 InfoNCE 损失进行全参数微调，每个查询-工具对随机采样 5 个负样本。Tool-Rank 基于 Qwen3-Reranker-4B，采用 LoRA 适配（rank=32, alpha=64），以交叉熵为目标函数。重排阶段通过计算“true”与“false” token 的 logits 概率作为相关性得分：

$$ P(relevant) = \frac{\exp(\ell_{true})}{\exp(\ell_{true}) + \exp(\ell_{false})} $$

该公式将二分类问题转化为概率估计，使得重排器能够更精细地区分高相关与低相关文档，弥补了向量检索在细粒度排序上的不足。

## 实验评估

实验在 ToolRet 和自建 TOOL-REX 基准上进行，后者包含 Web、Code 和 Customized 三类工具，其中 Code 和 Customized 仅用于测试以验证 OOD 泛化。基线覆盖了 BM25s、GritLM-7B、Qwen3-Embedding 系列及主流重排器，但未包含 CoHyDE 等协同训练方法。

| 模型 | ToolRet N@10 | ToolRet R@10 | ToolRet C@10 | TOOL-REX N@10 | TOOL-REX R@10 | TOOL-REX C@10 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3-Embedding-8B | 45.54 | 57.36 | 47.27 | 45.65 | 56.13 | 46.04 |
| Tool-Embed-4B (ours) | 51.51 | 62.80 | 51.02 | 52.23 | 63.13 | 51.61 |
| Tool-Rank-4B (ours) | 52.37 | 63.26 | 52.40 | 56.44 | 67.81 | 56.60 |

Tool-Embed-4B 在 TOOL-REX 上以 52.23 的 NDCG@10 超越 Qwen3-Embedding-8B 的 45.65，证明小模型在高质量数据增强下可超越大模型基线。Tool-Rank-4B 进一步将 NDCG@10 提升至 56.44，较检索器阶段提升 4.21 个点，表明重排器在结构化文档上能更有效地利用语义线索。

消融实验显示，移除“example usage”字段反而提升了性能，而“function description”和“tags”的贡献最为显著。这表明并非所有扩充字段都有益，冗余信息可能稀释关键信号。此外，在原始 ToolRet 上，扩充文档训练出的模型仍优于未扩充模型，说明扩充提供的语义监督具有跨域迁移性。

评估边界方面，本文仅使用静态文档，未考虑工具执行反馈或动态环境变化。代码已开源，但训练数据仅来自 Web 类工具，Code 和 Customized 类的泛化能力虽被验证，但缺乏在真实噪声环境下的鲁棒性测试。

## 关联研究分析

从问题动机看，本文与 Re-Invoke 和 EASYTOOL 形成互补。Re-Invoke 通过生成伪查询来弥合语义鸿沟，侧重于查询端的增强；而本文直接作用于文档端，通过补全缺失信息来丰富文档的语义表达。这种差异源于对瓶颈的不同诊断：前者假设文档完整但表达晦涩，后者假设文档本身信息缺失。本文的方法在文档质量参差不齐的场景下更具优势，因为查询重写无法凭空生成文档中不存在的使用场景或限制条件。

从方法设计看，本文与 CoHyDE 等协同训练方法存在显著差异。CoHyDE 通过迭代优化检索器与编排器的交互来提升性能，属于系统级协同；而本文聚焦于静态数据增强，未涉及检索与编排的联合优化。这种选择使得本文方法更易于部署，但可能限制了其在复杂多步任务中的潜力。文档扩充能否替代 RLVR 在 OOD 任务上的优势，论文未给出回答，这暗示了数据增强与策略优化之间可能存在尚未探索的协同空间。

## 总结

本文针对工具检索中文档信息缺失导致的语义鸿沟，提出了 TOOL-REX 框架，通过 LLM 管道扩充文档结构化字段，并训练专用模型。实验证明，该方案在 TOOL-REX 上实现了 56.44 的 NDCG@10，显著优于现有基线。然而，本文的边界在于仅验证了静态文档增强在离线基准上的效果，未探讨在动态、噪声环境下的鲁棒性，也未分析扩充字段与强化学习训练的协同作用。当工具库规模进一步扩大且文档质量更加参差不齐时，静态扩充的边际收益是否递减，论文未给出回答。
