# ICLR2026最新论文 ｜Catalog-Native LLM: Speaking Item-ID Dialect with Less Entanglement for Recommendation ｜解耦协同与语义的混合专家推荐模型

研究机构：英国剑桥大学

作者：Reza Shirkavand、Xiaokai Wei、Chen Wang 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.05125)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.05125)

> 推荐系统需同时利用协同过滤的精准性与大语言模型（LLM）的语义泛化能力，但二者在共享参数空间时易产生知识干扰，导致推荐精度与语言理解能力双降。现有方法多通过投影层或简单词表扩展融合信号，未能从架构层面隔离模态冲突。本文提出 IDIOMoE，将 LLM 的前馈网络（FFN）拆分为文本专家与物品专家，通过静态 Token-Type 门控实现模态解耦。该设计在工业级数据上显著提升了推荐指标，但静态路由机制在复杂动态场景下的适应性仍存疑。

## 研究背景

推荐任务的核心矛盾在于协同信号（Collaborative Signals）的稀疏性与 LLM 语义空间的稠密性之间的分布差异。当物品 ID 被直接嵌入 LLM 词表时，ID 令牌携带的协同偏好模式与文本令牌承载的语义知识在共享的 FFN 层中发生纠缠。这种纠缠导致模型在处理 ID 序列时破坏了预训练的语言理解能力，或在处理文本时无法有效捕捉协同过滤的隐式偏好。为缓解此问题，早期工作尝试通过外部编码器生成文本偏差（Text-derived Bias）或显式插入属性文本，但前者牺牲了对话能力，后者增加了序列长度且未解决参数共享带来的干扰。

主流生成式推荐架构如 TIGER 和 P5 将推荐重构为自回归生成任务，但通常依赖复杂的量化编码或统一的文本到文本范式，未显式区分 ID 与文本的处理路径。HSTU 等工业级模型虽规模庞大，但缺乏 LLM 的指令遵循与解释能力。本文切入点在于识别出“参数共享导致的模态干扰”是性能瓶颈的关键，而非单纯的容量不足。通过引入混合专家（Mixture-of-Experts, MoE）机制，将协同信号视为一种独立的“方言”，在架构层面实现文本与物品的物理隔离，从而在保持 LLM 语义完整性的同时，高效建模协同偏好。

## 核心方法

### 方法参照系

本文基于 Qwen2.5-0.5B 骨干网络，扩展词表以包含物品 ID 令牌。与标准 LLM 推荐流程（如 P5）不同，本文不将 ID 视为普通文本令牌参与统一的 FFN 计算，而是将其视为需要独立处理路径的特殊模态。关键差异在于：标准流程中所有令牌共享同一组 FFN 参数，而本文在每一层 Transformer 中引入双专家结构，根据令牌类型路由至不同 FFN。

### 双专家 FFN 架构与静态门控

在标准 Transformer 块中，FFN 层负责存储和转换特征信息。本文将该层替换为两个独立的 FFN：保留预训练 LLM 的原始 FFN 作为“文本专家”（Text Expert），新增一个可训练的 FFN 作为“物品专家”（Item Expert）。路由机制采用静态 Token-Type 门控，即仅当输入令牌为物品 ID（`<|it-id|>`）时激活物品专家，其余令牌（标题、属性、指令）激活文本专家。

$$
\text{FFN}_{\text{out}}(x) = \begin{cases}
\text{FFN}_{\text{item}}(x) & \text{if } x \in \mathcal{V}_{\text{item}} \\
\text{FFN}_{\text{text}}(x) & \text{if } x \in \mathcal{V}_{\text{text}}
\end{cases}
$$

该公式表明，每个令牌仅通过单一专家进行前馈计算，避免了参数竞争。设计动机在于解决共享参数导致的“知识干扰”：协同信号具有高度稀疏性和特定性，若与通用语义共享参数，会迫使模型在拟合 ID 模式时扭曲语义表示。静态门控确保了计算复杂度与基座模型相当，同时实现了模态的物理隔离。

### 混合嵌入层与输出头

为支持 ID 令牌的嵌入与生成，本文构建了混合嵌入层（Hybrid Embedding Layer）。该层由冻结的文本嵌入矩阵和可训练的物品嵌入表组成。对于物品 ID 令牌，其嵌入向量直接取自物品嵌入表；对于文本令牌，则使用预训练文本嵌入。输出头复用相同的混合参数化结构，使模型能够直接生成物品 ID。

$$
E(x) = \begin{cases}
E_{\text{item}}(x) & \text{if } x \in \mathcal{V}_{\text{item}} \\
E_{\text{text}}(x) & \text{if } x \in \mathcal{V}_{\text{text}}
\end{cases}
$$

这一设计确保了输入端的模态分离与输出端的生成能力一致。通过冻结文本嵌入，模型保留了预训练的世界知识；通过独立训练物品嵌入，模型能够学习协同过滤所需的特定 ID 表示。这种分离避免了 ID 嵌入对文本语义空间的污染，使得模型在生成解释时仍能保持语言流畅性，而在生成 ID 时能精准捕捉用户偏好。

## 实验评估

实验在 Amazon 系列数据集（Games, Instruments, Arts, Sports, Beauty, Toys）及 Roblox 工业级数据集上进行，评估指标为 NDCG@10、HR@10 和 MRR。基线覆盖经典序列模型（SASRec, HSTU）、生成式推荐（TIGER, P5, VIP5）及 LLM 适配方法（E4SRec, ReAT, CoVE）。在 Amazon Beauty 数据集上，IDIOMoE 取得 NDCG@10 0.0665 和 HR@10 0.1104，优于 SASRec（0.0541/0.0945）和 HSTU（0.0542/0.0958），也显著高于 P5-CID（0.0662/0.0994）。在工业级数据集上，相比 SASRec 基线，IDIOMoE 的 NDCG@10 提升 27.1%，HR@10 提升 16.6%，MRR 提升 31.2%，验证了架构解耦在大规模场景下的有效性。

| 数据集 | 方法 | NDCG@10 | HR@10 |
| :--- | :--- | :--- | :--- |
| Amazon Beauty | SASRec | 0.0541 | 0.0945 |
| Amazon Beauty | HSTU | 0.0542 | 0.0958 |
| Amazon Beauty | P5-CID | 0.0662 | 0.0994 |
| Amazon Beauty | IDIOMoE | 0.0665 | 0.1104 |
| Industrial | SASRec (Baseline) | - | - |
| Industrial | IDIOMoE (Δ%) | +27.1% | +16.6% |

消融实验揭示了关键设计决策的影响。在 Amazon Beauty 上，将 MoE 层置于最后 8 层比置于前 8 层带来更高的增益（NDCG@10 +28.4% vs +10.3%），表明深层网络中任务特定语义与协同模式更为显著，更适合专家分离。静态路由策略相比动态路由在 NDCG@10 上高出 59.5%（Amazon Beauty），证明对于 ID/Text 这种二元模态，简单的类型门控比复杂的动态路由更有效且稳定。此外，扩大物品专家容量（Shrink=8）在 Amazon Beauty 上带来 +41.8% 的 NDCG@10 提升，但在工业数据集上反而下降 3.1%，暗示工业数据中协同信号的稀疏性限制了额外容量的收益。

评估边界方面，论文未提供代码开源链接，且工业数据集细节（如具体用户数、物品数）未完全披露，限制了可复现性。指标仅关注排序质量（NDCG/HR），未评估生成解释的忠实度或对话推荐的交互质量，这与 LLM 推荐强调可解释性的趋势存在差距。此外，实验主要基于 0.5B 和 1.5B 小模型，未验证该架构在更大规模 LLM（如 7B+）上的可扩展性。

## 关联研究分析

从问题动机看，本文与 TIGER 和 P5 的核心差异在于对“协同信号”的处理方式。TIGER 依赖 RQ-VAE 将物品量化为离散语义 ID，试图在语义空间内对齐协同信号；P5 则通过文本到文本范式，将 ID 视为普通文本。本文认为这两种方法都未解决参数共享导致的模态干扰，因此选择架构级解耦。根源在于 TIGER 和 P5 假设协同信号可以被语义空间完全表征，而本文实验表明，ID 令牌具有独特的统计特性，需要独立的参数空间来避免对语义空间的破坏。

从方法设计看，本文与 HSTU 和 OneRec 等工业级生成式推荐模型形成对比。HSTU 采用大规模 Transformer 直接处理 ID 序列，虽规模大但缺乏 LLM 的语义理解能力；OneRec 使用稀疏 MoE 编码器-解码器，但主要关注训练效率而非模态解耦。本文的 IDIOMoE 借鉴了 MoE 的稀疏激活思想，但将其应用于模态分离而非单纯的容量扩展。这种设计使得模型在保持 LLM 指令遵循能力的同时，实现了高效的 ID 建模。然而，静态路由的局限性在于无法处理 ID 与文本混合的复杂上下文，例如当用户查询同时包含自然语言描述和特定 ID 时，模型无法动态调整专家权重，这可能限制了其在多轮对话推荐中的灵活性。

## 总结

本文旨在解决 LLM 推荐中协同信号与语义知识在共享参数空间中的干扰问题。现有方法如 TIGER 和 P5 通过语义对齐或文本化 ID 来融合信号，但未能从架构层面隔离模态冲突，导致推荐精度与语言理解能力难以兼得。本文提出 IDIOMoE，通过静态 Token-Type 门控将 FFN 拆分为文本专家与物品专家，实现了模态的物理隔离。实验表明，该架构在 Amazon Beauty 上取得 NDCG@10 0.0665，在工业数据集上相比 SASRec 提升 27.1% NDCG@10，验证了解耦设计的有效性。然而，静态路由机制无法适应动态变化的上下文，且实验仅在小规模模型上进行，未验证其在大规模 LLM 和复杂对话场景中的泛化能力。当用户查询包含混合模态信息时，静态门控是否会导致信息损失，论文未给出回答。
