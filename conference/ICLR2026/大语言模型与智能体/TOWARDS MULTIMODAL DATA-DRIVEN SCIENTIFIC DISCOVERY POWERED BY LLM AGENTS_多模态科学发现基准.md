# ICLR2026最新论文 ｜TOWARDS MULTIMODAL DATA-DRIVEN SCIENTIFIC DISCOVERY POWERED BY LLM AGENTS ｜多模态科学发现基准

研究机构：香港科技大学

作者：Fan Liu、Xiaozhao Zeng、Hao Liu

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_15834911)

> 现有科学发现基准局限于单模态数据与切片级任务，无法评估智能体在真实科研中整合异构数据、执行跨模态推理的能力。MoSciBench 通过从同行评审文献构建 88 个仓库级多模态任务，强制智能体完成数据对齐、建模与假设验证的全流程。实验表明，即使最强智能体准确率仅 48.4%，且超过 60% 的错误源于跨模态对齐失败，揭示了当前 LLM 智能体在异构数据融合上的根本瓶颈。该基准填补了多模态科学发现评测的空白，但其精确匹配评估协议是否足以捕捉科学推理的深层逻辑，仍存疑。

## 研究背景

当智能体面对包含卫星图像、气候时序与表格测量的混合数据仓库时，其首要挑战并非模型选择，而是将不同格式、尺度与分辨率的数据映射到共享的计算表示——这一过程称为跨模态对齐。对齐失败会导致后续建模与推理建立在错误的数据关联上，例如将特定地理网格的降水数据与错误的图像区域关联，使得统计检验结果完全失真。因此，评估智能体科学发现能力的关键，不在于其能否生成代码，而在于其能否在异构数据间建立正确的语义与空间对应关系。

数据驱动的科学发现已从人工构建工作流向自动化智能体演进，但现有评测体系存在结构性缺失。ScienceAgentBench 与 DiscoveryBench 等基准虽形式化了数据准备、分析与验证流程，但每个任务仅绑定单一数据类型（如纯表格或单时序），且任务粒度局限于数据切片而非完整仓库。这种单模态、碎片化的设计掩盖了真实科研中多模态整合的复杂性，导致智能体在孤立模态上的高分无法迁移至跨模态场景。MoSciBench 的切入点在于将评测单元从“单模态切片”扩展为“多模态仓库”，要求智能体自主处理从数据加载、对齐到假设验证的端到端工作流，从而暴露当前智能体在异构数据融合上的真实能力边界。

## 核心方法

### 任务形式化与跨模态对齐

MoSciBench 将科学发现任务定义为跨模态假设验证工作流，其核心差异在于强制智能体在执行建模前完成异构数据的对齐。传统基准中，数据预处理是预设步骤，智能体仅需处理已对齐的单一模态数据；而在本基准中，对齐是智能体必须自主解决的子任务。每个任务由任务指令、多模态数据集与评估协议组成，其中数据集涵盖七种模态，包括多传感器时序、表格数据、卫星图像、质谱、分子结构、基因型矩阵与 HDF 矩阵。智能体必须通过共享索引（如主体 ID 或地理网格）将不同模态的数据关联起来，例如将生理信号与环境变量通过时间戳对齐，或将卫星图像与气象数据通过空间坐标匹配。这一设计直接针对现有基准中“对齐被隐式完成”的假设，将数据融合从背景条件提升为被评估的核心能力。

### 四阶段构建流水线

为确保任务的真实性与可验证性，MoSciBench 采用四阶段流水线从同行评审文献中构建任务。第一阶段提取原始数据，筛选发布数据集且提出明确数据驱动科学问题的论文；第二阶段进行多模态处理与对齐，通过特征过滤、多源整合与标准化，将异构数据转换为可计算格式；第三阶段制定任务指令与标注，将科学问题转化为简洁的指令，并指定可验证的假设与答案格式；第四阶段进行人工验证与质量控制，通过端到端可执行脚本复现工作流，确保标注与金标准假设的一致性。该流程的关键在于，所有任务均源自真实科研场景，而非合成数据，且经过多轮人工验证，保证了假设的科学有效性与答案的客观性。

### 评估协议与指标设计

MoSciBench 采用假设中心评估，以精确匹配准确率作为核心指标，辅以代码执行成功率与建模合理性评分。精确匹配要求智能体输出与参考答案完全一致，对于数值型答案应用任务特定的容差（如精度或顺序），以确保评估的公平性与可复现性。建模合理性由 LLM 作为评判者，对智能体的工作流进行 1-5 分评分，涵盖变量选择、模型设计与分析推理的科学性。这种评估设计将“结果正确性”与“过程合理性”分离，避免了仅关注最终答案而忽略推理路径的缺陷。然而，精确匹配对数值型答案的容差设置可能影响评估的严格性，例如在预测建模任务中，RMSE 的微小差异可能导致答案被判定为错误，这在一定程度上限制了评估对模型细微差异的敏感度。

## 实验评估

实验在 MoSciBench 的 88 个任务上评估了四种智能体框架（ReAct、DataVoyager、Reflexion、SelfDebug、RAG-ReAct）与四种 LLM（Qwen3-30B-A3B、DeepSeek-V3.1、gpt-5-mini、o4-mini）的组合。基线覆盖了主流的单模态发现智能体，但缺失专用多模态科学模型（如 S1-Omni），这可能低估了多模态基础模型在跨模态对齐上的潜力。主实验结果显示，o4-mini 与 ReAct 组合取得最高准确率 48.4%，而 NoDataGuess 基线（无数据驱动）准确率降至 0.0%-10.5%，证实数据接地是科学发现的必要条件。

| 模型 | 框架 | 整体准确率 | 代码执行成功率 | 建模合理性 |
| :--- | :--- | :--- | :--- | :--- |
| o4-mini | ReAct | 0.484 | 1.000 | 3.75 |
| o4-mini | Reflexion | 0.458 | 0.589 | 3.65 |
| DeepSeek-V3.1 | ReAct | 0.365 | 1.000 | 3.63 |
| Qwen3-30B-A3B | RAG-ReAct | 0.373 | 1.000 | 3.64 |

错误分析表明，对齐错误占 31.8%，建模错误占 15.9%，推理错误仅占 3.4%，证实跨模态对齐是主要瓶颈。消融实验显示，轻量级工作流脚手架（Workflow Scaffolding）比领域知识注入更有效，平均提升准确率 5.7%，降低对齐错误 5-10%。这一发现暗示，显式的任务分解比提供额外领域知识更能帮助智能体处理异构数据，因为对齐失败主要源于流程混乱而非知识缺失。

评估协议采用精确匹配准确率，缺乏对推理路径透明性与可证伪性的过程级指标，这与领域共识中强调的过程评估存在差异。代码与数据已开源，但实验未报告计算效率指标（如 Token 消耗或推理延迟），限制了其在实际部署中的可复现性评估。

## 关联研究分析

从问题动机看，MoSciBench 与 ScienceAgentBench 的核心差异在于任务粒度与模态多样性。ScienceAgentBench 聚焦于单模态数据切片，评估智能体在孤立模态上的分析能力；而 MoSciBench 强制仓库级多模态整合，将对齐作为独立评估环节。这一差异源于任务特性：真实科学发现（如气候研究）天然涉及多模态数据，单模态评测无法捕捉跨模态推理的复杂性。然而，MoSciBench 未探索专用多模态基础模型（如 S1-Omni）在跨模态对齐上的表现，这可能掩盖了基础模型架构对对齐能力的潜在贡献。

从方法设计看，MoSciBench 与 DiscoveryBench 均形式化了数据驱动发现工作流，但 MoSciBench 在任务构建上更强调真实性与可验证性。DiscoveryBench 的任务多基于合成数据或简化场景，而 MoSciBench 直接源自同行评审文献，并通过四阶段流水线确保假设的科学有效性。这一设计选择解决了现有基准中任务与真实科研脱节的问题，但引入了任务复杂度与评测噪声的权衡：仓库级任务可能导致智能体在数据预处理上消耗大量计算资源，从而掩盖其核心推理能力。此外，MoSciBench 未采用过程级评估指标（如推理路径透明度），这与领域共识中强调的可证伪性评估存在差距，可能低估了智能体在科学推理过程中的逻辑严谨性。

## 总结

MoSciBench 解决了现有科学发现基准无法评估多模态仓库级任务的核心矛盾，通过从同行评审文献构建 88 个跨模态假设验证任务，强制智能体完成数据对齐、建模与推理的全流程。实验证明，当前 LLM 智能体在多模态科学发现上表现有限，最强配置准确率仅 48.4%，且超过 60% 的错误源于跨模态对齐失败，揭示了异构数据融合是主要瓶颈。该基准的边界在于其精确匹配评估协议缺乏过程级指标，且未评估专用多模态基础模型，可能低估了基础模型架构对对齐能力的贡献。当智能体在仓库级任务中消耗大量计算资源于数据预处理时，其核心推理能力是否被掩盖，论文未给出回答。
