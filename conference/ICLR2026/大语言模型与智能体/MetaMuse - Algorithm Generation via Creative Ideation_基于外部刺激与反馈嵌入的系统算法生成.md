# ICLR2026最新论文 ｜MetaMuse: Algorithm Generation via Creative Ideation ｜基于外部刺激与反馈嵌入的系统算法生成

研究机构：美国加州大学伯克利分校、微软研究院

作者：Ruiying Ma、Chieh-Jan Mike Liang、Yanjie Gao 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.03851)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.03851)

> 系统算法设计面临解空间不连续导致的搜索困难，传统手工设计耗时且依赖通用启发式。现有LLM方法受限于“可得性偏差”，倾向于生成经典模板而非创新结构。MetaMuse通过外部刺激引导跳跃采样，并结合性能向量度量多样性，实现了从抽象概念到可执行代码的系统化映射。该方法在缓存与装箱问题上显著优于基线，但其对非平稳动态环境的适应性及跨域泛化能力仍存疑。

## 研究背景

系统算法如缓存替换与在线装箱，其性能对数据结构或控制流的微小改动极为敏感，这种解空间的不连续性使得传统的数值优化或平滑梯度搜索失效。工程师常因设计成本高昂而退守于LRU、First-Fit等通用启发式，导致性能次优。这一困境催生了利用大语言模型（LLM）进行算法生成的需求，旨在通过语义推理跨越不连续的性能谷底。

自动启发式设计（AHD）的主流路线依赖进化搜索，将LLM作为变异算子嵌入种群迭代。然而，LLM的下一词元预测机制导致其输出受训练数据频率分布支配，产生“可得性偏差”，即生成的解倾向于聚集在文献中常见的经典设计周围，难以实现真正的结构创新。此外，调整温度等超参数仅能平滑概率分布，无法从根本上打破这种偏差。MetaMuse的切入点在于将算法生成重构为解空间中的采样过程，通过引入外部刺激与基于性能反馈的多样性评估，迫使LLM利用看似无关的知识进行创造性跳跃，从而突破经典模板的束缚。

## 核心方法

### 方法参照系

本文问题属于LLM引导的自动算法设计，但区别于基于种群进化的标准流程。传统方法通过变异和交叉在初始种群附近搜索，而MetaMuse采用单点采样策略，核心差异在于利用外部刺激引导解空间跳跃，并通过性能向量而非语义相似度来度量解的多样性，以克服LLM的生成偏差。

### 基于反馈嵌入的多样性评估

传统方法常使用代码或描述的语义嵌入来评估解的多样性，但语义差异并不等同于功能差异，例如不同描述的LFU算法可能具有相同的命中率。MetaMuse将多样性评估锚定在可测量的反馈空间，定义每个解的反馈嵌入为在 $n$ 个负载轨迹上的性能度量向量 $\mathbf{p} = [p_1, p_2, \dots, p_n]$。

$$
\mathbf{p}_i = [p_{i,1}, p_{i,2}, \dots, p_{i,n}]
$$

该向量直接反映解在真实工作负载下的表现，其欧氏距离直观地量化了解之间的性能差异。这种设计解决了语义嵌入无法区分功能等价解的问题，使得多样性评估能够直接关联到算法的实际效用，为后续的定向搜索提供了明确的几何基础。

### 外部刺激引导与路点推理

在确定搜索方向后，MetaMuse通过外部刺激引导LLM生成新解。RSDict-SF策略利用高斯过程回归（GPR）预测不同刺激组合对应的反馈嵌入，选择最接近目标方向（如最远点或高性能点）的刺激集。

$$
\hat{\mathbf{p}} = \sum_{j=1}^{N} \alpha_j K(\boldsymbol{\phi}(o_{new}), \boldsymbol{\phi}(o_j))
$$

其中 $K$ 为点积核函数，$\boldsymbol{\phi}$ 为语义嵌入。这一机制解决了盲目随机选择刺激导致无效推理的问题，实现了探索与利用的平衡。随后，通过路点推理（Waypoint Reasoning）将刺激转化为代码，依次执行属性提取、问题映射、方案制定和代码生成。这种结构化步骤防止了LLM将刺激简单转化为变量名，确保了从抽象概念到具体实现的逻辑连贯性，提升了生成解的可执行性与创新性。

## 实验评估

实验在缓存替换与在线装箱两个系统问题上进行，对比了MCTS-AHD、ReEvo等LLM基线及LRU、First-Fit等人工启发式。MetaMuse在缓存替换中将缺失率降低最多35.76%，在装箱问题中将箱使用率降低最多30.93%，显著优于所有基线。

| 方法 | 缓存缺失率降低 (%) | 装箱使用率降低 (%) | 解多样性倍数 |
| :--- | :--- | :--- | :--- |
| MetaMuse (GPT-4o) | 35.76 | 30.93 | 1.78 |
| MetaMuse (DeepSeek-V3) | 9.14 | 21.06 | 1.80 |
| Repeated Sampling | - | - | 1.00 |
| MCTS-AHD | - | - | 1.00 |

消融实验显示，RSDict-SF比RSDict多产生12.50%的高性能解，且解多样性提升13.17%。路点推理使GPT-4o生成的不同解数量从149增至175，证明了结构化推理对避免表面化生成的关键作用。单解生成成本低至2.16美分，低于Repeated Sampling的3.38美分，表明该框架在计算效率上具有优势。

评估边界方面，实验仅覆盖缓存与装箱两类问题，缺乏在TSP等标准组合优化基准上的验证。代码未公开，且依赖特定的负载轨迹生成工具（如libCacheSim），限制了跨域复现性。此外，GPR模型的训练依赖初始解的质量，若初始解分布过于集中，可能影响后续搜索方向的准确性。

## 关联研究分析

从问题动机看，MetaMuse与FunSearch均旨在利用LLM突破手工设计的局限，但FunSearch依赖种群进化维持多样性，而MetaMuse通过外部刺激实现解空间跳跃。这一差异源于任务特性：系统算法解空间的不连续性使得局部变异难以跨越性能谷底，而外部刺激能引导LLM利用无关知识进行远距离跳跃。FunSearch在平滑搜索空间中可能更稳定，但在不连续空间中易陷入局部最优。

从方法设计看，MetaMuse与CodeEvolve在多样性评估上存在根本分歧。CodeEvolve使用岛屿模型和文本相似度维持多样性，而MetaMuse使用性能向量距离。这一选择反映了系统算法对实际性能的高度敏感性，语义相似性无法保证性能差异。然而，性能向量距离的计算依赖于负载轨迹的代表性，若轨迹分布狭窄，可能导致解空间覆盖不均。MetaMuse未探讨如何动态调整负载轨迹以适配不同问题域，这限制了其在非平稳环境中的适用性。

## 总结

MetaMuse针对系统算法解空间不连续导致的LLM生成偏差，提出基于外部刺激与反馈嵌入的创造性构思框架。通过性能向量度量多样性与GPR引导刺激选择，该方法在缓存与装箱问题上实现了35.76%的缺失率降低与30.93%的箱使用率降低，显著优于进化基线。其边界在于实验仅覆盖两类系统问题，且依赖特定负载轨迹，缺乏跨域泛化验证。当负载分布发生剧烈偏移时，基于静态轨迹训练的GPR模型是否仍能准确预测解的性能方向，论文未给出回答。
