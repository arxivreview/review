# ICLR2026最新论文 ｜Aria: An Agent For Retrieval and Iterative Auto-Formalization via Dependency Graph ｜基于依赖图与术语级语义锚定的猜想级自动形式化智能体

研究机构：北京大学、中国人民大学

作者：Hanyu Wang、Ruohan Xie、Yutong Wang 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.04520)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.04520)

> 自动形式化旨在将自然语言数学陈述转换为交互式定理证明器可验证的代码，其核心价值在于弥合人类数学直觉与机器严格验证之间的鸿沟。现有单次生成范式在处理研究级猜想时，因缺乏对隐式前提的解析能力与术语真实语义的锚定，常产生语法合法但逻辑错误的代码。Aria 通过构建概念依赖图进行自底向上合成，并引入术语级检索机制强化语义校验，实现了从语法编译到语义忠实的跨越。该方法在研究级猜想上突破了基线全零的困境，但其对静态库快照的依赖与高昂的推理成本，限制了其在动态演化数学生态中的即时适用性。

## 研究背景

交互式定理证明器（Interactive Theorem Provers, ITPs）如 Lean 4 及其核心库 Mathlib 构成了形式化数学的基础设施。自然语言数学陈述中往往隐含大量未显式声明的前提与定义，这些隐式依赖构成了自动形式化的主要障碍。当大语言模型（Large Language Models, LLMs）尝试直接翻译这些陈述时，其预训练知识的静态性导致无法识别 Mathlib 中快速演化的接口，进而生成引用不存在函数或类型不兼容的代码。这种语法层面的失败尚可通过编译器反馈修正，但更隐蔽的语义幻觉——即生成语法正确但数学含义偏离原意的代码——则直接破坏了形式化验证的根基。

早期研究聚焦于竞赛级问题的单句翻译，假设 LLM 具备足够的数学常识，主要挑战在于少样本提示下的语法生成。随着 ProofNet 等基准暴露出隐式前提识别的瓶颈，研究者引入检索增强生成（Retrieval-Augmented Generation, RAG）与编译器反馈，试图用计算延迟换取对复杂依赖的解析能力。然而，现有方法在处理研究级或猜想级陈述时仍面临双重失效：一方面，单次生成范式无法自发合成库中不存在的新定义；另一方面，基于表面文本相似度的语义检查器难以捕捉 Lean 术语深层逻辑结构的细微偏差。Aria 的切入点在于将形式化过程重构为对概念依赖图的递归解析与自底向上合成，并通过术语级语义锚定解决验证环节的盲区。

## 核心方法

### 依赖图分解与自底向上合成

陈述自动形式化的通用流程通常将全局翻译任务转化为局部依赖解析，但传统线性分解难以处理深层嵌套的概念结构。Aria 采用思维图（Graph-of-Thought, GoT）范式，将单句形式化建模为有向无环图（Directed Acyclic Graph, DAG）的构建与求解过程。该设计动机在于解决单次生成在面对“未见前提”时的合成失效问题。

分解阶段执行自顶向下的依赖扩展。对于输入陈述，规划模块将其拆解为概念节点，每个节点代表一个定义、结构或类。系统通过 LeanSearch 动态查询 Mathlib 最新快照，对每个节点进行接地（Grounding）。若检索到匹配的规范定义，节点标记为“已接地”；若未找到匹配项，节点标记为“未接地”并触发子节点扩展，直至所有叶节点均能在库中找到对应物。合成阶段则执行自底向上的代码生成。对于未接地的内部节点，系统收集其子节点已验证的正式代码作为上下文，调用 LLM 生成目标概念的 Lean 定义。生成的代码立即进入编译器在环（Compiler-in-the-loop）反思机制：若编译失败，错误信息与代码回传 LLM 进行修正；若成功，代码标记为已合成并用于父节点生成。这一过程确保了语法正确性，但无法排除“类型正确但语义错误”的情况，需依赖后续的语义校验模块。

### 术语级语义锚定校验

语义校验旨在检测形式化代码与自然语言原意之间的细微偏差。现有方法如 LeanScorer 依赖子任务分解与模糊积分聚合，但受限于表面文本匹配，易漏检参数顺序颠倒或类型强制转换等深层错误。AriaScorer 在继承子任务评估框架的基础上，引入了术语级检索与解释步骤。

该模块利用静态分析器 jixia 提取形式化陈述中引用的所有 Lean 术语，并查询 Herald 建立的非形式化 Mathlib 数据集，获取每个术语的名称、类型、值及非形式化描述。这些权威定义被注入 LLM 的评估上下文，使模型能够基于术语的真实数学含义而非表面语法进行比对。评估过程将陈述分解为原子假设与结论，对每个子任务标记为“完美匹配”、“轻微不一致”或“重大不一致”。最终得分通过 Sugeno 模糊积分计算：

$$ S = \int_{\mu} f d\mu = \bigvee_{i=1}^{n} (\mu(A_i) \wedge f(x_i)) $$

其中 $f(x_i)$ 为子任务 $i$ 的匹配分数，$\mu(A_i)$ 为基于子任务重要性的模糊测度。该公式通过取最大值运算聚合局部偏差，使得单个重大不一致即可导致整体得分骤降，从而有效拦截语义幻觉。相比纯文本比对，术语级锚定使 AriaScorer 能够识别隐含前提缺失与定义误用，显著提升了语义校验的召回率。

## 实验评估

实验在 ProofNet、FATE-H、FATE-X 及真实世界猜想数据集上进行，基线包括 Gemini-2.5-Pro、Goedel-Formalizer-V2-32B（Goedel-V2）、Kimina-Autoformalizer-7B 及 Herald-translator。Aria 在所有基准上均取得领先，尤其在研究级猜想上实现了从 0% 到 42.9% 的突破。

| 方法 | ProofNet (Final Acc.) | FATE-H (Final Acc.) | FATE-X (Final Acc.) | Conjectures (Final Acc.) |
| :--- | :--- | :--- | :--- | :--- |
| Aria | 68.5 | 71.0 | 44.0 | 42.9 |
| Goedel-V2 (pass@128) | – | 43.0 | 24.0 | 0 |
| Gemini-2.5-Pro (pass@1) | 27.8 | 31.0 | 21.0 | 0 |
| Kimina (pass@1) | 24.7* | 0.0 | 1.0 | 0 |
| Herald (pass@1) | 18.3 | 12.0 | 5.0 | 0 |

*注：Kimina 在 ProofNet 上的结果标记为潜在数据污染。*

Aria 在 FATE-X 上的最终准确率（44.0%）显著高于 Goedel-V2 在 pass@128 下的表现（24.0%），尽管后者使用了超过 7 倍的 API 调用次数。这表明 GoT 结构化的依赖解析比暴力采样更高效地定位了语义错误。在语义校验模块的对比中，AriaScorer 在 FATE-X 上以 89.9% 的准确率和 96.2% 的召回率优于 LeanScorer（71.0% 准确率）和反向翻译方法（33.3% 准确率）。

| 校验器 | Accuracy | Precision | Recall | F1 |
| :--- | :--- | :--- | :--- | :--- |
| AriaScorer (α=0) | 89.9% | 90.9% | 96.2% | 93.5% |
| LeanScorer (α=0) | 71.0% | 77.6% | 88.5% | 82.1% |
| Back Translation | 33.3% | 87.5% | 13.5% | 23.3% |

消融实验显示，移除术语级接地步骤后，校验器的假阳性率显著上升，证实了该模块对检测细微语义偏差的关键作用。评估边界方面，论文未报告置信区间，且 Conjectures 数据集规模较小，统计显著性受限。此外，Aria 平均每个问题需 17.7 次 API 调用，计算成本远高于单次生成模型，限制了其在大规模数据生成流水线中的实时应用。

## 关联研究分析

从问题动机看，Aria 与 DRIFT 同属分解-检索路线，但 DRIFT 侧重子查询分解以解决隐式前提识别，而 Aria 聚焦于概念依赖图的构建以解决新定义合成问题。DRIFT 假设所有依赖均可在库中找到，而 Aria 明确处理库中缺失的概念，通过自底向上合成填补空白。这一差异源于任务难度的提升：竞赛题依赖多为已知定理，而研究级猜想常涉及未形式化的新结构。Aria 的 GoT 结构允许并行解析独立依赖，但在依赖稀疏时是否退化为线性搜索，论文未给出量化分析。

从方法设计看，AriaScorer 与 LeanScorer 共享子任务分解框架，但 AriaScorer 引入了术语级检索作为评估上下文。LeanScorer 依赖 LLM 对表面文本的直觉判断，易受术语命名歧义影响；AriaScorer 通过注入 Mathlib 中的权威定义，将评估锚定在形式化语义上。这一设计解决了 LLM 在解释 Lean 代码时倾向于使用熟悉数学类比而非严格类型定义的偏差。然而，AriaScorer 依赖 Herald 建立的非形式化数据集，若 Mathlib 更新导致描述滞后，校验精度可能下降。与 M2F 等项目级形式化框架相比，Aria 聚焦单句陈述的高保真翻译，未涉及跨文件依赖管理与版本控制，其架构更适合作为大规模形式化流水线的原子组件而非独立系统。

## 总结

Aria 旨在解决研究级数学陈述自动形式化中语义幻觉与新定义合成缺失的核心矛盾。现有单次生成范式因预训练知识静态化及表面文本匹配局限，无法处理猜想级依赖。Aria 通过 GoT 依赖图实现自底向上合成，并引入术语级语义锚定强化校验，在 ProofNet 上达到 68.5% 最终准确率，在真实世界猜想上实现 42.9% 成功率，突破基线全零困境。其边界在于对 Mathlib 静态快照的依赖及高昂的推理成本，限制了在动态演化库中的即时适配。当 Mathlib 接口频繁变更时，术语级检索的缓存策略与更新机制如何平衡实时性与计算开销，论文未给出回答。
