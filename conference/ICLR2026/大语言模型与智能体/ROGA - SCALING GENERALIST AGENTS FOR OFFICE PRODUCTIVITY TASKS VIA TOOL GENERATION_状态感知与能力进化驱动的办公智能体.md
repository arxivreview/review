# ICLR2026最新论文 ｜ROGA: SCALING GENERALIST AGENTS FOR OFFICE PRODUCTIVITY TASKS VIA TOOL GENERATION ｜状态感知与能力进化驱动的办公智能体

研究机构：北京大学

作者：Mugeng Liu、Xiaojun Ma、Yuhang Xie 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_16997494)

> 通用智能体在处理长程、有状态的办公任务时，因缺乏连贯的世界模型、无状态执行机制及静态能力生成而失效。现有自动工具生成（ATG）范式仅能应对简单无状态任务，无法适应部分可观测环境下的复杂交互。ROGA通过主动世界建模、持久符号记忆和动态能力进化三大机制，重构了智能体在长程任务中的推理与执行架构。该框架在办公基准上显著超越现有ATG智能体，但其对骨干模型上下文窗口的强依赖及特定任务类型的高分表现，提示其通用性边界仍需进一步审视。

## 研究背景

当智能体面对长达数十页的Excel文档或复杂的PPT结构时，其上下文窗口往往无法容纳全部细节，导致对文件元数据（如公式依赖、样式层级）的感知出现盲区。这种部分可观测性迫使智能体依赖被动读取，但LLM的静态推理难以从碎片化信息中构建连贯的世界模型。为解决此问题，自动工具生成（ATG）范式应运而生，允许智能体按需生成代码工具以操作环境。然而，ATG通常将工具调用视为孤立事件，缺乏对中间状态演化的显式追踪，导致在修改同一文件对象的长链条操作中，早期步骤的状态信息在后续步骤中丢失，引发上下文断裂与执行错误。

当前通用智能体研究多聚焦于静态工具检索或简单的代码执行，如Toolformer和ToolLLM通过预定义工具集提升调用准确率，但无法覆盖开放任务中未预见的工具需求。ATG智能体如AutoAgent和Alita虽能动态生成工具，但其执行模型本质上是无状态的，且能力生成是一次性的，缺乏对生成工具的长期维护与复用机制。这种“生成即弃”的模式在长程任务中导致冗余计算与错误累积。ROGA的切入点在于识别出长程有状态任务中“世界模型构建”、“状态连续性”与“能力进化”三个被忽视的核心瓶颈，并针对办公生态这一典型复杂场景，提出了一套结构化的状态感知与元学习框架。

## 核心方法

### 离散时间决策过程与状态定义

ROGA将智能体工作流建模为离散时间决策过程，其状态 $S_t$ 由部分可观测的文件上下文 $F_t$、持久符号记忆 $M_t$ 和自进化能力集 $T_t$ 组成。动作空间 $A$ 包含工具生成、工具执行和终止三种类型。该定义明确了智能体在每一步需同时处理环境感知、状态维护与能力管理，区别于传统ReAct范式仅关注推理与动作的交替。

$$ S_t = (F_t, M_t, T_t), \quad a_t \sim \pi(S_t), \quad S_{t+1} = \delta(S_t, a_t) $$

此公式确立了ROGA的基础架构，其中 $\pi$ 为决策函数，$\delta$ 为状态转移函数，确保智能体在长程任务中始终基于完整状态进行决策。

### 主动世界建模与持久符号记忆

针对被动感知导致的上下文盲区，ROGA引入主动世界建模（AWM），通过迭代生成专用理解工具来探测环境元数据。当规划器检测到 $M_t$ 不足以支持当前任务时，智能体生成如“提取所有包含透视表的表名”的子目标，并调用生成的工具获取答案，将其整合至 $M_t$。这一过程克服了LLM无法一次性读取长文档的限制。为维持状态连续性，ROGA采用持久符号记忆（PSM），通过共享状态沙箱维护中间产物（如工作簿对象、数据框）的符号句柄。PSM强制要求原子性与可逆性：工具调用要么完全成功并提交状态至 $M_{t+1}$，要么失败并回滚至 $M_t$。

$$ M_{t+1} = \text{Commit}(M_t, a_t) \text{ if } \text{Success}(a_t) \text{ else } M_t $$

该机制确保了在修改同一文件对象的迭代操作中，后续步骤能准确引用前序步骤创建的对象，避免了无状态执行导致的上下文丢失。

### 动态能力进化与有限状态机

为解决静态能力生成导致的冗余再生成，ROGA引入动态能力进化，将工具生命周期管理形式化为有限状态机（FSM）。能力集 $T_t$ 中的每个工具经历“生成”、“激活”、“使用中”、“修改”和“弃用”五个状态。当工具在“使用中”状态失败时，触发情境自校正（SSC），在影子沙箱中进行状态感知功能测试与语义意图验证。若校正成功，工具进入“激活”状态供复用；若多次失败，则进入“弃用”状态。

$$ P(\text{Select}(c_i)) \propto \text{Fitness}(c_i) \cdot \text{ContextMatch}(c_i, S_t) $$

此公式表明，工具的选择概率由其历史适应度与当前上下文匹配度共同决定，实现了从一次性生成到长期元学习的转变，消除了相似步骤的冗余计算。

## 实验评估

实验在OSWorld、WindowsAgentArena（WAA）、GAIA-Office、TableBench和SheetCopilotBench上进行，基线包括AutoAgent、OctoTools、OWL及专用智能体SheetAgent，均使用GPT-4.1作为骨干模型。ROGA在OSWorld上的Pass@1达到31.82%，较最佳基线OWL（16.36%）提升15.46个百分点；在WAA上Pass@1为76.92%，较OWL（73.08%）提升3.84个百分点。在表格任务上，ROGA的TableBench Pass@1为56.09%，超越专用智能体SheetAgent（51.47%）4.62个百分点，表明通用ATG范式在特定领域可超越专用流水线。

| 方法 | OSWorld Pass@1 (%) | WAA Pass@1 (%) | TableBench Pass@1 (%) |
| :--- | :--- | :--- | :--- |
| OWL (GPT-4.1) | 16.36 | 73.08 | 25.73 |
| SheetAgent (GPT-4.1) | - | - | 51.47 |
| ROGA (GPT-4.1) | 31.82 | 76.92 | 56.09 |

消融实验显示，移除主动世界建模导致Pass@1显著下降，而Exec@1基本不变，说明AWM主要提升任务完成质量而非执行成功率。移除持久符号记忆后，WAA Pass@1从76.92%降至53.85%，降幅达23.07个百分点，证实状态连续性对长程操作的关键作用。移除能力生命周期管理后，OSWorld Pass@1从31.82%降至26.19%，表明工具复用机制对效率的贡献。

评估边界方面，ROGA在GAIA-Office上取得95%以上Exec@1，但该基准任务相对简化，可能高估通用能力。此外，ROGA对骨干模型上下文窗口敏感，使用OpenAI-o3时性能显著下降，暴露其对长上下文依赖的局限。代码已开源，但超参数细节未完全披露，可复现性受限于GPT-4.1的API访问成本。

## 关联研究分析

从问题动机看，ROGA与Toolformer等工具检索方法的核心差异在于对“工具来源”的处理。Toolformer依赖预定义工具集，通过自监督学习决定调用时机，适用于工具边界明确的场景；而ROGA针对开放任务中工具需求未预见的情况，通过动态生成解决覆盖度不足问题。这一差异源于任务特性：办公任务涉及非标准化文件结构，预定义工具难以穷举，而动态生成能适配具体文件上下文。然而，ROGA未探讨动态生成在工具生态高度标准化（如Web API）场景下的效率，其生成开销是否优于检索机制，论文未给出回答。

从方法设计看，ROGA与AutoAgent等ATG智能体的关键区别在于状态管理。AutoAgent将工具调用视为独立事件，缺乏对中间状态的显式追踪，导致长程任务中上下文丢失；ROGA通过持久符号记忆和原子性执行，将离散动作转化为连贯的状态流。这一设计解决了无状态执行在迭代操作中的失效问题。但ROGA的FSM生命周期管理增加了系统复杂度，其状态转移规则是否适用于非办公领域（如代码生成）的长程任务，论文未进行跨域验证，限制了其通用性的评估。

## 总结

ROGA旨在解决长程有状态办公任务中世界模型构建、状态连续性与能力进化的缺失问题。现有ATG范式因被动感知、无状态执行和静态生成而失效，ROGA通过主动探测、符号记忆和FSM管理实现了范式突破。实验显示，ROGA在OSWorld Pass@1上较基线提升15.46个百分点，并在表格任务上超越专用智能体。其边界在于对骨干模型上下文窗口的强依赖，以及GAIA-Office高分可能源于任务简化。当任务复杂度进一步增加或环境动态性增强时，主动世界建模的探测效率与持久符号记忆的存储开销之间的平衡，是否仍能维持性能优势，论文未给出回答。
