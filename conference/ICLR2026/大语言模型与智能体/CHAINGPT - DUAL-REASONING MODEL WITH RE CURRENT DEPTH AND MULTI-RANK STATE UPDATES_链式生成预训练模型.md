> 固定深度 Transformer 在有限精度下受限于 AC[0] 或 TC[0] 电路类，无法端到端解决深递归推理任务。现有思维链（CoT）方法依赖离散 Token 生成，计算成本随序列长度线性增长，且受自然语言表达力限制；纯循环神经网络（RNN）虽高效但状态矩阵维度有限，难以保留长程上下文。ChainGPT 通过层内多子步状态更新与层间递归精炼的双层架构，将推理内化至连续潜在空间，在保持近线性复杂度的同时实现图灵完备性。该架构在算术与抽象推理任务上超越同规模基线，但缺乏大规模预训练数据支撑，其在标准基准上的泛化能力仍存疑。

## 研究背景

理解本文需厘清两个核心约束：电路复杂度类与状态空间容量。标准 Transformer 的固定深度使其计算能力被限制在 AC[0] 或 TC[0] 类中，这意味着在有限精度下，模型无法可靠执行需要深度递归的多步规划或符号操作。为突破此瓶颈，CoT 通过生成中间自然语言步骤扩展有效计算深度，但离散 Token 序列的表达力限制了非线性推理模式的捕捉，且生成长度直接决定计算开销。与此同时，RNN 架构虽具备线性复杂度优势，但其有限维状态矩阵无法忠实保留详细上下文，导致在多跳推理任务中出现显著性能瓶颈（Jelassi et al., 2024）。

当前高效推理研究主要沿两条路线展开：一是优化推理策略，如树状思维（ToT）通过分支搜索探索多条路径，但计算成本随分支数指数增长；二是优化底层架构，如 Jamba 和 Samba 采用混合架构平衡质量与效率，但全局注意力面临可扩展性瓶颈，局部窗口注意力则受限于状态容量。现有混合架构多为顺序组合，缺乏有效协调机制，无法同时解决深层推理与长程依赖保留问题。ChainGPT 的切入点在于将推理从显式 Token 生成转移至潜在计算空间，通过架构设计而非提示工程或外部搜索，在单一前向传播内实现多轮状态更新，从而在保持近线性复杂度的同时突破固定深度的表达力限制。

## 核心方法

### 方法参照系

本文问题归属于内部状态推理增强类别，与通用 Transformer 推理流程的关键差异在于：不依赖外部生成的离散推理步骤，而是通过模型内部连续状态的迭代精炼实现推理深度扩展。标准流程中，推理深度由层数固定决定；本文则通过层内多子步与层间递归解耦推理深度与模型参数量，使计算复杂度与推理步数解耦。

### RWKV-Product 多子步状态更新

层内推理的核心在于突破 RNN 单步更新的秩限制。传统 RWKV-7 采用“对角+秩1”结构，每次状态更新仅能引入秩1修正，表达力受限。ChainGPT 引入 RWKV-Product 机制，在单次前向传播内执行 $M$ 个子步更新，每个子步拥有独立的键值表示与门控策略。状态矩阵 $\mathbf{s}_t$ 的更新公式为：

$$ \mathbf{s}_t = \text{diag}(\mathbf{a}_{t,j}) \mathbf{s}_{t-1} + \beta \mathbf{b}_{t,j} \mathbf{k}_{t,j}^\top $$

其中 $\text{diag}(\mathbf{a}_{t,j})$ 执行通道级衰减，$\beta \mathbf{b}_{t,j}$ 控制秩1修正强度。通过 LoRA 增量共享基线键值，$M$ 个子步的累积效应可近似高秩变换，使有效更新秩动态扩展至 $M$。这一设计解决了单步更新表达力不足的问题，使模型在单层内完成多轮局部推理，无需增加层数即可提升推理深度。

### 状态引导稀疏注意力（SGSA）

层内多子步更新解决了局部计算深度问题，但 RNN 状态矩阵的有限维度仍导致长程信息丢失。SGSA 通过稀疏注意力机制构建全局依赖路径，查询位置仅访问局部窗口 $W$ 内的 Token 与每隔 $G$ 个位置采样的全局锚点。检索过程分解为“写入与指针读取”：RWKV-Product 聚合局部片段并传播至锚点，SGSA 通过稀疏寻址检索内容。该机制将计算复杂度降至 $O(N(W+N/G))$，避免了密集注意力的 $O(N^2)$ 开销。与纯滑动窗口架构相比，SGSA 的全局锚点机制在长上下文任务中完全解决了状态瓶颈问题，使模型在保持近线性复杂度的同时有效召回长程信息。

### 递归深度与自适应停止

层间推理采用递归深度方法，将模型分解为底层特征提取器、递归推理核心与顶层输出模块。递归核心迭代精炼潜在状态直至收敛，训练稳定性通过两阶段策略保障：无梯度预热与截断反向传播，辅以基于熵的早期停止机制。停止准则定义为：

$$ \Delta H_t(b) = |H_t(b) - H_{t-1}(b)| \leq \tau $$

其中 $H_t(b)$ 为样本 $b$ 在第 $t$ 次迭代时的输出熵，$\tau$ 为固定阈值。当熵变化低于阈值时，递归在步骤 $t$ 停止。这一机制实现了推理深度与计算预算的可控权衡，避免冗余迭代，使模型在简单任务上快速收敛，在复杂任务上自动增加推理轮数。

## 实验评估

实验在 8 块 NVIDIA L20 GPU 上进行，ChainGPT 模型参数量为 0.5B 和 1.5B，在 FineWeb 数据集的 20B 和 40B Token 上训练，基线为 Qwen2.5。评估采用 lm-eval-harness 框架，零样本设置覆盖六个语言理解与常识推理任务。基线覆盖同规模 Transformer 与 RNN 架构，但缺失知识库中 SOTA 的显式压缩方法（如 UCoT、SLAT）及主流 CoT 增强模型（如 DeepSeek-R1）。

| 模型 | ARC-Challenge | HellaSwag | 平均 |
|---|---|---|---|
| Qwen2.5-0.5B | 0.2218 | 0.5290 | 0.4317 |
| ChainGPT-0.5B | 0.4082 | 0.6425 | 0.5059 |
| Qwen2.5-1.5B | 0.3224 | 0.6380 | 0.5059 |
| ChainGPT-1.5B | 0.6425 | 0.6860 | 0.5291 |

ChainGPT 在 ARC-Challenge 和 HellaSwag 上显著超越同规模基线，表明其通用推理能力更强。在 GOAT 算术数据集上，ChainGPT 无 CoT 监督时准确率为 57.53%，优于 HRM 的 54.00% 和 Qwen3+Loop 的 50.54%；结合 CoT 后准确率达 99.98%，远超 Qwen3+CoT 的 88.43%。

| 模型 | GOAT 准确率 |
|---|---|
| Qwen3 | 33.82% |
| HRM | 54.00% |
| ChainGPT | 57.53% |
| ChainGPT + CoT | 99.98% |

消融实验显示，LoRA 子步机制仅增加 0.1M 参数，但验证损失从 3.2715 降至 3.1901，训练步数从 3200 减至 2500。子步数 $M$ 从 1 增至 2 时验证损失持续下降，$M=2$ 提供最佳权衡。在 MQAR 任务中，ChainGPT 在序列长度 2048 时准确率仍保持 99% 以上，而 RWKV-7 降至 72.93%，验证了 SGSA 解决状态瓶颈的有效性。

评估边界存在局限：未报告置信区间，ARC-AGI-1 得分 38.6% 低于知识库 SOTA URM 的 53.8%；代码未公开，超参数细节（如锚点间隔 $G$ 的最优值）仅在附录中部分披露；实验基于从零训练的小模型，未验证在大规模预训练模型上的迁移效果。

## 关联研究分析

从问题动机看，ChainGPT 与 UCoT 代表潜在推理与显式压缩两条不同路线。UCoT 通过专用压缩器生成精简推理轨迹，依赖离散 Token 的语义剪枝，其优势在于保持可解释性，但受限于离散表达瓶颈；ChainGPT 将推理内化至连续状态空间，通过架构设计突破 Token 生成限制，但牺牲了推理过程的可解释性。两者在 GSM8K 上的性能差异（ChainGPT+CoT 99.98% vs UCoT 90.0%）可能源于评估协议不同：ChainGPT 从零训练并显式结合 CoT，而 UCoT 基于微调大模型。这种差异暗示，潜在推理的准确率优势是否可泛化至未结合显式 CoT 的场景，论文未给出回答。

从方法设计看，ChainGPT 与 HRM 同属递归深度架构，但 HRM 仅通过层间迭代增加深度，单层表达力受限；ChainGPT 引入层内多子步更新，使单层具备多轮推理能力，解决了 HRM 在复杂任务上收敛慢的问题。然而，ChainGPT 的层内多子步与层间递归存在计算冗余：当层内子步数 $M$ 较大时，层间递归的边际收益可能递减。论文未量化这种冗余，也未探索 $M$ 与递归深度 $K$ 的最优组合策略，这在计算预算受限场景下可能影响实际部署效率。

## 总结

ChainGPT 旨在解决固定深度 Transformer 在有限精度下无法端到端执行深递归推理的核心矛盾。其切入点在于将推理从离散 Token 生成转移至连续潜在空间，通过层内多子步状态更新与层间递归精炼的双层架构，在保持近线性复杂度的同时实现图灵完备性。实验表明，ChainGPT 在 GOAT 算术任务上无 CoT 监督时准确率达 57.53%，结合 CoT 后达 99.98%，在 ARC-Challenge 上超越同规模基线 0.1862。然而，其 ARC-AGI-1 得分 38.6% 低于知识库 SOTA，且实验基于从零训练的小模型，未验证在大规模预训练模型上的泛化能力。当模型规模扩展至 7B 以上时，层内多子步与层间递归的计算冗余是否会导致训练不稳定，论文未给出回答。
