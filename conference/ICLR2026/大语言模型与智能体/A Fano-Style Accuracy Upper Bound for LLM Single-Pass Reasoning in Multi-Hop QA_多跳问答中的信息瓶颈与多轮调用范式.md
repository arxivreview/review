# ICLR2026最新论文 ｜A Fano-Style Accuracy Upper Bound for LLM Single-Pass Reasoning in Multi-Hop QA ｜多跳问答中的信息瓶颈与多轮调用范式

作者：Kaiyang Wan、Lang Gao、Honglin Mu 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.21199)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.21199)

> 多跳问答（Multi-Hop Question Answering, MHQA）要求模型整合分散在长上下文中的互依证据，但大语言模型（LLM）单次前向生成的输出容量存在硬性上限。当任务信息需求超过该容量时，单轮推理范式下的准确率并非平滑下降，而是发生骤降。本文通过信息论推导揭示这一“准确率悬崖”，并提出多轮调用框架 InfoQA，通过容量感知分解与查询收缩将复杂任务拆解为低负载子步骤。该工作从机制层面解释了单轮推理失效的根源，但其在受控合成基准上的结论能否泛化至开放域真实场景，仍存疑。

## 研究背景

多跳推理的本质是链式依赖：模型需将前一步的中间发现 $Z_k$ 作为后续步骤的输入，最终推导答案 $A$。这一过程受限于两个信息论约束：一是单次生成的输出熵 $H(Y)$ 决定了模型能携带的最大信息量（输出容量 $C$）；二是任务本身的信息需求 $\beta = H(A|Q, C)$ 随跳数 $h$ 和上下文长度 $L$ 增长。当 $\beta > C$ 时，根据 Fano 不等式，模型无法在单次输出中完整解析答案的不确定性，导致推理失败。

现有主流路线如 Chain-of-Thought (CoT) 和 ReAct 均属于单轮调用范式，试图在一次前向传播中完成所有推理步骤。尽管这些方法通过提示工程提升了中间步骤的可见性，但它们无法突破单次生成的物理容量限制。随着跳数增加，信息需求呈超线性增长，单轮范式不可避免地陷入“容量溢出”，即关键证据被噪声稀释。此外，单轮范式还面临“跨步误差累积”问题：即使单步准确率较高，链式依赖中的微小错误也会逐级放大，导致最终答案失效。

本文切入点在于指出单轮范式本身的结构性缺陷，而非优化提示策略。通过建立信息论上限，本文证明单轮推理在复杂 MHQA 任务中是“根本性不足”的，从而为多轮调用（Multi-call）范式提供了理论依据。

## 核心方法

### 单轮推理的信息论参照系

单轮推理的标准流程是将问题 $Q$ 和上下文 $C$ 一次性输入 LLM，生成包含推理轨迹 $R$ 和答案 $A$ 的输出 $Y$。该范式的核心假设是模型能在单次生成中整合所有分散证据。然而，这一假设忽略了输出容量的物理限制。本文的关键差异在于，将 MHQA 视为一个信息传输问题，而非单纯的文本生成任务，从而引入了容量约束这一被传统提示工程忽略的维度。

### Fano 风格准确率上限推导

传统方法未对单轮推理的性能上限进行形式化界定，导致无法区分“模型能力不足”与“任务复杂度超限”。本文通过结合条件 Fano 不等式与输出熵界，推导出单轮推理的准确率上限。设任务信息需求为 $\beta = H(A|Q, C)$，模型输出容量为 $C = H(Y)$，则最大准确率 $\text{Acc}$ 满足：

$$ h(\text{Acc}) \leq C - \beta + 1 $$

其中 $h(\cdot)$ 为二元熵函数。该公式表明，当 $\beta > C + 1$ 时，$\text{Acc}$ 的上限严格小于 1，且随着 $\beta$ 增加，准确率呈双曲衰减。这一推导揭示了“准确率悬崖”现象：性能在阈值处发生相变式崩溃，而非平滑退化。

### 容量感知的多轮调用框架

单轮范式无法解决容量溢出，因为所有信息必须压缩在有限输出中。InfoQA 通过多轮调用将高需求任务分解为低需求子任务。其核心机制是“迭代查询收缩”：每一步仅解决单跳子问题，并将中间发现 $Z_k$ 嵌入新查询 $Q_{k+1}$，同时剪除前序推理轨迹。具体而言，第 $k$ 步的信息需求被限制为 $\beta_k = H(Z_k|Q_k, C)$，确保 $\beta_k \leq C$。通过显式依赖工作流，InfoQA 将推理状态显式化为查询本身，避免了内部记忆的不确定性，从而在每一步都保持高准确率，抑制了跨步误差累积。

## 实验评估

实验在自建合成基准上进行，该基准系统控制跳数（1-4跳）和上下文长度（0.5k-10k token），以精确调节信息需求 $\beta$。基线覆盖 Direct、CoT、Self-Refine、ReAct、Plan-and-Solve 等单轮方法，但未包含检索增强生成（RAG）类基线，如 IRCoT 或 CRAFT，这限制了与外部知识整合范式的直接对比。

| 跳数 | 上下文长度 | CoT F1 | InfoQA F1 | 提升幅度 |
| :--- | :--- | :--- | :--- | :--- |
| 4 | 10k | 0.04 | 0.42 | +0.38 |
| 3 | 8k | 0.18 | 0.96 | +0.78 |
| 2 | 4k | 0.59 | 1.00 | +0.41 |
| 1 | 0.5k | 1.00 | 1.00 | 0.00 |

在极端容量溢出场景（4跳、10k token）下，InfoQA 的 F1 分数为 0.42，显著高于 CoT 的 0.04，验证了多轮调用在突破单轮容量限制方面的有效性。消融实验显示，移除“容量感知任务分解”或“剪除前序推理轨迹”均导致性能下降，其中移除剪除机制在长上下文下影响更显著，表明噪声累积是主要失效因素。

评估边界方面，本文仅使用 F1 指标，未报告置信区间或计算成本（如 token 消耗）。合成基准的高语义相似度设计可能高估了多轮调用在真实噪声环境中的收益，且未验证在开放域基准（如 HotpotQA）上的泛化性。代码未公开，可复现性受限。

## 关联研究分析

从问题动机看，本文与 CRAFT 和 GlobalRAG 等 RAG 方法形成鲜明对比。CRAFT 通过强化学习优化检索-推理协同，解决知识过时问题；而 InfoQA 完全排除外部检索，仅关注上下文内推理的容量瓶颈。这一差异源于任务设定：InfoQA 假设所有必要证据已在上下文中，问题在于“如何整合”而非“如何获取”。这暗示 InfoQA 在封闭域长文本任务中更具优势，但在开放域知识密集型任务中，其缺乏外部知识获取能力可能成为瓶颈。

从方法设计看，InfoQA 与 Self-Refine 同属多轮调用范式，但 Self-Refine 依赖自由生成的反馈进行迭代修正，而 InfoQA 采用结构化的查询收缩。Self-Refine 的反馈可能包含虚假逻辑或噪声，导致误差累积；InfoQA 通过显式依赖工作流和剪除机制，确保每一步的信息负载可控。这一设计选择解决了 Self-Refine 在长链推理中因噪声累积导致的性能衰减问题，但牺牲了生成自由度，可能限制模型在复杂推理中的灵活性。

## 总结

本文核心矛盾在于单轮 LLM 推理的输出容量与多跳任务信息需求之间的结构性冲突。现有方法如 CoT 和 ReAct 无法突破这一物理限制，而 InfoQA 通过信息论推导揭示了“准确率悬崖”，并采用多轮调用与查询收缩将任务分解为容量对齐的子步骤。实验在合成基准上验证了 InfoQA 在极端容量溢出场景下显著优于单轮基线（如 4跳 10k token 下 F1 从 0.04 提升至 0.42）。然而，其结论基于受控合成数据，未验证在开放域真实基准上的泛化性，且缺乏与 RAG 方法的对比。当上下文长度进一步增加或跳数超过 4 时，多轮调用的累积延迟与误差是否仍可控，论文未给出回答。
