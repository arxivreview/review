# ICLR2026最新论文 ｜Generalizable End-to-End Tool-Use RL with Synthetic CodeGym ｜代码合成强化学习环境

研究机构：美国卡内基梅隆大学

作者：Weihua Du、Hailei Gong、Zhan Ling 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.17325)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.17325)

> 工具增强大语言模型（Tool-Augmented LLMs）在分布外（OOD）任务上泛化能力薄弱，主要源于监督微调（SFT）依赖静态轨迹且现有强化学习（RL）环境局限于窄域任务。CodeGym 利用编程题中固有的执行逻辑，将静态代码转化为可交互、可验证的多轮工具调用环境，通过通用合成环境弥补窄域 RL 的多样性缺失。该方法在 OOD 基准上实现了显著的性能提升，但其仅依赖二元结果奖励的设计在长程信用分配上存在潜在局限。

## 研究背景

当智能体面对未见过的工具组合时，其决策能力往往因训练数据中缺乏相应交互模式而失效。这种失效源于静态参数化知识无法覆盖动态工作流，迫使模型依赖外部工具进行实时信息获取与计算。然而，现有训练数据多为人工标注的静态轨迹，难以覆盖真实世界中复杂且多变的工具调用逻辑，导致模型在分布外场景下表现脆弱。

主流解决方案分为两条路线：一是基于 SFT 的模仿学习，通过大规模标注轨迹训练模型调用工具，但受限于数据标注成本高企及分布外泛化能力差；二是基于可验证奖励的强化学习（RLVR），通过环境交互与试错机制赋予模型自主规划能力。然而，现有 RLVR 工作多聚焦于特定领域（如代码调试或信息检索），环境多样性不足，限制了模型通用工具使用能力的习得。CodeGym 的切入点在于利用编程题作为结构化基底，将代码中的原子函数抽象为工具，构建大规模、多样化的通用工具调用环境，从而在 RL 训练中暴露智能体于广泛的工作流逻辑中。

## 核心方法

### 方法参照系

CodeGym 属于 RLVR 路线，其核心流程包括环境构建、策略优化与奖励反馈。与依赖真实 API 或窄域任务的传统 RLVR 方法不同，CodeGym 的关键差异在于环境来源：它不依赖外部真实系统，而是从静态编程题中合成虚拟交互环境，确保任务的可验证性与多样性。

### 环境合成与验证

传统 RL 环境构建依赖真实系统接口，存在延迟高、状态不可控及验证困难等问题。CodeGym 通过提取编程题中的原子函数作为工具，将代码执行逻辑转化为多轮交互任务。环境被定义为部分可观测马尔可夫决策过程（POMDP），其状态转移与奖励函数如下：

$$
\mathcal{M} = \langle \mathcal{S}, \mathcal{A}, \mathcal{T}, \mathcal{R} \rangle
$$

其中，状态 $S$ 编码任务变量，动作空间 $A$ 包含通用调用（如 `Observe`）与领域特定工具，奖励 $R$ 仅在终止时根据答案正确性赋予二元值（1 或 0）。为确保环境可解，CodeGym 采用 pass@K 策略，生成 K=10 个候选解决方案，若任一通过单元测试则环境有效。这一设计解决了真实环境中状态不可控与验证缺失的问题，提供了稳定且可复现的训练信号。

### 分布式 RL 训练框架

长程工具调用中，错误调用可能导致环境崩溃或延迟激增，影响训练稳定性。CodeGym 引入“试错-覆盖”（Trial-then-Overwrite）机制，在每次工具调用前序列化环境状态，并在子进程中执行调用。若执行成功，则更新状态；否则，回滚至原状态并返回错误信息。该机制通过隔离错误调用，确保了高并发 RL 训练的鲁棒性。训练采用 GRPO 算法，通过解耦 GPU 绑定的策略更新与 CPU 绑定的环境服务，实现了高效的数据吞吐。

## 实验评估

实验在 Qwen2.5 系列（7B-72B）及 QwQ-32B 上进行，对比基线包括 Oracle-SFT（基于真值轨迹）与 Distillation-SFT（基于强模型蒸馏）。CodeGym 训练后的模型在 OOD 基准 $\tau$-Bench 上表现突出，Qwen2.5-32B-Instruct 准确率提升 8.7 点，达到 46.7%，与 GPT-4o 基线持平。

| 模型 | 基准 | 提升幅度 | 绝对准确率 |
| :--- | :--- | :--- | :--- |
| Qwen2.5-32B-Instruct | $\tau$-Bench | +8.7 | 46.7% |
| Qwen2.5-32B-Instruct | GAIA | - | 46.7% |

消融实验显示，环境过滤机制（难度与复杂度筛选）对性能至关重要。未过滤数据集在域内验证与 OOD 任务上均表现更差，表明高质量数据筛选提升了训练效率。此外，长 CoT 模型在难度增强集上训练，短 CoT 模型在原始集上训练，验证了任务难度与模型推理能力的匹配性。

评估边界方面，论文未报告置信区间，且缺乏与 Tool-R1、Tool Zero 等同类 RLVR 方法的直接横向对比。代码已开源，但超参数细节（如具体 GPU 配置）未在正文中详述，可能影响复现性。

## 关联研究分析

从问题动机看，CodeGym 与 SWE-Gym 同属代码域 RL 环境，但 SWE-Gym 聚焦于调试任务，环境状态复杂且验证依赖测试用例；CodeGym 则聚焦于通用工具调用逻辑，通过抽象原子函数简化了状态空间，更强调工作流的多样性而非单一任务的深度。这一差异源于任务定义：调试需要精确的状态追踪，而工具调用更关注逻辑组合的泛化性。

从方法设计看，CodeGym 与 Tool-R1 均使用 GRPO 算法，但 Tool-R1 依赖真实工具库，环境多样性受限于可用 API 数量；CodeGym 通过合成环境突破了这一限制，但代价是环境真实性降低。二元奖励设计在长程任务中可能导致信用分配稀疏，Tool-R1 通过损失掩码机制区分模型生成与工具返回 token，而 CodeGym 未采用此类细粒度监督，这可能限制了其在复杂依赖任务上的表现。

## 总结

CodeGym 解决了通用工具调用 RL 环境稀缺的问题，通过代码合成实现了环境多样性与可验证性的统一。其核心贡献在于证明了合成环境在 OOD 泛化上的有效性，Qwen2.5-32B-Instruct 在 $\tau$-Bench 上提升 8.7 点。然而，二元奖励设计在长程任务中的信用分配效率存疑，且缺乏与细粒度过程奖励方法的对比。当任务步骤超过 50 步时，二元奖励是否足以引导模型习得正确的中间状态管理，论文未给出回答。
