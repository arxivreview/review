研究机构：南京大学

作者：Jie-Jing Shao、Bo-Wen Zhang、Xiao-Wen Yang 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_41379003)

> 旅行规划要求智能体在空间、时间与财务维度间进行多步依赖决策，现有基准多依赖固定槽位填充，无法评估模型对隐含意图与组合逻辑的泛化能力。本文提出 ChinaTravel 基准，通过领域特定语言（DSL）将自然语言约束转化为可执行代码，实现自动化验证。实验表明神经符号方法在约束满足率上显著优于纯大语言模型，但组合泛化仍是主要瓶颈。该工作揭示了从模板化交互向开放域语义接地迁移的关键挑战，其绝对成功率仍受限于语义解析精度。

## 研究背景

旅行规划任务的核心在于处理跨维度的组合约束。当用户提出“预算5000元且第二天下午前到达上海”时，系统需同时满足财务上限与时间窗口，这超出了单一属性提取的范畴，涉及谓词逻辑的组合与验证。传统基准如 TravelPlanner 采用槽位填充范式，将查询映射为固定属性值（如预算、日期），这种命题逻辑无法表达“餐饮预算不超过1000元”或“特定时间段内的活动依赖”等复杂内部结构。

现有神经符号集成方法在固定约束场景下表现良好，但面对开放域查询时暴露出泛化缺陷。LLM-Modulo 等框架依赖符号验证器反馈，但在长程任务中反馈效率衰减，且无法处理未见过的约束组合。TTG 等混合整数线性规划方法在 POI 数量增加时复杂度呈 $O(N^3 T)$ 增长，导致求解不可行。本文切入点在于构建一个支持组合约束验证的开放域基准，通过 DSL 将自然语言意图转化为可执行的逻辑代码，从而量化模型在未见约束组合上的真实能力，而非仅评估其在固定模板下的表现。

## 核心方法

### 方法参照系

本文问题属于神经符号规划中的自然语言到形式化表示转换。标准流程为：LLM 解析自然语言生成形式化模型（如 PDDL），符号求解器生成计划，验证器检查约束。本文的关键差异在于将形式化表示从静态 PDDL 领域模型扩展为动态 DSL 约束代码，验证对象从计划本身扩展为约束满足过程，以支持开放域的组合逻辑。

### 组合约束 DSL 设计

针对固定规则列表无法泛化至未见约束的问题，本文设计了一套 Python 风格的 DSL。该语言包含变量、逻辑运算符、算术运算符及概念函数（如 `cost`, `dist`），允许通过组合原子概念表达复杂约束。约束验证通过 Python 编译器执行 DSL 代码实现，公式表示为：

$$
\text{Pass}(p, C) = \bigwedge_{c \in C} \text{Exec}_{DSL}(c, p)
$$

其中 $p$ 为计划，$C$ 为约束集，$\text{Exec}_{DSL}$ 为 DSL 解释器执行结果。这一设计消除了对每个新约束进行人工规则工程的需求，使得约束验证具备组合泛化能力，能够处理训练数据中未出现的约束组合。

### 神经符号规划框架

在 DSL 基础上，本文提出 NeSy Planning 框架，解耦理解、规划与执行。LLM 负责将自然语言查询翻译为 DSL 约束代码，符号搜索器基于 DSL 约束进行深度优先贪心搜索生成计划。搜索过程引入规则化活动选择与评分函数，例如在午餐时段优先选择符合菜系要求的餐厅。该框架通过 DSL 代码的精确性弥补 LLM 在长程状态追踪上的缺陷，确保生成的计划在时空与财务维度上严格满足约束，解决了纯 LLM 方法中常见的约束遗漏与逻辑幻觉问题。

## 实验评估

| 方法 | 模型 | Easy FPR (%) | Human-154 FPR (%) | Human-1000 FPR (%) |
| :--- | :--- | :--- | :--- | :--- |
| ReAct (one-shot) | GPT-4o | 5.77 | 2.59 | 6.43 |
| LLM-Modulo | GPT-4o | 4.33 | 2.59 | 0.0 |
| NeSy Planning | DeepSeek-V3 | 52.6 | 37.0 | 23.3 |
| NeSy Planning (Oracle) | DeepSeek-V3 | 75.0 | 52.0 | 32.0 |

实验在 ChinaTravel 基准上进行，包含 Easy、Human-154 和 Human-1000 子集。基线覆盖纯 LLM（ReAct）、符号优化（TTG）及神经符号（LLM-Modulo）。NeSy Planning 在 Human-1000 上取得 23.3% 的最终通过率（FPR），显著优于纯 LLM 方法的 0%-6.43% 区间，验证了神经符号架构在复杂约束满足上的必要性。Oracle 模式（使用真实 DSL 翻译）将 FPR 提升至 32.0%，表明语义翻译是主要瓶颈。

消融实验显示，TTG 在 Easy 子集上仅取得 8.66% 的 FPR，且在 2-3 天行程中求解时间超出限制，证实了混合整数规划在长程任务中的计算不可行性。LLM-Modulo 在迭代 3-5 轮后错误修正能力衰减至 $\le 1$，导致性能停滞。NeSy Planning 的偏好优化模块在 5/6 个单一偏好场景中优于基线，但在“最小化市内交通时间”与“最小化酒店成本”的组合中胜率仅为 0.10，暴露了 LLM 在刚性权衡中的局限。

评估协议采用 Micro/Macro 双指标，并引入条件逻辑通过率（C-LPR）以排除环境约束未满足导致的逻辑误判。代码与数据已开源，但 DSL 翻译依赖 LLM 提示工程，缺乏端到端训练，限制了泛化能力的进一步提升。

## 关联研究分析

从问题动机看，本文与 LLM-Modulo 同属神经符号集成路线，但针对其反馈机制在长程任务中的失效进行了重构。LLM-Modulo 依赖符号验证器反馈错误信息给 LLM 进行迭代修正，但在多日多 POI 场景中，这种“错误-重生成”循环导致计算开销激增且收敛缓慢。本文通过 DSL 将约束验证前置为代码执行，利用符号搜索器在约束空间内直接求解，避免了 LLM 在长序列中维持逻辑一致性的负担。这一差异源于任务特性：旅行规划涉及高维时空组合，符号搜索比 LLM 迭代修正更具效率优势。

从方法设计看，本文与 Planner-R1 等强化学习规划方法形成对比。Planner-R1 通过奖励塑造提升小模型规划能力，但依赖大规模环境交互数据。本文采用基于规则的偏好排序与 DSL 验证，无需环境交互，适合离线基准测试。然而，本文未探索 RL 在 DSL 翻译优化中的应用，其偏好优化模块仅基于规则，可能在未见偏好组合上泛化不足。这种设计选择反映了基准构建的优先级：首先验证神经符号架构的可行性，而非优化学习范式。

## 总结

本文核心矛盾在于开放域自然语言意图与形式化逻辑验证之间的鸿沟。现有方法受限于固定槽位或迭代反馈效率，无法处理组合约束的泛化。本文通过 DSL 将约束转化为可执行代码，结合符号搜索实现自动化验证，在 Human-1000 上取得 23.3% 的 FPR，较纯 LLM 提升约 10 倍。然而，Oracle 模式与标准模式的差距（32.0% vs 23.3%）表明，瓶颈仍在于 LLM 对未见约束组合的语义接地能力。当 DSL 翻译错误率降至 10% 以下时，符号搜索的求解效率是否成为新的主要限制，论文未给出回答。
