# ICLR2026最新论文 ｜Latent Speech-Text Transformer ｜潜在语音-文本 Transformer

研究机构：美国约翰斯·霍普金斯大学

作者：Yen-Ju Lu、Yashesh Gaur、Wei Zhou 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.06195)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.06195)

> 语音大语言模型面临的核心矛盾是声学序列的高冗余性与文本语义的稀疏性导致的计算效率失衡，现有交错训练方法虽能实现模态对齐，但语音 token 序列长度远超文本，致使同等语义内容下的推理算力消耗呈数量级差异，且这种密度不匹配阻碍了跨模态知识的深度迁移。本文切入点在于将自回归建模的粒度从离散 token 提升至潜在语音补丁（Latent Speech Patch），通过动态聚合语音片段来拉平两种模态的信息密度。具体做法是引入基于文本对齐或静态窗口的补丁编码器，配合课程学习策略，使模型在训练初期利用对齐信息，推理时仅需静态补丁即可运行。该方案在计算受控和数据受控设置下均提升了语音与文本性能，但其在复杂逻辑推理任务上的有效性尚未在大规模基准上得到验证，且补丁机制对副语言细节的保留程度存疑。

## 研究背景

理解本文需先厘清生成式口语语言建模（Generative Spoken Language Modeling, GSLM）的基本困境。GSLM 将原始语音波形编码为离散 token 序列，并训练自回归语言模型进行下一 token 预测。然而，同一语义内容在语音中所需的 token 数量远多于文本，Cuervo & Marxer (2024) 估算这种密度差异导致语音模型需多至三个数量级的数据才能达到文本模型同等能力。这种序列长度的膨胀不仅增加了预训练成本，更在推理阶段造成算力浪费，使得语音模态在混合训练中占据不成比例的算力份额，进而干扰了文本模态的知识保持。

主流端到端语音大语言模型（如 SpiritLM, Nguyen et al., 2025）通过交错训练语音与文本 token 来缓解模态差距，试图让模型在两种模态间自由切换。然而，这种直接 token 级对齐并未解决信息密度失衡的根本问题：语音 token 的连续性和冗余性仍干扰大语言模型内部的语义绑定，导致语音输入下的推理性能显著低于文本。现有方法多聚焦于嵌入空间的对齐或蒸馏，却忽视了自回归序列建模粒度这一底层瓶颈。本文指出，若不能从序列结构上压缩语音表示，任何上层对齐策略都难以突破计算效率与对齐质量的天花板。

## 核心方法

### 方法参照系

标准语音-文本联合建模流程包含语音分词器、解码器 Transformer 和声码器。本文沿用 HuBERT 分词器（501 码本，25Hz）和 Llama 2 文本分词器，核心差异在于在 Transformer 骨干前引入补丁机制，将自回归单元从单个 token 扩展为变长语音补丁，从而改变序列建模的基本粒度。

### 潜在语音补丁机制

传统方法直接处理离散语音 token，导致序列过长。本文引入补丁编码器（Patch Encoder），利用滑动窗口自注意力和交叉注意力将局部语音片段聚合为潜在表示。对于帧索引集合 $P_i$，补丁嵌入 $z_i$ 通过编码器整合帧表示：

$$ z_i = \text{PatchEncoder}(\{x_j\}_{j \in P_i}) $$

这一设计将多个冗余的声学帧压缩为单一语义单元，使语音补丁的信息密度接近文本 token。设计动机在于解决直接 token 建模中算力被低信息量声学细节占据的问题，通过有界上下文的时间聚合，在保留音素可区分性的同时降低序列级冗余。

### 课程补丁策略

静态补丁虽高效但缺乏语义同步，对齐补丁虽精准但推理时需额外模型。本文提出课程补丁（Curriculum Patching），在训练过程中动态调整对齐补丁的使用概率 $P(u)$：

$$ P(u) = \begin{cases} 1 & u < T/3 \\ 0.5 & T/3 \le u < 2T/3 \\ 0 & u \ge 2T/3 \end{cases} $$

训练初期强制使用基于 Wav2Vec2+CTC 时间戳的对齐补丁，建立语音-文本的语义对应；中期混合使用；后期转为静态补丁。这一策略解决了推理时无法获取对齐时间戳的依赖问题，使模型在享受对齐监督收益的同时，具备静态推理的鲁棒性。

## 实验评估

| 模型 | 训练 Token (B) | HellaSwag S→S | HellaSwag T→T | StoryCloze S→S | TopicStoryCloze S→S |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Base SpeechLLM | 87 | 39.0 | 47.0 | 59.1 | 87.5 |
| LST (Curriculum) | 108 | 45.5 | 52.2 | 61.4 | 87.9 |

实验在 HellaSwag、StoryCloze 和 TopicStoryCloze 上进行，对比基线包括无补丁的 Base SpeechLLM 和 BPE SpeechLLM。LST (Curriculum) 在计算受控设置下，HellaSwag 语音准确率从 39.0% 提升至 45.5%，文本准确率从 47.0% 提升至 52.2%，表明补丁机制不仅提升语音性能，还通过更高效的算力分配改善了文本能力。BPE 基线未能超越 Base SpeechLLM，证实了子词分词在语音 token 上的无效性，而 LST 的补丁机制提供了更优的压缩路径。

| 补丁策略 | 平均补丁大小 | HellaSwag S→S | StoryCloze S→S | TopicStoryCloze S→S |
| :--- | :--- | :--- | :--- | :--- |
| Static | 4 | 40.5 | 58.2 | 86.2 |
| Curriculum (sil sep.) | 5.8→4 | 41.3 | 58.6 | 86.6 |
| Align (sil sep.) | 5.8 | 39.9 | 60.3 | 85.7 |

消融实验显示，Curriculum 策略在 HellaSwag 上达到 41.3%，优于 Static 的 40.5% 和 Align 的 39.9%。值得注意的是，Align 策略在 StoryCloze 上表现最佳（60.3%），但在 HellaSwag 上落后，表明对齐补丁在长序列叙事连贯性上更优，但在短序列常识推理中因变长补丁导致测试时算力波动而受损。Curriculum 策略通过混合训练平衡了这两种特性，成为整体最优选择。

评估边界方面，本文仅在 1B 和 7B 规模下验证了缩放行为，未报告置信区间。代码已开源，但补丁编码器与解码器的具体超参数（如滑动窗口大小 512）在附录中给出，主文未详述。评估基准聚焦于故事补全，缺乏对复杂逻辑推理或情感识别等下游任务的直接测试，限制了结论的泛化性。

## 关联研究分析

从问题动机看，SALAD (Cuervo et al., 2025) 通过两阶段蒸馏解决知识遗忘，侧重于输出分布的对齐；而 LST 聚焦于输入序列的粒度压缩，认为密度不匹配是推理退化的底层成因。SALAD 依赖教师模型的质量，LST 则通过架构设计内在解决算力分配问题。两者的差异源于对“模态差距”根源的不同假设：SALAD 认为差距源于表示空间的错位，LST 认为差距源于序列长度的失衡。若密度对齐足以缓解推理退化，则 LST 应能在复杂推理基准上超越 SALAD，但本文未提供此类对比。

从方法设计看，Moshi (Défossez et al., 2024) 采用全双工多流模型，通过并行处理语音和文本流降低延迟，但其核心仍是 token 级建模。LST 的补丁机制与 Moshi 的流式架构正交，前者解决序列冗余，后者解决实时性。LST 的补丁大小动态变化，可能引入流式处理中的边界不确定性，这在 Moshi 的固定帧率架构中不存在。LST 是否能在保持补丁压缩率的同时实现全双工交互，论文未探索，这限制了其在实时语音助手场景的直接应用。

## 总结

本文要解决的核心矛盾是语音 token 序列长度导致的计算效率失衡与跨模态对齐瓶颈。现有交错训练方法未能从序列粒度上解决密度不匹配，而 LST 通过潜在语音补丁机制，将自回归单元从 token 提升至语义补丁，从而拉平模态间的信息密度。实验证明，在计算受控设置下，LST (Curriculum) 将 HellaSwag 语音准确率从 39.0% 提升至 45.5%，文本准确率从 47.0% 提升至 52.2%，验证了密度对齐对双模态性能的协同提升。然而，本文的边界在于评估基准局限于故事补全，缺乏对复杂逻辑推理和副语言感知的直接测试，且补丁机制对声学细节的压缩可能损失情感语调等关键信息。当模型规模扩展至 7B 以上时，补丁压缩带来的信息损失是否会被更大的模型容量所补偿，从而在复杂推理任务上超越基于蒸馏的对齐方法，论文未给出回答。
