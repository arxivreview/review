# ICLR2026最新论文 ｜EMPOWERING LLM TOOL INVOCATION WITH TOOL CALL REWARD MODEL ｜工具调用奖励模型

研究机构：上海交通大学

作者：Da Ma、Ziyue Yang、Hongshen Xu 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_85872312)

> 工具增强大语言模型在强化学习训练中面临结果奖励导致的梯度冲突，即中间步骤正确但最终答案错误时，模型无法区分工具调用的效用。现有基于可验证奖励的强化学习（RLVR）方法仅评估最终输出，忽视了多步交互中单次调用的质量。本文提出工具调用奖励模型（TRM），通过二元分类头量化每次调用的必要性与质量，并设计轮次级优势估计以解决组内归一化引发的奖励黑客问题。该方案在搜索问答与代码数学任务上稳定提升了不同规模模型的策略性能，但其二元评分机制在复杂连续效用场景下的表达力仍存疑。

## 研究背景

当大语言模型（LLM）通过调用搜索引擎或代码解释器解决复杂任务时，其推理过程表现为“思考-行动-观察”的交替序列。在这一序列中，模型生成的每个工具调用（Tool Call）都是后续推理的基础，然而传统的强化学习（RL）训练往往仅依据最终答案的正确性给予奖励。这种结果奖励（Outcome Reward）机制导致信用分配（Credit Assignment）的粒度过于粗糙：若最终答案错误，即便中间某次工具调用检索到了关键信息，该调用仍会被整体惩罚。这种信号与真实效用之间的错位引发了梯度冲突（Gradient Conflict），使得模型难以学习到有效的工具使用策略，甚至出现为了规避惩罚而减少调用次数的“奖励黑客”现象。

工具增强 LLM 的训练范式正从监督微调（SFT）向基于可验证奖励的强化学习（RLVR）演进。SFT 依赖人工标注轨迹，在分布外（OOD）任务上泛化能力差；而 RLVR 通过环境交互赋予模型自主规划能力，但主流方法如 Search-R1 和 ToRL 仍局限于结果奖励。尽管过程奖励模型（PRM）在数学推理中已证明细粒度监督的有效性，但其在工具调用场景的应用尚属空白。现有 PRM 研究主要关注推理步骤的逻辑连贯性，未针对工具调用的“必要性”与“执行质量”进行专门建模。本文的切入点在于将 PRM 特化为工具调用奖励模型（TRM），不仅评估调用是否发生，更评估其是否对任务推进产生实质贡献，从而在 RL 训练中提供稳定的细粒度监督信号。

## 核心方法

### 方法参照系

本文问题置于基于策略优化的工具调用 RL 框架下。标准流程通常采用 PPO 或 GRPO 算法，以最终答案正确性作为唯一奖励信号，通过广义优势估计（GAE）或组内归一化计算 token 级优势。本文与该通用流程的关键差异在于引入了独立的奖励模型来评估中间工具调用，并修改了优势估计的粒度，从轨迹级或组级降至轮次级（Turn-level）。

### TRM 构建与二元效用评分

TRM 的构建旨在解决结果奖励无法区分“无效调用”与“有效调用”的问题。设计动机在于，模型需要明确知道某次搜索是否带来了新信息，或某段代码是否执行成功，而非仅知道最终答案对错。TRM 采用 Transformer 架构，将语言建模头替换为二元分类头。对于轨迹中的第 $i$ 次工具调用 $a_i$，TRM 基于其输出 $o_i$ 的最后一个 token 隐状态预测效用分数 $\tilde{s}_i$。该分数由两个二元维度决定：必要性（Necessity）$s_i^{ne}$ 和质量（Quality）$s_i^q$。

$$
\tilde{s}_i = s_i^{ne} \cdot s_i^{q}, \quad s_i^{ne}, s_i^{q} \in \{0, 1\}
$$

此公式表明，只有当工具调用既对任务推进有实质贡献（必要性为 1），又以正确参数执行（质量为 1）时，TRM 才赋予正奖励。训练数据通过前沿 LLM（如 DeepSeek-R1）在搜索环境中生成轨迹，并由其自身评估每次调用的二元标签。这种蒸馏策略避免了人工标注的高成本，同时利用大模型的推理能力保证了标签的逻辑一致性。

### 轮次级信用分配与优势估计

TRM 分数需融入 RL 算法以优化策略。设计动机在于，直接将 TRM 分数作为轨迹级奖励会导致信号稀释，而在 GRPO 中直接进行组级归一化会引发奖励黑客，即模型倾向于减少调用次数以降低被惩罚概率。为此，本文提出轮次级信用分配（Turn-level Credit Assignment）。对于 PPO，将 TRM 分数 $\tilde{s}_i$ 分配至第 $i$ 次工具调用结束 token $e_i$，并与最终结果奖励结合，通过 GAE 计算 token 级优势。对于 GRPO，本文引入轮次级优势估计，对每个轮次 $i$ 的奖励在组内独立归一化，而非对整条轨迹归一化。

$$
\hat{A}_j = \sum_{k=j}^{L} \gamma^{k-j} \left( \alpha \cdot \frac{R_{trm}^{(I(k))} - \mu_{trm}^{(I(k))}}{\sigma_{trm}^{(I(k))}} + \frac{R_{out} - \mu_{out}}{\sigma_{out}} \right)
$$

其中 $I(k)$ 映射 token 索引 $k$ 到所属轮次，$\alpha$ 为 TRM 权重，$\mu$ 和 $\sigma$ 为组内统计量。该公式确保每个工具调用的奖励信号仅在同轮次的轨迹间进行比较，避免了因调用次数不同导致的归一化偏差，从而抑制了模型通过减少调用来规避惩罚的行为，实现了细粒度的策略优化。

## 实验评估

实验在搜索问答（HotpotQA, NQ 等）和代码数学（AIME, MATH500 等）两个场景下进行，基线涵盖直接推理、SFT、RAG、IRCoT 以及基于结果奖励的 Search-R1-PPO/GRPO 和 ToRL-PPO/GRPO。基线覆盖了从非工具使用到工具使用、从 SFT 到 RL 的主要路线，但缺失 2026 年最新的纯 RL 方法如 Tool Zero，可能低估了 RL 范式的上限。

| 模型 | 方法 | HotpotQA | AIME24 | Avg. (QA) | Avg. (Math) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen2.5-7B | Search-R1-GRPO | 47.80 | - | 46.90 | - |
| Qwen2.5-7B | Search-R1-GRPO-TRM | 47.67 | - | 48.62 | - |
| Qwen2.5-Math-7B | ToRL-GRPO | - | 35.00 | - | 52.19 |
| Qwen2.5-Math-7B | ToRL-GRPO-TRM | - | 36.56 | - | 53.70 |

在 Qwen2.5-7B 的搜索任务中，TRM 将平均准确率从 46.90% 提升至 48.62%；在 Qwen2.5-Math-7B 的数学任务中，TRM 将平均准确率从 52.19% 提升至 53.70%。TRM 在所有模型规模（1.5B, 3B, 7B）和算法（PPO, GRPO）上均带来一致提升，验证了细粒度奖励的普适性。消融实验显示，10K 训练样本足以训练出鲁棒的 TRM，且 3B 规模的 TRM 性能优于 7B，表明中等规模模型在数据有限时更易避免过拟合。

评估边界方面，实验仅覆盖单工具（搜索或代码）场景，未涉及多工具协同或动态工具库，限制了结论在复杂编排任务中的外推性。代码已开源，超参数 $\alpha$ 在 PPO 中设为 0.05，GRPO 中设为 0.01，但不同任务间的 $\alpha$ 敏感性分析未详细展开。

## 关联研究分析

从问题动机看，TRM 与 PROVE 均致力于解决多步调用中的信用分配难题，但 PROVE 采用程序化规则计算五部分奖励函数，无需外部模型，而 TRM 依赖独立训练的奖励模型。PROVE 的优势在于无需额外训练开销，但规则难以覆盖所有工具类型的效用差异；TRM 通过数据驱动学习效用模式，更具泛化性，但引入了模型训练与推理的额外成本。这种差异源于任务特性：PROVE 针对结构化约束任务，规则可枚举；TRM 针对开放式搜索任务，效用难以用固定规则定义。

从方法设计看，TRM 与 REST 均改进 GRPO 的训练稳定性，但 REST 通过动态调整 token 权重解决收敛问题，TRM 通过轮次级优势估计解决奖励黑客问题。REST 关注的是优化过程的数值稳定性，TRM 关注的是奖励信号的语义正确性。TRM 的二元评分机制可能无法捕捉工具调用效用的连续差异，例如一次检索返回了部分相关信息但未完全解决问题，其效用介于 0 和 1 之间，二元评分将其简化为 0 或 1，可能导致策略学习的粗糙化。

## 总结

本文核心矛盾在于结果奖励导致的梯度冲突阻碍了工具调用策略的有效学习。TRM 通过二元分类头量化调用效用，并设计轮次级优势估计，解决了 GRPO 中的奖励黑客问题。实验证明 TRM 在搜索与数学任务上稳定提升了 1.5B 至 7B 模型的性能，平均提升约 1.5-2 个百分点。其边界在于仅验证了单工具场景，且二元评分机制可能简化了复杂效用。当工具调用效用呈现连续分布时，二元 TRM 是否仍能保持策略优化的精度，论文未给出回答。
