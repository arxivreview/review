# ICLR2026最新论文 ｜PLAGUE: Plug and Play Framework for Lifelong Adaptive Generation of Multi-Turn Jailbreaks ｜多轮越狱攻击的终身学习框架

研究机构：美国马萨诸塞大学阿默斯特分校

作者：Neeladri Bhuiya、Madhav Aggarwal、Diptanshu Purwar

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_38295253)

> 多轮对话场景下，LLM 的安全对齐机制易被渐进式上下文污染绕过，但现有自动化攻击方法缺乏跨目标的策略复用能力，导致在强对齐模型上攻击成功率（ASR）停滞。PLAGUE 通过引入基于向量检索的终身学习记忆库，将规划、预热与终结三个阶段解耦为可插拔模块，解决了静态策略库无法适应动态防御的瓶颈。该框架在 OpenAI o3 上实现了 81.4% 的 ASR，显著优于基线，但其高性能是否完全源于攻击策略本身，还是受限于特定基座模型的脆弱性，仍需进一步剥离验证。

## 研究背景

当用户与 LLM 进行多轮交互时，攻击者不再依赖单条恶意提示，而是通过一系列看似无害的查询逐步引导模型进入对抗性上下文，这一过程称为多轮越狱。多轮攻击的核心难点在于语义漂移：随着对话轮次增加，模型容易偏离初始攻击目标，导致后续查询失效。为维持攻击连贯性，攻击代理需具备从历史交互中提炼有效策略的能力，这构成了终身学习在对抗场景下的应用基础。

现有自动化多轮攻击方法主要分为两类：一类如 Crescendo 和 GOAT，依赖固定的策略库或迭代反馈优化查询，但缺乏跨目标的记忆机制，导致在强对齐模型（如 Claude Opus 4.1）上 ASR 低于 40%；另一类如 ActorBreaker，强调规划多样性，但忽略了策略复用，导致计算预算浪费。这些方法的共同瓶颈在于战术僵化，无法在多个攻击目标间积累并迁移成功经验。PLAGUE 的切入点在于将终身学习机制引入多轮攻击框架，通过外部记忆库实现策略的动态检索与复用，从而在有限预算内突破强对齐模型的防御。

## 核心方法

### 方法参照系

多轮越狱攻击的标准流程通常包含规划、执行与反馈三个环节。传统方法如 GOAT 将规划与执行耦合，使用静态策略库生成查询；Crescendo 则通过迭代反馈优化单轮查询，但缺乏全局规划。PLAGUE 的关键差异在于引入外部向量记忆库，将策略生成与执行解耦，并支持跨目标的策略检索。

### 规划阶段：基于嵌入相似度的策略检索

规划阶段的核心创新在于利用向量嵌入记忆库检索历史成功策略。传统方法如 GOAT 使用静态策略库，无法适应新目标；PLAGUE 将历史成功策略编码为向量，存储于记忆库 $R$ 中。对于当前目标 $p_i$，计算其嵌入向量 $e(p_i)$，并检索相似度最高的策略：

$$
s^* = \arg\max_{s \in R} \cos(e(p_i), e(s))
$$

其中 $\cos$ 表示余弦相似度。该公式的物理含义是：语义相似的目标往往共享有效的攻击路径，通过检索相似策略作为上下文学习示例，可显著提升规划质量。这一设计解决了静态策略库无法泛化到新目标的问题，使攻击代理能复用历史成功经验。

### 预热与终结阶段：上下文冻结与反馈回溯

预热阶段（Primer）利用规划生成的 $n-1$ 步锚点，逐步构建对抗性上下文。与 Crescendo 的迭代优化不同，PLAGUE 在预热阶段结束后冻结上下文，进入终结阶段（Finisher）。终结阶段基于初始目标生成最终查询，若评分低于阈值（3/10），则触发回溯机制，移除当前轮次并重新生成。反馈模块使用 Rubric Scorer 对合规性、实用性、细节程度和相关性进行量化评分，其中相关性权重最高（4 分）。该设计解决了多轮攻击中语义漂移问题，通过冻结上下文确保终结阶段的查询始终指向初始目标，同时通过回溯机制避免无效轮次消耗预算。

## 实验评估

实验在 HarmBench 200 样本集上进行，对比基线包括 Crescendo、GOAT、ActorBreaker 和 AutoDAN-Turbo。PLAGUE 在 OpenAI o3 上实现 81.4% 的 ASR，较 GOAT 提升 32.14%；在 Claude Opus 4.1 上实现 67.3% 的 ASR，较 Crescendo 提升 40.2%。

| 方法 | OpenAI o3 (ASR) | Claude Opus 4.1 (ASR) | Deepseek-R1 (ASR) |
| :--- | :--- | :--- | :--- |
| GOAT | 0.445 | 0.142 | 0.937 |
| Crescendo | 0.374 | 0.352 | 0.937 |
| ActorBreaker | 0.318 | 0.217 | 0.322 |
| PLAGUE | 0.662 | 0.318 | 0.945 |

消融实验显示，添加规划模块（P）和策略检索（RSS）后，OpenAI o3 的 ASR 从 0.582 提升至 0.662，Claude Opus 4.1 从 0.31 提升至 0.318。值得注意的是，在 Claude Opus 4.1 上，使用 GOAT 作为终结模块时 ASR 仅为 0.142，而替换为 Crescendo 后提升至 0.352，表明终结模块的选择对强对齐模型影响显著。

评估边界方面，PLAGUE 仅使用黑盒 API 调用，未涉及白盒梯度优化；实验未报告计算延迟和吞吐量，且未对比系统级防御（如 IsolateGPT）。代码未公开，超参数（如相似度阈值 0.6）的敏感性分析缺失，限制了可复现性。

## 关联研究分析

从问题动机看，PLAGUE 与 AutoDAN-Turbo 均引入终身学习机制，但 AutoDAN-Turbo 聚焦单轮攻击，依赖响应嵌入检索，而 PLAGUE 针对多轮场景，基于目标嵌入检索。差异根源在于任务特性：多轮攻击需维持上下文连贯性，目标嵌入比响应嵌入更能捕捉攻击路径的语义相似性。PLAGUE 未探索响应嵌入在多轮场景中的有效性，这可能是一个未开发的优化方向。

从方法设计看，PLAGUE 与 ActorBreaker 均强调规划多样性，但 ActorBreaker 使用自模拟生成规划，而 PLAGUE 通过记忆库检索历史策略。ActorBreaker 的多样性更高，但 ASR 低于 PLAGUE 30%-90%，表明多样性并非攻击成功率的唯一决定因素。PLAGUE 的模块化设计允许集成 ActorBreaker 的规划模块，提升多样性 15% 且 ASR 几乎无损失，验证了规划与执行解耦的有效性。

## 总结

PLAGUE 旨在解决多轮越狱攻击中策略僵化与缺乏跨目标复用的矛盾，通过引入基于向量检索的终身学习记忆库，将规划、预热与终结解耦为可插拔模块。该框架在 OpenAI o3 上实现 81.4% 的 ASR，在 Claude Opus 4.1 上实现 67.3% 的 ASR，显著优于现有基线。然而，实验未剥离基座模型（如 Deepseek-R1）的固有脆弱性对 ASR 的贡献，且未评估策略检索阈值（0.6）对性能的影响。当目标模型的安全对齐机制发生显著变化时，记忆库中历史策略的有效性是否衰减，论文未给出回答。
