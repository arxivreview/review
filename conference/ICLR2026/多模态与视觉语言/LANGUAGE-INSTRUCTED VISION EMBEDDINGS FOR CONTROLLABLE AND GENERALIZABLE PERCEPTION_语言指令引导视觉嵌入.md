# ICLR2026最新论文 ｜LANGUAGE-INSTRUCTED VISION EMBEDDINGS FOR CONTROLLABLE AND GENERALIZABLE PERCEPTION ｜语言指令引导视觉嵌入

作者：Chengzhi Mao、Xudong Lin、Wen-Sheng Chu

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_28327798)

> 视觉基础模型通常作为静态特征提取器，将任务适配负担转嫁给下游大语言模型，导致推理成本高且无法恢复被编码器忽略的细粒度细节。LIVE 提出反向范式：利用大语言模型生成合成指令-答案三元组，通过对比学习将指令知识蒸馏至视觉编码器内部，使其在推理时能根据文本指令动态调制特征。该方法在 MMVP 基准上以 71.2% 的准确率超越 LLaVA 等 LLM 基线 7.9 个点，参数量仅为后者的 1/10，但其在标准分类任务上的泛化能力及对合成数据分布的鲁棒性仍存疑。

## 研究背景

当视觉编码器面对包含文字干扰的图像时，其静态特征往往无法区分“物体”与“文字”语义，导致在需要特定关注点的任务中产生幻觉。这种静态性源于传统双塔架构（如 CLIP、SigLIP）中视觉嵌入 $z = E(x)$ 的计算独立于查询内容，迫使下游模块承担语义解析重任。为打破这一瓶颈，研究者尝试通过视觉提示（Visual Prompting）或微调适配特定任务，但这些方法优化的是固定目标，无法响应零样本的自然语言指令。

现有主流路线存在结构性缺陷：LLM 中心架构（如 LLaVA、InstructBLIP）虽能处理指令，但依赖庞大的下游模块，计算开销巨大且无法修复视觉编码器端的感知缺失；基于描述性文本的调制方法（如 Lavoie et al., 2024）受限于描述性文本与指令性文本的语义差异，缺乏可控性。LIVE 的切入点在于将“指令”本身作为视觉编码器的输入条件，通过蒸馏 LLM 的知识生成能力，使视觉编码器具备“意图驱动”的特征提取能力，从而在表示空间内直接实现任务感知。

## 核心方法

### 双塔架构下的指令注入参照系

标准视觉-语言模型采用双塔架构，视觉编码器 $E(\cdot)$ 与文本编码器 $T(\cdot)$ 独立计算嵌入。LIVE 沿用此框架，但关键差异在于：不再将视觉嵌入视为通用表示，而是将其重构为条件表示。文本编码器保持冻结，仅更新视觉编码器及新增的投影层，将“指令-图像”对映射至与“答案”对齐的语义空间。

### 指令条件化视觉嵌入计算

传统视觉提示仅在输入端注入静态向量，无法处理语义歧义（如“车”的颜色 vs 品牌）。LIVE 引入语言指令 $q$ 作为视觉编码器的动态条件。具体而言，复用预训练文本编码器 $T(\cdot)$ 计算指令嵌入，通过线性投影层将其注入 Vision Transformer (ViT) 内部，与图像特征进行交互。指令条件化视觉嵌入定义为：

$$ z_{[I]} = E_{live}(x, T(q)) $$

该公式的物理含义是：视觉编码器 $E_{live}$ 不再输出固定特征，而是根据指令 $q$ 的语义，选择性增强图像中与 $q$ 相关的视觉区域，抑制无关区域。这种设计解决了静态特征在细粒度属性识别上的失效，使同一图像在不同指令下产生不同的特征表示。

### 基于 Sigmoid 的三元组对比学习

为训练 $E_{live}$ 遵循指令，LIVE 采用图像-指令-答案三元组 $(x, q, a)$ 进行对比学习。不同于标准 CLIP 的二元对比，LIVE 使用 Sigmoid 对齐损失，确保指令条件化嵌入 $z_{[I]}$ 与正确答案嵌入 $z_{[T]} = T(a)$ 接近，同时远离错误答案。损失函数定义为：

$$ \mathcal{L} = -\frac{1}{N} \sum_{i,j} \log \sigma(y_{ij} (z_{[I]}^T z_{[T]} - b)) $$

其中 $y_{ij} \in \{-1, 1\}$ 指示匹配关系，$b$ 为可学习偏置。该损失函数的设计动机在于：Sigmoid 损失相比标准对比损失在训练初期更稳定，且能更精细地调节正负样本间的距离，防止指令注入导致的表示漂移破坏预训练对齐。

## 实验评估

LIVE 在 MMVP-VLM 和 GQA 基准上评估零样本指令跟随能力，基线涵盖静态视觉模型（SigLIP、CLIP）、融合方法（Fusion、Menon et al.）及 LLM 基线（LLaVA、InstructBLIP、BRAVE）。实验设置中，LIVE 使用 SigLIP 2 ViT-B-16 作为骨干，训练数据为 Gemini 2.0 Flash 生成的约 1640 万条 ImageNet 三元组。

| 模型 | MMVP 准确率 (%) | GQA 准确率 (%) | 参数量 (M) |
| :--- | :--- | :--- | :--- |
| SigLIP ViT-B-16 | 12.0 | - | 86.6 |
| LLaVA | 63.3 | 31.3 | ~13000 |
| InstructBLIP | 49.5 | - | ~14200 |
| **LIVE (ViT-B-16)** | **71.2** | **67.4** | **891.0** |

LIVE 在 MMVP 上以 71.2% 的准确率超越 LLaVA 7.9 个点，在 GQA 上以 67.4% 超越 LLaVA 36.1 个点，且参数量仅为 LLaVA 的 1/14.6。这表明指令引导的视觉编码器在细粒度感知任务上优于依赖 LLM 解码的架构。

消融实验揭示了关键设计决策的影响。将具体指令替换为中性提示（如“Caption the image”）导致 GQA 准确率从 67.4% 骤降至 13.1%，证明指令特异性是性能核心；将丰富答案替换为类别标签使 GQA 准确率降至 2.7%，表明描述性监督对细粒度推理至关重要。此外，语言注入深度影响任务表现：Layer 1 注入在 MMVP 上表现最佳（69.5%），Layer 8 注入在 GQA 上表现最佳（68.2%），暗示早期注入利于细节保留，晚期注入利于语义抽象。

评估边界方面，LIVE 未报告 ImageNet Base-to-Novel 等标准分类指标，无法直接对比 CoOp 等 VPT 方法在分类任务上的性能。训练数据完全依赖 LLM 合成，可能存在分布偏差，论文未验证模型对真实用户指令的鲁棒性。代码与数据已开源，但训练需 256 TPUv3 核心，复现门槛较高。

## 关联研究分析

从问题动机看，LIVE 与 CoOp、CoCoOp 等 VPT 方法存在根本差异。VPT 旨在通过优化少量提示参数适配特定任务，保持骨干冻结，核心目标是提升分类准确率并缓解 BNT 权衡；LIVE 则更新视觉编码器权重，核心目标是实现指令驱动的动态特征调制。VPT 的提示是静态的，无法响应查询变化；LIVE 的指令是动态的，但牺牲了骨干的通用性。这种差异源于任务定义：VPT 面向固定标签集的分类，LIVE 面向开放指令的感知。

从方法设计看，LIVE 与 InstructBLIP 同属指令跟随范式，但架构路径相反。InstructBLIP 通过 Q-Former 桥接视觉与 LLM，依赖 LLM 解码答案；LIVE 将 LLM 知识蒸馏至视觉编码器，推理时无需 LLM。InstructBLIP 的优势在于 LLM 的推理能力，劣势在于计算开销；LIVE 的优势在于效率，劣势在于视觉编码器容量限制。LIVE 在 GQA 上超越 InstructBLIP 37.7 个点，表明对于细粒度视觉感知任务，视觉端的指令调制比 LLM 端的解码更有效。

## 总结

LIVE 解决了视觉编码器静态性与任务动态性之间的矛盾，通过蒸馏 LLM 知识实现指令引导的特征调制。其核心贡献在于证明轻量级视觉编码器在指令跟随任务上可超越大型 LLM 架构，MMVP 71.2% 与 GQA 67.4% 的结果验证了这一路径的可行性。然而，LIVE 的训练依赖合成数据，且未验证在标准分类任务上的性能，其“零样本”泛化能力可能受限于合成指令的分布覆盖。当真实用户指令出现训练分布外的语义组合时，视觉编码器的指令响应是否仍能保持精度，论文未给出回答。
