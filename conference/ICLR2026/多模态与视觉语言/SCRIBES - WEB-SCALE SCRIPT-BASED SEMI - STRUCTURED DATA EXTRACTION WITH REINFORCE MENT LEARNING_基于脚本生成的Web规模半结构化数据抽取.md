# ICLR2026最新论文 ｜SCRIBES: WEB-SCALE SCRIPT-BASED SEMI - STRUCTURED DATA EXTRACTION WITH REINFORCE MENT LEARNING ｜基于脚本生成的Web规模半结构化数据抽取

研究机构：美国斯坦福大学、美国华盛顿大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_18013238)

> 本文旨在解决Web规模下从HTML半结构化内容中高效提取结构化知识（如三元组）的难题。现有方法要么依赖脆弱的规则模板，要么因逐页调用大语言模型（LLM）导致计算成本不可控。SCRIBES利用同域网页的布局相似性，通过强化学习训练模型生成可复用的抽取脚本，将单页推理转化为组级推理。该方法在保持与最强基线相当精度的同时，显著降低了大规模处理的计算开销，但其对复杂嵌套结构的泛化能力仍受限于脚本的静态特性。

## 研究背景

Web数据中大量事实信息存储于HTML表格、列表和信息框中，这些半结构化内容虽富含信息，但格式复杂，直接用于问答或知识图谱构建时面临解析难题。传统信息抽取方法如包装器归纳（Wrapper Induction）和基于布局的算法，在面对未见过的数据或模式时极易失效，缺乏泛化能力。随着LLM的兴起，基于模型的方法能处理更复杂的结构，但逐页调用LLM进行推理在Web规模下资源消耗巨大，难以落地。

该领域的核心矛盾在于抽取的准确性与计算效率之间的权衡。主流路线分为两类：一是传统IE方法，虽轻量但脆弱；二是LLM直接推理，虽准确但昂贵。现有LLM方法通常将每页视为独立任务，忽略了同域网站内页面布局高度相似这一先验知识。SCRIBES的切入点正是利用这种布局相似性，通过生成可复用的脚本而非逐页生成结果，实现效率与泛化的平衡。

## 核心方法

### 方法参照系

本文问题可归入基于LLM的结构化信息抽取范畴，但关键差异在于输出形式：传统方法直接输出抽取结果，而SCRIBES输出可执行的Python脚本。这一转变使得单次推理的结果能应用于同组多个页面，从而将计算复杂度从$O(N)$降至$O(N/K)$（$K$为组内页面数）。

### 基于组内交叉验证的强化学习框架

设计动机在于解决LLM生成脚本时缺乏泛化能力的问题，即生成的脚本往往仅对当前页面有效，无法处理同组其他页面的细微差异。SCRIBES采用组相对策略优化（GRPO），其奖励函数不仅包含脚本在输入页面（self-score）上的表现，更强调其在同组其他页面（cross-score）上的执行成功率。

$$
R(p) = \frac{1}{|G(p)|} r_{self}(p) + \frac{|G(p)|-1}{|G(p)|} \frac{1}{|G(p)|-1} \sum_{q \in G(p), q \neq p} r_{cross}(p, q)
$$

该公式表明，cross-score构成了奖励信号的主体，迫使模型学习能应对组内布局变异的通用脚本，而非过拟合于单一示例。

### 基于CommonCrawl失败案例的合成数据迭代

设计动机在于解决高质量标注数据稀缺的问题。SCRIBES提出两阶段训练：首先在小规模标注数据上训练，然后利用CommonCrawl（CC）中的未标注网页进行迭代优化。具体地，模型在CC数据上生成脚本并执行，筛选出未能提取出任何三元组的“失败案例”，仅用这些案例结合LLM直接抽取的伪标签进行后续训练。

$$
\mathcal{D}_{fail} = \{ p \in \mathcal{D}_{CC} \mid \text{Triples}(Script(p)) = \emptyset \}
$$

这一策略假设模型在已掌握简单模式后，通过聚焦失败案例能更高效地学习复杂或罕见布局，避免噪声奖励对已有能力的干扰。

## 实验评估

实验基于SemiBench数据集，该数据集包含139个网站的半结构化网页及三元组标注。基线覆盖直接LLM抽取（如GPT-4o、Llama-3.3-70B）和Agentic脚本生成方法（如ReAct式重试）。SCRIBES训练的Qwen2.5-32B模型在$F_1^{LM}$指标上达到33.2，与最强基线GO-120B的34.3相当，但计算成本大幅降低。

| 方法 | $R_{LM}$ | $P_{LM}$ | $F_1^{LM}$ |
| :--- | :--- | :--- | :--- |
| GO-120B 2-shot flatten | 42.3 | 46.3 | 40.4 |
| GO-120B agentic-3-iter 2-shot | 33.9 | 41.0 | 34.3 |
| Q-32B (SCRIBES + CC) | 37.4 | 36.0 | 33.2 |

消融实验显示，奖励函数中cross-score的存在至关重要：移除后，模型在Holdout页面上的$F_1^{LM}$下降7.2%。此外，使用失败案例子集进行CC训练比使用全量CC数据对Q-32B模型带来+3.5%的提升，验证了聚焦难例的有效性。

评估边界方面，实验仅覆盖英文网页，且SemiBench规模有限（192页标注）。代码已开源，但超参数调优细节较少，且未报告置信区间。

## 关联研究分析

从问题动机看，SCRIBES与文档图像解析（DIE）领域的端到端方法（如Donut、Qwen2-VL）共享“消除多阶段管道误差”的目标，但输入模态不同。DIE方法处理像素，依赖视觉编码器捕捉布局；SCRIBES处理HTML文本，依赖代码逻辑解析布局。这种差异意味着SCRIBES无法处理图像中的表格或公式，但其脚本复用机制在文本结构上更具计算优势。

从方法设计看，SCRIBES的RL奖励设计与Logics-Parsing等DIE方法中的结构一致性优化有异曲同工之妙，均通过全局奖励引导模型关注整体结构。然而，SCRIBES的奖励基于脚本执行结果，是离散且可验证的；而DIE方法中的奖励往往基于编辑距离或结构相似度，是连续且模糊的。这种离散性使得SCRIBES的RL训练更稳定，但也限制了其对细微语义错误的捕捉能力。

## 总结

SCRIBES解决了Web规模下半结构化数据抽取的效率瓶颈，通过利用同域网页布局相似性，将逐页LLM推理转化为组级脚本生成。其核心创新在于基于组内交叉验证的RL奖励设计和失败案例驱动的合成数据迭代，使Qwen2.5-32B模型在$F_1^{LM}$上达到33.2，与最强基线相当且计算成本更低。然而，实验显示模型在复杂嵌套列表和多列布局上性能显著下降，且脚本的静态特性使其难以适应动态变化的网页结构。当网页布局发生细微但关键的变异时，脚本是否仍能保持鲁棒性，论文未给出充分回答。
