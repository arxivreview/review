# ICLR2026最新论文 ｜ReTabAD: A Benchmark for Restoring Semantic Context in Tabular Anomaly Detection ｜恢复语义上下文的表格异常检测基准

研究机构：LG AI研究院、韩国成均馆大学

作者：Sanghyu Yoon、Dongmin Kim、Suhee Yoon 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.02060)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.02060)

> 表格异常检测（Tabular AD）长期受限于纯数值输入，导致模型无法利用特征描述与领域知识等关键语义线索，造成在类别型特征或专业领域数据上的检测失效。现有基准如 ADBench 虽提供了标准化数据，但剥离了文本元数据，使 LLM 等具备语义推理能力的模型无法发挥其上下文优势。ReTabAD 通过构建包含丰富文本元数据的 20 个精选数据集，并设计零样本 LLM 框架，验证了语义上下文对检测性能与可解释性的提升作用。该工作确立了上下文感知 AD 的评估范式，但其零样本方法在大规模数据下的可扩展性及对纯数值场景的泛化能力仍存疑。

## 研究背景

表格数据中异常的定义高度依赖领域语境，例如临床数据中“心率 200 bpm”的异常性需结合“成人静息状态”这一语义前提才能被正确识别。传统异常检测（AD）将数据视为数值向量 $x \in \mathbb{R}^K$，通过学习正常分布 $p(x)$ 来识别偏离，这种范式在处理混合了数值、类别及文本属性的异构表格数据时，往往通过整数编码或丢弃非数值字段来简化输入，从而丢失了特征间的语义关联与领域约束。这种信息缺失导致模型难以区分“良性偏差”与“关键异常”，尤其在特征语义复杂或数据量较小的场景中，检测边界容易失效。

现有基准如 DAMI Repository 和 ADBench 虽推动了算法对比，但其设计基于早期检测范式，仅保留数值特征，排除了特征描述、测量单位及操作约束等文本元数据。随着大语言模型（LLM）在上下文推理能力上的提升，利用语义元数据作为领域先验成为可能，但现有基准缺乏相应的文本标注，限制了 LLM 在表格 AD 中的应用。ReTabAD 旨在填补这一空白，通过恢复语义上下文，使模型能够基于语义而非纯统计模式进行异常判断，从而建立上下文感知 AD 的研究基础。

## 核心方法

### 条件分布建模与语义元数据注入

传统表格 AD 的目标是学习正常数据分布 $p(x)$，而 ReTabAD 将其扩展为条件分布 $p(x|M)$，其中 $M$ 为包含领域知识、特征描述及正常统计信息的语义元数据。这一改动的动机在于，纯数值向量无法表达“为什么”某个值是异常的，而语义元数据提供了决策边界所需的领域先验。通过引入 $M$，模型不再仅依赖统计离群度，而是结合语义合理性进行判断，解决了传统方法在类别型特征（如“ATRX=1”）上因缺乏语义解释而导致的误判问题。

### 零样本 LLM 框架设计

ReTabAD 提出了一种零样本 LLM 框架，通过结构化提示词（Prompt）将语义元数据与数据实例整合，无需任务特定训练即可进行异常检测。该框架的核心在于将每个数据实例 $x_i$ 序列化为自然语言，并注入三类语义上下文：领域知识 $C_{domain}$、特征描述 $C_{feature}$ 和正常统计 $C_{statistic}$。提示词结构如下：

$$
\text{Prompt}(x_i) = S_{role} \oplus C_{domain} \oplus C_{feature} \oplus C_{statistic} \oplus T(x_i) \oplus Q
$$

其中 $S_{role}$ 定义 LLM 的专家角色，$T(x_i)$ 为数据实例的文本格式化（如 "Record 0: LB=135, AC=3..."），$Q$ 为结构化输出查询，要求 LLM 返回异常分数 $s \in [0,1]$、关键特征列表 $F$ 及推理文本 $e$。这一设计使 LLM 能够利用预训练知识中的领域常识（如“凝血酶原时间升高提示肝功能受损”），将浅层数值偏差转化为领域感知的异常解释，从而在零样本设置下实现与训练式方法相当的检测性能。

## 实验评估

实验在 ReTabAD 的 20 个数据集上进行，评估协议采用单类分类设置，训练集包含 50% 正常样本，测试集包含剩余正常样本及所有异常样本。基线覆盖经典方法（如 IForest、LOF）、深度学习方法（如 DeepSVDD、MCM）及 LLM 方法（AnoLLM），但缺乏基于图或时序的特定表格方法。主实验结果显示，零样本 LLM（Gemini-2.5-pro）平均 AUROC 为 0.847，优于训练式 SOTA 方法 MCM（0.825），且在类别型特征丰富的数据集（如 glioma）上性能提升显著。

| 方法类型 | 代表算法 | 平均 AUROC | 平均排名 |
| :--- | :--- | :--- | :--- |
| 训练式 SOTA | MCM | 0.825 | 4.03 |
| 零样本 LLM (Ours) | Gemini-2.5-pro | 0.847 | 4.08 |
| 经典方法 | IForest | 0.778 | 7.43 |
| LLM 基线 | AnoLLM | 0.769 | 7.25 |

消融实验表明，语义元数据的类型对性能影响显著。Type D（包含正常统计、特征描述及领域知识）在所有 LLM 中均取得最高胜率，其中 Gemini-2.5-pro 的胜率达 0.80，而 Type A（仅正常统计）胜率仅为 0.05。这表明领域知识与特征描述的联合注入是性能提升的关键，而非单一信息源。此外，语义元数据显著提升了推理质量，Type D 在关键特征对齐的 F1@1 指标上从 Type A 的 0.086 提升至 0.344（campaign 数据集），证明 LLM 能够生成更具领域意义的异常解释。

| 上下文类型 | 包含信息 | Gemini-2.5-pro 胜率 |
| :--- | :--- | :--- |
| Type A | 正常统计 | 0.05 |
| Type B | 正常统计 + 特征描述 | 0.20 |
| Type C | 特征描述 + 领域知识 | 0.15 |
| Type D | 正常统计 + 特征描述 + 领域知识 | 0.80 |

评估边界方面，论文主要报告 AUROC 指标，缺乏对 FPR@95%TPR 等常用 AD 指标的对比，可能影响对误报率的全面评估。评估协议采用 50% 正常样本训练，未探讨不同训练比例对零样本 LLM 性能的影响。可复现性方面，论文提供了代码及超参数配置，但未披露 LLM 调用的具体成本与延迟，限制了其在实时场景中的部署评估。

## 关联研究分析

从问题动机看，ReTabAD 与 AnoLLM 均旨在利用 LLM 进行表格 AD，但 AnoLLM 受限于现有基准缺乏文本标注，仅能使用列名作为上下文，导致其无法捕获特征间的语义关系与领域约束。ReTabAD 通过构建包含丰富文本元数据的基准，解决了这一输入限制，使 LLM 能够基于完整的语义信息进行推理。这一差异源于任务特性：表格数据的异常定义高度依赖领域语境，仅靠列名无法提供足够的决策依据，而 ReTabAD 的元数据设计直接回应了这一需求。

从方法设计看，ReTabAD 的零样本 LLM 框架与训练式深度学习方法（如 MCM）在骨干网络与训练范式上存在根本差异。MCM 通过对比学习优化表示空间，依赖大量数据学习正常分布，而 ReTabAD 利用 LLM 的预训练知识，无需任务特定训练即可进行异常判断。这一冲突暗示，在数据量较小或语义信息丰富的场景中，零样本 LLM 可能比训练式方法更具优势，但在大规模纯数值数据上，其性能是否仍优于训练式方法，论文未给出回答。

## 总结

ReTabAD 针对表格 AD 中语义上下文缺失导致检测失效的核心矛盾，通过构建包含丰富文本元数据的基准并设计零样本 LLM 框架，证明了语义信息对检测性能与可解释性的提升作用。实验显示，零样本 LLM 平均 AUROC 达 0.847，优于训练式 SOTA 方法 MCM（0.825），且在类别型特征数据集上性能提升显著。然而，论文未探讨零样本 LLM 在大规模纯数值数据上的泛化能力，也未评估不同训练比例对性能的影响。当数据规模扩大至百万级且语义信息稀疏时，零样本 LLM 的性能是否仍能保持优势，论文未给出回答。
