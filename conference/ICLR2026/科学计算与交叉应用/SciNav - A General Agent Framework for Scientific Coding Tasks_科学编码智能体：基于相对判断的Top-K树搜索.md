# ICLR2026最新论文 ｜SciNav: A General Agent Framework for Scientific Coding Tasks ｜科学编码智能体：基于相对判断的Top-K树搜索

研究机构：美国俄亥俄州立大学

作者：Tianshu Zhang、Huan Sun

论文原文见 [arXiv](https://arxiv.org/abs/2603.20256)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.20256)

> 科学编码任务要求生成可执行且结果正确的程序，但现有端到端科研智能体多聚焦于假设生成等开放性问题，缺乏针对可验证代码输出的结构化搜索框架。通用智能体如OpenHands依赖逐步执行，而专用框架如AIDE则预设了明确的评估指标，这在真实科研场景中往往不可用。本文提出SciNav，通过引入相对判断（Relative Judgments）引导的Top-K比较树搜索（TKCTS），在受限预算下无需预定义指标即可高效筛选最优代码分支。该框架在ScienceAgentBench上将成功率提升至18.6%，但其在非代码类科学假设评估中的泛化能力仍存疑。

## 研究背景

当大语言模型（LLM）尝试解决科学编码任务时，其输出是具体的Python程序，而非模糊的文本假设。这种可执行性使得评估可以基于代码运行结果进行客观判定，区别于传统科研智能体中依赖专家主观评审的开放性问题。然而，科学编码任务往往缺乏预先定义的成功指标（如准确率或F1分数），且计算预算有限，这要求智能体在探索过程中能够自主判断代码质量，而非依赖外部反馈信号。

现有科研智能体主要沿两条路线发展：一是面向全流程的开放系统，如Agent Laboratory和ResearchAgent，它们生成假设、实验和报告，但输出难以自动评估；二是面向特定领域的编码框架，如AIDE，它假设存在明确的评估指标（如排行榜分数）并允许长时间（如24小时）的穷举搜索。这两类方法在真实科学编码场景中均存在局限：前者无法提供可验证的闭环，后者依赖不可用的先验指标。本文的切入点在于，针对缺乏预定义指标且预算受限的科学编码任务，构建一个不依赖外部评分、通过内部相对比较来引导搜索的结构化智能体框架。

## 核心方法

### 方法参照系

科学编码智能体的标准流程通常包含代码生成、执行调试和结果评估。与AIDE等依赖任务定义指标（task-defined metric）的框架不同，本文问题在于评估信号缺失。因此，参照系需从“基于绝对分数的优化”转向“基于相对偏好的搜索”，核心差异在于如何在不明确“正确答案”的情况下，判断哪个候选解更优。

### 相对判断引导的前沿比较器

在树搜索的每一步，智能体需决定扩展哪些分支。传统做法是让LLM对每个候选解打绝对分数，但绝对评分噪声大且区分度低。本文引入前沿比较器（Frontier Comparator），通过成对比较（pairwise comparison）来更新候选解的排名。其核心逻辑是：给定任务 $T$ 和两个候选解 $s_i, s_j$，LLM返回偏好权重 $w$，表示 $s_i$ 相对于 $s_j$ 的质量优势。

$$
w = \text{COMPARE}(T, s_i, s_j)
$$

该公式的物理含义是，LLM不输出一个孤立的数值，而是输出一个相对关系，这种比较提供了更清晰的信号，指出一个解在何处优于另一个解，从而在受限预算下更可靠地引导搜索方向。

### Top-K比较树搜索（TKCTS）

TKCTS将相对判断整合进树搜索结构。在每一轮迭代中，智能体从优先队列 $Q$ 中选择候选对进行比较，更新排名后，仅保留Top-K个最 promising 的分支，剪枝其余低潜力分支，并扩展保留分支的子节点。

$$
S_{keep} = \text{TOPK}(Q, K), \quad S_{drop} = Q \setminus S_{keep}
$$

这一设计解决了单一代理在长程探索中容易陷入局部最优的问题。通过动态剪枝和回溯，TKCTS允许智能体在路径停滞时返回之前排名较低的候选解重新探索，避免了过早承诺于次优解，从而在有限预算内实现更系统、自适应的解决方案搜索。

## 实验评估

实验在ScienceAgentBench和DA-Code两个基准上进行，基线包括Direct Prompting、Self-Debug和OpenHands。值得注意的是，实验未对比DeepScientist或Kosmos等记忆增强型多智能体系统，这可能限制了与最新长程自主系统的直接比较。

| Base Model | Agent | SR (%) | VER (%) | Cost ($) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-4o (2024-11-20) | Self-Debug | 15.0 | 67.0 | 0.030 |
| GPT-4o (2024-11-20) | SciNav | 18.6 | 69.9 | 0.342 |
| Claude-3.7 | Self-Debug | 22.5 | 84.3 | 0.066 |
| Claude-3.7 | SciNav | 25.5 | 72.5 | 0.893 |

在GPT-4o (2024-11-20)上，SciNav的成功率（SR）比Self-Debug高3.6个百分点，但成本增加了10倍以上。在Claude-3.7上，SciNav的SR提升3.0个百分点，但VER（有效执行率）反而从84.3%降至72.5%，表明相对判断机制可能在某些情况下引入了更多的执行错误，或Self-Debug在该模型上的调试效率更高。

消融实验显示，初始解数量从1增加到5，SR从40.5%提升至45.2%；启用自我改进（Self-Improve）后，SR进一步跃升至57.1%。这表明初始解的多样性和迭代自我修正对最终性能至关重要，相对判断仅是在此基础上的优化手段。

评估边界方面，论文未报告置信区间，且仅在ScienceAgentBench的“无专家知识”设置下测试。代码已开源，但超参数（如K值、预算B）的敏感性分析仅在附录中简要提及，未提供不同计算预算下的性能曲线，限制了对其成本效益比的全面评估。

## 关联研究分析

从问题动机看，SciNav与AIDE（Jiang et al., 2025）同属测试时扩展（test-time scaling）路线，但AIDE假设存在明确的评估指标（如准确率），而SciNav针对指标缺失场景。这一差异源于任务特性：机器学习竞赛任务通常有公开排行榜，而科学编码任务往往缺乏统一标准。SciNav的相对判断机制是对AIDE框架的关键改造，使其适用于更广泛的真实科研场景，但这也意味着其性能上限可能低于拥有明确指标时的AIDE。

从方法设计看，SciNav与OpenHands（Wang et al., 2024）形成鲜明对比。OpenHands基于ReAct框架逐步执行，缺乏全局搜索视角；SciNav则通过树搜索实现全局优化。然而，SciNav未采用多智能体协作（如DeepScientist的角色分工），而是依赖单智能体内部的相对判断。这种设计选择可能牺牲了长程记忆和复杂推理能力，换取了计算效率。在需要跨步骤依赖和长期规划的复杂科学任务中，单智能体树搜索是否足以替代多智能体协作，论文未给出回答。

## 总结

SciNav旨在解决科学编码任务中评估指标缺失与计算预算受限的矛盾。通过引入相对判断引导的Top-K树搜索，它避免了依赖预定义指标，实现了在有限预算下的高效探索。实验表明，在ScienceAgentBench上，SciNav将GPT-4o的成功率从15.0%提升至18.6%，验证了相对判断的有效性。然而，其在Claude-3.7上VER下降的现象，以及未与多智能体系统对比的局限，暴露了该框架在复杂模型和长程任务中的潜在短板。当任务复杂度增加，需要跨步骤依赖和长期记忆时，单智能体相对判断机制是否仍能保持优势，论文未给出回答。
