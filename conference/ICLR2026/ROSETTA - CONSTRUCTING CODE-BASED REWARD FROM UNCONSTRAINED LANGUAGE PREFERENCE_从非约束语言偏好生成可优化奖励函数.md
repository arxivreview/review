# ICLR2026最新论文 ｜ROSETTA: CONSTRUCTING CODE-BASED REWARD FROM UNCONSTRAINED LANGUAGE PREFERENCE ｜从非约束语言偏好生成可优化奖励函数

研究机构：美国斯坦福大学、美国西北大学

作者：Sanjana Srivastava、Kangrui Wang、Yung-Chieh Chan 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_89411967)

> 具身智能体需实时对齐人类动态、非结构化的语言偏好，但现有方法依赖固定目标与多轮反馈，无法处理单步内目标突变或语义歧义。ROSETTA 通过“偏好接地-阶段规划-代码生成”三级流水线，将自然语言直接转化为可执行的奖励代码，实现单步即时适应。该方法在 116 个偏好序列上取得 86% 人类满意度与 87% 成功率，但其依赖 LLM 推理能力的架构在长序列交互中面临错误累积风险，且缺乏对生成代码鲁棒性的形式化保证。

## 研究背景

当机器人执行“把球推到目标中心”的任务时，人类可能突然说“不，太慢了，往左一点”。这一指令包含对前序状态的否定、对速度的约束以及对位置的修正，且未提供结构化标签。传统强化学习（RL）奖励建模假设目标固定，通过 Bradley-Terry 模型从成对偏好中学习标量奖励，但此类方法无法处理目标在交互中动态变化、相互矛盾或依赖上下文的场景。更关键的是，自然语言中的指代消解（如“它”指代哪个物体）和隐含意图（如“慢一点”对应何种速度阈值）使得直接从文本映射到奖励函数成为非平凡问题。

现有基于大语言模型（LLM）的奖励生成方法，如 Eureka 和 Text2Reward，虽能利用代码生成能力将语言转化为奖励，但均预设目标在交互过程中保持不变，反馈仅用于微调固定目标的奖励参数。这导致它们无法应对人类偏好中常见的“目标重构”——即新指令完全改变任务结构而非优化现有结构。此外，这些方法缺乏对语言歧义的显式处理机制，直接依赖 LLM 的字面理解，易在上下文依赖或口语化表达中失效。ROSETTA 的切入点在于将奖励生成解耦为语义理解、任务规划与代码实现三个独立阶段，通过引入中间结构化表示（接地偏好与奖励阶段）来桥接自然语言的模糊性与奖励函数的精确性，从而支持单步内的目标动态适应。

## 核心方法

### 方法参照系

ROSETTA 属于基于 LLM 的奖励工程路线，其通用流程为：输入语言描述 → LLM 生成奖励代码 → 训练策略 → 评估。与 Eureka 等基线相比，关键差异在于输入约束：基线要求目标固定且反馈结构化，而 ROSETTA 处理目标动态变化、语言非约束且需单步适应的场景，因此必须在代码生成前引入语义消歧与任务分解环节。

### 偏好接地与阶段规划

设计动机在于解决 LLM 对非结构化语言的字面依赖导致的语义错位。例如，“不，往中心推”中的“不”是否定执行而非目标，“它”需映射到具体物体，“中心”需结合环境几何定义。ROSETTA 引入偏好接地模块，利用 gpt-4o 结合轨迹图像、符号状态与历史偏好，生成单句接地目标。该过程可形式化为：给定历史偏好序列 $H_t = \{l^{(0)}, h^{(1)}, ..., h^{(t)}\}$ 与当前策略 $\pi^{(t-1)}$，接地模块输出 $g^{(t)} = \text{Ground}(H_t, \pi^{(t-1)})$，其中 $g^{(t)}$ 是消歧后的单句目标描述。随后，阶段规划模块将 $g^{(t)}$ 转化为结构化奖励阶段 $S^{(t)} = \{s_1, s_2, ..., s_k\}$，每个 $s_i$ 对应一个可独立奖励的子目标。这一设计将模糊语言转化为 LLM 擅长的规划任务，避免直接代码生成中的语义跳跃。

### 代码生成与验证

设计动机在于确保生成的奖励代码既语义匹配又可优化，同时抑制 LLM 在空间推理上的幻觉。编码模块接收 $S^{(t)}$、环境代码与领域知识清单，使用 o1-mini 生成多个奖励函数变体 $R^{(t)}_v$。关键创新在于引入迭代验证机制：对每个变体，o1-mini 在模拟器中运行并修正错误，最终输出 $R^{(t)}_{final}$。该过程可表示为：

$$
R^{(t)}_{final} = \text{Verify}(\text{Code}(S^{(t)}, E, K), M)
$$

其中 $E$ 为环境代码，$K$ 为领域知识清单，$M$ 为模拟器。验证步骤确保代码可执行，而领域知识清单（如奖励稠密化、阶段掩码）引导 LLM 生成符合 RL 优化特性的奖励结构，而非仅语义正确的代码。

## 实验评估

实验在 ManiSkill 3 的五个操作环境中进行，对比 Eureka 与 Text2Reward，并设置三个消融变体（无接地、无阶段、无后续验证）。主结果显示，ROSETTA 在 86.0% 的偏好上提升了人类满意度，平均满意度评分为 79.0%，成功率达 87%。与基线相比，ROSETTA 在目标相关、行为偏好和偏好性指令上显著优于 Eureka 和 Text2Reward，但在纠正性指令上表现相当，这与基线专为纠正场景设计的事实一致。

| 指标 | ROSETTA | Eureka | Text2Reward |
| :--- | :--- | :--- | :--- |
| 人类满意度 (%) | 86.0 | - | - |
| 平均成功率 (%) | 87.0 | - | - |
| 语义匹配 (Cascading) | 78.0 | - | - |

消融实验揭示了各模块的贡献：无接地变体在上下文依赖偏好上对齐度显著下降，但可优化性反而更高，因为未接地的偏好常导致对前序奖励的最小修改，若该奖励可优化则成功率高但语义错位。无阶段变体在整体性能上全面下降，表明结构化规划对处理复杂目标至关重要。无后续验证变体在纠正性指令上表现最佳，因为验证步骤在此场景下可能引入干扰，但在其他场景下验证显著提升了代码可执行性（从 79.35% 提升至 95.38%）。

评估边界方面，论文未报告置信区间，且人类满意度依赖 Upwork 标注者的主观判断，可能存在个体偏差。代码未公开，超参数（如变体数量 $V$）固定为 3，未进行系统调优。此外，实验仅覆盖操作任务，未验证在导航或协作任务中的泛化能力。

## 关联研究分析

从问题动机看，ROSETTA 与 CausalRM 等鲁棒奖励模型路线存在根本差异。CausalRM 通过因果分解阻断虚假相关，假设奖励模型需从静态数据中学习鲁棒表示；而 ROSETTA 假设奖励函数是动态生成的，鲁棒性来源于 LLM 的实时推理与验证机制。这一差异源于任务特性：CausalRM 面向固定目标的偏好预测，而 ROSETTA 面向动态目标的即时适应。ROSETTA 未涉及奖励模型对虚假特征的过拟合问题，其“鲁棒性”体现在语义匹配而非分布外泛化，这暗示在长序列交互中，LLM 可能累积语义错误而非优化压力导致的黑客行为。

从方法设计看，ROSETTA 与逆向奖励学习（IRL）方法如 Masked IRL 共享从人类反馈推断奖励的目标，但路径不同。Masked IRL 利用 LLM 生成掩码以隔离无关状态分量，假设奖励函数可参数化学习；ROSETTA 则直接生成代码，无需参数化模型，但依赖 LLM 的代码生成能力。ROSETTA 的 Staging 模块可视为一种隐式过程奖励模型（PRM），将任务分解为可独立奖励的阶段，但不同于 PRM 的步骤级评分，ROSETTA 的阶段是语义层面的规划而非数值化的步骤奖励。这种设计避免了 PRM 在长序列中的信用分配偏差，但引入了 LLM 规划错误传播的风险，论文未量化该风险对最终策略性能的影响。

## 总结

ROSETTA 解决的核心矛盾是自然语言偏好的动态性与奖励函数静态性之间的冲突。现有方法因预设目标固定而无法处理单步内的目标重构，ROSETTA 通过引入接地与阶段规划中间表示，将模糊语言转化为结构化奖励计划，再由 LLM 生成可执行代码，实现了单步即时适应。实验证明其在 116 个偏好上达到 86% 人类满意度与 87% 成功率，显著优于 Eureka 和 Text2Reward。然而，论文自身实验暴露了错误累积问题：前序步骤的 LLM 幻觉会污染后续提示，导致性能在第四轮交互时下降至 78.1% 成功率。当交互序列长度超过四轮时，接地模块能否有效隔离历史错误而非简单继承，论文未给出回答。
