# ICLR2026最新论文 ｜LongHorizonUI: A Unified Framework for Robust Long Horizon Task Automation of GUI Agent ｜长程GUI智能体鲁棒性框架

研究机构：中国科学院、中国科学院大学

作者：Bin Kang、Shaoguo Wen、YIFEI BI 等 8 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_74666488)

> 长程GUI任务中，单步错误会随序列长度指数级累积，导致智能体在超过15步后性能崩溃。现有基于监督微调或强化学习的方法缺乏对历史状态一致性的显式验证与执行失败后的即时补偿机制，难以维持跨步上下文连贯。LongHorizonUI通过无微调的感知-反思-补偿闭环框架，在长程基准上实现了显著的性能提升。该框架验证了结构化推理与多级执行回滚在长程场景下的有效性，但其对底层多模态大语言模型推理延迟的依赖，限制了其在实时性要求极高场景中的适用性。

## 研究背景

GUI智能体在动态交互环境中执行任务时，面临的核心挑战是部分可观测性下的状态依赖维护。当任务序列延长，智能体必须准确追踪界面元素的时空变化，任何一步的定位偏差或动作失误都会污染后续决策的输入状态。这种错误累积效应并非线性，而是随着序列长度增加呈现非线性恶化，导致智能体在长程任务中频繁偏离目标轨迹。

当前主流路线主要依赖大规模监督微调或在线强化学习来提升智能体的自主决策能力。监督微调方法在短程任务上表现优异，但受限于训练数据的多样性，难以泛化到未见过的复杂工作流；强化学习方法虽能探索新策略，但试错过程扩大了动作空间，进一步放长了程中的累积误差。此外，现有评测基准多聚焦于15步以内的短程任务，无法充分暴露智能体在长序列下的上下文一致性失效问题。LongHorizonUI的切入点在于，不改变底层模型参数，而是通过外部结构化模块显式管理历史验证与执行补偿，直接针对长程任务中的状态漂移与执行失败进行干预。

## 核心方法

### 方法参照系

本文问题属于长程GUI智能体决策框架的改进。通用流程通常由感知、决策、执行三阶段组成，但标准流程缺乏对历史状态一致性的显式校验，且执行阶段假设动作指令能直接映射为物理坐标，忽略了动态界面下的定位不确定性。本文的关键差异在于引入了基于索引的状态锚定与多级补偿执行机制，将隐式的序列建模转化为显式的闭环验证。

### 多模态增强感知器

感知阶段通常仅依赖多模态大语言模型的视觉编码，易在复杂界面中产生定位幻觉。本文提出多模态增强感知器，通过并行运行图标检测与光学字符识别模块，为每个UI元素分配唯一空间索引。该设计动机在于，索引作为稳定锚点，能抵抗微小布局变化带来的定位漂移。元素绑定通过最大交并比函数实现：

$$j^* = \arg\max_j \text{IoU}(b_i, b_j)$$

其中 $b_i$ 为图标边界框，$b_j$ 为文本边界框。仅当 $\text{IoU}(b_i, b_j^*) \ge \tau$ 时，才将文本 $t_{j^*}$ 绑定至图标 $i$。这种显式的语义绑定确保了感知输出的结构化与一致性，为后续决策提供了可靠的时空状态表示。

### 深度反思决策器

决策阶段通常直接输出动作，缺乏对历史执行结果的验证。本文设计深度反思决策器，通过结构化JSON Schema强制实施三级闭环推理。该设计动机在于，显式验证历史状态一致性可阻断错误向后续步骤传播。决策过程包含历史验证、目标检查与动作可解释性三个字段，其中历史验证通过OCR与图标检测确认UI状态转移是否成功。若检测到错误对话框或无响应元素，则触发根因分析。这种机制将隐式的序列依赖转化为显式的状态校验，确保每一步动作都建立在已验证的环境状态之上。

### 补偿动作执行器

执行阶段通常假设动作指令能直接映射为屏幕坐标，但在动态界面中，坐标漂移或遮挡会导致点击失败。本文引入补偿动作执行器，实施多级降级策略。该设计动机在于，通过冗余的执行路径与实时回滚机制，容忍单次定位失败。执行器按优先级尝试索引、相对坐标、绝对坐标三种编码方式。若索引点击失败，则在元素边界框内均匀采样相对坐标：

$$p_{rel} = (x_{min} + \lambda w, y_{min} + \lambda h), \quad \lambda \sim U[0, 1]$$

其中 $w, h$ 为边界框宽高。若仍失败，则使用绝对坐标并添加有界扰动 $\epsilon$（$\|\epsilon\|_\infty \le 5$ px）以避开边缘遮挡。所有候选均失败时，系统回滚至上一已提交快照，确保执行轨迹的可靠性。

## 实验评估

实验在LongGUIBench、ScreenSpot、AndroidControl及GUI-Odyssey上进行，基线覆盖GPT-4o、UI-TARS-1.5、AgentCPM-GUI等主流模型，但缺失MobileRL等在线强化学习方法的直接对比。

| 基准 | 模型 | 低层指令SR (%) | 高层指令SR (%) |
| :--- | :--- | :--- | :--- |
| LongGUIBench (General) | LongHorizonUI | 85.3 | 52.3 |
| LongGUIBench (General) | UI-TARS-1.5 | 79.2 | 21.8 |
| LongGUIBench (Game) | LongHorizonUI | 83.9 | 52.1 |
| LongGUIBench (Game) | UI-TARS-1.5 | 69.5 | 19.4 |

在长程基准上，LongHorizonUI的高层指令成功率较UI-TARS-1.5提升30.5%，表明结构化反思机制对复杂目标分解具有显著增益。

| 消融组件 | 移除影响 | 说明 |
| :--- | :--- | :--- |
| 图标检测器 | -6.1% | 细粒度识别能力下降 |
| OCR模块 | -2.3% | 图标-文本复合控件错误增加 |
| 相对坐标补偿 | +1.2% | 索引失败后的第一级降级 |
| 绝对坐标补偿 | +2.5% | 第二级降级，增加鲁棒性 |
| 历史坐标补偿 | +3.9% | 融合历史空间线索，收益最大 |

消融实验显示，历史坐标补偿贡献最大，说明融合历史空间线索对动态界面下的定位鲁棒性至关重要。移除图标检测器导致性能下降最显著，验证了显式索引在长程状态追踪中的核心作用。

评估协议缺乏对推理延迟与Token消耗的量化，且LongGUIBench由6名专家标注，样本量371，统计显著性未报告。代码已开源，但超参数配置细节仅在附录中简要提及，复现时需注意骨干模型版本的一致性。

## 关联研究分析

从问题动机看，LongHorizonUI与PAL-UI均关注长程记忆，但PAL-UI侧重历史摘要的压缩与检索，而本文侧重实时执行补偿。PAL-UI通过双层级历史摘要增强上下文感知，但缺乏对执行失败的回滚机制；本文通过补偿动作执行器直接干预执行层，但历史管理依赖MLLM的即时推理，未引入显式的摘要存储。这种差异源于任务特性：PAL-UI面向多步骤工作流的信息整合，本文面向动态界面下的动作可靠性。

从方法设计看，LongHorizonUI与UI-TARS同属原生模型驱动路线，但UI-TARS依赖大规模监督微调提升视觉接地能力，而本文采用无微调框架。UI-TARS在ScreenSpot-V2上达到91.6%的点击准确率，而本文在ScreenSpot上平均成功率为90.4%，略低于UI-TARS。这一差距表明，无微调框架在静态定位精度上不及经过专门微调的模型，但在长程动态任务中，本文的补偿机制弥补了定位精度的不足，实现了整体任务成功率的提升。这种权衡揭示了训练范式与框架设计之间的互补性：微调提升感知上限，框架提升执行鲁棒性。

## 总结

LongHorizonUI旨在解决长程GUI任务中错误累积导致的性能崩溃问题。现有方法缺乏对历史状态一致性的显式验证与执行失败后的即时补偿，而本文通过无微调的感知-反思-补偿闭环框架，将隐式序列建模转化为显式闭环验证。实验表明，该框架在LongGUIBench上高层指令成功率达52.3%，较基线提升30.5%，验证了结构化推理与多级执行回滚的有效性。然而，框架依赖多模态大语言模型的实时推理，继承了其固有的延迟瓶颈，且未报告计算效率指标。当任务序列长度进一步增加至30步以上时，补偿机制的累积延迟是否会抵消其鲁棒性增益，论文未给出回答。
