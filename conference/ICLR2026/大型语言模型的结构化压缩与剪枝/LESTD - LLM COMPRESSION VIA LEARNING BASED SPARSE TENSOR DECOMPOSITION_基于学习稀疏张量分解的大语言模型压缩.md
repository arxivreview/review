# ICLR2026最新论文 ｜LESTD: LLM COMPRESSION VIA LEARNING BASED SPARSE TENSOR DECOMPOSITION ｜基于学习稀疏张量分解的大语言模型压缩

作者：Yi Li、Zhichun Guo、Miao Yin 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_37921596)

> 大语言模型（LLM）部署受限于参数量带来的存储与内存开销，后训练压缩是避免重训练的主流路径。现有低秩分解方法多采用矩阵级独立压缩，忽略了多注意力头（MHA）间的结构冗余，且张量分解产生的稠密核心张量成为新的存储瓶颈。本文提出 LeSTD，通过两阶段框架先学习共享子空间基，再对核心张量进行基于闭式重要性分数的稀疏化。该方法在 GPT-J 等模型上实现了更优的压缩-精度权衡，但其非结构化稀疏核心在标准硬件上的实际加速收益有限，且缺乏与主流结构化剪枝方法的横向对比。

## 研究背景

Transformer 架构中的 MHA 模块由多个注意力头组成，每个头包含 Query、Key、Value 和 Output 投影矩阵。这些矩阵在处理相同输入分布时，往往学习到重叠的特征子空间，即存在层内头间共享结构。然而，传统的奇异值分解（SVD）压缩方法将每个权重矩阵视为独立对象，无法捕捉这种跨头的高阶相关性，导致压缩率受限。

低秩分解是 LLM 压缩的重要路线，SVD-LLM 和 TensorLLM 等方法已证明其在保持性能的同时减少参数量的有效性。然而，TensorLLM 等张量分解方法虽然通过 Tucker 分解识别了共享基，但其核心张量（Core Tensor）保持稠密状态。随着 Tucker 秩的增加以维持精度，核心张量的存储开销呈多项式增长，形成了“稠密核心瓶颈”，限制了进一步压缩的空间。LeSTD 的切入点在于解决这一瓶颈，通过引入核心张量稀疏化，在共享子空间内消除冗余，从而突破现有张量分解方法的压缩上限。

## 核心方法

### 方法参照系

LeSTD 属于后训练低秩分解压缩路线，其参照系为 TensorLLM 的 MHA 张量化 Tucker 分解流程。标准流程将 MHA 权重重组为四阶张量，通过高阶正交迭代（HOOI）求解共享因子矩阵和稠密核心张量。LeSTD 的关键差异在于，它不满足于低秩近似，而是在 Stage I 得到的共享正交子空间内，对核心张量执行显式的稀疏化操作，将稠密核心转化为超稀疏核心。

### 共享子空间 Tucker 分解

Stage I 旨在为所有注意力头学习一个高质量的共享正交基，以捕捉头间共性。设计动机是解决矩阵级 SVD 忽略头间结构冗余的问题，通过联合优化提升基的表达能力。具体地，将 MHA 权重张量化为 $\mathbf{W}_{total} \in \mathbb{R}^{d_{model} \times d_{head} \times 4 \times h}$，其中 $h$ 为头数。LeSTD 对模式 1、2、3 进行 Tucker 分解，保留模式 4（头索引）不压缩，使得所有头共享因子矩阵 $\mathbf{U}^{(n)}$，而每个头拥有独立的核心切片 $\mathbf{G}_i$。优化目标为最小化重构误差：

$$ \min_{\mathbf{U}^{(1)}, \mathbf{U}^{(2)}, \mathbf{U}^{(3)}, \mathbf{G}_{total}} \|\mathbf{W}_{total} - \mathbf{G}_{total} \times_1 \mathbf{U}^{(1)} \times_2 \mathbf{U}^{(2)} \times_3 \mathbf{U}^{(3)}\|_F^2 $$

该公式通过 HOOI 算法迭代求解，确保共享基 $\mathbf{U}^{(n)}$ 能够最大程度地重构原始 MHA 权重，同时允许头特异性信息保留在核心张量中。

### 基于重要性分数的核心稀疏化

Stage II 针对 Stage I 产生的稠密核心张量 $\mathbf{G}_{total}$ 进行稀疏化，以消除稠密核心瓶颈。设计动机是解决 Tucker 分解中核心张量存储开销随秩增加而急剧上升的问题，通过移除低重要性元素实现极致压缩。LeSTD 定义了核心元素 $g_\beta$ 的重要性分数，基于将其置零后重构误差的归一化增量。由于 Stage I 的基张量 $\mathbf{B}_\beta$ 是正交的，重要性分数简化为：

$$ \text{Imp}(g_\beta) = \frac{E(g_\beta=0) - E}{E} = \frac{g_\beta^2}{E} $$

其中 $E$ 为 Stage I 的重构误差。该闭式解表明，按重要性排序等价于按幅值 $|g_\beta|$ 排序。算法迭代地剪除最低分数的元素，并对剩余元素进行闭式重拟合（Refitting），以在固定稀疏度下最小化重构误差，最终生成超稀疏核心 $\mathbf{G}_{sparse}$。

## 实验评估

实验在 GPT-J (6B)、Llama2 (13B) 和 OPT (30B) 上评估，基准包括 WikiText-2、MathQA、GSM8K 和 TruthfulQA。基线覆盖低秩分解（ASVD, SVD-LLM, TensorLLM）、剪枝（SliceGPT）和量化（PB-LLM, BiLLM）。LeSTD 在 WikiText-2 上表现显著优于 SVD-LLM 和 TensorLLM。例如，在 GPT-J 0.6 压缩率下，LeSTD 的困惑度（PPL）为 9.48，而 SVD-LLM 为 20.28，TensorLLM 高达 11105.18。这表明 LeSTD 在保持精度的同时实现了更高的压缩效率。

| 方法 | GPT-J PPL (0.6) | Llama2-13B PPL (0.6) | OPT-30B PPL (0.6) |
| :--- | :--- | :--- | :--- |
| SVD-LLM | 20.28 | 14.97 | 14.92 |
| TensorLLM | 11105.18 | 14.09 | 11.95 |
| LeSTD | 9.48 | 7.93 | 9.98 |

消融实验显示，Stage II 的重拟合步骤对性能至关重要。在 GPT-J 0.6 压缩率下，移除重拟合步骤后，PPL 从 9.57 上升至 11.25，吞吐量从 11925.90 降至 11932.45（变化微小，主要影响精度）。此外，将稠密矩阵乘法替换为稀疏矩阵乘法（torch.sparse.mm）仅带来约 5.4% 的吞吐量提升（从 11945.98 到 12592.54 tokens/sec），说明加速主要源于结构变化而非稀疏算子本身。

| 配置 | PPL | Throughput (tokens/sec) |
| :--- | :--- | :--- |
| LeSTD (Full) | 9.57 | 11925.90 |
| LeSTD (w/o refit) | 11.25 | 11932.45 |
| torch.matmul | 11945.98 | - |
| torch.sparse.mm | 12592.54 | - |

评估边界方面，LeSTD 未覆盖 HellaSwag、MMLU 等常识推理基准，且未与结构化剪枝方法（如 LLM-Pruner）进行直接对比。代码未公开，但提供了详细的超参数设置（如 Tucker 秩 $R_1, R_2, R_3$ 和稀疏率 $\alpha$）。实验在标准 Transformers 库中运行，无需自定义内核，但非结构化稀疏核心的硬件加速潜力未充分验证。

## 关联研究分析

从问题动机看，LeSTD 与 TensorLLM 同属张量分解路线，但 LeSTD 针对 TensorLLM 的稠密核心瓶颈提出了稀疏化解决方案。TensorLLM 通过全局 Tucker 分解识别共享基，但核心张量保持稠密，限制了压缩率；LeSTD 通过 Stage II 的稀疏化，在相同基下进一步压缩核心，实现了更高的压缩比。这一差异源于对“压缩后存储瓶颈”的不同理解：TensorLLM 关注维度降低，LeSTD 关注潜空间内的冗余消除。

从方法设计看，LeSTD 与 SVD-LLM 等矩阵级方法存在根本差异。SVD-LLM 独立处理每个权重矩阵，忽略了头间相关性；LeSTD 通过张量化和共享基，显式建模了头间结构。然而，LeSTD 的稀疏核心是非结构化的，这与领域共识中“结构化剪枝更利于硬件加速”的观点相悖。LeSTD 依赖标准库的稀疏算子，其实际加速效果可能低于结构化剪枝，这在论文中仅通过吞吐量数据间接体现，未深入分析硬件层面的效率差异。

## 总结

LeSTD 旨在解决张量分解中稠密核心张量导致的存储瓶颈，通过两阶段框架实现共享基学习与核心稀疏化的解耦。其核心创新在于利用闭式重要性分数指导核心张量的剪枝与重拟合，从而在保持精度的同时突破压缩上限。实验表明，LeSTD 在 GPT-J 0.6 压缩率下 PPL 为 9.48，显著优于 SVD-LLM 的 20.28。然而，其非结构化稀疏核心在标准硬件上的加速收益有限，且缺乏与结构化剪枝方法的对比，限制了其在实际部署中的竞争力。当核心稀疏度进一步增加时，非结构化稀疏矩阵乘法的效率是否会成为新的瓶颈，论文未给出明确回答。
