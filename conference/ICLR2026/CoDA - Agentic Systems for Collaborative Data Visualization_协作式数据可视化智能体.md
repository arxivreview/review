# ICLR2026最新论文 ｜CoDA: Agentic Systems for Collaborative Data Visualization ｜协作式数据可视化智能体

研究机构：美国加州大学圣塔芭芭拉分校

作者：Zichen Chen、Jiefeng Chen、Sercan Ö. Arik 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.03194)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.03194)

> 数据可视化自动化旨在将自然语言查询转化为直观图表，以解决分析师在数据准备与绘图上耗费大量时间的问题。现有单模型或简单多智能体系统在处理多文件复杂数据时，常因直接摄入原始数据导致上下文溢出，或因缺乏深度反思机制而在迭代修改中失效。CoDA 通过元数据预处理规避 Token 限制，并引入全局任务列表与搜索智能体，构建了一个包含理解、规划、生成与反思的闭环协作框架。该框架在 MatplotBench 上显著优于现有基线，但其依赖 LLM 作为评估器的机制在极端复杂场景下的可靠性仍存疑。

## 研究背景

数据分析师在探索复杂数据集时，往往需要处理多个非结构化文件，并反复调整图表以平衡清晰度与美学。这一过程的核心瓶颈在于自然语言查询的模糊性与底层数据结构的复杂性之间的映射困难。为应对此挑战，大语言模型（LLM）被引入以自动化代码生成，但直接处理原始数据极易触发上下文窗口限制，导致模型在长程任务中出现幻觉或逻辑断裂。

早期基于规则的系统如 Voyager 和 Draco 虽能确保合规性，但受限于预定义模板，无法适应多样化的自然语言需求。随后的 LLM 驱动方法如 CoML4VIS 利用链式思维（Chain-of-Thought）生成代码，但缺乏对数据元信息的深度分析，导致在多源数据整合时表现脆弱。现有的多智能体框架如 VisPath 和 MatplotAgent 虽引入了协作机制，但往往将推理重心局限于初始查询解析，缺乏针对代码错误和视觉质量的持久性反思。CoDA 的切入点在于将可视化任务重构为协作式问题解决过程，通过专业化智能体分工与元数据驱动预处理，解决复杂数据环境下的鲁棒性问题。

## 核心方法

### 方法参照系

CoDA 属于智能体生成框架，其标准流程通常包含查询解析、数据摄入、代码生成与执行。与通用流程的关键差异在于，CoDA 摒弃了直接摄入原始数据文件的做法，转而通过元数据摘要（Metadata Summary）作为智能体间通信的中间表示，以规避 LLM 的上下文限制。

### 元数据驱动预处理与全局任务规划

传统方法直接读取 CSV 或 JSON 文件，导致 Token 消耗巨大且易丢失关键结构信息。CoDA 引入数据处理器（Data Processor）智能体，利用轻量级工具提取模式（Schema）、统计特征及潜在转换建议，生成紧凑的元数据摘要 $M$。该摘要作为全局状态共享给下游智能体，确保后续决策基于数据本质而非原始噪声。同时，查询分析器（Query Analyzer）将自然语言查询 $Q$ 分解为全局待办列表（Global TODO List）$T$，形式化为：

$$ T = \{ t_1, t_2, ..., t_n \mid t_i \in \text{TaskType}, \text{dep}(t_i) \subseteq T \} $$

此设计动机在于解决单模型在长上下文中的注意力分散问题，通过显式的任务依赖关系协调多智能体协作，确保复杂查询被拆解为可执行的原子操作。

### 搜索增强生成与视觉反思闭环

在代码生成阶段，CoDA 引入搜索智能体（Search Agent），根据图表类型检索相关代码示例 $E$，以弥补 LLM 在特定绘图库语法上的记忆缺陷。生成的代码 $C$ 经调试智能体执行后，由视觉评估器（Visual Evaluator）基于生成图像 $I$ 与查询 $Q$ 进行评分。若评分低于阈值 $\theta_q$，系统触发反思循环，设计探索器（Design Explorer）根据评估报告 $R$ 更新设计规范 $D$，代码生成器据此修订代码。该闭环机制的改进价值在于，它将质量验证从代码静态检查提升至视觉结果层面，通过迭代修正解决布局重叠、颜色冲突等单步生成难以捕捉的视觉缺陷。

## 实验评估

CoDA 在 MatplotBench 和 Qwen Code Interpreter 基准上进行了评估，基线包括 MatplotAgent、VisPath 和 CoML4VIS，所有方法均使用 Gemini-2.5-Pro 作为骨干 LLM。CoDA 在 MatplotBench 上取得了 79.5% 的总体得分（OS），较最强的基线 MatplotAgent（51.0%）提升 28.5 个百分点，较 VisPath（44.2%）提升 35.3 个百分点。在 Qwen 基准上，CoDA 同样领先，OS 达到 7.4% 的相对提升。

| 方法 | MatplotBench OS (%) | Qwen OS (%) |
| :--- | :--- | :--- |
| MatplotAgent | 51.0 | - |
| VisPath | 44.2 | - |
| CoML4VIS | 62.6 | - |
| **CoDA** | **79.5** | **7.4 (rel. gain)** |

消融实验显示，移除全局 TODO 列表导致 OS 从 79.5% 降至 75.1%，移除搜索智能体则降至 76.0%。这表明全局任务规划对复杂查询的分解至关重要，而搜索智能体主要提升了代码执行成功率（EPR），防止了因语法错误导致的任务失败。迭代次数分析表明，性能在 3 次迭代后趋于稳定，增加迭代次数并未带来显著收益，反而增加了计算开销。

评估协议主要依赖 LLM-as-a-Judge 进行图像级评分，缺乏针对数据保真度的独立验证。实验未报告置信区间，且仅在单一骨干 LLM（Gemini-2.5-Pro）上进行了主要对比，虽在附录中测试了其他 LLM，但未深入分析不同骨干对多智能体协作效率的影响。代码未公开，限制了可复现性。

## 关联研究分析

从可靠性保障机制看，CoDA 与 MultiVis-Agent 代表了两种不同的路径。MultiVis-Agent 引入四层逻辑规则框架，通过形式化约束防止无限循环，适合工业级高可靠场景；而 CoDA 依赖数据驱动的自我反思，通过视觉评估器动态修正错误。CoDA 的反思机制在创意生成和复杂语义理解上可能更具灵活性，但在极端复杂任务中，缺乏硬性逻辑约束可能导致陷入局部最优或无限循环，这是其相对于 MultiVis-Agent 的潜在盲区。

从数据预处理策略看，CoDA 与 NL2Dashboard 存在显著差异。NL2Dashboard 采用中间表示（IR）驱动，强调细粒度控制与 Token 效率，适用于仪表盘生成；CoDA 则通过元数据摘要实现轻量级预处理，侧重于规避上下文限制。CoDA 的元数据策略牺牲了部分原始数据细节，可能在处理高度非结构化或噪声数据时丢失关键信息，而 NL2Dashboard 的 IR 构建成本较高，但能提供更精确的数据映射。两者在数据保真度与计算效率之间的权衡点不同，CoDA 更适合大规模多文件场景，而 NL2Dashboard 更适合交互式仪表盘构建。

## 总结

CoDA 旨在解决多智能体系统在长程可视化任务中因上下文溢出和缺乏反思导致的可靠性问题。其核心切入点是通过元数据预处理规避 Token 限制，并引入全局任务列表与搜索智能体增强协作深度。实验证明，该框架在 MatplotBench 上实现了 79.5% 的总体得分，显著优于现有基线。然而，其依赖 LLM 作为视觉评估器的机制缺乏独立的数据保真度验证，且在极端复杂场景下，自我反思机制是否比形式化逻辑规则更鲁棒，论文未给出明确回答。当数据规模进一步扩大或查询复杂度超出当前元数据摘要的表达能力时，CoDA 的反思闭环是否仍能维持稳定的收敛，是一个值得深入探究的问题。
