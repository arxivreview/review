# ICLR2026最新论文 ｜MASTER SKILL LEARNING WITH POLICY-GROUNDED SYNERGY OF LLM-BASED REWARD SHAPING AND EXPLORING ｜策略协同的奖励塑形与探索

研究机构：深圳大学

作者：Yanbin Chang、Junfan Lin、Jie Jiang 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_78539822)

> 机器人技能学习中的核心矛盾在于：大语言模型（LLM）生成的目标导向奖励虽能减少人工调参，但往往因忽视状态空间探索而陷入局部最优；传统好奇心驱动探索又因缺乏任务相关性导致资源浪费。PoRSE 通过 LLM 构建可供性状态空间（AFS）并引入动态平衡机制，将目标奖励与探索奖励协同优化。该框架在 24 项机器人任务中显著提升了稀疏奖励场景下的成功率，但其对 LLM 生成 AFS 的鲁棒性依赖及动态权重调整的稳定性边界尚存疑。

## 研究背景

在强化学习（RL）中，智能体通过最大化累积奖励来优化策略，但奖励函数的设计直接决定了优化方向的有效性。当奖励仅反映最终目标达成（如物体到达指定位置）时，智能体在稀疏奖励环境中难以获得足够的梯度信号，导致探索效率低下。为解决此问题，内在动机机制引入基于状态访问频率的探索奖励，但传统方法将探索与任务目标解耦，导致智能体在无关状态上浪费计算资源。

LLM 的兴起为自动化奖励设计提供了新路径。Eureka 框架利用 LLM 根据任务描述生成可执行的奖励代码，并通过 RL 反馈迭代优化，显著降低了人工调参成本。然而，现有 LLM 驱动方法仅关注目标导向奖励（$R_g$），忽略了状态空间的探索维度。在高自由度任务（如灵巧手抓取）中，策略搜索空间巨大且目标状态稀疏，单一的目标导向奖励极易使智能体陷入局部最优。ROSKA 虽引入策略继承以提升数据效率，但其奖励设计仍缺乏与任务相关的探索引导。PoRSE 的切入点在于：利用 LLM 不仅生成目标奖励，还构建任务相关的可供性状态空间，并通过动态平衡机制协同优化目标达成与状态探索。

## 核心方法

### 方法参照系

PoRSE 置于 LLM 驱动的自动化奖励设计框架下，与 Eureka 和 ROSKA 共享“LLM 生成奖励-RL 训练-反馈迭代”的基本流程。关键差异在于：Eureka 仅优化目标奖励，ROSKA 侧重策略继承，而 PoRSE 将探索奖励纳入 LLM 的生成与优化范围，并引入动态权重调整机制。

### 可供性状态空间与探索奖励

传统好奇心驱动探索基于全局状态访问计数，缺乏任务针对性。PoRSE 利用 LLM 将高维状态空间 $S$ 映射到低维离散可供性状态空间 $S_o$，其中每个维度量化当前状态与目标状态在特定行为可供性上的距离。探索奖励 $R_e$ 定义为：

$$ R_e = \lambda / \sqrt{\sum_{t=1}^{T} \mathbb{I}(s_{t,o,d} = s_{c,o,d})} $$

该公式通过离散化状态访问频率计算探索奖励，频繁访问的状态获得较低奖励，未探索状态获得较高奖励。设计动机在于：通过 LLM 解析任务描述自动生成映射函数 $M: S \to S_o$，使探索奖励紧密对齐任务目标，避免智能体在无关状态上浪费资源。

### 策略内改进接地过程（IPG）

目标奖励 $R_g$ 与探索奖励 $R_e$ 的平衡系数 $\beta$ 通常需人工调参且固定不变。PoRSE 引入 IPG 机制，利用 LLM 分析策略性能反馈 $V(\theta)$ 动态生成 $\beta$ 值集合，并通过消除-扩展过滤机制（LEF）优化奖励-探索组合。总奖励定义为：

$$ R_{total} = \beta R_e + (2 - \beta) R_g $$

该公式通过 $\beta$ 动态调整探索与利用的权重。设计动机在于：传统方法中 $\beta$ 固定导致策略在不同训练阶段无法适应环境变化，而 IPG 通过实时策略反馈引导 LLM 生成适配当前阶段的 $\beta$ 值，并结合策略融合机制继承先前策略知识，避免从头训练的计算开销。

## 实验评估

实验在 Bi-DexHands 和 Isaac Gym 环境中进行，覆盖 24 项机器人技能学习任务，包括灵巧操作和腿式运动。基线方法包括稀疏奖励、人工设计奖励、Eureka 和 ROSKA。PoRSE 在中等难度任务中 15/16 项取得最佳表现，在困难任务中首次解决 TwoCatch 和 BlockStack 等此前未解任务。

| 任务 | PoRSE MTS | Eureka MTS | ROSKA MTS | Human MTS |
| :--- | :--- | :--- | :--- | :--- |
| TwoCatch | 0.349 | 0.000 | 0.000 | 0.000 |
| BlockStack | 0.753 | 0.254 | 0.148 | 0.600 |
| PushBlock | 0.318 | 0.025 | 0.069 | 0.011 |
| DoorOpenInward | 0.250 | 0.000 | 0.000 | 0.000 |

消融实验显示，移除目标奖励 $R_g$ 或探索奖励 $R_e$ 均导致性能显著下降，其中移除 $R_e$ 在 TwoCatch 任务中性能从 0.349 降至 0.193，降幅 44.7%。移除策略融合机制 $\theta_{fusion}$ 在 BlockStack 任务中性能从 0.753 降至 0.603，降幅 20.0%。这表明目标奖励与探索奖励的协同优化及策略继承对复杂任务至关重要。

评估指标主要采用最大训练成功率（MTS），反映策略在训练过程中的最佳表现，但未报告部署时的泛化性能。实验使用 5 个随机种子，但未提供置信区间。代码未公开，超参数（如 $\lambda=0.01$、$\alpha=0.8$）固定，缺乏对 LLM 生成 AFS 质量的敏感性分析。

## 关联研究分析

从问题动机看，PoRSE 与 Eureka 的核心差异在于对探索维度的处理。Eureka 假设目标导向奖励足以引导策略优化，但在稀疏奖励任务中，智能体因缺乏中间状态反馈而停滞。PoRSE 通过 AFS 将探索奖励与任务目标绑定，解决了 Eureka 在高维稀疏环境中的局部最优问题。然而，PoRSE 的 AFS 依赖 LLM 对任务描述的解析能力，若 LLM 生成的映射函数存在偏差，探索奖励可能引导智能体偏离真实目标，这一风险在 Eureka 中因缺乏探索机制而不存在。

从方法设计看，PoRSE 与 ROSKA 在策略继承机制上存在差异。ROSKA 使用贝叶斯优化确定融合比例，计算成本高且收敛慢；PoRSE 采用 LLM 辅助的快速优化，通过消除-扩展过滤机制动态调整 $\beta$ 和 $\alpha$。这种设计提升了计算效率，但引入了对 LLM 实时反馈分析能力的依赖。若 LLM 对策略性能反馈 $V(\theta)$ 的解析不准确，可能生成次优的 $\beta$ 值，导致探索-利用平衡失调。ROSKA 的贝叶斯优化虽慢，但提供了更稳定的参数搜索保证，而 PoRSE 的快速优化在复杂任务中的鲁棒性尚未充分验证。

## 总结

PoRSE 解决了 LLM 生成奖励在稀疏奖励任务中因缺乏探索引导而陷入局部最优的矛盾，通过 LLM 构建任务相关的可供性状态空间并引入动态平衡机制，实现了目标奖励与探索奖励的协同优化。实验表明，PoRSE 在 TwoCatch 任务中达到 0.349 的 MTS，而 Eureka 和 ROSKA 均为 0.000，验证了其在高维稀疏环境中的有效性。然而，PoRSE 的性能高度依赖 LLM 生成 AFS 的准确性，且动态 $\beta$ 调整机制在部署时的稳定性未经验证。当 LLM 生成的 AFS 存在系统性偏差时，探索奖励是否会导致策略偏离真实目标，论文未给出回答。
