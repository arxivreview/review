# ICLR2026最新论文 ｜DUALMAP: ENABLING BOTH CACHE AFFINITY AND LOAD BALANCING FOR DISTRIBUTED LLM SERVING ｜DualMap：双映射调度打破缓存亲和与负载均衡的帕累托前沿

研究机构：华中科技大学

作者：Ying Yuan、Pengfei Zuo、Bo Wang 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_79834030)

> 分布式大语言模型（LLM）服务中，复用提示前缀的键值（KV）缓存能显著降低首Token延迟（TTFT），但将共享前缀的请求路由至同一节点以最大化缓存复用的“缓存亲和”策略，与将请求均匀分散至各节点以提升资源利用率的“负载均衡”策略在单一映射空间内存在根本冲突。现有调度器如Preble和Mooncake仅在部分请求上应用亲和路由，其余采用负载路由，无法同时优化两目标。DualMap通过两个独立哈希函数将每个请求映射至两个候选实例，并基于服务等级目标（SLO）动态选择，实现了缓存亲和与负载均衡的同步达成。该设计在真实工作负载上将有效请求容量提升2.25倍，但其对前缀热度分布的假设及弹性扩展时的缓存命中率衰减边界，仍需在更极端的动态场景下验证。

## 研究背景

多轮对话与智能体应用中，请求频繁共享系统提示或历史对话前缀。为消除重复预填充计算，推理系统采用上下文缓存，存储这些前缀对应的KV状态供后续请求复用。然而，在分布式集群中，调度器必须决定将请求发送至哪个计算实例。若仅依据前缀匹配路由（缓存亲和），热门前缀会导致特定实例过载，而冷前缀实例闲置；若仅依据当前负载路由（负载均衡），共享前缀的请求被分散至不同实例，KV缓存命中率骤降，引发大量重计算。

该冲突源于缓存亲和与负载均衡策略均被限制在单一映射空间内。缓存亲和依赖提示感知函数，将相同前缀请求绑定至固定节点；负载均衡依赖负载感知函数，将请求导向最空闲节点。Preble（Srivatsa et al., 2024）在前缀命中率超过50%时启用亲和路由，否则切换至负载路由；Mooncake（Qin et al., 2025）根据集群负载状态动态切换策略。这些方法本质上是分段应用两种映射，导致系统性能始终处于帕累托前沿的折中点，无法同时逼近缓存命中率与负载均衡的理论上限。DualMap的切入点在于，通过引入双独立哈希函数生成两个候选实例，将路由决策从“单点选择”转变为“双点候选+动态选择”，从而在结构上解耦了亲和性与均衡性的约束。

## 核心方法

### 双映射基础架构

DualMap将请求路由问题置于“Power of Two Choices (PoTC)”调度范式下。传统单选择（d=1）调度中，请求随机分配至一个实例，最大负载偏差随实例数n呈对数增长。PoTC原理指出，当每个请求随机选择两个候选实例并分配至负载较低者时，最大负载偏差收敛至$\log \log n$，实现指数级更优的均衡性。DualMap采用d=2，利用两个独立哈希函数$f_1$和$f_2$，以请求的部分前缀为键，将每个请求映射至两个候选实例$\{I_1, I_2\}$。这一设计确保共享前缀的请求大概率映射至相同的候选集，维持KV缓存局部性，同时通过随机性保证负载均匀分布。

### SLO感知路由与热点重平衡

SLO感知路由解决了双候选选择中亲和性与均衡性的二次冲突。其核心逻辑是：优先选择拥有KV缓存的实例以最小化重计算，仅当预期TTFT超过SLO阈值时，才切换至负载较低的实例。该策略通过动态阈值避免了Preble中频繁切换导致的缓存命中率波动。针对前缀热度偏斜导致的热点实例问题，DualMap引入热点感知重平衡机制。当某实例过载时，系统将其部分请求迁移至其双映射中的备用实例，且优先迁移那些备用实例负载低且缓存复用率高的请求。这一机制在不破坏整体缓存亲和性的前提下，实现了负载的局部再分配，避免了全局重映射的开销。

### 双哈希环弹性扩展

静态哈希映射在实例扩缩容时会破坏前缀与实例的绑定关系，导致缓存命中率骤降。DualMap采用双哈希环结构，请求与实例的分配仅依赖于它们在哈希环上的相对位置。当实例增加或移除时，仅影响哈希环上相邻的一小部分映射关系，而非全局重映射。这一设计确保了系统在动态扩展时的弹性，避免了因缓存失效引发的服务抖动。

$$
L_{max} \le \frac{m}{n} + \frac{2 \log \log n}{\log d}
$$

该公式量化了PoTC在d=2时的最大负载上界，表明负载偏差随n增长极慢，为DualMap的均衡性提供了理论保障。

## 实验评估

实验基于vLLM引擎，使用Qwen2.5-7B/14B模型，部署于8节点Ascend NPU集群，负载为Mooncake提供的Conversation与Tool&Agent真实Trace。基线包括Cache Affinity、Least Loaded、Min TTFT（Mooncake简化版）及Preble。DualMap在Tool&Agent负载下，有效请求容量（SLO达标率）较最佳基线提升125%，Goodput提升16.7%-48%；在Conversation负载下，有效请求容量提升40.6%-80%，Goodput提升14.3%-40%。

| 负载类型 | 模型 | 指标 | DualMap | 最佳基线 | 提升幅度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Tool&Agent | 7B | Goodput | - | - | +48% |
| Tool&Agent | 14B | Goodput | - | - | +16.7% |
| Conversation | 7B | Goodput | - | - | +40% |
| Conversation | 14B | Goodput | - | - | +14.3% |

消融实验显示，SLO感知路由较Min-TTFT策略降低P50/P90 TTFT 23.5%/18.5%；热点重平衡进一步降低P90 TTFT 11.3%。纯缓存亲和策略虽缓存命中率最高，但负载不均衡导致TTFT尾部延迟激增；纯负载均衡策略则因缓存命中率低而增加重计算开销。DualMap通过动态选择与局部迁移，在两者间取得了最优平衡。

评估边界方面，实验仅覆盖8实例集群，未测试更大规模（如64+实例）下的哈希环扩展性能；负载为静态Trace，未模拟突发流量或前缀热度剧烈变化场景；未对比Dynamo等成本感知调度器，可能低估了其在特定成本模型下的表现。代码已开源，但超参数（如SLO阈值、热点迁移比例）的敏感性分析缺失。

## 关联研究分析

从问题动机看，DualMap与Preble、Mooncake同属KV缓存调度路线，但解决了单映射空间下的帕累托限制。Preble依赖命中率阈值切换，导致路由决策离散化；DualMap通过双候选连续选择，实现了更平滑的性能过渡。差异根源在于，Preble假设前缀热度分布均匀，而DualMap通过PoTC原理显式处理了热度偏斜，这使其在Tool&Agent等智能体负载下优势更显著。

从方法设计看，DualMap与PagedAttention（Kwon et al., 2023）在层级上互补。PagedAttention解决块级内存管理，DualMap解决全局路由决策。然而，DualMap仅基于精确前缀匹配，未考虑语义等价查询。在RAG场景中，若查询存在语义变体，DualMap的缓存命中率可能低于GPTCache等语义缓存方案。这暴露了DualMap在动态上下文下的适用性边界：它优化了前缀共享场景的调度效率，但未解决语义匹配问题。

## 总结

DualMap针对分布式LLM服务中缓存亲和与负载均衡的冲突，通过双映射架构与SLO感知路由，在结构上解耦了两者约束。实验证明，其在真实负载下将有效请求容量提升2.25倍，显著优于单映射调度器。然而，其性能依赖于前缀热度分布的统计特性，且在实例频繁扩缩容时，双哈希环的缓存命中率衰减边界未充分量化。当集群规模扩展至数百节点且前缀热度呈现极端偏斜时，PoTC的$\log \log n$负载上界是否仍能维持SLO达标率，论文未给出回答。
