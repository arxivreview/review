【AGNOSTICS: LEARNING TO SYNTHESIZE CODE IN ANY PROGRAMMING LANGUAGE WITH A UNIVERSAL REINFORCEMENT LEARNING ENVIRONMENT ｜语言无关强化学习后训练

研究机构：美国东北大学

作者：Aleksander Boruch-Gruszecki、Yangtian Zi、Zixuan Wu 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_99287433)

> 大语言模型在Python等高资源语言上表现优异，但在Fortran、Julia等低资源语言上能力严重不足，根源在于预训练数据稀缺与后训练基础设施缺失。现有方法依赖每语言定制的数据集与测试框架，工程成本极高且难以扩展。本文提出Agnostics，通过构建基于输入输出行为的通用验证器，将代码正确性判断从语言特定逻辑解耦，实现任意编程语言的统一强化学习训练。该方法在五个低资源语言上显著提升了小参数模型性能，但受限于标准输入输出任务格式，无法覆盖复杂工程场景。

【AUTOCODEBENCH: LARGE LANGUAGE MODELS ARE AUTOMATIC CODE BENCHMARK GENERATORS ｜自动化多语言代码基准生成

作者：Changzhi Zhou、Ao Liu、Yuchi Deng 等 16 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_48976970)

> 代码生成评估面临静态基准饱和与多语言覆盖失衡的双重困境，人工标注难以兼顾规模、难度与语言多样性。现有动态基准依赖外部收集，无法保证题目与测试用例的严格对齐。本文提出基于LLM-沙盒交互的自动化流水线，通过反向生成范式与三阶段过滤，构建了覆盖20种语言、3920道题目的AutoCodeBench。该基准有效区分了SOTA模型在多语言场景下的能力差异，但其对低资源语言的“近似翻译”策略可能引入语义偏差，且仅依赖Pass@1指标未能覆盖非功能质量维度。

【CLARC: C/C++ BENCHMARK FOR ROBUST CODE SEARCH ｜C/C++ 代码检索鲁棒性基准

研究机构：美国南加州大学

作者：Kaicheng Wang、Liyan Huang、Weike Fang 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.04484)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_17069754)

> 代码检索模型在标准基准上表现优异，但这一高分往往源于对标识符名称等表面词汇特征的依赖，而非对代码深层语义的理解。现有基准多聚焦 Python 且缺乏对文本扰动的压力测试，导致无法区分模型的语义理解能力与词汇匹配能力。本文提出 CLARC，一个基于真实 C/C++ 仓库构建的基准，通过标识符匿名化和编译至低层语言来剥离表面特征，暴露模型鲁棒性缺陷。该工作揭示了当前 SOTA 检索模型在语义泛化上的脆弱性，但其结论受限于仅评估了少数支持 C/C++ 的嵌入模型，且未探索通过微调彻底解决该问题的路径。

【CRITIQUE-CODER: ENHANCING CODER MODELS BY CRITIQUE REINFORCEMENT LEARNING ｜批判强化学习

研究机构：加拿大滑铁卢大学、加拿大向量研究所

作者：Chi Ruan、Dongfu Jiang、Yubo Wang 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_10167755)

> 代码生成模型在标准强化学习（RL）训练中缺乏对错误解的反思机制，导致推理深度受限。现有RLVR范式仅奖励最终解的正确性，无法激励模型识别中间步骤的逻辑缺陷。本文提出CRL，通过奖励模型对“问题-解”对的二元判断准确性，显式引入批判机制。该范式在4B/8B小模型上显著提升了LiveCodeBench等基准的性能，但二元奖励的粒度是否足以捕捉复杂逻辑错误仍存疑。

【CROSSPL: SYSTEMATIC EVALUATION OF LARGE LANGUAGE MODELS FOR CROSS PROGRAMMING LANGUAGE INTEROPERATING CODE GENERATION ｜跨编程语言互操作代码生成评估

研究机构：浙江大学、澳大利亚新南威尔士大学

作者：Zhanhang Xiong、Dongxia Wang、Yuekang Li 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_42104021)

> 现有代码生成基准聚焦单语言函数级任务，无法衡量模型在真实多语言系统中处理进程间通信（IPC）与外部函数接口（FFI）的能力。本文通过挖掘19,169个真实GitHub仓库并设计156个有限状态机（FSM），构建了首个包含2,534个CPL互操作任务的基准。实验表明，当前SOTA模型在FFI任务上表现极差，揭示了单语言能力与跨语言互操作能力间的巨大鸿沟。该基准填补了CPL评估空白，但FSM对非标准协议变体的覆盖度存疑。

【EDIT-BENCH: EVALUATING LLM ABILITIES TO PER FORM REAL-WORLD INSTRUCTED CODE EDITS ｜指令式代码编辑基准

研究机构：美国卡内基梅隆大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_839682)

> 指令式代码编辑要求模型根据自然语言指令修改现有代码片段，但现有基准多依赖人工标注或竞赛题，无法反映真实IDE交互中的模糊指令与长上下文依赖。EDIT-Bench通过VSCode扩展收集500名开发者的真实编辑日志，构建了包含540个多语言、多上下文维度的测试集。该基准揭示了模型在整合高亮代码与光标位置时的性能波动，以及闭源与开源模型在真实编辑任务上的显著差距。其价值在于填补了真实交互模式评估的空白，但测试用例由人工构建，可能引入主观偏差，且仅覆盖Python与Javascript。

【EDITBENCH: EVALUATING LLM ABILITIES TO PERFORM REAL-WORLD INSTRUCTED CODE EDITS ｜真实场景指令式代码编辑基准

研究机构：美国卡内基梅隆大学

作者：Wayne Chi、Valerie Chen、Ryan Shar 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_58490788)

> 现有代码生成基准多依赖静态、人工编写的题目，无法反映开发者在IDE中通过自然语言指令修改局部代码的真实交互模式，且缺乏对高亮代码、光标位置等上下文信息的评估。本文通过开发VS Code插件收集近500名用户的真实编辑日志，构建了包含540道题目的EditBench，首次将指令、代码上下文、高亮区域和光标位置作为联合输入进行评测。该基准揭示了当前模型在真实编辑任务上的显著短板，但仅覆盖Python和JavaScript两种编程语言，且依赖人工构建的测试用例，其泛化边界尚存疑。

【GISTIFY! CODEBASE-LEVEL UNDERSTANDING VIA RUNTIME EXECUTION ｜代码库级执行流理解评估

研究机构：美国北卡罗来纳大学教堂山分校、微软研究院

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_38274923)

> 现有仓库级基准依赖GitHub Issue文本，且允许模型通过检索局部补丁绕过全局执行逻辑，导致无法区分模型是真正理解了代码库结构还是仅在进行模式匹配。GISTIFY任务通过要求模型生成一个最小化、自包含且能复现特定命令运行时行为的单文件，强制模型追踪完整的跨文件执行路径。该方法利用程序化验证而非LLM裁判，解决了动态基准构建成本高且易受污染的问题。尽管该方法在理论上填补了自动化代码库级评估的空白，但当前SOTA模型在长执行轨迹下的失败率依然极高，其评估结果是否足以证明深层语义理解仍存疑。

【HARDTESTGEN: A HIGH-QUALITY RL VERIFIER GENERATION PIPELINE FOR LLM ALGORITHMIC CODING ｜高质量RL验证器生成管道

研究机构：美国卡内基梅隆大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_19448995)

> 算法竞赛代码生成中的强化学习（RL）训练依赖结果验证器（Outcome Verifier）提供准确的奖励信号，但现有合成测试用例存在大量假阳性，导致模型学到错误策略。本文指出直接由大语言模型（LLM）生成测试输入难以保证有效性与覆盖度，提出HARDTESTGEN管道，通过LLM生成“生成器程序”而非直接生成输入，结合共识过滤机制合成高质量测试集HARDTESTS。该方法在竞赛编程任务上显著提升了验证精度，并实证了测试质量对RL及拒绝采样（Rejection Sampling）下游性能的决定性影响，但其依赖Oracle程序的前提限制了在无参考解场景下的泛化能力。

【HOW MANY CODE AND TEST CASES ARE ENOUGH? EVALUATING TEST CASES GENERATION FROM A BINARY-MATRIX PERSPECTIVE ｜从二进制矩阵视角评估测试用例生成

研究机构：哈尔滨工业大学、中南大学

作者：Xianzhen Luo、JinYang Huang、Wenzhen Zheng 等 8 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_77641761)

> 导读 测试用例生成（Test Case Generation, TCG）的质量直接决定代码评估的可靠性，但现有基准在评估TCG方法时面临计算成本高昂与分数膨胀的双重困境。主流方法依赖未过滤的错误代码集合，导致常见错误淹没关键故障，使得评估失去区分度。本文切入点在于将错误代码与测试用例的执行结果形式化为二进制矩阵，利用矩阵秩理论构建最小且最具区分度的诊断基。通过提出WrongSelect算法筛选错误代码，本文构建了TC-Bench基准，揭示了当前SOTA方法在复杂错误模式下的显著缺陷。该工作为TCG评估提供了防膨胀的理论框架，但其对非线性错误模式的覆盖能力仍存疑。

【ON CODE-INDUCED REASONING IN LLMS ｜代码诱导推理的因果机制解构

研究机构：美国卡内基梅隆大学

作者：Abdul Waheed、Zhen Wu、Carolyn Rose 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_79282749)

> 大语言模型在代码数据上训练后推理能力显著提升，但具体是代码的何种属性驱动了这一增益，现有研究仅停留在相关性观察层面，缺乏因果归因。本文通过构造平行自然语言与代码指令集，并施加规则与生成式受控扰动，解耦了代码的语法、结构与语义信号。实验表明，模型对结构扰动比语义扰动更敏感，且伪代码等抽象形式可替代具体代码实现等效推理增益。该框架填补了“为何有效”的解释空白，但其结论局限于8B以下小模型，且依赖LLM-as-Judge评估，大模型外推性与评估偏差仍是存疑点。

【RECODE-H: A Benchmark for Research Code Development with Interactive Human Feedback ｜科研代码生成的交互式反馈基准

研究机构：清华大学、加拿大麦吉尔大学

作者：Chunyu Miao、Henry Peng Zou、Yangning Li 等 31 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.06186)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.06186)

> 现有科研代码生成基准普遍采用一次性生成设定，忽略了真实科研工作中人类反馈对代码修正的关键作用。RECODE-H 通过引入五级结构化反馈层级，将“反馈粒度”作为可控变量，系统评估大语言模型在多轮交互中利用人类指导修正代码的能力。该基准包含102个源自真实论文与代码库的任务，并提出了ReCodeAgent框架以模拟专家反馈循环。实验表明，即使是最基础的诊断信号也能使模型通过率接近翻倍，但模型在语义对齐与领域知识填补上仍存在显著瓶颈，且反馈收益呈现明显的边际递减效应。

【SWINGARENA: ADVERSARIAL PROGRAMMING - ARENA FOR LONG CONTEXT GITHUB ISSUE SOLVING ｜对抗性持续集成评估框架

作者：Wendong XU、Jing Xiong、Chenyang Zhao 等 19 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_68781887)

> 现有代码生成基准多聚焦于静态快照下的功能正确性，难以捕捉真实软件工程中的迭代协作与动态审查机制，导致模型在复杂仓库级任务上的能力被高估。SWINGARENA 通过构建提交者与审查者的双代理对抗环境，将评估嵌入真实的持续集成（CI）流水线，以动态生成的测试用例和全链路质量门控替代固定测试集。该框架结合多语言检索增强代码生成（RACG）模块，在 400 个真实 GitHub Issue 上验证了不同模型在补丁激进性与 CI 稳定性间的权衡。其价值在于揭示了静态基准无法量化的协作鲁棒性，但受限于基线模型时效性与检索瓶颈，结论的普适性存疑。

【VeriEquivBench: An Equivalence Score for Ground-Truth-Free Evaluation of Formally Verifiable Code ｜形式化代码等价性评估基准

研究机构：华中科技大学、加拿大阿尔伯塔大学

作者：Lingfei Zeng、Fengdi Che、Xuhan Huang 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.06296)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.06296)

> 形式化验证旨在通过数学证明确保代码与用户意图的严格对齐，但现有基准依赖人工标注的“真值”规格，导致数据规模受限且标注错误率高。本文提出一种无需真值规格的双向蕴含验证指标，并构建了包含2389个复杂算法问题的基准。该工作通过Dafny验证器自动化评估代码与规格的逻辑等价性，揭示了当前大语言模型在复杂形式化推理上的严重缺陷，但其评估结果受限于Dafny语法门槛与多阶段流水线的依赖。
