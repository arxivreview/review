# ICLR2026最新论文 ｜HeurekaBench: A Benchmarking Framework for AI Co-scientist ｜基于代码验证的开放式科学代理基准

研究机构：瑞士洛桑联邦理工学院、瑞士苏黎世联邦理工学院

作者：Siba Smarak Panigrahi、Jovana Videnović、Maria Brbić

论文原文见 [arXiv](https://arxiv.org/abs/2601.01678)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.01678)

> 现有科学代理评估多聚焦于单步计算或事实检索，无法衡量代理在真实科研中自主规划、探索数据并生成新洞察的能力。本文指出，缺乏基于真实实验数据与代码执行验证的开放式问题基准，导致评估结果无法反映代理作为“共同科学家”的实际效用。HEUREKABENCH 通过构建“洞察提取-代码验证-问题生成”的半自动流水线，将已发表的科研成果转化为可复现的开放式研究问题，并引入原子事实分解评估机制。该框架在单细胞生物学实例化后，揭示了当前代理在开放式推理上的显著短板，但其评估依赖 LLM 裁判的稳定性仍存疑。

## 研究背景

当 LLM 代理被赋予分析实验数据集的任务时，其核心挑战在于区分“基于数据的推理”与“基于预训练知识的记忆”。若代理仅凭参数中的事实性知识回答，而非通过执行代码探索数据，其输出便不具备科学发现的效力。这一区分要求评估基准必须包含真实的实验数据集，并强制代理通过多步工作流（如选择分析工具、执行代码、解读结果）来生成答案，而非直接匹配固定选项。

当前针对科学代理的评估基准存在结构性缺陷。多数基准（如 BixBench、SciCode）测试的是单步计算或指令遵循能力，例如“计算 Benjamini-Hochberg 校正后的显著 miRNA 数量”，这类任务将科研流程拆解为孤立的计算步骤，忽略了共同科学家需要自主规划子任务、整合证据并得出开放式结论的核心能力。最接近的 BaisBench 虽尝试生成研究问题，但仅依赖单一 LLM 从文献中提问，缺乏对问题可解性与答案正确性的验证，导致大量无效问题。HEUREKABENCH 的切入点在于将基准构建过程本身视为一个科学验证过程：通过执行代码复现已发表结果，确保每一个基准问题都建立在可复现的科学事实之上，从而消除 LLM 幻觉对评估基准的污染。

## 核心方法

### 任务形式化与参照系

HEUREKABENCH 将共同科学家任务形式化为三元组 $(D, Q, A)$，其中 $D$ 为实验数据集，$Q$ 为开放式研究问题，$A$ 为基于科学文献验证的基准答案。与传统的多步问答任务不同，该框架要求 $Q$ 不能通过单一计算步骤解决，必须涉及工作流级别的推理，且 $A$ 必须通过代码执行结果与文献报道的一致性进行验证。这一设计将评估重心从“任务完成率”转移至“证据链的完整性与数据驱动性”。

### 基于代码执行的洞察验证流水线

基准构建的核心在于从已发表文献中提取“高置信度”的科学洞察。流水线包含四个模块：InsightExtractor 从论文中提取候选洞察，CodeDescriber 将代码脚本转化为自然语言描述，CodeMatcher 将洞察与代码描述匹配，CodeGenerator 组合脚本形成多步工作流。关键创新在于引入人工验证环节：运行生成的代码，确保输出结果（如图表、统计量）与论文中记录的基准答案一致。只有复现成功的洞察才进入基准池。这一机制直接解决了 BaisBench 等基准中“问题不可解”或“答案错误”的可靠性问题，确保基准本身具备科学严谨性。

### 原子事实分解评估机制

针对开放式问题（OEQs）的评估，HEUREKABENCH 提出了一种基于原子事实分解的评分方案。传统评估依赖表面匹配或整体相似度，无法区分代理是“碰巧猜对”还是“基于数据推理正确”。该方案指示 LLM 裁判（GPT-4o）将代理回答与基准答案均分解为原子事实（如条件、趋势、结论），然后评估事实的重叠度。评分公式可表示为：

$$
Score = f(\text{Complete Facts}, \text{Partial Facts}, \text{Missing Facts}, \text{Contradictions})
$$

其中，只有当所有基准事实存在且无矛盾时，代理才获得最高分；额外的非冲突发现不扣分。这一设计强制代理必须提供数据支持的结论，而非仅复述文献中的已知事实，从而有效抑制了基于预训练知识的“记忆型”回答。

## 实验评估

实验在 sc-HEUREKABENCH-Lite 子集上进行，包含 22 个 OEQs 和 18 个 MCQs，以规避大数据集导致的代理崩溃问题。对比基线包括 Biomni、CellVoyager 和 BixBench-Agent，三者均使用 Claude-4-Sonnet 作为底层 LLM。

| Agent | OEQs Correctness [1-5] | MCQs Accuracy [%] | MCQs Recall [%] | MCQs Precision [%] |
| :--- | :--- | :--- | :--- | :--- |
| BixBench-Agent | **2.34** | 44.44 | 80.56 | 62.96 |
| CellVoyager | 2.03 | 27.78 | 38.89 | 32.41 |
| Biomni | 2.31 | **50.00** | **88.24** | **76.96** |

Biomni 在 MCQs 上表现最佳，准确率 50.00%，但在 OEQs 上所有代理得分均低于 2.5/5，表明当前代理在开放式科学推理上存在显著瓶颈。BixBench-Agent 在 OEQs 上得分最高（2.34），但其 MCQs 表现低于 Biomni，暗示其可能在开放式任务中依赖了不同的推理路径或存在评估偏差。

| Model (Open) | OEQs Correctness [1-5] | MCQs Accuracy [%] | MCQs Recall [%] | MCQs Precision [%] |
| :--- | :--- | :--- | :--- | :--- |
| MedGemma-27B | 1.53±0.02 | 20.41 | 41.84 | 37.59 |
| Qwen3-235B-THINKING | 1.85±0.03 | **46.00** | 65.00 | 57.33 |
| GPT-4o | 1.68±0.05 | 18.00 | 59.00 | 44.83 |
| Claude-4-Sonnet | **2.58**±0.05 | 44.00 | **85.00** | **66.33** |

Planner 消融实验显示，闭源模型（Claude-4-Sonnet）在 OEQs 上显著优于开源模型（最高 2.58 vs 1.85），但引入多轮推理（Qwen3-235B-THINKING）可缩小差距。Critic 模块的引入对开源模型有显著增益：GPT-OSS-120B 在加入 End-critic 后，低分问题（Low）的平均得分从 1.32 提升至 1.91，整体平均分从 2.04 提升至 2.49，接近闭源模型水平。然而，Plan-critic 在开头介入反而导致性能下降，表明反馈时机对推理轨迹的稳定性至关重要。

评估协议依赖 GPT-4o 作为 LLM 裁判，其与 Claude-4.5-Sonnet 和 Gemini-2.5-Pro 的评分相关性分别为 0.84 和 0.79，Kappa 系数分别为 0.81 和 0.71，表明不同 LLM 裁判间存在较高一致性，但绝对评分的客观性仍受裁判模型偏见影响。代码已开源，但基准构建依赖人工验证，限制了其可扩展性。

## 关联研究分析

从问题动机看，HEUREKABENCH 与 BaisBench 的核心差异在于对“基准可靠性”的处理。BaisBench 依赖 LLM 从文献中直接生成问题，缺乏对问题可解性的验证，导致部分问题无法通过数据探索得到正确回答。HEUREKABENCH 通过代码执行验证过滤不可复现的洞察，确保每个问题都有经过验证的基准答案。这一差异源于任务特性：科学发现要求结论必须基于数据，而非文献记忆，因此基准构建本身必须遵循科学验证流程。

从方法设计看，HEUREKABENCH 与 Kosmos 等数据驱动发现系统形成互补。Kosmos 侧重通过世界模型和文献搜索实现自主发现，而 HEUREKABENCH 侧重评估代理在已知科学事实下的推理能力。HEUREKABENCH 的原子事实分解评估机制与 FIRE-Bench 的“洞察重发现”评估有相似之处，但前者更强调开放式回答的结构化验证，后者更侧重于隐藏关键细节后的推理能力。HEUREKABENCH 未探索代理在完全未知数据上的发现能力，其评估边界局限于已发表文献中的已知事实，这限制了其对“真正”科学发现能力的衡量。

## 总结

HEUREKABENCH 旨在解决科学代理评估中“开放式推理”与“基准可靠性”的双重缺失。通过引入代码执行验证的洞察提取流水线和原子事实分解评估机制，该框架将基准构建过程本身转化为一个科学验证过程，确保评估问题具备数据驱动性和可复现性。实验表明，当前最强代理在开放式问题上得分仅约 2.5/5，且闭源模型显著优于开源模型，但引入 Critic 模块可缩小差距。该框架的边界在于其评估依赖于已发表文献中的已知事实，且 LLM 裁判的稳定性仍受模型偏见影响。当代理面对完全未知、无文献参考的数据集时，其开放式推理能力是否仍能保持，HEUREKABENCH 未提供答案。
