# ICLR2026最新论文 ｜PROPERSIM: DEVELOPING PROACTIVE AND PERSONALIZED AI ASSISTANTS THROUGH USER-ASSISTANT SIMULATION ｜主动个性化助手模拟框架

研究机构：韩国科学技术院、韩国首尔大学

作者：Jiho Kim、Junseong Choi、Woosog Chay 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.21730)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_22959852)

> 现有 AI 助手研究将“主动性”与“个性化”割裂，导致建议要么时机不当，要么内容错位。ProPerSim 通过构建双智能体模拟环境，将两者统一为基于时间步的干预决策问题。该方法利用检索增强生成与直接偏好优化，让助手在模拟中实时学习用户偏好。其价值在于验证了联合优化的可行性，但依赖 LLM 模拟的评估真实性仍存疑。

## 研究背景

当助手试图在用户未发起请求时提供建议，它面临一个双重约束：既要判断“何时”介入（主动性），又要决定“说什么”（个性化）。若仅具备主动性，助手可能向素食者推荐牛排；若仅具备个性化，助手则需等待用户提问，丧失了主动服务的意义。这种割裂源于早期研究将两者视为独立任务：主动性研究关注事件触发的响应，个性化研究关注静态画像的匹配，缺乏在时间维度上联合优化的机制。

该领域的核心瓶颈在于缺乏能够同时评估“时机”与“内容”的动态基准。现有方法如 Proactive Agent（Lu et al., 2024）仅处理用户触发的事件，忽略了用户在不同时间点对干预频率和内容的差异化需求。ProPerSim 的切入点是将助手行为建模为离散时间步上的序列决策问题，通过模拟用户代理的实时反馈，构建了一个闭环训练环境，使助手能够同时学习干预时机与内容偏好。

## 核心方法

### 时间步决策框架

本文问题区别于传统单次生成任务的关键在于引入了时间离散化。助手策略 $A_\theta$ 在每个时间步 $t \in \{T, 2T, 3T, \dots\}$ 基于当前用户动作 $A_t$ 和内部状态 $S_t^{(a)}$ 生成推荐 $R_t$，其中 $R_t$ 可以是具体建议或“无推荐”。

$$ R_t = A_\theta(A_t, S_t^{(a)}) $$

该公式表明助手的输出不仅取决于用户当前行为，还取决于其累积的内部状态，从而支持跨时间步的上下文感知。

### 内部状态与记忆检索

内部状态 $S_t^{(a)}$ 由两部分构成：当日交互的结构化摘要与相似历史交互的检索结果。近期交互（过去 10 分钟）保留细节，早期交互被压缩为 1 小时和 4 小时块。同时，助手通过 OpenAI embeddings 检索最相似的 5 个历史 $(A_t, R_t)$ 对，以提供上下文锚点。

$$ S_t^{(a)} = \text{Summary}(H_{recent}) \cup \text{Retrieval}(A_t, H_{past}) $$

这一设计解决了长程依赖导致的上下文窗口溢出问题，通过分层压缩与检索结合，使助手在有限算力下维持对长期偏好的记忆。

### 基于 DPO 的偏好对齐

助手采用直接偏好优化（DPO）进行每日离线训练。对于每个用户动作，助手生成 $n$ 个候选推荐，用户代理评分后形成偏好对。训练目标为最大化偏好响应的似然：

$$ \mathcal{L}_{DPO} = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)} \right) \right] $$

该损失函数通过对比高分与低分响应，引导模型学习符合用户特定画像（如大五人格）的推荐风格，而非仅优化通用满意度。

## 实验评估

实验在 ProPerSim 模拟环境中进行，包含 32 个基于大五人格生成的用户画像。基线包括无记忆（No Memory）、仅动作-推荐历史（AR Memory）及含奖励信号的历史（ARS Memory）。ProPerAssistant 在 Day 1 的平均得分为 2.2，Day 14 稳定在 3.3，成功干预率从 51.06% 提升至 71.51%。

| 方法 | Day 1 平均分 | Day 14 平均分 | 成功干预率 (Day 14) |
| :--- | :--- | :--- | :--- |
| ProPerAssistant | 2.2 | 3.3 | 71.51% |
| ARS Memory | - | - | - |
| AR Memory | - | - | - |
| No Memory | - | - | - |

注：表格中仅 ProPerAssistant 的具体数值在正文中明确给出，基线具体分数未在正文文本中列出，故留空。

消融分析显示，ARS Memory 优于 AR Memory，表明显式奖励信号比单纯的历史记录更能指导偏好学习。而 AR Memory 与 No Memory 差异微小，说明缺乏反馈的历史数据对个性化贡献有限。ProPerAssistant 的显著优势源于其每日 DPO 训练机制，将用户评分转化为可优化的训练信号，而非仅作为上下文提示。

评估边界方面，ProPerSim 依赖 Gemini 2.0 Flash 作为 LLM-as-a-judge，其评分合理性经人工评估确认率为 90.54%，但 LLM 评估者可能存在系统性偏差。代码已开源，但单 persona 模拟耗时约 10 天（A100 GPU），API 成本约 $30，限制了大规模扩展性。

## 关联研究分析

从问题动机看，ProPerSim 与 Proactive Agent（Lu et al., 2024）的核心差异在于触发机制。后者基于用户触发事件，前者基于固定时间步，这使得 ProPerSim 能捕捉用户“无动作”时的潜在需求，但也引入了“何时不干预”的决策复杂度。这一差异源于任务定义：Proactive Agent 假设用户意图明确，而 ProPerSim 假设用户意图隐式且动态。

从方法设计看，ProPerSim 与 Generative Agents（Park et al., 2023）共享记忆架构，但后者关注单智能体社会模拟，前者引入双智能体交互闭环。ProPerSim 的 DPO 训练机制借鉴了 RLHF 思想，但将其应用于模拟环境中的实时反馈，而非静态数据集。这种设计使得助手能够适应模拟用户的动态变化，但同时也依赖于模拟用户行为的真实性，若模拟行为偏离真实人类，训练信号将产生偏差。

## 总结

ProPerSim 解决了主动性与个性化割裂的问题，通过时间步决策框架将两者统一为序列优化任务。其核心贡献在于构建了双智能体模拟环境，利用 DPO 实现实时偏好对齐，使助手得分从 2.2 提升至 3.3。然而，该方法的边界在于依赖 LLM 模拟的用户行为，其评估真实性受限于模拟环境的保真度。当模拟用户的偏好分布与真实人类存在系统性偏差时，训练出的助手策略是否仍能泛化到真实场景，论文未给出回答。
