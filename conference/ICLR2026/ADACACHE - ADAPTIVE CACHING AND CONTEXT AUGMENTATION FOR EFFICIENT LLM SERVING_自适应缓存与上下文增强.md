# ICLR2026最新论文 ｜ADACACHE: ADAPTIVE CACHING AND CONTEXT AUGMENTATION FOR EFFICIENT LLM SERVING ｜自适应缓存与上下文增强

研究机构：新加坡南洋理工大学、阿里巴巴集团

作者：Zihao Zeng、Siyi Li、Xinyu Yan 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_98742063)

> 检索增强生成（RAG）在提升大语言模型（LLM）事实准确性的同时，因注入大量外部文本导致预填充阶段计算开销激增，现有缓存方案要么依赖精确前缀匹配导致命中率低，要么采用均匀重计算忽略注意力分布差异。本文切入点在于同时解决跨查询的上下文重叠冗余与单查询内的上下文过度分配问题。通过构建基于注意力模式的分层缓存机制与置信度引导的自适应上下文扩展策略，AdaCache 实现了在保持生成质量前提下的延迟优化。其价值在于打破了静态检索与均匀重算的固有假设，但在多跳推理任务中的精度保持能力缺乏量化验证，且多次前向传播的累积开销在极端长上下文场景下的表现尚存疑。

## 研究背景

RAG 系统通过检索外部知识库丰富用户查询，但检索文本块的注入使输入序列长度从通常不足 200 tokens 扩展至 2,000 tokens 以上，导致计算与内存开销增加超过 10 倍。这种膨胀直接恶化了首 Token 延迟（Time-To-First-Token, TTFT），成为制约系统吞吐量的核心瓶颈。为缓解此问题，键值缓存（Key-Value Cache, KV Cache）技术被引入以复用已计算的注意力状态，但其有效性高度依赖于输入序列的结构特征。

当前主流 RAG 缓存方案存在两类根本性低效。第一类是跨查询的上下文重叠，外部知识库中少数高频文本块被多次查询重复检索，形成幂律分布，导致相同上下文被反复计算。第二类是单查询内的上下文过度分配，静态 Top-k 检索策略无视查询复杂度差异，对简单查询也注入大量无关文本，不仅浪费算力还可能引入噪声降低准确率。现有方法如 Prefix Caching 依赖精确序列匹配，在长上下文或动态位置下命中率骤降；CacheBlend 虽通过独立块缓存与选择性重计算恢复了跨块注意力，但其对所有块应用均匀的重计算比例，未能利用不同块间注意力模式的异质性。

本文针对上述局限，提出 AdaCache 框架。该框架不再假设静态检索深度与均匀重算比例，而是通过剖析层间注意力分布构建分层缓存变体，并引入轻量级置信度评估动态决定每个查询所需的最小上下文长度，从而在计算效率与生成质量间实现双重优化。

## 核心方法

### 方法参照系

本文问题属于 RAG 场景下的 KV 缓存加速路线。标准流程假设静态 Top-k 检索，并通过精确前缀匹配或独立块缓存复用 KV 状态，辅以均匀比例的选择性重计算以恢复跨块依赖。本文的关键差异在于：将缓存复用策略与检索深度决策解耦，前者基于注意力稀疏性进行差异化重算，后者基于模型输出置信度进行动态扩展。

### 基于注意力模式的层级缓存与差异化重算

传统独立块缓存忽略跨块注意力导致精度损失，而 CacheBlend 的均匀重算比例未能反映不同块在注意力矩阵中的重要性差异。本文首先分析 Qwen3-8B 模型的层间注意力分布，发现浅层（1-18 层）呈现局部化模式，深层（19-36 层）出现注意力汇聚现象，即特定“汇聚块”捕获后续块的大部分注意力。基于此，本文构建三级缓存层级：硬前缀缓存要求精确匹配，直接复用无重算；软前缀缓存仅需匹配有效前缀（汇聚块或前驱块），以较低比例 $\alpha$ 重算；独立缓存作为兜底，以较高比例 $\beta$ 重算。重算候选 Token 通过首层跨块注意力比例识别，并利用层间一致性假设推广至所有层。重算比例 $\rho$ 根据缓存匹配状态动态调整：

$$
\rho = \begin{cases}
0 & \text{if Hard Prefix Match} \\
\alpha & \text{if Soft Prefix Match} \\
\beta & \text{if Independent Cache}
\end{cases}
$$

该机制通过仅重算高偏差 Token 恢复跨块依赖，避免了均匀重算在简单块上的冗余计算，同时通过层级匹配最大化缓存命中率。

### 置信度引导的自适应上下文扩展

静态 Top-k 检索对简单查询过度分配上下文，导致算力浪费与潜在精度下降。本文引入自适应上下文增强（Adaptive Context Augmentation, ACA）模块，摒弃一次性拼接所有检索块的做法，改为增量式扩展。每次仅添加一个文本块，并通过复合置信度指标评估当前上下文是否足以生成准确答案。置信度 $conf$ 由最后几层的平均 KL 散度与输出熵加权计算：

$$
conf = \lambda \cdot KL_{[l]}(O_{1..l-1}, O_l) + (1 - \lambda) \cdot H_{[l]}(O_l)
$$

当 $conf$ 超过阈值 $\tau$ 时停止扩展并执行解码。该设计将检索深度从固定值 $k$ 转化为查询自适应变量，仅处理对答案有贡献的文本块，从源头消除了上下文过度分配带来的计算冗余。

## 实验评估

实验在配备 NVIDIA RTX 6000 Ada GPU 的服务器上，使用 Llama-3-8B-Instruct、Qwen3-4B 和 Qwen3-8B 模型，在 MMLU、TriviaQA 等数据集上评估。基线覆盖 Full Recomputation、Prefix Caching 和 CacheBlend，但未包含 GPTCache 等语义响应缓存方法，也未对比 PagedAttention 等底层调度优化，限制了跨路线方法的全面比较。

| 方法 | 对比基线 | 平均 TTFT 加速比 | 最大 TTFT 加速比 |
| :--- | :--- | :--- | :--- |
| AdaCache | Full Recomputation | 3.12x | 6.02x |
| AdaCache | Prefix Caching | 2.69x | 5.0x |
| AdaCache | CacheBlend | 1.32x | 2.34x |

消融实验显示，ACA 模块与不同缓存机制兼容，为 Prefix Caching 和 CacheBlend 分别带来 1.65x 和 1.22x 的平均加速。完整 AdaCache 系统相比 ACA 增强的基线，在 MMLU 和 TriviaQA 上分别实现 1.95x 和 1.62x 的额外加速，而在 MMLU-Pro 和 SuperGPQA 上仅为 1.25x 和 1.14x。这一差异表明，ACA 的收益与数据集的上下文需求分布强相关：头部集中、尾部稀疏的数据集（如 MMLU）获益更大，而需要更深推理的数据集（如 SuperGPQA）中，动态截断可能限制了上下文充分性，导致加速比收敛。

评估指标仅包含 Exact Match 和 TTFT，缺乏对多跳推理任务（如 HotpotQA）生成质量的细粒度量化（如 ROUGE-L），无法直接验证 ACA 在复杂推理中是否因截断上下文导致精度损失。论文未提供代码仓库，且未报告置信区间，多次前向传播的累积延迟在极端长上下文下的稳定性缺乏数据支撑。

## 关联研究分析

从方法设计看，AdaCache 与 CacheBlend 的核心差异在于重算策略的粒度。CacheBlend 假设所有块具有同等的跨块注意力重要性，应用统一重算比例；而 AdaCache 基于层间注意力稀疏性，识别出“汇聚块”与“前驱块”作为有效前缀，仅对高偏差 Token 进行重算。这一改进源于对 Transformer 注意力机制深层结构的洞察，而非简单的参数调优。根源在于 RAG 上下文中文本块的功能异质性：部分块承载核心事实，部分块仅为背景填充，均匀重算无法区分这种功能差异，导致在简单块上浪费算力。

从问题动机看，AdaCache 与 FusionRAG 在 TriviaQA 上均实现了 1.4x-5.0x 的 TTFT 降低，但路径截然不同。FusionRAG 侧重离线预处理，通过相似性引导的预交叉注意力增强文档块间关联，属于静态优化；AdaCache 侧重在线自适应，通过置信度动态决定检索深度，属于动态优化。FusionRAG 的收益依赖于离线计算的充分性，而 AdaCache 的收益依赖于在线置信度评估的准确性。在查询模式高度可预测的场景下，FusionRAG 可能更高效；而在查询复杂度波动剧烈的场景下，AdaCache 的动态调整能力更具优势。两者在单跳任务上性能持平，暗示在简单查询中，静态优化与动态优化的收益上限趋同。

## 总结

AdaCache 旨在解决 RAG 系统中跨查询冗余计算与单查询上下文过度分配的双重矛盾。其切入点在于利用注意力分布的异质性与模型输出置信度的动态性，分别优化缓存复用策略与检索深度决策。通过构建层级缓存与差异化重算机制，结合置信度引导的增量上下文扩展，AdaCache 在 MMLU 和 TriviaQA 上实现了 1.32x-2.34x 的 TTFT 加速，同时保持生成质量。其边界在于，实验仅覆盖单跳与通用知识任务，缺乏多跳推理任务中精度保持的量化证据，且 ACA 的多次前向传播在长上下文场景下的累积开销未得到充分评估。当查询复杂度分布从头部集中转向长尾分布时，自适应截断策略是否会导致关键上下文缺失，进而影响多跳推理的准确性，论文未给出回答。
