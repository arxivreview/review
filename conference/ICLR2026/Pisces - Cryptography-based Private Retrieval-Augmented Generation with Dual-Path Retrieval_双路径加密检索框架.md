# ICLR2026最新论文 ｜Pisces: Cryptography-based Private Retrieval-Augmented Generation with Dual-Path Retrieval ｜双路径加密检索框架

作者：Xiaojian Liang、Lushan Song、Shishuai Du 等 12 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_58752589)

> 检索增强生成（RAG）在医疗等敏感场景面临查询与知识库双向隐私泄露风险，现有差分隐私（DP）方案因噪声干扰无法支持词汇检索，导致检索精度受损。Pisces 提出基于安全多方计算（MPC）的加密框架，通过粗筛与多实例协议实现语义与词汇双路径隐私检索。该框架在精度上接近明文基线，但仅验证了半诚实模型下的性能，未评估恶意攻击下的鲁棒性。

## 研究背景

RAG 系统通过外部知识库缓解大语言模型（LLM）的幻觉，但引入了双向隐私风险：用户查询可能暴露个人病史，知识库文档可能泄露患者临床笔记。这种泄露违反了 GDPR 等法规，要求检索过程实现“互惠隐私”，即服务器无法推断用户信息，用户无法获取知识库内容。传统 DP 方案通过向嵌入向量注入噪声保护隐私，但噪声破坏了精确词匹配，使得依赖词频的 BM25 词汇检索失效，仅支持语义检索，限制了检索精度。

RAG 隐私保护研究长期聚焦于生成阶段，检索阶段的隐私保护相对薄弱。现有工作如 RemoteRAG 和 Yao & Li (2025) 主要采用 DP 技术，但均局限于单一语义路径，无法兼顾词汇检索的精确性。Pisces 的切入点在于利用加密技术替代 DP，因为加密不改变原始数据，能同时支持语义相似度计算与词汇精确匹配。然而，直接应用加密技术面临两大效率瓶颈：大规模知识库的语义相似度计算开销巨大，以及词汇检索中重复调用标签私有集合交集（Labeled PSI）导致的通信延迟。

## 核心方法

### 加密检索参照系

Pisces 属于加密检索路线，与 DP 路线的核心差异在于数据扰动方式。DP 通过不可逆噪声保护隐私，导致精确匹配失效；加密技术通过同态或秘密共享保持数据原始性，支持双路径检索。本文问题与通用 MPC 流程的关键差异在于需同时优化语义（高维向量）与词汇（离散词频）两条路径的效率。

### 粗筛语义检索协议

针对语义检索中全库计算余弦相似度的开销问题，Pisces 引入粗筛策略。设计动机是避免在加密环境下对全库进行高成本向量运算。首先，双方使用 SimHash 将嵌入向量转化为 $L$ 位二进制向量 $\mathbf{v}_i^{[b]}$ 和 $\mathbf{q}^{[b]}$，将余弦相似度近似为汉明距离。随后，调用无感知过滤器协议 $\Pi_{\text{Oblivious Filter}}$，基于汉明空间私有地筛选出候选集 $D'$，大幅缩小搜索空间。最后，仅对候选集执行基于秘密共享的 MPC 余弦相似度计算。该设计将计算复杂度从 $O(N)$ 降至 $O(|D'|)$，其中 $|D'| \ll N$。

### 多实例词汇检索协议

针对词汇检索中 BM25 评分需多次调用 Labeled PSI 获取词频的问题，Pisces 设计多实例 Labeled PSI 协议 $\Pi_{\text{MultLPSI}}$。设计动机是消除重复调用带来的通信开销。该协议基于无感知伪随机函数（OPRF）和无感知键值存储（OKVS），在单次执行中获取所有查询词在每块文档中的词频 $tf_{i,l}$。随后，双方利用 MPC 联合计算 BM25 分数：

$$
\text{BM25}(q, d_i) = \sum_{j=1}^{n} \frac{(k_1 + 1) tf_{i,j}}{tf_{i,j} + k_1 (1 - b + b \frac{|d_i|}{\text{avgdl}})} \cdot \log \frac{N - df_j + 0.5}{df_j + 0.5}
$$

其中 $df_j$ 为文档频率，由词频聚合得出。单次执行获取所有词频避免了 $n$ 次独立 PSI 调用，显著降低了通信轮次。

## 实验评估

实验在 ClapNQ、SQuAD 和 HotpotQA 数据集上进行，对比明文基线、DP 方法及 LSE 协议。Pisces 在 HotpotQA 上语义 Top-5 精度为 79.90%，词汇 Top-5 精度为 90.06%，整体精度损失在 1.87% 以内。

| 数据集 | 路径 | Top-5 精度 | Top-10 精度 |
| :--- | :--- | :--- | :--- |
| HotpotQA | 语义 | 79.90% | 79.80% |
| HotpotQA | 词汇 | 90.06% | 89.48% |
| SQuAD | 语义 | 78.02% | 75.96% |
| SQuAD | 词汇 | 97.56% | 97.32% |

粗筛策略在大规模数据集上节省 41.21% 检索时间，减少 68.77% 上传/下载开销；多实例 LPSI 比 LSE 快 496.03 倍，上传开销降低 70733 倍。

| 策略 | 时间 (s) | 上传 (MB) | 下载 (MB) |
| :--- | :--- | :--- | :--- |
| Fine-Only (HotpotQA) | 34.19 | 1008.39 | 4610.26 |
| Coarse-to-Fine (HotpotQA) | 20.10 | 324.90 | 1439.70 |
| LSE (HotpotQA) | 1051.98 | 161.61 | 382.26 |
| MultLPSI (HotpotQA) | 2.35 | 0.0006 | 79.82 |

评估边界方面，实验仅在 Apple M4 Pro 单机上运行，未评估多服务器分布式场景下的通信延迟。指标仅关注精度与效率，未报告隐私预算消耗或安全证明的严格性。代码已开源，但超参数配置未详细披露。

## 关联研究分析

从问题动机看，Pisces 与 Private-RAG 形成路线对立。Private-RAG 采用 DP 解决隐私预算线性增长问题，但牺牲了词汇检索能力；Pisces 采用加密技术保留数据原始性，支持双路径，但面临更高的计算开销。这种差异源于对“隐私-效用”权衡的不同取舍：DP 路线追求低延迟与易集成，加密路线追求强隐私保证与检索完整性。Pisces 的效率优化（粗筛与多实例协议）正是为了弥合加密路线在实用性上的短板。

从方法设计看，Pisces 与 p2RAG 同属加密检索，但 p2RAG 仅支持语义检索，Pisces 扩展至双路径。Pisces 的无感知过滤器利用 SimHash 近似，引入了精度损失（语义路径精度低于词汇路径），这是为了换取效率的必要妥协。p2RAG 未涉及词汇检索，因此无法直接对比双路径下的精度-效率权衡。Pisces 的设计表明，在加密环境下，词汇检索的精度保持优于语义检索，这可能暗示在特定领域（如医疗术语匹配）中，词汇路径的隐私保护更具价值。

## 总结

Pisces 旨在解决 RAG 检索阶段的双向隐私泄露与检索精度损失矛盾。现有 DP 方案因噪声干扰无法支持词汇检索，Pisces 利用加密技术保留数据原始性，通过粗筛与多实例协议优化效率。实验证明其在 HotpotQA 上精度损失仅 1.87%，效率提升显著。然而，实验仅在半诚实模型下验证，未评估恶意攻击者（如投毒或提取攻击）下的鲁棒性。当攻击者试图通过查询频率推断知识库结构时，加密检索的通信模式是否仍会泄露元数据，论文未给出回答。
