# ICLR2026最新论文 ｜ONCE-MORE: CONTINUOUS SELF-CORRECTION FOR LARGE LANGUAGE MODELS VIA PERPLEXITY-GUIDED INTERVENTION ｜连续自纠正框架

研究机构：加拿大不列颠哥伦比亚大学

作者：Jiaxun Gao、Him Wai (Michael) Ng、Z. Jane Wang

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_11962538)

> 大语言模型（LLMs）在长文本生成中面临错误累积导致的推理漂移，现有后验迭代修正方法因反馈粒度粗且滞后，无法在错误传播前进行有效干预。本文提出 Once-More 框架，通过引入词元级困惑度（Perplexity）作为实时不确定性信号，结合外部验证器反馈与对数几率（Logit）重分配机制，在生成单元级别实现连续自纠正。该框架无需模型训练，在 AIME 2024 等基准上显著优于 Self-Refine 等基线，但其性能上限受限于基础模型的内在能力，且对验证器质量存在依赖。

## 研究背景

自回归语言模型在生成过程中，早期 token 的错误会作为后续生成的条件输入，导致错误在序列中复合并放大，这一现象被称为错误累积。为缓解此问题，模型需要实时的质量监控信号。困惑度（Perplexity）是衡量模型预测不确定性的标准指标，当模型对下一个 token 的预测概率分布分散时，困惑度升高，通常指示模型处于“不确定”或“错误”状态。然而，仅依赖困惑度无法区分“高难度但正确”与“错误”的情况，因此需要结合语义层面的验证信号。

现有自纠正方法主要分为两类：基于监督微调的方法将纠正行为内化于模型参数中，但受限于训练数据分布，泛化能力差；基于后验迭代的方法（如 Self-Refine, CRITIC）在推理时通过提示工程让模型自我批评或调用外部工具，但这些方法通常在完整草稿生成后才介入，反馈粒度粗，且容易陷入非收敛的修正循环。本文的切入点在于将干预时机从“生成后”前移至“生成中”，通过细粒度的单元级监控与概率干预，在错误传播前进行截断与修正。

## 核心方法

### 生成-验证循环架构

Once-More 将标准 LLM 生成过程重构为多智能体交互系统，包含生产者（Producer）、验证器（Verifier）与生成单元（Generation Units）。生产者为冻结的预训练 LLM，负责增量生成内容；验证器可以是 LLM、非 LLM 程序或工具增强模块，负责对每个生成单元进行二元判断（接受/拒绝）并提供反馈。生成单元是自适应的语义块（如句子、代码块），其边界由语法标记或学习到的边界预测器确定。该架构的关键差异在于，它不等待完整输出，而是以单元为粒度进行“生成-监控-验证-修正”的闭环，确保错误在局部被隔离。

### 困惑度驱动的不确定性监控

为实时检测潜在错误，Once-More 计算单元级困惑度作为触发验证的信号。对于单元 $Y = [y_1, \dots, y_n]$，其困惑度定义为单元内各 token 困惑度的平均值：

$$ \text{PPL}_{\text{unit}}(Y) = \frac{1}{n} \sum_{i=1}^{n} \text{PPL}_i(y_i) $$

其中 $\text{PPL}_i(y_i)$ 基于 top-$K$ 近似计算。当 $\text{PPL}_{\text{unit}}(Y) > P_{\text{th}}$ 时，触发验证器介入。这一设计解决了传统方法中“盲目生成”的问题，通过低成本的困惑度计算筛选出高不确定性单元，仅对这部分内容调用高成本的验证器，实现了计算效率与纠错精度的平衡。

### 基于对数几率重分配的引导再生成

当单元被拒绝时，简单重试往往导致相同错误，因为模型的先验偏好会引导其重复采样相同 token。Once-More 引入引导再生成机制，结合验证器反馈与概率分布调整。首先，将拒绝单元的 token 级困惑度转换为抑制权重 $u_j$，高困惑度 token 获得更高权重。其次，通过单调对齐矩阵 $A$ 将抑制权重映射到再生成序列的对应位置，并应用距离衰减 $\tau$ 避免误抑制。最后，调整再生成时的 token 概率分布 $\tilde{q}_j(v)$：

$$ \tilde{q}_j(v) = (1 - \alpha_j) q_j^{(2)}(v) + \alpha_j \frac{r_j(v)}{\sum_{v' \in V} r_j(v')} $$

其中 $q_j^{(2)}(v)$ 是再生成时的原始分布，$r_j(v)$ 衡量模型信念在两次尝试间的偏移，$\alpha_j$ 是全局缩放因子。该机制通过强制抑制之前选择的错误 token 并提升替代选项的概率，打破模型的局部最优陷阱，确保修正方向的有效性。

## 实验评估

| 模型 | 基准 | Raw | Self-Refine | CRITIC | Once-More |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3-14B | AIME24 | 26.7±3.3 | 28.8±3.8 | 28.8±1.9 | **36.7±3.3** |
| Qwen3-14B | GPQA-D | 48.0±1.5 | 49.2±1.0 | 50.5±1.3 | **55.6±1.6** |
| Qwen3-4B | AIME24 | 13.3±3.3 | 13.3±3.3 | 14.4±1.9 | **16.7±3.4** |
| Qwen3-8B | LiveBench | 30.5±0.9 | 31.2±1.3 | 31.5±1.3 | **39.5±1.3** |

实验在 Qwen3 系列（4B, 8B, 14B）上进行，基线包括 Self-Refine、CRITIC 及原始生成。Once-More 在所有模型规模和基准上均显著优于基线，例如在 AIME 2024 上，14B 模型从 26.7% 提升至 36.7%，而 Self-Refine 仅提升 2.1 个点。消融实验显示，困惑度重分配与验证器反馈的贡献是叠加的：移除重分配导致 AIME24 性能下降 3.4 个点，移除反馈导致下降 6.4 个点，表明两者分别解决了“探索不足”与“语义错误”问题。单元粒度消融表明，当单元长度超过 32 句时，性能显著下降并趋近于原始模型，证实了细粒度干预的必要性。

评估边界方面，论文未报告计算效率的具体 GPU 小时数，仅定性指出 token 使用量低于 Self-Refine。代码未公开，超参数（如 $P_{\text{th}}$, $\alpha$, $\tau$）的校准细节仅在附录中简述，可复现性依赖于对附录中校准流程的精确实现。此外，实验主要聚焦于数学与科学推理，未覆盖开放域对话等缺乏确定性验证器的场景。

## 关联研究分析

从问题动机看，Once-More 与 Self-Refine 同属推理时自纠正路线，但核心差异在于干预粒度。Self-Refine 依赖模型对完整输出的自我批评，反馈信号稀疏且滞后，导致错误在生成过程中已累积；Once-More 通过困惑度实时监控，将干预点下沉至单元级别，解决了“错误传播前无法拦截”的问题。这一差异源于对“错误累积”机制的不同理解：Self-Refine 假设错误可通过事后修正消除，而 Once-More 认为错误是动态过程，需实时阻断。

从方法设计看，Once-More 借鉴了 GeDi 等解码时引导思想，但将其应用于错误纠正而非属性控制。GeDi 通过判别模型引导生成方向，而 Once-More 通过 Logit 重分配强制探索替代路径。与训练式自进化方法（如 SPIN, R-Zero）相比，Once-More 不涉及参数更新，因此不受“放大 vs 复合”能力上限争议的影响，但其性能提升依赖于基础模型的内在推理能力。对于小模型（如 4B），Once-More 仍能带来 3.4 个点的提升，这与领域共识中“小模型自纠正困难”的观点形成对比，暗示概率干预可能部分弥补了小模型在元认知上的不足，但这种提升是否掩盖了根本性的能力缺陷，论文未给出深入分析。

## 总结

Once-More 旨在解决 LLM 长文本生成中错误累积导致的推理漂移问题，其核心矛盾在于后验修正的滞后性与错误传播的即时性之间的冲突。本文通过引入困惑度驱动的实时监控与 Logit 重分配机制，在生成单元级别实现连续干预，从而在错误传播前进行截断。实验表明，该框架在 AIME 2024 上将 14B 模型性能从 26.7% 提升至 36.7%，显著优于 Self-Refine 等基线。然而，其性能上限仍受限于基础模型的内在能力，且对验证器质量存在依赖，当单元粒度过大时，纠错效果迅速衰减。当基础模型本身缺乏足够的推理能力时，Logit 重分配能否通过强制探索生成出原本不存在的正确路径，还是仅能避免错误，这一边界在论文中尚未被充分界定。
