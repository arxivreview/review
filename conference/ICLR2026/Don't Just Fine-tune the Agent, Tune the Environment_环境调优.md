# ICLR2026最新论文 ｜Don't Just Fine-tune the Agent, Tune the Environment ｜环境调优

研究机构：浙江大学、西湖大学

作者：Siyuan Lu、Zechuan Wang、Hongxuan Zhang 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.10197)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.10197)

> 多轮工具使用智能体面临高质量训练数据极度稀缺与强化学习（RL）训练不稳定的双重困境。现有监督微调（SFT）方法在分布外任务上泛化崩溃，而直接应用 RL 则因冷启动问题和长轨迹信用分配难题导致性能坍塌。本文提出 ENVIRONMENT TUNING，通过结构化课程、可操作环境增强和细粒度进度奖励，让智能体直接从问题实例中学习，无需专家轨迹。该方法在仅 400 个样本下实现了显著的分布内性能提升和分布外泛化优势，但其环境增强机制的自动化生成成本与对特定反馈格式的依赖仍是未解的疑点。

## 研究背景

多轮工具使用任务要求智能体在多个交互轮次中协调调用不同领域的 API，任何一轮的失败都会导致整个任务失败。这一过程可形式化为部分可观测马尔可夫决策过程（POMDP），其中智能体需在有限上下文窗口内，根据当前状态和任务目标生成动作序列以最大化终端奖励。然而，由于奖励信号稀疏且延迟（仅在任务结束时提供二元反馈），RL 算法难以进行有效的信用分配，导致训练过程极不稳定。

该领域的主流解决方案分为两条路线：一是基于合成轨迹的 SFT，通过大规模生成工具调用数据来缓解数据稀缺问题；二是直接应用 RL，通过在线交互和探索来提升泛化能力。SFT 路线的代表工作如 xLAM 和 BitAgent 虽然在分布内基准上表现强劲，但在分布外任务上出现严重性能崩溃，例如 xLAM 在 BFCL V3 上达到 70.50%，但在 OOD Web Search 任务上骤降至 5.00%。RL 路线则面临“冷启动”困境：初始策略较差的智能体无法有效探索庞大的动作空间，陷入低质量 rollout 的循环，且长交互链导致梯度爆炸和性能坍塌。本文的切入点在于指出，问题不仅在于数据或算法，更在于环境反馈的质量——标准环境提供的模糊错误信息阻碍了智能体从失败中学习，因此需要将环境本身作为可优化的训练组件。

## 核心方法

### 方法参照系

本文问题属于多轮工具使用智能体的策略优化范畴。标准流程通常采用 SFT 或直接 RL 训练智能体，前者依赖静态轨迹数据，后者依赖稀疏终端奖励。本文的关键差异在于，将环境反馈机制纳入训练循环，通过动态修改环境返回的信息来塑造学习信号，而非仅优化智能体策略参数。

### 结构化课程与阶段转换

直接在全量数据上应用 RL 会导致训练不稳定，因为智能体需同时掌握低层语法技能和高层推理能力。本文设计四阶段课程，逐步增加目标复杂度。阶段 1 专注于语法正确性，使用格式奖励 $R_{format}$ 和工具调用奖励 $R_{tool}$ 训练智能体生成有效输出：

$$R_{format} = \frac{N - C_{format}}{N}, \quad R_{tool} = \frac{C_{correct}}{C_{correct} + C_{error}}$$

其中 $N$ 为总轮次，$C_{format}$ 为格式违规次数，$C_{correct}$ 和 $C_{error}$ 分别为正确和错误工具调用次数。该设计隔离了基础技能，避免策略错误与格式错误相互混淆。阶段 2-4 逐步引入任务导向推理、复杂场景和评估环境对齐，阶段转换基于验证准确率平台期和梯度范数稳定性，确保智能体在当前阶段技能收敛后再进入更复杂任务。

### 可操作环境增强与细粒度进度奖励

标准环境返回的模糊错误信息（如“FileNotFoundError”）无法指导智能体发现工具依赖或理解内部约束。本文提出可操作环境增强，将失败轨迹转化为建设性学习信号。例如，在旅行 API 任务中，标准反馈“无可用路线”被替换为“无效机场代码：...”，提示智能体需先调用其他工具获取正确代码。这种增强通过 LLM 驱动的工作流生成，嵌入工具依赖关系和操作规则，剪枝探索空间。

为解决奖励稀疏问题，本文引入细粒度进度奖励 $R_P$，替代稀疏二元终端奖励。对于长度为 $T$ 的 episode，每轮 $t$ 的成功率定义为状态评估 $r_t^{[state]}$ 和执行结果评估 $r_t^{[exec]}$ 的乘积：

$$R_P = \frac{1}{T} \sum_{t=1}^{T} (r_t^{[state]} \cdot r_t^{[exec]})$$

该公式提供密集的轮次级学习信号，区分“接近正确”与“完全错误”的轨迹，使智能体能从部分成功的尝试中高效学习，同时保留发现新策略的自由度。

## 实验评估

实验在 BFCL V3 多轮子集（400 训练样本）上进行，基线覆盖 SFT 模型（Arch-Agent-7B, xLAM-2-8b-fc-r, BitAgent-8B）和专有模型（Claude Sonnet 4, GPT-4o, Gemini 2.5 Pro, o3），但缺失纯提示工程基线。主实验结果显示，ENVIRONMENT TUNING 在 Qwen2.5-7B-Instruct 上将平均准确率从 7.00% 提升至 36.92%，超越 BitAgent-8B（53.75%）和 Gemini 2.5 Pro（58.00%）在部分子集上的表现；在 watt-tool-8B 上从 35.74% 提升至 54.34%，超过 o3（51.00%）和 GPT-4o（63.00%）在部分子集上的表现。

| Qwen2.5-7B-Instruct | 7.00 | 9.33 | 9.33 | 6.33 | 3.00 |

消融实验表明，环境增强在 Missing Parameters 和 Missing Functions 子集上带来超过 20% 的性能提升，而进度奖励在复杂阶段（Stage 3）对训练稳定性至关重要，二元奖励在这些子集上导致性能接近零。评估边界方面，论文未报告置信区间，且环境增强的自动化生成成本未量化；代码未公开，超参数细节仅在附录中提供，可复现性受限。

## 关联研究分析

从问题动机看，本文与 Tool-R0 和 Agent0 均针对数据稀缺问题，但路径不同。Tool-R0 通过生成器-求解器协同进化在合成环境中训练，依赖可验证奖励；Agent0 通过课程 Agent 与执行 Agent 协同进化，利用 RL 在零人工标注数据下提升能力。本文的核心差异在于，将环境反馈本身作为优化对象，而非仅优化智能体策略或环境生成过程。这种差异源于多轮工具使用中环境反馈的模糊性对探索的阻碍，而 Tool-R0 和 Agent0 未显式处理这一环节。

从方法设计看，本文与 SFT 基线（如 xLAM）形成鲜明对比。xLAM 依赖大规模合成轨迹数据，在分布内任务上表现强劲，但在 OOD 任务上泛化崩溃；本文通过环境交互学习通用问题解决原则，而非记忆数据集特定模式。这一差异揭示了 SFT 方法的根本局限：静态轨迹无法覆盖真实世界的动态变化，而环境交互能提供更丰富的学习信号。然而，本文的环境增强机制依赖 LLM 生成纠错提示，其自动化程度和成本未充分评估，可能在大规模工具生态中面临可扩展性挑战。

## 总结

本文要解决的核心矛盾是多轮工具使用中数据稀缺与 RL 训练不稳定之间的冲突。现有 SFT 方法因静态轨迹导致泛化崩溃，直接 RL 因冷启动和稀疏奖励导致性能坍塌，而本文通过环境调优将失败转化为学习信号，实现了从轨迹模仿到环境探索的范式转变。ENVIRONMENT TUNING 结合结构化课程、可操作环境增强和细粒度进度奖励，在仅 400 个样本下将 Qwen2.5-7B 的性能从 7.00% 提升至 36.92%，并在 OOD 任务上显著优于 SFT 基线。本文的边界在于，环境增强机制的自动化生成成本未量化，且对特定反馈格式的依赖可能在未见过的工具生态中失效。当工具数量从 84 个扩展到数千个时，环境增强的生成效率和泛化能力是否仍能维持，论文未给出回答。
