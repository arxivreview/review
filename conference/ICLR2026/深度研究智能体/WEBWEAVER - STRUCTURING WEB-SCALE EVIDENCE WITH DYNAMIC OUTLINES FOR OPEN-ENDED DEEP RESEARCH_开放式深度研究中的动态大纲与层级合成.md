# ICLR2026最新论文 ｜WEBWEAVER: STRUCTURING WEB-SCALE EVIDENCE WITH DYNAMIC OUTLINES FOR OPEN-ENDED DEEP RESEARCH ｜开放式深度研究中的动态大纲与层级合成

研究机构：香港科技大学、阿里巴巴集团

作者：Zijian Li、Xin Guan、Bo Zhang 等 12 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_38464159)

> 导读 开放式深度研究要求智能体在无标准答案的开放环境中，从海量网络证据中合成结构化报告，核心难点在于长程信息整合与引用准确性。现有方案或采用静态大纲导致搜索边界受限，或采用暴力长文生成导致上下文注意力失效。WebWeaver 通过“大纲-搜索共进化”循环与“层级检索写作”机制，将规划与执行解耦为动态协同过程。该框架在 DeepResearch Bench 上取得 50.80 的 RACE 得分，但依赖闭源大模型且未涉及强化学习训练，其泛化能力与训练效率存疑。

## 研究背景

当智能体面对超过 100 个网页的复杂研究任务时，直接将所有原始文本输入上下文会导致“中间丢失”现象，即模型对长序列中间部分的注意力显著下降，进而引发幻觉与逻辑断裂。为解决此问题，检索增强生成（RAG）引入了外部知识库，但传统 RAG 仅依赖单次静态检索，无法处理需要多步导航与假设验证的长程任务。深度研究智能体（Deep Research Agents, DRA）因此被提出，旨在通过“推理-行动-观察”循环实现动态探索，但早期 ReAct 范式受限于长程记忆丢失，难以维持目标一致性。

当前 DRA 领域存在两条主要路线：架构派通过多智能体协作显式管理记忆与规划，训练派则依赖大规模强化学习（RL）优化端到端策略。架构派面临的核心瓶颈是静态大纲的僵化性，即预先生成的大纲无法适应搜索过程中涌现的新证据；训练派则面临信用分配难题，难以区分长轨迹中关键决策与冗余步骤。WebWeaver 的切入点在于打破规划与执行的单向流程，提出大纲与搜索策略的共进化机制，同时通过层级化写作解决长上下文注意力管理问题。

## 核心方法

### 方法参照系

本文问题属于开放式深度研究中的报告生成任务，与通用 RAG 流程的关键差异在于缺乏标准答案且证据规模巨大。标准 RAG 流程为“查询-检索-生成”，而 DRA 需扩展为“规划-搜索-大纲优化-检索-写作”的多轮迭代过程，核心挑战在于如何动态调整搜索策略并管理长程上下文。

### 动态大纲-搜索共进化

传统方法将大纲生成与搜索解耦，或先搜后写，或先写大纲后搜，导致搜索边界受限或大纲僵化。WebWeaver 的 Planner 采用 ReAct 框架，动作空间包含 `search`、`write_outline` 和 `terminate$。在每一轮迭代中，Planner 基于当前上下文生成思考（$\tau_i$），执行动作（$a_i$），并接收观察（$o_i$）。搜索动作不仅返回原始 URL，还通过 LLM 执行 URL 选择、页面解析、摘要生成与证据提取，将结构化证据存入记忆库。大纲优化动作则基于新证据扩展章节、添加引用 ID 或重构大纲，形成“搜索-大纲”反馈循环。该机制解决了静态大纲无法适应涌现证据的问题，使大纲成为动态的战略蓝图，指导后续搜索填补知识空白。

### 层级检索与剪枝写作

Writer 阶段面临的核心失效是暴力长文生成导致的上下文饱和与跨章节干扰。WebWeaver 的 Writer 采用层级化合成策略，动作空间包含 `retrieve`、`write` 和 `terminate$。对于大纲中的每个章节，Writer 首先执行 `retrieve` 动作，通过大纲中的引用 ID 从记忆库中仅检索相关证据，而非加载全部材料。随后，Writer 执行 `think` 动作进行内部推理，分析前文与检索内容，形成综合洞察，再执行 `write` 动作生成章节内容。关键创新在于“检索-剪枝”机制：每完成一个章节，其对应的源材料即从上下文中移除并替换为占位符，确保后续章节的上下文仅包含当前相关证据。该机制通过公式 $C_{t+1} = C_t \setminus E_t \cup \{placeholder\}$ 实现，其中 $C_t$ 为当前上下文，$E_t$ 为第 $t$ 章证据，$placeholder$ 为占位符。这一设计解决了长上下文注意力失效问题，使模型能专注于当前章节的深度推理，而非浅层摘要。

## 实验评估

实验在 DeepResearch Bench（100 个博士级任务）、DeepConsult 与 DeepResearchGym 上进行，基线覆盖开源系统（OpenScholar, WebShaper）与闭源系统（OpenAI, Gemini），但缺失 RL 训练派方法（如 ASearcher）的直接对比。

| 系统 | RACE Overall | RACE Comp. | RACE Insight | FACT C. acc. |
| :--- | :--- | :--- | :--- | :--- |
| WebWeaver (Claude-sonnet-4) | 50.80 (0.1) | 51.39 (0.2) | 51.65 (0.1) | 92.13 (0.7) |
| Gemini-2.5-pro-deepresearch | 49.71 | 49.51 | 49.45 | 75.01 |
| OpenAI-deepresearch | 46.45 | 46.46 | 43.73 | - |
| WebWeaver (Qwen3-30b) | 45.78 (0.7) | 44.44 (0.5) | 45.10 (0.5) | 25.29 (0.9) |

WebWeaver (Claude-sonnet-4) 在 RACE 整体得分上超越 Gemini-2.5-pro 1.09 分，引用准确率达 92.13%，显著高于 Gemini 的 75.01。消融实验显示，大纲优化轮次从 1 轮增至 3 轮，DeepResearch Bench 整体得分从 48.85 升至 50.82，洞察得分从 46.33 升至 48.35，验证了动态大纲的必要性。层级写作相比暴力长文生成，洞察得分提升 6.75 分（42.72 → 49.47），引用准确率提升 5.40 分（86.73 → 92.13），证明层级检索对注意力管理的增益。

评估边界方面，论文未报告计算效率与延迟，且依赖闭源模型（Claude/GPT）的 API 调用，可复现性受限。代码已开源，但 SFT 数据集 WebWeaver-3k 的生成过程依赖 GPT-oss-120b，小模型微调效果（Qwen3-30b）在引用准确率上仅 25.29%，远低于大模型，表明架构优势在小模型上未完全迁移。

## 关联研究分析

从问题动机看，WebWeaver 与 ASearcher 形成“显式规划 vs 端到端优化”的对比。ASearcher 通过大规模 RL 训练智能体自主优化搜索策略，解决长程稀疏奖励问题，但依赖验证答案进行信用分配；WebWeaver 则通过架构设计显式管理大纲与证据，无需 RL 训练即可提升报告质量，但缺乏对搜索策略的端到端优化。这一差异源于任务特性：WebWeaver 聚焦开放式报告生成，强调结构完整性与引用准确性，而 ASearcher 聚焦多跳问答，强调答案准确性。WebWeaver 未与 ASearcher 对比，可能因后者未提供报告生成能力，或闭源模型与开源 RL 模型的评估协议不兼容。

从方法设计看，WebWeaver 与 LongWriter 在写作策略上存在根本差异。LongWriter 采用“计划-写作”策略，将全部证据输入上下文进行暴力长文生成，导致注意力分散；WebWeaver 通过层级检索与剪枝，将长上下文问题转化为系统级上下文管理问题。这一差异源于对“长上下文”本质的理解：LongWriter 视其为模型能力问题，WebWeaver 视其为架构设计问题。WebWeaver 的“检索-剪枝”机制在小模型上效果有限（引用准确率 25.29%），暗示该机制可能依赖大模型的强推理能力，而非纯粹的架构优势。

## 总结

WebWeaver 要解决的核心矛盾是开放式深度研究中静态大纲的僵化性与长上下文注意力失效问题。其切入点在于打破规划与执行的单向流程，通过大纲-搜索共进化与层级检索写作，将长程任务解耦为动态协同的子任务。实验证明该框架在 DeepResearch Bench 上取得 50.80 的 RACE 得分与 92.13% 的引用准确率，超越闭源系统。然而，其边界在于依赖闭源大模型，且小模型微调效果有限，表明架构优势可能未完全解耦于模型能力。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
