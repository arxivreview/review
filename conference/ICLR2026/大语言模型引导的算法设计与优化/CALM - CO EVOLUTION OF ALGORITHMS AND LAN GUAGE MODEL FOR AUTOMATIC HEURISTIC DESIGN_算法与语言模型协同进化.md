# ICLR2026最新论文 ｜CALM: CO EVOLUTION OF ALGORITHMS AND LAN GUAGE MODEL FOR AUTOMATIC HEURISTIC DESIGN ｜算法与语言模型协同进化

研究机构：香港城市大学、东南大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_96454454)

> 自动启发式设计（AHD）旨在利用大语言模型（LLM）的语义推理能力，在计算预算受限条件下突破传统进化算法的局部最优陷阱，实现从自然语言意图到高性能算法结构的自动化映射。现有主流方法仅通过操纵提示词引导进化，即“言语梯度”，忽视了利用评估反馈调整模型权重这一“数值梯度”维度，导致生成能力受限于静态模型的固有偏差。CALM 提出将 LLM 微调与启发式搜索解耦为双通道协同过程，通过强化学习内化成功启发式的特征，使模型在进化过程中自我适应。该方法在本地 24GB GPU 上运行 7B 量化模型，性能超越依赖商业 API 的 SOTA 基线，但其跨域泛化能力与微调稳定性仍存疑。

## 研究背景

组合优化问题（COP）的求解长期依赖专家手工设计启发式，这一过程耗时且泛化能力差。自动启发式设计（AHD）试图通过计算系统自动发现算法，早期依赖遗传编程（GP）等进化搜索框架，但受限于搜索空间狭窄且缺乏对代码语义的理解，难以发现复杂算法结构。LLM 的引入将自然语言中的领域知识转化为语义先验，压缩了高维离散搜索空间，使得从“参数搜索”向“程序结构发现”的范式转变成为可能。

当前 LLM-AHD 主流路线将 LLM 视为固定的语义变异算子，通过迭代生成、评估和反思形成闭环。然而，这些方法仅通过文本提示操纵引导进化，即“言语梯度”，完全忽略了利用启发式性能反馈来微调 LLM 权重这一“数值梯度”机会。这种静态模型假设导致 LLM 无法内化成功启发式的结构特征，在复杂任务中易陷入局部最优。CALM 的切入点在于将启发式生成过程视为训练数据源，通过强化学习（RL）微调 LLM，实现算法与模型的双向协同进化。

## 核心方法

### 方法参照系

标准 LLM-AHD 流程包含种群维护、算子选择、LLM 生成、评估反馈四个环节。本文的关键差异在于，在评估反馈环节后新增模型参数更新步骤，将传统的“固定模型+动态提示”架构改为“动态模型+动态提示”架构，使 LLM 本身成为进化对象。

### 双梯度协同机制

CALM 的核心创新在于引入 GRPO（Group Relative Policy Optimization）算法，将启发式性能转化为 RL 奖励信号。设计动机是解决纯言语梯度中 LLM 无法从失败案例中有效学习的问题。在每轮进化中，系统采样 $G$ 个响应，计算归一化优势值 $A_{i,t} = (r_i - \text{mean}(\mathbf{r})) / \text{std}(\mathbf{r})$，其中 $r_i$ 为第 $i$ 个响应的性能奖励。模型参数通过最大化以下目标函数更新：

$$
\mathcal{L}(\theta) = \mathbb{E}_{q \sim D, o \sim \pi_{\theta_{old}}} \left[ \min\left( \frac{\pi_\theta(o|q)}{\pi_{\theta_{old}}(o|q)} A, \text{clip}\left( \frac{\pi_\theta(o|q)}{\pi_{\theta_{old}}(o|q)}, 1-\epsilon, 1+\epsilon \right) A \right) - \beta D_{KL}(\pi_\theta \| \pi_{ref}) \right]
$$

该公式通过组内相对奖励消除对价值网络的需求，降低内存开销，同时 KL 散度项确保更新稳定性。这一机制使 LLM 能够内化成功启发式的结构特征，提升后续生成的质量。

### 细粒度变异算子

为增强 GRPO 的归因精度，CALM 引入注入（Injection）和替换（Replacement）算子。设计动机是解决传统算子中单个组件变化导致整体性能剧烈波动，使得梯度信号不可靠的问题。注入算子要求 LLM 在保留原有结构的基础上引入新组件，并存储组件描述以促进多样性；替换算子则针对特定指令（如重写超参数、实例依赖规则）进行局部修改。这些算子通过限制变异粒度，使 GRPO 能更精准地识别单个结构变化的贡献，从而提升微调效率。

## 实验评估

实验在 OBP、TSP、CVRP、OP 四个任务上进行，基线覆盖 FunSearch、EoH、MCTS-AHD 等主流 LLM-AHD 方法，但缺失传统 GP 超启发式基线。CALM 使用 Qwen2.5-7B-Instruct-INT4 本地模型，对比 GPT-4o-mini API 模型。

| 任务 | 方法 | 模型 | 平均 Gap (%) |
|---|---|---|---|
| OBP | MCTS-AHD | GPT-4o-mini | 0.89 |
| OBP | CALM | Qwen2.5-7B-INT4 | 0.82 |
| TSP (N=200) | MCTS-AHD | GPT-4o-mini | 13.71 |
| TSP (N=200) | CALM | Qwen2.5-7B-INT4 | 13.41 |

CALM 在更弱骨干下超越或持平强基线，验证了协同进化的有效性。消融实验显示，移除 GRPO 后 OBP Gap 从 0.82% 升至 1.78%，证明数值梯度的关键作用；移除多样性交叉算子后 Gap 升至 0.98%，表明结构多样性对避免局部最优至关重要。

评估边界存在局限：未报告置信区间，且多数实验仅关注最优性差距，忽视计算成本与鲁棒性的联合评估。代码已开源，但 INT4 量化导致的精度损失可能影响复杂问题结构的理解能力。

## 关联研究分析

从问题动机看，CALM 与 EvoTune 同属模型适配路线，但 EvoTune 采用 DPO（Direct Preference Optimization）进行偏好优化，而 CALM 采用 GRPO 进行基于分数的 RL 微调。差异根源在于任务特性：AHD 中启发式性能是连续标量，更适合 GRPO 的组内相对奖励机制，而 DPO 更适合二元偏好场景。CALM 在 OBP 任务上优于 EvoTune，验证了 GRPO 在连续奖励场景下的优势。

从方法设计看，CALM 与 CodeEvolve 同属开源本地框架，但 CodeEvolve 仅做种群进化，未涉及模型微调。CALM 通过引入 GRPO 实现了模型权重的动态更新，而 CodeEvolve 依赖固定模型的语义变异能力。这一差异导致 CALM 在复杂任务中更具适应性，但 CodeEvolve 在可复现性和多样性维持上可能更稳定。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

CALM 要解决的核心矛盾是 LLM 静态模型假设与启发式进化动态需求之间的不匹配。现有方法仅通过言语梯度引导进化，无法利用评估反馈调整模型权重，导致生成能力受限于固有偏差。CALM 通过 GRPO 微调 LLM，实现算法与模型的双向协同进化，在 OBP 任务上以 0.82% 的平均 Gap 超越 MCTS-AHD 的 0.89%，验证了数值梯度的有效性。然而，实验显示微调后的模型在 OP 任务上出现性能波动，且 INT4 量化可能限制复杂结构理解。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
