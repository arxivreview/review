# ICLR2026最新论文 ｜Incentivizing Agentic Reasoning in LLM Judges via Tool-Integrated Reinforcement Learning ｜工具集成强化学习评判框架

研究机构：美国埃默里大学

作者：Ran Xu、Jingjing Chen、Jiayu Ye 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.23038)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.23038)

> 现有 LLM 评判模型依赖纯文本推理，在处理精确计数、代码执行验证等任务时易产生幻觉，导致评估失效。本文切入点在于将代码解释器作为环境组件，通过端到端强化学习（RL）训练模型自主生成并执行代码以获取可验证证据。该框架通过多轮交互与结构化奖励，实现了无需蒸馏冷启动的自举训练。其价值在于以 8B 参数规模逼近闭源大模型性能，但工具调用预算限制与特定任务域偏差仍存疑。

## 研究背景

当评判模型面对“统计文本中特定字符出现次数”或“验证代码逻辑正确性”等任务时，纯文本推理往往因缺乏精确计算能力而陷入幻觉。这一困境源于大语言模型（LLM）的自回归生成机制，其本质是概率预测而非确定性计算，导致在符号推理与精确枚举场景下可靠性骤降。为解决此问题，工具集成推理（Tool-Integrated Reasoning, TIR）范式应运而生，它允许模型在推理过程中调用外部解释器，将不可靠的文本推断转化为可执行、可验证的代码操作，从而获取客观反馈。

LLM-as-a-Judge 领域的主流路线分为两类：一是基于提示工程或微调的纯文本评判，如 G-Eval 和 Prometheus，它们擅长语义理解但在精确计算上存在固有局限；二是早期工具辅助方法，如 AgentRM，通常在推理阶段通过提示引导模型调用工具，但缺乏对“何时调用”及“如何整合工具输出”的深度训练，导致工具使用策略僵化且泛化性差。现有方案的瓶颈在于，推理时的工具调用与训练时的策略优化是割裂的，模型无法通过强化学习内化工具使用的最优策略。本文的切入点正是打破这一割裂，提出 TIR-Judge，通过端到端的多轮强化学习，让评判模型在训练阶段就学会生成代码、执行代码并基于执行结果修正判断，从而在可验证任务上实现精确评估。

## 核心方法

### 方法参照系

本文问题属于“专用评判模型训练”类别，但与传统基于 SFT 或纯文本 RL 的评判模型不同，其核心差异在于将评判过程建模为与外部环境（代码解释器）的交互序列。传统流程中，评判模型直接输出分数或偏好，而 TIR-Judge 将评判轨迹定义为推理步骤、代码生成与执行结果的交替序列，使得评判决策建立在可验证的执行证据之上。

### 工具集成轨迹建模

传统文本评判模型将输入映射为单一输出，忽略了中间验证步骤。TIR-Judge 将评判过程形式化为多轮交互轨迹 $s_k = \{r_1, c_1, o_1, \dots, r_k, c_k, o_k\}$，其中 $r_i$ 为自然语言推理，$c_i$ 为生成的代码，$o_i = I(c_i)$ 为解释器 $I$ 的执行结果。该设计动机在于解决纯文本模型在计数、计算等任务上的幻觉问题，通过引入外部确定性反馈，使模型能够基于客观证据而非主观概率进行判断。最终预测 $a_i$ 基于完整轨迹 $s_T$ 生成，实现了推理与工具使用的紧密耦合。

### 结构化奖励与迭代自举

为引导模型有效使用工具，TIR-Judge 设计了组合奖励函数 $R = R_c \cdot R_f \cdot R_t$。其中，$R_c$ 为正确性奖励，衡量预测与真实偏好标签的一致性；$R_f$ 为格式奖励，确保输出符合结构化标签要求，并对非可验证任务（如安全性）施加“无工具调用”的正向激励；$R_t$ 为工具特定奖励，仅在代码无错误且调用次数不超过预算（max 3）时给予满分。该公式的物理含义是：只有当判断正确、格式合规且工具使用高效时，模型才能获得完整奖励，从而抑制无效工具调用并鼓励精确验证。此外，TIR-Judge-Zero 变体证明，通过迭代 RL 从初始检查点自举，无需依赖教师模型蒸馏数据，即可实现工具使用能力的自我进化，解决了此前方法对高质量蒸馏数据依赖过高的问题。

## 实验评估

实验在 PPE、IFBench、CodeJudgeBench、RewardBench、RM-Bench 和 JudgeBench 等七个基准上进行，覆盖单点、成对和列表式评判。基线包括 GPT-4o、Claude 3.5、RRM-32B 等强模型及 AgentRM 等工具辅助方法。TIR-Judge-Zero 8B 在 PPE 成对评判中达到 75.7% 准确率，超越 RRM-32B 的 74.0%，并在 RewardBench 2 列表式评判中达到 73.4%，接近 Claude-Opus-4 的 76.5%。

| 方法 | 参数规模 | PPE Pairwise Avg | RewardBench 2 Avg |
| :--- | :--- | :--- | :--- |
| TIR-Judge-Zero 8B | 8B | 75.7 | 73.4 |
| RRM-32B | 32B | 74.0 | 78.4 |
| Claude-Opus-4 | - | - | 76.5 |
| AgentRM 8B | 8B | 65.7 | - |

消融实验显示，TIR-Judge-Zero 在 4B 规模下比蒸馏版本高 1.2%，证明迭代 RL 的有效性。错误分析表明，TIR-Judge 的语法错误率（1.20%）显著低于 Qwen-3-Tool（4.95%），且格式错误率低于 1%，说明性能提升源于代码生成与推理能力的增强，而非格式修正。

评估边界方面，论文未报告置信区间，且工具调用限制为 3 次，可能影响复杂多步验证场景。代码未开源，但提供了详细超参数（如 $\epsilon_{low}=0.2, \epsilon_{high}=0.3$）和硬件配置（8x H100），具备一定可复现性。

## 关联研究分析

从方法设计看，TIR-Judge 与 AgentRM 的核心差异在于工具使用的训练方式。AgentRM 依赖提示工程在推理时调用工具，而 TIR-Judge 通过 RL 内化工具调用策略，使模型学会“何时”及“如何”使用工具。这一差异源于任务特性：评判任务需要精确验证，纯提示无法保证代码生成的正确性，而 RL 可通过执行反馈优化代码生成质量。然而，TIR-Judge 的工具调用预算限制（max 3）是否足以应对复杂多步推理，论文未给出回答。

从问题动机看，TIR-Judge 与 RRM 等纯文本推理评判模型不同，后者通过长链推理提升语义理解，但无法解决精确计算问题。TIR-Judge 通过代码执行消除了计数、计算等任务中的幻觉偏差，如 IFEval 案例中精确统计字符数。这一改进源于对评判任务中“可验证性”维度的重视，但其在非可验证任务（如安全性）上的表现是否优于纯文本模型，需进一步验证。

## 总结

TIR-Judge 旨在解决 LLM 评判模型在精确计算与符号推理任务中的幻觉问题，通过端到端 RL 训练模型自主调用代码解释器获取可验证证据。其核心创新在于结构化奖励设计与迭代自举机制，证明了无需蒸馏即可实现工具使用能力的自我进化。实验显示，8B 参数的 TIR-Judge-Zero 在 PPE 成对评判中达到 75.7%，超越 32B 的 RRM，并在 RewardBench 2 中接近 Claude-Opus-4 性能。然而，工具调用预算限制为 3 次，可能制约复杂多步验证场景的表现。当任务涉及超过 3 步的复杂代码验证时，TIR-Judge 的性能衰减程度如何，论文未给出回答。
