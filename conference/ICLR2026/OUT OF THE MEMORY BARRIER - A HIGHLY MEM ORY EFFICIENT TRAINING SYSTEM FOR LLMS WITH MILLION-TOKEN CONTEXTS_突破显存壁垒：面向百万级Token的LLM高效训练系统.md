# ICLR2026最新论文 ｜OUT OF THE MEMORY BARRIER: A HIGHLY MEM ORY EFFICIENT TRAINING SYSTEM FOR LLMS WITH MILLION-TOKEN CONTEXTS ｜突破显存壁垒：面向百万级Token的LLM高效训练系统

研究机构：厦门大学、北京大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_43544496)

> 长上下文大语言模型（LLM）训练面临的核心矛盾是激活值与键值缓存（KV Cache）内存随序列长度线性增长，导致单卡显存迅速耗尽。现有并行训练范式依赖多卡集群分摊负载，而免训练扩展方法在深层推理任务上表现失效，均无法在有限硬件上实现超长序列的端到端训练。OOMB通过分块递归训练框架结合激活重计算、分页内存管理与异步CPU卸载，将激活内存复杂度降至常数级，从而在单张H200 GPU上实现4M Token上下文的训练。该方案显著降低了长上下文训练的资源门槛，但其稀疏注意力近似对最终模型推理性能的长期影响尚存疑。

## 研究背景

Transformer架构的自注意力机制在处理长序列时，其计算复杂度呈二次方增长，且前向传播产生的激活值与反向传播所需的KV Cache均随上下文长度 $N$ 线性占用GPU显存。以Qwen2.5-7B模型为例，处理256K上下文时，仅KV Cache即需64GB显存，远超单张A100 GPU的容量，这使得32K Token成为单卡训练的实际上限。激活重计算（Activation Recomputation）是缓解此瓶颈的经典策略，其核心思想是在前向传播中丢弃中间激活值，在反向传播时即时重算，以计算换空间。然而，在Transformer中直接应用该策略面临挑战：由于注意力机制的全局依赖特性，分块处理时后续块需访问前序块的全部KV状态，导致KV Cache无法像循环神经网络（RNN）的隐藏状态那样被局部化，从而成为新的内存瓶颈。

长上下文扩展的主流路线分为训练无关与微调两类。训练无关方法通过插值或外推位置编码实现，但实验表明其在需要深层上下文理解的任务上存在“表面掌握”问题，即困惑度指标优异但推理能力退化。微调路线虽能解决泛化问题，但受限于显存，现有工作多依赖大规模集群，例如使用256-GPU集群扩展至4M Token上下文。参数高效微调（PEFT）虽降低了权重与优化器状态开销，却未触及随序列长度线性增长的激活内存瓶颈。OOMB的切入点在于将训练范式从“并行处理全序列”转向“串行处理分块”，通过系统级优化彻底解耦激活内存与上下文长度的依赖关系，从而在单卡资源下突破显存壁垒。

## 核心方法

### 分块递归训练范式

OOMB将长序列划分为 $S$ 个块，串行处理每个块。前向传播时，块 $i$ 的注意力计算依赖前序所有块的KV Cache $M_{1:i-1}$，其激活值 $A_i$ 在计算后立即丢弃。反向传播时，$A_i$ 被即时重算。该范式将激活内存复杂度从 $O(N)$ 降至 $O(1)$，仅取决于单块大小，但将瓶颈转移至需全程保留的KV Cache及其梯度。

### 分页内存管理与稀疏注意力

针对KV Cache的线性增长，OOMB引入分页内存管理器，借鉴虚拟内存思想将KV Cache与梯度存储为固定大小的页面，消除内存碎片。自定义Triton内核绕过PyTorch Autograd，直接在页面级执行前向与反向操作，通过原子加法累积梯度。为降低计算复杂度，系统支持页面级稀疏注意力。对于密集注意力模型，通过Top-K检索机制选择关键页面：

$$ \text{Score}_{m \times n} = \sum_{j=1}^{P} \text{softmax}(\mathbf{Q}_{[i,j]}^\top \mathbf{K}_{\text{avg}[k]}) $$

该公式通过聚合查询页面内所有Token与关键页面代表向量的相似度，确定需检索的Top-K关键页面索引，从而将注意力计算限制在相关页面内，显著减少计算量与通信开销。

### 异步KV Cache卸载

为应对超长序列下KV Cache超出GPU显存的情况，OOMB实现异步CPU卸载。对于密集注意力，采用预取策略：在计算第 $i-1$ 层时，异步从CPU加载第 $i$ 层的KV Cache，利用计算掩盖数据传输延迟。对于稀疏注意力，由于所需页面在查询投影后才确定，系统在查询投影后立即发起页面检索与数据传输，将其与后续的键值投影计算重叠。该机制利用GPU的DMA引擎与专用CUDA流，将端到端卸载开销控制在5%以内，实现了内存扩展与计算效率的平衡。

## 实验评估

实验基于Qwen2.5-7B模型与arXiv数据集，对比FlashAttention并行训练与Ring Flash Attention（RFA）上下文并行基线。OOMB在单张H200 GPU上实现4M Token上下文训练，而RFA需8张H200 GPU仅支持256K Token。

| 方法 | GPU数量 | 激活内存复杂度 | 最大Token数 |
| :--- | :--- | :--- | :--- |
| FlashAttention (Baseline) | 1×H200 | $O(N)$ | 32K (OOM) |
| Ring Flash Attention | 8×H200 | $O(N/8)$ | 256K |
| OOMB + Dense Attn | 1×H200 | $O(1)$ | 4M |
| OOMB + Sparse Attn | 1×H200 | $O(1)$ | 4M+ |

消融实验显示，稀疏注意力在长序列下加速显著，256K上下文时较密集注意力提速13.5倍。分块大小对延迟影响有限，12K分块在256K上下文下仅增加12%延迟。CPU卸载使峰值内存随上下文长度增长趋缓，每增加10K Token仅增加10MB显存占用。

评估边界方面，实验仅验证了训练过程中的内存效率与收敛性，未报告下游任务（如长文本问答）的准确率指标。稀疏注意力作为密集注意力的近似，其梯度误差在1M上下文下虽收敛，但长期训练对模型泛化能力的影响未充分验证。代码已开源，但超参数配置（如检索预算）对最终模型性能的影响缺乏系统性分析。

## 关联研究分析

从问题动机看，OOMB与上下文压缩方法（如LLMLingua、ICAE）均受限于KV Cache瓶颈，但目标截然不同。压缩方法旨在推理时精简Token以提升有效信息利用率，而OOMB聚焦训练时突破显存限制。这一差异源于任务特性：推理阶段需实时响应，压缩开销敏感；训练阶段数据量有限，内存是主要约束。OOMB未涉及语义保真度，其稀疏注意力仅作为计算优化手段，而非信息筛选机制，这导致其无法直接迁移至推理场景。

从方法设计看，OOMB与SeCO同属分块训练路线，但SeCO缺乏算子级优化，仅支持16K上下文。OOMB通过分页内存与异步卸载实现10倍以上的扩展。与Ring Attention相比，OOMB摒弃了多卡并行通信，采用单卡串行处理，牺牲了吞吐量以换取资源效率。这种设计选择源于长上下文微调场景下数据集规模通常较小，内存而非吞吐量是主要瓶颈。然而，OOMB未探索训练-推理联合优化，即训练时引入的稀疏模式能否直接用于推理加速，这一潜在价值未被验证。

## 总结

OOMB解决的核心矛盾是长上下文训练中激活内存与序列长度的线性依赖。其切入点在于将训练范式从并行转向串行分块，通过激活重计算将激活内存降至常数级，并系统级整合分页内存、稀疏注意力与异步卸载以管理KV Cache。实验证明，该方案在单张H200 GPU上实现4M Token上下文训练，峰值内存每增加10K Token仅增长10MB。其边界在于稀疏注意力作为近似机制，对模型最终推理性能的影响未充分验证，且串行处理引入的延迟在吞吐量敏感场景中可能成为瓶颈。当训练数据规模扩大至需要高吞吐量时，OOMB的串行范式是否仍能保持资源效率优势，论文未给出回答。
