# ICLR2026最新论文 ｜From Conversation to Query Execution: Benchmarking User and Tool Interactions for EHR Database Agents ｜电子健康记录交互式查询基准

研究机构：韩国科学技术院

作者：Gyubok Lee、Woosog Chay、Heeyoung Kwak 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.23415)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.23415)

> 临床数据访问面临用户提问模糊与数据库术语不匹配的双重障碍，传统静态文本转SQL基准无法评估智能体在动态对话中消解歧义与调用工具的能力。EHR-ChatQA通过构建包含LLM模拟用户与验证器的交互式环境，首次量化了智能体在随机对话路径下的鲁棒性缺陷。该基准揭示了当前最优模型在“至少一次成功”与“五次全部成功”间存在高达60%的性能鸿沟，证明了现有智能体在安全关键场景中的不可靠性，但其评估局限于单智能体架构，未验证多智能体协作对一致性的增益。

## 研究背景

临床数据访问的核心困境在于自然语言意图与结构化数据库状态之间的语义断层。用户常以模糊表述（如“最近的化验单”）发起查询，而电子健康记录（EHR）中的临床术语（如“Lopressor”对应“metoprolol tartrate”）存在命名规范差异，这种查询歧义与值不匹配要求智能体具备主动澄清与术语映射能力。解决此问题需将任务建模为部分可观测马尔可夫决策过程（POMDP），其中智能体需在未观测用户真实意图的状态下，通过多轮交互与工具调用逐步收敛至可执行SQL。

现有文本转SQL基准（如Spider、BIRD）聚焦于单轮、无歧义问题的静态映射，SParC与CoSQL虽引入对话上下文，但依赖预定义交互脚本，无法捕捉真实临床场景中开放式的探索行为。MedAgentBench等智能体基准虽覆盖EHR任务，但初始指令明确，绕过了动态消解歧义的核心挑战。EHR-ChatQA的切入点在于构建端到端交互环境，强制智能体在模糊起点下自主完成意图澄清、值探索与SQL生成，从而暴露静态基准无法揭示的鲁棒性短板。

## 核心方法

### 交互式POMDP任务框架

EHR-ChatQA将EHR查询任务形式化为POMDP $(S, A, T, R, \Omega)$，状态 $s \in S$ 包含未观测的用户意图、对话历史及数据库内容，动作空间 $A$ 涵盖用户交互与工具调用双循环。该框架的关键差异在于奖励函数 $R$ 的二值性：仅当智能体最终答案与基于确定性GT SQL生成的答案匹配时 $r=1$，否则 $r=0$。这种设计将评估重心从中间SQL生成的语法正确性转移至端到端任务完成的一致性，迫使智能体在随机用户行为下维持策略稳定性。

### 模拟用户与验证器机制

为量化对话路径随机性对性能的影响，基准引入基于Gemini-2.0-Flash（温度1.0）的模拟用户与基于Gemini-2.5-Flash（温度0.0）的验证器。模拟用户遵循行为规则，从模糊查询开始逐步释放约束，且被隔离于数据库内容与GT答案之外，防止信息泄露。验证器作为LLM-as-a-judge，审查完整对话轨迹，若检测到用户违反指令（如提前终止、偏离规则），则标记轨迹无效并重跑。该机制通过嵌套验证-反思循环提升模拟器可靠性，确保评估失败归因于智能体而非环境噪声。其核心创新在于将“鲁棒性”操作化为Pass@5与Pass∧5的差距：

$$
\text{Gap}_k = \text{Pass}@k - \text{Pass}_{\wedge}k
$$

其中Pass@k为k次独立试验中至少一次成功的比例，Pass∧k为k次全部成功的比例。Gap-k直接度量智能体在多样对话路径下的性能波动，揭示了静态基准中不可见的可靠性缺陷。

### 双交互流任务设计

基准包含366个任务实例，分布于MIMIC-IV与eICU两个EHR数据库，分为增量查询细化（IncreQA）与自适应查询细化（AdaptQA）两类交互流。IncreQA测试智能体在用户线性添加约束（如时间范围、患者队列）时维持上下文的能力；AdaptQA则引入条件分支，要求智能体根据中间响应动态调整查询计划（如品牌名无记录时转向通用名）。AdaptQA的设计原则是每条指令必须隐藏智能体需自主发现的信息，强制其通过值探索工具（如value_similarity_search）解决术语映射，而非依赖用户明确提示。这种设计将值不匹配处理从静态映射提升为动态决策过程，更贴近真实临床数据访问场景。

## 实验评估

实验在MIMIC-IV与eICU的隐私安全演示版本上进行，评估o4-mini、GPT-4o、Gemini-2.5-Flash等闭源模型及Llama 3.3-70B、Qwen3-32B等开源模型，所有模型采用统一函数调用设置与温度0.0，性能差异仅源于用户模拟器的随机性。基线覆盖主流LLM，但缺失多智能体协作架构，无法验证角色分工对一致性的潜在增益。

o4-mini在IncreQA上SR-5达81.3%，但Gap-5高达38.8%；在AdaptQA上SR-5降至35.8%，Gap-5扩大至58.7%。开源模型在AdaptQA上表现显著更差，Llama 3.3-70B SR-5仅14.2%。这一差距表明，即使最优模型也无法在随机对话路径下保持一致性能，AdaptQA的条件分支结构进一步放大了智能体的脆弱性。

消融分析显示，Gap-k随试验次数k增加而扩大，且用户交互轮数与成功率负相关。o4-mini的失败轨迹中，一致失败（五次全败）反映根本能力局限，不一致失败（部分成功）则暴露对对话路径变化的敏感性。环境成本约$0.004/IncreQA任务，$0.007/AdaptQA任务，全基准五次运行总成本约$95（o4-mini）或$52（Gemini-2.5-Flash），表明评估具备可扩展性。

评估边界受限于单智能体架构与静态GT SQL，未纳入多模态数据或长周期状态管理。代码与数据公开于GitHub，但用户模拟器依赖Gemini-2.0-Flash，其指令遵循可靠性仍存疑，41.8%的模拟重跑源于用户遗漏条件，提示环境噪声可能部分归因于模拟器而非智能体。

## 关联研究分析

从问题动机看，EHR-ChatQA与MedAgentBench同属EHR智能体评估，但前者聚焦动态对话中的歧义消解，后者侧重静态指令下的任务执行。MedAgentBench的SELSM达100%任务完成率，但其初始指令明确，无需智能体主动澄清意图；EHR-ChatQA的o4-mini Pass∧5仅约50%，差异根源在于任务是否包含未观测用户意图的探索过程。这提示，静态基准的高成功率可能掩盖了智能体在真实模糊场景中的可靠性缺陷，而非反映其真实能力水平。

从方法设计看，EHR-ChatQA借鉴Tau-Bench的用户-工具双循环框架，但引入EHR特有的值不匹配处理机制。Tau-Bench评估通用工具调用，而EHR-ChatQA要求智能体通过value_similarity_search等工具解决临床术语映射，这一设计将值探索从可选步骤提升为必要环节。然而，论文未验证多智能体协作（如MedCoAct的置信度感知机制）是否能缩小Gap-5，单智能体架构下的鲁棒性缺陷是否可通过角色分工缓解，仍是未探索的盲区。

## 总结

EHR-ChatQA针对静态文本转SQL基准无法评估动态交互鲁棒性的矛盾，通过构建LLM模拟用户与验证器的端到端环境，量化了智能体在随机对话路径下的性能波动。其核心发现是o4-mini在IncreQA与AdaptQA上的Gap-5分别达38.8%与58.7%，证明当前最优模型缺乏安全关键场景所需的一致性。该基准的边界在于局限于单智能体架构与静态GT SQL，未验证多智能体协作或动态奖励机制对一致性的潜在增益。当用户模拟器的随机性被控制后，Gap-5是否仍显著存在，还是主要由环境噪声驱动，论文未给出回答。
