# ICLR2026最新论文 ｜RECODE-H: A Benchmark for Research Code Development with Interactive Human Feedback ｜科研代码生成的交互式反馈基准

研究机构：清华大学、加拿大麦吉尔大学

作者：Chunyu Miao、Henry Peng Zou、Yangning Li 等 31 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.06186)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.06186)

> 现有科研代码生成基准普遍采用一次性生成设定，忽略了真实科研工作中人类反馈对代码修正的关键作用。RECODE-H 通过引入五级结构化反馈层级，将“反馈粒度”作为可控变量，系统评估大语言模型在多轮交互中利用人类指导修正代码的能力。该基准包含102个源自真实论文与代码库的任务，并提出了ReCodeAgent框架以模拟专家反馈循环。实验表明，即使是最基础的诊断信号也能使模型通过率接近翻倍，但模型在语义对齐与领域知识填补上仍存在显著瓶颈，且反馈收益呈现明显的边际递减效应。

## 研究背景

科研代码生成的核心困境在于输入语料的“欠定”特性。研究论文通常通过高层叙事、数学公式及领域惯例描述方法，大量实现细节隐含在上下文或作者经验中，这种碎片化描述使得模型难以直接映射到可执行代码。为量化这一难度，领域引入了Pass@k指标，即模型生成代码通过单元测试的比例。然而，Pass@k仅衡量最终状态的正确性，无法区分模型是“一次性猜对”还是“通过反馈迭代修正”，更无法捕捉模型在长程推理中利用外部指导的能力。

主流评估路线分为两类：一类是通用代码基准（如HumanEval、SWE-bench），侧重函数级或仓库级Issue修复，但任务定义与科研方法复现存在本质差异；另一类是科研代码基准（如SciReplicate-Bench、ResearchCodeBench），虽聚焦论文复现，但多采用非交互式设定，要求模型在单次响应中产出正确代码。这种设定忽略了两个现实约束：用户往往无法一次性完整指定需求，且模型首次生成极少完美对齐。RECODE-H的切入点在于将“人类反馈”从不可控的噪声转化为结构化的评估维度，通过控制反馈的粒度与类型，量化模型在迭代过程中的适应性与收敛速度。

## 核心方法

### 方法参照系

本文问题归属于仓库级软件工程评估范畴，但与传统SWE-bench等基准的关键差异在于任务来源与交互范式。传统基准侧重修复GitHub Issue，输入为明确的错误报告；RECODE-H侧重复现论文方法，输入为模糊的学术描述。此外，传统基准多为单轮或简单多轮，而RECODE-H将“反馈层级”作为核心控制变量，模拟从“仅报错”到“提供正确代码片段”的完整指导谱系。

### 五级反馈层级

在标准代码生成流程中，模型通常仅接收执行日志或简单的Pass/Fail信号。RECODE-H在此环节引入了五级反馈层级（Level 0-4），将人类专家的指导深度量化为离散变量。Level 0仅提供执行失败日志；Level 1增加高层错误描述；Level 2提供错误成因诊断；Level 3给出自然语言修正指引；Level 4直接提供正确的代码片段。这种设计解决了传统基准中反馈不可控导致的评估噪声问题，使得模型对“浅层诊断”与“深层监督”的利用效率可被独立测量。反馈生成由GPT-o4-mini模拟专家完成，确保跨任务的一致性与可复现性。

$$
L_{feedback} = \{L_0, L_1, L_2, L_3, L_4\}, \quad L_i \subseteq L_{i+1}
$$

该公式表示反馈层级具有累积性，每一级包含前一级所有信息并增加新的指导维度，从而允许研究者通过差分比较（如$L_1 - L_0$）精确量化特定类型反馈（如“错误成因解释”）对模型性能的边际贡献。

### ReCodeAgent框架

ReCodeAgent是执行多轮交互的代理框架，其核心创新在于将反馈整合进迭代循环。在每一轮交互中，Agent执行“读取文件-编写代码-提交测试”的动作序列，并接收对应层级的反馈。框架限制Agent在单轮内最多执行3个动作，并维护大小为5的记忆窗口，以模拟真实研究者有限的工作记忆。这一设计解决了长上下文窗口中信息稀释的问题，迫使模型在有限记忆约束下高效利用最新反馈。

$$
C_{t+1} = \text{Refine}(C_t, F_t, M_t)
$$

其中$C_t$为第$t$轮生成的代码，$F_t$为第$t$轮接收的反馈，$M_t$为记忆窗口中的历史交互摘要。该公式表明，代码修正是一个基于当前代码、即时反馈及历史上下文的联合优化过程，而非简单的错误替换。

## 实验评估

实验在RECODE-H基准上进行，涵盖GPT-5、DeepSeek-V3.1、Claude-Sonnet-4及Gemini 2.5系列共7个模型。基线覆盖主流闭源大模型，但缺失开源小模型（如CodeLlama）及专用SWE Agent（如SWE-Agent），限制了跨规模与跨架构的对比深度。

| 模型 | 反馈层级 | Recall | MRR | 测试通过率 |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5 | Level 0 | 0.294 | 0.060 | - |
| GPT-5 | Level 4 | 0.716 | 0.119 | - |
| DeepSeek-V3.1 | Level 0 | 0.108 | - | - |
| DeepSeek-V3.1 | Level 4 | 0.706 | - | - |

*注：表中数值直接取自论文正文描述，部分指标在原文表格中未完整展示或格式不一，故仅列出明确提及的关键对比值。*

GPT-5的Recall从Level 0的0.294提升至Level 4的0.716，DeepSeek-V3.1从0.108跃升至0.706，证实了反馈对性能的巨大增益。然而，增益呈现非线性特征：从Level 0到Level 1的提升幅度最大，后续层级收益递减。这表明模型对“浅层诊断”高度敏感，而对“深层代码级监督”的边际利用效率较低。

消融实验显示，GPT-5在Level 4下表现最佳，而Claude-Sonnet-4的反馈采纳率随层级增加反而下降，Gemini-2.5-pro则在70%左右波动。错误分析指出，失败主要源于论文指令误解（Type 2）与领域知识缺失（Type 3），而非语法错误（Type 1）。这揭示了一个反直觉现象：模型已克服基础编码障碍，但在将模糊学术描述映射为精确逻辑时，缺乏对隐含假设的推理能力。

评估边界方面，RECODE-H仅覆盖102个任务，样本量较小，统计显著性受限。反馈由LLM模拟而非真实人类，可能引入模拟偏差，例如LLM生成的反馈可能过于结构化或遗漏人类专家的非正式提示。此外，Level 4提供正确代码片段，可能导致评估退化为“代码补全”而非“代码生成”，削弱了对模型自主推理能力的考察。

## 关联研究分析

从问题动机看，RECODE-H与SciReplicate-Bench同属科研代码生成领域，但后者侧重端到端工作流，缺乏对交互过程的细粒度控制。RECODE-H将“反馈”作为独立变量，填补了从“一次性生成”到“交互式修正”的评估空白。然而，这种结构化反馈是否完全等价于真实科研场景中的非正式沟通，论文未提供实证对比。真实研究者可能提供模糊、矛盾或带有个人偏见的反馈，而LLM模拟的反馈往往逻辑严密且指向明确，这可能高估了模型在嘈杂环境下的鲁棒性。

从方法设计看，RECODE-H借鉴了MINT的多轮交互思路，但MINT侧重工具使用，RECODE-H侧重代码修正。与SWE-bench相比，RECODE-H的任务复杂度更高，因为论文描述比Issue报告更抽象。然而，RECODE-H未采用SWE-bench中常见的“执行验证”作为唯一标准，而是结合了CodeBLEU等语义相似度指标。这种混合评估可能引入偏差，因为语义相似度高不代表功能正确，反之亦然。论文未深入讨论这种指标组合对最终结论的影响，也未提供单独使用Pass@k时的对比结果。

## 总结

RECODE-H旨在解决科研代码生成中“反馈利用效率”不可量化的问题，通过五级反馈层级将人类指导转化为可控变量。实验证明，结构化反馈能显著提升模型性能，GPT-5的Recall从0.294提升至0.716，但收益随反馈粒度增加而递减。该基准的边界在于反馈由LLM模拟，且Level 4可能退化为代码补全，未能完全反映真实科研协作中的噪声与模糊性。当反馈来源从结构化LLM切换为真实人类专家时，模型对非正式、矛盾或模糊指导的适应能力是否会发生显著变化，论文未给出回答。
