# ICLR2026最新论文 ｜ThinKV: Thought-Adaptive KV Cache Compression for Efficient Reasoning Models ｜思维自适应KV缓存压缩

研究机构：美国佐治亚理工学院、英伟达研究院

作者：Akshat Ramachandran、Marina Neseem、Charbel Sakr 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.01290)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.01290)

> 大推理模型（LRM）在生成数千Token的思维链时，键值缓存（KV Cache）的线性增长导致显存溢出，成为长输出推理的核心瓶颈。现有压缩方法多聚焦于预填充阶段或采用Token级贪心驱逐，忽略了推理过程中的语义结构差异，导致高精度压缩下准确率显著下降。本文提出ThinKV，通过注意力稀疏度分解思维类型，实施思维自适应量化与驱逐，并设计连续思考内核消除内存碎片。该框架在低于5%的原始KV缓存预算下实现了近乎无损的推理精度，但其思维类型定义的泛化性在跨模型场景下仍存疑。

## 研究背景

长输出推理中，解码阶段受限于内存带宽而非算力，KV缓存占用往往超过模型参数本身。以GPT-OSS20B为例，生成32K Token且批大小为32时，KV缓存需50GB，加上40GB权重，超出A100的80GB显存。这一困境源于自回归生成中每个新Token需读取全部历史KV对，导致内存压力随序列长度线性累积。

早期KV压缩研究聚焦于长输入任务的预填充阶段，如SnapKV利用观察窗口筛选关键Prompt Token，H2O基于累积注意力分数动态驱逐低价值Token。然而，这些方法假设Token重要性静态或仅依赖近期性，无法捕捉LRM中推理轨迹的动态演变。近期针对LRM的工作如R-KV和PM-KVQ虽引入了冗余感知或渐进量化，但仍停留在Token级操作，缺乏对推理语义结构的整体把握，导致在高压缩率下关键推理步骤被误删或次要步骤过度保留，造成精度-效率权衡失衡。

本文切入点在于识别LRM思维链中存在的离散思维类型，并利用注意力稀疏度的三模态分布作为分类依据。通过从Token级提升至思维段级操作，ThinKV旨在解决现有方法在长输出场景中因忽略语义结构而导致的累积误差问题，实现高精度压缩下的推理稳定性。

## 核心方法

### 方法参照系

本文问题属于KV缓存压缩中的“量化+驱逐”混合路线。标准流程通常独立执行统一量化或基于注意力分数的Token驱逐。本文的关键差异在于引入前置的“思维分解”步骤，将压缩决策从Token粒度提升至思维段粒度，并依据思维重要性动态分配量化精度与驱逐保留率。

### 思维分解与自适应量化

传统量化方法对所有Token施加统一比特精度，忽略了不同推理阶段的信息密度差异。ThinKV首先通过核密度估计（KDE）在离线校准阶段确定注意力稀疏度阈值，将解码过程中的Token划分为推理（R）、执行（E）和过渡（T）三类。基于反事实重要性分析，R类思维对最终答案影响最大，T类最小。据此，定义思维自适应量化策略，将比特精度 $b$ 与思维重要性 $\rho$ 映射：

$$
\psi(c_j) = b_k \quad \text{where} \quad \rho(c_j) > \rho(c_{j'}) \implies b_k \geq b_{k'}
$$

具体实现中，R类分配8-bit（或4-bit），E类分配4-bit，T类分配2-bit。这种非对称量化解决了统一量化在低比特下因离群值导致的精度崩塌，同时避免了高比特存储低重要性Token的内存浪费。

### 思维自适应驱逐与连续思考内核

Token级驱逐常导致内存碎片，需高开销的gather操作进行紧凑化。ThinKV提出思维自适应驱逐（TBE），以思维段为最小单元，当检测到T类思维（推理轨迹改变）时，对前序思维段执行渐进式驱逐。保留率 $R$ 定义为递减序列 $\{64, 32, 16, 8, 4\}$，每次轨迹改变时，前序段保留率降至下一档：

$$
|S^*_{i[\ell]}(c_j)| = \min(|S_{i[\ell]}(c_j)|, R_n)
$$

其中 $n$ 为当前思维段被选为驱逐目标的次数。为消除驱逐后的内存空洞，设计连续思考（CT）内核，扩展PagedAttention的块表结构，记录思维类型、起始索引及驱逐掩码，实现驱逐内存槽位的原地复用，彻底规避了gather操作带来的HBM带宽竞争。

## 实验评估

实验在DeepSeek-R1-Distill、GPT-OSS等LRM上，使用AIME、LiveCodeBench等基准，对比H2O、KIVI、R-KV等基线。基线覆盖了驱逐、量化及混合路线，但缺乏架构级优化（如MLA）的对比，限制了与源头减量方法的直接比较。

| 模型 | 方法 | 比特宽度 | AIME | LiveCodeBench |
| :--- | :--- | :--- | :--- | :--- |
| R1-Qwen-14B | Baseline | 16-16 | 53.33 | 40.00 |
| | KIVI | 2-2 | 47.90 | 34.56 |
| | PM-KVQ | 3.2-3.2 | 43.33 | 41.97 |
| | **ThinKV** | 3.5-3.5 | **50.00** | **45.84** |

在R1-Qwen-14B上，ThinKV以3.5-bit平均精度在LiveCodeBench上达到45.84，显著优于KIVI的34.56和PM-KVQ的41.97，且接近Baseline的40.00（注：此处Baseline LiveCodeBench为40.00，ThinKV 45.84高于Baseline，表明压缩策略可能通过正则化效应提升了特定任务表现，或Baseline数据存在波动，需结合原文Figure 2理解）。

| 组件 | 平均精度/预算 | LiveCodeBench准确率 |
| :--- | :--- | :--- |
| FullKV | – | 77.8 |
| TBQ | 3.5 / 1024 | 77.8 |
| **ThinKV (TBQ+TBE)** | 3.8 / 1024 | **76.4** |

消融实验显示，仅使用TBQ时准确率与FullKV持平（77.8），但生成长度膨胀抵消了压缩收益。引入TBE后，准确率微降至76.4，但实现了24倍压缩率（GSM8K场景），证明了驱逐策略在控制生成长度与内存占用上的关键作用。

评估边界方面，论文未报告置信区间，且仅在A100/GH200上验证。代码未开源，超参数（如$\tau=128$）固定，限制了跨硬件的可复现性。此外，思维类型定义依赖特定模型的注意力稀疏模式，跨架构泛化性未充分验证。

## 关联研究分析

从方法设计看，ThinKV与KIVI的核心差异在于量化精度的分配逻辑。KIVI基于Key/Value分布特性实施非对称量化，但精度对所有Token统一；ThinKV则引入思维维度，将精度分配与语义重要性绑定。这一差异源于LRM长输出场景中，Token重要性随推理轨迹动态变化，静态分布假设失效。ThinKV通过思维分解捕捉了这种动态性，但代价是引入了额外的分类开销，且依赖注意力稀疏度的三模态假设，该假设在部分层或模型中可能不成立。

从问题动机看，ThinKV与R-KV均针对LRM长输出，但R-KV聚焦于冗余感知驱逐，ThinKV则强调语义结构感知。R-KV的Token级驱逐虽灵活，但导致内存碎片和gather开销；ThinKV的思维段级驱逐虽牺牲了细粒度保留能力，但通过CT内核消除了系统开销。这种取舍反映了算法与系统协同设计的必要性，但思维段边界（$\tau=128$）的鲁棒性在极短或极长思维链中是否稳定，论文未给出明确回答。

## 总结

ThinKV旨在解决LRM长输出推理中KV缓存内存瓶颈与精度保持的矛盾。现有Token级方法因忽略推理语义结构，在高压缩率下精度崩塌，而ThinKV通过注意力稀疏度分解思维类型，实施自适应量化与驱逐，实现了语义感知的压缩。实验表明，在低于5%的KV缓存预算下，ThinKV在AIME和LiveCodeBench上保持了近乎无损的精度，吞吐量提升5.8倍。然而，其思维类型定义依赖特定模型的注意力模式，且$\tau=128$的刷新间隔固定，当推理轨迹变化频率显著偏离该假设时，分类误差是否会累积并导致关键推理步骤误删，论文未提供跨模型或动态$\tau$的验证数据。
