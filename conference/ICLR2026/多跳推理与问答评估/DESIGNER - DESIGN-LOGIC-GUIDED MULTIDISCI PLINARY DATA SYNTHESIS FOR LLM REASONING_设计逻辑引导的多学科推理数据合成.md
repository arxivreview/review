# ICLR2026最新论文 ｜DESIGNER: DESIGN-LOGIC-GUIDED MULTIDISCI PLINARY DATA SYNTHESIS FOR LLM REASONING ｜设计逻辑引导的多学科推理数据合成

研究机构：阿里巴巴集团、南京大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_66909785)

> 大语言模型在跨学科复杂推理上表现滞后，根源在于高质量、高难度、多学科的训练数据稀缺。现有合成方法要么受限于种子问题覆盖度，要么退化为简单事实回忆，缺乏对推理结构的有效控制。本文提出 DESIGNER，通过反向工程人类出题专家的“设计逻辑”（Design Logic），将其作为可复用的元知识指导从原始文本中生成复杂推理题。该方法在 Qwen3 和 Llama3 上验证了数据有效性，但依赖单一模型生成响应且未直接评估推理过程的忠实性，其长期泛化能力存疑。

## 研究背景

当模型面对大学级别的学科特定推理任务时，其性能瓶颈往往不在于参数规模，而在于训练数据中缺乏具备深层推理结构的样本。这种数据稀缺导致模型在数学和编程之外的领域表现薄弱，而现有的数据合成方法难以同时保证难度、多样性与学科广度。

多跳推理评估领域已确立静态基准的局限，指出模型常通过捷径学习而非真实逻辑推导得出答案。这一共识延伸至数据合成领域，即单纯基于文档或查询的生成方法无法控制推理路径的复杂性。主流路线分为查询中心（Query-centric）和文档中心（Document-centric）两类：前者通过重写种子问题扩展，受限于种子池覆盖度；后者从原始文档生成，虽事实基础扎实，但常退化为事实回忆，缺乏对推理深度的显式控制。本文切入点在于引入“设计逻辑”这一中间层，将人类出题的结构化思维过程形式化，从而在文档中心框架下实现难度与多样性的精确调控。

## 核心方法

### 方法参照系

本文问题属于文档中心数据合成路线，标准流程为“文档预处理-问题生成-质量过滤”。关键差异在于，传统方法直接由文档生成问题，缺乏对推理结构的显式约束；本文在生成前引入“设计逻辑提取与匹配”环节，将出题逻辑从数据中解耦，作为独立的可复用控制变量。

### 设计逻辑提取与去重

设计动机：解决文档中心方法无法控制推理深度和多样性的问题，避免生成简单事实题。
从数亿题库中，利用 LLM 反向工程提取出题者的思维过程，抽象为 Mermaid 格式的结构化逻辑。为消除冗余，采用基于语义相似度的图连通分量去重算法。设逻辑嵌入向量为 $\mathbf{e}_i$，相似度矩阵 $S_{ij} = \cos(\mathbf{e}_i, \mathbf{e}_j)$，构建图 $G=(V,E)$，其中边 $E$ 连接 $S_{ij} \ge \tau$ 的节点。保留每个连通分量中相似度总和最高的节点，最终得到 125,328 个唯一设计逻辑。该公式确保了逻辑库在语义空间中的最大分散性，为后续生成提供多样化的推理骨架。

### 两阶段检索-生成机制

设计动机：避免逻辑与文本的笛卡尔积爆炸，同时确保生成的问题严格遵循特定推理结构。
对于每个文本片段 $t$，首先通过向量相似度检索 Top-5 候选逻辑 $d$，计算 $s(t, d) = \cos(\mathbf{e}(t), \mathbf{e}(d))$。随后，LLM 对候选逻辑进行细粒度评估，选择最优逻辑并严格遵循其步骤生成问题及参考答案。这一粗到细的排序机制将检索召回与逻辑对齐解耦，前者保证候选覆盖，后者确保生成质量。相比直接提示生成，该机制显著提升了问题的推理深度，使 DLR-Book 和 DLR-Web 中“极难”题目比例远高于基线数据集。

## 实验评估

实验在 Qwen3 和 Llama3 系列模型上进行 SFT，对比官方最终模型及基线合成数据集。基线包括 OpenThoughts3、NaturalReasoning 等，覆盖了查询中心和文档中心主要路线，但缺失了基于强化学习（RLVR）的最新方法对比。

| 模型 | MMLU Accuracy | GPQA-Diamond CoT-SC | SuperGPQA Accuracy |
| :--- | :--- | :--- | :--- |
| Qwen3-8B (Thinking Mode) | 85.85 | 59.44 ± 2.53 | 47.52 |
| Qwen3-8B-SFT (DLR-Web+Book) | 87.60 | 71.01 ± 2.33 | 50.90 |
| Llama-3.1-8B-Instruct | 70.86 | 23.18 ± 1.78 | 20.08 |
| Llama-3.1-8B-SFT (DLR-Web+Book) | 84.13 | 65.45 ± 1.47 | 45.06 |

SFT 后的基础模型在 GPQA-Diamond 上显著超越官方最终模型，例如 Qwen3-8B-SFT 达到 71.01%，较官方版本提升 11.57 个百分点。这表明合成数据有效增强了通用推理能力，而非过拟合特定基准。

| 方法 | MMLU Accuracy | GPQA-Diamond CoT-SC |
| :--- | :--- | :--- |
| DESIGNER (Full) | 87.53 | 69.39 ± 1.87 |
| w/o Design Logic | 86.51 | 64.10 ± 2.81 |
| w/o Coarse Ranking | 86.29 | 58.74 ± 0.75 |

消融实验显示，移除设计逻辑导致 GPQA-Diamond 性能下降 5.29 个百分点，验证了逻辑结构对推理深度的关键作用。移除粗粒度检索阶段的影响较小，暗示细粒度 LLM 评估在逻辑匹配中起主导作用，粗粒度检索主要起候选过滤作用。

评估边界方面，论文未报告计算效率指标，且依赖 Qwen3-235B 生成响应，未验证响应本身的推理忠实性。代码与数据虽提供项目页面，但完整复现需依赖特定 LLM 版本，存在环境依赖风险。

## 关联研究分析

从问题动机看，DESIGNER 与 NaturalReasoning 同属文档中心路线，但后者依赖单一提示模板，导致多样性受限；DESIGNER 通过引入外部逻辑库，将多样性控制从提示工程转移至逻辑结构匹配，根源在于对“推理结构”的显式建模。从方法设计看，DESIGNER 与 CRAFT 均强调过程可控，但 CRAFT 聚焦于推理轨迹的忠实性验证，而 DESIGNER 聚焦于问题生成的逻辑结构约束。两者共同指向“过程可控”的目标，但 DESIGNER 未涉及推理过程的评估，仅保证问题的复杂性，这可能导致模型在训练中学会“解题套路”而非真实推理。

## 总结

DESIGNER 旨在解决多学科推理数据稀缺且缺乏结构控制的问题，通过形式化人类出题逻辑，实现了难度与多样性的精确调控。实验证明，基于该数据 SFT 的模型在 GPQA-Diamond 上超越官方最终模型，验证了数据的有效性。然而，论文未评估生成响应的推理忠实性，且依赖单一模型生成答案，可能引入不忠实推理。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
