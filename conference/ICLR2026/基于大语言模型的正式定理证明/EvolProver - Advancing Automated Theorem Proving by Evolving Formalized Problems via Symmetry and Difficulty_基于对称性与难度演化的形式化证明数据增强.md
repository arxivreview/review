# ICLR2026最新论文 ｜EvolProver: Advancing Automated Theorem Proving by Evolving Formalized Problems via Symmetry and Difficulty ｜基于对称性与难度演化的形式化证明数据增强

研究机构：香港浸会大学、复旦大学

作者：Yuchen Tian、Ruiyuan Huang、Xuanwu Wang 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.00732)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.00732)

> 形式化定理证明的核心瓶颈在于高质量训练数据的极度稀缺与模型对微小扰动的高敏感性。现有合成数据方法虽能扩充规模，但往往引入语义错误，且未显式建模数学问题的内在对称结构，导致模型泛化能力受限。本文提出 EvolProver，通过结合抽象语法树（AST）确定性变换与大语言模型（LLM）演化指令，从对称性与难度两个维度系统增强形式化数据。该方法在 7B 非推理模型上实现了多项基准的 SOTA，但其性能上限仍受限于非推理架构，与智能体框架存在显著差距。

## 研究背景

形式化证明要求代码级的严格逻辑验证，这一特性使得自然语言推理无法替代机器验证，确立了 Lean 等交互式定理证明器（ITP）作为正确性唯一标准的范式边界。然而，形式化证明的编写依赖深厚的领域专家知识，导致高质量训练数据极度稀缺，这与大语言模型（LLM）依赖海量数据的训练范式形成根本冲突。为缓解数据稀缺，研究者引入了数据合成方法，如 DeepSeek-Prover 通过自动翻译非形式化问题生成形式化陈述，STP 则采用猜想者-证明者对抗生成新数据。

尽管合成数据扩充了训练规模，但现有模型仍表现出严重的脆弱性。研究表明，对问题陈述进行微小的代数重写或变量替换，会导致 LLM 的证明成功率剧烈波动，这表明模型未能学习到数学问题的底层对称结构。此外，单一难度分布的数据集容易使模型依赖捷径或记忆，而非掌握通用的推理策略。本文的切入点在于，通过显式建模数学问题的语法对称性、语义对称性及难度梯度，构建一个鲁棒的数据增强流水线，以解决模型泛化性不足的核心问题。

## 核心方法

### 数据增强参照系

现有数据合成方法主要依赖 LLM 进行非形式化问题的翻译或自博弈生成，其核心假设是 LLM 能够保持语义一致性。然而，LLM 的生成过程具有非确定性，不可避免地引入语法或语义错误。本文的关键差异在于引入确定性约束，将数据增强分解为基于逻辑等价性的确定性变换与基于 LLM 的创造性演化两个互补阶段，确保生成数据的语义正确性。

### 基于 AST 的语法对称性增强

针对 LLM 生成数据中常见的语法错误问题，本文提出 EvolAST，利用 Lean 4 的抽象语法树（AST）进行确定性重写。该方法将形式化陈述解析为 AST，并应用一组基于公理和定理的逻辑等价变换规则 $R = \{r_1, ..., r_7\}$，包括假设重排、交换律、结合律等。给定输入陈述 $S_i$ 和概率参数 $p$，变换过程定义为：

$$ A(S_i, p) = S'_i $$

其中 $A$ 递归遍历 AST 节点，以概率 $p$ 应用适用规则 $r_k$。这一设计消除了对 LLM 语义判断的依赖，保证了生成数据在语义上与原陈述严格等价，同时增加了语法多样性，解决了纯 LLM 生成中语义漂移导致的训练噪声问题。

### 基于 LLM 的语义与难度演化

在语法正确性得到保证的基础上，本文通过 LLM 进一步扩展数据的语义空间与难度分布。EvolDomain 通过抽象逻辑骨架并在不同数学域中实例化，实现语义对称性增强；EvolDifficulty 则通过五种演化策略（如调整逻辑结构、数学深度等）控制难度梯度。演化过程定义为函数 $F$ 和 $E$：

$$ F(S_i, D_m) = (S'_i, P'_i), \quad E(S_i, s_k, \delta) = (S'_i, P'_i) $$

其中 $D_m$ 为目标域，$s_k$ 为演化策略，$\delta$ 为难度方向。这种混合架构利用 LLM 的创造性生成新命题，同时通过 Lean 4 编译器验证和 LLM 裁判进行双重过滤，确保数据质量。该设计弥补了 EvolAST 仅能生成等价变体、无法探索新数学结构的局限，构建了从语法到语义、从简单到复杂的完整数据增强闭环。

## 实验评估

EvolProver 在 FormalMATH-Lite、MiniF2F-Test 和 Ineq-Comp 三个基准上进行了评估，基线覆盖了推理模型（如 DeepSeek-Prover-V2）、非推理模型（如 STP）和树搜索模型（如 BFS-Prover）。实验设置采用 pass@32 指标，以评估模型在多次采样下的成功率。

| 模型 | 类型 | FormalMATH-Lite (%) | MiniF2F-Test (%) | Ineq-Comp Ratio (%) |
| :--- | :--- | :--- | :--- | :--- |
| DeepSeek-Prover-V2 (CoT) | 推理 | 51.76 | - | 67.23 |
| STP | 非推理 | 48.59 | - | 36.12 |
| EvolProver-Base | 非推理 | 44.71 | 52.05 | 34.43 |
| **EvolProver** | **非推理** | **53.86** | **69.80** | **65.17** |

EvolProver 在 FormalMATH-Lite 上以 53.86% 的准确率超越所有同尺寸模型，包括推理模型 DeepSeek-Prover-V2 的 51.76%。在 Ineq-Comp 基准上，其鲁棒性比率（Pass Ratio）达到 65.17%，较基线 EvolProver-Base 提升 30.61 个百分点，显著优于非推理模型 STP 的 36.12%，表明数据增强有效提升了模型对扰动的鲁棒性。

消融实验显示，EvolAST、EvolDomain 和 EvolDifficulty 均对性能有正向贡献。其中，引入 EvolAST 后，Ineq-Comp 的 Transformed 准确率从 29.19% 提升至 30.35%，而完整流水线进一步将其提升至 34.02%。这表明语法对称性增强对鲁棒性的贡献相对有限，主要收益来自语义与难度的演化。然而，EvolProver 在 MiniF2F-Test 上的 69.80% 仍低于智能体框架 Hilbert 的 99.2%（据领域综述），揭示了非推理架构在复杂长程推理上的固有局限。

评估边界方面，论文未报告置信区间，且部分基线（如树搜索模型）的 token 消耗不可比。代码未公开，但提供了详细的提示模板和超参数设置，可复现性中等。

## 关联研究分析

从问题动机看，本文与 DeepSeek-Prover 系列工作均关注数据稀缺问题，但 DeepSeek-Prover 侧重于通过大规模翻译扩充数据规模，而本文聚焦于数据质量的鲁棒性。DeepSeek-Prover 的翻译过程依赖模型评分筛选，但未显式处理语法等价性，导致数据中可能存在语义噪声。本文通过 EvolAST 引入确定性约束，解决了这一盲区，但其代价是限制了语义空间的探索广度，因为 AST 变换仅生成等价变体，无法像 LLM 演化那样生成全新的数学结构。

从方法设计看，本文与 MetaMath 等非形式化数学数据增强方法共享“演化”思路，但 MetaMath 依赖 LLM 进行问题重写，缺乏形式化验证机制。本文将演化过程嵌入 Lean 4 环境，通过编译器验证确保语法正确性，这是形式化证明领域的特有约束。然而，本文未探索如何将 AST 增强扩展至推理链（CoT）层面，对于推理模型，语法对称性可能不足以解决长程依赖中的逻辑漂移问题，这一局限在本文的非推理模型设定下未被暴露。

## 总结

EvolProver 旨在解决形式化证明中数据稀缺与模型脆弱性的矛盾，其切入点在于通过 AST 确定性变换与 LLM 演化相结合，显式建模数学问题的对称性与难度梯度。该方法在 7B 非推理模型上实现了 FormalMATH-Lite 53.86% 和 Ineq-Comp Ratio 65.17% 的性能，证明了数据增强对鲁棒性的显著提升。然而，其性能上限受限于非推理架构，在 MiniF2F-Test 上仍落后于智能体框架，且 AST 变换的确定性约束可能限制了语义空间的探索广度。当支持集增大到研究级数学时，语法对称性增强是否足以弥补长程推理中的逻辑漂移，论文未给出回答。
