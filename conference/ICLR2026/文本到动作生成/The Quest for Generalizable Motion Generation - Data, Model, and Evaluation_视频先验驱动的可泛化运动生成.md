# ICLR2026最新论文 ｜The Quest for Generalizable Motion Generation: Data, Model, and Evaluation ｜视频先验驱动的可泛化运动生成

研究机构：新加坡南洋理工大学、商汤

作者：Jing Lin、Ruisi Wang、Junzhe Lu 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.26794)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.26794)

> 文本驱动人体运动生成（Text-to-Motion Generation, T2M）旨在从自然语言合成逼真且语义一致的人体动作，但现有模型在长尾指令下的泛化能力严重不足。传统方法受限于动作捕捉（MoCap）数据的语义覆盖狭窄，难以处理训练分布外的复杂动作。本文提出 ViMoGen，通过门控双分支架构将视频生成（ViGen）模型的语义先验迁移至运动扩散过程，并配套构建大规模多源数据集与细粒度基准。该框架在泛化性上显著超越基线，但揭示了视频先验与运动物理保真度之间的内在权衡，其长期有效性仍存疑。

## 研究背景

理解本文需厘清两个核心概念的张力：运动生成的物理保真度与语义泛化性。光学 MoCap 数据提供高精度的关节动力学，但受限于摄影棚场景，语义多样性极低；而视频生成模型在海量网络数据上训练，具备强大的动作语义理解能力，但其提取的运动信号存在抖动与幅度失真。这种“质量-泛化”的二元对立，构成了 T2M 领域长期未解的核心矛盾。

T2M 领域的主流路线分为连续扩散与离散自回归两类。扩散模型（如 MDM）在连续潜空间迭代去噪，保真度高但推理慢；自回归模型（如 T2M-GPT）将运动离散化为 Token，语义组合性强但存在累积误差。2024 年后，流匹配（Flow Matching）凭借更直的采样路径成为新范式，但现有工作仍主要依赖单一文本条件，未能有效利用视频模态中蕴含的海量动作先验。ViMoGen 的切入点在于：不将视频生成模型视为独立的数据源，而是将其作为“语义教师”，通过架构层面的门控机制，动态平衡视频先验的泛化优势与 MoCap 数据的物理可靠性。

## 核心方法

### 流匹配基础架构

ViMoGen 采用基于 SMPL-X 的 276 维过参数化表示，每帧包含根节点平移、旋转、关节位置及速度。模型使用整流流（Rectified Flow）建模生成过程，定义前向插值 $x_t = (1-t)\epsilon + tx_0$，其中 $\epsilon \sim \mathcal{N}(0, I)$，$t \in [0, 1]$。训练目标为预测速度场 $v_t = x_0 - \epsilon$，损失函数为 $\mathcal{L} = \mathbb{E}_{x_0, \epsilon, t, c} [\|f_\theta(x_t, t, c) - v_t\|^2]$。该设计继承自连续归一化流理论，相比传统扩散模型，其采样路径更直，训练更稳定，为后续引入复杂多模态条件提供了高效的计算基础。

### 双分支门控融合机制

针对单一文本条件无法覆盖长尾动作的问题，ViMoGen 引入双分支交叉注意力结构。每个 DiT 块包含自注意力层及两个互斥的交叉注意力分支：T2M 分支与 M2M 分支。T2M 分支使运动 Token 直接关注文本嵌入 $z_{text}$，利用 MoCap 数据学习物理合理的动力学；M2M 分支使运动 Token 关注视频运动 Token $z_{video}$，迁移视频模型的语义知识。两分支共享约 66% 的参数（自注意力与 FFN 层），仅在交叉注意力处分离。门控机制 $\mathcal{G}(z_{text}, z_{video})$ 根据文本与视频运动的语义对齐程度，动态选择激活分支。若对齐度高，激活 M2M 以利用视频先验；若对齐度低（如视频生成失真），则回退至 T2M 以保证物理稳定性。这一设计解决了现有方法中视频先验噪声直接污染运动生成的问题，实现了“泛化”与“保真”的自适应平衡。

### 训练时域差距模拟

推理时需离线生成视频并提取运动，计算开销巨大。为消除训练与推理的域差距，ViMoGen 在训练时不依赖在线视频生成，而是对真实 MoCap 运动施加复合噪声策略（随机损坏、抖动模拟、时间丢弃），模拟视觉 MoCap 的伪影，生成伪 $z_{video}$。同时，掩码全局平移，强制 M2M 分支仅依赖局部姿态动力学。这一策略使得模型在训练阶段即可学习从含噪视频先验中恢复高质量运动的能力，避免了推理时昂贵的视频生成依赖，为轻量级变体 ViMoGen-light 的知识蒸馏奠定了基础。

## 实验评估

ViMoGen 在自建 MBench 基准上与 MDM、T2M-GPT、MoMask 等 SOTA 方法对比。MBench 包含 9 个维度，涵盖运动质量、条件一致性与泛化性。

| 方法 | Motion Condition Consistency | Motion Generalizability | Jitter Degree | Foot Sliding |
| :--- | :--- | :--- | :--- | :--- |
| Video Generation Baseline | 0.51 | 0.58 | 0.0193 | 0.0161 |
| T2M Only | 0.46 | 0.54 | 0.0111 | **0.0039** |
| M2M Only | 0.51 | 0.59 | 0.0145 | 0.0113 |
| **ViMoGen (Adaptive)** | **0.53** | **0.68** | **0.0108** | 0.0064 |

ViMoGen 在泛化性（0.68）与条件一致性（0.53）上均显著优于所有基线，其中泛化性比最强基线高出 0.10。然而，其脚部滑动指标（0.0064）劣于纯 T2M 模型（0.0039），表明视频先验的引入虽提升了语义覆盖，但牺牲了部分物理细节的稳定性。

消融实验揭示了数据源与文本编码器的关键影响。

| 训练数据组成 | Clip Number | Motion Generalizability | Foot Sliding |
| :--- | :--- | :--- | :--- |
| HumanML3D | 89k | 0.44 | **0.0032** |
| + Other Optical Mocap | 83k | 0.48 | 0.0033 |
| + Visual Mocap | 42k | 0.50 | 0.0042 |
| + Synthetic Video | 14k | **0.55** | 0.0051 |

仅增加 14k 合成视频数据，泛化性从 0.50 提升至 0.55，证明语义多样性比数据规模更关键。文本编码器方面，T5-XXL 在泛化性（0.44）与身体穿透（1.05）上优于 CLIP（0.35/1.39）和 MLLM（0.46/1.51），表明强大的语言模型对长尾指令的理解至关重要。

评估边界方面，MBench 虽经人工验证，但缺乏与 HumanML3D 标准指标（如 FID、R-Precision）的直接映射关系，限制了跨基准的可比性。代码与数据声明将公开，但训练依赖内部大规模视频数据库，外部复现难度较高。

## 关联研究分析

从问题动机看，ViMoGen 与 HY-Motion 均致力于解决泛化瓶颈，但路径截然不同。HY-Motion 依赖大规模 MoCap 数据的“先规模后精炼”策略，通过数据量堆叠提升泛化；而 ViMoGen 认为 MoCap 数据存在语义天花板，转而引入视频模态作为语义补充。这一差异源于对“数据瓶颈”的不同诊断：前者认为是数据量不足，后者认为是语义多样性不足。ViMoGen 的实验证明，少量高多样性合成数据（14k）即可带来显著泛化增益，挑战了“数据规模决定上限”的传统共识，暗示在 T2M 领域，数据质量的语义覆盖度可能比绝对数量更具决定性。

从方法设计看，ViMoGen 与 MoLingo 同属 Flow Matching 路线，但条件注入方式存在本质差异。MoLingo 采用语义对齐的运动编码器与整流流输出头，在连续域进行自回归生成，强调运动与文本的深层对齐；ViMoGen 则采用双分支门控，将视频运动 Token 作为独立条件分支，强调跨模态先验的自适应融合。MoLingo 的单一连续路径难以处理视频先验中的噪声伪影，而 ViMoGen 的门控机制允许模型在视频先验不可靠时回退至文本条件，这种“容错”设计是其在长尾动作上表现更优的关键。然而，ViMoGen 对视频生成模型的依赖引入了额外的计算开销与误差传播风险，这在 MoLingo 的纯文本-运动框架中是不存在的。

## 总结

ViMoGen 旨在解决 T2M 领域中运动物理保真度与语义泛化性难以兼得的核心矛盾。现有方法受限于 MoCap 数据的语义狭窄或视频先验的物理失真，无法在长尾指令下保持高质量生成。ViMoGen 通过门控双分支架构，动态平衡视频语义先验与 MoCap 动力学，并配套构建多源数据集与细粒度基准。实验显示，其在 MBench 泛化性指标上达到 0.68，显著优于基线，但脚部滑动指标（0.0064）劣于纯文本模型（0.0039），暴露了视频先验引入的物理代价。当视频生成模型在复杂动态动作（如体操翻转）中产生严重失真时，门控机制能否完全抑制噪声传播并恢复物理合理性，论文未给出充分验证。
