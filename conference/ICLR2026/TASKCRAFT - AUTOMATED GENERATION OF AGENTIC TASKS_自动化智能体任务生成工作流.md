# ICLR2026最新论文 ｜TASKCRAFT: AUTOMATED GENERATION OF AGENTIC TASKS ｜自动化智能体任务生成工作流

研究机构：北京航空航天大学、南京大学

作者：Dingfeng Shi、Jingyi Cao、Qianben Chen 等 17 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_41239338)

> 深度研究智能体（DRA）的训练依赖高质量、具备真实工具依赖性的多步任务数据，但现有基准如 GAIA 和 BrowseComp 受限于高昂的人工标注成本，难以规模化扩展。Self-Instruct 等静态指令生成方法无法建模动态工具交互，导致训练数据与真实智能体场景脱节。TaskCraft 通过“原子任务生成 + 深度/宽度扩展 + 增量验证”的结构化工作流，自动化生成 41k 可验证的多工具任务。该工作解决了数据瓶颈这一基础设施问题，但其生成任务与测试集分布的重叠性、以及小模型在数据增强下的性能上限，仍存疑。

## 研究背景

智能体任务的核心在于通过 Thought–Action–Observation (TAO) 范式实现长程推理，其中工具执行涉及定位输入索引 $i_T$ 并在其上操作工具 $T$ 以获取上下文 $C$，进而应用关系 $R$ 推导答案 $a$。这一过程要求任务必须依赖外部工具才能解决，而非仅靠语言模型（LLM）的参数化知识。然而，现有基准如 GAIA（466 题）和 Humanity’s Last Exam (HLE)（2,500 题）依赖大量专家标注，HLE 构建需 1,000 名专家标注 2,500 个样本，导致大规模扩展在工程上不可行。

主流数据合成路线如 Self-Instruct 和 WizardLM 聚焦于静态指令跟随，通过规则或 LLM 重写生成多样化指令，但缺乏对动态环境交互的建模，生成的任务无法触发真实的工具调用链。这导致基于此类数据训练的智能体在需要多步工具执行的场景中表现受限。TaskCraft 的切入点在于将任务生成本身视为一个智能体工作流，通过结构化扩展机制自动化构建具备真实工具依赖性的任务，从而突破人工标注的成本瓶颈，为监督微调（SFT）和强化学习（RL）提供可扩展的训练数据源。

## 核心方法

### 任务抽象与原子任务生成

智能体任务可最小化定义为输入索引 $i_T$ 与工具执行上下文上的关系 $R$ 的组合，即 $q = f_q(i_T, R)$。原子任务生成从非标注语料中提取 $i_T$，通过工具执行获取上下文 $C$，由 LLM 识别候选答案 $a$ 并推断其与 $C$ 的关系 $R$，最终构造问题 $q$。这一设计动机在于解决直接提示 LLM 生成任务时工具调用率低、难度不可控的问题，通过显式绑定 $i_T$ 和 $R$ 确保任务必须通过工具执行才能求解。

### 深度与宽度扩展机制

在原子任务基础上，TaskCraft 通过深度扩展和宽度扩展增加任务复杂度。深度扩展构建多跳任务，其中第 $n+1$ 跳的输入索引 $i_T^{[n]+1}$ 是第 $n$ 跳索引 $i_T^{[n]}$ 的超集，通过搜索智能体识别超集并推断关系 $R^{[n]+1}$，递归定义任务：

$$ q^{[n]+1} = f_m(q^{[n]}, \hat{q}^{[n]+1}, i_T^{[n]}) $$

其中 $f_m$ 引导 LLM 将中间任务 $\hat{q}^{[n]+1}$ 合并到原任务中。宽度扩展则将两个子任务 $q_1 \to a_1$ 和 $q_2 \to a_2$ 合并为 $q_{width}$，要求智能体分解并并行解决。这一机制解决了单一原子任务难度不足、无法覆盖长程推理场景的问题，通过递归扩展实现任务难度的自适应提升。

### 增量验证与拒绝采样

任务验证分为原子任务验证和扩展验证。原子任务验证通过智能体执行与推理 LLM 对比，仅保留智能体成功但 LLM 失败的任务，验证工具必要性。扩展验证仅通过 LLM 语言分析检查增量部分，避免全量执行。这一设计动机在于降低验证成本，同时确保任务质量。拒绝采样机制保留了真正需要工具的任务，过滤掉可被 LLM 直接回答的简单任务，确保训练数据的有效性。

## 实验评估

实验在 GAIA、WebWalker、BrowseComp 和 HLE 四个基准上评估，基线包括 R1-Searcher、WebSailor、Search-o1 等 SFT/RL 混合训练模型。TaskCraft 数据在 Qwen-2.5-32B-Instruct 上，5k MHQA + 2.5k TaskCraft (SFT) + 8k TaskCraft (RL) 组合在 GAIA 上达到 60.8%，BrowseComp 上达到 24.8%，超越多数基线。

| 方法 | SFT | RL | GAIA (%) | BrowseComp (%) |
| :--- | :--- | :--- | :--- | :--- |
| 5k MHQA | ✓ | | 38.8 | 5.6 |
| 7.5k TaskCraft | ✓ | | 60.2 | 22.4 |
| 5k MHQA + 2.5k TaskCraft (SFT) + 8k TaskCraft (RL) | ✓ | ✓ | 60.8 | 24.8 |

消融实验显示，原子任务生成中引入 $i_T$ 和 $R$ 结构后，通过率从 18.5% 提升至 43.0%，时间从 119.7s 降至 86.7s，工具调用次数从 2.8 降至 2.1，方差从 1.2 降至 0.4。这表明结构化任务生成显著提升了采样效率和任务一致性。

评估边界方面，论文未报告置信区间，且 GAIA 高分可能源于数据分布与测试集重叠。代码已开源，但超参数和 GPU 资源未详细说明，可复现性受限。

## 关联研究分析

从问题动机看，TaskCraft 与 Self-Instruct 同属数据合成路线，但 Self-Instruct 聚焦静态指令，而 TaskCraft 通过工具执行和增量验证建模动态交互。这一差异源于任务特性：智能体任务需要真实环境反馈，静态指令无法提供工具依赖性的验证信号。TaskCraft 的拒绝采样机制确保了任务必须通过工具才能解决，这是 Self-Instruct 无法实现的。

从方法设计看，TaskCraft 与 ASearcher 同属 RL 训练路线，但 ASearcher 依赖大规模端到端 RL 优化策略，而 TaskCraft 聚焦数据生成，通过 SFT/RL 混合训练提升模型性能。这一差异源于研究目标：ASearcher 解决策略优化问题，TaskCraft 解决数据瓶颈问题。TaskCraft 的数据可支持类似 ASearcher 的 RL 训练，形成数据-模型闭环，但论文未探索纯 RL 场景下的数据效率。

## 总结

TaskCraft 解决了智能体训练数据规模化生成的核心矛盾，通过结构化工作流自动化构建具备真实工具依赖性的任务，突破了人工标注的成本瓶颈。其切入点在于将任务生成视为智能体工作流，通过深度/宽度扩展和增量验证实现任务复杂度的可控提升。实验证明，TaskCraft 数据在 Qwen-2.5-32B 上使 GAIA 性能从 38.8% 提升至 60.8%，BrowseComp 从 5.6% 提升至 24.8%。然而，论文未验证生成任务与测试集分布的重叠性，且小模型（7B）在 TaskCraft 数据下的性能上限未明确。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
