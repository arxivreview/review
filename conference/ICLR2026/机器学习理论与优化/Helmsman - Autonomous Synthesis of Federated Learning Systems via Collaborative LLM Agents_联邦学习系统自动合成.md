# ICLR2026最新论文 ｜Helmsman: Autonomous Synthesis of Federated Learning Systems via Collaborative LLM Agents ｜联邦学习系统自动合成

研究机构：荷兰埃因霍温理工大学

作者：Haoyuan Li、Mathias Funk、Aaqib Saeed

论文原文见 [arXiv](https://arxiv.org/abs/2510.14512)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.14512)

> 联邦学习（Federated Learning, FL）的部署面临策略组合爆炸与静态方案脆弱性的双重困境，传统人工设计无法应对动态异构环境。现有单智能体代码生成框架缺乏处理分布式系统级复杂度的能力，本文切入点在于利用多智能体协作模拟人类研发流程。Helmsman 通过交互式规划、模块化编码与沙箱评估闭环，将高层需求转化为可部署的 FL 代码。该框架在持续学习等复杂任务上超越手工基线，但其性能依赖特定 LLM 组合且缺乏理论收敛保证。

## 研究背景

联邦学习系统的设计本质是一个高维组合优化问题。当客户端数据呈现非独立同分布（Non-IID）特性时，模型收敛困难，需引入近端项或控制变量；同时，边缘设备的计算资源异构性要求动态调整训练策略。这些约束并非孤立存在，而是相互耦合：通信压缩可能放大统计异构性带来的漂移，资源限制又制约了复杂聚合算法的部署。理解这一耦合关系，需要掌握 FL 中“统计异构性”与“系统异构性”的交互机制，以及多智能体系统（Multi-Agent System, MAS）中“分工协作”对复杂任务求解的增益原理。

FL 领域长期存在“点状解决方案”与“系统级部署”之间的鸿沟。主流研究如 FedProx 和 SCAFFOLD 针对特定挑战（如客户端漂移）提供了有效算法，但这些方案难以组合，且在动态环境中表现脆弱。现有自动化代码生成框架（如 ReAct）虽能处理自包含编程任务，但无法同时推理算法权衡、资源约束与通信协议。Helmsman 针对这一空白，提出将 FL 系统设计分解为规划、编码、评估三个协作阶段，利用 LLM 多智能体团队实现端到端自动化。

## 核心方法

### 方法参照系

通用代码生成 Agent 通常采用单智能体架构，通过 Chain-of-Thought 或 ReAct 提示技术解决独立编程任务。本文问题的关键差异在于 FL 系统的多组件依赖性：数据加载、客户端训练、服务器聚合等模块需协同工作，单一 Agent 难以同时维护全局一致性与局部正确性，且缺乏针对分布式运行时错误的反馈机制。

### 模块化协同编码

传统代码生成缺乏对分布式系统模块依赖关系的显式管理。Helmsman 引入 Supervisor Agent 执行“关注点分离”原则，将计划分解为任务、客户端、策略、服务器四个独立模块。Supervisor 构建依赖图，确保服务器模块仅在策略与任务模块稳定后启动。每个模块由 Coder Agent 与 Tester Agent 组成团队，通过内部编码-测试循环保证模块级正确性。该设计解决了单 Agent 在处理长上下文时容易忽略模块间接口兼容性的问题，通过物理隔离降低集成失败概率。

$$
C_{final} = \text{Integrate}(M_{task}, M_{client}, M_{strategy}, M_{server})
$$

其中 $M_i$ 为各模块代码，Integrate 函数执行依赖检查与接口对齐，确保生成的代码库在结构上符合 FL 框架规范。

### 沙箱闭环评估

模块化编码仅保证语法正确，无法暴露运行时集成错误。Helmsman 引入基于 Flower 框架的沙箱模拟环境，执行 $N=5$ 轮联邦训练以生成日志 $L_i$。Evaluator Agent 执行分层诊断：L1 层扫描 Python 异常以识别崩溃，L2 层分析结构化输出以检测算法逻辑错误（如指标停滞、零参与）。若状态为 FAIL，Debugger Agent 接收错误报告 $E_i$ 并生成补丁 $C_{i+1}$。该闭环通过短跑模拟提供低成本、高信号的反馈，解决了传统静态分析无法捕捉动态行为缺陷的问题。

$$
(S_i, E_i) = f_{eval}(L_i, H), \quad C_{i+1} = f_{debug}(C_i, E_i) \quad \text{if } S_i = \text{FAIL}
$$

其中 $H$ 为预定义启发式规则集，$f_{eval}$ 与 $f_{debug}$ 分别为评估与调试智能体函数，该迭代过程直至通过 L1 与 L2 验证或达到最大尝试次数 $T_{max}$。

## 实验评估

实验在 AgentFL-Bench 上进行，涵盖 16 个任务，包括数据异构、分布偏移、系统异构、通信效率、个性化、主动学习与持续学习。基线包括 FedAvg、FedProx 及特定优化方法（如 FedNova、FedWeIT）。Helmsman 使用 Gemini-2.5-flash 进行规划，Claude-Sonnet-4.0 进行编码与评估。

| 任务 ID | 数据集 | 挑战 | FedAvg | FedProx | 特定方法 | Helmsman |
|---|---|---|---|---|---|---|
| Q1 | CIFAR-10-LT | 数量偏斜 | 70.08±0.52 | 69.65±0.42 | 78.96±0.41 | 76.71±0.43 |
| Q5 | HAR | 用户异构 | 94.84±0.44 | 95.22±0.32 | 95.19±0.75 | **96.28**±0.42 |
| Q10 | CIFAR-100 | 带宽限制 | 41.77±0.79 | 45.21±0.61 | 45.77±0.39 | **48.78**±0.29 |
| Q16 | Split-CIFAR100 | 增量任务 | 15.38±0.97 | 15.86±0.65 | 29.45±0.72 | **50.95**±1.09 |

在 Q16 持续学习任务中，Helmsman 生成的策略（客户端经验回放结合全局模型蒸馏）以 51.04% 的准确率和 0.07 的遗忘度显著优于 FedWeIT 的 21.74% 与 0.46，表明其在复杂时序任务上的组合创新能力。

| 配置 | 成功率 | 平均成本 ($) |
|---|---|---|
| Single ReAct Agent | 0% | 1.75 |
| Helmsman (w/o Collab. Coding) | 28.57% | 2.11 |
| Helmsman (Full System w/o HITL) | 100% | 1.14 |
| Helmsman (Full System) | 100% | 0.98 |

消融实验显示，移除协同编码模块导致成功率从 100% 降至 28.57%，证明模块化分工是解决系统级复杂度的关键。移除双层验证则导致成功率归零，凸显沙箱闭环对集成错误的必要性。完全自动化（无 HITL）与完整系统成功率相同，但成本略高，表明 HITL 主要优化资源而非成功率。

评估边界方面，实验仅在仿真环境进行，未验证真实硬件上的鲁棒性。指标仅包含准确率与遗忘度，缺乏通信轮次、能量消耗等系统级指标。代码未公开，超参数（如 $T_{max}$、LLM 版本）未详细披露，限制了可复现性。

## 关联研究分析

从问题动机看，Helmsman 与 Flower Hub 等仿真基准平台形成互补。Flower Hub 提供标准化评估环境，但依赖人工配置算法；Helmsman 则自动化配置过程，但依赖 Flower 作为执行引擎。差异根源在于任务目标：前者关注算法公平对比，后者关注系统生成效率。Helmsman 未引用 SCAFFOLD 等控制变量方法作为基线，可能因其策略生成机制更倾向于组合简单算法（如 FedAvg+Replay），而非引入复杂优化器。

从方法设计看，Helmsman 与通用代码生成框架 ReAct 存在架构差异。ReAct 采用单智能体推理-行动循环，适合自包含任务；Helmsman 采用 Supervisor 管理的多智能体团队，适合分布式系统。差异根源在于任务复杂度：FL 系统涉及多模块依赖与运行时状态，单智能体难以维护全局一致性。Helmsman 引入的 L2 语义验证是 ReAct 所缺乏的，这解决了静态代码检查无法捕捉算法逻辑错误的问题。

## 总结

Helmsman 旨在解决 FL 系统设计空间爆炸与静态方案脆弱性的矛盾，通过多智能体协作模拟人类研发流程，将高层需求转化为可部署代码。其在 Q16 持续学习任务上以 51.04% 准确率超越 FedWeIT，验证了自动组合策略的有效性。然而，实验仅在仿真环境进行，且缺乏通信与能量指标，限制了其在真实边缘部署中的适用性评估。当客户端数量增加至千级时，沙箱模拟的 5 轮短跑是否仍能充分暴露大规模并发下的集成错误，论文未给出回答。
