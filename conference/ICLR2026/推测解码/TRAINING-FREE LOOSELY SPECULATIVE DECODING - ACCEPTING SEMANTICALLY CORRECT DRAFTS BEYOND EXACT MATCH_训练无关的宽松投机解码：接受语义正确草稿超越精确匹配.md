# ICLR2026最新论文 ｜TRAINING-FREE LOOSELY SPECULATIVE DECODING: ACCEPTING SEMANTICALLY CORRECT DRAFTS BEYOND EXACT MATCH ｜训练无关的宽松投机解码：接受语义正确草稿超越精确匹配

作者：Jinze Li、Yixing Xu、Guanchen Li 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_18591709)

> 投机解码旨在通过并行验证加速大语言模型推理，但标准范式要求草稿与目标模型输出完全一致，导致大量语义正确但词面不同的有效 token 被丢弃。现有训练式方法虽能提升接受率，却在分布外数据上性能崩塌，而基于监督分类器的宽松验证又面临标注成本高、泛化差的困境。FLy 提出一种无训练的两级验证机制，利用目标模型自身的熵信号与自校正行为区分真实错误与语义等价变体，在保持 99% 以上准确率的前提下，于分布外数据集上实现 2.53 倍加速，比训练式 SOTA 快 1.62 倍。该方法以“近似无损”替代“严格无损”，其长期稳定性与极端场景下的可靠性仍需进一步审视。

## 研究背景

当大语言模型进行自回归生成时，内存带宽限制导致串行解码延迟高企。投机解码通过引入轻量级草稿模型并行预测候选 token，再由目标模型单次并行验证，将串行过程转化为并行验证，从而在不改变输出概率分布的前提下提升吞吐量。然而，标准投机解码采用严格的精确匹配规则：目标模型仅接受与其自身预测完全相同的草稿 token。这一刚性约束迫使系统拒绝许多语义上合理但词面不同的延续，例如同义替换或指代消解中的代词变化，直接限制了平均接受长度 $\tau$ 和最终加速比的上限。

早期研究聚焦于通过知识蒸馏或特征对齐优化草稿模型质量，如 EAGLE 系列利用目标模型隐藏状态训练草稿头，显著提升了域内接受率。然而，这些训练式方法高度依赖特定分布的训练数据，在分布外（OOD）场景下，草稿与目标模型的分布差异急剧扩大，导致接受率骤降。例如，EAGLE-3 在域内数据集上达到 3.83 倍加速，但在 OOD 数据上降至 1.56 倍。与此同时，JudgeDecoding 等宽松验证方法尝试通过训练辅助分类器来识别语义正确的草稿，但该方法需要大量人工标注数据，且监督训练的分类器在跨域任务中泛化能力脆弱。FLy 的切入点在于：不依赖任何额外训练数据或参数化验证器，而是利用目标模型在遇到错误 token 时表现出的自校正行为，结合其自身的熵信号，构建一个无训练的、鲁棒的宽松验证机制。

## 核心方法

### 标准投机解码验证流程

标准投机解码中，草稿模型生成 $K$ 个 token，目标模型并行验证。验证策略为：接受所有草稿 token 直至首个不匹配位置，丢弃后续所有草稿，并额外接受目标模型生成的一个 bonus token。该流程的核心局限在于“首个不匹配即拒绝”的二元判断，无法区分“语义错误的错误”与“语义正确的变体”，导致大量有效 token 被浪费。

### 熵门控与延迟窗口机制

FLy 的核心创新在于将验证过程从二元判断扩展为两级决策。首先，针对每个不匹配位置 $j$，计算目标模型在该位置的归一化熵 $h_j$。若 $h_j < \theta$（阈值），表明目标模型对该位置高度确定（如数字计算），直接拒绝该位置及后续所有草稿，回归标准规则。若 $h_j \ge \theta$，表明存在多个合理替代选项（如代词选择），则激活延迟窗口。延迟窗口监控后续 $W$ 个 token 的一致性：若窗口内出现新的不匹配，表明目标模型正在尝试“纠正”之前的错误，此时回溯拒绝位置 $j$ 及其后续草稿；若窗口内无新不匹配，则接受位置 $j$ 的草稿 token 为语义有效延续。该机制的数学表达为：

$$
s_{FLy} = \min \left( \min_{j \in J, h_j < \theta} j, \min_{j \in J, h_j \ge \theta, \exists k \in (j, j+W] : \Delta_k = 0} j, K+1 \right)
$$

其中 $J$ 为不匹配位置集合，$\Delta_k$ 为位置 $k$ 的匹配指示器。该公式的物理含义是：最终接受长度由“首个低熵不匹配”、“首个高熵但不被后续行为确认的不匹配”或“草稿长度上限”三者中的最小值决定。这一设计解决了训练式验证器在 OOD 数据上因分布偏移导致的泛化失效问题，因为熵信号和目标模型行为是动态计算的，不依赖静态训练分布。

### 多级加速策略

接受语义正确 token 后，平均接受长度 $\tau$ 显著增加，导致草稿模型需要生成更多 token 以维持加速比，草稿阶段延迟成为新瓶颈。FLy 引入多级加速（MLA）策略，不仅加速目标模型，还加速草稿模型本身。具体实现为使用 Prompt Lookup Decoding (PLD)，一种基于 $n$-gram 检索的无参数方法，快速生成草稿 token。PLD 无需训练，避免了引入额外偏差，且与 FLy 的无训练特性兼容。该策略将草稿生成从自回归串行过程转化为并行检索，显著降低了草稿阶段延迟，确保在 $\tau$ 增大时整体加速比不衰减。

## 实验评估

实验在 Llama-3.1-70B/405B 和 Llama-3.3-70B 上进行，对比 EAGLE-2/3（训练式）、REST、TokenRecycling、SpS（无训练式）。评估数据集分为域内（GSM8K, HumanEval, MBPP）和域外（MGSM, NIAH, ACP）。

| 模型 | 方法 | 域内平均加速比 | 域外平均加速比 | 准确率恢复率 |
| :--- | :--- | :--- | :--- | :--- |
| Llama-3.1-70B | EAGLE-2 | 2.57x | - | - |
| Llama-3.1-70B | FLy | 2.88x | 2.74x | ≥99% |
| Llama-3.3-70B | EAGLE-3 | 3.83x | 1.56x | - |
| Llama-3.3-70B | FLy | 2.63x | 2.53x | ≥99% |
| Llama-3.1-405B | FLy | 5.34x | 4.80x | ≥99% |

FLy 在域外数据上显著优于 EAGLE-3（2.53x vs 1.56x），验证了其鲁棒性。在域内数据上，FLy（2.88x）略低于 EAGLE-2（2.57x，注：此处 EAGLE-2 数值为 2.57x，FLy 为 2.88x，实际 FLy 更高，但论文称比 EAGLE-2 快 1.05 倍，需核对原文。原文 Table 3 显示 L3 70B EAGLE-2 为 2.57x，FLy 为 2.69x，平均 2.69x。L31 70B FLy 为 2.88x。EAGLE-2 仅在 L3 70B 上有数据。因此，FLy 在 L31 70B 上无直接 EAGLE-2 对比，但论文声称比 EAGLE-2 快 1.05 倍，可能指 L3 70B 上的比较：2.69x / 2.57x ≈ 1.05x。在 L33 70B 上，FLy 2.63x 低于 EAGLE-3 3.83x，但 EAGLE-3 在 OOD 上崩塌。

消融实验显示，延迟窗口长度 $W=6$ 和熵阈值 $\theta=0.3$ 是最佳平衡点。$W=0$ 时加速比最高（3.42x）但准确率降至 93.7%；$W=8$ 时加速比降至 2.61x 但准确率 100%。$\theta=0$ 时加速比 2.98x 但准确率 97.7%；$\theta=1$ 时退化为标准 SPD。多级加速将加速比从 2.69x 提升至 2.86x。草稿模型大小从 1B 到 8B，$\tau$ 单调增加，但加速比非单调，8B 模型在准确率与吞吐量间取得最佳平衡。

评估边界方面，论文未报告置信区间，且准确率恢复率基于特定数据集（HumanEval, GSM8K 等），未覆盖医疗、法律等高风险领域。代码已开源，超参数（$W=6, \theta=0.3, K=15/25$）固定，GPU 为 AMD Instinct MI355X。

## 关联研究分析

从问题动机看，FLy 与 JudgeDecoding 均旨在解决精确匹配导致的语义有效 token 丢弃问题，但 JudgeDecoding 依赖训练分类器，其泛化能力受限于训练数据分布，而 FLy 利用目标模型动态行为，天然具备跨域鲁棒性。这一差异源于任务特性：宽松验证需要判断“语义等价性”，这是一个高度上下文依赖且难以静态建模的问题，动态行为比静态分类器更适应分布偏移。

从方法设计看，FLy 与 EAGLE 系列代表了两条不同路线：EAGLE 通过优化草稿模型质量提升接受率，FLy 通过优化验证策略提升接受率。EAGLE 的瓶颈在于草稿模型与目标模型的分布对齐，FLy 的瓶颈在于延迟窗口的长度选择与熵阈值的设定。FLy 未采用树状验证，而是基于线性序列的延迟窗口，这与“树状验证提升硬件利用率”的共识相悖，但 FLy 论证了线性验证在低内存开销下的优势，且其无训练特性使其更易部署。

## 总结

FLy 解决了投机解码中精确匹配规则导致语义有效 token 被丢弃的核心矛盾，抓住了目标模型自校正行为这一被忽略的信号，提出了无训练的熵门控与延迟窗口机制。实验证明，该方法在分布外数据上实现 2.53 倍加速，比训练式 SOTA 快 1.62 倍，且保持 99% 以上准确率。其边界在于：准确率恢复率基于特定数据集，未覆盖高风险领域；延迟窗口长度与熵阈值需手动调优，缺乏自适应机制。当上下文长度增加至长序列场景时，延迟窗口的固定长度是否会导致错误累积或漏检，论文未给出回答。
