# ICLR2026最新论文 ｜FLOWSEARCHER: SYNTHESIZING MEMORY-GUIDED AGENTIC WORKFLOWS FOR WEB INFORMATION SEEKING ｜FlowSearcher：基于记忆引导的智能体工作流合成

研究机构：新加坡南洋理工大学

作者：Keyi Xiang、Zeyu Feng、Zhuoyi Lin 等 8 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_36987402)

> 智能体搜索旨在让大语言模型（LLM）自主规划并执行多步信息检索任务，以突破静态检索增强生成（RAG）在多跳推理中的局限。现有主流框架如 ReAct 将搜索过程锁定为线性的“思考-行动-观察”循环，无法处理需要分支探索与回溯的复杂查询，且缺乏跨任务的经验积累机制。FlowSearcher 提出将网络搜索重构为“经验驱动的工作流合成”问题，通过动态生成有向无环图（DAG）工作流并引入层级化记忆复用，实现无参数更新的跨任务泛化。该方法在 GAIA 和 BrowseComp 基准上显著优于强化学习（RL）微调的基线，但其性能上限仍受限于骨干模型能力，且未提供与多智能体架构的直接对比。

## 研究背景

当 LLM 面对需要多步推理的开放域查询时，其参数化知识的时效性滞后与幻觉问题迫使系统依赖外部检索。传统 RAG 采用静态的“检索-生成”管道，无法根据中间结果动态调整后续查询，导致推理断裂。为解决此问题，ReAct 框架（Yao et al., 2023）引入了推理与行动交替执行的机制，使 LLM 能够动态调用工具并基于观察调整策略。然而，ReAct 强制智能体遵循单线程的线性轨迹，将本质上具有分支结构的查询压缩为线性链条，抑制了并行探索与结构修正。此外，现有系统依赖短暂的上下文窗口，执行轨迹在任务结束后即被丢弃，导致智能体无法从过往经验中积累可复用的结构化知识，反复重复无效动作。

该领域的核心矛盾在于：线性 ReAct 架构的结构瓶颈无法通过单纯的参数微调克服。WebThinker 等基于 RL 的系统虽提升了策略稳定性，但受限于 ReAct 模板，其性能增益迅速饱和（如 WebThinker-RL 在 GAIA 上仅比 Base 提升 3.8）。Plan-Execute 框架虽提供高层组织，但计划一旦生成便成为固定脚手架，缺乏对新证据的适应性。FlowSearcher 的切入点在于将搜索过程从“序列动作预测”重构为“工作流合成”，通过显式的图结构表示和记忆引导，使智能体能够根据查询特性动态调整工具调用的组合、顺序与深度，从而在不依赖参数更新的情况下实现自适应规划与跨任务泛化。

## 核心方法

### 方法参照系

本文问题属于智能体搜索中的工作流规划范畴。标准流程通常采用 ReAct 范式，即智能体在每一步基于历史轨迹生成单一动作（搜索、浏览或思考），环境返回观察后继续下一步。本文的关键差异在于摒弃了线性轨迹，转而将查询分解为子目标，并为每个子目标合成一个显式的、可操作的工作流图，而非隐式的步骤序列。

### 层级化任务形式化与记忆结构

FlowSearcher 将研究任务形式化为 $\{Q, \hat{y}, \Gamma\}$，其中 $\Gamma = \{\mu_i, G_i\}$ 包含分解后的子问题 $\mu_i$ 及其对应的工作流图 $G_i$。为解决长程任务中的信息遗忘与噪声问题，系统引入结构化组合记忆 $M$，其核心在于将执行轨迹抽象为三级层级：节点级记录具体工具调用的动作序列 $\boldsymbol{\alpha}$ 与输出 $\boldsymbol{o}$；图级存储工作流拓扑、成功指示器 $\gamma_i$ 及工具使用向量 $\mathbf{n}_i$；任务级封装端到端的问题上下文与结果。这种设计动机在于，线性轨迹无法区分“有效策略”与“无效尝试”，而层级化记忆允许系统选择性检索并复用成功的结构模式，避免对脆弱工具链的过度依赖。

$$
M = \{M_j^{[task]}\}, \quad M_j^{[task]} = \{Q_j, \xi_{Q_j}, \{G_i, \gamma_i, \mathbf{n}_i\}_{i=1}^{K}\}
$$

该公式表明，每个任务记忆条目不仅包含原始查询 $Q_j$ 和成功标志 $\xi_{Q_j}$，还捆绑了所有子问题的工作流图及其性能信号，为后续的经验驱动合成提供结构化基础。

### 记忆引导的工作流合成与执行

在高层编排阶段，FlowSearcher 通过检索算子 $R(\cdot; \zeta)$ 从记忆中提取相关轨迹，其中 $\zeta \in \{graph, node\}$ 指定检索层级。检索结果经指令模块 $I_G$ 蒸馏为洞察 $\xi_G$，注入编排提示 $\theta_G$，指导生成类型化 DAG 工作流 $G^*$。节点级执行则遵循公式：

$$
(\boldsymbol{\alpha}^*, \boldsymbol{o}^*) = \text{execute}(\theta_v \oplus \xi_v, \tau_v), \quad \xi_v = I_v(\tilde{M}_v, G^*, Q^*, \mu^*)
$$

这一设计解决了 ReAct 中查询生成盲目性的问题：通过注入过往节点级的执行日志 $\tilde{M}_v$，系统能够针对特定角色（如检索或解析）进行行为精炼，实现工作流规划与执行的协同优化。与 AutoFlow 等离线优化方法不同，FlowSearcher 在推理时动态合成工作流，使结构本身成为可适应、可修订的对象，而非固定模板。

## 实验评估

实验在 GAIA（103 个文本问题）、BrowseComp 和 GPQA-Diamond 上进行，基线涵盖无智能体的 LLM、标准 RAG、闭源 OpenAI Deep Research 以及 ReAct 式框架（Vanilla ReAct, WebThinker, WebDancer, Search-o1）。值得注意的是，论文未直接对比知识库中提到的 M-ASK 等多智能体框架或 Search-R1 等 RLVR 基线，这可能影响对架构优势的全面评估。

| Backbone | Framework | GAIA Avg. | BrowseComp Avg. | GPQA-Diamond Avg. |
| :--- | :--- | :--- | :--- | :--- |
| Qwen-2.5-32B | WebThinker-RL | 44.2 | 2.4 | 63.6 |
| QwQ-32B | WebDancer | 44.7 | 2.7 | 70.7 |
| QwQ-32B | **FlowSearcher** | **55.3** | **11.0** | **65.7** |
| GPT-4o-mini | **FlowSearcher** | **56.3** | **11.8** | **71.2** |

FlowSearcher 在相同骨干下显著优于 ReAct 式基线，例如 QwQ-32B 骨干下 GAIA 平均分数从 WebDancer 的 44.7 提升至 55.3。消融实验显示，块库的灵活性对性能影响显著：从“First-Hit only”到“No limitations”，GAIA 平均分从 27.2 提升至 55.3，表明更广泛的工具组合空间能激发更多样化的策略。记忆组成分析表明，包含成功与失败轨迹的完整记忆（Full Mem.）在 103 个任务中累计成功 57 个，而仅使用成功轨迹（Succ.-Only）为 53 个，说明失败经验对避免重复错误具有边际贡献。

评估边界方面，论文未报告计算效率指标，且 BrowseComp 的绝对性能（11.8%）远低于领域综述中提到的 Pi-Serini（40.1%），这可能源于骨干模型能力差异或评估协议不同。代码已开源，但超参数细节如检索阈值 $\delta$ 的具体取值未在正文中明确列出，可能影响复现性。

## 关联研究分析

从问题动机看，FlowSearcher 与 WebThinker 等 RL 基线的根本分歧在于对“瓶颈”的诊断。WebThinker 假设通过强化学习优化线性轨迹中的动作选择即可提升性能，但实验显示其增益迅速饱和（GAIA 仅 +3.8）。FlowSearcher 则指出线性结构本身限制了探索空间，因此将优化目标从“动作序列”转移至“工作流结构”。这一差异源于任务特性：复杂查询往往需要分支与回溯，线性轨迹无法表达这种非线性依赖。然而，论文未探讨当查询复杂度较低时，动态图合成是否引入不必要的计算开销，这可能限制了其在简单任务中的效率优势。

从方法设计看，FlowSearcher 的记忆机制与 Mem0 或 G-Memory 等现有智能体记忆系统存在显著差异。Mem0 侧重于轻量级状态维护与上下文摘要，而 FlowSearcher 的记忆直接驱动工作流图的拓扑结构，即记忆不仅辅助提示，而是决定“如何组织工具调用”。这种设计使得经验复用从“行为模仿”升级为“结构迁移”。但与 AutoFlow 相比，FlowSearcher 放弃了离线进化搜索，转而采用推理时的记忆引导合成，这提升了适应性但可能牺牲了全局最优性。查询侧增强在数据充足时是否仍有增益，论文未给出回答，且未对比多智能体架构在长程任务中的稳定性差异。

## 总结

FlowSearcher 旨在解决线性 ReAct 架构在复杂查询中缺乏分支探索能力且无法跨任务积累经验的矛盾。其切入点在于将搜索重构为工作流合成问题，通过显式 DAG 表示和层级化记忆，使智能体能够动态调整工具调用结构并复用过往经验。该方法在 GAIA 上取得 55.3% 平均分，BrowseComp 上取得 11.8% 平均分，显著优于同骨干的 ReAct 基线，验证了结构优化在无参数更新场景下的有效性。然而，其性能上限仍受限于骨干模型能力，且未提供与多智能体框架的直接对比，暴露了其在大规模信息聚合任务中的潜在局限。当查询复杂度进一步增加时，动态图合成的计算开销是否会抵消其结构灵活性带来的收益，论文未给出回答。
