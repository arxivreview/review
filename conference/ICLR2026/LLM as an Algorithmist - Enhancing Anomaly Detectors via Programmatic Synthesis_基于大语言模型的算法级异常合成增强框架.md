# ICLR2026最新论文 ｜LLM as an Algorithmist: Enhancing Anomaly Detectors via Programmatic Synthesis ｜基于大语言模型的算法级异常合成增强框架

研究机构：吉林大学、香港中文大学

作者：Hangting Ye、Jinmeng Li、He Zhao 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.03904)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.03904)

> 表格异常检测（TAD）长期受限于单类分类范式下检测器对特定异常模式假设的脆弱性，导致在异构数据中性能波动。现有方法多依赖数据级扰动或微调大语言模型（LLM）处理原始数据，既无法精准针对算法逻辑盲区，又面临隐私泄露与数值处理瓶颈。本文提出 LLM-DAS，将 LLM 重构为“算法策略师”，通过生成数据无关的 Python 代码来合成针对特定检测器弱点的“硬”异常，从而在不接触原始数据的前提下增强检测鲁棒性。该方法在 36 个基准上显著提升了主流检测器性能，但其效果高度依赖 LLM 对算法逻辑的推理准确性，且未验证对端到端深度检测器的普适性。

## 研究背景

表格异常检测的核心困境在于真实世界异常类型的异质性与检测器假设的单一性之间的冲突。当检测器基于重构误差（如 PCA）或隔离路径长度（如 IForest）等特定假设训练时，面对不符合这些假设的“硬”异常（如位于密集流形附近的局部异常），其决策边界会失效。这种失效源于单类分类范式仅利用正常样本训练，缺乏对异常分布的显式建模，导致模型对边界区域的判别能力不足。

主流解决路线分为两类：一是设计新的检测器以覆盖更多异常类型，但这往往引入新的假设漏洞；二是利用 LLM 进行数据增强或微调。然而，将 LLM 作为“数据处理器”直接输入表格数据，不仅面临高基数分类变量与数值特征的编码瓶颈，更因数据暴露产生严重的隐私风险。此外，传统数据增强方法（如 SMOTE、高斯噪声）在数据层面操作，无法感知检测器的内部逻辑，生成的异常往往过于“容易”被检测，无法有效修补算法盲区。本文的切入点在于将 LLM 的角色从数据处理转向算法推理，通过逻辑级攻击生成针对性异常，实现隐私保护与检测增强的解耦。

## 核心方法

### 方法参照系

本文问题置于单类分类（One-Class Classification）框架下，标准流程为：仅用正常样本 $D_{train}$ 训练评分函数 $f_t$，对测试样本 $x$ 输出异常分数。关键差异在于，本文不修改 $f_t$ 的训练过程，而是引入一个外部增强模块，通过合成“硬”异常将单类问题转化为二分类问题，从而在不破坏原检测器对正常分布建模能力的前提下，提升其对异常边界的判别力。

### 数据无关的代码生成

传统数据增强在数据空间操作，无法感知检测器 $A_t$ 的算法弱点。本文在 Phase 1 中，利用 LLM 对检测器的高层描述 $p_t^{description}$ 进行推理，生成数据无关的 Python 代码 $Code_t$。设计动机在于，只有理解算法逻辑（如 IForest 依赖轴对齐分裂），才能生成能欺骗该逻辑的异常。LLM 接收提示 $p_t^{code}$，输出包含策略 $S_{policy}$、程序 $S_{program}$ 和解释 $S_{explanation}$ 的结构化代码：

$$ Code_t = \text{LLM}(p_t^{description}, p_t^{objective}, p_t^{requirements}) $$

该公式表明，$Code_t$ 是 LLM 基于算法描述而非数据生成的确定性函数。由于 LLM 不接触 $D_{train}$，该过程天然规避了隐私泄露，且生成的代码可跨数据集复用，解决了传统增强方法需针对每个数据集重新设计策略的低效问题。

### 数据相关的硬异常实例化

Phase 2 将 $Code_t$ 实例化到具体数据集。设计动机在于，算法逻辑是通用的，但“硬”异常的具体形态取决于当前数据集的分布边界。代码接收接口集合 $I_t = \{D_{train}, f_t, N_{syn}\}$，其中 $f_t$ 是已训练的评分函数。代码首先识别 $D_{train}$ 中靠近决策边界的“边界”正常样本（即 $f_t(x)$ 最高的正常样本），然后通过受控外推将其转化为异常：

$$ D_{syn}^t = Code_t(I_t) $$

$$ D_{aug}^t = D_{train} \cup D_{syn}^t $$

随后，在 $D_{aug}^t$ 上训练二分类器 $\tilde{f}_t$，最终检测器 $F_t$ 通过融合原始分数与增强分数实现：

$$ F_t(x) = \frac{f_t(x) - \min(f_t)}{\max(f_t) - \min(f_t)} + \frac{\tilde{f}_t(x) - \min(\tilde{f}_t)}{\max(\tilde{f}_t) - \min(\tilde{f}_t)} $$

这一融合机制确保了即使 LLM 生成的异常存在偏差，原始检测器 $f_t$ 对正常分布的建模能力仍被保留，避免了因合成数据噪声导致的性能退化。

## 实验评估

实验在 36 个来自 ODDS 和 ADBench 的数据集上进行，涵盖医疗、金融等领域。基线包括 PCA、IForest、OCSVM、ECOD 和 DRL 五种经典检测器，以及 AnoLLM 等 LLM 基线。LLM-DAS 在所有源检测器上均带来一致提升，例如在 OCSVM 上，AUC-PR 平均提升 0.0723，相对提升 84.49%，且在 36 个数据集中的 25 个上取得显著改善（p < 0.05）。

| 检测器 | 基线 AUC-PR | LLM-DAS AUC-PR | 平均提升 (∆) | 相对提升 (%) | 胜出数据集数 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| OCSVM | 0.5295 | 0.6018 | 0.0723 | 84.49 | 25 / 36 |
| PCA | 0.5975 | 0.6377 | 0.0402 | 21.50 | 30 / 36 |
| IForest | 0.5724 | 0.6341 | 0.0617 | 23.60 | 26 / 36 |
| ECOD | 0.5376 | 0.5888 | 0.0512 | 23.05 | 28 / 36 |
| DRL | 0.7437 | 0.7849 | 0.0412 | 15.81 | 25 / 36 |

消融实验表明，LLM-DAS 优于高斯噪声、随机异常和 SMOTE 等传统增强方法。以 PCA 为例，LLM-DAS 的平均 AUC-PR 为 0.6376，而 SMOTE 仅为 0.5594。进一步分析显示，LLM-DAS 生成的异常与检测器最弱的异常类型（如 IForest 对 Dependency 和 Local 异常）在 Wasserstein 距离上最接近，证实了“逻辑级攻击”的有效性。不同 LLM 骨干（GPT-4o, Gemini-2.5-Pro, Qwen3）均能保持性能优势，其中 Gemini-2.5-Pro 表现最佳，平均 AUC-PR 为 0.6019（基于 OCSVM）。

评估边界方面，实验主要聚焦于经典统计与浅层学习检测器，未涵盖端到端深度异常检测模型（如 Deep SVDD 的变体或自编码器）。此外，合成异常数量固定为训练集的 10%，未探索不同比例对性能的影响。代码已开源，但 LLM 调用成本（每次检测器类型需两次 API 调用）在大规模部署中可能成为瓶颈。

## 关联研究分析

从问题动机看，LLM-DAS 与 AnoLLM（Tsai et al., 2025）均利用 LLM 增强 TAD，但路径截然不同。AnoLLM 将 LLM 微调为数据处理器，直接输入表格特征，这继承了 LLM 在数值保真度上的弱点，且存在隐私风险。LLM-DAS 则通过代码生成解耦数据与模型，其优势在于隐私保护与跨数据集复用，但劣势在于依赖 LLM 对算法逻辑的准确理解。若 LLM 对某检测器的内部机制理解有误，生成的代码可能无法有效针对弱点，而 AnoLLM 的数据驱动方式虽低效但更直接。

从方法设计看，LLM-DAS 与 STDG 领域的 LLM 应用（如 TabPFN 或 GReaT）形成对比。STDG 中 LLM 旨在生成统计分布相似的数据，关注边缘分布与高阶依赖；LLM-DAS 中 LLM 旨在生成逻辑上“困难”的异常，关注检测器的决策边界。前者追求分布保真，后者追求判别增强。这种差异源于任务目标：STDG 需数据可用于下游训练，而 TAD 仅需数据用于增强检测器。LLM-DAS 的“硬”异常定义（检测器难以区分）与 STDG 的“真实”异常定义（统计分布偏离）存在本质区别，前者是相对于特定检测器的相对概念，后者是绝对概念。

## 总结

LLM-DAS 解决了单类异常检测中检测器假设脆弱性与 LLM 数据隐私风险之间的矛盾。其核心在于将 LLM 从数据处理器重构为算法策略师，通过生成数据无关的代码来合成针对特定检测器逻辑盲区的“硬”异常，从而在不接触原始数据的前提下增强检测鲁棒性。实验证明，该方法在 36 个基准上显著提升了 OCSVM 等主流检测器的 AUC-PR（如 OCSVM 提升 84.49%），且优于传统数据增强方法。然而，其效果高度依赖 LLM 对算法逻辑的推理准确性，且实验仅覆盖经典检测器，未验证对端到端深度模型的普适性。当检测器架构从基于假设的浅层模型转向端到端深度网络时，LLM 能否通过代码生成有效识别并针对其复杂的非线性决策边界，论文未给出回答。
