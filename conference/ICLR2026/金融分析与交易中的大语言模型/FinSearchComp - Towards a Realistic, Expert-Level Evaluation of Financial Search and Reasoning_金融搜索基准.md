# ICLR2026最新论文 ｜FinSearchComp: Towards a Realistic, Expert-Level Evaluation of Financial Search and Reasoning ｜金融搜索基准

作者：Liang Hu、Jianpeng Jiao、Jiashuo Liu 等 23 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.13160)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.13160)

> 现有金融大语言模型（LLM）评估基准多局限于静态文本分析或短期回测，无法反映真实分析师在开放域、实时、多源冲突证据下的搜索与综合推理能力。FinSearchComp 通过构建包含 635 道专家级问题的开放域基准，强制模型调用外部工具获取动态数据，填补了端到端金融搜索评估的空白。该基准揭示了当前 SOTA 模型在时间敏感性和多源对账上的显著缺陷，但缺乏对专用金融模型和交易执行环节的覆盖，其作为“搜索能力”测试床的边界仍需进一步界定。

## 研究背景

金融分析师的日常工作流高度依赖对实时市场信号、结构化历史披露和非结构化背景信息的快速检索与整合。这一过程涉及复杂的时间戳对齐、单位换算及多源证据冲突解决，任何细微的错误都会直接影响估值、风险管理和合规性。传统的大语言模型评估往往假设数据已预收集，忽略了“获取数据”这一关键环节，导致模型在真实决策场景中的表现被高估。

早期金融基准如 FinQA 和 FinanceQA 聚焦于数值推理，但默认提供相关上下文，规避了开放域搜索的挑战。通用浏览基准如 BrowseComp 虽评估多步导航，但缺乏金融领域的专业深度，如财年对齐、GAAP 与非 GAAP 指标区分等。这些现有方案要么过于静态，要么缺乏领域特异性，无法有效诊断 LLM 在高风险、决策相关场景下的真实能力。FinSearchComp 的切入点在于将“搜索”本身作为核心评估对象，通过设计时间敏感、历史查询和复杂调查三类任务，模拟分析师的真实工作流，从而暴露模型在信息获取、验证和整合方面的短板。

## 核心方法

### 任务架构与动态评估机制

FinSearchComp 的核心创新在于将金融搜索任务解耦为三个层级：时间敏感数据获取（T1）、简单历史查询（T2）和复杂历史调查（T3）。这种分层设计不仅覆盖了从实时到长周期的时间跨度，还引入了动态答案机制。对于 T1 任务，答案随市场波动实时变化，评估时需调用 API 获取最新数据点，并设定基于资产波动特性的容错区间。这种设计直接对抗了传统基准中因数据静态化导致的记忆污染问题，强制模型依赖实时检索而非参数记忆。

### 多源证据整合与容错评分

针对 T2 和 T3 任务中常见的单位不一致、报告日历错位及数据源冲突问题，FinSearchComp 引入了基于规则（rubric-based）的 LLM 评估协议。该协议不仅检查数值匹配，还验证数据来源的权威性和时间戳的准确性。例如，在 T3 任务中，模型需整合多个季度的报告，调整公司行动（如拆股、分拆）的影响，并确保跨时间值的可比性。评分公式可表示为：

$$
Score = \alpha \cdot Match_{value} + \beta \cdot Match_{source} + \gamma \cdot Match_{timestamp}
$$

其中，$Match_{value}$ 为数值在容错区间内的匹配度，$Match_{source}$ 为数据来源的权威性评分，$Match_{timestamp}$ 为时间戳对齐的准确性。这一机制解决了传统精确匹配评分在金融数据修订和四舍五入差异下的失效问题，提升了评估的鲁棒性和公平性。

### 专家驱动的质量控制

为确保基准的专业性和可靠性，FinSearchComp 采用了 70 名专业金融专家进行数据标注和多阶段验证。每个问题都经过可靠数据源选择、歧义消除和多专家答案验证。对于存在多种合理答案的情况，基准设定了范围或容错带，而非单一固定值。这种质量控制流程确保了基准不仅测试模型的搜索能力，还测试其对金融领域特定约定（如 TTM vs. FY）的理解，从而更真实地反映分析师的工作需求。

## 实验评估

实验评估了 21 个主流模型（包括 Web 产品和 API 端点）在 FinSearchComp 上的表现。基线覆盖广泛，但缺乏专用金融模型（如 FinGPT、FinRS），这可能限制了结果在特定金融任务上的泛化性。主结果显示，Grok 4 (web) 在全球子集上取得最高分 68.9%，但仍低于人类专家 75.0% 的基线 6.1 个百分点。在 Greater China 子集上，DouBao (web) 领先，但所有模型均落后于人类专家 34 个百分点以上。

| 模型 | Global Subset (%) | Greater China Subset (%) |
| :--- | :--- | :--- |
| Grok 4 (web) | 68.9 | 88.3 |
| GPT-5-Thinking (web) | 63.9 | 84.7 |
| DouBao (web) | 53.0 | 82.0 |
| Human Expert | 75.0 | 100.0 |

消融分析表明，配备 Web 搜索和金融插件能显著提升模型性能。例如，DeepSeek-R1 在启用搜索后，T1 任务得分从 25.0 提升至 69.2，T2 任务从 37.3 提升至 40.3，T3 任务从 14.0 提升至 13.9（注：T3 提升不明显，可能因复杂推理瓶颈）。这一发现验证了外部工具在弥补 LLM 实时数据获取短板上的关键作用，但也揭示了模型在复杂历史调查任务上的推理瓶颈。

评估边界方面，FinSearchComp 主要关注搜索和信息整合能力，未涉及交易执行、风险建模或合规性检查。此外，基准的静态答案部分（T2/T3）仍可能存在记忆污染风险，尽管通过多源验证和容错机制进行了缓解。可复现性方面，论文提供了 GitHub 和 HuggingFace 链接，但动态答案的评估依赖于实时 API，不同时间点的测试结果可能存在差异，需严格记录评估时间戳以确保公平性。

## 关联研究分析

从问题动机看，FinSearchComp 与 FinQA 和 FinanceQA 的核心差异在于数据获取方式。FinQA 等基准预收集了相关上下文，模型仅需进行数值推理，而 FinSearchComp 强制模型在开放域中搜索数据，这更接近真实分析师的工作流。这一差异源于任务特性的不同：FinQA 关注“如何计算”，FinSearchComp 关注“如何找到并验证”。FinSearchComp 的设计揭示了 LLM 在信息获取环节的脆弱性，而 FinQA 等基准可能高估了模型在真实场景中的表现。

从方法设计看，FinSearchComp 与 BrowseComp 的区别在于领域深度和答案复杂度。BrowseComp 优化于“可发现性”，答案短且易验证，而 FinSearchComp 要求长程综合、单位对齐和多源对账，答案复杂且需专业判断。这一差异反映了金融搜索的高门槛：不仅需找到信息，还需理解其财务含义和时间背景。FinSearchComp 的引入填补了通用浏览基准与专业金融 QA 基准之间的空白，为评估 LLM 在高风险决策支持中的能力提供了更严格的测试床。

## 总结

FinSearchComp 旨在解决 LLM 在金融搜索与推理评估中缺乏开放域、实时性和多源整合能力的核心矛盾。通过构建 635 道专家级问题并引入动态评估机制，该基准首次量化了模型在真实分析师工作流中的表现。实验显示，即使是最先进的模型如 Grok 4，在全球子集上仍落后于人类专家 6.1 个百分点，揭示了当前 LLM 在时间敏感性和复杂推理上的不足。然而，基准未覆盖专用金融模型和交易执行环节，且动态答案的评估受限于实时 API 的可用性。当模型在 T3 复杂历史调查任务上的得分提升停滞时，是否意味着单纯增加搜索工具无法解决深层推理瓶颈，论文未给出明确回答。
