# ICLR2026最新论文 ｜TOKMEM: ONE-TOKEN PROCEDURAL MEMORY FOR LARGE LANGUAGE MODELS ｜单Token程序性记忆

研究机构：加拿大阿尔伯塔大学

作者：Zijun Wu、Yongchang Hao、Lili Mou

论文原文见 [arXiv](https://arxiv.org/abs/2510.00444)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_81417545)

> 长提示词在推理时重复占用上下文窗口并引入二次方计算开销，导致任务扩展时效率急剧下降。现有检索增强或参数微调方案分别受限于文本冗余与灾难性遗忘，难以实现模块化复用。本文提出TokMem，将任务程序编译为单个可训练记忆Token，在冻结骨干模型上实现按需调用与组合执行。该方法在参数效率与持续学习稳定性上优于基线，但牺牲了提示词的人类可读性与跨模型直接迁移能力。

## 研究背景

当LLM执行多步工具调用或复杂推理时，通常依赖长提示词提供上下文线索。这种文本化上下文工程（Textualized Context Engineering）虽然灵活，但每次查询都需重新处理冗长指令，自注意力机制的二次方复杂度使得推理延迟随提示长度线性增长，且挤占输入输出空间导致截断。为缓解此问题，检索增强生成（Retrieval-Augmented Generation, RAG）将外部知识作为文本块插入上下文，但这仅解决了事实检索，未解决程序性知识的压缩存储；参数高效微调（如LoRA）虽能内化行为，却因共享权重导致新任务学习时旧任务性能衰退，即灾难性遗忘。

该领域长期存在“显式文本记忆”与“隐式参数记忆”的路线分歧。前者如MemGPT，通过检索历史对话维持状态，但频繁重读文本造成计算浪费；后者如全量微调，虽能固化行为，但缺乏模块化隔离，无法支持技能的持续累积。现有方法未能同时满足“常量开销”、“模块化组合”与“无干扰持续学习”三个约束。TokMem的切入点在于借鉴认知科学中程序性记忆（Procedural Memory）的概念，将任务行为从文本描述解耦为独立的参数单元，从而在保持骨干模型冻结的前提下，实现技能的按需召回与组合。

## 核心方法

### 方法参照系

本文问题可置于参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）框架下审视，但关键差异在于：PEFT（如LoRA）通过低秩矩阵更新共享权重，任务间存在参数纠缠；而TokMem将每个任务程序映射为独立的特殊Token嵌入，实现参数隔离。

### 程序性记忆Token化

传统PEFT在训练时更新所有层的适配器权重，导致新任务学习干扰旧任务。TokMem将每个程序性任务编码为一个专用记忆Token $m_i$，其嵌入向量 $e_i \in \mathbb{R}^d$ 作为唯一可训练参数，骨干模型权重保持冻结。训练时，输入序列布局为 $[q; m_i; r_1, \dots, r_n]$，其中 $q$ 为查询，$r$ 为响应。损失函数仅计算记忆Token位置及响应位置的下一Token预测误差：

$$
\mathcal{L} = -\sum_{t \in \{i, r_1, \dots, r_n\}} \log P(x_t | x_{<t})
$$

此设计使每个程序拥有独立的参数空间，新技能加入时不改变旧技能的嵌入方向，从根源上规避了权重纠缠导致的遗忘。

### 路由召回与重归一化

推理时，模型基于查询 $q$ 的隐藏状态 $h_k$ 预测记忆Token分布，选择概率最高的 $m^*$ 拼接至输入以引导生成。对于多步任务，模型在每段响应后再次预测下一个记忆Token，实现链式调用。然而，新Token嵌入范数易膨胀，主导路由Logits并抑制旧记忆检索。为此，引入重归一化策略：计算现有记忆库的平均范数 $\bar{||m||}$，将新嵌入 $m_{new}$ 缩放为 $m'_{new} = m_{new} \cdot \frac{\bar{||m||}}{||m_{new}||}$。该操作保持方向不变，仅对齐幅度，确保新记忆平滑融入而不破坏既有路由动态。

## 实验评估

实验在Super-Natural Instructions（SNI，原子任务）和APIGen（组合工具调用）上进行，基线涵盖Base、ICL、RAG、LoRA及Replay Memory。SNI任务数从10扩展至1000，APIGen涉及2-4次工具调用。

| 模型 | 方法 | SNI 1000任务 ROUGE-L | APIGen 工具选择 F1 (Avg) | APIGen 参数量 |
| :--- | :--- | :--- | :--- | :--- |
| Llama 3.1 8B | RAG | 65.8 | 82.0 | – |
| Llama 3.1 8B | Fine-Tuning | 63.7 | 82.8 | 3.41M |
| Llama 3.1 8B | TokMem | 66.7 | 89.3 | 0.20M |
| Llama 3.2 3B | Fine-Tuning | 58.7 | 76.4 | 2.29M |
| Llama 3.2 3B | TokMem | 62.6 | 86.3 | 0.15M |

TokMem在SNI 1000任务上ROUGE-L达66.7（Llama 8B），优于LoRA的63.7和RAG的65.8；在APIGen上，TokMem以0.20M参数实现89.3的工具选择F1，显著高于LoRA的82.8（3.41M参数），参数效率提升约17倍。

| 模型 | 方法 | SNI 1000任务 路由准确率 | SNI 10任务 路由准确率 |
| :--- | :--- | :--- | :--- |
| Llama 3.1 8B | RAG (Sentence-BERT) | 79.7 | 99.6 |
| Llama 3.1 8B | TokMem | 97.5 | 99.8 |
| Llama 3.2 3B | TokMem | 96.1 | 100.0 |

路由准确率显示，RAG在1000任务时降至79.7%，而TokMem保持在97.5%以上，表明参数化路由比文本检索更鲁棒。消融实验表明，解耦变体TokMem+DC在小模型上有微弱增益，但在大模型上无提升甚至下降，故主实验采用基础TokMem。重归一化实验证实，无此策略时新Token会抑制旧记忆，导致小模型性能骤降。

评估指标包括ROUGE-L、F1及路由准确率，但未报告推理延迟与显存占用的具体数值，仅定性提及“常量开销”。代码已开源，训练使用单卡A6000，超参数（如学习率5e-3 for TokMem）已披露，可复现性较好。

## 关联研究分析

从问题动机看，TokMem与UCL（Universal Conditional Logic）同属形式化路线，但UCL侧重通过声明式语法约束文本提示的可验证性，而TokMem侧重将程序压缩为参数嵌入。差异根源在于任务特性：UCL面向逻辑约束满足，需保留文本可读性以便调试；TokMem面向高频重复任务，追求推理效率，牺牲可读性换取计算节省。这种取舍是否适用于需要人工审计的合规场景，论文未给出回答。

从方法设计看，TokMem与LoRA均使用低秩/小参数更新，但LoRA更新共享权重，TokMem更新独立Token嵌入。LoRA在任务间存在负迁移，而TokMem通过参数隔离避免此问题。然而，TokMem依赖路由机制选择Token，当任务语义高度相似时，路由错误率可能上升，而LoRA通过全局上下文隐式处理相似性。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文核心矛盾在于长提示词的计算开销与参数微调的灾难性遗忘。TokMem通过将程序编译为独立记忆Token，实现了参数隔离与按需召回，在SNI 1000任务上以66.7 ROUGE-L和97.5%路由准确率验证了有效性，并在APIGen上以1/17参数超越LoRA。其边界在于：记忆Token缺乏文本形式，无法直接跨模型迁移或人工调试；且路由机制在任务语义重叠时可能失效。当任务库规模扩展至万级且语义高度相似时，单Token路由的准确率是否仍能保持，论文未给出回答。
