# ICLR2026最新论文 ｜FASTA: FAST-SLOW TOOLPATH AGENT WITH SUB-ROUTINE MINING FOR EFFICIENT MULTI-TURN IMAGE EDITING ｜快慢工具路径智能体

研究机构：美国马里兰大学帕克分校

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_57139603)

> 多轮图像编辑任务要求执行检测、分割、重绘等异构操作序列，现有端到端模型难以直接处理长时程依赖，而纯搜索规划方法计算成本过高。CoSTA* 虽通过 A* 搜索实现了成本-质量平衡，但其“测试时规划”机制无法复用历史经验，导致重复探索相同子任务。FaSTA* 引入基于 LLM 归纳推理的符号化子程序挖掘，构建快慢规划框架，在保持质量的前提下大幅降低规划成本。该方法在效率维度上具有显著优势，但其子程序泛化性受限于特定工具集与任务分布，对生成质量的提升贡献有限。

## 研究背景

多轮图像编辑的核心挑战在于长时程任务中的工具调用规划。当指令包含“检测长椅并涂色、移除猫、重绘墙壁”等复合操作时，系统需将高层意图分解为原子工具调用序列（Toolpath）。这一过程涉及两个关键概念：一是**子任务分解**，即利用大语言模型（LLM）将自然语言指令映射为离散的操作链；二是**成本-质量权衡**，即在不同工具（如 YOLO 检测器 vs. Grounding DINO）之间选择，以平衡执行耗时与输出精度。传统端到端扩散模型（如 InstructPix2Pix）缺乏显式规划能力，难以处理多步依赖；而纯 LLM 代理（如 GenArtist）虽能分解任务，但常因幻觉选择昂贵工具或忽略局部约束，导致效率低下。

现有主流路线分为两类：一是端到端微调，通过大规模数据学习指令到像素的映射，但在复杂多轮任务中缺乏长序列一致性；二是代理式规划，利用 LLM 分解任务并调用专用工具。CoSTA*（Gupta et al., 2025）代表了后者的前沿，它结合 LLM 高层规划与 A* 搜索底层路径，实现了成本敏感的最优工具路径。然而，CoSTA* 是“测试时”方法，每次任务都需重新进行昂贵的 A* 搜索，无法从历史任务中积累知识。FaSTA* 的切入点在于引入**在线学习机制**，通过挖掘可复用的符号化子程序，将重复性子任务的规划从“搜索”转化为“检索”，从而解决长时程任务中的计算瓶颈。

## 核心方法

### 方法参照系

FaSTA* 建立在 CoSTA* 的层级规划框架之上，其标准流程包括：LLM 生成子任务树、构建工具依赖子图、执行 A* 搜索以最小化成本函数 $f(x) = g(x) + h(x)$。本文的关键差异在于，FaSTA* 在 LLM 规划与 A* 搜索之间插入了一层**符号化子程序库**，将底层搜索转化为基于规则的条件匹配，仅在规则失效时触发搜索。

### 在线子程序挖掘与归纳推理

FaSTA* 的核心创新之一是自动从历史执行轨迹中提取可复用的子程序。子程序 $P_s = (t_1, t_2, \dots, t_k)$ 表示针对特定子任务 $s$ 的有效工具调用序列，其激活条件 $C_s$ 由 LLM 通过归纳推理从执行日志中合成。这一过程解决了 CoSTA* 中重复探索相同子任务导致的计算冗余。具体而言，系统每 $K=20$ 个任务触发一次精炼，LLM 分析最近的执行轨迹 $T_{recent}$，识别高频成功路径，并推断其适用的上下文条件（如“对象大小非过小”、“背景为简单纹理”）。

子程序的选择基于成本-质量权衡分数：

$$
\text{Score}(P_j) = C_{avg}(P_j)^{\alpha} \times (2 - Q_{avg}(P_j))^{-\alpha}
$$

其中 $C_{avg}$ 和 $Q_{avg}$ 分别为子程序 $P_j$ 的历史平均成本与质量，$\alpha$ 为用户定义的成本-质量权衡系数。该公式的物理含义是：在满足激活条件的前提下，优先选择历史表现中成本与质量平衡最优的工具序列。通过这种符号化规则，FaSTA* 将底层 A* 搜索的探索空间从连续的工具依赖图压缩为离散的规则匹配，显著降低了规划开销。

### 自适应快慢规划执行

子程序库构成了“快规划”的基础，而 A* 搜索则作为“慢规划”的后备机制。FaSTA* 的执行流程分为两阶段：首先，LLM 根据当前图像上下文与子程序规则表 $R$，为每个子任务 $s_i$ 选择最优子程序 $P_{s_i}$ 或标记为“None”，生成快规划 $M_{subseq}$。随后，系统顺序执行快规划，并在每个工具调用后通过视觉语言模型（VLM）进行质量检查。

若快规划成功（即所有工具执行通过 VLM 检查），则直接输出结果，完全避免 A* 搜索。若快规划失败（无适用子程序或质量检查未通过），系统触发“慢规划”：构建该子任务的局部工具子图 $G_{low}(s_i)$，并执行 A* 搜索以寻找最优路径。这一机制确保了在子程序失效时仍能通过底层搜索保证编辑质量，实现了效率与鲁棒性的动态平衡。

## 实验评估

实验在 CoSTA* 基准数据集（121 个图像-提示对，含 1-8 个子任务）及 Complex-Edit 基准上进行，所有实验均在单张 NVIDIA A100 GPU 上完成。基线包括 CoSTA*、GenArtist、CLOVA、InstructPix2Pix 和 MagicBrush。FaSTA* 在平均执行时间上显著优于所有基线，其质量得分与 CoSTA* 接近，但成本大幅降低。

| 方法 | 平均执行时间 (s) | 平均质量得分 | 备注 |
| :--- | :--- | :--- | :--- |
| FaSTA* (Ours) | 29.5 | 0.91 | $\alpha=1.0$ |
| CoSTA* | 58.2 | 0.94 | $\alpha=1.0$ |
| GenArtist | 65.1 | 0.73 | 无成本敏感规划 |
| CLOVA | 65.7 | 0.63 | 贪心工具调用 |
| InstructPix2Pix | 67.2 | 0.56 | 端到端模型 |

FaSTA* 相比 CoSTA* 将平均执行成本降低了 49.3%，而质量仅下降 3.2%（从 0.94 降至 0.91）。在 Complex-Edit 基准上，FaSTA* 同样实现了约 30% 的成本降低，质量保持可比水平。这表明子程序复用机制在独立数据集上具有泛化性。

消融实验揭示了快慢规划各组件的贡献。移除子程序验证机制（即不通过 VLM 检查快规划输出）导致回退率从 9% 上升至 28%，说明质量检查是防止错误子程序传播的关键。仅使用快规划（无 A* 后备）时，质量降至 0.84，成本为 27.5s；仅使用慢规划（无子程序）时，质量为 0.93，成本为 46.8s。FaSTA* 在两者之间取得了最佳平衡，证明了“快规划为主、慢规划兜底”策略的有效性。

评估边界方面，论文采用人工评估（Human Evaluation）作为主要质量指标，因自动指标（如 CLIP）难以捕捉多步编辑中的细微语义错误。然而，实验未报告置信区间，且子程序挖掘依赖于特定的工具集（YOLO, SAM, SD Inpaint 等），其在其他工具组合下的泛化性未充分验证。此外，冷启动阶段（无历史经验时）FaSTA* 的性能与 CoSTA* 持平，未体现优势，表明其效率增益依赖于足够的历史任务积累。

## 关联研究分析

从问题动机看，FaSTA* 与 MIRA（Zeng et al., 2025）同属推理与规划框架，但关注点截然不同。MIRA 侧重通过强化学习优化语义一致性和感知质量，解决复杂指令下的组合推理问题；而 FaSTA* 聚焦于工具调用的计算效率，通过符号化规则减少 A* 搜索开销。MIRA 的“慢”在于 RL 训练的迭代过程，FaSTA* 的“慢”在于底层 A* 搜索。FaSTA* 的快慢规划机制并未涉及语义推理的深度优化，其质量提升主要源于避免了错误工具选择，而非增强了语义理解能力。

从方法设计看，FaSTA* 与 EditThinker（Li et al., 2025）在“迭代反馈”机制上存在差异。EditThinker 利用 MLLM 作为裁判进行细粒度评估，并据此优化编辑策略，强调通用性；FaSTA* 则通过 VLM 质量检查触发回退，强调效率。FaSTA* 的子程序挖掘是一种离线/在线混合的知识积累过程，而 EditThinker 的反馈是实时的。FaSTA* 的符号化规则（如“对象大小非过小”）具有可解释性，但可能忽略全局语义连贯性；EditThinker 的密集反馈能捕捉细微差别，但计算成本更高。FaSTA* 在效率与可解释性上占优，但在细粒度语义控制上可能不如 EditThinker。

## 总结

FaSTA* 旨在解决多轮图像编辑中工具路径规划的计算瓶颈，其切入点在于利用 LLM 归纳推理挖掘可复用的符号化子程序，将重复性子任务的规划从昂贵的 A* 搜索转化为低成本的规则匹配。该方法通过快慢规划框架，在保持与 CoSTA* 相当的质量（0.91 vs. 0.94）的同时，将平均执行成本降低了 49.3%（29.5s vs. 58.2s）。然而，其效率增益依赖于历史任务的积累，冷启动阶段无优势；且子程序规则受限于特定工具集，对生成质量的提升贡献有限。当工具集扩展或任务分布发生显著变化时，符号化子程序的泛化性是否仍能维持 49.3% 的成本降低，论文未给出回答。
