# ICLR2026最新论文 ｜CODE DRIVEN PLANNING WITH DOMAIN-ADAPTIVE SELECTOR ｜代码驱动规划与领域自适应选择器

研究机构：中国科学院、中国科学院大学

作者：Zikang Tian、Shaohui Peng、Di Huang 等 14 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_99840186)

> 大语言模型（LLM）在具身任务中因通用知识与环境特定约束的错位，常生成看似合理但不可执行的计划，且依赖高频查询进行即时反馈修正导致算力成本高昂。现有即时反馈范式受限于短视策略，难以优化长期奖励。CoPiC 通过生成多个高层规划程序并引入基于强化学习的领域自适应选择器，在降低查询成本的同时提升规划质量。该方法在 ALFWorld 等基准上显著优于基线，但其对预定义动作空间的依赖限制了在完全开放环境中的泛化能力。

## 研究背景

LLM 将自然语言指令转化为环境动作序列时，面临部分可观测马尔可夫决策过程（POMDP）中的状态追踪难题。由于缺乏显式的状态表示，LLM 往往依赖模式匹配而非逻辑推理，导致在复杂约束下产生幻觉。为解决此问题，主流方法采用即时反馈范式，即 LLM 根据每一步的环境观察迭代修正计划。然而，这种逐步查询机制不仅消耗大量 Token，还使模型陷入局部最优，无法兼顾长期任务目标。

该领域的核心矛盾在于 LLM 的语义灵活性与环境逻辑严谨性之间的冲突。早期工作如 ReAct 和 Reflexion 通过增加查询频率来弥补逻辑缺陷，但未能解决成本与长期规划能力的权衡问题。代码驱动规划路线（如 AdaPlanner）尝试将计划封装为可执行程序，但单一静态程序难以应对动态环境中的多样化观察。CoPiC 的切入点在于将规划过程解耦为“程序生成”与“计划选择”两个阶段，利用混合专家（MoE）机制生成多个候选程序，并通过强化学习训练的选择器从候选计划中筛选出最符合长期奖励的方案，从而在降低 LLM 调用频率的同时提升决策质量。

## 核心方法

### 规划程序生成与候选集构建

CoPiC 摒弃了直接生成静态计划的传统流程，转而利用 LLM 生成多个高层规划程序 $\rho_i$。每个程序是一个可执行的 Python 函数，接收任务指令 $I$ 和当前观察 $o$，输出动作序列 $p_i$。这一设计将 LLM 的角色从“逐步决策者”转变为“策略生成器”，程序内部封装了状态检查与逻辑分支，减少了与环境交互时的 LLM 查询次数。

$$
p_i = \rho_i(I, o), \quad i \in \{1, \dots, n\}
$$

该公式表明，$n$ 个不同的规划程序针对同一上下文生成 $n$ 个候选计划。这种多程序并行机制解决了单一程序在复杂任务中因采样能力有限而导致的规划失败问题，为后续的选择提供了多样性基础。

### 领域自适应选择器与强化学习优化

在获得候选计划集 $\{p_i\}$ 后，CoPiC 引入领域自适应选择器 $C_\theta$ 进行评估。选择器是一个小型神经网络，其参数 $\theta$ 通过近端策略优化（PPO）算法进行微调。选择器不仅考虑当前观察，还结合历史交互摘要，预测每个候选计划的长期回报。

$$
L_{PPO}(\theta) = \mathbb{E}_t \left[ \min\left( r_t(\theta) \hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_t \right) - c_1(V_\theta(s_t) - R_t)^2 + c_2 H[C_\theta](o_t) \right]
$$

此损失函数通过优势函数 $\hat{A}_t$ 引导选择器学习哪些计划能带来更高的累积奖励，而非仅关注即时反馈。这种设计使得 CoPiC 能够识别出那些短期看似低效但长期收益更高的策略（如 NetHack 中保护宠物以击败怪物的策略），从而克服了即时反馈范式的短视缺陷。

## 实验评估

CoPiC 在 ALFWorld、NetHack 和 StarCraft II 三个环境中进行了评估，基线包括 Reflexion、AdaPlanner、Prospector 和 REPL-plan。实验协议采用“训练集学习+测试集零样本”设置，比基线的“测试集在线学习”更为严格。

| 方法 | ALFWorld Pick SR (%) | ALFWorld Pick Cost (M) | NetHack Upgrade SR (%) | NetHack Upgrade Cost (M) |
| :--- | :--- | :--- | :--- | :--- |
| CoPiC | 100.00 | 0.05 | 90.00 | 0.04 |
| AdaPlanner | 100.00 | 0.63 | 80.00 | 1.57 |
| Reflexion | 91.67 | 2.09 | 70.00 | 1.65 |

*注：NetHack 数据据论文正文描述推算，具体数值见原文 Table 2 及正文描述。CoPiC 在 ALFWorld 上平均成功率提升 19.14%，Token 成本降低 79.39%。*

消融实验显示，规划程序数量 $n$ 对性能有显著影响。在 StarCraft II 的 Hard 任务中，$n=1$ 时成功率为 33%，而 $n=3$ 时达到 100% 且成本最低。这表明多程序竞争机制是解决复杂任务的关键，但 $n$ 过大（如 $n=6$）会导致选择器评估难度增加，性能略有下降。此外，CoPiC 在开源 LLM（如 Qwen2.5-14B）上表现优于 AdaPlanner 26.29%，且避免了 Reflexion 因上下文累积导致的内存溢出问题。

评估边界方面，CoPiC 依赖预定义的动作空间 API，未验证在动作空间未知或动态变化环境中的表现。代码未公开，但提供了详细的超参数设置（如 PPO 的 batch size、clip ratio 等），复现性中等。

## 关联研究分析

从问题动机看，CoPiC 与 PDDLCoder 均旨在解决 LLM 规划中的逻辑一致性，但路径截然不同。PDDLCoder 依赖外部符号验证器（如 VAL）对生成的 PDDL 进行语义评分，强调形式化逻辑的严谨性；而 CoPiC 完全摒弃符号验证，通过代码执行和 RL 选择器在物理环境中试错。这种差异源于任务特性：PDDL 适用于静态、逻辑约束明确的问题，而 CoPiC 针对的是动态、部分可观测的具身任务，其中环境反馈比形式化验证更具信息量。

从方法设计看，CoPiC 与 Planner-R1 同属 RL 优化 LLM 规划的范畴，但优化对象不同。Planner-R1 通过奖励塑造直接优化 LLM 的策略网络，使小模型获得规划能力；CoPiC 则保持 LLM 作为程序生成器，仅优化外部的选择器。这种解耦设计使得 CoPiC 能够利用 LLM 强大的代码生成能力，同时通过轻量级选择器实现领域适应，避免了微调大模型的高昂成本。然而，CoPiC 的选择器依赖于训练数据中的奖励信号，在奖励稀疏或分布外任务中可能失效，这一点在论文中未充分探讨。

## 总结

CoPiC 解决了 LLM 具身规划中高频查询成本与长期奖励优化之间的矛盾。通过生成多个规划程序并引入基于 PPO 的选择器，CoPiC 在 ALFWorld 上实现了 100% 的成功率，同时将 Token 成本降低了近 80%。其核心贡献在于证明了“程序化封装+选择性执行”范式在动态环境中的有效性，超越了即时反馈范式的局限。然而，CoPiC 的性能高度依赖于预定义的动作空间 API 和训练数据中的奖励信号，当环境动作空间未知或奖励函数稀疏时，选择器的泛化能力尚不明确。当任务涉及未预定义的复杂交互或需要跨域迁移时，CoPiC 的程序生成机制能否自动发现新的 API 并适应新领域，论文未给出回答。
