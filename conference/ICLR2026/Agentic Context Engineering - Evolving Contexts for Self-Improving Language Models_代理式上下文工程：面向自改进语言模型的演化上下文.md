> 导读 长上下文大语言模型（Long-Context LLM）在代理与领域推理任务中，常因上下文压缩导致关键领域知识丢失，现有方法多受限于“简洁性偏差”与“上下文坍缩”。ACE 框架将上下文视为动态演化的“剧本”，通过生成、反思与策展的模块化闭环，实现增量式上下文更新。该框架在代理与金融推理基准上显著优于基线，并大幅降低适应延迟。其核心价值在于证明了无需权重更新即可通过结构化上下文演化实现自改进，但其在无可靠反馈信号下的鲁棒性仍存疑。

## 研究背景

当大语言模型（Large Language Model, LLM）应用于复杂代理任务或领域推理时，模型性能高度依赖于输入上下文中包含的指令、策略与证据。这种通过修改输入而非模型权重来提升性能的方法称为上下文适应（Context Adaptation）。然而，现有的上下文优化方法往往倾向于生成简短、通用的指令，即“简洁性偏差”（Brevity Bias），这导致领域特定的启发式规则被丢弃。更严重的是，当上下文长度增加时，基于单体 LLM 重写的优化方法容易将详细上下文压缩为简短摘要，造成信息急剧丢失，即“上下文坍缩”（Context Collapse），导致性能断崖式下跌。

长上下文能力的提升使得在输入中饱和大量潜在有用信息成为可能，但如何有效组织这些信息仍是难题。传统方法如动态提示优化或外部记忆机制，多依赖单一模型进行端到端重写，缺乏对上下文结构的细粒度控制。ACE 框架针对这一痛点，提出将上下文视为不断积累和精炼的“剧本”，通过模块化代理架构避免信息坍缩，实现从“能读长文”到“能深推理”的范式转变。

## 核心方法

### 方法参照系：模块化代理架构

ACE 框架建立在动态外部记忆机制之上，其核心流程由三个专门化的代理角色组成：生成器（Generator）、反思器（Reflector）和策展器（Curator）。生成器负责产生推理轨迹，反思器从成功与失败中提取具体洞察，策展器将这些洞察整合为结构化的上下文更新。这一设计将评估、洞察提取与上下文整合解耦，避免了单一模型承担所有职责导致的瓶颈。

### 增量 Delta 更新机制

传统方法在每次适应步骤中重写整个上下文，易引发上下文坍缩。ACE 引入增量 Delta 更新机制，将上下文表示为结构化的、条目化的项目符号（Bullets）集合。每个项目符号包含元数据（如唯一标识符、有用/有害计数器）和内容（如可复用策略、领域概念）。当生成器解决新问题时，反思器根据反馈提出修正更新，策展器生成紧凑的 Delta 条目，并通过非 LLM 的确定性逻辑合并到现有上下文中。

$$
C_{t+1} = C_t \oplus \Delta C_t
$$

该公式表示上下文 $C$ 在时间步 $t+1$ 的状态由前一步状态 $C_t$ 与增量更新 $\Delta C_t$ 合并而成。$\oplus$ 代表基于元数据的确定性合并操作，如去重、冲突解决与计数器更新。这一设计确保了只有相关的项目符号被更新，实现了局部化编辑，大幅降低了计算成本并保留了详细知识。

### Grow-and-Refine 机制

随着上下文不断积累，冗余信息可能干扰模型推理。ACE 引入 Grow-and-Refine 机制，在上下文稳步扩展的同时控制冗余。该机制通过监控项目符号的有用/有害计数器，定期触发精炼过程，移除低效或冲突的条目。

$$
\text{Score}(b_i) = \alpha \cdot N_{\text{helpful}}(b_i) - \beta \cdot N_{\text{harmful}}(b_i)
$$

该公式计算项目符号 $b_i$ 的保留分数，其中 $N_{\text{helpful}}$ 和 $N_{\text{harmful}}$ 分别为被标记为有用和有害的次数，$\alpha$ 和 $\beta$ 为权重系数。当分数低于阈值时，条目被移除或合并。这一机制平衡了上下文的丰富性与简洁性，防止了长上下文中的注意力稀释。

## 实验评估

ACE 在代理基准 AppWorld 和金融推理基准 FiNER/Formula 上进行了评估。基线包括基础 LLM、In-Context Learning (ICL)、MIPROv2、GEPA 和 Dynamic Cheatsheet (DC)。实验分为离线适应（系统提示优化）和在线适应（测试时记忆适应）两种设置。

| 方法 | GT Labels | Test-Normal TGC | Test-Challenge TGC | Average |
| --- | --- | --- | --- | --- |
| ReAct | - | 42.4 | 21.6 | 42.4 |
| ReAct + ICL | ✓ | 46.0 | 27.3 | 46.0 |
| ReAct + GEPA | ✓ | 46.4 | 30.2 | 46.4 |
| ReAct + ACE | ✓ | 57.3 | 39.6 | 59.4 |
| ReAct + ACE | ✗ | 54.4 | 35.2 | 57.2 |

在 AppWorld 上，ACE 在离线设置下平均提升 10.6%，在线设置下提升 7.6%。值得注意的是，即使在没有真实标签（GT Labels）的情况下，ACE 仍通过执行反馈实现了 14.8% 的平均提升，证明了其自改进能力。

| 方法 | GT Labels | FiNER (Acc) | Formula (Acc) | Average |
| --- | --- | --- | --- | --- |
| Base LLM | - | 70.7 | 67.5 | 69.1 |
| ICL | ✓ | 72.3 | 67.0 | 69.6 |
| GEPA | ✓ | 73.5 | 71.5 | 72.5 |
| ACE | ✓ | 78.3 | 85.5 | 81.9 |
| ACE | ✗ | 71.1 | 83.0 | 77.1 |

在金融基准上，ACE 在离线设置下平均提升 12.8%，在线设置下提升 7.5%。消融实验表明，反思器与多轮迭代对性能贡献最大，移除后平均性能下降显著。

评估边界方面，ACE 依赖可靠的执行反馈信号。在无监督或反馈噪声大的场景下，上下文可能被误导性信号污染。此外，ACE 生成的上下文较长，虽通过 KV 缓存复用降低了服务成本，但在极端长上下文场景下的推理延迟仍需进一步验证。

## 关联研究分析

从问题动机看，ACE 与 Dynamic Cheatsheet (DC) 均旨在通过外部记忆积累策略，但 DC 依赖单体 LLM 重写上下文，易引发上下文坍缩。ACE 通过模块化代理架构与增量更新解决了这一问题。从方法设计看，ACE 与 GEPA 均利用自然语言反馈优化上下文，但 GEPA 受限于简洁性偏差，倾向于生成简短指令，而 ACE 主张保留详细领域知识，通过结构化剧本实现更精细的上下文控制。

与强化学习（RL）方法相比，ACE 不直接优化模型权重，而是通过上下文演化实现适应。RLVR 等方法通过可验证奖励优化推理路径，但计算成本高且依赖奖励模型。ACE 利用执行反馈作为隐式奖励，通过策展器将反馈转化为结构化知识，实现了更低的适应成本与更高的可解释性。然而，ACE 的信用分配机制依赖于反思器的质量，若反思器无法提取有效洞察，上下文演化将失效。

## 总结

ACE 框架针对长上下文代理任务中的简洁性偏差与上下文坍缩问题，提出了一种模块化、增量式的上下文演化方法。通过生成、反思与策展的闭环，ACE 在 AppWorld 和 FiNER 基准上分别实现了 10.6% 和 8.6% 的平均性能提升，并大幅降低了适应延迟。其核心价值在于证明了无需权重更新即可通过结构化上下文实现自改进。然而，ACE 依赖强反思器与可靠反馈信号，在无监督或噪声环境下性能可能退化。当反馈信号不可靠时，如何保证上下文演化的鲁棒性，仍是该框架面临的实际挑战。
