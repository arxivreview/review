# ICLR2026最新论文 ｜PixelCraft: A Multi-Agent System for High-Fidelity Visual Reasoning on Structured Images ｜像素级接地与非线性视觉推理的多智能体系统

研究机构：微软研究院、清华大学

作者：Shuoshuo Zhang、Zijian Li、Yizhen Zhang 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.25185)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.25185)

> 结构化图像中的细微几何偏差会导致推理链断裂，现有方法依赖低保真图像处理或线性推理路径，难以应对复杂图表与几何图。PixelCraft 通过微调小型多模态大语言模型（MLLM）实现像素级坐标定位，驱动经典计算机视觉（CV）算子执行高保真图像编辑，并引入规划器管理的图像记忆支持非线性回溯。该方法在 CharXiv 和 ChartQAPro 上显著优于基线，但其对特定 CV 算子集的依赖限制了在未见过的非标准图表结构上的泛化能力。

## 研究背景

当模型面对包含密集数据点的科学图表时，视觉编码器对坐标轴刻度或柱状图高度的细微误读会直接导致算术错误。这种对细粒度空间信息的敏感度要求模型具备精确的符号抽象能力，而非仅依赖自然图像中的纹理或物体模式识别。为弥补纯文本推理在空间感知上的缺失，视觉思维链（Visual CoT）被引入，通过生成中间视觉线索辅助推理。然而，现有 Visual CoT 方法通常依赖不可用的源代码或仅提供低分辨率的图像裁剪，且推理过程呈线性链条状，无法支持假设测试与回溯。

结构化图像理解的核心矛盾在于高保真感知与灵活推理的脱节。主流路线分为两类：一类是端到端微调，如 Chart-RL 使用可验证奖励强化学习（RLVR）优化推理可靠性，但受限于模型内部表示的粒度；另一类是工具增强，如 Refocus 和 Visual Sketchpad 引入外部工具，但工具集专用性强且推理路径固定。PixelCraft 的切入点在于将“感知”与“操作”解耦：不依赖 LLM 直接生成代码或像素，而是通过微调的接地模型提供精确坐标，由确定性 CV 算子执行编辑，从而在保持高保真度的同时，通过多智能体讨论机制实现非线性的推理探索。

## 核心方法

### 方法参照系

本文问题可置于“工具增强的视觉推理”框架下。标准流程为：LLM 解析查询 → 调用视觉工具（如 OCR、裁剪） → 基于处理后的图像进行文本推理。关键差异在于，标准流程假设工具输出是可靠的且推理路径是线性的，而 PixelCraft 引入了“接地精度”作为工具调用的前置约束，并通过“图像记忆”打破线性推理的刚性。

### 高保真接地与 CV 算子协同

传统方法中，LLM 直接生成裁剪坐标或代码，常因缺乏像素级精度导致工具执行失败。PixelCraft 在此环节引入一个微调的 Qwen2.5-VL-3B 模型作为“智能眼”，其输出为文本引用到像素坐标的映射。该坐标驱动经典 CV 算子（如 OpenCV 的裁剪、掩码函数）执行操作。设查询 $Q$ 指向图像 $I$ 中的区域 $R$，接地模型输出坐标 $C = (x_1, y_1, x_2, y_2)$，CV 算子 $T$ 执行 $I' = T(I, C)$。这一设计解决了 LLM 生成代码时常见的语法错误与坐标漂移问题，将视觉编辑的误差从语义层转移至确定性的算法层，确保了中间视觉线索的高保真度。

### 规划器管理的非线性图像记忆

线性 Visual CoT 将历史图像顺序追加至上下文，导致长序列注意力分散且无法回溯。PixelCraft 引入规划器（Planner）管理的图像记忆 $M = \{ (I_k, d_k) \}_{k=1}^N$，其中 $I_k$ 为中间图像，$d_k$ 为描述。规划器在每一步 $t$ 不生成新图像，而是从 $M$ 中检索最相关的历史图像 $I_{t'}$ 作为当前推理的输入。形式化地，当前状态 $S_t$ 由查询 $Q$、当前子任务 $q_t$ 及检索图像 $I_{t'}$ 构成：

$$ S_t = f(Q, q_t, \text{Retrieve}(M, q_t)) $$

这一机制允许模型在遇到矛盾时回溯至早期步骤（如重新裁剪不同子图），而非被迫沿错误路径继续。它解决了线性推理在复杂多分支问题上的认知刚性，同时通过选择性召回而非全量输入，降低了长上下文带来的计算开销与注意力稀释。

## 实验评估

实验在 CharXiv、ChartQAPro、EvoChart 及 Geometry3K 辅助线子集上进行，基线包括 Direct Answer、CoT、Debate、Reconcile 及 Refocus。PixelCraft 在 GPT-4o 骨干下，CharXiv 准确率达 55.2%，较 CoT 基线 52.51% 提升 2.69 个百分点；ChartQAPro 达 58.83%，较 CoT 57.85% 提升 0.98 个百分点。在 Geometry3K 上，GPT-4o 的准确率从 CoT 的 17.19% 提升至 26.56%，显示其在几何推理上的显著优势。

| 方法 | CharXiv (GPT-4o) | ChartQAPro (GPT-4o) | Geometry3K (GPT-4o) |
| :--- | :--- | :--- | :--- |
| CoT | 52.51 | 57.85 | 17.19 |
| Refocus | 56.52 | 68.64 | - |
| PixelCraft | 55.2 | 58.83 | 26.56 |

消融实验显示，工具智能体（TA）贡献最大，移除后 CharXiv 准确率从 68.1% 降至 63.8%（注：此处数据来自 Table 4 的 Claude-3.7-sonnet 行，GPT-4o 对应数据未在表格中明确列出，但趋势一致）。视觉批评者（VC）和规划批评者（PC）的加入分别带来 0.9 和 1.5 个百分点的提升，表明自我修正机制对减少视觉错误至关重要。评估协议采用 LLM-as-a-judge（GPT-4.1-mini），未报告置信区间，且缺乏与 RLVR 类方法（如 Chart-RL）的直接对比，限制了跨范式比较的有效性。

## 关联研究分析

从方法设计看，PixelCraft 与 Refocus 的核心差异在于工具执行的确定性。Refocus 依赖 LLM 生成 Python 代码进行图像处理，代码错误率较高且难以调试；PixelCraft 通过微调接地模型提供坐标，由预定义的 CV 算子执行，消除了代码生成环节的不稳定性。这一选择源于结构化图像对像素精度的极端要求，但代价是工具集封闭，无法处理 CV 算子未覆盖的非标准图表元素（如复杂 3D 图表或手绘草图）。

从推理范式看，PixelCraft 与 Chart-RL 代表了“架构优化”与“训练优化”的两条路径。Chart-RL 通过 RLVR 在训练阶段强化数值推理的可靠性，适用于静态问答；PixelCraft 通过多智能体讨论与图像记忆在推理阶段实现动态探索，适用于需要多步视觉操作的复杂任务。两者在 CharXiv 上的表现未直接对比，但 PixelCraft 在 Geometry3K 上的优势表明，对于依赖视觉线索（如辅助线）的任务，推理时的动态操作比训练时的静态奖励更有效。

## 总结

PixelCraft 旨在解决结构化图像中因感知精度不足和推理路径刚性导致的错误累积问题。其切入点在于将视觉编辑从 LLM 的语义生成解耦为“接地模型定位 + CV 算子执行”，并通过规划器管理的图像记忆实现非线性回溯。实验证明，该方法在 GPT-4o 骨干下将 Geometry3K 辅助线子集的准确率从 17.19% 提升至 26.56%，CharXiv 准确率较 CoT 提升 2.69 个百分点。然而，其性能高度依赖预定义的 CV 算子库，当面对算子未覆盖的图表结构时，系统缺乏自适应生成新工具的能力。当图表类型超出预定义算子集时，接地模型能否通过零样本泛化生成新的操作指令，论文未给出回答。
