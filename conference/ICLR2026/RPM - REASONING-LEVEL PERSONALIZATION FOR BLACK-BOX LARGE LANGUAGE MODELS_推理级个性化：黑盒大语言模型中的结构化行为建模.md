# ICLR2026最新论文 ｜RPM: REASONING-LEVEL PERSONALIZATION FOR BLACK-BOX LARGE LANGUAGE MODELS ｜推理级个性化：黑盒大语言模型中的结构化行为建模

研究机构：韩国延世大学

作者：Jieyong Kim、Tongyoung Kim、SooJin Yoon 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_72695644)

> 黑盒大语言模型（LLM）因参数不可访问，难以实现深度个性化，现有方法仅能匹配最终输出，无法捕捉用户行为背后的决策逻辑。本文提出推理级个性化范式，通过从原始行为数据自动发现用户特定的结构化推理路径，将个性化从响应匹配提升至逻辑对齐。RPM框架通过特征提取、因子聚类与统计赋值构建用户模型，并基于特征检索引导推理生成。该方法在四个基准上显著优于响应级基线，但其依赖LLM自身能力进行特征提取的循环依赖风险及跨骨干迁移的稳定性边界尚存疑。

## 研究背景

当用户与黑盒LLM交互时，模型无法访问内部参数，只能依赖输入上下文进行适配。检索增强生成（RAG）通过注入历史上下文实现非参数化适配，但其检索机制基于文本相似度，往往引入语义相关但逻辑无关的噪声样本。这些噪声样本无法揭示用户偏好与响应之间的因果链条，导致模型仅能学习输入与输出的浅层相关性，即响应级个性化的局限。

该局限在长程交互与复杂任务中尤为突出，表现为过度个性化引发的幻觉与不可解释性。现有黑盒个性化方法分为检索类（如HYDRA、RAG）与提示优化类（如Fermi），前者依赖效用重排序或相似度匹配，后者依赖启发式模板或迭代反馈，两者均未显式建模用户行为中的推理结构。本文切入点在于：将用户历史转化为结构化推理先验，通过自动发现用户特定的推理逻辑，实现黑盒场景下的推理级对齐。

## 核心方法

### 方法参照系

黑盒LLM个人化的标准流程是构建用户特定上下文 $c_u(q')$ 并注入提示。RPM的关键差异在于，$c_u(q')$ 不再是原始文本或优化后的提示，而是由用户历史自动推导出的结构化推理路径集合，其构建过程包含特征提取、因子聚类与统计赋值三个前置步骤。

### 结构化用户模型构建

传统方法将用户历史视为静态文本序列，RPM将其转化为可统计的语义结构。设计动机在于解决原始查询中无关元素引入的噪声问题。首先，利用LLM从每个查询 $q_i$ 中提取响应影响特征 $G_{q_i} = \{f_j\}$，其中 $f_j = (\text{name}_j, \text{context}_j, \text{factor}_j)$。随后，通过LLM聚类将特征分组为因子 $F^{(m)}$，并赋予统计意义 $\theta^{(m)}$。对于离散响应任务，计算倾向分数：

$$ P(y | F^{(m)}) = \frac{\sum_{i=1}^N I(y_i = y) I(F^{(m)} \cap G_{q_i} \neq \emptyset)}{\sum_{i=1}^N I(F^{(m)} \cap G_{q_i} \neq \emptyset)} $$

该公式量化了因子存在时特定响应的条件概率，将隐式偏好显式化为可计算的统计量。

### 推理对齐生成

基于结构化模型，RPM构建个性化推理路径 $r_{q_i}$ 并存储于推理增强记忆 $S_u$。设计动机在于解决通用CoT缺乏用户特定逻辑的问题。推理时，利用特征 $G_{q'}$ 通过余弦相似度检索 $S_u$ 中的相关样本，将检索到的推理路径作为少样本示例注入提示。该机制通过特征匹配而非文本匹配检索，确保示例与当前查询在逻辑结构上的一致性，从而引导LLM生成符合用户决策模式的推理与响应。

## 实验评估

实验在LaMP-2/3/5与GOQA四个基准上进行，基线覆盖Zero-shot、ICL、RAG、PAG、HYDRA与Fermi，缺失参数化方法（因黑盒约束合理）及最新SOTA如CARD。主结果显示，RPM在LaMP-2 Acc达0.561，较RAG基线0.526提升0.035；在GOQA Acc达0.852，较HYDRA基线0.800提升0.052。

| 数据集 | 方法 | LaMP-2 Acc | LaMP-3 MAE | LaMP-5 R-1 | GOQA Acc |
|---|---|---|---|---|---|
| LaMP-2 | RAG | 0.526 | - | - | - |
| LaMP-2 | RPM | 0.561 | - | - | - |
| GOQA | HYDRA | - | - | - | 0.800 |
| GOQA | RPM | - | - | - | 0.852 |

消融实验表明，移除推理生成步骤（RPM w/o Reasoning）导致LaMP-2 Acc降至0.510，GOQA Acc降至0.820，证实显式推理路径的必要性。特征检索策略中，基于特征 $G_{q'}$ 的检索优于基于查询 $q'$ 的检索，在GOQA上提升0.013（0.852 vs 0.839），验证了结构化特征作为检索键的有效性。

评估边界方面，实验仅使用gpt-4o-mini作为骨干，未验证跨模型泛化性；指标未包含推理延迟与Token成本，无法评估实时部署可行性；人工评估显示RPM在可解释性上优于基线，但幻觉率仍有3.5%-4.75%，表明结构化推理未完全消除事实性风险。

## 关联研究分析

从问题动机看，RPM与HYDRA均针对RAG的检索噪声问题，但HYDRA依赖训练效用重排序器，RPM依赖无训练的特征匹配。HYDRA的效用标准需额外参数训练，增加部署复杂度；RPM的特征检索无需训练，但依赖LLM特征提取质量。这一差异根源在于任务特性：HYDRA适用于数据充足可训练场景，RPM适用于黑盒冷启动场景。

从方法设计看，RPM与Fermi均属于提示优化路线，但Fermi通过迭代反馈优化提示文本，RPM通过结构化推理路径引导生成。Fermi的优化目标是提示质量，RPM的优化目标是推理逻辑一致性。Fermi在GOQA上Acc为0.800，RPM为0.852，差距0.052。这一差距可能源于Fermi的提示优化无法捕捉用户行为中的深层逻辑结构，而RPM的因子统计提供了更稳定的推理锚点。

## 总结

RPM解决的核心矛盾是黑盒LLM个性化中响应匹配与逻辑对齐的脱节。现有方法因缺乏用户特定推理结构建模，导致个性化浅层化与不可解释。RPM通过特征-因子-统计的三层结构化建模，将隐式行为转化为显式推理先验，在LaMP-2与GOQA上分别提升0.035与0.052。其边界在于特征提取依赖LLM自身能力，可能引入循环依赖；跨骨干迁移实验显示gpt-3.5-turbo上RPM性能低于gpt-4o，暗示方法对骨干推理能力敏感。当用户历史规模扩大至千级交互时，特征聚类的计算开销与统计稳定性是否仍能支撑推理级个性化的有效性，论文未给出回答。
