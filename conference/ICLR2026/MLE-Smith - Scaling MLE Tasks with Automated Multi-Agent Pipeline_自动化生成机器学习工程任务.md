# ICLR2026最新论文 ｜MLE-Smith: Scaling MLE Tasks with Automated Multi-Agent Pipeline ｜自动化生成机器学习工程任务

研究机构：美国佐治亚理工学院、美国斯坦福大学

作者：Rushi Qiang、Yuchen Zhuang、Anikait Singh 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.07307)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.07307)

> 机器学习工程（Machine Learning Engineering, MLE）智能体面临高质量训练与评估数据稀缺的瓶颈，现有基准依赖人工策展，难以规模化扩展。MLE-Smith 通过多智能体流水线从原始数据集逆向构建竞赛级任务，解决了任务生成的自动化与质量验证问题。该框架实现了从数据到可执行任务的端到端转换，但生成任务的难度分布与真实竞赛的细微差异仍需进一步量化。

## 研究背景

MLE 智能体需完成从数据预处理、特征工程到模型调优的全流程，其能力评估依赖于可执行、可验证的任务环境。传统基准如 MLE-Bench 和 MLE-Dojo 虽提供了标准化接口，但任务集是静态的，新增任务需人工设计竞赛规则、编写评估脚本并调试环境，这一过程耗时且不可持续。任务质量需同时满足结构完整性（文件与脚本可执行）、语义合理性（目标与数据匹配）及经验可解性（基线模型能产生有效性能差异），单一维度的检查无法保证任务的有效性。

现有自动化任务生成方法多聚焦于代码补全或简单问答，缺乏对复杂工程工作流的覆盖。SWE-Smith 等研究通过 Bug 注入生成软件工程任务，但 MLE 任务涉及数据划分、指标计算等多组件协同，逆向构建难度更高。MLE-Smith 的切入点在于将任务生成解耦为生成、验证、执行三个独立阶段，利用多智能体分工处理不同粒度的约束，从而在自动化规模与任务质量间取得平衡。

## 核心方法

### 多智能体生成流水线

MLE-Smith 采用 Brainstormer、Designer 和 Refactor 三个智能体串联工作。Brainstormer 基于数据集探索生成多个候选任务假设，Designer 将假设实例化为包含预处理脚本、评估指标和测试数据的完整任务包，Refactor 则统一所有任务的文件结构与接口规范。该流程解决了单智能体在处理长程依赖时易丢失上下文或陷入局部最优的问题，通过模块化分工确保每个环节的输出可被独立验证。

### 混合验证机制

为确保任务质量，MLE-Smith 引入三层验证：断言（Assertions）、审查（Reviews）和执行验证（Execution-based Validation）。断言通过确定性代码检查文件结构与脚本可执行性；审查利用 LLM 评估任务描述的语义清晰度与指标合理性；执行验证则在 MLE-Dojo 环境中运行基线智能体，确认任务可解且性能指标对模型质量敏感。这一机制解决了静态检查无法捕捉语义缺陷、纯执行检查无法定位具体错误来源的问题。

$$
V_{task} = A_{struct} \cdot R_{sem} \cdot E_{sol}
$$

其中 $A_{struct}$ 为结构断言通过标志，$R_{sem}$ 为语义审查得分，$E_{sol}$ 为执行验证中的基线性能达标率。任务仅在三项均满足阈值时被保留，确保生成的任务在结构、语义和可解性上均无缺陷。

### 执行接地验证

执行验证阶段模拟真实智能体交互，通过 ReAct 风格代理在环境中执行代码并获取反馈。该阶段不仅验证任务可运行，还通过监控基线模型的性能分布来确保任务具有区分度。若基线模型表现过强或过弱，任务将被标记为难度异常并退回 Designer 重新设计。这一设计解决了合成任务常出现的“平凡可解”或“不可解”问题，确保任务难度落在有效区间内。

## 实验评估

实验在 50 个 MLE-Smith 生成任务（Smith set）和 50 个 MLE-Dojo 人工任务（Dojo set）上评估 8 个主流 LLM。基线覆盖 OpenAI、Google 和 DeepSeek 的最新模型，但未对比其他任务生成方法或不同验证策略的消融实验。

| 模型 | Dojo Set Elo | Smith Set Elo | Combined Set Elo |
|---|---|---|---|
| Gemini-2.5-Pro | 1272.0 | 1346.9 | 1214.3 |
| GPT-4o-mini | 659.3 | 549.5 | 716.8 |
| o4-mini | 1019.9 | 1075.6 | 1082.9 |

生成任务与人工任务的模型排名高度一致，Pearson 相关系数达 0.982，Spearman 秩相关系数为 0.952。这表明 MLE-Smith 生成的任务能有效区分模型能力，且难度分布与真实竞赛相似。

论文未提供消融实验数据，无法量化各验证层（断言、审查、执行）对最终任务质量的独立贡献。执行验证阶段的计算成本也未报告，限制了对其规模化潜力的评估。代码与超参数未公开，可复现性依赖 MLE-Dojo 环境的可用性。

## 关联研究分析

与 SWE-Smith 相比，MLE-Smith 的核心差异在于任务结构的复杂性。SWE-Smith 通过注入 Bug 生成任务，验证主要依赖单元测试通过；而 MLE 任务涉及数据划分、特征工程等多步骤，单一测试无法覆盖所有组件的正确性。MLE-Smith 引入语义审查层，专门处理数据与目标的匹配问题，这是 SWE 任务中不存在的约束。这一差异源于 MLE 任务的开放性：同一数据集可支持多种学习目标，需额外机制确保目标与数据的语义一致性。

与 TaskCraft 等通用任务生成框架相比，MLE-Smith 更强调执行接地的深度。TaskCraft 侧重任务多样性，验证主要基于格式检查；而 MLE-Smith 将执行验证作为核心环节，通过基线模型的性能反馈来校准任务难度。这一设计选择反映了 MLE 领域对“可解性”的更高要求：任务不仅需格式正确，还需确保智能体能在合理步数内产生有效性能提升。执行验证的计算开销是否限制了生成规模，论文未给出明确回答。

## 总结

MLE-Smith 解决了 MLE 智能体训练数据稀缺的核心矛盾，通过多智能体流水线与混合验证机制实现了从原始数据集到竞赛级任务的自动化转换。其关键创新在于将任务质量分解为结构、语义、可解性三个独立维度，并通过执行接地验证确保任务难度落在有效区间。实验显示生成任务与人工基准的模型排名高度一致（Pearson r=0.982），证明了其有效性。然而，论文未报告执行验证的计算成本，也未提供消融实验以量化各验证层的贡献。当数据集规模扩大至数千个时，执行验证阶段的计算开销是否会成为瓶颈，论文未给出回答。
