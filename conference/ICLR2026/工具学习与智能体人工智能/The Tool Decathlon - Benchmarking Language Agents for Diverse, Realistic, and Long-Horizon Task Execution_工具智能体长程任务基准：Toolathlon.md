# ICLR2026最新论文 ｜The Tool Decathlon: Benchmarking Language Agents for Diverse, Realistic, and Long-Horizon Task Execution ｜工具智能体长程任务基准：Toolathlon

研究机构：香港科技大学、美国卡内基梅隆大学

作者：Junlong Li、Wenshuo Zhao、Jian Zhao 等 21 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.25726)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.25726)

> 工具增强大语言模型（Tool-Augmented LLMs）在真实场景中的长程任务执行能力缺乏高保真评估手段。现有基准多依赖模拟环境或简化状态，无法反映跨应用协调与动态状态管理的复杂性。本文构建了涵盖32个真实应用、604个工具及108个模糊指令任务的Toolathlon基准，通过确定性脚本验证最终环境状态。该基准揭示了当前SOTA模型在真实长程任务中的显著短板，但其对模型内部决策过程的诊断能力仍受限于黑盒评估协议。

## 研究背景

当智能体需要在邮件、数据库与文件系统间切换以完成行政任务时，其面临的不仅是工具调用的准确性，更是环境状态随交互演化的复杂性。这种复杂性源于部分可观测马尔可夫决策过程（POMDP）中状态空间 $S$ 与观测空间 $O$ 的非线性映射，模型必须从模糊指令与环境反馈中推断用户意图，并在长轨迹中维持对中间状态的追踪。

工具增强范式旨在突破大语言模型静态参数化知识的局限，但早期评估基准如BFCL与τ-Bench主要关注单步或短程函数调用的准确性，依赖模拟API或语言模型模拟环境。这种设计虽保证了可复现性，却剥离了真实软件中环境状态初始化、并发干扰及长上下文依赖等关键挑战。随着Model Context Protocol (MCP) 的普及，工具生态从封闭API转向开放、异构的应用网络，现有基准在环境真实性与任务长程性上的不足日益凸显，无法有效区分模型在真实工作流中的规划与恢复能力。

Toolathlon 的切入点在于将评估重心从“工具调用正确性”转移至“环境状态一致性”。通过引入真实远程服务与本地容器化应用，该基准构建了包含预置状态、模糊指令及跨应用依赖的任务集，旨在测试智能体在动态、噪声环境下的端到端执行能力，填补了从模拟基准到真实部署之间的评估空白。

## 核心方法

### 任务形式化与环境构建

Toolathlon 将每个任务定义为 POMDP $(S, A, O, T, R, U)$，其中状态空间 $S$ 由真实软件（如 Snowflake、Canvas）的运行时数据构成，动作空间 $A$ 为可用的 MCP 工具集。与模拟基准不同，该框架强调环境状态的真实性与可初始化性。对于难以在远程服务中复现的复杂状态（如包含数十名学生的课程），采用本地容器化部署开源软件（如 Poste.io、WooCommerce）进行模拟。这种设计确保了环境状态在每次评估前可通过脚本精确重置，解决了真实远程环境状态不可复现的难题。

$$
R(s_t) = \mathbb{1}[\text{State}(s_t) \approx \text{GroundTruth}(s_T)]
$$

该奖励函数 $R$ 不依赖中间步骤的轨迹匹配，而是直接比较最终环境状态 $s_T$ 与预定义的真值状态。这种执行式评估（Execution-based Evaluation）消除了 LLM 裁判的主观性，确保评估结果基于客观、确定性的规则，从而提高了基准的可靠性与可复现性。

### 模糊指令与状态初始化机制

传统基准通常提供显式的步骤指导，而 Toolathlon 的任务指令模仿真实用户查询，具有模糊性与歧义性。例如，指令可能仅要求“根据简历更新 HR 记录”，而不指定具体字段或格式，模型需从环境中的现有数据示例推断意图。这种设计迫使智能体具备从观察中推断意图的能力，而非仅执行预定义的脚本。

$$
\pi(a_t | o_{1:t}, u) = \text{Policy}(a_t | \text{Infer}(u, s_{1:t}))
$$

策略 $\pi$ 依赖于对模糊指令 $u$ 与环境观测 $o_{1:t}$ 的联合推断。状态初始化脚本在任务开始前预置特定的环境状态（如预填充的邮件箱或数据库记录），使得任务难度不仅取决于指令复杂度，还取决于初始状态的丰富度与干扰项数量。这一机制将环境配置纳入评估协议，揭示了模型在处理复杂初始状态时的鲁棒性差异。

## 实验评估

实验在 Toolathlon 的 108 个任务上进行，涵盖商业模型（Claude-4.5-Sonnet, GPT-5）与开源模型（DeepSeek-V3.2-Exp, Qwen-3-Coder）。基线覆盖主流 LLM，但未包含专门针对长程规划的强化学习训练模型（如 Tool Zero），限制了训练策略对性能的贡献分析。

| 模型 | Pass@1 (%) | Pass@3 (%) | Pass^3 (%) | Avg Turns |
| :--- | :--- | :--- | :--- | :--- |
| Claude-4.5-Sonnet | 38.6 | 51.9 | 20.4 | 20.2 |
| GPT-5 | 30.6 | 43.5 | 16.7 | 18.7 |
| DeepSeek-V3.2-Exp | 20.1 | 27.8 | 12.0 | 20.2 |
| Qwen-3-Coder | 13.0 | 22.2 | 5.6 | 15.2 |

Claude-4.5-Sonnet 以 38.6% 的成功率领先，但远低于人类专家水平，表明当前模型在真实长程任务中仍存在显著瓶颈。开源模型表现更弱，DeepSeek-V3.2-Exp 仅为 20.1%。Pass@3 与 Pass^3 之间的巨大差距（如 Claude-4.5-Sonnet 的 51.9% vs 20.4%）揭示了模型在多次尝试中缺乏一致性，即模型虽具备部分能力覆盖，但无法稳定复现成功轨迹。

消融分析显示，增加推理努力（如 GPT-5-high）并未带来性能提升，反而可能因过度思考导致效率下降。这表明在智能体任务中，探索新观察（Observation）比内部推理（Reasoning）更为关键。此外，长上下文建模与工具调用错误追踪是主要失败模式，模型在处理超过 20 轮交互时容易丢失早期状态信息，导致级联失败。

评估边界方面，Toolathlon 依赖确定性脚本验证最终状态，无法诊断中间步骤的逻辑错误。代码已开源，但环境初始化脚本的复杂性可能影响跨硬件平台的复现性。未报告计算成本与延迟，限制了其在实时部署场景中的评估价值。

## 关联研究分析

从问题动机看，Toolathlon 与 MCP-Atlas 同属 MCP 生态基准，但前者侧重端到端状态验证，后者侧重原子声明验证。MCP-Atlas 将答案分解为独立可验证的声明，适合细粒度部分信用评分，但难以捕捉跨应用状态依赖。Toolathlon 通过整体状态匹配，更贴近真实工作流的完整性要求，但牺牲了过程诊断能力。这种差异源于任务特性：MCP-Atlas 面向查询类任务，而 Toolathlon 面向执行类任务，后者对状态一致性的要求更高。

从方法设计看，Toolathlon 与 SWE-Bench 共享容器化隔离与执行式评估框架，但 SWE-Bench 局限于代码修复，而 Toolathlon 扩展至非代码领域（如金融、教育）。SWE-Bench 的环境状态相对静态（代码仓库），而 Toolathlon 引入动态状态初始化（如实时数据库），增加了环境的不确定性。这种扩展揭示了模型在非代码领域长程任务中的脆弱性，但也引入了环境配置复杂度的变量，使得跨基准比较需谨慎。

## 总结

Toolathlon 旨在解决真实长程任务评估中环境真实性与可复现性的矛盾。通过引入真实软件状态与模糊指令，该基准突破了模拟基准的局限，揭示了当前 SOTA 模型在跨应用协调与状态追踪上的显著短板。实验表明，最佳模型 Claude-4.5-Sonnet 仅取得 38.6% 的成功率，且 Pass@3 与 Pass^3 的差距暴露了模型一致性的不足。然而，该基准依赖黑盒状态验证，无法区分失败源于规划错误还是执行错误，且未包含训练策略的对比。当环境状态复杂度进一步增加时，模型是否具备从错误中恢复并动态重规划的能力，仍是该基准未能充分揭示的关键问题。
