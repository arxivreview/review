# ICLR2026最新论文 ｜Benchmarking LLM Tool-Use in the Wild ｜野性工具使用基准

作者：Peijie Yu、Wei Liu、Yifan Yang 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.06185)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.06185)

> 现有工具调用基准因任务过于理想化，高估了大语言模型在真实多轮交互中的鲁棒性。本文通过引入真实用户行为中的组合任务、隐式意图与指令转换，构建了 WildToolBench 基准。其核心贡献在于证明当前最先进模型在真实场景下的会话准确率不足 15%，揭示了“工具执行”与“用户理解”能力的脱节。该基准填补了评估生态中“用户行为动态性”的空白，但其依赖人工标注的构建方式限制了规模化扩展，且未验证针对特定强化学习方法的改进效果。

## 研究背景

当大语言模型（LLM）作为智能体执行多步工具调用时，其决策依赖于对当前用户指令的准确解析。然而，真实用户交互并非孤立的指令提交，而是包含上下文依赖、指代消解及意图切换的连续对话。这种动态性要求模型具备长程上下文推理与策略动态切换能力，即从“被动执行工具”转向“主动理解用户”。

当前主流基准如 BFCL 与 τ-Bench 虽已支持多轮交互，但其任务设计存在两个根本缺陷：一是任务间缺乏语义关联，每个任务独立同分布，忽略了真实对话中信息跨轮次传递的特性；二是用户意图显式且完整，未模拟真实场景中常见的信息省略、模糊指代及指令类型频繁切换。这导致模型在基准上表现优异，但在真实环境中因无法处理“野性”（Wild）用户行为而频繁失败。本文的切入点在于，将评估重心从“工具调用的算法复杂度”转移至“用户行为的自然复杂度”，通过构建基于真实日志分布的基准，量化模型在隐式意图推理与指令转换适应上的能力缺口。

## 核心方法

### 方法参照系

本文问题属于多轮工具调用评估基准构建。标准流程通常涉及任务生成、工具集定义及执行轨迹标注。与现有基准的关键差异在于，WildToolBench 不追求工具调用步骤的极端复杂度，而是通过模拟真实用户行为的“组合性”、“隐式性”与“转换性”，构建高保真的交互环境，并引入基于拓扑结构的细粒度评估指标。

### 基于拓扑枚举的编排评估

传统基准仅评估最终答案的正确性，无法区分“正确但低效”与“正确且高效”的工具调用路径。WildToolBench 引入“枚举-匹配-评分”三阶段管线，将工具调用建模为有向无环图（DAG）。首先，通过深度优先拓扑排序枚举所有合法执行路径；其次，增量匹配 LLM 生成的调用序列；最后，计算最优路径率（OP Rate）与完成进度率（AP Rate）。

$$
OP_{rate} = \frac{\sum_{i=1}^{N} \mathbb{I}[Path_i = Path_{opt}]}{N}
$$

该公式计算 LLM 生成的路径中，深度最小（即步骤最少）的路径占比。这一设计解决了传统评估无法量化“工具编排效率”的问题，能够识别模型是否构建了冗余或次优的调用拓扑，从而更精确地反映模型在组合任务中的规划能力。

### 隐式意图与指令转换建模

针对真实对话中信息分散与意图多变的特点，WildToolBench 在数据构建中显式注入三类挑战：部分信息（Partial Information）、共指引用（Coreferential Reference）及长程依赖（Long-Range Dependency）。同时，将任务划分为单工具（$g_{single}$）、多工具（$g_{multi}$）、闲聊（$g_{chat}$）及澄清（$g_{clarify}$）四类，并控制其切换频率。

$$
P(Switch) = \frac{\sum_{t=1}^{T} \mathbb{I}[Type(u_t) \neq Type(u_{t-1})]}{T-1}
$$

该公式量化对话中指令类型切换的频率。通过人工标注确保切换符合真实用户日志分布，该设计迫使模型在每一轮对话中动态判断当前意图类型，并选择相应的策略（如调用工具、直接回答或反问澄清），从而评估模型在“野性”交互中的策略适应能力。

## 实验评估

实验在 WildToolBench 上评估了 57 个主流 LLM，涵盖专有通用、开源通用及开源专用模型。基线覆盖广泛，但缺失针对特定强化学习训练方法（如 Tool-R1）的专项对比，主要聚焦于模型原生能力。

| 模型类别 | 代表模型 | Task Accuracy (%) | Session Accuracy (%) |
| :--- | :--- | :--- | :--- |
| 专有通用 | o1 | 94.92 | 14.45 |
| 专有通用 | Claude-4-Sonnet | 52.34 | 12.50 |
| 开源通用 | GLM-4.5 | 44.53 | 7.81 |
| 开源专用 | xLAM-2-70B | 64.45 | 4.69 |

数据显示，尽管 o1 在任务准确率上达到 94.92%，但其会话准确率仅为 14.45%，表明模型在单步任务上表现良好，但在维持整个对话会话的正确性上存在巨大差距。开源专用模型 xLAM-2-70B 虽在任务准确率上较高（64.45%），但会话准确率最低（4.69%），揭示了专用模型在泛化性与上下文管理上的脆弱性。

消融分析显示，长程依赖任务是所有模型的最弱项，无模型准确率超过 50%。在工具编排评估中，混合工具使用（$g_{multi}^{S+P}$）的任务准确率仅为 25%，远低于顺序多步任务，表明模型难以处理并行与串行混合的复杂拓扑。此外，推理模型（如 o1, Gemini-2.0-Thinking）在隐式意图推理上显著优于非推理模型，但其在指令转换适应性上并未表现出绝对优势，暗示推理能力与策略切换能力并非完全正相关。

评估边界方面，WildToolBench 依赖人工标注的真实日志分布，构建成本高，难以快速扩展至新领域。代码已开源，但超参数配置未详细披露，且未提供针对特定训练策略（如 RLVR）的消融实验，限制了其对训练方法改进效果的直接指导意义。

## 关联研究分析

从问题动机看，WildToolBench 与 BFCL 的核心差异在于对“用户行为”的建模深度。BFCL 关注工具调用的语法正确性与参数填充，任务间独立且意图显式；而 WildToolBench 强调意图的隐式性与动态性，要求模型从上下文中推断缺失信息并适应指令切换。这一差异源于任务特性的不同：BFCL 旨在评估基础工具调用能力，而 WildToolBench 旨在评估智能体在真实交互中的鲁棒性。WildToolBench 揭示了模型在“用户理解”层面的短板，这是 BFCL 等基准无法捕捉的盲区。

从方法设计看，WildToolBench 与 τ-Bench 均支持多轮交互，但评估指标存在显著差异。τ-Bench 主要依赖最终答案的正确性，而 WildToolBench 引入了基于拓扑枚举的 OP 与 AP 率，能够细粒度评估工具编排效率。这一设计差异使得 WildToolBench 能够区分“正确但低效”与“正确且高效”的调用路径，更精确地反映模型的规划能力。然而，WildToolBench 未探索基于过程奖励模型（PRM）的评估方法，这可能限制了其对多步调用中信用分配问题的深入分析。

## 总结

WildToolBench 旨在解决现有工具调用基准因任务理想化而高估模型鲁棒性的核心矛盾。其切入点在于将评估重心从工具调用复杂度转移至用户行为动态性，通过引入组合任务、隐式意图与指令转换，构建了高保真的真实交互环境。实验证明，当前最先进模型在真实场景下的会话准确率不足 15%，揭示了“工具执行”与“用户理解”能力的脱节。本文的边界在于依赖人工标注的构建方式限制了规模化扩展，且未验证针对特定强化学习方法的改进效果。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
