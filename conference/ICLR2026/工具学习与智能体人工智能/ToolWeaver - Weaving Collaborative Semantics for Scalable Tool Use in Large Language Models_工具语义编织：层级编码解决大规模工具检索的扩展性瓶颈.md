# ICLR2026最新论文 ｜ToolWeaver: Weaving Collaborative Semantics for Scalable Tool Use in Large Language Models ｜工具语义编织：层级编码解决大规模工具检索的扩展性瓶颈

研究机构：中国科学院、中国科学院大学

作者：Bowen Fang、Wen Ye、Yunyue Su 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.21947)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.21947)

> 大规模工具库场景下，传统“一工具一Token”的生成式方法面临词表线性膨胀与语义隔离的双重困境，导致模型难以泛化至未见工具且易引发灾难性遗忘。ToolWeaver 通过引入协作感知的残差向量量化机制，将工具映射为层级离散代码序列，在保持对数级词表扩展的同时，利用共享代码的密集共现信号学习工具间的协作关系。该方法在 ToolBench 基准上显著优于现有生成式与检索式基线，但其有效性主要局限于静态工具集下的离线训练场景，动态环境下的鲁棒性仍存疑。

## 研究背景

当 LLM 面对数万级 API 时，直接将其映射为独立 Token 会导致词表规模线性增长，不仅增加内存开销，更因每个 Token 语义孤立而阻碍模型学习工具间的协作逻辑。这种扁平化表示使得模型在复杂任务中难以推断如“天气”与“空气质量”之间的隐含依赖，必须依赖稀疏的 ID 共现统计，导致推理链条断裂。为突破此局限，残差量化变分自编码器（Residual-Quantized Variational AutoEncoder, RQ-VAE）提供了一种层级压缩路径，通过多级码本将高维语义映射为紧凑的离散序列，但其原始形式仅关注语义重构，缺乏对工具实际使用模式的建模。

现有工具增强范式主要分为检索式与生成式两类。检索式方法（如 ToolLLM）依赖外部检索器，受限于上下文窗口且流程复杂；生成式方法（如 ToolGen）虽实现端到端调用，但“一工具一Token”策略在大规模场景下引发严重的扩展性危机与语义瓶颈。ToolWeaver 的切入点在于重构工具表示本身：不再将工具视为原子单元，而是通过无监督的协作感知量化过程，生成兼具内在功能语义与外在共现模式的层级代码，从而在词表规模与语义表达力之间取得平衡。

## 核心方法

### 生成式工具调用参照系

主流生成式框架将工具选择重构为下一词元预测任务，通过微调 LLM 直接输出工具标识符。该范式的关键差异在于标识符的构造方式：传统方法采用扁平化唯一 Token，而 ToolWeaver 采用由 $L$ 个码本构成的层级序列 $[\iota_1, \dots, \iota_L]$，将词表扩展量从 $N$ 降至 $L \times K$，实现了从线性到对数的压缩。

### 协作感知残差量化

针对传统 RQ-VAE 仅捕捉语义相似性而忽略工具协作关系的缺陷，ToolWeaver 在量化损失中引入图拉普拉斯正则化项。该设计动机在于：工具间的功能协作（如天气与空气质量）往往比单一语义相似度更具预测价值，但传统方法无法从稀疏的 ID 共现中有效学习。通过构建工具共现矩阵 $C$ 并计算余弦相似度 $A_{uv}$，模型在量化过程中强制功能相关的工具在潜在空间中邻近。其核心训练目标为：

$$ \mathcal{L} = \mathcal{L}_{rec} + \mathcal{L}_{quant} + \lambda \sum_{u,v} A_{uv} \| \hat{z}_u - \hat{z}_v \|^2 $$

其中 $\mathcal{L}_{rec}$ 为重构损失，$\mathcal{L}_{quant}$ 为量化损失，$\lambda$ 平衡协作结构对齐强度。该公式的物理含义是：在最小化语义重构误差的同时，惩罚高频共现工具在量化表示上的距离，使共享父代码的工具（如 `<T1_1>`）自然聚类，从而让模型从共享代码的密集共现中习得协作模式，而非依赖孤立 ID 的稀疏统计。

### 冲突缓解与生成对齐

为解决层级量化中不同工具映射至相同代码序列的冲突问题，ToolWeaver 在最终码本层引入均匀映射约束，将其建模为最优传输问题，并通过 Sinkhorn-Knopp 算法求解，确保每个工具拥有唯一标识且不破坏语义结构。随后，通过两阶段生成对齐微调：第一阶段学习从查询生成工具代码序列，第二阶段在全轨迹上学习推理-行动-观察循环，仅对助手 Token 计算损失。这一渐进式对齐确保了模型既能准确检索工具，又能执行复杂的多步调用。

## 实验评估

实验基于包含 46,985 个 API 的 ToolBench 基准，涵盖单工具（I1）、单类多工具（I2）及跨类编排（I3）场景。基线覆盖检索式（BM25, EmbSim, ToolRetriever）与生成式（ToolGen）方法，但缺失 RLVR 类基线（如 Tool-R1），限制了与强化学习路线的直接对比。

| 模型 | I1 NDCG@1 | I3 NDCG@1 | I3 SoPR | I3 SoWR |
| :--- | :--- | :--- | :--- | :--- |
| ToolGen | 81.00 | 81.00 | 36.34 | 49.18 |
| ToolWeaver | 91.16 | 88.00 | 52.19 | 59.02 |

ToolWeaver 在 I3 复杂场景下 NDCG@1 达 88.00，较 ToolGen 提升 7 个百分点；SoPR 达 52.19，显著优于 ToolGen 的 36.34，验证了协作语义对多步编排的增益。在通用能力保持方面，ToolWeaver 的 WikiText-2 PPL 为 25.36，远低于 ToolGen 的 104.54，表明层级编码有效缓解了大规模 OOV Token 注入导致的灾难性遗忘。

消融实验未单独报告，但设计决策显示：图拉普拉斯正则化是核心贡献，移除后模型退化为纯语义量化，I3 性能预计大幅下降。均匀映射约束虽增加计算开销，但避免了 ID 冲突导致的检索歧义，是保证唯一性的必要代价。

评估边界方面，实验仅基于静态工具集，未测试工具动态更新或噪声环境下的鲁棒性；指标侧重检索精度（NDCG）与任务成功率（SoPR），缺乏对推理延迟与内存占用的详细报告。代码已开源，但超参数（如 $\lambda$、$K$）的敏感性分析未在正文中展开，可复现性依赖附录细节。

## 关联研究分析

从问题动机看，ToolWeaver 与 ToolGen 同属生成式路线，但 ToolGen 聚焦于将工具知识作为虚拟 Token 注入，忽视了 Token 间的语义关联；ToolWeaver 则通过协作感知量化，将工具间的共现模式内化至代码结构。这一差异源于任务特性：ToolGen 适用于工具间独立性较强的场景，而 ToolWeaver 针对多步依赖任务，其协作信号建模是解决级联失败的关键。

从方法设计看，ToolWeaver 借鉴了 LC-Rec 的 RQ-VAE 框架，但引入了基于共现矩阵的图拉普拉斯正则化，区别于 LC-Rec 的纯语义量化。LC-Rec 旨在解决推荐系统中的 ID 冲突，而 ToolWeaver 旨在解决工具协作推理的语义瓶颈。这种差异暗示：在工具调用场景中，外在使用模式（共现）比内在语义（描述）更具预测力，但论文未验证在工具描述质量极高时，语义量化是否足以替代协作信号。

## 总结

ToolWeaver 旨在解决大规模工具库下生成式方法的扩展性与语义瓶颈矛盾。其切入点在于：传统“一工具一Token”范式无法从稀疏 ID 共现中学习协作关系，而层级编码通过共享代码的密集共现提供了更丰富的监督信号。方法上，ToolWeaver 通过协作感知 RQ-VAE 生成层级代码，并在两阶段对齐中融入 LLM。实验证明，其在 ToolBench I3 场景下 SoPR 达 52.19，PPL 保持 25.36，显著优于 ToolGen。然而，其边界在于：实验仅覆盖静态工具集，未验证动态更新或噪声环境下的鲁棒性；且缺乏与 RLVR 方法的对比，无法确认结构化编码在复杂约束下的泛化上限。当工具库频繁更新时，层级编码的重训练成本是否高于在线强化学习，论文未给出回答。
