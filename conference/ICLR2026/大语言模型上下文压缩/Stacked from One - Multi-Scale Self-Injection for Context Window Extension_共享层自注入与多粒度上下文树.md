> 长上下文处理面临计算复杂度与内存瓶颈的双重限制，现有外推方法或需高昂预训练成本，或牺牲推理效率。SHAREDLLM 通过共享权重的上下层模型架构，将长文本压缩为多粒度树状表示，以最小化参数微调实现超长上下文外推。该方法在 128K 长度下保持低困惑度，但缺乏对压缩信息保真度的独立验证，其树状结构在复杂依赖任务中的泛化能力存疑。

## 研究背景

Transformer 自注意力机制的二次方计算复杂度 $O(T^2)$ 导致长序列推理延迟激增，且 KV Cache 内存占用随序列长度线性增长。为突破上下文窗口限制，研究者通常采用位置编码缩放（如 YaRN）或滑动窗口架构，但这些方法要么需要大规模长文本预训练，要么因特殊注意力模式与 FlashAttention 等高效实现不兼容。SHAREDLLM 的核心切入点在于利用短上下文 LLM 的现有检查点，通过架构改造而非数据扩充来实现长度外推，避免了高昂的预训练成本。

长上下文扩展的主流路线分为直接预训练与适配短窗口模型两类。直接预训练消耗巨大算力，而适配方法如 CEPE 和 Activation Beacon 虽能实现“短训长测”，但前者需额外预热阶段对齐隐藏空间，后者在长距离依赖任务中性能退化。SHAREDLLM 提出自注入机制，将同一 LLM 的前 M 层作为压缩器，剩余层作为解码器，通过共享权重消除隐藏空间差异。这种设计不仅降低了训练成本，还通过树状结构实现查询感知的信息筛选，解决了静态压缩在动态任务中信息利用率低的问题。

## 核心方法

### 自注入架构参照系

本文问题属于长上下文外推，与通用压缩流程的关键差异在于：压缩器与解码器共享同一模型权重，且压缩过程发生在推理预填充阶段而非独立训练阶段。传统编码器-解码器架构（如 T5）需独立训练编码器，而 SHAREDLLM 利用短上下文 LLM 的浅层作为压缩器，深层作为解码器，通过 KV 状态共享实现信息传递。

### 多粒度上下文树构建

设计动机：静态压缩无法区分任务相关与无关信息，导致高压缩比下关键细节丢失。SHAREDLLM 引入查询依赖的动态树构建，仅展开与查询相关的节点。对于非叶节点，训练时采用随机分裂策略：

$$ b = \lfloor \frac{l}{2} - \epsilon \rfloor, \quad \epsilon \sim \mathcal{N}(0, \sigma^2) $$

该公式通过引入噪声避免模型过拟合固定分裂位置，测试时 $\epsilon=0$ 确保确定性。树的高层节点保留粗粒度语义，低层保留细粒度细节，压缩比 $\alpha_w$ 随层级递减（$\alpha_w = 2\alpha_{w+1}$），实现从粗到细的信息分布。

### 位置感知交叉注意力

设计动机：压缩后的 KV 状态丢失了原始序列的位置信息，导致解码器无法区分上下文块的时序关系。SHAREDLLM 在交叉注意力层引入块级位置索引，将查询 Q 视为最后一个块，应用 RoPE 编码：

$$ \text{RoPE}(Q, K, \text{block\_index}) $$

该机制使交叉注意力自然尊重查询与压缩块之间的相对距离，确保时序连贯性。交叉注意力输出通过残差连接融合至解码器自注意力状态，避免信息冲突。

## 实验评估

实验在 RedPajama 子集上进行持续预训练，并在 LongBench 和 InfiniBench 上进行监督微调评估。基线覆盖 StreamingLLM、SnapKV、OmniKV 等主流长上下文方法，但缺失 LLMLingua 系列硬压缩基线，限制了与纯压缩方法的直接对比。

| 方法 | Arxiv 32K PPL | PG19 32K PPL | ProofPile 32K PPL |
| :--- | :--- | :--- | :--- |
| CEPE | 2.58 | 6.91 | 2.47 |
| SHAREDLLM | 2.51 | 6.80 | 2.45 |

SHAREDLLM 在 32K 长度下困惑度略优于 CEPE，但在 128K 长度下 ProofPile 任务中 CEPE 表现更优（2.38 vs 2.40），表明自注入机制在极端长度下存在性能波动。

| 配置 | Arxiv PPL | MD-QA F1 |
| :--- | :--- | :--- |
| Default | 2.46 | 30.93 |
| w/o query-aware | - | 29.27 |
| w/o noise | 2.51 | 30.08 |
| w/o chunk pid | 2.49 | 29.81 |

消融实验显示，移除查询感知机制导致 MD-QA 性能下降 1.66 分，影响最大；移除噪声正则化导致困惑度上升 0.05，表明随机分裂对训练稳定性至关重要。块级位置索引的移除导致 F1 下降 1.12 分，验证了时序信息对多跳推理的重要性。

评估边界：论文未报告压缩比与推理延迟的帕累托前沿，仅声称 2× 加速但未提供具体数值。代码开源但超参数（如 $\sigma$、树高度）的敏感性分析不足，128K 测试仅用 10 个样本，统计显著性存疑。

## 关联研究分析

从问题动机看，SHAREDLLM 与 GIST 均使用潜在表示压缩，但 GIST 聚焦于提示压缩以提升推理效率，而 SHAREDLLM 旨在扩展上下文窗口。差异根源在于任务特性：GIST 处理短提示，无需处理长距离依赖；SHAREDLLM 需处理 128K 序列，树状结构成为必要。从方法设计看，SHAREDLLM 与 ICAE 均使用自编码器思想，但 ICAE 采用线性记忆槽，SHAREDLLM 引入层级结构。ICAE 的线性表示在复杂依赖任务中易丢失局部细节，而树状结构通过查询感知展开保留关键信息，但增加了计算复杂度。

## 总结

SHAREDLLM 解决的核心矛盾是长上下文外推的高训练成本与推理效率的平衡。其切入点在于共享权重消除隐藏空间差异，通过树状结构实现查询感知压缩。实验证明其在 32K 长度下困惑度优于 CEPE，MD-QA F1 达 30.93。边界在于 128K 长度下性能波动，且缺乏与硬压缩方法的对比。当树高度超过 3 时，性能是否因过度分裂而下降，论文未给出完整回答。
