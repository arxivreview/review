# ICLR2026最新论文 ｜Generative Universal Verifier as Multimodal Meta-Reasoner ｜生成式通用验证器

研究机构：清华大学、美国普林斯顿大学

作者：Xinchen Zhang、Xiaoying Zhang、Youbin Wu 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.13804)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.13804)

> 多模态大语言模型在交错推理与生成场景中，常因缺乏对视觉中间状态的可靠校验而产生逻辑断裂或幻觉。现有评估多聚焦静态问答的最终准确率，难以诊断模型在动态生成过程中对视觉工件的忠实度。本文提出生成式通用验证器概念，构建ViVerBench基准并训练OmniVerifier-7B，通过顺序测试时缩放（Sequential Test-Time Scaling, TTS）范式将验证嵌入生成循环。该工作填补了视觉结果验证的空白，但其依赖裁判模型的评估协议及小模型泛化能力仍存疑。

## 研究背景

当多模态模型执行“思考-生成-反思”的交错推理时，视觉输出（如生成的图像或工具返回的截图）成为推理链的关键节点。若模型无法准确判断这些视觉工件是否符合预期，后续推理将基于错误前提展开。这种对视觉结果（Visual Outcomes）的验证缺失，导致模型在复杂任务中表现出“正确但错误推理”的特征，即最终答案可能碰巧正确，但中间视觉状态与文本描述存在严重偏差。

当前多模态评估领域正从静态感知向动态可靠性诊断转移。主流路线如MM-CoT和RPTS聚焦于文本思维链的逻辑连贯性，或通过统计模型量化基准中的语言捷径。然而，这些方法将视觉视为静态上下文，未能解决视觉模态特有的高维性与歧义性带来的验证难题。在统一多模态模型（Unified Multimodal Models, UMMs）架构下，文本与图像输入输出交织，传统的文本中心推理范式无法覆盖视觉结果的自我批评需求。本文切入点在于将验证器从“打分器”升级为“生成式批评者”，使其能直接参与视觉工件的迭代修正，从而在推理与生成过程中实现闭环反馈。

## 核心方法

### 方法参照系

现有过程评估范式通常将推理链分解为离散步骤，通过规则或裁判模型对每步文本输出进行二元判断。本文问题与该通用流程的关键差异在于：评估对象从低维文本扩展至高维视觉工件，且验证器需具备生成能力以支持迭代修正，而非仅输出分数。

### 双指标评估协议

为阻断模型通过猜测获得虚假正确率，本文设计了规则评估与模型评估双指标体系。规则评估仅计算答案正确性，而模型评估在答案为假时强制要求解释一致性。设 $N$ 为任务总数，$y_i$ 为真值，$\hat{y}_i$ 为预测，$e_i$ 为真值解释，$\hat{e}_i$ 为模型解释，$F(e_i, \hat{e}_i)$ 为裁判模型判断函数。模型评估准确率定义为：

$$
Acc_{model} = \frac{1}{N} \sum_{i=1}^{N} \mathbb{1}(\hat{y}_i = y_i) \cdot \mathbb{1}(y_i = \text{true} \lor F(e_i, \hat{e}_i) = \text{true})
$$

该公式的物理含义是：当答案为真时，仅需预测正确；当答案为假时，必须同时预测正确且解释与真值语义一致。这一设计动机在于消除随机猜测带来的虚假正确性，强制模型在否定判断时提供可验证的视觉证据，从而量化模型的视觉忠实度。

### 顺序测试时缩放范式

在验证器训练后，本文提出OmniVerifier-TTS，将验证器集成至统一多模态模型的生成循环中。不同于并行测试时缩放（如Best-of-N）的独立采样，顺序TTS通过迭代“生成-验证-编辑”实现细粒度优化。设 $I_0$ 为初始生成图像，$V$ 为验证器，$E$ 为编辑模块，第 $t$ 轮迭代更新为：

$$
I_t = E(I_{t-1}, V(I_{t-1}, P))
$$

其中 $P$ 为提示词。该设计的动机在于解决并行采样中计算资源浪费与错误累积问题。通过验证器识别图像中的物理矛盾或属性缺失，编辑模块进行局部修正，而非重新生成整图。这一机制使得模型能在小步长调整中逐步逼近视觉一致性，显著提升了复杂组合生成任务的上限，同时降低了推理时间成本。

## 实验评估

实验在ViVerBench（3,594样本）及T2I-ReasonBench、GenEval++上进行，基线涵盖Gemini 2.5 Pro、GPT-5、Seed 1.5-VL等SOTA模型。ViVerBench结果显示，Gemini 2.5 Pro在规则评估中得分0.745，模型评估中降至0.685，而人类评估达0.932，暴露出模型在细粒度对齐与物理常识激活上的显著差距。OmniVerifier-7B在ViVerBench上较Qwen2.5-VL-7B基线提升8.3点，超越GPT-4o。

| 模型 | ViVerBench 规则评估 | ViVerBench 模型评估 | T2I-ReasonBench Overall | GenEval++ Overall |
| :--- | :--- | :--- | :--- | :--- |
| Gemini 2.5 Pro | 0.745 | 0.685 | - | - |
| Seed 1.5-VL | 0.731 | 0.693 | - | - |
| Qwen2.5-VL 7B | 0.570 | 0.523 | - | - |
| OmniVerifier 7B | 0.653 | 0.559 | - | - |
| Qwen-Image | - | - | 55.5 | 0.675 |
| OmniVerifier-TTS (Qwen-Image) | - | - | 59.2 | 0.718 |
| GPT-Image-1 | - | - | 76.8 | 0.689 |
| OmniVerifier-TTS (GPT-Image-1) | - | - | 79.3 | 0.721 |

在生成任务中，OmniVerifier-TTS使Qwen-Image在T2I-ReasonBench上提升3.7点，GenEval++提升4.3点；GPT-Image-1分别提升2.5点和3.2点。消融实验表明，顺序TTS优于并行Best-of-N，且验证器在物理一致性任务（如Maze、Robotics）上的增益最为显著，证实了原子能力（显式对齐、关系验证、整合推理）的协同泛化效应。

评估边界方面，模型评估依赖GPT-4.1作为裁判，未讨论裁判模型自身的组合偏差风险。ViVerBench为静态基准，未涵盖长时序视频或动态交互场景。代码未公开，仅提供项目页面，可复现性受限。

## 关联研究分析

从问题动机看，MM-CoT（Zhang et al., 2025）通过选择题形式诊断思维链的视觉一致性，但局限于静态图像问答，无法处理生成过程中的动态视觉状态。本文的OmniVerifier-TTS将验证嵌入生成循环，解决了静态评估无法捕捉迭代修正中视觉漂移的问题。这一差异源于任务特性：MM-CoT关注“是否看懂”，本文关注“是否做对”，后者要求验证器具备生成与编辑能力，而非仅判断能力。

从方法设计看，TsT（Brown et al., 2025）通过交叉验证量化基准中的非视觉捷径，属于基准审计路线；本文则通过训练生成式验证器消除捷径，属于能力增强路线。TsT假设基准存在固定难度分布，而本文假设视觉验证能力可通过原子技能迁移获得。当验证器应用于未见过的复杂物理场景时，其泛化边界是否受限于训练数据的原子技能覆盖度，论文未给出明确回答。

## 总结

本文核心矛盾在于多模态模型在交错推理中缺乏对视觉中间状态的可靠校验，导致逻辑断裂。现有静态评估无法诊断动态生成中的视觉忠实度，本文通过构建ViVerBench并训练OmniVerifier-7B，将验证器升级为生成式批评者，实现“生成-验证-编辑”闭环。实验证明OmniVerifier-7B在ViVerBench上提升8.3点，OmniVerifier-TTS在T2I-ReasonBench上提升3.7点。边界在于评估依赖裁判模型且基准为静态，未覆盖长时序动态场景。当验证器应用于未见过的复杂物理场景时，其泛化边界是否受限于训练数据的原子技能覆盖度，论文未给出明确回答。
