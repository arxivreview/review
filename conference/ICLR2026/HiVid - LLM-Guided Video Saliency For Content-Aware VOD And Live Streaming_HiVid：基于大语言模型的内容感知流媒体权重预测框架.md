论文原文见 [arXiv](https://arxiv.org/abs/2602.14214)

> 导读 内容感知流媒体旨在通过动态分配码率提升主观体验质量（QoE），其核心在于为视频片段生成准确的重要性权重。传统视觉模型泛化能力差，人工标注成本高昂且无法适应直播场景，现有方案难以兼顾精度与实时性。本文提出 HiVid 框架，利用大语言模型（LLM）作为主观评分代理，结合滑动窗口感知、全局重排与多模态时序预测，解决长视频上下文限制与直播延迟问题。该框架在 VOD 和直播场景下显著提升了权重预测精度，但受限于 LLM 推理延迟与开源模型性能差距，其实际部署的算力开销仍是主要制约。

## 研究背景

内容感知流媒体依赖自适应码率（ABR）算法优化用户体验，其核心输入是视频片段的主观重要性权重 $w_i$。传统方法通过高亮检测或视频摘要模型预测权重，但这些小型模型缺乏对复杂语义内容的理解能力，在未见过的视频类别上泛化性能急剧下降。另一方面，基于众包的人工评分虽然准确，但单视频耗时 78 分钟且成本高达 100 美元，完全无法满足直播流媒体的实时性要求。

大语言模型（LLM）在主观推理方面展现出接近人类的判断力，但直接应用面临两大瓶颈：一是主流 SOTA LLM（如 GPT-4o）不支持视频模态输入，仅能处理图像；二是其有限的上下文窗口（如 128k tokens）无法容纳长视频的全局历史。此外，LLM 在不同局部窗口内的评分分布存在显著偏差，导致 VOD 场景下全局一致性缺失；而在直播场景中，LLM 推理延迟可变且无法获取未来帧信息，使得基于历史数据的权重预测面临不确定性。

HiVid 的切入点在于将 LLM 视为可扩展的人类代理，通过模块化设计解耦感知、排序与预测任务。它不直接输入视频流，而是采样锚帧进行局部评估，并通过周期性摘要维持全局上下文，从而在 LLM 的模态与长度限制下实现高精度的权重生成。

## 核心方法

### 方法参照系

本文问题属于内容感知流媒体中的权重估计任务，标准流程为：输入视频片段 → 提取特征 → 预测重要性分数 → 优化 ABR 码率。与通用流程的关键差异在于，本文需处理 LLM 的模态限制（仅图像）、上下文限制（需滑动窗口）以及直播场景的因果约束（无未来信息），因此引入了专门的感知、排序与预测模块。

### 滑动窗口感知与全局重排

针对 LLM 无法处理长视频上下文的问题，感知模块采用滑动窗口策略，每次输入 $m$ 个锚帧及周期性视频摘要 $S_i$，由 LLM 输出帧组评分 $R_i$ 并更新摘要。这一设计解决了直接输入全视频导致的 Token 溢出问题。然而，局部窗口评分缺乏全局参照，导致不同窗口间评分分布不一致（如高潮片段评分偏低，平淡片段评分偏高）。为消除这一偏差，排序模块引入 LLM 引导的归并排序算法。该算法将已排序的帧组两两合并，每次从两个组中各取 $m/2$ 帧，由 LLM 基于全局摘要进行相对排序，最终生成全局一致的权重序列。其核心公式为：

$$
\text{Merge}(A, B) = \text{Sort}_{LLM}(A[1:m/2] \cup B[1:m/2]) \cup \text{Merge}(A[m/2+1:], B[m/2+1:])
$$

该过程通过递归合并消除局部评分偏差，确保最终权重反映视频整体语义重要性。

### 多模态时序预测与自适应时域

针对直播场景无法获取未来权重的约束，预测模块与感知模块并行运行。它利用 CLIP 对齐帧图像与文本摘要，构建多模态时序输入，通过内容感知注意力机制捕捉视频统计特征对权重演化的影响。由于 LLM 推理延迟可变，预测模块采用自适应时域策略，动态调整预测长度以覆盖尚未评分的片段间隙，确保 ABR 算法总能获得足够的未来权重进行优化。其预测目标为最小化预测权重与真实权重的误差，同时通过相关性损失增强时序一致性：

$$
\mathcal{L} = \mathcal{L}_{MSE}(\hat{w}, w) + \lambda \mathcal{L}_{Corr}(\hat{w}, w)
$$

这一设计解决了固定预测长度在 LLM 延迟波动下导致的权重缺失问题，实现了低延迟的实时权重生成。

## 实验评估

实验在 Youtube-8M、TVSum 和 SumMe 三个高亮检测数据集上进行，基线覆盖 CV 高亮检测（DETR）、视频摘要（VASNet）、视频理解模型（VideoLLaMA3, VILA）及时序预测 SOTA（iTransformer, TimeMixer 等）。

| 数据集 | 方法 | PLCC | SRCC | mAP50 | mAP15 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Youtube-8M | HiVid | 0.66 | 0.67 | 0.86 | 0.53 |
| Youtube-8M | SL-module | 0.59 | 0.55 | 0.81 | 0.49 |
| TVSum | HiVid | 0.50 | 0.52 | 0.67 | 0.40 |
| TVSum | DETR | 0.43 | 0.41 | 0.57 | 0.33 |

HiVid 在 Youtube-8M 上 PLCC 达 0.66，较次优的 SL-module（0.59）提升 11.5%，在 TVSum 上 PLCC 0.50 优于 DETR（0.43）。在时序预测任务中，HiVid-M 取得最高 PLCC 0.29 和最低 MAE 0.08，优于 iTransformer（PLCC 0.15）等 SOTA 基线，验证了内容感知注意力机制的有效性。

消融实验显示，移除排序模块导致 PLCC 从 0.66 降至 0.63，证实了全局重排对消除评分偏差的关键作用；移除感知模块则使 PLCC 降至 0.61，表明周期性摘要对维持长视频上下文一致性不可或缺。在直播场景下，HiVid 在 2 小时视频流中成本为 4.81 美元，PLCC 0.24，虽随视频时长增加成本线性增长，但保持了稳定的预测精度。

评估边界方面，实验仅使用 GPT-4o 作为主 LLM，未充分验证开源模型（如 Llama-3.2-11B-Vision）在大规模部署下的性能衰减；此外，论文未报告 LLM 推理延迟对 ABR 决策实时性的具体影响指标，仅通过异步流水线掩盖延迟，缺乏对极端延迟场景下 QoE 损失的量化分析。

## 关联研究分析

从问题动机看，HiVid 与流式视频理解中的 VST 等模型均面临长视频上下文限制，但 VST 关注语义记忆的完整性以支持多步推理，而 HiVid 关注主观权重的准确性以优化码率分配。VST 采用双记忆系统（短期视觉+长期文本）维持语义连贯，HiVid 则采用滑动窗口+周期性摘要控制 LLM 输入长度。差异根源在于任务目标：语义理解需要保留细粒度视觉细节以支持推理，而权重预测仅需捕捉宏观内容重要性，因此 HiVid 的摘要策略更激进地压缩了视觉信息，牺牲了细节以换取计算效率。

从方法设计看，HiVid 的 LLM 引导归并排序与流式视频理解中的注意力机制存在本质差异。注意力机制通过加权求和融合历史信息，适用于连续特征空间；而归并排序通过离散比较操作重排帧序列，适用于主观评分的序数性质。HiVid 选择排序而非注意力，是因为主观评分具有非线性且非加和的特性，直接加权求和无法消除局部偏差。这一设计选择揭示了 LLM 在主观推理任务中更适合处理离散比较而非连续融合，但论文未探讨当评分分布高度非均匀时，排序算法的收敛性与稳定性问题。

## 总结

HiVid 解决了内容感知流媒体中 LLM 模态限制、上下文限制与直播延迟之间的矛盾，通过滑动窗口感知、LLM 引导归并排序与多模态时序预测，实现了 VOD 场景下 PLCC 11.5% 的提升和直播场景下 26% 的预测精度增益。其核心创新在于将 LLM 的主观推理能力与流媒体系统的实时性约束相结合，通过模块化设计解耦了感知、排序与预测任务。然而，实验显示开源 LLM 的 PLCC 较 GPT-4o 低 13.7%，且直播场景下成本随视频时长线性增长，表明该框架在算力受限的边缘设备上部署仍面临挑战。当视频时长超过 6 小时时，HiVid 的成本达 14.43 美元，PLCC 降至 0.24，此时 LLM 摘要的累积误差是否会导致权重预测的显著退化，论文未给出回答。
