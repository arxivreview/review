# ICLR2026最新论文 ｜AGENTFOLD: LONG-HORIZON WEB AGENTS WITH PROACTIVE CONTEXT FOLDING ｜主动上下文折叠的长程Web智能体

研究机构：上海交通大学

作者：Rui Ye、Zhongwang Zhang、Kuan Li 等 15 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_72470046)

> 长程Web信息检索任务中，智能体面临上下文饱和与关键信息丢失的双重困境。ReAct范式因累积原始噪声导致推理退化，而固定步长摘要则可能不可逆地抹除细节。AgentFold引入多尺度状态摘要与主动折叠机制，将上下文管理内化为智能体的核心推理步骤。该架构在BrowseComp等基准上以30B参数模型超越了671B规模的开源模型，但其有效性局限于信息检索场景，在动态Web交互任务中的泛化能力尚存疑。

## 研究背景

Web智能体执行长程任务时，需维持对历史交互的准确记忆以支撑连贯规划。ReAct（Yao et al., 2023）范式通过交替生成推理与动作，将完整的“推理-动作-观察”三元组累积在上下文中，这种追加式策略虽保留了信息完整性，但原始网页数据的噪声随步骤增加呈线性增长，导致关键信号被淹没，引发“迷失在中间”现象。为解决此问题，MEM1（Zhou et al., 2025b）和MemAgent（Yu et al., 2025）等近期工作尝试在每步对全历史进行机械摘要，虽维持了上下文整洁，却面临单次摘要阶段可能过早且不可逆地丢失关键细节的风险，尤其在复杂多步子任务中，这种刚性压缩策略缺乏对信息重要性的动态评估能力。

现有方法在上下文全面性与简洁性之间陷入两难：保留全部历史导致噪声爆炸，固定摘要导致信息损失。AgentFold的切入点在于借鉴人类认知中的回顾性整合（Retrospective Consolidation）机制，将上下文视为需主动管理的动态工作区而非被动日志。通过引入显式的折叠指令，智能体在每步推理中同时决定“折叠什么”和“执行什么”，从而在保留细粒度细节与抽象粗粒度结论之间实现动态平衡，解决了长程任务中上下文膨胀与推理质量下降的核心矛盾。

## 核心方法

### 方法参照系

AgentFold基于ReAct范式构建，但核心差异在于将上下文管理从被动累积转变为主动策展。标准ReAct流程中，上下文 $C_t$ 随步骤 $t$ 线性增长，包含所有历史三元组；而AgentFold将上下文重构为多尺度状态摘要与最新交互的组合，通过显式折叠操作动态调整历史信息的粒度，使上下文长度在长程任务中保持亚线性增长。

### 多尺度状态摘要与折叠指令

AgentFold的上下文 $C_t$ 定义为四元组 $(Q, T, S_{t-2}, I_{t-1})$，其中 $Q$ 为用户问题，$T$ 为工具列表，$S_{t-2}$ 为多尺度状态摘要序列，$I_{t-1}$ 为最新交互。$S_{t-2}$ 表示为有序摘要块序列 $\{s_{x_i, y_i}\}_{i=1}^m$，其中每个 $s_{x,y}$ 是步骤 $x$ 到 $y$ 的文本摘要，步长范围划分整个历史，满足 $x_1=1, y_m=t-2, x_{i+1}=y_i+1$。这种多尺度结构允许单步摘要 $s_{x,x}$ 保留细粒度细节，而多步摘要 $s_{x,y}$ ($y>x$) 抽象子任务结论。

在每步 $t$，AgentFold生成响应 $R_t$，解析为四元组 $(th_t, f_t, e_t, a_t)$，其中 $f_t$ 为折叠指令，形式为JSON对象 $\{ \text{"range": } [k, t-1], \text{"summary": } \sigma_t \}$。该指令支持两种模式：细粒度压缩（$k=t-1$）将最新交互 $I_{t-1}$ 折叠为单步摘要 $s_{t-1, t-1}$；深度整合（$k < t-1$）将最新交互与先前摘要链融合为粗粒度摘要 $s_{k, t-1}$，替换原范围内所有摘要块。这一设计解决了固定摘要策略无法区分信息重要性的问题，通过动态选择折叠范围，智能体可在子任务完成时抽象中间步骤，或在关键发现时保留细粒度细节，避免不可逆信息损失。

### 折叠-行动协同推理

AgentFold的响应生成将上下文管理与行动规划耦合为单一推理过程。折叠指令 $f_t$ 的生成迫使智能体批判性评估轨迹，蒸馏历史上下文中最显著的信息，这一反思过程本身提升了当前状态理解，从而优化后续动作 $a_t$ 的选择。反之，规划新动作需查询近期历史以识别关键线索，这一过程实时提供了值得保留在折叠摘要中的信号。这种协同机制使上下文策展成为推理的内生部分，而非被动副产品，解决了ReAct中上下文管理与行动规划分离导致的效率低下问题。

## 实验评估

实验在BrowseComp、BrowseComp-ZH、WideSearch-en和GAIA（文本子集）四个基准上进行，对比了包括WebThinker、WebDancer、GLM-4.5-355B-A32B、DeepSeek-V3.1-671B-A37B在内的开源智能体及OpenAI-o4-mini等专有智能体。基线覆盖广泛，但缺失WebArena等动态Web交互基准的专用方法，如Branch-and-Browse，限制了结论在复杂UI操作任务中的泛化性。

| Agent | BrowseComp | BrowseComp-ZH | WideSearch | GAIA |
| :--- | :--- | :--- | :--- | :--- |
| GLM-4.5-355B-A32B | 26.4 | 37.5 | - | 66.0 |
| DeepSeek-V3.1-671B-A37B | 30.0 | 49.2 | - | 63.1 |
| OpenAI-o4-mini | 37.4 | - | - | 44.3 |
| AgentFold-30B-A3B | 36.2 | 47.3 | 62.1 | 67.0 |

AgentFold-30B-A3B在BrowseComp上取得36.2%，超越671B规模的DeepSeek-V3.1（30.0%），在WideSearch上以62.1%超越所有专有智能体，验证了主动上下文折叠在信息检索任务中的有效性。消融实验显示，AgentFold上下文长度在100步内仅从3.5k增长至7k tokens，而ReAct基线增长至84k tokens以上，节省约7GB内存/实例，证明折叠机制有效抑制了上下文膨胀。

评估边界方面，论文未报告置信区间，且BrowseComp等基准侧重静态信息检索，未涵盖动态加载、异步交互等真实Web特性。代码已开源，但Fold-Generator依赖GLM-4.5和DeepSeek-V3.1生成训练数据，数据合成过程的噪声控制细节未充分披露，可能影响模型在分布外任务上的鲁棒性。

## 关联研究分析

从问题动机看，AgentFold与WebCoach（Liu et al., 2025）均针对长程任务中的记忆管理，但WebCoach依赖外部记忆存储（EMS）实现跨会话学习，而AgentFold聚焦于任务内上下文策展，通过内部折叠机制避免外部存储的投毒风险。这一差异源于任务特性：WebCoach处理需跨会话积累经验的导航任务，而AgentFold针对单次长程信息检索任务，其上下文膨胀问题更紧迫，内部折叠比外部存储更轻量且实时性更强。

从方法设计看，AgentFold与MEM1（Zhou et al., 2025b）同属上下文压缩路线，但MEM1采用固定步长全历史摘要，而AgentFold引入多尺度动态折叠，允许智能体根据子任务完成度选择折叠粒度。这一改进解决了MEM1在复杂多步任务中可能丢失关键中间状态的问题，但AgentFold的折叠指令生成依赖额外推理开销，其延迟增加幅度论文未量化，在实时性要求高的Web交互场景中可能成为瓶颈。

## 总结

AgentFold旨在解决长程Web智能体中上下文饱和与关键信息丢失的矛盾，通过引入多尺度状态摘要与主动折叠机制，将上下文管理内化为推理过程的核心步骤。该架构在BrowseComp上以30B参数模型取得36.2%的成功率，超越671B规模的DeepSeek-V3.1，并在WideSearch上以62.1%超越所有专有智能体，验证了主动上下文策展的有效性。然而，实验仅覆盖静态信息检索基准，未涉及动态Web交互任务，且Fold-Generator依赖大模型生成训练数据，其噪声控制与分布外泛化能力未充分验证。当任务涉及动态UI布局与实时交互时，折叠策略的粒度选择是否仍能保持上下文效率，论文未给出回答。
