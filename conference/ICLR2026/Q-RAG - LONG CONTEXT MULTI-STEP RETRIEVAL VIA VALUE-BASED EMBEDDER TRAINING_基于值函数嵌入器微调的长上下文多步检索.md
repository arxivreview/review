# ICLR2026最新论文 ｜Q-RAG: LONG CONTEXT MULTI-STEP RETRIEVAL VIA VALUE-BASED EMBEDDER TRAINING ｜基于值函数嵌入器微调的长上下文多步检索

作者：Artyom Sorokin、Nazar Buzun、Aleksandr Anokhin 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_93403660)

> 长上下文多步检索旨在解决大语言模型在百万级 token 语境下因注意力稀释导致的证据定位失效问题。现有主流方法要么依赖昂贵的 LLM 微调生成查询，要么通过构建知识图谱引入高昂的推理延迟，难以兼顾效率与精度。Q-RAG 将多步检索建模为有限时域马尔可夫决策过程，仅微调文本块嵌入器以在潜在空间直接选择证据，实现了单卡训练与超长上下文的高精度检索。该方法在效率与长文本泛化上表现优异，但在开放域复杂逻辑推理上的证据覆盖能力仍存疑。

## 研究背景

当模型面对包含数百万 token 的叙事文本时，关键证据往往分散且存在时序依赖，传统的单次检索无法捕捉这种跨文档的逻辑链条。这种困境源于长上下文中的“中间迷失”现象，即模型难以在海量噪声中定位特定事实。为了解决这一定位难题，多步检索被引入，其核心是通过迭代交互逐步缩小搜索空间，将复杂的长文本推理转化为一系列局部的检索决策。

当前解决多步检索的主流路线存在显著的效率瓶颈。一类方法如 SearchR1 和 R1-Searcher，通过强化学习微调 LLM 生成中间查询，虽然提升了推理能力，但需要至少 8 张 A100 GPU 进行训练，且无法适配专有模型。另一类方法如 HippoRAG 和 GraphReader，通过构建知识图谱显式建模实体关系，但推理时需处理整个上下文以构建图结构，导致延迟极高。此外，基于 BeamSearch 的 BeamRetriever 虽在短文本表现良好，但依赖 Transformer 重排，难以扩展至超长语境。Q-RAG 的切入点在于解耦检索与生成，仅微调轻量级的嵌入器，利用值函数强化学习在向量空间直接优化检索策略，从而在保持 LLM 冻结的前提下实现资源高效的多步检索。

## 核心方法

### 多步检索的 MDP 建模

多步检索通常被视为序列决策问题，但现有方法多依赖 LLM 生成文本查询作为动作，导致动作空间巨大且计算成本高。Q-RAG 将动作空间定义为文本块的嵌入向量，通过状态嵌入器 $E_s$ 和动作嵌入器 $E_a$ 的内积来估计 Q 值，从而在连续潜在空间中执行检索。这种设计避免了 LLM 在每一步生成文本的开销，使得检索过程可以并行化且计算密集度更低。

### 基于 PQN 的值函数优化

传统 DQN 依赖经验回放缓冲区，但在长上下文场景中，回放需重新嵌入所有文档块以估计后续状态值，内存与计算开销巨大。Q-RAG 采用 PQN 算法进行在线策略学习，结合软 Q 函数与目标网络以稳定训练。其核心损失函数为最小化 Q 值与 $\lambda$-return 的均方误差：

$$ \mathcal{L}_Q = \frac{1}{T K} \sum_{k=1}^K \sum_{t=1}^T \left[ \nabla_\theta (Q_\theta(s_t^{[k]}, a_t^{[k]}) - G_t^{[k]}) \right]^2 $$

其中 $G_t$ 为 $\lambda$-return，平衡了即时奖励与长期价值。该设计消除了回放缓冲区的依赖，使得模型能在单卡 A100 上高效训练，同时通过软 Q 函数增强了对长序列中稀疏奖励的探索能力。

### 相对位置编码与时序推理

在叙事文本中，判断某个文本块是否相关往往取决于其相对于已提取事实的时间位置，而非绝对位置。标准检索器缺乏这种时序感知能力，导致在需要“之前”或“之后”信息的任务上失效。Q-RAG 引入相对位置编码 $\rho_t(i)$，将文档索引映射为相对于已选事实区间的位置：

$$ \rho_t(i) = j \cdot \delta + (i - b_j) \cdot \ell $$

其中 $b_j$ 为区间边界，$\delta$ 和 $\ell$ 控制区间间与区间内的分辨率。该编码被注入动作嵌入器，使 Q 函数能够显式利用候选块与已检索证据的空间关系，从而在长叙事中准确定位具有时序依赖的关键信息。

## 实验评估

| 方法 | RULER 1M S | RULER 1M MK | RULER 1M MV | HotPotQA Ans F1 | MuSiQue Ans F1 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Q-RAG | 100 | 100 | 99.7 | 0.97 | 0.64 |
| Beam Retriever | 98.5 | 98 | 99 | 0.77 | 0.64 |
| SearchR1 | - | - | - | 0.93 | 0.59 |

Q-RAG 在 RULER 基准的 1M token 长度下，S、MK、MV 任务均达到或接近满分，显著优于 Titans 和 Atlas 等长上下文模型。在开放域 QA 上，Q-RAG 在 HotPotQA 的 Ans F1 达到 0.97，超越 SearchR1 的 0.93，但在 MuSiQue 上与 Beam Retriever 持平。基线覆盖包括长上下文模型（Titans, Atlas）和 RL 检索方法（SearchR1, RAG-RL），但缺失了 PRISM 等最新的智能体架构方法，且部分基线为原文报告值，存在设置差异。

| 方法 | BabiLong QA3 1K | BabiLong QA3 128K | BabiLong QA3 1M |
| :--- | :--- | :--- | :--- |
| Q-RAG | 97.8 | 20.33 | 15.52 |
| Q-RAG w.o. Soft-Q | 97.4 | 20.87 | 16.38 |
| Multi-Step RAG w. SFT | 96.8 | 77.6 | 15.51 |

消融实验显示，移除 Soft-Q 或目标网络对性能影响较小，但监督微调（SFT）在 128K 长度下性能大幅衰退（77.6 vs 97.8），表明 RL 在长上下文泛化上的优势。值得注意的是，Q-RAG 在 1M 长度的 QA3 任务上 F1 仅为 15.52，远低于 1K 长度的 97.8，暴露出其在超长叙事推理中的局限性。

评估协议存在指标不一致问题，HotPotQA 使用 F1/EM，而 RULER 使用准确率，且部分基线未报告置信区间。代码已开源，训练仅需单卡 A100，超参数包括温度 $\alpha$ 和 TD 参数 $\lambda$，但缺乏对 LLM 骨干敏感性的详细分析。

## 关联研究分析

从方法设计看，Q-RAG 与 SearchR1 同属强化学习检索路线，但优化对象截然不同。SearchR1 微调 LLM 生成文本查询，动作空间为离散 token 序列，依赖 LLM 的语义生成能力；Q-RAG 微调嵌入器，动作空间为连续向量，依赖向量相似度。这种差异源于任务特性：SearchR1 侧重复杂逻辑推理，需 LLM 生成中间假设；Q-RAG 侧重长文本定位，需高效检索。Q-RAG 的嵌入空间检索牺牲了生成查询的语义灵活性，可能难以处理需要复杂语义变换的查询，但换来了极低的计算成本。

从问题动机看，Q-RAG 与 HippoRAG 均旨在解决长上下文中的证据分散问题，但路径相反。HippoRAG 通过显式构建知识图谱来捕捉跨文档关系，推理时需遍历图结构，延迟高；Q-RAG 通过相对位置编码隐式建模时序关系，推理时仅计算向量内积，延迟低。HippoRAG 的优势在于可解释性和复杂关系捕捉，Q-RAG 的优势在于效率和可扩展性。Q-RAG 的相对位置编码仅捕捉线性时序关系，对于非线性或循环依赖的逻辑结构，其表达能力可能不足，这一点在 MuSiQue 基准上与 Beam Retriever 持平的结果中有所体现。

## 总结

Q-RAG 旨在解决长上下文多步检索中计算效率与推理深度的矛盾。现有方法要么微调 LLM 导致资源消耗巨大，要么构建图谱导致推理延迟高，Q-RAG 通过仅微调嵌入器并利用值函数强化学习，在潜在空间直接优化检索策略，实现了单卡训练与百万级 token 的高效检索。实验表明，Q-RAG 在 RULER 1M token 下达到 100% 准确率，HotPotQA Ans F1 达 0.97，证明了其在长文本定位上的有效性。然而，其在 BabiLong QA3 1M 长度下 F1 仅为 15.52，暴露出在超长叙事推理中时序建模的局限性。当上下文长度进一步增加或逻辑依赖更加复杂时，仅依赖相对位置编码的嵌入器能否捕捉非线性的跨文档关系，论文未给出回答。
