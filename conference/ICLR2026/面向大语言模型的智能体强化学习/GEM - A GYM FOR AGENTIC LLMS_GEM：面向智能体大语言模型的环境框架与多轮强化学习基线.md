# ICLR2026最新论文 ｜GEM: A GYM FOR AGENTIC LLMS ｜GEM：面向智能体大语言模型的环境框架与多轮强化学习基线

研究机构：新加坡国立大学、新加坡管理大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ICLR_2026_18693177)

> 导读 大语言模型（LLM）智能体的强化学习（RL）训练长期受限于单轮任务假设，导致主流算法在多轮交互中失效。现有方法如 GRPO 依赖固定折扣因子与稀疏奖励，无法处理密集回合级反馈与效率激励。本文提出 GEM（General Experience Maker）环境框架及兼容多轮密集奖励的 REINFORCE 变体（ReBN），通过标准化接口与异步执行解耦环境与训练。该工作填补了 LLM 智能体 RL 基础设施空白，但 ReBN 在长程任务上的收敛优势是否源于方差降低，仍需更严格的消融验证。

## 研究背景

LLM 智能体与环境交互时，动作粒度决定了 RL 问题的复杂度。若将每个 token 视为动作，轨迹长度达数千步，奖励分配极难评估；若将整个响应视为动作，问题退化为上下文赌博机（Contextual Bandits），适用于单轮数学题但无法扩展至多轮游戏或工具调用。多轮交互中，轨迹长度 $T > 1$，要求算法支持密集回合级奖励与任意折扣因子 $\gamma$，以引导智能体在长程任务中平衡探索与效率。

当前 LLM RL 研究集中于单轮任务，如数学推理或数据检索，这些场景下 GRPO 等基于组内相对优势估计的算法表现优异。然而，当任务扩展至多轮交互（如代码调试、网页导航）时，GRPO 的优势估计在所有步骤上保持恒定，导致细粒度信用分配失效。此外，GRPO 固定 $\gamma = 1$，消除了对快速解决问题的激励，这在需要效率优化的任务中尤为关键。现有环境框架多为定制任务，缺乏标准化接口，阻碍了算法的公平比较与复现。

GEM 的切入点在于提供 OpenAI-Gym 式的标准化环境基础设施，并设计兼容多轮密集奖励的基线算法。通过解耦环境部署与训练引擎，GEM 支持异步向量化执行，解决长尾延迟问题。同时，ReBN 算法通过批量归一化回报，在无需 Critic 网络的情况下实现稳定的多轮策略优化，弥补了 GRPO 在多轮场景中的结构性缺陷。

## 核心方法

### 方法参照系

LLM 智能体 RL 的标准流程通常采用 PPO 或 GRPO，前者依赖 Critic 网络估计价值函数，后者通过组内相对优势避免 Critic 开销。本文问题与该通用流程的关键差异在于：多轮交互中密集奖励与任意折扣因子的兼容性，以及环境侧与训练侧的解耦需求。

### 多轮兼容的 REINFORCE 变体

设计动机：GRPO 在多轮中因优势估计恒定导致信用分配失效，且固定 $\gamma = 1$ 无法引导效率优化。本文采用 REINFORCE 作为基线，因其原生支持密集奖励与任意 $\gamma$，但原始 REINFORCE 对奖励整形敏感，收敛不稳定。

ReBN 通过批量归一化回报系数，降低策略梯度方差。其核心公式为：

$$ A_{t}^{ReBN} = \frac{G_t - \text{mean}(\mathbf{G})}{\text{std}(\mathbf{G})} $$

其中 $G_t = \sum_{k=t}^{T-1} \gamma^{k-t} r_k$ 为从时间步 $t$ 开始的折扣回报，$\mathbf{G}$ 为批次内所有轨迹所有时间步的回报集合。该公式将原始回报转换为零均值单位方差的优势估计，自适应调整梯度尺度，缓解奖励整形带来的探索障碍。

### 异步向量化环境执行

设计动机：同步 RL 中，长尾轨迹导致 GPU 闲置，且上下文长度动态增长引发内存溢出。GEM 通过异步向量化执行与 Autoreset 机制，解耦环境部署与训练引擎。

Autoreset 机制在轨迹终止后自动重置环境，允许用户通过单一 `.step()` 调用连续生成批次数据，无需手动跟踪终止状态。其核心逻辑为：

$$ \text{next\_obs}, r, \text{terminated}, \text{truncated} = \text{env.step}(a) $$

若 $\text{terminated}$ 为真，环境自动重置并返回新初始状态，确保 Critic 学习不跨越轨迹边界进行价值引导。该设计消除了同步等待导致的资源气泡，提升吞吐量，同时保持 On-policy 训练的正确性。

## 实验评估

实验在 GEM 的八个环境上进行，涵盖单轮推理（ReasoningGym）、多轮游戏（Sudoku, GuessTheNumber）及工具集成任务（Math, QA）。基线包括 GRPO、PPO、REINFORCE 及 ReBN，均使用 Qwen3-1.7B/4B-Base 模型，通过 Oat 框架实现。对比方法覆盖主流 RL 算法，但缺失 Tree-GRPO、SLEA-RL 等最新多智能体 SOTA 基线，限制了与领域前沿的直接比较。

| 环境 | 算法 | 平均 Episode Return |
| :--- | :--- | :--- |
| Sudoku (1.7B) | PPO | 0.8 |
| Sudoku (1.7B) | ReBN | 0.8 |
| GuessTheNumber (1.7B) | GRPO | 0.5 |
| GuessTheNumber (1.7B) | ReBN | 0.8 |

ReBN 在多轮环境中显著优于 GRPO，尤其在 Sudoku 中达到与 PPO 相当的性能，而无需 Critic 网络。在单轮环境中，GRPO 表现稳健，验证其在稀疏奖励场景下的有效性。ReBN 的优势源于批量归一化对梯度方差的抑制，而非 Critic 学习的稳定性，这解释了其在 Minesweeper 等复杂环境中优于 PPO 的现象。

消融实验显示，折扣因子 $\gamma$ 对多轮学习至关重要。在 GuessTheNumber 中，$\gamma = 0.9$ 引导智能体收敛至二分查找最优步数（$\log_2(50) \approx 5.6$），而 $\gamma = 0.999$ 导致步数增加，效率下降。工具集成任务中，启用 Python 或搜索工具后，Qwen3-4B 在 AIME24 上的准确率从 16.7% 提升至 30.0%，表明工具调用显著增强推理能力，但 RL 训练本身贡献约 13.3 个点。

评估边界方面，GEM 提供标准化接口，但缺乏跨框架的超参数统一协议。代码开源（axon-rl/gem），支持 Oat、VeRL、OpenRLHF 等五个框架，但异步执行在 RL2 中带来 2 倍墙钟时间增益，其他框架未报告类似效率数据。指标完备性上，主要依赖平均 Episode Return，未报告样本效率或泛化性能，限制了算法鲁棒性的全面评估。

## 关联研究分析

从方法设计看，GEM 的 ReBN 与 GRPO 的核心差异在于优势估计的粒度与折扣因子兼容性。GRPO 通过组内相对优势避免 Critic 开销，但固定 $\gamma = 1$ 且优势在所有步骤恒定，导致多轮中信用分配失效。ReBN 通过批量归一化原始回报，支持任意 $\gamma$ 与密集奖励，其优势估计随时间步动态变化，更贴合多轮交互的信用分配需求。这一差异源于任务特性：单轮任务中 GRPO 的简化假设成立，而多轮任务中效率激励与细粒度反馈不可或缺。

从系统架构看，GEM 与 AgentRL 等异步框架均追求环境-训练解耦，但 GEM 聚焦环境侧标准化，提供统一接口与工具集成，而 AgentRL 侧重训练侧资源调度。GEM 的 Autoreset 机制简化了数据收集逻辑，但缺乏 AgentRL 中的动态资源分配策略，可能在异构任务负载下效率受限。MCP 工具接口的引入，使 GEM 成为首个支持标准化外部工具调用的 LLM RL 环境，填补了工具增强智能体评估的空白。

## 总结

GEM 解决了 LLM 智能体 RL 中环境标准化缺失与多轮算法兼容性不足的核心矛盾。通过提供 OpenAI-Gym 式接口与 ReBN 算法，GEM 实现了密集奖励与任意折扣因子的支持，弥补了 GRPO 在多轮场景中的结构性缺陷。实验显示，ReBN 在 Sudoku 等长程任务中达到 0.8 的平均回报，优于 GRPO 的 0.5，且无需 Critic 网络。然而，ReBN 的优势是否依赖于特定骨干网络（Qwen3）或奖励整形方式，论文未提供跨模型或跨奖励结构的消融数据。当支持集增大或任务复杂度提升时，ReBN 的收敛稳定性是否仍优于 PPO，论文未给出回答。
