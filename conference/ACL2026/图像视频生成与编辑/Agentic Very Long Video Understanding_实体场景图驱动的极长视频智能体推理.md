# ACL2026最新论文 ｜Agentic Very Long Video Understanding ｜实体场景图驱动的极长视频智能体推理

研究机构：美国威斯康星大学麦迪逊分校

作者：Aniket Rege、Arka Sadhu、Yuliang Li 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.18157)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.18157)

> 极长视频理解旨在让模型处理跨越数天甚至数周的连续第一人称视频流，以支持个性化助手的长期记忆与情境感知。现有方法受限于上下文窗口，依赖均匀采样或扁平向量检索，难以在数小时尺度上维持实体身份一致性并执行跨天多跳关系推理。EGAgent 通过离线构建带时间戳的实体场景图，将视频结构化为可查询的关系网络，并让规划智能体通过 SQL 查询该图结合视觉/音频检索来定位证据。该方法在周级视频基准 EgoLifeQA 上刷新了多跳推理类别的 SOTA，但其性能高度依赖离线图构建的质量与 LLM 骨干能力，且未解决细粒度视觉细节的实时定位问题。

## 研究背景

当智能眼镜持续记录用户一周的生活时，产生的视频流长度超过 50 小时，远超当前多模态大语言模型（MLLMs）的上下文窗口限制。直接输入全量帧会导致计算成本不可接受，而传统的均匀帧采样策略在长时程中极易遗漏稀疏的关键交互证据。为缓解这一矛盾，检索增强生成（RAG）范式通过预先检索相关片段来缩小输入范围，但基于向量相似度的扁平检索难以维持实体在时间轴上的身份一致性，无法回答“上周三我和谁一起去了哪里”这类需要跨天实体关系追踪的问题。

长视频理解领域的主流路线分为被动压缩与主动代理两类。被动压缩路线（如 VideoNSA、AdaCodec）通过稀疏注意力或 Token 压缩在单次前向传播中捕捉信息，适合实时性要求高的场景，但在证据极度稀疏的长时程任务中召回率受限。主动代理路线（如 LongVT、Video-o3）通过工具调用进行迭代验证，提升了证据定位精度，但现有方法多依赖非结构化的文本摘要或重复的帧检索，缺乏对实体间复杂关系的显式建模。EGAgent 的切入点在于引入结构化表示：它不直接检索原始帧或文本块，而是预先从视频中提取实体场景图，将“人-物-地”及其关系编码为带时间戳的图结构，使智能体能够通过结构化查询（SQL）直接定位跨天关系，从而解决扁平检索在长时程实体追踪上的失效。

## 核心方法

### 方法参照系

EGAgent 属于智能体推理框架，其标准流程是规划智能体分解查询、调用工具检索证据、迭代推理直至生成答案。与 Video-RAG 等基于向量相似度的检索方法不同，EGAgent 的核心差异在于将检索源从非结构化的帧/文本块替换为结构化的实体场景图，并将检索操作从语义匹配升级为结构化查询。

### 实体场景图构建

传统 RAG 方法将视频切分为独立片段进行向量化，丢失了片段间的实体关联。EGAgent 通过 LLM 提取器 $F$ 从音频转录 $A_T$ 和视觉场景描述 $V$ 中联合提取实体与关系，构建实体图 $G=(V, E)$。每个节点 $v \in V$ 代表人、物或地点，每个边 $e \in E$ 表示关系（如 `talks_to`, `uses`），并标注时间区间 $(t_{start}, t_{end})$。

$$
e = (v_s, v_t, r, t_{start}, t_{end}, d^*)
$$

其中 $v_s, v_t$ 为源/目标节点，$r$ 为关系类型，$d^*$ 为支持该关系的原始文本片段。该公式的物理含义是：将视频中的动态交互离散化为带时间戳的静态关系元组，存储在 SQLite3 数据库中。这种设计使图支持增量更新，新视频流到达时只需追加新边，无需重建全图，解决了长时程视频中实体关系随时间演化的建模难题。

### 智能体协同推理框架

在推理阶段，规划智能体（Planning Agent）将复杂查询 $Q$ 分解为子任务列表 $\{(S_i, T_i, q_i)\}$，其中 $S_i$ 为子任务描述，$T_i$ 为选定的工具，$q_i$ 为查询参数。对于每个子任务，智能体调用对应的检索工具获取数据，并通过分析器工具（Analyzer Tool）过滤无关信息，将证据累积到工作记忆 $M$ 中。

$$
M \leftarrow M \cup \{ \text{AnalyzerTool.analyze}(T(q_i), S_i) \}
$$

最终，VQA 智能体基于累积的跨模态证据 $M$ 生成答案。该设计的关键在于工具选择的联合优化：规划智能体不仅决定“查什么”，还决定“用哪个工具查”。例如，对于“谁经常坐在我旁边”这类习惯追踪问题，智能体优先调用实体图搜索工具执行 SQL 查询，而非盲目检索视觉帧，从而避免了在 50 小时视频中逐帧搜索的计算浪费。

## 实验评估

EGAgent 在 EgoLifeQA（500 个 MCQ，基于 50 小时连续第一人称视频）和 Video-MME (Long)（300 个 30-60 分钟视频）上进行评估。基线覆盖 MLLM 均匀采样（Gemini 2.5 Pro, GPT-4.1）、代理式基线（EgoButler, VideoAgent, Ego-R1）及 RAG 方法（Video-RAG）。在 EgoLifeQA 上，EGAgent（Gemini 2.5 Pro 骨干）取得 57.5% 的准确率，较前 SOTA（EgoButler）提升 20.6%，在 RelationMap 类别上超越前 SOTA 32%、超越 Gemini 2.5 Pro 均匀采样 20.8%。在 Video-MME (Long) 上，EGAgent（Gemini 2.5 Pro）取得 74.1%，高于 Video-RAG（+4.5%），但低于原生 Gemini 2.5 Pro（82.0%）。

| 方法 | 骨干 | EgoLifeQA (%) | Video-MME (Long) (%) |
| :--- | :--- | :--- | :--- |
| Gemini 2.5 Pro (Uniform) | Gemini 2.5 Pro | 46.8 | 82.0 |
| EgoButler | GPT-4o | 36.0 | – |
| Video-RAG | LLaVA-OneVision-7B | 30.4 | – |
| EGAgent | Gemini 2.5 Pro | 57.5 | 74.1 |
| EGAgent | GPT-4.1 | 54.4 | – |

消融实验显示，实体图构建中引入视觉描述（而非仅音频转录）平均提升 2.6% 准确率，表明视觉信息对实体识别至关重要。将转录搜索从 LLM 替换为 BM25 使 Token 使用量降低 3.3 倍，但准确率下降 6.8%，说明 LLM 在语义匹配上的优势不可完全替代。EGAgent 回答一个 MCQ 的墙钟延迟为 2-3 分钟，主要耗时在规划智能体的多轮工具调用上。

评估边界方面，EgoLifeQA 仅包含 500 个样本，统计显著性有限；Video-MME (Long) 上 EGAgent 未超越原生 MLLM，表明在亚小时级视频中，结构化图检索的增益不足以抵消其离线构建开销。代码已开源，但实体图构建依赖 LLM 提取器，不同 LLM 版本可能导致图结构差异，影响可复现性。

## 关联研究分析

从问题动机看，EGAgent 与 Video-RAG 均旨在解决长视频上下文溢出问题，但 Video-RAG 依赖向量相似度检索非结构化片段，而 EGAgent 通过实体图实现结构化关系查询。这一差异源于任务特性：EgoLifeQA 强调跨天实体关系追踪（如“谁经常坐在我旁边”），需要显式建模实体间关系，而 Video-RAG 的扁平检索无法区分“Jake 与 Shure 交谈”和“Jake 与 Lucia 交谈”的语义差异。然而，EGAgent 的图构建依赖 LLM 提取，若 LLM 未能正确识别实体或关系，图结构将存在噪声，这在细粒度视觉细节任务上可能成为瓶颈。

从方法设计看，EGAgent 与 GraphRAG 共享知识图谱思想，但 GraphRAG 面向文本语料，而 EGAgent 扩展至视频时空维度，增加了时间戳标注和多模态节点。与 LongVT 等强化学习驱动的代理方法相比，EGAgent 未使用 RL 优化工具调用策略，而是依赖 LLM 的推理能力进行任务分解。这种设计简化了训练流程，但可能限制了智能体在复杂查询下的策略优化能力。LongVT 通过 RL 激励“假设-验证”循环，可能在证据极度稀疏的任务上更具鲁棒性，而 EGAgent 的 SQL 查询依赖图结构的完整性，若图缺失关键关系，智能体将无法通过查询获取证据。

## 总结

EGAgent 针对极长视频中实体关系追踪失效的问题，通过离线构建带时间戳的实体场景图，将非结构化视频转化为可查询的结构化关系网络，使智能体能够通过 SQL 查询直接定位跨天关系。在 EgoLifeQA 上，该方法在 RelationMap 类别上超越前 SOTA 32%，证明了结构化表示在多跳关系推理中的优势。然而，其性能高度依赖 LLM 骨干能力（Gemini 2.5 Pro 骨干下才达到 SOTA），且在 Video-MME (Long) 上未超越原生 MLLM，表明在亚小时级视频中，图检索的增益不足以抵消离线构建开销。当视频长度进一步增加至数月级时，实体图的增量更新效率与噪声累积问题是否会导致检索精度下降，论文未给出回答。
