# ACL2026最新论文 ｜HERMES: KV Cache as Hierarchical Memory for Efficient Streaming Video Understanding ｜分层键值缓存记忆

研究机构：复旦大学、新加坡国立大学

作者：Haowei Zhang、Shudong Yang、Jinlan Fu 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.14724)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.14724)

> 流式视频理解面临无限输入与有限显存的物理冲突，现有方法或依赖外部检索引入延迟，或采用统一驱逐策略丢失长程语义。本文切入点在于发现多模态大语言模型（MLLMs）不同解码层对视频信息的注意力偏好存在天然分化，据此将键值缓存（KV Cache）重构为分层记忆系统。通过层级差异化驱逐与跨层平滑机制，HERMES 在无训练条件下实现了实时响应与精度保持。其价值在于以机制可解释性替代黑盒压缩，但通用引导提示的局限使其在特定领域场景下的适应性存疑。

## 研究背景

流式视频理解要求模型在因果约束下处理连续帧序列，核心瓶颈在于视觉 Token 的持续累积导致显存溢出。为维持实时性，系统需在有限内存预算内决定保留哪些历史帧信息。这一决策直接关联键值缓存（KV Cache）的管理策略，因为 KV Cache 是 MLLMs 存储历史上下文的关键载体，其压缩率与信息保留度的平衡决定了模型的长程理解能力。

现有流式内存管理路线主要分为外部记忆与内部记忆两类。外部记忆方法将视频内容存储于 CPU 或磁盘，查询时进行检索与预填充，如 ReKV 和 LiveVLM，但这一过程引入了显著的传输延迟与计算开销。内部记忆方法则直接在 GPU 内管理 KV Cache，如 StreamMem 利用聊天模板引导压缩，但缺乏细粒度的层级管理。主流方案普遍采用统一的先进先出（FIFO）驱逐策略，忽视了模型内部不同层级对视觉信息处理功能的差异，导致在长视频流中细粒度感知与长程语义记忆难以兼得。

本文针对统一驱逐策略的缺陷，提出基于注意力机制实证的分层记忆框架。通过揭示浅层、中层、深层在视频 Token 注意力分布上的功能分化，HERMES 将 KV Cache 转化为具备感官、工作、长期记忆功能的层级系统，从而在无训练条件下实现更精细的内存管理。

## 核心方法

### 层级注意力参照系

流式视频处理的标准流程是逐块编码视频流，当 KV Cache 达到预设预算时触发 Token 驱逐。传统方法通常对所有层采用相同的驱逐标准，如基于时间距离的 FIFO 或基于全局注意力权重的 Top-K。本文的关键差异在于，驱逐策略不再全局统一，而是依据解码层在视觉信息处理中的功能角色进行差异化设计。

### 层级差异化驱逐策略

针对统一驱逐导致长程语义丢失的问题，本文根据层级注意力特性设计了三类重要性评分函数。浅层作为感官记忆，表现出强烈的近期偏差，其重要性评分采用指数遗忘曲线，模拟人类记忆随时间衰减的特性：

$$ S_i^{shallow} = e^{-k \cdot (T - i)} $$

其中 $T$ 为缓存总 Token 数，$k$ 为遗忘率，该公式确保浅层优先保留最新帧信息。深层作为长期记忆，注意力分布稀疏且呈现周期性，其重要性直接由用户查询的注意力权重决定：

$$ S_i^{deep} = W_i^{deep} $$

这里 $W_i^{deep}$ 为第 $i$ 个 Token 在深层的归一化注意力权重，利用通用引导提示作为伪查询，确保深层保留帧级锚点 Token。中层作为工作记忆，通过插值平衡近期偏差与注意力驱动：

$$ S_i^{middle} = \omega_0 \cdot S_i^{shallow} + (1-\omega_0) \cdot S_i^{deep} $$

其中 $\omega_0 = 0.75$，该设计使中层能够桥接短期感官痕迹与长期语义摘要，解决了单一策略无法兼顾细节与长程依赖的失效。

### 跨层记忆平滑与位置重索引

层级独立驱逐可能导致同一缓存索引在不同层被不同 Token 占据，造成视觉记忆错位。为解决此问题，本文引入跨层记忆平滑，将深层的重要性信号向浅层传播：

$$ \tilde{S}_i^{l} = (1-\lambda) S_i^{l} + \lambda S_i^{l+1} $$

其中 $\lambda$ 为平滑超参数，该机制确保了层级间视觉记忆的连贯性。同时，为防止流式输入导致的位置索引超出模型范围，采用惰性重索引策略，仅在索引接近上限时将其重映射至连续区间 $[0, |M|)$，避免了频繁重索引带来的计算开销，维持了流式因果约束下的推理稳定性。

## 实验评估

实验在 StreamingBench、OVO-Bench、RVS 等流式基准及 VideoMME、Egoschema 等离线基准上进行，基线覆盖离线 MLLM、在线 MLLM 及无训练方法（ReKV, LiveVLM, StreamMem）。缺失与 2026 年最新主动推理方法（如 VST, Wan-Streamer）的直接对比，限制了其在综合流式理解维度的定位。

| 模型 | 基准 | 准确率 (%) |
| :--- | :--- | :--- |
| Qwen2.5-VL-7B + HERMES (4K) | StreamingBench | 79.44 |
| Qwen2.5-VL-7B + HERMES (4K) | OVO-Bench | 59.21 |
| LLaVA-OV-7B + HERMES (6K) | RVS-Ego | 60.3 |
| LLaVA-OV-7B + HERMES (4K) | VideoMME | 58.85 |

在 StreamingBench 上，HERMES 基于 Qwen2.5-VL-7B 取得 79.44% 准确率，较基线提升 6.13%；在 RVS-Ego 上，LLaVA-OV-7B 版本取得 60.3% 准确率，显著优于 ReKV 的 57.0%。效率测试显示，在 256 帧输入下，HERMES 的 TTFT 较 SOTA 方法 StreamingTOM 加速 10 倍，且 GPU 显存占用保持恒定。

消融实验表明，层级预算分配对整体性能影响较小，但向深层分配更多 Token 能提升长视频子集性能。跨层平滑机制在 VideoMME 上带来 3.7 个百分点的提升，验证了层级一致性的重要性。位置重索引策略中，惰性重索引在流式任务上优于急迫重索引，而急迫重索引在离线任务上表现更佳，反映了两种场景对位置连续性的不同需求。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码已开源，超参数配置详细，但实验仅覆盖 0.5B 至 32B 参数规模，未验证 72B 大模型下的有效性。通用引导提示的使用可能限制了方法在特定领域（如驾驶）中的细粒度语义适应能力。

## 关联研究分析

从方法设计看，HERMES 与 StreamingVLM 均致力于解决无限流输入下的上下文断裂问题，但 StreamingVLM 采用注意力沉没与连续 RoPE 位置编码，属于架构层面的标准化方案，而 HERMES 聚焦于 KV Cache 内部的层级管理，属于内存管理层面的精细化策略。两者的核心差异在于：StreamingVLM 通过修改位置编码机制维持长程依赖，HERMES 则通过差异化驱逐策略保留关键信息。这种差异源于任务侧重点的不同，前者关注架构的通用性，后者关注内存效率与精度的平衡。

从问题动机看，HERMES 与 ReKV、LiveVLM 同属无训练流式方法，但 ReKV 和 LiveVLM 依赖外部 CPU/磁盘存储与检索，导致查询时延迟显著。HERMES 摒弃了外部检索环节，将记忆完全内化于 GPU 内的 KV Cache，通过层级管理实现无辅助计算的实时响应。这一设计选择解决了外部记忆方法在低延迟场景下的瓶颈，但其代价是放弃了外部存储的容量优势，在超长视频流中可能面临内存预算不足的局限。

## 总结

HERMES 旨在解决流式视频理解中无限输入与有限显存的矛盾，其切入点在于利用 MLLMs 解码层的注意力分化特性，将 KV Cache 重构为分层记忆系统。通过层级差异化驱逐与跨层平滑，该方法在无训练条件下实现了 10 倍 TTFT 加速与 68% Token 压缩，同时在 StreamingBench 上取得 79.44% 的准确率。其边界在于通用引导提示的局限性，以及未验证超大模型下的有效性。当视频流包含高度专业化的领域语义时，基于通用提示的层级重要性评分是否仍能准确区分关键信息，论文未给出回答。
