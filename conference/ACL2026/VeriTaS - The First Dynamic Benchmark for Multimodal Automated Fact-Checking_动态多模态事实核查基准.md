# ACL2026最新论文 ｜VeriTaS: The First Dynamic Benchmark for Multimodal Automated Fact-Checking ｜动态多模态事实核查基准

论文原文见 [arXiv](https://arxiv.org/abs/2601.08611)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.08611)

> 自动化事实核查（Automated Fact-Checking, AFC）旨在替代人工核查以应对海量错误信息，但现有静态基准因大语言模型（Large Language Models, LLMs）预训练数据泄露而失效，导致评估结果虚高。VERITAS 通过季度自动更新切断泄露路径，并首次整合图像与视频模态，重新定义了评估指标。其核心贡献在于构建了一个抗泄露、细粒度且多模态的评估基础设施，但当前最佳模型性能仍远低于可接受阈值，揭示了多模态验证的巨大缺口。

## 研究背景

当 LLM 在公开网络数据上持续预训练时，历史事实核查声明及其判决结果会被隐式编码进模型参数。这种数据泄露导致静态基准上的高分往往反映的是记忆而非推理能力，使得评估效度在模型知识截止日期（Knowledge Cutoff Date, KCD）后急剧下降。为量化这一效应，需引入动态基准，即通过定期引入新声明来确保测试集始终位于模型训练数据之外，从而隔离参数记忆对评估结果的干扰。

AFC 领域长期受限于任务碎片化与模态缺失。多数基准将核查分解为图像语境化、操纵检测等子任务，或仅覆盖纯文本声明，无法反映多模态内容在错误信息传播中的主导作用。现有静态基准如 FEVER 和 LIAR 虽奠定了评估标准，但其数据源与 LLM 预训练语料高度重叠，导致评估结果系统性偏高。VERITAS 的切入点在于解决“评估效度危机”：通过构建首个动态、多模态且多语言的基准，强制模型在开放、实时且对抗的环境中验证声明，而非依赖静态记忆。

## 核心方法

### 评估基础设施参照系

传统 AFC 基准构建遵循“数据采集-人工标注-静态发布”流程，其核心假设是测试数据与模型训练数据正交。本文问题与该通用流程的关键差异在于：LLM 的持续预训练打破了这一正交性，要求基准具备时间维度的动态扩展能力，且标注协议需从离散分类转向连续评分以捕捉不确定性。

### 七阶段自动化构建流水线

设计动机：解决人工标注不可扩展及合成声明缺乏真实性的问题，实现季度级自动更新。流水线从 ClaimReview 模式检索约 371K 专家审查记录，经发布者可信度过滤（剔除 15% 非专业来源）、文章抓取与媒体去重（余弦相似度阈值 0.85），最终生成 24K 条标准化声明。关键创新在于声明重写与判决标准化：利用 GPT-5.2 和 Gemini 2.5 Pro 将原始文本重写为自包含声明，并通过四模型集成（GPT-5.2, Gemini 2.5 Pro, Claude Sonnet 4.5, Llama 4 Maverick）对判决进行投票，剔除集成内部分差超过 1 的样本（约 2.8%），确保标注一致性。

$$
\text{Integrity} = \min(\text{Contextualization}, \text{Veracity}, \text{Context Coverage})
$$

该公式表明整体完整性由最低分属性决定，任一属性违规即导致声明被标记为“受损”（Compromised），实现了从单一标签到多属性解耦的映射。

### 细粒度不确定性评分机制

设计动机：解决传统三分类（Supports/Refutes/NEI）将严重混淆（True vs. False）与轻微混淆（True vs. NEI）同等对待的问题。VERITAS 将声明评估解耦为媒体真实性、媒体语境化、真实性（Veracity）和语境覆盖四个独立属性，每个属性在 $[-1, 1]$ 区间内评分，0 表示完全不确定（NEI）。评估指标采用均方误差（Mean Squared Error, MSE），其惩罚机制如下：

$$
\text{MSE} = \frac{1}{N} \sum_{i=1}^{N} (y_i - \hat{y}_i)^2
$$

MSE 对翻转错误（如预测 1 而实际 -1）施加平方级惩罚，而对接近正确的预测给予较低惩罚，从而在指标层面区分了“逻辑错误”与“置信度不足”，迫使模型不仅预测正确标签，还需校准其不确定性输出。

## 实验评估

在 Q4-2025 分割集上，VERITAS 测试了六个基础模型及两个专用 AFC 系统（DEFAME, LOKI）。基线覆盖审计显示，测试对象包含 SOTA 多模态模型（Gemini 3 Pro, GPT-5.2）及开源模型（Llama 4 Maverick），但缺失知识库中提到的检索增强专用系统（如 ClaimCheck）或多智能体辩论框架（如 GAVEL），这可能低估了复杂推理架构在动态场景下的表现。

| 方法 | Search | MSE (↓) | MAE (↓) | Acc. (↑) |
|---|---|---|---|---|
| GEMINI 3 PRO | ✓ | 0.39 | 0.35 | 74.6 |
| GPT-5.2 | ✓ | 0.45 | 0.40 | 70.6 |
| DEFAME (w/ GPT-5.2) | ✓ | 0.55 | 0.49 | 60.4 |
| LOKI (w/ GPT-5.2) | ✓ | 0.86 | 0.59 | 61.8 |
| LLAMA 4 MAVERICK | ✓ | 1.04 | 0.72 | 49.6 |

最佳模型 Gemini 3 Pro 在启用搜索后 MSE 降至 0.39，但仍远高于 0.1 的可接受阈值，表明即使 SOTA 模型在动态多模态场景下也缺乏可靠的验证能力。专用系统 LOKI 表现最差，MSE 高达 0.86，接近随机猜测水平，挑战了专用架构优于通用 LLM 的假设。

消融实验验证了集成投票与过滤机制的有效性。移除过滤（no filtering）导致 MSE 从 0.034 升至 0.042，移除集成（no ensemble）则使 MSE 激增至 0.086，准确率从 96.8% 降至 93.9%。这表明集成投票对维持标注一致性至关重要，单模型标注会引入显著噪声。纵向分析显示，所有模型在 KCD 后 MSE 平均从 0.6 升至 0.8 以上，证实了数据泄露对静态基准评估效度的系统性破坏。

评估边界方面，VERITAS 仅使用 Q4-2025 作为可靠基准分割，早期季度因审查覆盖不足被排除，限制了长期趋势分析的粒度。代码与数据承诺公开，但七阶段流水线依赖特定 LLM 版本（GPT-5.2, Gemini 2.5 Pro），模型迭代可能导致标注分布漂移，复现性受限于 LLM 服务的稳定性。

## 关联研究分析

从问题动机看，VERITAS 与 MUMIN 和 TRUE 同属动态基准路线，但二者均缺乏视频模态或图像覆盖，且未解决多语言问题。VERITAS 的核心差异在于其“动态性”并非仅指数据更新，而是通过季度分割强制模型面对 KCD 后的未知声明，直接针对 LLM 参数记忆这一根本缺陷。相比之下，MUMIN 和 TRUE 的自动化流程虽具可扩展性，但未显式建模时间维度上的评估效度衰减，其动态更新更多服务于数据规模而非评估严谨性。

从方法设计看，VERITAS 的细粒度评分机制与 FActScore 的分解-验证范式存在逻辑共鸣，但 FActScore 聚焦于长文本原子事实的独立验证，而 VERITAS 将分解应用于声明与媒体属性的正交解耦。关键差异在于 VERITAS 引入了媒体真实性与语境化属性，解决了 FActScore 等纯文本方法无法处理的视觉证据对齐问题。然而，VERITAS 未采用多智能体辩论机制，其集成投票仅用于标注一致性而非推理增强，这可能导致其在复杂多跳推理场景下的评估灵敏度不足，专用系统 LOKI 的失败是否归因于缺乏此类推理增强机制，论文未给出回答。

## 总结

VERITAS 解决了静态 AFC 基准在 LLM 持续预训练下的评估效度危机，通过季度自动更新与细粒度不确定性评分，构建了首个抗泄露的多模态评估基础设施。其核心创新在于将评估指标从离散分类转向连续 MSE，强制模型校准不确定性，并通过七阶段流水线实现大规模真实声明的标准化。实验证明，即使 SOTA 模型在动态场景下 MSE 仍高达 0.39，远低于 0.1 的可接受阈值，揭示了多模态事实核查的远未解决状态。本文的边界在于其评估协议未涵盖多智能体推理增强系统，且标注依赖特定 LLM 版本，可能引入模型迭代带来的分布漂移。当专用 AFC 系统在 VERITAS 上的表现显著低于通用 LLM 时，这种差距是源于细粒度评分对推理深度的要求，还是专用架构在动态开放域中的固有局限，仍需进一步验证。
