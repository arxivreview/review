# ACL2026最新论文 ｜SkMTEB: Slovak Massive Text Embedding Benchmark and Model Adaptation ｜斯洛伐克语嵌入基准与模型压缩

作者：Marek Šuppa、Andrej Ridzik、Daniel Hládek 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.13647)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.13647)

> 文本嵌入模型在低资源语言上的性能瓶颈源于词汇表冗余与训练数据覆盖不足，导致多语言大模型在特定语言上表现退化且部署成本高昂。现有方案要么依赖高资源语言预训练权重的直接迁移，要么通过从头训练专用模型，前者缺乏针对性，后者计算开销巨大。本文切入点在于构建首个斯洛伐克语深度基准 SkMTEB，并验证“词汇修剪+定向微调”的低成本适配路径。该方法通过移除无关词元将模型参数缩减 62%，在保持跨语言迁移能力的同时实现了本地化部署，但其性能上限仍受限于预训练骨干的通用语义容量。

## 研究背景

当多语言嵌入模型处理斯洛伐克语等低资源语言时，其词表中大量非目标语言词元占据 30%-40% 的参数空间，却对目标语言语义贡献甚微。这种结构性冗余导致模型在特定语言上的表示能力被稀释，且高维嵌入向量在边缘设备上的推理延迟难以接受。解决此问题需同时满足两个条件：一是建立能诊断语言特异性缺陷的评估基准，二是开发能在有限算力下提升目标语言性能的模型压缩技术。

通用嵌入领域已确立 MTEB 作为标准评估框架，但其在低资源语言上的覆盖深度严重不足。以斯洛伐克语为例，MMTEB 仅包含 8 个任务，仅为英语 MTEB 深度的 14%，且缺乏本土检索、领域特定任务等关键场景。现有斯洛伐克语基准 skLEP 仅覆盖自然语言理解任务，未涉及嵌入模型核心的检索与相似度计算。这种评估真空使得模型性能无法被准确诊断，也阻碍了针对特定语言的高效适配策略研发。

本文针对这一双重缺失，构建了包含 31 个数据集、7 种任务类型的 SkMTEB 基准，并探索了基于词汇修剪（Vocabulary Trimming, VT）与定向微调的模型压缩路径。该路径不同于 LLM2Vec 等双向化改造或 Conan-Embedding-v2 的从头训练，而是聚焦于预训练模型词表结构的精简，旨在以极低的计算成本实现语言特异性嵌入模型的本地化部署。

## 核心方法

### 基准构建与任务覆盖

SkMTEB 遵循 MTEB 框架，但针对斯洛伐克语资源匮乏的现状进行了深度定制。基准包含 31 个数据集，其中 7 个为全新构建，25 个为现有数据集的适配，仅 6 个与 MMTEB 重叠。任务类型涵盖检索、重排序、分类、聚类、双语挖掘、对分类及语义文本相似度（STS）。这种设计确保了评估不仅覆盖通用语义能力，还包含医疗、议会辩论、事实核查等斯洛伐克语特有领域场景，弥补了通用多语言基准在语言特异性诊断上的盲区。

### 词汇修剪与定向微调

本文的核心创新在于将词汇修剪（VT）应用于嵌入模型适配流程。传统微调直接作用于完整词表，而本文在微调前基于 FineWeb2-Slovak 语料库的词频统计，保留 60K 高频词元，移除其余 190K 无关词元。这一操作将 E5-small 参数从 118M 缩减至 45M（62% 缩减），E5-large 从 560M 缩减至 365M（35% 缩减）。修剪后的模型在 skLEP 数据集（SKSQuAD、NLI、STS、RTE）上进行定向微调，使用 Mean Pooling 与 Multiple Negatives Ranking Loss (MNL Loss)。

$$
\mathcal{L}_{MNL} = -\log \frac{\exp(\text{sim}(q, d^+) / \tau)}{\sum_{i=1}^{N} \exp(\text{sim}(q, d_i) / \tau)}
$$

该损失函数通过优化正样本对与负样本对的相似度差异，塑造嵌入空间的几何结构。VT 的设计动机在于消除词表冗余对参数空间的占用，使模型容量更集中于目标语言的高频语义单元。实验表明，VT 不仅未损害性能，反而因去除了噪声词元，使小模型在分类任务上获得 +0.13 的性能提升，验证了“少即是多”的压缩有效性。

### 指令前缀与跨语言迁移保持

在微调基础上，本文引入 query:/passage: 前缀作为指令微调信号。消融实验显示，该策略对 E5-small 带来 +0.51 的性能增益，而对 E5-large 仅 +0.02，表明显式任务区分对容量受限的小模型更具价值。针对 VT 可能损害跨语言迁移的担忧，本文在斯洛伐克语-英语、斯洛伐克语-捷克语双语挖掘任务上进行了验证。结果显示，修剪后模型在 6 个双语任务上的 F1 分数变化均在 1 点以内，平均变化仅为 0.25 F1（小模型）和 0.04 F1（大模型），证明目标语言词表精简并未破坏模型的多语言对齐能力。

## 实验评估

SkMTEB 评估了 31 个模型，涵盖从 45M 到 8B 参数的开源模型及专有 API。基线覆盖 Multilingual E5、BGE-M3、Jina、Qwen3-Embedding 等主流家族，但缺失 ColBERT 等多向量表示基线，这可能影响对细粒度检索任务的全面评估。主实验结果显示，multilingual-e5-large-instruct 以 77.49 分领先，gemini-embedding-001 紧随其后（77.23）。值得注意的是，3.8B 参数的 jina-embeddings-v4 得分仅为 72.44，低于 568M 参数的 snowflake-arctic-embed-l-v2.0（72.54）和 330M 参数的 nomic-embed-text-v2-moe（72.58），表明在斯洛伐克语任务上，规模扩张存在边际收益递减现象。

| 模型 | 参数量 | SkMTEB 平均分 | 备注 |
| :--- | :--- | :--- | :--- |
| multilingual-e5-large-instruct | 560M | 77.49 | 最佳开源模型 |
| gemini-embedding-001 | — | 77.23 | 专有 API |
| e5-sk-large (VT+FT) | 365M | 74.70 | 本文压缩模型 |
| text-embedding-3-large | — | 75.07 | 专有 API |
| e5-sk-small (VT+FT) | 45M | 70.56 | 本文压缩模型 |
| text-embedding-3-small | — | 70.48 | 专有 API |

消融实验揭示了 VT、FT 与前缀的独立贡献。VT 单独应用带来 +0.13（小）和 +0.31（大）的提升，FT 带来 +0.26（小）和 +0.21（大）的提升。组合 VT+FT 后，E5-small 达到 70.56 分，与专有 API text-embedding-3-small（70.48）持平，而参数量仅为后者的 1/10 左右。前缀策略对小模型的增益（+0.51）显著大于大模型（+0.02），暗示小模型更依赖显式任务信号来弥补容量不足。

评估边界方面，SkMTEB 仅覆盖斯洛伐克语，无法直接反映模型在其他低资源语言上的泛化能力。实验使用单一 NVIDIA H100 GPU，训练时间小于 1 小时，超参数固定（学习率 $2 \times 10^{-5}$，3 epochs），确保了可复现性。然而，论文未报告置信区间，且部分数据集（如 SlovakSumSTS）依赖 LLM 生成并经人工验证，可能存在标注偏差。

## 关联研究分析

从方法设计看，本文的词汇修剪路径与 Matryoshka 表示学习（MRL）形成鲜明对比。MRL 通过维度截断实现压缩，依赖模型在训练时学习不同维度下的性能保持，而 VT 通过词表精简实现压缩，依赖预训练阶段已习得的语义分布。VT 的优势在于无需重新训练即可大幅缩减参数，且对跨语言迁移影响极小；劣势在于其压缩上限受限于目标语言词表大小，无法像 MRL 那样灵活调整嵌入维度。本文未探索 VT 与 MRL 的结合，这可能在进一步压缩时提供互补收益。

从问题动机看，本文聚焦于低资源语言的“本地化部署”，而 LLM2Vec 等 LLM 适配方法聚焦于“全局语义捕获”。LLM2Vec 通过移除因果掩码引入双向注意力，解决了因果注意力在嵌入任务中的信息瓶颈，但改造过程复杂且可能损失生成能力。本文则保留因果注意力结构，仅精简词表，牺牲了部分全局语义捕获能力，换取了极低的部署成本。这种取舍反映了低资源语言场景下“可用性优先于最优性”的工程逻辑，但论文未量化这种取舍在复杂语义任务（如长文档检索）上的具体损失。

## 总结

本文针对低资源语言嵌入模型评估缺失与部署成本高的矛盾，构建了 SkMTEB 基准并验证了词汇修剪+定向微调的压缩路径。该方法将 E5-small 参数缩减 62% 至 45M，性能与专有 API 持平，证明了低成本适配的可行性。然而，实验显示 3.8B 模型在斯洛伐克语上未显著优于 500M 模型，暗示预训练骨干的通用语义容量可能是性能上限的主要制约因素，而非模型规模。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
