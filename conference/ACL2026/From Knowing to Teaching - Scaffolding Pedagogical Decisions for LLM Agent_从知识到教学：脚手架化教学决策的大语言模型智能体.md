# ACL2026最新论文 ｜From Knowing to Teaching: Scaffolding Pedagogical Decisions for LLM Agent ｜从知识到教学：脚手架化教学决策的大语言模型智能体

研究机构：清华大学、美国麻省理工学院

作者：Yucheng Wang、Shen Yang、Jifan Yu 等 10 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_c25d8b3aad79)

> 大语言模型（LLM）生成的教育内容常因缺乏教学意图而沦为流畅但无效的文本，现有单文档或纯格式转换方法无法解决跨组件的逻辑断裂。本文切入点在于将学科教学知识（PCK）解构为选择、排序与综合三个可计算决策，通过三智能体协同实现多文档教学合成。实验显示其在自建基准上取得67.8%的人类胜率，但视觉生成能力仍逊于专用代码生成模型，且基准的逆向工程构建方式限制了泛化性验证。

## 研究背景

当LLM面对异构教学材料时，其参数化知识虽能检索事实，却无法区分“核心内容”与“风格模板”的教学角色，导致生成内容出现意图错位。这种意图缺失进一步引发认知层级混乱，模型往往跳过基础概念直接生成高阶应用题，违背了Bloom分类法所要求的认知进阶规律。最终，幻灯片、脚本与测验之间缺乏术语与逻辑的一致性，形成“跨组件断裂”，使得教学材料在整体上失去连贯性。

解决这一“知-教鸿沟”的主流路线包括基于ADDIE框架的规划系统（如Instructional Agents）和端到端合成工具（如NotebookLM）。前者虽具备阶段划分，但缺乏对源文档的接地，导致生成内容脱离具体教材；后者虽能处理多文档，但缺乏显式的教学决策结构，无法保证认知进阶与组件一致性。现有方法均未同时建模专家教师的三个核心决策：基于意图的选择、基于Bloom层级的排序以及基于Schema的综合。TeachCraft针对这一空白，提出通过专门化智能体显式执行这三个决策，将PCK理论转化为可操作的计算流程。

## 核心方法

### 多文档教学合成参照系

本文任务属于多文档摘要（MDS）的教育特化版本，但关键差异在于输出并非单一文本，而是包含幻灯片、脚本与测验的异构组件集合。通用MDS系统通常执行聚合（选择与拼接），而教育合成要求真正的综合（生成新文本并确保跨组件一致性）。TeachCraft将这一过程形式化为 $L = f(D, R) = (A_G \circ A_P \circ A_E)(D, R)$，其中 $A_E, A_P, A_G$ 分别对应选择、排序与综合智能体，输入为异构文档 $D$ 与需求 $R$，输出为教学组件序列 $L$。

### 意图感知选择与Bloom排序

Explorer智能体解决“选什么”的问题，通过六类意图分类（Content, Prerequisite, Supplementary, Application, Assessment, Style）将原始文档块 $c$ 映射为教学角色 $\psi(c)$，公式为 $C = \{(c, \psi(c)) \mid c \in C_{raw}\}$。这一设计动机在于打破LLM将所有输入视为可互换文本的默认行为，确保风格模板不被误用为内容。Planner智能体解决“怎么排”的问题，提取学习目标 $O$ 并依据Bloom层级 $\beta$ 进行排序，约束条件为 $\beta(o_i) \le \beta(o_j)$ 当 $o_i$ 先于 $o_j$。该机制强制基础概念先于应用题出现，解决了模型直接生成高阶内容导致的认知断层。

### Schema驱动的综合与一致性约束

Generator智能体解决“如何连贯”的问题，采用“文件系统作为记忆”架构，在生成组件 $c_j$ 前加载前序组件 $c_1, \dots, c_{j-1}$ 的结构化文件。生成过程受Schema $\sigma_j = (LO_j, \beta_j, terms_j, layout_j)$ 约束，公式为 $c_j = \phi(M_j, \sigma_j)$。其中 $terms_j$ 确保术语与前序幻灯片一致，$LO_j$ 确保测验仅测试已引入的目标。这一设计动机在于克服长上下文窗口中的信息漂移，通过显式文件读取而非隐式记忆，保证测验问题与幻灯片内容的严格对齐，如避免测试未在幻灯片中出现的HeapSort。

## 实验评估

LESSONBENCH基准包含40个专家设计的课程，源自MIT OCW与Khan Academy的逆向工程源文档，覆盖STEM、社科、人文与专业领域。基线涵盖直接提示（GPT-5, Claude Sonnet 4.5）、通用智能体（Manus, ChatGPT Agent, Claude Code）与教育系统（Instructional Agents, NotebookLM）三类。TeachCraft在人类评估中取得67.8%胜率，LLM评估中达79.6%，其中对NotebookLM的人类胜率仅为49.8%，但LLM胜率高达74.4%，揭示人类对视觉复杂度的偏好掩盖了逻辑缺陷。

| 基线类型 | 代表方法 | 人类胜率 (%) | LLM胜率 (%) |
|---|---|---|---|
| 教育系统 | NotebookLM | 49.8 | 74.4 |
| 教育系统 | Instructional Agents | 55.0 | — |
| 通用智能体 | Claude Code | 62.3 | — |
| 通用智能体 | ChatGPT Agent | 90.8 | — |

消融实验显示，移除Schema综合导致胜率降至95.3%（相对于完整系统的相对性能），移除Bloom排序降至92.3%，移除意图选择降至73.5%。这表明跨组件一致性（Schema）对整体质量的影响最大，其次为认知排序，意图选择的影响相对较小但显著。在SLIDESBENCH上，TeachCraft平均分为67.2，执行率100%，优于GPT-4o+SlidesLib的86.7%执行率，但图像质量（70.8）低于GPT-4o（83.7），反映其优先文本逻辑而非视觉装饰的设计取舍。

评估协议采用盲法成对比较，24名人类评估者产生920个判断，Gwet’s AC1为0.70，表明人类与LLM评估者间存在实质性一致。局限在于LESSONBENCH的源文档为逆向工程生成，可能引入人工偏差；且未报告计算延迟与成本，限制了部署可行性评估。代码已开源，但超参数细节仅在附录中提供，复现需依赖Gemini 2.5 Pro作为骨干模型。

## 关联研究分析

从问题动机看，TeachCraft与EduAgentQG同属多智能体教育生成，但EduAgentQG聚焦数学题目的难度控制与求解验证，而TeachCraft关注跨组件（幻灯片-脚本-测验）的一致性。这一差异源于任务特性：数学题目是单一模态的封闭问题，而教学课程是多模态的开放系统，后者更需要Schema约束来防止术语漂移。EduAgentQG的“求解者验证”机制在TeachCraft中被“Schema一致性检查”取代，因为教学内容的正确性不仅在于答案对错，更在于组件间的逻辑连贯。

从方法设计看，TeachCraft与Instructional Agents均基于ADDIE框架，但后者缺乏文档接地，仅从主题名称生成计划，导致内容脱离具体教材。TeachCraft通过Explorer的意图分类实现文档接地，将ADDIE的阶段划分与具体源文档绑定。这一改进解决了Instructional Agents在Query Fulfillment维度上的短板（51.7%胜率），但代价是增加了文档解析与意图分类的计算开销。NotebookLM作为端到端系统，虽能处理多文档，但缺乏显式教学决策结构，导致其在LLM评估中暴露出逻辑缺陷，而TeachCraft通过显式智能体分工弥补了这一盲区。

## 总结

TeachCraft旨在解决LLM生成教育内容时“知-教鸿沟”导致的跨组件断裂与认知断层问题。其切入点在于将PCK理论解构为选择、排序、综合三个可计算决策，通过Explorer-Planner-Generator三智能体协同实现多文档教学合成。实验证明，该框架在LESSONBENCH上取得67.8%人类胜率与79.6% LLM胜率，消融实验确认Schema综合对一致性的关键作用。然而，其视觉生成能力（SLIDESBENCH图像分70.8）仍逊于专用代码生成模型，且基准的逆向工程构建方式限制了泛化性验证。当源文档的意图标注存在噪声时，Explorer的分类准确率对最终教学质量的因果影响如何量化，论文未给出回答。
