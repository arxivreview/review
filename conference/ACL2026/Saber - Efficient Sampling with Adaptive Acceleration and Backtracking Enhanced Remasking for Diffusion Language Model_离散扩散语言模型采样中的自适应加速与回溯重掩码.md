# ACL2026最新论文 ｜Saber: Efficient Sampling with Adaptive Acceleration and Backtracking Enhanced Remasking for Diffusion Language Model in Code Generation ｜离散扩散语言模型采样中的自适应加速与回溯重掩码

作者：Yihong Dong、Zhaoyu Ma、Xue Jiang 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_5c814a77c104)

> 离散扩散语言模型（DLM）在代码生成等强结构约束任务中，面临并行解码速度与输出质量不可兼得的根本矛盾：增加并行度以缩短采样步数时，Pass@1 准确率可骤降超过 60%。现有静态加速策略因无法适应生成难度的动态变化且缺乏错误修正机制，导致早期高置信度错误不可逆地污染后续上下文。Saber 通过基于演化置信度的动态阈值自适应调整每步去掩码数量，并引入回溯机制撤销因新上下文暴露的早期错误，在无需训练的前提下同时提升速度与质量。该方法在 HumanEval 上实现 45.12% 的 Pass@1 与 41:55 的推理时间，但理论误差界依赖置信度校准假设，其统计显著性与跨架构泛化边界尚待更严格的验证。

## 研究背景

DLM 通过迭代去噪过程并行更新多个 token 位置，其核心状态由已去掩码集合 $U_t$ 和待去掩码集合 $M_t$ 定义。模型对每个掩码位置 $i \in M_t$ 输出词表上的概率分布，其 top-1 预测的置信度 $c_i$ 成为采样决策的关键依据。与自回归模型（ARM）仅决定“下一个 token 是什么”不同，DLM 必须同时决定“在哪里生成”和“生成什么”，这使得早期在稀疏上下文下做出的错误选择会被永久锁定，并破坏所有后续步骤的上下文完整性。

DLM 采样加速的主流路线是静态并行策略，如 Fast-dLLM 和 WINO 使用固定阈值或固定 token 数量决定每步去掩码规模。这些方法假设生成难度在序列中均匀分布，但代码生成任务中，初始步骤上下文稀疏、预测难度高，后期步骤上下文丰富、难度显著降低。静态策略在简单阶段过于保守浪费计算，在复杂阶段过于激进导致质量崩塌。ReMDM 虽引入重掩码机制，但仅在固定阶段执行，无法动态响应置信度的实时变化。Saber 的切入点在于识别出 DLM 采样的两个被忽略的动态特性：生成难度随上下文积累单调递减，以及已生成 token 的置信度会随新上下文出现而剧烈波动，从而需要自适应加速与动态回溯的协同机制。

## 核心方法

### 方法参照系

DLM 标准采样流程为：每步计算所有掩码位置的置信度，贪心选择最高置信度 token 去掩码。该流程保证质量但速度极慢（256 步）。并行采样变体通过放宽选择标准加速，但缺乏对难度动态性和错误传播的显式建模。Saber 的关键差异在于将采样决策从静态规则升级为基于历史置信度演化的动态反馈控制。

### 自适应动态去掩码

静态阈值无法适应生成难度的非均匀分布，导致早期过度保守或后期过度激进。Saber 引入动态阈值 $\tau_t$，定义为所有已去掩码 token 在去掩码时刻置信度的历史均值：

$$
\tau_t = \begin{cases} \frac{1}{|U_{t-1}|} \sum_{j \in U_{t-1}} c_j^{\text{unmask}} & t > 0 \\ c_{\max} & t = 0 \end{cases}
$$

该公式的物理含义是：阈值随已生成 token 的平均置信度自然上升，早期低阈值仅允许最确定的 token 去掩码，后期高阈值允许更激进的并行生成。候选集 $D_t = \{i \in M_{t-1} \mid c_i \geq \tau_t\}$ 中的 token 被临时去掩码。这一设计解决了静态策略在难度变化场景下的次优性，使采样轨迹从谨慎逐步过渡到激进，最大化速度而不提前承诺低置信度 token。

### 回溯增强重掩码

自适应加速引入的激进并行会放大早期错误，因为 DLM 中已生成 token 的上下文会随新 token 填充而演化，导致原本高置信度的预测可能变为错误。Saber 引入回溯机制，每步根据当前去掩码规模确定回溯数量 $\mu_t = \max(1, \lfloor |D_t| / \mu \rfloor)$，其中 $\mu$ 为超参数。对新上下文下的已去掩码 token $j \in U_{t-1}$，计算置信度下降量 $\Delta_j = c_j^{t-1} - c_j^t$，选择下降量最大的 $\mu_t$ 个 token 重新掩码。最终去掩码集合更新为 $U_t = (U_{t-1} \cup D_t) \setminus R_t$。该机制打破了传统 DLM 采样的不可逆性，通过撤销因新上下文暴露的错误预测，阻止错误级联传播，使激进并行成为可能。

## 实验评估

实验在 HumanEval、MBPP、HumanEval-ET、MBPP-ET 和 LiveCodeBench 上进行，基线覆盖标准 DLM 采样（Random、Entropy、Confidence）和高效采样方法（Fast-dLLM、SAR、ReMDM、WINO）。Saber 在所有基准上取得最高 Pass@1 和最短推理时间。

| 方法 | HumanEval Pass@1 | HumanEval Time | MBPP Pass@1 | MBPP Time |
| --- | --- | --- | --- | --- |
| Confidence (p=1) | 43.29 | 2:11:52 | 42.86 | 3:12:08 |
| WINO | 40.24 | 100.12 | 43.09 | 88.49 |
| Saber | 45.12 | 41:55 | 44.73 | 1:33:33 |

Saber 在 HumanEval 上 Pass@1 较 Confidence (p=1) 提升 1.83%，推理时间从 2:11:52 降至 41:55；较 WINO 提升 4.88% 且时间缩短 58.2%。

消融实验验证了两个组件的独立贡献与协同效应。

| 变体 | Pass@1 | Steps | Time |
| --- | --- | --- | --- |
| Saber | 0.4512 | 118.92 | 41:55 |
| w/o Adaptive Accelerate | 0.4451 | 256 | 1:32:33 |
| w/o Backtracking Remask | 0.3523 | 65.67 | 28:30 |
| w/o both | 0.3476 | 256 | 51:13 |

移除自适应加速后，步数恢复至 256，时间增至 1:32:33，证明其是速度提升的主要来源。移除回溯机制后，步数降至 65.67，时间缩短至 28:30，但 Pass@1 从 45.12% 骤降至 35.23%，降幅达 9.89%，表明激进并行缺乏纠错机制时错误传播导致质量崩塌。将动态阈值替换为初始生成 token 的平均置信度，Pass@1 降至 42.07%，验证了自适应调整的必要性。

评估边界方面，论文未报告置信区间，1.9% 的 Pass@1 提升统计显著性未知。超参数 $\mu$ 的敏感性分析缺失，仅说明其为限制回溯比例的小数。代码未公开，可复现性受限。理论分析依赖“置信度作为准确性的代理”假设，校准松弛 $\delta_{\text{calib}}$ 的取值未经验证。

## 关联研究分析

从问题动机看，Saber 与 ReMDM 均针对 DLM 采样的错误传播问题，但 ReMDM 的重掩码仅在固定阶段执行，无法响应置信度的实时波动。Saber 将重掩码决策与当前去掩码规模 $\mu_t$ 和置信度下降量 $\Delta_j$ 绑定，实现了全动态回溯。这一差异源于任务特性：代码生成的结构约束使早期错误具有级联放大效应，固定阶段的重掩码无法覆盖错误暴露的随机时间点，而动态回溯能在新上下文暴露错误时立即修正。

从方法设计看，Saber 与 WINO 等静态并行方法在加速机制上存在根本分歧。WINO 通过最小化解码步数实现速度提升，但牺牲了质量；Saber 通过自适应阈值在保持速度的同时提升质量。这一差异的根源在于对生成难度动态性的建模：WINO 假设难度均匀，Saber 通过历史置信度均值跟踪难度演化。然而，Saber 的动态阈值依赖已去掩码 token 的置信度历史，若模型置信度校准偏差较大，阈值可能系统性偏离真实难度，论文未对此进行鲁棒性分析。

## 总结

Saber 针对 DLM 代码生成中并行解码速度与质量不可兼得的矛盾，抓住了生成难度非均匀性和已生成 token 置信度动态演化这两个被静态策略忽略的特性。通过基于历史置信度均值的动态阈值自适应调整去掩码规模，并引入基于置信度下降量的回溯重掩码机制，Saber 在无需训练的前提下同时提升了速度与质量。在 HumanEval 上，Saber 实现 45.12% 的 Pass@1 和 41:55 的推理时间，较基线 Confidence (p=1) 提升 1.83% 且时间缩短 81.2%。其边界在于理论误差界依赖置信度校准假设，且未报告统计显著性。当模型置信度校准偏差较大时，动态阈值是否仍能准确跟踪生成难度，论文未给出回答。
