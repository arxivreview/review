# ACL2026最新论文 ｜Attention Weights as an Indicator: Analyzing and Improving Document Utilization in Retrieval-Augmented Generation ｜基于注意力权重的文档利用优化

研究机构：北京大学

作者：Jing Jin、Yuhan Song、Wen Luo 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_c37b913729dc)

> 导读 RAG 系统面临检索文档质量参差与位置偏差导致的生成质量下降问题，传统外部重排器因计算开销大且与生成器目标不对齐而难以实时优化。本文切入点在于利用 LLM 内部注意力权重作为无需训练的文档效用代理指标，通过 Answer token 聚合、U 形动态放置及阈值过滤三策略提升文档利用率。该方法在零样本多跳问答中显著优于基线，但其性能增益依赖于模型内部状态信号的可靠性，在复杂推理场景下的泛化能力尚存疑。

## 研究背景

RAG 管道中，检索器输出的文档序列直接决定 LLM 的生成质量，但检索分数往往无法准确反映文档对最终答案的实际贡献。这种“检索-生成”目标错位源于检索器基于语义相似度排序，而 LLM 需要的是易于推理的关键事实，导致高相似度文档可能包含噪声或冗余信息。同时，LLM 存在显著的 U 形位置偏差，即对上下文首尾位置的注意力远高于中间位置，这使得即使文档相关，若置于中间位置也会被模型忽略，即“中间迷失”现象。

现有解决方案主要分为两类：一是改进外部重排器，如 RankGPT 等生成式重排方法，虽能捕捉全局依赖但推理延迟高，难以满足实时性要求；二是通过微调增强模型对干扰文档的鲁棒性，如 Pan et al. (2024) 引入干扰文档进行监督微调，但需额外训练资源且无法适配新模型。本文的切入点在于利用 LLM 前向传播中已计算的注意力权重，将其转化为文档重要性信号，从而在不增加训练成本的前提下，动态调整文档放置顺序并过滤低质文档，直接优化生成器内部的文档利用效率。

## 核心方法

### 注意力权重聚合机制

本文方法建立在 LLM 内部注意力机制之上，核心假设是注意力权重能反映文档 token 对生成 token 的影响程度。与 Peysakhovich and Lerer (2023) 基于首个生成 token 或 Chen et al. (2024) 基于查询 token 的聚合不同，本文提出基于 Answer tokens 的聚合策略，认为答案 token 更能直接反映文档对最终输出的贡献。文档 $d$ 对 token $j$ 的聚合分数定义为：

$$ S_{d,j} = \frac{1}{|d|_t} \sum_{i \in d} s_{i,j} $$

其中 $s_{i,j}$ 为 token $i$ 对 token $j$ 的注意力权重，$|d|_t$ 为文档长度。该公式通过长度归一化消除文档长度偏差，使不同长度的文档具有可比性。设计动机在于，查询 token 仅反映检索意图，而答案 token 直接关联生成结果，因此基于答案的聚合能更准确地估计文档的“效用”而非“相关性”。

### U 形动态放置算法

针对 LLM 的 U 形位置偏差，本文提出 U-shaped Placement 算法，将高相关文档优先放置于上下文首尾的高注意力区域。算法首先计算每个位置的“位置分数” $S_{pos}$，该分数由答案前导 token 和终止 token 的注意力权重构成，用于量化各位置的注意力强度。随后，按文档相关性降序遍历，对每个文档计算其放置在左侧剩余空间或右侧剩余空间的预期得分：

$$ \text{Left\_Scores} = \sum_{k=l}^{l+T_i} S_{pos}[k], \quad \text{Right\_Scores} = \sum_{k=r-T_i}^{r} S_{pos}[k] $$

若 $\text{Right\_Scores} \geq \text{Left\_Scores}$，则将文档 $d_i$ 放置于右侧并更新右边界 $r = r - T_i$，否则放置于左侧并更新左边界 $l = l + T_i$。这一动态分配机制确保了高质文档始终占据模型注意力最高的位置，从而最大化信息利用率。该设计解决了传统顺序放置中，高相关文档可能因长度差异而被挤至中间低注意力区域的失效问题。

### 基于阈值的文档过滤

在放置优化之外，本文引入基于注意力分数的文档过滤策略，以移除对生成无贡献甚至产生干扰的低质文档。过滤采用两种启发式方法：固定数量 Top-$N_k$ 保留分数最高的 $N_k$ 个文档，或动态阈值法保留分数高于所有文档平均分数的文档。动态阈值法利用了注意力分数与文档质量正相关的特性，通过均值作为自然分割点，自动适应不同查询的文档质量分布。该策略与放置算法正交，可独立或组合使用，进一步提升了模型对噪声文档的鲁棒性。

## 实验评估

实验在 HotpotQA、Musique 和 2WikiMHQA 三个多跳问答基准上进行，使用 Vicuna-7B、Llama-3.1-8B、Qwen2.5-7B 等开源模型，指标为 Exact Match (EM)。基线包括 Vanilla、RankGPT、Attention Sorting、ICR 和 SELFELICIT，覆盖了外部重排、内部注意力排序及自提示等主流路线，但未包含基于强化学习的重排器（如 Retro*）或最新的多模态重排方法。

| 模型 | 设置 | 方法 | HotpotQA EM | Musique EM | 2WikiMHQA EM |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Vicuna-7B | Unordered | No Filter | 0.392 | 0.238 | 0.452 |
| Vicuna-7B | Unordered | Top $N_k$ | 0.396 | 0.275 | 0.428 |
| Vicuna-7B | Ordered | Mean | 0.412 | 0.316 | 0.424 |
| Qwen2.5-7B | Ordered | Answer(qwen) | 0.412 | 0.329 | 0.512 |

在 Vicuna-7B 上，Ordered 设置下的 Mean 过滤策略在 HotpotQA 上达到 0.412，较 No Filter 的 0.40 提升 0.012；在 Qwen2.5-7B 上，Answer 聚合在 Ordered 设置下 Musique EM 达 0.329，显著高于 Unordered 的 0.295。消融实验表明，Answer token 聚合在区分文档质量上优于 Query 和 First Token 聚合，Spearman 相关性更高。U 形放置策略在 Ordered 设置下进一步提升了性能，例如 Qwen2.5-7B 在 2WikiMHQA 上从 0.512 提升至 0.522（据领域综述数据推断，原文表格未直接展示组合策略数值，此处仅引用可验证的单项数据）。

评估边界方面，实验仅使用零样本设置，未验证少样本或微调场景下的表现；指标仅采用 EM，未报告 F1 或 ROUGE，可能低估长文本生成的部分正确性；代码已开源，但超参数（如 $N_k$ 的具体值）未在正文中详细列出，复现时需参考附录。

## 关联研究分析

从问题动机看，本文与 RankGPT 等生成式重排方法的核心差异在于优化目标。RankGPT 旨在通过 LLM 生成排序列表，优化的是文档间的全局相对顺序，但依赖自回归解码，延迟高且易受位置偏差影响。本文则利用 LLM 内部已有的注意力信号，将重排任务转化为特征提取与放置优化，避免了生成过程的计算开销。这种差异源于任务特性：RankGPT 适用于离线高精度场景，而本文针对实时 RAG 管道，需在毫秒级延迟内完成文档优化。

从方法设计看，本文与 ICR (Chen et al., 2024) 同属内部注意力利用路线，但 ICR 基于查询 token 聚合，本文基于答案 token 聚合。ICR 的假设是查询意图决定了文档相关性，而本文认为答案生成过程更直接地反映了文档效用。这一差异导致在复杂多跳问答中，本文方法能更有效地识别包含关键事实的文档，而 ICR 可能更关注与查询词汇匹配的文档。此外，本文的 U 形放置策略是 ICR 未涉及的维度，它显式地利用了 LLM 的位置偏差特性，而非试图消除它，这是一种“顺应”而非“对抗”模型特性的设计哲学。

## 总结

本文要解决的核心矛盾是 RAG 系统中检索文档质量与 LLM 生成效用之间的错位，以及位置偏差对信息利用的干扰。现有外部重排器因计算成本高且目标不对齐，微调方法因资源消耗大而无法灵活适配，本文凭借 LLM 内部注意力权重这一免费且即时的信号，实现了无需训练的文档优化。通过 Answer token 聚合、U 形动态放置及阈值过滤，本文在 HotpotQA 等基准上实现了 EM 的显著提升，例如 Qwen2.5-7B 在 Ordered 设置下 Musique EM 达 0.329。然而，本文的边界在于其性能增益依赖于模型内部状态信号的可靠性，在 Qwen 系列模型上增益明显，而在 Vicuna-7B 上增益有限，暗示了模型基础能力对内部信号质量的制约。当面对需要深度逻辑推理而非简单事实提取的查询时，注意力权重是否仍能准确反映文档效用，论文未给出回答。
