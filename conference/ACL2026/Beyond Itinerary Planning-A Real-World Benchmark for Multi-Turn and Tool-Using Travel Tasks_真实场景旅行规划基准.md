# ACL2026最新论文 ｜Beyond Itinerary Planning-A Real-World Benchmark for Multi-Turn and Tool-Using Travel Tasks ｜真实场景旅行规划基准

研究机构：中国人民大学、新加坡国立大学

作者：Xiang Cheng、Yulan Hu、Xiangwen Zhang 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2512.22673)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2512.22673)

> 旅行规划任务要求智能体在复杂约束下协调多步推理与工具调用，但现有基准多依赖合成数据或单一行程规划，无法评估模型在真实用户交互中的边界识别与隐式偏好提取能力。TravelBench 通过整合真实用户日志、10 个生产级工具及不可解子集，构建了首个支持多轮交互与能力边界评估的旅行规划基准。其核心在于利用缓存沙箱实现可复现的工具调用评估，并引入 LLM-as-a-judge 与工具惩罚机制量化模型可靠性。该基准揭示了前沿模型在复杂交互中的性能失衡，但缓存机制对实时环境适应性的影响尚存疑。

## 研究背景

旅行规划涉及兴趣点（POI）探索、路线规划及行程设计，要求智能体在长程任务中维持状态一致性并协调多重约束。传统 LLM 直接生成计划常因逻辑幻觉导致无效动作，而符号规划器虽能保证逻辑正确性，却缺乏自然语言理解能力。神经符号集成范式试图结合两者，但在开放世界场景中，LLM 需直接调用外部工具获取实时信息，而非依赖静态 PDDL 模型。

现有旅行规划基准如 TravelPlanner 和 ChinaTravel 主要聚焦于行程构建，任务约束相对简单且多为单轮交互，未能覆盖真实用户查询中的噪声、歧义及隐式偏好。这些基准往往预设用户偏好或仅支持短途/长途规划，缺乏对模型“何时该问”和“何时该拒”能力的评估。随着 LLM 代理在工具使用上的进展，评估重点已从单纯的计划可行性转向多轮交互中的动态澄清与边界识别，这要求基准具备真实数据分布、可复现的工具环境及细粒度的评分协议。

## 核心方法

### 方法参照系

本文问题属于具身智能中的工具增强规划，与经典神经符号集成不同，其核心差异在于不依赖形式化验证器，而是通过真实工具 API 的调用轨迹评估 LLM 的语义理解与执行可靠性。标准流程通常包含任务分解、工具选择及结果整合，但本文额外引入了不可解任务识别与多轮偏好提取机制。

### 沙箱环境与缓存机制

为解决工具调用不可复现的问题，本文构建了离线沙箱环境。设计动机是消除在线 API 的随机性对评估结果的干扰，确保不同模型在相同工具响应下可比。沙箱预存约 200,000 条真实工具调用响应，当模型发起调用时，系统优先从缓存中检索匹配结果。对于缓存未命中的情况，采用基于嵌入的检索增强生成策略：利用 Qwen3-Embedding-8B 计算工具参数嵌入，通过 Faiss 检索最相似的 8 条缓存记录，并作为上下文示例引导 LLM 生成模拟响应。该机制的评分公式定义为：

$$ S_{tool} = \frac{N_{err}}{N_{all}} $$

其中 $N_{err}$ 为违反工具规范（如参数类型错误、缺失必填项）的调用次数，$N_{all}$ 为总调用次数。该比率直接反映模型在工具使用上的可靠性，而非仅关注最终答案的正确性。

### 多维评估协议

针对多轮交互的复杂性，本文采用 LLM-as-a-judge 协议，结合规则评分与惩罚项。设计动机是传统规则验证无法捕捉交互质量与幻觉问题。对于单轮任务，评估维度包括推理规划、摘要提取与呈现；多轮任务额外增加用户交互维度。每个维度 $i$ 的原始得分 $r_{t,j,i} \in \{1, 2, 3, 4, 5\}$ 经归一化后，引入元裁判校准因子 $w_{meta}$ 与工具惩罚因子 $w_{tool}$。最终实例得分计算为：

$$ S_{t,j}^{pen} = S_{t,j} \cdot w_{t,j}^{meta} \cdot w_{t,j}^{tool} $$

其中 $w_{t,j}^{meta}$ 用于校正原始裁判可能的高估（如遗漏幻觉），$w_{t,j}^{tool}$ 基于上述工具错误率施加惩罚。该公式将交互质量与执行可靠性解耦，使评分更贴近实际部署场景中的用户体验。

## 实验评估

实验在 TravelBench 的三个子集（500 单轮、500 多轮、100 不可解）上进行，对比了 GPT-5.1、Qwen-Plus、DeepSeek-V3.2 等前沿模型及 Qwen3 系列开源模型。基线覆盖专有与开源模型，但未包含符号规划器基线，符合本文聚焦 LLM 代理能力的定位。

| 模型 | 多轮 (Pen.) | 单轮 (Pen.) | 不可解 (Acc.) | 总分 |
| :--- | :--- | :--- | :--- | :--- |
| Qwen-Plus | 65.58 | 70.87 | 80.00 | 76.29 |
| DeepSeek-V3.2 | 82.80 | 83.29 | 51.33 | 72.47 |
| Kimi-K2-0925 | 49.99 | 61.62 | 94.00 | 68.54 |
| GPT-5.1 | 71.31 | 73.81 | 80.00 | 75.04 |

数据显示，Qwen-Plus 以 76.29 的总分领先，但 DeepSeek-V3.2 在可解任务上表现最佳（约 83 分），却在不可解任务上仅得 51.33 分，暴露出模型在“能力边界识别”与“任务执行”上的能力失衡。Kimi-K2-0925 在不可解任务上高达 94 分，但在多轮交互中仅 49.99 分，进一步证实这两项能力并非正相关。

消融实验显示，工具惩罚机制显著影响了最终得分。以 MiniMax-M2 为例，多轮任务原始分为 78.44，应用惩罚后降至 66.79，表明模型虽能部分恢复错误，但工具调用错误率（15.37%）严重损害了实用性。稳定性测试表明，三次独立运行的标准差在 0.19-0.81 之间，离线沙箱与在线工具调用的得分差异仅为 0.11-0.31，验证了缓存机制的有效性。

评估边界方面，LLM-as-a-judge 与人工标注的平均绝对误差（MAE）为 0.52，接近人工间差异（0.48），表明评分可靠性较高。然而，缓存命中率约 90%，可能使模型倾向于“记忆”常见查询而非实时推理。代码已开源，但超参数细节（如嵌入维度 4,096）固定，限制了跨模型架构的泛化分析。

## 关联研究分析

从问题动机看，TravelBench 与 ChinaTravel 均强调真实约束，但 ChinaTravel 依赖 DSL 形式化验证，而本文通过工具调用惩罚直接量化执行可靠性。这一差异源于任务特性：ChinaTravel 聚焦静态行程优化，而本文关注动态交互中的实时反馈。本文未采用符号验证器，是因为真实工具 API 的响应本身即为“事实源”，无需额外逻辑推导，但这也意味着无法评估模型在工具不可用时的逻辑推理能力。

从方法设计看，本文与 Planner-R1 同属旅行规划领域，但 Planner-R1 通过强化学习优化小模型性能，而本文仅评估现有模型。本文引入的“不可解”子集是 Planner-R1 等 RL 方法未覆盖的维度，因为 RL 通常假设任务可解。这种设计差异揭示了当前 LLM 代理研究的盲区：模型在无法完成任务时的行为（如承认失败、请求澄清）比成功完成任务时的优化更关键，但缺乏系统评估。

## 总结

TravelBench 旨在解决现有旅行规划基准无法评估 LLM 在真实多轮交互中边界识别与隐式偏好提取能力的问题。其切入点在于利用真实用户日志与缓存沙箱，将评估从静态计划可行性扩展至动态交互可靠性。通过引入工具惩罚与多维 LLM 裁判，该基准量化了模型在工具使用上的错误率，揭示了前沿模型在“可解任务执行”与“不可解任务识别”上的能力失衡。实验显示 Qwen-Plus 总分最高（76.29），但 DeepSeek-V3.2 在不可解任务上仅得 51.33 分，表明当前模型缺乏统一的边界感知机制。本文的边界在于缓存机制可能掩盖模型对实时环境变化的适应能力，且未探索通过强化学习优化边界识别的可能性。当缓存命中率降至 50% 以下时，模型的工具调用错误率是否会显著上升，从而验证其实时推理能力，论文未给出回答。
