# ACL2026最新论文 ｜GIFT: Guided Fine-Tuning and Transfer for Enhancing Instruction-Tuned Language Models ｜引导式微调与迁移

研究机构：南方科技大学、阿里巴巴集团

作者：Zhiwen Ruan、Yichao Du、Jianjie Zheng 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.01256)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_c4ac4a5cf8a4)

> 指令微调模型在适配特定领域任务时，直接微调常破坏其原有的通用推理与指令遵循平衡，导致性能崩溃。现有参数合并方法将指令模型视为被动接收者，忽略了其内部对齐信号对任务学习方向的潜在引导作用。GIFT 框架通过在基座模型上训练适配器时，引入指令模型的 Token 级置信度作为损失加权信号，使学习过程聚焦于指令一致的关键知识，最终将适配器合并回指令模型。该方法在数学推理上实现了显著增益，但在通用指令遵循能力上仅维持持平，其引导机制对非推理类任务的普适性存疑。

## 研究背景

当指令微调模型（如 Llama3.1-Instruct）被直接用于数学或医疗问答微调时，其参数空间中的通用推理能力与指令遵循行为往往发生冲突，导致模型在特定任务上提升的同时，通用能力显著退化。这种退化源于直接微调迫使模型拟合所有 Token，包括那些风格化或可替换的低价值 Token，从而引入了与指令对齐目标相悖的噪声更新。为规避此问题，研究者提出在预训练基座模型上学习任务适配器，再将其合并至指令模型，利用两者参数空间的邻近性实现能力迁移。

然而，主流迁移方法如 Shadow-FT 和 Chat Vector 仅将指令模型作为最终的合并目标，训练过程仍采用标准监督微调（SFT）损失，未利用指令模型已具备的对齐知识来指导基座模型的学习方向。这导致基座模型学到的适配器可能包含大量与指令模型表示空间不兼容的更新，合并后引发性能波动甚至下降。GIFT 的切入点在于，指令模型对训练数据中每个 Token 的预测置信度，实际上反映了该 Token 对任务核心知识的贡献程度，这一信号可被用于重塑基座模型的优化目标。

## 核心方法

### 参数合并参照系

GIFT 建立在模型算术（Model Arithmetic）的线性假设之上，即指令模型参数 $\theta_I$ 可表示为基座模型参数 $\theta_B$ 与指令偏移量 $\Delta_I$ 之和：$\theta_I = \theta_B + \Delta_I$。在此框架下，任务适配通过训练低秩适配器 $\phi$ 实现，其合并操作定义为 $\theta'_I = \theta_I + M(\phi)$，其中 $M(\cdot)$ 为 LoRA 合并算子。该参照系的关键局限在于，适配器 $\phi$ 的训练目标未考虑指令模型的内部状态，导致合并后的参数更新可能与 $\Delta_I$ 产生干扰。

### 置信度引导的损失重塑

GIFT 的核心创新在于将指令模型的 Token 级置信度转化为基座模型适配器的损失权重。对于训练样本 $(x, y)$，首先通过指令模型执行一次前向传播，计算每个目标 Token $y_t$ 的条件概率 $q_t = p_{\theta_I}(y_t | x, y_{<t})$。该置信度序列 $q = [q_1, \dots, q_T]$ 被离线预计算并存储，作为后续训练的重要性信号。

$$
L_{GIFT}(\phi) = \mathbb{E}_{(x,y)\sim\mathcal{D}} \left[ \sum_{t=1}^{T} q_t \cdot \ell_t(\phi) \right], \quad \ell_t(\phi) = -\log p_{\theta_B,\phi}(y_t | x, y_{<t})
$$

此公式的物理含义是：指令模型对某 Token 的预测置信度越高，该 Token 在基座模型适配器训练中的梯度贡献越大；反之，低置信度 Token 的梯度被抑制。这一设计解决了标准 SFT 中“所有 Token 同等重要”的假设失效问题，将优化信号从模糊的风格化区域重新分配至指令一致的任务关键区域，从而确保学到的适配器 $\phi$ 在合并后能与指令模型的表示空间保持兼容。

### 离线标注与合并流程

GIFT 将训练过程分为两个阶段：离线标注与引导式微调。在离线标注阶段，指令模型对固定数据集进行一次前向传播，生成每个样本的置信度序列 $q$，形成增强训练元组 $(x, y, q)$。在引导式微调阶段，基座模型使用 $L_{GIFT}$ 损失训练 LoRA 适配器，训练完成后，适配器 $\phi^*$ 被直接合并至指令模型，得到任务增强模型 $\theta'_I$。该流程避免了知识蒸馏中的分布匹配计算，仅利用标量置信度重加权交叉熵损失，保持了 SFT 的计算效率，同时注入了指令对齐的引导信息。

## 实验评估

GIFT 在数学推理与医疗问答两个领域进行评估，基线包括直接微调（Instruct-SFT）、Shadow-FT、Re-Adapt 及 LoRE-Adapt。实验覆盖 Llama3.1-8B、Llama3.2-3B、Qwen2.5-7B 及 DeepSeek-Math-7B 四个模型家族，数学任务使用 NuminaMath-CoT 2,000 样本微调，医疗任务使用 MedMCQA 10,000 样本微调。

| 模型 | 基线 (Avg) | Shadow-FT (Avg) | GIFT (Avg) |
| :--- | :--- | :--- | :--- |
| Llama3.1-8B-Instruct | 16.8 | 18.0 | 22.0 |
| Llama3.2-3B-Instruct | 16.5 | 16.7 | 19.5 |
| Qwen2.5-7B-Instruct | 41.3 | 38.0 | 42.9 |
| DeepSeek-Math-7B-Instruct | 16.8 | 17.4 | 19.7 |

GIFT 在所有模型上均超越基线与 Shadow-FT，其中 Llama3.1-8B 平均准确率提升 5.2 分，Qwen2.5-7B 提升 1.6 分。消融实验显示，使用基座模型自身置信度（GIFT-BaseT）仅恢复至基线水平（41.0 vs 41.3），而使用指令模型置信度（GIFT）则带来 +1.6 的平均增益，证明指令对齐信号是性能提升的关键。

| 变体 | Math-500 | Minerva Math | Olympiad Bench | AIME24 | AMC23 | Average |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Instruct Model | 73.2 | 38.2 | 35.4 | 11.2 | 48.6 | 41.3 |
| SFT+Merge | 70.6 | 36.6 | 31.3 | 7.9 | 43.4 | 38.0 |
| GIFT-BaseT | 73.5 | 37.3 | 34.6 | 12.1 | 47.7 | 41.0 |
| GIFT (ours) | 75.0 | 38.4 | 36.1 | 12.7 | 52.5 | 42.9 |

SFT+Merge 导致平均 3.3 分的性能下降，证实了无引导合并的不稳定性。GIFT 在 MMLU 和 IFEval 上保持或微增（Llama3.1-8B IFEval 从 73.8 升至 74.7），表明其未损害通用能力。评估边界方面，数学任务采用 Pass@16 随机解码，医疗任务采用多选准确率，未覆盖多轮对话或复杂逻辑指令场景。代码已开源，LoRA 超参数（rank=64, alpha=128）固定，离线标注成本约为 2 分钟/2000 样本（RTX 4090）。

## 关联研究分析

从问题动机看，GIFT 与 TRIM 均利用模型内部信号指导训练，但 TRIM 基于注意力显著性进行数据筛选，旨在降低计算成本，而 GIFT 基于指令模型置信度进行损失加权，旨在解决参数合并的兼容性问题。TRIM 的信号来源是基座模型自身的注意力分布，反映样本对当前模型的难度；GIFT 的信号来源是指令模型的对齐置信度，反映 Token 对任务核心知识的贡献。这一差异源于任务目标的不同：数据筛选关注“哪些样本值得训练”，而引导式微调关注“哪些 Token 值得拟合”。

从方法设计看，GIFT 与 DPO 在“利用模型自身信号”上有异曲同工之妙，但 DPO 通过偏好对优化策略分布，GIFT 通过置信度重加权监督损失。DPO 需要成对的偏好数据，计算开销较大；GIFT 仅需单次前向传播获取置信度，计算效率更高。然而，DPO 直接优化指令遵循行为，而 GIFT 仅间接影响指令兼容性。GIFT 在 IFEval 上仅微增（+0.9 分），表明置信度引导对格式约束类指令的增强作用有限，这可能因为格式约束更多依赖显式规则而非 Token 级语义置信度。

## 总结

GIFT 旨在解决指令微调模型在任务适配中通用能力退化的矛盾，其切入点在于利用指令模型的 Token 级置信度作为基座模型适配器的损失权重，从而在训练阶段就确保更新方向与指令表示空间兼容。该方法在 Llama3.1-8B 数学推理上实现 +5.2 分的平均增益，同时在 MMLU 和 IFEval 上保持性能稳定。然而，其实验仅覆盖数学与医疗问答，未验证在代码生成或多轮对话等复杂逻辑任务中的有效性。当任务涉及多约束逻辑结构时，Token 级置信度是否仍能准确区分关键知识，论文未给出回答。
