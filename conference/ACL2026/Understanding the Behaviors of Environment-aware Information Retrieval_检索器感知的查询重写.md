# ACL2026最新论文 ｜Understanding the Behaviors of Environment-aware Information Retrieval ｜检索器感知的查询重写

研究机构：复旦大学、阿里巴巴集团

作者：Ruifeng Yuan、Chaohao Yuan、David Dai 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_8358d7d12cbd)

> 智能体搜索（Agentic Search）在处理复杂查询时，通常将检索视为统一的工具调用，忽略了不同检索后端对查询形式的差异化需求。现有强化学习（RL）框架多关注多跳推理路径的信用分配，却未解决单步检索中查询策略与检索器架构的静态不匹配问题。本文通过 Group Relative Policy Optimization (GRPO) 训练 LLM 生成适配特定检索器的查询，并引入分支 Rollout 稳定多轮训练。该研究填补了查询形式适配的研究空白，但其结论局限于检索质量指标，未验证端到端答案准确率的转化效率。

## 研究背景

当 LLM 面对本地私有知识库（如金融报告）时，直接生成的自然语言查询往往无法匹配检索器的内部表征偏好。这种不匹配源于检索器的架构特性：稀疏检索器（如 BM25）依赖关键词匹配，而稠密检索器（如 Contriever）基于语义向量相似度。若 LLM 无法根据目标检索器调整查询的“方言”（如关键词密度 vs. 陈述句结构），检索召回率将显著下降。这一现象被称为检索器感知的查询形式适配问题，其核心在于 LLM 需习得在不同检索环境间进行“代码切换”的能力。

智能体搜索的主流路线通过 RL 优化长程推理策略，如 Search-R1 利用可验证奖励解决多跳问答中的信用分配难题。然而，这些方法假设检索器是固定的黑盒，仅优化查询内容而非查询形式。当任务从通用搜索引擎转向本地异构检索器时，静态的查询生成策略暴露出严重的适应性缺陷：为 Contriever 优化的长描述性查询在 BM25 上表现不佳，反之亦然。现有研究缺乏对 LLM 如何通过 RL 习得这种检索器特定查询策略的系统分析，导致在混合检索后端场景下性能受限。

## 核心方法

### 方法参照系

本文问题属于检索器协同优化路线，但区别于 CoSearch 等联合优化检索器参数的工作，本文仅优化 LLM 侧的查询生成策略，保持检索器为黑盒。关键差异在于：本文将检索器视为 RL 环境，通过奖励信号引导 LLM 学习适配特定检索器的查询形式，而非修改检索器本身的表征空间。

### 基于 GRPO 的查询重写策略

传统 RL 方法如 PPO 需要价值函数评估器，导致训练不稳定且计算开销大。本文采用 Group Relative Policy Optimization (GRPO)，通过组内相对优势计算消除对独立评估器的依赖。对于单轮检索，策略 $\pi_\theta$ 生成查询 $q$，奖励 $r(q, D)$ 定义为检索文档 $D$ 相对于真值 $d^*$ 的 nDCG@10。GRPO 目标函数为：

$$ L_{GRPO}(\theta) = -\frac{1}{|y_i|} \sum_{i=1}^{G} \sum_{t=1}^{|y_i|} \min \left( \rho_{i,t} A_i, \text{clip}(\rho_{i,t}, 1-\epsilon, 1+\epsilon) A_i \right) - \beta D_{KL}(\pi_\theta || \pi_{ref}) $$

其中优势 $A_i$ 通过组内奖励归一化计算：$A_i = \frac{r_i - \mu_{group}}{\sigma_{group} + \delta}$。该设计使 LLM 能直接根据检索质量反馈调整查询形式，无需额外评估器，显著提升了训练稳定性。

### 分支 Rollout 与加权奖励聚合

多轮检索中，中间步骤奖励方差大导致训练崩溃。本文引入分支 Rollout 策略，将线性轨迹（如 16×1）改为分支结构（如 4×4），即采样 $M$ 个首轮动作，每个分支 $N$ 个二轮完成。首轮动作的价值通过分支平均估计：

$$ V(q_{i,1}) \approx r(q_{i,1}) + \frac{1}{N} \sum_{j=1}^{N} r(q_{i,2}^{(j)}) $$

同时，总轨迹奖励 $R_i$ 采用加权聚合：$R_i = \sum_{k=1}^{K} \lambda_k \cdot r(q_{i,k}, e_{i,k})$，其中后期轮次权重更高（如 $\lambda_1=0.5, \lambda_2=1$）。该机制隔离了二轮学习的信号，确保优势计算反映二轮重写质量，而非受首轮质量干扰，解决了多轮 RL 中的信用分配难题。

## 实验评估

实验在 RAGBench（通用）、BEIR（OOD）和 FinAgentBench（金融）上进行，基线覆盖 BM25、Contriever、all-MiniLM-L6-v2 和 Qwen3-Embedding-0.6B。缺失强基线如 Search-R1 等端到端智能体框架，仅对比检索器原生性能与简单提示重写。

| 检索器 | RAGBench Avg. nDCG@10 | BEIR Avg. nDCG@10 |
| :--- | :--- | :--- |
| Contriever | 45.5 | 28.84 |
| Contriever + rewrite (direct) | 56.3 | 34.98 |
| BM25 | 45.0 | - |
| BM25 + rewrite (explore) | 56.9 | - |
| Qwen3-Embedding-0.6B | 61.5 | - |
| Qwen3-Embedding-0.6B + rewrite (general) | 64.1 | - |

Contriever 在 RAGBench 上从 45.5 提升至 56.3，BEIR 上从 28.84 提升至 34.98，表明 RL 习得的查询策略在分布内和分布外均有效。BM25 的“explore”策略提升幅度（45.0→56.9）大于“direct”策略（45.0→56.2），暗示探索性提示对稀疏检索器更有效。

消融实验显示，14B 模型在 Contriever 环境下突破了“本地策略茧房”，性能超越 4B 模型，且发现了人类专家未预期的查询形式（如将问题重写为文档风格）。多轮训练中，加权奖励聚合相比均匀权重提升了二轮检索质量，验证了后期轮次权重更高的设计合理性。

评估仅关注 nDCG@10，未报告端到端答案准确率，无法确认检索提升是否线性转化为最终答案质量。代码已开源，但超参数细节（如 GRPO 步数、分支数量）未在正文中完整披露，可复现性依赖附录。

## 关联研究分析

从问题动机看，本文与 CoSearch 均关注检索器与智能体的协同，但 CoSearch 通过联合优化检索器参数解决静态不匹配，而本文仅优化查询生成策略。这种差异源于任务特性：CoSearch 假设检索器可训练，适用于大规模通用场景；本文针对本地私有知识库，检索器不可修改，故聚焦查询侧适配。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但其在金融领域的迁移成功暗示了策略的鲁棒性。

从方法设计看，本文与 Search-R1 同用 RL 优化搜索策略，但 Search-R1 关注多跳推理路径的信用分配，奖励信号为最终答案正确性；本文关注单步查询形式，奖励信号为 nDCG@10。这种差异导致本文方法在长程任务中可能失效，因为 nDCG 无法捕捉多步推理中的中间证据依赖。分支 Rollout 虽解决了多轮方差问题，但仅适用于两轮设置，更长轨迹的信用分配机制未探索。

## 总结

本文要解决的核心矛盾是 LLM 查询形式与本地检索器架构的静态不匹配。现有方法忽略查询形式的差异化需求，本文通过 GRPO 和分支 Rollout 使 LLM 习得检索器特定的查询“方言”。实验证明 Contriever 在 RAGBench 上 nDCG@10 从 45.5 提升至 56.3，BEIR 上从 28.84 提升至 34.98。本文的边界在于仅评估检索质量，未验证端到端答案准确率，且分支 Rollout 局限于两轮设置。当检索轨迹扩展到五轮以上时，分支结构的计算开销与信用分配精度如何平衡，论文未给出回答。
