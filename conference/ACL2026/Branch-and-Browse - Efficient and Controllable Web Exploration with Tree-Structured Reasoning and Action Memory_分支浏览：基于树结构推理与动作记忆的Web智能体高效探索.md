# ACL2026最新论文 ｜Branch-and-Browse: Efficient and Controllable Web Exploration with Tree-Structured Reasoning and Action Memory ｜分支浏览：基于树结构推理与动作记忆的Web智能体高效探索

研究机构：美国密歇根大学、阿里巴巴集团

作者：Shiqi He、Yue Cui、Xinyu Ma 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.19838)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.19838)

> 长程Web任务中，线性推理轨迹一旦早期步骤出错便导致级联失败，而传统树搜索因分支独立探索产生大量冗余计算。本文切入点在于将树结构探索与页面级共享记忆结合，通过子任务管理器、最近URL状态回放及背景推理机制，在保持多分支回溯能力的同时显著降低执行开销。该方法在WebArena基准上实现了35.8%的任务成功率，并将平均执行时间减少40.4%，但在绝对成功率上仍低于部分策略型基线，其效率-成功率权衡的边界尚待更严苛的动态环境验证。

## 研究背景

当智能体在电商网站执行“查找所有50美元以下的鞋子并加入心愿单”这类多步任务时，若在第3步错误点击了“品牌”而非“价格”筛选器，线性ReAct框架（Yao et al., 2023）无法回溯修正，只能从头重启整个序列。这种缺乏错误恢复机制的线性轨迹，在步骤数增加后性能急剧下降，暴露了长程任务中推理漂移与执行错误的耦合问题。为解决此困境，树搜索方法（Koh et al., 2024b）通过扩展多个状态分支提升任务完成率，但其各分支独立探索，未有效利用已访问页面或失败交互模式等共享上下文，导致冗余探索与高计算成本。

现有Web智能体在开放、动态环境中仍远未达到人类可靠性水平，WebArena上主流方法成功率普遍低于50%。ReAct范式虽确立了推理-行动交替的主流架构，但其线性结构在长程任务中的稳定性不足；而Tree Search等搜索策略虽引入多分支探索，却因粒度粗、计算开销大而难以实用化。本文针对这一效率与稳定性的双重瓶颈，提出Branch-and-Browse框架，通过结构化子任务管理、页面级动作记忆及探索加速机制，实现细粒度、可控的多分支推理与高效回溯。

## 核心方法

### 方法参照系

本文问题可置于“基于LLM的序贯决策Web智能体”通用框架下，其标准流程为：观察网页状态→生成推理轨迹→执行动作→接收反馈。本文与标准ReAct流程的关键差异在于：将线性轨迹改造为树结构探索，并引入跨分支共享的页面级记忆，以解决早期错误导致的级联失败与分支冗余探索问题。

### 子任务感知的树结构探索

标准ReAct在单一轨迹上执行，无法在失败时回溯；Tree Search虽支持多分支，但各分支独立计算，未共享上下文。本文在树探索中引入子任务管理器，将全局指令$i$分解为子任务集$\{u_1, \dots, u_K\}$，每个子任务定义目标函数$O(u_k)$与成功谓词$A(u_k)$。探索过程中，智能体维护可扩展节点前沿$F$，选择效用值$v$最高的节点$o$进行扩展，生成分支因子$b$个候选动作$\{a_i\}_{i=1}^b$，每个动作产生后继观察$o_{(i)} = T(o, a_i)$。该设计通过子任务粒度的进度跟踪与动态更新，使智能体能在失败分支回溯时保留已完成子任务的上下文，避免全局重启，解决了线性轨迹中早期错误导致后续全部失效的问题。

### 页面动作记忆与探索加速

Tree Search各分支独立探索，导致相同页面被重复加载与评估。本文引入页面动作记忆模块，以URL为粒度存储结构化记录，包括目标、进度摘要、推理-行动历史、页面快照及动作记忆。每个动作记录维护$\{ActionID, name, ref, result\}$，支持确定性回放与高效回溯。为加速探索，本文设计最近URL状态回放机制：重访早期状态$o_j$时，恢复最近缓存URL $url_c$（$c \le j$）并仅回放剩余动作$(a_c, \dots, a_{j-1})$，而非重放全轨迹。同时，背景推理机制离线评估未探索节点$o \in F$，通过分析其DOM快照$C(o)$推断可行动作，对确定性导航步骤（如点击有效URL）进行预扩展，剪枝无望分支。该机制将探索效率提升40.4%，解决了Tree Search中冗余分支扩展导致的计算浪费问题。

## 实验评估

实验在WebArena基准（812个长程任务，涵盖电商、GitLab、Reddit等5个网站）上进行，基线覆盖ReAct（WebArena、BrowserGym）、策略型（SteP、AgentOccam-Judge）及搜索型（Tree Search）三类方法，但缺失多模态基线。主实验结果显示，Branch-and-Browse在整体成功率上达到35.8%，显著优于Tree Search的19.2%，但在Reddit域提升39.6点，而在Multisite域仅提升2.1点，表明其在多网站长轨迹任务中的优势有限。

| 方法 | 模型 | 整体SR (%) | Shopping | GitLab | Reddit | Multisite |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Tree Search | GPT-4o | 19.2 | 27.8 | 16.5 | 26.6 | 11.3 |
| Branch-and-Browse | GPT-4o | 35.8 | 34.6 | 26.4 | 46.8 | 18.8 |
| AgentOccam-Judge | GPT-4-Turbo | 45.7 | 43.3 | 46.2 | 52.3 | 16.7 |

消融实验聚焦回放与背景推理机制对执行时间的影响。禁用最近URL回放时，平均任务时间略有增加，表明该机制主要避免冗余导航；禁用背景推理时，任务时间显著上升，因其通过离线评估提前剪枝无望分支，对整体效率贡献更大。超参数敏感性分析显示，深度$d=5$、分支因子$b=5$时成功率达35.8%，执行时间12.4分钟，而$d=0$、$b=1$时成功率仅23.9%，执行时间8.2分钟，表明探索深度与成功率的正相关性及边际收益递减趋势。

评估边界方面，论文未报告置信区间，不同方法使用不同骨干网络（GPT-4o vs GPT-4-Turbo），公平性受限；代码未公开，超参数（如探索预算10步）固定，可复现性依赖特定实现细节。

## 关联研究分析

从问题动机看，Branch-and-Browse与WebDART（Yang et al., 2025）同属动态规划路线，但WebDART侧重子任务分解后的重规划，强调分解的灵活性与子任务互补性；本文则聚焦执行阶段的回溯效率，通过页面级记忆共享解决分支冗余。这一差异源于任务特性：WebDART处理高复杂度任务时更关注规划阶段的鲁棒性，而本文在动态Web环境中更关注执行阶段的计算开销。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从方法设计看，Branch-and-Browse与Tree Search（Koh et al., 2024b）同属搜索型策略，但Tree Search各分支独立探索，未利用共享上下文；本文通过页面动作记忆实现跨分支信息传递，将探索效率提升40.4%。这一改进的根源在于Web环境的动态性与部分可观测性，使得已访问页面的状态信息具有高度复用价值，而Tree Search的独立分支假设在此场景下导致大量冗余计算。

## 总结

本文要解决的核心矛盾是长程Web任务中线性轨迹的脆弱性与树搜索的高计算成本。其切入点在于将树结构探索与页面级共享记忆结合，通过子任务管理器实现可控回溯，通过最近URL回放与背景推理降低执行开销。方法上，Branch-and-Browse在WebArena上实现35.8%成功率与40.4%时间减少，证明了结构化探索与记忆共享在效率-稳定性权衡中的有效性。其边界在于：绝对成功率仍低于AgentOccam-Judge等策略型基线，且在Multisite长轨迹任务中优势有限，暴露了其在跨网站复杂导航中的局限。当任务涉及多个网站间的长程依赖时，页面级记忆的跨域迁移能力是否足以支撑高效回溯，论文未给出回答。
