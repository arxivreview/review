> 共指消解在形态丰富语言中面临提及边界与词边界不对齐的根本性挑战，导致标准评估协议失效。现有基准依赖金标准分词，掩盖了真实部署中分词错误与聚类错误的耦合效应。本文通过构建首个希伯来语共指数据集 KibutzR 并提出三级诊断评估协议，量化了分词与聚类对性能的独立贡献。该工作揭示了大语言模型在形态复杂文本中性能反转的现象，但受限于单一语言验证，其结论的跨语言普适性尚存疑。

## 研究背景

当模型处理希伯来语等形态丰富语言时，单个正字法 token 可能包含多个指代成分，如“דבריו”（他的词）需拆解为名词与代词后缀。这种形态堆叠导致提及边界不再对齐词边界，使得依赖词边界假设的共指消解（Coreference Resolution, CR）模型在提及检测阶段即产生系统性错误。提及检测的精度直接决定后续聚类效果，而在形态复杂文本中，分词错误会直接传播至聚类阶段，导致实体轨迹断裂。

主流 CR 研究长期依赖 OntoNotes 等基于英语的基准，其标注规范限制提及必须对齐空格分隔的 token。这一假设在形态丰富语言中失效，迫使研究者采用金标准分词作为预处理步骤，从而在评估中隔离了分词错误。然而，随着大语言模型（LLM）直接处理原始文本的端到端范式兴起，这种“分词前置”的流水线假设与部署现实脱节。现有基准无法区分模型失败源于形态分词困难还是语义聚类错误，导致性能评估缺乏诊断价值。本文切入点在于构建一个允许子词级提及标注的希伯来语基准，并设计能隔离分词与聚类错误的评估协议。

## 核心方法

### 形态感知标注规范

本文基于 OntoNotes 5.0 规范，针对希伯来语形态特征做出两项关键修改。首先，允许在单个正字法 token 内标注子词级提及，以捕捉代词附着与所有格后缀的独立指代功能。其次，将递归构词状态（Construct State）视为嵌套提及层级，允许对复合名词短语的整体及其嵌入成分分别建立共指链接。这一设计解决了标准规范无法标注形态内多重指代的问题，使数据集能真实反映希伯来语中提及边界的复杂性。

### 三级诊断评估协议

为隔离分词与聚类错误，本文提出包含原始文本、自动分词与金标准分词三种输入条件的评估阶梯。对于 LLM，额外增加金标准提及条件以单独评估聚类能力。该协议的核心在于通过控制输入预处理程度，量化不同错误源的贡献。设 $S_{raw}$ 为原始文本输入，$S_{auto}$ 为自动分词输入，$S_{gold}$ 为金标准分词输入，$M_{gold}$ 为金标准提及输入。模型在 $S_{gold}$ 与 $S_{auto}$ 间的性能差 $\Delta_{seg} = F1(S_{gold}) - F1(S_{auto})$ 直接反映分词错误的独立影响；而 $M_{gold}$ 与 $S_{gold}$ 间的差值则揭示聚类阶段的剩余瓶颈。

$$
\Delta_{seg} = F1(S_{gold}) - F1(S_{auto})
$$

该公式通过对比相同文本在不同分词质量下的性能，将分词错误从总误差中解耦，使研究者能明确诊断模型失效的具体环节。

## 实验评估

实验基于 KibutzR 数据集（351 篇文档，20,194 个提及），对比神经编码器（LingMess-He）与 8 个 LLM（GPT-4o, Gemini 2.5-Pro 等）。基线覆盖监督式编码器与生成式 LLM 两条主流路线，但缺失其他形态丰富语言（如土耳其语、巴斯克语）的对比基线，限制了跨语言结论的泛化性。

| 模型 | 金标准分词 F1 | 自动分词 F1 | $\Delta$ F1 |
|---|---|---|---|
| LingMess-He (+DictaBERT) | 50.4 | 47.9 | -2.6 |
| LingMess-He (+AlephBERT) | 44.3 | 42.8 | -1.4 |
| GPT-4o | 14.5 | 15.3 | +0.8 |
| Gemini 2.5-Pro | 26.8 | 27.4 | +0.6 |

神经编码器在金标准分词下性能领先，但自动分词导致 1.4–2.6 个 F1 点的下降，证实分词是独立瓶颈。LLM 在金标准提及条件下（GPT-4o 45.4 F1）仍落后于神经编码器（50.4 F1）5.0 个点，与英语中 LLM 占优的模式相反。

消融实验显示，LLM 在金标准提及下性能提升 20–30 个 F1 点，表明提及边界恢复是主要障碍；但自动分词与金标准分词间的差异在不同 LLM 间表现不一，说明分词质量并非唯一决定因素。神经编码器每文档产生 9.2–9.7 个正确簇，而 LLM 仅 1.6–1.9 个，证实聚类阶段存在显著瓶颈。

评估协议依赖 CoNLL-F1 指标，未报告置信区间，且 LLM 结果存在非确定性（$\sigma=0.4–3.2$）。代码与标注工具已开源，但仅针对希伯来语验证，未在其他形态丰富语言上复现，限制了协议的可迁移性验证。

## 关联研究分析

从问题动机看，本文与 CorefUD 多语言基准共享解决低资源语言 CR 数据缺失的目标，但 CorefUD 侧重语言覆盖广度，采用标准 CoNLL-U 格式，未处理形态内提及问题。本文 KibutzR 聚焦形态复杂性，通过子词级标注解决提及边界与词边界不对齐的核心矛盾。这一差异源于任务特性：希伯来语代词附着现象使标准词边界假设彻底失效，而 CorefUD 涵盖的语言中部分（如英语、法语）仍保留词边界对齐特性，无需形态感知标注。

从方法设计看，本文与 ImCoref-CeS 混合架构均试图结合监督模型与 LLM 优势，但 ImCoref-CeS 在英语域外数据上验证，依赖 LLM 进行聚类纠错；本文则揭示在希伯来语中 LLM 在聚类阶段本身即弱于监督编码器，混合架构的前提（LLM 聚类优势）在形态复杂语言中不成立。这一差异暗示 LLM 的推理优势可能依赖于训练数据的形态分布，而非架构固有特性。LLM 在希伯来语上的劣势是否源于训练数据缺乏希伯来语形态样本，还是架构对形态堆叠的固有处理缺陷，论文未提供消融实验加以区分。

## 总结

本文核心矛盾在于形态丰富语言中分词错误与聚类错误的耦合导致 CR 性能评估缺乏诊断性。现有基准依赖金标准分词掩盖了真实部署中的分词瓶颈，而 LLM 端到端范式又缺乏隔离错误源的评估框架。本文通过构建允许子词提及的 KibutzR 数据集与三级诊断协议，量化了分词错误对神经编码器的独立影响（1.4–2.6 F1 点），并揭示 LLM 在希伯来语聚类阶段落后监督编码器 5.0 个 F1 点的性能反转。该工作的边界在于仅验证希伯来语，未在其他形态丰富语言（如土耳其语、格鲁吉亚语）上复现，且未分析 LLM 劣势源于数据缺乏还是架构缺陷。当评估协议迁移至其他形态丰富语言时，子词级提及标注的必要性是否随语言形态复杂度线性变化，论文未给出回答。
