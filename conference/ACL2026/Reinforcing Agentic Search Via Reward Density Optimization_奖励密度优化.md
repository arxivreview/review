# ACL2026最新论文 ｜Reinforcing Agentic Search Via Reward Density Optimization ｜奖励密度优化

研究机构：中国科学院、香港科技大学

作者：Kun Luo、Hongjin Qian、Zheng Liu 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_f1d5aed9f2f3)

> 智能体搜索（Agentic Search）在长程多步任务中面临强化学习（RL）奖励稀疏导致的策略梯度失效问题。现有基于可验证奖励的强化学习（RLVR）方法仅依赖最终答案正确性，无法为中间探索步骤提供有效反馈，致使模型在复杂查询中陷入无效循环。本文提出奖励密度优化（Reward Density Optimization, RDO）框架，通过子目标脚手架、路径提示与双智能体精炼机制，最大化单位探索成本下的期望奖励。该框架使轻量级模型在深度搜索基准上匹敌部分闭源模型，但其性能上限受限于骨干模型规模，且未验证多模态场景下的泛化能力。

## 研究背景

当大语言模型（LLM）处理需多步推理的复杂查询时，其参数化知识的时效性滞后与事实幻觉缺陷迫使系统依赖外部检索。传统检索增强生成（RAG）采用静态“检索-生成”管道，无法根据中间结果动态调整后续查询，导致多跳推理中出现推理断裂。为突破此局限，ReAct 框架引入推理与行动交替执行机制，使 LLM 能自主规划搜索策略并迭代调用工具，将任务建模为序贯决策过程：智能体基于历史轨迹生成动作，环境返回观察，最终综合证据生成答案。

该范式转变将 LLM 从被动证据消费者提升为主动搜索智能体，但引入了长程任务中的信用分配难题。在长轨迹搜索中，稀疏的最终奖励难以确定哪些中间步骤对成功贡献最大，导致 RL 训练不稳定。Search-R1 等 RLVR 方法虽利用最终答案正确性作为信号，但仅关注结果，无法指导中间查询质量，致使智能体在困难样本上多次尝试仍无法产生正确轨迹，策略更新缺乏有效梯度。本文切入点在于将学习过程形式化为奖励密度优化问题，通过增加过程级监督信号与降低探索成本，解决 RLVR 在深度搜索中的稀疏奖励瓶颈。

## 核心方法

### 方法参照系

本文问题置于 RLVR 训练优化路线下。标准流程为：智能体在环境中执行多轮搜索-推理轨迹，仅当最终答案正确时获得二元奖励，通过策略梯度更新参数。本文关键差异在于：标准流程假设探索成本固定且奖励信号足够密集，而深度搜索任务中探索成本高、成功率低，导致奖励密度不足，策略学习停滞。

### 奖励密度形式化与双智能体精炼

设计动机：长轨迹积累大量噪声证据，超出 LLM 上下文限制，增加认知负担与错误累积概率，直接降低奖励密度。InfoFlow 将探索成本 $C(\tau)$ 近似为轨迹长度 $l(\tau)$，定义策略 $\pi$ 的奖励密度为：

$$
\rho(\pi) = \frac{\mathbb{E}_{\tau \sim \pi}[R(\tau)]}{\mathbb{E}_{\tau \sim \pi}[C(\tau)]}
$$

该公式表明，提升奖励密度需同时增加分子（期望奖励）与减小分母（探索成本）。为此，框架采用双智能体架构：Researcher Agent 负责推理与搜索，Refiner Agent 将检索到的噪声证据 $e_{k,j}$ 压缩为紧凑摘要 $sum_{k,j} = F_\phi(q, q_{k,j}, e_{k,j})$。Refiner 作为信息瓶颈，在训练时提供紧凑监督目标，在推理时压缩证据以更新 Researcher 状态。实验显示，3B Refiner 使 Researcher 上下文长度从 2372 降至 1310 tokens（减少 45%），成功率提升 5.0 点，直接降低了探索成本分母。

### 子目标脚手架与路径提示

设计动机：单一二元奖励无法为长轨迹中间步骤提供梯度信息，且困难样本在多次 on-policy 探索中仍无法解决，导致策略更新缺乏信号。子目标脚手架将复杂查询分解为加权子目标 $\{(g_i, s_i)\}_{i=1}^M$，其中 $\sum s_i = 1$。总奖励定义为：

$$
R(\tau) = \max\left(R_{final}(\tau) + w \cdot \sum_{g_i \in G_{solved}(\tau)} s_i, 1\right)
$$

其中 $w=0.3$ 平衡结果与过程奖励，$G_{solved}(\tau)$ 为轨迹中已解决的子目标集合。该公式为部分正确轨迹提供梯度信息，增加分子中的期望奖励。路径提示则针对 on-policy 探索瓶颈：当轨迹超过预设轮次 $K_h=5$ 未达终止状态时，插入预构建的引导查询 $a_{search}^{k,hint}$，与原始推理轨迹 $a_{think}^k$ 组合为 $a'_k = a_{think}^k \circ a_{search}^{k,hint}$。这些提示作为离线策略引导，使智能体从无效循环中恢复，增加成功探索比例，进一步提升奖励密度。

## 实验评估

实验在 InfoSeek 数据集（18,000 训练实例）上进行，评估基准包括 Natural Questions (NQ)、TriviaQA (TQA)、PopQA、HotpotQA (HQA)、2WikiMultihopQA (2Wiki)、Musique (MSQ)、Bamboogle (Bamb) 及 BrowseComp-Plus。基线覆盖 Search-R1、ZeroSearch、AutoRefine、InForage、ParallelSearch 等 RLVR 路线方法，但缺失多智能体协同架构（如 M-ASK）的直接对比。

InfoFlow-7B 在七个 QA 基准上平均准确率 46.2%，显著优于 ZeroSearch-7B（39.1%）与 ParallelSearch-7B（42.5%），且在 MSQ 与 Bamb 等多跳推理任务上优势更为明显。BrowseComp-Plus 上，InfoFlow-7B 取得 23.2% 准确率，高于 Gemini 2.5 Pro（19.0%）与 GPT-4.1（14.6%），但低于 GPT-5（55.9%）。

消融实验显示，联合 RFT（Co-training）使 Mean@4 从 31.0 提升至 34.3，Solve None 比例从 50.3% 降至 46.0%；路径提示进一步将 Mean@4 提升至 39.1，Solve None 降至 42.1%。路径提示对困难样本的解决率提升显著，但增加了搜索调用次数（从 4.17 至 4.72），表明其以额外探索成本换取成功率提升。

评估指标以 Exact Match (EM) 为主，BrowseComp-Plus 使用 LLM 判断准确率。协议局限在于：未报告置信区间，且不同方法使用相同检索设置（E5 嵌入、Wiki-18 语料、top-3 检索），但 BrowseComp-Plus 使用 BM25 检索器，与 QA 基准协议不一致。可复现性方面，论文未提供代码 URL，但详细描述了超参数（$K_h=5$, $w=0.3$）与数据构建流程。

## 关联研究分析

从问题动机看，InfoFlow 与 Search-R1 均聚焦 RLVR 中的稀疏奖励问题，但 Search-R1 仅依赖最终答案正确性，而 InfoFlow 通过子目标脚手架引入过程级奖励。这一差异源于任务复杂度：Search-R1 主要针对单跳或简单多跳任务，奖励稀疏程度较低；InfoFlow 针对深度搜索任务，成功率低（初始准确率 <10%），需更密集的信号。然而，子目标奖励的权重 $w=0.3$ 为固定超参数，未随任务难度动态调整，可能在简单任务中引入过多过程噪声，论文未验证此条件依赖性。

从方法设计看，InfoFlow 的双智能体架构与 Expand-then-Squeeze 均关注上下文压缩，但 Expand-then-Squeeze 采用查询扩展与压缩策略，而 InfoFlow 通过 Refiner Agent 实现端到端信息精炼。关键差异在于：Expand-then-Squeeze 的压缩是独立于 RL 训练的后处理步骤，而 InfoFlow 的 Refiner 参与联合 RFT 训练，其摘要质量直接影响策略学习。这种耦合设计使 Refiner 能针对搜索任务优化摘要内容，但增加了训练复杂度。此外，InfoFlow 的路径提示在推理时移除，可能导致训练-推理分布偏移，论文未量化此偏移对最终性能的影响。

## 总结

InfoFlow 解决的核心矛盾是深度搜索任务中 RL 训练的奖励稀疏与探索成本高昂之间的冲突。现有 RLVR 方法因仅依赖最终奖励，无法为长轨迹中间步骤提供有效梯度，导致策略学习停滞；InfoFlow 通过形式化奖励密度优化，结合子目标脚手架、路径提示与双智能体精炼，同时增加奖励信号密度与降低探索成本。实验证明，该框架使 7B 模型在七个 QA 基准上平均准确率 46.2%，在 BrowseComp-Plus 上达到 23.2%，匹敌部分闭源模型。然而，论文实验局限于 7B 以下模型，未验证奖励密度优化在更大规模模型（如 14B、32B）上的扩展性，且仅处理文本证据，未涉及多模态场景。当骨干模型规模扩大时，子目标奖励的边际收益是否递减，路径提示的探索成本是否被模型自身能力抵消，论文未给出回答。
