# ACL2026最新论文 ｜Mitigating Context Interference for Reliable and Efficient Search Agents ｜多轮搜索智能体中的上下文干扰缓解

研究机构：香港中文大学、英国伦敦大学学院

作者：Boyang Xue、Bin Wu、Shuofei Qiao 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_78e5a37df2c5)

> 多轮搜索智能体在迭代检索中面临检索文档噪声对生成质量的持续干扰，现有方法多聚焦于检索器优化或记忆管理，却忽视了上下文内部信息密度的动态调控。本文切入点在于识别并量化这种“上下文干扰”的来源，提出一种基于蒸馏的轻量级上下文精炼器，在每轮检索后动态压缩无关信息。该方法在提升检索效率与答案可靠性上取得平衡，但其对复杂多跳推理的绝对性能增益仍受限于基础模型能力，且未与主流强化学习训练范式进行直接对比。

## 研究背景

多轮搜索智能体（Multi-turn Search Agent）通过交替执行推理与检索动作解决复杂查询，其状态空间由历史查询、检索文档及推理步骤构成。检索器为保证覆盖率通常返回Top-K文档，其中必然包含与当前子问题无关的冗余信息。这种冗余并非简单的长度问题，而是构成“上下文干扰”（Context Interference），即无关上下文导致大语言模型（LLM）注意力分散，进而降低生成准确性并增加额外检索成本。

早期研究如IRCoT（Trivedi et al., 2023）确立了“思考-检索-生成”的交替范式，但默认将检索文档直接拼接至上下文，未区分信息相关性。随着任务复杂度提升，长上下文中的噪声累积效应显著，导致智能体在已检索到正确证据的情况下仍生成错误答案。现有缓解策略多集中于对话系统或静态RAG场景，缺乏针对多轮动态搜索中上下文干扰的系统性分析与干预机制。本文旨在通过定位干扰源并引入动态精炼模块，解决多轮搜索中证据利用效率低下的问题。

## 核心方法

### 方法参照系

本文基于IRCoT框架，该框架将搜索过程建模为马尔可夫决策过程（MDP），其中状态 $s_n$ 包含历史查询与观察。标准流程中，第 $i$ 轮观察 $o_i$ 直接取自检索器返回的文档集合 $d_i$。本文的关键差异在于，在 $o_i$ 进入状态 $s_n$ 之前，引入一个独立的上下文精炼器 $F$，对 $d_i$ 进行基于查询 $q_{i-1}$ 的信息筛选与压缩，从而改变状态转移中的信息密度。

### 干扰源定位与消融分析

为确定干扰来源，本文设计了掩码实验，分别移除历史文档、历史查询或历史思考步骤。实验表明，移除历史文档（IRCoT-o）能同时提升可靠性与效率，证明历史文档是主要干扰源；而移除历史思考步骤（IRCoT-oqp）虽降低干扰但显著增加检索次数，说明思考步骤承载了关键推理信息。这一发现指向最新一轮检索文档 $d_i$ 是干扰的主导因素，因为历史查询与思考已对前文进行了摘要，而 $d_i$ 未经过滤直接引入大量噪声。

### 基于蒸馏的上下文精炼器

针对最新文档的干扰，本文提出训练一个轻量级精炼器 $F$，其目标是从 $d_i$ 中提取与 $q_{i-1}$ 高度相关的信息 $\tilde{d}_i$。由于小模型直接提取关键信息能力有限，本文采用蒸馏策略：首先利用强教师模型（GPT-4）在IRCoT轨迹上生成精炼文本，并通过蕴含模型验证 $\tilde{d}_i$ 完全包含于 $d_i$ 且无额外知识，构建精炼数据集 $D_c = \{\tilde{d}_j, d_j, q_j\}$。随后，通过监督微调（SFT）训练基础模型 $M_\pi$ 作为精炼器，其损失函数定义为：

$$
\mathcal{L}_{SFT} = -\frac{1}{M} \sum_{i=1}^{M} \log M_\pi(\tilde{d}_i | d_i, q_i)
$$

该公式迫使模型学习在给定原始文档和查询的条件下，生成仅保留关键信息的精炼文本。精炼后的 $\tilde{d}_i$ 替代原始 $d_i$ 作为观察 $o_i$ 进入状态 $s_n$，从而在生成动作 $a_i$ 前消除噪声。这一设计将“精炼”从推理时的后处理提升为训练时的核心组件，使智能体在训练阶段即学会利用高质量证据，间接优化了长程任务中的信用分配信号质量。

## 实验评估

| 方法 | NQ (EM/ART) | HotpotQA (EM/ART) | Avg. (EM/ART) |
| :--- | :--- | :--- | :--- |
| IRCoT (7b) | 30.6 / 2.0 | 24.6 / 3.0 | 27.5 / 2.6 |
| GPT-Refine (7b) | 34.6 / 1.1 | 33.0 / 1.3 | 33.2 / 1.2 |
| Context Refiner (7b) | 34.0 / 1.2 | 32.0 / 1.4 | 32.2 / 1.2 |
| IRCoT (3b) | 21.6 / 1.2 | 24.1 / 1.6 | 24.3 / 1.4 |
| Context Refiner (3b) | 30.7 / 1.0 | 24.1 / 1.0 | 26.6 / 1.0 |

实验在NQ、TriviaQA、PopQA、HotpotQA等单跳与多跳QA基准上进行，基线包括Direct、CoT、IRCoT及其掩码变体，以及GPT-Compress、GPT-Refine和Self-Refine。主结果显示，Context Refiner在7B模型上平均EM达到32.2，ART降至1.2，相比IRCoT基线（27.5/2.6）在可靠性与效率上均有显著提升。在3B模型上，Context Refiner将平均EM从24.3提升至26.6，ART从1.4降至1.0，表明蒸馏策略有效弥补了小模型的关键信息提取能力不足。

消融实验揭示，GPT-Refine在可靠性上优于GPT-Compress，但ART略高，证明基于查询的动态精炼优于全局摘要。Context Refiner在7B模型上略低于GPT-Refine（32.2 vs 33.2），但在3B模型上显著优于Self-Refine（26.6 vs 24.5），验证了蒸馏对轻量级模型的必要性。值得注意的是，IRCoT-oqp在移除历史思考后ART显著增加，说明思考步骤对避免重复检索至关重要，而本文方法通过精炼文档而非移除思考，保留了这一效率优势。

评估边界方面，本文未报告置信区间，且未与Search-R1等基于强化学习的SOTA方法直接对比。代码已开源，但精炼器训练依赖GPT-4生成的数据，复现成本较高。指标仅涵盖EM与ART，缺乏对推理路径质量的细粒度评估。

## 关联研究分析

从问题动机看，本文与Expand-then-Squeeze（Zhao et al., 2025）均关注上下文噪声，但后者通过查询扩展增加召回后压缩，侧重信息覆盖；本文则通过精炼降低噪声，侧重信息密度。这一差异源于任务特性：Expand-then-Squeeze适用于检索召回率低的场景，而本文针对检索召回率高但噪声大的场景。MemSearcher（Yuan et al., 2025）通过显式记忆解决长程遗忘，与本文的即时精炼互补，共同应对长程任务中的上下文挑战，但本文未探索记忆与精炼的联合优化。

从方法设计看，本文与CoSearch（2025）在检索器协同优化上存在分歧。CoSearch联合优化检索器与智能体，打破黑盒假设；本文则保持检索器独立，仅优化智能体侧的上下文处理。这一选择可能源于本文聚焦于干扰缓解而非检索质量提升，但这也意味着本文方法在检索器本身性能不足时可能受限。此外，本文未与Pi-Serini（Hsu et al., 2026）对比，后者表明词汇检索在强LLM支持下可能足够，这挑战了本文使用E5密集检索器的必要性，也暗示精炼器可能部分弥补了检索器类型的局限。

## 总结

本文核心矛盾在于多轮搜索中检索文档噪声对生成质量的持续干扰，现有方法未能有效区分上下文中的关键信息与冗余噪声。本文通过定位干扰源至最新检索文档，提出基于蒸馏的上下文精炼器，在每轮检索后动态压缩无关信息，实现了“精炼上下文再生成”的新范式。实验证明该方法在7B模型上平均EM达32.2，ART降至1.2，显著优于IRCoT基线。然而，本文方法在绝对性能上未超越基于强化学习的SOTA，且精炼器与LLM的联合优化、以及在检索器性能不足场景下的鲁棒性，仍是未解问题。当检索器返回的文档本身缺乏关键信息时，精炼器是否仍能通过上下文重构提升答案质量，论文未给出回答。
