# ACL2026最新论文 ｜SeDev: Structured Semantic Exploration for LLM-Driven Code Generation ｜结构化语义探索框架

研究机构：华南理工大学、新加坡南洋理工大学

作者：Ronghui Yang、Jie Liu、Jiajie Zeng 等 8 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_df9ffcfbf808)

> 现有LLM代码生成方法在复杂软件任务中常因缺乏显式探索机制而陷入局部最优，导致功能完整性不足。SeDev通过引入元提示（Meta-prompt）将指令作为探索变量，结合单元测试反馈合成，实现了对语义相邻解空间的高效迭代搜索。该方法在FSD-Bench++上以84.12%的功能完整性超越了基于MCTS的基线，但其计算成本随探索轮次线性增长，且缺乏对探索-利用平衡的显式控制机制。

## 研究背景

在复杂软件生成任务中，解空间涉及编程语言、数据结构、架构设计及函数命名等多维选择，其规模远超单一函数补全场景。传统直接生成方法依赖模型内在随机性，但这种无引导的随机性往往导致输出质量低下；而基于蒙特卡洛树搜索（MCTS）的方法虽能显式探索，却因高维语义空间中的稀疏奖励和大量回滚操作而效率极低。此外，现有反馈增强方法如EvoMAC虽能利用单元测试迭代优化，但缺乏对解空间多样性的主动引导，易收敛至局部最优。

多智能体框架如MetaGPT和ChatDev通过角色分工模拟人类开发流程，解决了任务分解问题，但其线性瀑布式流程缺乏对中间结果的修正机制，导致错误累积且难以纠正。与此同时，固定提示策略在任务复杂度增加时无法捕捉细微需求差异，限制了探索的有效性。SeDev的切入点在于将提示本身视为可探索的变量，通过元提示动态生成任务特定指令，并结合单元测试反馈合成模块，将原始测试结果转化为语义相邻的改进建议，从而在有限迭代内高效逼近高质量解。

## 核心方法

### 方法参照系

SeDev属于多智能体代码生成框架，其标准流程包含架构设计、计划制定和代码生成三个阶段。与MetaGPT等线性流程不同，SeDev引入并行探索模块，允许同时启动多条探索路径，每条路径由Architect、Project Manager和Programmer三个智能体协作完成，旨在通过多样性生成提高解空间覆盖效率。

### 元提示结构化提示

固定提示在复杂任务中难以适应多样化需求，导致探索路径高度相似。SeDev引入元提示（Meta-prompt）作为任务无关模板，其指令部分仅定义有效指令的构成要素，而非具体目标。在探索过程中，元提示的输入输出占位符填充具体任务信息后，LLM基于高温度采样生成任务特定指令，使指令成为探索的核心驱动变量。这一设计解决了固定提示导致的多样性缺失问题，使探索过程能够动态调整方法论和约束条件。

$$
P_{task} = \text{Instantiate}(M, I_{task}, O_{task})
$$

其中 $M$ 为元提示模板，$I_{task}$ 和 $O_{task}$ 为任务特定输入输出，$P_{task}$ 为生成的任务特定提示。该公式表明，通过实例化元提示，系统能够生成多样化的指令组合，从而引导LLM探索不同的实现路径。

### 反馈合成与语义相邻探索

原始单元测试结果对LLM缺乏指导性，无法直接用于代码修正。SeDev的反馈合成模块分两步处理：首先，LLM分析每条探索路径的代码与测试结果，识别导致失败测试的关键元素；其次，另一LLM聚合所有路径的分析结果，生成针对三个智能体的定制化改进建议。对于成功路径，模块提取伪代码作为参考；对于失败路径，生成具体修正指导。这些建议被整合到下一轮的结构化提示中，引导探索向语义相邻的解空间演进。

$$
S_{next} = \text{Synthesize}(\{A_i, T_i\}_{i=1}^{N})
$$

其中 $A_i$ 为第 $i$ 条路径的分析结果，$T_i$ 为对应测试结果，$S_{next}$ 为下一轮探索的改进建议集合。该过程将离散测试结果转化为连续语义空间中的方向性指导，实现了从“试错”到“引导式探索”的转变。

## 实验评估

实验在HumanEval、DevEval和FSD-Bench++三个基准上进行，对比GPT-Engineer、MetaGPT、ChatDev、EvoMAC、MapCoder和GIF-MCTS等八种基线方法。SeDev在FSD-Bench++上表现最优，R=5轮时功能完整性（FC）达84.12%，显著优于GIF-MCTS的33.59%和EvoMAC的62.58%。

| 方法 | FC (%) | Tokens | Duration (s) |
| :--- | :--- | :--- | :--- |
| GPT-4o-Mini | 36.01 | 14.80 | - |
| MetaGPT | 30.20 | 44122 | 67.58 |
| EvoMAC | 62.58 | 25132 | 451.96 |
| GIF-MCTS | 33.59 | 11520 | 1245.82 |
| SeDev R=5 | 84.12 | 320360 | 1568.45 |

消融实验显示，移除元提示导致FC分数下降6.98%，验证了动态指令对探索多样性的关键作用。然而，SeDev的计算成本随轮次线性增长，R=6时Token消耗达390162，且R=5后收益递减明显（84.12%至84.49%），表明存在最优探索轮次阈值。

评估协议依赖LLM生成的测试代码，可能引入评估偏差；论文未报告置信区间，且骨干模型使用GPT-4o-Mini和DeepseekV3，与领域常见的GPT-4o基线存在可比性限制。代码已开源，但超参数配置（如并行路径数固定为3）未提供自适应机制。

## 关联研究分析

从问题动机看，SeDev与EvoMAC均利用单元测试反馈，但EvoMAC聚焦于代码层面的迭代修正，而SeDev将反馈提升至架构和计划层面，通过反馈合成模块生成跨智能体的改进建议。这一差异源于任务复杂度：EvoMAC适用于单文件或简单多文件任务，而SeDev针对多模块依赖的复杂软件，需要更高层级的语义指导。

从方法设计看，SeDev与GIF-MCTS同属探索式生成，但GIF-MCTS依赖MCTS的树搜索结构，在语义空间中效率低下；SeDev以LLM推理替代树搜索，通过元提示生成多样化指令，避免了大量回滚操作。然而，SeDev缺乏MCTS的显式利用机制，可能导致在已验证有效路径上的重复探索。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

SeDev旨在解决复杂软件生成中解空间探索效率低下的问题，通过元提示将指令作为探索变量，结合反馈合成实现语义相邻搜索。该方法在FSD-Bench++上以84.12%的FC超越了MCTS基线，证明了结构化探索的有效性。其边界在于计算成本随轮次线性增长，且缺乏对探索-利用平衡的显式控制。当任务难度增加时，固定并行路径数是否会导致探索不足，论文未给出回答。
