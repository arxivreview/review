# ACL2026最新论文 ｜AgencyBench: Benchmarking the Frontiers of Autonomous Agents in 1M-Token Real-World Contexts ｜长时程真实世界智能体基准

作者：Keyu Li、Junhao Shi、Yang Xiao 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.11044)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.11044)

> 现有智能体评估基准普遍受限于任务短视与单一能力聚焦，且依赖人工反馈导致评估无法规模化。AGENCYBENCH 通过构建 1M Token 级的多能力长时程任务集，并引入用户模拟代理与 Docker 沙箱实现全自动闭环评估，解决了真实场景复现与自动化瓶颈。该基准揭示了前沿模型在长时程自主性与资源效率上的显著差距，但其评估结果高度依赖特定脚手架配置，模型内在能力与框架效应的解耦仍存疑。

## 研究背景

智能体在动态环境中执行任务时，其表现不仅取决于最终输出，更受限于多步推理中的状态维持与错误恢复能力。这种长时程交互要求智能体在海量上下文（如百万级 Token）中保持逻辑一致性，而传统静态基准仅关注最终答案正确性，无法捕捉中间步骤的冗余操作或上下文丢失。为量化这种长时程能力，评估协议必须从结果导向转向轨迹审计，记录完整的动作-状态序列以诊断失败根源。

当前主流基准如 SWE-bench 和 GAIA 虽确立了交互式评估标准，但普遍存在任务深度不足与能力维度单一的问题，且依赖人工介入进行多轮反馈，导致 Rollout 收集成本高昂且难以复现。这种碎片化与人工依赖阻碍了大规模模型对比与自动化迭代。AGENCYBENCH 的切入点在于构建高保真的长时程真实世界任务集，并通过自动化代理替代人工反馈，实现评估流程的完全闭环与规模化。

## 核心方法

### 方法参照系

本文问题属于“评估框架与基础设施”路线，旨在解决长时程任务评估的自动化与标准化问题。与 AgentCompass 等侧重多基准聚合的基础设施不同，AGENCYBENCH 聚焦于单一基准的深度长时程构建，其关键差异在于引入了动态的用户交互闭环与视觉功能双重验证机制，而非仅执行静态脚本。

### 自动化交互闭环

传统基准依赖人工专家提供迭代反馈，导致评估无法并行化且存在主观偏差。AGENCYBENCH 在 Workspace 中引入用户模拟代理（User Simulation Agent），基于 Rubrics 自动判定任务完成度并生成针对性反馈。该代理利用 Claude-4-Sonnet（温度 0.0）解析未满足的评估标准，将失败原因反馈给执行智能体，形成“执行-反馈-修正”闭环。这一设计消除了人工瓶颈，使得大规模 Rollout 收集成为可能，同时通过人类验证研究（平均一致性得分 4.69/5）确保了反馈质量与真实人类专家的高度对齐。

### 多模态沙箱评估

仅基于文本输出的评估无法验证智能体在真实环境中的功能正确性（如 UI 渲染、交互逻辑）。AGENCYBENCH 将交付物同步至 Docker 远程沙箱，模拟鼠标点击、键盘输入等人类计算机操作，生成视频与截图等视觉工件。评估阶段采用双轨制：文本裁判（Claude-4-Sonnet）评估代码逻辑，视觉裁判（Gemini-2.5-Pro）评估动态行为与视觉正确性。最终得分由两部分加权平均得出，公式如下：

$$ S_{final} = \frac{S_{text} + S_{vision}}{2} $$

其中 $S_{text}$ 和 $S_{vision}$ 分别为文本与视觉裁判基于 Rubrics 给出的 0-10 分。该机制解决了纯文本评估无法捕捉运行时错误（如 JS 异常、布局错位）的问题，通过 Kappa 系数 0.93 验证了 LLM 裁判与人类标注的一致性，确保了评估的客观性与可复现性。

## 实验评估

实验覆盖 9 个前沿模型（5 闭源，4 开源），在 138 个任务上评估 6 种核心能力。基线选择聚焦于当前 SOTA 模型，但缺乏早期经典框架（如 ReAct 原始实现）的对比，限制了历史演进视角。主实验结果显示，闭源模型平均得分 48.4%，开源模型平均 32.1%，差距显著。

| 模型 | 类型 | 平均得分 (%) | 平均尝试次数 | Token 消耗 (M) | 执行时间 (H) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-5.2 | 闭源 | 56.5 | 1.46 | 3.4 | 0.6 |
| Claude-4.5-Opus | 闭源 | 47.7 | 1.54 | 1.7 | 0.8 |
| Gemini-3-Pro | 闭源 | 46.9 | 1.46 | 1.8 | 0.3 |
| Grok-4.1-Fast | 闭源 | 44.3 | 1.55 | 1.2 | 0.3 |
| GLM-4.6 | 开源 | 38.6 | 1.54 | 2.4 | 0.6 |
| Kimi-K2-Thinking | 开源 | 34.2 | 1.79 | 2.8 | 1.2 |
| DeepSeek-V3.2 | 开源 | 28.6 | 1.63 | 1.5 | 1.0 |
| Qwen-3-235B-A22B-Thinking | 开源 | 27.0 | 1.79 | 1.2 | 1.4 |

GPT-5.2 以 56.5% 的得分领先，但其 Token 消耗（3.4M）与尝试次数（1.46）均较高，呈现“暴力推理”特征。Grok-4.1-Fast 虽得分较低（44.3%），但 Token 效率最高（37.2%），适合资源受限场景。Qwen-3-235B-A22B-Thinking 得分最低（27.0%），且执行时间最长（1.4H），表明其在长时程任务中缺乏有效的错误恢复机制。

消融实验揭示了脚手架对性能的显著影响。在 10 个代表性场景中，Claude-4.5-Opus 在原生 Claude-Agent-SDK 中得分提升 20.5%，而 Kimi-K2-Thinking 在 OpenAI-Agents-SDK 中下降 12.8%。这种“主场优势”表明，模型性能并非固有属性，而是模型与脚手架耦合的结果。此外，反馈驱动自修正分析显示，GPT-5.2 在 Pass@2 中相对提升 88.9%，而 DeepSeek-V3.2 提升为 0.0%，说明部分模型无法利用外部反馈纠正错误路径。

评估边界方面，基准依赖 LLM 裁判，尽管 Kappa 系数高，但视觉裁判对复杂动态行为的捕捉能力仍受限于截图分辨率与帧率。可复现性上，代码已开源，但 Docker 沙箱的环境配置与模型 API 版本可能影响结果稳定性。

## 关联研究分析

从问题动机看，AGENCYBENCH 与 Holistic Agent Leaderboard 均关注成本效率，但前者聚焦于单基准内的长时程资源优化，后者侧重多基准间的 Pareto 前沿分析。AGENCYBENCH 引入用户模拟代理解决了人工反馈瓶颈，而 Holistic Agent Leaderboard 依赖标准化执行环境，两者在自动化路径上存在根本差异：前者通过模拟交互实现动态闭环，后者通过静态协议实现批量执行。

从方法设计看，AGENCYBENCH 与 MASEval 均揭示了框架对性能的影响，但 MASEval 聚焦多智能体协作中的消息历史追踪，AGENCYBENCH 聚焦单体智能体与脚手架的耦合。AGENCYBENCH 的“主场优势”发现暗示，模型训练目标与特定工具定义/提示结构存在深度优化，这种耦合在多智能体系统中可能被协作机制稀释或放大，论文未对此进行探索。

## 总结

AGENCYBENCH 旨在解决长时程真实世界任务评估的自动化与高保真问题，通过 1M Token 级任务集与用户模拟代理实现了评估闭环。实验证明闭源模型在长时程自主性上领先（48.4% vs 32.1%），但性能高度依赖脚手架配置，如 Claude-4.5-Opus 在原生 SDK 中提升 20.5%。该基准的边界在于，其评估结果混淆了模型内在能力与框架效应，且用户模拟代理的反馈分布是否与真实人类专家完全一致，论文未给出定量验证。当移除特定脚手架优化时，模型在长时程任务中的真实能力边界在哪里，仍是待解之谜。
