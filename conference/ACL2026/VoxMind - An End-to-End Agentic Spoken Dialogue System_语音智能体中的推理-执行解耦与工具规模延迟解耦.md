# ACL2026最新论文 ｜VoxMind: An End-to-End Agentic Spoken Dialogue System ｜语音智能体中的推理-执行解耦与工具规模延迟解耦

研究机构：浙江大学、厦门大学

作者：Tianle Liang、Yifu Chen、Shengpeng Ji 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.15710)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_0a4bcc932c60)

> 端到端语音对话模型在处理复杂任务时，常因缺乏显式规划能力而陷入被动响应，且大规模工具集成会导致推理延迟随工具数量指数级增长。VoxMind 通过引入“先思考后说话”机制与多智能体动态工具管理，将结构化推理内化至语音模型，并解耦工具规模与推理耗时。该框架在语音代理任务上显著超越了现有开源与部分闭源模型，但其对通用语音能力的保持及真实场景鲁棒性仍受限于合成数据的分布偏差。

## 研究背景

当语音助手需要执行如“查询航班并预订靠窗座位”这类多步任务时，直接映射输入到输出的端到端模型往往难以维持逻辑连贯性。这种失效源于语音模态的高 Token 开销，使得模型在编码声学特征的同时，难以同时处理复杂的工具语义解析与参数填充。为突破这一瓶颈，文本领域的智能体范式引入了中间推理阶段，将交互范式从 $x \to y$ 扩展为 $x \to z \to y$，其中 $z$ 代表链式思维（Chain-of-Thought, CoT）等结构化规划过程。然而，将这一范式迁移至语音领域面临双重挑战：一是缺乏标注了推理轨迹与工具交互的语音数据，二是大规模工具库的上下文窗口占用导致推理延迟不可控。

现有端到端语音模型如 Kimi-Audio 和 Qwen2.5-Omni 主要优化于感知与生成，缺乏对目标导向任务的规划能力。级联系统（如 Qwen3-8B + Whisper）虽利用文本 LLM 的优势，但引入了额外的转换延迟且无法直接建模副语言信息。VoxMind 的切入点在于构建一个统一的端到端框架，既通过专用数据集内化认知规划过程，又通过异步多智能体架构解决工具规模扩展带来的延迟瓶颈，从而在保持语音自然度的同时实现复杂的代理行为。

## 核心方法

### 方法参照系

本文问题归属于端到端语音对话模型中的代理能力增强。通用流程通常采用级联架构（ASR-LLM-TTS）或简单的端到端映射。关键差异在于，本文不依赖外部文本 LLM 进行推理，而是将推理能力直接注入语音模型内部，并针对语音模态特有的高 Token 开销设计了动态工具管理机制，以解决大规模工具调用下的实时性问题。

### Think-before-Speak 推理机制

该机制解决了直接映射范式在复杂规划任务中缺乏中间状态导致的逻辑断裂。在生成最终语音响应或工具调用前，模型首先采样一条显式的 CoT 轨迹 $c_t$。这一过程被形式化为：

$$ c_t \sim \pi_{\text{think}}^{\theta}(c \mid o_t, H_{t-1}, T_{\text{local}}^t) $$

该公式表明，推理轨迹 $c_t$ 是基于当前观测 $o_t$、历史交互 $H_{t-1}$ 及局部工具集 $T_{\text{local}}^t$ 条件采样得到的。随后，动作 $a_t$ 基于该推理轨迹生成：

$$ a_t \sim \pi_{\text{act}}^{\theta}(a \mid c_t, o_t, H_{t-1}, T_{\text{local}}^t) $$

这种两阶段设计确保了所有可观察行为均植根于显式推理，使模型能够处理任务分解与并行处理等复杂逻辑，而非仅进行反射式响应。

### 多智能体动态工具管理

针对工具库规模扩大导致的推理延迟指数级增长，VoxMind 引入了辅助语言模型（Auxiliary LLM）进行异步工具检索。当主模型生成推理轨迹 $c_t$ 后，系统并行执行两个过程：主模型基于当前局部工具集采样动作，辅助模型从全局工具池 $T_{\text{all}}$ 中提出候选工具 $T_{\text{cand}}^t$。

$$ (a_t, T_{\text{cand}}^t) \sim \left( \pi_{\text{act}}^{\theta}(\cdot \mid c_t, T_{\text{local}}^t), \pi_{\text{LLM}}(c_t, T_{\text{all}}) \right) $$

若主模型发出检索动作 $a_{\text{retrieve}}$，则更新局部工具集：

$$ T_{\text{local}}^{t+1} = T_{\text{local}}^t \cup T_{\text{cand}}^t $$

此机制通过按需扩展工具空间，避免了每次决策都处理整个工具库，从而实现了推理延迟与工具规模的解耦，确保在工具富集环境下仍能保持响应速度。

## 实验评估

VoxMind 在自建的 AgentChat 数据集上进行了评估，该数据集包含 470 小时标注了推理轨迹的语音数据。基线覆盖了闭源模型（Gemini-2.5-pro, GPT-4o-audio）、级联系统（Qwen3-8B+Whisper）及开源端到端模型（Kimi-Audio, StepAudio2）。

| 模型类型 | 模型名称 | Overall Score |
| :--- | :--- | :--- |
| 闭源 | Gemini-2.5-pro | 71.51 |
| 级联 | Qwen3-8B+Whisper | 64.00 |
| 端到端 | Kimi-Audio | 54.94 |
| 端到端 | StepAudio2 | 34.88 |
| 本文 | VoxMind | 74.57 |

VoxMind 以 74.57 的综合得分超越了最强的闭源基线 Gemini-2.5-pro（71.51）和级联系统 Qwen3-8B+Whisper（64.00），显示出端到端架构在整合推理与语音生成方面的优势。

消融实验揭示了推理机制对性能的关键作用。在未使用深度思考（w/o think）的配置下，增加代理数据比例（从 1:1 到 1:0.5）仅使得分从 68.83 微升至 70.97，且导致通用语音能力（VoiceBench）从 59.72 下降至 54.80。相比之下，启用深度思考（w/ think）后，1:0.5 比例的配置取得了 74.57 的最高代理得分，同时 VoiceBench 得分保持在 64.21，仅比基线模型下降 0.53 分。这表明显式 CoT 推理不仅提升了任务完成度，还有效缓解了领域专业化与通用语音能力之间的权衡。

评估边界方面，AgentChat 数据主要由文本合成语音（CosyVoice2 + SeedTTS）生成，缺乏真实人类对话的声学噪声与副语言复杂性，可能高估模型在真实环境下的鲁棒性。此外，评估依赖 Gemini-2.5-Flash 作为专家评判器，虽通过三次平均降低方差，但仍存在 LLM 评判的固有偏差。代码与数据已开源，但训练需 2 块 H20 GPU 并采用 ZeRO-3 策略，复现门槛较高。

## 关联研究分析

从问题动机看，VoxMind 与 Social Agent 均利用 LLM 进行高层推理，但 Social Agent 聚焦于非语言行为（如手势、视线）的社交适当性，而 VoxMind 侧重于工具调用的逻辑准确性与参数完整性。这一差异源于任务目标的不同：前者需捕捉社交规范中的模糊性，后者需处理 API 接口的严格结构化约束。VoxMind 的“Think-before-Speak”机制更适用于确定性任务规划，而 Social Agent 的显式社交推理更适合处理开放式的社交互动。

从方法设计看，VoxMind 与 UniLS 同属端到端语音交互框架，但 UniLS 致力于解决全双工交互中的唇形同步与头部运动生成，而 VoxMind 关注语义层面的任务执行。UniLS 采用多尺度编解码器优化声学-运动相关性，VoxMind 则通过动态工具管理优化计算效率。两者在底层均依赖语音编码，但 UniLS 的输出是连续的面部参数，VoxMind 的输出是离散的工具调用指令。这种差异表明，端到端语音模型在处理感知生成任务与认知执行任务时，需要截然不同的架构优化方向。

## 总结

VoxMind 旨在解决端到端语音模型在复杂任务中缺乏规划能力及工具规模扩展导致的延迟瓶颈。通过构建 AgentChat 数据集内化推理过程，并设计多智能体动态工具管理机制，该框架实现了推理与执行的解耦以及延迟与工具规模的解耦。实验显示，其代理任务得分达 74.57，超越 Gemini-2.5-pro 的 71.51，且通用语音能力损失控制在 0.53 分以内。然而，其训练数据主要依赖合成语音，缺乏真实场景的声学多样性，且评估依赖 LLM 评判。当面对包含大量背景噪声、重叠语音或副语言情感线索的真实对话场景时，该动态工具管理机制的延迟解耦效果与推理准确性是否会因声学输入的复杂性而显著退化，论文未给出回答。
