# ACL2026最新论文 ｜TH-RAG : Topic-Based Hierarchical Knowledge Graphs for Robust Multi-hop Reasoning in Graph-based RAG Systems ｜层级知识图谱检索框架

研究机构：韩国汉阳大学

作者：JungHyoun Kim、Soohyeong Kim、Seok Jun Hwang 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_4f9164f5de4f)

> 图增强检索生成（GraphRAG）旨在通过结构化知识缓解大语言模型（LLM）的多跳推理断裂与幻觉问题，但现有基于三元组的图构建常因连通性不足导致推理路径中断，而社区检测等增强手段又引入高计算成本与语义失真。本文切入点在于利用 LLM 一次性提取三元组、子主题与主题，构建三层语义层级图，以近零额外成本提升图连通性。该方法通过主题引导的自顶向下遍历与句子级证据过滤，在多个基准上超越了主流图检索基线。其价值在于平衡了结构完整性与计算效率，但层级标注的语义一致性依赖 LLM 的提取质量，跨域泛化能力仍受限于语料库的覆盖度。

## 研究背景

检索增强生成（RAG）通过引入外部知识缓解 LLM 的幻觉，但基于向量相似度的文本检索难以捕捉实体间的显式逻辑关系，导致多跳推理时路径断裂。为了解决这一问题，图增强检索生成（GraphRAG）将语料库组织为知识图谱（KG），利用节点-边结构约束推理链条。然而，LLM 直接从文本提取的三元组往往稀疏且碎片化，形成大量孤立子图，使得关键实体间的关系路径缺失，严重阻碍了全局语义理解与长程推理。

主流解决方案如社区检测（Edge et al., 2024）或 HNSW 聚类（Xu et al., 2025）试图通过算法恢复连通性，但这些方法计算开销巨大，且摘要过程可能丢失细粒度语义或引入幻觉。本文针对这一瓶颈，提出在图构建阶段同步提取层级语义标签，而非事后进行昂贵的图增强。这种设计将连通性保障前置到提取环节，旨在以单次 LLM 调用的成本，构建一个既具备全局结构又保留原始句子证据的层级图，从而在效率与保真度之间取得平衡。

## 核心方法

### 方法参照系

本文问题属于图增强检索生成路线，标准流程为“三元组提取-图构建-子图检索-答案生成”。与通用流程的关键差异在于，本文摒弃了独立的图增强模块，将层级结构（主题-子主题-实体）的构建整合进三元组提取阶段，并采用主题引导的遍历替代全局社区检索。

### 层级图构建与语义锚定

传统方法在提取三元组后，需额外运行聚类算法来连接孤立节点，这导致计算成本线性增长且语义被摘要压缩。本文在提取每个三元组时，同步让 LLM 生成其所属的子主题（Subtopic）和主题（Topic），形成 $G = (V, E)$，其中 $V = V_E \cup V_{ST} \cup V_T$。每个实体节点 $e \in V_E$ 至少连接两个边，且通过 $E_{sub}$ 和 $E_{top}$ 向上挂载至子主题与主题节点。这种设计动机在于，通过语义包含关系（Topic $\supset$ Subtopic $\supset$ Entity）强制建立跨实体的连接，避免了事后聚类的信息损失。公式上，每个三元组边 $r \in E_{triplet}$ 保留原始句子 $S$ 作为属性，确保检索可回溯至源文本，最小化幻觉风险。

### 主题引导的遍历与过滤

层级图构建后，检索阶段面临搜索空间爆炸问题。本文采用两步 LLM 引导遍历：首先从所有主题节点中选出 $N_T$ 个与查询 $q$ 相关的主题，再为每个主题选出 $N_{ST}$ 个子主题。这一过程可视为在层级图上的自顶向下剪枝，将搜索空间从全图缩小至特定语义区域。随后，从选定子主题下的实体出发，收集 1-hop 邻居边，计算查询与候选句子 $s_i$ 的余弦相似度：

$$ \text{score}(q, s_i) = \frac{\mathbf{q} \cdot \mathbf{s}_i}{\|\mathbf{q}\| \|\mathbf{s}_i\|} $$

选取 Top-$K_1$ 句子作为主上下文，并进一步扩展 Top-$K_2$ 句子的源块作为扩展上下文。该设计解决了纯向量检索无法捕捉逻辑依赖的问题，同时通过 $K_2 \ll K_1$ 的扩展策略，在保持证据忠实性的同时补充了局部语境，缓解了实体遗漏导致的推理断裂。

## 实验评估

实验在 UltraDomain（抽象型）和 MultiHop-RAG、HotpotQA（具体型）上进行，基线覆盖 NaiveRAG、GraphRAG（局部/全局）、LightRAG、PathRAG 和 HyperGraphRAG。在 MultiHop-RAG 上，TH-RAG 的 F1 达到 0.712，显著高于 HyperGraphRAG 的 0.526 和 GraphRAG-G 的 0.526；在 HotpotQA 上，F1 为 0.671，优于 LightRAG 的 0.496。

| 方法 | MultiHop-RAG F1 | MultiHop-RAG Acc | HotpotQA F1 | HotpotQA Acc |
| :--- | :--- | :--- | :--- | :--- |
| NaiveRAG | 0.501 | 0.604 | 0.584 | 0.509 |
| GraphRAG-G | 0.526 | 0.653 | 0.393 | 0.343 |
| LightRAG | 0.464 | 0.526 | 0.496 | 0.439 |
| HyperGraphRAG | 0.526 | 0.621 | 0.674 | 0.599 |
| TH-RAG | 0.712 | 0.722 | 0.671 | 0.612 |

消融实验表明，移除上下文块（chunks）导致 F1 从 0.712 降至 0.576，移除三元组信息降至 0.680，绕过遍历机制降至 0.620。这证实了句子级证据保留和层级遍历是性能提升的关键。效率方面，TH-RAG 索引阶段仅消耗 2.3M tokens，为 LightRAG（8M）的 29%，且 LLM 调用次数仅为 HyperGraphRAG 的 32.5%。

评估边界方面，论文未报告置信区间，且 UltraDomain 使用 LLM-as-a-judge 评估，可能存在评估偏差。代码已开源，但超参数 $K_1, K_2$ 的敏感性分析显示，当 $K_1=50, K_2=10$ 时性能下降，提示存在“上下文腐烂”风险，限制了其在超长上下文场景的适用性。

## 关联研究分析

从问题动机看，本文与 HyperGraphRAG 均致力于解决图碎片化问题，但 HyperGraphRAG 依赖超图构建与复杂算法，而本文通过 LLM 直接生成层级标签实现连通性。这一差异源于任务特性：HyperGraphRAG 追求全局结构的最优表示，而本文更关注在有限 LLM 调用预算下的效率与保真度平衡。本文的层级标注是否比算法聚类更鲁棒地处理长尾实体，论文未给出直接对比，但效率数据暗示其在资源受限场景更具优势。

从方法设计看，本文与 LightRAG 同属轻量级图检索框架，但 LightRAG 仅提取实体与关系，缺乏语义层级，导致图连通性依赖实体共现。本文引入主题-子主题层级，本质上是将语义聚类前置到提取阶段。这种设计挑战了“社区检测是标准做法”的隐含共识，表明 LLM 的语义理解能力可以替代部分图算法功能。然而，层级标注的一致性依赖 LLM 的提取质量，若 LLM 对主题划分存在偏差，可能导致检索路径偏离，这一风险在论文中仅通过允许多选候选来缓解，未进行定量评估。

## 总结

本文核心矛盾在于图增强检索中连通性保障与计算效率的冲突。现有方法通过事后聚类解决连通性，但引入高成本与语义失真；本文通过 LLM 同步提取层级标签，以近零额外成本构建语义连通图。实验证明，该层级结构在 MultiHop-RAG 上实现了 0.712 的 F1，超越最强基线 18.6%。其边界在于，层级标注的语义一致性依赖 LLM 的提取质量，且当检索参数 $K_1, K_2$ 过大时，性能因上下文腐烂而下降。当语料库规模扩大至百万级文档时，主题节点的数量是否会指数级增长，导致遍历阶段的 LLM 调用成本超过社区检测，论文未给出回答。
