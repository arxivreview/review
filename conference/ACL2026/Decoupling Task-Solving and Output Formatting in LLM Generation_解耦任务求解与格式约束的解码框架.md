# ACL2026最新论文 ｜Decoupling Task-Solving and Output Formatting in LLM Generation ｜解耦任务求解与格式约束的解码框架

研究机构：美国加州大学洛杉矶分校

作者：Haikang Deng、Po-Nien Kung、Nanyun Peng

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_9f64cd724097)

> 大语言模型在同时处理复杂推理与严格输出格式时，常因提示词中的指令耦合导致推理能力退化。现有硬约束解码方法虽能保证格式合规，但通过掩码重归一化引入的分布扭曲会进一步损害语义质量。DECO-G 通过引入独立的格式估计模块，将格式合规性从语言模型的认知负荷中剥离，利用概率前瞻信号重加权 Token 分布。该框架在保持 100% 格式合规的同时显著提升了任务准确率，但其依赖的隐马尔可夫模型近似误差在长序列中的累积效应尚存疑。

## 研究背景

当模型需要生成包含特定结构（如 JSON 或固定短语）的文本时，传统的提示工程往往将任务指令与格式要求混合在同一输入中。这种耦合迫使模型在每一步解码时同时权衡语义正确性与格式合规性，导致注意力分散。为了解决这一问题，受控文本生成领域引入了属性控制机制，其核心是通过贝叶斯规则将目标分布分解为语言模型概率与属性似然的乘积。然而，直接计算属性似然需要对所有未来序列进行边缘化，计算复杂度呈指数级增长，这使得实时解码中的精确控制难以实现。

主流解决方案分为两类：一类是硬约束解码，如 Outlines，通过有限状态自动机实时屏蔽非法 Token，虽能保证格式但造成分布截断；另一类是软约束解码，如 Ctrl-G，利用从无条件采样中蒸馏的隐马尔可夫模型（Hidden Markov Model, HMM）进行概率前瞻。然而，硬约束的“投影税”导致推理退化，而软约束因 HMM 未捕捉指令微调后的条件分布，控制信号在复杂任务中失效。DECO-G 的切入点在于指出，指令微调模型的输出分布与无条件生成存在根本差异，必须通过指令感知的蒸馏构建更精确的代理模型，并解决复杂模板下的自动机构建瓶颈。

## 核心方法

### 方法参照系

DECO-G 基于 GeLaTo 和 Ctrl-G 建立的 HMM-DFA 框架，即使用 HMM 近似语言模型分布，DFA 编码格式约束，通过计算满足约束的序列概率来引导解码。与通用流程的关键差异在于，DECO-G 将任务指令与格式约束在输入层面完全解耦，LLM 仅接收任务信息，格式约束仅传递给格式估计模块（Format Estimation Module, FEM），从而避免格式指令对推理路径的直接干扰。

### 指令感知 HMM 蒸馏与概率前瞻

传统方法从无条件采样中蒸馏 HMM，导致其无法反映指令微调模型在特定任务下的条件分布，控制信号因此失效。DECO-G 采用指令感知蒸馏，利用 Natural-Instructions-v2 数据集中超过一百万条指令-响应对训练 HMM，使其捕捉任务导向的行为模式。在解码阶段，FEM 利用该 HMM 与 DFA 计算未来序列满足格式约束 $\alpha$ 的边际概率 $P_{FEM}(\alpha|x_t, x_{<t})$，并以此作为似然项重加权当前 Token 概率：

$$ P(x_t|x_{<t}, \alpha) \propto P_{LM}(x_t|x_{<t}) [P_{FEM}(\alpha|x_{<t}, x_t)]^\gamma $$

该公式表明，解码不再依赖硬掩码，而是通过调整概率分布的相对权重，引导模型在保持自然推理流的同时逐步趋向格式合规，$\gamma$ 控制引导强度。

### 灵活 Trie 构建与状态剪枝

复杂格式模板包含变长字段，标准 DFA 构建会导致状态空间爆炸。DECO-G 提出灵活 Trie 算法，通过状态收敛策略将变长通配符路径合并至固定枢轴节点，确保状态空间复杂度从指数级 $O(K^N)$ 降至线性 $O(N \times K)$。此外，针对 HMM 发射阶段的高计算开销，利用隐状态概率质量高度集中的特性，仅保留 Top-k 状态进行计算，将发射复杂度从 $O(h|V|)$ 降至 $O(k|V| + h \log h)$，在保留 97.8% 概率质量的前提下实现约 13 倍的 FLOPs 减少。

## 实验评估

实验在 GSM8K、ACE05 和 SummEval 三个基准上进行，基线包括 Prompt-Only、Outlines（硬约束）和 Ctrl-G（软约束）。DECO-G 在所有模型上均实现了 100% 格式合规，且任务准确率显著优于基线。

| 模型 | 方法 | Format (%) | Acc. (%) |
| :--- | :--- | :--- | :--- |
| Llama-3.1-8B-Instruct | Prompt-Only (NL) | 96.3 | 82.3 |
| Llama-3.1-8B-Instruct | Outlines (JSON) | 75.7 | - |
| Llama-3.1-8B-Instruct | Ctrl-G | 61.6 | - |
| Llama-3.1-8B-Instruct | DECO-G | 85.2 | - |
| Qwen3-8B | Prompt-Only (NL) | 97.4 | 90.5 |
| Qwen3-8B | Outlines (JSON) | 99.2 | 90.6 |
| Qwen3-8B | DECO-Gγ=2 | 91.7 | - |

注：表格中部分准确率数值在原文表格中未明确对应列，此处仅展示可逐字定位的格式合规率与部分准确率。在 GSM8K 上，Llama-3.1-8B 的 DECO-G 准确率为 85.2%，高于 Prompt-Only (NL) 的 82.3%；Qwen3-8B 的 DECO-G 准确率为 91.7%，高于 Prompt-Only (NL) 的 90.5%。

消融实验显示，HMM 状态剪枝对性能影响极小。Llama-3.1-8B 上，剪枝后准确率从 85.4% 降至 85.2%（$\Delta=-0.2$）；Qwen3-8B 上，剪枝后准确率从 90.8% 升至 91.7%（$\Delta=+0.9$），表明剪枝不仅未损害性能，甚至在某些模型上因减少了噪声状态而略有提升。

评估边界方面，实验采用零样本贪心解码，未报告置信区间。代码未公开，HMM 蒸馏依赖特定 LLM，跨模型迁移性受限。指标仅关注格式合规率与任务准确率，未量化分布扭曲的具体程度（如 KL 散度）。

## 关联研究分析

从问题动机看，DECO-G 与 DCCD 同属缓解约束解码分布扭曲的路线，但 DCCD 依赖草稿模型预测来修正可行质量量，计算开销较大且需额外模型推理；DECO-G 则通过 HMM 前瞻实现轻量级引导，无需额外模型，但 HMM 作为代理模型的近似误差可能限制其在极端复杂约束下的精度。从方法设计看，DECO-G 与 Outlines 形成鲜明对比，Outlines 通过硬掩码保证合规但牺牲推理流，DECO-G 通过概率重加权保留推理自然性，但后者依赖 HMM 对 LLM 分布的准确捕捉，若 HMM 蒸馏数据与测试任务分布差异过大，控制信号可能失效。

## 总结

DECO-G 旨在解决任务指令与格式约束耦合导致的推理退化问题。其核心在于通过指令感知 HMM 蒸馏和灵活 Trie 构建，实现格式合规性的概率引导而非硬约束。实验证明，在 GSM8K 上，DECO-G 使 Llama-3.1-8B 的准确率从 82.3% 提升至 85.2%，同时保证 100% 格式合规。然而，该方法依赖 HMM 对 LLM 分布的近似，且 HMM 需针对每个 LLM 重新蒸馏，跨模型通用性受限。当 HMM 蒸馏数据与测试任务的分布差异增大时，概率前瞻信号的准确性是否仍能维持，论文未给出回答。
