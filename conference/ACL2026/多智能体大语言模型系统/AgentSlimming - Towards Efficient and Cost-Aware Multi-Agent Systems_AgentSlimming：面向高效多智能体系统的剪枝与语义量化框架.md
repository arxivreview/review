# ACL2026最新论文 ｜AgentSlimming: Towards Efficient and Cost-Aware Multi-Agent Systems ｜AgentSlimming：面向高效多智能体系统的剪枝与语义量化框架

作者：Yulang Chen、Haoxuan Peng、Jinyan Liu 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.08813)

> 多智能体系统（Multi-Agent Systems, MAS）在复杂任务中展现出超越单模型的推理能力，但自动化工作流生成往往导致结构臃肿与 Token 成本激增。现有方法多聚焦于动态拓扑生成或端到端强化学习优化，忽视了在固定工作流结构上进行后处理压缩的潜力，导致部署时计算开销难以控制。AgentSlimming 提出了一种即插即用的压缩框架，通过混合重要性评估机制识别冗余节点，执行结构剪枝与模型语义量化。该工作验证了稀疏异构拓扑在成本-性能帕累托前沿上的优势，但其静态压缩特性在动态任务适应性上的表现尚待验证。

## 研究背景

当自动化代理工作流生成框架（如 AFlow）通过蒙特卡洛树搜索（MCTS）探索最优推理拓扑时，其优化目标通常假设计算资源无约束。这种假设导致生成的工作流倾向于使用高成本模型（如 GPT-4）构建密集连接，以最大化任务准确率。然而，在实际部署中，这种“无约束”假设失效：冗余的并行路径与低价值的信息交换导致 Token 消耗呈二次方增长，使得系统难以规模化。

为缓解这一瓶颈，领域内发展出两类主要路线：一是动态拓扑优化，如 GPTSwarm 和 G-Designer，通过图神经网络或生成模型实时调整通信结构；二是智能体路由与调度，如 OI-MAS，根据状态感知分配计算资源。前者依赖训练数据且推理开销大，后者侧重任务分配而非结构精简。AgentSlimming 的切入点在于：既然自动化搜索已生成高性能但臃肿的工作流，为何不将其视为一个待压缩的“预训练模型”，通过结构剪枝与模型替换直接降低执行成本？这一视角将神经网络压缩中的剪枝与量化概念迁移至 MAS 工作流，填补了后处理压缩方法的空白。

## 核心方法

### 混合重要性评估机制

AgentSlimming 的核心在于如何准确识别工作流中“可被移除或替换”的节点。传统图剪枝仅依赖拓扑结构（如度中心性），忽略了节点的功能贡献；而基于 Shapley 值的方法虽能衡量功能贡献，但计算复杂度为 NP-hard。AgentSlimming 提出了一种混合重要性评估机制，融合拓扑先验、功能贡献与经济潜力三个维度。

对于任意节点 $v$，其综合重要性分数通过倒数排名融合（Reciprocal Rank Fusion, RRF）计算：

$$
\text{RRF}(v) = \sum_{m \in \{deg, bet, shap, \Delta C\}} \frac{w_m}{\kappa + r_m(v)}
$$

其中，$r_m(v)$ 是节点 $v$ 在指标 $m$ 下的排名，$w_m$ 为权重，$\kappa$ 为平滑常数。该公式的物理含义是：一个节点若同时具有低拓扑中心性（结构边缘）、低 Shapley 值（功能冗余）和高成本节省潜力（经济价值），其 RRF 分数将最低，从而被优先选中进行剪枝或量化。这一设计解决了单一指标评估的偏差问题，例如仅依赖拓扑中心性可能误删功能关键但连接稀疏的节点。

### 结构剪枝与语义量化

基于混合重要性分数，AgentSlimming 执行两阶段压缩：结构剪枝（AgentPruner）与语义量化（AgentQuant）。

**结构剪枝**旨在移除冗余节点。对于候选节点 $v$，若移除后工作流性能下降在容忍阈值 $\tau_p$ 内，则执行剪枝：

$$
S(G_p) \geq S(G_{base}) - \tau_p
$$

其中 $S(\cdot)$ 为任务得分，$G_p$ 为剪枝后的图。剪枝后通过边修补（Edge Patching）维持图连通性。该步骤直接减少了通信路径与节点数量。

**语义量化**则针对保留节点，将其底层 LLM 替换为低成本模型（如从 GPT-4.1-mini 替换为 GPT-4.1-nano）。量化决策同样基于 RRF 分数，接受条件为：

$$
S(G_q) \geq S(G_p) - \tau_q
$$

其中 $G_q$ 为量化后的图。这一创新将“模型替换”形式化为“语义量化”，解决了传统剪枝无法降低单节点计算成本的问题。通过保留高贡献节点的高精度模型，量化低贡献节点，AgentSlimming 实现了异构模型协同，在保持核心推理能力的同时大幅降低 API 调用成本。

## 实验评估

实验在 GSM8K、MATH、MBPP、HotpotQA、DROP、AIME、LiveCode 和 MuSiQueAns 八个基准上进行，基线包括 CoT、Self-Refine、ADAS 及 AFlow。AgentSlimming 在成本-性能帕累托前沿上表现显著，尤其在复杂推理与代码生成任务中实现“双赢”。

| 基准 | 方法 | 准确率 (%) | 成本 ($/prob.) | 成本降低 (%) |
| :--- | :--- | :--- | :--- | :--- |
| GSM8K | AFlow | 95.5 | 4.38e-3 | - |
| | **AgentSlimming** | **95.5** | **9.30e-4** | **78.8%** |
| MBPP | AFlow | 73.3 | 2.58e-3 | - |
| | **AgentSlimming** | **77.9** | **7.30e-4** | **71.7%** |
| LiveCode | AFlow | 55.3 | 1.17e-2 | - |
| | **AgentSlimming** | **61.7** | **2.47e-3** | **78.9%** |
| MATH | AFlow | 74.8 | 1.20e-2 | - |
| | **AgentSlimming** | **73.9** | **6.88e-3** | **42.7%** |

在 GSM8K 上，AgentSlimming 保持与 AFlow 相同的 95.5% 准确率，但成本降低 78.8%。在 MBPP 和 LiveCode 上，准确率分别提升 4.6 和 6.4 个百分点，同时成本降低超过 70%。这表明剪枝与量化不仅未损害性能，反而通过去除噪声路径提升了推理效率。

消融实验显示，混合重要性评估（RRF）优于单一指标。仅使用度中心性或介数中心性会导致准确率显著下降（如 MATH 上从 74.8% 降至 73.1% 或 74.0%），而仅使用 Shapley 值虽能保持性能但成本降低有限。RRF 融合策略在 MATH 上实现了 79.7% 的成本降低，同时保持 74.8% 的准确率，验证了拓扑与功能信号互补的必要性。

评估边界方面，实验未覆盖动态任务场景，且未与 G-Designer 等动态拓扑生成方法进行直接对比。此外，成本计算基于 API 调用价格，未包含本地部署的硬件开销。

## 关联研究分析

从问题动机看，AgentSlimming 与 GPTSwarm 形成鲜明对比。GPTSwarm 通过强化学习动态生成拓扑，旨在适应任务变化，但引入了训练开销与推理延迟；AgentSlimming 则假设工作流结构已确定，通过后处理压缩降低成本，适用于部署阶段。这一差异源于对“优化时机”的不同选择：前者在训练/搜索阶段优化结构，后者在部署前优化结构。AgentSlimming 的静态压缩特性使其在分布外任务上的适应性存疑，若任务复杂度超出原始工作流设计范围，剪枝后的结构可能无法恢复性能。

从方法设计看，AgentSlimming 与 AgentDropout 均涉及节点移除，但 AgentDropout 侧重动态剪枝以应对实时负载，而 AgentSlimming 的剪枝是静态且一次性的。AgentSlimming 引入的“语义量化”是 AgentDropout 未涉及的维度，后者仅移除节点而不替换模型。这一差异使得 AgentSlimming 能在保留节点功能的同时降低计算成本，但依赖于模型替换的语义等价性假设。当低成本模型无法胜任高成本模型的任务时，量化可能导致性能崩溃，论文通过回滚机制缓解此风险，但未量化该风险的发生频率。

## 总结

AgentSlimming 针对自动化工作流生成导致的计算冗余问题，提出了一种基于混合重要性评估的剪枝与语义量化框架。通过融合拓扑中心性与 Shapley 值近似，该框架准确识别冗余节点，并通过模型替换降低执行成本。实验表明，AgentSlimming 在 GSM8K 上实现 78.8% 的成本降低且保持准确率，在 LiveCode 上实现 78.9% 的成本降低并提升准确率。其边界在于静态压缩特性可能限制动态任务适应性，且未与动态拓扑生成方法进行直接对比。当任务分布发生显著偏移时，预压缩的静态工作流是否仍能维持性能优势，论文未给出回答。
