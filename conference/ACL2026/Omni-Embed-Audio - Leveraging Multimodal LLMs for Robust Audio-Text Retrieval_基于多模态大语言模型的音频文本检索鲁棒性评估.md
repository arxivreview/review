# ACL2026最新论文 ｜Omni-Embed-Audio: Leveraging Multimodal LLMs for Robust Audio-Text Retrieval ｜基于多模态大语言模型的音频文本检索鲁棒性评估

作者：HaeJun Yoo、Yongseop Shin、Insung Lee 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.18360)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_88bff5491aec)

音频文本检索旨在通过自然语言查询从海量音频库中定位目标片段，其核心挑战在于模型对真实用户查询意图的解析能力。现有基于对比语言-音频预训练（CLAP）的模型在标准字幕式查询上表现优异，但难以应对指令、否定等多样化真实查询，导致评估结果高估实际性能。本文提出 OmniEmbed-Audio (OEA)，利用多模态大语言模型（LLM）作为统一编码器，并引入用户意图查询（UIQ）基准，验证了 LLM 骨干在复杂语义判别上的优势，但其标准文本到音频检索性能仍落后于专用 CLAP 模型。

## 研究背景

当检索系统面对“寻找没有雷声的雨声”这类包含否定逻辑的查询时，传统双编码器架构往往将“没有雷声”误读为正向特征，导致检索失败。这种失效源于对比学习范式下的嵌入空间压缩机制：文本编码器将查询映射为单一向量，丢失了句法结构中的排除性语义。为保留这种结构信息，需要引入具备指令跟随能力的语言模型，但 LLM 通常缺乏针对检索任务的对比对齐训练，且其音频编码能力是否足以替代专用声学编码器尚存疑问。

音频文本检索的主流路线是 CLAP，通过大规模配对数据学习共享嵌入空间，代表工作如 M2D-CLAP 在 AudioCaps 上取得了 SOTA 性能。然而，现有基准（AudioCaps, Clotho）主要使用描述性字幕作为查询，与真实用户行为存在显著偏差：真实查询平均仅 1.8 个 token，且包含大量指令和否定形式。这种评估偏差掩盖了模型在复杂查询下的鲁棒性缺陷。本文切入点在于，利用预训练多模态 LLM 的统一骨干替代双编码器，假设其丰富的语言先验能更好地解析复杂查询，同时构建 UIQ 基准以系统评估这种鲁棒性。

## 核心方法

### 统一编码器架构

标准 CLAP 流程使用独立的音频和文本编码器，分别提取特征后通过投影层对齐。本文的关键差异在于使用单一共享的多模态 LLM 骨干处理两种模态，旨在减少模态间隙并利用 LLM 的语言先验。文本查询添加 `query:` 前缀，音频波形通过原生音频编码器处理并添加 `passage:` 前缀，两者均通过 Transformer 后取最后一层隐藏状态的均值池化。

### LoRA 适配与对比训练

为在冻结骨干上实现检索能力，本文采用低秩适配（LoRA）技术，仅在注意力层引入轻量级适配器矩阵，并训练模态特定的投影头将表示映射到 512 维共享空间。训练目标为对称 InfoNCE 损失，温度系数 $\tau = 0.07$。

$$ \mathcal{L} = -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp(\text{sim}(a_i, t_i) / \tau)}{\sum_{j=1}^{N} \exp(\text{sim}(a_i, t_j) / \tau)} $$

该公式通过最大化匹配对相似度、最小化不匹配对相似度，迫使共享 LLM 骨干在冻结状态下学习音频-文本对齐。设计动机在于解决标准 LLM 缺乏检索特定对比信号的问题，同时通过 LoRA 限制可训练参数（约 11-16M），避免灾难性遗忘。

### 硬负样本判别指标

标准 R@k 指标仅检查目标是否被检索，无法衡量模型对声学相似但语义不同干扰项的抑制能力。本文提出硬负样本抑制率（HNSR@k），定义为在 top-k 中检索到目标且硬负样本排名在 top-k 之外的查询比例。

$$ \text{HNSR@k} = \frac{1}{N} \sum_{i=1}^{N} \mathbb{I}(\text{Rank}(t_i) \le k \land \text{Rank}(hn_i) > k) $$

其中 $hn_i$ 为针对目标 $t_i$ 挖掘的硬负样本。该指标直接量化了模型在排除性查询下的细粒度语义判别能力，弥补了传统指标在否定逻辑评估上的盲区。

## 实验评估

实验在 AudioCaps、Clotho 和 MECAT 上进行，基线覆盖 LAION-CLAP、Robust-CLAP、MGA-CLAP 和 M2D-CLAP，以及未训练的 Qwen2.5-Omni 和 Nemotron-3B。OEA 在标准文本到音频（T2A）检索上未超越 M2D-CLAP，但在文本到文本（T2T）检索和硬负样本判别上表现显著。

| 模型 | AudioCaps R@5 | Clotho R@10 | MECAT R@5 | Avg UIQ | Hard Neg. (HNSR@10) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| M2D-CLAP | 77.13 | 74.76 | 23.55 | 47.76 | 30.3 |
| OEA-Qwen7B (+Cl) | 67.47 | 62.70 | 22.94 | 47.16 | 34.6 |
| OEA-Qwen3B (+Cl) | 69.35 | 63.25 | 17.16 | 47.18 | 32.8 |

OEA-Qwen7B (+Cl) 在 HNSR@10 上达到 34.6%，较 M2D-CLAP 的 30.3% 提升 4.3 个百分点，表明 LLM 骨干在否定查询判别上的优势。在 T2T 检索中，OEA 在 Clotho 上 R@1 达 64.52%，较 M2D-CLAP 的 55.85% 提升 8.67 个百分点。消融实验显示，添加 Clotho 训练（+Cl）在 Clotho 数据集上带来显著提升，但在 AudioCaps 上略有下降，暗示领域特定数据存在迁移效应。

评估边界方面，MECAT 数据集用于无泄漏评估，但使用自动生成的字幕，噪声可能影响结果。论文未报告计算效率指标，且 UIQ 基准的生成依赖 GPT-5.1，可能存在生成偏差。代码未公开，仅提供 Web Demo，限制了复现性。

## 关联研究分析

从问题动机看，RobustCLAP 通过多视图对比学习提升对释义查询的鲁棒性，但仅针对词汇变化，未涉及句法结构如否定。OEA 利用 LLM 的指令跟随能力，从语义层面解析否定逻辑，这是双编码器架构难以实现的。差异根源在于任务特性：否定查询需要组合语义理解，而非简单的词汇匹配。

从方法设计看，M2D-CLAP 结合自监督掩码建模与对比学习，优化通用表示，但在否定查询上 HNSR@10 仅为 30.3%。OEA 使用统一 LLM 骨干，虽然 T2A 性能略低，但在复杂查询判别上显著优于 M2D-CLAP。这暗示 LLM 的语言先验在语义判别上优于专用声学编码器的对比对齐，但音频编码能力可能限制了其在标准检索任务上的表现。

## 总结

本文核心矛盾在于现有 CLAP 模型在真实多样化查询下的鲁棒性不足。切入点在于利用多模态 LLM 的统一骨干保留句法结构，并通过 UIQ 基准系统评估。方法上，OEA 采用 LoRA 适配冻结 LLM 骨干，提出 HNSR 指标量化否定判别能力。实验证明 OEA 在硬负样本判别上较 M2D-CLAP 提升 4.3 个百分点，T2T 检索提升 8.67 个百分点。边界在于标准 T2A 检索性能仍落后于 M2D-CLAP，且依赖自动生成的 MECAT 数据。当 LLM 骨干的音频编码能力增强后，其在标准检索任务上能否超越专用 CLAP 模型，论文未给出回答。
