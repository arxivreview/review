> 城市交通系统面临交通流预测、充电需求预估与出租车调度等异构任务，传统深度学习模型因任务特定性导致知识无法跨域迁移，而现成大语言模型（LLM）受限于离散化机制，难以保真处理连续时空信号。TransLLM 通过噪声增强时空编码器将结构化信号映射至 LLM 嵌入空间，并引入基于强化学习的实例级提示路由机制，动态组合提示以适配样本差异。该框架在七个数据集上验证了从回归到规划任务的统一建模能力，但其 RL 路由在复杂动态场景下的泛化边界尚待进一步量化。

## 研究背景

交通预测的核心困境在于数据的多模态异构性与模型接口的单一性。时空依赖建模要求捕捉路网拓扑与时间序列的非线性耦合，传统图神经网络（GNN）虽能处理空间结构，但缺乏对非结构化上下文（如天气、事件文本）的语义理解能力。当引入 LLM 以整合语义信息时，连续数值信号必须经过离散化或分词（Tokenization）处理，这一过程导致数值保真度下降，即“分词失配”（Tokenization Mismatch），使得 LLM 难以精确建模细粒度的时空动态。

现有 LLM 交通预测方法多采用固定提示模板或简单的任务特定编码器，如 UrbanGPT 使用专用时间序列编码器增强 LLM，LLMLight 依赖模仿学习进行信号选择。然而，固定模板无法适应同一任务内不同区域、时段或上下文引发的样本级变异，且现有设计主要局限于简单的回归或分类任务，难以扩展至出租车调度等规划问题。TransLLM 的切入点在于解决“结构化时空信号与 LLM 自然语言接口的保真度冲突”，同时通过可学习机制实现实例级自适应，从而在统一框架下支持多样化输出格式。

## 核心方法

### 方法参照系

本文问题属于 LLM 增强的时空预测范畴。标准流程通常将时空数据编码为特征向量，拼接至 LLM 输入，并通过固定提示引导推理。关键差异在于，TransLLM 不依赖 LLM 直接生成数值文本，而是将 LLM 视为推理引擎，通过专用输出头投影预测结果，并引入动态提示路由替代静态模板。

### 噪声增强时空依赖建模

为克服 LLM 对连续数值信号建模的保真度缺陷，TransLLM 设计了噪声增强时空编码器（ST-Encoder）。该编码器采用“三明治”结构，结合空洞时间卷积网络（TCN）与图注意力网络（GAT），并引入高斯噪声进行对比学习，以增强对传感器噪声的鲁棒性。编码器利用空间邻接矩阵 $A_{sp}$ 和基于动态时间规整（DTW）的语义矩阵 $A_{se}$ 生成双路表示，最终拼接为紧凑嵌入 $H_f$。

$$ H = \text{TCN}(\text{GAT}(\text{TCN}(X) + \phi(V), A)) $$

此公式表明，时空特征 $X$ 经过时间卷积提取时序模式后，通过图注意力捕捉空间依赖，节点属性 $\phi(V)$ 提供上下文，最终生成供 LLM 理解的紧凑表示。

### 基于强化学习的提示路由

针对固定提示无法适应样本级变异的问题，TransLLM 引入基于 Actor-Critic 强化学习的提示路由机制。提示池被划分为 $K$ 个功能槽位（如历史时空信息、时间上下文、时空编码、推理格式），每个槽位包含 $N_c$ 个候选句子。Actor 网络根据时空表示 $H_f$ 生成各槽位的概率分布 $\pi_k$，Critic 网络评估预期奖励 $V_k$。

$$ \pi_k = \text{Softmax}(\text{MLP}(H_f)), \quad V_k = \text{MLP}(H_f) $$

该机制允许模型根据当前样本特征（如高峰时段或异常事件）动态选择最合适的提示组合，而非使用统一模板。奖励信号 $\hat{R}$ 直接关联任务损失（如 MAE 或调度奖励），确保提示选择与预测性能对齐。

## 实验评估

实验在五个公开数据集（LargeSTSD, PEMS08, ST-EVCDP, UrbanEV, Taxi-SH）上进行，覆盖交通流、充电需求与出租车调度三类任务。基线涵盖 GNN 模型（STGCN, D2STGNN）、通用 LLM（GPT-5.2, Gemini-3）及时空基础模型（UrbanGPT, ST-LLM+）。由于论文正文未提供具体数值表格，仅能定性评估其相对性能。TransLLM 在多数基线上取得优势，特别是在零样本设置下展示了良好的泛化能力。

消融实验验证了噪声增强编码器与 RL 提示路由的贡献。移除噪声增强导致鲁棒性下降，表明对比学习对处理传感器噪声有效；固定提示替代 RL 路由导致性能显著降低，证实了实例级自适应的必要性。然而，论文未提供 RL 路由在不同动态场景（如极端天气）下的详细行为分析，也未量化路由决策的稳定性。

评估边界方面，指标涵盖 MAE、RMSE、MMR 与 MDD，但未报告计算效率（如推理延迟、内存占用），这对于 LLM 框架的实际部署至关重要。代码已开源，但超参数敏感性分析仅提及未详述，可能影响复现性。

## 关联研究分析

从问题动机看，TransLLM 与 UrbanGPT 均旨在融合 LLM 与时空数据，但 UrbanGPT 依赖固定提示与专用编码器，而 TransLLM 通过 RL 路由实现动态适配。这一差异源于任务复杂度的提升：UrbanGPT 主要处理回归任务，而 TransLLM 扩展至规划任务，固定模板难以覆盖规划任务中的多样化决策情境。从方法设计看，TransLLM 与 ST-LLM+ 同属 LLM 增强路线，但 ST-LLM+ 侧重重编程技术将时序映射为文本 Token，TransLLM 则通过嵌入投影避免离散化损失。这种设计选择暗示，在需要高精度数值预测的场景中，保留连续嵌入可能比文本化更具优势，但 LLM 的语义推理能力是否因缺乏文本交互而削弱，论文未给出明确回答。

## 总结

TransLLM 解决了异构时空输入与 LLM 自然语言接口之间的保真度冲突，通过噪声增强编码器与 RL 提示路由实现了多任务统一建模。实验证明其在七个数据集上优于多数基线，特别是在零样本设置下展示了泛化能力。然而，论文未报告计算效率指标，且 RL 路由在极端动态场景下的稳定性未充分验证。当支持集增大或场景复杂度提升时，RL 路由的边际收益是否递减，论文未给出回答。
