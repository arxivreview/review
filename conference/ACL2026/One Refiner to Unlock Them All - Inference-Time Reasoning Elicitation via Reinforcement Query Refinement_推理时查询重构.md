# ACL2026最新论文 ｜One Refiner to Unlock Them All: Inference-Time Reasoning Elicitation via Reinforcement Query Refinement ｜推理时查询重构

研究机构：浙江大学、东南大学

作者：Yixiao Zhou、Dongzhou Cheng、Zhiliang wu 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_f0f0f181e290)

> 大语言模型（LLM）在复杂推理任务中常因输入表述的模糊性而未能激活其潜在推理能力，现有对齐方法要么通过微调每个模型产生 O(N) 的高昂成本，要么依赖静态提示词无法解决查询层面的结构复杂性。ReQueR 将推理激发重构为推理时的输入对齐任务，通过强化学习训练一个通用的 Refiner 策略，将模糊的人类查询重写为显式的逻辑分解，从而在不更新下游 Solver 参数的前提下解锁其推理潜力。该框架在多种架构上实现了 1.7%–7.2% 的绝对性能提升，但其性能上限仍受限于 Solver 的预训练权重，且仅适用于具有可验证答案的任务。

## 研究背景

当 LLM 面对模糊的自然语言查询时，其内部推理引擎往往无法被有效激活，这种现象源于人类意图与机器逻辑之间的分布失配。为弥合这一差距，监督微调（SFT）和基于可验证奖励的强化学习（RLVR）通过修改模型内部权重来对齐偏好，但在代理系统中模型频繁更换，导致对齐 N 个模型需要 N 次独立训练，产生 O(N) 的复杂度。此外，自动化提示优化（APO）如 TextGrad 和 OPRO 虽轻量，但通常作为静态包装器，仅附加浅层指令，缺乏针对每个样本进行深度逻辑重构的能力，且易过拟合特定模型或数据集。

主流路线的瓶颈在于无法在推理时提供通用的、实例级的解决方案。ReQueR 的切入点是将对齐负担从参数更新转移到输入优化，提出 O(1) 的推理时范式。它不针对特定模型微调，而是训练一个统一的元策略（Meta-policy），通过强化学习让 Refiner 学习将任意查询转化为结构化逻辑，从而在冻结的 Solver 上实现跨架构的推理激发。

## 核心方法

### 方法参照系

ReQueR 属于测试时推理增强路线，但区别于 LTPO 等优化潜在向量的方法，它优化的是文本查询本身。与标准 RLVR 流程优化模型权重不同，ReQueR 将 Solver 视为环境，优化 Refiner 的输入分布以匹配 Solver 的内在推理触发器。

### 自适应求解器层级（ASH）

ASH 机制位于 Refiner 与 Solver 的交互环节，解决了静态训练环境导致的奖励稀疏问题。通常做法是固定一个 Solver 进行训练，但能力过弱或过强的 Solver 均无法提供有效反馈。ASH 基于最近发展区（ZPD）理论，维护一个能力各异的 Solver 池，根据 Refiner 当前能力动态匹配 Solver 难度。其核心目标函数为：

$$ \max_{\theta} \mathbb{E}_{(x,y^*) \sim D} \left[ \mathbb{E}_{M \in S} \left[ R(y^*, M(\pi_\theta(x))) \right] \right] $$

其中 $S$ 由 ASH 动态管理。当 Refiner 持续失败时，ASH 升级 Solver 难度；当成功变得平凡时，降低难度。这种动态调整确保了 Refiner 始终处于最优成长区，维持了密集的奖励信号，避免了模型特定偏见的过拟合。

### 困惑度泄露约束

为抑制奖励黑客（即 Refiner 将答案直接泄露到查询中），ReQueR 引入了基于困惑度（PPL）的约束。该约束通过单次前向传播检测潜在泄露，计算原始查询与重构查询下答案的困惑度比值：

$$ R_{leak} = \mathbb{I} \left[ \frac{PPL(y^*|x)}{PPL(y^*|x') + \epsilon} > \tau_{leak} \right] $$

若比值超过阈值 $\tau_{leak}$（设为 5.0），则施加惩罚。这一机制比生成式 LLM 裁判更稳定且计算成本低，迫使 Refiner 优先进行结构消歧而非表面线索泄露，确保激发的是真实的潜在推理能力。

## 实验评估

ReQueR 在 GSM8K 和 MATH 的 2,048 个样本上训练，并在 MATH-500、GSM-Symbolic 等七个基准上评估。基线包括 TextGrad、GEPA、RaR 等 APO 方法，但缺失 DeepSeek-R1 等 SOTA RLVR 模型的直接对比，因为后者涉及参数更新。

| 方法 | MATH-500 | GSM-Plus | Avg. |
| :--- | :--- | :--- | :--- |
| Zero-shot CoT | 64.20 | 43.80 | 45.43 |
| TextGrad | 72.40 | 44.05 | 46.68 |
| GEPA | 73.60 | 45.32 | 47.28 |
| ReQueR | 77.60 | 46.09 | 49.38 |

ReQueR 在 MATH-500 上以 77.60% 的准确率领先，较最强基线 GEPA 提升 4.0 个百分点，验证了 RL 驱动的重构比静态优化更鲁棒。

消融实验显示，ASH 是训练稳定性的关键组件。移除 ASH 后，Llama-3.1-8B-Instruct 在 MATH-500 上的性能从 54.00% 降至 48.15%，下降 5.85 个百分点，表明动态难度匹配对维持最优能力-难度平衡至关重要。泄露惩罚的移除导致 Qwen3-0.6B 在 GSM-Plus 上下降 2.15 个百分点，证实了其对防止奖励黑客的有效性。

评估边界方面，ReQueR 仅适用于具有可验证答案的任务，无法处理开放式生成。其性能提升部分源于 Solver 效率的提升，重构查询使响应长度缩短 4.8%–17.3%。代码已开源，超参数详细列出，但实验仅在 8 块 H100 GPU 上进行，大规模集群下的可扩展性未验证。

## 关联研究分析

从问题动机看，ReQueR 与 ZPD-Guided Synthesis 均利用 ZPD 理论，但前者用于动态选择 Solver 以稳定 RL 训练，后者用于合成数据以调整任务难度。ReQueR 的 ASH 机制更侧重于推理时的环境动态性，而 ZPD-Guided Synthesis 侧重于训练数据的静态分布。这种差异源于 ReQueR 旨在解决推理时的泛化问题，而 ZPD-Guided Synthesis 旨在解决训练时的数据稀缺问题。

从方法设计看，ReQueR 与 LTPO 同属测试时增强，但 LTPO 优化潜在向量，ReQueR 优化文本查询。LTPO 依赖于潜在空间的可微分性，适用于有明确奖励信号的任务，而 ReQueR 通过文本重构实现了更高的透明性和可解释性。ReQueR 的 O(1) 范式意味着一次训练即可应用于多个模型，而 LTPO 通常需要针对每个任务进行优化。这种差异表明，文本层面的重构可能在跨架构泛化上更具优势，但其在复杂逻辑任务上的深度探索能力是否优于潜在空间优化，论文未给出回答。

## 总结

ReQueR 旨在解决 LLM 推理能力因输入模糊性而未被激活的问题，现有方法因 O(N) 微调成本或静态提示的局限性而失效。ReQueR 通过训练一个通用的 Refiner 策略，利用 ASH 动态调整 Solver 难度并引入困惑度约束防止泄露，实现了 O(1) 的推理时对齐。实验证明其在 MATH-500 上较最强基线提升 4.0 个百分点，并在多种架构上实现 1.7%–7.2% 的绝对增益。然而，ReQueR 的性能上限受限于 Solver 的预训练权重，且仅适用于可验证任务。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
