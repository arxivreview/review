# ACL2026最新论文 ｜Don't Click That: Teaching Web Agents to Resist Deceptive Interfaces ｜欺骗性UI防御与评估校准

研究机构：中国人民大学

作者：Yilin Zhang、Yingkai Hua、Chunyu Wei 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.09497)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.09497)

> 视觉语言模型驱动的Web智能体在真实网页中极易被暗模式（Dark Patterns）诱导执行错误操作，现有检测工具缺乏任务语义整合，而简单拒绝策略又导致良性任务失败。本文提出DUDE框架，通过混合奖励学习校准评估器置信度，并结合经验总结实现无参数更新的防御增强。该方案在自建基准上显著降低欺骗率，但其对动态交互环境的适应性及跨基准泛化能力仍存疑。

## 研究背景

当智能体面对包含虚假下载链接或误导性弹窗的网页时，其视觉定位能力虽能准确识别UI元素，却缺乏判断元素意图是否恶意的机制。这种“感知接地”与“意图判断”的脱节，导致智能体将欺骗性元素视为正常交互目标。为解决此问题，需引入一个独立的评估环节，在动作执行前对点击坐标进行安全性与有效性校验，这构成了欺骗感知防御的核心逻辑。

Web智能体领域长期关注任务成功率，但真实网络环境中的对抗性设计使得基准测试表现与部署可靠性存在巨大鸿沟。主流防御路线分为两类：一是任务无关的检测器，如UIGuard，能识别暗模式但无法结合具体任务上下文；二是系统级沙箱，如ceLLMate，通过权限隔离限制风险但牺牲了智能体灵活性。现有方法未能解决“如何在保持任务执行能力的同时，精准区分良性与恶意交互”这一核心矛盾。本文切入点在于将防御视为一个校准问题，通过强化学习赋予智能体类似人类经验积累的“风险感知”能力，而非简单的规则匹配或权限封锁。

## 核心方法

### 方法参照系

本文问题可置于“智能体动作评估”通用框架下，标准流程为：感知UI状态→生成候选动作→执行动作。关键差异在于，本文在生成与执行之间插入一个基于视觉-语言模型的评估器（Evaluator），该评估器不仅判断动作是否有效，还专门针对欺骗性元素进行二元分类，从而将防御逻辑内嵌于决策闭环中。

### 混合奖励学习校准

针对评估器易陷入“过度保守”或“盲目乐观”的失效模式，本文设计非对称惩罚机制。传统奖励函数对误报（将良性判为恶意）与漏报（将恶意判为良性）同等对待，导致评估器倾向于保守以规避风险。本文引入严重度权重 $\omega$，对漏报恶意点击施加极高惩罚，公式如下：

$$ R = \mathbb{1}[\hat{L}=L] - \alpha \cdot \omega(L, \hat{L}) \cdot (1-\gamma) $$

其中 $\gamma$ 为置信度，$\alpha$ 为注意力标量。该公式的物理含义是：当评估器错误地批准恶意点击（C4类错误）时，$\omega$ 取最大值10，迫使模型在不确定时倾向于拒绝，但在明确良性时保持高置信度，从而校准其风险判断边界。

### 经验总结与迭代蒸馏

混合奖励学习虽能提升单次判断准确率，但无法跨任务积累防御知识。为解决此局限，本文引入经验总结模块，将失败案例蒸馏为紧凑的上下文指导。该过程通过迭代采样失败池 $F$ 与成功池 $S$，利用多模态总结器生成经验上下文 $X$，公式表达为：

$$ X_{t} = \text{SUMMARIZE}(B_f, X_{t-1}) $$

其中 $B_f$ 为当前迭代的失败样本批次。这一设计的动机在于，参数更新成本高昂且难以实时部署，而经验总结允许智能体在不修改模型权重的情况下，通过上下文注入获得对特定欺骗模式的“免疫记忆”，实现部署时的渐进式改进。

## 实验评估

实验在自建RUC基准上进行，该基准包含1,407个场景，覆盖新闻、预订、购物和软件四个领域。基线对比仅包含无防御的Vanilla智能体与简单拒绝策略，缺失WebSentinel等专用防御基线，限制了横向比较的充分性。

| 设置 | SR (%) | DFR (%) | Steps |
| :--- | :--- | :--- | :--- |
| Vanilla Agent | 6.50 | 2.00 | 25.23 |
| + Stage-1 Only | 28.00 | 5.50 | 5.80 |
| + Stage-2 Only | 15.50 | 4.50 | 5.50 |
| + Stage-1 + Stage-2 | 33.50 | 0 | 5.86 |

消融实验揭示了一个反直觉现象：单独使用Stage-1或Stage-2均会导致DFR轻微上升（分别至5.5%和4.5%），而两者结合后DFR降至0。这表明视觉接地（Stage-1）与行为约束（Stage-2）存在互补关系，单一模块无法独立解决欺骗防御问题。

| 变体 | Eval Pass (%) | Fatal Error (%) |
| :--- | :--- | :--- |
| Full Reward | 55.9 | 9.75 |
| w/o Severity Weight | 51.4 | 27.53 |
| Only Confidence | 55.3 | 12.37 |

移除严重度权重导致致命错误率翻倍，验证了非对称惩罚设计的必要性。评估边界方面，RUC基准基于静态截图，未验证动态异步交互环境下的鲁棒性；代码与数据已公开，但超参数配置细节有限，可复现性依赖社区验证。

## 关联研究分析

从问题动机看，DUDE与WebSentinel均利用LLM语义理解检测异常，但WebSentinel侧重页面整体意图分析，而DUDE聚焦于点击行为层面的细粒度评估。这一差异源于任务特性：WebSentinel处理的是页面级安全，而DUDE处理的是交互级风险，后者对实时性要求更高，因此采用了更轻量的评估器架构。

从方法设计看，DUDE与ceLLMate同属系统级防御路线，但ceLLMate依赖外部沙箱权限控制，DUDE则依赖模型内评估。ceLLMate的优势在于硬性安全边界，但可能限制智能体灵活性；DUDE的优势在于保持任务执行能力，但依赖模型对齐质量。这种差异暗示了安全防御的两种范式：外部约束与内部校准，前者更稳健但僵化，后者更灵活但易受模型偏差影响。

## 总结

本文核心矛盾在于Web智能体在真实网络中缺乏对欺骗性UI的意图判断能力，导致任务成功率与安全性无法兼得。DUDE通过混合奖励学习校准评估器置信度，并结合经验总结实现无参数更新的防御增强，在RUC基准上将DFR降至0，同时保持SR在33.5%。其边界在于评估基于静态截图，未验证动态交互环境下的鲁棒性，且缺乏与专用防御基线的横向对比。当智能体面对异步加载的动态UI时，经验总结模块能否实时适应新的欺骗模式，论文未给出回答。
