# ACL2026最新论文 ｜Why Do LLM-based Web Agents Fail? A Hierarchical Planning Perspective ｜分层规划视角下的LLM Web智能体失败归因

研究机构：美国乔治梅森大学

作者：Mohamed Aghzal、Gregory J. Stein、Ziyu Yao

论文原文见 [arXiv](https://arxiv.org/abs/2603.14248)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.14248)

> 现有LLM Web智能体在真实动态网站上的可靠性远低于人类水平，但主流评估仅依赖端到端成功率，无法定位失败究竟源于任务理解偏差、高层策略错误还是底层执行偏差。本文切入点在于将智能体能力解耦为高层规划、低层执行与重规划三个独立维度，通过引入形式化表示与后条件检查机制实现过程级诊断。其核心做法是构建一个基于PDDL（Planning Domain Definition Language）的分层评估框架，在Mind2Web-Live基准上对三个主流LLM进行模块化测试。该框架揭示了低层执行是主要瓶颈，但受限于小模型骨干与单一文本输入，其结论的普适性存疑。

## 研究背景

Web智能体在长程任务中频繁失败，根源在于其决策过程是一个多维耦合系统：高层规划决定任务分解的合理性，低层执行负责将抽象子目标映射为具体的DOM操作，而重规划则处理环境偏离预期时的恢复。若仅观察最终成功率，无法区分是规划阶段遗漏了关键步骤，还是执行阶段未能准确定位UI元素。这种黑盒评估掩盖了故障的具体位置，阻碍了针对性优化。

自动化规划领域早已确立分层架构的必要性，将复杂任务分解为抽象目标与具体动作序列。然而，现有Web智能体评估多采用轨迹匹配或LLM-as-Judge对最终状态进行整体判断，缺乏对中间过程的细粒度验证。Mind2Web-Live等基准虽提供了真实环境，但其评估协议仍停留在端到端层面，无法揭示智能体在特定步骤上的能力短板。本文旨在通过引入结构化规划语言与后条件检查，将评估粒度从“任务是否完成”细化到“每个子目标是否达成”，从而建立故障归因的坐标系。

## 核心方法

### 分层规划参照系

传统Web智能体评估通常将LLM视为黑盒，输入指令与网页状态，输出动作序列，最终通过规则或LLM判断任务成败。这种流程忽略了智能体内部的能力分层，导致无法区分规划错误与执行错误。本文的关键差异在于显式引入后条件检查器（Postcondition Checker），将执行过程切分为多个可验证的子目标单元，使评估能够定位到具体的能力层级。

### PDDL结构化高层规划

高层规划环节通常由LLM直接生成自然语言子目标，但自然语言缺乏显式的约束结构，易产生过度细化或遗漏。本文引入PDDL作为高层规划的形式化表示，强制LLM在生成子目标时明确前置条件与后置效果。设高层计划为 $P = [g_1, g_2, \dots, g_n]$，其中每个子目标 $g_i$ 在PDDL中定义为包含参数、前置条件与效果的谓词逻辑表达式。这种符号约束迫使LLM生成更简洁、目标导向的计划，减少了自然语言中常见的冗余步骤与模糊表述，从而为后续执行提供更稳定的基础。

### 后条件检查与重规划触发

低层执行后，智能体需判断子目标是否达成。传统方法依赖LLM对最终状态的语义判断，缺乏中间反馈。本文引入后条件检查器，基于当前状态 $s'$ 与子目标 $g_i$ 的后置条件，计算满足度 $\Phi(g_i, s')$。若 $\Phi(g_i, s') = 0$，则触发重规划机制。重规划分为局部调整（从最后成功子目标继续）与全局重规划（丢弃原计划重新生成）。本文仅评估单轮重规划，通过对比重规划前后的子目标完成率与任务成功率，量化重规划对提升可靠性的贡献。

## 实验评估

实验基于Mind2Web-Live测试集（104个实例），使用gpt-5-nano、claude-haiku-4.5与gemini-flash-2.5三个模型。基线包括人类标注计划、自然语言（NL）计划与PDDL计划，但未与Branch-and-Browse等SOTA架构直接对比，因本文聚焦能力诊断而非性能刷榜。

| 计划表示 | 子目标完成率 (%) | 计划完成率 (%) | 任务成功率 (%) |
| :--- | :--- | :--- | :--- |
| Human | 69.7 | 38.5 | 36.4 |
| NL | 63.2 | 34.6 | 32.1 |
| PDDL | 70.3 | 37.5 | 35.6 |

数据显示，PDDL计划在子目标完成率上略优于人类计划（70.3% vs 69.7%），但任务成功率仍低于人类（35.6% vs 36.4%）。重规划后，NL与PDDL计划的子目标完成率分别提升至84.0%与81.4%，任务成功率提升至41.4%与45.1%，表明单轮重规划能显著改善执行表现。

消融分析显示，低层执行是主要瓶颈。即使提供人类标注的高层计划，gpt-5-nano的计划完成率仅为38.5%。失败模式分析表明，34.2%的动作冗余源于状态理解不足，32.0%的goto动作指向不存在的链接，10.4%的失败由重复动作导致。这些错误集中在感知接地与控制层面，而非规划层面。

评估边界方面，本文使用文本DOM表示，未引入视觉模态，可能低估了多模态智能体的执行能力。104个样本的规模较小，统计显著性有限。代码未公开，超参数与提示词细节仅在附录中部分披露，可复现性受限。

## 关联研究分析

从问题动机看，本文与WebDART（Yang et al., 2025）均关注长程任务中的性能崩溃，但WebDART通过动态分解与重规划提升鲁棒性，而本文通过分层评估诊断崩溃原因。WebDART的机制是本文发现的方法论延伸，但本文未验证动态分解是否优于静态PDDL计划。从方法设计看，本文与Branch-and-Browse（He et al., 2025）形成互补：Branch-and-Browse通过树结构回溯解决执行僵化，本文则通过PDDL与后条件检查定位僵化根源。Branch-and-Browse的架构改进可能缓解本文发现的重复动作问题，但本文未测试该架构在分层评估下的表现。

## 总结

本文核心矛盾在于端到端评估无法归因LLM Web智能体的失败。其切入点在于引入PDDL形式化约束与后条件检查，将评估粒度细化至子目标层级。实验证明PDDL计划更简洁，单轮重规划可提升任务成功率至45.1%，但低层执行仍是瓶颈，34.2%的动作冗余暴露了状态理解的不足。本文边界在于仅使用文本DOM与小模型，未验证多模态输入或大模型骨干下的结论是否成立。当支持集增大或引入视觉模态时，低层执行的瓶颈是否会被缓解，论文未给出回答。
