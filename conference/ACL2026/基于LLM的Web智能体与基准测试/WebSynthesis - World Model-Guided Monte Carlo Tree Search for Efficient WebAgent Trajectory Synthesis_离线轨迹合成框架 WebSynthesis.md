# ACL2026最新论文 ｜WebSynthesis: World Model-Guided Monte Carlo Tree Search for Efficient WebAgent Trajectory Synthesis ｜离线轨迹合成框架 WebSynthesis

研究机构：北京交通大学、新加坡南洋理工大学

作者：Yifei Gao、Junhong Ye、Yifan Yang 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_c9b7e8b56498)

> 大语言模型（LLM）驱动的 Web 智能体训练长期受限于高质量交互轨迹获取的高昂成本与真实环境动作不可逆导致的探索局限。现有方法依赖实时网络请求或线性采样，难以兼顾数据规模与多样性。WebSynthesis 通过构建基于 LLM 的世界模型（LWM）模拟状态转移，并引入蒙特卡洛树搜索（MCTS）实现可回溯的离线探索，从而生成高覆盖率的训练数据。该框架在纯监督微调（SFT）设定下验证了合成数据的有效性，但其对世界模型预测精度的依赖及仅采用 SFT 的训练范式，限制了其在复杂推理任务上的上限。

## 研究背景

Web 智能体在开放网络中执行多步任务时，面临状态空间巨大且动态变化的挑战。为了在有限步骤内最大化累积奖励，智能体需在部分可观测马尔可夫决策过程（POMDP）框架下，基于当前观测 $o_t$ 和指令 $q$ 生成动作 $a_t$。然而，真实网页环境的交互具有不可逆性，一旦执行点击或输入，状态变更无法回滚，这直接阻断了基于树搜索的系统性探索路径，迫使现有方法局限于低多样性的线性采样策略。

该领域的主流数据获取路线存在显著瓶颈。基于真实环境交互的方法（如 OS-Genesis）受限于网络不稳定性和网站反爬机制，基础设施开销巨大且难以规模化；基于教程或规则生成的方法（如 AgentTrek）则覆盖场景有限，缺乏对错误恢复路径的建模。WebSynthesis 的切入点在于将“环境模拟”与“搜索策略”解耦：利用 LLM 预测网页结构状态以消除网络依赖，再利用 MCTS 在模拟环境中实现分支与回溯，从而在离线条件下生成包含成功与失败恢复路径的高多样性轨迹。

## 核心方法

### 方法参照系

本文问题归属于 Web 智能体数据合成路线。与直接生成文本轨迹或依赖真实环境采集不同，WebSynthesis 的核心差异在于引入一个可学习的状态转移函数，将不可逆的真实环境转化为可逆的模拟环境，使得树搜索算法能够应用于轨迹生成。

### 基于 LLM 的世界模型

传统世界模型（如 WebDreamer）仅预测动作结果，无法准确捕捉网页结构的细微变化，限制了多步决策的可靠性。WebSynthesis 将网页表示为无障碍树（A11y），训练 LWM 预测动作执行后的完整 A11y 结构。其目标函数定义为状态转移预测：

$$ o_t = w(o_{t-1}, a_t) $$

该公式表明，世界模型 $w$ 接收前一状态 $o_{t-1}$ 和动作 $a_t$，输出预测的下一状态 $o_t$。通过显式建模结构信息，LWM 能够支持 MCTS 在长程任务中连续响应策略模型的动作请求，解决了早期方法因结构预测缺失导致的搜索中断问题。

### MCTS 引导的轨迹生成

LWM 的可逆性使得 MCTS 成为可能。WebMCTS 通过节点选择、动作扩展和回溯传播三个阶段构建搜索树。节点选择采用上置信界（UCB）策略平衡探索与利用：

$$ UC = v_C + \epsilon \cdot \sqrt{\frac{\ln n_P}{n_C}} $$

其中 $v_C$ 为节点估计值，$n_P$ 和 $n_C$ 分别为父节点和当前节点的访问次数，$\epsilon$ 控制探索强度。该机制允许智能体在模拟环境中自由回溯并尝试替代路径，生成包含“成功轨迹”与“回滚轨迹”的混合数据。回滚轨迹通过识别失败分支并构造 $S \to P \to C$ 路径，显式教会智能体识别错误并执行 `go_back` 操作，弥补了真实数据中错误恢复样本的稀缺。

## 实验评估

实验在 WebArena、WebVoyager 和 Mind2Web-Online 三个在线基准上进行，基线包括零样本提示（GPT-4, Qwen2.5-7B）、真实数据训练（OS-Genesis）和教程数据训练（AgentTrek）。值得注意的是，本文未对比其他基于世界模型的方法（如 WebEvolver），且所有方法均使用文本状态表示，未涉及多模态输入。

| 方法 | WebArena Pass@1 (%) | WebArena Pass@3 (%) | WebVoyager Avg (%) | Mind2Web-Online Avg (%) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-4 | 13.58 | - | 35.71 | 11.36 |
| OS-Genesis | 11.19 | 18.66 | 31.40 | 12.50 |
| AgentTrek | 9.70 | 11.94 | 14.57 | - |
| WebSynthesis-14B | 17.28 | 28.34 | 39.29 | 31.82 |

WebSynthesis-14B 在 WebArena Pass@3 上达到 28.34%，显著优于 OS-Genesis 的 18.66%；在 WebVoyager 和 Mind2Web-Online 上分别取得 39.29% 和 31.82% 的平均成功率，领先 OS-Genesis 7.89 和 19.32 个百分点。Pass@1 到 Pass@3 的提升幅度（+11.06%）大于基线，表明合成数据扩展了智能体的能力边界。

消融实验揭示了组件贡献的关键差异。仅使用回滚轨迹训练导致性能骤降至 2.4%，因为智能体缺乏正向目标导向，过度依赖 `go_back` 动作；仅使用成功轨迹训练得 9.6%，缺乏鲁棒性。结合两者提升至 15.6%，而加入 UI 理解预训练阶段后达到 24.1%。世界模型预测质量分析显示，在 5 步深度下，WebMCTS 通过树搜索筛选高质量状态，维持 38.66% 的结构正确率，远高于直接 SFT 模型的 12.09% 和 GPT-4 提示的 4.81%，验证了搜索机制对误差累积的抑制作用。

评估协议依赖 LLM-as-judge 和字符串匹配，缺乏对中间推理步骤的细粒度评估。代码已开源，但未报告计算效率指标（如推理延迟或内存占用），且世界模型训练需预先采集约 7.9k 条真实轨迹作为种子，这限制了其“完全离线”的宣称纯度。

## 关联研究分析

从问题动机看，WebSynthesis 与 OS-Genesis 均旨在解决数据稀缺问题，但 OS-Genesis 依赖真实环境交互，受限于基础设施开销和动作不可逆性，导致轨迹多样性低。WebSynthesis 通过 LWM 模拟环境，突破了这一物理限制，但其代价是引入了预测误差。与 WebEvolver 相比，后者侧重策略模型与世界模型的共进化以提升决策精度，而 WebSynthesis 侧重利用世界模型生成训练数据，两者在“世界模型用途”上存在根本分歧：前者用于在线决策辅助，后者用于离线数据合成。

从方法设计看，WebSynthesis 的 MCTS 引入解决了线性采样覆盖不足的问题，但其节点选择依赖 UCB 策略，假设奖励信号可靠。然而，Web 环境中奖励模型（Reward Model）的准确性直接影响搜索方向，实验显示替换奖励模型为 Qwen2.5-72B 后性能下降至 13.9%，表明搜索质量对奖励信号敏感。这与基于强化学习（RL）的方法（如 WebRL）形成对比，后者通过直接优化策略避免了对中间奖励模型的依赖，但 WebSynthesis 的 SFT 范式更易于部署且无需在线交互，这种取舍在数据充足但计算资源受限的场景下更具优势。

## 总结

WebSynthesis 针对 Web 智能体训练数据获取的高成本与探索局限，提出通过 LLM 世界模型模拟环境并结合 MCTS 进行离线轨迹合成的框架。该方法在 WebArena 和 WebVoyager 上证明了合成数据可超越真实数据基线，核心优势在于通过树搜索生成包含错误恢复路径的高多样性轨迹。然而，其性能受限于世界模型的预测精度，且在 5 步深度后结构正确率仍降至 38.66%，表明长程任务中的误差累积仍是主要瓶颈。此外，仅采用 SFT 训练范式，未探索 RL 或混合训练策略，可能限制了模型在复杂推理任务上的上限。当世界模型预测误差随任务深度增加而累积时，MCTS 的搜索效率是否会因噪声过大而退化，论文未给出定量分析。
