# ACL2026最新论文 ｜SynthAgent: Adapting Web Agents with Synthetic Supervision ｜合成监督下的Web智能体环境适应

研究机构：美国普渡大学

作者：Zhaoyang Wang、Yiming Liang、Xuchao Zhang 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2511.06101)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2511.06101)

> Web智能体在新环境中因缺乏特定任务演示而难以泛化，现有合成数据方法要么任务幻觉严重，要么轨迹噪声过大。SynthAgent通过“分类探索”与“任务-轨迹双重精炼”机制，在无需人工标注的情况下生成高质量监督数据。该方法在WebArena上以7B开源模型达到31.67%成功率，优于其他合成基线，但其绝对性能仍显著低于基于更强骨干或强化学习的SOTA方法，且数据规模扩展的边际收益尚未完全揭示。

## 研究背景

Web智能体在新网站部署时面临的核心困境是环境特异性数据的稀缺。智能体依赖多模态观察（DOM树与截图）执行动作，但新环境缺乏对应的任务-轨迹对，导致模型无法习得特定界面的交互模式。传统人工标注成本高且不可扩展，直接复用旧环境数据又因界面差异导致泛化失败。这一矛盾迫使研究转向合成数据生成，但合成过程本身引入了新的质量瓶颈：任务描述与真实界面状态不符（幻觉），或执行轨迹因任务变更而包含冗余与错位动作。

合成数据生成路线在解决数据稀缺问题上取得了进展，但现有方法普遍存在“单侧优化”缺陷。OS-Genesis（Sun et al., 2025）基于单步观察反向合成任务，虽保证了接地性，但上下文不足导致任务常引用不存在的元素；Explorer（Pahuja et al., 2025）在执行中连续精炼任务，虽解决了初始任务模糊问题，但频繁的任务意图变更导致轨迹早期段与最终目标错位，68.3%的轨迹因超步数预算而失败。SynthAgent的切入点在于识别出“任务接地”与“轨迹一致性”之间的设计张力：任务合成需要环境接地以避免幻觉，但执行中的激进接地会引入轨迹噪声。

## 核心方法

### 方法参照系

本文问题属于Web智能体合成监督数据生成范式。标准流程为：探索环境生成任务 → 执行任务收集轨迹 → 微调模型。关键差异在于，本文不将任务生成与轨迹收集视为独立阶段，而是引入在线任务精炼与离线轨迹精炼，以解决任务可行性与轨迹干净度之间的冲突。

### 分类探索与冲突触发式任务精炼

分类探索替代了随机元素采样，将页面交互元素按语义角色（如账户管理、搜索过滤）分组，每组均匀采样未访问元素，确保功能覆盖的多样性。任务精炼则采用冲突触发机制，仅在检测到任务与观察不一致时激活。设计动机是避免Explorer式连续精炼导致的任务意图漂移。冲突判定函数定义为：

$$ C(h_t, \tau_t) = \text{ExistsUI}(\tau_t, o_t) \lor \text{MissingArgs}(\tau_t, h_t) \lor \text{Stall}(h_t) $$

该公式物理含义为：当任务引用的UI元素缺失、关键参数无法从历史推断、或出现连续无进展/循环时，触发任务修正。修正遵循“具体化缺失细节、对齐观察、降维简化、保持类别”四原则，平均仅触发2.0次精炼，将超步数率从68.3%降至6.3%。

### 全局上下文轨迹精炼

任务精炼虽保证了任务可执行，但引入了轨迹噪声：早期步骤基于旧任务版本，与最终任务 $\tau^{[\star]}$ 不一致。轨迹精炼作为后处理步骤，利用全局上下文（最终任务与完整轨迹）进行离线编辑。设计动机是去除任务编辑导致的错位及智能体漫游产生的冗余动作。编辑操作包括删除（Remove）、重排（Reorder）、丢弃（Drop）与保留（Keep），由LLM基于 $(\tau^{[\star]}, h_T)$ 提议。重排仅应用于局部可交换步骤（如独立过滤与排序），占比仅4.1%，体现保守编辑策略。该步骤将轨迹质量评分从68.5提升至82.6（GPT-5.1评估），确保监督信号的纯净性。

## 实验评估

实验在WebArena（5个自托管网站）与Online-Mind2Web（136个实时网站）上进行，基线包括Self-Instruct、OS-Genesis与Explorer，均使用GPT-4.1合成数据，微调Qwen2.5-VL-7B-Instruct与UI-TARS-1.5-7B。缺失WebWorld等世界模型类基线及强化学习基线。

| 方法 | WebArena Avg. (Qwen2.5-VL) | Online-Mind2Web Avg. (Qwen3) |
| :--- | :--- | :--- |
| Self-Instruct | 16.78 | - |
| OS-Genesis | 16.62 | - |
| Explorer | 8.44 | - |
| SynthAgent | 31.67 | 24.34 |

SynthAgent在WebArena上以31.67%显著优于其他合成基线，但低于SFT上限（28.00%为GPT-4.1 judge下Qwen2.5-VL的SFT值，此处需注意表格中SFT行数据为28.00/18.67/27.00，Avg 16.90/6.49/19.48，实际SFT Avg为19.48，SynthAgent 31.67高于SFT？需核对原文：Table 1中SFT Avg为19.48，SynthAgent Avg为31.67，确实高于SFT。但原文文字称“SFT provides an informative upper bound”，此处存在矛盾，以表格数值为准，SynthAgent 31.67 > SFT 19.48。在Online-Mind2Web上，SynthAgent（24.34%）低于TGPO（38.4%）与Avenir-Web（48.0%），表明其泛化能力受限于7B骨干与合成数据规模。

| :--- | :--- | :--- |
| w/o CE | 3.54 | CMS下降7.01%，验证分类探索对功能覆盖的必要性 |

| w/o TR&JR | Shopping升/Maps降 | 证实TR与JR的协同性：TR引入噪声，JR后续清除 |

消融显示任务精炼（TR）贡献最大，移除后性能下降4.87%，表明任务可行性是合成数据质量的首要瓶颈。TR与JR的协同效应表现为：单独移除TR在Shopping上性能反升，但Maps下降，证实TR引入的噪声需JR清除，二者缺一不可。

评估边界方面，论文未报告置信区间，且不同judge（GPT-4.1/GPT-5.1/WebJudge）结果存在波动。代码已开源，但合成过程依赖GPT-4.1，未探索更廉价LLM的替代方案。数据扩展实验显示，从4%到100%数据量，成功率从10.6%升至20.8%，但边际收益递减趋势未量化。

## 关联研究分析

从问题动机看，SynthAgent与WebWorld（Xiao et al., 2026）均旨在解决新环境适应问题，但路线截然不同。WebWorld构建大规模世界模型模拟交互，支持离线训练，但面临预测误差累积导致的训练-测试差距；SynthAgent直接交互真实环境，保证接地性，但计算成本高且依赖实时环境可用性。SynthAgent未探索世界模型加速轨迹生成的可能性，其分类探索策略在静态快照中效率更高，但在动态实时网站中，URL池维护与元素状态同步的开销未充分讨论。

从方法设计看，SynthAgent与Branch-and-Browse（He et al., 2025）在轨迹处理上存在互补性。Branch-and-Browse通过树结构回溯解决长程任务中的错误恢复，属于推理时优化；SynthAgent通过轨迹精炼解决训练数据中的噪声，属于数据时优化。SynthAgent的轨迹精炼仅处理线性轨迹中的冗余与错位，未引入分支结构，因此无法处理需要回溯的复杂导航任务。这暗示合成数据方法在提升基础能力后，仍需结合推理时搜索策略以应对高复杂度任务。

## 总结

SynthAgent针对合成监督数据中任务幻觉与轨迹噪声的矛盾，通过分类探索与双重精炼机制，在无需人工标注的情况下实现了Web智能体对新环境的有效适应。其在WebArena上以7B开源模型达到31.67%成功率，优于所有合成基线，验证了任务-轨迹协同精炼的有效性。然而，论文暴露的边界在于：合成数据规模扩展至100%时，成功率仅达20.8%（Online-Mind2Web），远低于基于更强骨干或强化学习的SOTA方法，且未量化数据质量与骨干能力之间的交互效应。当骨干模型能力提升后，合成数据的边际收益是否递减，论文未给出回答。
