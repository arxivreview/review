# ACL2026最新论文 ｜Evo-Attacker: Memory-Augmented Reinforcement Learning for Long-Horizon Tool Attacks on LLM-MAS ｜Evo-Attacker：基于记忆增强强化学习的长程工具攻击框架

> 导读 大语言模型多智能体系统（LLM-MAS）依赖外部工具获取实时信息，但智能体对工具返回值的隐式信任构成了关键攻击面。现有工具攻击方法受限于领域特异性或静态模板，难以在复杂的多轮交互中实现跨架构、跨任务的通用性。本文提出 Evo-Attacker，将工具攻击建模为记忆增强的强化学习过程，通过动态攻击记忆与 Attack-Flow GRPO 优化长程决策。该框架在多种架构下显著降低系统性能，验证了工具通道作为主要攻击面的脆弱性，但其防御机制的缺失与攻击隐蔽性的边界仍存疑。

## 研究背景

当智能体调用 Web 搜索或代码解释器时，其输出被视为可信事实而非用户输入，这种隐式信任源于工具在静态文本生成向动态环境交互范式转变中的核心地位。然而，这种信任假设忽略了网络传输劫持或第三方服务被攻破的可能性，使得工具返回值成为绕过输入安全过滤器的潜在入口。

LLM-MAS 通过编排专业化智能体处理深度研究、Web 操作等复杂任务，其复杂的交互拓扑扩大了攻击面。主流防御策略聚焦于用户输入或智能体间消息的恶意内容检测，但工具通道因其“可信源”属性而缺乏同等强度的监控。现有工具攻击研究如 InjecAgent 和 Forced Output 针对单智能体直接注入恶意命令，但在多智能体系统中，这些简单注入常被下游智能体识别为上下文不一致而失效。Web Fraud 等针对多智能体的方法则严格限定于 Web 导航场景，Prompt Infection 依赖静态模板，无法适应 LLM-MAS 中不断演化的智能体策略与工具架构。

本文切入点在于解决工具攻击在长程交互中的信用分配难题与泛化性瓶颈。传统方法无法规划跨越多个交互轮次的协同扰动，导致局部修改被系统自我修正机制抵消。Evo-Attacker 通过引入记忆机制存储成功攻击轨迹，并利用强化学习优化攻击策略，旨在实现跨架构、跨任务的通用工具攻击。

## 核心方法

### 方法参照系

工具攻击通常被视为单步注入问题，攻击者直接篡改工具返回值以误导智能体。本文问题与该通用流程的关键差异在于：LLM-MAS 的长程交互要求攻击者规划一系列协同扰动，且需适应非平稳的工具架构与智能体策略，静态模板无法应对这种动态性。

### 动态攻击记忆与审议推理

静态模板在 LLM-MAS 中失效的根本原因是漏洞的高度上下文敏感性。本文构建动态攻击记忆 $M_A$，将成功攻击轨迹封装为结构化条目 $m^{(e)} = (X_{ctx}, T_{trace})$，其中 $X_{ctx}$ 标识任务上下文，$T_{trace}$ 记录原始工具调用、修改指令与扰动返回。

$$
M_A = \{ m^{(e)} \mid J(o^{(e)}) = 1 \}
$$

该公式表示攻击记忆仅存储导致系统失败（$J(o)=1$）的完整执行轨迹。在攻击阶段，策略 $\pi_\theta$ 执行 Retrieve-Reflect-Modify 流程：首先基于当前状态 $x_t$ 生成检索查询 $q_t$，从 $M_A$ 中获取 Top-k 相似记忆；随后进行可行性分析，输出控制决策 $d_t \in \{\text{ATTACK, CONTINUE, NOOP}\}$；最后生成具体修改指令 $\phi_{t,i_t}$。这一设计解决了静态模板无法适应动态工具架构的问题，通过检索历史成功模式实现跨任务泛化。

### Attack-Flow GRPO 优化

长程攻击中，终端失败奖励难以归因到中间推理步骤，导致强化学习训练不稳定。本文提出 Attack-Flow GRPO，将终端结果广播至所有攻击者生成的 token。

$$
\mathcal{L}(\theta) = -\mathbb{E}_{\zeta \sim \pi_{\theta_{old}}} \left[ \frac{1}{G} \sum_{i=1}^G \sum_{t \in I_{atk}} \rho_t A_i \right]
$$

其中 $I_{atk}$ 仅包含攻击者生成的 token，$A_i$ 为组相对优势。该公式通过掩码机制严格限制优化范围，确保策略仅从自身干预中学习，而非环境响应。相比标准 GRPO，此设计解决了长程依赖中的信用分配难题，使早期规划决策因对最终失败的贡献而得到强化。

## 实验评估

实验在 Flat、Chain、Hierarchical 三种架构及 HumanEval、MAB、DRB、WebArena、WebShop 五个基准上进行，对比 InjecAgent、Forced Output、Web Fraud、Prompt Infection 四个基线。基线覆盖单智能体与多智能体攻击路线，但缺乏针对 LLM-MAS 的防御性基线对比。

| 架构 | 方法 | Code (TS) | Research (RACE) | Web (Score) |
| :--- | :--- | :--- | :--- | :--- |
| Flat | w/o Attack | 66.2 | 80.0 | 33.3 |
| Flat | Evo-Attacker | 39.2↓27.0 | 54.6↓25.4 | 14.5↓18.8 |
| Chain | w/o Attack | 63.4 | 81.2 | 30.8 |
| Chain | Evo-Attacker | 37.8↓25.6 | 53.1↓28.1 | 13.4↓17.4 |
| Hier. | w/o Attack | 69.6 | 85.4 | 35.8 |
| Hier. | Evo-Attacker | 49.7↓19.9 | 63.8↓21.6 | 18.4↓17.4 |

Evo-Attacker 在所有架构下均显著降低系统性能，其中 Flat 架构 Code 任务下降 27.0 个百分点，验证了框架的通用性。消融实验显示，移除强化学习模块（w/o RL）导致最严重性能下降（Code 任务 55.2 vs Full 40.9），表明 Attack-Flow GRPO 对长程规划至关重要；移除检索模块（w/o RT）次之，证实动态记忆是泛化性的关键。

评估边界方面，论文未报告置信区间，且攻击预算 $B=3$ 的设置可能限制了对极端长程任务的评估。可复现性受限于未提供代码 URL，但超参数（$k=5, G=8, \lambda=0.5$）已详细披露。

## 关联研究分析

从问题动机看，Evo-Attacker 与 Reflexion 共享记忆增强机制，但目标函数相反：Reflexion 优化任务成功率，本文优化系统失败率。这一差异源于工具通道的“可信源”属性，使得攻击者无需对抗输入过滤器，而是利用智能体对工具输出的隐式信任。Reflexion 的记忆用于自我修正，本文的记忆用于存储成功攻击模式，这种反向利用揭示了智能体自我进化机制在安全层面的双刃剑效应。

从方法设计看，Evo-Attacker 与 Tool-R0 同属强化学习路线，但 Tool-R0 依赖合成环境提供可验证奖励，本文依赖终端失败指标广播。Tool-R0 的奖励设计针对工具调用策略优化，本文的奖励设计针对长程依赖的信用分配。这种差异暗示，在缺乏高质量合成环境的安全攻击场景中，终端结果广播可能是更可行的替代方案，但其对稀疏奖励的敏感性尚未在大规模环境中验证。

## 总结

Evo-Attacker 解决了 LLM-MAS 工具攻击中的长程信用分配与泛化性难题，通过动态攻击记忆与 Attack-Flow GRPO 实现了跨架构、跨任务的通用攻击。实验证明其在 Flat 架构 Code 任务中降低性能 27.0 个百分点，验证了工具通道作为主要攻击面的脆弱性。然而，论文未评估攻击在不同防御机制下的隐蔽性边界，且攻击预算 $B=3$ 的设置可能低估了长程任务中的实际风险。当防御机制引入动态工具验证时，基于静态成功轨迹的攻击记忆是否仍能保持有效性，论文未给出回答。
