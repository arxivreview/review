# ACL2026最新论文 ｜ReasonAny: Incorporating Reasoning Capability to Any Model via Simple and Effective Model Merging ｜基于对比梯度识别的推理能力合并框架

研究机构：新加坡国立大学、中国人民大学

作者：Junyao Yang、Chen Qian、Dongrui Liu 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.05560)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.05560)

> 大语言模型（LLM）在获得长思维链（Long-CoT）推理能力后，如何将其无损注入垂直领域模型，构成了“推理+X”的核心难题。现有模型合并方法在融合推理与领域能力时，常导致推理深度与领域效用双降的破坏性崩溃。本文发现推理能力主要驻留在低梯度敏感区域，据此提出对比梯度识别（Contrastive Gradient Identification）框架，通过互斥掩码实现能力解耦。该方案在免训练条件下显著优于基线，但其低梯度假设的普适性仍受限于特定蒸馏模型架构。

## 研究背景

模型合并旨在通过算术运算融合不同微调模型的参数向量，以规避全量重训的高昂成本。其核心机制是计算任务向量 $\tau = \theta_{fine} - \theta_{base}$，并通过加权求和或冲突消解策略合成最终参数。然而，传统合并方法普遍假设高梯度幅值对应关键参数，这一假设在知识注入场景中有效，但在涉及复杂推理能力的融合时面临失效风险。

当前领域面临的核心矛盾在于，推理能力与领域知识在参数空间中的分布特性存在本质差异。主流合并技术如 TIES-Merging 和 DARE-Merging 依赖高梯度选择或随机缩放来处理参数冲突，导致推理模型特有的低幅值梯度结构被高幅值的领域更新覆盖，引发性能崩溃。本文切入点在于揭示推理能力的参数拓扑特性：长思维链模型在微调过程中产生的梯度幅值显著低于标准指令模型，这意味着推理能力并非由高敏感度参数承载，而是依赖于低梯度区域的精细结构保持。

## 核心方法

### 方法参照系

本文问题归属于模型合并中的参数重要性识别与冲突消解范畴。标准流程通常采用统一的梯度幅值指标（如 Top-K 选择）筛选关键参数，假设所有任务的关键能力均对应高梯度区域。本文的关键差异在于，针对推理模型采用了反向的低梯度选择策略，并引入了基于集合论的互斥掩码机制，以解决推理与领域参数在空间上的重叠冲突。

### 对比梯度识别

传统方法对任务模型和推理模型采用相同的 Top-K 高梯度选择策略，导致推理模型中幅值较小的关键参数被忽略。本文提出对比梯度识别，对任务模型保留高梯度参数，对推理模型保留低梯度参数。具体地，任务参数集 $N_t$ 通过 Top-K 算子选取梯度幅值最大的前 $p_t$ 比例参数，而推理参数集 $N_r$ 通过 Bottom-K 算子选取梯度幅值最小的前 $p_r$ 比例参数：

$$
N_r = \text{BottomK}(I(\theta_r), p_r)
$$

其中 $I(\theta_r)$ 为推理模型在推理数据集上的梯度敏感度向量。这一设计动机在于，实验表明仅注入低梯度参数即可恢复大部分推理能力，而注入高梯度参数会导致性能完全崩溃，从而验证了推理能力驻留在低梯度区域的假设。

### 互斥掩码合成

直接叠加任务与推理向量会导致参数冲突，即同一参数被两个源同时更新，引发破坏性干扰。本文引入冲突排除机制，通过集合差运算生成互斥掩码，确保每个参数仅由单一源更新。最终合并参数 $\theta_{merged}$ 计算如下：

$$
\theta_{merged} = \theta_{base} + \lambda_t (\tau_t \odot M_t) + \lambda_r (\tau_r \odot M_r)
$$

其中 $M_t$ 和 $M_r$ 为互斥的二进制掩码，$\lambda_t, \lambda_r$ 为缩放因子。该机制保证了低梯度推理结构不被高幅值领域更新覆盖，实现了“推理+X”能力的无损合成。

## 实验评估

实验在 Qwen2.5-7B 和 Llama3.1-8B 系列模型上进行，涵盖安全、生物医学和金融领域。基线覆盖 Linear、Task Arithmetic、TIES、DARE、FuseLLM 和 LED 六种主流合并方法，但未对比基于 Fisher 信息约束的合并方法，这可能影响对防崩溃机制全面性的评估。

| 方法 | GSM8K | MMLU | Safety-Tuned |
| :--- | :--- | :--- | :--- |
| Linear | 50.42 | 57.34 | 2.08 |
| TIES | 62.17 | 62.14 | 1.95 |
| DARE | 0.53 | 0.00 | 0.40 |
| LED | 72.48 | 71.93 | 2.41 |
| ReasonAny | 86.28 | 72.73 | 1.19 |

ReasonAny 在 GSM8K 上达到 86.28，接近推理专家模型的 87.23，而 DARE 和 FuseLLM 出现严重崩溃（GSM8K 分别为 0.53 和 0.00）。在安全基准上，ReasonAny 的有害性得分 1.19 与安全检查模型 1.18 几乎一致，表明领域能力未受损。

消融实验显示，移除推理参数识别模块导致 GSM8K 得分降至 0.15，证实低梯度选择对推理能力的决定性作用；移除安全参数识别则使有害性得分升至 2.39，表明高梯度选择对领域对齐的必要性。这一结果验证了对比策略的必要性，单一梯度方向无法同时满足两类能力需求。

评估协议主要依赖标准基准，未报告计算效率指标（如 Token 长度或延迟），且部分基线（如 DARE）在特定设置下出现输出崩溃（标记为 *），可能影响公平性。代码已开源，但超参数设置（如 $p_t, p_r$ 的具体取值）在正文中未详细列出，复现时需参考附录。

## 关联研究分析

从问题动机看，本文与 RLVR（Reinforcement Learning with Verifiable Rewards）路线形成互补。RLVR 通过训练优化推理策略，但面临灾难性遗忘和训练成本高的问题；本文通过合并实现免训练的能力注入，但受限于源模型的质量。两者在“推理能力来源”上存在根本差异：RLVR 假设推理能力可通过奖励反馈激发，本文假设推理能力已存在于蒸馏模型中，仅需正确提取。

从方法设计看，本文与 TIES-Merging 的差异在于冲突消解机制。TIES 通过符号一致性修剪冲突参数，本文通过梯度幅值方向（高/低）分离参数空间。TIES 假设冲突源于符号相反，本文假设冲突源于幅值分布差异。这一差异源于任务特性：知识注入通常涉及高梯度参数，而推理能力涉及低梯度参数，导致传统符号修剪无法有效保护推理结构。

## 总结

本文要解决的核心矛盾是推理能力与领域知识在模型合并中的相互破坏。现有方法因假设高梯度参数重要而失效，本文凭借推理能力驻留在低梯度区域的发现，通过对比梯度识别和互斥掩码实现了能力解耦。实验证明 ReasonAny 在 GSM8K 上保留 86.28 的推理能力，同时保持安全对齐性能。其边界在于低梯度假设仅在 DeepSeek-R1-Distill 等特定蒸馏模型上验证，对于原生推理模型或不同架构的 LLM 是否成立，论文未给出回答。
