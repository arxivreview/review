# ACL2026最新论文 ｜EverMemOS: A Self-Organizing Memory Operating System for Structured Long-Horizon Reasoning ｜EverMemOS：基于记忆生命周期的结构化长时程推理系统

论文原文见 [arXiv](https://arxiv.org/abs/2601.02163)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.02163)

> 导读 LLM智能体在长时程交互中面临的核心困境是固定上下文窗口导致的跨会话状态丢失与认知矛盾。现有记忆系统多将记忆视为孤立记录的扁平集合，缺乏将碎片化情景经验转化为连贯知识结构的显式机制，导致智能体虽能检索到相关事实，却无法检测冲突或维持稳定的用户模型。EverMemOS 提出了一种受生物记忆痕迹（Engram）启发的三阶段生命周期架构，通过情景轨迹形成、语义固化与重构性回忆，将离散交互转化为支持长时程推理的稳定语义结构。该系统在 LoCoMo 和 LongMemEval 基准上显著优于现有方法，但其性能增益对骨干模型的依赖以及前瞻性推断的独立贡献量化仍是存疑之处。

## 研究背景

当智能体需要基于数月前的对话历史提供个性化建议时，单纯的向量相似度检索往往失效。这是因为原始对话流包含大量冗余与歧义，直接检索到的片段缺乏语义连贯性，无法支撑多跳推理或时序逻辑判断。为了解决这一问题，研究引入了情景记忆（Episodic Memory）与语义记忆（Semantic Memory）的区分：前者记录具体事件，后者存储抽象知识。然而，从情景到语义的转化过程，即记忆固化（Memory Consolidation），在现有计算架构中往往缺失或过于简化，导致智能体在长期交互中产生“记忆幻觉”或状态不一致。

该领域的演进脉络显示，早期工作如 RAG 确立了外部存储范式，但受限于静态检索；MemGPT 引入操作系统类比，解决了容量问题，但未解决语义整合问题；Mem0 和 Zep 等系统通过知识图谱或原子事实提取提升了结构化程度，但仍主要关注存储优化或事实维护，缺乏对经验进行主动抽象与固化的机制。EverMemOS 的切入点在于指出，现有方法的主要失败并非源于信息缺失，而是源于整合不足。它主张将记忆管理从被动的记录存储转变为主动的生命周期过程，通过显式的固化阶段将碎片化经验转化为支持长时程推理的连贯结构。

## 核心方法

### 记忆原语与生命周期参照系

EverMemOS 的核心单元是 MemCell，定义为元组 $c = (E, F, P, M)$，其中 $E$ 为情景叙事，$F$ 为原子事实集合，$P$ 为带有有效时间区间 $[t_{start}, t_{end}]$ 的前瞻性推断，$M$ 为元数据。这一设计区别于传统 RAG 的纯文本块或 Mem0 的纯事实三元组，关键在于引入了时间约束的前瞻性信号 $P$，使记忆单元具备时序感知能力，为后续的冲突检测与状态演化提供基础。

### 语义固化与增量聚类

针对扁平存储中情景碎片无法聚合为主题化知识的问题，EverMemOS 引入语义固化阶段。当新 MemCell 到达时，系统计算其嵌入并与现有 MemScene 质心进行相似度匹配。若相似度超过阈值 $\tau$，则将其同化并增量更新场景表示；否则创建新 MemScene。该过程可形式化为：

$$ S_{new} = \begin{cases} \text{Update}(S_{nearest}, c) & \text{if } \text{sim}(c, S_{nearest}) > \tau \\ \text{Create}(c) & \text{otherwise} \end{cases} $$

这一机制解决了静态聚类无法适应实时交互流的问题，通过在线增量更新维持了主题结构的动态稳定性，避免了批量重处理带来的延迟。

### 重构性回忆与充分性验证

检索阶段摒弃了固定预算的 Top-K 策略，采用基于“必要性与充分性”原则的重构性回忆。系统首先通过 RRF 融合密集检索与 BM25 检索定位相关 MemScene，随后在场景内对情景进行重排序，并过滤掉时间失效的前瞻性信号。关键创新在于引入 LLM 验证器进行充分性检查：

$$ C_{final} = \begin{cases} C_{retrieved} & \text{if } \text{Verify}(q, C_{retrieved}) = \text{Sufficient} \\ \text{Rewrite}(q) \rightarrow \text{Retrieve} & \text{otherwise} \end{cases} $$

该设计解决了固定检索预算下噪声累积与关键信息遗漏的矛盾，通过代理式验证确保输入下游推理的上下文既包含必要证据，又避免无关干扰，从而提升多跳推理的准确性。

## 实验评估

实验在 LoCoMo（1,540 题，10 个超长对话）和 LongMemEval（500 题，约 115k tokens/对话）上进行，基线包括 Zep、Mem0、MemOS、MemoryOS 和 MemU。所有方法统一使用 GPT-4.1-mini 作为骨干，评估协议采用 LLM-as-a-judge，Cohen’s $\kappa > 0.89$。

| 方法 | LoCoMo Overall (%) | LongMemEval Overall (%) |
| :--- | :--- | :--- |
| Zep | 81.06 | - |
| MemOS | 77.80 | 76.30 |
| EverMemOS | 86.76 | 83.00 |

EverMemOS 在 LoCoMo 上以 86.76% 超越最强基线 Zep 7.0%，在 LongMemEval 上以 83.00% 超越 MemOS 6.7%。消融实验显示，移除 MemScene 导致 LoCoMo 准确率从 93.05% 降至 89.16%，移除 MemCell 进一步降至 81.82%，表明层级结构对性能有显著贡献。多跳推理任务上，EverMemOS 较 Zep 提升 19.7%，验证了语义固化在整合分散证据方面的有效性。

评估边界方面，实验未报告置信区间，且 LongMemEval 基线分数取自 MemOS 官方排行榜，可能存在配置差异。前瞻性推断（Foresight）的贡献未通过独立消融量化，仅通过案例研究展示。代码已开源，但超参数敏感性分析（如阈值 $\tau$ 和检索数量 $K$）仅在附录中简要提及，主文缺乏详细的计算成本分解。

## 关联研究分析

从方法设计看，EverMemOS 与 Mandol 同属结构化记忆路线，但侧重点不同。Mandol 采用 DuckDB 和语义图优化工程性能，追求低延迟；EverMemOS 则通过 MemScene 聚类实现语义深度整合，牺牲部分实时性换取推理一致性。这种差异源于任务特性：Mandol 针对客服等高并发场景，而 EverMemOS 面向需要复杂长时程推理的个性化助手。EverMemOS 未采用 Mandol 的 Token 约束定量检索，可能导致其在资源受限环境下效率较低，但其在多跳推理上的优势表明，语义固化对于复杂任务是不可替代的。

从问题动机看，EverMemOS 与 GAM 都关注记忆稳定性，但机制迥异。GAM 通过写隔离防止实时噪声腐蚀长期知识，属于防御性策略；EverMemOS 通过语义固化主动构建稳定结构，属于建设性策略。GAM 的写隔离机制在实时交互中更鲁棒，但缺乏对知识演化的主动建模；EverMemOS 的固化机制能捕捉用户偏好的动态变化，但依赖 LLM 进行聚类决策，存在计算开销和潜在的错误传播风险。两者在“稳定性”的定义上存在分歧：GAM 强调抗干扰，EverMemOS 强调语义连贯。

## 总结

EverMemOS 旨在解决 LLM 智能体在长时程交互中因记忆碎片化导致的推理不一致问题。现有方法缺乏将情景经验转化为稳定语义结构的显式机制，而 EverMemOS 通过引入受生物记忆启发的三阶段生命周期，实现了从被动存储到主动固化的转变。实验表明，该架构在 LoCoMo 多跳推理任务上较最强基线提升 19.7%，验证了语义固化对整合分散证据的有效性。然而，其性能高度依赖 GPT-4.1-mini 骨干，且前瞻性推断的独立贡献未量化。当骨干模型能力较弱时，LLM 驱动的聚类与验证步骤是否会导致错误累积，从而抵消语义固化的收益，论文未给出回答。
