# ACL2026最新论文 ｜Aligned Multi-View Scripts for Universal Chart-to-Code Generation ｜多语言图表到代码生成

研究机构：新加坡管理大学

作者：Zhihan Zhang、Lizi Liao

论文原文见 [arXiv](https://arxiv.org/abs/2604.24559)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.24559)

> 图表到代码生成旨在将静态图像转化为可执行脚本，以解决科学出版中数据不可复用的痛点。现有方法受限于Python/matplotlib单一生态，忽略了不同绘图语言间共享的潜在视觉语义这一关键监督信号。本文通过构建176K对齐数据集与语言条件低秩子空间适配器，实现了跨Python、R、LaTeX的统一生成。该工作填补了多语言基准空白，但其性能在单语言Python任务上仍落后于最新专用模型，且依赖同源数据构建可能高估泛化能力。

## 研究背景

图表作为量化证据的载体，其数字化复现依赖于从像素到代码的精确映射。这一过程涉及视觉编码器提取图像特征，经由多模态投影器对齐至语言模型嵌入空间，最终由大语言模型生成语法正确的绘图脚本。然而，传统流水线仅关注单一语言的语法正确性，忽视了同一图表在不同绘图工具中存在的语义等价性，导致模型难以捕捉跨语言的通用结构。

图表理解领域长期存在“Python中心主义”偏差，主流数据集如ChartMimic和Plot2Code仅包含matplotlib脚本，限制了模型在R (ggplot2) 和 LaTeX (TikZ) 等科学出版标准工具上的应用。这种单语言范式不仅降低了实际可用性，更丢弃了多语言脚本间对齐的视觉语义监督信号。现有模型在处理非Python语言时表现出严重的性能失衡，例如ChartCoder-7B在LaTeX上的执行率骤降至17.9%，而Python上高达96.2%。本文切入点在于利用多语言脚本的视觉同构性，构建跨语言对齐数据集，并设计参数高效的适配器以共享核心视觉理解，同时实现语言特定的代码生成。

## 核心方法

### 多模态投影器参照系

LLaVA架构采用两层MLP投影器将视觉特征映射至LLM嵌入空间，形成共享基础表示。该流程假设视觉特征与语言指令通过单一线性变换对齐，缺乏对目标语言语法结构的显式建模。本文问题与该通用流程的关键差异在于：需在保持视觉理解一致性的前提下，动态适配不同绘图语言的语法约束，而非静态映射。

### 语言条件低秩子空间适配器

标准MLP投影器无法区分不同语言的语法差异，导致多语言训练时出现干扰。本文在MLP投影器后引入低秩子空间适配器，通过语言引导路由动态选择子空间。设计动机是解决独立专家模型的参数冗余与联合训练的负迁移问题。适配器包含低秩投影器 $A$、子空间池 $\{b_i\}_{i=1}^N$ 及语言特定路由器 $W_l$。给定视觉特征 $Z_v$ 和目标语言 $l$，路由器计算概率分布并选择Top-$r$ 子空间：

$$y_l = \text{topr}(\text{softmax}(W_l Z_v))$$

$$H_v = W Z_v + A B Z_v, \quad B = \text{concat}_{i \in y_l} b_i$$

该公式表明，最终视觉令牌由共享基础表示 $W Z_v$ 与语言自适应表示 $A B Z_v$ 叠加而成。低秩约束 $r < N$ 确保适配器仅捕获语言特异性差异，而非重复建模视觉共性，从而在1.3B模型上以极少参数实现跨语言泛化。

### 渐进式训练策略

直接联合训练多语言数据易导致路由不稳定。本文采用两阶段训练：首先在ChartMoE-Align上预训练MLP投影器，冻结视觉编码器与LLM；随后在Chart2NCode上微调适配器与LLM。设计动机是分离视觉对齐与语言适配任务。预热阶段固定子空间池与路由器，仅训练LLM骨干，确保路由机制稳定后再联合优化。该策略避免了早期训练中的梯度冲突，使模型在Python、R、LaTeX上均获得均衡提升，而非偏向某一语言。

## 实验评估

实验在ChartMimic、Plot2Code及自建Chart2NCode测试集上进行，基线涵盖GPT-4o、Qwen3-VL、ChartCoder等。CharLuMA-6.7B在ChartMimic上取得92.3 ER与77.4 DS，优于ChartCoder-7B的91.4 ER，但低于MM-ReCoder的96.7 ER（据领域综述）。在Chart2NCode上，CharLuMA-6.7B在Python、R、LaTeX上分别达到98.0、96.5、89.0 ER，显著优于ChartCoder-7B在LaTeX上的17.9 ER，验证了多语言对齐的有效性。

| 模型 | ChartMimic ER | ChartMimic DS | Chart2NCode Python ER | Chart2NCode LaTeX ER |
| :--- | :--- | :--- | :--- | :--- |
| ChartCoder-7B | 91.4 | 86.4 | 96.2 | 17.9 |
| CharLuMA-6.7B | 92.3 | 77.4 | 98.0 | 89.0 |
| GPT-4o | 93.2 | 83.5 | 94.5 | 78.2 |

消融实验显示，移除语言特定路由器使DS从78.9降至75.1，证实路由机制对视觉保真度的贡献。子空间配置32-16优于32-8，表明足够的激活容量对复杂图表至关重要。未冻结矩阵A导致DS降至78.0，验证了低秩约束防止过拟合的作用。评估边界方面，Chart2NCode测试集源自训练数据同源分布，可能高估泛化能力；MJ指标依赖GPT-4o判断，存在主观性偏差；代码开源但超参数细节有限，复现需依赖附录。

## 关联研究分析

从问题动机看，MoCA采用令牌级模态仲裁解决多任务干扰，而本文聚焦多语言语法差异。MoCA的仲裁机制针对模态冲突，本文的语言条件路由针对语法特异性，根源在于任务特性：MoCA处理理解与生成混合任务，本文仅处理生成任务。本文未探索MoCA的动态仲裁是否适用于多语言场景，查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从方法设计看，REChart利用大型推理模型优化编辑效率，本文采用参数高效适配器。REChart侧重推理预算控制，本文侧重结构共享，差异源于目标：REChart追求编辑速度，本文追求跨语言一致性。本文未对比REChart的混合奖励机制，若引入效率奖励是否进一步提升LaTeX生成速度，论文未给出回答。

## 总结

本文核心矛盾在于单语言范式丢弃了跨语言视觉语义监督，导致模型在非Python语言上性能崩塌。切入点在于利用多语言脚本的视觉同构性，构建对齐数据集并设计语言条件适配器。方法通过低秩子空间路由共享视觉理解，实现语言特定代码生成。实验证明CharLuMA-6.7B在Chart2NCode上LaTeX ER达89.0，较ChartCoder-7B提升71.1个百分点。边界在于ChartMimic上DS 77.4低于GPT-4o的83.5，且测试集同源可能高估泛化。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
