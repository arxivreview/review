# ACL2026最新论文 ｜Towards Robust Real-World Spreadsheet Understanding with Multi-Agent Multi-Format Reasoning ｜多智能体多模态电子表格理解

研究机构：香港中文大学、商汤

作者：Houxing Ren、Mingjie Zhan、Zimu Lu 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_05c06b069835)

> 导读 真实世界电子表格包含层级表头、合并单元格及颜色语义，且规模常超出大语言模型（LLM）上下文窗口，导致现有纯文本序列化方法在结构保真与长程依赖上失效。本文切入点在于将全表一次性输入转化为局部区域的多模态增量读取，通过构建中间结构草图规避长上下文瓶颈。SpreadsheetAgent 采用双阶段多智能体框架，结合代码执行、视觉与 LaTeX 转换工具进行迭代提取与验证。该方法在 SpreadsheetBench 上以 GPT-OSS-120B 取得 38.16% 准确率，超越 ChatGPT Agent 基线，但其性能高度依赖特定多模态大模型，通用性存疑。

## 研究背景

当 LLM 处理包含数千行、多级表头及视觉格式（如字体颜色、阴影）的电子表格时，传统的 Markdown 或 HTML 序列化会丢失空间布局与语义关联，且全表输入极易超出上下文限制。为解决此问题，表格序列化（Table Serialization）旨在将二维结构映射为一维文本，但这一过程不可避免地破坏行列邻接关系。为保留复杂结构，研究转向图或超图表示，如 TAMO 利用超图建模高阶关系（Li et al., 2025），但此类方法计算开销大，且难以处理真实世界中的视觉噪声与非标准布局。

现有主流路线分为专用预训练模型与通用 LLM 微调。TaPas 等专用模型受限于泛化能力，而 TableLlama 等指令微调模型虽提升了通用性，但在处理包含透视表、图表等复杂元素的真实电子表格时，仍面临结构解析错误与数值幻觉问题。智能体框架如 SheetMind 引入了规划与执行机制，但多采用全表文本输入，未能有效解决长上下文下的注意力稀释与视觉语义缺失。本文针对这一缺口，提出在结构提取阶段引入多模态局部区域读取，以兼顾布局保真度与计算效率。

## 核心方法

### 多智能体增量提取参照系

本文问题属于智能体推理框架与多模态融合的交叉领域。标准智能体流程通常一次性输入全表文本，通过规划-执行-反思循环生成答案。本文的关键差异在于将“全表文本输入”替换为“局部区域多模态迭代提取”，先构建 YAML 结构草图，再进行任务推理，从而在有限上下文预算下处理大规模表格。

### 多模态区域提取与 YAML 结构构建

设计动机在于解决纯文本序列化丢失视觉语义（如颜色、边框）及全表输入超出上下文限制的问题。提取智能体（Extraction Agent）驱动探索，通过调用代码执行、视觉范围智能体（Vision Range Agent）和 LaTeX 范围智能体（LaTeX Range Agent）获取局部区域信息。视觉智能体将选定区域渲染为图像，利用视觉语言模型提取颜色与布局线索；LaTeX 智能体将区域转换为符号表格，保留层级表头与对齐关系。提取结果被整合为 YAML 格式的结构草图 $Y$，其构建过程可形式化为：

$$ Y = \text{Parse}_{\text{YAML}} \left( \bigcup_{i=1}^{N} \text{Extract}(S_i, M_i) \right) $$

其中 $S_i$ 为第 $i$ 个局部区域，$M_i \in \{\text{Code}, \text{Vision}, \text{LaTeX}\}$ 为模态类型，$N$ 为迭代次数。该公式表明，最终结构表示是多个局部区域在不同模态下提取结果的并集与解析，实现了布局与语义的绑定。

### 双重验证与迭代修正

设计动机在于降低结构提取中的错误传播，确保下游推理基于忠实表示。验证智能体（Verification Agent）不重新处理全表，而是选择性聚焦于不确定或结构复杂的区域。它通过视觉验证智能体将区域转为图像，查询视觉语言模型检查布局一致性；通过 LaTeX 验证智能体将区域转为 LaTeX 表格，查询语言模型检查结构保真度。验证过程可表示为：

$$ Y^* = \begin{cases} Y, & \text{if } \text{Verify}_{\text{Vision}}(Y, S) \land \text{Verify}_{\text{LaTeX}}(Y, S) \\ Y + \Delta, & \text{otherwise} \end{cases} $$

其中 $\Delta$ 为验证失败时生成的修正建议。该机制通过“检查而非求解”的策略，在迭代中逐步修正结构错误，提升了表示的可靠性。

## 实验评估

实验在 SpreadsheetBench（912 个真实 Excel 问题）上进行，基线包括 GPT-4o、ChatGPT Agent 及 TreeThinker。本文方法在 Soft Restriction 下，GPT-OSS-120B 取得 38.16% 准确率，Qwen3-Coder-480B 取得 41.67%，均显著优于 ChatGPT Agent 的 35.27% 和 GPT-4o 的 16.96%。

| 模型 | Soft Restriction (Overall) | Hard Restriction (Overall) |
|---|---|---|
| GPT-4o | 16.96 | 13.27 |
| ChatGPT Agent | 35.27 | - |
| GPT-OSS-120B w/ SpreadsheetAgent | 38.16 | 31.47 |
| Qwen3-Coder-480B w/ SpreadsheetAgent | 41.67 | 34.65 |

消融实验显示，移除验证模块（w/o Verify）导致整体准确率从 22.37% 降至 21.45%，移除所有工具与验证（w/o All）则骤降至 16.41%，表明多模态工具与验证机制的协同效应至关重要。移除 LaTeX 工具对结构保真度影响显著，而移除视觉工具在软限制下影响较小，但在硬限制下性能下降明显，说明视觉线索在复杂布局解析中不可或缺。

评估边界方面，本文仅在 SpreadsheetBench 和 RealHiT-Bench 上验证，未与 WikiTQ 等干净数据基准对比，限制了与领域通用 SOTA 的直接可比性。代码已开源，但实验依赖 GLM-4.5V 等特定多模态模型，且未报告置信区间，数值比较需谨慎。

## 关联研究分析

从方法设计看，本文与 TreeThinker 均关注层级结构，但 TreeThinker 仅处理文本序列化的层级表头，而本文通过视觉与 LaTeX 多模态输入捕获颜色、边框等非文本语义。这一差异源于任务特性：真实电子表格的视觉格式携带关键语义，纯文本方法无法保留。然而，本文未探索视觉模态在噪声数据下的鲁棒性，当表格包含模糊或对抗性视觉扰动时，视觉智能体的提取可靠性是否下降，论文未给出回答。

从框架架构看，本文与 SheetMind 同属多智能体框架，但 SheetMind 侧重操作执行（如单元格修改），本文侧重结构理解与验证。本文引入独立的验证智能体，通过双重校验确保结构保真，而 SheetMind 依赖反思智能体进行错误修正。这一设计差异表明，在结构提取任务中，显式的多模态验证比隐式的文本反思更有效。但本文未对比基于强化学习（如 TableGPT-R1）的方法，RL 在数值计算上的优势是否能在结构提取任务中复现，仍是未解问题。

## 总结

本文核心矛盾在于真实电子表格的复杂布局与 LLM 长上下文限制之间的冲突。切入点在于将全表输入转化为局部多模态增量提取，通过 YAML 结构草图与双重验证机制，在有限上下文下保留布局语义。SpreadsheetAgent 在 SpreadsheetBench 上以 GPT-OSS-120B 取得 38.16% 准确率，超越 ChatGPT Agent 基线 2.89 个点。其边界在于高度依赖 GLM-4.5V 等特定多模态大模型，且未在小模型蒸馏或开源模型适配上进行验证。当支持集增大或模型规模缩小至 30B 以下时，多模态提取的边际收益是否递减，论文未给出回答。
