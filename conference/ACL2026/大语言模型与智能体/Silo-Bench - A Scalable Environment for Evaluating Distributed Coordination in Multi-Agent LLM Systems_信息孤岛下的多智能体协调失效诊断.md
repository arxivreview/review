# ACL2026最新论文 ｜Silo-Bench: A Scalable Environment for Evaluating Distributed Coordination in Multi-Agent LLM Systems ｜信息孤岛下的多智能体协调失效诊断

研究机构：北京大学、浙江大学

作者：Yuzhe Zhang、Feiran Liu、Yi Shan 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.01045)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.01045)

> 多智能体大语言模型系统（Multi-Agent LLM Systems, MAS）旨在通过分布式信息处理突破单模型上下文窗口限制，但现有基准多预设固定角色与通信拓扑，无法隔离评估智能体在信息隔离状态下的自主协调与推理整合能力。SILO-BENCH 通过构建无角色约束的算法任务环境，系统性地量化了智能体在通信与推理两个维度的表现差异。该基准揭示了当前大语言模型在分布式计算中存在的“通信-推理断层”，即智能体能自发形成正确拓扑并获取信息，却无法将其整合为正确答案。这一发现挑战了单纯增加智能体数量即可提升性能的假设，为 MAS 的规模化应用提供了关键的诊断维度，但其结论是否适用于非算法类任务仍需进一步验证。

## 研究背景

当单一大型语言模型面对超出其上下文窗口的全局信息时，其注意力机制的二次方计算复杂度导致处理效率急剧下降，甚至出现“迷失在中间”现象。为突破这一瓶颈，研究者将全局数据切分并分配给多个智能体，每个智能体仅持有局部数据片段，这种状态被称为信息孤岛。智能体必须通过通信协议交换局部信息，最终协同计算出全局正确答案。这一过程不仅要求智能体具备基本的信息传递能力，更要求其具备将分散的局部状态整合为全局一致性的推理能力。

现有 MAS 研究主要聚焦于通信拓扑优化与策略学习，如 GPTSwarm 通过强化学习动态调整连接权重，G-Designer 利用图生成模型自动构建任务特异性拓扑。这些方法假设智能体具备足够的推理整合能力，将性能瓶颈归因于通信结构的不匹配。然而，现有基准如 CAMEL 和 MetaGPT 均预设了固定的角色分工（如“经理”、“程序员”），这种角色先验掩盖了智能体在缺乏结构化指导时的真实协调极限。主流路线的瓶颈在于：它们优化的是“如何通信”，却未验证“通信后能否正确推理”。SILO-BENCH 的切入点在于剥离角色与预设拓扑，将任务难度锚定在通信复杂度理论上，从而直接暴露智能体在信息孤岛下的推理整合短板。

## 核心方法

### 通信复杂度驱动的任务分级

SILO-BENCH 的任务设计基于 Yao 通信复杂度理论，将任务划分为三个层级，以隔离不同通信模式下的协调难度。Level-I（聚合）任务具有星型拓扑特征，最优通信复杂度为 $O(N)$，如全局最大值计算；Level-II（网格）任务具有链式依赖，复杂度为 $O(N)$，如前缀和计算；Level-III（全局洗牌）任务具有全连接特征，复杂度为 $O(N \log N)$ 至 $O(N^2)$，如分布式排序。这种分级确保了性能差异可归因于协调需求，而非任务本身的算法难度。

### 四维评估指标体系

为量化协调失效的具体环节，SILO-BENCH 定义了四个互补指标。成功率 $S$ 衡量所有智能体收敛至正确答案的比例；部分正确率 $P$ 衡量答案的连续质量，其定义为：

$$ P = \frac{1}{N} \sum_{i=1}^{N} q_i $$

其中 $q_i$ 为智能体 $i$ 的答案质量分数。$P$ 与 $S$ 的差值 $P - S$ 专门量化了推理整合阶段的性能损失，即智能体获取了信息但未能正确整合的代价。此外，Token 消耗 $C$ 和通信密度 $D$ 分别量化计算成本与交互强度，其中 $D$ 定义为实际消息数与最大可能消息数 $N(N-1)$ 的比值。

### 相对协调成本量化

为了区分任务固有难度与协调开销，SILO-BENCH 引入了相对协调成本（Relative Coordination Cost, RCC）。RCC 定义为单智能体基线成功率与多智能体成功率的相对损失：

$$ RCC = 1 - \frac{SR(N=k)}{SR(N=1)} $$

该公式的物理含义是：在给定任务难度下，多智能体协作相对于单智能体直接处理所损失的性能比例。若 RCC 随规模 $k$ 显著增加，则表明协调开销是性能崩塌的主因，而非任务本身变难。

## 实验评估

实验在 54 种配置（6 种规模 $\times$ 3 种协议 $\times$ 3 种模型）上进行，共 1,620 次实验。基线仅包含 $N=1$ 的单智能体 Oracle，未对比 GPTSwarm 等动态拓扑优化方法，这限制了结论在“优化后系统”上的外推性。主结果显示，即使是最强的 DeepSeek-V3.1，平均成功率仅为 36.9%，且随规模增加呈非线性下降。

| 模型 | 平均成功率 (%) | 平均部分正确率 (%) | 平均 Token 消耗 | 平均通信密度 |
| :--- | :--- | :--- | :--- | :--- |
| DeepSeek-V3.1 | 36.9 | 47.1 | 323.0 | 0.82 |
| GPT-OSS-120B | 16.9 | 38.3 | 313.8 | 1.01 |
| Qwen3-Next-80B-A3B | 8.2 | 19.8 | 873.6 | 0.25 |

数据表明，DeepSeek-V3.1 在 Level-I 任务上的部分正确率高达 88.0%，但成功率仅为 62.0%，26 个百分点的差距证实了“信息获取”与“答案整合”的解耦。在 Level-III 任务中，当 $N \ge 50$ 时，成功率降至 0%，而部分正确率仍保持在 8-16%，说明智能体虽能获取部分全局信息，但完全无法完成最终整合。

| 难度等级 | N=2 成功率 (%) | N=50 成功率 (%) | N=100 成功率 (%) |
| :--- | :--- | :--- | :--- |
| Level I | 82.0 | 18.0 | 10.0 |
| Level II | 62.0 | 6.0 | 5.0 |
| Level III | 41.0 | 0.0 | 0.0 |

消融分析显示，通信协议的选择对性能有显著影响，但无法弥补推理整合的缺陷。DeepSeek-V3.1 在广播协议（BP）下表现优于共享文件系统（SFS），但所有协议在大规模下均失效。通信密度随规模增加而下降，表明智能体在大规模下倾向于稀疏化交互，但这恰恰发生在最需要密集协调的时刻，形成了“协调悖论”。

评估边界方面，SILO-BENCH 仅使用算法任务，缺乏对自然语言推理或代码生成等复杂语义任务的覆盖。代码已开源，但实验未报告置信区间，且模型均为本地部署，未考虑云端 API 的延迟与成本差异。

## 关联研究分析

从问题动机看，SILO-BENCH 与 GPTSwarm 等拓扑优化方法存在根本差异。GPTSwarm 假设智能体具备推理整合能力，通过优化通信结构来提升性能；而 SILO-BENCH 证明，即使拓扑结构正确（如自发形成的星型拓扑），智能体仍可能因推理整合失败而任务失败。这一差异暗示，当前 MAS 研究的瓶颈可能不在“通信结构”而在“推理机制”，拓扑优化无法解决智能体无法将局部信息整合为全局一致性的根本问题。

从方法设计看，SILO-BENCH 与 M-GRPO 等强化学习协同优化方法形成互补。M-GRPO 通过层级信用分配优化策略，旨在解决奖励稀疏问题；而 SILO-BENCH 揭示的“通信-推理断层”表明，即使策略优化到位，若智能体缺乏显式的同步检查点或共识协议，仍无法在大规模下完成整合。SILO-BENCH 的无角色设定排除了角色专业化带来的性能增益，这可能导致其结论在角色化系统中被高估，但同时也提供了更纯粹的协调能力诊断视角。

## 总结

SILO-BENCH 旨在解决多智能体系统在信息孤岛下的协调失效问题，其切入点在于剥离角色与预设拓扑，直接测试智能体的自主协调与推理整合极限。通过基于通信复杂度理论的任务分级与四维指标体系，该基准揭示了当前大语言模型在分布式计算中的“通信-推理断层”：智能体能自发形成正确拓扑并获取信息，但无法将其整合为正确答案。实验证明，性能随规模与复杂度呈乘性下降，Level-III 任务在 $N \ge 50$ 时成功率归零，而部分正确率仍保持正值，证实了推理整合是主要瓶颈。本文的边界在于仅使用算法任务，且未对比动态拓扑优化方法，无法排除“优化后的拓扑结构可弥补推理断层”的可能性。当智能体规模进一步扩大至百级以上时，现有的通信协议是否仍能维持基本的信息传递效率，论文未给出回答。
