# ACL2026最新论文 ｜SLICEFORMER: Static Program Slicing Using Language Models With Dataflow-Aware Pretraining and Constrained Decoding ｜静态程序切片的数据流感知预训练与约束解码

研究机构：加拿大康考迪亚大学

作者：Pengfei He、Shaowei Wang、Tse-Hsun Chen 等 4 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_966c8599491c)

> 静态程序切片旨在从代码中精确提取影响特定变量的语句子集，是漏洞分析与调试的基础。现有基于语言模型的方法常因依赖表面模式而非真实数据流，导致切片遗漏或包含无关语句，且生成过程易产生幻觉。本文提出 SLICEFORMER，通过数据流图（DFG）感知的预训练目标与 TSED 单调性约束解码，将切片重构为序列到序列任务。该方法在 Java 和 Python 基准上显著提升了精确匹配率，但其对传统静态分析工具缺乏直接对比，且未报告计算开销，限制了其工程适用性的评估。

## 研究背景

静态程序切片的核心在于构建代码依赖图（CDG），通过静态分析识别变量间的定义-使用关系，从而确定哪些语句语义上影响了切片准则。与动态切片不同，静态切片无需执行程序，适用于无法运行或执行成本过高的场景。然而，传统工具如 JavaSlicer 依赖复杂的系统依赖图（SDG）构建，难以处理现代编程语言的复杂特性。随着大语言模型（LLM）的兴起，研究者尝试用学习式方法替代规则匹配，但面临两大瓶颈：一是模型难以精确捕捉数据依赖，常基于位置邻近性而非语义关联进行预测；二是生成式模型缺乏约束，容易输出输入代码中不存在的标识符或语句，违反切片必须为输入子序列的基本性质。

现有学习式切片方法主要分为两类：基于嵌入的分类方法与基于提示的生成方法。NS-slicer（Yadavally et al., 2024）利用 CodeBERT 和 GraphCodeBERT 计算语句嵌入，通过距离度量进行二元分类，但其非端到端设计限制了上下文利用，且嵌入目标与切片任务存在偏差。Shahandashti et al. (2024) 则采用 GPT-4o 等大模型结合检索增强生成（RAG）和思维链（CoT）提示，虽提升了灵活性，但幻觉问题严重，且计算成本高。本文的切入点在于指出，现有方法未显式建模数据流结构，且缺乏对生成过程的硬约束。SLICEFORMER 通过引入 DFG 感知的预训练目标，使模型在微调前即具备数据依赖理解能力，并通过约束解码在推理时强制保证输出的词法与句法正确性，从而在小型模型上实现高精度切片。

## 核心方法

### 序列到序列切片范式

本文将静态程序切片形式化为序列到序列学习问题。输入 $x = \{s_1, s_2, \dots, s_N; v; [n]\}$ 包含代码语句序列、切片准则变量 $v$ 及其行号 $[n]$，输出 $y = \{s_{i_1}, \dots, s_{i_k}\}$ 为影响 $v$ 的语句子序列。与 NS-slicer 的逐语句分类不同，本文采用端到端生成范式，利用 CodeT5+ 等小型语言模型直接生成完整切片。关键差异在于，本文不依赖预训练嵌入的相似度，而是通过生成过程显式建模语句间的依赖关系，并通过特殊标记（如 `<code>`, `<criterion>`, `<slice>`）引导模型输出结构化结果。

### 数据流感知预训练

为解决模型依赖表面模式而非数据流的问题，本文设计了两个基于 DFG 的预训练目标。首先，数据流保持语句置换（Dataflow-Preserving Statement Permutation）训练模型识别语句独立性。给定代码片段 $C$ 和 DFG，算法随机交换同一基本块内无数据依赖的语句对，生成等价变体 $C'$。模型需学习区分哪些语句可交换，从而理解数据依赖的本质。其次，数据流感知跨度损坏（Dataflow-Aware Span Corruption）通过 DFG 引导掩码，强制模型重构数据流链。具体而言，随机选择 DFG 中的变量节点 $v$，以 50% 概率掩码其父节点（定义处）或子节点（使用处），或以粗粒度掩码整个语句。这种掩码策略确保每个被掩码单元在语义上连贯，迫使模型学习变量级的细粒度依赖和语句级的粗粒度数据流。

$$
\text{Mask}(v) = \begin{cases}
\text{Parents}(v) \cup \text{Children}(v) & \text{if fine-grained} \\
\text{Stmt}(\text{Parents}(v)) \cup \text{Stmt}(\text{Children}(v)) & \text{if coarse-grained}
\end{cases}
$$

该公式表明，掩码操作严格遵循 DFG 的边关系，确保模型在重构时关注的是值的来源与去向，而非表面的文本模式。

### TSED 单调性约束解码

预训练赋予模型数据流理解能力，但不保证生成无幻觉。本文引入约束解码机制，在标准束搜索中施加词法与句法约束。词法约束将词汇表限制为输入代码中出现的 token，任何不在输入中的 token 被赋予 $-\infty$ 对数概率，确保输出是输入的严格子序列。句法约束基于树编辑距离相似度（TSED）的单调性。由于有效切片是输入代码的子序列，随着生成语句的增加，生成切片与输入代码的 AST 相似度应单调递增。TSED 定义为：

$$
\text{TSED}(T_x, T_y) = 1 - \frac{\min_{\text{ops}} \sum_{i=1}^{n} w(\text{op}_i)}{\max(\text{Nodes}(T_x), \text{Nodes}(T_y))}
$$

其中 $T_x, T_y$ 分别为输入和生成切片的 AST，$w(\text{op}_i)$ 为编辑操作成本。在束搜索中，每当生成一个完整语句，计算当前 TSED 分数。若分数低于前一个语句边界时的分数，表明出现结构错误（如语句顺序错误），该束路径被立即终止。这一机制有效过滤了词法正确但句法无效的候选，确保输出的结构连贯性。

## 实验评估

实验在 CodeNet-Slice 数据集的 Java 和 Python 子集上进行，使用 JavaSlicer 和 Python slicer 生成真值切片。基线包括 NS-slicer（基于 CodeBERT/GraphCodeBERT 的分类方法）、GPT-4o-mini 和 GPT-5（结合 RAG/CoT 提示的大模型），以及 CodeLlama-7B、Qwen3-8B 和 CodeT5+（直接微调的模型）。SLICEFORMER 在所有指标上均优于基线，尤其在精确匹配（ExactMatch）上表现突出。

| 方法 | Java ExactMatch (%) | Python ExactMatch (%) |
|---|---|---|
| NS-slicer (GraphBERT) | 85.77 | 61.25 |
| SLICEFORMER | 92.20 | 83.15 |

SLICEFORMER 在 Java 上超越最强基线 6.4 个百分点，在 Python 上超越 21.9 个百分点，表明数据流感知预训练与约束解码在两种语言上均有效。消融实验未提供详细数值，但论文指出，移除词法约束会导致幻觉 token 增加，移除 TSED 约束会导致结构错误率上升。评估边界方面，本文未报告计算开销，且未与传统静态分析工具（如 JavaSlicer）进行直接对比，仅将其作为真值生成器。此外，实验仅覆盖 Java 和 Python，未验证其他语言的泛化能力。

## 关联研究分析

从问题动机看，SLICEFORMER 与 NS-slicer 的核心差异在于任务建模方式。NS-slicer 将切片视为二元分类问题，依赖嵌入空间的距离度量，其性能受限于嵌入模型对数据流的理解能力。而 SLICEFORMER 将切片视为序列生成问题，通过 DFG 感知的预训练显式建模数据依赖，并通过约束解码保证输出正确性。这一差异源于任务特性：切片要求输出是输入的严格子序列，生成范式更自然地满足这一约束，而分类范式需额外处理语句顺序和完整性问题。

从方法设计看，SLICEFORMER 与 AST-T5 共享结构感知预训练的思想，但本文改用 DFG 而非 AST。AST 层级较深，包含大量语法细节，而 DFG 结构更简单，直接反映数据依赖，更适合切片任务。这一选择暗示，对于依赖敏感的任务，数据流结构比语法结构更具信息量。然而，论文未探讨 DFG 预训练在其他代码分析任务（如漏洞检测）中的泛化能力，也未分析 DFG 构建的开销对整体效率的影响。

## 总结

SLICEFORMER 针对学习式切片中依赖识别不准与生成幻觉两大痛点，通过 DFG 感知的预训练目标与 TSED 单调性约束解码，在小型模型上实现了高精度切片。该方法在 Java 和 Python 基准上分别取得 92.20% 和 83.15% 的精确匹配率，显著优于现有基线。其边界在于缺乏与传统静态分析工具的公平对比，且未报告计算开销，限制了其在大规模代码库中的适用性评估。当代码库规模增大时，DFG 构建与 TSED 计算的开销是否成为瓶颈，论文未给出回答。
