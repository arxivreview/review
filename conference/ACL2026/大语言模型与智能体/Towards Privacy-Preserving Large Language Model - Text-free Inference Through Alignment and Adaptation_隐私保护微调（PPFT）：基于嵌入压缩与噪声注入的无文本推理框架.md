# ACL2026最新论文 ｜Towards Privacy-Preserving Large Language Model: Text-free Inference Through Alignment and Adaptation ｜隐私保护微调（PPFT）：基于嵌入压缩与噪声注入的无文本推理框架

研究机构：韩国高丽大学

作者：Jeongho Yoon、Chanhee Park、Yongchan Chun 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.06831)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.06831)

> 导读 云端大语言模型（LLM）服务要求用户以明文传输提示词，导致敏感医疗或法律数据在传输、日志存储及潜在的训练复用中面临泄露风险。现有方案如文本改写或加密计算虽能缓解风险，但前者破坏语义连贯性，后者计算开销过大，且均未解决微调阶段的数据暴露问题。PPFT 通过客户端编码器将提示词转化为嵌入向量，经 $k$-Pooling 压缩与拉普拉斯噪声扰动后传输至服务器，使服务器端 LLM 直接基于混淆嵌入进行推理与领域适配，从而在接口层面彻底消除明文传输。该框架在敏感域问答任务中实现了接近无噪声上限的性能，但其隐私保证依赖于 $d\chi$-隐私核算而非标准差分隐私，且未验证多轮对话场景下的噪声累积效应。

## 研究背景

当用户向云端 LLM 提交包含病史或法律条文的提示词时，明文传输使得数据在信道拦截、服务器日志留存及内部人员访问中均暴露于风险之下。这种暴露不仅限于单次交互，更可能通过系统日志持久化或进入下游训练管道，构成持续的安全隐患。为应对此问题，差分隐私（Differential Privacy, DP）通过引入随机噪声限制算法输出对单个数据点的敏感性，提供了抵御成员推断攻击（Membership Inference Attack, MIA）的数学保证，但在 LLM 场景下，高维梯度噪声导致的效用崩塌迫使研究转向推理阶段的局部保护。

主流推理时隐私保护路线分为文本扰动与表示层扰动两类。文本扰动方法如 Paraphrase 通过改写提示词降低敏感度，但常因替换关键诊断线索导致任务性能显著下降；表示层方法如 Split-and-Denoise 在客户端执行嵌入层并注入噪声，但缺乏对服务器端模型的适配训练，导致语义信息在传输中丢失。此外，生成式反转攻击（Inversion Attack）证明，即使嵌入向量经过启发式噪声处理，攻击者仍可利用重建模型恢复语义忠实的原文，暴露了单纯嵌入传输缺乏强隐私保证的缺陷。PPFT 的切入点在于构建一个统一的“无文本”接口，不仅覆盖推理阶段，还延伸至领域微调阶段，通过训练服务器端解码器适应混淆嵌入，从而在保持语义连贯性的同时抵抗反转攻击。

## 核心方法

### 方法参照系

PPFT 属于推理时隐私保护路线，但偏离了标准局部差分隐私（Local Differential Privacy, LDP）流程。标准 LDP 直接扰动 Token 或文本，无需训练；而 PPFT 扰动连续嵌入向量，并引入两阶段对齐与适配训练。其核心差异在于将隐私保护从离散符号空间转移至连续表示空间，并通过模型适配弥补信息压缩带来的效用损失。

### 嵌入压缩与投影对齐

传统嵌入传输方案直接发送 Token 级嵌入，保留了过高的信息分辨率，易受反转攻击。PPFT 在客户端编码器输出后引入 $k$-Pooling 机制，将序列长度从 $n$ 压缩至 $m = \lceil n/k \rceil$，通过块均值聚合降低可恢复的 Token 级细节。压缩后的嵌入 $\mathbf{U}$ 经可训练投影层 $P_\psi$ 映射至解码器输入空间，形成连续前缀 $\mathbf{Z} = P_\psi(\mathbf{U})$。这一设计动机在于，通过降低表示的信息密度，增加攻击者重建原文的难度，同时通过投影层对齐编码器与解码器的潜在空间，使解码器能够基于连续向量而非离散 Token 进行语义条件生成。

$$
\mathbf{u}_j = \frac{1}{|I_j|} \sum_{i \in I_j} \mathbf{h}_i, \quad \mathbf{Z} = P_\psi(\mathbf{U})
$$

该公式表明，每个池化向量 $\mathbf{u}_j$ 是其对应 Token 块内隐藏状态的均值，投影层 $P_\psi$ 则负责维度匹配与语义对齐，确保解码器能直接从 $\mathbf{Z}$ 中提取生成所需的语义信息。

### 噪声注入与无文本域适配

仅靠压缩不足以抵御强攻击者，PPFT 在 Stage 2 引入拉普拉斯噪声注入。对于每个池化向量，采样方向均匀分布于单位球面、幅度服从 Gamma 分布（形状 $d_e$，率 $\epsilon$）的噪声，并进行 $L_2$ 归一化，得到混淆嵌入 $\tilde{\mathbf{U}}$。服务器端仅接收 $\tilde{\mathbf{U}}$ 与目标标签 $\mathbf{y}$，通过微调投影层与 LoRA 适配的解码器，使其学会在噪声干扰下解析语义。这一设计解决了此前方法中“噪声导致语义漂移”的失效问题，因为解码器在训练阶段已适应噪声分布，从而在推理时能更鲁棒地恢复任务性能。

$$
\tilde{\mathbf{U}} = \text{Norm}_2(\mathbf{U} + \mathcal{L}(\epsilon)), \quad \min_{\theta, \psi} -\log P(\mathbf{y} | P_\psi(\tilde{\mathbf{U}}), \theta)
$$

该公式表明，噪声注入后的嵌入 $\tilde{\mathbf{U}}$ 作为条件输入，解码器参数 $\theta$ 与投影层参数 $\psi$ 通过最小化目标序列的负对数似然进行联合优化，确保模型在隐私约束下仍能准确生成响应。

## 实验评估

实验在医疗（Pri-DDX, Pri-NLICE）与法律（Pri-SLJA）问答数据集上进行，基线包括 $d\chi$-privacy、Paraphrase 及 PrivacyRestore。PPFT 在 8B 解码器下取得最佳平均准确率 0.7314，显著优于 $d\chi$-privacy 的 0.2750 与 Paraphrase 的 0.3757。在 Pri-SLJA 上，PPFT 达到 95.6% 准确率，接近无噪声上限 94.66%（注：原文此处数值可能存在笔误，PPFT 高于上限，但趋势表明性能保持良好）。

| 方法 | 8B 平均准确率 | 1B 平均准确率 |
| --- | --- | --- |
| $d\chi$-privacy | 0.2750 | 0.2608 |
| Paraphrase | 0.3757 | 0.2635 |
| PrivacyRestore | 0.6343 | 0.4519 |
| PPFT | 0.7314 | 0.5699 |

消融实验显示，池化大小 $k$ 是性能-隐私权衡的关键控制变量。当 $k=4$ 时，任务得分最高（0.9049），但 ROUGE-L 也较高（0.4050），表明嵌入保留较多可恢复信息；随着 $k$ 增至 16，ROUGE-L 降至 0.3241，但任务得分降至 0.7630。噪声类型对比表明，拉普拉斯噪声在所有 $\epsilon$ 值下均比高斯噪声产生更低的 ROUGE-L，说明其在高维嵌入空间中更有效地破坏语义可重建性。

评估边界方面，PPFT 使用 $d\chi$-隐私核算而非标准 DP，其隐私保证强度与标准 DP 不可直接比较。实验未报告置信区间，且仅在单轮 QA 任务上验证，未涵盖多轮对话场景。代码未公开，超参数细节仅在附录中提供，限制了可复现性。

## 关联研究分析

从问题动机看，PPFT 与 Split-and-Denoise（Mai et al., 2023）均旨在消除明文传输，但后者仅保护推理阶段，且未训练服务器端模型适应噪声嵌入，导致语义信息在传输中丢失。PPFT 通过引入 Stage 1 对齐与 Stage 2 域适配，使解码器能够主动解析混淆嵌入，从而在保持隐私的同时提升任务效用。这一差异源于任务特性：敏感域 QA 对语义精确性要求极高，单纯噪声注入不足以维持性能，必须通过模型适配来补偿信息损失。

从方法设计看，PPFT 与 DP-Forward（Du et al., 2023）均使用噪声注入，但 DP-Forward 作用于前向计算中的中间激活，而 PPFT 作用于输入嵌入。DP-Forward 需要访问模型内部梯度，适用于白盒微调；PPFT 仅需客户端编码器与服务器端解码器的接口，适用于黑盒 API 场景。然而，PPFT 未对比标准 LDP 基线，其 $d\chi$-隐私核算的严格性是否优于标准 LDP 尚不明确。此外，PPFT 使用拉普拉斯噪声而非高斯噪声，这与 DP-SGD 中常用的高斯噪声不同，其选择可能源于嵌入空间的几何特性，但论文未提供理论依据。

## 总结

PPFT 旨在解决云端 LLM 服务中明文提示词传输导致的隐私泄露问题，现有方法或因语义破坏或因计算开销过大而失效。PPFT 通过客户端嵌入压缩与噪声注入，构建无文本接口，使服务器端 LLM 直接基于混淆嵌入进行推理与微调。实验表明，PPFT 在敏感域 QA 任务中实现了接近无噪声上限的性能，且对反转攻击具有强鲁棒性。然而，其隐私保证依赖于 $d\chi$-隐私核算，且未验证多轮对话场景下的噪声累积效应。当对话轮次增加时，嵌入噪声的累积是否会导致语义信息完全丢失，论文未给出回答。
