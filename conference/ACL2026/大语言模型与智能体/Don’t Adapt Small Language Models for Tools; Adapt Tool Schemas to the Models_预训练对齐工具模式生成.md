# ACL2026最新论文 ｜Don’t Adapt Small Language Models for Tools; Adapt Tool Schemas to the Models ｜预训练对齐工具模式生成

作者：Jonggeun Lee、Woojung Song、Jongwook Han 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_8da3161da580)

> 小语言模型（SLM）在工具调用中常因命名规范与预训练知识不匹配而生成不存在的工具名，即模式错位。现有训练方法成本高且易过拟合，无训练方法多聚焦描述优化而忽略名称本身。PA-Tool 借用数据污染检测中的峰值度信号，通过重命名工具组件以适配模型内部化知识，实现无训练的性能提升。该方法在特定子任务上显著优于微调基线，但其收益是否随模型规模扩大而消失，以及能否泛化至复杂多步依赖场景，仍存疑。

## 研究背景

工具调用要求模型从给定 API 列表中准确选择工具并填充参数。当模型面对陌生命名规范时，倾向于回退到预训练阶段内化的熟悉词汇，生成看似合理但实际不存在的工具名，这种现象称为模式错位（Schema Misalignment）。模式错位导致执行失败，且错误具有隐蔽性，因为生成的名称在语义上往往合理。

主流提升工具使用能力的路线分为训练基与无训练基。训练基方法如监督微调（SFT）和强化学习（RL）通过大量数据或算力优化策略，但面临数据标注成本高、分布外泛化差及计算资源受限等问题，尤其不适合边缘部署场景。无训练基方法如 EasyTool 通过重写工具描述提升清晰度，或 ToolLLM 通过检索修正错误，但这些方法未触及名称与模型内部知识的不匹配这一根本原因。PA-Tool 的切入点在于，不改变模型参数，而是改变工具接口，将工具名称重命名为模型在预训练中高频接触的模式，从而从源头消除模式错位。

## 核心方法

### 方法参照系

本文问题属于无训练工具文档优化范畴。标准流程如 EasyTool 通过 LLM 重写描述以提升可读性，但保留原始名称。PA-Tool 的关键差异在于，它不优化描述文本，而是基于模型自身的生成分布，重新生成并选择工具与参数的名称，使名称与模型内部化知识对齐。

### 候选名称生成与采样

传统方法直接采用人工命名或固定 API 名称，忽略了模型对特定词汇的熟悉度差异。PA-Tool 首先针对每个组件描述 $d$，引导模型 $M$ 以温度 $t \in (0, 1]$ 采样 $N$ 个候选名称 $C = \{s_1, s_2, \dots, s_N\}$。这一设计动机在于，温度采样能探索模型分布的尾部，揭示单一贪心解码无法捕捉的多样化命名模式，从而为后续熟悉度评估提供充分样本空间。

### 峰值度评分与名称选择

在获得候选集后，PA-Tool 计算每个候选名称的峰值度（Peakedness）。峰值度定义为在字符级编辑距离阈值 $\alpha$ 下，与当前候选 $s_i$ 相似的候选数量：

$$
P(s_i) = \sum_{j \neq i} \mathbb{I}(d_{edit}(s_i, s_j) \leq \alpha)
$$

其中 $\mathbb{I}$ 为指示函数，$d_{edit}$ 为 Levenshtein 距离。该公式的物理含义是，若某名称周围聚集了大量相似变体，说明该命名模式在模型预训练分布中占据局部最大值，即模型对该模式高度熟悉。PA-Tool 选择峰值度最高的候选 $s^* = \arg\max_{s_i \in C} P(s_i)$ 作为新名称。这一机制解决了传统频率统计（MostFreq）仅关注绝对出现次数而忽略分布集中度的缺陷，例如在“diet_tracker”（5次）与“diet_insights”（4次但周围有4个相似变体）之间，PA-Tool 选择后者，因为后者代表了更紧密的分布簇，更符合模型的自然生成偏好。

## 实验评估

实验在 MetaTool 和 RoTBench 上进行，基线涵盖 Base、Greedy、MostFreq、Human、SFT、EasyTool、BM25 及 ToolLLM。缺失 RLVR 类强基线（如 Tool-R1），但考虑到 PA-Tool 定位为无训练方法，与 SFT 的对比更具针对性。

| 模型 | 方法 | MetaTool Reliability | MetaTool Multi-tool | RoTBench Single-turn Tool Sel |
| :--- | :--- | :--- | :--- | :--- |
| Llama3.2-3B | Base | 43.6 | 79.1 | 56.2 |
| Llama3.2-3B | PA-Tool | 60.6 | 80.5 | 62.9 |
| Llama3.1-8B | Base | 53.5 | 78.7 | 58.1 |
| Llama3.1-8B | PA-Tool | 66.0 | 88.3 | 68.6 |

数据显示，PA-Tool 在 Reliability 子任务上提升最显著（Llama3.2-3B 提升 17.0%），因为该任务要求模型识别“无合适工具”，对名称理解的准确性要求极高。在 Multi-tool 任务中，Llama3.1-8B 达到 88.3%，超过所有闭源模型基线（如 Claude-Sonnet-4.5 的 85.1%），表明名称对齐在多工具组合场景下具有累积优势。

消融实验显示，工具名称对齐主要提升工具选择，参数名称对齐主要提升参数识别，两者联合使用效果最佳。例如，Llama3.1-8B 在联合配置下，RoTBench 单轮工具选择从 58.1% 提升至 68.6%。值得注意的是，PA-Tool 单独使用在 Reliability 和 Multi-tool 上优于 SFT1 和 SFT2，且 SFT2 在 RoTBench 上出现性能下降（59.1% vs 61.0%），暗示额外训练数据可能导致过拟合，而 PA-Tool 避免了这一风险。

评估边界方面，实验主要聚焦于单轮或少量多轮交互，未覆盖长程依赖任务。指标以准确率为主，未报告置信区间，且多数结果基于单次运行。可复现性良好，代码开源，超参数（如 $N=32-64$, $\alpha=0.2$）明确，生成时间仅需 8-16 秒，适合一次性预处理。

## 关联研究分析

从问题动机看，PA-Tool 与 EasyTool 形成互补而非替代关系。EasyTool 通过重写描述提升语义清晰度，解决“模型不理解工具功能”的问题；PA-Tool 通过重命名解决“模型不熟悉工具名称”的问题。实验表明，两者结合在 RoTBench 参数识别上取得最佳效果（Qwen2.5-3B 从 7.6% 提升至 19.1%），证明名称对齐与描述优化是正交维度。然而，PA-Tool 未探索描述与名称的联合优化策略，仅验证了简单叠加，这可能限制了其在复杂语义场景下的潜力。

从方法设计看，PA-Tool 与 CDD（Contamination Detection）共享峰值度机制，但目标不同。CDD 用于检测数据污染，PA-Tool 用于优化接口。关键差异在于，CDD 关注特定文本的重复性，而 PA-Tool 关注命名模式的分布集中度。这种迁移是否适用于长尾工具（即预训练中出现频率极低的工具）存疑，因为峰值度依赖局部聚集，长尾工具可能缺乏足够的相似变体，导致峰值度信号失效。论文未提供长尾工具的具体实验数据，这一盲区限制了方法在大规模异构工具库中的适用性。

## 总结

PA-Tool 解决了 SLM 工具调用中模式错位导致的执行失败问题，其核心在于将数据污染检测中的峰值度机制转化为名称对齐信号，通过重命名工具组件以适配模型预训练知识。实验证明，该方法在无训练条件下，于 MetaTool Reliability 子任务上提升 17.0%，在 RoTBench 单轮工具选择上提升 10.5%，且优于 SFT 基线。其边界在于，收益随模型规模扩大而递减（LLM 上提升较小），且未验证在长程多步依赖任务中的鲁棒性。当工具库规模扩大至数万级且包含大量长尾工具时，峰值度信号是否仍能准确识别模型熟悉模式，论文未给出回答。
