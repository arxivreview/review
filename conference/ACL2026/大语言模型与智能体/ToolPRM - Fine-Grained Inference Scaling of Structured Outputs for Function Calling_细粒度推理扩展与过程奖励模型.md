# ACL2026最新论文 ｜ToolPRM: Fine-Grained Inference Scaling of Structured Outputs for Function Calling ｜细粒度推理扩展与过程奖励模型

研究机构：上海交通大学

作者：Jianghao Lin、Yuanyuan Shi、Xin Peng 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.14703)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.14703)

> 工具调用智能体在推理时面临计算资源分配与输出可靠性的矛盾，现有推理扩展方法多针对非结构化文本，忽略了函数调用中早期错误不可恢复的特性。本文切入点在于将函数调用拆解为语义明确的中间步骤，并训练专用过程奖励模型（Process Reward Model, PRM）进行细粒度评分。通过结合束搜索（Beam Search）与“多探索少保留”原则，ToolPRM 在 BFCL 基准上使 7B 模型性能超越 32B 基线。该方法验证了细粒度监督在结构化输出中的有效性，但其泛化能力与动态适应性仍存疑。

## 研究背景

函数调用是智能体执行外部动作的核心机制，其输出为严格的结构化 JSON 格式。与传统自由文本生成不同，函数调用中的函数名选择、参数名识别及参数值填充构成一个强依赖的序列，任何一步的错误（如选错函数）都会导致后续步骤失效且无法通过后续反思修正。这种“不可恢复性”使得简单的多路径采样策略在结构化任务中效率低下，因为大量计算资源被浪费在注定失败的轨迹上。

推理扩展（Inference Scaling）旨在通过增加推理时计算量来提升模型性能，主流方法如束搜索和蒙特卡洛树搜索（MCTS）通常依赖结果奖励模型（Outcome Reward Model, ORM）或粗粒度过程奖励模型进行路径剪枝。然而，现有研究主要聚焦于数学推理等非结构化任务，其中中间步骤错误可被后续步骤修正。在函数调用场景中，将整轮调用视为原子单元进行评分的粗粒度方法（如 Best-of-N）无法定位具体错误环节，导致搜索策略无法精准区分“函数名正确但参数错误”与“函数名错误”这两种截然不同的失败模式，从而限制了推理扩展在结构化任务中的收益。

## 核心方法

### 方法参照系

本文问题属于推理时优化范畴，与训练阶段的强化学习不同，其核心在于不更新模型权重，仅通过调整解码策略提升单次推理质量。标准流程为：生成候选轨迹 -> 使用奖励模型评分 -> 选择最优轨迹。本文的关键差异在于将“轨迹”定义从整轮函数调用细化为单次调用内部的语义步骤，并引入状态转移机制以支持细粒度评分。

### 细粒度状态分解与标注

针对粗粒度 ORM 无法定位错误环节的问题，ToolPRM 将函数调用过程形式化为五个状态：初始状态、选择函数名、填充参数名、填充参数值及终止状态。每个状态转移对应一个二元奖励标签，如 `<FUNC_NAME>` 表示函数名选择是否正确，`<ARG_VALUE>` 表示参数值填充是否正确。这种分解使得奖励信号从稀疏的最终结果转变为密集的中间步骤反馈。训练数据通过函数掩码（Function Masking）技术生成，即用随机字符串替换函数名和参数标识符，迫使模型依赖上下文描述而非记忆工具名称，从而增强泛化能力。数据集规模达 192,061 样本，平均每样本包含 6.25 个步骤标签，远超数学 PRM 数据集规模。

### 生成式过程奖励建模与束搜索

ToolPRM 采用生成式方式预测每个步骤的正确性，其训练目标为最小化预测标签与真实标签的交叉熵损失：

$$ \mathcal{L} = -\sum_{t=1}^{T} \log P(r_t | s_t, a_t) $$

其中 $r_t \in \{0, 1\}$ 为步骤 $t$ 的正确性标签，$s_t$ 为当前状态，$a_t$ 为动作。该公式意味着模型需根据当前上下文预测下一步决策的正确概率，而非仅判断最终结果。在推理阶段，ToolPRM 引导束搜索：在每步生成时，保留 $M$ 个最高分候选，但仅保留 $N$ 个进入下一步（$N < M$）。这一“多探索少保留”策略基于结构化输出的不可恢复性：宽束宽（$M$）确保探索多样性，窄保留数（$N$）避免在错误分支上浪费后续计算资源。实验表明，该策略在 BFCL 上使 Hammer2.1-7B 模型的平均准确率从 88.65% 提升至 89.52%，超越 Qwen2.5-32B-Instruct 的 87.21%。

## 实验评估

实验在 BFCL 和 ToolAlpaca 基准上进行，基线涵盖通用模型（GPT-4o, Qwen2.5 系列）、函数调用专用模型（Hammer2.1, xLAM）及推理扩展策略（束搜索、多数投票、Best-of-N）。ToolPRM 在 BFCL 平均准确率上表现最优，Hammer2.1-7B+ToolPRM 达到 89.52%，显著高于基线 88.65% 及 Best-of-N 的 88.27%。在 ToolAlpaca 上，Hammer2.1-3B+ToolPRM 的 F1 分数为 71.96%，高于基线 71.57%。

| 模型 | BFCL Avg. | ToolAlpaca Avg. |
| :--- | :--- | :--- |
| Hammer2.1-7B (Base) | 88.65 | 72.77 |
| + Best of N (ORM) | 88.27 | 72.15 |
| + ToolPRM (Ours) | 89.52 | 73.30 |

消融实验显示，细粒度监督对预测准确率的提升显著。ToolPRM 的步骤准确率（Step Acc）为 99.11%，轨迹准确率（Trajectory Acc）为 99.38%，均高于 C-PRM 的 98.87% 和 99.06%，以及 ORM 的 98.39%。这表明细粒度标签不仅提升了中间步骤的判断精度，还通过更密集的监督信号改善了整体序列的正确性预测。值得注意的是，ToolPRM 的模型损失（0.0286）低于 C-PRM（0.0371）和 ORM（0.0536），验证了细粒度分解在降低预测不确定性方面的有效性。

评估边界方面，实验仅使用 BFCL 和 ToolAlpaca 两个基准，未涵盖动态环境或噪声场景。可复现性上，论文提供了代码与模型检查点，但束搜索参数（$N, M$）的选取范围有限（1-16），未探讨更大搜索空间下的性能饱和点。

## 关联研究分析

从问题动机看，ToolPRM 与 Tool-R1 等基于强化学习（RL）的方法形成互补。Tool-R1 通过环境交互优化策略权重，侧重训练阶段的泛化能力；而 ToolPRM 聚焦推理时计算分配，不改变模型参数。两者在“细粒度奖励”上共识一致，但 ToolPRM 的奖励信号仅用于搜索引导，而非策略更新，这使其在部署成本上更低，但可能无法解决模型内在的推理缺陷。

从方法设计看，ToolPRM 与 REST 等静态奖励整形方法存在差异。REST 通过调整 token 权重解决收敛不稳定问题，属于训练阶段优化；ToolPRM 则通过动态束宽调整解决推理时计算浪费问题。ToolPRM 的“多探索少保留”原则是否适用于所有结构化任务（如代码生成、SQL 查询），论文未给出回答。此外，ToolPRM 依赖函数掩码增强鲁棒性，但未验证在未见过的工具描述或复杂嵌套调用场景下的表现，其泛化边界尚不明确。

## 总结

ToolPRM 解决了结构化函数调用中推理扩展的计算效率与可靠性矛盾，通过细粒度状态分解与生成式 PRM 实现精准路径剪枝。该方法在 BFCL 上使 7B 模型性能超越 32B 基线，验证了“多探索少保留”原则的有效性。然而，实验局限于静态基准，未探讨动态噪声环境下的鲁棒性，且束搜索参数固定，缺乏自适应调整机制。当工具库规模扩大至万级且包含噪声描述时，ToolPRM 的细粒度评分是否仍能保持高效，论文未给出回答。
