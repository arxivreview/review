# ACL2026最新论文 ｜BrowseComp-Plus: A Fair and Disentangled Evaluation Benchmark for Deep Search Agents ｜深度搜索智能体评估基准

作者：Zijian Chen、Xueguang Ma、Shengyao Zhuang 等 21 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ae168fed3f3a)

> 深度搜索智能体（Deep Search Agents, DSA）在复杂多跳查询中表现优异，但现有基准依赖黑盒网络搜索 API，导致评估缺乏公平性与可复现性，且无法解耦检索器与智能体的独立贡献。本文通过构建固定、人工验证的文档语料库，将动态网络评估转化为受控检索环境，实现了检索与智能体贡献的显式分离。该基准揭示了检索质量对智能体效率与准确率的决定性影响，但其固定语料协议与真实网络动态性之间的外推有效性仍存疑。

## 研究背景

深度搜索智能体通过迭代查询推理、搜索规划与结果反思，超越了传统单次检索增强生成（RAG）的局限。然而，评估此类智能体时，黑盒网络 API 引入了两个维度的不透明性：文档语料的动态变化（页面增删改）与检索算法的不可见性。这种不透明性使得不同智能体在相同基准上的比较失去公平性，因为基准难度随时间漂移，且不同提供商的检索策略差异无法被量化。

现有基准如 BrowseComp 虽设计了高难度事实查询，但依赖实时网络检索，导致无法隔离检索器对最终准确率的贡献。随着大语言模型（LLM）能力增强，检索研究者开始质疑更强检索器的边际收益是否递减，但缺乏固定语料环境使得这一假设无法被严格验证。本文切入点在于将经典 Cranfield 范式扩展至现代深度搜索评估，通过固定语料实现检索与智能体贡献的解耦，为公平比较提供基础设施。

## 核心方法

### 方法参照系

传统信息检索评估采用固定语料库与标准查询集，通过 Recall 和 nDCG 衡量检索效果。本文问题与该通用流程的关键差异在于：评估对象从静态检索系统扩展为动态多轮智能体，需同时量化智能体的推理能力与检索器的证据获取能力，且语料需包含足够硬负例以维持检索挑战性。

### 固定语料构建与硬负例挖掘

设计动机在于解决黑盒 API 导致的语料动态性与检索算法不透明性。本文采用两阶段流水线：首先利用 OpenAI o3 模型反向工程，提供答案与问题，搜索支持证据的网页并结构化输出线索-URL-证据表格；随后人工验证者标注文档中支持每个线索的文本跨度，并确认线索组合足以回答完整问题。对于硬负例，将原始问题分解为约 7 个子查询，通过 Google Search API 获取每个子查询的前 100 个结果，形成干扰文档。最终语料包含 100,195 个文档与 830 个查询，平均每个查询含 6.1 个证据文档、76.28 个负例与 2.9 个金文档。

$$
\text{Corpus} = \bigcup_{q \in Q} \left( D_{\text{evidence}}(q) \cup D_{\text{negative}}(q) \cup D_{\text{gold}}(q) \right)
$$

该公式表示语料库由所有查询的证据文档、负例文档与金文档的并集构成，其中金文档定义为语义上包含最终答案的文档，而非仅字符串匹配。

### 解耦评估协议

设计动机在于量化检索器对智能体性能的独立贡献。本文定义三种评估模式：无检索器（仅参数化知识）、BM25 稀疏检索、Qwen3-Embedding-8B 稠密检索。智能体被提示使用提供的检索工具，并引用来源以评估引用质量。检索工具设置为返回前 k=5 个结果，每个结果截断至前 512 个 token。通过比较同一智能体在不同检索器下的准确率与搜索调用次数，可解耦检索器贡献。

$$
\Delta \text{Accuracy} = \text{Acc}(\text{Agent}, \text{Retriever}_{\text{strong}}) - \text{Acc}(\text{Agent}, \text{Retriever}_{\text{weak}})
$$

该公式表示检索器贡献的量化指标，即强检索器与弱检索器下同一智能体准确率的差值，直接反映检索质量对最终答案正确性的影响。

## 实验评估

实验在 BrowseComp-Plus 基准上进行，评估 GPT-5、o3、GPT-4.1、Opus 4、Sonnet 4、Gemini 2.5 Pro/Flash、Qwen3-32B、Search-R1-32B 与 gpt-oss-120B 等智能体，搭配 BM25、Qwen3-Embedding-0.6B/4B/8B、ReasonIR-8B 与 JinaColBERT-v2 等检索器。基线覆盖闭源与开源智能体，但缺失多智能体架构如 WebWeaver，可能低估复杂规划能力。

| LLM | Retriever | Accuracy | # Search | C.E. | Recall |
| :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-5 | None | 1.69% | - | 40.92% | - |
| GPT-5 | BM25 | 14.34% | 9.95 | 29.79% | 21.31% |
| GPT-5 | Qwen3-Embed-8B | 36.75% | 9.03 | 24.51% | 47.33% |
| o3 | None | 26.18% | - | 24.57% | - |
| o3 | BM25 | 55.90% | 23.23 | 13.50% | 61.70% |
| o3 | Qwen3-Embed-8B | 70.12% | 21.74 | 9.11% | 78.98% |

核心数字对比显示，o3 搭配 Qwen3-Embedding-8B 达到 70.12% 准确率，较 BM25 提升 14.22 个百分点，同时搜索调用次数从 23.23 降至 21.74，表明更强检索器不仅提升效果，还提高效率。

| Retriever | R@5 | R@100 | R@1000 | nDCG@10 |
| :--- | :--- | :--- | :--- | :--- |
| BM25 | 1.2 | 4.7 | 13.7 | 1.6 |
| Qwen3-Embed-8B | 14.5 | 47.7 | 76.7 | 20.3 |
| ReasonIR-8B | 12.2 | 43.6 | 73.9 | 16.8 |

消融实验显示，Qwen3-Embedding 家族存在清晰的模型规模缩放律，8B 模型在 R@5 上达到 14.5，远超 BM25 的 1.2。ReasonIR-8B 在推理密集查询上表现略低于 Qwen3-Embedding-8B，但优于 BM25，表明专用训练对推理检索有增益但非决定性。

评估边界方面，指标涵盖准确率、搜索调用次数、校准误差、召回率、引用召回率与引用比例，但未报告计算成本与延迟。评估协议局限在于固定语料可能无法反映真实网络动态性，且文档截断至 512 token 可能丢失关键证据。可复现性方面，代码与数据已公开，但人工验证过程耗时 400 小时，难以完全复现标注细节。

## 关联研究分析

从问题动机看，BrowseComp-Plus 与 GAIA 均针对长程任务评估，但 GAIA 依赖实时网络浏览，而本文采用固定语料。这一差异根源在于任务特性：GAIA 强调真实世界导航能力，而本文聚焦检索与智能体贡献的解耦。固定语料牺牲了动态性，但换来了可复现性与公平性，这在检索研究社区更受重视，但在智能体研究社区可能被认为过于简化。

从方法设计看，本文与 Search-R1 等 RL 训练方法形成互补。Search-R1 通过强化学习优化搜索策略，但依赖黑盒 API 评估，无法量化检索器贡献。本文提供固定检索环境，使 RL 智能体与非 RL 智能体可在相同条件下比较。然而，本文仅评估单智能体架构，未探索多智能体协作在固定语料下的表现，这可能低估了复杂规划能力。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文要解决的核心矛盾是深度搜索智能体评估中检索器与智能体贡献的不可解耦性。现有黑盒 API 基准无法隔离检索质量的影响，而本文通过固定、人工验证的语料库实现了这一解耦。本文构建了包含 100,195 个文档的 BrowseComp-Plus 基准，并证明更强检索器可提升智能体准确率并减少搜索调用。其边界在于固定语料协议与真实网络动态性之间的外推有效性未经验证，且仅评估单智能体架构。当语料库规模扩大至百万级文档时，检索效率与智能体推理能力的权衡关系是否改变，论文未给出回答。
