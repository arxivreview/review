# ACL2026最新论文 ｜ToolOmni: Enabling Open-World Tool Use via Agentic learning with Proactive Retrieval and Grounded Execution ｜开放世界工具使用中的主动检索与解耦强化学习

研究机构：哈尔滨工业大学

作者：Shouzheng Huang、Meishan Zhang、Baotian Hu 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.13787)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_9175e502c8e5)

> 开放世界场景下，海量且动态更新的工具库使得静态嵌入检索难以对齐用户意图，而参数化记忆工具文档的方法又无法泛化至未见工具。现有方案要么将检索与执行割裂为独立流水线，要么在有限工具集上应用强化学习，导致大规模场景下的端到端性能受限。ToolOmni 通过构建“主动检索-接地执行”的统一智能体框架，并采用解耦多目标 GRPO 算法同步优化两个子任务，解决了检索精度与执行鲁棒性的协同优化难题。该框架在 ToolBench 上实现了显著的检索与执行提升，但其级联架构在极端复杂任务中的灵活性及小模型扩展性仍存疑。

## 研究背景

当智能体面对包含数万 API 的开放世界工具库时，传统的基于语义相似度的单次嵌入检索往往因浅层匹配而漏选关键工具，导致后续执行阶段因缺少必要功能而失败。这种检索与执行的脱节源于被动检索范式：检索过程独立于智能体的推理逻辑，无法根据任务进展动态调整查询策略。为突破此局限，近期研究转向基于可验证奖励的强化学习（RLVR），旨在通过环境交互赋予模型自主规划能力。然而，现有 RLVR 工作多局限于搜索引擎或代码解释器等封闭工具集，且常将检索视为前置静态步骤，未将其纳入策略优化的核心循环。

该领域的核心矛盾在于：如何在动态、大规模的工具生态中，实现检索精度与执行鲁棒性的端到端协同优化。主流 SFT 范式依赖人工标注轨迹，在分布外（OOD）任务上泛化能力差；而纯 RL 方法虽能探索未知策略，但面临奖励稀疏与训练不稳定的挑战。ToolOmni 的切入点在于将“主动检索”重构为智能体可执行的动作，而非外部预处理步骤，并通过解耦奖励机制，使模型在强化学习过程中同时优化“找对工具”与“用对工具”两项能力，从而在开放世界场景中实现更优的泛化与鲁棒性。

## 核心方法

### 级联检索-执行架构

ToolOmni 将开放世界工具使用建模为级联过程，区别于传统流水线中检索与执行的物理隔离。其核心差异在于：检索不再是单次静态操作，而是由策略 $\pi_\theta$ 驱动的迭代式主动查询。智能体在每一轮交互中，先通过推理生成检索查询 $q_t$，调用嵌入模型获取候选工具，再基于反馈决定是继续检索还是进入执行阶段。这种设计解决了被动检索无法根据任务上下文动态调整搜索意图的问题，使模型能够主动过滤噪声工具，确保进入执行阶段的工具集 $T_{sub}$ 具备任务完备性。

### 解耦多目标 GRPO 优化

针对检索与执行目标冲突导致的梯度干扰，ToolOmni 提出解耦多目标 GRPO 算法。传统 GRPO 使用单一奖励信号，难以区分检索失败与执行错误的责任归属。本文创新性地计算独立的检索奖励 $R_{ret}$ 与执行奖励 $R_{exec}$，并分别计算优势函数后整合至单一优化目标。检索奖励由格式合规性、真值工具召回率及转化效率加权构成：

$$ R_{ret} = \alpha_1 \cdot r_{fmt}^{ret} + \alpha_2 \cdot r_{rec} \cdot r_{conv} $$

其中 $r_{rec}$ 衡量累计检索集对真值工具 $T_{gold}$ 的召回，$r_{conv}$ 奖励最终选入 $T_{sub}$ 的工具比例。执行奖励则聚焦于格式有效性与答案正确性：

$$ R_{exec} = \beta_1 \cdot r_{fmt}^{exec} + \beta_2 \cdot r_{ans} $$

这种解耦设计提供了细粒度的过程监督，确保检索召回与执行推理被独立优化，避免了联合更新中可能出现的破坏性梯度冲突，从而在复杂多步任务中提升了策略收敛的稳定性。

## 实验评估

ToolOmni 在 ToolBench 基准上进行了全面评估，基线涵盖 BM25、ToolRetriever、ToolGen 及 GPT-3.5 流水线。实验设置采用 Qwen3-4B-Instruct 作为骨干模型，在 8 块 NVIDIA H100 GPU 上训练。主实验结果显示，ToolOmni 在检索任务上取得了显著优势，尤其在多领域（Multi-Domain）设置下，平均 NDCG@5 达到 78.29%，远超 ToolRetriever 的 76.44% 和 ToolGen 的 68.64%。在执行任务上，端到端设置下的可解通过率（SoPR）为 54.13%，较 GPT-3.5 流水线的 42.35% 提升 11.78 个百分点，且可解胜率（SoWR）达到 50.16%，显著优于开源基线 ToolLlama-v2 的 35.90%。

| 方法 | 检索 NDCG@5 (Multi-Domain) | 执行 SoPR (End-to-End) | 执行 SoWR (End-to-End) |
| :--- | :--- | :--- | :--- |
| ToolRetriever | 76.44 | - | - |
| ToolGen | 68.64 | 36.10 | - |
| GPT-3.5 Pipeline | - | 42.35 | 39.77 |
| ToolOmni | 78.29 | 54.13 | 50.16 |

消融实验揭示了关键设计决策的有效性。移除强化学习阶段导致检索 NDCG 下降 28.99%，表明检索质量主要依赖 RL 探索而非 SFT 模仿；而移除 SFT 冷启动则使执行 SoPR 从 52.50% 降至 43.40%，证实 SFT 为 RL 提供了必要的推理基础。此外，移除轨迹过滤机制导致 SoPR 骤降至 38.5%，说明在无效上下文中训练会严重损害模型推理能力。解耦优化相比联合更新（Combined Update）提升了 9.9 个百分点的 SoPR，验证了独立奖励设计在避免梯度冲突方面的必要性。

评估边界方面，ToolOmni 仅在 Qwen3-4B 小模型上验证，未探索更大规模模型的扩展性；评估指标依赖 GPT-5 裁判，可能存在主观偏差；代码已开源，但超参数敏感性分析仅覆盖检索数量 $k$，未深入探讨奖励权重 $\alpha, \beta$ 的交互影响。

## 关联研究分析

从问题动机看，ToolOmni 与 Tool-R1 同属 RLVR 路线，但 Tool-R1 聚焦于封闭工具集下的样本高效训练，而 ToolOmni 将场景扩展至开放世界大规模工具库。两者的核心差异在于检索机制：Tool-R1 依赖静态检索或预定义工具集，而 ToolOmni 将检索本身作为可学习的动作，通过迭代查询动态调整工具集。这一差异源于任务特性：开放世界场景下工具数量庞大且动态变化，静态检索无法保证召回率，而主动检索允许模型根据推理进展实时补充缺失功能。

从方法设计看，ToolOmni 与 CoHyDE 在检索优化策略上形成互补。CoHyDE 采用协同训练机制，通过迭代更新检索器与规划器以对齐需求，侧重于检索器本身的参数优化；而 ToolOmni 保持嵌入模型冻结，仅优化智能体的查询生成策略，侧重于利用现有检索基础设施的灵活性。这种设计选择反映了不同的技术假设：CoHyDE 认为检索器需要适应特定任务分布，而 ToolOmni 认为通用嵌入模型已具备足够能力，关键在于智能体如何高效利用其输出。查询侧增强在数据充足时是否仍能超越检索器参数优化，论文未给出直接对比回答。

## 总结

ToolOmni 旨在解决开放世界工具使用中检索精度与执行鲁棒性难以协同优化的核心矛盾。现有方法或因检索被动导致工具缺失，或因奖励耦合导致训练不稳定，而 ToolOmni 通过主动检索机制与解耦多目标 GRPO 算法，实现了两个子任务的独立优化与同步提升。实验证明，该框架在 ToolBench 上取得了 78.29% 的检索 NDCG@5 和 54.13% 的端到端 SoPR，显著优于静态检索与联合优化基线。然而，其级联架构限制了在需要基于中间结果动态发现工具链的极端复杂任务中的灵活性，且仅在 4B 小模型上验证了有效性。当骨干模型规模扩大至 70B 以上时，解耦奖励机制是否仍能保持梯度稳定性，以及主动检索带来的额外计算开销是否会被更大的推理能力所抵消，论文未提供相关证据。
