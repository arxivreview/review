# ACL2026最新论文 ｜Mem$^2$Evolve: Towards Self-Evolving Agents via Co-Evolutionary Capability Expansion and Experience Distillation ｜能力-经验共进化智能体

研究机构：北京航空航天大学、北京理工大学

作者：Zihao Cheng、Zeming Liu、Yingyu Shan 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.10923)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.10923)

> 自进化智能体需在开放环境中持续扩展能力边界，但现有框架将经验积累与资产创建割裂，导致静态工具集限制或无引导生成的不稳定。Mem[2] Evolve 通过双记忆机制耦合这两者，实现能力与经验的协同进化。其核心在于经验引导资产创建、资产执行反哺经验蒸馏的闭环。该框架在8个基准上验证了协同进化的优势，但缺乏对参数化进化路线的同预算对比，且经验引导对资产多样性的潜在抑制未被量化。

## 研究背景

当智能体面对超出预定义工具集的任务时，其执行能力受限于静态资产库——这一现象称为能力边界固化。为突破此限制，动态资产创建成为必要路径，但无经验引导的从零生成往往导致重复错误与不可复现的成功。解决这一矛盾的关键在于建立经验与能力的双向反馈：经验指导资产创建的可行性，资产执行产生新经验以优化后续策略。

自进化智能体领域长期存在两条孤立路线：经验中心进化（如 AFlow、ReasoningBank）通过优化提示或检索记忆提升执行效率，但工具集固定导致能力空间静态；能力中心进化（如 Alita、ToolMaker）动态生成新工具或专家代理，但缺乏经验约束导致资产质量不稳定。这种割裂使得单一路线无法兼顾能力扩展的广度与执行策略的稳定性。Mem[2] Evolve 的切入点在于将两者耦合为共进化闭环，使经验不仅优化执行，更直接指导资产创建，而新资产的成功执行又反哺经验库，形成持续进化的正反馈。

## 核心方法

### 双记忆架构与资产表示

Mem[2] Evolve 的核心是 Asset Memory ($M_A$) 与 Experience Memory ($M_E$) 的协同。Asset Memory 存储可执行资产，包括专家代理库 $B_{agt}$ 与工具库 $B_{tool}$。每个工具条目 $m_{tool} \in B_{tool}$ 定义为：

$$
m_{tool} = \langle n, d_{func}, c_{impl}, \omega_{doc} \rangle
$$

其中 $n$ 为工具名称，$d_{func}$ 为功能描述，$c_{impl}$ 为符合 Model Context Protocol (MCP) 的实现代码，$\omega_{doc}$ 为输入输出文档。这一设计动机在于解决能力中心进化中资产缺乏标准化接口导致的集成困难，通过 MCP 合规性确保新工具能无缝接入不同 LLM 骨干。

### 经验引导的资产创建与验证

在 Forward Inference 阶段，当子任务 $s_i$ 与 Asset Memory 相似度低于阈值 $\delta$ 时，系统触发经验引导的资产创建。工具创建过程条件化于子任务、网络搜索结果及 Experience Memory 中的相关经验 $e \in E_{tool}$：

$$
m_{new} = \pi_\theta(s_i, \text{WebSearch}(s_i), e)
$$

这一设计解决了无引导生成中“重复错误”的问题，通过经验约束将生成空间限定在已验证的可行解附近。创建后的资产需通过 Self-Correction Loop 验证：LLM 基于批评 $c_t$ 合成测试用例，执行 $m_{new}$ 直至通过所有测试，最终版本 $m_{final}$ 存入 Asset Memory。该机制确保只有高可靠性资产进入持久记忆，避免低质量资产污染后续进化。

### 轨迹反思与经验蒸馏

Backward Evolution 阶段通过 LLM-as-a-Judge 评估轨迹 $\tau_t$ 与答案 $a_t$，生成成功标志 $r_t \in \{0,1\}$ 与批评 $c_t$。经验蒸馏函数 $Reflection(\tau_t, r_t, c_t)$ 从成功轨迹中提取策略指导，从失败轨迹中编码反模式与修复对：

$$
e_{new} = Reflection(\tau_t, r_t, c_t) \rightarrow M_E
$$

这一设计动机在于解决经验中心进化中“经验仅用于提示优化”的局限，使经验不仅指导执行，更直接约束资产创建。通过区分 Agent Experience（策略洞察）与 Tool Experience（实现指南），经验库实现了细粒度的知识复用，避免了粗粒度反思导致的上下文噪声。

## 实验评估

实验在 GAIA、ALFWorld、HotpotQA、AIME 等 8 个基准上进行，所有方法统一使用 GPT-5-chat 作为骨干，确保公平对比。基线覆盖三类：Naive LLM（ReAct、CoT）、经验中心进化（AFlow、DSPy）与能力中心进化（Alita、AgentVerse）。Mem[2] Evolve 在平均 Pass@1 上达到 70.24%，超越最强能力中心基线 Alita 6.46%，超越经验中心基线 AFlow 11.80%。在 GAIA 上，Mem[2] Evolve 取得 76.31%，而 Alita 为 67.36%，AFlow 为 19.75%，表明协同进化在复杂通用任务上的优势显著。

| 方法 | GAIA | ALFWorld | HotpotQA | AIME24 | Avg. Pass@1 |
| --- | --- | --- | --- | --- | --- |
| Mem2Evolve | 76.31 | 94.31 | 82.00 | 59.25 | 70.24 |
| Alita | 67.36 | 86.13 | 77.40 | 48.32 | 63.78 |
| AFlow | 19.75 | 92.50 | 60.80 | 49.55 | 58.44 |
| ReAct | 18.47 | 81.80 | 39.13 | 27.49 | 41.40 |

消融实验显示，移除 Tool Creation 导致性能下降 10.28%，移除 Agent Memory 下降 4.73%，表明动态工具扩展与经验记忆对性能贡献最大。经验引导对资产创建质量的影响显著：在 GAIA 上，经验引导使首次通过率从 32.7% 提升至 51.0%（相对提升 56.0%），在 AIME24/25 上，平均调试迭代次数从 0.76/0.82 降至 0.24/0.26（相对减少 68.4%/68.3%）。这一结果验证了经验约束对生成稳定性的关键作用，但论文未报告经验引导对资产多样性的影响，即是否导致生成资产趋同。

评估协议存在局限：所有实验基于 GPT-5-chat 单一骨干，缺乏与参数化进化方法（如 EvolveR）的同预算对比，无法量化非参数化协同进化与参数化内化的效率差异。代码已开源，但超参数（如相似度阈值 $\delta$、经验检索 top-k）未详细披露，可能影响复现性。此外，跨任务实验仅使用 GAIA 记忆初始化其他基准，未测试领域差异更大的迁移场景，泛化性结论需谨慎解读。

## 关联研究分析

从问题动机看，Mem[2] Evolve 与 Alita 的核心差异在于资产创建的约束机制。Alita 依赖 LLM 的内在知识从零生成工具，而 Mem[2] Evolve 引入 Experience Memory 作为生成约束，将创建过程从“开放式生成”转变为“条件化生成”。这一差异源于对“不稳定扩张”问题的不同理解：Alita 认为动态生成本身足以扩展能力，而 Mem[2] Evolve 认为无约束生成会导致重复错误，需经验引导确保资产质量。然而，经验引导是否抑制了资产多样性，即是否导致生成工具趋同于已验证模式，论文未提供量化证据。

从方法设计看，Mem[2] Evolve 与 ReasoningBank 在经验利用上存在本质区别。ReasoningBank 将经验用于提示优化，即在执行阶段检索相关经验作为上下文，而 Mem[2] Evolve 将经验用于资产创建，即在生成阶段将经验作为条件输入。这一设计差异使得 Mem[2] Evolve 的经验作用从“执行辅助”升级为“能力构建”，但代价是经验库的维护复杂度增加。与 EvoFSM 相比，Mem[2] Evolve 在 HotpotQA 上取得 82.00%，接近 EvoFSM 的 82.2%，但 EvoFSM 依赖有限状态机结构约束推理路径，而 Mem[2] Evolve 依赖动态工具扩展，两者在结构化推理任务上的优势来源不同，前者源于路径约束，后者源于工具丰富性。

## 总结

Mem[2] Evolve 旨在解决自进化智能体中经验积累与能力扩展割裂导致的静态边界或不稳定扩张问题。其切入点在于建立经验引导资产创建、资产执行反哺经验蒸馏的双向闭环，通过双记忆机制实现协同进化。实验表明，该框架在 8 个基准上平均 Pass@1 达 70.24%，超越能力中心基线 Alita 6.46%，验证了协同进化的有效性。然而，论文未量化经验引导对资产多样性的影响，且缺乏与参数化进化路线的同预算对比，无法判断非参数化协同进化在长期稳定性上的优势。当经验库规模增大时，检索精度是否下降，进而影响资产创建质量，论文未给出回答。
