# ACL2026最新论文 ｜CoEvolve: Training LLM Agents via Agent-Data Mutual Evolution ｜智能体-数据协同进化

研究机构：阿里巴巴集团

作者：Shidong Yang、Ziyu Ma、Tongwen Huang 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.15840)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_c54e11166f26)

> 大语言模型智能体在开放环境中的训练长期受限于静态数据分布，导致长尾交互模式覆盖不足。现有合成数据方法虽降低标注成本，但缺乏对智能体实时弱点的反馈机制，无法动态调整训练集。本文提出 CoEvolve，通过提取轨迹中的遗忘、边界与稀有信号，引导 LLM 合成针对性新任务并闭环验证，实现智能体与数据分布的协同进化。该方法在中小规模开源模型上验证了显著增益，但其长期稳定性与跨域泛化边界尚存疑。

## 研究背景

当智能体在 Web 导航或工具调用环境中执行任务时，其策略往往在特定交互模式下表现稳定，而在长尾场景（如按钮标签变更、API 参数微调）中失效。这种失效源于训练数据与测试分布的静态错位，即分布偏移。为缓解此问题，研究者引入合成数据生成，利用 LLM 的世界知识探索环境并构建轨迹。然而，合成数据通常基于随机探索或离线脚本，缺乏对智能体当前能力状态的感知，导致生成的任务与智能体的实际弱点脱节，训练效率低下且无法持续改进。

当前 LLM 智能体训练的主流路线分为专家监督与合成数据两类。专家监督依赖人工构建轨迹，成本高且覆盖有限；合成数据虽降低了标注成本，但多为开环生成，数据分布固定，无法随智能体能力演进而调整。这种静态范式导致智能体在训练后期陷入局部最优，无法有效覆盖复杂环境中的长尾交互。CoEvolve 的切入点在于将“数据生成”从离线静态过程转化为在线闭环过程，通过实时提取智能体行为中的弱点信号，动态重塑训练数据分布，使数据进化与智能体优化同步进行。

## 核心方法

### 方法参照系

CoEvolve 基于 Group Relative Policy Optimization (GRPO) 框架，其核心差异在于训练集 $D_t$ 并非静态，而是随训练迭代动态更新。标准 GRPO 在固定数据集上优化策略，而 CoEvolve 引入“信号提取-任务合成-环境验证”闭环，使数据分布 $D_t$ 成为智能体策略 $\pi_\theta$ 的函数，实现数据与策略的联合进化。

### 弱点信号提取

传统合成数据方法缺乏对智能体当前失败模式的感知，导致生成的任务与智能体弱点无关。CoEvolve 在训练迭代 $t$ 中，从 rollout 轨迹中提取三类行为信号：遗忘信号、边界信号与稀有信号。遗忘信号检测智能体从成功到失败的转变，定义为存在历史得分 $s_i \ge 0.5$ 且当前得分 $s_{now} < 0.5$ 的任务；边界信号识别同一任务下结果方差大的情况，即采样轨迹中同时存在成功（$\tilde{R} > 0.5$）与失败（$\tilde{R} < 0.5$）结果；稀有信号捕捉低频但重复出现的动作模式，定义为累计出现次数 $c_p$ 满足 $c_p/N < \theta$ 且 $c_p > 0$ 的模式。这些信号共同标记了智能体的不稳定区域与探索盲区，为后续任务合成提供定向反馈。

### 信号引导任务合成与验证

基于提取的信号，CoEvolve 利用 LLM 进行信号引导的环境重探索。对于每个信号标注的轨迹，LLM 生成结构化探索上下文，描述失败原因与行为不稳定点。随后，LLM 沿多轮与多步两个维度重新探索环境，生成步骤级交互三元组 $(a_t, o_t, id)$。这些三元组被聚合为任务-解决方案对，并通过环境执行验证：若任务成功完成或获得正奖励，则保留并加入训练集 $D_t$。该机制确保新任务既针对智能体弱点，又在环境中可执行，避免了随机合成数据的无效性。

## 实验评估

实验在 AppWorld 与 BFCL-V3 基准上进行，使用 Qwen2.5-7B、Qwen3-4B 与 Qwen3-30B-A3B 作为骨干模型。基线包括 Zero-shot、GRPO 及闭源 LLM（如 GPT-4、Claude-Sonnet-4.5）。CoEvolve 在 Qwen3-4B 上取得 AppWorld TestN TGC 35.71 与 BFCL-V3 63.00，显著优于 GRPO 基线（28.57 与 58.00），并超越 GPT-4（54.00）在 BFCL-V3 上的表现。

| 模型 | AppWorld TestN (TGC) | BFCL-V3 | 平均提升 |
| :--- | :--- | :--- | :--- |
| Qwen3-4B (Zero-shot) | 16.67 | 26.50 | - |
| Qwen3-4B (GRPO) | 28.57 | 58.00 | - |
| Qwen3-4B (CoEvolve) | 35.71 | 63.00 | +15.58 |
| Qwen3-30B-A3B (CoEvolve) | 54.76 | 67.00 | +18.14 |

消融实验显示，反馈信号对性能提升贡献最大。移除遗忘信号导致平均分从 49.36 降至 45.18，降幅 4.18 分，表明纠正训练过程中的能力退化是关键。边界信号与稀有信号的移除分别导致 1.6 分与 1.9 分下降，验证了多信号互补性。超参数分析表明，初始数据量 $N=100$ 与生成频率 $F=5$ 在 BFCL 上表现最佳，而 $N=200$ 虽提升 AppWorld 但轻微降低 BFCL，暗示数据多样性与规模需平衡。

评估边界方面，论文未报告长期训练后的灾难性遗忘指标，且缺乏与非参数化自进化方法（如 EvoFSM、COMAP）的直接对比。代码已开源，超参数（学习率 $10^{-6}$，KL 系数 $10^{-3}$）明确，但计算成本仅报告约 10% 额外开销，未详细分解各阶段耗时。

## 关联研究分析

从问题动机看，CoEvolve 与 EvolveR 均关注长期能力固化，但 EvolveR 通过蒸馏文本经验至参数，而 CoEvolve 演化任务分布本身。EvolveR 假设经验可抽象为通用知识，CoEvolve 则认为弱点是环境特定的，需通过新任务实例化。这一差异源于任务特性：EvolveR 适用于知识密集型任务，CoEvolve 更适合交互密集型环境。CoEvolve 未对比 EvolveR，可能因两者评估基准不同，但缺乏跨范式对比限制了其通用性判断。

从方法设计看，CoEvolve 借鉴 Reflexion 的反思机制，但将其用于数据生成而非即时提示。Reflexion 在推理时注入反思文本，CoEvolve 在训练时生成新任务。这种转变将反思从“推理辅助”变为“数据增强”，解决了 Reflexion 在长序列中上下文窗口受限的问题。然而，CoEvolve 依赖 LLM 生成新任务，若 LLM 世界知识不足，可能生成无效任务。论文未讨论 LLM 能力对合成质量的敏感性，这是其方法边界的关键点。

## 总结

CoEvolve 解决了静态训练数据无法覆盖长尾交互模式的核心矛盾，通过信号引导的数据闭环实现智能体与数据的协同进化。其切入点在于将弱点信号转化为可执行任务，使数据分布随策略动态调整，避免了静态合成数据的无效性。实验证明，该方法在 Qwen3-4B 上带来 15.58% 的平均提升，并在 BFCL-V3 上超越 GPT-4。然而，论文未报告长期训练下的遗忘指标，且缺乏与非参数化方法的对比，暴露了其在稳定性与通用性上的边界。当训练迭代超过一定阈值后，动态数据分布是否会导致策略震荡或过拟合特定弱点，论文未给出回答。
