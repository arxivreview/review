# ACL2026最新论文 ｜IterCOMP: Reasoning-aware Adaptive Prompt Compression for Multi-hop Question Answering ｜迭代推理感知提示压缩

作者：JungMin Yun、YoungBin Kim

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_bf9cc78e028b)

> 多跳问答中，检索文档的冗余噪声导致大语言模型注意力稀释与推理链断裂，现有提示压缩方法仅针对单轮查询的表面相关性进行筛选，无法捕捉跨文档的隐含依赖。本文切入点在于将压缩过程从静态过滤转变为动态推理闭环，通过迭代判断证据充分性并生成追问来逐步构建紧凑提示。IterCOMP 采用无训练框架，结合语义与词法双重评分筛选证据，并利用 LLM 判断可答性以控制迭代终止。该方法在降低 Token 预算的同时提升了多跳问答的准确性，但其性能上限受限于 LLM 对隐含线索的识别能力，且在缺乏结构化知识表示的情况下，对复杂实体关系的处理仍存疑。

## 研究背景

多跳问答要求模型跨越多个文档进行链式逻辑推导，这一过程依赖于中间实体的准确识别与证据的有序整合。然而，检索增强生成（Retrieval-Augmented Generation, RAG）系统通常将大量检索文档直接输入大语言模型（Large Language Models, LLMs），导致输入长度线性增长。长上下文不仅增加了推理延迟与计算成本，更引发了“中间迷失”（Lost-in-the-Middle）现象，即模型难以有效整合分散在长文本中的关键证据，导致推理链中断或答案偏离。

为缓解此问题，提示压缩技术旨在保留关键信息并剔除噪声。现有方法主要分为查询无关与查询感知两类：前者基于统计特性筛选 Token，后者通过查询-文档相似度匹配保留相关内容。然而，这些方法普遍采用“单查询-单文档”范式，仅评估表面相关性，无法处理多跳任务中查询分解为多个子组件、证据分散于不同文档且存在隐含依赖的复杂场景。当查询包含多个子问题时，单一的相关性评分往往遗漏连接不同证据片段的关键中间线索，导致压缩后的提示虽短但信息不完整，无法支撑完整的推理链。

IterCOMP 针对这一局限，提出将多跳推理逻辑嵌入压缩循环。其核心假设是 LLM 能够判断给定证据是否足以回答问题，并在证据不足时识别缺失信息并生成针对性追问。通过这种“筛选-判断-追问”的迭代机制，IterCOMP 不再一次性压缩所有文档，而是根据推理进展动态积累证据，从而在保持提示紧凑性的同时，确保逻辑连贯性与证据完整性。

## 核心方法

### 方法参照系

IterCOMP 属于查询感知提示压缩路线，其标准流程为：接收原始查询与检索文档，通过相似度计算筛选相关片段，拼接为压缩提示供 LLM 生成答案。本文与标准流程的关键差异在于，它将压缩视为一个受推理状态控制的迭代过程，而非一次性的静态过滤操作，引入了可答性判断作为动态终止信号。

### 双重相关性评分筛选

在证据筛选阶段，传统方法仅依赖语义相似度，易忽略多跳推理中关键的精确关键词匹配。IterCOMP 引入词法相似度以补充语义信号的不足。设计动机在于，多跳任务中实体名称或特定术语的精确匹配往往比泛化语义对齐更能指示证据的相关性。该方法结合语义内积与词法加权内积，构建双重评分函数：

$$ S_{dual}(q, e_{i,j}) = \lambda \cdot S_{sem}(q, e_{i,j}) + (1 - \lambda) \cdot S_{lex}(q, e_{i,j}) $$

其中 $S_{sem}$ 为嵌入向量内积，$S_{lex}$ 为基于 BGE-M3 模型计算的词法重要性加权内积。该公式通过超参数 $\lambda$ 平衡两种信号，确保筛选出的证据既具备语义相关性，又包含关键实体线索。随后，系统根据全局分数分布的百分位阈值动态截断，保留高分证据段，抑制噪声传播。

### 可答性判断与迭代控制

筛选后的证据集需经过充分性评估，这是 IterCOMP 区别于静态压缩的核心。设计动机在于，静态压缩无法判断保留的证据是否足以回答多跳问题，可能导致过早终止或冗余迭代。IterCOMP 利用 LLM 作为二元分类器，判断当前证据集 $E^{(h)}_{cand}$ 是否可答。若可答，则终止迭代，将证据集作为最终压缩提示；若不可答，LLM 识别缺失信息并生成追问 $q^{(h)}$，该追问作为新查询重新触发筛选模块，实现证据的迭代积累。这一机制将压缩过程转化为一个受控的推理循环，确保最终提示包含解决所有子问题所需的完整证据链，而非仅包含表面相关片段。

## 实验评估

实验在 MuSiQue、2WikiMultiHopQA 和 HotpotQA 三个多跳问答基准上进行，对比基线包括 Selective-Context、LLMLingua 系列、RECOMP 等压缩方法。值得注意的是，实验未对比 PRISM、GRASP 等迭代检索 SOTA 方法，仅聚焦于压缩效率与精度的权衡。

| 方法 | HotpotQA EM | HotpotQA F1 | MuSiQue EM | MuSiQue F1 | 2Wiki EM | 2Wiki F1 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Raw Documents | 9.69 | 19.92 | 24.06 | 36.75 | 31.60 | 43.63 |
| Selective-Context | 3.02 | 9.96 | 18.87 | 29.30 | 17.74 | 28.82 |
| RECOMP (extractive) | 8.32 | 16.76 | 22.26 | 33.89 | 28.09 | 40.78 |
| LLMLingua-2 | 6.62 | 14.72 | 18.70 | 33.35 | 24.01 | 37.76 |
| LongLLMLingua | 10.95 | 19.66 | 23.19 | 34.83 | 31.68 | 46.49 |
| R2C | 12.29 | 22.44 | 19.41 | 32.09 | 33.63 | 47.80 |
| **IterCOMP (ours)** | **16.67** | **27.36** | **27.39** | **39.69** | **37.65** | **51.78** |

IterCOMP 在三个基准的 EM 和 F1 指标上均优于所有对比基线，且在 HotpotQA 上 F1 达到 51.78，较原始文档提升约 7 个点，表明迭代压缩在保留关键推理线索方面的有效性。

在消融分析中，论文未提供详细的组件消融表格，但通过初步分析验证了 LLM 判断可答性的能力。结果显示，随着跳数增加，LLM 在“完整证据”场景下的判断准确率下降（如 Mistral-7B 从 2-hop 的 92% 降至 4-hop 的 78.5%），而在“部分证据”场景下准确率反而提升。这一反直觉现象表明，识别缺失信息比确认完整证据更容易，但也意味着在复杂多跳任务中，LLM 可能因误判“可答”而提前终止迭代，导致证据缺失。为此，IterCOMP 设置了最大迭代次数限制以平衡风险。

评估边界方面，论文未报告置信区间，且未提供代码开源链接，可复现性受限。此外，实验仅使用 BGE-M3 作为编码器，未探讨不同编码器对词法评分的影响。指标上，论文未报告计算延迟或 Token 压缩率的具体数值对比（仅提及降低 Token 预算），缺乏效率-精度的联合量化评估。

## 关联研究分析

从问题动机看，IterCOMP 与 PRISM 均针对多跳证据分散问题，但 PRISM 侧重通过迭代检索积累全量证据，而 IterCOMP 侧重在压缩过程中筛选关键片段。PRISM 的高 Recall（90.9%）依赖于多次 LLM 调用与检索，计算成本高；IterCOMP 则通过压缩降低输入长度，追求效率与精度的平衡。两者的差异根源在于任务目标：PRISM 旨在最大化证据覆盖，IterCOMP 旨在最小化输入噪声。IterCOMP 未对比 PRISM，可能因为两者在“证据完整性”与“提示紧凑性”的权衡点上不同，直接对比需统一计算预算，而论文未提供此类协议。

从方法设计看，IterCOMP 与 S2G-RAG 均使用 LLM 判断证据充分性，但 S2G-RAG 用于控制检索终止，IterCOMP 用于控制压缩迭代。S2G-RAG 的充分性判断基于累积证据上下文，而 IterCOMP 的判断基于筛选后的候选证据集。这一差异导致 IterCOMP 在证据筛选阶段可能遗漏隐含语义线索，因为筛选依赖词法与语义评分，而 S2G-RAG 的检索阶段可能通过更广泛的召回弥补筛选的不足。IterCOMP 缺乏结构化知识表示（如知识图谱），仅依赖扁平文本句段，这可能限制其在复杂实体关系推理中的表现，而 S2G-RAG 等迭代检索方法通常结合更强大的检索器，能捕捉更深层的语义关联。

## 总结

IterCOMP 旨在解决多跳问答中提示冗余导致的注意力稀释与推理链断裂问题。其切入点在于将提示压缩从静态过滤转变为受 LLM 推理控制的迭代过程，通过可答性判断动态终止迭代，从而在降低 Token 预算的同时保留关键推理线索。实验表明，IterCOMP 在 HotpotQA 上 F1 达到 51.78，优于 LongLLMLingua 等基线，验证了迭代压缩的有效性。然而，论文暴露的局限在于 LLM 对复杂多跳证据充分性的判断准确率随跳数增加而下降，且缺乏结构化知识表示支持，可能导致隐含语义线索的遗漏。当跳数进一步增加至 4-hop 以上时，LLM 误判“可答”的风险是否会显著增加，进而导致迭代过早终止，论文未给出回答。
