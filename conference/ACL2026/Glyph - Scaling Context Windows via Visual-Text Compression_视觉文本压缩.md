# ACL2026最新论文 ｜Glyph: Scaling Context Windows via Visual-Text Compression ｜视觉文本压缩

研究机构：清华大学、智谱AI

作者：Jiale Cheng、Yusen Liu、Xinyu Zhang 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.17800)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.17800)

> 长上下文推理面临计算与内存的双重瓶颈，传统Token级压缩在极高压缩比下易导致语义断裂或计算开销抵消加速收益。本文切入点在于利用视觉模态的高信息密度特性，将文本渲染为图像，以视觉Token替代文本Token，从而在固定窗口内处理更长的原始文本。具体做法是构建包含持续预训练、LLM驱动遗传搜索及后训练的三阶段框架，实现3-4倍Token压缩。该范式在效率与保真度间取得了新平衡，但其对渲染参数的敏感性及OCR精度瓶颈限制了其在极端场景下的泛化能力。

## 研究背景

Transformer自注意力机制的二次方复杂度使得百万级Token的上下文处理在计算与内存上均不可行。为缓解此问题，研究者通常采用位置编码外推或稀疏注意力机制，但这些方法并未减少Token数量，仅优化了单Token处理效率，整体开销依然巨大。另一种思路是通过检索增强生成（Retrieval-Augmented Generation, RAG）缩短输入，但外部检索可能遗漏关键信息并引入额外延迟。

现有压缩路线主要分为硬压缩与软压缩。硬压缩通过剔除冗余Token实现精简，但易造成指代悬空；软压缩将上下文映射为连续向量，虽保真度较高但缺乏可解释性且训练成本高。视觉语言模型（Vision-Language Models, VLMs）在光学字符识别（Optical Character Recognition, OCR）任务中展现出将多个字符编码为单个视觉Token的能力，这为利用视觉模态的高信息密度进行上下文压缩提供了新路径。本文旨在探索这一“视觉上下文扩展”范式，通过渲染文本为图像，使固定窗口的VLM能够处理远超其文本窗口限制的长文本，从而在不扩展窗口的前提下实现长上下文理解。

## 核心方法

### 方法参照系

本文问题属于长上下文压缩范畴，但区别于传统的Token级筛选或向量池化，其核心差异在于模态转换：将文本序列 $C$ 转化为视觉页面序列 $V$，利用VLM处理视觉Token。标准流程通常涉及固定的渲染配置，而本文引入了动态配置搜索机制以优化压缩率与性能的权衡。

### 视觉压缩任务形式化

传统长上下文任务定义为三元组 $(I, C, R)$，其中 $I$ 为指令，$C$ 为长文本上下文，$R$ 为目标响应。本文将其重构为 $(I, V, R)$，其中 $V = \{v_1, ..., v_n\}$ 为渲染后的视觉页面序列。压缩比 $\rho$ 定义为文本Token总数与视觉Token总数之比：

$$ \rho = \frac{\sum_{i=1}^{T} 1}{\sum_{j=1}^{n} \tau(v_j)} $$

其中 $\tau(v_j)$ 表示第 $j$ 个视觉页面消耗的视觉Token数。该公式量化了每个视觉Token承载的文本信息量，$\rho$ 越高表示压缩效率越强。这一设计动机在于，通过增加单Token的信息密度，可以在不增加模型计算复杂度的情况下，有效扩展可处理的原始文本长度，解决传统方法中Token数量不变导致的整体开销问题。

### LLM驱动的遗传搜索

固定渲染配置难以在不同任务间取得最优的压缩-性能平衡。本文在持续预训练后，引入LLM驱动的遗传搜索以自动发现最优渲染配置 $\theta^*$。搜索过程包括：1. 使用候选配置 $\theta_k$ 渲染验证集；2. 评估任务准确率与压缩比；3. 利用LLM分析当前种群性能，建议变异与交叉操作；4. 记录历史并采样下一代候选。该过程迭代直至收敛。此创新解决了人工设计配置无法适应特定任务需求的问题，通过自动化探索字体、布局、分辨率等参数，实现了针对下游任务的最优压缩配置，避免了固定配置在复杂任务上的性能退化。

### 后训练与OCR对齐

在确定最优配置 $\theta^*$ 后，通过监督微调（SFT）和强化学习（RL）进一步提升模型性能。SFT阶段使用思考风格格式，鼓励模型进行逐步推理。RL阶段采用组相对策略优化（Group Relative Policy Optimization, GRPO），结合可验证奖励与格式奖励。此外，引入辅助OCR对齐任务，通过Levenshtein距离奖励模型正确识别图像中的文本细节。这一设计动机在于，视觉压缩的核心挑战是细粒度文本的忠实恢复，OCR任务强化了模型对低层文本细节的感知能力，确保在高压缩比下语义信息的完整性，弥补了纯视觉特征可能丢失的字符级信息。

## 实验评估

实验在LongBench、MRCR、RULER及MMLongBench-Doc等基准上进行，基线包括GPT-4.1、Qwen3-8B、GLM-4-9B-Chat-1M等SOTA LLM。Glyph在LongBench上取得50.56的平均准确率，与Qwen3-8B的50.19持平，但实现了3.3倍的平均压缩比。在MRCR 4-needle任务中，Glyph取得25.12的平均准确率，优于GLM-4-9B-Chat-1M的17.86。

| 基准 | 模型 | 平均准确率 (%) | 压缩比 |
| :--- | :--- | :--- | :--- |
| LongBench | Glyph | 50.56 | 3.3× |
| LongBench | Qwen3-8B | 50.19 | 1.0× |
| MRCR (4-needle) | Glyph | 25.12 | 3.0× |
| MRCR (4-needle) | GLM-4-9B-Chat-1M | 17.86 | 1.0× |

消融实验显示，移除RL阶段导致LongBench性能下降7.11%，移除SFT中的OCR任务导致下降8.12%，表明OCR对齐对视觉压缩下的语义保真至关重要。遗传搜索配置优于随机与手动配置，在LongBench上分别高出1.67%和0.00%（与手动持平，但优于随机1.67%）。

评估边界方面，论文未报告HotpotQA等QA基准的精确匹配（Exact Match, EM）值，仅报告准确率，限制了与文本压缩方法的直接横向对比。代码已开源，但渲染过程的CPU/GPU开销未详细披露，4.8倍Prefill加速是否包含渲染时间存疑。

## 关联研究分析

从问题动机看，Glyph与GIST等软压缩方法均旨在通过潜在表示提升信息密度，但GIST使用连续向量，而Glyph使用离散视觉Token。这一差异源于视觉模态固有的空间局部性，使得单个视觉Token能编码更多字符，从而在相同窗口下实现更高压缩比。然而，GIST的连续表示在跨层语义对齐上更平滑，而Glyph依赖VLM的OCR能力，对渲染参数敏感，这在任务特性上决定了Glyph更适合对可解释性要求较低但追求极致压缩比的场景。

从方法设计看，Glyph与ICAE的自编码器架构不同，ICAE通过联合训练自编码损失与语言建模损失实现高保真重构，而Glyph通过遗传搜索优化渲染配置。ICAE的压缩是端到端的，而Glyph的压缩依赖于外部渲染过程，这引入了额外的系统复杂性。ICAE在跨层语义错位问题上通过层语义对齐模块解决，而Glyph通过OCR辅助任务缓解字符级信息丢失。两者在解决高压缩比下的性能退化问题上采取了不同路径：ICAE优化内部表示，Glyph优化外部输入格式。

## 总结

本文核心矛盾在于长上下文处理中计算成本与信息保真度的非线性权衡。Glyph抓住视觉模态高信息密度的特性，通过渲染文本为图像，利用VLM处理视觉Token，实现了3-4倍压缩比下的性能保持。实验证明其在LongBench上达到50.56准确率，与SOTA LLM持平，同时实现4.8倍Prefill加速。其边界在于对渲染参数的敏感性及OCR精度瓶颈，UUID等罕见字符识别错误限制了其在极端压缩下的可靠性。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
