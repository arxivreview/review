# ACL2026最新论文 ｜Reasoning Hijacking: The Fragility of Reasoning Alignment in Large Language Models ｜推理劫持：大语言模型推理对齐的脆弱性

作者：Yuansen Liu、Yixuan Tang、Anthony Kum Hoe Tung

论文原文见 [arXiv](https://arxiv.org/abs/2601.10294)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_a86ea17ed7e5)

> 当大语言模型（LLM）被嵌入邮件过滤或评论审核等第三方应用时，系统指令与外部数据在架构上被混合处理，导致模型难以区分权威指令与不可信内容。现有安全对齐主要防御“目标劫持”，即攻击者直接篡改任务目标，但忽略了模型在推理过程中对中间逻辑脚手架的依赖。本文提出“推理劫持”新范式，通过注入虚假决策标准而非改变任务目标，诱导模型在保持意图对齐的前提下产生错误分类。该方法揭示了当前基于意图检测的防御机制存在根本性盲区，但其在复杂多步推理任务中的泛化能力仍存疑。

## 研究背景

LLM 在判别式任务中常将决策标准外化为显式文本，作为生成最终标签前的逻辑脚手架。这种“标准先行”的生成机制旨在提升输出一致性，却使模型过度依赖上下文中出现的规则性陈述。当外部数据中嵌入看似合理的决策标准时，模型可能将其误认为有效的中间表示，而非待验证的数据，从而在逻辑层面被劫持。

间接提示注入（Indirect Prompt Injection, IPI）研究长期聚焦于目标劫持，即攻击者通过注入指令覆盖系统提示，迫使模型执行恶意任务。主流防御如 StruQ 和 SecAlign 均基于“攻击表现为意图偏离”的假设，通过结构化查询或偏好优化来抑制指令覆盖。然而，这些防御无法捕捉那些不改变任务目标、仅篡改决策逻辑的攻击。本文切入点在于指出，随着 CoT 推理的普及，模型对中间逻辑步骤的安全性依赖增强，使得“推理逻辑篡改”成为比“目标劫持”更隐蔽且难以防御的威胁。

## 核心方法

### 方法参照系

本文问题属于 IPI 攻击范畴，但区别于传统的梯度优化或 LLM 迭代重写路线。传统 IPI 旨在通过优化 token 概率或重写指令来改变模型行为，而本文利用语义标准挖掘，构造自然语言后缀，在不访问模型梯度的情况下实现黑盒攻击。关键差异在于攻击载荷的语义结构：从“指令覆盖”转变为“逻辑误导”。

### 标准挖掘与聚类

设计动机在于解决传统 IPI 攻击中“指令覆盖”易被意图检测防御拦截的问题。本文首先利用攻击者模型 $A$ 从标注数据集 $\mathcal{D} = \{(x_i, y_i)\}$ 中挖掘标签条件标准。对于每个样本，提取支持预测 $y_i$ 的理由集合 $R_i$，并聚合为标签条件标准库 $C_y = \bigcup_{i:y_i=y} R_i$。为消除冗余，对 $C_y$ 中的标准进行嵌入并执行 k-means 聚类，选取每个簇的原型标准，得到精简集合 $\bar{C}_y$。

$$ \bar{C}_y = \{ c^{(1)}_y, \dots, c^{(k)}_y \} $$

该公式表示通过聚类得到的代表性标准集合，作为后续攻击的候选逻辑单元。

### 可反驳标准选择与后缀合成

设计动机在于利用目标输入 $x^*$ 与真实标签 $y^*$ 之间的逻辑非充分性，即 $x^*$ 虽属于 $y^*$，但不满足 $y^*$ 的所有启发式标准。对于目标输入 $x^*$，查询攻击者模型判断其是否满足 $\bar{C}_{y^*}$ 中的每个标准 $c$，得到二元判断 $g(x^*, c) \in \{0, 1\}$。收集不满足的标准子集 $M(x^*) = \{ c \in \bar{C}_{y^*} : g(x^*, c) = 0 \}$。随后，利用模板将 $M(x^*)$ 中的标准转化为虚假推理轨迹，构造后缀 $s(x^*)$，形成扰动输入 $\tilde{x}^* = x^* \| s(x^*)$。

$$ s(x^*) = \text{Template}(M(x^*), x^*, y' \neq y^*) $$

该公式表示后缀由可反驳标准、目标输入及错误标签通过模板生成，旨在诱导模型基于虚假逻辑得出错误结论。

## 实验评估

实验在 Enron（垃圾邮件）、Wiki Toxic（毒性评论）和 IMDb（负面评论）三个分类任务上进行，使用 Qwen3、Mistral、Gemma 和 GPT-OSS 等五个 LLM 轮换作为攻击者和受害者。基线包括 Escape Separation、Ignore、Topic 等 IPI 攻击方法。在 StruQ 和 SecAlign 防御下，Criteria Attack 的 ASR 显著高于基线。

| 攻击方法 | StruQ (Toxic) | SecAlign (Toxic) | StruQ (Spam) | SecAlign (Spam) |
| :--- | :--- | :--- | :--- | :--- |
| Escape Separation | 12.1 | 4.7 | 20.4 | 23.6 |
| Topic | 12.3 | 15.4 | 39.6 | 84.8 |
| Criteria Attack | 47.3 | 15.2 | 58.9 | 55.3 |

Criteria Attack 在毒性评论检测中 ASR 达 47.3%（StruQ），远超基线的 12.3%（Topic），表明推理劫持在强防御下仍具高有效性。

消融实验显示，移除虚假推理轨迹（No Fake Reasoning）导致 ASR 大幅下降，证明推理脚手架是攻击成功的关键机制。使用随机标准（Random Criteria）而非可反驳标准，ASR 从 96.1% 降至 89.0%（Gemma-3-27B, Spam），说明标准与输入的逻辑一致性至关重要。

评估边界方面，实验仅覆盖二元分类任务，未涉及多步推理或生成式任务。代码已开源，但超参数（如 k-means 簇数 k=20）的敏感性未详细讨论。

## 关联研究分析

从问题动机看，本文与 GCG 等梯度优化攻击形成鲜明对比。GCG 通过优化离散 token 后缀实现白盒攻击，依赖模型梯度信息，而本文利用语义标准挖掘，属于黑盒攻击，无需梯度访问。这一差异源于任务特性：GCG 针对生成式越狱，需精确控制 token 概率；本文针对判别式分类，利用模型对语义逻辑的依赖，更具跨模型泛化性。

从方法设计看，本文与 StruQ 等结构化防御存在根本冲突。StruQ 通过分离指令与数据通道来防止指令覆盖，但无法阻止数据通道中嵌入的虚假标准被模型采纳。这揭示了现有防御的盲区：它们假设攻击必须改变任务意图，而本文证明攻击可以仅改变决策逻辑。这种冲突暗示，未来的防御需从“意图检测”转向“逻辑一致性验证”。

## 总结

本文核心矛盾在于 LLM 推理对齐的脆弱性：模型依赖中间逻辑脚手架，导致其易受虚假标准注入的影响。本文抓住“推理逻辑篡改”这一被忽略的切入点，通过挖掘可反驳标准并合成虚假推理轨迹，实现了对模型决策边界的隐蔽操控。实验证明，在 StruQ 和 SecAlign 防御下，Criteria Attack 的 ASR 达 47.3%-58.9%，显著高于目标劫持基线。本文边界在于仅验证了二元分类任务，未探讨复杂推理场景。当任务涉及多步逻辑依赖时，虚假标准的注入是否仍能有效诱导错误结论，论文未给出回答。
