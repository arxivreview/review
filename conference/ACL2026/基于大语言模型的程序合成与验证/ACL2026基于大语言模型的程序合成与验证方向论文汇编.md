【ExecVerify: White-Box RL with Verifiable Stepwise Rewards for Code Execution Reasoning ｜执行轨迹白盒强化学习

研究机构：浙江大学、英国伦敦大学学院

作者：Lingxiao Tang、He Ye、Zhaoyang Chu 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ba49c258edf5)

> 代码大语言模型（LLM）在生成代码时往往缺乏对程序具体执行过程的语义理解，导致下游代码生成与修复性能受限。现有方法多依赖监督微调（SFT）模仿教师模型生成的文本解释，但SFT无法显式验证中间执行步骤的正确性，且训练数据缺乏难度控制。本文提出ExecVerify，通过约束式数据合成构建可控难度数据集，并引入基于解释器执行轨迹的白盒强化学习（RL），将训练目标从文本模仿转向逐步语义正确性验证。该方法显著提升了小模型在执行推理任务上的表现，但其奖励机制仅覆盖局部状态，对全局逻辑一致性的保证仍存疑。

【QiMeng-PRepair: Precise Code Repair via Edit-Aware Reward Optimization ｜编辑感知强化学习下的精确代码修复

研究机构：中科院计算所、中国科学院大学

作者：Changxin Ke、Rui Zhang、Jiaming Guo 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.05963)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.05963)

> 代码修复旨在自动纠正故障程序并保留其预期语义，但现有基于大语言模型（LLM）的方法往往陷入“过度编辑”陷阱，即通过重写大量正确代码来掩盖错误，导致可维护性下降且难以定位真实缺陷。本文指出，仅优化修复正确性的强化学习范式忽略了编辑幅度，导致模型无法区分“精准修复”与“暴力重写”。PRepair 框架通过自破坏数据生成与编辑感知组相对策略优化（EA-GRPO），将编辑成本纳入奖励函数，实现了在保持正确性的同时最小化代码变更。该方法在 Python 和 Verilog 任务上显著提升了修复精度，但受限于单元测试的覆盖范围，其“精确性”是否等同于逻辑正确性仍存疑。

【SpecMind: Cognitively Inspired, Interactive Multi-Turn Framework for Postcondition Inference ｜探索-提交解耦的后条件推断框架

研究机构：新加坡南洋理工大学

作者：Cuong Chi Le、Minh V.T. Pham、Tung Duy Vu 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_408d8e52db03)

> 程序后条件（Postcondition）的自动推断旨在从代码中合成能精确刻画函数行为的逻辑谓词，以替代人工编写。现有单次提示方法生成的后条件往往语法正确但语义模糊，缺乏区分正确与错误实现的判别力。SPECMIND将大语言模型（LLM）从一次性生成器重构为交互式推理者，通过解耦探索与提交、引入历史感知反馈及自主停止机制，实现后条件的迭代精炼。该框架在Python函数后条件生成任务上显著提升了正确性与完备性，但其依赖变异体反馈而非形式化验证器，对深层逻辑错误的覆盖能力存疑。

【Towards Trustworthy Smart Contract Synthesis: A Multi-Agent Framework with Lean-Based Verification ｜可信智能合约合成：基于Lean验证的多智能体闭环框架

研究机构：中国人民大学

作者：Bowei Zhang、Hanbing Liu、Qixin Tian 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_e571328bd7cc)

> 智能合约的不可变性与金融属性使得LLM生成的代码面临“易生成、难信任”的信任鸿沟，传统静态分析误报率高且缺乏数学保证。现有LLM审计依赖自然语言反馈，无法区分正确实现与幻觉，而人工形式化验证成本过高。LeVer通过引入Lean定理证明器进行自动形式化，并配合对抗性攻击代理，构建了“生成-验证-攻击-修复”的闭环。该方法在降低攻击成功率方面表现优异，但其形式化翻译的语义忠实性仍依赖经验验证而非数学证明，存在理论边界。
