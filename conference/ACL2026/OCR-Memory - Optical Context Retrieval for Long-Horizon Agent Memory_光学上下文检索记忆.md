# ACL2026最新论文 ｜OCR-Memory: Optical Context Retrieval for Long-Horizon Agent Memory ｜光学上下文检索记忆

作者：Jinze Li、Yang Zhang、Xin Yang 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.26622)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_e7c695f0c9dc)

> 长时程智能体在有限上下文窗口内复用历史经验时，面临存储容量与信息保真度的根本冲突：文本摘要丢失细节，原始日志耗尽Token预算。现有检索增强生成（RAG）依赖相似度匹配，易混淆主题相关但逻辑无关的片段，且生成式检索存在幻觉风险。OCR-Memory将交互轨迹渲染为带视觉锚点的图像，通过“定位-转录”机制将检索转化为索引选择，从源头阻断幻觉。该框架在Mind2Web和AppWorld上取得SOTA，但视觉模态对复杂因果推理的支持能力仍存疑。

## 研究背景

当智能体执行多步任务时，其生成的轨迹包含推理痕迹、工具调用及环境反馈，这些细粒度信息对调试与规划至关重要。然而，大语言模型（LLM）的固定上下文窗口无法容纳完整历史，迫使系统采用摘要或抽象策略，导致关键细节（如错误消息、中间状态）丢失。为保留完整信息，需引入外部记忆库，但传统文本检索依赖向量相似度，难以捕捉长程依赖与因果逻辑，且生成式检索易产生幻觉。

长时程智能体记忆研究旨在解决非平稳交互环境中的状态一致性问题。主流路线包括基于检索的记忆系统、经验抽象与上下文压缩。检索路线（如RAG）通过外部存储扩展上下文，但受限于相似度匹配的脆弱性；抽象路线（如AWM）将轨迹压缩为技能或工作流，虽提升效率却牺牲低层细节；压缩路线（如ACON）通过潜在表示压缩上下文，但文本中心压缩难以保留视觉布局与结构线索。OCR-Memory的切入点在于利用视觉模态的高密度特性，将交互历史无损存储为图像，并通过视觉锚点实现精准定位，从而在有限Token预算下保留完整证据。

## 核心方法

### 方法参照系

本文问题属于记忆架构设计路线，核心差异在于存储介质由文本/向量转为图像，检索机制由相似度匹配转为视觉锚点索引选择。传统RAG流程中，检索模块输出自由文本片段，而OCR-Memory将检索任务重构为二分类索引预测，解耦了上下文理解与证据生成。

### 定位-转录检索机制

传统检索模块直接生成文本片段，易产生幻觉且延迟高。OCR-Memory采用Set-of-Mark（SoM）提示，将记忆图像中的每个文本段标注唯一数值ID，模型仅输出二进制相关性向量 $\hat{y}_i(q) = (\hat{y}_{i,1}, \dots, \hat{y}_{i,K_i}) \in \{0,1\}^{K_i}$，其中 $\hat{y}_{i,k}=1$ 表示选中第 $k$ 段。该设计将检索转化为指针选择，避免自由文本生成，确保检索内容逐字准确。

$$
\hat{S}(q) = \{(i, k) \mid \hat{y}_{i,k} = 1\}
$$

此公式定义了全局索引集，通过聚合所有记忆图像的二分类预测，确定需检索的片段。确定性文本提取函数 $\text{Fetch}(\hat{S}(q), M)$ 根据索引从日志中获取原文，实现零幻觉检索。

### 年龄感知自适应分辨率

长时程交互中，历史记忆数量庞大，高分辨率图像存储成本过高。OCR-Memory引入年龄感知机制，根据记忆年龄 $\Delta t_i$ 动态调整分辨率层级 $\ell_i = \rho(\Delta t_i)$，旧记忆降为低分辨率缩略图。当检索模块识别出低分辨率记忆中的相关片段时，触发主动召回上采样，即时恢复高分辨率版本。该机制模拟人类记忆从清晰到模糊的衰减过程，平衡存储成本与检索精度。

$$
I_i = \phi_{\ell_i}(I_i^h)
$$

此公式表示根据层级 $\ell_i$ 对高分辨率图像 $I_i^h$ 进行下采样，生成当前存储图像 $I_i$。主动召回机制确保关键记忆在需要时恢复全保真度，避免重复存储高低分辨率副本。

## 实验评估

实验在Mind2Web和AppWorld基准上进行，基线包括Zero-Shot、Retrieval、MemoryBank、AWM及ACON。OCR-Memory在Mind2Web任务成功率（Task SR）达58.1%，AppWorld平均成功率（Avg）达58.1%，均显著优于最强基线ACON（56.2%）。

| 方法 | Mind2Web Task SR (%) | AppWorld Avg (%) |
|---|---|---|
| Zero-Shot | 41.9 | 41.9 |
| Retrieval | 46.2 | 46.2 |
| MemoryBank | 52.1 | 52.1 |
| AWM | 55.0 | 55.0 |
| ACON | 56.2 | 56.2 |
| OCR-Memory | 58.1 | 58.1 |

消融实验显示，移除SoM机制后，Mind2Web元素准确率（Ele Acc）从53.8%降至46.5%（文本生成）或49.2%（边界框），延迟从1.7秒增至5.3秒或2.1秒。SoM机制对性能与效率的贡献显著，验证了视觉锚点索引选择优于自由文本生成。

| 变体 | Ele Acc (%) | Step SR (%) | Latency (s) |
|---|---|---|---|
| OCR-Memory (Full) | 53.8 | 46.1 | 1.7 |
| w/o SoM (Text Gen) | 46.5 | 39.2 | 5.3 |
| w/o SoM (BBox) | 49.2 | 44.5 | 2.1 |

评估边界方面，论文未报告置信区间，且未对比MAGMA、Mandol等最新结构化图谱方法。代码未公开，超参数（如LoRA秩、学习率）细节有限，可复现性受限。

## 关联研究分析

从问题动机看，OCR-Memory与MemoryBank均针对长时程记忆的信息损失问题，但MemoryBank基于艾宾浩斯遗忘曲线进行文本摘要，而OCR-Memory通过视觉存储保留完整细节。差异根源在于任务特性：MemoryBank面向对话场景，摘要可接受；OCR-Memory面向工具使用任务，需保留错误消息等低层细节。视觉模态的高密度特性使其在结构 grounding 任务上更具优势，但论文未验证其在纯文本对话场景的适用性。

从方法设计看，OCR-Memory与ACON同属上下文压缩路线，但ACON通过潜在表示压缩文本，而OCR-Memory将文本转为图像。ACON的压缩比受限于文本语义密度，OCR-Memory则利用视觉编码的压缩优势。然而，ACON支持多模态输入，OCR-Memory仅处理文本轨迹。视觉锚点索引选择是否比向量检索更鲁棒，论文未给出直接对比，仅在Mind2Web上展示性能优势。

## 总结

OCR-Memory解决的核心矛盾是长时程智能体在有限上下文窗口内复用历史经验时的存储容量与信息保真度冲突。其切入点在于利用视觉模态的高密度特性，将交互轨迹无损存储为图像，并通过“定位-转录”机制实现零幻觉检索。该方法在Mind2Web和AppWorld上取得SOTA，任务成功率均达58.1%。然而，视觉模态对复杂因果推理的支持能力未经验证，且缺乏与结构化图谱方法的对比。当任务涉及多跳因果推理时，视觉锚点索引选择是否仍能保持优势，论文未给出回答。
