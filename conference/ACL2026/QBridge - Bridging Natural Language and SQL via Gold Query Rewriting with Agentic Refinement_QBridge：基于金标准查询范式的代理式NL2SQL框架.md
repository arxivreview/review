# ACL2026最新论文 ｜QBridge: Bridging Natural Language and SQL via Gold Query Rewriting with Agentic Refinement ｜QBridge：基于金标准查询范式的代理式NL2SQL框架

研究机构：浙江大学、香港科技大学

作者：Zhensheng Luo、Sai Wu、Yuan Qiu 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_9e06f6ffe13e)

> 自然语言到SQL（NL2SQL）旨在将口语化问题映射为可执行查询，但真实用户提问常存在噪声、歧义及与数据库语义的弱对齐，导致单步解码脆弱。现有方法多依赖解码器同时处理意图解析与模式链接，缺乏对语言层面失配的显式干预。QBridge通过引入“金标准查询”（Gold Query）作为结构化中间表示，结合蒸馏回译与双反馈修正机制，在零样本骨干下提升生成鲁棒性。该框架在Spider基准上取得86.2%的执行准确率，但绝对性能仍低于最新强化学习基线，其轻量级适配策略的泛化边界尚待验证。

## 研究背景

NL2SQL的核心挑战在于自然语言意图与数据库模式之间的语义鸿沟。当用户提问包含缩写、口语化表达或隐含逻辑时，模式链接（Schema Linking）极易出错，进而导致SQL生成失败。为缓解此问题，中间表示（Intermediate Representation, IR）被引入以解耦语言解析与符号生成，但传统IR如SQL Sketch往往脱离自然语言，丢失关键线索，且一旦模板选择错误，错误将难以恢复。

主流LLM方法通过提示工程与分解式推理提升性能，如DIN-SQL将任务拆解为子任务，DAIL-SQL利用检索增强选择示例。然而，这些方法仍依赖解码器在单步或轻量修正中完成模式对齐，未显式处理输入端的语言失配。当输入问题存在冗余、歧义或模式无意识时，错误会在解码阶段放大。QBridge的切入点在于将语言规范化前移至解码之前，通过一个显式的、模式感知的自然语言中间表示稳定意图，从而降低对单步解码鲁棒性的依赖。

## 核心方法

### 方法参照系

QBridge属于LLM提示工程与轻量适配的混合路线，其标准流程为：输入问题与模式 → 中间表示生成 → SQL生成 → 反馈修正。与纯提示工程不同，QBridge在中间表示生成阶段引入微调的轻量级重写器，并在修正阶段采用双信号反馈，区别于仅依赖执行反馈的传统自修正机制。

### 金标准查询范式与蒸馏回译

传统方法直接让LLM从问题生成SQL，缺乏对语言结构的显式约束。QBridge定义金标准查询规范（Gold Query Norm），要求重写遵循固定槽位顺序 [SELECT, FROM, JOIN, WHERE, GROUP BY, ORDER BY, LIMIT]，将子句级意图显式化。为训练重写器，提出蒸馏回译（Distilled Back-Translation, DBT）：教师LLM生成候选重写，仅保留经执行一致性验证（ECV）的样本，形成高质量语料 $D = \{(q, S, r^*)\}$。学生重写器 $M_S$ 通过监督学习最小化交叉熵损失：

$$
\mathcal{L}_{SFT} = -\sum_{i=1}^{N} \log P_{M_S}(r^*_i | q_i, S_i)
$$

该公式确保学生模型学习的是经SQL验证的、无幻觉的重写行为，而非教师模型的原始输出。DBT的关键在于将SQL作为监督信号，过滤掉逻辑漂移与模式幻觉，使重写器在推理时无需显式模式链接即可生成模式感知的查询。

### 双反馈驱动的迭代修正

重写后的金标准查询 $\tilde{r}$ 仍可能包含细微偏差，QBridge通过两阶段修正闭环。第一阶段，重写审查器基于固定检查清单（语义等价、槽位顺序、连接有效性等）诊断问题，提出最小编辑动作 $\text{fixes}_{rewrite}$，生成精化金标准查询 $\hat{r}$。第二阶段，SQL生成器基于 $\hat{r}$ 生成候选SQL $\tilde{s}$，并通过双反馈迭代修正：执行反馈 $\phi_t^e = f_{exec}(\tilde{s}_t, S)$ 捕获语法与运行时错误；语义反馈通过反向推导 $D^{\leftarrow}$ 生成逆向查询 $q_r$ 与语义编辑动作 $\Delta s_t$，显式暴露与 $\hat{r}$ 的意图偏差。更新公式为：

$$
\tilde{s}_{t+1} = R_{SQL}(\tilde{s}_t, \Delta e_t, \Delta s_t, S)
$$

其中 $\Delta e_t$ 为执行反馈转化的编辑动作。该机制将执行有效性与语义一致性解耦，避免单一执行反馈因噪声导致错误修正，确保最终SQL $\hat{s}$ 同时满足可执行性与意图忠实性。

## 实验评估

QBridge在Spider、BIRD及三个Spider鲁棒性变体上评估，基线覆盖零样本（ChatGPT-SQL、C3）、少样本（SQL-PaLM）及微调/代理系统（DAIL-SQL、DIN-SQL、MAC-SQL）。Spider基准上，QBridge + DeepSeek-V3取得86.2%平均执行准确率（EX），自一致性（SC）提升至86.8%；BIRD-dev上EX为63.4%，有效效率分数（VES）为70.7。与零样本基线相比，QBridge显著优于C3 + GPT-4（82.1% EX），但与微调基线MAC-SQL + GPT-4（86.8% EX）持平，低于最新SOTA SAFE-SQL（93.4% EX，据领域综述）。

| 方法 | Spider Dev EX | Spider Mean EX | BIRD Dev EX | BIRD Dev VES |
| :--- | :--- | :--- | :--- | :--- |
| QBridge + DeepSeek-V3 | 86.4 | 86.2 | 63.4 | 70.7 |
| QBridge + DeepSeek-V3 + SC | 86.9 | 86.8 | 64.9 | 71.9 |
| MAC-SQL + GPT-4 | 86.8 | 84.8 | 57.6 | 59.5 |
| DAIL-SQL + GPT-4 | 83.6 | 84.9 | 54.8 | 56.1 |
| C3 + GPT-4 | 82.1 | – | – | – |

消融实验显示，DBT蒸馏重写器在Spider上比无重写器基线提升+5.4 EX和+28.9 EM，证明SQL验证对重写质量的决定性作用。然而，未蒸馏的通用重写器（如Gemini-2.5-flash）在加入金标准查询规范后EX下降12.5%，表明规范约束对未适配模型具有负迁移效应。结构分层分析显示，QBridge在嵌套查询（71.7%）与集合操作（75.0%）上优于DAIL-SQL（67.9%、65.0%），但在多表连接（68.9%）上低于MAC-SQL（77.0%），暴露其在复杂连接逻辑上的局限。

评估协议采用标准Spider与BIRD指标，但BIRD仅报告dev集结果，缺乏test集验证。代码已开源，但DBT数据构建依赖DeepSeek-V3作为教师，未报告不同教师模型对重写器性能的影响。成本效率分析显示，QBridge平均每查询成本0.0010美元，显著低于DIN-SQL（0.3136美元），但延迟23.71秒高于DAIL-SQL（2.4秒），反映多阶段管道的计算开销。

## 关联研究分析

从问题动机看，QBridge与DIN-SQL均采用任务分解策略，但分解点存在本质差异。DIN-SQL将分解置于解码阶段，将SQL生成拆解为模式链接、查询分解与生成子任务，依赖LLM的上下文学习完成各子任务。QBridge则将分解前移至输入端，通过金标准查询规范化语言结构，使解码器面对的是已结构化的意图表示。这一差异源于对错误来源的不同假设：DIN-SQL假设错误主要源于复杂逻辑的推理难度，QBridge假设错误主要源于输入语言的歧义与模式无意识。当输入问题高度规范时，DIN-SQL的分解策略可能更高效；但当输入噪声大时，QBridge的前置规范化更具鲁棒性。

从方法设计看，QBridge与MAC-SQL同属代理式系统，但协作机制不同。MAC-SQL通过多智能体协作（模式链接、SQL生成、验证）实现并行处理，依赖各模块的独立优化。QBridge采用串行管道，重写、审查、生成、修正依次执行，前一阶段的输出作为后一阶段的输入。串行设计确保了中间表示的忠实性传递，但引入了累积误差风险；并行设计允许错误隔离，但缺乏全局一致性约束。QBridge的双反馈机制部分缓解了累积误差，但反向推导的语义反馈依赖LLM的逆向推理能力，其可靠性未在不同模型规模上充分验证。

## 总结

QBridge针对NL2SQL中语言失配导致的单步解码脆弱性，通过金标准查询范式与蒸馏回译实现输入端的显式规范化，结合双反馈修正闭环提升生成鲁棒性。在Spider基准上，QBridge + DeepSeek-V3取得86.2% EX，自一致性提升至86.8%，成本效率显著优于多阶段基线。然而，其绝对性能低于最新强化学习基线，且在多表连接等复杂结构上表现不及专用代理系统。DBT蒸馏依赖特定教师模型，重写器对未适配模型的负迁移效应表明，金标准查询规范的泛化能力受限于训练数据的分布覆盖。当教师模型与推理骨干不一致时，重写分布与解码器的对齐程度如何影响最终性能，论文未给出系统性回答。
