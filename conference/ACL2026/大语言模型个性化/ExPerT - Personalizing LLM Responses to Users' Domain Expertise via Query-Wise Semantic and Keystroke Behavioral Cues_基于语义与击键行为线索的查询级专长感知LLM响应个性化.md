# ACL2026最新论文 ｜ExPerT: Personalizing LLM Responses to Users' Domain Expertise via Query-Wise Semantic and Keystroke Behavioral Cues ｜基于语义与击键行为线索的查询级专长感知LLM响应个性化

研究机构：韩国高丽大学

作者：Yeji Park、Jiwon Tark、Taesik Gong

论文原文见 [arXiv](https://arxiv.org/abs/2607.01242)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.01242)

> 大语言模型（LLM）个性化旨在使通用模型输出适配特定用户的风格与偏好，其核心价值在于解决“千人一面”的通用对齐与个体需求之间的结构性矛盾。现有静态画像方法无法捕捉用户在同一主题下随任务语境波动的领域专长，导致响应复杂度与用户认知状态错配。ExPerT通过联合解析查询文本语义与击键动力学行为信号，在推理时动态推断查询级专长并条件化生成响应。该框架验证了非文本行为信号在隐式偏好发现中的有效性，但其对键盘输入场景的强依赖限制了跨设备泛化能力。

## 研究背景

当用户向LLM提出模糊或简短的查询时，模型难以仅凭文本判断其真实认知水平。专家可能为效率简化提问，新手可能误用专业术语，这种语义歧义导致静态画像方法（如Persona-based prompting）将固定的用户属性注入所有查询，忽视了专长在查询间的动态变化。为突破文本信号的局限，研究需引入能反映用户输入时认知流畅度的行为信号，击键动力学（Keystroke Dynamics）通过记录按键时序与流畅度，提供了独立于文本内容的正交证据。

现有LLM个性化研究主要依赖静态画像或长期交互历史，假设用户偏好是持久且显式的。检索增强生成（RAG）与基于强化学习的人类反馈（RLHF）微调虽能注入用户信息，但前者受限于上下文窗口与检索噪声，后者优化群体平均效用而边缘化个体差异。更关键的是，这些方法均假设专长是会话级或用户级的稳定属性，无法响应同一用户在不同子任务中从“新手”到“专家”的认知状态切换。ExPerT的切入点在于将个性化粒度从“用户”细化到“查询”，通过实时解析击键行为中的时序特征，解决文本语义无法准确推断查询级专长的难题。

## 核心方法

### 方法参照系

ExPerT属于推理时自适应（Inference-time Adaptation）路线，其标准流程为：接收用户输入→提取特征→推断用户状态→条件化生成。与RAG等依赖外部记忆库的方法不同，ExPerT不维护长期用户画像，而是将专长推断视为一个基于上下文学习（In-Context Learning, ICL）的分类任务，其关键差异在于输入模态从纯文本扩展为“语义+行为”双通道。

### 击键特征提取与词级聚合

传统击键分析多关注全局统计量，但ExPerT指出词级时序特征与语义内容对齐才能有效推断专长。设计动机在于解决全局流畅度指标无法区分“快速输入错误术语”与“快速输入正确术语”的歧义。ExPerT将原始击键序列 $K_q = \{k_0, k_1, \dots, k_m\}$ 按空格与标点分割为词单元，对每个词 $w$ 计算12维特征向量：

$$
\mathbf{x}_w = \phi(K_w) = [\mu_{dur}, \sigma_{dur}, \mu_{DD}, \sigma_{DD}, \mu_{UD}, \sigma_{UD}, \mu_{UU}, \sigma_{UU}, \mu_{DU}, \sigma_{DU}, N_{backspace}, v_{speed}]
$$

其中 $\mu$ 和 $\sigma$ 分别为按键持续时间（Duration）及四种键间间隔（Down-Down, Up-Down, Up-Up, Down-Up）的均值与标准差，$N_{backspace}$ 为退格次数，$v_{speed}$ 为每分钟击键数。该公式将细粒度的按键时序压缩为稳定的行为单元，使LLM能将“输入‘queue’时的犹豫”与“输入‘scheduling’时的流畅”分别关联到不同的语义概念上，从而捕捉专长在术语层面的分布不均。

### 语义-行为联合专长推断

仅依赖行为信号会高估新手（因熟练打字掩盖概念缺失），仅依赖语义会低估专家（因简化提问掩盖深度理解）。ExPerT通过结构化提示将语义查询 $q$ 与行为摘要 $\mathbf{X}_q$ 联合输入LLM，执行ICL分类。设计动机在于利用两种信号的正交性：语义反映“说了什么”，行为反映“怎么说”。推断过程定义为：

$$
\hat{e}_q = f_{ICL}(q, \mathbf{X}_q; \mathcal{S})
$$

其中 $f_{ICL}$ 为基于GPT-4.1的上下文学习函数，$\mathcal{S}$ 为包含10个同用户历史查询-专长对的支持集。该机制无需参数更新，通过提示中的多步分类程序引导模型权衡语义歧义与行为流畅度，例如当语义显示“请求解释”但行为显示“高速度低退格”时，模型倾向于判定为专家而非新手，从而避免了单一模态的误判。

## 实验评估

实验在自建数据集上进行，包含40名参与者、3个领域（化学、计算机科学、商业）的1270条查询，每条查询记录文本、击键日志、自报专长（5级）及满意度评分。基线覆盖静态画像（Persona-based）、会话级聚合（Session-level）及动态对话适应（IDL, AI Persona）路线，但缺失RAG标准基线，且所有基线均未使用行为信号。

| 方法 | 适应类型 | 语义 | 行为 | MAE↓ | MSE↓ |
|---|---|---|---|---|---|
| Random Guess | Static | ✗ | ✗ | 1.600 | 4.000 |
| Persona-based | Static | ✓ | ✗ | 1.251 | 2.341 |
| Session-level | Static | ✓ | ✗ | 1.307 | 2.406 |
| IDL | Dynamic | ✓ | ✗ | 1.162 | 1.885 |
| AI Persona | Dynamic | ✓ | ✗ | 1.353 | 2.633 |
| Semantic-only | Dynamic | ✓ | ✗ | 0.488 | 0.858 |
| Behavior-only | Dynamic | ✗ | ✓ | 0.790 | 1.600 |
| **ExPerT** | Dynamic | ✓ | ✓ | **0.398** | **0.698** |

ExPerT的MAE 0.398较最强基线IDL（1.162）降低65.7%，且显著优于仅用语义（0.488）或仅用行为（0.790）的消融变体，证实了双模态融合的必要性。

| 击键表示方法 | MAE↓ | MSE↓ |
|---|---|---|
| Key-level Raw Feature | 0.483 | 0.887 |
| Query-level Aggregation | 0.410 | 0.735 |
| Word-level Aggregation | 0.398 | 0.698 |

词级聚合较键级原始特征降低MAE 0.085，较查询级聚合降低0.012，表明粒度选择对行为信号有效性有显著影响，词级在稳定性与语义对齐间取得最优平衡。

评估边界方面，实验仅使用自建数据集，未与LaMP、LongLaMP等标准基准对比，跨领域泛化性存疑。指标仅包含MAE/MSE与满意度，缺乏事实性幻觉检测。代码已开源，但击键采集依赖自定义Web界面，移动端触控场景未验证。

## 关联研究分析

从问题动机看，ExPerT与RPM（ICLR 2026）同属推理时个性化，但RPM依赖文本推理路径引导生成，假设偏好可从对话历史中显式提取；ExPerT则针对“文本无法推断专长”的盲区，引入击键行为作为隐式信号。这一差异源于任务特性：RPM处理的是风格偏好，可通过语义匹配捕捉；ExPerT处理的是认知状态，需依赖输入时的生理-认知耦合信号。IDL（Cheng et al., 2024）虽也采用动态适应，但其通过DPO微调更新参数，假设专长在会话内稳定；ExPerT的查询级粒度更细，但代价是依赖实时行为采集，无法在纯文本API场景部署。

从方法设计看，ExPerT与Persona-based（Hu and Collier, 2024）形成鲜明对比：后者将用户属性作为静态前缀注入所有查询，ExPerT则通过ICL动态推断每查询专长。这一差异揭示了静态画像在“同用户不同专长”场景下的根本失效。然而，ExPerT的ICL推断依赖10-shot同用户历史，若用户首次交互（冷启动）则支持集为空，此时行为信号是否仍能独立支撑专长推断，论文未给出回答。

## 总结

ExPerT要解决的核心矛盾是静态画像无法捕捉查询级专长动态性，导致响应复杂度与用户认知状态错配。其切入点在于利用击键动力学这一非文本行为信号，通过语义-行为联合ICL推断实现查询级专长估计。方法上，ExPerT设计了词级击键特征聚合管道与双模态提示框架，证明了行为信号在隐式偏好发现中的有效性。实验显示，ExPerT将专长推断MAE从1.162降至0.398，满意度从3.71提升至4.36。其边界在于强依赖键盘输入场景，且冷启动时缺乏历史支持集。当用户通过语音或移动端触控交互时，击键时序特征失效，此时仅靠语义信号能否维持查询级专长推断的准确性，论文未给出回答。
