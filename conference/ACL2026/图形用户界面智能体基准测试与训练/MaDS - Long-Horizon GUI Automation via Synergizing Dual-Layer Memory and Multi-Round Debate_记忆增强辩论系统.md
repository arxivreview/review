# ACL2026最新论文 ｜MaDS: Long-Horizon GUI Automation via Synergizing Dual-Layer Memory and Multi-Round Debate ｜记忆增强辩论系统

作者：Pengchen Chen、Shi Chen、Qiming Ye 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_7b95440f6dab)

> 长程GUI自动化面临的核心矛盾是视觉定位的噪声敏感性与操作不可逆性之间的冲突。现有方法或依赖脆弱的结构化数据，或采用线性执行导致错误累积，缺乏执行前的强制验证机制。MaDS通过双层记忆提供上下文先验抑制幻觉，并引入多轮辩论在执行前拦截风险动作，将失败转化为可检索的负向约束。该方法在自建基准上取得90.23%的任务成功率，但其性能高度依赖特定骨干模型与人工构建的基准，跨平台泛化能力存疑。

## 研究背景

GUI智能体在真实移动环境中执行长程任务时，首先遭遇的是界面元素的视觉噪声。密集布局下的低信噪比（SNR）使得纯视觉模型难以区分目标与背景，导致定位幻觉；而基于HTML或Accessibility Tree的结构化方法则因自定义渲染和动态内容导致元数据缺失或失效，无法覆盖所有应用场景。这种感知层的不可靠性直接传导至决策层：在不可逆的操作环境中，一次微小的定位偏差或规划错误会引发级联失败，且事后纠错机制因动作已执行而失效。

主流的多智能体框架（如Mobile-Agent、Agent S）虽通过规划-执行分离提升了稳定性，但普遍采用线性执行或事后验证范式。这种设计假设错误是可逆的，或至少允许在错误发生后进行回溯，但在真实GUI操作中，删除文件、发送消息等动作一旦执行便无法撤销。此外，现有记忆模块多依赖启发式规则或嵌入相似度进行检索，在低SNR环境下检索精度下降，导致智能体无法有效利用历史经验避免重复错误。MaDS的切入点在于将验证环节前移至执行之前，并通过辩证学习机制将失败经验转化为硬约束，从根本上切断错误累积的路径。

## 核心方法

### 方法参照系

MaDS属于多智能体协作架构，其参照系为“规划-执行-反思”闭环。与标准流程的关键差异在于，MaDS在规划与执行之间插入了强制的“多轮辩论”验证环节，并将反思模块的输出从简单的轨迹摘要升级为包含因果分析的负向警告（Negative Warnings），作为后续检索的硬约束。

### 双层记忆模块

传统记忆模块仅存储成功轨迹，导致智能体在遇到新场景时缺乏对潜在风险的预判。MaDS引入双层存储结构，将通用交互先验（Semantic Knowledge Memory）与场景特定经验（Operational Experience Memory）解耦。语义层预装43个基于Android Material Design的通用事实，提供概率性先验；经验层则通过软分区（Soft Partitioning）和过程签名（Process Signature）$S_{sig}$ 记录动作意图而非像素坐标，以抵抗分辨率变化和布局漂移。检索策略采用场景优先的全局回退机制，公式如下：

$$ R(q, M) = \text{TopK}(q, M_{sem}) \cup \text{TopK}(q, \text{Scope}(M_{exp}, L_{scene}|\tau)) $$

该公式表明，系统首先从语义记忆中检索通用规范，同时从经验记忆中检索当前场景下的特定约束；当场景内相似度低于阈值$\tau$时，自动扩展至全局池，平衡了检索精度与召回率。

### 多轮辩论与辩证学习

线性执行范式无法拦截规划阶段的逻辑错误。MaDS通过多轮辩论（Multi-Round Debate）在执行前对计划进行对抗性审查。评估智能体基于规则合规性$C_{rule}$、视觉定位$C_{ground}$和逻辑一致性$C_{logic}$计算最终置信度：

$$ C_{final} = w_1 C_{rule} + w_2 C_{ground} + w_3 C_{logic} $$

若$C_{final}$低于阈值，触发重新规划；若达到最大轮数$K_{max}$仍无共识，则执行置信度最高的计划以避免停滞。执行后，反思模块通过解析前后截图的语义变化，将失败归因并封装为负向警告存入记忆。这些警告在后续辩论中作为硬约束，直接拒绝与历史错误轨迹相似的动作，实现了从“事后修复”到“事前预防”的范式转移。

## 实验评估

实验在MaDS-Benchmark（271个任务，平均15.5步）及AITW、AITZ、CAGUI等公开基准上进行。基线覆盖通用MLLM（GPT-5, Claude-3.5-Sonnet等）和专用智能体框架（AutoGLM, AgentCPM-GUI等），但缺失了基于强化学习的最新方法（如MobileRL, UI-S1），这可能低估了MaDS相对于RL范式的相对优势。所有框架统一使用Doubao-1.5-UI-TARS作为视觉编码器，GPT-4o作为推理引擎，以隔离架构贡献。

| 方法 | AITW (TSR/SPSR/SSR) | AITZ (TSR/SPSR/SSR) | CAGUI (TSR/SPSR/SSR) | MaDS-Benchmark (TSR/SPSR/SSR) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5 | 2.70 / 91.86 / 46.33 | 0.00 / 91.26 / 25.97 | 0.00 / 93.70 / 19.53 | 0.00 / 94.21 / 18.01 |
| AutoGLM | 83.78 / 90.46 / 86.16 | 90.48 / 95.17 / 97.15 | 90.32 / 96.15 / 98.44 | 71.43 / 86.69 / 95.48 |
| AgentCPM-GUI | 86.49 / 95.56 / 96.69 | 80.95 / 94.08 / 94.24 | 77.42 / 94.37 / 95.89 | 42.86 / 64.10 / 90.72 |
| MaDS | 94.74 / 96.41 / 97.03 | 95.24 / 96.83 / 97.49 | 96.77 / 98.24 / 99.37 | 90.23 / 95.83 / 98.34 |

MaDS在MaDS-Benchmark上以90.23%的任务成功率（TSR）领先AutoGLM（71.43%）18.8个百分点，表明事前验证机制在长程任务中的显著增益。消融实验显示，移除多轮辩论导致TSR从91.67%降至22.22%，恢复成功率（RSR）从85.71%降至36.20%，证实辩论机制是防止错误累积的关键。仅使用操作经验记忆可将TSR从5.56%提升至72.22%，但加入语义记忆后进一步提升至91.67%，说明通用先验对推理陌生界面组件具有互补作用。

评估边界方面，MaDS-Benchmark由人工构建且任务长度显著长于现有基准，可能存在过拟合风险。论文未报告推理延迟和计算成本，多轮辩论机制可能显著增加实时性开销。代码已开源，但超参数设置（如$\tau_{conf}$, $K_{max}$）未详细披露，限制了跨平台复现性。

## 关联研究分析

从问题动机看，MaDS与Mobile-Agent-v2同属多智能体架构，但后者侧重通过记忆模块解决上下文丢失问题，而MaDS聚焦于不可逆错误的事前拦截。Mobile-Agent-v2的反思机制主要用于轨迹摘要，缺乏对失败因果的细粒度分析，导致其无法生成硬约束来阻止重复错误。MaDS引入的负向警告机制将失败转化为可检索的约束，这一设计源于GUI操作不可逆性的任务特性，而非通用的记忆优化需求。

从方法设计看，MaDS与UI-S1在提升长程稳定性上路径迥异。UI-S1通过半在线强化学习优化策略分布，依赖大量交互数据来学习错误恢复能力；MaDS则通过推理时的辩论验证和记忆检索，在不更新模型参数的前提下提升鲁棒性。UI-S1的优势在于分布外泛化，但训练成本高且样本效率低；MaDS的优势在于部署灵活性和即时纠错，但其性能上限受限于骨干模型的推理能力和记忆库的覆盖范围。两者在“学习”与“验证”之间的取舍，反映了GUI智能体在数据稀缺与计算资源约束下的不同技术路线。

## 总结

MaDS旨在解决长程GUI任务中视觉噪声导致的定位幻觉与操作不可逆性引发的错误累积矛盾。其切入点在于将验证环节前移至执行之前，并通过辩证学习将失败经验转化为硬约束，从而在无需更新模型参数的情况下提升鲁棒性。实验表明，MaDS在自建基准上取得90.23%的任务成功率，显著优于AutoGLM等基线。然而，其性能高度依赖GPT-4o的推理能力和人工构建的MaDS-Benchmark，且在公开基准上的高分可能部分源于骨干模型的强大预训练能力，而非框架本身的贡献。当任务复杂度进一步增加或界面异构性加剧时，多轮辩论的计算开销与记忆检索的精度瓶颈是否会导致系统性能急剧下降，论文未给出回答。
