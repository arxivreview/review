# ACL2026最新论文 ｜Mobile-R1: Towards Interactive Capability for VLM-Based Mobile Agent via Systematic Training ｜分层课程强化学习驱动的多轮移动智能体

研究机构：阿里巴巴集团

作者：Jihao Gu、Qihang Ai、Yingyao Wang 等 14 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_c37dbd4d148e)

> 移动端图形用户界面（GUI）智能体需在动态、部分可观测的环境中完成多步任务，但现有基于视觉语言模型（VLM）的强化学习方法多依赖单步动作级奖励，导致智能体陷入局部最优，缺乏跨步骤的探索与纠错能力。本文指出，直接施加任务级稀疏奖励会引发训练不稳定，而纯动作级监督则抑制了长程规划。Mobile-R1 提出三阶段分层课程（格式对齐、可验证动作探索、多轮任务级优化），在 3B 参数骨干上实现了 78.55% 的动作准确率与 30.60% 的任务成功率，并观察到“顿悟式”自我纠错行为的涌现。其价值在于验证了分层奖励对稀疏 GUI 环境的适配性，但任务成功率仍低于 7B 基线，且评估局限于中文应用生态，跨平台泛化能力存疑。

## 研究背景

GUI 智能体的核心挑战在于将自然语言指令映射为像素级操作序列，这一过程依赖视觉语言模型（VLM）对截图的感知与推理。然而，移动端环境具有动态性与部分可观测性，单步动作的正确性无法保证整体任务的成功，这要求智能体具备跨步骤的状态回溯与错误修正能力。Group Relative Policy Optimization (GRPO) 作为无需价值函数的强化学习算法，通过组内归一化优势解决稀疏奖励问题，成为 VLM 训练的主流范式。但 GRPO 在 GUI 场景中的直接应用面临奖励稀疏性困境：任务级奖励信号过于稀疏，导致策略梯度估计方差大；动作级奖励虽密集，却仅优化单步精度，无法引导长程规划。

现有基于 RL 的 GUI 智能体（如 UI-R1、GUI-R1）多采用单步动作级奖励，其本质是“贪心局部最优”策略，智能体被鼓励“思考更久”以选择精确的单步动作，却缺乏对整体任务轨迹的反思能力。这种范式在静态或短程任务中有效，但在多轮交互的移动端场景中，早期微小错误会累积导致后续轨迹偏离，且智能体无法从错误状态中恢复。Mobile-R1 的切入点在于识别出“动作级”与“任务级”奖励之间的梯度断层：直接跳过动作级探索进入任务级训练会导致奖励平台期，而仅依赖动作级奖励则抑制探索。因此，本文提出通过分层课程平滑过渡，先建立原子动作的执行能力，再解锁任务级规划与自我纠错。

## 核心方法

### 方法参照系

本文问题属于“基于 RL 的 GUI 智能体训练”类别，标准流程为 SFT 冷启动 + 单步 GRPO 优化。关键差异在于：标准流程将奖励局限于单步动作匹配，而本文将奖励扩展至多轮轨迹，并引入课程学习机制以解决稀疏奖励下的训练不稳定问题。

### 三阶段分层课程与可验证反馈

Stage 1 采用监督微调（SFT）进行格式对齐，建立指令、GUI 状态与动作的初步关联。Stage 2 引入可验证动作反馈（Verifiable Action Feedback），通过密集奖励信号稳定原子动作执行。其奖励函数定义为：

$$R_{\text{action}} = R_{\text{Act}} + R_{\text{Fmt}}$$

其中 $R_{\text{Act}}$ 为动作正确性奖励（坐标动作需落在真实边界框内，非坐标动作需精确匹配），$R_{\text{Fmt}}$ 为格式完整性奖励（二值，1 或 0）。这一设计解决了稀疏奖励下的“冷启动失败”问题，确保智能体在执行长程任务前已具备稳定的单步交互能力。

### 多轮任务级 GRPO 与顿悟式纠错

Stage 3 转向多轮任务级 GRPO，奖励施加于整个轨迹而非单步。轨迹级奖励 $R_{\text{task}}$ 由格式奖励与轨迹级奖励组成：

$$R_{\text{task}} = R_{\text{Fmt}} + R_{\text{Traj}}$$

其中 $R_{\text{Traj}}$ 由 GPT-4o 作为 LLM-as-Judge 对轨迹连贯性与任务完成度进行 5 级评分（0-1）。该设计动机在于：动作级奖励鼓励贪心局部最优，而任务级奖励通过长程信用分配，迫使智能体反思历史轨迹，从而涌现“顿悟式”（Eureka）自我纠错能力——即智能体能从错误状态回溯至正确动作。

## 实验评估

实验在自建中文基准（500 轨迹/1842 步）上进行，基线覆盖 UI-R1、GUI-R1、AgentCPM 等 RL 方法，但缺失纯 SFT 基线（如 UI-TARS）及英文生态强基线。主实验结果显示，Mobile-R1 在 3B 骨干上取得 78.55% 的动作准确率，较最佳基线（GUI-R1-7B 的 71.72%）高 6.83 个百分点，但任务成功率（30.60%）低于 GUI-R1-7B（32.60%），表明 3B 骨干在长程规划上存在瓶颈。

消融实验显示，Stage 1 & 2 已使 3B 模型超越标准版本，但 Stage 3 仅带来 1.2 个百分点的任务成功率提升，边际收益递减。跳过 Stage 2 直接进行 Stage 3 导致奖励平台期，验证了动作级与任务级奖励间的梯度断层。评估边界方面，指标完备性不足（未报告推理延迟、Token 消耗），评估协议局限于中文应用（京东、淘宝等），缺乏跨平台泛化测试；可复现性方面，代码与数据已开源，但 GPT-4o 作为奖励模型的版本（0806）可能引入评估偏差。

## 关联研究分析

从问题动机看，Mobile-R1 与 UI-R1、GUI-R1 同属 GRPO 框架，但后者聚焦单步动作级奖励，本质是“局部最优”策略；Mobile-R1 则通过任务级奖励实现“全局规划”，其差异根源在于任务特性：移动端多轮交互要求长程信用分配，而单步奖励无法捕捉跨步骤依赖。从方法设计看，Mobile-R1 与 DeepSeek-R1 的规则奖励思路一致，但将规则奖励从文本推理迁移至 GUI 交互场景，并引入课程学习以缓解稀疏性。与 ARPO（任务级在线 RL）相比，Mobile-R1 的分层课程更强调“动作-任务”过渡的稳定性，而 ARPO 直接采用任务级奖励，可能面临更严重的训练震荡。

## 总结

Mobile-R1 旨在解决 GUI 智能体在稀疏奖励环境下的长程规划与纠错难题，其切入点在于识别出动作级与任务级奖励间的梯度断层，并通过分层课程平滑过渡。方法上，三阶段课程（格式对齐、可验证动作探索、多轮任务级优化）在 3B 骨干上实现了 78.55% 的动作准确率与 30.60% 的任务成功率，验证了分层奖励对稀疏 GUI 环境的适配性。然而，任务成功率低于 7B 基线，且评估局限于中文应用生态，跨平台泛化能力未经验证。当支持集从 500 轨迹扩展至更大规模时，任务级奖励的稀疏性是否仍构成瓶颈，论文未给出回答。
