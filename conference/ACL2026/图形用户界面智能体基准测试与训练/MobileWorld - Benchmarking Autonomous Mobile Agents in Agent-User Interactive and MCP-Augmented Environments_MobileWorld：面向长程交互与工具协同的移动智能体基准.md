# ACL2026最新论文 ｜MobileWorld: Benchmarking Autonomous Mobile Agents in Agent-User Interactive and MCP-Augmented Environments ｜MobileWorld：面向长程交互与工具协同的移动智能体基准

作者：Quyu Kong、Xu Zhang、Zhenyu Yang 等 13 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_cd0767eed124)

> 现有移动GUI智能体基准已陷入饱和，AndroidWorld上SOTA框架成功率超过90%，导致增量改进与实质性突破难以区分。本文指出饱和背后是任务复杂度的结构性缺失：短程单应用任务无法覆盖真实场景中的跨应用工作流、模糊指令澄清及外部工具调用。MobileWorld通过构建201个长程任务，引入Agent-User Interaction与MCP-Augmented两类新任务范式，在容器化开源环境中实现确定性评估。该基准揭示了当前端到端模型在交互与工具编排上的能力断层，但其依赖LLM模拟用户与开源替代应用的设定，限制了结论向真实商业环境的直接外推。

## 研究背景

当智能体执行“给Kevin发邮件”这类指令时，若设备通讯录中不存在该联系人，传统基准假设指令完备，智能体只能失败或幻觉；而真实场景中，智能体需识别信息缺失并主动发起澄清。这一需求引出了Agent-User Interaction任务，其核心在于测试模型对歧义的感知与主动询问能力，而非单纯的视觉定位。同时，随着Model Context Protocol (MCP) 成为标准化工具接口，智能体需在GUI操作与API调用间动态切换，这构成了MCP-Augmented任务，要求模型具备混合动作空间的编排能力。

移动GUI智能体领域长期依赖AndroidWorld作为核心评测基准，其可复现的模拟器环境与确定性验证机制确立了行业规范。然而，随着UI-TARS等模型在AndroidWorld上取得90%以上的成功率，该基准已无法有效区分模型间的性能差异。更关键的是，现有基准普遍缺乏对长程跨应用工作流、模糊指令处理及外部工具集成的评估，导致模型在真实复杂场景中的鲁棒性被高估。MobileWorld的切入点在于通过提升任务步长与跨应用比例，并引入交互与工具协同任务，重建一个能暴露当前架构短板的评测坐标系。

## 核心方法

### 基准架构参照系

MobileWorld继承AndroidWorld的容器化Android AVD架构与确定性验证思路，但将任务构造逻辑从“单应用状态转移”扩展为“多应用状态协同”。关键差异在于，本文环境不仅包含GUI操作，还集成了LLM模拟用户与MCP服务器，使得动作空间从纯GUI扩展为GUI、交互、工具三类动作的混合体。

### 混合动作空间与确定性验证

传统基准仅支持GUI动作，导致无法评估智能体在信息缺失时的澄清行为或工具调用决策。MobileWorld扩展动作空间，引入`ask_user`与`mcp_call`动作，并设计多模态验证机制确保评估确定性。对于Agent-User Interaction任务，智能体需调用`ask_user`向LLM模拟用户获取缺失信息，其质量通过User Interaction Quality (UIQ) 衡量：

$$
UIQ = \frac{\sum_{i \in I_{interact}} q_i}{|I_{interact}| + |I_{triggered}|}
$$

其中 $q_i$ 为任务 $i$ 的质量分，当 $c_i > 0$ 时 $q_i = s_i / c_i$，否则为0。该公式惩罚不必要的询问，奖励高效澄清。对于MCP任务，智能体需调用外部工具获取数据，验证通过后端数据库检查完成，避免了MLLM-as-a-judge的噪声。这一设计解决了商业应用黑盒导致的评估不可复现问题，使工具调用与交互行为可被精确量化。

### 长程跨应用任务构造

现有基准任务平均步长仅14.3步，且9.5%涉及跨应用，无法测试长程记忆与规划。MobileWorld将平均步长提升至27.8步，62.2%任务涉及跨应用工作流。任务构造采用“信息剥离”策略：人工标注完整目标后，移除关键信息（如邮箱地址），并验证设备环境不含该信息，迫使智能体必须通过交互获取。这种构造方式将长程规划与主动澄清绑定，使模型无法通过单步定位或简单状态转移完成任务，从而暴露其在多步依赖与上下文追踪上的缺陷。

## 实验评估

实验在MobileWorld的201个任务上进行，对比3个前沿LLM驱动的Agentic框架（GPT-5, Claude-4.5-Sonnet, Gemini-3-Pro）与9个端到端GUI模型（如Doubao-1.5-UI-TARS, Qwen3-VL系列）。基线覆盖了当前主流的视觉语言模型与专用GUI模型，但缺乏针对MobileWorld专门训练的SFT/RL模型，限制了算法贡献与骨干网络能力的区分。

| 模型 | 总体SR (%) | GUI-Only SR (%) | User-Int. SR (%) | MCP SR (%) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5 | 51.7 | 54.0 | 62.2 | 51.6 |
| Gemini-3-Pro | 46.3 | 55.6 | 24.4 | 48.6 |
| Claude-4.5-Sonnet | 43.8 | 47.8 | 37.8 | 50.0 |
| Doubao-1.5-UI-TARS | 20.9 | 26.3 | 32.4 | - |
| Qwen3-VL-235A22B | 9.5 | 12.8 | 4.4 | 5.4 |

GPT-5以51.7%的总体成功率领先，但远低于AndroidWorld上90%以上的SOTA水平，证实了基准的难度提升。端到端模型表现显著落后，最佳模型Doubao-1.5-UI-TARS仅20.9%，且在MCP任务上接近0%，揭示了端到端架构在工具编排上的根本缺陷。

| 模型 | 平均步数 | 平均查询数 | UIQ | 平均MCP调用 |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5 | 27.8 | 1.11 | 0.40 | 2.23 |
| Claude-4.5-Sonnet | 26.6 | 0.76 | 0.25 | 1.91 |
| Gemini-3-Pro | 24.2 | 0.36 | 0.19 | 2.63 |
| Doubao-1.5-UI-TARS | 20.9 | 1.22 | 0.13 | - |

GPT-5在交互任务上表现最佳，UIQ达0.40，表明其能高效识别歧义并澄清。Gemini-3-Pro虽GUI-Only成功率较高（55.6%），但UIQ仅0.19，平均查询数0.36，显示其过度依赖单步推理而忽视澄清。Doubao-1.5-UI-TARS查询数最高（1.22）但UIQ最低（0.13），说明其频繁发出无效或冗余的澄清请求，反映了端到端模型在交互策略上的低效。

评估协议采用确定性验证（数据库、存储、文本匹配），避免了主观评分噪声，但依赖开源替代应用（如Mattermost替代Slack），其UI复杂度与商业应用存在差异。LLM模拟用户（GPT-4.1）的响应模式可能无法覆盖真实人类的模糊性与不耐烦情绪，限制了交互任务结论的普适性。代码与超参数未完全公开，复现需自行构建MCP服务器与模拟用户环境。

## 关联研究分析

从问题动机看，MobileWorld与OSWorld-MCP均关注工具协同，但OSWorld侧重桌面环境的API调用，而MobileWorld聚焦移动端的GUI-工具混合编排。MobileWorld引入Agent-User Interaction任务，这一设计源于τ-bench的模拟用户对话范式，但将其与GUI操作绑定，测试模型在视觉感知与语言交互间的切换能力。OSWorld-MCP未涉及模糊指令澄清，因此无法评估模型在信息缺失时的主动行为，这反映了桌面任务与移动任务在用户交互模式上的本质差异。

从方法设计看，MobileWorld的Planner-Executor框架将视觉定位与高层规划解耦，允许通用VLM作为规划器，专用模型作为定位器。这与UI-TARS等端到端模型形成对比，后者将定位与规划整合在单一模型中。实验显示，Agentic框架在MobileWorld上显著优于端到端模型，表明在长程复杂任务中，解耦架构能更好地处理跨应用协调与工具调用。然而，端到端模型在GUI-Only任务上的表现（如Doubao-1.5-UI-TARS的26.3%）仍高于部分Agentic框架（如Claude-4.5-Sonnet的47.8%），提示端到端模型在纯视觉操作上的效率优势，但在混合任务上的泛化能力不足。

## 总结

MobileWorld旨在解决移动GUI智能体基准饱和与真实场景复杂度缺失的矛盾。通过引入长程跨应用任务、Agent-User Interaction与MCP-Augmented任务，该基准在容器化开源环境中实现了确定性评估，揭示了当前模型在交互澄清与工具编排上的能力断层。实验显示，最佳Agentic框架GPT-5仅达51.7%成功率，而端到端模型在MCP任务上接近0%，证实了现有架构在混合动作空间上的根本局限。该基准的边界在于依赖LLM模拟用户与开源替代应用，其交互模式与UI复杂度可能无法完全代表真实商业环境。当模拟用户的响应模式从GPT-4.1切换为更具模糊性的模型时，智能体的澄清策略是否会发生显著变化，论文未给出回答。
