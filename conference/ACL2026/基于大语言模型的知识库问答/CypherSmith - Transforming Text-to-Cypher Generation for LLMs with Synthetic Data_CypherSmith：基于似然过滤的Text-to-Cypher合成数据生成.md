# ACL2026最新论文 ｜CypherSmith: Transforming Text-to-Cypher Generation for LLMs with Synthetic Data ｜CypherSmith：基于似然过滤的Text-to-Cypher合成数据生成

研究机构：美国俄勒冈大学

作者：Zeyu Zhang、Kexuan Sun、Zheng Tang 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_9bc36d94cd6e)

> 导读 Text-to-Cypher旨在将自然语言问题转化为属性图数据库的可执行查询，以解决大语言模型在知识图谱检索中的事实幻觉与知识截止问题。现有指令数据集规模小、领域受限且依赖昂贵专有模型或规则模板，导致模型泛化能力不足。本文提出CypherSmith，通过开源大模型将SQL模式转换为知识图谱本体，并引入基于似然比的数据过滤机制以剔除噪声。该方法在Text2Cypher和CypherBench基准上显著提升了微调模型性能，但其无真实图谱执行验证的过滤策略在语义一致性上的完备性仍存疑。

## 研究背景

属性图（Property Graph）因其紧凑的架构与人类可读的模式，正逐步取代资源描述框架（RDF）成为工业界知识图谱存储的主流范式。在属性图中，实体与关系被建模为节点与边，Cypher作为其标准查询语言，允许通过声明式语句检索复杂子图。然而，大语言模型直接生成Cypher查询时，常因缺乏外部事实约束而产生语法错误或语义偏差，即幻觉。为缓解此问题，检索增强生成（RAG）范式通常依赖子图检索，但现有方法在编码结构与语义方面存在瓶颈，且难以扩展至包含数十亿三元组的现代知识图谱。因此，将自然语言直接转化为精确、可执行的Cypher查询（Text-to-Cypher）成为提升知识图谱检索准确性的关键路径。

Text-to-Cypher的研究受限于公开数据集的稀缺与质量低下。现有数据集如CySpider、SyntheT2C等，多采用规则映射或专有大模型生成，导致数据规模有限、领域覆盖狭窄且缺乏多样性。此外，传统数据清洗方法依赖真实知识图谱执行查询以验证正确性，但在大规模合成数据场景下，构建对应真实图谱的成本极高甚至不可行。这一矛盾构成了本文的核心切入点：如何在无真实知识图谱执行验证的前提下，大规模合成高质量、高多样性的Text-to-Cypher指令数据，以支撑大语言模型的有效微调。

## 核心方法

### 方法参照系

Text-to-Cypher通常被建模为序列到序列任务，输入包含本体、自然语言问题与指令，输出为Cypher查询。标准流程依赖真实知识图谱执行查询以验证语义一致性，但本文场景下无真实图谱可用，故需替代验证机制。

### 基于SQL模式转换的数据合成

数据合成阶段旨在解决现有数据集领域单一的问题。本文利用开源大模型Qwen2.5-32B-Instruct，将大规模Text-to-SQL数据集SynSQL-2.5M中的数据库模式转换为属性图本体。转换规则为：表映射为实体，列映射为属性，外键映射为关系。为增强多样性，随机采用四种本体格式（类列表、YAML、Python字典、Neo4j约束）。生成顺序遵循“查询优先”策略，即先生成Cypher查询，再基于查询与本体生成自然语言问题及推理文本。此设计动机在于，Cypher查询的结构精确性使得逆向生成自然语言问题比正向生成更可靠，从而降低语义歧义。

### 基于似然比的数据过滤

数据过滤阶段旨在解决合成数据中的噪声与冗余问题，且无需真实图谱执行。首先通过Neo4j库进行语法验证，剔除513,648个语法错误样本；随后进行本体对齐检查，确保查询中引用的实体、属性与关系在本体中明确定义，再剔除141,530个样本。核心创新在于语义过滤，提出基于似然比的过滤准则。设完整上下文为 $(i, o, q, r)$，生成查询 $c$ 的概率为 $P(c|i, o, q, r)$。若移除某上下文元素 $e \in \{o, q, r\}$ 后，生成概率未降低，则说明该元素冗余或噪声。过滤准则定义为：

$$
P(c|i, o, q, r) < \min\{P(c|i, q, r), P(c|i, o, r), P(c|i, o, q)\}
$$

该公式的物理含义是：只有当完整上下文（本体、问题、推理）共同作用时，模型生成查询的置信度高于任何缺失单一元素的子上下文，该样本才被视为高质量。此机制替代了传统执行验证，通过模型内部似然分数评估各上下文元素的贡献度，从而在缺乏真实图谱的情况下实现语义一致性过滤。

## 实验评估

实验在Text2Cypher与CypherBench两个基准上进行，基线涵盖专有模型（GPT-5, GPT-4o）、开源模型（Qwen2.5系列）及不同数据集微调的模型。主要对比对象包括使用Text2Cypher、CypherBench、SyntheT2C、CySpider、SynthCypher数据集微调的模型。

| 数据集 | 模型 | BLUE | EX-A | EX | PSJS | Exec |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Text2Cypher | LLM + CypherSmith | 77.6 | 30.9 | 53.9 | - | - |
| Text2Cypher | LLM + Text2Cypher | 72.7 | 29.3 | 51.4 | - | - |
| Text2Cypher | GPT-5 | 59.3 | 22.6 | 49.2 | - | - |
| CypherBench | LLM + CypherSmith | - | - | 74.8 | 77.5 | 99.2 |
| CypherBench | LLM + CypherBench | - | - | 34.2 | 46.3 | 86.0 |
| CypherBench | GPT-5 | - | - | 64.8 | 82.0 | 93.1 |

在Text2Cypher上，使用CypherSmith微调的模型EX分数为53.9，超越GPT-5的49.2；在CypherBench上，EX分数达74.8，显著高于GPT-5的64.8。消融实验表明，移除推理文本 $r$ 导致性能显著下降，验证了推理标注的重要性。在似然过滤项中，移除 $P(c|i, o, r)$（即忽略问题对查询的条件作用）导致最大性能跌幅，确认了问题上下文在查询生成中的关键作用。

评估边界方面，本文仅评估英语场景，未涉及多语言泛化。评估指标包含BLEU、执行准确率（EX-A/EX）及来源子图Jaccard相似度（PSJS），但未报告计算延迟与内存开销。代码与超参数未公开，可复现性受限。

## 关联研究分析

从数据生成策略看，CypherSmith与SyntheT2C、CySpider等现有Text-to-Cypher数据集存在根本差异。后者依赖规则映射或专有模型（如GPT-4o）生成数据，导致成本高且领域受限；本文利用开源模型转换SynSQL-2.5M的SQL模式，实现了领域覆盖的扩展与成本降低。这一差异源于任务特性：SQL模式的结构化程度高，易于通过规则或模型映射为图本体，而直接生成图查询则需更复杂的语义理解。本文的“查询优先”生成策略借鉴了Text-to-SQL领域的经验，但将其适配至Cypher场景，解决了自然语言问题生成中的歧义问题。

从数据过滤机制看，本文的似然比过滤与IFD（Instruction-Following Difficulty）等指令数据选择方法思想类似，均利用模型内部状态评估数据质量。但IFD依赖单样本与零样本性能差异，而本文针对Cypher上下文定制，比较完整上下文与缺失单一元素上下文的似然比。这一差异源于数据特性：Text-to-Cypher数据包含本体、问题、推理三个强相关上下文元素，单一元素的缺失会显著影响查询生成的正确性，因此需评估各元素的边际贡献。相比之下，通用指令数据缺乏这种结构化的上下文依赖，故IFD等通用方法无法直接迁移。

## 总结

CypherSmith旨在解决Text-to-Cypher指令数据规模小、质量低且依赖真实图谱验证的矛盾。其切入点在于利用开源模型转换SQL模式为图本体，并通过似然比过滤替代执行验证，从而在无真实图谱条件下实现大规模高质量数据合成。实验表明，该方法在Text2Cypher与CypherBench上显著提升了微调模型的执行准确率，分别达到53.9与74.8，超越GPT-5等专有模型。然而，本文的边界在于仅支持英语，且似然比过滤未验证其在复杂多跳推理或噪声本体下的鲁棒性。当本体中存在冗余或歧义关系时，似然比过滤是否仍能准确区分有效与噪声样本，论文未给出回答。
