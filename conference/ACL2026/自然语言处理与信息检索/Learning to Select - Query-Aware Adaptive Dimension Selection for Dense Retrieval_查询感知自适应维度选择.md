# ACL2026最新论文 ｜Learning to Select: Query-Aware Adaptive Dimension Selection for Dense Retrieval ｜查询感知自适应维度选择

研究机构：北京航空航天大学

作者：Zhanyu Wu、Richong Zhang、Zhijie Nie

论文原文见 [arXiv](https://arxiv.org/abs/2602.03306)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.03306)

> 稠密检索的高维嵌入存在查询级冗余，即仅部分维度对特定查询的相关性排序有贡献，其余维度甚至产生干扰。现有方法要么依赖噪声伪相关反馈（PRF）进行启发式推断，要么学习全局共享的适配器变换，均无法实现基于监督信号的查询级动态维度筛选。本文提出从监督标签蒸馏“Oracle”维度重要性分布，并训练轻量预测器在推理时生成查询专属掩码。该方法在保持文档索引不变的前提下，以约20-40%的维度实现了超越全维基线的检索精度，但其泛化边界与跨域鲁棒性尚待验证。

## 研究背景

双编码器架构将查询与文档映射至共享向量空间，通过内积或余弦相似度计算相关性。然而，随着大语言模型嵌入维度升至4096维，向量空间中的坐标并非均匀有效：对于特定信息需求，仅少数维度承载了区分相关文档与无关文档的关键信号，其余维度可能引入噪声或冗余。这一现象被称为查询级维度冗余，它导致全维计算不仅浪费算力，更可能因无关维度的干扰降低排序精度。

主流解决路线分为两类。一是基于伪相关反馈（PRF）的维度重要性估计（DIME），如DIME（Faggioli et al., 2024）和Eclipse（D’Erasmo et al., 2025），它们利用检索结果或LLM生成的伪文档推断维度权重，但依赖噪声伪标签且作为独立的启发式阶段运行，未利用已有的监督相关性标签。二是监督适配器（Search Adapter），如Yoon et al. (2024a)提出的方法，通过可学习线性投影重塑嵌入空间，但其学习的是全局共享变换，旨在优化全维性能，缺乏对查询特定维度重要性的建模能力。本文的切入点在于：能否利用监督标签直接蒸馏出查询感知的维度重要性分布，并训练一个仅作用于查询侧的预测器，在推理时动态选择高价值维度，从而在不修改文档索引的情况下提升检索精度。

## 核心方法

### 方法参照系

本文问题可置于“嵌入后处理”框架下，与Matryoshka Representation Learning (MRL) 和 Search Adapter 同属一类。MRL 通过嵌套训练实现静态前缀截断，Search Adapter 通过全局投影优化全维检索。本文的关键差异在于：不改变编码器权重，不学习全局变换，而是将维度选择建模为基于监督标签的查询级预测任务，目标是提升峰值精度而非单纯压缩存储。

### Oracle 维度重要性蒸馏

设计动机：DIME 等 PRF 方法依赖噪声伪标签，无法利用训练集中已有的高质量相关性标注。本文首先从监督标签构建“Oracle”维度重要性分布，作为预测器的训练目标。对于查询 $q$，收集相关文档集合 $D_+(q)$ 和硬负例集合 $D_-(q)$。计算加权正例嵌入质心 $\bar{p}$ 和负例嵌入均值 $\bar{n}$。维度 $j$ 的原始判别分数定义为正负对齐差异：

$$ r_{q,j} = e_{q,j} (\bar{p}_j - \bar{n}_j) $$

该公式量化了维度 $j$ 在支持相关匹配与排斥负例方面的贡献强度。随后，通过温度缩放 Softmax 将 $r_{q,j}$ 归一化为概率分布 $\pi_q$，作为该查询的 Oracle 重要性目标。

### 查询感知预测器训练

设计动机：Oracle 分布依赖文档嵌入，推理时不可用。本文训练一个轻量全连接层 $f_\theta: \mathbb{R}^D \to \mathbb{R}^D$，仅以冻结的查询嵌入 $e_q$ 为输入，预测维度重要性分布 $\hat{\pi}_q$。训练目标为最小化预测分布与 Oracle 分布的 KL 散度：

$$ \mathcal{L} = \text{KL}(\pi_q \| \hat{\pi}_q) $$

该损失函数迫使预测器从查询语义中内化“哪些维度对当前查询最重要”的知识。推理时，根据 $\hat{\pi}_q$ 选择 Top-$k$ 维度，将查询向量其余维度置零，得到掩码查询嵌入 $\tilde{e}_q$。随后，使用 $\tilde{e}_q$ 与原始文档嵌入计算相似度。此过程仅修改查询侧，文档嵌入与 ANN 索引完全不变，实现了零重索引成本的精度提升。

## 实验评估

实验在 SciFact、NFCorpus 和 MS MARCO 三个 BEIR 域内数据集上进行，评估了 Qwen-Embedding（0.6B/4B/8B）、OpenAI text-embedding-3-large、LLM2Vec（Mistral/Llama3）及 GritLM 共七种编码器。基线覆盖全维（Full）、静态前缀（Cutoff）、范数选择（Norm）、PRF 方法（DIME/Eclipse）及监督适配器（Adapter）。

| 数据集 | 模型 | Baseline (100%) | Adapter (100%) | Ours (Peak) | Ours@30% |
| :--- | :--- | :--- | :--- | :--- | :--- |
| SciFact | Qwen-8B | 0.783 | 0.883 | 0.883 (32%) | 0.881 |
| SciFact | GritLM | 0.786 | 0.883 | 0.906 (40%) | 0.902 |
| MS MARCO | Qwen-8B | 0.646 | 0.698 | 0.714 (20%) | 0.709 |
| MS MARCO | OpenAI | 0.681 | 0.680 | 0.700 (34%) | 0.696 |
| NFCorpus | Qwen-8B | 0.432 | 0.419 | 0.455 (38%) | 0.449 |
| NFCorpus | GritLM | 0.429 | 0.434 | 0.462 (58%) | 0.461 |

核心发现是，本文方法在保留 20-40% 维度时，NDCG@10 普遍超越全维基线及全维适配器。例如，在 MS MARCO 上，Qwen-8B 模型使用 20% 维度达到 0.714，高于适配器的 0.698；在 SciFact 上，GritLM 使用 40% 维度达到 0.906，显著高于适配器的 0.883。消融实验表明，引入正例加权与硬负例挖掘可进一步提升 Oracle 上限，且最佳性能通常出现在 20-40% 维度区间，暗示大量维度对检索是有害的。

评估边界方面，实验仅覆盖域内任务，未测试零样本或跨域泛化能力。预测器为单层全连接网络，超参数（温度 $\tau$、负例采样 $K, M$）需针对每个模型-数据集对单独调优，缺乏统一的默认配置。论文未提供代码，且未报告计算延迟，无法评估推理时预测器带来的额外开销。

## 关联研究分析

从问题动机看，本文与 DIME（Faggioli et al., 2024）直接对立。DIME 解决的是“无标签场景下的维度选择”，依赖 PRF 噪声信号；本文解决的是“有标签场景下的精度提升”，利用监督标签蒸馏。这一差异源于任务目标的不同：DIME 旨在无监督部署，而本文旨在利用已有标注数据最大化峰值精度。然而，本文未探讨当标注数据稀缺或分布偏移时，蒸馏出的 Oracle 分布是否仍具鲁棒性，这是其相对于 DIME 的潜在盲区。

从方法设计看，本文与 Search Adapter（Yoon et al., 2024a）形成互补而非替代。Adapter 学习全局线性变换 $A$，优化全维检索性能；本文学习查询级掩码，优化子维检索性能。实验显示，在 MS MARCO 上，Adapter+Ours 组合（0.715）优于单独使用 Adapter（0.698）或 Ours（0.714），表明两者捕获的信息维度不同。但本文未分析为何 Adapter 在 NFCorpus 上表现不佳（0.419 vs Baseline 0.432），而本文方法有效（0.455），这可能暗示全局变换在某些领域结构下失效，而查询级选择更具适应性。

## 总结

本文针对稠密检索中查询级维度冗余导致精度受损的问题，提出从监督标签蒸馏 Oracle 维度重要性分布，并训练查询感知预测器生成动态掩码。该方法在保持文档索引不变的前提下，以 20-40% 的维度实现了超越全维基线及全局适配器的检索精度，如 MS MARCO 上 Qwen-8B 的 0.714 和 SciFact 上 GritLM 的 0.906。其边界在于仅验证了域内任务，预测器需逐数据集调优，且未评估推理延迟。当支持集增大或领域分布发生偏移时，基于监督标签蒸馏的维度重要性预测是否仍能保持泛化能力，论文未给出回答。
