# ACL2026最新论文 ｜Generating then Refining for Reliable Knowledge Base Question Answering ｜生成-验证-精炼框架下的可靠逻辑形式生成

研究机构：上海交通大学、香港科技大学

作者：Jianqi Gao、Hang Yu、Jian Cao 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_78192506c6da)

> 知识库问答（KBQA）旨在利用结构化知识回答自然语言问题，其核心价值在于缓解大语言模型（LLM）语义泛化能力与知识图谱（KG）事实精确性之间的张力。现有语义解析（SP）方法依赖 LLM 直接生成逻辑形式（LF），但 LLM 固有的语义幻觉导致生成的 LF 在 KG 中不可执行，严重制约了推理准确性。本文提出 ARI-KBQA 框架，通过“生成-验证-精炼”闭环机制，将逐跳生成与动态 KG 交互相结合，以过滤无效路径并修正关系错误。该框架在标准基准上取得了 SOTA 性能，但其对验证器计算开销的控制及跨领域泛化能力仍存疑。

## 研究背景

当 LLM 尝试将自然语言问题转化为可执行的 SPARQL 查询时，其生成的逻辑形式（Logical Form, LF）常因语义幻觉而包含 KG 中不存在的关系或实体。这种不可执行性并非简单的语法错误，而是源于 LLM 参数化知识与 KG 事实知识之间的结构性不一致。为缓解此问题，早期方法采用“检索-生成”策略，先检索相关子图再辅助生成，但检索过程往往引入大量噪声路径，干扰 LLM 的推理精度。因此，研究重心转向“生成-检索”范式，即直接生成 LF 后执行查询，如 ChatKBQA 和 TFS-KBQA。然而，这些方法缺乏对生成过程的实时约束，一旦首跳关系错误，后续推理将陷入局部最优或完全失效。

KBQA 的核心挑战在于如何在保证 LF 可执行性的同时，维持 LLM 的语义理解能力。SP 范式强调精确性，但受制于生成错误导致的不可执行风险；IR 范式侧重证据召回，但缺乏逻辑约束。本文的切入点在于识别出“不可执行 LF”是 SP 方法性能瓶颈的关键因素。实验表明，在 CWQ 数据集上，不可执行 LF 导致 F1 下降 11.83%，Hit@1 下降 13.28%。ARI-KBQA 通过引入反思验证器（Reflection Verifier），在生成过程中实时交互 KG，将“一次性生成”转变为“逐跳生成-验证-精炼”的迭代过程，从而在源头上抑制幻觉传播。

## 核心方法

### 方法参照系

ARI-KBQA 属于 SP-based 路线，其标准流程是将问题映射为 LF 并执行。与 ChatKBQA 等直接生成完整 LF 的方法不同，ARI-KBQA 将 LF 生成拆解为逐跳（hop-by-hop）过程，并引入外部验证模块。关键差异在于，传统方法依赖 LLM 内部一致性保证 LF 正确性，而 ARI-KBQA 依赖 KG 结构约束进行动态修正，形成闭环优化。

### 逐跳生成与条件依赖

动作生成器（Action Generator）采用逐跳生成策略，第 $j$ 跳 LF 的生成显式依赖于前 $j-1$ 跳的 LF。这一设计降低了单次生成的复杂度，避免了 LLM 在长序列生成中累积错误。其优化目标为最大化条件概率：

$$
P_\theta(L_p|q, G) = \prod_{i=1}^{|E_q|} P_\theta(l_i^j|q, e_i^q, l_i^{j-1}, G)
$$

其中 $l_i^j$ 为第 $i$ 个主题实体在第 $j$ 跳的 LF，$l_i^{j-1}$ 为前跳 LF。该公式表明，当前跳的生成不仅取决于问题和 KG，还受前跳路径的约束，从而确保路径的连贯性。

### 动态验证与关系修正

反思验证器在第 $j$ 跳生成后，根据 LF 结构确定搜索方向（前向或后向），并从 KG 中检索 Top-K 候选关系。验证器通过计算生成关系与候选关系的加权相似度，筛选出最可能的正确关系：

$$
\Phi(r_c) = \arg\text{top}_k \sum_{i=1}^n p_i \cdot \text{sim}(r_i, r_c)
$$

若当前 LF 不可执行，验证器将替换错误关系并重新生成下一跳。这一机制解决了直接生成方法中“错误传播”的问题，通过实时反馈确保每一步 LF 在 KG 中可执行，从而提升最终答案的准确性。

## 实验评估

ARI-KBQA 在 WebQSP、CWQ、FreebaseQA 和 LC-QuAD 四个基准上进行了评估，基线涵盖 Non-LLM、Prompting-LLM 和 Fine-tuning-LLM 三类方法。实验显示，ARI-KBQA 在 Llama-2-7B 骨干下，WebQSP Hits@1 达到 90.1，CWQ Hits@1 达到 88.28，显著优于 ChatKBQA（86.4/86.0）和 PoG（87.3/75.0）。在 LC-QuAD 上，ARI-KBQA 的 Hits@1 为 83.6，远超 ChatKBQA 的 68.1，验证了其在不同 KG 上的泛化能力。

| 方法 | 骨干 | WebQSP Hits@1 | CWQ Hits@1 | FreebaseQA Hits@1 |
| :--- | :--- | :--- | :--- | :--- |
| ChatKBQA | Llama-2-7B/13B | 86.4 | 86.0 | 85.77 |
| PoG | GPT-4.0 | 87.3 | 75.0 | - |
| ARI-KBQA | Llama-2-7B | 90.1 | 88.28 | 89.24 |
| ARI-KBQA | Llama-3-8B | 91.65 | 89.63 | 89.77 |

消融实验表明，仅使用动作生成器（ARI-KBQA only AC）的 WebQSP F1 为 81.78，而完整框架（ARI-KBQA）达到 83.4，提升 1.62 个点。直接生成（ARI-KBQA DR）的 F1 仅为 74.93，说明验证机制对性能提升至关重要。效率方面，ARI-KBQA 在 CWQ 上平均耗时 11.4 秒，低于 ToG 的 96.5 秒，但高于 ChatKBQA 的 11.7 秒，表明验证机制引入了额外计算开销，但通过减少无效 LLM 调用（>90% 步骤验证器空闲）实现了效率平衡。

评估边界方面，论文未报告置信区间，且基线中缺少 2025-2026 年最新的 Agentic 方法（如 CLAUSE、EvoMemKG）。代码已开源，但超参数细节（如 Top-K 值）未在正文中详细列出，可能影响复现性。

## 关联研究分析

从问题动机看，ARI-KBQA 与 GRV-KBQA 均关注 LF 的可执行性，但 GRV-KBQA 采用“结构生成-语义接地-验证”三阶段，而 ARI-KBQA 强调逐跳依赖与动态修正。GRV-KBQA 的验证是后验的，而 ARI-KBQA 的验证是过程性的，后者能更早地纠正错误，避免错误在后续跳中放大。这一差异源于任务特性：多跳推理中，早期错误的影响呈指数级增长，因此过程性验证比后验验证更有效。

从方法设计看，ARI-KBQA 与 ToG 代表不同路线：ToG 是 IR/Agentic 路线，通过迭代探索路径，但易引入噪声；ARI-KBQA 是 SP 路线，通过生成 LF 并验证，避免噪声但依赖 LLM 生成质量。ARI-KBQA 的效率优于 ToG，但泛化能力可能受限于 LLM 的语义理解。查询侧增强在数据充足时是否仍有增益，论文未给出回答，这可能限制了其在低资源场景下的应用。

## 总结

ARI-KBQA 旨在解决 LLM 生成 LF 不可执行导致的 KBQA 性能瓶颈。其切入点在于识别出“不可执行 LF”是 SP 方法的关键失效点，并通过逐跳生成与动态验证的闭环机制，在生成过程中实时修正错误。实验证明，该框架在 WebQSP 和 CWQ 上分别取得 90.1 和 88.28 的 Hits@1，显著优于基线。然而，其边界在于验证机制引入了额外计算开销，且对 LLM 骨干的依赖较强，跨领域泛化能力未充分验证。当支持集增大到 5-shot 时，验证器的边际收益是否递减，论文未给出回答。
