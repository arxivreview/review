# ACL2026最新论文 ｜OptiCo: Adaptive Distributed Training Optimization via Collaborative Agent Reasoning ｜多智能体协同推理驱动的分布式训练配置优化

研究机构：北京航空航天大学、新加坡南洋理工大学

作者：Sheng Chen、Tang Zhe、Weixing Zhang 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_44536516bd74)

> 分布式训练配置调优长期依赖专家经验或静态搜索算法，难以适应动态硬件与模型组合。现有自动并行框架受限于离线 Profiling 开销与泛化性差，无法在运行时实时响应性能瓶颈。本文提出 OptiCo，通过四个 LLM 智能体基于共享记忆池进行迭代推理，自动调整张量、流水线等并行参数。该方法在 25 种配置下平均提升模型 FLOPs 利用率（MFU）1.84%，但缺乏对超大规模集群通信瓶颈的验证，其推理随机性对全局收敛性的影响存疑。

## 研究背景

当模型参数规模突破单卡显存上限时，必须采用混合并行策略将计算切分至多设备。张量并行（TP）与流水线并行（PP）的组合配置空间呈指数级增长，且最优配置随硬件拓扑、序列长度动态变化。模型 FLOPs 利用率（MFU）作为衡量计算资源有效性的核心指标，其最大化要求并行策略与硬件特性精确匹配，而人工调优耗时且难以复现。

自动并行配置搜索旨在替代人工试错，但主流方法存在结构性缺陷。基于混合整数线性规划（MILP）的方法如 OptPipe 依赖精确的性能模型，求解时间随变量维度急剧增加；基于静态 Profiling 的框架如 Alpa 和 AMP 需预先采集大量硬件特征，导致离线开销巨大，且配置难以跨模型或硬件迁移。这些方法将配置优化视为一次性求解问题，缺乏对运行时失败反馈的闭环利用能力。

本文切入点在于将配置优化重构为多智能体协作推理过程。不同于传统搜索算法的“黑盒”探索，OptiCo 模拟专家调优的认知流程，通过瓶颈分析、策略生成、验证与故障诊断四个角色的迭代交互，将历史执行数据转化为可复用的决策知识，从而在无需离线 Profiling 的前提下实现动态自适应。

## 核心方法

### 方法参照系

自动并行配置搜索的标准流程通常包含性能建模、搜索空间定义与优化求解三个环节。本文问题与该通用流程的关键差异在于：放弃显式性能模型与全局搜索算法，转而采用基于大语言模型（LLM）的局部启发式推理，将配置调整转化为序列化的决策过程。

### 多智能体协同架构

OptiCo 的核心创新在于引入全局消息池（Global Message Pool, $M_{pool}$）作为共享记忆机制，协调四个智能体的迭代行为。在迭代 $t$，瓶颈分析智能体 $A_a$ 基于 $M_{pool}$ 中的历史性能数据生成参数影响排序 $\Delta_t$，策略生成智能体 $A_g$ 据此生成候选配置 $C_t$：

$$ C_t = A_g(M_{pool}, \Delta_t, \text{rules}) $$

该公式表明配置生成并非随机搜索，而是受历史数据与规则约束的方向性修改。策略验证智能体 $A_v$ 执行 $C_t$ 并记录结果，若失败则触发故障分析智能体 $A_f$ 提取错误日志 $E_t$ 并更新 $M_{pool}$。这一设计解决了传统方法中失败配置被丢弃、无法转化为负面知识的问题，使搜索空间随迭代逐步收缩。

### 链式思维推理机制

为提升决策稳定性，OptiCo 在瓶颈分析阶段引入链式思维（Chain-of-Thought, CoT）推理。$A_a$ 不仅输出参数排序，还生成推理轨迹，解释每个参数对 MFU 的影响机制。消融实验显示，移除 CoT 后平均性能降至 79.06%（相对于完整系统的 101.84%），且无一配置超越专家基线。CoT 通过显式化因果逻辑，抑制了 LLM 推理的随机性，使智能体能够区分高置信度故障与模糊信号，从而避免重复探索无效配置。

## 实验评估

实验在 8 或 16 块 NVIDIA A100（80GB）或 XPU（96GB）上运行，涵盖 Llama、Qwen、GPT 系列共 8 种模型。基线包括专家调优配置及 Alpa、AMP、Aceso 三个自动并行框架。Alpa 和 AMP 在 16 GPU 下因内存溢出（OOM）失败，Aceso 吞吐量受限，而 OptiCo 在所有设置下均稳定运行。

| 模型 | 硬件 | 专家调优 MFU | OptiCo MFU | 专家调优 TGS | OptiCo TGS |
| :--- | :--- | :--- | :--- | :--- | :--- |
| GPT3-7B | 16-GPU | 56.1% | 57.2% | 4164.3 | 4246.0 |
| Llama3-8B | 8-GPU | 67.9% | 68.2% | 4416.7 | 4436.2 |
| Qwen3-MoE-A0.6B | 16-GPU | 12.6% | 13.7% | 10916.7 | 11869.7 |

OptiCo 在 GPT3-7B 16-GPU 设置下 TGS 提升 1.96%，在 Qwen3-MoE-A0.6B 16-GPU 设置下提升 8.73%，平均 MFU 提升 1.84%。

| 消融变体 | 平均性能（相对专家） | 超越专家比例 |
| :--- | :--- | :--- |
| 完整 OptiCo | 101.84% | 100% |
| 无全局消息池 | 86.15% | 0% |
| 无故障分析智能体 | 79.22% | 0% |
| 无 CoT 推理 | 79.06% | 0% |

移除全局消息池导致性能骤降 15.69 个百分点，且无一配置超越专家基线，表明共享记忆是避免重复失败的关键。无 CoT 推理与无故障分析智能体的性能降幅相近（均约 22.8%），说明结构化推理与故障知识复用对优化稳定性具有同等重要性。

评估边界受限于最大 16 GPU 规模，未验证跨节点通信瓶颈下的表现。指标仅包含 MFU 与 TGS，缺乏端到端训练时间收敛性分析。代码已开源，但 LLM API 调用成本（约 $0.26/次）在超大规模集群中的累积开销未量化。

## 关联研究分析

从方法设计看，OptiCo 与 OptPipe 代表两条截然不同的优化路径。OptPipe 通过 MILP 求解全局最优配置，依赖精确的性能模型，但在模型或硬件变化时需重新建模；OptiCo 通过 LLM 推理进行局部启发式搜索，无需显式模型，但牺牲了全局最优性保证。这一差异源于任务特性：OptiCo 针对的是配置空间高维且动态变化的场景，全局求解的计算开销不可接受，而 LLM 的语义理解能力使其能直接解析错误日志并推断参数影响，这是传统搜索算法无法实现的。

从问题动机看，OptiCo 与 AsyncHZP 解决不同层面的问题。AsyncHZP 通过异步调度隐藏通信延迟，提升硬件利用率；OptiCo 通过调整并行参数优化计算-通信平衡，提升 MFU。二者互补：OptiCo 可确定最优 TP/PP 组合，AsyncHZP 可在该组合下优化执行时序。OptiCo 未涉及通信重叠的具体实现，仅将 overlap 作为可调参数，这暗示其在高带宽受限场景下的潜力未充分挖掘。

## 总结

OptiCo 旨在解决分布式训练配置调优中静态搜索算法泛化性差与人工调优效率低的核心矛盾。其切入点在于利用 LLM 的语义推理能力将配置优化转化为多智能体协作过程，通过全局消息池积累执行经验，实现无需离线 Profiling 的动态自适应。实验证明该方法在 16 GPU 规模下平均提升 MFU 1.84%，最高达 8.65%，且优于 Alpa、AMP 等基线。然而，其实验规模局限于单节点或双节点，未验证跨节点通信瓶颈下的有效性，且 LLM 推理的随机性可能影响收敛稳定性。当集群规模扩展至千卡以上时，LLM 推理延迟与通信开销的比值是否仍具优势，论文未给出回答。
