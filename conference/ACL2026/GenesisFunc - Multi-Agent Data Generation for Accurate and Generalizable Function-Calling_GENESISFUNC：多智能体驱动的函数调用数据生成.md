# ACL2026最新论文 ｜GenesisFunc: Multi-Agent Data Generation for Accurate and Generalizable Function-Calling ｜GENESISFUNC：多智能体驱动的函数调用数据生成

作者：Hao-Xiang Xu、Chong Deng、Jiaqing Liu 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.28835)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_a229059b1b8c)

> 函数调用（Function-Calling, FC）训练数据面临真实标注成本高与合成数据质量低的双重困境，现有自动化流水线常因API不可靠、场景单一及缺乏严格校验导致模型泛化能力受限。GENESISFUNC 通过构建基于可靠基准工具池的多智能体对话生成框架，结合规则与模型双重校验机制，解决了合成数据在多样性与准确性上的平衡难题。该方法在 BFCL 基准上实现了 93.31 的准确率，显著优于同规模开源模型，但人工验证环节的引入限制了其完全自动化的扩展潜力。

## 研究背景

函数调用任务要求大语言模型（LLM）根据用户查询 $q$ 和候选工具集 $T$，生成包含正确参数填充的工具调用序列 $S$。这一过程不仅涉及语义理解，还需处理参数槽位的精确匹配与多轮交互中的状态保持，其核心挑战在于训练数据需同时具备高准确性、高多样性及广泛的场景覆盖，而真实世界数据往往存在标注噪声且难以覆盖长尾场景。

当前主流合成数据生成方法主要依赖单模型自举或简单提示工程，如 ToolACE 通过自动化流水线构建大规模语料，但这类方法常受限于API的可靠性与工具集的可扩展性，且生成的对话多集中于单轮孤立调用，缺乏对多轮交互及错误检测场景的覆盖。此外，缺乏严格的质量控制机制导致合成数据中隐含的格式错误或逻辑不一致难以被有效过滤，进而削弱下游模型的执行能力。GENESISFUNC 的切入点在于将数据生成过程重构为多智能体协作系统，通过引入记忆机制与分层评估模块，在确保工具可靠性的前提下，系统性地提升合成对话的场景丰富度与执行正确性。

## 核心方法

### 方法参照系

本文问题可归类于合成数据生成中的“生成优化”路线，其标准流程通常包括种子数据选择、模型生成及基础过滤。与通用流程的关键差异在于，GENESISFUNC 将生成过程解耦为多智能体协作对话，并引入显式的多阶段评估闭环，而非依赖单一模型的端到端输出。

### 多智能体对话生成机制

针对单模型生成易陷入高频模式重复且缺乏上下文多样性的问题，GENESISFUNC 设计了由 Sample、Memory、Function 和 Judge 四个智能体组成的协作框架。Sample Agent 从工具池中选取目标工具与干扰项，Function Agent 通过随机槽位选择策略 $P' \subseteq P$ 实例化可选参数，以增强调用的真实性。Memory Agent 记录历史对话实例 $D = \{d_1, \dots, d_k\}$ 及其语义标签 $\tau(d_i)$，并引导生成器产生未见过的 $\tau$ 类型，从而在语义层面扩展多样性。该机制的核心公式为：

$$
\tau_{new} = \arg\min_{\tau \in C \setminus \{\tau(d_i)\}} \text{Sim}(\tau, \tau(d_i))
$$

此公式确保新生成的对话在语义上下文中与历史样本保持最大距离，有效缓解了模式坍塌。

### 多阶段评估与质量过滤

为解决生成数据中存在的格式错误与语义偏差，GENESISFUNC 引入了规则检查器（Rule Checker）与模型检查器（Model Checker）的双重过滤机制。Rule Checker 执行静态合规性检查，验证工具定义完整性与调用格式；Model Checker 则利用 GPT-4o 进行语义质量评估，仅保留置信度分数高于阈值 $\theta = 0.75$ 的样本。最终，剩余约 5% 的高风险样本进入人工验证环节。该过程可形式化为：

$$
S_{final} = \{s \in S_{gen} \mid \text{Rule}(s) = \text{Pass} \land \text{Conf}(\text{Model}(s)) > \theta \land \text{Human}(s) = \text{Approved}\}
$$

这一分层过滤策略确保了训练数据在执行层面的正确性，避免了低质量样本对模型微调的负面影响。

## 实验评估

实验在 BFCL、API-Bank 和 ACEBench 三个基准上进行，对比基线包括 GPT-4o、Qwen3-8B 及 ToolACE-8B 等。GENESISFUNC-8B 在 BFCL Non-Live 子集上取得 93.31 的准确率，显著优于 ToolACE-8B 的 91.04 和 Qwen3-8B 的 88.60，且在 Live 子集上达到 83.78，相对 ToolACE-8B 提升 3.8%。在域外基准 API-Bank 上，其整体准确率为 64.79，优于 GPT-4o 的 51.45，表明合成数据具备良好的泛化能力。

| 模型 | BFCL Non-Live | BFCL Live | API-Bank Overall | ACEBench Overall |
| :--- | :--- | :--- | :--- | :--- |
| GPT-4o | 83.88 | 70.54 | 51.45 | 87.60 |
| ToolACE-8B | 91.04 | 80.73 | 56.21 | 1.00 |
| Qwen3-8B | 88.60 | 77.79 | 55.56 | 76.67 |
| GENESISFUNC-8B | 93.31 ± 0.42 | 83.78 ± 0.37 | 64.79 ± 0.41 | 83.67 ± 0.35 |

消融实验显示，移除 Memory Agent 导致性能显著下降，验证了多样性机制的重要性；移除 Judge Agent 则造成准确率明显跌落，证实了质量控制的必要性。在样本数量影响分析中，每工具生成 5 条对话时性能达到峰值，增至 10 条后收益递减，表明场景多样性饱和后额外数据边际效用降低。

评估协议基于三次独立运行的均值与标准差，确保了结果的统计稳健性。代码已开源，但人工验证环节需约 15 小时，限制了大规模扩展的自动化程度。指标聚焦于准确率，未深入分析推理延迟或计算成本，且域外基准 ACEBench 中 ToolACE-8B 的 1.00 分异常低，可能反映其在该特定场景下的失效，而非普遍性能水平。

## 关联研究分析

从方法设计看，GENESISFUNC 与 ToolACE 的核心差异在于生成架构。ToolACE 依赖单模型自举，易受限于模型自身的分布偏差；而 GENESISFUNC 采用多智能体协作，通过 Memory Agent 的语义去重机制显式控制多样性。这种设计源于函数调用任务对参数槽位精确匹配的高要求，单模型难以在保持格式正确的同时覆盖长尾场景。相比之下，EvoSyn 采用进化算法优化数据过滤策略，而 GENESISFUNC 通过多阶段评估实现静态过滤，前者更适用于可验证奖励场景，后者则侧重于对话结构的完整性。

从问题动机看，GENESISFUNC 与 CircuitSynth 均关注数据可靠性，但侧重点不同。CircuitSynth 引入概率软约束处理逻辑一致性，适用于高风险领域；GENESISFUNC 则通过规则与模型双重检查确保执行正确性，更适用于通用工具调用场景。这种差异反映了任务特性的决定作用：函数调用强调可执行性，而逻辑推理强调语义一致性。GENESISFUNC 未探索动态约束机制，其在处理复杂多任务交互时的鲁棒性仍有待验证。

## 总结

GENESISFUNC 旨在解决函数调用训练数据中准确性与多样性的矛盾，通过多智能体协作生成与多阶段评估过滤，实现了合成数据质量的系统性提升。该方法在 BFCL 基准上取得 93.31 的准确率，较 ToolACE-8B 提升 2.5%，证明了多智能体框架在增强场景覆盖与执行正确性上的有效性。然而，其依赖人工验证环节，且样本数量超过 5 条后收益递减，表明当前方法在完全自动化与数据规模扩展上存在瓶颈。当工具集规模进一步扩大时，Memory Agent 的语义去重机制是否仍能保持高效的多样性控制，论文未给出回答。
