# ACL2026最新论文 ｜GROKE: Vision-Free Navigation Instruction Evaluation via Graph Reasoning on OpenStreetMap ｜无视觉导航指令评估：基于开放街图推理的 GROKE 框架

作者：Farzad Shami、Subhrasankha Dey、Nico Van de Weghe 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.07375)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_b7b586424306)

> 导航指令的质量评估长期依赖参考文本的词汇重叠或视觉模拟器的执行成功率，前者无法捕捉空间逻辑的矛盾，后者则受限于高保真图像数据的获取成本与感知噪声干扰。GROKE 框架通过剥离视觉模态，直接利用 OpenStreetMap (OSM) 的拓扑结构作为环境表征，将指令评估转化为纯图推理任务。该框架采用层级化智能体架构，先分解指令为原子子目标，再在结构化 JSON 表示的局部地图上进行航点预测。这一去视觉化路径验证了符号化地图在 LLM 空间推理中的有效性，但其评估结果是否完全等价于真实物理环境中的可导航性，仍存疑。

## 研究背景

导航指令的功能性由其在物理空间中引导智能体到达目标的合规条件决定，而非其语法结构或词汇相似度。传统评估指标如 BLEU 和 ROUGE 基于 n-gram 重叠计算，假设存在唯一正确的描述方式，这在空间导航中失效：两条指令可能共享高词汇重叠却指向相反方向，或零重叠却描述同一有效动作。这种内在文本评估无法区分指令的语义清晰度与执行可行性，导致无法有效筛选训练数据或优化生成模型。

现有外在评估范式通常训练跟随智能体在 Matterport3D 或 Google Street View (GSV) 等视觉模拟器中执行指令，以成功率作为指令质量的代理指标。然而，该范式存在两个核心瓶颈：一是视觉感知错误与语言理解错误混淆，智能体因无法识别模糊图像中的地标而失败，却被归因于指令质量；二是 GSV 等专有数据集的 API 成本、许可限制及海量全景图像下载需求，构成了可复现性与可扩展性的壁垒。Map2Seq 数据集提供了对齐的 OSM 节点、边和兴趣点 (POI) 数据，使得将环境抽象为语义拓扑结构成为可能，从而解耦视觉与语言模态，为构建基于结构逻辑的指令评估提供了基础。

## 核心方法

### 方法参照系

GROKE 属于零样本导航框架的变体，其核心差异在于输入模态从 RGB-D 图像替换为 OSM 图数据，且目标从导航执行转向指令评估。标准 VLN 流程依赖视觉编码器提取特征，而 GROKE 直接序列化地图拓扑，利用 LLM 的先验知识进行符号推理，消除了对高保真视觉输入的依赖。

### 子指令分解与地标接地

传统端到端模型在处理长指令时易出现状态漂移，GROKE 引入子指令智能体将自然语言指令 $I$ 分解为原子子目标序列 $\{g_1, g_2, \dots, g_K\}$。每个子目标 $g_k$ 对应 MOVE_FORWARD、TURN_LEFT 或 TURN_RIGHT 三种基本操作之一，并关联状态指示器。该设计将长时程规划问题降维为短视距的子目标执行，解决了 LLM 在长序列依赖中注意力分散的问题。地标接地模块提取指令中的地标 $L = \{l_1, \dots, l_M\}$，并通过 Haversine 距离公式计算地标 POI 与路径节点的相对方向：

$$ \delta = (h_{v \to p} - h_{curr} + 180) \mod 360 - 180 $$

其中 $h_{v \to p}$ 为节点到 POI 的方位角，$h_{curr}$ 为当前航向。该公式将连续角度差映射为 Forward、Left、Right、Back 四类离散方向，为后续导航提供语义锚点。

### 可见区域构建与航点预测

导航智能体在每一步构建局部可见区域 $G_t$，通过遍历当前航向下的街道网络，直至达到指定的交叉口数量 $u$。算法仅保留度大于 2 的分支节点作为决策点，并计算相邻节点的方位角差 $\Delta h$：

$$ \Delta h(h_1, h_2) = \min(|h_1 - h_2|, 360 - |h_1 - h_2|) $$

当 $\Delta h < 100^\circ$ 时，该节点被纳入可见路径集 $V_{path}$。这种基于角度阈值的过滤机制模拟了人类导航的视野限制，排除了后方及侧向无关节点，降低了 LLM 的上下文长度。导航智能体接收当前子目标 $g_k$、位置 $v_t$、航向 $h_t$ 及结构化 JSON 格式的 $G_t$，输出下一航点 $v_{t+1}$ 及子目标状态。该过程迭代执行直至所有子目标完成或达到最大步数，实现了从语义解析到拓扑遍历的闭环。

## 实验评估

实验在 Map2Seq 数据集的 TestSetA 和 TestSetB 上进行，各包含 700 个导航回合。基线包括 Random Walker、Action Sampling 和 Heuristic Agent，缺失 MapGPT 或 DUET 等主流 VLN 模型的对比，限制了横向可比性。GROKE 使用 Gemini-3 Pro 模型，无需训练，平均步数为 5.91（TestSetA）和 6.15（TestSetB），平均总 Token 消耗分别为 44,438 和 46,305。

| 方法 | TestSetA NE | TestSetA SR | TestSetB NE | TestSetB SR |
| :--- | :--- | :--- | :--- | :--- |
| Random Walker | 259.0 | 4.4% | 244.3 | 6.1% |
| Action Sampling | 250.1 | 5.1% | 241.6 | 7.4% |
| Heuristic Agent | 180.6 | 18.0% | 173.0 | 17.9% |
| GROKE | 56.8 | 66.4% | 59.8 | 63.3% |

GROKE 在 TestSetA 上的成功率 (SR) 为 66.4%，导航误差 (NE) 为 56.8 米，显著优于 Heuristic Agent 的 18.0% SR 和 180.6 米 NE。消融实验表明，结构化 JSON 格式在空间推理中表现最优，其 NE 为 41.3 米，SR 为 74.0%，优于网格矩阵和 GraphViz 可视化格式。相关性分析显示，导航误差与人类标注的可导航性呈显著负相关（Pearson r = -0.3096, p < 0.01），验证了代理指标的有效性。

评估边界受限于 OSM 数据的静态性与稀疏性，无法反映动态障碍物或实时交通变化。代码已开源，但实验未报告置信区间，且仅使用单一 LLM 骨干，未探讨模型规模对评估鲁棒性的影响。

## 关联研究分析

从问题动机看，GROKE 与 MapGPT 均利用地图拓扑辅助 LLM 推理，但 MapGPT 依赖在线构建的语言拓扑地图，其输入仍源于视觉观测，而 GROKE 直接消费 OSM 矢量数据。这一差异源于任务目标的不同：MapGPT 旨在提升导航性能，需保留视觉细节以应对复杂室内场景；GROKE 旨在评估指令质量，需剥离感知噪声以隔离语言逻辑。然而，OSM 数据的语义粒度远低于视觉图像，GROKE 在评估依赖细微视觉地标（如“红色建筑”）的指令时，可能因 POI 缺失而产生系统性偏差，论文未对此类场景的评估准确性进行量化分析。

从方法设计看，GROKE 的层级架构与 VELMA 相似，均分离高层规划与低层执行，但 VELMA 面向室内视觉导航，使用 Transformer 编码历史观测，而 GROKE 采用无状态图遍历。GROKE 的可见区域构建基于固定角度阈值（100°）和交叉口计数，这是一种启发式规则，缺乏自适应机制。相比之下，VELMA 通过注意力机制动态聚焦相关区域。GROKE 的简化设计降低了计算开销，但可能在复杂路口或长直道上导致上下文信息不足，影响航点预测的精度。

## 总结

GROKE 解决了导航指令评估中视觉依赖导致的噪声混淆与数据获取壁垒问题，通过 OSM 图推理实现了去视觉化的功能性评估。其层级架构将长指令分解为原子子目标，结合结构化 JSON 地图表示，在 Map2Seq 数据集上取得了 66.4% 的成功率和 56.8 米的导航误差，显著优于启发式基线。然而，该框架的评估有效性依赖于 OSM 数据的完整性与语义丰富度，对于依赖视觉细节或动态环境的指令，其评估结果可能偏离真实物理可导航性。当 OSM 数据中缺乏关键地标或拓扑结构不完整时，GROKE 的评估指标是否仍能准确反映指令质量，论文未提供相应的鲁棒性测试数据。
