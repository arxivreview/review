# ACL2026最新论文 ｜UI-Copilot: Advancing Long-Horizon GUI Automation via Tool-Integrated Policy Optimization ｜UI-Copilot：基于工具集成策略优化的长程GUI自动化

研究机构：浙江大学

作者：Zhengxi Lu、Fei Tang、Guangyi Liu 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.13822)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.13822)

> 长程GUI任务中，智能体因上下文过载导致记忆退化、进度混淆与数学幻觉，现有方法或依赖固定流水线或受限于检索质量，难以在保持轻量上下文的同时按需获取外部辅助。本文提出UI-Copilot框架，通过记忆解耦将详细推理与对话历史分离，并引入轻量Copilot模型按需执行检索或计算。该框架结合TIPO算法解耦工具调用与动作生成的训练过程，在MemGUI-Bench上确立了7B模型的性能领先，但在通用动态基准上表现仍落后于SOTA，其依赖外部工具的架构是否违背原生模型驱动趋势存疑。

## 研究背景

GUI智能体在短程任务中表现稳健，但长程场景下，多模态大语言模型（MLLM）面临上下文窗口限制。随着交互步数增加，历史推理轨迹与动作记录不断累积，导致关键信息被稀释或遗忘，即记忆退化；同时，冗长的上下文干扰任务状态判断，引发进度混淆；数值计算错误在后续步骤中复合传播，形成数学幻觉。这三种失效模式相互交织，使得智能体在超过10步的任务中性能急剧下降，现有7B模型在MemGUI-Bench上平均性能跌幅达90.9%。

主流解决方案分为多智能体工作流与检索增强两类。多智能体工作流（如Mobile-Agent-v2）通过预定义流水线调用外部模块，虽能分担计算压力，但无论任务是否需要均强制调用，导致推理成本高昂且灵活性不足。检索增强方法依赖检索质量，且无法解决进度混淆问题，因为检索仅补充信息而未优化上下文结构。本文的切入点在于识别出上述方法的共同根源：智能体承担了超出其内在能力的任务，在过载上下文中产生混乱。因此，GUI智能体应聚焦于轻量上下文下的任务执行，将记忆与计算解耦，仅在必要时调用外部工具。

## 核心方法

### 方法参照系

本文问题属于长程GUI决策中的上下文管理范畴。标准流程中，智能体在每步$t$基于指令$I$、当前截图$S_t$及历史$H_t$采样动作$a_t$。传统方法将完整推理轨迹纳入$H_t$，导致上下文膨胀。本文的关键差异在于将历史$H_t$重构为仅包含简洁进度摘要，并将详细推理内容外置存储，从而在保持决策连贯性的同时降低上下文负载。

### 记忆解耦与按需工具调用

设计动机在于解决多轮上下文（MC）中因内容过载导致的进度混淆。本文提出多轮摘要（MS）范式，将对话历史更新为$H_t = H_{t-1} \cup \{a_{t-1}, \text{summary}_{t-1}\}$，其中$\text{summary}_{t-1}$仅报告当前完成状态（如“已完成子任务A”）。详细推理内容$\text{thought}_{t-1}$（包含规划与显式观察）存储于本地文件$K$中：$K = K \cup \text{thought}_{t-1}$。这种解耦使智能体在轻量上下文中聚焦执行，同时保留详细信息供按需检索。当任务需要记忆检索或数值计算时，智能体调用Copilot模型（Qwen3-4B）作为Retriever或Calculator。Retriever接收历史知识$K$、指令$I$及进度摘要，返回文本结果；Calculator生成可执行Python代码，由解释器执行后返回结果。该机制避免了固定流水线的冗余调用，实现了自适应工具使用。

### 工具集成策略优化（TIPO）

设计动机在于解决传统强化学习（RL）中工具调用与动作生成训练动态不一致的问题。TIPO将训练过程解耦为两部分：工具调用学习采用单轮监督，基于离线历史$H_t^*$预测工具选择；动作生成学习采用多轮在线策略，基于自生成历史$H_t^\pi$进行动作预测。训练目标函数为：

$$
\mathcal{L}_{\text{TIPO}} = \mathbb{E}_{I \sim D_{\text{tool}}^{\text{RL}}} \left[ \sum_{t} r_{\text{tool}} \right] + \mathbb{E}_{I \sim D_{\text{action}}^{\text{RL}}} \left[ \sum_{t} \rho(\theta) A_{i,t} \right] - \beta \mathbb{E} \left[ D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}}) \right]
$$

其中，$r_{\text{tool}}$为基于规则的工具调用奖励，$A_{i,t}$为归一化优势，$\rho(\theta)$为重要性采样比，$\beta$控制KL散度惩罚强度。该公式表明，工具调用通过单轮规则奖励优化，而动作生成通过多轮在线策略优化，两者独立训练但共享策略模型。这种解耦确保了工具调用学习的稳定性与动作生成学习的部署一致性，避免了传统RL中因工具反馈延迟导致的训练不稳定。

## 实验评估

实验在MemGUI-Bench、AndroidWorld、MiniWob++等基准上进行，基线覆盖UI-TARS、UI-S1、GUI-Owl等开源SOTA模型及GPT-4o等闭源模型，但缺失MobileRL等最新在线RL基线。在MemGUI-Bench上，UI-Copilot-7B取得pass@1 16.4%、pass@3 20.3%的成绩，显著优于GUI-Owl-7B（10.2%）和UI-TARS-1.5-7B（10.2%），确立了7B模型在该基准上的领先。在AndroidWorld上，UI-Copilot-7B取得39.1%的成功率，虽低于MobileRL的80.2%和UI-S1的72.0%（据领域综述），但较基座模型Qwen2.5VL-7B提升17.1个百分点，验证了框架在通用动态任务中的泛化能力。

| 基准 | 模型 | Pass@1 (%) | Pass@3 (%) | 平均步数 |
| :--- | :--- | :--- | :--- | :--- |
| MemGUI-Bench | UI-Copilot-7B | 16.4 | 20.3 | 16.6 |
| MemGUI-Bench | GUI-Owl-7B | 10.2 | 10.2 | - |
| MemGUI-Bench | UI-TARS-1.5-7B | 10.2 | 10.2 | - |
| AndroidWorld | UI-Copilot-7B | 39.1 | - | - |

消融实验显示，多轮摘要（MS）范式相比多轮上下文（MC）在MemGUI-Bench上准确率提升5.6个百分点，平均步数减少1.3步，验证了记忆解耦对进度混淆的缓解作用。工具调用消融表明，Calculator与Retriever均对性能有正向贡献，完整工具集取得51.5%平均准确率，优于固定流水线方法。Copilot模型选择中，Qwen3-4B表现最佳，优于Qwen3-0.6B和Qwen2.5VL-7B，凸显其在上下文理解与摘要生成上的优势。TIPO消融证实，SFT冷启动对RL训练至关重要，且在线策略（on-policy）历史优于离线策略（off-policy）历史，因前者与多轮评估更一致。

评估边界方面，论文未报告置信区间，数值比较需谨慎。MemGUI-Bench上绝对成功率较低（最高20.3%），反映长程记忆任务的极高难度。AndroidWorld上39.1%的成绩远低于SOTA，可能源于工具调用引入的额外步骤导致超时或执行效率下降。代码未公开，TIPO的具体实现细节需自行复现，超参数如KL惩罚强度$\beta$和最小优势方差阈值$\eta=0.3$未提供完整敏感性分析。

## 关联研究分析

从问题动机看，UI-Copilot与PAL-UI均针对长程记忆问题，但PAL-UI侧重主动检索历史以增强历史感知，而UI-Copilot侧重记忆解耦与外部计算。PAL-UI通过双层级历史摘要与主动检索机制解决上下文丢失，但可能引入推理延迟；UI-Copilot通过将详细推理外置存储，避免了上下文膨胀，但依赖Copilot模型的检索质量。两者的差异根源在于任务特性：PAL-UI适用于需要频繁回溯历史的场景，而UI-Copilot适用于需要数值计算或信息检索的场景。UI-Copilot未探索检索延迟对实时性的影响，这在资源受限设备上可能成为瓶颈。

从方法设计看，UI-Copilot与Mobile-Agent-v2均涉及多智能体协作，但Mobile-Agent-v2采用固定角色分工，而UI-Copilot采用按需调用机制。Mobile-Agent-v2的固定流水线确保任务分解的稳定性，但缺乏灵活性；UI-Copilot的按需调用降低了推理成本，但依赖智能体对工具必要性的准确判断。两者的差异根源在于训练范式：Mobile-Agent-v2基于提示工程，而UI-Copilot基于TIPO解耦训练。UI-Copilot未验证工具调用错误对任务失败的累积效应，这在长程任务中可能导致性能波动。

## 总结

本文要解决的核心矛盾是长程GUI任务中上下文过载导致的记忆退化、进度混淆与数学幻觉。现有方法或依赖固定流水线或受限于检索质量，难以在保持轻量上下文的同时按需获取外部辅助。本文抓住的切入点是智能体应承担超出其内在能力的任务，通过记忆解耦将详细推理与对话历史分离，并引入轻量Copilot模型按需执行检索或计算。UI-Copilot框架结合TIPO算法解耦工具调用与动作生成的训练过程，在MemGUI-Bench上取得pass@3 20.3%的成绩，较基线提升10.1个百分点，在AndroidWorld上较基座模型提升17.1个百分点。本文的边界在于AndroidWorld上39.1%的成功率远低于SOTA，且依赖外部工具的架构可能违背原生模型驱动趋势。当Copilot模型的推理延迟超过任务时间约束时，按需调用机制是否仍能保持性能优势，论文未给出回答。
