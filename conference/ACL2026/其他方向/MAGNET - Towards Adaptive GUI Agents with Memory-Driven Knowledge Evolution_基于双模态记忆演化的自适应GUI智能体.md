# ACL2026最新论文 ｜MAGNET: Towards Adaptive GUI Agents with Memory-Driven Knowledge Evolution ｜基于双模态记忆演化的自适应GUI智能体

研究机构：复旦大学、美国南加州大学

作者：Libo Sun、Jiwen Zhang、Siyuan Wang 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.19199)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.19199)

> 移动应用频繁更新导致界面外观与工作流逻辑发生漂移，使基于固定数据集训练的GUI智能体失效。现有记忆增强框架多依赖文本描述或静态标识符，缺乏对视觉变化的鲁棒性。MAGNET通过构建关联视觉补丁与功能语义的静态记忆，以及存储抽象工作流的程序记忆，利用动态演化机制实现知识更新。该框架在免训练场景下显著提升了分布外泛化能力，但其绝对性能仍低于强化学习训练的专用模型，且依赖成功轨迹进行初始化。

## 研究背景

GUI智能体在动态环境中面临的核心挑战是界面演化带来的双重漂移。外观漂移指UI元素视觉重构但功能不变（如Twitter图标变为X），工作流漂移指操作逻辑重组但任务意图不变（如更改货币的路径改变）。这种漂移导致基于固定数据训练的专用模型（如UI-TARS）泛化能力受限，而现有记忆系统（如Agent-S）主要存储文本工作流，缺乏多模态视觉知识，无法应对视觉层面的变化。

领域主流路线分为两类：一是通过大规模监督微调（SFT）或强化学习（RL）训练端到端专用模型，其在分布内任务上表现优异，但难以适应未见过的界面状态；二是采用规划-执行（Planner-Actor）架构的推理时框架，通过外部记忆增强适应性，但受限于记忆表示的单一性。MAGNET的切入点在于识别界面演化中的“语义稳定性”与“意图稳定性”，即尽管视觉和工作流表面变化，底层功能语义和高层任务目标保持一致。通过利用这些稳定属性，MAGNET旨在构建一个能随环境演化持续更新的自适应智能体，而非依赖冻结的预训练知识。

## 核心方法

### 规划-执行架构与记忆解耦

MAGNET采用多智能体架构，将任务分解与动作执行解耦。规划器（Planner）负责将用户指令分解为子任务，执行器（Actor）负责具体的UI元素定位与操作。与常规框架不同，MAGNET为规划器配备程序记忆，为执行器配备静态记忆，分别应对工作流漂移和外观漂移。这种解耦设计使得记忆更新可以独立于模型参数进行，避免了重新训练的高昂成本，解决了传统SFT模型在界面更新后需重新标注数据的问题。

### 静态记忆与视觉-语义绑定

静态记忆旨在解决外观漂移导致的定位失效。其核心是将UI元素的视觉补丁 $v_i$ 与其功能描述 $d_i$ 绑定，形成对 $\langle d_i, v_i \rangle$。当执行器需要定位元素时，通过子任务描述查询功能描述 $d_i$，检索匹配的视觉补丁 $v_i$ 作为参考。对于通用多模态大语言模型（MLLM），补丁直接拼接至上下文；对于专用定位模型，通过模板匹配定位中心点并绘制包围框作为视觉提示。这种设计使得执行器基于功能而非精确视觉外观进行推理，从而在图标重设计等视觉变化下保持鲁棒性。

### 程序记忆与动态演化机制

程序记忆存储抽象工作流以应对工作流漂移。每个工作流由任务类别名和包含占位符（如[AppName]）的高层步骤序列组成。动态演化机制通过保留分数 $R_i$ 管理记忆优先级，公式为：

$$ R_i = \exp(-g_i / n_i) $$

其中 $g_i$ 为不活跃间隔，$n_i$ 为检索次数。该公式借鉴艾宾浩斯遗忘曲线，高频访问的记忆衰减更慢。新记忆通过自动化管线从成功轨迹中提取，包括轨迹收集、任务聚类（基于MiniCPM-Embedding构建相似度图并提取最大团）和工作流抽象。这种机制确保记忆库随环境演化更新，优先保留当前版本中有效且常用的知识，丢弃过时信息。

## 实验评估

MAGNET在离线基准（AITZ, GUI-Odyssey, Amex）和在线基准（AndroidWorld）上进行评估。离线实验对比了专用模型（如UI-Venus-Navi-7B, AtlasPro-7B）和免训练框架（COAT, Agent-S）。在线实验对比了M3A, AppAgent, Agent-S。基线覆盖了SFT/RL训练的专用模型和推理时框架，但缺乏与最新在线RL模型（如MobileRL）的直接对比，这可能影响对绝对性能的判断。

| 方法 | AITZ SR (%) | GUI-Odyssey SR (%) | Amex SR (%) |
| :--- | :--- | :--- | :--- |
| Atlas-Pro-7B | 66.64 | 58.82 | 67.45 |
| UI-Venus-Navi-7B | 60.27 | 65.93 | 63.58 |
| COAT (Qwen2.5-VL-32B) | 41.09 | 48.13 | 59.68 |
| Agent-S (Qwen2.5-VL-32B) | 42.98 | 49.21 | 67.69 |
| MAGNET (Qwen2.5-VL-32B) | 43.50 | 50.16 | 62.84 |
| MAGNET (Gemini-2.5-Pro) | 52.77 | 49.74 | 62.23 |

在免训练框架中，MAGNET在GUI-Odyssey上以50.16%的成功率领先Agent-S的49.21%。在线AndroidWorld评估中，MAGNET取得42.62%的任务完成率，高于AppAgent的34.43%和Agent-S的40.98%。消融实验显示，程序记忆对成功率（SR）的提升（+2.66% on Amex）大于静态记忆（+0.52%），因为静态记忆主要受益于模型缺乏特定图标先验的情况，这在静态离线基准中较少见。静态记忆在定位准确率（Grd.）上贡献显著（+0.26%至+0.88%）。

评估边界方面，离线实验使用自定义的分布外子集（模板、应用、领域偏移），但在线实验仅报告单一成功率，未提供置信区间。代码未公开，记忆构建管线依赖OmniParserV2和Qwen2.5-VL32B，复现需特定版本依赖。

## 关联研究分析

从问题动机看，MAGNET与UI-Voyager均关注自适应，但路线迥异。UI-Voyager基于失败经验进行拒绝微调（RFT），属于训练时优化，计算成本高且依赖大量轨迹生成；MAGNET通过推理时记忆演化，无需更新模型参数，更适合部署场景。差异根源在于任务特性：UI-Voyager针对特定任务的策略优化，而MAGNET针对界面演化的通用适应。MAGNET未探索失败轨迹的利用，仅从成功轨迹提取记忆，这可能限制了其在高失败率新领域的初始化能力。

从方法设计看，MAGNET与AppAgent同属Planner-Actor框架，但记忆表示不同。AppAgent依赖XML页面结构中的元素标识符，易受UI重构影响；MAGNET使用视觉补丁与功能语义绑定，解耦了视觉外观与功能逻辑。这一差异源于对“稳定性”的不同假设：AppAgent假设结构标识符稳定，MAGNET假设功能语义稳定。在真实移动环境中，功能语义比XML ID更稳定，因此MAGNET在分布外场景表现更优。然而，MAGNET的视觉补丁检索依赖余弦相似度，在视觉特征高度相似但功能不同的元素上可能产生混淆，论文未对此进行详细分析。

## 总结

MAGNET旨在解决GUI智能体在应用更新下的适应性难题，抓住界面演化中语义与意图稳定性的切入点，通过双模态记忆与动态演化机制实现免训练适应。实验证明其在AndroidWorld上达到42.62%成功率，优于AppAgent和Agent-S，且在分布外子集上保持鲁棒性。其边界在于依赖成功轨迹初始化，且绝对性能低于RL训练的专用模型（如MobileRL的80.2%）。当初始探索失败导致记忆库为空时，MAGNET的自适应能力是否完全丧失，论文未给出回答。
