# ACL2026最新论文 ｜One Pair Suffices: Unlocking Universal Zero-Shot Translation via Cross-Architecture Alignment ｜混合跨架构对齐

研究机构：大连理工大学、北京交通大学

作者：Hao Zong、Cong Hu Yuan、Chao Bei 等 7 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_3d6fb6ba8d18)

> 多语言大语言模型（LLMs）在低资源语言上因预训练数据稀疏导致翻译性能骤降，而专用编码器虽具备对齐的语义空间却缺乏生成能力。现有连续预训练或大规模微调方案计算成本高昂且概念冗余，本文切入点在于验证编码器语义拓扑的通用性，提出通过冻结双模型与闭环适配器实现零样本跨语言生成。HCA 框架通过源侧预条件化、门控跨模态对齐及查询残差保留，仅用德英单语对训练即可解锁数十种语言到英语的翻译能力。该框架在低资源语言上显著优于大模型基线，但完全冻结 LLM 是否限制了其内部多语言推理能力的利用，仍存疑。

## 研究背景

当解码器架构成为多语言模型主流时，模型内部形成以英语为主导的潜在语义空间，非英语输入需映射至英语表征进行推理。这种“语义枢纽”机制虽促进知识共享，却导致低资源语言在深层表征中被边缘化，其语义信息依赖表面形式重叠而非独立编码。为解决此问题，研究者尝试通过对比学习在静态嵌入空间中拉近平行句子距离，但受限于表示质量与数据稀缺，难以解释低资源语言在动态推理路径中的边缘化现象。

主流路线分为两类：一类依赖连续预训练（CPT）或大规模监督微调（SFT），迫使 LLM 重新学习多语言对齐，计算成本极高且存在负迁移风险；另一类利用专用编码器（如 NLLB）的对齐空间，但缺乏生成能力。六 T（SixT）曾证明单语对训练可解锁零样本翻译，但其轻量解码器缺乏现代 LLM 的推理与流畅性。本文切入点在于挑战“数据数量是瓶颈”的观点，提出“拓扑对齐”才是关键，即验证 LLM 能否通过学习“读取”一个语言的编码器特征，泛化到所有语言。

## 核心方法

### 方法参照系

本文问题属于跨架构知识融合，区别于传统的参数高效微调。标准流程通常涉及 LoRA 或输入层投影，将外部编码器特征映射至 LLM 输入层。本文的关键差异在于拒绝浅层投影，主张在解码器每一层通过门控交叉注意力注入预条件化的编码器特征，以解决源特征分布与解码器预期输入流形显著偏离导致的对齐失效。

### 源侧对齐适配器

标准交叉注意力在源特征分布偏离目标解码器输入流形时往往失效。本文在 NLLB 编码器内部引入源侧对齐适配器，对自注意力输出进行并行精炼。该适配器通过下投影、ReLU 激活及上投影生成对齐特征，并与前馈网络输出相加后经过最终归一化：

$$ H'_{enc} = \text{FinalNorm}(\text{FFN}(H^l_{attn}) + \text{ReLU}(H^l_{attn} W^{src}_{down}) W^{src}_{up}) $$

这一设计动机在于“预条件化”密集多语言向量，将其变换为与后续投影兼容的拓扑空间，解决了直接投影导致的信息丢失问题。

### 门控跨模态对齐与查询残差

源侧对齐后的特征需注入 LLM 生成空间。本文设计跨模态对齐适配器，将编码器特征投影为键（K）和值（V），LLM 隐藏状态作为查询（Q），通过门控缩放控制融合比例：

$$ C_{cross} = g \cdot \left( \text{Softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V \right) $$

同时，为保持 LLM 生成稳定性，引入查询残差适配器独立处理 LLM 查询特征，最终输出为三者之和：

$$ H_{out} = H_{llm} + C_{cross} + H_{res} $$

该闭环设计确保模型在利用编码器对齐能力的同时，保留 LLM 的内部语言知识，避免了直接注入跨模态信息对推理流的干扰。

## 实验评估

实验基于 FLORES-200 devtest 划分，覆盖 10 种语言到英语的翻译任务。基线包括 TowerPlus-9B、Aya-101 及 NLLB-1.3B，覆盖了大规模监督微调与专用编码器路线，但缺乏与 LaMaTE 等反向融合方法的直接对比。

| 模型 | 参数规模 | 低资源语言 COMET | 整体平均 COMET |
| --- | --- | --- | --- |
| HCA (Zero-Shot) | ~5.25B | 82.6 | 82.9 |
| TowerPlus-9B | 9B | 73.6 | - |
| Aya-101 | 13B | 80.7 | - |
| HCA (Oracle) | ~5.25B | - | 85.8 |
| NLLB-1.3B | 1.3B | - | 85.6 |

HCA 零样本模型在低资源语言上以 82.6 COMET 超越 TowerPlus-9B 9.0 分，并优于 Aya-101。Oracle 模型整体平均 85.8 COMET，超过全监督 NLLB-1.3B 教师模型，证明框架实现了编码器表示与 LLM 生成能力的协同。

消融实验显示，仅用德英 580k 对训练即达到 Oracle 性能的 96.7%（82.9 vs 85.8 COMET），验证了“源侧对齐泛化”现象。将编码器从 600M 升级至 1.3B 后，古吉拉特语性能提升 3.4 COMET，表明性能随编码器规模线性扩展，且无需额外训练。

评估边界方面，论文未报告置信区间，且仅评估 X-to-English 方向，未涵盖双向翻译或英语到 X 的场景。代码未公开，超参数细节（如门控初始值 $g=1$ 的敏感性）未充分讨论，可复现性受限。

## 关联研究分析

从问题动机看，本文与 SixT 共享“单对训练零样本”的核心假设，但 SixT 依赖从头训练轻量解码器，而本文利用冻结 LLM 的生成能力。这一差异源于任务特性：SixT 关注翻译准确性，而本文强调生成流畅性与低资源泛化。然而，本文完全冻结 LLM，未探索 LLM 内部多语言知识对对齐的贡献，这与领域共识中“LLM 内部存在英语中心空间”的观点形成潜在矛盾。

从方法设计看，本文与 MT-LLM 等浅层投影方法形成对比。MT-LLM 使用 LoRA 和输入层投影，主要面向跨语言理解任务；本文采用深层门控交叉注意力，针对翻译任务的严格语义保真度。这种设计选择暗示，浅层投影在生成任务中可能无法充分捕获编码器特征与 LLM 生成空间的拓扑差异。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文核心矛盾在于 LLM 低资源翻译性能差与编码器对齐能力强的割裂。切入点在于验证编码器语义拓扑的通用性，通过冻结双模型与闭环适配器实现零样本泛化。HCA 框架证明了单对训练可恢复 96.7% 的 Oracle 性能，且在低资源语言上显著优于大模型基线。边界在于仅评估 X-to-English 方向，且完全冻结 LLM 可能限制其内部多语言推理能力的利用。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
