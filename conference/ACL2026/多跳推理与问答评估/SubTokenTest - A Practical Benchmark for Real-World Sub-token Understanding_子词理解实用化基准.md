# ACL2026最新论文 ｜SubTokenTest: A Practical Benchmark for Real-World Sub-token Understanding ｜子词理解实用化基准

研究机构：北京大学

作者：Shuyang Hou、Yi Hu、Muhan Zhang

论文原文见 [arXiv](https://arxiv.org/abs/2601.09089)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.09089)

> 大语言模型在字符级操作上的失效常被归因于分词器粒度与任务语义粒度的错位，但现有基准仅评估孤立的原子操作，无法反映该缺陷在表格解析、地图导航等真实场景中的功能性后果。SUBTOKENTEST 通过构建十项剥离复杂推理的实用任务，将感知准确性与逻辑推理解耦，从而隔离分词导致的底层解析错误。该基准揭示了推理模型虽能缓解子词盲区，但需付出极高 token 成本，且性能随思考长度呈倒 U 型变化。这一发现挑战了“增加推理预算必然提升性能”的假设，但其在多模态或长上下文耦合场景下的泛化能力仍存疑。

## 研究背景

当模型处理包含密集符号的文本时，分词器（Tokenizer）将连续字符切分为离散 token，导致单个 token 内可能包含多个语义单元或一个单元被拆分为多个 token。这种粒度错位使得模型无法直接访问字符级结构，必须依赖训练语料中的统计模式推断字符组成，这一现象被称为子词盲区（Sub-token Blindness）。子词盲区在基础字符计数任务中表现明显，但在表格对齐、二维地图状态读取等实用任务中，它会导致坐标定位错误和结构解析失败，且这些感知错误常被混淆为逻辑推理错误，难以被现有评估体系捕捉。

多跳推理与检索增强生成（RAG）领域的评估体系长期聚焦于逻辑链的完整性与证据整合能力，如 HotpotQA 和 MuSiQue 等基准要求模型通过跨文档链接推导答案。然而，这些基准假设模型具备完美的底层感知能力，即能够准确解析输入文本的结构。当模型在感知层面出现子词解析错误时，后续的逻辑推理将建立在错误的前提上，导致“答案正确但过程错误”或“过程正确但答案错误”的复杂失效模式。现有子词理解基准（如 Edman et al., 2024）仅测试拼写、计数等原子操作，缺乏与真实应用场景的关联，导致模型在这些简单任务上的失败被低估其在复杂任务中的实际影响。SUBTOKENTEST 的切入点在于将子词理解评估从原子操作迁移至实用功能场景，通过剥离复杂推理，专门诊断模型在字符流解析层面的能力边界。

## 核心方法

### 感知-推理解耦架构

SUBTOKENTEST 的设计核心是将感知准确性与复杂逻辑推理解耦。在传统的多跳问答或 Agent 任务中，模型失败往往源于感知错误（如误读表格单元格）与推理错误（如逻辑推导失误）的叠加，导致无法定位根本原因。该基准通过最小化逻辑复杂度，仅保留确定性的字符级映射或结构解析步骤，从而隔离出模型对 token 序列中底层字符流的解析能力。这一设计解决了现有基准中感知错误与推理错误相互混淆的问题，使得评估能够精确指向分词器粒度带来的具体失效。

### 原子能力映射与任务构建

基准将十项实用任务映射至六种原子子词能力：拼写（Spelling）、逆拼写（Inverse Spelling）、字符计数（Character Counting）、字符索引（Character Indexing）、字符替换（Character Substitution）和 Token 长度（Token Length）。这种映射建立了高层任务与底层失效模式的因果联系。例如，在“对齐表格”任务中，模型需利用 Token 长度计算列宽，利用字符索引定位分隔符，利用字符计数生成填充空格。任务生成采用自动化流水线，支持可控难度，确保测试集覆盖不同长度和复杂度的输入。评估指标采用精确匹配（EM）和归一化 Levenshtein 相似度，其中相似度定义为：

$$
\text{Sim}(p_i, g_i) = 1 - \frac{d_{\text{lev}}(p_i, g_i)}{\max(|p_i|, |g_i|)}
$$

该公式通过计算预测序列 $p_i$ 与真实序列 $g_i$ 之间的编辑距离并归一化，量化了模型在字符级操作上的近似正确性，弥补了 EM 指标对细微字符错误不敏感的缺陷。

### 测试时预算控制与机制探针

为探究推理预算对子词理解的影响，论文引入测试时预算控制（TTBC）方法，通过强制设定思考 token 上限 $t_{\text{exact}}$ 来调节模型推理长度。当模型提前终止时注入“Wait”提示，超限时截断，从而构建思考长度与性能的函数关系。此外，为验证模型内部是否编码字符级信息，论文对 Qwen-2.5-7B-Instruct 的隐藏层进行线性探针（Linear Probing）分析。探针任务定义为预测输入字符串的字符计数向量 $y \in \mathbb{N}^{|A|}$，其中 $y_m$ 表示第 $m$ 个字符的出现次数。探针模型在最后一层隐藏状态 $h_\ell$ 上训练，以检测不同文本形式（正常词、错别字、随机字母、特殊符号）下字符信息的编码深度。

## 实验评估

实验覆盖 GPT-4、GPT-5、o4-mini、DeepSeek-V3、DeepSeek-R1 及 Qwen 系列模型，测试集共 1,700 个实例。基线审计显示，对比方法均为通用大语言模型，未包含专门针对子词理解的微调模型或采用随机分词（如 BPE-Dropout）的变体，这限制了与特定缓解策略的直接对比。主实验结果显示，大规模推理模型（如 DeepSeek-R1、GPT-5）在多数任务上显著优于非推理模型，但 token 消耗量高达数十倍。例如，在 Gomoku 任务中，DeepSeek-R1 的精确匹配率为 93.0%，而 DeepSeek-V3 为 53.0%，但前者平均消耗 13,801 个 token，后者仅 2,213 个。

| 任务 | 指标 | DeepSeek-V3 | DeepSeek-R1 | GPT-4 | GPT-5 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Keystroke Encoding | EM | 86.0% | 95.0% | 90.0% | 99.0% |
| Cipher | Exact Match | 30.0% | 25.0% | 25.0% | 40.0% |
| Bio-seq | Exact Match | 77.0% | 32.0% | 32.0% | 97.0% |
| Map-Nav (Sokoban) | EM | 79.0% | 48.0% | 48.0% | 98.0% |
| Gomoku | Linear EM | 53.0% | 36.0% | 36.0% | 97.0% |

在消融实验中，TTBC 分析揭示了倒 U 型性能曲线：在生物序列操作任务中，DeepSeek-R1-Distill-Qwen-7B 的性能在 2048 token 预算时达到峰值，随后随预算增加而下降。这表明过度思考（Overthinking）在子词任务中不仅无益，反而因冗余推理引入噪声。机制探针分析显示，字符级信息在深层网络中编码更充分，但随机字母和特殊符号的编码能力显著低于正常词汇，暗示模型对非自然语言结构的子词解析存在固有局限。

评估边界方面，论文未报告置信区间，且模型版本迭代迅速，结果在最新模型上的稳健性需进一步验证。代码与数据集已开源，但自动化任务生成流水线的超参数细节仅在附录中提供，复现成本较高。

## 关联研究分析

从问题动机看，SUBTOKENTEST 与 NovelHopQA 等长上下文基准均关注模型在特定维度上的认知极限，但前者聚焦于粒度错位导致的感知失效，后者聚焦于长度导致的注意力稀释。NovelHopQA 通过增加上下文长度诊断位置偏差，而 SUBTOKENTEST 通过固定长度但增加字符密度诊断分词偏差。这种差异源于任务特性：长上下文任务中，信息定位是主要瓶颈；而在表格或地图任务中，信息解析是主要瓶颈。论文未探讨当两者同时存在（如长表格）时的交互效应，这可能导致在真实 Agent 场景中低估感知错误的累积影响。

从方法设计看，SUBTOKENTEST 的解耦策略与 CRAFT 等强调轨迹忠实度的方法形成对比。CRAFT 通过结构化输出提升推理轨迹的可审计性，而 SUBTOKENTEST 通过剥离推理提升感知准确性的可测性。两者均旨在解决“黑盒”问题，但 CRAFT 关注逻辑链的完整性，SUBTOKENTEST 关注字符流的完整性。这种差异暗示，在感知与推理耦合的任务中，仅优化感知或仅优化推理均不足，需要联合评估框架。论文未提供此类联合评估，限制了其在复杂 Agent 任务中的应用价值。

## 总结

SUBTOKENTEST 解决了子词理解评估中感知错误与推理错误混淆的核心矛盾，通过构建实用化任务并剥离逻辑推理，首次量化了分词粒度对模型功能性任务的影响。实验证明，推理模型虽能缓解子词盲区，但需付出极高 token 成本，且存在倒 U 型性能曲线，揭示了过度思考在字符级任务中的负迁移效应。该基准的边界在于其任务设计剥离了真实场景中的推理-感知耦合，且未涵盖多模态输入。当模型在长上下文表格中同时面临长度偏差与粒度偏差时，其性能退化是否呈线性叠加，论文未给出回答。
