# ACL2026最新论文 ｜Mango: Multi-Agent Web Navigation via Global-View Optimization ｜基于全局视图优化的多智能体网页导航

作者：Weixi Tong、Yifeng Di、Tianyi Zhang

论文原文见 [arXiv](https://arxiv.org/abs/2604.18779)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_5aeaed18360d)

> 现有网页智能体从根 URL 开始线性探索，在深层级网站中易陷入导航陷阱或耗尽预算。MANGO 通过预构建网站全局结构，将 URL 选择建模为多臂老虎机问题，利用 Thompson Sampling 动态分配导航预算，从而在有限步骤内定位目标信息。该方法在 WebVoyager 上取得 63.6% 成功率，但在 WebWalkerQA 多源任务中仍低于领域最高水平，其全局爬取成本与实时性权衡尚存疑。

## 研究背景

当智能体面对拥有数百万页面的大型网站时，从首页开始逐层遍历会导致搜索空间爆炸。这种盲目探索不仅浪费计算资源，更因缺乏全局视野而频繁陷入无关分支。为解决此问题，多臂老虎机（Multi-Armed Bandit, MAB）提供了一种在不确定环境下优化资源分配的框架，其核心在于通过“探索-利用”平衡来最大化累积奖励。然而，传统 MAB 假设臂的寿命固定，而网页导航中 URL 的有效性是动态变化的，这要求引入基于反馈的状态转移机制，即有限寿命臂模型。

当前主流网页智能体如 AgentOccam 和 WebWalker 主要聚焦于优化动作空间或引入探索-批评范式，但均继承自 ReAct 框架的线性执行逻辑，即从根节点开始逐步发现网站结构。这种增量式探索在复杂层级结构中效率低下，且无法在导航前剪枝无效路径。MANGO 的切入点在于将“起点选择”从导航过程中解耦出来，通过预分析网站全局结构来识别候选 URL，从而在导航开始前就缩小搜索范围。

## 核心方法

### 方法参照系

本文问题属于网页智能体中的“规划与导航”子任务。标准流程为：接收查询 -> 从根 URL 启动 -> 迭代执行动作 -> 输出结果。MANGO 的关键差异在于引入了“全局结构分析”前置模块，将传统的单点线性搜索转变为基于全局信息的多起点并行评估，改变了搜索空间的初始状态。

### 全局结构分析与候选集构建

设计动机在于解决根 URL 作为唯一入口导致的深层级页面不可达问题。MANGO 首先通过广度优先搜索（BFS）爬取网站，过滤非 HTML 文件及外部链接，保留同域页面。对于爬取受限的大型站点（如 arXiv），结合 LLM 生成的关键词利用 Google Search 的 site 操作符补充索引。随后，使用 BM25 算法对候选 URL 内容与用户查询 $q$ 进行语义相似度评分，选取 Top 10 构成候选集 $U$。这一过程将搜索空间从整个网站层级压缩至与查询高度相关的有限子集。

### 基于 Thompson Sampling 的动态 URL 选择

设计动机在于解决固定生命周期 MAB 无法适应网页动态性的问题。MANGO 将每个候选 URL 视为一个臂，其状态在 Active 与 Exhausted 间动态转换。初始化时，利用归一化的 BM25 分数 $\rho_u$ 设定 Beta 分布参数：

$$ \alpha_u^{(0)} = 1 + \kappa \cdot \rho_u, \quad \beta_u^{(0)} = 1 + \kappa \cdot (1 - \rho_u) $$

其中 $\kappa$ 为相关性权重。在每步导航中，从 Active 臂的后验分布中采样 $\theta_u$，选择最大值对应的 URL $u^*$ 进行访问。导航结束后，反思智能体根据轨迹输出二元奖励 $r \in \{0, 1\}$，更新参数：

$$ \alpha_u^{(t+1)} = \alpha_u^{(t)} + r^{(t)}, \quad \beta_u^{(t+1)} = \beta_u^{(t)} + (1 - r^{(t)}) $$

若反思判定为死胡同，该 URL 标记为 Exhausted 并移除。此机制实现了基于反馈的自适应预算分配，避免重复访问无效路径。

## 实验评估

| 基准 | 骨干模型 | MANGO | AgentOccam | WebWalker |
| :--- | :--- | :--- | :--- | :--- |
| WebVoyager | GPT-5-mini | 63.57 | 56.25 | 16.28 |
| WebVoyager | Qwen3-32B | 37.98 | 34.11 | 14.73 |
| WebWalkerQA | GPT-5-mini | 52.50 | 20.29 | 25.74 |
| WebWalkerQA | Qwen3-32B | 28.38 | 10.59 | 16.76 |

实验在 WebVoyager（129 个 QA 任务）和 WebWalkerQA（680 个任务）上进行，对比了 AgentOccam（动作空间优化）和 WebWalker（探索-批评范式）。MANGO 在 GPT-5-mini 骨干下表现最佳，WebVoyager 成功率达 63.57%，较 AgentOccam 提升 7.32 个百分点；WebWalkerQA 整体成功率 52.50%，较 WebWalker 提升 26.76 个百分点。在 Qwen3 系列中，性能随模型规模单调递增，但绝对值显著低于 GPT-5-mini，表明方法对骨干模型推理能力依赖较强。

消融实验显示，MANGO 相比 MCTS 变体在 WebWalkerQA 上取得 5.2% 至 17.1% 的绝对提升，验证了 Thompson Sampling 优于树搜索。然而，使用 GPT-5-mini 时，MANGO 的平均动作数高于基线，分析表明这是因为其能完成更多长程复杂任务，而非效率降低。在 Qwen3 系列中，动作数保持稳定，说明性能提升源于决策准确性而非探索深度。

评估边界方面，论文未报告置信区间，且 WebVoyager 仅使用 129 个过滤任务，样本量较小。代码已开源，但全局爬取的时间开销未量化，无法评估其在实时性要求高的场景下的可行性。此外，实验未包含基于强化学习（如 WebRL）或多模态接地（如 Avenir-Web）的基线，限制了与最新 SOTA 的直接对比。

## 关联研究分析

从问题动机看，MANGO 与 WebPilot 同属搜索策略优化，但 WebPilot 采用 MCTS 在导航过程中动态扩展树结构，而 MANGO 通过预构建全局结构在导航前剪枝。这一差异源于对“搜索空间”定义的不同：WebPilot 视搜索为在线过程，MANGO 视其为离线预处理。MANGO 的优势在于降低了在线计算开销，但代价是引入了爬取延迟，这在网站结构频繁变化的动态环境中可能失效。

从方法设计看，MANGO 的情景记忆粒度为 URL 级，存储轨迹与反思摘要以防止重复访问，这与 WebCoach 的任务级经验记忆不同。WebCoach 关注跨会话的长期策略学习，而 MANGO 聚焦于单次任务内的路径去重。这种设计选择反映了 MANGO 对“效率”而非“泛化”的侧重，其记忆机制无法迁移至新网站或新任务类型，限制了其在开放网络中的长期适应能力。

## 总结

MANGO 旨在解决深层级网站中从根 URL 线性探索导致的效率低下与预算耗尽问题。其核心创新在于将 URL 选择建模为有限寿命 MAB，通过全局结构分析预剪枝搜索空间，并利用 Thompson Sampling 动态分配导航预算。实验证明该方法在 GPT-5-mini 骨干下显著优于 AgentOccam 和 WebWalker，WebVoyager 成功率达 63.57%，WebWalkerQA 达 52.50%。然而，方法依赖预爬取的全局结构，且性能高度依赖骨干模型推理能力，在 Qwen3 系列中表现大幅下滑。当网站结构动态变化或爬取成本过高时，全局视图的时效性与构建开销如何平衡，论文未给出回答。
