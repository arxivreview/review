# ACL2026最新论文 ｜Learning to Edit Knowledge via Instruction-based Chain-of-Thought Prompting ｜基于指令链式思维的知识编辑

研究机构：北京邮电大学、北京大学

作者：Jinhu Fu、Yan Bai、Longzhu He 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.05540)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_d357115d2e8c)

> 大语言模型（LLMs）在预训练后固化了静态知识，面对动态现实时，全量微调成本高昂且易引发灾难性遗忘，而现有知识编辑方法多局限于原子事实的“死记硬背”，难以处理非结构化知识且泛化能力受限。CoT2Edit 指出，参数编辑缺乏语义理解，纯上下文学习则受限于提示模板的僵化，其切入点在于将知识编辑重构为基于检索增强生成（RAG）的推理任务。该方法通过两阶段训练（SFT 冷启动 + GRPO 优化）让模型学会从非结构化上下文中提取事实并生成链式思维（CoT），在单次训练后实现了跨格式与分布外（OOD）的强泛化。其价值在于突破了三元组编辑的局限，但推理时的检索依赖与训练数据的规模上限仍制约其长期稳定性。

## 研究背景

当模型面对“美国领导人是谁”与“美国总统是谁”这类语义等价但表述不同的查询时，参数编辑方法往往只能对精确匹配的查询生效，而对改写查询失效，这种现象被称为通用性（Generality）不足。这种失效的根源在于，定位-编辑范式（如 ROME, MEMIT）将知识存储视为 FFN 层中离散的键值对（K-V pairs），修改权重仅改变了特定神经元的激活，并未赋予模型理解查询语义的能力。因此，当查询形式发生微小变化，模型无法通过语义推理关联到被编辑的事实，导致编辑效果在真实场景中大打折扣。

知识编辑领域长期存在参数编辑与非参数编辑的路线之争。参数编辑方法（如 AlphaEdit）虽在单跳任务上可靠性高，但受限于“死记硬背”机制，无法处理新闻、文章等非结构化知识，且在大规模编辑下易产生涟漪效应。非参数方法（如 IKE）通过上下文学习注入知识，虽无需修改参数，但依赖静态提示模板，缺乏对复杂推理链的建模，导致在多跳问答和分布外场景中性能急剧下降。CoT2Edit 的切入点在于，不再将编辑视为对参数的局部修改或对提示的简单拼接，而是将编辑过程重构为“检索-推理-生成”的闭环，通过训练模型具备从非结构化文本中提取事实并进行多步推理的能力，从而在保持参数不变的前提下，实现语义层面的知识更新。

## 核心方法

### 方法参照系

本文问题属于非参数编辑路线，但区别于 IKE 等基于静态提示的方法，其核心差异在于引入了显式的推理链生成机制。标准非参数流程是直接将编辑事实拼接到提示中，模型一步生成答案；而 CoT2Edit 将任务分解为“从上下文提取事实”和“基于事实推理答案”两个阶段，要求模型输出中间推理步骤，从而将知识编辑从记忆匹配转化为逻辑推导。

### 双阶段数据构建与推理链生成

针对现有方法仅处理结构化三元组、无法应对非结构化知识的局限，CoT2Edit 构建了包含多跳推理与非结构化实体的指令数据集。设计动机在于，静态提示无法引导模型处理需要多步逻辑跳转的查询，而显式的推理链能增强模型对编辑事实的语义理解。数据构建分为两部分：一是利用 MQuAKE 和 MQuAKE-uns 生成结构化与非结构化推理链，二是从 HotpotQA 提取实体关系，通过 LLM Agent 合成额外的指令数据。对于非结构化数据，模型需先从编辑上下文 $C$ 中提取相关事实 $E$，再基于 $E$ 回答查询 $Q$。该过程形式化为：

$$ f_{\theta'}(e, q) = g_{\theta'}(h_{\theta'}(e, q)) $$

其中 $h_{\theta'}(e, q)$ 生成可解释的推理链，$g_{\theta'}(\cdot)$ 基于推理链产生最终答案。这一两阶段映射迫使模型在生成答案前显式地处理编辑事实，避免了单步生成中的幻觉，提升了在语义改写查询上的鲁棒性。

### SFT 冷启动与 GRPO 强化优化

针对纯 SFT 训练导致的过拟合与分布外泛化差的问题，CoT2Edit 采用两阶段训练策略。设计动机在于，SFT 仅能教会模型模仿训练数据中的编辑模式，无法泛化到未见过的编辑场景，而强化学习能通过奖励信号优化模型的推理策略。第一阶段使用 SFT 数据作为冷启动，让模型学习基本的指令遵循格式；第二阶段引入 Group Relative Policy Optimization (GRPO)，以数据演化的方式优化模型。GRPO 的奖励函数包含格式奖励（检查是否包含 `
</think>

` 和 `<answer>` 标签）和准确性奖励（答案与真值匹配）。通过 GRPO，模型在推理过程中被鼓励生成逻辑正确且格式规范的推理链，从而在保持通用能力的同时，显著提升了对复杂推理任务和 OOD 编辑的泛化能力。

## 实验评估

实验在 Llama3-8B、Falcon3-10B 和 Qwen3-14B 上进行，对比了 RoME、MEMIT、IKE、AlphaEdit、EditCoT 等基线。基线覆盖了参数编辑与非参数编辑两条路线，但缺失了近期在终身编辑中表现优异的 EvoEdit 和 MetaKE 等强基线，这可能低估了参数编辑在特定场景下的上限。

| 方法 | ZsRE Edit Succ. | MQuAKE Nei. | CounterFact-uns Edit Succ. |
| :--- | :--- | :--- | :--- |
| RoME | 2.01 | 80.28 | 74.97 |
| MEMIT | 34.62 | 81.19 | 77.35 |
| IKE | 80.88 | 86.63 | 84.64 |
| AlphaEdit | 88.78 | 97.11 | 93.64 |
| EditCoT | 86.13 | 90.58 | 93.64 |
| CoT2Edit | 93.17 | 99.95 | 94.56 |

在 ZsRE 单跳任务上，CoT2Edit 的 93.17% 低于 AlphaEdit 的 88.78% 吗？不，表格显示 AlphaEdit 为 88.78%，CoT2Edit 为 93.17%，CoT2Edit 更高。但在 MQuAKE 多跳任务上，CoT2Edit 的 99.95% 显著优于 AlphaEdit 的 97.11% 和 EditCoT 的 90.58%，验证了推理链在多跳推理中的优势。在非结构化编辑（CounterFact-uns）上，CoT2Edit 达到 94.56%，优于参数编辑方法，表明其跨格式鲁棒性。

消融实验显示，移除 SFT 阶段后，CoT2Edit 在 CounterFact 上的 Edit Succ. 从 99.13% 降至 87.13%，降幅达 12%；移除 GRPO 阶段后，降至 92.06%。这表明 SFT 提供了必要的格式基础，而 GRPO 进一步提升了推理的准确性。值得注意的是，移除训练（W/O Train）后性能骤降至 61.73%，证实了训练过程对编辑能力的决定性作用。

评估边界方面，论文未报告推理延迟的具体数值，仅定性指出 CoT2Edit 推理时间略高于 IKE 但远低于 EditCoT。代码已开源，但训练数据规模（约 10k 条）相对较小，且未提供不同规模数据下的性能曲线，限制了对其数据效率的深入评估。

## 关联研究分析

从问题动机看，CoT2Edit 与 EditCoT 均旨在解决参数编辑的语义理解缺失问题，但 EditCoT 依赖多模型流水线（一个模型生成 CoT，另一个模型执行编辑），导致计算成本高且部署复杂。CoT2Edit 通过单模型的 SFT+GRPO 训练，将 CoT 生成内化为模型能力，简化了流程。这一差异源于任务特性的不同：EditCoT 假设 CoT 生成与知识编辑可解耦，而 CoT2Edit 认为两者需协同优化，以在有限参数下最大化推理效率。

从方法设计看，CoT2Edit 与 IKE 同属非参数编辑，但 IKE 依赖静态提示模板，而 CoT2Edit 引入 RAG 动态检索与 CoT 推理。IKE 的局限在于提示长度固定，无法适应复杂查询；CoT2Edit 通过检索相关事实并生成推理链，实现了动态适配。然而，CoT2Edit 的 RAG 依赖外部向量数据库，当编辑事实数量极大时，检索延迟可能成为瓶颈，而 IKE 的静态提示虽简单但无此依赖。这种取舍反映了非参数编辑在灵活性与效率之间的权衡。

## 总结

CoT2Edit 旨在解决非参数编辑中泛化性差与非结构化知识处理难的矛盾，其切入点在于将编辑重构为基于 RAG 的推理任务，通过 SFT 冷启动与 GRPO 强化学习，使模型具备从非结构化文本中提取事实并生成逻辑推理链的能力。实验表明，该方法在 MQuAKE 多跳任务上达到 99.95% 的准确率，显著优于参数编辑基线，且在 OOD 场景中保持 85% 以上的稳定性。然而，其性能依赖于训练数据的规模与质量，且推理时的检索机制在大规模编辑下可能引入延迟。当编辑事实数量从 2k 增长到 20k 时，检索精度与推理延迟的平衡如何影响最终性能，论文未给出量化回答。
