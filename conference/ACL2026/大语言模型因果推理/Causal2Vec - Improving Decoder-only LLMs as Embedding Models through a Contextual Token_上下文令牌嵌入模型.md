# ACL2026最新论文 ｜Causal2Vec: Improving Decoder-only LLMs as Embedding Models through a Contextual Token ｜上下文令牌嵌入模型

作者：Ailiang Lin、Zhuoyun Li、Yusong Wang 等 5 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_33e3e8f4246a)

> 解码器大语言模型在生成文本嵌入时，受限于因果注意力机制，早期词元无法访问后续信息，导致表征能力受限。现有主流方案或强制切换为双向注意力引发预训练失配，或重复输入文本增加计算开销，均未能兼顾架构兼容性与效率。Causal2Vec通过引入轻量级双向编码器生成单一上下文令牌并前置注入，在不修改LLM架构的前提下解决了该瓶颈。该方法在公开数据训练约束下刷新了MTEB基准SOTA，但其性能上限是否受限于外部编码器容量，仍存疑。

## 研究背景

文本嵌入模型将自然语言映射为稠密向量，是检索增强生成（RAG）系统的核心组件。解码器LLM凭借强大的语义理解能力成为构建嵌入模型的新骨干，但其固有的因果注意力掩码导致除最后一个词元外，其他词元只能关注前文，无法获取全局上下文信息。这种信息截断使得基于最后词元池化（last-token pooling）的嵌入方法易受序列末端噪声干扰，产生最近偏差（recency bias），难以生成鲁棒的语义表征。

主流解决方案分为两类：一类是移除因果掩码实现双向注意力，如GRITLM和LLM2Vec，但这破坏了LLM预训练时的注意力模式，导致微调性能下降，且仅对Mistral-7B等特定架构有效；另一类是保留因果注意力但增加输入，如ECHO重复输入文本或bge-en-icl引入上下文示例，虽能获取全局信息，但序列长度翻倍或显著增加，计算成本高昂。Causal2Vec的切入点在于，既保留LLM原始因果架构以维持预训练语义能力，又通过外部轻量编码器注入全局上下文，避免架构修改与输入膨胀的双重代价。

## 核心方法

### 方法参照系

解码器LLM嵌入模型的标准流程包含输入编码、注意力计算与池化表示三个环节。本文问题与该通用流程的关键差异在于，如何在保持因果注意力掩码不变的前提下，解决早期词元缺乏全局上下文信息导致的表征瓶颈，同时避免引入额外输入文本带来的计算开销。

### 上下文令牌生成与注入

传统方法中，双向编码器直接输出嵌入或LLM内部词元独立计算，缺乏跨模态信息融合。Causal2Vec在输入编码环节引入一个轻量级BERT风格双向编码器，对输入文本进行均值池化得到$k$维向量$h$，再通过可训练MLP层将其投影至LLM词嵌入空间维度$d$，生成上下文令牌$C$。该设计动机在于，利用双向编码器捕获全局语义，弥补因果注意力下早期词元的信息缺失，且无需修改LLM架构。

$$C = \sigma(hW_1^\top)W_2^\top$$

其中$W_1 \in \mathbb{R}^{d \times k}$和$W_2 \in \mathbb{R}^{d \times d}$为可训练投影矩阵，$\sigma$为GELU激活函数。该公式将双向编码器的全局语义压缩为单一令牌，使其能作为LLM输入序列的一部分参与因果注意力计算。

### 混合池化表示

标准last-token pooling仅使用EOS词元隐状态，易受末端噪声影响。Causal2Vec在表示环节拼接上下文令牌$C$与EOS词元的最后一层隐状态作为最终文本嵌入。该设计动机在于，上下文令牌不受序列末端噪声干扰，且已编码全局语义，与EOS词元拼接可缓解最近偏差，提供更丰富的上下文信息。

$$\mathbf{e} = [\mathbf{h}_C; \mathbf{h}_{EOS}]$$

其中$\mathbf{h}_C$和$\mathbf{h}_{EOS}$分别为上下文令牌和EOS词元的最后一层隐状态，$[\cdot; \cdot]$表示垂直拼接。该表示方法通过显式监督上下文令牌，帮助LLM更好地理解注入的语义信息，同时保持嵌入向量的维度兼容性。

## 实验评估

实验在MTEB基准（56个数据集，7类任务）上进行，基线覆盖双向注意力（GRITLM, LLM2Vec）、单向重复输入（ECHO）及上下文学习（bge-en-icl）等主流路线，但未包含纯编码器基线。Causal2Vec在Mistral-7B骨干上取得66.10的平均分，超越bge-en-icl的66.08；在S-LLaMA-1.3B上取得62.83，显著高于LLM2Vec的51.44。

| 方法 | 骨干 | MTEB平均分 |
| :--- | :--- | :--- |
| LLM2Vec | S-LLaMA-1.3B | 51.44 |
| Causal2Vec | S-LLaMA-1.3B | 62.83 |
| bge-en-icl | Mistral-7B | 66.08 |
| Causal2Vec | Mistral-7B | 66.10 |

消融实验显示，移除上下文令牌导致S-LLaMA-1.3B性能下降0.38分，Mistral-7B下降0.60分；替换为直接嵌入拼接则性能显著退化，证明增益源于架构改进而非简单融合。增加上下文令牌数量至2、4、8个时，性能反而下降，表明单一令牌已足够捕获必要上下文，多余令牌引入冗余。

评估边界方面，实验仅使用公开检索数据训练，未报告置信区间；MTEB-MINI子集用于消融，全量评估需200+ A100 GPU小时。代码未公开，超参数如温度$\tau=0.05$固定，LoRA应用于小模型，可复现性依赖未公开的预处理细节。

## 关联研究分析

从问题动机看，Causal2Vec与ECHO均旨在解决因果注意力下的上下文缺失，但ECHO通过重复输入实现，序列长度翻倍，计算成本增加；Causal2Vec通过外部编码器注入单一令牌，序列长度仅增加1，推理时间降低82%。这一差异源于任务特性：嵌入任务对全局语义敏感，但无需长序列建模，外部编码器的高效压缩更适配该场景。

从方法设计看，Causal2Vec与Anchor均保留因果注意力，但Anchor通过双向重构目标增强EOS表示，需全参数微调；Causal2Vec通过外部编码器注入上下文，仅用LoRA微调。Anchor的重构目标旨在丰富EOS语义，而Causal2Vec的上下文令牌直接提供全局信息，避免了全参数微调的计算开销，但引入了外部编码器依赖。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

Causal2Vec要解决的核心矛盾是解码器LLM因果注意力导致的上下文缺失与架构兼容性、计算效率之间的冲突。现有方法或牺牲架构一致性（双向化），或牺牲效率（重复输入），Causal2Vec凭借轻量级外部编码器生成单一上下文令牌，在不修改LLM架构的前提下实现了全局信息注入。该方法在MTEB基准上取得66.10（Mistral-7B）和62.83（S-LLaMA-1.3B）的SOTA成绩，验证了架构保留策略的有效性。其边界在于，性能上限受限于外部编码器容量，且单一令牌假设在复杂长文本场景下的鲁棒性未充分验证。当输入文本长度超过双向编码器上下文窗口时，上下文令牌的语义完整性是否受损，论文未给出回答。
