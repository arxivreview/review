# ACL2026最新论文 ｜PACE: Predictive Adaptive Context Extraction for Long-Horizon LLM Agents ｜预测性自适应上下文提取

作者：Lei Wei、Xiao Peng、Tt 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_a5fc4587d711)

> 长时域智能体在数百步交互中面临上下文窗口耗尽与关键信息丢失的双重困境，传统截断或静态摘要策略无法兼顾信息完整性与计算效率。现有方法将记忆管理视为独立的元认知任务，导致决策过程与记忆操作耦合，限制了模型泛化能力。PACE 将上下文选择重构为下一步预测问题，通过向量注意力评分与压力自适应阈值动态调整历史记忆粒度。该框架在超长时域任务中实现了 4,897 步的有效推理，较基线提升 66.2 倍，但其预测机制对复杂逻辑依赖的捕捉能力尚存疑。

## 研究背景

当智能体执行多步任务时，每一步的决策都依赖于历史交互序列，但 Transformer 架构的二次方注意力复杂度使得完整历史保留在长时域下不可行。这一矛盾催生了上下文管理问题：如何在有限窗口内筛选出对当前动作最具价值的历史信息。解决该问题的核心在于区分“相关”与“无关”信息，而相关性并非静态属性，而是随任务进展动态变化的，这要求管理策略具备预测性而非反应性。

长上下文大语言模型研究早期聚焦于扩展窗口长度，但“中间迷失”现象揭示了注意力稀释的固有缺陷，即模型对中间位置信息的利用率显著低于首尾。在智能体场景中，这一缺陷被放大为决策质量的持续退化：随着交互步数增加，早期关键证据被后期冗余信息淹没，导致智能体在长时域任务中频繁偏离目标。主流解决方案分为两类：一是 ReAct 风格的全历史保留，虽保证信息完整但迅速耗尽窗口；二是 AgentFold 等折叠机制，通过学习式指令压缩历史，但将记忆管理绑定为特定技能，限制了通用推理能力。这两种路线均未解决“何时压缩”与“压缩多少”的动态决策问题，导致在超长时域场景中性能急剧下降。

PACE 的切入点在于将上下文管理从独立的元认知任务解耦，重构为与决策过程同构的预测问题。借鉴 Transformer 中注意力机制动态加权输入 token 的原理，PACE 将历史交互块视为外部记忆存储，计算其对下一步动作的预测相关性，并据此动态调整信息粒度。这一范式转变使得上下文构建过程与智能体的决策循环同步，无需额外的学习式折叠指令，从而在保持模型通用推理能力的同时，实现了对长时域任务的自适应管理。

## 核心方法

### 方法参照系

现有智能体上下文管理遵循“存储-检索-组装”流程，通常采用固定窗口截断或静态摘要策略。本文的关键差异在于将检索环节从基于规则的静态匹配升级为基于预测的动态注意力评分，并将组装环节从固定粒度替换为压力自适应的多粒度选择，从而实现了上下文构建与决策过程的深度耦合。

### 预测性注意力评分

传统方法在检索历史时依赖时间邻近性或简单关键词匹配，无法捕捉语义层面的动态相关性。PACE 引入低温度 Softmax 机制，将历史块与当前查询的余弦相似度转化为尖锐的概率分布，确保仅高相关块获得显著权重。该设计解决了静态检索在长序列中因分布平坦化导致的关键信息淹没问题。

$$ w_i = \frac{\exp(s_i / \tau)}{\sum_{j=1}^{M} \exp(s_j / \tau)} $$

其中 $s_i$ 为历史块 $i$ 与当前查询的余弦相似度，$\tau=0.3$ 为低温度参数。该公式通过指数放大差异，使权重分布高度集中于最相关块，其余块权重趋近于零，为后续粒度选择提供清晰的信号。

### 压力自适应粒度选择

固定阈值策略在任务初期与末期表现不一致：初期历史少，阈值过严导致信息丢失；末期历史多，阈值过松导致窗口溢出。PACE 引入压缩压力 $P_t$，动态调整粒度阈值，使压缩强度随任务进展与窗口占用率自动增强。该设计解决了静态策略在长时域中无法平衡信息保留与计算效率的矛盾。

$$ P_t = \max\left(\frac{t}{T_{max}}, \frac{|C_{t-1}|}{B_{max}}\right) $$

其中 $T_{max}$ 为任务预期最大长度，$B_{max}$ 为 token 预算。压力值 $P_t$ 驱动阈值 $\alpha_t, \beta_t, \gamma_t$ 线性增长，迫使更多历史块降级为简要摘要或占位符，实现压缩强度的自适应调节。

## 实验评估

实验在 GAIA、BrowseComp 等六个基准上评估了 WebSailor-32B、tongyi-deepresearch-30B 等四个模型，基线包括 ReAct、Summary Agent 与 Folding Agent。基线覆盖静态截断、累积摘要与学习式折叠三类主流路线，但缺失 RAG 与递归推理基线，无法排除检索增强或任务分解带来的性能增益。

| 模型 | 方法 | GAIA | xbench-DR |
| :--- | :--- | :--- | :--- |
| tongyi-deepresearch-30B | ReAct Agent | 64.6 | 69.0 |
| tongyi-deepresearch-30B | Folding Agent | 72.4 | 77.0 |
| tongyi-deepresearch-30B | PACE | 74.0 | 81.0 |
| Claude-4-Sonnet | ReAct Agent | 65.2 | 62.0 |
| Claude-4-Sonnet | Folding Agent | 70.1 | 69.0 |
| Claude-4-Sonnet | PACE | 76.4 | 72.0 |

PACE 在 GAIA 上较 Folding Agent 提升 1.6 个百分点，在 xbench-DR 上提升 4.0 个百分点，表明预测性机制在复杂深度研究任务中优势更显著。

| 配置 | BrowseComp | GAIA |
| :--- | :--- | :--- |
| PACE (Full) | 47.6 | 74.0 |
| w/o Multi-gran. | 42.3 | 68.5 |
| w/o Pressure | 43.9 | 70.9 |
| w/o Softmax | 43.1 | 69.3 |

移除多粒度表示导致性能下降 5.3-8.3%，降幅最大，证实灵活粒度是核心贡献；移除低温度 Softmax 导致下降 4.7-7.5%，表明分布锐化对识别相关块至关重要。压力自适应机制移除后性能接近 Summary Agent，说明其在特定任务特性下具有条件依赖性。

评估协议未报告置信区间，且超参数如 $\tau=0.3$ 与 $\lambda=0.5$ 未提供敏感性分析。代码未公开，BGE-M3 嵌入模型与 Gemini 2.5 Flash-Lite 摘要模型的版本锁定信息缺失，限制了可复现性。

## 关联研究分析

从问题动机看，PACE 与 MemGPT 均旨在突破固定窗口限制，但 MemGPT 采用操作系统启发的分页机制，将上下文管理视为资源调度问题，而 PACE 将其视为预测问题。MemGPT 的分页策略依赖预定义的页大小与换入换出规则，缺乏对任务语义的动态感知；PACE 的预测性评分则直接关联下一步动作，使得记忆选择与决策目标对齐。这一差异源于任务特性：MemGPT 面向对话历史管理，强调状态一致性；PACE 面向智能体任务执行，强调决策相关性。

从方法设计看，PACE 与 AgentFold 均涉及历史压缩，但 AgentFold 通过微调模型生成显式“折叠”指令，将记忆管理内化为模型技能；PACE 则通过外部向量相似度评分实现无监督压缩，保持模型通用性。AgentFold 的折叠指令依赖特定训练数据，泛化性受限；PACE 的 BGE-M3 嵌入模型支持多语言，无需额外微调。然而，PACE 的预测机制假设语义相似度可替代逻辑依赖，对于需要多跳推理的任务，向量相似度可能无法捕捉深层因果链，这一局限在论文中未得到验证。

## 总结

PACE 解决的核心矛盾是长时域智能体中上下文窗口有限性与信息完整性需求之间的冲突。现有方法将记忆管理视为独立任务，导致决策与记忆操作耦合，而 PACE 通过重构为下一步预测问题，实现了上下文构建与决策过程的同步。该框架通过预测性注意力评分与压力自适应粒度选择，在超长时域任务中实现了 4,897 步的有效推理，较 ReAct 基线提升 66.2 倍。然而，实验仅验证了任务成功率与操作寿命，未评估预测机制对复杂逻辑链的捕捉能力，且缺失 RAG 基线对比。当任务涉及多跳因果推理时，向量相似度评分是否足以替代显式逻辑推导，论文未给出回答。
