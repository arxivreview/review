# ACL2026最新论文 ｜COMPASS: Enhancing Agent Long-Horizon Reasoning with Evolving Context ｜长时域智能体的战略推理与上下文管理

研究机构：美国弗吉尼亚大学

作者：Guangya Wan、Mingyang Ling、Xiaoqi Ren 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.08790)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.08790)

> 导读 长时域任务（Long-Horizon Tasks, LHT）要求智能体在多步工具交互中维持战略连贯性，但现有单智能体系统受限于统一上下文窗口，易因历史轨迹累积导致关键证据淹没与注意力稀释。多智能体系统虽通过角色分离缓解此问题，却依赖人工设计的协调流程，缺乏可扩展性。本文提出 COMPASS 框架，将战术执行、战略监督与上下文组织解耦为三个异步协作组件，通过动态刷新上下文与外部战略信号注入，实现无需人工干预的长时域推理。该架构在 BrowseComp 等基准上显著提升了单智能体性能，逼近顶级闭源模型，但其战略监控的实时性与专用上下文模型的泛化边界仍需进一步验证。

## 研究背景

当智能体面对需要数十步工具调用的复杂查询时，其内部状态随执行轨迹线性增长。这种动态上下文 $C_t^{dyn}$ 的无限膨胀导致早期关键约束被后期冗余输出淹没，引发“中间迷失”现象，使模型在长轨迹中忽略初始目标或陷入局部错误循环。为应对此困境，单智能体系统（Single-Agent Systems, SAS）如 ReAct 范式通过 Think-Act-Observe 循环维持端到端控制，但其统一上下文窗口在长时域下必然面临截断或权重失衡。多智能体系统（Multi-Agent Systems, MAS）通过规划、执行与反思角色的物理隔离来分散上下文压力，然而其协调机制多依赖人工设计的消息传递或层级控制，难以适应动态变化的推理状态。

当前长上下文研究多聚焦于静态文档理解中的位置编码改进或稀疏注意力机制，忽视了动态交互轨迹中“战略推理”与“战术执行”的解耦需求。战术推理关注单步工具调用的准确性，而战略推理需跨步监控异常、决定何时修正计划或终止搜索。现有方法要么将二者混同于单一模型内部，导致反思流于表面；要么通过复杂的多智能体拓扑实现，引入高昂的协调开销。如何在保留单智能体简洁性与自主性的同时，赋予其类似多智能体的显式战略监控与结构化上下文管理能力，成为长时域智能体可靠运行的关键瓶颈。

## 核心方法

### 方法参照系：战术与战略的解耦架构

COMPASS 将长时域推理建模为双循环结构：内循环为战术执行，外循环为战略监督。与传统 ReAct 仅依赖内部思维链不同，COMPASS 引入外部组件显式管理上下文与决策。其核心假设是，战略监控应独立于执行轨迹，通过异步信号干预而非阻塞式等待来维持推理连贯性。该架构将上下文视为可动态重构的资源，而非仅随时间累积的日志。

### 战略监控与异步干预机制

传统单智能体在检测到错误时往往依赖内部自我反思，易受当前错误上下文污染。COMPASS 引入 Meta-Thinker 组件，独立于 Main Agent 运行，专门负责战略推理。Meta-Thinker 不直接参与工具调用，而是监控 Main Agent 的轨迹 $T_t$，检测如循环行为、工具误用或任务完成信号等异常。一旦触发，它发出高层战略信号 $decision_t$（如“重新规划”或“验证”），该信号不阻塞 Main Agent 的当前执行，而是作为下一轮上下文合成的输入。这种异步设计避免了战略监控延迟对执行流畅性的影响，同时通过外部视角打破内部错误锚定。

### 动态上下文合成与结构化笔记

Main Agent 的执行依赖于 Context Manager 提供的精简上下文 $x_t$。Context Manager 并非简单截断历史，而是从三个来源合成新上下文：持久化结构化笔记 $n_t$、当前推理轨迹 $T_t$ 以及 Meta-Thinker 的战略信号 $decision_t$。其合成过程可形式化为：

$$
x_{t+1} = \text{SynthesizeContext}(q, T_t, n_t, decision_t)
$$

其中 $q$ 为初始查询。该公式表明，新上下文是初始目标、当前进展、历史摘要与战略指令的加权融合。Context Manager 随后将关键观察（如已验证事实、失败尝试）提取并追加至笔记存储 $n_{t+1}$，确保长期连贯性。这种机制将无限增长的动态上下文压缩为有界、结构化的状态表示，使 Main Agent 始终在聚焦且无冗余的环境中执行战术推理。

## 实验评估

实验在 GAIA、BrowseComp 和 Humanity’s Last Exam (HLE) 三个长时域基准上进行，主要评估指标为 Pass@1 准确率。基线覆盖单智能体（含工具增强）、多智能体（层级/去中心化）及迭代优化流程。COMPASS 在 Gemini 2.5 Pro 骨干上，BrowseComp 准确率达 35.4%，显著高于单智能体基线 16.8% 和多智能体基线 31.8%。在 GAIA 上，COMPASS 取得 67.8%，略高于 DeepResearch (o3) 的 67.4%。COMPASS-TTS 通过并行采样进一步将 BrowseComp 提升至 43.7%，GAIA 提升至 72.1%。

| 方法 | 骨干模型 | BrowseComp (%) | GAIA (%) | HLE (%) |
| :--- | :--- | :--- | :--- | :--- |
| Single-Agent (Search+Browse) | Gemini 2.5 Pro | 16.8 | 58.6 | 14.8 |
| Multi-Agent (Agent-as-a-Tool) | Gemini 2.5 Pro | 31.8 | 65.5 | 28.6 |
| **COMPASS** | **Gemini 2.5 Pro** | **35.4** | **67.8** | **31.7** |
| DeepResearch (o3) | o3 | 51.1 | 67.4 | 26.6 |
| **COMPASS-TTS** | **Gemini 2.5 Pro** | **43.7** | **72.1** | **35.2** |

消融实验显示，移除 Meta-Thinker 导致 BrowseComp 准确率从 35.4% 骤降至 15.2%，且战略指标（如 Pivot Recognition）接近零，证实了外部战略监控对避免“盲目坚持”的关键作用。移除 Context Manager 则导致 Token 消耗激增且准确率降至 26.4%，表明结构化上下文压缩对维持长时域效率不可或缺。Context-12B 专用模型在保持与 Gemini 2.5 Flash 相当性能的同时，仅使用 70% 的 Token，验证了上下文管理任务可通过蒸馏实现高效部署。

评估边界方面，实验未对比基于强化学习（RLVR）的长上下文推理方法，且战略指标依赖 LLM-as-a-Judge 评估，可能存在评估偏差。代码未开源，复现依赖特定 Gemini API 版本。

## 关联研究分析

从问题动机看，COMPASS 与 Recursive Language Models (RLM) 均旨在突破固定上下文窗口限制，但路径截然不同。RLM 通过递归分解将长提示视为外部环境，由模型编程调用自身处理子片段，本质是任务分解；COMPASS 则保持单智能体端到端结构，通过上下文压缩与外部监控维持状态，本质是状态管理。RLM 在处理超长输入时更具扩展性，但引入子任务分解错误累积风险；COMPASS 在中等长度长时域任务中更稳定，但受限于单智能体推理能力上限。

从方法设计看，COMPASS 的 Context Manager 与 MemGPT 的分页机制功能相似，均涉及历史信息的存取与压缩。然而，MemGPT 侧重于虚拟内存式的被动存储管理，而 COMPASS 的 Context Manager 是主动的、战略信号驱动的上下文合成器。MemGPT 缺乏显式的战略监控组件，其上下文更新主要依赖当前查询相关性；COMPASS 则通过 Meta-Thinker 注入“重新规划”等高层指令，使上下文管理具备目标导向性。这种差异源于 COMPASS 对长时域任务中“战略漂移”问题的针对性设计，而 MemGPT 更关注对话历史的无限扩展。

## 总结

COMPASS 针对长时域智能体中战术执行与战略推理耦合导致的上下文腐烂与错误累积问题，提出了一种轻量级分层架构。通过将战略监控与上下文管理外化为异步组件，COMPASS 在 BrowseComp 上将单智能体准确率从 16.8% 提升至 35.4%，并在 GAIA 上超越部分多智能体基线。其核心贡献在于证明了显式角色分离可在不牺牲单智能体自主性的前提下提升长时域可靠性。然而，该框架依赖 Gemini 2.5 Pro 等强骨干模型，且 Meta-Thinker 的异步监控在极端快速变化的环境中可能存在信号滞后。当任务分布显著偏离训练数据时，基于提示工程的战略监控是否仍能保持鲁棒性，论文未给出回答。
