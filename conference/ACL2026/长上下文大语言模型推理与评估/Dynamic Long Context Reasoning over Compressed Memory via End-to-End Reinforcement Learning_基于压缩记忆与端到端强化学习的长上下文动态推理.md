# ACL2026最新论文 ｜Dynamic Long Context Reasoning over Compressed Memory via End-to-End Reinforcement Learning ｜基于压缩记忆与端到端强化学习的长上下文动态推理

研究机构：哈尔滨工业大学

作者：Zhuoen Chen、Dongfang Li、Meishan Zhang 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.08382)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.08382)

> 长上下文处理面临计算复杂度与推理深度的双重瓶颈，现有稀疏注意力、检索增强生成（RAG）及递归架构均在效率与能力间存在显著权衡。LycheeMemory 借鉴人类记忆机制，将长文本压缩为 KV-cache 表示存入长期记忆，并通过门控机制动态筛选相关块进行迭代推理。该方法通过联合强化学习优化压缩与推理模块，在 1.75M tokens 规模下实现了精度与效率的平衡，但其对短上下文精度的牺牲及门控机制在分布外数据上的泛化能力仍存疑。

## 研究背景

当模型处理百万级 token 的文档时，自注意力机制的二次方计算复杂度导致显存溢出，而简单的截断或摘要策略会破坏多跳推理所需的逻辑依赖。这种困境源于长序列中信息密度的稀释：随着上下文长度增加，关键证据被大量无关文本淹没，导致模型在定位与整合信息时出现“中间迷失”现象。为应对此问题，研究界发展出稀疏注意力、RAG 及递归架构等路线，但前者在超长序列上性能急剧下降，RAG 因将文本块视为独立实体而切断语义连贯性，递归架构则受限于串行状态更新的低效性。

长上下文领域的核心矛盾在于名义窗口长度与有效推理能力的脱节。主流方法如 MemAgent 虽通过递归调用突破窗口限制，但缺乏对无关信息的过滤机制，导致推理延迟随上下文长度线性增长。LycheeMemory 的切入点在于引入“压缩记忆”与“动态门控”的组合：通过压缩降低存储与计算开销，通过门控实现状态依赖的选择性召回，从而在保持多跳推理完整性的同时，显著降低长上下文处理的边际成本。

## 核心方法

### 方法参照系

LycheeMemory 属于记忆增强型长上下文处理框架，其标准流程通常包含外部记忆存储与检索两个阶段。与 MemGPT 等基于文本摘要的记忆系统不同，本文采用隐式向量存储（KV-cache 表示），并将记忆更新过程建模为可优化的离散动作空间，从而引入强化学习（RL）进行端到端优化。

### 压缩记忆构建

传统 RAG 直接存储原始文本块，导致检索时仍需处理大量冗余 token。LycheeMemory 引入 Compressor 模块，将每个文本块 $C_i$ 映射为紧凑的潜在表示 $\theta_i$。具体而言，通过插入可训练的记忆 token $V_i$ 并与原始 token 交错，利用基础模型 $\Phi$ 的前向传播将语义信息嵌入记忆 token 的隐藏状态中。该设计解决了原始文本存储导致的计算冗余问题，使得记忆库 $\Theta = \{\theta_1, \dots, \theta_K\}$ 在保持语义保真度的同时，大幅降低了后续推理阶段的输入长度。

$$ \theta_i = \text{HiddenState}_{\text{mem}}(\Phi_{\text{comp}}(C_i' \mid V_i)) $$

此公式表明，压缩表示 $\theta_i$ 并非简单的特征提取，而是通过模型内部状态对原始文本进行语义聚合，为后续的动态召回提供高密度信息载体。

### 动态门控与迭代推理

MemAgent 等递归架构对所有文本块进行强制更新，导致无关信息干扰推理路径。LycheeMemory 引入 Gate 模块作为状态依赖的相关性过滤器，其输入包含当前工作记忆 $\mathbf{m}_t$、用户查询 $Q$ 及候选记忆块 $\theta_i$。Gate 输出一个相关性概率 $P$，仅当 $P > \tau$ 时，Reasoner 才更新工作记忆：

$$ \mathbf{m}_{t+1} = \Phi_{\text{reason}}(\mathbf{m}_t, \theta_i, Q) \quad \text{if} \quad P(\theta_i \mid \mathbf{m}_t, Q) > \tau $$

该机制解决了全序列盲处理导致的注意力稀释问题，通过选择性更新确保工作记忆仅包含与当前推理状态相关的证据，从而支持跨多个记忆块的多步推理。

## 实验评估

实验在 RULER-HQA、2WikiMultihopQA 及 StreamingQA 上进行，基线涵盖 MemAgent、Search-R1 及多种长上下文 LLM。LycheeMemory-7B 在 1.75M tokens 下保持 71.09% 的 sub-EM 准确率，显著优于 QwenLong-L1-32B 的 OOM 状态及 DS-Distill-Qwen-32B 的 7.03%。

| 模型 | 7K | 112K | 1.75M |
| :--- | :--- | :--- | :--- |
| QwenLong-L1-32B | 72.66 | 31.25 | OOM |
| DS-Distill-Qwen-32B | 70.31 | 23.44 | OOM |
| MemAgent-7B | 82.03 | 79.69 | 75.78 |
| LycheeMemory-7B | 77.34 | 75.78 | 71.09 |

消融实验显示，移除 Gate 模块后，112K 上下文下的准确率从 75.78% 提升至 80.47%，但推理速度降低 3.5 倍。这表明 Gate 以约 4.7% 的精度损失换取了显著的效率提升，验证了其在超长上下文场景下的必要性。

评估协议主要依赖 sub-EM 指标，未报告置信区间，且缺乏对分布外（OOD）数据的系统性测试。代码未公开，超参数细节仅部分披露，限制了结果的直接复现性。

## 关联研究分析

从方法设计看，LycheeMemory 与 MemAgent 的核心差异在于记忆表示与更新策略。MemAgent 基于原始文本的递归调用，缺乏对无关信息的过滤，导致推理延迟随上下文线性增长；LycheeMemory 通过 KV-cache 压缩与 Gate 门控，将更新操作限制在相关块上，实现了近常数时间的推理效率。这一差异源于任务特性：长文档中无关信息占比极高，强制更新会引入噪声，而选择性召回则能维持推理路径的纯净性。

从问题动机看，LycheeMemory 与 RAG 路线形成互补。RAG 依赖静态语义相似度检索，难以捕捉多跳推理中动态变化的证据相关性；LycheeMemory 的 Gate 模块以工作记忆为条件，实现了状态依赖的动态检索。然而，Gate 的二分类训练是否足以应对复杂多跳推理中证据相关性的非线性变化，论文未给出充分验证。

## 总结

LycheeMemory 旨在解决长上下文处理中计算效率与推理深度的矛盾，通过压缩记忆与动态门控的组合，实现了在 1.75M tokens 规模下的有效推理。其核心贡献在于将记忆更新过程建模为可优化的离散动作空间，并通过端到端强化学习联合优化压缩与推理模块。实验表明，该方法在超长上下文下保持了 71.09% 的准确率，较 MemAgent 提速 6 倍。然而，Gate 模块在短上下文下导致的精度下降（约 4.7%）及其在分布外数据上的泛化能力，仍是该方法面临的主要局限。当上下文长度进一步扩展至十亿级 token 时，压缩表示的信息保真度与门控机制的决策鲁棒性之间是否存在不可调和的冲突，论文未给出回答。
