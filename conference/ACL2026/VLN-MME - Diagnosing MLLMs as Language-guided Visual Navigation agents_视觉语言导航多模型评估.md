# ACL2026最新论文 ｜VLN-MME: Diagnosing MLLMs as Language-guided Visual Navigation agents ｜视觉语言导航多模型评估

作者：Xunyi Zhao、Gengze Zhou、Qi Wu

论文原文见 [arXiv](https://arxiv.org/abs/2512.24851)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2512.24851)

> 具身智能体在连续三维空间中执行导航任务时，多模态大语言模型（MLLM）的推理能力与空间感知能力常被高估，现有评估框架因依赖高保真模拟器且固定智能体架构，导致无法区分模型内在缺陷与工程策略失效。本文提出 VLN-MME，通过模块化解耦模型、智能体与任务，并采用无模拟器预渲染管线，实现零样本 MLLM 导航能力的细粒度诊断。该框架揭示了 MLLM 在具身导航中存在的“感知-动作断裂”及思维链（CoT）推理的负迁移现象，为后续针对性后训练提供了诊断依据，但其离散图评估协议对连续环境几何接地能力的覆盖仍存疑。

## 研究背景

当 MLLM 被部署为具身导航智能体时，其面临的核心挑战并非单纯的视觉识别，而是在动态视角变化中维持长时程空间记忆并执行序列决策。这一过程要求模型不仅理解指令语义，还需将视觉感知接地为具体的低层动作，任何历史信息的遗忘或空间推理的偏差都会导致智能体陷入局部循环。然而，现有评估体系多依赖 Matterport3D 或 Habitat 等高保真模拟器，其高昂的计算开销使得大规模模型对比变得低效，且固定智能体设计掩盖了模型推理能力与提示工程策略之间的边界。

主流零样本导航方法如 NavGPT 和 MapGPT 虽验证了 LLM 的潜力，但其评估往往聚焦于端到端成功率，缺乏对失败模式的细粒度归因。NavBench 等近期基准虽试图标准化流程，但受限于单一智能体架构，无法解耦模型内在能力与外部规划策略的贡献。本文切入点在于构建一个模块化、无模拟器的评估框架，通过独立替换模型、记忆机制与推理策略，精准定位 MLLM 在具身导航中的具体认知短板，从而区分是模型空间推理不足还是智能体工程设计缺陷。

## 核心方法

### 模块化评估架构

现有 VLN 评估通常将模型、智能体逻辑与环境耦合在单一模拟器中，导致无法进行组件级消融。本文将其置于通用具身智能评估框架下，关键差异在于引入工厂模式（Factory Pattern）实现 Model、Agent、Task 三者的正交解耦。这种设计允许在保持导航语义不变的前提下，独立替换骨干网络或记忆策略，从而隔离变量以诊断性能瓶颈。

### 无模拟器空间-时间交换

传统管线依赖实时 GPU 渲染，造成 VRAM 占用高且单步延迟大。本文采用预渲染图像替代实时几何渲染，通过磁盘 I/O 读取缓存视角，实现了“空间换时间”的效率提升。该策略将显存需求从 $\sim 10$ GB 降至 $\sim 1.7$ GB，观测访问速度提升 8.8 倍。其物理含义是用存储冗余换取计算实时性，使得消费级硬件即可运行大规模 MLLM 评估，消除了硬件壁垒对实验可复现性的限制。

### 细粒度错误诊断与记忆解耦

针对 MLLM 在长程导航中易陷入循环的问题，本文设计了文本摘要与拓扑地图两种记忆机制，并引入 CoT 与反思推理变体。通过对比不同记忆负载下的表现，发现复杂拓扑地图并未显著提升性能，反而可能增加认知负荷。其核心公式可表示为智能体动作 $a_t$ 由观测 $o_t$、历史记忆 $M_t$ 及推理策略 $\pi$ 共同决定：

$$ a_t = \pi(o_t, M_t, \text{Instruction}) $$

这一设计动机在于验证显式空间记忆是否真正解决了长时程依赖问题，而非仅作为信息容器。实验表明，简单的文本摘要记忆在部分场景下优于复杂地图，暗示 MLLM 对结构化空间信息的利用能力有限，更依赖于即时视觉输入与指令的直接映射。

## 实验评估

实验基于 R2R、REVERIE 和 ObjectNav 的验证未见集子集，对比了 GPT-5、Gemini-2.5 Pro、Qwen2.5-VL-7B 等六个 MLLM 在八种智能体配置下的表现。基线覆盖了 NavGPT 与 MapGPT 的典型架构，但缺乏与微调专用模型（如 DUET）的直接同协议对比，主要聚焦于零样本场景下的相对性能。

| 方法 | 任务 | SR (%) | SPL (%) |
| :--- | :--- | :--- | :--- |
| Qwen2.5-VL-7B (NavGPT) | Fine-Grained | 27.50 | 17.11 |
| Qwen2.5-VL-7B (NavGPT w/ CoT) | Fine-Grained | 21.00 | 11.41 |
| Qwen2.5-VL-7B (MapGPT) | Fine-Grained | 26.00 | 17.31 |
| GPT-5 (NavGPT) | Fine-Grained | 38.07 | 22.43 |

数据表明，Qwen2.5-VL-7B 在细粒度导航中 SR 为 27.50%，而引入 CoT 后降至 21.00%，证实了推理策略的负迁移效应。GPT-5 虽保持最高性能，但各开源模型间差异显著，Qwen2.5-VL-7B 表现优于 LLaVA-OneVision 和 InternVL3-2B，成为开源基线的首选。

消融实验显示，记忆机制的选择对性能影响小于预期，InternVL3-2B 在粗粒度任务中从文本摘要的 7.33% SR 提升至拓扑地图的 12.00%，但大模型如 Qwen2.5-VL-7B 在两种记忆下差异微小。这反驳了“显式地图必然提升长程导航性能”的共识，暗示 MLLM 的空间瓶颈在于感知-动作接地而非记忆容量。此外，在“Hard Negatives”子集上，引入 Oracle 辅助将 SR 从 0.00% 提升至 52.00%，而仅增加失败案例的少样本提示仅提升至 16.00%，证明高层推理支持比单纯的模式匹配更有效。

评估协议采用离散图导航，未涉及连续环境中的碰撞与运动学约束，可能高估了真实部署性能。指标涵盖 SR、SPL、nDTW 等，但未报告置信区间，数值比较需谨慎。代码与预渲染资产已开源，支持单卡 A100 复现，但缺乏对动态障碍物或光照变化的鲁棒性测试。

## 关联研究分析

从问题动机看，本文与 NavBench 同属标准化评估范畴，但 NavBench 聚焦于统一任务协议，而 VLN-MME 强调组件解耦以诊断模型缺陷。NavBench 的固定智能体设计使得无法区分模型推理能力与提示工程贡献，而 VLN-MME 通过模块化架构实现了这一解耦，其根源在于评估目标从“性能排名”转向“能力诊断”。这种差异源于任务特性：零样本 MLLM 的失败模式高度依赖智能体设计，固定架构会掩盖模型内在的空间推理短板。

从方法设计看，本文与 MapGPT 共享拓扑地图记忆思路，但 MapGPT 将其作为固定组件，而 VLN-MME 将其作为可替换模块进行消融。MapGPT 假设显式地图能增强全局规划，而本文实验发现复杂地图可能增加认知负荷，导致性能未显著提升。这一冲突暗示 MLLM 对结构化空间信息的利用存在瓶颈，可能源于预训练数据中缺乏具身导航的细粒度空间推理样本，而非地图表示本身的问题。

## 总结

本文旨在解决 MLLM 在具身导航中评估不透明的问题，通过模块化无模拟器框架解耦模型与智能体，揭示了 CoT 推理的负迁移及感知-动作断裂现象。实验证明 Qwen2.5-VL-7B 在细粒度导航中 SR 为 27.50%，而 Oracle 辅助可将其提升至 52.00%，表明失败主要源于规划缺陷而非感知局限。其边界在于离散图评估未覆盖连续环境的几何约束，且缺乏与微调模型的直接对比。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
