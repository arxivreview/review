> 现有智能体评估基准普遍依赖预打包工具与干净输入，导致实验室分数高估真实部署性能。AgentGym2 通过构建包含噪声、歧义及工具发现需求的非模拟环境，量化了智能体在开放动作空间下的端到端执行能力。其核心贡献在于将评估焦点从“给定工具下的推理”转向“未知环境下的探索与组合”，揭示了当前 SOTA 模型在真实世界任务中的显著短板。尽管该基准有效暴露了模型在工具发现与去噪方面的弱点，但其对长时程状态漂移的覆盖仍受限于 100 轮交互上限。

## 研究背景

智能体评估的核心困境在于环境假设与真实部署场景的错位。传统基准如 AgentBench 和 τ-bench 通常提供预定义的工具接口和明确的任务指令，这种“理想化”设置使得智能体只需关注推理与规划，而无需处理信息缺失或工具不可用等现实约束。当智能体进入生产环境，用户请求往往模糊不清，必要工具可能未预先配置，且信息来源充满噪声。这种从“封闭世界”到“开放世界”的范式转变，要求评估体系必须涵盖工具发现、目标澄清及鲁棒性处理等此前被忽略的能力维度。

主流评估路线在解决碎片化问题的同时，加剧了环境的静态性。AgentCompass 和 Holistic Agent Leaderboard 致力于统一基础设施以提升可比性，但其底层任务仍多基于模拟环境或预清洗数据。MASEval 揭示了框架对性能的影响，却未深入探讨环境本身的复杂性如何干扰模型能力。现有方法普遍假设工具集是已知且固定的，这导致评估结果无法反映智能体在动态、非结构化环境中的真实表现。AgentGym2 的切入点在于打破“工具预知”假设，通过引入基础可组合工具箱和去理想化任务实例，强制智能体在交互中主动探索工具边界并处理不确定性，从而建立更贴近生产部署的评估标准。

## 核心方法

### 方法参照系

AgentGym2 属于领域特定基准构建路线，但其核心差异在于环境非模拟性与动作空间开放性。与 AgentBench 等提供专用接口的基准不同，AgentGym2 仅提供基础工具集，要求智能体通过交互发现并组合工具，以解决端到端任务。

### 基础可组合工具箱

传统基准为每个任务预配置专用工具，导致智能体无需探索即可调用。AgentGym2 改为提供覆盖网页浏览、信息检索、文件处理、多模态理解及代码执行五大类的基础工具箱，支持超过 27 种动作。这种设计将动作空间从“任务特定”扩展为“通用基础”，迫使智能体在运行时识别可用工具并学习其用法。其评估目标可形式化为：给定基础工具集 $\mathcal{T}_{base}$ 和任务 $g$，智能体需通过交互轨迹 $\tau$ 发现并组合 $\mathcal{T}_{base}$ 中的元素以达成 $g$，其中 $\mathcal{T}_{used} \subseteq \mathcal{T}_{base}$ 且 $\mathcal{T}_{used}$ 非预先指定。这一机制量化了智能体在未知环境下的工具发现与组合能力，解决了预打包工具导致的能力高估问题。

### 去理想化任务构造

针对真实场景中用户指令模糊及信息噪声的问题，AgentGym2 构建了包含 437 个任务的基准，涵盖复杂工具使用、数据分析及深度搜索三类场景。深度搜索任务通过受控扰动注入歧义与偏差，例如在查询中混入记忆偏差导致的错误属性。任务有效性通过级联验证流程确保，结合模型检查与人工审查，验证任务可解性及答案唯一性。该设计将评估维度从“正确性”扩展至“鲁棒性”，即智能体在输入 $x$ 包含噪声 $n$ 时，仍能输出正确结果 $y$ 的概率 $P(y|x+n)$。通过模拟真实世界的信息不完美，该基准揭示了模型在去噪与目标澄清方面的具体失效模式，弥补了干净环境评估的盲区。

## 实验评估

| 模型 | 类型 | Avg@3 (Overall) | Pass@3 (Overall) |
| :--- | :--- | :--- | :--- |
| GPT-5 | 专有 | 46.15 | 65.68 |
| Claude-4.5-Sonnet | 专有 | 37.17 | 47.82 |
| Gemini-2.5-Pro | 专有 | 20.67 | 35.24 |
| Nex-N1-671B | 开源 | 32.19 | 48.52 |
| DeepSeek-V3.1 | 开源 | 21.66 | 40.27 |
| Qwen3-235B-A22B-Instruct | 开源 | 25.40 | 36.38 |

实验覆盖 15 个专有及开源模型，采用 ReAct 框架，温度 0.6，最大交互轮数 100。基线包含 GPT-5、Claude 等 SOTA 模型及 Nex-N1 系列开源模型，但缺乏专门针对工具发现优化的专用 Agent 基线。GPT-5 在 AgentGym2 上仅取得 46.15 的 Avg@3，显著低于其在理想化基准上的表现，验证了去理想化环境的挑战性。开源模型中，Nex-N1-671B 以 32.19 领先，但整体表现仍远低于专有模型，表明当前开源智能体在复杂真实任务中存在显著差距。

消融分析显示，模型规模与性能呈正相关，Qwen3 系列从 8B 到 235B 的性能从 8.70 提升至 25.40。然而，增加交互轮数未产生显著缩放效应，GPT-5 等顶级模型通常在 20-30 轮内完成任务。Agentic 后训练带来显著提升，Nex-N1-32B 较其基座模型 Qwen3-32B 提升 9.16 点，Nex-N1-671B 较 DeepSeek-V3.1 提升 10.5 点。错误分布分析表明，“分析错误”（24.0%）和“探索不足”（22.8%）是主要失败模式，揭示了推理能力与开放世界探索能力的双重短板。

评估协议采用 LLM-as-Judge，人机一致性达 98.9%，确保了结果可靠性。代码与数据已开源，支持复现。局限在于 100 轮交互上限可能掩盖长时程任务中的状态漂移问题，且未提供细粒度的工具发现成功率指标，仅通过整体任务成功率间接反映。

## 关联研究分析

从问题动机看，AgentGym2 与 MCP-AgentBench 均关注工具标准化，但前者侧重工具发现，后者侧重协议遵循。MCP-AgentBench 假设工具接口已知，评估重点在于智能体如何正确调用标准化工具；而 AgentGym2 假设工具未知，评估重点在于智能体如何从基础工具箱中识别并组合工具。这一差异源于任务特性的不同：MCP 场景下工具集相对固定，而 AgentGym2 模拟的是工具集动态变化的真实部署环境。AgentGym2 的设计更贴近生产环境，但可能因工具发现难度过高而过度增加非核心认知负担，导致评估结果偏向探索能力而非推理能力。

从方法设计看，AgentGym2 与 τ-bench 均涉及多轮交互，但环境开放性存在本质区别。τ-bench 提供固定 API 接口，智能体需在已知工具集下完成状态管理；AgentGym2 提供基础工具箱，智能体需在开放环境中探索工具边界。这种设计使得 AgentGym2 能捕捉到 τ-bench 无法覆盖的“工具执行失败”和“探索不足”等错误模式。然而，AgentGym2 未像 MASEval 那样解耦模型能力与框架效应，其固定使用 ReAct 框架可能混淆了模型内在能力与框架对工具调用的优化效果。若采用 Plan-and-Execute 等更复杂的框架，性能是否会显著提升，论文未给出回答。

## 总结

AgentGym2 旨在解决智能体评估中环境理想化与真实部署复杂性之间的矛盾。现有基准因预打包工具和干净输入而高估模型能力，AgentGym2 通过引入基础可组合工具箱和去理想化任务，强制智能体在开放动作空间中执行端到端任务。实验表明，GPT-5 在 AgentGym2 上仅取得 46.15 的 Avg@3，远低于其在理想化基准上的表现，揭示了当前 SOTA 模型在工具发现与去噪方面的显著短板。该基准的边界在于 100 轮交互上限可能掩盖长时程状态漂移问题，且未解耦模型能力与框架效应。当交互轮数增加至 500 轮时，智能体在长时程任务中的记忆失效与状态漂移是否成为主要瓶颈，论文未给出回答。
