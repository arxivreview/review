# ACL2026最新论文 ｜AgentRouter: A Knowledge-Graph-Guided LLM Router for Collaborative Multi-Agent Question Answering ｜知识图谱引导的多智能体问答路由

作者：Zheyuan Zhang、Kaiwen Shi、Zhengqing Yuan 等 9 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_d8172fe7befb)

> 固定下游任务中，不同大语言模型（LLM）智能体在特定查询上的表现存在显著差异，单一最优智能体无法覆盖所有输入。现有路由方法多聚焦于成本优化或粗粒度模型选择，忽略了问答任务中细粒度上下文结构对智能体协作权重的决定性作用。AgentRouter 将多智能体问答转化为知识图谱上的异构图神经网络（GNN）路由问题，通过实体级上下文建模学习软性协作分布。该方法在四个基准上超越了最佳单智能体与集成基线，但其性能增益是否完全源于图结构而非集成效应，仍需更严格的消融验证。

## 研究背景

多智能体问答系统通常由多个基于不同LLM骨干和提示策略的智能体组成，如思维链（Chain-of-Thought, CoT）与多智能体辩论（Multi-Agent Debate, MAD）。这些智能体在处理同一查询时，其输出质量分布往往宽泛且互不重叠，导致“最佳智能体”随查询类型和骨干模型变化而剧烈波动。这种异构性使得静态集成或单一模型选择策略失效，必须引入动态路由机制来实时调整智能体权重。

传统LLM路由研究主要解决成本-质量权衡问题，如FrugalGPT的级联策略或RouteLLM的偏好对齐，其核心假设是模型能力与成本呈单调关系。然而，在固定任务的智能体协作场景中，优化目标从成本最小化转向准确率最大化，且决策对象从单一模型扩展为智能体组合。GraphRouter（Feng et al., 2025）虽引入图结构，但将查询与上下文压缩为单节点，丢失了实体间的细粒度关系。AgentRouter 的切入点在于：问答任务的推理有效性高度依赖于上下文实体的语义关联，这些关联直接决定了何种推理策略（即智能体）最有效，因此路由决策必须建立在显式的上下文结构建模之上。

## 核心方法

### 方法参照系

多智能体路由的标准流程通常基于查询嵌入与智能体嵌入的相似度计算，或通过强化学习直接优化选择策略。本文问题与该通用流程的关键差异在于：路由决策不仅依赖查询语义，更依赖于查询与上下文实体之间的细粒度关系结构，且输出为软性权重分布而非硬选择。

### 知识图谱构建与异构表示

将问答实例转化为知识图谱是本文的基础创新，旨在解决传统方法忽略上下文内部结构的问题。图谱包含查询节点 $V_Q$、智能体节点 $V_A$ 和实体节点 $V_E$，其中实体节点通过 spaCy 管道从上下文中提取命名实体、时间表达式和数值提及。边类型包括查询-实体边、实体-实体边（通过依赖解析提取关系三元组）和智能体-实体边（通过提示智能体识别其关注的实体）。这种设计将静态语义结构与动态路由偏好解耦：冻结边捕获上下文锚点，可训练的查询-智能体边编码自适应路由信号。

$$
G = (V, E), \quad V = V_Q \cup V_A \cup V_E
$$

该公式定义了图谱的节点空间，确保查询、智能体和实体共享同一嵌入空间，使消息传递能够跨类型传播语义信息。

### 类型感知消息传递与软监督训练

在图谱基础上，RouterGNN 执行类型感知消息传递，以解决单节点表示无法捕捉实体间关系的问题。每个节点嵌入通过类型特定的投影算子 $Proj_\tau$ 更新，消息聚合采用均值池化，并通过可学习门控组合不同边类型的消息。路由分数由查询与智能体嵌入的拼接经多层感知机（MLP）计算，最终通过温度缩放 Softmax 生成软目标分布。训练目标为 KL 散度，而非交叉熵，以强制路由器对齐整个分布而非仅关注最优智能体。

$$
L_{KL}(q) = \sum_{a \in A} p^*(a | q) \log \frac{p^*(a | q)}{p_\theta(a | q, G)}
$$

该损失函数确保路由器不仅识别最佳智能体，还近似正确的互补智能体平衡，避免路由崩溃现象。

## 实验评估

实验在 HotpotQA、NewsQA、2Wiki 和 TriviaQA 四个基准上进行，基线包括最佳智能体、多数投票、LLM-Blender、HybridLLM 和 GraphRouter。缺失 RouteLLM、xRouter 等主流 LLM 路由基线，因其优化目标为成本而非准确率，与本文设置不匹配。

| 方法 | HotpotQA F1 | NewsQA F1 | 2Wiki F1 | TriviaQA F1 |
|---|---|---|---|---|
| Best Agent | 68.68±1.70 | 62.89±2.62 | 74.89±1.12 | 59.33±2.05 |
| GraphRouter | 61.73±0.76 | 64.95±0.33 | 64.09±0.13 | 52.37±1.26 |
| AgentRouter | 70.54±0.23 | 65.61±1.35 | 74.86±2.34 | 63.36±0.19 |

AgentRouter 在 HotpotQA 上 F1 达 70.54%，优于 Best Agent 的 68.68% 和 GraphRouter 的 61.73%。在 2Wiki 上，AgentRouter 与 Best Agent 持平（74.86% vs 74.89%），但在 NewsQA 和 TriviaQA 上显著领先。

限制路由器输出至 Top-K 智能体（K=3, 5, 10）产生最强性能，K=5 时在 HotpotQA 达 69.19%，K=3 时在 2Wiki 达 75.39%。这一反直觉发现表明，剪除低质量智能体尾部可减少方差，提升聚合精度。超参数分析显示，隐藏维度增大带来稳定增益，而层数增加不一定提升 F1，尤其在多跳数据集上可能出现负迁移。

评估指标仅包含 F1 和 EM，缺乏成本、延迟等效率维度。代码仓库已公开，训练使用 NVIDIA GeForce RTX 3090 GPU，隐藏尺寸 256，层数 2，学习率 $1 \times 10^{-4}$。

## 关联研究分析

从问题动机看，AgentRouter 与 GraphRouter 的核心差异在于上下文建模粒度。GraphRouter 将查询与上下文压缩为单节点，本质上是将路由问题简化为查询-模型匹配，忽略了实体间关系对推理策略选择的影响。AgentRouter 通过显式构建实体-实体边，使消息传递能够传播语义依赖，从而捕捉“何种实体关联需要何种推理策略”的细粒度信号。这一差异源于任务特性：多跳问答的有效性高度依赖于实体链的完整性，而单节点表示无法保留这种链式结构。

从方法设计看，AgentRouter 与 LLM-Blender 的差异在于决策机制。LLM-Blender 依赖 LLM 作为裁判进行启发式投票，其决策过程不可微且难以适应新输入分布。AgentRouter 通过可训练的查询-智能体边和 KL 散度监督，将路由决策转化为可优化的连续变量，使模型能够从经验性能信号中学习协作权重。这一设计解决了 LLM 裁判在长尾查询上泛化能力不足的问题，但引入了对 spaCy 实体提取准确性的依赖，其错误是否会导致路由偏差，论文未给出量化分析。

## 总结

AgentRouter 解决的核心矛盾是固定任务中智能体表现的查询依赖性，其切入点在于将上下文实体结构显式建模为知识图谱，使路由决策能够捕捉细粒度语义依赖。通过异构 GNN 消息传递和 KL 散度软监督，该方法在 HotpotQA 上 F1 达 70.54%，超越最佳单智能体 1.86 个百分点。其边界在于：Top-K 剪枝的增益可能部分源于集成效应而非路由精度，且缺乏成本维度评估，无法判断图结构建模的计算开销是否在生产环境中可接受。当智能体池规模扩大至百级时，知识图谱构建的稀疏性与消息传递的计算复杂度是否成为瓶颈，论文未给出回答。
