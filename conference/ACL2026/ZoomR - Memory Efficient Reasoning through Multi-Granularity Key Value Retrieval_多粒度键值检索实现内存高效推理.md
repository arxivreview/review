# ACL2026最新论文 ｜ZoomR: Memory Efficient Reasoning through Multi-Granularity Key Value Retrieval ｜多粒度键值检索实现内存高效推理

研究机构：美国伦斯勒理工学院、IBM研究院

作者：David H. Yang、Yuxuan Zhu、Mohammad Mohammadi Amiri 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.10898)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.10898)

> 长输出推理中，键值缓存（KV Cache）随生成序列线性增长，导致显存溢出与解码延迟激增。现有驱逐策略多针对预填充阶段的静态输入压缩，难以应对解码阶段动态生成内容的长程依赖丢失问题。ZoomR 通过微调模型生成段落级摘要，利用摘要键作为粗粒度索引，动态检索并加载关键细节段至 GPU，实现了显存与精度的平衡。该方法在 AIME2025 上接近全缓存性能，但牺牲了吞吐量，且依赖额外的微调步骤。

## 研究背景

自回归解码依赖 KV Cache 存储历史隐状态，其大小与序列长度成正比。当推理模型生成数万 Token 的思维链时，缓存占用往往超过模型参数本身，成为显存瓶颈。同时，注意力计算需读取全部历史 KV，导致每生成一个 Token 的计算量随序列长度线性增加，形成“计算-内存”双重压力。

主流 KV 优化路线分为两类：一是基于注意力稀疏性的动态驱逐（如 H2O），通过丢弃低重要性 Token 减少缓存，但 Token 级粒度易破坏语义连贯性，且无法预知未来 Token 的重要性；二是低比特量化（如 KIVI），通过压缩数值精度降低存储，但 Key 矩阵的通道级离群值导致低比特下精度损失严重。这两类方法均假设上下文结构相对静态，或仅关注预填充阶段的输入压缩。然而，在长输出推理中，生成内容的语义重要性随时间动态漂移，早期关键步骤可能在后期被后续推理反复引用，静态驱逐或均匀量化无法适应这种动态性。ZoomR 的切入点在于：将生成历史划分为“摘要”与“细节”两个粒度层级，利用摘要作为索引，仅在需要时“放大”至细节，从而在有限显存下保留长程依赖。

## 核心方法

### 方法参照系

ZoomR 属于动态 KV 缓存管理路线，但区别于 H2O 的 Token 级驱逐，其核心差异在于引入了“段落级摘要”作为中间表示，并采用 CPU-GPU 分层存储架构。标准流程中，缓存管理仅决定保留哪些 Token 的 KV 对；ZoomR 则决定保留哪些段落的“摘要 KV”与“细节 KV”，并通过动态加载实现多粒度上下文构建。

### 摘要生成与多粒度表示

设计动机：Token 级驱逐易碎片化语义，而纯摘要压缩会丢失细粒度推理所需的约束与中间结果。ZoomR 通过微调模型在每段推理后生成摘要，将历史上下文划分为正则段 $R_i$（原文）与摘要段 $S_i$（压缩表示）。摘要段被压缩为每个注意力头、每层的均值摘要键 $\bar{k}_i^{[l,h]}$，其计算为：

$$ \bar{k}_i^{[l,h]} = \frac{1}{|S_i|} \sum_{j \in S_i} k_j^{[l,h]} $$

该公式将一段文本的多个 Key 向量平均为一个代表向量，利用了短文本内 Key 向量的局部性，使得摘要键能高效表征段落语义。摘要键常驻 GPU，作为粗粒度索引；原文 KV 对则存储在 CPU，仅在需要时加载。

### 基于共识的动态检索

设计动机：单一注意力头的评分可能受局部偏差影响，需全局共识以识别真正重要的段落。ZoomR 在解码步 $t$ 时，利用当前查询向量 $q_t^{[l,h]}$ 与所有摘要键计算近似注意力分数，每个头投票选出 Top-$k$ 重要摘要。随后，聚合所有头与层的投票，选出得票最高的 $c$ 个摘要作为共识集 $I_c$。最终上下文由三部分构成：共识集对应的原文段 $R_i$（“放大”至细节）、非共识但被选中的摘要段 $S_i$（保留压缩表示）、以及静态的提示 Token 与最近窗口 Token。该机制实现了“按需放大”，仅在模型全局认为重要时才加载高成本细节，避免了全缓存的显存开销。

## 实验评估

| 模型 | 方法 | GPQA Diamond (%) | AIME2025 (%) | MATH500 (%) | 平均 (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Llama | Vanilla | 48.9 | 26.7 | 88.9 | 54.8 |
| Llama | H2O | 36.8 | 16.7 | 76.5 | 43.3 |
| Llama | ZoomR | 43.4 | 26.7 | 83.0 | 51.0 |
| Qwen | Vanilla | 49.0 | 30.0 | 92.5 | 57.2 |
| Qwen | H2O | 39.1 | 16.7 | 79.4 | 45.1 |
| Qwen | ZoomR | 42.8 | 23.3 | 87.8 | 51.3 |

实验在 Qwen2.5-7B 与 Llama-3.1-8B 上进行，基线包括 StreamingLLM、H2O 及简化版 SumR。ZoomR 在 AIME2025 上达到 26.7%（Llama）与 23.3%（Qwen），接近全缓存基线（26.7% 与 30.0%），显著优于 H2O（16.7%）。在 MATH500 上，ZoomR 保持 83.0% 与 87.8%，仅比全缓存低 5.9 与 4.7 个点。消融实验显示，ZoomR 比仅保留摘要的 SumR 平均提升 8% 准确率，证明“放大”细节的必要性。然而，ZoomR 的吞吐量低于全缓存，受限于 PCIe 带宽的 CPU-GPU 数据传输延迟。

评估边界方面，论文未报告 LongBench 等长上下文基准，且未与量化类方法（如 KIVI）对比。代码未开源，超参数（如 $c, k$）的敏感性分析仅通过图表展示，缺乏具体数值。实验仅在 H100 GPU 上进行，未验证在消费级 GPU 上的实际部署效果。

## 关联研究分析

从问题动机看，ZoomR 与 ThinKV 均针对长思维链的累积误差，但 ThinKV 侧重思维类型感知的量化精度分配，而 ZoomR 侧重空间分层检索。ThinKV 假设不同思维步骤具有不同的量化容忍度，通过混合精度存储所有 Token；ZoomR 则假设不同段落具有不同的访问频率，通过动态加载部分 Token。这一差异源于对“重要性”的定义不同：ThinKV 关注数值精度，ZoomR 关注语义访问。ZoomR 的段落级粒度可能牺牲 Token 级精度，导致细粒度推理失效，但论文未提供 Token 级错误分析。

从方法设计看，ZoomR 与 H2O 共享注意力评分机制，但 H2O 在解码步实时计算 Token 重要性，而 ZoomR 在语义边界（如句末）更新选择集，摊销了计算开销。这一设计降低了计算延迟，但可能错过句内关键 Token 的重要性变化。此外，ZoomR 依赖 LoRA 微调生成摘要，而 H2O 无需训练。微调步骤引入了额外成本，且摘要质量依赖基础模型能力，若基础模型摘要能力弱，ZoomR 的性能可能退化。

## 总结

ZoomR 旨在解决长输出推理中 KV Cache 显存溢出与长程依赖丢失的矛盾。其切入点在于利用人类记忆分层理论，将生成历史划分为摘要与细节两层，通过动态检索实现多粒度上下文构建。实验证明，ZoomR 在 AIME2025 上接近全缓存性能，同时节省超过 4 倍 GPU 显存。然而，其吞吐量受限于 CPU-GPU 传输延迟，且依赖额外的微调步骤。当生成序列长度进一步增加至 32K 以上时，摘要数量增长是否会导致共识投票的计算开销超过其显存节省收益，论文未给出回答。
