# ACL2026最新论文 ｜ASTRA: Adaptive Semantic Tree Reasoning Architecture for Complex Table Question Answering ｜自适应语义树推理架构

研究机构：浙江大学

作者：Xiaoke Guo、Songze Li、Zhiqiang Liu 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.08999)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.08999)

> 复杂表格问答的核心瓶颈在于二维拓扑结构向一维序列转换时的信息损耗，导致模型难以定位细粒度证据并执行可靠计算。现有线性化或规则树方法无法兼顾层级语义保留与结构灵活性，ASTRA 通过 LLM 全局语义感知重建逻辑语义树，并集成文本导航与符号执行双模推理来解决此矛盾。该方法在复杂表格基准上超越了纯推理模型，但其在非层级化交叉引用表格及视觉噪声场景下的泛化能力尚存疑。

## 研究背景

当 LLM 处理包含合并单元格和多级表头的复杂表格时，传统的 Markdown 或 HTML 序列化将二维空间关系扁平化为一维文本流，破坏了行列邻接关系。这种结构丢失导致模型无法准确定位特定单元格所属的语义层级，例如无法区分“Yukon-Percent”是独立属性还是“Sex of accused”下的子项。为解决此问题，表格序列化（Table Serialization）成为关键前置步骤，其目标是将结构化数据转换为 LLM 可理解的中间表示，但现有方法在保留显式层级与适应不规则布局之间存在根本冲突。

复杂表格问答（Complex Table QA）要求模型在深层嵌套结构中执行聚合与逻辑推断，这比扁平表格问答更具挑战性。主流路线分为两类：一是基于图或三元组的原子化表示（如 GraphOTTER），虽具 schema 灵活性但丢失了层级语义；二是基于物理布局的规则树构建（如 ST-Raptor），虽保留层级但依赖脆弱的启发式规则，面对格式变异时泛化能力差。ASTRA 的切入点在于利用 LLM 自身的语义理解能力替代规则引擎，通过自适应机制动态选择构建策略，从而在保留显式层级依赖的同时实现结构灵活性。

## 核心方法

### 方法参照系

本文问题属于表格结构表示重构路线，旨在解决 2D-to-1D 序列化中的结构丢失。与通用线性化流程不同，ASTRA 将表格视为具有内在语义层级的对象，而非单纯的文本序列，其核心差异在于引入“语义树”作为中间表示，并在此基础上执行双模推理。

### 自适应语义树重建（AdaSTR）

传统规则树构建依赖物理布局启发式，难以处理非标准表头。ASTRA 利用 LLM 挖掘隐藏语义组，将孤立属性锚定至实体上下文。设原始表格为 $T$，通过头标识与归一化模块得到归一化头列表 $H_{norm}$，进而通过层级识别模块生成层级定义 $D_{hier}$。

$$ T_{\tilde} = \tau(T) = \text{TreeSynthesize}(T, D_{hier}, \text{Mode}) $$

其中 $\text{Mode} \in \{\text{DSP, SRE, PSS}\}$ 根据表格规模与 token 密度自适应选择。DSP 模式直接生成完整树；SRE 模式使用坐标占位符压缩冗长内容；PSS 模式生成循环脚本实例化大规模重复结构。此设计解决了规则树在异构表格上的脆弱性，通过语义抽象而非物理规则保留层级依赖。

### 双模树推理（DuTR）

纯文本推理在数值聚合任务中易产生幻觉，而纯符号执行缺乏语义上下文。DuTR 将语义树同时作为可导航文本语料和结构化代码对象。文本推理模块通过自适应遍历策略（Leaf-to-Root 或 Root-to-Leaf）筛选证据路径 $C$：

$$ C = \text{Navigate}(T_{\tilde}, Q, \text{Strategy}) $$

符号推理模块将树抽象为结构骨架，生成 Python 代码在沙箱中执行，若出错则触发自我修正循环。最终答案由轻量级 LLM 对比文本答案与符号答案，基于原始表格证据进行自适应选择。该机制结合了语义检索的灵活性与符号计算的确定性，解决了单一模式在复杂查询中的失效问题。

## 实验评估

实验在 AIT-QA、HiTab 和 SSTQA 三个复杂表格基准上进行，基线涵盖基础模型（GPT-4o, o3）、提示增强方法（E5, EEDP）、表格专用模型（TableLlama, TableGPT2）及中间表示方法（GraphOTTER, ST-Raptor）。所有训练-free 方法统一使用 DeepSeek-V3-250324 作为骨干，评估采用 GPT-5 作为二元裁判计算准确率。

| 方法 | AIT-QA (%) | SSTQA (%) | HiTab (%) |
|---|---|---|---|
| o3 | 89.1 | 78.2 | 85.3 |
| GraphOTTER | 90.4 | 71.5 | 88.8 |
| ST-Raptor | 62.7 | 71.1 | 49.0 |
| ASTRA (Adaptive) | 91.6 | 81.9 | 90.1 |

ASTRA 在三个数据集上均取得最优成绩，尤其在 HiTab 上以 90.1% 超越 o3 的 85.3%，验证了结构引导对数值聚合任务的增益。在 SSTQA 上，ASTRA 的 81.9% 显著高于 GraphOTTER 的 71.5%，表明语义树在保留层级语义方面优于三元组表示。

消融实验显示，移除评估器引导循环导致平均覆盖率从 0.929 降至 0.745，证明该机制对纠正生成错误至关重要。在 DuTR 模块中，移除路径引导使文本推理准确率下降 8.50%，而移除代码示例使符号推理准确率下降 4.84%，表明语义导航与格式指导对各自模式均具关键作用。静态语义树输入（70.55%）优于原始文本序列化（63.20%），证实了层级表示本身的内在价值。

评估协议使用 LLM-as-a-Judge 替代精确匹配，虽能捕捉语义等价性，但引入了裁判模型的主观性偏差。论文未报告置信区间，且实验仅在单一骨干（DeepSeek-V3）上进行，缺乏跨模型泛化性验证。代码未开源，限制了可复现性。

## 关联研究分析

从结构表示范式看，ASTRA 与 TABGR 和 TAMO 存在显著差异。TABGR 采用属性图保留二维拓扑，TAMO 使用超图建模高阶关系，二者均强调非层级化的复杂连接；而 ASTRA 聚焦于层级依赖，通过语义树显式建模表头层级。这种差异源于任务特性：ASTRA 针对的 AIT-QA 和 HiTab 以嵌套表头为主，层级结构是主要挑战；而 TABGR 针对的 WikiTQ 包含更多交叉引用。ASTRA 未探索非层级化表格，其在处理无明确层级的复杂交叉引用表格时是否失效，论文未给出回答。

从推理机制看，ASTRA 的双模推理与 TableMind 等智能体框架不同。TableMind 依赖规划-执行-反思循环，计算开销大且协调复杂；ASTRA 通过自适应选择文本或符号路径，避免了多智能体协调开销。然而，ASTRA 的符号执行依赖代码生成质量，而 TableMind 的工具调用更具确定性。ASTRA 未对比强化学习方法（如 Table-R1），其双模推理在需要多步逻辑链的复杂任务中是否优于 RL 优化的策略，缺乏直接证据。

## 总结

ASTRA 针对复杂表格 QA 中序列化导致的结构丢失与推理不透明问题，提出利用 LLM 语义感知重建逻辑语义树，并集成文本导航与符号执行的双模推理框架。该方法在 HiTab 上达到 90.1% 准确率，超越 o3 的 85.3%，证明了显式层级表示对数值聚合任务的增益。然而，其自适应构建策略依赖表格规模与 token 密度特征，对于结构高度不规则或缺乏明确层级语义的表格，语义树的构建质量可能下降。当表格包含大量视觉线索（如颜色、合并单元格）且无文本层级提示时，纯文本语义树是否能保留足够的结构信息，论文未提供实验验证。
