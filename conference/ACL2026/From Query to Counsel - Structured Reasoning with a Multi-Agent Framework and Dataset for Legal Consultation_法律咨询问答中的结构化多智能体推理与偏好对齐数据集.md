# ACL2026最新论文 ｜From Query to Counsel: Structured Reasoning with a Multi-Agent Framework and Dataset for Legal Consultation ｜法律咨询问答中的结构化多智能体推理与偏好对齐数据集

研究机构：澳大利亚悉尼科技大学、英国伯明翰大学

作者：Mingfei Lu、Yi Zhang、Mengjia Wu 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.10470)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.10470)

> 法律咨询问答（Legal CQA）要求模型在模糊、多面且高度依赖上下文的自然语言查询中生成可执行的法律建议，这超出了传统法条检索或选择题评估的范畴。现有方法要么通过持续预训练注入法律知识但受限于数据质量，要么通过静态检索拼接法条但无法处理动态事实解释，导致在真实咨询场景中表现不佳。本文构建了包含43,000余条专家验证实例的JURISCQAD数据集，并提出JURISMA框架，通过法律元素图分解查询并由多智能体迭代优化生成过程。该工作证明了结构化分解与偏好对齐训练在提升法律回答准确性与引用可靠性上的有效性，但其评估主要依赖生成指标而非严格的法律逻辑正确性验证。

## 研究背景

法律咨询场景中的用户查询往往包含事实模糊性、非正式表述及个性化困境，例如识别合同中介责任或追溯损害因果关系。解决此类问题需要模型具备法律背景知识、面向法律的查询分解能力以及强大的上下文理解与推理能力。传统法律问答任务通常操作于定义明确的输入和受限选项上，而Legal CQA处理的是开放域自然语言查询，涉及多个纠缠的法律概念和推理步骤，这对模型的语义对齐、法律合规性及表达专业性提出了更高要求。

主流Legal CQA研究遵循两条路径：一是通过持续预训练增强模型法律知识，但因数据处理粗糙、覆盖有限且非场景化，导致监督信号质量低，性能提升边际化；二是通过输入重构，如检索句级法条提供显式法律基础，但静态法条匹配难以处理需要动态解释事实、行为者和法律影响的复杂咨询。这两类方法均未能充分应对真实法律咨询中模糊、多面且高上下文依赖的特性。本文切入点在于识别出高质量训练数据缺失、复杂任务组合及高上下文依赖三大核心挑战，并通过构建大规模专家验证数据集与结构化多智能体框架加以解决。

## 核心方法

### 法律元素图与任务分解

Legal CQA的标准流程通常采用端到端生成范式，直接映射查询到回答，忽略了法律推理的结构化与步骤化特性。本文引入法律元素图 $G=(V,E)$ 作为语义基础，其中节点集 $V$ 包含实体（如原告）、事件（法律行动或争议）及用户主张，边集 $E$ 表示语义关系（如亲属关系、合同义务）。该设计基于法理学中法律作为主体、事实、规范与关系结构化系统的理论，将自由文本查询转化为JSON序列化的全局上下文抽象。这一改动解决了端到端模型在复杂查询中无法显式捕捉法律实体间逻辑依赖的问题，为下游推理提供了可解释且可控的语义基础。

### 多智能体迭代优化与DPO训练

在初始草稿生成后，本文采用多智能体框架进行迭代优化。Manager Agent 动态评估草稿质量，若存在结构或表达缺陷，触发 FormatCheck Agent 生成修订建议；若法律引用缺失，触发 LawSearch Agent 检索相关法条。Draft Agent 整合这些反馈，循环直至 Manager Agent 返回“Pass”或达到最大迭代次数。该过程模拟专业法律写作工作流，通过模块化控制避免错误传播。此外，本文采用直接偏好优化（DPO）训练模型，目标函数为最大化偏好响应 $y_+$ 与非偏好响应 $y_-$ 的对数似然差：

$$ \mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x, y_+, y_-) \sim \mathcal{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_+|x)}{\pi_{\text{ref}}(y_+|x)} - \beta \log \frac{\pi_\theta(y_-|x)}{\pi_{\text{ref}}(y_-|x)} \right) \right] $$

其中 $\sigma$ 为sigmoid函数，$\beta$ 为温度参数。这一设计使模型能够区分法律正确与看似合理但错误的回答，直接针对法律幻觉问题，弥补了静态检索无法动态更新法律基础的局限。

## 实验评估

实验在修正版LawBench上进行，基线包括通用LLM（GPT-4o, Qwen3-14B）、法律LLM（ChatLaw-33B, LawGPT等）及Agent/检索基线（ReAct, LexRAG等）。JURISMA在ROUGE-1、ROUGE-2、ROUGE-L、BLEU-2/N、BERTScore及LLM Score上均取得最佳或次佳成绩，例如ROUGE-L为31.14%，BERTScore为75.05%，显著优于GPT-4o的24.50%和73.22%。

| 模型 | ROUGE-L (%) | BERTScore (%) | LLM Score |
| :--- | :--- | :--- | :--- |
| GPT-4o | 24.50 | 73.22 | – |
| LawGPT | 7.26 | 63.44 | – |
| LexRAG | 21.51 | 71.45 | – |
| JURISMA | 31.14 | 75.05 | – |

消融实验显示，移除修订阶段导致BERTScore下降5.49（14B模型），移除Manager Agent导致BLEU-N下降7.36，移除法律元素图导致ROUGE-L下降9.57。这表明迭代修订对语义质量至关重要，动态路由增强一致性，而法律元素图提升事实基础。

评估边界方面，本文主要使用生成指标（ROUGE/BLEU/BERTScore）及LLM评分，未报告严格的法律逻辑正确性准确率。代码未公开，超参数细节在附录中提供，但缺乏与最新SOTA如LegalGraphRAG在统一准确率指标下的直接对比。

## 关联研究分析

从问题动机看，本文与MASLegalBench同属多智能体协作路线，但MASLegalBench侧重通过角色分工和辩论机制提升复杂推理的鲁棒性，而本文更关注数据稀缺与任务复杂性，通过DPO训练增强模型内在能力而非仅靠推理时协作。这一差异源于Legal CQA对高质量训练数据的依赖，MASLegalBench未解决数据质量问题，而本文通过JURISCQAD数据集弥补了这一盲区。

从方法设计看，本文的LawSearch Agent与LexRAG的静态检索不同，前者嵌入迭代循环中由Manager Agent动态触发，解决了静态RAG缺乏上下文适应性的问题。然而，法律元素图的构建本身依赖LLM提取，可能引入新的幻觉源，论文未讨论图结构构建的误差累积风险。相比之下，Falkor-IRAC通过图约束生成实现引用接地准确性，但本文未采用形式化验证，仅依赖多智能体迭代优化，这在法律规则明确子领域中的可审计性可能不如形式化方法。

## 总结

本文核心矛盾在于Legal CQA中高质量训练数据缺失与复杂任务组合导致的模型性能瓶颈。切入点在于构建大规模专家验证数据集JURISCQAD，并通过法律元素图分解查询与多智能体迭代优化生成过程。实验证明JURISMA在修正版LawBench上ROUGE-L达31.14%，BERTScore达75.05%，优于通用与法律LLM。边界在于评估主要依赖生成指标而非严格法律逻辑正确性，且法律元素图构建可能引入幻觉。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
