> 多模态有害表情包检测面临类型漂移与时间演化带来的泛化失效，现有方法依赖静态特征组合或单轮提示，难以捕捉隐含的设计逻辑。本文切入点在于挖掘不同有害表情包共享的“不变设计原则”，将其形式化为可检索的图结构。通过构建设计概念图（DCG）并引导多模态大语言模型（MLLM）进行步骤化推理，REPMD 在类型漂移场景下实现了 81.1% 的准确率，且域外性能下降仅 2.1%。该方法以结构化知识注入换取了对动态内容的鲁棒性，但其静态图构建机制对全新设计范式的适应性仍存疑。

## 研究背景

当检测器面对新生成的有害表情包时，其视觉元素与文本表达往往与历史数据存在系统性差异，这一现象称为类型漂移（Type Shifting）与时间演化（Temporal Evolving）。这种漂移导致传统基于特征拼接或简单提示的方法失效，因为仇恨意图不再直接体现在表面特征中，而是隐藏在用户特定的设计逻辑里。例如，通过高亮配饰来暗示种族歧视，这种隐含表达无法被仅学习有害元素组合的模型捕捉。解决此类问题的关键在于识别表象之下的“不变原则”，即恶意用户设计表情包时遵循的底层逻辑，如将特定事实归因于特定群体（Human Specification）。

多模态仇恨表情包检测的主流路线已从早期的特征融合转向基于大型视觉语言模型（VLMs）的生成式推理。然而，现有方法如 PromptHate 或 MIND 主要依赖提示工程或检索增强生成（RAG），这些方法在处理快速演变的内容时存在滞后性，且缺乏对设计逻辑的结构化解释。GECO 等多智能体框架虽提升了鲁棒性，但计算成本高且未显式建模设计步骤。本文针对这一瓶颈，提出将攻击树（Attack Tree）思想引入表情包检测，通过复现历史失败案例的设计步骤，构建可解释的设计概念图，从而在漂移场景下提供稳定的推理引导。

## 核心方法

### 方法参照系

本文问题属于基于 MLLM 的有害内容检测范畴，与通用 RAG 框架的关键差异在于检索对象。通用 RAG 检索文本片段或图像相似度，而 REPMD 检索的是结构化的“设计步骤”图，旨在通过逻辑复现而非表面匹配来识别隐含仇恨。

### 失败原因树与设计概念图构建

设计动机在于解决 MLLM 在优化提示后仍无法检测的“顽固”有害表情包，这些案例蕴含了通用的设计逻辑。首先，通过五个 MLLM 的投票机制提取失败案例，利用 Qwen3VL-235B 分析失败原因并生成失败原因树 $G_F$。随后，将失败原因节点 $N_F$ 推导为复现步骤，构建设计概念图 $G_D = \langle \{N_T, N_M, N_G, N_\sigma\}, \{E_T, E_A, E_{Link}\} \rangle$。其中，$N_M$ 为复现方法节点，$N_G$ 为复现目标节点，$N_\sigma$ 为逻辑门节点。该过程将“原因级表达”转化为“复现级思路”，例如将“疯狂女性的育儿问题”转化为“故意选择疯狂女性以攻击该群体”的设计步骤。

### SVD 图剪枝与引导检测

设计动机在于 $G_D$ 包含大量冗余节点，直接输入 MLLM 会导致上下文溢出且降低推理效率。本文提出基于奇异值分解（SVD）的剪枝算法，通过计算节点与根节点的相关性及节点间的差异性来保留关键结构。复现分数定义为：

$$ Score_{rep}(N_{ij}) = ReLU(sim(N_i, N_{root}) - sim(N_i, N_j)) $$

该公式确保保留与根节点（如宏观类型或目标）高度相关且与其他节点差异显著的节点，从而精简图结构。对于目标表情包，从剪枝后的 $G'_D$ 中检索相似的复现步骤，形成步骤化引导提示，帮助 MLLM 逐步识别有害性。

## 实验评估

实验在 GOAT-Bench（类型漂移）和自建 Twitter 数据（时间演化）上进行，基线包括 Mod-Hate、MIND、RA-HMD 及四个 MLLM。本文未对比 GECO、DR-HM 等最新 SOTA 方法，但聚焦于漂移场景下的泛化能力。

| 方法 | ID Accuracy (%) | OOD Accuracy (%) | $\Delta$(OOD, ID) (%) |
| :--- | :--- | :--- | :--- |
| Mod-Hate | 63.3 | 44.7 | $\downarrow$18.7 |
| MIND | 66.4 | 46.9 | $\downarrow$19.5 |
| RA-HMD | 72.2 | 51.8 | $\downarrow$20.4 |
| GPT-4o (Vanilla) | 70.7 | 69.4 | $\downarrow$1.3 |
| GPT-4o + REPMD | 82.3 | 80.0 | $\downarrow$2.3 |

REPMD 在 GPT-4o 骨干上实现了 82.3% 的 ID 准确率，较 Vanilla 提升 10.5 个百分点。关键优势在于 OOD 性能下降仅 2.3%，远低于基线的 18.7%-20.4%，验证了设计概念在类型漂移下的稳定性。

| 变体 | ID Accuracy (%) | OOD Accuracy (%) | TE Accuracy (%) |
| :--- | :--- | :--- | :--- |
| GPT-4o + REPMD | 82.3 | 80.0 | 69.3 |
| w/o SVD | 76.8 | 71.6 | 60.5 |
| w/o DCG | 76.3 | 70.9 | 60.1 |
| SVD $\rightarrow$ GPT-4o | 79.9 | 78.2 | 68.1 |

消融实验显示，移除 SVD 或 DCG 导致准确率下降超过 5 个百分点，表明结构化图与剪枝机制是性能核心。用 MLLM 替代 SVD 进行剪枝虽在时间演化任务上略优，但计算成本增加 14 倍，且因信息截断在 ID/OOD 任务上失败，证实了 SVD 在效率与性能间的平衡优势。

评估协议未报告置信区间，且 Twitter 数据集仅 2,000 样本，统计显著性有限。代码已开源，但 DCG 构建依赖 Qwen3VL-235B 的 API 调用，复现需考虑模型版本差异。

## 关联研究分析

从问题动机看，REPMD 与 MIND 均利用 RAG 解决知识滞后问题，但 MIND 依赖双向洞察增强推理，侧重于语义匹配，而 REPMD 显式建模设计逻辑，侧重于因果复现。这一差异源于对“隐含仇恨”本质的不同假设：MIND 假设仇恨可通过语义相似性检索，REPMD 假设仇恨源于可复现的设计步骤。当面对全新设计范式时，MIND 可能因缺乏相似样本而失效，REPMD 则依赖 DCG 中是否包含该范式的抽象步骤，若 DCG 未覆盖新范式，其优势将消失。

从方法设计看，REPMD 与 GECO 同属生成式推理路线，但 GECO 采用多智能体辩论降低偏见，REPMD 采用单模型加结构化引导。GECO 的计算成本源于多轮交互，REPMD 的成本源于图构建与检索。在可解释性上，REPMD 的 DCG 提供了步骤化证据，比 GECO 的辩论日志更结构化，但 DCG 的静态性限制了其对实时新梗的适应。GECO 的动态辩论机制理论上能捕捉新出现的逻辑，但缺乏结构化约束，可能导致推理发散。

## 总结

本文核心矛盾在于有害表情包表象漂移与底层逻辑不变之间的张力，现有方法因缺乏对设计逻辑的结构化建模而在漂移场景下泛化失效。REPMD 通过构建设计概念图（DCG）并引入 SVD 剪枝，将隐含的设计步骤显式化，引导 MLLM 进行步骤化推理，在类型漂移场景下实现了 81.1% 的准确率且域外性能下降仅 2.1%。其边界在于 DCG 的静态构建机制，依赖历史失败案例的覆盖度，若出现全新设计范式，DCG 可能无法提供有效引导。当 DCG 中未包含目标表情包的设计步骤时，检索机制是否退化为无效提示，论文未给出回答。
