作者：Pengfei Li、Shijie Wang、Fangyuan Li 等 10 人

> 大语言模型（LLM）在代码生成等推理任务中受限于单策略先验的探索瓶颈，导致轨迹多样性不足与性能天花板。现有搜索增强方法虽引入结构化探索，但仍由单一策略驱动，难以突破先验约束；而多智能体协作框架缺乏与结构化搜索的深度耦合。MARS[2] 将搜索树建模为可学习的多智能体交互环境，通过树一致奖励整形实现层级信用分配。该方法在 LiveCodeBench 上显著提升了系统级搜索性能，但其对异构能力智能体的鲁棒性边界尚需进一步验证。

## 研究背景

当 LLM 在代码生成任务中采用独立同分布（i.i.d.）采样时，其有效探索空间被模型自身的先验分布严格限制。这种限制导致轨迹多样性不足，策略过早收敛至局部最优，形成难以突破的性能上限。为缓解此问题，搜索增强强化学习（Search-Augmented RL）引入蒙特卡洛树搜索（MCTS）以在固定计算预算下显式扩展候选解空间。然而，现有方法如 TreeRL 仍由单一策略分布驱动整个搜索树，随着训练推进，搜索行为集中于高概率分支，导致探索收益递减。

多智能体强化学习（MARL）通过引入多策略交互产生非平稳数据分布，理论上可突破单策略的探索边界。近期研究如 MAPoRL 表明，将多智能体协作纳入训练循环比仅在推理时使用多智能体协议能获得更稳定的性能增益。然而，现有 LLM 多智能体框架多依赖对话、辩论或投票等轻量级协调机制，将智能体交互视为简单的协调手段而非结构化探索过程。这导致多智能体协作与底层搜索动态脱节，缺乏对分支、回溯及探索预算分配的显式支持，限制了其在深度多分支推理任务中的适用性。

## 核心方法

### 方法参照系

本文问题可置于“搜索增强强化学习”与“多智能体协作”的交叉领域。标准流程为：单智能体通过 MCTS 生成轨迹，利用组相对策略优化（GRPO）进行策略更新。本文的关键差异在于将搜索树本身建模为多智能体共享的可学习环境，并引入层级化的奖励分配机制，以解决单策略先验导致的探索停滞问题。

### 树结构多智能体搜索环境

传统 MCTS 中，节点扩展由单一策略决定，缺乏动态平衡探索与利用的机制。MARS[2] 将每次节点扩展建模为智能体-节点对上的多臂老虎机问题，通过 Thompson 采样选择最有可能的智能体及其关联节点。智能体分为两类：生成节点（提出新候选解）与精化节点（沿现有路径改进）。这种设计允许不同智能体在共享拓扑中动态分配探索预算，避免单一策略先验导致的分支集中。

### 树一致奖励整形与层级信用分配

在树结构中，节点并非独立生成，而是存在父子依赖与兄弟竞争关系。标准 GRPO 的全局组优势无法捕捉这种层级依赖。MARS[2] 引入树一致奖励整形，定义混合基线 $b(v) = \lambda r_p(v) + (1-\lambda) \mu_{C(p(v))}$，其中 $r_p(v)$ 为父节点奖励，$\mu_{C(p(v))}$ 为同父节点兄弟节点的均值奖励，$\lambda \in [0,1]$ 平衡垂直改进与水平竞争。结构一致性增益定义为 $\Delta(v) = r_v - b(v)$，整形后奖励为 $\hat{r}_v = r_v + \gamma \Delta(v)$。该机制显式鼓励子节点优于父节点且优于兄弟节点，实现了复杂搜索轨迹下的稳定信用分配。

实验在 LiveCodeBench (v6) 上进行，基线包括 Vanilla GRPO 和单智能体树搜索 RS[2]。MARS[2] 在系统级指标 Pass@1 (MCTS) 上表现突出，例如 Q&A-14B 系统达到 68.9%，较 Base 提升 6.0 个百分点。值得注意的是，在单模型 Pass@1 上，MARS[2] 的提升幅度（如 Qwen3-8B 提升 8.0%）大于 RS[2]（提升 5.1%），表明多智能体协作不仅优化了搜索过程，也反向提升了个体策略质量。

消融实验显示，引入较弱智能体 DeepCoder-14B 后，个体 Pass@1 增益从 5.1% 降至 3.4%，说明弱智能体可能注入噪声轨迹，干扰个体策略优化。然而，系统级 Pass@1 (MCTS) 和 Pass@N 仍保持单调提升，表明 MARS[2] 通过树结构搜索有效聚合了互补信息，维持了系统级优势。多样性评估指标（如 AEC, G-Vendi）显示 MARS[2] 在平均排名上优于其他方法，验证了其增强探索多样性的能力。

评估边界方面，论文未报告计算效率（如 GPU 时间或内存占用），且 Pass@1 (MCTS) 依赖“最新胜出”规则，该规则的优势仅在附录中简要验证。代码已开源，但超参数（如 $\lambda, \gamma$）的敏感性分析未在正文中详细展开，可能影响复现性。

## 关联研究分析

从问题动机看，MARS[2] 与 TreeRL 均旨在解决单策略探索瓶颈，但 TreeRL 将 MCTS 视为静态采样工具，而 MARS[2] 将其转化为动态多智能体环境。这一差异源于任务特性：代码生成需要长时程的层级改进，静态采样无法捕捉父子节点间的依赖关系，而多智能体动态选择能更好地平衡探索与利用。

从方法设计看，MARS[2] 与 MAPoRL 均利用多智能体交互，但 MAPoRL 依赖对话或投票等轻量级协调，缺乏结构化搜索支持。MARS[2] 通过树一致奖励整形实现了细粒度的信用分配，而 MAPoRL 的奖励信号较为稀疏。这种设计差异暗示，在需要精确归因的推理任务中，结构化搜索比轻量级协调更具优势。然而，MARS[2] 未显式建模通信成本，仅通过 Thompson 采样隐式控制，这在带宽受限场景下是否足够高效，论文未给出回答。

## 总结

MARS[2] 旨在解决 LLM 推理中单策略先验导致的探索瓶颈，通过多智能体协作与树搜索的深度耦合，突破了现有搜索增强方法的局限。其核心创新在于将搜索树建模为可学习的多智能体环境，并引入树一致奖励整形实现层级信用分配。实验表明，MARS[2] 在 LiveCodeBench 上显著提升了系统级搜索性能，Q&A-14B 系统的 Pass@1 (MCTS) 达到 68.9%。然而，消融实验显示，弱智能体的引入会削弱个体策略优化效果，表明该方法对智能体能力均衡性存在依赖。当智能体能力差异进一步扩大时，树一致奖励整形是否仍能维持有效的信用分配，论文未给出回答。
