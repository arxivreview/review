# ACL2026最新论文 ｜GTA: Generating Long-Horizon Tasks for Web Agents at Scale ｜基于站点图检索种子的多跳任务生成

研究机构：美国南加州大学、Salesforce AI研究院

作者：Tenghao Huang、Kung-Hsiang Huang、Prafulla Kumar Choubey 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.29218)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.29218)

> 现有 Web 智能体基准面临数据稀缺与过程监督缺失的双重困境，人工标注成本高且无法覆盖长程推理轨迹，而早期自动生成分布偏差大、任务浅层化。GTA 通过解耦爬取与生成环节，利用站点图检索种子构建组合性任务，实现了可执行轨迹的规模化产出。该框架在 50 个网站上的实验揭示了智能体在跨域与非英语环境下的显著性能断层，但其评估仍受限于单一文本模态与有限基线覆盖，对复杂 UI 布局的接地能力验证不足。

## 研究背景

Web 智能体的核心挑战在于将自然语言意图映射为动态网页中的精确操作序列。这一过程本质上是隐马尔可夫过程，关键不确定性存在于未观测的中间状态与动作。由于现有基准仅提供粗粒度的起止标注，缺乏对中间决策步骤的监督，智能体在训练中小规模手工数据集上过拟合，难以泛化至真实的多跳、跨页场景。

主流数据合成路线存在显著瓶颈。AgentTrek 等基于教程文档转换的方法虽具自动性，但依赖昂贵的策略滚动，且 LLM 策略倾向于探索“显而易见”的路径，导致站点图覆盖率极低（如 AgentTrek 仅 20.2%）。NNetNav 等基于策略探索的方法同样存在探索偏置，生成的任务多为单跳检索，缺乏组合性。GTA 的切入点在于摒弃策略驱动的探索，转而利用检索增强的种子节点，在站点图结构上强制构建多跳依赖，从而在降低计算成本的同时提升任务的结构多样性与推理深度。

## 核心方法

### 站点图构建与任务形式化

GTA 将 Web 环境建模为有向图 $G=(V, E)$，其中节点 $v \in V$ 对应爬取的网页，边 $(v_i, v_j) \in E$ 对应超链接。任务被形式化为 $T = \langle q, A, P[\star] \rangle$，其中 $q$ 为自然语言查询，$A$ 为答案，$P[\star] = \langle v_1, v_2, \dots, v_m \rangle$ 为图内通向答案的最小可执行路径。该形式化明确了多跳任务的定义：若求解需聚合至少 $n$ 个不同网页的证据，则任务为 $n$ 跳。这一设计将任务生成从线性轨迹记录转变为图结构上的组合推理，解决了此前方法中任务与站点结构脱节的问题。

### 检索种子生成与质量控制

在获取站点图后，GTA 采用检索种子策略生成任务。首先，利用 LLM 编码器 $f_\theta$ 将每个节点 $v$ 嵌入为稠密向量 $h_v \in \mathbb{R}^d$。给定种子节点 $v_s$，通过稠密检索获取候选集 $R(v_s) = \{v_1, \dots, v_k\}$。随后，随机选取次级节点 $v_t \in R(v_s)$，将 $(content(v_s), content(v_t))$ 作为上下文输入生成器 LLM，合成需要跨页推理的查询 $q$。

$$
q \sim \text{Gen}_{\theta}(\text{content}(v_s), \text{content}(v_t))
$$

该公式表明，查询 $q$ 的生成依赖于两个语义相关但内容独立的页面证据，强制模型进行组合推理而非单点检索。为确保证据有效性，GTA 实施多阶段质量控制：拒绝由“and”连接的独立单跳查询；验证器 LLM 仅基于支持节点内容复现答案；检测查询歧义性；并检查图内是否存在最小可执行路径 $P[\star]$。这一机制确保了任务的唯一解性与可重放性，避免了此前方法中因路径缺失导致的评估不可复现问题。

## 实验评估

实验在 50 个公开网站上进行，涵盖电商、医疗、金融等领域，生成 5,000 个站内任务与 600 个跨站任务。基线包括 Browser Use 与 AgentOccam，两者均为主流开源框架，但缺乏多模态智能体（如 Avenir-Web）或树搜索架构（如 Branch-and-Browse）的对比，限制了评估的全面性。

| 数据集 | 搜索基线正确率 (%) | GTA 搜索基线正确率 (%) |
| :--- | :--- | :--- |
| AgentTrek | 95 | 14 |
| NNetNav | 100 | 14 |

搜索基线在 AgentTrek 和 NNetNav 上高达 95%-100% 的正确率，而在 GTA 上仅 14%，证明 GTA 任务无法被简单检索解决，具备真正的多跳推理难度。在智能体性能上，Browser Use 在 WebVoyager 上可达 82%，但在 GTA 站内任务中常低于 20%-30%。跨站任务表现更差，Mayo Clinic 与 WebMD 组合任务成功率仅 12.5%，Drugs.com 与 CVS Health 组合低至 4.2%。多语言评估显示，Browser Use 在德语、意大利语网站上成功率为 0%，日语为 2.9%，而英语网站为 6.0%-8.2%，揭示了严重的语言偏置。

GTA 的页面覆盖率达 77.4%-80.7%，远高于 AgentTrek 的 20.2% 和 NNetNav 的 24.3%，表明其任务分布更均匀地覆盖了站点功能。人工评估中，GTA 任务复杂度评分 2.35，显著高于 WebDS 的 1.90 和 AgentTrek 的 1.23，但真实性评分 1.53 低于 AgentTrek 的 1.98，可能源于图接地生成引入了非自然用户意图的查询。

评估边界方面，GTA 未报告计算效率的具体数值，仅定性描述为“显著降低”。代码已开源，但缺乏统一骨干网络下的公平对比，且未验证多模态输入对复杂 UI 接地的影响，限制了其在视觉密集场景下的适用性判断。

## 关联研究分析

从数据生成机制看，GTA 与 AgentTrek 的根本差异在于探索策略。AgentTrek 依赖 LLM 策略滚动，导致探索偏置集中于高频路径，而 GTA 利用检索种子在图结构上采样，实现了功能覆盖的均匀化。这一差异源于任务目标的不同：AgentTrek 旨在复现教程流程，而 GTA 旨在构建组合推理场景。检索种子策略是否引入了新的语义偏置，例如过度依赖语义相似度而忽略结构距离，论文未给出定量分析。

从评估维度看，GTA 与 WebArena 等标准基准相比，更强调任务的动态性与多语言覆盖，但缺乏步骤级细粒度诊断。WebArena 提供功能正确性评估，而 GTA 虽提供可执行轨迹，但主要结论仍依赖端到端成功率。跨站任务中 4.2% 的低成功率揭示了智能体在处理非重叠知识整合时的脆弱性，这与知识库中关于“跨网站迁移困难”的共识一致，但 GTA 未深入分析是术语不一致还是 UI 结构差异导致的具体失败模式。

## 总结

GTA 解决了 Web 智能体基准中数据稀缺与过程监督缺失的核心矛盾，通过解耦爬取与生成环节，利用站点图检索种子构建组合性任务，实现了可执行轨迹的规模化产出。实验证明其任务难度显著高于现有合成基准，搜索基线正确率从 95% 降至 14%，且页面覆盖率达 77.4% 以上。然而，其评估局限于文本模态与有限基线，未验证多模态感知在复杂 UI 布局下的接地能力，且跨站任务中 4.2% 的低成功率暴露了智能体在分布偏移处理上的根本局限。当站点图规模扩大至百万级节点时，检索种子的语义偏置是否会抵消结构覆盖的优势，论文未给出回答。
