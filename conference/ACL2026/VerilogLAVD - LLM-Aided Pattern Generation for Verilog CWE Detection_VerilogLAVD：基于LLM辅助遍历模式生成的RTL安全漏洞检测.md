> 导读 硬件描述语言（HDL）的并发语义导致传统静态分析与纯LLM隐式推理在RTL安全漏洞检测上均失效，前者受限于规则僵化，后者缺乏对跨结构数据流的控制。VerilogLAVD通过构建统一属性图（VeriPG）并引入LLM生成、验证器约束的可执行遍历检测模式（TDP），将模糊语义匹配转化为确定性图遍历。该框架在合成基准上实现了F1分数0.57，较知识增强基线提升133%，但在真实仓库中仍依赖人工审计且受限于上下文窗口，其泛化边界尚待验证。

## 研究背景

寄存器传输级（RTL）代码的安全漏洞往往源于多个并发执行语句的交互，而非单一顺序路径。这种并发特性要求检测工具同时理解语法结构、控制流与数据依赖，但现有方法缺乏统一表示。抽象语法树（AST）仅捕捉语法骨架，控制流图（CFG）忽略数据流，数据依赖图（DDG）缺失控制逻辑，三者孤立导致如CWE-1234（权限绕过）这类需同时关联信号存在性与控制流追踪的漏洞无法被检测。

硬件安全验证长期面临数据稀缺与语义对齐难题。传统静态分析工具如CWEAT依赖预定义模板，无法覆盖13个CWE类别中的8个，且在处理CWE-1280（访问控制）等复杂并发语义时召回率仅60.00%。纯LLM方法虽能利用自然语言理解，但直接将代码序列输入模型时，因缺乏对RTL结构的显式建模，易产生幻觉且无法捕捉阻塞与非阻塞赋值带来的时序差异。VerilogLAVD的切入点在于将LLM的语义理解能力与图结构的确定性遍历结合，通过生成可执行的遍历规则而非直接输出漏洞判断，解决LLM在硬件并发语义上的推理盲区。

## 核心方法

### 方法参照系

本文问题属于“LLM辅助静态分析”范畴，但区别于直接提示LLM判断漏洞的隐式推理范式。关键差异在于引入中间表示层：不依赖LLM直接输出结果，而是让LLM生成针对特定图结构的遍历规则，再由执行器在图上机械运行，从而将随机推理转化为确定性计算。

### VeriPG统一属性图构建

设计动机在于解决AST、CFG、DDG孤立导致的跨结构漏洞检测失效。VeriPG定义为有向属性图 $G = (V, E, P_V, P_E)$，其中顶点 $V$ 包含语法节点与语句，边 $E$ 按类型标注为AST、CFG或DDG。针对硬件并发，CFG采用按过程块构建策略，并行语句节点共享父节点而非线性连接；DDG严格区分阻塞（=）与非阻塞（<=）赋值，剪除非阻塞赋值对当前周期后续语句的错误依赖边。通过AST唯一标识符对齐三种图的公共节点，形成统一拓扑，使遍历能同时跨越控制流与数据流。

### 验证器约束的TDP生成

设计动机在于抑制LLM生成遍历规则时的结构幻觉。TDP格式为复合结构，包含原始遍历操作、参数及布尔过滤条件。生成过程采用渐进式工作流：从CWE描述蒸馏检测逻辑，映射为VeriPG拓扑路径，最终合成原始操作。验证器将图遍历建模为有限状态机（FSM），形式化编码VeriPG模式，仅当当前状态与目标节点类型间存在有效转移时操作合法。若LLM生成非法操作（如在Always状态执行Branch），验证器返回具体错误反馈，引导LLM迭代修正。该机制将随机输出约束在拓扑合法空间内，确保生成的TDP可执行且语义正确。

## 实验评估

实验在自建81个合成CWE基准（覆盖13个类别）及11个开源硬件仓库（约108万行代码）上进行。基线包括DeepSeek-V3、GPT-4o的零样本与知识增强设置，以及静态分析工具CWEAT。

| 方法 | P(%) | R(%) | F1 |
| :--- | :--- | :--- | :--- |
| GPT-4o + Knowledge | 40.21 | 66.10 | 0.50 |
| GPT-4o + VerilogLAVD | 47.25 | 72.88 | 0.57 |
| DeepSeek-V3 + VerilogLAVD | 46.15 | 54.55 | 0.50 |

VerilogLAVD在GPT-4o骨干下F1达0.57，较知识增强基线提升133%，在FSM逻辑（CWE-1245）与访问控制（CWE-1280）上表现尤为突出。对比CWEAT，VerilogLAVD在CWE-1280上召回率达84.91%，显著优于CWEAT的60.00%，且覆盖全部13个CWE类别。

| 配置 | IPTR(%) | IPMR(%) | Total(%) |
| :--- | :--- | :--- | :--- |
| LLM+Knowledge | 27.04 | 13.83 | 40.87 |
| VerilogLAVD (w/o Validator) | 23.96 | 12.88 | 36.84 |
| VerilogLAVD (with Validator) | 3.49 | 6.61 | 10.10 |

消融实验显示，验证器将无效路径率（IPTR）从27.04%降至3.49%，降幅87.10%，证明FSM约束对抑制LLM结构幻觉的关键作用。执行效率方面，运行时间与VeriPG规模无线性依赖，而与执行的原始操作数量强相关，体现“无关代码不敏感”特性，支持大规模设计扩展。

评估边界受限于合成基准的构造性质，真实仓库缺乏地面真值，依赖人工审计107个警报。代码已开源，但超参数与GPU配置未在正文详述，且未报告置信区间，数值比较需谨慎。

## 关联研究分析

从问题动机看，VerilogLAVD与ChIRAAG同属LLM生成验证属性路线，但前者聚焦安全漏洞检测，后者针对功能断言生成。ChIRAAG依赖检索增强生成（RAG）从自然语言规范生成SystemVerilog断言（SVA），而VerilogLAVD通过图结构约束生成遍历规则。差异根源在于任务特性：SVA生成侧重语义对齐，可容忍一定模糊性；漏洞检测需精确捕捉并发时序依赖，图遍历的确定性更关键。VerilogLAVD的FSM验证器是否限制了复杂漏洞模式的表达，论文未给出回答。

从方法设计看，VerilogLAVD与CWEAT代表语义推理与模板匹配的路线分歧。CWEAT依赖预定义规则，无法泛化至未覆盖的CWE类别；VerilogLAVD利用LLM生成规则，但受限于LLM对硬件语义的理解深度。在CWE-1271（未初始化值）上，VerilogLAVD出现较高误报（2/20 TP），因缺乏运行时仿真数据，而CWEAT在此类场景可能更稳定。这暗示静态图遍历在捕捉深层时序漏洞时存在盲区，仿真反馈与图遍历的互补性尚未在本文实验中充分验证。

## 总结

VerilogLAVD旨在解决HDL并发语义下安全漏洞检测的难题，抓住LLM隐式推理缺乏结构约束这一痛点，通过VeriPG统一图与TDP验证器生成机制，将语义匹配转化为确定性图遍历。实验证明其在合成基准上F1达0.57，较基线提升133%，并在真实仓库中识别出有效漏洞。然而，其边界在于合成基准与真实漏洞分布的差异，以及缺乏运行时仿真数据导致的误报。当支持集增大到复杂层次化设计时，VeriPG构建的计算开销与TDP生成的上下文窗口限制是否成为瓶颈，论文未给出回答。
