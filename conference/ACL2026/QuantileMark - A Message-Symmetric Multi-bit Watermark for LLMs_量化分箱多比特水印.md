# ACL2026最新论文 ｜QuantileMark: A Message-Symmetric Multi-bit Watermark for LLMs ｜量化分箱多比特水印

作者：Junlin Zhu、Baizhou Huang、Xiaojun Wan

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_776727df0322)

> 多比特溯源要求水印不仅验证来源，还需解码用户ID等具体元数据，但现有词汇划分方案在低熵解码下导致不同消息获得不均等的概率预算，造成质量波动与检测失效。本文指出这一“消息对称性”缺失是核心瓶颈，提出在累积概率区间而非词汇空间进行等质量分箱采样。通过固定每个符号 $1/M$ 的概率预算，QuantileMark 在理论上保证无偏性，并在实验中实现了接近饱和的多比特恢复率。该方案在白盒设定下有效解决了低熵场景下的不对称问题，但其对模型内部访问的依赖限制了第三方验证场景的适用性。

## 研究背景

自回归语言模型生成文本时，解码器在每一步基于前文历史 $h_t$ 预测下一个 token 的概率分布 $p_0(\cdot|h_t)$。传统零比特水印通过偏置 logits 实现存在性检测，但多比特溯源需将离散消息符号 $s$ 映射到具体的 token 选择上。这一映射过程引入了关键约束：消息内容本身不应系统性地改变文本质量或检测证据强度，即“消息对称性”。若某些消息被分配到高概率 token 集合，嵌入成本低且证据强；而另一些消息若仅对应低概率尾部 token，则嵌入会显著扭曲分布并削弱统计证据，导致服务质量与归因可靠性随消息内容波动。

现有生成式水印主要分为失真型与分布保持型两类。失真型方案（如 MPAC）通过词汇划分将词表分为 $M$ 个不相交子集，对目标符号对应的子集施加 logit 偏置。然而，在低熵解码场景（如代码生成或长文本问答）中，概率分布高度集中，词汇划分导致概率预算严重不均：高概率 token 可能全部落入某一个符号的子集，而其他符号的子集仅包含尾部 token。分布保持型方案（如 StealthInk）虽通过重加权确保边际分布不变，但为满足黑盒验证的隐蔽性要求，其单步失真极小，导致多比特恢复所需的统计证据过于微弱。QuantileMark 的切入点在于利用白盒访问权限，放弃黑盒隐蔽性约束，转而显式强制消息对称性，通过连续概率区间的等质量分箱，将全部概率质量集中注入目标符号对应的区间，从而在保持无偏性的同时最大化单步证据强度。

## 核心方法

### 方法参照系

多比特水印的标准流程包含位置分配、符号嵌入与证据聚合。位置分配函数 $\phi_t$ 确定当前步 $t$ 嵌入哪个消息符号 $s_{i_t}$；嵌入阶段将符号映射为 token 选择策略；检测阶段通过教师强制重建分布并聚合证据。本文的关键差异在于嵌入阶段的操作空间：传统方法在离散词汇空间划分，本文在连续累积概率区间（CDF）划分，将符号与概率质量区间绑定，而非与特定 token 身份绑定。

### 等质量量化分箱嵌入

传统词汇划分在低熵分布下导致概率预算不均，QuantileMark 将嵌入通道定义在累积概率区间 $[0, 1)$ 上。在步骤 $t$，将区间划分为 $M$ 个等质量箱 $B_r = [r/M, (r+1)/M)$，其中 $M=2^m$。嵌入目标符号 $s_{i_t}$ 时，首先通过密钥与局部上下文推导置换 $\phi_t$，确定目标箱 $r^*_t = \phi_t(s_{i_t})$。随后，在目标箱内均匀采样随机值 $u_t \sim U(B_{r^*_t})$，输出 token $x_t$ 为覆盖 $u_t$ 的区间对应的 token。该机制保证每个符号获得固定的 $1/M$ 概率预算，无论上下文熵如何变化。

$$
p_{wm}(v | h_t, r) = M \cdot \mu_t(v, r)
$$

其中 $\mu_t(v, r) = |I_t(v) \cap B_r|$ 为 token $v$ 的概率区间 $I_t(v)$ 与箱 $B_r$ 的重叠质量。该公式表明，水印分布仅保留目标箱内的概率质量，并将其放大 $M$ 倍以归一化，从而将全部证据集中于目标符号，显著提升单步检测信噪比。

### 后验概率证据聚合

检测阶段需从观测 token 反推其所属的潜在箱。由于 token 区间可能跨越多个箱边界，硬分配会丢失信息。QuantileMark 计算 token $x_t$ 来自箱 $r$ 的后验概率：

$$
p_t(r) = \frac{\mu_t(x_t, r)}{p_0(x_t | h_t)}
$$

该后验概率提供了软证据：若 token 跨越箱 $r_1$ 和 $r_2$，则对两者均产生正支持，同时排除无重叠的箱。为数值稳定，将 $p_t(r)$ 裁剪至 $[\epsilon, 1-\epsilon]$，并计算对数后验比（LPO）：

$$
\text{LPO}_t(r) = \log \left( \frac{p_t(r)}{1 - p_t(r)} \right)
$$

对于每个消息符号 $s_h$，聚合所有分配给位置 $h$ 的步骤的 LPO 值，通过 argmax 解码最可能的符号 $\hat{s}_h$。该设计避免了词汇划分的硬投票缺陷，利用重叠质量实现更精细的证据累积，尤其在低熵场景下，软证据比硬分配更能抵抗分布波动带来的噪声。

## 实验评估

实验在 C4（Llama-2-7B）与 LFQA（Llama-3.1-8B-Instruct）上进行，嵌入 24 位消息于 300 token 序列中，对比 MPAC（词汇划分）与 StealthInk（分布保持）。基线覆盖失真型与分布保持型两条主要路线，但缺失 DLM 类基线（因架构不同）及低熵专用检测器。

| 方法 | C4 Bit Acc | C4 AUC | C4 TPR@1%FPR | C4 PPL | LFQA Bit Acc | LFQA AUC | LFQA TPR@1%FPR | LFQA PPL |
|---|---|---|---|---|---|---|---|---|
| No watermark | – | – | – | 7.684 | – | – | – | 2.647 |
| MPAC | 0.9702 | 0.9887 | 0.9800 | 10.351 | 0.8770 | 0.9756 | 0.8056 | 3.793 |
| StealthInk | 0.9003 | 0.9869 | 0.7920 | 8.235 | 0.7447 | 0.8301 | 0.2425 | 2.636 |
| QuantileMark | 0.9893 | 0.9995 | 0.9840 | 7.404 | 0.9500 | 0.9997 | 1.0 | 2.759 |

QuantileMark 在 C4 上 Bit Acc 达 0.9893，AUC 0.9995，PPL 7.404，接近无水印基线 7.684；在 LFQA 上 TPR@1%FPR 达 1.0，Bit Acc 0.9500，显著优于 MPAC（0.8770）与 StealthInk（0.7447）。LFQA 的 next-token 分布更尖锐，词汇划分导致概率预算不均，QuantileMark 的等质量分箱在此场景下优势明显。

消融实验显示，符号大小 $m$ 存在权衡：$m=2,3$ 性能最佳，$m=4$ 时 Bit Acc 急剧下降，尽管检测 AUC 仍强。这是因为固定长度预算下，$m$ 增大导致每个符号的支撑 token 数减少，信息稀释。$m=1$ 时 AUC 较低，因人类文本 token 常落在 CDF 尾部，二元划分下检测器易找到虚假对齐消息。

评估边界方面，实验仅覆盖自回归架构，未测试 DLMs 或扩散模型；检测依赖白盒访问（教师强制），无法用于黑盒 API 场景；样本量 500 可能不足以反映长尾分布下的稳定性；未报告计算效率对比（仅检测时间 0.343s vs MPAC 0.103s）。

## 关联研究分析

从问题动机看，QuantileMark 与 MPAC 均解决多比特溯源，但 MPAC 假设词汇划分能均匀分配概率质量，这在低熵场景下失效。QuantileMark 通过连续区间划分，将符号与概率质量而非 token 身份绑定，解决了低熵下的不对称问题。这一差异源于任务特性：多比特溯源要求每个符号的证据强度一致，而词汇划分在分布集中时无法满足此要求。

从方法设计看，QuantileMark 与 StealthInk 同属分布保持型，但 StealthInk 为黑盒验证设计，单步失真极小，导致证据微弱；QuantileMark 利用白盒访问，允许更大失真以集中证据。这一差异源于验证场景：白盒设定下，隐蔽性非必需，证据强度成为首要目标。QuantileMark 的等质量分箱机制可视为 KGW 绿红列表在连续概率空间上的推广，但引入了重叠质量后验计算，提升了检测精度。

## 总结

QuantileMark 解决的核心矛盾是多比特溯源中消息对称性与检测鲁棒性的冲突：词汇划分在低熵下导致概率预算不均，分布保持型方案证据过弱。本文抓住白盒访问权限，通过连续概率区间的等质量分箱，强制每个符号获得固定 $1/M$ 概率预算，理论上证明消息无偏性，并在 C4/LFQA 上实现 Bit Acc 0.9893 与 TPR@1%FPR 1.0。其边界在于依赖白盒访问，无法用于黑盒 API 场景；实验仅覆盖自回归架构，未测试 DLMs；$m=4$ 时性能下降表明固定长度预算下信息稀释问题。当消息长度固定时，增大符号大小 $m$ 是否必然导致 Bit Acc 下降，还是可通过动态调整嵌入步数来缓解，论文未给出回答。
