# ACL2026最新论文 ｜MemSearch-o1: Empowering Large Language Models with Reasoning-Aligned Memory Growth in Agentic Search ｜基于推理对齐记忆生长的智能体搜索框架

研究机构：香港城市大学、大连理工大学

作者：Sheng Zhang、Junyi Li、Yingyi Zhang 等 10 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_f6dc261a3747)

> 智能体搜索在迭代“思考-搜索”循环中面临记忆稀释问题，即累积的冗余文档与思维历史导致信噪比下降，使关键证据被噪声淹没。现有记忆管理方法多依赖全局语义匹配或简单压缩，难以捕捉查询与文档间的细粒度语义关联，且易丢失关键信息。MemSearch-o1 通过从查询中提取词元级“记忆种子”引导记忆片段生长，并利用贡献函数回溯重组记忆路径，实现了推理对齐的结构化记忆管理。该框架在多个基准上显著缓解了记忆稀释，但其性能高度依赖底层大语言模型的推理能力，且缺乏对长程任务中动态策略优化的验证。

## 研究背景

当大语言模型（LLM）执行多跳推理任务时，其上下文窗口会迅速被检索到的文档片段和中间思考过程填满。这种累积效应导致注意力分散，即记忆稀释，使得模型难以从海量噪声中定位关键证据。为应对此问题，智能体搜索范式引入了迭代检索与推理机制，但静态的检索增强生成（RAG）无法适应动态变化的查询意图，导致证据召回率随推理深度增加而下降。

智能体搜索领域的核心矛盾在于长程任务中的信用分配与上下文窗口限制。主流路线分为两类：一是基于强化学习（RL）的策略优化，如 Search-R1 和 MemSearcher，通过端到端训练解决信用分配，但训练成本高且依赖稀疏奖励；二是推理时的记忆管理，如 Expand-then-Squeeze 和 A-Mem，通过压缩或过滤上下文降低噪声，但往往忽略记忆片段间的逻辑结构，导致推理路径断裂。MemSearch-o1 的切入点在于摒弃训练式优化，转而利用语言学结构在推理时构建细粒度的记忆生长机制，试图在不增加训练成本的前提下，通过结构化记忆提升推理质量。

## 核心方法

### 方法参照系

MemSearch-o1 属于智能体搜索中的推理时记忆管理路线。与标准 ReAct 框架直接拼接上下文不同，该框架在“思考-搜索”循环中插入了记忆种子提取与记忆路径回溯两个关键步骤，将线性累积的记忆流转化为结构化、词元对齐的记忆空间。

### 记忆种子提取与片段生长

传统记忆管理依赖查询与文档的全局语义匹配，这种粗粒度对齐在长文档中易导致信息纠缠与丢失。MemSearch-o1 利用 spaCy 工具将查询 $q^{(n)}$ 分解为基于词性的记忆种子 $S^{(n)}$，包括主语、动作、程度修饰词和时间标记。每个种子 $s_i^{(n)}$ 包含一组词元，作为引导 LLM 从检索文档 $D^{(n)}$ 中提取相关信息的锚点。记忆片段 $m_i^{(n)}$ 的生成概率定义为：

$$ P_M = \prod_{i=1}^{L_r} \prod_{t=T_{s_i}^{(n)}-1}^{T_{s_i}^{(n)}} P(M_t^{(n)} | M_{<t}^{(n)}, s_i^{(n)}, I_M, D^{(n)}) $$

该公式表明，LLM 在生成记忆片段时，以记忆种子为条件约束，强制模型关注与查询目标紧密相关的特定语义维度，从而避免了全局语义匹配带来的噪声干扰。

### 记忆路径回溯与贡献函数

多轮推理后，记忆片段可能因查询漂移而包含无关信息。MemSearch-o1 设计贡献函数 $C(m_i; q_o)$ 来筛选和重组记忆片段，其定义为：

$$ C(m_i; q_o) = \alpha \cdot C_{Rel} + \beta \cdot C_{BP} $$

其中 $C_{Rel} = Sim(Emb(m_i), Emb(q_o))$ 衡量片段与原始查询的相关性，$C_{BP}$ 衡量片段与其他片段的桥接潜力。通过贪心搜索，框架选择高贡献片段构建语义平滑的记忆路径，确保最终生成基于逻辑连贯的证据链，而非冗余的原始文档堆砌。

## 实验评估

实验在 HotpotQA、2WikiMQA、MuSiQue 等八个基准上进行，对比了 Direct RAG、Search-o1、A-Mem 和 Amber 等基线。基线覆盖了静态 RAG、迭代搜索和记忆管理路线，但缺失了 2025-2026 年最新的 SOTA 方法如 M-ASK 和 EvolveSearch，这可能影响对方法相对位置的准确判断。

| 方法 | HotpotQA F1 | 2WikiMQA F1 | MuSiQue F1 |
| :--- | :--- | :--- | :--- |
| Direct RAG | 54.40 | 47.23 | 27.54 |
| Search-o1 (RAgent) | 57.41 | 62.86 | 44.78 |
| A-Mem | 54.24 | 60.08 | 39.95 |
| Amber | 53.78 | 61.16 | 37.61 |
| MemSearch-o1 | 59.71 | 65.95 | 44.11 |

MemSearch-o1 在 HotpotQA 上取得 59.71% F1，显著高于 Search-o1 (RAgent) 的 57.41% 和 A-Mem 的 54.24%，表明结构化记忆管理在复杂多跳推理中的优势。

消融实验显示，移除记忆生长模块导致 HotpotQA F1 从 67.78% 降至 54.64%，移除回溯模块降至 64.27%，证明两个模块均对性能有显著贡献。在 2WikiMQA 上，完整模型 F1 为 68.32%，无记忆模块为 56.41%，无回溯模块为 63.91%，进一步验证了记忆路径重组对长程推理的重要性。

| 配置 | HotpotQA F1 | 2WikiMQA F1 | MuSiQue F1 |
| :--- | :--- | :--- | :--- |
| w/o memory | 54.64 | 56.41 | 44.31 |
| w/o retracing | 64.27 | 63.91 | 47.69 |
| Complete | 67.78 | 68.32 | 52.01 |

评估边界方面，论文未报告计算效率指标，且实验主要基于 Qwen2.5-72B 和 DeepSeek V3.1 两个骨干，未验证在小模型上的泛化能力。代码已开源，但超参数设置（如 $\alpha, \beta$ 权重）未详细披露，可能影响复现性。

## 关联研究分析

从问题动机看，MemSearch-o1 与 MemSearcher 均关注显式记忆管理，但 MemSearcher 依赖 RL 训练解决信用分配，而 MemSearch-o1 采用推理时规则。这种差异源于任务特性：MemSearch-o1 假设 LLM 具备足够的推理能力，仅需结构化记忆即可提升性能，而 MemSearcher 针对需要策略优化的长程任务。MemSearch-o1 未探索 RL 与记忆管理的结合，其在长程任务中查询策略的长期优化能力存疑。

从方法设计看，MemSearch-o1 与 Expand-then-Squeeze 均解决上下文噪声，但后者侧重压缩，前者侧重基于词元的结构化生长。Expand-then-Squeeze 通过长上下文 LLM 压缩文本，可能丢失细粒度语义，而 MemSearch-o1 通过记忆种子引导提取，保留了与查询目标对齐的关键信息。然而，MemSearch-o1 依赖词性分析，其在非英语或复杂句法结构中的泛化能力未经验证，而 Expand-then-Squeeze 基于语义压缩，可能更具语言无关性。

## 总结

MemSearch-o1 旨在解决智能体搜索中的记忆稀释问题，通过词元级记忆种子引导记忆生长，并利用贡献函数回溯重组记忆路径，实现了推理对齐的结构化记忆管理。实验显示，该框架在 HotpotQA 上取得 59.71% F1，显著优于 Search-o1 和 A-Mem 等基线，证明细粒度记忆管理对提升多跳推理质量的有效性。然而，论文未验证该方法在长程任务中动态策略优化的能力，且依赖词性分析的限制使其在复杂句法或非英语场景中的泛化能力存疑。当查询结构复杂或跨语言时，基于词元的记忆种子是否仍能保持语义对齐，论文未给出回答。
