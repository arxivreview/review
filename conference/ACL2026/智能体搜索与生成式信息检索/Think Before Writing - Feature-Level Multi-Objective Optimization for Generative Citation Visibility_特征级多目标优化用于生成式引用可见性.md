# ACL2026最新论文 ｜Think Before Writing: Feature-Level Multi-Objective Optimization for Generative Citation Visibility ｜特征级多目标优化用于生成式引用可见性

研究机构：南京大学

作者：Zikang Liu、Peilan Xu

论文原文见 [arXiv](https://arxiv.org/abs/2604.19113)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.19113)

> 生成式引擎通过选择性引用而非排名列表暴露内容，传统基于词元级文本编辑的生成式引擎优化（GEO）方法缺乏可解释性且难以平衡引用可见性与内容质量。本文提出 FeatGEO，将网页抽象为结构、内容与语言三层特征向量，在特征空间执行多目标进化优化以解耦高层决策与表面文本生成。该方法在三个生成引擎上稳定提升可见性并维持质量，但绝对数值受限于特定基准协议，且未探讨特征操纵的对抗风险。

## 研究背景

生成式答案引擎（如 Perplexity、Bing Chat）不再展示文档排名列表，而是通过引用少量检索源合成回答。在此范式下，内容的可见性取决于是否被引用，而非检索排名。这一机制引入了与传统搜索引擎优化（SEO）根本不同的优化问题：SEO 针对列表接口优化排名，而生成式引擎要求优化内容以被不透明的生成模型引用。

现有 GEO 研究主要依赖词元级启发式编辑，如插入关键词或增强权威语气。这类方法存在两个核心局限：首先，引用行为受潜在且多样的用户意图空间驱动，针对单一查询优化文本无法捕捉跨语义变体的稳定主题级引用偏好；其次，直接文本操作混淆了网页传达的信息与其语言实现，掩盖了系统性影响 LLM 引用决策的高层内容与结构属性。Aggarwal et al. (2024) 提出的词元级策略在孤立案例中有效，但在大规模基准上表现不稳定，且无法提供可见性与质量之间的可控权衡。

本文切入点在于将 GEO 重构为特征级多目标决策问题。通过抽象网页为可解释的高层属性，并在该结构化空间中进行优化，FeatGEO 解决了词元级方法缺乏可解释性与稳定性不足的问题，使优化过程能够同时兼顾引用可见性与内容质量。

## 核心方法

### 方法参照系

标准 GEO 流程基于检索增强生成（RAG）管道，通过修改网页表面文本以提升引用率。本文问题与该通用流程的关键差异在于：不直接编辑文本，而是优化抽象特征配置，由 LLM 根据特征生成新页面，从而解耦高层决策与表面实现。

### 主题级引用建模

传统方法针对单一查询优化，但 LLM 暴露于共享语义主题下的多样用户意图空间。本文引入主题级引用建模，通过生成语义相关查询集 $Q_\tau$ 探测潜在意图分布，聚合各查询下的引用源集合 $S_\tau$。定义引用频率 $c(s) = \frac{1}{|Q_\tau|} \sum_{q \in Q_\tau} \mathbb{I}(s \in S(q))$，高频引用源被视为主题一致的引用范例，作为下游优化的参考点。这一设计解决了单一查询优化目标不稳定的问题，捕捉了跨语义变体的稳定引用偏好。

### 特征空间多目标优化

网页被表示为三层特征向量 $\mathbf{x} = [\mathbf{x}_{struct}, \mathbf{x}_{content}, \mathbf{x}_{lang}]$，涵盖结构（标题层级、列表密度）、内容（统计密度、引用源频率）与语言（流畅度、关键词聚焦）属性。优化目标定义为 Pareto 最优意义下的双目标问题：

$$
\min_{\mathbf{x}} \left( -f_{vis}(\mathbf{x}), -f_{qual}(\mathbf{x}) \right)
$$

其中 $f_{vis}$ 为预期引用可见性，$f_{qual}$ 为内容质量。由于引用行为通过 LLM 生成与评估间接影响，且无梯度可访问，本文采用 NSGA-II 算法在特征空间执行黑盒多目标优化。每个个体对应一个特征配置，通过 LLM 生成网页并插入生成引擎评估，迭代更新种群以逼近 Pareto 前沿。这一设计解决了词元级方法无法提供可见性-质量权衡控制的问题，使优化过程可解释且适应不同引擎偏好。

## 实验评估

实验在 GEO-Bench 上进行，包含 10K 查询与 25 个领域，采用两阶段 RAG 管道（Google Search 检索 top-5 + LLM 生成引用答案）。对比方法包括基线、九种词元级启发式（Aggarwal et al., 2024）、AutoGEO-global 与 AutoGEO-instance。基线覆盖词元级编辑与规则重写路线，但缺失知识库中提到的 IF-GEO 等指令融合方法，可能影响对比全面性。

| 方法 | GPT-4o-mini Vis (%) | Gemini Vis (%) | Qwen-plus Vis (%) |
| :--- | :--- | :--- | :--- |
| Baseline | 13.34 | 8.89 | 5.20 |
| AutoGEO-global | 11.71 | 4.96 | 3.37 |
| FeatGEO | 18.31 | 15.35 | 10.17 |

FeatGEO 在三个引擎上均取得最高可见性，相对基线提升分别为 37%、73% 与 96%，同时维持或改善质量分数（81.52、76.14、77.12）。词元级启发式在 LLM 生成页面上普遍失效，可见性下降 10.92% 至 12.21%（GPT-4o-mini），揭示了“制度依赖饱和效应”：词元级重写对结构或风格有缺陷的页面有益，但对已流畅的生成内容产生负迁移。

消融实验显示，内容特征（统计、引用源）对可见性贡献最大，结构特征提供稳定支持，语言特征效果混合。Pareto 前沿分析表明，教育领域高可见性需显著牺牲质量，而食品领域可见性增益伴随最小质量损失，凸显多目标优化的必要性。评估边界方面，质量分数依赖 LLM 评判者，但跨评判者（Gemini、Claude）排名一致，确认结论鲁棒性；代码已开源，但计算成本细节仅在附录提供，未报告 GPU 需求。

## 关联研究分析

从问题动机看，FeatGEO 与 AutoGEO 均针对生成式引擎引用优化，但 AutoGEO 依赖规则提取与文本重写，而 FeatGEO 转向特征空间优化。差异根源在于任务特性：AutoGEO 假设引用偏好可通过自然语言规则捕捉，但规则泛化性差且无法处理可见性-质量权衡；FeatGEO 通过结构化特征解耦高层决策与表面实现，解决了规则方法的脆弱性。然而，特征空间的离散化粒度是否足以捕捉 LLM 引用的细微语义偏好，论文未给出回答。

从方法设计看，FeatGEO 与 CoSearch 同属联合优化范式，但 CoSearch 优化检索器与智能体协同，而 FeatGEO 仅优化生成端内容。差异源于任务边界：CoSearch 关注“如何找到信息”，FeatGEO 关注“如何让信息被引用”。FeatGEO 未涉及检索器调整，可能限制了其在动态查询场景中的适应性；特征级优化是否比词元级更容易被逆向工程用于恶意操纵，论文未探讨对抗鲁棒性。

## 总结

本文核心矛盾在于词元级 GEO 方法缺乏可解释性与稳定性，无法平衡引用可见性与内容质量。FeatGEO 抓住特征级抽象的切入点，通过解耦高层决策与表面实现，在特征空间执行多目标进化优化，解决了词元级方法的目标不稳定与权衡缺失问题。实验证明 FeatGEO 在三个引擎上稳定提升可见性（GPT-4o-mini 18.31% vs 基线 13.34%），且质量分数不降反升。然而，绝对数值受限于 GEO-Bench 协议，且未对比 IF-GEO 等强基线，绝对性能定位存疑。当特征空间维度扩展至更细粒度语义属性时，优化复杂度与 LLM 生成一致性之间的平衡是否恶化，论文未给出回答。
