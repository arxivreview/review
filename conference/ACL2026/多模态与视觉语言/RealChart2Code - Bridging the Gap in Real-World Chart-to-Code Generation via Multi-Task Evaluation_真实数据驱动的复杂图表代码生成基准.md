# ACL2026最新论文 ｜RealChart2Code: Bridging the Gap in Real-World Chart-to-Code Generation via Multi-Task Evaluation ｜真实数据驱动的复杂图表代码生成基准

研究机构：香港中文大学

作者：Jiajun Zhang、Yuying Li、Zhixun Li 等 15 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_ac7097cdb96a)

> 现有图表到代码（Chart-to-Code）基准多依赖合成数据或简单单面板布局，导致模型在简单任务上的高分无法反映其处理真实世界复杂多面板可视化及大规模原始数据的能力。RealChart2Code 通过引入真实 Kaggle 数据集、复杂复合布局及多轮迭代修正任务，构建了首个系统性评估上述能力的基准。该基准揭示了当前视觉语言模型（VLMs）在真实场景下的显著性能断崖，尤其是开源模型在语法执行与空间布局上的系统性失效。尽管其多智能体评估框架与人类判断高度一致，但限于 Matplotlib 生态且未提供针对真实数据泛化性的模型改进方案，其作为诊断工具的价值高于作为训练范式的贡献。

## 研究背景

图表代码生成的核心挑战在于将视觉像素映射为可执行的逻辑结构。这一过程要求模型不仅识别图表类型，还需精确解析数据映射关系、空间布局及样式属性。当输入从简单的单面板柱状图扩展至包含多个子图、复杂网格及大规模原始数据的复合可视化时，模型对视觉细节的敏感度与对数据逻辑的理解能力成为瓶颈。传统基准如 ChartMimic 和 Plot2Code 主要依赖合成数据或互联网爬取的简单图表，其任务复杂度不足以区分具备高级视觉推理能力的模型与仅能模仿表面特征的模型。

随着大语言模型在代码生成领域的进步，研究者开始关注模型在真实开发工作流中的表现。然而，现有评估体系缺乏对“从原始数据到复杂图表”这一完整链路的考察，更未涉及多轮对话中的代码迭代修正能力。RealChart2Code 的切入点在于打破合成数据的局限，通过引入经过严格筛选的真实 Kaggle 数据集（约 8.6 亿行数据）和手动设计的复杂可视化任务，构建了一个贴近真实开发场景的评估环境。该基准不仅测试模型的逆向工程能力，还通过错误注入机制模拟了用户反馈与代码调试的多轮交互过程，从而全面评估模型在复杂数据驱动场景下的鲁棒性。

## 核心方法

### 条件代码生成任务定义

RealChart2Code 将图表到代码任务形式化为条件代码生成问题。给定源图表图像 $V$ 和提示词 $P$，模型 $F(\cdot)$ 需生成可执行代码片段 $C$，使得渲染结果在视觉和结构上准确复现 $V$ 并满足 $P$ 的要求。该定义与通用代码生成流程的关键差异在于，其输出不仅是语法正确的代码，更是具有特定视觉保真度的数据可视化实现。

$$ C = F(V, P) $$

此公式强调了视觉输入 $V$ 与文本指令 $P$ 的联合约束作用，区别于仅依赖文本描述的代码补全任务。

### 多任务基准构建与评估框架

基准构建包含数据筛选、任务设计、代码实现及错误注入四个阶段。数据源来自 Kaggle，经两轮筛选保留 1,036 个高质量数据集，涵盖金融、医疗等 8 大领域。任务分为三类：Chart Replication（仅图像输入）、Chart Reproduction（图像+原始数据+元数据）和 Chart Refinement（多轮对话修正错误代码）。评估采用多智能体投票机制，对 8 项指标（如布局、数据一致性）进行 0-2 分打分，其中数据一致性在 Reproduction 任务中通过代码级比对程序化验证。

$$ S_{total} = \frac{1}{N} \sum_{i=1}^{N} \left( \mathbb{I}_{exec}(C_i) \cdot \sum_{j=1}^{8} w_j \cdot s_{ij} \right) $$

其中 $\mathbb{I}_{exec}$ 为执行成功指示函数，$s_{ij}$ 为第 $i$ 个样本在第 $j$ 项指标上的得分。该设计动机在于解决传统单一准确率指标无法捕捉视觉保真度细微差异的问题，通过多智能体投票提升评估的稳定性与人类偏好一致性。

## 实验评估

实验在 RealChart2Code 及 ChartMimic、Plot2Code 上进行，对比 5 个闭源和 9 个开源 VLMs。闭源模型中 Claude-4.5-Opus 表现最佳，RealChart2Code 平均得分为 8.2，而在 ChartMimic 上得分为 92.3；开源模型中 Qwen3-VL-235B 在 RealChart2Code 上仅得 3.6，但在 ChartMimic 上高达 80.4。

| 模型 | RealChart2Code (AVG Score) | ChartMimic (Score) | Plot2Code (Score) |
| :--- | :--- | :--- | :--- |
| Claude-4.5-Opus | 8.2 | 92.3 | 75.4 |
| Gemini-3-Pro-Preview | 8.1 | 96.0 | 79.5 |
| Qwen3-VL-235B | 3.6 | 80.4 | 69.8 |
| Intern-VL-3.5-241B | 3.4 | 76.9 | 69.0 |

数据表明，模型在简单基准上的高分与在真实复杂基准上的低分存在巨大落差，验证了 RealChart2Code 对模型能力的区分度。错误分析显示，开源模型主要受困于语法执行错误（46%）和布局结构失败（47%），而闭源模型则主要出现数据映射错误（46%），表明其代码能力较强但视觉-数据对齐存在偏差。

评估边界方面，基准限于 Matplotlib 生态，未覆盖其他可视化库；多智能体评估虽与人类判断 Cohen’s κ 达 0.83，但仍可能遗漏细微视觉瑕疵。可复现性上，代码与数据已开源，但 8.6 亿行数据的完整复现需大量存储资源，且多轮对话任务的评估依赖特定 API 格式，限制了部分模型的参与。

## 关联研究分析

从问题动机看，RealChart2Code 与 ChartMimic 的核心差异在于数据源的真实性与任务复杂度。ChartMimic 依赖合成或简单真实图表，旨在评估基础代码生成能力，而 RealChart2Code 引入大规模真实数据和复杂多面板布局，旨在暴露模型在真实开发场景中的短板。这一差异源于任务特性的根本不同：前者关注“能否生成代码”，后者关注“能否在复杂数据约束下生成正确且可维护的代码”。RealChart2Code 揭示的模型在真实数据下的性能断崖，暗示了合成数据训练在泛化性上的局限，这一发现对依赖合成数据预训练的模型具有警示意义。

从方法设计看，RealChart2Code 的多轮 Chart Refinement 任务与 REChart 的迭代编辑思路相似，但前者更强调多轮对话中的上下文一致性与局部更新能力。REChart 侧重于通过推理预算控制提升编辑效率，而 RealChart2Code 通过错误注入机制模拟真实调试流程，考察模型在用户反馈下的代码修正能力。这种设计差异反映了两种不同的评估视角：REChart 关注编辑过程的效率与保真度，RealChart2Code 关注模型在交互式环境中的鲁棒性与状态管理能力。RealChart2Code 发现的“回归性编辑”错误（即修正一处错误时引入新错误），揭示了当前模型在多轮代码维护中的系统性弱点，这是 REChart 等单轮或有限轮编辑任务未能充分暴露的问题。

## 总结

RealChart2Code 旨在解决现有图表代码生成基准在真实世界复杂场景下评估能力不足的问题。其切入点在于引入真实大规模数据、复杂多面板布局及多轮迭代修正任务，构建了首个系统性评估模型在真实开发工作流中表现的基准。通过 14 个主流 VLMs 的评估，该基准揭示了闭源与开源模型在真实场景下的显著性能差距，尤其是开源模型在语法执行与空间布局上的系统性失效。其边界在于限于 Matplotlib 生态且未提供针对真实数据泛化性的模型改进方案，仅作为诊断工具而非训练范式。当模型在简单基准上得分超过 90% 时，其在真实复杂基准上的得分骤降至 5 分以下，这一断崖式下降是否完全由数据规模与布局复杂度导致，还是反映了模型在视觉-数据对齐机制上的根本缺陷，论文未给出进一步归因。
