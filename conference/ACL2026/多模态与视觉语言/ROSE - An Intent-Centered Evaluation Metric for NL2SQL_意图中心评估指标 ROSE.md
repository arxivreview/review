# ACL2026最新论文 ｜ROSE: An Intent-Centered Evaluation Metric for NL2SQL ｜意图中心评估指标 ROSE

研究机构：香港科技大学、新加坡国立大学

作者：Wenqi Pei、Shizheng Hou、Boyan Li 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.12988)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.12988)

> NL2SQL 领域长期依赖执行准确率（EX）作为核心指标，但该指标在语义等价但形式不同、问题存在歧义或金标准错误时失效，导致模型性能被系统性低估或误判。现有 LLM 评估器虽引入语义判断，但仍锚定单一金标准 SQL，无法区分“逻辑正确但形式偏离”与“逻辑错误”。本文提出 ROSE，通过 Prover-Refuter 对抗级联实现意图中心评估，在金标准独立判断与对抗验证之间取得平衡。其在专家共识验证集上 Cohen’s κ 达 80.43%，较最强基线 FLEX 提升 24%，但依赖推理模型成本且验证集规模有限，长期稳定性存疑。

## 研究背景

NL2SQL 任务要求将自然语言问题 $Q$ 映射为可执行 SQL $S_p$，其正确性需同时满足语法有效性与语义意图匹配。传统评估依赖执行结果比对，即 $E_p = E_g$ 时判定正确，但此标准忽略了 SQL 实现的多样性：同一逻辑可因投影顺序、值格式化等产生不同执行结果，结构审计显示非规范但正确的形式导致高达 28.9% 的假阴性。更关键的是，当问题存在歧义时，多个合理 SQL 均能回答用户意图，但 EX 仅认可与金标准 $S_g$ 执行结果一致的那一个，Ambrosia 基准报告超过半数失败源于歧义。此外，大规模基准中 $S_g$ 本身存在错误，BIRD Dev 集金标准错误率达 6.91%，EX 会将这些标注错误传播至所有预测。

领域主流评估路线分为确定性指标与 LLM 基指标两类。确定性指标如 EX、ETM 依赖规则匹配，无法处理语义变体；LLM 基指标如 FLEX、LLM-SQL-Solver 引入语义判断，但仍以 $S_g$ 为参考基准，对歧义容忍度不足，且易被错误 $S_g$ 误导。本文切入点在于将 $S_g$ 的角色从“匹配参考”转变为“挑战证据”，通过独立意图判断与对抗验证分离，解决参考依赖导致的评估偏差。

## 核心方法

### 评估范式参照系

NL2SQL 评估的通用流程为：语法检查 → 执行结果比对 → 语义判断。确定性指标止步于执行比对，LLM 基指标在语义判断阶段引入 $S_g$ 作为参考。本文的关键差异在于语义判断阶段不再依赖 $S_g$ 作为唯一标准，而是构建独立意图判断与对抗验证的双阶段机制，将 $S_g$ 降级为挑战证据而非匹配基准。

### SQL Prover 独立意图判断

SQL Prover 在 $S_p$ 语法有效且 $E_p \neq E_g$ 时触发，仅使用问题 $Q$、数据库信息 $D$ 及接受标准 $C$ 独立判断 $S_p$ 是否满足用户意图，不访问 $S_g$。其设计动机是解决 LLM 基指标对 $S_g$ 的锚定问题：当 $S_g$ 存在错误或问题歧义时，参考依赖会导致正确预测被误判。Prover 输出布尔判断 $j_p$ 及推理依据 $R$，形式化为：

$$
j_p = \sigma_{\text{sem}}(S_p, Q | C)
$$

其中 $\sigma_{\text{sem}}$ 为语义正确性函数，仅基于 $Q$ 和 $D$ 评估 $S_p$ 的逻辑是否匹配用户意图。此独立判断避免了 $S_g$ 错误对评估结果的污染，为歧义问题提供合理预测的识别空间。

### Adversarial Refuter 对抗验证

Adversarial Refuter 在 Prover 判断后介入，使用 $S_g$ 作为挑战证据反驳 Prover 的接受判断。当 $E_p = E_g$ 时，Refuter 直接比对 $S_p$ 与 $S_g$ 的推理逻辑，识别偶然正确（false positive）；当 $E_p \neq E_g$ 且 Prover 接受 $S_p$ 时，Refuter 定位 $S_p$ 与 $S_g$ 的语义分歧，并基于 $Q$ 的意图重新评估哪一逻辑更忠实。其设计动机是抑制 Prover 的过度宽容：完全独立判断可能接受逻辑错误但形式相似的 $S_p$，Refuter 通过对抗机制引入 $S_g$ 的噪声信号作为约束。Refuter 输出布尔判断 $j_r$（true 表示推翻 Prover）及诊断标签 $L_q$（AmbQ 或 GoldX），形式化为：

$$
j_r = \text{Ref}(S_p, S_g, Q, D, C, E_p, E_g, R)
$$

其中 $\text{Ref}$ 为对抗验证函数，仅在 $E_p \neq E_g$ 时调用 $E_p, E_g, R$。此机制将 $S_g$ 从“标准答案”转化为“挑战证据”，既保留其信息价值，又避免参考依赖，同时输出诊断标签用于数据集审计。

## 实验评估

实验在 BIRD Mini-Dev（500 对）和 Spider Test 上进行，基线覆盖确定性指标（EX, EM, ETM）和 LLM 基指标（FLEX, LLM-SQL-Solver），但缺失结构感知指标变体如 ETM 的扩展版本。在 ROSE-VEC 验证集（585 专家共识样本）上，ROSE_o3-2504 的 Cohen’s κ 达 80.43%，Acc 91.79%，较 FLEX_o3-2504（κ 60.74%, Acc 85.47%）提升 24% κ 和 6.32% Acc。

| 指标 | κ (%) | Acc (%) | MCC (%) | F1 (%) |
| :--- | :--- | :--- | :--- | :--- |
| EX | 25.56 | 55.90 | 37.23 | 57.00 |
| FLEX_o3-2504 | 60.74 | 85.47 | 61.46 | 90.40 |
| ROSE w/o Refuter | 80.43 | 91.79 | 81.04 | 94.16 |
| ROSE_o3-2504 | 80.43 | 91.79 | 81.04 | 94.16 |

消融实验显示，移除 Refuter 后 ROSE w/o Refuter 的 κ 为 80.43%，与完整 ROSE 相同，表明在 ROSE-VEC 上 Refuter 未带来额外增益，但论文指出在 BIRD 子集上 Refuter 对抑制 false positive 至关重要。诊断标签精度方面，ROSE_o3-2504 识别 GoldX 的精度为 84.32%，AmbQ 为 91.23%，验证了其作为数据集审计工具的有效性。

评估边界方面，ROSE-VEC 仅 585 样本，统计显著性有限；ROSE 依赖推理模型（如 o3-2504），单线程平均耗时 22.48s，多线程下降至 3.35s，但成本仍高于 EX（1.22s）。代码已开源，但超参数和模型版本策略未完全披露，可复现性依赖推理模型版本稳定性。

## 关联研究分析

从问题动机看，ROSE 与 FLEX 均针对 EX 的假阴性问题，但 FLEX 通过精心设计的提示引导 LLM 判断 $S_p$ 与 $S_g$ 的一致性，仍保留参考依赖；ROSE 则通过 Prover 独立判断切断对 $S_g$ 的锚定，仅将 $S_g$ 作为 Refuter 的挑战证据。这一差异源于对歧义问题的处理：FLEX 对歧义容忍度部分，而 ROSE 通过 Prover 的独立判断为合理预测提供空间，Refuter 再基于 $Q$ 的意图仲裁分歧。根源在于任务特性：NL2SQL 中问题歧义是固有属性，参考依赖评估无法区分“逻辑正确但形式偏离”与“逻辑错误”，ROSE 的双阶段机制正是为此设计。

从方法设计看，ROSE 与 LLM-SQL-Solver 同属 LLM 基指标，但 LLM-SQL-Solver 直接提示 LLM 判断 $S_p$ 与 $S_g$ 的等价性，采用 Miniature & Mull 等策略寻找反例；ROSE 则引入 Prover-Refuter 对抗级联，将判断分解为独立意图验证与对抗挑战。这一差异源于对错误 $S_g$ 的鲁棒性需求：LLM-SQL-Solver 在 $S_g$ 错误时易被误导，而 ROSE 的 Prover 独立判断可识别 $S_g$ 错误，Refuter 通过诊断标签 GoldX 标记此类案例。论文未探索 Prover 与 Refuter 的权重平衡，当 $S_g$ 错误率高时，Refuter 的挑战可能过度抑制正确预测，这一条件依赖未在实验中充分验证。

## 总结

本文核心矛盾在于 EX 的参考依赖导致 NL2SQL 评估无法反映真实语义正确性，现有 LLM 基指标虽引入语义判断但仍锚定 $S_g$，无法处理歧义和错误金标准。ROSE 抓住“$S_g$ 角色转换”这一切入点，通过 Prover 独立意图判断与 Refuter 对抗验证分离，将 $S_g$ 从匹配参考降级为挑战证据，在 ROSE-VEC 上 Cohen’s κ 达 80.43%，较 FLEX 提升 24%。其边界在于验证集规模有限（585 样本），且 Refuter 在 ROSE-VEC 上未带来额外增益，仅在 BIRD 子集上体现价值，表明其效果依赖数据集特性。当 $S_g$ 错误率超过 25% 时，Refuter 的挑战机制是否会导致正确预测被过度抑制，论文未给出回答。
