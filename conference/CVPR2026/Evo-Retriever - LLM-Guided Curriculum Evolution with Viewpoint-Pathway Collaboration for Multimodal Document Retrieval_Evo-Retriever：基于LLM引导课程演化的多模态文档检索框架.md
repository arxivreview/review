> 复杂视觉文档检索（Complex Visual Document Retrieval, CVDR）旨在从大规模语料中精准定位包含特定文本、布局或视觉元素的页面，其核心难点在于文档异构结构导致的关键信息分散。现有基于多向量后期交互的检索模型虽提升了细粒度对齐能力，但受限于单一视角的空间感知不足、文本混淆脆弱性以及静态训练课程导致的模型能力停滞。Evo-Retriever通过引入多视角图像对齐与双向对比学习增强表征，并部署外部大语言模型作为元控制器动态调整负样本难度，实现了模型与训练课程的协同演化。该框架在ViDoRe V2基准上刷新了SOTA，但其依赖外部LLM API的训练架构在部署成本与训练效率间的权衡尚存疑。

## 研究背景

当检索模型面对包含图表、表格的复杂文档时，单一固定视角的图像编码难以整合空间上分散但语义相关的信息点，这种空间感知不足导致了对复杂布局理解的碎片化。为缓解此问题，多向量后期交互范式（如ColPali）通过Token级细粒度相似度计算取代了单向量全局匹配，显著提升了检索精度。然而，该范式下的对比学习策略主要挖掘视觉相似但语义不同的硬负样本，忽略了文本相似但视觉不匹配的干扰项，且训练过程通常采用静态阈值或预定义课程，无法适应模型判别能力的实时提升。

随着视觉语言模型（Vision-Language Model, VLM）在文档理解领域的普及，检索任务的重心从单纯的特征提取转向了表征鲁棒性与训练策略的优化。主流方法如Llama-Nemoretriever和GME虽采用了多阶段训练或数据合成，但其课程安排仍是静态的，导致模型在掌握初始硬负样本后，后续训练信号逐渐减弱，判别能力增长停滞。Evo-Retriever的切入点在于将训练课程视为一个动态决策过程，通过引入外部智能体监控训练状态并调整负样本难度，解决静态课程与模型演化速度失配的问题。

## 核心方法

### 方法参照系

Evo-Retriever基于Qwen2.5-VL骨干构建，沿用ColPali的多向量后期交互架构，通过投影层将Token嵌入映射至128维空间，并利用MaxSim计算查询与图像Token间的细粒度相似度。与标准流程的关键差异在于，本文不再使用固定的Top-K或随机负样本，而是通过多视角增强与双向对比学习构建更鲁棒的表征基础，并引入LLM元控制器动态调度负样本难度。

### 多视角图像对齐与双向对比学习

针对空间感知不足与文本混淆问题，本文在表征增强阶段引入多视角图像对齐（Multi-view Image Alignment, MVA）与双向对比学习（Bidirectional Contrastive Learning, BCL）。MVA通过旋转、缩放及拼接生成多视角复合图像，与原始图像并行处理，强制模型在不同几何变换下保持语义一致性。BCL则通过硬负查询合成（Hard Negative Query Synthesis, HNQ）管道生成文本相似但视觉不匹配的负查询，构建文档到查询的反向对比路径。整体优化目标采用基于Softplus的边际损失函数，独立处理每个硬负样本以稳定梯度信号：

$$
\mathcal{L}_{total} = \alpha \mathcal{L}_{forward} + \mathcal{L}_{backward}
$$

其中 $\mathcal{L}_{forward}$ 包含原始视角与增强视角的双重对比项，$\mathcal{L}_{backward}$ 约束反向检索路径。该设计迫使模型超越表面文本匹配，将语义锚定在视觉证据上，从而在空间变换和文本扰动下维持稳定的检索性能。

### LLM引导的演化课程

在表征增强基础上，LLM引导的演化课程（LLM-guided Evolutionary Curriculum, LLM-EC）取代了静态阈值挖掘。该模块分为离线候选池生成与在线课程演化两阶段。离线阶段利用当前模型自身表征空间检索Top-N最相似负文档，构建静态搜索空间；在线阶段由外部LLM元控制器根据训练状态摘要（如损失趋势、历史决策性能）动态选择难度区间。LLM遵循三阶段决策协议：探索阶段映射难度-性能景观，过渡阶段选择最优锚点，锁定阶段进行细粒度调整。这种机制允许课程难度随模型能力非单调调整，确保监督信号始终具有挑战性，避免了静态课程中负样本难度滞后于模型能力的现象。

## 实验评估

| 模型 | 规模 (B) | ViDoRe V2 Avg. (nDCG@5 %) | MMEB VisDoc Avg. (nDCG@linear 5 %) |
| :--- | :--- | :--- | :--- |
| Llama-Nemoretriever-3b-v1 | 4.4 | 63.5 | - |
| GME-Qwen2-VL-7B-Instruct | 8.3 | - | 75.18 |
| Evo-Retriever-3B | 3.0 | 63.3 | 75.91 |
| Evo-Retriever-7B | 7.0 | 65.2 | 77.12 |

实验在ViDoRe V2和MMEB (VisDoc)两个基准上进行，前者侧重跨语言零样本检索，后者评估结构复杂文档的泛化能力。基线覆盖了Llama-Nemoretriever、GME、ColPali等主流多向量与单向量方法。Evo-Retriever-7B在ViDoRe V2上取得65.2%的nDCG@5，较前SOTA Llama-Nemoretriever提升1.7%；在MMEB上取得77.12%，超越GME的75.18%。值得注意的是，3B模型在ViDoRe V2上达到63.3%，接近7B基线水平，暗示动态课程对小模型的能力挖掘更为显著。

消融实验揭示了各组件的贡献：仅添加MVA使nDCG@5从61.17%提升至62.25%（+1.08%），而固定窗口课程策略（如Fixed Window 80-98%）仅达62.10%，低于LLM-EC的63.05%。探索阶段的禁用导致性能下降1.19%，验证了初始难度自适应的重要性。此外，将235B控制器替换为32B模型后性能未显著下降，表明LLM-EC的有效性不依赖于超大规模控制器的推理能力，而是源于其基于自然语言协议的灵活决策逻辑。

评估协议主要关注检索精度（nDCG），未报告训练延迟或LLM API调用成本。代码与模型权重已在HuggingFace开源，使用8张H20 GPU进行数据并行训练，LoRA秩设为32。由于缺乏计算效率维度的量化数据，LLM元控制器引入的额外训练开销与精度增益之间的具体权衡尚不明确。

## 关联研究分析

从问题动机看，Evo-Retriever与GME等数据合成方法均旨在解决硬负样本质量不足的问题，但GME依赖预定义的静态课程，而本文通过LLM动态调整难度区间，解决了模型能力演化与课程难度滞后的矛盾。这一差异源于对训练过程动态性的不同理解：静态方法假设课程难度可预先确定，而动态方法认为难度应随模型状态实时反馈调整。从方法设计看，本文与ColPali共享多向量后期交互架构，但ColPali仅关注推理时的细粒度匹配，而Evo-Retriever在训练阶段引入MVA与BCL，增强了表征对空间变换和文本扰动的鲁棒性。这种训练-推理解耦的设计使得模型在保持轻量级推理成本的同时，提升了复杂文档的检索精度。

## 总结

Evo-Retriever旨在解决复杂视觉文档检索中静态训练课程与模型能力演化失配导致的判别能力停滞问题。通过多视角对齐与双向对比学习增强表征鲁棒性，并引入LLM元控制器动态调度负样本难度，该框架实现了模型与课程的协同演化。实验证明其在ViDoRe V2和MMEB基准上均取得SOTA性能，其中7B模型在ViDoRe V2上达到65.2%的nDCG@5。然而，其依赖外部LLM API进行训练控制的架构引入了额外的计算与通信开销，且评估未涵盖训练效率维度。当LLM控制器的推理延迟与API成本被计入总训练开销时，动态课程带来的精度增益是否仍具有经济可行性，论文未给出回答。
