# CVPR2026最新论文 ｜MMBench-GUI: A Unified Hierarchical Evaluation Framework for Multi-Platform GUI Agents ｜多平台GUI智能体层级化评估框架

研究机构：上海交通大学、厦门大学

作者：Xuehui Wang、Zhenyu Wu、JingJing Xie 等 25 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_dfb4a6c27b7a)

> 现有GUI智能体基准往往割裂感知、定位与执行能力，且仅关注任务成功率而忽视交互效率，导致无法诊断智能体在复杂工作流中的具体失效环节。MMBench-GUI通过构建覆盖六大操作系统的四级能力层级，并引入效率-质量感知（Efficiency-Quality-Aware, EQA）指标，实现了从静态理解到跨应用协作的系统性评估。该框架揭示了视觉接地精度是决定任务成功的关键瓶颈，同时暴露了当前智能体在长程规划与跨应用状态追踪上的严重短板。尽管其层级化设计提供了精细的诊断视角，但L4任务极低的成功率是否完全归因于模型能力而非任务设计复杂度，仍需进一步验证。

## 研究背景

GUI智能体在动态界面中执行任务时，面临从像素级元素定位到多步逻辑规划的连续挑战。视觉接地（GUI Grounding）要求模型将自然语言指令映射为精确的屏幕坐标，这是执行点击等动作的前提；然而，单步定位的准确性并不保证多步任务的最终成功，因为长程任务中的错误会累积，且智能体需在不同应用间维持状态一致性。这种从感知到执行的层级依赖关系，使得单一维度的评估难以定位性能瓶颈。

早期基准如ScreenSpot聚焦于空间定位，OSWorld侧重桌面端端到端任务成功率，但均存在场景覆盖狭窄或能力维度单一的问题。这种碎片化评估导致研究者无法判断智能体的失败是源于视觉理解偏差、定位偏移，还是规划逻辑缺陷。同时，传统成功率指标无法区分高效执行与冗余操作，掩盖了智能体在步骤预算上的低效问题。MMBench-GUI旨在通过统一的多平台层级框架，解决能力诊断碎片化与效率评估缺失的双重困境。

## 核心方法

### 层级化任务架构

MMBench-GUI将GUI智能体能力解构为四个递进层级：L1内容理解、L2元素接地、L3单应用任务自动化及L4跨应用任务协作。该架构的核心设计动机在于建立能力间的因果链条，使高阶任务的失败可追溯至低阶能力的缺陷。所有层级共享同一组GUI场景与应用，确保评估的一致性。L1和L2为离线静态任务，L3和L4为在线交互任务，这种混合模式兼顾了评估效率与真实环境模拟。

### 效率-质量感知指标

针对传统成功率（Success Rate, SR）无法量化交互成本的问题，MMBench-GUI提出EQA指标。该指标通过计算成功-步骤预算曲线下的面积，联合评估任务完成度与动作冗余度。其数学定义为：

$$ \text{EQA} \propto \sum_{m=1}^{M} \text{SR}(B_m) $$

其中 $B_m$ 为递增的步骤预算，$\text{SR}(B_m)$ 为在预算 $B_m$ 内截断后的成功率。该公式的物理含义是：智能体若能在较少步骤内达成高成功率，则获得更高的EQA分数；反之，依赖冗长序列才成功的智能体将被惩罚。这一设计直接回应了现有智能体“成功但低效”的普遍现象，将效率提升为一等公民评估维度。

### 跨平台统一协议

为实现跨平台可比性，MMBench-GUI将Windows、macOS、Linux、iOS、Android及Web的动作空间标准化为统一的点击、输入与滚动接口。特别地，该基准首次将macOS任务套件作为一级组件纳入统一评估协议，填补了此前基准在macOS覆盖上的空白。数据标注采用多模型生成加人工校验的流程，L1使用Claude 3.7生成问题并经GPT-o4-mini验证，L2指令则区分基础视觉描述与高级功能暗示，以测试不同难度的接地能力。

## 实验评估

| 模型 | L1 Overall (Easy) | L2 Avg (Basic) | L3 Avg SR | L4 Avg SR |
| :--- | :--- | :--- | :--- | :--- |
| InternVL3-72B | 79.15 | 72.20 | - | - |
| UI-TARS-72B-DPO | 40.18 | 74.25 | 26.1 | 8.78 |
| GPT-4o | 60.16 | 2.9 | 7.2 | - |
| Qwen-Max-VL | 68.15 | 58.0 | - | - |

实验覆盖开源与闭源模型，基线包括UI-TARS、InternVL3、GPT-4o及Claude系列。L1结果显示InternVL3-72B在内容理解上表现最优（79.15%），但UI-TARS-72B-DPO仅得40.18%，表明其视觉理解能力相对较弱。L2接地任务中，UI-TARS-72B-DPO以74.25%的平均准确率领先，而GPT-4o仅2.9%，证实了通用语言模型在像素级定位上的严重缺陷。L3单应用自动化中，UI-TARS-72B-DPO取得26.1%的成功率，显著高于GPT-4o的7.2%。L4跨应用协作任务成功率骤降至8.78%，揭示当前智能体在多应用状态追踪上的极端脆弱性。

消融分析显示，结合通用模型与专用接地模块（如GPT-4o+UI-TARS）能显著提升L3性能，从6.13%提升至17%以上，验证了模块化设计在接地环节的有效性。平台差异方面，移动端与Web环境下的准确率普遍高于桌面端，UI-TARS在Android和Web上超过80%（Basic设置），而在Linux和iOS上表现相对较弱。EQA指标进一步显示，即使成功率相近，不同智能体的步骤冗余度存在显著差异，部分模型需接近最大步骤限制才能完成任务。

评估协议采用程序化状态检查判定任务成功，确保客观性。代码与数据已开源，但L3/L4任务依赖虚拟化环境，复现需配置特定OS镜像。指标完备性上，EQA虽量化了效率，但未考虑计算延迟或内存占用，且L4任务成功率极低可能受任务设计复杂度影响，而非纯粹反映模型能力。

## 关联研究分析

从问题动机看，MMBench-GUI与OSWorld均关注端到端任务成功率，但OSWorld局限于桌面平台且缺乏效率维度，而MMBench-GUI通过引入EQA指标和六平台覆盖，解决了评估维度单一与场景狭窄的问题。这一差异源于MMBench-GUI对“效率”作为独立能力维度的重视，而OSWorld更侧重于任务完成的二元判定。从方法设计看，MMBench-GUI的层级化结构与ScreenSpot的单一接地评估形成对比，后者仅测试定位精度，无法诊断定位错误对后续规划的影响。MMBench-GUI通过共享场景的层级递进，实现了能力间的因果追溯，但这也引入了高阶任务对低阶能力的依赖假设，若L1/L2能力存在补偿机制，该依赖关系可能被高估。

## 总结

MMBench-GUI旨在解决GUI智能体评估中能力维度割裂与效率指标缺失的矛盾。通过构建四级层级架构与EQA指标，该框架实现了从感知到协作的系统性诊断，揭示了视觉接地是任务成功的关键瓶颈，且当前智能体在跨应用协作上存在严重短板。实验表明UI-TARS-72B-DPO在L2接地与L3自动化上表现最优，但L4成功率仅8.78%，暴露了长程规划与状态追踪的局限。该基准的边界在于L4任务极低的成功率可能混淆了模型能力不足与任务设计过难的因素，且未涵盖计算效率维度。当L4任务成功率提升至20%以上时，EQA指标能否有效区分不同规划策略的效率差异，论文未给出回答。
