# CVPR2026最新论文 ｜LiteVGGT: Boosting Vanilla VGGT via Geometry-aware Cached Token Merging ｜几何感知缓存Token合并加速VGGT

研究机构：南京大学、浙江大学

作者：Zhijian Shu、Cheng Lin、Tao Xie 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2512.04939)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2512.04939)

> 多视图三维重建中，全局注意力的二次复杂度导致VGGT在处理数百张图像时内存溢出或耗时数十分钟，阻碍了大规模场景的实时应用。现有加速方案如通用Token合并忽略了3D几何Token的空间耦合特性，导致细节丢失。本文通过构建几何感知特征图指导Token分区，并缓存层间合并索引，在保持重建精度的前提下实现10倍加速。该策略有效缓解了长序列瓶颈，但其依赖离线微调以恢复精度，限制了纯推理场景下的泛化能力。

## 研究背景

VGGT通过帧间全局自注意力机制联合预测相机位姿、深度与点图，其核心在于将所有图像Token拼接后进行全序列交互。这种设计确保了跨视图几何一致性，但计算量随图像数量呈二次方增长。当输入序列超过500张图像时，原始VGGT在96GB显存的H20 GPU上即发生内存溢出（OOM），即便移除冗余操作的优化版本VGGT*，处理1000张图像仍需20分钟。这一效率瓶颈使得前馈式重建范式难以落地于无人机测绘、自动驾驶等需要处理长序列图像的大规模场景。

针对该瓶颈，现有加速路线存在明显局限。流式处理（如StreamVGGT）牺牲了单次前向传播的端到端能力；模型量化（如QuantVGGT）依赖耗时的跨场景校准，损害通用性；通用Token合并（如FastVGGT）借鉴自LLM或扩散模型，采用随机采样或固定步长池化，未考虑VGGT Token与图像块及3D点云的一一对应关系。这种忽略几何耦合性的做法导致高信息量Token（如边缘、纹理）被错误合并，造成几何细节丢失与重建质量下降。LiteVGGT的切入点在于识别VGGT Token的几何冗余特性：局部图像区域的Token具有固有的几何相关性，且这种相似性在相邻网络层间保持稳定。

## 核心方法

### 方法参照系

通用Token合并策略通常将Token随机划分为源（src）与目标（dst）集合，通过特征平均减少序列长度。该流程假设Token间无强空间约束，适用于语义理解任务。然而，VGGT的Token携带局部几何信息，随机合并会破坏空间连续性，导致3D重建中的几何幻觉。本文的关键差异在于引入几何先验指导分区，并利用层间稳定性消除重复计算。

### 几何感知特征图与Token分区

设计动机在于解决通用合并策略中“高信息量Token被低信息量Token稀释”的失效问题。本文首先构建几何感知（Geometry-aware, GA）特征图，融合像素梯度（Sobel算子提取边缘）与Token方差（衡量语义几何变异性）：

$$ \Psi_{GA} = \alpha \Psi_g + \beta \Psi_v $$

其中 $\Psi_g$ 和 $\Psi_v$ 分别为归一化的梯度图与方差图。基于该图，Token被划分为三类：GA Token（每帧得分最高的10%，保留以维持关键几何细节）、dst Token（空间平衡的锚点，包括首帧所有Token及其他帧每2×2网格中GA得分最低的Token）、src Token（其余冗余Token）。此分区策略确保边缘与纹理区域不被合并，而平滑区域被最大化压缩。

### 缓存合并与解合并机制

承接GA分区，本文通过余弦相似度将src Token匹配至最相似的dst Token，并更新dst特征：

$$ x'_d = \frac{x_d + \sum_{s \in S_d} x_s}{|S_d| + 1} $$

其中 $S_d$ 为分配给dst Token $d$ 的src Token集合。由于Token相似性在相邻层间稳定，合并索引每6层计算一次并缓存复用，避免了逐层重复的大矩阵运算。在全局注意力后，通过Token复制（Unmerging）恢复原始序列长度，确保后续帧注意力与预测头能获取完整的稠密几何信息。该机制在降低二次方复杂度的同时，通过缓存策略额外减少约25%的延迟。

## 实验评估

实验在ScanNet-50、7Scenes、NRGBD、Tanks & Temples、DTU及CO3Dv2上进行，对比Fast3R、CUT3R、VGGT、FastVGGT等基线。基线覆盖了流式、量化及通用合并路线，但缺失MASt3R-SLAM等SLAM类方法，可能低估了在线重建场景下的竞争强度。

| 方法 | 7Scenes Acc↓ | 7Scenes Time↓ | NRGBD Acc↓ | NRGBD Time↓ |
| :--- | :--- | :--- | :--- | :--- |
| VGGT | 0.021 | 133.1s | 0.024 | 233.1s |
| FastVGGT | 0.021 | 36.5s | 0.029 | 70.7s |
| LiteVGGT | **0.020** | **19.2s** | **0.031** | **36.3s** |

LiteVGGT在7Scenes上取得0.020的Accuracy，优于VGGT的0.021，且推理时间从133.1秒降至19.2秒，实现近7倍加速。在NRGBD上，其Accuracy为0.031，虽略高于VGGT的0.024，但显著优于FastVGGT的0.029，表明几何感知策略在非刚体物体重建中保留了更多细节。

| 模块 | DTU Acc↓ | DTU Time↓ | 内存 (GiB) |
| :--- | :--- | :--- | :--- |
| VGGT* | 0.508 | 1275.6s | OOM |
| + GA Token Merging | 0.789 | 264.3s | 60.34 |
| + Fine-tuning | 0.587 | 264.3s | 60.34 |
| + Cache Merge Indices | 0.621 | 200.6s | 59.28 |
| + FP8 Quantization | **0.652** | **127.9s** | **45.31** |

消融实验显示，GA Token合并导致DTU Accuracy从0.508恶化至0.789，微调将其恢复至0.587，证明合并策略引入了显著精度损失。缓存合并索引进一步将时间从264.3秒降至200.6秒，而FP8量化在保持精度的同时将内存降至45.31 GiB。微调步骤是恢复精度的关键，但也引入了对特定数据集的依赖。

评估协议采用Chamfer Distance、Accuracy、Completeness及AUC@3°等指标，但未报告置信区间，且Tanks & Temples的F1分数阈值经过5倍/10倍缩放以过滤噪声，这可能掩盖了细微的几何偏差。代码已开源，但微调需8张H20 GPU训练3天，限制了复现门槛。

## 关联研究分析

从方法设计看，LiteVGGT与AVGGT同属高效前馈重建路线，但路径截然不同。AVGGT通过全局到帧转换及子采样注意力降低计算量，侧重于注意力机制本身的稀疏化；LiteVGGT则通过Token合并减少参与注意力的Token数量，侧重于数据冗余的消除。AVGGT无需重训练即可加速，而LiteVGGT依赖微调恢复精度，这暗示Token合并对特征分布的扰动大于注意力稀疏化。两者在极端复杂场景下的表现差异，可能源于稀疏注意力丢失长程依赖与Token合并丢失局部细节的不同失效模式。

从问题动机看，LiteVGGT与FastVGGT均针对VGGT的效率瓶颈，但FastVGGT采用通用Token合并策略，忽略了3D几何Token的空间耦合特性。LiteVGGT通过GA特征图显式保留边缘与纹理Token，解决了FastVGGT在细节丰富场景下的重建质量下降问题。这一差异源于任务特性：3D重建对局部几何精度的敏感度远高于语义理解任务。然而，GA特征图仅依赖Sobel算子与方差，是否足以应对弱纹理或动态场景中的几何变化，论文未给出充分验证。

## 总结

LiteVGGT旨在解决VGGT在长序列处理中的内存与计算瓶颈，其切入点在于利用3D Token的几何冗余性与层间稳定性，通过几何感知分区与缓存合并实现高效压缩。该方法在7Scenes上以0.020的Accuracy和19.2秒的推理时间，实现了优于VGGT精度且近7倍的速度提升。然而，其依赖离线微调以恢复合并带来的精度损失，限制了在零样本或动态场景中的直接应用。当输入序列包含大量弱纹理或动态物体时，基于静态梯度与方差的GA特征图是否仍能准确识别关键几何Token，论文未提供相关实验证据。
