# CVPR2026最新论文 ｜UETrack: A Unified and Efficient Framework for Single Object Tracking ｜统一高效单目标跟踪框架

研究机构：大连理工大学、香港城市大学

作者：Ben Kang、Jie Zhao、Xin Chen 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.01412)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.01412)

> 多模态单目标跟踪旨在融合可见光、深度、热红外等异构信号以突破单一RGB模态在复杂场景下的感知瓶颈，但现有统一框架往往因架构复杂导致计算开销巨大，难以在嵌入式设备上实时部署。UETrack针对这一效率瓶颈，提出基于Token-Pooling的混合专家机制与目标感知自适应蒸馏策略，在保持多模态融合能力的同时显著降低推理延迟。该框架在Jetson AGX等平台上实现了实时性能，但其在长序列遮挡场景下的绝对精度仍低于非实时SOTA，且未验证状态空间模型在实时性上的潜在优势。

## 研究背景

单目标跟踪（SOT）的核心挑战在于如何在视频序列中持续定位指定目标，而实际应用中单一RGB模态在低光照或遮挡下信噪比急剧下降。为弥补这一短板，研究者引入深度、热红外等互补模态，但不同传感器捕获的特征分布存在巨大差异，导致静态特征拼接难以充分利用互补信息。参数高效微调（PEFT）成为适配新模态的主流策略，旨在以低成本注入多模态知识，然而现有高效跟踪器多局限于RGB场景，缺乏对多模态输入的统一高效处理机制。

多模态跟踪领域已形成统一框架与专用模型并存的格局。早期方法如ViPT通过提示学习冻结RGB骨干，解决了全参数微调的高昂成本，但架构复杂度随模态数量增加而上升。SUTrack采用统一令牌处理多模态，消除了额外模块，但计算开销仍限制其实时部署。现有方法在表示质量与计算成本之间做出取舍，导致在资源受限设备上难以兼顾精度与速度。UETrack的切入点在于，通过轻量化架构与稀疏专家结构，解决统一多模态跟踪在嵌入式设备上的实时性瓶颈，填补高效多模态跟踪的空白。

## 核心方法

### 统一多模态输入编码

UETrack继承SUTrack的统一建模路线，将深度、热红外、事件数据与RGB图像沿通道维度拼接为6通道复合输入，语言模态通过CLIP编码器获取令牌嵌入。所有嵌入联合输入Transformer骨干，实现单模型处理五种模态。该设计的关键差异在于，本文未采用模态特定模块，而是通过统一令牌空间降低参数冗余，为后续高效计算奠定基础。

### Token-Pooling-based Mixture-of-Experts (TP-MoE)

传统MoE依赖离散门控函数进行令牌路由，引入排序与跨专家通信开销，导致推理延迟增加。TP-MoE消除门控机制，采用基于相似度的软分配策略，通过加权特征聚合实现专家协作。输入令牌被划分为$E$个子空间，每个子空间经平均池化后生成专家令牌，计算相似度矩阵$S \in \mathbb{R}^{L_1 \times L_2}$，经Softmax生成路由权重$S_a$。该权重作为连续路由图，使令牌与专家进行全并行交互，无需硬门控。

$$
\mathbf{O} = \text{Merge}\left( \sum_{i=1}^{E} \text{Expert}_i(\text{Split}(\mathbf{T}_a)) \cdot S_a \right)
$$

此公式表明，输出$\mathbf{O}$通过专家处理后的令牌与路由权重的加权求和生成，实现了子空间专业化与特征多样性，缓解了模态异质性。设计动机在于，轻量级模型难以捕捉多模态互补信息，TP-MoE通过软分配增强表示能力，同时保持计算效率。

### Target-aware Adaptive Distillation (TAD)

教师模型在遮挡或变形样本上预测不可靠，直接蒸馏会引入噪声监督。TAD引入自适应网络，基于学生与教师特征动态决定蒸馏开关。自适应网络输入搜索区域特征序列，经全局平均池化、MLP降维后，通过Gumbel-Softmax输出二值决策$\alpha$。当$\alpha=1$时，使用教师分布与特征图监督学生；否则仅使用学生自身预测。

$$
\mathcal{L}_{\text{student}} = \mathcal{L}_c + \lambda_g \mathcal{L}_g + \lambda_{l1} \mathcal{L}_{l1} + \mathcal{L}_t + \alpha (\lambda_{kd} \mathcal{L}_{kd} + \lambda_f \mathcal{L}_f)
$$

该损失函数中，$\alpha$动态调节蒸馏项权重，过滤误导性信号。设计动机在于，困难样本上教师输出不可靠，自适应机制避免负迁移，提升训练稳定性。

## 实验评估

实验在12个数据集与3个硬件平台（GPU、CPU、Jetson AGX）上进行，基线覆盖SUTrack、ViPT、OneTracker等统一框架，但缺失LLMTrack等语义跟踪方法，因任务侧重不同。UETrack-B在LaSOT上取得69.2% AUC，在AGX上运行163 FPS，较SUTrack-T快1.8倍，精度相当。

| 方法 | LaSOT AUC (%) | AGX FPS | 参数 (M) |
| :--- | :--- | :--- | :--- |
| UETrack-B | 69.2 | 60 | 13 |
| SUTrack-T | 67.8 | 34 | - |
| MixFormerV2-S | 67.8 | 63 | - |

消融实验显示，TP-MoE专家数量从8增至32时，平均性能下降0.5%，表明过多专家引入冗余。移除TP-MoE导致LaSOT AUC下降0.8%，验证其必要性。自适应蒸馏中，加入KL散度与特征模仿损失分别提升0.3%与0.5%，自适应机制额外提升1.0%，证明动态监督的有效性。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码已开源，超参数与训练细节完整披露，可复现性良好。但实验未涵盖长序列遮挡场景，且未对比状态空间模型（SSM）在实时性上的表现，评估协议存在局限。

## 关联研究分析

从方法设计看，UETrack与OneTrackerV2均使用MoE，但OneTrackerV2采用双MoE与元合并器，侧重多模态数据贡献不均的处理，而UETrack采用单TP-MoE，通过软分配消除门控延迟，侧重极致轻量化。这一差异源于任务特性：OneTrackerV2面向高精度统一框架，UETrack面向实时部署，前者可容忍额外计算开销，后者必须严格控制延迟。

从问题动机看，UETrack与SEATrack均追求高效，但SEATrack依赖LoRA进行参数高效微调，UETrack依赖TP-MoE进行容量扩展。SEATrack通过冻结骨干与轻量模块适配新模态，UETrack通过替换FFN层增强多模态表示。两者代表PEFT的不同实现路径，SEATrack更侧重模态对齐，UETrack更侧重特征建模。查询侧增强在数据充足时是否仍有增益，论文未给出回答，这可能影响其在大规模多模态数据上的泛化能力。

## 总结

UETrack要解决的核心矛盾是统一多模态跟踪框架在嵌入式设备上的实时性瓶颈。现有方法如SUTrack虽实现统一建模，但计算开销大，难以实时部署；UETrack通过TP-MoE的软分配机制与TAD的自适应蒸馏，在保持多模态融合能力的同时降低延迟。实验证明，UETrack-B在LaSOT上取得69.2% AUC，在AGX上运行60 FPS，较SUTrack-T快1.8倍。其边界在于，绝对精度低于非实时SOTA，且未验证SSM在实时场景的优势。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
