# CVPR2026最新论文 ｜DSFlash: Comprehensive Panoptic Scene Graph Generation in Realtime ｜全景场景图生成的实时化与效率优化

作者：Julian Lorenz、Vladyslav Kovganko、Elias Kohout 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.10538)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.10538)

> 全景场景图生成（Panoptic Scene Graph Generation, PSGG）旨在从图像中提取像素级实例掩码及其间的语义关系，以支持具身智能等下游任务。现有方法虽在精度上取得进展，但普遍忽视计算延迟，难以部署于资源受限的边缘设备。DSFlash 通过共享骨干网络、双向关系预测及动态剪枝策略，在保持 SOTA 精度的同时实现了毫秒级推理。该方法验证了高效架构在实时场景理解中的可行性，但其两阶段解耦设计是否牺牲了全局上下文建模能力，仍存疑。

## 研究背景

场景图生成通常依赖边界框定位实例，但边界框无法捕捉不规则形状对象的空间细节，导致关系预测精度受限。全景分割通过像素级掩码提供更精细的空间上下文，成为 PSGG 的核心基础。然而，掩码级定位的计算开销远高于框级检测，使得实时性成为该任务落地的主要瓶颈。

SGG 领域长期聚焦于提升关系预测精度，主流一阶段端到端方法虽能捕捉对象间依赖，但参数量庞大、推理延迟高。DSFormer 等两阶段方法通过解耦分割与关系预测实现了精度突破，但需运行两个独立骨干网络，资源效率低下。DSFlash 的切入点在于：不追求极致的单点精度，而是通过架构重构，在资源受限条件下实现“精度-延迟”的帕累托最优，填补了低延迟 PSGG 的研究空白。

## 核心方法

### 方法参照系

DSFlash 基于 DSFormer 的两阶段范式，但摒弃了其“分割与关系预测使用独立骨干”的设计。关键差异在于：DSFlash 将分割骨干（EoMT）的特征直接复用为关系预测的输入，消除了二次前向传播，从而在保持掩码级定位优势的同时，大幅降低计算冗余。

### 共享骨干与掩码嵌入

传统两阶段方法需分别运行分割模型和关系模型，导致特征提取重复。DSFlash 采用冻结的 EoMT 骨干，直接从其提取特征补丁（Feature Patches），并引入掩码嵌入模块。对于每对实例掩码，计算掩码覆盖补丁面积的比例 $r_s, r_o$，并添加可学习位置编码：

$$ e_{patch} = f_{patch} + r_s \cdot t_s + r_o \cdot t_o + t_{bg} $$

该公式将空间位置信息注入特征，使 Transformer 颈部（Neck）能区分主客体位置，解决了独立骨干方案中特征对齐困难的问题。

### 双向预测与动态剪枝

为减少关系预测的前向次数，DSFlash 提出双向关系预测头。对于实例对 $(A, B)$，单次前向传播同时预测 $A \to B$ 和 $B \to A$ 的关系，将计算量减半。此外，引入基于掩码的动态补丁剪枝（Dynamic Patch Pruning），移除背景区域的补丁令牌，仅保留前景相关特征进入颈部。结合 Token Merging (ToMe) 技术，进一步压缩注意力层计算。这种组合策略在不显著损失精度的前提下，将延迟从 458 ms 降至 18 ms。

## 实验评估

| 方法 | mR@50 (SGDet) | Latency (ms) | # Params |
| :--- | :--- | :--- | :--- |
| DSFormer | 30.70 | 458 | 330M |
| DSFlash-L | 30.90 | 50 | 340M |
| DSFlash-S* | 25.05 | 18 | 40M |
| REACT | 19.00 | 19 | 43M |

DSFlash-L 在 PSG 数据集 SGDet 协议下以 30.90 的 mR@50 超越 DSFormer (30.70)，同时延迟降低至 50 ms。DSFlash-S* 虽精度降至 25.05，但实现了 18 ms 的超低延迟，优于 REACT 的 19.00 精度。基线覆盖了两阶段（DSFormer）与实时框级方法（REACT），但缺乏 VLM 辅助的开放词汇方法对比，因本文聚焦封闭集实时任务。

| 优化策略 | mR@50 | Latency (ms) |
| :--- | :--- | :--- |
| Baseline (DSFormer) | 30.7 | 445 |
| Unified Backbone | 25.0 | 41 |
| Gated Bidir. Pred. | 28.8 | 29 |
| No Seg. Upscaling | 28.5 | 23 |
| EoMT-3S | 25.1 | 18 |

消融实验显示，统一骨干导致精度从 30.7 降至 25.0，但延迟骤降 91%。双向预测头将精度恢复至 28.8，延迟降至 29 ms。动态剪枝在 GTX 1080 上将延迟从 230 ms 降至 205 ms，精度仅下降 2.13。这表明剪枝对低算力硬件收益显著，而对高算力硬件（H100/3090）影响有限，因后者已能并行处理所有令牌。

评估采用 SingleMPO 协议，纠正了以往 SOTA 方法中“一对多掩码”导致的 mR@50 虚高问题。DSFlash 通过防止同一实例生成多个掩码，确保了指标公平性。代码与检查点将在接收后发布，训练仅需单张 GTX 1080 运行 24 小时，复现门槛较低。

## 关联研究分析

从问题动机看，DSFlash 与 REACT 均针对实时 SGG，但 REACT 基于 YOLOv8 的框级检测，而 DSFlash 采用掩码级定位。DSFlash 在 PSG 任务上精度（30.90 vs 19.00）与延迟（50 ms vs 19 ms）均占优，表明掩码提供的空间上下文在关系预测中价值显著，且 EoMT 骨干的并行效率足以抵消掩码计算开销。

从方法设计看，DSFlash 与 DSFormer 同属两阶段范式，但 DSFormer 强调精度极致，DSFlash 强调效率。DSFlash 的共享骨干设计牺牲了部分分割精度（mR@50 从 30.7 降至 25.0 后通过优化恢复），换取了训练速度与推理延迟的大幅降低。这种取舍在资源受限场景下合理，但在高精度需求场景下，独立骨干可能仍具优势。

## 总结

DSFlash 解决了 PSGG 中精度与实时性的矛盾，通过共享 EoMT 骨干、双向预测及动态剪枝，在 PSG 数据集上以 30.90 的 mR@50 实现 SOTA 精度，同时将延迟降至 18-50 ms。其边界在于：两阶段解耦虽提升效率，但可能限制全局上下文建模能力；实验仅覆盖静态图像，未验证视频流中的时序一致性。当支持集增大或场景复杂度提升时，共享骨干的特征复用是否仍能保持精度优势，论文未给出回答。
