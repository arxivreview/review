# CVPR2026最新论文 ｜CARE-Edit: Condition-Aware Routing of Experts for Contextual Image Editing ｜条件感知专家路由图像编辑

研究机构：香港科技大学

作者：Yucheng Wang、Zedong Wang、Yuetong Wu 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.08589)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.08589)

> 统一扩散编辑器在处理文本、掩码与参考图等多源条件时，常因静态融合机制导致信号冲突，引发边界色彩溢出或身份漂移。现有方法将异构条件简单拼接，无法根据去噪阶段动态调整计算资源分配。本文提出 CARE-Edit，通过轻量级潜在注意力路由器将 token 动态分派至四个专用专家，实现条件感知的计算分配。该方法在多条件编辑任务上显著提升了保真度，但其依赖 LoRA 微调的范式与领域主流的免训练趋势存在张力，且未验证其在高分辨率场景下的扩展性。

## 研究背景

当编辑器同时接收文本指令、空间掩码与参考图像时，不同模态对去噪过程的贡献权重并非恒定。早期去噪阶段需确立语义布局，后期则需细化边界与风格一致性。这种时间动态性要求模型具备自适应调节能力，而传统架构缺乏此机制。

统一编辑器（如 OmniControl、OmniGen2）通常采用静态拼接或加性适配器整合多模态输入。这种“容量无关”的融合方式导致有限模型容量无法在冲突信号间动态分配，例如文本语义可能覆盖掩码约束，或参考图风格错误地扩散至非编辑区域。尽管 Rectified Flow (RF) 与 DiT 架构提升了生成质量，但条件融合机制的静态本质仍是多条件编辑的核心瓶颈。

CARE-Edit 的切入点在于将条件融合从“静态信号叠加”转变为“动态计算路由”。它不改变骨干网络的全局去噪动力学，而是引入异构专家机制，根据当前 token 的内容、任务类型及去噪时间步，选择性激活特定模态的专家，从而在保持预训练先验的同时，解决多条件冲突导致的伪影问题。

## 核心方法

### 方法参照系

本文基于 DiT 骨干与 LoRA 微调范式，继承 OmniControl 的多模态条件输入结构。关键差异在于：标准流程将所有条件编码后静态拼接至统一潜变量序列，而本文将其解耦为四个独立专家分支，并通过路由机制实现 token 级的动态选择，而非全局共享计算。

### 条件感知路由机制

静态融合无法区分不同 token 对特定模态的依赖程度，导致全局信号相互干扰。CARE-Edit 在 DiT 块中引入轻量级路由器，基于局部内容特征与全局任务上下文计算专家选择概率。对于每个 token $h'_i$，路由器计算其相对于四个专家（文本、掩码、参考、基础）的 logits，并通过 Top-$K$ 稀疏化选择最相关的 $K$ 个专家：

$$
S_i = \text{Top}_K(\text{softmax}(\alpha_{i,e} + b_e))
$$

其中 $\alpha_{i,e}$ 为预 softmax 激活值，$b_e$ 为可学习偏置。该机制允许每个 token 在去噪过程中自适应地关注最相关的模态，例如边界 token 优先激活掩码专家，而语义中心 token 优先激活文本专家，从而在计算层面隔离冲突信号。

### 掩码重绘与潜变量混合

用户提供的掩码常与物体边界错位，导致编辑区域模糊。Mask Repaint 模块利用参考图几何信息，在潜空间迭代细化掩码，预测软边界以平滑过渡区域。随后，Latent Mixture 模块融合专家输出，通过时间步自适应门控平衡全局背景保持与局部编辑：

$$
h'_{final} = \gamma(h_b, s) \cdot h'_b + (1 - \gamma(h_b, s)) \cdot h'_{fuse}
$$

其中 $\gamma$ 为基于基础专家特征与时间步嵌入学习的门控系数。该设计确保早期去噪步骤侧重全局结构（基础专家主导），后期步骤侧重细节融合（混合输出主导），解决了静态方法中背景漂移与编辑泄漏并存的难题。

## 实验评估

实验在 EMU-Edit、MagicBrush 与 DreamBench++ 上进行，基线涵盖 PnP、OmniControl、OmniGen2 等统一编辑器及任务特定方法。缺失 FlowEdit 等无反转方法作为对比，限制了其在效率维度的评估。

| 方法 | 数据集 | CLIPout↑ | DINO↑ | L1↓ |
| :--- | :--- | :--- | :--- | :--- |
| OmniGen2 | MagicBrush | 0.877 | 0.877 | 0.057 |
| CARE-Edit | MagicBrush | **0.885** | **0.885** | **0.052** |
| OmniGen2 | DreamBench++ (Multi) | 0.713 | 0.560 | - |
| CARE-Edit | DreamBench++ (Multi) | **0.720** | **0.568** | - |

CARE-Edit 在 MagicBrush 与 DreamBench++ 多对象设置上均取得最优结果，尤其在 DINO 指标上显著优于 OmniGen2，验证了动态路由对身份保持的增益。

| 变体 | DINO-I↑ | CLIP-I↑ | CLIP-T↑ |
| :--- | :--- | :--- | :--- |
| w/o Experts | 0.485 | 0.652 | 0.296 |
| Full Model (K=3) | **0.568** | **0.720** | **0.327** |

消融实验显示，移除专家路由导致性能大幅下降，证实动态分配是核心贡献。$K=3$ 时性能最优，$K=4$ 时略有下降，表明专家数量过多会稀释专业化程度。

评估指标依赖 CLIP 与 DINO，缺乏针对“编辑泄漏”的专用量化指标。代码与模型将开源，但训练依赖 8× NVIDIA L20 GPU 进行 100K 迭代，复现成本较高。未报告推理速度，无法直接对比免训练方法的效率优势。

## 关联研究分析

从问题动机看，CARE-Edit 与 FlowEdit 均旨在解决多条件编辑中的冲突，但路径截然不同。FlowEdit 基于 RF 的速度场校正，通过无反转范式避免累积误差，属于动力学层面的干预；而 CARE-Edit 聚焦于条件融合层面的计算分配，属于架构层面的解耦。FlowEdit 假设速度场差异足以引导编辑，而 CARE-Edit 认为静态融合是主要瓶颈。这种差异暗示：在 DiT 架构下，条件冲突可能比反转误差更显著，但论文未提供跨架构的公平比较，无法断定哪种瓶颈在特定场景下更主导。

从方法设计看，CARE-Edit 与 EC-DiT 同属 MoE 框架，但专家异构性是关键差异。EC-DiT 使用同质专家扩展容量，而 CARE-Edit 使用模态专用专家解决语义冲突。这种设计选择源于任务特性：图像编辑需要区分语义、空间与风格功能，而非单纯扩大模型容量。然而，CARE-Edit 依赖 LoRA 微调，与领域主流的 Training-free 趋势相悖。这是否意味着动态路由必须依赖参数更新才能稳定？若采用免训练路由，其性能衰减程度如何，论文未给出回答。

## 总结

CARE-Edit 针对统一编辑器中静态条件融合导致的信号冲突，提出条件感知专家路由机制，通过动态分配计算资源解决多模态编辑中的身份漂移与边界伪影。实验表明，其在 DreamBench++ 多对象设置上 DINO 得分达 0.568，优于 OmniGen2 的 0.560。然而，该方法依赖 LoRA 微调，与免训练范式存在张力，且未验证高分辨率下的显存效率。当支持集增大或任务复杂度提升时，动态路由的边际收益是否递减，论文未给出回答。
