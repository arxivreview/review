# CVPR2026最新论文 ｜Omni IIE Bench: Benchmarking the Practical Capabilities of Image Editing Models ｜Omni IIE Bench：面向实际设计场景的指令式图像编辑诊断基准

研究机构：中国科学院大学

作者：Yujia Yang、Yuanxiang Wang、Zhenyu Guan 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.16944)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.16944)

> 指令式图像编辑（Instruction-based Image Editing, IIE）旨在通过自然语言指令对图像进行精确、可控的视觉修改，其核心价值在于连接人类意图与视觉生成。现有基准多采用混合任务评估，掩盖了模型在低语义尺度（如属性修改）与高语义尺度（如实体替换）间切换时的性能波动，且缺乏专业设计师对数据实用性的验证。本文提出 Omni IIE Bench，通过构建包含单轮一致性与多轮协调的双轨数据集，并引入解耦诊断评估框架，量化模型在实际设计工作流中的稳定性。该基准揭示了主流模型在跨尺度编辑中的普遍失效，但受限于仅评估 8 个非推理代理类模型，其结论对复杂指令场景的普适性存在边界。

## 研究背景

当设计师在广告或电商场景中迭代修改图像时，指令往往从“将天空变红”（低语义尺度，属性修改）迅速切换至“将左侧人物替换为机器人”（高语义尺度，实体替换）。这种动态切换要求模型不仅具备单次编辑的精度，更需维持跨指令的上下文一致性。然而，扩散模型的全局去噪特性导致高频信息在多轮交互中渐进退化，且现有评估指标（如 CLIP Score）将全局语义与局部保真度混合计算，无法区分模型是“整体重绘”还是“精准局部修改”。

早期 IIE 基准如 MagicBrush 和 InstructPix2Pix 聚焦于单轮指令遵循，假设模型能独立处理每条指令。随着多模态大语言模型（MLLMs）的引入，领域范式转向“推理-规划-执行”，但评估体系仍滞后于方法演进。ImgEdit-Bench 等后续工作虽引入多轮概念，但通常限制在 2-3 轮对话，且未区分语义尺度的动态变化。这导致基准性能与真实设计工作流中的“频繁渐进式修改”存在显著差距。现有研究缺乏一个能同时诊断单轮跨尺度一致性与多轮长程误差累积的评估工具，且数据未经过专业设计师的行业相关性审查，导致理想化基准分数与实际可用性脱节。

## 核心方法

### 双轨诊断数据集构建

本文的问题属于评估基准构建路线，其关键差异在于将“语义尺度动态切换”作为核心诊断维度，而非单纯的任务覆盖。传统基准如 I2EBench 虽区分高低级编辑，但采用孤立检查表评估，未测试同一图像上下文中的跨尺度稳定性。Omni IIE Bench 通过 GPT-4o 生成场景描述并随机修改，利用 Nano Banana 生成目标图像，再经 GroundingDINO 和 SAM 提取掩码。数据分为单轮一致性（1,725 对）和多轮协调（260 组，最多 16 轮）两轨，多轮指令在属性与实体修改间随机交错，以模拟真实设计流程中的尺度跳跃。

### 解耦诊断评估框架

设计动机在于解决全局指标平均化局部错误的问题。传统方法计算整图 LPIPS，掩盖了背景污染或前景失真。本文引入前景/背景解耦机制，定义前景掩码 $M_{fg} = M_{gt}$ 和背景掩码 $M_{bg} = 1 - M_{gt}$。对于前景保真度，计算零化背景后的图像差异：

$$
\text{FG-LPIPS} = \text{LPIPS}(I_{gen} \odot M_{fg}, I_{gt} \odot M_{fg})
$$

该公式仅量化编辑区域的感知相似度，剥离了非编辑区域的干扰。背景保真度对称计算，确保非编辑区域像素级一致性被独立评估。此外，指令遵循度通过 GPT-4o 生成 QA 对并由 MLLM 裁判判定，采用“一票否决”策略：仅当所有 QA 对均为 True 时得分 1.0，否则为 0.0。这一严格标准避免了部分正确编辑获得高分的偏差，使评估更贴近专业设计师对“完全合规”的要求。

## 实验评估

实验在 Omni IIE Bench 上评估 8 个主流 IIE 模型，包括 Qwen-image-edit、FLUX、InstructPix2Pix 等。基线覆盖扩散模型微调与流匹配路线，但缺失 MIRA、EditThinker 等基于 MLLM 推理代理的最新方法，这可能影响对复杂指令场景结论的普适性。

| 模型 | 单轮 LPIPS (↓) | 单轮 CLIP (↑) | 多轮 LPIPS (↓) | 多轮 CLIP (↑) |
| :--- | :--- | :--- | :--- | :--- |
| Qwen-image-edit | 0.245 | 0.887 | 0.254 | 0.888 |
| InstructPix2Pix | 0.327 | 0.774 | 0.390 | 0.842 |
| ICEdit | 0.450 | 0.867 | 0.510 | 0.875 |
| MGIE | 0.284 | 0.858 | 0.296 | 0.801 |
| HIVE | 0.441 | 0.849 | 0.552 | 0.771 |
| FLUX | 0.569 | 0.796 | 0.669 | 0.677 |
| HQEdit | 0.252 | 0.863 | 0.263 | 0.819 |
| Step1X | 0.295 | 0.794 | 0.388 | 0.819 |

单轮任务中，Qwen-image-edit 以 0.245 的 LPIPS 领先，而 MGIE 虽图像质量高（LPIPS 0.284），但指令遵循度极低，暴露了混合评估的盲区。多轮任务中，所有模型 LPIPS 均上升，如 Qwen-image-edit 从 0.245 升至 0.254，FLUX 从 0.569 升至 0.669，证实了误差累积效应。背景保真度在多轮中显著下降，表明当前模型缺乏长期记忆机制。

消融分析显示，语义尺度切换对性能影响显著。附录 B 指出，从高到低尺度切换时，模型背景污染率增加。设计决策上，双零容忍过滤标准（质量满分+行业相关）导致最终接受率仅 35.94%（单轮）和 37.36%（多轮组），虽牺牲数据规模，但确保了诊断的严谨性。

评估边界方面，指标完备性依赖 GPT-4o 的 QA 生成质量，若指令歧义可能导致 QA 对偏差。可复现性上，论文提供 GitHub 链接，但未报告 GPU 资源与推理延迟，计算效率维度缺失。

## 关联研究分析

从问题动机看，Omni IIE Bench 与 ImgEdit-Bench 均关注多轮编辑，但前者聚焦“语义尺度动态切换”下的稳定性，后者侧重内容记忆与版本回滚。ImgEdit-Bench 假设指令尺度相对静态，而本文揭示设计师工作流中尺度跳跃的普遍性。这一差异源于任务特性：设计迭代往往伴随从细节修饰到主体重构的跳跃，静态评估无法捕捉此类波动。

从方法设计看，本文与 I2EBench 共享语义尺度分层思路，但 I2EBench 采用孤立检查表，未测试跨尺度协调。本文通过共享上下文的多轮对话，量化了模型在尺度切换时的性能衰减。然而，本文未采用 I2EBench 的细粒度任务分类，而是简化为属性/实体两类，这可能忽略中间尺度（如姿态修改）的复杂性。此外，本文评估模型均为端到端微调或流匹配架构，未纳入 MIRA 等推理代理模型。推理代理通过显式分解指令，可能在跨尺度切换中表现更优，但本文未验证此假设，导致结论对“复杂指令”场景的覆盖存在盲区。

## 总结

Omni IIE Bench 旨在解决 IIE 评估中“基准性能与实际可用性脱节”的核心矛盾。现有基准混合评估掩盖了模型在语义尺度切换时的失效，且缺乏专业设计师验证。本文通过构建双轨诊断数据集与解耦评估框架，量化了 8 个主流模型在单轮跨尺度一致性与多轮误差累积中的表现。实验显示，Qwen-image-edit 单轮 LPIPS 为 0.245，多轮升至 0.254，而 FLUX 多轮 LPIPS 达 0.669，证实了误差累积的普遍性。本文的边界在于仅评估非推理代理模型，且未报告计算效率。当引入 MIRA 等显式推理机制时，模型在跨尺度切换中的性能衰减是否显著降低，论文未给出回答。
