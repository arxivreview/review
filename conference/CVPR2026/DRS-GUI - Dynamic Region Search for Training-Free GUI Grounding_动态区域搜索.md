# CVPR2026最新论文 ｜DRS-GUI: Dynamic Region Search for Training-Free GUI Grounding ｜动态区域搜索

研究机构：南开大学、中国科学院

作者：Yichao Liu、Huawen Shen、Liu Yu 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.15542)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.15542)

> GUI 定位在高分辨率密集界面中常因视觉干扰导致注意力分散，现有迭代裁剪方法因前向不可逆而难以纠正早期偏差。本文切入点在于将定位重构为可回溯的树状搜索过程，通过引入蒙特卡洛树搜索（MCTS）调度感知动作，在预测前动态筛选指令相关区域。该方法无需训练即可插拔至现有多模态大语言模型（MLLMs），在通用基准上显著提升了定位精度，但在高分辨率专业软件场景下，其性能增益仍受限于骨干模型的底层感知能力。

## 研究背景

GUI 定位的核心挑战在于将自然语言指令映射至像素坐标，这一过程要求模型在视觉冗余中精准隔离目标。多模态大语言模型（MLLMs）虽具备语义理解能力，但其视觉编码器在高分辨率截图中易受无关元素干扰，导致注意力分散。为缓解此问题，研究界引入了测试时缩放策略，通过迭代裁剪缩小视野。然而，此类线性前向聚焦机制缺乏对每一步操作有效性的评估，一旦初始裁剪偏离目标，误差将不可逆地累积，最终导致定位失败。

现有 GUI 定位方法主要分为静态全屏预测与迭代细化两类。静态方法如 SeeClick 依赖大规模预训练，但在密集布局下泛化能力不足；迭代方法如 GUI-Spotlight 虽能逐步聚焦，但其“前向-only”特性使其无法在发现错误时回溯或重定向。人类视觉搜索行为则表现出动态适应性，即在不确定性出现时扫描、调整甚至退回视野。本文针对这一机制缺失，提出将 GUI 定位视为“搜索-预测”两阶段过程，旨在通过可逆的区域探索机制，在最终坐标预测前锁定高置信度的指令相关区域，从而解决密集界面下的细粒度定位失效问题。

## 核心方法

### 搜索-预测范式重构

传统 GUI 定位直接将全屏截图输入 MLLM 进行坐标回归，本文将其解耦为区域搜索策略 $\pi_S$ 与基础定位模型 $M$ 的级联。该范式的关键差异在于，$\pi_S$ 不直接输出坐标，而是生成一个紧凑的指令相关区域 $R_{best}$，由 $M$ 在该局部区域内执行最终定位。这种解耦使得感知范围的调整与坐标预测分离，避免了全屏输入带来的视觉冗余干扰。

### 基于 MCTS 的动态感知规划

设计动机在于解决线性迭代裁剪中“错误不可逆”的缺陷。本文引入 MCTS 作为动作规划器，将区域状态 $S=(R, U, \{s_i\})$ 定义为搜索树节点，其中 $R$ 为当前区域，$U$ 为解析出的 UI 元素集，$\{s_i\}$ 为语义相关性分数。规划器通过 UCT 策略在 Focus（收缩）、Shift（平移）和 Scatter（扩展）三种感知动作间进行探索与利用平衡。节点选择遵循公式：

$$ a^* = \arg\max_{a \in A(S)} \left( Q(S, a) + c \sqrt{\frac{\ln V(S)}{V(S, a)}} \right) $$

该公式通过平衡高奖励区域的利用与低访问次数的探索，使搜索过程能够动态修正早期偏差，而非沿单一路径盲目深入。

### 区域质量奖励函数

设计动机在于为 MCTS 提供可量化的区域评估信号，防止搜索陷入语义稀疏或视觉冗余区域。奖励函数由三项组成：交互加权相关性 $r_{rel}$、UI 覆盖一致性 $r_{cov}$ 和语义集中度 $r_{con}$。最终奖励定义为：

$$ R = \alpha r_{rel} + \beta r_{cov} + \gamma r_{con} $$

其中 $r_{rel}$ 强调可交互元素的相关性，$r_{cov}$ 衡量区域中 UI 元素的空间占比，$r_{con}$ 通过归一化熵评估语义焦点的紧凑程度。该复合奖励引导规划器优先选择语义明确、结构完整且视觉信息密集的区域，从而在预测前有效剪枝冗余视觉干扰。

## 实验评估

实验在 ScreenSpot-V1、ScreenSpot-v2 和 ScreenSpot-Pro 三个基准上进行，基线涵盖通用 MLLM（Qwen2.5-VL）和 GUI 专用模型（UGround）。ScreenSpot-Pro 聚焦高分辨率专业软件，是评估细粒度感知的关键场景。

| 方法 | ScreenSpot-Pro Avg (%) | ScreenSpot-v2 Avg (%) |
| :--- | :--- | :--- |
| Qwen2.5-VL-7B | 26.8 | 86.5 |
| + DRS-GUI | 40.9 | 90.5 |
| UGround-V1-7B | 31.4 | 87.6 |
| + DRS-GUI | 45.7 | 91.8 |

在 ScreenSpot-v2 上，DRS-GUI 将 UGround-V1-7B 的准确率从 87.6% 提升至 91.8%，超越了领域综述中提到的 WinDOM（88.8%）和 GUI-Cursor（88.8%）。然而，在 ScreenSpot-Pro 上，尽管 UGround-V1-7B+DRS-GUI 达到 45.7%，仍低于领域综述中 GUI-AIMA-3B 的 61.5%，表明在极端高分辨率场景下，搜索策略的增益受限于骨干模型的底层感知能力。

| 消融配置 (ScreenSpot-v2) | Mobile (%) | Desktop (%) | Web (%) | Avg (%) |
| :--- | :--- | :--- | :--- | :--- |
| Baseline | 90.0 | 87.8 | 85.2 | 87.6 |
| + $r_{rel}$ | 91.8 | 89.5 | 87.2 | 89.6 |
| + $r_{rel} + r_{cov}$ | 92.2 | 90.1 | 87.0 | 89.9 |
| + $r_{rel} + r_{cov} + r_{con}$ | 93.0 | 91.1 | 90.5 | 91.8 |

消融实验显示，语义集中度 $r_{con}$ 对 Web 场景提升最大（+3.5%），表明复杂布局中语义焦点的紧凑性对定位稳定性至关重要。感知动作空间中，Scatter 动作的引入使准确率从 91.0% 提升至 91.8%，验证了扩展视野以恢复上下文信息的必要性。

评估协议采用标准点内框判定，未报告置信区间或计算延迟。代码未公开，但超参数（如 MCTS 预算 $N=8$，深度 $H=3$）已详细披露。由于依赖 OmniParser V2 和 Instructor-large 等外部组件，复现需确保这些依赖项的版本一致性。

## 关联研究分析

从问题动机看，DRS-GUI 与 GUI-Spotlight 均针对高分辨率下的细粒度定位失败，但 GUI-Spotlight 采用线性迭代裁剪，缺乏对中间步骤有效性的评估机制，导致早期错误无法纠正。DRS-GUI 通过 MCTS 引入可逆搜索，允许在发现偏差时通过 Shift 或 Scatter 重定向视野，这一差异源于对“感知过程是否应包含反馈机制”的不同假设。GUI-Spotlight 假设逐步聚焦必然收敛，而 DRS-GUI 认为密集界面中的视觉干扰可能导致聚焦路径偏离，需动态修正。

从方法设计看，DRS-GUI 与 UI-Actor 均利用结构化信息辅助定位，但 UI-Actor 通过注意力头直接生成视觉 Patch 权重，属于端到端的无坐标定位范式；DRS-GUI 则依赖外部 UI 解析器（OmniParser）提供结构化元素，属于基于符号推理的搜索范式。UI-Actor 的优势在于避免离散坐标生成的量化误差，但其在复杂布局下的泛化能力尚未经过大规模基准验证。DRS-GUI 的符号化搜索虽引入了解析误差，但通过区域质量奖励提供了可解释的决策依据，两者在精度与可解释性之间做出了不同取舍。

## 总结

DRS-GUI 旨在解决高分辨率密集界面中 GUI 定位的误差累积问题，其切入点在于将线性前向聚焦升级为可逆的树状搜索，通过 MCTS 调度感知动作并引入区域质量奖励，在预测前动态筛选指令相关区域。实验证明，该方法在 ScreenSpot-v2 上将 UGround-V1-7B 的准确率提升至 91.8%，在 ScreenSpot-Pro 上提升 14.3%。然而，其在 ScreenSpot-Pro 上的绝对性能（45.7%）仍显著低于专用微调模型 GUI-AIMA-3B（61.5%），暴露出 Training-free 策略在极端复杂场景下对骨干模型底层感知能力的依赖。当骨干模型在密集布局中的基础定位能力不足时，区域搜索策略的增益是否会被解析误差和视觉冗余抵消，论文未给出回答。
