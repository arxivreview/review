# CVPR2026最新论文 ｜An Efficient Token Compression Framework for Visual Object Tracking ｜多帧视觉跟踪中的自适应Token压缩框架

作者：Weijing Wu、Qihua Liang、Bineng Zhong 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.08329)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.08329)

> 多帧视觉跟踪旨在利用历史模板帧增强目标表征，但引入的大量视觉Token不仅带来二次方计算负担，更因冗余信息导致性能退化。现有方案或依赖手工规则剪枝，或简单堆叠帧数，均无法在保留判别性特征的同时消除冗余。ETCTrack提出“压缩-交互”框架，通过可学习的自适应Token压缩器（ATC）动态筛选关键Token，并配合层级交互编码器实现深层特征融合。该方法在七个基准上取得SOTA，但固定压缩率限制了其对动态场景复杂度的实时适应能力。

## 研究背景

当跟踪器从单帧模板匹配转向多帧历史建模时，输入Token数量随帧数线性增长。Transformer自注意力的二次方复杂度使得计算成本急剧上升，更关键的是，历史帧中大量背景与重复纹理构成了视觉冗余，稀释了目标判别特征，导致模型在长序列中性能不升反降。这一现象揭示了多帧跟踪的核心矛盾：时序信息的丰富性与计算效率、特征纯度之间的冲突。

主流路线试图通过增加帧数或优化注意力机制来缓解此问题，但往往陷入两难。早期方法如OSTrack依赖单流架构的全局交互，但未解决多帧输入的冗余瓶颈；近期工作如FARTrack采用自蒸馏压缩编码器深度，或CPDATrack利用判别性注意力剪枝背景Token，但这些方法多依赖固定规则或静态阈值，难以动态适应目标外观的剧烈变化。ETCTrack的切入点在于借鉴多模态大语言模型（MLLM）中“消除视觉冗余是平衡能力与成本的关键”这一原则，将Token压缩视为一个可学习的、由跟踪目标直接引导的优化过程，而非后处理步骤。

## 核心方法

### 方法参照系

多帧跟踪的标准流程通常包括：提取多帧模板特征、与搜索区域特征进行联合编码、预测目标状态。本文的关键差异在于，在特征进入交互编码器之前，插入一个显式的、可学习的Token压缩阶段，将压缩与交互解耦为两个协同工作的模块，而非在单一编码器内隐式处理冗余。

### 自适应Token压缩器

传统剪枝方法依赖注意力图或固定空间规则评估Token重要性，这些非可学习标准往往与最终跟踪目标不对齐，可能丢弃关键信息。ATC模块通过全局自注意力机制建模所有模板Token间的时空相关性，动态评估每个Token的上下文重要性。其核心是掩码引导的Token剪枝与合并策略：首先通过固定随机投影生成重要性分数，将Token分为保留集 $A$ 和冗余集 $B$；随后，通过贪心余弦相似度匹配，将每个冗余Token $b_i$ 合并到其最相似的保留Token $a_j$ 中，公式如下：

$$ a_j' = a_j + \frac{1}{|\Omega_j|} \sum_{i \in \Omega_j} b_i $$

其中 $\Omega_j$ 为分配给 $a_j$ 的冗余Token索引集。这一设计避免了直接丢弃信息导致的语义损失，同时通过合并操作显著降低了Token数量，为后续交互提供了紧凑且高判别力的表征。

### 层级交互编码器

压缩后的模板Token虽已去冗余，但仍需与搜索区域特征进行深层交互以完成定位。HIBlock通过多阶段非对称交互实现这一目标：首先，模板Token作为Query，搜索Token作为Key和Value进行交叉注意力，使模板感知当前搜索上下文；随后，增强后的模板Token与原始搜索Token拼接，进入标准骨干块进行联合特征学习；最后，搜索Token再次查询深层编码后的模板Token，实现模板对搜索过程的显式引导。这一流程确保了模板表征不仅提供静态外观信息，还能动态调整搜索区域的特征响应，解决了传统联合自注意力中交互隐式、缺乏方向性的问题。

## 实验评估

| 基准 | 方法 | AUC (%) | P_norm (%) | P (%) |
| :--- | :--- | :--- | :--- | :--- |
| LaSOT | ETCTrack-B224 | 74.9 | 85.1 | 82.7 |
| LaSOT | DreamTrack-B384 | 73.8 | 83.4 | 80.6 |
| TrackingNet | ETCTrack-B384 | 87.3 | 91.7 | 88.2 |
| TNL2K | ETCTrack-B384 | 63.0 | 68.4 | - |

实验在GOT-10k、LaSOT等七个基准上进行，基线覆盖了OSTrack、TransT等经典Transformer方法及DreamTrack、SPMTrack等近期SOTA，但缺失SAM 2系列基础模型的直接对比，限制了其在开放世界泛化能力上的评估。ETCTrack-B224在LaSOT上以74.9 AUC超越DreamTrack-B384的73.8，且在TrackingNet上达到87.3 AUC，表明其在复杂背景下的鲁棒性。

| 配置 | LaSOT AUC (%) | TNL2K AUC (%) | MACs (G) |
| :--- | :--- | :--- | :--- |
| w/o ATC (r=1.0) | 74.4 | 60.5 | 35.9 |
| ATC (r=0.9) | 74.9 | 61.3 | 34.1 |
| ATC (r=0.5) | 74.3 | 60.6 | 28.2 |

消融实验显示，引入ATC模块在r=0.9时带来+0.5 AUC的提升，同时降低1.8G MACs；当r降至0.5时，性能微降0.1 AUC，但MACs进一步降至28.2G，验证了压缩率与性能的非线性权衡。值得注意的是，模板帧数从3增至6时，无ATC基线性能在5帧后显著下降，而ETCTrack保持平稳，证实了视觉冗余是性能瓶颈而非帧数本身。

评估协议采用标准测试集，但未报告FPS等实时性指标，仅以MACs衡量计算成本，这在边缘部署场景中可能低估实际延迟。代码已开源，超参数如学习率、批次大小等细节完整，可复现性良好。

## 关联研究分析

从问题动机看，ETCTrack与FARTrack同属Token压缩路线，但FARTrack侧重通过自蒸馏压缩编码器深度，依赖任务特定Token进行知识迁移，其压缩是静态的、基于层级的；而ETCTrack的ATC是动态的、基于Token重要性的，直接由跟踪目标引导。这一差异源于FARTrack关注模型轻量化，而ETCTrack关注特征纯度，前者牺牲部分背景细节换取速度，后者通过合并冗余保留判别信息。

从方法设计看，ETCTrack与CPDATrack均关注背景抑制，但CPDATrack在早期编码器层引入判别性选择性注意力，移除低信息量背景Token，其剪枝标准基于目标概率估计，属于规则-based；ETCTrack则采用可学习的相似度合并，不依赖预设阈值。这种设计选择暗示，在目标外观剧烈变化时，固定规则可能失效，而可学习机制更能适应动态场景。然而，ETCTrack的固定压缩率r=0.9是否在所有场景下最优，论文未给出回答。

## 总结

ETCTrack旨在解决多帧跟踪中视觉冗余导致的性能退化与计算成本矛盾。其切入点在于将Token压缩视为一个可学习的、由跟踪目标直接引导的过程，而非依赖手工规则的后处理。通过ATC模块动态筛选并合并冗余Token，配合HIBlock实现深层交互，该方法在LaSOT上取得74.9 AUC，较DreamTrack-B384提升1.1%，同时在r=0.9时降低1.8G MACs。其边界在于固定压缩率无法实时适应场景复杂度变化，当目标外观剧烈变化或背景极度杂乱时，静态r值可能导致关键信息丢失或冗余残留。当场景复杂度动态变化时，自适应压缩率能否在不增加计算开销的前提下进一步提升性能，论文未给出回答。
