> 现有对话智能体将非语言行为视为模态翻译任务，缺乏跨轮次的行为决策能力，导致时序错位与社会性缺失。ViBES 通过混合模态专家架构与分数位置编码，在预训练语音大模型上轻量级挂载运动生成模块，实现了语言、语音与 3D 全身动作的联合自回归生成。该方案在对话行为基准上优于现有基线，但其依赖单视角重建数据且未验证物理交互能力，限制了其在具身智能领域的直接迁移。

## 研究背景

多模态对话智能体的核心挑战在于维持语言语义、语音韵律与身体动作在时间轴上的严格同步。传统方法将动作生成视为条件翻译问题，即给定音频或文本序列，通过扩散模型或 Transformer 生成对应的运动序列。这种范式假设输入信号已包含所有行为意图，智能体无需进行推理或决策。然而，在真实对话场景中，行为往往由上下文逻辑驱动，例如用户指令“请后退并挥手”要求智能体理解语义后执行特定动作，而非仅对语音节奏做出反应。

主流路线分为模块化拼接与端到端生成两类。模块化方案将语音大模型与运动生成器串联，但缺乏共享的对话状态，导致跨轮次一致性无法保证，且无法处理显式动作指令。端到端方案如 LoM 和 SOLAMI 虽尝试对齐语音与运动，但受限于数据规模，仅关注模态对齐而非保留语言推理能力。现有数据集多为成对对齐（如文本-运动、音频-运动），缺乏大规模、时间同步的音频-文本-运动三元组监督，阻碍了统一模型的训练。ViBES 的切入点在于利用预训练语音大模型的语义理解能力，通过轻量级专家模块扩展运动生成能力，并构建大规模同步数据集以解决数据瓶颈。

## 核心方法

### 混合模态专家架构

本文问题区别于标准视觉-语言-动作模型（VLA）的关键在于输出空间从连续物理动作向量变为离散运动 Token，且无需物理环境反馈。参照系为多模态大语言模型（MLLM）的专家混合（MoE）架构，通常通过可学习路由器动态分配计算资源。ViBES 采用硬路由策略，根据模态标签确定性地将 Token 分配至三个专家：文本-语音（TS）专家、面部专家与身体专家。TS 专家初始化自 GLM-4-Voice 并冻结，负责语言理解与语音生成；面部与身体专家为新增的轻量级 Transformer 块，仅通过交叉注意力读取 TS 流的键值对，不写回骨干网络。这种“稀疏”设计确保了骨干网络权重不变，最小化了新增模态的计算开销。

### 分数位置编码与跨模态对齐

跨模态时间对齐是联合生成的核心难点。音频 Token 帧率（12.5 fps）与运动 Token 帧率（25 fps 或 6.25 fps）不一致，直接交错会导致时序错位。ViBES 引入分数旋转位置编码（Fractional RoPE），将运动 Token 的位置索引定义为相邻 TS 锚点之间的线性插值。设 TS 锚点索引为 $A = \{a_0, \dots, a_{L-1}\}$，运动 Token $t$ 的时间戳为 $u(t)$，其分数索引 $s_t$ 计算如下：

$$
s_t = a_i + \frac{u(t) - u(a_i)}{u(a_{i+1}) - u(a_i)}
$$

其中 $i$ 为满足 $u(a_i) \le u(t) < u(a_{i+1})$ 的索引。该公式将离散的运动帧映射到连续的 TS 时间轴上，使得面部与身体 Token 在注意力计算中拥有精确的相对时间位置。消融实验表明，启用面部与身体之间的直接注意力无显著增益，因此设计为单向读取 TS 流，简化了计算图并降低了训练不稳定性。

## 实验评估

实验在自建 Converse3D 数据集（1000 小时）及 BEATv2、TFHP 等公开基准上进行。基线覆盖共语音手势生成（SynTalker, LOM, EMAGE）与文本到运动生成（MotionGPT, MoMask）两类路线，但缺失具身智能体领域的 VLA 基线（如 RT-2），因任务定义不同（虚拟化身 vs 物理机器人）无法直接对比。

| 方法 | 输入 | R1-Balanced↓ | R1-Motion↓ | R1-Conv↓ | FID↓ | Div→ |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| LOM | Response audio | 0.323 | 0.025 | 0.621 | 373.8 | 2.49 |
| MotionGPT | Question text | 0.244 | 0.123 | 0.452 | 262.2 | 7.40 |
| ViBES | Question text | **0.467** | **0.308** | **0.745** | **93.9** | **10.73** |

ViBES 在对话行为基准上全面领先，FID 从 LOM 的 373.8 降至 93.9，表明生成运动与真实分布的差距显著缩小。在 BEATv2 共语音手势生成任务中，ViBES 的 FGD 为 5.257，优于 LOM 的 5.301；在 TFHP 说话人头部合成任务中，FDD 为 6.05，显著优于 ARTalk 的 20.77。

消融实验聚焦于注意力机制设计。启用面部与身体之间的双向注意力未带来性能提升，反而增加计算复杂度，证实了“运动流在条件于 TS 流后近似独立”的假设。这一发现简化了架构，避免了冗余的特征交互。

评估边界受限于单视角重建伪影与缺乏物理验证。Converse3D 数据源自 YouTube 视频，通过单视角管线恢复 3D 运动，存在固有的几何误差。评估指标主要依赖多模态 LLM 裁判与任务特定指标，缺乏人类偏好对齐的可靠性验证。代码已开源，但超参数与训练细节未在正文中完整披露，复现需依赖官方仓库。

## 关联研究分析

从问题动机看，ViBES 与 RT-2 等 VLA 模型均追求多模态端到端映射，但 RT-2 面向物理机器人，输出连续动作向量以最大化任务成功率，而 ViBES 面向虚拟化身，输出离散运动 Token 以优化社会性与时序对齐。这一差异源于任务特性：物理环境要求动作的精确性与安全性，需结合强化学习（RL）与物理约束；虚拟环境则更关注生成质量与交互自然度，可依赖监督学习（SFT）与预训练权重。ViBES 未使用 RL，这与领域共识中“RL 提升数据效率”的观点形成对比，暗示在数据充足且无物理约束的场景下，SFT 可能足以实现高性能生成。

从方法设计看，ViBES 与 LoM 同属语音-运动对齐路线，但 LoM 强调模态对齐，缺乏语言推理骨干，无法处理显式动作指令；ViBES 通过挂载 TS 专家保留了语言智能，实现了混合主动性交互。这一改进的根源在于架构解耦：TS 专家冻结保证了语言能力的稳定性，运动专家通过交叉注意力读取语义信息，实现了“理解-生成”的分离。然而，这种解耦是否导致运动生成对复杂语义指令的响应延迟，论文未给出量化分析。

## 总结

ViBES 解决了对话智能体中语言、语音与身体动作割裂的问题，通过混合模态专家架构与分数位置编码，在预训练语音大模型上实现了低开销的运动生成扩展。该模型在对话行为基准上取得 FID 93.9 与 FGD 5.257 的领先结果，证明了统一架构在时序对齐与社会性上的优势。其边界在于依赖单视角重建数据，缺乏物理交互验证，且未利用现代 LLM 的完整推理能力。当对话轮次增加至长时程场景时，仅依赖短期上下文与分数位置编码是否足以维持行为一致性，论文未给出回答。
