> 现有扩散与自回归生成模型依赖固定预训练权重处理所有输入，导致在复杂或模糊语境下产生过平滑或不一致的样本。传统测试时训练虽能提升适应性，但梯度优化开销巨大，而混合专家架构受限于固定专家池且需重新训练。Composer 通过轻量级元生成器在推理时直接合成输入条件的低秩参数更新，实现了无需微调的逐实例特化。该方法在保持极低计算开销的同时显著提升了生成保真度，但其对绝对生成质量上限的突破仍受限于骨干网络本身。

## 研究背景

当生成模型面对高维语义空间中的细微差异时，静态权重无法动态调整内部表征以匹配特定输入，这种刚性导致输出缺乏语境一致性。解决此问题的关键在于引入动态参数适应机制，即根据输入信号实时调整模型权重。低秩适应（LoRA）提供了高效的参数更新框架，但其共享矩阵特性限制了逐实例的特化能力。

生成模型领域长期面临“静态参数”与“动态需求”的矛盾。主流路线包括测试时训练（TTT）和混合专家（MoE）。TTT 通过梯度下降适应输入，但在高分辨率扩散模型中计算成本呈指数级增长；MoE 通过路由选择固定专家，但路由粒度粗且依赖固定专家池，难以实现细粒度的实例特定适应。Composer 的切入点在于将参数适应从“迭代优化”转变为“前向合成”，利用元生成器直接从条件信号生成低秩更新，从而在推理阶段实现高效、细粒度的权重重组。

## 核心方法

### 方法参照系

本文问题可置于“参数高效微调”类别下，但关键差异在于：标准 LoRA 的 $A, B$ 矩阵在所有输入间共享，而 Composer 要求 $A, B$ 随输入动态变化。这要求从静态权重更新转向输入条件的动态参数生成。

### 输入条件低秩参数生成

传统 LoRA 中 $W' = W + AB$ 的 $A, B$ 为静态共享矩阵，无法捕捉输入特异性。Composer 引入 Transformer 元生成器，将预训练权重 $W_Q, W_V$ 线性投影为初始 token 序列，并与提示词 token 拼接。通过多头注意力机制，组件 token 关注提示词以获取语境，同时保持块内局部注意力与块间全局关联。最终输出重塑为低秩矩阵：

$$ W^* = A_{Q/V} B_{Q/V} $$

其中 $A_{Q/V} \in \mathbb{R}^{d \times r}, B_{Q/V} \in \mathbb{R}^{r \times d}$。这一设计解决了静态 LoRA 无法适应复杂语境的问题，使每个输入获得独特的权重修正，提升了生成保真度。

### 上下文感知训练与量化补偿

为平衡适应一致性与多样性，Composer 采用上下文感知采样策略：批次中 $\alpha \times b$ 样本来自相同类别或相似提示，$(1-\alpha) \times b$ 来自不同类别。训练目标为标准扩散损失：

$$ \mathcal{L} = \mathbb{E}_{t, x_0, \epsilon} \left[ \| \epsilon - \epsilon_\theta(x_t, t, P) \|^2 \right] $$

在量化场景下，Composer 进一步引入可学习缩放因子 $\gamma$，在低精度格式下训练 $A, B, \gamma$，通过知识蒸馏损失补偿量化误差。该策略解决了随机采样导致的适应不稳定问题，并在低比特量化下恢复了生成质量。

## 实验评估

| 方法 | FID↓ | IS↑ | 推理时间(s) | 峰值内存(GB) |
| :--- | :--- | :--- | :--- | :--- |
| Standard (VAR d-16) | 3.55 | 274.4 | 0.40 | 2.37 |
| Test-time Training | 3.22 | 277.2 | 40.52 | 4.58 |
| Composer | 3.15 | 280.4 | 0.42 | 2.57 |

实验在 ImageNet 256×256 和 512×512 上进行，基线包括 Standard、TTT 及量化模型（Q-Diffusion, CTEC）。Composer 在 VAR d-16 上将 FID 从 3.55 降至 3.15，推理时间仅增加 0.02s，而 TTT 耗时增加 10,030%。在 2/8 位量化下，Q-Diffusion + Composer 的 IS 从 49.08 提升至 78.21，Precision 从 43.18% 升至 55.2%，显著优于基线。

消融实验显示，低秩维度 $r=8$ 时 IS 与 FID 达到最佳平衡，$\alpha=0.75$ 时上下文感知效果最优。Global-Local Attention 优于 Standard Attention，Transformer 生成器优于 CNN/MLP 生成器。这些结果验证了动态参数生成与注意力机制设计的有效性。

评估边界方面，论文未报告置信区间，且未在大规模 T2I 数据集（如 COCO 30K 全量）上对比最新 SOTA 蒸馏模型。代码已开源，超参数（$r=8, \alpha=0.75$）固定，训练使用 A100 80GB，AdamW 优化器，学习率 1e-4，50 epochs。

## 关联研究分析

从问题动机看，Composer 与 MoE 均旨在解决静态权重适应性不足，但 MoE 依赖固定专家池的路由选择，粒度粗且需架构修改；Composer 通过生成新参数实现细粒度适应，无需架构变更。这一差异源于 MoE 的“选择”范式与 Composer 的“合成”范式，前者受限于专家容量，后者受限于生成器表达能力。

从方法设计看，Composer 与 TTT 均实现测试时适应，但 TTT 需梯度优化，计算成本高；Composer 仅需前向传播，效率提升百倍。然而，Composer 的低秩更新可能限制其适应复杂分布的能力，而 TTT 的全参数微调理论上更具表达力。论文未探讨当输入分布极度偏离预训练域时，Composer 是否仍能保持有效适应。

## 总结

Composer 解决了静态生成模型在复杂输入下适应性不足的问题，通过元生成器动态合成低秩参数更新，实现了无需微调的逐实例特化。实验表明，其在 ImageNet 256×256 上将 FID 从 3.55 降至 3.15，推理时间仅增加 0.2%，并在 2/8 位量化下显著恢复生成质量。然而，其绝对生成质量仍低于当前 SOTA（如 PixSGR FID 1.51），且未验证在大规模 T2I 任务上的泛化能力。当输入分布与预训练域存在显著偏移时，低秩更新的表达能力是否足以补偿分布差异，论文未给出回答。
