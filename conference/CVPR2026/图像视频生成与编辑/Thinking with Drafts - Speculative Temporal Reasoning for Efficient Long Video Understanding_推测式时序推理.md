# CVPR2026最新论文 ｜Thinking with Drafts: Speculative Temporal Reasoning for Efficient Long Video Understanding ｜推测式时序推理

研究机构：阿里巴巴集团

作者：Pengfei Hu、Meng Cao、Yingyao Wang 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2512.00805)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2512.00805)

> 长视频理解的核心矛盾在于，模型需在有限的计算预算内从海量冗余视觉帧中提取稀疏的关键时序证据。现有的“思考-帧”（Thinking-with-frames）范式通过迭代式全局推理与局部密集采样来定位关键帧，但这一过程导致多模态上下文不断累积，造成严重的推理延迟与内存瓶颈。SpecTemp 借鉴推测解码（Speculative Decoding）思想，将时序感知与推理解耦，由轻量级草稿模型负责密集采样与帧筛选，目标模型仅负责验证与推理，从而在保持精度的同时显著降低延迟。该框架在效率-精度权衡上取得了有效突破，但其双模型协作的泛化边界及在极端长视频下的稳定性仍有待进一步验证。

## 研究背景

长视频理解面临的核心挑战是 Transformer 上下文窗口限制与视觉 Token 冗余性之间的冲突。当模型处理小时级视频时，均匀采样会导致关键动态丢失，而密集采样则因视觉 Token 数量激增而超出内存限制。为应对此问题，研究者提出了“思考-帧”范式，该范式交替执行全局时序线索提取与局部密集帧检查，通过迭代细化逐步聚焦于信息丰富的片段。然而，这一范式存在固有的效率瓶颈：随着迭代轮次增加，模型需维护包含高层推理轨迹与密集视觉 Token 的长上下文，导致推理延迟随视频长度线性增长。

现有长视频高效推理路线主要聚焦于单模型内的 Token 压缩或关键帧选择，如 LongVA 通过扩展上下文窗口支持小时级视频，GroundVTS 通过查询引导过滤视觉 Token。这些方法虽降低了计算成本，但未能解决“思考-帧”范式中推理与感知耦合导致的冗余累积问题。SpecTemp 的切入点在于借鉴大语言模型中的推测解码机制，将耗时的密集帧探索过程委托给轻量级草稿模型，目标模型仅处理稀疏的代表性帧，从而在架构层面解耦了时序感知与语义推理，实现了效率与精度的平衡。

## 核心方法

### 方法参照系

SpecTemp 属于长视频高效推理路线，但区别于传统的单模型 Token 压缩或静态关键帧选择，其核心差异在于引入了双模型协作的迭代式“推测-验证”机制。传统方法在单模型内完成从全局定位到局部细化的全过程，导致上下文不断膨胀；SpecTemp 则将这一过程拆分为两个独立但协同的子任务，由不同容量的模型分别承担，从而避免了单一模型在处理密集视觉信息时的计算过载。

### 双模型协作架构

SpecTemp 的核心创新在于将时序感知与推理解耦，通过 7B 参数目标模型（Target MLLM）与 3B 参数草稿模型（Draft MLLM）的协作实现高效推理。目标模型负责全局时序推理与验证，草稿模型负责在预测的时间区域内进行密集采样并筛选稀疏代表帧。这一设计解决了传统“思考-帧”范式中，单模型在处理密集视觉 Token 时因上下文累积导致的推理延迟问题。目标模型首先均匀采样初始帧进行初步推理，预测需要进一步关注的时间区域；随后，草稿模型在该区域内以 1 fps 密集采样，并基于视觉信息增益选择 2 个代表帧返回给目标模型；目标模型验证这些帧，若信息不足则触发下一轮迭代，直至收敛或达到最大迭代次数（$T_{max}=3$）。

$$
\mathcal{L}_{total} = \mathcal{L}_{SFT} + \mathcal{L}_{RFT}
$$

该公式表示 SpecTemp 采用两阶段训练策略，首先通过监督微调（SFT）建立双模型的基础能力，再通过强化微调（RFT）优化协作策略。SFT 阶段分别训练目标模型的验证能力与草稿模型的帧选择能力，RFT 阶段则通过 GRPO 算法优化双模型的联合策略，确保协作过程的高效性与准确性。

### 奖励函数设计

为优化双模型协作，SpecTemp 设计了针对目标模型与草稿模型的不同奖励信号。目标模型的奖励包含格式奖励（$R_{format}^{target}$）、答案奖励（$R_{answer}$）与 IoU 奖励（$R_{IoU}$），其中 IoU 奖励通过计算预测证据片段与真值时间区域的重叠度，直接优化时序定位精度。草稿模型的奖励包含格式奖励（$R_{format}^{draft}$）与视觉信息增益奖励（$R_{visual}$），后者通过 CLIP 相似度分数鼓励选择与问题相关且与已选帧差异大的帧，避免冗余。

$$
R_{visual} = \alpha \cdot \text{sim}(q, f_i) - \beta \cdot \max_{f_j \in F_{prev}} \text{sim}(f_i, f_j)
$$

该公式定义了草稿模型的视觉信息增益奖励，其中 $\text{sim}$ 表示 CLIP 相似度，$q$ 为问题文本，$f_i$ 为候选帧，$F_{prev}$ 为已选帧集合。第一项奖励与问题相关的帧，第二项惩罚与已选帧相似的帧，从而确保草稿模型选择的帧既具有信息量又具有多样性，为后续的目标模型验证提供高质量的稀疏视觉证据。

## 实验评估

SpecTemp 在 8 个视频理解基准上进行了评估，涵盖短视频（TempCompass, MVBench, MMVU, VSI-Bench）与长视频（Video-Holmes, LongVideoBench, MLVU, Video-MME）。基线覆盖包括 Qwen2.5-VL-7B、LongVA-7B、VideoChatR1.5 等主流方法，但缺失专门的时空解耦架构（如 DIVID）对比。在长视频基准上，SpecTemp 使用 14.5 帧平均输入，在 Video-Holmes 上达到 47.0% 准确率，较 Qwen2.5-VL-7B（16 帧）提升 12.0%，同时将推理延迟从 4.1s 降至 3.7s。在 LongVideoBench 上，SpecTemp 使用 58.1 帧平均输入，达到 61.4% 准确率，较 VideoChatR1.5（64 帧）提升 0.8%，且延迟降低 23%。

| 基准 | 模型 | 帧数 | 准确率 | 延迟 (s) |
| :--- | :--- | :--- | :--- | :--- |
| Video-Holmes | Qwen2.5-VL-7B | 16 | 35.0 | 4.1 |
| Video-Holmes | SpecTemp | 14.5 | 47.0 | 3.7 |
| LongVideoBench | VideoChatR1.5 | 64 | 60.6 | 11.5 |
| LongVideoBench | SpecTemp | 58.1 | 61.4 | 8.9 |

消融实验揭示了迭代次数与奖励组件对性能的影响。最大迭代次数 $T_{max}$ 从 1 增加到 3 时，LongVideoBench 准确率从 54.7% 提升至 57.5%，但 $T_{max}=5$ 时准确率降至 58.1%（注：原文数据为 58.1，但正文描述为性能下降，此处以表格数据为准，实际表格中 $T_{max}=5$ 对应 58.1，$T_{max}=3$ 对应 57.5，存在矛盾，以正文描述“$T_{max}=3$ 达到最佳平衡”为准，表格数据可能为笔误，此处按正文逻辑分析：$T_{max}=3$ 时 LongVideoBench 57.5%，Video-Holmes 47.0%；$T_{max}=5$ 时 Video-Holmes 46.2%，表明过度迭代导致性能下降）。奖励组件消融显示，IoU 奖励对目标模型贡献最大（+3.4% Video-Holmes），视觉信息增益奖励对草稿模型贡献显著（+2.6% Video-Holmes），两者结合达到最佳性能。

| 消融项 | Video-Holmes | LongVideoBench |
| :--- | :--- | :--- |
| 基线 (SFT) | 42.1 | 53.1 |
| + $R_{IoU}$ | 45.5 | 55.8 |
| + $R_{visual}$ | 44.7 | 54.6 |
| + $R_{IoU}$ + $R_{visual}$ | 47.0 | 57.5 |

评估边界方面，SpecTemp 未报告置信区间，且部分基准（如 Video-MME）未包含字幕，可能影响结果可比性。代码未公开，但提供了详细的训练配置（16×H100，SFT 2 epochs，RFT 1 epoch，学习率 $1 \times 10^{-6}$，KL 系数 0.04）。NIAH 测试显示，SpecTemp 在 2000 帧视频中保持 80% 以上的检索准确率，验证了其在极端长视频中的鲁棒性，但该测试仅针对单帧视觉问题，未涵盖复杂时序推理。

## 关联研究分析

从问题动机看，SpecTemp 与 LongVA 等 Token 压缩方法存在根本差异。LongVA 通过扩展上下文窗口与视觉 Token 压缩解决内存瓶颈，但假设模型能处理所有压缩后的 Token；SpecTemp 则假设视觉 Token 存在高度冗余（>90% 注意力分数低于 $10^{-3}$），通过双模型协作主动筛选稀疏帧，而非被动压缩。这一差异源于对“冗余性”的不同理解：LongVA 视冗余为需压缩的噪声，SpecTemp 视冗余为可被轻量模型高效过滤的冗余信息。SpecTemp 的设计更适应“思考-帧”范式，但可能牺牲对全局动态的感知，因为草稿模型仅关注预测的时间区域，若初始预测偏差较大，可能导致关键帧遗漏。

从方法设计看，SpecTemp 与 VideoChatR1.5 同属“思考-帧”范式，但 VideoChatR1.5 在单模型内完成迭代推理，导致上下文累积；SpecTemp 通过双模型解耦，将密集采样委托给 3B 草稿模型，目标模型仅处理稀疏帧。这一设计借鉴了推测解码的“草稿-验证”机制，但将 Token 级加速扩展至帧级选择。与 VideoChatR1.5 相比，SpecTemp 在相近精度下降低 19-23% 延迟，但引入了双模型通信开销。论文未明确报告双模型同步延迟的具体数值，仅通过总延迟对比间接体现，这可能掩盖了双模型架构在实时性要求极高场景下的潜在瓶颈。

## 总结

SpecTemp 旨在解决长视频理解中“思考-帧”范式因上下文累积导致的效率瓶颈，其切入点在于借鉴推测解码思想，将时序感知与推理解耦，通过 7B 目标模型与 3B 草稿模型的协作实现高效帧筛选。该框架在 Video-Holmes 上以 14.5 帧平均输入达到 47.0% 准确率，较基线提升 12.0%，同时降低延迟 10%；在 LongVideoBench 上以 58.1 帧输入达到 61.4% 准确率，较 VideoChatR1.5 提升 0.8% 且延迟降低 23%。其边界在于，双模型协作的泛化能力未在不同骨干网络（如 InternVL3）上验证，且 NIAH 测试仅针对单帧视觉问题，未涵盖复杂时序推理。当视频长度进一步增加至小时级且关键信息分布极度稀疏时，草稿模型的密集采样是否仍能高效定位关键帧，论文未给出回答。
