# CVPR2026最新论文 ｜OASIS: On-Demand Hierarchical Event Memory for Streaming Video Reasoning ｜按需分层事件记忆

研究机构：中山大学

作者：Zhijia Liang、Jiaming Li、Weikai Chen 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.17052)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.17052)

> 流式视频理解面临的核心矛盾是无限增长的时序上下文与有限模型窗口之间的冲突，现有方法要么因保留全量历史导致注意力崩溃，要么因暴力压缩丢失关键证据。OASIS 指出问题本质不在于存储容量，而在于如何精准定位历史中决定性的证据区域。该框架通过构建分层事件记忆并执行“粗推理-细检索”两阶段策略，实现了训练无关的按需语义检索。其价值在于以结构化访问替代盲目扩容，但在弱骨干模型上的鲁棒性及极端动态场景下的记忆碎片化问题仍存疑。

## 研究背景

流式视频推理要求模型在严格因果约束下处理连续输入，此时模型无法回看未来帧，只能依赖当前及过去观测。这一约束导致两个核心概念紧密耦合：一是**流式因果性**，它确立了实时交互的底层逻辑，使得离线视频的全局优化范式失效；二是**注意力崩溃**，当模型试图将无限累积的历史帧塞入有限上下文时，大量冗余噪声会淹没当前时刻的关键信号，导致模型无法准确 grounding 当前场景。

在解决无限流与有限窗口冲突的主流路线中，早期方法如 Flash-VStream 依赖异步流水线与固定记忆模块，而 StreamingVLM 采用注意力沉没与连续位置编码确立架构标准。这些方法虽然解决了显存溢出，但普遍采用“检索-堆叠”策略，将检索到的历史证据与当前帧强行拼接，导致异构时间信息混淆。此外，基于嵌入相似度的朴素 RAG 检索往往获取视觉相似但语义无关的记忆，无法应对复杂的多步推理需求。OASIS 的切入点在于将流式视频推理重构为**时间路由**问题，认为核心能力不是存储更多历史，而是通过语义引导精准定位决定性区域，从而在保持低延迟的同时提升长程推理精度。

## 核心方法

### 方法参照系

本文问题可置于流式视频内存管理类别下。标准流程通常采用固定滑动窗口或简单摘要来压缩历史，其关键差异在于：本文不依赖固定窗口或暴力压缩，而是引入在线维护的分层事件森林，并通过 LLM 推理生成检索查询，替代了传统的固定 Top-K 相似度检索。

### 分层事件记忆构建

OASIS 构建了一个包含短窗口、中分辨率缓冲与事件森林的多分辨率记忆结构。短窗口 $\mathbf{W}_s$ 以高帧率 $r_s$ 保留最近 $\tau_s$ 秒的高保真帧，用于即时感知；中分辨率缓冲 $\mathbf{W}_m$ 以较低帧率 $r_m$ 保留更长时间的结构信息。对于长期历史，系统维护一个事件森林 $\mathcal{F}$，其中每个节点 $\mathbf{R}_j$ 由关键帧张量 $\mathbf{F}_j$、文本摘要 $s_j$ 及其嵌入向量 $\mathbf{e}_j$ 组成。为防止根节点无限增长，系统采用有界合并机制，当根节点数超过阈值 $n_r$ 时，贪心合并时间相邻且语义相似的节点对。合并评分函数为：

$$ \text{Score}(\mathbf{R}_j, \mathbf{R}_k) = \cos(\mathbf{e}_j, \mathbf{e}_k) - \lambda(d_j + d_k) $$

该公式通过余弦相似度促进语义连贯事件的融合，同时通过层级惩罚项 $\lambda$ 避免过度抽象，保留了记忆的层级粒度。这一设计解决了固定窗口无法适应动态事件流、且简单摘要导致细粒度信息丢失的问题。

### 两阶段语义引导推理

推理过程分为粗推理与细推理两阶段。粗推理阶段，模型仅使用短窗口、中分辨率缓冲及根节点摘要 $\{s_j\}$ 进行初步回答。若模型判断信息不足，则触发细推理阶段。此时，模型不直接检索原始问题，而是生成一个任务导向的语义假设查询 $I_i$。例如，对于“刚才有人吗？”的问题，查询可能被细化为“客厅里的人”。随后，系统计算 $I_i$ 的嵌入与事件森林中各节点嵌入的相似度，并采用贪心剪枝策略选取 $k_f$ 个节点，同时移除已选节点的祖先和后代以确保信息多样性。检索内容 $\mathbf{C}_{fine}$ 包含选中节点的关键帧及 $k_q$ 个历史 QA 对。这一机制解决了朴素 RAG 因嵌入相似度导致的语义错位问题，通过高层意图引导检索，确保获取的是决定性证据而非视觉噪声。

## 实验评估

实验基于 Qwen3-VL-8B、Qwen2.5-VL-7B 和 GLM-4.6V 骨干，在 OVO-Bench、StreamingBench 和 StreamBench 上评估。基线覆盖 Gemini 1.5 Pro、GPT-4o 及多种开源 MLLM，但缺失 Flash-VStream 等早期流式专用基线的直接对比。

| 模型 | 帧率 | Perception Avg | Backward Avg |
| :--- | :--- | :--- | :--- |
| Qwen2.5-VL-7B | 0.5 fps | 60.93 | 50.24 |
| + OASIS | - | 67.26 | 52.61 |
| Qwen3-VL-8B | 0.5 fps | 66.79 | 51.19 |
| + OASIS | - | 78.14 | 57.21 |

在 OVO-Bench 上，OASIS 在 Perception 子集上带来显著提升，Qwen3-VL-8B 从 66.79 提升至 78.14，增幅达 11.35 个百分点，验证了短窗口聚焦对注意力崩溃的缓解作用。Backward 子集提升 6.02 个百分点，表明细推理阶段有效克服了信息丢失。在 StreamingBench 上，OASIS 在 MCU（误导性上下文理解）任务上从 35.74 提升至 49.60，进一步证实了其在处理高相似连续镜头时的优势。

消融实验显示，移除事件森林导致 Backward 性能从 57.21 降至 48.65，说明长期记忆对回溯任务至关重要。将 OASIS 替换为朴素 RAG 后，Perception 从 78.14 降至 78.01，Backward 从 57.21 降至 56.13，表明语义引导检索在长程依赖任务上优于纯向量检索。此外，OASIS 的平均 Token 消耗稳定在 10k 左右，而全上下文基线在 StreamingBench 上高达 29,517 tokens，证明了其计算效率。

评估边界方面，论文未报告置信区间，且主要依赖平均指标，缺乏对极端延迟尖峰的细粒度分析。代码已开源，超参数（如 $\tau_s=8s, n_r=4$）明确，可在单张 A800 GPU 上复现。

## 关联研究分析

从问题动机看，OASIS 与 HERMES 同属分层记忆框架，但 HERMES 侧重于 KV 缓存的分层压缩，而 OASIS 强调事件级的语义索引与主动检索。HERMES 的压缩是被动且固定的，而 OASIS 的检索是主动且查询自适应的。这种差异源于任务特性：HERMES 旨在解决显存溢出，而 OASIS 旨在解决长程推理中的证据定位难题。OASIS 的语义引导检索是否比纯向量检索更鲁棒，在弱骨干模型上是否失效，论文未给出明确回答。

从方法设计看，OASIS 与 VideoLLM-Online 的主动响应机制存在关联，但 VideoLLM-Online 聚焦于“何时说话”的二元决策，而 OASIS 聚焦于“何时看历史”的检索决策。VideoLLM-Online 依赖外部标注训练 EOS 预测头，而 OASIS 通过 LLM 指令跟随实现训练无关的决策。这种差异暗示了主动响应机制的实现路径分歧：显式监督 vs. 隐式推理。OASIS 的训练无关性使其易于部署，但依赖骨干模型的指令跟随能力，这在弱模型上可能成为瓶颈。

## 总结

OASIS 针对流式视频理解中无限上下文与有限窗口的矛盾，抓住了“精准定位决定性证据”这一被忽略的核心点，通过分层事件记忆与两阶段语义引导推理，实现了训练无关的按需检索。实验表明，该方法在 OVO-Bench Perception 子集上提升 11.35 个百分点，并将 Token 消耗稳定在 10k 左右。其边界在于依赖骨干模型的指令跟随能力，且在极端动态场景下的记忆碎片化问题未充分验证。当骨干模型指令跟随能力较弱时，语义引导检索的鲁棒性是否下降，论文未给出回答。
