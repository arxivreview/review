> 指令式图像编辑长期受限于纯文本指令无法精确描述复杂纹理、材质或风格等抽象属性，导致模型在“让袋子拥有裙子图案”这类任务中频繁失败。现有统一生成模型虽能处理单张参考图，但无法区分多张参考图的索引，且缺乏对抽象属性的提取能力。DreamOmni2 通过引入索引编码、位置编码偏移及 VLM 联合训练机制，构建了支持多参考图输入的多模态编辑与生成框架。该工作填补了抽象属性迁移的空白，但在自建基准上的表现是否具备跨域泛化性，仍需更严苛的评估协议验证。

## 研究背景

当用户试图通过自然语言指令修改图像中的特定属性时，如“将第一张图中人物的发型改为第二张图中人物的发型”，纯文本指令往往因缺乏视觉锚点而失效。这种语义模糊性源于语言在描述细粒度视觉特征（如纹理、光影、姿态）时的表达局限，迫使模型依赖参考图像作为条件输入。然而，主流扩散模型（如 Flux Kontext）在处理多张参考图时，仅依靠位置编码无法区分“图1”与“图2”的语义指向，导致生成结果出现像素混淆或复制粘贴伪影。

指令式图像编辑（IBIE）的主流路线已从早期的端到端微调（如 InstructPix2Pix）演进至基于多模态大语言模型（MLLMs）的推理规划框架。尽管 MLLM 提升了复杂指令的理解能力，但现有方法多聚焦于具体对象的组合生成，对抽象属性（如全局风格、局部材质）的迁移支持不足。此外，传统数据构建依赖分割检测模型生成参考图，难以处理遮挡物体或抽象概念，导致训练数据分布偏差。DreamOmni2 的切入点在于将编辑任务扩展至“多模态指令”范畴，即同时利用文本与多张参考图，并解决多参考图输入下的身份混淆与抽象属性提取难题。

## 核心方法

### 方法参照系

本文问题置于统一生成与编辑模型框架下，其关键差异在于输入模态从“单图+文本”扩展为“多图+文本”，且编辑对象从具体实体扩展至抽象属性。标准流程中，参考图被编码为视觉 Token 与噪声 Token 拼接输入 DiT，但缺乏区分多张参考图索引的机制，且无法直接提取抽象属性作为条件。

### 索引编码与位置编码偏移

为解决多参考图输入时的身份混淆，本文在位置编码通道中引入索引编码（Index Encoding）。设第 $i$ 张参考图的位置编码为 $P_i$，索引编码为 $I_i$，则最终位置表示为：

$$ P_{final} = P_i + I_i + \sum_{j=1}^{i-1} W_j $$

其中 $W_j$ 为前 $j$ 张参考图的宽度偏移量。该设计动机在于，仅靠位置编码无法区分“图1”与“图2”的语义指向，索引编码显式标记图像序号，而位置偏移防止不同参考图间的像素混淆。实验表明，该机制显著降低了复制粘贴伪影，使模型能准确响应“将图1的物体替换为图2的物体”等指令。

### 特征混合数据管线与 VLM 联合训练

针对抽象属性提取难题，本文提出三阶段特征混合数据管线。第一阶段，通过双分支注意力特征混合生成包含相同抽象属性的配对图像，避免传统双联图（Diptych）方法的分辨率损失与边缘融合问题。第二阶段，利用第一阶段数据训练提取模型，从目标图中提取抽象属性生成参考图，并结合指令编辑模型生成源图，形成“源图-指令-参考图-目标图”四元组。第三阶段，从源图中提取多个参考图，构建多参考图生成数据。此外，本文引入 Qwen2.5-VL 与生成模型联合训练，VLM 将非结构化用户指令转化为结构化描述，弥合真实指令与训练格式间的差距。该设计解决了纯文本指令无法描述复杂纹理的问题，并提升了模型对不规则指令的鲁棒性。

## 实验评估

| 模型 | Concrete Object (Gemini) | Abstract Attribution (Gemini) | Human Eval (Editing) |
| :--- | :--- | :--- | :--- |
| GPT-4o | 0.6829 | 0.7805 | 0.7439 |
| Nano Banana | 0.6829 | 0.7073 | 0.5488 |
| Qwen-Image-Edit-2509 | 0.2683 | 0.2927 | 0.1159 |
| DreamOmni2 (Ours) | 0.5854 | 0.6585 | 0.6280 |

实验在自建 DreamOmni2 基准上进行，涵盖具体对象与抽象属性的编辑与生成任务。基线覆盖 GPT-4o、Nano Banana 等闭源模型及 Qwen-Image-Edit 等开源模型，但缺失 InstructPix2Pix 等早期 IBIE 基线。DreamOmni2 在 Gemini 评估下，具体对象编辑得分 0.5854，高于 Qwen-Image-Edit-2509 的 0.2683，接近 GPT-4o 的 0.6829；抽象属性编辑得分 0.6585，显著优于开源模型，但略低于 GPT-4o 的 0.7805。人工评估显示，DreamOmni2 在编辑任务中得分 0.6280，优于 Nano Banana 的 0.5488，表明其在真实场景下的可用性。

消融实验验证了索引编码与 VLM 联合训练的有效性。对比无索引编码方案，引入索引编码后模型能准确区分参考图索引，生成准确率提升。VLM 联合训练（Scheme 4）优于单独训练 VLM（Scheme 3）和无 VLM 方案（Scheme 2），表明 VLM 对复杂指令的结构化翻译显著提升了生成模型的理解能力。然而，论文未报告置信区间，且评估依赖 VLM（Gemini/Doubao）与人工评估，可能存在评估偏差。

评估边界方面，DreamOmni2 基准仅包含真实图像，缺乏合成数据对比，可能高估模型在真实场景下的泛化性。代码已开源（dvlab-research/DreamOmni2），但训练细节（如 LoRA 秩、学习率）未完全披露，可复现性受限。此外，论文未报告推理延迟，多参考图输入的计算开销未量化，限制了实时部署的评估。

## 关联研究分析

从问题动机看，DreamOmni2 与 InstructPix2Pix 的核心差异在于指令模态的扩展。InstructPix2Pix 依赖纯文本指令，通过 GPT-3 生成配对数据，但无法处理需要视觉参考的抽象属性编辑。DreamOmni2 引入参考图作为条件，解决了文本表达局限，但其数据构建依赖特征混合，可能引入分布偏差，导致对真实图像泛化不足。相比之下，MIRA 等推理框架通过 MLLM 分解指令，但未解决多参考图输入的身份混淆问题，两者在“语义理解”与“空间定位”上的侧重不同。

从方法设计看，DreamOmni2 与 Flux Kontext 等统一生成模型共享骨干网络，但引入了索引编码与位置偏移机制。Flux Kontext 仅支持单图输入，而 DreamOmni2 通过索引编码区分多图，解决了多参考图场景下的像素混淆。然而，DreamOmni2 的 VLM 联合训练仅用于指令结构化，未参与生成过程，与 MIRA 等将 MLLM 作为推理引擎的方法不同。这种设计降低了计算开销，但可能限制了模型对复杂逻辑指令的推理能力。

## 总结

DreamOmni2 旨在解决多模态指令编辑中抽象属性迁移与多参考图身份混淆的矛盾。其切入点在于利用特征混合数据管线生成高质量配对数据，并通过索引编码与 VLM 联合训练提升模型对复杂指令的理解。实验显示，DreamOmni2 在自建基准上具体对象编辑得分 0.5854，接近 GPT-4o 的 0.6829，抽象属性编辑得分 0.6585，显著优于开源模型。然而，其评估依赖自建基准与 VLM，缺乏跨基准验证，且未报告推理效率。当参考图数量增加至五张以上时，位置编码偏移的计算开销是否成为瓶颈，论文未给出回答。
