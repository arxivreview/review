# CVPR2026最新论文 ｜Efficient and High-Fidelity Omni Modality Retrieval ｜全模态组合检索中的效率与保真度权衡

研究机构：美国马里兰大学帕克分校、澳大利亚莫纳什大学

作者：Chuong Huynh、Manh Luong、Abhinav Shrivastava

论文原文见 [arXiv](https://arxiv.org/abs/2603.02098)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.02098)

> 多模态检索旨在解决异构数据在统一语义空间中的对齐与匹配问题，但现有模型受限于双模态架构，无法处理文本、视觉与音频的组合查询。主流方法面临计算效率与表示保真度的双重瓶颈：直接输入海量媒体Token导致对比学习失效，而简单池化则丢失细粒度语义。OmniRet通过共享媒体重采样器压缩Token，并引入注意力切片Wasserstein池化（ASWP）保留分布信息，实现了三模态统一嵌入。该框架填补了音频检索基准空白，但在通用图文任务上未超越专用模型，且未验证更大规模骨干的扩展性。

## 研究背景

当检索系统需要处理“一张图片加一句描述”或“一段音频加修改指令”的组合查询时，传统双编码器架构暴露出根本性缺陷。这类查询要求模型在单一向量空间中同时理解多种模态的语义关联，而现有模型如CLIP或BLIP仅支持文本-视觉对齐，音频模态因缺乏专用模型与训练数据而处于边缘地位。更深层的矛盾在于，将丰富的多模态输入压缩为单一嵌入向量时，简单的平均池化或[EOS]Token提取会丢弃细粒度细节，形成信息瓶颈；而保留Token级信息的延迟交互方法（如ColBERT）虽能解决保真度问题，却因计算与存储成本过高，无法用于大规模实时检索。

通用多模态检索领域正从静态语义映射向动态认知推理演进，但计算效率始终是制约模型规模与数据量的核心瓶颈。以VLM2Vec为代表的LLM嵌入方法虽提升了语义理解能力，但直接处理媒体编码器输出的数百个Token会导致批次大小受限，进而削弱对比学习中硬负样本的有效性。OmniRet的切入点在于解耦效率与保真度：通过注意力机制将媒体Token压缩为固定大小的潜变量，既降低了LLM的计算负载，又通过新颖的池化策略在单向量框架内保留了分布级细节，从而在计算受限条件下实现三模态组合查询的高保真嵌入。

## 核心方法

### 方法参照系

OmniRet属于通用多模态检索路线，其基础架构遵循“专用编码器+LLM组合器+对比学习”范式。与标准流程的关键差异在于，本文在媒体编码器与LLM之间插入了重采样模块，并替换了传统的池化机制，以解决Token爆炸与信息丢失问题。

### 共享媒体重采样器

媒体编码器（如SigLIP或QwenAudio）通常输出超过500个Token，直接输入LLM会限制批次大小，削弱对比学习效果。OmniRet引入基于Perceiver架构的共享媒体重采样器，将长序列压缩为固定数量的潜向量。该模块在所有模态间共享权重以增强泛化，但通过添加模态特定潜变量（modality-specific latents）保留模态敏感性。对于视频，先应用3D三线性插值减少帧间冗余。重采样后的Token $\mathbf{M} \in \mathbb{R}^{N \times D}$ 需保持多样性，避免信息坍缩。为此，引入多样性损失 $\mathcal{L}_{div}$，通过计算Token间相似度矩阵的正交性约束，使用平滑$L_1$函数（Huber loss）惩罚非正交性，并配合Dropout实现稀疏采样，确保重采样Token覆盖输入信息的不同维度。

$$
\mathcal{L}_{div} = \text{SmoothL1}(\text{clip}(\mathbf{M}\mathbf{M}^\top - \mathbf{I}, 0))
$$

该公式的物理含义是：强制重采样后的Token在向量空间中尽可能正交，从而最大化信息容量，防止多个Token编码相似语义导致的信息冗余。

### 注意力切片Wasserstein池化

LLM输出的隐藏状态序列包含丰富的Token级信息，但平均池化会模糊细粒度结构。ASWP将LLM输出Token视为分布 $\mathbf{Z}$，并与一组可学习参考点 $\mathbf{X}$ 进行比较。通过$L$个一维投影 $\Theta$，计算每个投影下的Monge耦合，生成直方图式描述符 $\mathbf{Z}'$。随后，对 $\mathbf{Z}'$ 的每列应用Softmax得分与Straight-Through Maximum（STM）估计器进行硬选择，通过Hadamard积保留关键信息，最后列求和得到最终嵌入 $\mathbf{h}$。

$$
\mathbf{h}_i = \sum_{j=1}^{S} [\mathbf{V}]_{ji}, \quad \mathbf{V} = \mathbf{Z}' \odot \mathbf{m}(\mathbf{Z}')
$$

该公式表明，ASWP并非简单聚合，而是通过可学习的参考点分布距离，选择性地保留与查询意图最相关的Token特征，从而在单向量格式下模拟了延迟交互的细粒度匹配能力，同时保持ANN索引的兼容性。

## 实验评估

OmniRet在扩展版M-BEIR（13个任务）和MMEBv2子集上评估，基线涵盖CLIP、SigLIP、VLM2VecV2及音频专用模型CLAP、ImageBind。在组合视觉文本任务（I,T→I）上，OmniRet取得86.2的Recall@5，显著高于VLM2VecV2的76.4；在视频检索（V→T）上，OmniRet达到43.8，而VLM2VecV2仅为17.6。在新增的ACM基准上，OmniRet在组合音频检索（A,T→A）任务中取得23.0，虽低于多阶段Gemma+QwenOmni管线的44.6，但后者计算成本极高，且Gemma管线在音频-视觉任务上表现不佳（A→V仅16.1），而OmniRet在A→V任务上达到35.5，接近ImageBind的36.3。

| 任务 | OmniRet | VLM2VecV2 | ImageBind |
| :--- | :--- | :--- | :--- |
| I,T→I (M-BEIR) | 86.2 | 76.4 | - |
| V→T (M-BEIR) | 43.8 | 17.6 | - |
| A→V (ACM) | 35.5 | - | 36.3 |
| A,T→A (ACM) | 23.0 | - | - |

消融实验显示，移除多样性损失导致平均Recall下降3.1%，移除Triplet损失仅下降0.5%，表明Token多样性对重采样质量至关重要。将ASWP替换为平均池化导致性能暴跌29.5%，证实了分布级聚合对细粒度检索的决定性作用。使用单个[EOS]向量替代ASWP，性能下降6.8%，说明简单池化确实丢失了关键信息。

评估边界方面，ACM基准仅基于VGG-Sound构建，样本量有限，且依赖生成模型合成标注，可能存在分布偏差。论文未报告计算延迟与吞吐量数据，无法量化ASWP与ColBERT在实时检索中的效率差异。代码基于LLaVA开源库，但LoRA超参数与数据采样策略细节仅部分披露，复现难度中等。

## 关联研究分析

从问题动机看，OmniRet与VLM2Vec同属LLM嵌入路线，但VLM2Vec聚焦于指令跟随与文本-视觉对齐，未解决媒体Token爆炸问题；OmniRet通过重采样器将计算瓶颈从LLM转移至轻量级Perceiver模块，使得在固定批次大小下能容纳更多硬负样本，这是其组合查询性能超越VLM2Vec的根本原因。然而，OmniRet在通用图文检索（I→T）上仅取得50.6，低于PE-Core的58.0，表明重采样器在纯视觉-文本任务中可能引入了信息损失，或LoRA微调未能充分适配视觉编码器。

从方法设计看，OmniRet的ASWP与ColBERT的延迟交互形成鲜明对比。ColBERT保留所有Token嵌入，通过MaxSim计算相似度，精度高但存储开销大；ASWP通过可学习参考点将Token分布压缩为固定维度向量，牺牲了部分理论上限以换取ANN索引兼容性。这种取舍在音频-视觉任务上表现良好（A→V 35.5 vs ImageBind 36.3），但在组合音频检索（A,T→A）上落后于多阶段管线，暗示ASWP在处理复杂语义组合时，其分布近似能力可能不如显式推理。

## 总结

OmniRet旨在解决全模态组合检索中计算效率与表示保真度的矛盾，通过共享媒体重采样器压缩Token负载，并利用ASWP在单向量框架内保留分布级细节。实验证明其在组合视觉文本与视频检索任务上显著优于VLM2VecV2，且在音频-视觉对齐上接近ImageBind水平。然而，论文自身实验暴露出边界：在组合音频检索任务上，OmniRet（23.0）远落后于多阶段生成管线（44.6），且未验证更大LLM骨干对性能的提升潜力。当音频查询涉及复杂逻辑修改（如“狗叫变成嚎叫”）时，ASWP的分布近似是否足以捕捉语义变化，还是必须依赖外部推理模块，论文未给出回答。
