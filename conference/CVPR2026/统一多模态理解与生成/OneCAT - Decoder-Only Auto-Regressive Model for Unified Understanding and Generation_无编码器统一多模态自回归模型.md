# CVPR2026最新论文 ｜OneCAT: Decoder-Only Auto-Regressive Model for Unified Understanding and Generation ｜无编码器统一多模态自回归模型

研究机构：美团、上海交通大学

作者：Han Li、Xinyu Peng、Yaoming Wang 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2509.03498)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2509.03498)

> 统一多模态模型长期受困于外部视觉编码器带来的推理延迟与模态融合深度不足。现有解耦或混合架构虽缓解了理解与生成的表征冲突，但引入了额外的计算开销与架构复杂度。OneCAT 通过移除 ViT 与视觉 Tokenizer，采用模态特定 MoE 与多尺度自回归机制，在单一解码器内实现理解、生成与编辑。该设计在推理效率上取得显著突破，但生成保真度仍低于混合扩散架构，其纯自回归路线的充分性存疑。

## 研究背景

统一多模态模型的核心困境在于视觉信息的输入处理。传统组合式架构依赖预训练视觉编码器（如 CLIP、SigLIP）将图像压缩为固定维度的特征向量，再送入大语言模型。这种“晚期融合”模式导致两个问题：一是编码器处理图像必须完整结束，LLM 才能开始生成，造成高分辨率输入下的 Prefill 阶段延迟；二是连接器作为信息瓶颈，丢失了细粒度视觉细节，限制了模型对局部特征的感知能力。

为克服上述瓶颈，领域内出现了两类主流路线。一类是解耦架构（如 Janus），通过分离理解与生成编码器缓解梯度冲突，但增加了参数冗余；另一类是混合 AR-Diffusion 架构（如 BAGEL、Transfusion），结合自回归与扩散目标以提升生成质量，但继承了扩散模型的高推理延迟。这两类方法均保留了外部视觉组件，未能从根本上解决架构复杂性与效率问题。OneCAT 的切入点在于彻底移除外部编码器，主张通过纯解码器架构与模态特定专家路由，在保持架构简洁性的同时实现早期跨模态融合。

## 核心方法

### 方法参照系

OneCAT 属于纯自回归统一架构路线，但区别于 Chameleon 等早期工作直接使用离散视觉 Token。其关键差异在于输入端采用连续 Patch Embedding 处理原始像素，输出端采用多尺度离散 Token 进行生成，并通过 MoE 机制在单一解码器内隔离不同模态的计算路径。

### 模态特定混合专家架构

针对理解任务偏好全局语义、生成任务偏好局部细节的表征冲突，OneCAT 在 Qwen2.5 骨干中引入模态特定 MoE 层。该设计将 FFN 层复制为三个专家：Text FFN 处理文本 Token，Und FFN 处理连续视觉 Token，Gen FFN 处理离散视觉 Token。路由机制基于模态类型硬分配，确保不同任务的数据流经专用参数，避免共享参数上的梯度干扰。

$$
\mathcal{L}_{Und} = \mathcal{L}_{NTP} + \lambda \mathcal{L}_{Distill}
$$

其中 $\mathcal{L}_{Distill} = \sum_{n=1}^{N} \text{MSE}(\mathbf{h}_S^{[n]}, \mathbf{h}_T^{[n]})$。该公式表明，理解任务的训练不仅依赖下一词预测损失，还通过全层隐藏状态匹配从教师模型蒸馏视觉感知能力。这种全层对齐策略解决了传统 Logits 蒸馏中教师模型容量限制学生表达能力的“监督瓶颈”问题，使 Und FFN 能更有效地习得视觉特征。

### 多尺度自回归生成机制

为解决高分辨率图像生成中序列长度平方增长导致的效率问题，OneCAT 引入 Next-Scale Prediction (NSP) 机制。图像通过多尺度 VAE 编码为分层离散 Token，生成过程从低分辨率到高分辨率逐级预测。为增强不同尺度 Token 的特征表达，引入尺度感知适配器（SAA），其结构为低秩分解模块，作为 Gen FFN 的跳跃连接。

$$
\text{SAA}_i = W_{down} \cdot \text{Linear}_i \cdot W_{up}
$$

SAA 针对每个 VAE 尺度 $i$ 独立训练，提取尺度特定表征。低尺度 Token 编码全局结构，高尺度 Token 编码纹理细节，SAA 使模型能区分处理这些功能迥异的 Token，避免共享 FFN 造成的表征混淆。该机制在自回归框架内实现了粗到细的生成过程，规避了扩散模型的迭代去噪延迟。

## 实验评估

OneCAT-3B 在 MMBench 上取得 78.8 分，低于 BAGEL 的 87.76 分，但高于 Janus-Pro 的 79.2 分（据领域综述，BAGEL 为 2025 年 SOTA）。在 GenEval 上，OneCAT-3B 得分 80.7，低于 UniDFlow 的 0.95（据领域综述），但高于 FLUX.1 [Dev] 的 0.82。推理效率方面，OneCAT-3B 在 768×768 分辨率下推理时间为 0.067 秒，比 Qwen2.5-VL-3B 的 0.135 秒降低 50%，比 BAGEL-7B 的 8.76 秒降低 84%。

| 模型 | MMBench | GenEval | 推理时间 (768×768) |
|---|---|---|---|
| OneCAT-3B | 78.8 | 80.7 | 0.067 |
| Qwen2.5-VL-3B | 79.1 | - | 0.135 |
| BAGEL-7B | 87.76 | - | 8.76 |
| Janus-Pro | 79.2 | - | - |

消融实验显示，全层蒸馏策略（Avg. 35.3）优于仅蒸馏最后一层 Logits（Avg. 33.9）或隐藏状态（Avg. 33.9），且优于 EvE（Avg. 33.4）和 VoRA（Avg. 32.3）。Token 比例实验表明，生成任务 Token 数量从 10B 增至 45B 时，GenEval 从 80.7 提升至 81.4，边际收益递减，而理解任务性能基本稳定。移除 SAA 导致生成性能显著下降，验证了尺度特定表征的必要性。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码未开源，仅提供 Project Page。超参数详细披露（如学习率、Batch Size），但 GPU 数量与训练时长未明确说明。评估基准覆盖理解、生成与编辑，但缺乏闭环评估以验证理解与生成间的协同效应。

## 关联研究分析

从方法设计看，OneCAT 与 BAGEL 均采用 MoE 架构，但 BAGEL 结合扩散目标，OneCAT 坚持纯自回归。BAGEL 在 GenEval 上表现更优，暗示扩散目标对高频细节重建的贡献不可忽略。OneCAT 的 NSP 机制虽提升了效率，但离散 Token 的信息损失可能限制了生成保真度，这与领域共识中“离散化是核心瓶颈”的观点一致。

从问题动机看，OneCAT 与 EvE、VoRA 同属无编码器路线，但蒸馏策略不同。EvE/VoRA 使用小型 ViT 作为教师，存在容量限制；OneCAT 使用定制 MLLM 教师并全层对齐，解决了监督瓶颈。然而，OneCAT 的推理效率优势主要源于移除外部编码器，而非 MoE 本身。若对比 Flash-Unified 等加速方法，OneCAT 的架构简化是否足以应对更高分辨率（如 1024×1024 以上）的延迟挑战，论文未给出充分验证。

## 总结

OneCAT 试图解决统一多模态模型中外部编码器导致的推理延迟与融合深度不足问题。其切入点在于移除 ViT 与 Tokenizer，通过模态特定 MoE 隔离优化目标，结合 NSP 机制实现高效生成。实验证明其在推理效率上显著优于混合架构（768×768 下比 BAGEL 快 84%），理解性能接近专用 VLM（MMBench 78.8 vs 79.1）。然而，生成质量仍低于混合 AR-Diffusion 架构（GenEval 80.7 vs 0.95），暴露了纯自回归路线在高频细节重建上的局限。当输入分辨率提升至 1024×1024 以上时，NSP 机制的序列长度增长是否会导致效率优势消失，论文未提供足够数据支持。
