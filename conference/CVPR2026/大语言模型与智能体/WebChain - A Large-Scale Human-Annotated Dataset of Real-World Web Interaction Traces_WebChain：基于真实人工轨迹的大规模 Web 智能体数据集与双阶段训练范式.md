> 导读 Web 智能体领域长期受困于训练数据规模不足与真实环境覆盖缺失，导致模型在长程任务中泛化能力受限。现有合成数据方法因反爬机制无法覆盖高价值认证场景，而开源人工数据集又缺乏验证 Scaling 效应所需的体量。本文通过构建包含 31,725 条真实人工标注轨迹的 WebChain 数据集，并提出解耦空间接地与长程规划的双阶段训练范式，旨在填补数据空白并优化训练效率。该工作提供了可复现的数据基础设施，但其对人工标注成本的依赖及跨基准泛化能力的边界仍存疑。

## 研究背景

GUI 智能体在浏览器环境中执行任务时，面临的核心挑战是空间接地（Spatial Grounding）与长程规划（Long-horizon Planning）的耦合失效。空间接地要求模型将自然语言指令精确映射到像素坐标或 DOM 节点，而长程规划则依赖对历史状态的准确记忆以维持决策连贯性。当智能体在复杂 UI 布局下出现定位误差，或在中途步骤丢失关键上下文时，后续动作必然失效，导致任务成功率随步骤数增加而急剧下降。这种感知与规划的强依赖关系，使得单一维度的优化往往以牺牲另一维度为代价，构成了 Web 智能体性能瓶颈的根源。

当前主流路线分为合成数据驱动与人工标注驱动两类。合成方法如 Explorer 和 OSGenesis 虽能低成本采集真实交互，但受限于反爬检测、CAPTCHA 及隐私认证机制，无法覆盖银行、电商结账等高价值工作流，导致数据分布偏差。人工标注数据集如 Mind2Web 虽具备真实性，但规模仅 2,350 条轨迹，不足以验证现代大模型（VLM）的 Scaling 效应。此外，现有训练范式多采用监督微调（SFT），存在协变量偏移问题，智能体在偏离训练轨迹的状态下难以恢复。WebChain 的切入点在于通过大规模真实人工轨迹突破数据规模瓶颈，并引入双阶段训练解耦感知与规划，以克服 SFT 的分布偏移局限。

## 核心方法

### 方法参照系

Web 智能体训练通常遵循“数据收集-监督微调-强化学习”流程。标准流程假设数据可自动合成且感知与规划可联合优化，但本文问题在于真实高价值场景数据不可自动获取，且联合优化导致空间接地与长程规划相互干扰。

### 三重对齐数据构建

针对合成数据无法覆盖认证场景的失效，WebChain 采用人工标注并实施三重对齐（Triple Alignment）机制。该机制同步三层上下文：视觉上下文（Viewport 与全页截图）、结构上下文（Accessibility 树）及动作对齐（像素坐标、边界框与 CSS 选择器）。其核心公式定义为：

$$
\mathcal{A}_t = \{ I_t^{vis}, T_t^{ax}, C_t^{act} \}
$$

其中 $I_t^{vis}$ 为视觉输入，$T_t^{ax}$ 为 AX 树结构，$C_t^{act}$ 为动作坐标。这一设计解决了纯视觉模型缺乏结构语义、纯文本模型缺乏空间感知的问题，使模型能理解像素背后的 DOM 逻辑，提供接地、注意力分配与 DOM 感知导航的丰富信号。

### 双阶段中间训练

针对 SFT 中感知与规划耦合导致的泛化受限，WebChain 提出双阶段中间训练（Dual Mid-Training）。该范式将空间接地与长程规划解耦，分别进行中间训练后再进行强化学习。空间接地阶段采用视觉接地稠密化（VGD）与推理提示（RP），其优化目标为最大化步骤奖励：

$$
\max_{\theta} \mathbb{E}_{(I_t, x_t) \sim \mathcal{D}} \left[ r_t(\hat{a}_t, \hat{y}_t | I_t, x_t; \theta) \right]
$$

其中 $r_t$ 由动作类型奖励与内容奖励组成。长程规划阶段则通过 CoT-SFT 显式建模规划逻辑。这种解耦策略避免了端到端优化对复杂任务结构泛化能力的限制，使最终 RL 阶段能专注于长期奖励优化，显著提升了长程任务的稳定性。

## 实验评估

实验在 WebChainBench（WCB-S 与 WCB-L）及公开基准（AndroidControl, GUI-Act, OmniAct）上进行，基线包括 Zero-shot Qwen2.5-VL 及 GUI-R1。WebChain-LCRL-7B+SGRL+CoT-SFT 在 Overall 指标上取得 81.4%，显著优于 GUI-R1-7B 的 74.2% 及 Zero-shot 7B 的 70.9%。

| 模型 | AC-High (SR) | GUI-Act-Web (SR) | OA-Web (SR) | Overall |
| :--- | :--- | :--- | :--- | :--- |
| Qwen2.5-VL-7B (Zero-shot) | 57.0 | 83.9 | 70.3 | 70.9 |
| GUI-R1-7B | 51.7 | 80.3 | 77.3 | 74.2 |
| WebChain-LCRL-7B+SGRL+CoT-SFT | 62.4 | 87.6 | 78.9 | 81.4 |

消融实验显示，VGD 与 RP 在 WCB-S 上独立产生增益，组合后效果最强。在 WCB-L 上，非 RP+VGD+LCRL 范式表现最佳，表明空间接地的推理正则化对长程规划存在负迁移，解耦训练是必要的。CoT-SFT 显著提升下游 RL 性能，验证了显式规划监督的有效性。

评估边界方面，WebChainBench 为自有基准，缺乏与 WebArena 等标准基准的直接 SOTA 对比。论文未报告计算效率指标（如推理延迟），且人工标注成本限制了数据在长尾场景的可扩展性。代码与数据已开源，但超参数细节需查阅仓库。

## 关联研究分析

从数据构建路线看，WebChain 与 SynthAgent 等合成方法形成鲜明对比。SynthAgent 依赖自动脚本采集，成本低但受限于反爬机制，无法覆盖认证场景；WebChain 采用人工标注，虽成本高但确保了高价值工作流的覆盖。这一差异根源在于任务特性：高价值 Web 任务往往涉及隐私与认证，自动化工具难以突破安全边界。WebChain 通过约束式任务合成与人工验证，解决了合成数据在真实环境中的分布偏差问题，但其可扩展性受限于人工标注效率。

从训练范式看，WebChain 与 GUI-R1 的纯 RL 范式存在关键差异。GUI-R1 直接进行 RL 优化，依赖模型自身的探索能力；WebChain 引入双阶段中间训练，先通过 SFT 稳定感知与规划能力，再进行 RL 优化。这一设计解决了 RL 在开放 Web 环境中奖励稀疏与探索空间巨大的问题。WebChain 的实验表明，高质量的 SFT 初始化是 RL 稳定性的前提，这与领域共识中“RL 需要 Warm Start”的观点一致，但具体到解耦感知与规划的中间训练策略，是本文对训练范式的独特贡献。

## 总结

Web 智能体面临的核心矛盾是真实高价值数据稀缺与长程任务泛化能力的不足。WebChain 通过大规模人工标注真实轨迹突破数据规模瓶颈，并提出双阶段训练解耦感知与规划，解决了合成数据覆盖缺失与 SFT 分布偏移问题。实验证明，该范式在 WebChainBench 上取得 81.4% 的 Overall 性能，优于 GUI-R1 基线。然而，其依赖人工标注的成本结构限制了数据在长尾场景的扩展，且自有基准与公开基准间的泛化差异未充分验证。当支持集规模进一步扩大时，人工标注的边际收益是否递减，论文未给出回答。
