作者：Yuxin Qin、Ke Cao、Haowei Liu 等 16 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.05898)

> 电商海报生成需同时满足主体保真、文字准确与风格一致，但现有方法或依赖多阶段流水线导致风格割裂，或单阶段模型难以兼顾复杂文字渲染。InnoAds-Composer 通过统一 Token 化与重要性感知注入，在单阶段 MM-DiT 框架内实现三条件联合控制。该方法在自建基准上显著降低了推理成本并提升了文字准确率，但其通用组合能力与跨域泛化性仍缺乏验证。

## 研究背景

电商海报生成不同于自由艺术布局，它受限于严格的商业规则：主体必须清晰、文字必须可读、背景风格必须统一。这种约束使得生成过程成为一个多目标优化问题。扩散模型（Diffusion Models）虽能生成高保真图像，但其原生架构缺乏对异构条件（如图像、文本、风格）的显式联合控制机制。当尝试将多种条件简单拼接时，注意力机制的二次复杂度会导致计算爆炸，且不同条件在生成过程中的重要性分布不均，盲目注入会引入冗余计算并干扰核心特征。

现有方案主要分为两类：多阶段流水线与单阶段模型。多阶段流水线（如 PosterMaker）先合成场景再渲染文字，虽解耦了任务，但阶段间信息传递导致风格不一致与主体保真度下降。新兴单阶段方法（如 AnyText2）虽能整合文本控制，但在处理复杂脚本和小字号时精度不足，且背景风格往往依赖提示词驱动，易偏离全局语义约束。InnoAds-Composer 的切入点在于：不改变底层扩散模型架构，而是通过分析条件在层与时间步上的重要性分布，实现“按需注入”，从而在保持预训练先验的同时，解决多条件拼接带来的计算冗余与语义干扰问题。

## 核心方法

### 多条件统一 Token 化与解耦注意力

InnoAds-Composer 基于 MM-DiT 骨干，将风格、主体、文字三种异构条件映射至同一 Token 空间。通常做法是将所有条件 Token 与噪声潜变量 Token 拼接后进行全注意力计算，但这会导致条件 Token 与噪声 Token 之间产生大量低价值的交叉注意力。本文引入解耦注意力（Decoupled Attention），移除条件查询（$Q_c$）对噪声键（$K_n$）的路径，仅保留噪声查询对条件键的注意力。这一设计基于条件 Token 在去噪过程中变化缓慢的特性，消除了冗余交互，使得条件分支的激活值可跨时间步缓存，显著降低了推理时的计算开销。

### 重要性感知条件注入

针对多条件 Token 拼接导致的序列长度膨胀，本文提出重要性感知注入策略。首先，通过训练一个全条件模型，计算各条件在每一层（$b$）和时间步（$t$）的注意力偏好权重 $S_{ci}(b, t)$：

$$ S_{ci}(b, t) = \text{Mean}(\text{Mask}_{ci} \odot \text{Attention}(Q_{[b,t]}, K_{[b,t]})) $$

该公式量化了特定条件在特定生成阶段的贡献度。实验发现，风格条件在早期层和时间步占主导，主体条件在中深层持续高亮，而文字条件在后期逐渐增强。基于此分布，模型仅在每个条件最敏感的层和时间步保留其 Token，其余位置直接丢弃。这种稀疏注入策略将有效序列长度缩短，从而抑制了注意力计算的二次增长，实现了精度与效率的平衡。

### 文本特征增强模块（TFEM）

为解决单阶段模型中文字渲染模糊的问题，TFEM 采用双分支结构。第一分支使用 VAE 编码整张文字图像，获取视觉 Token $h^{[c]}_1$；第二分支使用 OCR 骨干处理单字符裁剪图，并注入绝对位置、字号及局部位置编码，生成语义 Token $h^{[c]}_2$。两者通过轻量级字符编码器融合：

$$ h^{[c]} = \text{Fuse}(h^{[c]}_1, h^{[c]}_2) $$

这一设计将视觉形态与语义位置信息解耦再融合，确保了文字边缘的完整性与可读性，弥补了纯视觉编码在细粒度文字结构上的不足。

## 实验评估

| 模型 | Sen. Acc (↑) | NED (↑) | DINO (↑) | IoU (↑) | FID (↓) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Flux-Kontext | - | - | 0.831 | 0.793 | 76.76 |
| PosterMaker | 0.765 | 0.848 | 0.916 | 0.954 | 60.55 |
| Ours (Stage I) | 0.857 | 0.976 | 0.923 | 0.972 | 54.39 |
| Ours (Stage II) | 0.847 | 0.969 | 0.914 | 0.960 | 55.24 |

实验在自建 InnoComposer-Bench 上进行，基线涵盖 Flux 系列、PosterMaker 及商业模型 Seedream 4.0。InnoAds-Composer (Stage I) 在文字准确率（Sen. Acc 0.857）和主体一致性（IoU 0.972）上均领先，FID 54.39 显著优于 Flux-Kontext 的 76.76。Stage II 通过 Token 剪枝，在保持性能接近 Stage I 的同时，将推理延迟降低 37.8%，FLOPs 降低 38.1%。

消融实验显示，移除 TFEM 导致 Sen. Acc 下降约 5%，证实了双分支融合对文字精度的关键作用。在 Token 剪枝策略对比中，随机与均匀剪枝导致指标快速下降，而重要性感知策略在剪除 80% 文字 Token 和 50% 主体 Token 前仍能维持稳定质量，验证了条件重要性分布的非均匀性假设。

评估边界方面，本文使用自建数据集，缺乏与 COCO-Position 或 GenEval 等通用基准的对比，限制了跨任务泛化性的判断。此外，论文未公开代码与超参数细节，且未报告置信区间，使得数值比较的统计显著性存疑。

## 关联研究分析

从问题动机看，InnoAds-Composer 与 GLIGEN 等布局引导生成方法存在本质差异。GLIGEN 聚焦于通过边界框实现物体的空间定位，其核心挑战是几何对齐；而本文聚焦于商业海报的语义与美学约束，核心挑战是异构条件（风格、主体、文字）的联合保真。GLIGEN 采用适配器注入空间条件，而本文采用统一 Token 化与解耦注意力，这反映了从“空间控制”向“多模态条件协同”的范式转移。本文未探索空间布局的精确控制，而是假设布局由风格与主体隐含决定，这在需要严格构图的任务中可能失效。

从方法设计看，本文与 Laytrol 等 DiT 原生布局控制方法共享“保持预训练先验”的理念，但 Laytrol 侧重空间条件的注入，而本文侧重计算效率的优化。Laytrol 通过专门模块适配布局输入，而本文通过重要性分析动态剪枝 Token。这种差异源于任务特性：布局控制对空间精度敏感，需保留完整空间信息；而海报生成对计算效率敏感，允许在低重要性区域丢弃条件 Token。本文的解耦注意力是否牺牲了条件间的全局交互能力，从而在复杂布局下导致语义纠缠，论文未给出回答。

## 总结

InnoAds-Composer 旨在解决电商海报生成中多条件联合控制与计算效率的矛盾。现有方法或因多阶段流水线导致风格割裂，或因单阶段拼接导致计算爆炸，本文通过重要性感知注入与解耦注意力，在单阶段框架内实现了三条件的高效协同。实验表明，该方法在自建基准上实现了 FID 54.39 与 Sen. Acc 0.857 的性能，同时降低了 37.8% 的推理延迟。然而，其评估局限于自建数据集，且未验证在通用组合任务上的表现。当条件数量进一步增加或布局约束更为严格时，重要性感知剪枝策略是否仍能保持语义一致性，论文未给出回答。
