# CVPR2026最新论文 ｜Resolving Evidence Sparsity: Agentic Context Engineering for Long-Document Understanding ｜长文档证据稀疏下的上下文工程：SLEUTH 框架

研究机构：复旦大学

作者：Keliang Liu、Zizhi Chen、Mingcheng Li 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2511.22850)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2511.22850)

> 长文档问答的核心矛盾在于，关键证据往往稀疏地散布于数百页冗余信息中，而视觉语言模型（VLM）在超长上下文下性能急剧衰减。现有检索增强生成（RAG）方法虽能缩小搜索空间，但召回的页面仍包含大量噪声，直接干扰推理。SLEUTH 提出一种无训练的多智能体上下文工程框架，通过并行线索挖掘与视觉筛选，将噪声检索结果精炼为紧凑的证据密集上下文。该方法在 8B 参数级模型上显著提升了长文档问答精度，但其性能上限受制于初始检索器的召回质量，且纯提示驱动的设计缺乏自我进化能力。

## 研究背景

当 VLM 处理包含复杂图表与表格的长文档时，其有限的上下文窗口无法容纳全量高分辨率图像，导致跨页证据丢失。这一困境催生了检索增强生成（RAG）范式，即先通过检索器定位相关页面，再交由模型推理。然而，RAG 的召回结果往往包含大量无关页面，VLM 难以从这些噪声中精准提取关键证据，导致幻觉率上升。为解决此问题，智能体框架（Agentic Framework）被引入，通过多轮交互与工具调用实现主动导航。但现有智能体方法多聚焦于推理路径优化，忽视了输入上下文本身的质量，导致推理过程仍受冗长噪声上下文的干扰。

长文档理解领域的主流路线分为三类：增强推理能力、提升检索召回率、以及两者结合。MACT 等方法通过智能体协作强化推理，但输入仍为长上下文；M3DocRAG 等 RAG 方法提升了召回率，但未能解决召回噪声问题；MDocAgent 结合了两者，但推理过程仍涉及长且嘈杂的上下文。SLEUTH 的切入点在于“上下文工程”，即不修改模型架构，而是通过构建紧凑、高信噪比的证据密集上下文，从输入端解决证据稀疏与冗余干扰问题。这一视角将长文档问答重构为“如何从噪声检索结果中构建高质量上下文”的问题，而非单纯的检索或推理优化。

## 核心方法

### 方法参照系

SLEUTH 置于“检索-推理”解耦的长文档理解框架中。标准流程为：检索器缩小搜索空间 → VLM 直接处理检索页 → 生成答案。本文的关键差异在于，在检索与推理之间插入“证据精炼”阶段，通过多智能体协作将噪声页面转化为结构化、证据密集的上下文，而非直接输入原始页面图像。

### 粗粒度视觉检索与证据精炼

设计动机：标准 RAG 直接输入检索页，导致 VLM 在长上下文中难以定位关键证据。SLEUTH 首先使用 ColPali 进行页面级视觉检索，计算查询与页面的细粒度相似度：

$$s_i = \sum_{t=1}^{n_Q} \max_{1 \le j \le n_i} \langle \mathbf{q}_t, \mathbf{v}_{i,j} \rangle$$

该公式通过多向量后期交互（Late Interaction）捕捉查询与页面视觉元素的细粒度对齐，选出 Top-K 候选页面。随后，Clue Discovery Agent 与 Page Screening Agent 并行处理候选页。前者提取区域级线索（如表格单元格、图表区域），生成结构化记录 $(w_{i,m}, c_{i,m}, k_{i,m}, r_{i,m})$，其中 $w$ 为空间位置，$c$ 为内容，$k$ 为关键洞察，$r$ 为推理链；后者评估页面整体视觉相关性，输出离散标签 $y_i \in \{CR, R, IR\}$（完全相关、相关、不相关），并动态保留相关页面。这一并行机制确保文本线索与视觉证据的互补性，构建证据密集上下文 $C = (P_{\text{retained}}, E)$。

### 难度感知决策与推理

设计动机：不同查询复杂度需不同推理深度，固定推理模式导致效率与精度的失衡。Difficulty Assessment Agent 分析查询与上下文，输出难度等级 $d \in \{0, 1\}$ 及指令集 $\Gamma_d$：

$$d = \Phi_{\text{assess}}(Q, C), \quad \Gamma_d = \text{Instructions}(d)$$

$d=0$ 对应 Instruct 型模型，处理基础查询；$d=1$ 对应 Thinking 型模型，执行跨页聚合与数值推理。Core Decision Agent 根据 $\Gamma_d$ 选择模型类型，生成最终答案 $A^*$ 及证据引用表 $S$，确保推理过程的可验证性。该机制通过动态模型选择平衡效率与推理深度，避免对简单查询过度推理或对复杂查询推理不足。

## 实验评估

实验在 MMLongBench-Doc、LongDocURL、PaperTab 和 FetaTab 四个基准上进行，使用 Qwen3-VL-8B 作为骨干，ColPali-v1.3 作为检索器。基线覆盖 RAG（M3DocRAG、MoLoRAG）与智能体（MDocAgent）路线，但缺失纯检索优化或强化学习（RL）训练基线。在 MMLongBench-Doc 上，SLEUTH 取得 52.77% 平均准确率，显著优于 MoLoRAG（48.75%）和 MDocAgent（47.82%），尤其在 Pure-text（59.26%）和 Figure（50.27%）类别表现突出。

消融实验显示，Clue Discovery Agent 单独启用带来 +1.85% 增益，加入 Page Screening Agent 后增益扩大至 +4.53%，表明视觉筛选对抑制幻觉至关重要。Top-5 检索设置下，SLEUTH 平均准确率达 52.77%，较 Base 方法提升 +6.01%。然而，当检索 Top-K 增大时，性能提升边际递减，暗示初始检索质量是性能上限的关键约束。

评估指标采用广义准确率（Generalized Accuracy），基于规则脚本覆盖不同答案类型，但未报告置信区间。代码未公开，但 ColPali 与 Qwen3-VL 均有开源版本，基础组件可复现。实验未覆盖计算效率维度（如延迟、吞吐量），且未与 RL 训练方法（如 MACT）进行公平对比，因后者需额外训练成本。

## 关联研究分析

从问题动机看，SLEUTH 与 MDocAgent 均针对长文档证据稀疏问题，但 MDocAgent 侧重智能体导航与推理路径优化，而 SLEUTH 聚焦输入上下文的质量构建。这一差异源于对瓶颈的不同定位：MDocAgent 认为推理过程受噪声干扰，SLEUTH 认为输入上下文本身冗余。SLEUTH 的上下文工程视角更直接地解决了 VLM 在长上下文下性能衰减的问题，但可能牺牲了导航的灵活性。

从方法设计看，SLEUTH 与 MoLoRAG 同属检索增强路线，但 MoLoRAG 通过多语言嵌入提升召回率，SLEUTH 通过智能体精炼提升召回质量。SLEUTH 的无训练设计降低了部署门槛，但纯提示驱动的智能体缺乏经验积累能力，难以适应新领域文档。MoLoRAG 的嵌入学习可泛化至新领域，但需大量标注数据。SLEUTH 的难度评估机制仅二分（0/1），是否足以覆盖复杂推理谱系（如多步数值推理与定性趋势分析）尚不明确。

## 总结

SLEUTH 解决的核心矛盾是长文档中证据稀疏与上下文冗余导致的 VLM 性能衰减。其切入点在于，现有 RAG 与智能体方法均忽视了输入上下文的质量，而 SLEUTH 通过无训练的多智能体协作，将噪声检索结果精炼为证据密集上下文，从输入端提升推理可靠性。实验证明，在 Qwen3-VL-8B 上，SLEUTH 在 MMLongBench-Doc 上取得 52.77% 准确率，较最强基线 MoLoRAG 提升 4.02 个百分点。其边界在于，性能高度依赖初始检索器的召回质量，若关键页面被遗漏，下游智能体无法恢复；且纯提示驱动的设计缺乏自我进化能力，难以适应新领域文档。当检索 Top-K 增大时，性能提升边际递减，这是否意味着上下文工程存在固有的信息密度上限，论文未给出回答。
