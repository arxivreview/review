# CVPR2026最新论文 ｜MOMO: Mars Orbital Model Foundation Model for Mars Orbital Applications ｜火星轨道基础模型：基于验证损失对齐的模型合并策略

作者：Mirali Purohit、Bimal Gajera、Irish Mehta 等 11 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.02719)

> 火星遥感领域长期缺乏专用基础模型，现有地球观测（EO）模型因大气与地表材质差异无法直接迁移，而多传感器数据在分辨率上存在两个数量级差距，导致传统联合训练或通道堆叠方法失效。本文切入点在于规避数据对齐难题，采用独立预训练后通过模型合并整合表征。具体做法是提出等验证损失（Equal Validation Loss, EVL）策略，在兼容收敛阶段融合不同传感器模型。该方案填补了火星基础模型空白，但合并机制是否牺牲了跨传感器深层特征交互能力，仍需进一步验证。

## 研究背景

火星轨道卫星系统性地收集表面与大气遥感数据，其传感器配置与地球观测高度同构，但物理环境存在本质差异。理解本文需厘清两个核心概念：掩码图像建模（Masked Image Modeling, MIM）与模型合并（Model Merging）。MIM通过重建被遮挡图像块学习通用表征，是EO基础模型的主流预训练范式；然而，当面对火星传感器间巨大的分辨率异构性（如HiRISE 0.25 m/pixel与THEMIS 100 m/pixel）时，直接联合训练会导致高频细节丢失或计算浪费。模型合并则通过整合独立训练的模型权重，在不增加推理成本的前提下提升泛化能力，但其关键挑战在于如何确定各模型的“兼容”合并时机。

当前EO基础模型研究已确立ViT骨干与自监督预训练的主导地位，但针对火星的专用模型尚属空白。主流EO方法如SatMAE与CROMA依赖多传感器数据的空间时间对齐或通道堆叠，这在火星场景中因传感器覆盖不均（CTX覆盖近100%，HiRISE不足3%）而难以实施。此外，直接迁移EO模型至火星任务时，由于大气条件、光照及地表材质的系统性差异，性能显著下降。本文的切入点在于摒弃数据层面的异构融合，转而采用模型层面的表征整合，通过独立预训练保留各传感器独特分布特征，再引入基于验证损失对齐的检查点选择策略，解决多分辨率数据下的架构刚性问题。

## 核心方法

### 方法参照系

本文问题属于多传感器基础模型构建，但偏离EO领域标准的联合预训练或通道堆叠流程。关键差异在于：火星传感器间分辨率差异过大且覆盖不均，无法获取大量空间时间重合观测，因此本文采用“独立预训练+模型合并”路线，将数据异构性转化为模型异构性处理。

### 结构感知预训练目标

标准MAE仅使用均方误差（MSE）作为重建目标，这导致模型虽能恢复颜色分布，但无法捕捉火星地貌（如陨石坑边缘、滑坡边界）的结构细节。本文在MSE基础上引入感知损失与结构相似性损失，以引导模型学习边缘级与形状一致的表征。最终预训练目标函数为：

$$ \mathcal{L} = \mathcal{L}_{MSE} + \lambda_1 \mathcal{L}_{LPIPS} + \lambda_2 (1 - \mathcal{SSIM}) + \lambda_3 \mathcal{L}_{grad} $$

其中 $\mathcal{L}_{grad}$ 为预测与真实图像水平及垂直梯度差的 $\ell_1$ 范数。该设计动机在于MSE对高阶空间特征不敏感，而LPIPS与SSIM能强制模型关注几何一致性，从而在重建任务中保留关键地貌特征，为下游分割任务提供更鲁棒的特征基础。

### 等验证损失检查点选择

独立预训练后，各传感器模型处于不同的收敛阶段，直接合并可能导致过拟合或欠拟合模型的权重冲突。本文提出EVL策略，通过验证损失相似度对齐检查点，确保融合发生在兼容收敛阶段。定义候选元组 $\mathbf{t}_c = (e_1, ..., e_n)$ 为损失对齐，当且仅当：

$$ |L_i(e_i) - L_j(e_j)| < \epsilon, \quad \forall i, j \in \{1, ..., n\} $$

其中 $L_i(e_i)$ 为传感器 $i$ 在 epoch $e_i$ 的验证损失，$\epsilon$ 为容差。随后，选择平均归一化epoch距离最小的元组 $\mathbf{t}_c^*$ 进行任务算术（Task Arithmetic）合并。该策略解决了传统方法在最终检查点合并时因训练轨迹差异导致的性能不稳定问题，确保各传感器贡献的权重均处于泛化最优区域附近。

## 实验评估

实验在Mars-Bench的9个轨道下游任务上进行，涵盖4个分类与5个分割任务。基线覆盖ImageNet预训练、随机初始化、EO基础模型（SatMAE, CROMA, Prithvi, TerraFM, DINOv3）、传感器特定预训练及联合数据预训练（DM）。基线设置较为全面，但缺失其他模型合并策略（如TIES, DARE）的对比，限制了合并方法本身的横向比较。

MOMO在平均排名上取得1.67，显著优于所有基线。在分割任务上，MOMO相比联合数据预训练（DM）提升5.4% mIoU，相比传感器特定预训练提升4.2%。值得注意的是，EO基础模型（如CROMA, Prithvi）在火星任务上性能大幅下滑，验证了跨行星域迁移的失效。

消融实验聚焦于检查点选择策略。EVL策略相比早期停止（ES）和最后epoch（LE）合并，在三个分割任务上平均提升约2.5% mIoU。唯一例外是ConeQuest数据集，差异仅为1%。这表明EVL在大多数场景下提供了更稳定的合并点，但“最后epoch”定义的模糊性（取决于训练轮数）使其成为不可靠的基准。

评估边界方面，Mars-Bench仅包含9个任务，且部分分类任务性能已饱和（F1 0.96-0.98），可能掩盖了模型在复杂分类场景下的差异。论文提供了代码与数据开源链接，但未报告计算效率指标（FLOPs、内存），限制了部署可行性的评估。此外，缺乏跨域泛化验证，无法确认MOMO在月球或小行星等更极端环境下的适用性。

## 关联研究分析

从问题动机看，MOMO与EO领域的RAMEN、THOR等分辨率自适应架构形成鲜明对比。RAMEN通过投影模块处理不同GSD输入，THOR采用可变补丁大小，两者均在单一模型内解决分辨率异构性。MOMO则通过独立预训练规避了输入端的重采样或架构修改，将异构性处理移至模型合并阶段。这一差异源于火星传感器覆盖不均的约束：RAMEN类方法需要大量空间对齐数据以学习通用投影，而火星数据难以满足此条件。MOMO的合并策略虽避免了数据对齐难题，但牺牲了跨传感器特征的深层交互，其表征整合能力是否弱于联合训练模型，在数据充足场景下是否仍具优势，论文未给出回答。

从方法设计看，MOMO借鉴了NLP领域的模型编辑技术，但引入了EVL策略以解决遥感数据分布差异大的问题。与CROMA等EO多模态模型相比，CROMA依赖对比学习对齐雷达与光学数据，而MOMO通过验证损失对齐确保合并时的收敛兼容性。CROMA的对齐发生在特征空间，MOMO的对齐发生在优化轨迹空间。这一设计选择暗示，当传感器间物理特性差异极大（如光学与红外）时，基于优化状态的合并可能比基于特征的对齐更稳定。然而，EVL策略依赖于验证损失曲线的平滑性，若某传感器数据噪声大导致损失波动剧烈，该策略的鲁棒性可能下降，论文未对此进行敏感性分析。

## 总结

MOMO旨在解决火星多传感器遥感数据中分辨率异构与覆盖不均导致的架构刚性问题。现有EO模型因物理环境差异无法迁移，而联合训练又受限于数据对齐难度，MOMO通过独立预训练与EVL检查点选择策略，在兼容收敛阶段融合模型，实现了跨传感器表征整合。实验表明，MOMO在Mars-Bench上平均排名1.67，分割任务性能较联合预训练提升5.4% mIoU。然而，该模型在分类任务上的优势不明显，且缺乏跨域泛化验证。当传感器间物理特性差异进一步增大（如从光学到合成孔径雷达）时，基于验证损失对齐的合并策略是否仍能保持稳定性，论文未给出回答。
