# CVPR2026最新论文 ｜OmniDocLayout: Towards Diverse Document Layout Generation via Coarse-to-Fine LLM Learning ｜文档布局生成的粗到细学习

研究机构：上海交通大学、中山大学

作者：Hengrui Kang、Zhuangcheng Gu、Zhiyuan Zhao 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2510.26213)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2510.26213)

> 文档布局生成旨在自动化排列文本、表格等异构视觉元素，但现有数据集严重偏向学术论文，导致模型在报纸、教材等复杂长序列场景中失效。本文切入点在于构建首个百万级多域文档数据集 OmniDocLayout-1M，并提出两阶段 Coarse-to-Fine 学习范式，先学通用美学原则再适配特定域。该方法以 0.5B 参数模型在 M6Doc 基准上显著超越扩散模型与通用大语言模型，但其对细粒度标注的依赖及指标在复杂布局下的失效性仍存疑。

## 研究背景

文档布局生成面临的核心困境是数据分布的长尾效应与结构异构性。传统数据集如 PubLayNet 和 DocBank 主要覆盖学术文章的曼哈顿布局，元素数量少且结构单一。当任务扩展至报纸或教材时，单页元素数量激增，类别细粒度化，导致基于统计分布拟合的生成对抗网络（GAN）和扩散模型（Diffusion Model）因数据饥饿而难以收敛，长序列建模能力严重不足。

现有 LLM 布局生成方法虽利用语义先验缓解了多样性问题，但直接微调或上下文学习在复杂域中易过拟合，且依赖大量计算资源。LayoutNUWA 和 LGGPT 等域无关模型虽具泛化潜力，但仅在有限文档类型上验证，且缺乏针对复杂结构的有效训练策略。本文针对数据稀缺与复杂长序列建模的双重瓶颈，提出通过大规模多域数据预训练获取基础空间先验，再以少量细粒度数据适配特定域的解决方案。

## 核心方法

### 布局序列建模参照系

本文遵循 LGGPT 的字符串编码范式，将布局表示为离散 Token 序列，而非 HTML 代码。这一选择摒弃了 HTML 中冗余的结构描述符（如 `<body>`），以纯字符串形式 `<|cat_start|> c <|cat_end|><|box_start|> x y w h <|box_end|>` 序列化元素，其中坐标归一化至 [0, 999]。该参照系的关键差异在于，它不依赖外部渲染环境或视觉反馈闭环，而是完全在文本空间内通过条件序列建模实现布局生成，牺牲了部分语义丰富度以换取训练与推理效率。

### 粗粒度预训练与空间先验获取

设计动机在于解决复杂文档直接学习导致的过拟合与泛化失败。在粗粒度阶段，模型在 OmniDocLayout-1M 上学习对齐、避免重叠等通用美学原则。该阶段使用粗粒度标签集 $C_{coar}$，其损失函数为条件对数似然最大化：

$$ \mathcal{L}_{coar} = -\sum_{i=1}^{K} \log P(t_i | t_{1:i-1}, C_{coar}) $$

此公式意味着模型在多样化文档类型上建立基础的空间组织逻辑，而非记忆特定域的细粒度结构。通过统一标签空间，模型习得可迁移的结构先验，为后续复杂域适配奠定基础。

### 细粒度适配与标签映射机制

承接粗粒度阶段的空间先验，细粒度阶段通过标签映射 $\phi: C_{coar} \to C_{fine}$ 将粗类扩展为细粒度子类（如 "text" 映射为 "paragraph", "lead"）。适配过程在 M6Doc 等特定域上进行，仅使用数百个细粒度标注样本。该机制的核心在于利用预训练模型已掌握的空间约束，仅需微调语义映射关系，从而以极低的监督成本实现复杂布局的精确生成。这一设计直接解决了细粒度标注数据稀缺导致的训练困难，使模型能在保持结构完整性的同时适配特定文档类型。

## 实验评估

实验在 M6Doc 数据集的五个文档类型上进行，基线涵盖 LayoutDM、LACE、LGGPT 及 GPT-4o 等通用 LLM。本文方法在 Newspaper Refinement 任务中 FID 为 10.60，mIoU 为 0.732，显著优于 LGGPT 的 220.33 和 0.000，以及 GPT-4o 的 10.59 和 0.585。

| 任务 | 方法 | FID↓ | mIoU↑ |
| :--- | :--- | :--- | :--- |
| Newspaper Refinement | Ours | 10.60 | 0.732 |
| Newspaper Refinement | LGGPT | 220.33 | 0.000 |
| Newspaper Refinement | GPT-4o | 10.59 | 0.585 |

消融实验显示，Coarse-to-Fine 两阶段策略优于单阶段微调。在 Newspaper 域，仅细粒度微调（F.）的 FID 为 14.88，而两阶段（Both）降至 10.71，mIoU 从 0.164 提升至 0.185。模型规模方面，0.5B 模型在多数任务上表现优于 3B 模型，表明布局生成不严格遵循传统缩放定律，大模型可能因优化不足或过拟合导致性能下降。

评估指标存在局限：mIoU 在复杂多元素布局中常因标签不匹配而为 0，掩盖了结构错误；FID 在有限测试样本上波动大。代码与模型将公开，但论文未报告计算效率指标，且未对比 PosterLlama 等最新 LLM 布局方法在文档域的迁移性能。

## 关联研究分析

从方法设计看，本文与 LayoutNUWA 同属 LLM 路线，但 LayoutNUWA 采用 HTML 代码补全，依赖预训练中的网页结构先验；本文采用纯字符串编码，更贴合文档的线性阅读顺序，但牺牲了 HTML 的语义丰富性。这一差异源于文档布局的异构性：HTML 的固定标签体系难以覆盖报纸等复杂布局的细粒度类别，而字符串编码通过粗到细映射灵活适配不同域的标签空间。

从问题动机看，本文与 LayoutDM 同解决布局生成，但 LayoutDM 基于扩散模型，依赖大量数据迭代去噪；本文基于 LLM 序列建模，利用长上下文能力处理复杂序列。LayoutDM 在数据充足时表现稳定，但在数据稀缺的文档域中收敛困难；本文通过粗粒度预训练缓解数据饥饿，但缺乏扩散模型的高保真几何精度。这种取舍反映了 LLM 路线在语义理解与几何精度之间的平衡，而本文通过两阶段学习在数据受限条件下实现了更优的语义-几何对齐。

## 总结

本文核心矛盾是文档布局数据稀缺与复杂长序列建模的冲突。切入点在于构建百万级多域数据集 OmniDocLayout-1M，并提出 Coarse-to-Fine 学习范式，先学通用美学原则再适配特定域。方法以 0.5B 模型在 M6Doc 上实现 SOTA，Newspaper Refinement 任务 FID 10.60、mIoU 0.732 显著超越基线。边界在于 mIoU 指标在复杂布局中失效，且未验证交互式编辑能力。当细粒度标注样本增加至数千级时，Coarse-to-Fine 两阶段策略的边际收益是否递减，论文未给出回答。
