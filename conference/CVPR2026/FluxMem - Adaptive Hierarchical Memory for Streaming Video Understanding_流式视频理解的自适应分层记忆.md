# CVPR2026最新论文 ｜FluxMem: Adaptive Hierarchical Memory for Streaming Video Understanding ｜流式视频理解的自适应分层记忆

研究机构：复旦大学、美国马里兰大学帕克分校

作者：Yiweng Xie、Bo He、Junke Wang 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.02096)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.02096)

> 流式视频理解要求模型在严格因果约束下实时处理连续帧，同时维持长程时序一致性。现有Token压缩方法多采用固定比例或全局策略，导致近期细节过度剪枝或远期冗余累积，难以平衡实时性与语义完整性。FluxMem通过短-中-长三级记忆级联，结合基于Otsu方法的自适应阈值动态调整压缩率，在无需训练的情况下实现了流式基准的SOTA性能。其核心价值在于将离线全局优化转化为在线因果级联，但纯视觉相似度驱动的剪枝是否足以保留任务关键语义，仍存疑。

## 研究背景

当多模态大语言模型（MLLMs）处理连续视频流时，视觉Token数量随时长线性增长，导致Transformer注意力机制的二次方复杂度激增。为缓解这一瓶颈，视觉Token压缩成为关键手段，其核心在于从冗余的视觉特征中筛选出对下游任务有贡献的Token。然而，流式场景引入了严格的因果约束：模型必须在当前帧到达时立即做出响应，无法像离线任务那样回溯全局信息以进行最优剪枝。这要求压缩策略必须在线、低延迟，且能动态适应场景从静态到剧烈运动的切换。

流式视频理解的主流路线包括KV缓存管理、查询引导过滤和Token压缩。其中，Token压缩因在LLM输入前完成去重，兼具灵活性与解耦性，成为更具潜力的方向。然而，以TimeChat-Online为代表的现有方法通常应用单一的剪枝或合并策略贯穿整个视频流，忽视了记忆的时间依赖性效用。近期帧需要密集保留以支持即时定位，而远期历史则容忍更强压缩。全局策略因此倾向于对长期上下文剪枝不足，同时过度剪枝对因果推理至关重要的短期细节。FluxMem针对这一矛盾，提出基于时间邻近性的分层记忆架构，将视觉上下文划分为短期、中期和长期三个层级，并引入自适应机制以消除手动调参的依赖。

## 核心方法

### 方法参照系

流式视频Token压缩的通用流程是在视觉编码器输出后、LLM输入前，对连续帧的Token序列进行剪枝或合并。标准做法通常基于固定比例或全局相似度阈值，假设视频动态性均匀分布。本文的关键差异在于，它不假设动态性均匀，而是承认近期与远期Token的效用差异，并通过分层级联结构将时间冗余与空间冗余的消除解耦为两个独立阶段。

### 时间邻近选择（TAS）

TAS模块作用于短期记忆溢出的边界，旨在消除帧间时间冗余。传统方法直接比较相邻帧Token的相似度，但容易受局部运动或相机抖动导致的非对齐影响。TAS通过计算每个空间位置在3×3窗口内与前后帧的最小余弦距离，构建双向时间变化分数。设计动机在于，仅当Token相对于过去或未来帧均发生显著变化时，才保留该Token，从而鲁棒地捕捉真实内容变化。

$$ s_{t,h,w}^{[-]} = \min_{(i,j) \in \mathcal{N}_{3\times3}} d(v_{t-1,h+i,w+j}, v_{t,h,w}), \quad s_{t,h,w}^{[+]} = \min_{(i,j) \in \mathcal{N}_{3\times3}} d(v_{t+1,h+i,w+j}, v_{t,h,w}) $$

该公式计算Token在时间轴上前后方向的局部最小距离，距离越小表示该位置在时间上越冗余。TAS利用Otsu方法分别对$s_{t,h,w}^{[-]}$和$s_{t,h,w}^{[+]}$的分布计算自适应阈值$\Theta_t^{[-]}$和$\Theta_t^{[+]}$。若$s_{t,h,w}^{[-]} > \Theta_t^{[-]}$或$s_{t,h,w}^{[+]} > \Theta_t^{[+]}$，则Token被保留至中期记忆。这种基于分布的自适应阈值使得压缩强度随场景动态性自动调整，避免了固定阈值在极端静态或动态场景下的失效。

### 空间域整合（SDC）

SDC模块作用于中期记忆溢出的边界，进一步消除帧内空间冗余。TAS已过滤掉时间冗余Token，但保留的Token在空间上仍可能存在重复区域。SDC在TAS保留的Token集合上构建稀疏8连通图，若两个Token的空间距离小于Otsu阈值$\Theta_t$，则建立连接。设计动机在于，通过连通分量分析将局部连贯区域合并为单一锚点，从而在保留空间结构的同时大幅降低Token数量。

$$ a_{t,k} = \frac{1}{|C_{t,k}|} \sum_{v \in C_{t,k}} v $$

该公式计算每个连通分量$C_{t,k}$的质心作为锚点$a_{t,k}$，替换原始Token集合。由于图构建仅基于TAS预过滤的稀疏集合，SDC的计算复杂度接近线性。这种从时间选择到空间整合的级联设计，将短时动态转化为紧凑的长程上下文，实现了空间冗余的精细化消除。

## 实验评估

实验基于Qwen2.5-VL-7B骨干，在OVO-Bench、StreamingBench（在线）及VideoMME、MLVU、LongVideoBench（离线）上评估。基线覆盖训练型（TimeChat-Online, StreamForest）与无训练型（LiveVLM, ReKV）方法，但缺失知识库中SCORE、InfoMerge等最新离线SOTA的直接对比。

| 基准 | 方法 | 平均分 | 延迟降低 | 内存降低 |
| :--- | :--- | :--- | :--- | :--- |
| OVO-Bench | Qwen2.5-VL | 49.8 | - | - |
| OVO-Bench | FluxMem | 53.3 | 69.9% | 34.5% |
| StreamingBench | Qwen2.5-VL | 73.9 | - | - |
| StreamingBench | FluxMem | 76.4 | - | - |
| MLVU | Qwen2.5-VL | 67.9 | 44.3% | 31.2% |
| MLVU | FluxMem | 73.1 | - | - |

FluxMem在OVO-Bench实时任务上从49.8提升至53.3，同时延迟降低69.9%；在MLVU上从67.9提升至73.1，Token数量减少65%。

| 记忆配置 | MLVU | VideoMME | StreamingBench | 平均Token丢弃率 |
| :--- | :--- | :--- | :--- | :--- |
| 仅短期 | 67.8 | 63.3 | 73.9 | 0.0% |
| 短+中 | 69.9 | 65.5 | 74.7 | 43.2% |
| 短+长 | 70.9 | 62.0 | 75.9 | 85.1% |
| 全层级 | 73.1 | 65.3 | 76.4 | 64.3% |

消融显示，全层级配置在MLVU上取得最高分73.1，而仅短期配置在StreamingBench上略高（73.9 vs 76.4），表明短期记忆对实时任务至关重要，但长期记忆对离线长视频理解贡献显著。自适应阈值在中期记忆上以65.6分超越最佳固定阈值的65.5分，验证了Otsu方法的有效性。

评估边界方面，论文未报告置信区间，且多数对比方法未使用相同骨干，导致性能差异归因困难。代码已开源，超参数（如记忆长度8/64/剩余）在正文中明确，但Otsu阈值$\gamma$的敏感性分析缺失。

## 关联研究分析

从问题动机看，FluxMem与TimeChat-Online同属流式Token压缩路线，但TimeChat-Online采用固定比例剪枝，假设视频动态性均匀。FluxMem引入Otsu自适应阈值，解决了固定比例在动态场景下过度剪枝或保留冗余的问题。这一差异源于任务特性：流式场景要求实时响应，无法像离线方法（如FastV）那样利用全局注意力分数进行后验剪枝，因此必须依赖在线统计量（如Otsu）进行前验决策。

从方法设计看，FluxMem与SCORE同属LLM端Token压缩，但SCORE基于强化学习训练压缩器，侧重离线长视频理解；FluxMem为无训练框架，侧重流式因果约束。SCORE在VideoMME上取得58.5%准确率，FluxMem在相同基准上取得65.3%，但FluxMem使用Qwen2.5-VL-7B骨干，而SCORE骨干未明确。这种性能差异可能源于骨干优势而非方法本身，论文未提供控制变量实验以隔离骨干贡献。此外，FluxMem的纯视觉相似度剪枝未显式对齐任务语义，与知识库中“机器导向压缩”共识存在潜在冲突，即是否丢失了任务关键的高频语义细节。

## 总结

FluxMem要解决的核心矛盾是流式视频理解中实时因果约束与长程语义完整性之间的冲突。现有方法因采用固定比例或全局策略，无法动态适应场景变化，导致近期细节丢失或远期冗余累积。FluxMem通过短-中-长三级记忆级联，结合Otsu自适应阈值，实现了无需训练的在线压缩。实验证明其在OVO-Bench上提升3.5分并降低69.9%延迟，在MLVU上提升5.2分。其边界在于纯视觉相似度驱动的剪枝未显式对齐任务语义，且缺乏与最新离线SOTA的直接对比。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
