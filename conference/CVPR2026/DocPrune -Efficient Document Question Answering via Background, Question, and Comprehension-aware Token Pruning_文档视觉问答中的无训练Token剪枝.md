# CVPR2026最新论文 ｜DocPrune:Efficient Document Question Answering via Background, Question, and Comprehension-aware Token Pruning ｜文档视觉问答中的无训练Token剪枝

研究机构：韩国高丽大学、韩国科学技术院

作者：Joonmyung Choi、Sanghyeok Lee、Jongha Kim 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.22281)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.22281)

> 多模态大语言模型处理文档时，因版面稀疏导致视觉Token冗余，算力消耗巨大。现有针对自然图像或视频的剪枝方法忽略文档的结构特性，直接应用会导致文本连续性破坏或性能下降。DocPrune利用文档背景占比高、证据局部化及模型理解度随层数演进的三个特性，提出无训练的渐进式剪枝框架。该方法在M3DocRAG上实现了3.0倍至3.3倍的吞吐量提升，同时F1分数提升1.0，验证了结构感知剪枝的有效性，但其对长文档跨页证据完整性的影响尚存疑。

## 研究背景

文档视觉问答（DocVQA）依赖视觉语言模型（VLM）直接解析页面图像，但文档版面中大量背景区域与无关内容生成了数千个视觉Token，导致Transformer计算成本激增。这种冗余源于文档布局的固有稀疏性：内容仅占据页面局部，而背景占据主导。理解这一现象需引入“视觉Token剪枝”概念，即在推理过程中动态丢弃低重要性Token以降低计算量。然而，自然图像中的相邻Patch通常包含相似视觉信息，适合基于冗余度的剪枝；文档则不同，其文本行、表格遵循严格空间组织，随意丢弃Token极易破坏语义完整性。

主流VLM文档理解路线已从模块化OCR转向端到端图像解析，如M3DocRAG和VDocRAG等检索增强生成（RAG）框架。这些方法虽提升了精度，但推理效率仍是部署瓶颈。现有Token剪枝方法如FastV、DivPrune和VTW主要面向自然图像或视频，依赖固定启发式规则或迭代优化，未考虑文档特有的结构先验。FastV基于注意力分数剪枝，但在文档中易误删关键文本；DivPrune的迭代开销在高Token数下反而降低吞吐量；VTW的层间剪枝损害细粒度理解。DocPrune的切入点在于利用文档的“背景主导”、“问题相关稀疏”及“理解度层间演进”三个独特属性，设计无需训练的渐进式剪枝策略，以解决通用剪枝方法在文档场景下的失效问题。

## 核心方法

### 方法参照系

标准文档VQA流程包含检索与问答两阶段：检索模型从文档库中选取Top-K页面，问答模型基于这些页面生成答案。传统剪枝方法在编码或解码阶段统一应用固定规则，未区分文档背景与内容，也未利用检索阶段的语义信息。DocPrune的差异在于将剪枝嵌入流程的特定节点，并引入文档结构先验与模型内部状态作为动态决策依据。

### 背景与问题感知剪枝

设计动机：解决通用剪枝方法忽略文档背景冗余及问题无关内容的缺陷，避免误删关键语义。在编码前，DocPrune首先执行背景Token剪枝（BTP）。将图像分割为$P \times P$的Patch，计算每个Patch的灰度均值，并估计图像全局背景强度$m$（众数）。若Patch内像素强度与$m$的偏差小于阈值$\tau_e$的比例超过$\tau_{bg}$，则该Patch被判定为背景并丢弃。随后执行问题感知Token剪枝（QTP），利用检索阶段已有的文档Token嵌入$E_{doc}$与问题Token嵌入$E_{qst}$，计算余弦相似度$S$。通过双线性插值对齐分辨率并应用高斯平滑$G_\sigma$，得到平滑后的相关性图$S'$。仅保留$S'$超过阈值$\tau_{qst}$的Token。这一设计直接利用了检索阶段的计算结果，无需额外训练即可过滤问题无关区域，将Token数量从数千降至数百，显著降低后续编码负担。

### 理解度感知剪枝

设计动机：解决固定层剪枝无法适应不同难度文档的问题，避免过早剪枝导致信息不足或过晚剪枝导致计算浪费。在解码阶段，DocPrune引入理解度感知Token剪枝（CTP）。定义第$l$层最后一个Token的L2范数$c[l] = ||x_N^{[l]}||$作为模型理解度的代理指标。当$c[l]$超过阈值$\tau_{comp}$时，触发剪枝。此时，基于输出Token对所有视觉Token的注意力权重$a^{[l^*]}$，丢弃注意力值低于$\tau_{att}$的Token。该机制动态选择剪枝层，确保模型在积累足够语义信息后才进行压缩。实验表明，L2范数与问答性能高度相关，且易样本在浅层即达到高理解度，难样本需深层，验证了该指标的可靠性。

## 实验评估

实验在M3DocVQA、MMLongBench-Doc、ChartQA等基准上进行，基线包括M3DocRAG、VDocRAG及FastV、DivPrune、VTW等剪枝方法。DocPrune在M3DocVQA Top-4设置下，将TFLOPs降低70%以上，吞吐量提升3.3倍，同时F1分数从36.3提升至37.3。在MMLongBench-Doc Top-1设置下，Qwen2.5-VL模型的ACC从31.5提升至32.2，吞吐量提升2.1倍。

| 方法 | 数据集 | TFLOPs (ENC/DEC) | 吞吐量 (ENC/DEC) | Overall F1 |
| :--- | :--- | :--- | :--- | :--- |
| M3DocRAG (Baseline) | M3DocVQA (Top-4) | 59.28 / 86.27 | 0.6 / 0.6 | 36.3 |
| + DocPrune | M3DocVQA (Top-4) | 16.36 / 25.45 | 1.8 / 2.0 | 37.3 |
| VDocRAG (Baseline) | ChartQA | 9.9 / 30.4 | 3.1 / 1.5 | 48.0 |
| + DocPrune | ChartQA | 6.7 / 10.9 | 4.6 / 3.9 | 48.0 |

消融实验显示，BTP、QTP、CTP三个组件均带来正向收益。单独应用CTP时，L2范数准则优于熵和特征差准则，在保持吞吐量的同时最大化F1。值得注意的是，在DUDE数据集上，DocPrune的F1分数较基线下降0.2，表明在特定复杂布局下剪枝可能引入轻微性能损失，但整体效率收益显著。

评估边界方面，论文未报告置信区间，且仅在单GPU（RTX A6000）上测试，未涵盖多卡并行或边缘设备场景。代码未公开，超参数如$\tau_{bg}$、$\tau_{qst}$、$\tau_{comp}$的具体取值未详细列出，限制了可复现性。此外，实验主要聚焦于单页或少页场景，未验证在数百页长文档中，背景剪枝是否可能移除跨页布局线索，导致证据丢失。

## 关联研究分析

从问题动机看，DocPrune与MinerU2.5等文档解析方法形成互补。MinerU2.5通过解耦两阶段架构优化解析精度，侧重数据引擎与模型结构；DocPrune则聚焦推理效率，不改变模型架构，仅优化计算路径。两者均针对VLM处理文档的瓶颈，但MinerU2.5解决“解析不准”问题，DocPrune解决“计算太慢”问题。DocPrune的无训练特性使其更易集成到现有RAG框架中，而MinerU2.5需要精细的两阶段训练流程。

从方法设计看，DocPrune与FastV、DivPrune等通用剪枝方法存在根本差异。FastV依赖注意力分数，在文档中易误删关键文本；DivPrune采用迭代优化，计算开销大。DocPrune引入文档结构先验（背景检测）与模型内部状态（L2范数），实现了结构感知与动态决策的结合。与ColPali等检索方法相比，DocPrune复用了检索阶段的嵌入信息用于QTP，体现了模块间的信息复用，而非独立计算。这种设计降低了额外计算成本，但依赖于检索模型与问答模型的特征空间对齐，若两者差异过大，QTP的效果可能受限。

## 总结

DocPrune旨在解决VLM处理文档时的算力冗余问题，抓住文档背景稀疏、证据局部化及理解度层间演进的特性，提出无训练的渐进式剪枝框架。通过BTP、QTP、CTP三阶段协同，在M3DocRAG上实现3.0倍至3.3倍吞吐量提升，F1分数提升1.0。其边界在于实验主要覆盖单页/少页场景，未验证长文档跨页证据的完整性，且L2范数阈值在不同文档复杂度下的鲁棒性未充分探讨。当文档页数增加至数百页时，背景剪枝是否可能移除跨页布局线索，导致关键证据丢失，论文未给出回答。
