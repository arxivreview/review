> 文档生成旨在将设计意图或视觉元素转化为结构化、可编辑的文档产物，但现有方法受限于单一类别覆盖、扁平坐标表示的结构表达力不足及高质量数据稀缺。本文切入点在于引入层级化HTML/CSS作为统一表示，并构建自动化合成管线以突破数据瓶颈。具体做法是微调多模态大语言模型生成HTML/CSS代码，并通过高度感知强化学习抑制内容溢出。该框架在跨类别生成任务上优于通用大模型与专用基线，但其评估高度依赖主观评分且未验证复杂交互场景下的鲁棒性。

## 研究背景

文档生成的核心挑战在于如何在保持视觉保真度的同时确保产物的可编辑性与结构合规性。传统光栅图像生成方法虽能产出高保真视觉结果，但彻底牺牲了文本与元素的独立操控能力；而基于扁平坐标序列（如JSON）的生成方法虽保留了编辑性，却在处理复杂布局时陷入几何计算泥潭，元素间的包含、间距与分组关系需依赖大量精确数值推算，导致模型难以聚焦高层设计意图。这一矛盾催生了对更优文档表示形式的需求，即一种既能自然表达层级结构，又能通过声明式规则简化布局约束的中间表示。

现有文档生成研究多聚焦于特定类别（如海报、幻灯片），缺乏跨类别泛化能力，且依赖人工构建的小规模数据集（如Crello仅含20K样本），限制了模型潜力。主流路线分为光栅生成与坐标生成两类，前者缺乏编辑性，后者在复杂结构下布局质量急剧下降。AnyDoc的切入点在于利用HTML/CSS的层级语义与声明式布局机制（如flexbox、grid），将文档生成转化为代码生成问题，并通过自动化管线合成大规模多类别数据，从而在表示形式与数据规模两个维度同时突破既有瓶颈。

## 核心方法

### 方法参照系

文档生成通常遵循“输入条件→布局规划→元素渲染”流程，现有方法多采用扁平坐标序列作为中间表示，通过回归或自回归预测元素位置与尺寸。本文的关键差异在于摒弃扁平坐标，采用层级化HTML/CSS代码作为统一输出，将布局约束从数值计算转化为声明式样式规则，使模型能直接生成具备结构语义的可编辑文档。

### HTML/CSS统一表示与数据合成

设计动机在于解决扁平坐标表示在复杂文档中因几何计算冗余导致的布局失效问题。HTML的父子层级天然映射元素包含关系，CSS的flexbox与grid模块通过`row-gap`、`justify-content`等属性声明式控制间距与对齐，无需精确坐标推算。数据合成管线包含五阶段：元数据收集（利用InternVL3提取设计意图与描述）、HTML/CSS代码生成（Qwen3-Coder480B基于元数据生成代码）、图像资产合成（FLUX.1-dev生成占位图像）、渲染（Playwright生成截图）及数据清洗。该管线产出DocHTML数据集，含265,206个样本、111个类别与32种风格，每个样本包含元数据、源代码、图像资产与渲染截图，确保数据规模与多样性。

### 高度感知强化学习（HARL）

设计动机在于监督微调（SFT）后模型仍存在内容溢出问题，即生成文档高度超出指定值导致渲染截断。HARL基于Group Relative Policy Optimization（GRPO），对每个输入查询采样一组候选HTML/CSS代码，利用Playwright渲染获取实际高度 $\hat{h}$，并计算与指定高度 $h$ 的比值 $\rho = \hat{h}/h$。奖励函数定义为：

$$r = \begin{cases} 1 - \alpha(\rho - 1) & \text{if } \rho > 1 + \gamma \\ 1 - \alpha(1 - \rho) & \text{if } \rho < 1 - \gamma \\ 1 & \text{otherwise} \end{cases}$$

其中 $\alpha$ 为溢出惩罚系数，$\gamma$ 为容差因子。该公式通过双向惩罚溢出与欠流，防止模型通过缩短内容规避高度约束。GRPO的组相对优势机制使组内高度更接近目标值的候选获得更高奖励，从而在保持视觉质量的同时抑制溢出。

## 实验评估

实验在DocHTML测试集（1,000个随机样本）上进行，基线覆盖通用多模态大模型（GPT-4o、InternVL3-78B）与专用生成模型（WebSight、Design2Code、LaDeCo、OpenCOLE、FLUX.1-dev）。在意图到文档（I2D）任务中，AnyDoc在Layout（8.64）、Position（0.910）、Color（0.958）等指标上优于GPT-4o（8.02、0.871、0.899）；在文档去渲染（DD）任务中，Block（0.965）、Text（0.986）指标领先Design2Code（0.909、0.989）；在元素到文档（E2D）任务中，Layout（8.62）、Innovation（7.36）指标超越GPT-4o（8.09、6.87）。

| 任务 | 方法 | Layout | Position/Block | Height/Ove |
| :--- | :--- | :--- | :--- | :--- |
| I2D | AnyDoc | 8.64 | 0.910 | 0.309 |
| I2D | GPT-4o | 8.02 | 0.871 | 0.034 |
| DD | AnyDoc | 0.965 | 0.986 | 0.0625 |
| DD | Design2Code | 0.909 | 0.989 | 0.3756 |
| E2D | AnyDoc | 8.62 | 8.39 | 0.0494 |
| E2D | GPT-4o | 8.09 | 7.90 | 0.2520 |

消融实验显示，移除HARL导致Height指标从0.005升至0.299，Layout从8.62降至8.48，证实HARL对溢出抑制与整体质量的关键作用。将HTML/CSS替换为扁平坐标表示后，Overlap指标从0.0494恶化至0.2627，验证了层级表示在布局质量上的优势。数据规模从10K增至全量时，指标保持稳定，表明DocHTML的10K子集已具备足够代表性。

评估指标包含MLLM主观评分（Layout、Image等）与客观物理指标（Overlap、Height、Alignment），但缺乏人类专家评估对照，MLLM评分（InternVL3-78B）可能存在主观偏差。实验使用Qwen2.5-VL-7BInstruct作为骨干，SFT采用LoRA（rank=32），HARL采用全参数微调，训练于8块NVIDIA A100 GPU，超参数（学习率1e-4/1e-6、batch size 128/64）已公开，但代码未开源，可复现性受限。

## 关联研究分析

从问题动机看，AnyDoc与Design2Code、WebSight等截图转代码方法同属文档生成领域，但后者依赖扁平坐标表示，在复杂布局下因几何计算冗余导致布局失效；AnyDoc通过HTML/CSS层级结构将布局约束转化为声明式规则，解决了结构表达力不足的问题。这一差异源于任务特性：截图转代码需精确还原视觉布局，而AnyDoc强调跨类别通用生成，层级表示更适配多类别结构多样性。

从方法设计看，AnyDoc与GRPO在LLM对齐中的应用同属强化学习后训练框架，但GRPO的奖励函数基于文本对齐或人类偏好，而AnyDoc的HARL奖励函数基于物理高度约束（渲染高度与指定高度的比值）。这一差异源于文档生成的物理合规性需求：文本生成无高度约束，而文档生成需确保内容在指定画布内完整呈现。HARL通过Playwright渲染反馈实现物理约束优化，是RL在视觉生成任务中的具体化应用。

## 总结

AnyDoc要解决的核心矛盾是文档生成中可编辑性与结构合规性的冲突，现有方法因扁平坐标表示的几何计算冗余与数据稀缺而难以兼顾。本文抓住HTML/CSS的层级语义与声明式布局机制作为切入点，通过自动化合成管线构建DocHTML数据集，并设计HARL后训练抑制内容溢出。实验证明AnyDoc在I2D任务Layout得分8.64、DD任务Block得分0.965，优于GPT-4o与专用基线。其边界在于评估依赖MLLM主观评分且未验证复杂交互场景，当文档包含动态元素或用户交互时，HTML/CSS表示的布局稳定性是否仍具优势，论文未给出回答。
