# CVPR2026最新论文 ｜Pointer-CAD: Unifying B-Rep and Command Sequences via Pointer-based Edges & Faces Selection ｜指针式命令序列

研究机构：北京航空航天大学、上海科技大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_a05c47539961)

> 计算机辅助设计（CAD）自动化生成的核心瓶颈在于，传统命令序列无法表达“选择特定几何实体”这一关键操作，导致倒角、圆角等工业常用操作失效，且离散化引入的量化误差破坏了拓扑水密性。Pointer-CAD 通过引入指针机制，让大语言模型（LLM）直接引用边界表示（B-Rep）中的边和面，将连续几何选择转化为离散指针预测，从而在保持序列生成效率的同时支持复杂编辑。该方法在文本到 CAD 生成任务中显著降低了分段误差（SegE）和通量包围误差（FluxEE），但其对模型容量的依赖及单件建模的局限，使其在复杂装配场景下的泛化能力仍存疑。

## 研究背景

CAD 建模依赖精确的几何与拓扑连接，边界表示（B-Rep）通过参数化曲面、曲线及顶点间的拓扑关系描述实体，是工业标准数据结构。然而，B-Rep 同时包含离散拓扑与连续几何，且需满足严格的水密性约束。当利用 LLM 生成 CAD 时，若仅将操作编码为数值序列，模型无法感知前序步骤生成的几何状态，导致新绘制的曲线无法精确吸附到现有边缘，产生微小的坐标偏差。这种偏差在后续操作中累积，最终导致模型拓扑断裂或水密性失效。

现有 LLM 驱动的 CAD 生成主要分为代码生成与命令序列生成两条路线。代码生成（如 CADmium）虽支持灵活操作，但 Token 序列冗长（平均 424.75 个），推理耗时高（6.14 秒），且依赖外部执行器验证，难以实现实时交互。命令序列生成（如 Text2CAD）效率更高（平均 43.97 个 Token，1.61 秒），但受限于表示能力，无法支持需要显式实体引用的操作（如倒角、圆角），且连续变量的离散化引入了量化误差。Pointer-CAD 的切入点在于，借鉴指针网络（Pointer Networks）思想，在命令序列中嵌入对 B-Rep 几何实体的直接引用，既保留了序列生成的效率，又解决了实体选择缺失与量化误差导致的拓扑失效问题。

## 核心方法

### 方法参照系

Pointer-CAD 属于 LLM 驱动的参数化 CAD 生成路线，其基础架构与 Text2CAD 等命令序列方法一致：将 CAD 建模过程分解为自回归生成的 Token 序列。关键差异在于，传统方法仅预测数值参数，而 Pointer-CAD 在序列中引入“指针”Token，用于从候选几何实体集合中选择操作目标，并将 B-Rep 几何信息作为条件输入 LLM。

### 指针式命令序列表示

传统命令序列将草图平面选择建模为 3D 旋转回归问题，易因量化误差导致平面错位。Pointer-CAD 将其重构为离散选择问题：LLM 预测一个 128 维向量，通过余弦相似度匹配 B-Rep 中的候选面或边。对于倒角（Chamfer）或圆角（Fillet）操作，指针 $p$ 指向目标边集合，参数 $c$ 或 $f$ 统一应用于所有选中边。指针预测采用对比式损失函数，鼓励预测向量与有效候选集 $P$ 的相似度高于无效候选集 $N$：

$$
L_p = - \frac{|P| + |N|}{|P|} \left[ \sum_{j \in P} \log \left( \sigma \left( \frac{\cos(p, c_j)}{\tau} \right) \right) + \sum_{j \in N} \log \left( 1 - \sigma \left( \frac{\cos(p, c_j)}{\tau} \right) \right) \right]
$$

其中 $\sigma$ 为 Sigmoid 函数，$\tau$ 为可学习温度。该设计将几何吸附问题转化为分类问题，消除了连续回归中的量化误差，使新生成的几何元素能精确对齐现有结构。

### 多步条件化生成与 B-Rep 编码

Pointer-CAD 采用多步自回归策略，每步生成均条件化于文本描述及前序步骤累积的 B-Rep 几何。B-Rep 被编码为无向面邻接图 $G(V, E)$，节点为面，边为共享边界。每个面在参数域均匀采样 $32 \times 32$ 网格，提取 3D 坐标、法向量、高斯曲率等特征，经平均池化投影为 128 维嵌入。随后，K 层图神经网络（GNN）传播局部与全局信息，节点特征更新公式为：

$$
h_i^{(k)} = \phi^{(k)} \left( (1 + \epsilon^{(k)}) h_i^{(k-1)} + \sum_{j \in \mathcal{N}(i)} f_\Theta(h_{ij}^{(k-1)}) \odot h_j^{(k-1)} \right)
$$

其中 $\phi^{(k)}$ 为 MLP，$\epsilon^{(k)}$ 为可学习标量，$f_\Theta$ 投影边特征至节点空间。GNN 输出的面与边嵌入通过结构化提示词注入 LLM，使模型在生成当前步骤时能感知全局几何上下文，确保操作的空间一致性。

## 实验评估

Pointer-CAD 在 Recap-DeepCAD（176,439 模型）和 Recap-OmniCAD+（575,559 模型）上评估，基线包括 Text2CAD、CADmium 及适配的 DeepCAD。实验显示，Pointer-CAD 在支持倒角/圆角的 Recap-OmniCAD+ 上表现突出，其 0.5B 模型 SegE 为 0.15，显著优于 Text2CAD 的 0.81，且 FluxEE 为 3.51，低于 Text2CAD 的 35.16，表明指针机制有效提升了拓扑水密性。在 Recap-DeepCAD 上，1.5B 模型 SegE 降至 0.13，优于 Text2CAD 的 0.44 和 CADmium 的 0.47，但 0.5B 模型 SegE 为 0.64，高于基线，显示小模型在指针预测上的容量瓶颈。

| 模型 | 数据集 | CD mean ↓ | SegE ↓ | FluxEE ↓ |
| :--- | :--- | :--- | :--- | :--- |
| Pointer-CAD (0.5B) | Recap-OmniCAD+ | 5.49 | 0.15 | 3.51 |
| Text2CAD | Recap-OmniCAD+ | 13.29 | 0.81 | 35.16 |
| Pointer-CAD (1.5B) | Recap-DeepCAD | 10.53 | 0.13 | 2.97 |
| Text2CAD | Recap-DeepCAD | 17.48 | 0.44 | 17.75 |
| CADmium (7B) | Recap-DeepCAD | 11.51 | 0.47 | 38.63 |

消融实验表明，GNN 对弧结构（Arc F1）提升显著，Pointer-CAD 0.5B 模型 Arc F1 从 67.14 提升至 85.70，CD mean 从 5.13 降至 3.81，验证了图结构编码对复杂几何捕获的有效性。然而，0.5B 模型在 Recap-DeepCAD 上的 SegE 劣于基线，暗示指针预测对模型规模敏感，小模型可能因特征表示不足导致错误选择。评估协议基于归一化空间 $[-0.5, 0.5]^3$，CD 使用 8,192 采样点，FluxEE 缩放 $10^3$ 倍，但未报告置信区间，且缺乏对装配级约束的评估。

## 关联研究分析

从问题动机看，Pointer-CAD 与 Text2CAD 同属命令序列路线，但 Text2CAD 将几何选择视为纯数值回归，导致量化误差累积；Pointer-CAD 通过指针机制将选择离散化，根源在于其任务定义包含“实体引用”这一 Text2CAD 未建模的维度。这一差异并非源于算法复杂度，而是对 CAD 工作流中“点击选择”交互的忠实模拟，使得倒角、圆角等操作成为可能。相比之下，CADmium 等代码生成方法虽支持这些操作，但通过执行 Python 脚本实现，牺牲了序列生成的效率与实时性，Pointer-CAD 在效率（110.72 Token vs 424.75 Token）与功能支持间取得了平衡。

从方法设计看，Pointer-CAD 借鉴了 UV-Net 的图神经网络思想编码 B-Rep 拓扑，但将其应用于 LLM 的条件输入而非独立任务。UV-Net 旨在分类或分割，而 Pointer-CAD 利用 GNN 提取的几何特征作为指针匹配的候选嵌入，实现了几何感知与语义生成的耦合。这种设计使得 LLM 不仅能理解文本语义，还能感知几何上下文，从而在生成时做出空间一致性的决策。然而，Pointer-CAD 未探索多模态输入（如图像、点云），其 B-Rep 编码器仅处理文本条件化场景，限制了其在逆向工程或多模态交互中的应用潜力。

## 总结

Pointer-CAD 旨在解决 LLM 生成 CAD 时命令序列无法支持实体选择及量化误差导致拓扑失效的核心矛盾。其切入点在于将几何选择重构为离散指针预测，并通过多步条件化生成确保全局一致性。该方法在 Recap-OmniCAD+ 上将 SegE 降至 0.15，FluxEE 降至 3.51，显著优于 Text2CAD，验证了指针机制在拓扑有效性上的优势。然而，0.5B 模型在 Recap-DeepCAD 上 SegE 为 0.64，高于基线，暴露了小模型在指针预测上的容量瓶颈，且方法仅支持单件建模，未处理装配级约束。当模型规模扩大至 7B 时，指针预测的准确率是否足以支撑复杂装配体的层级依赖关系，论文未给出回答。
