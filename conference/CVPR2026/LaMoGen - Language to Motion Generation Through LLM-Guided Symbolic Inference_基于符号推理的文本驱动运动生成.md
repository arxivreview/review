# CVPR2026最新论文 ｜LaMoGen: Language to Motion Generation Through LLM-Guided Symbolic Inference ｜基于符号推理的文本驱动运动生成

研究机构：香港浸会大学

作者：Junkun Jiang、Ho Yin Au、Jingyu Xiang 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.11605)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.11605)

> 文本驱动人体运动生成（Text-to-Motion Generation, T2M）旨在从自然语言合成逼真且语义一致的动作，但现有方法常因依赖黑盒嵌入而难以精确对齐细粒度时空指令。LaMoGen 引入基于拉班舞谱（Labanotation）的 LabanLite 符号系统，将运动分解为可解释的原子动作，利用大语言模型（LLM）进行零样本符号组合。该方法在指令遵循与可解释性上表现优异，但在分布相似度指标上显著弱于主流扩散模型，其价值在于建立了语言与运动间的显式符号桥梁，而非追求极致的视觉保真度。

## 研究背景

当指令要求“向前走5步再向后走3步”时，基于联合嵌入的方法往往将其泛化为通用的“行走”动作，丢失了步数与时序约束。这种失效源于连续向量嵌入无法显式编码离散的动作单元与时间间隔。为了解决这一语义对齐难题，拉班舞谱（Labanotation）作为一种记录人体运动的符号系统被引入，它将动作分解为身体部位、方向、时长等属性，但传统拉班谱是事件级的，缺乏帧级对齐，难以直接用于机器学习。

T2M 领域的主流路线分为连续扩散与离散自回归两类。扩散模型（如 MDM）在连续保真度上占优，但推理慢且难以控制细粒度语义；离散自回归模型（如 T2M-GPT）通过 VQ-VAE 将运动离散化，增强了语义组合性，但其 Token 是学习得到的黑盒向量，缺乏人类可解释性。现有方法在“语义精确性”与“生成质量”之间难以兼顾，尤其是面对包含复杂时序逻辑的指令时，缺乏一种既能被 LLM 理解又能精确映射到运动的中间表示。

LaMoGen 的切入点在于将拉班舞谱改造为帧级、身体部位级的 LabanLite 表示。每个符号不仅对应一个动作，还绑定一个标准化的文本描述（Conceptual Description）。这种设计使得 LLM 可以通过检索增强提示（RAG）直接组合符号序列，充当运动规划器，从而在生成前就明确动作的结构与时序，解决了传统方法中语义与运动解耦的问题。

## 核心方法

### 方法参照系

本文问题属于离散自回归生成范式，但关键差异在于 Token 的来源与生成机制。标准流程使用 VQ-VAE 学习离散 Token，再由 Transformer 自回归生成。LaMoGen 摒弃了学习式离散化，采用规则提取的拉班符号作为 Token，并引入 LLM 进行高层符号规划，将生成过程解耦为“符号组合”与“运动解码”两个阶段。

### LabanLite 符号表示与编码

LabanLite 将运动序列 $X = \{x_t\}_{t=1}^T$ 转换为帧级符号实例序列 $S$。对于每个身体部位组 $j$ 和帧 $t$，符号 $s_{t,j}$ 由方向、水平、姿态等属性字段定义。设计动机是解决 VQ-VAE Token 缺乏语义解释性的问题，使 LLM 能直接理解 Token 含义。编码过程通过查表将符号映射为向量：

$$ z_t = \sum_{j=1}^G C_{s_{t,j}} $$

其中 $C$ 是拉班码本，$G$ 是身体部位组数。该公式将离散的符号组合线性叠加为连续潜变量，保留了动作的结构信息，同时允许通过线性组合近似连续变化。

### LLM 引导的符号组合与解码

LLM 接收文本指令与检索到的参考符号序列，生成概念级符号序列 $S_{concept}$。设计动机是利用 LLM 的推理能力处理复杂时序逻辑，弥补纯数据驱动模型在长程依赖上的不足。随后，运动生成器（Transformer 解码器）将 $S_{concept}$ 细化为详细符号并解码为运动：

$$ \hat{X} = \mathcal{D}(\mathcal{A}(S_{concept})) $$

其中 $\mathcal{A}$ 是运动学细节增强器，$\mathcal{D}$ 是解码器。这一过程将高层语义规划与低层运动合成分离，使得 LLM 只需关注动作逻辑，而无需处理高维运动数据，显著提升了生成过程的可解释性与可控性。

## 实验评估

实验在 HumanML3D 和 KIT-ML 数据集上进行，基线包括 MDM、CoMo、MotionGPT 等。LaMoGen（GPT-4.1）在 HumanML3D 上的 R@3 达到 0.813，FID 为 0.206。相比之下，CoMo 的 R@3 为 0.790，FID 为 0.262；MDM 的 R@3 为 0.611，FID 为 0.544。LaMoGen 在语义对齐指标（R-Precision）上优于 CoMo 和 MDM，但 FID 高于 CoMo，表明其符号抽象牺牲了部分低层运动细节的多样性。

| 方法 | R@3 ↑ | FID ↓ | MM-Dist ↓ |
| :--- | :--- | :--- | :--- |
| MDM | 0.611 | 0.544 | 5.566 |
| CoMo | 0.790 | 0.262 | 3.032 |
| MotionGPT | 0.778 | 0.232 | 3.096 |
| LaMoGen (GPT-4.1) | 0.813 | 0.206 | 2.993 |

消融实验显示，检索参考数量从 1 增加到 3 时，R@3 从 0.755 提升至 0.796，FID 从 0.595 降至 0.252；增加到 5 或 7 时性能不再提升，甚至略有下降，表明 LLM 上下文窗口限制导致过多参考反而干扰推理。掩码比例（Masking Ratio）为 0.3 时性能最佳，过高或过低均导致语义引导失效。

评估边界方面，LaMoGen 依赖外部 LLM API，推理延迟高，不满足实时交互需求。代码未开源，但提供了详细的超参数（如学习率 $1 \times 10^{-4}$，Batch Size 512）。指标上，LaMoGen 在自建 Laban Benchmark 上表现优异，但在标准 FID 上弱于专用生成模型，说明其优势在于语义精确性而非分布覆盖。

## 关联研究分析

从问题动机看，LaMoGen 与 CoMo 均致力于细粒度控制，但 CoMo 使用 Pose Code 表示关键姿态，缺乏过渡动态；LaMoGen 使用拉班符号，显式编码方向与时长，更适合处理时序指令。根源在于 CoMo 关注空间姿态的离散化，而 LaMoGen 关注动作结构的符号化。从方法设计看，LaMoGen 与 MotionGPT 均利用 LLM，但 MotionGPT 通过微调 LLM 使其直接生成运动 Token，而 LaMoGen 保持 LLM 零样本，仅通过 RAG 组合符号。MotionGPT 的路线更紧凑，但缺乏可解释性；LaMoGen 的路线更透明，但依赖符号系统的完备性。

## 总结

LaMoGen 解决了 T2M 中细粒度语义对齐与可解释性不足的矛盾，通过 LabanLite 符号系统使 LLM 能显式规划动作结构。实验证明其在指令遵循上优于 CoMo 和 MDM，R@3 达 0.813，FID 0.206。其边界在于符号抽象丢失了低层运动细节，导致 FID 高于专用生成模型，且依赖 LLM 推理，延迟较高。当指令包含未见过的复杂动作组合时，拉班符号系统的完备性是否足以覆盖所有语义，论文未给出回答。
