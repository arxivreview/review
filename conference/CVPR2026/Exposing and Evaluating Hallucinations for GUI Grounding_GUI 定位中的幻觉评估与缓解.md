# CVPR2026最新论文 ｜Exposing and Evaluating Hallucinations for GUI Grounding ｜GUI 定位中的幻觉评估与缓解

研究机构：上海交通大学、复旦大学

作者：Zicheng Zhang、Hongyi Jing、Rui Lv 等 10 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_3a09864071d9)

> 现有 GUI 基准主要考察模型能否完成点击任务，却忽视了模型在无法定位时“自信地编造坐标”的可靠性风险。本文指出，定位幻觉并非孤立现象，而是源于底层界面解析（Parsing）能力的缺失。通过构建首个双语 GUI 幻觉基准 GUI-HalluBench，并验证“先解析后定位”的提示工程与幻觉感知微调策略，本文证明了提升结构感知能力可显著抑制幻觉。该工作填补了 GUI 可靠性评估的空白，但其缓解策略对模型端到端推理效率的影响及跨语言泛化边界尚存疑。

## 研究背景

GUI 定位要求多模态大语言模型（LMMs）将自然语言指令映射至屏幕特定像素坐标。然而，当指令指向的元素在截图中不存在或视觉特征高度相似时，模型往往不会拒绝回答，而是输出看似合理的错误坐标。这种失效模式被定义为幻觉，具体分为两类：一是混淆幻觉（Confusion Hallucination），即模型因语义歧义或视觉相似性错误选中干扰元素；二是捏造幻觉（Fabricated Hallucination），即模型凭空想象出界面中不存在的元素并生成坐标。

当前主流 GUI 基准如 ScreenSpot 和 ScreenSpot-Pro 侧重于评估模型在标准场景下的定位准确率，缺乏对模型“鲁棒性”和“可靠性”的系统考察。这些基准假设目标元素必然存在，导致模型在遇到负样本（即目标不存在）时的行为未被量化。与此同时，现有自然图像幻觉基准（如 POPE）关注物体级幻觉，无法捕捉 GUI 结构化界面中特有的功能混淆与元素捏造问题。本文的切入点在于揭示定位幻觉与界面解析能力之间的因果关联：模型若无法正确解析界面结构（Parsing），便极易在定位阶段产生幻觉。

## 核心方法

### 方法参照系

标准 GUI 定位流程通常采用端到端范式，即模型直接接收截图与指令，输出坐标。本文将其置于“解析-定位”两阶段框架下审视，关键差异在于：本文不将解析视为可选的中间步骤，而是将其定义为定位可靠性的前置必要条件，并针对解析失败导致的幻觉设计了专用评估与缓解机制。

### 解析引导提示（PGP）

在标准流程中，模型直接执行定位任务。本文引入 PGP 策略，强制模型在单次推理中先执行解析步骤，再执行定位步骤。具体而言，提示词要求模型首先枚举界面上所有可见元素（图标与文本）及其语义和坐标，然后基于此解析结果定位目标元素。该策略的设计动机在于，显式的解析过程迫使模型建立对界面结构的完整认知，从而在定位时能够区分相似元素或识别目标缺失。其核心逻辑可形式化为：

$$
\text{Output} = \text{Grounding}(\text{Parse}(I), T)
$$

其中 $I$ 为截图，$T$ 为指令，$\text{Parse}(I)$ 生成包含所有元素语义与坐标的结构化列表。通过这种链式推理，模型在输出最终坐标前已完成了对界面元素的“预筛选”，降低了因视觉相似性导致的混淆概率。

### 幻觉感知微调（HFT）

PGP 仅依赖提示工程，无法改变模型内部的表征分布。HFT 策略通过引入幻觉标注数据对模型进行微调，以增强其对幻觉场景的鲁棒性。训练数据包含两类样本：混淆样本（目标存在但存在相似干扰项）和捏造样本（目标不存在）。微调目标函数旨在最小化模型在捏造场景下输出坐标的概率，同时保持其在混淆场景下正确定位的能力。形式化地，HFT 优化的是模型在幻觉分布下的条件概率：

$$
\mathcal{L}_{HFT} = - \sum_{i \in \mathcal{D}_{hallu}} \log P(y_i | I_i, T_i, \theta)
$$

其中 $\mathcal{D}_{hallu}$ 为包含幻觉标注的数据集，$y_i$ 为真实标签（包括“无此元素”的拒绝标签）。通过显式训练模型识别“无目标”状态，HFT 使模型学会了在不确定时弃权，而非强行生成坐标。

## 实验评估

| 模型 | Parsing-Avg (%) | Hallu-Avg (%) |
| :--- | :--- | :--- |
| GPT-4o (with grounding) | 20.2 | 47.2 |
| Qwen3-VL-8B | 58.1 | 62.2 |
| Qwen3-VL-8B (PGP) | 58.1 | 65.3 |
| Qwen3-VL-8B (HFT) | 72.3 | 69.1 |

实验在 GUI-HalluBench 上进行，该基准包含 2,000 个双语（中/英）样本，涵盖移动、Web 和桌面平台。基线覆盖了闭源模型（GPT-4o, Claude, Gemini）和开源模型（Qwen3-VL, InternVL, UI-TARS 等）。结果显示，开源模型在解析和幻觉抵抗上普遍优于闭源模型，其中 Qwen3-VL-8B 表现最佳。应用 PGP 后，Qwen3-VL-8B 的幻觉平均准确率从 62.2% 提升至 65.3%，表明解析引导对缓解幻觉有正向作用。进一步应用 HFT 后，该指标提升至 69.1%，解析平均准确率也从 58.1% 跃升至 72.3%，证实了微调对结构感知能力的显著增强。

消融分析显示，HFT 带来的提升幅度（约 7%）远大于 PGP（约 3%），且 HFT 同时提升了解析性能，说明幻觉抑制与结构理解是协同优化的。值得注意的是，GPT-4o 尽管在通用推理上强大，但其解析精度仅为 20.2%，导致其幻觉抵抗能力极弱（47.2%），这揭示了通用 LMM 在 GUI 结构化感知上的固有短板。

评估边界方面，GUI-HalluBench 引入了双语覆盖，但中文数据占比约 50%，可能存在文化偏差。此外，基准仅包含 2,000 个样本，规模较小，可能限制统计显著性。代码已开源，但 HFT 的训练细节（如 LoRA 配置）仅在附录中简要提及，复现难度中等。

## 关联研究分析

从问题动机看，本文与 ScreenSpot 系列基准形成互补。ScreenSpot 关注“能否找到”，而 GUI-HalluBench 关注“找不到时是否诚实”。这种差异源于任务定义的不同：ScreenSpot 假设目标必然存在，而本文引入了负样本机制。根源在于 GUI 智能体在实际部署中常面临动态界面变化，目标元素可能消失，因此“拒绝回答”的能力比“强行猜测”更具实用价值。

从方法设计看，本文的 PGP 策略与 UI-Actor 的无坐标定位范式形成对比。UI-Actor 试图通过注意力机制直接生成视觉 Patch 权重，避免离散坐标生成的误差累积；而 PGP 仍依赖文本坐标输出，但通过前置解析步骤提高可靠性。两者的差异在于：UI-Actor 追求架构层面的连续化，PGP 追求推理层面的结构化。PGP 的局限在于增加了推理延迟，且未解决坐标量化误差问题，而 UI-Actor 在复杂布局下的泛化能力尚未经过大规模基准验证。

## 总结

本文核心矛盾在于 GUI 定位模型在目标缺失或模糊时的可靠性缺失。切入点在于揭示解析能力是定位可靠性的基石，通过构建 GUI-HalluBench 并验证 PGP 与 HFT 策略，证明了提升结构感知可显著抑制幻觉。实验显示，HFT 使 Qwen3-VL-8B 的幻觉平均准确率从 62.2% 提升至 69.1%。边界在于，HFT 依赖大量幻觉标注数据，且 PGP 增加了推理开销，未探索在不增加训练成本的前提下实现高效幻觉抑制的方法。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
