> 指令式图像编辑（IBIE）面临的核心瓶颈并非模型架构的缺失，而是缺乏大规模、高质量且可共享的真实图像编辑数据。现有数据集多依赖合成生成或有限的人工标注，导致分布偏差与质量不可控，阻碍了模型在复杂场景下的泛化。本文通过构建 Pico-Banana-400K，利用前沿多模态大语言模型（MLLM）生成编辑对并自动质检，填补了这一数据基础设施空白。其价值在于提供了包含多轮序列与偏好对的多目标训练资源，但数据集本身未验证下游模型性能，且对细粒度空间编辑的覆盖存在明显短板。

## 研究背景

指令式图像编辑要求模型根据自然语言指令修改图像，同时保持非编辑区域的一致性。这一任务依赖高质量的“指令-图像对”进行监督微调，但真实世界中的编辑意图难以大规模获取。早期数据集如 MagicBrush（Yin et al., 2023）仅包含 10K 人工标注样本，规模受限；而 HQ-Edit（Hui et al., 2024）等合成数据集虽规模较大，却存在领域偏移与质量噪声，导致模型在真实场景下的鲁棒性不足。

领域主流路线正从单纯扩大数据规模转向提升数据质量与多样性。然而，现有方案在“可共享性”与“细粒度控制”上存在矛盾：合成数据虽易获取但缺乏真实纹理，人工标注数据虽真实但成本高昂且难以扩展至百万级。Pico-Banana-400K 的切入点在于利用 Nano-Banana 等前沿 MLLM 从 OpenImages 真实照片中生成编辑对，并通过 Gemini-2.5-Pro 进行自动化多维度质检，从而在保持真实图像底色的同时，实现了数据规模的自动化扩展与质量的可控过滤。

## 核心方法

### 方法参照系

本文属于数据构建路线，其参照系为传统的“生成-过滤”数据流水线。与 MagicBrush 等依赖人工标注的流程不同，本文的关键差异在于将 MLLM 同时作为生成器与评估器，实现了从数据生成到质量控制的闭环自动化，无需人工介入即可处理大规模真实图像。

### 双指令生成与自动质检机制

传统数据构建通常仅提供单一粒度的指令，且依赖人工筛选。本文在指令生成环节引入了双格式策略，利用 Gemini-2.5-Flash 生成详细训练指令，同时通过 Qwen2.5-7B-Instruct 结合人工示例重写为简洁用户风格指令，以覆盖从精确监督到自然交互的不同需求。在质检环节，Gemini-2.5-Pro 作为自动裁判，依据加权评分函数对编辑结果进行评估：

$$
S = 0.4 \cdot C_{inst} + 0.25 \cdot S_{seam} + 0.20 \cdot P_{bal} + 0.15 \cdot T_{qual}
$$

其中 $C_{inst}$ 为指令遵循度，$S_{seam}$ 为无缝性，$P_{bal}$ 为保持平衡，$T_{qual}$ 为技术质量。该公式将主观的视觉质量转化为可量化的阈值判断（阈值设为 0.7），解决了人工标注无法扩展至 400K 规模的问题，同时通过保留失败案例作为负样本，为偏好学习提供了数据基础。

### 多轮序列与偏好对构建

单轮编辑无法捕捉指令间的上下文依赖，导致多轮交互中的累积误差。本文从单轮数据中均匀采样 100K 样本，随机扩展 1-4 个额外编辑类型，形成 2-5 轮的多轮序列。指令生成时，Gemini-2.5-Pro 被提示使用指代语言（如“change the color of it”）链接前序编辑，强调话语连续性。这一设计解决了现有数据集多轮编辑中指令独立、缺乏语义关联的问题，使得模型能够学习在连续修改中维持场景一致性的能力。

## 实验评估

本文未报告基于该数据集训练的模型在 GEdit-Bench 等标准基准上的性能，仅提供了数据集内部的成功率统计与构成分析。作为数据资源，其有效性需通过下游模型训练验证，本文本身未提供此类对比基线。

| 编辑类型 | 成功率 |
| :--- | :--- |
| Strong artistic style transfer | 0.9340 |
| Film grain/vintage | 0.9068 |
| Modern↔historical restyling | 0.8875 |
| Remove object | 0.8328 |
| Relocate object | 0.5923 |
| Change font/style | 0.5759 |

数据显示，全局风格编辑成功率最高（0.9340），而涉及细粒度空间控制与文字渲染的编辑类型成功率显著较低（Relocate object 0.5923, Change font/style 0.5759）。这一分布揭示了当前 MLLM 在几何一致性上的局限，也暗示了该数据集在空间编辑任务上的监督信号可能较弱。

评估边界方面，本文未提供代码超参数细节或 GPU 资源需求，仅公开了数据与代码仓库。质检阈值 0.7 的设定缺乏消融实验支持，其是否足以区分“难负例”与“易负例”尚不明确。此外，数据集依赖 Nano-Banana 的生成能力，若该模型存在系统性偏差，数据集将继承此偏差，且缺乏独立于生成模型的第三方验证机制。

## 关联研究分析

从数据构建策略看，Pico-Banana-400K 与 MagicBrush 形成鲜明对比。MagicBrush 依赖人工标注确保质量，但规模仅 10K；本文利用 MLLM 自动质检实现 400K 规模，但牺牲了人工标注的绝对准确性。这种差异源于任务特性：真实图像编辑的多样性远超人工标注能力，自动化是规模化的唯一路径。然而，自动质检的可靠性取决于裁判模型（Gemini-2.5-Pro）的能力上限，若裁判模型对某些编辑类型（如文字渲染）存在盲区，数据集的质量控制将失效。

从多轮编辑设计看，本文与 EditReward 等偏好学习工作形成互补。EditReward 关注奖励模型的训练，而本文提供了 56K 偏好对作为训练数据。本文的多轮序列设计强调指代消解，这与 MIRA 等推理框架关注的指令分解不同。MIRA 通过显式推理分解复杂指令，而本文通过数据层面的多轮序列隐式学习上下文依赖。这种差异暗示，数据驱动的多轮学习可能无法完全替代显式推理机制，特别是在涉及复杂逻辑推理的场景中。

## 总结

Pico-Banana-400K 旨在解决指令式图像编辑中高质量真实数据稀缺的问题。其切入点在于利用前沿 MLLM 生成与质检的闭环，实现了数据规模的自动化扩展。本文构建了包含 258K 单轮样本、56K 偏好对及 72K 多轮序列的数据集，证明了 MLLM 在数据构建中的可行性。然而，数据集在细粒度空间编辑上的成功率较低（0.5923），暴露了当前生成模型在几何一致性上的局限。当使用此数据集训练模型时，空间编辑任务的性能提升是否受限于数据本身的分布偏差，而非模型架构，这一问题在本文未得到回答。
