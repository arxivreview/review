# CVPR2026最新论文 ｜UniChange: Unifying Change Detection with Multimodal Large Language Model ｜统一变化检测的多模态大语言模型框架

研究机构：南开大学

作者：Xu Zhang、Danyang Li、Xiaohang Dong 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2511.02607)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2511.02607)

> 遥感变化检测长期受困于二元与语义任务的架构割裂，以及多源数据间类别定义的语义冲突，导致模型泛化能力受限。现有专用模型无法同时利用不同标注类型的数据进行联合训练，而传统视觉基础模型方案又难以处理跨数据集的标签不一致。UniChange 通过引入特殊 Token 机制，将变化检测重构为基于嵌入查询的生成任务，实现了单一模型对二元与语义检测的统一支持。该框架在多个基准上取得了有竞争力的性能，但其对多模态大语言模型推理效率的依赖及语义 Token 的泛化边界仍需进一步审视。

## 研究背景

变化检测的核心在于从双时相图像中识别地表动态，其任务复杂度从仅定位变化区域的二元变化检测（Binary Change Detection, BCD）延伸至需识别“从-到”语义转换的语义变化检测（Semantic Change Detection, SCD）。SCD 不仅要求像素级定位，还需区分具体的土地覆盖类别转换，这使其在决策支持中提供比 BCD 更丰富的信息。然而，这两类任务在数据标注与模型架构上存在根本性差异：BCD 数据集通常仅包含变化掩码，而 SCD 数据集则包含双时相的语义分割标注。这种差异导致传统模型难以在混合数据源上进行联合训练，因为同一地物（如建筑）在一个数据集中是正样本，在另一个数据集中可能被视为背景。

主流研究路线长期遵循专用化设计：BCD 模型采用孪生网络结构提取差异特征，SCD 模型则通过解耦策略或双编码器架构处理语义转换。这种架构的不兼容性使得模型只能从单一类型的数据中学习，限制了知识迁移与泛化能力。尽管视觉基础模型（Vision Foundation Models, VFMs）如 SAM 被引入以增强特征表示，但现有方法如 RSBuilding 仍局限于特定地物类别，无法扩展至通用的多类别变化检测。UniChange 的切入点在于利用多模态大语言模型（Multimodal Large Language Models, MLLMs）的语言先验与统一能力，将 BCD 和 SCD 任务转化为基于文本指令的生成问题，从而打破架构壁垒并解决数据语义冲突。

## 核心方法

### 方法参照系

传统变化检测模型通常由视觉骨干、特征融合模块和任务特定的解码器组成。BCD 模型输出单一变化掩码，SCD 模型则需输出双时相语义掩码及变化掩码。本文的关键差异在于摒弃了固定的分类头与专用解码器，转而采用 MLLM 作为核心推理引擎，通过文本指令动态引导像素级掩码生成，实现了任务定义的统一。

### 嵌入即变化范式

传统方法依赖预定义的分类头来区分语义类别，这在多源数据联合训练时会导致类别冲突。UniChange 提出“嵌入即变化”（Embedding as Change）范式，将语义类别转化为文本查询，通过特殊 Token 的嵌入向量作为动态查询键。该设计消除了对固定类别头的依赖，使得模型能够处理类别定义不一致的数据集。具体而言，MLLM 根据文本指令自回归生成包含特殊 Token 的序列，这些 Token 的最后一层嵌入经 MLP 投影后，作为查询向量与视觉特征交互：

$$ \hat{h}_{task} = MLP(h_{task}) $$

其中 $h_{task}$ 是 MLLM 中对应特殊 Token 位置的最后一层嵌入。这一机制允许模型通过文本语义动态指定检测目标，而非依赖硬编码的类别索引。

### Token 驱动解码器

Token 驱动解码器（Token Driven Decoder）负责将 MLLM 的高层指令转化为像素级掩码。该解码器接收双时相图像的多尺度特征与投影后的任务嵌入，通过层级化的注意力机制进行特征细化。解码器包含四层，每层处理对应尺度的视觉特征，任务查询通过自注意力与跨注意力机制与视觉序列交互。最终，精化的任务查询与视觉特征通过爱因斯坦求和运算生成掩码：

$$ M_{task} = \sum_{i} \hat{e}_{task} \cdot F_{task}^{(i)} $$

其中 $\hat{e}_{task}$ 是精化后的任务嵌入，$F_{task}^{(i)}$ 是对应尺度的视觉特征。这种设计使得同一解码器结构能够根据输入 Token 的不同，灵活生成变化掩码或语义掩码，实现了架构层面的统一。

## 实验评估

实验在 WHU-CD、S2Looking、LEVIR-CD+ 和 SECOND 四个基准上进行，基线覆盖了 CNN、Transformer 及 VFM 路线，但缺失纯无训练开放词汇检测方法的对比。UniChange 在 BCD 任务上表现优异，在 WHU-CD 上取得 94.96 的 F1 分数，在 LEVIR-CD+ 上达到 88.19 的 F1 分数，均优于对比方法。在 SCD 任务上，SECOND 数据集上的 IoU 为 57.62，F_scd 为 63.50，展现了语义理解能力。

| 数据集 | 指标 | UniChange | 最佳基线 | 基线方法 |
| :--- | :--- | :--- | :--- | :--- |
| WHU-CD | F1 | 94.96 | 91.76 | Changer |
| LEVIR-CD+ | F1 | 88.19 | 86.44 | SFCD-Net |
| SECOND | IoU | 57.62 | 56.89 | SCD-SAM |
| SECOND | F_scd | 63.50 | 62.88 | HGINet |

消融实验表明，双时相语义监督对性能提升显著，同时监督 T1 和 T2 图像比仅监督单一时相更有效。视觉骨干的选择影响性能，RSBuilding-ViT-L 在冻结与微调设置下均优于 SAM 和 SAM2。LoRA 秩为 8 时性能最佳，表明适度的参数更新足以适配变化检测任务。联合训练多个数据集（A+B+C+D）能进一步提升泛化能力，验证了多源数据融合的有效性。

评估协议采用标准的像素级指标，但未报告计算效率与推理延迟，这在 MLLM 框架下是一个关键缺口。代码已开源，超参数设置详细，但训练依赖 4 块 H100 GPU，资源门槛较高。指标完备性方面，SCD 任务使用了 mIoU、F_scd 和 SeK，但缺乏对长序列生成事实性的评估，这与变化描述任务的评测标准存在差异。

## 关联研究分析

从问题动机看，UniChange 与 SCD-SAM 均利用 VFM 增强特征表示，但 SCD-SAM 采用专用双编码器架构，仅针对 SCD 任务优化，而 UniChange 通过 MLLM 统一了 BCD 与 SCD。这种差异源于任务定义方式的不同：SCD-SAM 依赖固定类别头，限制了其处理多源数据的能力；UniChange 通过文本 Token 动态定义类别，解决了数据语义冲突问题。然而，UniChange 对 MLLM 推理能力的依赖可能引入额外的计算开销，这在实时遥感监测场景中是一个潜在瓶颈。

从方法设计看，UniChange 与 TaCo 在语义约束策略上存在显著差异。TaCo 通过时空语义一致性约束提升检测精度，属于专用语义约束路线；UniChange 则通过 MLLM 的语言先验隐式建模语义关系，属于统一生成路线。TaCo 在 SECOND 上取得了 0.960 的 F1 分数，高于 UniChange 的 57.62 IoU（指标不同，不可直接比，但 TaCo 的 F1 极高暗示其定位精度更强）。这表明专用模型在特定任务上仍可能优于统一框架，UniChange 的优势在于灵活性与数据兼容性，而非绝对精度。

## 总结

UniChange 解决了变化检测领域长期存在的任务割裂与数据语义冲突问题，通过 MLLM 的语言先验与特殊 Token 机制，实现了 BCD 与 SCD 任务的统一。该框架在 WHU-CD 上取得 94.96 的 F1 分数，在 SECOND 上取得 63.50 的 F_scd 分数，证明了统一框架的有效性。然而，实验未报告推理延迟，且 SCD 性能低于专用模型 TaCo，暴露了 MLLM 在像素级定位精度上的局限。当支持集增大时，文本 Token 的语义泛化能力是否足以弥补专用分类头的精度损失，论文未给出回答。
