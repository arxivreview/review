# CVPR2026最新论文 ｜HorizonForge: Driving Scene Editing with Any Trajectories and Any Vehicles ｜可控驾驶场景编辑与统一基准

研究机构：美国石溪大学

作者：Yifan Wang、Francesco Pittaluga、Zaid Tasneem 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.21333)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.21333)

> 自动驾驶长尾场景验证面临真实数据稀缺与合成数据物理失真双重困境，现有重建法缺乏泛化性，纯生成法难以保持结构一致性。HorizonForge 通过提取可编辑的 3D 高斯泼溅与网格资产，结合噪声感知视频扩散模型，实现了单次前向传播下的多智能体轨迹编辑。该框架在 Waymo 数据集上建立了统一评测基准 HorizonSuite，验证了 3D 表示与时序先验对生成质量的关键作用，但其离线编辑范式与实时闭环仿真的差距仍存疑。

## 研究背景

理解本文需厘清 3D 高斯泼溅（3D Gaussian Splatting, 3DGS）与视频扩散模型（Video Diffusion Model, VDM）的协同机制。3DGS 以各向异性高斯原语表示场景，通过 Alpha 混合实现实时光栅化，但其在新视角下易产生伪影；VDM 通过迭代去噪过程 $p_\theta(x_{t-1}|x_t, c)$ 从噪声恢复图像，具备强大的生成能力但缺乏显式几何约束。将 3DGS 作为条件输入 $c$ 注入 VDM，旨在利用前者提供空间结构，后者修正视觉细节，从而解决单一模态在可控性与真实感上的局限。

驾驶场景合成领域长期受困于“重建-生成”二元对立：基于重建的方法（如 OmniRe）几何精度高但无法生成未见区域，基于生成的方法（如 StreetCrafter）能幻觉新内容但结构漂移严重。混合仿真路线试图融合两者，但现有工作多依赖逐轨迹优化，计算开销大且难以规模化。HorizonForge 的切入点在于简化这一流程，摒弃复杂的优化循环，转而通过单次前向传播实现从 3D 资产编辑到视频渲染的映射，并引入语言驱动的车辆插入机制，以解决细粒度交通编辑中可控性与计算效率的矛盾。

## 核心方法

### 3D 资产提取与网格对齐

本文方法参照系为混合仿真流程：场景重建 $\rightarrow$ 资产编辑 $\rightarrow$ 视频渲染。与依赖逐轨迹优化的传统混合方法不同，HorizonForge 将编辑解耦为静态资产操作与动态渲染两个阶段。3D 资产提取阶段利用 OmniRe 从输入视频重建 3DGS，同时通过 SAM 分割与 Pix2Gestalt 补全获取车辆网格。针对 Hunyuan3D 生成网格缺乏度量尺寸与正确朝向的问题，本文设计了基于深度差异与 IoU 的对齐目标函数：

$$ \min_s \left( \| D(M_s) - D_{gt} \|_2^2 + (1 - \text{IoU}(B(M_s), B_{gt})) \right) $$

其中 $M_s$ 为缩放后的网格，$D$ 为渲染深度，$B$ 为投影包围盒。该公式通过联合优化深度一致性与几何重叠度，确保插入车辆与真实场景在空间尺度与姿态上的物理兼容，解决了文本生成网格直接插入导致的穿模或比例失调问题。

### 噪声感知视频扩散渲染

资产编辑后的 3D 场景需渲染回 2D 视频，但 3DGS 在新视角下的伪影会破坏视觉真实感。本文在 VDM 的去噪过程中引入光栅化帧作为条件，训练模型学习从“带伪影的 3D 渲染”到“真实视频”的映射。训练数据通过循环重建策略构建：对原始轨迹 $T$ 施加扰动 $\delta$ 得到 $\tilde{T}$，渲染 $\tilde{v}$ 并重建新 3DGS，再渲染回 $T$ 形成配对样本。扩散模型预测噪声 $\epsilon_\theta(x_t, t, v_c)$，其中 $v_c$ 为条件视频。这一设计动机在于利用 VDM 的时序先验填补 3D 重建的几何缺失，相比图像扩散模型，VDM 能更好地维持跨帧一致性，避免复杂多智能体编辑中的时间闪烁，实现了单次前向传播下的高保真生成。

## 实验评估

实验在 Waymo 数据集上进行，基线涵盖重建法（OmniRe）、生成法（StreetCrafter）及混合法（Difix3D）。HorizonForge 在用户研究中取得 91.02% 的胜率，显著优于 OmniRe 的 7.78% 与 StreetCrafter 的 0.40%，表明其在感知质量与轨迹一致性上的综合优势。

| 方法 | Win Rate (%) |
| :--- | :--- |
| StreetCrafter | 0.40 |
| Difix3D | 0.80 |
| OmniRe | 7.78 |
| **HorizonForge** | **91.02** |

消融实验揭示了两个关键设计决策的影响。首先，3D 条件模态的选择至关重要：在自车速度变化任务中，使用 3DGS 条件的 FID 为 39.92，而使用点云条件的 FID 高达 62.16，使用包围盒条件的 FID 更是达到 108.54。这证实了 3DGS 在编码外观线索上的优越性，稀疏点云缺乏细节，包围盒则完全缺失视觉上下文。其次，时序先验不可或缺：视频扩散模型在车道变更任务中的 FVD 为 583.78，而图像扩散模型（Difix3D 骨干）的 FVD 高达 869.06，表明 VDM 在维持时序连贯性上具有显著优势。

| 条件模态 | 自车速度变化 FID | 自车车道变更 FVD |
| :--- | :--- | :--- |
| Point Cloud | 62.16 | 877.87 |
| BBox | 108.54 | 152.10 |
| Image DM | 82.19 | 920.29 |
| **Ours (3DGS+VDM)** | **39.92** | **583.78** |

评估边界方面，HorizonSuite 基准虽覆盖了多种编辑任务，但主要基于离线视频生成，未涉及实时闭环交互延迟测试。指标体系包含 FID、FVD、VIMS、BAS 及 OSR，但缺乏物理动力学约束的量化指标（如碰撞时间 TTC），且未报告置信区间，数值比较需谨慎。代码与超参数细节部分依赖附录，复现需依赖 CogVideoX 骨干与特定预训练模型。

## 关联研究分析

从方法设计看，HorizonForge 与 SimScale 均利用 3D 高斯泼溅提升几何一致性，但 SimScale 侧重闭环强化学习训练，强调场景对自车动作的实时响应；HorizonForge 则聚焦离线编辑，通过单次前向传播生成多样化场景，牺牲了实时性以换取编辑的灵活性与计算效率。这种差异源于任务目标的不同：前者旨在训练策略，后者旨在生成测试数据。HorizonForge 未探索实时推理加速，这限制了其在在线闭环仿真中的应用潜力。

从问题动机看，HorizonForge 与 MagicDrive 均致力于解决多视角一致性，但 MagicDrive 依赖跨视角注意力机制在 2D 隐空间对齐，HorizonForge 则通过显式 3D 资产编辑实现几何对齐。MagicDrive 的纯 2D 生成难以保证物理可行性，而 HorizonForge 的 3D 条件提供了硬约束，但这也导致其对新物体插入的依赖性强，需借助外部网格生成模型。这种对显式几何的依赖是否会在极端长尾场景（如复杂遮挡）中导致泛化能力下降，论文未给出充分验证。

## 总结

HorizonForge 旨在解决驾驶场景编辑中真实性与可控性的权衡矛盾，通过 3D 高斯泼溅与网格资产提取，结合噪声感知视频扩散模型，实现了单次前向传播下的多智能体编辑。实验表明，3DGS 条件相比点云或包围盒显著降低了 FID，视频扩散模型相比图像扩散模型大幅改善了时序一致性，用户研究胜率高达 91.02%。然而，该方法依赖离线 3D 重建与外部网格生成，未解决实时闭环仿真的延迟问题，且缺乏物理动力学约束的量化评估。当编辑任务涉及极端长尾场景或复杂遮挡时，显式 3D 资产的泛化能力是否足以维持生成质量，仍是该框架面临的具体挑战。
