# CVPR2026最新论文 ｜Geometrically-Constrained Agent for Spatial Reasoning ｜几何约束智能体

研究机构：北京航空航天大学、上海交通大学

作者：Zeren Chen、Xiaoya Lu、Zhijie Zheng 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2511.22659)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2511.22659)

> 视觉-语言模型（Vision-Language Models, VLMs）在空间推理中面临语义空间与几何空间解耦的“语义-几何鸿沟”，导致其无法精确执行三维几何计算。现有训练式方法受限于“预言机悖论”，而工具集成方法仅约束了执行环节，规划过程仍受损失性语义干扰。GCA 提出通过形式化任务约束将 VLM 角色解耦为语义分析师与受限求解器，在无需微调的前提下桥接这一鸿沟。该范式在多个基准上刷新了 SOTA，但其性能上限受制于 VLM 形式化生成的准确率，且未解决几何工具本身的精度瓶颈。

## 研究背景

当 VLM 处理“坐在沙发上时餐桌在哪”这类查询时，它首先将视觉输入转化为文本语义，这一过程丢失了精细的几何细节，即语义-几何鸿沟。为弥合此差距，模型需建立参考系（Reference Frame）以锚定空间坐标，并明确目标约束（Objective Constraint）以定义测量对象。然而，VLM 常默认使用相机视角而非物体视角，导致参考系建立错误，进而引发后续几何计算的全面失效。

空间推理的主流解决路线分为两类：一是端到端训练，通过大规模数据微调嵌入几何先验，但数据生成依赖 GPT-4o 等本身存在空间缺陷的预言机，导致模型学习错误的空间逻辑；二是工具集成，将几何计算外包给确定性工具，但 VLM 的规划过程仍在其损失性语义空间中进行，容易产生几何错误的计划。GCA 的切入点在于识别出规划过程的未约束性是核心失效点，主张利用 VLM 在定性语义推理上的优势，先生成不可变的形式化约束，再在约束下执行计算。

## 核心方法

### 方法参照系

GCA 基于 ReAct 框架，但关键差异在于引入了中间的形式化任务约束 $C_{task}$。标准 ReAct 中，智能体直接根据查询生成工具调用序列，规划与执行耦合；GCA 将这一过程拆分为两个独立阶段，强制 VLM 在调用任何工具前，先输出一个机器可解析的几何约束定义，从而将“解决什么”与“如何求解”在架构上分离。

### 任务形式化与参考系锚定

该阶段解决了 VLM 在规划时默认采用错误视角（如相机视角而非物体视角）的失效问题。VLM 作为语义分析师，将模糊查询转化为 $C_{task} = (C_R, C_O)$，其中 $C_R$ 为参考系约束，$C_O$ 为目标约束。参考系被定义为三维笛卡尔坐标系，其原点 $O_R$ 和正交基向量 $(\mathbf{x}_R, \mathbf{y}_R, \mathbf{z}_R)$ 必须锚定到场景中的几何原语。

$$
\mathbf{z}_R = \text{normalize}(\text{Centroid}(o_{target}) - \text{Centroid}(o_{ref}))
$$

此公式定义了基于方向的参考系，例如“烤箱在洗手池北边”时，$\mathbf{z}_R$ 由两物体质心向量归一化确定。通过强制 VLM 显式输出这种几何定义，GCA 防止了模型在后续步骤中因视角歧义而陷入错误的空间想象，确保了计算起点的几何正确性。

### 受限几何计算与知识增强代码生成

该阶段解决了工具执行中公式幻觉的问题。VLM 作为受限求解器，在 $C_{task}$ 的约束下迭代调用工具获取几何数据，并生成 Python 代码进行最终计算。为防止代码生成器凭记忆猜测错误的几何公式，GCA 采用知识增强策略，类似于静态检索增强生成（RAG）。

$$
\text{Code} = \text{Gen}(\text{Req}, \text{Vars}, \text{Lib}(\text{Types}(\text{Vars})))
$$

其中 $\text{Lib}(\text{Types}(\text{Vars}))$ 表示根据绑定变量的数据类型，从预置的、经过验证的几何公式库中自动检索并注入相关公式。这一机制确保了计算步骤是基于形式化任务和可靠几何原理的确定性推导，而非黑盒猜测，从而在保持 VLM 灵活性的同时，保证了几何计算的数学严谨性。

## 实验评估

GCA 在 MMSI-Bench、MindCube-tiny、OmniSpatial、SPBench 和 CV-Bench 上进行了评估，对比了基础 VLM、训练式方法（如 SpatialLadder）和工具智能体（如 TIGeR）。基线覆盖了当前主要技术路线，但缺少与纯几何接地方法（如 GeoWeaver）的直接对比，这可能影响对 GCA 相对于显式几何注入方法优势的全面评估。

| 方法 | MMSI-Bench | MindCube-tiny | OmniSpatial | SPBench | CV-Bench | Avg. |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Gemini-2.5-Pro | 31.8 | 47.3 | 58.6 | 50.0 | 80.7 | 53.7 |
| SpatialLadder | 22.7 | 33.0 | 49.5 | 70.3 | 64.5 | 48.0 |
| TIGeR | 27.8 | 28.3 | 49.8 | 46.3 | 84.5 | 47.3 |
| **GCA** | **47.6** | **64.2** | **65.1** | **61.8** | **86.9** | **64.8** |

GCA 的平均准确率为 64.8%，比最强基础 VLM Gemini-2.5-Pro 高 12%，比 SpatialLadder 高 27%，比 TIGeR 高 38%。在最具挑战性的 MMSI-Bench 上，GCA 达到 47.6%，显著优于其他方法，验证了形式化约束在复杂多视角推理中的有效性。

| 配置 | MMSI-Bench |
| :--- | :--- |
| Baseline (CoT-Only) | 32.6 |
| + Tool Integration | 36.8 |
| + KACG | 38.7 |
| + Feedback | 40.1 |
| + $C_{task}$ | **47.6** |

消融实验显示，工具集成、知识增强代码生成（KACG）和反馈机制累计带来 7.5 点的提升，而引入 $C_{task}$ 额外带来 7.5 点的提升。这表明形式化约束的贡献与工具链本身相当，证实了约束规划过程是解决语义-几何鸿沟的关键。然而，GCA 与人工标注的 Oracle 形式化（49.5%）之间仍有 1.9 点的差距，说明 VLM 的形式化生成准确率（约 70%）仍是性能上限的主要限制因素。

评估协议主要基于图像输入，未涵盖视频或动态场景，限制了其在具身智能应用中的泛化验证。论文未报告计算效率指标，且依赖外部工具（如 VGGT 进行 3D 重建），其实际部署中的延迟和成本未予量化。代码已开源，但工具链的复杂配置可能增加复现难度。

## 关联研究分析

从问题动机看，GCA 与 GeoWeaver 等显式几何接地方法存在根本差异。GeoWeaver 通过引入深度图或点云作为输入，直接增强 VLM 的几何感知能力，属于“输入侧”增强；而 GCA 不修改模型输入或架构，而是通过“过程侧”约束，利用 VLM 现有的语义能力生成几何约束。这种差异源于对 VLM 缺陷的不同诊断：GeoWeaver 认为 VLM 缺乏几何信息，GCA 认为 VLM 缺乏几何推理的约束机制。GCA 的优势在于无需高质量几何数据，避免了“预言机悖论”，但其性能依赖于 VLM 语义理解的准确性，若 VLM 无法正确识别参考系原语，约束生成将失败。

从方法设计看，GCA 与 TIGeR 同属工具集成路线，但 GCA 引入了形式化中间层。TIGeR 采用迭代规划-执行策略，VLM 直接决定下一步工具调用，规划过程不受约束；GCA 则强制 VLM 先输出 $C_{task}$，将规划过程转化为确定性的约束生成任务。这一设计解决了 TIGeR 中 VLM 在损失性语义空间中规划导致的几何错误问题。然而，GCA 的形式化生成阶段本身是一个新的瓶颈，其准确率受限于 VLM 的语义解析能力，而 TIGeR 的端到端规划虽易出错，但无需额外的形式化步骤，在简单任务上可能具有更高的效率。

## 总结

GCA 旨在解决 VLM 空间推理中语义空间与几何空间解耦导致的规划失效问题。现有训练式方法受限于数据质量，工具集成方法未约束规划过程，GCA 通过引入形式化任务约束 $C_{task}$，将 VLM 角色解耦为语义分析师和受限求解器，利用其语义优势生成几何约束，再在约束下执行确定性计算。实验表明，GCA 在多个基准上取得 SOTA，平均准确率 64.8%，比最强基线高 12%。其边界在于形式化生成阶段的准确率（约 70%）限制了性能上限，且依赖外部工具链，未解决工具本身的精度问题。当 VLM 的语义理解能力进一步提升时，$C_{task}$ 的生成准确率能否突破当前瓶颈，从而释放 GCA 范式的全部潜力，是后续研究需验证的关键问题。
