# AAAI2026最新论文 ｜LexChronos: An Agentic Framework for Structured Event Timeline Extraction in Indian Jurisprudence ｜印度司法事件时间线抽取框架

作者：Anka Chandrahas Tummepalli、Preethu Rose Anish

论文原文见 [arXiv](https://arxiv.org/abs/2603.01651)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.01651)

> 法律判决预测长期受限于非结构化文本中关键事实与法律逻辑的细粒度对齐缺失，导致模型难以捕捉案件的时间因果链条。现有通用大语言模型（LLM）在处理长文档时往往将判决视为整体文本块，忽略了事件间的共指与层级依赖，且印度法域缺乏公开的事件级标注基准。本文提出 LexChronos，一种基于双智能体迭代反馈的结构化事件时间线抽取框架，并构建了首个印度最高法院合成数据集。该工作填补了特定法域的数据空白，但其在合成数据上的高准确率能否迁移至真实司法场景，仍存疑。

## 研究背景

**预备知识**
法律推理依赖于对案件事实、法律适用及量刑结果之间逻辑关系的精确解析。当面对长达数万字的判决书时，传统自然语言处理技术难以直接捕捉跨段落的事件共指关系与时间因果链，这一现象被称为长文档依赖稀释。为了解决这一问题，事件抽取（Event Extraction）技术旨在从非结构化文本中识别并结构化关键事实、行为者及时间关系。然而，在法律领域，事件不仅包含时间戳，还紧密关联法官身份、引用先例及法律论证，这要求抽取模型具备比通用领域更复杂的语义约束能力。

**研究脉络**
法律判决预测（LJP）的主流路线正从判别式分类转向生成式推理，以应对黑盒模型缺乏可解释性的问题。然而，无论是基于 BERT 的判别式模型，还是基于 RAG 的生成式框架，大多将输入文本视为静态整体，未能显式建模判决内部的事件时序结构。这种结构缺失导致模型在复杂案件推理中容易忽略关键程序性事件，且难以支持先例映射等下游任务。针对印度最高法院判决这一低资源场景，现有工作如 AALAP 虽提升了摘要与问答性能，但缺乏针对事件级细粒度标注的公开数据集，导致基准测试与复现困难。本文切入点在于构建一个专门针对印度司法语境的事件抽取框架，通过结构化中间表示增强法律推理的透明度。

## 核心方法

### 双智能体迭代架构

本文方法参照系为基于 LLM 的指令微调抽取流程，其关键差异在于引入了置信度驱动的反馈闭环，而非单次生成。标准流程通常由单一模型直接输出结构化结果，但本文认为单次生成难以保证法律文本中时间线与事实的严格一致性。

### 置信度驱动停止准则

**设计动机**：解决 LLM 在迭代生成中可能出现的过度修正或收敛停滞问题，平衡计算成本与抽取精度。
提取智能体（Extraction Agent）基于 LoRA 微调的 Llama 3.2 3B Instruct 生成候选事件集 $E_0$。反馈智能体（Feedback Agent）基于预训练的 Gemma 2 2B IT 对 $E_0$ 进行七维评分，包括叙事相关性、时间准确性等。迭代过程遵循以下更新规则：

$$ E_{i+1} = \text{FeedbackAgent}(J, E_i, F_i) $$

其中 $J$ 为判决文本，$F_i$ 为反馈评分。系统设定两个停止条件：耐心限制（Patience Limit）与容差阈值（Tolerance Threshold）。当置信度分数连续 3 次未超过历史最佳分数 $S_{best}$，或连续 3 次保持不变时，迭代终止。该机制确保在精度边际收益递减时及时停止，避免无效计算。

### 法律事件模式（LES）

**设计动机**：解决通用事件抽取模式无法覆盖法律判决特有要素（如法官、先例）的问题。
本文定义了 LexChronos Event Schema (LES)，包含四个核心属性：时间戳（Timestamp）、事件描述（Event）、法官（Judge）及先例（Precedent）。该模式通过归纳分析印度最高法院判决结构得出，旨在将非结构化文本映射为机器可读的法律历史表示。LES 的构建确保了抽取结果不仅包含事实，还保留了法律权威来源与程序性节点，为下游的先例映射与论证生成提供结构化基础。

## 实验评估

**实验设置与主结果**
实验基于自建合成数据集，包含 2,000 份由 DeepSeek-R1 和 GPT-4 生成的印度最高法院判决，其中 1,600 份用于训练，400 份用于测试。基线对比涵盖 8 种开源 LLM，包括 Llama、Gemma、Qwen 等，但缺失了领域内经典的判别式基线（如 BERT 分类头）及检索增强基线。

| 模型 | BERT Precision | BERT Recall | BERT F1 |
| :--- | :--- | :--- | :--- |
| Llama 3.2 3B Instruct | 0.8450 | 0.8336 | 0.8390 |
| Gemma 2 2B IT | 0.7809 | 0.7957 | 0.7880 |
| Gemma 3 1B IT | 0.8237 | 0.7992 | 0.8113 |
| Llama 3.2 1B Instruct | 0.6058 | 0.6054 | 0.6052 |
| DeepSeek R1 Distill Qwen 1.5B | 0.5548 | 0.5135 | 0.5276 |
| Qwen 2.5 3B | 0.5628 | 0.4467 | 0.4752 |
| Phi 4 Mini Reasoning | 0.4802 | 0.2442 | 0.3048 |
| Qwen 3 4B | 0.4472 | 0.2506 | 0.3005 |

Llama 3.2 3B Instruct 在单独作为提取智能体时取得最高 F1 分数 0.8390，显著优于其他候选模型，表明其架构在结构化信息抽取上的优势。

**消融与设计决策验证**
引入反馈智能体后，抽取质量进一步提升。

| 反馈配置 | BERT Precision | BERT Recall | BERT F1 |
| :--- | :--- | :--- | :--- |
| Self Feedback | 0.8681 | 0.8371 | 0.8523 |
| Gemma 2 2B IT | 0.8918 | 0.8590 | 0.8751 |
| Gemma 3 1B IT | 0.8664 | 0.8348 | 0.8502 |
| Llama 3.2 3B Instruct | 0.8665 | 0.8351 | 0.8505 |
| Llama 3.2 1B Instruct | 0.8661 | 0.8344 | 0.8499 |

Gemma 2 2B IT 作为反馈智能体时，F1 分数达到 0.8751，较无反馈基线提升 0.0361。值得注意的是，Self Feedback（使用同一模型进行自我批评）的效果（0.8523）低于使用不同架构模型（Gemma 2 2B IT）的效果，暗示跨模型反馈可能提供更具多样性的错误检测视角。

**评估边界与可复现性**
下游摘要任务采用 GPT-4 作为裁判，通过成对比较评估结构化与非结构化输入的效果，GPT-4 在 75% 的案例中偏好结构化摘要。然而，评估完全依赖合成数据，缺乏真实判决的分布验证。代码与提示词已公开，但合成数据的生成过程（DeepSeek-R1 与 GPT-4 混合）可能引入生成模型特有的语言偏差，影响泛化性评估。

## 关联研究分析

从问题动机看，本文与 DLEE（Xian et al., 2024）同属法律文档级事件抽取，但 DLEE 针对中文法律文本，采用半自动标注管道，而本文针对印度法域，采用全合成数据生成。这一差异源于印度法律 NLP 资源极度匮乏，导致无法像中文领域那样依赖大规模真实语料进行半自动标注。本文的合成策略虽解决了数据缺失问题，但引入了“生成-抽取”的闭环偏差风险，即模型可能过度拟合生成模型的语言风格，而非真实司法逻辑。

从方法设计看，本文与 JurisMMA（Kang et al., 2026）均采用多智能体协作，但 JurisMMA 模拟法官与律师的对抗角色以预测判决结果，而本文模拟提取与反馈角色以优化信息抽取质量。JurisMMA 关注的是推理过程的逻辑一致性，而本文关注的是事实提取的结构化完整性。这种差异反映了法律 AI 中“推理”与“感知”两个子任务的不同需求：前者需要角色分工以模拟司法程序，后者需要迭代反馈以消除噪声。本文未探索将提取出的事件时间线直接用于判决预测，而是仅验证了摘要任务，这限制了其在 LJP 主任务中的直接应用价值。

## 总结

本文旨在解决印度最高法院判决中事件结构缺失导致的法律推理不透明问题，通过构建首个公开合成数据集与双智能体迭代框架，实现了从非结构化文本到结构化时间线的映射。实验表明，该框架在合成数据上取得了 0.8751 的 BERT F1 分数，且结构化表示显著提升了摘要质量。然而，其有效性局限于合成环境，缺乏真实司法数据的验证，且合成数据可能携带生成模型的语言偏差。当支持集从合成数据扩展至真实判决时，该框架的抽取精度是否会出现显著衰减，论文未给出回答。
