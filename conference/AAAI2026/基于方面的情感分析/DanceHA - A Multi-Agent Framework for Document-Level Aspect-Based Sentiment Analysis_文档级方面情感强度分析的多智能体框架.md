# AAAI2026最新论文 ｜DanceHA: A Multi-Agent Framework for Document-Level Aspect-Based Sentiment Analysis ｜文档级方面情感强度分析的多智能体框架

作者：Lei Wang、Min Huang、Eduard Dragut

论文原文见 [arXiv](https://arxiv.org/abs/2603.16546)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.16546)

> 文档级方面情感强度分析（ABSIA）旨在从长文本中解耦出针对特定属性的细粒度情感及其强度量化，其核心难点在于长上下文中的信息分散与非正式语言风格的干扰。现有句子级方法受限于局部窗口，无法捕捉跨句依赖，而直接应用大语言模型（LLM）则面临幻觉与结构不一致问题。本文提出 DanceHA 框架，通过“分治协作”策略将长文档分解为方面级思维组，由多个专家智能体并行处理，并引入人机协作标注机制构建新数据集。该框架在自建基准上显著优于少样本思维链基线，但其性能高度依赖骨干模型能力，且缺乏与标准句子级基准的横向对比，泛化性存疑。

## 研究背景

当用户评论从简短句子扩展为包含多段落的长文档时，方面术语（Aspect Term）与观点词（Opinion Word）之间的语义关联被跨句线索稀释。这种长距离依赖使得传统的序列标注或句子级生成模型失效，因为局部上下文不足以支撑完整的方面-观点绑定。为量化情感强度，研究引入了方面情感强度分析（ABSIA），要求模型不仅判断极性，还需输出 0-5 的强度分数。然而，非正式语言风格（如拉长词 "coool"）对强度的影响尚未在 ABSIA 中被系统性建模，导致现有模型在解析此类表达时强度预测偏差显著。

文档级 ABSIA 的核心瓶颈在于缺乏大规模、高质量的细粒度标注数据。现有数据集如 DOTSA 平均仅含 1.26 个四元组，且未涵盖强度维度，难以支撑长文本推理能力的训练与评估。主流路线中，端到端生成式方法虽能捕捉联合依赖，但在长文档中易产生未接地幻觉；而基于图神经网络的结构化方法计算复杂度随文档长度指数级增长。本文切入点在于利用多智能体框架的分工特性，将复杂的文档级推理拆解为可管理的子任务，同时通过人机协作解决数据稀缺问题，从而在开放域长文本中实现稳健的 ACOSI 五元组提取。

## 核心方法

### 方法参照系

文档级 ABSIA 可视为句子级方面情感四元组预测（ASQP）在长文本上的扩展，但关键差异在于需处理跨句上下文聚合与非正式风格对强度的调制。标准 ASQP 流程假设输入为单句，而本文需先解决长文档的语义分段问题，再执行细粒度提取。

### 分治协作机制

Dance 模块的核心创新在于将长文档 $d$ 分解为方面级思维组 $\{(a, g)\}$，其中 $a$ 为方面术语，$g$ 为包含该方面所有相关句子的子集。这一设计解决了长文档中方面线索分散导致的注意力稀释问题。Divider 智能体执行三步操作：分割含多方面句子的片段、合并同方面连续句子、提取显式方面术语。形式化表示为：

$$ \{(a_0, g_0), \dots, (a_n, g_n)\} = F_D(d) $$

该公式表明，文档被重构为以方面为中心的局部上下文单元，使得后续智能体仅需在短窗口内推理，降低了长距离依赖的建模难度。

### 专家智能体协同与强度量化

在 Conquer 阶段，三个专家智能体并行处理每个思维组。Category Assignment 智能体 $F_C$ 利用检索增强生成（RAG）工具从预定义类别列表中匹配类别 $c$；Opinion Extraction 智能体 $F_O$ 提取保留非正式风格的观点词 $\{o\}$；Sentiment Polarity & Intensity 智能体 $F_S$ 基于观点词输出极性 $s$ 与强度分数 $i$。强度量化公式为：

$$ (s, i) = F_S(a, g, o) $$

其中 $i \in [0, 5]$ 为 Likert 量表分数。该设计将强度预测与观点词的非正式特征（如拉长、标点）显式绑定，解决了传统模型忽略风格线索导致强度预测偏差的问题。最终通过规则合并输出结构化列表 $T = \{(g, a, c, o, s, i)\}$。

## 实验评估

实验在自建 Inf-ABSIA 数据集上进行，该数据集包含 2,714 篇长文档，平均 90 词，每篇含 8.48 个 ACOSI 五元组。基线覆盖零样本与 5 样本思维链（CoT）推理，使用 GPT-4o 作为骨干，但缺失 Span-ASTE、GAS 等经典判别式/生成式基线，也未对比其他多智能体框架如 TaCoMOE。

| 方法 | 骨干模型 | Rest F1 (%) | Hotel F1 (%) | Lap F1 (%) |
| :--- | :--- | :--- | :--- | :--- |
| fs-CoT | GPT-4o | 35.04 | 31.40 | 16.61 |
| Dance | GPT-4o | 47.80 | 44.18 | 29.97 |
| MA | DeepSeek-V3 | 63.18 | 59.07 | 47.40 |

Manager Agent（MA）在 Rest 域 F1 达 63.18%，较 Dance 的 47.80% 提升 15.38 个百分点，表明多团队集成与冲突消解机制显著提升了结构一致性。消融实验显示，移除分治策略（w/o D&C）导致平均 F1 下降 8.37%，移除团队协作（w/o Teamwork）下降 2.91%，证明任务分解是性能主要来源，而智能体间协作提供边际增益。

评估指标包含 F1、Accuracy 与 MAE，但缺乏置信区间报告，且未在标准句子级基准（如 Rest15）上验证泛化性。代码已开源，但超参数设置（如 LoRA rank 32）仅针对 Qwen3 系列优化，其他骨干模型的调参细节未披露。

## 关联研究分析

从问题动机看，本文与 E-ABSA20K 均关注长文本幻觉抑制，但 E-ABSA20K 采用两阶段“提议-验证”流程，依赖显式证据跨度接地，而 DanceHA 通过多智能体分工将验证内化于协作过程中。差异根源在于任务设定：E-ABSA20K 面向电商评论的固定结构提取，而 DanceHA 处理开放域非正式风格，后者更依赖语义推理而非规则匹配。这种设计选择是否牺牲了结构严谨性以换取风格适应性，论文未给出量化对比。

从方法设计看，DanceHA 与 TaCoMOE 同属多智能体/混合专家路线，但 TaCoMOE 侧重任务路由以隔离不同子任务的知识，而 DanceHA 侧重任务分解以缓解长文本信息过载。TaCoMOE 在 DiaASQ 对话任务中 F1 达 49.91%，而 DanceHA 在文档级任务中 MA 最高 F1 为 63.18%，两者基准不同无法直接比较。关键差异在于 DanceHA 引入了人机协作标注环节，这既是数据构建手段，也是推理链蒸馏的来源，而 TaCoMOE 完全依赖自动标注。这种人机混合范式在数据稀缺场景下的优势是否可迁移至其他长文本任务，仍需更多实证支持。

## 总结

本文核心矛盾在于长文档 ABSIA 中细粒度标注数据稀缺与 LLM 幻觉抑制的冲突。切入点在于利用多智能体分治策略将长文本推理局部化，并通过人机协作构建高质量数据集。DanceHA 框架通过 Divider 分解文档、专家智能体并行处理、Manager 集成冲突，在 Inf-ABSIA 上实现 MA F1 63.18%（Rest 域），较少样本 CoT 提升 28.14 个百分点。边界在于实验仅在自建基准上进行，缺乏与标准句子级方法的横向对比，且强度预测 MAE 仍较高（0.086），表明非正式风格解析仍有不足。当骨干模型从 GPT-4o 切换至 DeepSeek-V3 时性能提升显著，这暗示框架性能对 LLM 推理能力高度敏感，而非完全由多智能体架构决定。
