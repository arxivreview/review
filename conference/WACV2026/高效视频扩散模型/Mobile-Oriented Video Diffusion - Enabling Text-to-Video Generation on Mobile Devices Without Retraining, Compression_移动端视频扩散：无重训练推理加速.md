# WACV2026最新论文 ｜Mobile-Oriented Video Diffusion: Enabling Text-to-Video Generation on Mobile Devices Without Retraining, Compression, or Pruning ｜移动端视频扩散：无重训练推理加速

作者：Bosung Kim、Kyuhwan Lee、Isu Jeong 等 6 人

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_4031d2816edb)

> 移动端部署视频扩散模型面临算力、内存与延迟的三重硬约束，传统依赖蒸馏、量化或剪枝的方案需高昂的重训练成本且易损失质量。MOVD 切入点是利用预训练模型推理阶段的轨迹线性冗余与时间维 Token 相似性，在不修改架构、不重训练、不压缩模型的前提下实现端侧生成。其核心机制为线性比例跳跃（Linear Proportional Leap, LPL）与时间维 Token 合并（Temporal Dimension Token Merging, TDTM），辅以动态加载并发推理（Concurrent Inference with Dynamic Loading, CI-DL）。该工作验证了纯推理优化在 iPhone 15 Pro 上的可行性，但缺乏量化质量指标与强基线对比，其加速收益的普适性存疑。

## 研究背景

视频扩散模型在移动端部署时，首先受制于去噪过程的迭代耗时。以 Open-Sora 为例，其 STDiT 模块需执行 50 次去噪迭代，在 iPhone 15 Pro 上单次推理耗时即达 1768.320 秒，远超用户可接受延迟。其次，STDiT 的自注意力机制计算复杂度随 Token 数量呈二次方增长，对于 68 帧 256×256 视频，单步注意力计算已接近移动端 GPU 算力极限。最后，模型参数量巨大，T5 编码器（18.00 GB）、STDiT（4.50 GB）与 VAE（0.82 GB）累计内存需求达 23 GB，远超 iPhone 15 Pro 的 3.3 GB 可用内存上限。

高效视频生成领域的主流路线包括步数蒸馏、高效注意力与系统级优化。步数蒸馏如 DMD 通过分布匹配将多步压缩为少步，但需维护生成器、分数估计器与判别器，训练流程复杂；高效注意力如 SANA-Video 采用块线性注意力降低复杂度，但需重新训练或迁移预训练权重；系统级优化如 Inferix 引入序列并行，但依赖多 GPU 集群。这些方案均假设拥有充足的训练资源或高性能服务器，无法直接迁移至资源受限的移动端。MOVD 的切入点在于识别预训练模型推理过程中的固有冗余：Rectified Flow 轨迹在后半段趋于线性，且视频相邻帧在时间维上具有高度相似性，这两点均可在不修改模型参数的前提下利用。

## 核心方法

### 方法参照系

本文问题属于“无训练推理加速”范畴，与步数蒸馏和高效注意力有本质区别。标准步数蒸馏需训练学生模型匹配教师分布，高效注意力需修改架构并重新训练。MOVD 的关键差异在于：它不改变模型参数、不修改架构、不引入额外训练，仅通过修改推理调度策略与 Token 处理流程实现加速。

### 线性比例跳跃（LPL）

LPL 作用于去噪过程的步数调度环节。通常做法是执行完整的 K 步去噪，每步计算漂移向量 $v(P_k, t_k)$ 并更新潜变量。MOVD 观察到，当去噪进行到第 n 步时，后续轨迹趋于直线，此时可停止逐步去噪，直接按比例跳跃至终点。其核心公式为：

$$ z_K = z_n + v(P_{n+1}, t_{n+1}) \cdot t_{n+1} $$

该公式的物理含义是：假设第 n+1 步的漂移方向 $v(P_{n+1}, t_{n+1})$ 在剩余所有步骤中保持不变，则只需将该漂移向量乘以剩余时间步长 $t_{n+1}$，即可直接得到最终潜变量 $z_K$。这一设计解决了传统少步生成中因轨迹弯曲导致的模式崩溃问题，因为 LPL 仅在轨迹已趋于线性时触发跳跃，避免了在轨迹弯曲阶段强行跳跃的质量损失。

### 时间维 Token 合并（TDTM）

TDTM 作用于注意力层的 Token 处理环节。通常做法是对空间维 Token 进行合并，但论文指出空间维合并在视频生成中性能次优。MOVD 创新性地沿时间维合并相邻帧 Token，利用视频帧间相似性降低计算量。其合并公式为：

$$ \text{TDTM}_{\text{merge}}(T)[i] = \frac{1}{2}(T[:, i, :] + T[:, i+1, :]) $$

该公式的物理含义是：将时间维上相邻的两个帧 Token 取平均，生成一个合并 Token，使 Token 数量减半。由于自注意力复杂度为 $O(N^2)$，Token 减半可使自注意力计算量降至四分之一；交叉注意力复杂度为 $O(NM)$，Token 减半可使计算量降至二分之一。合并后，注意力输出通过复制操作还原至原始时间维尺寸。这一设计解决了空间维合并在视频生成中因破坏时序结构而导致的质量下降问题，因为时间维合并保留了帧内空间信息，仅压缩帧间冗余。

## 实验评估

实验在 iPhone 15 Pro（2.15 TFLOPS GPU，3.3 GB 可用内存）上进行，使用 Open-Sora 作为骨干，生成 68 帧 256×256 视频。评估数据集包括 VBench 的 800 个提示词、Pandas70M 的 1000 个提示词和 VidGen 的 1000 个提示词。基线仅为 Open-Sora 原版，未对比 DMD、SANA-Video、TeaCache 等主流加速方法，也未对比 MobileWan 等移动端专用模型。该论文实验数据不可得，未提供实验表格。

论文未报告 VBench 总分、FPS、Latency 或 Speedup 等量化指标，仅通过定性视频对比展示 MOVD 与 Open-Sora 的生成质量相似。例如，在“lemur”提示词下，MOVD 生成狐猴转头的动态视频，Open-Sora 生成静态但视觉相似的视频。这种定性评估无法量化加速比与质量损失的权衡，也无法证明 MOVD 在复杂场景下的稳定性。论文声称 MOVD 是首个无需重训练、压缩或剪枝的移动端视频扩散框架，但未提供与 SnapGen-V 等需重训练方法的量化对比，无法证明其效率优势。

评估协议存在明显局限：仅使用单一骨干（Open-Sora），未验证方法在 Pyramidal Flow、HunyuanVideo 等其他模型上的泛化性；未报告置信区间或多次运行均值，无法评估结果稳定性；未测试长视频（>68 帧）或高分辨率（>256×256）场景，无法验证 LPL 线性假设在高动态场景下的有效性。代码已开源，但超参数（如 LPL 触发阈值、TDTM 应用步数）未在正文中明确列出，可复现性受限。

## 关联研究分析

从问题动机看，MOVD 与 MobileWan 均面向移动端部署，但技术路线截然不同。MobileWan 侧重模型压缩，通过剪枝、量化和 LoRA 缩小模型规模，需重训练以恢复质量；MOVD 侧重推理优化，通过 LPL 和 TDTM 减少计算量，无需重训练。这一差异源于任务特性：MobileWan 假设模型规模是主要瓶颈，MOVD 假设推理延迟是主要瓶颈。MOVD 未探索模型压缩与推理优化的结合，其纯推理路径在模型规模极大时可能因内存限制而失效，论文未给出回答。

从方法设计看，MOVD 的 LPL 与 DMD 均旨在减少去噪步数，但机制不同。DMD 通过分布匹配训练学生模型，使其在少步内逼近教师分布；LPL 利用 Rectified Flow 轨迹的线性特性，在推理时动态跳跃。LPL 的优势是无需训练，劣势是依赖轨迹线性假设，该假设在高动态视频（如快速运动、场景切换）中可能失效。MOVD 未测试高动态场景，其 LPL 的适用边界不明。TDTM 与 SANA-Video 的块线性注意力均降低注意力复杂度，但 TDTM 是维度合并，SANA-Video 是架构替换。TDTM 无需修改架构，但可能损失时间维细节；SANA-Video 需重新训练，但能从根本上降低复杂度。MOVD 未对比两者在质量-效率权衡上的差异，其 TDTM 的长期影响未知。

## 总结

MOVD 要解决的核心矛盾是移动端视频扩散的算力、内存与延迟瓶颈，现有方法因依赖重训练或高性能硬件而无法直接迁移。MOVD 抓住的切入点是预训练模型推理过程中的轨迹线性冗余与时间维 Token 相似性，凭借无需修改模型参数、无需重训练、无需压缩模型的特性，在 iPhone 15 Pro 上实现了 Open-Sora 的端侧运行。其核心贡献是验证了纯推理优化在移动端视频扩散的可行性，但未提供量化质量指标与强基线对比，无法证明其加速收益的普适性。论文的边界在于：仅验证单一骨干（Open-Sora）、单一分辨率（256×256）、单一帧数（68 帧），未测试高动态场景、长视频或高分辨率，LPL 的线性假设与 TDTM 的时间维合并的适用边界不明。当视频内容包含快速运动或场景切换时，LPL 的轨迹线性假设是否失效，TDTM 的时间维合并是否导致时序细节损失，论文未给出回答。
