# WACV2026最新论文 ｜ObjectCore - Efficient Few-shot Logical Anomaly Detection using Object Representations ｜对象表示驱动的少样本逻辑异常检测

作者：Matic Fučka、Vitjan Zavrtanik、Danijel Skočaj

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_12b5e8478b58)

> 工业质检中，多部件产品的逻辑异常（如部件缺失、错位）与训练样本极度稀缺的少样本场景叠加，构成了当前视觉异常检测中最具挑战性的子任务。现有少样本方法依赖全局语义对齐或像素级特征记忆，无法捕捉对象间的组合关系，而全样本逻辑异常方法又因数据需求过高难以落地。ObjectCore 将图像组合信息建模为对象表示集合，通过微调开放世界检测器提取对象特征，并利用二分匹配在测试图像与支持图像的对象表示间建立对应关系，从而在极少样本下实现逻辑异常检测。该方法在 MVTec LOCO 和 CAD-SD 上刷新了少样本逻辑异常检测的 SOTA，但其推理速度受限于匹配算法，且在纯结构异常任务上未超越专用基线，提示对象级抽象对局部纹理异常的捕捉能力存在边界。

## 研究背景

当工业产品由多个独立部件组成时，异常不再局限于表面纹理的破损，而是表现为部件集合的错误组合，即逻辑异常。检测此类异常需要模型理解对象间的空间与语义关系，而非仅识别局部像素偏差。然而，真实缺陷样本的稀缺性使得模型无法通过大量标注数据学习这些复杂关系，这构成了少样本逻辑异常检测的核心困境：如何在仅有一至四张正常样本的条件下，建立对对象组合模式的鲁棒表征。

主流少样本异常检测方法分为 CLIP 系与 PatchCore 系。CLIP 系方法（如 WinCLIP、PromptAD）依赖文本提示引导全局语义匹配，虽具备跨域泛化能力，但缺乏对局部对象组合的细粒度建模；PatchCore 系方法（如 FastRecon）通过构建正常特征记忆库检测局部偏差，在结构异常上表现优异，但无法捕捉对象缺失或错位等全局组合违规。逻辑异常检测领域的组合基方法（如 SALAD、AnomalyMoE）虽尝试建模语义信息，但前者依赖大量训练样本，后者需为每个类别设计不同超参数，限制了实际部署的灵活性。ObjectCore 的切入点在于：将组合信息从类别级语义分割下沉至对象级表示，利用开放世界检测器自动提取对象特征，并通过二分匹配实现无需类别先验的组合一致性验证。

## 核心方法

### 方法参照系

本文问题可置于嵌入基异常检测框架下，其标准流程为：提取预训练特征 → 构建正常分布模型（记忆库/高斯拟合） → 计算测试样本偏离度。本文与该通用流程的关键差异在于：正常分布模型被解耦为结构记忆库（存储补丁特征）与逻辑记忆库（存储对象表示），且逻辑异常的检测机制从距离计算转变为对象间的二分匹配。

### 类无关对象检测与微调

传统逻辑异常方法依赖人工标注的部件分割图或类别特定的检测器，这在少样本场景下不可行。ObjectCore 采用 GroundingDINO 作为开放世界检测器，使用通用文本提示“part”从支持集中提取伪检测。由于伪检测不完备，直接用于训练会引入噪声，本文提出仅使用 GLIP 中的对比分类损失 $L_{cls}$ 进行微调，并刻意省略边界框回归损失 $L_{bbox}$。

$$ L_{cls} = \text{align}(\text{prompt\_emb}, \text{box\_emb}) $$

该公式的物理含义是：强制模型将单一文本提示“part”的嵌入与所有检测到的边界框嵌入对齐，从而学习一个通用的、不依赖具体类别的对象检测能力。省略 $L_{bbox}$ 的设计动机在于：该损失会惩罚模型预测伪检测中不存在的边界框，这与“尽可能检测所有对象”的目标冲突，导致模型倾向于保守检测，遗漏关键部件。

### 对象表示构建与二分匹配

对象表示 $o$ 的计算结合了补丁特征与掩码信息。首先，从 GroundingDINO 的 Swin 编码器前三层提取补丁特征 $f$，并应用 5×5 均值滤波以包含周围区域信息；随后，使用 SAM 生成精确的对象掩码 $m$。对象表示定义为掩码内补丁特征的均值：

$$ o = \frac{1}{M} \sum_{j \in m} f(j) $$

其中 $M$ 为掩码内像素总数。这一设计解决了此前方法使用类别级语义分割导致的信息损失问题：对象级表示保留了每个部件的局部外观细节，同时通过掩码聚合消除了背景噪声。在推理阶段，逻辑异常检测通过计算测试图像对象表示集合 $O_{test}$ 与支持集中最相似图像对象表示集合 $O_{sup}$ 之间的二分匹配代价来实现。匹配失败的代价直接映射为逻辑异常分数，从而精确定位缺失或错位的部件。

## 实验评估

实验在 MVTec LOCO、CAD-SD（逻辑异常）及 MVTec AD、VisA（结构异常）四个基准上进行，支持集大小 $k \in \{1, 2, 4\}$。基线覆盖 CLIP 系（WinCLIP、PromptAD）、嵌入系（PatchCore、FastRecon）及组合系（SALAD、AnomalyMoE），但未包含纯重建类方法。在逻辑异常任务上，ObjectCore 在 4-shot 设置下于 MVTec LOCO 取得 80.8% I-AUROC，超越 AnomalyMoE 5.7 个百分点；在 CAD-SD 上取得 96.5% I-AUROC，超越 SALAD 13.9 个百分点。在结构异常任务上，ObjectCore 在 VisA 上超越 PromptAD 2.2 个百分点，但在 MVTec AD 上略低于 PromptAD 0.5 个百分点，表明对象级建模对纯结构异常存在轻微负迁移。

消融实验揭示了关键设计决策的影响。移除逻辑记忆库导致 I-AUROC 下降 10.2 个百分点，移除结构记忆库下降 12.1 个百分点，证实双记忆库的互补性。省略微调导致 I-AUROC 下降 11.8 个百分点，验证了类无关检测器微调对对象检测完整性的关键作用。使用边界框替代掩码计算对象表示导致 I-AUROC 下降 4.1 个百分点，说明掩码对去除背景噪声的重要性。推理速度方面，ObjectCore 单样本推理耗时 215.3 ms，慢于 PatchCore（41.6 ms）和 PromptAD（26.7 ms），但快于 AnomalyMoE（452.3 ms），主要瓶颈在于二分匹配算法。

评估协议采用 I/P-AUROC 和 I/P-F1-Max 指标，重复 3 次取平均。代码已开源，超参数在所有类别和数据集上保持一致，无需类别特定调整。然而，论文未报告计算复杂度（GFLOPs）及不同 GPU 型号下的推理延迟，且未测试支持集大小超过 4-shot 的性能变化，限制了其在更大样本场景下的适用性评估。

## 关联研究分析

从问题动机看，ObjectCore 与 AnomalyMoE 均致力于解决少样本逻辑异常检测，但两者对组合信息的建模粒度存在根本差异。AnomalyMoE 依赖文本提示特征、补丁特征和全局统计的多分支记忆库，其组合信息隐含在特征空间中，需为每个类别调整超参数；ObjectCore 则显式将组合信息建模为对象表示集合，通过二分匹配直接验证对象对应关系，实现了跨类别统一超参数。这一差异的根源在于：AnomalyMoE 假设组合异常可通过特征距离间接捕捉，而 ObjectCore 认为组合异常本质上是对象对应关系的断裂，需显式建模。ObjectCore 在 CAD-SD 上 13.9 个百分点的优势表明，显式对象匹配比隐式特征距离更有效地捕捉了部件缺失与错位。

从方法设计看，ObjectCore 与 PatchCore 共享嵌入基框架，但检测机制从 KNN 距离计算转变为二分匹配。PatchCore 通过查找测试补丁在正常记忆库中的最近邻来检测结构异常，其假设是异常补丁远离正常分布；ObjectCore 的逻辑记忆库则存储对象表示，通过匹配测试对象与支持对象来检测组合异常，其假设是异常对象无法在支持集中找到对应。这一转变使得 ObjectCore 能够检测 PatchCore 无法捕捉的逻辑异常，但代价是推理速度下降 5 倍。此外，ObjectCore 使用 SAM 生成掩码以计算对象表示，而 PatchCore 直接使用补丁特征，这一差异源于对象级抽象需要精确的边界信息以隔离背景噪声，而补丁级检测对边界精度要求较低。

## 总结

ObjectCore 旨在解决少样本条件下逻辑异常检测中组合信息建模不足的问题。现有方法或因依赖全局语义对齐而缺乏细粒度组合感知，或因数据需求过高而无法落地，ObjectCore 通过对象级表示与二分匹配机制，在仅有一至四张样本的条件下实现了对对象组合违规的精确检测。该方法在 MVTec LOCO 4-shot 设置下取得 80.8% I-AUROC，在 CAD-SD 上取得 96.5% I-AUROC，显著超越现有 SOTA。然而，实验显示其在 MVTec AD 结构异常任务上略低于 PromptAD，且推理速度受限于二分匹配算法，表明对象级抽象在捕捉局部纹理异常时存在精度损失，且计算开销限制了实时部署。当支持集从 4-shot 增加至 8-shot 时，对象表示的匹配精度是否进一步提升，抑或受限于检测器伪标签噪声而趋于饱和，论文未给出回答。
