# WACV2026最新论文 ｜ObjectCore – Efficient Few-shot Logical Anomaly Detection using Object Representations ｜基于对象表示的少样本逻辑异常检测

研究机构：斯洛文尼亚卢布尔雅那大学

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_WACV_2026_63359307)

> 工业质检中，多部件产品的逻辑异常（如部件缺失或错位）无法通过局部纹理重建捕捉，且新品类往往仅有极少量正常样本可用。现有少样本方法依赖语义分割图或手工文本提示，缺乏对对象间细粒度交互的建模能力，且超参数难以跨类别复用。本文提出 ObjectCore，利用微调后的开放世界检测器提取对象级表示，通过双记忆库与二分匹配机制实现无类别先验的逻辑异常检测。该方法在 MVTec LOCO 和 CAD-SD 上刷新了少样本逻辑异常检测的 SOTA，但其性能高度依赖 GroundingDINO 的检测精度，且推理速度受限于匈牙利匹配算法。

## 研究背景

工业异常检测的核心困境在于正常样本充足而缺陷样本稀缺，标准设定下模型仅能访问无异常图像进行训练。逻辑异常（Logical Anomaly）特指违反对象间关系、数量或空间布局规则的异常，如部件缺失或位置错乱，其本质是组合结构（Composition）的违规，而非局部纹理的偏离。少样本异常检测（Few-Shot Anomaly Detection, FSAD）进一步将数据约束收紧至每类仅 1-4 张支持集图像，要求模型在极端数据稀缺下同时建模外观与组合信息。

主流逻辑异常检测方法分为局部-全局重建、全局分布建模与组合式建模三类。组合式方法（如 SALAD、ComAD）依赖预训练的语义分割图或手工设计的文本描述来建模对象关系，但在少样本场景下，分割图质量不稳定且文本提示需针对每个类别单独设计，导致方法难以泛化至新数据集。AnomalyMoE 虽引入了多分支记忆库，但其异常分数计算逻辑复杂且超参数不统一，限制了实际部署。ObjectCore 的切入点在于：放弃依赖外部分割图或文本描述，转而利用开放世界检测器直接提取对象级表示，将组合信息建模为对象特征的集合，从而在无需类别先验的情况下实现细粒度的逻辑异常检测。

## 核心方法

### 方法参照系

ObjectCore 属于基于嵌入（Embedding-based）的异常检测方法，其基础流程继承自 PatchCore：提取预训练特征、构建正常分布记忆库、通过最近邻搜索计算异常分数。关键差异在于，PatchCore 仅存储补丁（Patch）特征以检测结构异常，而 ObjectCore 需额外建模对象间的组合关系以检测逻辑异常，且支持集规模极小（1-4 张），无法通过统计拟合分布，必须依赖显式的对象匹配机制。

### 无类别先验的对象检测与表示提取

传统组合式方法依赖语义分割图，但少样本场景下分割模型泛化能力差。ObjectCore 采用 GroundingDINO 作为开放世界检测器，使用通用文本提示“part”从支持集中提取伪检测（Pseudo-detections）。由于伪检测不完整，直接微调会导致模型过拟合于已检测到的对象，因此本文采用对比分类损失 $L_{cls}$ 并移除边界框回归损失 $L_{bbox}$，鼓励模型学习通用的“part”嵌入，从而提升对未见对象的检测能力。

$$
o = \frac{1}{M} \sum_{j \in m} f_j
$$

其中 $o$ 为对象表示，$f_j$ 为对象掩码 $m$ 内第 $j$ 个位置的补丁特征，$M$ 为掩码内正像素总数。该公式通过掩码内特征均值聚合，将空间上分散的补丁特征压缩为单一的对象级向量，保留了对象的整体语义信息而丢弃了局部纹理细节，为后续的组合匹配提供了紧凑的表示。

### 双记忆库与二分匹配推理

结构异常与逻辑异常具有不同的空间特性：前者表现为局部像素偏离，后者表现为对象集合的缺失或错位。ObjectCore 构建两个独立记忆库：结构记忆库 $M_S$ 存储支持集的补丁特征，逻辑记忆库 $M_L$ 存储支持集的对象表示集合 $O_s$ 及其平均补丁特征索引。推理时，结构异常图 $A_S$ 通过补丁特征的余弦距离最近邻搜索计算；逻辑异常图 $A_L$ 则通过匈牙利算法（Hungarian Algorithm）在测试图像对象集合 $O_t$ 与支持图像对象集合 $O_s$ 之间进行二分匹配。

$$
d_C((o_t, m_t), (o_s, m_s)) = d_{cos}(o_t, o_s) + \gamma | |m_t| - |m_s| |
$$

该代价函数结合对象表示的余弦距离与掩码面积差异，确保匹配的对象不仅语义相似，且空间尺度一致。匹配失败的对象（即测试图中存在但支持图中缺失，或反之）被赋予高异常分数，从而精确定位逻辑异常区域。这种解耦设计避免了单一全局特征对局部细节的平滑效应，使模型能同时捕捉细微划痕与部件缺失。

## 实验评估

| 数据集 | 方法 | k=1 I-AUROC | k=2 I-AUROC | k=4 I-AUROC |
| :--- | :--- | :--- | :--- | :--- |
| MVTec LOCO | AnomalyMoE | 75.1 | 77.8 | 79.9 |
| MVTec LOCO | ObjectCore | 72.5 | 74.6 | 80.8 |
| CAD-SD | SALAD | 74.6 | 78.6 | 82.8 |
| CAD-SD | ObjectCore | 90.0 | 92.1 | 96.5 |

实验在 MVTec LOCO、CAD-SD、MVTec AD 和 VisA 上进行，覆盖逻辑与结构异常检测。基线包括 AnomalyMoE、SALAD、PatchCore 等，但缺少基于 DINOv2 等最新视觉基础模型的少样本逻辑异常对比。在 MVTec LOCO 上，ObjectCore 在 4-shot 设定下以 80.8% I-AUROC 超越 AnomalyMoE 的 79.9%；在 CAD-SD 上，其 96.5% I-AUROC 大幅领先 SALAD 的 82.8%，平均提升 14.3 个百分点。

| 消融组件 | I-AUROC 变化 (p.p.) | P-AUROC 变化 (p.p.) |
| :--- | :--- | :--- |
| 移除 GroundingDINO 微调 | -11.8 | -4.2 |
| 仅使用结构记忆库 | -12.1 | -10.2 |
| 仅使用逻辑记忆库 | -10.2 | -4.3 |
| Swin-B 替换为 Swin-T | -4.5 | -3.1 |

消融实验表明，GroundingDINO 微调是性能的关键，移除后 I-AUROC 下降 11.8 个百分点，证实了伪检测微调对提升对象检测覆盖率的重要性。双记忆库的移除均导致显著性能下降，其中仅使用结构记忆库时 I-AUROC 下降 12.1 个百分点，说明逻辑记忆库对捕捉组合异常不可或缺。骨干网络从 Swin-B 降级为 Swin-T 导致 4.5 个百分点的性能损失，表明对象检测精度对下游异常检测具有强依赖性。

评估协议采用 I/P-AUROC 和 F1-max 指标，支持集随机采样并重复 3 次。代码已开源，但论文未报告计算复杂度细节，仅提及推理速度受限于匈牙利匹配。CAD-SD 仅含图像级标注，像素级定位有效性未在该数据集上验证。

## 关联研究分析

从问题动机看，ObjectCore 与 AnomalyMoE 均针对少样本逻辑异常检测，但 AnomalyMoE 依赖文本提示特征与全局统计的组合，超参数需针对每个类别调整，而 ObjectCore 通过对象级表示实现了超参数跨类别统一。这一差异源于对“组合信息”建模粒度的不同：AnomalyMoE 将组合视为全局语义的偏离，而 ObjectCore 将其视为对象集合的结构匹配。ObjectCore 的优势在于无需手工设计文本提示，但其性能依赖于 GroundingDINO 的检测精度，当对象边界模糊或重叠时，掩码聚合可能引入噪声。

从方法设计看，ObjectCore 与 PatchCore 共享记忆库范式，但 PatchCore 仅处理结构异常，其最近邻搜索在逻辑异常场景下失效，因为部件缺失不会导致局部补丁特征偏离正常分布。ObjectCore 引入逻辑记忆库与二分匹配，将异常检测从“特征距离”扩展至“集合匹配”，解决了 PatchCore 无法捕捉全局组合违规的盲区。然而，这种解耦设计增加了推理复杂度，且对象检测器与异常检测器的训练是分离的，未实现端到端联合优化，可能导致特征表示与匹配目标之间的次优对齐。

## 总结

ObjectCore 旨在解决少样本条件下逻辑异常检测中组合信息建模不足的问题。现有方法依赖语义分割或文本提示，缺乏对对象间细粒度交互的捕捉，且超参数难以跨类别复用。ObjectCore 通过微调开放世界检测器提取对象表示，结合双记忆库与二分匹配机制，实现了无类别先验的逻辑异常检测。在 MVTec LOCO 和 CAD-SD 上，其 4-shot I-AUROC 分别达到 80.8% 和 96.5%，显著优于 AnomalyMoE 和 SALAD。然而，该方法高度依赖 GroundingDINO 的检测精度，移除微调后性能下降 11.8 个百分点，且推理速度受限于匈牙利匹配算法。当支持集规模增大至 5-shot 以上时，对象匹配机制的边际收益是否递减，论文未给出回答。
