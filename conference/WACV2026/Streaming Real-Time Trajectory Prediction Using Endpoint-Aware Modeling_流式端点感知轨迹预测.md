# WACV2026最新论文 ｜Streaming Real-Time Trajectory Prediction Using Endpoint-Aware Modeling ｜流式端点感知轨迹预测

作者：Alexander Prutsch、David Schinagl、Horst Possegger

论文原文见 [arXiv](https://arxiv.org/abs/2603.01864)

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.01864)

> 自动驾驶系统需在连续数据流中实时预测周边智能体未来轨迹，以支撑毫秒级决策。现有高精度模型依赖多阶段迭代精炼，导致推理延迟过高，无法适应真实场景的时序一致性要求。本文提出SEAM架构，利用上一帧预测终点作为空间锚点提取目标区域上下文，通过单次解码实现低延迟流式预测。该方法在Argoverse 2多智能体基准上刷新了流式预测SOTA，但其仅依赖几何端点先验，未显式建模长尾场景下的语义不确定性。

## 研究背景

轨迹预测的核心挑战在于平衡几何精度与计算延迟。在自动驾驶栈中，预测模块位于感知与规划之间，其推理时间直接叠加到传感器观测到控制动作的总延迟中。若模型采用多阶段精炼策略以提升精度，虽能捕捉长程依赖，但高昂的计算成本会导致传感器数据过时，反而降低决策可靠性。

当前主流路线分为两类：一是基于快照（Snapshot）的独立预测，如QCNet和SmartRefine，它们通过迭代解码逐步细化轨迹，在Argoverse 2等长时程基准上表现优异，但缺乏跨帧时序一致性；二是早期流式方法，如RealMotion，虽引入上下文流和轨迹中继机制，但未充分利用历史预测中的空间信息，导致上下文提取效率低下。本文切入点在于识别出“预测终点”这一被忽略的强先验：在连续驾驶中，上一帧预测的终点区域往往包含当前帧决策所需的关键交互元素（如即将穿越的行人），利用该信息可直接引导场景编码器聚焦高相关区域，从而替代耗时的迭代精炼过程。

## 核心方法

### 方法参照系

标准轨迹预测流程通常包含场景编码、多模态解码及可选的迭代精炼阶段。QCNet等基线采用两阶段解码，先预测粗略轨迹，再将其作为先验进行交叉注意力精炼。本文问题与该通用流程的关键差异在于：摒弃迭代精炼，转而利用时间维度上的预测连续性，将上一帧的输出转化为当前帧的输入约束，实现单次解码的高精度预测。

### 目标中心上下文编码

传统场景编码以焦点智能体当前位置为中心，隐含假设未来运动仅受当前邻域影响。然而，在长时程预测中，智能体未来的交互对象往往位于当前视野边缘或预测路径终点附近。SEAM引入目标中心编码（Target-Centric Encoding），利用上一帧预测的 $K$ 个终点作为锚点，提取半径 $r$ 内的场景元素。设上一帧预测轨迹为 $F_{t-1} \in \mathbb{R}^{K \times T_f \times 2}$，其终点坐标定义为 $E_{t-1} = F_{t-1}[:, -1, :]$。以 $E_{t-1}$ 为原点构建局部坐标系，提取该区域内的场景令牌 $C_T^{[t]}$，并通过浅层编码器 $f_T$ 生成目标特征 $T^{[t]} = f_T(C_T^{[t]})$。这一设计解决了传统编码在长距离交互场景中因视野限制而丢失关键上下文的问题，使模型无需迭代即可感知未来路径上的潜在冲突。

### 双上下文解码器

仅依赖目标中心特征可能导致对当前动态状态的感知不足。SEAM设计双上下文解码器，同时融合智能体中心特征 $S^{[t]}$（基于当前位置编码）和目标中心特征 $T^{[t]}$。解码过程执行单次交叉注意力，查询向量 $Q$ 同时关注 $S^{[t]}$ 和 $T^{[t]}$ 的键值对。公式表示为：

$$
(F^{[t]}, P^{[t]}) = f_D(S^{[t]}, T^{[t]})
$$

其中 $f_D$ 为单步解码器，$P^{[t]}$ 为多模态概率评分。该机制的设计动机在于，智能体中心特征提供即时运动状态，而目标中心特征提供未来意图区域的空间约束，二者互补使得单次解码即可达到迭代精炼的效果。相比RealMotion的轨迹中继（仅传递轨迹偏移），SEAM直接传递空间区域信息，增强了上下文的相关性。

## 实验评估

实验在Argoverse 2（AV2）单智能体和多智能体基准上进行，历史输入为3秒，预测6秒未来。基线覆盖QCNet、SmartRefine、RealMotion、DeMo等主流快照与流式方法，但缺乏扩散模型（如MID）或LLM增强类基线的对比。

| 方法 | 流式 | minADE6 (m) | minFDE6 (m) | brier-minFDE6 |
| :--- | :---: | :---: | :---: | :---: |
| QCNet | ✗ | 0.71 | 1.39 | 1.91 |
| SmartRefine | ✗ | 0.67 | 1.29 | 1.86 |
| RealMotion | ✓ | 0.73 | 1.37 | 1.93 |
| DeMo | ✓ | 0.66 | 1.24 | 1.84 |
| **SEAM** | **✓** | **0.66** | **1.24** | **1.84** |

SEAM在单智能体任务中，brier-minFDE6与DeMo持平，但minADE6略优。在多智能体任务中，SEAM的avgBrierMinFDE6为1.85，优于RealMotion（2.24）和DeMo（1.93），接近快照SOTA QCNeXt（1.79）。延迟分析显示，SEAM在线延迟仅为28ms（B=1），远低于QCNet的118ms和SmartRefine的>118ms，验证了单次解码的效率优势。

消融实验表明，端点感知建模（EAM）比RealMotion的上下文流（CS）和轨迹中继（TR）带来更大的性能提升。在AV2验证集上，结合EAM、CS和TR的方法取得最佳结果（mADE6 0.59）。目标半径 $r$ 的敏感性分析显示，性能在30米时饱和，10米时仍有效，说明端点先验本身具有强引导作用，无需过大搜索范围。

评估边界方面，论文仅报告AV2和AV1结果，未涉及WOMD或nuScenes，限制了泛化性验证。指标以几何误差为主，缺乏对闭环规划性能的评估。代码未公开，但提供了详细的超参数和GPU配置（NVIDIA V100），可复现性中等。

## 关联研究分析

从方法设计看，SEAM与QCNet的核心差异在于上下文获取策略。QCNet依赖迭代精炼，通过多次解码逐步扩大有效视野，适合离线高精度场景；SEAM则利用时间连续性，将上一帧的预测终点作为当前帧的空间先验，实现了“以时间换空间”的效率优化。这种差异源于任务特性：流式场景下，上一帧预测的可靠性较高，其终点区域与当前帧的决策高度相关，因此无需迭代即可捕捉关键上下文。然而，SEAM未显式建模多模态分布的不确定性，仅输出概率评分，这可能限制了其在长尾场景下的鲁棒性。

从问题动机看，SEAM与RealMotion同属流式预测路线，但RealMotion侧重于轨迹中继（传递轨迹偏移），而SEAM侧重于端点感知（传递空间区域）。RealMotion的轨迹中继假设未来运动是过去运动的平滑延续，但在复杂交互中，智能体可能突然改变意图，导致轨迹偏移失效。SEAM通过端点锚定，直接关注未来交互区域，对意图变化更具鲁棒性。但SEAM未探索语义信息（如车道功能、交通标志）在端点选择中的作用，其端点仅基于几何位置，可能在语义复杂场景中产生误导。

## 总结

SEAM旨在解决流式轨迹预测中精度与延迟的矛盾，通过利用上一帧预测终点作为空间先验，替代耗时的迭代精炼。该方法在AV2多智能体基准上以28ms延迟实现了1.85的avgBrierMinFDE6，证明了单次解码在连续场景中的可行性。其边界在于仅依赖几何端点，未整合语义信息或显式分布建模，且在非AV2数据集上的泛化性未验证。当智能体意图发生剧烈变化时，上一帧预测终点是否仍能准确指示当前帧的关键交互区域，论文未给出回答。
