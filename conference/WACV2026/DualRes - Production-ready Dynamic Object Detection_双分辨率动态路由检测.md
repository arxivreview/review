# WACV2026最新论文 ｜DualRes: Production-ready Dynamic Object Detection ｜双分辨率动态路由检测

作者：Jibril El Hassani、Thomas Verelst

分析报告见 [ArxivReview](https://www.arxivreview.com/papers/conf_f536c5e86cbe)

> 静态目标检测器对所有输入执行相同计算量，导致简单场景下的算力冗余。现有动态网络方法多聚焦于图像分类，且难以适配生产级部署管线，导致理论与实际效率存在差距。本文提出基于图像复杂度的双分辨率路由机制，通过轻量级路由器在高低分辨率间切换，实现推理加速。该方法在7-10 GFLOPs区间建立了新的帕累托前沿，但其精度上限受限于低分辨率对小目标的丢失，且路由策略的通用性在复杂场景下存疑。

## 研究背景

边缘设备算力受限与复杂场景感知需求之间存在结构性矛盾。当检测器面对新生成模型时，其训练域与测试域的数据分布出现系统性差异——这一现象称为分布偏移。分布偏移导致传统分类器决策边界失效，而实际场景中往往能获取少量目标域样本，这恰好构成了小样本学习的条件：仅凭每个类别极少量标注样本泛化到新任务。解决此类问题的经典框架是原型网络，它计算各类别支持样本的特征均值作为"原型"，再通过距离度量完成分类。

实时目标检测的核心张力源于静态计算模式导致的算力浪费。46%的ImageNet样本可被归类为低难度，表明自适应处理策略具有优化潜力。动态神经网络（DNNs）通过调整计算复杂度来应对这一挑战，但现有研究主要集中在图像分类任务，大多数动态方法因架构限制无法直接应用于目标检测。此外，动态方法在生产部署管线中的额外复杂性阻碍了其广泛应用，形成了“理论效率”与“实际效率”之间的鸿沟。

本文切入点在于解决动态方法在目标检测中的部署难题与评估缺失。传统早期退出方法在目标检测中需添加多个检测头，增加了参数与部署难度。本文提出一种简单有效的方法：根据图像复杂度动态调整处理分辨率。通过预编译两种分辨率下的同一网络并共享权重，保持内存消耗不变。同时，引入AUC-Policy指标以解耦架构性能与路由策略质量，并构建ONNX部署管线以验证生产环境下的加速效果。

## 核心方法

### 动态分辨率路由参照系

动态分辨率处理旨在通过降低简单图像的处理分辨率来减少计算量。标准做法是设计一个路由器，根据输入特征决定下采样比例。本文问题与该通用流程的关键差异在于：需在不重新训练下游检测器的前提下，实现路由策略的端到端可训练性与生产级部署兼容性。

### 双分辨率路由机制

设计动机：解决离散路由决策不可微分导致的训练停滞问题，以及高难度样本占比过高导致的策略失衡。通常做法是使用硬阈值进行路由，但梯度无法回传。本文引入Gumbel-Softmax技巧进行重参数化，使路由器输出可微。定义双分辨率路由器 $R_\alpha: X \rightarrow \{0, 1\}$，其中 $\alpha \in [0, 1]$ 为目标高分辨率样本比例。下采样操作定义为：

$$
D_\alpha(x) = \begin{cases} x & \text{if } R_\alpha(x) = 1 \\ D_{sample}(x) & \text{otherwise} \end{cases}
$$

其中 $D_{sample}$ 为双线性插值下采样。推理时，样本 $x_i$ 的处理为 $\hat{y}_i = M(D_\alpha(x_i))$，$M$ 为下游检测模型。训练时，使用Gumbel噪声 $g_1, g_2$ 调节路由概率，并通过温度超参数 $\tau$ 平衡梯度流动与硬决策近似。

### 策略质量评估与训练优化

设计动机：标准精度-计算量权衡指标混淆了架构改进与路由优化贡献，且高难度样本主导损失导致路由器偏向高分辨率。本文提出AUC-Policy指标，量化路由策略相对于随机选择的有效性。定义指标函数 $Metric: \hat{Y} \times Y \rightarrow [0, 1]$，动态模型 $M_\beta$ 通过参数 $\beta$ 权衡精度与计算量。AUC-Policy定义为：

$$
AUC\text{-}Policy = \frac{\int_0^1 (Metric(\beta) - Metric(0)) d\beta}{Metric(1) - Metric(0)}
$$

该公式计算精度-计算量曲线下的归一化面积，反映策略在所有阈值下的整体质量。为平衡路由比例，损失函数增加正则项：

$$
L_{dynamic} = L_{YOLO} + \gamma \cdot (p - \theta)^2
$$

其中 $p$ 为当前批次高分辨率样本比例，$\theta$ 为目标比例，$\gamma$ 为权重。训练时冻结下游检测器，仅优化路由器权重，加速收敛并避免共优化不稳定。

## 实验评估

实验在COCO 2017、OpenLogo及车牌检测数据集上进行。基线覆盖EfficientDet、YOLOv6及Elastic-DETR等动态方法，但缺失DEIMv2、YOLO26等最新静态SOTA，限制了绝对精度的横向对比。

| 方法 | AUC-Policy (COCO) | 备注 |
| :--- | :--- | :--- |
| DualRes YOLOv6 (ours) | 0.700 | 本文方法 |
| DualRes EfficientDet (ours) | 0.636 | 本文方法 |
| Elastic DETR | 0.616 | 对比动态方法 |
| Dy-YOLOv7 | 0.614 | 对比动态方法 |

DualRes YOLOv6的AUC-Policy为0.700，高于Elastic-DETR的0.616，表明其路由策略在精度-计算量权衡上更优。在车牌检测任务中，AUC-Policy达到0.894，显著高于COCO的0.700，说明在物体形状规则、类别简单的场景中，分辨率路由的收益更大。

消融实验显示，类别数量增加导致策略效率下降。OpenLogo数据集（352类）的AUC-Policy为0.641，低于COCO（80类）的0.700，表明路由器在复杂形状与颜色变化下难以泛化。部署评估中，ONNX运行时相比PyTorch eager模式，在100%高分辨率下推理时间从179ms降至161ms，50%时从131ms降至109ms，0%时从73ms降至56ms。对比VGG-SDN，其6个嵌套早期退出阶段在ONNX中仅比静态模型快1.7倍，而本文方法因使用单一torch.cond操作，部署开销更低，更适合生产环境。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码未公开，但YOLO/EfficientDet有官方开源，可复现基线。AUC-Policy指标需至少三个精度-计算量数据点，限制了其在数据点较少方法上的应用。

## 关联研究分析

从问题动机看，本文与Elastic-DETR同属动态分辨率路由，但本文强调生产部署兼容性。Elastic-DETR使用基于注意力的分辨率预测器，而本文采用MobileNetV3骨干的二分类路由器。差异根源在于任务特性：Elastic-DETR面向Transformer检测器，其全局注意力机制对分辨率变化敏感，需复杂预测器；本文面向CNN检测器，局部归纳偏置使其对分辨率变化更鲁棒，简单路由器即可有效。这种差异暗示，动态路由策略的设计需与骨干网络的感受野特性匹配，而非通用化。

从方法设计看，本文与YOLO-Master等MoE方法同属动态计算分配，但本文调整输入分辨率，而MoE调整网络内部计算路径。MoE方法通过路由专家网络实现实例级自适应，但路由开销大且训练不稳定。本文通过预编译两种分辨率网络，将动态性外置于输入端，避免了内部路由的复杂性。这种设计牺牲了对小目标的精细处理能力，换取了部署简洁性。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但本文方法在低分辨率下对小目标的丢失是固有局限。

## 总结

本文解决的核心矛盾是静态检测器的算力冗余与动态方法部署困难。切入点在于将动态性外置于输入分辨率，通过预编译共享权重网络实现内存不变，并利用Gumbel-Softmax解决离散路由训练问题。方法通过双分辨率路由与AUC-Policy指标，在7-10 GFLOPs区间建立新帕累托前沿，COCO上AUC-Policy达0.700。边界在于低分辨率导致小目标信息丢失，且路由策略在复杂类别场景下泛化能力下降。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
