# HuggingFace最新推荐论文 ｜MillBill: A Machining Agent with Geometric Feedback ｜基于几何反馈的 CNC 加工规划智能体

作者：Gennadii Savrasov、Artem Slavin、Soslan Kabisov 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2611.22565)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2611.22565)

> 导读：将 CAD 模型转化为可执行的 CNC 加工代码，需要同时具备工艺知识与精确的几何计算能力。现有基于大语言模型（Large Language Model, LLM）的方法要么仅生成高层工艺计划而缺乏几何验证，要么让模型直接生成底层 G-code 导致数值幻觉频发。MillBill 提出了一种解耦架构，将 LLM 限定为工艺决策者，由确定性几何算法负责路径生成与物理模拟。该架构通过引入材料去除模拟与表面偏差反馈，实现了从设计意图到制造执行的闭环验证。其核心价值在于证明了中等规模开源模型配合几何 Harness 即可超越前沿大模型的端到端生成能力，但其在多轴加工及复杂曲面路径优化上的适用性仍存疑。

## 研究背景

当计算机辅助制造（Computer-Aided Manufacturing, CAM）系统面对复杂的边界表示（Boundary Representation, B-Rep）零件时，其核心困境在于决策与执行的耦合。工艺规划涉及操作序列选择、刀具匹配及切削参数设定，这属于依赖经验的过程知识；而刀具路径生成、材料去除模拟及偏差测量则属于严格的三维几何计算。传统 CAM 软件依赖人工专家介入，自动化程度低。若将这两类任务全部交给 LLM，模型需直接计算坐标、偏移量及扫掠体积，任何微小的数值错误都会导致加工出废品或损坏机床。

现有研究试图通过 LLM 自动化这一流程，但陷入了两难境地。一类方法如 CAPP-GPT 和 Design-to-Plan，利用 LLM 生成操作序列和参数，但止步于工艺计划，未生成可执行的刀具路径，导致计划无法在几何上被验证。另一类方法如 GLLM 或 CNCGEN，让模型直接生成 G-code 或参数化路径，但这要求模型具备极高的数值精度，且 CNCGEN 依赖大规模专用训练数据，泛化性受限。前沿模型虽能编写并运行几何代码，但将数值计算任务强加于语言模型，不仅计算成本高，且难以保证物理可行性。MillBill 的切入点在于明确区分“过程知识”与“几何执行”，让 LLM 仅负责高层决策，由几何 Harness 负责底层执行与验证，从而释放了模型对数值精度的依赖。

## 核心方法

### 方法参照系：解耦式加工规划流程

在标准的 CAM 自动化流程中，输入通常为 B-Rep 模型、毛坯及材料属性，输出为 G-code 程序。通用流程包括特征识别、Setup 规划、工艺决策、路径生成及模拟验证。MillBill 与该通用流程的关键差异在于执行层的解耦：LLM 不直接参与几何计算，而是通过调用 Harness 提供的工具接口，在受限的参数空间内进行决策。Harness 负责将高层计划转化为具体的几何操作，并将模拟结果反馈给 LLM 进行迭代修正。

### 基于可达性分析的 Setup 规划

传统 Setup 规划常基于可见性（Visibility）判断，即只要从某方向能看到表面区域即视为可加工。然而，可见性忽略了刀具夹持器（Holder）的物理干涉，导致深窄区域虽可见却不可达。MillBill 引入了考虑夹持器过悬（Overhang）的可达性测试。对于方向 $d$ 上的可见体素 $(x,y,z)$，若存在刀具 $t$ 满足以下条件，则判定为可达：

$$ \exists\,t\in\mathcal{T}:\quad\max_{\|(x^{\prime},y^{\prime})-(x,y)\|\leq\rho_{t}}H_{d}(x^{\prime},y^{\prime})\;-\;z\;\leq\;L_{t} $$

其中 $H_d$ 为高度图，$\rho_t$ 为夹持器半径与刀具半径之差，$L_t$ 为刀具可用长度。该公式通过灰度膨胀操作高效计算了夹持器干涉约束下的最大可达高度。这一设计解决了传统可见性方法忽略物理干涉导致的规划失效问题，确保了所选 Setup 在物理上可执行。Setup 选择采用贪心策略，优先选择能暴露最大新可达体积的方向，后续 Setup 基于前序 Setup 模拟后的剩余毛坯进行规划。

### 几何 Harness 驱动的闭环反馈机制

LLM 生成的工艺计划需经过几何 Harness 的执行与验证。Harness 包含 CAM 路径生成、材料去除模拟及偏差测量。在模拟阶段，MillBill 采用解析式扫掠体积测试而非离散化体素近似，以精确判断材料去除情况。对于刀具移动 $m$，点 $\mathbf{p}$ 被去除的条件为：

$$ \exists\,t\in[0,1]:\;\;d(t)\leq R\;\wedge\;p_{z}\geq c_{z}(t)+\eta\bigl(d(t)\bigr) $$

其中 $d(t)$ 为点到刀具轴线的平面距离，$\eta$ 为刀具轮廓函数。该公式通过解析几何精确计算了刀具扫掠体积，避免了离散化误差。模拟后，系统计算目标表面在公差 $\tau$ 内的面积比例 $\text{Acc}_{\tau}$，并将超出公差的区域（多余材料或过切）归因至具体特征和操作，反馈给 LLM。LLM 据此调整操作序列或参数（如增加精加工步骤），最多迭代三次。这一闭环机制弥补了纯语言模型缺乏物理约束的缺陷，使模型能够基于真实的几何偏差自我修正。

## 实验评估

实验在 GrabCAD 数据集的 100 个零件上进行，评估指标为模拟加工后目标表面在 0.1 mm 公差内的面积比例（$\text{Acc}_{\tau}$）。基线对比涵盖了基于前沿模型（GPT-6 Astra）的代码编写智能体。

| 方法 | 模型规模 | Acc_τ (%) | 备注 |
| :--- | :--- | :--- | :--- |
| MillBill (Qwen3.8-27B) | 27B (Open) | 97.4 | 含几何 Harness 反馈 |
| MillBill (No Model) | N/A | 97.0 | 仅 Harness 默认计划 |
| Code-writing Agent | Frontier | 94.3 | GPT-6 Astra |

MillBill 使用开源 Qwen3.8-27B 模型取得了 97.4% 的 $\text{Acc}_{\tau}$，优于基于前沿模型 GPT-6 Astra 的 94.3%。值得注意的是，即使移除 LLM 决策模块，仅使用 Harness 的默认标准实践计划，$\text{Acc}_{\tau}$ 仍达到 97.0%。这表明性能提升主要源于几何 Harness 的精确执行与验证，而非 LLM 的推理能力。LLM 的作用在于在 Harness 提供的受限空间内进行微调，其边际收益约为 0.4 个百分点。

评估边界方面，实验仅针对三轴立式加工中心，未涉及五轴联动或复杂曲面加工。此外，对比基线缺乏传统规则式 CAPP 系统或纯几何算法基线，难以量化 LLM 相对于传统自动化方法的增益。可复现性方面，代码已开源，但依赖 FreeCAD 及特定模拟环境，硬件需求为 4 张 H100 GPU。

## 关联研究分析

从问题动机看，MillBill 与 CNCGEN 均致力于从 B-Rep 到加工规划的自动化，但路线截然不同。CNCGEN 依赖大规模加工数据集训练端到端模型，直接输出操作和参数化路径，存在数据依赖重、泛化性差的问题。MillBill 采用零样本/少样本的 LLM+算法混合模式，利用预训练特征识别器（AAGNet）和物理模型，无需针对加工任务进行专门训练。这种差异源于对“知识来源”的不同假设：CNCGEN 假设知识可从数据中学习，MillBill 假设知识可从 LLM 和物理规则中获取。

从方法设计看，MillBill 与 Design-to-Plan 均使用 Agent 架构，但执行层存在本质差异。Design-to-Plan 输出 CAD 脚本，依赖 CAD 内核执行，缺乏物理制造约束的验证。MillBill 输出 G-code 并引入材料去除模拟，将反馈从“模型有效性”提升至“制造可行性”。这一差异反映了任务特性的不同：CAD 生成关注几何拓扑正确性，而 CAM 规划关注物理干涉与材料去除精度。MillBill 的几何 Harness 设计填补了 LLM 在物理世界交互中的验证空白。

## 总结

MillBill 针对 LLM 在 CNC 加工规划中数值幻觉与物理验证缺失的矛盾，提出了 LLM 决策与几何执行解耦的架构。通过引入考虑夹持器干涉的可达性分析和解析式材料去除模拟，该架构实现了从 B-Rep 到 G-code 的闭环验证。实验表明，配合几何 Harness 的开源 Qwen3.8-27B 模型在 $\text{Acc}_{\tau}$ 上达到 97.4%，超越了前沿模型的端到端生成能力。然而，该架构仅支持三轴加工，且 LLM 的边际贡献有限，其核心价值在于 Harness 的确定性执行。当加工任务扩展至五轴联动或涉及复杂自由曲面时，LLM 能否在更广阔的参数空间中提供有效的工艺优化，而非仅作为默认计划的微调器，仍有待验证。
