# HuggingFace最新推荐论文 ｜The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements ｜智能体进化中的评估分辨率瓶颈

研究机构：上海科技大学

作者：Yuanhao Zeng、Shaocheng Lan、Ao Lu 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2611.23068)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2611.23068)

> 智能体进化旨在通过迭代优化外部工件（如提示词、技能库）来提升冻结大语言模型（Large Language Model, LLM）的性能，但现有方法常陷入“增益不稳定”与“排名不可复现”的困境。传统评估范式假设单次运行分数能准确反映工件的真实质量，却忽视了评估噪声与运行间方差对微小改进的掩盖效应。本文提出“分辨率假设”，指出进化停滞的根源并非提议者无法生成有效工件，而是评估管线缺乏识别微小真实改进的统计分辨率。通过大规模方差分解与候选池隔离实验，该研究揭示了当前评估体系在方法排名与工件选择上的系统性失效。这一发现挑战了现有进化算法的有效性评估标准，但如何构建低噪声的中间过程指标以突破高噪声基准的分辨率限制，仍是亟待解决的开放问题。

## 研究背景

当智能体进化系统试图通过修改外部工件来提升性能时，其核心机制依赖于一个闭环：提议者生成候选工件，评估器在任务集上打分，选择器保留高分工件。这一过程隐含了一个关键前提：评估分数能够可靠地区分“真实改进”与“随机波动”。然而，LLM 的推理轨迹具有内在随机性，导致同一工件在重复评估中产生分数波动，即评估噪声（Evaluation Noise, $\sigma$）；同时，不同进化运行生成的工件质量本身也存在差异，即运行间方差（Run-to-Run Variance, $\tau$）。当真实改进幅度小于这两者构成的评估分辨率时，选择器便无法有效筛选出更优工件，导致进化过程退化为随机游走。

当前智能体进化研究面临的核心矛盾在于：文献中报道的方法间性能差距（通常仅为几个百分点）往往小于单次评估的统计波动范围。主流评估实践通常仅报告单次运行结果，未对评估噪声进行量化或控制，导致方法排名极易受运气影响。此外，部分基准上观察到的显著增益被证实源于评估捷径（Evaluation Shortcuts），即工件利用了评分器的格式偏好而非真实能力提升。这种评估体系的脆弱性使得社区难以判断进化算法是否真正有效，亟需从统计分辨率的角度重新审视评估协议。

## 核心方法

### 方差分解模型与评估分辨率定义

本文首先建立了一个形式化的方差分解模型，以量化评估管线的统计分辨率。对于任意工件 $A$，其单次观测分数 $\hat{Y}(A)$ 可分解为真实质量 $Y(A)$ 与零均值评估噪声 $\epsilon$ 之和。根据全方差定律，观测分数的总方差由评估噪声方差 $\sigma^2$ 和运行间方差 $\tau^2$ 共同决定：

$$ \mathrm{Var}(\hat{Y}) = \underbrace{\mathbb{E}_{A}\!\left[\mathrm{Var}(\hat{Y}\mid A)\right]}_{\sigma^{2}} + \underbrace{\mathrm{Var}_{A}\!\left(\mathbb{E}[\hat{Y}\mid A]\right)}_{\tau^{2}} $$

该公式表明，评估分辨率取决于这两个方差分量的大小。$\sigma^2$ 反映了同一工件在重复评估中的不稳定性，而 $\tau^2$ 反映了不同进化运行生成工件质量的波动。设计动机在于，传统方法将两者混为一谈，导致无法区分“评估仪器噪声”与“算法随机性”。通过分离这两个分量，本文能够精确计算识别特定幅度改进所需的统计功效，从而界定评估管线的最小可检测改进量。

### 候选池隔离与提议-选择解耦评估

为验证分辨率假设，本文设计了候选池隔离实验，将“提议质量”与“选择可靠性”解耦。传统端到端评估无法区分进化停滞是因为提议者未生成好工件，还是因为选择器未能识别好工件。本文构建了两个独立的固定候选池：Proposal Pool 用于评估提议者生成高质量工件的能力，Selection Pool 用于评估选择器在已知存在优质工件时的识别能力。

在 Selection Pool 实验中，选择器仅能观测到工件的少量 rollout 结果，而工件的真实质量由大量 held-out rollouts 确定。这一设计动机在于，通过固定候选池，消除了提议者随机性对选择器评估的干扰，从而能够独立测量选择机制在统计噪声下的表现。实验发现，即使候选池中包含显著优于基线的工件，基于执行分数或 LLM 评判的选择器在区分优劣工件时的准确率仍接近随机猜测（50%），证实了选择环节是进化积累的主要瓶颈。

### 评估捷径审计与增益归因

针对文献中报道的显著增益，本文实施了评估捷径审计。通过逐条分析进化产生的工件指令，发现大部分增益可由单条规则复现，该规则通常利用了评分器对特定输出格式的偏好。为验证这一假设，本文修复了评估协议，恢复官方评分标准或基于语义而非表面形式进行评分，并重新评估相同工件。

这一设计动机在于，若增益源于真实能力提升，修复评估后增益应保留；若源于评估捷径，增益应消失。实验结果显示，修复评估后，中位增益从 17.6 个百分点骤降至 0.8 个百分点，且重新运行进化算法无法恢复原有增益。这证实了部分基准上的“成功”进化实为对评估漏洞的过拟合，而非真实能力的提升，进一步支持了分辨率假设：只有当改进幅度远超评估噪声时，进化才能被观察到，而这类大幅改进往往源于捷径。

## 实验评估

本文在 Terminal-Bench、ALFWorld、SpreadsheetBench 和 OfficeQA 等基准上，对七种进化方法（包括 GEPA、SkillOpt-Lite 等）和六种模型进行了大规模重复实验，共计 1,030 次独立进化运行和超过 210 万条测试轨迹。实验设置旨在量化评估噪声 $\sigma$ 和运行间方差 $\tau$，并测试标准评估实践能否识别方法间的真实差异。

| 基准 | 评估噪声 $\sigma$ (pp) | 运行间方差 $\tau$ (pp) | 单次运行标准差 (pp) | 识别中位增益所需运行次数 |
| :--- | :--- | :--- | :--- | :--- |
| SpreadsheetBench | 1.0 - 3.7 | 0 - 12.3 | 1.7 - 4.1 | ~5 |
| OfficeQA | 1.0 - 3.7 | 0 - 12.3 | 1.7 - 4.1 | ~10 |
| ALFWorld | 1.0 - 3.7 | 0 - 12.3 | 1.7 - 4.1 | ~19 |
| Terminal-Bench | 4.5 | 0 - 12.3 | 1.7 - 4.1 | ~23 |

*注：pp 为百分点。数据源自论文正文及附录描述。*

实验结果显示，Terminal-Bench 上的评估噪声最高，达到 4.5 pp。在 Terminal-Bench 上，单次运行排名仅能 33% 的概率识别出四种文本工件方法中的最优者，接近随机猜测（25%）。相比之下，在 SpreadsheetBench 上，单次运行排名准确率为 51% 至 73%。这表明，在高噪声基准上，标准评估实践完全无法可靠区分方法优劣。

在候选池实验中，Selection Pool 包含 100 个技能，其中存在显著优于基线的工件。然而，执行分数选择器的成对准确率为 49.7%，LLM 评判器为 45.4% 至 49.0%，均无统计显著性差异。这表明，即使存在真实改进，现有选择机制也无法在统计噪声下将其识别出来。此外，修复评估捷径后，中位增益从 17.6 pp 降至 0.8 pp，证实了大部分显著增益源于评估漏洞。

评估边界方面，本文未覆盖计算效率维度，且实验主要基于冻结模型，未探讨模型权重更新对评估分辨率的影响。可复现性方面，论文承诺发布轨迹数据，但未提供即时代码链接。

## 关联研究分析

从评估方法论角度看，本文与 CORE（Michelakis et al., 2025）等全路径评估框架存在显著差异。CORE 通过确定性有限自动机对动作路径进行标注，旨在提供细粒度的过程诊断，其核心假设是过程指标能更准确地反映智能体能力。然而，本文指出，即使引入过程指标，若其本身具有高噪声或依赖 LLM 评判，仍无法解决分辨率问题。本文的方差分解模型为过程评估提供了统计严谨性基础，即任何过程指标的有效性必须首先通过 $\sigma$ 和 $\tau$ 的量化来验证，否则其诊断价值可能被噪声淹没。

从进化算法设计角度看，本文与 GEPA（Agrawal et al., 2024）和 SkillOpt-Lite 等主流方法形成对照。这些方法致力于优化提议者策略或选择器算法，假设评估反馈是可靠的。本文则批判性地指出，在评估分辨率不足的情况下，优化提议者或选择器算法本身可能是无效的，因为瓶颈在于评估仪器而非算法逻辑。这一观点挑战了当前进化研究的主流范式，即通过更复杂的算法设计来提升性能，转而强调评估基础设施的标准化与噪声控制。

## 总结

本文针对智能体进化中增益不稳定与排名不可复现的核心矛盾，提出“分辨率假设”，指出评估噪声与运行间方差导致的分辨率不足是进化停滞的根本原因。通过方差分解模型与候选池隔离实验，本文证明了标准评估实践在高噪声基准上无法可靠识别方法差异，且选择机制在统计噪声下退化为随机猜测。核心实验数据显示，Terminal-Bench 上单次运行排名准确率仅为 33%，修复评估捷径后中位增益从 17.6 pp 降至 0.8 pp。本文的边界在于未探讨低噪声中间过程指标的具体构建方法，也未覆盖模型权重更新场景。当评估噪声成为主要瓶颈时，如何设计能够突破高噪声基准分辨率限制的细粒度过程指标，是后续研究需解决的关键问题。
