# HuggingFace最新推荐论文 ｜VSpark: Speculative Decoding for Autoregressive Vision-Language-Action Models ｜VSpark：面向自回归视觉-语言-动作模型的无损投机解码

作者：Suho Yoo、Youngjoon Jang、Hyebin Cho 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2611.22666)

> 自回归视觉-语言-动作模型（Vision-Language-Action Models, VLAs）在机器人控制中受限于逐 Token 生成的串行延迟，难以满足高频控制需求。现有投机解码（Speculative Decoding, SD）方法在 VLA 场景下失效，因为压缩动作 Token 化使得单 Token 无法独立解码为有效动作，且动作空间的连续相似性导致基于离散 Token 匹配的严格验证接受率极低，而放宽验证又会破坏无损性。VSpark 提出在草稿侧利用动作相似性而非放宽验证侧，通过校准动作噪声 Rollout、特征对齐和续写复用机制，在保持严格无损验证的前提下提升接受长度。该工作证明了在压缩 Token 化场景下，通过优化草稿模型对动作语义的感知能力，可以在不牺牲控制精度的情况下实现显著加速，但其依赖仿真环境收集噪声数据，真实世界泛化能力尚待验证。

## 研究背景

当机器人执行任务时，自回归 VLA 模型需将连续动作离散化为 Token 序列并逐个生成，这一过程受限于大模型前向传播的内存带宽瓶颈，导致控制频率低下。为解决此问题，投机解码引入轻量级草稿模型并行预测候选 Token，由目标模型单次并行验证，实现无损加速。然而，在 VLA 领域，动作 Token 化技术已从早期的逐维度分箱（Per-dimension Tokenizers）演进为压缩 Token 化（Compressed Tokenizers），如 FAST 和 ActionCodec。压缩 Token 化将多个时间步和维度的动作联合编码，单个 Token 不再对应单一动作值，必须解码完整序列才能恢复动作。这一特性使得传统 SD 中基于单 Token 分布对齐的验证逻辑失效：若草稿 Token 与目标预测不符，无法直接判断其动作偏差，因为无法在不生成后续 Token 的情况下解码动作。

现有针对 VLA 的 SD 方法试图通过放宽验证规则来应对这一挑战，例如接受动作分箱距离相近的 Token。但在压缩 Token 化下，这种基于分箱的邻近性定义不再适用，且实验表明基于 Token 嵌入距离的松弛验证会导致成功率大幅下降（如从 91.7% 降至 71.4%）。因此，核心矛盾在于：如何在压缩 Token 化导致单 Token 动作语义模糊、且严格验证接受率低的约束下，实现无损加速？VSpark 的切入点在于，既然验证侧难以利用动作相似性，便转向草稿侧，通过让草稿模型学习动作的连续语义特征，并复用目标模型在被拒绝分支上已计算但未使用的预测信息，从而在不改变验证规则的前提下提升接受长度。

## 核心方法

### 方法参照系：基于并行草稿的树状验证

VSpark 建立在 DSpark 并行草稿架构之上，该架构通过双向注意力一次性预测所有候选位置的基 logits，并利用轻量级马尔可夫头修正前序 Token 依赖。在标准树状验证中，目标模型并行验证草稿树的所有节点，仅接受与目标预测完全匹配的最长前缀，其余分支及目标模型在这些分支上计算出的后续预测均被丢弃。本文问题与该通用流程的关键差异在于：动作 Token 的语义连续性要求草稿模型不仅预测正确的 Token ID，还需理解 Token 背后的动作语义；同时，被拒绝分支上的目标预测蕴含了动作修正后的潜在延续信息，标准流程未加以利用。

### 校准动作噪声 Rollout 与特征对齐

针对草稿模型仅从演示数据的状态分布中学习，难以覆盖目标模型在推理时可能访问的扰动状态的问题，VSpark 引入校准动作噪声 Rollout。设计动机在于，草稿模型需要适应目标模型的动作误差分布，而非仅模仿专家动作。具体而言，在仿真 Rollout 中，将目标模型生成的动作替换为草稿模型的预测，计算两者在平移和旋转上的差异 $r_n$，并以此构建噪声协方差矩阵：

$$ \Sigma=\frac{1}{N}\sum_{n=1}^{N}r_{n}r_{n}^{\top} $$

该公式表明噪声分布直接反映了草稿模型预测目标动作时的误差结构。在训练阶段，向目标动作添加此高斯噪声以生成扰动状态，并在这些状态上收集目标模型的 Token 和隐藏特征作为监督信号。

在此基础上，VSpark 引入特征对齐以解决 Token 标签监督的离散性缺陷。传统交叉熵损失将动作相似但 Token 不同的预测视为同等错误。VSpark 将目标模型多层隐藏状态拼接并投影至草稿模型维度，作为草稿模型的输入和回归目标。损失函数替换为：

$$ \mathcal{L}=\sum_{i}w_{i}\left(\lambda\,\ell^{\mathrm{CE}}_{i}+(1-\lambda)\,\ell^{\mathrm{feat}}_{i}\right) $$

其中 $\ell^{\mathrm{feat}}_{i}$ 为 Smooth L1 损失，用于对齐目标模型输出头前的隐藏特征。这一设计使草稿模型获得连续的动作语义信号，能够识别不同 Token 编码的相似动作，从而在特征空间而非仅 Token 空间对齐目标模型。

### 续写复用机制

针对树状验证中被拒绝分支上的目标预测被丢弃的问题，VSpark 提出续写复用（Continuation Reuse）。设计动机在于，若被拒绝的草稿 Token $a$ 与目标预测 Token $b$ 动作相似，则目标模型在 $a$ 之后预测的 Token $c$ 在修正前缀 $b$ 下仍可能有效。标准解码丢弃了这些计算成本为零的预测。VSpark 在验证阶段提取被拒绝分支上的目标预测序列，并在下一轮草稿树构建时，将这些续写 Token 的草稿得分提升至该父节点下的最高分：

$$ \widetilde{s}_{i}(v)=\begin{cases}\max_{u}s_{i}(u),&v\in\mathcal{H}_{i},\\ s_{i}(v),&\text{otherwise}.\end{cases} $$

该公式确保目标模型预测的续写 Token 在候选选择中具有最高优先级，从而将已计算的动作延续信息转化为下一轮草稿的有效候选。由于这些候选仍需在下一轮接受严格验证，该机制在提升接受长度的同时保持了无损性。

## 实验评估

实验在 LIBERO、LIBERO-Plus、LIBERO-Pro 和 SimplerEnv 四个机器人操作基准上进行，覆盖 $\pi_0$-FAST、StarVLA-FAST、ActionCodec 和 G0.5 四种 VLA 模型。基线包括 EAGLE-3、P-EAGLE、DFlash、DFlash2 和 DSpark，涵盖了自回归草稿、并行草稿及特征对齐等主流 SD 路线。

| 模型 | 方法 | $\tau$ (Avg.) | Speedup (Avg.) |
| :--- | :--- | :--- | :--- |
| $\pi_0$-FAST | DSpark | 3.16 | $1.60\times$ |
| $\pi_0$-FAST | VSpark | 3.94 | $1.93\times$ |
| ActionCodec | DSpark | 3.69 | $1.93\times$ |
| ActionCodec | VSpark | 4.21 | $2.10\times$ |
| G0.5 | DSpark | 2.33 | $1.09\times$ |
| G0.5 | VSpark | 2.99 | $1.28\times$ |

VSpark 在所有模型和基准上均取得最高接受长度 $\tau$ 和加速比。在 $\pi_0$-FAST 上，加速比从 DSpark 的 $1.60\times$ 提升至 $1.93\times$；在 ActionCodec 上从 $1.93\times$ 提升至 $2.10\times$。值得注意的是，G0.5 因线性注意力机制限制了树状验证的并行效率，多数基线加速比低于 $1.1\times$，而 VSpark 仍达到 $1.28\times$，表明其草稿优化策略对硬件架构具有鲁棒性。

消融实验显示，续写复用、特征对齐和动作噪声 Rollout 三个组件互补。在 $\pi_0$-FAST 上，特征对齐贡献最大，将 $\tau$ 从 3.22 提升至 3.87；而在 ActionCodec 上，续写复用贡献显著，将 $\tau$ 从 3.69 提升至 4.04。这表明不同 Token 化方式对草稿优化的敏感度不同：FAST 的频域特征更依赖特征对齐，而 ActionCodec 的向量量化特征更受益于续写复用。

评估边界方面，实验仅在仿真环境中进行，噪声校准依赖仿真 Rollout，真实世界中的传感器噪声和动力学差异可能影响噪声协方差的准确性。此外，论文未报告置信区间，且 G0.5 的加速比提升幅度相对较小，提示线性注意力架构下树状验证的瓶颈可能需系统级优化而非仅靠算法改进。

## 关联研究分析

从验证策略看，VSpark 与 Spec-VLA 和 KERV 形成鲜明对比。Spec-VLA 和 KERV 通过放宽验证规则（如接受动作分箱距离相近的 Token）来提升接受率，但这在压缩 Token 化下不可行，且会引入控制误差。VSpark 坚持严格验证，将动作相似性的利用前移至草稿训练阶段，通过特征对齐让草稿模型“理解”动作语义，从而生成更可能通过严格验证的候选。这一差异源于对无损性在机器人控制中重要性的不同权衡：VSpark 认为动作 Token 的精确匹配对控制稳定性至关重要，因此拒绝任何验证侧的松弛。

从草稿架构看，VSpark 与 EAGLE-3 和 DSpark 同属特征对齐路线，但针对 VLA 特性进行了改造。EAGLE-3 移除了特征回归以简化训练，而 VSpark 恢复了特征监督，因为动作空间的连续相似性使得仅靠 Token 分布对齐不足以捕捉动作语义。DSpark 提供并行草稿基础，但 VSpark 引入续写复用，填补了树状验证中目标预测信息利用的空白。这一改进在文本 SD 中较少见，因为文本 Token 的语义独立性较强，被拒绝分支的后续预测复用价值较低，而在动作序列中，局部动作的连续性使得续写复用具有显著收益。

## 总结

VSpark 解决了压缩动作 Token 化下 VLA 模型无损加速的难题，其核心在于将动作相似性的利用从验证侧转移至草稿侧。通过校准噪声 Rollout、特征对齐和续写复用，VSpark 在保持严格验证的前提下，将 $\pi_0$-FAST 的加速比提升至 $1.93\times$，ActionCodec 提升至 $2.10\times$。该工作证明了在 Token 语义模糊场景下，草稿模型对连续特征的学习能力是提升接受率的关键。然而，其噪声校准依赖仿真环境，真实世界中的动力学差异可能导致噪声分布失配，进而影响草稿模型的泛化能力。当机器人部署于非结构化真实环境时，如何在线校准动作噪声分布以维持草稿模型的有效性，是该方法走向实际应用必须回答的问题。
