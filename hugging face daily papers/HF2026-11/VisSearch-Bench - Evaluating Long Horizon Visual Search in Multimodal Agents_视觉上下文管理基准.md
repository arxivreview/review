# HuggingFace最新推荐论文 ｜VisSearch-Bench: Evaluating Long Horizon Visual Search in Multimodal Agents ｜视觉上下文管理基准

研究机构：清华大学、中国人民大学

作者：ZhengXian Wu、Qianhao Nie、Zhuohong Chen 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2611.04894)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2611.04894)

> 多模态智能体在开放网络搜索中需跨步关联视觉证据，但现有评估仅关注是否使用图像，未量化视觉状态在长程交互中的维护与整合。本文提出“视觉上下文管理”概念，构建包含五类任务的VisSearch-Bench，通过Process Score诊断中间推理断裂。该基准揭示了当前模型在集合级验证与跨步线索追踪上的显著短板，最佳系统完全解决率仅26.47%。其价值在于将评估从静态感知推向动态状态维护，但低分是否源于工具限制而非能力不足，仍需进一步验证。

## 研究背景

当智能体面对需要跨多张图像、多个对象及多轮搜索才能回答的问题时，其核心挑战不再是单步识别，而是如何在动态交互中维护视觉状态。这一过程称为视觉上下文管理，指智能体在搜索中组织视觉信息并将其与外部发现关联的能力。若仅依赖文本先验或单步图像匹配，智能体无法处理如“对比目录中所有符合视觉条件的条目”这类任务，因为早期视觉线索需指导后续搜索，后期证据又需修正早期假设。

现有评估体系在此处存在盲区。MMSearch-Plus等基准虽强调细粒度视觉线索提取，但多关注单步或短链任务，未考察视觉证据如何跨步累积并影响最终答案。InterLV-Search探索了多分支结构，却未引入集合级验证与视觉结构引导。这种评估缺口导致模型在静态基准上的高分无法转化为开放网络中的可靠表现。本文切入点在于将评估重心从“是否使用视觉”转向“如何跨步管理视觉状态”，通过构建高难度动态基准，暴露模型在长程视觉搜索中的具体失效模式。

## 核心方法

### 方法参照系

本文问题属于智能体能力评估类别，其标准流程为：给定问题与初始图像，智能体通过ReAct框架调用工具（搜索、浏览、图像检查），逐步收集证据并生成答案。本文与该通用流程的关键差异在于，任务设计强制要求视觉证据在多个搜索步骤间传递、比较与聚合，而非仅作为初始查询的触发器。

### 任务分类与视觉状态定义

传统基准常将图像视为静态输入，本文则根据视觉信息在搜索链中的作用，将任务划分为五类：集合视觉搜索、序列视觉搜索、混合宽深搜索、竞争性视觉消歧、视觉结构引导搜索。这一分类旨在覆盖视觉证据从“识别”到“关联”再到“聚合”的不同认知层级。

为量化这一过程，本文定义交互历史 $h_t$ 为：

$$ h_t = (q, I_0, (a_1, o_1), \dots, (a_t, o_t)) $$

其中 $q$ 为问题，$I_0$ 为初始图像集，$a_i$ 为动作，$o_i$ 为工具返回的文本或视觉观测。该公式表明，智能体的决策依赖于所有历史观测的累积，而非仅当前状态。设计动机在于，此前方法常忽略 $o_i$ 中视觉信息的跨步依赖，导致模型在需要回溯或修正视觉假设时失效。

### 过程导向评估指标

仅评估最终答案准确率（Accuracy, Acc）无法区分“正确但错误推理”的案例。本文引入Process Score (PS)，量化子问题回答的正确性与完整性。对于任务 $i$，设 $m_i$ 为标注的关键状态数，$R_i$ 为正确恢复的状态集合，则：

$$ PS = \frac{1}{N} \sum_{i=1}^{N} \frac{|R_i|}{m_i} $$

其中 $|R_i|/m_i$ 表示任务 $i$ 中关键状态的恢复比例。该公式的物理含义是，即使最终答案错误，若智能体正确识别了大部分中间视觉对象或事实，仍可获得部分分数。这一设计解决了Acc指标在长程任务中区分度不足的问题，能够诊断模型是在搜索空间选择、视觉候选遗漏还是证据聚合阶段出现错误。

## 实验评估

实验在VisSearch-Bench的204个任务上进行，覆盖7个主要领域。基线包括16个多模态模型（开源与闭源）及两种智能体框架（ReAct, DeerFlow）。评估协议规定每个任务最多30轮搜索与60次工具调用，图像预算为20张。

| 模型/框架 | 设置 | Accuracy (%) | Process Score (%) |
| :--- | :--- | :--- | :--- |
| Qwen3.5-397B-A17B | Direct | 1.96 | 12.72 |
| Qwen3.5-397B-A17B | ReAct | 15.69 | 32.43 |
| Qwen3.5-397B-A17B | DeerFlow | 10.29 | 28.37 |
| GPT-5.5 | ReAct | 25.49 | 49.52 |
| Kimi-K3 | ReAct | 26.47 | 38.57 |

主结果显示，工具增强显著提升性能。以Qwen3.5-397B-A17B为例，ReAct框架使其Acc从1.96%提升至15.69%，PS从12.72%提升至32.43%。然而，最佳系统（ReAct+Kimi-K3）的完全解决率仅为26.47%，表明长程视觉搜索仍极具挑战性。值得注意的是，框架效果因模型而异：GPT-5.5在ReAct下表现优于DeerFlow，而Qwen3.6-35B-A3B在DeerFlow下Acc更高（10.78% vs 7.35%），说明框架与模型能力的匹配度至关重要。

消融实验进一步验证了视觉访问方式的影响。对比Direct、Text、Caption与Full四种设置，Full（允许直接检查图像与裁剪）在所有模型上均取得最高Acc与PS。例如，Qwen3.5-397B-A17B在Full设置下Acc为15.69%，而在Caption设置（仅使用图像描述）下降至14.71%。这表明，尽管图像描述能减轻组织负担，但通用描述常遗漏跨图像比较所需的细粒度细节，导致性能下降。此外，视觉工具调用在搜索前20%阶段最为频繁（占41.5%-69.2%），但后续阶段仍持续使用，证实视觉信息处理贯穿整个搜索过程。

评估边界方面，本文未覆盖计算效率维度，且低Acc可能部分源于工具调用限制（如30轮上限）而非模型能力不足。Process Score依赖人工标注的关键状态，其信度受标注一致性影响。代码与数据集已开源，但工具调用依赖外部API（Serper, SerpApi），复现需相应访问权限。

## 关联研究分析

从问题动机看，VisSearch-Bench与MMSearch-Plus均关注视觉线索，但后者侧重单步细粒度提取，前者强调跨步状态关联。MMSearch-Plus的任务设计允许模型在识别初始实体后转向纯文本搜索，而VisSearch-Bench的集合视觉搜索任务强制要求模型在多个对象间进行视觉比较与聚合，无法通过文本捷径完成。这一差异源于任务特性：前者评估感知精度，后者评估状态维护能力。

从方法设计看，VisSearch-Bench与BrowseComp-V3均评估跨图像推理，但BrowseComp-V3主要关注图像区域对齐与整合，而VisSearch-Bench引入了视觉结构引导搜索，要求模型利用图像中的空间位置或对象顺序指导外部搜索。BrowseComp-V3未涉及开放网络中的动态证据更新，而VisSearch-Bench的序列视觉搜索任务要求早期视觉线索决定后续搜索目标。这一差异反映了评估重心的不同：前者聚焦静态图像理解，后者聚焦动态交互中的视觉决策。

## 总结

本文针对多模态智能体在开放网络搜索中视觉状态维护能力评估缺失的问题，提出VisSearch-Bench基准。通过定义五类任务与Process Score指标，本文量化了视觉证据在长程交互中的跨步关联与聚合能力。实验表明，即使配备工具，最佳系统完全解决率仅26.47%，且模型在集合级验证与跨步线索追踪上存在显著短板。本文的边界在于，低准确率可能受限于工具调用轮次与图像预算，而非模型本体能力；Process Score的评分规则是否足以排除模型通过冗余工具调用“碰巧”得分，论文未给出充分验证。当工具调用限制放宽时，模型性能是否会线性提升，还是受限于视觉状态管理的内在瓶颈，仍需进一步探究。
