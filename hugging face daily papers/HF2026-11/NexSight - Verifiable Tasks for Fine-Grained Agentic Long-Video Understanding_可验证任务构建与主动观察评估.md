论文原文见 [arXiv](https://arxiv.org/abs/2611.22790)

> 导读：长视频细粒度理解要求模型在数小时的时间轴上定位分散的视觉证据，以回答计数、排序或状态变化等问题。现有方法依赖均匀采样或离线监督微调，导致关键帧丢失且无法监督“何时看、看哪里”的决策过程，模型常因缺乏视觉证据而依赖语言先验产生幻觉。本文提出 NexSight 框架，通过 SightForge 构建可验证任务，利用 SightLoop 实现多尺度主动观察评估，并基于求解器轨迹进行步骤级后训练。该框架将评估重心从最终答案正确性转向证据获取过程，为长视频代理式理解提供了可信的数据与评估闭环，但其核心模型性能尚未超越现有强化学习方法，且步骤级监督对复杂时序推理的泛化能力仍待验证。

## 研究背景

当模型面对长达数小时的视频时，固定帧预算的均匀采样会将时间轴上的关键瞬间稀释，导致细粒度动态信息丢失。为解决这一输入瓶颈，代理式长视频理解（Agentic Long-Video Understanding）允许模型自主决定搜索时间轴、检查细节并整合证据。然而，这一范式面临双重困境：一是评估困难，稀疏的视觉支持难以验证全局性声明（如精确计数），且现有基准多评估最终答案而非实际解码的帧，混淆了证据获取与证据使用；二是训练困难，最终答案监督无法指定“下一步看哪里”或“何时证据充足”等中间决策，导致模型即使拥有工具访问权限，其搜索性能仍可能低于被动接收均匀帧。

现有研究在长视频高效推理与时序定位强化学习之间做出了不同取舍。长视频高效推理路线（如 LongVA, GroundVTS）通过 Token 压缩或自适应采样保留时序线索，但缺乏对观察决策的显式监督；时序定位强化学习路线（如 TempR1, TimeThink）通过过程奖励提升推理精度，但依赖高质量标注数据且计算开销大。两类方法均未解决“如何构建可信任务以同时评估和训练主动观察能力”的问题。本文切入点在于将验证视为主动观察问题，通过构建可验证任务，使评估与训练共享同一证据获取逻辑，从而量化并监督证据获取过程。

## 核心方法

### 方法参照系：代理式观察决策

本文问题置于代理式长视频理解的通用流程下：给定视频 $V$ 和问题 $q$，模型基于历史 $h_k$ 选择观察动作 $u_k$，接收视觉观察 $o_k$，直至输出答案 $\hat{a}$。标准流程中，观察动作通常由启发式规则或端到端策略网络生成，评估仅关注最终答案。本文的关键差异在于引入“可验证性”约束，要求任务构建、评估与训练均基于从原始视频密集 reacquired 的证据，并将监督信号从答案扩展至观察轨迹。

### SightForge：可验证任务构建

SightForge 通过代理式工作流构建可靠任务，其核心创新在于“答案隐藏验证”与“反例检查”。传统任务构建依赖固定视图标注，无法验证全局声明。SightForge 要求验证者在不可见草稿答案的情况下，仅从问题与 reacquired 证据中重建答案，并通过反例检查（如搜索相邻窗口以确认计数无遗漏）来拒绝错误候选。这一设计解决了稀疏支持无法验证时间轴范围声明的失效问题，确保任务答案与视觉证据严格对齐。

### SightLoop：多尺度主动观察评估

SightLoop 提供共享的多尺度交互界面，耦合时间探索与空间检查。其核心公式为时间证据召回率 $R^{\mathrm{hit}}$：

$$ R_{i}^{\mathrm{hit}} = \frac{1}{m_{i}}\sum_{j=1}^{m_{i}}\mathbb{I}[T_{i}\cap I_{ij}\neq\varnothing] $$

其中 $T_i$ 为实际返回帧的时间戳集合，$I_{ij}$ 为标注证据区间。该公式量化了模型是否“找到”了正确时刻，而非仅“答对”问题。SightLoop 记录实际观察、解码时间戳及资源使用，将评估从答案正确性扩展至证据获取效率，揭示了“找到正确时刻”与“整合证据”之间的差距。

### 步骤级轨迹监督

针对最终答案监督无法指定观察决策的问题，本文利用求解器轨迹进行步骤级后训练。每个保留的求解器调用转化为训练样本，以交互历史为上下文，当前助手输出为目标。损失仅计算在当前目标轮次，历史轮次、视觉输入及工具返回作为上下文。这一设计解决了代理式训练中探索行为多样性丢失的问题，通过模仿求解器的搜索轨迹，使模型学会在证据不足时主动探索，而非依赖语言先验直接生成答案。

## 实验评估

实验在自建 SightLine 基准（310 个任务，108 个长视频）及外部基准 Video-MME Long 和 LVBench 上进行。基线覆盖 GPT-5.6 Sol、DeepSeek V4 等前沿模型及 Qwen3.5 系列开源模型。主结果显示，最强配置 GPT-5.6 Sol 在 SightLine 上仅达 54.52%，而提供标注证据的 Evidence Oracle 达 79.35%，证实证据获取是主要瓶颈。

| 模型 / 部署 | Direct-64 (Acc %) | Agentic (Acc %) |
| :--- | :--- | :--- |
| Qwen3.5-35B-A3B-Base | 25.81 | 21.29 |
| Qwen3.5-35B-A3B-Inst | 33.23 | 28.06 |
| Sight-35B (ours) | 28.39 | 42.26 |

Sight-35B 在交互式评估中较 Base 提升 20.97 个百分点，超越指令微调模型 14.19 点，但在固定输入 Direct-64 上低于指令微调模型，表明主动观察能力与被动问答能力存在分离。

| 基准 | 问题数 | 35B Base (Acc %) | Sight-35B (Acc %) | $\Delta$ |
| :--- | :--- | :--- | :--- | :--- |
| Video-MME Long | 900 | 53.00 | 61.22 | +8.22 |
| LVBench subset | 123 | 44.72 | 52.85 | +8.13 |

消融实验显示，在相同帧预算下，代理式窗口选择将时间证据召回率从 19.84% 提升至 40.63%，但跨窗口计数与状态变化准确率未显著提升，表明单纯的时间定位增益不足以解决多窗口整合问题。训练后，Sight-35B 在跨窗口计数上提升 37.50 点，且开始使用显式空间检查（0.72 次/轨迹），而 Base 模型从未使用。评估边界方面，$R^{\mathrm{hit}}$ 仅衡量时间交集，未保证空间细节解析；论文未提供代码，可复现性受限。

## 关联研究分析

从问题动机看，NexSight 与 CogniGPT 均聚焦代理式长视频理解，但 CogniGPT 侧重通过工具调用与记忆更新定位稀疏信息，其评估仍依赖最终答案；NexSight 则引入“可验证性”作为核心约束，将评估重心转向证据获取过程，解决了 CogniGPT 无法区分“未找到证据”与“错误推理”的盲区。从方法设计看，NexSight 与 TempR1 均旨在提升时序推理精度，但 TempR1 依赖强化学习（RL）的过程奖励优化最终答案，而 NexSight 采用步骤级监督模仿求解器轨迹。这一差异源于任务特性：NexSight 的任务构建本身即为主动观察过程，使得轨迹监督成为可能，而 TempR1 的任务标注为静态区间，无法提供观察决策的监督信号。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文针对长视频细粒度理解中证据获取不可量化、观察决策不可监督的核心矛盾，提出将验证视为主动观察问题，通过 SightForge 构建可验证任务，利用 SightLoop 评估证据获取，并基于求解器轨迹进行步骤级后训练。实验证明，Sight-35B 在交互式评估中较 Base 提升 20.97 个百分点，且在 Video-MME Long 上提升 8.22 点，证实了轨迹监督对主动观察能力的有效性。然而，论文暴露的局限在于：步骤级监督是否足以替代 RL 在复杂时序推理中的探索能力，以及 $R^{\mathrm{hit}}$ 指标是否真正反映了视觉证据的充分性，仍待进一步验证。
