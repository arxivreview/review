> 导读 视频生成模型在视觉保真度上取得突破，却常因缺乏显式物理因果建模而生成违反重力或碰撞定律的画面，导致其无法作为可靠的世界模拟器。现有方法多依赖静态参数推断或单一奖励信号，难以在开放域中实现物理知识的自动化提取与错误修复。PhysLoop 提出一种统一代理框架，将大语言模型（LLM）的物理推理能力与物理仿真器的执行约束相结合，通过“规划-仿真-验证-精修”闭环实现训练数据构建与推理时视频修复。该框架在物理修复任务上展现出显著优势，但其外观精修步骤对物理精度的潜在影响及 LLM 幻觉的收敛性仍需进一步验证。

## 研究背景

当视频生成模型面对复杂物理交互时，其训练目标通常优化像素级重建损失，导致模型仅捕捉统计相关性而非物理因果律。这种“视觉逼真但物理不可信”的矛盾，使得模型在生成物体穿透、速度突变或碰撞无响应等场景时频繁失效。为解决此问题，研究者引入了显式物理仿真器作为中间表示，通过生成符合物理定律的轨迹来约束视频合成。然而，传统仿真引导方法依赖预定义参数或高质量的 3D 重建，难以处理开放域中物理属性的自动估计与场景的自动化构建。

当前领域面临两大瓶颈：一是高质量物理监督数据的获取成本高昂，真实世界实验难以规模化且缺乏精确标注；二是现有视频模型在推理阶段缺乏有效的物理错误诊断与局部修复机制。虽然强化学习（RL）和直接偏好优化（DPO）可通过奖励信号内化物理知识，但其依赖外部评估器的准确性，且难以定位具体的物理违规片段。PhysLoop 的切入点在于利用 LLM 已有的物理常识，将其置于可执行的仿真环境中进行约束与验证，从而将 LLM 的隐性知识转化为显式的、可验证的物理视频数据，并支持对现有视频的物理错误进行闭环修复。

## 核心方法

### 方法参照系：仿真器在环的代理工作流

PhysLoop 属于物理仿真引导生成路线，其核心流程遵循“任务规范-场景构建-物理执行-验证修订”的闭环。与 PhysGen 等依赖静态参数推断的方法不同，PhysLoop 引入 LLM 代理作为核心控制器，负责将自然语言请求转化为可执行的仿真场景程序。该框架的关键差异在于，它不直接将仿真轨迹作为扩散模型的条件输入，而是通过 LLM 代理动态编排资产检索、场景布局及仿真参数，并在仿真执行后通过验证器反馈迭代修正场景配置，最终将验证通过的仿真视频作为运动参考，指导视频精修模型生成高保真画面。

### 核心创新：LLM 驱动的仿真场景程序化构建

在场景构建环节，传统方法通常依赖人工标注或预定义的资产库，难以应对开放域请求。PhysLoop 设计了任务规范与场景构建代理，LLM 首先将文本请求扩展为包含目标事件、构建假设及验证条件的任务规范。随后，代理通过外部搜索或生成工具获取 3D 资产，并编写场景程序以指定对象放置与关系。该程序将视觉网格与物理表示分离，允许详细外观与简化碰撞代理并存。设计动机在于解决 LLM 直接生成视频时空间关系与物理条件不一致的问题，通过程序化构建确保场景在仿真前的逻辑正确性。代理在完整仿真前渲染低分辨率预览帧，若发现对象错位或交互遮挡，则调整布局或相机视角，从而抑制 LLM 在场景构建中的幻觉风险。

### 核心创新：基于仿真状态与视觉观测的双重验证机制

仿真执行成功并不等同于请求事件发生，因此 PhysLoop 引入了验证与修订机制。验证器将仿真状态（如接触信号、物体状态）与视觉观测同预定义的事件要求进行比对。对于碰撞任务，验证器检查接触是否发生及后续运动是否满足规范，并执行考虑外力与数值误差的守恒检查。若验证失败，验证器返回包含仿真或视觉证据的失败描述，代理据此修订负责阶段的配置。该机制通过可验证的执行反馈闭环，确保 LLM 的物理知识在应用过程中被持续校正。最终视频验证在外观精修后进行，以评估精修过程是否破坏了已验证的物理关系，从而保证最终输出在保留物理动力学的同时提升视觉保真度。

## 实验评估

实验在 PhysLoop-Gen、PhysLoop-Repair 及外部基准 Physics-IQ Verified 上进行。基线覆盖包括 Seedance 2.5、MiniMax H3 等 SOTA 视频生成模型，以及不同 LLM 骨干（Claude Opus 5, Kimi K3）与精修器组合。PhysLoop 在 PhysLoop-Gen 上取得 85% 的任务成功率，显著高于 Seedance 2.5 的 73%；在 PhysLoop-Repair 上，其修复成功率达到 86.00%，远超最强基线 Seedance 2.5 的 19.33%。在 Physics-IQ Verified 上，PhysLoop 得分为 52.06，低于 VJEPA-2 Reward Signal 的 62.64，但高于 Seedance 2.5 的 48.07。

| 方法 | PhysLoop-Gen 任务成功率 (%) | PhysLoop-Repair 修复成功率 (%) | Physics-IQ Verified 得分 |
| --- | --- | --- | --- |
| PhysLoop | 85.00 | 86.00 | 52.06 |
| Seedance 2.5 | 73.00 | 19.33 | 48.07 |
| H3 | 53.00 | 18.00 | 28.14 |
| Gemini Omni | 49.00 | 14.67 | 18.94 |

消融实验显示，移除精修器（w/o Refiner）会导致物理合理性评分从 4.06 降至 3.94，且视觉真实感显著下降，表明外观精修在保持物理动力学与提升视觉质量之间存在权衡。评估协议主要依赖人工评分与自动指标（VideoCon-Physics, VBench），但自动指标可能偏向特定视觉风格，难以检测稀疏帧中的时序物理错误。代码与数据集已开源，但 LLM 代理的修订循环收敛性未提供理论保证，存在资源耗尽风险。

## 关联研究分析

从问题动机看，PhysLoop 与 WMReward 均致力于推理时物理对齐，但路径截然不同。WMReward 利用潜在世界模型作为奖励信号，通过强化学习优化生成策略，其优势在于端到端的物理一致性优化，但依赖奖励模型的准确性且计算开销大。PhysLoop 则通过显式仿真器作为可验证的执行环境，将物理约束转化为可解释的验证反馈，其优势在于修复过程的可控性与可解释性，但受限于仿真场景的构建复杂度。PhysLoop 未与 WMReward 直接对比，可能因任务设定（修复 vs 生成）及评估基准差异导致直接比较困难。

从方法设计看，PhysLoop 与 PSIVG 均利用仿真器作为中间桥梁，但 PSIVG 侧重从 2D 视频提升 3D 属性以初始化仿真，而 PhysLoop 侧重 LLM 代理对仿真全流程的编排。PSIVG 假设场景属性可准确从 2D 提升至 3D，而 PhysLoop 通过 LLM 代理主动构建场景，减少了对源视频 3D 重建精度的依赖。然而，PhysLoop 依赖高质量 3D 资产库，当资产缺失时，其场景构建能力可能受限，而 PSIVG 的 2D 提升策略在资产受限场景下可能更具鲁棒性。

## 总结

PhysLoop 针对视频生成中物理知识难以自动化提取与错误修复的矛盾，提出了一种结合 LLM 代理与物理仿真器的闭环框架。该框架通过程序化场景构建与双重验证机制，将 LLM 的物理常识转化为可验证的视频数据，在 PhysLoop-Repair 上实现了 86.00% 的修复成功率，显著超越了现有基线。然而，其外观精修步骤可能导致物理精度的轻微损失，且 LLM 代理在复杂场景下的修订循环收敛性尚未得到充分验证。当仿真器无法覆盖目标物理现象或资产库缺失时，该框架的泛化能力是否仍能保持，论文未给出明确回答。
