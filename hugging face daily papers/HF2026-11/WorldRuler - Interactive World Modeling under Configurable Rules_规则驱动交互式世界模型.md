研究机构：北京理工大学、日本东京大学

作者：Mingliang Zhai、Chuanhao Li、Jiaming Tan 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2611.24869)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2611.24869)

> 交互式视频世界模型旨在构建能够感知、交互并预测物理世界演化的内部模拟器，其核心价值在于弥合被动视频生成与主动具身智能之间的鸿沟。现有方法多聚焦于物理或几何一致性，难以处理用户自定义规则（如游戏机制）在保存/加载后的状态持久性与视觉实现。WorldRuler 提出可执行 3D 规则图与动态对象绑定机制，将规则逻辑下沉至视频生成潜空间进行属性替换。该工作拓展了世界模型的交互维度，但其规则定义依赖外部输入，且评估基准为自建数据集，跨域通用性尚待验证。

## 研究背景

当玩家在游戏中执行“击败怪物掉落钥匙”这一动作时，若中途保存并退出，重新加载后世界必须准确恢复“怪物已死、钥匙在地、门未开”的状态，且后续动作需严格遵循此逻辑链。这一需求超越了传统视频生成模型对视觉分布的匹配，要求模型具备显式的状态记忆与因果推理能力。传统世界模型（World Models）如 Ha 和 Schmidhuber (2018) 提出的框架，虽奠定了基于想象进行策略训练的基础，但其低维潜空间难以承载高维视觉流中的复杂规则依赖。随着视频扩散模型（Video Diffusion Models）的兴起，研究重心转向高维视觉流的动作条件生成，但自回归生成中的误差累积与场景遗忘问题，使得长时程规则遵循成为瓶颈。

当前领域在长时程一致性上主要依赖显式或隐式记忆机制，如 AlayaWorld 通过显式记忆检索维持场景持久性，WorldPlay 通过流式生成架构维持几何一致性。然而，这些方法主要解决物理或几何状态的持久性，对于用户自定义规则（Rule）的逻辑状态维护关注不足。Code World Model 和 Programmable World Model 虽引入可执行逻辑，但多停留在代码或程序层面，未深入视频生成的潜空间进行细粒度属性控制。WorldRuler 的切入点在于：如何将非物理的用户定义规则，通过显式图结构与潜空间属性替换，实现从逻辑状态到视觉实例的精确映射与持久化。

## 核心方法

### 方法参照系：可执行状态与视觉生成的解耦

在交互式世界模型的标准流程中，模型需根据历史观测 $O_{1:t}$ 和动作 $A_{1:t}$ 预测未来观测 $O_{t+1:T}$。现有方法通常将状态维护与视觉生成分离，状态模块输出条件信号，生成模块负责渲染。WorldRuler 的关键差异在于，它将规则定义、依赖关系及执行状态组织为可执行 3D 规则图 $\mathcal{G}_{t}$，并通过动态对象绑定 $\mathcal{B}_{t}$ 将规则实体映射至视觉实例。这一设计使得规则状态不仅作为生成条件，更直接介入去噪过程，确保视觉输出严格遵循逻辑约束。

### 可执行 3D 规则图与状态持久化

传统方法在保存/加载时往往仅恢复视觉上下文，导致规则依赖断裂。WorldRuler 引入可执行 3D 规则图，将对象身份、空间信息与交互逻辑统一表示。执行状态 $X_{t}$ 记录对象属性与规则进度，其演化遵循：

$$
X_{t+1}=\operatorname{Execute}_{\mathcal{R}}\!\left(X_{t},u_{t},e_{t}\right)
$$

其中 $u_{t}$ 为当前动作，$e_{t}$ 为接受的事件证据。该公式表明，状态更新不仅依赖动作，还依赖经过验证的事件证据，防止未完成的动作错误触发规则。通过联合序列化图、状态与绑定 $\mathcal{C}_{t}=\operatorname{Save}\!\left(\mathcal{G}_{t},X_{t},\mathcal{B}_{t}\right)$，WorldRuler 实现了规则定义与执行状态的原子性保存与恢复，解决了此前方法在长时程交互中因状态丢失导致的逻辑断裂问题。

### 动态对象绑定与属性状态替换

规则效果需在正确的视觉实例上实现，尤其是当目标对象不可见时。WorldRuler 通过动态对象绑定将规则实体关联至 3D 对象与视觉实例，并在去噪过程中引入对象属性状态替换机制。在潜空间 $z_{\sigma}$ 中，通过池化操作提取局部特征 $a_{i}$，利用冻结的仿射读取器估计当前属性 $\widehat{s}_{i}$，并计算与规则目标 $s_{i}^{\star}$ 的偏差 $\delta_{i}$。属性替换算子 $T_{\phi}$ 定义为：

$$
a_{i}^{\prime}=T_{\phi}(a_{i},s_{i}^{\star})=a_{i}+B_{i}\delta_{i}+\gamma(\delta_{i})\,Q_{i}f_{\phi}\!\left(a_{i},h_{i},\widehat{s}_{i},s_{i}^{\star},\sigma\right)
$$

其中 $B_{i}$ 为右逆矩阵，用于修正属性坐标；$Q_{i}$ 为投影矩阵，确保兼容调整不改变规定读数。该机制在保持视觉连贯性的同时，强制潜空间特征符合规则规定的属性状态，解决了生成视频与输入动作在时空上错位的问题。

## 实验评估

WorldRuler 在自建数据集 RuleVerse 及公开基准 WorldState-Bench 上进行了评估。RuleVerse 包含 3,200 对规则驱动交互视频，覆盖 Habitat 室内场景与 GTA-V 开放游戏环境。实验对比了 SWM、MiniMax-H3 等基线方法。在 GTA-V 子集上，WorldRuler 在规则成功率（RSR）与完全完成率（FCR）上均取得显著优势。

| 方法 | 数据集 | RSR (%) | FCR (%) |
| :--- | :--- | :--- | :--- |
| SWM | GTA-V | 44.19 | - |
| MiniMax-H3 | GTA-V | 43.43 | - |
| WorldRuler | GTA-V | 67.42 | 66.66 |

WorldRuler 在 GTA-V 上的 RSR 达到 67.42%，较 SWM 的 44.19% 提升 23.23 个百分点，表明显式规则图与属性替换机制在开放游戏环境中具有显著有效性。消融实验显示，动态对象绑定与属性状态替换对性能贡献最大，移除任一组件均导致规则遵循能力大幅下降。然而，评估主要依赖自建数据集，缺乏与 Sora 等主流大规模视频生成模型的直接对比，且未报告置信区间，数值比较需谨慎。

## 关联研究分析

从问题动机看，WorldRuler 与 Code World Model 均关注可执行逻辑，但 Code World Model 通过编码代理维护状态并编译为代理视频，侧重于高层逻辑控制；WorldRuler 则将规则状态下沉至视频生成的潜空间，通过属性替换实现细粒度视觉控制。这一差异源于任务特性：Code World Model 适用于结构化环境，而 WorldRuler 需处理开放世界中复杂的视觉-逻辑耦合。WorldRuler 未探索从视频自动归纳规则的能力，规则定义仍依赖自然语言或代码输入，这限制了其在未知环境中的泛化能力。

从方法设计看，WorldRuler 与 AlayaWorld 均采用显式记忆机制，但 AlayaWorld 通过流式 3D 点缓存维持时空一致性，侧重于几何持久性；WorldRuler 通过可执行 3D 规则图维持逻辑状态，侧重于规则遵循。AlayaWorld 的记忆检索开销较大，而 WorldRuler 的图结构在开放世界中的扩展性瓶颈尚未被充分评估。当规则数量增加时，图结构的维护与绑定效率是否成为性能瓶颈，论文未给出回答。

## 总结

WorldRuler 针对交互式世界模型中用户自定义规则的状态持久性与视觉实现难题，提出可执行 3D 规则图与动态对象绑定机制，通过潜空间属性替换实现规则逻辑与视觉生成的闭环。实验表明，该方法在 GTA-V 数据集上 RSR 达到 67.42%，显著优于基线方法。然而，其规则定义依赖外部输入，且评估基准为自建数据集，跨域通用性尚待验证。当规则复杂度增加至多步依赖与动态环境时，显式图结构的维护成本与绑定效率是否仍能保持实时性，论文未给出回答。
