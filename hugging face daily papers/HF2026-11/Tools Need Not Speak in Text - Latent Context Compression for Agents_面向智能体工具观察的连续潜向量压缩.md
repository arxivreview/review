> 导读 智能体在多步交互中因累积原始工具输出导致上下文爆炸，进而引发计算开销激增与注意力稀释。现有文本级压缩方法受限于离散符号的语义连贯性约束，难以在极高压缩比下保留决策关键信息。本文提出 Coca-Cola，将工具观察压缩为连续潜向量并直接注入智能体嵌入空间，通过动作分布对齐训练保留决策关键信息。该工作突破了文本压缩的比率上限，但在动作保真与语义保真之间的等价性上仍存疑。

## 研究背景

当智能体遵循 ReAct 范式执行多步任务时，每次工具调用返回的原始观察（如搜索结果）被直接追加至上下文。随着交互步数增加，工具观察迅速占据上下文主体（在示例中达 96.7%），导致 Token 消耗呈线性甚至超线性增长。这种上下文膨胀不仅带来二次方计算复杂度的推理延迟，更因冗余信息干扰模型注意力，造成“中间迷失”现象，使模型难以从噪声中定位下一步决策所需的关键线索。

为缓解此问题，主流路线分为硬压缩与软压缩。硬压缩（如 LLMLingua）通过剔除低信息量 Token 实现精简，但易导致指代悬空与逻辑链断裂；软压缩（如 ICAE）将文本映射为连续向量，虽提升了压缩比，但其训练目标通常聚焦于原始文本的重构保真度。在智能体场景下，重构完整文本并非必要，核心需求是保留足以支持下一步动作选择的决策信息。现有方法未能针对“动作效用”进行端到端优化，导致压缩表示与智能体决策行为之间存在语义错位。

## 核心方法

### 方法参照系与理论动机

在通用长文本压缩中，软提示压缩通常将输入映射为固定数量的潜在向量，并通过自编码损失重构原文。本文针对智能体工具观察场景，指出文本 Token 的离散性限制了信息密度。理论上，$n$ 个文本 Token 的最大码本容量为 $\mathcal{C}_{\text{text}}(n) = n \log_2 |\mathcal{V}|$，而 $m$ 个 $d$ 维连续潜向量在有限精度下的容量为 $\mathcal{C}_{\text{latent}}(m) = m d_{\text{eff}} \log_2 B$。当 $d_{\text{eff}} \log_2 B > \log_2 |\mathcal{V}|$ 时，连续表示在相同位置预算下具备更高信息容量，为高压缩比提供了理论支撑。

### 上下文感知编码与潜向量适配

针对工具观察的决策依赖性，本文设计上下文感知编码器 $C_\theta$，联合编码任务指令 $q$、当前推理轨迹 $r_t$ 与工具观察 $o_t$，生成条件隐藏状态 $H_t = C_\theta(q, r_t, o_t)$。由于编码器与目标智能体 $p_\psi$ 处于不同表示空间，引入潜向量适配器 $A_\phi$ 将 $H_t$ 映射为 $m$ 个潜向量 $z_t \in \mathbb{R}^{m \times d}$，并直接插入智能体输入嵌入序列：

$$
z_t = A_\phi(H_t) \in \mathbb{R}^{m \times d}
$$

该设计消除了文本重构环节，使压缩表示直接作为智能体可消费的连续接口，解决了离散 Token 在跨模型空间传递时的语义断裂问题。

### 动作保持训练机制

为在有限表示预算下保留决策关键信息，本文提出动作保持训练（Action-Preserving Training）。传统软压缩以文本重构损失为目标，而本文通过 KL 散度对齐全量观察与压缩潜向量下的智能体下一步动作分布：

$$
\mathcal{L} = \lambda_{\text{KL}} D_{\text{KL}}(p_{\text{full}} \| p_{\text{latent}}) + \lambda_{\text{CE}} \text{CE}(y_{t+1}, p_{\text{latent}})
$$

其中 $p_{\text{full}} = p_\psi(\cdot | q, h_t, o_t)$ 为全量观察下的动作分布，$p_{\text{latent}} = p_\psi(\cdot | q, h_t, z_t)$ 为压缩表示下的动作分布。该损失函数迫使压缩器丢弃对动作选择无贡献的冗余信息，仅保留“动作充分”的潜表示，实现了从“文本保真”到“效用保真”的目标转移。

## 实验评估

实验在 NQ、TriviaQA、2Wiki 和 HotpotQA 四个基准上，使用 Qwen 和 GLM 两组模型配置进行评估。基线覆盖硬压缩（LongLLMLingua）、文本摘要（LLMSummary）及软压缩（ICAE）。结果显示，Coca-Cola 在大幅降低 Token 消耗的同时提升了任务性能。

| 模型配置 | 数据集 | 方法 | EM (%) | F1 (%) | 压缩率 (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3.5-35B-A3B | NQ | Vanilla | 23.67 | 33.17 | - |
| | | Coca-Cola | 24.78 | 37.33 | 85.78 |
| | HotpotQA | Vanilla | 11.00 | 16.41 | - |
| | | Coca-Cola | 25.70 | 33.75 | 70.01 |
| GLM-4.7-Flash | NQ | Vanilla | 21.50 | 26.08 | - |
| | | Coca-Cola | 23.50 | 31.45 | 73.73 |
| | 2Wiki | Vanilla | 26.50 | 31.29 | - |
| | | Coca-Cola | 28.00 | 36.20 | 74.75 |

在效率方面，Coca-Cola 相比未压缩智能体减少 70.01%–89.24% 的 Token 消耗，端到端运行时间降低 24.45%–55.97%。值得注意的是，在 HotpotQA 上，Coca-Cola 的 EM 从 11.00 提升至 25.70，表明去除冗余噪声显著改善了多跳推理中的注意力聚焦。

消融实验显示，移除推理状态或任务指令输入均导致 EM 下降（如移除推理状态后 NQ EM 从 23.50 降至 21.45），证实了上下文感知编码的必要性。潜向量数量 $m$ 从 8 增至 128 时，F1 从 26.34% 升至 31.45%，但压缩率从 82.56% 降至 73.73%，表明存在效率与性能的权衡边界。

评估边界方面，实验仅覆盖 Web 搜索 QA 任务，未涉及代码修复或复杂规划场景。此外，动作分布对齐是否等同于语义保真尚缺乏独立验证，存在“动作正确但推理逻辑错误”的黑盒风险。

## 关联研究分析

与 ICAE 相比，两者均使用自编码架构生成连续潜向量，但训练目标存在本质差异。ICAE 旨在重构原始文本，适用于通用长文本理解；Coca-Cola 则通过动作分布对齐优化，专为智能体决策服务。这一差异源于任务特性：智能体无需完整文本，仅需决策线索。然而，动作对齐是否足以保证在未见过的复杂推理链中的泛化性，论文未给出回答。

与 ACON 相比，ACON 基于规则或 LLM 摘要进行动态上下文管理，属于文本级压缩；Coca-Cola 则是端到端可微分的潜向量压缩。ACON 保留了人类可读性，便于审计；Coca-Cola 牺牲可解释性换取更高压缩比。在需要严格审计的场景中，Coca-Cola 的黑盒特性可能成为部署障碍，而 ACON 的显式摘要更具优势。

## 总结

本文针对智能体工具观察导致的上下文爆炸与注意力稀释问题，提出 Coca-Cola 框架，通过连续潜向量压缩与动作保持训练，实现了高压缩比下的决策信息保留。实验表明，该方法在 Web 搜索任务中降低 Token 消耗 70% 以上，并显著提升 EM 与 F1 分数。其核心局限在于评估场景局限于单轮或短程多跳 QA，且动作分布对齐无法完全排除语义扭曲风险。当智能体面临需要严格逻辑验证或外部审计的复杂任务时，动作保真与语义保真之间的潜在偏差是否会引发系统性错误，仍待验证。
