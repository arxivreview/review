> 导读 长时程人-场景交互（Human-Scene Interaction, HSI）合成旨在让智能体在三维场景中执行由自然语言指令驱动的多步物理交互序列。现有基于大语言模型（Large Language Model, LLM）的代理方法受限于高层文本控制与定性视觉反馈，无法精确修正执行偏差，导致多步任务中误差累积而失败。Inhabitant 提出一种免训练代理框架，通过空间控制接口直接编写运动生成器的位置、路径与姿态约束，并利用半物理仿真器提供定量测量反馈，构建“生成-执行-测量-修订”的闭环。该框架在自建基准 Inhabit 上实现了 98.7% 的任务成功率，显著优于现有基线，但其对预训练生成器 Kimodo 的依赖及半物理仿真的简化假设，限制了其在真实物理动力学场景中的直接迁移能力。

## 研究背景

当智能体在三维场景中执行“拿起方块并扔进篮子”这类长时程任务时，其核心挑战在于将高层语义意图转化为精确的全身运动轨迹。这一过程通常依赖预训练的运动生成器，如 Kimodo，将文本或空间约束映射为人体姿态序列。然而，生成器输出的运动仅是运动学上的近似，实际执行中受场景几何阻挡与物体动力学影响，往往偏离预期。若缺乏对执行结果的精确感知，智能体无法判断偏差来源，导致后续步骤基于错误的初始状态继续执行，形成误差累积。

早期 HSI 研究多聚焦于单步静态交互，如坐下或抓取，通过优化或变分自编码器（Variational Autoencoder, VAE）生成满足几何约束的姿态。随着扩散模型（Diffusion Models）的引入，动态运动生成的多样性与保真度显著提升，但语义捷径问题暴露：模型倾向于利用文本与场景的统计相关性而非物理逻辑生成动作。近期，LLM 被引入 HSI 作为高层规划器，如 HumanCLAW 调用原子技能，InteractAgent 通过文本提示控制生成器。然而，这些方法在控制接口上仍停留在高层语义或离散技能层面，缺乏对关节位置、路径的细粒度空间控制；在反馈机制上，仅依赖渲染帧的定性观察，无法量化手与物体间的厘米级偏差。这种“开环”或“弱反馈”架构使得智能体在需要精确空间对齐的复杂任务中频繁失败。

## 核心方法

### 方法参照系：开环代理与运动生成器

在标准的 LLM 驱动 HSI 代理框架中，LLM 作为规划器输出高层指令（如文本描述或技能 ID），运动生成器 $\mathcal{G}$ 接收指令并生成运动序列 $m$，场景仿真器 $\mathcal{E}$ 执行运动并返回渲染图像。该流程的关键缺陷在于控制粒度粗与反馈信息模糊：LLM 无法直接指定关节坐标，且仅能通过视觉判断“是否成功”，无法获知“偏差多少”。Inhabitant 在此参照系中重构了代理与生成器、仿真器之间的接口，将开环规划转变为基于定量反馈的闭环控制。

### 空间控制接口：细粒度约束编写

传统代理通过文本提示控制生成器，无法精确指定手在特定帧的位置。Inhabitant 引入空间控制接口，允许 LLM 直接编写运动生成器 Kimodo 的控制规范 $c$。Kimodo 支持三种空间约束：根节点路径点（Root Waypoints）、末端执行器目标（End-effector Targets）和全身关键帧（Full-body Keyframes）。代理在每次 `try` 调用中，不仅提供文本提示，还显式指定关节在特定帧的目标位置或姿态。

该设计的核心在于将高层语义分解为可执行的几何约束。代理通过前向运动学（Forward Kinematics）计算目标姿态对应的关节旋转，确保约束在生成器输入空间中有效。这一改动解决了此前方法因文本模糊性导致的动作与目标物体空间错位问题，使代理能够精确控制手在抓取瞬间的坐标，而非仅依赖生成器的隐式推断。

### 定量反馈机制：基于测量的闭环修正

传统代理依赖渲染帧进行定性判断，无法量化执行偏差。Inhabitant 引入定量反馈机制，代理通过 `measure` 调用向仿真器查询特定物理量。仿真器基于半物理（Half-physics）模型执行运动，返回身体部位位置、手与物体距离、接触状态等数值测量 $M(q, \tau)$。

代理利用这些测量值修订控制规范。例如，若测量显示手在抓取帧距离物体 5 厘米，代理将调整下一尝试中的手目标位置，补偿该偏差。这一闭环机制解决了误差累积问题：代理仅在测量值满足意图时才提交（commit）当前运动段，否则回滚（rollback）并重新尝试。该设计将物理执行的不确定性转化为可量化的控制误差，使代理能够通过迭代修正逼近物理可行的交互序列。

## 实验评估

实验在自建基准 Inhabit 上进行，该基准包含 75 个家庭任务，涵盖放置、投掷、脚踢、抽屉开关及姿态保持五类目标，分为低、中、高及姿态四个难度层级。评估指标包括任务成功率、子目标完成率、碰撞数、干扰物体数及脚滑率。基线包括 InteractAgent（文本控制）、HumanCLAW（技能调用）及 GEMS（单次空间规划）。

| 方法 | 语言模型 | 成功率 (%) | 子目标完成率 | 碰撞数 | 脚滑率 (%) | 尝试次数 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| InteractAgent† | Claude Opus 5.5 | 26.7 | 34.5 | 105.0 | 52.8 | 133 |
| HumanCLAW† | Claude Opus 5.5 | 20.0 | 26.8 | 42.1 | 11.9 | 12 |
| GEMS† | Claude Opus 5.5 | 6.7 | 13.5 | 11.9 | 3.8 | 7 |
| Inhabitant | Claude Opus 5.5 | 98.7 | 99.6 | 9.3 | 4.7 | 51 |

Inhabitant 在 Claude Opus 5.5 驱动下完成 74/75 任务，成功率 98.7%，显著优于最佳基线 InteractAgent 的 26.7%。消融实验表明，移除空间控制接口后，尽管保留反馈，代理仍无法完成多数任务；移除定量反馈后，运动精度下降，代理难以识别任务完成状态。值得注意的是，Inhabitant 在解决任务上的 API 成本为 1.7 美元，低于基线的 4.8 至 21.1 美元，显示闭环修正虽增加尝试次数，但提高了单次尝试的有效性。

评估边界方面，Inhabit 基准依赖半物理仿真，抓取通过距离规则抽象，未涉及复杂摩擦与形变。此外，实验未报告推理延迟，且依赖特定预训练生成器 Kimodo，其生成质量对闭环效果的影响未充分解耦。

## 关联研究分析

从问题动机看，Inhabitant 与 PhysHSI 均关注物理合理性，但路径截然不同。PhysHSI 通过强化学习（Reinforcement Learning, RL）将物理约束内化于策略训练，追求端到端的物理可行运动；Inhabitant 则通过仿真器外化反馈，在推理阶段通过闭环修正补偿物理偏差。PhysHSI 适用于训练数据充足的特定任务，而 Inhabitant 的免训练特性使其能泛化至未见过的长时程任务组合，但代价是推理时的计算开销与对仿真器精度的依赖。

从方法设计看，Inhabitant 与 GEMS 均使用 LLM 编写空间约束，但 GEMS 采用单次规划，缺乏执行反馈，导致误差累积。Inhabitant 引入定量反馈闭环，解决了 GEMS 在复杂交互中因初始规划偏差导致的失败。然而，Inhabitant 未对比基于扩散模型直接生成长序列的方法（如 Interact2Ar），因后者不支持 Agent 闭环控制，这一缺失使得无法评估闭环机制相对于端到端长序列生成在语义对齐上的优劣。

## 总结

Inhabitant 针对长时程 HSI 中控制粒度粗与反馈模糊的核心矛盾，提出通过空间控制接口与定量反馈机制构建闭环代理框架。该框架在 Inhabit 基准上实现 98.7% 的任务成功率，证明了细粒度空间控制与定量误差修正在多步交互中的有效性。其边界在于依赖半物理仿真与预训练生成器 Kimodo，未验证在全物理动力学或真实机器人硬件上的迁移能力。当仿真器物理模型与真实世界存在显著域差距时，基于定量反馈的闭环修正是否仍能收敛至物理可行解，论文未给出回答。
