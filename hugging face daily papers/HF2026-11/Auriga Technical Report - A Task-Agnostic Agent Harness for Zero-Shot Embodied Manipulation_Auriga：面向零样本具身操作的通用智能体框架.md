# HuggingFace最新推荐论文 ｜Auriga Technical Report: A Task-Agnostic Agent Harness for Zero-Shot Embodied Manipulation ｜Auriga：面向零样本具身操作的通用智能体框架

论文原文见 [arXiv](https://arxiv.org/abs/2611.01112)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2611.01112)

> 视觉-语言模型（Vision-Language Model, VLM）在理解复杂指令方面表现优异，但在直接驱动机器人执行物理操作时，常因缺乏对物理约束的显式建模而陷入“看见-做到”差距。现有端到端视觉-语言-动作（Vision-Language-Action, VLA）模型虽能生成连续动作，但在零样本、无重置的单集执行中，难以处理执行过程中的微小偏差与不可逆错误。Auriga 提出了一种任务无关的智能体框架，通过显式任务信念、3D几何测量与单一准入网关，将高层规划与底层物理执行解耦。该框架在 RoboDojo 和 RoboCasa365 基准上显著缩小了规划与执行的差距，挑战了端到端架构在鲁棒性上的绝对优势，但其对仿真环境理想化假设的依赖仍需真实世界验证。

## 研究背景

当机器人面对未见过的任务时，其核心困境在于高层语义意图与低层物理执行之间的断裂。VLM 能够解析“将杯子挂在架子上”的指令，但无法直接输出满足毫米级精度的关节角度序列。这一断裂被称为“看见-做到”差距。为了弥合这一差距，主流研究发展出了 VLA 模型，通过大规模数据预训练将视觉、语言直接映射为连续动作向量。然而，VLA 模型通常假设环境是可重置的，且依赖大量特定任务数据，在零样本、单集执行且失败不可逆的真实场景中，其容错能力受到严重限制。

现有方法在零样本泛化上存在两种主要瓶颈。一是端到端策略网络缺乏显式的错误恢复机制，一旦动作偏离预期，模型难以从当前物理状态中诊断原因并修正计划。二是基于代码生成的智能体方法虽具备逻辑规划能力，但生成的程序往往无法感知实时场景变化，导致执行失败后无法有效恢复。Auriga 的切入点在于：不训练新的策略网络，而是构建一个通用的智能体框架，通过显式的物理验证网关和3D几何测量，赋予通用大模型在单集执行中实时感知偏差、暂停执行并原地恢复的能力。

## 核心方法

### 方法参照系：闭环决策与任务无关框架

Auriga 将具身操作建模为闭环决策过程，区别于传统 VLA 的端到端映射。在该框架中，模型不直接输出动作，而是通过工具调用或生成程序来请求物理动作。所有物理动作必须通过一个名为“准入网关”（Admission Gateway, $A$）的单一接口执行。该网关负责验证动作的可行性、监控执行过程并返回量化反馈。这一设计将任务决策权完全保留给大模型，而将物理约束的执行与验证交由框架处理，实现了任务无关的通用性。

### 显式任务信念与证据记录分离

传统智能体方法常将规划状态与交互历史混合在上下文窗口中，导致长程任务中信息过载与状态混淆。Auriga 引入了显式任务信念 $B_t$ 与证据记录 $E_t$ 的分离机制。$B_t$ 是模型当前对任务的理解、计划及关键前提状态的紧凑表示，而 $E_t$ 是完整的交互历史，存储在上下文之外，按需检索。

模型在每一步决策时，基于任务描述 $g$、当前信念 $B_t$ 和证据记录 $E_t$ 选择工具调用 $u_t$：

$$ u_t \sim \pi_\theta(\cdot | g, B_t, E_t) $$

其中 $\pi_\theta$ 为固定参数的预训练模型。这一公式表明，模型的决策不仅依赖于当前观测，还依赖于其内部维护的信念状态。$B_t$ 包含计划、注意力列表和前提账本，每个前提状态标记为 pending、supported、contradicted 或 unknown。这种设计使得模型能够在长程任务中保持对关键物理状态（如“杯子是否被夹持”）的显式追踪，避免了端到端模型中隐式状态估计的模糊性。

### 准入网关与预览-执行-验证闭环

为了解决执行过程中的不可逆错误，Auriga 设计了准入网关 $A$，实施预览-执行-验证闭环。在物理动作执行前，网关在暂停的仿真环境中生成轨迹预览，包括路径、成本及碰撞警告。模型确认预览后，网关执行动作，并实时监控每个阶段的偏差。

每个动作阶段 $k$ 具有目标状态 $\hat{x}_k$ 和模型设定的容差 $\tau_k$。执行过程中，网关测量实际状态 $x_k$，当偏差 $\epsilon_k$ 超出容差时，立即停止执行并返回回执 $r_t$：

$$ \epsilon_k = x_k - \hat{x}_k, \quad \text{if } |\epsilon_k| > \tau_k \implies \text{halt} $$

这一机制将执行错误从“事后发现”转变为“实时拦截”。回执 $r_t$ 包含已完成的阶段、测量偏差及未执行阶段，使模型能够基于精确的物理偏差数据，从当前状态原地恢复，而非重置环境。这种硬约束验证弥补了端到端 VLA 模型在接触丰富任务中缺乏显式物理反馈的缺陷。

## 实验评估

实验在 RoboDojo 和 RoboCasa365 两个仿真基准上进行，重点评估零样本、单集执行条件下的泛化能力与鲁棒性。基线对比涵盖了端到端 VLA 模型（如 $\pi_0$, WorldScape）及现有智能体方法（如 PyRUA-Lean, HexaShell）。

| 方法 | 类型 | RoboDojo SR (%) | RoboDojo Score | RoboCasa365 Overall SR (%) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-6 Astra (RoboProbe) | Agent | 22.5 | 29.0 | - |
| PyRUA-Lean | Agent | 50.35 | 55.26 | 56.4 |
| HexaShell-Preview | Agent | 46.85 | 53.18 | - |
| GO-3 Nano Preview | Agent + WAM | 56.42 | 61.90 | - |
| **Auriga** | **Agent** | **57.74** | **64.00** | **73.2** |

Auriga 在 RoboDojo 上以 57.74% 的成功率（SR）和 64.00 的得分位居榜首，较参考智能体框架 RoboProbe 提升显著。在 RoboCasa365 的复合任务中，Auriga 达到 73.2% 的 SR，超越依赖预训练策略的 VLA 辅助智能体 RPent（59.2%）和 PyRUA-Lean（56.4%）。这一结果证明，在零样本条件下，通用智能体框架通过显式验证机制，在长程复合任务上的表现优于依赖特定数据预训练的端到端策略。

消融实验表明，预览机制与阶段容差停止对性能贡献最大。移除预览机制导致成功率从 42/50 降至 36/50，且未审查动作中的碰撞风险显著增加。移除阶段容差停止则导致错误累积，成功率降至 34/50。这验证了“预览-执行-验证”闭环在防止不可逆错误中的核心作用。

评估边界方面，实验主要在仿真环境中进行，尽管引入了场景随机化，但仿真物理引擎的理想化假设（如完美的接触模型）可能高估了真实世界的鲁棒性。此外，Auriga 依赖 VGGT-Omega 和 SAM 3.1 等预训练感知模型，其性能上限受限于这些感知模块在极端光照或遮挡条件下的表现。

## 关联研究分析

从问题动机看，Auriga 与端到端 VLA 模型（如 $\pi_0$）存在根本差异。$\pi_0$ 等模型通过 Flow Matching 直接生成连续动作，依赖大规模数据隐式学习物理约束，在短程任务中控制频率高且平滑。然而，在零样本、无重置的长程任务中，$\pi_0$ 缺乏显式的错误诊断与恢复机制，一旦执行偏差超出训练分布，模型难以从当前状态修正。Auriga 则通过准入网关将物理执行转化为可验证的离散步骤，牺牲了部分控制频率，换取了执行过程中的可解释性与鲁棒性。这种差异源于任务特性的不同：$\pi_0$ 针对的是分布内的高频控制，而 Auriga 针对的是分布外的零样本规划。

从方法设计看，Auriga 与 PyRUA-Lean 等同为智能体方法，但 Auriga 引入了更严格的零样本协议与物理验证网关。PyRUA-Lean 虽能生成代码，但其执行过程缺乏对物理状态的实时反馈与容差检查，导致在接触丰富任务中易因微小偏差失败。Auriga 的准入网关 $A$ 强制所有动作通过预览与阶段验证，将“程序正常退出”与“物理任务成功”解耦。这一设计是否比端到端 VLA 在真实世界部署中更具优势，取决于真实传感器噪声与仿真环境之间的差距，论文未提供真实机器人实验数据，这一边界尚待验证。

## 总结

Auriga 针对零样本具身操作中“看见-做到”差距的核心矛盾，提出了一种任务无关的智能体框架。通过显式任务信念与准入网关的预览-执行-验证闭环，该框架在 RoboDojo 上达到 57.7% 的成功率，显著缩小了规划与执行的差距。其核心价值在于证明了在零样本条件下，通用大模型结合显式物理验证机制，能够超越依赖特定数据预训练的端到端 VLA 模型。然而，该方法的边界在于其高度依赖仿真环境的理想化物理反馈与预训练感知模型的精度。当真实世界中的传感器噪声与物理不确定性远超仿真假设时，基于容差 $\tau_k$ 的硬约束停止机制是否会频繁触发导致任务停滞，论文未给出回答。
