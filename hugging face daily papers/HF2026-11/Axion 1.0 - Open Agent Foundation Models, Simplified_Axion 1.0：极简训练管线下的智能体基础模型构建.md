> 智能体基础模型旨在将推理、工具调用与持续交互内化为模型固有属性，以突破静态参数化知识在实时信息与精确计算上的局限。现有主流训练管线通过堆叠中期训练、直接偏好优化（Direct Preference Optimization, DPO）及在线策略蒸馏（On-Policy Distillation, OPD）等复杂阶段来构建这些能力，导致训练成本高昂且能力增益来源难以解耦。Axion 1.0 提出了一种极简的三阶段训练范式，仅包含两阶段监督微调（Supervised Fine-Tuning, SFT）与强化学习（Reinforcement Learning, RL），摒弃了所有额外的对齐与蒸馏阶段。该模型通过模型感知的数据构造与确定性工具任务合成，在通用推理与科学任务上展现出与前沿商业模型相当的竞争力。这一极简范式挑战了复杂训练栈的必要性，但其在纯工具编排基准上的表现及极端噪声环境下的鲁棒性仍存疑。

## 研究背景

当大语言模型（Large Language Model, LLM）从单纯的文本生成向智能体演进时，其核心挑战在于如何将外部工具调用与长程推理无缝融合。早期研究如 ReAct 确立了“思考-行动-观察”的交互范式，但依赖人工标注轨迹的监督微调（SFT）范式在分布外（Out-of-Distribution, OOD）任务上表现脆弱，且难以处理多步依赖传播中的级联失败。为提升泛化性，研究重心转向基于可验证奖励的强化学习（Reinforcement Learning with Verifiable Rewards, RLVR），通过环境反馈替代人工标注。然而，当前前沿智能体模型的训练管线日益臃肿，往往包含中期训练、多阶段 SFT、DPO、RL 及 OPD 等复杂环节。这种复杂性不仅推高了复现成本，更使得各阶段对最终能力的贡献难以剥离，阻碍了训练配方在不同模型间的迁移。

Axion 1.0 针对这一痛点，提出核心问题：构建强泛化能力的智能体基础模型，究竟需要多少训练复杂度？现有方法倾向于通过增加训练阶段来弥补数据或算法的不足，而 Axion 1.0 认为，简化训练管线并不意味着简化学习问题，而是应将重心转移至高质量、高难度训练数据的构造。通过模型感知的数据增强与确定性工具任务合成，Axion 1.0 证明了仅凭两阶段 SFT 与 RL 即可实现与复杂管线相当甚至更优的智能体能力，为智能体训练从“堆砌阶段”向“数据质量驱动”的范式转变提供了实证支持。

## 核心方法

### 极简三阶段训练范式

Axion 1.0 的训练流程由两个轻量级 SFT 阶段与一个 RL 阶段组成，未引入任何中期训练、DPO 或 OPD。第一阶段 SFT 聚焦于自包含推理，第二阶段 SFT 扩展至依赖外部工具推理，RL 阶段则进一步巩固长程推理与智能体-环境交互能力。该范式的设计动机在于解耦能力构建与训练阶段，通过明确的能力递进路径（独立推理 $\rightarrow$ 接地交互 $\rightarrow$ 长程优化）替代传统管线中模糊的多阶段对齐。

### 模型感知的自包含推理数据构造

在第一阶段 SFT 中，Axion 1.0 采用模型感知的数据构造流程，根据基座模型的现有能力动态调整任务难度。具体而言，系统首先从公开题库生成增强问题，若基座模型能正确解答，则随机应用四种难度增强操作之一：组合（Composition）、参数化（Parameterization）、范围偏移（Range Shift）或案例分析（Case Analysis）。这一设计解决了传统数据合成中任务难度与模型能力不匹配导致的训练效率低下问题，确保训练信号始终处于模型的“最近发展区”。

### 确定性工具依赖任务合成

第二阶段 SFT 针对工具依赖推理，通过确定性程序在结构化公开数据库上构建任务。任务构造遵循“过滤-选择-计算-表述”四步流程：首先应用显式条件过滤实体，其次根据属性极值选择唯一实体，接着检索额外属性并计算派生量，最后由 LLM 将逻辑转化为自然语言问题。该流程确保了任务答案的确定性可验证性，避免了 LLM 生成工具任务时常见的幻觉与逻辑不一致问题。

### 基于过程奖励的强化学习优化

RL 阶段采用异步 GRPO 算法，结合结果奖励与过程奖励优化长程轨迹。奖励函数 $R(\tau; y, z)$ 定义为：

$$
R(\tau; y, z) = \begin{cases}
1, & F = 1, \\
\max(0, 0.3P - 0.1(1 - A)), & F = 0.
\end{cases}
$$

其中 $F$ 表示最终答案正确性，$A$ 表示是否提交有效答案，$P$ 表示验证的中间进度。中间进度 $P(\tau; z)$ 按依赖顺序聚合：

$$
P(\tau; z) = \frac{1}{m} \sum_{j=1}^{m} \prod_{\ell=1}^{j} b_\ell(\tau; z)
$$

该公式确保后续步骤仅在所有前置依赖验证通过后才获得信用，解决了多步工具调用中信用分配稀疏与噪声干扰问题，有效抑制了无最终答案的无效探索。

## 实验评估

Axion 1.0 在涵盖通用推理、科学推理、搜索与智能体问题解决的六个基准上进行了评估。基线覆盖包括 Agents-A1、GPT-5.5、GPT-5.6 Sol、Claude Fable 5 等前沿开源与闭源模型。主实验结果显示，Axion 1.0-122B 在 FrontierScience Research 上达到 66.7%，超越 GPT-5.6 Sol 的 63.3%；在 HLE 上达到 59.0%，显著高于 Agents-A1 的 47.6%。

| 模型 | HLE (%) | SEAL-0 (%) | FrontierScience Olympiad (%) | FrontierScience Research (%) |
| :--- | :--- | :--- | :--- | :--- |
| Agents-A1 | 47.6 | 56.4 | 79.0 | 40.0 |
| GPT-5.5 | 52.2 | 42.3 | 78.0 | 26.7 |
| GPT-5.6 Sol | - | 53.2 | 79.0 | 63.3 |
| Axion 1.0-35B | 52.2 | 62.2 | 86.0 | 56.7 |
| Axion 1.0-122B | 59.0 | 58.6 | 87.0 | 66.7 |

消融实验揭示了各训练阶段的边际贡献。第一阶段 SFT 主要提升自包含科学推理能力，如 35B 模型在 FrontierScience Olympiad 上从 71.0% 提升至 83.0%；第二阶段 SFT 显著增强工具依赖任务，35B 模型在 BioMysteryBench 上从 17.6% 跃升至 35.3%。RL 阶段进一步巩固了长程推理，35B 模型在 SEAL-0 上从 53.2% 提升至 62.2%。值得注意的是，RL 对科学推理基准的影响存在模型规模依赖性：122B 模型在 FrontierScience Research 上从 65.0% 提升至 66.7%，而 35B 模型则从 58.3% 微降至 56.7%，表明小模型在 RL 阶段可能面临过拟合或奖励噪声干扰。

评估边界方面，Axion 1.0 未报告在 BFCL 等纯工具编排基准上的表现，其有效性主要验证于“推理+工具”复合任务。此外，HLE 评估限制了部分网站访问，可能低估了模型在开放网络环境下的真实能力。代码与数据构造管线完全开源，提升了可复现性。

## 关联研究分析

从问题动机看，Axion 1.0 与 Tool Zero 均挑战了传统 SFT 冷启动的必要性，但路径截然不同。Tool Zero 试图通过纯 RL 从零训练智能体，依赖动态泛化引导奖励策略；Axion 1.0 则保留了两阶段 SFT 作为能力基座，仅将 RL 用于长程优化。这种差异源于对“基础能力”与“策略优化”边界的理解：Axion 1.0 认为自包含推理与工具调用模式需通过 SFT 显式注入，而 Tool Zero 假设 RL 可自主发现这些模式。Axion 1.0 的稳健性可能源于 SFT 提供的先验，但其在完全未知工具集上的零样本泛化能力是否弱于 Tool Zero，论文未给出回答。

从方法设计看，Axion 1.0 的数据构造策略与 DIVE 的多样化任务合成形成对比。DIVE 侧重于通过自动化管线生成大规模、多样化轨迹以覆盖工具生态；Axion 1.0 则强调“模型感知”的对抗性增强，通过基座模型反馈动态提升任务难度。这种差异反映了数据规模与数据质量的权衡：DIVE 依赖规模效应，Axion 1.0 依赖难度适配。在数据标注成本高昂的背景下，Axion 1.0 的模型感知机制是否能在工具库规模扩大至数万级时保持数据构造效率，论文未给出回答。

## 总结

Axion 1.0 针对智能体训练管线日益复杂化导致的能力增益来源模糊与复现成本高昂问题，提出了一种极简的三阶段训练范式。通过模型感知的自包含推理数据构造与确定性工具任务合成，Axion 1.0 仅凭两阶段 SFT 与 RL 即实现了与前沿商业模型相当的竞争力，在 FrontierScience Research 上达到 66.7%，在 HLE 上达到 59.0%。该工作证明了高质量数据构造可替代部分复杂训练阶段，为智能体训练提供了可复现的极简路径。然而，Axion 1.0 未评估在纯工具编排基准上的表现，且 RL 阶段对小模型科学推理能力的负迁移现象表明，极简管线在模型规模与任务类型上的适用边界仍需探索。当工具库规模扩大至数万级且环境噪声显著增加时，模型感知的数据构造机制是否仍能维持训练信号的稳定性，论文未给出回答。
