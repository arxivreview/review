# HuggingFace最新推荐论文 ｜Mage-VL-Cowork: A Full Training Recipe to Learn Hybrid Computer Use From Evolved Harnesses ｜混合计算机使用智能体

作者：Xiaoyi Zhang、Haoqing Wang、Xinjie Zhang 等 22 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.40747)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.40747)

> 计算机使用智能体（Computer-Use Agents, CUAs）旨在通过像素级截图理解并操作图形用户界面，但纯视觉通道在处理结构化文件时面临高昂的Token成本与低效的重复点击。现有混合方法多依赖多智能体编排或事后工具调用，缺乏在单一策略内对GUI与终端通道的动态路由能力。本文提出Mage-VL-Cowork，通过进化教师模型的外部执行框架（Harness）以获取高质量混合轨迹，并采用五阶段渐进式课程训练，在4B参数规模下实现了GUI与代码执行的深度融合。该工作验证了单策略混合通道在端侧部署中的可行性，但终端操作的安全隔离与长尾场景下的通道路由鲁棒性仍待验证。

## 研究背景

当智能体面对需要批量修改电子表格或解析复杂文档的任务时，纯视觉通道迫使模型通过数十次鼠标点击和截图反馈来推导结果，这一过程不仅消耗数千Token，且极易因界面渲染延迟导致状态误判。这种“像素级重推导”的困境源于GUI通道在抽象层级上的局限：它擅长处理视觉依赖状态，却难以直接操作底层数据结构。为解决此问题，引入终端（Terminal）通道成为自然选择，允许智能体直接调用代码库或命令行工具。然而，简单的工具接入并未带来能力的线性提升，模型往往陷入“通道混淆”，即在应使用代码的场景下仍坚持点击，或在需要视觉确认时盲目执行代码，导致执行效率低下甚至任务失败。

当前领域在混合CUA的研究上存在两条主要路线：一是基于多智能体架构（如CoAct-1），通过编排器分离GUI操作与代码执行，但这引入了通信开销与上下文同步的复杂性；二是基于大规模监督微调（SFT）的后训练范式（如ProCUA），但其通常假设模型已具备较强的基础能力，且数据合成多依赖静态截图或简单的Agent探索，难以覆盖动态应用状态下的复杂交互。本文的切入点在于：如何在单一策略模型内部，通过优化教师模型的执行框架（Harness）而非仅依赖模型权重，来习得高效的通道路由策略，并通过可复用的工作流合成大规模、高一致性的混合交互数据，从而在轻量级模型上实现端到端的混合能力。

## 核心方法

### 方法参照系：单策略混合执行框架

本文解决的问题属于混合计算机使用智能体范畴，其标准流程通常涉及视觉感知、动作规划与执行反馈。与通用CUA流程的关键差异在于，本文在单一策略模型内并行暴露GUI（鼠标/键盘坐标）与Terminal（Shell命令/代码）两个动作空间，要求模型在每一步决策中动态选择最优通道，而非由外部编排器进行任务级路由。

### Harness进化：优化教师模型的混合执行策略

在数据合成阶段，通常做法是直接利用前沿大模型（Teacher）在标准提示下生成轨迹。然而，前沿模型在默认设置下往往表现出次优的通道习惯，如通过GUI点击完成本可由一行代码完成的文件编辑。本文创新性地提出Harness进化机制，将教师模型定义为 $A_T = (M_T, H)$，其中 $H = (F, T, P, E)$ 分别代表执行脚手架、工具接口、系统提示与终端环境。Harness进化通过移除冗余工具（如xdotool）并注入领域库（如python-pptx），优化 $H$ 以最大化任务成功率与Token效率的权衡。这一设计解决了直接蒸馏默认轨迹会继承教师模型通道混淆缺陷的问题，确保生成的监督信号包含清晰的通道路由逻辑。

### Workflow-First数据合成：可复用的任务与环境生成

传统数据合成依赖Agent逐任务探索，成本高且一致性差。本文提出Mage-CUA-Forge，采用“工作流优先”策略。对于每个原子技能，构建包含LLM节点、文件预置器（Preparers）和设置操作的可复用工作流。任务包生成公式可抽象为：

$$ \mathcal{T} = \text{Compose}(\mathcal{W}_{skills}, \mathcal{S}_{spec}) $$

其中 $\mathcal{W}_{skills}$ 为技能工作流集合，$\mathcal{S}_{spec}$ 为统一的任务规范。该机制将一次性构建与重复生成分离，通过共享预置器确保环境状态（如LibreOffice文档内容、Thunderbird邮件库）的确定性初始化。这一创新解决了动态应用状态难以复现导致的评估噪声问题，使得大规模合成293,806个高一致性任务成为可能，且边际成本降低82.6%。

### 五阶段渐进式课程训练：从原子能力到混合路由

现有后训练范式常直接从专用GUI模型起步，忽略了基础编码能力的缺失。本文提出从通用多模态检查点开始的五阶段课程：(1) GUI导向中训练，(2) GUI Agent SFT，(3) 编码与终端SFT，(4) 混合CUA SFT，(5) 在线混合RL。在混合SFT阶段，上下文折叠机制将历史轨迹压缩为动作摘要，公式化表示为：

$$ C_t = \text{Fold}(S_{t-3:t}, R_{t-4:t}, \text{Action}_{1:t-4}) $$

其中 $S$ 为截图，$R$ 为响应。该设计在有限上下文窗口内保留了关键视觉状态与操作历史，解决了长程任务中因上下文溢出导致的历史意图丢失问题，使模型能在单一策略内协调视觉与代码动作。

## 实验评估

实验在OSWorld-Verified基准上进行，该基准包含369个基于真实Web和桌面应用的任务，评估多步推理与交互能力。基线覆盖包括Muse Glimmer-30B、Qwen3.6-27B等开源SOTA及GPT-5.5等前沿模型。Mage-VL-Cowork-4B以66.0%的成功率超越了参数量更大的Muse Glimmer-30B (65.9%) 和 EvoCUA-32B (56.7%)，显示出在4B规模下的显著效率优势。

| 方法 | 参数量 | OSWorld-Verified 成功率 (%) |
| :--- | :--- | :--- |
| Mage-VL-Cowork (Ours) | 4B | 66.0 |
| Muse Glimmer | 30B | 65.9 |
| Qwen3.6 | 27B | 63.9 |
| EvoCUA | 32B | 56.7 |
| Human | - | 72.4 |

消融实验表明，从GUI SFT (45.56%) 到混合SFT (55.84%) 再到最终RL (66.0%)，性能提升20.44个百分点，证实了混合通道与RL对长程任务鲁棒性的贡献。Harness进化带来的工具剪枝与库注入，在蒸馏至4B学生模型时带来了12.5个百分点的增益，验证了优化教师执行框架而非仅依赖模型权重的有效性。然而，论文未提供Terminal通道在总成功率中的具体贡献拆解，也未对比CoAct-1等多智能体架构在同等计算预算下的表现，使得单策略与多策略的效率权衡尚不明确。此外，评估主要依赖LLM作为裁判，可能存在对复杂逻辑判断的偏差。

## 关联研究分析

从问题动机看，Mage-VL-Cowork与CoAct-1均致力于解决纯GUI操作的低效问题，但CoAct-1采用编排器分离GUI与编码Agent，这种架构虽降低了单模型复杂度，却引入了跨Agent通信与状态同步的开销。Mage-VL-Cowork主张单策略内融合，其根源在于认为通道路由是策略学习的一部分，而非外部调度问题。然而，当任务涉及极长序列或高度并行的子任务时，单策略的上下文管理压力是否会导致性能瓶颈，论文未给出回答。

从方法设计看，Mage-CUA-Forge与OS-Genesis均涉及数据合成，但OS-Genesis通过反向任务合成构建GUI轨迹，侧重于视觉定位；Mage-CUA-Forge则通过可复用工作流构建包含应用状态与文件预置的混合环境，侧重于操作逻辑的确定性。这一差异源于混合CUA对“环境状态”定义的扩展：从静态截图扩展至动态应用内部状态。若将Mage-CUA-Forge的工作流机制应用于纯GUI基准，是否能同样降低数据成本并提升泛化性，论文未进行跨域验证。

## 总结

本文针对纯视觉CUA在结构化操作上的低效与混合通道路由困难的核心矛盾，提出通过进化教师Harness与Workflow-First数据合成，在4B模型上实现了端到端的混合计算机使用能力。Mage-VL-Cowork在OSWorld-Verified上达到66.0%的成功率，超越了参数量更大的开源模型，证明了单策略混合通道在端侧部署中的潜力。其边界在于对Terminal操作的安全沙箱隔离机制讨论不足，且未量化混合通道中代码执行的具体贡献比例。当面对需要严格权限控制或涉及不可逆系统修改的真实部署场景时，单策略模型如何在不牺牲效率的前提下保证终端操作的安全性，仍是一个亟待验证的问题。
