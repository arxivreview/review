> 导读 混合专家（Mixture-of-Experts, MoE）架构通过稀疏激活机制解耦模型容量与计算成本，但单个专家的具体功能分工仍不清晰。现有分析依赖人工预设的领域标签统计路由频率，受限于分类粒度粗糙且无法区分表面属性与深层特征贡献。本文提出在特征空间研究专家分工，利用稀疏自编码器（Sparse AutoEncoder, SAE）的仿射编码特性，将 MoE 层输出精确分解为各专家的贡献。该方法揭示了模型内部存在远超领域标签粒度的专业化分工，如区分 Java 与前端代码专家。这一发现为 MoE 的压缩与负载均衡提供了基于特征贡献的新视角，但高贡献纯度是否等同于下游任务不可替代性，仍需进一步验证。

## 研究背景

当 MoE 模型处理输入时，路由网络将每个 Token 分配给少数专家，使得模型在保持单 Token 计算成本接近稠密模型的同时，大幅扩展了参数容量。然而，这种稀疏激活机制导致专家的具体职责成为黑盒。传统分析通常统计专家在带有领域标签（如代码、数学）的语料库上的激活频率，以此推断专家是否具备领域专业化。这种方法的局限在于，领域分类由分析者预设，粒度远粗于模型内部数十至数百个专家的分工；且激活频率仅记录专家是否被选中，忽略了路由权重，无法反映专家对层输出的实际功能贡献。

为突破这一瓶颈，研究重心从外部标签匹配转向模型内部特征空间的解析。稀疏自编码器（SAE）通过字典学习将模型的高维激活映射到稀疏、单义的特征空间，其编码过程是仿射的。这一特性恰好与 MoE 层输出为专家加权和的结构相契合，使得每个潜在特征（Latent）的激活可以精确分解为各个专家的贡献。本文正是利用这一数学性质，在 Qwen3-30B-A3B 模型上构建了专家与特征之间的贡献图谱，从而在不预设分类体系的前提下，量化单个专家在模型特征空间中的具体功能。

## 核心方法

### 专家贡献的精确分解

在标准 MoE 架构中，层输出 $y(t)$ 是激活专家输出 $u_j(t)$ 的加权和，权重由路由网络给出。本文引入 SAE 对该输出进行编码，由于 SAE 编码器是仿射变换，潜在特征 $i$ 的激活值 $f_i(t)$ 可精确分解为各专家贡献之和。这一分解是本文方法的核心基石，它使得分析从“谁被选中”转向“谁贡献了多少”。

$$ f_i(t) = \sum_{j \in A(t)} g_j(t) W_{\text{enc},(i)} \cdot u_j(t) + b_{\text{enc},(i)} $$

该公式表明，潜在特征的激活由路由权重 $g_j(t)$、编码器权重 $W_{\text{enc},(i)}$ 与专家输出 $u_j(t)$ 的内积共同决定。通过提取正贡献部分并归一化，本文定义了专家 $j$ 对潜在特征 $i$ 在特定上下文中的贡献分数 $C(j, i, x_{1:t})$。这一设计解决了传统路由频率分析无法区分“被选中但贡献微小”与“被选中且主导输出”的缺陷，提供了功能层面的量化指标。

### 支配图与专家分工量化

基于贡献分数，本文在语料库上聚合得到专家对潜在特征的平均贡献 $C(j, i)$，并进一步归一化为贡献占比 $s(j, i)$。当 $s(j, i)$ 超过阈值 $\tau$ 时，定义专家 $j$ “支配”潜在特征 $i$。所有支配关系构成一个二部图，即支配图（Dominance Graph）。

$$ s(j, i) = \frac{C(j, i)}{\sum_{j'=1}^{N} C(j', i)} $$

该公式计算了专家 $j$ 对潜在特征 $i$ 的相对重要性。通过设定阈值 $\tau=0.2$，本文提取出每个专家的“支配集”（Dominant Set），即该专家主要驱动的潜在特征集合。这一设计将专家分工从模糊的领域标签转化为具体的特征集合，使得专家的功能可以通过其支配的潜在特征来解释。实验发现，贡献分布高度集中，大多数潜在特征仅由一到两个专家支配，且专家间的支配集重叠极少，证明了模型内部存在高度专业化的分工结构。

## 实验评估

本文在 Qwen3-30B-A3B 模型的第 4、30、46 层上训练 SAE，并在 1.5B Token 的验证集上计算贡献统计。实验主要验证了贡献分布的集中度、专家分工的细粒度以及领域分配的不均衡性。

| 指标 | 第 4 层 | 第 30 层 | 第 46 层 |
| :--- | :--- | :--- | :--- |
| 平均 Jaccard 相似度 | $1.73 \times 10^{-3}$ | $1.57 \times 10^{-3}$ | $2.12 \times 10^{-3}$ |
| 中位数 Jaccard 相似度 | $1.06 \times 10^{-4}$ | $1.01 \times 10^{-4}$ | $1.37 \times 10^{-4}$ |
| 无共享潜在特征的专家对比例 | 37.8% | 40.5% | 37.5% |
| 前 10% 专家对承载的交集比例 | 83.8% | 78.5% | 81.0% |

上表显示，专家支配集的重叠度极低，中位数 Jaccard 相似度仅为 $10^{-4}$ 量级，且大部分交集集中在少数专家对之间。这表明专家分工高度独立，仅在特定功能相近的专家间存在协作。

在细粒度分工验证中，本文通过 GPT-5.5 对专家支配集的潜在特征进行解释。例如，第 30 层的专家 50 被识别为 Java 专家，其支配集中 86.7% 的潜在特征与 Java 开发相关，而随机基线仅为 1.9%。专家 57 则专注于前端 Web 开发。这一结果证明，模型内部的分工粒度远细于“代码”这一粗粒度领域标签，而是细化到具体的编程语言或框架。

评估边界方面，本文未直接对比下游任务性能（如 MMLU），而是通过特征解释的纯度验证方法有效性。此外，SAE 训练成本高昂，且分析依赖于 GPT-5.5 的解释能力，可能存在解释偏差。

## 关联研究分析

从问题动机看，本文与 Switch Transformer 等架构优化工作形成互补。Switch Transformer 关注如何通过 Top-1 路由降低通信开销，假设专家功能可互换；而本文揭示专家功能高度专业化且不可互换，这暗示了强制负载均衡可能损害模型性能，因为将 Token 路由到非主导专家会导致贡献稀释。

从方法设计看，本文与 PuzzleMoE 等压缩方法存在逻辑关联。PuzzleMoE 通过合并专家来减少冗余，其有效性依赖于专家间存在功能重叠。本文发现专家支配集重叠极少，仅在少数专家对间存在协作，这为压缩策略提供了理论依据：仅合并高重叠专家对可能比全局合并更有效。然而，本文未验证高贡献纯度是否意味着专家在剪枝后不可替代，这一假设仍需实验支撑。

## 总结

本文针对 MoE 专家功能黑盒问题，提出利用 SAE 的仿射特性将层输出精确分解为专家贡献，从而在特征空间量化专家分工。实验证明，专家分工粒度远细于领域标签，如区分 Java 与前端代码，且贡献分布高度集中。这一发现挑战了传统基于领域标签的分析范式，为 MoE 的压缩与负载均衡提供了基于特征贡献的新视角。然而，本文未验证高贡献纯度与下游任务性能之间的直接因果关系，当专家被剪枝或合并时，其支配的潜在特征是否会导致模型性能显著下降，仍需进一步实验验证。
