> 导读：LLM 引导的进化搜索旨在通过迭代优化程序解决数学与科学计算难题，但现有框架因依赖冗长的文本思维链导致计算成本高昂、搜索规模受限。SwarmEvolve 提出在潜在空间进行推理与通信，利用 KV Cache 传递隐藏状态替代文本生成，从而大幅提升吞吐量。该框架通过新颖性过滤器维持种群多样性，并在同等算力下以 8B 模型超越前沿大模型的部分结果。其核心价值在于验证了潜在空间交互在程序搜索中的高效性，但潜在推理的可解释性缺失仍是应用瓶颈。

## 研究背景

当进化算法用于程序搜索时，LLM 充当变异与交叉算子，通过生成候选程序并评估其性能来迭代优化解。这一过程通常依赖 LLM 生成显式的文本思维链（Chain-of-Thought, CoT）以指导代码修改。然而，文本生成不仅耗时，且随着种群规模扩大和评估反馈累积，上下文窗口迅速膨胀，导致推理延迟高、GPU 资源消耗大。这种“文本瓶颈”限制了进化搜索在开放科学问题上的规模扩展，使得许多需要大规模并行探索的问题难以在有限时间内收敛。

现有主流框架如 OpenEvolve、ShinkaEvolve 和 CodeEvolve 均遵循“文本推理-代码生成-评估”的标准流程。尽管部分工作尝试通过并行轨迹或强化学习微调来加速，但核心瓶颈未变：LLM 必须将内部推理状态解码为离散 Token，再重新编码为文本输入给下一环节。这一往返转换不仅引入了显著的序列化开销，还因文本表达的离散性损失了部分连续推理空间的细微信息。SwarmEvolve 针对这一痛点，提出让代理直接在连续嵌入空间推理，并通过键值缓存（KV Cache）共享潜在状态，从而绕过文本编解码环节，实现低成本、高吞吐的进化搜索。

## 核心方法

### 潜在推理与 KV Cache 通信机制

传统 LLM 智能体通过采样离散 Token 进行推理，而 SwarmEvolve 采用潜在推理（Latent Reasoning），将上一层的隐藏状态直接映射为下一层的输入嵌入，无需解码文本。这一机制基于 LatentMAS 框架，通过岭回归求解对齐矩阵 $W_a$，将输出隐藏状态 $h_t$ 映射回输入嵌入空间 $e_{t+1}$：

$$ e_{t+1} = \gamma \frac{W_a h_t}{\|W_a h_t\|}, \quad W_a = (W_{out}^\top W_{out} + \rho I)^{-1} W_{out}^\top W_{in} $$

其中 $\gamma$ 为词表嵌入平均范数，$W_{in}$ 和 $W_{out}$ 分别为输入和输出嵌入矩阵。该公式的物理含义是：通过线性变换将高维语义空间中的推理状态“投影”回输入空间，使模型能在连续向量空间中执行多步逻辑推演，避免了离散 Token 采样带来的信息损失和计算延迟。每个潜在推理步骤仅增加一个位置到 KV Cache，极大降低了序列长度。

### 基于隐藏状态的新颖性过滤

在进化搜索中，维持种群多样性至关重要，但传统方法依赖外部嵌入模型或 LLM 判断器来去重，成本高昂。SwarmEvolve 利用潜在推理产生的隐藏状态直接计算多样性。每个代理在 40 步潜在推理后，其状态表示为平均隐藏状态 $\bar{h}_j$：

$$ \bar{h}_j = \frac{1}{40} \sum_{t=1}^{40} h_{j,t} $$

随后，系统计算各代理状态与群体均值 $\mu$ 的归一化偏差向量 $z_j$，并通过贪心最远点选择算法保留余弦距离最大的 30 个代理。这一设计动机在于：潜在空间中的几何距离直接反映了推理路径的差异性，无需额外模型即可高效筛选出最具创新性的变异个体，解决了传统文本去重方法在大规模并行搜索中的效率瓶颈。

### 潜在空间交叉与程序生成

SwarmEvolve 的交叉操作发生在潜在空间而非文本层面。每个 Swarm 的总结器（Summarizer）代理接收其保留的 30 个潜在代理的 KV Cache，以及父程序的 KV Cache。总结器的 KV Cache 构造为：

$$ K^{(\ell)} = [K^{(\ell)}_{prob}; K^{(\ell)}_1; \dots; K^{(\ell)}_{30}; K^{(\ell)}_{p1}; \dots; K^{(\ell)}_{ins}] $$

其中 $K^{(\ell)}_j$ 为第 $j$ 个潜在代理的键，$K^{(\ell)}_{p1}$ 为父程序的键。通过旋转位置编码（RoPE）调整各缓存块的相对位置，总结器在注意力机制中直接融合多个潜在推理轨迹的信息，最终解码生成一个新程序。这种机制实现了“潜在交叉”：不同代理的推理特征在注意力层自然混合，无需显式的文本重组，从而在保留语义连贯性的同时提升了组合效率。

## 实验评估

SwarmEvolve 在 21 个数学发现与科学计算问题上与 OpenEvolve、ShinkaEvolve 和 CodeEvolve 进行对比。实验使用 Qwen3 8B、14B 和 32B-FP8 模型，在单 GPU 上运行 60 分钟。评分定义为相对于 AlphaEvolve 发布解的归一化得分，大于 1 表示超越 AlphaEvolve。

| 模型 | 框架 | 平均得分 |
| :--- | :--- | :--- |
| Qwen3 8B | OpenEvolve | 0.693 |
| Qwen3 8B | ShinkaEvolve | 0.642 |
| Qwen3 8B | CodeEvolve | 0.700 |
| **Qwen3 8B** | **SwarmEvolve** | **0.804** |
| Qwen3 32B-FP8 | OpenEvolve | 0.774 |
| Qwen3 32B-FP8 | ShinkaEvolve | 0.733 |
| Qwen3 32B-FP8 | CodeEvolve | 0.731 |
| **Qwen3 32B-FP8** | **SwarmEvolve** | **0.869** |

SwarmEvolve 在所有模型规模下均取得最高平均分。值得注意的是，Qwen3 8B 驱动的 SwarmEvolve（0.804）超越了所有基线框架在 Qwen3 32B-FP8 下的表现（最高 0.774），表明潜在空间推理显著提升了小模型的计算效能。此外，SwarmEvolve 在 15 分钟内的平均最佳得分已高于基线框架 60 分钟的平均值，且每小时评估的程序数量是基线的 5 至 13 倍。

在消融实验方面，将潜在推理替换为文本推理会导致得分下降，验证了潜在空间操作的核心贡献。SwarmEvolve 在 26 个圆填充正方形问题中达到已知最佳半径和 2.635983，并在两个自相关不等式问题上改进了 AlphaEvolve 的界限。然而，实验未提供置信区间，且基线框架未针对潜在空间优化进行适配，可能存在实现偏差。评估协议依赖 AlphaEvolve 的解作为基准，限制了在更广泛开放问题上的泛化性验证。

## 关联研究分析

从问题动机看，SwarmEvolve 与 Reflexion 均致力于通过反馈优化智能体行为，但二者在信息载体上存在本质差异。Reflexion 依赖文本反思，将失败经验转化为自然语言提示，受限于文本表达的模糊性和上下文窗口；SwarmEvolve 则通过 KV Cache 传递连续隐藏状态，保留了推理轨迹的细微语义差异，更适合需要精确数值优化的程序搜索任务。这种差异源于任务特性：数学发现需要高精度的逻辑推导，而文本反思易引入噪声。

从方法设计看，SwarmEvolve 与 AutoGen 均涉及多代理协作，但通信机制截然不同。AutoGen 通过文本消息进行角色间协调，存在序列化开销和状态同步延迟；SwarmEvolve 通过共享 KV Cache 实现潜在状态融合，消除了文本编解码瓶颈。然而，AutoGen 的文本交互提供了天然的可解释性，便于人类调试；SwarmEvolve 的潜在交互则牺牲了可解释性，导致难以诊断进化失败的具体原因。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

SwarmEvolve 针对 LLM 进化搜索中的文本推理瓶颈，提出在潜在空间进行推理与通信的框架，通过 KV Cache 共享和隐藏状态新颖性过滤，实现了高吞吐、低成本的程序优化。实验表明，该框架在同等算力下将吞吐量提升 5 至 13 倍，且 Qwen3 8B 模型的平均得分（0.804）超越基线框架在 32B 模型下的表现。其边界在于潜在推理的黑盒特性导致可解释性缺失，且评估局限于特定数学基准。当潜在空间推理应用于需要严格逻辑验证的自然语言推理任务时，其稳定性与可解释性如何平衡，仍是一个待验证的问题。
