> 导读 离线边缘设备上的检索增强生成（Retrieval-Augmented Generation, RAG）系统依赖预计算向量以规避高昂的本地计算开销，但数字签名仅能证明发布源身份，无法保证向量与文本的语义绑定。现有防御机制多聚焦于在线API的文本级投毒检测，未能覆盖离线供应链中攻击者通过篡改向量操纵检索结果的攻击面。本文提出“边际定律”量化容差验证的暴露风险，并设计代码级验证机制实现向量与文本的精确绑定。该研究填补了离线RAG系统向量完整性验证的空白，但其对硬件计算确定性的强依赖限制了在异构加速平台上的普适性。

## 研究背景

当边缘设备部署RAG系统时，本地计算嵌入向量的延迟极高（如在Raspberry Pi 5上处理950个文本块需29分钟），迫使系统依赖包含预计算向量的知识包。数字签名机制可验证知识包的来源与版本，但无法验证向量是否真实编码了对应文本。攻击者若控制发布管道或作为内部人员，可发布文本合规但向量被恶意篡改的知识包，从而在检索阶段操纵结果。

现有RAG安全研究主要关注在线API场景下的文本级投毒与隐私泄露，防御手段多基于文本语义过滤或鲁棒聚合。然而，离线场景下的攻击面从文本内容转移至向量数据本身，文本级防御对此类“文本-向量解耦”攻击完全失效。本文针对这一被忽略的供应链完整性缺口，研究如何在不依赖网络连接的受限硬件上，验证预计算向量与文本的绑定关系。

## 核心方法

### 容差验证的几何失效与边际定律

在向量数据库的完整性审计中，验证器通常采用容差机制：接受与重计算向量余弦相似度高于阈值 $\tau$ 的预计算向量。该做法的基准假设是，容差可吸收浮点噪声与量化误差，同时阻断恶意篡改。本文指出，该假设忽略了检索决策的几何特性：检索结果由查询向量与候选向量间的微小角度差决定。

本文提出“边际定律”（Margin Law）量化容差验证的暴露风险。定义查询向量 $q$ 与真实文档向量 $g$ 的夹角为 $\theta_g$，与最近非相关文档向量 $c$ 的夹角为 $\theta_c$，则角度边际 $m(q) = \theta_c - \theta_g$。当验证器容差对应的角度为 $\alpha = \arccos \tau$ 时，最优攻击者将非相关向量向查询向量旋转 $\alpha$ 角度。劫持率（Hijack Rate, HR）等于角度边际小于容差角度的查询比例：

$$ HR(\tau) = \frac{1}{|Q|} \sum_{q \in Q} \mathbb{I}(m(q) < \arccos \tau) $$

该公式表明，容差验证的劫持率完全由诚实数据的角度边际分布决定。由于实际语料库中检索边际极小（中位数仅为 2.1°–7.4°），即使是吸收浮点噪声的极小容差，也会将大量查询暴露给攻击者。

### 代码级验证与规范化机制

针对容差验证的几何失效，本文提出代码级验证（Code-level Verification）机制，将验证对象从连续向量空间转移至离散量化代码空间。该机制的基准做法是直接比较存储向量与重计算向量，而本文创新在于：验证器仅信任自身重计算并量化后的代码，拒绝使用发布者的浮点向量。

对于标量量化（SQ）、乘积量化（PQ）或二值化存储，验证器计算自身代码 $c$。当重计算值处于量化边界附近时，标记为“模糊”（ambiguous），并允许存储代码等于相邻代码 $a$。验证通过后，执行“规范化”（Canonicalisation），即用验证器自身的代码覆盖存储代码。该设计消除了容差带来的攻击预算，将验证转化为精确的离散匹配问题，在提供确定性完整性保证的同时，避免了同态加密等强隐私保护机制带来的高昂计算开销。

## 实验评估

实验在 Raspberry Pi 5、桌面级 GPU 及 Apple M2 平台上进行，使用 SQuAD 2.0、BEIR 等数据集，评估了不同容差阈值下的劫持率及端到端攻击影响。

| 存储格式 | 最大诚实重构角度 | 容差审计暴露率 (HR) |
| :--- | :--- | :--- |
| FP16 | 0.03° | 0–5.2% |
| SQ8 | 0.35–0.56° | 2.0–14.5% |
| SQ4 | 5.8–9.6° | 55–89% |
| PQ | 23–40° | 99.7–100% |
| Binary | 41–47° | 100% |

实验数据证实了边际定律的预测：随着存储格式压缩率增加，重构误差扩大，容差审计的暴露率急剧上升。在乘积量化（PQ）和二值化存储中，为吸收诚实重构误差而设置的容差，导致几乎所有查询（99.7–100%）面临被劫持的风险。在针对真实 FAISS 索引的端到端攻击中，所有篡改向量均通过容差检查，并使攻击者文档在 25% 的目标查询中排名第一。

在消融与设计决策方面，本文验证了代码级验证的有效性。在三个平台与四种计算后端上，代码级验证接受了所有诚实向量，并成功拦截了所有篡改代码。然而，实验暴露了严格的评估边界：代码级验证依赖推理管道的位级可重现性。实验发现，PyTorch 和 ONNX Runtime 的 FP32 及动态 INT8 推理在不同批次大小和架构（x86 与 ARM）间存在非确定性偏差，这要求部署环境必须使用整数推理或经过严格校准的容差带，限制了该机制在通用异构硬件上的直接应用。

## 关联研究分析

从问题动机看，本文与 PoisonedRAG 均针对 RAG 系统的检索操纵，但攻击面存在根本差异。PoisonedRAG 通过优化文本内容使其在检索时被优先选中，防御手段可通过文本语义过滤或鲁棒聚合实现。本文攻击者无需修改文本，仅操纵向量，直接绕过了所有基于文本内容的审查机制。这一差异表明，在离线供应链场景下，针对文本的防御体系存在结构性盲区。

从方法设计看，本文与 PRA-RAG 均提供可证明的鲁棒性保证，但技术路径不同。PRA-RAG 采用可证明鲁棒聚合策略，量化投毒内容对生成结果的影响，适用于多源在线检索场景。本文则通过精确的代码级验证消除投毒可能，适用于单源离线知识包场景。查询侧增强或鲁棒聚合在数据充足时是否仍有增益，论文未给出回答，但本文的精确验证在离线受限环境下提供了更强的确定性保证。

## 总结

本文针对离线 RAG 系统中签名有效但向量-文本绑定失效的供应链完整性缺口，提出边际定律量化容差验证风险，并设计代码级验证机制实现精确绑定。实验证明，在乘积量化存储下，容差审计的暴露率高达 99.7–100%，而代码级验证可完全拦截篡改攻击。该研究的边界在于对硬件计算确定性的强依赖，实验证实通用浮点与动态量化推理存在跨架构非确定性。当部署环境包含非确定性神经处理单元（NPU）时，如何在不牺牲检索精度的前提下实现代码级验证的位级可重现性，是该机制走向实际部署必须跨越的障碍。
