# HuggingFace最新推荐论文 ｜Interpreting Coding Agents Through Their Behavioral Trajectories ｜基于行为轨迹归一化的编码智能体过程评估

作者：Ibragim Badertdinov、Alexander Golubev

论文原文见 [arXiv](https://arxiv.org/abs/2611.17440)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2611.17440)

> 导读 编码智能体基准通常将复杂的多步交互简化为二元结果，即是否通过测试，这种黑盒评估掩盖了产生结果的具体行为模式。现有方法虽关注过程分析，但受限于异构执行轨迹的格式差异，难以在跨模型、跨脚手架的大规模场景下进行统一比较。本文提出一种确定性规则解析器，将异构轨迹映射为统一的高层动作分类法，并引入结果匹配对设计以隔离性能差异。该工作填补了跨栈行为量化分析的空白，为理解智能体决策逻辑提供了新维度，但行为画像的稳定性是否受任务分布影响仍需进一步验证。

## 研究背景

当智能体在真实代码仓库中执行任务时，其内部决策逻辑通过一系列工具调用（如文件读取、代码编辑、测试执行）外化为执行轨迹。然而，不同脚手架（Scaffolding Harness）暴露的工具接口、命令格式及记录模式存在显著差异，导致原始轨迹在语义层面高度异构。这种异构性使得直接基于工具名称或原始命令的跨系统比较失效，因为实现细节混淆了语义动作。为了在统一坐标系下分析智能体行为，需要一种能够剥离实现细节、捕捉核心意图的共享表示。

领域内对编码智能体的评估长期依赖 SWE-bench 等基准的二元解决率，这一指标虽便于排名，却无法揭示不同模型或架构在探索、修改和验证策略上的差异。尽管近期研究开始关注过程级分析，如阶段标记或失败诊断，但多局限于单系统或特定失败案例，缺乏跨栈的大规模对比。本文切入点在于构建一个跨系统的行为归一化框架，通过解析 143,209 条执行轨迹，揭示在解决率相近的情况下，智能体行为模式的显著分歧，从而将评估从“结果导向”推向“过程导向”。

## 核心方法

### 异构轨迹的动作归一化

本文方法置于轨迹分析（Trajectory Analysis）的通用流程下，其核心差异在于处理异构性的策略。传统方法通常针对特定脚手架定制解析逻辑，而本文开发了一个确定性规则解析器，将原始执行事件映射为统一的高层动作分类法。该解析器将每个工具调用与其执行输出配对，并分类为四个核心属性：主要操作（Primary Operation）、目标文件角色（Target File Role）、变异类型（Mutation Type）和读取模式（Read Mode）。

主要操作将动作归类为探索、搜索、文件读取、文件变异、正式测试执行等十类。目标文件角色通过路径启发式规则（如 `tests/`, `conftest`）区分测试文件与非测试仓库文件。变异类型区分创建、编辑、删除等操作。读取模式区分直接读取与视口延续。这一设计解决了此前方法因依赖特定工具名称而无法跨系统比较的失效问题，使得不同脚手架下的行为可在同一语义空间中对齐。

### 结果匹配对与行为分离度量化

在归一化动作的基础上，本文引入结果匹配对（Outcome-Matched Pair）设计，以隔离性能差异对行为分析的影响。该设计比较共享相同脚手架但基础模型不同的配置对，要求其在至少 50 个共享任务上的解决率差异 $|\Delta \text{solve}| \le 1.0$ 个百分点。为了区分真实的行为差异与运行间的随机波动，本文建立了分裂半空对照（Split-half Null Control）。对于每个栈，将其多次运行轨迹随机分为两半，计算同一配置两半之间的行为差异作为经验零假设基线。

行为分离度通过任务配对的 95% 自助法置信区间（Bootstrap Confidence Interval）是否排除零来判定。若两个不同配置在至少 $k$ 个工作流指标上分离，且该分离在空对照中极少发生，则认定存在显著行为差异。这一机制解决了此前研究无法区分“模型能力差异”与“运行随机性”导致的伪差异问题，确保了行为对比的统计严谨性。

### 行为画像的跨域检索

为了验证行为画像的判别力，本文构建了低维行为特征向量，并测试其在未见环境中的检索能力。特征向量包含四个归一化动作坐标（探索、文件读取、非测试仓库写入、正式测试调用）和四个序列验证特征（归一化熵、工具切换率、写入后工作区检查、未验证终止）。这些特征严格排除了解决结果、总动作数、Token 量和原生工具名称。

检索协议采用余弦最近邻匹配。在跨仓库设置中，将 413 个 Python 仓库分为两个不相交的子集，评估 111 个栈在分裂集上的检索性能。在跨语言设置中，评估 16 个栈在 Go、Java、Python、Rust 和 TypeScript 五种语言上的表现。这一设计旨在验证行为签名是否独立于具体任务内容和编程语言，从而证明其作为部署栈指纹的稳定性。

## 实验评估

实验基于 SWE-rebench 数据集，包含 143,209 条执行轨迹，覆盖 125 个智能体配置和 117 个基础模型。解析器通过六模型共识面板在 500 个动作样本上进行审计，主要操作的一致率为 82.4%，读取模式为 96.6%。

| 分离指标数 | 分裂半空对照 (%) | 匹配对 ($|\Delta| \le 1$ pp) (%) |
| :--- | :--- | :--- |
| $\ge 1$ metric | 30.53 | 100.00 |
| $\ge 2$ metrics | 6.40 | 100.00 |
| $\ge 3$ metrics | 0.78 | 96.70 |

在结果匹配对分析中，60/60 的对在至少两个工作流指标上分离，58/60（96.7%）在至少三个指标上分离。相比之下，同一配置的空对照中，$\ge 3$ 指标分离仅发生在 0.78% 的情况下。这表明即使解决率几乎相同，智能体在探索比例、测试频率等操作模式上存在显著且可复现的差异。

| 特征表示 | 跨仓库 Top-1 (%) | 跨仓库 Top-3 (%) | 跨语言 Top-1 (%) | 跨语言 Top-3 (%) |
| :--- | :--- | :--- | :--- | :--- |
| 完整行为画像 | 85.1 | 96.8 | 90.3 | 98.8 |
| 动作坐标子集 | 62.6 | 86.5 | 87.5 | 98.4 |

在跨仓库检索中，完整行为画像的 Top-1 召回率为 85.1%，远高于 0.9% 的随机基线。跨语言检索中，Top-1 召回率为 90.3%，高于 6.25% 的随机基线。这表明行为画像具有极强的栈识别能力，且这种能力在不同编程语言间保持稳健。

评估边界方面，本文未报告置信区间，且跨仓库检索未完全控制任务组成差异，这可能影响行为签名的独立性解释。此外，解析器对复杂脚本（如内联 Python）的语义捕捉依赖规则匹配，其鲁棒性在极端异构场景下有待验证。

## 关联研究分析

从问题动机看，本文与 AgentLens（Sahoo et al., 2026）均关注过程轨迹，但 AgentLens 侧重于单系统内的“幸运通过”检测，旨在识别结果正确但过程错误的案例；而本文侧重于跨系统的行为模式对比，旨在揭示不同栈在解决相同问题时的策略差异。AgentLens 的局限在于其分析范围局限于单一评估协议，无法回答“不同脚手架如何改变模型行为”这一更宏观的问题。本文通过大规模跨栈分析，将过程评估从诊断工具提升为系统比较工具。

从方法设计看，本文与 SWE-agent（Yang et al., 2024）形成互补。SWE-agent 定义了 Agent-Computer Interface (ACI) 的标准交互范式，强调工具封装对性能的影响；本文则通过解析 SWE-agent-like 与其他脚手架（如 Claude Code）的轨迹，量化了 ACI 设计对动作分布的具体影响。例如，在 Claude Code 栈中，92.4% 的编辑使用原生 API，而在 SWE-agent-like 栈中，模型更依赖 Shell 重定向。这种差异揭示了脚手架不仅是接口，更是行为塑造者。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文针对编码智能体评估中“结果掩盖过程”的核心矛盾，提出了基于规则解析器的轨迹归一化方法，通过结果匹配对设计隔离性能差异，实现了跨栈行为的大规模对比。实验证明，解决率相近的智能体在探索、编辑和验证模式上存在显著差异，且行为画像能跨仓库和语言以 85.1% 的 Top-1 准确率识别部署栈。本文的边界在于未完全控制任务组成对行为签名的潜在混淆，且解析器对复杂脚本的语义理解依赖启发式规则。当行为画像的判别力部分源于任务难度分布而非策略本身时，如何进一步解耦任务效应与行为效应，是后续研究需解决的关键问题。
