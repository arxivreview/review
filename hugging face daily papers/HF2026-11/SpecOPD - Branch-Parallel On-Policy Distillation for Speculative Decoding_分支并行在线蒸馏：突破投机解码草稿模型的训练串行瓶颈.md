> 投机解码通过“草稿-验证”范式打破自回归生成的串行瓶颈，其加速上限取决于草稿模型与目标模型的分布对齐程度。现有在线蒸馏方法虽能提升接受率，但依赖串行草稿-验证轨迹收集，导致训练阶段 GPU 利用率低下且更新缓慢。SpecOPD 提出分支并行在线蒸馏框架，在参考锚点处并行采样独立草稿分支，并通过共享前缀计算实现高效目标监督。该工作显著提升了并行草稿模型的训练吞吐与接受长度，但在高并发场景下的加速增益衰减及长上下文适配性仍存疑。

## 研究背景

当大语言模型（Large Language Model, LLM）在低并发场景下推理时，内存带宽成为主要瓶颈，导致算术强度不足。投机解码（Speculative Decoding, SD）通过引入轻量级草稿模型并行预测候选 token，再由目标模型单次并行验证，将串行解码转化为并行验证，实现无损加速。然而，草稿模型的质量直接决定接受长度（Acceptance Length, AL），进而决定加速比。早期研究多采用独立小模型或特征对齐自回归草稿，但独立模型分布对齐困难，自回归草稿仍受限于逐 token 生成的串行开销。并行草稿模型（如 DFlash）通过单次前向传播预测整个块，消除了草稿阶段的串行瓶颈，但其训练效率成为新的制约因素。

在线蒸馏（On-Policy Distillation, OPD）通过让草稿模型采样自身策略下的历史，并由目标模型提供密集监督，有效突破了监督微调（Supervised Fine-Tuning, SFT）的接受率平台期。然而，传统 SD 定制的 OPD 流程（如 Draft-OPD）需要执行完整的串行草稿-验证轨迹：草稿模型生成块，目标模型验证，接受的前缀决定下一轮起点。这种依赖关系使得监督收集过程串行化，导致训练期间 GPU 利用率低（实测仅 26.37%），且更新吞吐量受限。SpecOPD 的核心洞察在于：在线监督无需继承完整响应的串行依赖，草稿块仅需其参考前缀和草稿采样历史即可被监督。这一发现为解耦监督收集与完整轨迹 rollout 提供了理论基础。

## 核心方法

### 方法参照系：串行轨迹收集与并行草稿的冲突

在标准 SD 训练流程中，草稿模型通常通过 SFT 或离线蒸馏对齐目标模型分布。在线蒸馏旨在优化草稿模型在其自身采样分布上的表现，以最大化推理时的接受率。标准流程要求草稿模型自回归生成候选序列，目标模型验证并反馈接受状态，以此构建训练数据。对于并行草稿模型，虽然推理时块生成是并行的，但训练时的在线数据收集仍遵循“生成-验证-更新”的串行循环。SpecOPD 针对这一痛点，将在线监督从完整响应 rollout 中解耦，利用预收集的参考响应作为共享主干，在锚点处并行采样分支，从而在保持在线策略特性的同时消除收集阶段的串行依赖。

### 提案树构建与分支并行采样

SpecOPD 首先构建提案树以组织并行监督数据。给定目标模型生成的参考响应 $x$，随机采样 $B$ 个锚点位置 $A$。在每个锚点，当前草稿模型 $q_\theta$ 并行采样长度为 $W$ 的草稿分支 $y_{b,1:W}$。分支内的采样依赖前序 token，但不同分支间相互独立。分支 $b$ 在位置 $i$ 的采样分布定义为：

$$
y_{b,i} \sim q_\theta(\cdot | h_{b,i}), \quad h_{b,i} = (x_{\le a_b}, y_{b,<i})
$$

其中 $h_{b,i}$ 由参考前缀 $x_{\le a_b}$ 和该分支已采样的历史 $y_{b,<i}$ 组成。由于分支间无依赖，联合分布可分解为独立乘积，允许并行收集。这一设计将监督上下文从“完整验证轨迹”简化为“参考前缀+草稿历史”，使得目标模型无需等待完整响应生成即可对每个分支位置进行评分。

### 异构注意力机制下的共享前缀评分

为高效计算目标模型 $p$ 在分支历史 $h_{b,i}$ 下的分布，SpecOPD 复用参考主干的 KV 缓存，并针对三种主流注意力机制设计分支历史保留策略。对于全注意力（如 GQA），采用树注意力掩码 $M_{u,v}$，限制每个查询仅关注其祖先节点，防止未来 token 或兄弟分支泄露：

$$
M_{u,v} = \begin{cases} 0, & v \in \text{Anc}(u) \cup \{u\} \\ -\infty, & \text{otherwise} \end{cases}
$$

对于稀疏注意力（如 QSA），通过分支一致的索引器组（Indexer Groups）保留块选择逻辑，共享完整前缀组，仅重建分支特定部分。对于线性注意力（如 GDN），由于掩码无法隔离递归状态，采用索引状态重放（Indexed State Replay）：从检查点恢复锚点状态 $S_{c_b}$，并并行推进各分支的递归更新 $S_{b,j} = F(S_{b,j-1}, z_{b,j})$。这一机制在共享前缀计算的同时，精确保留了每个分支的因果历史，避免了重复执行完整前缀。

### 端到端接受长度优化

SpecOPD 采用端到端总变差（End-to-End Total Variation, E2E-TV）代理目标直接优化接受长度。在固定历史下，token 接受概率 $\alpha_{b,i}$ 等于草稿与目标分布的重叠度：

$$
\alpha_{b,i} = 1 - \text{TV}(q_\theta(\cdot | h_{b,i}), p(\cdot | h_{b,i}))
$$

训练损失最小化分支上前缀接受概率乘积的补集：

$$
L = 1 - \frac{1}{BW} \sum_{b=1}^B \prod_{i=1}^W \alpha_{b,i}
$$

该目标直接建模解码进度，早期不匹配会惩罚后续所有前缀项，促使草稿模型在长序列上保持分布一致性。

## 实验评估

实验在 Qwen3-8B、27B 和 125B 目标模型上，使用 DFlash、DSpark 和 DFlash V2 并行草稿架构，覆盖 MT-Bench、HumanEval、MATH-500、SWE 和 Terminal 五个基准。基线包括自回归解码（AR）、多 token 预测（MTP）及原始草稿模型。

| 方法 | 目标模型 | 温度 | 平均接受长度 (AL) | 相对提升 |
| :--- | :--- | :--- | :--- | :--- |
| DFlash | 8B | 0 | 2.649 | - |
| SpecOPD | 8B | 0 | 3.747 | +41.45% |
| DFlash V2 | 27B | 0 | 5.103 | - |
| SpecOPD | 27B | 0 | 5.242 | +2.72% |
| DFlash V2 | 125B | 0 | 3.941 | - |
| SpecOPD | 125B | 0 | 4.122 | +4.59% |

在 8B 模型上，SpecOPD 实现 41.45% 的平均 AL 提升，Terminal 任务提升达 81.51%。随着模型规模增大，增益收窄至 2.72%-5.01%，表明并行草稿在大规模模型上的分布对齐难度增加。训练效率方面，SpecOPD 相比 Draft-OPD 实现 16.09 倍监督 token 吞吐量提升，GPU 平均活动率从 26.37% 升至 77.23%。

消融实验显示，SpecOPD 在匹配优化步数下，比离线 CE 和离线 E2E-TV 基线分别提升 6.96% 和 15.71% 的平均 AL。值得注意的是，离线基线随训练进行接受率下降，而 SpecOPD 持续提升，且在草稿位置 7 的存活率提升 4.33 个百分点，证明在线策略对长草稿块的稳定性至关重要。

评估边界方面，高并发（Concurrency 32）下加速比降至 1.35 倍，且 SWE 任务慢于原始草稿，表明分支并行在批处理调度中可能引入额外开销。代码未开源，复现依赖特定硬件配置。

## 关联研究分析

从问题动机看，SpecOPD 与 Draft-OPD 均致力于在线蒸馏，但 Draft-OPD 依赖目标模型辅助的完整 rollout，导致收集阶段串行化。SpecOPD 通过参考锚点解耦监督与完整轨迹，这一差异源于对“在线”定义的重新审视：在线性体现在草稿采样历史，而非完整响应上下文。然而，这种解耦是否牺牲了长程依赖信息的捕获，导致在长上下文任务中接受率增益受限，论文未给出回答。

从方法设计看，SpecOPD 复用 SpecInfer 的树状结构，但将其从推理验证扩展至训练监督。与 EAGLE 的特征对齐自回归草稿不同，SpecOPD 针对并行草稿架构，需处理异构注意力下的状态隔离。EAGLE 通过隐藏状态对齐简化了特征耦合，而 SpecOPD 需显式处理 GQA、QSA、GDN 的状态重放，复杂度更高。并行草稿在复杂推理任务中的接受率上限是否低于自回归草稿，论文未给出回答。

## 总结

SpecOPD 针对并行草稿模型在线训练中的串行收集瓶颈，提出分支并行在线蒸馏框架，通过参考锚点采样与异构注意力共享前缀评分，实现高效在线监督。实验证明其在 8B 模型上提升 41.45% 平均接受长度，训练吞吐提升 16.09 倍。然而，其在 27B/125B 模型上增益显著收窄，且高并发下加速比衰减，暴露了并行草稿在大规模模型与批处理场景下的适配局限。当目标模型规模扩大至 125B 时，并行草稿的分布对齐难度是否已接近其架构上限，论文未给出回答。
