> 导读 全模态大语言模型（Omni-modal Large Language Models, OLLMs）虽能联合处理音视频流，但难以严格遵循用户定义的复杂结构化指令，导致下游生成任务缺乏可控性。现有基准或侧重语义问答，或局限于单模态，无法评估格式约束与内容推理的耦合效应。本文构建了首个全模态指令遵循基准 OmniCap-IF，通过解耦格式与内容评估协议，揭示了“格式-内容权衡”现象。该工作填补了全模态可控生成的评估空白，但其对长视频场景的覆盖不足，且依赖 LLM 裁判的可靠性仍存疑。

## 研究背景

当 OLLMs 生成视频描述时，用户往往要求特定的输出结构（如 JSON 表格、时间戳格式）与特定的内容焦点（如仅描述音频氛围、排除视觉天气信息）。这种需求源于文本到音视频生成（T2AV）脚本编写、具身智能体动作规划等下游任务，要求模型不仅“看懂”视频，还要“听懂”指令。然而，指令遵循能力涉及两个维度：格式约束（Format Constraints）要求输出符合语法结构，内容约束（Content Constraints）要求语义事实准确。二者在模型内部共享注意力资源，当格式约束变得严苛（如深层嵌套 JSON），模型分配给跨模态推理的注意力被挤占，导致内容准确性下降。

多模态指令遵循评估长期存在盲区。文本指令遵循基准（如 IFEval）仅处理纯文本输入，视觉指令遵循基准（如 IF-VidCap）忽略音频模态，而全模态字幕基准（如 Omni-Cloze）侧重描述丰富度而非指令合规性。主流路线的瓶颈在于缺乏程序化可验证性：现有全模态基准多采用 LLM-as-a-judge 评估语义相似度，无法精确量化格式错误（如括号不匹配）或时间定位偏差（如时间戳偏移）。本文切入点在于构建一个同时覆盖视觉、音频、音视频联合约束，并引入时间定位（Temporal Grounding）的基准，通过规则化工具与 LLM 裁判结合，实现格式与内容的解耦评估。

## 核心方法

### 双机制解耦评估协议

全模态指令遵循评估通常依赖 LLM 裁判对生成文本进行整体打分，但该方法在格式错误检测上不稳定，且易受描述流畅度干扰。本文采用双机制解耦协议：格式约束通过“LLM 提取 + 规则工具验证”两步法评估，内容约束通过“LLM 问答 + 时间定位计算”评估。设计动机在于消除 LLM 裁判在结构化验证上的随机性，将客观格式检查转化为确定性程序执行。

格式评估中，LLM 从生成输出中提取结构化信息（如 JSON 键值对、时间戳），随后规则工具验证其是否符合预定义模式。内容评估中，对于时间定位约束，使用时间交并比（t-IoU）计算预测区间 $I_{pred}$ 与真值区间 $I_{gt}$ 的重叠度：

$$
\text{t-IoU} = \frac{|I_{pred} \cap I_{gt}|}{|I_{pred} \cup I_{gt}|}
$$

当 t-IoU $\geq 0.5$ 时判定为满足约束。该公式量化了模型在时空精度上的表现，避免了 LLM 对时间描述的模糊判断。对于非时间内容约束，LLM 通过二元或选择题验证事实准确性，优先评估事实对齐而非语言流畅性。

### 分解式数据生成策略

复杂指令的直接生成往往导致真值数据质量低下，因为模型在同时满足多个约束时易产生幻觉或格式错误。本文采用分解式生成策略：将指令拆分为内容子任务（每个含 2-3 个约束）和格式约束，分别生成中间响应后聚合。设计动机在于规避单步生成中约束冲突导致的性能崩溃，确保训练数据的高保真度。

具体流程为：首先，基于视频字幕，Gemini-3-Flash 生成内容子任务的中间响应；随后，将中间响应聚合为完整内容响应；最后，仅对聚合后的内容应用格式约束，生成最终真值。该策略在 500 个随机样本上的对比实验中，96.3% 的情况下优于直接生成。这一设计解决了复杂指令标注中“约束越多，错误率越高”的难题，为后续微调提供了高质量数据基础。

## 实验评估

| 模型 | Overall CSR | Format CSR | Content CSR (AV) |
| :--- | :--- | :--- | :--- |
| Gemini-3.1-Pro | 80.65 | 75.02 | 73.40 |
| Qwen3-Omni-30B-A3B-Thinking | 71.91 | 64.79 | 62.64 |
| OmniCaptioner-IF-7B (Ours) | 70.73 | 59.43 | 64.71 |

实验在 14 个主流 OLLMs 上进行，基线覆盖闭源（Gemini、MiMo）与开源（Qwen、MiniCPM）模型。主结果显示，Gemini-3.1-Pro 在 Overall CSR 上领先（80.65），但开源模型 OmniCaptioner-IF-7B 在 AV 内容约束上（64.71）超越了 Qwen3-Omni-30B-A3B-Thinking（62.64），表明指令微调对跨模态推理的增益。

| 训练数据量 | Overall CSR | Format CSR |
| :--- | :--- | :--- |
| Base (Qwen2.5-Omni-7B) | 49.19 | 62.97 |
| 20K | 68.50 | 88.50 |
| 54K (Full) | 70.73 | 90.39 |

消融实验显示，仅使用 20K 样本微调，Overall CSR 从 49.19 跃升至 68.50，Format CSR 从 62.97 提升至 88.50。然而，从 20K 到 54K，Overall CSR 仅增加 2.23 个点，Format CSR 甚至轻微下降（90.52 至 90.39），表明数据质量与约束多样性比单纯规模更重要，54K 样本已接近收敛“甜点”。

评估边界方面，基准视频时长限于 30-90 秒，未覆盖小时级长视频；内容评估依赖 LLM 裁判，虽通过规则工具缓解格式偏差，但语义幻觉无法完全消除；代码与数据已开源，但超参数配置（如 FPS=1.0, Temperature=0.0）固定，未探索不同采样率下的鲁棒性。

## 关联研究分析

从问题动机看，本文与 IF-VidCap 同属指令遵循评估，但 IF-VidCap 仅处理视觉模态，而本文扩展至音视频联合约束。关键差异在于本文引入了时间定位（Temporal Grounding）作为内容约束的子类，这源于全模态场景中音视频同步的重要性。IF-VidCap 缺乏音频维度，无法评估模型对声音事件的时间定位能力，而本文通过 t-IoU 量化了这一能力，揭示了模型在处理音视频联合约束时的性能瓶颈。

从方法设计看，本文与 Omni-Cloze 同属全模态字幕评估，但 Omni-Cloze 侧重描述丰富度，采用 LLM 裁判评估语义相似度，而本文侧重指令合规性，采用规则工具验证格式。这一差异源于任务目标不同：Omni-Cloze 旨在测试模型对视频内容的感知深度，本文旨在测试模型对用户指令的遵循精度。本文的解耦评估协议更适用于可控生成场景，但可能低估了模型在自由描述任务中的表现，因为格式约束的严苛性会挤占内容推理资源。

## 总结

本文核心矛盾在于全模态模型难以同时满足严苛格式约束与复杂内容推理，现有基准无法量化这一权衡。本文通过构建 OmniCap-IF 基准与解耦评估协议，揭示了格式复杂度对内容准确性的负面影响，并验证了分解式数据生成策略的有效性。实验表明，OmniCaptioner-IF-7B 在 AV 内容约束上超越同规模开源基线，但 Overall CSR 仍低于 Gemini-3.1-Pro。本文边界在于视频时长限制与 LLM 裁判依赖，当视频时长扩展至小时级，或格式约束进一步复杂化（如多层嵌套 JSON），模型的内容推理能力是否会出现断崖式下跌，论文未给出回答。
