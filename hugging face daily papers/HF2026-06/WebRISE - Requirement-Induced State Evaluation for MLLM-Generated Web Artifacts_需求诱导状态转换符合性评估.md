作者：Yuxin Meng、Yuhan Suo、Junjie Wang 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.03220)

> 多模态大语言模型（MLLM）生成的网页常面临“视觉逼真但功能失效”的困境，现有基准仅验证局部动作响应，无法覆盖需求隐含的全局状态约束。WebRISE 将任务需求编译为交互契约图（Interaction Contract Graph, ICG），通过自适应浏览器代理执行状态转换并验证 DOM/视觉断言，实现了从“外观检查”到“行为符合性”的评估范式转移。该基准揭示了当前最强模型在交互完整性上的显著短板，但其依赖专家构建契约的评估流程限制了自动化扩展潜力。

## 研究背景

当 MLLM 根据文本或截图生成网页时，模型往往能还原布局与控件，却难以保证点击筛选后列表同步更新、删除商品后总价重算等隐含逻辑。这种“视觉合理但行为断裂”的现象源于评估对象从静态渲染转向动态交互：页面不再是像素集合，而是具备状态记忆与因果响应的执行环境。验证此类环境需引入状态转换概念，即用户意图驱动下 UI 配置从 $S_{from}$ 到 $S_{to}$ 的演化过程，以及该过程中必须满足的不变量约束。

现有 Web 生成基准（如 FrontendBench、WebGen-Bench）多采用脚本断言或检查点验证，仅确认特定动作是否触发局部反馈，未定义需求诱导的完整状态空间。这导致两类失效被系统性遗漏：一是事件中心评估无法枚举应覆盖的状态转换，二是局部响应通过时页面可能违反跨组件同步、分页重置等全局一致性约束。WebRISE 的切入点在于将评估对象从“动作-结果对”重构为“需求诱导的可观察状态转换符合性”，通过有限状态机建模将隐含产品约束显式化，从而在浏览器执行环境中实现可归因的行为诊断。

## 核心方法

### 方法参照系

Web 生成评估通常遵循“生成-渲染-断言”流程，但传统断言依赖固定选择器或单一模态快照，无法适应实现差异。本文的关键差异在于将断言锚定于需求语义而非 DOM 结构，通过状态图约束替代孤立检查点，使评估协议与具体实现解耦。

### 交互契约图编译

ICG 将任务需求 $R_\tau$ 编译为三元组 $G_\tau = (S_\tau, T_\tau, \Phi_\tau)$，其中 $S_\tau$ 为需求相关的可观察 UI 状态，$T_\tau$ 为用户意图驱动的转换，$\Phi_\tau$ 为 DOM/视觉谓词。设计动机在于解决检查点范式无法表达跨步骤状态依赖的问题：

$$
T_j = (s_{from}^j, s_{to}^j, g_j, P_j, A_{dom}^j, A_{vis}^j)
$$

该公式将每个转换定义为源/目标状态、自然语言目标 $g_j$、前置条件 $P_j$ 及双通道断言。瞬态行为（如加载、防抖）不作为独立状态，而是作为转换级过程证据附着于 $T_j$，保持状态空间有限且稳定。

### 契约引导执行与双 Oracle 验证

评估时，ICG 指定“验证什么”，自适应代理决定“如何执行”。代理将页面序列化为索引化 DOM 观察，每次动作后重新生成索引，避免固定选择器失效。设计动机在于解决脚本化执行在实现差异下的脆弱性：

$$
o_j = \text{AGGREGATE}(\text{agent status}, r_{dom}, r_{vis})
$$

其中 $r_{dom} = \text{SCORE}_{DOM}(A_{dom}^j, L)$ 验证过程级 DOM 证据，$r_{vis} = \text{SCORE}_{VISUAL}(A_{vis}^j, img_{pre}, img_{post})$ 验证最终视觉结果。仅当源状态可达、代理完成交互且所有断言通过时，转换标记为 PASS。该机制将证据本地化至需求关联的状态变更，支持分支状态图的隔离验证。

## 实验评估

实验覆盖 442 个任务、5 种输入模态（Text, Markdown, Sketch, Image, Video）及 14 个 MLLM（7 开源、7 闭源）。基线审计显示，对比方法缺失专用 Web 生成微调模型，且未包含基于强化学习的交互优化模型，可能低估当前 SOTA 上限。主结果如下：

| 模型 | 模态 | T (%) | R (%) | V (%) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5.5 | Video | 65.6 | 66.3 | 73.9 |
| Kimi-K2.6 | Video | 63.3 | 65.4 | 73.5 |
| Qwen3.6-35B-A3B | Markdown | 15.5 | 19.2 | 80.8 |
| GPT-5.5 | Text | 51.7 | 59.7 | 78.4 |

GPT-5.5 在 Video 模态下 T=65.6%、R=66.3%，表明约三分之一需求转换未满足。Qwen3.6-35B-A3B 在 Markdown 下 V=80.8 但 T=15.5，证实视觉质量非交互正确性代理。Video 模态相比 Text 提升 T、R、Ri 分别 8.8、8.3、10.6 个百分点，时序交互信号优于静态视觉保真度。

消融分析聚焦缺陷注入元评估：ICG 检测 16/25 状态相关缺陷，而宽泛检查点仅 8/25，严格检查点仅 1/25。失败归因显示 State & Logic 错误占比最高（GPT-5.5 为 57.2%），表明主要瓶颈在于状态更新与结果逻辑维护，而非控件暴露。该发现与领域共识中“长程任务依赖状态管理”一致，但 WebRISE 将状态约束从 Agent 轨迹评估迁移至生成工件评估，揭示了生成模型在隐含约束遵循上的系统性缺陷。

评估边界方面，ICG 构建依赖专家标注，自动化生成潜力未验证；安全诊断仅覆盖基础 HTML 检查，未涉及提示注入等对抗攻击；可复现性受限于浏览器环境版本与代理预算 $K$ 的敏感性，论文未报告推理延迟与内存占用。

## 关联研究分析

从问题动机看，WebRISE 与 WebGen-Bench 均关注交互验证，但后者采用检查点范式，仅验证局部动作-结果对，无法表达跨组件状态同步约束。WebRISE 的 ICG 通过需求映射 $M_\tau$ 将转换证据归因至显式/隐含需求，解决了检查点范式“可见但不可归因”的局限。这一差异源于任务特性：生成工件评估需覆盖完整需求空间，而 Agent 轨迹评估可聚焦单步决策正确性。

从方法设计看，WebRISE 与 FrontendBench 均使用脚本断言，但前者依赖固定选择器，后者采用自适应代理重新索引 DOM。这一改进解决了实现差异下的选择器失效问题，但引入了代理执行的不确定性。与 IWR-Bench 相比，WebRISE 扩展了 Video 输入，从“轨迹重建”转向“行为符合性”评估，但 IWR-Bench 的 MLLM 断言可能更灵活地处理非结构化输出。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

WebRISE 要解决的核心矛盾是生成网页“视觉逼真但功能失效”的评估盲区，现有检查点范式无法覆盖需求隐含的全局状态约束。其切入点在于将评估对象重构为需求诱导的状态转换符合性，通过 ICG 将隐含约束显式化，使评估协议与实现解耦。实验证明 GPT-5.5 在 Video 模态下 T=65.6%、R=66.3%，揭示当前模型在交互完整性上的显著短板。本文的边界在于 ICG 构建依赖专家标注，自动化生成潜力未验证，且安全诊断未覆盖对抗攻击。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
