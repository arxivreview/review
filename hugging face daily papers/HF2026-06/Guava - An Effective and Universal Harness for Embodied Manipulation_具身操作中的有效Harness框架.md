# HuggingFace最新推荐论文 ｜Guava: An Effective and Universal Harness for Embodied Manipulation ｜具身操作中的有效Harness框架

研究机构：美国伊利诺伊大学厄巴纳-香槟分校、加拿大滑铁卢大学

论文原文见 [arXiv](https://arxiv.org/abs/2606.18363)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.18363)

> 具身智能体需将自然语言指令转化为鲁棒的物理动作，但端到端视觉-语言-动作（Vision-Language-Action, VLA）模型依赖海量机器人演示数据，且内部动作表征难以支持显式的计划检查与修复。现有模块化系统多采用一次性代码生成，缺乏对执行失败的闭环响应能力。Guava通过系统性消融实验确立了迭代感知-推理-动作循环、语义动作抽象与多模态观察三大设计原则，并验证了利用少于2K条仿真轨迹将前沿模型能力蒸馏至4B开源模型的有效性。该框架在数据效率与失败恢复方面表现突出，但其对精细操作与工具级错误的处理边界仍受限于当前动作原语的选择。

## 研究背景

当机器人执行“将罐子放入盒子”这类长时程任务时，抓取失败或物体位移等随机扰动会迅速导致初始计划失效。这种执行不确定性要求智能体具备闭环反馈能力，即在执行过程中持续观察环境状态并动态调整策略，而非依赖单次预测生成完整轨迹。这一需求引出了Harness（工具调用框架）的概念：它定义了语言模型与外部感知、控制模块之间的交互协议，使模型能调用特定工具而非直接输出底层控制信号。

具身语言智能体领域长期存在端到端VLA与模块化架构的路线之争。VLA模型通过大规模预训练实现感知-动作紧耦合，但数据收集成本高且难以泛化至未见场景；模块化方法如Code-as-Policies（Liang et al., 2022）和Maestro（Shi et al., 2025）利用LLM生成代码或调用工具，保留了可解释性，但普遍依赖一次性程序生成，无法在执行失败后重新规划。Guava的切入点在于回答一个基础问题：什么样的Harness设计能使具身智能体在低推理成本下实现鲁棒的长时程操作与失败恢复？

## 核心方法

### 方法参照系

本文问题属于模块化具身规划范畴，其通用流程为：LLM解析指令→生成动作序列→执行器执行。关键差异在于，传统流程假设执行过程无扰动，而Guava将执行视为随机过程，要求模型在每一步后重新评估状态并决定后续动作，从而将开环预测转化为闭环交互。

### 迭代感知-推理-动作循环

一次性代码生成在抓取失败时无法触发修正，因为生成的程序已固定。Guava引入ReAct（Yao et al., 2023）风格的迭代循环，使VLM在每次工具调用后接收新的观察结果，并基于此更新推理状态。该循环的决策过程可形式化为：

$$a_t = \pi_\theta(o_{1:t}, l, h_{1:t-1})$$

其中 $a_t$ 为第 $t$ 步动作，$o_{1:t}$ 为多模态观察序列，$l$ 为语言指令，$h_{1:t-1}$ 为历史推理轨迹。该公式表明，当前动作不仅依赖当前观察，还依赖完整的交互历史，使模型能识别“抓取未成功”等状态并触发重试或替代动作。消融实验显示，相比单轮规划，迭代循环在六个长时程任务上平均成功率提升超过30个百分点，尤其在需要多次尝试的任务中优势显著。

### 语义动作抽象与多模态观察

直接输出关节空间控制要求VLM处理复杂的几何与物理推理，这超出了当前模型的可靠能力范围。Guava将动作空间抽象为语义工具，如 `grasp(object)` 和 `move(x,y,z)`，将运动规划委托给底层控制器。同时，观察空间结合视觉图像与文本状态描述，提供互补的环境上下文。工具集的设计遵循层级原则：高层工具（如 `grasp`）封装了感知引导的抓取逻辑，低层工具（如 `move`）允许精细位置控制。这种抽象使VLM专注于任务分解与语义推理，而非执行可行性计算。实验表明，语义动作空间相比低层几何接口，在“按大小排列”等需要空间推理的任务上成功率从40%提升至66.7%，验证了抽象层对降低模型推理负担的有效性。

## 实验评估

实验在Robosuite仿真环境与Franka Research 3真机上开展，任务分为分布内（ID）、分布外物体（OOD Object）、分布外提示（OOD Prompt）与分布外长时程（OOD Long Horizon）四类。基线包括前沿VLM GPT-5.4、未微调的Qwen3.5-4B及一次性代码生成系统CaP-Agent0。值得注意的是，实验未包含端到端VLA基线（如RT-2或OpenVLA），这使得无法直接比较模块化与端到端路线在相同数据预算下的性能差异。

| 任务类别 | 任务名称 | CaP-Agent0 | Qwen3.5-4B | GPT-5.4 | Guava-Agent-4B |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ID | place can in box | 86.7 | 20.0 | 100.0 | 100.0 |
| ID | arrange by size | 46.7 | 0.0 | 40.0 | 66.7 |
| OOD Object | pick up carrot | 100.0 | 66.7 | 100.0 | 100.0 |
| OOD Long Horizon | separate food and utensils | 86.7 | 0.0 | 86.7 | 93.3 |
| Overall | - | 62.7 | 23.1 | 70.2 | 75.6 |

Guava-Agent-4B在整体成功率上达到75.6%，超过GPT-5.4的70.2%与CaP-Agent0的62.7%。在ID任务中，该模型在“place can in box”与“remove cube from tray”上均取得100%成功率；在OOD任务中，其对未见物体与提示的泛化能力显著，如在“push pot”任务上从GPT-5.4的26.7%提升至73.3%。长时程任务中，“separate food and utensils”与“set table”均达到93.3%，但“shell game”仅6.7%，“place all red objects in basket”为0.0%，表明复杂多步推理仍是瓶颈。

消融实验揭示了关键设计决策的影响。迭代工作流相比单轮规划，在“arrange by size”任务上成功率从33%提升至67%；语义动作空间相比低层工具集，在“place can in box”任务上从67%提升至100%；多模态观察相比纯文本观察，在“remove cube from tray”任务上从40%提升至67%。这些结果验证了三大设计原则的必要性，且各原则之间存在协同效应：迭代循环依赖多模态观察获取状态更新，语义抽象降低了迭代决策的推理复杂度。

评估协议存在若干局限。仿真实验基于15个episode，真机实验基于10个episode，样本量较小，未报告置信区间，数值比较需谨慎。所有训练在8块NVIDIA H100 80GB GPU上以bfloat16精度完成，视觉编码器与对齐器在训练过程中保持冻结。代码与超参数细节见补充材料，但论文未提供完整的训练数据生成脚本与RL奖励函数定义，可复现性依赖于补充材料的完整性。

## 关联研究分析

从问题动机看，Guava与Maestro（Shi et al., 2025）同属Harness框架路线，但二者对“有效性”的定义存在根本差异。Maestro聚焦于通过程序生成实现任务完成，其评估指标为任务成功率，未显式建模执行失败后的恢复行为；Guava则将失败恢复作为核心设计目标，通过引入恢复轨迹训练与迭代循环，使模型能检测并纠正执行错误。这一差异源于任务特性：Maestro面向结构化任务，执行失败概率较低；Guava面向长时程操作，随机扰动频繁，失败恢复成为性能瓶颈。Guava在“shell game”任务上仅6.7%的成功率，表明即使引入恢复机制，复杂多步推理中的错误累积仍未完全解决，这是否为模块化路线的固有局限，还是可通过更丰富的工具集缓解，论文未给出回答。

从方法设计看，Guava与Code-as-Policies（Liang et al., 2022）共享“LLM生成控制逻辑”的范式，但二者在动作空间抽象层级上存在显著差异。Code-as-Policies生成Python脚本直接调用底层API，要求LLM处理几何计算与运动规划；Guava将动作抽象为语义工具，将运动规划委托给专用控制器。这一设计选择牺牲了动作的精细度，换取了推理的可靠性与可解释性。在“arrange by size”任务中，Guava的66.7%成功率低于CaP-Agent0的46.7%与GPT-5.4的40.0%，但高于Qwen3.5-4B的0.0%，表明语义抽象在小模型上具有显著优势，但在前沿模型上可能限制了性能上限。语义工具抽象是否限制了精细操作的极限性能，论文未提供对比实验。

## 总结

Guava要解决的核心矛盾是：如何在有限数据预算下，使具身智能体具备鲁棒的长时程操作与失败恢复能力。现有端到端VLA依赖海量数据且难以显式修复计划，模块化系统缺乏闭环反馈，而Guava通过迭代ReAct循环、语义动作抽象与多模态观察三大原则，构建了有效的Harness框架，并利用少于2K条仿真轨迹将前沿模型能力蒸馏至4B开源模型。实验证明，该模型在Robosuite整体成功率达75.6%，超过GPT-5.4的70.2%，并在真机上实现零样本迁移。然而，论文自身实验暴露了边界：在“shell game”与“place all red objects in basket”等复杂长时程任务上，成功率分别仅为6.7%与0.0%，表明当前框架在处理多步依赖与状态追踪时仍存在显著缺陷。当任务复杂度进一步增加，语义工具抽象的粒度是否足够支持精细的状态推理，论文未给出回答。
