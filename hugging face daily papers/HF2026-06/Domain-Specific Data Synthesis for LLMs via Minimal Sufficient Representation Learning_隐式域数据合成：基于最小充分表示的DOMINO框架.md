> 导读 现有LLM域适应方法依赖显式自然语言定义，无法处理难以言表的隐式领域。DOMINO通过从少量参考样本学习最小充分表示，绕过了人工提示工程。该框架结合提示调优与对比解耦，生成多样化域对齐数据。其价值在于解决了隐式域定义的合成难题，但泛化边界仍受限于参考样本的分布覆盖。

## 研究背景

当领域知识无法用自然语言精确描述时，传统基于提示工程的数据合成方法失效。这引出了“隐式域定义”问题：仅凭少量参考样本，模型需归纳出领域的潜在规则。解决此问题需区分域级通用模式与样本级噪声，避免过拟合。这一区分依赖于信息论中的“最小充分表示”概念，即保留足以重建数据的最低信息量，剔除冗余细节。

主流LLM数据合成路线包括指令进化、关键点驱动及系统提示引导。这些方法均假设领域知识可被显式转化为文本指令，但在新兴科学领域或快速演变的文化趋势中，这种假设不成立。直接对少量参考样本进行监督微调（SFT）会导致模型记忆表层特征，而非泛化底层原则。DOMINO的切入点在于将域适应视为归纳推理过程，通过学习隐式嵌入来捕捉领域本质，从而在无显式定义条件下实现数据合成。

## 核心方法

### 方法参照系

本文问题对应于生成式域适应路线，但去除了视觉生成环节。与依赖ControlNet等显式结构约束的视觉方法不同，DOMINO利用预训练LLM作为隐式编码器，通过软提示调优学习域表示。关键差异在于，本文不依赖外部结构条件，而是从数据内部归纳域特征，以解决隐式域定义下的过拟合问题。

### 隐式域表示学习

为捕捉域的本质特征，DOMINO引入域软令牌 $\mathbf{D} = [\mathbf{d}_1, \dots, \mathbf{d}_k]$，每个令牌维度为 $d$。优化目标为最大化参考数据 $\mathbf{X}_{[1:n]}$ 在给定域表示下的似然：

$$ \max_{\mathbf{D}} \prod_{i=1}^{n} p(\mathbf{X}_i | \mathbf{D}) $$

该公式的物理含义是寻找一组软令牌，使得LLM在注入该令牌后，能够以最高概率生成所有参考样本。这一设计解决了传统提示工程依赖人工设计、无法自动适应隐式域的问题，通过数据驱动的方式自动提取域特征。

### 对比解耦机制

为防止域表示过拟合样本特定细节，DOMINO引入对比解耦损失，分离域级模式与样本级噪声。总损失函数为：

$$ \mathcal{L} = -\sum_{i=1}^{n} \log p(\mathbf{X}_i | \mathbf{D}) + \lambda \mathcal{L}_{contrast} $$

其中 $\mathcal{L}_{contrast}$ 鼓励域表示 $\mathbf{D}$ 与样本特定特征正交。这一机制确保了表示的最小性，即仅保留对域重建必要的信息。其改进价值在于，当参考样本数量较少时，该机制能有效抑制对个别样本的过拟合，提升合成数据的泛化能力，避免直接SFT导致的性能下降。

## 实验评估

实验在LiveCodeBench上进行，涵盖代码生成与执行两个隐式域。基线包括Reference SFT、MAGPIE-Human及MAGPIE-Few Shot。DOMINO在Qwen2.5-Coder-7B-Instruct骨干上，Live Code Generation Pass@1达17.31%，较MAGPIE-Few Shot的14.36%提升2.95个百分点，较Reference SFT的13.47%提升3.84个百分点。

| 方法 | Live Code Gen Pass@1 | Live Code Exec Pass@1 |
| :--- | :--- | :--- |
| Qwen2.5-Coder-7B-Instruct | 16.88 | 55.55 |
| Reference SFT | 13.47 | 36.11 |
| MAGPIE-Few Shot | 14.36 | 48.15 |
| DOMINO | 17.31 | 56.48 |

消融实验显示，温度 $T=0.8$ 时性能最优，Pass@1为17.31%；$T=0.2$ 时降至16.35%。超参数 $\lambda=1$ 时Pass@1为17.31%，$\lambda=2$ 时微升至17.58%，但Pass@5下降，表明对比损失权重需平衡多样性与准确性。

评估边界方面，实验仅覆盖代码与NLP任务，未涉及多模态或动态场景。代码已开源，但超参数 $\lambda$ 与温度 $T$ 的敏感性分析表明，方法对生成参数较为敏感，复现时需仔细调参。

## 关联研究分析

从问题动机看，DOMINO与Self-Instruct和Evol-Instruct形成对比。后者依赖显式提示工程，假设领域知识可被人工描述；DOMINO则假设领域知识隐含于数据中，通过归纳推理获取。这一差异源于任务特性：代码领域的算法模式往往具有隐性结构，难以用简单提示捕捉，而DOMINO的隐式表示学习更适配此类场景。

从方法设计看，DOMINO与视觉域适应中的ControlNet方法存在异同。两者均利用预训练模型作为生成器，但ControlNet依赖外部结构条件（如边缘图），DOMINO依赖内部学习的软令牌。这种差异暗示，在文本域中，显式结构约束可能不如隐式表示学习有效，因为文本的结构往往体现在语义逻辑而非表面格式。

## 总结

DOMINO解决了隐式域定义下数据合成的核心矛盾，即缺乏显式描述时的过拟合风险。其切入点在于利用最小充分表示理论，通过提示调优与对比解耦分离域级模式与样本噪声。实验证明，在LiveCodeBench上，DOMINO较强基线提升Pass@1达4.63%。然而，其边界在于仅验证了代码与NLP任务，且对生成参数敏感。当参考样本分布覆盖不全时，最小充分表示能否有效捕捉域的全局特征，论文未给出回答。
