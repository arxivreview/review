# HuggingFace最新推荐论文 ｜Critic-R: Improving Agentic Search using Instruction-tuned Retrievers with Natural Language Introspective Feedback ｜基于内省反馈的检索器协同优化

研究机构：美国马萨诸塞大学阿默斯特分校、英国伦敦大学学院

作者：Md Zarif Ul Alam、Alireza Salemi、Hamed Zamani

论文原文见 [arXiv](https://arxiv.org/abs/2606.00590)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.00590)

> 智能体搜索（Agentic Search）旨在让大语言模型（LLM）通过迭代检索解决多跳推理，但现有方法常将检索器视为冻结黑盒，导致检索失败成为性能瓶颈。本文指出，仅靠推理模型改写查询无法弥补检索缺陷，且联合训练依赖金标准标注，限制了实际部署。Critic-R 通过引入独立批评模型解析智能体内省反馈，在推理时动态精炼查询，并利用该过程产生的轨迹离线微调检索器。该框架在单智能体架构下显著提升了多跳问答准确率，但其收益高度依赖推理模型的内省质量，且未验证在更复杂多智能体系统中的泛化能力。

## 研究背景

当智能体执行多跳问答时，它需要分解查询并逐步获取证据。这一过程依赖检索器返回相关文档，若检索器无法理解智能体动态生成的子查询，证据缺失将导致推理链断裂。这种“检索-推理”的不匹配源于传统检索器针对人类静态查询优化，而智能体查询具有高度上下文依赖性。解决此问题需打破检索器黑盒假设，实现检索与推理的协同。

主流路线分为两类：一是强化学习（RL）优化推理策略，如 Search-R1，但假设检索器足够强大；二是联合优化检索器与智能体，如 CoSearch 和 Agentic-R，但依赖端到端训练或金标准段落标注，在检索器外部提供或智能体不可训练时失效。本文切入点在于解耦这两个过程：不修改推理智能体参数，也不依赖人工标注，而是利用智能体在推理过程中自然产生的“内省反馈”作为监督信号，构建一个轻量级的反馈闭环。

## 核心方法

### 方法参照系

本文问题属于检索器协同优化范畴。标准流程是联合训练检索器与智能体，以最终答案正确性为奖励。关键差异在于，本文不修改智能体训练目标，而是介入推理时的检索环节，将检索质量评估从智能体内部剥离，由独立模型执行。

### 推理时查询精炼循环（Critic-R-Zero）

在 ReAct 框架中，智能体生成查询并获取文档后，通常直接基于文档继续推理。本文在此环节插入一个独立批评模型（Critic），其设计动机是解决长轨迹中智能体因上下文噪声导致的过度自信问题，即智能体可能误判检索失败。批评模型接收全局问题 $Q$、当前查询 $q_i^{[t]}$、检索文档 $D_i^{[t]}$ 以及智能体消费文档后的内省轨迹 $T_i^{[t+1]}$，输出二元判定 $\sigma_i^{[t]}$ 及诊断原因 $r_i^{[t]}$：

$$ \sigma_i^{[t]} = \text{Critic}(Q, q_i^{[t]}, D_i^{[t]}, T_i^{[t+1]}) $$

若 $\sigma_i^{[t]} = \text{no}$，批评模型基于 $r_i^{[t]}$ 重写查询与指令，触发新一轮检索。此过程最多迭代 $K$ 次。该机制将检索失败恢复从智能体内部推理中解耦，动态分配推理时计算资源以修复检索错误，无需梯度更新。

### 轨迹内对比学习微调（Critic-Embed）

Critic-R-Zero 产生的轨迹包含天然的正负样本：满足智能体需求的文档为正例，被拒绝的文档为轨迹内硬负例。设计动机是摊销推理时精炼的计算开销，并将隐式检索质量信号转化为显式训练信号。本文利用这些轨迹微调检索器，损失函数为 InfoNCE：

$$ \mathcal{L} = -\log \frac{\exp(\text{sim}(q_i, z_i^+)/\tau)}{\sum_{z \in Z_i} \exp(\text{sim}(q_i, z)/\tau)} $$

其中 $Z_i$ 包含正例、批内负例及轨迹内硬负例。此方法无需金标准标注，仅依赖智能体自身的内省反馈，实现了检索器对智能体动态查询模式的自适应。

## 实验评估

实验在 HotpotQA、2WikiMultihopQA、MuSiQue 和 Bamboogle 上进行，基线包括静态检索器 Stella-400M 和联合优化基线 Agentic-R。本文方法在单智能体架构下显著优于静态基线，但缺乏与 DeepResearcher 等强 RL 智能体的直接对比。

| 方法 | HotpotQA F1 | 2Wiki F1 | MuSiQue F1 | Bamboogle F1 | Avg F1 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Stella-400M (k=1) | 0.4470 | 0.4564 | 0.2684 | 0.4963 | 0.4470 |
| Critic-Embed (k=1) | 0.5446 | 0.5083 | 0.2821 | 0.5872 | 0.4806 |
| Critic-R (k=1) | 0.5501 | 0.5237 | 0.2895 | 0.6200 | 0.4959 |

Critic-Embed 单独使用即提升平均 F1 至 0.4806，结合推理时循环后进一步提升至 0.4959。消融实验显示，移除智能体内省反馈 $T_i^{[t+1]}$ 后，Critic-Embed 性能下降 0.0285 F1，证明内省反馈是监督信号的关键来源。批评模型规模从 32B 增至 72B 时，收益递减，表明推理时计算扩展存在边际效应。

评估边界方面，论文未报告置信区间，且仅使用 Qwen2.5 系列模型，未验证跨模型泛化性。代码与模型已开源，超参数在附录中提供，可复现性良好。

## 关联研究分析

从方法设计看，Critic-R 与 CoSearch 均针对检索瓶颈，但 CoSearch 依赖 GRPO 联合训练，需金标准标注；Critic-R 通过解耦的推理时反馈与离线微调，降低了训练门槛。差异根源在于任务特性：CoSearch 假设检索器与智能体可同步优化，而 Critic-R 针对检索器外部提供的场景，更贴近实际部署。

从问题动机看，Critic-R 与 Agentic-R 均优化多轮搜索检索器，但 Agentic-R 侧重全局答案正确性建模，Critic-R 侧重局部证据充分性判定。Critic-R 引入独立批评模型，解决了智能体自评估不可靠的问题，但这也引入了额外的模型依赖。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文核心矛盾是检索器静态性与智能体动态查询的不匹配，现有联合训练方法依赖金标准标注，限制了部署。Critic-R 抓住智能体内省反馈这一被忽略的监督信号，通过推理时精炼与离线对比学习解耦优化，在 HotpotQA 等基准上实现 10.9% 相对提升。其边界在于收益依赖推理模型内省质量，且未验证在多智能体系统中的泛化性。当推理模型内省反馈噪声增大时，Critic-Embed 的检索器性能是否仍保持稳定，论文未给出回答。
