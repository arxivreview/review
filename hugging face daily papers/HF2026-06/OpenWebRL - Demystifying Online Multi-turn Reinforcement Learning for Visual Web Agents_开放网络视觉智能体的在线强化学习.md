> 视觉网页智能体（Visual Web Agent）在长程任务中面临静态监督数据覆盖不足与真实环境动态性导致的泛化失效问题。现有开源方案依赖大规模人工标注轨迹进行监督微调，而在线强化学习（Online RL）虽能解决数据瓶颈，却受限于实时浏览器交互的脆弱性与缺乏规则化奖励验证。本文提出 OpenWebRL 框架，通过小规模监督预热、多模态上下文管理及轨迹级评判机制，实现了在真实开放网络上的端到端在线 RL 训练。该框架以 4B 参数规模刷新了开源智能体在多个实时基准上的性能上限，但其对计算资源的依赖及评判模型的泛化边界仍存疑。

## 研究背景

理解本文需厘清部分可观测马尔可夫决策过程（POMDP）在多模态交互中的具体形态。智能体在每一步 $t$ 接收包含截图 $I_t$ 与文本元数据 $x_t$ 的观测 $o_t$，生成包含推理与工具调用的响应 $y_t$，环境据此转移至新状态。由于网页内容动态变化且无法完全观测，智能体必须依赖历史交互轨迹 $h_t$ 进行状态推断，这构成了长程规划的核心挑战。

视觉网页智能体的训练长期受困于数据稀缺与环境失真。主流开源模型如 MolmoWeb 依赖 278K 条人工筛选轨迹进行监督微调（SFT），这种静态数据不仅采集成本高昂，且无法覆盖开放网络的动态噪声与长尾场景。与此同时，早期的强化学习工作多局限于文本模态或自托管模拟环境（如 WebArena），回避了实时浏览器交互中的反爬虫机制、页面异步加载及缺乏规则化奖励验证等难题。尽管 WebGym 等尝试引入开放网络，但其 RL 形式化仍不完整，且依赖昂贵的专有 API 进行评估。本文的切入点在于：如何在不依赖大规模静态演示的前提下，利用实时开放网络交互，为紧凑规模的视觉模型提供高效、可复现的在线 RL 训练范式。

## 核心方法

### 多模态多轮 GRPO 优化框架

本文基于多模态多轮 Group Relative Policy Optimization (MM-GRPO) 构建优化目标。与单轮响应不同，多轮设置下采样单元为完整轨迹 $\tau_i$，其组相对优势 $A_i$ 由轨迹级奖励 $R(\tau_i)$ 在组内标准化得出：

$$ A_i = \frac{R(\tau_i) - \text{mean}(\{R(\tau_j)\}_{j=1}^G)}{\text{std}(\{R(\tau_j)\}_{j=1}^G)} $$

该公式将轨迹级的稀疏成功信号传播至轨迹内所有回合的动作 token，解决了长程任务中单步奖励缺失导致的信用分配难题。

### 上下文管理与环境反馈机制

针对长程交互中的上下文爆炸问题，本文设计了分离视觉感知与长期记忆的上下文管理策略。在 $t$ 时刻，策略仅保留最近 $K$ 张截图 $I_{\max(0, t-K+1)}, \dots, I_t$，而将更早的历史压缩为文本状态信息。关键设计在于保留完整的历史推理轨迹 $y_j$ 与环境反馈字符串，而非简单的动作摘要。环境反馈从 DOM 树变化中提取，提供动作执行结果的显式信号（如导航成功、输入不匹配）。这一机制解决了纯视觉模型在动态网页中因截图丢失而导致的“静默失败”检测失效问题，使智能体能在多工具调用接口下准确识别需重试的子动作。

### 轨迹级评判与奖励蒸馏

开放网络任务缺乏规则化验证，本文采用 VLM-as-a-Judge 设计轨迹级奖励。奖励 $r(\tau)$ 由格式正确性 $r_{fmt}$ 与任务成功性 $r_{succ}$ 共同决定，仅当格式合规且评判模型判定成功时给予正奖励。为降低专有 API 成本，本文从 12.5K 在线 rollout 及 GPT-4.1 标签中蒸馏出 8B 评判模型（OpenWebRL-Judge-8B）。该模型不仅预测成功与否，还生成评判理由，在保持与 GPT-4.1 高度一致（89.8% 准确率）的同时，将单次实验评估成本降低约 $545.5。

## 实验评估

实验在 WebVoyager、Online-Mind2Web 和 DeepShop 三个实时基准上进行，基线涵盖 Fara-7B、MolmoWeb-8B 及 Qwen3-VL-235B 等开源模型，以及 GPT-5、OpenAI CUA 等专有系统。OpenWebRL-4B 仅使用 0.4K SFT 轨迹与 2.2K RL 任务，在三个基准上分别取得 74.1%、67.0% 和 64.0% 的成功率，平均成功率 68.4%，显著超越同规模开源模型，并与专有系统保持竞争力。

| 方法 | WebVoyager | Online-Mind2Web | DeepShop | Avg |
| :--- | :--- | :--- | :--- | :--- |
| OpenWebRL-4B | 74.1 | 67.0 | 64.0 | 68.4 |
| MolmoWeb-8B | 31.3 | 35.3 | 24.7 | 30.4 |
| Fara-7B | 33.9 | 34.1 | 26.2 | 31.4 |
| Qwen3-VL-235B-A22B | 35.3 | 42.3 | 32.0 | 36.5 |

消融实验揭示了关键设计决策的影响。移除历史推理轨迹导致 Online-Mind2Web 成功率从 67.0% 骤降至 41.3%（-23.7pp），表明文本记忆对长程任务至关重要。移除文本环境反馈使成功率下降 8.0pp，验证了显式执行信号对动态网页交互的必要性。仅使用 10 步 rollout 相比 30 步，在 DeepShop 上性能下降 6.7pp，说明 rollout 长度课程对复杂任务探索的影响。

评估边界方面，WebVoyager 构建时间较早，网站动态变化可能影响结果可比性。训练过程消耗约 300 B200 GPU 小时，计算成本较高。代码与模型已开源，但评判模型的蒸馏数据未完全公开，可能限制复现性。

## 关联研究分析

从训练范式看，OpenWebRL 与 MolmoWeb 形成鲜明对比。MolmoWeb 依赖 278K 静态轨迹进行 SFT，其性能上限受限于数据覆盖范围；而 OpenWebRL 通过 0.4K SFT 预热后在线 RL，利用实时交互获取新分布数据，解决了静态数据无法覆盖动态网页噪声的问题。这一差异根源在于任务特性：开放网络的非平稳性使得静态模仿学习难以泛化，而在线 RL 能通过环境反馈自适应调整策略。

从奖励机制看，OpenWebRL 与 WebRL 存在关键分歧。WebRL 在自托管环境中使用规则化奖励或训练评判模型，而 OpenWebRL 在开放网络中依赖蒸馏的 8B 评判模型。WebRL 的规则化奖励在封闭环境中可靠，但在开放网络中因任务开放性而失效。OpenWebRL 的评判模型虽降低了成本，但其泛化能力受限于蒸馏数据分布，面对全新网站类型时可能产生偏差。这种权衡反映了开放网络评估中可靠性与可扩展性的根本矛盾。

## 总结

OpenWebRL 解决了视觉网页智能体在开放网络训练中数据稀缺与环境动态性冲突的核心矛盾。其切入点在于利用小规模 SFT 预热结合在线 RL，通过多模态上下文管理与轨迹级评判机制，使紧凑模型能在实时环境中高效学习。实验证明，仅用 0.4K 初始化轨迹，OpenWebRL-4B 在 Online-Mind2Web 上达到 67.0% 成功率，超越 235B 参数开源模型。然而，该框架依赖 300 B200 GPU 小时的计算资源，且评判模型的泛化边界未充分验证。当面对与训练分布差异极大的全新网站类型时，蒸馏评判模型的可靠性是否仍能维持，论文未给出回答。
