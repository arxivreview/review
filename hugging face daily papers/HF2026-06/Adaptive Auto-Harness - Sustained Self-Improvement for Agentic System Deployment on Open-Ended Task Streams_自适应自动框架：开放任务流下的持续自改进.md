> 开放任务流中，任务类型混杂且分布随时间漂移，导致单一密集框架在长期部署中性能先升后降。现有自动框架系统仅在静态离线基准上评估，无法捕捉流式环境下的过拟合与适应滞后。本文通过构建状态化多智能体进化器与推理时路由机制，将框架进化从线性覆盖转为树状分支隔离。该方案在预测市场与安全竞赛流中显著优于基线，但其对参数化方法的缺失对比及人类介入的依赖程度仍存疑。

## 研究背景

当智能体面对连续到达的预测市场问题时，其存储的经验可能因环境变化而过时，现有方法缺乏有效的实时验证机制来检测并修正记忆与当前环境状态的不一致，导致决策错误。这种“任务隔离”特性使得静态执行范式在分布外场景中表现不佳，而实际部署中任务流无固定终点，反馈异步到达，且任务类型（如政治、体育、金融）在同一小时内混合出现。解决此类问题的关键在于区分“进化损失”与“适应损失”：前者源于进化器能力不足，后者源于在观察任务前就承诺单一框架。

自进化大语言模型智能体（Self-Evolving LLM Agents）旨在打破静态代理的能力瓶颈，早期研究以非参数化反思为主线，通过自然语言记忆实现即时修正。然而，当长期任务暴露出经验固化不足后，研究者转向参数化内化与强化学习，用更高的计算成本换取能力的持久嵌入。现有自动框架系统如 A-Evolve 和 GEPA 虽在 SWEbench 等静态基准上取得显著增益，但其评估协议未捕捉部署的核心压力：框架必须在历史增长、任务类型变化及分布漂移的时序流中持续改进。本文切入点在于指出单一密集框架在长流中因积累过多特化技能而性能衰退，需通过结构化稀疏框架与推理时适应来维持长期稳定性。

## 核心方法

### 方法参照系

本文问题属于 Harness 进化路线，但区别于知识库中常见的单智能体线性进化流程。标准流程通常将历史轨迹压缩至有限上下文窗口，通过单次变异更新提示、技能与工具。本文的关键差异在于将进化过程解耦为“进化时构建”与“推理时选择”两个阶段，并引入 Git 分支隔离不同任务域，解决单一框架过拟合问题。

### 遗憾分解与双损失框架

设计动机在于现有方法混淆了进化器能力不足与任务异质性导致的适应滞后，导致盲目增加进化周期反而加剧过拟合。本文将框架构建形式化为对 oracle 参考的遗憾最小化问题，将总遗憾分解为进化损失 $L_{evo}$ 与适应损失 $L_{adapt}$。

$$
\text{Regret} = V(H_t, x_t) - V(\phi(H_t), x_t) = \underbrace{[V(H_t, x_t) - V(C^*_{\Phi}, x_t)]}_{L_{evo}} + \underbrace{[V(C^*_{\Phi}, x_t) - V(\phi(H_t), x_t)]}_{L_{adapt}}
$$

该公式表明，$L_{evo}$ 反映进化器类 $\Phi$ 的能力上限，需通过更强大的多智能体系统降低；$L_{adapt}$ 反映在观察任务 $x_t$ 前承诺单一框架的代价，需通过推理时路由降低。这一分解为系统设计提供了明确的方向：分别针对构建质量与选择精度进行优化。

### 状态化多智能体进化与树状路由

设计动机在于单智能体进化器无法在有限上下文内处理无限流中的异步反馈与异质任务，导致信息丢失与策略冲突。本文采用四阶段（Analyze-Research-Build-Verify）多智能体进化器，利用持久化工作区（任务板、研究日志、Git 仓库）实现跨周期记忆。进化器在进化时构建分支化框架树，每个分支携带特定领域的提示、技能与工具注册表。

$$
C_{selected} = \arg\max_{b \in \mathcal{B}} \text{Route}(x_t, \text{Workspace}_b)
$$

该公式表示推理时路由智能体通过读取各分支工作区内容，为当前任务 $x_t$ 选择最合适的分支 $b$。这种机制将重适应成本从进化时转移至推理时，利用 Git 的版本控制与隔离特性，防止新任务经验污染旧任务策略，从而在分布非平稳环境下保持能力稳定性。

## 实验评估

实验在 PolyBench（预测市场）、CTF-Dojo（安全竞赛）与 FutureX（事件预测）三个开放任务流上进行，基线覆盖 A-Evolve、GEPA、Meta-Harness 等五个自动框架系统及 OctoTools 人工设计系统，但缺失参数化强化学习基线（如 CoMAS）。

| 基准 | 指标 | A-Evolve | Meta-Harness | Full System (Ours) |
| :--- | :--- | :--- | :--- | :--- |
| PolyBench | Accuracy (%) | 18.4 | 50.8 | **80.9** |
| PolyBench | Return (%) | +7.2 | +320 | **+352** |
| CTF-Dojo | Pass@1 (%) | 45.2 | 41.0 | **50.2** |
| FutureX | Pass@1 (%) | 47.5 | 29.4 | **49.5** |

Full System 在 PolyBench Accuracy 达 80.9%，较 Meta-Harness 的 50.8% 提升 30.1 个百分点；在 CTF-Dojo Pass@1 达 50.2%，领先 A-Evolve 的 45.2%。消融实验显示，移除评估反馈或跨周期记忆会导致性能显著下降，验证了状态化进化的必要性。

评估边界方面，论文未报告计算效率维度，且所有实验使用 Claude Sonnet 4.6 作为求解器、Opus 4.6 作为进化器，温度设为 0 以排除采样噪声。代码已开源，但超参数细节（如分支数量上限）未在正文中详细披露，可能影响复现性。

## 关联研究分析

从问题动机看，本文与 A-Evolve 的核心差异在于对“静态基准”与“流式部署”的区分。A-Evolve 假设任务分布相对固定，通过线性链进化优化单一框架；而本文指出在异质任务流中，单一框架会因积累过多特化技能而失效。这一差异根源在于任务特性：预测市场等场景任务类型高度混杂，单一策略无法同时优化所有子域。本文通过分支隔离解决了这一问题，但未探索分支间知识共享机制，可能导致各分支独立进化效率低下。

从方法设计看，本文与 SkillOS 同属非参数化进化路线，但 SkillOS 通过强化学习训练策展策略，而本文采用多智能体协作与 Git 分支结构。SkillOS 依赖奖励信号优化技能选择，适用于奖励稀疏但可量化的场景；本文则依赖人类在环（HITL）钩子处理历史信号不足的情况。这种设计选择暗示，在开放环境中，完全自主的进化可能面临安全对齐风险，人类介入是必要的兜底机制。然而，论文未量化人类介入的频率与成本，其实际部署中的可扩展性存疑。

## 总结

本文要解决的核心矛盾是开放任务流中单一密集框架的过拟合与适应滞后问题。现有方法因缺乏对任务异质性与分布非平稳性的结构化处理，导致长期性能衰退。本文通过遗憾分解框架，将问题解耦为进化损失与适应损失，并分别以状态化多智能体进化器和推理时路由机制加以解决。实验证明，Full System 在 PolyBench Accuracy 达 80.9%，CTF-Dojo Pass@1 达 50.2%，显著优于最强基线。然而，论文未对比参数化强化学习方法，且依赖人类在环处理信号不足场景，其完全自主进化的能力边界尚不明确。当任务流中人类介入频率超过一定阈值时，该系统的自动化程度是否仍具优势，论文未给出回答。
