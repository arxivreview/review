论文原文见 [arXiv](https://arxiv.org/abs/2606.06462)

> 当前大语言模型评估面临的核心矛盾在于，静态基准的构建依赖大量人工劳动且迭代缓慢，而模型能力的快速提升导致现有基准迅速饱和，无法持续区分前沿模型的性能差异。现有自动化方案多聚焦于在固定基准上执行评估或生成训练数据，缺乏对基准构建全流程的端到端控制。本文提出 Benchmark Agent，通过“规划-执行”双组件架构，将用户自然语言需求自动转化为可运行的定制化基准。该框架在降低人工成本的同时实现了基准的持续刷新，但其生成基准的测量效度与统计保证仍缺乏严格验证。

## 研究背景

当评估者需要针对特定领域（如医疗影像或跨语言音频）构建新基准时，传统流程要求人工完成任务设计、数据清洗、标注与偏好对齐，这一过程不仅耗时且难以复用。这种“一次性构建”模式导致基准更新滞后于模型迭代速度，且每个新基准几乎从零开始，造成重复劳动。为解决此问题，研究界引入了多智能体系统（Multi-Agent Systems, MAS）来自动化部分流程，但现有工作主要局限于在既定基准上执行多轮评估（如 Evaluation Agent）或合成训练数据，尚未触及基准本身的动态生成与结构化管理。

领域内关于动态基准的探索主要集中在模型间互惠评估（如 AutoBench）或基于实时新闻的知识时效性测试（如 OKBench），这些方法解决了题目污染问题，但缺乏对基准内部结构（如子任务划分、数据接地、难度配额）的精细控制。Benchmark Agent 的切入点在于将基准构建视为一个长程决策任务，借鉴脑-小脑层级架构，将高层级的需求解析与低层级的数据执行解耦。它不依赖模型共识来生成题目，而是通过验证数据转换的可行性来确保基准的落地性，从而在自动化构建中保留了人工基准的结构严谨性。

## 核心方法

### 双组件架构参照系

本文问题属于自动化基准构建范畴，区别于传统的“模型互评”或“纯生成”路线。其核心差异在于引入“数据接地”（Grounding）机制，即每个子任务必须映射到真实数据集并验证转换可行性，而非仅由 LLM 凭空生成题目。这一设计旨在解决纯生成基准中常见的“幻觉题目”与“逻辑断裂”问题。

### 规划模块：子任务分解与接地验证

规划模块（Benchmark Planner）负责将抽象需求 $R$ 转化为结构化子任务集 $S$。设计动机在于解决单一 LLM 调用在处理长程任务时容易出现的“目标漂移”与“数据不可用”问题。该模块包含设计、接地与分配三个智能体。接地智能体（Grounding Agent）对每个子任务 $s_i$ 执行转换可行性验证，其核心判据为：

$$
\text{Valid}(s_i) \iff \exists (d_{i,j}, t_{i,j}) \in \mathcal{D}_i \times \mathcal{T} : \text{Score}(s_i, d_{i,j}, t_{i,j}) > \tau
$$

其中 $\mathcal{D}_i$ 为候选数据集，$t_{i,j}$ 为转换计划，$\text{Score}$ 评估对齐度、鲁棒性与信号保留度。只有当所有子任务均满足此条件时，规划才进入分配阶段，否则反馈至设计智能体修正。这一闭环机制确保了基准规格在数据层面的可执行性。

### 执行模块：样本级编排与质量控制

执行模块（Benchmark Executor）将规划转化为具体样本。设计动机在于解决数据集级转换规则在个体样本上的“过拟合”或“失效”问题。该模块采用“编排-执行”交替机制，LLM 根据当前样本状态动态调整转换动作，但受限于数据集级计划 $t_{i,j}$ 以防止发散。生成的样本需通过质量与配额控制，其有效性判定公式为：

$$
\mathcal{B}_{final} = \{ x \in \mathcal{B}_{raw} : \text{Verify}(x, s_i) = 1 \land \text{Quota}(s_i) \le Q_{max} \}
$$

其中 $\text{Verify}$ 检查语义有效性与格式合规性。无效样本被丢弃或局部重生成，直至满足配额。这种基于验证的补充机制保证了最终基准的样本量与质量稳定性，避免了因部分样本失败导致的基准结构残缺。

## 实验评估

实验基于 GPT-5.1 作为骨干模型，使用 General-Bench 作为数据池，构建了涵盖文本、音频、图像及多模态的 15 个基准。基线对比包括直接提示不同 LLM（如 GPT-5.4, Claude-Sonnet-4-6）构建基准，但未包含人工构建基准的量化成本对比，也未对比 AutoBench 等动态生成方法。

| 基准类型 | 人类接受率 (Acc) | UIA (意图对齐) | FSQ (格式质量) | TSD (目标信号依赖) |
| :--- | :--- | :--- | :--- | :--- |
| Multi-Perspective (T) | 97.65 | 76.77 | 87.93 | 63.36 |
| Omni-Understanding (O) | 96.09 | 68.54 | 99.66 | 49.71 |
| Art-Reasoning (I) | 98.65 | 74.06 | 99.70 | 66.04 |

数据显示，人类接受率普遍高于 96%，表明生成样本在表面质量上可靠。然而，UIA 分数在 68.54 至 81.48 之间波动，且 TSD 分数显著低于 FSQ，表明模型在“确保题目真正考察目标能力”方面存在短板。与直接提示 LLM 的基线相比，Benchmark Agent 在 UIA 上表现更稳定，但绝对值仍低于 80，暗示自动化构建在深层意图对齐上仍有提升空间。

消融实验显示，移除“转换可行性检查+计划评分”（TC + Scoring）导致 UIA 下降最显著（如 Omni-Understanding 从 68.54 降至 44.30），验证了接地机制对意图对齐的关键作用。移除“样本级规划”（SLP）则主要影响 TSD，表明细粒度控制对难度校准至关重要。

评估边界方面，论文未报告置信区间或统计显著性检验，仅依赖点估计。代码已开源，但依赖 GPT-5.1 闭源模型，限制了可复现性与开源社区的适用性。

## 关联研究分析

从问题动机看，Benchmark Agent 与 AutoBench 均旨在解决基准饱和与污染问题，但路径截然不同。AutoBench 依赖模型间互惠评估生成题目，其质量上限受限于参与模型的能力共识，且易受模型偏差影响；而 Benchmark Agent 依赖数据接地与转换验证，其质量下限由真实数据集支撑，但新颖性受限于数据池的覆盖范围。这种差异源于任务特性：AutoBench 适合探索模型未知能力边界，而 Benchmark Agent 适合构建结构化、可复现的领域特定评估。

从方法设计看，Benchmark Agent 与 MACEval 同属多智能体框架，但 MACEval 侧重评估路由与动态数据生成，缺乏对基准内部结构（如子任务划分、配额分配）的显式建模。Benchmark Agent 引入的 Allocation Agent 与 Transformability Validation 机制，将基准构建从“黑盒生成”转化为“白盒工程”，解决了 MACEval 中评估数据缺乏结构一致性的问题。然而，这种结构化控制是否限制了基准的“创造性”上限，论文未给出回答。

## 总结

Benchmark Agent 试图解决静态基准构建成本高、迭代慢与模型能力快速提升之间的结构性错位。其切入点在于将基准构建解耦为“规划”与“执行”两个层级，通过数据接地验证确保基准的可执行性，从而在自动化中保留了人工基准的结构严谨性。实验表明，该方法生成的基准人类接受率达 96-98%，UIA 分数在 68-81 之间，显著优于直接提示 LLM 的基线，但在目标信号依赖（TSD）上仍存在明显短板。其边界在于依赖闭源模型与固定数据池，且缺乏统计保证。当数据池覆盖范围有限时，接地机制是否会导致基准新颖性不足，从而无法有效区分前沿模型的深层能力差异，论文未给出回答。
