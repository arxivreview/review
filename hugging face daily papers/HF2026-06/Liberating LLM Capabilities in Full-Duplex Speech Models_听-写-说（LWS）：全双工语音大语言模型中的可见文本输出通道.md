# HuggingFace最新推荐论文 ｜Liberating LLM Capabilities in Full-Duplex Speech Models ｜听-写-说（LWS）：全双工语音大语言模型中的可见文本输出通道

研究机构：丰田研究所

作者：Luoyuan Zhang、Bokai Xu、Junbo Cui 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.07547)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.07547)

> 语音大语言模型（Speech LLMs）长期受限于“可说性”瓶颈，即模型必须将代码、表格等结构化文本压缩为线性语音，导致信息丢失与交互低效。现有全双工模型虽解决了实时性，却将文本降级为隐藏中间态，未将其作为用户可见的一等输出。本文提出 Listen-Write-Speak (LWS) 范式，通过 Token Schema 在单一自回归 Transformer 中并行执行听、写、说三通道，使文本成为与语音并列的主输出。该设计在保持全双工低延迟的同时，显著提升了复杂推理与结构化输出的质量，但其对长程推理深度的限制及输入模态的单一性仍构成主要边界。

## 研究背景

当开发者通过语音指令要求生成 Python 代码时，传统语音 LLM 只能逐字朗读代码，用户需手动转录，而文本 LLM 可直接返回可执行文件。这一差异源于语音模态的线性约束与文本模态的空间结构化特性之间的根本冲突。语音擅长处理轮次转换与语用协调，但无法承载精确、可回溯的复杂结构；文本则相反，适合持久化与空间组织。这种模态功能的不匹配导致语音交互中，模型最具价值的文本原生能力（如代码生成、数学推导）被强制投影至狭窄的“可说”子空间，造成能力抑制。

当前语音 LLM 研究主要聚焦于模态对齐与全双工交互。SHANKS 等模型实现了“边听边想”，但思维链（Chain-of-Thought, CoT）仅作为内部状态，用户不可见且不可编辑；Moshi 等全双工模型优化了重叠处理与低延迟，但输出仅限语音，缺乏结构化文本通道。这些方案共同假设文本是语音的辅助工具，而非独立输出。LWS 的切入点在于打破这一假设，将可见写作（Visible Writing）确立为与语音平级的一等输出通道，使模型在实时交互中同时提供可听的自然语言与可编辑的结构化文本，从而释放 LLM 的完整文本能力。

## 核心方法

### 三通道自回归架构

LWS 基于 MiniCPM-V 架构与 Qwen3-8B 骨干，采用标准自回归 Transformer，未引入额外解码器或跨通道融合模块。其核心在于将交互时间轴划分为 1 秒的 Unit，每个 Unit 内并行运行三个通道：持续监听用户音频的 Listening 通道、始终激活的 Visible Writing 通道（输出可见文本），以及仅在响应阶段激活的 Speaking 通道（输出语音）。三通道共享同一因果注意力上下文，音频、可见文本与语音 token 在同一计算图中参与注意力计算，无需显式对齐模块。这种设计将多模态对齐问题转化为语言建模问题，简化了训练目标，同时通过共享上下文实现了隐式信息融合。

### Token Schema 与因果一致性

LWS 通过特殊 token 定义通道边界，实现三通道行为的纯 token 级编码。在 Listening Unit 中，模型生成 `ls_cogn` 文本，仅基于已听到的音频进行增量推理；在 Speaking Unit 中，模型生成 `speak` 语音 token 与 `reply_cogn` 结构化文本。关键设计在于分离 `ls_cogn` 与 `reply_cogn`，因为两者条件信息不同：前者仅依赖用户输入，后者还依赖模型自身的响应生成。这种分离避免了全双工交互中的信息泄露，简化了下一 token 预测。

$$
\mathcal{L}_{total} = \mathbb{E}_{t} \left[ -\log P(x_t | x_{<t}, a_t, w_{<t}) \right]
$$

其中 $x_t$ 为当前 Unit 的生成 token（语音或文本），$a_t$ 为当前 Unit 的音频 token，$w_{<t}$ 为历史可见文本。该损失函数表明，模型在每一步预测时，同时条件于当前音频输入与历史可见文本，确保可见写作与语音生成在因果时间线上严格一致。

### 两阶段数据管道

训练数据需包含逐秒认知标注，但公开语料缺乏此格式。LWS 设计了两阶段管道：第一阶段离线合成，利用教师 LLM 从文本 QA 对生成三股文本流（流式推理链、语音响应、结构化响应），并施加严格因果约束，确保第 $t$ 秒的推理仅基于前 $t$ 秒已听到的输入；第二阶段在线构建，将文本流与真实音频及 CTC 对齐结合，构建 Unit 序列，并加入中断增强以模拟重叠行为。最终数据集包含 50 万条中英文样本，Unit 时长固定为 1 秒。

$$
\mathcal{D} = \{ (a_{1:T}, w_{1:T}, s_{1:T}) \mid w_t \sim P(\cdot | a_{1:t}), s_t \sim P(\cdot | a_{1:t}, w_{1:t}) \}
$$

该公式描述了数据生成的因果依赖：可见文本 $w_t$ 仅依赖前 $t$ 秒音频，语音 $s_t$ 依赖前 $t$ 秒音频与文本。这种因果一致性是 LWS 在实时交互中保持逻辑连贯的关键，避免了未来信息泄露导致的训练-推理偏差。

## 实验评估

LWS 在 URO-Bench、VoiceBench 与 Full-DuplexBench 上进行了评估。基线覆盖 GPT-4o-Audio、Moshi、Step-Audio 2 等主流模型，但缺乏纯文本 LLM 基线以隔离语音模态影响。在 URO-Bench 中文 Pro 子集上，LWS 取得 84.6 的平均分，超越 GPT-4o-Audio 的 83.3；在 VoiceBench AlpacaEval 上，LWS 得分 4.72，仅落后 GPT-4o-Audio 的 4.78 0.06 分。

| 基准 | 指标 | LWS | GPT-4o-Audio | Moshi | Step-Audio 2 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| URO-Bench (Zh Pro) | Avg | 84.6 | 83.3 | - | - |
| VoiceBench | AlpacaEval | 4.72 | 4.78 | - | - |
| Full-DuplexBench | Turn Taking Lat. | 0.48s | - | 0.26s | - |

消融实验显示，移除 `ls_cogn` 或 `reply_cogn` 均导致性能下降。例如，中文 Basic 平均分从 82.6 降至 77.9（移除 `ls_cogn`）或 73.7（移除 `reply_cogn`），表明可见写作在监听与响应阶段均对推理质量有显著贡献。通道一致性测试中，LWS 达到 92.6% 的写作-语音一致性，说明两通道输出在事实层面高度对齐，未因并行生成导致自相矛盾。

评估边界方面，LWS 未报告置信区间，且 Full-DuplexBench 的延迟指标（0.48s）虽优于商业模型，但略高于 Moshi（0.26s），表明三通道并行可能引入轻微延迟开销。代码与数据已开源，训练配置（32 A100 GPUs, 500K 样本）明确，可复现性良好。

## 关联研究分析

从问题动机看，LWS 与 SHANKS 均关注“边听边想”，但 SHANKS 将思维链视为内部状态，旨在优化后续语音生成，而 LWS 将思维链外化为可见文本，使其成为用户可编辑的一等输出。这一差异源于任务定义的不同：SHANKS 优化的是语音响应质量，LWS 优化的是文本原生能力的释放。LWS 的可见写作通道不仅提升了推理透明度，还允许用户在模型响应前介入修正，这是 SHANKS 架构无法实现的。

从方法设计看，LWS 与 Qwen3-Omni 均采用并行文本-语音架构，但 Qwen3-Omni 的文本通道主要用于合成控制或隐藏分析，而非用户可见的自由文本输出。LWS 通过 Token Schema 将文本提升为主输出，改变了多模态 LLM 的输出范式。然而，LWS 的输入仍限于语音，未支持代码、截图等多模态输入，这限制了其在复杂协作场景中的应用。相比之下，Moshi 虽实现了全双工，但缺乏文本通道，无法提供结构化输出。LWS 的三通道设计在保持全双工实时性的同时，弥补了 Moshi 在结构化输出上的缺失，但代价是增加了训练数据的构建复杂度与推理时的 token 开销。

## 总结

LWS 解决了语音 LLM 中“可说性”瓶颈与文本原生能力抑制的矛盾，通过 Token Schema 将可见写作确立为一等输出通道，在单一自回归 Transformer 中实现听、写、说并行。实验表明，LWS 在 URO-Bench 中文 Pro 子集上超越 GPT-4o-Audio，并在 VoiceBench 上接近顶级闭源模型，验证了可见写作对推理质量的提升。然而，LWS 的实时性约束限制了长程推理深度，且输入模态单一，未支持多模态上下文。当用户需要处理复杂工具调用或多步规划时，LWS 的 1 秒 Unit 时长是否足以支撑深度推理，论文未给出回答。
