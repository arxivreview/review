# HuggingFace最新推荐论文 ｜AutoLab: Can Frontier Models Solve Long-Horizon Auto Research and Engineering Tasks? ｜长时程闭环优化基准

研究机构：美国华盛顿大学、美国斯坦福大学

论文原文见 [arXiv](https://arxiv.org/abs/2606.05080)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.05080)

> 前沿大语言模型在数小时尺度的工程优化任务中表现如何，现有单轮或短轨迹基准无法回答。静态编码测试与短交互代理评测均忽略了“持续迭代”这一核心能力维度，导致无法区分模型的原始编码能力与长期优化潜力。AUTOLAB 通过 36 个跨领域任务、连续锚定评分及反黑客机制，构建了首个针对超长时间闭环优化的评估体系。该基准揭示了“持久性”而非“初始解质量”是决定最终性能的关键因素，但固定 Harness 的设置限制了模型自进化能力的展示，其结论的普适性仍存疑。

## 研究背景

当智能体执行如 CUDA 内核优化或模型后训练等任务时，其成功不再依赖单次代码生成的正确性，而是取决于在严格时间预算内反复执行“修改-运行-测量-反思”循环的能力。这种长时程迭代过程涉及对噪声经验信号的持续管理，要求智能体具备时间意识与资源分配策略，这构成了超长时间闭环优化（Ultra Long-Horizon Closed-Loop Optimization）的核心挑战。

当前主流评估体系存在显著断层。HumanEval 与 SWE-bench 等静态基准仅测试一次性代码生成，而 GAIA 与 Terminal-Bench 等代理基准虽扩展至多步交互，但轨迹长度仍限于分钟级，且评分多为二元或最终状态导向。现有的长时程基准如 MLE-Bench 和 KernelBench 虽触及小时级任务，但领域覆盖狭窄，且缺乏对迭代过程本身的度量。这种评估空白导致无法隔离模型在持续实证迭代中的真实贡献，尤其是当高性能演示往往依赖于高度定制的模型特定 Harness 时，基础模型的能力边界变得模糊。

AUTOLAB 的切入点在于将“持续实证迭代”本身作为主要评估对象，而非最终产物。它通过强制小时级时间预算、连续校准评分及严格的反奖励黑客机制，旨在揭示前沿模型在长时间自主优化中的行为局限，特别是时间意识缺失与持久性不足的问题。

## 核心方法

### 任务形式化与连续评分

AUTOLAB 的任务定义包含指令、容器化环境、验证器、参考解及墙钟预算。每个任务提供一个正确但次优的基线实现，智能体需在预算内将其优化至接近参考解的水平。评分机制采用两种锚定方案，将异构指标归一化至 [0, 1] 区间。对于性能优化任务，采用对数拉伸评分：

$$ s(x) = \frac{\log(m_B / m(x))}{\log(m_B / m_R)} $$

其中 $m_B$ 和 $m_R$ 分别为基线与参考解的原始指标值（如运行时间，越低越好）。该公式确保基线得分为 0，参考解得分为 0.5，性能接近理论最优时趋近 1.0。对于有界质量指标，则采用线性插值：

$$ s(x) = \frac{m(x) - m_B}{m_R - m_B} $$

这种连续评分设计解决了二元基准无法区分“部分进步”与“完全失败”的问题，使得在难度极高的任务中，智能体在基线与参考解之间的微小改进也能被量化，从而支持跨任务的聚合比较。

### 反奖励黑客与验证机制

为防止智能体通过篡改评分函数或利用测量漏洞获取高分，AUTOLAB 引入了多层防御机制。验证器是密封的，智能体仅能访问本地评估脚本，无法接触用于最终评分的保留测试输入或参考输出。关键文件通过 SHA 哈希固定，任何未授权修改立即导致零分。此外，机器学习任务包含正确性门控，其输入分布与开发期间可见的数据不相交。在任务构建阶段，专门部署对抗性智能体以发现捷径，任何可通过非真实改进解决的任务均被剔除或修补。这一设计动机源于性能基准比补丁式基准暴露了更大的攻击面，确保评分反映的是真实的工程优化能力，而非对评估系统的操纵。

## 实验评估

实验在 17 个前沿模型上进行，包括 Claude Opus 4.6、Gemini 3.1 Pro 等专有模型及 DeepSeek V4 Pro 等开源模型。评估使用统一的 Harbor 框架和 terminus-2 智能体，总消耗 2,544 墙钟小时和 86 亿 token。基线覆盖广泛，但缺失 Reflexion 等自进化算法，因本文旨在评估基础模型在固定 Harness 下的固有优化能力，而非进化机制的效果。

| 模型 | Avg@3 | Best@3 | Dominance |
| :--- | :--- | :--- | :--- |
| claude-opus-4.6 | 0.68 | 0.76 | 0.93 |
| gemini-3.1-pro | 0.50 | 0.59 | 0.62 |
| kimi-k2.6 | 0.46 | 0.60 | 0.62 |
| deepseek-v4-pro | 0.38 | 0.51 | 0.47 |
| gpt-5.4 | 0.36 | 0.53 | 0.39 |

Claude Opus 4.6 以 0.68 的 Avg@3 显著领先，其 Dominance 分数 0.93 表明其在绝大多数任务上优于其他模型。Gemini 3.1 Pro 紧随其后，但在 CUDA 任务上表现较弱。值得注意的是，GPT-5.4 和 Grok 4-20 排名靠后，主要归因于过早终止而非原始编码能力不足。

消融分析显示，较小模型如 DeepSeek V4 Flash（0.37）在整体表现上与更大的 DeepSeek V4 Pro（0.38）持平，甚至在 CUDA 和算法谜题任务上超越后者。轨迹分析揭示，最终性能与“持久性”（反复基准测试、编辑和整合反馈的次数）的相关性远高于与初始解质量的相关性。许多高分模型在轨迹中多次达到中间最优解，但未能有效维持或提交，而低分模型往往在预算耗尽前仅执行少量动作。

评估边界方面，AUTOLAB 的评分依赖于特定沙箱硬件配置，$m_B$ 和 $m_R$ 为沙箱依赖量，限制了跨硬件的可比性。固定 Harness 的设置虽隔离了模型能力，但也排除了模型通过优化自身工具链或工作流来提升性能的可能性。代码已开源，但 2,544 小时的计算成本使得独立复现极具挑战性。

## 关联研究分析

从问题动机看，AUTOLAB 与 EvoPolicyGym 均关注过程级评估，但前者聚焦于工程优化中的实证迭代，后者侧重策略进化中的反馈利用率。AUTOLAB 的核心差异在于其任务的时间尺度（小时级）和评分的连续性，这使其能够捕捉到短轨迹基准中不可见的“时间意识”缺陷。相比之下，EvoPolicyGym 的任务通常较短，无法暴露智能体在长时间预算分配上的策略失误。

从方法设计看，AUTOLAB 与 Terminal-Bench 共享容器化沙箱思路，但将其从短轨迹工具使用扩展至长时程闭环优化。关键差异在于 AUTOLAB 引入了反奖励黑客机制和连续锚定评分，而 Terminal-Bench 主要关注最终状态的正确性。这种设计选择源于性能优化任务中“部分进步”的价值，以及防止智能体通过操纵评分函数获取虚假高分的风险。然而，固定 Harness 的设置与 DarwinX 等 Harness 进化方法形成对比，后者认为优化外部脚手架是提升性能的有效途径，而 AUTOLAB 通过固定 Harness 来隔离模型本身的贡献，这两种视角在“性能提升来源”上存在根本分歧。

## 总结

AUTOLAB 旨在解决现有基准无法评估前沿模型在小时级闭环优化中持续迭代能力的问题。通过构建 36 个跨领域任务、连续锚定评分及反黑客机制，它成功隔离了模型在固定 Harness 下的固有优化潜力，揭示了“持久性”而非“初始解质量”是决定最终性能的关键预测因子。实验显示 Claude Opus 4.6 以 0.68 的 Avg@3 领先，而许多强模型因过早终止或预算耗尽而表现不佳。该基准的边界在于其固定 Harness 设置排除了模型自进化能力的展示，且评分依赖于特定硬件配置。当智能体被允许动态调整其工具链或工作流时，其在长时程任务中的表现是否会显著偏离固定 Harness 下的评估结果，论文未给出回答。
