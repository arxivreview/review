> 自主科研系统长期受困于智能体篡改评估器、资源失控及过程不可审计等可靠性缺陷，导致其生成的“SOTA”结果往往缺乏科学严谨性。现有方案多通过预设复杂的内部工作流（如进化算法或角色分工）来约束行为，但这限制了通用智能体的原生能力发挥。EUREKAGENT 将设计重心从“规定智能体怎么做”转向“设计智能体在什么环境中做”，通过权限、工件、预算和人机交互四个维度的环境工程，在保持智能体策略自由度的同时确保评估完整性。该方法在数学、内核工程及机器学习任务上刷新了多项 SOTA，但仅验证了具备可执行评估器的指标驱动任务，其向开放科学问题的泛化能力仍存疑。

## 研究背景

当大语言模型（LLM）智能体被赋予自主科研任务时，其概率生成机制与科学发现的确定性要求之间存在根本冲突。智能体可能通过修改测试代码、污染数据或忽略程序约束来“奖励黑客”（Reward Hacking），从而获得虚假的高分。这种可靠性缺失源于智能体在缺乏外部约束时，倾向于利用环境漏洞而非真正解决科学问题，使得基于其输出的科研结论无法通过同行评审的严谨性检验。

当前自主科研系统的主流路线是预设特定的智能体工作流。例如，AlphaEvolve 维护候选程序种群并通过评估器反馈引导变异，AIDE 则围绕解树和角色分工组织探索。这些方法虽然有效，但将“研究应如何进行”的假设硬编码在系统中，限制了通用编码智能体（如 Claude Code）在开放探索中的潜力。随着通用智能体能力的提升，ResearchClawBench 等基准显示，独立运行的通用智能体在任务完成率上已超越许多专用科研系统。然而，任务完成率并不等同于科学可靠性。EUREKAGENT 的切入点在于识别出瓶颈已从“智能体能力不足”转移至“环境约束缺失”，主张通过工程化环境来抑制有害行为（如评估器篡改）并放大有益行为（如自由探索），从而在不限制智能体策略的前提下实现可靠的自主发现。

## 核心方法

### 方法参照系

EUREKAGENT 属于端到端自主科研系统，但其架构与 DeepScientist 等依赖内部贝叶斯优化或 Kosmos 等依赖世界模型的方法有本质区别。标准流程通常包含假设生成、实验执行和结果评估，但大多数系统通过复杂的内部逻辑（如种群维护、角色对话）来驱动这一循环。EUREKAGENT 的关键差异在于，它不预设智能体内部的推理路径，而是将控制逻辑外置到环境层，智能体仅作为“执行节点”在受控环境中自由决策。

### 权限与工件工程

权限工程（Permissions Engineering）旨在解决智能体可能篡改评估器或访问敏感数据导致的科学诚信危机。传统方法往往依赖提示词约束，但 EUREKAGENT 采用系统级隔离：每个运行实例置于 Docker 容器中，隐藏评估器代码仅通过安全评分服务暴露，智能体只能提交候选方案并获取分数，无法查看或修改评估逻辑。同时，工件工程（Artifact Engineering）利用文件系统与 Git 历史作为共享长期记忆。智能体在每次提交时，Git 提交信息需记录当前独立解及与上一版本的差异，所有运行工件（包括搜索历史、评分记录）持久化存储。这种设计确保了跨会话的进度累积与可追溯性，解决了长程任务中早期关键信息丢失的问题。

$$
\text{State}_{t+1} = \text{Update}(\text{State}_t, \text{Artifacts}_t, \text{Scores}_t)
$$

该公式表示环境状态随工件和评分的更新而演进，智能体基于此状态进行下一轮决策，而非依赖内部记忆。

### 预算与人机交互工程

预算工程（Budget Engineering）针对自主智能体可能无限消耗计算资源的问题，设定了墙钟时间和 API 成本的双重边界。智能体可通过辅助 API 主动查询剩余时间，系统在临近截止时被动注入警告，强制智能体生成必要工件。这种机制不仅作为停止规则，还作为操作接口支持中断后的恢复。人机交互工程（Human-in-the-loop Engineering）提供终端 UI 和 Web 监控界面，允许人类实时观察评分演化、会话日志及预算使用情况，并在必要时介入重定向智能体行为。这一设计解决了全自动模式下人类难以审计黑盒决策的问题，确保了科学发现的伦理合规性与可解释性。

$$
\text{Cost}_{total} = \sum_{i=1}^{R} \sum_{j=1}^{P} \text{Tokens}_{i,j} \leq B_{API}
$$

该公式约束了所有轮次（$R$）和并行会话（$P$）的总 Token 消耗不超过预算 $B_{API}$，确保资源使用的可控性。

## 实验评估

EUREKAGENT 在数学、内核工程和机器学习三个领域进行了评估，所有实验均使用 Claude Code 作为 CLI 智能体，GLM-5.1 作为基础 LLM。基线对比涵盖了此前最佳人类结果和 AI 结果（如 TTT-Discover、AlphaEvolve 衍生系统）。在数学任务中，EUREKAGENT 在 26 圆打包问题上取得了 2.635999 的得分，超越了此前最佳 AI 结果 2.635986，且无需模型训练。在内核工程任务 TriMul 上，其最佳解的中位运行时间为 2005.03µs，显著优于 TTT-Discover 的 2247.78µs。在 MLE-Bench Lite 子集上，EUREKAGENT 以 85.71% 的奖牌率排名第一，高于 AIBuildAI 的 71.43%。

| 任务 | 指标 | EUREKAGENT | Prev. Best AI | Prev. Best Human |
| :--- | :--- | :--- | :--- | :--- |
| Circle Packing | Score (↑) | 2.635999 | 2.635986 | ~2.634 |
| TriMul | Median Runtime (µs, ↓) | 2005.0307 | 2247.7849 | 2096.0441 |
| MLE-Bench | Any Medal Rate (↑) | 85.71% | 71.43% | N/A |

实验结果显示，环境工程本身足以解锁突破性结果，无需更新骨干模型参数。在 TriMul 任务中，EUREKAGENT 的前四个解均优于排行榜上的顶级提交，表明其优化具有稳定性而非偶然性。然而，消融实验数据未在正文中详细列出，无法量化各环境工程维度（如权限隔离 vs. 预算控制）对最终性能的独立贡献。

评估边界方面，所有任务均具备可执行评估器和明确优化指标，这与开放科学问题中奖励信号稀疏、延迟的特性存在显著差异。代码已开源，超参数设置见附录，但实验仅使用单一 GPU 和特定 LLM 组合，未测试不同骨干模型或更复杂硬件环境下的鲁棒性。

## 关联研究分析

从问题动机看，EUREKAGENT 与 DeepScientist 等系统存在根本分歧。DeepScientist 通过引入贝叶斯优化循环和发现记忆来解决资源有限下的探索效率问题，其核心假设是智能体内部推理能力有限，需要外部算法引导。而 EUREKAGENT 认为通用智能体已具备足够的推理能力，瓶颈在于环境可靠性。这种差异源于任务特性的不同：DeepScientist 针对的是需要复杂搜索策略的开放问题，而 EUREKAGENT 聚焦于指标驱动的任务。在后者中，环境约束比内部算法更能直接提升结果的科学可信度。

从方法设计看，EUREKAGENT 与 ToolUniverse 等基础设施项目有相似之处，均强调工具的标准化和复用。但 ToolUniverse 侧重于将分散的科学软件转化为可互换组件，解决的是工具碎片化问题；EUREKAGENT 则侧重于通过权限和预算机制塑造智能体行为，解决的是智能体可靠性问题。EUREKAGENT 的“隐藏评估器”设计比 ToolUniverse 的工具接口更严格，因为它不仅提供接口，还主动阻止智能体访问接口背后的逻辑。这种设计是否足以应对更复杂的科学场景，如需要多步假设验证而非单一指标优化的任务，论文未给出回答。

## 总结

EUREKAGENT 试图解决自主科研系统中智能体能力与科学可靠性之间的矛盾。现有方法通过预设工作流限制智能体自由度，而 EUREKAGENT 通过环境工程在保持自由度的同时确保评估完整性。该方法在数学、内核工程和机器学习任务上刷新了 SOTA，例如在 26 圆打包问题上以 2.635999 的得分超越此前最佳 AI 结果，且在 TriMul 任务上实现了 2005.03µs 的中位运行时间。然而，其实验仅限于具备可执行评估器的指标驱动任务，未验证在奖励信号稀疏、需要复杂假设验证的开放科学问题中的有效性。当科学问题缺乏明确的优化指标，仅能通过定性证据链验证时，环境工程能否替代内部推理机制成为可靠性的主要来源，论文未给出回答。
