# HuggingFace最新推荐论文 ｜DailyReport: An Open-ended Benchmark for Evaluating Search Agents on Daily Search Tasks ｜日常搜索智能体评估基准

研究机构：中国科学技术大学、美团

作者：Jingxuan Han、Wei Liu、Mingyang Zhu 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.12871)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.12871)

> 深度研究智能体（Deep Research Agents, DRA）在开放式信息检索中面临评估维度粗粒度与用户视角缺失的双重困境，现有基准多依赖专家构建的静态任务，无法量化真实用户的感知满意度。DailyReport 通过源自实时热点的日常搜索任务与级联评分协议，将评估重心从专家标准转向用户偏好。该基准揭示了当前前沿智能体在事实性与用户满意度上的显著短板，但其未涵盖强化学习训练型智能体的对比，结论的泛化性存疑。

## 研究背景

当智能体面对“列出2026年QS前100中国大学并分析优劣”这类查询时，若未能正确识别大学名单，后续分析对用户而言毫无价值。这种层级依赖关系揭示了传统评估中各维度独立打分的失效：指令遵循（Instruction Following）是事实性（Factuality）与理性（Rationality）评估的前提，缺乏这种级联逻辑会导致评分与用户实际体验脱节。

深度研究智能体的评估长期依赖 BrowseComp 或 DeepResearch Bench 等基准，这些工作多由领域专家构建专业化任务，侧重高难度导航或报告生成质量，但任务静态且脱离日常场景，且采用线性加权聚合粗粒度评分，无法解释性能差异来源。随着智能体能力向日常实用场景延伸，评估需捕捉动态、时效性强的用户信息需求，并量化“用户偏好”这一核心指标。DailyReport 正是在此背景下提出，旨在通过实时热点任务与用户中心级联评估，填补日常场景下智能体能力评估的空白。

## 核心方法

### 任务构建与级联评分框架

现有基准如 BrowseComp 采用固定答案或专家定义的任务，缺乏动态更新机制，且评分维度独立。DailyReport 从微博、Facebook 等平台收集实时热点，由专家转化为 150 个开放式任务（100 个检索中心、50 个分析中心），覆盖 10 个宏观领域与 35 个细分类别。每个任务分解为原子子任务，并生成级联评分标准（Cascade Rubrics），确保评分反映用户感知的层级优先级。

### 级联性能归因

传统方法对指令遵循、事实性、理性独立打分，忽略了维度间的依赖关系。DailyReport 引入级联归因机制：仅当子任务满足指令遵循要求时，才评估其事实性与理性。设 $T_i$ 为第 $i$ 个子任务，$Res = SA(T_i)$ 为智能体响应，维度得分 $dim_i$ 由评判模型基于对应评分标准 $r_{dim}(T_i)$ 计算：

$$
dim_i = \text{Judge}_{dim}(Res, r_{dim}(T_i))
$$

其中 $dim \in \{ins, fac, rat\}$。事实性得分 $fac_i$ 仅在 $ins_i = 1$ 时有效，否则视为 0，避免对缺失内容的无效评估。该设计解决了独立评分中“错误指令下的事实性高分”悖论，使评分更贴近用户实际体验。

### 用户中心聚合算法

线性加权聚合无法区分子任务的重要性差异，导致用户偏好量化失真。DailyReport 通过消融实验确定每个子任务的用户感知重要性（$P_0$ 至 $P_2$ 等级），并设计规则化聚合算法计算用户偏好得分（UserPref）：

$$
\text{UserPref} = f(\{o_k\}, \{p_k\})
$$

其中 $o_k \in [0,1]$ 为子任务 $k$ 的性能得分，$p_k$ 为其重要性等级。算法优先检查 $P_0$ 级子任务（缺失导致响应不可用），若全部满足则进一步评估 $P_1$ 级（缺失导致显著缺陷），最终输出 1-4 分的用户偏好等级。该机制将用户感知重要性显式纳入评分，解决了线性聚合中“次要错误掩盖核心缺陷”的问题。

## 实验评估

实验覆盖 17 个前沿智能体系统，分为原生深度研究智能体（如 OpenAI o3 Deep Research）、搜索增强 LLM（如 GPT 5.4）及 Claude Code 增强 LLM 三组。基线未包含 ASearcher、ABSeeker 等强化学习训练型智能体，可能因评估协议不兼容或系统未公开。主结果显示，搜索增强 LLM 表现最佳，GPT 5.4 在用户偏好（2.89）、子任务通过率（0.484）、事实性（0.835）上均领先，但所有系统的用户偏好得分均低于“可接受”阈值 3，表明当前智能体在用户满意度上存在显著差距。

| 系统类型 | 代表系统 | UserPref | SubTask Pass | Factuality |
| :--- | :--- | :--- | :--- | :--- |
| 搜索增强 LLM | GPT 5.4 | 2.89 | 0.484 | 0.835 |
| 原生 DRA | Grok 3 Deep Research | 2.48 | 0.301 | 0.731 |
| Claude Code 增强 | CC-GPT 5.4 | 2.87 | 0.478 | 0.813 |

消融分析显示，分析中心任务在指令遵循与理性上略优，但事实性更低，因其开放式分析导致证据分散，难以交叉验证。追踪分析表明，搜索调用次数与整体性能强相关，而引用支持率（Reference_Support）普遍低于无引用支持率（No_Reference_Support），揭示智能体在事实性上的瓶颈并非缺乏引用，而是引用内容本身的不准确性。

评估边界方面，DailyReport 依赖 Gemini-3-Flash 作为评判模型，其准确率（96.5%）高于人类标注（88.4%），但事实性与理性的评判仍受限于评判模型的能力。代码已开源，但任务集基于特定时间点的热点，动态更新机制的长期稳定性未经验证。

## 关联研究分析

从问题动机看，DailyReport 与 DeepResearch Bench 均关注开放式报告评估，但前者侧重用户偏好量化，后者侧重检索与报告质量的分离评估。这一差异源于任务场景的不同：DeepResearch Bench 面向专业研究任务，用户为专家，评估需侧重深度与准确性；DailyReport 面向日常用户，评估需侧重实用性与满意度。然而，用户偏好与洞察深度是否正相关，论文未提供证据，若两者负相关，则用户中心评估可能牺牲深度研究的严谨性。

从方法设计看，DailyReport 的级联归因与 BrowseComp 的独立评分形成对比。BrowseComp 假设各维度独立，适合高难度导航任务；DailyReport 的级联逻辑更贴合日常任务的层级依赖，但增加了评估复杂度。这种设计选择是否更鲁棒，论文未提供消融实验对比，若级联逻辑在特定任务类型（如纯检索任务）中引入偏差，则其普适性存疑。

## 总结

DailyReport 旨在解决深度研究智能体评估中用户视角缺失与维度独立评分的矛盾，通过实时热点任务与级联归因机制，将评估重心转向用户偏好。该基准证明了当前前沿智能体在事实性与用户满意度上的不足，GPT 5.4 的用户偏好得分仅为 2.89，低于可接受阈值。其边界在于未对比强化学习训练型智能体，且任务集基于静态时间点，动态更新机制的长期有效性未验证。当任务集更新后，级联归因逻辑是否仍能准确捕捉用户偏好的变化，论文未给出回答。
