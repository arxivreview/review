# HuggingFace最新推荐论文 ｜A Verifiable Search Is Not a Learnable Chain-of-Thought ｜可验证搜索不可蒸馏为思维链

作者：Harsh Patel

论文原文见 [arXiv](https://arxiv.org/abs/2606.21884)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.21884)

> 该方向旨在解决“可解程序”向小模型思维链（Chain-of-Thought, CoT）蒸馏时的性能鸿沟问题。现有方法假设只要存在完美求解器，其步骤即可通过监督微调（SFT）或强化学习（RL）被模型习得，但这一假设在涉及回溯搜索的任务上彻底失效。本文通过构建确定性生成器基准，量化了求解器覆盖率与模型可学习性之间的断裂，并证明“前向可推导性”是决定蒸馏成败的因果边界。其价值在于提供了搜索型任务不可学习的机制解释，但结论局限于特定架构与任务类型，对通用推理能力的泛化性存疑。

## 研究背景

当大语言模型面对需要多步逻辑推导的任务时，思维链（CoT）通过生成中间步骤提升了准确率，但其自回归特性导致推理链冗长且计算成本高企。早期研究聚焦于通过长度惩罚或剪枝控制推理长度，但受制于离散 Token 的表达瓶颈。随着强化学习（Reinforcement Learning, RL）结合可验证奖励（RLVR）的普及，长 CoT 成为主流，研究重心转向效率与准确率的平衡。然而，一个被忽视的假设是：如果存在一个能解决所有实例的短程序，该程序就能被写成自然语言步骤并蒸馏给小模型。这一假设在涉及回溯搜索的任务上面临挑战，因为搜索过程包含大量“尝试-拒绝”的分支，无法简化为线性的前向推导。

该领域要解决的核心矛盾是推理深度与计算效率之间的张力，以及模型能否忠实模拟复杂算法逻辑。主流路线包括显式压缩（如 UCoT、SLAT）和潜在推理（如 CODI、PCCoT），前者通过语义剪枝减少 Token 冗余，后者通过连续潜在空间突破离散瓶颈。然而，这些方法均假设推理过程是可被线性化或连续化表示的。目标论文的切入点在于挑战这一假设，指出对于“信息自由结构”上的回溯搜索，不存在忠实的前向 CoT，导致 SFT 仅学习其表面形式而非逻辑。

## 核心方法

### 方法参照系

本文问题置于 CoT 蒸馏的通用流程中：反向工程生成器为求解器，渲染合成 CoT，通过 SFT 将程序步骤安装至小模型。与标准蒸馏流程的关键差异在于，本文引入了“前向可推导性”作为筛选指标，并针对搜索型任务设计了因果干预实验，以区分“能力不足”与“表示瓶颈”。

### 前向可推导性作为因果边界

设计动机在于解决 SFT 在搜索任务上失效却无法归因于模型能力的问题。通常做法是将求解器的完整步骤（包括回溯）渲染为 CoT，但本文发现这种“展示搜索”的轨迹导致模型陷入循环或截断。本文创新在于定义“前向可推导性”：任务是否存在一条从左到右、无需回溯即可到达答案的推导路径。对于加密算术（Cryptarithm）任务，其唯一解是回溯搜索，前向可推导比例约为 $1/659$。通过因果干预实验，揭示密钥（使推导变为前向）将同一实例的准确率从 $0.03$ 提升至 $0.571$，证明前向可推导性是蒸馏成功的因果杠杆，而非模型规模或架构。

### Verdict-as-Token 机制

设计动机在于解释为何 SFT 在搜索任务上产生“看似推理实则无效”的输出。通常做法假设模型模仿 CoT 的逻辑结构，但本文通过逐行审计发现，模型在算术计算上正确率高达 $97-100\%$，但在关键决策点（Verdict）上，输出退化为无条件模板，正确率仅为 $16-57\%$。这一现象被称为“Verdict-as-Token”，即模型学习了消除步骤的表面形式，但将其与逻辑证据解耦。公式上，这表现为决策概率 $P(v|e)$ 中证据 $e$ 的权重趋近于零，导致模型在无法前向推导时，仅凭上下文先验生成答案，而非基于当前行证据进行推理。

## 实验评估

实验在 9 个确定性生成器任务上进行，基准具有“训练集≡测试集”属性，确保评估无泄漏。基线覆盖 SFT、RLVR/GRPO 和 STaR，但缺失推测解码等系统级优化，因本文聚焦模型级学习。主结果显示，前向可计算任务（如罗马数字、单位转换）的模型准确率接近求解器（$\approx 1.00$），而搜索型任务（加密算术）的模型准确率仅为 $0.01-0.07$，尽管求解器准确率为 $0.71$。

| 任务类别 | 求解器准确率 | 模型准确率 (SFT) | 前向可推导比例 |
| :--- | :--- | :--- | :--- |
| 罗马数字 | 1.00 | $\approx 1.00$ | 高 |
| 单位转换 | 1.00 | $\approx 1.00$ | 高 |
| 位操作 | 0.989 | 0.678 | 中 |
| 加密算术 (Deduce) | 0.71 | 0.01–0.07 | $\approx 0$ |

消融实验表明，RLVR 在搜索任务上梯度存在但不转移，因正样本在真实实例中过稀；STaR 仅在位操作（前向可计算）上有效，将准确率从 $0.526$ 提升至 $0.678$。架构控制实验显示，在 3B 至 671B 的不同骨干（Mamba/MoE/Transformer）上，搜索蒸馏天花板均低于 $0.04$，证明该失败是架构通用的，而非特定于状态空间模型。

评估边界在于基准仅包含确定性生成器任务，缺乏对通用推理能力的评估；可复现性方面，论文提供了求解器与审计代码，但依赖特定竞赛平台（Kaggle）的 LoRA 服务，超参数（如 rank-32）可能限制结论的泛化性。

## 关联研究分析

从问题动机看，本文与 UCoT、SLAT 等 CoT 压缩方法形成互补。UCoT 通过解耦压缩器与执行器优化 Token 效率，假设推理逻辑可被压缩而不损失关键信息；本文则证明，对于搜索型任务，压缩或蒸馏逻辑本身是无效的，因为不存在可压缩的忠实前向轨迹。这一差异源于任务特性：算术任务具有线性推导结构，而搜索任务具有分支结构，前者适合压缩，后者适合记忆化。

从方法设计看，本文与 CODI、PCCoT 等潜在推理方法存在潜在矛盾。潜在推理假设连续空间可突破离散 Token 瓶颈，提升推理带宽；本文则揭示，即使使用连续表示，若任务本质是搜索，模型仍无法忠实模拟其逻辑，除非将搜索结构预计算为有限目录并记忆化。这一冲突暗示，潜在推理的有效性可能依赖于任务的前向可推导性，而非单纯的表示形式。

## 总结

本文要解决的核心矛盾是“可解程序”与“可学习 CoT”之间的鸿沟，现有方法因假设推理可线性化而失效。本文抓住“前向可推导性”这一被忽略的因果边界，通过因果干预实验证明其决定蒸馏成败。方法上，本文构建了确定性生成器基准，量化了求解器与模型的性能差距，并识别出“Verdict-as-Token”机制。实验证明，搜索型任务的蒸馏天花板低于 $0.07$，而前向可计算任务可达 $0.99$。本文的边界在于结论局限于确定性生成器任务，未验证在开放域推理任务上的普适性。当任务结构从确定性搜索转向模糊推理时，前向可推导性是否仍是有效的筛选指标，论文未给出回答。
