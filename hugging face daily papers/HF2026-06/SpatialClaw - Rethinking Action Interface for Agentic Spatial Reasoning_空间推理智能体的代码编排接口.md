> 视觉-语言模型（Vision-Language Models, VLMs）在处理三维几何关系时，常因缺乏显式几何证据而产生空间幻觉。现有工具增强智能体受限于单次代码执行或固定 API 调用，无法在推理过程中动态组合感知输出以应对测试时涌现的计算需求。SpatialClaw 提出将代码作为动作接口，通过持久化 Python 内核实现多轮迭代、中间状态检查与动态代码生成。该框架在 20 个基准上平均准确率达 59.9%，较基线提升 11.2 个百分点，但其性能仍低于经过专门训练的强化学习模型，且未报告计算开销。

## 研究背景

当 VLM 面对“哪辆车离桌子最近”这类问题时，其内部语言骨干主导的推理路径与视觉编码器中分布式的空间信号存在解耦。这种解耦导致模型依赖语言统计规律而非视觉证据，产生与输入矛盾的空间描述，即空间幻觉。为抑制幻觉，研究界尝试注入显式几何约束，但 VLM 自身难以从像素中可靠地执行深度估计、相机位姿解算等结构化几何分析，这构成了引入外部感知工具的必要性。

工具增强型智能体旨在通过调用检测器、分割器或深度估计器来弥补 VLM 的几何短板。然而，现有方案在动作接口设计上存在瓶颈：单次代码执行要求智能体在观察任何中间结果前就确定完整分析策略，而结构化工具调用则受限于预定义的命令模式，难以表达仅在测试时才能确定的复杂组合计算。SpatialClaw 的切入点在于重新定义动作接口，将代码视为一个编排空间，允许智能体在持久化内核中逐步组合感知工具与数值原语，根据中间证据动态调整分析路径。

## 核心方法

### 动作接口参照系

工具增强智能体的标准流程通常包含感知工具调用与结果整合两个环节。本文问题与该通用流程的关键差异在于，传统接口将工具调用视为原子操作或一次性程序，而 SpatialClaw 将代码执行过程本身作为可迭代、可观察的状态机，使得中间变量成为后续推理的一等公民。

### 持久化内核与状态保持

SpatialClaw 的核心创新在于构建了一个持久化 Python 内核，该内核在智能体执行过程中保持所有中间结果作为普通 Python 变量。设计动机在于解决单次代码执行中中间视觉证据无法参与推理循环的失效问题。内核预加载输入帧、感知工具（如 SAM3、Depth Anything 3）及科学库（NumPy、SciPy），智能体每步生成一个可执行代码单元，其输出（掩码、深度图、点云）保留在内存中。状态保持机制可用以下公式表示：

$$ S_{t+1} = S_t \cup \{ \text{exec}(C_t, S_t) \} $$

其中 $S_t$ 为第 $t$ 步前的变量状态，$C_t$ 为生成的代码单元，$\text{exec}$ 表示执行并返回新变量。这意味着第 $t+1$ 步的代码可以直接访问第 $t$ 步产生的掩码或深度数组，无需重新计算或序列化传输。

### 迭代反馈与动态组合

在持久化状态基础上，SpatialClaw 引入了基于中间反馈的迭代循环。设计动机在于解决结构化工具调用无法表达测试时涌现计算的局限。智能体每步执行后，系统组装包含标准输出、变量摘要及渲染图像的反馈，追加至模型上下文。下一轮代码生成条件于这些反馈，允许智能体检查掩码有效性、修正几何计算或引入新的数值原语。动态组合过程可形式化为：

$$ C_{t+1} = \text{LLM}(Q, \text{Docs}, S_t, F_t) $$

其中 $Q$ 为问题，$\text{Docs}$ 为工具文档，$F_t$ 为第 $t$ 步的反馈。这种机制使得智能体能够根据中间证据（如分割掩码质量不佳）动态调整策略，例如从质心距离计算切换到基于 KDTree 的最近点搜索，从而适应复杂 3D/4D 推理任务中不可预见的计算需求。

## 实验评估

实验在 20 个空间推理基准上进行，涵盖单图像、多视角、视频 4D 及通用视频理解。基线包括无工具、单次代码执行、结构化工具调用及 SpaceTools、pySpatial 等近期智能体。SpatialClaw 在 Gemma4-31B 骨干上平均准确率达 59.9%，较 SpaceTools 提升 11.2 个百分点。

| 基准 | No-tool | Single-Pass | Structured | SpatialClaw |
| :--- | :--- | :--- | :--- | :--- |
| MindCube | 57.5 | 67.1 | 72.8 | 72.8 |
| MMSI | 37.9 | 33.2 | 51.3 | 51.3 |
| VSI-Bench-U | 48.0 | 44.4 | 48.5 | 48.5 |
| DSI-Bench | 45.3 | 43.7 | 62.9 | 62.9 |

消融实验显示，移除感知工具（SAM3/DA3）导致性能大幅下降，而移除效用函数（如 `tools.Mask`）影响较小，表明显式几何接地是性能提升的关键。在 13 个元类别中，SpatialClaw 在 11 个类别上优于基线，增益最大的是需要多步几何组合的类别，如相机运动和多视角推理。

评估边界方面，论文未报告计算开销或推理延迟，仅关注准确率。所有实验使用相同超参数和系统提示，未进行模型特定调优。代码已开源，但部分基准（如 VADAR）不支持视频输入，导致对比不完整。

## 关联研究分析

从问题动机看，SpatialClaw 与 STAR-R1 均旨在解决多视角空间推理中的视角转换失败，但路径截然不同。STAR-R1 依赖强化学习微调模型内部表征，而 SpatialClaw 主张通过外部代码接口注入几何证据，无需修改模型权重。这一差异源于对“空间智能来源”的不同假设：前者认为空间能力内化于模型参数，后者认为空间能力可通过外部工具动态组合实现。SpatialClaw 的 training-free 特性使其在跨模型泛化上占优，但绝对性能低于 STAR-R1（86.1% vs 72.8% on MindCube），暗示训练数据与接口设计的贡献难以分离。

从方法设计看，SpatialClaw 与 ViewFusion 同属多视角推理路线，但 ViewFusion 依赖结构化思维链在语言空间对齐视角，而 SpatialClaw 在代码空间执行几何计算。ViewFusion 的局限在于其思维链仍受语言先验干扰，而 SpatialClaw 通过显式数值计算（如 KDTree 距离）提供了硬约束。然而，SpatialClaw 依赖 SAM3 和 Depth Anything 3 的准确性，若这些工具在真实世界噪声下失效，其性能将受限。论文未探讨工具误差对最终推理结果的传播机制，也未对比隐式几何学习方法的鲁棒性。

## 总结

SpatialClaw 的核心矛盾在于如何克服 VLM 对语言先验的过度依赖，同时避免固定 API 对复杂几何计算的束缚。其切入点是将代码作为动作接口，利用持久化内核实现中间状态的可观察性与动态组合，从而在无需训练的情况下提升空间推理能力。实验证明该接口在 20 个基准上平均准确率达 59.9%，较基线提升 11.2 个百分点，且在多视角和 4D 视频任务上增益显著。然而，其性能仍低于经过强化学习训练的 STAR-R1，且未报告计算开销，表明接口设计的增益可能以推理延迟为代价。当感知工具（如 SAM3）在遮挡或低光照场景下失效时，SpatialClaw 的动态组合机制是否仍能维持空间一致性，论文未给出回答。
