> 导读 GUI智能体面临的核心矛盾在于高质量标注数据稀缺与模型泛化需求之间的失衡，现有方法依赖大规模人工标注或复杂奖励模型，导致数据获取成本高昂且难以扩展。本文切入点在于利用网页与移动端截图中隐含的交互信号，通过弱监督预训练替代部分人工标注，构建低成本数据生成管线。具体做法是设计两阶段课程学习框架，先以无标注截图中的交互信号进行强化学习预训练，再用少量高质量数据微调。该方法以0.1%的数据量达到与UI-TARS相当的性能，但其在复杂多步任务逻辑建模上的有效性仍存疑。

## 研究背景

GUI智能体的视觉接地（Visual Grounding）精度直接决定任务成功率，而接地精度依赖于模型对界面元素空间位置的准确预测。当前主流方法通过监督微调（SFT）或强化学习（RL）优化接地能力，但两者均依赖大规模人工标注的轨迹数据。标注细粒度坐标与多步动作的成本极高，且现有自动标注方法常产生低质量标签，导致数据规模受限。数据不足进一步引发跨GUI与跨域泛化能力薄弱的问题，模型仅在训练分布覆盖的界面类型上表现良好，面对新布局或新应用时性能显著下降。

该领域的主流路线分为两类：一类依赖大规模高质量数据训练端到端模型，如UI-TARS使用18.4M轨迹样本；另一类通过强化学习优化策略，如GUI-R1使用约3K标注数据。前者数据效率低下，后者受限于标注数据规模与质量。本文的切入点在于利用无标注截图中的隐含交互信号，将数据生成成本从人工标注转移至自动化提取，从而在极低数据量下提升接地精度与泛化能力。

## 核心方法

### 方法参照系

GUI智能体训练的标准流程通常包含数据收集、标注、模型训练与评估四个环节，其中标注环节是主要瓶颈。本文问题与该通用流程的关键差异在于：将标注环节替换为基于交互信号的弱监督预训练，利用截图中隐含的可交互元素位置作为奖励信号，无需人工标注任务指令与动作。

### 弱监督GUI预训练

Stage 1的核心创新在于从静态截图中提取交互信号并构造元任务，替代传统人工标注任务。对于网页平台，使用Playwright从MHTML文件中识别可点击、可输入、可选择元素，存储为边界框位置，并构造三类元任务，如“点击页面上任意可点击区域，如按钮，但非空白区域”。对于移动端平台，从AndroidControl和AITZ数据集的无障碍树中提取可点击、可检查、可编辑元素，构造相应元任务。奖励设计采用基于高斯分布的位置奖励，避免边界框过大导致的奖励失衡。位置奖励$R_p$计算为：

$$R_p = \exp\left(-\frac{1}{2}(\mu_p - \mu_{gt})^T \Sigma_{gt}^{-1} (\mu_p - \mu_{gt})\right)$$

其中$\mu_p$为预测点，$\mu_{gt}$为真实边界框中心，$\Sigma_{gt}$为对角协方差矩阵，其元素由边界框宽高缩放得到。该公式的物理含义是：预测点越接近真实元素中心，奖励越高，且奖励随距离增加呈高斯衰减，避免了二元奖励的梯度稀疏问题。

### 高质量强化微调

Stage 2在Stage 1基础上引入少量高质量人工标注数据，通过GRPO算法进一步优化模型。数据源包括Mind2Web训练集（4,966样本）、GUI-R1-3K（1,744网页样本+85桌面样本）及AMEX（3,200移动端样本），总计6,795网页/桌面样本与3,200移动端样本。奖励设计与Stage 1类似，但每个样本仅有一个真实边界框或点用于计算位置奖励。该阶段的设计动机在于：Stage 1的元任务虽能提升接地精度，但缺乏对具体任务语义的理解，Stage 2通过高质量数据校准模型的任务执行能力，实现从粗粒度感知到细粒度执行的过渡。

## 实验评估

实验在Mind2Web、ScreenSpot-Pro、AndroidControl、AITW、OmniACT、AndroidWorld六个基准上进行，基线覆盖UI-TARS、GUI-R1、UI-R1、ShowUI、GPT-4o等主流方法，但缺失2026年最新SOTA如BEAP-Agent。主实验结果显示，GUICrafter-3B在Mind2Web All Avg达到60.2%，ScreenSpot-Pro All Avg达到54.7%，均超过UI-TARS-2B的59.5%与54.7%。在同等标注数据量下，GUICrafter超越GUI-R1-3B的59.5%与54.7%。

| 基准 | 方法 | 数据量 | All Avg |
| :--- | :--- | :--- | :--- |
| Mind2Web | GUICrafter-3B | 6.7K | 60.2 |
| Mind2Web | UI-TARS-2B | 18.4M | 59.5 |
| Mind2Web | GUI-R1-3B | 3.0K | 59.5 |
| ScreenSpot-Pro | GUICrafter-3B | 6.7K | 54.7 |
| ScreenSpot-Pro | UI-TARS-2B | 18.4M | 54.7 |
| ScreenSpot-Pro | GUI-R1-3B | 3.0K | 54.7 |

消融实验表明，仅Stage 1相比基线Qwen2.5-VL-3B在Mind2Web上提升超过10%，仅Stage 2提升约12.4%，两阶段结合提升15.4%。数据效率实验显示，仅10个弱监督样本即可在Mind2Web上提升1.7%，在ScreenSpot-Pro上提升2.6%。评估边界方面，论文未报告置信区间，且0.1%数据量对比可能因UI-TARS包含大量非GUI数据而失真。可复现性方面，代码、数据与模型已公开，训练使用8 NVIDIA H20 GPUs。

## 关联研究分析

从问题动机看，GUICrafter与VideoAgentTrek同属数据合成路线，但前者从静态截图提取交互信号，后者从视频逆向工程合成数据。VideoAgentTrek依赖多模态模型生成内心独白标注，引入噪声与分布偏差，而GUICrafter利用截图中隐含的交互信号，成本更低但信息密度可能较低。这一差异源于任务特性：静态截图的交互信号是确定性的，而视频中的交互需要时序推理，导致后者数据质量更不稳定。

从方法设计看，GUICrafter与GUI-R1同属RLVR框架，但前者引入弱监督预训练阶段，后者直接依赖人工标注数据。GUI-R1的奖励信号基于二元点-框判断，而GUICrafter采用高斯分布位置奖励，提供更密集的梯度信号。这一改进解决了GUI-R1在数据量有限时奖励稀疏的问题，但元任务抽象是否导致对复杂多步任务逻辑的建模不足，论文未给出回答。

## 总结

GUICrafter要解决的核心矛盾是GUI智能体数据稀缺与泛化需求之间的失衡，其切入点在于利用无标注截图中的隐含交互信号，通过弱监督预训练替代部分人工标注。方法上，设计两阶段课程学习框架，先以交互信号进行RLVR预训练，再用少量高质量数据微调。实验证明，以0.1%的数据量达到与UI-TARS相当的性能，且在同等数据量下超越GUI-R1。本文的边界在于：元任务抽象可能无法充分建模复杂多步任务的逻辑依赖，且0.1%数据量对比的公平性受UI-TARS数据构成影响。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
