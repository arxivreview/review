研究机构：浙江大学

作者：Xinyu Qiu、Yunzhu Zhang、Heng Jia 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.14579)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.14579)

> 强化学习在 GUI 定位中常因奖励稀疏导致组内方差归零，使策略优化停滞。标准 GRPO 依赖单视图重复采样，难以在困难样本上产生有效对比信号。本文通过构建目标保持的多视图组并引入条件触发的 oracle 锚点，恢复组内奖励方差。该方法在 ScreenSpot-Pro 上显著提升了 Qwen 系列模型的定位精度，但其对训练数据几何分布的依赖及推理效率开销仍需审视。

## 研究背景

GUI 定位要求模型将自然语言指令映射至屏幕特定像素坐标，其核心难点在于 UI 元素的小尺寸与高密度分布。当使用 Group Relative Policy Optimization (GRPO) 进行强化学习训练时，策略网络通过比较同一提示下多个 rollout 的奖励差异来更新参数。然而，GUI 定位的奖励函数通常基于“点是否在框内”的二值判定，这种稀疏奖励机制导致在困难截图中所有 rollout 均失败（全零组），或在简单截图中均成功（全一组），使得组内标准差 $\sigma$ 趋近于零，相对优势 $A$ 消失，训练信号中断。

早期 GUI 定位研究主要依赖大规模监督微调（SFT），确立了 SeeClick 等基线，但 SFT 难以突破数据分布上限。随后，基于规则奖励的强化学习（如 UI-R1）被引入以提升泛化能力，但现有 RL 方法普遍面临训练后期收益递减的问题。根本原因在于，传统 GRPO 假设同一视图下的多次采样能暴露模型的不确定性，但在 GUI 几何约束下，同一截图的多次预测往往高度一致，无法提供有效的对比梯度。本文的切入点在于重构 GRPO 的组构建逻辑：不再依赖单视图的重复采样，而是通过生成同一 GUI 实例的多个目标保持视图，将“同视图内的随机性”转化为“跨视图的几何鲁棒性对比”，从而在训练阶段即注入对视角变化的敏感度。

## 核心方法

### 标准 GRPO 流程与失效点

标准 GRPO 对同一提示采样 $G$ 个完成序列，计算组内奖励均值 $\mu$ 和标准差 $\sigma$，进而得到归一化优势 $A_i = (r_i - \mu) / (\sigma + \epsilon)$。在 GUI 定位中，由于坐标生成的离散性与几何敏感性，同一截图的 $G$ 个 rollout 往往产生相同的二值奖励，导致 $\sigma \approx 0$，$A_i$ 无定义或为零，策略梯度消失。本文指出，这一失效源于组构建方式与任务几何特性的不匹配，而非奖励函数本身的设计缺陷。

### 视图一致组采样（View-Consistent Group Rollout）

为恢复组内方差，VISTA 将组内样本从“同视图重复采样”改为“跨视图语义一致采样”。对于每个训练实例，以概率 $p_{crop}$ 生成 $K$ 个目标保持裁剪视图 $\{V_k\}_{k=1}^K$，每个视图均完整包含目标框 $B$ 并精确重映射坐标。组内共采样 $G=Kn$ 个 rollout，其中每个视图采样 $n$ 次。组统计量仅基于模型生成的 rollout 计算：

$$
\mu_m = \frac{1}{G} \sum_{k=1}^K \sum_{j=1}^n r_{k,j}, \quad \sigma_m = \sqrt{\frac{1}{G} \sum_{k=1}^K \sum_{j=1}^n (r_{k,j} - \mu_m)^2}
$$

此设计动机在于：不同视图改变了截图的几何上下文，迫使模型在同一语义目标下输出不同坐标，从而在困难实例上更可能产生“部分成功、部分失败”的混合奖励组，恢复 $\sigma_m > 0$ 的学习信号。实验显示，该策略将信息组比例从固定视图下的不足 5% 提升至约 20%。

### 自验证跨视图锚点（Self-Verified Cross-View Anchoring）

多视图采样虽恢复了方差，但可能导致坐标格式不稳定。为稳定训练，VISTA 引入条件触发的 oracle 锚点。仅当组内至少有一个模型 rollout 达到最大奖励 $R_{max}$（即自验证成功）时，才从失败视图 $N$ 中均匀选取一个视图，构造 oracle 中心点序列 $y_{anchor}$。该序列不参与组统计量 $\mu_m, \sigma_m$ 的计算，其优势值定义为：

$$
A_{anchor} = \frac{R_{max} - \mu_m}{\sigma_m + \epsilon}
$$

最终损失包含标准 GRPO 项与锚点项：

$$
\mathcal{L} = \mathcal{L}_{GRPO} + \lambda_a \mathcal{L}_{anchor} + \beta \mathcal{L}_{KL}
$$

其中 $\mathcal{L}_{anchor}$ 为优势加权监督损失。此设计动机在于：避免在模型尚未具备定位能力的全零组中注入无条件模仿信号，防止 oracle 污染基线；仅在模型已证明可解的组中，利用 oracle 稳定坐标生成格式，实现“探索”与“稳定”的解耦。

## 实验评估

实验在 ScreenSpot-Pro、ScreenSpot-V2、MMBench-GUI L2、OSWorld-G 及 OSWorld-G-R 五个基准上进行，覆盖移动、Web、桌面及高分辨率专业软件。基线包括 Qwen3-VL 系列、UI-TARS、GTA1、Holo2 等主流 GUI 模型。VISTA 在 Qwen3-VL 骨干上实现了跨规模一致提升，尤其在高分辨率基准 ScreenSpot-Pro 上增益显著。

| 模型 | SSPro | SSV2 | MMBench-L2 | OSWorld-G | Avg. |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3-VL-4B | 55.5 | 88.5 | 85.3 | 58.2 | 71.1 |
| VISTA-4B | 63.4 | 94.4 | 86.7 | 63.8 | 75.5 |
| Qwen3-VL-8B | 52.7 | 91.7 | 81.3 | 54.8 | 69.0 |
| VISTA-8B | 65.8 | 95.5 | 86.8 | 62.4 | 76.3 |
| Qwen3-VL-30B-A3B | 53.7 | 94.7 | 83.7 | 66.5 | 73.6 |
| VISTA-30A3B | 67.0 | 95.2 | 86.8 | 67.1 | 77.6 |

消融实验揭示了组件间的互补性。单独使用动态裁剪（GRPO + crop）将 ScreenSpot-Pro 从 63.4 提升至 64.3，单独使用自适应锚点（GRPO + anchor）提升至 64.8，而两者结合（VISTA）达到 65.8。这表明视图构建解决“探索不足”，锚点解决“格式不稳定”，二者针对不同的失效模式。值得注意的是，未门控的 oracle 注入（Normalized, Gate=✗）导致性能从 64.3 骤降至 57.8，证实了自验证门控机制对避免基线污染的关键作用。

评估边界方面，所有实验采用温度 0 的确定性解码，未报告置信区间。训练开销方面，VISTA 因多视图生成导致训练时间增加约 25%。代码已开源，但论文未提供不同 $p_{crop}$ 或 $K$ 值的敏感性分析，限制了超参数选择的指导意义。

## 关联研究分析

从问题动机看，VISTA 与 GUI-Spotlight 均利用裁剪/缩放机制，但二者处于训练-推理的不同阶段。GUI-Spotlight 是推理时迭代聚焦，通过动态工具调用缩小视野，解决单步定位的精度问题；VISTA 是训练时静态多视图，通过组构建注入几何鲁棒性，解决 RL 训练信号缺失问题。GUI-Spotlight 无需训练成本，但推理延迟高；VISTA 增加训练成本，但推理时兼容 MVP 等多视图聚合策略，二者在效率与精度上形成互补。VISTA 的多视图训练是否使模型在推理时更依赖 MVP 策略，论文未给出直接证据。

从方法设计看，VISTA 与 UI-R1 同属基于规则奖励的 RL 框架，但核心差异在于组构建逻辑。UI-R1 侧重奖励函数的规则设计，假设单视图采样足以提供梯度；VISTA 指出单视图采样的根本缺陷，并通过跨视图采样重构组结构。VISTA 的自验证锚点机制区别于 LUFFY 或 BREAD 等数学推理中的 oracle 引导方法，后者将 oracle 混入组内改变基线，而 VISTA 将 oracle 排除在基线外，仅作为条件稳定信号。这种设计更契合 GUI 定位的几何约束，避免了 oracle 对策略探索空间的压缩。

## 总结

VISTA 针对 GUI 定位中 GRPO 训练信号因奖励稀疏而失效的核心矛盾，提出通过目标保持多视图组构建恢复组内方差，并引入自验证锚点稳定坐标生成。该方法在 ScreenSpot-Pro 上将 Qwen3-VL-30B-A3B 的准确率从 53.7% 提升至 67.0%，验证了视图一致性作为训练信号的有效性。然而，实验仅覆盖点击定位任务，未涉及拖拽或状态预测等复杂交互，且多视图训练对原始全图分辨率依赖的影响未量化。当支持集增大或视图多样性增加时，自验证锚点的边际收益是否递减，论文未给出回答。
