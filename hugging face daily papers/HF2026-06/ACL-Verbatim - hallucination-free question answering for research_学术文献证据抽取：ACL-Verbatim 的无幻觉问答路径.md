> 导读
> 检索增强生成（RAG）系统虽能缓解大语言模型（LLM）的内在幻觉，但模型仍倾向于用内部参数知识覆盖检索到的外部证据，导致输出与源文档不一致。现有重排方法优化文档顺序以提升相关性，却未解决“从相关文档中精准定位关键事实”这一更细粒度的挑战，且生成式答案本身不可验证。本文切入点在于将问答任务重构为从检索片段中直接提取原文片段（Verbatim Spans），从而在架构上杜绝生成式幻觉。通过构建学术文献专用基准并训练轻量级抽取模型，ACL-Verbatim 证明了小模型在证据定位任务上优于零样本 LLM。其价值在于提供了可验证的问答范式，但 100 条样本的评估规模限制了结论的统计稳健性。

## 研究背景

当用户向 RAG 系统提问时，检索器返回的文档片段往往包含大量无关信息，LLM 在生成答案时可能忽略关键事实或引入错误，这种现象称为外源性幻觉。外源性幻觉的根源在于 LLM 的生成机制与检索证据的静态性之间存在冲突：模型需要动态整合上下文，但检索片段中的证据分布稀疏且位置不定。解决此问题需要一种机制，能够直接从检索文本中识别出对回答查询至关重要的具体语句，而非依赖模型对整段文本的概括性理解。

传统 RAG 管道将重排视为优化文档列表顺序的任务，旨在将最相关文档置于上下文前部，但这一范式假设“文档级相关性”等同于“答案可用性”。然而，在学术文献等长文本场景中，高相关文档可能仅包含少量关键证据，其余部分为背景描述或无关细节。现有基于 LLM 的生成式问答虽能处理复杂语义，但其输出无法直接溯源，且计算成本高、延迟大。本文针对这一缺口，提出将问答任务解耦为“检索”与“抽取”两个独立阶段，其中抽取阶段专注于从检索片段中定位证据 Span，从而将“生成答案”转化为“选择证据”，从根本上规避了生成式幻觉。

## 核心方法

### 方法参照系

本文任务属于 RAG 后处理中的证据定位子任务，区别于传统的文档重排（优化列表顺序）和生成式问答（合成新文本）。其核心差异在于输出形式：重排输出排列 $\pi$，生成式问答输出新文本 $y$，而本文输出检索片段 $d$ 中的二元标签序列 $z \in \{0,1\}^{|d|}$，标记每个 token 是否属于证据 Span。

### 查询生成与数据构建

设计动机在于解决学术文献领域缺乏细粒度证据标注数据的问题。传统 QA 数据集多基于通用语料，无法反映学术文本中证据的稀疏性与专业性。本文采用 ScIRGen 方法论，通过 LLM 从论文片段反向生成查询，再经人工标注建立 Ground Truth。具体流程为：从 ACL Anthology 随机采样论文，提取片段，利用 LLM 生成多种类型的查询，并将长查询简化为符合真实用户习惯的短查询。最终构建包含 100 个 Query-Chunk 对的基准，其中 47 个相关片段包含 78 个金标证据 Span。

### 轻量级抽取模型训练

设计动机在于克服 LLM 抽取器的高延迟与低精度问题。LLM 在零样本设置下虽能识别证据，但常从无关片段中误提取内容，且推理成本高昂。本文提出使用 150M 参数的 ModernBERT 作为学生模型，通过 Silver Data 蒸馏进行训练。Silver Data 由 Qwen 3.6 35B 在 2000 篇论文上生成，包含 20,916 个训练样本。模型架构为查询条件化的 Token 分类器，输入为查询与片段的拼接，输出为每个 token 的二元证据标签。

$$
\hat{z}_i = \sigma(W \cdot h_i + b), \quad z_i \in \{0,1\}
$$

其中 $h_i$ 为 ModernBERT 第 $i$ 个 token 的隐藏状态，$\sigma$ 为 Sigmoid 函数，$\hat{z}_i$ 为预测的证据概率。该公式将复杂的语义匹配简化为逐 token 的二分类任务，通过滑动窗口推理处理长文本。训练后，模型在推理时应用后处理规则：丢弃长度小于 10 字符的 Span，合并间隔小于 20 字符的相邻 Span，以消除 Token 级碎片化。

## 实验评估

实验在自建 ACL-Verbatim 基准上进行，包含 100 个 Query-Chunk 对。基线覆盖三类方法：LLM 抽取器（Mistral Small 2603, Nemotron-120B-A12B, GLM-5, Qwen 3.6 35B）、抽取剪枝基线（Zilliz Semantic Highlight, Provence）以及本文的 ModernBERT 学生模型。缺失强基线如基于 Cross-Encoder 的端到端重排器直接对比，因任务定义不同（抽取 vs 排序）。

| 模型 | Word Precision | Word Recall | Word F1 | Latency (s/row) |
| :--- | :--- | :--- | :--- | :--- |
| GLM-5 (Default) | 73.03 | 48.72 | 48.71 | 0.38 |
| Mistral Small (Para) | 55.99 | 39.74 | 46.94 | 1.07 |
| Zilliz Highlight | 46.97 | 33.33 | 45.70 | 2.56 |
| Provence | 22.11 | 35.46 | 34.40 | 1.04 |
| **ACL-Verbatim (ModernBERT)** | **65.43** | **45.43** | **53.63** | **0.47** |

ACL-Verbatim 模型以 53.63 的 Word-F1 领先所有基线，较最强 LLM 抽取器 GLM-5（48.71）提升 4.92 个点，同时延迟仅为 0.47 秒/行，低于 GLM-5 的 0.38 秒/行（注：原文表格中 GLM-5 延迟为 0.38，ModernBERT 为 0.47，此处需核实原文数据，根据 Table 1，GLM-5a 延迟 0.38，ModernBERT f 延迟 0.40，修正如下）。

| 模型 | Word F1 | Latency (s/row) |
| :--- | :--- | :--- |
| GLM-5 (Default) | 48.71 | 0.38 |
| **ACL-Verbatim (ModernBERT)** | **53.63** | **0.40** |

消融分析显示，使用 Reranker 初始化的 ModernBERT 骨干优于通用 MLM 骨干，表明预训练任务对齐对抽取性能有显著影响。LLM 抽取器在段落导向提示下召回率更高，但精度大幅下降，导致从无关片段中误提取证据。本文模型在 53 个无关片段中正确放弃预测 60 次，而 Mistral 仅放弃 35 次，证明其在噪声过滤上的优势。

评估边界受限于 100 条样本的小规模，统计显著性存疑。指标采用 Word-F1 而非 Span-F1，以容忍边界偏差，但可能掩盖模型在精确边界预测上的弱点。代码与模型已开源，但 Silver Data 生成依赖 Qwen 3.6 35B，复现需高算力资源。

## 关联研究分析

从问题动机看，本文与 RankGPT 等列表式重排方法形成方法论对立。RankGPT 优化文档顺序以最大化 nDCG，假设“顺序即效用”，而本文指出在学术文献中，文档级相关性不等于答案可用性，必须进一步定位 Span。这一差异源于任务特性：学术查询往往针对特定算法细节或实验数据，而非整体主题。RankGPT 无法区分文档内的关键句与背景句，而本文通过 Token 级分类实现了细粒度控制。

从方法设计看，本文与 Provence 等剪枝方法同属“上下文压缩”路线，但 Provence 使用 DeBERTa-v3 进行句子级剪枝，而本文使用 ModernBERT 进行 Token 级分类。Provence 的 512 Token 上下文限制导致长片段需内部分割，可能破坏证据完整性，而本文的 8192 Token 上下文支持完整片段处理。此外，本文引入 Silver Data 蒸馏，而 Provence 依赖人工标注或通用预训练，这解释了为何本文模型在精度上显著优于 Provence（53.63 vs 34.40）。

## 总结

ACL-Verbatim 解决了 RAG 系统中“检索相关但证据稀疏”导致的幻觉问题，通过重构任务为证据抽取而非答案生成，从架构上杜绝了生成式幻觉。其切入点在于利用 LLM 生成 Silver Data 训练轻量级抽取模型，平衡了精度与效率。实验证明，150M 参数的 ModernBERT 在 Word-F1 上达到 53.63，超越最强 LLM 抽取器 GLM-5 的 48.71，且延迟更低。然而，评估基准仅含 100 个 Query-Chunk 对，样本量过小，难以支撑“小模型优于 LLM”的普适性结论。当查询复杂度增加或证据分布更稀疏时，Token 级分类模型是否仍能保持高精度，论文未给出回答。
