> 自动驾驶策略在部署前需通过长尾安全场景的闭环验证，但传统重建式模拟器受限于原始采集数据，无法生成未见过的动态环境。本文提出 OmniDreams，一个基于因果扩散架构的实时生成式世界模型，通过流式 KV 缓存与多视角注意力机制，在闭环中实时响应策略动作并合成高保真传感器观测。该模型不仅作为环境模拟器，其骨干网络还可微调为高性能策略模型，以 1/5 参数量超越视觉-语言-动作（VLA）基线。其核心价值在于打通了“生成”与“决策”的架构壁垒，但缺乏显式物理约束下的动力学可行性验证。

## 研究背景

闭环仿真要求策略模型的动作能实时改变环境状态，进而影响下一时刻的传感器观测。这一交互过程依赖于世界模型对场景演化的准确预测，而传统基于神经辐射场（NeRF）或3D高斯泼溅（3DGS）的重建式模拟器虽具备高保真度，却严格锚定在原始采集走廊内，无法泛化至新视角或极端天气等长尾场景。这种“所见即所得”的限制导致重建式模拟器难以覆盖自动驾驶系统中关键的罕见事件验证需求。

生成式世界模型通过大规模视觉数据学习先验分布，能够合成重建式方法无法捕捉的动态现象，如暴雨、行人异常行为等。然而，通用视频生成模型通常采用双向注意力机制进行离线长片段生成，无法满足闭环仿真中毫秒级的实时交互要求。此外，多视角生成中的几何一致性问题长期制约着传感器数据的物理可信度。OmniDreams 的切入点在于将 Cosmos 基础模型适配为因果自回归架构，结合流式推理优化，在保持生成多样性的同时实现实时闭环交互，并探索世界模型表征在策略学习中的复用潜力。

## 核心方法

### 因果自回归扩散架构

OmniDreams 基于 Cosmos-Predict 2.5 骨干网络，将其从双向注意力改造为因果扩散公式，确保每帧预测仅依赖过去观测与当前条件。这一设计解决了离线视频生成模型无法实时响应策略动作的问题，使模拟器能在每个时间步根据最新动作更新世界状态。模型采用流式 KV 缓存机制，复用先前计算的注意力键值对，避免长序列重计算，从而在分钟级滚动中维持时序一致性。

$$
\hat{x}_t = \text{Dec}\left( \text{DiT}\left( z_t, \text{KV}_{<t}, a_t, s_t \right) \right)
$$

其中 $z_t$ 为当前噪声潜变量，$\text{KV}_{<t}$ 为历史帧的流式缓存，$a_t$ 为策略动作，$s_t$ 为抽象场景状态。该公式表明生成过程是严格因果的，新帧的合成即时依赖于当前动作与历史上下文，而非全局序列。

### 多视角几何一致性约束

针对多相机同步生成中的几何漂移问题，OmniDreams 在 DiT 中引入跨视角注意力层（Cross-View Attention）。该层位于文本交叉注意力之后，强制不同视角的 token 相互关注，确保四路相机（前广角、前长焦、左交叉、右交叉）在空间结构上的对齐。设计动机在于解决纯单视角生成无法保证多传感器几何一致性的缺陷，从而提升闭环评估中策略对空间关系的感知准确性。

$$
\text{Attn}_{cv} = \text{Softmax}\left( \frac{Q_i K_j^T}{\sqrt{d}} \right) V_j, \quad i \neq j
$$

其中 $i, j$ 表示不同视角的 token 索引。该机制通过显式的跨视角信息交换，抑制了各视角独立生成时可能出现的物体位置偏移或形状变形，使合成数据在几何上更接近真实多传感器采集结果。

## 实验评估

实验在 501 个场景的 PAI NuRec 子集上进行，对比重建式基线 NuRec 与 VLA 策略 Alpamayo 1.5。OmniDreams 作为环境模拟器时，其闭环事故率排名与 NuRec 保持一致，验证了其作为真实世界代理的有效性。当 OmniDreams 骨干微调为 World-Action Model (WAM) 策略时，碰撞率从 6.9% 降至 4.2%，后碰撞率从 5.3% 降至 3.0%，参数规模仅为 Alpamayo 1.5 的 1/5（2B vs 10B）。

| 指标 | NuRec (重建) | OmniDreams (生成) | Alpamayo 1.5 (VLA) | OmniDreams WAM |
| :--- | :--- | :--- | :--- | :--- |
| Collision (Total) | - | - | 6.9% | 4.2% |
| Collision (Rear) | - | - | 5.3% | 3.0% |
| Collision (Front) | - | - | 1.0% | 0.9% |
| Collision (Lateral) | - | - | 0.6% | 0.4% |

消融实验显示，使用 LightTAE 解码器相比原始 VAE 将 FVD 从 24.8 降至 1.90，同时 3D 检测 LET-AP 从 0.400 提升至 0.388（注：此处原文表格数据存在矛盾，LET-AP 应为提升，但数值显示下降，需以原文 Table 4 为准，原文中 Distilled (LightTAE) 的 LET-AP 为 0.388，Original VAE 为 0.400，表明解码器优化可能轻微牺牲了检测精度以换取生成速度）。多 GPU 推理中，16 GPU 配置下四视角生成延迟为 151 ms，有效帧率达 105 FPS，满足实时闭环需求。

评估边界方面，论文未报告 FID 等标准生成质量指标，仅通过闭环事故率间接验证保真度。代码未公开，且依赖 NVIDIA GB300 硬件，可复现性受限。缺乏与 MagicDrive、GAIA-1 等生成式基线的直接对比，无法量化其在生成质量上的相对优势。

## 关联研究分析

从问题动机看，OmniDreams 与 SimScale 均致力于闭环仿真，但 SimScale 依赖 3DGS 静态重建与动态生成结合，侧重数据增强；OmniDreams 则完全基于生成式先验，强调对未见场景的合成能力。这种差异源于任务特性：SimScale 需保证与真实数据的严格对齐，而 OmniDreams 旨在覆盖长尾分布。然而，OmniDreams 缺乏显式物理约束，其生成的场景动力学可行性仅通过闭环事故率间接体现，未像 CCFM 那样引入碰撞约束向量场，这在极端场景下的物理一致性上存在潜在风险。

从方法设计看，OmniDreams 与 UniDriveDreamer 同属多模态世界模型，但 UniDriveDreamer 侧重单阶段多模态生成（视频+LiDAR），而 OmniDreams 聚焦实时视频生成与策略复用。OmniDreams 引入 WAM 概念，将世界模型骨干直接微调为策略，这一设计在 UniDriveDreamer 中未见。这种架构统一是否牺牲了世界模型的通用性以换取策略性能，论文未给出充分消融。此外，OmniDreams 的跨视角注意力机制与 MagicDrive 的 3D 几何约束不同，前者依赖数据驱动的一致性学习，后者依赖显式几何先验，前者在计算效率上更具优势，但几何精度可能受限于训练数据分布。

## 总结

OmniDreams 解决了生成式世界模型在实时闭环仿真中的交互延迟与多视角一致性矛盾，通过因果自回归架构与流式 KV 缓存实现了 105 FPS 的实时生成，并首次验证了世界模型骨干可直接微调为高性能策略模型，以 2B 参数实现 4.2% 碰撞率，优于 10B 参数的 VLA 基线。其边界在于缺乏显式物理约束，生成场景的动力学可行性仅通过闭环结果间接验证，且未提供 FID 等标准生成质量指标。当训练数据分布覆盖不足时，跨视角注意力机制能否保证极端场景下的几何一致性，论文未给出回答。
