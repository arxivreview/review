> 代理系统在部署后往往缺乏初始技能、成功轨迹或可靠的验证器，导致现有自进化方法在真实开放场景中失效。OpenSkill 提出“开放世界自进化”范式，允许代理仅凭任务提示和外部资源，从零构建技能及其验证信号。其核心机制是从开放世界获取知识锚点，并基于这些锚点生成虚拟任务以迭代精炼技能，全程隔离目标测试监督。该方法在 SkillsBench 等基准上取得了最佳自动化通过率，但其虚拟验证器仅 56.9% 的精确率暗示了其在复杂任务收敛性上的潜在局限。

## 研究背景

当 LLM 代理面对需要最新 API 文档或特定领域规则的长程任务时，其参数化知识 $K_\theta$ 往往滞后且缺乏针对性。这种知识缺口导致代理无法生成有效的程序性技能，而传统技能生成方法依赖人工编写或从成功轨迹中蒸馏，在冷启动阶段因缺乏素材而失效。解决此困境的关键在于引入外部知识源，但直接注入外部文档会导致上下文溢出且无法保证技能质量，因此需要一种机制将外部证据转化为可复用的技能，并建立独立于目标任务的验证闭环。

现有自进化研究主要沿两条路线演进：一是基于轨迹反馈的优化，如 SkillOpt 和 SkillGrad，它们依赖验证集或执行结果来指导技能编辑，但在无初始成功轨迹的开放场景中无法启动；二是基于参数化内化的方法，如 LatentSkill，虽提升了推理效率但牺牲了跨模型可迁移性。这些方法共同假设存在可用的学习信号（如奖励、验证器或历史轨迹），而真实部署环境往往仅提供一个任务提示。OpenSkill 的切入点在于打破对目标监督的依赖，将开放世界资源同时作为知识来源和验证锚点，构建一个完全自举的技能进化循环。

## 核心方法

### 方法参照系

本文问题可置于“技能生成与蒸馏”路线下，但偏离了依赖轨迹或人工技能的标准流程。其关键差异在于：知识源从“内部参数或历史轨迹”扩展至“开放世界文档”，验证信号从“目标任务反馈”替换为“基于外部事实的虚拟任务”，从而实现了无监督条件下的技能构建。

### 开放世界知识获取与锚点提取

设计动机在于解决参数化知识 $K_\theta$ 的时效性与领域特异性不足问题。OpenSkill 首先通过检索函数 $D$ 从开放世界 $K$ 中获取任务相关知识 $k_i$，并同步提取验证知识 $k_i^{[v]}$。$k_i^{[v]}$ 包含官方文档中的参考值、数据集统计不变量及领域标准，作为后续虚拟测试的锚点。这一设计将技能构建的基础从模型内部记忆转移至外部可验证事实，确保了技能内容的 groundedness。

$$ k_i = D(I_i, K), \quad k_i^{[v]} = D_v(I_i, K) $$

该公式表示代理根据任务指令 $I_i$ 从开放世界 $K$ 中检索技能构建知识 $k_i$ 和验证锚点 $k_i^{[v]}$，两者均不包含目标测试 $T_i^{GT}$。

### 泄漏屏障下的虚拟任务精炼

设计动机在于解决无目标反馈下的技能质量评估难题。OpenSkill 构建虚拟测试套件 $\tilde{T}_i$，其断言基于 $k_i^{[v]}$ 而非猜测目标测试内容。代理在沙箱中执行技能 $S_i^{(j)}$，计算虚拟通过率 $\tilde{r}^{(j)}$ 作为质量代理。若 $\tilde{r}^{(j)} < 1$，系统生成结构化诊断 $F^{(j)}$，区分“知识缺口”与“实现错误”，并触发针对性检索或代码修正。此过程在“泄漏屏障”下运行，确保 $T_i^{GT}$ 不进入进化循环，仅用于最终评估。

$$ \tilde{r}^{(j)} = \frac{1}{|\tilde{T}_i|} \sum_{k=1}^{|\tilde{T}_i|} \tilde{t}_{i,k}(S_i^{(j)}) $$

该公式计算当前技能集在虚拟测试上的平均通过率，作为迭代精炼的收敛信号，替代了传统方法中依赖目标奖励的验证门控。

## 实验评估

实验在 SkillsBench（11 领域）、SocialMaze 和 ScienceWorld 上进行，对比了 No Skill、Self-Gen、CoT、Skill-Creator、AutoSkill、Memento 等闭世界基线。OpenSkill 在 SkillsBench 上 Opus 4.6 和 GPT 5.2 的整体通过率分别为 43.6% 和 42.1%，分别比最强基线 Skill-Creator 和 CoT 高出 8.9 和 8.8 个点，且是唯一在两个模型家族上均表现稳定的方法。

| 方法 | Opus 4.6 Overall (%) | GPT 5.2 Overall (%) |
| :--- | :--- | :--- |
| No Skill | 25.5 | 25.0 |
| Skill-Creator | 34.7 | 29.2 |
| CoT | 23.9 | 33.3 |
| **OpenSkill** | **43.6** | **42.1** |
| Human | 44.5 | 44.8 |

消融实验显示，虚拟验证器迭代次数对性能影响显著：3 次迭代时性能峰值为 82.7%，5 次和 10 次分别降至 79.9% 和 78.0%，表明过度精炼导致对虚拟测试的过拟合。组件贡献分析表明，开放世界查询（DR）和虚拟验证器（VV）各自独立提升性能，且组合效果最佳，证实了知识获取与验证机制的互补性。

评估边界方面，论文未报告置信区间，且 SkillsBench 上 Manufacturing 领域所有自动化方法均为 0.0%，暴露了开放世界获取在特定复杂领域的能力边界。代码已开源，但虚拟验证器的 LLM 判断依赖 Opus 4.6，可能引入模型偏差。

## 关联研究分析

从问题动机看，OpenSkill 与 CoEvoSkills 均强调验证器独立性，但 CoEvoSkills 依赖目标任务生成断言，而 OpenSkill 依赖开放世界事实。这一差异源于任务特性：CoEvoSkills 假设存在可交互的目标环境以生成测试，而 OpenSkill 针对无反馈的冷启动场景。根源在于开放世界资源的可用性是否足以替代目标反馈，论文通过 88.9% 的测试意图覆盖率提供了肯定证据，但在缺乏外部文档的封闭领域，该假设是否成立尚存疑问。

从方法设计看，OpenSkill 借鉴了 SkillOpt 的迭代精炼框架，但将验证门控从“验证集性能”替换为“虚拟任务通过率”。SkillOpt 依赖冻结模型上的验证集，而 OpenSkill 在完全无监督下构建验证信号。这一改动解决了 SkillOpt 在冷启动阶段因缺乏验证集而无法启动的问题，但引入了虚拟验证器精度不足的风险。OpenSkill 的 56.9% 精确率低于 SkillOpt 的验证门控可靠性，暗示在复杂任务中，外部锚点的噪声可能阻碍技能收敛。

## 总结

OpenSkill 解决了开放世界部署中代理缺乏初始技能与验证信号的矛盾，通过从外部资源获取知识锚点并构建虚拟任务，实现了无监督下的技能自进化。其在 SkillsBench 上 43.6% 的通过率证明了该范式的有效性，但虚拟验证器 56.9% 的精确率揭示了其在复杂任务中可能因噪声信号导致过拟合的局限。当任务复杂度增加导致外部锚点稀疏时，虚拟验证器的诊断能力是否足以支撑技能的稳定收敛，论文未给出回答。
