# HuggingFace最新推荐论文 ｜CLI-Universe: Towards Verifiable Task Synthesis Engine for Terminal Agents ｜终端智能体可验证任务合成引擎

研究机构：南京大学、华中科技大学

论文原文见 [arXiv](https://arxiv.org/abs/2606.22883)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.22883)

> 终端智能体在复杂命令行任务中表现强劲，但高质量训练数据稀缺，现有合成流水线往往通过改造表面工件生成任务，导致指令模糊、执行路径浅薄且测试信号微弱。CLI-Universe 提出一种“由内而外”的合成引擎，通过结构化能力规格与证据引导的深度研究构建任务蓝图，并引入多阶段可执行验证以剔除低质量样本。该引擎在仅 6k 条轨迹上微调 Qwen3-32B，在 Terminal-Bench 2.0 上取得 33.4% 的通过率，超越了同规模开源模型。这一结果证明了数据质量对终端智能体训练的关键作用，但其对闭源前沿模型的能力差距及非确定性环境的泛化能力仍存疑。

## 研究背景

终端智能体需在隔离的 Docker 环境中执行多步 CLI 操作，其核心挑战在于环境状态的不可逆性与验证信号的稀疏性。不同于静态代码生成，终端任务涉及系统配置、服务启动及文件操作，任何中间步骤的错误都可能导致环境崩溃或状态偏离，使得传统的基于最终输出的奖励机制难以提供有效的梯度信号。这种“执行-验证”的强耦合特性，要求训练数据不仅包含正确的操作序列，还必须附带可执行的状态转换证明，以确保监督信号的无歧义性。

当前终端智能体训练数据合成主要依赖两条路线：一是基于 LLM 生成的技能分类法直接枚举任务，二是从现有代码仓库或基准中挖掘并改造 Docker 环境。前者虽覆盖面广，但缺乏真实技术约束，生成的任务往往过于简单或存在逻辑漏洞；后者虽基于真实基础设施，但直接转换常产生模糊的查询指令和脆弱的测试用例，导致模型在训练中学到的是“如何运行脚本”而非“如何解决问题”。现有方法普遍存在“扩大任务来源而非提升任务质量”的缺陷，未能解决高难度、长程交互任务中监督信号密度低的核心瓶颈。

CLI-Universe 的切入点在于将任务构造视为一个可验证的工程过程，而非简单的数据转换。它摒弃了从表面工件反向推导任务的“由外而内”模式，转而采用“由内而外”的策略：先定义能力空间中的具体坐标，再通过深度研究将其锚定在真实技术材料上，最后通过严格的可执行验证筛选出具备高信息密度的样本。这种方法论的转变，旨在解决终端智能体训练中数据规模与数据质量之间的权衡问题，证明在有限数据预算下，结构化验证比单纯扩大数据量更能提升模型能力。

## 核心方法

### 结构化能力规格与证据引导蓝图

终端智能体任务合成通常直接从代码库或文档中提取片段，缺乏对能力维度的显式控制，导致任务分布不均且难度不可控。CLI-Universe 引入多维能力分类法，将任务定义在领域（Domain）、技能类型（Skill Type）、能力（Capability）和工程支柱（Engineering Pillar）四个正交维度上。给定一个锚点组合，系统生成任务想法并评分，仅保留高分候选进入后续流程。

设计动机在于解决现有合成方法中任务难度与技能覆盖度的不可控问题。通过显式采样能力维度，CLI-Universe 确保生成的任务在技能层面具有多样性，而非仅在表面主题上重复。随后，一个专门的研究智能体对候选任务进行证据引导的精炼，搜索真实的技术仓库、文档和 Issue 讨论，将抽象的能力规格转化为包含具体工具、约束和失败模式的技术蓝图。这一过程显著提升了任务的真实性与难度，实验显示，经过证据引导精炼的任务，求解者平均轮次增加 3.45 倍，通过率降低 13.3 个百分点，证实了该机制有效增加了任务的认知负荷而非仅延长执行路径。

### 多阶段可执行验证流水线

蓝图构建后，任务需转化为可执行的 Docker 环境并生成测试用例。传统方法中，测试与参考解往往由同一智能体生成，存在“自我验证”偏差，即测试可能过于宽松或参考解可能绕过测试逻辑。CLI-Universe 采用角色分离的智能体架构，测试智能体与解智能体独立工作，互不可见对方输出，以消除这种偏差。

设计动机在于解决监督信号的可信度问题，确保测试用例能准确反映任务完成状态。验证流水线包含三个关键阶段：首先，测试智能体基于蓝图生成测试用例，并对照测试用例评分标准（Test-Case Rubrics）进行迭代优化，确保测试的正确性、确定性和边缘情况覆盖；其次，提示条件过滤（Hint-Conditional Filtering）比较有无内部提示（Hint）的求解结果，仅保留无提示失败而有提示成功的任务，剔除平凡可解实例；最后，失败到通过检查（Fail-to-Pass Check）验证测试在初始环境失败，而在执行参考解后通过，确保任务实现了从“未解决”到“已验证”的状态转换。

该验证机制的核心逻辑可形式化为对任务 $t$ 的保留条件：

$$
\mathcal{R}(t) = \mathbb{I}[\text{Test}(t, E_0) = \text{Fail}] \cdot \mathbb{I}[\text{Test}(t, E_{sol}) = \text{Pass}] \cdot \mathbb{I}[\text{Solve}(t, \text{no-hint}) = \text{Fail}] \cdot \mathbb{I}[\text{Solve}(t, \text{hint}) = \text{Pass}]
$$

其中 $E_0$ 为初始环境，$E_{sol}$ 为执行参考解后的环境。该公式表明，只有当测试能区分初始状态与解决状态，且提示对求解具有必要性时，任务才被保留。这一机制拒绝了约三分之二的候选任务，将训练信号集中在高保真、非平凡的样本上。

## 实验评估

实验在 Terminal-Bench 1.0 和 2.0 上进行，使用 Terminus 2 脚手架，报告 avg@4 指标。基线包括 SkillSynth、Nemotron-Terminal、TerminalTraj 等开源合成数据模型，以及 Qwen3、GLM-4.7 等开源基础模型。CLI-Universe-32B 在 TB 2.0 上取得 33.4% 的通过率，显著优于同规模的 SkillSynth-32B（29.6%）、Nemotron-Terminal-32B（27.4%）和 TerminalTraj-32B（22.0%）。此外，CLI-Universe-32B 还超越了规模大一个数量级的 Qwen3-Coder-480B（23.9%）和 Kimi-K2-Instruct（27.8%），但低于闭源模型 Claude-Opus-4.5（57.8%）。

| 模型 | 规模 | Terminal-Bench 1.0 | Terminal-Bench 2.0 |
| :--- | :--- | :--- | :--- |
| CLI-Universe-32B | 32B | 38.8 | 33.4 |
| SkillSynth-32B | 32B | 33.8 | 29.6 |
| Nemotron-Terminal-32B | 32B | – | 27.4 |
| TerminalTraj-32B | 32B | 35.3 | 22.0 |
| Qwen3-Coder-480B | 480B | 37.5 | 23.9 |
| Kimi-K2-Instruct | 1T | 44.6 | 27.8 |
| Claude-Opus-4.5 | – | 47.5 | 57.8 |

消融实验揭示了各组件的贡献。在 1k 任务子集上，移除资产策略导致 TB 2.0 得分从 26.7 降至 20.5（-6.2 分），表明环境多样性是任务覆盖的主要驱动因素；移除查询评分标准（Query Rubrics）导致得分降至 23.3（-3.4 分），说明查询质量限制了学习上限；移除测试用例评分标准导致得分降至 22.8（-3.9 分），证实了高保真验证对可训练轨迹的重要性。数据侧消融显示，仅保留成功轨迹（6k）比保留完整轨迹（10k）性能高 5.2 分，表明失败交互引入的噪声在 32B 模型规模下降低了训练信号质量。教师模型选择方面，Kimi-K2.6 蒸馏出的轨迹（33.4%）优于 DeepSeek-V4-Pro（31.2%），但差距不大，说明流水线对教师模型不敏感。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码与超参数细节在附录中提供，但 Docker 环境的构建依赖外部资源获取，可复现性受网络环境稳定性影响。此外，实验仅在 Terminal-Bench 系列基准上进行，未涵盖非确定性环境（如实时网络搜索）的泛化测试，限制了结论的普适性。

## 关联研究分析

从问题动机看，CLI-Universe 与 ASearcher 均关注长程任务中的监督信号稀疏问题，但解决路径截然不同。ASearcher 采用端到端强化学习，通过大规模 RL 训练优化搜索策略，依赖模型自身的泛化能力；而 CLI-Universe 采用数据蒸馏，通过高质量 SFT 数据提升小模型性能。这种差异源于任务特性的不同：ASearcher 针对的是开放式网络搜索，奖励信号虽稀疏但可通过轨迹级优化缓解；CLI-Universe 针对的是终端操作，环境状态离散且可执行验证明确，使得数据侧的质量控制比策略侧的优化更具性价比。在 32B 模型规模下，CLI-Universe 的数据效率优势明显，但在更大模型规模下，RL 训练是否仍能保持优势，论文未给出回答。

从方法设计看，CLI-Universe 与 WebWeaver 均强调结构化规划，但应用对象不同。WebWeaver 使用双智能体框架解决报告生成的逻辑连贯性问题，其规划对象是信息检索与综合过程；CLI-Universe 使用结构化分类法解决任务构造的覆盖度与难度问题，其规划对象是能力空间中的任务坐标。两者都体现了“显式结构优于隐式学习”的设计哲学，但 CLI-Universe 的创新在于将“证据引导”应用于任务定义而非答案生成，并通过可执行验证闭环确保结构的有效性。这种“由内而外”的任务构造方式，与 WebWeaver 的“由外而内”报告生成方式形成互补，共同指向了智能体系统中结构化与自动化之间的平衡。

## 总结

CLI-Universe 旨在解决终端智能体训练数据稀缺且质量低下的核心矛盾，通过结构化能力规格与证据引导深度研究构建高保真任务，并利用多阶段可执行验证剔除低信号样本。该引擎在仅 6k 条轨迹上微调 Qwen3-32B，在 Terminal-Bench 2.0 上取得 33.4% 的通过率，超越了同规模开源模型及大一个数量级的开源模型，证明了数据质量对终端智能体训练的关键作用。然而，实验仅在确定性 Docker 环境中进行，且模型规模限于 32B，未探索在更大模型或非确定性环境下的表现。当模型规模扩展至 100B 以上时，高质量 SFT 数据的边际收益是否会被端到端 RL 训练超越，论文未给出回答。
