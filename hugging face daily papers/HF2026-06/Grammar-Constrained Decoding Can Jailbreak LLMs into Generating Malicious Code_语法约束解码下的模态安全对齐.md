# HuggingFace最新推荐论文 ｜Grammar-Constrained Decoding Can Jailbreak LLMs into Generating Malicious Code ｜语法约束解码下的模态安全对齐

研究机构：清华大学、电子科技大学

作者：Yitong Zhang、Shiteng Lu、Jia Li

论文原文见 [arXiv](https://arxiv.org/abs/2606.11817)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.11817)

> 大语言模型（LLM）在代码生成中面临的安全对齐失效问题，通常被归因于提示注入或模型权重篡改，但现有防御机制普遍假设自然语言拒答通道在推理时始终可用。本文指出，广泛采用的语法约束解码（GCD）会静默移除该通道，导致模型被迫在代码模态中生成恶意代码，且无需任何对抗性语法或梯度优化。针对此盲区，CodeShield 通过直接偏好优化（DPO）训练模型生成“蜜罐代码”，在语法合法的前提下实现语义无害。该工作揭示了推理框架层面的内生安全漏洞，但蜜罐代码对复杂语法收紧的鲁棒性边界尚待进一步压力测试。

## 研究背景

当 LLM 被要求生成恶意代码时，其安全对齐机制通常通过输出自然语言拒答（如“我无法协助”）来阻断风险。然而，主流推理框架（如 VLLM、SGLANG）为提升代码生成的语法可靠性，普遍支持 GCD，该机制通过掩码非法 token 将输出空间限制在特定编程语言的语法树内。这一机制的引入改变了安全对齐的底层假设：GCD 将自然语言拒答排除在有效输出空间之外，迫使模型在无法表达拒答的情况下，继续生成符合语法的代码。

现有安全对齐研究主要聚焦于输入侧的提示工程或模型侧的偏好优化，其核心目标是将恶意提示的概率质量导向自然语言拒答集合。这一范式隐含了一个关键前提：推理时自然语言模态始终可访问。然而，随着 GCD 在工业界成为标准配置，这一前提在代码生成场景中不再成立。当输出空间被限制为纯代码时，模型在代码模态中的行为缺乏显式的安全约束，导致其倾向于复现训练数据中的恶意代码模式。

本文的切入点在于识别并量化这一“模态错位”风险。不同于依赖对抗性语法或复杂提示工程的攻击，CodeSpear 仅利用标准编程语言语法即可触发安全失效。这要求防御机制不能仅依赖自然语言拒答，而必须在代码模态内部建立独立的安全行为准则，即当自然语言不可用时，模型应生成语法合法但语义无害的代码。

## 核心方法

### 方法参照系

本文问题属于 LLM 安全对齐范畴，但与传统 DPO 流程存在关键差异。标准 DPO 通过构造“拒答 vs 恶意代码”的偏好对，优化模型在自然语言模态下的拒绝行为。本文的核心差异在于，攻击向量（GCD）改变了有效输出空间，使得标准 DPO 训练出的拒答行为在推理时失效，因此需要在代码模态中重新定义“安全响应”的分布。

### CodeSpear：基于 GCD 的模态劫持攻击

CodeSpear 的攻击机制在于利用 GCD 对输出空间的限制，切断模型的自然语言拒答通道。其设计动机在于揭示现有安全对齐对自然语言模态的过度依赖。攻击过程无需修改模型权重或构造对抗性语法，仅需调用标准 GCD 接口。给定恶意提示 $p$ 和标准代码语法 $G$，模型在 GCD 约束下的输出分布为：

$$ P_{M[G]}(y|p) = \frac{P_M(y|p)}{\sum_{y' \in L(G)} P_M(y'|p)} \quad \text{if } y \in L(G), \quad 0 \text{ otherwise} $$

该公式表明，GCD 将概率质量重新归一化至语法合法集合 $L(G)$ 内。由于自然语言拒答 $y_{refuse} \notin L(G)$，其概率被置零，模型被迫在代码空间内采样。若模型在代码模态中未接受过安全对齐，其生成的代码 $y$ 将直接实现恶意需求，从而绕过安全机制。

### CodeShield：代码模态下的蜜罐代码对齐

CodeShield 旨在修复 GCD 导致的安全失效，其设计动机在于为模型提供在代码模态中“安全且难以被语法收紧抑制”的行为模式。传统防御可能训练模型生成固定的拒答注释或 `pass` 语句，但攻击者可通过收紧语法（如禁止注释）轻易移除这些模式。CodeShield 引入“蜜罐代码”（Honeypot Code）作为正样本，要求代码语义无害且结构多样。偏好对构造包含三类响应：自然语言拒答 $y_{refuse}$、蜜罐代码 $y_{honeypot}$ 和恶意代码 $y_{harmful}$。偏好层级定义为 $y_{refuse} \succ y_{honeypot} \succ y_{harmful}$。DPO 优化目标为：

$$ \mathcal{L}_{DPO} = -\mathbb{E}_{(p, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{P_{\theta}(y_w|p)}{P_{ref}(y_w|p)} - \beta \log \frac{P_{\theta}(y_l|p)}{P_{ref}(y_l|p)} \right) \right] $$

其中 $y_w$ 为优选响应（$y_{refuse}$ 或 $y_{honeypot}$），$y_l$ 为劣选响应（$y_{honeypot}$ 或 $y_{harmful}$）。通过随机采样自通用代码库的蜜罐代码，模型学习到在代码模态中保持语法合法的同时，避免实现恶意功能。这种结构多样性使得攻击者无法通过单一语法收紧规则排除所有安全行为，从而提升了防御的鲁棒性。

## 实验评估

实验在 10 个 LLM（包括 Qwen2.5-Coder-7B、GPT-5 等）和 4 个基准（RMCBench、MalwareBench、HumanEval、MBPP）上进行。基线覆盖 CodeJailbreaker 等攻击方法，但缺乏与 RESCUE、SecCoderX 等主流防御方法的横向对比，限制了防御效果的相对评估。

| 模型 | 攻击方式 | ASR (%) | MR (%) |
| :--- | :--- | :--- | :--- |
| Qwen2.5-Coder-7B | 无攻击 | 28.36 | 22.05 |
| Qwen2.5-Coder-7B | CodeSpear | 83.11 | 54.12 |
| Qwen2.5-Coder-7B | CodeSpear + CodeShield | 5.57 | 2.78 |
| MiniMax-M2.7 | CodeSpear | 85.53 | 64.29 |

CodeSpear 在本地部署模型上平均 ASR 达 81.82%，在 API 模型上提升超过 40 个百分点，显著高于 CodeJailbreaker 的 40.11% ASR。CodeShield 将 Qwen2.5-Coder-7B 在 CodeSpear 攻击下的 ASR 从 83.11% 降至 5.57%，低于无攻击基线，表明其不仅修复了漏洞，还增强了内生安全性。

消融实验显示，蜜罐代码样本数 $K$ 从 1 增至 10 时，ASR 稳定在低位，而功能保持性（pass@1）在 $K=5$ 时达到平衡。Qwen2.5-Coder-7B 在 MBPP 上的 pass@3 仅从 78.00% 降至 77.00%，部分模型（如 Qwen2.5-7B）甚至出现功能提升，归因于通用代码数据的引入。

评估边界方面，实验未报告置信区间，且缺乏与基于 RL 或 RAG 的防御方法在相同 GCD 攻击下的对比。代码未公开，超参数（如学习率 1e-5、epoch 1）固定，可复现性依赖特定推理框架的 GCD 实现。

## 关联研究分析

从问题动机看，本文与 SecCoderX 均关注功能-安全联合优化，但 SecCoderX 通过在线强化学习解决功能-安全悖论，假设自然语言拒答通道可用；本文则揭示在 GCD 约束下，该通道失效，需引入代码模态特定的安全行为。这一差异源于任务特性：SecCoderX 针对常规代码生成，而本文针对推理框架层面的解码约束，后者是 Agent 工具调用的核心组件，攻击面更底层。

从方法设计看，CodeShield 与 RESCUE 均利用外部代码库，但 RESCUE 用于检索增强生成以提升安全性，而 CodeShield 将代码库用于构造 DPO 偏好对中的正样本。CodeShield 的蜜罐代码设计解决了 RESCUE 等 RAG 方法在 GCD 下可能失效的问题，因为 RAG 检索的内容若不符合语法约束，同样会被 GCD 过滤或导致生成中断。CodeShield 通过训练模型内生地生成符合语法的无害代码，避免了对外部检索结果的依赖，提升了在受限解码场景下的鲁棒性。

## 总结

本文核心矛盾在于现有安全对齐对自然语言拒答通道的依赖与 GCD 对该通道的静默移除之间的冲突。CodeSpear 通过利用标准语法约束揭示了这一漏洞，CodeShield 则通过 DPO 训练模型生成结构多样的蜜罐代码，在代码模态中重建安全行为。实验证明 CodeShield 将 Qwen2.5-Coder-7B 在 CodeSpear 攻击下的 ASR 从 83.11% 降至 5.57%，同时保持功能性能。其边界在于蜜罐代码的多样性是否足以抵抗更复杂的语法收紧攻击，以及缺乏与主流防御方法的横向对比。当攻击者采用自适应语法收紧策略时，蜜罐代码的鲁棒性是否仍能维持，论文未给出充分回答。
