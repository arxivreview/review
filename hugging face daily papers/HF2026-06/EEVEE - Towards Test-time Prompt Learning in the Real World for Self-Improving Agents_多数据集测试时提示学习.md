研究机构：上海交通大学、美国普林斯顿大学

作者：Weixian Xu、Shilong Liu、Mengdi Wang

论文原文见 [arXiv](https://arxiv.org/abs/2606.11182)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.11182)

> 现有测试时提示学习方法在处理单一任务流时表现良好，但面对真实部署中异构的多域数据流时，单一提示更新往往导致跨任务干扰与性能退化。Eevee 通过引入路由器将输入流划分为任务簇，并采用路由器-提示共进化策略，解决了这一多数据集适应中的互斥问题。该方法在四基准混合流上实现了正向的累计保留增益，显著优于基线方法，但其对规则标签的依赖限制了其作为纯无监督适应机制的泛化边界。

## 研究背景

当大语言模型（LLMs）部署于真实环境时，输入查询往往来自不同的领域、格式与能力混合体，而非单一静态分布。这种异构性导致传统的测试时提示学习（Test-time Prompt Learning）面临跨数据集干扰：针对某一域优化的提示更新，可能破坏另一域已习得的行为。解决这一问题的核心在于如何在不更新模型权重的前提下，利用无标签或反馈驱动的测试流，实现多任务下的稳定适应。

测试时提示学习旨在通过优化提示词来适应新输入与分布偏移，是轻量级适应的主流范式。然而，现有方法如 GEPA 和 ACE 主要假设统一适应目标或固定提示空间，通常针对单一数据集或基准进行优化。当多个基准进入适应流时，这些方法在先前任务上积累负向保留（Negative Retention），表明单一学习提示难以吸收异构反馈而不丢失任务特异性行为。Eevee 的切入点在于打破单一提示的约束，通过引入路由器机制，将异构流分解为任务簇，并让不同簇调用专门的提示配置，从而在保留专业化的同时从混合流中学习。

## 核心方法

### 方法参照系

Eevee 属于提示调优与优化路线，但针对多数据集场景进行了扩展。与单域熵最小化或一致性正则不同，其核心差异在于引入了条件化的提示选择机制，即路由器，以解决多任务流中的干扰问题。

### 路由器-提示共进化

单一提示无法兼容多域反馈，Eevee 维护提示集 $P = \{p_1, \dots, p_K\}$ 与路由器 $R$。路由器 $R$ 将输入 $x$ 映射到特定提示槽位 $k$，目标模型 $M$ 随后使用 $p_k$ 生成回答。由于路由决策决定了每个提示看到的数据，而提示质量又决定了路由的有效性，两者存在耦合依赖。Eevee 采用共进化策略，交替执行路由器进化与提示进化。在路由器进化阶段，固定提示集，通过变异与反思优化路由规则，其评分函数综合考虑下游准确率、一致性与平衡性：

$$
S(R) = \alpha \cdot \text{Acc}(R) + \beta \cdot \text{Consistency}(R) + \gamma \cdot \text{Balance}(R)
$$

该公式通过退火机制动态调整权重，早期侧重多样性，后期侧重准确率，避免了固定路由对异构任务结构的僵化拟合。

### 三阶段训练与帕累托前沿管理

为解决共进化中的效率与稳定性问题，Eevee 设计了初始化、探索与收敛三阶段。初始化阶段通过贪心覆盖规则从帕累托前沿池中选取初始提示集，确保提示行为的互补性。探索阶段在轻量预算下交替更新路由器与提示，防止在不稳定路由下浪费优化预算。收敛阶段固定稳定后的路由器，分配更大预算进行提示精调。提示进化阶段利用帕累托前沿池管理候选提示，仅当新提示在验证集上的正确性向量不被现有提示支配时，才进入池子：

$$
p_{new} \in \mathcal{P}_{frontier} \iff \nexists p_{old} \in \mathcal{P}_{frontier}, \text{ s.t. } \mathbf{c}(p_{old}) \ge \mathbf{c}(p_{new}) \land \mathbf{c}(p_{old}) \neq \mathbf{c}(p_{new})
$$

这一机制保留了多样化的有效提示，避免了单一最优提示对特定任务行为的过拟合，从而在混合流中维持了跨任务的稳定性。

## 实验评估

实验在 GPQA Diamond、Formula、TheoremQA 和 HumanEval 四个基准上进行，对比基线包括 GEPA、ACE 及未适应的目标模型（Qwen3-4B-Instruct 和 DeepSeek-V3.2）。基线覆盖了反思式提示学习与上下文进化路线，但未包含传统的单域熵最小化方法，这符合 LLM 提示学习的当前主流评估协议。

| 方法 | Qwen3-4B Avg. | DeepSeek-V3.2 Avg. | 累计保留增益 (4 Tasks) |
| :--- | :--- | :--- | :--- |
| Baseline | 41.37 | 39.75 | - |
| GEPA | 37.73 | 55.83 | -15.36 |
| ACE | 34.92 | 49.83 | -18.58 |
| **Eevee** | **51.75** | **64.07** | **+41.53** |

Eevee 在 Qwen3-4B 上比基线高 10.38 分，在 DeepSeek-V3.2 上高 24.32 分。在增量多基准保留测试中，Eevee 最终累计增益为 +41.53，而 GEPA 和 ACE 分别为 -15.36 和 -18.58，表明路由器机制有效抑制了跨任务干扰。

消融实验显示，默认路由器（43.58）和手动路由器（37.18）均显著低于完整 Eevee（51.75），且无共进化变体（42.88）也低于完整方法。这表明学习到的路由与交替优化是性能提升的关键，静态分区或两阶段学习无法捕捉路由与提示间的相互依赖。此外，Eevee 的 Token 成本为 4.32k/样本，远低于 ACE 的 21.30k，接近 GEPA 的 3.47k，说明路由机制未引入显著的推理开销。

评估边界方面，实验依赖规则或真值标签进行反馈，未完全实现纯无监督适应。跨模型泛化显示 Qwen3 学习的提示在 DeepSeek 上仍有增益（54.10 vs 39.75），但跨任务泛化在 MMLU-Pro 上出现轻微下降（68.92 vs 70.74），提示学习可能强化通用推理而削弱特定领域知识。代码已开源，但随机搜索导致运行间性能存在波动。

## 关联研究分析

从问题动机看，Eevee 与 VLM 领域的测试时适应（TTA）方法如 TPT 和 MetaTPT 存在本质差异。TPT 针对单样本域偏移，通过优化文本提示对齐视觉特征，其核心假设是测试分布与预训练分布的协变量偏移。而 Eevee 面对的是多数据集异构流，其核心矛盾是跨域干扰而非单一域偏移。TPT 的熵最小化目标在 Eevee 的多任务场景中会导致类坍缩或任务互斥，因此 Eevee 采用反思与进化搜索替代熵最小化，利用语义反馈而非概率分布进行优化。这一差异源于 LLM 输出的离散性与语义丰富性，使得基于概率的熵最小化难以捕捉任务特异性行为。

从方法设计看，Eevee 的路由器机制与 VLM 中的原型缓存（如 TDA）有相似之处，均通过维护多个参考点（提示或原型）来适应不同输入。然而，TDA 的原型是基于特征空间的几何距离更新，而 Eevee 的路由器是基于语义规则的离散选择。TDA 在资源受限场景下具有无梯度优势，但灵活性受限；Eevee 的路由器需要学习，计算开销略高，但能处理更复杂的任务结构。Eevee 未探索将原型缓存与路由器结合的可能性，即是否可以用特征原型作为路由器的输入特征，从而降低路由学习的难度。这一盲区可能限制了其在高维特征空间中的扩展性。

## 总结

Eevee 解决了多数据集测试时提示学习中跨域干扰导致性能退化的核心矛盾。现有方法如 GEPA 和 ACE 因单一提示空间无法兼容异构反馈，在任务增加时出现负向保留。Eevee 通过引入路由器将输入流划分为任务簇，并采用路由器-提示共进化策略，实现了多任务下的稳定适应。实验证明其在四基准混合流上实现了 +41.53 的累计保留增益，显著优于基线的负值。然而，其依赖规则标签的反馈机制限制了纯无监督场景的适用性，且跨任务泛化在知识密集型任务上出现轻微下降。当适应数据分布与真实应用存在偏差时，学习到的提示是否仍能保持鲁棒性，论文未给出明确回答。
