论文原文见 [arXiv](https://arxiv.org/abs/2606.20945)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.20945)

> 长上下文 Transformer 中，自注意力的二次方复杂度与均匀激活所有查询头导致算力浪费，现有稀疏化方法多聚焦于限制 Token 交互范围或改变 KV 缓存结构，却忽视了查询头层面的条件计算潜力。本文切入点在于将混合专家（MoE）路由机制从 MLP 块迁移至分组查询注意力（GQA）的查询头内部，在不改变 KV 缓存密度的前提下，实现查询侧计算的稀疏化。具体做法是保留 GQA 的 KV 共享结构，通过路由器为每个 Token 动态选择组内 Top-k 查询专家，并引入重归一化加权槽位与常驻共享头以稳定训练。该方法在 250M 参数规模下以 9/16 的查询计算量匹配了全激活 GQA 基线的精度，但缺乏大规模模型验证及与线性注意力架构的对比，其“无损加速”结论的普适性存疑。

## 研究背景

当序列长度延伸至百万级 Token 时，标准自注意力机制中 Token 间交互数量的二次方增长成为计算瓶颈。为缓解这一问题，分组查询注意力（GQA）通过让多个查询头共享同一组键值（KV）头，显著降低了 KV 缓存的内存带宽压力，成为当前大语言模型的主流配置。然而，GQA 仅优化了 KV 侧的存储与读取，仍要求每个 Token 激活所有查询头进行计算。这种均匀分配策略忽略了 Token 信息密度的异质性：承载关键语义或长程依赖的 Token 可能需要特定的注意力模式，而标点、停用词等低信息量 Token 则无需全量查询头参与。若不同 Token 所需的查询头存在差异，则对所有 Token 执行全量查询头计算即为冗余开销。

注意力效率优化的主流路线分为稀疏化与线性化两类。稀疏化方法如 Longformer 或 HySparse 通过限制 Token 交互范围或动态选择重要 Token 来降低复杂度，但往往面临训练-推理不匹配或动态选择计算开销抵消收益的问题；线性化方法如 Mamba 移除 Softmax 归一化以实现线性复杂度，却在深层序列组合任务上存在表达力理论下界劣势。现有研究多关注如何减少参与注意力的 Token 数量或改变注意力数学形式，较少从“查询头条件计算”角度切入，即在不改变 KV 路径密度的前提下，通过路由机制跳过不必要的查询头计算。本文旨在填补这一空白，探索将 MoE 条件计算思想应用于 GQA 查询头内部，以解决均匀激活导致的算力浪费问题。

## 核心方法

### 方法参照系

本文方法建立在 GQA 架构之上，其标准流程是将 $N$ 个查询头划分为 $G$ 组，每组共享一个 KV 头，所有查询头对每个 Token 均执行计算。与常规稀疏注意力限制 Token 交互范围不同，GQE 保持 KV 路径完全密集，仅对查询头进行组内路由，核心差异在于计算稀疏性发生在查询投影与注意力得分计算阶段，而非 KV 缓存或 Token 选择阶段。

### 组内查询专家路由

在 GQA 的每组内，$M = N/G$ 个查询头被视为专家池。路由器对每个 Token $x_i$ 在组 $g$ 内的专家产生概率分布，通过 Softmax 归一化后选取 Top-$k$ 专家。该设计动机在于解决固定稀疏模式无法适应 Token 异质性的问题，使模型能根据 Token 内容动态分配查询计算资源。路由分数计算如下：

$$ p_{i,g,m} = \text{softmax}_m(\text{Router}(x_i, g)) $$

其中 $m$ 遍历组 $g$ 内的所有专家。选取概率最高的 $k$ 个专家 $K_g(x_i)$ 执行注意力计算，其余专家被跳过。这一机制将查询头计算从全激活转变为条件激活，直接减少了注意力得分矩阵的计算量。

### 输出构建与路由信号稳定

仅靠硬路由（Hard Concat）无法为路由器提供有效的梯度信号，因为 Top-$k$ 选择操作不可微。为解决此失效，GQE 在输出构建中引入两个关键组件：一是常驻共享头 $s(x_i)$，为每个 Token 提供稳定的基础注意力路径；二是重归一化加权槽位，利用路由概率对选中专家输出进行加权求和。最终输出拼接硬路由专家输出、加权槽位与共享头输出：

$$ \text{Out}_i = \text{Concat}\left( \{o_{i,g,m}\}_{m \in K_g(x_i)}, \sum_{g} \sum_{m \in K_g(x_i)} \frac{p_{i,g,m}}{\sum_{m'} p_{i,g,m'}} o_{i,g,m}, s(x_i) \right) $$

加权槽位提供了从语言建模损失到路由器的可微路径，使路由器能学习“哪个 Token 需要哪个专家”；共享头则锚定训练过程，防止路由专家在训练初期因信号不稳定而崩溃。此设计确保了稀疏路由在保持表达力的同时具备可训练性。

## 实验评估

实验在 250M 参数规模、30B Token 预算下进行，使用 FineWeb-Edu 子集训练，评估基准包括 HellaSwag、PIQA 和 ARC-Easy。基线仅对比全激活 GQA 模型，未包含 Mamba、FlashAttention 或线性注意力等知识库中常见的强基线，限制了方法在效率-精度权衡全景中的定位。

| 变体 | HellaSwag | ARC-Easy | PIQA | 平均 |
| :--- | :--- | :--- | :--- | :--- |
| GQA 基线 (16 头全激活) | 41.31 | 61.36 | 64.90 | 55.86 |
| 加权拼接，无重归一化槽位 | 40.16 | 60.52 | 64.85 | 55.18 |
| 仅硬拼接 | 40.66 | 60.56 | 65.07 | 55.43 |
| **GQE (重归一化 + 共享头)** | 41.01 | 62.41 | 64.69 | **56.04** |

消融实验揭示了路由成功的关键依赖：无重归一化槽位的加权拼接平均精度比基线低 0.68 分，仅硬拼接低 0.43 分，而完整 GQE 变体以 56.04 的平均精度略超基线。这表明稀疏路由的有效性并非源于稀疏性本身，而是依赖于路由器获得归一化学习信号及共享头提供的稳定性锚点。在吞吐量方面，GQE 在 4k 至 1024k Token 序列长度下实现了 1.67× 至 1.80× 的预填充加速，验证了查询侧计算减少在长上下文场景下的实际收益。

评估边界存在明显局限：实验仅在 250M 参数规模下验证，未测试更大模型中路由器的泛化能力；未报告长上下文（>128k）下的精度保持情况，仅展示吞吐量；缺乏与 Mamba 等线性架构在相同计算预算下的对比，无法判断 GQE 是否优于架构重构路线。论文未提供代码链接，超参数细节虽在附录中列出，但 ZClip 等训练技巧的具体配置可能影响复现结果。

## 关联研究分析

从方法设计看，GQE 与 Sparse Query Attention (SQA) 均旨在减少查询头计算，但 SQA 通过全局减少查询头数量来降低复杂度，而 GQE 在 GQA 组内保留完整专家池并动态路由。SQA 的静态头数减少可能导致特定 Token 类型（如长程依赖 Token）缺乏必要的注意力模式，而 GQE 的动态路由理论上能保留更多样的注意力模式。然而，GQE 的路由开销（路由器计算与调度）在小序列长度下（2k Token）仅带来 1.15× 加速，表明其收益高度依赖序列长度，这与 SQA 的固定计算节省形成对比。GQE 未探索更大专家池（$M$ 增大）下的路由性能，而 SQA 的头数选择通常基于全局重要性评估，两者在“静态全局优化”与“动态局部路由”之间的取舍尚未在统一基准下充分比较。

从问题动机看，GQE 与 All-or-Here Attention (AoHA) 均涉及条件计算，但 AoHA 通过二元门控将 Token 路由至全注意力或局部窗口注意力路径，改变的是注意力的空间范围；GQE 则保持全注意力空间范围，仅改变查询头的激活子集。AoHA 的局部窗口路径在长程依赖任务上可能存在信息截断风险，而 GQE 通过保留共享头与动态专家组合，理论上能更好地维持长程依赖捕获能力。但 GQE 未报告在需要精确长程依赖的任务（如 MATH500 或 InfiniteBench）上的表现，而 AoHA 类方法通常在长上下文基准上有更多验证。GQE 声称的“无质量损失”仅在短程推理任务（HellaSwag, PIQA）上验证，其在复杂推理任务上的表现未知，这限制了其作为通用注意力优化方案的说服力。

## 总结

本文核心矛盾在于长上下文下查询头均匀激活导致的算力浪费与稀疏路由训练不稳定的冲突。GQE 抓住 GQA 组内查询头可独立路由的特性，通过引入重归一化加权槽位与常驻共享头，解决了硬路由缺乏梯度信号的问题，实现了查询侧计算的条件化。在 250M 参数规模下，GQE 以 9/16 的查询计算量匹配了 GQA 基线精度（56.04 vs 55.86），并在长上下文下获得 1.7-1.8× 加速。其边界在于实验规模过小、缺乏长上下文精度验证及与线性架构的对比，未证明该路由机制在更大模型或更复杂推理任务中仍能保持“无损”。当模型参数扩展至 7B 以上时，路由器能否在更大专家池中维持稳定的专家利用率而不导致负载失衡，论文未给出回答。
