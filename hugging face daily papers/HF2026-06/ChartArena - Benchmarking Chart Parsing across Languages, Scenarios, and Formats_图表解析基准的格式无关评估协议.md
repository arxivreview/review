> 图表解析领域长期受困于评估碎片化：不同模型输出Markdown、JSON或代码等互不兼容格式，且现有基准仅覆盖少数数字图表类型，缺乏对流程图等图结构及真实拍摄场景的测试。ChartArena通过构建涵盖八类图表、三种视觉场景及双语内容的综合基准，并设计将异构输出归一化为三元组或有向图的格式无关评估协议，解决了跨模型公平比较的难题。该工作填补了评估基础设施的空白，但其归一化过程对细粒度布局错误的检测能力仍存疑。

## 研究背景

当多模态大语言模型（MLLMs）将图表解析重构为端到端序列生成任务时，模型直接映射像素至序列化输出，如Markdown或Python代码。这种范式虽提升了泛化能力，却导致输出格式高度异构：同一语义内容可能以表格、JSON结构或代码形式呈现，使得直接跨模型比较变得不可行。此外，真实世界中的图表常以打印照片或手绘草图形式存在，包含模糊、透视畸变等视觉噪声，而现有基准多聚焦于纯净的数字渲染图，无法反映实际部署条件。

图表解析评估的碎片化源于三个叠加因素：输出格式孤岛化、基准覆盖窄域化以及数据场景单一化。主流基准如ChartQA和PlotQA主要关注条形图、折线图等数字图表，忽略了需要图结构理解的流程图和思维导图，且缺乏对真实视觉扰动的测试。这种碎片化使得研究者难以识别模型在复杂场景下的具体失效点，阻碍了从“受控基准高性能”向“真实环境鲁棒解析”的演进。ChartArena的切入点在于构建一个统一框架，同时覆盖数字与图结构图表、多种视觉场景及双语内容，并通过格式无关协议消除语法差异对语义评估的干扰。

## 核心方法

### 方法参照系

传统图表解析评估依赖于特定输出格式的字符串匹配或模板解析，如针对Markdown表格的行级比对。本文问题的关键差异在于：模型输出格式多样且互不兼容，直接比对无法反映语义一致性。因此，评估流程需从“格式特定解析”转向“格式无关归一化”，将任意格式映射至统一语义空间后再进行结构感知评分。

### 格式无关归一化

归一化环节通常由格式特定的解析器完成，如从Markdown提取表格行或从JSON解析列字典。本文创新在于设计确定性管道，将所有模型输出映射至两个规范语义空间：数字图表的归一化三元组视图和图结构图表的有向图视图。对于数字图表，输出被解析为$(header, entity, value)$三元组集合，通过词法和数值规范化处理等价值（如“3.0”与“3”）。对于流程图和思维导图，输出被归一化为带标签节点和有向边的图结构，抽象掉Mermaid、Graphviz等图语言的语法差异。这一设计消除了格式选择对评分的影响，确保分数差异反映语义理解而非表面语法。

$$
T_{pred} = \{ (h_i, e_i, v_i) \mid (h_i, e_i, v_i) \in \text{Normalize}(O_{model}) \}
$$

其中$O_{model}$为模型原始输出，$T_{pred}$为归一化后的三元组集合，$\text{Normalize}$为确定性解析与规范化函数。

### 结构感知评分

评分环节通常基于字符串相似度或令牌重叠，但无法捕捉结构错误。本文创新在于采用结构感知指标，对三元组使用交集并集比（IoU）计算重叠，对图结构使用匈牙利算法匹配节点和边，并赋予边更高权重以惩罚拓扑错误。评分在三个容差水平（strict, slight, high）下进行，最终报告mAPhigh作为主指标，平衡标注歧义鲁棒性与结构一致性。

$$
\text{mAP}_{high} = \frac{1}{|\Theta|} \sum_{\theta \in \Theta} \text{AP}(\theta)
$$

其中$\Theta$为容差阈值集合，$\text{AP}(\theta)$为在阈值$\theta$下的平均精度，mAPhigh通过多阈值平均提供分级正确性视图。

## 实验评估

实验在ChartArena基准上进行，涵盖26个模型，包括通用MLLMs（如Gemini 3.1 Pro、Qwen3.5-35B-A3B）、文档解析MLLMs（如HunyuanOCR）和专家图表解析器（如RRVF）。基线覆盖了三类主流路线，但缺失知识库中最新的RLVR优化模型（如Chart-RL），这可能低估了当前SOTA在复杂推理上的真实水平。

| 模型 | 类型 | 平均EN | 平均ZH |
| :--- | :--- | :--- | :--- |
| Gemini 3.1 Pro | 通用MLLM | 59.2 | 73.2 |
| Qwen3.5-35B-A3B | 通用MLLM | 56.0 | 67.1 |
| HunyuanOCR | 文档解析 | 41.4 | 52.8 |
| RRVF | 专家解析 | 36.0 | 51.0 |

Gemini 3.1 Pro以59.2 EN/73.2 ZH领先，但开源模型Qwen3.5-35B-A3B（56.0 EN）与其差距较小。文档解析模型在数字图表上表现合理，但在流程图上显著落后于通用MLLMs，如HunyuanOCR在流程图上得39.9 EN，比Gemini 3.1 Pro低25.7 EN。

| 模型 | 格式 | mAPhigh (数字) | mAPhigh (流程图) |
| :--- | :--- | :--- | :--- |
| Seed-2.0 Pro | Markdown | 54.9 | 58.3 |
| Seed-2.0 Pro | JSON | 59.1 | 62.0 |
| Qwen3.5-35B-A3B | Markdown | 56.0 | 57.0 |
| Qwen3.5-35B-A3B | JSON | 46.9 | 59.5 |

格式适应性实验显示，同一模型在不同输出格式下得分存在差异，如Seed-2.0 Pro在JSON格式下数字图表mAPhigh为59.1，高于Markdown的54.9。这表明归一化协议虽能消除部分格式偏差，但模型对特定格式的生成质量仍影响最终得分。

评估边界方面，ChartArena未报告计算效率指标，且归一化过程可能丢失细粒度布局信息，如元素相对位置错误。代码已开源，但标注细节和超参数配置在附录中，可复现性依赖对归一化管道的完整实现。

## 关联研究分析

从问题动机看，ChartArena与MoCA等代码生成方法共享“代码是精确表示”的假设，但MoCA聚焦于生成可执行代码以支持编辑，而ChartArena将代码仅作为评估中间态，用于验证结构保真度。这一差异源于任务特性：MoCA需解决动态编辑中的状态一致性，而ChartArena需解决静态解析中的公平比较。MoCA在ChartMimic上95.66的执行率表明代码范式在生成任务上的优势，但ChartArena未测试此类模型，可能高估了通用MLLMs在结构理解上的相对差距。

从方法设计看，ChartArena与ChartPoint等视觉接地方法在解决数值幻觉上路径不同。ChartPoint通过显式坐标提示约束视觉搜索空间，而ChartArena通过归一化三元组隐式处理数值对齐，未引入坐标信息。这种设计选择反映了评估与优化的目标差异：ChartPoint旨在提升模型感知精度，而ChartArena旨在提供公平比较框架。ChartPoint在密集图表上的优势是否能在ChartArena的格式无关协议下复现，论文未给出回答。

## 总结

ChartArena要解决的核心矛盾是图表解析评估的碎片化，即异构输出格式、窄域覆盖和单一场景导致无法公平比较模型能力。其切入点在于构建统一基准和格式无关协议，通过归一化消除语法差异，使分数反映语义理解。该工作证明了通用MLLMs在整体性能上领先，但开源模型正在缩小差距，且文档解析模型在图结构上存在显著短板。其边界在于归一化过程可能丢失细粒度布局错误，且未包含RLVR优化模型，可能低估当前SOTA水平。当支持集增大到真实世界复杂场景时，归一化协议对细粒度布局错误的检测能力是否足够，论文未给出回答。
