> 现有数学推理基准多聚焦于最终答案匹配或自然语言证明的文本质量，无法有效区分模型是真正理解了离散结构还是仅生成了流畅但无效的论证。ComBench 针对这一盲区，将“严格证明推理”与“构造性实现”解耦，通过引入确定性 Python 验证器对离散见证物进行机器可检查的验证。该基准揭示了前沿模型在证明能力与构造能力上的显著解耦，为诊断组合数学中的创造性推理缺口提供了新工具，但其评估范围局限于特定离散对象，对更广泛数学领域的泛化性尚待检验。

## 研究背景

组合数学问题的求解往往要求模型不仅给出逻辑严密的证明，还必须显式构造出满足全局约束的离散对象，如着色方案、铺砌结构或图实例。这种“构造性实现”能力要求模型将存在性论证转化为具体、无歧义且可验证的见证物，而自然语言描述难以可靠评估此类对象的全局有效性。现有基准如 GSM8K 和 MATH 主要依赖最终答案匹配，IMO-Bench 等则采用评分标准评估证明文本，但均无法直接验证构造对象的数学正确性。

随着大语言模型在竞赛级数学基准上接近饱和，研究重心转向诊断模型在复杂推理中的具体短板。主流路线如 RLVR 训练提升了长链推理能力，但未能解决离散结构构造中的逻辑一致性问题。ComBench 的切入点在于，通过可执行验证器将构造任务从自然语言评估中剥离，直接检查见证物的数学约束，从而精准定位模型在“证明”与“构造”两个维度上的能力差异。

## 核心方法

### 方法参照系

ComBench 属于形式化验证与评估基准类别，其核心差异在于不依赖 Lean/Coq 等通用定理证明器，而是针对离散组合对象设计特定 Python 验证器。与 IMO-Bench 的纯文本评分不同，ComBench 将评估目标从“证明质量”扩展至“证明+构造”双任务，通过机器可检查性确保构造对象的数学有效性。

### 验证器门控评分机制

传统评估中，构造失败常被忽略或仅作为次要指标，导致高评分证明可能包含未实现的构造缺口。ComBench 引入验证器门控评分，将构造有效性作为证明得分的硬性约束。对于构造中心记录，模型输出证明得分 $p \in \{0, 1, 6, 7\}$ 和二元构造得分 $c \in \{0, 1\}$。若构造通过，最终得分保持 $p$；若构造失败，高分被降级：$7 \to 6$ 且 $6 \to 1$，而 $0$ 和 $1$ 保持不变。该机制确保高评分证明必须伴随可验证的构造，避免“流畅但无效”的论证获得高分。

$$
\text{Final Score} = \begin{cases}
p & \text{if } c = 1 \\
\min(p, 6) & \text{if } c = 0 \text{ and } p = 7 \\
1 & \text{if } c = 0 \text{ and } p = 6 \\
p & \text{if } c = 0 \text{ and } p \in \{0, 1\}
\end{cases}
$$

此公式体现了“构造确认实现”的设计动机：有效见证物不是额外奖励，而是高评分构造性解决方案的必要条件。

### 离散见证物验证流水线

构造中心记录需包含特定构造指令、参考见证物、非形式化验证计划及确定性 Python 验证器代码。验证器仅读取原始构造负载，检查声明的表示形式和数学约束。该流水线通过 LLM 辅助语义审计确保从原始问题到可执行验证器的一致性，防止上游规格问题或验证器生成错误。参考见证物通过同一原始标准输入接口传递给验证器，仅当检查成功时记录才被接受，确保验证器的严格性和覆盖性。

## 实验评估

实验在 ComBench 的 100 道组合数学问题上评估 10 个前沿模型，包括 GPT-5.5、Gemini-3.1-Pro 和 Kimi-K2.6 等。基线覆盖闭源和开源模型，但缺失专门针对构造任务的 RLVR 训练模型，如 DeepSeekMath-V2 在构造任务上的表现未被直接对比。

| 模型 | 分析中心 Avg. (%) | 分析中心 Best@4 (%) | 构造中心 Avg. (%) | 构造中心 Best@4 (%) | 总体 Avg. (%) | 总体 Best@4 (%) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-5.5 | 62.4 | 72.9 | 65.4 | 75.3 | 65.4 | 75.3 |
| Gemini-3.1-Pro | 56.1 | 69.7 | 64.5 | 78.3 | 60.3 | 74.0 |
| Kimi-K2.6 | 43.5 | 60.6 | 63.4 | 83.7 | 53.5 | 72.1 |
| DeepSeek-V4-Pro | 37.8 | 56.6 | 52.6 | 67.7 | 45.2 | 62.1 |

GPT-5.5 在总体 Avg. 上以 65.4% 领先，但 Kimi-K2.6 在构造中心 Best@4 上以 83.7% 超越 GPT-5.5 的 75.3%，表明构造能力并非证明能力的简单副产品。

| 模型 | 证明得分 (%) | 构造通过率 (%) | 验证器门控得分 (%) |
| :--- | :--- | :--- | :--- |
| GPT-5.5 | 72.3 | 75.0 | 68.4 |
| Gemini-3.1-Pro | 68.9 | 75.0 | 64.5 |
| Kimi-K2.6 | 66.3 | 75.0 | 63.4 |
| DeepSeek-V4-Pro | 56.1 | 62.5 | 52.6 |

验证器门控得分普遍低于证明得分，证实高评分证明常伴随无效构造。Kimi-K2.6 的构造通过率与 GPT-5.5 持平，但证明得分较低，进一步验证了两种能力的解耦。

评估边界方面，ComBench 仅覆盖 100 道组合数学问题，未包含非组合数学领域。验证器依赖特定 Python 代码，对复杂全局约束的覆盖性受限于人工审计质量。代码未开源，超参数如温度 0.6 和采样次数 4 固定，可复现性受限于模型版本更新。

## 关联研究分析

从问题动机看，ComBench 与 AlphaGeometry 均强调结构化求解，但 AlphaGeometry 侧重符号推导引擎与神经网络结合，解决几何问题的连续推理，而 ComBench 聚焦离散组合对象的构造验证。差异根源在于任务特性：几何问题可通过符号推导自动验证，而组合构造需检查全局离散约束，Python 验证器更灵活但缺乏通用性。

从方法设计看，ComBench 与 DExploration 均利用可执行手段确保逻辑严谨性，但 DExploration 用于生成形式化问题，ComBench 用于评估答案。ComBench 的验证器门控机制是新增设计，将构造失败作为证明得分的降级条件，而非独立指标。这一选择牺牲了评估的细粒度，换取了“证明-构造”联合有效性的直接度量，但可能掩盖模型在构造尝试中的部分正确性。

## 总结

ComBench 解决了组合数学评估中“证明流畅但构造无效”的矛盾，通过验证器门控评分将构造有效性嵌入证明评估。其核心贡献在于揭示前沿模型在严格证明推理与构造性实现上的解耦，GPT-5.5 总体 Avg. 65.4% 和 Kimi-K2.6 构造 Best@4 83.7% 的数据证实了这一缺口。该基准的边界在于其离散对象验证依赖人工设计的 Python 验证器，对非组合数学领域的泛化性未经验证。当验证器覆盖的离散对象类型扩展至更复杂的代数结构时，其评估协议是否仍能保持区分度，论文未给出回答。
