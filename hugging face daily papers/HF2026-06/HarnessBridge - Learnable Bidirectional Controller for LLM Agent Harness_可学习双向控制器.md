# HuggingFace最新推荐论文 ｜HarnessBridge: Learnable Bidirectional Controller for LLM Agent Harness ｜可学习双向控制器

研究机构：美国加州大学洛杉矶分校

作者：Xiaoxuan Wang、Haixin Wang、Alexander Taylor 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2606.12882)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.12882)

> 长程智能体交互中，静态脚手架导致上下文冗余与无效动作累积，严重侵蚀效率与任务成功率。现有方法将脚手架视为固定基础设施或仅优化外部提示，忽略了运行时信息流的动态调控。本文提出 HarnessBridge，将智能体-环境接口形式化为可学习的双向投影策略，通过轻量模型指令微调实现上下文压缩与动作校验。该方案在保持任务性能的同时大幅降低 Token 消耗，但其泛化性受限于单一代码域训练，且未涉及强化学习以解决深层信用分配问题。

## 研究背景

当智能体执行长程软件工程任务时，交互历史迅速膨胀至数万 Token，其中混杂着过时的错误日志、被推翻的假设及冗余的探索步骤。这种上下文污染不仅推高推理成本，更导致生成器（Generator）在关键决策点丢失任务相关状态。为缓解此问题，传统脚手架（Harness）采用静态规则进行摘要或截断，但这类手工设计的启发式方法无法适应动态变化的任务状态，往往在压缩关键信息的同时保留噪声。

长程智能体研究长期聚焦于提升生成器能力与丰富环境设计，却忽视了中介接口对行为塑造的实质影响。ReAct 范式确立了推理-行动循环，但将脚手架视为固定组件；Meta-Harness 等近期工作尝试搜索外部脚手架配置，仍未触及运行时信息流的动态调控。本文切入点在于将脚手架本身视为可优化的策略对象，解决静态接口在长程交互中无法动态平衡信息暴露与动作执行的问题。

## 核心方法

### 方法参照系

传统智能体框架将脚手架定义为固定序列化函数，直接拼接历史 $H_t$ 输入生成器。本文关键差异在于将脚手架参数化为可学习策略 $\pi_h$，冻结生成器 $\pi_g$，仅优化接口层的双向映射，实现信息流与动作流的独立调控。

### 观察投影

观察投影解决长程历史中决策关键状态被冗余信息淹没的问题。传统摘要方法静态压缩，易丢失未解决错误等动态状态。本文引入主动状态索引 $U_t$ 与单元级曝光决策 $z_i$，对历史单元 $h_i$ 执行 Pass、Compress 或 Drop 操作：

$$ \hat{H}_t = [U_t, \hat{h}_1, \dots, \hat{h}_t], \quad \hat{h}_i = \begin{cases} h_i & z_i = \text{Pass} \\ \text{Compress}(h_i) & z_i = \text{Compress} \\ \emptyset & z_i = \text{Drop} \end{cases} $$

该机制将未解决错误、开放约束等关键信息显式前置，避免生成器从长轨迹中重建当前状态，在压缩冗余的同时保留决策依据。

### 动作投影

动作投影解决生成器输出无效动作消耗环境步数的问题。传统校验仅检查语法，无法识别语义冗余。本文引入轨迹接地拒绝机制，对提议动作 $a_t$ 预测决策 $d_t$ 与反馈 $\rho_t$：

$$ a'_t = \begin{cases} a_t & d_t = \text{Pass} \\ \emptyset & d_t = \text{Reject} \end{cases}, \quad \rho_t = (\text{concern}, \text{evidence}, \text{suggestion}) $$

拒绝时必须提供轨迹接地的证据，否则默认通过。该机制拦截重复无效操作，将环境步数导向高信息量动作，同时通过反馈引导生成器修正方向，避免盲目探索。

## 实验评估

实验在 Terminal-Bench 2.0 与 SWE-bench Verified 上进行，基线覆盖 Terminus 2、OpenHands、Meta-Harness 等静态与搜索型脚手架，但缺乏基于强化学习的生成器优化基线（如 Tool-R0）。

| 模型 | 基准 | SR (%) | Tokens (M) |
| :--- | :--- | :--- | :--- |
| Qwen3.5-35B-A3B | SWE | 59.1 | 1.38 |
| Qwen3.5-35B-A3B | TB | 29.2 | 0.53 |
| GPT-5.4 | TB | 53.9 | 0.99 |
| Claude-Opus-4.7 | TB | 65.2 | 0.19 |

HarnessBridge 在 Qwen3.5-35B-A3B 上 SWE-bench 成功率 59.1%，Token 消耗 1.38M，显著低于 Terminus 2 的 9.41M；在 GPT-5.4 上 TB 成功率保持 53.9%，Token 消耗降至 0.99M，降幅 89.5%。

消融实验显示，移除观察投影或动作投影均导致成功率下降，但 Token 消耗变化不一。观察投影移除后 Token 消耗增加，动作投影移除后 Token 消耗略降但成功率显著下降，表明动作投影对任务完成率的贡献大于其 Token 节省效应。

评估边界受限于代码域，未验证 Web 导航等非代码场景；仅报告单次运行结果，缺乏置信区间；代码与超参数已开源，但商业模型 API 调用细节未完全披露，可复现性受 API 版本波动影响。

## 关联研究分析

从问题动机看，HarnessBridge 与 Reflexion 均关注长程错误累积，但 Reflexion 通过语言反馈优化生成器策略，而 HarnessBridge 冻结生成器，仅优化接口层。这一差异源于任务特性：Reflexion 假设生成器具备自我修正能力，而 HarnessBridge 针对生成器能力固定但接口低效的场景。当生成器本身存在推理缺陷时，接口层优化是否足以弥补，论文未给出回答。

从方法设计看，HarnessBridge 与 Meta-Harness 同属脚手架优化路线，但 Meta-Harness 搜索外部提示与协议变体，属于离线优化；HarnessBridge 学习运行时双向投影策略，属于在线调控。这一差异暗示接口优化与生成器微调可能互补：Meta-Harness 改进静态配置，HarnessBridge 改进动态交互，但两者联合优化时的收益分配与冲突机制，现有研究未探索。

## 总结

本文核心矛盾在于静态脚手架无法动态适配长程交互中的信息流与动作流需求。现有方法将脚手架视为固定基础设施或仅优化外部配置，忽略了运行时接口的策略性作用。HarnessBridge 通过双向投影策略，将观察压缩与动作校验统一为可学习接口，在 Qwen3.5-35B-A3B 上 SWE-bench 成功率 59.1% 且 Token 消耗降低至 1.38M。其边界在于训练数据仅覆盖代码域，且采用监督微调而非强化学习，未解决长程信用分配问题。当支持集扩展至非代码域时，接口策略的泛化能力是否衰减，论文未给出回答。
