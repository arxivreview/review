# HuggingFace最新推荐论文 ｜ProCUA-SFT Technical Report ｜桌面智能体合成数据的前置条件验证框架

研究机构：美国华盛顿大学

论文原文见 [arXiv](https://arxiv.org/abs/2606.17321)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.17321)

> 桌面计算机使用智能体（Computer-Use Agent, CUA）的训练受限于高质量交互轨迹的获取成本，人工标注数据在监督微调（Supervised Fine-Tuning, SFT）中常引发负迁移。现有合成方法因任务不可行或桌面内容空洞，导致生成的轨迹无法支撑复杂跨应用推理。本文提出ProCUA-SFT，通过单视觉语言模型（Vision-Language Model, VLM）闭环生成带前置条件验证的3.1M步级样本，在OSWorld基准上将UI-TARS-7B的成功率从26.3%提升至45.0%。该数据贡献验证了合成数据对SFT上限的突破，但其绝对性能仍低于当前强化学习（Reinforcement Learning, RL）路线的SOTA，数据规模与模型能力的边界尚待厘清。

## 研究背景

CUA通过像素级截图感知桌面状态，并输出键盘鼠标指令执行操作。这一范式摆脱了对HTML或无障碍树等结构化数据的依赖，但每条轨迹均需完整的虚拟机（Virtual Machine, VM）环境——包括启动的操作系统、安装的应用及真实文件内容。这种环境实例化成本使得大规模数据收集远比文本指令微调昂贵，构成了CUA训练的核心瓶颈。

领域主流路线分为人工标注与自动合成两类。人工标注数据集如AgentNet提供22.5K条跨平台轨迹，但实验表明，在UI-TARS-7B上对其进行一个epoch的SFT会导致OSWorld成功率从26.3%骤降至8–10%，归因于任务多样性不足、缺乏跨应用推理及众包标注噪声。自动合成路线如AgentSynth和PC Agent-E尝试用大语言模型生成轨迹，但常面临任务引用不存在文件或应用不可用的问题，浪费计算资源且教模型“发明”状态。本文切入点在于解决合成数据中“任务不可行”与“内容空洞”两个具体子问题，通过前置条件验证与真实内容种子，生成既困难又可行的桌面交互轨迹。

## 核心方法

### 方法参照系

CUA数据合成通常遵循“生成任务-执行轨迹-过滤样本”流程。本文问题与该通用流程的关键差异在于：传统方法在轨迹生成后通过事后过滤剔除失败样本，而本文将可行性验证嵌入任务生成环节，确保每条轨迹在启动前即满足环境约束。

### 前置条件验证闭环

任务生成环节通常由VLM独立输出目标，本文改为要求模型同时生成目标与一组二元前置条件（如“文件Q3.xlsx是否存在于桌面？”）。设计动机是解决合成任务引用不存在资源导致的无效rollout问题。验证过程由独立的Judge策略对每个前置条件进行二元判定，仅当所有条件通过时才执行轨迹。该闭环通过迭代重试机制，将失败判定反馈给生成器，引导其避开已证伪的前置条件。

$$
\text{Accept}(g) = \bigwedge_{i=1}^{n} v_i^{[k]} = 1
$$

该公式表示仅当第$k$轮所有前置条件的判定值$v_i$均为1时，目标$g$才被接受进入rollout阶段。

### 真实内容种子与单VLM执行

桌面初始化环节通常使用默认空状态，本文引入SpreadsheetBench的912个真实电子表格（超100列、20K行）及Zenodo10K的约10K个演示文稿作为种子。设计动机是解决空状态无法支撑跨应用复杂推理（如从表格读取数据并生成图表）的问题。执行环节采用单一VLM（Kimi-K2.5）同时担任目标生成器、验证器与执行器，消除规划-执行能力差距，确保模型不提出超出自身执行能力的目标。轨迹通过步前缀扩展（Step-prefix expansion）转化为SFT样本，保留完整历史上下文以匹配推理时的窗口布局。

$$
\mathcal{D}_{SFT} = \bigcup_{t=1}^{T} \{ (V_t(\tau), H_t(\tau), o_t) \}
$$

该公式表示将长度为$T$的轨迹$\tau$扩展为$T$个训练样本，其中$V_t$保留最近3张截图，$H_t$将更早步骤摘要为文本块，$o_t$为第$t$步的模型输出。

## 实验评估

实验在OSWorld基准（369个真实桌面任务）上进行，基线为UI-TARS-7B预训练模型及AgentNet训练结果。对比方法覆盖人工标注（AgentNet）与合成数据（ProCUA-SFT）两条路线，但缺失与RL方法（如UI-S1）或视频合成方法（如Video2GUI）的直接对比。

| 方法 | 训练数据 | OSWorld成功率 (%) | 相对基线变化 |
| :--- | :--- | :--- | :--- |
| UI-TARS-7B (Base) | - | 26.3 | - |
| UI-TARS-7B + AgentNet | 22.5K人工轨迹 | 8–10 | -16.3 to -18.3 |
| UI-TARS-7B + ProCUA-SFT | 3.1M合成样本 | 45.0 | +18.7 |

ProCUA-SFT在相同训练步数下恢复并超越基线性能，而AgentNet导致性能持续下降。消融实验显示，按应用组合轮询采样（30.9%）优于按动作集采样（24.9%）和非多样化基线（27.3%），表明应用组合覆盖是CUA SFT的主导多样性轴。

评估边界方面，本文仅报告OSWorld单一基准，未提供置信区间或计算效率指标（如推理延迟、Token消耗）。可复现性上，论文提供Hugging Face数据集链接，但VM后端（Singularity/NVCF）的异构计算配置细节未完全公开，可能影响跨平台复现。

## 关联研究分析

从问题动机看，ProCUA-SFT与AgentNet的核心差异在于数据生成范式：前者通过前置条件验证确保任务可行性，后者依赖人工标注的静态轨迹。这一差异根源在于桌面环境的动态性——人工标注难以覆盖所有可能的桌面状态，而合成方法可通过环境配置动态生成任务。AgentNet的负迁移现象揭示了人工数据在任务多样性与标注噪声上的固有局限，而ProCUA-SFT的45.0%成功率证明合成数据在SFT场景下可超越人工数据。

从方法设计看，ProCUA-SFT与Video2GUI同属合成数据路线，但前者聚焦桌面端复杂文档操作，后者挖掘视频中的用户行为。Video2GUI通过视频解析生成轨迹，需处理遮挡与模糊等视觉噪声，而ProCUA-SFT通过真实内容种子直接构建复杂桌面状态，避免了视频解析的时序一致性挑战。两者在数据多样性与分布一致性间的取舍不同：Video2GUI依赖外部视频分布，ProCUA-SFT依赖OSWorld配置与真实文档分布。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

CUA训练的核心矛盾在于高质量轨迹获取成本与模型泛化需求之间的失衡。本文抓住合成数据中“任务不可行”与“内容空洞”两个被忽略的子问题，通过前置条件验证闭环与真实内容种子，生成既困难又可行的3.1M步级样本。实验证明，ProCUA-SFT在OSWorld上将UI-TARS-7B的成功率从26.3%提升至45.0%，较AgentNet训练结果高出35个百分点以上。本文的边界在于仅验证SFT场景下的数据贡献，未探索RL或自进化训练路径，且绝对性能仍低于当前RL路线的SOTA。当支持集从3.1M样本扩展至更大规模时，合成数据的边际收益是否递减，论文未给出回答。
