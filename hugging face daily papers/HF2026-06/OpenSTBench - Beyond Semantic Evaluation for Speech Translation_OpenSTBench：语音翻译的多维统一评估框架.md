> 导读 语音翻译系统正从离线文本输出扩展至流式语音生成，但现有评估协议割裂了翻译质量、语音自然度与时间延迟，导致异构系统无法公平比较。本文提出 OpenSTBench，通过共享样本记录与统一接口，将 S2TT/S2ST、离线/流式系统纳入同一评估 Schema。实验证明，翻译质量最优的系统在语音保留或时间一致性上未必领先，单一指标排名失效。该框架填补了评估协议空白，但自动语音指标与人类判断的一致性校准仍存疑。

## 研究背景

语音翻译评估长期沿用机器翻译范式，依赖 BLEU 和 COMET 衡量文本准确性。然而，当系统输出从文本转向语音时，仅靠文本指标无法捕捉说话人特征丢失、情感扭曲或延迟累积等关键缺陷。这种评估盲区源于任务特性的根本变化：S2ST 系统的行为由翻译文本、声学实现和生成时序共同决定，三者相互独立又相互制约。

主流评估路线存在结构性割裂。SimulEval 等工具聚焦流式延迟与质量权衡，但仅支持文本输出；S2ST 研究虽引入 UTMOS 和说话人相似度，却缺乏统一的时间一致性度量。这种碎片化导致不同协议下的结果不可比，例如流式 S2ST 与离线 S2ST 在延迟指标上无法直接对照。OpenSTBench 的切入点在于构建一个能同时容纳异构输出模态与生成时序的统一评估协议，而非优化特定模型架构。

## 核心方法

### 方法参照系

语音翻译评估的通用流程是分别计算文本质量、语音质量和时间指标，但各维度使用独立数据集与接口。本文的关键差异在于：通过共享样本记录（Shared Sample Record）和统一评估器接口，强制所有系统在相同输入下产出可比的多维分数，而非各自为政的局部最优。

### 多维指标解耦与统一

传统评估将“语音质量”视为单一 MOS 分数，无法区分自然度、说话人保留与情感保真度的独立贡献。OpenSTBench 将语音质量解耦为 UTMOS（自然度）、CER/WER（文本实现保真度）、Resemblyzer/WavLM（说话人相似度）、Emotion2Vec（情感相似度）及 CLAP 事件 F1（副语言保真度）。这种解耦解决了单一指标掩盖具体属性丢失的问题。例如，某系统可能 UTMOS 高但说话人相似度低，传统 MOS 无法揭示这一矛盾。

$$
\text{SLC}_p = \frac{1}{N} \sum_{i=1}^{N} \mathbb{1}\left( \frac{T_{y_i}}{T_{x_i}} \in [1-p, 1+p] \right)
$$

其中 $T_y$ 和 $T_x$ 分别为目标与源语音的时长，$\mathbb{1}$ 为指示函数。该公式量化了生成语音时长与源语音时长的相对偏差，SLC 值越高表示时间结构保留越好。设计动机在于：流式翻译中，时长失控会导致用户感知延迟与内容截断，而传统延迟指标（如 ATD）无法区分“生成慢”与“生成时长错误”。

### 异构系统适配协议

流式 S2ST、流式 S2TT 与离线 S2ST 在输出形式上不对称，直接对比会导致指标缺失或误判。OpenSTBench 通过“适用性掩码”机制，仅对系统实际输出的模态计算对应指标。例如，Baidu Realtime ST 输出句末文本，故不计算说话人相似度，仅报告句末延迟；而 Qwen3-LiveTranslate 输出增量语音，则计算全部语音侧指标。这一设计避免了因输出形式差异导致的“虚假可比性”，确保每个维度上的排名仅基于系统实际提供的信息。

## 实验评估

实验在 MSLT（翻译/时间质量）、LibriTTS（说话人保留）、RAVDESS/MCAE-SPPS（情感）及 NonverbalTTS/SynParaSpeech（副语言）上进行，覆盖 EN↔ZH 双向。基线包括 Qwen3-LiveTranslate、Doubao AST 2.0、GPT Realtime Translate、Baidu Realtime ST（流式）及 SeamlessM4T-v2、UniSS（离线）。未纳入 MTP-S2UT、SimulU 等学术 SOTA，可能因 API 限制或协议不兼容，导致无法覆盖离散单元范式的最新进展。

| 系统 | EN→ZH BLEU | EN→ZH UTMOS | EN→ZH WavLM | EN→ZH ATD (ms) |
| :--- | :--- | :--- | :--- | :--- |
| Qwen3-LiveTranslate | **43.2726** | 3.6028 | 0.2255 | 5138.88 |
| Doubao AST 2.0 | 36.7764 | 2.8675 | **0.6849** | **4072.74** |
| GPT Realtime Translate | 21.4059 | 3.1749 | 0.2275 | 5956.45 |
| SeamlessM4T-v2 | 23.5334 | **3.7160** | 0.2669 | – |
| UniSS | 34.1008 | 3.2409 | 0.6291 | – |

Qwen3-LiveTranslate 在翻译质量上领先，但说话人相似度（0.2255）远低于 Doubao AST 2.0（0.6849）；Doubao AST 2.0 延迟最低（4072.74 ms），但翻译质量次之。这证实了跨维度排名差异：无单一系统在所有维度占优。

消融实验未提供独立数据，但设计决策验证显示：说话人保留采用同语言参考（LibriTTS 英文 vs 合成中文），因跨语言比较会混淆语言不匹配与说话人差异（WavLM 相似度从 0.7721 降至 0.4556）。副语言保真度普遍偏低（Event Content F1 < 0.15），表明当前模型在声学事件保留上存在共性短板，而非特定系统缺陷。

评估边界方面，实验仅覆盖 EN↔ZH，缺乏低资源语言验证；自动语音指标（如 UTMOS）与人类判断的一致性未校准；流式与离线系统在输出形式上不对称，限制了严格匹配比较。代码已开源，但 API 系统的 RTF 与参数量未报告，影响效率对比的完整性。

## 关联研究分析

从问题动机看，OpenSTBench 与 SimulEval 均关注流式翻译的延迟-质量权衡，但 SimulEval 仅支持文本输出，而 OpenSTBench 扩展至语音侧指标。这一差异源于任务特性：S2ST 系统的语音实现质量（如说话人保留）无法通过文本指标间接推断，必须直接评估声学输出。SimulEval 的局限在于其设计初衷是文本同步翻译，未考虑语音模态的独立评估需求。

从方法设计看，OpenSTBench 与 UniSS 等模型研究形成互补：UniSS 通过统一自回归模型提升表达力，而 OpenSTBench 提供评估其表达力保留程度的工具。两者差异在于：UniSS 关注模型内部机制（如跨模态思维链），OpenSTBench 关注外部行为观测（如 SLC 分数）。这种互补性揭示了领域现状：模型创新与评估创新不同步，导致新模型的表达力优势难以被量化验证。

## 总结

OpenSTBench 解决了语音翻译评估中异构系统不可比的核心矛盾，通过共享样本记录与统一接口，将翻译、语音、时间质量纳入同一协议。实验证明 Qwen3-LiveTranslate 翻译质量最高但说话人保留弱，Doubao AST 2.0 延迟最低但翻译次之，证实单一指标排名失效。其边界在于仅覆盖 EN↔ZH，且自动语音指标未与人类判断校准。当扩展到低资源语言时，CLAP 事件检测的准确率是否足以支撑副语言保真度评估，论文未给出回答。
