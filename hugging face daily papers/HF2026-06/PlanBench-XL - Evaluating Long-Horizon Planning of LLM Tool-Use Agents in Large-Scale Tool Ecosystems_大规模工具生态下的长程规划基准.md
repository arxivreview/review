> 大规模工具生态中，智能体受限于上下文窗口，仅能访问检索到的部分工具，且这些工具可能失效或误导，导致长程任务中的路径中断与重规划失败。现有基准多假设工具全量可见或行为可靠，无法诊断智能体在部分可观测且不可靠环境下的自适应能力。PlanBench-XL 通过构建包含 1,665 个工具的零售域交互式环境，引入检索时阻塞机制，强制智能体在路径失效时进行双向探索与重规划。该基准揭示了前沿模型在静默故障与长恢复路径下的脆弱性，但其评估局限于单一领域且未涵盖强化学习策略优化，对通用自适应规划能力的刻画仍有局限。

## 研究背景

当智能体在包含数千个 API 的生态系统中执行多步任务时，上下文窗口限制迫使其依赖工具检索来访问局部子集，这一过程称为检索中介工具使用。检索中介导致工具可见性部分化，智能体无法预知所有可用工具，必须通过迭代检索发现中间证据。然而，大规模工具库中的检索结果往往包含语义相似但功能错误的干扰项，或返回过时、损坏的数据，这种不可靠性使得基于静态计划的执行策略在长程任务中频繁失效。

现有工具使用基准如 ToolBench 和 APIBench 主要评估工具选择与调用准确率，但普遍假设工具集固定且描述清晰，忽略了检索过程中的不确定性。长程任务基准如 EscapeBench 关注隐式子目标，但缺乏对工具失效后重规划能力的测试。PlanBench-XL 的切入点在于将“部分工具可见性”与“工具不可靠性”结合，构建一个要求智能体在动态变化环境中持续适应的交互式测试床，从而诊断当前模型在真实世界工具生态中的规划鲁棒性。

## 核心方法

### 方法参照系

本文问题属于交互式工具使用基准构建，与 ToolBench 等静态基准的关键差异在于：后者提供全量可见且可靠的工具集，而 PlanBench-XL 要求智能体在部分可观测且工具可能失效的环境中，通过双向探索与动态重规划完成任务。

### 双向预期检索协议

传统工具检索通常基于当前输入状态进行前向搜索，PlanBench-XL 引入双向预期机制，允许智能体从目标结果反向推导所需中间信息。检索模式定义为：

$$
R_t = \{ \tau \in \mathcal{T} \mid \text{match}(\tau, q_t) \geq \theta \}
$$

其中 $q_t$ 为自然语言查询，$\theta$ 为匹配阈值。该设计解决了仅前向检索导致的“局部最优陷阱”，即智能体可能陷入与当前输入兼容但无法通向最终目标的工具循环，通过反向预期强制智能体规划中间子目标。

### 检索时阻塞机制

为模拟真实世界工具失效，PlanBench-XL 在检索阶段动态替换关键路径工具。阻塞类型包括显式失败（返回错误信息）、隐式失败（返回无效值）和语义误导（返回功能相似但错误的工具）。阻塞概率定义为：

$$
P(\tau' \mid \tau \in \mathcal{T}_{blk}) = 1
$$

其中 $\mathcal{T}_{blk}$ 为被阻塞工具集，$\tau'$ 为替换工具。该机制强制智能体检测路径中断并寻找替代方案，解决了静态基准无法评估智能体在工具不可靠环境下自适应重规划能力的缺陷。

## 实验评估

实验在 PlanBench-XL 的 327 个零售任务上评估 10 个前沿 LLM，包括 GPT-5.4、Gemini-3.1-Pro 等。基线覆盖专有与开源模型，但缺乏专用工具调用微调模型如 Tool-R0，可能低估策略优化方法在不可靠环境下的表现。

| 模型 | 准确率 (%) | EGT 精确率 (%) | 平均轮次 |
| :--- | :--- | :--- | :--- |
| Gemini-3.1-Pro | 77.06 | 91.47 | 19.55 |
| GPT-5.4 | 51.90 | 72.92 | 22.92 |
| DeepSeek-V4-Flash | 35.74 | 59.67 | 19.13 |
| Llama-3.3-70B-Instruct | 18.96 | 51.71 | 20.65 |

Gemini-3.1-Pro 以 77.06% 的准确率领先 GPT-5.4 25.16 个百分点，表明模型规模与架构对长程规划能力有显著影响。

消融实验显示，隐式失败比显式失败导致更严重的性能下降，GPT-5.4 在隐式失败下准确率降至约 30%，而在显式失败下保持约 40%。这表明静默故障比显式错误更难检测，智能体倾向于将无效值作为后续调用的输入，导致错误传播。

评估边界方面，基准局限于零售领域，未测试跨领域泛化能力；阻塞机制基于预定义规则，未模拟真实 API 的非确定性故障模式；未报告计算效率指标如 Token 消耗与延迟，限制了部署可行性评估。

## 关联研究分析

从问题动机看，PlanBench-XL 与 OpaqueToolsBench 均关注工具文档缺失或行为不可预测，但前者侧重长程规划中的路径中断与重规划，后者聚焦单步工具行为推断。PlanBench-XL 的阻塞机制要求智能体在多步轨迹中维持状态一致性并动态调整计划，而 OpaqueToolsBench 的任务更偏向于通过观察轨迹学习工具参数结构，两者对智能体能力的要求存在本质差异。

从方法设计看，PlanBench-XL 与 ToolBench 同属大规模工具基准，但 ToolBench 假设工具全量可见且可靠，评估重点在于工具选择准确率；PlanBench-XL 引入部分可见性与不可靠性，评估重点转向自适应规划能力。这一差异源于任务特性：ToolBench 的任务多为单步或短程调用，而 PlanBench-XL 的任务平均需 25 轮交互，要求智能体在长程中持续探索与利用，导致两者对模型能力的评估维度不同。

## 总结

PlanBench-XL 旨在解决大规模工具生态中智能体在部分可观测且工具不可靠环境下的长程规划失效问题。现有基准因假设工具全量可见或行为可靠，无法诊断智能体在路径中断时的自适应能力，而本文通过构建包含 1,665 个工具的交互式零售环境并引入检索时阻塞机制，强制智能体进行双向探索与重规划。实验表明，Gemini-3.1-Pro 在默认设置下取得 77.06% 的准确率，但 GPT-5.4 在最严重阻塞条件下降至 11.36%，揭示了当前模型在静默故障与长恢复路径下的脆弱性。该基准的边界在于局限于零售领域且未涵盖强化学习策略优化，当智能体具备从失败轨迹中学习的自我进化能力时，其在不可靠工具环境中的规划鲁棒性是否显著提升，论文未给出回答。
