> 导读 符号音乐生成长期面临音频输出难以直接解析为乐谱结构、且现有评估指标无法定位具体结构缺陷的困境。传统专用模型依赖重训练，而通用大语言模型（LLM）缺乏对音乐时序与和声的显式感知接口，导致代理系统无法进行有效的自我诊断与修正。本文提出 Libretto，通过构建显式槽位语法与基于语料库校准的29轴统计云，将音乐结构转化为可测量、可编辑的文本对象，使 LLM 代理能在生成-测量-修正循环中实现免训练的细粒度控制。该框架在长序列生成与局部编辑中展现了结构一致性优势，但其评估体系完全依赖内部统计分布，缺乏与人类主观审美或专用生成模型质量的横向可比性。

## 研究背景

当 LLM 代理尝试生成多声部乐曲时，若采用 ABC 记谱法，音符起始时间需通过累加前序时值推导，这种隐式时序导致局部编辑极易引发下游节奏错位。为解决这一问题，Libretto 引入了显式整数槽位语法，将节奏、音高与声部分离为可直接读取的文本单元。然而，仅解决表示问题不足以支撑代理的自我修正，因为传统评估依赖全局 MOS 或似然分数，无法指出“和声不稳定”或“纹理过密”等具体结构偏差。

符号音乐生成领域的主流路线分为专用模型训练与 LLM 适配两类。Music Transformer 等专用模型虽能捕捉长程依赖，但针对特定属性的控制需重训练，且黑盒特性阻碍了错误归因；ComposerX 等 LLM 代理系统虽实现了免训练交互，但缺乏结构化的反馈机制，代理只能基于模糊的文本提示进行盲目迭代。本文的切入点在于构建一个“表示-评估-反馈”闭环：通过语料库校准的统计轴将音乐结构量化为可解释的坐标，使 LLM 能够像音乐家一样诊断并修正结构缺陷，而非仅依赖概率采样。

## 核心方法

### 方法参照系

本文问题属于交互式编辑与协作路线，但区别于依赖专用验证器或规则引擎的传统流程，Libretto 将评估逻辑内嵌于 LLM 代理的推理循环中。其关键差异在于：不训练新的生成骨干，而是通过外部统计云提供结构化的“肌肉记忆”，使通用 LLM 具备音乐结构感知能力。

### 显式槽位语法与局部编辑

针对 ABC 记谱法中时值累加导致的编辑非局部性问题，Libretto 设计了基于整数槽位的文本语法。每个音符 Token 显式携带音高、起始槽位（onset slot）与持续槽位（duration slot），同时音高用加号连接。在 16 分音符 4/4 拍网格中，拍点位置固定为槽位 1, 5, 9, 13。这种设计使得修改单个音符的时值不会触发后续所有音符的重新推导，实现了编辑的局部性。其物理含义是：将时序信息从“相对累积”转化为“绝对定位”，消除了 LLM 在长序列生成中因误差累积导致的节奏漂移。

$$
\text{Onset}(n_i) = \text{Slot}_{\text{start}}(n_i), \quad \text{Duration}(n_i) = \text{Slot}_{\text{end}}(n_i) - \text{Slot}_{\text{start}}(n_i)
$$

该公式表明，音符的时序属性由独立的整数槽位直接定义，无需依赖前序音符的时值计算，从而保证了局部编辑的稳定性。

### 29轴统计云与结构诊断

为替代主观质量分数，Libretto 构建了基于 314 首真实 MIDI 语料库的 29 轴结构指纹。每个轴对应节奏、和声、旋律、纹理、曲式或内部变化中的一个可观测属性，其值被转换为相对于语料库的百分位（Percentile）。候选轴经过方差与冗余过滤，确保轴间独立性（平均相关系数 $|r| = 0.16$）。代理生成的候选乐谱被映射至该空间，若某轴值低于第 5 百分位或高于第 95 百分位，则被标记为“结构极端”。

$$
P(x) = \frac{1}{N} \sum_{i=1}^{N} \mathbb{I}(x_i < x_{\text{candidate}})
$$

其中 $N=314$，$x_i$ 为语料库中第 $i$ 首乐曲在特定轴上的原始值。该公式将绝对音乐属性转化为相对统计位置，使得“好”与“坏”不再由主观偏好定义，而是由“是否符合真实音乐的结构分布”决定。反馈机制不暴露原始指标，而是将极端轴转化为音乐家可读的描述（如“减少和声不稳定性”），引导 LLM 进行针对性修正。

## 实验评估

实验基于 Lakh MIDI 数据集的子集（314 首，8 种风格），使用 Claude Opus 4.8 作为代理。基线仅包含单轮生成与检索开关，未对比 SFS、AnchorSteer 等专用生成模型，导致无法评估 Libretto 在绝对生成质量上的竞争力。

| 任务 | 对比条件 | 基线结果 | Libretto 结果 |
| :--- | :--- | :--- | :--- |
| Gap Filling | 单轮 vs. 3轮循环 | 6/51 (12%) | 20/51 (39%) |
| Full-piece | 单轮 vs. 3轮循环 | 10/16 (62%) | 15/16 (94%) |
| Full-piece | 无检索 vs. 有检索 | 2/8 (25%) | 6/8 (75%) |
| Education | 无检索 vs. 有检索 | 7/8 | 6/8 |

数据表明，迭代循环对结构缺陷的修复效果显著，Gap Filling 通过率提升 27 个百分点；检索增强在全曲生成中使通过率翻倍，但在教育任务中因约束已显式化而失效（7/8 降至 6/8），揭示了检索机制对“模糊风格引导”有效，对“明确规则约束”无效的条件依赖性。

评估边界存在明显局限：指标完全基于内部统计通过率与 Copy Risk，缺乏人类 MOS 或 FMD 等外部质量指标。代码未公开，且 314 首语料库规模较小，统计云的泛化能力存疑。此外，论文未报告推理延迟，无法评估其在实时交互场景下的可行性。

## 关联研究分析

从问题动机看，Libretto 与 ProGress 均试图解决“结构合理性”问题，但路径截然不同。ProGress 依赖显式音乐理论规则（如 Schenkerian 分析）进行硬约束，在 Bach Chorales 上取得 3.30 LLM Score，但泛化性受限；Libretto 采用数据驱动的统计云，通过软约束引导 LLM，避免了规则形式化的困难，但牺牲了对特定理论规则的精确控制。这种差异源于任务特性：ProGress 面向严格规则约束的古典风格，而 Libretto 面向风格模糊的流行/爵士生成，后者更依赖分布统计而非逻辑推导。

从方法设计看，Libretto 与 AnchorSteer 同属推理时干预路线，但干预对象不同。AnchorSteer 通过激活引导在潜空间层面保持结构，精度更高但需训练特定探针；Libretto 通过文本反馈在语义层面引导修正，通用性强但依赖 LLM 的语言理解能力。Libretto 的 29 轴指纹本质上是一种“外部化的潜空间投影”，它将高维音乐结构压缩为低维可解释坐标，这种设计是否足以捕捉复杂和声的非线性关系，论文未给出深入讨论。

## 总结

Libretto 解决了 LLM 代理在符号音乐生成中缺乏结构化反馈接口的问题，通过显式槽位语法与 29 轴统计云，将音乐结构转化为可测量、可编辑的文本对象。实验证明，迭代循环与检索增强能显著提升生成通过率（Gap Filling 12%→39%，Full-piece 62%→94%），验证了免训练干预的可行性。然而，其评估体系封闭于内部统计分布，缺乏与人类审美或专用模型质量的横向对比，且 314 首语料库的规模限制了统计云的鲁棒性。当语料库规模扩大至万首级别时，29 轴指纹的维度是否需动态调整以捕捉更细粒度的风格差异，论文未给出回答。
