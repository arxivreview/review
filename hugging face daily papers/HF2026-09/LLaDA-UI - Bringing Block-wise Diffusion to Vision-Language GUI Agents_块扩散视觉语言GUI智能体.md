# HuggingFace最新推荐论文 ｜LLaDA-UI: Bringing Block-wise Diffusion to Vision-Language GUI Agents ｜块扩散视觉语言GUI智能体

研究机构：西湖大学

作者：Zhangxuan Gu、Haoxing Chen、Qi Qin 等 20 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.13287)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.13287)

> 现有GUI智能体依赖自回归（AR）范式，其逐token生成的串行特性导致推理延迟高，且严格的因果结构限制了双向上下文建模能力。本文提出LLaDA-UI，首个基于块级掩码扩散（Block-wise Masked Diffusion）的视觉语言GUI智能体，通过并行解码机制在保持结构化动作格式稳定性的同时，显著降低非缓存推理延迟。该工作验证了扩散模型作为GUI智能体生成范式的可行性，但其长程任务成功率仍受限于重复动作循环，且缺乏强化学习（RL）微调以解决错误累积问题。

## 研究背景

GUI智能体需通过像素级截图理解并操作数字设备，其核心挑战在于如何高效生成空间定位准确且格式稳定的可执行动作。自回归（AR）大语言模型（LLM）通过逐token预测实现这一目标，但其串行解码机制导致推理延迟随序列长度线性增长，且严格的因果注意力结构无法利用后续token信息来优化当前预测，这在需要全局语义理解的GUI定位任务中构成瓶颈。

主流GUI智能体如UI-TARS、Qwen-VL系列均采用AR架构，尽管在ScreenSpot-V2等基准上取得了90%以上的定位精度，但其推理延迟在长轨迹任务中成为部署瓶颈。同时，AR模型在长程任务中易出现错误累积，早期微小错误导致后续步骤偏离，而现有方法缺乏有效的自我反思与回溯机制。本文切入点在于利用扩散语言模型（dLLM）的块并行解码特性，通过同时预测多个token来降低延迟，并借助双向上下文建模提升结构化动作生成的稳定性。

## 核心方法

### 方法参照系

本文问题属于多模态GUI智能体的动作生成环节。标准流程为：视觉编码器提取截图特征，投影层映射至语言空间，语言模型基于任务指令与交互历史生成结构化动作。本文与标准流程的关键差异在于语言骨干由AR LLM替换为MoE扩散LLM，并引入块级掩码扩散损失以支持并行解码。

### 块级掩码扩散语言模型

AR模型逐token生成的串行特性导致推理延迟高，且无法利用双向上下文优化当前预测。本文采用块级掩码扩散（Block-wise Masked Diffusion）机制，将输出序列划分为大小为 $L_B$ 的块，每个块内的token并行去噪。训练损失定义为：

$$
\mathcal{L}_{BDLM}(\theta) = -\mathbb{E}_{t, x_0, x_t} \sum_{k=1}^{K} \sum_{i=1}^{L_B} \frac{-\alpha'_t}{1-\alpha_t} \mathbb{1}[x_{t,k}^i = \text{[MASK]}] \log p_\theta(x_{0,k}^i | x_{0,<k}, x_{t,k})
$$

该公式通过指示函数 $\mathbb{1}[\cdot]$ 确保仅对掩码token计算预测损失，时间权重 $\frac{-\alpha'_t}{1-\alpha_t}$ 平衡不同去噪步长的贡献。块并行解码使多个token同时生成，显著降低推理延迟，同时双向上下文建模提升了结构化动作格式的稳定性。

### MoE负载均衡与互补掩码

MoE架构中专家利用不均导致路由崩溃，影响训练稳定性。本文采用无辅助损失的负载均衡机制，通过RMSNorm归一化专家负载不平衡项来平滑偏置更新：

$$
b_i = b_i + u \times \frac{(F_i - Q_i)}{\sqrt{\sum_{j=1}^{n} (F_j - Q_j)^2}}
$$

其中 $F_i$ 为当前专家负载分布，$Q_i$ 为理想均匀分布。该机制促进专家差异化专业化，同时保持计算负载均匀分布。此外，互补掩码机制为每个干净目标构造两个逻辑互补的掩码视图，确保每个token在配对中被观察和预测一次，减少token级采样偏差，提升多模态预训练的信息利用率。

## 实验评估

实验在ScreenSpot-V2、AndroidWorld、OSWorld-Verified等六个基准上评估，基线覆盖Qwen2.5-VL-7B、Qwen3-VL-8B等AR模型及UI-TARS等专用GUI智能体，但缺失MobileRL、UI-S1等RL方法。LLaDA-UI在ScreenSpot-Pro（52.9%）、AndroidWorld（53.5%）、MobileWorld（25.6%）、WebVoyager（56.9%）上超越Qwen3-VL-8B，但在OSWorld-Verified（25.6%）上落后于Qwen3.5-9B（17.9%）和UI-Venus-1.0-7B（8.5%）。

| 基准 | LLaDA-UI | Qwen3-VL-8B | Qwen2.5-VL-7B |
| :--- | :--- | :--- | :--- |
| ScreenSpot-V2 | 90.7 | 93.0 | 86.0 |
| ScreenSpot-Pro | 52.9 | 52.7 | 26.8 |
| AndroidWorld | 53.5 | 47.9 | 25.5 |
| MobileWorld | 25.6 | 9.4 | 7.0 |
| OSWorld-Verified | 25.6 | 33.9 | 3.0 |
| WebVoyager | 56.9 | 45.2 | 11.0 |

消融实验显示，禁用EOS早停使AndroidWorld成功率从42.7%提升至52.6%，表明早停可能中断可解析动作的形成。块大小从32增至64且去噪步数从32减至16时，成功率从42.7%降至33.0%，揭示块粗化与去噪轮次减少导致交互可靠性显著下降。

评估协议未报告置信区间，多数原始论文未提供计算效率维度（如推理延迟、Token消耗）。代码与超参数已开源，训练使用32-64块H100 GPU，最大序列长度16K tokens，图像像素预算约12.8M。

## 关联研究分析

从问题动机看，本文聚焦推理效率与结构化动作稳定性，而MobileRL、UI-S1等RL方法聚焦长程任务错误恢复与分布外泛化。LLaDA-UI仅采用SFT，长程任务成功率在20+步时降至14.29%，印证了SFT难以解决错误累积的共识，但未提供RL证据。RL训练范式能否直接迁移至扩散模型，论文未给出回答。

从方法设计看，LLaDA-UI与UI-TARS-7B同为7B级GUI智能体，但语言骨干由AR替换为扩散。LLaDA-UI在AndroidWorld上略优（53.5% vs 30.0%），但在OSWorld上大幅落后（25.6% vs 未报告/低分）。扩散模型的双向上下文特性旨在缓解长序列状态偏离，但实验显示长轨迹仍易陷入重复，表明并行解码优势未完全转化为长程鲁棒性。

## 总结

本文要解决的核心矛盾是AR模型推理延迟高与双向上下文建模能力不足。本文抓住扩散模型块并行解码的特性，通过块级掩码扩散语言模型与MoE负载均衡机制，在保持结构化动作格式稳定性的同时降低推理延迟。LLaDA-UI在四个基准上超越Qwen3-VL-8B，非缓存推理延迟降低3.579-8.951倍。其边界在于长程任务成功率受限于重复动作循环，且缺乏RL微调以解决错误累积。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
