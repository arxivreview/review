# HuggingFace最新推荐论文 ｜TabFM: A Zero-Shot Foundation Model for Tabular Data ｜表格基础模型

作者：Weihao Kong、Erez Louidor Ilan、Shuxin Nie 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.37959)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.37959)

> 表格数据预测长期受限于小样本与异构特征，导致通用深度架构难以稳定超越梯度提升树（GBDT）。现有先验数据拟合网络（Prior-Data Fitted Networks, PFN）虽通过合成数据预训练实现零样本泛化，但受限于二次方注意力复杂度，上下文长度通常不足千行。TabFM 通过解耦行-列注意力与线性复杂度诱导机制，将上下文扩展至 16,384 行，在 TabArena 基准上确立零样本基础模型的新 SOTA。其价值在于突破了规模瓶颈，但预训练仅覆盖合成数据，对真实世界复杂语义的泛化边界尚存疑。

## 研究背景

表格数据缺乏空间局部性或序列结构，特征类型异构且样本量有限，这使得传统深度学习模型难以直接应用。为从有限样本中推断后验分布，先验数据拟合网络（PFN）范式提出在大规模合成数据上预训练 Transformer，使模型具备上下文学习（In-Context Learning, ICL）能力，无需针对特定数据集微调即可进行预测。然而，PFN 的核心瓶颈在于计算复杂度：朴素注意力机制在 $T$ 行 $H$ 列的表格上复杂度为 $O(T^2H^2)$，历史上将表格 Transformer 限制在少于 1,000 行的规模，无法处理工业级中等规模数据。

主流路线如 TabPFN 和 TabICL 虽确立了 PFN 在中小规模数据上的 SOTA 地位，但未能根本解决长序列计算瓶颈。TabICLv2 引入稀疏注意力，但仍依赖特定的合成数据分布假设，且对预训练资源要求较高。TabFM 的切入点在于架构层面的解耦：将特征编码与跨实例推理分离，通过线性复杂度的列向注意力与固定宽度的行向池化，在不牺牲零样本泛化能力的前提下，将上下文长度提升一个数量级，从而在更大规模数据上验证 PFN 范式的鲁棒性。

## 核心方法

### 方法参照系

TabFM 遵循 PFN 范式，将监督表格预测重构为上下文学习问题。与标准 PFN 流程的关键差异在于，TabFM 不直接对全单元格进行全注意力计算，而是引入交替的行-列注意力机制与诱导点压缩，以解决 $O(T^2H^2)$ 复杂度导致的规模限制。

### 频谱单元格嵌入与特征分组

设计动机在于解决异构特征（数值与类别）在统一嵌入空间中的表示冲突。TabFM 采用二进特征分组，将每列 $j$ 与偏移量为 0, 1, 3 的邻居列分组，每组大小 $G=3$。每个槽位 $g$ 通过特定的傅里叶频率银行 $\boldsymbol{\omega}_g \in \mathbb{R}^{32}$ 投影标量值 $v$：

$$
\gamma_g(v) = \left[ \cos(2\pi \omega_{g,1} v), \sin(2\pi \omega_{g,1} v), \dots, \cos(2\pi \omega_{g,32} v), \sin(2\pi \omega_{g,32} v) \right]^\top \in \mathbb{R}^{64}
$$

该公式将连续数值映射至度量尺度，同时将类别映射至独立嵌入，避免类别无序性带来的干扰。数值与类别列通过独立的频率银行与投影矩阵路由，最终求和得到单元格嵌入 $X^{(0)}_{i,j} \in \mathbb{R}^E$（$E=128$）。这种频谱嵌入确保了连续值的精细分辨率与类别值的离散区分度在注意力前已得到初步对齐。

### 交替行-列注意力与诱导点压缩

设计动机在于解耦特征编码与跨实例推理，避免全单元格注意力的二次方复杂度。TabFM 交替执行列向诱导自注意力块（Induced Self-Attention Blocks, ISAB）与行向自注意力块（Self-Attention Blocks, SAB）。列向注意力将 $T$ 行视为序列，通过 $m=256$ 个学习诱导点 $I \in \mathbb{R}^{m \times E}$ 压缩信息：

$$
\text{ISAB}_m(X; M) = \text{MAB}\left( X, \text{MAB}(I, X; M_{ctx}); 0 \right)
$$

其中 $M_{ctx}$ 为上下文掩码，仅允许标注行作为键。内层块将 $T$ 个实例压缩至 $m$ 个诱导向量，外层块读取回，将复杂度从 $O(T^2E)$ 降至 $O(TmE)$。行向注意力则通过旋转位置嵌入（Rotary Position Embeddings, RoPE）在特征轴上建模交叉结构，保持行的置换等变性。两个未绑定阶段各包含 3 个 ISAB 和 3 个 SAB，随后通过 8 个学习 CLS 令牌池化为固定宽度 1024 的行表示 $R \in \mathbb{R}^{T \times 1024}$。这种设计使得上下文长度可扩展至 16,384 行，且测试行预测条件独立，防止标签泄漏。

## 实验评估

TabFM 在 TabArena 基准（51 个数据集，38 分类，13 回归）上进行评估，对比方法包括调优 GBDT（LightGBM）、AutoML 系统（AutoGluon 1.5 extreme）及同类基础模型（TabPFN-3, TabICLv2, EXAONE-Tabular）。基线覆盖全面，但缺失部分最新开源轻量模型如 Orion-MSP。

| 方法 | 分类 Elo | 回归 Elo | 几何平均误差 (分类) | 几何平均误差 (回归) |
| :--- | :--- | :--- | :--- | :--- |
| TabFM (Zero-shot) | 1768.6 | 2055.2 | 0.0957 | 16.40 |
| EXAONE-Tabular | 1768.0 | 1973.1 | - | - |
| TabPFN-3 | 1641.9 | 1866.6 | - | - |
| TabICLv2 | 1586.4 | 1723.6 | - | - |
| AutoGluon 1.5 (extreme) | 1669.7 | 1851.2 | - | - |

TabFM 在零样本设置下，分类 Elo 1768.6 与 EXAONE-Tabular 的 1768.0 几乎持平，但回归 Elo 2055.2 显著领先，且几何平均误差最低。这表明频谱嵌入在连续目标预测上更具优势。TabFM+ 与 TabFM-Auto 在不更新权重的前提下，通过多视图集成与 LLM 引导特征工程，进一步提升了性能，其中 TabFM-Auto 在回归任务上达到 0.00% 的 oracle improvability。

消融实验未单独列出，但设计决策验证显示，将上下文从 2,048 扩展至 16,384 行的四阶段课程学习，通过保持每步计算量恒定（222 tokens ≈ 4.19M），稳定了优化过程。ISAB 诱导点机制在保持线性复杂度的同时，未显著牺牲全局依赖信息的捕捉，因为 24 层预测器在池化后的行表示上执行深度混合，补偿了列向压缩可能带来的信息损失。

评估边界方面，TabArena 强调开箱即用性能，但与企业级数据存在脱节。论文未报告置信区间，且预训练仅覆盖合成数据，对真实世界复杂语义（如文本字段）的泛化能力未充分验证。代码与权重已开源，但超参数搜索细节有限，可复现性依赖于 Hugging Face 提供的预训练检查点。

## 关联研究分析

从方法设计看，TabFM 与 TabICLv2 均致力于解决长序列计算瓶颈，但 TabICLv2 依赖稀疏注意力与 Muon 优化器，而 TabFM 采用 ISAB 诱导点与 RoPE 行注意力。TabFM 的解耦架构将特征编码与跨实例推理分离，使得行向注意力仅处理固定宽度的特征轴，避免了 TabICLv2 中可能存在的长序列预训练不稳定性。这一差异源于任务特性：TabFM 更强调零样本泛化的鲁棒性，而 TabICLv2 侧重真实数据分布的适应性。

从问题动机看，TabFM 与 Orion-MSP 同属高效架构路线，但 Orion-MSP 针对多尺度稀疏注意力，而 TabFM 通过诱导点实现线性复杂度。TabFM 的预训练完全依赖结构因果模型（SCM）生成的合成数据，这与 Orion-MSP 可能采用的混合数据策略不同。TabFM 的局限在于合成数据缺乏真实世界的复杂语义，导致其在包含文本或高维稀疏特征的数据集上可能表现不佳。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但 TabFM-Auto 的 LLM 引导特征工程暗示了通过外部知识弥补合成数据语义缺失的可能性。

## 总结

TabFM 旨在解决表格基础模型在中等规模数据上的计算瓶颈与零样本泛化矛盾。其切入点在于通过解耦行-列注意力与线性复杂度诱导机制，突破 PFN 范式的规模限制。方法上，TabFM 采用频谱单元格嵌入与交替 ISAB/SAB 架构，将上下文扩展至 16,384 行。实验证明，TabFM 在 TabArena 回归任务上以 2055.2 Elo 领先，分类任务上以 1768.6 Elo 与 EXAONE-Tabular 持平，且几何平均误差最低。其边界在于预训练仅覆盖合成数据，对真实世界复杂语义的泛化能力未充分验证，且评估基准与企业级数据存在脱节。当支持集增大到百万行级时，ISAB 诱导点机制是否仍能保持线性复杂度优势而不丢失全局依赖信息，论文未给出回答。
