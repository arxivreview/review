# HuggingFace最新推荐论文 ｜Reasoning with Image Generation ｜基于图像生成的多模态推理框架

作者：Nishad Singhi、Hector Garcia Rodriguez、Aditya Arora 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.16409)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.16409)

> 视觉语言模型在空间与物理直觉任务上受限于文本带宽瓶颈，现有固定工具框架无法执行开放域视觉变换。REIMAGIN 将指令跟随图像生成模型作为通用推理工具，通过自然语言提示实现像素级中间状态生成。该框架无需任务特定训练，在六类视觉推理任务上显著优于纯文本与固定工具基线，但生成图像的忠实度与错误传播机制仍缺乏系统性验证。

## 研究背景

当多模态大语言模型（MLLMs）处理遮挡计数或新视角合成任务时，其内部文本推理链无法承载高维空间结构，导致视觉证据在离散化过程中丢失。这一现象源于视觉编码器到语言模型的投影层对高频空间细节的压缩，即文本带宽瓶颈。为弥补内部感知不足，早期研究引入裁剪、深度估计等固定视觉工具，但这类工具仅能执行预定义的窄域操作，无法生成替代视角或复杂场景变换，且依赖人工设计的上下文示例，限制了向新任务的泛化能力。

视觉推理领域长期存在“内部潜在推理”与“外部工具增强”两条路线。潜在推理方法（如 LVR, Monet）在连续空间生成视觉思维，但可解释性低且需特定训练；外部工具方法（如 Visual Sketchpad）依赖固定专家模块，灵活性受限。REIMAGIN 的切入点在于利用近期指令跟随图像生成模型的开放域能力，将视觉推理从“程序化算子调用”转向“生成式视觉思维”，使单一工具能执行从深度图生成到俯视图合成的任意变换，且能力随生成模型进步自动扩展。

## 核心方法

### 方法参照系

本文问题属于“视觉工具交互”路线，标准流程为 MLLM 交替执行文本推理与固定视觉算子（如分割、检测）。关键差异在于：本文用单一指令跟随生成模型替代固定工具箱，工具接口从“函数调用”变为“自然语言提示”，实现开放域视觉变换。

### 生成式视觉推理循环

在 ReAct 框架基础上，REIMAGIN 引入 `generate_image` 工具，接受自然语言提示与参考图像，返回合成图像至上下文。设计动机是解决固定工具无法执行“想象替代视角”等生成性操作的失效。每轮推理中，MLLM 生成思维链 $\theta_t$ 与可执行动作 $\alpha_t$，其中 $\alpha_t$ 可调用 `generate_image(prompt, image_i)` 或程序化工具。生成图像作为视觉中间状态 $o_t$ 追加至上下文 $C_t$，形成闭环：

$$
C_t = (Q, V, h_1, \dots, h_{t-1}), \quad h_i = (\theta_i, \alpha_i, o_i)
$$

该公式表明上下文由查询、输入图像及历史轮次（思维、动作、输出）构成，生成图像直接参与后续推理，而非仅作为最终答案依据。

### 测试时缩放与自动策略发现

针对生成图像的随机性，REIMAGIN 采用测试时缩放：独立采样 $N$ 个候选图像，由 MLLM 选择最忠实于提示的结果。设计动机是解决复杂变换（如俯视图合成）中生成方差大导致的推理错误。自动策略发现则通过迭代优化提示 $p^*$，在开发集上评估候选提示 $p \in P_r$ 的任务指标 $J(p)$，并由提议模型基于成功/失败轨迹生成新提示。该机制无需人工设计任务特定策略，使 MLLM 自主发现有效视觉变换（如碰撞预测中绘制轨迹线），恢复大部分手工策略的性能增益。

## 实验评估

实验覆盖六类任务：深度推理（BLINK）、拼图完成（MIRA）、遮挡计数（CAPTURE）、碰撞预测（Spatial457）、空间推理（MMSI）及路径追踪（自引入）。基线包括无工具（No Tools）与固定工具框架 Visual Sketchpad，缺失潜在推理方法（如 LVR, Monet）及强化学习优化方法（如 GRPO）的直接对比。

| 任务 | 模型 | No Tools | Visual Sketchpad | REIMAGIN |
|---|---|---|---|---|
| Spatial (MMSI) | Gemini-3.1-Pro | 37.2±2.6 | 38.5±8.9 | 42.3±2.2 |
| Occ. Count (CAPTURE) | Gemini-3.1-Pro | 8.9±0.4 | 9.7±0.2 | 7.1±0.6 |
| Collision (Spatial457) | Gemini-3.1-Pro | 60.3±0.9 | 65.0±0.8 | 69.7±1.2 |
| Depth (BLINK) | Gemini-3.1-Pro | 91.7±0.3 | 99.2±0.0 | 94.6±1.5 |
| Spatial (MMSI) | Qwen-3.5-27B | 34.6±2.2 | 25.6±2.6 | 46.2±2.2 |
| Occ. Count (CAPTURE) | Qwen-3.5-27B | 12.2±0.3 | 8.7±0.0 | 6.8±0.6 |

REIMAGIN 在空间推理与碰撞预测上显著优于基线，但在遮挡计数上低于 Visual Sketchpad（Gemini 设置下 7.1 vs 9.7），表明生成工具在精确计数任务上可能引入噪声。自动策略发现实验显示，自动发现的提示在多数任务上接近手工策略性能（如碰撞预测 87.3 vs 89.0），验证了 MLLM 对有效视觉变换的先验知识。

评估边界方面，论文未报告生成图像忠实度的量化指标，仅通过最终答案准确率间接评估。代码未公开，超参数（如采样数 $N$）未详细说明，可复现性受限。与领域共识相比，本文支持“外部工具优于内部潜在推理”的观点，但缺乏与 LVR 等潜在方法的直接对比，无法判断生成式工具在细粒度感知任务上的相对优势。

## 关联研究分析

从问题动机看，REIMAGIN 与 LVR（Li et al., 2025）均针对文本带宽瓶颈，但 LVR 在潜在空间生成视觉思维，REIMAGIN 在像素空间生成可解释图像。LVR 需任务特定训练且可解释性低，REIMAGIN 无需训练但依赖生成模型能力。这一差异源于任务特性：LVR 适合细粒度几何推理，REIMAGIN 适合空间组合与生成性变换。生成图像的幻觉是否比潜在状态引入更多噪声，论文未给出回答。

从方法设计看，REIMAGIN 与 DeepEyes（2025）同属工具增强路线，但 DeepEyes 依赖强化学习训练模型调用裁剪工具，REIMAGIN 依赖提示优化实现自动策略发现。DeepEyes 需大量训练数据与计算资源，REIMAGIN 无需训练但受限于生成模型的指令跟随能力。提示优化在数据充足时是否仍有增益，论文未给出回答。

## 总结

REIMAGIN 解决的核心矛盾是固定视觉工具无法执行开放域视觉变换，其切入点在于利用指令跟随图像生成模型的灵活性，将视觉推理从程序化算子调用转向生成式视觉思维。该方法通过自然语言提示实现像素级中间状态生成，在空间推理与碰撞预测上较基线提升 25% 与 40%。边界在于生成图像的忠实度缺乏量化评估，且在精确计数任务上性能低于固定工具。当生成模型能力进一步提升时，REIMAGIN 的性能增益是否持续扩大，论文未给出回答。
