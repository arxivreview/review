> 大语言模型（LLM）强化学习（RL）后训练涉及多模型、多阶段的分布式计算，其执行计划常因序列长度增长或资源波动而失效。现有系统要么固定并行策略，要么仅支持单模型弹性，无法处理多模型耦合下的全局状态迁移。Nereus 通过引入弹性模型单元（Elastic Model Unit, EMU）抽象与成本感知自适应策略，实现了跨模型阶段的安全并发状态转换。该系统在 1,024 GPU 规模下将 PPO 吞吐提升 2.14–7.27 倍，但其收益高度依赖在线成本模型的校准精度，且未验证对算法收敛动力学的影响。

## 研究背景

RL 后训练的核心计算单元是执行计划（Execution Plan），它定义了 Actor、Critic、Reward 及 Reference 模型在生成、推理、训练三个阶段的数据并行（DP）、张量并行（TP）与流水线并行（PP）配置。由于 Actor 在训练过程中生成序列长度呈指数增长（实测 1,000 步内增长 16 倍），初始计划往往因显存溢出或通信瓶颈而失效。这种工作负载漂移（Drift）要求系统动态调整并行策略，但多模型共享 GPU 资源使得局部调整可能引发全局死锁或状态不一致。

主流 RL 后训练框架如 Verl 和 OpenRLHF 支持丰富的并行配置，但启动后固定不变；弹性训练系统如 Tenplex 和 Oobleck 虽能调整运行中计划，但仅管理单一模型，无法协调 Actor 与 Critic 间的资源竞争。DynaRL 尝试在固定资源池内调度多组件，但其基于组件的迁移策略在 GPU 紧张时成功率仅 34–62%。Nereus 的切入点在于将状态边界与模型依赖结构对齐，通过全局转换图（Transition DAG）协调跨模型阶段的 GPU 释放与获取，解决“何时适应、复用何种状态、如何转换”三个核心问题。

## 核心方法

### 方法参照系

本文问题属于分布式系统资源调度范畴，但区别于传统弹性训练，其难点在于多模型耦合下的状态一致性。标准流程是静态分配 GPU 并固定 TP/PP/DP 配置，本文差异在于引入运行时重规划机制，将执行计划视为动态优化变量，而非一次性配置。

### 成本感知自适应策略

控制器通过监控序列长度、可用 GPU 数及峰值显存，触发重规划。设计动机是避免盲目切换带来的性能抖动，仅当预期收益覆盖转换成本时才执行迁移。目标计划 $S^*$ 通过最小化预测步延迟 $\hat{L}_{step}(S)$ 并满足显存约束 $\text{Mem}_{peak}(S) \le \text{Mem}_{cap}$ 确定。准入规则采用回本期（Payback Period）机制：

$$
\frac{\hat{L}_{tran}}{\Delta L} > 0 \land \Delta L \le \gamma H_x
$$

其中 $\Delta L = \hat{L}_{step}(S) - \hat{L}_{step}(S^*)$ 为每步延迟节省，$\hat{L}_{tran}$ 为转换成本，$\gamma$ 为置信边际（默认 0.5），$H_x$ 为触发信号下次阈值穿越的预估步数。该公式确保仅在节省时间足以覆盖转换开销且留有不确定性缓冲时，才允许从当前计划 $S$ 切换至 $S^*$。

### 依赖对齐的弹性模型单元

EMU 将 TP 和 PP 封装在单元内部，DP 作为副本计数暴露于外部。设计动机是 TP/PP 涉及紧密同步的集合通信，而 DP 副本间仅周期性同步，这种解耦允许在保持内部同步完整性的同时，灵活增删副本。状态转换由四个原语组成：Split（位置级 AllGather）、Merge（目标布局组装）、Extend（秩对齐广播）和 Destroy（本地拆除）。全局转换 DAG 通过添加资源依赖边，确保当无空闲 GPU 时，先执行释放资源的 Destroy 操作，再执行获取资源的 Extend 操作，从而避免死锁。

## 实验评估

实验在三个 GPU 集群（AMD MI250X、NVIDIA A100、H200）上进行，基线包括 OpenRLHF、Verl、Laminar 及弹性系统 Tenplex、Oobleck、MCP、UCP。Nereus 在 8B PPO 任务上，相比 OpenRLHF 吞吐提升 2.14–7.27 倍（中位数 3.99 倍），相比 Verl 提升 1.10–1.47 倍。在 1,024 GPU 规模下，Nereus 步延迟较 OpenRLHF 降低 3.20 倍。

| :--- | :--- | :--- | :--- | :--- |
| UCP | 695.94 | 798.94 | 836.74 | 981.21 |
| Tenplex | 39.72 | 51.68 | 66.43 | 89.92 |
| Oobleck | 10.54 | 21.48 | 39.06 | 83.72 |
| Nereus | 2.45 | 5.58 | 6.52 | 8.48 |

Nereus 的扩展速度比 Oobleck 快 3.8–9.9 倍，比 Tenplex 快 9.3–16.2 倍。在动态漂移测试中，Nereus 平均步延迟 858.7 s，优于 DynaRL 风格的 928.3 s。成本模型预测误差均值为 4.96%，最大误差 14.61%，$R^2=0.9993$。

评估边界方面，论文未报告代码开源地址，且实验仅覆盖 PPO 算法，未验证 GRPO 等新型 RL 算法下的表现。成本模型依赖在线校准，若硬件效率波动剧烈（如网络拥塞），预测误差可能增大。此外，论文未量化系统加速对 RL 收敛步数或最终模型性能的影响，仅关注训练吞吐。

## 关联研究分析

从问题动机看，Nereus 与 DynaRL 均关注 RL 后训练的资源调度，但 DynaRL 局限于固定资源池内的组件迁移，而 Nereus 处理动态资源池下的全局状态转换。这一差异源于任务特性：DynaRL 假设资源总量恒定，而实际集群中 Spot 实例回收导致资源波动，Nereus 的 Destroy/Extend 原语专门为此设计。从方法设计看，Nereus 与 Tenplex 同属弹性训练系统，但 Tenplex 以 Shard 为状态单元，需协调复杂的路由与同步，而 Nereus 以 EMU 为单元，将 TP/PP 封装内部，简化了规划器复杂度。这种设计选择牺牲了细粒度状态复用，但换取了转换效率，其根源在于 RL 后训练中 DP 副本的独立性远高于 TP/PP 分片。

## 总结

Nereus 解决了 RL 后训练中多模型耦合下的动态并行策略调整难题，通过 EMU 抽象与成本感知准入机制，实现了高效的状态迁移。其核心贡献在于将系统调度与模型依赖结构对齐，使转换成本降低 99.1%（相比 MCP）。然而，论文实验仅验证了训练吞吐提升，未探讨系统加速是否改变了 RL 算法的收敛动力学，例如更短的步延迟是否导致策略更新频率变化，进而影响最终模型性能。当序列长度增长超过 8K tokens 时，EMU 的显存预测精度是否仍能维持 5% 以内，论文未给出回答。
