# HuggingFace最新推荐论文 ｜Don't Drop Dropout: Optimizing Layer Sparsity for Efficient LLM Training and Inference ｜层丢弃优化：LLM 训练与推理弹性

论文原文见 [arXiv](https://arxiv.org/abs/2609.05275)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.05275)

> 大规模 LLM 预训练面临算力成本与推理延迟的双重压力，传统激活丢弃因稀疏内核开销无法转化为实际加速，且现有证据碎片化导致层丢弃（Layer Dropout）在 SOTA 模型中被弃用。本文切入点在于将层丢弃从正则化手段重构为结构化稀疏机制，通过联合优化深度分布、时间调度与优化器超参数，实现训练 FLOPs 节省与零样本推理弹性的统一。具体做法是引入递增层丢弃分布（ILD）与递减时间调度（DTS），并采用 $1/\rho$ 缩放因子确保超参数迁移稳定性。该研究证明了在特定配置下，层丢弃不仅不损精度，反而能解锁高达 1.5 倍的推理加速，但其对长上下文精确检索能力的潜在影响尚未在标准基准上得到验证。

## 研究背景

当 Transformer 模型扩展至数十亿参数时，自注意力机制的二次方复杂度与键值缓存（KV Cache）内存占用成为部署瓶颈。为降低计算成本，研究者曾尝试激活丢弃（Activation Dropout）或非结构化权重稀疏，但这些细粒度稀疏化因 GPU 稀疏内核执行效率低下，往往导致实际墙钟时间（Wall-clock Time）不降反升。相比之下，整层跳过（Skipping Entire Transformer Blocks）产生的是结构化稀疏，其计算节省与丢弃率呈线性关系，且无需修改硬件内核。然而，层丢弃在大规模单轮（Single-epoch）预训练中的有效性长期存疑，早期工作如 LayerDrop（Fan et al., 2020）仅在 BERT 时代的小规模多轮训练中得到验证，而近期针对解码器 LLM 的研究（Elhoushi et al., 2024）报告了显著的精度下降，导致该技术在现代 LLM 预训练配方中几乎消失。

现有矛盾在于，层丢弃理论上能赋予模型“弹性深度”（Elastic Depth），使其在推理时通过跳过部分层来适应不同延迟预算，但缺乏在固定架构与数据条件下，系统性地解耦优化器超参数、深度分布与时间调度影响的受控实验。许多报告的精度损失可能源于次优的超参数配置或调度策略，而非层丢弃本身的固有缺陷。本文旨在通过大规模实验，厘清层丢弃在现代 LLM 预训练中的真实作用，并建立一套可迁移的最佳实践，以解决训练效率与推理灵活性之间的权衡问题。

## 核心方法

### 方法参照系

本文问题属于“训练感知深度弹性”（Training-aware Depth Elasticity）范畴，与量化感知训练（QAT）类似，旨在通过训练时的干预使模型对推理时的结构变化保持鲁棒。与引入路由器（Router）或辅助损失（Auxiliary Loss）的弹性架构不同，本文仅修改训练过程中的残差流掩码，不改变模型拓扑或增加额外参数，从而保持预训练流程的简洁性。

### 超参数迁移与缩放因子

此前层丢弃研究常因缩放因子（Scaling Factor）选择不当导致超参数无法跨丢弃率迁移，需针对每个丢弃率重新调参，成本高昂。本文引入层密度 $\rho = 1 - p$，并采用 $r_{train} = 1/\rho$ 作为训练时的缩放因子，而非传统的 $r_{train} = 1$。

$$ H_{\ell+1,t} = H_{\ell,t} + r_{train} M_{\ell,t} f_\ell(H_{\ell,t}) $$

该公式表明，当层被丢弃（$M_{\ell,t}=0$）时，残差流直接传递；当层被保留时，其输出被放大 $1/\rho$ 倍以补偿期望值。这一设计满足了“最大残差流更新”（Maximal Residual Stream Update）准则，使得不同丢弃率下的模型具有相似的激活尺度，从而允许学习率、批量大小等超参数在多个丢弃率间直接迁移，无需重新搜索。

### 深度分布与时间调度

为最大化训练效率与推理弹性，本文提出两种关键配置：递增层丢弃分布（Increasing Layer Dropout, ILD）与递减时间调度（Decreasing Time Schedule, DTS）。ILD 假设深层对精度贡献更大，因此浅层丢弃率高于深层，其平均丢弃率 $\bar{p}_{ILD}$ 为：

$$ \bar{p}_{ILD} = \frac{1}{L} \sum_{\ell=0}^{L-1} \frac{\ell}{L-1} p_{max} = 0.5 p_{max} $$

这意味着在 ILD 下，有效深度随训练进程动态变化。DTS 则规定丢弃率随训练步数 $t$ 递减，早期训练高丢弃率以加速收敛并建立鲁棒性，后期训练低丢弃率以恢复精度。这种组合使得模型在训练初期即暴露于低深度环境，从而在推理时跳过层或提前退出（Early Exit）时，损失曲线保持平稳，而非出现剧烈波动。

## 实验评估

实验基于 Celerity 架构，在 Cerebras CS-3 系统上运行超过 2400 次训练，模型规模从 271M 到 8.2B 参数，数据量最高达 160B tokens。基线包括无丢弃的 Dense Baseline 及子层丢弃（Sub-Layer Dropout）。主要评估指标为验证损失（Val Loss）、训练 FLOPs 节省比例及推理加速比。

| 模型规模 | 丢弃配置 | 训练 FLOPs 节省 | 推理加速比 (Self-Speculative) | 验证损失变化 |
| :--- | :--- | :--- | :--- | :--- |
| 3.9B | 0.4 (ILD, DTS) | 25% | 1.54× | 持平或优于 Dense |
| 3.9B | 0.2 (ILD) | 10% | 1.20× | 持平 |
| 271M | 0.1 (Layer) | ~5% | - | 3.18% 增加 |

在 3.9B 模型上，采用 ILD+DTS 配置（$p_{max}=0.4$）实现了 25% 的训练 FLOPs 节省，同时验证损失与 Dense 基线持平甚至更优。在推理阶段，该配置使自推测解码（Self-Speculative Decoding）加速比达到 1.54 倍，而 Dense 基线在此任务上仅获得 1.02 倍的微弱提升，甚至出现性能回退。这表明层丢弃诱导的弹性是高效推测解码的前提。

消融实验显示，整层丢弃（Layer Dropout）优于子层丢弃（Sub-Layer Dropout），后者在 271M 模型上导致 3.61% 的验证损失增加，而前者仅为 3.18%。此外，按序列（Per-sequence）采样掩码优于按批次（Per-batch）采样，前者能提供更细粒度的稀疏化，从而获得更低的损失。在中间层跳过（Intermediate Layer Skipping）测试中，ALD（交替层丢弃）在 20% FLOPs 节省下保持了比 ILD 更低的验证损失，表明 ALD 更适合非连续层跳过场景，而 ILD 更适合连续提前退出。

评估边界方面，本文主要关注语言建模困惑度（PPL/Val Loss）与推理速度，未覆盖 RULER 或 LongMemEval 等长上下文精确检索基准。代码未公开，但提供了详细的超参数迁移规则。由于实验基于 Celerity 架构，结果在其他架构（如 MoE 或 SSM 混合架构）上的泛化性未经验证。

## 关联研究分析

从方法设计看，本文与 Flextron（Cai et al., 2024）和 LlamaFlex（Cai et al., 2025）等弹性架构方法形成鲜明对比。后者通常需要在预训练后引入额外的适配器（Adapter）或进行持续预训练（Continual Pretraining）以学习层跳过策略，而本文证明仅通过修改预训练掩码即可实现零样本（Zero-shot）弹性。这种“免费”弹性的根源在于层丢弃在训练过程中强制模型学习在部分层缺失的情况下仍能维持特征流的完整性，从而内化了深度鲁棒性。然而，这种粗粒度的层跳过可能牺牲了细粒度路由的精度上限，因为路由器可以根据每个 token 的难度动态选择计算深度，而层丢弃仅基于全局丢弃率。

从问题动机看，本文挑战了“大规模预训练中丢弃无用”的共识。与激活丢弃不同，层丢弃的价值不在于正则化（防止过拟合），而在于结构化稀疏带来的计算节省与推理弹性。这与知识库中“动态计算分配”共识一致，但本文提供了更具体的实现路径：无需路由器，仅通过训练时的随机层跳过即可实现。相比之下，GateSkip（arxiv_2510.13876）等方法依赖门控机制进行层跳过，需要额外的计算开销来评估门控值，而本文的层丢弃在训练时即完成“门控”学习，推理时无需额外计算。

## 总结

本文旨在解决大规模 LLM 预训练中训练效率与推理灵活性难以兼得的矛盾。现有方法要么牺牲精度换取速度，要么引入复杂模块实现弹性，而本文通过联合优化层丢弃的深度分布、时间调度与超参数迁移，证明了结构化稀疏可以在不增加架构复杂度的前提下，同时提升训练与推理效率。实验表明，在 3.9B 模型上，ILD+DTS 配置实现了 25% 的训练 FLOPs 节省和 1.54 倍的推理加速，且验证损失未受损。然而，本文的边界在于未验证该配置在长上下文精确检索任务上的表现，也未探索其与混合架构（如 Transformer+SSM）的协同效应。当模型规模进一步扩大至万亿参数时，层丢弃的弹性收益是否会被 KV Cache 内存瓶颈所抵消，论文未给出回答。
