# HuggingFace最新推荐论文 ｜FLEET: From Logits Entropy to Enhanced Trajectories in Text Generation ｜基于记忆增强的解码引导：FLEET

作者：Oleksii Streltsov、Oleksandra Vitko

论文原文见 [arXiv](https://arxiv.org/abs/2609.27657)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.27657)

> 大语言模型在自回归生成中面临“局部错误级联”与“采样冗余”的双重困境，传统温度采样因缺乏历史记忆导致边际收益递减。FLEET 通过引入在线隐藏状态聚类与蒙特卡洛树搜索机制，将解码过程从盲目随机采样转化为基于历史轨迹的定向搜索。该方法在 LiveCodeBench 上以 3 倍加速实现了 66.2% 的 Pass@32 准确率，但在开放域泛化与复杂反思模型上的适用性仍存疑。

## 研究背景

当模型在推理链的早期步骤产生微小偏差时，后续步骤往往基于错误前提继续推导，导致最终答案完全偏离正确路径。这种“流畅但错误”的现象源于自回归机制的局部最优性无法保证全局逻辑正确性。为缓解此问题，测试时计算扩展（Test-Time Scaling, TTS）范式应运而生，其核心是通过增加推理时的计算资源来提升性能。然而，主流 TTS 策略如自一致性（Self-Consistency）依赖大量并行采样与多数投票，存在计算成本高、静态且易受验证器噪声影响的局限。

现有 TTS 方法大多将验证与生成解耦，即先生成 $N$ 条路径再筛选，忽略了生成过程中的实时纠错潜力。标准温度采样虽然引入了随机性，但其无记忆特性导致在关键分支点（Branching Points）上持续向不可行候选分配概率质量，且无法利用历史评估反馈进行探索-利用平衡。FLEET 的切入点在于将解码过程重构为一种带有历史记忆的搜索过程，通过内省模型内部状态识别高不确定性节点，并利用历史轨迹数据动态调整 logits，从而在单条或少量生成中实现高效的路径优化。

## 核心方法

### 解码策略参照系

本文问题归属于测试时推理扩展中的解码策略优化。与“生成-验证-选优”的标准 TTS 流程不同，FLEET 将干预前置至解码阶段，通过实时惩罚次优 token 引导生成轨迹，而非事后筛选。

### 基于熵-方差的状态识别与在线聚类

设计动机在于解决标准温度采样在低熵结构步骤（如标点、语法）上无效注入方差，以及在多模态决策步骤上无法区分语义等价与语义分歧的问题。FLEET 利用 Logit Lens 技术从中间层提取隐藏状态 $h^{(l)}$，计算条件熵 $H$ 与方差熵 $V$ 以识别关键分支点。对于触发阈值的状态，引入向量不相交并查集（VectorDSU）进行在线聚类，将连续隐藏状态映射为离散搜索节点。聚类依据余弦相似度 $S_C$ 与 KL 散度 $D_{KL}$ 的对应关系：

$$
S_C(h_1, h_2) \ge \tau \implies D_{KL}(P_1 \| P_2) \le \epsilon
$$

该机制确保语义相近的状态被聚合，从而在低内存开销下构建可复用的历史轨迹图。

### 基于 pUCT 的软约束解码

设计动机在于克服标准 UCT 在巨大词汇空间下假设穷举局部探索的局限性，以及温度采样缺乏“利用”（Exploitation）概念的问题。FLEET 采用预测器引导的 UCT（pUCT）公式，结合语言模型先验 $P(s,a)$ 与历史奖励期望 $Q(s,a)$ 计算动作价值：

$$
\text{pUCT}(s, a) = Q(s, a) + c_{puct} P(s, a) \sqrt{\frac{\ln N(s)}{1 + N(s, a)}}
$$

算法不替换解码器，而是对未最大化 pUCT 目标的已探索次优 token 施加 logit 惩罚 $\lambda$。这种软约束机制保留了原始解码策略的灵活性，同时通过历史记忆引导概率质量向高奖励分支集中，实现了从盲目随机到定向搜索的范式转变。

## 实验评估

实验基于 Llama 3.2-3B 模型，在 LiveCodeBench（222 道易题）和 GSM8K 上进行评估，对比基线仅为优化后的温度采样。FLEET 在 LiveCodeBench 上 Pass@32 达到 66.2%，相比基线的 59.9% 提升 6.3 个百分点，且推理速度提升 3 倍。在 GSM8K 上，FLEET 达到了与基线相同的准确率，但显著降低了计算成本。

| 任务 | 指标 | FLEET | 温度采样基线 | 提升幅度 |
| :--- | :--- | :--- | :--- | :--- |
| LiveCodeBench | Pass@32 (%) | 66.2 | 59.9 | +6.3 |
| GSM8K | 准确率 (%) | 同基线 | - | 0 |

消融实验显示，FLEET 的性能依赖于中间层选择与阈值校准。层选择评分 $S(L)$ 综合考虑了预测对齐率、聚类可分性与分布偏差，最终选定层需平衡 Logit Lens 匹配率与熵-方差聚类质量。温度 $T_{resample}$ 被校准至探索尾部概率质量超过利用头部（top-1）的临界点（约 2.9），以确保早期搜索的探索性。

评估边界方面，实验仅覆盖代码生成与数学推理两个可验证领域，缺乏开放域任务测试。基线对比缺失 Self-Consistency、PRM 等主流 TTS 方法，导致无法直接量化 FLEET 相对于标准验证器路线的优势。代码已开源，但超参数校准依赖特定模型的中间层特性，跨架构迁移性未验证。

## 关联研究分析

从问题动机看，FLEET 与 ReProbe 均利用隐藏状态，但 ReProbe 侧重于事后步骤级验证评分，而 FLEET 侧重于事前解码引导。这一差异源于任务目标的不同：ReProbe 旨在从多条路径中选出正确解，FLEET 旨在在生成过程中避免错误路径。FLEET 的软约束机制避免了 ReProbe 所需的额外前向传播开销，但牺牲了验证过程的可解释性，且依赖生成器内部表示的稳定性。

从方法设计看，FLEET 与 CoRefine 均涉及自适应计算分配，但 CoRefine 基于外部验证器信号，FLEET 基于内部状态聚类。CoRefine 在 AIME24 上取得 60.43% 的高分，但依赖昂贵的验证器调用；FLEET 在 LiveCodeBench 上以 3 倍加速实现性能提升，但局限于小模型与特定任务。这种差异暗示，内部状态引导在计算受限场景下更具优势，但在高难度、高反思性任务中，外部验证器的全局视角可能更为关键。FLEET 未对比 Self-Consistency，是否因其旨在替代而非增强采样，论文未给出明确回答。

## 总结

FLEET 针对测试时扩展中采样冗余与计算效率的矛盾，提出了一种基于记忆增强的解码引导框架。其核心在于利用中间层隐藏状态的熵-方差特征识别关键分支点，并通过 VectorDSU 在线聚类与 pUCT 搜索策略动态调整 logits，实现了从盲目随机采样到定向搜索的转变。实验证明，该方法在 LiveCodeBench 上以 3 倍加速实现了 66.2% 的 Pass@32 准确率，显著优于温度采样基线。然而，其边界在于仅验证了可验证领域的小模型场景，缺乏与主流 TTS 方法的横向对比，且在依赖内部反思的复杂推理模型上可能失效。当模型进入深度反思状态时，FLEET 的确定性选择机制是否会导致性能退化，论文未给出回答。
