研究机构：美国弗吉尼亚理工大学、美国南加州大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.05824)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.05824)

> 大规模技能库中，独立相关性排序导致功能冗余技能挤占上下文窗口，而多步任务所需的互补技能常被遗漏。现有检索器仅优化单点相关性，无法感知技能集合间的覆盖完整性。DSR 引入行列式点过程（Determinantal Point Process, DPP）进行集合选择，通过查询残差核区分“查询相关相似”与“功能冗余”。该方法在 SkillRouter 基准上提升了多技能任务的全覆盖率，但增益幅度有限，且未验证在动态增长技能库下的计算效率。

## 研究背景

当代理面对包含数万技能的注册表时，上下文窗口成为硬性约束。若直接加载所有相关技能，不仅会溢出上下文，还会因大量功能重叠的技能干扰执行。这要求路由机制不仅识别单个技能的相关性，还需评估技能集合的互补性。传统检索将每个技能独立打分并取 Top-k，忽略了技能间的结构依赖。例如，一个数据分析任务需要解析、清洗和可视化三个技能，它们因均与“数据分析”查询相关而在嵌入空间中距离较近，独立排序可能选出三个解析技能，却遗漏了清洗技能。

技能路由领域的主流路线是“检索-重排”两阶段架构。SkillRouter（Zheng et al., 2026）确立了这一范式，使用嵌入模型检索候选集，再用重排模型对每个候选独立打分。该范式在单技能任务中表现良好，但在多技能组合任务中暴露出“相关性-效用差距”：高相关分数的技能可能功能高度重叠，导致选出的集合无法覆盖任务全流程。DSR 的切入点在于将路由问题从“独立排序”重构为“多样性感知的子集选择”，在重排阶段引入集合级优化，以解决冗余技能挤占上下文的问题。

## 核心方法

### 方法参照系

DSR 基于标准的“检索-重排”流程，但改变了重排后的选择逻辑。标准流程中，重排器输出独立分数，直接取 Top-k 作为最终结果。DSR 保留检索器和重排器不变，仅在最终选择阶段引入 DPP 机制，将独立分数转化为集合选择问题，以平衡相关性与非冗余性。

### 查询残差多样性核

标准 DPP 核直接使用技能间余弦相似度计算多样性，这会惩罚所有共享嵌入方向的技能。然而，在技能路由中，两个技能可能因均与查询相关而相似，而非因功能冗余。DSR 提出查询残差核，先剔除技能嵌入中与查询对齐的分量，再计算残差空间的相似度。这一设计解决了标准核误删互补技能的失效：

$$
r_i = e_i - (e_i^\top e_x) e_x
$$

该公式从技能嵌入 $e_i$ 中减去其在查询嵌入 $e_x$ 上的投影，得到与查询正交的残差向量 $r_i$。随后，DSR 将残差与原始嵌入混合并归一化：

$$
\tilde{z}_i = \lambda r_i + (1 - \lambda) e_i, \quad z_i = \frac{\tilde{z}_i}{\|\tilde{z}_i\|_2}
$$

其中 $\lambda = 0.85$ 控制残差投影强度。查询条件相似度定义为 $\phi_x(s_i, s_j) = 1 + z_i^\top z_j$，映射至 $[0, 1]$。这一设计使多样性惩罚仅作用于查询无关的功能重叠，保留了因查询相关而产生的相似性，从而避免误删互补技能。

### 贪心 MAP 选择

DPP 的精确最大后验（MAP）推理计算复杂度高，DSR 采用贪心策略。从空集开始，每次选择使对数行列式边际增益最大的候选技能：

$$
s^* = \arg\max_{s_i \in C_x \setminus A} \log \det(L(x)_{A \cup \{s_i\}}) - \log \det(L(x)_A)
$$

该公式通过增量 Cholesky 更新计算边际增益，避免全量重算。当 $|A| = k$ 时停止，选出的技能按质量分数排序输出。这一设计在保持 DPP 集合优化优势的同时，将计算复杂度控制在可接受范围内，适用于大规模技能库的实时路由。

## 实验评估

| 指标 | SkillRouter | DSR | 提升 |
| :--- | :--- | :--- | :--- |
| Recall@20 (All) | 0.754 | 0.768 | +0.014 |
| Full Coverage@20 (All) | 0.560 | 0.573 | +0.013 |
| Recall@20 (Multi) | 0.704 | 0.739 | +0.035 |
| Full Coverage@20 (Multi) | 0.458 | 0.492 | +0.034 |

DSR 在 SkillRouter 基准（80K 技能，75 查询）上评估，基线为 SkillRouter 的点式重排。主结果显示，DSR 在所有查询上的 Recall@20 从 0.754 提升至 0.768，Full Coverage@20 从 0.560 提升至 0.573。多技能子集上增益更显著：Recall@20 从 0.704 提升至 0.739，Full Coverage@20 从 0.458 提升至 0.492。这表明多样性选择对多技能任务更有效，但整体增益幅度有限，未出现数量级提升。

| 消融配置 | Recall@10 | Multi-FC@10 |
| :--- | :--- | :--- |
| Cosine Kernel + Reranker Quality | 0.711 | 0.254 |
| Query-Residual Kernel + Reranker Quality | 0.711 | 0.441 |
| Query-Residual Kernel + Embedding Quality | 0.618 | 0.237 |

消融实验揭示，查询残差核是最大增益来源：将标准余弦核替换为查询残差核，Multi-FC@10 从 0.254 提升至 0.441，提升 0.187。质量信号同样关键：使用嵌入质量替代重排器质量，Recall@10 从 0.711 降至 0.618，Multi-FC@10 从 0.441 降至 0.237。这表明多样性选择依赖可靠的相关性信号，若质量分数无法区分有用技能，DPP 优化将失效。

评估边界方面，DSR 仅使用 Recall@k 和 Full Coverage@k 两个指标，未报告 MRR@k 以外的早期精度诊断。实验在 NVIDIA A100 80GB GPU 上运行，但未报告推理延迟或计算开销，无法评估 DPP 贪心选择在实际部署中的效率。代码未公开，复现依赖 SkillRouter 的开源实现。

## 关联研究分析

从问题动机看，DSR 与 SkillDAG 均关注大规模技能库的检索瓶颈，但解决路径不同。SkillDAG 采用图结构路由，显式建模技能间的依赖关系，通过遍历图结构确保选出的技能集满足依赖约束。DSR 则采用 DPP 多样性选择，隐式处理冗余，不显式建模依赖。这一差异源于任务特性：SkillDAG 适用于依赖关系明确的任务（如工作流执行），而 DSR 适用于依赖关系模糊但功能互补的任务（如多步数据分析）。DSR 未对比 SkillDAG，无法判断在依赖关系明确的任务中，图结构是否优于多样性选择。

从方法设计看，DSR 与 SkillRouter 共享“检索-重排”框架，但 DSR 在重排后引入集合优化。SkillRouter 的重排器输出独立分数，DSR 将分数转化为 DPP 核的质量项。这一改动使 DSR 能感知技能集合的覆盖完整性，但引入了额外的计算开销。SkillRouter 未报告计算效率，DSR 也未报告，两者均无法评估在实际部署中的延迟影响。DSR 的查询残差核是一种非图结构的替代方案，避免了图构建的复杂性，但可能无法捕捉显式的依赖关系。

## 总结

DSR 针对大规模技能库中独立排序导致冗余技能挤占上下文、互补技能遗漏的问题，提出查询残差 DPP 选择机制。该方法通过剔除查询对齐分量区分功能冗余与查询相关相似，在 SkillRouter 基准上将多技能 Full Coverage@20 从 0.458 提升至 0.492。实验表明，查询残差核是最大增益来源，但整体提升幅度有限，且未验证在动态增长技能库下的计算效率。当技能库实时增长时，DPP 矩阵的增量更新是否可行，论文未给出回答。
