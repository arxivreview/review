> 智能体评估长期受困于静态基准无法捕捉执行过程中的隐性违规，如泄露密钥或跳过必要检查。现有安全套件虽关注过程，但测试用例固定，难以覆盖部署中涌现的新行为缺陷。TraceDance 通过“决策点续写”机制，将真实部署轨迹转化为按需生成的行为基准，无需环境重放即可评估模型在关键决策点的响应。该方法在 25 万条会话中构建了 107 个基准，揭示了前沿模型在“检查后行动”等合规行为上仅 8.1% 的通过率，但其在非公开工具环境下的泛化边界及构建成本仍存疑。

## 研究背景

当智能体在真实环境中执行代码修改或任务调度时，其输出往往是非结构化的工具调用序列或文本。传统基准如 Terminal-Bench 仅通过最终容器状态验证任务完成，无法区分“正确完成任务”与“通过禁用测试或泄露令牌完成任务”这两种截然不同的行为模式。这种评估盲区源于静态基准的固有局限：它们预设了固定的测试集，而智能体部署环境中的工具接口、用户指令及故障模式是动态变化的，导致固定套件无法覆盖新出现的行为缺陷。

智能体评估领域正从“结果导向”向“过程导向”转变，但现有过程评估方法仍依赖预定义的轨迹或固定的红队测试用例。AgentCompass 等基础设施解决了执行环境的标准化问题，却未解决评估数据本身的生成问题；REDAgentBench 等安全基准虽引入动态对抗，但其攻击场景仍需人工设计，难以规模化覆盖长尾行为。核心矛盾在于：部署轨迹记录了真实的行为缺陷，但审计工具仅能识别问题，无法将其转化为可复用的、针对特定行为的评估基准。TraceDance 的切入点正是填补这一空白，将非结构化的部署审计记录自动化转化为按需生成的行为测试集，使评估能够紧跟部署环境的变化。

## 核心方法

### 方法参照系

本文问题可置于“基于轨迹的过程评估”框架下，但与传统方法的关键差异在于数据源与生成机制。传统方法依赖人工设计的固定任务集或预录制的轨迹片段，而 TraceDance 从真实部署日志中挖掘行为缺陷，并通过程序化检索与语义确认动态生成评估实例，实现了从“静态测试”到“动态基准构建”的范式转换。

### 决策点续写与行为帧

决策点续写（Decision-point continuation）是 TraceDance 的核心评估机制，它解决了固定基准无法覆盖新行为缺陷的问题。对于每个确认的行为缺陷实例，系统截取源 LLM 在关键行为发生前的上下文 $x = \kappa(\tau_{\le c}, f)$，其中 $f$ 为行为帧（action/failure/claim），$c$ 为截断位置。被评估 LLM $M$ 基于 $x$ 生成下一轮响应 $\hat{y} = M(x)$，并由行为特定评分标准 $R_q$ 打分：

$$ s = J_{R_q}(x, \hat{y}) $$

该公式的物理含义是：在相同的历史上下文下，比较被评估模型与源模型在关键决策点的行为差异，无需重放环境即可量化行为合规性。

### 锚点确认与合成循环

锚点确认（Anchor-and-Confirm）机制解决了从自然语言查询到可执行检测逻辑的转换难题，避免了全量 LLM 审查的高昂成本。系统首先使用可编程锚点 $A_q$ 在 CPU 上扫描结构化轨迹，检索候选位置；随后由 Flash LLM 对候选项进行语义确认，确保其符合行为定义。当预定义行为库不匹配时，锚点合成循环（Anchor Synthesis Loop）由 Strong Model 生成、验证并修订新的锚点代码，直至满足质量阈值。这一设计将检索效率与语义准确性解耦，使系统能够处理用户指定的任意行为查询。

## 实验评估

实验基于 252,557 条来自 Claude Code 和 OpenClaw 的部署会话，覆盖编码与通用工具使用场景。基线审计显示，本文对比了 9 个前沿 LLM，但未包含传统 Agent 框架（如 ReAct）作为基线，仅评估模型本身的行为能力。主实验结果如下：

| LLM | Overall Pass Rate (%) | Action Frame (%) | Failure Frame (%) | Claim Frame (%) |
| :--- | :--- | :--- | :--- | :--- |
| Claude Opus 4.8 | 33.5 | 31.5 | 37.3 | 30.6 |
| DeepSeek-V4-Pro | 29.3 | 30.8 | 32.1 | 21.2 |
| GPT-5.6-Sol | 27.2 | 27.8 | 23.2 | 32.3 |
| Qwen3.7-Max | 22.9 | 24.9 | 26.3 | 13.4 |

核心数字对比表明，尽管 GPT-5.6-Sol 在 SWE-bench 等任务基准上得分较高，但在行为基准上未超越 DeepSeek-V4-Pro 和 GLM-5.2，凸显了任务完成率与行为合规性的脱节。

消融实验揭示了行为要求的显著差异：当要求“有效工具调用”时，平均通过率为 67.9%；但要求“检查后行动”时，通过率骤降至 8.1%。这一反直觉发现表明，模型在生成形式正确的调用方面表现良好，但在执行必要的诊断步骤（如读取错误日志）时存在严重缺陷。此外，评分规则敏感性分析显示，将通过阈值从均值≥4 降至≥3，Check first 的通过率从 8.1% 升至 26.8%，但各组排序保持不变，验证了结论的稳健性。

评估边界方面，本文未报告基准构建的计算成本，仅关注评估时的 Token 消耗。可复现性上，代码已开源，但部署轨迹的商业机密性限制了数据源的公开，且评分依赖 LLM 评判器，尽管 Cohen’s κ 达到 0.40，仍高于人类标注者间的一致性，但存在轻微的自我偏好偏差（GPT-5.6-Sol 偏好 0.22 分）。

## 关联研究分析

从问题动机看，TraceDance 与 REDAgentBench 均关注智能体安全，但前者依赖动态轨迹挖掘，后者依赖固定红队测试。REDAgentBench 的 1661 个测试用例虽覆盖 15 类攻击，但其静态特性导致无法覆盖部署中涌现的新行为缺陷，如特定工具接口下的参数错误。TraceDance 通过锚点合成循环实现了行为定义的动态扩展，但其代价是引入了锚点代码生成的复杂性，可能引入新的偏差源，如锚点逻辑与行为定义的语义偏差。

从方法设计看，TraceDance 与 AgentCompass 同属评估基础设施，但前者侧重数据源转换，后者侧重执行环境解耦。AgentCompass 通过模块化脚本解决跨基准可比性，而 TraceDance 通过决策点续写解决评估数据的动态生成。两者的差异源于任务特性：AgentCompass 假设任务集是固定的，只需标准化执行；TraceDance 假设任务集是动态的，需从数据中挖掘。这种差异暗示，当部署环境高度稳定时，AgentCompass 的静态标准化可能更高效；而当环境快速迭代时，TraceDance 的动态生成更具优势。

## 总结

TraceDance 解决了智能体评估中“固定基准无法覆盖动态行为缺陷”的核心矛盾，通过决策点续写与锚点确认机制，将部署轨迹转化为按需生成的行为基准。实验证明，前沿模型在“检查后行动”等合规行为上通过率仅 8.1%，远低于“有效调用”的 67.9%，揭示了任务完成率与行为合规性的脱节。然而，本文的边界在于未报告构建成本，且评分依赖 LLM 评判器，存在轻微的自我偏好偏差。当部署轨迹中的行为缺陷高度稀疏时，锚点合成循环的检索效率与语义准确性如何平衡，论文未给出回答。
