# HuggingFace最新推荐论文 ｜Environment Evolution for Terminal Agents ｜环境演化

论文原文见 [arXiv](https://arxiv.org/abs/2609.04128)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.04128)

> 前沿大模型在静态终端环境中已具备高通过率，导致强化学习（RL）训练缺乏有效的梯度信号。现有基于策略回滚（on-policy rollout）的协同演化方法受限于当前模型能力，难以在模型变强后持续提供挑战。本文提出离线环境演化范式，通过解耦环境生成与策略训练，利用多智能体循环机制沿场景、技能、长度三个维度增量提升环境难度。该方法在Qwen3.6系列模型上验证了更持久的学习信号，但缺乏对演化过程收敛性的理论保证。

## 研究背景

终端智能体（Terminal Agent）通过命令行工具与计算系统交互，其能力上限取决于训练环境的难度与多样性。当智能体在固定环境中反复训练时，若其通过率接近100%，奖励信号将失去区分优劣轨迹的能力，导致训练停滞。这构成了RL中的“学习信号稀疏”问题：环境必须始终位于智能体能力的“可解但困难”区间，即学习前沿（Learnable Frontier）。

传统环境扩展方法如POET（Paired Open-Ended Trailblazer）和UED（Unsupervised Environment Design）通过环境-智能体协同演化来维持这一前沿。然而，这些方法依赖指定智能体在种子环境上的on-policy回滚来估计难度，生成的新环境分布与回滚模型及初始环境分布强耦合。当目标模型能力提升后，基于旧模型弱点生成的环境可能不再具有挑战性，或泛化能力受限。本文的切入点在于将环境难度估计从策略依赖的on-policy模式转变为策略无关的off-policy模式，通过直接操纵环境结构实现难度的独立演化。

## 核心方法

### 方法参照系

本文问题属于非平稳环境下的课程学习（Curriculum Learning）范畴。标准流程是动态调整环境分布以匹配智能体能力，但通常依赖智能体反馈（如通过率）作为难度代理。本文的关键差异在于移除对目标智能体回滚的依赖，转而基于环境本身的语义结构定义难度，并实现环境的自演化。

### 离线难度建模与演化方向

传统方法使用模型通过率作为难度指标，但这仅反映特定模型的能力，而非环境固有难度。本文从多轮学习目标出发，定义环境难度为高层级轨迹的负对数似然。设 $\xi = (\sigma_0, \kappa_1, \dots, \kappa_L, \sigma_L)$ 为场景-技能交替的高层级轨迹，$g$ 为任务指令，$p_T$ 为基于广泛世界知识的参考分布。环境固有难度 $D_T(\xi)$ 定义为：

$$ D_T(\xi) = \sum_{t=1}^{L} \left( -\log p_T(\sigma_{t-1} | g) - \log p_T(\kappa_t | \sigma_{t-1}, g) \right) $$

该公式将难度分解为三个正交维度：执行长度 $L$、场景新颖性 $-\log p_T(\sigma | g)$ 和技能稀有性 $-\log p_T(\kappa | \sigma, g)$。这一设计解决了on-policy方法中“模型弱点”与“环境难度”混淆的问题，使得难度估计独立于具体策略，从而允许在模型变强后继续生成具有挑战性的环境。

### 循环工程多智能体演化框架

基于上述难度分解，本文实现了一个循环工程化的多智能体框架，包含计划细化（Plan Refinement）和环境细化（Environment Refinement）两个闭环。计划生成器（Proposer）根据选定的演化方向（场景、技能或长度）修改执行序列，生成演化计划；评审器（Reviewer）基于评分标准迭代审查计划，直至通过。随后，修改器（Modifier）将计划转化为环境增量 $\Delta E$，并应用至当前环境。候选环境必须通过三个并行验证器：Oracle验证器确保参考解在沙箱中成功，无效测试验证器确保空解失败，通用评分验证器检查环境质量。

$$ (g_{u+1}, k_{u+1}) = \begin{cases} (g_u, k_u + 1), & \hat{p}_u(E_i, g_u, k_u) \le \tau \\ (g_u + 1, 1), & \hat{p}_u(E_i, g_u, k_u) > \tau \land k_u = N_{i,g_u} \end{cases} $$

该调度器（EL Scheduler）通过监控通过率 $\hat{p}_u$ 控制环境代际的释放节奏。当当前环境通过率低于阈值 $\tau$（设为6/8）时，切换至同代下一环境；仅当当前代所有环境均被耗尽时，才进入下一代。这一机制避免了过早暴露过难环境导致的零梯度问题，确保了RL训练信号的连续性。

## 实验评估

实验在Terminal-Bench 2.1基准上进行，使用Qwen3.6-27B（稠密）和Qwen3.6-35B-A3B（MoE）作为目标模型，训练算法为GRPO。基线包括Agent-Environment Co-Evolution（基于on-policy回滚的协同演化）和Environment Ensemble（环境组合）。主要结果如下：

| 方法 | Qwen3.6-27B 峰值准确率 | Qwen3.6-35B-A3B 峰值准确率 | 峰值出现步数 (27B / 35B) |
| :--- | :--- | :--- | :--- |
| Environment Evolution (Ours) | 71.5% | 64.9% | 170 / 190 |
| Co-evolution | 62.9% | 55.1% | 130 / 160 |
| Ensemble | 60.0% | 52.8% | 90 / 70 |

环境演化在两个模型上均显著优于基线，且在更晚的训练步数达到峰值，表明其提供了更持久的学习信号。消融实验显示，在15代演化中，length方向产生最大的通过率下降（-7.1 pp），而scenario方向产生最大的平均轮数增加（+13.5）。High effort设置下，指令突变率保持在95%-100%，而环境和验证系统突变率较低，表明演化主要作用于任务描述而非底层代码结构。

评估边界方面，实验仅使用5次运行平均，未报告置信区间。环境难度评估依赖Hy4 preview、Claude Opus 5和GPT-5.6 Sol三个外部模型的回滚通过率，缺乏对演化环境内在复杂度的直接数学度量。代码未公开，且演化过程依赖Claude Code harness，限制了可复现性。

## 关联研究分析

从问题动机看，本文与POET和UED的核心差异在于难度估计的解耦。POET和UED依赖智能体在环境中的表现来定义“可解性”，这导致环境分布随智能体能力漂移，难以在智能体饱和后提供新挑战。本文通过引入基于世界知识的参考分布 $p_T$，将难度定义为环境属性而非智能体属性，从而实现了环境演化的独立性。这一设计源于终端任务的高维语义空间特性，使得基于语义结构的演化比基于参数空间的突变更具可控性。

从方法设计看，本文与基于模型基RL（MBRL）的方法存在根本区别。MBRL通过学习世界模型生成想象数据来提高样本效率，但面临模型误差累积问题。本文不学习世界模型，而是直接演化环境本身，并通过Oracle验证器确保环境的可解性。这种“环境即模型”的思路避免了模型误差，但牺牲了对环境动态的细粒度控制。此外，本文未探讨演化环境之间的泛化关系，即在一个演化谱系中训练的策略能否迁移到另一谱系，这在POET中是核心关注点，但在本文中被环境谱系的独立性所取代。

## 总结

本文解决的核心矛盾是前沿模型在静态环境中学习信号稀疏的问题。现有协同演化方法受限于on-policy回滚，无法在模型变强后持续提供挑战，而本文通过引入基于世界知识的离线难度建模，将环境演化与策略训练解耦。具体而言，本文提出了沿场景、技能、长度三个维度增量演化的多智能体框架，并通过EL Scheduler控制环境释放节奏。实验证明，该方法在Qwen3.6-27B和Qwen3.6-35B-A3B上分别提升了14.4和18.0个百分点的Terminal-Bench 2.1准确率，且学习信号持续时间更长。然而，实验仅验证了单一基准上的性能提升，未分析演化环境之间的泛化能力或策略迁移效果。当演化谱系扩展到超过15代时，环境复杂度的增长是否会导致验证器失效或智能体完全无法探索，论文未给出回答。
