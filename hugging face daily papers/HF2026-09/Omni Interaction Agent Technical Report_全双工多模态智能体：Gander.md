# HuggingFace最新推荐论文 ｜Omni Interaction Agent Technical Report ｜全双工多模态智能体：Gander

研究机构：浙江大学、上海交通大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.08977)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.08977)

> 导读 现有语音交互模型受限于“请求-响应”的离散轮次范式，无法处理人类对话中自然存在的打断、背景音干扰及多模态实时感知需求，且单一模型难以同时满足低延迟交互与长程复杂推理的计算需求。Gander 提出了一种基于“小脑-大脑”解耦架构的全双工智能体，通过流式块级扁平化机制统一多模态输入输出，并引入异步执行层处理长程任务。该设计在内部评估中展现了在噪声、打断等复杂场景下的鲁棒性，但在标准多模态理解基准上性能低于基线模型，其实际泛化能力存疑。

## 研究背景

当智能体需要处理连续的视频流和语音流时，传统的离散轮次交互范式面临根本性挑战。这种挑战源于全双工交互（Full-Duplex Interaction）的要求：系统必须能够同时监听和说话，并在用户打断或环境变化时动态调整状态。实现这一目标需要模型具备内在的交互控制能力，而非依赖外部语音活动检测（VAD）模块。然而，实时交互对低延迟的极致要求与复杂智能体任务所需的长程推理深度之间存在固有的计算资源冲突，单一单体模型难以兼顾两者。

当前主流路线分为两类：一类是纯音频交互模型，如 BayLing-Duplex 和 Seeduplex，它们通过状态令牌处理打断和背景音，但缺乏视觉感知能力，无法利用视觉上下文解决语音歧义；另一类是全模态模型，如 MiniCPM-o 4.5 和 SeedRealtime，它们实现了多模态流的统一处理，但通常将交互控制与复杂推理耦合在同一模型中，导致在长程任务中响应延迟增加或推理能力受限。Gander 的切入点在于将交互控制与复杂推理解耦，通过“小脑”负责实时多模态感知与交互控制，“大脑”负责异步长程推理，从而在保持实时性的同时扩展智能体能力边界。

## 核心方法

### 方法参照系

Gander 的问题定位在全模态实时交互智能体，与传统的文本智能体（如 ReAct 范式）的关键差异在于输入输出的连续性与模态多样性。传统智能体处理离散文本指令，而 Gander 需处理每秒数十帧的视频和连续语音流，且交互状态（听/说/打断）需在毫秒级内决策。因此，其方法参照系并非标准的“推理-行动”循环，而是基于流式处理的“感知-控制-执行”并行架构。

### 流式块级扁平化机制

为了解决多模态流的时间对齐与交互状态控制问题，Gander 引入了流式块级扁平化（Streaming Chunk Flattening）机制。该机制将连续的音视频输入和模型输出分割为固定时间窗口（1秒）的块（Chunk），并将每个块内的感知令牌、控制令牌和生成令牌拼接为统一的自回归序列。在每个块中，模型首先预测一个控制令牌，决定当前窗口的交互状态：

$$
c_t \in \{ \text{listen}, \text{speak}, \text{interrupt} \}
$$

其中 $c_t$ 为第 $t$ 个块的控制令牌。若 $c_t = \text{listen}$，模型保持静默并继续观察；若 $c_t = \text{speak}$，模型生成语音内容；若 $c_t = \text{interrupt}$，模型中断当前发言。这一设计将“是否说话”与“说什么”解耦，避免了传统自回归模型中交互决策与内容生成纠缠导致的流式解码不稳定。通过滑动窗口管理上下文（固定 128 块，约 2 分钟），该机制确保了长会话中推理成本的稳定性，同时保留了最近的交互历史。

### 小脑-大脑解耦架构

为了解决实时交互与长程推理的计算冲突，Gander 采用了小脑-大脑（Cerebellum-Brain）解耦架构。小脑负责实时多模态感知、交互控制和语音生成，大脑则作为异步推理模块，处理复杂规划、工具调用和长程任务执行。小脑通过工具调用机制将累积的文本上下文、语音转录和视觉帧传递给大脑，大脑异步执行推理并返回中间摘要或最终结果。

该架构的核心在于大脑的“免训练”（Training-free）与“即插即用”（Plug-and-play）特性。大脑不直接参与实时交互训练，而是作为一个独立的推理引擎，通过统一的 Worker Provider 接口集成。这意味着更强的推理模型可以直接替换大脑，而无需重新训练小脑，从而实现了交互能力与推理能力的独立扩展。这种设计解决了单一模型中响应性与智能性的权衡问题，使得系统能够在用户打断或环境变化时，由小脑快速响应，同时由大脑在后台继续执行长程任务。

## 实验评估

Gander 的评估涵盖对话能力、全模态理解、交互能力和智能体智能四个维度。在基线覆盖上，论文对比了 MiniCPM-o 4.5、Qwen3-Omni、Gemini 2.5 Flash 等全模态模型，但缺乏针对全双工交互的专用基准对比，如 GPT-Live 或 Moshi。在标准多模态理解基准 BigBenchAudio 上，Gander 的表现低于基线模型：

| 模型 | BigBenchAudio (Acc %) | Daily-Omni (Acc %) |
| :--- | :--- | :--- |
| MiniCPM-o 4.5 | 55.70 | 80.20 |
| Qwen3-Omni | 54.00 | 70.70 |
| Gander | 49.62 | 78.53 |

Gander 在 BigBenchAudio 上比 MiniCPM-o 4.5 低 6.08 个百分点，在 Daily-Omni 上低 1.67 个百分点。这一差距表明，引入流式交互机制和大脑解耦架构可能牺牲了部分静态多模态理解能力。然而，在 SpokenQA 任务中，Gander 的表现接近基于轮次的系统，仅比 Baichuan-Omni-1.5 低 2.90 个百分点，说明流式格式本身并未显著损害语言骨干的知识保留。

在交互鲁棒性方面，论文通过内部人工评估展示了 Gander 在背景噪声、多方交互和打断场景下的表现。消融实验显示，移除大脑模块后，系统在长程任务上的 Pass@1 从 0.520 降至 0.450，RespQual 从 0.740 降至 0.600，验证了大脑在复杂任务执行中的关键作用。然而，论文未提供详细的超参数设置、训练数据规模对比或计算成本分析，限制了结果的可复现性。此外，评估主要依赖内部人工评估和特定基准，缺乏标准化的全双工交互基准，使得与现有全双工模型的直接比较受限。

## 关联研究分析

从问题动机看，Gander 与 MiniCPM-o 4.5 的核心差异在于交互控制的实现方式。MiniCPM-o 4.5 采用 Omni Flow 机制，将多模态输入输出置于统一时间轴，但交互决策仍由单一模型内部处理，缺乏显式的状态控制令牌。Gander 通过引入控制令牌 $c_t$，将交互状态显式化，使得模型能够更精细地控制打断和静默行为。这一差异源于任务特性的不同：MiniCPM-o 4.5 侧重于通用多模态理解，而 Gander 侧重于实时交互的鲁棒性。然而，Gander 在静态理解基准上的性能下降，暗示显式状态控制可能引入了额外的计算开销或干扰了多模态特征的融合。

从方法设计看，Gander 与 ReAct 范式的差异在于执行架构的解耦。ReAct 采用串行的“推理-行动”循环，每一步行动依赖前一步的推理结果，导致长程任务中延迟累积。Gander 通过小脑-大脑解耦，实现了感知与推理的并行化，小脑负责实时响应，大脑负责异步推理。这一设计解决了 ReAct 在实时交互场景中的延迟瓶颈，但引入了状态同步的复杂性。大脑与小脑之间的通信依赖工具调用和状态验证，若大脑执行时间过长，可能导致小脑上下文过期或任务状态不一致。论文未详细讨论这种异步执行下的状态一致性保障机制，这是其方法设计中的一个潜在盲区。

## 总结

Gander 试图解决全双工多模态智能体中实时交互与长程推理的计算冲突，通过流式块级扁平化机制和“小脑-大脑”解耦架构，实现了交互控制与复杂推理的分离。该设计在内部评估中展现了在噪声、打断等复杂场景下的鲁棒性，但在标准多模态理解基准 BigBenchAudio 上性能低于 MiniCPM-o 4.5 6.08 个百分点，表明流式交互机制可能牺牲了部分静态理解能力。其边界在于缺乏标准化的全双工交互基准对比，且异步执行下的状态一致性保障机制未充分验证。当大脑执行时间超过小脑上下文窗口时，任务状态是否会出现不一致，论文未给出回答。
