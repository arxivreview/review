# HuggingFace最新推荐论文 ｜MemBodied: Recurrent Associative Memory for Vision-Language-Action Models ｜固定容量关联记忆用于视觉-语言-动作模型

研究机构：新加坡南洋理工大学

作者：Tej Deep Pala、Navonil Majumder、Bryce Goh 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.28256)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.28256)

> 视觉-语言-动作（VLA）模型在长时程操作中面临“时间状态别名”困境，即当前观测相同但历史不同导致动作需求不同，而现有方法要么丢弃历史，要么通过扩展上下文引入高昂的推理延迟。MEMBODIED 通过引入固定大小的关联记忆状态与初始场景锚点，在不增加策略上下文长度的前提下实现了对过去交互信息的检索与利用。该方法在记忆依赖任务上实现了数倍于无记忆基线的成功率，同时保持了在标准基准上的竞争力，但其对真实物理环境动态噪声的鲁棒性仍存疑。

## 研究背景

当机器人执行“将物体移开后放回原位”的任务时，若仅依赖当前摄像头图像，由于物体已不在初始位置，策略无法确定“原位”坐标，这种当前观测无法唯一确定动作的现象被称为时间状态别名。解决此问题需要策略具备记忆能力，但直接保留完整历史帧会导致上下文长度、显存占用与推理延迟随时间线性增长，违背了实时控制的需求。因此，如何在固定计算预算内有效编码并检索关键历史证据，成为具身智能长时程控制的核心瓶颈。

现有 VLA 架构如 RT-2 和 π0 主要依赖当前观测与语言指令生成动作分块，虽在短时程任务中表现优异，但缺乏跨策略调用的状态保持机制。针对记忆缺失，近期研究分为三类：压缩历史观测为 Token（如 HAMLET、NativeMEM）、维持循环隐状态（如 µVLA）或显式存储检索（如 MemoryVLA）。然而，压缩历史 Token 方法仍会导致上下文随新信息累积而膨胀；循环隐状态依赖隐式嵌入，难以显式访问特定过去事件；显式存储方法则引入额外的辅助目标或处理管线，增加了系统复杂度。MEMBODIED 的切入点在于采用一种在线更新、大小固定的关联记忆机制，通过显式的读写接口让策略仅依靠动作目标学习何时写入、保留和检索信息，从而在效率与记忆容量间取得平衡。

## 核心方法

### 方法参照系

本文问题可置于“基于 VLM 骨干的连续动作生成”通用框架下，其标准流程为：输入当前观测 $I_t$、机器人状态 $s_t$ 和指令 $\ell$，经 VLM 编码后由动作专家生成动作分块 $a_t$。本文的关键差异在于引入了一个跨策略调用持久化的记忆状态 $E_{t-1} = (M_{t-1}, A)$，其中 $M_{t-1}$ 为关联记忆矩阵，$A$ 为初始场景锚点，策略输出变为 $a_t \sim p_\theta(\cdot | I_t, s_t, \ell, E_{t-1})$，从而将马尔可夫决策过程扩展为依赖历史的状态空间。

### 门控 Delta 规则关联记忆

为了解决传统循环记忆隐式存储导致的关键信息被覆盖问题，MEMBODIED 采用门控 Delta 规则更新固定大小的关联矩阵 $S_t^{(l)} \in \mathbb{R}^{B \times r \times r}$。写入值 $v_t^{(l)}$ 由执行后的视觉后果 $e_{t+1}^{vision}$ 与动作摘要 $a_t$ 拼接投影得到，写入键 $k_t^{(l)}$ 由层输出状态 $h_{t,out}^{(l)}$ 变换而来。状态更新公式为：

$$ S_t^{(l)} = \text{Diag}(\alpha_t^{(l)}) S_{t-1}^{(l)} + \text{Diag}(\beta_t^{(l)}) (v_t^{(l)} - \text{Diag}(\alpha_t^{(l)}) S_{t-1}^{(l)} k_t^{(l)}) (k_t^{(l)})^\top $$

该公式中，保留门 $\alpha_t^{(l)}$ 控制旧状态保留比例，写入门 $\beta_t^{(l)}$ 控制新关联强度，Delta 项 $(v_t^{(l)} - \dots)$ 确保仅修正与当前键关联的值，避免无差别累积。这种设计使得记忆大小 $r$ 固定，不随回合数增长，解决了 NativeMEM 等压缩历史方法中上下文膨胀导致的推理延迟问题。

### 初始场景锚点与延迟写入

关联记忆的反复更新可能覆盖早期场景细节，MEMBODIED 引入固定锚点 $A$ 作为补偿。$A$ 由首帧观测 $I_1$ 的视觉 Token 池化生成，在回合内保持不变。在每次策略调用时，当前状态 $s_t$ 通过交叉注意力从 $A$ 中检索紧凑的空间参考 $b_t$，并条件化动作网络。此外，采用延迟写入机制：策略在 $t$ 步读取记忆并生成动作，待环境返回 $I_{t+1}$ 后，才将 $t$ 步的动作与 $I_{t+1}$ 的视觉后果写入记忆。这一设计确保了记忆值包含动作的实际后果，而非仅包含动作意图，使记忆表征更具物理意义，同时避免了未来观测泄露到当前决策中。

## 实验评估

实验在 RMBench（记忆依赖任务）和 LIBERO（通用操作任务）上进行，基线包括无记忆 π0-Stateless、帧堆叠 π0-FrameStack、循环记忆 π0-Vanilla Recurrent Memory 及压缩历史 NativeMEM。在 RMBench 的五个任务上，MEMBODIED 平均成功率为 50.0%，是无记忆基线 6.4% 的 7.81 倍，也是 NativeMEM 38.4% 的 1.30 倍。在 LIBERO 基准上，MEMBODIED 平均成功率为 95.1%，与 π0 的 94.2% 相当，但在长时程 LIBERO-Long 套件上达到 90.6%，比 π0 的 85.2% 高出 5.4 个百分点。

| 方法 | RMBench Mean (%) | LIBERO-Long (%) | LIBERO Mean (%) |
| :--- | :--- | :--- | :--- |
| π0-Stateless | 6.4 | 85.2 | 94.2 |
| NativeMEM | 38.4 | - | - |
| MEMBODIED | 50.0 | 90.6 | 95.1 |

消融实验显示，移除锚点路径后，平均成功率从 50.0% 降至 37.6%，其中 Swap Blocks 任务从 56.0% 降至 16.0%，表明锚点对需要回忆初始场景的任务至关重要；但在 Block Ranking 任务上，锚点反而使成功率从 32.0% 降至 22.0%，说明固定首帧参考在依赖动态进度跟踪的任务中可能产生干扰。写入值组成分析表明，视觉观测与动作摘要的组合（46.7%）优于单独使用视觉（42.7%）或动作（34.7%），证实了两者在记忆表征中的互补性。

评估边界方面，RMBench 为仿真基准，虽提供了记忆复杂度的分类，但缺乏真实物理环境的噪声与动态性测试；LIBERO 评测未报告置信区间，且不同方法可能使用不同的 VLM 骨干，导致性能差异难以完全归因于记忆机制本身。代码已开源，但超参数如记忆秩 $r=128$ 和锚点秩 $r_A=64$ 的敏感性分析未在文中详细展开。

## 关联研究分析

从问题动机看，MEMBODIED 与 HAMLET 和 NativeMEM 均旨在解决长时程任务中的信息丢失，但路线截然不同。HAMLET 和 NativeMEM 通过压缩历史观测为 Token 并追加到上下文，其核心假设是“更多历史 Token 带来更好性能”，但代价是上下文长度随时间线性增长，导致推理延迟增加。MEMBODIED 则假设“固定大小的关联状态足以捕获关键交互”，通过 Delta 规则更新而非追加，实现了推理延迟降低 91.9% 且显存占用减少 9.5%。这一差异源于对“记忆容量”与“访问效率”权衡的不同取舍：压缩历史方法牺牲效率换取显式历史访问，而关联记忆牺牲显式历史可见性换取恒定计算成本。

从方法设计看，MEMBODIED 与 µVLA 等循环隐状态方法同属“固定大小状态”路线，但 µVLA 依赖隐式嵌入通过重复变换传递信息，缺乏显式的读写接口，难以诊断或控制记忆内容。MEMBODIED 引入显式的键值对结构和门控机制，允许策略通过动作目标学习何时写入和检索，这使得记忆行为可解释且可控。此外，MEMBODIED 的锚点机制是区别于所有现有循环记忆方法的关键创新，它解决了循环状态在长序列中早期信息被覆盖的问题，而 µVLA 等方法未提供类似的持久化参考机制。这种设计选择暗示，对于需要回忆初始条件的任务，显式的静态参考比纯动态循环状态更有效。

## 总结

MEMBODIED 针对 VLA 模型在长时程操作中因丢弃历史而导致的时间状态别名问题，提出了固定容量的关联记忆与初始场景锚点相结合的方法。通过门控 Delta 规则更新固定大小的关联矩阵，并引入延迟写入机制确保记忆包含动作后果，该方法在 RMBench 记忆依赖任务上实现了 50.0% 的平均成功率，是无记忆基线的 7.81 倍，同时在 LIBERO-Long 上比 π0 高出 5.4 个百分点，证明了其在保持通用操作能力的同时显著提升了历史依赖控制。然而，实验主要基于仿真环境，且锚点机制在动态进度跟踪任务中表现出负迁移，表明固定首帧参考并非对所有长时程任务均有益。当任务环境发生剧烈变化导致初始场景与当前状态差异过大时，锚点检索是否仍能提供有效参考，论文未给出回答。
