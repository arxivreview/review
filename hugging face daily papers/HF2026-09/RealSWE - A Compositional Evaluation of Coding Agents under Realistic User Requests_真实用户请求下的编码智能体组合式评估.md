# HuggingFace最新推荐论文 ｜RealSWE: A Compositional Evaluation of Coding Agents under Realistic User Requests ｜真实用户请求下的编码智能体组合式评估

研究机构：韩国成均馆大学

作者：Gyuhyeong Kim、Hyojung Gwon、Jeonghyeon Kim 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.27831)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.27831)

> 现有软件工程基准依赖结构化的 GitHub Issue 描述，与真实用户简短、非正式的请求存在显著分布偏差，导致模型性能被系统性高估。本文切入点在于量化这种“基准-现实差距”的因果机制，而非仅构建新数据集。通过构建 381 个多变体任务族，控制信息字段与语言风格，揭示输入构成对智能体性能的独立影响。该工作提供了可操作的评估框架，但受限于未覆盖前沿大模型，其结论在最强模型上的普适性存疑。

## 研究背景

当编码智能体面对“空输入崩溃，修复它”这类简短指令时，它必须从代码库中推断缺失的需求，这一过程称为上下文推断。然而，传统基准如 SWE-bench 提供的 Issue 描述通常包含复现步骤、环境信息等丰富细节，这种信息冗余掩盖了智能体在信息稀疏条件下的真实能力。这种输入分布的错位导致基准成绩无法反映实际部署场景中的性能，构成了评估指标与真实能力之间的偏差。

当前主流路线试图通过合成欠规范任务或截断问题描述来模拟真实场景，如 CursorBench 使用真实会话但闭源，其他开源方案则依赖启发式规则且缺乏实证基础。这些方法虽揭示了差距的存在，却未能系统性地解耦信息构成与语言风格的影响，无法回答“哪些信息字段真正有价值”这一核心问题。本文基于 SWE-CHAT 真实用户数据，通过结构化分类与 LLM 重写，构建了可配置的多变体评估框架，旨在量化输入信息对智能体性能的因果贡献。

## 核心方法

### 信息分类与语言维度定义

参照系为传统的单一 Issue 描述评估，其假设输入信息固定且完整。本文的关键差异在于将输入解耦为独立的信息字段与语言风格维度。设计动机在于解决现有基准无法隔离“信息内容”与“表达方式”对性能影响的问题。定义六类信息字段：问题陈述 [P]、期望行为 [D]、复现步骤 [R]、环境信息 [E]、附加信息 [A] 及功能请求的动机 [M]。同时定义四个语言维度：正式性、句式类型、确定性、视角。这种正交分解使得后续消融实验能独立控制变量。

### 多变体任务族构建

在参照系的单一任务实例基础上，本文引入 LLM 驱动的重构管道。设计动机在于确保同一底层任务在不同信息组合下具有可比性，避免任务难度混淆。首先，使用 GPT-5.4 将原始 Issue 分解为信息字段，保留技术内容如代码块与错误消息。随后，根据 SWE-CHAT 中观察到的主流语言风格（如 87% 非正式语气），重写为真实用户风格。最终形成 381 个任务族，每个族包含同一任务的不同信息子集变体。

$$
\text{Variant}_{i,j} = \text{Rephrase}(\text{Decompose}(\text{Issue}_i) \mid \mathcal{F}_j, \mathcal{L}_k)
$$

其中 $\mathcal{F}_j$ 为信息字段子集，$\mathcal{L}_k$ 为语言风格配置。该公式表明，变体由原始 Issue 经分解后，在特定字段与风格约束下重写生成，确保语义等价性。

### 分布对齐的基准采样

基于 SWE-CHAT 的实证分布，REALSWE-Bench 按特定比例采样变体。设计动机在于使评估集反映真实用户请求的信息稀疏性。对于 Bug 修复，74% 的变体仅含 [P]，26% 含 [PA]；功能请求则分别为 72% 和 28%。这种采样策略确保基准平均描述长度（1,417 字符）与 SWE-CHAT（1,427 字符）高度一致，远低于传统基准的 1,672–2,776 字符。

$$
P(\mathcal{F}) = \begin{cases} 0.74 & \text{if } \mathcal{F} = \{P\} \\ 0.26 & \text{if } \mathcal{F} = \{P, A\} \end{cases}
$$

该概率分布直接映射自真实用户数据，确保评估场景的生态效度。

## 实验评估

实验在 SWE-bench Verified 和 Pro 的 381 个任务上评估 7 个 LLM，包括 DeepSeek V4 Pro、MiMo V2.5 Pro 等。基线覆盖主流开源与商业模型，但未对比 SWE-agent 等专用智能体架构，仅评估模型在固定代理框架下的表现。

| 模型 | 原始解决率 (%) | RealSWE 解决率 (%) | 差值 (pp) |
|---|---|---|---|
| DeepSeek V4 Pro | 53.9±0.6 | 45.9±2.0 | −8.0 |
| MiMo V2.5 Pro | 49.1±1.2 | 44.0±1.0 | −5.1 |
| Qwen3.7 Plus | 50.1±0.5 | 43.5±0.8 | −6.6 |
| MiniMax M3 | 34.1±0.5 | 30.1±1.7 | −4.0 |

所有模型在 RealSWE 下解决率平均下降 6.4 pp，且排名发生逆转：MiMo V2.5 Pro 从第四升至第二，超越 Qwen3.7 Plus。这一变化表明，原始基准可能误导用户选择更昂贵但实际表现更差的模型。

消融实验显示，信息字段的价值极不均衡。移除期望行为 [D] 导致 Bug 修复解决率平均下降 8.0 pp，而移除复现步骤 [R] 和环境信息 [E] 无可测影响。对于功能请求，动机 [M] 的移除导致平均下降 3.4 pp，但模型间差异显著。语言风格变化仅产生微小且依赖模型的效果，证实信息内容比表达方式更关键。

评估边界方面，本文未报告计算效率的绝对值，仅显示成本平均增加 6.2%。可复现性上，代码与框架已开源，但 LLM 重写依赖 GPT-5.4，可能引入语义漂移。未覆盖 GPT-5.6 等前沿模型，结论在最强模型上的泛化性未知。

## 关联研究分析

从问题动机看，本文与 CursorBench 同属真实场景评估，但 CursorBench 使用真实会话导致任务与输入耦合，无法隔离输入影响；本文通过 LLM 重写实现任务-输入解耦，但依赖 LLM 的语义保持能力，其重写是否严格等价于原任务，论文未提供人工验证的完整统计。从方法设计看，本文与 SWE-RL 等强化学习方法不同，后者关注训练信号，本文关注评估输入。SWE-RL 假设执行反馈是可靠奖励，而本文发现输入信息稀疏会削弱智能体获取有效反馈的能力，暗示 RL 训练需考虑输入分布的鲁棒性。

## 总结

本文核心矛盾在于基准输入分布与真实用户请求的错位导致性能高估。切入点在于利用 SWE-CHAT 数据量化信息字段的因果价值，而非仅构建新数据集。通过 381 个多变体任务族，证明期望行为与动机是关键信号，而复现步骤与环境信息无显著贡献。核心数字为平均解决率下降 6.4 pp 及排名逆转。边界在于未覆盖前沿模型，且 LLM 重写的语义等价性未完全验证。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
