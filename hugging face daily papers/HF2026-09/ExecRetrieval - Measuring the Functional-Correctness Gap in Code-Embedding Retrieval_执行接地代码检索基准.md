# HuggingFace最新推荐论文 ｜ExecRetrieval: Measuring the Functional-Correctness Gap in Code-Embedding Retrieval ｜执行接地代码检索基准

作者：Aaryan Kapoor、Md Abdullah Al Hafiz Khan

论文原文见 [arXiv](https://arxiv.org/abs/2609.01865)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.01865)

> 代码嵌入检索是编码智能体与检索增强生成（Retrieval-Augmented Generation, RAG）的候选召回环节，其核心矛盾在于：现有基准仅评估主题相似度或身份匹配，无法隔离“近克隆但功能错误”的干扰项对排序的影响。本文切入点在于构建一个搜索池本身包含受控执行验证变异体的基准，使检索器的功能判别能力可被直接测量。通过植入单编辑错误变体并采用执行验证作为黄金标准，EXECRETRIEVAL 揭示了当前主流嵌入模型在 Rank-1 精度上的严重缺陷。其价值在于暴露了“召回即足够”假设的盲区，但受限于函数级任务粒度，其结论向仓库级智能体系统的迁移性存疑。

## 研究背景

当编码助手从本地仓库检索代码片段时，嵌入模型作为第一道过滤器，决定了哪些候选能被下游重排或执行验证看到。若检索池中存在与正确实现仅差一个操作符的“近克隆”错误变体，主题相似度极高的嵌入模型可能将错误代码排在正确代码之前，导致下游验证负担激增。这一困境源于传统代码检索基准（如 CodeSearchNet, Husain et al., 2019）仅依赖人工标注的主题相关性，缺乏对功能正确性的执行接地验证，使得“完美主题检索器”与“完美功能检索器”在现有指标下得分相同。

主流代码检索评估路线分为三类：人工标注基准（如 CoSQA, Huang et al., 2021）、聚合套件（如 CodeXGLUE, Lu et al., 2021）及下游生成质量评估（如 CodeRAG-Bench, Wang et al., 2025）。这些路线的共同瓶颈在于搜索池中缺乏受控的、可归因的功能错误变体，导致无法隔离单一编辑对排序的影响。最接近的工作 CoQuIR（Geng et al., 2026）虽关注质量轴，但其正确性标签来自自然发生的代码缺陷，而非针对每个查询的规范实现进行受控变异。EXECRETRIEVAL 的切入点是将执行验证前移至检索阶段，通过植入单编辑变异体，将稀疏的测试反馈转化为密集的排序判别信号，从而直接测量嵌入模型在功能判别上的盲区。

## 核心方法

### 方法参照系

本文问题属于代码检索基准构建，但与传统基准的关键差异在于验证机制：传统基准依赖人工标注或自然代码缺陷，而 EXECRETRIEVAL 要求搜索池中包含针对每个查询规范实现的受控单编辑变异体，且正确性由执行测试套件判定，而非文本相似度。

### 受控变异体生成与验证

传统基准的干扰项来自自然代码库，其错误类型不可控且难以归因。本文在生成阶段引入机械变异算子，针对每个查询的规范实现 $c$ 生成 $n \in \{3, 4\}$ 个单编辑错误变体 $D_1, \dots, D_n$。变异类型限定为六种机械操作：`wrong_operator`、`off_by_one_boundary`、`swap_arguments`、`off_by_one`、`wrong_comparison`、`remove_edge_case_check`。这些算子对应经典变异测试中的常量替换、关系/算术操作符替换及语句删除（Jia and Harman, 2011），确保每个错误变体仅引入一个可归因的语义偏差。

$$
\text{PASS}(c, T_q) = 1 \quad \text{and} \quad \exists j \in \{1, \dots, n\}: \text{PASS}(D_j, T_q) = 0
$$

该公式定义了基准的有效性约束：规范实现必须通过所有测试，而每个错误变体必须至少失败一个测试。这一设计解决了自然代码缺陷中“错误类型混杂”导致的归因困难，使得每次检索失败都可精确归因到特定的单编辑操作。验证流程包含五阶段门控：Schema 检查、AST 语义验证、规范执行、变体执行及语料库完整性审计，确保 939 个任务中所有规范实现通过测试，所有 3,755 个变体至少失败一个测试。

### 执行接地检索指标

传统检索指标如 nDCG 基于身份匹配，无法区分功能正确性。本文定义执行接地指标 exec@k，衡量 Top-k 检索结果中是否存在通过测试的实现：

$$
\text{exec@k}(q) = \mathbb{1}\left[ \exists i \le k : \text{PASS}(\hat{r}_i, T_q) = 1 \right]
$$

该指标将验证信号从“是否匹配规范实现”转变为“是否功能正确”，解决了传统指标在存在近克隆干扰项时的失效问题。当搜索池中包含与规范实现仅差一个操作符的错误变体时，nDCG 可能因身份匹配而高估检索质量，而 exec@k 直接测量功能判别能力。本文同时报告 execution_precision@k（Top-k 中通过测试的比例）和 canonical-ID nDCG，以对比功能正确性与身份匹配的差异。

## 实验评估

实验在 EXECRETRIEVAL 基准上进行，包含 939 个 Python 任务，覆盖 10 个算法领域，搜索池共 4,694 个片段。基线覆盖 23 种密集嵌入配置（Gemini、Mistral、OpenAI、Qwen3、BGE、E5、GTE、Sentence-Transformers）及 BM25 稀疏基线，采用各提供商文档中的最佳公平调用设置。

| 模型 | exec@1 | exec@10 | 95% CI (exec@1) |
|---|---|---|---|
| Gemini Embedding 2 | 0.331 | 1.00 | [0.299, 0.362] |
| Gemini Embedding 001 | 0.329 | 1.00 | [0.297, 0.360] |
| Mistral Embed | 0.224 | 0.98 | [0.195, 0.255] |
| Qwen3-8B | 0.214 | 0.98 | [0.185, 0.245] |
| BM25 | 0.058 | 0.422 | [0.038, 0.080] |

核心发现是 Top-k 检索饱和而 Rank-1 检索脆弱：Gemini Embedding 2 在 exec@10 上达到 1.00，但 exec@1 仅为 0.331。Rank-1 错误中 91.5%–99.4% 是配对的错误变体，表明失败并非随机查找错误，而是结构性地无法区分规范实现与其单编辑近克隆。在 Gemini Embedding 2 上，66.8% 的查询中规范实现的余弦相似度低于其至少一个配对变体；在 Qwen3-Embedding-8B 上，这一比例为 78.4%。

消融实验显示，该差距并非池密度的人工产物：当移除所有近克隆干扰项时，exec@1 显著提升，但即使仅保留一个干扰项，Rank-1 精度仍大幅下降。欺骗率（deception rate）在六种机械变异类型间广泛分布，总体为 44.3%，范围 39.3%–48.0%，其中 `remove_edge_case_check` 欺骗率最低，`wrong_comparison` 最高。这表明失败模式是嵌入近相同代码的固有属性，而非特定 bug 类型或微编辑的产物。

评估边界方面，本文仅评估函数级检索，未涉及仓库级依赖或环境配置；指标仅基于执行测试，未考虑代码可维护性或可读性；可复现性通过发布完整数据集、嵌入矩阵、执行缓存及 SHA-256 清单保障，但提供商 API 调用依赖外部服务，存在版本漂移风险。

## 关联研究分析

从问题动机看，EXECRETRIEVAL 与 SWE-bench（Jimenez et al., 2024）共享执行接地验证原则，但任务粒度从仓库级 Issue 修复缩小至函数级检索排序。SWE-bench 评估智能体端到端解决率，而 EXECRETRIEVAL 隔离检索前置环节的功能判别能力。这一差异源于任务特性：SWE-bench 中检索失败可被下游智能体通过多轮交互弥补，而 EXECRETRIEVAL 证明在存在近克隆干扰项时，Rank-1 失败率高达 66.9%，若下游重排无法完全修复此缺陷，则 SWE-bench 的高解决率可能掩盖了上游召回的功能盲区。

从方法设计看，EXECRETRIEVAL 与 xCodeEval（Khan et al., 2024）均采用执行验证，但构造层级不同：xCodeEval 评估代码-代码检索，其执行验证变体作为微调数据；EXECRETRIEVAL 将执行验证变体植入自然语言检索池，测试查询-代码排序。这一差异源于评估目标：xCodeEval 关注嵌入模型的功能一致性分类能力，而 EXECRETRIEVAL 关注检索器在真实查询场景下的功能判别能力。Li et al. (2025b) 的 Type-IV 变体（相似语法、不同功能）与 EXECRETRIEVAL 的单编辑变体形成对比：前者测试语义漂移，后者测试微编辑敏感性，两者共同揭示了嵌入模型在功能判别上的不同维度缺陷。

## 总结

EXECRETRIEVAL 要解决的核心矛盾是代码检索基准中功能正确性与主题相似度的混淆，现有方法因缺乏受控近克隆干扰项而无法隔离单一编辑对排序的影响。本文抓住的切入点是构建搜索池本身包含执行验证单编辑变异体的基准，使功能判别能力可被直接测量。通过植入 3,755 个受控变体并采用 exec@k 指标，EXECRETRIEVAL 证明了当前主流嵌入模型在 Rank-1 精度上的严重缺陷：最佳系统 exec@1 仅为 0.331，且 Rank-1 错误中 91.5%–99.4% 是配对错误变体。本文的边界在于仅评估函数级检索，未涉及仓库级依赖或环境配置，且未提供下游重排能完全修复 Rank-1 错误的证据。当搜索池中存在多个近克隆干扰项时，exec@10 的饱和是否意味着下游重排可完全弥补 Rank-1 缺陷，论文未给出回答。
