# HuggingFace最新推荐论文 ｜Using Grounded Theory for Agent Behavior Analysis at Scale ｜基于扎根理论的智能体行为分析

研究机构：美国普渡大学、美国史蒂文斯理工学院

作者：Zhuoran Lu、Yangyang Yu、Zhuoyan Li 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.30391)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.30391)

> 智能体在长程任务中频繁失败，但现有评估仅记录“是否成功”，无法解释“为何失败”。定量元数据缺乏过程信息，人工分析成本过高且难以扩展，预定义分类法则僵化且遗漏涌现行为。本文引入社会学中的扎根理论（Grounded Theory），构建 AutoTraceGT 流水线，通过多智能体协作自动执行开放式、轴心式与理论编码，直至理论饱和。该方法在 7,500+ 条轨迹上验证了代码本的可复现性与对人工分类法的高覆盖率，但其作为预测特征时的增益微弱，且未证明其结论能直接转化为训练信号。

## 研究背景

当智能体执行数百步的复杂任务时，早期微小的决策偏差会随步骤增加而放大，导致最终任务失败。这种错误累积现象使得仅凭最终状态无法定位失败根源，而理解失败需要分析轨迹中的具体行为模式。然而，当前主流的智能体评估体系（如 SWE-bench、WebArena）仅报告任务成功率，对失败过程保持“过程盲”（process-blind）。轻量级定量元数据（如动作计数、Token 长度）虽可扩展，但无法揭示底层推理逻辑；人工定性分析虽具解释力，但面对数千条长轨迹时成本不可承受。

领域内已出现若干失败分析工作，如 AgentErrorTaxonomy 和 MAST，它们通过人工归纳或单次 LLM 提示构建预定义分类法。这些方法存在两个核心瓶颈：一是分类法由专家预先设定，难以适应新任务中涌现的未知行为模式；二是缺乏可验证的停止准则，分析过程往往在固定迭代次数后终止，无法确认是否已覆盖所有行为结构。AutoTraceGT 的切入点在于将扎根理论这一具有“理论饱和”（Theoretical Saturation）停止准则的归纳方法论自动化，使行为分类从数据中自然涌现，而非依赖先验假设。

## 核心方法

### 方法参照系

本文问题可置于“智能体轨迹定性分析”范畴，但区别于传统的行为克隆或强化学习（RL）训练流程。标准 RL 流程为“数据→模型→奖励”，旨在优化策略；而本文流程为“轨迹→编码→理论”，旨在表征行为。关键差异在于：本文不更新模型参数，而是利用 LLM 作为定性分析工具，通过迭代编码构建可审计的行为分类法（Codebook）。

### 分层语义压缩与编码

AutoTraceGT 的核心在于将扎根理论的三个阶段映射为四个角色化智能体。OpenCode 智能体对单条轨迹进行开放式编码，输出形式为 $(code, span, quote)$ 的三元组，其中 $code$ 为 2-5 个词的概念标签，$span$ 为子步骤范围，$quote$ 为原文证据。设计动机在于解决预定义分类法无法捕捉“反馈解耦”等细粒度行为的问题。公式化地，每条轨迹 $m$ 被分割为块 $m_i$，OpenCode 在块间传递分段备忘录（segment memo）以保持分析连续性：

$$
\mathcal{R}_m = \bigcup_{i} \text{OpenCode}(m_i, \text{memo}_{i-1})
$$

该机制确保了长轨迹中行为模式的抽象一致性，避免了表面动作的简单复述。

### 代码本管理与理论饱和

轴心编码（AxialCode）将批量编码结果聚类为类别，并建立类型化关系。Manage 智能体负责跨轮次的常数比较（constant comparison），维护版本化代码本状态 $K_t = (C_t, R_t, L_t)$。对于每个新类别，Manage 从 $\{add, merge, split, flag\}$ 中选择操作，遵循“合并优先”（merge-first）策略。理论饱和被操作化为连续 $W$ 轮新增类别数 $a_t$ 小于阈值 $\epsilon$：

$$
a_t = |\{ \ell \in L_t \setminus L_{t-1} : \ell.action = add \}|, \quad \text{Saturated if } a_j < \epsilon \forall j \in \{t-W+1, \dots, t\}
$$

这一准则解决了现有方法缺乏停止标准的问题，确保代码本在概念广度上收敛，而非任意终止。

## 实验评估

实验在 ALFWorld、GAIA、WebShop、Tau-Bench、Go-Browse 和 SWE-Agent 六个数据集上进行，共 7,500+ 条轨迹。基线包括 Few-shot LLM 和 Zero-shot LLM，但缺乏传统统计元数据基线（如基于动作频率的分类器）的对比，这可能高估了行为编码的相对优势。

| 数据集 | 人工分类法类别数 | AutoTraceGT 类别数 | 召回率 (%) | 精确率 (%) | 匹配率 (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ALFWorld | 75.0 | 60.0 | 82.4 | - | - |
| GAIA | 73.7 | 63.2 | 58.0 | - | - |
| WebShop | 90.9 | 88.9 | 87.9 | - | - |

AutoTraceGT 在 WebShop 上覆盖了 90.9% 的人工失败模式，但在 GAIA 上召回率仅为 58.0%，表明其在复杂推理任务上的归纳能力存在波动。值得注意的是，AutoTraceGT 发现了人工分类法遗漏的系统性模式，如 ALFWorld 中的“不合规无动作”（noncompliant inaction），这验证了归纳方法在发现未知行为上的优势。

| 数据集 | 方法 | MCC | ROC AUC |
| :--- | :--- | :--- | :--- |
| SWE-Agent | Few-shot | 0.243 | 0.720 |
| SWE-Agent | Codebook Feature Engineering | 0.245 | - |

在失败预测任务中，基于代码本的特征工程仅比 Few-shot 基线在 MCC 上提升 0.002（0.245 vs 0.243），增益微弱。这一结果暗示，行为编码在解释性上有效，但在预测性上并未显著超越简单的 LLM 提示，可能源于代码本特征与最终失败状态之间的非线性关系未被充分捕捉。

评估协议未报告置信区间，且代码本的可复现性仅通过 Mann-Whitney U 检验（$p < 10^{-20}$）验证，缺乏对噪声数据下饱和准则鲁棒性的测试。代码已开源，但超参数（如 $\epsilon, W$）的敏感性分析未在正文中详细展开。

## 关联研究分析

从问题动机看，AutoTraceGT 与 MAST（Cemri et al., 2025）均基于扎根理论，但 MAST 依赖人工执行，仅覆盖 150+ 条轨迹，而 AutoTraceGT 实现了端到端自动化并扩展至 7,500+ 条。这一差异源于任务特性：人工分析在样本量小时可行，但无法处理大规模轨迹的多样性；AutoTraceGT 的自动化管道虽解决了规模问题，但引入了 LLM 作为编码器的潜在偏差，其归纳结果是否完全独立于后端模型先验，论文通过跨 LLM 稳定性测试（$p < 0.001$）部分回应，但未排除模型固有偏见的深层影响。

从方法设计看，AutoTraceGT 与 AgentErrorTaxonomy（Zhu et al., 2025）形成互补而非替代关系。AgentErrorTaxonomy 提供预定义分类法，AutoTraceGT 证明其遗漏了如“计划-执行解耦”等跨模块行为。然而，AutoTraceGT 的代码本作为预测特征时增益微弱，这可能表明，行为分类的粒度与失败预测所需的信号粒度不匹配。若将代码本作为过程奖励模型（PRM）的输入，能否提升 RL 训练的稳定性，论文未给出回答，这限制了其在智能体训练闭环中的直接应用价值。

## 总结

AutoTraceGT 解决了智能体失败分析中“可扩展性”与“可解释性”的矛盾，通过自动化扎根理论实现了从轨迹到理论的可审计链路。其核心贡献在于验证了理论饱和准则在大规模数据上的可行性，并发现了人工分类法遗漏的系统性行为模式（如 WebShop 上 90.9% 的覆盖率）。然而，实验显示其代码本在失败预测任务中仅比 Few-shot 基线提升 0.002 MCC，表明行为编码的预测价值有限。这一局限暴露了定性分析结论与定量预测任务之间的鸿沟：当代码本特征无法显著优于简单提示时，其作为训练信号的有效性存疑。若将代码本嵌入 RL 奖励函数，能否解决长程任务中的信用分配难题，论文未提供实证支持。
