论文原文见 [arXiv](https://arxiv.org/abs/2609.25187)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.25187)

> 具身智能体在长程操作中常因缺乏中间结构而直接映射观测到动作，导致子目标排序错误与状态追踪失效。现有视觉-语言-动作（VLA）模型多采用粗粒度任务标注或串行解码推理，无法兼顾语义可解释性与执行延迟。本文提出 X-Planner，通过构建多源层级化事件监督数据，并引入阶梯式解码机制并行生成潜在规划状态，以解耦语义理解与控制执行。该框架在真实机器人任务中取得了最高平均进度，但其离线文本质量仍略逊于最强基线，且缺乏对两种规划形态的受控对比。

## 研究背景

当智能体执行“将衣物放入篮子”这类长程指令时，视觉-语言-动作（Vision-Language-Action, VLA）模型通常直接输出低层控制指令，忽略了中间的任务分解结构。这种直接映射范式在短程技能中有效，但在长程任务中，智能体需先选择并排序接地的子目标，再发出命令。由于许多 VLA 模型将这一中间结构隐式化，导致高层意图与低层控制之间的桥梁断裂，这不仅是多模态表征问题，更是规划问题。

主流路线试图通过引入思维链（Chain-of-Thought, CoT）推理来弥补这一缺陷，但存在三个关键瓶颈。数据层面，现有训练数据多使用任务级描述或手写子目标列表，缺乏对事件边界（如重新抓取、接触失败）的精细标注，导致监督信号模糊。粒度层面，推理规划器往往锁定单一外部强加的粒度，如固定语义层级或子目标图像预测，无法适应行为变化引发的动态边界。延迟层面，传统 CoT 规划器逐 token 自回归解码，长序列推理中重复处理重叠的视觉-语言上下文，造成串行依赖延迟，且长显式轨迹易发生误差传播。X-Planner 针对这三重缺口，将语义事件作为规划单元，结合离散与潜在双模态接口，实现从指令到可执行行为的可靠映射。

## 核心方法

### 方法参照系

本文问题属于具身智能中的任务规划前端，区别于经典的神经符号集成范式（如 PDDL 形式化生成）。标准流程通常将自然语言转换为形式化规划语言，再由符号规划器求解。本文的关键差异在于未使用刚性符号系统，而是以“语义事件”作为中间表示，通过视觉-语言模型（VLM）直接生成事件结构化的表征，条件化下游世界-动作模型，从而在保持语义灵活性的同时避免符号转换的语义遗漏。

### 层级化事件监督与失败感知

传统具身规划数据仅包含任务级标签，无法捕捉演示内部的执行错误与事件边界。X-Planner 构建了包含 Ego、UMI 和遥操作数据的层级化监督体系，定义 L3 任务、L2 子任务、L1 动作、L0 片段四级结构。其中，遥操作数据支持全四级标注，而 Ego 和 UMI 因运动速度快仅保留 L1-L3。为监督执行中的错误识别，论文标注了接管时间（takeover times），并补充人工设计的失败演示，以覆盖单一策略的失败分布偏差。这种设计使得规划器不仅能生成初始计划，还能在滚动执行中追踪当前/下一事件、归一化进度及识别错误。

### 阶梯式解码与潜在规划

自回归潜在推理（如 Coconut）虽压缩了中间思考，但仍保留潜在步骤间的串行依赖。X-Planner 提出阶梯式解码（Staircase Decoding），将 Transformer 在继电器深度 $N_r$ 处分割。下层编码共享的视觉-语言上下文，上层针对推理步骤特化。第一个潜在位置遍历下层生成共享的继电器表征，上层块则并行更新潜在状态，每个位置拥有独立的因果缓存。潜在状态序列 $\hat{y}_{1:K_c}$ 通过前缀投影器 $P_{pref}$ 映射至冻结轻量语言模型的嵌入空间，并重建文本 CoT 轨迹：

$$
\mathcal{L}_{CoT} = - \sum_{m=1}^{M_r} \log P_{\phi}(r_m | z_{1:K_c}, r_{<m})
$$

该公式的物理含义是：通过最大化潜在状态 $z_{1:K_c}$ 条件下重建文本轨迹 $r_m$ 的对数似然，迫使紧凑的潜在状态保留高层事件语义，同时避免复制特定的 token 级隐藏轨迹。这种深度并行调度缩短了串行关键路径，使潜在规划状态共享下层接地计算，从而在保持语义锚定的同时降低解码延迟。

## 实验评估

实验在桌面双臂机器人上进行，使用同步多视角观测。主要指标为任务进度（Task Progress），一个 0-100 的密集评分，根据任务特定评分标准给予部分完成信用。基线包括 U-Scratch（从头训练的固定长度指令-动作系统）、$\pi_{0.5}$、DreamZero 和 LingBot-VA。X-Planner 在推理操作套件中平均任务进度为 71.60%，高于最强基线 U-Scratch 的 59.50%；在泛化套件中为 53.75%，高于 DreamZero 的 28.50%。

| 套件 | 模型 | 平均任务进度 (%) |
| :--- | :--- | :--- |
| 推理操作 | X-Planner (event) | 71.60 |
| 推理操作 | U-Scratch | 59.50 |
| 推理操作 | $\pi_{0.5}$ | 56.40 |
| 推理操作 | DreamZero | 32.70 |
| 推理操作 | LingBot-VA | 31.60 |
| 泛化 | X-Planner (event) | 53.75 |
| 泛化 | DreamZero | 28.50 |
| 泛化 | $\pi_{0.5}$ | 24.00 |
| 泛化 | U-Scratch | 18.50 |

离线两步规划评估中，X-Planner 在 BERTScore-F1 和整体评分上均排名第二，仅次于 kimi3。其 BERTScore-F1 为 0.9011，高于 Qwen (0.8878) 和 Doubao (0.8846)，但低于 kimi3 (0.9108)。整体评分为 1.411，同样低于 kimi3 (1.434)。这表明 X-Planner 在语义匹配和计划质量上优于 Qwen 和 Doubao，但在离线文本生成上未超越最强基线。

评估边界方面，论文未报告试验级分数或不确定性统计，图表仅展示报告均值，无法进行方差或显著性分析。代码已开源，但超参数与 GPU 配置未在摘要中详述。此外，论文未提供离散事件模式与潜在统一模式的受控对比，两种规划形态的性能差异尚不明确。

## 关联研究分析

从问题动机看，X-Planner 与 Planner-in-the-Loop 均关注规划可靠性，但路径截然不同。Planner-in-the-Loop 依赖外部符号规划器（如 Fast Downward）提供诊断信号进行定向修复，强调逻辑可验证性；而 X-Planner 通过内部事件结构化监督与潜在状态重建，在 VLM 内部实现语义锚定，未引入外部符号验证器。这种差异源于任务特性：具身操作任务对实时性要求高，外部规划器的计算延迟可能不可接受，而 X-Planner 的阶梯式解码旨在降低内部串行延迟。然而，缺乏外部符号验证器是否足以保证复杂约束下的逻辑一致性，论文未给出回答。

从方法设计看，X-Planner 借鉴了 Coconut 的潜在推理思想，但解决了其串行依赖问题。Coconut 将中间思考压缩为连续表征，但潜在步骤间仍自回归依赖；X-Planner 通过阶梯式解码实现深度并行，使潜在状态共享下层计算。与 CoT-VLA 相比，后者预测子目标图像或光流，侧重空间特异性；X-Planner 采用语义事件作为规划单元，侧重语言可解释性与控制可实现性的平衡。这种设计选择使得 X-Planner 在泛化套件中显著优于 DreamZero，但其在离线文本质量上未超越 kimi3，暗示潜在状态在语义精确性上可能仍存在损失。

## 总结

X-Planner 旨在解决具身智能中长程任务规划中数据粒度粗、推理延迟高及中间结构隐式化的矛盾。其切入点在于将语义事件作为规划单元，并通过阶梯式解码并行化潜在推理，从而在保持语义锚定的同时降低串行延迟。实验证明，该框架在真实机器人推理操作与泛化任务中取得了最高平均任务进度（71.60% 与 53.75%），优于现有 VLA 基线。然而，其离线文本质量仍落后于 kimi3，且未提供离散与潜在两种规划形态的受控对比，暴露出潜在状态在语义精确性与执行效率之间的权衡边界。当潜在状态序列长度增加时，阶梯式解码的并行收益是否会被误差累积抵消，论文未给出回答。
