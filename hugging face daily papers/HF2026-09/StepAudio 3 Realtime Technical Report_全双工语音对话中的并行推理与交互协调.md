# HuggingFace最新推荐论文 ｜StepAudio 3 Realtime Technical Report ｜全双工语音对话中的并行推理与交互协调

作者：Bin Lin、Bo Zhao、Boyang Zhang 等 90 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.14005)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.14005)

> 全双工语音对话系统（Full-Duplex Spoken Dialogue Systems, FD-SDS）需解决的核心矛盾是：模型在生成语音响应的同时，必须处理用户的新输入并执行复杂的逻辑推理，而传统串行架构无法兼顾响应延迟与思考深度。现有端到端模型虽实现了监听与生成的并行，但推理过程往往阻塞语音流，或依赖外部模块进行轮替判断，导致交互僵硬。本文提出“边说边想”（Think-While-Speaking）机制，通过自适应思考路由与多令牌预测，将私有推理与语音生成解耦。该方案在交互动态上达到SOTA水平，但在多轮约束遵循与零售工具调用上仍显不足。

## 研究背景

当用户在全双工对话中插入停顿或简短反馈时，系统需区分这是语义完整的结束信号，还是等待补充的中间状态。这一判断依赖声学时序与语义完整性的联合建模，即轮替预测（Turn-Taking）。若仅依赖静音阈值，系统易在用户思考时误响应；若依赖完整语义解析，则引入不可接受的延迟。此外，复杂请求要求模型在说话的同时进行深度推理，传统链式思考（Chain-of-Thought, CoT）需等待输入完整，导致“思考-说话”冲突。

全双工交互的演进从级联架构转向原生端到端模型，如Moshi确立了双通道流式生成范式。然而，现有端到端模型在推理与生成的资源竞争上存在瓶颈：显式思考增加序列长度从而增加延迟，而潜在推理虽快但缺乏复杂逻辑的连贯性。领域共识认为端到端优于级联，但如何在毫秒级约束下实现“深度思考”与“即时响应”的平衡，仍是精细化阶段的核心难题。本文切入点在于将推理过程从语音生成流中剥离，使其作为并行后台任务运行，并通过动态路由决定何时启用显式推理。

## 核心方法

### 双流状态交错架构

全双工建模的标准流程是将用户与系统音频流并行输入编码器，生成统一表示。本文的关键差异在于引入时间交错的状态令牌（State Token）。音频被切分为320ms块，每块后跟随一个状态或文本令牌，形成序列化输入。这种设计将交互状态（如轮替、重叠）显式编码进模型上下文，而非依赖外部VAD模块。

### 边说边想与自适应思考

传统方法中，推理与生成共享同一解码路径，导致推理未完成时无法开始说话。本文提出Think-While-Speaking机制，允许语音生成先于完整推理完成。其核心是Adaptive Thinking路由，动态决定当前轮次是否启用显式推理。

$$
\text{Route}(t) = \begin{cases} \text{Direct} & \text{if } P(\text{need\_think} | X_u, X_s, H_t) < \tau \\ \text{Deliberate} & \text{otherwise} \end{cases}
$$

该公式表示，基于用户音频 $X_u$、系统音频 $X_s$ 及历史 $H_t$，模型预测是否需要显式思考。若概率低于阈值 $\tau$，则直接响应；否则进入深思路径。这一设计解决了固定思考长度导致的延迟问题，使简单查询无需等待推理，复杂查询则获得深度处理。

### 多令牌预测加速

对于启用显式推理的轮次，本文采用多令牌预测（Multi-Token Prediction, MTP）加速私有思考流。MTP3配置下，每个目标模型步骤同时预测3个未来令牌。

$$
\mathcal{L}_{\text{MTP}} = \sum_{k=1}^{K} \mathcal{L}_{\text{CE}}(y_t, \hat{y}_{t+k})
$$

其中 $K$ 为预测头数量，$\mathcal{L}_{\text{CE}}$ 为交叉熵损失。该机制通过投机解码减少串行步骤，在保持推理质量的同时降低解码延迟。实验显示，MTP5在典型接受率下每步接受2.153个草稿令牌，相比基线实现1.72倍墙钟加速。

## 实验评估

实验覆盖音频理解、对话推理、全双工交互及代理任务四大领域。基线包括GPT-Realtime-2.1、Gemini 3.1 Pro、Qwen Audio 3.0等闭源SOTA，但缺失开源Moshi的直接对比，限制了与开源生态的公平比较。

| 基准 | StepAudio 3 Realtime | Gemini 3.1 Pro | GPT-Realtime-2.1 |
| :--- | :--- | :--- | :--- |
| MMSU | 90.6 | 83.6 | - |
| MMAR | 86.5 | 81.7 | - |
| AA Full-Duplex Bench | 98.9 | - | 95.3 |
| τ-Voice | 56.0 | - | 45.7 |

StepAudio 3 Realtime在MMSU和MMAR上分别领先Gemini 3.1 Pro 7.0和4.8分，表明其在音频接地推理上的优势。在AA Full-Duplex Bench上，其Overall得分98.9高于GPT-Realtime-2.1的95.3，其中轮替得分100.0，中断处理99.0，验证了Seamless Duplex模块的有效性。然而，在AudioMultiChallenge上，其得分49.3落后Gemini 3.1 Pro的67.0达17.7分，暴露出多轮约束遵循的短板。

消融实验显示，数据质量优于数量：仅用10万高质量样本（约为200万随机样本的1/20），MMSU从78.78提升至89.70，MMAR从74.70提升至84.50。Adaptive Thinking在Reasoning类别上，全思考模式比强制无思考模式高11.37分，但思考率仅59.5%，说明路由策略未能将思考资源最优分配给最受益的轮次。MTP5相比MTP3，每步接受令牌数从1.801增至2.153，但第4、5头的严格边际接受率降至10.7%和5.7%，显示深层预测的边际收益递减。

评估协议存在局限：Full-Duplex-Bench采用0-100分制，与知识库中部分基准的F1或Pass@1指标不可直接比较。论文未提供代码与超参数细节，且未报告置信区间，限制了结果的可复现性与统计显著性验证。

## 关联研究分析

从问题动机看，本文与BayLing-Duplex同属原生端到端路线，但解决焦点不同。BayLing-Duplex通过DPO优化时序决策，侧重轮替自然度；本文则通过Think-While-Speaking解决推理与生成的资源竞争。这一差异源于任务特性：BayLing假设推理可被压缩或省略，而本文承认复杂请求需深度推理，故需并行机制。Chronological Thinking通过生成内部思考令牌模拟认知，但增加序列长度；本文的Adaptive Thinking通过动态路由避免不必要的思考，更契合实时性约束。

从方法设计看，本文与Moshi的双通道架构一致，但引入了状态令牌交错。Moshi依赖纯音频令牌，而本文的320ms块+状态令牌设计将交互状态显式化。这一选择可能牺牲了音频细粒度感知，因为状态令牌占据了序列空间。与DuplexSLA相比，后者将动作与语音同步序列化，侧重具身交互；本文则聚焦语音对话中的工具调用，通过异步执行保持对话流。这种差异反映了全双工系统从“对话”向“代理”扩展的不同路径。

## 总结

StepAudio 3 Realtime旨在解决全双工语音对话中推理深度与响应延迟的矛盾。现有端到端模型因推理阻塞语音流或依赖外部轮替判断，无法兼顾两者。本文通过Think-While-Speaking机制，将私有推理与语音生成解耦，并利用Adaptive Thinking动态路由思考资源。实验表明，其在MMSU上达90.6分，AA Full-Duplex Bench Overall达98.9分，验证了并行推理的有效性。然而，其在AudioMultiChallenge上落后Gemini 3.1 Pro 17.7分，且Adaptive Thinking在Reasoning类别的思考率仅59.5%，显示路由策略未能精准匹配思考需求。当用户请求涉及多轮约束更新时，自适应思考是否足以维持语义一致性，论文未给出回答。
