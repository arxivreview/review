# HuggingFace最新推荐论文 ｜SimpleMemVLA: A Simple but Effective Native-Video Memory for Vision-Language-Action Models ｜原生视频上下文作为视觉-语言-动作模型记忆

研究机构：中国人民大学、清华大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.05533)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.05533)

> 长时程操作中的部分可观测性要求策略依赖分钟级历史，但现有专用记忆机制在写入时即丢失未来决策所需的关键证据。本文指出，现代视觉-语言模型骨干的原生上下文窗口已足以容纳分钟级视频流，无需额外压缩或检索。SimpleMemVLA 直接以带时间戳的视频流作为输入，利用骨干自注意力在决策时动态检索历史，并通过共享前缀预填充维持实时性。该方法在记忆基准上大幅超越专用机制，但在通用控制任务上仅持平，其优势是否源于骨干能力而非记忆接口本身，仍需更严格的归因验证。

## 研究背景

当机器人执行“将方块从垫子A移至垫子B”这类任务时，当前帧可能仅显示方块已离开垫子A，而“垫子A是哪一个”这一关键信息仅存在于数秒前的观测中。这种当前观测无法唯一确定动作的状态称为部分可观测性（Partial Observability, PO）。在PO环境下，反应式策略 $\pi(a_t | o_t, l)$ 是病态的，因为两个当前观测相同但历史不同的状态可能要求截然不同的动作。策略必须显式依赖历史 $h_{t-1}$，即 $a_t \sim \pi(a_t | o_t, h_{t-1}, l)$。

传统VLA模型多依赖单帧或亚秒级窗口，无法解决PO问题。现有解决方案包括检索库、学习压缩器和循环状态，它们均在写入历史时决定保留哪些信息。然而，这种“写入时承诺”（Write-time Commitment）导致未来决策所需的关键证据可能在写入阶段被丢弃。随着VLM骨干上下文窗口扩大至262k tokens，60秒历史仅占5.6k tokens，上下文容量不再构成瓶颈。本文切入点在于：既然历史可以完整保留，是否还需要专用记忆机制？

## 核心方法

### 方法参照系

标准VLA记忆流程在观测流与策略之间插入中间接口（如检索索引或压缩表示），策略通过该接口访问历史。本文的关键差异在于移除该接口，将带时间戳的原始视频流直接作为骨干输入，利用原生自注意力在决策时动态选择相关历史。

### 原生视频上下文作为记忆

专用记忆机制在写入时决定保留内容，而本文在读取时决定使用内容。具体而言，策略将采样历史 $h_t = (o_{\le t}, l)$ 以时间戳视频格式输入骨干，骨干生成当前子任务 $g_t$。子任务的隐藏状态与嵌入构成历史到达流匹配动作头的唯一通道：

$$
a_t \sim \pi_{\text{flow}}(a_t | \text{hidden}(g_t), \text{embed}(g_t))
$$

此设计避免了写入时的信息丢失，允许骨干在任务条件注意力下动态检索特定历史帧。相比检索机制（仅暴露8帧无序图像）或压缩机制（固定64 token预算），原生上下文保留了完整感知细节与时间结构，解决了专用机制在计数、永久性任务上的性能瓶颈。

### 共享前缀预填充推理

连续决策间视觉历史高度重叠，仅新增一个时间补丁。本文在机器人执行当前动作块期间，预填充共享历史前缀，并在下一决策时复用。该机制将决策延迟从1.02秒降至0.68秒，接近单帧VLA，同时保持输出与全量重计算一致。此设计解决了长上下文推理的计算开销问题，使分钟级记忆在实时控制中可行。

## 实验评估

实验在RMBench、RoboMME、MIKASA-Robo、RoboMemArena四个记忆基准及LIBERO、LIBERO-Plus两个通用基准上进行。基线覆盖检索（MemER）、压缩（TokenDrop）、循环（Recurrent）三类机制，但缺失符号存储类基线。

| 基准 | 方法 | 成功率 (%) |
|---|---|---|
| RoboMME | SimpleMemVLA | 88.3 |
| RoboMME | GroundSG (GT) | 84.1 |
| RoboMME | MemoryVLA | 41.2 |
| RMBench | SimpleMemVLA | 94.0 |
| RMBench | MemoryWAM | 83.0 |
| MIKASA-Robo | SimpleMemVLA | 74.0 |
| MIKASA-Robo | GMP | 67.8 |
| LIBERO | SimpleMemVLA | 97.5 |
| LIBERO | RIPT-VLA | 97.5 |

SimpleMemVLA在RoboMME上达88.3%，高于GroundSG（84.1%）4.2个百分点，且在所有16个任务上排名第一。在RMBench上，其94.0%的成绩显著高于MemoryWAM（83.0%）。在LIBERO通用任务上，其97.5%与RIPT-VLA持平，表明长历史未损害通用控制性能。

消融实验显示，原生上下文（88.3%）远超检索（31.5%）、压缩（22.6%）和循环（20.6%）变体，即使使用相同骨干和训练设置。因果干预实验证实，掩蔽任务相关历史帧会改变输出，而掩蔽无关片段则无影响，证明策略确实读取历史。

评估边界方面，所有结果基于闭环评估，种子集与训练数据分离。代码已开源，但论文未报告显存占用与推理延迟的完整分布，仅给出平均延迟0.68秒。LIBERO成绩低于SimpleVLA-RL（99.1%），可能因缺乏强化学习后训练，但本文未进行此对比。

## 关联研究分析

从问题动机看，HAMLET通过插件式历史帧注意力解决长时程状态遗忘，但本文证明原生上下文更优。HAMLET需额外训练注意力模块，而本文仅依赖骨干预训练能力。差异根源在于：HAMLET假设历史需显式建模，而本文假设骨干已具备视频理解能力。若骨干视频预训练不足，原生上下文是否仍优于HAMLET，论文未给出回答。

从方法设计看，π0使用流匹配动作头但仅输入单帧，本文将其输入扩展为长视频流。π0的流匹配头在单帧下表现优异，但在PO任务中因缺乏历史而失效。本文通过子任务 $g_t$ 桥接历史与动作，解决了π0在长时程任务中的误差累积问题。这一设计是否适用于非流匹配动作头（如离散Token），论文未探索。

## 总结

本文核心矛盾在于专用记忆机制的写入时承诺导致关键证据丢失，而现代VLM骨干的原生上下文容量已足以容纳分钟级历史。SimpleMemVLA通过直接输入带时间戳视频流，利用骨干自注意力在决策时动态检索历史，避免了写入时信息丢失。实验证明其在RoboMME上达88.3%，高于GroundSG（84.1%），且在LIBERO通用任务上持平SOTA。其边界在于：优势可能部分源于骨干能力而非记忆接口本身，且未验证在历史超出45分钟上下文窗口时的性能衰减。当历史长度超过骨干上下文窗口时，原生上下文与轻量压缩策略的结合方式，论文未给出回答。
