# HuggingFace最新推荐论文 ｜T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks ｜长程终端智能体强化学习：T1 的稳定性与密集奖励机制

研究机构：新加坡国立大学、美国佐治亚大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.11042)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.11042)

> 长程终端智能体训练面临的核心矛盾是：稀疏的二元执行结果无法提供足够的梯度信号，而大规模混合专家模型（Mixture-of-Experts, MoE）在推理与训练栈间的数值差异会导致策略梯度失效。现有基于组相对策略优化（Group Relative Policy Optimization, GRPO）的去 Critic 范式在长程多轮交互中因优势坍缩而失效，且未解决 MoE 路由不一致问题。本文通过引入 TITO 与 R3 机制校正训练-推理一致性，并采用断言级密集奖励替代二元结果，实现了 122B 参数模型在终端任务上的稳定强化学习。该方案在 Terminal-Bench 2.1 上取得 64.0% 的解决率，但其对 Critic 网络的依赖及特定 Harness 下的性能表现，使其在通用泛化性上仍存疑。

## 研究背景

长程终端任务要求模型在状态化环境中执行不可逆操作，其验证依赖于代码执行而非偏好标注。这一特性导致传统基于人类反馈的强化学习（RLHF）范式失效，转而依赖可验证奖励强化学习（Reinforcement Learning with Verifiable Rewards, RLVR）。然而，RLVR 在长程任务中面临两个独特挑战：一是二元结果奖励导致单轨迹仅产生 1 比特信号，引发优势坍缩；二是 MoE 模型中，推理与训练栈的数值差异会翻转专家路由选择，使得策略梯度更新指向错误的参数子集。

主流 GRPO 变体通过消除 Critic 网络降低计算开销，但在长程多轮交互中，组内轨迹往往获得相同奖励导致相对优势为零，梯度更新消失。此外，GRPO 假设推理与训练栈完全一致，这在 MoE 模型中不成立，因为离散 Top-K 路由对数值差异极度敏感。本文的切入点在于同时解决这两个问题：通过 TITO 和 R3 机制确保策略梯度的有效性，并通过密集验证奖励恢复组内方差，从而在保留 PPO 框架的同时实现大规模 MoE 智能体的稳定训练。

## 核心方法

### 方法参照系

本文基于 PPO 框架，但针对 MoE 长程智能体场景进行了关键改造。与 GRPO 去 Critic 路线不同，本文保留 Critic 网络以支持密集奖励的价值估计，并新增 MoE 一致性校正模块。关键差异在于：GRPO 依赖组内相对奖励，而本文依赖执行断言的绝对数量，且必须解决推理-训练栈的数值偏差。

### TITO: Token-In-Token-Out

TITO 机制解决了多轮交互中 Token 序列不一致的问题。通常做法是训练时重新渲染历史，但这会导致解析规范化或模板重分词引入偏差。本文要求训练器直接消费采样器输出的 Token 标识符，并在回合边界进行漂移修复。其物理含义是确保策略梯度中的分母 $\pi_{t-1}$ 与采样器实际生成的分布完全一致。设计动机在于，多轮工具调用中，回合边界的 Token 序列扰动会累积，导致训练器条件于采样器从未产生的流，从而使重要性采样比率 $r_j(\theta) = \frac{\pi_t}{\pi_{t-1}}$ 失效。

### R3: Rollout Routing Replay

R3 机制解决了 MoE 模型中专家路由不一致的问题。通常做法是训练时重新计算路由掩码，但不同栈的核函数差异会导致 Top-K 选择翻转。本文在生成时记录每个 Token 在每个 MoE 层的路由掩码 $I^r_{\ell,j}$，并在训练前向传播中重放这些掩码。其物理含义是强制训练器使用与采样器相同的专家子网络，确保策略 $\pi_\theta(\cdot | T_{<j}, I_j)$ 的一致性。设计动机在于，MoE 中 95.5% 的参数由专家持有，路由掩码决定了激活的子网络，数值差异虽微小但足以交换专家，导致比率关联两个不同的网络而非同一网络的两个版本。

$$
I^r_{\ell,j} = \text{TopK}_k(s^r_{\ell,j}), \quad y_{\ell,j} = \sum_{e \in I^r_{\ell,j}} f_e(h_{\ell,j})
$$

该公式表明，路由掩码 $I^r_{\ell,j}$ 是采样器计算的专家选择，训练器必须重放此掩码以计算价值函数，而非重新计算。

## 实验评估

实验在 Terminal-Bench 2.1（89 个保留任务）和 Long-Horizon Terminal Bench（LHTB）上进行，使用 Harbor/Terminus-2 Harness。基线对比涵盖 GPT-5.4、DeepSeek-V4-Flash、Claude Opus 4.6 等前沿模型，但缺失 GRPO 变体基线，因任务特性（长程多轮、MoE）使得 GRPO 难以直接应用。

| 模型 | 大小 (总-激活) | Terminal-Bench 2.1 (%) | LHTB (平均奖励) |
| :--- | :--- | :--- | :--- |
| T1 | 122B-A10B | 64.0 | 27.9 |
| Claude Opus 4.7 | / | 66.1 | – |
| DeepSeek V4 Flash (high) | 295B-A21B | 56.9 | – |
| GPT-5.4 | / | 54.8 | 27.2 |
| Qwen3.5-122B-A10B (base) | 122B-A10B | 43.8 | 18.9 |
| RST-SFT Model | 122B-A10B | 49.4 | 23.6 |

T1 在 Terminal-Bench 2.1 上达到 64.0%，较 SFT 基线提升 14.6 个百分点，较基础模型提升 20.2 个百分点。在 LHTB 上，T1 达到 27.9，超过 GPT-5.4 的 27.2。消融实验显示，二元奖励在 TMax-15k 上仅将基础模型从 43.8% 提升至 47.2%，未超过 SFT 基线，验证了密集奖励的必要性。TITO 和 R3 将训练-推理对数概率差从 0.021 降至 0.013，且 Token 漂移率为 0.0000%。

评估边界方面，论文未提供代码 URL，且性能高度依赖特定 Harness（Terminus-2）。论文承认 Harness 选择会显著影响数值，例如 Claude Opus 4.6 在 Claude Code 下得分为 70.1，而在 Terminus-2 下为 63.8。此外，训练数据 T1-15k 与评估集完全分布外，确保了泛化性，但缺乏跨 Harness 的鲁棒性测试。

## 关联研究分析

从问题动机看，本文与 SSVPO 等步骤级信用分配方法均旨在解决稀疏奖励问题，但 SSVPO 依赖步骤分割，而本文依赖执行断言。SSVPO 在 AIME25 上达到 82.0%，但其在长程多轮交互中未验证，且未解决 MoE 路由不一致问题。本文的密集奖励设计更适用于可执行验证的任务，而 SSVPO 更适用于文本推理。差异根源在于任务特性：终端任务具有明确的执行验证器，而数学推理依赖逻辑正确性，断言级奖励在后者中难以定义。

从方法设计看，本文与 DAPO 等 GRPO 变体均关注训练稳定性，但 DAPO 通过解耦裁剪和动态采样缓解梯度消失，而本文通过 TITO/R3 解决 MoE 一致性。DAPO 假设推理-训练栈一致，这在 MoE 中不成立。本文保留 Critic 网络，而 DAPO 去 Critic，这是因为密集奖励需要价值估计来归因断言级信号，而 GRPO 的组内相对奖励无法处理长程多轮中的优势坍缩。这种设计选择暗示，在 MoE 长程智能体中，Critic 网络的计算开销是必要的代价，以换取更精准的信用分配。

## 总结

本文要解决的核心矛盾是 MoE 长程智能体在稀疏奖励下的训练不稳定与策略梯度失效。现有 GRPO 变体因优势坍缩和路由不一致而无法应用，本文通过 TITO/R3 机制校正训练-推理一致性，并采用断言级密集奖励恢复梯度信号。实验证明，该方案在 Terminal-Bench 2.1 上达到 64.0%，较 SFT 基线提升 14.6 个百分点，且在 LHTB 上超过 GPT-5.4。本文的边界在于性能高度依赖特定 Harness，且未验证跨 Harness 的鲁棒性。当训练数据与评估集分布外时，密集奖励的泛化能力是否依赖于验证器的质量，论文未给出回答。
