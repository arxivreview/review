# HuggingFace最新推荐论文 ｜Token-Efficient Data Reasoning Agents via Adaptive Structuring of Unstructured Data ｜代理数据裂解

研究机构：美国哈佛大学

作者：Milad Rezaei Hajidehi、Qitong Wang、Stratos Idreos

论文原文见 [arXiv](https://arxiv.org/abs/2608.31082)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.31082)

> 非结构化数据推理面临高昂的Token消耗瓶颈，传统检索增强生成（RAG）无法处理多步依赖，而纯代理推理虽准确但成本极高。本文切入点在于利用查询间的语义局部性，将推理过程中的文档加载转化为可复用的结构化资产。通过引入“代理数据裂解”机制，在代理打开文档时并行提取潜在结构，使后续查询直接读取结构化数据而非重新加载文档。该方案在保持准确率不显著下降的前提下大幅降低了推理成本，但其效果高度依赖查询间的实体重叠度，对孤立查询的增益有限。

## 研究背景

数据推理任务要求智能体从分散的非结构化文档中提取事实，构建中间状态并执行多步逻辑推导。这一过程本质上是Prefill密集型：智能体需反复将大文档加载至上下文以恢复散落证据，而最终答案往往简短。以FanOutQA基准为例，单个问题可消耗高达一百万Token，成本接近一美元。这种成本结构限制了代理推理在大规模企业场景中的可扩展性，因为真实工作流中问题往往涉及数百个文档的扇出（Fan-out）。

现有解决方案存在两极分化。固定Top-K检索（RAG）成本低但无法处理多跳依赖，准确率远低于代理系统；纯代理推理（Agentic Reasoning）通过规划、搜索和代码执行实现高准确率，但每次查询都重复支付文档Prefill成本。数据库领域的“数据裂解”（Data Cracking）技术通过查询驱动的方式自适应地重组关系结构，但传统裂解仅适用于已结构化的关系数据，无法直接应用于非结构化文本。本文的核心切入点是：非结构化文档中蕴含的实体、属性和关系结构，可以通过代理的语义理解能力在推理过程中被“裂解”出来，并作为可复用资产存储，从而将后续查询的成本从文档Prefill转移至低成本的Decode。

## 核心方法

### 方法参照系

本文问题属于“结构化编排”与“数据工程”的交叉领域，但关键差异在于处理对象。标准数据工程流程假设输入为半结构化或结构化数据，通过ETL管道清洗转换；而本文处理的是完全非结构化的文本（如网页、PDF），且结构本身是未知的、随查询动态显现的。因此，不能套用固定的Schema或预定义提取规则，必须依赖代理的语义推理能力在运行时动态发现并固化结构。

### 裂纹对象数据模型

裂纹对象（Cracked Object）是本文的核心数据结构，用于表示从非结构化文档中提取的、带有证据背书的语义关系。每个裂纹对象被建模为扩展的RDF风格边，包含主体、关系、客体、基数、单位和证据。

$$ c = \langle s, r, o, \kappa, u, \epsilon \rangle \in C, \quad s \in E, r \in R, o \in E \cup V $$

其中 $E$ 和 $R$ 是由裂解子代理填充的开放域，$V$ 是带类型标签的标量值（字符串、整数、日期）。$\kappa \in \{singular, list\}$ 区分单值关系与集合关系，$\epsilon = \langle d, \rho \rangle$ 记录源文档 $d$ 及支持该事实的具体区域 $\rho$。这一设计动机在于解决传统知识图谱构建中“Schema预定义”的局限：通过开放域 $E$ 和 $R$，系统无需预先知道文档中可能包含哪些实体或关系，而是由代理在读取文档时动态发现并记录，同时通过证据 $\epsilon$ 确保每个提取的事实可追溯、可验证，避免了幻觉。

### 自适应裂解与KV-Cache复用

裂解过程发生在代理打开文档以回答当前查询时。系统从已加载的上下文中分叉出一个裂解子代理（Cracking Sub-Agent），该子代理利用共享前缀的KV-Cache，仅执行有界的Decode操作来提取结构。

$$ Cost_{cracking} \approx Cost_{decode} \ll Cost_{prefill} $$

这一设计解决了“全量提取不可行”的困境。由于文档包含的实体和关系远超任何单一工作负载所需，全量提取会导致无界的Decode成本。裂解子代理仅在当前查询的语义引导下，推测可能服务于未来相关查询的邻近结构（如当前查询提取NBA球员的得分，裂解子代理同时提取篮板数据）。由于Prefill成本已由主代理支付，裂解的边际成本极低（仅Decode Token），且裂解分支与主回答路径并行执行，不阻塞当前查询。这种“查询驱动”的自适应机制确保了提取的结构是“有用”的，而非冗余的，从而在成本与效用之间取得平衡。

## 实验评估

实验基于FanOutQA基准和一个电影案例研究，使用Claude-Haiku-4.5模型。基线包括纯代理推理（Baseline）和固定Top-K RAG。本文方法（Adc）在FanOutQA上平均成本从$0.26降至$0.12，案例研究中从$0.81降至$0.27。准确率方面，LLM-as-Judge评分从43%降至42%（p=0.39，无显著差异），字符串匹配准确率下降2点。

| 指标 | Baseline (FanOutQA) | Adc (FanOutQA) | Baseline (Case Study) | Adc (Case Study) |
| :--- | :--- | :--- | :--- | :--- |
| 平均成本 (USD) | $0.26 | $0.12 | $0.81 | $0.27 |
| 平均Prefill Tokens | 189K | 87K | 565K | 161K |
| LLM-Judge Accuracy | 43% | 42% | - | - |
| 中位数成本 (USD) | $0.246 | $0.072 | - | - |

成本分布显示，裂解在75%的查询上带来收益，第10百分位成本降低9倍，但第90百分位成本增加1.24倍（无复用查询）。裂解开销为每查询12%（4K Token预算），产生约150个裂纹对象。

评估边界方面，实验仅使用单一模型（Claude-Haiku-4.5），未验证跨模型迁移性；FanOutQA的查询间局部性是通过人工生成相关查询模拟的，未反映真实用户行为的动态性；代码未公开，裂解子代理的具体提示词和验证算法细节缺失，限制了可复现性。

## 关联研究分析

从问题动机看，本文与Tree-Notebook等结构化编排方法存在根本差异。Tree-Notebook聚焦于解决长上下文中的状态不可见和静默失败，通过树搜索和熵感知数据影子提升推理的鲁棒性；而本文聚焦于成本效率，通过结构复用降低Token消耗。Tree-Notebook的“数据影子”是临时的、用于当前推理的状态表示，而本文的“裂纹对象”是持久的、跨查询复用的结构资产。这一差异源于任务特性：Tree-Notebook处理的是单次复杂推理任务，而本文处理的是工作负载级别的查询序列。

从方法设计看，本文与RAG（Retrieval-Augmented Generation）形成互补而非替代。RAG通过向量检索获取相关片段，但无法处理多步依赖和实体关系构建；本文通过裂解构建显式的实体-关系结构，使后续查询可直接通过结构化读取（类似SQL）获取答案，避免了向量检索的模糊性和文档加载的高成本。然而，本文的裂解机制依赖于查询间的语义局部性，对于实体重叠度低的孤立查询，裂解产生的结构可能无法被复用，导致成本增加。这种对局部性的依赖是RAG所不具备的，也是本文方法的主要局限。

## 总结

本文解决的核心矛盾是非结构化数据推理的高准确率与高成本之间的权衡。现有方法要么牺牲准确率（RAG），要么牺牲成本（纯代理推理），而本文通过利用查询间的语义局部性，将推理过程中的文档加载转化为可复用的结构化资产，实现了成本与准确率的双赢。实验证明，在FanOutQA上，裂解方法将平均成本降低53%，同时保持准确率不显著下降。然而，本文的边界在于其效果高度依赖查询间的实体重叠度，对于孤立查询或实体分散的工作负载，裂解可能带来负收益。当工作负载中的查询实体重叠度低于某一阈值时，裂解的边际收益是否仍为正，论文未给出回答。
