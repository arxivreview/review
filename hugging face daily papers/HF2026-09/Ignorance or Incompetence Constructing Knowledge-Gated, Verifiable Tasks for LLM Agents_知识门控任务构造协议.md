# HuggingFace最新推荐论文 ｜Ignorance or Incompetence? Constructing Knowledge-Gated, Verifiable Tasks for LLM Agents ｜知识门控任务构造协议

研究机构：新加坡南洋理工大学、北京大学

论文原文见 [arXiv](https://arxiv.org/abs/2608.30322)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.30322)

> 专业领域智能体评估面临的核心困境在于，基准任务往往依赖公开语料中不存在的私有约定，导致无法区分模型是“无知”还是“无能”。现有合成数据方法或受限于生成器能力天花板，或无法验证私有知识的必要性。本文提出一种构造协议，将任务指令与包含私有约定的紧凑工件分离，并通过泄漏审计与配置相对校准屏幕验证依赖关系。该协议在15个校准任务中实现了从0%到68.0%的通过率切换，但仅验证了构造行为，未证明训练价值。

## 研究背景

当智能体执行法律条款审查或BOM成本汇总等任务时，其正确性依赖于特定的内部阈值、归一化表或别名映射。这些约定通常不存在于公开语料中，若基准未控制智能体是否拥有这些约定，评估结果便混淆了知识缺失与执行能力。这种混淆源于传统合成数据生成的两个局限：模型生成的指令微调受限于生成器自身能力，无法超越其固有上限；而数据集蒸馏旨在压缩语料用于权重更新，对推理时依赖上下文的智能体无效。

当前领域主流路线包括基于GitHub Issue的代码环境构建、模拟工具生态及自博弈循环。这些方法虽提升了环境复杂度，但普遍缺乏对“私有知识”作为受控变量的显式建模。SkillsBench等基准虽引入了技能文档，但将其视为辅助上下文，未建立指令与工件的强制分离机制，导致无法量化知识贡献。本文切入点在于将私有约定从“背景噪声”转化为“门控变量”，通过构造时的不对称性（答案植入、廉价验证、组合验证）建立可审计的能力边界。

## 核心方法

### 任务-工件分离与泄漏审计

参照系为标准的指令-响应合成流程，其关键差异在于本文引入“构造特权”：答案在构造时植入，不可从指令推导。设计动机是解决现有方法中“生成器已知规则”导致任务缺乏区分度的问题。协议要求指令与工件字节级一致，且指令仅提及“既定内部规范”，不引用工件。静态泄漏审计扫描指令与环境数据中的显式门控常数，确保-A条件（无工件）是真正的知识消融而非环境损坏。该审计提供证据而非保证，但确保了观察到的效果是“全失败”与“多数成功”之间的切换，而非边际增益。

### 配置相对校准屏幕

在分离基础上，本文引入配置相对校准屏幕以筛选有效任务。设计动机是解决RLVR中通过率饱和或绝对零值导致梯度信号缺失的问题，但仅用于离线质量控制。屏幕基于两个固定配置：前沿配置 $A_F$（Claude Opus 4.8）与中端配置 $A_{mid}$（Qwen3.6-Plus）。保留指标定义为：

$$
\mathbf{I}_{\text{retain}} = \mathbf{1}\Big[ \hat{p}(A_F, +A) \geq 0.6 \;\land\; \hat{p}(A_F, -A) = 0 \;\land\; \hat{p}(A_{mid}, +A) \leq 0.4 \Big]
$$

该公式要求前沿模型在有工件时通过率至少60%，无工件时通过率为0，且中端模型在有工件时通过率不超过40%。这确保了任务对前沿模型是“知识门控”的，对中端模型是“能力受限”的。由于每格仅5次试验，该屏幕是粗粒度质量控制，非统计检验，其结果仅描述当前批次，不证明保留任务具有更优的训练价值。

## 实验评估

实验在15个校准任务上进行，每格5次独立运行，使用Docker沙箱与BenchFlow框架。基线覆盖前沿模型（Opus 4.8）与中端模型（Qwen3.6-Plus），但缺失其他主流模型对比，且未与SkillsBench官方结果直接对比，仅作为上下文参考。

| 任务 | $A_F$ -A | $A_F$ +A | $A_{mid}$ +A |
| :--- | :--- | :--- | :--- |
| Contract Clause Risk | 0/5 | 4/5 | 0/5 |
| Publication Index | 0/5 | 5/5 | 0/5 |
| BOM Cost Rollup | 0/5 | 5/5 | 0/5 |
| Airline Booking Audit | 0/5 | 5/5 | 2/5 |
| Clinical Variant Mapper | 0/5 | 5/5 | 1/5 |
| Mortgage Escrow Analysis | 0/5 | 5/5 | 2/5 |
| Dependency Audit | 0/5 | 3/5 | 2/5 |
| **Pooled** | **0/75** | **51/75** | **17/75** |

核心数字对比显示，$A_F$ 配置下工件的引入使通过率从0%提升至68.0%，而 $A_{mid}$ 配置下仅为22.7%。在BOM成本任务中，使用扰动工件（将12%开销率改为15%等）导致通过率为0%，证明效果追踪工件正确性而非仅存在性。

消融实验揭示，7个保留任务中，3个（airline-booking, mortgage-escrow, dependency-audit）恰好位于40%中端模型上限，属于边界案例。重述探针显示，Qwen在单轮无工具条件下能100%正确重述约定并解题，但在完整智能体框架下通过率为0%，表明失败源于工具使用、文件发现或输出格式合规，而非知识缺失。

评估边界在于：静态泄漏审计无法排除语义层面的隐性泄露；5次试验的样本量导致置信区间宽泛（如0/5对应[0.00, 0.43]）；且实验未进行下游训练验证，仅证明构造协议的行为符合预期。代码已开源，但部分审计脚本仅覆盖9/15任务。

## 关联研究分析

从问题动机看，本文与AgentDojo等安全基准均关注能力边界，但AgentDojo聚焦对抗攻击下的鲁棒性，而本文聚焦知识依赖下的可验证性。AgentDojo通过嵌入攻击测试智能体抵抗能力，本文通过植入私有约定测试智能体应用知识能力。差异根源在于任务特性：安全任务需模拟动态威胁，知识门控任务需静态控制变量。本文未探索动态知识更新场景，当私有约定随时间变化时，静态审计是否仍有效，论文未给出回答。

从方法设计看，本文与SkillsBench同属技能条件基准，但SkillsBench将技能文档视为辅助上下文，本文将其转化为门控变量。SkillsBench的评估关注“有/无技能”的性能差异，本文通过字节级指令一致性与泄漏审计，将差异归因于知识访问而非提示格式。本文的“配置相对”设计承认了框架影响，但通过固定Harness试图隔离，这与领域共识中“框架影响显著”的观点存在张力。当Harness改变时，知识门控效果是否稳定，论文未提供跨框架验证。

## 总结

本文要解决的核心矛盾是专业任务评估中私有知识依赖与可验证性的冲突。现有方法无法区分知识缺失与执行无能，本文通过构造时的不对称性（答案植入、廉价验证）建立可审计边界。协议将任务指令与私有工件分离，通过泄漏审计与配置相对校准屏幕验证依赖关系。实验证明，在15个任务中，工件引入使前沿模型通过率从0%切换至68.0%，且扰动工件导致0%通过率，验证了协议的有效性。边界在于静态审计无法排除语义泄露，且未证明训练价值。当私有约定从静态文本扩展为动态数据库时，该构造协议如何维持可验证性，论文未给出回答。
