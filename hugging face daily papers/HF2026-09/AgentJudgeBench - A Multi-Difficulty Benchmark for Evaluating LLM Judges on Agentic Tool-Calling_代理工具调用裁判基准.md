# HuggingFace最新推荐论文 ｜AgentJudgeBench: A Multi-Difficulty Benchmark for Evaluating LLM Judges on Agentic Tool-Calling ｜代理工具调用裁判基准

作者：Abhigya Verma、Amit Kumar Saha、Seganrasan Subramanian 等 4 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.26623)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.26623)

> 代理工具调用评估面临的核心矛盾是：LLM 裁判在结构化工作流上的可靠性缺乏校准，现有基准仅报告聚合通过率，无法区分裁判在工具选择、参数结构、序列准确性与查询覆盖四个正交维度上的失效模式。AgentJudgeBench 通过 3,808 条带程序化验证真值轨迹的 DAG 记录，在配对有/无真值条件下量化了 321,648 次裁判对齐，揭示了无真值时所有裁判收敛于 77–82% 的结构性天花板，以及前沿模型因过度锚定导致的对齐度反降现象。该基准提供了可操作的部署指南，但其合成数据与单轮设定限制了向多轮交互式代理场景的推广。

## 研究背景

当 LLM 从文本生成扩展为调用外部工具的自主代理时，评估对象从“流畅性偏好”转变为“结构正确性”：一个工具调用计划必须在类型化模式中选择正确工具、提供合法参数、尊重执行依赖顺序，并覆盖用户意图的全部部分。这种正确性具有四维正交性——工具选择、参数结构、序列准确性、查询覆盖——且各维度间不干净相关，一个在简单顺序任务上校准良好的裁判可能在复杂扇入或菱形工作流中完全失效。当无真值执行轨迹可用（即常见部署场景），裁判必须仅从查询和工具模式重建正确性，这是一个根本性更难的推断问题。

现有工具调用评估基准（ToolLLM、StableToolBench、MCP-AgentBench）将 LLM 裁判作为实现细节而非研究对象，仅在小样本上报告单一聚合通过率，不变化任务复杂度、难度或真值可用性。Zheng et al. (2023) 确立的 LLM-as-a-Judge 范式针对开放式文本偏好对齐，其偏差分类（位置、冗长、自我增强）无法直接迁移至结构正确性任务，因为后者的判决空间是 {0, 0.5, 1} 而非偏好排序，失效模式是多维且相互依赖的。AgentJudgeBench 的切入点在于：保持裁判范式不变，但系统性地测量其可靠性，通过配对有/无真值条件、受控难度分层和逐指标分解，将裁判可靠性从“黑盒聚合分数”转化为可审计的统计量。

## 核心方法

### 方法参照系

本文问题最接近的通用流程是 LLM-as-a-Judge 的成对比较协议，但关键差异在于：标准流程评估文本质量偏好，本文评估结构正确性；标准流程以人类判断为参考，本文以确定性程序化裁判为参考。这一差异源于结构正确性可被规则化验证，而文本偏好不可。

### 程序化参考基准与四维评分

设计动机：使用另一个 LLM 作为参考会重新引入同一可靠性问题，人类参考无法扩展至 321,648 次评估，确定性规则评分器为每个因子单元格提供相同、可复现的参考。程序化裁判对每条记录输出四个独立分数，工具选择准确性 $p_{\text{tool}}$ 惩罚集合级不匹配：

$$
p_{\text{tool}} = \max\left(0, 1 - \frac{|\mathcal{G} \setminus \mathcal{E}| + |\mathcal{E} \setminus \mathcal{G}|}{\max(|\mathcal{E}|, 1)}\right)
$$

该公式计算预测工具集合与真值工具集合的对称差比例，值域 [0,1]，1 表示完全匹配。序列准确性 $p_{\text{seq}}$ 测量逐位置身份，参数结构准确性 $p_{\text{param}}$ 对每个预测调用检查参数键集是否包含真值键集（允许额外键得 0.5，缺失键得 0），查询覆盖准确性 $p_{\text{cov}}$ 计算真值工具标识符被预测覆盖的比例。四指标等权聚合，Spearman ρ ≥ 0.832 验证了等权聚合对五种替代加权方案的排名稳定性。

### 配对有/无真值协议与难度分层

设计动机：无真值是常见部署场景，但现有研究不区分有/无真值条件，导致无法量化真值暴露对裁判对齐的影响。每条记录扩展为三个难度层级（易、中、难），通过增加查询歧义同时保持任务结构和真值轨迹不变。LLM 裁判接收结构化提示，包含原始用户查询、完整工具模式集合和生成器的预测工具调用序列，要求输出 JSON 对象对四个指标各赋予 {0, 0.5, 1} 分数。有真值提示额外暴露真值工具调用序列作为参考块，无真值提示完全省略。对齐度定义为程序化参考与 LLM 裁判判决的逐指标绝对差均值。该协议的核心价值在于：通过配对设计隔离真值暴露的因果效应，而非仅报告单一条件下的聚合分数。

## 实验评估

实验设置：5 个生成器（SmolLM3-3B、Llama-3.1-8B、Qwen3-32B、Llama-3.3-70B、GPT-5.4）产生工具调用输出，6 个裁判（GPT-5.4、Gemini-2.5-Pro、QwQ-32B、GPT-OSS-20B、GPT-OSS-120B、Prometheus-2）在配对有/无真值条件下评分，共 321,648 次有效评估。基线覆盖通用前沿模型和专用裁判模型（Prometheus-2），但缺失其他代理专用裁判配置。

| 条件 | 难度 | 最佳裁判 | 对齐度 (%) |
| :--- | :--- | :--- | :--- |
| 无真值 | 易 | Gemini-2.5-Pro | 92.1 |
| 无真值 | 中 | GPT-5.4 | 87.7 |
| 无真值 | 难 | GPT-5.4 | 79.7 |
| 有真值 | 易 | QwQ-32B | 94.0 |
| 有真值 | 中 | QwQ-32B | 90.0 |
| 有真值 | 难 | QwQ-32B | 83.4 |

无真值难查询下，所有六个裁判收敛于 77–82% 区间，跨四个生成器（含 GPT-5.4）一致，表明任务级而非裁判级天花板。有真值条件下 QwQ-32B 在所有难度层级领先，GPT-OSS-120B 为最佳开源替代。

消融发现：链式思维推理在 24 个配对单元格中平均贡献 +0.11 pp，最大单格差异 0.3 pp，无单元格超过 0.3 pp；裁判温度在 T ∈ {0.3, 0.7, 1.0} 下最大差异 0.6 pp，两个裁判-生成器配对均确认温度不敏感性。结构化逐指标 JSON 提示在 Qwen3-32B 对 Llama-3.3-70B 配对上有真值时提升 +4.8–+6.5 pp，但在 QwQ-32B 对 SmolLM3-3B 配对上难查询时反转（−0.8 pp），表明提示格式效应是裁判/生成器依赖的，非普遍主导。过度锚定效应：GPT-5.4 有真值对齐度比无真值低 1.5 pp，Gemini-2.5-Pro 低 3.9 pp，引导式置信区间不重叠，确认前沿模型见真值后对齐度下降。

评估边界：120 条难记录人工标注研究验证评分器与人类判断的指标级一致率为 92.7%，但仅覆盖难难度层级；easy→medium 难度重写仅在 58.1% 记录上获一致验证，41.9% 情况下 medium 更接近改写而非严格难度增加，因此主要难度退化证据来自 medium→hard 步骤。代码和数据集已公开，但合成数据生成依赖 SyGra 框架，未报告 GPU 资源需求。

## 关联研究分析

从问题动机看，AgentJudgeBench 与 FuncBenchGen 共享 DAG 结构化工具调用数据格式，但目的根本不同：FuncBenchGen 训练和评估生成器代理，AgentJudgeBench 测量裁判可靠性。这一差异源于任务特性：生成器评估关注输出质量，裁判评估关注评估过程本身的可靠性。FuncBenchGen 不提供配对有/无真值协议和逐指标分解，因此无法回答“裁判在哪个维度失效”这一核心问题。AgentJudgeBench 的程序化参考基准选择也区别于 FuncBenchGen 的生成器评估范式，后者以环境执行反馈为参考，前者以确定性规则评分为参考，这一选择使得裁判对齐度可被精确量化，但代价是参考基准本身可能引入规则化偏差——程序化裁判对“功能等价但结构偏离”的序列的惩罚是否合理，论文未深入讨论。

从方法设计看，AgentJudgeBench 与 Prometheus 2 代表两条不同路线：Prometheus 2 通过指令微调训练专用裁判模型，使其能根据自然语言评分标准进行细粒度评分；AgentJudgeBench 使用通用 LLM 作为裁判，通过协议设计（配对条件、难度分层、逐指标分解）测量其可靠性。实验显示 Prometheus-2 在结构任务上与所有裁判的一致率接近随机水平（42–52% 精确匹配，κ = 0.01–0.07），远低于六个主要裁判的“公平至实质”区间，表明专用裁判模型在结构正确性任务上失效。这一结果挑战了“专用训练更鲁棒”的领域共识，暗示结构正确性评估可能需要不同的训练范式或评估协议，而非简单的微调。

## 总结

AgentJudgeBench 要解决的核心矛盾是 LLM 裁判在代理工具调用结构化正确性评估上的可靠性缺乏校准，现有基准仅报告聚合分数，无法分解失效模式。本文抓住的切入点是：结构正确性可被程序化验证，因此可构建确定性参考基准，通过配对有/无真值协议隔离真值暴露的因果效应。本文构建了 3,808 条带程序化验证真值轨迹的 DAG 记录，在 321,648 次评估中量化了裁判对齐度，证明无真值难查询下所有裁判收敛于 77–82% 的结构性天花板，且前沿模型因过度锚定导致有真值对齐度下降 1.5–3.9 pp。本文的边界在于：合成数据与单轮设定限制了向多轮交互式代理场景的推广，程序化参考基准对“功能等价但结构偏离”序列的惩罚合理性未经验证，且 easy→medium 难度重写的验证率仅 58.1%，削弱了难度分层的校准性。当程序化参考基准本身存在规则化偏差时，裁判对齐度的测量是否仍具因果解释力，论文未给出回答。
