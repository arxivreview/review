> 在迭代式对话生成中，用户仅指定局部修改时，大语言模型（LLM）需自主识别并更新所有受影响的依赖元素以维持全局一致性，这一过程称为修订传播。现有研究多聚焦于依赖关系显式或可静态分析的代码库、知识图谱或文档，而对话生成工件中的依赖往往隐式存在于对话历史中，缺乏系统评估。本文构建了人工标注的基准 RevPropBench，并系统评估了九种修订方法在六种 LLM 上的表现。研究揭示了测试时计算策略的成本效益边界，为低成本提升修订可靠性提供了实证依据，但其在非 JSON 格式及动态依赖场景下的泛化能力尚待检验。

## 研究背景

当 LLM 辅助用户通过多轮对话生成计划、配置等 JSON 工件时，用户常仅提出局部修订请求（如“移除目的地 B”），而模型需推断该操作对预算、时间等关联元素的连锁影响。这种依赖关系并非显式编码在工件结构中，而是隐含于对话上下文（Conversation Context）中，构成了隐式依赖解析（Implicit Dependency Resolution）问题。若模型仅修改显式提及的元素，将导致工件内部逻辑不一致（如预算未随人数调整），即修订传播失败。

修订传播问题在代码编辑（Repository-level Coding）和知识编辑（Knowledge Editing）中已有研究，但前者依赖调用图与变量引用等静态结构，后者依赖预存知识图谱，其依赖关系均可通过静态分析显式获取。对话生成工件的依赖则动态建立于对话流中，无法通过静态图结构解析，导致现有方法在此场景下失效。本文切入点在于：将修订传播从“静态依赖解析”转向“对话上下文驱动的隐式依赖推断”，并首次构建针对此场景的标准化评估基准。

## 核心方法

### 任务定义与基准构建

本文任务分为生成与修订两阶段。生成阶段，LLM 通过多轮对话增量构建 JSON 工件；修订阶段，用户提出局部请求，LLM 输出符合 RFC 6902 标准的 JSON Patch 序列。基准 RevPropBench 包含 150 个样本（50 场景 × 3 尺寸），覆盖 9 个领域，依赖关系由人工标注 Gold Patch 定义。评估指标为完成率（Completion Rate），即生成 Patch 与 Gold Patch 在路径与值上完全匹配的样本比例。该设计将隐式依赖问题转化为结构化输出匹配问题，使评估可量化。

### 测试时计算策略

为提升单次推理的修订准确率，本文引入测试时计算（Test-Time Compute）策略，核心在于通过多次采样与选择机制优化最终 Patch 质量。设单次推理生成的 Patch 集合为 $\mathcal{P} = \{p_1, p_2, \dots, p_k\}$，其中 $k$ 为采样次数。本文评估了两种选择机制：基于中位数的选择（MED）与基于 LLM 的选择（SELECT）。MED 选择与其余候选在叶子节点层面平均分歧最小的 Patch：

$$
p_{\text{med}} = \arg\min_{p_i \in \mathcal{P}} \frac{1}{k-1} \sum_{j \neq i} D(p_i, p_j)
$$

其中 $D(p_i, p_j)$ 为两个 Patch 应用后工件的叶子节点差异度量。SELECT 则利用 LLM 对候选 Patch 进行推理评估，选择最完整且一致的选项。该设计动机在于：单次推理易遗漏隐式依赖（Miss），而并行采样可覆盖不同依赖推断路径，选择机制则从统计或语义层面过滤噪声，从而在有限计算成本下提升全局一致性。

## 实验评估

实验在 RevPropBench 测试集（120 样本）上进行，评估六种 LLM（gpt-oss-20b/120b, gpt-5.4-mini, qwen3.5-9b/27b/122b）与九种方法。基线包括仅工件（J）、仅对话历史（H）及两者结合（J+H）的单次推理，以及 REFLECT、OR、AND、MAJ、MED、SELECT 等测试时计算方法。

| 模型 | J+H 完成率 | SELECT 完成率 | 提升幅度 |
| :--- | :--- | :--- | :--- |
| gpt-5.4-mini | 93.0% | 95.5% | +2.5% |
| qwen3.5-122b | 90.3% | 95.2% | +4.9% |
| qwen3.5-9b | 81.7% | 88.7% | +7.0% |

数据显示，J+H 基线完成率在 68.3%–93.0% 之间波动，模型规模越大表现越好。SELECT 方法在所有模型上均带来一致提升（+3.3%–12.5%），其中小模型（qwen3.5-9b）提升幅度最大。MED 次之（+1.8%–7.7%），而基于规则合并的 AND 方法因要求全票一致，导致正确编辑被丢弃，完成率低于 J+H 基线（-13.2%–21.3%）。

消融分析表明，对话历史（H）对性能贡献显著，J < H < J+H 的顺序在所有模型中成立，证实隐式依赖主要存在于对话上下文中。成本分析显示，SELECT 在 Qwen 模型上因推理 Token 增多，成本为 J+H 的 5.7–7.5 倍，但在固定成本对齐后，其性能优势依然保持，表明增益源于方法本身而非单纯算力堆砌。

评估边界方面，基准仅覆盖 JSON 格式工件，未涉及自然语言文档或代码库；评估指标为精确匹配，未考虑部分正确性；实验未报告置信区间，且样本量（120）较小，统计显著性有限。代码与工具已开源，支持复现。

## 关联研究分析

从问题动机看，本文与 RippleEdits（Cohen et al., 2024）均关注编辑后的连锁反应，但 RippleEdits 依赖预存知识图谱显式定义事实间关联，而本文依赖对话上下文隐式推断。这一差异根源在于任务特性：知识编辑中事实关联是静态且可预定义的，而对话生成工件的依赖是动态且随对话流演化的。本文未探索如何利用对话历史构建显式依赖图，这可能导致在长对话中依赖追踪的累积误差。

从方法设计看，本文的 MED 与 SELECT 是 Self-Consistency（Wang et al., 2023）的结构化变体。Self-Consistency 通过多数投票选择最终答案，适用于离散选项任务；而本文针对 JSON Patch 的连续结构，引入叶子节点分歧度量（MED）与 LLM 推理选择（SELECT）。这一改进解决了多数投票在结构化输出中无法处理路径与值细微差异的问题。然而，本文未对比基于检索增强生成（RAG）的方法，即从对话历史中检索相关片段辅助修订，这可能在长对话场景中比全量上下文更高效。

## 总结

本文核心矛盾在于对话生成工件中隐式依赖的解析与低成本验证。现有方法依赖静态结构，无法处理对话驱动的动态依赖，而本文通过构建人工标注基准与评估测试时计算策略，首次量化了 LLM 在此场景下的能力边界。实验证明，SELECT 与 MED 策略可在 2.2%–9.7% 范围内提升完成率，且成本效益优于简单迭代反思。本文边界在于仅评估 JSON 格式、精确匹配指标及小样本量，未探索长对话中依赖追踪的累积误差或检索增强方法。当对话轮次超过 20 轮时，全量上下文输入是否会导致依赖信息稀释，从而降低 SELECT 的选择准确性，论文未给出回答。
