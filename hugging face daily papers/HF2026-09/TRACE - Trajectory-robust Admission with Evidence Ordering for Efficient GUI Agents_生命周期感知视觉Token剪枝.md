# HuggingFace最新推荐论文 ｜TRACE: Trajectory-robust Admission with Evidence Ordering for Efficient GUI Agents ｜生命周期感知视觉Token剪枝

研究机构：大连理工大学、香港理工大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.10297)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.10297)

> 多步GUI智能体在轨迹展开时累积高分辨率截图，导致推理延迟与显存占用随步数线性增长。现有无训练剪枝方法假设每步可独立重选Token，但KV缓存复用机制使得历史帧仅编码一次，丢弃的视觉证据无法恢复，迫使剪枝从可逆选择转变为不可逆的写入时承诺。TRACE通过布局先验引导的嵌套证据排序与原生Token覆盖修复，在冻结模型上实现单调收缩的会话状态管理。该方法在紧预算下显著优于现有剪枝基线，但其对动态UI布局变化的适应能力及跨任务泛化边界尚存疑。

## 研究背景

GUI智能体依赖多模态大语言模型（MLLM）解析屏幕截图并执行动作，其推理成本主要源于视觉编码。随着交互步数增加，历史截图的视觉Token在KV缓存中持续累积，形成时间冗余；同时，单张高分辨率截图内部存在大量空间冗余，如背景区域与重复UI组件。这种双重冗余使得长程任务的推理延迟与显存占用成为部署瓶颈，亟需在冻结模型上实现高效的视觉状态管理。

主流无训练剪枝方法如FastV（Chen et al., 2024）基于注意力统计丢弃低权重Token，DivPrune（Alvar et al., 2025）强调特征多样性，CDPruner（Zhang et al., 2025b）结合指令相关性。这些方法假设每步查询独立，允许重新计算保留集合。然而，在KV缓存复用场景中，历史帧仅在首次预填充时编码，后续步骤直接从缓存读取，导致单步剪枝决策具有不可逆性：若某Token在首次写入时被丢弃，未来所有查询均无法访问该视觉证据，除非重新编码整帧。这一约束要求剪枝输出必须满足嵌套性，即历史保留集必须是当前保留集的子集，且所有预算级别均通过前缀实现。TRACE正是针对这一“写入时承诺”问题，提出在预填充前一次性确定嵌套排序，并通过布局先验与覆盖修复确保未来目标的可见性。

## 核心方法

### 方法参照系

本文问题属于无训练视觉Token剪枝，但与传统剪枝的关键差异在于生命周期约束。传统方法（如FastV）每步独立重选，允许Token集合漂移；TRACE要求保留集满足 $S^{hist}_t \subseteq S^{cur}_t$，且所有预算级别通过前缀实现，确保历史帧收缩时仅删除行而非重新编码。这一约束将剪枝从可逆选择转变为不可逆的写入时承诺，要求排序在未知未来目标下仍具鲁棒性。

### 布局导引交互先验（LIP）

LIP解决指令相关性剪枝无法预判后续步骤目标的问题。传统方法依赖当前指令计算相关性，但多步任务中后续目标在写入时未知，导致关键操作区域被误删。LIP通过OmniParser检测UI布局框，计算每个框的交互能量 $E = H + C + G + R$，其中 $H$ 为纹理熵，$C$ 为边界对比度，$G$ 为包含度，$R$ 为共振度。能量除以覆盖的活跃Token数 $n$ 得到密度 $\rho = E/n$，散射至视觉Token网格并归一化为 $p$。最终交互先验定义为 $m_j = 1 + \alpha N p_j$，其中 $\alpha$ 控制偏置强度。该先验独立于查询，将布局结构转化为Token保留偏置，确保操作区域在后续步骤中仍可见。

### 嵌套证据排序与覆盖修复（NEO-NCR）

NEO融合LIP先验、指令相关性与特征新颖性，生成单一嵌套排序。排序得分结合先验质量 $m_j$、指令余弦相似度及正交残差，通过softmax归一化。NCR在排序基础上修复空间覆盖：当前帧采用步长采样保留原生Token，历史帧通过区域质心（medoid）选择代表Token，确保保留集为当前集子集。这一设计解决了纯重要性排序在紧预算下空间覆盖坍缩的问题，如r=5%时指令剪枝仅覆盖1/4目标，而TRACE保留3/4。

## 实验评估

实验在ScreenSpot-v2、ScreenSpot-Pro、MMBench-GUI、OmniGUI、Mind2Web、AndroidControl六个基准上评估，对比FastV、DivPrune、VisPruner、PruneSID等11种无训练剪枝方法，覆盖单步定位与多步动作预测。基线未包含训练式方法（如ReVision），但覆盖了主流无训练路线。

| 方法 | SS-v2 (r=5%) | SS-Pro (r=10%) | Mind2Web (tight) | Avg. (%) |
| :--- | :--- | :--- | :--- | :--- |
| PruneSID | 34.20 | 4.55 | 27.57 | 47.8 |
| VisPruner | 20.68 | 12.21 | 30.67 | 47.3 |
| TRACE | 55.19 | 20.30 | 34.20 | 61.1 |

TRACE在紧预算下全面领先，SS-v2上较PruneSID提升20.99%，Mind2Web上较VisPruner提升3.53%。消融显示，移除LIP先验导致SS-v2下降23.74%，移除NCR使Mind2Web从34.20%降至27.79%，验证了布局先验与覆盖修复的互补性。

| 消融项 | SS-v2 | SS-Pro | Mind2Web |
| :--- | :--- | :--- | :--- |
| 移除LIP先验 | -23.74 | -16.50 | -15.50 |
| 移除NCR | -17.45 | -10.62 | -6.41 |

评估边界方面，实验仅使用GUI-Owl-1.5-8B/2B与UI-TARS-1.5-7B，未测试更大规模模型；指标未报告置信区间，且多步任务成功率（Step SR）对动作类型与目标的双重正确性要求严格，可能低估部分方法的实际效用。代码声明将发布，但未提供具体URL，超参数如 $\alpha$ 与步长未详细披露。

## 关联研究分析

从问题动机看，TRACE与FastV、DivPrune等方法的根本差异在于对缓存复用约束的处理。FastV基于注意力统计每步重选，假设Token集合可漂移；TRACE强制嵌套性，将剪枝视为一次性承诺。这一差异源于任务特性：多步GUI交互中历史帧不可重新编码，而单步定位任务无此约束。TRACE的布局先验设计直接回应了“未来目标未知”的挑战，而FastV的注意力机制仅反映当前查询，无法预判后续需求。

从方法设计看，TRACE与PruMerge+（Shang et al., 2025）同属无训练剪枝，但PruMerge+通过合成摘要聚合冗余Token，允许Token集合动态变化；TRACE坚持保留原生Token，以支持缓存行删除而非重建。这一选择牺牲了压缩率，但确保了单调收缩的可行性。PruMerge+的合成本质上破坏了嵌套性，因为合成Token无法在后续步骤中部分保留，而TRACE的原生Token保留使得历史收缩仅涉及行删除，避免了重新编码开销。

## 总结

TRACE解决的核心矛盾是KV缓存复用下视觉Token剪枝的不可逆性与未来目标未知性。现有方法假设每步可独立重选，但缓存复用要求一次性承诺，导致关键操作区域在后续步骤中丢失。TRACE通过布局先验引导的嵌套排序与原生Token覆盖修复，在冻结模型上实现单调收缩的会话状态管理。实验显示，紧预算下TRACE在SS-v2上达到55.19%，较最强基线PruneSID提升20.99%；Mind2Web上达到34.20%，较VisPruner提升3.53%。其边界在于对动态UI布局变化的适应能力：LIP依赖OmniParser检测静态布局，若界面元素位置频繁变动，先验可能失效。当UI布局在轨迹中发生显著重排时，嵌套排序的前缀约束是否仍能保持目标可见性，论文未给出回答。
