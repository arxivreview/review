# HuggingFace最新推荐论文 ｜MobileVLA-R1 2.0: RL-Enhanced Reasoning for Mobile Robot Control ｜移动机器人推理-动作接口：MobileVLA-R1 2.0

研究机构：北京大学、华南理工大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.06251)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.06251)

> 移动机器人执行长时程指令时，高层语义决策与低层物理控制之间的断层导致动作连贯性失效。现有VLA模型多依赖隐式表征直接映射动作，缺乏显式的中间推理机制来协调导航与操作。本文通过构建多粒度思维链（Chain-of-Thought, CoT）数据引擎与推理条件动作解码器，将结构化推理显式转化为任务级动作指令。该框架在真实人形机器人上实现了10.0个百分点的全任务成功率提升，但其推理延迟与跨本体迁移的泛化边界仍存疑。

## 研究背景

当四足或人形机器人执行“避开障碍并前往特定物体”这类复合指令时，视觉-语言模型（Vision-Language Model, VLM）往往能正确理解语义，却因缺乏对空间约束与执行策略的显式规划，导致底层控制器产生抖动或偏离目标。这种从语义到物理的转化依赖隐式特征映射，即System-1式处理，难以应对长时程任务中的状态累积误差。为弥补这一缺陷，研究者引入System-2式推理，即通过生成结构化的中间表征来编码任务解释与空间决策，但现有方法多停留在生成人类可读的解释文本，未能建立推理表征与可执行动作之间的显式接口。

VLA领域的核心瓶颈在于如何将自然语言指令可靠地接地为连续、平滑的物理控制信号。早期工作如RT-2将动作离散化为Token，虽便于利用大语言模型知识，但受限于控制频率与动作不连续性。随后，π0引入流匹配（Flow Matching）机制实现连续动作生成，解决了精度问题，但决策过程仍主要关注观测到动作的直接预测，中间推理过程保持隐式。在移动机器人场景下，导航与操作需在同一任务中协调，隐式推理难以同时处理语义目标、空间约束与物理交互。MobileVLA-R1 2.0的切入点在于构建一个显式的推理-动作接口，将结构化CoT表征转化为紧凑的任务级动作目标，并通过强化学习优化推理与动作的一致性，从而支持跨本体的迁移执行。

## 核心方法

### 方法参照系

标准VLA流程将多模态观测与指令输入VLM骨干，直接输出动作序列。本文的关键差异在于插入显式推理层：骨干网络自回归生成结构化CoT序列，其隐状态作为条件输入至独立动作解码器，而非直接解析文本为动作。这一设计将语义决策与本体执行解耦，避免了VLM直接预测关节角导致的精度损失与本体依赖。

### 多粒度CoT数据引擎

设计动机在于解决单一粒度推理无法覆盖长时程任务中不同时间尺度决策的问题。引擎以Gemini-2.5-Flash为后端，针对导航与具身控制轨迹生成Episode级（任务总结）、Navigation级（路径规划）与Step级（即时动作分析）三类推理轨迹。每条样本包含多模态观测、指令及可选状态-动作历史，输出格式为`<answer>...动作...</answer>`。从168K原始生成中，经格式校验、动作一致性、安全性与语义正确性四阶段半自动验证，最终保留134K有效样本。该数据集为后续监督对齐提供了覆盖不同时间尺度的显式推理监督信号。

### 推理条件动作解码器与GRPO优化

设计动机在于直接解析CoT文本为动作仅建立隐式连接，无法保证推理逻辑与物理执行的严格对齐。解码器接收观测隐状态 $H_{obs}^t$ 与推理隐状态 $H_{rea}^t$，构建联合上下文序列。其核心是一个包含两个可学习查询（分别对应运动与行为）的单层交叉注意力模块，隐藏维度 $d=4096$，8个注意力头。运动分支输出连续指令 $(V_x, V_y, \omega)$，行为分支输出离散原语 $\alpha$。

$$
\hat{A}_{t,j} = \frac{r_{t,j} - \bar{r}_t}{\sigma_{r,t} + \epsilon}
$$

该公式计算组相对优势，其中 $r_{t,j}$ 为第 $j$ 个候选输出的奖励，$\bar{r}_t$ 为组均值，$\sigma_{r,t}$ 为标准差。GRPO阶段在固定数据集上离线优化，无需环境交互。奖励函数 $r_{t,j} = \lambda_{mov}R_{mov} + \lambda_{beh}R_{beh} + \lambda_{fmt}R_{fmt}$ 综合运动一致性、行为正确性与格式有效性。监督对齐阶段使用LoRA（秩 $r=16$，缩放 $\alpha_{LoRA}=32$）微调LLaMA3-8B骨干，冻结深度与点云编码器。GRPO阶段在单张H20 GPU上优化1K步，学习率 $1 \times 10^{-6}$，KL系数 $\beta=0.04$。这一两阶段训练策略先建立结构化推理能力，再通过RL强化推理-动作一致性，解决了纯监督学习中推理与动作脱节的问题。

## 实验评估

实验覆盖VLN-CE（R2R/RxR）、QUARD四足控制及Unitree Go2/G1真实部署。基线包括NaVILA、MobileVLA-R1、MoRE及CLIP等，但未对比π0、OpenVLA等通用VLA SOTA，因任务侧重移动推理接口而非通用操作。

| 方法 | R2R-CE SR | R2R-CE SPL | RxR-CE SR | RxR-CE SPL |
| :--- | :--- | :--- | :--- | :--- |
| NaVILA | 1.29 | 0.83 | 1.76 | 0.80 |
| MobileVLA-R1 | 1.03 | 0.93 | 1.23 | 0.91 |
| MobileVLA-R1 2.0 | 0.96 | 0.95 | 1.12 | 0.94 |

注：表格数值源自论文Table 4真实世界Go2评估，非VLN-CE仿真数据。VLN-CE主结果中，MobileVLA-R1 2.0在R2R-CE达69.8% SR与66.9% SPL，较MobileVLA-R1提升1.5与1.7个百分点；在RxR-CE达73.1% SR，提升1.6个百分点。QUARD基准上，平均成功率从MobileVLA-R1的0.70提升至0.76，较MoRE的0.60提升0.16。

| 消融项 | R2R-CE SR | R2R-CE SPL |
| :--- | :--- | :--- |
| No-CoT | 64.0 | 59.6 |
| Multi-granularity CoT | 68.3 | 65.2 |
| 无GRPO | 65.2 | 61.0 |
| 完整模型 | 68.3 | 65.2 |

消融显示，多粒度CoT监督较无CoT提升4.3个百分点SR，其中Navigation级推理贡献最大。GRPO阶段中，行为奖励 $R_{beh}$ 单独使用即达61.9% SR，高于运动奖励的60.7%，表明行为一致性对导航成功更关键。完整奖励组合进一步将SR推至68.3%。解码器架构消融中，Dual-Query Dual-Head较Mean Pooling + MLP提升1.1个百分点SR，证实分离运动与行为查询的有效性。

评估边界方面，VLN-CE使用标准val-unseen分割，QUARD每任务25集，真实世界Go2共160集、G1共120集。代码与超参数已公开，但8B骨干在Jetson Orin Nano上无法本地运行，依赖远程H20 GPU，端到端延迟205-245ms，有效决策频率仅4.1-4.9Hz。G1评估未使用任何G1特定轨迹或微调，验证了跨本体迁移，但失败分析显示抓取与操作执行错误（16+14例）远超导航错误（10例），表明推理-动作接口在精细操作环节仍脆弱。

## 关联研究分析

从问题动机看，MoRE同样针对四足VLA控制，但侧重通过RL直接优化动作分布，未引入显式推理层。本文的差异在于将RL用于优化推理-动作一致性而非动作本身，这源于移动机器人长时程任务中，隐式动作优化难以维持语义连贯性。MoRE在QUARD上平均成功率0.60，低于本文的0.76，但MoRE未评估真实世界人形操作，两者任务范围不同，直接数值对比需谨慎。

从方法设计看，NaVILA作为本文骨干来源，采用LLaMA3-8B与多模态编码器，但动作生成依赖确定性文本解析。本文改造动作头为可学习解码器，并引入GRPO，这一差异是否源于任务特性（移动推理需显式规划）还是通用VLA的潜在改进空间，论文未给出回答。GR00T N1侧重人形通用性，采用大规模预训练，而本文聚焦推理接口，两者在数据规模与任务复杂度上存在本质差异，无法直接比较。

## 总结

MobileVLA-R1 2.0解决的核心矛盾是VLM语义理解与移动机器人物理执行间的断层，其切入点在于构建显式的System-2推理到System-0执行的标准化接口，通过多粒度CoT与GRPO优化推理-动作一致性。该框架在R2R-CE上达69.8% SR，在G1真实世界全任务成功率提升10.0个百分点，证明了显式推理对长时程移动操作的增益。然而，实验暴露出两个边界：一是8B骨干依赖远程GPU，延迟205-245ms限制了实时性；二是G1失败分析中抓取与操作错误占比最高，表明推理-动作接口在精细操作环节仍脆弱。当支持集增大或任务复杂度进一步提升时，显式推理的边际收益是否递减，以及推理延迟对动态环境响应的具体影响，论文未给出回答。
