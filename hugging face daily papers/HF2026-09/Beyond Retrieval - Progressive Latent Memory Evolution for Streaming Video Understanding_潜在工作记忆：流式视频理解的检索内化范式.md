# HuggingFace最新推荐论文 ｜Beyond Retrieval: Progressive Latent Memory Evolution for Streaming Video Understanding ｜潜在工作记忆：流式视频理解的检索内化范式

研究机构：南京大学、新加坡国立大学

论文原文见 [arXiv](https://arxiv.org/abs/2609.04131)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.04131)

> 流式视频理解要求模型在因果约束下处理无限视觉流，核心矛盾在于历史证据的存储与推理利用之间的解耦。现有方法将检索到的视觉证据作为外部上下文拼接，导致上下文膨胀且无法形成紧凑的潜在状态。LatentStream 提出“检索-内化”范式，通过层级潜在记忆令牌（LMTs）将证据内化为固定长度的潜在状态，并基于预测熵进行测试时优化。该框架在无需训练骨干网络的前提下刷新了 OVO-Bench 的免训练 SOTA，但其对多轮交互长程依赖的覆盖仍显不足。

## 研究背景

流式视频理解面临显存溢出与实时响应的双重约束。视觉 Token 随视频时长线性增长，直接输入会导致 GPU 显存耗尽，而滑动窗口或暴力压缩往往丢失长程依赖。为解决此问题，分层记忆架构（Hierarchical Memory Architecture）成为主流，它将历史观测组织为短期、中期和长期记忆，在固定预算下平衡细节保留与长程推理。然而，现有方法通常将记忆视为外部证据库，查询到达时检索相关视觉 Token 并拼接至上下文，这种“存储-检索”范式未能将证据内化为模型内部的紧凑状态，导致推理过程与记忆管理松散耦合。

2024 年至 2025 年，研究重心从被动感知转向主动响应与内存管理标准化。VideoLLM-Online 确立了静默/响应的二元范式，StreamingVLM 通过注意力沉没解决了无限流架构问题。2026 年，VST 等“边看边想”方法利用查询间隙进行自回归推理，但引入了额外的计算开销。LatentStream 的切入点在于质疑“检索即上下文”的默认假设：检索到的证据不应仅作为辅助视觉上下文，而应被内化为一个紧凑、查询条件化且持续演化的潜在工作记忆，直接参与后续推理，从而在有限显存下实现更深的语义整合。

## 核心方法

### 方法参照系

本文问题属于流式视频理解的内存管理路线。标准流程为：构建分层记忆库 → 查询到达时检索相关视觉证据 → 将证据拼接至上下文 → 生成响应。本文的关键差异在于，检索到的证据不再作为外部上下文保留，而是通过潜在记忆令牌（Latent Memory Tokens, LMTs）内化为固定长度的潜在状态，并在最终解码前移除原始视觉 Token。

### 层级潜在记忆演化

传统方法中，检索证据直接暴露给模型，导致上下文长度随检索量线性增加。LatentStream 引入 LMTs，将其分为短、中、长期三组，每组具有嵌套的检索感受野。设计动机是解决外部记忆与查询条件化推理的解耦问题，使模型能根据已内化的证据动态调整后续检索。在演化迭代 $r$ 中，LMT 组 $\hat{Z}^{(r)}_g$ 从对应记忆域 $C_g$ 检索证据，检索分数定义为候选视觉 Token $m_j$ 与 LMT 的最大余弦相似度：

$$
a^{(r)}_{g,j} = \max_{k \in \{1,\dots,K\}} \cos(m_j, \hat{Z}^{(r)}_{g,k})
$$

该公式确保检索过程由潜在状态引导，而非直接依赖查询向量，实现了查询语义在潜在空间中的隐式编码。

### 渐进置信度引导优化

检索证据注入后，需确定哪些证据对推理有益。LatentStream 提出渐进置信度引导的潜在记忆优化（PMO），利用冻结 MLLM 的预测熵作为内在反馈。设计动机是解决宽范围检索引入无关证据导致潜在演化不稳定的问题。层级进度奖励定义为：

$$
R_{prog}(U) = \sum_{g \in G} (1 - E_g(U)) + [E_s(U) - E_m(U)]^+ + [E_m(U) - E_l(U)]^+
$$

其中 $E_g(U)$ 为第 $g$ 组 LMT 的归一化 Top-$\delta$ 熵。该公式鼓励随着历史范围扩大，预测置信度单调递增，通过 REINFORCE 策略梯度更新 LMT 嵌入，实现无监督的测试时优化。

## 实验评估

实验基于 Qwen2.5-VL-3B/7B 骨干，在 OVO-Bench、StreamingBench、VideoMME、MLVU 和 LongVideoBench 上评估。基线覆盖免训练（FluxMem, OASIS）和训练型（ThinkStream, Streamo）方法，但缺失全模态交互类基线（如 Wan-Streamer）。

| 方法 | OVO-Bench | StreamingBench | VideoMME | MLVU |
| :--- | :--- | :--- | :--- | :--- |
| Qwen2.5-VL-7B | 54.0 | 63.3 | 67.9 | 60.7 |
| + FluxMem | 56.9 | 65.3 | 73.1 | 61.1 |
| + OASIS | 60.0 | – | – | – |
| + LatentStream | 64.2 | 66.6 | 74.0 | 62.1 |

LatentStream 在 OVO-Bench 上超越 OASIS 4.2 个百分点，在 VideoMME 上超越 FluxMem 1.3 个百分点，验证了内化机制优于传统检索拼接。

消融实验显示，仅使用绝对置信度优化（62.5%）优于无优化（58.1%），但加入层级进度奖励后提升至 64.2%，证明渐进置信度约束对长程依赖整合至关重要。演化迭代数 $R=4$ 时性能最佳，候选预算 $B=8$ 时达到峰值，进一步增加 $B$ 导致性能下降，表明有限的相关证据足以引导演化，过多候选引入冗余。

评估边界方面，论文未报告置信区间，数值比较需谨慎。TTFT 从 7.63s 增至 8.41s，TPOT 从 6.45ms 降至 3.16ms，峰值显存从 30.80GB 降至 21.97GB，显示内化机制在降低解码延迟和显存占用方面具有优势，但预填充延迟略有增加。代码未公开，超参数（如 $\sigma=10\%$）需自行复现。

## 关联研究分析

从问题动机看，LatentStream 与 VST 形成鲜明对比。VST 利用查询前的流式间隔进行显式自回归文本推理，构建双记忆系统，但引入了额外的 LLM Token 消耗和非可忽略的计算开销。LatentStream 则通过潜在空间优化实现“无显式 CoT”的深度推理，避免了文本生成的延迟，但在多轮交互任务（如 StreamingBench）上略逊于 VST（66.6% vs 79.5%），这可能源于潜在推理在长程语义连贯性上的局限。

从方法设计看，LatentStream 与 FluxMem 同属免训练分层记忆路线，但证据利用方式截然不同。FluxMem 将检索证据作为外部上下文拼接，导致上下文长度随检索量增长；LatentStream 将证据内化为 LMTs，最终解码前移除原始视觉 Token，实现了固定长度的潜在状态。这种设计挑战了“必须依赖 KV Cache 或外部上下文”的隐含假设，但 LMTs 是否真正承载了细粒度视觉信息（如 OCR 细节），论文未提供细粒度感知任务的专项验证。

## 总结

LatentStream 旨在解决流式视频理解中历史证据存储与推理利用解耦的矛盾。现有方法将检索证据作为外部上下文，导致上下文膨胀且无法形成紧凑的潜在状态；LatentStream 通过 LMTs 将证据内化为固定长度的潜在工作记忆，并基于预测熵进行测试时优化，在无需训练骨干网络的前提下实现了更深的语义整合。实验表明，该方法在 OVO-Bench 上取得 64.2% 的准确率，超越免训练 SOTA 4.2 个百分点，并在 VideoMME 上达到 74.0%。其边界在于，潜在推理在长程多轮交互任务上的表现仍落后于显式推理方法，且 LMTs 对细粒度视觉信息的承载能力缺乏专项验证。当视频时长超过 40 分钟时，LMTs 是否会出现信息饱和或遗忘，论文未给出回答。
