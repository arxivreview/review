> 测试时计算扩展（Test-Time Scaling, TTS）旨在通过增加推理阶段算力提升大语言模型性能，但现有方法多假设“思考更久”总能带来收益。本文指出小推理模型（sRM）的失败源于“执行瓶颈”与“知识瓶颈”的本质差异，单纯内部反思无法解决后者。FlyBy 框架通过强化学习训练模型在推理轨迹中动态识别知识缺口，并选择性地向更强外部模型发起多深度查询。该工作证明了“何时求助”比“如何思考”更关键，但其效果高度依赖外部模型的成本结构与查询接口的定义。

## 研究背景

当小推理模型（sRM）面对复杂任务时，其失败往往被归因于推理能力不足，导致研究者倾向于通过延长思维链或增加采样次数来弥补。然而，这种“内部扩展”策略忽略了参数化知识的缺失：即使模型具备逻辑推导能力，若缺乏特定领域的事实或定理，内部反思仅能固化错误路径，无法生成正确解。这一现象揭示了 TTS 的核心矛盾：计算资源的投入必须匹配当前推理状态的瓶颈类型，而非盲目增加时长。

现有 TTS 方法主要聚焦于并行采样聚合（如 Self-Consistency）或串行搜索（如 Tree of Thoughts），这些策略默认模型内部具备解决所有问题的潜在能力。然而，对于 sRM 而言，这种假设在科学、医学等知识密集型任务上失效。主流自适应计算分配方法（如 SCALE）仅调整内部 token 预算，未将“获取外部信息”纳入计算决策空间。FlyBy 的切入点在于将“外部模型查询”建模为推理轨迹中的原子动作，通过诊断中间状态是“可内部恢复”还是“需外部知识”，实现计算类型的动态切换。

## 核心方法

### 状态价值与熵的干预测量

FlyBy 的方法论基础是对推理中间状态 $s_t$ 的量化诊断。不同于传统方法仅关注最终答案，FlyBy 定义状态价值 $V(s)$ 为从该状态出发采样 $N$ 条续写轨迹中到达正确答案的比例，以及答案熵 $\mathcal{H}(s)$ 来衡量解的多样性。通过对比“无干预”与“插入反思提示”或“注入外部信息”后的状态变化，FlyBy 区分了执行瓶颈（$V(s)>0$，反思可提升价值）与知识瓶颈（$V(s)=0$，仅外部信息能提升价值）。这一机制解决了此前方法无法区分“思考不够”与“知识缺失”的模糊性，为后续策略提供了可操作的诊断信号。

### 多深度查询动作空间

FlyBy 将外部模型封装为具有成本梯度的工具。模型在推理过程中可发起查询动作，选择深度 $d \in \{1, 2, 3\}$，对应不同强度与成本的后端模型（如 DeepSeek-V4-Flash 至 Pro）。关键约束是外部模型仅接收查询内容，不接收原始问题，防止答案泄露。这一设计将“获取知识”转化为一个可学习的决策变量，而非固定的预处理步骤。其物理含义是：模型需权衡“内部推导的成本”与“外部查询的 API 成本”，在知识瓶颈处支付最小必要的外部算力。

### 成本感知强化学习校准

SFT 阶段仅让模型学会“如何查询”，RL 阶段则校准“何时查询”。FlyBy 采用修改后的 GRPO 目标函数，仅在轨迹成功时惩罚成本：

$$ r(x, y) = \mathbb{I}[y = y^*] (1 - \lambda \hat{C}(y)) $$

其中 $\hat{C}(y)$ 为归一化成本。该公式迫使策略在简单问题上保持低成本内部推理，仅在内部推理失效且外部信息能显著提升成功率时才发起查询。这一设计解决了 SFT 模型倾向于过度查询或查询无关信息的问题，实现了成本-收益的全局最优。

## 实验评估

| Qwen3-4B | 8.34 | 35.54 | 24.17 | 25.25 | 15.66 | 18.07 | 21.17 | 10.63 |
| Qwen3-14B | 14.46 | 52.63 | 43.85 | 59.30 | 32.82 | 46.78 | 41.64 | 20.35 |
| Search-R1 | 11.17 | 36.38 | 27.14 | 38.48 | 15.53 | 26.17 | 25.81 | 8.35 |

FlyBy-4B 在六个基准的平均性能上达到 45.96%，超越 Qwen3-14B 的 41.64%，且服务成本低 2.7 倍。基线覆盖了更大模型、检索增强（Search-R1）和前置查询（Query Opening），但缺失了纯并行采样（如 Best-of-N）在同等成本下的对比，这可能低估了 FlyBy 相对于简单采样策略的相对优势。

消融实验显示，SFT 后模型 pass@8 为 36.39%，RL 后提升至 45.96%，成本仅微增。关键发现是 RL 使模型从“单次查询”演变为“迭代查询”，在后续轮次保持高查询概率，且自适应深度分配以接近最浅后端的成本达到了接近最深后端的性能。这表明成本感知 RL 有效抑制了盲目求助，实现了计算资源的精细化调度。

评估协议限定于 Qwen3-4B pass@1 ≤ 0.25 的“难问题”子集，这解释了为何 FlyBy-4B 在 GPQA-D 上（60.01%）远低于领域综述中 SOTA 的整体准确率（89.0%）。指标完备性方面，论文报告了 pass@8 和成本，但未提供置信区间，且外部模型 API 价格波动可能影响成本结论的可复现性。代码已开源，但依赖特定的外部模型接口。

## 关联研究分析

从问题动机看，FlyBy 与 Search-R1 均旨在通过外部信息弥补 sRM 的知识缺口，但 Search-R1 将检索视为固定预处理，而 FlyBy 将其内化为推理过程中的动态决策。差异根源在于任务特性：科学推理中的知识缺口往往依赖于中间推理状态，前置检索无法精准定位缺失信息，而 FlyBy 的“先推理后查询”策略能根据当前状态生成针对性查询。

从方法设计看，FlyBy 与 SCALE 等自适应计算分配方法共享“动态预算”思想，但 SCALE 仅调整内部 token 长度，FlyBy 引入了外部 API 成本维度。这一扩展改变了 TTS 中“计算”的定义边界，将参数化推理与非参数化知识获取统一在成本-收益框架下。然而，FlyBy 未使用独立的过程奖励模型（PRM），而是通过 RL 内化判断能力，这可能导致在开放域任务上对查询时机的泛化能力弱于显式 PRM 引导的方法。

## 总结

FlyBy 解决了小推理模型在知识密集型任务上“内部反思无效”的核心矛盾，通过区分执行与知识瓶颈，将外部查询建模为可学习的成本感知动作。实验证明 FlyBy-4B 以 2.7 倍低成本超越 Qwen3-14B，验证了“选择性求助”优于“盲目思考”。其边界在于依赖外部模型的成本结构与查询接口，且仅在“难问题”子集上验证了优势。当外部模型 API 成本大幅波动或查询接口定义改变时，FlyBy 学到的成本-收益平衡策略是否仍能保持鲁棒，论文未给出回答。
