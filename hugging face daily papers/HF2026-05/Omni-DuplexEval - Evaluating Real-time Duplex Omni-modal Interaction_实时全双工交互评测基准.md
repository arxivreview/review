# HuggingFace最新推荐论文 ｜Omni-DuplexEval: Evaluating Real-time Duplex Omni-modal Interaction ｜实时全双工交互评测基准

研究机构：清华大学、同济大学

论文原文见 [arXiv](https://arxiv.org/abs/2605.17360)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.17360)

> 实时全双工交互要求模型在流式输入中同步完成感知与响应，但现有基准仅评估最终答案准确率，无法量化“何时说”与“持续说”的时序质量。本文通过构建包含连续描述与主动提醒的双场景基准，并引入联合评估时序与内容的自动评分框架，填补了这一空白。实验揭示当前模型在时序决策上存在根本性缺陷，但评估框架对模型静默行为的惩罚机制是否过度严苛，仍存疑。

## 研究背景

流式视频理解的核心约束是因果性，即模型在时间 $t$ 仅能访问 $t$ 之前的观测。这一约束将问题从静态识别转化为动态时序决策，模型不仅需理解内容，更需判断响应时机。然而，现有评测体系多基于离线范式，假设视频完整可见，导致模型在实时交互中的时序对齐能力无法被有效度量。

主流流式基准如 StreamingBench 和 OVO-Bench 虽引入流式设定，但主要依赖选择题格式，关注最终响应质量，忽略了连续生成过程中的时间同步性。OmniMMI 等基准虽提供开放式响应，但答案稀疏，难以评估实时适应性。ProactiveVideoQA 聚焦主动检测，却缺乏对时序动态的细粒度评估。这种评估维度的缺失，使得模型在“持续描述”与“事件触发”两种模式下的真实能力被掩盖。

本文切入点在于将实时全双工交互拆解为两个互补场景：实时描述（Real-Time Description）评估连续响应能力，主动提醒（Proactive Reminder）评估事件触发决策能力。通过引入时间戳级标注与联合评估框架，本文旨在量化模型在“说什么”与“何时说”上的双重表现，揭示现有模型在实时交互中的根本局限。

## 核心方法

### 双场景任务分类体系

本文基准包含 660 个视频，平均时长 34 秒，覆盖 9 个任务。实时描述场景包含计数（CT）、交互关系（IR）、全模态（Omni）、世界知识（WK）、OCR 和细粒度运动（FM）六个子任务，要求模型生成与视频演变同步的连续响应。主动提醒场景包含事件提醒（ER）、事后提醒（PER）和纠正（CR）三个子任务，要求模型在特定事件发生时触发响应。该设计将实时交互从单一问答解耦为连续流与离散事件两种模式，覆盖了真实场景中感知与响应的耦合特性。

### 联合时序与内容评估框架

针对实时描述场景，本文提出二维评估框架，联合计算内容一致性（Content Consistency, CC）与时序敏感度（Temporal Sensitivity, TS）。CC 通过 LLM-as-a-Judge 评估响应与视频-音频内容的全局语义对齐，采用扣分制惩罚事实错误与幻觉。TS 评估响应的实时对齐能力，引入四步流水线：首先通过语义相关性过滤剔除礼貌语等非实质输出，计算无关句比例 $r = |S_{irr}|/|S|$；其次构建 $k=4$ 个候选时间窗口以容忍约 2 秒的自然延迟；再次在每个窗口内以 2 FPS 采样视频帧并提取音频，由 LLM 评估句子与窗口的对齐度，取最大值为句子得分；最后计算平均得分并施加衰减惩罚。最终得分公式为：

$$ Score_{final} = Score_{CC} \times 0.5 + Score_{TS} \times 0.5 $$

其中 $Score_{TS} = f(score_1, \dots, score_n)$ 为相关句子的平均对齐分，并受无关句比例 $r$ 的衰减影响。该设计解决了传统评估仅关注最终答案、忽略时序噪声的问题，使模型在局部时序对齐与全局内容一致性上的权衡得以量化。

## 实验评估

实验在 Omni-DuplexEval 上评估了 LiveCC、StreamingVLM、MMDuet2 和 MiniCPM-o 4.5 等全双工模型，并对比了人类离线与全双工表现。基线覆盖了实时字幕生成（LiveCC）、无限流架构（StreamingVLM）及全模态交互（MiniCPM-o 4.5）等主流路线，但未包含纯离线 SOTA 模型作为上限参照，限制了性能边界的完整刻画。

| 模型 | Real-Time Description Avg | Proactive Reminder Avg | Overall |
| :--- | :--- | :--- | :--- |
| Human-Duplex | 70.8 | 81.8 | — |
| MiniCPM-o 4.5 | 59.1 | 20.0 | 39.6 |
| MMDuet2 | 58.4 | 24.2 | — |
| LiveCC-Inst | 42.9 | 11.9 | — |
| StreamingVLM | 36.2 | 1.0 | — |

MiniCPM-o 4.5 以 39.6 的整体得分领先，但远低于人类全双工表现。在主动提醒任务上，最佳模型仅得 20.0 分，揭示模型在“何时响应”上的严重不足。错误分布分析显示，MiniCPM-o 4.5 和 MMDuet2 主要错误为“无答案”（49.2% 和 75.8%），而 LiveCC 和 StreamingVLM 主要错误为“错误输出”（93.1% 和 96.7%），表明模型缺乏事件触发机制或无法准确定位事件时间戳。

实时描述场景中，模型在时序敏感度（TS）上表现相对较好，但在内容一致性（CC）上显著落后。例如，MiniCPM-o 4.5 的 TS 平均为 79.9，而 CC 仅为 38.3。这种差距源于模型的稀疏输出行为：为保持局部时序对齐，模型在视频大部分时间保持静默，导致全局内容覆盖不足。该发现揭示了实时描述中“完整性-及时性”权衡的根本矛盾，即模型难以在持续生成与精确时序对齐之间取得平衡。

评估边界方面，本文基准视频时长均小于 1 分钟，平均 34 秒，未覆盖长视频场景下的记忆管理挑战。LLM-as-a-Judge 框架的可靠性依赖于评估模型自身的时序理解能力，且未报告与人类判断的细粒度相关性系数。代码已开源，但评估框架的超参数（如候选窗口数量 $k=4$、采样帧率 2 FPS）对结果的影响未进行消融分析，可复现性受限于评估模型的版本与配置。

## 关联研究分析

从问题动机看，本文与 OVO-Bench 等基准的核心差异在于评估维度的扩展。OVO-Bench 关注流式因果约束下的答案准确率，而本文将时序对齐作为独立评估维度，要求模型在连续流中保持时间同步。这一差异源于任务特性的不同：OVO-Bench 侧重离散问答，本文侧重连续生成与事件触发。然而，本文未探索长视频场景下的记忆管理问题，其评估框架在视频时长超过 1 分钟时是否仍有效，论文未给出回答。

从方法设计看，本文与 StreamingVLM 等架构类工作的差异在于关注点不同。StreamingVLM 通过注意力沉没与连续 RoPE 解决无限流架构中的上下文断裂问题，属于模型内部机制优化；本文则聚焦于外部交互行为的评测，不涉及模型架构改动。这种差异暗示了流式视频理解领域的两个并行方向：架构效率与交互质量。本文揭示了交互质量的瓶颈，但未提供解决该瓶颈的架构方案，两者之间存在明显的互补空间。

## 总结

本文要解决的核心矛盾是实时全双工交互中“何时说”与“说什么”的联合评估缺失。现有基准仅关注最终答案准确率，无法量化时序对齐质量，而本文通过构建双场景基准与联合评估框架，首次系统性地度量了模型在连续描述与主动提醒中的时序表现。实验证明，当前最佳模型 MiniCPM-o 4.5 在主动提醒任务上仅得 20.0 分，远低于人类表现，揭示了模型在事件触发决策上的根本缺陷。本文的边界在于视频时长限制（<1 分钟）与评估框架对静默行为的惩罚机制，未覆盖长视频场景。当视频时长增加至分钟级时，模型的静默行为是否源于记忆管理失效而非时序决策能力不足，论文未给出回答。
