> 指令式图像编辑的瓶颈已从生成质量转移至奖励信号的可靠性，现有基于大规模偏好标注训练奖励模型的范式成本高且无法适配冻结模型。本文指出人类仅需少量演示即可内化评估标准，而模型需数十万条数据，这一数据效率不对称是核心矛盾。REWARDHARNESS 将奖励建模重构为上下文演化，通过迭代优化外部的技能与工具库替代权重更新。该框架在数据效率上取得突破，但其评估精度是否足以支撑复杂多轮编辑的物理一致性验证，仍存疑。

## 研究背景

指令式图像编辑的强化学习对齐依赖能忠实反映人类偏好的奖励信号。传统范式通过收集大规模人类偏好标注并训练专用奖励模型（如 EditReward），但这一流程存在标注成本高、模型不透明且无法应用于 API 封闭模型等局限。图像编辑的偏好判断具有多维性和细微性，需同时理解指令、源图与编辑结果，使得单一标量奖励难以捕捉细粒度差异。

当前领域共识认为，扩散模型与流匹配模型是主流骨干，而多模态大语言模型（MLLMs）在复杂指令理解中至关重要。然而，现有奖励模型普遍依赖监督微调（SFT）从数万至数十万条偏好对中学习，导致数据效率低下。人类标注者能从少量校准集内化评估标准并一致应用，而模型需海量数据习得类似行为，这一不对称性揭示了现有范式在数据利用上的根本缺陷。REWARDHARNESS 的切入点在于，不将少量演示用于训练更小的奖励模型，而是将其用于迭代构建显式、可复用的评估知识库，从而在冻结模型权重的前提下实现数据高效的偏好对齐。

## 核心方法

### 方法参照系

本文问题归属于“推理与规划框架”在奖励建模领域的变体。标准流程是训练一个端到端的奖励网络，输入图像与指令，输出标量分数。本文的关键差异在于冻结评估模型权重，将适应性从参数更新转移至外部上下文（Skills 与 Tools 库）的演化，实现了评估逻辑的外化与可解释性。

### 技能与工具库的结构化定义

设计动机在于解决传统奖励模型输出不透明、无法细粒度定位错误根源的问题。REWARDHARNESS 维护一个版本化的库，包含声明式的评估准则（Skills）与程序化的视觉分析规范（Tools）。Skills 定义评分细则，如区分概念不真实与视觉伪影；Tools 定义特定分析流程，如 OCR 文本校验。Sub-Agent 作为冻结的 VLM，读取库中条目后临时扮演专家角色，构建推理链。其评分过程可形式化为：

$$ \mathbf{s} = M(I_s, \{I_k\}_{k=1}^K, p, C) $$

其中 $M$ 为冻结 VLM，$C$ 为 Orchestrator 检索并注入的 Skills 与 Tools 上下文。该公式表明，偏好分数完全由外部上下文 $C$ 驱动，而非模型内部参数，使得评估行为可被直接编辑与审计。

### 自演化循环与门控机制

设计动机在于解决静态提示工程无法适应复杂评估场景、且缺乏错误反馈闭环的问题。Orchestrator 驱动一个五阶段循环：评估、打分、链分析、库更新、验证门控。在链分析阶段，Orchestrator 对错误预测进行根因分析，判断失败源于缺失准则、准则应用错误还是感知幻觉，并据此提出库更新提案。验证门控机制确保只有当验证集准确率提升时才接受更新，否则回滚。最终库状态的选择基于验证集最高准确率，其相对提升可表示为：

$$ \Delta_{acc} = \frac{Acc_{final} - Acc_{empty}}{Acc_{empty}} $$

其中 $Acc_{final}$ 为最终库的验证准确率，$Acc_{empty}$ 为空库基线准确率。该机制通过保守门控防止性能退化，并通过激进剪枝移除探索期积累的冗余条目，最终收敛至紧凑且高效的评估配置。

## 实验评估

实验在 EditReward-Bench 与 GenAI-Bench 上评估偏好判断精度，并在 ImgEdit-Bench 上验证下游 RL 效果。基线覆盖专有模型（GPT-5, Gemini）与开源模型（EditReward, Qwen2.5-VL），但缺失基于 DPO 的奖励模型对比，可能高估了上下文演化相对于其他对齐技术的优势。

| 方法 | EditReward-Bench Avg. | GenAI-Bench | 整体平均 |
| :--- | :--- | :--- | :--- |
| GPT-5 | 42.1 | – | 42.1 |
| EditReward (MiMo) | 44.1 | – | 44.1 |
| REWARDHARNESS (Qwen) | 45.7 | 67.5 | 45.7 |
| REWARDHARNESS (Gemini) | 47.4 | 64.4 | 47.4 |

REWARDHARNESS (Gemini) 以 47.4% 的平均准确率领先，较 GPT-5 提升 5.3 点，较 EditReward (MiMo) 提升 3.3 点。在相同 Qwen2.5-VL-7B 骨干下，REWARDHARNESS 比 EditReward (Qwen) 高 3.7 点，证明增益源于框架而非骨干。

| 方法 | ImgEdit-Bench Overall |
| :--- | :--- |
| FLUX.2-klein-base-4B | 3.32 |
| +RL (EditReward) | 3.45 |
| +RL (REWARDHARNESS) | 3.52 |

在下游 RL 任务中，REWARDHARNESS 作为奖励信号使 FLUX.2-klein-base-4B 的整体得分从 3.32 提升至 3.52，优于 EditReward 的 3.45。这表明其提供的训练信号在 GRPO 框架下更具有效性，尤其在 Adjust 与 Background 类别上增益显著。

评估边界方面，论文未报告置信区间，数值比较需谨慎。代码与超参数未完全公开，仅提供项目页面，可复现性受限。指标聚焦于排名准确率与下游编辑得分，未覆盖计算效率维度，如推理延迟与函数评估次数，这在实时部署场景中是关键考量。

## 关联研究分析

从问题动机看，REWARDHARNESS 与 EditReward 均旨在解决图像编辑偏好评估的细微性，但 EditReward 依赖 200K 偏好对进行 SFT，而本文仅用 100 条演示。这一差异源于对“评估知识”本质的不同假设：EditReward 假设知识隐含于模型参数中，需大量数据拟合；本文假设知识可外化为结构化文本，通过上下文学习即可激活。这种假设在数据稀缺场景下更具优势，但在数据充足时，参数化模型可能因规模效应而反超，论文未对此进行对比。

从方法设计看，REWARDHARNESS 借鉴了 Reflexion 等自演化智能体的“反思-更新”机制，但将记忆外化为可组合的 Skills 与 Tools 库，而非单一提示。与 ReAct 等工具增强 LLM 不同，本文的工具集本身是演化对象，而非固定接口。这一设计使得评估逻辑具备模块化与可审计性，但也引入了库维护的复杂性。当评估标准发生漂移时，库的演化速度是否能跟上，以及剪枝机制是否会过度移除潜在有用条目，是框架泛化性的关键制约。

## 总结

REWARDHARNESS 针对图像编辑奖励建模中数据效率低下的核心矛盾，通过冻结模型权重并演化外部 Skills 与 Tools 库，实现了仅用 100 条演示即可超越大规模 SFT 奖励模型的效果。其核心贡献在于证明了结构化评估知识可通过上下文演化获得，而非必须依赖参数更新。实验显示，该框架在 EditReward-Bench 上达到 47.4% 平均准确率，并在下游 RL 中取得 3.52 的 ImgEdit-Bench 得分，优于 EditReward 基线。然而，其评估精度在复杂多轮编辑与物理一致性验证场景中是否足够，以及库演化在长期任务中的稳定性，论文未提供充分证据。当支持集从 100 条扩展至 1000 条时，上下文演化的边际收益是否递减，论文未给出回答。
