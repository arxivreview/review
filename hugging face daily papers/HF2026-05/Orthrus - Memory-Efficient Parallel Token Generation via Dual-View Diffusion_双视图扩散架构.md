# HuggingFace最新推荐论文 ｜Orthrus: Memory-Efficient Parallel Token Generation via Dual-View Diffusion ｜双视图扩散架构

研究机构：美国俄勒冈大学、谷歌DeepMind

作者：Chien Van Nguyen、Chaitra Hegde、Van Cuong Pham 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.12825)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.12825)

> 自回归模型（AR）的串行解码导致推理延迟高企，而扩散语言模型（DLM）虽能并行生成却常伴随分布漂移与性能损失。现有适配方法通过修改AR权重实现并行，但往往需海量数据且无法保证输出与原始AR模型分布一致。Orthrus提出一种双视图架构，冻结AR骨干以维持高保真上下文，外挂轻量级扩散头进行单步并行投影，并通过模型内共识机制验证输出。该设计在保持AR精确预测分布的前提下实现了最高7.8倍加速，但其单步投影策略在长序列复杂推理中的泛化边界尚待检验。

## 研究背景

自回归解码的瓶颈源于生成阶段的串行依赖：每生成一个Token需执行一次前向传播并更新Key-Value（KV）缓存，造成内存带宽瓶颈。扩散语言模型（DLM）通过掩码扩散范式将生成视为并行去噪过程，理论上可一次性恢复多个Token，但其条件独立性假设破坏了严格的因果依赖，导致预测分布偏离AR目标分布。这种分布漂移在长序列推理任务中会迅速累积，造成性能显著下降。

主流解决路线分为两类：一是从头训练大规模DLM（如LLaDA、Dream），虽能实现并行但需数百亿Token训练且性能仍逊于同级AR模型；二是将预训练AR模型适配为DLM（如Fast-dLLM、SDAR），通过微调权重引入并行能力，但此类方法通常需持续预训练50B至500B Token，且因架构改变导致原始AR分布不可恢复。Orthrus的切入点在于识别AR瓶颈仅存在于生成阶段，其自注意力机制在构建上下文表示时仍是最优的，因此无需修改AR权重，而是通过结构增强实现并行生成与分布保真的解耦。

## 核心方法

### 双视图注意力机制

本文问题与标准DLM训练流程的关键差异在于：不改变AR骨干权重，而是引入独立的扩散注意力模块共享同一KV缓存。在标准Transformer中，注意力头处理序列时生成KV表示供后续层使用。Orthrus在每个Transformer层中并行嵌入一个可训练的扩散注意力模块，其投影矩阵$W_Q^{diff}, W_K^{diff}, W_V^{diff}$从冻结的AR对应矩阵初始化。扩散头处理由锚点Token和$K-1$个`<mask>`Token组成的扩展块，其查询同时关注冻结AR缓存和块内双向自表示。由于AR缓存原地复用，扩散头不引入额外历史KV缓存存储，仅更新约16%的模型参数。

### 单步并行投影与共识验证

设计动机在于解决多步迭代去噪导致的吞吐量下降与分布漂移。扩散头在单次前向传播中投影出$K$个候选Token $\hat{y} = (\hat{y}_1, ..., \hat{y}_K)$，其分布为：

$$ p_{diff}(\hat{y} | \mathbf{x}_{<t}, \tilde{y}_t) $$

随后，冻结AR头对完全填充的块执行单次前向传播，计算精确目标分布 $p_{AR}(v | \mathbf{x}_{\leq t}, \hat{y}_{1:k-1})$。共识机制通过严格左到右评估同步Token：若投影Token $\hat{y}_k$ 与AR贪心预测一致则保留；若发生分歧，则提交前缀并采用AR修正Token，截断KV缓存至当前步。对于温度采样，采用精确拒绝采样保证无损性。该机制确保最终输出严格匹配基础AR模型的预测分布，消除了条件漂移。

## 实验评估

实验基于Qwen3-1.7B/4B/8B模型，在GSM8K、MATH-500、AIME、HumanEval等基准上评估。基线覆盖Dream、LLaDA-1.5、Fast-dLLM-v2、SDAR等主流DLM，但缺乏与同规模纯AR模型（如Qwen3-8B AR）的详细消融对比，仅提及Fast-dLLM-v2相对其AR基线有11.1点下降。

| 模型 | 参数 | GSM8K | MATH-500 | HumanEval | MBPP |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Dream-7B | 7B | 79.3 | 39.6 | 57.9 | 58.8 |
| LLaDA-1.5 | 7B | 82.4 | 57.4 | 52.4 | 42.8 |
| Fast-dLLM-v2 | 7B | 83.7 | 61.5 | 43.3 | 28.2 |
| SDAR-Qwen3-8B | 8B | 91.7 | 78.6 | 78.7 | 72.0 |
| Orthrus-Qwen3-8B | 8.7B | 96.0 | 86.2 | 95.1 | 93.4 |

Orthrus-Qwen3-8B在GSM8K上达到96.0%，MATH-500上达到86.2%，显著优于SDAR-Qwen3-8B（91.7%和78.6%）及其他DLM基线。在加速性能上，8B模型平均Tokens Per Forward Pass (TPF)为5.39，最高加速比达7.83倍（LiveCodeBench-v5任务）。

消融实验验证了单步投影策略的有效性。对比多步去噪变体，单步策略的TPF为6.35，而两步策略仅3.53，吞吐量降低1.8倍。块大小$K$从4增至32时，TPF从1.85增至6.35，且前向传播延迟保持恒定，表明并行扩展无额外延迟惩罚。

评估边界方面，论文未报告置信区间，且“无损”声明基于贪心解码下的精确匹配，未提供大规模统计检验证明分布一致性。代码已开源，训练仅需单节点8xH200 GPU，24小时内完成，超参数（$K=32$, 600K样本）明确，可复现性较高。

## 关联研究分析

从问题动机看，Orthrus与Fast-dLLM-v2均旨在解决DLM推理效率问题，但路线截然不同。Fast-dLLM-v2通过修改AR权重并采用多步迭代去噪实现并行，导致MATH-500性能下降11.1点；Orthrus则冻结AR权重，仅外挂扩散头，通过共识机制保证分布一致性。根源在于Fast-dLLM-v2将并行生成视为对AR模型的“转换”，而Orthrus将其视为AR模型的“增强”，前者牺牲了原始分布保真度，后者通过结构隔离保留了AR的高保真表示。

从方法设计看，Orthrus与投机解码（Speculative Decoding）共享“草稿-验证”逻辑，但存在关键差异。投机解码依赖外部草稿模型，需维护独立KV缓存，内存开销大；Orthrus将扩散头内化于AR模型中，共享同一KV缓存，实现零冗余历史缓存存储。这一差异源于Orthrus的双视图架构设计，使得扩散头能直接访问AR构建的高保真上下文，而投机解码的草稿模型通常容量较小，上下文表示质量受限。

## 总结

Orthrus旨在解决AR模型串行解码延迟与DLM并行生成分布漂移之间的矛盾。其切入点在于识别AR瓶颈仅存在于生成阶段，通过冻结AR骨干并外挂轻量级扩散头，利用模型内共识机制验证输出，从而在保持AR精确预测分布的前提下实现并行加速。实验证明，该方法在GSM8K上达到96.0%，MATH-500上达到86.2%，最高加速比7.83倍，显著优于现有DLM适配方法。然而，论文仅验证了单步投影在标准基准上的有效性，未探讨其在长序列复杂推理任务中是否会导致条件漂移累积，当序列长度超过2048 Token时，共识机制的验证开销是否会抵消并行加速收益，论文未给出回答。
