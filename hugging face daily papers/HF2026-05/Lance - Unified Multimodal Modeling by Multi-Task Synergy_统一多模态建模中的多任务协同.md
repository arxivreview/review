# HuggingFace最新推荐论文 ｜Lance: Unified Multimodal Modeling by Multi-Task Synergy ｜统一多模态建模中的多任务协同

论文原文见 [arXiv](https://arxiv.org/abs/2605.18678)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.18678)

> 统一多模态模型（UMM）旨在单一架构内融合视觉理解与生成，但现有方案常因表征冲突导致性能妥协，且任务覆盖局限于图文域。Lance 指出，广泛的多任务联合训练能激发跨模态迁移，而非简单能力叠加。该模型通过双流混合专家架构与模态感知位置编码，在 3B 参数下实现了图像与视频的全谱系理解、生成与编辑。其价值在于验证了小模型下多任务协同的有效性，但缺乏闭环评估指标以量化“理解辅助生成”的具体增益。

## 研究背景

当视觉理解模型追求语义抽象时，其高层特征与生成模型所需的低层连续表征（如纹理、几何）在共享参数空间内产生梯度冲突。这种表征错位导致联合训练时一方性能提升往往以另一方下降为代价，即“伪统一”现象。为解决此问题，主流路线分为两类：一类采用统一视觉表征（如 Chameleon），虽架构简洁但难以平衡推理与保真度；另一类采用解耦表征（如 Janus、BAGEL），通过分离编码器缓解冲突，但增加了架构复杂度且知识共享减弱。此外，现有 UMM 多局限于文本-图像域，视频理解与生成通常作为下游微调技能，缺乏在统一多任务训练中的系统性优化。

Lance 的切入点在于将多任务学习视为促进跨模态迁移的机制，而非单纯的能力聚合。它主张通过覆盖 X2T（任意到文本）、X2I（任意到图像）、X2V（任意到视频）的全谱系任务，在统一上下文中激发任务间的正向互益。这一设计直接回应了领域内关于“任务覆盖广度是否带来涌现泛化”的争议，并试图在轻量级模型（3B 激活参数）中验证多任务协同对表征冲突的缓解作用，区别于依赖大规模参数堆叠的 BAGEL 或 Show-o2。

## 核心方法

### 混合 AR-Diffusion 架构参照系

Lance 属于混合自回归-扩散（AR-Diffusion）路线，其标准流程是在单一 Transformer 骨干中，文本使用自回归（AR）预测，视觉使用扩散或流匹配（Flow Matching）预测。与 BAGEL 等大规模模型不同，Lance 的关键差异在于引入双流混合专家（Dual-stream MoE）结构，将解耦从编码器层面扩展至骨干网络层面，以在共享上下文的同时保留任务特异性容量。

### 双流混合专家与解耦能力路径

在标准混合架构中，理解与生成任务共享同一组 Transformer 层，导致语义抽象与像素保真目标在梯度更新中相互干扰。Lance 采用双流 MoE 架构，将骨干分为 $LLM_{UND}$ 和 $LLM_{GEN}$ 两个专家流，分别处理语义推理与视觉合成。对于输入序列，模型通过路由机制将 Token 分配至对应专家，并在共享的交错多模态序列上执行广义 3D 因果注意力。其核心损失函数结合自回归交叉熵与流匹配速度预测：

$$ \mathcal{L} = \mathcal{L}_{AR}(\hat{y}_{text}, y_{text}) + \lambda \mathcal{L}_{Flow}(\hat{v}, v_{target}) $$

其中 $\mathcal{L}_{AR}$ 为文本 Next-token Prediction 损失，$\mathcal{L}_{Flow}$ 为视觉潜空间的速度预测损失。这种设计使得理解任务依赖的高层语义特征与生成任务依赖的低层连续特征在物理路径上分离，避免了共享参数上的梯度冲突，同时通过共享上下文实现了信息交互。

### 模态感知旋转位置编码（MaPE）

在统一序列中，文本 Token、ViT 语义 Token 与 VAE 视觉 Token 具有不同的模态属性与空间结构，标准旋转位置编码（RoPE）无法区分这种异构性，导致位置干扰。Lance 引入 MaPE，根据 Token 的模态类型动态调整旋转角度，以缓解异构视觉 Token 在统一上下文中的位置冲突。其位置编码计算可表示为：

$$ \mathbf{p}_i = \mathbf{R}(\theta_{modality(i)} \cdot i) \mathbf{e}_i $$

其中 $\theta_{modality(i)}$ 为根据第 $i$ 个 Token 模态确定的频率参数。这一改进增强了跨任务上下文对齐，特别是在视频生成中，MaPE 有助于维持时序一致性，解决了传统 RoPE 在处理长序列视频 Token 时可能出现的时序漂移问题。

## 实验评估

Lance 在 128-GPU 预算下训练，对比基线包括 Show-o2、BAGEL 等主流 UMM，但缺失 FLUX 等专用扩散模型的直接对比，限制了生成保真度的绝对评估。在视频理解基准上，Lance 取得 62.0 的综合得分，较次优统一模型 Show-o2 7B 相对提升约 11.3%，且仅使用 3B 激活参数，表明多任务训练在保持理解能力的同时未牺牲生成能力。

| 模型 | 参数规模 | 视频理解综合得分 | 相对提升 |
| :--- | :--- | :--- | :--- |
| Lance | 3B | 62.0 | +11.3% vs Show-o2 |
| Show-o2 | 7B | 55.7* | - |

*注：55.7 为根据 62.0 与 11.3% 相对提升反推的近似值，原文未直接列出 Show-o2 具体分数，此处仅展示 Lance 的绝对得分与相对优势。*

消融实验显示，引入理解数据（Gen.:Und. = 8:2）同时提升了图像与视频生成质量，表明理解数据为视觉合成提供了语义锚点。多任务生成数据（Gen.:MT-Gen. = 6:4）不仅增强生成能力，还意外提升了视频理解性能，证实了跨任务正向迁移的存在。MaPE 的移除导致视频理解得分从 80.94 降至 80.56，图像编辑从 6.86 降至 6.30，验证了位置编码对异构 Token 协调的关键作用。

评估边界方面，论文未报告 GenEval 等图像生成标准基准的具体总分，仅声称超越开源 UMM，缺乏与专用 SOTA 的量化对比。代码未开源，仅提供项目页面，限制了可复现性。此外，缺乏闭环评估指标，无法量化“理解是否真正辅助了生成”的因果贡献，多任务协同的机制仍停留在相关性层面。

## 关联研究分析

从方法设计看，Lance 的双流 MoE 与 BAGEL 的专家分离思路相似，但 BAGEL 侧重大规模交错数据下的专家专业化，而 Lance 强调小模型下的多任务数据调度。Lance 的解耦发生在骨干层，而 Janus 的解耦仅在编码器层，这意味着 Lance 在生成路径上拥有独立的容量，可能更彻底地缓解梯度冲突，但也可能削弱理解与生成间的深层知识共享。Lance 未探索解耦程度对协同效应的边际影响，即完全解耦是否会导致“伪统一”的另一种形式——模块间缺乏交互。

从问题动机看，Lance 将多任务学习视为解决表征冲突的手段，这与 Transfusion 等混合架构仅关注目标函数混合不同。Lance 引入 MaPE 解决异构 Token 位置干扰，这是 Show-o2 等视频统一模型未明确处理的细节。然而，Lance 未对比 MaPE 与标准 RoPE 在纯文本或纯图像任务上的性能差异，无法排除 MaPE 的增益是否源于位置编码本身的改进而非多任务协同。此外，Lance 未讨论 3B 参数下多任务协同是否因容量限制而失效，需更大规模验证。

## 总结

Lance 旨在解决统一多模态模型中理解与生成的表征冲突及任务覆盖局限，其切入点是通过广泛的多任务联合训练激发跨模态迁移，而非依赖参数规模。该模型采用双流 MoE 架构与 MaPE，在 3B 参数下实现了视频理解综合得分 62.0，较 Show-o2 提升 11.3%。其边界在于缺乏与专用扩散模型的直接对比，且未提供闭环评估指标以量化多任务协同的因果贡献。当模型规模扩大至 7B 以上时，双流 MoE 的解耦优势是否会被共享参数的规模效应所抵消，论文未给出回答。
