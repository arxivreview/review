> 智能体搜索在广度任务中面临实体覆盖不全与上下文饱和的双重瓶颈，现有单体或固定分解架构无法在数百行结构化数据中维持一致性。Web2BigTable 通过双层自进化记忆机制，将任务分解与执行策略外化为可编辑技能库，实现无梯度下的规划-执行协同优化。该框架在 WideSearch 上取得 38.50 的 Avg@4 Success Rate，显著超越现有基线，但其性能增益高度依赖训练集规模与技能泛化能力，边界尚待验证。

## 研究背景

当智能体需要从开放网络中提取数百个实体的结构化属性时，单体架构的上下文窗口迅速饱和，且初始固定的分解策略无法适应后续检索中发现的覆盖缺口。这一困境源于广度搜索（Wide Search）与深度搜索（Deep Search）的本质差异：前者要求对大量实体进行并行、一致的证据验证，后者仅需对单一目标进行长程推理。传统多智能体框架虽通过任务分解缓解上下文压力，但依赖静态启发式规则，缺乏从执行反馈中修正分解策略的机制，导致系统性覆盖遗漏。

智能体搜索领域的核心矛盾在于规划僵化与执行动态性的不匹配。主流路线如 Search-R1 依赖强化学习优化单体策略，但梯度更新难以捕捉长程任务中的细粒度信用分配；M-ASK 等多智能体框架通过角色分工提升鲁棒性，但分解策略仍为预设或弱自适应。Web2BigTable 的切入点在于将规划与执行解耦为两个独立演化的记忆层，通过外部技能库实现无参数更新的策略迭代，直接回应了“如何在不修改模型权重的前提下，使分解策略随执行反馈动态调整”这一关键问题。

## 核心方法

### 双层策略分解参照系

本文问题最接近多智能体协同架构中的任务分解-执行范式，但关键差异在于：传统方法将分解策略硬编码或依赖固定启发式，而 Web2BigTable 将分解与执行策略外化为可独立演化的技能库，实现规划与执行的联合自进化。

### 双层技能库自进化机制

设计动机：解决固定分解策略在复杂查询中导致的系统性覆盖缺口。传统方法中，分解策略在任务开始时确定且不可变，无法根据执行中发现的实体分布调整。Web2BigTable 引入 Orchestrator Skills $S_o$ 与 Worker Skills $S_w$，通过 Run-Verify-Reflect 闭环更新：

$$
S_{o[k+1]} \leftarrow M_o(S_{o[k]}, r_{o[k+1]}), \quad S_{w[k+1]} \leftarrow M_w(S_{w[k]}, r_{o[k+1]})
$$

其中 $r_{o[k+1]}$ 是基于 Item-F1 计算的结构化错误报告，$M_o$ 和 $M_w$ 为 LLM 驱动的单调更新算子。该机制将最终表格质量信号反向传播至分解与执行策略，使技能库随训练迭代持续优化，无需梯度更新。

### 异步工作板协调机制

设计动机：解决并行 Worker 间的冗余探索与证据冲突。传统多智能体框架中，Worker 独立执行且无法共享中间发现，导致重复检索与覆盖遗漏。Web2BigTable 引入共享工作板 $m_e$，通过文件锁与标签分区实现异步协调：

$$
m_{e[t+1]} \leftarrow M_e(m_{e[t]}, \{h_{i[t+1]}\}_{i \in A[t]})
$$

其中 $A[t]$ 为当前活跃 Worker 集合，$M_e$ 为合并算子。Worker 仅读取与自身子任务相关的工作板切片，降低单步上下文成本，同时通过共享状态实现冲突消解与缺口填补。

## 实验评估

实验在 WideSearch（广度）与 XBench-DeepSearch（深度）上进行，基线覆盖单体 LLM、端到端系统及多智能体框架，但未对比基于 RL 训练的 Search-R1 等强基线。

| 配置 | WideSearch Avg@4 SR | WideSearch Avg@4 Row F1 | WideSearch Avg@4 Item F1 | XBench Acc |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5 mini (single agent) | 4.00 | 33.28 | 3.00 | 35.0 |
| Gemini 3 Flash (single agent) | 22.10 | 18.70 | 31.61 | 28.0 |
| **Web2BigTable** | **38.50** | **63.53** | **80.12** | **73.0** |

Web2BigTable 在 WideSearch 上取得 38.50 的 Avg@4 Success Rate，为第二佳（5.10）的 7.5 倍，Item F1 达 80.12，显著超越所有单体与多智能体基线。

| 消融配置 | WideSearch Row F1 | XBench Acc |
| :--- | :--- | :--- |
| Web2BigTable (full) | 63.53 | 73.0 |
| w/o orchestrator skills | 45.23 | 41.0 |
| w/o workboard | 54.81 | 60.0 |
| w/o worker skills | 59.67 | 64.0 |

移除 Orchestrator Skills 导致 WideSearch Row F1 从 63.53 降至 45.23，降幅最大，证实双层策略学习是性能主要驱动力；移除工作板使 XBench Acc 从 73.0 降至 60.0，表明异步协调对深度任务泛化至关重要。

评估协议采用 Avg@4 与 Max@4 报告，但未提供置信区间；代码已开源，但训练集仅 20 个查询，技能库规模与收敛速度未量化；未报告计算成本与延迟，可复现性受限于模型 API 访问。

## 关联研究分析

从优化范式看，Web2BigTable 与 Search-R1 形成鲜明对比：后者依赖 RLVR 通过梯度更新优化单体策略，前者通过外部记忆实现无梯度策略演化。这一差异源于任务特性：广度搜索的分解策略具有强组合性，梯度更新难以捕捉离散分解决策的信用分配，而记忆更新可直接存储与检索成功分解模式。然而，无梯度方法在需要精细数值推理或连续状态估计的任务上是否失效，论文未给出回答。

从架构设计看，Web2BigTable 与 M-ASK 同属多智能体框架，但 M-ASK 侧重角色分工解决长程信用分配，Web2BigTable 侧重技能自进化解决规划僵化。M-ASK 的分解策略仍依赖预设角色，而 Web2BigTable 的 Orchestrator Skills 可随训练迭代演化，使分解策略适应具体查询结构。这一差异表明，多智能体框架的性能瓶颈可能不在执行并行度，而在规划策略的适应性，但技能库跨任务迁移能力未经验证。

## 总结

Web2BigTable 针对广度搜索中规划僵化与执行动态性的矛盾，通过双层技能库自进化与异步工作板协调，实现了无梯度下的规划-执行协同优化。该框架在 WideSearch 上取得 38.50 的 Avg@4 Success Rate 与 80.12 的 Item F1，显著超越现有基线，证实了记忆驱动策略演化的有效性。其边界在于训练集规模有限（20 个查询），技能库泛化能力未量化，且未对比 RL 基线。当训练集扩大至数百个查询时，技能库的收敛速度与稳定性是否保持，论文未给出回答。
