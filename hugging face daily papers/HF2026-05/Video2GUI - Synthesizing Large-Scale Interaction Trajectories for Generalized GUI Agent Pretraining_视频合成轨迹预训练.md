# HuggingFace最新推荐论文 ｜Video2GUI: Synthesizing Large-Scale Interaction Trajectories for Generalized GUI Agent Pretraining ｜视频合成轨迹预训练

研究机构：小米、北京大学

作者：Weimin Xiong、Shuhao Gu、Bowen Ye 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.14747)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.14747)

> GUI智能体泛化能力受限于高质量交互轨迹数据的稀缺，现有方案依赖昂贵的人工标注或受限的仿真环境，难以覆盖真实世界的多样性。本文切入点在于利用互联网视频中天然存在的操作演示，通过自动化管线将其转化为结构化训练数据。具体做法是构建Video2GUI框架，从5亿视频元数据中筛选并提取1200万条轨迹，形成WildGUI数据集进行持续预训练。该工作验证了大规模离线视频数据对静态定位与规划任务的有效性，但在动态在线环境中的增益有限，其作为RL前置基础的定位尚需进一步验证。

## 研究背景

GUI智能体在部分可观测马尔可夫决策过程（POMDP）中运行，其策略 $\pi_\theta$ 需根据历史交互 $e_{t-1}$ 选择动作 $a_t$。动作参数化包含类型 $\tau_t$ 与空间坐标 $b_t$，后者要求模型具备像素级视觉定位能力。由于真实GUI环境状态转移 $T: S \times A \to S$ 复杂且不可完全观测，模型必须在未见过的应用界面中保持鲁棒的感知-决策闭环，这直接依赖于训练数据对界面异构性的覆盖程度。

当前主流数据获取路径存在显著瓶颈：人工标注成本高且规模受限，仿真环境虽可控但缺乏真实世界的噪声与多样性。SeeClick等工作奠定了视觉接地数据基础，但静态截图难以捕捉长程交互的时序依赖。UI-Voyager尝试复用内部失败经验，但受限于模型自身探索范围。核心矛盾在于，模型在训练分布外的新应用或新OS上性能显著下降，根源在于训练数据多样性有限，而现有自动化生成方法尚未解决从非结构化视频到精确空间坐标的映射难题。

## 核心方法

### 方法参照系

GUI智能体训练通常遵循“数据构建-监督微调（SFT）”范式。标准流程假设数据已具备精确的动作-状态对齐，直接用于策略优化。本文的关键差异在于，数据源为非标注互联网视频，缺乏显式交互标签，且视频压缩导致分辨率不足，无法直接用于像素级定位训练。因此，方法核心从“数据利用”前移至“数据合成”，需解决从原始视频到结构化轨迹的自动化转换。

### 粗到细视频过滤

针对互联网视频规模大、噪声高的问题，本文采用两级过滤策略。第一级基于元数据，利用DeepSeek-V3标注1万样本微调Qwen2.5-7B分类头，从5亿视频中筛选出约2000万候选。第二级引入视觉评分模型，提取视频首分钟，从主题相关性、指令清晰度、录屏质量三个维度评估。该设计解决了元数据过滤无法识别低质量录屏或广告内容的问题，最终保留416万视频（约30万小时），确保训练数据的高信噪比。

### 轨迹提取与空间接地

轨迹提取阶段利用Gemini-3-Pro将视频转化为指令-轨迹对。为处理长视频上下文限制，采用滑动窗口策略，每个片段最长4分钟，并携带前序片段提取结果作为文本上下文，以维持长程记忆。空间接地阶段解决视频压缩导致的定位模糊问题。对于时间戳 $t$ 的动作，提取 $t-0.5s, t, t+0.5s$ 三帧高分辨率图像，由VLM判断哪一帧可定位并预测边界框。接地动作定义为：

$$ a_t = (\tau_t, b_t), \quad b_t = \text{Ground}(I_{t-0.5}, I_t, I_{t+0.5}, \text{Instruction}_t) $$

其中 $\text{Ground}$ 为VLM的空间定位函数。该多帧策略通过时间冗余补偿单帧信息缺失，人工验证显示95%以上动作参数化准确，有效缓解了视频帧率与GUI操作高频特性不匹配导致的定位偏差。

### 两阶段训练策略

为充分利用合成数据，本文采用持续预训练与后训练结合的策略。Stage 1在WildGUI上进行持续预训练，优化目标聚合了定位、动作预测与轨迹建模三项任务：

$$ \mathcal{L}_{pre} = \mathcal{L}_{ground} + \mathcal{L}_{action} + \mathcal{L}_{traj} $$

其中 $\mathcal{L}_{traj}$ 仅在文本token上计算损失，以建模多轮交互的自回归特性。Stage 2在高质量开源数据集上进行3轮微调，巩固特定任务性能。该设计动机在于，大规模离线数据提供泛化基础，而小规模高质量数据校准策略精度，避免合成数据噪声直接干扰最终策略。

## 实验评估

实验在OSWorld-G、ScreenSpot-Pro、AndroidControl、CAGUI、OSWorld及AndroidWorld上进行。基线覆盖闭源模型（GPT-4o, Gemini-2.5-Pro）及开源SOTA（UI-TARS, OS-Atlas, Qwen3-VL），但缺失强化学习（RL）类方法（如MobileRL, UI-S1）的直接对比，限制了在动态环境中的竞争力评估。

| 基准 | 模型 | 指标 | 数值 |
| :--- | :--- | :--- | :--- |
| OSWorld-G | Mimo-VL-7B + WildGUI | Avg | 67.6 |
| OSWorld-G | Qwen3-VL-32B | Avg | 60.6 |
| ScreenSpot-Pro | Mimo-VL-7B + WildGUI | Avg | 56.9 |
| ScreenSpot-Pro | Qwen3-VL-32B | Avg | 54.9 |
| AndroidControl-High | Mimo-VL-7B + WildGUI | Step SR | 71.4 |
| AndroidControl-High | UI-TARS-7B | Step SR | 72.5 |
| AndroidWorld | Mimo-VL-7B + WildGUI | SR | 31.9 |
| AndroidWorld | Base Model | SR | 16.4 |

在离线基准上，Mimo-VL-7B经WildGUI预训练后在OSWorld-G上达到67.6，超越Qwen3-VL-32B的60.6；在ScreenSpot-Pro上达到56.9，优于Qwen3-VL-32B的54.9。AndroidControl-High的Step SR为71.4，略低于UI-TARS-7B的72.5。在线基准AndroidWorld上，完整管线达到31.9%，近乎基础模型16.4%的两倍，但远低于领域综述中MobileRL的80.2%。

消融实验显示，仅进行Stage 2后训练在AndroidWorld上仅为23.3%，加入Stage 1预训练后提升至31.9%，表明大规模离线数据对动态环境泛化有显著贡献。OSWorld上从10.4%提升至12.3%，增益幅度小于AndroidWorld，可能源于桌面环境操作复杂度更高。

评估边界方面，论文未报告置信区间，且在线基准成功率整体偏低，可能受限于缺乏RL微调。可复现性上，论文承诺开源WildGUI数据集与Video2GUI管线，训练使用256块NVIDIA GPU，超参数详细披露，具备较高复现条件。

## 关联研究分析

从数据源角度看，Video2GUI与SeeClick均致力于解决数据稀缺，但SeeClick依赖静态截图与指令对，缺乏时序动态信息；Video2GUI利用视频天然包含的操作序列，通过滑动窗口与多帧接地提取长程轨迹。差异根源在于任务特性：静态截图适合单步定位，而视频适合多步规划。Video2GUI在CAGUI中文界面上Type Acc达到90.3，较基础模型提升14.1，表明视频数据中的跨语言多样性对泛化有直接贡献，这是静态截图难以提供的。

从训练范式看，Video2GUI仅采用SFT/预训练，未引入RL。这与UI-S1、MobileRL等强调RL在动态环境中必要性的路线形成对比。Video2GUI在AndroidWorld上31.9%的成绩虽优于基础模型，但远低于RL方法，暗示纯数据预训练无法解决长程任务中的错误累积与恢复问题。这一差距并非数据规模不足，而是缺乏在线交互中的自我反思机制。视频预训练提供了更鲁棒的初始策略，但无法替代RL在分布外场景下的适应性优化。

## 总结

Video2GUI旨在解决GUI智能体训练数据稀缺导致的泛化不足问题。其切入点在于利用互联网视频的规模与多样性，通过自动化管线将非结构化视频转化为精确空间坐标的轨迹数据。方法上，粗到细过滤与多帧接地确保了数据质量，两阶段训练平衡了泛化与精度。实验证明，WildGUI预训练使Mimo-VL-7B在OSWorld-G上达到67.6，在AndroidWorld上从16.4%提升至31.9%。然而，在线基准的低分暴露了纯SFT范式在动态环境中的局限，缺乏RL机制导致长程任务错误恢复能力不足。当预训练数据规模继续扩大时，其对在线RL收敛速度的影响是否显著，论文未给出回答。
