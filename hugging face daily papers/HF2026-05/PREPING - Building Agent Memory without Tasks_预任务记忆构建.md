# HuggingFace最新推荐论文 ｜PREPING: Building Agent Memory without Tasks ｜预任务记忆构建

研究机构：韩国科学技术院

作者：Yumin Choi、Sangwoo Park、Minki Kang 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.13880)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.13880)

> 智能体在接入新环境时面临“无任务经验”的冷启动困境，离线构建依赖昂贵的人工标注，在线构建则需等待用户交互积累记忆，导致部署初期性能低下且成本高昂。PREPING 提出在部署前通过受控合成练习构建程序性记忆，利用 Proposer 控制练习分布、Validator 门控记忆写入，解决了合成轨迹冗余与不可行导致的记忆污染问题。该方法在 AppWorld 和 BFCL v3 上超越了依赖真实任务的 ACE-Online，但其在复杂异构工具环境中的泛化能力及长期记忆维护机制仍存疑。

## 研究背景

智能体在可执行环境中执行任务时，不仅需识别可用工具，更需掌握工具组合、前置条件及故障恢复等环境特定程序。这种程序性知识无法从静态文档中直接获取，必须通过交互经验沉淀为可复用的外部记忆。然而，现有记忆构建范式存在时序错位：离线方法（如 ACE-Offline）依赖部署前收集的人工任务轨迹，成本高昂且难以覆盖新环境；在线方法（如 ACE-Online）虽无需预置数据，但初始记忆为空，智能体在用户任务到达前无法形成有效策略，导致冷启动期间性能接近无记忆基线，且部署时增加记忆更新延迟与计算开销。

该领域主流路线聚焦于“经验驱动”的记忆构建，即从真实任务反馈中提取程序性指令。其瓶颈在于经验获取的滞后性：新环境接入时，既无历史轨迹可供离线构建，又无用户交互可供在线学习。PREPING 的切入点是将记忆构建从“经验后处理”前移至“经验前预演”，提出预任务记忆构建（Pre-Task Memory Construction）问题：在无任何目标环境任务数据的情况下，仅利用环境文档与自生成合成练习，构建可部署的程序性记忆。这要求解决两个耦合控制问题：如何生成覆盖广且可行的合成任务，以及如何筛选高质量轨迹避免记忆污染。

## 核心方法

### 方法参照系

PREPING 属于记忆演化与自学习路线，但区别于依赖真实任务反馈的标准流程，其核心差异在于构建阶段无目标任务分布约束。标准 ACE 框架通过 Reflector-Curator 管道从真实轨迹归纳 Playbook，而 PREPING 将输入源替换为自生成合成轨迹，并引入构建时控制状态以调节练习分布。

### Proposer 记忆控制练习分布

设计动机：无约束合成任务易陷入局部重复或生成不可行目标，导致记忆覆盖度不足。PREPING 引入 Proposer Memory ($M_{prop}$) 作为构建时控制状态，包含练习历史视图（记录已用工具、失败原因）与环境接地视图（记录实体、状态约束）。Proposer 基于 $M_{prop}$ 生成任务 $x_t$，公式为：

$$ x_t \sim A_{prop}(\cdot | M_{prop}^{(t)}, D) $$

该公式表明任务生成是条件概率过程，$M_{prop}$ 通过抑制重复工具调用、引导未覆盖区域，使合成练习在可行性与覆盖度间取得平衡，避免随机探索的浅层重复。

### Validator 门控记忆写入

设计动机：合成轨迹可能包含不可行操作或错误恢复模式，直接写入会污染 Solver Memory。Validator 对任务-轨迹对 $(x_t, \tau_t)$ 进行可行性与完成度评分，仅当可行性评分为 5 时允许写入 Solver Memory ($M_{sol}$)。更新规则为：

$$ M_{sol}^{(t+1)} = U_{sol}(M_{sol}^{(t)}, x_t, \tau_t, v_t) \cdot \mathbb{1}[\text{Feasible}(v_t)] $$

该公式通过指示函数 $\mathbb{1}[\text{Feasible}(v_t)]$ 实现门控，确保仅高质量轨迹进入部署记忆。同时，所有验证结果（含拒绝项）反馈至 $M_{prop}$，形成“练习-验证-调整”闭环，使 Proposer 能动态规避失败模式。

## 实验评估

实验在 AppWorld（状态化应用）、BFCL v3（函数调用）和 MCP-Universe（MCP 服务器）上进行，基线涵盖无记忆 Base、文档直接记忆、随机/引导探索及任务驱动 ACE 方法。PREPING 在 AppWorld Test-Normal 上取得 83.7% TGC，较 Base 提升 17.1 点，超越 ACE-Online 的 80.4%；在 BFCL v3 上平均得分 62.3%，较 Base 提升 19.3 点，同样优于 ACE-Online 的 58.7%。

| 方法 | AppWorld N-TGC | AppWorld C-TGC | BFCL v3 Avg | MCP-Universe Avg |
|---|---|---|---|---|
| Base | 69.6 | 36.7 | 41.9 | 10.1 |
| ACE-Online | 80.4 | 78.3 | 58.7 | – |
| PREPING | 83.7 | 72.2 | 62.3 | 12.1 |

消融实验显示，Validator 门控是性能关键：移除验证器后，AppWorld TGC 从 83.7% 降至 47.8%，表明未过滤轨迹严重污染记忆。Proposer Memory 中的练习历史将唯一工具覆盖度从 69.0 提升至 81.7，验证了覆盖扩展机制的有效性。然而，MCP-Universe 上 PREPING 仅比 Base 提升 5.4 点（12.1% vs 10.1%），远低于其他基准，暗示合成练习在异构工具环境中泛化能力有限。

评估边界方面，论文未报告置信区间，且 MCP-Universe 结果缺乏与检索型基线（如 HippoRAG）的对比，难以区分性能增益源于记忆构建还是工具调用优化。代码未公开，超参数（如 100 个合成任务预算）的敏感性分析仅覆盖 AppWorld，BFCL v3 的构建成本未量化。

## 关联研究分析

从问题动机看，PREPING 与 ACE 的核心差异在于经验来源的时序解耦。ACE 依赖真实任务反馈构建记忆，其性能上限受限于任务分布的代表性；PREPING 通过合成练习解耦构建与部署，但面临合成任务分布与真实任务分布的偏移风险。论文通过 Proposer Memory 的环境接地视图缓解此偏移，但未量化合成任务与真实任务的分布距离，MCP-Universe 的低增益可能正是分布偏移的体现。

从方法设计看，PREPING 的 Validator 门控机制与知识图谱构建中的实体关系验证有相似性，但前者针对轨迹可行性，后者针对结构一致性。与 Mem0 等事实提取方法相比，PREPING 聚焦程序性记忆而非事实性记忆，其验证器仅评估任务完成度，未处理事实冲突或时效性问题。这导致 PREPING 在需要长期事实一致性的场景中可能失效，而论文未探讨程序性记忆与事实性记忆的分层治理。

## 总结

PREPING 解决了智能体新环境接入时的冷启动记忆构建矛盾，通过 Proposer-Validator 闭环将合成练习转化为可部署程序性记忆，在 AppWorld 上以 83.7% TGC 超越依赖真实任务的 ACE-Online。其边界在于合成任务分布与真实任务分布的潜在偏移，MCP-Universe 上仅 12.1% 的平均得分暴露了异构工具环境中的泛化短板。当工具接口复杂度进一步增加时，Proposer 的环境接地视图能否有效约束合成任务可行性，论文未给出回答。
