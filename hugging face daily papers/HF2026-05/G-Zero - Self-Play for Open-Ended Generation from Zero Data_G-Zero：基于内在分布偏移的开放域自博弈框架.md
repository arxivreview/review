> 大语言模型（LLMs）在开放域任务中的自我进化长期受制于外部验证器的缺失，现有依赖 LLM-as-a-Judge 的方法面临能力瓶颈与奖励黑客风险。G-Zero 提出 Hint-δ 信号，通过量化提示对生成器预测分布的偏移来构建内在监督，实现了无需外部真值的协同进化。该方法在 AlpacaEval 上提升 3.74 点，在 AIME 25 上提升 5.21 点，验证了内在信号的有效性，但其对数学推理的绝对性能提升有限，且理论保证仅覆盖理想化 DPO 变体。

## 研究背景

当模型在开放域生成任务中尝试自我改进时，缺乏确定性 Oracle 导致无法直接计算奖励，这构成了自博弈范式在不可验证领域的核心障碍。为绕过此限制，现有方法常引入 LLM-as-a-Judge 作为代理验证器，但这引入了两个结构性缺陷：一是模型性能上限被 Judge 的能力所锁定，二是优化过程极易陷入奖励黑客，即模型通过利用 Judge 的风格偏好（如冗长、特定格式）而非提升内容质量来最大化奖励。

自博弈（Self-Play）在可验证任务（如数学、代码）中已证明其有效性，R-Zero 等工作通过多数投票机制挖掘复杂任务，但严格依赖程序化验证。在开放域指令遵循或多轮对话中，这种依赖无法成立。G-Zero 的切入点在于将监督信号从“外部判断”内化为“分布动态”，通过 Proposer 与 Generator 的协同进化，利用模型自身对提示的响应差异来定义学习信号，从而在缺乏外部真值的情况下维持探索与利用的平衡。

## 核心方法

### 协同进化参照系

G-Zero 建立在挑战者-求解者（Challenger-Solver）自博弈架构之上，但关键差异在于奖励来源。传统自博弈依赖可验证结果（如答案正确性）作为奖励，而 G-Zero 在开放域中无法获取此类信号，因此必须从模型内部动态中推导奖励，以驱动 Proposer 生成具有挑战性的查询-提示对。

### Hint-δ 内在信号

Hint-δ 是 G-Zero 的核心创新，它量化了提示 $h$ 对生成器 $π_G$ 在无提示响应 $a_{hard}$ 上的预测分布偏移。该信号定义为逐 token 平均对数似然差：

$$ \delta(q, h) = \frac{1}{T} \sum_{t=1}^{T} \left[ \log π_G(a_t | q, h, a_{<t}) - \log π_G(a_t | q, a_{<t}) \right] $$

这一设计动机在于解决开放域中“难度”与“信息量”难以分离的问题。Hint-δ 仅在查询对生成器具有挑战性且提示携带缺失信息时才会显著增大，从而自动靶向生成器的盲区。使用逐 token 平均而非序列总和，确保了信号对响应长度的不变性，防止 Proposer 通过诱导更长响应来操纵奖励。

### 基于 δ 的数据过滤与 DPO 训练

在生成器训练阶段，G-Zero 采用直接偏好优化（DPO）而非强化学习，以利用其闭式解特性适应自配对数据。关键设计在于数据过滤策略：保留 δ 值位于经验分布下半部分的偏好对。这一反直觉的选择源于两点：低 δ 对构成“难以区分”的训练信号，迫使 DPO 学习细粒度结构改进而非表面差异；高 δ 对则违反 DPO 隐含的 KL 散度约束，可能导致策略偏离参考模型过远，引发训练不稳定。通过长度归一化 DPO 损失，进一步消除了长度偏差：

$$ \mathcal{L}_{DPO} = -\mathbb{E}_{(x, y_w, y_l) \sim D} \left[ \log \sigma \left( \beta \left( \frac{1}{|y_w|} \log \frac{π_θ(y_w|x)}{π_{ref}(y_w|x)} - \frac{1}{|y_l|} \log \frac{π_θ(y_l|x)}{π_{ref}(y_l|x)} \right) \right) \right] $$

该机制使生成器内化提示引导的结构模式，从而在无提示推理时产生更高质量的独立响应。

## 实验评估

实验在 Qwen3-8B-Base 和 Llama-3.1-8B-Instruct 上进行，基准包括 AIME24/25（mean@32）、IFEval 和 AlpacaEval 2.0。基线仅对比 R-Zero 和 Base Model，缺失 LLM-as-a-Judge 等开放域自对齐方法的直接对比，限制了方法优势的全面评估。

| 模型 | 指标 | Base | R-Zero | G-Zero R1 | G-Zero R2 |
|---|---|---|---|---|---|
| Qwen3-8B-Base | AlpLC | 8.94 | 8.04 | 9.07 | 8.47 |
| Qwen3-8B-Base | IF-pS | 43.07 | 37.56 | 54.12 | 56.24 |
| Qwen3-8B-Base | AIME25 | 7.19 | 11.36 | 12.19 | 12.40 |
| Llama-3.1-8B-Instruct | AlpLC | 24.12 | 21.74 | 23.88 | 27.86 |
| Llama-3.1-8B-Instruct | IF-pS | 58.41 | 56.94 | 66.35 | 66.35 |
| Llama-3.1-8B-Instruct | AIME25 | 0.42 | 0.34 | 1.04 | 0.63 |

G-Zero 在两轮迭代后，Qwen3 的 AIME25 从 7.19% 提升至 12.40%，Llama-3.1 的 AlpLC 从 24.12% 提升至 27.86%。相比 R-Zero，G-Zero 在保持数学推理提升的同时，避免了对话性能的显著下降（R-Zero 在 Qwen3 上 AlpLC 下降 0.9 点），显示出更均衡的能力进化。

消融实验显示，δ 过滤区间 [0, 50] 在 Qwen3 上取得最佳平均性能 34.96%，优于 [20, 80] 的 34.40% 和 [50, 100] 的 34.04%。这表明保留低 δ 对确实有助于学习细粒度改进，而高 δ 对可能引入噪声。DPO 池组成分析显示，Advice 类任务占比最高（30.2%），Math 和 Code 类占比较低（9.6% 和 9.0%），暗示开放域任务中逻辑推理类数据占比有限。

评估协议存在局限：AIME 分数仅反映数学推理能力，未涵盖其他可验证任务；AlpacaEval 依赖 Qwen3-235B 作为 Judge，可能引入评估偏差。代码已开源，但超参数设置（如 LoRA 秩、学习率）未在正文中详细列出，复现性依赖附录或代码库。

## 关联研究分析

从问题动机看，G-Zero 与 R-Zero 的核心差异在于验证信号的来源。R-Zero 依赖多数投票，严格限制于可验证任务，而 G-Zero 通过 Hint-δ 将监督信号内化，扩展至开放域。这一差异源于任务特性：可验证任务存在确定性 Oracle，而开放域任务缺乏此类信号，迫使研究者转向内在分布动态。G-Zero 的 Hint-δ 设计解决了 R-Zero 在开放域中无法应用的问题，但其代价是放弃了确定性奖励的精确性，转而依赖分布偏移的统计特性。

从方法设计看，G-Zero 与 SPIN 均利用分布差异进行迭代优化，但信号粒度不同。SPIN 区分人类文本与模型文本，信号为序列级；G-Zero 区分有/无提示文本，信号为 token 级。这一差异源于数据构造方式：SPIN 依赖外部人类数据，而 G-Zero 完全自生成。G-Zero 的 token 级信号更细粒度，能捕捉提示对局部推理步骤的影响，但计算成本更高，且对生成器分布的稳定性更敏感。

## 总结

G-Zero 解决了开放域自进化中缺乏验证器的核心矛盾，通过 Hint-δ 将提示诱导的分布偏移形式化为内在奖励，实现了 Proposer 与 Generator 的协同进化。该方法在 AlpacaEval 上提升 3.74 点，在 AIME 25 上提升 5.21 点，证明了内在信号的有效性。然而，其数学推理绝对性能（12.40%）远低于专用自博弈方法（如 Absolute Zero 的 46.42%），且理论保证仅覆盖理想化 DPO 变体，未考虑非平稳分布下的信号稳定性。当生成器分布漂移过快时，Hint-δ 信号是否仍能准确反映认知差距，论文未给出回答。
