# HuggingFace最新推荐论文 ｜CHI-Bench: Can AI Agents Automate End-to-End, Long-Horizon, Policy-Rich Healthcare Workflows? ｜医疗行政工作流智能体基准

研究机构：美国斯坦福大学、美国卡内基梅隆大学

论文原文见 [arXiv](https://arxiv.org/abs/2605.16679)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.16679)

> 美国医疗体系中的先验授权（Prior Authorization, PA）、利用管理（Utilization Management, UM）与护理管理（Care Management, CM）是长时程、政策密集且操作不可逆的行政流程，现有临床诊断智能体基准无法覆盖此类场景。当前前沿大语言模型在编码类长时程任务中表现优异，但在真实医疗行政工作流中面临政策检索、多角色切换与多方交互的三重挑战，导致端到端自动化率极低。本文构建了包含20个高保真医疗应用模拟器与1279份政策文档的χ-Bench基准，通过MCP工具接口与双层验证器评估智能体在不可逆工作流中的表现。该基准揭示了当前模型在行政合规与长程状态管理上的严重短板，但仅作为压力测试工具，未提供解决算法。

## 研究背景

理解本文需先厘清医疗行政工作流与临床诊断的本质差异。临床诊断关注基于电子健康记录（EHR）的医学推理，而PA/UM/CM核心在于依据保险政策与操作规范执行行政决策。这类任务具有“政策密度”特征，即每个决策必须锚定在随时间变化的医疗指南与保险规则库中；同时具备“多角色组合”特性，单一智能体需在接诊、护士审查、医师复核等角色间切换，且步骤提交后不可逆；此外还涉及“多方交互”，如医患沟通与对等审查（Peer-to-Peer, P2P）对话，要求智能体从后台执行切换至实时对话以获取增量信息。

现有医疗AI基准主要聚焦于静态知识问答（如MedQA）或短程EHR查询，缺乏对长时程行政流程的覆盖。MedAgentBench虽引入虚拟EHR环境，但侧重临床任务执行而非行政合规；HealthAdminBench关注GUI操作，未涉及深层政策推理。主流多智能体协作框架（如MedAgents）通过角色分工提升诊断准确性，但假设输入数据完整且规则明确，难以应对行政流程中信息缺失、规则冲突及不可逆操作带来的状态一致性挑战。本文切入点在于构建首个结合长时程工具调用、显式密集政策检索、不可逆工作流状态及隐藏多方交互的医疗行政基准，以压力测试前沿智能体在真实运营场景中的可靠性。

## 核心方法

### 方法参照系

本文问题可置于长时程智能体评估框架下，但与传统编码或GUI基准的关键差异在于：任务状态由29个状态机节点构成，操作具有法律效力的不可逆性，且决策依据是1279份结构化政策文档而非代码库或网页DOM。传统基准的验证器仅检查最终输出文本，而本文要求验证器检查模拟器持久化的世界状态、事件日志与多轮对话记录。

### 高保真模拟器与MCP工具接口

设计动机在于解决现有基准无法模拟医疗软件间原子性跨应用效应的问题。本文构建χ-World Engine，包含151个REST API与87个MCP工具，覆盖PA、UM、CM三个域。智能体通过MCP服务器操作应用，动作触发一致的状态转移，如提供商提交PA包会生成支付方接收记录并推进事件日志。任务被形式化为层级部分可观测马尔可夫决策过程（Hierarchical POMDP），其状态空间 $S$ 涵盖患者图表、支付方/提供商记录、工作流状态、通信、工件及事件历史：

$$
M = (S, A, O, P, Z, R, \rho_0; H)
$$

其中 $H = (G, \nu, W)$ 定义角色智能体规格、交接顺序与共享工作区。该公式明确了智能体在部分可观测环境下，需通过角色作用域的动作 $A$ 与观测 $O$ 进行序列决策，且交接 $\nu$ 具有不可逆性，即出站提交成为入站输入，累积状态决定奖励 $R$。

### 双层验证器与政策手册技能

设计动机在于解决单一LLM评判器在政策合规性评估上的主观性与不一致性。本文采用复合验证器，结合确定性契约检查与基于评分标准的LLM评判器，二元奖励 $R$ 定义为：

$$
R = \text{DeterministicPass} \land \text{JudgePass}
$$

确定性层检查状态机前向推进、同意完整性标志、护理计划结构完整性及字段级完整性；LLM层以严格多数投票评估沟通适当性、评估依据、护理计划构成及升级判断。同时，引入1279份Markdown文档构成的“管理护理操作手册”作为技能，采用渐进披露结构，顶层路由至三个角色子技能，共享医疗库与平台教程。该设计将技能编写视为新员工入职指南，确保智能体在长工具调用链中持续锚定政策依据，而非依赖短期记忆。

## 实验评估

本文评估30种智能体框架/模型配置，包括专有栈（Claude Code、Codex、Gemini CLI）与开源栈（OpenClaw、Hermes、OAI Agents、DeepAgents），每任务运行3次独立试验，报告pass@1、pass@3与pass^3。基线覆盖前沿闭源模型（GPT-5.5、Claude Opus 4.6/4.7）与开源模型（GLM-5.1、Kimi K2.6等），但缺失专用医疗智能体基线（如MedAgents），因本文任务为行政流程而非临床诊断，专用医疗模型不适用。

| 配置 | Overall pass@1 (%) | UM pass@1 (%) | CM pass@1 (%) |
| :--- | :--- | :--- | :--- |
| Claude Code + Opus 4.6 | 28.0 | 41.3 | 24.0 |
| Codex + GPT-5.5 | 20.9 | 32.0 | 1.3 |
| OAI Agents + GLM-5.1 | 18.7 | 33.3 | 4.0 |
| Claude Code + Sonnet 4.6 | 26.2 | 41.3 | 20.0 |

主结果显示，最佳配置Claude Code + Opus 4.6在Overall pass@1上仅达28.0%，UM域最高为41.3%（Opus 4.6），CM域最高为32.0%（Opus 4.7）。可靠性指标pass^3显著低于pass@1，如Opus 4.6从28.0降至18.7，GPT-5.5从20.9降至9.3，暴露运行间不一致性。

消融实验揭示手册技能的影响具有域依赖性。UM域对手册敏感，移除域手册使pass@1从32.0降至17.3，而移除医疗库影响甚微；PA域出现反直觉现象，移除全部手册（-Both）反而略高于保留部分手册，因完整手册诱导智能体进入过度验证模式，在不确定时拒绝提交，而无手册时智能体直接提交并被验证器接受；CM域复杂度源于对话驱动而非政策，手册影响较小。该发现表明大规模技能在政策密集型任务中可能引发认知过载或拒绝行为。

评估边界方面，本文仅评估语言智能体，未涵盖影像与语音多模态推理；评判器仅使用Claude Opus 4.7，未测试其他模型作为评判器的影响；任务集从523个候选中筛选至75个，可能遗漏长尾工作流。可复现性上，论文提供代码链接与详细版本信息（如Claude Code 2.1.123、Modal 1.4.2），但未公开完整模拟器数据与标注轨迹。

## 关联研究分析

从问题动机看，本文与MedAgentBench同属EHR环境智能体评估，但MedAgentBench聚焦临床任务执行（如诊断、治疗推荐），而本文聚焦行政运营（PA/UM/CM）。差异根源在于任务特性：临床任务允许一定程度的模糊性与人工复核，而行政任务具有法律效力的不可逆性，错误提交可能导致财务损失或监管处罚。MedAgentBench的验证器侧重临床准确性，本文验证器侧重政策合规性与工作流完整性，这导致本文基准对智能体的状态跟踪与规则遵循能力要求更高。

从方法设计看，本文与HealthAdminBench同属医疗行政基准，但HealthAdminBench通过GUI像素/DOM浏览模拟操作，本文通过结构化MCP工具与政策手册技能。差异根源在于交互抽象层级：GUI操作更接近人类用户界面，但难以模拟深层政策推理与跨应用状态同步；MCP工具提供程序化接口，便于模拟原子性跨应用效应，但可能掩盖智能体在界面导航上的能力。本文选择MCP是为了聚焦政策密集与长时程挑战，而非界面操作能力，这导致本文基准更适用于评估智能体的推理与规划能力，而非感知与操作能力。

## 总结

本文核心矛盾在于前沿智能体在编码类长时程任务中的高表现与在真实医疗行政工作流中的低可靠性之间的差距。现有方法无法覆盖政策密集、多角色切换与不可逆操作并存的场景，本文通过构建高保真模拟器与双层验证器，首次量化了这一差距。实验证明最佳智能体仅解决28.0%的任务，且可靠性指标pass^3进一步降至18.7%，失败主要归因于临床推理错误（35.4%）、工作流未完成（23.3%）与政策合规错误（13.2%）。本文边界在于仅评估语言智能体，未涵盖多模态推理，且评判器单一。当智能体在政策密集型任务中因过度验证而拒绝提交时，如何平衡合规性与任务完成率，论文未给出回答。
