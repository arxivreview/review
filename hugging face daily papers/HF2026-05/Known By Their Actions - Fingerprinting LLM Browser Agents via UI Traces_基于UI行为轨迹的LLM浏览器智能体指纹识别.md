# HuggingFace最新推荐论文 ｜Known By Their Actions: Fingerprinting LLM Browser Agents via UI Traces ｜基于UI行为轨迹的LLM浏览器智能体指纹识别

研究机构：英国牛津大学

作者：William Lugoloobi、Samuelle Marro、Jabez Magomere 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.14786)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.14786)

> 部署在真实网络中的LLM浏览器智能体面临被网站运营者被动识别底层模型的风险，而现有安全防御仅关注“是否恶意”或依赖可伪造的浏览器属性，忽视了行为时序中蕴含的模型特异性。本文切入点在于证明智能体的点击、滚动及按键间隔等UI动作轨迹本身构成了不可伪造的模型指纹，通过被动注入JavaScript采集这些轨迹并训练轻量级分类器即可实现身份归因。该方法利用XGBoost对动作时序与结构特征进行多分类，揭示了智能体在开放网络中“匿名性”的失效。其价值在于将安全威胁从内容操纵前移至身份侦察，但随机延迟防御的脆弱性表明行为混淆尚未形成有效屏障。

## 研究背景

当LLM智能体在网页上执行点击与滚动操作时，每次交互均产生毫秒级的时间戳与坐标数据。这些看似随机的交互序列实则是模型内部规划节奏的外在映射，即动作间隔（Inter-Event Intervals, IEI）。IEI不仅受模型推理速度影响，更反映了不同架构在处理视觉输入时的决策延迟分布，这种分布具有个体特异性。然而，传统Bot检测仅将此类轨迹用于人机二分类，忽略了在确认“非人类”后，进一步区分“哪个模型”的可能性，导致针对特定模型漏洞的精准攻击缺乏前置侦察手段。

Web智能体领域长期聚焦于任务成功率与鲁棒性，如WebArena基准评估导航能力，ceLLMate等框架通过系统级沙箱隔离防御提示注入。然而，这些防御假设攻击者需主动探测或依赖模型对齐，未考虑被动观察场景。Pasquini et al. (2025) 虽通过主动查询指纹识别LLM应用，但需发送特定输入，易被检测。本文指出，在智能体已部署于生产环境的背景下，网站运营者无需任何主动交互，仅通过页面内被动监听即可获取足够信号，这一“零交互”攻击面被现有安全框架完全忽视，构成了从“模拟环境任务执行”到“真实世界可靠代理”跨越中的关键安全盲区。

## 核心方法

### 行为轨迹分类参照系

本文问题可归入侧信道攻击中的流量指纹识别范畴，但关键差异在于观测源从网络层加密包序列转移至客户端DOM事件流。传统流量指纹依赖包大小与时间戳，而本文利用Midscene.js纯视觉模式下的UI动作序列，确保所有智能体共享相同浏览器Harness，排除执行环境差异，使行为差异完全归因于底层模型。

### 被动轨迹采集与特征工程

设计动机在于消除可伪造的浏览器属性（如User-Agent、Canvas指纹），转而依赖模型固有的决策节奏。智能体在状态 $s_t$ 下生成动作 $u_t$，轨迹定义为 $\tau = \{(s_t, u_t, \Delta t_t)\}_{t=1}^T$，其中 $\Delta t_t$ 为连续动作间的时间间隔。特征映射 $\phi(\tau)$ 提取IEI统计量（均值、标准差、分位数）、导航结构（点击频率、页面停留时间）及交互模式（按键类型分布）。这些特征捕捉了模型在视觉推理与动作执行间的固有延迟模式，例如GPT-5.4与Claude Opus 4.6在首次动作前的等待时间存在显著差异，该差异源于各自推理链长度的不同。

### 闭集与开集身份归因

设计动机在于区分“已知模型识别”与“未知模型检测”两种实战场景。闭集指纹识别将问题形式化为多分类：给定轨迹 $\tau$，预测模型 $\hat{m} = f(\tau)$，其中 $f$ 为XGBoost分类器，训练目标为最小化交叉熵损失。开集指纹识别采用留一法（Leave-One-Agent-Out, LOO）协议，训练集排除目标模型 $a_i$，测试集包含 $a_i$ 作为“未知”类，通过AUROC评估已知/未知二分类能力。该设计揭示了闭集高F1与开集低AUROC的解耦现象：Seed-2-lite在闭集F1达96.1%，但在开集AUROC仅0.47，表明其行为虽在已知分布中独特，但与未知模型的行为边界模糊，这对防御者意味着仅靠闭集分类无法应对新发布的模型。

## 实验评估

实验在2WikiMultiHop、FRAMES、WebShop及DeepShop四个基准上进行，涵盖信息检索与购物任务，共1050个轨迹样本。基线为14类随机猜测（~7% F1），未对比其他行为分类方法，因本文是首个针对LLM模型身份的行为指纹研究。主结果显示，XGBoost在闭集设定下Macro F1最高达96.1%（Seed-2-lite on 2WikiMultiHopQA），UI-TARS-1.5在WebShop达92.1%，显著高于随机基线。

| 模型 | 2WikiMultiHop F1 (%) | FRAMES F1 (%) | WebShop F1 (%) | DeepShop F1 (%) |
| :--- | :--- | :--- | :--- | :--- |
| Seed-2-lite | 96.1 | 96.6 | 93.4 | 87.5 |
| Qwen3-VL-30B | 92.7 | 80.3 | 73.5 | 83.8 |
| GPT-5.4 | 91.5 | 78.5 | 68.8 | 68.3 |
| UI-TARS-1.5 | 91.3 | 90.1 | 92.1 | 82.9 |
| Qwen3.5-27B | 90.9 | 97.4 | 82.2 | 87.7 |

消融实验表明，时序特征是主要信号源，但动作特征更具鲁棒性。SHAP分析显示，原始轨迹中IEI标准差与首次动作时间贡献最大；当注入5秒随机延迟并重训练后，分类器转向依赖结构按键比与点击坐标分散度，Macro F1仅轻微下降。这证明行为指纹并非单一依赖时序，而是时序与空间动作的复合特征。开集检测中，多数模型AUROC>0.60，但Seed-2-lite在三个数据集低于0.5，表明其开集可检测性弱于闭集可识别性。

评估边界受限于单一浏览器Harness（Midscene.js）与纯视觉模式，未测试DOM文本输入场景。可复现性方面，论文发布标注语料库与Harness，但14个模型中部分为专有API（GPT-5.4、Claude Opus 4.6），其内部推理延迟可能随API负载波动，影响轨迹稳定性。未报告置信区间，且未控制模型版本更新对行为特征的影响，新模型发布后需重新采集轨迹以更新分类器。

## 关联研究分析

从问题动机看，本文与ceLLMate (P13) 形成防御策略的根本对立。ceLLMate假设攻击者需执行恶意操作，通过系统级沙箱阻断未授权动作，属于“硬隔离”；本文则证明攻击者无需执行任何恶意操作，仅通过被动观察即可识别模型，属于“软特征”泄露。这一差异根源在于任务特性：ceLLMate关注动作合法性，本文关注行为模式特异性。若智能体行为足够随机，ceLLMate的隔离可能失效，因为攻击者已获知模型身份，可针对性构造绕过沙箱的提示注入。

从方法设计看，本文与WebSentinel (P19) 构成攻击链上下游。WebSentinel利用LLM语义理解检测页面中的注入内容，属于“内容层”防御；本文揭示的指纹识别属于“身份层”侦察，是实施针对性注入的前提。WebSentinel未考虑攻击者已知模型身份的情况，其检测逻辑假设注入内容是通用的，而本文证明攻击者可基于模型特异性选择更隐蔽的注入策略。这种差异暗示现有语义检测框架可能低估了身份识别带来的攻击精度提升，WebSentinel在已知模型身份场景下的检测率是否下降，论文未给出回答。

## 总结

本文核心矛盾在于LLM智能体部署规模扩大与行为匿名性失效之间的冲突。现有方法依赖可伪造的浏览器属性或主动探测，无法应对被动观察场景，而本文凭借UI动作轨迹中固有的模型特异性时序与结构特征，实现了零交互身份归因。通过XGBoost分类器，在14个前沿模型上达成最高96.1% F1，证明行为指纹的可行性。其边界在于随机延迟防御的脆弱性：重训练后分类器性能大幅恢复，表明行为混淆需更复杂的策略。当智能体引入自适应动作抖动以破坏IEI分布时，分类器是否仍能依赖空间动作特征维持高F1，论文未给出回答。
