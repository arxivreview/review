> 基于可验证奖励的强化学习（RLVR）在难题上面临奖励稀疏与信用分配模糊的双重困境，导致模型难以从失败轨迹中提取有效学习信号。现有课程学习方法依赖外部提示或监督模仿，破坏了策略的自探索特性。SCRL 通过离线构建可验证子问题序列，在单次在线策略 rollout 中实现过程级监督，将部分进展转化为密集学习信号。该方法在数学推理基准上显著优于基线，但其对子问题生成质量的依赖及理论假设的适用边界尚存疑。

## 研究背景

当大语言模型面对竞赛级数学难题时，其正确率往往极低，导致强化学习训练中的奖励信号极度稀疏。这种稀疏性直接引发了组相对策略优化（GRPO）中的“梯度死区”现象：当同一提示词下的所有采样响应均失败时，组内奖励方差为零，优势函数归零，梯度消失，模型无法从这些高价值但失败的尝试中获取任何更新信号。为了解决这一困境，研究界引入了课程学习思想，试图通过降低问题难度或提供辅助信息来密集化学习信号。

主流的课程学习路线分为两类：一是监督模仿与离线策略方法，通过让模型模仿专家轨迹来补偿稀疏奖励，但这引入了分布偏移，损害了泛化能力；二是在线策略课程方法，如提供专家推理前缀或重构问题，但这将关键步骤作为固定结论输入，模型无需自行推导，导致其未能内化底层逻辑。SCRL 的切入点在于，它要求模型在单次 rollout 中自行生成并解决一系列难度递增的子问题，既保留了在线探索的特性，又通过子问题级的验证实现了细粒度信用分配。

## 核心方法

### 方法参照系

SCRL 基于 GRPO 框架，但针对难题的信用分配失效进行了改造。标准 GRPO 在样本级进行奖励归一化，将单一优势值分配给整个响应序列，无法区分长思维链中正确与错误的中间步骤。SCRL 的关键差异在于将归一化粒度从“样本级”细化至“子问题位置级”，并通过结构化响应格式将优势值精确映射到对应的 token 跨度。

### 子问题构建与进度感知奖励

SCRL 首先利用外部大语言模型从参考解中离线提取 $K$ 个可验证子问题，形成难度递增的课程序列，其中最后一个子问题固定为原题。在训练时，模型需在一次 rollout 中按顺序回答所有子问题。为防止模型跳过早期子问题直接求解后期子问题（奖励黑客），SCRL 引入进度感知修正机制。定义课程进度 $k_i$ 为从起始位置连续解对的最大子问题数，最终奖励向量 $\tilde{\mathbf{r}}_i$ 仅保留前 $k_i$ 个位置的正确标记，其余置零。

$$
\tilde{r}_{i[j]} = \begin{cases} r_{i[j]} & \text{if } j \le k_i \\ 0 & \text{if } j > k_i \end{cases}
$$

这一设计确保了信用分配与课程进度严格对齐，只有连续掌握前置步骤的进展才会被奖励，从而引导模型逐步构建推理能力。

### 子问题级归一化与混合组训练

在获得进度感知奖励后，SCRL 执行子问题级归一化。对于同一提示词下的 $G$ 个 rollout，在每个子问题位置 $j$ 独立计算优势函数 $A_{i[j]}$，而非像 GRPO 那样计算单一的整体优势。

$$
A_{i[j]} = \frac{\tilde{r}_{i[j]} - \text{mean}(\{\tilde{r}_{i'[j]}\}_{i'=1}^G)}{\text{std}(\{\tilde{r}_{i'[j]}\}_{i'=1}^G)}
$$

该公式使得每个子问题的成功与否独立于其他子问题，实现了细粒度的信用分配。随后，通过结构化标签 `<p_j>` 和 `</p_j>` 定位每个子问题的答案 token 跨度，将 $A_{i[j]}$ 分配给该跨度内的所有 token，跨度外 token 优势为零。为缓解课程提示与原题提示的分布不匹配，SCRL 采用混合组训练：每个问题 $x$ 的 $G/2$ 个 rollout 来自课程提示 $t_K(x)$，另 $G/2$ 个来自原题提示 $x$，两者在同一更新步中联合优化。

## 实验评估

实验在 Qwen3-4B-Base、Qwen3-14B-Base 和 Llama3.2-3B-Instruct 上进行，使用 1,024 道高难度竞赛数学题训练 300 步。基线包括 GRPO、DAPO、QuestA 和 NuRL，覆盖了标准 RLVR 和主流课程学习方法，但未对比 SC-GRPO 或 Token Hidden Reward 等 2026 年最新的细粒度信用分配方法。

在 Qwen3-4B-Base 上，SCRL 的平均得分 35.0 较 GRPO 的 30.9 提升 4.1 点，在 AIME’24 和 AIME’25 等难题基准上提升尤为显著，验证了子问题分解对难题梯度恢复的有效性。

消融实验显示，移除进度感知修正（w/o corr.）导致平均得分从 44.2 降至 41.9，降幅 2.3 点，表明防止奖励黑客的修正机制对维持训练稳定性至关重要。此外，使用较弱的 Qwen3-4B-Instruct 生成子问题时，SCRL 仍优于 GRPO，说明该方法对子问题生成器的质量具有一定鲁棒性，但强生成器（DeepSeek-V3.2）能带来更高收益。

评估协议主要关注 Pass@1 和 Pass@64，未报告置信区间，且训练集仅包含 1,024 道题，样本量较小可能影响统计显著性。论文未提供代码仓库，但使用了公开的 Verl 框架，超参数细节在附录中提供，可复现性中等。

## 关联研究分析

从问题动机看，SCRL 与 SC-GRPO 均旨在解决无外部奖励模型下的细粒度信用分配，但路径截然不同。SC-GRPO 依赖自条件教师模型测量 token 级 KL 散度来识别关键 token，属于后验归因；而 SCRL 通过前置的子问题分解将信用分配转化为结构化的过程验证，属于先验结构约束。SCRL 的优势在于无需额外的教师模型推理开销，但代价是依赖外部 LLM 离线生成子问题，引入了潜在的生成噪声。SC-GRPO 则完全基于自身 rollout，自监督性更强，但计算复杂度更高。

从方法设计看，SCRL 与 QuestA 同属课程学习路线，但核心机制存在根本差异。QuestA 通过重构问题上下文来降低难度，模型只需完成剩余部分，其学习信号仍偏向于“续写”能力；SCRL 要求模型在单次 rollout 中自行生成并求解所有子问题，其学习信号涵盖了“构建中间步骤”和“求解最终问题”两个环节。这种设计迫使模型内化推理脚手架的构建逻辑，而非仅仅依赖外部提供的提示。然而，SCRL 的混合组训练策略是否完全消除了课程提示与原题提示之间的分布冲突，论文未提供直接的分布偏移度量来验证。

## 总结

SCRL 针对 RLVR 在难题上因奖励稀疏导致的梯度消失问题，提出了子问题课程强化学习框架。其核心创新在于将难题分解为可验证子问题序列，并通过子问题级归一化实现细粒度信用分配，同时利用进度感知修正防止奖励黑客。实验表明，该方法在 Qwen3-4B-Base 上较 GRPO 平均提升 4.1 点，在 AIME 等难题基准上提升 3.7 点（Pass@1），证明了子问题分解能有效恢复难题的学习信号。然而，SCRL 的性能依赖于外部 LLM 生成子问题的质量，且理论分析假设子问题分解能线性恢复梯度信号，这一假设在子问题难度分布不均或存在强依赖关系时是否依然成立，论文未给出充分验证。当子问题之间的逻辑依赖变得复杂且非线性时，简单的进度感知修正是否足以捕捉这种依赖结构，仍是该方法面临的关键挑战。
