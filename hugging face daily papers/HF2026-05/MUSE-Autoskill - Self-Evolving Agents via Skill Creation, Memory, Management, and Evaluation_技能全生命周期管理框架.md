# HuggingFace最新推荐论文 ｜MUSE-Autoskill: Self-Evolving Agents via Skill Creation, Memory, Management, and Evaluation ｜技能全生命周期管理框架

研究机构：美国罗切斯特理工学院

作者：Huawei Lin、Peng Li、Jie Song 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.27366)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.27366)

> 代理技能长期被视为一次性生成的静态产物，导致其在跨任务复用中缺乏经验积累与质量验证机制。现有自动技能系统往往割裂了创建、记忆与评估环节，无法在推理时动态修正技能缺陷。MUSE-Autoskill 通过构建包含创建、记忆、管理、评估与精炼的五阶段统一生命周期，将技能转化为可测试、可演化的外部资产。该框架在 SkillsBench 上验证了自生成技能超越人类技能上限的潜力，但其对单元测试依赖的强约束在开放域任务中的普适性仍存疑。

## 研究背景

当代理执行长程任务时，扁平的对话历史极易因上下文窗口限制而截断关键信息，导致推理断裂。为解决此问题，代理技能（Agent Skill）将程序性知识封装为独立模块，解耦了模型权重与任务逻辑。然而，技能若仅作为静态文件存储，无法记录执行过程中的失败模式与优化经验，使得同一技能在不同任务中重复犯相同错误。这种“无记忆”状态阻碍了技能从单次工具向长期资产的演进，亟需一种能跨任务积累特定技能经验的机制。

代理技能领域的核心矛盾在于技能生成的自动化与技能质量保障的缺失。Voyager 开创了可执行代码技能库，但缺乏结构化记忆；Skill1 等强化学习方法虽实现了策略协同，却将技能绑定于特定训练策略，迁移成本高。主流路线要么依赖人工编写技能（如 Anthropic Skills），要么通过离线蒸馏生成静态技能，均无法在运行时闭环中即时验证与修正。MUSE-Autoskill 的切入点在于将技能视为长期演化的基础设施，通过内置创建工具与单元测试门控，在推理循环内实现技能的即时生成、验证与精炼，填补了训练免费（Training-free）路线中缺乏动态质量控制的空白。

## 核心方法

### 技能生命周期参照系

本文问题对应代理技能自动优化领域，但区别于 SkillOpt 等基于文本梯度的离线优化，MUSE 强调推理时（Inference-time）的闭环管理。其关键差异在于将技能创建嵌入 ReAct 循环，并通过单元测试（Unit Test）作为硬约束门控，而非依赖验证集性能提升作为软反馈。

### 运行时技能创建与测试门控

传统方法中技能生成与执行解耦，导致生成的技能缺乏运行时上下文感知。MUSE 通过内置 `skill_create` 工具，在代理规划阶段直接触发技能合成。技能包遵循 Anthropic 格式，包含 `SKILL.md` 接口定义、`scripts/` 执行代码及 `tests/` 验证用例。创建后，系统强制在沙箱中运行单元测试，仅当所有测试通过时，技能才注册至技能库（Skill Bank）。这一设计动机在于消除“创建-使用不匹配”，确保进入库的技能具备最小可靠性。技能注册状态可形式化为：

$$
\mathcal{S}_{new} \in \mathcal{B} \iff \forall t \in \mathcal{T}_{skill}, \text{Exec}(t, \mathcal{S}_{new}) = \text{Pass}
$$

其中 $\mathcal{B}$ 为技能库，$\mathcal{T}_{skill}$ 为技能包内定义的测试集。该公式表明技能入库是二元判定过程，而非概率性优化，从源头过滤了不稳定技能。

### 技能级记忆与自适应精炼

静态技能库无法区分同一技能在不同任务中的表现差异。MUSE 引入技能级记忆（Skill-level Memory），独立于短期与长期记忆，专门存储特定技能的历史执行反馈。当技能执行失败或测试未通过时，精炼器（Refiner）读取技能级记忆中的错误日志（如超时、类型错误），生成补丁（Patch）更新 `scripts/` 或 `tests/`，并重新进入测试门控。记忆更新机制定义为：

$$
M_{skill}^{(t+1)} = M_{skill}^{(t)} \cup \{ \text{Trace}_{fail}, \text{Patch}_{applied} \}
$$

其中 $M_{skill}$ 为技能级记忆向量，$\text{Trace}_{fail}$ 为失败轨迹摘要。这一设计使得技能具备“经验积累”能力，后续调用时可参考历史失败模式调整参数或逻辑，解决了传统方法中技能“无状态”导致的重复错误问题。

## 实验评估

实验基于 SkillsBench 的 51 个真实世界任务，对比 Codex、Hermes 及 MUSE-Autoskill 三个基于 GPT-5.5 的代理。基线覆盖人工技能与无技能场景，但未直接对比 SkillOpt 或 SkillGrad 等 2026 年最新优化方法，限制了与前沿自动优化算法的直接可比性。

| 代理 | 无技能 (%) | 人工技能 (%) | 自生成技能 (%) |
| :--- | :--- | :--- | :--- |
| Codex | 52.11 | 67.28 | - |
| Hermes | 47.89 | 61.21 | 58.40 |
| MUSE-Autoskill | 53.19 | 68.40 | 60.35 |

MUSE 在人工技能条件下以 68.40% 领先，较无技能基线提升 15.21 个百分点。在自生成技能条件下，MUSE 整体准确率为 60.35%，低于人工技能，但在成功生成技能的 35 个任务上，Phase 2 准确率达到 87.94%，显著超越 68.40% 的人工技能上限。这一反直觉结果表明，自生成技能在覆盖任务上具有极高的任务相关性，但整体性能受限于 31.4% 的任务生成失败率（16/51）。

消融分析显示，技能迁移能力是 MUSE 的关键优势。将 MUSE 生成的技能注入 Hermes，其准确率从 47.89% 提升至 58.40%，闭合了与人工技能差距的 79%。相比之下，Hermes 使用人工技能仅达 61.21%，而 MUSE 使用自生成技能为 60.35%，两者差距仅 1.95 个百分点。这证明 MUSE 生成的技能是外部化知识资产，而非绑定特定代理行为的内部状态。

评估边界方面，SkillsBench 任务均配备确定性验证器，单元测试门控的有效性依赖于任务的可测试性。在缺乏明确验证器的开放域任务中，单元测试的生成质量与覆盖度可能成为瓶颈。论文未提供代码开源链接，且未报告置信区间，复现性受限。

## 关联研究分析

从问题动机看，MUSE 与 Skill1 形成鲜明对比。Skill1 通过强化学习协同优化技能选择与策略，将技能进化建模为马尔可夫决策过程，追求端到端性能最大化。MUSE 则坚持训练免费路线，将技能视为独立于策略的外部资产，通过单元测试而非奖励信号驱动进化。这一差异源于任务特性：Skill1 适用于动态环境中的长程决策，而 MUSE 更适用于结构化、可验证的领域任务。MUSE 的单元测试门控在缺乏明确验证器的开放域任务中是否仍能保持有效性，论文未给出回答。

从方法设计看，MUSE 与 Voyager 共享可执行技能库思想，但 Voyager 缺乏结构化记忆与测试机制，技能质量依赖环境反馈的偶然性。MUSE 引入技能级记忆与强制测试，将技能从“代码片段”升级为“可测试软件包”。与 Anthropic Skills 相比，MUSE 增加了自动化精炼闭环，解决了人工维护成本高的问题。然而，MUSE 的单元测试生成依赖 LLM 自身能力，若 LLM 无法生成有效测试，门控机制将失效，这一盲区在复杂逻辑任务中可能更为显著。

## 总结

MUSE-Autoskill 旨在解决代理技能静态化与缺乏质量验证的核心矛盾。通过构建五阶段生命周期，将技能创建嵌入推理循环并引入单元测试门控，实现了技能的动态演化与跨代理迁移。实验证明，自生成技能在覆盖任务上可达 87.94% 准确率，超越人工技能上限，且迁移至其他代理后保留 79% 的效用。然而，其整体性能受限于 31.4% 的任务生成失败率，且单元测试门控的有效性高度依赖任务的可测试性。当任务缺乏确定性验证器时，技能级记忆的积累是否仍能驱动有效精炼，而非累积噪声，是决定该框架泛化边界的关键问题。
