> 代理在流式任务中需持续积累并复用经验，但现有方法要么依赖人工策展，要么使用固定启发式规则，无法从延迟的下游反馈中学习复杂的长期管理策略。SkillOS 将技能策展解耦为独立于执行器的可训练模块，通过分组任务流与复合奖励，让策展器从间接信号中学习插入、更新与删除操作。该方法在 ALFWorld 和 WebShop 上优于无记忆及静态记忆基线，但其在具身任务上的绝对成功率仍显著低于联合优化策略的 SOTA，且策展器规模受限可能制约其泛化上限。

## 研究背景

当代理面对连续到达的任务流时，它必须从过往交互中提取可复用的程序性知识，这一过程称为技能策展。策展的质量直接决定了代理在后续任务中的执行效率与成功率，但策展决策的效果往往滞后于当前步骤，仅能通过未来相关任务的表现间接显现。这种延迟反馈使得传统的监督学习或短视强化学习难以有效优化策展策略，因为模型无法立即判断某次技能插入或删除是否真正有益。

现有技能进化路线主要分为两类：一类是基于文本梯度或验证门控的自动优化方法（如 SkillOpt, SkillGrad），它们假设技能结构具有层次性或通过有界编辑实现稳定更新，但缺乏对技能库整体生态的动态管理能力，难以处理有害技能的删除与过时技能的修订；另一类是端到端的强化学习框架（如 Skill1, SkillRL），它们联合优化策略与技能，但在长程任务中信号密度低，且将策展与执行耦合，导致模块化复用困难。SkillOS 的切入点在于将策展视为一个独立的、可训练的“操作系统”层，通过解耦执行器与策展器，专门针对延迟反馈设计训练机制，从而在保持执行器冻结的前提下，实现技能库的长期自我进化。

## 核心方法

### 多智能体模块化架构

SkillOS 采用冻结的代理执行器（Agent Executor）与可训练的技能策展器（Skill Curator）组成的双模块架构。执行器负责基于当前环境观测和检索到的技能子集 $\tilde{S}_t$ 生成动作，而策展器则观察执行轨迹 $\xi_t$ 并生成结构化的策展操作 $c_t$。这种设计的关键差异在于，策展器不直接参与任务执行，而是通过文件 I/O 操作（insert/update/delete）管理外部的 Markdown 技能库 $S_t$，将技能管理从执行策略中剥离，使其成为一个独立的、可单独优化的控制信号。

### 分组任务流与复合奖励机制

为解决策展决策的延迟反馈问题，SkillOS 将训练实例构建为基于技能相关性的任务组 $G$。在组内，早期任务的轨迹用于更新技能库，后续相关任务则作为评估这些更新效用的“测试集”。策展器策略 $\pi_S$ 通过 Grouped Reward Policy Optimization (GRPO) 进行优化，其目标函数最大化复合奖励 $r$，该奖励由四部分组成：

$$
r = r_{task} + r_{fc} + r_{comp} + r_{cnt}
$$

其中，$r_{task}$ 为任务结果奖励，定义为组内除首个任务外所有任务的平均成功率，直接关联策展决策的下游效用；$r_{fc}$ 为函数调用奖励，衡量策展器生成的操作是否有效执行；$r_{comp}$ 为压缩奖励，定义为 $1 - \frac{|S_i|}{|\chi_i|}$，旨在惩罚冗长的技能存储，鼓励蒸馏而非复制轨迹；$r_{cnt}$ 为内容质量奖励，由外部裁判模型对技能语义有用性打分。这一设计将间接的环境反馈转化为密集的学习信号，使策展器能够区分“即时有用”与“长期有益”的操作，特别是学会了删除有害技能这一复杂管理行为。

## 实验评估

实验在 ALFWorld（具身交互）、WebShop（购物决策）及 AIME/GPQA（单轮推理）上进行，基线包括无记忆、ReasoningBank（静态洞察蒸馏）、MemP（程序性记忆）及 SkillOS 内部变体。值得注意的是，基线中未包含 SkillOpt 或 Skill1 等 2026 年 SOTA 方法，这限制了与当前最强方法的直接对比。

| 方法 | 执行器 | ALFWorld Avg. SR (%) | WebShop SR (%) |
| :--- | :--- | :--- | :--- |
| No Memory | Qwen3-8B | 47.9 | 9.8 |
| ReasoningBank | Qwen3-8B | 55.7 | 11.4 |
| SkillOS | Qwen3-8B | 61.2 | 16.5 |
| SkillOS | Gemini-2.5-Pro | 80.2 | 41.3 |

在 Qwen3-8B 执行器下，SkillOS 在 ALFWorld 上取得 61.2% 的成功率，较最强基线 ReasoningBank 提升 5.5 个百分点；在 WebShop 上，成功率从 11.4% 提升至 16.5%。当执行器升级为 Gemini-2.5-Pro 时，SkillOS 的 ALFWorld 成功率达到 80.2%，表明策展器的增益与执行器能力呈正相关。

| 消融配置 | ALFWorld Avg. SR (%) | Steps |
| :--- | :--- | :--- |
| SkillOS (Full) | 61.2 | 18.9 |
| w/o $r_{cnt}$ | 58.6 | 20.1 |
| w/o $r_{comp}$ | 60.0 | 19.3 |
| w/o grouping | 57.3 | 20.6 |

消融实验显示，移除分组任务流（w/o grouping）导致性能下降最显著（61.2% 降至 57.3%），验证了将策展决策与下游任务结果绑定是核心创新。移除内容质量奖励 $r_{cnt}$ 导致成功率下降 2.6 个百分点，说明中间监督信号对引导技能更新至关重要。压缩奖励 $r_{comp}$ 的移除虽对成功率影响较小，但增加了交互步数，表明其主要用于提升执行效率而非直接提升成功率。

评估边界方面，论文未报告置信区间，且未提供代码开源链接，可复现性受限。此外，实验仅聚焦于文本交互环境，未涉及多模态或高维连续控制任务，限制了结论的普适性。

## 关联研究分析

从问题动机看，SkillOS 与 Skill1 的核心差异在于优化目标的解耦程度。Skill1 采用统一的强化学习框架，协同优化技能选择、利用与蒸馏，其优势在于策略与技能的端到端协同，但在长程任务中信号稀疏且难以模块化复用。SkillOS 则冻结执行器，仅训练策展器，将策展视为独立于执行的控制信号。这种解耦设计的根源在于任务特性：在流式设置下，执行器可能频繁更换或升级，而技能库作为外部资产需要跨执行器持久化。然而，解耦也意味着策展器无法感知执行器的内部状态（如注意力分布或潜在表示），这可能限制了策展器对执行器特定偏好的适应能力。

从方法设计看，SkillOS 与 SkillOpt 代表了技能优化的两种不同范式。SkillOpt 基于文本梯度和验证门控，假设技能结构具有层次性，通过有界编辑实现稳定更新，适用于确定性较强的结构化任务（如 SpreadsheetBench）。SkillOS 则采用强化学习探索技能空间，通过分组任务流提供延迟反馈，更适合动态环境中的长期进化。两者的差异源于对“技能效用”定义的不同：SkillOpt 关注单步或短程任务的即时性能，而 SkillOS 关注跨任务流的累积效用。SkillOS 在 ALFWorld 上的性能（61.2%）远低于 Skill1 的 SOTA（97.9%），这可能源于其 8B 策展器的规模限制，以及解耦架构在复杂具身任务中信息传递的损失。

## 总结

SkillOS 旨在解决流式代理中技能策展的延迟反馈难题，通过解耦执行器与策展器，并利用分组任务流将间接信号转化为密集奖励，实现了技能库的长期自我进化。实验证明，该架构在 ALFWorld 上较静态基线提升 5.5 个百分点，且 8B 策展器在特定配置下可超越 Gemini-2.5-Pro 的零-shot 策展能力。然而，其在具身任务上的绝对性能仍显著低于联合优化策略的 SOTA，且策展器规模受限可能制约其在高复杂度任务中的泛化能力。当执行器能力大幅提升时，解耦架构中策展器对执行器内部状态感知缺失的性能瓶颈是否会成为主要限制因素，论文未给出回答。
