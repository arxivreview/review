# HuggingFace最新推荐论文 ｜Model-Adaptive Tool Necessity Reveals the Knowing-Doing Gap in LLM Tool Use ｜模型自适应工具必要性下的认知-执行鸿沟

研究机构：美国马里兰大学帕克分校

作者：Yize Cheng、Chenrui Fan、Mahdi JafariRaviz 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.14038)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.14038)

> 工具增强大语言模型（Tool-Augmented LLMs）面临的核心困境并非“如何调用”工具，而是“何时调用”的决策失误。现有研究将工具必要性视为静态、模型无关的属性，忽略了不同模型能力边界的差异，导致评估基准与真实部署场景脱节。本文通过定义基于模型经验性能的动态必要性指标，并解构内部认知与外部执行两个阶段，揭示了LLM在工具使用中存在显著的“认知-执行鸿沟”。这一发现挑战了“模型能识别即能执行”的隐含假设，为智能体可靠性提供了新的诊断视角，但其结论局限于特定任务类型，对复杂多步任务的普适性尚待验证。

## 研究背景

当智能体面对一个数学计算或事实查询时，它必须判断是依赖内部参数化知识直接回答，还是调用外部计算器或搜索API。这一决策过程涉及元认知（Meta-cognition），即模型对自身能力边界的评估。然而，传统评估范式将“是否需要工具”定义为查询本身的静态属性，由人工或强模型标注，这种模型无关（Model-agnostic）的定义掩盖了关键事实：同一查询对强模型可能是冗余的，对弱模型却是必需的。

工具使用研究长期聚焦于优化调用策略（How to use），如ReAct确立的“思考-行动-观察”范式，以及近期基于可验证奖励的强化学习（RLVR）方法如Tool-R1和Tool Zero，旨在提升多步调用的泛化性与鲁棒性。然而，这些方法隐含假设模型具备正确的“何时调用”（When to use）判断能力，即内部认知与外部行动是一致的。当模型在分布外（OOD）任务或能力边界附近波动时，这种假设往往失效。现有基准如BFCL主要评估任务成功率，无法区分“因认知错误导致的调用失败”与“因执行失败导致的调用错误”，从而无法诊断智能体在自适应工具使用中的根本缺陷。

本文切入点在于重新定义工具必要性，将其从静态标签转化为基于模型经验性能的动态指标。通过对比模型在无工具条件下的多次推理结果，确定其真实能力边界，进而量化实际必要性与观察到的工具调用行为之间的偏差。这种视角转换使得研究焦点从“优化调用策略”转向“诊断调用决策机制”，揭示了LLM在工具使用中存在的一个被长期忽视的结构性问题：模型可能“知道”需要工具，但未能“执行”调用动作。

## 核心方法

### 线性探针与两阶段解构框架

本文方法建立在表示工程（Representation Engineering）与机制可解释性（Mechanistic Interpretability）的基础上，核心工具是线性探针（Linear Probing）。在标准流程中，线性探针通过训练一个线性分类器 $y = \sigma(\mathbf{w}^T \mathbf{h} + b)$ 来解码隐藏状态 $\mathbf{h}$ 中的特定概念。本文将其应用于工具使用场景，但引入了关键差异：探针的目标不再是静态的查询属性，而是模型自适应的工具必要性。

### 模型自适应必要性定义

传统方法将必要性 $n(x)$ 定义为查询 $x$ 的固定属性。本文提出模型自适应必要性 $n_f(x)$，其定义基于模型 $f$ 的经验表现。具体而言，对于查询 $x$，在无工具条件下进行 $N$ 次独立推理，温度为 $T$。若模型在所有 $N$ 次中均正确回答，则 $n_f(x)=0$（不必要）；否则 $n_f(x)=1$（必要）。

$$
n_f(x) = \begin{cases}
0 & \text{if } f(x) \text{ is correct for all } i \in \{1, \dots, N\} \\
1 & \text{otherwise}
\end{cases}
$$

这一设计动机在于解决静态标注无法捕捉模型能力边界动态性的问题。例如，一个中等难度的算术题对Qwen3-8B可能是不必要的，但对Llama-3.2-3B则是必要的。通过 $N$ 和 $T$ 参数控制严格度，该定义更贴近真实部署中对“可靠性”的要求，而非单纯的“正确性”。

### 认知-执行两阶段分解与正交性分析

本文将工具使用过程解构为两阶段：$x \rightarrow z_f(x) \rightarrow a_f(z_f(x))$，其中 $z_f(x)$ 为内部认知（Cognition），$a_f$ 为执行动作（Action）。为诊断失败来源，本文训练两个探针：认知探针 $\mathbf{w}_c$ 预测 $n_f(x)$，执行探针 $\mathbf{w}_a$ 预测实际调用行为 $a_f$。

$$
\mathbf{w}_c = \arg\min_{\mathbf{w}} \sum_{k} \mathcal{L}(\sigma(\mathbf{w}^T \mathbf{h}_{[t, l]}^{[x_k]}), n_f(x_k))
$$

关键发现在于，在深层（Late-layer）且靠近生成起始的token位置，$\mathbf{w}_c$ 与 $\mathbf{w}_a$ 的余弦相似度接近零，即二者近乎正交。这表明模型内部关于“是否需要工具”的表征与“是否调用工具”的意图表征在几何空间上是分离的。这一正交性解释了为何模型可能具备正确的元认知（$\mathbf{w}_c$ 可解码），却未能转化为正确的行动（$\mathbf{w}_a$ 不可解码或方向偏离），构成了“认知-执行鸿沟”的机制基础。

## 实验评估

实验基于两个代表性领域：算术（4,000例，涵盖从简单加减到复杂优先级运算）和事实问答（TruthfulQA，817例）。评估对象包括Qwen3-8B、Qwen3-4B、Llama-3.1-8B-Instruct和Llama-3.2-3B-Instruct四个模型。基线审计方面，本文未对比具体的SFT或RLVR训练方法，而是以模型自身的无工具推理性能为基准，对比其有工具调用行为与理论最优必要性之间的偏差。这种设计使得实验重点在于机制诊断而非性能提升，因此缺乏与Tool-R1或IACM-RL等优化方法的直接性能对比。

| 模型 | 算术任务不匹配率 (%) | TruthfulQA不匹配率 (%) | 主要失败模式 (算术) |
| :--- | :--- | :--- | :--- |
| Qwen3-8B | 41.7 | 31.1 | 工具过度使用 (UN-C: 38.2%) |
| Qwen3-4B | 26.5 | 41.8 | 工具使用不足 (N-NC: 14.5%) |
| Llama-3.1-8B-Instruct | 38.5 | 30.8 | 工具使用不足 (N-NC: 30.1%) |
| Llama-3.2-3B-Instruct | 54.0 | 32.8 | 工具使用不足 (N-NC: 39.0%) |

数据显示，不匹配率高达26.5%至54.0%（算术）和30.8%至41.8%（TruthfulQA），表明相当比例的查询中，模型的工具调用行为与其实际能力边界不一致。值得注意的是，失败模式具有强烈的模型依赖性：Qwen3-8B在算术任务中倾向于过度调用工具（UN-C占38.2%），而在TruthfulQA中转为使用不足；Llama系列模型则在算术任务中普遍表现出严重的使用不足（N-NC高达30.1%-39.0%）。这种跨任务、跨模型的不一致性表明，不存在单一的偏差方向可以解释所有错误，进一步支持了认知与执行解耦的假设。

评估边界方面，本文实验局限于单步工具调用（计算器或搜索API），未涉及多步依赖或复杂API交互。指标上，主要报告不匹配率（Mismatch Rate），未提供置信区间或统计显著性检验。可复现性方面，代码已开源，但探针训练超参数（如学习率0.01，Adam优化器）在附录中给出，未详细报告GPU资源消耗。由于缺乏与优化方法的对比，本文结论的有效性限于解释力，无法直接推断现有SOTA方法在BFCL等基准上的高分是否掩盖了类似的认知缺陷。

## 关联研究分析

从问题动机看，本文与Tool-R1（Zhang et al., 2025）和Tool Zero（Zeng et al., 2025）形成互补而非竞争关系。Tool-R1通过损失掩码机制优化多步交互中的信用分配，Tool Zero通过动态泛化引导奖励策略提升OOD泛化性，二者均假设模型能够正确识别何时需要工具，从而将优化重点放在“如何调用”的策略上。本文则指出，在能力边界附近，模型可能无法正确识别必要性，或者识别了但未能执行。这意味着，即使采用Tool-R1的强化学习框架，若模型存在认知-执行鸿沟，奖励信号可能无法有效纠正根本性的决策错误。本文的发现提示，RLVR方法可能需要引入针对“必要性判断”的细粒度奖励，而不仅仅是任务成功率的稀疏奖励。

从方法设计看，本文与IACM-RL（Zhu et al., 2026）在意图管理上存在潜在冲突。IACM-RL通过追踪用户意图的修改和澄清来动态调整上下文，旨在提升多轮交互中的适应性。然而，本文发现的主要错误源于执行阶段而非认知阶段，即模型内部已知晓必要性但未能输出调用token。IACM-RL的上下文管理可能改善了认知阶段的准确性，但若执行阶段的正交性问题未被解决，其收益可能受限。此外，本文使用的线性探针方法在TruthfulQA上的表现弱于算术任务，表明在开放域事实问答中，必要性信号更难线性解码。这与GRETEL等检索增强方法面临的挑战一致：语义相似度不等于功能可行性，且内部表征的线性可解码性受任务表面结构影响。

## 总结

本文针对工具增强LLM中“何时调用”决策的可靠性问题，提出了模型自适应必要性定义，并揭示了认知与执行阶段的解耦现象。通过线性探针分析，本文证明了模型内部具备区分必要性的能力，但这一认知在深层表征中与执行意图正交，导致高达54.0%的行为不匹配。这一发现挑战了现有RLVR方法中关于模型具备正确元认知能力的隐含假设，表明优化调用策略前需先解决认知到行动的转化问题。然而，本文实验局限于单步工具调用和特定任务类型，未验证该鸿沟在复杂多步依赖任务中的存在性。当任务涉及多步工具链且中间状态需要动态更新时，认知-执行的正交性是否依然成立，还是会被任务结构所掩盖，论文未给出回答。
