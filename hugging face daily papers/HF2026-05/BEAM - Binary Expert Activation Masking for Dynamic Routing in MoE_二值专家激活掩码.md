# HuggingFace最新推荐论文 ｜BEAM: Binary Expert Activation Masking for Dynamic Routing in MoE ｜二值专家激活掩码

研究机构：北京大学

作者：Juntong Wu、Jialiang Cheng、Qishen Yin 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.14438)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.14438)

> 稀疏混合专家（Sparse Mixture-of-Experts, SMoE）架构通过固定 Top-K 路由解耦参数规模与计算成本，但忽略了 Token 级复杂度差异，导致简单 Token 产生冗余计算。现有动态路由方法要么修改 Logits 无法跳过高权重冗余专家，要么引入零计算专家造成间接控制与超参依赖，且在训练-推理阶段存在不一致性。BEAM 通过引入轻量级可学习掩码路由器，在 Top-K 候选集上生成二值掩码直接剔除冗余专家，实现了稀疏控制与专家选择的解耦。该方法在保持 98% 以上精度的同时，将 MoE 层 FLOPs 降低至 85%，但 Mask Router 的额外参数量与训练成本是否抵消了推理收益，仍需更严格的系统级评估。

## 研究背景

SMoE 的核心机制在于路由网络 $R$ 将输入 Token $\mathbf{x}$ 映射为 Logits $\mathbf{r}$，经 Softmax 归一化后仅激活权重最高的 $K$ 个专家。这一固定预算机制虽简化了训练，却假设所有 Token 具有同等计算需求。当面对低复杂度 Token 时，部分高权重专家的输出贡献微乎其微，形成计算冗余。这种冗余直接转化为推理延迟，成为 SMoE 部署的主要瓶颈之一。

为打破固定 Top-K 的限制，研究界探索了动态专家激活路线。修改路由 Logits 的方法（如 MoE-Dynamic）通过累积概率阈值决定激活数，但受限于最低激活下限，无法实现极端稀疏；引入零计算专家的方法（如 AdaMoE）通过路由至空专家减少 FLOPs，但稀疏性控制是被动且间接的，且需额外超参调优；静态剪枝与合并方法虽无需训练，但无法适应推理时输入复杂度的实时变化。这些方法共同的缺陷在于将专家选择、负载均衡与稀疏控制耦合在单一路由器中，导致梯度冲突，且在训练与推理阶段的行为不一致，限制了其在后训练场景下的稳定性。

BEAM 的切入点在于解耦稀疏控制与专家选择。它不修改主路由器的 Logits，也不引入新的专家类型，而是新增一个轻量级掩码路由器，专门负责在 Top-K 候选集中识别并剔除冗余专家。这种设计保留了主路由器的负载均衡功能，同时通过二值掩码实现了 Token 级的细粒度稀疏控制，旨在解决现有动态路由方法在高稀疏度下性能急剧下降的问题。

## 核心方法

### 方法参照系

BEAM 置于动态路由框架下，其标准流程为：主路由器计算 Top-K 候选集，随后通过某种机制调整激活数量。与修改 Logits 或引入零专家的方法不同，BEAM 在 Top-K 候选集之后引入独立的二值掩码步骤，将稀疏决策从路由选择中剥离，形成“选择-掩码”两级结构。

### 二值掩码生成与解耦

BEAM 的核心创新在于引入参数为 $\mathbf{W}_m \in \mathbb{R}^{d \times N}$ 的掩码路由器，生成原始掩码 $\hat{\mathbf{m}} = \sigma(\mathbf{x}\mathbf{W}_m)$，并通过固定阈值 $\tau=0.5$ 二值化为 $\mathbf{m} \in \{0,1\}^N$。最终激活权重为 $\hat{\mathbf{g}} = \mathbf{g} \odot \mathbf{m}$，其中 $\mathbf{g}$ 为主路由器的 Top-K 权重。

$$
\hat{\mathbf{g}} = \text{Top-K}(\text{softmax}(\mathbf{r})) \odot \mathbb{I}(\sigma(\mathbf{x}\mathbf{W}_m) \geq 0.5)
$$

该公式表明，掩码路由器仅对主路由器选出的 Top-K 专家进行“否决”，不改变专家的选择顺序。设计动机在于解决 Logits 修改方法无法跳过高权重冗余专家的失效：即使某专家 Logits 较高，若其对当前 Token 贡献微小，掩码可将其置零。这种解耦避免了稀疏优化与负载均衡的梯度冲突，使主路由器专注于专家选择，掩码路由器专注于冗余消除。

### 直通估计器与稀疏正则化

由于二值化操作不可微，BEAM 采用直通估计器（Straight-Through Estimator, STE）进行反向传播。在反向传播中，阈值函数被视为恒等映射，梯度直接传回原始掩码 $\hat{\mathbf{m}}$。同时，引入 L1 正则化损失 $L_{reg} = \beta \sum_{i \in TK} |\hat{m}_i|$，其中 $TK$ 为 Top-K 候选集。

$$
L_{total} = L_{lm} + \alpha L_{bal} + \beta \sum_{i \in TK} |\hat{m}_i|
$$

该损失函数直接鼓励掩码路由器抑制 Top-K 集合内的冗余专家，而不影响非选中专家。设计动机在于解决软掩码方法（如 Sigmoid 门控）在训练-推理阶段的不一致性问题：软掩码在推理时需额外阈值化，导致性能退化；而 BEAM 通过 STE 和 L1 正则化，确保训练时的稀疏信号与推理时的二值行为一致，实现了端到端的稀疏学习。

## 实验评估

实验在 Qwen1.5-MoE-A2.7B、DeepSeek-V2-Lite 和 Qwen3-30B-A3B 上进行，使用 Tulu 3 SFT 数据集微调，基线包括 Top-K Reduced、Top-K Pruning、MoE-Dynamic、AdaMoE 和 DynMoE。评估基准涵盖 MMLU、GSM8K、HumanEval 等 8 项任务，硬件为单卡 NVIDIA H20。

| 模型 | 方法 | Avg-K | MMLU | GSM8K | H_Eval | Avg. |
|---|---|---|---|---|---|---|
| Qwen3-30B-A3B | BEAM (β=0.1) | 1.23 | 76.06 | 85.90 | 81.10 | 77.14 |
| Qwen3-30B-A3B | Top-K Reduced K=2 | 2.00 | 72.99 | 77.79 | 72.56 | 72.18 |
| Qwen3-30B-A3B | MoE-Dynamic φ=0.1 | 1.74 | 67.59 | 75.36 | 72.38 | 67.93 |
| DeepSeek-V2-Lite | BEAM (β=1.0) | 0.48 | 38.33 | 45.19 | 42.07 | 47.39 |
| DeepSeek-V2-Lite | Top-K Reduced K=1 | 1.00 | 28.75 | 31.99 | 25.00 | 35.77 |

在 Qwen3-30B-A3B 上，BEAM 在 Avg-K=1.23 时取得 77.14 的平均准确率，显著优于 Top-K Reduced (72.18) 和 MoE-Dynamic (67.93)。在 DeepSeek-V2-Lite 极端稀疏设置下，BEAM (Avg-K=0.48) 比 Top-K Reduced (Avg-K=1.00) 高出 11.62 个百分点，验证了解耦机制在高稀疏度下的稳定性。

消融实验显示，移除 $L_{reg}$ 导致 Avg-K 从 1.23 升至 6.31，准确率仅微升 0.9%，表明正则化对稀疏性控制至关重要。将 L1 替换为 L2 正则化，Avg-K 升至 2.01，准确率下降 2.4%，说明 L1 范数更适合稀疏诱导。软掩码变体（Soft）性能骤降 69.5%，证实了 STE 与二值化在训练-推理一致性中的必要性。

评估边界方面，实验仅覆盖单卡 H20 环境，未测试多卡分布式场景下的通信开销。Mask Router 的参数量占比未详细报告，可能影响整体内存占用。代码已开源，但超参数 $\beta$ 需针对每个模型单独调优，缺乏通用设置。

## 关联研究分析

从问题动机看，BEAM 与 Elastic MoE 均追求动态稀疏，但路径截然不同。Elastic MoE 通过随机共激活采样在推理时扩展激活专家，侧重解决资源波动下的性能退化；BEAM 则通过训练时学习掩码在推理时收缩激活专家，侧重解决固定 Top-K 的计算冗余。BEAM 的掩码机制依赖于训练阶段的充分采样，若训练数据未覆盖极端稀疏场景，推理时可能失效。Elastic MoE 的采样策略虽灵活，但缺乏理论指导，性能波动较大。BEAM 的解耦设计是否能在训练数据分布偏移时保持鲁棒性，论文未给出回答。

从方法设计看，BEAM 与 PuzzleMoE 均关注专家冗余，但处理层级不同。PuzzleMoE 通过稀疏专家合并与位打包实现静态压缩，侧重降低内存占用；BEAM 通过二值掩码实现动态稀疏，侧重降低计算 FLOPs。PuzzleMoE 的合并策略基于静态相似度，难以捕捉动态上下文下的功能互补性；BEAM 的掩码路由器基于输入 Token 实时决策，具有更强的适应性。然而，BEAM 的掩码路由器引入了额外参数，而 PuzzleMoE 的合并是训练后处理，无额外推理开销。在内存受限的边缘设备上，BEAM 的额外参数量是否抵消了 FLOPs 降低的收益，需结合内存占用指标综合评估。

## 总结

BEAM 旨在解决固定 Top-K 路由导致的计算冗余问题，其切入点在于解耦稀疏控制与专家选择，通过轻量级掩码路由器在 Top-K 候选集上生成二值掩码，避免了 Logits 修改方法的梯度冲突与零专家方法的间接控制缺陷。实验证明，BEAM 在 Qwen3-30B-A3B 上以 1.23 的平均激活专家数保持了 77.14 的准确率，比 Top-K Reduced 高出 4.96 个百分点，并在 DeepSeek-V2-Lite 极端稀疏下比基线高出 11.62 个百分点。然而，BEAM 的边界在于 Mask Router 的额外参数量与训练成本，以及超参数 $\beta$ 的模型依赖性。当模型规模进一步扩大或部署于内存受限的边缘设备时，Mask Router 的参数量占比是否成为新的瓶颈，论文未给出回答。
