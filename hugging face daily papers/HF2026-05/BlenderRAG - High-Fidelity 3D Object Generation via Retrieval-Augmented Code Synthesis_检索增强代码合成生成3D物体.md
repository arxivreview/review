> 从文本描述生成可执行Blender代码以构建高保真3D物体，是连接语言指令与几何建模的关键环节。现有大语言模型（LLM）直接生成代码常伴随语法错误与几何比例失调，而微调路线依赖昂贵的GPU资源。本文切入点在于利用检索增强生成（Retrieval-Augmented Generation, RAG）注入专家验证的语义相似样本，无需训练即可提升代码质量。该方法通过向量数据库匹配多模态三元组作为上下文，显著提升了编译成功率与语义对齐度。其价值在于降低了部署门槛，但单物体生成的局限性与静态代码库的泛化边界仍存疑。

## 研究背景

当LLM尝试将自然语言转化为Blender Python代码时，其输出往往缺乏几何连贯性，导致生成的物体出现比例失真或结构断裂。这一困境源于LLM在训练过程中缺乏对3D空间几何约束的显式建模，仅依赖文本统计规律难以保证代码执行后的物理合理性。为缓解此问题，检索增强生成（Rrieval-Augmented Generation, RAG）被引入，其核心机制是在推理阶段从外部知识库中检索与查询语义相似的实例，将其作为上下文注入提示词，从而引导模型生成更符合领域规范的内容。

3D场景与物体生成领域长期面临数据稀缺与几何一致性难以兼顾的矛盾。早期方法如BlenderLLM（Du et al., 2024）通过迭代微调与自我改进提升代码质量，但需消耗数百GPU小时且依赖复杂训练管线；SceneCraft（Yang et al., 2024）采用多智能体分解策略，虽解决了结构规划问题，却牺牲了单个物体的视觉真实感。主流路线在“可编辑性”与“视觉保真度”之间做出不同取舍，而零训练部署的轻量化方案尚属空白。本文聚焦于单物体代码合成，旨在通过外部知识检索替代参数更新，在保持LLM通用能力的同时，针对性地弥补其在3D几何细节生成上的短板。

## 核心方法

### 多模态专家数据集构建

本文方法建立在结构化代码表示之上，将3D物体定义为可执行的Blender Python代码序列，而非隐式神经场或3D高斯泼溅（3DGS）。与通用代码生成流程不同，本文构建了一个包含500个专家验证样本的多模态数据集，覆盖50个物体类别（25室内、25室外），每个类别含10种设计变体。每个样本由文本描述、可执行代码及渲染图像三元组组成，代码长度从简单物体的约4,000字符到复杂结构的约24,000字符不等。这种设计动机在于，LLM直接生成代码时缺乏对特定几何结构的先验知识，而专家验证的代码提供了经过物理与视觉双重校验的“标准答案”，为检索提供了高质量锚点。

### 语义检索与上下文注入

在推理阶段，系统首先利用Nomic-AI嵌入模型将用户查询文本向量化，并在Qdrant向量数据库中检索语义最相似的$k$个样本（实验中$k=3$）。检索过程基于余弦相似度计算：

$$
\text{sim}(q, d_i) = \frac{\mathbf{e}_q \cdot \mathbf{e}_{d_i}}{\|\mathbf{e}_q\| \|\mathbf{e}_{d_i}\|}
$$

其中$\mathbf{e}_q$与$\mathbf{e}_{d_i}$分别为查询与文档的嵌入向量。该公式的物理含义是，在语义空间中寻找与用户意图最接近的几何结构范式。随后，检索到的文本描述与对应代码被注入LLM提示词作为上下文。这一设计解决了纯自回归生成中模型“幻觉”几何细节的问题，通过提供具体的代码模式（如顶点坐标、材质参数），引导LLM在局部结构上模仿专家样本，从而在无需微调的情况下实现几何连贯性的显著提升。

## 实验评估

实验在30个分布外（Out-of-Distribution, OOD）提示上进行，评估指标为编译成功率与基于CLIP的语义对齐分数。基线对比涵盖Claude Sonnet 4.5、GPT-5、Gemini 3 Flash及Mistral Large四个LLM的零样本表现，但未包含BlenderLLM等微调方法的直接对比，限制了与SOTA微调路线的公平性比较。

| 模型 | 编译成功率 (%) Base | 编译成功率 (%) RAG | 语义对齐 Base | 语义对齐 RAG |
| :--- | :--- | :--- | :--- | :--- |
| Claude Sonnet 4.5 | 43.3 | 76.7 | 0.544 | 0.780 |
| GPT-5 Chat | 56.6 | 80.0 | 0.267 | 0.777 |
| Gemini 3 Flash | 66.7 | 53.3 | 0.498 | 0.770 |
| Mistral Large | 53.3 | 56.7 | 0.327 | 0.769 |
| **平均** | **40.8** | **70.0** | **0.409** | **0.774** |

数据显示，RAG机制将平均编译成功率从40.8%提升至70.0%，语义对齐分数从0.409提升至0.774。值得注意的是，Gemini 3 Flash在RAG条件下编译率反而下降（66.7%至53.3%），这可能源于检索代码与该模型预训练分布的不匹配，揭示了RAG效果对底层LLM特性的依赖。

评估边界方面，30个OOD样本量较小，统计显著性有限；缺乏与微调方法的对比，无法证明RAG的性能上限是否高于微调；代码未公开超参数细节（如嵌入模型版本、检索阈值），可复现性依赖GitHub仓库的完整实现。

## 关联研究分析

从问题动机看，BlenderRAG与BlenderLLM均旨在解决LLM生成3D代码的几何不一致性，但前者选择外部知识检索而非参数更新。BlenderLLM通过迭代微调内化几何先验，适合资源充足的场景；而BlenderRAG通过检索外部样本，将几何知识外置，牺牲了模型的自主泛化能力，换取了部署的轻量化。这种差异源于任务特性：单物体生成对几何细节的依赖高于对长程语义推理的需求，使得静态代码库的检索比动态学习更具性价比。

从方法设计看，BlenderRAG与SceneCraft同属LLM驱动的代码生成框架，但后者采用多智能体分解处理多物体场景，前者聚焦单物体几何质量。SceneCraft通过结构规划解决全局布局，BlenderRAG通过语义检索解决局部几何。两者互补：BlenderRAG可作为SceneCraft中物体生成的原子模块，提供高保真的单物体代码，而SceneCraft负责将这些物体组合成场景。这种分工暗示了“结构化代码”路线中，局部几何生成与全局结构规划可解耦处理。

## 总结

BlenderRAG旨在解决LLM生成3D代码时几何连贯性不足与微调成本高昂的矛盾。其切入点在于利用检索增强生成注入专家验证的多模态样本，无需训练即可提升代码质量。实验表明，该方法将平均编译成功率从40.8%提升至70.0%，语义对齐分数从0.409提升至0.774。然而，其边界在于单物体生成局限、静态代码库的泛化能力以及缺乏与微调方法的公平对比。当支持集从500个样本扩展至更大规模时，检索的边际收益是否递减，论文未给出回答。
