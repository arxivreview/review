# HuggingFace最新推荐论文 ｜Continual Harness: Online Adaptation for Self-Improving Foundation Agents ｜持续框架：具身智能体在线自改进的无重置范式

研究机构：美国普林斯顿大学、谷歌DeepMind

论文原文见 [arXiv](https://arxiv.org/abs/2605.09998)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.09998)

> 具身智能体在长时程部分可观测环境中缺乏类似代码代理的标准化脚手架，导致前沿视觉语言模型在角色扮演游戏（RPG）中几乎无法取得进展。现有提示优化方法依赖完整回合重置，无法处理长时程任务中后期才出现的失败模式，且重置会中断经验积累。本文提出 Continual Harness，通过在线上下文学习在单一连续回合内自动重构系统提示、子代理、技能与记忆，实现无重置的框架自改进。该框架在强模型上显著降低操作成本并缩小与人工专家框架的差距，但在弱模型上失效，揭示了能力阈值对框架进化的决定性作用。

## 研究背景

具身智能体交互依赖最小化接口，即帧观测 $o_t$、ASCII 文本地图 $m_t$ 与按钮输入 $a_t$。由于视觉语言模型空间推理能力有限，文本地图补偿了帧观测的不足，但不包含路径规划或目标列表。这种部分可观测性要求智能体通过外部脚手架（Harness）管理状态，而代码代理领域的 Claude Code 等工具已确立了包含工具、记忆与规划的标准化脚手架，具身领域却缺乏等效基础设施。

主流自进化路线分为非参数化反思与参数化内化。Reflexion 等通过自然语言反思实现即时修正，但受限于上下文窗口；EvolveR 等通过定期微调将经验蒸馏为参数，但面临灾难性遗忘与高计算成本。提示优化方法如 GEPA 虽能重写提示，但需运行完整回合并在更新间重置，导致无法触及长时程任务后期（如终局战斗、多步谜题）的失败模式，且重置后经验积累归零。本文切入点在于将框架进化从离线批量优化转为在线连续过程，利用单一回合内的轨迹数据实时重构脚手架，避免重置带来的状态丢失与经验断裂。

## 核心方法

### 框架组件与最小化基线

框架 $H$ 定义为模型 $M$ 与环境间的脚手架层，包含系统提示 $p$、子代理 $G$、技能 $K$ 与记忆 $M$。最小化框架 $H_{min}$ 仅提供环境接口与通用提示，无子代理、记忆或技能。专家框架 $H_{expert}$ 通过人工工程填充所有组件，包含预构建的路径规划器、类型图表与伤害计算器。本文从 $H_{min}$ 出发，引入自动化 Refiner 在线重构 $H$，形成运行态框架 $H_{CH}$。

### 无重置在线重构循环

Refiner 每 $F$ 步读取最近轨迹窗口 $\tau_{t-F:t}$，识别导航循环、工具调用失败等失败签名，并对 $p, G, K, M$ 执行 CRUD 操作。重构公式为：

$$ H_{t+1} = H_t \oplus \Delta, \quad \Delta = (\Delta p, \Delta G, \Delta K, \Delta M) $$

其中 $\oplus$ 表示基于元工具 API 的组件更新。与 GEPA 等重置方法不同，该过程在单一回合内连续进行，早期观察到的失败签名在后续重构中持续可用，重构质量随回合长度复合增长。设计动机在于解决重置方法无法触及长时程后期失败模式的问题，同时避免重置导致的经验积累中断。

### 模型-框架协同学习

在线协同学习循环将开源模型权重 $\theta$ 与框架状态 $H_t$ 联合更新。每轮迭代运行策略 $\pi_{\theta_k}$ 于实时重构框架 $H_t$ 中 $K=256$ 步，使用成对过程奖励模型（PRM） $R(s_t, a_t, \tau) \in [0,1]$ 评分：

$$ \theta_{k+1} = \theta_k - \eta \nabla L_{SFT}(\mathcal{D}_k) $$

其中 $\mathcal{D}_k$ 为低奖励窗口经前沿教师重标注后的数据分片。循环无重置，第 $k$ 轮结束时的模拟器状态加载为第 $k+1$ 轮起点，模型游戏位置跨训练迭代累积。设计动机在于解决单一组件优化的局限，使模型轨迹分布与框架状态共同适应，形成闭环自改进。

## 实验评估

实验在 Pokémon Red 与 Emerald 上进行，使用 PokeAgent Challenge 标准化里程碑评估，主指标为累计按钮按压数。基线包括 $H_{min}$、$H_{expert}$ 及三种 Continual Harness 变体（从头开始、引导冻结、引导更新）。模型涵盖 Gemini 3 Pro、Flash、Flash-Lite 及开源 Gemma-4 系列。

| 模型 | 框架变体 | 里程碑达成率 (%) | 中位成本 (USD) |
| :--- | :--- | :--- | :--- |
| Gemini 3 Pro | $H_{min}$ | 98 | 215 |
| Gemini 3 Pro | CH, from scratch | 100 | 130 |
| Gemini 3 Pro | CH, bootstrap updating | 96-100 | 110-140 |
| Gemini 3 Flash | $H_{min}$ | 77 | 30 |
| Gemini 3 Flash | CH, bootstrap updating | 80 | 42 |
| Gemini 3 Flash-Lite | $H_{min}$ | 20 | 11 |
| Gemini 3 Flash-Lite | CH, all variants | 3-13 | 可比或更高 |

在 Pro 模型上，CH 从头开始变体以 $130 中位成本达到 100% 里程碑，较 $H_{min}$ 的 $215 降低约 40% 且无完成度损失，严格帕累托占优。Flash 模型上收益高方差，引导更新变体以 $42 达到 80%，略高于 $H_{min}$ 的 $30 达到 77%。Flash-Lite 上所有 CH 变体表现低于 $H_{min}$ 的 20%，降至 3-13%，表明框架进化存在能力阈值。

消融显示框架重构集中于导航与战斗组件，Yellow Legacy 运行中更新持续而非收敛至固定脚手架。协同学习在 Pokémon Red 上驱动 Gemma-4 模型跨训练迭代实现持续里程碑进展，从开局与中局检查点均有效。评估边界在于仅使用 Gemini API 成本作为代理指标，未报告计算延迟或 GPU 资源消耗；开源模型实验仅验证了 Gemma-4 系列，未覆盖其他架构；代码未公开，可复现性受限。

## 关联研究分析

从问题动机看，本文与 Reflexion 共享“从失败中学习”的核心逻辑，但 Reflexion 依赖自然语言反思存储于外部记忆，受限于检索精度与上下文窗口，且通常需任务重置。本文将反思自动化为 Refiner 的 CRUD 操作，直接修改框架组件而非仅存储文本，解决了长时程任务中经验固化不足的问题。差异根源在于任务形态：具身 RPG 的状态空间连续且部分可观测，文本反思难以精确映射到按钮序列，而框架组件（如路径规划器）可直接执行，因此组件级重构比文本级反思更具操作性。

从方法设计看，本文与 Voyager 的技能库概念相似，但 Voyager 通过课程驱动探索构建静态技能库，需离线验证与存储。本文技能库在线动态更新，Refiner 可删除未有效调用的技能，适应环境变化。与 GEPA 相比，GEPA 优化提示需完整回合重置，本文无重置在线更新，但 GEPA 在文本任务中可能更稳定，因文本生成错误率低于具身动作序列。本文未探索框架复杂度与模型能力的自适应匹配机制，Flash-Lite 失效是否因模型无法理解复杂框架指令，论文未给出回答。

## 总结

本文核心矛盾在于具身智能体缺乏标准化脚手架，且现有自进化方法依赖重置，无法处理长时程后期失败。本文抓住“无重置在线重构”切入点，利用单一回合轨迹数据实时修改框架组件，避免重置导致的经验断裂。方法通过 Refiner 执行 CRUD 操作与模型-框架协同学习，在 Pro 模型上以 $130 成本达到 100% 里程碑，较基线降低 40% 成本。边界在于框架进化存在能力阈值，Flash-Lite 上所有变体表现低于基线，且协同学习仅验证了 Gemma-4 系列。当模型能力低于阈值时，框架重构是否反而引入噪声导致性能下降，论文未给出回答。
