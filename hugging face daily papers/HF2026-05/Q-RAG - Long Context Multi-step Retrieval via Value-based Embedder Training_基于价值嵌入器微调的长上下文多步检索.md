> 长上下文多步检索旨在解决大语言模型在超长文本中因注意力稀释导致的证据定位失效问题。现有方法要么依赖昂贵的LLM微调，要么受限于静态检索策略，难以兼顾效率与精度。Q-RAG通过强化学习直接微调文本块嵌入器，在潜在空间执行多步检索决策。该方法在10M token长上下文基准上取得SOTA，但在复杂多跳问答中表现略逊于过程奖励方法，其泛化边界尚待验证。

## 研究背景

当大语言模型处理百万级token的长文本时，静态参数化知识无法覆盖动态更新的信息，且长上下文中的注意力稀释导致关键证据被忽略。这一困境催生了检索增强生成（Retrieval-Augmented Generation, RAG）范式，其核心是通过外部检索过滤无关内容，使模型聚焦于短小且相关的输入。然而，传统单次检索仅适用于简单任务，复杂问题需要多步交互以逐步积累证据，这构成了多步检索推理的核心挑战。

多步检索的主流路线包括构建知识图谱和LLM智能体。知识图谱方法（如GraphReader, HippoRAG）虽无需额外训练，但推理时需LLM处理整个上下文以构建图谱，速度极慢。LLM智能体方法（如Search-R1, R1-Searcher）通过微调LLM生成中间查询，但需要昂贵的LLM微调资源，且对噪声检索结果敏感。这些方法的共同瓶颈在于：要么牺牲推理速度，要么牺牲训练效率，且均未能有效解决长上下文中的时序依赖问题。

Q-RAG的切入点在于将优化对象从LLM转向嵌入器。通过基于价值的强化学习（Value-based RL）直接微调文本块嵌入器，Q-RAG在潜在空间执行多步检索，避免了LLM微调的高昂成本。这一设计使得模型能够与任意规模的LLM（包括专有模型）配合使用，同时保持训练和推理的高效性。

## 核心方法

### 方法参照系

多步检索通常被建模为序列决策问题，主流方法通过微调LLM生成查询或构建图谱来优化检索策略。Q-RAG的关键差异在于：不微调LLM，而是微调嵌入器，使其在潜在空间直接评估文本块的检索效用，从而将多步检索转化为基于价值函数的序列决策过程。

### 基于价值的嵌入器微调

Q-RAG将多步检索建模为有限时域马尔可夫决策过程（MDP），其中状态$s_t$包含初始查询$q$和已选文本块序列，动作$a_t$为选择下一个文本块。设计动机在于解决固定启发式规则无法适应长上下文动态性的问题。Q函数通过状态嵌入器$E_s$和动作嵌入器$E_a$的内积计算：

$$Q_\theta(s, a[i]) = \langle E_s(s; \theta_1), E_a(a[i], i; \theta_2) \rangle$$

该公式的物理含义是：通过两个嵌入向量的相似度评估在状态$s$下选择文本块$a[i]$的效用。策略$\pi_\theta$采用Boltzmann分布，根据Q值概率选择下一个文本块，温度$\alpha$控制探索强度。训练采用PQN算法，使用$\lambda$-return作为目标，避免重放缓冲区的内存开销。

### 时序推理机制

针对叙事文本中事件时序依赖导致的检索歧义，Q-RAG引入相对位置编码。设计动机在于解决标准检索器无法捕捉“事件前因后果”这一时序逻辑的问题。相对位置映射$\rho_t(i)$将原始文本块索引映射为相对于已选事实的区间位置：

$$\rho_t(i) = b_j + \delta \cdot \frac{i - b_j}{b_{j+1} - b_j}$$

其中$b_j$为区间边界，$\delta$控制区间间步长。该机制使Q函数能够利用候选文本块与已检索证据的空间关系，保留区间内局部顺序，从而支持时序推理。

## 实验评估

实验覆盖Babilong（常识/时序推理）、RULER（NIAH/长上下文QA）和HotpotQA/Musique（开放域多跳QA），上下文长度从4K到10M token。基线包括长上下文模型（Titans, Atlas, Mamba2-Hybrid, LongRoPe2-8B）和RL检索方法（Beam-Retriever, Search-R1, RAG-RL）。

| 基准 | 方法 | 1M Token Avg. | 10M Token Avg. |
| :--- | :--- | :--- | :--- |
| RULER | Q-RAG | 99.7 | 100 |
| RULER | LongRoPe2-8B | 96.7 | n/a |
| RULER | Mamba2-Hybrid | 88.0 | n/a |

在RULER基准上，Q-RAG在1M token时平均得分99.7，10M token时达到100，显著优于LongRoPe2-8B（96.7）和Mamba2-Hybrid（88.0）。在HotpotQA上，Q-RAG的Ans F1为0.97，Ans EM为0.71；在Musique上，Ans F1为0.64，Ans EM为0.48。

| :--- | :--- | :--- | :--- |
| Q-RAG | 97.8±0.17 | 93.3±0.45 | 15.52±0.11 |
| w.o. Soft-Q | 97.4±0.14 | 79.2±26.0 | 16.38±0.10 |
| w.o. Target | 97.1±0.08 | 78.1±26.6 | 15.51±0.16 |
| w. SFT | 96.8±0.08 | 77.6±27.2 | 15.34±0.12 |
| w.o. FT | 95.9±0.70 | 75.9±28.2 | — |

消融实验显示，移除Soft-Q（熵正则化）导致32K token时F1从93.3降至79.2，降幅14.1点，表明探索机制对长上下文检索至关重要。移除目标网络导致32K token时F1降至78.1，降幅15.2点，验证了目标网络对训练稳定性的贡献。监督微调（SFT）比无微调（w.o. FT）提升2.9点，但RL微调比SFT提升5.7点，表明RL在长上下文泛化上优于监督学习。

评估边界方面，Q-RAG在Musique上的EM（0.48）低于GTA-RAG（50.5），可能因缺乏过程奖励导致多跳推理稳定性不足。论文未提供代码URL，但所有训练在单卡A100（80GB）上完成，超参数包括温度$\alpha$、TD参数$\lambda$和EMA$\tau$。

## 关联研究分析

从方法设计看，Q-RAG与Search-R1同属RL检索路线，但优化对象不同。Search-R1微调LLM生成查询，而Q-RAG微调嵌入器评估文本块效用。这一差异源于任务特性：Search-R1依赖LLM的语义理解能力生成复杂查询，而Q-RAG依赖嵌入器的向量相似度计算，更适合长上下文中的高效检索。Q-RAG的效率优势（单卡训练 vs. 8卡集群）使其更易于部署，但可能牺牲了对复杂语义查询的理解能力。

从问题动机看，Q-RAG与HippoRAG均旨在解决多跳证据分散问题，但路径不同。HippoRAG通过构建知识图谱显式建模实体关系，而Q-RAG通过相对位置编码隐式捕捉时序依赖。HippoRAG的图谱构建成本高且推理慢，Q-RAG的嵌入器微调成本低且推理快。Q-RAG未对比HippoRAG，可能因两者适用场景不同：HippoRAG适合结构化知识密集任务，Q-RAG适合长上下文叙事任务。

## 总结

Q-RAG要解决的核心矛盾是长上下文多步检索中效率与精度的权衡。现有方法要么依赖昂贵的LLM微调，要么受限于静态检索策略，难以兼顾两者。Q-RAG通过基于价值的RL微调嵌入器，在潜在空间执行多步检索，避免了LLM微调的高昂成本。实验证明，Q-RAG在10M token长上下文基准上取得SOTA（RULER 100分），在HotpotQA上Ans EM达0.71。其边界在于：在Musique等复杂多跳任务上EM略低于过程奖励方法，且未验证在结构化知识密集任务上的表现。当嵌入器RL与过程奖励结合时，能否在保持效率优势的同时提升多跳推理稳定性，论文未给出回答。
