# HuggingFace最新推荐论文 ｜π-Bench: Evaluating Proactive Personal Assistant Agents in Long-Horizon Workflows ｜长程个人助理的主动意图评估基准

研究机构：上海交通大学、复旦大学

作者：Haoran Zhang、Luxin Xu、Zhilin Wang 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.14678)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.14678)

> 长程个人助理面临的核心困境是用户指令往往模糊且依赖未言明的偏好，现有基准多假设目标明确或侧重记忆检索，无法量化代理在持久工作流中主动发现并解决隐藏意图的能力。本文切入点在于构建一个包含跨会话依赖与隐藏意图状态追踪的评估环境，将“主动性”形式化为可计算的比率。通过100个多轮任务与9个前沿模型的实验，揭示了任务完成度与主动性之间的显著解耦。该基准填补了长程主动辅助评估的空白，但其用户模拟器“兜底提供信息”的机制是否掩盖了真实场景下的失败模式，仍存疑。

## 研究背景

当个人助理代理处理“帮我规划下周行程”这类请求时，表面目标明确，但实际执行依赖预算、时间偏好等未言明的约束。这种未言明需求被称为隐藏意图（Hidden Intents），它们往往分散在长程交互的历史会话中。若代理仅被动等待用户补充信息，将导致认知负荷增加与任务效率下降；反之，代理需具备主动性（Proactivity），即利用上下文与历史记忆预判需求，并通过行动或澄清推动任务进展。

现有评估体系存在结构性盲区。通用代理基准（如AgentBench）假设交互时目标已明确，记忆基准（Memory Agent Benchmarks）侧重信息的存储与检索，而非利用信息检测缺失需求。现有的主动基准多局限于移动端或GUI短程任务，缺乏对持久工作区、长程依赖及工件迭代场景的覆盖。这导致无法区分代理是“真正主动推断”还是“被动等待后完成任务”。π-BENCH的切入点正是将评估场景从短程GUI迁移至长程持久工作流，通过引入跨会话依赖与隐藏意图状态机，量化代理在长程交互中主动解决未明确需求的能力。

## 核心方法

### 方法参照系

本文问题属于代理能力评估类别，但与传统基准的关键差异在于评估对象从“任务完成”扩展至“意图发现过程”。传统流程通常以最终工件是否符合检查表为唯一标准，而本文引入中间状态追踪，将“如何获得信息”纳入评估维度，从而解耦了结果正确性与过程主动性。

### 隐藏意图状态追踪机制

传统基准中，用户模拟器通常一次性提供所有必要信息或仅响应代理提问，无法区分代理是主动推断还是被动等待。本文在会话交互循环中引入隐藏意图状态机，每个隐藏意图 $i \in I$ 被赋予唯一的终态状态。该设计解决了此前方法无法量化“代理是否主动发现需求”的问题，使得主动性可被精确计算。

$$
\text{Status}(i) \in \{ \text{completed}, \text{inferred}, \text{provided} \}
$$

其中，$\text{completed}$ 表示代理未询问用户即通过行动或工件满足意图；$\text{inferred}$ 表示代理提出针对性问题，用户随后揭示需求；$\text{provided}$ 表示代理未推断也未询问，用户主动提供信息。该状态机将模糊的“主动性”转化为离散的状态转移，为后续评分提供基础。

### 主动性与完整性解耦评估

基于状态追踪，本文定义了两个独立指标：主动性（Proactivity, PROC）与完整性（Completeness, COMP）。PROC衡量代理驱动需求发现的比率，COMP衡量最终任务要求的满足度。二者解耦揭示了“被动等待用户补充信息也能完成任务”但“缺乏主动性”的现象，这是此前单一成功率指标无法捕捉的维度。

$$
\text{PROC} = \frac{|I_{\text{com}}| + |I_{\text{inf}}|}{|I|}
$$

该公式将直接完成（$I_{\text{com}}$）与主动澄清（$I_{\text{inf}}$）赋予同等权重，仅排除用户被动提供（$I_{\text{pro}}$）的情况。其物理含义是：无论代理是直接推断还是通过提问获取，只要需求发现过程由代理驱动，即视为主动。COMP则基于检查表 $C$ 的评分总和，确保任务最终交付物的正确性。这种解耦设计使得评估能区分“高效但被动”与“低效但主动”的代理行为。

## 实验评估

实验在π-BENCH上进行，包含100个多轮任务，覆盖5个领域角色（研究员、营销人员、法律实习生、药剂师、金融家），每个角色20个会话。基线覆盖9个前沿LLM（GPT-5.4, Gemini 3.1 Pro, Claude 4.6 Opus等），但缺失专门针对主动性的强化学习微调模型（如ProActor）或神经符号增强模型（如NOEM3A），导致无法评估“增强方法”对主动性的提升效果。

| 模型 | PROC (%) | COMP (%) |
| :--- | :--- | :--- |
| GPT-5.4 | 67.0 | 65.6 |
| Claude 4.6 Opus | 65.6 | 67.6 |
| Qwen3.6 Plus | 64.0 | 64.1 |
| Kimi K2.5 | 43.1 | 61.6 |
| Seed2.0 Pro | 58.4 | 52.1 |

数据显示，GPT-5.4在PROC上最高（67.0%），而Claude 4.6 Opus在COMP上最高（67.6%）。Kimi K2.5的COMP（61.6%）显著高于其PROC（43.1%），表明该模型能完成任务但缺乏主动性，依赖用户补充信息。这种分离验证了PROC与COMP的解耦有效性，但也暴露了当前前沿模型在主动推断上的普遍短板。

消融实验未单独报告，但领域趋势分析显示，药剂师任务PROC与COMP均最高，因其任务基于具体本地文件与文献，隐藏意图更易从工件中推断；而研究员任务PROC较低，因其工作流标准化程度低，隐藏意图更抽象。这暗示PROC分数对任务类型的依赖性较强，可能低估了代理在复杂、非结构化场景下的主动能力。

评估边界方面，PROC对“澄清”与“直接推断”赋予同等权重，可能低估了直接推断的认知负荷优势。用户模拟器在代理未推断时主动提供信息，这一机制确保了任务可完成，但掩盖了真实场景中因代理沉默导致的任务失败或用户流失。代码已开源，但隐藏意图标注的准确性依赖领域专家，缺乏跨基准泛化验证。

## 关联研究分析

从问题动机看，π-BENCH与ProActor（Ding et al., 2026）均关注主动行为，但前者侧重评估基准构建，后者侧重RL优化动作正确性。ProActor通过时序感知RL解决SFT对早期行动惩罚的问题，而π-BENCH测试的是基座模型在无增强下的主动推断上限。二者互补：ProActor提供了提升主动性的方法路径，π-BENCH提供了评估该路径有效性的标准。然而，π-BENCH未包含RL微调模型作为基线，导致无法直接验证ProActor类方法在长程工作流中的增益。

从方法设计看，π-BENCH与NOEM3A（Tzachristas and Sui, 2025）形成“原生vs.增强”的潜在对比。NOEM3A通过神经符号本体增强提升小模型意图识别精度，而π-BENCH依赖LLM隐式推断。领域共识认为结构化表示能提升跨模型鲁棒性，但π-BENCH未使用5W3H等显式协议，而是测试LLM在无结构化约束下的表现。这种设计选择暗示，在长程持久工作流中，LLM的隐式推断能力可能已足够支撑跨会话一致性，但缺乏结构化协议时，推断稳定性是否足以应对高复杂度任务，论文未给出回答。

## 总结

π-BENCH要解决的核心矛盾是长程个人助理中隐藏意图的主动推断缺乏量化评估标准。现有基准或假设目标明确，或侧重记忆检索，无法区分代理是主动发现需求还是被动等待。本文通过构建包含跨会话依赖与隐藏意图状态机的评估环境，将主动性形式化为PROC比率，并证明其与完整性COMP显著解耦。实验显示GPT-5.4在PROC上最高（67.0%），但所有模型在PROC上均低于COMP，表明主动推断仍是前沿模型的短板。本文的边界在于用户模拟器“兜底提供信息”的机制，可能掩盖真实场景下因代理沉默导致的任务失败。当隐藏意图的复杂度进一步增加，或用户不再主动补充信息时，当前PROC分数是否仍能准确反映代理的主动能力，论文未给出回答。
