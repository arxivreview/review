# HuggingFace最新推荐论文 ｜optimize_anything: A Universal API for Optimizing any Text Parameter ｜通用文本工件优化接口

研究机构：美国麻省理工学院

作者：Lakshya A Agrawal、Donghyun Lee、Shangyin Tan 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.19633)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.19633)

> 现有LLM进化系统各自锁定单一工件类型（代码、提示或架构），无法跨域复用优化逻辑。本文指出，只要将工件序列化为字符串并配备评分函数，所有优化问题共享同一结构，从而构建了统一API。通过扩展Pareto搜索并引入侧信息契约，该系统在六个异构领域达到或超越专用工具性能。其价值在于验证了文本优化的通用性，但多任务迁移的边界条件与计算成本仍存疑。

## 研究背景

当优化器面对CUDA内核、云调度策略或智能体架构时，传统数值优化方法因缺乏梯度信号而失效。此时，大语言模型（LLM）作为提议者（Proposer）介入，通过读取执行反馈生成改进候选。然而，现有框架如AlphaEvolve仅处理代码，GEPA仅处理提示，导致用户需为每类工件编写专用接口，且无法利用跨域共享的优化模式。

该领域长期存在“工件类型锁定”瓶颈：代码进化系统（如FunSearch）依赖岛屿模型与特定标记，提示优化系统（如MIPROv2）依赖少样本选择，二者接口互不兼容。这种碎片化阻碍了通用优化范式的形成，使得跨域知识迁移（如将内存合并策略从CUDA迁移至其他计算任务）无法在单一系统内实现。

本文切入点在于将“工件”抽象为任意可序列化文本，并将“评估”标准化为返回分数与诊断信息的函数。通过剥离框架特定的变异模板与拓扑配置，optimize_anything将优化过程还原为“序列化-评估-反思”的闭环，旨在证明单一接口可覆盖代码、提示、架构及图像生成等异构任务。

## 核心方法

### 方法参照系

本文问题归属于LLM进化搜索范畴，标准流程为：LLM生成候选工件→评估器打分→选择最优者迭代。关键差异在于，传统流程假设工件类型固定且评估仅返回标量分数，而本文要求接口兼容任意文本工件，并强制评估器返回结构化诊断信息以支持跨域迁移。

### 侧信息（SI）契约机制

传统进化算法仅传递标量分数，导致提议者无法定位失败原因（如代码语法错误 vs 逻辑错误）。本文在评估器契约中引入侧信息（Side Information, SI）作为一等公民，要求评估器返回包含错误日志、性能剖析数据或渲染图像的字典。

$$
f(x, e) = (s(x, e), \mathcal{I}(x, e))
$$

其中 $s$ 为标量分数，$\mathcal{I}$ 为SI字典。该设计使LLM提议者能基于具体诊断（如堆栈跟踪）进行针对性修复，而非盲目变异。消融实验显示，SI使收敛速度提升4-6倍，并显著改善最终性能，解决了纯分数反馈下提议者“知其然不知其所以然”的失效问题。

### 多模式Pareto前沿搜索

GEPA的Pareto选择依赖多数据点评估，无法直接用于单任务（如单个圆打包问题）。本文扩展Pareto前沿类型，支持单任务、多任务与泛化三种模式。在多任务模式下，前沿共享跨任务模式，但输出时各任务独立选择最优候选。

$$
\mathcal{P} = \{ \Phi \in \mathcal{C} \mid \nexists \Phi' \in \mathcal{C}, s_j(\Phi') \ge s_j(\Phi) \forall j \in J, s_k(\Phi') > s_k(\Phi) \exists k \in J \}
$$

该公式定义Pareto非支配集 $\mathcal{P}$，保留在任一指标上表现最优的候选。通过按候选在多个目标上达到最佳的频率采样，系统聚焦于广泛有效的解。此机制使多任务搜索能发现跨问题共享的优化模式（如CUDA内核的向量化访问），避免了单任务模式下的重复探索，实现了跨域知识迁移。

## 实验评估

实验覆盖六个主域（智能体技能、云调度、ARC-AGI、AIME提示、CUDA内核、圆打包）及两个附录域，基线包括AlphaEvolve、OpenEvolve、ShinkaEvolve、GEPA、MIPROv2等专用工具。基线覆盖代码进化、提示优化与架构搜索三条路线，但缺失ProTeGi等纯提示优化基线（因任务类型不同）。

| 领域 | 模式 | 提议者 | 关键结果 |
| :--- | :--- | :--- | :--- |
| Agent Skills | G | Claude Opus 4.6 | 100% pass rate (+20.7pp) |
| Cloud Sched. | G | Gemini 3 Pro | 40.2% cost savings |
| ARC-AGI | G | Gemini 3 Flash | 89.5% test (+57pp) |
| AIME Prompts | G | GPT-5 | 60.0% test (+13.3pp) |
| CUDA Kernels | M | GPT-5 | 87% match baseline |
| Circle Pack. | S | GPT-5 | Beats AlphaEvolve |

核心数字显示，在ARC-AGI上，优化后的智能体架构将Gemini Flash准确率从32.5%提升至89.5%；在云调度上，成本降低40.2%。这些结果验证了统一接口在异构任务上的有效性，且多任务模式在CUDA内核上优于单任务独立优化。

消融实验聚焦SI与多任务机制。SI在提示优化、圆打包与CUDA内核三个域中均带来4-6倍收敛加速，且最终性能提升显著（如提示优化测试分数从82.5升至86.32）。多任务搜索的收益随相关任务数量增加而扩大，但在缺乏共享结构的任务（如不同N值的圆打包）中可能引入噪声，导致性能下降。

评估边界方面，指标以任务特定分数（如F1、成本节省率）为主，缺乏统一的样本效率度量（如单位调用提升）。可复现性上，代码已开源，但部分实验（如ARC-AGI）依赖特定LLM版本（Gemini 3 Flash），且优化成本从$1至$144.70不等，计算开销未标准化报告。

## 关联研究分析

从问题动机看，本文与GEPA同属反馈驱动优化，但GEPA局限于提示域，而本文通过SI契约将诊断信息结构化，解决了提示优化中“反馈稀疏”的问题。GEPA的Pareto选择依赖多数据点，本文扩展至单任务与多任务，使得优化逻辑可迁移至代码与架构域。这一差异源于任务特性：提示优化通常有充足训练集，而代码优化常面临单实例评估，要求搜索策略更灵活。

从方法设计看，本文与AlphaEvolve同属LLM进化范式，但AlphaEvolve依赖岛屿模型与特定标记，本文剥离这些框架特定抽象，采用声明式接口。AlphaEvolve在圆打包上表现优异，但本文通过多任务模式与SI机制，在相同任务上超越其公开结果。这一优势可能源于SI提供的细粒度诊断，使提议者能更精准地修复几何错误，而非依赖随机变异。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文核心矛盾在于现有LLM优化系统工件类型锁定，导致跨域知识迁移受阻。切入点是将工件抽象为文本字符串，评估标准化为分数+SI契约，从而构建统一接口。方法上，扩展Pareto搜索支持多模式，并引入SI作为一等公民。实验证明，该系统在ARC-AGI上将准确率从32.5%提升至89.5%，在云调度上降低40.2%成本。边界在于，多任务迁移仅在共享结构任务中有效，且计算成本随任务复杂度波动。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
