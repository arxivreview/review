> 长时程大语言模型智能体面临的核心矛盾是：随着交互积累，记忆维护的串行延迟与全量重写开销呈线性增长，导致系统无法实时响应新对话。现有系统如Mem0和EverMemOS将LLM推理嵌入写入关键路径，造成提取与维护阶段的严重瓶颈，而本文切入点在于将记忆管理重构为写入高效的时间数据管理问题。MemForest通过并行块提取与MemTree分层时间索引，将维护成本从全局状态规模解耦至局部树路径。该架构在LongMemEval-S上以79.8%的准确率实现了比最强基线高6倍的写入吞吐量，但其对LoCoMo多跳推理任务的覆盖不足暴露了局部更新策略在跨范围时序逻辑上的潜在局限。

## 研究背景

当智能体需要回答“用户搬到迈阿密之前住在哪里”这类历史状态查询时，简单的向量相似度检索往往失效，因为语义重叠度高的记录可能对应错误的时间点。这种“错误时间”检索源于独立记忆记录缺乏时序关联，而将记录合并为单一可变状态（如用户画像）虽能解决检索问题，却引入了全量重写的维护瓶颈。为平衡检索精度与写入效率，系统需要一种既能保留时间轨迹、又能支持局部更新的记忆组织形式，这构成了时间范围（Temporal Scope）抽象的核心需求。

现有主流记忆系统主要沿两条路线演进：一是基于扁平向量库的独立记录存储，如Mem0，其写入关键路径为$O(M)$，依赖顺序LLM更新；二是基于可变状态摘要的全局维护，如MemoryOS和EverMemOS，其关键路径为$O(M+N)$，每次写入需重写整个状态对象。这些方案在记忆规模$N$增大时，维护延迟不可接受地增长，且无法同时支持当前状态查询与历史状态推理。MemForest的切入点在于识别出串行LLM-in-the-loop提取与状态规模依赖的全局重写是两大结构性瓶颈，并借鉴数据库LSM-Tree思想，通过并行化与局部索引更新打破这一权衡。

## 核心方法

### 方法参照系

本文问题可置于“记忆架构设计”与“系统实现部署”的交叉路线中。通用流程包含提取、维护、检索三阶段，但传统方法将提取与维护耦合为串行依赖链。本文的关键差异在于将提取阶段并行化，并将维护阶段从全局状态重写转化为局部树节点更新，从而解耦了写入延迟与记忆总规模。

### 并行提取与规范事实整合

传统系统在提取阶段将新对话同步送入LLM进行摘要或整合，导致写入关键路径被LLM推理延迟主导。MemForest将新会话切分为短窗口块，并行执行提取操作，生成独立的规范事实（Canonical Facts）。这一设计消除了提取阶段的串行依赖，使得写入延迟不再随新证据数量$M$线性增长。规范事实作为稳定的写入单元，后续通过合并操作解决并行提取带来的语义碎片化问题，为后续树结构构建提供原子化输入。

### MemTree分层时间索引与脏路径刷新

MemTree将每个时间范围（如用户居住地）组织为时间有序树，而非扁平记录或单一摘要。树节点存储不同粒度的时间区间摘要，叶节点保留原始证据。当新事实插入时，系统仅更新受影响的“脏路径”（Dirty Path），即从插入点到根节点的路径上的节点摘要，而非重写整个树或全局状态。维护成本由$O(N)$降至$O(\log N)$，其中$N$为范围内证据总数。

$$
\text{Maintenance Cost} = O(\log N) \cdot C_{\text{LLM}}
$$

该公式表明，维护开销仅与树高（即$\log N$）和单次LLM调用成本相关，与记忆总规模$N$解耦。这一设计解决了可变状态摘要中“增长或压缩”的两难困境：保留所有证据会导致提示词膨胀，压缩则丢失中间状态。MemTree通过分层摘要既保留了历史轨迹，又将更新限制在局部路径，实现了写入效率与时间保真度的平衡。

## 实验评估

实验在LongMemEval-S和LoCoMo两个基准上进行，使用Qwen3-4B和Qwen3-30B作为骨干模型，对比Mem0、EverMemOS、MemoryOS、LightMem和MemPalace。基线覆盖了主流的记忆架构路线，但缺失MAGMA、GAM等2026年最新的多图谱结构化方法，可能低估了结构化组织在复杂推理任务上的上限。

| 方法 | LongMemEval-S pass@1 (30B) | LoCoMo Overall (30B) | 写入时间 (s, 30B) |
|---|---|---|---|
| MemForest | 79.8 | 68.4 | 178.0 |
| EverMemOS | 70.0 | 69.6 | 1048.8 |
| MemoryOS | 78.32 | 50.9 | 2439.9 |
| Mem0 | 73.65 | 18.6 | 353.2 |

MemForest在LongMemEval-S上以79.8%的准确率领先EverMemOS 9.8个百分点，同时写入时间仅为后者的1/6，验证了效率-质量前沿的改进。在LoCoMo上，MemForest（68.4%）略低于EverMemOS（69.6%），但远高于Mem0（18.6%），表明其在多会话对话中的鲁棒性。

| 变体 | LongMemEval-S pass@8 (30B) |
|---|---|
| llm+planner | 90.0 |
| llm | 88.3 |
| emb | 85.0 |
| flat-10 | 78.3 |
| root-only | 73.3 |

消融实验显示，planner-guided LLM浏览（90.0%）显著优于纯嵌入浏览（85.0%）和扁平检索（78.3%），证实了树结构内导航对证据访问的增益。值得注意的是，entity+scene树组合（86.7%）与完整entity+scene+session系统持平，表明结构化时间视图本身已具备足够的检索能力，session树主要作为高保真回退通道。

评估边界方面，论文未报告置信区间，且LoCoMo多跳推理任务（16.2%）上MemForest表现弱于EverMemOS，暗示局部更新策略可能在跨会话证据组合上存在信息损失。代码已开源，使用NVIDIA H100 GPU和vLLM部署，超参数包括分支因子$k=10$和top-$k=10$，可复现性良好。

## 关联研究分析

从方法设计看，MemForest与MAGMA的多图谱架构形成鲜明对比。MAGMA融合语义、时间、因果及实体四种关系图谱，旨在捕捉复杂交互动态，但计算开销大；MemForest仅采用单维时间树，牺牲了跨关系推理能力以换取写入效率。这种差异源于任务特性：LongMemEval-S侧重时间一致性与状态更新，而LoCoMo多跳任务需要跨会话关联，MemForest的局部更新策略可能在此类任务上受限。

从问题动机看，MemForest与Mem0共享原子事实提取思路，但Mem0将事实存储于向量库并依赖顺序LLM更新，而MemForest将事实组织为时间树并支持并行局部更新。Mem0的$O(M)$写入路径在高频交互场景下不可扩展，而MemForest的$O(\log N)$路径更适合长时程部署。然而，Mem0在LoCoMo上的极低准确率（18.6%）也暴露了纯向量检索在时序逻辑上的根本缺陷，MemForest通过树结构部分缓解了这一问题，但未完全解决多跳推理的瓶颈。

## 总结

MemForest要解决的核心矛盾是长时程智能体记忆中写入延迟与时间保真度的权衡。现有方法因串行LLM提取和全局状态重写，导致维护成本随记忆规模线性增长，无法实时响应新对话。MemForest通过并行块提取与MemTree分层时间索引，将维护成本解耦至局部树路径，实现了$O(\log N)$的写入复杂度。实验证明其在LongMemEval-S上以79.8%的准确率实现了6倍于EverMemOS的写入吞吐量，但在LoCoMo多跳推理任务上略逊于EverMemOS。这一局限暗示，局部更新策略在需要跨会话证据组合的任务上可能存在信息损失。当记忆范围跨越多个独立时间轨迹时，单维时间树是否足以支持复杂的状态转移推理，论文未给出回答。
