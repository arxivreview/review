> 导读 解耦式大语言模型（LLM）推理将键值缓存（KV Cache）从GPU内部状态转变为跨网络传输的显式负载，导致通信延迟成为端到端性能的主要瓶颈。现有KV压缩方法通常采用静态配置，无法适应生产环境中动态变化的工作负载类型、有效带宽及服务等级目标（SLO），导致固定策略在特定条件下甚至引发负优化。KVServe将KV压缩重构为服务状态依赖的约束策略选择问题，通过模块化策略空间、贝叶斯离线搜索与在线控制器实现自适应压缩。该框架在解耦推理中实现了显著的延迟降低，但其精度保持能力高度依赖离线搜索质量，且未覆盖多模态场景。

## 研究背景

解耦式LLM推理架构将预填充（Prefill）与解码（Decode）阶段分离至不同GPU节点，或将KV缓存卸载至远程存储池以支持跨请求复用。在这一架构下，KV缓存不再是驻留在GPU显存中的静态数据结构，而是必须跨越网络或I/O边界传输的大规模数据负载。由于自回归生成过程中KV缓存随序列长度线性增长，其体积往往超过模型参数本身，使得KV传输成本在端到端延迟中占据主导地位。

传统KV压缩研究聚焦于单节点显存受限场景，通过量化或驱逐策略减少内存占用。然而，在解耦架构中，压缩不仅影响存储大小，更直接决定网络传输时间与压缩/解压缩计算开销。现有方法如CacheGen和KIVI通常采用固定的量化粒度或变换预处理，属于静态运行时配置。这种静态配置在带宽充足或工作负载单一时可能有效，但在生产环境中，由于工作负载类型、有效带宽和SLO预算的动态变化，固定策略往往无法保持最优，甚至因压缩开销超过通信收益而导致延迟增加。KVServe的切入点在于将KV压缩视为一个受约束的、服务状态依赖的在线决策问题，而非固定的算法选择。

## 核心方法

### 模块化策略空间抽象

KVServe将KV压缩抽象为统一的模块化流水线，将代表性方法分解为可插拔组件。这一设计解决了现有压缩方法代码与参数接口不兼容、难以复用和组合的问题。通过引入新的量化组件并实现跨方法组合，KVServe构建了一个可枚举且可扩展的策略空间。每个策略（Profile）由压缩比 $cr_p$ 和有效吞吐量 $s_p$ 参数化，其中 $cr_p \triangleq V/V_p$，$V$ 为未压缩KV总量，$V_p$ 为压缩后大小。这种抽象使得不同压缩技术（如量化、剪枝、变换）可以在同一框架下被统一评估和组合，为后续的高效搜索奠定了基础。

### 贝叶斯离线搜索引擎

面对策略空间的组合爆炸，KVServe设计了贝叶斯剖析引擎（Bayesian Profiling Engine）。该引擎利用高斯过程代理模型迭代建模配置到精度的映射，并基于效用分数选择下一个候选配置进行评估。这一设计解决了穷举剖析在巨大策略空间中不切实际的问题，将离线搜索开销从1000小时量级降低至20小时量级。引擎通过异构参数编码、探索-利用策略、双向剪枝和早停机制，在有限预算内高效识别帕累托前沿上的最优配置。搜索过程在离线阶段完成，生成包含不同精度损失桶的候选策略集，为在线选择提供基础。

### 服务感知在线控制器

在线控制器结合解析延迟模型与轻量级多臂老虎机（Bandit），在运行时感知服务上下文并选择最优策略。服务上下文抽象为 $c = (w, B, T_{SLO}, q_{min})$，其中 $w$ 为工作负载类别，$B$ 为有效带宽，$T_{SLO}$ 为延迟预算，$q_{min}$ 为最小质量要求。控制器首先利用带宽阈值定理过滤非有益策略，即当带宽 $B$ 超过阈值 $B^*_p$ 时，压缩不再带来端到端加速。随后，基于分段最优策略定理，控制器在 $x = 1/B$ 空间中进行查表操作，以 $O(1)$ 复杂度返回最优策略。该设计解决了静态策略无法适应动态带宽变化及离线剖析与在线执行间漂移的问题，通过老虎机机制修正模型失配，确保在SLO约束下的鲁棒性。

## 实验评估

实验在vLLM 0.10.1上实现，使用Qwen2.5-7B-Instruct、Llama-3.1-8B-Instruct和Qwen2.5-32B-Instruct模型，覆盖GSM8K、HumanEval、Multi-News、Qasper等数据集。基线包括CacheGen、KIVI和DuoAttention，但缺失H2O、SnapKV等纯驱逐类SOTA方法，限制了与算法级压缩方法的全面对比。

| 方法 | GSM8K Acc/CR | HumanEval Acc/CR | Multi-News Acc/CR | Qasper Acc/CR |
| :--- | :--- | :--- | :--- | :--- |
| Default (BF16) | 84.91 / 1.00 | 66.46 / 1.00 | 26.87 / 1.00 | 45.66 / 1.00 |
| CacheGen | 83.47 / 5.85 | 62.80 / 3.98 | 26.08 / 6.20 | 44.46 / 6.65 |
| KIVI | 81.35 / 4.32 | 60.37 / 2.61 | 26.44 / 4.45 | 44.97 / 4.89 |
| DuoAttn | 83.93 / 2.16 | 65.24 / 1.06 | 23.41 / 2.89 | 43.90 / 3.77 |
| MixHQ (KVServe) | 76.99 / 6.19 | 59.76 / 5.36 | 26.47 / 6.05 | 44.83 / 6.60 |

KVServe（MixHQ）在压缩比上显著优于基线，但在部分数据集上精度低于Default，例如GSM8K上76.99%对比84.91%。这表明在97%相对精度约束下，高压缩比策略可能牺牲部分精度。消融实验显示，移除异构参数编码（Enc）和探索-利用策略（Exp）导致收敛至局部最优，压缩比降至8.96×和8.53×，而完整策略在194次迭代内收敛至全局最优9.31×。移除剪枝（Prune）和早停（Stop）虽能找到最优解，但耗尽300次迭代预算。

评估边界方面，论文未报告置信区间，且精度指标为相对值，难以与绝对精度基准直接对比。代码已开源，但超参数配置未详细披露，复现性依赖vLLM版本和网络环境模拟。

## 关联研究分析

从问题动机看，KVServe与CacheGen、KIVI等量化方法的核心差异在于约束条件的不同。CacheGen和KIVI关注单节点显存占用，假设带宽充足或忽略通信开销，因此采用固定配置以最大化压缩比或最小化精度损失。KVServe则明确将有效带宽和SLO作为一等公民，指出在低带宽下压缩有益，但在高带宽下可能因压缩/解压缩开销导致延迟增加。这一差异源于解耦架构中KV传输成为关键路径，使得压缩策略必须动态适应网络状态，而非仅优化静态指标。

从方法设计看，KVServe与PagedAttention等系统级方法共享“资源调度”思想，但作用对象不同。PagedAttention解决GPU显存碎片化，通过分页管理提升内存利用率；KVServe解决跨节点KV传输瓶颈，通过策略选择优化通信延迟。两者均属于系统级优化，但KVServe引入了算法级的压缩策略选择，形成了“系统调度+算法压缩”的协同机制。这种协同在现有研究中较少见，多数工作要么聚焦算法压缩（如KIVI），要么聚焦系统调度（如PagedAttention），缺乏两者的深度整合。

## 总结

KVServe针对解耦式LLM推理中KV缓存传输导致的通信瓶颈，抓住了现有静态压缩策略无法适应动态服务状态的痛点。通过将KV压缩重构为服务状态依赖的约束策略选择问题，KVServe利用模块化策略空间、贝叶斯离线搜索和服务感知在线控制器，实现了在动态带宽和工作负载下的自适应压缩。实验表明，KVServe在PD分离服务中实现了最高9.13×的JCT降低，在KV解耦服务中实现了最高32.8×的TTFT降低。然而，其精度保持能力在部分数据集上低于基线，且未覆盖多模态场景。当工作负载类型发生剧烈变化时，离线搜索生成的策略集是否仍能覆盖所有潜在的最优配置，论文未给出回答。
