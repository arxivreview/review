# HuggingFace最新推荐论文 ｜Agentic CLEAR: Automating Multi-Level Evaluation of LLM Agents ｜智能体行为的多层级自动诊断

作者：Asaf Yehudai、Lilach Eden、Michal Shmueli-Scheuer

论文原文见 [arXiv](https://arxiv.org/abs/2605.22608)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.22608)

> 智能体系统在执行多步任务时频繁出现循环、子代理失配及错误传播，这些细微故障难以从最终输出中察觉，导致开发者依赖人工审查海量轨迹。现有可观测性平台仅做基础指标聚合，而静态错误分类法无法适应动态变化的业务场景，二者均缺乏对“为何失败”的因果解释。Agentic CLEAR 通过 LLM 裁判生成步骤级、轨迹级及任务级评分，并利用 CLEAR 算法聚类实例反馈，在无预设分类法的情况下自动提取系统、节点及轨迹三层级的文本洞察。该方法降低了诊断门槛，但其诊断结果对裁判模型选择高度敏感，且未验证其对实际修复效率的提升。

## 研究背景

当智能体在复杂环境中执行任务时，其决策过程由一系列 LLM 调用构成，每次调用包含输入、输出及执行节点。这一序列称为执行轨迹（Execution Trace）。轨迹中的每一步都可能引入错误，且错误会在后续步骤中累积或传播，使得仅关注最终任务成功率的评估方式失效。为定位故障根源，需要一种能解析轨迹内部结构、区分不同组件（节点）行为差异的评估机制，这要求评估工具不仅能打分，还能生成可解释的文本诊断。

智能体评估领域正从静态基准测试向过程审计转变，但现有方案存在结构性瓶颈。一方面，LangSmith 等可观测性平台虽能记录轨迹，但其评估能力局限于粗粒度的单提示 LLM 裁判，无法捕捉系统性模式；另一方面，TRAIL 等人工构建的错误分类法虽然精确，但依赖大量手工工程，且类别固定，难以适应开发者日常面临的定制化任务。这种“基础设施标准化”与“诊断灵活性”之间的脱节，导致开发者在迭代智能体时缺乏自动化的、细粒度的反馈机制。Agentic CLEAR 的切入点在于将评估从“静态分类匹配”转向“动态模式发现”，通过自动化生成任务特定标准并聚合实例反馈，实现无需人工标注的层级化诊断。

## 核心方法

### 方法参照系

智能体过程评估的通用流程通常包含轨迹记录、指标计算及结果聚合。传统方法依赖预定义的指标（如准确率、步数）或固定分类法（如 TRAIL 的 20 类错误）对轨迹进行标注。本文的关键差异在于摒弃了预定义分类法，转而采用 LLM 裁判生成自然语言批评（Critique），并通过聚类算法从实例级反馈中涌现出全局模式，实现了从“匹配已知错误”到“发现未知模式”的范式转换。

### 多层级 LLM 裁判评估

在轨迹评估环节，常规做法是对完整轨迹应用单一提示进行整体评分。本文将该环节解耦为三种互补的评估模式，以捕捉不同粒度的故障。对于轨迹 $t_n = \{(i_k, o_k, a_k)\}_{k=1}^{K_n}$，其中 $i_k, o_k$ 为第 $k$ 步的输入输出，$a_k$ 为执行节点，LLM 裁判 $J$ 执行以下操作：

$$
\begin{aligned}
c_{node}^{nk} &= J_s(i_k, o_k) \\
c_{trace}^n &= J_t(t_n) \\
r_n &= J_r(x_n), \quad c_{rubric}^n = J_v(t_n, r_n)
\end{aligned}
$$

其中 $J_s$ 生成步骤级质量分数与批评，$J_t$ 评估完整轨迹的执行质量，$J_r$ 基于任务描述 $x_n$ 动态生成任务特定标准（Rubric），$J_v$ 则验证轨迹是否满足这些标准。这一设计解决了静态分类法无法适应新领域任务的问题，通过动态生成 $r_n$，评估标准随任务上下文自适应调整，避免了人工构建分类法的滞后性。

### CLEAR 聚类聚合

实例级反馈 $c_{node}^{nk}$ 和 $c_{trace}^n$ 是离散的，直接呈现给开发者会导致信息过载。本文引入 CLEAR 算法对反馈进行聚类，提取重复出现的故障模式。对于每个节点 $a$，将其关联的所有步骤批评 $\Phi_{node}[a]$ 输入 CLEAR，生成节点级洞察 $I_{node}[a]$；同时，将所有轨迹级与标准级批评 $\Phi_{sys}$ 聚合，生成系统级洞察 $I_{sys}$：

$$
I_{node}[a] = \text{CLEAR}(\Phi_{node}[a]), \quad I_{sys} = \text{CLEAR}(\Phi_{sys})
$$

该聚合过程将分散的文本批评转化为结构化的故障类别，并保留每个洞察与具体触发步骤或轨迹的链接。这一机制解决了单点 LLM 裁判随机性大、无法揭示系统性弱点的问题，使开发者能从“单条轨迹错误”上升到“组件级或系统级缺陷”的诊断视角。

## 实验评估

实验在 SWE-Bench Verified Mini、GAIA、AppWorld 和 $\tau$-Bench 四个基准上进行，涵盖 CUGA、HAL 及 HF DeepResearch 等智能体架构，使用 GPT-5 和 OSS-120B 作为裁判模型。基线审计显示，本文对比了 TRAIL 人工分类法及频率基线，但缺乏与 AgentCompass 等基础设施类方法的直接性能对比，主要验证诊断质量而非任务成功率。

| 方法 | Micro F1 | Macro Cat F1 |
| :--- | :--- | :--- |
| Random (GT freq) | 0.342 | 0.288 |
| Always top-4 | 0.459 | 0.199 |
| OSS-120B (full+partial) | 0.427 | 0.374 |
| GPT-5 (full+partial) | 0.497 | 0.459 |

GPT-5 裁判在 TRAIL 分类映射上取得最高 Macro-F1 0.459，显著优于频率基线（0.199），表明自动生成的洞察能覆盖长尾错误类别。在预测轨迹成功率的 AUC 测试中，AppWorld 表现最佳，GPT-5 裁判的 Trace 级评估达到 0.890，而 $\tau$-Bench 所有方法均低于 0.62，显示评估有效性高度依赖基准特性。

| 基准 | Agent | Model | Step-Wise (GPT-5) | Trace (GPT-5) | Rubric (GPT-5) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| AppWorld | CUGA | GPT-4o | 0.823 | 0.890 | 0.828 |
| GAIA | Generalist Agent | Claude 4.5 Sonnet | 0.632 | 0.720 | 0.566 |
| SWE-bench | Generalist Agent | Claude 4.5 Sonnet | 0.779 | 0.803 | 0.524 |
| TAU-bench | Generalist Agent | Claude 3.7 Sonnet | 0.529 | 0.554 | 0.597 |

消融分析显示，Trace 级评估在多数场景下优于 Step-wise 和 Rubric 方法，但在模块化架构（如 CUGA）中，Step-wise 评估因组件独立性而更具优势。Rubric 方法在 $\tau$-Bench 上表现不佳，原因在于该基准包含对抗性任务，正确行为是拒绝请求，而仅基于任务描述生成的 Rubric 往往错误地奖励任务完成，揭示了动态标准生成对任务元数据依赖的盲区。

评估边界方面，本文未报告计算成本及延迟，且诊断结果的可操作性缺乏量化指标。可复现性上，代码已开源为 PyPI 包，但裁判模型（GPT-5/OSS-120B）的闭源特性限制了完全复现。

## 关联研究分析

从问题动机看，Agentic CLEAR 与 CORE 等全路径评估框架同属过程评估路线，但 CORE 侧重基于确定性有限自动机的路径合规性检查，输出结构化状态转移，而 Agentic CLEAR 侧重语义层面的错误诊断，输出自然语言洞察。这一差异源于任务特性：CORE 适用于规则明确的环境（如 Web 导航），而 Agentic CLEAR 针对开放式任务，其中错误模式难以用固定状态机穷举。然而，Agentic CLEAR 未利用环境状态反馈，仅依赖 LLM 裁判对文本轨迹的解读，这在状态敏感型任务中可能遗漏物理层面的执行错误。

从方法设计看，与 AgentCompass 等基础设施工作相比，Agentic CLEAR 位于执行层之上，不解决基准可比性问题，而是解决单系统内部的可解释性问题。AgentCompass 通过标准化接口实现跨框架对比，而 Agentic CLEAR 通过统一中间表示解耦底层框架，使诊断逻辑独立于具体执行环境。这种定位差异导致二者互补：AgentCompass 提供“横向对比”的基础，Agentic CLEAR 提供“纵向深挖”的工具。但 Agentic CLEAR 的动态 Rubric 生成是否引入了对任务描述的过度依赖，导致在元数据丰富的基准（如 AppWorld）上表现优于元数据稀疏的基准，这一条件依赖性在论文中未得到充分量化。

## 总结

Agentic CLEAR 旨在解决智能体故障诊断中“静态分类法僵化”与“人工审查低效”的矛盾，通过动态生成任务标准与聚类聚合实例反馈，实现了无预设分类法的自动诊断。实验证明其生成的洞察与人工标注错误具有较高一致性（Macro-F1 0.459），且在 AppWorld 上具备较强的轨迹成功预测能力（AUC 0.890）。然而，其诊断有效性高度依赖裁判模型能力，且在对抗性任务中动态 Rubric 生成存在逻辑偏差。当任务描述缺乏关键约束信息时，自动生成的评估标准是否仍能准确捕捉故障根源，论文未给出回答。
