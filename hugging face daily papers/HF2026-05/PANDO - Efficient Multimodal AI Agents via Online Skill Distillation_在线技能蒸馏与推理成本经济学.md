# HuggingFace最新推荐论文 ｜PANDO: Efficient Multimodal AI Agents via Online Skill Distillation ｜在线技能蒸馏与推理成本经济学

研究机构：美国卡内基梅隆大学

论文原文见 [arXiv](https://arxiv.org/abs/2605.24785)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.24785)

> 多模态网页智能体在长程任务中面临推理成本随步骤线性增长的困境，传统“增加Token换准确率”的策略导致延迟与能耗不可控。现有方法通过离线工具发现或多次验证器调用提升成功率，但将计算成本前置或分散，未解决单次任务内的边际负载问题。PANDO 提出在评估流中在线蒸馏结构化技能库，以规则与例程替代重复动作链，实现成功率与Token消耗的双重帕累托改进。该方法在 VisualWebArena (VWA) 上以更低成本超越现有基线，但其在线学习假设任务流平稳，且未验证对抗性排序下的鲁棒性。

## 研究背景

多模态网页智能体（Web Agent）在处理复杂交互时，每一步均需处理截图、维护历史轨迹并调用规划器，导致推理负载呈轨迹级累积。这种“Token经济学”困境表现为：智能体步数常达人类的 1.4–2.7 倍，且规划与反思环节占据 75–94% 的延迟。为提升性能，主流方案倾向于增加推理预算，如采用 Best-of-N 采样或引入验证器，但这进一步推高了单次任务的边际成本。

当前领域存在两条主要技术路线：一是离线工具发现（如 WALT），在基准测试前消耗大量预算生成工具，但隐藏了预评估成本；二是验证器扩展（如 SGV），通过多轮验证提升准确率，但计算开销随任务线性增长。这两类方法均未解决“智能体能否在积累经验的同时降低推理成本”的核心问题。PANDO 的切入点在于将技能诱导内化至评估流中，通过在线蒸馏将成功轨迹转化为可复用的结构化技能，使智能体在任务流推进中变得“更便宜”，而非更昂贵。

## 核心方法

### 方法参照系

PANDO 基于 Plan-Act-Reflect-Learn 循环构建，其核心差异在于引入结构化技能库（Skill Library）作为共享根系统。与线性 ReAct 或树搜索不同，PANDO 将重复动作链抽象为参数化例程（Routines）和模式规则（Rules），通过确定性检索替代每次任务的独立推理，从而在单轮次（Single-rollout）设定下实现效率优化。

### 结构化技能库与在线蒸馏

设计动机在于解决重复动作循环（Repeat-action loops）导致的无效Token消耗。PANDO 将技能库分为规则 $R_t$ 和例程 $F_t$，每个技能 $s$ 携带置信度 $c_s$。在线蒸馏模块在任务结束后提取成功子轨迹，生成候选技能。例程表示为参数化程序 $f: \Theta_f \to (a_1, \dots, a_k)$，通过极性对合并（Polarity-pair merging）将方向相反的操作（如升序/降序）折叠为单一技能 $f_\pm(x, d)$，其中 $d \in \{asc, desc\}$。这一机制减少了提示词波动，提高了缓存利用率。

$$
S_{t+1} = \left( S_t \cup \text{Admit}(\text{Induce}(\xi_t); B_{\text{demote}}) \right) \setminus \text{Demote}(S_t)
$$

该公式描述了技能库的动态更新：新技能需通过去重检查（$B_{\text{demote}}$）方可入库，而低置信度技能则被降级剔除，防止陈旧技能成为隐性负债。

### 层级路由与缓存感知提示

设计动机在于降低高频接地操作的边际成本。PANDO 采用层级路由，将高成本模型（如 Claude Opus 4.6）仅用于规划与反思，低成本模型（如 GPT-5.2）处理执行。执行成本分解为：

$$
C_{\text{exec}}(\tau) = \kappa_H \lfloor |\text{Plan}(\xi_\tau)|/q_{\text{plan}} \rfloor + \lfloor T/k_R \rfloor q_{\text{reflect}} + \kappa_L T q_{\text{act}}
$$

其中 $\kappa_H > \kappa_L$，$k_R=3$ 为反思触发间隔。结合视觉压缩（将截图长边缩放至 896px）和缓存感知提示布局（静态前缀置于动态观察之前），PANDO 将提示缓存利用率提升至 72.4%，显著降低了重复计算的Token开销。

## 实验评估

PANDO 在 VWA-910 全量任务上进行评估，基线包括 SGV、WALT 及多种 SoM 变体。实验覆盖多模态接地与单轮次推理路线，但缺乏强化学习（RL）基线（如 WebRL），可能高估免训练方法的相对优势。

| 方法 | SR (%) | Tokens (K) | ARR (%) | Cache (%) |
| :--- | :--- | :--- | :--- | :--- |
| SGV (Gemini Flash) | 54.0 | 275 | 14.2 | 45.1 |
| WALT (Sonnet-4) | 45.2 | 294 | 18.3 | 38.6 |
| **PANDO (Opus 4.6 + GPT-5.2)** | **58.3** | **115** | **9.1** | **72.4** |

PANDO 以 58.3% 的成功率超越 SGV 4.3 个百分点，同时 Token 消耗仅为 SGV 的 42%。消融实验显示，技能库组件贡献了大部分成功率提升（+18.7 pp），而路由与压缩主要降低 Token 负载。

| 配置 | SR (%) | ΔSR (pp) | Tokens (K) |
| :--- | :--- | :--- | :--- |
| Backbone: SoM-Qwen (M) | 38.6 | – | 223 |
| + Rules | 44.2 | +5.6 | 215 |
| + Seed routines | 48.1 | +3.9 | 198 |
| + Online distillation | 53.9 | +2.9 | 174 |
| + Cache-aware prompting | 59.0 | +0.5 | 117 |

规则与例程的引入显著降低了动作重复率（ARR 从 39.1% 降至 9.1%），验证了结构化技能对长程任务稳定性的贡献。

评估边界方面，PANDO 未报告置信区间，且结果依赖于固定任务顺序。代码与超参数已公开，但在线学习假设任务流平稳，未测试对抗性排序下的性能衰减。

## 关联研究分析

从问题动机看，PANDO 与 ASI 同属在线技能诱导路线，但 ASI 缺乏降级机制，导致技能库单调增长，可能引入陈旧技能干扰。PANDO 引入置信度降级与极性合并，解决了技能库“只增不减”的隐患，但这一机制是否适用于非平稳任务分布，论文未给出回答。

从方法设计看，PANDO 与 WALT 形成鲜明对比：WALT 将计算成本前置至离线发现阶段，而 PANDO 将其内化至评估流中。这种差异源于任务特性：WALT 假设工具可预定义，而 PANDO 假设技能需从轨迹中动态提取。然而，PANDO 的确定性检索（关键词匹配）可能限制其在复杂语义场景下的泛化能力，相比之下，基于嵌入的检索虽增加计算开销，但可能提升技能匹配精度。

## 总结

PANDO 解决了多模态网页智能体中推理成本与成功率权衡的核心矛盾，通过在线技能蒸馏将计算成本内化至任务流，实现了免训练下的效率优化。其在 VWA 上以 58.3% 成功率和 115K Token 消耗证明了结构化技能库的有效性，但实验局限于固定任务顺序与单一基准。当任务流呈现对抗性排序或分布漂移时，在线蒸馏的稳定性与技能库的泛化边界，仍是亟待验证的关键问题。
