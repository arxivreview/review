# HuggingFace最新推荐论文 ｜VibeSearchBench: Benchmarking Long-horizon Proactive Search in the Wild ｜无模式图谱驱动的长程主动搜索基准

作者：Xiaohongshu Inc

论文原文见 [arXiv](https://arxiv.org/abs/2605.27882)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.27882)

> 现有搜索基准依赖过指定查询、单轮交互与固定模式输出，无法反映真实用户模糊意图的动态收敛过程，导致模型在基准上的高分与用户体验脱节。本文提出 VibeSearch 范式，通过构建包含用户画像与无模式知识图谱的基准，强制智能体在多轮交互中主动挖掘意图。其核心贡献在于揭示了当前前沿模型在长程主动搜索中的严重不足，但评估协议对模型能力的剥离程度仍存疑。

## 研究背景

当智能体面对“帮我找点关于超级英雄电影的资料”这类模糊请求时，传统检索增强生成（RAG）管道因缺乏多步推理能力而失效，ReAct 框架虽引入了工具调用，但其评估基准仍假设查询是完整且静态的。这种静态假设忽略了真实搜索中用户意图的渐进性：用户往往在看到部分结果后才能明确具体需求，这构成了“评估-体验差距”的核心来源。

主流搜索基准如 WideSearch 和 BrowseComp 分别聚焦广度聚合与深度检索，但均将任务约束打包在单一提示中，且输出评估依赖固定 Schema（如表格或实体列表）。这种设计跳过了智能体主动挖掘用户真实意图这一最关键的交互环节，导致模型在基准上的表现无法映射到实际部署场景。本文切入点在于重新定义搜索任务为“双向收敛”过程，通过引入渐进式披露的用户模拟器和无模式知识图谱评估，填补了长程主动搜索评估的空白。

## 核心方法

### 任务形式化与参照系

本文问题属于智能体搜索评测范畴，但区别于传统的单轮问答或固定 Schema 表格生成。其关键差异在于将搜索过程建模为多轮交互中的序贯决策，其中用户意图是隐性的且随交互动态演化，而非预先给定的静态约束。

### 渐进式披露用户模拟器

传统基准中用户是静态输入，本文创新在于引入基于触发条件的用户模拟器。该机制将用户画像 $P$ 分解为 $K$ 个信息披露阶段，每个阶段 $k$ 包含触发条件 $c_k$ 和新需求 $u_k$。智能体响应 $a_t$ 需满足 $c_k$ 才能解锁 $u_k$，否则模拟器持续施压。这一设计解决了静态基准中智能体无法主动探索意图的问题，强制模型在交互中通过提问和提供部分结果来收敛需求。

$$
\text{Stage}_k \text{ unlocks} \iff \text{LLM\_Judge}(a_t, c_k) = \text{True}
$$

该公式表明，阶段推进完全依赖于智能体响应是否满足预设的语义触发条件，而非简单的关键词匹配。

### 无模式图谱匹配评估

固定 Schema 评估无法覆盖真实世界复杂的知识关系，本文采用无模式有向图 $G^* = (V^*, E^*)$ 作为真值。评估通过 LLM-as-Judge 进行信息蕴含匹配，计算预测图 $\hat{G}$ 与真值图 $G^*$ 的三元组级 Precision、Recall 和 F1。Recall 考虑直接匹配、子集覆盖及组合推导，Precision 计算参与覆盖至少一个真值三元组的预测三元组比例。这一方法解决了固定 Schema 评估的刚性缺陷，使评估能适配任意复杂度的知识结构。

$$
\text{Recall} = \frac{|\{e \in E^* \mid \exists \hat{e} \in \hat{E}, \hat{e} \models e\}|}{|E^*|}
$$

该公式定义了基于语义蕴含的召回率，允许实体别名和关系同义词的等价匹配，提升了评估的客观性与细粒度。

## 实验评估

实验在 VibeSearchBench（200 个双语任务）上评估 7 个前沿模型，对比 ReAct 与 OpenClaw 框架。基线覆盖主流闭源与开源模型，但未对比 Search-R1 等强化学习训练后的专用搜索智能体，这可能低估了训练优化对主动搜索能力的提升。

| 模型 | 框架 | F1 (Pro) | F1 (Daily) | F1 (Avg) |
| :--- | :--- | :--- | :--- | :--- |
| Claude Opus 4.6 | OpenClaw | 32.55 | 28.04 | 30.30 |
| DeepSeek-V4-Pro | ReAct | 33.47 | 25.37 | 27.04 |
| Gemini-3.1 Pro | ReAct | 29.79 | 24.66 | 23.54 |
| GPT-5.4 | OpenClaw | 22.78 | 25.64 | 24.32 |

最佳模型 Claude Opus 4.6 在 OpenClaw 下仅取得 30.30 的平均 F1，所有模型均低于 33，表明当前模型在长程主动搜索中普遍不足。

消融实验显示，OpenClaw 的子智能体、本地记忆和终身记忆机制均未带来显著 F1 提升。子智能体虽降低上下文压力，但跨智能体信息整合导致性能损失；记忆机制增加上下文开销，抵消了持久化收益。这一反直觉结果暗示，VibeSearch 的瓶颈在于模型级的长上下文推理与意图挖掘能力，而非 Harness 架构增强。

评估协议依赖 LLM-as-Judge，虽与人类专家一致性达 98.5% 以上，但可能引入语义判断偏差。代码与超参数已公开，但用户模拟器基于 Seed-2.0-Pro，其行为模式可能限制评估的泛化性。

## 关联研究分析

从问题动机看，WideSearch 聚焦广度聚合，假设查询完整且输出为固定表格，而 VibeSearchBench 强调意图的动态收敛与无模式输出。这一差异源于任务特性：WideSearch 适合结构化数据收集，VibeSearch 适合模糊探索。InteractComp 虽引入多轮交互，但其用户模拟器规则简单且输出仍为实体匹配，未能捕捉复杂知识关系，VibeSearchBench 通过 Persona 渐进披露和无模式图谱弥补了这一盲区。

从方法设计看，本文未采用强化学习优化智能体策略，而是直接评估前沿模型的零样本能力。这与 Search-R1 等通过 RLVR 优化搜索策略的路线不同。Search-R1 在 HotpotQA 上取得 50.09 F1，但其在多轮交互与模糊意图场景下的表现未知。VibeSearchBench 的低分可能部分源于评估协议的严苛性，而非模型能力的绝对缺陷，这种评估与训练解耦的设计是否公平，论文未给出回答。

## 总结

本文核心矛盾在于现有基准的静态假设与真实搜索的动态性之间的脱节。通过引入渐进式披露用户模拟器和无模式图谱评估，VibeSearchBench 揭示了前沿模型在长程主动搜索中的严重不足，最佳 F1 仅为 30.30。其边界在于消融实验显示架构增强无效，暗示瓶颈在模型级能力，但评估协议对模型能力的剥离程度及 LLM-as-Judge 的语义偏差仍存疑。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
