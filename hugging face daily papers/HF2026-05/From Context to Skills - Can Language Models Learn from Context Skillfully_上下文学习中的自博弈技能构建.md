# HuggingFace最新推荐论文 ｜From Context to Skills: Can Language Models Learn from Context Skillfully? ｜上下文学习中的自博弈技能构建

研究机构：美国伊利诺伊大学厄巴纳-香槟分校、香港中文大学

作者：Shuzheng Si、Haozhe Zhao、Yu Lei 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.27660)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.27660)

> 上下文学习要求大语言模型从未见过的复杂文档中提取规则并推理，但人工标注技能成本过高且缺乏外部反馈验证技能质量。现有自动化技能构建方法依赖执行反馈或真值对比，在纯文本上下文场景中失效。Ctx2Skill 通过 Challenger-Reasoner 自博弈循环自动发现并精炼技能，利用 Cross-Time Replay 机制防止技能过拟合。该方法在 CL-bench 上显著提升了多个骨干模型的表现，但其技能泛化能力受限于自博弈生成的任务分布，且未验证在可验证领域（如数学）中的扩展性。

## 研究背景

当模型面对长篇技术文档或实验数据时，其参数化知识无法覆盖这些新信息，必须直接从上下文中学习规则与程序。这一能力称为上下文学习，其核心难点在于上下文知识往往隐含在复杂结构中，需要深度理解而非表面检索。然而，将上下文转化为可复用的自然语言技能面临两大障碍：人工标注需完全内化复杂文档，经济上不可行；自动化构建缺乏外部反馈信号，无法判断技能是否忠实且完整地捕获了上下文知识。

现有技能构建路线分为两类：一类依赖人工标注，如 SkillNet 和 SkillsBench 中的技能库，虽质量高但无法扩展至长文档场景；另一类依赖外部反馈，如 CoEvoSkills 通过生成器-验证器协同进化，SkillOpt 通过验证门控优化技能，但这些方法均假设存在执行反馈或真值对比，而上下文学习任务中不存在此类信号。Ctx2Skill 的切入点在于利用自博弈机制替代外部反馈：Challenger 生成探测任务，Reasoner 尝试解决，Judge 提供二元反馈，双方通过技能文本而非模型参数协同进化，从而在无外部监督下自动构建技能。

## 核心方法

### 方法参照系

本文问题属于“技能生成与蒸馏”路线，但关键差异在于：标准流程依赖轨迹数据或人工标注，而本文仅从静态上下文出发，通过自博弈生成任务与反馈。这要求设计一种无需外部真值的技能质量评估机制，以及防止技能在迭代中过拟合的约束。

### 自博弈技能协同进化

自博弈循环的核心是 Challenger 与 Reasoner 的技能集 $S_C$ 和 $S_R$ 通过失败驱动的文本编辑协同进化。在迭代 $i$ 中，Challenger 基于 $S_C^{i-1}$ 生成 $M$ 个任务及评分标准（rubrics），Reasoner 基于 $S_R^{i-1}$ 尝试解决，Judge 返回二元判定 $y_m = \prod_k [r_{m,k}(a_m) = \text{pass}]$。失败任务 $F_i = \{m: y_m = 0\}$ 路由至 Reasoner 侧，由 Proposer 诊断缺失知识，Generator 更新 $S_R$；成功任务 $P_i = \{m: y_m = 1\}$ 路由至 Challenger 侧，强化其探测策略。该设计解决了无外部反馈时技能质量无法评估的问题：Challenger 的持续对抗压力迫使 Reasoner 技能覆盖更全面的上下文知识，而失败案例提供了具体的诊断信号。

### Cross-Time Replay 机制

自博弈循环存在“对抗崩溃”风险：Challenger 生成极端任务，Reasoner 技能过特化于这些病态案例，导致泛化能力下降。Cross-Time Replay 通过从历史迭代中选择最优技能集解决此问题。在每次迭代中，将最难的失败任务加入硬探针集 $Q_h$，最简单的成功任务加入易探针集 $Q_e$。自博弈结束后，Reasoner 在每个候选技能集 $S_R^i$ 下重新回答所有探针任务，计算拉普拉斯平滑后的求解率 $\rho_h(i)$ 和 $\rho_e(i)$，选择最大化乘积 $\rho_h(i) \cdot \rho_e(i)$ 的迭代 $i^*$。该机制确保最终技能集在困难任务与简单任务间取得平衡，避免后期迭代中技能冗余积累导致的泛化退化。

## 实验评估

| 模型 | Overall (%) | Domain Knowledge Reasoning (%) | Rule System Application (%) | Procedural Task Execution (%) | Empirical Discovery & Simulation (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-4.1 (Base) | 11.1 | 10.6 | 14.8 | 10.4 | 4.6 |
| GPT-4.1 (Ctx2Skill) | **16.5** | **16.8** | **17.6** | **17.6** | **9.7** |
| GPT-5.1 (Base) | 21.1 | 22.4 | 21.0 | 22.8 | 13.6 |
| GPT-5.1 (Ctx2Skill) | **25.8** | **27.9** | **24.9** | **26.9** | **19.1** |
| GPT-5.2 (Base) | 18.2 | 19.5 | 18.0 | 19.1 | 12.1 |
| GPT-5.2 (Ctx2Skill) | **21.4** | **22.2** | **20.4** | **25.4** | **12.6** |

实验在 CL-bench 上进行，包含 500 个上下文、1899 个任务和 31607 个评分标准，覆盖四个类别。基线包括 Prompting（单次技能提取）和 AutoSkill4Doc（文档分割技能提取），均使用相同骨干模型。Ctx2Skill 在所有骨干模型和类别上均显著优于基线，例如 GPT-4.1 从 11.1% 提升至 16.5%（+5.4%），GPT-5.1 从 21.1% 提升至 25.8%（+4.7%）。值得注意的是，GPT-4.1 使用 Ctx2Skill 技能后的 16.5% 超过了无技能的 Gemini 3 Pro（15.8%），表明上下文特定技能可弥补模型能力差距。

| 消融项 | GPT-4.1 Overall (%) | GPT-5.1 Overall (%) |
| :--- | :--- | :--- |
| Ctx2Skill (Full) | **16.5** | **25.8** |
| w/o Cross-Time Replay | 14.7 | 23.0 |
| w/o Challenger Skills Evolving | 13.8 | 22.5 |
| w/o Decoupling Proposer and Generator | 15.9 | 25.1 |
| w/o Hard Probe Set | 15.2 | 24.7 |
| w/o Easy Probe Set | 15.7 | 24.2 |

消融实验显示，移除 Challenger 技能进化导致最大性能下降（GPT-4.1 从 16.5% 降至 13.8%），证实持续对抗压力对技能发现的必要性。Cross-Time Replay 是第二大贡献，移除后性能下降 1.8%（GPT-4.1）和 2.8%（GPT-5.1），验证了其对对抗崩溃的抑制作用。硬探针集比易探针集贡献更大，表明困难任务对技能泛化能力的影响更显著。

评估边界方面，CL-bench 的评分标准由领域专家制定，可能限制了技能在非结构化上下文中的泛化能力。论文未报告置信区间，且由于 API 预算限制，仅运行 5 次迭代和每次 5 个任务，未探索更大规模的影响。代码已开源（S1s-Z/Ctx2Skill），但超参数（如迭代次数、任务数量）的敏感性分析缺失。

## 关联研究分析

从问题动机看，Ctx2Skill 与 CoEvoSkills 均解决技能自动构建问题，但 CoEvoSkills 依赖生成器-验证器协同，验证器提供结构化失败诊断，而 Ctx2Skill 用 Challenger 生成的任务替代验证器，适应无真值场景。这一差异源于任务特性：CoEvoSkills 面向可验证任务（如代码），而 Ctx2Skill 面向纯文本上下文学习，后者缺乏执行反馈。然而，Challenger 生成的评分标准是否可能引入偏差，导致技能偏离上下文原意，论文未提供证据支持。

从方法设计看，Ctx2Skill 与 SkillOpt 均涉及技能优化，但 SkillOpt 依赖验证门控，仅接受提升验证集性能的编辑，而 Ctx2Skill 通过自博弈对抗压力驱动技能更新。SkillOpt 在 SpreadsheetBench 上达到 78.5% 的 Hard Score，但依赖验证集，而 Ctx2Skill 在无验证集场景下仍有效。这一差异暗示，当外部反馈不可用时，对抗机制可作为替代信号，但其稳定性是否优于基于规则的优化，需在更多基准上验证。

## 总结

Ctx2Skill 解决了上下文学习中技能构建缺乏外部反馈的核心矛盾，通过自博弈机制替代人工标注和验证门控，实现了无监督技能发现。其切入点在于利用 Challenger-Reasoner 对抗压力生成诊断信号，并通过 Cross-Time Replay 防止技能过拟合。实验证明该方法在 CL-bench 上显著提升多个骨干模型的表现，例如 GPT-4.1 从 11.1% 提升至 16.5%。然而，其边界在于自博弈生成的任务分布可能偏离真实上下文知识，且未验证在可验证领域（如数学）中的扩展性。当上下文包含可执行代码或形式化规则时，自博弈生成的评分标准是否仍能准确反映技能质量，论文未给出回答。
