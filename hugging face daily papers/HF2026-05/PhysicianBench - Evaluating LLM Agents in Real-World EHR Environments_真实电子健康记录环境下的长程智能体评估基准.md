# HuggingFace最新推荐论文 ｜PhysicianBench: Evaluating LLM Agents in Real-World EHR Environments ｜真实电子健康记录环境下的长程智能体评估基准

研究机构：美国斯坦福大学、MiniMax

作者：Ruoqi Liu、Imran Q. Mohiuddin、Austin J. Schoeffler 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.02240)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.02240)

> 临床决策支持系统正从静态知识问答转向自主执行多步工作流，但现有基准仅评估单步原子操作或意图，无法验证智能体在真实电子健康记录（EHR）系统中的长程状态管理与动作执行能力。PhysicianBench 通过构建基于真实病例的 FHIR 合规环境，将任务形式化为部分可观测马尔可夫决策过程（POMDP），并引入执行接地验证机制，首次实现了对智能体临床工作流完整闭环的细粒度评估。该基准揭示了当前大语言模型（LLM）在长程任务中可靠性严重不足的现状，但其仅评估单智能体架构，未验证多智能体协作在缓解长程推理失败中的潜在作用。

## 研究背景

理解本文需厘清两个核心概念的因果关联。临床智能体在真实 EHR 中工作时，无法直接观测患者完整状态，必须通过主动查询构建工作临床图景，这一过程天然符合 POMDP 的建模框架，其中状态空间包含完整 EHR 内容，智能体需在部分可观测条件下进行序列决策。然而，传统评估仅关注最终文本输出或单步动作意图，忽略了动作执行后 EHR 底层状态是否真实更新这一关键环节，导致“意图正确但执行失败”的隐蔽错误无法被捕获。

现有医学基准存在三重局限：MedQA 等静态问答基准已趋于饱和，无法反映动态交互；HealthBench Professional 侧重对话质量，缺乏系统操作维度；MedAgentBench 虽提供 FHIR 环境，但任务多为单步原子操作，未覆盖从信息检索到文档生成的复合工作流。PhysicianBench 的切入点在于将评估重心从“模型知道什么”转向“模型能否可靠地完成临床工作流”，通过执行接地验证填补了意图与执行之间的评估空白，直接回应了长程状态管理这一当前 LLM 智能体的核心短板。

## 核心方法

### 任务形式化与 POMDP 建模

本文任务结构遵循 POMDP 标准流程，但关键差异在于状态空间的定义与验证机制。标准 POMDP 在医疗场景中通常假设状态转移由外部事件驱动，而本文将状态转移严格限定为智能体工具调用引发的 EHR 状态变更，确保环境动态性完全由智能体行为决定。

$$
s_{t+1} = T(s_t, a_t)
$$

其中 $T$ 为确定性转移函数，写操作（如创建 `MedicationRequest`）修改 EHR 状态，读操作保持状态不变。该设计动机在于消除环境随机性对评估的干扰，使失败归因可精确追溯至智能体决策而非环境噪声，解决了此前基准中因环境不可控导致的评估信度不足问题。

### 执行接地验证与检查点评估

在任务执行环节，常规做法仅评估智能体输出的文本或动作意图，本文创新性地引入执行接地验证，通过查询 FHIR 服务器确认动作是否真实生效。每个任务被分解为检查点集合 $C = \{c_1, ..., c_K\}$，总检查点数 670 个，覆盖数据检索、临床推理、动作执行与文档生成四个阶段。

$$
\text{Score}(c_i) = \begin{cases}
1 & \text{if } \text{CodeGrader}(c_i) \lor \text{HybridGrader}(c_i) \lor \text{LLMJudge}(c_i) = \text{pass} \\
0 & \text{otherwise}
\end{cases}
$$

该公式表明检查点评分由三种评分器联合决定：代码评分器验证 FHIR 资源创建，混合评分器结合确定性计算与 LLM 提取，LLM 裁判评分器评估临床推理质量。这一设计解决了单步评估无法定位长程任务中具体失败环节的问题，使诊断粒度从任务级细化至步骤级，为后续失败模式分析提供了结构化基础。

## 实验评估

实验在自建 PhysicianBench 上进行，覆盖 12 个主流 LLM，基线审计显示未包含多智能体协作框架（如 MedCoAct）或 RAG 增强基线，仅评估单智能体架构。主实验结果如下：

| 模型 | Pass@1 (%) | Pass^3 (%) | #Turns |
| :--- | :--- | :--- | :--- |
| GPT-5.5 | 46.3±1.2 | 28.0 | 41.9 |
| Claude Opus 4.6 | 31.7±2.3 | 18.0 | 25.2 |
| DeepSeek V4-Pro | 18.7±2.9 | 6.0 | 35.3 |
| Grok-4.20 | 5.3±3.2 | 1.0 | 16.7 |

GPT-5.5 以 46.3% 的 Pass@1 领先，但 Pass^3 仅 28.0%，表明即使最强模型在三次独立运行中全部成功的概率不足三成，可靠性严重不足。失败分布分析显示，临床推理类检查点失败占比最高（平均 50.4%），其次是动作执行（18.8%）与文档生成（18.4%），数据检索失败占比最低（12.4%），表明瓶颈不在信息获取而在推理与执行环节。

消融实验未提供独立表格，但按专科分组分析显示，GPT-5.5 在 8 个专科组中的 7 个组领先，唯一例外是肾脏/泌尿科，其中 Claude 家族以 33.3% 超越 GPT-5.5 的 29.2%。按任务类型分析，治疗规划是最难任务类型，最佳非 GPT-5.5 模型仅达 23.5%，而诊断任务达 43.6%，表明开放式多步任务对当前模型构成更大挑战。

评估边界方面，基准未报告置信区间，且仅使用默认温度与高推理努力参数，未探索不同超参数组合的影响。可复现性方面，论文提供完全开源的环境、智能体框架与评估工具，每个任务运行在隔离 Docker 容器中，确保无状态泄漏。

## 关联研究分析

从问题动机看，PhysicianBench 与 MedAgentBench 均基于 FHIR 环境，但前者聚焦长程复合工作流，后者侧重单步原子操作。这一差异源于任务定义的根本不同：MedAgentBench 评估的是“能否执行单个临床动作”，而 PhysicianBench 评估的是“能否完成从检索到文档的完整临床流程”。根源在于真实临床工作流本质上是多步依赖的，单步能力无法线性叠加为长程能力，这一假设在本文实验中得到验证——GPT-5.5 在单步操作上表现优异，但在长程任务中 Pass^3 骤降至 28.0%。

从方法设计看，PhysicianBench 与 τ-bench 共享多步工具调用评估框架，但前者引入执行接地验证，后者仅评估最终状态。这一差异源于医疗领域的特殊性：临床动作具有不可逆性，错误执行可能导致患者伤害，因此必须验证动作是否真实生效而非仅评估意图。τ-bench 在零售/航空领域可容忍部分执行错误，但医疗场景要求零容忍，这一领域特性决定了执行接地验证的必要性。

## 总结

PhysicianBench 要解决的核心矛盾是静态基准无法评估 LLM 智能体在真实 EHR 环境中的长程工作流执行能力。其切入点在于将任务形式化为 POMDP 并引入执行接地验证，通过 FHIR 状态变更确认动作真实生效，填补了意图与执行之间的评估空白。该基准证明了当前最强模型 GPT-5.5 仅能完成 46.3% 的任务，且 Pass^3 仅 28.0%，可靠性严重不足。其边界在于仅评估单智能体架构，未验证多智能体协作在缓解长程推理失败中的潜在作用，也未探索 RAG 增强对事实准确性的影响。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
