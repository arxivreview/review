> 大语言模型在思维链推理中常陷入“表演性推理”，即在内部已确定答案后仍生成冗长推导，导致延迟与算力浪费。现有方法或依赖训练调整生成策略，或将连续嵌入用于隐式生成，均未能同时兼顾推理效率、可读性与答案可靠性。COPT 通过反转“先答后思”的顺序，并利用连续嵌入作为推理时验证器来评估草稿答案的可靠性，从而选择性触发后续思考。该范式在无需额外训练的情况下提升了准确率并大幅削减了 Token 消耗，但其对草稿答案可靠性的判断机制在对抗性场景下的鲁棒性尚存疑。

## 研究背景

当模型面对复杂数学或编程任务时，标准思维链（Chain-of-Thought, CoT）范式要求模型先完成完整的自然语言推导再输出答案。这一流程假设“思考”是“回答”的必要前置条件，但在实际推理中，模型往往在生成早期步骤时已在内部隐藏状态中锁定了答案，后续生成的文本仅是对既定结论的事后合理化，这种现象被称为表演性推理。表演性推理不仅增加了推理延迟，还引入了不必要的 Token 消耗，使得基于文本的监控机制难以区分真实推理与装饰性文本。

为了解决这一效率与忠实度的矛盾，研究界主要沿两条路线展开。一条是显式推理优化，通过强化学习或提示工程调整生成策略，但这类方法通常保留“先思后答”的顺序，无法从根本上消除冗余推导。另一条是潜在推理（Latent CoT），利用连续嵌入替代离散 Token 进行隐式推理，虽然提升了表征带宽，但牺牲了推理过程的可读性，且连续嵌入直接用于生成时易出现表征漂移或多样性丧失。COPT 的切入点在于打破这两条路线的固有局限：它不改变显式推理的可读性，也不将连续嵌入用于生成，而是反转推理顺序，先输出草稿答案，再利用连续嵌入保留的不确定性信息作为验证器，动态决定是否需要后续思考。

## 核心方法

### 方法参照系

COPT 属于推理范式重构与效率优化的交叉领域。与标准 CoT 的“先思后答”流程不同，COPT 将推理过程解耦为“草稿答案生成”与“条件化在线思考”两个阶段。其核心差异在于，它不依赖训练来改变模型行为，而是通过推理时的对比机制，利用连续嵌入与离散 Token 之间的分布差异来评估草稿答案的可靠性，从而决定后续思考的触发与可见性。

### 草稿答案可靠性估计

在标准 CoT 中，模型必须生成完整推导才能输出答案，导致即使答案已确定也需消耗大量 Token。COPT 首先强制模型在问题后立即输出 `</think>` 并生成草稿答案 $a = (a_1, \dots, a_{T_a})$。在生成过程中，模型缓存每个 Token 的离散概率 $p_t$ 和基于下一 Token 分布计算的连续嵌入 $e_t$。草稿答案完成后，COPT 计算归一化序列级反向 KL 散度估计量 $\kappa_a$，以衡量草稿答案的可靠性。

$$
\kappa_a = \frac{1}{T_a} \sum_{t=1}^{T_a} \log \frac{p_t}{p_t^{[e]}}
$$

该公式的物理含义是：对比模型在离散输入（学生分布）与连续输入（教师分布）下对同一草稿答案的支持度。若连续嵌入保留的不确定性显著改变了模型对草稿答案的支持度（即 $p_t^{[e]}$ 远小于 $p_t$），则 $\kappa_a$ 较大，表明草稿答案可能不可靠，需触发后续思考。这一设计解决了标准 CoT 中无法提前识别答案可靠性的问题，避免了在简单问题上的过度思考。

### 在线思考的动态可见性控制

当 $\kappa_a > \tau_a$ 时，COPT 触发在线思考阶段。此时，草稿答案可能包含部分有用信息，但全程暴露可能误导模型。COPT 将思考轨迹划分为长度为 $C$ 的块，并在每个块结束时计算第二个 KL 估计量 $\kappa_{r_k}$，以动态控制草稿答案在下一块的可见性。

$$
\kappa_{r_k} = \frac{1}{C} \sum_{t=s_k}^{s_k+C-1} \log \frac{p_t}{p_t^{[e]}}
$$

该公式衡量当前思考块的稳定性。若 $\kappa_{r_k}$ 较大，表明当前思考过程不稳定，易受草稿答案误导，COPT 将隐藏草稿答案；反之，则保留其可见性。这一机制解决了草稿答案在后续思考中可能引入噪声的问题，实现了“有用时利用，有害时隐藏”的精细控制，提升了推理过程的鲁棒性。

## 实验评估

COPT 在 Qwen3 和 Qwen3.5 系列模型（2B、8B、35B 规模）上进行了评估，覆盖数学、编程和智能体推理任务。基线包括标准 CoT、贪心 CoT 以及使用连续嵌入生成的 Soft-Thinking 和 SwiReasoning。实验结果显示，COPT 在保持或提升准确率的同时，显著减少了 Token 消耗。

| 基准 | 方法 | 准确率 (%) | Token 数 |
| :--- | :--- | :--- | :--- |
| GSM8K | CoT | 95.75 | 2138 |
| GSM8K | COPT | 96.36 | 1813 |
| AIME24 | CoT | 75.83 | 12077 |
| AIME24 | COPT | 79.17 | 11525 |
| HumanEval | CoT | 92.68 | 2368 |
| HumanEval | COPT | 96.34 | 1842 |

在 GSM8K 上，COPT 将准确率从 95.75% 提升至 96.36%，同时 Token 数从 2138 降至 1813，减少了 15.2%。在更具挑战性的 AIME24 上，COPT 的准确率提升 3.34%，Token 数减少 4.6%。在编程任务 HumanEval 上，COPT 的准确率提升 3.66%，Token 数减少 22.2%。这些结果表明，COPT 通过选择性触发思考，在简单问题上节省了冗余 Token，在复杂问题上提升了峰值准确率。

COPT 与 Soft-Thinking 和 SwiReasoning 的对比显示，COPT 在四个基准上均取得了更高的准确率和更少的 Token 消耗。例如，在 GSM8K 上，COPT 的准确率为 96.36%，Token 数为 1813，而 Soft-Thinking 的准确率为 95.38%，Token 数为 2073。这一优势源于 COPT 保留了显式推理的可读性，同时利用连续嵌入的不确定性信息进行验证，避免了连续嵌入直接生成时的表征漂移问题。

实验评估的边界在于，COPT 的可靠性估计机制依赖于连续嵌入与离散 Token 之间的分布差异，这一假设在对抗性提示或隐藏任务下可能失效。此外，实验未报告置信区间，且未与忠实度专用基准（如 FaithCoT-Bench）进行对比，因此无法直接评估 COPT 对推理忠实性的影响。代码已开源，但超参数（如 $\tau_a$ 和 $\tau_r$）的设置对结果影响较大，需在不同任务上仔细调优。

## 关联研究分析

从问题动机看，COPT 与 FaithCoT-Bench 等忠实度评估基准存在根本差异。FaithCoT-Bench 旨在量化思维链与内部计算的一致性，通过反事实干预检测表演性推理，而 COPT 关注的是推理效率与准确率的权衡，通过反转顺序减少冗余 Token。COPT 的可靠性估计量 $\kappa_a$ 虽能识别不可靠的草稿答案，但并未直接验证思维链的忠实性，因此无法替代忠实度审计。这一差异源于任务目标的不同：COPT 追求成本效益，而忠实度基准追求因果证据。

从方法设计看，COPT 与 COCONUT 等潜在推理方法在连续嵌入的使用上存在关键分歧。COCONUT 将连续嵌入用于生成隐式推理步骤，提升了表征带宽但牺牲了可读性；COPT 则将连续嵌入重构为推理时验证器，保留了显式推理的可读性，同时利用其不确定性信息。这一设计选择解决了潜在推理方法中连续嵌入直接生成时易出现的表征漂移和多样性丧失问题，但可能限制了连续嵌入在复杂推理中的信息容量。COPT 的验证机制是否能在高维连续空间中有效捕捉所有相关不确定性，论文未给出回答。

## 总结

COPT 旨在解决大语言模型在思维链推理中因表演性推理导致的效率低下与 Token 浪费问题。其切入点在于反转“先思后答”的顺序，并利用连续嵌入作为推理时验证器，动态评估草稿答案的可靠性。通过计算离散与连续输入下的反向 KL 散度，COPT 实现了选择性触发思考与动态可见性控制，在无需额外训练的情况下提升了准确率并削减了 Token 消耗。实验显示，COPT 在 GSM8K 上将准确率提升至 96.36% 并减少 15.2% 的 Token，在 AIME24 上提升 3.34% 的准确率。然而，COPT 的可靠性估计机制依赖于连续嵌入与离散 Token 的分布差异，这一假设在对抗性场景下的鲁棒性未经验证。当模型面对精心设计的对抗性提示时，连续嵌入的不确定性是否仍能准确反映草稿答案的可靠性，论文未给出回答。
