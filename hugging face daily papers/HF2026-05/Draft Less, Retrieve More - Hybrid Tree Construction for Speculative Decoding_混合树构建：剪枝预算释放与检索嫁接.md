# HuggingFace最新推荐论文 ｜Draft Less, Retrieve More: Hybrid Tree Construction for Speculative Decoding ｜混合树构建：剪枝预算释放与检索嫁接

研究机构：浙江大学、中国科学技术大学

作者：Yuhao Shen、Tianyu Liu、Xinyi Hu 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.20104)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.20104)

> 投机解码（Speculative Decoding, SD）旨在通过并行验证打破自回归解码的串行瓶颈，但现有动态树剪枝方法在降低延迟的同时，因丢弃潜在有效候选而严格限制了平均接受长度（MAT）。本文指出剪枝本质上是“预算释放”而非单纯移除，提出 Graft 框架，将检索分支嫁接至剪枝释放的拓扑空隙，以零额外验证开销打破延迟-MAT 帕累托前沿。该设计在短上下文与长上下文场景均显著优于 EAGLE-3 基线，但其检索机制对局部重复模式的依赖在低重复性任务中的鲁棒性尚存疑。

## 研究背景

自回归解码中，每个 token 的生成依赖前缀序列，导致 LLM 推理受限于内存带宽而非计算能力。投机解码通过轻量级草稿模型并行预测候选 token，再由目标模型单次并行验证，在不改变输出分布的前提下提升吞吐量。核心指标为 MAT，即每个草稿-验证周期中平均被接受的 token 数量，它直接决定了加速比的上限。早期方法采用线性链验证，但 GPU 并行能力未被充分利用；树状验证（Tree-based Verification）通过生成多个候选分支并行验证，最大化硬件利用率，但引入了草稿侧搜索与内存带宽开销。

EAGLE-3 等特征对齐方法利用目标模型隐藏状态生成高质量草稿树，显著提升了 MAT，但密集树结构导致草稿成本激增。动态深度剪枝（如 DDD、ECHO）通过移除低置信度分支降低延迟，但存在结构性缺陷：剪枝后的树严格是原始静态树的子树，无法引入新候选路径。由于置信度信号存在噪声，细粒度剪枝不可避免地误删有效延续，导致 MAT 严格低于密集树上限。这构成了严格的延迟-MAT 前沿：剪枝越快，接受长度损失越大。现有检索增强 SD 方法（如 PLD、TR）虽能低成本提供候选，但多作为独立草稿器或目标侧辅助机制，未与树状验证深度耦合，且依赖 CPU 侧查找，同步开销抵消了推测收益。

## 核心方法

### 动态树前沿与预算释放机制

标准 SD 中，草稿模型生成树 $T$，目标模型验证，加速比近似为 $\frac{M(T)}{C_{draft}(T) + C_{verify}(T)}$。动态剪枝策略 $\pi$ 修改树结构为 $T_\pi \subseteq T_{dense}$，虽然降低了 $C_{draft}$，但 $M(T_\pi) \le M(T_{dense})$。本文重新定义剪枝为预算释放机制：当草稿置信度低于阈值时，剪枝释放的候选槽位（slots）不再空置，而是作为可复用计算预算。这一视角打破了“剪枝即移除”的传统认知，为引入外部候选源提供了拓扑空间。

### 剪枝-检索耦合的混合树构建

Graft 的核心创新在于将检索分支嫁接至剪枝释放的槽位，而非根节点或尾部。设剪枝后释放的槽位集合为 $S_{free}$，检索模块从 GPU 驻留邻接矩阵中获取当前 token 的局部延续候选 $R$，并将 $R$ 中的高置信度节点映射至 $S_{free}$。最终验证树 $T_{final} = T_{pruned} \cup R_{grafted}$，其总候选数保持与原始静态树一致。

$$
T_{final} = T_{pruned} \cup \{ r \in R \mid \text{conf}(r) > \tau, \text{parent}(r) \in S_{free} \}
$$

该公式表明，检索节点仅填入剪枝产生的空隙，不占用原有草稿节点预算。设计动机在于解决 $Graft(ROOT)$ 与 $Graft(TAIL)$ 的失效：前者在根节点竞争导致高质量草稿节点被稀释，后者依赖前缀完全接受，早期拒绝即失效。通过“剪枝供预算，检索补覆盖”，Graft 在保持验证预算不变的前提下，引入了原静态树之外的候选路径，从而突破动态树剪枝的 MAT 上限。

### GPU 驻留邻接矩阵在线更新

为确保生产环境可行性，检索分支根植于当前 token，并与自回归草稿并行准备。Graft 使用 GPU 驻留邻接矩阵存储局部转移模式，通过预热初始化，并利用目标模型验证信号在线更新。验证过程中，无论草稿节点被接受或拒绝，其对应的转移概率均更新至矩阵。这一机制避免了 CPU 侧同步，且随着上下文延长，矩阵中积累的局部模式更丰富，自然提升检索命中率，无需额外开销。

## 实验评估

实验在 8 块 NVIDIA H20 GPU 上进行，覆盖短上下文（HumanEval, GSM8K, CNN/DM, Alpaca, MT-Bench）与长上下文（QMSum, GovReport, MultiNews, LCC, RepoBench-P）场景，基线包括 EAGLE-3、DDD、ECHO、PLD、TR 及长上下文专用方法 MagicDec、TokenSwift。

| 模型 | 基准 | EAGLE-3 Speedup | Graft Speedup | 相对提升 |
| :--- | :--- | :--- | :--- | :--- |
| Qwen3-32B | HumanEval | 2.14× | 2.51× | 17.3% |
| Qwen3-32B | GSM8K | 2.46× | 2.86× | 16.3% |
| LLaMA3.1-8B | LCC | 2.05× | 2.92× | 42.4% |
| Qwen3-14B | RepoBench-P | 1.86× | 2.33× | 25.3% |

Graft 在短上下文上全面超越 EAGLE-3，Qwen3-235B 上平均加速比提升 21.8%。长上下文场景中，检索优势在代码补全任务尤为显著，Qwen3-8B 上 LCC 提升 32.4%，RepoBench-P 提升 38.6%，表明局部重复模式对检索命中率的关键作用。

消融实验显示，移除检索分支（w/o retrieval）导致加速比下降 4.5%-5.5%，移除剪枝（w/o prune）则使 MAT 降低 3.1%-5.5%。检索深度 $d$ 从 2 增至 12 时，加速比从 2.41× 升至 2.54×，但边际收益递减；宽度 $w$ 从 2 增至 12 时，加速比从 2.37× 升至 2.75×，表明宽度对覆盖率的贡献大于深度。

评估边界方面，论文未报告置信区间，且部分基线（如 SpecInfer、HASS）未纳入对比。代码未公开，但提供了详细超参数。长上下文实验采用 YaRN 适配的 EAGLE3-64K 草稿模块，与 SpecPV 设置一致，确保了可比性。

## 关联研究分析

从问题动机看，Graft 与 ECHO 等动态剪枝方法同属“降低草稿成本”路线，但 ECHO 将剪枝视为终止信号，而 Graft 将其视为资源再分配机制。这一差异源于对“预算”定义的重新阐释：ECHO 假设剪枝后剩余计算能力无法有效利用，Graft 则证明通过检索可填补拓扑空隙。根源在于任务特性：代码与长文档包含大量局部重复模式，使检索成为低成本高收益的候选源；而在低重复性任务（如数学推理）中，检索命中率可能下降，论文未充分探讨此边界。

从方法设计看，Graft 与 REST、PLD 等检索增强 SD 方法共享“非参数化候选生成”思想，但 REST 将检索作为独立草稿器，Graft 将其嵌入树状验证路径。这一差异解决了 REST 的 CPU 同步开销问题，但引入了对邻接矩阵更新频率的依赖。与 EAGLE-3 相比，Graft 未改变特征对齐草稿的核心机制，仅优化了树结构构建策略，因此其加速比上限仍受限于 EAGLE-3 的草稿质量。在 GSM8K 上，Graft 的 2.86× 加速比低于领域综述中 HASS 的 4.05×，暗示检索对数学推理的局部模式依赖可能限制了其在高抽象任务中的表现。

## 总结

Graft 针对动态树剪枝导致的 MAT 损失问题，提出剪枝预算释放与检索嫁接耦合机制，在保持验证预算不变的前提下突破延迟-MAT 帕累托前沿。实验证明其在短上下文 Qwen3-235B 上实现 21.8% 平均加速比提升，长上下文 LLaMA3.1-8B 上达 3.22× 加速比。其边界在于检索机制对局部重复模式的依赖，在低重复性任务中效果可能衰减。当上下文长度进一步扩展至百万级 token 时，邻接矩阵的内存占用与更新延迟是否成为新的瓶颈，论文未给出回答。
