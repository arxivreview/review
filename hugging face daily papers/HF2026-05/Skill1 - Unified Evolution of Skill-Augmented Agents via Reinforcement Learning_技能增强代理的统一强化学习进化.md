> 代理技能库的维护涉及选择、利用与蒸馏三个耦合环节，现有方法往往孤立优化或引入冲突的辅助奖励，导致进化停滞。Skill1 指出，将检索与蒸馏模块从策略梯度中剥离是性能瓶颈的根源，其切入点在于通过单一任务结果信号实现全链路信用分配。该方法将任务结果分解为低频趋势与高频变异，分别驱动技能效用追踪与新技能生成，在 ALFWorld 和 WebShop 上验证了协同进化的有效性。尽管在具身交互任务中达到 SOTA，但其对动态网页环境的适应性及计算成本仍存疑。

## 研究背景

当代理在长程任务中积累经验时，策略参数仅隐式吸收成功路径，无法显式复用。为解决此问题，技能库作为外部程序性记忆被引入，存储自然语言策略与场景描述。然而，技能库的有效运转依赖三个环节的协同：从库中检索相关技能（选择）、依据技能执行任务（利用）、从轨迹中提取新技能（蒸馏）。若任一环节失效，整体性能将受限。

早期方法如 SkillRL 冻结检索模块，仅优化利用与蒸馏；RetroAgent 虽优化蒸馏，但依赖独立内在奖励，导致信号源不一致。这种分离式优化造成“优化瓶颈”：策略可能擅长利用技能，却因路由至次优技能而失败。核心矛盾在于，三个环节共同决定任务成功率，使用不一致的奖励信号会产生冲突压力，阻碍统一进化。Skill1 针对此问题，提出通过单一任务结果信号 $r(\tau)$ 的分解，实现选择、利用、蒸馏的联合优化，消除辅助奖励带来的偏差。

## 核心方法

### 方法参照系

标准技能增强代理流程包含查询生成、候选检索、重排选择、条件执行及技能蒸馏。传统架构将检索器视为冻结外部模块，蒸馏依赖独立教师或启发式评分。本文的关键差异在于，将查询生成、重排及蒸馏全部纳入单一策略 $\pi_\theta$ 的参数空间，所有学习信号均源自任务结果 $r(\tau)$，而非多源奖励。

### 基于频率分解的信用分配

选择环节通常依赖语义相似度，但无法捕捉长期执行效用。Skill1 引入指数移动平均（EMA）追踪每个技能的效用分数 $U(s)$，作为低频趋势信号。该信号通过归一化折损累计增益（NDCG）监督重排策略，奖励与效用排序一致的重排结果：

$$ R_{\text{rerank}} = \text{NDCG}(\sigma, \text{argsort}(-U(B_K))) $$

此设计解决了纯语义检索导致的“相关性-效用差距”，使策略学会优先选择历史表现稳定的技能，而非仅文本相似的技能。

### 基于结果变异的蒸馏激励

蒸馏环节缺乏即时反馈，因为新技能的价值需在未来任务中验证。Skill1 利用当前任务结果与库内最佳效用分数的偏差作为高频变异信号，近似新技能的边际贡献：

$$ R_{\text{distill}} = r(\tau) - \hat{U}_i $$

其中 $\hat{U}_i$ 为检索候选中的最高效用分数。正偏差表明当前经验超越库内现有能力，激励策略生成新技能；负偏差则抑制冗余蒸馏。该机制无需额外 rollout 或辅助模型，直接利用任务结果驱动技能库的边界扩展，避免了独立奖励信号与任务目标脱节的问题。

## 实验评估

实验在 ALFWorld 和 WebShop 上进行，基线覆盖无训练（ReAct）、纯 RL（GiGPO）及技能 RL（SkillRL, RetroAgent）三类方法，均使用 Qwen2.5-7B-Instruct 作为骨干模型。缺失基于图结构检索（如 SkillDAG）及参数化内化（如 LatentSkill）方法的对比，可能影响对检索机制优势的全面评估。

| 方法 | ALFWorld Avg (%) | WebShop Succ (%) |
| :--- | :--- | :--- |
| ReAct | 31.2 | 19.5 |
| GiGPO | 90.8 | 84.4 |
| SkillRL | 97.7 | 84.4 |
| RetroAgent | 94.9 | 82.3 |
| **Skill1** | **97.5** | **82.9** |

Skill1 在 ALFWorld 上以 97.5% 的平均成功率超越 RetroAgent 2.6 个点，但在 WebShop 上低于 SkillRL 1.5 个点。消融实验显示，移除技能库导致性能从 97.5% 骤降至 80.9%，其中 Heat 和 Pick2 任务损失超过 28 点，证实库对多步子程序组合的关键作用。移除蒸馏信号使性能下降 5.1 点，表明原始轨迹存储导致选择噪声增加。同时移除选择与蒸馏信号，性能降至 90.2%，低于单独移除任一信号的降幅，证明两个辅助目标对利用环节存在互补增益。

评估边界方面，论文未报告样本效率或计算延迟，仅展示成功率。代码已开源，但超参数细节（如 $\lambda_1, \lambda_2$ 的具体值）未在正文中列出，需查阅附录。WebShop 性能低于 SkillRL 的现象暗示，重排机制在动态网页环境中可能引入额外噪声，或效用追踪在快速变化的商品规格下收敛较慢。

## 关联研究分析

从问题动机看，Skill1 与 SkillRL 形成鲜明对照。SkillRL 冻结检索模块，假设语义相似度足以捕捉技能相关性，仅优化利用与蒸馏。Skill1 则指出，检索质量直接制约利用上限，将查询生成与重排纳入策略梯度，使代理能根据任务上下文动态调整检索策略。这一差异源于对“检索瓶颈”的不同认知：SkillRL 视检索为静态前置步骤，Skill1 视其为动态决策过程。

从方法设计看，Skill1 与 RetroAgent 在奖励信号来源上存在根本分歧。RetroAgent 使用独立内在奖励评估蒸馏质量，导致信号与任务目标解耦。Skill1 通过分解单一任务结果，确保所有环节优化方向一致。这种设计简化了训练流程，但依赖效用分数 $U(s)$ 的准确追踪。在技能库冷启动阶段，效用分数稀疏，NDCG 奖励可能不稳定，论文未讨论此阶段的信号有效性保障措施。

## 总结

Skill1 解决的核心矛盾是技能库维护中多环节优化信号不一致导致的进化停滞。其切入点在于识别出检索与蒸馏模块从策略梯度中剥离是性能瓶颈，通过单一任务结果信号的低频/高频分解，实现全链路信用分配。该方法在 ALFWorld 上以 97.5% 的成功率超越基线，证明统一优化优于分离式进化。然而，实验仅在文本交互环境进行，WebShop 性能低于 SkillRL 的现象暴露了效用追踪在动态环境中的适应性局限。当技能库规模扩大至数万级时，EMA 效用追踪的计算开销与检索延迟是否成为新的瓶颈，论文未给出回答。
