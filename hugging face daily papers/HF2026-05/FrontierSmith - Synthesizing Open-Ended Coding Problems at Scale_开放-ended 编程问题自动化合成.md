# HuggingFace最新推荐论文 ｜FrontierSmith: Synthesizing Open-Ended Coding Problems at Scale ｜开放-ended 编程问题自动化合成

研究机构：美国华盛顿大学、美国斯坦福大学

论文原文见 [arXiv](https://arxiv.org/abs/2605.14445)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.14445)

> 现有 LLM 代码生成研究聚焦于可二值验证的闭源任务，而真实工程中的开放-ended 任务缺乏已知最优解且需连续质量评分，导致训练数据极度稀缺。现有数据合成方法仅能生成闭源题，无法处理无标准答案的连续评分场景。本文通过变异闭源题目标、输出与输入，结合 Idea Divergence 指标筛选高多样性问题，并自动化构建测试环境，实现了开放-ended 编程问题的规模化合成。该方法证明了自动化合成数据可替代人工标注，但受限于自包含算法环境，未覆盖仓库级复杂场景。

## 研究背景

闭源编程任务（如 LeetCode 竞赛题）具备离散正确性，可通过单元测试进行二值验证，这使得基于可验证奖励的强化学习（Reinforcement Learning from Verifiable Rewards, RLVR）成为主流训练范式。然而，开放-ended 编程任务（如云集群调度优化）不存在全局最优解，其质量由 makespan、尾延迟等连续指标决定，验证可行性容易但证明最优性在大规模下不可行。这种“验证-优化”不对称性导致开放-ended 任务缺乏可自动化的奖励信号，进而阻碍了 LLM 在长程推理与复杂优化场景下的能力提升。

当前代码生成数据合成路线主要解决闭源任务的数据稀缺问题。AutoCode、SWE-smith 等方法通过 LLM 生成测试用例或新题目，但均局限于二值正确性设定，无法处理需要连续评分的开放-ended 场景。NP-Engine 虽针对 NP-hard 任务构建了规则验证器，但其问题目录固定，仅难度变化，限制了问题多样性。FrontierSmith 的切入点在于利用闭源题作为种子，通过结构化变异消除已知最优解，将二值验证转化为连续评分，从而在保留闭源题丰富语料优势的同时，生成具备真实开放-ended 特征的训练数据。

## 核心方法

### 问题表示与变异机制

代码生成数据合成的标准流程通常从现有语料中提取问题并生成测试用例，但开放-ended 任务缺乏现成的问题表述来源。本文提出将问题表述形式化为三元组 $(O, C_I, C_O)$，其中 $O$ 为计算目标，$C_I$ 为输入实例约束，$C_O$ 为输出约束。针对闭源题存在已知高效解的特性，本文定义三种变异操作以消除最优解：改变目标（如将 2-SAT 判定转为 Min-True 2-SAT 优化）、限制输出（如为最小生成树添加度约束使其变为 NP-hard）、泛化输入（如将最大独立集从二分图扩展至任意图）。这些变异确保生成的问题在大规模下无法精确求解，且具备连续质量度量，从而满足开放-ended 任务的定义。

### Idea Divergence 筛选机制

变异后产生的候选问题池包含大量噪声，需筛选出能激发多种算法策略的高多样性问题。本文引入 Idea Divergence 指标，定义为两个独立求解者使用不同核心算法的概率。该指标通过两阶段估计：首先利用 LLM-as-a-Judge 对采样解进行策略分类，计算语义差异；其次在构建测试环境后，利用执行分数向量的欧氏距离计算行为差异。

$$
\hat{d}_{exec}(c) = \frac{2}{n(n-1)} \sum_{i<j} \sqrt{\frac{1}{m} \|\mathbf{q}_i - \mathbf{q}_j\|_2^2}
$$

其中 $\mathbf{q}_i$ 为解 $s_i$ 在 $m$ 个测试用例上的分数向量。该公式量化了解在不同测试场景下的性能分布差异，若两种策略在部分测试上表现迥异，则距离较大，表明问题具备真正的开放-ended 特性。此筛选机制解决了单一策略主导导致问题退化为闭源任务的问题，确保训练数据能提供更强的 GRPO 梯度信号。

### 自动化测试环境构建

筛选后的候选问题需配套测试用例与验证器。本文采用双智能体交叉验证机制：测试用例智能体生成针对稀疏/稠密图、均匀/偏斜分布的对抗性输入，验证器智能体生成连续评分函数。两者迭代运行直至对方输出不再暴露错误，未收敛的候选被丢弃。该设计确保了测试环境能准确反映不同算法策略的性能差异，为连续奖励信号提供可靠基础。

## 实验评估

实验在 FrontierCS（172 个算法题）与 ALE-bench（10 个任务）上进行，基线包括 Base、人工标注 FrontierCS、人工标注 ALE-bench、闭源 HardTests 及随机奖励。

| 训练数据 | Qwen3.5-9B FrontierCS Avg@5 | Qwen3.5-9B ALE-bench Best@5 | Qwen3.5-27B FrontierCS Avg@5 | Qwen3.5-27B ALE-bench Avg@5 |
|---|---|---|---|---|
| Base | 1.80 | 327.22 | 7.70 | 352.52 |
| FrontierCS (172) | 11.17 | 558.49 | 13.98 | 543.80 |
| FrontierSmith (200) | 10.62 | 782.30 | 19.82 | 661.64 |
| HardTests (200) | 5.38 | 397.18 | 11.20 | 529.12 |
| Random Reward (172) | 3.04 | 376.82 | - | - |

FrontierSmith 在 9B 模型上 FrontierCS 得分 10.62，接近人工标注的 11.17，但在 ALE-bench Best@5 上以 782.30 显著超越人工标注的 558.49。27B 模型在两个基准上均优于人工标注基线，表明合成数据具备跨规模泛化能力。

消融实验显示，移除 Idea Divergence 筛选后，FrontierCS 得分从 10.62 降至 8.57，ALE-bench 从 633.6 降至 564.4，证明筛选机制对性能至关重要。随机奖励基线得分 3.04，接近 Base 的 1.80，排除了问题格式暴露作为增益来源的可能性，确认连续奖励信号的有效性。

评估边界方面，本文仅使用自包含算法环境，排除需云基础设施的仓库级任务。训练限制在 100 步单轮 GRPO，未探索 Agentic RL。代码与训练脚本已开源，但 27B 模型因算力限制未报告随机奖励基线，部分对比存在缺失。

## 关联研究分析

从问题动机看，FrontierSmith 与 NP-Engine 均针对开放-ended 任务，但 NP-Engine 依赖手工构建固定问题目录，仅通过难度变化实现多样性，而 FrontierSmith 通过变异闭源题实现问题表述的结构性创新。这一差异源于 NP-Engine 聚焦于经典 NP-hard 任务的理论完备性，而 FrontierSmith 追求训练数据的规模化与多样性，前者受限于专家知识边界，后者受限于 LLM 变异能力。

从方法设计看，FrontierSmith 与 AgentCoder 均采用多智能体交叉验证，但 AgentCoder 用于闭源任务的代码-测试一致性检查，而 FrontierSmith 用于开放-ended 任务的测试-验证器一致性检查。关键差异在于奖励信号类型：AgentCoder 输出二值正确性，FrontierSmith 输出连续分数。这一设计选择决定了 FrontierSmith 能提供更细粒度的梯度信号，但也引入了验证器评分偏差的风险，论文未讨论验证器本身的质量评估机制。

## 总结

本文核心矛盾在于开放-ended 编程任务缺乏可自动化的连续奖励信号，导致 LLM 训练数据稀缺。FrontierSmith 通过变异闭源题消除已知最优解，并利用 Idea Divergence 筛选高多样性问题，实现了开放-ended 问题的规模化合成。实验证明，200 个合成问题可使 Qwen3.5-27B 在 FrontierCS 上提升 12.12 分，在 ALE-bench 上提升 309.12 Elo 分，性能接近或超越人工标注数据。然而，该方法局限于自包含算法环境，未覆盖需复杂环境设置的仓库级任务，且验证器质量缺乏独立评估。当问题涉及跨文件依赖或外部 API 调用时，变异策略是否仍能保持连续评分的有效性，论文未给出回答。
