> 任务导向对话系统（TOD）在垂直服务场景中面临高质量标注数据稀缺、静态语料时效性滞后以及众包数据策略深度不足的三重困境。现有合成方法多依赖预定义模板或LLM内部知识，导致生成的对话缺乏真实用户意图的动态性与专业服务的策略连贯性。Stream框架通过挖掘公开流媒体中的原子交互信号，结合角色接地的人设合成与对话蓝图规划，实现了高保真服务对话的规模化生成。该工作验证了流媒体作为数据源的可行性，但其对“策略深度”的量化评估仍依赖主观裁判，缺乏客观的细粒度指标支撑。

## 研究背景

任务导向对话（Task-Oriented Dialogue, TOD）的核心挑战在于状态跟踪（Dialogue State Tracking, DST）与策略规划。在汽车销售、酒店预订等高价值垂直领域，助手需超越简单的槽位填充，执行需求挖掘、约束冲突处理及异议应对等复杂策略。然而，公开基准如MultiWOZ和SGD主要依赖众包标注，存在两大缺陷：一是标注成本高导致规模受限，二是众包工人缺乏领域专家知识，生成的对话虽功能正确但策略浅层，缺失说服、升级销售等关键要素。此外，静态语料无法捕捉车型更新、法规变化等动态领域漂移，导致模型在实时部署中失效。

针对上述瓶颈，现有合成方法如Generative Agents和PatientSim尝试通过定义认知画像提升仿真度，但普遍存在交互不对称与策略-动作解耦问题。用户画像多从模板或LLM内部知识采样，无法反映真实垂直用户的意图漂移与非规范语言特征；智能体行为缺乏显式专业约束，导致服务策略泛化。Stream框架的切入点在于将数据源从静态文本扩展至动态流媒体（直播、短视频），通过挖掘真实交互中的原子信号，构建具备策略深度的结构化对话数据，以解决数据稀缺与策略浅层的矛盾。

## 核心方法

### 方法参照系

本文问题属于垂直领域数据构建路线，但区别于基于预定义模板或静态画像的传统合成方法。其核心差异在于数据源的非结构化动态性（流媒体）与生成过程的显式轨迹规划（蓝图），旨在从噪声丰富的真实交互中重构具备逻辑连贯性的服务对话。

### 流媒体信号摄入与自适应人设合成

传统方法直接利用LLM生成对话，忽略了真实交互中的噪声与策略线索。Stream在数据摄入阶段（SSI）从直播弹幕、语音转写中提取五类原子信号：用户问题（$Q_u$）、智能体响应（$R_a$）、问答对（$P_{qa}$）、对话策略（$S_{tag}$）及账户元数据（$I_{acc}$）。为抑制ASR噪声，系统采用领域词典（如410万条汽车词汇）进行实体校正，并基于时间邻近性与语义相关性对齐问答对。随后，自适应人设合成（APS）阶段将信号转化为结构化人设。用户人设 $P_u$ 整合真实问题与种子对话，定义目标、核心需求及潜在话语变体；智能体人设 $P_a$ 结合账户元数据与领域知识库 $R$，界定服务边界与专业风格。这一设计解决了传统模板化人设无法捕捉真实用户意图分布与专家服务边界的问题，为后续生成提供了角色接地的先验约束。

### 对话蓝图规划与图聚类过滤

在生成阶段，Stream引入对话蓝图（Conversational Blueprint, $B$）作为显式轨迹规划机制。$B$ 包含整体节奏、关键节点定义、典型场景应对策略及对话流图谱，将对话从随机游走转化为目标导向的渐进过程。生成过程采用双向交互循环：用户话语模拟（UUS）与智能体响应生成（ARG）均利用检索增强生成（RAG）从种子池中检索相似历史作为行为参考，确保回复符合 $B$ 规划的逻辑路径。最终，通过构建对话相似度图进行社区检测，仅当用户侧与智能体侧表示均超过阈值时建立边：

$$
Edge(D_i, D_j) = \mathbb{I}(sim(u_i, u_j) > \tau_u) \land \mathbb{I}(sim(a_i, a_j) > \tau_a)
$$

该公式通过双向语义阈值过滤冗余对话，在保持多样性的同时去除重复模式。蓝图规划解决了长对话中策略连贯性缺失的问题，而图聚类过滤则确保了数据集的分布多样性，避免了单一策略模式的过拟合。

## 实验评估

实验在CrossWOZ、RiSAWOZ及TransferTOD构建的公开数据池上进行，基线包括纯公开数据、仅种子合成、仅流媒体合成及混合策略。DST任务使用Qwen3-1.7B、Qwen3-8B及Gemma3-4B作为骨干网络，训练预算固定为2000条对话。

| 训练策略 | Qwen3-8B JGA (%) | Qwen3-8B F1 (%) | Gemma3-4B JGA (%) |
| :--- | :--- | :--- | :--- |
| SFT w/ Public Data (Baseline) | 93.94 | 98.56 | 95.71 |
| + Seed-Only | 95.71 | 99.20 | 97.73 |
| + Stream-Only | 95.96 | 99.12 | 97.98 |
| + StreamDial (Hybrid) | **96.72** | **99.41** | **97.98** |

混合策略（StreamDial）在Qwen3-8B上取得96.72%的JGA，显著优于基线的93.94%及单一源策略。消融实验显示，种子数据提供了基础结构，而流媒体信号贡献了策略多样性，二者融合产生了协同效应。内在质量评估采用Qwen3-Max、GPT-5.2及Gemini3-Pro作为裁判，StreamDial在信息量、多样性及灵活性维度上均优于基线，且趋势在不同裁判模型间保持一致，降低了单一裁判偏差的风险。

评估边界方面，内在质量依赖LLM-as-a-Judge，虽有人工验证（1431条会话）佐证，但缺乏客观的细粒度策略指标（如异议处理成功率）。多语言迁移实验在X-RiSAWOZ上进行，但仅报告了Qwen3-8B的结果，其他骨干网络的跨语言表现未充分披露。代码与数据已开源，但流媒体信号提取的ASR错误率（3.5%-10.5%）对最终数据质量的影响未进行敏感性分析。

## 关联研究分析

从问题动机看，Stream与MADS均致力于解决垂直领域数据稀缺问题，但MADS侧重通过多智能体自博弈生成说服策略数据，而Stream聚焦于服务任务流程的完整性与时效性。MADS的模拟环境是封闭的，策略来源于博弈均衡；Stream的策略来源于真实流媒体中的专家行为挖掘，这使其数据更具现实分布特征，但可能引入流媒体特有的噪声偏差。Stream与ProCoT在策略规划上存在异同：ProCoT在推理时通过思维链规划对话策略，属于在线优化；Stream将规划前置为数据生成阶段的蓝图约束，属于离线数据增强。这种差异源于任务目标不同：ProCoT追求单轮回复的策略合理性，Stream追求长程对话的整体轨迹连贯性。

从方法设计看，Stream的人设构建与PAL等显式对齐方法有本质区别。PAL通过NLI关系优化人设与回复的一致性，属于模型层面的对齐；Stream的人设 $P_u, P_a$ 是数据层面的结构化字段，用于约束生成过程。Stream的RAG使用与GRAG不同：GRAG在推理时利用LLM生成通用响应作为接地信号，Stream在生成时利用RAG检索真实历史作为行为参考。Stream的图聚类过滤机制在现有合成数据方法中较为独特，多数方法仅依赖长度或困惑度过滤，Stream通过双向语义相似度去重，更有效地保留了策略多样性。

## 总结

Stream框架旨在解决垂直领域TOD数据稀缺、策略浅层及时效性滞后的核心矛盾。其切入点在于利用流媒体中真实、动态的交互信号，通过蓝图规划与角色接地人设，将噪声丰富的媒体内容转化为结构化、高保真的对话数据。实验证明，混合策略在DST任务上较基线提升2.78%的JGA，且内在质量评估显示其在策略多样性上具有优势。然而，该框架的边界在于对“策略深度”的评估仍依赖主观裁判，缺乏客观的细粒度指标；此外，流媒体信号的ASR噪声对数据质量的影响未充分量化。当支持集规模扩大或领域切换至低资源语言时，蓝图规划的泛化能力与流媒体信号提取的鲁棒性是否依然有效，论文未给出回答。
