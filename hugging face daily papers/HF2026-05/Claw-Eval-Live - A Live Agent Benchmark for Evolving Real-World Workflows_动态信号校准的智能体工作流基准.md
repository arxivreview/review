研究机构：香港中文大学、华南理工大学

作者：Chenxin Li、Zhengyang Tang、Mingxin Huang 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.28139)

> 现有智能体基准在发布时冻结任务集，导致评估分布与真实工作流需求逐渐脱节，且仅凭最终文本无法验证智能体是否真正执行了关键操作。Claw-Eval-Live 通过引入公开工作流需求信号动态校准任务分布，并采用基于执行轨迹的混合评分机制，解决了静态基准的时效性漂移与证据缺失问题。该基准将评估对象从单一答案扩展为可审计的工作流轨迹，但当前快照仍受限于特定生态系统的信号源，且服务类工作流的难度天花板尚未被突破。

## 研究背景

当智能体从单轮问答转向多步执行时，评估的核心矛盾从“回答是否合理”转变为“工作是否完成”。这一转变要求评估不仅关注最终输出，还需验证智能体在跨系统检索、状态变更及工件修复中的具体行为。然而，传统基准如 WebArena 和 OSWorld 采用静态发布模式，任务集在出版时固定，无法反映工具栈演化与企业瓶颈转移带来的工作流分布变化。

主流评估路线面临双重瓶颈：一是任务来源依赖人工策展或静态池，导致基准与真实部署场景的漂移；二是评分机制多依赖最终文本或单一环境，无法区分“说得对”与“做了工作”。例如，智能体可能生成流畅报告却遗漏关键写入操作，或在网页交互中忽略本地工作区修复。Claw-Eval-Live 的切入点在于将基准构建解耦为“动态信号层”与“固定发布层”，利用公开工作流信号作为分布先验，并通过可复现的时间戳快照实现稳定性与时效性的平衡。

## 核心方法

### 信号-任务转换流水线

现有基准构建通常由作者直接定义任务类别，缺乏外部需求对齐。Claw-Eval-Live 引入五阶段流水线，将 ClawHub Top-500 技能信号转化为可执行任务。设计动机在于解决静态任务集与动态工作流生态的脱节，通过外部信号校准任务混合比例。

### 混合整数线性规划选择

在候选任务筛选阶段，传统方法依赖人工策展，缺乏可审计的选择标准。本文采用混合整数线性规划（MILP）从 157 个可运行候选中选取 105 个公开任务，目标函数最大化试点模型排序保持率，约束条件包括发布规模、家族覆盖及零区分任务排除。

$$ \max \sum_{t \in T} x_t \sum_{i=1}^{K-1} \sum_{j=i+1}^{K} p_{t[i,j]} $$

该公式确保选出的任务子集在保持模型区分度的同时，覆盖预设的工作流家族分布，将发布构建从主观策展转化为可复现的优化问题。

### 动作锚定混合评分

最终文本评分无法捕捉中间步骤错误，如遗漏工具调用或错误实体更新。本文采用“规则提取 + 结构化 LLM 评判”的混合评分，其中确定性检查覆盖数据检索（15-20%）、数据准确性（40-60%）及动作验证（10-20%），LLM 评判仅用于语义维度。

$$ Score_t = \alpha \cdot Check_{det} + \beta \cdot Judge_{LLM} $$

该评分机制将证据锚定在可观测的执行轨迹上，如服务审计日志与工作区状态，确保评分反映智能体的实际行为而非文本流畅度。

## 实验评估

实验在 105 个任务上评估 13 个前沿模型，执行预算为 24 轮/300 秒。基线覆盖 Anthropic、OpenAI、Google 等主流厂商，但缺乏对特定脚手架（如 ReAct vs. Plan-and-Execute）的解耦对比，无法区分模型能力与框架效应。

| 模型 | 组织 | 通过率 | 通过数 | 总体完成度 |
| :--- | :--- | :--- | :--- | :--- |
| Claude Opus 4.6 | Anthropic | 66.7% | 70 | 83.6 |
| GPT-5.4 | OpenAI | 63.8% | 67 | 81.7 |
| Claude Sonnet 4.6 | Anthropic | 61.9% | 65 | 79.9 |
| GLM-5 | Zhipu AI | 61.9% | 65 | 78.1 |
| MiniMax M2.7 | MiniMax | 54.3% | 57 | 77.5 |

最佳模型 Claude Opus 4.6 通过率仅 66.7%，未突破 70% 阈值，表明稳定工作流执行仍远未达到可靠自动化水平。服务类工作流（87 任务）通过率最高仅 59.8%，而工作区修复（18 任务）最低模型通过率仍超 72.2%，显示跨系统协调与状态管理是当前主要瓶颈。

| 模型 | Token (M) | 轮次 | 估算 API 成本 | 时间 |
| :--- | :--- | :--- | :--- | :--- |
| Claude Opus 4.6 | 3.32 | 506 | $31.61 | 213 min |
| GPT-5.4 | 1.26 | 373 | $6.27 | 104 min |
| DeepSeek V3.2 | 2.06 | 617 | $0.56 | 118 min |
| MiniMax M2.5 | 1.81 | 465 | $0.78 | 79 min |

效率指标显示，GPT-5.4 在保持高通过率的同时，Token 消耗与 API 成本显著低于 Claude Opus 4.6，揭示准确率与资源消耗的非线性关系。低成本模型如 DeepSeek V3.2 虽成本极低，但通过率仅 51.4%，表明当前部署中性能与成本的权衡仍缺乏统一度量标准。

评估边界受限于 24 轮/300 秒的固定预算，可能低估长时程任务中的状态漂移问题。LLM 评判器使用 GPT-5.4，与被评估模型重叠，虽通过限制评判范围缓解偏差，但缺乏人工校准验证。代码与超参数未完全开源，动态信号管道的可复现性依赖 ClawHub 快照的稳定性。

## 关联研究分析

从任务来源看，Claw-Eval-Live 与 LiveCodeBench 共享“滚动更新”理念，但前者针对业务工作流，后者聚焦代码竞赛。关键差异在于信号源：LiveCodeBench 依赖竞赛平台数据，而本文采用 ClawHub 技能下载量作为需求代理。这一选择源于工作流生态的分散性，但可能导致任务难度分布不稳定，影响纵向可比性。

从评分机制看，本文与 CORE 均强调轨迹评估，但 CORE 使用确定性有限自动机标注动作路径，而本文采用混合整数规划选择任务并混合评分。CORE 的自动化标注适用于结构化环境，而本文的混合评分更适应非结构化业务场景。差异根源在于任务复杂度：业务工作流涉及多系统协调与语义判断，难以完全自动化标注，需 LLM 评判补充。

## 总结

Claw-Eval-Live 解决的核心矛盾是静态基准与动态工作流生态的脱节，以及最终文本评分与执行证据的错位。其切入点在于将公开工作流信号作为分布先验，并通过 MILP 优化与混合评分实现可复现的动态校准。实验证明最佳模型通过率仅 66.7%，服务类工作流成为主要瓶颈。本文边界在于信号源依赖特定生态系统，且缺乏对长时程状态漂移的系统性度量。当 ClawHub 信号分布发生结构性变化时，MILP 选择的目标函数是否仍能保持模型区分度，论文未给出回答。
