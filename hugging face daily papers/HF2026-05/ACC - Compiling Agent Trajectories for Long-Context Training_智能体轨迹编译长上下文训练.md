# HuggingFace最新推荐论文 ｜ACC: Compiling Agent Trajectories for Long-Context Training ｜智能体轨迹编译长上下文训练

研究机构：中国科学技术大学

作者：Qisheng Su、Zhen Fang、Shiting Huang 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2605.21850)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2605.21850)

> 长上下文推理能力的训练长期受限于高质量长文档标注成本高昂及启发式合成数据依赖关系虚假的问题。现有方法或依赖人工精细标注，或采用随机拼接导致证据链断裂，难以提供真实的多轮依赖监督。本文提出智能体上下文编译（Agent Context Compilation, ACC），将多轮智能体交互轨迹中的工具响应与环境观测直接编译为长上下文问答对，无需额外人工标注。该方法在图遍历任务上超越了复杂强化学习流程，但在多轮指代任务上仍落后于专用模型，其通用性边界尚待验证。

## 研究背景

智能体在执行搜索、软件工程或数据库查询任务时，需跨多轮交互整合分散的证据。标准智能体监督微调（SFT）通常掩码工具响应（Observations），仅监督轮次级的动作选择，导致模型无法学习跨轮次的证据整合能力，形成“监督盲点”。这一盲点使得智能体产生的海量轨迹数据无法直接用于长上下文推理训练，因为关键证据信号在损失计算中被过滤。

长上下文训练数据构建的主流路线包括人工标注长文档与启发式合成。前者如 Longwanjuan 依赖连贯性过滤，成本极高；后者如 Quest 通过关键词聚类拼接短文档，但缺乏真实的长程依赖结构。这些方法均无法提供“问题-分散证据-答案”的显式对应关系，导致模型在长距离依赖建模任务中性能受限。本文切入点在于利用智能体轨迹中天然存在的多轮依赖结构，通过编译机制将过程性证据转化为静态训练数据，解决数据稀缺与依赖虚假的双重瓶颈。

## 核心方法

### 方法参照系

长上下文训练数据构建通常遵循“源文档获取-依赖关系构建-问答对生成”流程。本文问题与该通用流程的关键差异在于：源数据非静态文档，而是动态多轮交互轨迹；依赖关系非人工标注，而是由智能体工具调用自然产生。

### 监督盲点消除与上下文编译

标准智能体 SFT 的损失函数仅包含模型生成 token，工具响应 $o_t$ 被掩码，导致其梯度仅通过短路径影响下一动作 $a_{t+1}$，无法有效传递至最终答案 $y$。ACC 通过将所有轮次的工具响应与环境观测聚合为单一长上下文 $C$，重构训练目标为直接预测答案：

$$ \mathcal{L}_{ACC} = -\log P(y, r | q, C) $$

该公式消除了中间动作项，使最终答案的监督信号直接作用于所有证据 token，迫使模型学习从分散片段中整合全局信息，而非优化局部工具选择。

### 证据结构化与干扰项保留

ACC 提取轨迹中的结构化证据片段 $E_i(\tau) = [e_1, ..., e_m]$，并应用随机排列 $\pi$ 拼接为上下文 $C = \text{Concat}(\pi(e_1), ..., \pi(e_m))$。设计动机在于打破证据的时序顺序，迫使模型依赖语义关联而非位置线索定位关键信息。同时，保留未访问的搜索结果或未打开的文件作为干扰项，模拟真实场景中的噪声，提升模型对关键证据的定位鲁棒性。

## 实验评估

实验基于 Qwen3-30B-A3B-Thinking 模型，使用 10,802 条编译轨迹（Search: 3,369; SWE: 4,368; SQL: 3,065）进行微调。基线覆盖 QwenLong-L1.5（多阶段清洗+RL）、LongPO（DPO）及 LongRLVR（RLVR），但缺失架构扩展类基线（如 MRROPE）。

| 模型 | MRCR Overall | GraphWalks Overall |
| :--- | :--- | :--- |
| Qwen3-30B-A3B-Thinking (Base) | 50.19 | 69.92 |
| Qwen3-30B-A3B-Thinking + ACC | 68.28 | 77.51 |
| QwenLong-L1.5-30B | 92.30 | 73.85 |
| Qwen2.5-14B-LongRLVR | 20.06 | 22.78 |

ACC 在 GraphWalks 上超越 QwenLong-L1.5，但在 MRCR 上显著落后，表明其优势依赖于证据结构类型。消融实验显示，移除干扰项导致 MRCR 下降 3.34-3.81 分，证实干扰项对定位能力的正向贡献；仅使用 SQL 轨迹在 GraphWalks 上提升 5.58 分，而 Search/SWE 轨迹在该任务上表现不佳，反映关系型数据与图遍历任务的结构性契合。

评估边界受限于单一模型规模与三类智能体场景，未验证百万 token 上下文下的扩展性。可复现性方面，论文提供了 HuggingFace 数据集与 Checkpoint，训练超参数（如序列长度 131,072，学习率 $1 \times 10^{-5}$）完整公开，但推理合成依赖 DeepSeek-V3.2-Thinking，存在教师模型偏差风险。

## 关联研究分析

从数据构建路线看，ACC 与 LongRLVR 的核心差异在于证据获取方式。LongRLVR 依赖从长文本中精确标注证据块，成本高且依赖人工规则；ACC 直接复用智能体轨迹中的工具响应，证据天然与问题关联。这种差异源于任务特性：智能体任务本身要求跨轮次整合，而静态文档任务需额外构建依赖。ACC 未探索轨迹中时序逻辑对推理的影响，随机排列是否破坏了原有的因果依赖链，论文未给出回答。

从训练范式看，ACC 与 LoongRL 均利用干扰项提升鲁棒性，但机制不同。LoongRL 通过 KeyChain 主动插入无关文档以合成困难样本，属于数据增强策略；ACC 保留轨迹中自然存在的未访问结果，属于数据保留策略。前者可控性强但可能引入分布外噪声，后者真实性高但噪声密度不可控。ACC 在 MRCR 上的落后可能源于自然干扰项的语义相关性不足，未能充分模拟多轮指代中的复杂干扰模式。

## 总结

本文核心矛盾在于长上下文训练数据的高标注成本与真实依赖结构稀缺。ACC 抓住智能体轨迹中天然存在的多轮依赖，通过编译机制将过程性证据转化为静态训练数据，解决了监督盲点问题。实验证明其在 GraphWalks 上达到 77.51，超越复杂 RL 方法，但在 MRCR 上仅 68.28，落后于 QwenLong-L1.5。边界在于仅验证三类智能体与单一模型规模，且随机排列可能破坏时序逻辑。当轨迹长度扩展至百万 token 时，编译上下文的计算开销与证据定位精度是否仍能保持平衡，论文未给出回答。
