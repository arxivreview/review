# HuggingFace最新推荐论文 ｜Qianfan-OCR: A Unified End-to-End Model for Document Intelligence ｜统一端到端文档智能模型

论文原文见 [arXiv](https://arxiv.org/abs/2603.13398)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.13398)

> 文档信息抽取（DIE）旨在从非结构化像素中还原结构化数据，但传统多阶段管道存在误差累积与视觉上下文丢失，而通用视觉语言模型（VLM）在结构化解析上精度不足。Qianfan-OCR 通过单一 4B 参数架构统一解析、布局分析与理解，并引入可选的 Layout-as-Thought 机制在生成前显式输出布局先验。该设计在端到端模型中实现了 OmniDocBench v1.5 的 SOTA 性能，但其在简单文档上的性能回退及对其他任务泛化性的缺失，暴露了“思维链”式布局推理的适用边界。

## 研究背景

文档解析的核心困境在于空间结构与语义内容的耦合。传统 OCR 管道将布局检测与文本识别解耦，虽具备模块化优势，但中间阶段的文本提取会不可逆地丢弃图表结构、空间关系等视觉上下文，导致下游理解任务（如图表问答）性能崩塌。为保留完整视觉信息，端到端 VLM 直接映射图像至 Markdown，消除了级联误差，却丧失了显式布局分析能力——用户无法获取边界框与元素类型，这在需要精确定位或结构校验的场景中成为功能缺口。

该领域正从“通用识别”向“垂直领域高精度抽取”过渡，核心矛盾是生成式模型的灵活性需求与结构化数据零容错要求之间的冲突。主流端到端方法（如 Logics-Parsing）依赖强化学习（RL）优化结构一致性，但奖励函数设计缺乏统一标准，且主要聚焦于识别精度或效率，未解决布局分析输出的缺失问题。Qianfan-OCR 的切入点在于：不改变端到端架构，而是将布局分析内化为模型内部的“思维”步骤，通过监督微调（SFT）而非 RL 实现结构先验的注入，试图在保持端到端高效性的同时，复现管道系统的布局分析功能。

## 核心方法

### 方法参照系

本文问题归属于端到端文档解析路线，其标准流程为：视觉编码器提取特征 → 跨模态适配器对齐 → 语言模型自回归生成结构化文本。与通用 VLM 的关键差异在于，本文需在单一模型内同时支持“纯文本生成”与“显式布局分析”两种模式，且后者需在不增加独立检测模块的前提下实现。

### 架构与数据合成

设计动机：解决端到端模型缺乏细粒度布局控制及多语言/复杂表格数据稀缺的问题。视觉编码器采用 Qianfan-ViT，支持 4K 分辨率动态分块（448×448 patches），每块生成 256 个视觉 token，最大支持 4,096 个 token 以覆盖密集文本。语言骨干为 Qwen3-4B，采用分组查询注意力（GQA）降低 KV 缓存内存。跨模态适配器为两层 MLP，将 1024 维视觉特征投影至 2560 维语言嵌入空间。数据合成方面，构建了 6 条流水线，其中文档解析数据采用 PaddleOCR-VL 生成 25 类细粒度布局标签（如区分 `abstract` 与 `content`），并通过 OTSL 中间格式转换表格为 HTML。多语言数据采用“反向合成”策略，从 HPLT 语料渲染图像，覆盖 192 种语言。

### Layout-as-Thought 机制

设计动机：弥补端到端模型无法输出显式布局结果的功能缺口，并解决复杂布局下的识别歧义。该机制通过 `<think>` 触发词激活可选的思维阶段，模型在生成最终 Markdown 前，先输出包含边界框、元素类型和阅读顺序的结构化布局表示。其数学形式可视为在生成序列 $y$ 前插入中间布局序列 $z$，即：

$$ P(y|x) \approx P(y|z, x) \cdot P(z|x) $$

其中 $x$ 为输入图像，$z$ 为布局先验。这一设计将布局分析从“独立模块”转化为“推理步骤”，使得模型在生成内容前能聚焦于相关文档区域。对于结构简单的文档，该阶段可被跳过；对于复杂多栏或混排文档，显式的结构先验有助于消解空间歧义。

## 实验评估

实验基于 OmniDocBench v1.5、OlmOCR Bench 及多个 KIE 基准，对比了 Pipeline 系统（PaddleOCR-VL, MinerU2.5）与端到端模型（DeepSeek-OCR, Gemini-3 Pro）。基线覆盖全面，但缺失对最新 RL 增强模型（如 Logics-Parsing）的直接对比，可能低估了 RL 在结构一致性上的优势。

| 基准 | 指标 | Qianfan-OCR | PaddleOCR-VL | DeepSeek-OCR-v2 | Qwen3-VL-4B |
| :--- | :--- | :--- | :--- | :--- | :--- |
| OmniDocBench v1.5 | Overall | 93.12 | 94.50 | 91.09 | - |
| OlmOCR Bench | Overall | 79.8 | 80.0 | - | - |
| OCRBench | Score | 880 | 549 | 620 | 873 |
| KIE (Mean) | Score | 87.9 | - | - | 83.5 |

Qianfan-OCR 在端到端模型中取得 OmniDocBench v1.5 最高分 93.12，超越 DeepSeek-OCR-v2（91.09），但低于最佳 Pipeline 系统 PaddleOCR-VL（94.50）。在 KIE 任务上，其 87.9 的平均分显著高于同规模 Qwen3-VL-4B（83.5）及更大规模的 Qwen3-VL-235B（84.2），表明 4B 模型在结构化抽取上的效率优势。

消融实验显示，四阶段训练（Adapter → General Pretrain → OCR+General Mix → Instruction Tuning）至关重要。跳过 Stage 2（通用预训练）直接进行领域微调，性能从 84.39% 降至 80.07%，证明大规模通用预训练提供了不可替代的能力基础。此外，Stage 3 中 OCR 与通用数据 1:1 混合优于纯 OCR 数据，表明通用数据作为正则化器防止了过拟合。

评估边界方面，Layout-as-Thought 仅在 OmniDocBench 上验证，其在 KIE 或图表理解中的有效性未知。推理吞吐量在单卡 A100 上达到 1.024 PPS（W8A8 量化），与 PaddleOCR-VL（1.224 PPS）相当，但代码开源状态及完整超参数细节需进一步确认。

## 关联研究分析

从方法设计看，Qianfan-OCR 与 Logics-Parsing 形成鲜明对比。Logics-Parsing 采用 SFT-then-RL 范式，通过全局奖励优化阅读顺序，旨在解决自回归监督在结构学习上的信号不足；而 Qianfan-OCR 坚持 SFT 路线，通过 Layout-as-Thought 将布局分析显式化。这种差异源于任务目标的不同：Logics-Parsing 聚焦于长文档的全局结构一致性，而 Qianfan-OCR 更关注布局分析的功能恢复与垂直领域 KIE 的精度。Qianfan-OCR 未采用 RL，可能牺牲了复杂结构下的极致一致性，但换取了训练稳定性与部署简洁性。

从问题动机看，Qianfan-OCR 与 PaddleOCR-VL 等 Pipeline 系统的核心差异在于“视觉上下文的保留”。Pipeline 系统在文本提取阶段丢弃了图表的空间结构，导致其在 CharXiv 等图表问答任务上得分归零（0.0），而 Qianfan-OCR 作为端到端模型，保留了完整视觉信息，在 CharXiv_DQ 上取得 94.0 分。这一结果证实了端到端架构在需要空间推理的任务上的不可替代性，但也暴露了其在纯文本密集任务上可能因“过度推理”导致的性能波动。

## 总结

Qianfan-OCR 试图解决端到端文档解析中“布局分析功能缺失”与“视觉上下文丢失”的双重矛盾。其切入点在于将布局分析内化为模型内部的思维步骤，而非独立模块，从而在单一 4B 参数模型中统一了解析、定位与理解。实验证明，该模型在 OmniDocBench v1.5 上取得 93.12 分，超越所有端到端基线，并在 KIE 任务上以 87.9 分显著优于同规模通用 VLM。然而，其边界在于 Layout-as-Thought 在简单文档上导致性能回退（92.64 vs 93.12），且该机制在其他任务上的泛化性未经验证。当文档布局熵值较低时，显式布局推理是否仍能提供正向增益，还是仅引入不必要的计算开销，论文未给出系统性回答。
