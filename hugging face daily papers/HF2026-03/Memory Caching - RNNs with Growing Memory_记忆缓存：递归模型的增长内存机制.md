# HuggingFace最新推荐论文 ｜Memory Caching: RNNs with Growing Memory ｜记忆缓存：递归模型的增长内存机制

作者：Ali Behrouz、Zeman Li、Yuan Deng 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.24281)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.24281)

> 长上下文建模的核心矛盾在于递归模型固定状态导致的检索失效与Transformer二次方计算成本。现有混合架构通过引入全注意力层解决检索问题，但牺牲了递归模型的线性复杂度优势。本文提出记忆缓存（Memory Caching, MC），通过分段缓存递归状态实现内存随序列长度增长，在保持递归更新效率的同时恢复长程检索能力。实验表明MC显著提升了递归模型在长上下文任务上的表现，但其绝对性能仍低于全注意力基线，且缺乏与主流混合架构的直接对比。

## 研究背景

递归神经网络（RNN）通过固定大小的隐藏状态压缩历史序列，实现了 $O(L)$ 的计算复杂度，但这一机制导致信息在长序列中发生不可逆的遗忘。当序列长度超出状态容量时，模型无法精确检索远距离信息，这在需要精确回忆的长上下文任务中表现为性能崩塌。为突破这一瓶颈，线性注意力（Linear Attention）通过核函数近似将注意力转化为递归形式，但固定状态的根本限制依然存在。

长上下文领域的研究重心已从单纯的复杂度降低转向效率与检索精度的平衡。主流路线包括混合架构（如Jamba、MiniCPM-SALA），通过交错全注意力层与递归层来保留检索能力，但全注意力层的 $O(L^2)$ 开销限制了其扩展性。另一路线是测试时训练（TTT）和稀疏状态更新，试图在递归内部解决遗忘问题，但计算开销大或稳定性不足。本文的切入点在于，递归模型的“遗忘”并非算法缺陷，而是固定状态容量的物理限制，通过缓存历史状态检查点，可以在不改变递归更新规则的前提下，让模型的有效内存随序列长度线性增长。

## 核心方法

### 递归状态缓存框架

本文方法建立在嵌套学习视角之上，将递归更新视为在线优化过程，记忆状态即优化检查点。标准递归模型仅使用当前状态 $M_t$ 计算输出，导致历史信息被压缩丢失。本文引入分段机制，将序列划分为 $N$ 个段，每段结束时缓存其记忆状态 $M^{[i]}_{L[i]}$。输出计算不再仅依赖当前状态，而是聚合所有历史段的缓存状态与当前在线状态，从而实现对完整历史的直接访问。

### 门控残差记忆与稀疏选择

基础残差记忆通过求和聚合缓存状态，但对于线性记忆模块会退化为固定状态。为解决此问题，本文提出门控残差记忆（Gated Residual Memory, GRM），引入输入依赖的门控参数 $\gamma^{[i]}_t$ 调节各段贡献：

$$ y_t = M_t(\mathbf{q}_t) + \sum_{i=1}^{s} \gamma^{[i]}_t M^{[i]}_{L[i]}(\mathbf{q}_t) $$

其中 $\gamma^{[i]}_t$ 由当前输入 $\mathbf{x}_t$ 与第 $i$ 段上下文的相似度决定，实现了内容感知的选择性检索。对于超长序列，本文进一步提出稀疏选择缓存（Sparse Selective Caching, SSC），借鉴混合专家（MoE）路由机制，仅选择 $k$ 个最相关的缓存状态进行聚合：

$$ R_t = \text{arg Top-}k(\{ \mathbf{r}^{[i]}_t \}_{i=1}^{s-1}) $$

SSC通过预计算段上下文均值，使路由过程可并行化，且无需在加速器中存储所有缓存状态，仅加载被选中的状态，显著降低了内存带宽压力。

## 实验评估

实验在760M和1.3B参数模型上进行，训练数据为FineWeb与Long-DataCollections混合，上下文长度覆盖4K至32K。基线包括Transformer、DLA、Titans、SWLA等递归模型，但缺失Jamba、Mamba2等主流混合架构基线，限制了与SOTA方法的直接对比。

| 模型 | WikiText PPL↓ | LMB PPL↓ | 平均准确率↑ |
| :--- | :--- | :--- | :--- |
| Transformer (1.3B) | 17.92 | 42.6 | 53.19 |
| Titans (LMM) + GRM (1.3B) | 15.37 | 50.4 | 58.33 |
| DLA + GRM (1.3B) | 16.08 | 45.8 | 55.96 |
| SWLA + GRM (1.3B) | 18.51 | 40.6 | 54.60 |

在1.3B参数规模下，Titans+GRM在WikiText困惑度（15.37）和平均准确率（58.33）上均优于Transformer（17.92, 53.19），表明MC在语言建模和常识推理任务上有效。在Needle-in-a-Haystack（NIAH）任务中，Titans+GRM在16K长度下的S-NIAH-2准确率为88.2，高于Transformer的79.8，显示MC在长程检索上具有竞争力。

消融实验显示，移除上下文依赖门控导致检索准确率从40.5降至33.0（Titans），移除门控机制进一步降至32.4，表明内容感知门控是MC有效性的关键。共享 $u$ 和 $q$ 参数导致模型完全失效（准确率00.0），验证了独立参数化对记忆区分度的必要性。

评估边界方面，论文未报告置信区间，且NIAH超越Transformer的结果可能受基线优化程度影响（如未使用FlashAttention）。代码未公开，超参数（如段长度、Top-k值）的敏感性分析缺失，限制了可复现性。

## 关联研究分析

从问题动机看，MC与Factorization Memory（FM）均针对递归模型遗忘问题，但FM通过稀疏更新固定数量的记忆状态来扩展容量，而MC通过缓存所有段状态实现内存增长。FM的计算复杂度仍为 $O(L)$，但内存占用恒定；MC的内存占用随 $N$ 线性增长，换取了更完整的检索能力。这一差异源于对“遗忘”根源的不同假设：FM认为遗忘源于状态更新干扰，MC认为源于状态容量不足。

从方法设计看，MC的SSC变体与NSA（Native Sparse Attention）的动态稀疏路由思想相似，但NSA选择的是Token级注意力头，MC选择的是段级记忆状态。NSA的稀疏性作用于计算密度，MC的稀疏性作用于内存访问。MC的段级选择粒度更粗，路由开销更低，但可能损失段内细粒度的检索精度。这种粒度差异是否影响在极长序列（如128K+）上的性能，论文未给出回答。

## 总结

本文针对递归模型固定状态导致的长程检索失效，提出记忆缓存（MC）技术，通过分段缓存状态实现内存随序列长度增长，在保持递归更新效率的同时恢复检索能力。实验表明，MC在1.3B参数模型上将Titans的WikiText困惑度从15.60降至15.37，NIAH 16K准确率从75.4提升至88.2，显著优于基线递归模型。然而，MC的绝对性能仍低于全注意力Transformer，且缺乏与Jamba等主流混合架构的直接对比，其“纯递归+缓存”路线在工业部署中的竞争力存疑。当段长度 $N$ 增大到接近序列长度 $L$ 时，MC的内存开销是否逼近全注意力，论文未给出回答。
