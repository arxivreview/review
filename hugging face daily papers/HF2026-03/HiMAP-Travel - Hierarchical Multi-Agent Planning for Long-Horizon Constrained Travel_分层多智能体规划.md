> 长程工具调用任务中，LLM 因上下文累积导致全局硬约束注意力稀释，现有“生成-修复”范式存在延迟与精度双重瓶颈。本文通过战略-战术解耦与并行执行，将约束执行从事后验证前移至构造阶段。核心机制为同步全局状态监控、合作议价协议及统一角色条件策略。该架构在 TravelPlanner 上刷新 SOTA，但仅符号化资源冲突，语义约束仍依赖 LLM 自身，泛化边界尚存疑。

## 研究背景

长程规划任务要求智能体在满足预算、时间等硬约束的同时优化用户偏好。当规划跨度超过数天，中间工具输出与推理轨迹在上下文窗口中不断累积，导致模型对初始全局约束（如总预算）的注意力显著下降，这一现象被定义为“长工具轨迹下的约束漂移”（Constraint Drift under Long Tool Traces）。漂移使得顺序生成器在后期步骤中频繁违反早期设定的边界，且错误具有级联效应，一旦第一天超支，后续行程往往无法挽回。

主流缓解策略如 ATLAS 采用“验证-修复”循环，即生成完整计划后再由约束管理器检查并修正。这种事后纠正机制存在两个致命缺陷：一是计算延迟随计划长度呈超线性增长，7 天行程需完全生成后才能发现第一天错误；二是修复过程依赖自然语言对话，效率低且易引入新错误。HiMAP-Travel 的切入点在于将约束执行从“事后修复”转变为“构造时正确”（correct-by-construction），通过分层架构将全局约束分解为局部边界条件，并在并行执行中通过确定性机制实时拦截冲突，从而在保持语义灵活性的同时消除逻辑幻觉。

## 核心方法

### 方法参照系

本文问题属于分层强化学习（HRL）在 LLM 规划中的应用，但与传统 HRL 不同，其核心挑战并非状态空间维数灾难，而是 LLM 上下文窗口中的注意力稀释。通用流程为高层策略设定子目标，低层策略执行动作，但本文需解决并行执行下的耦合约束一致性与稀疏奖励下的信用分配问题。

### 同步全局状态与事务性监控

传统多智能体系统依赖自然语言通信协调资源，易产生竞态条件。HiMAP-Travel 引入同步全局状态 $\Sigma = \langle B_{used}, V_{committed}, M_{trans} \rangle$，作为确定性事务监控器。其核心公式为原子提交操作：

$$
\text{COMMIT}(a) = \begin{cases} \Sigma \leftarrow \Sigma' & \text{if } I(\Sigma') \text{ holds} \\ \text{Reject}(a) & \text{otherwise} \end{cases}
$$

该机制通过全局可重入互斥锁保护状态，确保预算守恒与非重复性约束在动作执行前被原子性验证。设计动机在于解决并行执行中“公地悲剧”问题，即独立规划器可能同时超支或重复预订。通过拦截非法动作并返回类型化错误，系统实现了冲突的预防而非事后修复，将有效上下文长度从 $O(T)$ 降至 $O(T/D)$。

### 合作议价协议与统一策略优化

严格的自上而下层级在子目标不可行时易失效。本文引入合作议价协议，执行器通过结构化 JSON 信号（状态、缺口、违规类型）拒绝不可行分配，触发协调器重规划。为优化多智能体信用分配，采用组相对策略优化（GRPO）训练统一角色条件策略 $\pi_\theta$。优势函数计算为：

$$
A_i = \frac{R(\tau_i) - \mu_G}{\sigma_G + \epsilon}
$$

其中 $\mu_G, \sigma_G$ 为组内奖励均值与标准差。设计动机在于解决稀疏奖励下多智能体梯度更新不稳定问题。通过共享参数并基于角色提示条件化，战术执行中习得的推理能力可迁移至战略分配，同时 FIFO 更新机制将峰值内存降低 $D+1$ 倍，实现高效并行训练。

## 实验评估

实验在 TravelPlanner（1000 测试查询）与 FlexTravelBench 上进行，基线覆盖 ReAct、ATLAS、MTP 及受控对比的 DeepTravel。缺失 PDDL 形式化基线（如 LLM+P），但鉴于任务特性，工具调用范式更贴合实际部署场景。

| 方法 | 模型 | Test FPR (%) | 延迟倍数 |
| :--- | :--- | :--- | :--- |
| ATLAS | Gemini-2.5-Pro | 35.00 | — |
| DeepTravel (Controlled) | Qwen3-8B | 43.98 | 1.0 |
| HiMAP-Travel | Qwen3-8B | 52.65 | 0.4 |

HiMAP-Travel 在相同骨干模型与工具条件下，较 DeepTravel 提升 8.67 pp，较 ATLAS 提升 17.65 pp，且延迟降低 2.5 倍。消融实验显示，移除同步监控导致 FPR 下降 9.58 pp，多样性违规率从 8% 飙升至 34%；移除协调器导致预算失败激增，FPR 下降 12.98 pp。这表明同步监控对资源冲突预防至关重要，而协调器对全局预算分配起主导作用。议价协议移除仅导致 3.88 pp 下降，说明其作为兜底机制而非主要性能来源。

评估边界方面，FPR 仅衡量硬约束满足，未评估软偏好优化程度；FlexTravelBench 多轮场景成功率（44.34%）显著低于单轮，表明动态约束适应仍是瓶颈。代码未公开，但超参数（G=4, β=0.01）与训练细节（100 epochs, 45 queries）已披露，可复现性中等。

## 关联研究分析

从问题动机看，HiMAP-Travel 与 ATLAS 均针对长程约束漂移，但 ATLAS 依赖事后验证，其 Constraint Manager 需处理完整计划文本，导致延迟随长度平方增长。HiMAP-Travel 通过并行分解将延迟线性化，但代价是引入了同步开销。根源在于任务特性：TravelPlanner 的约束多为资源型（预算、地点），适合原子化监控；若约束涉及复杂语义因果（如“先参观博物馆再吃饭”），同步状态 $\Sigma$ 无法表达，仍需 LLM 推理，此时 ATLAS 的全局验证可能更鲁棒。

从方法设计看，HiMAP-Travel 与 Planner-R1 同属 RL 优化路线，但 Planner-R1 侧重奖励塑造以提升小模型规划能力，未改变顺序生成架构。HiMAP-Travel 则通过架构解耦解决上下文稀释，其 GRPO 训练仅用于策略优化，而非能力涌现。差异根源在于：Planner-R1 假设 LLM 具备潜在规划能力，仅需激励；HiMAP-Travel 假设 LLM 在长程中不可靠，需外部结构补偿。若 LLM 规模进一步扩大，上下文窗口扩展至百万 token，HiMAP-Travel 的并行分解收益是否仍显著，论文未给出回答。

## 总结

HiMAP-Travel 针对长程工具调用中的约束漂移问题，通过战略-战术解耦与同步全局状态监控，将约束执行从事后修复前移至构造阶段。该架构在 TravelPlanner 上实现 52.65% FPR 与 2.5 倍延迟降低，证明分层并行与确定性监控的有效性。然而，其同步状态仅处理资源冲突，路由可行性与时间因果性仍依赖 LLM 自身推理，未完全形式化。当约束类型从资源型扩展至语义因果型时，同步监控的覆盖范围是否足够，以及 LLM 在并行执行中是否会产生新的局部幻觉，论文未提供实验证据。
