研究机构：瑞士苏黎世大学、北京大学

作者：Jingwei Ni、Yihao Liu、Xinpeng Liu 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.25158)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.25158)

> 代理技能进化旨在通过外部程序性记忆提升大语言模型（LLM）代理的长程任务执行能力，但现有在线顺序更新范式易导致技能碎片化与过拟合。Trace2Skill 提出一种离线并行蒸馏框架，模拟人类专家“先积累后撰写”的认知模式，通过多智能体并行分析轨迹池并层级合并补丁，生成单一综合技能。该框架无需修改模型权重或依赖外部检索模块，实现了跨模型规模与分布外（Out-of-Distribution, OOD）任务域的技能迁移。其核心价值在于验证了经验可被蒸馏为可转移的声明式技能，但单一文档架构在技能库规模扩大时的可扩展性仍存疑。

## 研究背景

当 LLM 代理执行复杂多步任务时，静态参数化知识缺乏对特定领域陷阱的感知，导致执行失败。为解决此问题，代理技能（Agent Skill）作为结构化、可复用的文档被引入，编码任务求解程序与操作指南。然而，人工编写技能存在严重的可扩展性瓶颈，且自动生成的技能往往依赖浅层参数化知识或顺序过拟合于非泛化的轨迹局部教训，导致技能库膨胀与检索困难。

现有技能进化主流路线采用在线顺序更新机制，即代理持续与环境交互，基于新到达的轨迹逐步编辑技能库。这种范式模拟了作者在学习过程中即时修改文档的场景，但存在两个关键缺陷：一是技能碎片化，为容纳轨迹局部教训而创建大量狭窄技能，加剧检索难度；二是顺序更新导致经验碎片化，代理在缺乏充分领域理解前过早反应，难以形成高层抽象。Trace2Skill 的切入点在于重构技能进化的时序逻辑，将“流式编辑”转变为“批量归纳”，通过并行分析大量轨迹挖掘普遍模式，从根源上解决技能过拟合与碎片化问题。

## 核心方法

### 技能进化问题形式化

本文问题属于技能生成与蒸馏路线，但区别于标准在线进化流程。其核心差异在于将技能进化建模为离线批量优化问题，而非流式更新。给定冻结代理 $\pi_\theta$、初始技能 $S_0$ 及进化集 $\mathcal{D}_{evolve}$，目标是在不更新 $\theta$ 的前提下，从轨迹中构建改进技能 $S^*$，最大化测试集 $\mathcal{D}_{test}$ 上的成功率：

$$ \max_{S^*} \mathbb{E}_{t \sim \mathcal{D}_{test}} [\mathbb{1}(\pi_\theta(t, S^*) = y_t^*)] $$

该公式表明技能进化是纯外部记忆优化过程，解耦了模型参数与任务知识。

### 并行多智能体补丁提案

设计动机在于解决顺序更新中“单轨迹偏见”导致的技能特异性过强问题。Stage 2 部署并行分析师子代理，每个子代理独立处理单条轨迹 $\tau_i$，基于冻结的 $S_0$ 提出技能补丁 $p_i$。错误分析师（Error Analyst）采用 ReAct 多轮循环，通过检查输入输出文件与地面真值对比，迭代定位失败根因，确保补丁基于已验证的因果分析；成功分析师（Success Analyst）则采用单次调用提取可泛化行为模式。所有补丁构成池 $\mathcal{P} = \{p_i\}$，无顺序依赖，保留轨迹观察的完整多样性。

### 冲突自由层级合并

设计动机在于将轨迹局部教训归纳为领域级通用程序，同时消除补丁间冲突。Stage 3 将 $\mathcal{P}$ 层级合并为单一更新 $p^*$，合并算子 $M$ 执行归纳推理：

$$ p^* = M(\pi_\theta, S_0, \mathcal{P}) = \text{Induce}(\{p_i \mid \text{Prevalent}(p_i)\}) \setminus \text{Conflict}(\mathcal{P}) $$

其中 $\text{Prevalent}(p_i)$ 标识在多个独立补丁中重复出现的编辑，$\text{Conflict}(\mathcal{P})$ 通过程序化检测剔除引用不存在文件或同一行范围冲突的编辑。该机制丢弃孤立补丁（视为特例），保留普遍模式（视为系统性任务属性），实现从具体经验到抽象 SOP 的压缩。

## 实验评估

实验在 SpreadsheetBench-Verified（400 样本，200 进化/200 测试）及 OOD 基准 WikiTableQuestions 上进行，基线包括 No Skill、Human-Written 及 Parametric。主结果以 Delta 形式呈现，Avg 指标均权内分布与 OOD 性能。

| 条件 | Skill User: 122B (Vrf/Soft/Hard/WikiTQ) | Skill User: 35B (Vrf/Soft/Hard/WikiTQ) | Avg |
| :--- | :--- | :--- | :--- |
| No Skill | 27.67 / 36.30 / 17.03 / 21.50 | 19.00 / 26.17 / 9.67 / 13.33 | - |
| Human-Written | 48.33 / 36.60 / 17.50 / 74.68 | 36.30 / 26.17 / 17.50 / 23.73 | - |
| 122B-Authored +Combined | +21.50 / +10.87 / +12.50 / +1.62 | +27.00 / +9.44 / +2.86 / +4.56 | +17.62 |
| 35B-Authored +Error | +16.67 / +8.50 / +8.14 / -6.36 | +57.65 / +3.83 / +7.30 / +9.09 | +18.26 |

35B-Authored +Error 在 Avg 上达 +18.26 pp，其中 WikiTQ 增益 +57.65 pp，表明小模型蒸馏的技能可显著提升大模型 OOD 性能。消融实验显示，并行合并优于顺序编辑（Seq-B=1），122B 模型 Vrf 提升 +4.0 pp，且计算成本降低 20 倍。+Combined 比 ReasoningBank 高 +13.8 pp Vrf，证明单一综合技能无需检索即可超越检索式经验库。

评估边界方面，实验仅覆盖表格、数学与视觉问答三个领域，未验证代码生成或网络安全等动态环境。代码未开源，但提供了 vLLM 部署配置与种子（41, 42, 43），可复现性中等。指标完备性上，Avg 指标有效捕捉泛化性，但缺乏对技能文档长度与推理延迟的量化分析。

## 关联研究分析

从方法设计看，Trace2Skill 与 SkillOpt 形成鲜明对比。SkillOpt 采用在线验证门控，通过有界编辑操作迭代优化技能，依赖验证集反馈防止过拟合；而 Trace2Skill 采用离线批量归纳，通过普遍模式挖掘实现泛化。差异根源在于对“经验利用”的理解：SkillOpt 视经验为局部信号，需即时修正；Trace2Skill 视经验为分布样本，需全局统计。前者在确定性任务中更稳定，后者在 OOD 迁移中更具优势，但 Trace2Skill 缺乏对最新轨迹的实时响应能力，这在动态环境部署中可能是盲区。

从问题动机看，Trace2Skill 与 ReasoningBank 代表两种经验管理范式。ReasoningBank 保存轨迹级教训并通过相似度检索复用，保留细粒度信息但引入检索瓶颈；Trace2Skill 将教训蒸馏为单一 SOP，消除检索开销但丢失个体差异。论文未探索当技能库规模扩大至数千时，单一文档是否仍能有效承载所有领域知识，还是必然退化为“臃肿文档”导致注意力分散。这一可扩展性边界在现有实验中未得到验证。

## 总结

Trace2Skill 要解决的核心矛盾是技能进化中“局部过拟合”与“全局泛化”的冲突。现有在线顺序更新方法因缺乏全局视野而难以形成抽象 SOP，本文通过并行多智能体分析与层级归纳合并，将轨迹局部教训压缩为普遍模式，实现了跨模型与 OOD 任务域的技能迁移。实验证明 35B 模型蒸馏的技能可使 122B 代理在 WikiTQ 上提升 57.65 pp，且并行合并比顺序编辑更高效。然而，单一综合技能架构在技能库规模扩大时的可扩展性未经验证，当领域知识复杂度超过单一文档承载能力时，层级归纳机制是否仍能维持泛化优势，论文未给出回答。
