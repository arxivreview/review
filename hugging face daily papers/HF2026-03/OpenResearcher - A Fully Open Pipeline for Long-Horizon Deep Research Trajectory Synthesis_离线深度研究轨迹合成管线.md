作者：Zhuofeng Li、Dongfu Jiang、Xueguang Ma 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.20278)

> 深度研究智能体训练依赖高质量长程轨迹，但现有在线合成管线成本高、不可复现且难以分析。OpenResearcher 通过一次性在线引导构建离线语料库，将搜索-浏览循环完全移至本地环境，利用三个显式浏览原语生成可复现的长程轨迹。该方法以纯监督微调（SFT）替代强化学习（RL），在长程推理基准上取得显著增益，但其泛化边界与离线语料分布偏差仍存疑。

## 研究背景

当智能体执行多跳推理任务时，其决策路径长度往往远超单次上下文窗口限制，导致早期关键证据丢失，这一现象称为执行漂移。执行漂移使得智能体在长程任务中难以维持目标一致性，而解决该问题的关键在于提供包含完整推理链的高质量训练数据。然而，现有数据合成管线依赖实时网络 API，每次失败搜索路径均产生成本，且网络环境的不稳定性使同一管线难以复现，更无法对内部检索事件进行受控分析。

深度研究智能体的训练瓶颈不仅在于模型容量，更在于高保真长程轨迹的稀缺性。主流路线如 Search-R1 仅生成 2-5 轮交互轨迹，远不足以覆盖真实深度研究场景；WebExplorer 等系统虽能生成长轨迹，但依赖在线 API 导致成本高昂且不可复现。OpenResearcher 的切入点在于解耦语料构建与轨迹生成：通过一次性在线引导获取金标文档，构建离线语料库，随后在本地环境中运行多轮合成循环，从而在保留网络噪声特性的同时实现低成本、可复现的轨迹合成。

## 核心方法

### 方法参照系

本文问题属于深度研究智能体数据合成范畴，与标准 ReAct 范式交互循环一致，但关键差异在于将在线搜索 API 替换为离线 FAISS 检索引擎，并引入显式浏览原语以支持多尺度证据定位。

### 离线语料构建与金标引导

设计动机：解决在线合成中“证据缺失”与“策略失败”的混淆问题，确保轨迹失败仅反映搜索策略缺陷而非语料覆盖不足。本文通过一次性在线引导，将问题与参考答案拼接作为查询，经 Serper API 检索并清洗后，为 6K 问题获取 10K 金标文档。这些文档与 15M FineWeb 文档合并形成离线语料库，其中 FineWeb 文档充当干扰项，金标文档提供答案支持证据。语料库通过 Qwen3-Embedding-8B 嵌入并建立 FAISS 索引，模拟真实网络搜索的噪声与歧义性。

### 显式浏览原语与轨迹生成

设计动机：解决传统搜索抽象无法支持迭代证据聚合与长程推理的问题，使智能体学习不仅“检索什么”，还“如何检查文档并定位证据”。本文定义三个最小浏览原语：Search 返回查询的 Top-K 结果（标题、URL、摘要）；Open 获取文档全文；Find 在当前打开文档中定位精确字符串匹配。这些原语逐步缩小智能体关注范围，从语料库到文档再到具体证据。轨迹生成过程中，教师模型 GPT-OSS-120B 仅使用这三个工具，逐步推理并在确信答案时终止，且无法访问参考答案。过滤后获得 97K+ 轨迹，其中大量轨迹包含 100+ 工具调用，覆盖广泛推理跨度。

$$
H_T = \{(r_i, a_i, o_i)\}_{i=1}^{T-1}, a_T
$$

该公式表示轨迹 $H_T$ 由 $T-1$ 个推理-行动-观察三元组及最终答案 $a_T$ 组成，其中 $r_i$ 为思维链，$a_i$ 为工具调用，$o_i$ 为环境观察。

$$
P(\text{correct} \mid \text{open-hit}) = 86.72\%
$$

该条件概率表明，当智能体成功打开金标文档时，最终答案正确的概率高达 86.72%，揭示证据暴露与答案正确性的强关联。

## 实验评估

实验在 BrowseComp-Plus（离线）及 BrowseComp、GAIA、xbench-DeepSearch（在线）上评估，基线涵盖闭源模型（GPT-4.1、Claude-4-Opus）及开源深度研究智能体（ASearcher、WebDancer）。主实验显示，OpenResearcher-30B-A3B 在 BrowseComp-Plus 上取得 54.8% 准确率，较基础模型 Nemotron-3-Nano-30B-A3B 提升 34.0 个百分点，显著优于 GPT-4.1（36.4%）与 Claude-4-Opus（36.8%）。在在线基准上，其 GAIA 准确率为 64.1%，高于 ASearcher-QwQ-32B（52.8%）与 WebDancer-QwQ-32B（51.5%），但 BrowseComp 准确率为 26.3%，低于 Fathom-DeepResearch 的 42.98%（据领域综述）。

| 方法 | BrowseComp-Plus | GAIA | BrowseComp |
| :--- | :--- | :--- | :--- |
| GPT-4.1 | 36.4 | — | — |
| Claude-4-Opus | 36.8 | — | — |
| ASearcher-QwQ-32B | — | 52.8 | 5.2 |
| WebDancer-QwQ-32B | — | 51.5 | 3.8 |
| OpenResearcher | 54.8 | 64.1 | 26.3 |

消融实验揭示关键设计决策：轨迹正确性并非 SFT 的必要过滤信号，仅用正确轨迹（54.81%）、仅用错误轨迹（55.06%）及混合轨迹（54.46%）在 BrowseComp-Plus 上准确率差异小于 0.6 个百分点。语料覆盖消融显示，移除金标文档导致金标命中率从 29.54% 降至 1.73%，轨迹准确率从 56.86% 降至 43.81%，下游 BrowseComp-Plus 准确率从 54.81% 崩至 6.35%，证明一次性在线引导是离线合成的硬性前提。工具消融表明，仅 Search 准确率为 43.86%，Search+Open 为 56.39%，三者全用为 62.17%，且工具调用次数与平均 token 数随工具增加而减少，表明显式证据定位提升效率。

评估边界：BrowseComp-Plus 使用固定语料库，可复现性高；在线基准依赖 Serper API，存在环境波动。训练在 8 块 H100 GPU 上运行 8 小时，学习率 $5 \times 10^{-5}$，上下文长度 256K，代码与模型已开源。未报告置信区间，且未对比 WebWeaver、ABSeeker 等最新 RL 方法，基线覆盖存在缺口。

## 关联研究分析

从问题动机看，OpenResearcher 与 Search-R1 均聚焦长程搜索智能体训练，但 Search-R1 依赖在线 RL 优化策略，而 OpenResearcher 通过离线 SFT 数据合成替代 RL，解决成本与复现问题。这一差异源于任务特性：Search-R1 针对短程多跳 QA（2-5 轮），而 OpenResearcher 针对长程深度研究（100+ 轮），后者对轨迹质量与长度的要求更高，使得离线合成更具优势。然而，离线语料分布与真实动态网络的差异是否导致泛化偏差，论文未给出回答。

从方法设计看，OpenResearcher 与 WebExplorer 同属深度研究智能体框架，但 WebExplorer 依赖在线 API 生成轨迹，而 OpenResearcher 引入显式浏览原语（search/open/find）与离线 FAISS 引擎，支持受控分析。这一设计使 OpenResearcher 能够追踪金标文档检索与打开事件，揭示证据暴露与答案正确性的条件概率关系，而 WebExplorer 因环境动态性无法实现此类细粒度分析。显式浏览原语的引入是否在其他任务（如多模态搜索）中同样有效，论文未探索。

## 总结

OpenResearcher 解决的核心矛盾是长程深度研究轨迹合成的高成本与不可复现性。其切入点在于解耦语料构建与轨迹生成，通过一次性在线引导构建离线语料库，使搜索-浏览循环完全本地化。该方法以纯 SFT 替代 RL，在 BrowseComp-Plus 上取得 54.8% 准确率，GAIA 上达 64.1%，证明离线合成数据的有效性。其边界在于 BrowseComp 准确率 26.3% 低于在线 SOTA，且未对比最新 RL 方法，表明离线语料在特定高难度导航任务上可能存在分布偏差。当离线语料库规模扩大至 100M 文档时，金标文档比例对模型泛化能力的影响机制，论文未给出回答。
