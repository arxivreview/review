> 长程分析任务要求模型在非规范表格上执行多步数据获取、计算与综合，而现有方法受限于静态文本推理的上下文瓶颈与单次执行中的错误累积。本文切入点在于将表格推理重构为闭环决策过程，通过解耦宏观规划与微观执行，利用历史执行反馈动态优化操作路径。具体做法是构建元图结构、引入期望感知选择策略及孪生结构化记忆模块。该框架在特定基准上显著提升了分析深度与可行性，但其对干净结构化表格的泛化能力及冷启动阶段的探索效率仍存疑。

## 研究背景

当大语言模型（LLM）处理包含合并单元格、双向层级表头及缺失值的真实世界表格时，传统的二维转一维序列化（2D-to-1D Serialization）会破坏行列邻接关系，导致模型无法准确解析单元格语义。这种结构丢失使得模型在涉及跨区域聚合或条件分支的长程任务中，难以维持中间状态的一致性，进而引发数值计算幻觉。为应对这一挑战，程序化思维（Program-of-Thought, PoT）通过生成可执行代码来替代纯文本推理，利用确定性计算引擎抑制幻觉，但静态代码生成缺乏从执行失败中学习的机制，面对复杂结构时易陷入无效重试循环。

表格问答领域已从单表事实检索演进至复杂层级推理，主流路线分为结构表示重构与推理机制增强两类。结构表示路线如 TABGR 和 TAMO 通过图或超图建模保留拓扑信息，但在处理动态分析任务时缺乏执行反馈机制；推理增强路线如 TableMind 和 Code Loop 引入智能体框架，但多依赖静态工具调用或盲目循环重试，未能有效利用历史执行经验优化路径选择。本文针对非规范表格上的长程多跳分析任务，提出 Deep Tabular Research (DTR) 范式，旨在通过持续的经验驱动执行，解决长程推理中的错误传播与搜索空间爆炸问题。

## 核心方法

### 方法参照系

DTR 属于智能体推理框架路线，其标准流程为“规划-执行-反思”。与 TableMind 等依赖知识蒸馏或静态工具调用的框架不同，DTR 的关键差异在于将规划过程建模为基于执行反馈的在线策略优化，而非一次性生成固定代码序列。

### 元图构建与操作映射

传统方法将表格线性化为文本，导致层级语义丢失。DTR 首先提取显式与隐式元数据，构建双向头部元图 $G_T = (V_T, E_T)$，其中节点代表表头或内容元素，边表示包含或层级关系。该图结构显式保留了行与列语义的交互，解决了线性化导致的结构扁平化问题。随后，LLM 代理基于查询子句与元图三元组，从种子操作库 $\mathcal{O} = \{CLEAN, FILTER, GROUP, AGG, ...\}$ 中筛选候选操作，并构建操作映射以编码依赖关系。此设计动机在于，通过结构化表示降低操作选择的歧义性，使模型能在明确的语义约束下组合原子操作，而非在原始文本中盲目搜索。

### 期望感知路径选择与孪生记忆

静态规划无法应对执行中的不确定性，DTR 引入期望感知选择策略，基于历史执行奖励动态调整路径优先级。对于候选路径 $\pi$，其期望得分定义为：

$$ E(\pi) = \hat{R}(\pi) + \alpha \sqrt{\frac{\ln N_{total}}{N(\pi)}} $$

其中 $\hat{R}(\pi)$ 为历史平均回报，$N(\pi)$ 为执行次数，$\alpha$ 控制探索与利用的平衡。该公式确保高回报路径被优先执行，同时保留对未充分探索路径的探索概率。此外，DTR 采用孪生结构化记忆，同步维护参数化执行反馈（如执行时间、类型一致性）与抽象经验文本（如“聚合前需清洗”）。参数化反馈用于即时更新路径期望值，抽象经验则跨实例迁移，指导操作插入或删除。这一机制解决了长程执行中错误累积的问题，使系统能从失败中提炼策略，避免重复无效操作。

## 实验评估

实验在 DTR-Bench 和 RealHitBench 上进行，基线涵盖表格专用 LLM（TableGPT2、StructGPT）、通用 LLM（DeepSeek-V3）及工作流框架（ST-Raptor、Code Loop）。值得注意的是，基线中未包含知识库中提到的 TABGR 或 TAMO 等结构表示 SOTA 方法，这可能影响对结构感知贡献的独立评估。

| 方法 | 准确率 (Win Rate) | 分析深度 (Win Rate) | 可行性 (Win Rate) | 美观度 (Win Rate) |
|---|---|---|---|---|
| DeepSeek-V3 | 1.21 | 21.72 | 20.60 | 31.23 |
| Code Loop | 1.32 | 9.40 | 14.81 | 20.42 |
| DTR (DS-v3) | 1.93 | 30.23 | 27.62 | 42.74 |

DTR 在各项指标上均显著优于基线，尤其在分析深度上比 DeepSeek-V3 高出 8.51 个点，表明其多步推理能力更强。消融实验显示，完整模型比基线提升 4.0 点准确率，其中查询分解贡献 +1.4 点，期望感知选择贡献 +0.9 点，抽象经验贡献 +0.4 点。这表明高层规划从历史经验中获益显著，而低层代码模拟的边际收益较小。

评估边界方面，论文未报告置信区间，且仅在非规范表格基准上验证，缺乏在 WikiTQ 等干净基准上的泛化测试。代码未公开，超参数 $\alpha$ 的敏感性分析缺失，可复现性受限。

## 关联研究分析

从问题动机看，DTR 与 TAMO 均试图解决 2D-to-1D 结构丢失，但 TAMO 侧重静态超图表示以保留高阶关系，而 DTR 侧重动态推理中的结构导航。TAMO 的超图编码计算复杂度较高，且未涉及执行反馈机制；DTR 的元图构建更轻量，但依赖 LLM 的推理能力来解析结构，可能在结构极度复杂时出现解析错误。这一差异源于任务特性：TAMO 针对静态问答，DTR 针对动态分析，后者需要实时适应执行状态。

从方法设计看，DTR 与 TableMind 同属智能体框架，但 TableMind 侧重通过知识蒸馏将专家推理轨迹转移到训练样本中，属于离线优化；DTR 则通过在线执行反馈更新策略，属于在线优化。TableMind 的蒸馏过程需要大量高质量标注数据，而 DTR 依赖执行环境的即时反馈，无需额外标注。然而，DTR 的在线优化在冷启动阶段（无历史数据）可能面临探索偏差，论文未详细讨论此阶段的性能表现。

## 总结

DTR 旨在解决非规范表格上长程分析任务的错误累积与搜索空间爆炸问题，其切入点在于将推理重构为基于执行经验的闭环决策过程。通过元图构建、期望感知选择及孪生记忆，DTR 在 DTR-Bench 上实现了 4.0 点的准确率提升，并显著改善了分析深度与可行性。然而，其实验仅在非规范表格基准上进行，未验证在干净结构化表格上的泛化能力，且冷启动阶段的探索效率未充分讨论。当支持集增大或表格结构趋于规范时，DTR 的在线优化机制是否仍能保持相对于静态结构表示方法的优势，论文未给出回答。
