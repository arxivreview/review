# HuggingFace最新推荐论文 ｜Agentic Code Reasoning ｜无执行代码语义推理中的半形式化证书

作者：Shubham Ugare、Satish Chandra

论文原文见 [arXiv](https://arxiv.org/abs/2603.01896)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.01896)

> 导读 该方向旨在解决LLM代理在不运行代码的前提下，如何准确判定复杂仓库中补丁的语义等价性或定位故障根源。现有非结构化推理易产生幻觉，而完全形式化验证因语义形式化成本过高难以落地，本文切入点在于引入“半形式化证书”模板，强制代理在自然语言层面构建显式前提与执行轨迹。通过结构化提示工程，该方法在补丁等价性验证上达到93%准确率，但在缺乏测试补丁或处理深层间接依赖时仍受限于代理的静态追踪能力。

## 研究背景

当代理面对跨文件的复杂代码库时，直接执行测试往往因环境依赖缺失或沙箱成本过高而不可行，这要求模型具备静态语义分析能力。这种能力依赖于对程序控制流与数据流的精确追踪，即代理必须在不运行代码的情况下，通过阅读源码推断函数调用链的最终行为。然而，LLM在自由推理模式下常出现“跳跃式”结论，即假设函数行为符合直觉而非实际定义，导致对补丁等价性的误判。

主流路线分为两类：一类是训练专用奖励模型（如SWE-RM）或使用LLM直接作为评判者（如CodeJudge），这些方法依赖非结构化推理，允许模型在无证据支持下做出断言；另一类是将代码翻译为Lean或Coq等正式语言进行自动证明，但这种方法要求形式化任意仓库的语言语义，在实际工程中不具备可扩展性。本文的切入点在于寻找中间路径：不训练新模型，也不要求完全形式化，而是通过提示工程强制代理遵循“前提-轨迹-结论”的证书结构，从而在自然语言层面实现逻辑严谨性。

## 核心方法

### 方法参照系

本文问题属于代理式代码理解范畴，通用流程为代理探索代码库并生成自然语言解释。与标准链式思维（Chain-of-Thought）的关键差异在于，标准流程允许模型自由组织推理步骤，而本文要求推理过程必须符合预定义的逻辑模板，将非结构化的“思考”转化为可审计的“证书”。

### 半形式化证书结构

标准推理允许代理跳过中间步骤直接给出结论，这导致在函数名遮蔽或复杂依赖场景下产生幻觉。本文在提示中嵌入结构化模板，强制代理在得出结论前必须填充所有括号字段。该模板的核心逻辑可形式化为：

$$
C = f(P, T, E)
$$

其中 $C$ 为最终结论（等价/不等价），$P$ 为显式前提（补丁修改内容），$T$ 为每个测试用例的执行轨迹（Execution Trace），$E$ 为从代码库中检索到的具体证据（如函数定义行号）。这一设计迫使代理在生成 $C$ 之前，必须完成对 $T$ 的枚举，从而将“猜测行为”转化为“追踪行为”。

### 跨过程追踪机制

仅定义模板不足以解决深层依赖问题，代理仍需主动探索代码库以获取 $E$。本文利用SWE-agent接口，允许代理执行bash命令（如grep）定位函数定义，但禁止执行测试代码。这种“只读探索”机制确保代理必须通过静态分析发现如Django中 `format` 函数被模块级定义遮蔽的情况。设计动机在于，非结构化推理中代理常假设 `format` 为Python内置函数，而半形式化模板要求代理为每个断言提供代码行号证据，从而暴露了假设与事实的偏差。

## 实验评估

实验在SWE-bench-Verified（170个精选补丁对）、Defects4J（故障定位）和RubberDuckBench（代码问答）上进行。基线包括单次调用、标准代理推理及difflib文本相似度。在补丁等价性验证中，Opus-4.5结合半形式化推理达到93.0%准确率，显著高于标准代理的87.0%和difflib的73%。

| 模型 | 模式 | 准确率 | 平均步数 |
| :--- | :--- | :--- | :--- |
| Opus-4.5 | Agentic (Standard) | 87.0% | 19.7 |
| Opus-4.5 | Agentic (Semi-formal) | 93.0% | 37.82 |
| Sonnet-4.5 | Agentic (Semi-formal) | 91.5% | 43.23 |

在故障定位任务中，半形式化推理在Top-5准确率上比标准推理提升5-12个百分点，但在处理间接依赖（Indirection bugs）时仍频繁失效。消融实验显示，半形式化推理的步数是标准推理的2.8倍，表明结构化验证以计算成本换取了准确性。

评估边界在于，补丁等价性实验依赖测试补丁作为Ground Truth，若缺乏明确测试定义，方法适用性受限。此外，论文未报告置信区间，且SWE-bench数据可能存在训练集污染，尽管相对对比受污染影响较小，但绝对数值需谨慎解读。代码未公开，复现需依赖附录中的完整提示模板。

## 关联研究分析

从问题动机看，本文与SWE-RM（Shum et al., 2025）均旨在提供无执行反馈，但SWE-RM通过训练奖励模型学习测试结果的分布，而本文通过结构化提示强制逻辑一致性。差异根源在于任务特性：SWE-RM适用于大规模RL训练中的快速奖励信号，而本文适用于需要高置信度、可解释性的代码审查场景。SWE-RM的“黑盒”奖励无法解释为何判定为等价，而本文的证书结构提供了可审计的推理路径，这是否意味着在需要合规审计的场景中，半形式化推理具有不可替代性？

从方法设计看，本文与AlphaVerus（Wilf et al., 2023）同属神经符号集成，但AlphaVerus依赖外部形式化验证器（Verus）作为真理裁判，而本文依赖代理内部的自证证书。AlphaVerus的验证是确定性的，只要证明通过即正确；而本文的证书是概率性的，代理可能生成逻辑自洽但事实错误的轨迹。这种差异暗示，当代码库包含复杂并发或内存布局时，内部证书可能无法捕捉所有副作用，而外部验证器能。本文未探索将半形式化证书作为外部验证器的输入预处理步骤，这种组合能否弥补静态推理的盲区？

## 总结

本文核心矛盾在于LLM静态推理的幻觉与完全形式化验证的高成本之间的权衡。切入点在于利用结构化提示将非结构化推理转化为可审计的证书，从而在不训练新模型的情况下提升逻辑严谨性。方法通过强制代理填充前提、轨迹与证据字段，在补丁等价性验证上实现93%准确率，较标准推理提升6个百分点。边界在于，该方法高度依赖测试补丁的存在，且在处理间接依赖和第三方库语义时仍依赖代理的领域知识，缺乏外部验证器的最终裁决。当代码库包含未文档化的副作用或复杂并发状态时，仅靠静态追踪的半形式化证书能否保证语义等价性的判定可靠性，论文未给出回答。
