> 具身智能系统依赖视频流作为核心感知输入，但现有模型难以在严格因果约束下同时满足低延迟响应、长程记忆保持与主动交互决策，导致动作延迟或决策失误。本文切入点在于将流式视频理解从单一模型推理扩展为多代理协作框架，通过解耦推理、记忆与主动决策模块，构建感知-决策-行动闭环。其核心机制是主代理进行增量流式推理，子代理分别管理分层多模态记忆与主动交互时机。该框架在架构完整性上具有前瞻性，但缺乏定量性能验证，其多代理调度是否真正优于单模型端到端方案存疑。

## 研究背景

具身智能场景下的流式视频理解面临三重约束：实时性要求模型在毫秒级延迟内响应，长程性要求保留历史上下文以支持复杂推理，主动性要求模型自主判断何时介入。流式因果性（Streaming Causality）规定模型在时间 $t$ 仅能访问 $t$ 之前的观测，这一约束使得离线视频理解中利用未来帧进行全局优化的方法失效。在此约束下，视觉 Token 的线性增长与 GPU 显存限制形成物理冲突，而简单的滑动窗口或暴力压缩往往丢失长程依赖，导致模型在复杂时序任务上的准确率显著低于离线模型。

现有主流路线在解决上述冲突时存在明显瓶颈。内存管理路线如 StreamingVLM 采用注意力沉没与连续 RoPE 位置编码，确立了无限流架构标准，但其记忆粒度固定，难以适应动态事件流；主动推理路线如 VST 提出“边看边想”范式，利用查询前的流式间隔进行自回归文本推理，但引入了额外的计算开销且依赖预设的视觉 Token 容量边界。这些方法大多停留在感知与理解层面，缺乏将视觉语义直接转化为可执行物理动作的能力，无法支持具身智能在真实物理世界中的闭环交互。

StreamingClaw 的切入点在于将流式视频理解重构为多代理协作系统，而非单一模型的优化。它通过主-子代理架构解耦了推理、记忆与主动决策，并引入工具/技能库执行物理动作，从而在架构层面实现了从被动感知到主动执行的跨越。这一设计旨在解决现有方法在长程记忆一致性与主动响应时机决策上的系统性缺陷，为具身智能提供统一的流式交互框架。

## 核心方法

### 多代理协作架构参照系

本文问题可置于“流式视频理解与具身智能”的交叉领域。标准流程通常采用单模型端到端推理，通过 KV 缓存管理历史上下文，并依赖启发式规则或轻量模块决定响应时机。本文的关键差异在于引入主-子代理（Main-Sub Agent）协作机制，将流式推理、记忆管理与主动决策解耦为独立模块，并通过工具/技能库实现感知到行动的闭环。

### 增量流式推理与动态 KV 缓存

StreamingReasoning 主代理采用动态滑动窗口与增量 KV 缓存机制，解决长视频流中上下文无限增长导致的显存溢出问题。其核心在于将计算模式从重复全历史重算转变为线性增量更新。在每次解码步骤中，仅计算新到达 Token 的增量部分，并基于注意力贡献分数对缓存中的视觉 Token 进行剪枝。设 $L$ 为 Transformer 层数，$p$ 为保留比例，剪枝过程可表示为：

$$
\mathcal{K}_{t}^{new} = \text{Top}_p(\mathcal{S}_L(\mathcal{K}_{t-1}, \mathcal{V}_{t-1}, \mathcal{Q}_t))
$$

其中 $\mathcal{S}_L$ 为第 $L$ 层的交叉注意力分数。该公式的物理含义是：仅保留对当前查询贡献最高的前 $p\%$ 视觉 Token，丢弃低贡献 Token 以控制缓存大小。这一设计解决了传统滑动窗口在长程依赖任务中信息丢失的问题，同时通过增量计算降低了实时推理延迟，使模型能够在连续视频流中保持稳定的吞吐量。

### 分层多模态记忆演化

StreamingMemory 子代理引入分层记忆演化（Hierarchical Memory Evolution, HME）机制，解决传统文本记忆在流式视频中的语义错位与检索低效问题。记忆节点定义为 $n_t = (z, s, c, \tau)$，其中 $z$ 为压缩视频片段，$s$ 为文本摘要，$c$ 为详细描述，$\tau$ 为时间戳。HME 机制通过构建“片段→原子动作→事件”的多级摘要层级，实现记忆从短期到长期的动态演化。其核心公式为：

$$
M_{long} = \text{Evolve}(M_{short}, \mathcal{E})
$$

其中 $\mathcal{E}$ 为事件检测器，$\text{Evolve}$ 为演化函数，负责冗余去除与结构化压缩。该公式的含义是：短期记忆 $M_{short}$ 经过事件检测与摘要后，转化为更抽象的长期记忆 $M_{long}$。这一设计解决了单一记忆机制难以同时满足细节保留与长程推理的问题，通过多模态存储（视觉+文本）避免了纯文本记忆的语义损失，并通过层级演化实现了记忆的高效检索与动态更新。

## 关联研究分析

从方法设计看，StreamingClaw 与 VST 在记忆管理上存在显著差异。VST 采用双记忆系统（短期视觉+长期文本），通过自回归文本推理提升推理深度，但依赖预设的视觉 Token 容量边界；StreamingClaw 通过独立的 StreamingMemory 子代理实现多模态记忆存储与层级演化，更强调视觉信息的保留与动态更新。这一差异源于任务特性：VST 聚焦于复杂多步推理，而 StreamingClaw 面向具身智能的实时交互，需要更细粒度的视觉记忆支持。然而，StreamingClaw 的多代理架构是否引入额外通信延迟，论文未给出回答。

从问题动机看，StreamingClaw 与 Wan-Streamer 均面向全双工交互，但 Wan-Streamer 侧重端到端模型训练，统一处理文本、音频和视频；StreamingClaw 侧重框架级代理调度，通过工具/技能库实现感知到行动的闭环。这一差异反映了领域内对“全模态融合”的不同理解：Wan-Streamer 追求模型内部的多模态同步，而 StreamingClaw 追求系统层面的多模块协作。StreamingClaw 的架构设计是否能在弱基础模型上保持鲁棒性，论文未提供验证。

## 总结

StreamingClaw 要解决的核心矛盾是具身智能场景下流式视频理解的实时性、长程记忆与主动交互的协同优化。现有方法在单模型框架内难以同时满足这三重约束，而本文通过多代理协作架构解耦了推理、记忆与决策，并引入工具/技能库实现感知-决策-行动闭环。其核心贡献在于架构设计的完整性，但缺乏定量性能验证，无法确认多代理调度在实时性上是否优于单模型端到端方案。论文的边界在于缺乏对最坏情况延迟尖峰与具身规划能力的评估，多代理架构的通信开销与基础模型依赖性问题未得到量化。当支持集增大到长视频流时，多代理调度的边际收益是否递减，论文未给出回答。
