研究机构：同济大学

作者：Jiaxuan Lu、Kong Wang、Yemin Wang 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.08262)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.08262)

> 金融大语言模型（LLM）从静态文本分析转向动态自主交互时，工具调用错误比自由文本幻觉更具隐蔽性与破坏性，现有基准无法区分“执行成功”与“合规可行”。FinToolBench 通过构建 760 个可执行金融工具库与 295 个工具必需问题，引入时效性、意图克制与领域对齐的调用级合规指标，填补了金融工具使用评估的空白。该基准确立了可审计的工具轨迹评估标准，但其仅评估单智能体且缺乏金融专用模型对比，限制了其在复杂多智能体交易场景中的普适性。

## 研究背景

当 LLM 智能体将自然语言请求转化为 API 调用序列时，一次看似语法正确的调用可能因数据陈旧、端点漂移或市场领域错配而失效。这种失效被称为工具调用合规性缺失，它要求评估不仅关注 API 是否执行成功，还需验证调用轨迹是否满足金融特有的时效性（Timeliness）、意图克制（Intent Restraint）与领域对齐（Domain Alignment）约束。传统金融基准多聚焦于静态文档问答，缺乏可执行工具环境，导致无法量化上述约束在实时执行中的违反率。

金融 LLM 评估长期存在“静态范式”瓶颈，即评估止步于最终答案正确性，忽视了工具选择与执行过程的合规性。通用工具基准虽关注 API 正确性，但未内化金融领域的监管与风险约束。FinToolBench 的切入点在于将金融合规约束显式化为工具元数据，并基于真实执行轨迹计算调用级不匹配率，从而区分“能执行”与“可信赖”的智能体行为。

## 核心方法

### 工具调用评估参照系

现有工具使用评估通常遵循“检索-调用-执行”流程，核心指标为调用率与执行成功率。本文问题与该通用流程的关键差异在于，金融场景要求评估不仅覆盖执行层，还需在调用层引入领域特定的合规审计，即验证每次调用是否违反时效、意图或领域约束。

### 金融属性标注与合规度量

设计动机在于解决原始执行轨迹无法直接反映金融合规性的问题，因为金融约束常隐含于用户查询中。FinToolBench 为每个工具标注三个金融属性：更新频率（update_frequency）、意图类型（intent_type）与监管领域（regulatory_domain）。对于问题 $q$ 的工具轨迹 $\tau = \{(t_k, x_k, o_k)\}_{k=1}^m$，通过 LLM 裁判评估每次调用 $t_k$ 的属性 $A(t_k) = (f(t_k), i(t_k), d(t_k))$ 与查询约束的对齐情况。若轨迹中任意一次调用被判定违反对应约束，则该问题标记为不匹配。合规不匹配率定义为：

$$
\text{Mismatch Rate} = \frac{1}{|Q_{tool}|} \sum_{q \in Q_{tool}} \mathbb{I}\left( \exists k \in \{1, \dots, m\} : \text{violate}(t_k, q) \right)
$$

该公式量化了智能体在时效、意图或领域维度上的违规频率，将合规性从定性描述转化为可计算的调用级指标。

### 金融感知工具检索（FATR）

设计动机在于解决通用工具检索在金融场景中因约束缺失导致的低效调用与高错误率问题。FATR 在工具卡片中注入金融属性标签，使规划器在检索与选择时感知合规约束。同时，通过缓存、重试与输出压缩稳定执行环境。FATR 的核心改进在于将合规约束前置到工具描述层，而非仅在事后评估中检测，从而在调用前抑制高风险行为。

## 实验评估

实验在 FinToolBench 上进行，对比 Doubao-Seed-1.6、Qwen3-8B、GLM-4.7-Flash 与 GPT-4o 四个 LLM 规划器。基线覆盖通用 LLM，但缺失 FinGPT、FinAgent 等金融专用模型，限制了横向对比的完整性。主实验结果显示，Qwen3-8B 具有最高的工具调用率（TIR = 0.8712）与软准确率（Soft Score = 0.4234），但条件执行成功率（CER = 0.3385）最低，表明其频繁出现参数实例化错误。GPT-4o 采用保守策略，TIR 仅为 0.2267，但 CER 最高（0.6176），意图与领域不匹配率最低，凸显了精度与召回的权衡。

| 模型 | TIR | TESR | CER | Soft Score | CSS | TMR | IMR | DMR |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Doubao-Seed-1.6 | 0.6508 | 0.3254 | 0.5000 | 0.3958 | 0.4627 | 0.3438 | 0.6563 | 0.1719 |
| Qwen3-8B | 0.8712 | 0.2949 | 0.3385 | 0.4234 | 0.4040 | 0.3307 | 0.6887 | 0.1673 |
| GLM-4.7-Flash | 0.4407 | 0.2102 | 0.4769 | 0.2769 | 0.3791 | 0.4615 | 0.7231 | 0.1769 |
| GPT-4o | 0.2267 | 0.1400 | 0.6176 | 0.2302 | 0.6700 | 0.3529 | 0.5000 | 0.1176 |

消融实验验证了金融属性注入的效果。移除属性注入后，CER 从 50.0% 降至 46.3%，IMR 从 65.6% 升至 66.4%，DMR 从 17.2% 升至 21.5%。这表明属性注入虽略微降低调用率，但显著提升了条件执行可靠性并降低了合规不匹配率，证实了前置约束对抑制高风险调用的有效性。

评估边界方面，FinToolBench 依赖 LLM 裁判进行合规判定，虽采用重复评估降低方差，但裁判本身的稳定性与提示敏感性仍可能引入评估噪声。可复现性上，论文声明将开源工具清单、问题集与评估脚本，但 760 个工具的免费层级访问限制可能影响部分工具的长期可用性。

## 关联研究分析

从问题动机看，FinToolBench 与 StockBench 均旨在解决金融 LLM 评估的可靠性问题，但 StockBench 聚焦于交易收益与回测偏差，而 FinToolBench 聚焦于工具执行合规性。这一差异源于任务特性：StockBench 评估的是决策结果的经济价值，FinToolBench 评估的是执行过程的监管合规性。FinToolBench 未涉及回测偏差或记忆污染，其合规约束是静态的元数据标注，而非动态的市场状态感知，这限制了其在非平稳市场中的适应性。

从方法设计看，FinToolBench 与 VERAFI 均引入外部约束验证 LLM 输出，但 VERAFI 通过神经符号方法验证数值推理的精确性，FinToolBench 通过属性标注验证工具选择的合规性。VERAFI 的约束作用于推理链内部，FinToolBench 的约束作用于工具调用层。FinToolBench 未探索多智能体协作场景，而 VERAFI 等神经符号方法通常假设单智能体推理，两者在系统复杂度上存在互补空间。FinToolBench 的单智能体评估是否足以代表金融 Agent 的主流形态，论文未给出回答。

## 总结

FinToolBench 要解决的核心矛盾是金融 LLM 工具调用中“执行成功”与“合规可行”的评估脱节。现有静态基准无法量化时效、意图与领域约束的违反，而通用工具基准缺乏金融领域特异性。FinToolBench 通过 760 个可执行工具与 295 个工具必需问题，引入调用级合规不匹配率（TMR, IMR, DMR），将合规性转化为可审计的量化指标。实验表明，GPT-4o 以 0.6176 的 CER 与 0.1176 的 DMR 展示了精度优先策略的有效性，但 0.2267 的 TIR 暴露了召回不足的问题。该基准的边界在于仅评估单智能体且缺失金融专用模型对比，其合规约束基于静态元数据而非动态市场状态。当市场领域或监管规则发生动态变化时，静态属性标注的合规审计能力是否失效，论文未给出回答。
