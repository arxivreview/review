> 检索增强多跳开放域问答（RAG-MHQA）旨在解决大语言模型在知识密集型任务中因静态参数化知识导致的幻觉与长上下文注意力稀释问题。现有迭代检索与图结构方法在文本多跳任务上表现优异，但面对包含复杂表格、跨年代格式漂移及精确数值计算的企业级文档时，其“语义检索-文本生成”范式面临失效。本文提出 OfficeQA Pro，一个基于美国财政部公报的企业级接地推理基准，通过解耦文档解析、检索与定量分析，揭示了解析质量对最终答案的决定性影响。该基准填补了结构化数值推理评测空白，但当前前沿模型在此任务上仍表现脆弱，其作为通用企业智能体评测标准的普适性尚存疑。

## 研究背景

当大语言模型处理跨越数十年、格式从扫描件到数字 PDF 漂移的企业文档时，其静态参数化知识不仅无法覆盖长尾历史数据，更难以应对嵌套表格与单位换算带来的精确性挑战。这种困境源于文档解析（Document Parsing）的脆弱性：OCR 错误与布局识别偏差会导致数值提取失真，进而使后续基于错误证据的推理链彻底断裂。解析质量直接决定了检索召回的上限，而检索的准确性又依赖于对文档结构（如表格层级、脚注关联）的正确理解，二者构成严格的因果依赖链。

RAG-MHQA 领域的主流路线已从单次检索转向迭代式检索与结构化知识表示。IRCoT 通过推理指导检索解决了证据分散问题，GraphRAG 等通过知识图谱显式建模跨文档关系。然而，这些方法隐含假设文档内容可被无损转化为扁平文本或三元组，忽略了企业文档中结构化数据（表格、图表）的复杂性。现有基准如 HotpotQA 侧重文本多跳，缺乏对精确数值计算与异构文档格式的处理能力，导致模型在真实企业工作流中的表现被高估。

OfficeQA Pro 的切入点在于将“接地推理”（Grounded Reasoning）定义为文档解析、信息检索与定量分析三阶段的端到端过程。它不依赖人工专家评分，而是通过单一无歧义答案实现确定性评估，专门针对经济价值高、计算密集的企业任务。这一设计旨在暴露现有 RAG 范式在结构化数据上的失效边界，而非单纯提升检索精度。

## 核心方法

### 方法参照系

本文问题可置于“检索增强生成”通用流程中，但关键差异在于：传统 RAG 假设检索到的文本片段可直接用于生成，而 OfficeQA Pro 要求系统首先从非结构化 PDF 中精确提取结构化数值，再进行跨文档聚合与数学运算。解析错误在此流程中不是噪声，而是导致最终答案错误的根本原因。

### 接地推理三阶段解耦

设计动机在于隔离“检索瓶颈”与“解析/推理瓶颈”。通常做法是将 PDF 直接输入 LLM 或简单 OCR，但本文引入“Oracle Pages”设置，即直接提供包含答案的原始页面，以验证当检索完美时，性能瓶颈是否转移至解析与计算。

$$
\text{Correctness} = \mathbb{1}\left[ \frac{|\hat{y} - y|}{|y|} \le \epsilon \right]
$$

该公式定义了基于绝对相对误差的确定性评估指标，其中 $\hat{y}$ 为预测值，$y$ 为真值，$\epsilon$ 为允许误差阈值（默认 0.0%）。这确保了数值答案的精确性，避免了模糊匹配带来的假阳性。

### 结构化解析增强

设计动机在于解决 LLM 直接处理复杂 PDF 布局时的提取错误。本文采用 Databricks 的 `ai_parse_document` 将 PDF 转换为结构化表示，提取文本、表格及布局元数据，再拼接为简化文本供模型使用。

$$
\Delta P = P_{\text{parsed}} - P_{\text{pdf}}
$$

该公式量化了解析增强带来的性能增益。实验显示，使用解析文档相比原始 PDF，Agent 准确率平均提升 16.1%（相对增益），最高达 22 个百分点。这表明解析质量是独立于模型推理能力的关键变量，其错误会直接传播至下游计算。

## 实验评估

实验在 OfficeQA Pro（133 题）上进行，对比了 GPT-5.4、Claude Opus 4.6 和 Gemini 3.1 Pro Preview 在 Prompt Only、Web Search、Oracle PDF 及 Oracle Parsed 四种配置下的表现。基线覆盖了当前三大前沿 LLM 及其原生 Agent 框架，但缺乏针对文本多跳的经典 RAG 方法（如 IRCoT、PRISM）作为对比，因为本文侧重端到端企业任务而非特定检索算法。

| 模型 | 配置 | 准确率 (%) | 延迟 (min) | 工具调用次数 | 成本 ($) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Claude Opus 4.6 | Full PDF | 48.12 | 31.2 | 82.4 | 4.55 |
| Claude Opus 4.6 | DBX Parsed | 54.14 | 5.3 | 68.5 | 5.93 |
| GPT-5.4 | Full PDF | 36.09 | 13.1 | 57.0 | 1.79 |
| GPT-5.4 | DBX Parsed | 56.39 | 3.6 | 34.5 | 1.26 |
| Gemini 3.1 Pro Preview | Full PDF | 18.05 | 26.4 | 75.2 | 6.21 |
| Gemini 3.1 Pro Preview | DBX Parsed | 29.32 | 2.9 | 12.8 | 1.61 |

核心数字对比显示，即使提供 Oracle 页面，最强 Agent（Claude Opus 4.6）准确率仅为 60.90%（PDF）至 66.92%（Parsed），远低于文本多跳任务中 PRISM 的 90.9% Recall。这表明企业级接地推理的难度远超文本多跳，解析与计算错误是主要失败源。

消融实验揭示，解析增强不仅提升准确率，还显著降低延迟（4-9 倍）和成本（GPT-5.4 降低约 30%）。反直觉发现是：GPT-5.4 使用 OCR 暴力提取虽慢，但通过批量处理比 Claude 的逐页读取快 2.4 倍，且成本更低。这表明工具调用策略与模型能力同等重要。

评估边界在于：133 题样本量较小，且 99% 答案为数值，可能低估了非数值推理能力。代码已开源，但解析器 `ai_parse_document` 为专有工具，限制了第三方复现的公平性。

## 关联研究分析

从问题动机看，OfficeQA Pro 与 PRISM 等迭代检索方法存在根本差异。PRISM 假设证据分散在文本段落中，通过迭代精炼解决召回问题；而 OfficeQA Pro 显示，即使检索完美（Oracle），解析错误仍导致失败。这挑战了“检索精度决定上限”的共识，指出在结构化数据场景下，解析质量是更底层的瓶颈。根源在于任务特性：文本多跳依赖语义连贯，而企业推理依赖数值精确，前者可通过 LLM 的语义理解弥补，后者则需符号级精确提取。

从方法设计看，OfficeQA Pro 与 MAGE-RAG 等多模态检索方法形成互补。MAGE-RAG 探索页面-元素图以统一文本与图像表示，但 OfficeQA Pro 实证了即使使用 SOTA 解析器，表格错位与单位混淆仍导致 35-44% 的错误率。这暗示纯神经方法在处理精确数值计算时存在固有局限，可能需要结合符号引擎或程序化验证。论文未探索解析与推理的联合优化，仅将其视为独立阶段，这是否限制了性能上限，值得进一步探讨。

## 总结

OfficeQA Pro 要解决的核心矛盾是 LLM 静态知识与企业级文档动态复杂性之间的鸿沟。本文抓住的切入点是解耦解析、检索与计算，通过 Oracle 设置隔离瓶颈，揭示了现有 RAG 范式在结构化数值推理上的失效。本文构建了基于美国财政部公报的基准，证明了即使使用最强前沿模型，准确率也仅 48.1%，解析增强可提升 16.1%。本文的边界在于样本量有限且依赖专有解析器，未能验证解析与推理联合优化的潜力。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
