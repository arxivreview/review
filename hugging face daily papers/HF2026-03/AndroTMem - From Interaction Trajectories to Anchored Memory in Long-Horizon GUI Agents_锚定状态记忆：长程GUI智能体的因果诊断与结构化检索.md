# HuggingFace最新推荐论文 ｜AndroTMem: From Interaction Trajectories to Anchored Memory in Long-Horizon GUI Agents ｜锚定状态记忆：长程GUI智能体的因果诊断与结构化检索

作者：Yibo Shi、Jungang Li、Linghao Zhang 等 28 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.18429)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.18429)

> 长程GUI智能体在数十步交互中频繁失效，核心瓶颈并非单步感知错误，而是关键中间状态在时间轴上的丢失与误用。现有基准将任务长度简单叠加，掩盖了因果依赖断裂这一真实故障模式，导致记忆能力无法被独立度量。本文通过构建强因果依赖的Android基准AndroTMem-Bench，提出锚定状态记忆（Anchored State Memory, ASM）机制，以稀疏状态锚点及其因果链替代全序列回放，在12个模型上将任务完成率（Task Complete Rate, TCR）提升5%–30.16%。该框架首次将“记忆失效”从端到端成功率中剥离，但其对锚点标注的依赖及跨应用泛化边界仍存疑。

## 研究背景

GUI智能体执行跨应用任务时，后续动作往往依赖数步前提取的中间值（如价格、联系人ID），这些值既不可从初始指令直接获得，也无法仅凭当前屏幕恢复。这种依赖关系构成“中间任务状态”，其正确维持是长程任务成功的先决条件。当交互轨迹超过20步，上下文窗口溢出或噪声累积会导致这些关键状态被稀释或遗忘，智能体在需要复用早期结果时发生决策断裂。

主流GUI基准（如AndroidWorld、Mind2Web）侧重短程或弱耦合任务，其长度来自松散步骤串联而非强因果约束，使得后续步骤即使未复用早期信息也可能偶然成功。这导致端到端成功率混淆了感知错误、局部动作失误与记忆失效三类故障，无法定位性能退化的真实驱动因素。现有历史建模方案陷入两难：全序列回放冗余且放大噪声，粗粒度摘要则擦除下游决策所需的细粒度状态与依赖关系。本文切入点在于将“记忆”从黑箱中剥离，通过显式标注因果依赖的中间状态锚点，构建可诊断、可检索的结构化记忆机制。

## 核心方法

### 方法参照系

长程GUI智能体的历史建模通常置于“上下文管理”通用流程中，标准做法是将历史交互压缩为摘要或保留原始轨迹供LLM参考。本文问题与该流程的关键差异在于：任务成功不依赖历史信息的“存在”，而依赖特定中间状态的“因果复用”，通用摘要无法保证关键状态的可检索性与归因准确性。

### 因果依赖任务构造

**设计动机**：现有基准的任务长度来自步骤堆叠，缺乏强制因果约束，导致记忆失效被掩盖。本文通过模板化任务设计，确保每个后续步骤都依赖于前序步骤产生的特定中间状态，使记忆成为任务成功的必要条件。

任务指令由功能应用组（Functional App Group）与意图驱动模板生成。模板包含应用组槽位（如`{#group:shopping}`）与参数槽位（如`{item}`），实例化后由GPT-4o改写为自然语言。关键约束在于：模板中的槽位仅指定任务参数，不指定中间结果，迫使智能体在执行中动态提取并维持这些状态。例如，“比较JD与淘宝的AirPods Pro2价格，将更便宜的加入购物车并分享给Alice”这一任务，要求智能体在步骤7提取JD价格、步骤11提取淘宝价格、步骤12比较并确定更便宜项，后续步骤14（加购）与步骤21（分享）均依赖步骤12的输出。这种设计使稀疏但关键的中间状态成为下游决策的因果前提。

### 锚定状态记忆机制

**设计动机**：全序列回放随轨迹长度线性增长，摘要则丢失细粒度依赖。ASM通过显式存储因果链接的状态锚点，实现子目标定向检索，避免无关历史噪声干扰。

ASM将交互轨迹组织为稀疏的中间状态锚点集合，每个锚点包含状态值、证据（截图/边界框）及因果依赖关系。形式化地，锚点 $a_i$ 定义为三元组：

$$
a_i = \langle v_i, e_i, D_i \rangle
$$

其中 $v_i$ 为状态值（如价格、物品ID），$e_i$ 为支撑该值的视觉证据，$D_i$ 为依赖该锚点的后续步骤集合。检索时，智能体根据当前子目标 $g_t$ 查询锚点库，返回满足 $g_t \in D_i$ 的锚点集合 $\mathcal{A}_t$：

$$
\mathcal{A}_t = \{ a_i \mid g_t \in D_i \}
$$

该公式的物理含义是：仅检索与当前决策因果相关的历史状态，而非全部历史。相比全序列回放，ASM将上下文长度从 $O(T)$ 降至 $O(|\mathcal{A}_t|)$，其中 $|\mathcal{A}_t|$ 通常远小于总步数 $T$。相比摘要，ASM保留状态值的精确性与可追溯性，支持归因分析（即识别哪个早期状态导致当前错误）。

## 实验评估

实验在AndroTMem-Bench上进行，该基准包含1,069个任务、34,473个交互步骤，覆盖50个应用，平均32.1步/任务，最大65步。基线覆盖闭源模型（GPT-4o, GPT-5, Gemini系列）、开源模型（Qwen2.5-VL-7B, UI-TARS-1.5-7B等）及多智能体框架（Mobile-Agent-E, COLA），但未包含MemGPT等专用记忆机制基线，限制了与现有记忆方法的直接对比。

| 模型 | AMS (%) | TCR (%) |
| :--- | :--- | :--- |
| Gemini-3-Flash | 46.14 | 55.21 |
| UI-TARS-1.5-7B | 35.62 | 34.55 |
| GPT-4o | 14.24 | 11.75 |
| Qwen2.5-VL-7B | 20.71 | 16.04 |

Gemini-3-Flash以55.21%的TCR领先，但所有模型绝对性能均较低，表明长程跨应用任务对当前智能体极具挑战。ASM在12个模型上均优于全序列回放与摘要基线，TCR提升5%–30.16%，AMS提升4.93%–24.66%。提升幅度随任务长度增加而扩大，在40-49步区间，ASM较全序列回放提升0.16，较摘要提升0.28，验证了结构化记忆在长程场景中的边际收益递增。

评估边界方面，TCR指标依赖人工标注的状态锚点，其准确性受标注质量制约；基准仅覆盖Android平台，跨OS泛化能力未验证；代码已开源（`https://github.com/CVC2233/AndroTMem`），但超参数与GPU配置未在正文中详述，可复现性依赖附录补充。

## 关联研究分析

从问题动机看，Mobile-Agent-v2引入记忆模块解决长程上下文丢失，但其记忆机制基于通用LLM生成摘要，未显式建模因果依赖。本文的ASM通过结构化锚点实现定向检索，其根源差异在于：Mobile-Agent-v2假设历史信息可被压缩为语义摘要，而本文实证表明摘要会擦除下游决策所需的细粒度状态值。这一差异是否源于任务特性（即强因果依赖任务对摘要的敏感性更高），还是通用摘要在弱依赖任务中仍有效，论文未给出跨任务类型的对比实验。

从方法设计看，PAL-UI采用双层级历史摘要与主动检索，侧重语义层面的历史感知；ASM则侧重状态值的精确存储与因果归因。两者均解决“历史丢失”问题，但PAL-UI的摘要可能丢失具体数值（如价格），而ASM保留原始值。这一设计选择暗示：在需要精确数值复用的任务中，结构化记忆优于语义摘要；但在仅需语义理解的场景中，摘要可能更高效。论文未探索两种机制的混合策略，也未量化不同任务类型下两种方法的性能差异。

## 总结

本文核心矛盾在于长程GUI任务中关键中间状态的因果复用失效，现有方法因缺乏显式因果建模而无法诊断与解决。本文通过构建强因果依赖基准与ASM机制，将记忆从黑箱中剥离，实证了结构化锚点检索对长程任务的必要性，TCR提升5%–30.16%。其边界在于：ASM依赖人工标注的状态锚点，自动化提取的可靠性未验证；基准仅覆盖Android，跨平台泛化能力未知。当锚点标注成本随任务复杂度非线性增长时，ASM的部署可行性是否受限，论文未给出回答。
