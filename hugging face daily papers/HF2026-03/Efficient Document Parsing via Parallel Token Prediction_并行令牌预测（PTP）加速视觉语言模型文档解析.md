# HuggingFace最新推荐论文 ｜Efficient Document Parsing via Parallel Token Prediction ｜并行令牌预测（PTP）加速视觉语言模型文档解析

研究机构：中国人民大学

作者：Lei Li、Ze Zhao、Meng Li 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.15206)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.15206)

> 文档解析任务正从追求识别精度转向兼顾大规模部署下的推理效率，现有视觉语言模型（VLM）依赖自回归解码，其延迟随文档复杂度线性增长，成为落地瓶颈。本文切入点在于利用OCR转录任务的输出唯一性，将序列生成改造为并行预测。通过引入可学习寄存器令牌，模型在单步解码中同时生成多个未来令牌，实现1.6至2.2倍吞吐量提升。该方案在不改变基础架构的前提下突破了速度限制，但其精度上限仍受限于3B参数骨干，且并行预测在复杂公式场景下的误差累积机制尚待深入验证。

## 研究背景

当VLM处理高分辨率文档图像时，视觉编码器输出的海量视觉令牌需经语言模型逐字解码为文本。这一过程遵循下一令牌预测（Next-Token Prediction, NTP）范式，即每个新令牌的生成严格依赖前序所有令牌的隐状态。NTP的串行特性导致解码延迟与输出长度成正比，在密集文本或复杂表格场景下，推理时间呈线性膨胀，严重制约了实时文档处理系统的吞吐量。

文档解析领域的主流路线已从模块化流水线转向端到端VLM架构，以消除模块间误差累积并保留布局语义。然而，端到端范式在提升精度的同时，将计算负担完全转移至解码阶段。现有加速策略如视觉令牌压缩或输出序列精简，仅能缓解预填充或输出长度压力，未能触及自回归解码这一根本瓶颈。多令牌预测（Multi-Token Prediction, MTP）虽尝试并行生成，但需修改模型架构引入额外预测头，导致训练收敛缓慢且参数冗余。本文针对这一效率与架构兼容性的矛盾，提出无需修改骨干网络结构的并行解码方案，旨在以最小侵入性实现解码步骤的并行化。

## 核心方法

### 方法参照系

文档解析的标准流程基于VLM的自回归生成机制，其核心约束在于解码步骤的串行依赖。本文问题与该通用流程的关键差异在于，将高确定性的转录任务视为可并行化的局部识别过程，而非必须严格遵循全局上下文顺序的开放生成任务。

### 寄存器令牌并行预测

传统NTP在每一步仅生成一个令牌，而本文在训练序列中插入可学习寄存器令牌（Register Tokens），使其基于相对位置预测未来多个令牌。这一设计解决了MTP方法因引入独立预测头导致的架构复杂性与收敛困难问题。寄存器令牌共享同一嵌入向量，但通过位置编码区分预测偏移量，从而在单一模型内实现多步前瞻预测。

$$
\mathcal{L}_{PTP} = \mathcal{L}_{NTP} + \alpha \sum_{i=1}^{l} \sum_{j=1}^{n} \mathcal{L}_{reg}(x_{i+j}, r_{i+j})
$$

该公式表明，总损失由标准NTP损失与寄存器令牌预测损失加权组成，$\alpha$ 控制并行预测目标的权重，确保模型在保持基础生成能力的同时习得多令牌并行预测能力。

### 推理时KV缓存替换

在推理阶段，模型在每个解码步骤末尾追加 $n$ 个寄存器令牌，一次性生成 $n+1$ 个新令牌。由于寄存器令牌仅作为计算中介，其KV缓存不携带最终语义信息，因此在下一步解码前被丢弃，并用实际预测出的令牌的KV缓存替代。这一机制解决了并行预测中寄存器令牌隐状态可能污染后续上下文的问题，确保生成序列的语义一致性。

$$
SR = \frac{n+1}{L_{\theta} + L_{\theta}'}
$$

速度提升比（Speedup Ratio, SR）由每步生成的令牌数与单步解码延迟决定，$L_{\theta}$ 为常规解码延迟，$L_{\theta}'$ 为处理多令牌的额外前向传播延迟。当计算资源充足时，$L_{\theta}'$ 可忽略，理论加速比趋近于 $n+1$。

## 实验评估

实验在OmniDocBench和olmOCR-bench上进行，基线覆盖流水线工具（MinerU2-pipeline）、通用VLM（GPT-4o）及专用VLM（dots.ocr, MinerU2.5）。论文未直接对比其他并行解码方法如MTP变体，但通过消融实验验证了PTP相对于NTP的增益。

| 模型 | OmniDocBench Text Edit (↓) | olmOCR-bench CDM (↑) |
| :--- | :--- | :--- |
| Qwen2.5-VL-3B-NTP | 71.0 | 71.65 |
| Qwen2.5-VL-3B-PTP-0 | 71.0 | 91.59 |
| Qwen2.5-VL-3B-PTP-1 | 70.6 | 89.63 |
| Qwen2.5-VL-3B-PTP-2 | 70.6 | 77.23 |

PTP-1在文本识别上略优于NTP，但在公式识别CDM指标上低于PTP-0，表明并行预测在复杂LaTeX语法推理中存在精度损失。PTP-2的CDM降至77.23，显示随着并行令牌数增加，误差累积效应显著。

消融实验显示，连续插入寄存器令牌优于交错插入，因为连续方式允许后续寄存器利用前序预测的上下文信息。共享嵌入配置略优于独立嵌入，符合寄存器令牌作为位置敏感预测器的设计初衷。KV缓存替换机制对维持性能至关重要，移除该机制导致CDM从89.63降至39.43，证实了寄存器隐状态对后续生成的干扰。

评估边界方面，论文仅使用3B参数骨干，未验证在72B等大模型上的加速比线性度。指标聚焦于编辑距离与CDM，缺乏对推理延迟与吞吐量在不同硬件配置下的详细报告。代码已开源，超参数（$n=3, \alpha=0.5$）明确，但训练数据规模（1.8M样本）与基线模型的训练数据量未对齐，可能影响精度对比的公平性。

## 关联研究分析

从问题动机看，MinerU2.5通过解耦两阶段架构降低计算成本，但仍未突破自回归解码的串行瓶颈；本文PTP则直接针对解码步骤本身进行并行化，两者分别作用于解析流程的不同阶段。MinerU2.5的精度优势（OmniDocBench 75.2）源于其专用解析策略，而PTP-1的精度（70.6）受限于3B骨干容量，这暗示并行解码的加速收益可能以牺牲部分复杂结构识别精度为代价。

从方法设计看，MTP通过引入额外预测头实现多令牌预测，但需修改模型架构且收敛缓慢；PTP利用寄存器令牌在现有架构内实现并行预测，无需修改骨干网络。这一差异源于PTP将寄存器令牌视为位置敏感的计算中介，而非独立的预测模块，从而避免了架构冗余。然而，PTP在公式识别上的精度下降（PTP-2 CDM 77.23 vs PTP-0 91.59）表明，并行预测在需要长程依赖推理的任务中可能存在误差累积，这与MTP在语言模型中表现稳定的情况形成对比，可能源于文档解析中视觉-文本对齐的局部性更强。

## 总结

本文核心矛盾在于VLM自回归解码的串行延迟与文档解析大规模部署需求之间的冲突。现有方法如视觉令牌压缩仅缓解输入压力，MTP需修改架构，均未能以最小侵入性突破解码瓶颈。本文通过引入寄存器令牌并行预测，在不改变骨干结构的前提下实现1.6至2.2倍加速，并验证了其在文本识别上的精度保持能力。然而，实验暴露了并行预测在复杂公式场景下的精度损失（PTP-2 CDM降至77.23），且仅在3B骨干上验证，未探索更大模型或不同文档类型的泛化性。当寄存器令牌数从1增至2时，公式识别精度显著下降，这一误差累积机制在视觉-文本对齐任务中是否可通过更精细的位置编码或注意力掩码策略缓解，论文未给出回答。
