# HuggingFace最新推荐论文 ｜VTC-Bench: Evaluating Agentic Multimodal Models via Compositional Visual Tool Chaining ｜视觉工具链基准（VTC-Bench）：评估多模态大语言模型的工具组合能力

研究机构：新加坡南洋理工大学、美团

作者：Xuanyu Zhu、Yuhao Dong、Rundong Wang 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.15030)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.15030)

> 多模态大语言模型（Multimodal Large Language Models, MLLMs）正从被动视觉感知转向主动工具调用，但现有评估基准工具集稀疏且缺乏多步组合测试，无法反映真实计算机视觉流水线中的复杂编排需求。VTC-Bench 通过集成 32 种 OpenCV 原子操作与 680 道分层认知任务，构建了首个强制评估多工具链式依赖与执行效率的基准。该基准揭示了当前 SOTA 模型在工具泛化与长程规划上的显著瓶颈，为视觉智能体（Visual Agent）的可靠性诊断提供了新的过程级度量标准，但其对开源模型工具调用能力的负面结论是否源于提示工程适配性不足，仍存疑。

## 研究背景

当 MLLM 面对低光照或几何畸变的图像时，仅靠内在视觉编码器难以恢复有效特征，必须依赖外部工具进行预处理。这一需求催生了“视觉智能体”范式，即模型通过调用代码或接口执行裁剪、旋转、增强等操作，再基于处理后的图像进行推理。然而，工具调用的有效性不仅取决于单次操作的正确性，更依赖于多步操作的逻辑连贯性与参数配置的精确性，这构成了“多工具组合”（Multi-Tool Composition, MTC）的核心挑战。

现有基准如 VisualToolBench 和 TIR-Bench 虽引入了工具调用评估，但工具集规模有限（6-14 个）且任务多为单步或简单串联，缺乏对长程依赖（Long-Horizon Calling, LHC）和严格功能依赖（Strict Functional Dependency, SFD）的系统性测试。这种设计导致模型可通过记忆少量高频操作（如裁剪、缩放）获得高分，掩盖了其在复杂视觉推理中无法动态选择最优工具、无法处理未见操作的根本缺陷。VTC-Bench 的切入点在于将评估粒度从“能否调用工具”提升至“能否高效编排工具链”，通过引入地面真值执行轨迹（Ground-Truth Trajectory）与细粒度效率指标，量化模型在真实计算机视觉流水线中的规划能力与执行冗余度。

## 核心方法

### 方法参照系

本文问题属于“智能体能力评估”范畴，但区别于通用工具调用基准，其核心差异在于任务域限定为底层视觉操作，且强制要求评估中间执行轨迹的逻辑最优性，而非仅关注最终答案准确率。

### 分层认知任务体系

VTC-Bench 构建了九类任务组成的三层认知层级，旨在模拟从基础感知到复杂推理的认知演进。Tier 1（视觉感知增强）包含鲁棒 OCR、感知恢复和注意力聚焦，要求模型消除噪声或几何畸变；Tier 2（定量视觉估计）涵盖测量、颜色提取和计数，测试精确量化能力；Tier 3（组合视觉推理）包括图表、数学和空间推理，要求多步工具协同完成逻辑推导。该设计动机在于解决现有基准中任务难度扁平化、无法区分“简单操作”与“复杂编排”能力差异的问题。通过引入受控视觉扰动（如雾天、低光），强制模型从被动识别转向主动规划图像恢复路径，从而暴露其在非理想条件下的鲁性缺陷。

### 双范式评估与过程效率指标

针对代码生成与接口调用两种交互范式，VTC-Bench 引入“有效工具链”（Effective Toolchain）概念，定义为产生最终答案的最小工具调用序列。为量化模型执行计划与最优解的偏差，定义平均绝对误差（MAE）和工具使用效率（$Eff_{tool}$）：

$$
MAE = \frac{1}{N} \sum_{i=1}^{N} |L_{T,i} - L_{G,i}|
$$

$$
Eff_{tool} = \frac{1}{N} \sum_{i=1}^{N} \frac{L_{e,i}}{L_{T,i}}
$$

其中 $N$ 为样本总数，$L_{G,i}$、$L_{T,i}$、$L_{e,i}$ 分别为第 $i$ 个样本的地面真值链长、模型预测总链长和有效链长。MAE 衡量模型调用步骤数与最优步骤数的绝对偏差，反映规划冗余度；$Eff_{tool}$ 衡量有效步骤在总步骤中的占比，直接量化执行效率。该设计解决了仅用准确率（APR）评估时，模型可能通过冗余试错（Trial-and-Error）获得正确答案却掩盖逻辑断裂的问题，使得“正确但低效”与“正确且高效”的推理过程得以区分。

## 实验评估

实验覆盖 19 个主流 MLLM，包括 GPT-5.2、Gemini-3.0-Pro 等闭源模型及 Qwen3-VL 系列开源模型，采用代码（Code）与接口（Interface）双范式评估。基线审计显示，对比方法涵盖了专用工具模型（如 DeepEyes）与通用大模型，但缺乏针对视觉编码器微调模型的对比，可能高估了通用模型的工具调用劣势。

| 模型 | 设置 | Overall APR (%) | Delta (%) |
| :--- | :--- | :--- | :--- |
| Gemini-3.0-Pro | Code | 51.18 | +6.77 |
| GPT-5.2 | Code | 44.56 | +8.53 |
| GPT-4o | Inter. | 33.82 | +9.56 |
| Qwen3-VL-235B | Inter. | 34.85 | -1.47 |

闭源模型在工具增强下表现显著提升，Gemini-3.0-Pro 在代码范式下达到 51.18% 的最高准确率，较基线提升 6.77%；GPT-4o 在接口范式下提升幅度最大，达 +9.56%。相比之下，开源模型普遍呈现性能停滞或下降，Qwen3-VL-235B 在接口范式下较基线下降 1.47%，表明其缺乏有效的工具调用内化能力。

消融分析揭示了工具利用的“长尾效应”与效率瓶颈。模型高度依赖 Zoom In、Rotate 等少数高频工具，而 Hough Lines、Watershed 等复杂工具调用率极低。GPT-5.2 的 MAE 高达 9.96，$Eff_{tool}$ 仅为 16.78%，说明其虽能得出正确答案，但执行路径包含大量冗余步骤。这一反直觉发现表明，当前模型的“智能”更多源于试错启发式而非精确的程序化编排，且专用工具模型（如 DeepEyes）因过度训练工具调用而忽视了内在感知，导致感知与工具调用能力解耦。

评估边界方面，基准仅覆盖 OpenCV 视觉操作，未涉及代码执行或外部知识检索，限制了结论向通用智能体的泛化。可复现性上，论文提供了 GitHub 链接及详细提示模板，但 680 道题目的人工标注与交叉验证过程依赖专家主观判断，可能引入标注偏差。

## 关联研究分析

从问题动机看，VTC-Bench 与 Agentic-MME 均关注智能体的主动调查能力，但前者聚焦底层视觉操作的原子组合，后者侧重高层语义检索与工具协同。VTC-Bench 引入 SFD 约束，强制前序工具输出作为后序输入，这比 Agentic-MME 的松散工具调用更贴近计算机视觉流水线的刚性依赖。这种差异源于任务特性：视觉预处理具有严格的物理因果链（如必须先去噪再边缘检测），而语义检索则允许并行或跳跃式调用。VTC-Bench 对 SFD 的强调，揭示了模型在缺乏显式依赖提示时，难以自发构建符合物理逻辑的执行序列。

从方法设计看，VTC-Bench 与 TIR-Bench 同属代码驱动评估，但 VTC-Bench 引入了“有效工具链”回溯机制与 $Eff_{tool}$ 指标，而 TIR-Bench 主要关注最终答案正确性。这一差异导致 VTC-Bench 能识别出“正确但低效”的失败模式，而 TIR-Bench 可能将其误判为成功。根源在于 VTC-Bench 将评估对象从“结果”扩展至“过程”，通过量化执行冗余度，暴露了模型在长程规划中的逻辑断裂。然而，这种细粒度评估依赖地面真值轨迹的准确性，若标注轨迹存在多种可行解，MAE 的计算可能低估模型的灵活性。

## 总结

VTC-Bench 旨在解决 MLLM 在复杂视觉任务中工具编排能力评估缺失的问题，通过 32 种 OpenCV 工具与 680 道分层任务，构建了首个量化多工具组合效率的基准。实验证明，即便 SOTA 模型 Gemini-3.0-Pro 也仅取得 51.18% 的准确率，且普遍存在工具调用冗余与泛化不足的问题。其边界在于评估域限定于底层视觉操作，且开源模型的负面结果可能受提示工程适配性影响。当模型规模扩大至 235B 时，工具调用效率是否随参数增长而线性提升，还是受限于视觉编码器与语言模型的耦合瓶颈，论文未给出回答。
