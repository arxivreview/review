# HuggingFace最新推荐论文 ｜UI-Voyager: A Self-Evolving GUI Agent Learning via Failed Experience ｜自进化GUI智能体：基于失败经验的组相对自蒸馏

作者：Zichuan Lin、Feiyu Liu、Yijun Yang 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.24533)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.24533)

> 移动端GUI智能体在长程任务中面临稀疏奖励导致的信用分配模糊与失败轨迹利用率低的双重困境，传统强化学习难以定位具体错误步骤。本文切入点在于利用同组内成功轨迹作为教师，通过视觉相似度匹配定位分叉点，将稀疏的轨迹级奖励转化为密集的步级监督信号。具体做法是构建两阶段自进化管线，先通过拒绝微调迭代优化数据与模型，再引入组相对自蒸馏机制进行策略精化。该方法以4B参数量在AndroidWorld上超越人类水平，但其对视觉状态匹配的依赖及单一基准验证限制了结论的普适性。

## 研究背景

GUI智能体的交互过程可建模为部分可观测马尔可夫决策过程（POMDP），其中智能体仅能获取屏幕截图作为观测，无法直接访问底层状态。这种部分可观测性导致智能体在长程任务中难以区分当前状态与历史状态，进而引发决策歧义。当任务涉及多达30步交互时，单一错误动作可能导致整条轨迹失败，而传统的轨迹级奖励（成功/失败）无法提供步级反馈，使得智能体无法识别具体哪一步导致了失败，这一现象即信用分配问题。

现有主流路线主要依赖监督微调（SFT）或标准强化学习（RL）。SFT虽能提升基础能力，但难以处理动态环境中的错误恢复；RL（如PPO、GRPO）虽能优化策略，但在稀疏奖励场景下，优势函数在整条轨迹内保持一致，导致学习信号极度稀疏且模糊。MobileRL等在线RL方法虽提升了动态适应性，但样本效率低下，且未能解决信用分配的根本瓶颈。UI-Voyager的切入点在于重新利用被传统管线丢弃的失败轨迹，通过挖掘成功与失败轨迹间的共享状态，实现无需外部标注的步级纠错。

## 核心方法

### 方法参照系

本文问题置于交互式GUI智能体训练框架下，与标准RL流程的关键差异在于奖励信号的粒度与来源。标准流程依赖环境返回的稀疏标量奖励计算优势函数，而本文通过内部轨迹对比生成密集的步级监督信号，将策略优化从基于奖励的试错转变为基于状态匹配的自纠正。

### 拒绝微调与轨迹生成

设计动机在于解决高质量GUI交互数据稀缺及人工标注成本高的问题。传统SFT依赖静态数据集，无法覆盖动态UI行为；本文引入种子任务生成器，通过扰动时间约束、数量及文件实体等参数合成新任务，结合GUI智能体自动执行生成轨迹。随后采用拒绝采样机制，仅保留通过规则验证器（基于ADB命令检查应用状态）的成功轨迹用于SFT。这一闭环使数据与模型能力协同进化，每轮迭代使用新任务防止过拟合，为后续阶段提供高质量初始策略。

### 组相对自蒸馏

设计动机在于解决长程任务中稀疏奖励导致的信用分配模糊，即智能体无法识别具体错误步骤。在标准GRPO或PPO中，优势函数 $\hat{A}_{i,t}$ 在整条轨迹内相同，无法区分正确与错误动作。本文提出组相对自蒸馏（GRSD），在同组 $G$ 条轨迹中选取最短成功轨迹为“教师”，通过结构相似性指数（SSIM）匹配定位失败轨迹中的分叉点。分叉点定义为失败轨迹中观测与成功轨迹某步相同（$SAME(o^+_i, o^-_j)$）但后续动作导致状态偏离（$DIVERGE(i, j)$）的步骤。

分叉点检测的核心公式为：

$$
SAME(o_a, o_b) = \mathbb{1}[\text{SSIM}(\phi(o_a), \phi(o_b)) \ge \theta]
$$

其中 $\phi(\cdot)$ 为裁剪、缩放及灰度化预处理，$\theta$ 为相似度阈值。该公式通过视觉相似度判断两截图是否处于同一逻辑UI状态，避免了使用预训练视觉编码器的高计算成本。

在定位分叉点后，GRSD将成功轨迹在分叉点的正确动作蒸馏至失败轨迹的对应位置，通过SFT进行混合样本训练。这一过程将稀疏的轨迹级反馈转化为密集的步级监督，使智能体能从失败经验中直接学习纠正动作，无需依赖外部VLM或复杂奖励塑形。

## 实验评估

实验在AndroidWorld基准上进行，该基准包含116个跨20个应用的动态任务，支持参数随机化。基线覆盖Qwen3-VL、UI-Tars、MAI-UI、Step-GUI等开源模型及Gemini-2.5-Pro等闭源模型，但缺失MobileRL的直接对比，仅引用其训练思路。

| 方法 | 参数量 (B) | Pass@1 成功率 (%) |
| :--- | :--- | :--- |
| UI-Voyager | 4 | 81.0 |
| MAI-UI-235B-A22B | 235 | 76.7 |
| UI-Tars-2 | 230 | 73.3 |
| Step-GUI-8B | 8 | 67.7 |
| Qwen3-VL-4B | 4 | 45.3 |
| Human | - | 80.0 |

UI-Voyager以4B参数量取得81.0%的成功率，超越人类水平（80.0%）及所有基线，包括参数量大数十倍的MAI-UI-235B-A22B（76.7%）。与同规模Qwen3-VL-4B（45.3%）相比，性能提升35.7个百分点，验证了自进化管线在小模型上的高效性。

消融实验显示，RFT阶段经过三轮迭代，Pass@1从37%提升至73%，表明数据与模型的协同进化显著提升了基础能力。在GRSD阶段，从73.2%的RFT模型出发，GRSD将成功率提升至81.0%，而GRPO和PPO仅提升至约76%。这一差距表明，在稀疏奖励场景下，基于状态匹配的自蒸馏比基于优势函数的RL优化更有效，尤其在低成功率任务上，GRSD的优势更为显著。

评估边界方面，实验仅基于AndroidWorld单一基准，缺乏跨平台（如Web、桌面）验证，限制了结论的泛化性。可复现性方面，论文提供GitHub代码，但SSIM阈值 $\theta$ 及哈希相似度阈值（0.80）的敏感性分析未详细展开，可能影响分叉点检测的鲁棒性。此外，64次随机运行的方差范围未明确报告，数值比较需谨慎。

## 关联研究分析

从问题动机看，UI-Voyager与EvoCUA均关注长程任务中的信用分配问题，但解决路径截然不同。EvoCUA依赖外部VLM合成修正轨迹，用于直接偏好优化，其优势在于能利用外部模型的语义理解能力，但引入了额外的计算开销和模型依赖。UI-Voyager则采用基于SSIM的内部状态匹配，无需外部模型，更轻量且自包含。这一差异根源在于任务特性：GUI任务的视觉状态具有高度结构化特征，SSIM足以捕捉状态等价性，而EvoCUA可能更适用于视觉状态模糊或需语义推理的场景。UI-Voyager未探索SSIM在复杂动画或动态UI下的失效边界，这是其方法设计的潜在盲区。

从方法设计看，UI-Voyager与MobileRL同属在线/半在线训练路线，但优化机制存在本质差异。MobileRL采用标准RL优化，依赖环境奖励信号，样本效率受限于奖励稀疏性；UI-Voyager则通过GRSD将失败轨迹转化为监督信号，实现了数据的高效复用。这一差异源于对“失败经验”的不同利用方式：MobileRL将失败视为负奖励，UI-Voyager将失败视为纠错样本。UI-Voyager在AndroidWorld上以4B参数超越MobileRL的9B模型（据领域综述，MobileRL为80.2%），表明自蒸馏机制在特定任务上可能比在线RL更高效。然而，UI-Voyager未验证在极端分布外场景下，自蒸馏是否仍能保持优势，这是其与在线RL路线对比的关键未决问题。

## 总结

UI-Voyager旨在解决移动端GUI智能体在长程任务中因稀疏奖励导致的信用分配模糊及失败轨迹利用率低的核心矛盾。其切入点在于利用同组内成功轨迹的视觉状态匹配，将稀疏奖励转化为密集步级监督，从而在无需外部标注的情况下实现高效自进化。通过两阶段管线（RFT+GRSD），该方法以4B参数量在AndroidWorld上取得81.0%的成功率，超越人类水平及所有基线。然而，其边界在于对视觉状态匹配的依赖及单一基准验证，SSIM在动态UI下的鲁棒性未充分探讨。当GUI界面包含复杂动画或状态变化时，基于SSIM的分叉点检测是否仍能准确定位错误步骤，论文未给出回答。
