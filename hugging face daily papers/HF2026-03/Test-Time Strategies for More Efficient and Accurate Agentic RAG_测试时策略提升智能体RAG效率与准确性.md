> 智能体RAG在处理多跳问答时，常因模型遗忘前序检索信息而陷入重复查询的循环，导致推理延迟与Token消耗激增。现有强化学习训练框架虽能优化检索时机，却难以在推理阶段有效整合分散的上下文证据。本文通过引入外部LLM进行信息提取与缓存，在不修改模型参数的前提下，解决了信息遗忘与提取失效问题。该方案在HotpotQA上将精确匹配率提升5.6%并减少检索轮次，但其依赖外部API的架构引发了对部署成本与纯参数化效率的质疑。

## 研究背景

当大语言模型（LLM）面对需要跨文档关联的多跳问题时，单次检索往往无法覆盖分散的实体关系。为应对此局限，智能体RAG（Agentic RAG）框架如Search-R1引入强化学习（RL），让模型在推理过程中自主决定何时发起检索，形成“推理-检索”交替循环。然而，这种动态机制引入了新的瓶颈：模型在多次迭代中难以有效保留和利用前序步骤获取的关键信息，导致“信息遗忘”现象，进而生成重复的检索查询，不仅增加了计算开销，还因上下文冗余稀释了关键证据的权重。

Search-R1通过PPO或GRPO算法优化精确匹配（EM）分数，在基准测试中取得了显著进展，但其推理链分析暴露出两个核心缺陷：一是模型无法从已检索文档中高效提取有用信息，二是缺乏跨轮次的记忆机制。现有研究如Search-o1虽尝试通过外部LLM提取信息，但仅处理单步文档，未解决跨步骤的信息累积问题。本文切入点在于将信息提取与推理过程解耦，通过测试时（Test-Time）的后处理模块，在保持Search-R1原有架构不变的前提下，修复其推理效率与准确性的短板。

## 核心方法

### 方法参照系

本文基于Search-R1框架，该框架将检索视为LLM推理循环中的一个工具调用。标准流程中，模型生成查询 $q_i$，检索器返回文档 $D_i$，文档直接拼接至推理轨迹供模型继续推理。本文的关键差异在于，不再将原始文档 $D_i$ 直接注入上下文，而是插入一个中间处理层，对 $D_i$ 进行筛选或语义压缩，以优化输入给LLM的信息质量。

### 上下文化模块

针对模型“提取失效”的问题，本文引入上下文化（Contextualization）模块。该模块利用外部LLM（GPT-4.1-mini）从新检索文档 $D_i$ 中提取与用户提示 $p$ 相关的简洁信息，并维护一个持久化记忆缓存。其核心机制可表示为：

$$ C_{i} = \text{Extract}(p, D_i, C_{i-1}) $$

其中 $C_{i-1}$ 为上一轮累积的缓存，$\text{Extract}$ 函数约束外部LLM仅添加新相关信息，保留旧信息。这一设计动机在于，通过显式提取关键事实，避免原始文档中的噪声稀释LLM的注意力，同时通过缓存机制解决“信息遗忘”，使模型在后续轮次中无需重复检索已获取的信息。

### 去重与混合策略

为验证重复检索是否源于信息不足，本文设计了去重（De-duplication）模块。当检索到的文档ID已存在于历史集合中时，系统丢弃该文档并替换为检索器排名中下一个未见的文档。混合（Hybrid）策略则串联上述两个模块，先执行去重以保证文档多样性，再执行上下文化以提取关键信息。去重模块的引入旨在测试假设：若模型因缺乏新信息而重复查询，强制提供新文档应能减少冗余轮次。然而实验显示，去重反而增加了检索次数，表明重复查询更多源于模型对已获取信息的“遗忘”而非“缺失”，这反向验证了上下文化模块中缓存机制的必要性。

## 实验评估

| 模型变体 | Exact Match | LLM Match | Avg. # Searches |
| :--- | :--- | :--- | :--- |
| Qwen2.5-7b Search-R1 base (PPO) | 0.464 | 0.538 | 2.392 |
| base (PPO) w/ Cont (Ours) | 0.490 | 0.574 | 2.142 |
| base (PPO) w/ De-Dup (Ours) | 0.478 | 0.560 | 2.498 |
| base (PPO) w/ Hybrid (Ours) | 0.480 | 0.568 | 2.154 |

实验在HotpotQA和Natural Questions验证集的500个样本上进行，基线为Qwen2.5-7b Search-R1 (PPO)。上下文化模块在EM和LLM Match上均取得最高增益，分别提升5.6%和6.7%，同时将平均检索轮次从2.392降至2.142。去重模块虽然提升了EM，但平均检索轮次增至2.498，效率低于基线。混合策略在准确性上略低于纯上下文化，但效率接近。

去重模块的效率负迁移揭示了反直觉现象：模型重复检索并非因为缺乏新文档，而是因为无法从已有文档中提取有效信息。当去重模块强制提供新文档时，模型因未获得关键答案线索而继续生成相似查询，导致轮次增加。这一发现表明，单纯增加文档多样性无法解决推理瓶颈，关键在于信息的语义压缩与跨轮次保留。

评估协议存在局限：LLM Match指标依赖GPT-4.1-mini的主观判断，虽解决了EM对格式敏感的问题，但引入了评估器偏差。此外，实验未报告引入外部LLM后的总推理延迟与API成本，仅关注检索轮次，这使得“效率提升”的结论在工程部署层面缺乏完整支撑。代码未公开，且未对比Self-RAG等主流智能体基线，限制了结果的可比性。

## 关联研究分析

从信息处理机制看，本文与Search-o1（Li et al., 2025）均利用外部LLM提取信息，但Search-o1仅处理单步检索结果，而本文引入了持久化缓存 $C_i$。这一差异源于多跳推理中信息分散的特性：单步提取无法解决跨轮次依赖，缓存机制是应对“信息遗忘”的必要条件。然而，本文未探讨缓存长度对LLM上下文窗口的占用影响，当检索轮次增加时，累积缓存是否会导致新的“向量稀释”问题，论文未给出回答。

从优化路径看，本文属于测试时增强，与ACQO（Wen et al., 2026）的训练时优化形成对比。ACQO通过RL动态决定检索时机，实现了9.1倍推理加速，而本文通过减少冗余轮次提升效率。两者差异在于，ACQO优化的是“何时检索”，本文优化的是“检索后如何利用”。本文方法无需重新训练模型，部署成本低，但依赖外部API，这与ACQO的纯参数化方案在成本结构上存在根本差异。在延迟敏感的企业级场景中，外部LLM调用的网络开销可能抵消减少检索轮次带来的收益，这一权衡在论文中未被量化。

## 总结

本文针对智能体RAG中因信息遗忘导致的冗余检索问题，提出了基于外部LLM的上下文化与去重测试时策略。通过引入持久化记忆缓存，该方案在HotpotQA上将EM提升5.6%并降低检索轮次，证明了信息提取与推理解耦的有效性。然而，实验仅基于500个样本且未报告总推理成本，去重模块的效率负迁移也揭示了模型对已获取信息利用不足的深层原因。当检索轮次增加导致缓存累积时，外部LLM处理延迟与上下文窗口限制是否会成为新的瓶颈，论文未给出回答。
