# HuggingFace最新推荐论文 ｜Mozi: Governed Autonomy for Drug Discovery LLM Agents ｜受治理的药物发现智能体

作者：He Cao、Siyu Liu、Fan Zhang 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.03655)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.03655)

> 药物发现全流程涉及从靶点识别到先导化合物优化的长程依赖任务，现有通用大语言模型（LLM）智能体因缺乏约束机制，易在长程执行中产生轨迹漂移与工具调用幻觉。Mozi 通过引入双层架构，将 LLM 的推理灵活性与计算生物学的确定性执行解耦，实现了受治理的自主性。该框架在 PharmaBench 和 HLE 基准上展示了优于基线的编排准确率，但其性能提升主要源于架构约束而非模型能力突破，且缺乏对治理开销与发现效率权衡的量化评估。

## 研究背景

药物发现流程包含靶点识别、命中识别、命中转先导及先导优化等阶段，各阶段输出严格依赖前序结果。这种长程因果依赖要求智能体在执行中维持状态一致性，任何早期错误（如错误的 PDB 结构选择）都会导致后续计算资源浪费与结果失效。传统 ReAct 循环允许 LLM 自由调用工具，但在高成本、强约束的科学计算场景中，这种自由度导致参数幻觉与不可复现性，使得智能体难以满足制药行业的审计与合规要求。

现有科学智能体框架如 Biomni 和 DrugPilot 侧重于工具库扩展或记忆池管理，但未能解决长程任务中的错误累积问题。Biomni 提供 150+ 验证工具，但缺乏对工具调用顺序与权限的硬性约束；DrugPilot 通过参数化记忆减少 I/O 错误，但未建立层级化的监督机制。Mozi 的切入点在于将“治理”形式化为架构组件，而非仅依赖提示工程。它区分了负责推理的控制面与负责执行的工作流面，通过有状态技能图（Skill Graphs）将标准操作流程（SOP）编码为可执行工件，从而在保留 LLM 灵活性的同时，确保执行轨迹的确定性与可审计性。

## 核心方法

### 双层架构与状态空间定义

Mozi 将智能体执行形式化为元组 $M = \langle S, T, A, \Pi \rangle$，其中状态空间 $S$ 为混合结构 $s_t = (c_t, D_t)$。$c_t$ 表示非结构化交互上下文（意图、历史、推理轨迹），$D_t$ 表示结构化科学工件（靶点列表、PDB ID、分子结构）。这种分离解决了 LLM 在长程任务中上下文窗口溢出与状态丢失的问题，确保推理逻辑与数据实体同步。

### 控制面：层级化监督与权限隔离

控制面（Layer A）实现 Supervisor-Worker 层级结构，取代扁平多智能体协作。Supervisor 执行有界规划循环，通过反思机制评估步骤完成度，并在失败时触发重规划。关键创新在于硬编码工具过滤（Hard-Coded Tool Filtering），通过角色基于访问控制（RBAC）物理限制 Worker 的工具列表。例如，研究 Worker 无法调用高成本对接集群。这种机制将治理从提示层提升至执行层，消除了 LLM 生成非法参数或越权操作的可能性。

### 工作流面：有状态技能图与数据契约

工作流面（Layer B）将药物发现流程编码为有向无环图（DAG）形式的技能图。每个节点代表一个原子操作，节点间通过格式适配器（Format Adapters）强制执行数据契约。例如，对接节点前必须通过 PDBFixer 验证结构完整性。这种设计将 SOP 转化为可执行代码，避免了纯生成式方法中“垃圾进，垃圾出”的失效模式。HITL 检查点嵌入高不确定性节点，允许专家在关键决策点干预，确保计算轨迹符合临床可行性。

## 实验评估

实验在 PharmaBench（88 任务）和 HLE 药物发现子集（28 任务）上进行，基线包括 Biomni、Gemini-2.5-Pro 等。PharmaBench 评估分类与回归任务，HLE 侧重科学推理与实验设计知识。

| 系统 | MCQ acc. | Class. acc. | Reg. (SMAPE) |
|---|---|---|---|
| Biomni (Qwen3-30B) | 1/26 | 23/54 | 1.433 (8 tasks) |
| Mozi (Qwen3-30B) | 2/26 | 25/54 | 1.420 (8 tasks) |
| Biomni (Qwen3-235B) | 4/26 | 20/54 | 1.599 (8 tasks) |
| Mozi (Qwen3-235B) | 6/26 | 33/54 | 1.169 (8 tasks) |

在 HLE 子集上，Mozi (Deepseek-V3.2) 取得 21.42% 的精确匹配准确率，优于 Biomni (Claude-4.5-Sonnet) 的 17.86% 和 Gemini-2.5-Pro 的 10.71%。

消融分析显示，Mozi 的性能提升与基座模型规模正相关，Qwen3-235B 在分类任务上较 30B 版本提升 8 个百分点。然而，论文未提供治理机制本身的消融实验，无法区分性能提升源于架构约束还是模型能力。

评估边界方面，PharmaBench 任务量较小，可能不足以代表全流程复杂度；HLE 子集侧重知识检索，未充分测试长程生成能力。可复现性方面，论文提供主页面 URL，但未公开完整超参数与 GPU 配置细节，案例研究依赖 4x NVIDIA A6000 48GB GPU，硬件门槛较高。

## 关联研究分析

从问题动机看，Mozi 与 Biomni 均旨在解决 LLM 在科学工具调用中的幻觉问题，但路径截然不同。Biomni 通过扩展工具库与代码生成提升覆盖度，假设更多工具能解决更多问题；Mozi 则通过限制工具访问与强制流程合规提升可靠性，假设约束能抑制错误累积。这种差异源于对“灵活性”与“安全性”权衡的不同侧重：Biomni 面向探索性研究，Mozi 面向合规性生产。Mozi 的硬编码过滤机制虽提升了稳定性，但可能限制了 LLM 发现非标准路径的能力，这在数据稀疏的新靶点场景中是否成为瓶颈，论文未给出回答。

从方法设计看，Mozi 与 DrugPilot 均强调 I/O 约束，但实现层级不同。DrugPilot 通过参数化记忆池在提示层管理状态，依赖 LLM 的上下文理解能力；Mozi 通过工作流面在代码层执行状态管理，依赖确定性编程逻辑。Mozi 的设计更贴近软件工程中的状态机模式，牺牲了 LLM 的即时适应性，换取了执行的可预测性。这种设计在长程任务中优势明显，但在短程、高动态任务中可能引入不必要的延迟。Mozi 未对比两种机制在混合任务负载下的性能差异，其适用边界尚不明确。

## 总结

Mozi 针对 LLM 智能体在药物发现长程任务中的轨迹漂移与合规性缺失问题，提出双层架构解耦推理与执行。通过控制面的层级化监督与工作流面的有状态技能图，Mozi 在 PharmaBench 和 HLE 基准上实现了优于基线的编排准确率，其中 HLE 子集精确匹配准确率达 21.42%。然而，实验未量化治理机制对计算效率的影响，且案例研究依赖特定硬件配置，限制了结论的普适性。当任务复杂度增加至涉及多靶点联合优化时，HITL 检查点的触发频率与专家干预成本如何平衡，论文未给出回答。
