# HuggingFace最新推荐论文 ｜Agent Error Dataset: Scaling 50,000 Error--Diagnosis Pairs for Failure Analysis and Error-Aware Post-Training ｜智能体错误数据集与后训练

作者：Kunlun Zhu、Xuyan Ye、Yibo Li 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.40111)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.40111)

> 智能体在动态环境中的失败往往源于多步推理中的局部决策错误，而非最终输出偏差，但现有评估体系仅关注任务成功率，无法定位具体失效环节。现有失败分析工作如MAST和AgentDebug虽能识别错误模式，但缺乏将诊断转化为可执行修正并验证其有效性的闭环机制。本文通过构建包含50,228个错误-诊断对的Agent Error Dataset（AED），并设计五阶段Agentic Error-to-Training（AET）流水线，将自然发生的失败轨迹转化为支持诊断学习与行动恢复的训练视图。该工作首次实现了失败经验在诊断与恢复两个维度上的规模化复用，但其公开基准泛化能力受协议依赖限制，内部标签一致性高而外部表现波动，暴露了数据规模与泛化能力间的非单调关系。

## 研究背景

当智能体在WebArena或SWE-bench等环境中执行长时程任务时，早期步骤的参数错误会沿轨迹累积，导致后续动作偏离目标，最终任务失败。这种错误累积现象要求评估不仅关注最终状态，还需定位具体失效步骤，即精确步骤归因（Exact-Step Attribution）。然而，现有归因方法如Who&When和AgenTracer虽能识别责任代理与错误位置，但其标注目标局限于失败分析，未直接指定智能体应学习的替代动作，导致诊断结果无法直接转化为训练信号。

智能体后训练领域已探索从失败经验中学习的路径，AgentTuning使用奖励过滤轨迹进行监督微调，RAGEN将策略优化扩展至多轮环境反馈，但这些方法仅依赖结果奖励，无法指明哪个决策需要修正或应替换为何种动作。失败轨迹保留了智能体观察到的信息、选择的动作及环境响应，这些结构化信息若能有效转化，可同时提升诊断能力与行动恢复能力。本文切入点在于构建连接自然失败、诊断解释、修正提案与执行证据的统一数据集，解决现有资源在执行设置、标注目标与修正证据上的碎片化问题，使失败经验成为可复用的监督信号。

## 核心方法

### 方法参照系

本文问题属于智能体后训练中的数据驱动分支，与AgentDebug的诊断-修正范式最为接近，但关键差异在于：AgentDebug针对单实例失败进行交互式修复，而AED将失败转化为批量训练数据，需解决跨环境、跨框架的失败模式泛化问题，且必须验证修正的有效性而非仅生成文本解释。

### 五阶段AET流水线

AET流水线在数据生成环节引入证据接地与配对回放验证，解决此前方法中诊断缺乏执行证据支撑的问题。阶段1收集自然失败，保留动作-观察轨迹；阶段2生成带轨迹引用的诊断与修正提案；阶段3通过结构性与语义检查验证诊断在智能体可见轨迹中的接地性；阶段4在支持回放的环境中，将修正动作与同一检查点的原始动作重试进行配对对比；阶段5构建诊断SFT、恢复SFT与动作偏好三种训练视图。配对回放的核心公式为：

$$\Delta_{\text{replay}} = \mathbb{E}[\mathbb{1}(\text{verifier}(a^+) = \text{pass})] - \mathbb{E}[\mathbb{1}(\text{verifier}(a^-) = \text{pass})]$$

其中 $a^+$ 为修正动作，$a^-$ 为原始动作重试，该差值量化修正在受控条件下的效用。此设计解决了此前方法中修正提案无法验证有效性的问题，3,062个配对回放对显示修正动作将验证器通过率从18.4%提升至51.1%，增益32.7个百分点。

### 诊断与恢复训练视图

训练视图构建在损失函数层面区分诊断与恢复目标，解决单一SFT目标无法同时优化定位能力与行动能力的问题。诊断视图使用完整诊断目标 $y_i = d_i = (t_i^*, u_i^*, e_i, a_i^*)$，包含归因步骤、责任代理、证据解释与修正提案；恢复视图使用预错误历史与执行通过的动作对 $(h_{<t}, a_t^+)$，或添加原始错误动作及其拒绝作为掩码上下文。诊断损失采用每样本均值：

$$L_{\text{diag}}(\theta) = \frac{1}{|B|} \sum_{i \in B} \ell_i(\theta)$$

其中 $\ell_i(\theta) = -\sum_k m_{ik} \log \pi_\theta(y_{ik} | x_i, y_{i,<k})$，仅目标助手令牌接收损失。此设计使诊断学习聚焦于定位准确性，而恢复学习聚焦于动作有效性，避免目标混淆导致的性能退化。

## 实验评估

实验在943个内部教师标签案例上评估诊断能力，在3,062个配对回放对上评估修正效用，在WebShop-lite、TextQuest等6个环境上评估行动恢复。基线覆盖Qwen3-8B基座、GPT-6 Astra、Claude Opus 5等前沿模型，但缺失传统SFT基线如AgentTuning的直接对比，仅通过成功轨迹SFT作为对照。

| 模型/训练资源 | 内部精确步骤一致性 (%) | Who&When HC 代理/步骤 (%) | AgentErrorBench 环境宏平均 (%) |
| :--- | :--- | :--- | :--- |
| Qwen3-8B 基座 | 47.2 | 56.90/20.69 | 16.67/1.67 |
| AED 诊断 SFT | 63.6 | 50.00/15.52 | 20.33/5.00 |
| AED + 答案格式多样性 | 63.6 | 70.69/24.14 | 22.00/3.00 |
| Claude Opus 5 | 54.7 | 43.10/24.14 | — |

内部精确步骤一致性从47.2%提升至63.6%，超过Claude Opus 5的54.7%，但在Who&When公开协议下，AED SFT的代理归因准确率（50.00%）低于基座（56.90%），显示内部标签过拟合。修正效用方面，首次提案修正将验证器通过率从18.4%提升至51.1%，增益32.7个百分点（95%区间28.4–37.0）。行动恢复实验中，动作-only修复训练在WebShop-lite上比成功-only训练高6.67个百分点，但在TextQuest上低9.00个百分点，Holm调整后显著性仅保留于WebShop-lite增益与TextQuest损失。

消融显示，答案格式多样性在Who&When手工艺条件下将代理归因从50.00%提升至70.69%，但在算法生成条件下未超过基座，表明格式敏感性依赖任务类型。评估边界方面，内部标签由共识生成，可能引入系统性偏差；公开基准对比受任务重叠、提示格式与步骤索引协议影响，无法建立广泛泛化结论。代码与数据将在agenterrordata.apodex.com发布，但回放验证仅覆盖部分任务，未覆盖任务的修正有效性未经验证。

## 关联研究分析

从问题动机看，AED与AgentDebug共享诊断-修正范式，但AgentDebug针对单实例失败进行交互式修复，其修正有效性依赖人工验证，而AED通过配对回放实现自动化验证，将修正效用量化为32.7个百分点的增益。这一差异源于任务特性：AgentDebug适用于高价值单任务场景，而AED面向规模化后训练，需批量验证修正的统计显著性。然而，AED的回放验证仅覆盖支持回放的环境，对于无法执行回放的任务，修正有效性仍依赖文本诊断，这一限制在论文中未充分讨论。

从方法设计看，AED与MAST在失败分类上存在根本差异：MAST使用固定分类法组织失败模式，而AED采用自由文本诊断，保留更多细节但增加标注一致性难度。AED报告85.5%的原始步骤一致性（59/69），低于MAST的κ=0.88，表明自由文本诊断在跨标注者一致性上存在劣势。这一差异是任务特性决定还是标注协议选择的结果，论文未给出明确回答。此外，AED未与AgenTracer的强化学习系统进行直接对比，仅通过数据资源对比，无法隔离训练方法对性能的影响。

## 总结

AED要解决的核心矛盾是智能体失败经验无法同时转化为诊断能力与行动恢复能力的监督信号，现有方法要么局限于失败分析，要么依赖结果奖励无法定位具体失效环节。本文通过构建50,228个错误-诊断对并设计五阶段AET流水线，将自然失败转化为支持诊断SFT与恢复SFT的训练视图，证明了修正动作在配对回放中将验证器通过率从18.4%提升至51.1%，内部精确步骤一致性从47.2%提升至63.6%。其边界在于公开基准泛化能力受协议依赖限制，Who&When公开协议下代理归因准确率低于基座，且回放验证仅覆盖部分任务。当支持回放的环境比例降至50%以下时，修正效用的统计显著性是否仍成立，论文未给出回答。
