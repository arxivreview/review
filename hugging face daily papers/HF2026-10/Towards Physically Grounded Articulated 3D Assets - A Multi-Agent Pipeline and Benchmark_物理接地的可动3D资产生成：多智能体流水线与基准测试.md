## 研究背景

当生成模型试图合成可动3D资产时，外观、几何、关节结构与物理属性之间存在强烈的相互依赖关系。若仅优化视觉逼真度，生成的网格往往缺乏明确的拓扑结构，导致后续部件分解断裂；若缺乏物理接地，资产在重力或碰撞测试中会瞬间崩溃。这一困境构成了物理接地生成的核心挑战：如何在保证几何一致性的前提下，将3D生成从视觉表象的统计拟合扩展为具备交互能力的功能性资产合成。

早期研究受限于三维数据稀缺，主要依赖二维扩散模型的分数蒸馏采样（Score Distillation Sampling, SDS）来优化隐式表示，虽然降低了数据门槛，却受制于多视图一致性问题与极慢的优化速度。随着大规模三维数据集的涌现，研究范式转向基于紧凑潜空间的原生三维生成，潜空间扩散模型（Latent Diffusion Model, LDM）成为主流。然而，当前领域正经历从追求单体几何保真度向生成结构化、可交互功能资产的深刻转变。现有方法要么通过联合生成在潜空间同时预测几何与物理属性，要么通过后处理解耦提取结构，但均难以在工程落地中同时满足高保真几何与严格物理约束。ARTISAN 抓住了这一痛点，通过引入物理仿真器作为反馈源，将程序化代码生成与物理验证闭环结合，填补了从单体几何到功能化资产的演进空白。

## 核心方法

### 方法参照系：程序化代码生成与物理验证闭环

ARTISAN 属于程序化代码生成与物理仿真资产的交叉路线。其标准流程通常由大语言模型（Large Language Model, LLM）生成构建3D对象的程序代码，但传统单智能体方法存在自我评估偏差，且缺乏对物理属性的显式验证。本文的关键差异在于将生成过程拆解为多智能体协作，并引入 MuJoCo 物理仿真器作为硬性约束反馈源，形成“生成-验证-修复”的闭环。

### 多智能体协作架构

该架构由 Design Agent、Coding Agent 和 Review Agent 组成，旨在消除单智能体的自我评估偏差。Design Agent 输出结构化文本蓝图 $B$ 和设计板 $D$：

$$ A_{\text{design}}(p, I) \rightarrow (B, D), \quad \text{where } B = \{ \tilde{G}_i, \tilde{M}_i \}_{i=1}^P, (\tilde{K}, \tilde{J}), Q $$

该公式表明蓝图不仅包含几何 $\tilde{G}_i$ 和材质 $\tilde{M}_i$，还包含运动学结构 $\tilde{K}$、关节 $\tilde{J}$ 及功能约束 $Q$。Coding Agent 基于蓝图生成 Python 程序 $\Pi_t$ 并执行得到资产 $O_t$，Review Agent 则独立评估资产并输出分数 $S_t$ 和问题列表 $R_t$。这种独立性确保了审查标准不被生成逻辑污染，解决了此前方法中“自己出题自己答”导致的物理缺陷遗漏。

### 物理仿真反馈与标准连接器

Coding Agent 在生成过程中利用参数化标准连接器（如铰链、滑轨）构建关节，减少几何设计错误。物理验证模块在 MuJoCo 中执行碰撞与稳定性检查。碰撞检测通过凸分解构建网格碰撞几何，模拟单关节、双关节及多关节运动，记录穿透深度。稳定性测试则评估资产在重力下的倾斜角与位移。物理报告 $E_t$ 作为反馈输入 Coding Agent，指导其修复程序。这一设计将物理约束从后处理提升为生成循环的一等公民，确保了资产在仿真环境中的即时可用性。

## 实验评估

实验在 ArtVIP 和 LightWheel 数据集上评估空间保真度，在自建数据集上评估物理属性。基线覆盖学习式方法（Instruct-Particulate）、单智能体方法（Articraft）及通用编码代理（Codex）。ARTISAN 在空间保真度上取得竞争性成绩，同时在物理属性上显著超越现有方法。

| 方法 | 碰撞率 (Single) ↓ | 碰撞率 (Multiple) ↓ | 稳定性 (Rest) ↑ | 稳定性 (Open) ↑ |
| :--- | :--- | :--- | :--- | :--- |
| Instruct-Particulate | 70.4 | 98.7 | 68% | 42% |
| Articraft (GPT-6 Astra) | 45.5 | 78.8 | 82% | 82% |
| Codex (GPT-6 Astra) | 32.4 | 63.7 | 86% | 82% |
| ARTISAN (GPT-6 Astra) | 1.7 | 13.0 | 98% | 96% |

ARTISAN 将单关节碰撞率从 Articraft 的 45.5% 降至 1.7%，多关节碰撞率从 78.8% 降至 13.0%，稳定性提升至 98%。消融实验表明，移除物理验证后，碰撞率显著回升，证明物理反馈是生成可用资产的关键。在下游机器人任务中，使用 ARTISAN 资产训练的 $\pi_{0.5}$ 策略在 RoboTwin 2.0 上的成功率为 63%，高于 Articraft 的 60%；结合原生资产后成功率提升至 84%。

评估边界方面，空间保真度指标（如 Chamfer Distance）与学习式方法相比存在精度瓶颈，程序化表示难以捕捉极细微的几何噪声。此外，多智能体协作带来的计算开销与推理延迟限制了实时应用，论文未报告具体的生成耗时。

## 关联研究分析

从问题动机看，ARTISAN 与 PhysGen 均致力于物理接地，但 PhysGen 采用联合生成策略，在潜空间同时编码几何与物理属性，而 ARTISAN 采用程序化生成加后验证策略。PhysGen 在 DrivAerNet++ 上取得 F-score 0.95，表明联合生成在特定物理引导任务上的有效性，但 ARTISAN 在通用可动资产上的碰撞率更低，暗示程序化控制在处理复杂关节耦合时更具灵活性。

从方法设计看，ARTISAN 直接改进 Articraft 的单智能体架构。Articraft 依赖 LLM 自我验证，易产生自我评估偏差；ARTISAN 引入独立 Review Agent 和物理仿真器，将验证标准从“代码逻辑正确”提升至“物理行为正确”。这一差异源于任务特性：可动资产的物理可用性无法仅通过视觉或代码静态分析保证，必须依赖动态仿真反馈。

## 总结

ARTISAN 解决了可动3D资产生成中物理属性与几何结构割裂的核心矛盾，通过多智能体协作与物理仿真反馈闭环，实现了从视觉逼真到功能可用的跨越。其方法将 Design、Coding、Review 三个独立智能体与 MuJoCo 仿真器结合，显著提升了资产的物理合理性。实验证明，ARTISAN 将单关节碰撞率降至 1.7%，稳定性提升至 98%，并在下游机器人任务中表现出更高的资产可用性。然而，该流水线依赖 LLM 生成代码，其拓扑稳定性是否足以支撑复杂非刚体资产的物理仿真，以及多智能体协作带来的计算开销是否限制了实时应用，仍是该方向需要进一步验证的问题。
