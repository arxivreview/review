# HuggingFace最新推荐论文 ｜RoboJev: An Open Vision-Language Judge for Robot Success Detection ｜机器人操作视频成功检测的视觉-语言判定器

作者：Josef Liyanjun Chen

论文原文见 [arXiv](https://arxiv.org/abs/2610.33718)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.33718)

> 机器人操作策略的强化学习后训练与评估依赖高质量的成功/失败标签，但真实世界视频缺乏机器可读的结局标注，低层启发式规则难以覆盖语义多样性。现有基于视觉-语言模型（Vision-Language Model, VLM）的评估器多依赖闭源 API 或专用分类器，存在成本高昂、跨域泛化能力不透明及校准失效等问题。RoboJev 提出一种开源的 VLM 判定器，通过冻结视觉编码器、仅对语言模型施加低秩适应（Low-Rank Adaptation, LoRA）并引入源特定 KL 散度锚定，实现单前向传播的校准成功概率输出。该工作验证了 VLM 在特定本体上的高精度判别能力，但其在未见域上的泛化增益有限，且微调可能损害跨域排序能力，提示评估器鲁棒性需依赖基础模型而非微调适配。

## 研究背景

当机器人策略在真实环境中执行长时程任务时，微小的感知偏差或动作抖动会导致任务失败，而传统评估依赖人工标注或基于轨迹平滑度、终点距离的低层启发式规则。这些规则无法理解“将彩色环插入中央木钉”等语义指令，导致在复杂操作中的误判。为解决此问题，研究者引入 VLM 作为零样本评估器，利用其互联网规模的语义先验判断视频结局。然而，直接调用闭源 API 成本高且延迟不可控，而训练专用分类器则面临跨本体、跨环境泛化困难的问题。

当前，利用 VLM 进行机器人成功检测已成为强化学习后训练（如 SimpleVLA-RL）和奖励建模（如 RoboReward）的关键基础设施。主流路线包括基于对比学习的视频-语言批评家（Video-Language Critic）和基于帧进度损失的奖励模型（Robometer）。这些方法通常输出连续奖励信号或依赖复杂的时间排序损失，计算开销大。RoboJev 的切入点在于：将成功检测简化为二分类问题，通过参数高效微调保留 VLM 的通用语义理解能力，同时通过校准机制确保输出概率的物理意义，从而提供低成本、可复现的开源评估工具。

## 核心方法

### 任务条件化判定架构

RoboJev 将成功检测建模为任务条件化的二分类问题。输入包括任务指令 $u$、主摄像头的 10 个均匀采样帧 $V$ 以及辅助摄像头的最终帧。模型基于 JEV-27B-VL 骨干，冻结视觉编码器和视觉合并层，仅对语言模型部分应用 Rank-32 LoRA。这种设计动机在于保留预训练 VLM 的视觉-语义对齐能力，避免微调导致视觉特征退化。模型在指定位置生成 `false` 和 `true` 两个答案 Token 的 Logits $z_0, z_1$，通过校准读出机制输出成功概率：

$$
p_\theta(y=1 | u, V) = \frac{\exp((z_1 + b_1)/T)}{\sum_{c \in \{0,1\}} \exp((z_c + b_c)/T)}
$$

其中 $b_c$ 为基础偏置，$T=0.9$ 为温度参数。该公式将原始 Logits 映射为校准后的概率分布，确保输出值可直接用于阈值决策或奖励计算，而非仅作为排序分数。

### 源特定 KL 锚定与数据平衡

针对多源异构数据（如 RBM-1M、DROID、社区视频）导致的分布偏移，RoboJev 引入源特定 KL 散度锚定。训练目标函数为：

$$
L_i = w_i \text{CE}(y_i, q_\theta(x_i)) + \lambda a(x_i) D_{\text{KL}}(q_0(x_i) \| q_\theta(x_i))
$$

其中 $q_\theta$ 为适配模型输出，$q_0$ 为基础模型输出，$a(x_i)$ 为源指示函数。该设计动机在于防止微调过度拟合特定研究数据集（如 ViFailback）的视觉特征，从而损害跨域泛化能力。仅对研究数据源施加 $\lambda=1$ 的 KL 惩罚，将模型输出锚定在基础模型分布附近；社区数据则无此约束，允许模型学习更广泛的分布。同时，对合成负样本赋予固定权重 $w_i=0.5$，对原始样本使用源平衡权重，以缓解类别不平衡。

## 实验评估

实验在三个互补测试集上进行：SO-101 留出集（268 个回合）、未见域（459 个回合，来自不同实验室/机器人）和社区视频（135 个明确标注回合）。基线包括基础模型 JEV-27B-VL、闭源 API 模型（GPT-6 Astra, Claude Opus 5.5）及 Robometer。

| 方法 | SO-101 平衡准确率 (%) | SO-101 AUROC | 未见域 AUROC | 社区准确率 (%) |
| :--- | :---: | :---: | :---: | :---: |
| RoboJev-27B | 95.2 | 0.993 | 0.890 | 93.3 |
| Base JEV-27B-VL | 88.1 | 0.979 | 0.900 | - |
| GPT-6 Astra | 93.3 | - | - | 92.6 |
| Claude Opus 5.5 | - | - | - | 94.1 |

RoboJev 在 SO-101 上显著优于基础模型（平衡准确率提升 7.08 个百分点），但在未见域上 AUROC 为 0.890，略低于基础模型的 0.900。这表明微调在特定本体上有效，但未带来跨域泛化增益。

消融实验显示，KL 锚定对跨域性能至关重要。无锚定变体（DB）在未见域上的 AUROC 为 0.847，低于有锚定版本（DA）的 0.890。此外，时间上下文对判别能力有显著影响：仅使用最终帧时，未见域 AUROC 降至 0.776，而 10 帧协议提升至 0.890。

评估边界方面，RoboJev 的校准误差（ECE）在 SO-101 上为 0.032，但在未见域上激增至 0.148，表明模型在分布外环境中倾向于低估成功概率。社区数据中 32.5% 的回合被标记为“模糊”，未纳入二分类指标，提示评估器在不可观测事件上的局限性。

## 关联研究分析

从问题动机看，RoboJev 与 Robometer 均致力于利用 VLM 进行机器人奖励建模，但 Robometer 采用帧进度损失和轨迹偏好监督，输出连续奖励信号，适用于密集奖励场景；RoboJev 则聚焦终端二分类，通过温度缩放确保概率校准，更适用于稀疏奖励的强化学习后训练。RoboJev 的开源权重与完整评估预测集提供了可复现的基线，而 Robometer 的 RBM-1M 数据集虽被用于训练，但其模型未作为直接基线对比，导致无法直接量化两者在相同输入协议下的性能差异。

从方法设计看，RoboJev 与 SimpleVLA-RL 形成互补。SimpleVLA-RL 依赖成功/失败标签进行策略优化，而 RoboJev 提供了自动化标签生成工具。然而，RoboJev 在未见域上的泛化能力未超越基础模型，这与领域共识中“微调提升泛化”的预期存在冲突。这一冲突暗示，对于评估器任务，基础 VLM 的通用语义理解可能比任务特定微调更重要，微调可能过拟合特定机器人的视觉特征（如 SO-101 的机械臂外观），从而损害跨本体鲁棒性。

## 总结

RoboJev 解决了机器人操作视频缺乏机器可读成功标签的问题，通过冻结视觉编码器、LoRA 微调语言模型及源特定 KL 锚定，构建了开源的 VLM 判定器。其在 SO-101 上达到 95.2% 平衡准确率，验证了 VLM 在特定本体上的高精度判别能力。然而，其在未见域上的 AUROC（0.890）低于基础模型（0.900），且校准误差激增，表明微调未带来跨域泛化增益，反而可能损害排序能力。该工作的边界在于评估器鲁棒性高度依赖基础模型而非适配策略。当部署到新实验室或新机器人时，是否应完全放弃微调而直接使用基础模型，或仅对语言模型进行极小幅度适配，论文未给出明确回答。
