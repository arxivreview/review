> 导读 用户中心型智能体（User-Centric Agent）在强化学习（Reinforcement Learning, RL）训练中面临核心矛盾：学习信号不仅取决于策略本身，还受模拟用户与环境稳定性的制约。现有方法多通过奖励塑形或密集监督来优化固定基础设施产生的噪声信号，却忽略了模拟用户的随机性漂移与环境验证器错误导致的信号失真。本文提出 EAU（Environment-Agent-User Co-Evolution）框架，引入元代理（Meta-Agent）在训练过程中动态诊断并热更新用户模拟器、环境规则及 RL 超参数。该框架将训练系统从静态基础设施转变为与策略共同进化的动态组件，显著提升了多轮交互任务的成功率。然而，元代理干预决策的可解释性及动态环境对评估基准可比性的潜在影响，仍是该方向需进一步厘清的边界。

## 研究背景

当智能体在用户中心型任务中执行多轮交互时，其决策过程需同时处理环境工具调用与模拟用户对话。这一过程通常被建模为部分可观测马尔可夫决策过程（Partially Observable Markov Decision Process, POMDP），其中环境状态由工具状态、用户状态及查询意图共同构成。由于模拟用户基于大语言模型（Large Language Model, LLM）生成，其状态转移具有随机性，且可能偏离预设人设或提前泄露信息；同时，环境中的工具行为或验证器可能存在覆盖不全或逻辑错误。这种基础设施的不稳定性导致 RL 训练信号高度可变或系统性误导，严重破坏策略优化的收敛性。

主流研究路线主要聚焦于优化呈现给策略的监督信号，例如通过奖励塑形（Reward Shaping）奖励部分进度，或引入辅助监督提供密集信号。然而，这些方法将用户模拟器和环境视为固定基础设施，未能解决信号源头的失真问题。若工具静默失败或验证器错误拒绝成功轨迹，下游奖励调整无法恢复预期的交互逻辑。此外，随着策略能力提升，固定的模拟器和环境可能持续生成冗余或无信息量的轨迹，无法针对策略当前的弱点提供有效训练信号。EAU 框架正是针对这一被忽略的根因，提出将干预前移，通过元代理持续诊断并修订交互过程本身，实现训练系统与策略的协同进化。

## 核心方法

### 方法参照系：固定基础设施下的策略优化

在标准用户中心型 RL 中，智能体策略 $\pi_\theta$ 通过最大化任务成功奖励 $R_{task}$ 进行优化，同时受对话奖励 $r_{conv}$ 约束。该流程通常采用 Proximal Policy Optimization (PPO) 算法，结合广义优势估计（Generalized Advantage Estimation, GAE）计算动作优势。然而，该参照系假设环境 $E$ 和用户模拟器 $u$ 在训练全程保持不变，导致策略只能在固定且可能失真的交互分布中学习，无法适应策略演化带来的新需求。EAU 将这一静态流程重构为动态协同进化系统，元代理作为外部控制器，实时介入用户、环境与策略三个维度。

### 用户模拟器进化：符号化与 LLM 混合策略

针对 LLM 模拟用户随机性高、易幻觉的问题，EAU 引入符号化用户模拟器 $u_{sym}$，通过显式规则将解析后的交互状态映射为确定性响应。为平衡可控性与交互自然度，EAU 采用 $\epsilon$-符号化混合策略：

$$
u_\epsilon := \begin{cases} u_{sym}, & \text{with probability } \epsilon \\ u_{LLM}, & \text{with probability } 1 - \epsilon \end{cases}
$$

该公式定义了用户响应的生成机制，其中混合系数 $\epsilon \in [0, 1]$ 控制结构化监督与灵活交互的比例。元代理可根据训练轨迹动态调整 $\epsilon$ 及 LLM 的生成参数（如温度、人设提示词）。这一设计解决了纯 LLM 模拟器在长程任务中因随机性导致的奖励噪声问题，使元代理能够精确控制信息泄露的时机与条件，从而为策略提供更可靠的探索边界。

### 环境与策略协同进化：在线诊断与热更新

环境侧进化不依赖学习新的世界模型，而是通过程序化干预修改训练反馈。当元代理检测到策略因稀疏奖励难以探索时，可动态添加中间奖励规则以识别进度状态；若现有奖励诱导不良行为，则予以修订。策略侧进化则通过监控训练日志（如熵、KL 散度）动态调整 PPO 超参数。

EAU 支持运行内（Intra-run）与运行间（Inter-run）两种干预尺度。运行内干预允许将验证通过的修改（如符号规则更新、奖励调整）热交换（Hot-swap）至正在进行的训练循环中，无需从头重启。运行间干预则整合已完成运行的观察结果，修订后续训练设置。元代理维护一个经验池，记录哪些干预有效、哪些无效，从而在跨运行训练中避免重复错误。这种机制将训练系统本身转化为可学习组件，使环境复杂度与策略能力同步提升。

## 实验评估

实验在 UserGym、ColBench 和 $\tau$2-bench 三个用户中心型基准上进行，骨干模型选用 Qwen3-4B 和 Qwen2.5-7B-Instruct。基线覆盖包括闭源模型提示（GPT-4.1, Gemini-3-Flash）、开源模型提示（ReAct, Reflexion）及多种 RL 方法（RAGEN, Search-R1, UserRL, InfoPO, PPO）。EAU 在所有设置中均取得最优性能，尤其在 ColBench 任务上，相比最强基线 InfoPO 提升显著。

| 方法 | 骨干模型 | UserGym Avg. | ColBench Avg. | Overall |
| :--- | :--- | :--- | :--- | :--- |
| InfoPO | Qwen3-4B | 0.496 | 0.545 | 0.545 |
| PPO | Qwen3-4B | 0.242 | 0.462 | 0.462 |
| **EAU (Ours)** | **Qwen3-4B** | **0.643** | **0.627** | **0.627** |
| InfoPO | Qwen2.5-7B | 0.480 | 0.544 | 0.544 |
| PPO | Qwen2.5-7B | 0.298 | 0.508 | 0.508 |
| **EAU (Ours)** | **Qwen2.5-7B** | **0.596** | **0.615** | **0.615** |

在 Qwen3-4B 骨干上，EAU 的 Overall 得分达到 0.627，较 InfoPO 的 0.545 提升 15.0%；在 ColBench 子集上，成功率提升幅度最高达 36.7%。消融分析显示，元代理在训练早期倾向于提高熵系数以增强探索，而在后期则通过降低熵和 KL 系数来稳定策略，并动态调整 $\epsilon$ 以平衡符号规则与 LLM 交互。

评估边界方面，实验仅使用训练侧反馈指导元代理干预，未利用测试集信息，避免了数据泄露。然而，动态修改环境奖励和模拟用户规则可能导致不同运行间的训练分布不一致，现有基准未提供跨运行可比性的标准化协议。此外，元代理的具体干预决策（如何时重启训练）依赖其内部推理，缺乏细粒度的可解释性监控机制。

## 关联研究分析

从问题动机看，EAU 与 Agent0（Xia et al., 2025）均关注智能体的自进化，但二者解决的核心瓶颈不同。Agent0 侧重于通过课程 Agent 与执行 Agent 协同进化解决高质量训练数据稀缺问题，其环境生成主要依赖合成数据；EAU 则聚焦于用户中心型任务中固定基础设施导致的信号失真，强调在训练过程中在线诊断并修复模拟用户与环境的具体缺陷。这一差异源于任务特性：Agent0 面向通用工具使用，环境相对静态；EAU 面向多轮对话，用户模拟器的随机性是主要噪声源。

从方法设计看，EAU 与 Reflexion（Shinn et al., 2023）均引入反馈机制优化智能体，但干预层级存在本质区别。Reflexion 通过语言反馈优化策略自身的推理轨迹，属于策略层面的自我修正；EAU 的元代理则直接修改环境规则、用户模拟逻辑及 RL 超参数，属于训练系统层面的重构。Reflexion 无法解决因验证器错误或工具静默失败导致的奖励误导，而 EAU 通过热更新环境组件直接消除这些噪声源。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但 EAU 的设计表明，在交互噪声主导的场景下，优化信号源比优化策略反馈更有效。

## 总结

本文针对用户中心型智能体 RL 训练中固定基础设施导致信号失真的核心矛盾，提出 EAU 框架，通过元代理动态诊断并热更新用户模拟器、环境规则及训练超参数，实现训练系统与策略的协同进化。实验表明，EAU 在 ColBench 等基准上较最强基线提升 15.0%，验证了动态调整训练系统比单纯优化策略反馈更有效。然而，元代理的干预决策依赖其内部推理，缺乏细粒度可解释性监控，且动态修改环境可能导致跨运行训练分布不一致。当元代理错误修改环境规则导致训练崩溃时，如何设计安全边界以防止不可逆的干预错误，是该框架走向实际应用前必须解决的工程难题。
