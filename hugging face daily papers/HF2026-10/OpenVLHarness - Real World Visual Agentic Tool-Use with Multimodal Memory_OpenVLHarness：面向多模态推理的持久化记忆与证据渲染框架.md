> 多模态大语言模型（Multimodal Large Language Models, MLLMs）在复杂视觉任务中常因缺乏外部证据而陷入推理瓶颈，单纯增加推理预算带来的性能增益已趋于饱和。现有工具使用框架多采用固定管线或依赖模型微调，难以处理异构工具输出的格式差异，且缺乏跨轮次的状态保持机制，导致多步推理中信息丢失。OpenVLHarness 提出了一种无需更新模型权重的通用推理框架，通过能力层将异构工具输出渲染为模型可读证据，并引入持久多模态记忆实现跨轮次工件复用。该框架在 22 个基准测试上显著提升了多种骨干模型的性能，证明了结构化证据获取与推理能力扩展的互补性，但其对骨干模型指令遵循能力的依赖程度仍需进一步验证。

## 研究背景

当 MLLMs 面对需要密集目标定位、长尾实体检索或精确数值计算的视觉任务时，仅凭模型内部参数无法可靠获取所需信息。这种“证据缺失”迫使模型依赖语言先验进行猜测，导致幻觉频发。为解决此问题，视觉工具使用（Visual Tool Use）应运而生，通过连接感知模型、搜索引擎和代码执行器来补充外部证据。然而，早期方法如程序合成（Program Synthesis）将问题编译为固定管线，无法根据工具执行结果动态调整后续步骤；后续的多轮交互框架虽引入了反馈机制，但往往依赖脆弱的任务特定设计或昂贵的模型微调，且工具返回的原始数据（如分割掩码、深度图）格式异构，难以被语言模型直接理解。

当前领域共识认为，工具增强能突破纯文本推理瓶颈，但现有方法在“证据可解释性”与“状态持久性”上存在显著缺陷。一方面，原始工具输出（如 RLE 编码掩码）若直接序列化进入上下文，不仅消耗大量 Token，且无法向模型直观展示分割对象；另一方面，多步推理中前一步骤生成的中间工件（如检测框、深度数组）若无法被后续步骤精确引用，模型便无法执行跨工具的组合计算。OpenVLHarness 正是针对这一被忽略的工程与认知瓶颈，提出通过统一的能力层接口与持久化记忆机制，实现证据的标准化渲染与跨轮次复用。

## 核心方法

### 方法参照系：训练无关的视觉代理框架

OpenVLHarness 属于训练无关（Training-free）的视觉代理框架，其核心流程为：MLLM 作为编排器（Orchestrator），根据用户查询选择工具，执行后观察结果，迭代直至生成最终答案。与 Visual Sketchpad 或 OctoTools 等同类框架相比，本文的关键差异在于引入了“能力层”以统一异构后端接口，并建立了“持久多模态记忆”以支持跨轮次工件寻址，从而将单次工具调用升级为带状态的多步组合推理。

### 能力层：任务级接口与证据渲染

在标准工具调用中，后端模型（如 SAM 3 或 Grounding DINO）返回的原始数据格式各异，直接输入 MLLM 会导致上下文污染或信息不可读。OpenVLHarness 设计了能力层（Capability Layer），包含任务级工具接口与模型面向的证据渲染（Model-facing Evidence Rendering）。任务级接口定义了操作语义、类型化输入及暴露的证据，屏蔽了后端实现差异。证据渲染则通过输出处理器将原始数据转换为模型可读的观察结果。

例如，视觉定位工具不仅返回边界框坐标，还生成带有标签的掩码叠加图像及简洁的自然语言描述。这一设计解决了原始数据序列化导致的上下文膨胀问题，使编排器能直观“看到”检测结果。其核心逻辑可形式化为：

$$
O_t = \mathcal{R}(T_t(I, Q))
$$

其中 $T_t$ 为工具执行函数，$I$ 为输入图像，$Q$ 为文本查询，$\mathcal{R}$ 为渲染函数，$O_t$ 为生成的模型面向观察结果。该公式表明，工具输出并非直接传入，而是经过特定渲染器处理，转化为包含视觉附件、文本描述及结构化信息的复合观察，确保模型能基于视觉事实而非抽象编码进行推理。

### 持久多模态记忆：跨轮次工件寻址与组合计算

能力层解决了单次调用的可解释性，但多步推理需要复用前序步骤生成的工件。传统框架中，工具生成的图像或数据在下一轮对话中往往丢失或仅以文本描述存在，导致后续工具无法直接引用原始数据。OpenVLHarness 引入持久多模态记忆（Persistent Multimodal Memory），为每个查询维护一个显式的工件注册表。

注册表将工件载荷（Payload）与句柄（Handle）分离，编排器仅可见句柄及紧凑描述符，而框架保留底层值。记忆包含三类工件：图像工件（如 `input_image_3`）、结构化数据绑定（如 `segment_cabinet: dict`）及网页引用（如 `webpage_url_1`）。每轮工具调用后，环境更新消息（Environment Update）广播当前可用的句柄命名空间。这一机制支持记忆导向的计算（Memory-grounded Computation），例如 Python 编码代理可读取存储的深度数组与分割掩码，执行如下组合计算：

$$
\text{Depth}_{\text{region}} = \frac{1}{|M|} \sum_{(x,y) \in M} D(x,y)
$$

其中 $M$ 为记忆中的分割掩码，$D$ 为记忆中的深度数组。该公式展示了如何通过句柄引用跨工具数据，实现从感知到计算的无缝衔接，解决了此前方法因状态丢失而无法执行复杂多步推理的失效问题。

## 实验评估

实验在 22 个涵盖基础感知、视觉搜索、通用 VQA 及空间推理的基准上进行，对比了 Qwen3-VL、GPT-6 等八种骨干模型。基线包括无工具基线（Base）、Codex、Visual Sketchpad 及训练式基线 AdaReasoner 等。OpenVLHarness 在所有骨干上均取得显著提升，且在相同骨干下优于训练式基线，证明了通用框架的泛化性。

| 骨干模型 | 方法 | 平均得分 (%) | 相对提升 (pts) |
| :--- | :--- | :--- | :--- |
| Qwen3-VL-8B | Base | 34.2 | - |
| Qwen3-VL-8B | OpenVLHarness | 45.4 | +11.2 |
| Qwen3-VL-32B | Base | 38.3 | - |
| Qwen3-VL-32B | OpenVLHarness | 50.9 | +12.6 |
| GPT-6 Sol | Base | 52.7 | - |
| GPT-6 Sol | OpenVLHarness | 64.3 | +11.6 |

消融实验验证了能力层与记忆机制的独立贡献。从基线到完整框架，逐步添加原始工具、能力层、文本记忆及多模态记忆。结果显示，能力层带来的证据渲染在基础感知任务上增益最大，而多模态记忆在视觉搜索与空间推理中贡献显著，表明跨轮次工件复用对复杂推理至关重要。

| 变体 | 基础感知 | 视觉搜索 | 通用 VQA | 空间推理 | 总体 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Baseline (no tool) | 27.48 | 18.40 | 57.97 | 44.38 | 37.06 |
| + Tools | 41.70 | 23.34 | 62.16 | 47.83 | 40.84 |
| + Capability layer | 46.73 | 21.44 | 61.41 | 48.16 | 44.23 |
| + Textual memory | 47.27 | 25.97 | 63.63 | 47.98 | 44.93 |
| OpenVLHarness | 45.46 | 33.10 | 66.12 | 50.82 | 47.14 |

评估边界方面，实验未覆盖计算效率的绝对对比，仅报告了模型 Token 成本。此外，部分基准（如 MMMU）未直接报告总分，而是通过 22 基准平均值间接反映性能，这可能掩盖了特定任务上的细微差异。代码与评估协议已开源，但部分专有模型（GPT-6）的结果为单次运行，缺乏统计显著性检验。

## 关联研究分析

从问题动机看，OpenVLHarness 与 Visual Sketchpad 均致力于解决 MLLMs 的证据获取问题，但 Visual Sketchpad 依赖手动设计的工具接口与执行策略，缺乏对异构后端输出的统一渲染机制，导致其在处理复杂多步任务时易因格式不兼容而失败。OpenVLHarness 通过能力层抽象了后端差异，使框架更具适应性。从方法设计看，与 AdaReasoner 等训练式方法相比，OpenVLHarness 无需更新模型权重即可超越其性能，挑战了“工具使用需专门微调”的共识。这一差异源于训练式方法过拟合于固定工具集，而通用框架通过结构化记忆保留了模型的原始推理能力。然而，OpenVLHarness 对骨干模型的指令遵循能力高度依赖，当骨干模型较弱时（如 Qwen2.5-VL-7B），其性能显著低于训练式方法，暗示了通用框架在低能力模型上的局限性。

## 总结

OpenVLHarness 针对 MLLMs 在复杂视觉任务中证据获取与状态保持的瓶颈，提出了结合能力层证据渲染与持久多模态记忆的通用推理框架。该框架通过统一工具接口与跨轮次工件寻址，实现了无需微调的多步组合推理。实验表明，其在 Qwen3-VL-8B 上提升 11.2 个百分点，在 GPT-6 Sol 上提升 11.6 个百分点，证明了结构化证据获取与推理能力扩展的互补性。然而，框架性能高度依赖骨干模型的规划能力，且在低能力模型上表现受限。当骨干模型指令遵循能力不足时，持久化记忆中的复杂句柄引用是否会成为新的认知负担，进而抵消证据渲染带来的增益，论文未给出明确回答。
