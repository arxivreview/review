# HuggingFace最新推荐论文 ｜From Evidence to Action: How Tool-Using Agents Fail ｜证据-行动链评估：SAFEACTBENCH 深度剖析

研究机构：新加坡国立大学、香港浸会大学

作者：Hongzhan Lin、Shidong Cao、Ziyang Luo 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.07753)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.07753)

## 导读

大语言模型智能体正从静态文本生成转向具备状态变更能力的自主行动者，传统仅关注最终输出正确性的评估范式无法捕捉行动前的证据建立过程。现有交互式基准虽引入了轨迹记录，但往往混淆了“环境事实为真”与“智能体已建立证据”，导致对过早行动或错误绑定的失败无法定位。本文提出 SAFEACTBENCH，通过溯源绑定的证据账本与确定性轨迹重放，将评估重心从结果匹配转向证据-行动因果链的完整性验证。该框架揭示了静态决策能力与动态执行可靠性之间的显著鸿沟，但其对开放式任务中证据定义模糊性的处理能力仍存疑。

## 研究背景

当智能体执行退款、发送文档等具有外部效应的工具调用时，其正确性不再仅取决于动作本身，而取决于行动前是否建立了支持该动作的任务相关事实。这种从“回答”到“行动”的范式转变，要求评估体系能够区分“环境状态允许行动”与“智能体在可观测轨迹中建立了行动依据”这两个截然不同的概念。前者是静态的全局状态属性，后者是动态的交互过程属性，二者在智能体未充分调查或错误绑定证据源时会出现严重背离。

智能体评估领域已从静态函数调用准确率演进至交互式环境中的多步任务完成度评估。AgentBench、AppWorld 等基准确立了基于可执行交互和中间里程碑的评估标准，但主流路线仍侧重于最终状态匹配或里程碑达成，缺乏对行动前证据获取路径的细粒度审计。现有方法难以区分智能体是“基于正确证据行动”还是“碰巧猜对了参数”，也无法定位失败究竟源于调查不足、证据绑定错误还是依赖关系违反。本文切入点在于构建一个可观测的证据-行动链，将评估分解为调查、证据绑定、行动执行及下游依赖传播四个独立可诊断的环节。

## 核心方法

### 方法参照系

本文问题归属于交互式智能体轨迹评估范畴，与 ToolSandbox 等使用里程碑有向无环图（DAG）评分中间状态的方法同属一类。关键差异在于，通用流程通常验证动作序列是否符合预设计划或最终状态是否匹配，而本文要求验证每个状态变更动作（Consequential Action）在执行前，其所需的特定实体和状态证据是否已在可观测轨迹中被建立，且证据来源必须与动作目标严格绑定。

### 溯源绑定证据账本

传统评估中，只要智能体调用了正确的工具并返回成功，即视为任务完成，忽略了证据获取的时序与归属。本文引入溯源绑定证据账本（Provenance-bound Evidence Ledger），将已建立的事实与其源交互及描述的实体/状态显式绑定。其核心逻辑定义为：对于行动 $a$，其支持条件 $Supported(a)$ 成立当且仅当所有前置要求 $r \in R(a)$ 在行动 $a$ 执行前已被建立。

$$
Supported(a) \iff \forall r \in R(a), \text{r is established before } a
$$

这一设计解决了“值匹配但源错误”的失效模式。例如，从账单 C1 读取金额 $49.99$ 不能建立账单 C2 的金额证据，即使数值相同。通过强制证据与实体的绑定，该机制使得评估器能够识别出智能体虽执行了正确动作，但缺乏针对该特定目标的合法证据支持的情况，从而将“碰巧正确”与“有据可依”区分开来。

### 确定性轨迹重放与协议分层

为验证证据链的完整性，本文摒弃了依赖 LLM 评判器的模糊判断，采用确定性评估器对轨迹进行重放。评估器不检查隐藏推理，仅基于任务上下文、观察到的工具交互及最终环境状态进行二元判定。SAFEACTBENCH 设计了五个协议层级：Legacy（静态决策）、V0（调查性非行动）、V1（单行动）、V2（线性多行动）及 V3（依赖约束多行动）。

$$
\text{Success}_{V2} = \bigwedge_{i=1}^{n} \left( \text{Evidence}_i \text{ established before } a_i \land a_{i+1} \text{ uses actual result of } a_i \right)
$$

该公式表明，线性工作流的成功不仅要求每个行动前有证据，还要求后续行动必须使用前一行动的实际返回结果。这种分层设计使得评估器能够独立诊断调查不足（V0）、过早行动（V1）及依赖违反（V2/V3）等不同类型的失败，而非将任务失败归因于单一瓶颈。

## 实验评估

实验在 SAFEACTBENCH 的 656 个案例上进行，覆盖六个运营领域，评估了五个模型家族（Claude, GPT, DeepSeek, Qwen, GLM）与两种 Harness（家族关联及共享 Inspect）的十种配置。基线覆盖审计显示，本文未直接对比 GAIA 或 SWE-bench 等通用基准，而是专注于内部协议间的性能差异及 Harness 效应，缺失开源小模型基线以评估计算效率与性能的权衡。

| 模型 | Harness | ECS (%) | Legacy (%) | V1 (%) | V2 (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Claude-5 | Code | 67.2 | 97.7 | 60.3 | 60.6 |
| DeepSeek-V4 | DSH | 63.0 | 96.5 | 61.1 | 65.2 |
| GLM-5.2 | Inspect | 41.0 | 77.9 | 31.3 | 22.0 |

主结果显示，静态决策（Legacy）准确率普遍高于 90%，但交互式执行（V1-V3）准确率显著下降，如 Claude-5 在 Legacy 达 97.7%，而在 V1 降至 60.3%。这一差距揭示了静态评估能力与动态执行可靠性之间的巨大鸿沟。消融分析表明，失败主要源于调查不完整（BSR 21.7%-62.9%）或证据完成前行动（PAR 37.0%-66.9%），而在证据建立后的单行动执行可靠性较高（CAS 93.2%-100%）。Harness 效应显著且依赖模型，DeepSeek 在 DSH 下比 Inspect 高 5.5 个点，而 GLM 在 Inspect 下优于 ZCode，表明框架选择对执行可靠性有实质性影响。

评估边界方面，本文采用确定性二元评分，未报告置信区间或多次运行的统计波动，限制了结果的可复现性比较。代码与超参数未公开，且未涵盖 Token 成本指标，无法评估高成本模型的经济可行性。确定性评估器依赖预定义的证据要求，在处理证据定义模糊的开放式任务时，其泛化能力尚未得到验证。

## 关联研究分析

从问题动机看，本文与 Near-Miss (Rabinovich et al., 2026) 均关注行动前的只读观察，但 Near-Miss 侧重于策略检查的绕过，而本文扩展至多步依赖和实体绑定，解决了 Near-Miss 无法定位“值正确但源错误”的盲区。与 ToolSandbox (Lu et al., 2025) 相比，后者使用里程碑 DAG 评分中间状态，但缺乏对证据溯源的显式追踪，导致无法区分“基于证据行动”与“盲目行动”。本文的差异根源在于任务特性：状态变更操作要求严格的因果链验证，而通用工具调用可能容忍部分信息缺失。

从方法设计看，本文与 AgentAbstain (Liu et al., 2026) 同属弃权评估范畴，但 AgentAbstain 仅评估是否停止，本文将其整合为“调查性非行动”协议，要求智能体在停止前完成必要的调查以建立“为何不行动”的证据。这一设计解决了 AgentAbstain 中智能体可能因懒惰而非证据不足而停止的混淆问题。然而，本文未探索当证据冲突时智能体的澄清行为，仅关注证据缺失或错误绑定，这在真实世界的动态交互中可能是更常见的失败模式。

## 总结

本文旨在解决智能体在状态变更操作中“结果正确但证据缺失”的评估盲区。现有方法因缺乏证据溯源机制，无法区分基于证据的行动与碰巧正确的行动，而本文通过溯源绑定证据账本与确定性轨迹重放，实现了证据-行动链的细粒度诊断。实验证明，静态决策能力与动态执行可靠性存在显著差距，Claude-5 在 Legacy 协议达 97.7%，但在 V1 协议降至 60.3%，揭示了调查不足与过早行动是主要失败来源。本文的边界在于其确定性评估器依赖预定义的证据要求，难以处理证据定义模糊的开放式任务。当任务中的证据需求无法被预先形式化时，该框架的诊断能力是否依然有效，论文未给出回答。
