# HuggingFace最新推荐论文 ｜REMORY: Learning Residual Memory for Context Compaction ｜残差记忆：面向上下文压缩的连续向量补充

作者：Hanchen Xia、Baoyou Chen、Yutang Ge 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.11287)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.11287)

> 导读 长时程智能体在有限上下文窗口内运行时，需通过文本摘要压缩历史交互以释放空间，但摘要作为离散、有损的压缩边界，往往遗漏支撑后续决策的细粒度线索，导致智能体在压缩后出现行为断裂或重复错误。现有方法多依赖检索离散文本片段或生成等预算的文本补充，前者受限于检索精度与延迟，后者则因生成文本的语义漂移而难以保留原始预测分布。REMORY 提出一种“残差记忆”机制，在文本摘要后拼接由神经网络生成的连续软令牌，通过冻结大语言模型的预测分布作为监督信号，训练记忆网络填补摘要与全历史之间的预测差距。该机制在极低输入开销下显著提升了智能体的归因准确性与任务完成率，但其扁平连续向量结构是否足以支撑复杂多跳因果推理，仍待验证。

## 研究背景

当智能体在长时程任务中累积大量观察、工具输出与决策记录时，其上下文长度迅速逼近模型窗口上限，迫使系统执行上下文压缩。主流实践如 Claude Code 和 Codex CLI 采用 `/compact` 指令生成文本摘要，将输入长度从锯齿状增长重置为低水位，摘要成为智能体恢复工作的检查点。然而，文本摘要仅保留主线逻辑，无法保证覆盖所有后续决策所需的细节，且早期上下文的相关性随任务推进动态变化。人类认知中，海马体索引理论描述了部分线索如何激活索引以重建分布式皮层表征，这提示智能体需一种机制，在保留可读检查点的同时，维持对原始上下文的预测性访问。

现有记忆增强方案在此场景下存在结构性缺陷。检索增强生成（Retrieval-Augmented Generation, RAG）与 MemGPT 依赖离散文本片段的检索，虽能保留精确记录，但检索器难以在压缩边界后动态识别“未被摘要但当前决策必需”的隐式信息，且引入额外延迟。AutoCompressors 与 Gist Tokens 等连续压缩方法虽生成软令牌，但其监督目标多为重构原文，未针对智能体“摘要条件下的续写预测”这一任务导向进行优化，导致压缩信息与下游决策脱节。REMORY 的切入点在于：不假设压缩后所需信息可预先枚举，而是通过冻结模型的预测分布匹配，让记忆网络自动学习填补摘要留下的预测空白。

## 核心方法

### 方法参照系：摘要条件压缩

在标准上下文压缩流程中，智能体在压缩边界 $i$ 生成摘要 $S_i$，后续调用仅读取 $S_i$ 与新交互。该流程的关键差异在于：传统方法将 $S_i$ 视为完整上下文替代品，而 REMORY 将 $S_i$ 视为条件锚点，要求记忆网络在 $S_i$ 基础上补充预测性信息，形成“摘要+残差记忆”的联合输入。

### 残差记忆构建与序列维度残差连接

REMORY 的核心创新在于将连续记忆令牌视为序列维度的残差连接。给定历史 $H_i$ 与摘要 $S_i$，记忆网络 $C_\phi$ 生成有界软令牌序列 $M_i$：

$$ M_i = C_\phi(H_i; S_i), \quad |M_i| \le m $$

其中 $M_i$ 为冻结模型输入空间中的向量序列。拼接后的 $[S_i; M_i]$ 构成残差连接，智能体读取持久指令、该序列及新交互。该设计动机在于：文本摘要提供可读检查点，而软令牌携带摘要未显式编码的预测性信息，二者互补而非替代。网络采用冻结模型特征与学习查询并行预测记忆向量，每 1,024 个源位置生成 64 个软令牌，分层压缩将最终记忆限制在 4,096 个槽位，保留源顺序。

### 冻结模型监督下的两阶段训练

为训练记忆网络，REMORY 采用两阶段优化，以冻结模型 $p_\theta$ 的预测分布为监督信号。阶段 I 为重构：教师模型接收源段落与重复指令，学生模型用软记忆替代段落接收相同指令，二者预测源文本，教授记忆网络保留源信息。阶段 II 为摘要条件续写：教师接收原始历史，学生接收固定摘要与对应记忆，二者预测相同后续响应。损失函数为学生对教师的反向 KL 散度：

$$ L(\phi) = \sum_j w_j D_{\text{KL}}(q_j \| p_j) $$

其中 $p_j = p_\theta(\cdot | C_{\text{full}}, y_{<j})$，$q_j = p_\theta(\cdot | C_{\text{mem}}, y_{<j})$，$w_j$ 为位置权重。该设计动机在于：阶段 I 确保记忆保真度，阶段 II 将记忆导向摘要未覆盖的预测差距，使记忆网络无需重构所有遗漏事实，仅需补充决策所需信息。梯度仅更新记忆参数 $\phi$，冻结模型参数不变。

## 实验评估

实验在 SummHay、BrowseComp、Terminal-Bench 2.1、AutomationBench 与 JobBench 上评估，对比 Raw Context、Summary、Summary++（等预算文本补充）及 Summary + REMORY。基线覆盖包含文本补充与全上下文，但缺失 Mem0、RAG 等离散检索基线的直接对比，因本文聚焦压缩边界后的连续补充，与检索路线任务设定不同。

SummHay 评估长文档集合的洞察恢复与源归因。REMORY 在仅使用 5.2% 原始上下文位置的前提下，联合得分接近全上下文，且归因 F1 显著提升，表明软令牌有效保留了归因线索。

| 表示 | Coverage | Citation F1 | Joint Score |
| :--- | :--- | :--- | :--- |
| Raw Context | 72.46 | 56.60 | 43.41 |
| Summary | 67.55 | 56.98 | 39.84 |
| Summary++ | 67.52 | 56.94 | 39.78 |
| Summary + REMORY | 67.95 | 61.03 | 43.39 |

核心数字对比：REMORY 联合得分 43.39 与 Raw Context 43.41 仅差 0.02，但输入位置仅为后者的 5.2%；等预算文本补充 Summary++ 联合得分 39.78，与 Summary 39.84 几乎持平，证明学习到的连续补充优于生成文本。

消融与设计决策验证显示，阶段 II 的摘要条件续写是关键：若仅用阶段 I 重构初始化，残差训练收敛速度显著慢于随机初始化，表明摘要条件直接引导记忆网络聚焦预测差距。Terminal-Bench 2.1 与 BrowseComp 上，REMORY 使重复工具输出减少 17.9–29.8%，错误减少 25.3–49.7%，验证了记忆对早期反馈的有效利用。

## 关联研究分析

从问题动机看，REMORY 与 MemGPT 均处理长上下文，但 MemGPT 依赖离散文本分页与检索，将记忆管理视为操作系统式调度；REMORY 将记忆视为序列维度的残差连接，不经过检索器，直接补充预测性信息。这一差异源于任务特性：MemGPT 面向通用对话，需精确事实召回；REMORY 面向智能体决策，需维持预测分布连续性。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从方法设计看，REMORY 与 AutoCompressors 均使用软令牌压缩，但 AutoCompressors 侧重通用文本压缩，监督目标为重构原文；REMORY 针对智能体摘要后的决策续写，监督目标为冻结模型的续写预测分布。这一差异源于框架目标：AutoCompressors 服务于信息检索，REMORY 服务于行动规划。扁平向量是否无法支持复杂多跳因果推理，论文未给出回答。

## 总结

REMORY 要解决的核心矛盾是：文本摘要作为压缩边界，无法保证覆盖所有后续决策所需的细粒度线索，导致智能体行为断裂。现有方法做不到，是因为检索离散片段难以识别隐式需求，生成文本补充则语义漂移。REMORY 通过冻结模型预测分布匹配，训练记忆网络生成连续软令牌填补预测差距。在 SummHay 上，REMORY 联合得分 43.39 接近全上下文 43.41，输入位置仅 5.2%；在 Terminal-Bench 2.1 上，Qwen3.8-27B 得分从 71.9 提升至 76.4。本文边界在于：记忆网络与特定模型骨干绑定，扁平连续向量结构未显式构建关系，其是否足以支撑复杂多跳因果推理，论文未给出回答。
