论文原文见 [arXiv](https://arxiv.org/abs/2610.31158)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.31158)

> 导读：视频内容蕴含丰富的时空与多模态线索，但现有智能体仅能处理短答案问答或脱离源视频的纯文本检索，无法生成以单一视频为核心、结合外部多模态证据的深度研究报告。本文提出视频中心深度研究报告生成任务，并构建 OmniDR-Bench 基准。通过引入审计式评分标准树（Omni-ARTs）与审计式标准构建（ARC）机制，该基准对智能体生成的交互式 HTML 报告进行细粒度评估。实验揭示了当前智能体在内容覆盖与引用支持上的巨大差距，为视频理解从检索向生成式研究评估的范式转移提供了新的坐标系。

## 研究背景

当用户面对一段包含复杂机制、产品参数或操作演示的视频时，往往需要验证视频中的声明、复现步骤或获取背景知识。视频原生保留了丰富的时空上下文、可见实体和细粒度动作，这些线索难以被完全文本化。然而，现有的文本中心深度研究智能体仅通过迭代网络搜索生成报告，完全忽略了源视频的视听证据；而现有的视频深度研究基准主要聚焦于短答案问答，缺乏对长程、可追溯研究报告的评估。

为了填补这一空白，研究重心正从单纯的“视频片段检索”转向“以视频为锚点的多模态证据整合”。传统方法在跨模态对齐上依赖全局特征匹配，难以处理长视频中的部分相关性与查询歧义。本文切入点在于将视频视为研究主干，要求智能体不仅提取视频内的时间戳证据，还需检索外部网页、图像和文档，最终合成一份包含视频时间导航的交互式 HTML 报告。

## 核心方法

### 任务定义与智能体工作流

本文任务可形式化为：给定源视频 $V$、用户请求 $Q$ 和开放工具环境 $E$，智能体 $A$ 需生成交互式 HTML 报告 $H$，即 $H = A(V, Q, E)$。该任务要求报告保持视频的中心地位，并将外部证据与源视频的具体时刻相链接。

为实现这一目标，本文设计了一个七阶段技能工作流。智能体首先对齐视觉与语音时间线，随后提取与请求相关的研究锚点（如声明、参数、实体）。接着，并行分支检索外部多模态证据，主智能体将这些证据与源视频内容建立支持、矛盾或解释等逻辑关联，最终渲染报告并执行修复检查。

### 审计式标准构建（ARC）

评估开放式报告面临无唯一参考答案的挑战。为此，本文提出审计式标准构建（ARC）机制，在生成任何评分标准前，先构建独立的事实库。ARC 通过隔离的智能体分别生成视频证据地图和外部网络证据地图，随后通过多轮搜索与人工审查，将事实转化为原子化二元标准。

ARC 的核心在于行为校准，确保评分标准对证据访问的敏感度。设 $R_1$ 为仅使用视频的报告，$R_2$ 为使用全工具的报告，$R_3$ 为使用事实库辅助的报告。ARC 要求所有保留任务满足 $R_1 < R_2 < R_3$ 且 $R_3 - R_1 > \delta_{cal}$，其中 $\delta_{cal}$ 为最小要求增益。这一设计动机在于防止评分标准过于宽松，确保只有真正整合了外部多模态证据的报告才能获得高分。

### 审计式原子评分标准树（Omni-ARTs）

在 ARC 构建的事实库基础上，本文提出 Omni-ARTs 进行细粒度评估。Omni-ARTs 包含三个维度（内容、引用、展示）、23 个共享诊断方向以及任务特定的原子二元标准。

对于方向 $d$，其原始通过率为 $r_d = \frac{1}{|A_d|} \sum a_j$，其中 $A_d$ 为适用标准数，$a_j \in \{0, 1\}$ 为结果。为控制高频方向对总分的影响，引入阈值 $\tau_d$ 和权重上限 $\kappa_d$，计算得分 $c_d = \min(1, r_d / \tau_d)$。最终报告得分 $S$ 为各维度得分的加权和：

$$ S = 100 \sum_{k \in \{C, R, P\}} \lambda_k \frac{\sum_{d \in D_k} w_d g_d c_d}{\sum_{d \in D_k} w_d} $$

其中 $\lambda_k$ 为维度权重，$g_d$ 为门控变量。该公式的物理含义是：通过门控机制和权重上限，确保报告在内容、引用和展示三个维度上的表现能够被公平、可审计地量化，避免单一维度的过度优化掩盖其他维度的缺陷。

## 实验评估

实验在 OmniDR-Bench 的 50 个任务上进行，评估了 18 种模型与智能体框架（Harness）的组合。基线覆盖了 Claude、GPT、Gemini 等主流大语言模型，但未包含传统的视频检索模型（如 CLIP4Clip），因为任务性质已从排序转向生成。

| 模型 | 框架 | 平均分 (Avg.) | 成功率 (Success) | 内容 (Content) | 展示 (Presentation) | 引用 (Citation) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Claude Opus 5 | Claude Code | 63.3 | 96.0% | 59.9 | 90.3 | 59.9 |
| GLM-5.3 | Claude Code | 62.0 | 100.0% | 58.2 | 83.2 | 54.4 |
| Qwen3.8-Omni-Flash | Claude Code | 59.3 | 98.0% | 54.6 | 89.0 | 51.5 |
| GPT-5.6 Sol | Claude Code | 54.9 | 100.0% | 42.0 | 85.7 | 56.0 |

主结果显示，最佳系统（Claude Opus 5）得分为 63.3。所有配置在展示维度上平均得分高达 81.8，但在内容和引用维度上仅为 45.4 和 47.8。这表明当前智能体能够很好地满足 HTML 模板的格式要求，但在深度内容覆盖和跨源证据整合上存在严重瓶颈。

| 变体 | 提供能力 | 平均分 | 成功率 | 内容 | 展示 | 引用 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| (i) | UI | 28.0 | 66.7% | 18.9 | 50.5 | 28.2 |
| (ii) | UI + Video | 31.8 | 73.3% | 26.6 | 54.3 | 25.4 |
| (iii) | UI + Video + Web | 45.5 | 100.0% | 34.9 | 80.3 | 40.0 |
| (iv) | UI + Video + Web + Multi. | 46.6 | 100.0% | 40.1 | 80.7 | 34.7 |
| (v) | Full (VDR) | 53.9 | 100.0% | 40.9 | 83.9 | 55.4 |

技能消融实验揭示了边际收益的递减与负迁移现象。添加多模态检索（Multi.）使内容得分提升 5.2 点，但引用得分下降 5.3 点，说明获取丰富证据并不等同于成功整合证据。完整的视频研究编排（VDR）带来了 7.3 点的整体提升，其中引用得分提升 20.7 点，但计算成本（Token 和步骤）显著增加。

评估协议方面，Omni-ARTs 依赖 GPT-5.6 Sol 作为多模态裁判，存在模型偏好风险。尽管 ARC 引入了人工审查，但 50 个任务的规模限制了统计显著性，且未报告计算效率指标。

## 关联研究分析

从问题动机看，本文与 STRIVE-D 均利用大语言模型进行结构化接地，但 STRIVE-D 旨在解决驾驶视频检索中的复杂查询，输出为排序结果；而本文要求生成包含外部证据的交互式报告，输出为长文本与多媒体混合体。这种差异源于任务特性的根本不同：检索任务关注候选集的相对排序，而报告生成任务关注证据链的绝对完整性与逻辑自洽性。

从方法设计看，本文的 ARC 机制与交互式检索中的不确定性量化（如 UMIVR）有相似之处，均试图通过多轮交互或独立验证来消除歧义。然而，ARC 构建的是独立于被评估系统的事实库，而 UMIVR 依赖模型自身的不确定性估计。ARC 的独立证据收集机制是否引入了新的领域偏差，从而削弱了跨域泛化评估，论文未给出回答。

## 总结

本文要解决的核心矛盾是现有视频理解基准无法评估以单一视频为锚点、结合外部多模态证据的深度研究报告生成能力。本文通过引入 ARC 和 Omni-ARTs，构建了独立于被评估系统的事实库与细粒度评分标准，证明了当前智能体在展示格式上表现良好（81.8 分），但在内容覆盖与引用支持上存在巨大差距（45.4 与 47.8 分）。本文的边界在于其评估高度依赖多模态大模型裁判，且 50 个任务的规模难以覆盖长尾视频场景。当智能体能够完美整合外部证据时，ARC 构建的独立事实库是否会因领域偏差而限制模型在未知领域的泛化能力，仍有待验证。
