# HuggingFace最新推荐论文 ｜Selection-Based Structured Reasoning: Toward Efficient Multimodal Search Agents ｜基于选择的多模态结构化推理

研究机构：美国卡内基梅隆大学

作者：Feiyu Gavin Zhu、Xiaoyu Zhu、Jiqi Yang 等 12 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.01892)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.01892)

> 多模态搜索智能体在执行动作前需生成自由推理文本，小模型受限于容量，冗长推理既消耗算力又难以提供有效动作指导。现有压缩推理或效率奖励方法仅减少文本长度，仍保留自回归解码的序列依赖。本文提出基于选择的多模态结构化推理（Selection-based Structured Reasoning, SSR），将推理重构为从预定义候选库中并行评分选择，而非逐token生成。该方法在保持任务成功率的同时大幅降低推理延迟，但其固定候选库能否覆盖开放世界中的长尾推理模式尚存疑问。

## 研究背景

多模态搜索智能体（Multimodal Search Agent）需交替执行感知、检索与工具调用，其核心循环遵循 ReAct 范式：模型基于当前上下文生成推理轨迹，再据此决定下一步动作。在自回归解码中，推理轨迹的每个 token 必须等待前一个 token 生成完毕，导致推理延迟与轨迹长度成正比。对于参数量有限的端侧模型，这种序列依赖意味着大量算力被消耗在生成低信息量的推理文本上，而非用于提升动作质量。

多模态搜索智能体的主流训练路线聚焦于提升任务成功率，如 MMSearch-R1 和 DeepMMSearch-R1 通过强化学习优化工具调用策略，TAPO 引入工具感知的信用分配机制。这些方法在提升性能的同时，默认推理轨迹是自由生成的自然语言文本，未针对推理过程的计算效率进行优化。现有高效推理方法如 Chain-of-Draft 和 Sketch-of-Thought 通过提示压缩或效率奖励减少生成 token 数量，但本质上仍依赖自回归解码，无法消除序列依赖带来的延迟瓶颈。本文的切入点在于改变推理的表示形式本身：既然搜索任务中的高层推理模式（如“实体已知但属性缺失，需搜索”）在不同问题间高度复用，那么推理空间无需覆盖整个自然语言空间，而可收敛为少量可复用的候选项。

## 核心方法

### 方法参照系

本文问题可置于“交错推理机制”类别下，其标准流程为：模型基于上下文生成中间推理状态，再据此生成动作。关键差异在于，标准流程中推理状态是自由生成的文本序列，而 SSR 将其替换为从固定候选库中的选择操作，从而将推理生成问题转化为分类评分问题。

### 并行推理解码

在标准 ReAct 流程中，推理轨迹 $z_t$ 由模型自回归生成，$z_t \sim p_\theta(\cdot | h_t)$，其延迟与轨迹长度 $L$ 成正比。SSR 引入推理库 $\mathcal{R} = \{r_1, \dots, r_N\}$，其中每个 $r_i$ 是预定义的自然语言候选。设计动机在于：搜索任务中高层推理模式高度复用，自由生成不仅浪费算力，还可能导致小模型生成偏离任务需求的冗长文本。SSR 使用语言模型本身作为分类器，计算每个候选在当前上下文 $h_t$ 下的长度归一化对数似然：

$$S_\theta(r_i | h_t) = \frac{1}{K_i^\alpha} \sum_{j=1}^{K_i} \log p_\theta(r_{i,j} | h_t, r_{i,<j})$$

其中 $K_i$ 是候选 $r_i$ 的 token 数，$\alpha=1$ 消除长度偏差。由于所有候选文本预先指定，teacher forcing 可在单次前向传播中并行计算所有 token 的似然，且不同候选共享同一 KV cache，实现候选级与 token 级双重并行。该机制将推理延迟从 $O(L \log(H+L))$ 降至 $O(\log(H+K_{\max}) + \log N)$，消除了轨迹长度 $L$ 的影响。

### 选择-动作联合训练

SSR 的推理选择与动作生成共享同一模型参数，可端到端联合优化。在 GRPO 强化学习中，设计动机在于：自由推理的 token 级重要性比率无法直接应用于选择操作，需将推理选择建模为单一分类比率。SSR 定义推理选择比率 $\rho_{\text{reason}} = \frac{q_\theta(z_t | h_t)}{q_{\text{old}}(z_t | h_t)}$ 与动作 token 比率 $\rho_{\text{action},t,k} = \frac{p_\theta(a_{t,k} | h_t, z_t, a_{t,<k})}{p_{\text{old}}(a_{t,k} | h_t, z_t, a_{t,<k})}$，最终目标函数为：

$$J_{\text{GRPO}}(\theta) = \mathbb{E}_{g \in \mathcal{G}} \left[ \gamma_{\text{RL}}^{\text{reason}} \sum_{t=0}^{T_g-1} \ell_\epsilon(\rho_{\text{reason},g,t}, \hat{A}_g) + \sum_{t=0}^{T_g-1} \sum_{k} \ell_\epsilon(\rho_{\text{action},g,t,k}, \hat{A}_g) \right] - \beta K_{\text{ref}}(\theta)$$

其中 $\ell_\epsilon$ 为裁剪代理损失，$\hat{A}_g$ 为组内归一化优势。该设计无需 SFT 预热，因为选择操作天然将模型约束在候选库内，避免了自由生成中模型可能偏离预期推理模式的问题。

## 实验评估

实验在七个多模态搜索基准上进行，使用 Qwen3-VL 2B/4B 模型，对比基线覆盖 SOTA 智能体（TAPO、MMSearch-R1）与高效推理方法（Chain-of-Draft、Sketch-of-Thought）。

| 方法 | 模型规模 | 平均成功率 (%) | 每轮推理延迟 (s) | 每问题模型延迟 (s) |
|---|---|---|---|---|
| TAPO + GSPO | 4B | 61.25 | — | — |
| SSR (Ours) | 4B | 61.37 | 0.061 | 2.514 |
| Sketch-of-Thought | — | 56.07 | 0.543 | 3.487 |
| Chain-of-Draft | — | 54.06 | 0.416 | 3.657 |

SSR 4B 模型平均成功率 61.37% 与 SOTA 基线 TAPO 的 61.25% 持平，但每轮推理延迟仅 0.061s，较最快基线 Sketch-of-Thought 的 0.543s 降低约 89%，每问题模型延迟 2.514s 较基线 3.487s 降低约 28%。

| 变体 | 平均成功率 (%) | 说明 |
|---|---|---|
| 完整推理文本选择 | 61.37 | 基线 |
| 仅索引选择 | 58.98 | 降低 3.9% |
| 自回归解码（无 SFT） | 60.23 | 退化为自由推理 |

消融实验显示，仅选择候选索引而非完整文本导致成功率下降 3.9%，表明候选语义对上下文依赖选择至关重要。自回归解码在无 SFT 预热时无法约束模型使用候选库，退化为自由推理，验证了选择机制对接口强制性的必要性。

评估边界方面，论文未报告置信区间，且所有实验基于固定六候选库，未测试候选库规模扩展对性能的影响。可复现性上，论文提供项目页面，但未开源完整代码与训练脚本，超参数设置（如 $\lambda_{\text{SFT}}^{\text{reason}}=1$）在附录中给出，GPU 为 NVIDIA H100。

## 关联研究分析

从问题动机看，SSR 与 Chain-of-Draft 和 Sketch-of-Thought 均针对推理效率，但前者通过提示压缩减少生成 token 数量，SSR 则通过改变推理表示消除序列依赖。这一差异源于任务特性：搜索任务中的高层推理模式高度结构化且复用性强，使得候选库选择可行；而在开放域问答中，推理模式可能更发散，固定候选库的覆盖率存疑。SSR 未探索候选库的动态扩展机制，这是其与自适应推理方法的关键区别。

从方法设计看，SSR 与 Thought Templates 共享“可复用推理”理念，但后者将模板作为外部知识注入，SSR 则利用语言模型内部语义先验进行上下文条件选择，无需额外检索系统。这一设计简化了系统架构，但将推理灵活性限制在预定义候选空间内。当任务需要超出候选库覆盖范围的推理模式时，SSR 的表现可能受限，论文未对此进行压力测试。

## 总结

本文要解决的核心矛盾是小模型多模态智能体中自由推理的高延迟与低效问题。现有压缩方法仅减少文本长度，无法消除自回归解码的序列依赖；SSR 抓住搜索任务中高层推理模式高度复用的特性，将推理重构为并行评分选择，从而在保持任务成功率的同时大幅降低延迟。实验证明 4B SSR 模型平均成功率 61.37% 与 SOTA 持平，每轮推理延迟降低超 90%。其边界在于固定六候选库的覆盖率未经验证，且候选库规模扩展对性能的影响仅通过单调增长曲线间接推断。当任务复杂度超出预定义候选库的覆盖范围时，选择机制是否仍能维持性能，论文未给出回答。
