# HuggingFace最新推荐论文 ｜HybridResearcher: Bridging the Structured-Unstructured Boundary for Deep Research Agents ｜跨源混合推理智能体训练框架

研究机构：韩国首尔大学、美国加州大学洛杉矶分校

作者：Soyoung Yoon、Peiran Xu、Han Wang 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.24899)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.24899)

> 深度研究智能体（Deep Research Agents, DRA）在单一数据源（如纯文本网络或纯结构化数据库）上的能力已趋成熟，但真实世界分析任务常需跨越结构化与非结构化边界进行证据合成。现有方法受限于单源训练数据无法自动组合成跨源能力，且朴素合成易导致模型利用参数化知识走捷径，从而绕过真实的跨源推理。本文提出 HybridResearcher 框架，通过从已验证的单源种子任务出发，围绕“桥接实体”合成强制依赖的跨源轨迹，并采用严格构造门控与强化学习（Reinforcement Learning, RL）训练小模型。该框架在 HybridDeepResearch 基准上显著提升了跨源推理能力，同时避免了单源能力的灾难性遗忘，为异构数据融合提供了可复现的训练范式。

## 研究背景

当智能体面对需要同时查询内部数据库和公开网络信息的复杂问题时，单一源的训练范式暴露出根本性局限。结构化数据（如 SQL 查询）与非结构化数据（如网页搜索）在语义空间和操作逻辑上存在巨大差异，导致模型难以在单次推理链中无缝切换。这种跨源推理能力的缺失，源于组件能力无法自动组合：即便模型分别精通 SQL 生成和网页搜索，若训练数据中缺乏“以 SQL 结果作为搜索输入”或“以搜索结果作为 SQL 参数”的显式依赖轨迹，模型便无法建立跨源逻辑链。

当前领域在单源智能体训练上进展迅速，如 Search-R1 等通过 RL 优化搜索策略，Text-to-SQL 领域也涌现出大量高效模型。然而，这些方法均假设证据来源同质。当 HybridDeepResearch 等基准揭示前沿模型在跨源任务上的性能瓶颈时，训练层面的空白随之显现：缺乏专门针对跨源依赖的数据合成机制与训练框架。朴素地混合单源数据或合成跨源问题，往往因模型依赖参数化记忆而失效，导致“捷径学习”——模型看似回答了问题，实则未执行必要的跨源工具调用。因此，如何构建强制跨源依赖的训练数据，并设计抗捷径的训练策略，成为突破 DRA 能力边界的关键。

## 核心方法

### 方法参照系：单源轨迹生成的局限

在标准的智能体训练流程中，数据通常由单源任务（如纯 SQL 或纯搜索）的轨迹构成，或通过大模型直接合成跨源问题。本文指出，这种参照系存在两个致命缺陷：一是单源轨迹从未涉及“工具输出作为另一工具输入”的交互，因此无法教授跨源桥接；二是朴素合成的跨源轨迹中，高达 79.5% 的样本未执行实质性 SQL 查询，模型直接通过参数化记忆回答，导致训练信号指向错误的推理路径。HybridResearcher 的核心在于重构数据生成逻辑，从“合成问题”转向“合成依赖”。

### 桥接实体驱动的数据合成

为解决单源数据无法组合的问题，本文提出基于“桥接实体”（Bridge Entity）的数据合成策略。该方法从已验证的单源种子任务（Text-to-SQL 或 Deep Search）出发，围绕种子输出中的一个实体合成缺失源的任务。对于 SQL-to-Search (SQL2S) 任务，桥接实体选自 SQL 执行结果，且必须通过成员门控（Membership Gate）确保该实体不出现在原始问题中，从而强制模型执行 SQL 以发现该实体。随后，围绕该实体合成虚构事实（Coined Facts）作为搜索约束，确保模型必须通过搜索验证这些事实。

对于 Search-to-SQL (S2SQL) 任务，桥接实体选自搜索答案或问题中的关键实体，作为 SQL 查询的锚点（Anchor）。通过执行测试（Execution Test）验证该锚点是“承重”的（Load-bearing），即移除该锚点会改变 SQL 结果，从而强制模型先通过搜索获取该实体，再将其作为参数输入 SQL 查询。这一设计确保了跨源依赖的刚性：

$$
\text{Dependency}(T_{SQL}, T_{Search}) \iff \text{Output}(T_{SQL}) \in \text{Input}(T_{Search}) \lor \text{Output}(T_{Search}) \in \text{Input}(T_{SQL})
$$

该公式表明，只有当两个任务的输入输出存在严格的集合包含关系时，才被视为有效的跨源轨迹。这种构造方式继承了种子任务的难度，同时通过虚构事实防止模型利用先验知识走捷径。

### 抗捷径训练与强化学习优化

在训练阶段，本文采用监督微调（Supervised Fine-Tuning, SFT）与 RL 相结合的策略。SFT 阶段使用通过严格构造门控的高质量轨迹，初始化模型的跨源推理模式。RL 阶段则针对 SFT 后仍难以解决的“硬案例”进行优化。为应对 RL 中常见的奖励噪声与捷径行为，本文引入了多数投票 Judge 机制与硬门控（Hard-gating）规则。

硬门控规则在轨迹生成阶段即介入，若智能体在未调用工具的情况下耗尽轮次、调用格式错误或重复查询，则直接终止并赋予零奖励。在奖励计算阶段，采用 5 票多数投票的 LLM-as-a-Judge 机制，以缓解单一 Judge 在语义匹配上的不稳定性。RL 的目标函数可形式化为：

$$
\mathcal{L}_{RL} = -\mathbb{E}_{\tau \sim \pi_\theta} \left[ \min \left( r_t(\theta) \hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_t \right) \right]
$$

其中，$r_t(\theta)$ 为策略比率，$\hat{A}_t$ 为优势函数。通过 CISPO 算法优化，模型在保持探索能力的同时，被强制约束在真实的跨源交互路径上，避免了因奖励稀疏导致的策略崩溃。

## 实验评估

实验在 HybridDeepResearch 基准的 120 题硬子集上进行，涵盖 S2SQL、SQL2S 及并行任务。基线对比包括 Qwen3.5-4B 基础模型、同家族旗舰模型 Qwen3.5-397B-A17B-FP8，以及前沿闭源模型 Claude Sonnet 4.6 和 GLM-5.2-FP4。评估指标采用 Pass@8 和 Avg@8，以衡量模型在多次采样下的鲁棒性。

| 模型 | 参数量 | HybridDeepResearch Pass@8 (%) | HybridDeepResearch Avg@8 (%) |
| :--- | :--- | :--- | :--- |
| Qwen3.5-4B (Base) | 4B | 30.83 | 7.71 |
| Qwen3.5-397B-A17B-FP8 | 397B | 52.50 | 26.77 |
| GLM-5.2-FP4 | - | 63.33 | 38.54 |
| Claude Sonnet 4.6 | - | 65.83 | 37.29 |
| **HybridResearcher-4B (SFT)** | **4B** | **59.17** | **23.75** |
| **HybridResearcher-4B (RL)** | **4B** | **60.83** | **27.19** |

HybridResearcher-4B 在 SFT 阶段即实现 Pass@8 从 30.83% 到 59.17% 的跃升，RL 阶段进一步提升至 60.83%，超越同家族 397B 模型 8.3 个百分点，并逼近 Claude Sonnet 4.6 的性能。在单源保留能力测试中，混合训练未导致灾难性遗忘，反而在 BrowseComp 和 Spider 2.0-lite 上取得提升，表明跨源桥接训练强化了底层组件能力。

| 基准 | 指标 | Qwen3.5-4B (Base) | HybridResearcher-4B (RL) | 提升幅度 |
| :--- | :--- | :--- | :--- | :--- |
| BrowseComp | Pass@8 (%) | 54.03 | 62.24 | +8.21 |
| BrowseComp-Plus | Pass@8 (%) | 60.84 | 73.13 | +12.29 |
| Spider 2.0-lite | Pass@8 (%) | 59.26 | 62.96 | +3.70 |

消融实验显示，SFT 阶段主要纠正了“盲搜”行为，将网页搜索次数减半，同时增加页面访问量，使 SQL2S 准确率从 12.9% 提升至 18.5%。RL 阶段则进一步提升了模型在严格依赖任务（如 S2SQL）上的置信度，Avg@8 从 23.75% 提升至 27.19%。然而，评估仍存在边界：HybridDeepResearch 基准依赖虚构事实，可能无法完全反映真实世界中的噪声分布；且 Pass@8 指标掩盖了单次推理的稳定性问题，模型在 22.2% 的 S2SQL 轨迹中仍未能成功浮现桥接实体。

## 关联研究分析

从问题动机看，HybridResearcher 与 Search-R1 和 ABSeeker 等单源 RL 方法形成鲜明对比。Search-R1 通过 RL 优化单源搜索策略，假设环境反馈直接指向最终答案；而 HybridResearcher 指出，在跨源场景下，单源优化无法解决“桥接”问题，必须显式构造依赖轨迹。ABSeeker 通过答案回溯进行步骤级信用分配，旨在解决长程任务中的稀疏奖励；HybridResearcher 则从数据源头入手，通过构造门控确保每一步都具备跨源必要性，从而在数据层面规避了信用分配的模糊性。这种差异源于任务特性：单源任务中，错误步骤可通过最终结果反推；跨源任务中，若缺乏显式依赖，错误步骤可能被参数化记忆掩盖，导致信用分配失效。

从方法设计看，HybridResearcher 与 WebWeaver 等多智能体架构存在路线分歧。WebWeaver 通过双智能体协作和显式大纲规划来管理跨源信息，依赖架构复杂度来保证逻辑连贯性；HybridResearcher 则坚持单智能体端到端训练，依赖数据合成的刚性约束来内化跨源逻辑。这一分歧反映了“架构派”与“训练派”在 DRA 领域的持续博弈。HybridResearcher 证明了在特定数据构造下，小模型可通过训练内化复杂逻辑，无需显式架构支持。然而，这种内化是否具备对未见异构源（如视频、音频）的泛化能力，论文未给出回答。

## 总结

HybridResearcher 针对 DRA 在跨结构化与非结构化数据源推理时的能力断层，提出了基于桥接实体的数据合成与抗捷径训练框架。通过从单源种子任务扩展出强制依赖的跨源轨迹，并结合 SFT 与 RL 优化，该框架使 4B 模型在 HybridDeepResearch 基准上取得 60.83% Pass@8，超越同家族 397B 模型，且未牺牲单源能力。其核心贡献在于证明了跨源推理能力可通过显式的数据构造而非架构创新来习得。然而，该方法依赖虚构事实与严格门控，其泛化边界局限于 SQL 与文本搜索的组合。当面对真实世界中噪声更大、依赖关系更隐晦的异构数据（如代码与文档、视频与文本）时，这种刚性构造门控是否仍能有效防止捷径学习，仍有待验证。
