> 导读 从零程序复现要求代理在无源码条件下重建程序行为，但缺乏可扩展的可验证训练环境导致模型难以习得自主设计与探索能力。现有代理框架多依赖源码级补丁或详细规格，无法提供从零复现所需的黑盒行为监督信号。本文提出ProgramGym，通过自动化流水线构建包含参考可执行文件与黑盒测试套件的训练环境，并设计角色隔离的长程代理工作流。该框架在ProgramBench上显著提升了开源模型的复现通过率，但黑盒测试的覆盖度局限是否会导致未见行为上的隐性错误，仍需进一步验证。

## 研究背景

当代理被要求从零复现程序时，其面临的核心困境是需求发现与架构设计的双重缺失。不同于SWE-bench等Issue Resolution任务提供现成代码库与明确缺陷，从零复现仅暴露参考可执行文件与使用文档。代理必须通过黑盒交互推断功能边界，并独立决定内部实现结构。这一过程要求代理具备长程规划能力，但通用代理框架的上下文窗口限制导致其在多轮探索后遗忘早期观察到的行为约束，且缺乏可靠的反馈信号来区分“正确复现”与“碰巧通过测试”。

为解决监督信号缺失问题，现有研究尝试构建合成训练环境。SWE-Gym等框架通过自动化生成Issue修复任务扩充训练数据，但其监督信号仍依赖源码级单元测试或静态分析，无法迁移至无源码场景。MindForge虽尝试构建命令行程序复现环境，但其测试生成缺乏行为覆盖度验证，导致功能错误的复现可能被误判为成功。这一监督可靠性缺口构成了从零复现代理训练的关键瓶颈：如何在不依赖源码的前提下，自动化构建具备高行为覆盖度且能可靠拒绝错误复现的训练环境。

## 核心方法

### 环境构建参照系与黑盒监督定义

从零程序复现的环境构建可形式化为映射 $\Phi$，将源码仓库 $P_i$ 转换为四元组环境 $e_i = (B^\star_i, D_i, T_i, S_i)$。其中 $B^\star_i$ 为参考可执行文件，$D_i$ 为使用文档，$T_i$ 为黑盒行为测试套件，$S_i$ 为网络隔离运行时沙箱。该流程与标准形式化验证闭环的关键差异在于验证信号源：标准流程依赖形式化规格与定理证明器，而本文采用黑盒测试作为符号层面的行为约束。由于测试套件 $T_i$ 仅覆盖有限输入，通过测试仅确立行为一致性而非语义等价性，这要求测试生成必须具备足够高的行为覆盖度以逼近真实功能边界。

### 反馈驱动的沙箱构建与测试生成

针对异构仓库的构建失败与测试覆盖不足问题，Program-Env引入反馈驱动修复机制。在沙箱构建阶段，流水线将在线依赖准备与离线编译解耦，当编译失败时，将错误日志与修复指令打包返回代理进行诊断。在测试生成阶段，为量化仓库复杂度以分配测试模块预算，定义复杂度评分函数：

$$ \xi = \text{clip}_{[0,10]}(\log_{10} \ell + \log_{10}(1 + r) - 2) $$

其中 $\ell$ 为生产代码行数，$r$ 为运行时依赖数。该公式将仓库规模与依赖复杂度映射至 $[0,10]$ 区间，据此将仓库划分为简单、中等、困难三档，分别分配4、6、8个测试模块预算。设计动机在于：单一代理处理数万行代码的仓库时，受限于上下文与生成预算，难以兼顾全局理解与细节覆盖。通过复杂度感知的任务分解，将仓库切分为功能内聚的模块并分配至并行子代理，配合覆盖率插桩反馈，使测试生成聚焦于未探索行为，显著提升了测试套件的行为覆盖度。

### 角色隔离的长程代理工作流

针对长程开发中探索与实现脱节、需求遗忘的问题，Program-Agent设计了分析、实现、审查角色隔离的迭代工作流。该工作流将单次会话拆分为独立角色会话，分析角色负责记录参考程序探索证据，实现角色基于持久化记录进行编码，审查角色负责行为验证。当实现失败时，离线构建检查与已验证检查点支持失败恢复。这一设计将长程任务的状态管理从隐式上下文依赖转化为显式持久化记录，解决了通用代理框架在上下文压缩过程中丢失关键行为约束的失效模式。

## 实验评估

实验在ProgramBench基准上进行，评估指标为Tests Passed、Almost Resolved与Resolved。基线覆盖包括GPT 5.4、Claude Opus 4.7等旗舰模型及mini-SWE-agent框架，但未包含基于形式化验证的AlphaVerus等方法，因任务定义差异导致基线不可比。

| 模型 | 代理框架 | Tests Passed (%) | ∆ Tests Passed (%) | Resolved (%) |
| :--- | :--- | :--- | :--- | :--- |
| Claude Opus 4.7 | mini-SWE-agent | 50.90 | – | 0.00 |
| DS-V4-Flash-0731 | Claude Code | 57.68 | – | 0.00 |
| Qwen3.8-27B | Claude Code | 34.87 | – | 0.50 |
| Qwen3.8-27B | Program-Agent | 55.71 | 20.84 | 0.50 |
| Qwen3.8-27B-SFT | Claude Code | 42.84 | 7.97 | 0.00 |
| Qwen3.8-27B-SFT | Program-Agent | 56.25 | 21.38 | 0.50 |

主结果显示，Program-Env训练使Qwen3.8-27B-SFT的Tests Passed从34.87%提升至42.84%，验证了合成环境行为监督的有效性。Program-Agent框架进一步将Qwen3.8-27B提升至55.71%，超越Claude Opus 4.7的50.90%。然而，所有模型的Resolved指标均接近0.00%，表明完整程序复现仍未被解决。

迭代预算分析显示，Qwen3.8-27B-SFT配合Program-Agent的Tests Passed从 $K=1$ 时的43.49%上升至 $K=3$ 时的54.13%，在 $K=5$ 时达到56.25%。增益在 $K=3$ 后趋于平缓，表明长程工作流的边际收益存在上限。环境构建统计显示，1,648个训练环境的平均测试覆盖率为72.99%，中位数为81.63%，但低覆盖率长尾表明部分代码路径无法通过黑盒接口触达。

评估协议存在覆盖度与正确性解耦的局限。Tests Passed超过50%但Resolved为0的现象，暴露了黑盒测试无法保证未见行为正确性的根本缺陷。此外，环境构建平均消耗82.99M tokens，高昂的计算成本限制了该流水线在更大规模仓库上的可扩展性。

## 关联研究分析

从监督信号源看，ProgramGym与AlphaVerus代表了可验证代码生成的两条分岔路线。AlphaVerus依赖形式化证明器提供数学上的正确性保证，适用于系统级关键代码；ProgramGym依赖黑盒测试提供行为一致性约束，适用于无源码的通用软件复现。这一差异源于任务特性的根本不同：从零复现缺乏形式化规格，使得定理证明不可行。但黑盒测试的有限覆盖度是否会导致代理过拟合于测试用例而忽略真实语义，论文未给出量化分析。

从代理训练范式看，ProgramGym与SWE-Gym共享“合成环境+代理训练”的框架，但监督粒度存在本质差异。SWE-Gym基于Issue Resolution，监督信号为源码级补丁的正确性；ProgramGym基于从零复现，监督信号为黑盒行为的一致性。这一转变将代理从“代码编辑器”重塑为“软件工程师”，但角色隔离工作流引入的额外推理开销是否会在资源受限场景下抵消其带来的性能增益，论文未提供跨硬件平台的效率对比。

## 总结

本文针对从零程序复现缺乏可扩展可验证训练环境的核心矛盾，提出ProgramGym框架，通过反馈驱动流水线构建黑盒行为监督环境，并以角色隔离工作流解决长程开发中的需求遗忘问题。实验证明，该框架使Qwen3.8-27B-SFT在ProgramBench上的Tests Passed达到56.25%，超越部分旗舰模型。然而，Resolved指标始终为0.00%暴露了黑盒测试监督的固有边界：通过有限测试用例无法保证完整语义等价性。当测试覆盖率停滞在72.99%时，代理在未见行为上的隐性错误率是否会随模型规模增大而系统性上升，论文未给出回答。
