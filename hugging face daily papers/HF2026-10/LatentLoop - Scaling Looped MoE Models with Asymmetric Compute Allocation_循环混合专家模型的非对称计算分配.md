# HuggingFace最新推荐论文 ｜LatentLoop: Scaling Looped MoE Models with Asymmetric Compute Allocation ｜循环混合专家模型的非对称计算分配

作者：Zefeng He、Yunkai Chai、Xiaoyang Chen 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.19975)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.19975)

> 循环混合专家模型通过复用参数增加有效深度，但在固定资源预算下，对称的循环计算未能充分利用不同访问阶段的贡献差异。现有方法假设每次循环访问执行相同的计算量，忽略了模型内部表征更新的非对称性。LatentLoop 通过序列压缩实现非对称计算分配，在第一次访问中处理压缩的潜在序列，第二次访问保持全分辨率，并将节省的计算资源重新分配给模型宽度。该工作揭示了循环机制中计算资源分配的优化空间，但序列压缩带来的信息损失与模型宽度增加之间的权衡机制仍需进一步厘清。

## 研究背景

循环 Transformer 通过重复应用共享层来增加有效深度，在不增加参数存储的前提下提升语言建模与推理能力。然而，每次访问仍需完整计算，导致在固定参数规模下的性能提升无法转化为等计算预算下的优势。稀疏混合专家（Sparse Mixture-of-Experts, SMoE）架构通过门控网络仅激活部分专家，解耦了模型总参数量与单 Token 计算成本。将循环机制与 SMoE 结合，允许存储参数容量与激活计算量独立调整，为在严格资源约束下扩展模型能力提供了新路径。

现有循环 SMoE 方法（如 SMELT）在两次循环访问中执行对称计算，即两次访问处理相同分辨率的序列并激活相同数量的专家。这种对称性假设忽略了循环访问在表征处理中的角色差异。近期研究表明，即使共享参数，不同循环访问也可能承担不同的功能角色。若两次访问对模型预测的贡献存在不对称性，则对称计算分配可能并非最优策略。如何在保持参数、KV Cache 和 FLOPs 预算严格匹配的前提下，通过非对称计算分配进一步提升循环 SMoE 模型的性能，成为亟待解决的关键问题。

## 核心方法

### 循环 SMoE 架构与预算匹配框架

本文基于 SMELT 的循环 SMoE 架构，将 Transformer 分为入口块、中间块和出口块，其中中间块被访问两次，共享所有参数。预算匹配框架通过四步调整确保公平比较：首先调整注意力投影维度以匹配 KV Cache，其次调整模型宽度以匹配每步计算量，然后调整存储专家数量以匹配参数预算，最后选择整数优化步数以匹配总训练 FLOPs。该框架确保所有比较方法在存储参数、KV Cache、每步 FLOPs 和总训练 FLOPs 四个维度上偏差控制在 1% 以内。

### 循环访问的残差尺度不对称性

为探测两次循环访问的贡献差异，本文引入可学习的残差系数 $\alpha_1$ 和 $\alpha_2$，分别控制第一次和第二次访问的残差更新强度：

$$h' = h + \alpha_v f_\ell(h), \quad v \in \{1, 2\}$$

其中 $f_\ell$ 表示注意力或 MoE 残差分支，$\alpha_v$ 在访问 $v$ 的所有层和分支类型间共享。实验发现，在 1.3B 和 3B 模型上，第一次访问学习到的系数显著小于第二次访问（最终值分别约为 0.27 和 0.87，以及 0.36 和 1.09）。固定系数实验进一步验证：降低第一次访问的残差尺度可保持或改善验证 NLL，而对第二次访问施加相同降低则导致性能退化。这一不对称性表明，第一次访问对模型表征的贡献较弱，为减少其计算量提供了理论依据。

### 非对称计算分配与 LatentLoop 设计

基于残差尺度不对称性，本文探索四种减少第一次访问计算量的策略：残差流宽度减半、专家中间宽度减半、激活专家数从 8 减至 4、以及序列压缩。实验表明序列压缩策略取得最低验证 NLL，因其保留了每个潜在位置的全模型宽度和专家激活数，而宽度或专家数减少会限制单次访问的容量。

LatentLoop 采用序列压缩策略，定义压缩因子 $k$，编码器将 $T$ 个 Token 的状态 $H \in \mathbb{R}^{T \times d}$ 映射为 $l = T/k$ 个潜在位置：

$$Z = \text{Enc}(H), \quad \Delta = F_1(Z) - Z, \quad \tilde{H} = H + \text{Dec}(\Delta)$$

其中 $F_1$ 和 $F_2$ 分别表示第一次和第二次访问。第一次访问在压缩的潜在序列上执行，第二次访问在恢复的全分辨率序列 $\tilde{H}$ 上执行。节省的计算资源重新分配给模型宽度，形成非对称计算分配。

### 校准写回与选择性参数共享

潜在空间的增量 $\Delta$ 需写回全分辨率状态，其更新强度需校准。本文引入可学习的写回系数 $w_s \in \mathbb{R}^d$，对每个通道和接收位置独立缩放：

$$\text{Dec}(\Delta)_{kj+s} = w_s \odot \Delta_j, \quad 0 \leq s < k$$

其中 $\odot$ 表示逐元素乘法，$w_s$ 初始化为 1。该设计仅增加 $2d$ 个参数（$k=2$ 时），即可学习潜在更新的写回强度。

两次访问处理不同分辨率序列，可能偏好不同的注意力与 MoE 计算。由于 MoE 专家权重占存储参数的大部分，完全解耦 MoE 会丧失参数复用优势。本文仅解耦注意力模块，通过减少存储专家数量（如从 76 减至 75）补偿额外参数，保持激活专家数不变。该选择性共享策略在匹配预算下改善了验证 NLL。

## 实验评估

实验在 15 个匹配预算配置上进行，覆盖 1.3B 至 7B 参数规模，最大训练预算超过 $10^{21}$ FLOPs。基线包括标准 MoE Transformer（MoE Base）和 SMELT 循环架构（MoE Loop）。所有方法使用相同的 FineWeb-Edu 训练流、TinyLlama 分词器和 0.1B Token 验证集。

| 方法 | 验证 NLL | 相对 MoE Base 计算节省 | 相对 MoE Loop 计算节省 |
|------|----------|------------------------|------------------------|
| MoE Base | 2.0426 | - | - |
| MoE Loop | 2.0293 | - | - |
| LatentLoop | 2.0199 | 19.0% | 7.9% |

在拟合 NLL 为 1.988 时，缩放曲线预测 LatentLoop 相比 MoE Base 节省 19.0% 训练计算，相比 MoE Loop 节省 7.9%。下游任务评估覆盖 9 个基准，LatentLoop 在所有 6 种规模与样本设置组合中取得最高平均分，5-shot 设置下相对 MoE Loop 提升 0.73 至 1.18 个百分点。

消融实验验证了各组件贡献。编码器与解码器比较显示，学习写回系数（Scaled Decoder）将 NLL 从 2.0268 降至 2.0199，而学习编码器卷积或同时学习两者无进一步改善。参数共享比较表明，解耦注意力模块在压缩第一次访问配置下降低 NLL（从 2.0303 至 2.0268），但在标准 MoE Loop 中反而增加 NLL（从 2.0293 至 2.0319），说明该策略的收益依赖于非对称计算分配。

评估边界方面，实验未覆盖计算效率维度的直接测量（如实际延迟或吞吐量），仅通过 FLOPs 匹配间接控制。下游任务评估使用 lm-evaluation-harness 标准协议，但未报告置信区间。代码与超参数细节在附录中提供，但 GPU 型号与训练时间未明确披露。

## 关联研究分析

从问题动机看，LatentLoop 与 Elastic MoE 均关注动态资源分配，但优化维度不同。Elastic MoE 通过随机共激活采样允许推理时动态调整激活专家数，解决固定稀疏度导致的性能退化；LatentLoop 则在训练阶段固定非对称计算分配，通过序列压缩优化循环访问间的计算负载。Elastic MoE 的灵活性以训练复杂度为代价，而 LatentLoop 的非对称性源于对循环访问角色差异的实证观察，其设计更依赖对模型内部动态的深入理解。

从方法设计看，LatentLoop 与 SMELT 共享循环 SMoE 基础架构，但在计算分配策略上存在根本差异。SMELT 假设对称计算分配最优，两次访问执行相同操作；LatentLoop 通过残差系数实验揭示不对称性，并据此设计非对称计算。这一差异的根源在于对循环机制本质的理解：SMELT 将循环视为参数复用手段，LatentLoop 则将其视为可优化的计算调度问题。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文针对循环 SMoE 模型中对称计算分配可能非最优的问题，通过残差系数实验揭示两次循环访问的贡献不对称性，提出 LatentLoop 架构，在第一次访问中压缩序列、第二次保持全分辨率，并将节省计算重新分配给模型宽度。在 15 个匹配预算配置上，LatentLoop 一致降低验证 NLL，在拟合 NLL 1.988 时相比 MoE Base 节省 19.0% 训练计算。该工作证明了非对称计算分配在循环 SMoE 中的有效性，但其收益是否主要源于模型宽度增加而非序列压缩本身，论文未通过控制变量实验明确区分。当压缩因子 $k$ 增大时，潜在空间信息损失与模型宽度增益之间的权衡曲线如何变化，论文未给出回答。
