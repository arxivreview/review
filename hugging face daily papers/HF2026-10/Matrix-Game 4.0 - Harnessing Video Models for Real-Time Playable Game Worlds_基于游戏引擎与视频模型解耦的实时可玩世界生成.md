研究机构：香港中文大学、中国科学技术大学

作者：Jihai Zhang、Runjia Qian、Kaiqin Kong 等 18 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.27999)

> 交互式视频世界模型旨在构建能够感知、交互并预测物理世界演化的内部模拟器，其核心价值在于弥合被动视频生成与主动具身智能之间的鸿沟。现有方法主要依赖视频生成模型内部隐式状态维持世界连贯性，导致长时程生成中误差累积、状态遗忘及物理规则违背，且难以在单消费级 GPU 上实现低延迟实时交互。Matrix-Game 4.0 提出“游戏引擎+视频模型”解耦架构，由轻量级引擎显式维护世界状态与执行规则，视频模型仅负责将低多边形代理渲染为高保真视觉。该架构通过因果自回归蒸馏与少步采样，在单张 RTX 5090 上实现 112 ms 延迟与 83 FPS 吞吐，验证了“渲染与逻辑分离”范式在实时可玩性上的有效性。然而，该架构依赖预定义引擎规则，其在开放域非结构化场景中的泛化能力及对未定义物理现象的处理边界仍存疑。

## 研究背景

当视频生成模型被用于模拟世界时，其核心困境在于状态持久性与实时交互的矛盾。传统视频扩散模型（Video Diffusion Models）通过时空注意力机制生成视觉连贯的序列，但缺乏显式状态存储，导致长时程生成中早期观测内容被遗忘，场景重置或物体消失。为解决此问题，自回归生成范式（Autoregressive Generation）被引入以支持流式交互，但误差累积问题随之凸显：微小偏差在滚动生成中不断放大，最终导致场景崩溃。此外，高保真扩散模型推理速度慢，难以满足实时交互需求，而加速方法往往牺牲视觉质量或长时程稳定性。

当前领域正经历从视觉保真度向长时程一致性、几何持久性及物理合理性的范式转移。主流路线如 Genie 系列和 GameNGen 确立了动作条件化生成范式，但依赖模型内部隐式潜空间维持状态，难以处理复杂游戏机制与多智能体协同。具身智能应用如 ABot-PhysWorld 通过 DPO 后训练抑制非物理行为，但后训练过程复杂且依赖高质量标注。实时交互架构如 ABot-World-0 通过系统级优化实现单 GPU 部署，但主要面向特定场景优化，缺乏通用规则执行能力。Matrix-Game 4.0 的切入点在于：将世界状态维护与规则执行从视频模型中剥离，交由外部游戏引擎处理，视频模型仅作为“渲染器”，从而从根本上解决状态遗忘与物理违背问题，并通过架构解耦释放实时性能瓶颈。

## 核心方法

### 方法参照系：动作条件化视频生成

交互式视频世界模型的标准流程为：给定历史观测序列 $O_{1:t}$ 和动作序列 $A_{1:t}$，模型预测未来观测 $O_{t+1:T}$，即 $P(O_{t+1:T} | O_{1:t}, A_{1:t})$。该流程要求模型不仅生成视觉逼真的视频，更要确保生成内容在因果逻辑上与动作输入一致。Matrix-Game 4.0 与该通用流程的关键差异在于：它不依赖模型内部隐式状态维持世界连贯性，而是引入外部游戏引擎作为“裁判”，显式维护世界状态并执行交互规则，视频模型仅接收引擎输出的低多边形代理（Low-poly Proxy）和动态字幕（Dynamic Caption）作为条件，负责视觉渲染。

### 引擎-模型解耦架构与动态字幕生成

该解耦架构将游戏执行与视觉生成分离：代码定义规则，引擎维护状态，视频模型生成视觉。引擎作为外部游戏管理器，通过简化几何表示（如低多边形代理）提供空间布局、物体运动和相机视角约束，并显式维护健康、库存、重力、碰撞等游戏状态。视频模型接收引擎输出的低多边形代理和动态字幕作为条件，生成高保真帧。动态字幕由引擎状态实时生成，包含可见物体 ID、位置、距离、状态及事件，为视频模型提供细粒度语义条件。该设计解决了纯生成式模型在长时程生成中因缺乏显式状态存储导致的场景重置问题，并通过引擎硬约束确保物理规则执行，避免了视频模型学习视觉相关性而非因果律的幻觉。

### 因果自回归蒸馏与少步采样推理

为满足实时交互需求，Matrix-Game 4.0 采用因果自回归蒸馏（Causal Autoregressive Distillation）将双向扩散模型转换为因果生成器，每次去噪一个块（一个潜帧）仅需一步或两步。训练分为三个阶段：第一阶段为教师强制自回归扩散，模型在干净历史帧条件下训练；第二阶段为因果一致性蒸馏，通过在线学生与 EMA 学生匹配教师预测，实现四步生成；第三阶段为分布匹配，学生从自身自回归滚动中学习，使用非对称 DMD（Distribution Matching Distillation）优化。推理时，模型通过 KV Cache 存储空间记忆帧、参考帧及最新 20 个块的键值，结合 FP8 量化、分裂 KV 注意力及 CUDA Graph 优化，在单张 RTX 5090 上实现 112 ms 延迟与 83 FPS 吞吐。该设计解决了高保真扩散模型推理速度慢的问题，通过架构解耦将计算瓶颈从状态维护转移至视觉渲染，并通过蒸馏与推理优化实现消费级 GPU 实时部署。

## 实验评估

实验在自建 UE5 配对数据集（CitySample、沙漠、城堡、空战）上进行，训练数据共 114,334 个片段，1,712 小时。评估协议为 40 秒 held-out 滚动生成，条件为低多边形代理与动态字幕。基线覆盖包括 World Model (streaming)、Magpie、AgentGarten 等实时系统，缺失知识库中经典的纯生成式基线（如 Genie, Sora）的直接对比，因任务定义不同（游戏引擎驱动 vs 纯数据驱动）。

| 系统 | 延迟 (ms) | 分辨率 | 硬件 | 吞吐 (FPS) |
| :--- | :--- | :--- | :--- | :--- |
| World Model (streaming) | ≈10,200 | 1344×768 | 1× H200 | — |
| Magpie | ≈1,550 | 1280×768 | 1× H100 | — |
| AgentGarten | ≈878 | 832×480 | 1× H100 | — |
| StreamRender-H3 | ≈517 | 1344×768 | 8× GB200 | — |
| Matrix-Game 4.0 | 112 | 864×480 | 1× RTX 5090 | 83 |

Matrix-Game 4.0 在单张消费级 GPU 上实现 112 ms 延迟，约为次优系统 AgentGarten 的 1/8，且是唯一在消费级 GPU 上运行的系统。单步去噪在 RTX 5090 上达到 83 FPS，在 RTX 5080 和 RTX 5070 Ti 上分别达到 67 FPS 和 58 FPS，显存占用约 18.2 GiB。消融实验显示，动态字幕与低多边形代理互补：代理提供结构约束，字幕提供语义细节，二者共同确保生成帧遵循引擎状态。评估边界在于：自建 UE5 数据与真实世界数据（如 DROID）分布差异可能影响模型在真实场景的迁移；引擎硬约束可能导致模型无法处理引擎未定义的“涌现”物理现象；知识库中 LIBERO、Minecraft VPT 等标准基准未直接覆盖本文任务，数值不可直接比较。

## 关联研究分析

从问题动机看，Matrix-Game 4.0 与 Genie 系列均致力于构建交互式世界模型，但 Genie 依赖模型内部隐式潜空间维持状态，导致长时程生成中误差累积与状态遗忘；Matrix-Game 4.0 通过外部引擎显式维护状态，从根本上解决此问题。这一差异源于任务特性：Genie 面向开放域视频生成，缺乏预定义规则；Matrix-Game 4.0 面向结构化游戏场景，引擎规则可预定义。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从方法设计看，Matrix-Game 4.0 与 ABot-World-0 均关注单 GPU 实时性，但 ABot-World-0 侧重系统级优化与部署效率，依赖模型内部状态；Matrix-Game 4.0 侧重“引擎-模型”解耦架构，将状态维护外包给引擎，视频模型仅负责渲染。这一差异源于对“世界模型”定义的不同理解：ABot-World-0 视模型为持久化生成环境，Matrix-Game 4.0 视模型为渲染器。引擎硬约束是否导致模型无法处理引擎未定义的“涌现”物理现象，论文未给出回答。

## 总结

Matrix-Game 4.0 要解决的核心矛盾是交互式视频世界模型中状态持久性与实时交互的冲突。现有方法依赖模型内部隐式状态维持世界连贯性，导致长时程生成中误差累积、状态遗忘及物理规则违背，且难以在单消费级 GPU 上实现低延迟实时交互。Matrix-Game 4.0 抓住“渲染与逻辑分离”的切入点，通过外部游戏引擎显式维护世界状态与执行规则，视频模型仅负责视觉渲染，从而从根本上解决状态遗忘与物理违背问题。该架构通过因果自回归蒸馏与少步采样，在单张 RTX 5090 上实现 112 ms 延迟与 83 FPS 吞吐，验证了“渲染与逻辑分离”范式在实时可玩性上的有效性。然而，该架构依赖预定义引擎规则，其在开放域非结构化场景中的泛化能力及对未定义物理现象的处理边界仍存疑。当引擎规则未覆盖某些物理交互时，视频模型是否会产生违反物理定律的幻觉，论文未给出回答。
