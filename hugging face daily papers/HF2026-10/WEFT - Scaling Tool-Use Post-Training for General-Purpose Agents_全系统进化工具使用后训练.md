# HuggingFace最新推荐论文 ｜WEFT: Scaling Tool-Use Post-Training for General-Purpose Agents ｜全系统进化工具使用后训练

研究机构：华东师范大学、复旦大学

作者：Bo Mao、Hang He、Linting Wang 等 20 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.36887)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.36887)

> 工具使用后训练的核心矛盾在于，仅扩展可执行环境无法保证学习信号的可靠性，因为任务失败可能源于环境缺陷或验证器错误而非模型策略。现有环境扩展方法将环境视为静态固定组件，忽略了交互系统中各组件间的耦合关系。WEFT 通过执行驱动自进化机制，利用执行轨迹区分策略失败与系统缺陷，迭代修订环境、任务及验证器组件。该方法在匹配规模的环境扩展基线中取得最优性能，但其自进化闭环对训练信号可靠性的提升幅度，在缺乏纯 RL 基线对比的情况下，归因仍存疑。

## 研究背景

当智能体在长程任务中执行多步工具调用时，早期微小错误会随步骤增加而放大，导致最终任务失败。这一错误累积现象源于缺乏有效的中间状态校验与回溯机制，使得模型难以区分是自身策略失误还是环境反馈异常。为缓解此问题，研究者引入前缀保留拒绝采样，保留已验证的中间进度，仅对失败原子任务进行重采样，从而避免整体轨迹废弃。然而，这种局部修复策略假设环境本身是可靠的，若环境存在工具实现缺陷或验证器逻辑错误，保留的“正确”前缀可能包含误导性状态，导致后续学习信号失真。

工具使用后训练的主流路线聚焦于可执行环境的程序化合成，通过扩展工具覆盖度与任务复杂度提升模型泛化能力。EnvScaler 等环境扩展方法证明了大规模合成环境对后训练的增益，但其核心假设是环境组件（工具、任务、验证器）在训练过程中保持静态。这一假设在复杂跨工具任务中失效：任务失败可能由不可行任务、工具崩溃或验证器误判引起，将此类失败归因于策略会惩罚有效行为，引入误导性学习信号。WEFT 的切入点在于将扩展范围从单一环境扩展至完整智能体交互系统，通过执行反馈驱动系统组件的迭代修订，从源头提升训练信号可靠性。

## 核心方法

### 方法参照系

工具使用后训练的标准流程包含环境构建、轨迹生成与策略优化三个阶段。本文问题与该通用流程的关键差异在于，标准流程假设环境组件静态固定，而 WEFT 将环境、任务、验证器纳入迭代修订闭环，使系统本身成为可优化的学习对象。

### 执行驱动自进化

传统环境扩展方法在构建完成后即固定环境组件，执行轨迹仅用于策略训练。WEFT 在执行阶段引入失败归因机制，利用执行轨迹与状态证据区分策略失败与系统缺陷。归因代理检查任务图、轨迹、检查点结果与状态差异，将失败路由至环境后端、任务图或验证器进行定向修订。修订后通过新鲜 Rollout 评估变更效果，驱动下一轮进化。该机制解决了静态环境假设下，环境缺陷导致的误导性学习信号问题，使训练数据质量随系统迭代持续提升。

$$
r_k(\tau) = \begin{cases} 1 & \text{if all checkpoint conditions hold} \\ 0 & \text{otherwise} \end{cases}
$$

轨迹得分 $r_k(\tau)$ 为各检查点条件的均值，用于量化任务完成度，为失败归因提供可验证的中间状态依据。

### 原子级信用分配

强化学习中的轨迹级奖励难以准确归因到具体中间步骤，导致长程任务训练不稳定。WEFT 采用原子级组相对信用分配，在固定拓扑序下，每个原子任务回合从相同历史与状态独立采样 $G$ 个片段，基于当前任务二元完成结果计算组相对优势。该设计将信用分配粒度从轨迹级细化至原子任务级，解决了轨迹级奖励在长轨迹中稀疏且噪声大的问题，提供更细粒度的学习信号。

$$
A_t = \frac{R_t - \bar{R}_t}{\sigma_t}
$$

原子级优势 $A_t$ 基于当前回合的二元完成结果 $R_t$ 与组内均值 $\bar{R}_t$ 计算，$\sigma_t$ 为组内标准差，确保学习信号局部化且可验证。

## 实验评估

实验在 BFCL V4、τ²-Bench、Claw-Eval、Toolathlon-Verified 与 AutomationBench 五个基准上评估 Qwen3-8B、14B 与 35B-A3B 模型。基线覆盖环境扩展类方法（Agent-World、EnvScaler、AWM 等），但缺失纯提示工程基线（如 ReAct 原始版）及最新 SOTA 对比，限制了跨路线公平比较。

| 方法 | BFCL V4 | τ²-Bench | Claw-Eval |
| :--- | :--- | :--- | :--- |
| Agent-World-14B | 53.9 | 55.8 | 31.5 |
| WEFT-14B | 52.38 | 76.32 | 43.77 |
| Agent-World-8B | 44.5 | 51.4 | 30.5 |
| WEFT-8B | 47.75 | 71.93 | 35.78 |

WEFT-14B 在 τ²-Bench 与 Claw-Eval 上显著领先 Agent-World-14B，分别提升 20.52 与 12.27 个百分点，但在 BFCL V4 上略低 1.52 点，表明自进化机制在多轮交互与长程任务中优势更明显。

| 配置 | Toolathlon-Verified | AutomationBench | Claw-Eval |
| :--- | :--- | :--- | :--- |
| Agentic | 27.78 | 10.50 | 59.55 |
| Both + OpenClaw + Hermes | 45.99 | 26.50 | 64.00 |

多视图与多框架组合带来最大增益，Toolathlon-Verified 提升 18.21 点，表明交互多样性对长程工作流任务至关重要。自进化三轮使工具调用错误率从 1.76% 降至 0.96%（相对降低 45.5%），下游基准提升 3.65–5.25 点，验证了系统修订对训练信号可靠性的直接贡献。

评估协议采用各基准原生框架与官方聚合指标，但多数结果未报告置信区间，数值比较需谨慎。代码与超参数未公开，可复现性受限。MegaMCP 基础设施实验显示其降低并发 Rollout 的数据传输、内存使用与冷启动延迟，但未量化对训练收敛速度的影响。

## 关联研究分析

从问题动机看，WEFT 与 Agent0 均聚焦自进化框架，但 Agent0 聚焦课程与执行 Agent 协同进化，WEFT 扩展至环境、任务与验证器组件修订。这一差异源于任务特性：Agent0 假设环境静态可靠，仅需优化策略；WEFT 针对跨 MCP 复杂任务，环境缺陷是主要失败源，必须将系统组件纳入优化范围。Tool-R0 同样使用 RL 与可验证奖励，但侧重难度奖励机制，WEFT 侧重原子级信用分配与系统修订，两者在奖励设计粒度上形成互补。

从方法设计看，WEFT 与 EnvScaler 同属环境扩展路线，但 EnvScaler 仅扩展环境覆盖度，WEFT 扩展至全交互系统。这一差异反映了领域共识的演进：早期研究认为环境规模是主要瓶颈，WEFT 指出信号可靠性是更深层约束。然而，WEFT 的自进化闭环是否引入过拟合特定环境的风险，论文未给出回答。当环境修订频繁时，模型是否过度适应修订后的环境而丧失跨域泛化能力，缺乏实验验证。

## 总结

WEFT 要解决的核心矛盾是环境扩展与学习信号可靠性之间的脱节。现有环境扩展方法将环境视为静态组件，无法区分策略失败与系统缺陷，导致误导性学习信号。WEFT 通过执行驱动自进化机制，利用执行轨迹归因失败并迭代修订系统组件，从源头提升信号可靠性。该方法在匹配规模的环境扩展基线中取得最优性能，WEFT-14B 在 τ²-Bench 上达 76.32%，自进化三轮使工具调用错误率相对降低 45.5%。其边界在于缺乏纯 RL 基线对比，无法完全归因增益来源；自进化闭环对跨域泛化能力的长期影响未量化。当环境修订频率增加时，模型是否过度适应修订后的环境而丧失跨域泛化能力，论文未给出回答。
