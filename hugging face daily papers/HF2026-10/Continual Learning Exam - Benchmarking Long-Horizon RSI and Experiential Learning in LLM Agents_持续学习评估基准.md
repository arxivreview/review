> 导读：LLM 智能体在长时程部署中需通过经验积累实现能力增益，但现有评估体系仅关注单次任务成功率，无法量化跨任务的知识复用与持续改进。本文提出 CLE 基准，通过构建具有依赖关系的五层任务阶梯，强制智能体在后续任务中复用前序任务产出的状态与知识。该基准引入诊断反馈机制，评估智能体从失败中修正策略的过程能力，并显式区分模型参数与脚手架状态对持续学习的影响。实验表明，即使提供诊断反馈，当前前沿模型在 CLE 上的最佳完成率仅为 47.67%，揭示了长时程经验复用仍是智能体部署的核心瓶颈。

## 研究背景

当智能体在真实工作流中连续执行任务时，其能力不仅取决于单次推理的准确性，更取决于能否从过往交互中提取有效经验并应用于新任务。这种能力被称为持续学习（Continual Learning, CL），其核心在于通过更新模型参数或持久化脚手架状态，实现知识的获取、精炼与复用，同时避免灾难性遗忘。然而，现有评估范式存在结构性缺陷：通用基准如 GAIA 将任务视为独立样本，仅评估最终输出的正确性；记忆基准如 LoCoMo 虽测试历史检索，却未验证检索到的知识是否真正提升了后续任务执行效率。这种“结果导向”的评估无法捕捉智能体在长时程交互中因经验积累而产生的能力演化，导致实验室高分与实际部署中的低效形成显著落差。

领域内对过程评估的共识已确立，即需审计智能体的完整行为轨迹而非仅关注最终状态。但现有过程评估多局限于单任务内的多步推理，缺乏跨任务的知识迁移度量。智能体脚手架（Scaffold）的设计对性能影响显著，但现有基准未将脚手架状态（如记忆、技能）的演化纳入评估维度。CLE 的切入点在于将评估对象从“单次任务解决能力”转向“跨任务经验复用能力”，通过构建具有强依赖关系的任务序列，量化智能体在长时程交互中的持续学习增益。

## 核心方法

### 任务阶梯与状态依赖结构

CLE 将每个任务组织为五层任务阶梯（Task Ladder），后续层级的任务目标与约束依赖于前序层级产出的状态与知识。这一设计将评估从独立任务序列转化为依赖链，强制智能体在后续任务中复用前序任务积累的经验。任务阶梯的结构化设计解决了现有基准中任务间无关联、无法评估知识迁移的问题。

### 持续学习形式化与更新机制

CLE 将智能体与环境交互建模为部分可观测马尔可夫决策过程（POMDP），显式区分环境状态 $x_t$ 与智能体内部状态 $s_t$。环境状态包含工作区文件、应用记录及任务进度，而智能体内部状态包含模型上下文、持久化记忆及技能。智能体通过策略 $\pi_{\theta,h}$ 选择动作，环境返回观测与奖励，脚手架通过更新算子 $U_t$ 更新内部状态。

$$
(\theta, s_{t+1}) = U_t(\theta, s_t, e_t)
$$

该公式描述了脚手架如何基于当前状态 $s_t$ 与交互经验 $e_t$ 更新智能体内部状态。在 CLE 评估中，模型参数 $\theta$ 保持冻结，学习过程完全通过更新持久化状态 $s_t$ 实现。这一设计隔离了模型预训练能力与脚手架学习能力，使评估聚焦于经验复用机制的有效性。

### 诊断反馈与多轮修正机制

CLE 引入诊断反馈机制，模拟人类协作中的修正过程。在 Trial 2 设置中，智能体首次提交失败后，评估代理返回基于评分标准的类别级反馈，智能体可据此修正策略并再次提交。这一机制评估了智能体从失败中学习并调整策略的能力，而非仅评估初始策略的鲁棒性。

$$
r_{t+1} = \begin{cases} v_t, & \text{if } a_t \text{ submits work for grading} \\ 0, & \text{otherwise} \end{cases}
$$

该奖励函数定义仅在提交动作时产生非零奖励，且奖励值由评估代理的判定结果 $v_t$ 决定。诊断反馈作为观测的一部分返回给智能体，成为更新内部状态 $s_t$ 的关键信号。这一设计解决了现有基准中失败信号缺失、智能体无法从错误中学习的问题。

## 实验评估

CLE 基准包含 120 个任务，每个任务五层，共 600 层，覆盖 89 个专业角色与 12 个职业领域。实验评估了 17 种脚手架-模型配置，包括 Claude Code、Codex 等主流框架及 GPT-5.6、Opus 5 等前沿模型。所有配置在模型参数冻结条件下执行，评估指标为层级完成率（Completion Rate）。

| 配置 | Trial 1 完成率 (%) | Trial 2 完成率 (%) | 增益 (pp) |
| :--- | :--- | :--- | :--- |
| Claude Code + Opus 5 | 42.37 | 47.67 | 5.30 |
| Codex + GPT-5.6-Sol | 27.87 | 33.17 | 5.30 |
| Codex + GPT-5.6-Terra | 27.87 | 33.17 | 5.30 |

实验结果显示，诊断反馈与二次提交机制带来中位数 5.3 个百分点的完成率增益，但最佳系统 Claude Code + Opus 5 的完成率仅为 47.67%，且仅 23.3% 的任务完成全部五层。这一低完成率反映了持续学习任务的极高难度，而非评估协议失效。与 GAIA 基准上 OAgents 73.93% 的完成率相比，CLE 的低分源于任务间强依赖结构对经验复用能力的严苛要求。

消融分析表明，脚手架设计对持续学习性能影响显著。不同脚手架在相同模型下表现出显著的性能差异，证实了脚手架状态管理是持续学习的关键瓶颈。然而，实验未深入分析 Token 成本与学习增益的帕累托前沿，未覆盖多智能体协作场景，且诊断反馈可能引入“作弊”信号，高估智能体自主学习能力。

## 关联研究分析

从问题动机看，CLE 与 τ-bench 均关注动态环境中的智能体表现，但 τ-bench 局限于单任务内的多轮交互一致性，未涉及跨任务知识迁移。CLE 通过任务阶梯结构，将评估维度从单任务状态管理扩展至跨任务经验复用，填补了持续学习评估的空白。这一差异源于任务特性：τ-bench 模拟客服场景，任务间无强依赖；CLE 模拟专业工作流，任务间存在强知识依赖。

从方法设计看，CLE 与 GAIA 均使用真实文件与工具调用环境，但 GAIA 将任务视为独立样本，CLE 通过任务阶梯强制后续任务依赖前序任务产出的状态。这一设计差异导致评估目标根本不同：GAIA 评估单次任务解决能力，CLE 评估跨任务经验复用能力。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

CLE 针对现有评估体系无法量化智能体跨任务经验复用能力的矛盾，通过构建具有强依赖关系的五层任务阶梯与诊断反馈机制，重新定义了持续学习评估标准。实验表明，即使提供诊断反馈，当前前沿模型在 CLE 上的最佳完成率仅为 47.67%，揭示了长时程经验复用仍是智能体部署的核心瓶颈。该基准的边界在于未覆盖多智能体协作场景，且诊断反馈可能引入外部信号干扰，高估智能体自主学习能力。当智能体在无诊断反馈条件下执行任务时，其经验复用能力是否显著下降，论文未给出回答。
