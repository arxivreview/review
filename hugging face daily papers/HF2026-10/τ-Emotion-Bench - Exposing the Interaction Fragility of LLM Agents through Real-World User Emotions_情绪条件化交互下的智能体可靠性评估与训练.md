> 导读：LLM智能体在长时程工具调用任务中，常因过度依赖用户交互或低效追问导致任务虽最终完成但用户体验极差，现有评估体系仅以终端任务成功率为核心指标，无法捕捉此类交互效率缺陷。本文引入情绪条件化用户模拟器，构建τ-Emotion-Bench基准，并设计Tracer数据生成管道，通过允许不满用户终止交互来提供交互感知奖励信号。该机制有效过滤了低效轨迹，显著提升了小模型在情绪波动环境下的任务一致性与工具使用平衡性。这一工作填补了智能体评估中情绪鲁棒性与交互效率解耦的空白，但情绪模拟的真实性与跨域泛化边界仍需进一步验证。

## 研究背景

当LLM智能体在动态环境中执行多步工具调用时，其能力不仅取决于底层模型的推理水平，更受制于与用户及环境的交互质量。传统评估框架如τ-Bench确立了工具-用户-环境交互范式，但其假设用户行为稳定且合作，忽略了真实场景中用户情绪波动对交互流程的干扰。这种理想化假设导致评估结果高估了智能体在复杂社会交互中的可靠性，使得实验室高分无法转化为生产环境中的稳定表现。

当前智能体训练与评估的核心瓶颈在于奖励信号的单一性。现有方法普遍以终端任务成功作为唯一正向信号，导致智能体学会通过反复追问或过度依赖用户来规避环境不确定性，即使最终完成任务，其交互过程也充满冗余与低效。这种“结果正确但过程低效”的行为模式在面向用户的智能体中是不可接受的。本文切入点在于将用户情绪状态纳入交互闭环，通过情绪条件化模拟非合作或易怒用户，迫使智能体在压力下优化工具使用与交互效率的平衡。

## 核心方法

### 方法参照系：情绪条件化交互评估框架

本文方法建立在τ-Bench的交互式评估框架之上，该框架通过可执行环境、领域策略文档及用户模拟器构建多轮对话任务。与通用流程的关键差异在于，本文在用户模拟器中引入了结构化情绪条件，将用户行为从静态指令执行转变为动态情绪响应。这一改动使得评估对象从单纯的任务完成度扩展为情绪鲁棒性与交互效率的综合表现，要求智能体在用户情绪恶化时仍能保持策略合规与工具调用效率。

### 核心创新：基于依赖图的任务生成与情绪注入

传统基准任务生成依赖人工编写或模板填充，难以保证工具调用的逻辑严密性与情绪条件的自然融合。Tracer管道首先从领域工具集与策略文档中构建有效多步工作流依赖图，确保任务在环境中的可执行性。随后，通过反向细化将工具调用轨迹转化为自然用户指令，并保留任务目标与上下文歧义。在此基础上，系统生成任务特定感受并映射至结构化情绪条件，包括愤怒、恐惧、厌恶、悲伤与愉悦五大情绪家族及其细粒度子情绪（如焦虑、挫败感）。

该设计解决了此前方法中情绪条件与任务目标脱节的问题。情绪条件不仅作为用户初始状态，更通过强度（低、中、高）与行为倾向（如简短、不耐烦、指责性）动态影响后续对话轮次。这种任务-情绪耦合机制确保了评估场景既具备工具调用的逻辑严谨性，又具备真实交互的情绪复杂性，为后续奖励信号设计提供了可控的测试环境。

### 核心创新：交互感知奖励信号与轨迹过滤

常规轨迹收集仅以任务完成为奖励，无法区分高效工具使用与低效用户依赖。Tracer引入交互感知奖励信号，其核心机制在于允许情绪不满的用户主动终止交互。当智能体反复提出不必要问题或未能通过工具获取可获取信息时，用户模拟器根据情绪状态判定满意度下降并终止对话，导致轨迹即使潜在可完成任务也无法获得正向奖励。

该机制的奖励函数可形式化为：

$$
R(\tau) = \begin{cases}
1 & \text{if } \text{TaskSuccess}(\tau) \land \text{InteractionEfficient}(\tau) \\
0 & \text{if } \text{TaskSuccess}(\tau) \land \neg \text{InteractionEfficient}(\tau) \\
-1 & \text{if } \neg \text{TaskSuccess}(\tau) \lor \text{UserTerminated}(\tau)
\end{cases}
$$

其中 $\text{InteractionEfficient}(\tau)$ 表示轨迹中工具调用与必要追问的平衡度。该公式的物理含义在于，仅当任务成功且交互过程未触发用户不满终止时，轨迹才被标记为高质量训练数据。这一设计直接过滤了“成功但低效”的轨迹，迫使智能体在训练阶段即学会优先使用工具而非用户，从而在推理阶段表现出更高的自主性与情绪鲁棒性。

## 实验评估

实验在τ-Emotion-Bench的580个任务上进行，涵盖航空、零售、电信等十个领域。评估协议采用三次独立运行，报告Avg@3（平均成功率）与Pass^3（三次均成功的一致性指标）。基线覆盖包括Qwen3系列、DeepSeek-V4.1-Flash等前沿模型，以及AReaL、EnvScaler等智能体训练方法。

| 模型 | 用户模拟器 | Avg@3 (%) | Pass^3 (%) |
| :--- | :--- | :--- | :--- |
| GLM-5.3 | GLM-5.2 | 78.6 | 66.5 |
| DeepSeek-V4.1-Flash | Qwen3-235B | 55.9 | 32.2 |
| Tracer-High-8B | GLM-5.2 | 54.7 | - |
| Qwen3-8B Base | GLM-5.2 | 8.4 | - |

主结果显示，即使是最强前沿模型GLM-5.3，在GLM-5.2用户模拟下Avg@3达78.6%，但Pass^3仅为66.5%，揭示了情绪波动下任务一致性的显著缺口。在Qwen3-235B用户模拟下，DeepSeek-V4.1-Flash的Pass^3进一步降至32.2%，证实了情绪条件化交互对智能体可靠性的严峻挑战。Tracer-High-8B在GLM-5.2用户下达到54.7% Avg@3，较Qwen3-8B基线提升46.3个百分点，验证了交互感知奖励对小模型能力的显著增强。

| 模型规模 | 方法 | Avg@3 (%) | Pass^3 (%) |
| :--- | :--- | :--- | :--- |
| Qwen3-1.7B | Base | 3.3 | 0.0 |
| Qwen3-1.7B | Tracer-Low | 9.3 | 8.0 |
| Qwen3-4B | Base | 16.0 | 0.0 |
| Qwen3-4B | Tracer-Low | 21.3 | 6.0 |
| Qwen3-8B | Base | 24.7 | 0.0 |
| Qwen3-8B | Tracer-Low | 29.3 | 8.0 |

消融分析表明，Tracer-Low仅使用1,498条四领域轨迹训练，即在1.7B至8B模型上均实现Pass^3从0.0%到6.0%-8.0%的突破，且Avg@3提升幅度达5.3-6.0个百分点。这一结果揭示了交互感知奖励在小模型上的高边际收益，且Tracer-Low在六个未见领域上仍保持最强Pass^3，证明了该训练信号具备跨域泛化能力。

评估边界方面，本文未报告置信区间，且用户模拟器可靠性虽经LLM评判器验证（仅1.1%失败轨迹含用户幻觉），但情绪模拟的细粒度真实性仍依赖LLM生成质量。代码与模型已开源，但情绪条件与任务目标的耦合强度缺乏量化指标，可能影响跨基准迁移的可解释性。

## 关联研究分析

从问题动机看，τ-Emotion-Bench与τ-Trait均关注用户行为变异，但τ-Trait侧重于静态特质（如不耐烦、困惑）对任务策略的影响，而本文引入动态情绪演化与交互终止机制，将评估从“行为稳定性”推进至“情绪鲁棒性”。这一差异源于任务特性：τ-Trait假设用户始终合作，而本文假设用户可能因低效交互而退出，更贴近生产环境中的用户流失风险。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从方法设计看，Tracer与AReaL、EnvScaler等智能体训练方法均利用可执行环境生成轨迹，但后者仅以任务成功为过滤标准，导致训练数据中混杂大量低效交互轨迹。Tracer通过用户终止机制引入负向信号，直接惩罚过度依赖用户的行为。这一设计选择解决了纯任务导向训练中“结果正确但过程低效”的失效模式，但代价是可能过滤掉部分在极端情绪下仍需用户澄清的合理交互，论文未量化此类误过滤对复杂任务的影响。

## 总结

本文针对LLM智能体在情绪波动交互中可靠性不足与交互效率低下的核心矛盾，提出τ-Emotion-Bench基准与Tracer训练管道。通过引入情绪条件化用户模拟器与交互感知奖励信号，该工作将评估维度从终端任务成功扩展至交互过程效率，并证明了该信号在提升小模型任务一致性上的有效性。GLM-5.3在GLM-5.2用户下78.6% Avg@3与66.5% Pass^3的差距，以及Tracer-High-8B较基线46.3个百分点的提升，量化了情绪鲁棒性评估的必要性与交互感知训练的收益。然而，情绪模拟的细粒度真实性与跨域泛化边界仍受限于LLM生成质量，且交互终止机制可能误过滤合理澄清行为。当情绪强度从低提升至高水平时，交互感知奖励对工具调用策略的约束是否会导致过度保守而牺牲任务灵活性，论文未给出回答。
