# HuggingFace最新推荐论文 ｜ReSAIL: Mitigating Collapse in Iterative Agent Self-Distillation ｜迭代自蒸馏中的性能崩溃与特权保留机制

研究机构：中国人民大学

作者：Shengjie Jin、Hengbo Xu、Zelong Sun 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2609.39306)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2609.39306)

> 迭代自蒸馏旨在让大语言模型智能体通过多轮部署实现递归自我改进，但现有方法在循环迭代中常出现性能崩溃。本文发现崩溃根源在于学生模型在提升普通视角任务性能的同时，丢失了作为下一轮教师所需的特权信息条件化能力。ReSAIL通过敏感度引导的选择性蒸馏与特权保留正则化，在保持教师能力的前提下优化学生模型。该机制有效缓解了性能崩溃，但仅在离线固定数据集上验证，在线动态环境下的泛化能力存疑。

## 研究背景

当智能体在环境中执行多步交互时，其生成的轨迹包含动作、观察与任务结果，这些轨迹为后续决策提供了反馈。利用这些反馈更新模型参数或记忆，构成了自进化的基础。然而，若仅将过往经验作为上下文提示，受限于上下文窗口，长期任务中性能会因信息溢出而下降；若将经验内化为模型参数，则面临灾难性遗忘风险。

参数化内化路线试图通过监督微调或强化学习将经验固化到权重中，以实现持久能力。EvolveR等框架通过定期蒸馏文本经验为参数，解决了长期知识固化问题，但计算成本高且易导致旧能力退化。近期工作如SDPO和OEL提出迭代自蒸馏，交替进行经验收集与离线蒸馏，旨在实现递归自我改进。然而，实验表明重复这一循环并不保证持续改进，性能可能在几个周期后崩溃。

本文切入点在于诊断迭代自蒸馏失效的具体机制。现有方法假设学生模型在更新后能无缝替代教师角色，但忽略了学生模型在失去特权信息（PI）后的普通视角训练，会破坏其保留特权视角行为的能力。这种“教师能力退化”导致后续循环的监督信号质量下降，形成恶性循环。ReSAIL旨在通过选择性蒸馏与特权保留，打破这一崩溃链条。

## 核心方法

### 方法参照系

本文基于迭代自蒸馏框架，其中策略 $\pi$ 具有共享参数的普通视角（无PI）与特权视角（有PI）。基线方法SDPO和OEL在每个周期 $r$ 中，使用固定轨迹数据集 $D_r$ 训练学生 $\pi_S$ 匹配冻结教师 $\pi_T$ 的特权视角分布，更新后的学生成为下一周期的教师。本文的关键差异在于引入对交互步骤的选择性蒸馏与特权视角行为的显式保留，以解决迭代崩溃问题。

### 敏感度引导的选择性蒸馏

基线方法对所有交互步骤均匀计算KL散度损失，忽略了PI对不同步骤预测影响程度的差异。ReSAIL引入敏感度引导选择（SGS），定义PI敏感度为教师模型在普通与特权视角下的Jensen-Shannon散度：

$$ s_{\pi}(h, c; z) = \frac{1}{|z|} \sum_{k=1}^{|z|} \text{JSD}(\pi(\cdot | h, z_{<k}), \pi(\cdot | h, c, z_{<k})) $$

该公式量化了PI对教师预测分布的改变程度。SGS仅保留敏感度最高的步骤进行蒸馏，并通过轨迹损失平衡（TLB）避免长轨迹主导损失。这一设计解决了均匀蒸馏中低信息量步骤稀释高信息量步骤信号的问题，提升了单周期内的学习效率。

### 特权保留正则化

选择性蒸馏仅优化学生模型的普通视角，未约束其特权视角行为，导致学生作为下一轮教师时能力退化。ReSAIL引入特权保留（PR），将学生模型的特权视角输出分布向冻结教师的特权视角分布正则化：

$$ \mathcal{L}_{ret} = \frac{1}{|B|} \sum_{\tau \in B} \frac{1}{|U(\tau)|} \sum_{t \in U(\tau)} \mathcal{L}_{ret}(\tau, t) $$

其中 $\mathcal{L}_{ret}(\tau, t)$ 为学生与教师在特权视角下的KL散度。该正则化项覆盖所有交互步骤，确保学生模型在提供下一轮监督时，其特权视角行为与当前教师保持一致。这一设计解决了迭代自蒸馏中教师能力随循环递减的根本问题，实现了跨周期的能力保持。

## 实验评估

实验在ALFWorld（ID/OOD）和TextCraft上进行，使用Qwen3-4B和Qwen3-8B模型，对比ReAct、RFT、GRPO、EPD、SDPO和OEL基线。ReSAIL作为插件应用于SDPO和OEL。

| 方法 | ALFWorld OOD (Qwen3-8B) Cycle 3 | TextCraft (Qwen3-8B) Cycle 3 |
| --- | --- | --- |
| SDPO | 49.2(2.8) | 51.0(2.0) |
| SDPO + ReSAIL | 75.3(1.2) | 73.3(1.5) |
| OEL | 41.4(1.4) | 51.3(0.6) |
| OEL + ReSAIL | 78.4(1.2) | 73.7(1.5) |

ReSAIL显著提升了最终周期性能，OEL+ReSAIL在ALFWorld OOD上达到78.4%，较OEL基线提升37.0个百分点。

| 组件 | ALFWorld ID Cycle 3 | ALFWorld OOD Cycle 3 |
| --- | --- | --- |
| OEL (基线) | 47.4(1.2) | 38.5(1.2) |
| + SGS | 50.5(3.2) | 37.8(2.5) |
| + SGS + TLB | 56.5(3.0) | 45.6(1.6) |
| + SGS + TLB + PR | 74.2(1.4) | 67.2(2.3) |

消融实验显示，SGS单独使用在第一周期效果显著，但第三周期性能低于第一周期；加入PR后，第三周期性能达到峰值，验证了特权保留对跨周期稳定性的关键作用。

评估边界：实验仅使用离线固定数据集，未测试在线动态环境；未报告计算效率的详细对比，仅提及SGS降低优化成本约74%；代码未开源，可复现性受限。

## 关联研究分析

从问题动机看，本文与EvolveR等参数化内化方法同属长期能力构建路线，但EvolveR关注经验从文本到参数的蒸馏效率，而ReSAIL聚焦迭代过程中的教师能力保持。EvolveR假设单次蒸馏即可固化知识，未考虑多轮迭代中监督信号质量的退化；ReSAIL则揭示并解决了这一迭代特有的失效机制。这种差异源于任务特性：EvolveR适用于一次性经验内化，而ReSAIL针对递归自我改进场景。

从方法设计看，本文与Reflexion等非参数化方法形成对比。Reflexion通过自然语言反思存储经验，部署灵活且无灾难性遗忘风险，但受限于上下文窗口；ReSAIL通过参数更新实现能力内化，但需额外计算成本（1.23倍OEL）。ReSAIL的特权保留机制类似于知识蒸馏中的正则化，但专门针对智能体自进化中的角色转换（学生变教师）。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文要解决的核心矛盾是迭代自蒸馏中性能崩溃与教师能力退化的关联。现有方法如SDPO和OEL假设学生更新后可无缝替代教师，但忽略了普通视角训练对特权视角行为的破坏。ReSAIL通过敏感度引导的选择性蒸馏提升单周期效率，并通过特权保留正则化确保跨周期教师能力稳定。实验证明，ReSAIL使OEL在ALFWorld OOD上的最终周期成功率从41.4%提升至78.4%，有效缓解了性能崩溃。然而，实验仅在离线固定数据集上进行，未验证在线动态环境中的泛化能力。当环境状态随时间变化时，特权保留正则化是否仍能维持教师能力，论文未给出回答。
