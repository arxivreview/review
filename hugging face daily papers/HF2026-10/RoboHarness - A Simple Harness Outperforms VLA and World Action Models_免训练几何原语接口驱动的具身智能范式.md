作者：Bince Qu、Wei Chen、Bo Zhang

> 视觉-语言-动作模型（Vision-Language-Action, VLA）旨在将自然语言指令直接映射为机器人连续控制信号，其核心价值在于突破传统策略在复杂非结构化环境中泛化能力差的瓶颈。然而，现有 VLA 模型高度依赖大规模机器人动作数据的监督训练，且受限于离散 Token 预测或连续动作生成的精度与频率矛盾，难以在长程任务中实现零样本泛化。RoboHarness 提出了一种免训练的具身智能范式，通过构建最小完备的几何原语接口，使通用大语言模型（Large Language Model, LLM）能够直接理解并调用具身任务。该范式利用 2D 视觉定位、光流追踪与深度反投影机制，将 LLM 的语义规划能力与底层几何约束求解器解耦，从而在无需任何动作训练的前提下执行复杂操作。这一设计挑战了领域内“端到端 VLA 优于模块化架构”的共识，但在短程高频控制任务的适用性上仍存疑。

## 研究背景

当机器人面对开放世界的长程家务任务时，其核心困境在于如何将高层语义意图转化为精确的物理动作。传统方法通常采用端到端的 VLA 架构，通过收集海量机器人轨迹数据，训练模型直接输出末端执行器的动作序列。然而，这种“感知-动作”的直接映射隐含了动作空间可被充分表征的假设，忽略了物理世界对动作连续性、高频控制与力反馈的刚性需求。随着任务复杂度提升，离散化动作表征导致控制频率低与动作不连续，而连续动作生成（如 Flow Matching）虽提升了平滑性，却引入了巨大的计算开销与数据依赖。更关键的是，LLM 的世界知识存在于文本空间，缺乏对物理几何关系的直接建模能力，导致其在需要精确空间推理的任务中表现不佳。

为了弥合这一“看见-做到”差距，研究者尝试引入世界模型或显式推理机制，但这些方法往往增加了系统复杂度且未能根本解决数据稀缺问题。现有基于 LLM 的规划方法（如 Code as Policies）虽能生成控制程序，但其依赖预定义的技能库，每当出现新物体或新任务时，均需重新定义函数，限制了泛化能力。RoboHarness 的切入点在于重新审视 LLM 与物理世界的接口：LLM 已具备强大的任务分解与规划能力，其局限并非缺乏动作生成能力，而是缺乏一个简单且完备的几何控制接口。通过提供基于几何约束的最小原语工具集，而非训练模型生成动作，有望在零样本条件下实现跨任务、跨环境的通用操作。

## 核心方法

### 几何状态追踪与统一坐标系

在具身智能系统中，LLM 原生缺乏对三维空间关系的可靠推理能力，但其在二维图像上的视觉定位（Grounding）精度较高。RoboHarness 首先建立了一个统一的相机坐标系，将不同机器人形态（如 BEHAVIOR R1 Pro 和 RoboDojo ARX X5）的空间关系标准化。该坐标系以相机视角为基准，定义 $x$ 轴向前、$y$ 轴向左、$z$ 轴向上。基于此，系统设计了 `track_object` 工具，通过光流关键点追踪与深度反投影机制，将 LLM 在二维图像上标记的兴趣点持续映射为三维空间坐标。这一机制解决了 LLM 无法直接获取动态物体三维位置的问题，为后续几何约束求解提供了精确的输入状态。

### 最小完备几何原语接口

RoboHarness 的核心创新在于构建了一套最小且完备的动作原语工具集，取代了传统的动作头（Action Head）。该工具集分为关键点约束工具与调整工具两类。关键点约束工具允许 LLM 指定一组输入点及其空间关系（如线性、共面），由 Harness 自动求解并执行满足约束的动作。其完备性基于以下理论证明：

**命题 1：任意抓取姿态可由关键点约束表达。**
夹爪携带三个预定义点 $\{F_L, F_R, G\}$（左指尖、右指尖、夹爪中心）。任意接触姿态 $(f_l, f_r, \theta)$ 与三个表面点 $(a_1, a_2, a_3)$ 存在解析双射关系，满足约束：

$$
\text{overlap}[a_1, F_L], \quad \text{overlap}[a_2, F_R], \quad \text{linear}[c, a_3, G]
$$

其中 $c = \frac{a_1 + a_2}{2}$。该公式表明，通过约束夹爪关键点与物体表面点的重合及线性关系，可唯一确定抓取姿态，无需显式生成动作序列。

**命题 2：任意手内与手外物体关系可由关键点约束表达。**
对于两个刚体间的任意相对坐标变换 $T_{true} \in SE(3)$，存在两组非平行的空间线重合约束，使得满足该约束系统的未知变换 $T$ 唯一确定为 $T_{true}$。其核心逻辑在于，通过固定两条非平行线的对应关系，可消除 $SE(3)$ 的六个自由度，从而唯一确定物体间的相对位姿。

这一设计动机在于突破预定义技能库的限制。传统方法如 SayCan 或 Code as Policies 依赖人工定义的技能函数，而 RoboHarness 通过几何原语的完备性证明，确保了 LLM 仅需输出几何约束即可表达任意操作意图，无需针对新任务重新训练或定义函数。

### 闭环执行与调整机制

在 LLM 生成几何约束后，Harness 执行器通过采样动作候选、过滤逆运动学不可行解、规划轨迹并执行，完成动作闭环。为增强鲁棒性，系统提供了直接控制底层自由度的调整工具（如 `adjust_left_eef`），允许 LLM 在约束失败（如物体滑脱）时进行微调。这种分层设计将高层语义规划（LLM）与底层几何求解（Harness）解耦，避免了端到端模型中动作专家梯度干扰预训练知识的问题，同时保留了 LLM 的通用推理能力。

## 实验评估

### 实验设置与主结果

RoboHarness 在 BEHAVIOR-1K 基准上进行了评估，该基准包含长程家务任务，重点考察模型在复杂场景下的多步规划与执行能力。对比基线包括 SOTA VLA 模型（如 Galaxea G0.5, $\pi_{0.5}$）以及 BEHAVIOR Challenge 2025 的优胜方案（RLC, Comet）。实验采用 Qwen3.8-Flash-Next 作为 LLM 代理，未进行任何微调。

| 方法 | 类型 | 评估指标 | 结果描述 |
| :--- | :--- | :--- | :--- |
| Qwen3.8-Flash-Next + RoboHarness | 免训练 LLM 代理 | Mean $q$-score | 高于 SOTA VLA 模型 |
| Galaxea G0.5 | VLA | Mean $q$-score | 基线 |
| $\pi_{0.5}$ | VLA | Mean $q$-score | 基线 |
| RLC | 竞赛优胜 | Mean $q$-score | 基线 |

*注：具体数值未在输入材料中提供，仅知 RoboHarness 在前 10 个任务上的平均 $q$-score 高于上述基线。*

### 消融与设计决策验证

论文未提供详细的消融实验表格，但通过理论证明与定性分析验证了设计决策的有效性。完备性证明（命题 1 与 2）是核心设计决策，它确保了工具集的最小性与充分性。若移除几何约束求解器，LLM 将无法直接控制机器人；若移除光流追踪，LLM 将失去动态空间感知能力。实验表明，在完全分布外（Out-of-Distribution, OOD）的泛化测试中，RoboHarness 显著优于 VLA 与世界模型基线，这归因于其不依赖特定任务数据训练，而是依赖 LLM 的通用语义理解与几何求解器的精确执行。

### 评估边界与可复现性

评估协议存在局限：仅报告了前 10 个任务的平均 $q$-score，未提供置信区间或详细子任务成功率。此外，实验仅使用了 5 个实例，样本量较小，可能影响统计显著性。代码已开源，但提示工程（Prompt Engineering）对结果的影响未进行系统消融，无法排除提示设计对性能提升的贡献。

## 关联研究分析

从方法设计看，RoboHarness 与 ReKep 均利用几何约束进行操控，但 ReKep 侧重于通过 Python 函数合成关系约束并优化子目标，仍依赖感知-动作闭环中的模型优化；而 RoboHarness 强调原语的最小完备性证明，并完全移除 VLA 模型，仅保留 LLM 与几何接口，实现了真正的免训练范式。与 HarnessVLA 相比，后者结合冻结 VLA 与解析原语，仍保留部分动作生成模型，而 RoboHarness 彻底解耦了语义规划与动作执行，将动作生成完全交由几何求解器处理。

从问题动机看，RoboHarness 挑战了领域内“端到端 VLA 优于模块化”的共识。现有共识认为端到端架构能更好地处理未见物体与指令，但 RoboHarness 在长程任务中证明，模块化 LLM+几何接口在零样本泛化上更具优势。这一差异源于任务特性：长程任务更依赖高层规划与几何逻辑，而非高频底层控制。然而，在短程高频控制任务（如 LIBERO-Spatial）中，RoboHarness 是否仍具优势，论文未给出回答。

## 总结

RoboHarness 针对 VLA 模型依赖大规模动作数据且泛化能力受限的核心矛盾，提出通过最小完备几何原语接口连接 LLM 与物理世界。该范式利用光流追踪与深度反投影实现空间接地，并通过几何约束求解器替代动作头，证明了在 BEHAVIOR-1K 长程任务中，免训练 LLM 代理可超越 SOTA VLA 模型。其边界在于对几何求解器实时性的依赖，以及在短程高频控制任务中的适用性未经验证。当任务对控制频率要求极高时，几何约束求解的延迟是否会成为性能瓶颈，论文未给出回答。
