> 导读 流式视频理解要求模型在严格因果约束下处理无限视频流，其核心挑战在于平衡实时响应延迟与长程语义记忆的完整性。现有方法多依赖 Token 压缩或 KV Cache 复用，导致事件转换隐式化且丢失原始像素细节，无法在后续查询需要时恢复证据。DeltaStreamer 提出一种类人智能体框架，通过显式记录帧间视觉变化构建分层文本记忆，并在查询到达时利用规划器指导记忆检索与历史帧重放。该框架在复杂时序推理任务上显著提升了准确率，但其重放机制引入的额外计算开销与实时性约束之间的张力，仍是工程落地的关键瓶颈。

## 研究背景

当视频流以每秒多帧的速度持续输入时，模型必须在仅能访问过去观测数据的因果约束下，维护一个能够支持未来任意查询的内部状态。这一约束将问题从静态的视觉识别转化为动态的时序决策：模型不仅需理解“看到了什么”，更需判断“何时响应”以及“如何遗忘”。在此背景下，流式因果性（Streaming Causality）确立了实时交互的底层逻辑，而无限视频流与有限上下文窗口的物理冲突则迫使模型进行记忆管理。传统的离线视频理解范式假设视频完整可见，允许利用未来帧信息进行全局优化，但这在实时场景中因因果性约束而失效，导致模型无法直接应用于流式环境。

主流流式视频理解路线主要聚焦于管理 Token 预算，通过视觉 Token 压缩、KV Cache 复用或多轮对话机制来缓解显存溢出。然而，这些方法存在两个根本性局限：其一，连续帧往往包含相似的场景内容，重复表示消耗了有限的记忆预算，却将区分事件的关键转换隐式化；其二，一旦帧被处理并压缩，原始视觉证据即被丢弃，若后续查询需要观察阶段未记录的细节（如特定物体的颜色），模型无法从文本摘要中恢复像素级信息。DeltaStreamer 针对这一“证据恢复”盲区，提出将流式视频理解视为主动信息收集问题，通过显式记录变化与按需重放历史帧，弥补被动编码范式的缺陷。

## 核心方法

### 方法参照系：流式记忆管理框架

在流式视频理解的通用流程中，模型接收视频流 $V = \{I_0, \dots, I_{T-1}\}$，在时间 $t$ 仅能访问 $V_{\le t}$。标准做法是维护一个内部状态 $M_t$，通过压缩或截断历史 Token 来适应固定上下文窗口，并在查询 $q$ 到达时生成响应。DeltaStreamer 将该流程改造为智能体（Agent）范式：在查询前持续观察并构建结构化记忆，在查询后通过规划与工具使用（如重放）主动收集证据。该框架的关键差异在于，它不单纯依赖压缩后的文本或 KV 状态，而是保留原始帧索引，允许在推理阶段回溯视觉证据。

### Delta 增强观察与分层记忆

传统流式观察通常对当前帧进行独立描述，导致相邻帧间的细微变化（如物体移动、状态改变）在文本层面被淹没。DeltaStreamer 在观察阶段引入 Delta 机制，联合描述当前场景及其相对于前一帧的变化。观察结果 $O_t$ 定义为：

$$ O_t = (D_t, \Delta_t) = \text{VLM}(I_{t-1}, I_t, M_{\text{snapshot}}^{t-1}) $$

其中 $D_t$ 为结构化场景描述（包含演员、物体、动作等），$\Delta_t$ 为文本化的帧间变化描述。该设计动机在于解决连续帧描述冗余导致的事件转换隐式化问题，通过显式记录 $\Delta_t$，模型无需在后续推理中重建时序关系，直接获取事件演进线索。

为管理这些观察记录，DeltaStreamer 构建了一个三层有向无环图（DAG）作为分层记忆：工作记忆（Working Memory）存储原始观察，情景记忆（Episodic Memory）聚合相关观察形成事件摘要，长期记忆（Long-term Pins）保留紧凑摘要。各层通过源指针（Source Pointers）双向链接，确保从摘要可追溯至原始观察及视频帧。这种结构解决了单一粒度记忆在长程推理中丢失细节或在细粒度感知中丢失上下文的问题。

### 查询驱动规划与目标重放

当查询 $q$ 在时间 $t_q$ 到达时，传统方法直接检索记忆并生成答案，若记忆缺失关键细节则产生幻觉。DeltaStreamer 引入查询驱动规划器（Query-Driven Planner），首先根据查询需求、实体索引及初步检索结果生成持久化计划 $P$：

$$ P = \text{VLM}(q, I_{t_q}, C_{t_q}) $$

其中 $C_{t_q}$ 为上下文快照。计划 $P$ 指定了证据类型、时间范围（过去、当前或未来）及搜索策略，并在后续推理中作为“证据契约”指导智能体行为。若检索到的文本描述缺乏所需视觉细节，智能体触发目标重放（Targeted Replay）机制，通过 $replay(\tau)$ 访问历史帧索引 $\tau$。该机制解决了文本记忆不可逆的信息丢失问题，允许模型在查询阶段“重新观察”过去，从而恢复像素级证据以验证答案。

## 实验评估

实验在 OVO-Bench 和 StreamingBench 两个基准上进行，对比了专有模型、开源离线模型及主流流式系统。DeltaStreamer 使用 Qwen3.6-27B 作为骨干网络，在 8x NVIDIA A100 GPU 上以 1 fps 采样率运行。

| 方法 | OVO-Bench Overall (%) | StreamingBench Overall (%) |
| :--- | :--- | :--- |
| Gemini 3 Flash | 64.02 | - |
| EventMemAgent | 60.75 | - |
| STRIDE | - | 57.58 |
| StreamAgent | - | 57.02 |
| **DeltaStreamer** | **66.07** | **59.53** |

DeltaStreamer 在 OVO-Bench 上取得 66.07 的准确率，较最强基线 EventMemAgent 提升 5.32 个百分点，并在动作序列识别（ASI）和幻觉检测（HLD）任务上表现突出。在 StreamingBench 上，其整体得分为 59.53，超越 STRIDE 1.95 个百分点，但在主动响应（PO）任务上得分仅为 10.40，表明改进的证据处理机制并未直接解决响应时机决策问题。

消融实验揭示了各组件的贡献。移除 Delta 机制（2F-NoDelta）导致 OVO-Bench 准确率从 66.07 降至 61.12，证实了显式变化记录对时序推理的关键作用。移除重放工具（-Replay）导致准确率降至 63.28，降幅最大，说明像素级证据恢复是弥补文本记忆缺陷的核心手段。此外，分层记忆结构较扁平记忆提升 4.82 个百分点，验证了 DAG 结构在平衡摘要覆盖与细节追溯上的有效性。

评估边界方面，实验未报告推理延迟（TTFT）和最大帧率（MaxFPS），重放机制引入的额外计算开销对实时性的影响尚不明确。此外，StreamingBench 上的低分可能源于 Agent 推理链过长导致的超时或截断，论文未对此进行细粒度分析。

## 关联研究分析

从问题动机看，DeltaStreamer 与 StreamAgent 和 EventMemAgent 同属流式智能体路线，但解决的核心痛点不同。StreamAgent 侧重于预期规划，EventMemAgent 侧重于事件记忆与视觉锚点，二者均依赖存储的文本或特征表示。DeltaStreamer 指出这些方法在“证据恢复”上的盲区，即当查询需要观察阶段未记录的像素细节时，纯文本记忆无法提供证据。通过引入重放机制，DeltaStreamer 将流式理解从“被动编码”转变为“主动调查”，这一差异源于对文本记忆不可逆性的深刻认知，而非单纯的任务特性差异。

从方法设计看，DeltaStreamer 与 VST（Video Streaming Transformer）形成互补。VST 利用查询前的流式间隔进行自回归文本推理，构建双记忆系统以提升推理深度，但其记忆仍基于文本语义。DeltaStreamer 则通过 Delta 机制显式记录视觉变化，并保留原始帧索引以支持像素级回溯。VST 的优势在于利用观察间隙进行深度思考，而 DeltaStreamer 的优势在于查询时的证据完整性。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但 DeltaStreamer 的实验表明，在需要细粒度视觉验证的任务上，像素级重放比纯文本推理更具鲁棒性。

## 总结

DeltaStreamer 针对流式视频理解中事件转换隐式化与证据不可恢复的矛盾，提出了一种结合显式变化记录与查询驱动重放的智能体框架。通过 Delta 增强观察与分层 DAG 记忆，该框架在 OVO-Bench 上取得 66.07 的准确率，显著提升了时序推理与幻觉检测能力。然而，其重放机制依赖启发式规则触发，且在 StreamingBench 的主动响应任务上表现薄弱，暴露了证据处理与响应时机决策之间的解耦局限。当重放频率随视频长度增加而上升时，系统能否在保持低延迟的同时维持证据恢复的准确性，仍是该框架走向实际部署前必须验证的问题。
