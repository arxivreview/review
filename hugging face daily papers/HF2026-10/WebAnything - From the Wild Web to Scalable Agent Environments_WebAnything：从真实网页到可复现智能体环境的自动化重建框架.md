> 导读 Web智能体在真实网络中面临状态不可控、交互不可复现及训练数据稀缺的三重困境，现有方法在自动化程度、源保真度与交互覆盖度之间难以兼顾。WebAnything提出了一种基于浏览器可观测证据的自动化重建框架，通过耦合的探索-构建器与独立验证器，将真实URL转化为可执行、可重置的本地环境。该框架在244个网站上的构建成本仅为每站约2.63美元，且在下游监督微调中显著提升了智能体在复杂任务上的成功率。其核心价值在于打通了从真实网页到高质量训练数据的自动化闭环，但长期维护效率与动态源变更的适应性仍待验证。

## 研究背景

当智能体在真实网页上执行长程任务时，动态加载、异步交互及反爬虫机制导致环境状态难以初始化与复现，这一现象构成了模拟到真实差距（Sim-to-Real Gap）的核心。为缓解此问题，自托管基准（如WebArena）通过人工镜像提供可控环境，但每站工程成本高昂；生成式方法虽能规模化构建，却难以保证与指定源网站的结构与行为一致性。这一矛盾迫使研究者在自动化、源保真度与交互覆盖度之间做出取舍。

现有路线中，人工镜像保真度高但扩展性差，生成式方法扩展性强但易偏离真实源，捕获-重放方法受限于捕获内容的覆盖范围。WebAnything的切入点在于：利用浏览器可观测的结构、资源与交互行为作为共享证据基础，通过自动化重建与独立验证机制，在无需逐站人工调试的前提下，实现高保真、可执行且可复用的Web环境构建。

## 核心方法

### 方法参照系：源接地环境构建

WebAnything将环境构建形式化为在源网站 $W$、入口URL、访问范围及预算约束下，寻找一个本地环境 $\hat{W}$，使其在站点契约 $C$ 内保留观测到的呈现、交互与状态变化。其核心差异在于，源网站仅通过浏览器观测而非私有后端代码访问，重建过程必须严格受限于可观测证据。

### 证据约束的源接地重建

传统生成式方法依赖模型先验或截图，易遗漏状态关系。WebAnything引入耦合的探索-构建器（Explorer-Builder），为每个访问状态关联页面结构、计算样式、元素几何、截图及资源引用，并将动作与后续可见反馈及状态变化绑定。其证据模型定义为：

$$
E = (E_p, E_r, E_b), \quad E_b = \{(o_t, a_t, o_{t+1})\}_{t=1}^N
$$

其中 $E_p$ 记录页面结构与外观，$E_r$ 记录资源与依赖，$E_b$ 记录动作前后的观测。该公式的物理含义是：重建过程不再依赖全局推断，而是将每个交互状态视为独立的证据单元，确保同一URL下的不同交互状态（如菜单展开与收起）能约束不同的实现需求，从而解决纯文本解析在复杂UI下的定位误差。

### 独立验证与证据感知细化

构建器自检易忽略源不一致缺陷，且难以区分实现错误与观测不足。WebAnything引入独立验证器（Independent Verifier），在隔离上下文中检查冻结候选实现，并依据证据进行诊断。若现有证据确立的预期结果未被复现，则触发局部修复（Local Repair）；若证据不足，则触发定向重捕获（Targeted Recapture）。该机制通过解耦构建与验证，将差异转化为可操作的修订指令，有效区分了实现缺陷与证据缺失，避免了传统方法中因观测不足导致的错误推断。

## 实验评估

实验在244个网站、14个领域及53个类别上评估构建规模、环境质量及下游效用。基线对比涵盖人工镜像WebHarbor与生成式环境VeriEnv。

**主结果：源保真度与交互有效性**

| 评估维度 | 系统 | 指标/结果 |
| :--- | :--- | :--- |
| 源保真度 (5站/14状态) | WebAnything | Pixel: 0.9240, SSIM: 0.7904, Text F1: 0.8541 |
| | WebHarbor | Pixel: 0.8083, SSIM: 0.6260, Text F1: 0.2617 |
| 盲测审计 (14状态) | WebAnything | 12胜, 2平, 0负 |
| 交互有效性 (WebHarbor子集) | WebAnything | 能力覆盖: 75%, 全测试通过: 63.3% |
| | WebHarbor | 能力覆盖: 80%, 全测试通过: 76.7% |

WebAnything在三项自动保真度指标上均显著优于WebHarbor，且在盲测中保持全胜。然而，在交互有效性上，WebHarbor的能力覆盖与全测试通过率更高，表明高视觉保真度并不直接等同于广泛的功能覆盖。

**下游学习效用**

| 基准 | 模型 | 指标 | 提升幅度 |
| :--- | :--- | :--- | :--- |
| REAL (91任务) | Qwen3.5-9B | Success | +9.9pp (24.2% → 34.1%) |
| Odysseys-Easy (44任务) | Qwen3.5-9B | Rubric Avg | +6.25pp (19.71% → 25.96%) |
| WebArena-Verified | Qwen3.5-9B | Overall | +13.33pp (16.41% → 29.74%) |

在相同骨干模型与训练配置下，使用WebAnything环境数据微调的模型在三个外部基准上均取得显著提升，验证了重建环境对下游任务的正向迁移价值。

**评估边界**

实验未覆盖长期维护效率与动态源变更的适应性。构建成本记录为每站平均2.63美元，但排除了未定价调用与系统开销，仅为下界。此外，WebArena-Verified上Retrieve任务性能下降8.75pp，可能源于重建环境缺失动态搜索后端，论文未对此进行消融分析。

## 关联研究分析

从问题动机看，WebAnything与WebWorld均致力于解决训练数据稀缺问题，但路线截然不同。WebWorld依赖世界模型进行大规模离线模拟，存在预测误差累积与训练-测试差距；WebAnything则直接重建真实网站源码与状态，通过源接地避免模拟偏差。这一差异源于对“保真度”定义的不同：前者侧重行为分布的统计一致性，后者侧重结构与交互的精确对应。

从方法设计看，WebAnything与VeriEnv同属自动化环境构建，但验证机制存在本质区别。VeriEnv提供克隆环境与确定性SDK验证，侧重于任务执行的正确性；WebAnything引入独立验证器进行证据感知的局部修复或定向重捕获，侧重于环境实现与源证据的一致性。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但独立验证器的引入显著增加了构建复杂度，其ROI（投资回报率）在大规模部署中尚不明确。

## 总结

WebAnything针对Web智能体训练环境的高保真与规模化矛盾，提出了一种基于浏览器可观测证据的自动化重建框架。通过耦合探索-构建器与独立验证器，该框架在244个网站上实现了每站约2.63美元的低成本构建，并在下游微调中将Qwen3.5-9B在WebArena-Verified上的成功率提升13.33pp。其核心贡献在于打通了从真实网页到高质量训练数据的自动化闭环，并验证了源接地重建对下游任务的有效迁移。然而，该框架目前仅评估了静态快照的重建质量，未系统评估长期维护效率与动态源变更下的环境更新机制。当真实网站持续更新页面结构与交互行为时，增量证据捕获与局部环境更新的成本是否会抵消自动化构建的收益，论文未给出回答。
