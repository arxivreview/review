> 导读 LLM 智能体的实际表现不仅取决于底层模型，更受限于其执行框架（Harness）的设计质量。现有方法多依赖离线搜索或单任务在线优化，难以在缺乏真值反馈的开放世界中实现跨任务的持续改进。本文提出 Harness2 框架，通过任务级递归优化当前执行框架，并通过框架级递归积累改进经验以指导未来任务。该工作验证了无监督条件下框架自进化的可行性，但其性能增益是否源于基线模型能力的波动，仍需进一步验证。

## 研究背景

当智能体在开放世界中执行复杂任务时，其能力边界往往受限于模型外部的执行框架——包括系统提示、工具接口、记忆机制等组件。即使底层模型参数冻结，不同框架配置下的任务成功率也存在显著差异。然而，手动设计框架成本高昂，且静态框架难以适应动态变化的任务需求。递归自改进（Recursive Self-Improvement, RSI）旨在让系统自主优化自身组件，但现有方法多依赖基准测试或验证集反馈，在缺乏真值标签的开放场景中失效。

当前主流路线分为离线优化与在线适应两类。离线方法如 Meta-Harness 在训练集上搜索最优框架，但泛化性差；在线方法如 Harness Scaling 针对单任务进行即时调整，但缺乏跨任务的经验积累，导致改进过程无法复用。本文切入点在于将“改进过程本身”作为学习对象，通过双层递归机制，既优化当前任务的执行框架，又更新指导未来改进的元框架，从而在无真值反馈下实现持续进化。

## 核心方法

### 方法参照系：双层递归架构

Harness2 将智能体定义为冻结模型 $M$ 与可编辑框架 $H$ 的组合 $A(\cdot; M, H)$。框架 $H$ 包含 8 个文件级组件（如系统提示、工具指南等）。本文问题与通用 RSI 的关键差异在于：优化对象是框架文件而非模型权重，且反馈信号来自执行轨迹的行为对比而非任务正确性评分。

### 任务级递归：对比式改进步骤

针对无真值反馈的挑战，本文提出 Propose-Probe-Compose 对比式改进步骤。首先，Propose 阶段基于当前框架 $H$ 和参考执行 $e_0$，生成两个候选框架：一个针对跨领域通用的代理缺陷（如规划能力），另一个针对当前领域的特定约束。

Probe 阶段在相同模型和环境配置下执行候选框架，生成行为对比证据。Compose 阶段根据证据选择性合并或修正编辑，形成后继框架 $H'$。该过程的形式化定义为：

$$
(H', e', \xi) = \Phi(q_t, H, E; R_t)
$$

其中 $\Phi$ 为改进操作，$E$ 为执行历史，$R_t$ 为固定的改进框架。该设计通过行为对比而非分数验证来指导编辑，解决了无真值反馈下无法量化改进效果的问题。

### 框架级递归：改进经验的持续积累

任务级递归产生的执行证据和框架编辑被用于更新改进框架 $R_t$。在任务结束后，系统回顾改进记录 $D_t$，提取可复用的框架组件和经验教训，更新改进库：

$$
R_{t+1} = \text{Update}(R_t, H^\star_t, D_t)
$$

其中 $H^\star_t$ 为选定的最优执行框架。改进库存储可执行框架及其适用条件、经验教训。后续任务启动时，虽然执行框架重置为初始状态 $H_0$，但改进框架 $R_{t+1}$ 指导 Propose 阶段复用或适配历史组件。该机制将改进过程本身转化为可迁移的知识，解决了单任务优化无法跨任务泛化的问题。

## 实验评估

实验在 WorkBuddy-Bench、JobBench 和 LAB 三个专业基准上进行，评估 Gemini 3.5 Flash 和 GLM-5 在 OpenCode 和 Codex 框架下的表现。基线包括 Base Harness、ReasoningBank（记忆检索）、Meta-Harness（离线优化）和 Harness Scaling（单任务在线优化）。

| 模型 | 框架 | 方法 | WorkBuddy Avg. | JobBench Score | LAB Partial |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Gemini 3.5 Flash | OpenCode | Base Harness | 72.4 | 31.5 | 79.9 |
| | | Meta-Harness | 76.4 | 35.8 | 81.6 |
| | | Harness2 (k=1) | 77.5 | 36.0 | 81.9 |
| | | + Recursion (k=5) | +3.3 | +3.0 | +2.6 |
| GLM-5 | OpenCode | Base Harness | 64.2 | 20.6 | 59.6 |
| | | Meta-Harness | 69.7 | 20.9 | 60.0 |
| | | Harness2 (k=1) | 75.7 | 24.2 | 71.4 |
| | | + Recursion (k=5) | +3.9 | +4.2 | +6.7 |

Harness2 在所有配置中均优于基线。在 WorkBuddy-Bench 上，GLM-5 经单步改进后平均得分提升 11.5 点，超越基线 Gemini 3.5 Flash 的原始表现。消融实验显示，移除改进库、作用域编辑或组合步骤均导致性能下降，其中移除作用域编辑在 JobBench 上造成 3.7 点降幅，表明领域特定编辑对专业任务至关重要。

评估边界方面，实验未包含强化学习类基线（如 Tool-R0），无法直接对比 RL 训练与框架编辑的效率。此外，性能增益可能部分源于基线模型在特定任务上的波动，论文未提供统计显著性检验。

## 关联研究分析

从优化对象看，Harness2 与 Reflexion 均利用执行反馈进行自我改进，但 Reflexion 优化的是轨迹文本或提示词，而 Harness2 优化的是包含工具接口、记忆机制等结构化组件的完整框架。这种差异使得 Harness2 能够处理更复杂的系统级缺陷，如工具调用格式错误或上下文管理失效，而 Reflexion 仅能修正推理逻辑。

从反馈机制看，Harness2 与 Tool-R0 均追求自进化，但 Tool-R0 依赖可验证奖励进行强化学习训练，而 Harness2 在无真值反馈下通过行为对比指导编辑。这一差异暗示了 Harness2 在缺乏明确成功标准的开放场景中的优势，但也限制了其在需要精确策略优化的复杂决策任务中的上限。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文针对开放世界中智能体框架难以自动适应新任务的问题，提出 Harness2 框架，通过任务级递归优化执行框架，并通过框架级递归积累改进经验。实验表明，该方法在 WorkBench 和 JobBench 上分别带来最高 11.5 点和 4.5 点的性能提升，验证了无监督框架自进化的有效性。然而，该方法依赖行为对比作为反馈信号，其可靠性受限于执行随机性和模型偏差。当任务分布发生剧烈变化时，历史改进经验是否会成为负迁移的来源，论文未给出回答。
