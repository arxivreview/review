> 导读 具身智能代理在动态物理环境中需通过交互积累经验并迁移至新任务，但现有评估体系割裂了持续学习与具身场景。数字环境基准缺乏空间与物理约束，而具身基准未专门量化经验复用能力。本文提出 EmbodiedCLBench，以组合泛化为核心原则，构建从原子动作到高级任务的层级结构，评估代理重组已学技能解决未见任务的能力。该基准揭示了当前代理在具身环境中经验提取效率低、无法随样本量线性提升性能的局限，为设计高效自进化代理提供了关键评测坐标。

## 研究背景

当代理在具身环境中执行长时程任务时，其核心挑战在于如何将过往交互中习得的原子动作重组为复杂行为序列。这种能力依赖于持续学习（Continual Learning），即代理在不遗忘旧知识的前提下，通过积累程序性经验解决新任务。然而，现有评估体系存在结构性缺失：持续学习基准多聚焦于知识密集型或数字交互环境，无法捕捉具身任务中的空间复杂性；具身基准虽涵盖感知与导航，却未将“经验积累与迁移”作为独立评估维度。这一缺口导致无法判断代理是否真正具备从简单任务中抽象技能并泛化至复杂场景的能力。

为填补这一空白，EmbodiedCLBench 将持续学习操作化为组合泛化（Compositional Generalization）问题。其核心假设是：若代理具备持续学习能力，则应能重组基础任务中习得的技能元素解决未见的高级任务，而非从零学习。该基准通过构建状态转移图，将任务分解为原子动作、基础任务与高级任务三级结构，实现了离线、确定性且可复现的评估。这一设计不仅量化了经验迁移的有效性，还揭示了当前代理在具身环境中从额外经验中提取有效信息的瓶颈。

## 核心方法

### 方法参照系：基于状态转移图的离线评估

EmbodiedCLBench 将具身持续学习评估置于离线状态转移图（State-Transition Graph）框架下。与传统在线仿真不同，该框架预计算任务的所有可能状态与动作分支，代理在每个节点观察图像并选择动作，沿边转移至下一状态。这一设计解决了在线仿真难以复现、难以控制复杂度的问题，使评估聚焦于代理的决策逻辑而非环境随机性。其关键差异在于，评估目标从“单次任务成功率”转向“基于基础任务经验的高级任务成功率”，从而直接量化持续学习带来的增益。

### 核心创新：组合泛化任务层级构建

该基准的核心创新在于通过组合泛化原则构建任务层级，将抽象的持续学习能力转化为可测量的任务重组问题。传统具身基准通常独立评估各类任务，无法区分代理是“学会了新任务”还是“重组了旧技能”。EmbodiedCLBench 定义原子动作为单一对象交互（如“拿起杯子”），基础任务为少量原子动作的组合（如“把杯子放到桌上”），高级任务则跨类别组合多个基础任务元素（如“整理房间”需结合“拿书”“放书”“关灯”等）。

任务生成过程遵循严格的组合逻辑：高级任务的原子动作必须来自 2-4 个不同类别的基础任务。这种结构强制代理在解决高级任务时，必须调用在基础任务阶段习得的技能模块。若代理无法重组这些模块，则无法完成高级任务。这一设计将“经验迁移”具象化为“技能重组成功率”，使得持续学习能力的评估具有明确的因果解释：高级任务成功率的提升直接归因于基础任务经验的复用，而非模型对高级任务本身的零样本泛化能力。

### 评估协议：双阶段经验积累与测试

评估协议分为学习阶段与测试阶段，通过控制信息流隔离经验积累与任务执行。在学习阶段，代理完成若干基础任务，其交互轨迹或技能摘要被保留为上下文；在测试阶段，代理尝试未见的高级任务，仅能利用学习阶段积累的信息。

该协议的关键设计在于区分 In-Context Learning (ICL) 与 Skill Learning 两种经验表示形式。ICL 保留完整交互轨迹，Skill Learning 则要求代理将经验压缩为 Markdown 格式的技能摘要。这一对比旨在探究具身环境中经验的有效表示形式：是保留原始轨迹细节更利于决策，还是抽象技能摘要更能促进泛化。评估指标为成功率（Success Rate, SR），定义为在步数预算内完成高级任务的比例：

$$
SR = \frac{1}{N} \sum_{i=1}^{N} c_i, \quad c_i \in \{0, 1\}
$$

其中 $N$ 为高级任务总数，$c_i$ 表示第 $i$ 个任务是否成功。该公式直接量化了经验迁移的最终效果，步数预算的设定（最短路径 + 额外容错步数）则控制了代理决策效率对结果的影响，确保评估聚焦于技能重组的正确性而非单纯的探索能力。

## 实验评估

实验在 EmbodiedCLBench 的 268 个任务（168 基础 + 100 高级）上进行，评估了 OPENCLAW、CODEX、HERMES 等代理框架搭配 Qwen3.8-Flash 与 GPT5.6-Terra 模型。基线覆盖 Zero-shot、ICL 与 Skill Learning 三种设置，未包含基于强化学习的在线优化方法，因本文侧重评估现有代理框架的经验复用能力而非提出新优化算法。

| Harness | Model | Basic Zero-shot | Adv. Zero-shot | Adv. ICL | Adv. Skill Learning |
| :--- | :--- | :--- | :--- | :--- | :--- |
| HERMES | Qwen3.8-Flash | 58.9 | 8.0 | 44.0 | 33.0 |
| HERMES | GPT5.6-Terra | 53.0 | 11.0 | 16.0 | 34.0 |
| OPENCLAW | Qwen3.8-Flash | 50.6 | 5.0 | 35.0 | 38.0 |
| OPENCLAW | GPT5.6-Terra | 47.6 | 12.0 | 39.0 | 22.0 |
| CODEX | Qwen3.8-Flash | 52.4 | 4.0 | 34.0 | 33.0 |
| CODEX | GPT5.6-Terra | 54.8 | 11.0 | 52.0 | 26.0 |

主结果显示，高级任务零样本成功率仅约 10%，而 ICL 与 Skill Learning 将其提升至 30% 以上，证实基础任务经验可有效迁移。消融分析揭示两个关键发现：其一，性能增益随任务复杂度（原子动作数 3-6）增加保持稳定，表明持续学习能力对难度不敏感；其二，成功率随学习样本数（$k=0$ 至 $6$）增加呈饱和趋势，$k=1$ 时即达最大增益，额外样本无一致提升。错误分析进一步指出，经验主要通过减少无效动作（降低 13%-20%）而非增加最优动作来提升成功率，且 Skill Learning 的行为改变幅度小于 ICL。

评估边界方面，离线状态图设计虽保证了可复现性，但可能低估了在线探索对技能发现的重要性。此外，未报告置信区间，且未对比基于 RL 的在线技能进化方法，限制了与领域 SOTA 的直接可比性。

## 关联研究分析

从问题动机看，EmbodiedCLBench 与 SkillsBench 均关注技能对代理性能的增益，但 SkillsBench 聚焦文本/数字任务中的技能检索与执行，而 EmbodiedCLBench 将场景扩展至具身模拟，强调空间与物理约束下的技能重组。这一差异源于具身任务中动作执行受状态空间限制，无法像文本任务那样通过语义相似度直接检索技能，必须依赖对物理状态的理解与动作序列的精确组合。

从方法设计看，EmbodiedCLBench 与 Voyager 均涉及技能库构建，但 Voyager 侧重在线生成可执行代码技能，而 EmbodiedCLBench 侧重离线评估代理对已学技能的重组能力。Voyager 假设技能可显式存储为代码，EmbodiedCLBench 则质疑当前代理能否从交互轨迹中有效提取可复用的程序性知识。实验揭示的“单样本饱和”现象表明，当前代理在具身环境中缺乏从多余经验中抽象通用模式的能力，这与 Voyager 依赖大量试错生成技能的路径形成对比，暗示具身技能提取可能需要更结构化的归纳机制而非单纯轨迹积累。

## 总结

EmbodiedCLBench 针对具身代理持续学习能力评估缺失的问题，通过组合泛化原则构建了从基础任务到高级任务的层级基准。实验证明，基础任务经验可将高级任务成功率从约 10% 提升至 30% 以上，但增益不随学习样本数线性增长，$k=1$ 时即饱和。这一结果揭示了当前代理在具身环境中经验提取效率低下的根本局限：代理能利用少量经验避免无效动作，却无法从额外交互中抽象出更通用的技能模式。当代理无法从多余样本中提取有效信息时，具身持续学习的瓶颈究竟在于经验表示形式的缺陷，还是代理架构本身缺乏归纳泛化能力，仍需进一步探究。
