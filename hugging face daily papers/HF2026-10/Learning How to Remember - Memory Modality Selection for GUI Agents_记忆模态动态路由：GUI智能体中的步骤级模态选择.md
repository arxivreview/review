> 导读 GUI智能体在长程任务中面临错误累积与上下文管理困难，记忆增强通过复用历史经验缓解此问题。现有方法通常固定记忆的表征模态（纯文本或纯图像），忽略了不同交互步骤对信息粒度的差异化需求。SwitchMem将记忆模态选择建模为步骤级决策，通过Directional Chain-of-Embedding (D-CoE) 分析Actor内部表征差异，训练轻量级路由器动态选择Text或Image记忆。该工作揭示了模态偏好的步骤依赖性，但在长程任务验证与强化学习协同方面存在局限。

## 研究背景

当GUI智能体执行多步任务时，单步感知或动作选择的错误会沿轨迹传播，导致后续决策偏离目标。为缓解此问题，记忆增强（Memory Augmentation）机制被引入，通过检索历史交互轨迹作为上下文辅助当前决策。然而，检索到的经验需转化为模型可处理的表征形式，现有系统通常采用预定义的固定模态：要么将历史状态抽象为文本描述，要么保留原始截图作为视觉记忆，且该选择在整个交互过程中保持不变。

文本表征提供紧凑的语义抽象，但可能丢失下游推理所需的细粒度空间与外观信息；视觉表征保留完整细节，但在信息可被结构化文本捕获时，文本抽象反而能提升复杂推理效率。领域内已有研究指出文本与视觉表征的相对效用取决于推理上下文，但GUI智能体中记忆模态偏好是否随交互步骤动态变化，以及这种偏好是否反映在模型内部表征中，尚不明确。SwitchMem针对这一被忽略的“模态-步骤”匹配问题，提出动态路由框架。

## 核心方法

### 方法参照系：固定模态记忆增强

在标准记忆增强GUI智能体流程中，给定当前状态 $x_i = (g_i, o_i)$（任务指令与截图），检索器从演示库中检索最相关的历史演示 $j_i$。该演示随后被实例化为单一模态的记忆 $m_i$，并注入Actor的提示中生成动作。本文的关键差异在于：传统流程在检索后固定记忆模态，而SwitchMem将模态选择转化为推理时的动态决策，需解决“如何在不增加推理延迟的前提下，准确预测当前步骤的最优模态”这一核心问题。

### D-CoE：基于内部表征的模态偏好信号

传统方法依赖外部启发式规则或独立分类器判断模态偏好，忽略了Actor内部已隐含的模态敏感性信息。SwitchMem提出Directional Chain-of-Embedding (D-CoE) 分析，通过对比同一检索演示在Text与Image两种记忆条件下的Actor隐藏状态差异，提取模态偏好信号。

设 $h^z_{i,\ell}$ 为Actor在第 $\ell$ 层、记忆模态 $z \in \{T, I\}$ 下的隐藏状态，D-CoE定义为层间有符号位移序列：

$$
C_i = \{ d_{i,\ell} = h^I_{i,\ell} - h^T_{i,\ell} \}_{\ell=1}^L
$$

该公式的物理含义是：同一语义内容在不同模态输入下，模型内部表征的演化轨迹差异。实验表明，该位移信号在深层Transformer中可被线性探针有效解码，AUROC随层数增加而提升，证明模态偏好已编码于Actor内部表征中，为后续路由提供了可解释的监督信号。

### Pairwise Router：偏好监督的轻量级路由

基于D-CoE提取的偏好信号，SwitchMem训练一个Pairwise Router实现推理时的动态选择。路由器不直接预测动作，而是对Text与Image记忆候选进行相对评分。

首先，将当前状态隐藏状态 $s_i$ 与记忆嵌入 $e^z_i$ 投影至共享空间并归一化，构造候选特征：

$$
v^z_i = [\hat{s}_i; \hat{e}^z_i; \hat{s}_i \odot \hat{e}^z_i; |\hat{s}_i - \hat{e}^z_i|]
$$

该特征通过拼接、逐元素乘积与绝对差值，显式建模状态与记忆的交互关系。共享MLP评分器 $f_\theta$ 将 $v^z_i$ 映射为标量分数 $q^z_i$，路由分数定义为：

$$
r_i = q^I_i - q^T_i
$$

路由器通过均方误差回归D-CoE构造的连续偏好目标 $t_i$ 进行训练。推理时，若 $r_i \geq \tau$ 则选择Image记忆，否则选择Text记忆。该设计避免了同时输入双模态导致的上下文冗余与性能退化，仅向Actor提供单一最优模态记忆。

## 实验评估

实验在AITW、LearnGUI与MobileMiniWoB++三个基准上进行，使用冻结的Qwen3.5-9B作为Actor，Qwen3-VL-Embedding-2B负责检索。基线覆盖通用VLM、GUI专用模型及多种记忆增强方法。

| Method | AITW (%) | LearnGUI (%) | MobileMiniWoB++ (%) |
| :--- | :--- | :--- | :--- |
| Qwen3.5-9B (No Memory) | 41.920 | 23.485 | 58.696 |
| Text Memory | 48.760 | 35.638 | 53.261 |
| Image Memory | 49.300 | 37.441 | 57.609 |
| Both Memory | 47.080 | 26.919 | 60.870 |
| SwitchMem | 51.420 | 38.131 | 63.043 |

SwitchMem在三个基准上均取得最优性能，AITW上较最强固定模态基线（Image）提升2.12个百分点，LearnGUI上提升0.69个百分点。值得注意的是，同时提供双模态（Both）在AITW与LearnGUI上反而低于单模态基线，验证了固定混合输入可能引入干扰，而动态选择单一模态能规避此问题。

消融实验进一步验证了路由设计的必要性。与Ratio-matched随机路由相比，SwitchMem在所有Image选择率下均保持性能优势，证明增益源于步骤级精准分配而非模态使用比例。此外，将SwitchMem迁移至GUI专用模型UI-TARS-7B-SFT时，仍稳定超越固定模态基线，表明该路由框架具有跨骨干网络的泛化性。

评估边界方面，本文未与在线强化学习方法（如MobileRL）进行对比，且MobileMiniWoB++上的路由权重直接迁移自LearnGUI，未针对该基准重新校准阈值。尽管SwitchMem推理延迟低于RAG-GUI等程序化基线，但D-CoE偏好目标的离线构建仍需双模态前向传播，训练成本高于纯SFT方法。

## 关联研究分析

从问题动机看，SwitchMem与EchoTrail、AGMem等同属记忆增强路线，但后者聚焦于记忆内容的构造（如文本步骤摘要或动作区域裁剪），默认检索后模态固定。SwitchMem指出固定模态在密集UI或功能型动作场景下的失效，将优化重心从“存什么”转向“怎么喂”，填补了记忆表征动态适配的空白。然而，该工作未探索记忆内容与模态的联合优化，例如是否可通过生成式摘要动态调整文本粒度以替代图像记忆，这一可能性未被验证。

从方法设计看，SwitchMem的Pairwise Router与多模态工具协同中的路径编排（如ToolCUA）存在结构相似性，均涉及离散选项的动态选择。但ToolCUA优化的是GUI操作与API调用的动作空间路径，而SwitchMem优化的是同一动作空间下的感知输入模态。两者在混合接口场景下可能产生交互效应：当智能体同时具备工具调用能力时，文本记忆是否因与API参数格式对齐而获得额外增益，论文未提供相关实验证据。

## 总结

SwitchMem针对GUI智能体记忆增强中固定模态表征导致的次优问题，揭示了模态偏好的步骤依赖性，并通过D-CoE信号训练轻量级路由器实现动态选择。在AITW与LearnGUI上，SwitchMem分别取得51.42%与38.13%的动作得分，稳定超越所有固定模态基线。该方法的边界在于仅优化记忆输入模态，未涉及策略层面的错误恢复机制，且评估基准以单步动作预测为主，缺乏AndroidWorld等长程动态环境的验证。当交互轨迹长度显著增加、状态转移复杂度超出当前路由器的感知范围时，步骤级模态选择是否仍能维持增益，抑或需引入层级化的记忆压缩策略，是该框架走向真实部署前必须回答的问题。
