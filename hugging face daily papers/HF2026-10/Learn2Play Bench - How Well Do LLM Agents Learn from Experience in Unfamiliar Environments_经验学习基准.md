# HuggingFace最新推荐论文 ｜Learn2Play Bench: How Well Do LLM Agents Learn from Experience in Unfamiliar Environments? ｜经验学习基准

研究机构：新加坡国立大学

作者：Yibo Li、Jinhang Qiu、Zhi Zheng 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.08215)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.08215)

> 现有智能体评估难以区分模型是调用预训练先验知识还是从交互中获取新规则，导致自进化能力的量化失真。本文通过构建包含反直觉隐藏规则的文本游戏环境，强制智能体在未知规则下通过试错学习，从而隔离预训练知识的干扰。实验表明，保留原始交互历史比压缩为规则或工作流更能支持有效学习，且执行框架（Harness）的选择对性能与成本有显著影响。该基准填补了“规则新颖性”评估空白，但其人工设计的反直觉规则是否具备真实环境的外推效度仍存疑。

## 研究背景

当智能体面对未覆盖于预训练数据中的环境时，其决策依赖于从交互反馈中归纳规则的能力。这一过程涉及两个核心概念：经验复用（Experience Reuse），即在不更新模型权重的前提下，将前序交互中的信息转化为后续决策依据；以及规则发现（Rule Discovery），即从确定性反馈中推断出环境背后的隐藏逻辑。若环境规则与常识一致，智能体的表现提升可能仅源于激活预训练知识，而非真正的学习。因此，评估必须引入“规则新颖性”，即设计违背常识或从未出现过的规则，以迫使智能体依赖交互证据而非先验假设。

当前自进化智能体研究主要聚焦于提出新的适应机制，如Reflexion的口头反思、AWM的工作流诱导或EvoTest的配置演化。然而，这些方法通常在熟悉任务或静态基准上评估，导致“性能提升”与“有效学习”混淆。主流评估协议缺乏对“知识来源”的区分，无法判断智能体是学会了新规则，还是仅仅恢复了已知知识。Learn2Play Bench 的切入点在于构建一个受控的、规则未知的文本游戏环境，通过确定性反馈和自动评分，系统性地解耦模型能力、自进化方法与执行框架对学习效果的影响。

## 核心方法

### 方法参照系

本文问题归属于“自进化智能体评估”范畴，但区别于传统任务成功率评估。通用流程通常关注最终状态 $s_T$ 是否满足目标 $g$，而本文关注轨迹 $\tau$ 中的学习动态，即智能体如何从 $s_0$ 到 $s_T$ 的过程中更新其内部策略。关键差异在于引入“规则新颖性”约束，确保评估对象是“从交互中获取新知识”的能力，而非“应用已知知识”的能力。

### 反直觉规则设计与实例化

为隔离预训练知识，Learn2Play Bench 设计了20款文本游戏，每款游戏包含隐藏规则，且规则具有反直觉特性（如“偷午餐有助于晋升”）。游戏分为固定实例（Fixed）和重洗牌实例（Re-shuffled）两类：前者重复同一实例以测试记忆保持，后者改变表面特征但保持核心规则不变，以测试知识迁移。这种设计使得评估能够区分“对特定实例的记忆”与“对通用规则的掌握”。

### 学习动态度量

本文定义了四个指标来量化学习过程，其中学习斜率（Learning Slope, LS）是核心指标。LS 通过线性回归拟合归一化得分 $y_{g,t}$ 随回合 $t$ 的变化趋势：

$$
LS_g = \hat{\beta}_{1,g}, \quad \text{where } y_{g,t} = \hat{\beta}_{0,g} + \hat{\beta}_{1,g}t + \epsilon_{g,t}
$$

该公式捕捉了智能体在完整评估窗口内的整体改进速率。相比仅比较首尾得分的学习增益（LG），LS 对中间波动更敏感，能反映学习的稳定性。此外，最大得分（Max）和平均得分（Mean）分别衡量峰值性能与一致性，共同构成对“成就”与“进步”的双维评估。

## 实验评估

实验在20款游戏实例上进行，每款游戏进行3次独立试验，每次试验包含5或10个回合（挑战游戏为10回合）。基线覆盖Reflexion、AWM、EvoTest、ReasoningBank、MEMORY（原始历史保留）和NAIVE（无跨回合记忆）。对比方法包括OpenCode、Claude Code和Codex三种执行框架，以及Kimi K3、Claude Opus 5、GPT-5 Mini等骨干模型。

| 系统/模型 | Max | Mean | LG | LS |
| :--- | :--- | :--- | :--- | :--- |
| Human Top-1 | 84.3 | 53.5 | +21.6 | +7.33 |
| Claude Code (Opus 5) | 81.8 | 62.3 | +27.1 | +6.59 |
| OpenCode (Opus 5) | 74.5 | 53.8 | +21.3 | +5.13 |
| MEMORY (Kimi K3) | 63.3 | 48.0 | +16.9 | +4.69 |
| Reflexion (Kimi K3) | 61.6 | 40.4 | +14.8 | +3.35 |

在Kimi K3骨干下，MEMORY方法的Max得分（63.3）高于Reflexion（61.6），且LS（+4.69）显著高于Reflexion（+3.35）。这表明保留原始交互历史比压缩为反思规则更能支持学习，因为原始证据允许智能体在后续回合中修正早期错误推断。例如，在GEMFORGE游戏中，EvoTest生成的规则可能错误地排除有效组合，而MEMORY保留了失败尝试的原始记录，使智能体能重新评估。

| 系统/模型 | Max | Mtok/ep. | USD/ep. | Max/(USD/ep.) |
| :--- | :--- | :--- | :--- | :--- |
| Claude Code (Opus 5) | 81.8 | 0.71 | 0.647 | 126.4 |
| Codex (GPT-5.6-SOL) | 74.3 | 0.49 | 0.144 | 516.6 |
| OpenCode (Kimi K3) | 68.5 | 0.56 | 0.313 | 218.5 |
| EvoTest (Kimi K3) | 62.4 | 0.16 | 0.658 | 94.8 |

成本分析显示，Codex在GPT-5.6-SOL下具有最高的效率比（516.6 Max/USD），而EvoTest虽然Token消耗低，但因生成大量更新内容导致成本较高。这证实了执行框架不仅影响性能，还通过减少冗余调用和上下文重复来优化成本。

评估边界方面，本文使用确定性环境和自动评分，确保了可复现性，但缺乏对真实世界噪声（如网络延迟、UI变化）的模拟。此外，反直觉规则的人工设计可能过度简化了真实环境的复杂性，导致学习曲线的外推效度受限。代码与超参数已公开，但游戏实例的随机种子固定，限制了泛化性测试。

## 关联研究分析

从问题动机看，Learn2Play Bench 与GAIA、WebArena等基准的核心差异在于“知识来源”的隔离。GAIA等基准关注任务完成能力，其规则通常隐含于常识或指令中，智能体可能依赖预训练知识而非交互学习。Learn2Play Bench 通过反直觉规则强制智能体依赖交互证据，从而更纯粹地评估“学习”能力。这一差异源于任务特性：GAIA模拟真实世界任务，而Learn2Play Bench 模拟“未知规则”场景，后者更贴近智能体面对全新环境时的挑战。

从方法设计看，本文与Reflexion、AWM等自进化方法的关系是“评估者”而非“竞争者”。Reflexion等方法提出具体的适应机制，而Learn2Play Bench 提供受控环境以系统比较这些机制的有效性。本文发现MEMORY优于Reflexion，这与Reflexion论文中声称的“反思提升性能”形成冲突。这一冲突暗示，在规则未知的环境中，压缩经验为规则可能丢失关键证据，导致后续修正困难。相比之下，在规则已知或熟悉的环境中，Reflexion可能更有效，因为规则压缩能减少上下文长度。本文未探索这一条件依赖，仅在当前设定下得出结论。

## 总结

Learn2Play Bench 解决了自进化智能体评估中“学习”与“回忆”混淆的核心矛盾。通过构建反直觉规则的游戏环境，本文隔离了预训练知识的干扰，系统验证了“证据保留优于规则压缩”这一反直觉结论。实验表明，MEMORY方法在Kimi K3上的LS（+4.69）显著高于Reflexion（+3.35），且Claude Code框架在性能与成本上均优于OpenCode。本文的边界在于人工设计的反直觉规则可能无法完全模拟真实环境的复杂性，且缺乏对噪声和动态变化的模拟。当游戏规则从“反直觉”转向“部分已知”时，MEMORY与Reflexion的性能差距是否缩小，论文未给出回答。
