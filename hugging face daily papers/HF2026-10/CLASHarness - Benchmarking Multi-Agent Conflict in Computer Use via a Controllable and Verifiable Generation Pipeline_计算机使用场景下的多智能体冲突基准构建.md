> 导读：多智能体系统在计算机使用场景中常因智能体间信息不一致导致协调失败，现有基准多假设环境一致或局限于纯文本对话，无法评估智能体在真实操作环境中的冲突解决能力。本文提出 CLASHarness，通过分层分阶段生成管线合成可验证的多智能体冲突任务，并引入事实预承诺与执行编译验证机制确保任务可解性。该框架揭示了当前前沿模型在主动状态变更与协调协议执行上的显著瓶颈。其价值在于提供了首个可验证的计算机使用冲突评估范式，但依赖 LLM 作为语义评判者可能引入评估噪声，且生成模型自身的偏差是否导致基准对特定模型家族过拟合仍存疑。

## 研究背景

当视觉语言模型（Vision-Language Models, VLMs）驱动的自主智能体被部署于计算机使用场景时，多智能体协作网络不可避免地面临信息不一致的困境。子智能体可能基于过时的缓存报告部署成功，而实时遥测数据却显示健康检查失败，这种状态冲突迫使主智能体必须跨越文本指令，通过检查操作环境中的视觉仪表盘来验证真值并执行配置回滚。评估此类冲突解决能力面临基准构建的根本挑战：人工任务策划无法在复杂操作环境中扩展，而无约束的大语言模型（Large Language Model, LLM）生成则导致叙事漂移、答案泄漏及不可满足的评分标准，使任务在逻辑上不可解。

多智能体系统（Multi-Agent Systems, MAS）验证与治理领域长期聚焦于形式化逻辑验证与运行时监控，旨在解决策略组合爆炸与状态空间不可扩展问题。然而，随着 LLM 成为智能体核心，其非确定性与自然语言语义的模糊性使得传统确定性模型检查失效。现有评估框架如 AgentCollabBench 虽关注协作质量，但多局限于纯文本对话，未能覆盖多模态计算机操作环境中的状态验证与协议执行。CLASHarness 的切入点在于将评估场景从静态文本扩展至动态计算机使用环境，通过可控生成管线弥合形式化规范与 LLM 非确定性行为之间的鸿沟，为诊断协调失败提供可验证的实证基础。

## 核心方法

### 方法参照系与任务形式化

本文问题属于基准与评估框架类别，但突破了传统静态任务集构建流程。CLASHarness 将多智能体冲突任务形式化为冲突轮次元组 $R = (W_0, I, T, v^\star, \Phi)$，其中 $W_0$ 为初始计算机使用工作区，$I$ 为包含竞争声明的指令，$T$ 为类型化动作空间，$v^\star$ 为解决矛盾的决定性真值，$\Phi$ 为混合评估套件。该形式化将冲突解决定义为主动调查与决策，而非被动文本分类。智能体需自主调查多模态证据，识别 $v^\star$，并执行操作状态变更。

### 分层分阶段生成管线

传统单轮提示生成多轮场景易导致模式崩溃与叙事漂移。CLASHarness 采用分层分阶段生成管线，将场景合成分解为宏观规划与验证微执行。总 API 调用次数随轮数 $R$ 严格线性扩展：

$$
\text{Total API Calls} = 8 + \lceil R/P_s \rceil + K \cdot R + A
$$

其中 $P_s$ 为阶段跨度，$K \in [7, 8]$ 为每轮子调用数，$A$ 为资产数。该公式表明生成成本可控，避免了上下文饱和。设计动机在于隔离失败模式，通过窄子调用实现有界循环重试，防止因单步错误丢弃有效包状态。

### 事实预承诺与执行编译验证

无约束生成常导致视觉证据与文本泄漏不一致，或评分标准不可满足。CLASHarness 引入事实预承诺机制，在环境渲染前锁定决定性真值 $v^\star$，确保视觉证据与验证谓词引用相同真值。同时，评估检查器 $\Phi$ 直接从执行的参考轨迹编译，保证任务可解性。有效动作空间由插件声明的操作效果决定：

$$
T_{\text{valid}} = \{ c \in T \mid E(c) \cap E(P) \neq \emptyset \}
$$

该公式定义了动作与冲突机制的匹配规则，确保只有能产生预期状态变更的动作才被允许。这一设计解决了此前方法中评分标准与执行轨迹脱节导致的任务不可解问题，通过代码派生的评分器实现了 100% 的任务可解性保证。

## 实验评估

实验在自建 CLASHarness 基准上进行，包含 600 个多轮任务，评估 15 个前沿模型。基线覆盖审计显示，本文对比了 Claude、GPT、Gemini 等主流 LLM 骨干，但未对比专用故障归因方法（如 Famas）或安全防御机制（如 ControlValve），因任务目标不同。主实验结果显示，GPT-6 Astra 以 28.7% 的通过率位居榜首，Claude Opus 5 为 25.2%，Gemini 3.5 Flash 仅为 3.0%。

| 模型 | 通过率 (%) | 95% CI | Easy (%) | Mid (%) | Hard (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| GPT-6 Astra | 28.7 | [25.0, 32.3] | 35.2 | 28.1 | 18.6 |
| Claude Opus 5 | 25.2 | [21.8, 28.7] | 32.2 | 25.0 | 13.6 |
| Gemini 3.5 Flash | 3.0 | [1.7, 4.5] | 3.8 | 2.7 | 2.1 |

消融实验揭示了“冲突解决门”的显著影响。当任务要求主动解决冲突（状态变更）而非仅被动调查时，通过率从 28.1% 降至 11.0%，净双重差分惩罚为 -18.2 pp。

| 实验条件 | 通过率 (%) | 变化幅度 (pp) |
| :--- | :--- | :--- |
| 仅调查 (Investigate-only) | 28.1 | - |
| 解决门控 (Resolve-gated) | 11.0 | -17.1 |
| 控制组 (Control) | 20.4 | +1.1 |

评估边界方面，65.1% 的检查项依赖 LLM 语义评判，虽通过 3 样本自一致性投票实现 97.5% 的一致率，但 LLM 评判者的噪声是否足以掩盖模型间细微性能差异仍存疑。此外，生成模型自身的偏差可能导致基准对特定模型家族过拟合，论文未提供跨生成器家族的充分验证。

## 关联研究分析

从问题动机看，CLASHarness 与 AgentCollabBench 均关注多智能体协作，但 AgentCollabBench 局限于纯文本对话，无法评估智能体在操作环境中的状态验证能力。CLASHarness 将评估扩展至多模态计算机使用环境，揭示了协调协议执行是普遍瓶颈，而非单纯的感知或推理能力。这一差异源于任务特性：计算机使用场景要求智能体执行具体动作命令并记录在审计效果日志中，而纯文本对话仅要求输出文本答案。

从方法设计看，CLASHarness 与 TraceFix 均关注协议修复，但 TraceFix 侧重离线调试，利用 TLC 模型检测器搜索反例指导协议迭代修复；CLASHarness 侧重在线冲突解决能力的评估，通过执行编译验证确保任务可解性。CLASHarness 依赖 LLM 作为语义评判者，而 TraceFix 依赖形式化逻辑验证，这一差异反映了 LLM 非确定性行为与传统形式化规范之间的鸿沟。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文要解决的核心矛盾是现有基准无法评估多智能体在计算机使用场景中的冲突解决能力，因人工策划不可扩展且无约束生成导致任务不可解。CLASHarness 抓住可控生成与可验证性这一切入点，通过分层分阶段生成管线与事实预承诺机制，合成了 600 个可验证的多智能体冲突任务。实验证明，主动解决冲突比被动调查难度显著增加（-18.2 pp），且协调协议执行是前沿模型的普遍瓶颈。本文的边界在于依赖 LLM 作为语义评判者可能引入评估噪声，且生成模型自身的偏差是否导致基准对特定模型家族过拟合仍存疑。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
