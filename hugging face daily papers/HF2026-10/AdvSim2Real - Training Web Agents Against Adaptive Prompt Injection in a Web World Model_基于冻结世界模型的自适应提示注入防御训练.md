# HuggingFace最新推荐论文 ｜AdvSim2Real : Training Web Agents Against Adaptive Prompt Injection in a Web World Model ｜基于冻结世界模型的自适应提示注入防御训练

研究机构：阿联酋扎耶德大学、美国麻省理工学院

作者：Sarim Hashmi、Mukul Ranjan、Kshitij Mishra 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.08773)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.08773)

> 本文旨在解决Web智能体在开放环境中因第三方页面内容导致的间接提示注入（Indirect Prompt Injection, IPI）攻击，该攻击迫使智能体偏离用户授权目标。现有防御方法依赖固定注入样本微调，无法应对针对已训练模型的自适应攻击，且任务静态化导致训练效率低下。ADVSIM2REAL在冻结的Web世界模型中协同进化任务课程、注入对手与执行智能体，通过“成功翻转”奖励机制实现动态对抗训练。该方法提升了4B模型在未知前沿模型攻击下的相对完成率33.6%，但其鲁棒性增益仍受限于世界模型内部判定，且未验证任务在注入后的实际可行性。

## 研究背景

Web智能体执行多步任务时，必须读取由第三方编写的页面内容，其中既包含任务所需的数据与控制元素，也可能嵌入竞争指令。这种数据与控制混合的特性使得智能体无法通过简单忽略页面来防御攻击，因为忽略页面意味着失去完成任务所需的值。间接提示注入利用这一矛盾，在页面中植入指令以重定向智能体行为，导致其在Web安全基准中高达86%的攻击成功率。

当前主流防御路线分为两类：一是基于固定注入样本的微调，如StruQ和Meta SecAlign，通过分隔符或偏好学习让模型忽略低权限指令；二是自适应对抗训练，如RETA和ARLAS，通过红队生成攻击并训练防御者。然而，固定注入方法在面对针对已训练模型优化的自适应攻击时失效，而现有自适应方法虽能更新攻击，但任务集保持静态，导致智能体解决任务后该任务不再提供学习信号，且新任务需依赖可执行站点。ADVSIM2REAL的切入点在于利用冻结的Web世界模型（WebWorld-14B）预测任意目标、页面和动作下的下一页面，从而移除任务静态化和站点依赖的限制，实现任务与攻击的双重动态进化。

## 核心方法

### 方法参照系

本文问题属于Web智能体安全防御中的对抗训练范畴，但区别于传统在真实浏览器或固定环境中进行的红队测试。关键差异在于环境模拟：本文使用冻结的世界模型 $W$ 替代真实浏览器，预测页面状态 $o_{t+1} \sim W(\cdot | h_t, a_t)$，使得攻击注入可以通过世界模型渲染为可信页面内容，而无需真实网络交互。

### 课程-执行者协同进化

第一阶段解决任务静态化问题，通过课程策略 $C$ 与执行者 $E$ 的交替更新，使任务难度跟随执行者能力边界。课程奖励基于执行者成功率 $p$ 的不确定性函数，避免执行者总能解决或总无法解决的任务提供梯度信号。

$$
R_C(x) = \nu(x) \max\left(0, q(\hat{p}_J(x)) - \lambda_C n(x)\right), \quad q(p) = 1 - 2|p - 1/2|
$$

该公式中 $q(p)$ 在 $p=1/2$ 时取最大值，在 $p \in \{0, 1\}$ 时为零，确保课程仅奖励处于执行者能力边缘的任务。设计动机在于解决固定任务集中“已解决任务不再教学”的失效，通过动态生成任务池维持训练信号的有效性。

### 对手-执行者协同进化

第二阶段引入对手策略 $A$，其奖励机制仅针对“成功翻转”：即原本被判定成功的干净轨迹，在注入后重放至特定步骤时失败。对手采样注入指令 $z$、标记 $m$、注入步 $d$ 及可选目标动作 $\zeta$，世界模型渲染注入后的页面，执行者继续执行。

$$
R_A(\alpha) = \mathbb{1}[\text{injection rendered}] \cdot \mathbb{1}[j(x, \tau_{\text{clean}})=1] \cdot \mathbb{1}[j(x, \tau_{\text{attacked}})=0]
$$

该奖励函数确保对手无法从执行者固有错误中获利，仅当注入直接导致成功变失败时才获得信用。设计动机在于解决现有自适应攻击中“对手利用执行者自身缺陷”的失效，通过因果归因确保训练信号直接关联注入效果。执行者 $E$ 在新攻击、历史攻击与干净任务的混合数据上训练，历史攻击保留以防止遗忘。

## 实验评估

实验在150个表单填充任务上进行，涵盖5个技能层级，使用Qwen3.5-4B作为执行者，WebWorld-14B作为世界模型，Qwen3.8-27B作为判定器。基线包括基础模型、托管Qwen3.5-9B及未参与训练的前沿模型Kimi-K3。缺失与系统级沙箱（如ceLLMate）或语义检测（如WebSentinel）的直接对比，但覆盖了模型级防御的主要路线。

| 检查点 | 干净完成率 (%) | 学习对手平均完成率 (%) | Kimi-K3攻击完成率 (%) |
| :--- | :--- | :--- | :--- |
| Base | 74.89 ±1.39 | 48.07 ±0.56 | 23.00 ±3.30 |
| Robust iter 3 | 81.33 ±2.31 | 57.48 ±0.56 | 30.72 ±3.04 |

核心数字显示，ADVSIM2REAL将干净完成率提升6.44个百分点，学习对手攻击下提升9.41个百分点，Kimi-K3攻击下相对提升33.6%。

消融实验表明，移除第一阶段（课程进化）导致干净完成率下降4.67个百分点，但攻击完成率仅下降0.44个百分点，且差异方向在不同对手间不一致。这表明第一阶段主要贡献于能力增益而非鲁棒性，鲁棒性增益主要来自第二阶段的对抗训练。反直觉发现是，第一阶段在未见过任何注入的情况下，将攻击平均完成率从48.07%提升至54.74%，暗示能力增强本身对鲁棒性有间接正向作用。

评估边界方面，所有攻击结果均为世界模型内部判定，未验证注入后任务是否仍可行；世界模型可能渲染执行者未输入的值，导致判定偏差。可复现性上，论文释放代码、基准及检查点，但单次Stage-1迭代消耗41.54 GPU-hours（2×96GB RTX 6000 Pro，20h46min），端到端成本未报告。

## 关联研究分析

从问题动机看，ADVSIM2REAL与ceLLMate代表两种根本不同的防御哲学。ceLLMate在浏览器HTTP层强制执行策略，通过系统级隔离限制智能体行为，不依赖模型对恶意指令的理解；而ADVSIM2REAL通过模型级训练提升智能体识别并忽略注入的能力，保持行为灵活性。ceLLMate的优势在于提供硬性安全边界，但可能因权限过严导致任务失败率上升；ADVSIM2REAL的优势在于任务保持鲁棒性，但依赖世界模型保真度。两者差异根源在于任务特性：表单填充任务中，注入通常表现为竞争指令而非数据篡改，模型级防御足以应对；而在支付等高风险场景中，系统级隔离可能更必要。

从方法设计看，ADVSIM2REAL与WebWorld的关系是环境依赖与训练范式创新的分离。WebWorld提供页面预测能力，使离线对抗训练成为可能，但本身不解决安全训练问题；ADVSIM2REAL利用WebWorld的冻结特性，构建课程-对手-执行者三方协同进化框架。与StruQ等固定注入方法相比，ADVSIM2REAL的关键差异在于攻击的动态性：StruQ的注入在训练前固定，而ADVSIM2REAL的对手针对当前执行者弱点生成注入，且任务动态更新。这种动态性解决了固定注入方法在面对自适应攻击时的失效，但引入了世界模型预测误差累积的风险，训练-测试差距可能限制真实部署效果。

## 总结

ADVSIM2REAL解决的核心矛盾是Web智能体在开放环境中既要读取第三方页面数据，又要抵御其中嵌入的竞争指令。现有固定注入微调无法应对自适应攻击，静态任务集导致训练信号枯竭，而本文通过冻结世界模型中的三方协同进化，使任务与攻击均跟随智能体能力动态更新。方法证明4B模型在Kimi-K3攻击下相对完成率提升33.6%，干净完成率提升6.44个百分点，且能力增益可迁移至真实浏览器。然而，所有鲁棒性数字均为世界模型内部判定，未验证注入后任务可行性，且世界模型可能渲染虚假页面内容。当世界模型预测误差累积到何种程度时，训练出的鲁棒性会在真实浏览器中失效，论文未给出量化边界。
