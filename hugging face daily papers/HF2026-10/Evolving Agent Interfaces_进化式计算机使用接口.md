# HuggingFace最新推荐论文 ｜Evolving Agent Interfaces ｜进化式计算机使用接口

作者：Saaket Agashe、Yuzhe Yang、Gonzalo Gonzalez-Pumariega 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.28601)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.28601)

> 计算机使用智能体（Computer-Use Agent, CUA）的核心瓶颈在于人类预设的静态交互界面与动态任务需求之间的结构性错配，导致模型需消耗大量计算资源进行低效的图形用户界面（Graphical User Interface, GUI）模拟操作。现有方法多致力于优化模型在固定接口上的表现，却忽略了接口本身作为可学习对象的潜力。本文提出Agent S4框架，将接口设计转化为智能体自身的能力，通过元智能体（Meta-agent）分析无标签合成任务轨迹，利用种群进化算法自动构建并优化可复用的代码接口库。该研究证明了在固定模型参数的前提下，仅通过进化交互界面即可使27B开源模型超越前沿闭源模型，确立了“接口即策略”的新范式。然而，该范式对未知UI变化的鲁棒性及其在极端分布外场景的泛化能力仍存疑。

## 研究背景

当智能体面对复杂的桌面环境时，其操作效率高度依赖于底层交互接口的抽象层级。传统的CUA框架主要依赖像素级截图与鼠标键盘动作作为基础接口，这种设计虽然具备跨平台的通用性，但在处理结构化数据或批量操作时存在严重的效率瓶颈。例如，智能体可能需要通过数十次点击和截图来读取一个电子表格，而一行代码即可实现相同功能。这种低效不仅增加了推理延迟，还因视觉噪声引入了错误累积的风险。为了缓解这一问题，领域内逐渐引入了命令行界面（Command-Line Interface, CLI）或应用程序编程接口（Application Programming Interface, API）作为补充，但这些工具集通常由人类专家预先定义，缺乏对特定任务流的自适应能力。

当前CUA研究的主流路线集中在优化模型在固定接口上的表现，包括通过监督微调（Supervised Fine-Tuning, SFT）提升视觉定位精度，或通过强化学习（Reinforcement Learning, RL）优化长程任务中的决策策略。然而，这些方法均将交互界面视为不可变的设计决策，导致模型必须通过增加测试时计算量来弥补接口与任务之间的不匹配。这种“框架驱动”或“模型驱动”的范式受制于人类对智能体需求的先验判断，难以随着任务多样性的增加而扩展。Agent S4的切入点在于将接口本身视为可进化的软件对象，通过从智能体自身的执行经验中学习，动态构建适配任务需求的混合接口，从而打破静态接口对智能体能力的限制。

## 核心方法

### 方法参照系：固定接口下的智能体交互

在标准的CUA框架中，智能体 $A$ 由模型 $M$ 和运行环境（Harness）$H$ 组成，通过一组固定的基础接口 $\mathcal{I}$ 与计算机状态 $s$ 交互。智能体在每一步 $t$ 根据指令 $g$ 和历史记录 $h_t$ 选择接口 $I_t$ 和动作 $a_t$，环境返回新的状态 $s_{t+1}$ 和观测 $o_t$。这一过程可形式化为：

$$
(I_t, a_t) \sim M(\cdot | g, h_t, \mathcal{I}), \quad (s_{t+1}, o_t) \sim T_{I_t}(\cdot | s_t, a_t)
$$

该流程的关键局限在于接口 $\mathcal{I}$ 在任务执行前已固定，智能体无法根据任务特性动态扩展其可请求的操作或可获取的观测类型。Agent S4将这一固定接口扩展为可进化的接口库 $\mathcal{R}$，其中包含可执行接口 $\mathcal{I}(\mathcal{R})$ 和使用知识 $\mathcal{K}(\mathcal{R})$，智能体的决策过程变为：

$$
(I_t, a_t) \sim M(\cdot | g, h_t, \mathcal{I} \cup \mathcal{I}(\mathcal{R}), \mathcal{K}(\mathcal{R}))
$$

### 基于轨迹分析的接口进化机制

Agent S4的核心创新在于引入元智能体 $A_{meta}$，通过研究任务智能体在合成任务上的执行轨迹来进化接口库。元智能体接收无成功标签的训练轨迹，识别重复操作、缺失能力或脆弱的工作流，并据此修改接口代码。这一过程不依赖传统的奖励信号，而是通过代码层面的重构来优化智能体的交互能力。接口进化步骤可表示为：

$$
\mathcal{R}_{k+1} = E(\mathcal{R}_k, \mathcal{T}_k)
$$

其中 $E$ 为进化算子，$\mathcal{T}_k$ 为使用接口库 $\mathcal{R}_k$ 产生的轨迹集合。元智能体通过两种主要操作实现进化：变异（Mutation），即在单一父代接口库基础上添加、修改或删除接口；交叉（Crossover），即结合两个不同父代接口库的优势，生成包含互补能力的新接口库。这种基于代码的进化机制允许智能体发现并封装特定应用的操作原语，例如为LibreOffice创建批量编辑接口，或为浏览器创建直接读取页面文本的API封装，从而消除GUI操作中的冗余步骤。

### 种群进化与验证集选择策略

为了防止接口进化过拟合于特定的合成任务，Agent S4采用种群进化策略，并实施严格的证据分离机制。元智能体仅能访问训练轨迹，而验证任务、轨迹及评估器对其不可见。验证集的表现仅用于指导父代选择，而不直接反馈给接口构建过程。这一不对称评估机制确保了进化出的接口具备泛化能力。种群更新过程如下：

$$
\mathcal{R}_{k+1} \leftarrow \mathcal{R}_k \cup \{ \mathcal{R}' \}
$$

其中 $\mathcal{R}'$ 为新生成的后代接口库。通过二元锦标赛选择（Binary Tournament Selection）从种群中挑选父代，保留高分变体并淘汰低分变体。这种机制使得早期分支的接口设计能够在后续进化中被重新利用和重组，避免了线性进化中常见的局部最优陷阱。最终，通过验证集表现选出的最优接口库 $\hat{\mathcal{R}}$ 被冻结，用于在目标测试集上评估智能体的性能。

## 实验评估

实验在OSWorld V2和ScienceBoard两个基准上进行，分别评估通用桌面任务和科学计算任务中的接口进化效果。基线对比涵盖了固定接口的开源模型（如Qwen CUA）和前沿闭源模型（如GPT-5.5, Claude Opus 4.8）。

| 模型 / 方法 | 接口类型 | 参数量 | 二元成功率 (%) | 部分得分 (%) | 单任务成本 ($) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen CUA (Qwen3.8-27B) | Fixed | 27B | 5.56 | 20.69 | 1.39 |
| Evolved repo. (w/ scratch VM) | Evolving | 27B | 19.44 | 51.06 | 1.27 |
| Evolved repo. (w/o scratch VM) | Evolving | 27B | 21.30 | 46.90 | 1.10 |
| Claude Opus 4.8 (batched) | Fixed | — | 20.60 | 54.80 | 72.40 |
| GPT-5.5 (batched) | Fixed | — | 13.00 | 49.50 | 25.50 |

在OSWorld V2上，使用进化接口的Qwen3.8-27B模型取得了21.30%的二元成功率，显著高于固定接口基线的5.56%，并超越了Claude Opus 4.8（20.60%）和GPT-5.5（13.00%）。值得注意的是，进化接口的单任务成本仅为1.10美元，远低于Claude Opus 4.8的72.40美元。这表明接口进化不仅提升了任务完成率，还通过减少GUI交互步骤显著降低了计算开销。

消融实验进一步揭示了进化策略与元智能体环境配置的影响。

| 条件 | 二元成功率 (%) | 部分得分 (%) |
| :--- | :--- | :--- |
| No Repository | 15.74 | 44.93 |
| Agent S4 Seed Repository | 19.44 | 44.90 |
| Linear, scratch VM | 19.44 | 47.17 |
| Population, scratch VM | 19.44 | 51.06 |
| Population, no scratch VM | 21.30 | 46.90 |

种子接口库将二元成功率从15.74%提升至19.44%，证明了基础工具封装的价值。种群进化策略在无沙盒虚拟机（Scratch VM）配置下取得了最高的二元成功率（21.30%），而在有沙盒虚拟机配置下取得了最高的部分得分（51.06%）。这一反直觉发现表明，沙盒环境允许元智能体测试代码，从而生成更复杂的应用特定接口，提升中间进度；但无沙盒环境迫使元智能体依赖轨迹分析，可能生成更鲁棒、更通用的接口，从而在最终任务完成上表现更佳。

评估边界方面，实验未报告置信区间，且合成任务无真实成功标签，可能导致元智能体对失败模式的识别存在偏差。此外，进化过程计算成本高，且接口库的维护与版本控制在实际部署中面临挑战。

## 关联研究分析

从问题动机看，Agent S4与ToolCUA（Hu et al., 2026）均致力于解决GUI操作效率低的问题，但路径截然不同。ToolCUA通过优化GUI与预定义工具之间的路径选择来提升效率，其工具集仍是静态的；而Agent S4直接生成新的工具接口，消除了GUI操作的中间层。这种差异源于对“工具”定义的不同：ToolCUA视工具为外部资源，Agent S4视工具为可进化的内部能力。Agent S4的方法在任务多样性极高时更具优势，但可能牺牲了对未知UI变化的鲁棒性，因为进化出的接口高度依赖特定应用的内部结构。

从方法设计看，Agent S4与MobileRL（Zhang et al., 2024）均试图提升智能体的自主性，但优化对象不同。MobileRL通过在线强化学习优化模型权重，使模型适应固定接口；Agent S4则固定模型权重，通过进化算法优化接口代码。这种“接口即策略”的范式避免了模型训练的高昂成本，但引入了接口代码的复杂性管理问题。MobileRL在动态环境中的泛化能力依赖于模型对视觉特征的鲁棒提取，而Agent S4的泛化能力依赖于进化出的接口是否具备足够的抽象层级。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文针对静态人机接口与动态任务需求之间的结构性错配，提出Agent S4框架，将接口设计转化为智能体自身的能力。通过元智能体分析无标签合成任务轨迹，并利用种群进化算法自动构建可复用的代码接口库，Agent S4在固定模型参数的前提下，使Qwen3.8-27B在OSWorld V2上取得21.30%的二元成功率，超越前沿闭源模型。该研究证明了接口设计是独立于模型规模的关键性能瓶颈。然而，实验显示进化出的接口高度依赖特定应用的内部结构，且无沙盒环境下的进化虽提升了最终成功率，但部分得分较低，暗示其可能牺牲了对复杂中间状态的感知能力。当面对训练分布外的全新应用或UI布局时，进化出的接口是否会因缺乏视觉鲁棒性而失效，论文未给出回答。
