# HuggingFace最新推荐论文 ｜SolarRenderer: Few-Step Generative Reference Rendering ｜通用结构视频渲染与少步加速

研究机构：新加坡国立大学、香港中文大学

作者：Guian Fang、Shengju Qian、Dongyue Lu 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.28630)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.28630)

> 导读 可控视频生成领域长期受困于控制信号与模型架构的强耦合，现有渲染器往往绑定特定引擎导出的单一结构表示，且依赖高计算成本的迭代去噪，难以满足实时交互需求。SolarRenderer 提出一种解耦控制与加速的通用渲染框架，通过原生参考路径注入无类型标识的结构视频，并利用结构引导分布匹配实现少步生成。该方法在保持预训练模型外观先验的同时，实现了对未见结构类型的泛化渲染与实时流式输出。其核心价值在于将“结构控制”从特定条件分支转化为通用参考读取能力，但自建评估基准与领域标准基准的脱节，使得其绝对性能优势尚需跨基准验证。

## 研究背景

当游戏引擎或智能体规划出场景布局与运动轨迹后，如何将这种粗粒度结构转化为高保真视频，是4D世界模型落地的关键瓶颈。传统视频扩散模型依赖文本或图像隐式引导，无法精确约束时空演变；而引入显式几何条件（如相机姿态、深度图）虽提升了控制精度，却导致模型架构与特定表示形式绑定。这种绑定使得新引擎或新结构类型（如线框图、手绘草图）的接入需要重新训练专用分支，且多步去噪过程计算开销巨大，阻碍了实时应用。

当前领域在“控制精度”与“泛化性/效率”之间存在显著张力。一方面，CameraCtrl等方法通过Plücker嵌入等专用模块实现高精度相机控制，但缺乏对多源异构结构的通用性；另一方面，免训练方法虽保留预训练分布，但在复杂结构遵循上精度不足。此外，训练数据中结构信号与目标视频常存在帧级不对齐，导致模型学习到错误的运动-外观映射。SolarRenderer 针对上述痛点，试图在冻结的大模型骨干上，通过轻量级适配器实现任意结构的通用渲染与少步加速。

## 核心方法

### 原生参考路径与无类型条件注入

在可控视频生成的标准流程中，结构条件通常通过ControlNet分支或通道拼接注入，这引入了额外参数且限制了表示形式的扩展性。SolarRenderer 摒弃了专用分支，将结构视频 $S$ 视为一种特殊的参考视频，直接输入至冻结的 MiniMax-H3 33B 骨干网络的原生参考路径。为解决零样本模型将结构视频误作风格参考的问题，该方法实施帧对齐位置编码：每个结构潜在帧 $s_k$ 共享其对应目标潜在帧 $z_k$ 的旋转位置编码（RoPE）坐标，确保注意力机制能建立逐帧的空间对应关系。

同时，结构视频在序列中不携带类型标识符，而是通过提示词中的固定文本描述其语义（如“无纹理灰色块”或“语义分割图”）。这种设计使得单一控制 LoRA 能够学习从任意视觉模式中提取布局与运动信息，而非记忆特定格式，从而支持对未见结构（如儿童蜡笔画、点云）的零样本泛化。

### 结构引导分布匹配加速

为将50步去噪压缩至4步，SolarRenderer 采用两阶段解耦训练：Stage 1 训练控制 LoRA 以学习结构遵循，Stage 2 训练加速 LoRA 以优化采样效率。直接对控制模型进行分布匹配蒸馏（Distribution Matching Distillation, DMD）会导致性能下降，因为教师模型（全步控制模型）在结构条件下生成的预测往往模糊，学生模型会被拉向这一模糊分布。

为此，论文提出结构引导分布匹配，通过外推教师模型的结构贡献来锐化目标分布。设 $\hat{z}_0(C)$ 为教师模型在包含结构条件 $C$ 下的预测，$\hat{z}_0(C_\emptyset)$ 为移除结构视频后的预测，则外推后的教师预测 $\hat{z}_0^w$ 为：

$$
\hat{z}_0^w = \hat{z}_0(C) + (w - 1) \left( \hat{z}_0(C) - \hat{z}_0(C_\emptyset) \right)
$$

其中 $w > 1$ 为引导强度。该公式通过放大结构信号对预测的影响，迫使加速模型在少步采样中保持比教师模型更清晰的结构遵循能力，从而在4步内实现高质量渲染。

### 帧对齐数据构建与因果流式扩展

针对真实视频估计结构（如深度、分割）存在噪声且与引擎导出结构分布不一致的问题，论文构建了包含136K个片段的帧对齐数据集。数据源涵盖游戏引擎（Unreal, CARLA）、模拟器及YouTube视频，仅保留结构帧与目标帧在时间与内容上严格对齐的样本，避免模型学习到松散的对应关系。

为支持实时交互，该方法进一步扩展为块因果（Block-Causal）变体。视频被分割为至多5个潜在帧的块，每个块仅关注自身结构、前5个块的干净帧及提示词，通过教师强制训练因果控制 LoRA。推理时，结合流式VAE解码器，该变体可在单GPU上以28 FPS实时渲染768p视频，尽管其外观一致性略低于双向模型，但结构控制能力得以保留。

## 实验评估

实验在自建分布内测试集（53个片段）和泛化基准（208个案例，含11种未见结构）上进行，主要采用Gemini 3.8 Flash进行成对判断并拟合Elo评分，辅以自动指标（DOVER, CoTracker3等）。基线覆盖包括官方骨干、现有加速LoRA组合（LongLive-Plug, DMAD）及专用结构渲染器（Streaming CWM, Cosmos-Transfer2.5等）。

| 方法 | 分布内测试集 (Overall) | 泛化基准 (Overall) | 结构遵循 (Struct.) | 首帧保持 (First fr.) |
| :--- | :---: | :---: | :---: | :---: |
| Official Backbone | 554 | 627 | - | - |
| Streaming CWM | 988 | 1075 | - | - |
| Stage 1 + LongLive-Plug | 1389 | 922 | - | - |
| **SolarRenderer (4-step)** | **1441** | **1096** | **1005** | **1076** |
| SolarRenderer (50-step) | 1386 | 1024 | - | - |

*注：Elo评分以对比方法均值为1000。SolarRenderer 4-step在分布内与泛化基准上均显著优于专用渲染器及简单组合基线。*

消融实验揭示了关键设计决策的影响。在条件注入设计上，使用原生参考路径比ControlNet分支在结构得分上高出1.2分（48.0 vs 46.8），且共享RoPE位置比独立RoPE更优。在数据层面，移除帧不对齐的WildWorld数据使结构得分提升0.8分，表明数据对齐质量比数据规模（1/10数据仅降低0.1分）更为关键。在加速阶段，结构引导强度 $w=1.5$ 时效果最佳，过强（$w=2$）反而导致评分下降，且仅在噪声水平 $\sigma \ge 0.9$ 时施加引导即可达到全阶段引导的效果，说明布局主要在去噪早期决定。

评估边界方面，论文未与领域标准基准（如RealEstate10K的RotErr）进行直接数值对比，而是依赖自建基准的相对排序。虽然提供了代码与权重，但Gemini评估协议的黑盒性质可能引入偏差。此外，因果流式变体在外观稳定性上存在明显短板，后续块易偏离首帧色彩。

## 关联研究分析

从控制机制看，SolarRenderer 与 CameraCtrl 代表了两种截然不同的显式控制路线。CameraCtrl 通过Plücker嵌入将相机位姿转化为几何射线，并注入专用编码器，这种设计在相机旋转精度上具有理论优势，但难以扩展至非相机类结构（如物体形变）。SolarRenderer 则通过原生参考路径将结构视为“视觉提示”，利用大模型固有的参考理解能力，牺牲了部分几何解析的显式性，换取了对任意结构表示的通用性。这种差异源于任务定义的不同：前者聚焦于单一维度的精确控制，后者聚焦于多源异构结构的统一渲染。

从加速策略看，SolarRenderer 与 DMAD 的关系体现了“通用加速”与“条件感知加速”的冲突。DMAD 等通用加速LoRA在无条件或文本条件下表现优异，但直接组合到控制模型上会导致结构遵循能力退化（评分从1024降至820）。SolarRenderer 的结构引导分布匹配通过外推教师模型的结构贡献，修正了通用加速模型在条件生成中的分布偏移。这一发现暗示，在条件生成任务中，加速过程必须显式感知条件信号，否则去噪步数的减少会不成比例地损害条件遵循能力。

## 总结

SolarRenderer 解决了可控视频生成中结构表示多样性与推理效率之间的矛盾。通过原生参考路径与无类型标识设计，它将结构控制转化为通用参考读取，并通过结构引导分布匹配实现了4步高质量渲染。实验表明，该方法在自建泛化基准上达到1096 Elo评分，显著优于专用渲染器，且能零样本泛化至未见结构。然而，其性能评估完全依赖自建基准，缺乏与领域标准几何指标的直接对标；因果流式变体在长程外观一致性上存在漂移。当结构信号与目标视频存在细微时间错位时，该模型对帧对齐的强依赖是否会成为开放域视频编辑的瓶颈，尚需进一步验证。
