# HuggingFace最新推荐论文 ｜The LLM-Attacker: A Unified Red-Team Framework for Privacy Evaluation of Split and Distributed LLM Systems ｜分布式大语言模型隐私评估框架

作者：Georgios Politis、Evangelos Pappas

论文原文见 [arXiv](https://arxiv.org/abs/2610.22722)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.22722)

> 导读 分布式大语言模型（LLM）在拆分训练与推理时，中间激活值与梯度不可避免地携带敏感信息，导致隐私泄露风险从静态数据提取扩展至动态通信过程。现有隐私评估方法多聚焦于单点攻击算法的有效性，缺乏对攻击者观察面、知识权限及计算预算的标准化记录，致使不同研究间的隐私结论难以复现与公平比较。LLM-Attacker 提出了一种统一的红队评估框架，通过形式化定义评估契约并强制链接无防御参考基线，将隐私评估转化为可复现、可审计的实验协议。该框架在受控实验中量化了梯度泄露对文本重构的显著增益，确立了评估方法论在分布式隐私安全中的核心地位，但其对纯黑盒 API 场景的适用性仍存疑。

## 研究背景

当大语言模型（LLM）采用拆分学习（Split Learning）架构时，客户端保留输入文本并运行前几层，将中间激活值发送至服务器，服务器在训练时返回梯度。这一通信过程使得攻击者能够通过截获激活值或梯度重构原始文本。然而，不同研究对攻击者能力的假设差异巨大：有的假设攻击者仅能观察激活值，有的假设其能获取训练后的模型权重，还有的假设其能控制服务器返回的张量。这种威胁模型的不一致，导致同一防御机制在不同评估协议下可能得出截然相反的隐私结论。

当前领域在隐私评估上面临的核心困境是“评估契约的缺失”。主流方法如 Scalable Extraction 确立了黑盒环境下的可提取性度量，MoPe 揭示了白盒参数扰动与隐私泄露的几何关联，但这些工作多侧重于单一攻击算法的创新，未将攻击者的观察面（Observations）、知识（Knowledge）与预算（Budget）作为独立变量进行标准化控制。在分布式系统中，防御机制的效用-隐私权衡高度依赖于攻击者是否知晓防御细节及是否拥有特定权限。若评估协议未明确记录这些条件，防御者可能通过隐藏攻击者权限来人为降低泄露率，从而掩盖真实的隐私风险。因此，建立一套能够显式记录攻击者权限、强制对比无防御基线并报告未测试威胁的评估框架，成为解决分布式 LLM 隐私审计不可靠问题的关键。

## 核心方法

### 评估契约的形式化定义

在分布式隐私评估中，通常的做法是报告单一指标（如重构准确率），但这种方法无法区分攻击成功是源于算法优越性还是攻击者权限的隐性提升。LLM-Attacker 将评估过程形式化为一个八元组 $E = (T, V, O, K, B, C, M, G)$。其中 $T$ 定义目标模型与拆分点，$V$ 定义攻击者位置与特权，$O$ 记录攻击者观察到的消息（如激活值、梯度），$K$ 记录攻击者已知的模型权重（如公共预训练层或训练后层），$B$ 限定计算与搜索预算，$C$ 固定语料库与分词器，$M$ 为测量结果，$G$ 包含控制变量与决策规则。该定义将实验对比转化为对特定分量的控制：例如，读取梯度改变 $O$，接收训练层改变 $K$。通过固定其余分量，框架能够隔离特定攻击变量（如梯度信息）对隐私泄露的独立贡献，解决了以往评估中因权限混淆导致的结论不可比问题。

### 捕获与重放机制

传统评估中，攻击算法与目标模型执行耦合，导致无法在不重新训练模型的情况下测试新攻击或重新评分。LLM-Attacker 引入捕获（Capture）与重放（Replay）机制，将目标执行与攻击执行解耦。框架在拆分点截获前向消息与训练时的返回梯度，并保存其会话与排序元数据。兼容的攻击模块在重放时，针对相同的检查点与文档复用这些观察数据。这一设计使得攻击者可以在不访问私有文本或服务器层的情况下，仅基于截获的张量进行重构。例如，激活值攻击者通过拟合岭解码器从公共激活值映射到词嵌入，而联合攻击者则结合激活值与梯度候选。该机制支持配对比较与独立重评分，确保了评估结果的可复现性，并允许后续研究在冻结的对比中无缝接入新攻击模块。

### 强制基线与覆盖率报告

防御评估的常见失效在于缺乏严格的对照，导致防御效果被高估。LLM-Attacker 规定，任何候选防御在通过评分规则前，必须链接一个无防御参考（Undefended Reference）。评分规则要求防御后的泄露率必须显著低于无防御基线，且需报告未测试的威胁（Coverage Report）。框架将威胁标记为“已覆盖”“部分覆盖”“未测量”或“超出范围”，明确区分执行失败与负面攻击结果。例如，在评估轻量级防御时，框架不仅报告重构率，还记录防御对模型效用（如交叉熵）的影响。这种设计强制评估者披露防御的隐性成本，防止通过牺牲模型效用或隐藏攻击者权限来伪造隐私保护效果，从而在隐私保证强度与部署可行性之间提供透明的权衡依据。

## 实验评估

实验在 GPT-2 (124M) 模型上进行，拆分点设在第 3 或第 6 层，使用 WikiText-2、代码及合成临床笔记作为语料库。基线审计覆盖了激活值攻击、梯度攻击及联合攻击，并对比了 BiSR 等已发表攻击实现。主实验聚焦于攻击者观察面的变化对重构效果的影响。

| 攻击配置 | 观察面 | 词元恢复率 (%) | 精确文档恢复率 (%) |
| :--- | :--- | :--- | :--- |
| 激活值攻击 | 仅激活值 | 94.20 | 13.71 |
| 联合攻击 | 激活值 + 梯度 | 97.38 | 37.77 |
| 联合攻击 (训练层) | 激活值 + 梯度 + 训练层 | 98.27 | 58.55 |

在深度 6 且攻击者持有公共层权重的条件下，联合攻击相比激活值攻击的词元恢复率提升 3.17 个百分点（95% 置信区间 [2.72, 3.64]），精确文档恢复率从 13.71% 跃升至 37.77%。这一结果表明，梯度信息对完整文档的重构具有决定性影响，而单一词元指标会严重低估隐私风险。

消融实验进一步验证了评估协议对语料库敏感性的捕捉能力。不同语料库的基线猜测率差异巨大，导致“超额恢复率”（Excess Recovery）成为更可靠的隐私指标。

| 语料库 | 基线猜测率 (%) | 恢复率 (%) | 超额恢复率 (pp) | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| 源代码 | 20.31 | 64.94 | +46.78 | FAIL |
| 合成临床笔记 | 6.25 | 100.00 | +93.75 | FAIL |
| WikiText-2 | 2.64 | 63.25 | +62.79 | FAIL |

合成临床笔记因高度模板化，其基线猜测率极低，导致攻击恢复率达到 100%，超额恢复率高达 93.75 个百分点。这揭示了在结构化数据上，即使简单的攻击也能造成完全泄露，而传统评估若未报告基线，可能误判防御的有效性。此外，框架在 20 至 100 训练步的长周期测试中，验证了防御判定的一致性，并发现某些防御（如 Mid-lite）虽能抑制攻击，但导致交叉熵从 4.39 激增至 7.42，暴露了隐私-效用权衡的极端性。

评估边界方面，框架目前主要验证了拆分架构下的白盒/灰盒重构，未直接覆盖纯黑盒 API 场景下的生成式提取。可复现性依赖于保存的预测值与哈希链日志，但框架本身未提供针对大规模生产级模型的自动化部署接口。

## 关联研究分析

从问题动机看，LLM-Attacker 与 Scalable Extraction (Nasr et al., 2023) 均关注训练数据泄露，但前者聚焦于分布式通信中的中间表示泄露，后者聚焦于黑盒生成式提取。Scalable Extraction 通过散度攻击证明了对齐模型仍可能泄露吉字节级数据，其核心贡献在于攻击算法的规模化；而 LLM-Attacker 的核心贡献在于评估协议的标准化，强调在比较不同防御时，必须控制攻击者权限与观察面。这一差异源于任务特性：分布式系统的隐私风险高度依赖于通信协议与攻击者位置，而黑盒提取更依赖于模型本身的记忆强度。

从方法设计看，LLM-Attacker 与 MoPe (P35) 均利用模型内部状态进行隐私评估，但 MoPe 通过参数扰动测量 Hessian 矩阵迹来识别训练数据成员，属于白盒成员推断；LLM-Attacker 则通过重构激活值与梯度来量化文本泄露，属于重构攻击。MoPe 揭示了模型几何结构与隐私的关联，但未涉及分布式通信中的权限控制问题。LLM-Attacker 的评估契约 $E$ 显式记录了攻击者是否拥有训练层权重（$K$），这一设计在 MoPe 中未被强调，因为 MoPe 默认假设攻击者拥有完整模型。这种差异暗示了分布式隐私评估中，权限泄露（如训练层权重泄露）可能比算法本身更具决定性影响。

## 总结

LLM-Attacker 针对分布式 LLM 隐私评估中威胁模型不一致、结论不可复现的核心矛盾，提出了基于八元组 $E$ 的标准化评估契约。通过强制链接无防御基线、解耦捕获与重放机制，框架将隐私评估从单一算法效果转化为可审计的实验协议。实验证明，在 GPT-2 拆分架构中，梯度信息的加入使精确文档恢复率从 13.71% 提升至 37.77%，且语料库特性对超额恢复率有显著影响。该框架的边界在于其验证主要基于受控的拆分实验，未直接覆盖纯黑盒 API 场景下的生成式提取风险。当评估协议从受控的拆分架构迁移至完全黑盒的生产级 API 时，如何定义攻击者的观察面 $O$ 与知识 $K$，以及如何在无法截获中间张量的情况下维持评估契约的区分度，是该框架走向通用化必须解决的关键问题。
