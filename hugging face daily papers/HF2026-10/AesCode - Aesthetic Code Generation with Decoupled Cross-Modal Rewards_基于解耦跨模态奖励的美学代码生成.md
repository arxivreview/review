> 导读 信息丰富的视觉产物（如幻灯片、海报）若以代码形式生成，虽具备可编辑性与可验证性，但代码模型缺乏对画布空间布局与色彩美学的直观感知，导致输出视觉平庸。现有图像生成模型虽擅长视觉设计，却常出现文本与逻辑错误，且其栅格化输出无法直接作为代码生成的绝对真值。AesCode 提出将图像生成器作为美学先验，通过设计图（Design Graph）将视觉目标解耦为可验证的结构属性与需感知的视觉属性，并采用解耦跨模态奖励进行强化学习训练。该工作验证了利用生成图像指导代码模型提升视觉质量的可行性，但其评估基准的自建性与人类偏好对齐的间接性，使其在通用美学评估中的泛化能力仍存疑。

## 研究背景

当代码模型生成信息丰富的视觉产物时，其核心困境在于无法“看见”画布。代码模型逐行声明空间布局、层级与色彩，这种线性生成方式导致输出虽满足内容约束，却常因缺乏全局视觉规划而显得陈旧。为解决此问题，研究者引入图像生成器作为视觉设计的参考，但直接以生成图像为真值进行像素级重建（如 Design2Code）会迫使代码模型模仿图像生成器的幻觉内容，并惩罚有效的设计变体。这一矛盾揭示了代码生成任务中“内容正确性”与“视觉美学”的解耦需求：代码模型需严格遵循文本提示的内容要求，同时灵活提取参考图像中的布局与风格灵感。

传统图像质量评估（IQA）与美学评估（IAA）多依赖单一标量分数或分布指标（如 FID），缺乏对局部伪影与结构缺陷的诊断能力。在多模态大语言模型（MLLMs）引入后，评估范式转向可解释的细粒度诊断，但现有方法多针对静态图像，未解决代码生成中“可验证结构”与“主观视觉”的奖励冲突。AesCode 的切入点在于：将评估与生成闭环，通过结构化中间表示（设计图）将视觉目标分解为可程序化验证的属性与需 VLM 判断的属性，从而在强化学习中平衡确定性规则与感知性美学。

## 核心方法

### 设计图作为监督目标

本文问题属于“代码生成中的视觉美学评估”，其通用流程通常以渲染图像与参考图像的像素相似度或 VLM 整体评分作为奖励。本文的关键差异在于：引入设计图（Design Graph）作为结构化监督目标，将视觉目标解耦为节点（元素）与边（关系），使每个属性可独立归因。

设计图定义为 $G_{tgt} = (V, E, X_V, r) = \Phi(p, I_{ref})$，其中 $V$ 为元素节点，$E$ 为关系边，$X_V$ 为属性集合，$r$ 为画布根节点。该结构将提示 $p$ 的内容要求与参考图像 $I_{ref}$ 的视觉线索分离：节点属性记录内容（如文本字符串、图表数据）与视觉属性（如边界框、颜色），边定义层级包含与空间对齐。这种解耦使得监督信号可针对特定维度（如内容正确性 vs. 布局美观性）独立计算，避免了混合奖励导致的梯度混淆。

### 解耦跨模态奖励通道

基于设计图的属性可验证性差异，本文构建互补的跨模态奖励通道。对于代码与 DOM 中可解析的结构化属性（如文本存在性、图表数据），采用确定性验证器（Deterministic Verifiers）进行快速、绝对检查；对于需视觉判断的属性（如层级、排版、色彩），采用 VLM 作为裁判，通过视觉图评分标准（Visual Graph Rubric, VGR）进行细粒度评估。

VGR 将开放式视觉判断转化为绑定于设计图节点的布尔问题集合 $Q_{train}$。VLM 根据候选渲染图像 $\hat{I}$ 回答固定问题，其通过率为：

$$s_{vgr} = \frac{1}{|Q_{train}|} \sum_{q \in Q_{train}} \mathbb{I}[\hat{I} \text{ satisfies } q]$$

该公式将整体美学评分分解为节点级二元判断，避免了 VLM 整体评分的不稳定性与幻觉风险。设计图在此作为评分标准的脚手架，而非策略输入，确保评估的针对性。

### 组奖励解耦归一化策略优化

由于确定性验证器（密集、易饱和）与 VGR（稀疏、难优化）的奖励尺度与学习速率差异巨大，直接聚合会导致密集信号淹没稀疏美学反馈。本文采用组奖励解耦归一化策略优化（Group reward-Decoupled Normalization Policy Optimization, GDPO），对每个奖励通道独立归一化后再聚合优势函数。

对于第 $v$ 个奖励通道，其优势函数 $A_i^{(v)}$ 在适用子集 $B_v$ 上归一化：

$$A_i^{(v)} = \frac{s_i^{(v)} - \mu_v}{\sigma_v + \epsilon}$$

最终优势 $A_i$ 为所有适用通道归一化优势的加权平均。GDPO 确保每个目标（如文本正确性、布局美观性）在策略更新中贡献均衡，防止规则奖励的饱和抑制美学奖励的学习信号。

## 实验评估

实验在自建的 300 个提示的 Infographic 基准上进行，评估指标分为 Rule（规则验证：文本、边界、图表）与 Visual（VLM 评分：内容、布局、风格）。基线覆盖前沿闭源模型（GPT-5.5, Claude Opus 4.8）与开源 VLM（Qwen3-VL 系列）。AesCode-32B 在 Visual 得分上达到 75.80%，较其骨干 Qwen3-VL-32B（53.39%）提升 22.4 个百分点，接近 GPT-5.5（76.78%）与 Claude Opus 4.8（75.80%）的水平，同时在 Rule 得分上保持领先（95.34% vs. GPT-5.5 的 91.40%）。

| 模型 | Rule | Visual | Overall |
|---|---|---|---|
| GPT-5.5 | 91.40 | 76.78 | 84.09 |
| Claude Opus 4.8 | 90.07 | 75.80 | 82.94 |
| Qwen3-VL-32B | 62.55 | 34.67 | 48.61 |
| AesCode-32B | 95.34 | 75.80 | 85.89 |

消融实验验证了设计图与解耦奖励的必要性。移除 VGR 仅使用 Layout/Whitespace 奖励时，Visual 得分从 75.80% 降至 68.12%；使用整体 VLM 评分替代 VGR 时，Visual 得分降至 68.91%，表明细粒度布尔判断优于整体评分。GDPO 相比标量 GRPO 提升 Visual 得分 5.12 个百分点，证实了解耦归一化对平衡多目标学习的有效性。

评估边界方面，自建基准的 Visual 得分与人类判断的一致性虽经 50 个实例的迭代验证，但未报告与标准 IQA 基准（如 AGIQA-3K）的 SRCC 相关性，其泛化性存疑。此外，实验未覆盖计算效率指标，GDPO 的多通道归一化与 VLM 评分的推理开销未量化。

## 关联研究分析

从问题动机看，AesCode 与 ImageDoctor 均利用 MLLM 进行细粒度诊断，但 ImageDoctor 针对图像伪影的被动评估，而 AesCode 将评估信号主动嵌入代码生成的强化学习闭环，通过设计图将美学目标转化为可优化的奖励函数。这一差异源于任务特性：代码生成需同时满足结构可验证性与视觉主观性，而图像评估仅需输出诊断结果。

从方法设计看，AesCode 与 Q-Align 均将评分转化为离散判断，但 Q-Align 针对图像美学等级，AesCode 针对代码渲染的视觉属性。AesCode 引入设计图作为中间表示，使 VLM 评分绑定于具体元素与关系，解决了 Q-Align 在复杂布局中缺乏空间定位能力的问题。然而，AesCode 依赖参考图像作为美学先验，这与领域共识中的无参考（NR）评估范式相悖，可能引入参考图像中的美学偏见，论文未讨论该风险。

## 总结

AesCode 针对代码生成中视觉美学与内容正确性的解耦难题，提出以设计图为中间表示，通过确定性验证器与 VLM 细粒度评分构建解耦奖励，并采用 GDPO 平衡多目标学习。实验表明，AesCode-32B 在自建基准上 Visual 得分达 75.80%，较骨干模型提升 22.4 个百分点，接近前沿闭源模型水平。其边界在于依赖参考图像作为美学先验，可能继承生成模型的美学偏见，且自建基准的泛化性未经验证。当参考图像包含系统性美学缺陷时，AesCode 的解耦奖励机制能否有效抑制其负面影响，论文未给出回答。
