> 智能体性能受限于其执行层（Harness）的设计，但人工调优成本高且无法随模型更新而自适应。现有进化搜索方法因探索不足、策略僵化及单目标优化，难以在组合爆炸的设计空间中突破局部最优。MILO 通过层级谱系记忆保留失败证据、多智能体突变器隔离偏置，以及编排器动态重构搜索策略，实现了框架与搜索算法的协同进化。该方法在软件工程和数学问题上超越了手工设计框架，但其泛化性仍受限于特定基准分布。

## 研究背景

智能体（Agent）由大语言模型（LLM）与执行层（Harness）构成，后者负责控制流、工具调用及上下文管理。当模型固定时，Harness 的质量直接决定了智能体在长程任务中的表现。例如，在 Terminal-Bench 上，同一模型搭配不同 Harness，解决率可从 35.2% 波动至 49.6%，且 Token 消耗差异显著。这种“模型-框架”耦合特性意味着，针对特定模型优化的 Harness 在模型升级后往往失效，导致工程团队需反复进行人工调优。

当前自动化框架发现（AHD）主要依赖 LLM 驱动的进化搜索（ES）。主流路线分为实例级（如 FunSearch）与策略级（如 GEPA、Meta-Harness）。实例级方法仅优化单任务解，无法泛化；策略级方法虽优化求解器本身，但存在三大瓶颈：一是 LLM 突变器存在利用偏置，导致搜索空间多样性衰减；二是多数方法仅保留成功候选，忽略失败信息，造成样本效率低下；三是搜索策略（如父代选择、突变方式）通常预先固定，无法在停滞时自适应调整。此外，现有方法多仅优化准确率，忽视了 Token 消耗与延迟等成本指标。

MILO 的切入点在于将 Harness 发现建模为策略级进化问题，并引入元进化机制。它不再将搜索策略视为固定参数，而是将其作为可进化的对象，通过编排器（Orchestrator）在搜索停滞时动态修改记忆结构、突变器分配及课程学习策略，从而在保持多样性的同时实现高效探索。

## 核心方法

### 方法参照系

MILO 属于策略级进化搜索框架，其标准流程包括记忆存储、父代选择、突变生成及适应度评估。与通用进化算法不同，AHD 的搜索空间是无限可数的代码/配置空间，且评估成本极高（单次评估需数小时），这要求算法必须具备极高的样本效率与自适应能力。

### 层级谱系记忆与多目标适应度

传统 ES 方法（如 OpenEvolve）仅存储 Pareto 前沿上的幸存者，导致失败方向被重复探索。MILO 采用层级谱系记忆（Hierarchical Lineage Memory），将每个岛屿（Island）内的所有候选 Harness 组织为树状结构，保留被拒候选作为负证据。适应度函数定义为多目标向量，包含准确率、Token 经济性及延迟：

$$
F(h) = \left[ \text{Acc}(h, B_{\text{search}}), 1 - \frac{\text{Cost}_1(h)}{c_1}, \dots, 1 - \frac{\text{Cost}_q(h)}{c_q} \right]
$$

其中 $c_i$ 为固定任务上限。该设计使得候选 Harness 仅在推进 Pareto 前沿时才会被接纳，从而在提升准确率的同时抑制成本漂移。

### 元进化编排器与岛屿隔离

为解决 LLM 突变器的利用偏置，MILO 引入岛屿模型，每个岛屿由独立的突变器（Mutator Agent）驱动，岛屿间通过 Graft（嫁接）交换成功基因但不竞争生存。当某岛屿停滞超过阈值 $P$ 轮时，编排器（Orchestrator Agent）介入，执行诊断与干预：

$$
\omega = (\omega_1, \dots, \omega_l), \quad \omega_i \in \{ \text{Reassign}, \text{Graft}, \text{Speciate}, \text{Curriculum} \}
$$

编排器可重新分配突变器、跨岛嫁接、分裂新岛屿或调整搜索任务集（Curriculum）。这种自适应性使搜索策略本身随 Harness 共同进化，突破了固定策略的局部最优陷阱。

## 实验评估

实验在 Terminal-Bench 2.1、PaperBench 和 DeepSWE 上进行，对比了 8 个 SOTA 手工 Harness 和 6 个进化搜索方法。基线覆盖了 GEPA、EvoX、Meta-Harness 等代表性策略级方法，但未对比纯 RL 训练的 Agent（如 Search-R1），这可能限制了与训练派方法的直接比较。

| 方法 | TB2.1 RR@5 (%) | PaperBench RR@3 (%) | DeepSWE RR@3 (%) |
| :--- | :--- | :--- | :--- |
| Best-of-3 (Seed) | 74.1 ±2.4 | 26.7 ±6.0 | 59.0 ±3.8 |
| GEPA (Prompt) | 78.6 ±2.5 | 33.3 ±4.4 | 53.7 ±4.1 |
| Meta-Harness | 78.2 ±2.7 | 45.0 ±2.9 | 59.0 ±3.8 |
| MILO (Ours) | 86.1 ±2.0 | 55.0 ±5.0 | 69.3 ±3.4 |

在 Opus 4.8 骨干下，MILO 在 TB2.1 上比最佳基线高 7.9%，在 PaperBench 上高 10.0%。在开源骨干 gpt-oss-120b 上，MILO 在 DeepSWE 上达到 15.6%，是初始 Harness 的 20 倍，而先前搜索方法均低于 1%。

消融实验显示，移除编排器后，TB2.1 的 RR@5 从 86.1% 降至 80.5%；移除多岛屿机制后，降至 79.3%。这表明编排器的自适应干预与岛屿多样性保持是性能提升的关键。值得注意的是，MILO 在 4K 输出限制下仍保持 81.1% 的 RR@5，而手工 Harness 性能骤降至 20.2%–34.4%，证明其框架对模型弱点的补偿能力。

评估边界方面，论文未报告置信区间的完整分布，且 Frontier-Bench 测试仅验证了 TB2.1 进化 Harness 的迁移性，未验证跨模型（如从 Opus 到 GPT-5）的泛化性。代码未公开，但附录提供了种子 Harness 源码，可复现性中等。

## 关联研究分析

从问题动机看，MILO 与 GEPA 和 EvoX 均致力于策略级优化，但 GEPA 仅优化 Prompt，EvoX 虽自适应但限于实例级。MILO 的差异在于将搜索策略本身纳入进化对象，解决了策略僵化问题。这一设计源于 Harness 空间的组合爆炸特性，固定策略无法覆盖所有潜在结构。

从方法设计看，MILO 与 WebWeaver 等架构派方法不同，后者依赖显式多智能体协作，而 MILO 通过进化自动发现最优控制流。MILO 在 PaperBench 上低于 HiRAS（66.6% vs 55.0%），这可能因为 HiRAS 的层级多智能体分工更适合论文复现的细粒度任务，而 MILO 的通用框架在特定垂直领域缺乏针对性优化。

## 总结

MILO 解决了 Harness 设计中人工调优成本高且无法自适应模型更新的核心矛盾。其切入点在于将搜索策略与 Harness 协同进化，通过元进化编排器突破局部最优。实验证明，该方法在 TB2.1 上达到 86.1% 的解决率，且在开源模型上实现了数量级的性能提升。然而，其泛化性受限于特定基准分布，且在垂直领域（如 PaperBench）上未超越专用多智能体架构。当 Harness 进化至复杂控制流时，其可解释性与人工审计成本是否成为新的瓶颈，论文未给出回答。
