# HuggingFace最新推荐论文 ｜ParetoRSI-Gym: Can AI Agents Improve Language Models Across Multiple Domains? ｜多域递归自我改进评估基准

研究机构：美国伊利诺伊大学厄巴纳-香槟分校、美国加州大学伯克利分校

作者：Haojin Wang、Yangzhen Wu、Zeyi Chen 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.34386)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.34386)

> 递归自我改进（RSI）要求智能体自主设计、训练并评估后继模型，但现有评估多局限于单域静态数据池，无法反映真实后训练中多能力权衡与动态数据获取的复杂性。PARETORSI-GYM 将评估场景扩展至数学、代码等五个领域，引入动态数据源搜索与泛化基准分离机制，以量化智能体在多目标帕累托前沿上的探索能力。该基准通过多轮反馈驱动的数据策展循环，揭示了当前智能体在维持已获能力与探索新能力之间的显著瓶颈。其价值在于构建了贴近工程现实的 RSI 评估体系，但智能体在长程迭代中的状态漂移与成本效率缺失仍是待解的开放问题。

## 研究背景

当智能体试图通过自动化后训练实现递归自我改进时，其核心挑战在于如何从海量非结构化数据中筛选出能提升模型特定能力的样本。这一过程通常被建模为数据策展（Data Curation），即智能体根据目标基准的反馈，动态调整数据选择策略。然而，传统评估框架如 PostTrainBench 往往假设数据池是静态且预定义的，智能体仅需从中挑选子集。这种设定忽略了真实工程中数据源的不确定性，且仅关注单一基准分数的提升，导致评估结果无法反映模型在多领域能力上的权衡。

随着大语言模型（LLM）智能体能力的增强，研究焦点从单轮静态筛选转向多轮动态优化。现有方法如 RSIBench-Data 虽引入了迭代改进，但仍局限于单域目标，未能捕捉多域能力之间的相互干扰。真实后训练场景要求模型在数学、代码、医疗等多个领域同时提升，任何单一领域的过度优化都可能导致其他领域的性能退化。因此，亟需一种能够评估智能体在多域帕累托前沿上探索能力的基准，以区分真正的能力泛化与对反馈信号的过拟合。

## 核心方法

### 多域反馈驱动的数据策展循环

PARETORSI-GYM 将数据策展建模为一个多轮迭代循环，智能体在每一轮中执行搜索、选择、拉取、训练和评估五个步骤。与通用智能体评估中关注任务执行轨迹不同，该基准关注的是数据选择与训练配置决策轨迹。智能体维护三个跨轮状态对象：模型池 $\mathcal{M}$、数据池 $\mathcal{P}$ 和书面原则 $\mathcal{R}$。每一轮，智能体基于当前原则 $\mathcal{R}_t$ 和预算 $\beta_t$，从 HuggingFace Hub 动态搜索数据，更新数据池 $\mathcal{P}_t$，并选择模型池中的父模型进行 LoRA 微调。

该设计的核心动机在于模拟真实后训练中的状态依赖性与资源约束。传统方法通常假设智能体拥有全局最优的数据视图，而 PARETORSI-GYM 强制智能体在有限预算下基于局部反馈进行决策。智能体接收的反馈不仅包含各领域的代理基准分数，还包含详细的评估轨迹，使其能够诊断失败原因并重写原则。这种机制迫使智能体在探索新数据源与利用已验证数据之间进行权衡，从而评估其长期规划能力。

### 泛化分离与帕累托前沿评估

为区分能力增益与反馈过拟合，PARETORSI-GYM 严格分离代理基准 $\mathcal{T}_p$ 与泛化基准 $\mathcal{T}_g$。代理基准用于在循环中提供即时反馈，而泛化基准在运行期间对智能体完全隐藏，仅在最终评估时用于报告性能。智能体的优化目标不是最大化单一领域的分数，而是推进能力向量 $\mathbf{s}_t = \mathcal{T}_p(M_t)$ 的帕累托前沿。

$$
\text{Objective: } \max \mathcal{F}(\mathbf{s}_t) \quad \text{s.t.} \quad \mathbf{s}_t \succeq \mathbf{s}_{t-1} \text{ (Pareto Improvement)}
$$

该公式表示智能体应寻求在至少一个领域提升且其他领域不下降的帕累托改进。评估时，报告最终轮次模型、代理最佳轮次模型以及各域最佳轮次模型（Oracle）的性能。通过比较代理最佳与泛化最佳之间的差距，量化智能体对反馈信号的过拟合程度。这一设计解决了现有基准中因反馈与评估同源导致的评估失真问题，确保评估结果反映的是模型在未见数据上的真实泛化能力。

## 实验评估

实验在三个基础模型（Qwen3-4B-Base, Ministral-3-3B, Olmo-3-1025-7B）上评估了三种智能体系统（Claude Code, Codex, CheetahClaw）。基线覆盖涵盖了主流闭源与开源智能体框架，但未包含专用数据策展智能体。主结果显示，Claude Code 在代理最佳检查点上平均提升 +2.3 点，相对提升 9.2%，而 CheetahClaw 平均下降 -0.3 点。

| 基础模型 | 智能体系统 | 检查点类型 | 数学 | 科学 | 医疗 | 金融 | 代码 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen3-4B-Base | Claude Code | M0 (无策展) | 65.33 | 31.94 | 39.36 | 24.50 | 65.03 |
| Qwen3-4B-Base | Claude Code | 代理最佳 | 60.97 | 33.33 | 43.69 | 24.50 | 71.93 |
| Ministral-3-3B | Claude Code | M0 (无策展) | 38.92 | 27.65 | 23.65 | 17.62 | 26.69 |
| Ministral-3-3B | Claude Code | 代理最佳 | 34.64 | 29.00 | 38.46 | 19.63 | 39.26 |

消融分析表明，智能体系统间的数据选择策略差异显著，同一智能体不同运行间的 Jaccard 重叠度仅为 0.24，而不同智能体间仅为 0.07。此外，固定骨干模型仅改变脚手架（Harness）时，性能差异从 +4.3 点到 +0.2 点不等，证实了脚手架设计对自主后训练性能的关键影响。

评估边界方面，该基准未报告 Token 消耗与 API 成本，与领域共识中“成本作为一级指标”的要求存在偏差。此外，智能体在长程迭代中表现出显著的状态漂移，45 个设置中有 24 个在后续轮次中性能下降，且 43/45 的模型-域组合中，代理最佳轮次并非泛化最佳轮次，揭示了当前智能体在维持帕累托前沿上的能力不足。

## 关联研究分析

从问题动机看，PARETORSI-GYM 与 PostTrainBench 均关注自动化后训练，但 PostTrainBench 局限于单域静态数据池，无法评估多域权衡。PARETORSI-GYM 通过引入动态数据源与多域目标，填补了从单域优化到多域帕累托探索的评估空白。这一差异源于任务特性的根本不同：前者关注数据筛选效率，后者关注多目标决策能力。

从方法设计看，PARETORSI-GYM 与 RSIBench-Data 均采用迭代反馈机制，但 RSIBench-Data 依赖静态数据池，而 PARETORSI-GYM 强制智能体实时搜索 HuggingFace。这一设计选择反映了真实工程中数据获取的不确定性，但也引入了环境噪声对评估稳定性的潜在影响。智能体在搜索过程中的探索策略是否受限于 HuggingFace 的索引质量，论文未给出回答。

## 总结

PARETORSI-GYM 针对现有 RSI 评估中单域静态假设与多域动态现实之间的矛盾，构建了首个支持动态数据源与泛化分离的多域数据策展基准。通过多轮反馈驱动循环，该基准量化了智能体在数学、代码等五个领域的帕累托前沿探索能力。实验表明，最强智能体 Claude Code 仅实现 +2.3 点的平均泛化提升，且多数情况下代理最佳轮次并非泛化最佳轮次，揭示了当前智能体在长程迭代中维持能力平衡的显著瓶颈。该基准的边界在于未纳入成本效率评估，且智能体在长程任务中的状态漂移机制尚未被充分解析。当智能体在后续轮次中因探索新数据而牺牲已获能力时，如何量化这种探索-利用权衡对最终泛化性能的具体贡献，仍是一个待验证的问题。
