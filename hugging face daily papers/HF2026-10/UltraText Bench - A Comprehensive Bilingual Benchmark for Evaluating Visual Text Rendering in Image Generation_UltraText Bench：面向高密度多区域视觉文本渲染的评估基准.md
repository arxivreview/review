> 导读 视觉文本渲染的核心矛盾已从短字符串的拼写正确性，转向高密度、多区域场景下的持续渲染保真度与场景融合能力。现有评估基准多依赖OCR或单一VLM评分，难以区分字符错误、布局偏差与载体融合失败，且无法处理数千字符的密集文本负载。本文提出UltraText Bench，构建包含432个双语提示词、24种场景类别的基准，并设计基于Q-Judger的六维评分体系，将文本准确性、完整性、可读性、位置、布局及场景整合度解耦为四个报告维度。该基准填补了密集文本渲染评估的空白，揭示了加速模型在清晰度与保真度间的权衡，但Q-Judger在长文本下的幻觉率及结构化参考的人工标注偏差仍需独立验证。

## 研究背景

当生成模型面对包含数十个文本区域的复杂场景时，局部文本的正确渲染往往掩盖了整体布局的崩溃或载体融合的失败——这一现象称为“局部成功掩盖全局失败”。传统评估依赖OCR识别或CLIPScore等全局指标，前者在密集文本下易受字体、尺度干扰，后者无法捕捉字符级错误。为解决此问题，视觉语言模型（Vision-Language Model, VLM）作为评判者（VLM-as-Judge）被引入，通过自然语言描述评估图像语义，但其缺乏对文本位置、载体属性及完整性的结构化约束，导致评分与人类感知存在偏差。

视觉文本渲染领域正经历从“短字符串拼写”向“文档级持续渲染”的范式转移。早期基准如MARIO-Eval和AnyText-Bench聚焦短关键词或单行文本，CVTG-2K和LongText-Bench虽扩展至多实例和长文本，但评估协议仍依赖OCR匹配或VLM文本提取，未将文本与物理载体（如招牌、屏幕）及空间布局解耦。InfoTextBench虽引入双语密集文本，但其评估仍侧重词级精度与召回，缺乏对文本-载体整合度的细粒度诊断。本文针对这一缺口，提出UltraText Bench，将评估焦点从“文本是否存在”转向“文本是否在正确载体上以正确布局完整呈现”，以应对海报、包装、界面等真实应用场景的需求。

## 核心方法

### 评估协议参照系

视觉文本渲染评估的通用流程为：生成图像后，通过OCR或VLM提取文本，与目标字符串进行匹配计算准确率。该流程的关键缺陷在于将文本视为孤立字符串，忽略了其在图像中的空间位置、载体属性及视觉清晰度。本文问题与该通用流程的关键差异在于：评估对象不仅是字符序列，而是“文本-位置-载体-场景”的四元组，且需在数千字符负载下保持评估稳定性。

### 结构化参考与六维评分体系

针对通用流程中评估维度单一的问题，本文设计了基于结构化Ground Truth（GT）的六维评分体系。通常做法仅提供目标字符串列表，而本文的GT包含每个文本区域的ID、文本内容、位置（$3 \times 3$网格）、尺寸、类型、载体及重要性。Q-Judger模型接收图像与完整GT参考，输出六个0-100分的原始评分：文本准确性（TA）、完整性（TC）、可读性（TR）、位置正确性（PC）、布局质量（LQ）及场景整合度（SI）。

该设计解决了OCR无法评估“未渲染区域”及VLM无法区分“拼写错误”与“模糊不清”的失效。六个原始分数映射为四个报告维度，其计算公式为：

$$
\text{Fidelity} = 0.5 \cdot \text{TA} + 0.5 \cdot \text{TC}
$$

$$
\text{Spatial} = 0.5 \cdot \text{PC} + 0.5 \cdot \text{LQ}
$$

其中，Fidelity（保真度）权重60%，Clarity（清晰度，即TR）权重30%，Spatial（空间质量）与Scene（场景质量，即SI）各占5%。该加权机制将文本正确性置于核心，同时保留清晰度与空间布局的独立诊断能力，避免单一标量掩盖特定维度的失败。

### 双语密集负载与场景覆盖

为测试模型在极端负载下的持续渲染能力，本文构建了24种场景类别、3个难度等级（L1-L3）的双语数据集。通常基准仅覆盖单一语言或低密度文本，而本文在L3级别要求英文提示词平均包含2386.68个字符、9.38个区域，中文平均包含743.62个字符、8.40个区域。

该设计解决了现有基准无法区分“长文本单区域”与“多区域分散文本”的局限。通过强制模型在物理载体（如菜单、收据）和数字界面（如网页、仪表盘）上同时渲染多个独立文本块，评估协议能够捕捉文本在跨载体迁移时的性能衰减，以及高密度负载下注意力机制的崩溃模式。

## 实验评估

实验在UltraText Bench上评估了24种模型配置，涵盖FLUX、Stable Diffusion、Qwen-Image等主流骨干网络。基线审计显示，对比方法覆盖了通用T2I模型与部分加速变体，但未包含AnyText、GlyphControl等专用文本渲染模型，这可能低估了通用模型与专用模型在字符级保真度上的差距。

| 模型配置 | 语言 | 难度 | 综合得分 | 保真度 | 清晰度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Qwen-Image-2512 | EN | L1 | 86.50 | - | - |
| Qwen-Image-2512 | EN | L3 | 42.86 | - | - |
| Z-Image-Turbo | - | - | - | - | +3.81 |
| Z-Image-Base | - | - | - | - | - |

*注：表中数值取自论文摘要及正文描述。Z-Image-Turbo清晰度提升3.81分，但保真度下降14.76分。*

消融分析揭示了加速策略与文本保真度的负相关。Z-Image-Turbo在清晰度上较Base版本提升3.81分，但保真度下降14.76分，表明加速采样在保留文本细节时牺牲了字符准确性。Qwen-Image-2512的英文综合得分从L1的86.50骤降至L3的42.86，证实了模型在文本负载超过2000字符时存在显著的性能断崖。

评估边界方面，Q-Judger的评分依赖结构化GT，但GT的人工标注可能引入偏差。此外，评估协议未报告Q-Judger在数千字符输入下的幻觉率，且缺乏与专用文本渲染模型的直接对比，限制了结论的普适性。

## 关联研究分析

从评估范式看，UltraText Bench与PSG-Score均使用结构化参考进行细粒度评估，但PSG-Score侧重对象间的语义关系匹配，而UltraText Bench侧重文本与物理载体的融合。这一差异源于任务特性：文本渲染要求字符级精确复现，而场景图评估容忍语义近似。UltraText Bench引入载体属性作为评分依据，解决了PSG-Score无法诊断“文本悬浮于背景”这一特定失效模式的问题。

从模型优化路线看，本文与GenPilot等提示词优化方法形成互补。GenPilot通过测试时搜索提升复杂提示词的语义对齐，但未涉及字符级渲染；UltraText Bench则提供了评估字符级保真度的标尺。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但UltraText Bench的低分结果暗示，仅靠提示词优化无法解决模型在密集文本下的根本性渲染缺陷，需结合模型端改进。

## 总结

本文针对视觉文本渲染评估中“局部成功掩盖全局失败”的矛盾，提出UltraText Bench，通过结构化GT与六维评分体系解耦文本准确性、布局与场景融合。实验证明，Qwen-Image-2512在L3负载下综合得分降至42.86，Z-Image-Turbo在清晰度提升3.81分的同时保真度下降14.76分，揭示了加速与保真的权衡。本文边界在于未对比专用文本渲染模型，且Q-Judger在长文本下的幻觉率未经独立人工校验。当评估参考包含数千字符时，VLM评判者是否会因上下文溢出而系统性高估完整性，论文未给出回答。
