> 智能体训练正从模仿人类演示转向在可执行环境中进行强化学习，但真实计算机环境的重置困难、状态漂移及探索风险构成了数据供给瓶颈。现有合成方法多局限于单一应用或单一交互界面，且依赖专有模型，难以支撑跨界面、长程任务的泛化训练。WildAWM 提出了一种基于开源模型的端到端合成管线，通过构建包含图形用户界面（GUI）、命令行界面（CLI）和模型上下文协议（MCP）服务的多日累积世界状态，生成具备高保真度与可验证性的跨界面任务。该工作证明了纯开源模型可合成高质量训练环境，显著提升了智能体在分布外基准上的表现，但其合成环境的多样性上限及跨界面状态一致性验证机制仍需进一步审视。

## 研究背景

当智能体需要在个人计算机上完成复杂任务时，其操作往往跨越多个界面：在浏览器中查看信息、在终端中运行脚本、或通过 API 调用服务。这种跨界面交互要求智能体具备灵活的动作空间选择与状态保持能力。然而，直接在真实操作系统中训练智能体面临巨大挑战：环境状态难以精确重置，在线服务随时间变化，且探索性动作可能引发不可逆的安全风险。为解决这一问题，研究者转向构建合成环境，但现有方法通常仅支持单一界面（如仅 GUI 或仅 CLI），导致智能体在需要界面切换的长程任务中缺乏训练信号。

合成环境的构建还面临“可解性”与“难度”的平衡难题。若任务过于简单，无法提供有效的强化学习梯度；若任务不可解，则导致训练崩溃。此外，现有合成管线多依赖 GPT-4 等专有模型，限制了开源社区的复现与扩展。WildAWM 针对上述痛点，提出利用开源模型构建支持 GUI、CLI 和 MCP 联合交互的 PC 级世界模型，并通过执行式质量门控确保合成任务的可解性与挑战性，旨在为通用计算机使用智能体（Computer-Use Agents, CUAs）提供可扩展、可控且开源的训练数据供给方案。

## 核心方法

### 多日累积世界状态构建

WildAWM 将环境定义为个人计算机的累积状态，包含 Web 应用、MCP 服务和本地文件。与传统静态快照不同，该框架通过“Persona-Driven”机制生成多日连续的世界状态 $W(c, d)$，其中 $c$ 代表用户画像，$d$ 代表天数。设计动机在于解决长程任务中历史上下文缺失导致的接地误差。生成器首先创建包含职业、联系人及多日故事线的用户画像，随后逐日规划活动。每一天的状态 $W(c, d)$ 基于前一日状态 $W(c, d-1)$ 通过确定性脚本增量更新，确保时间戳、ID 及密码哈希的确定性。这种累积机制使得任务可以依赖早期生成的数据（如聊天记录、文件），迫使智能体在长程交互中保持状态一致性，而非仅依赖当前观测。

### 跨界面任务合成与质量门控

在环境构建基础上，WildAWM 生成跨 GUI、CLI 和 MCP 的任务 $\tau$。为确保任务质量，引入了五重执行式质量门控：可解性、难度、验证器可靠性、初始状态不满足性及反事实探针。其中，可解性门控通过异构智能体池（24 种模型-工具组合）进行 rollout 验证，要求至少一个智能体成功解决任务。难度门控则要求任务不能过于简单，即不能所有智能体都能轻易解决。验证器可靠性通过对比多个 LLM 裁判的一致性来保证。这一设计解决了传统合成任务中常见的“假阳性”问题，即任务看似可解但实际因环境噪声或逻辑漏洞导致无法完成。

### 基于 GRPO 的密集奖励强化学习

利用合成环境进行训练时，WildAWM 采用组相对策略优化（Group Relative Policy Optimization, GRPO）算法。针对长程任务中奖励稀疏的问题，设计了结合最终结果与检查表分数的密集奖励机制。对于第 $j$ 个 rollout，若格式错误则奖励 $r_j = -1$；否则，奖励由任务完成状态与检查表得分 $v_i$ 加权组合：

$$
r_j = \begin{cases}
-1 & \text{if } e_j = 1 \\
\frac{1}{N} \sum_{i=1}^{N} v_i & \text{if } e_j = 0 \text{ and task incomplete} \\
1 & \text{if } e_j = 0 \text{ and task complete}
\end{cases}
$$

该公式的物理含义是：在任务未完成时，通过检查表提供部分学分，为长程轨迹提供中间梯度信号；任务完成时给予单位奖励。此外，为解决小模型训练中常见的零方差问题，引入了指数移动平均估计的 rollout 乘数，动态调整采样组大小，确保奖励分布的多样性，从而稳定策略更新。

## 实验评估

实验在 8 个分布外（OOD）基准上进行，涵盖 Web、Claw 和计算机使用智能体任务，包括 WebArena、Online-Mind2Web、OSWorld 等。基线对比覆盖了前沿闭源模型（GPT-6, Claude Opus）及开源基线（Qwen 系列）。WildAWM 训练后的 Qwen3.6-35B-A3B 模型在平均得分上从 42.84 提升至 53.42，显著缩小了与前沿模型的差距。

| Qwen3.6 (Base) | 69.60 | 53.54 | 57.86 | 38.00 | 53.73 | 33.16 | 13.22 | 23.57 | 42.84 |
| **WildAWM-35B** | **80.77** | **67.26** | **61.44** | **54.67** | **65.95** | **49.22** | **21.73** | **26.31** | **53.42** |

WildAWM-35B 在 Online-Mind2Web 上达到 80.77%，超越 GPT-5.5（72.22%），并在 WebArena 上与 GLM-5.2 持平（67.26%）。这一结果表明，在合成环境中训练的开源模型具备强大的跨域泛化能力。消融实验显示，移除 SFT 阶段或 RL 阶段均会导致性能显著下降，验证了“SFT 预热 + RL 精调”两阶段训练策略的必要性。此外，合成任务的难度分布显示，即使对于 GPT-6-Astra，仍有 27.3% 的任务在 8 次尝试后失败，证明合成环境提供了足够强的训练信号。

评估边界方面，实验主要依赖 LLM 作为裁判（GPT-5.5）进行部分基准的评分，可能存在裁判偏差。尽管提供了代码和模型，但合成环境的多样性受限于开源模型（GLM-5.2）的生成能力，且多日状态累积带来的计算开销未详细量化。

## 关联研究分析

从问题动机看，WildAWM 与 WebWorld 均致力于通过世界模型解决数据稀缺问题，但 WebWorld 主要聚焦于 Web 域的单界面交互，而 WildAWM 扩展至 PC 级多界面（GUI+CLI+MCP）。这一差异源于任务特性的不同：Web 任务通常局限于浏览器内，而通用计算机任务需要跨应用协作。WildAWM 通过引入 MCP 服务和 CLI 工具，填补了 Web 智能体在系统级操作上的空白，但也引入了跨界面状态同步的复杂性，这是 WebWorld 未涉及的盲区。

从方法设计看，WildAWM 与 CUA-Gym 同属合成环境路线，但 CUA-Gym 依赖专有模型（如 Claude Opus）进行合成，而 WildAWM 证明纯开源模型（GLM-5.2）可生成高质量环境。这一突破降低了训练门槛，但可能牺牲了部分复杂逻辑的生成质量。WildAWM 引入的“反事实探针”门控机制，通过注入相反判决来测试验证器的鲁棒性，这一设计在 CUA-Gym 中未见体现，反映了 WildAWM 对合成数据噪声控制的更细致考量。

## 总结

WildAWM 针对通用计算机使用智能体训练中真实环境不可控与合成环境单一化的矛盾，提出了基于开源模型的多日累积世界状态合成框架。通过构建支持 GUI、CLI 和 MCP 的跨界面环境，并引入执行式质量门控与密集奖励强化学习，该工作在 8 个分布外基准上实现了显著性能提升，其中 Qwen3.6-35B-A3B 平均得分提升 10.58 点，在 Online-Mind2Web 上达到 80.77%。然而，该方法的边界在于合成环境的多样性受限于开源生成模型的能力，且多日状态累积带来的计算成本与状态一致性验证的复杂度尚未完全优化。当合成环境的规模进一步扩大时，开源模型生成的任务逻辑一致性是否会因上下文长度限制而下降，仍需进一步验证。
