# HuggingFace最新推荐论文 ｜Can Test-Time Memory Evolution Outperform Test-Time Training for Scientific Discovery? ｜测试时记忆演化

作者：Yepeng Liu、Shengmai Chen、Xuandong Zhao 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2610.32046)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2610.32046)

> 导读 科学发现任务中，测试时训练（Test-Time Training, TTT）通过在线强化学习更新模型权重以内化搜索经验，但计算成本高昂且难以扩展至大模型。现有方法在参数内化与计算效率之间面临两难：固定权重模型无法利用累积经验，而权重更新则引入巨大开销。本文提出测试时记忆演化（TTME），将搜索经验蒸馏为外部记忆模块，在保持模型权重固定的前提下引导后续搜索。该机制通过双记忆模块分离操作指南与算法策略，实现了非参数化的测试时适应。TTME 在多个数学构造任务上超越了 TTT 基线，同时大幅降低计算成本，挑战了“测试时适应必须依赖权重更新”的隐含假设，但其有效性是否受限于特定任务结构仍待验证。

## 研究背景

当大语言模型（Large Language Models, LLMs）应用于科学发现时，其核心挑战在于如何从迭代搜索的失败与成功中高效学习。早期方法如 FunSearch 和 AlphaEvolve 依赖固定权重模型生成候选解，利用评估反馈指导搜索，但缺乏对累积经验的系统性内化，导致搜索效率受限。为解决这一问题，测试时训练（TTT）框架（如 TTT-Discover 和 ThetaEvolve）引入在线强化学习（Reinforcement Learning, RL），将评估后的搜索尝试作为训练数据更新模型权重。这种参数化适应使开源模型在特定任务上超越了仅依赖推理的前沿模型系统。

然而，TTT 的核心瓶颈在于其计算经济性。在线权重更新需要在整个发现过程中持续进行，即使仅更新低秩适配（Low-Rank Adaptation, LoRA）参数，其运行时和浮点运算次数（Floating Point Operations, FLOPs）仍显著高于纯推理过程。这限制了 TTT 向更大规模模型和更复杂发现任务的扩展。与此同时，领域共识指出，LLM 已具备广泛的基础知识和推理能力，可能无需通过权重更新即可利用外部经验。这一观察构成了本文的切入点：在保持模型权重固定的约束下，通过演化外部记忆结构来替代参数内化，是否能在科学发现任务中实现更优的精度-成本权衡？

## 核心方法

### 方法参照系：测试时适应的两种范式

在科学发现的迭代搜索框架中，适应机制通常分为参数化与非参数化两类。参数化适应通过更新模型参数 $\theta$ 来内化经验，形式化为 $\theta_{t+1} \leftarrow U_{\text{RL}}(\theta_t, D_t)$，其中 $D_t$ 为评估后的搜索记录。非参数化适应则保持 $\theta$ 固定，通过更新外部状态 $M$ 来影响生成上下文，形式化为 $M_{t+1} \leftarrow U_{\text{mem}}(M_t, D_t)$。TTME 属于后者，其关键差异在于将外部状态结构化为两个互补的记忆模块，分别处理实施层面的操作教训与算法层面的策略组合，而非简单的经验回放或提示工程。

### 双记忆模块：操作指南与算法策略的解耦

TTME 将搜索经验分解为两类互补信息，分别存储于 Guideline Memory 和 Strategy Memory。Guideline Memory 存储从执行和评估反馈中蒸馏出的共享操作指南，旨在解决实施层面的可靠性问题。每 $K$ 个搜索步骤，系统汇总结果 $r_t$，通过蒸馏函数生成新指南 $G_t$，并维护现有记忆：

$$
G_t \leftarrow \text{Distill}(r_t, L_t), \quad L_{t+1} \leftarrow \text{Maintain}(L_t, G_t, t)
$$

该公式表明，指南更新是一个基于现有记忆 $L_t$ 和新证据 $r_t$ 的增量过程。$\text{Maintain}$ 操作通过匹配现有条目来更新复发计数或添加新条目，并基于复发计数和时效性执行容量限制。这一设计解决了固定提示无法动态适应实施陷阱的问题，使模型能避免重复已知的实现错误。

Strategy Memory 则存储可复用的算法策略，旨在促进不同搜索尝试间的思想组合。系统从分数提升的修改中提取经验笔记 $E_t$，并将其整合为策略族：

$$
E_t \leftarrow \text{Extract}(D_t^+), \quad S_{t+1} \leftarrow \text{Consolidate}(S_t, E_t)
$$

其中 $D_t^+$ 为产生有效且高分结果的修改案例。$\text{Consolidate}$ 将新笔记分配至现有或新策略族，更新策略内容。这一机制解决了传统搜索中算法思想孤立、难以跨候选解迁移的问题，使模型能识别并复用有效的算法模式。

### 策略引导生成：从记忆到候选解的映射

在候选生成阶段，TTME 通过策略引导搜索将记忆转化为具体的修改指令。对于每个父程序，系统从 Strategy Memory 中选择最多 $N$ 个潜在改进策略，并生成父程序特定的修改指令 $d_{i,n}^{(t)}$：

$$
d_{i,n}^{(t)} = \begin{cases} \text{Adapt}(C_i^{(t)}, S_t[a_{i,n}^{(t)}]) & \text{if } a_{i,n}^{(t)} \neq \emptyset \\ \text{Propose}(C_i^{(t)}, S_t) & \text{if } a_{i,n}^{(t)} = \emptyset \end{cases}
$$

该公式定义了两种生成路径：若选中策略，则通过 $\text{Adapt}$ 将策略适配至当前父程序上下文 $C_i^{(t)}$；若未选中，则通过 $\text{Propose}$ 基于记忆提出新想法。最终候选解通过混合直接生成与策略引导生成产生，其中直接生成占比 $\alpha=1/2$。这一设计解决了纯策略引导可能导致的探索不足，以及纯直接生成无法利用累积算法经验的问题，实现了利用与探索的平衡。

## 实验评估

实验在 TTT-Discover 和 ThetaEvolve 两个框架下，针对 Erdős、AC1、AC2、AC3 和 Hadamard 五个数学构造任务进行评估。基线包括无适应（w/o TTT）和测试时训练（w/ TTT）。TTME 在所有评估设置中均超越了 TTT 基线，且无需更新模型权重。

| 方法 | 模型 | AC1 ↓ | AC2 ↑ | Erdős ↓ |
| :--- | :--- | :--- | :--- | :--- |
| TTT-Discover (w/ TTT) | Qwen3-8B | 1.50525 | 0.9472 | 0.380932 |
| TTT-Discover (w/o TTT) | Qwen3-8B | 1.505242 | 0.944771 | 0.380957 |
| Ours (w/ TTME) | Qwen3-8B | 1.504329 | 0.949248 | 0.380927 |

在 TTT-Discover 框架下，TTME 在 AC2 上达到 0.949248，高于 TTT 的 0.9472；在 Erdős 上达到 0.380927，优于 TTT 的 0.380932。这一结果证明，外部记忆演化在特定数学构造任务上能比参数内化产生更优的搜索引导。

消融实验验证了双记忆模块的必要性。移除 Guideline Memory 或 Strategy Memory 均导致性能下降，且两者结合的效果优于单独使用。此外，将 TTME 与 TTT 结合并未带来进一步增益，反而在某些任务上降低了性能，表明记忆演化与权重更新在功能上存在冗余或冲突。

| 配置 | AC1 ↓ | AC2 ↑ | Erdős ↓ |
| :--- | :--- | :--- | :--- |
| Full TTME | 1.502745 | 0.960784 | 0.380862 |
| w/o Guideline Memory | 1.505644 | 0.958506 | 0.380865 |
| w/o Strategy Memory | 1.505981 | 0.956493 | 0.380864 |
| w/o TTME | 1.505966 | 0.953682 | 0.380946 |

在效率方面，TTME 显著降低了计算成本。在 Qwen3-8B 上，TTME 相比 TTT 减少了 47.7–58.4% 的运行时和 82.8–84.6% 的 FLOPs。这一效率优势源于避免了在线 RL 训练，仅依赖推理时的记忆更新操作。

| 任务 | 模型 | TTT 运行时 (h) | TTME 运行时 (h) | 减少比例 | TTT FLOPs (EFLOPs) | TTME FLOPs (EFLOPs) | 减少比例 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| AC1 | Qwen3-8B | 11.76 | 5.36 | 54.5% | 29.47 | 4.53 | 84.6% |
| AC2 | Qwen3-8B | 12.73 | 6.66 | 47.7% | 33.09 | 5.69 | 82.8% |
| Erdős | Qwen3-8B | 11.67 | 4.85 | 58.4% | 26.21 | 4.15 | 84.2% |

评估边界方面，实验仅覆盖了数学构造任务，未涉及代码生成或科学假设验证等更广泛的发现场景。此外，记忆模块的容量限制和检索机制对性能的影响未进行敏感性分析，可能构成潜在瓶颈。

## 关联研究分析

从适应机制看，TTME 与 TTT-Discover 和 ThetaEvolve 形成直接对比。TTT 框架通过 RL 将经验内化至权重，隐含假设是模型参数容量足以存储复杂搜索策略。TTME 则挑战了这一假设，认为外部记忆的结构化组织（分离操作与策略）能更有效地利用 LLM 的上下文学习能力。这一差异的根源在于任务特性：数学构造任务具有明确的验证器和可解释的算法结构，使得经验易于蒸馏为文本化指南；而在噪声更大或验证器不明确的科学发现任务中，文本化记忆可能无法捕捉权重更新所能内化的隐式模式。

从搜索策略看，TTME 与 FunSearch 和 AlphaEvolve 等非参数化方法存在关联，但引入了自演化记忆。FunSearch 等方法依赖静态提示或简单的候选池管理，缺乏对累积经验的系统性蒸馏。TTME 的 Strategy Memory 通过策略族整合不同修改案例，实现了算法思想的跨候选解迁移。这一设计是否依赖于数学任务中算法模块的清晰边界，而在连续优化或高维搜索中失效，论文未给出回答。

## 总结

本文针对科学发现中测试时训练计算成本高昂的问题，提出测试时记忆演化（TTME），通过外部记忆模块替代权重更新。TTME 将搜索经验解耦为操作指南与算法策略，在保持模型权重固定的前提下引导搜索。实验表明，TTME 在五个数学构造任务上超越了 TTT 基线，同时降低了 82.8–84.6% 的 FLOPs。这一结果证明了非参数化适应在特定任务上的有效性，但其优势可能受限于任务的可解释性和验证器的可靠性。当搜索空间缺乏清晰的算法结构或评估反馈噪声较大时，文本化记忆是否仍能比参数内化提供更有效的引导，论文未给出回答。
