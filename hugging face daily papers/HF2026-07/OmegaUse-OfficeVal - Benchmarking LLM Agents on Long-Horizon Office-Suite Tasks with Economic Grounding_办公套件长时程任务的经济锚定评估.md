# HuggingFace最新推荐论文 ｜OmegaUse-OfficeVal: Benchmarking LLM Agents on Long-Horizon Office-Suite Tasks with Economic Grounding ｜办公套件长时程任务的经济锚定评估

论文原文见 [arXiv](https://arxiv.org/abs/2607.27155)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.27155)

> 现有智能体评估体系难以量化办公交付物的真实经济价值与可用性，导致实验室分数无法映射至实际生产力。OmegaUse-OfficeVal 通过引入任务级人力时间与价格代理，将成本与质量纳入同一评估框架。该基准采用代码验证器替代主观评判，确保长时程办公任务评估的稳定性与可复现性。其核心价值在于揭示了当前大语言模型在交付物质量上仍显著落后于人类，但具备显著的成本与速度优势，为“Vibe Working”的落地提供了量化标尺。

## 研究背景

当智能体从代码生成转向处理 Word、Excel 和 PPT 等办公文档时，评估的核心难点从“代码可执行性”转变为“交付物可用性”。办公任务通常缺乏唯一标准答案，且涉及复杂的格式约束与内容逻辑，传统基于精确匹配或单一状态断言的评估方法在此类非结构化输出中失效。这种评估盲区导致无法区分智能体是完成了任务还是仅生成了看似合理的文本，进而无法衡量其替代人类劳动的真实经济价值。

通用生产力基准如 GDPVal 和 RLI 虽涉及经济价值，但仅关联宏观职业类别，缺乏单任务粒度的成本标注；办公自动化基准如 OfficeBench 多聚焦于短视距的合成操作，忽视长时程任务的复杂性；GUI 智能体基准如 OSWorld 2.0 侧重交互过程而非最终交付物质量。这些现有方案均未能回答“智能体能否以可接受的成本交付正确且可用的办公成果”这一核心问题。OmegaUse-OfficeVal 的切入点在于将评估对象从“交互轨迹”下沉至“最终交付物”，并引入任务级经济锚定，使评估结果直接对应市场价值与人力成本。

## 核心方法

### 评估参照系与差异

通用智能体评估通常依赖 LLM-as-a-Judge 或环境状态断言，前者存在主观偏差与不稳定性，后者难以覆盖办公文档的细粒度格式要求。OmegaUse-OfficeVal 的关键差异在于放弃主观评判，转而构建基于细粒度评分细则（Rubrics）的代码验证器，将“可用性”与“任务完成度”转化为可执行的确定性逻辑，解决了办公任务无标准答案导致的评估不可复现问题。

### 任务级经济锚定机制

针对现有基准缺乏单任务经济价值标注的缺陷，本文引入双重经济信号：人力时间（Human Labor Time）与任务价格代理（Task Price Proxy）。人力时间通过激励协议记录人类标注者无 LLM 辅助下的完成耗时，反映真实劳动成本；任务价格代理则基于从业者明确报价或专家一致性估计，模拟市场定价。这一设计动机在于实现 LLM 推理成本与人类劳动成本的直接对比，支持价值加权评估（Value-weighted Evaluation），避免简单平均分数掩盖高价值任务的失败。

### 代码验证器与评分公式

为消除 LLM 评判的随机性，本文构建了包含可用性检查（Usability Checks）与任务完成度评分（Task Completion Rubrics）的两阶段验证协议。可用性检查为二元逻辑，任一失败即任务得分为零；任务完成度评分采用加权求和，正向项奖励需求满足，负向项惩罚意外损坏。最终得分 $Score(t)$ 定义为：

$$ Score(t) = U_t \cdot \frac{S_{clip}^t}{S_+^t} $$

其中 $U_t = \prod_{u \in U_t} I_u$ 为可用性通过标志，$S_{clip}^t = \max(0, \sum_{c \in C_t} w_c I_c)$ 为截断后的原始得分，$S_+^t = \sum_{c \in C_t: w_c > 0} w_c$ 为最大正向得分。该公式确保得分归一化至 [0, 1] 区间，且负向惩罚不会导致负分，仅降低最终得分，从而量化交付物的“净质量”。

## 实验评估

实验在 OmegaUse-OfficeVal 的 100 个长时程办公任务上进行，对比 GLM-5.2、Kimi K2.6、DeepSeek-V4-Pro、MiniMax M3、Qwen3.7-Plus 及人类基线。基线覆盖当前主流前沿大语言模型，但缺乏通用 Agent 框架（如 ReAct）的对比，限制了框架效应的解耦分析。

| 模型 | Score | Time-Weighted Score | Price-Weighted Score | Cost/Task (USD) | Time/Task (hours) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Human | 27.79 | 54.45 | 144.61 | $6.8560 | 2.324 |
| GLM-5.2 | 17.91 | 30.13 | 93.51 | $1.4823 | 0.521 |
| Qwen3.7-Plus | 17.51 | 34.73 | 106.50 | $0.2152 | 0.193 |
| Kimi K2.6 | 17.00 | 31.29 | 95.96 | $0.7719 | 0.389 |
| DeepSeek-V4-Pro | 14.48 | 27.14 | 79.33 | $0.6111 | 0.184 |
| Minimax M3 | 13.82 | 30.81 | 76.97 | $1.7572 | 2.275 |

最佳 LLM GLM-5.2 得分 17.91，显著低于人类基线的 27.79，差距约 9.88 分。然而，Qwen3.7-Plus 以 $0.2152 的单任务成本实现了 17.51 的得分，其成本仅为人类基线的 3.1%，耗时仅为人类的 8.3%。价值加权评估显示，Qwen3.7-Plus 在 Price-Weighted Score 上（106.50）高于 GLM-5.2（93.51），表明高分模型未必能捕获最具经济价值的任务，成本效率与质量存在非对称性。

评估协议采用代码验证器，确保了跨模型比较的稳定性，但缺乏置信区间报告，且人类基线取最高分提交，可能高估人类平均水平从而夸大 LLM 差距。代码开源完整，但任务集仅 100 个，统计显著性受限。

## 关联研究分析

从问题动机看，OmegaUse-OfficeVal 与 GDPVal 的核心差异在于经济价值的粒度。GDPVal 将经济价值关联至宏观职业类别，旨在衡量智能体对劳动力市场的整体替代潜力；而本文聚焦单任务粒度，旨在评估具体办公工作流的成本效益。这一差异源于任务特性：办公任务具有高度异质性，单任务成本波动大，宏观类别无法反映具体工作流的实际经济价值。

从方法设计看，本文与 OSWorld 2.0 存在根本分歧。OSWorld 2.0 侧重 GUI 交互过程评估，通过环境状态断言验证智能体是否到达预定状态；本文则剥离 GUI 交互依赖，聚焦最终交付物的可用性与质量。这一选择解决了办公任务中“过程正确但结果不可用”的评估盲区，但代价是忽略了智能体在复杂 GUI 环境中的导航能力。代码验证器能否完全替代 LLM 评判以捕捉主观质量维度，如 PPT 设计的审美合理性，论文未给出回答。

## 总结

OmegaUse-OfficeVal 旨在解决办公智能体评估中经济价值缺失与交付物质量不可验证的矛盾。通过引入任务级人力时间与价格代理，结合代码验证器，该基准实现了成本与质量的统一量化。实验表明，最佳 LLM 得分 17.91 远低于人类基线 27.79，但 LLM 在成本与速度上具备数量级优势。本文的边界在于任务集规模较小且缺乏通用 Agent 框架对比，人类基线取最高分可能高估差距。当任务集扩展至千级规模时，代码验证器对创意类办公任务的覆盖度是否仍能保持评估稳定性，论文未给出回答。
