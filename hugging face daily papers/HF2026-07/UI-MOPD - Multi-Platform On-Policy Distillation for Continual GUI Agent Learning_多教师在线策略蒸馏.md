# HuggingFace最新推荐论文 ｜UI-MOPD: Multi-Platform On-Policy Distillation for Continual GUI Agent Learning ｜多教师在线策略蒸馏

研究机构：清华大学、小米

作者：Niu Lian、Alan Chen、Zhehao Yu 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2607.04425)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.04425)

> 跨平台图形用户界面智能体（GUI Agent）在持续学习过程中面临行为模式混淆与灾难性遗忘，现有混合监督微调或模型合并方法因动作语义差异导致策略平均化，无法保留平台特异性交互习惯。本文切入点在于利用多教师在线策略蒸馏（Multi-Teacher On-Policy Distillation, MOPD）将平台特异性行为作为稳定锚点，通过动态路由机制在强化学习过程中隔离不同平台的交互先验。该方法在OSWorld与MobileWorld上分别取得38.2%和12.0%的任务成功率，验证了其在平衡新平台适应与旧能力保持上的有效性，但其在通用桌面任务上的绝对性能仍显著低于当前单平台SOTA，且缺乏对Web平台的覆盖。

## 研究背景

GUI智能体的核心挑战在于从单平台专用模型向跨平台通用智能体演进。当模型同时处理桌面与移动端环境时，动作语义的根本差异（如桌面关闭窗口 vs 移动端按返回键）导致联合训练产生“平均化策略”，即模型在优化过程中抹平了平台特有的交互惯例，引发行为混淆。这种混淆在持续学习场景下加剧，表现为新平台训练导致旧平台能力退化，即灾难性遗忘。解决此问题需要一种机制，既能吸收新平台的交互模式，又能锁定已掌握的平台特异性行为。

早期跨平台尝试主要依赖数据聚合或参数合并。OpenCUA等数据集通过扩大轨迹规模提升覆盖度，而Mixed-SFT或TIES Merging则试图在参数空间或数据空间直接融合异构信号。然而，这些方法将跨平台学习简化为信号叠加，忽视了不同平台动作空间的结构性冲突。例如，直接合并桌面与移动端专家模型权重，往往导致移动端性能归零或桌面性能停滞。现有强化学习框架如MobileRL虽提升了单平台鲁棒性，但未解决多平台共存时的行为隔离问题。本文针对这一空白，提出在策略优化阶段引入条件化的教师监督，而非在数据或参数层面进行静态融合。

## 核心方法

### 方法参照系

标准GUI智能体训练流程通常包含监督微调（SFT）初始化与强化学习（RL）优化两个阶段。在跨平台场景下，常规做法是将多平台数据混合进行SFT，或训练单一策略模型在混合环境中进行RL。本文的关键差异在于，它不将多平台信号视为同质数据流，而是将其视为需要隔离的行为分布，并在RL阶段引入多教师蒸馏机制以维持行为边界。

### 平台条件化教师路由

设计动机在于解决单一教师或混合教师信号导致的动作语义压缩。传统蒸馏中，教师提供全局分布约束，但在跨平台场景下，桌面与移动端的动作分布存在结构性冲突，直接混合会削弱平台特异性先验。本文引入平台条件化路由机制，根据当前Rollout的环境标签 $s_i$ 动态选择对应的专家教师 $\pi_{ref}^{[i]}$。

$$
\pi_{ref}^{[i]} = \begin{cases}
\pi_{ref}^{[d]} & \text{if } s_i = \text{Desktop} \\
\pi_{ref}^{[m]} & \text{if } s_i = \text{Mobile}
\end{cases}
$$

该公式表明，教师的选择完全由数据源标签决定，而非基于内容相似度。这种硬路由确保了桌面Rollout仅对齐桌面教师的交互模式，移动端Rollout仅对齐移动端教师，从而在优化过程中物理隔离了异构行为信号，防止策略向“平均化”方向漂移。

### 在线策略蒸馏与自适应KL掩码

设计动机在于解决离线蒸馏无法匹配学生当前错误分布的问题。离线蒸馏要求学生学习教师的所有行为模式，包括学生当前策略不会访问的状态，导致监督信号稀疏且低效。本文采用在线策略蒸馏，仅在学生策略 $\pi_\theta$ 实际访问的状态上施加教师约束。

$$
\mathcal{L}_{MOPD} = \sum_{i} \mu_{[i]} \cdot \hat{D}_{KL}(\pi_\theta \| \pi_{ref}^{[i]}) + \mathcal{L}_{RL}
$$

其中 $\mu_{[i]}$ 为自适应KL掩码，$\hat{D}_{KL}$ 为基于K3估计器的Token级KL散度。该公式的物理含义是：当任务奖励反馈不足时（$\mu_{[i]}$ 接近1），强化教师的行为约束以提供密集监督；当任务奖励已足够引导策略改进时（$\mu_{[i]}$ 接近0），移除教师约束以允许策略自由探索。这种机制将KL项从保守正则化器转变为动态行为锚点，仅在策略迷失时介入，平衡了探索效率与行为保持。

## 实验评估

实验在OSWorld（361个桌面任务）和MobileWorld（117个移动任务）上进行，基线涵盖通用视觉语言模型、单平台GUI模型及集成策略（Mixed-SFT、Model Merge）。

| 方法 | OSWorld (%) | MobileWorld (%) |
| :--- | :--- | :--- |
| Qwen3-VL-8B-Thinking | 33.9 | 7.7 |
| Mixed-SFT | 35.0 | 6.4 |
| Model Merge (TIES) | 36.8 | 0 |
| UI-MOPD | 38.2 | 12.0 |

UI-MOPD在两个平台上均优于基线，尤其在MobileWorld上显著高于Model Merge（12.0% vs 0%），证明动态行为蒸馏优于静态参数合并。在静态基准AndroidControl上，UI-MOPD取得80.05%，高于基线Qwen3-VL-8B-Thinking的78.73%，表明跨平台训练未损害基础GUI理解能力。

消融实验显示，单平台SFT导致另一平台性能归零（如OSWorld SFT后MobileWorld为0%），验证了行为混淆的严重性。UI-MOPD通过教师路由避免了此问题，但其在OSWorld上的38.2%仍低于单平台SOTA（如LocalLSTC的69.9%），暗示8B参数规模或蒸馏损失对复杂桌面任务的限制。

评估边界方面，论文未提供置信区间，且MobileWorld任务数较少（117个），统计显著性存疑。代码与数据已开源，但缺乏Web平台实验，限制了结论的通用性。

## 关联研究分析

从问题动机看，UI-MOPD与UI-S1均关注长程任务中的错误恢复，但UI-S1侧重单平台RL稳定性，通过补丁模块平衡探索与利用；UI-MOPD则聚焦多平台行为隔离，通过教师路由解决跨平台遗忘。差异根源在于任务特性：单平台任务中，错误主要源于环境动态性；多平台任务中，错误主要源于行为语义冲突。UI-MOPD的解决方案是否适用于非GUI的多模态持续学习场景，论文未给出回答。

从方法设计看，UI-MOPD借鉴了MiMo-V2Flash等基础模型中的MOPD思路，但将其从“能力维度”（如数学、写作）迁移至“平台维度”。MiMo-V2Flash中教师选择基于能力短板，而UI-MOPD中教师选择基于环境标签。这一迁移的关键差异在于，平台行为具有更强的结构性约束，而能力行为具有更强的连续性。UI-MOPD的硬路由机制是否过于刚性，导致无法利用平台间的潜在共性（如通用的点击逻辑），论文未进行细粒度分析。

## 总结

本文核心矛盾在于跨平台GUI智能体持续学习中的行为混淆与灾难性遗忘。现有混合SFT或模型合并方法因动作语义差异导致策略平均化，无法保留平台特异性。UI-MOPD通过平台条件化教师路由与在线策略蒸馏，将教师行为作为动态锚点，在RL过程中隔离异构行为信号。实验证明其在OSWorld和MobileWorld上分别取得38.2%和12.0%的成功率，优于Mixed-SFT和Model Merge基线。然而，其在OSWorld上的绝对性能仍显著低于单平台SOTA，且缺乏Web平台覆盖，暴露了8B模型规模与蒸馏损失对复杂任务的限制。当支持集扩大至Web平台时，平台条件化路由的硬隔离机制是否仍能保持行为边界，论文未给出回答。
