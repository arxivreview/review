# HuggingFace最新推荐论文 ｜Scaling Mixture-of-Experts Video Pretraining for Embodied Intelligence ｜具身智能导向的稀疏混合专家视频预训练

论文原文见 [arXiv](https://arxiv.org/abs/2607.07675)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.07675)

> 视频生成模型在具身智能应用中面临视觉保真与物理正确性的根本割裂，现有密集架构难以兼顾长序列计算效率与复杂动力学建模能力。LingBot-Video 通过引入稀疏混合专家（Mixture-of-Experts, MoE）架构解耦参数容量与计算开销，并融合机器人增强数据与多维物理奖励，构建了首个面向具身智能的大规模开源 MoE 视频基础模型。该工作验证了稀疏路由在物理一致性上的有效性，但其对长时程累积误差的理论解释仍显不足。

## 研究背景

当视频生成模型试图充当机器人或自动驾驶系统的“世界模拟器”时，其训练目标（美学、文本对齐）与具身智能需求（接触稳定性、刚体动力学）之间存在系统性错位。这种错位源于互联网视频数据缺乏精确的物理状态标注，导致模型仅能捕捉统计相关性而非因果物理律。为弥合这一鸿沟，研究者需解决两个耦合问题：一是如何在保持视觉真实感的同时内化物理约束，二是如何在不牺牲推理效率的前提下扩展模型容量以捕捉复杂时空动态。

当前主流视频生成范式依赖密集 Transformer 架构，所有参数在所有 token 和去噪步骤中均匀激活。这种设计在处理百万级时空 token 序列时产生 prohibitive 的计算开销，且单一参数路径难以同时建模空间纹理与时间运动等不对称域，导致严重的子任务干扰。现有物理接地方法多聚焦于后训练阶段的奖励优化或显式仿真器集成，却忽视了预训练阶段的架构瓶颈与数据偏置。LingBot-Video 的切入点在于从架构、数据、训练目标三个维度协同重构预训练范式，将 MoE 稀疏计算引入视频扩散模型，以解决容量-效率权衡问题，并通过机器人数据注入与物理奖励强化，实现从“内容创作”到“物理执行”的范式转移。

## 核心方法

### 任务统一单流扩散 Transformer

本文采用级联设计，基础生成器基于单流扩散 Transformer（DiT）处理紧凑视觉潜变量与多模态条件。与双流架构不同，单流设计将视觉与条件 token 拼接为统一序列，通过 3D MM-RoPE 机制在重叠时间坐标范围内分离模态，最大化参数复用并提升模型浮点运算利用率（MFU）。该设计消除了任务特定架构需求，使文本到图像（T2I）、文本到视频（T2V）和图像到视频（TI2V）任务在单一框架内统一处理，为后续稀疏扩展奠定基础。

### 稀疏混合专家架构与负载均衡

密集 FFN 迫使所有 token 共享同一参数路径，在统一视频预训练中引发子任务干扰。LingBot-Video 将密集 FFN 替换为 token-choice 稀疏 MoE 层，实现容量-计算解耦。给定调制 FFN 输入 $u_t$，MoE 分支输出由共享专家与路由专家共同计算：

$$ m(u_t) = \sum_{i=1}^{N_s} E_i^{(s)}(u_t) + \sum_{j \in R_b(u_t)} g_{t,j} E_j^{(r)}(u_t) $$

其中 $R_b(u_t)$ 为选中的路由专家集，$g_{t,j}$ 为路由权重。该公式表明，每个 token 仅激活部分专家，从而在保持总参数容量扩展的同时严格控制每 token 活跃 FLOPs。为维持负载均衡，采用无辅助损失策略，通过动态修正偏置 $b_j$ 在线调整专家选择：

$$ b_j \leftarrow b_j - \eta \text{sign}(n_j - \bar{n}) $$

其中 $n_j$ 为专家 $j$ 的 token 分配数，$\bar{n}$ 为平均负载。此机制避免了传统辅助损失对表示容量的干扰，确保专家专业化与共享先验的平衡。

### 多维奖励系统与 GRPO 后训练

预训练阶段注入的机器人数据与物理先验需通过强化学习进一步对齐。LingBot-Video 开发多维奖励系统，超越美学与文本对齐，纳入物理合理性与任务完成信号。采用组相对策略优化（GRPO）进行后训练，遵循 Flash-GRPO 的单步探索范式：每个 rollout 在共享去噪步骤上随机化，噪声通过系数保持采样（CPS）注入，策略梯度经时间步重平衡。该设计将物理约束内化为模型权重，而非依赖推理时外部模拟器，实现了端到端的物理一致性优化。

## 实验评估

LingBot-Video 在 RBench 与 Physics-IQ Verified 基准上进行评估，对比 Cosmos 3 Super、Wan 2.2 A14B、Hunyuan Video 1.5 等开源及闭源模型。RBench 聚焦机器人中心交互，包含 650 个文本-图像提示，覆盖操作、空间关系等多实体协作场景；Physics-IQ Verified 基于 66 个受控物理实验，评估模型预测真实物理现象的能力。基线覆盖主流开源视频模型，但缺乏显式仿真类方法（如 PhysGen）的直接对比，可能低估数据增强与架构创新的独立贡献。

| 模型 | 类型 | RBench 平均分 | Physics-IQ Verified I2V 分数 |
| :--- | :--- | :--- | :--- |
| LingBot-Video | 开源 | 0.620 | 40.4 |
| Cosmos 3 Super | 开源 | 0.581 | 39.5 |
| Hunyuan Video 1.5 | 开源 | 0.460 | 33.4 |
| Wan 2.2 A14B | 开源 | 0.507 | 32.2 |

LingBot-Video 在 RBench 平均分（0.620）与 Physics-IQ Verified I2V 分数（40.4）上均领先开源基线，其中 Physics-IQ 分数较 Cosmos 3 高 0.9，较 Wan 2.2 高 8.2，表明其在物理预测一致性上的优势。消融实验显示，MoE 13B-A1.4B 在训练与验证损失上持续优于 Dense 1.3B，且在 1M token 序列长度下，MoE 30B-A3B 相对于 Dense 6B、14B、30B 的速度比分别为 1.50×、2.59×、3.18×，验证了稀疏架构在长视频生成中的效率优势。

评估边界受限于公开基准的覆盖度：RBench 侧重机器人交互，Physics-IQ 侧重基础物理定律，均未涵盖流体、软体变形等复杂动力学场景。可复现性方面，论文提供 GitHub 与 HuggingFace 链接，但 RL 系统性能数据（如 30B 模型权重同步 20 秒/步）未提供完整超参数配置，可能影响复现精度。

## 关联研究分析

从问题动机看，LingBot-Video 与 WMReward 同属物理接地视频生成，但前者采用训练时 GRPO 对齐，后者依赖推理时世界模型奖励。WMReward 在不修改模型权重的前提下提升物理合理性，部署灵活但物理一致性上限受限；LingBot-Video 通过权重内化物理约束，追求更高一致性，但牺牲了实时调整能力。这一差异源于任务特性：具身智能应用要求模型具备稳定的物理先验，而非动态适应，因此训练时对齐更契合需求。

从方法设计看，LingBot-Video 与 PhysGen 形成方法论对立。PhysGen 引入显式刚体动力学仿真器作为中间表示，通过 3D 重建与轨迹生成指导视频合成，确保物理定律严格遵循，但受限于重建精度与计算开销。LingBot-Video 采用隐式数据驱动路线，依赖机器人增强数据与奖励信号，无需显式仿真器，泛化性更强但物理保证较弱。PhysGen 在 Physics-IQ 基准上表现更稳定，而 LINGBOT-VIDEO 在 RBench 上领先，暗示显式仿真在基础物理定律遵循上占优，隐式方法在复杂交互场景泛化上更具潜力。

## 总结

LingBot-Video 旨在解决视频生成模型在具身智能中视觉保真与物理正确性的割裂矛盾，通过 MoE 稀疏架构解耦容量与计算，融合机器人数据与多维物理奖励，实现了从内容创作到物理执行的范式转移。该模型在 RBench（0.620）与 Physics-IQ Verified（40.4）上领先开源基线，验证了稀疏路由在物理一致性上的有效性。然而，其实验未涵盖流体、软体等复杂动力学场景，且缺乏与显式仿真方法的直接对比，物理保证的边界尚不明确。当支持集增大到百万级 token 时，MoE 稀疏路由的边际收益是否递减，论文未给出回答。
