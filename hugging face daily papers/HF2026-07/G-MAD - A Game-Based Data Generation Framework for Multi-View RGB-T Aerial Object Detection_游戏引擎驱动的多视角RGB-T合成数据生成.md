> 航拍目标检测面临视角剧烈变化与多模态对齐难题，真实数据采集成本极高且难以控制视角同步。现有游戏引擎流水线多局限于单视角可见光，无法提供热成像配对数据，导致多模态融合研究缺乏结构化监督。本文提出G-MAD框架，将Arma3改造为支持约束感知采样与引擎级几何标注的自动化流水线，并构建AMOD基准。该工作验证了合成数据在跨视角泛化与Sim-to-Real迁移中的有效性，但游戏引擎物理精度对热成像仿真的影响尚未量化。

## 研究背景

航拍场景中的目标检测受视角偏移与尺度变化影响显著，RGB-热成像（RGB-T）双模态虽能互补可见光与热辐射特征，但真实数据需同步传感器采集与人工标注，导致数据集视角单一且模态对齐困难。合成数据生成通过计算手段构建训练图像，旨在解决真实数据稀缺与标注成本问题，其核心在于平衡几何可控性与视觉保真度。

早期研究依赖BlenderProc等3D渲染引擎，虽能获取精确几何标注，但受限于纹理真实感不足，导致仿真到现实差距显著。随着生成式AI成熟，领域范式转向混合驱动，但纯生成模型缺乏精确几何控制，需依赖后处理工具引入误差。游戏引擎如GTA V因预置资产丰富被用于数据生成，但现有Arma3基线框架存在单对象限制、GUI依赖及基于图像差分标注等缺陷，无法支持多视角同步捕获与结构化数据集构建。本文切入点在于利用Arma3的脚本化能力，实现约束感知的多对象采样与引擎原生几何标注，解决多视角RGB-T数据生成的结构化监督缺失问题。

## 核心方法

### 场景-视角解耦采样机制

传统游戏引擎数据生成通常将场景配置与相机姿态耦合，导致视角变化时物体布局随之改变，无法生成同一场景的多视角一致观测。G-MAD将数据生成形式化为两级采样过程，解耦场景级变量与视角级变量。设 $S$ 为用户约束定义的有效场景空间，$V$ 为视角与传感配置空间，采样过程表达为：

$$ s \sim P(S | \text{constraints}), \quad v \sim P(V | s) $$

该公式表明，单个场景 $s$ 可生成多个视角 $v$ 的观测，保持物体布局与环境不变，仅改变相机姿态与模态。这种解耦设计使得模型能从同一底层场景的多视角观测中学习视角不变表示，解决了此前方法中视角变化导致标注不一致的问题。

### 引擎原生几何标注与遮挡过滤

现有Arma3框架依赖前后帧图像差分推断物体位置，在多物体场景下易出错且无法生成有向边界框（OBB）。G-MAD直接查询Arma3引擎级几何信息，通过 $boundingBoxReal$ 函数获取物体在局部模型坐标系中的3D边界框顶点。给定上角坐标 $(x_m, y_m, z_m)$，枚举所有符号组合生成8个规范模型空间角点 $\{p_m[i]\}_{i=1}^8$，再经相机参数投影至图像平面生成HBB/OBB。同时，框架通过视线相交检测自动过滤完全遮挡物体，减少幽灵边界框噪声。这一设计消除了图像差分对多物体场景的依赖，实现了零后处理的精确标注，提升了标签质量与流水线可扩展性。

## 实验评估

实验采用Oriented R-CNN（Swin-S骨干）作为基线检测器，在自建AMOD数据集上评估多视角学习与Sim-to-Real迁移。基线覆盖单视角训练与ImageNet预训练，但缺乏与GenAI混合渲染或最新SOTA检测器的直接对比，限制了方法优越性的全面验证。

多视角训练（All）在平均AP50:95上达到50.96，较最佳单视角（20°）的44.57提升6.39点，验证了视角多样性对泛化能力的贡献。Sim-to-Real迁移实验中，AMOD预训练在DIOR-R上平均AP50从63.14提升至69.83（+6.69），在HIT-UAV上从74.57提升至77.08（+2.51），表明合成数据提供了可迁移的预训练信号。

消融实验显示，RADAR（25.70 AP75）与SAM（30.60 AP75）类别性能显著低于LCU（78.30 AP75）与Plane（79.30 AP75），归因于高类内变化。评估边界方面，论文未报告置信区间，且预训练增益可能部分归因于数据量而非合成质量；代码开源但Arma3物理引擎对热成像辐射特性的仿真精度未量化，限制了热成像结果的物理可信度。

## 关联研究分析

从方法设计看，G-MAD与BlenderProc同属3D渲染路线，但BlenderProc依赖通用引擎手动建模，而G-MAD利用Arma3预置军事资产库实现自动化场景采样。关键差异在于G-MAD支持多视角同步捕获与RGB-T双模态生成，而BlenderProc主要面向单视角RGB。这一差异源于任务特性：军事目标检测需覆盖多视角与热成像互补性，通用引擎缺乏原生热成像支持，需额外物理建模。G-MAD通过游戏引擎脚本化直接生成白热热成像，规避了复杂物理仿真，但牺牲了热辐射物理精度。

从问题动机看，SOC（Synthetic Object Compositions）聚焦开放词汇检测，通过对象组合生成大规模数据，而G-MAD聚焦军事垂直领域的多视角RGB-T检测。SOC依赖GenAI纹理生成与3D几何结合，G-MAD则完全依赖游戏引擎资产与脚本控制。SOC在LVIS上AP达31.4，但缺乏多视角同步能力；G-MAD在AMOD上验证了多视角增益，但未在开放词汇任务上评估。两者差异反映了合成数据生成在“数据量扩充”与“结构化监督”之间的不同取舍：SOC追求类别覆盖广度，G-MAD追求视角与模态对齐精度。

## 总结

G-MAD针对航拍RGB-T检测中视角控制与模态对齐难题，利用Arma3脚本化能力实现场景-视角解耦采样与引擎原生几何标注，构建了多视角同步的AMOD基准。实验证明多视角训练提升平均AP50:95达6.39点，AMOD预训练在DIOR-R上提升6.69点，验证了合成数据在跨视角泛化与Sim-to-Real迁移中的有效性。然而，Arma3物理引擎对热成像辐射特性的仿真精度未量化，游戏资产与真实军事目标的视觉差异可能导致迁移性能高估。当热成像数据用于实际部署时，游戏引擎生成的热辐射特征与真实传感器噪声的分布差距是否足以影响检测器泛化，论文未给出回答。
