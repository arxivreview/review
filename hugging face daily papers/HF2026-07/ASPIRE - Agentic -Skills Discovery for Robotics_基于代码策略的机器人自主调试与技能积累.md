研究机构：美国伊利诺伊大学厄巴纳-香槟分校、美国卡内基梅隆大学

论文原文见 [arXiv](https://arxiv.org/abs/2607.00272)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.00272)

> 机器人编程的核心困境在于执行失败时缺乏细粒度诊断信息，导致调试陷入盲目试错。现有代码策略系统仅提供任务级布尔反馈，无法区分感知、规划或控制环节的具体故障，且经验无法跨任务复用。ASPIRE 通过暴露原语级多模态轨迹实现故障归因，并将验证过的修复策略沉淀为可检索的技能库，配合进化搜索扩大探索空间。该方法在扰动基准上显著优于基线，但技能迁移仍依赖人工筛选，自动化适配机制缺失。

## 研究背景

当机器人执行复杂操作任务失败时，系统仅返回“任务未完成”的布尔信号，无法指示失败源于感知错误、抓取不稳定还是运动规划冲突。这种粗粒度反馈迫使调试代理在巨大的代码空间中盲目搜索，效率极低。为解决此问题，代码策略（Code-as-Policy）范式将机器人行为显式表示为可执行程序，使得行为可被检查、编辑和调试。然而，现有实现仍受限于静态的反馈接口，代理无法自主决定检查哪些证据或如何定位故障子系统。

传统任务与运动规划（TAMP）依赖符号逻辑与采样算法的解耦架构，在动态非结构化环境中面临组合爆炸与物理接地缺失的双重瓶颈。随着大语言模型（LLM）介入高层任务分解，语义理解能力增强，但执行层的鲁棒性成为新短板。主流路线如 ViReSkill 通过视觉接地重规划恢复失败，但依赖预定义技能库；SayCan 确立的“语言推理+物理验证”架构虽平衡了灵活性与安全性，却缺乏跨任务的经验积累机制。ASPIRE 的切入点在于将软件工程中的“调试-修复-积累”闭环迁移至机器人领域，通过自主诊断将一次性修复转化为持久化知识，打破“第100个任务与第1个任务同等无知”的局限。

## 核心方法

### 方法参照系

ASPIRE 属于分层规划与技能复用路线的变体，其参照系为标准的“高层推理-低层执行”闭环。与依赖预定义技能库或强化学习（RL）训练的传统流程不同，ASPIRE 的技能库由 LLM 在调试过程中自主诱导生成，无需人工预设分类法，且通过进化搜索并行探索多种修复假设，而非单轨迹迭代。

### 原语级多模态轨迹执行引擎

传统代码策略系统通过固定接口暴露场景级摘要，导致代理无法区分感知成功但规划失败的复杂情形。ASPIRE 引入闭环机器人执行引擎，为每个感知、规划和控制调用记录输入、输出、返回状态及多模态证据（如 RGB 关键帧、叠加层、抓取候选）。代理可自主选择检查与故障相关的原语日志，实现渐进式故障定位。该机制解决了粗粒度反馈下代理无法确定“检查什么证据”和“如何定位故障”的失效。故障归因过程可形式化为：

$$
\mathcal{Z} = \{ (a_i, x_i, y_i, s_i, v_i) \}_{i=1}^{N}
$$

其中 $a_i$ 为 API 调用，$x_i, y_i$ 为输入输出，$s_i$ 为状态码，$v_i$ 为多模态证据。代理基于 $\mathcal{Z}$ 中的异常状态码（如 `PLANNING_ERROR`）及其关联证据，生成针对性修复假设，而非盲目修改代码。

### 自主诱导技能库与进化搜索

单轨迹调试易陷入局部修复循环，反复修补同一失败策略。ASPIRE 通过进化搜索生成 $K$ 个候选程序，基于前代最优程序与残留故障轨迹条件化下一轮生成，扩大策略探索空间。验证通过的修复被协调器审计并提炼为紧凑的技能条目，存入共享技能库。技能条目包含故障签名、应用条件、修复策略及代码草图，作为后续任务的上下文引导。该设计解决了经验无法跨任务复用的问题，使代理性能随任务数量增长而提升。技能提炼过程可表示为：

$$
\mathcal{S}_{new} = \text{Distill}(\mathcal{H}, P^*, r_{val}, \mathcal{Z}_{val})
$$

其中 $\mathcal{H}$ 为调试历史，$P^*$ 为最优程序，$r_{val}$ 为验证分数。仅当修复在调试配置上验证通过且具备跨任务泛化潜力时，协调器才将其晋升至技能库，确保知识的可靠性。

## 实验评估

实验在 LIBERO-Pro、Robosuite 和 BEHAVIOR-1K 上进行，基线覆盖 VLA（OpenVLA, $\pi_0$）和代码代理（CaP-Agent0）。ASPIRE 在 LIBERO-Pro 扰动套件上平均提升 77%，在 Robosuite 双手交接任务上从 20% 提升至 92%，在 BEHAVIOR-1K 长时程任务上提升 32%。

| 基准 | 任务/套件 | CaP-Agent0 | ASPIRE | 提升幅度 |
| :--- | :--- | :--- | :--- | :--- |
| LIBERO-Pro | Object (Pos/Task) | 0.00 / 0.00 | 0.98 / 0.95 | +98 / +95 |
| LIBERO-Pro | Goal (Pos/Task) | 0.00 / 0.00 | 0.81 / 0.45 | +81 / +45 |
| LIBERO-Pro | Spatial (Pos/Task) | 0.00 / 0.00 | 0.51 / 0.60 | +51 / +60 |
| Robosuite | two_arm_handover | 0.20 | 0.92 | +72 |
| BEHAVIOR-1K | Radio pick-up (Task) | 0.56 | 0.88 | +32 |

消融实验显示，机器人执行引擎贡献最大，将宏观平均成功率从 14% 提升至 62%；进化搜索进一步将硬任务成功率提升至 72%。在 LIBERO-Pro Long 零样本迁移中，技能库大小 $N$ 从 0 增至 90，Pos 成功率从 0.00 升至 0.226，Task 成功率从 0.00 升至 0.383，表明技能积累与性能正相关。

评估边界方面，实验未报告置信区间，且 LIBERO-Pro 的扰动设置与标准 LIBERO 协议不同，数值不可直接比较。代码开源，但技能库的构建依赖特定 LLM（Claude Opus 4.6）和 CaP-X 框架，跨模型泛化性未验证。

## 关联研究分析

从问题动机看，ASPIRE 与 ViReSkill 均关注技能记忆，但 ViReSkill 依赖视觉接地重规划从实时观测中恢复失败，技能来源为成功执行的动作序列；ASPIRE 则通过代码调试从失败中提炼修复策略，技能来源为验证过的代码补丁。这一差异源于任务特性：ViReSkill 侧重感知-动作闭环的鲁棒性，ASPIRE 侧重程序逻辑的正确性。ASPIRE 的技能库无需预定义分类法，由 LLM 自主诱导，这是否比预定义技能库更易过拟合特定任务，论文未给出理论保证。

从方法设计看，ASPIRE 与 SayCan 同属神经符号范式，但 SayCan 通过基于 RL 的可供性过滤验证 LLM 计划的物理可行性，技能库为预定义的原子动作；ASPIRE 通过执行引擎轨迹验证代码修复的有效性，技能库为动态生成的复合策略。ASPIRE 的进化搜索引入了并行探索机制，而 SayCan 依赖单轨迹推理。这种设计选择使得 ASPIRE 在长时程任务中更具鲁棒性，但计算开销更大。进化搜索的边际收益递减现象（图 6c）表明，额外轮次对残留硬案例仍有增益，但效率降低，这是否值得在实时性受限的场景中采用，需进一步权衡。

## 总结

ASPIRE 解决的核心矛盾是代码策略系统中故障诊断的粗粒度与经验复用的缺失。现有方法因缺乏细粒度轨迹和持久化机制，导致调试效率低且经验无法积累。ASPIRE 通过原语级多模态轨迹实现故障归因，将验证过的修复策略沉淀为技能库，并配合进化搜索扩大探索空间。实验证明其在扰动基准上显著优于基线，LIBERO-Pro Object Pos 成功率达 0.98，Robosuite 双手交接成功率达 0.92。然而，技能迁移仍依赖人工筛选，跨本体迁移的自动化适配机制缺失。当技能库规模扩大后，检索效率与技能冲突解决机制是否成为瓶颈，论文未给出回答。
