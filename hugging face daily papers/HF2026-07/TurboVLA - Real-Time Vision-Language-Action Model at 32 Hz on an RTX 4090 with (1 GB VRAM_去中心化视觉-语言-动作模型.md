# HuggingFace最新推荐论文 ｜TurboVLA: Real-Time Vision-Language-Action Model at 32 Hz on an RTX 4090 with <1 GB VRAM ｜去中心化视觉-语言-动作模型

研究机构：华中科技大学、华为

作者：Hengyi Xie、Chenfei Yao、Xianjin Wu 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2607.27205)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.27205)

> 视觉-语言-动作（Vision-Language-Action, VLA）模型旨在将互联网规模的视觉-语言先验映射为机器人低层动作，以突破传统策略在非结构化环境中的泛化瓶颈。现有主流架构依赖大语言模型（Large Language Model, LLM）作为感知与动作间的核心接口，导致推理延迟高、显存占用大，难以在资源受限的物理机器人上实现实时闭环控制。本文提出 TurboVLA，通过移除 LLM 骨干，采用轻量文本编码器与双向视觉-语言交互直接生成连续动作分块，在保持高成功率的同时大幅降低计算开销。该设计验证了执行级控制无需依赖通用 LLM 的可行性，但其对开放词汇泛化能力的潜在牺牲尚存疑。

## 研究背景

机器人实时控制要求策略在毫秒级内完成从观测到动作的映射，而当前 VLA 模型普遍采用“视觉-语言-动作”（V → L → A）路径，即视觉特征先投影至 LLM 嵌入空间，与指令联合处理后解码动作。这一设计虽继承了 LLM 的语义推理能力，但每次策略调用均需处理数十亿参数的 LLM 核心，导致推理延迟高达数十至数百毫秒，严重限制了控制频率。例如，π0.5 在 RTX 4090 上推理延迟为 93.6 ms，仅能支持约 10 Hz 的动作更新，无法满足高吞吐操作需求。

该领域的核心矛盾在于：LLM 提供的语义泛化能力与实时控制所需的计算效率之间存在根本冲突。早期工作如 RT-2 和 OpenVLA 通过离散动作 Token 验证了语义先验的价值，但离散量化在精细操作中精度不足；后续工作如 π0 引入流匹配实现连续动作生成，解决了平滑性问题，但 LLM 骨干的计算瓶颈依然存在。现有轻量化方法如 SmolVLA 和 Evo-1 通过缩减模型规模或优化动作解码来缓解延迟，但仍保留 LLM 作为核心表征接口，未能从根本上消除计算开销。TurboVLA 的切入点在于重新审视执行级控制的需求：当指令已指定操作技能时，策略无需进行开放式语言生成或任务分解，仅需利用指令引导视觉证据生成动作。因此，本文提出直接“视觉+语言-动作”（V + L → A）范式，用轻量文本编码器和双向交叉注意力替代 LLM 中心接口，实现高效实时控制。

## 核心方法

### 方法参照系

标准 VLA 流程为：视觉编码器提取特征 → 投影至 LLM 嵌入空间 → 与指令 Token 联合输入 LLM → 解码动作。本文的关键差异在于移除 LLM 环节，改用独立视觉编码器与轻量文本编码器，通过显式双向交互直接生成动作表征，避免多模态输入经 LLM 处理的计算开销。

### 轻量指令编码与双向视觉-语言交互

传统 VLA 中，指令经 LLM 处理以提供语义上下文，但执行级任务仅需指令的操作相关语义，无需 LLM 的生成能力。本文采用 BERT 作为轻量文本编码器，提取指令的执行相关特征，并通过双向交叉注意力模块与视觉特征交互。该设计解决了 LLM 中心架构中视觉与语言信息在通用表征空间中融合效率低、计算冗余的问题。具体而言，视觉特征 $V$ 和指令特征 $L$ 经投影至共享空间后，通过 $N$ 层双向交叉注意力更新：

$$
L' = \text{CrossAttn}(L, V, V), \quad V' = \text{CrossAttn}(V, L', L')
$$

其中 $L'$ 为场景感知的指令特征，$V'$ 为指令条件化的视觉特征。这一双向交互确保指令特征能感知视觉场景，同时视觉特征能受指令引导，形成控制导向的多模态表征。相比单向交叉注意力，双向设计在 LIBERO 上提升 1.6% 成功率（96.5% → 97.7%），验证了互补信息的必要性。

### 非自回归连续动作分块解码

LLM 中心 VLA 通常采用自回归 Token 解码或附加动作专家，前者继承顺序解码开销，后者仍需 LLM 处理多模态输入。本文采用 ACT 风格 Transformer 解码器，直接从 $V'$ 和机器人状态 $s_t$ 预测连续动作分块 $a_{t:t+H-1}$，避免逐 Token 生成。动作分块长度 $H=12$ 经消融验证为最优：$H=8$ 时成功率 96.4%，$H=15$ 时降至 95.6%，表明过短限制时序表达，过长增加预测难度。该设计将推理延迟降至 31.2 ms，支持 32 Hz 动作更新，较 π0.5 的 93.6 ms 提升 3 倍，同时显存占用仅 0.9 GB，为边缘部署奠定基础。

## 实验评估

实验在 LIBERO、RoboTwin 2.0 及真实世界 AgileX Piper 平台进行，基线覆盖 LLM 中心 VLA（π0.5、OpenVLA）、轻量化 VLA（SmolVLA、Evo-1）及非 VLA 策略（Diffusion Policy）。缺失 RL 后训练类（如 SimpleVLA-RL）和记忆机制类（如 HAMLET）基线，可能低估本文在分布外鲁棒性上的相对表现。

| 方法 | 参数量 (B) | 显存 (GB) | 延迟 (ms) | LIBERO 平均成功率 (%) |
|---|---|---|---|---|
| TurboVLA | 0.2 | 0.9 | 31.2 | 97.7 |
| π0.5 | 3.4 | 12.8 | 93.6 | 96.9 |
| SmolVLA | 2.3 | 7.1 | 203.1 | 88.8 |
| Evo-1 | 0.8 | 1.7 | 137.2 | 94.8 |

TurboVLA 在效率指标上显著优于所有基线，LIBERO 成功率 97.7% 接近 π0.5 的 96.9%，但低于 SimpleVLA-RL 的 99.1%（据领域综述）。RoboTwin 2.0 上，TurboVLA 以 60.2% 成功率超越 π0.5 的 57.0% 和 StarVLA-α 的 50.3%，验证了双臂控制下的有效性。

消融实验显示，移除语言条件导致成功率从 97.7% 降至 70.8%，LIBERO-Goal 套件降幅最大（97.4% → 11.6%），证实语义指令对多行为兼容场景的必要性。文本编码器对比中，T5-small 达 97.1%，SigLIP 达 95.5%，表明架构不依赖特定文本骨干。交互层数 $N$ 从 2 增至 6 时成功率从 93.5% 升至 97.7%，$N=8$ 时降至 96.6%，存在容量-效率权衡。

评估边界：未报告置信区间，数值比较需谨慎；RoboTwin 2.0 仅用 clean 设置，未测试随机化场景；真实世界实验仅 4 个任务，样本量有限。代码已开源，超参数完整披露，可复现性良好。

## 关联研究分析

从问题动机看，TurboVLA 与 SmolVLA 同属轻量化路线，但 SmolVLA 保留 VLM 骨干，仅缩减规模，而 TurboVLA 彻底移除 LLM，将计算开销从“优化”转向“消除”。这一差异源于对执行级控制需求的重新定义：SmolVLA 假设 LLM 表征对泛化必要，TurboVLA 则认为轻量交互足以支撑操作级任务。根源在于任务特性——执行级指令已限定技能空间，无需 LLM 的开放推理，但论文未验证该假设在复杂语义场景（如多步规划）下的有效性。

从方法设计看，TurboVLA 借鉴 Grounding DINO 的跨模态交互，但将其从视觉定位任务迁移至动作生成。与 π0.5 相比，π0.5 依赖 LLM 提供多模态上下文，TurboVLA 用显式双向注意力替代隐式 LLM 融合。这一设计在效率上优势显著，但可能牺牲 LLM 的语义泛化能力。论文未提供开放词汇泛化的直接证据，仅通过 LIBERO 和 RoboTwin 2.0 的任务成功率间接验证，查询侧语义增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

TurboVLA 解决的核心矛盾是 LLM 中心 VLA 的语义泛化能力与实时控制计算效率之间的冲突。现有方法通过缩减规模或优化解码缓解延迟，但保留 LLM 骨干导致计算开销无法根本消除；TurboVLA 凭借执行级控制无需 LLM 生成能力的洞察，用轻量文本编码器和双向交互直接生成动作，在 0.2B 参数、31.2 ms 延迟下实现 97.7% LIBERO 成功率。其边界在于：未验证开放词汇泛化能力，真实世界实验仅覆盖 4 个任务，且缺乏 RL 后训练对分布外鲁棒性的增强。当指令语义复杂度超出执行级范畴（如需要多步规划或开放词汇理解）时，轻量交互是否仍能维持性能，论文未给出回答。
