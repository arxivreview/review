# HuggingFace最新推荐论文 ｜Environment-free Synthetic Data Generation for API-Calling Agents ｜无环境合成轨迹生成

论文原文见 [arXiv](https://arxiv.org/abs/2607.16900)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.16900)

> 训练 API 调用智能体需要海量包含多步交互、状态追踪与错误恢复的高质量轨迹数据，但此类数据依赖可执行环境与预填充数据库，导致规模化采集成本极高。现有合成方法虽能生成数据，却受限于对真实后端基础设施的强耦合，难以快速适配新 API 域。ESAT 提出将 LLM 作为动态数字世界模型，仅凭 API 规格即可模拟环境反馈并生成多步轨迹。该方法在 AppWorld 和 OfficeBench 上验证了无环境数据的有效性，但其模拟器在长响应下的状态漂移风险及跨域泛化边界仍存疑。

## 研究背景

API 调用智能体（API-calling Agent）通过执行外部函数突破静态知识边界，其核心能力依赖于对多步交互轨迹的监督微调（Supervised Fine-Tuning, SFT）。然而，高质量轨迹数据必须捕捉用户指令、交错读写 API 调用、执行结果及最终响应的完整过程，这种数据在真实环境中采集成本高昂且难以规模化。传统合成数据方法（如 ToolAlpaca, ToolACE）虽利用 LLM 生成模拟响应，但多依赖预编译 API 池或种子轨迹，且仅处理读操作，无法维持复杂状态环境的一致性。

领域主流路线存在显著瓶颈：基于真实环境的合成方法（如 AgentTuning）需构建专用后端并填充多样化状态数据，基础设施开销严重限制了向新 API 域扩展的速度；基于 LLM 模拟的方法（如 Simia）虽绕过部分基础设施，但依赖隐式对话连贯性，在长轨迹中易出现状态漂移与标识符幻觉。ESAT 的切入点在于解耦数据生成与环境构建，提出仅以 API 规格为输入，利用 LLM 的世界知识动态模拟状态变化，从而将轨迹合成转化为轻量级规格问题。

## 核心方法

### 方法参照系

ESAT 属于合成数据生成路线，但区别于需执行真实 API 的标准流程。其关键差异在于：不依赖可执行后端或预填充数据库，而是由 LLM 模拟器基于 API 规格与交互历史实时生成环境反馈，支持状态变化的写操作，实现从零开始的任务与轨迹生成。

### 任务合成与逆频率采样

任务合成阶段旨在生成覆盖广泛且难度均衡的用户任务。设计动机是解决传统随机生成导致的 API 覆盖不均与任务重复问题。ESAT 采用分桶生成策略，将任务按难度、动作类型、应用数量等属性划分为组合网格。为确保均匀覆盖，引入逆频率采样机制：

$$ P(\text{app}_i) \propto \frac{1}{C_i + \epsilon} $$

其中 $C_i$ 为应用 $i$ 在已生成任务中的使用计数，$\epsilon$ 为平滑项。该公式通过降低高频应用的采样概率，强制生成器关注低频 API，从而提升数据多样性。生成的任务经 LLM 裁判过滤后，由 LLM 重写为简洁的意图级请求，消除程序化冗余。

### 状态一致性的 LLM 模拟器

轨迹合成阶段的核心是 LLM 模拟器，其设计动机是解决长轨迹中状态漂移与标识符幻觉问题。模拟器作为动态数字世界模型，条件输入包括 API 规格、调用参数、任务指令、同应用交互历史及虚拟用户信息。为确保状态一致性，模拟器遵循四条规则：数据一致性（跨轮次保持状态）、数据多样性（混合相关与无关项）、数据真实性（遵守字段约束）及模式合规性。

模拟器输出经过多层质量检查：首先程序化验证参数类型与缺失，随后由 LLM 裁判评估语义正确性与历史一致性。若发现错误，模拟器基于反馈重新生成，直至通过或达到重试上限。这一机制将模拟器从简单的响应生成器转变为持久化的状态维护者，确保多步交互中环境状态的连贯性。

## 实验评估

实验在 AppWorld（457 个 API，9 个应用）和 OfficeBench（20 个 API，8 个应用）上进行，微调 Qwen3 与 Qwen3.5 系列模型（1.7B-27B）。基线包括 GPT-4o、Nemotron-3-120B 及现有合成数据集（ToolAlpaca, ToolACE, Simia）。ESAT 数据显著优于现有合成数据集，在 AppWorld Test-N 上，Qwen3.5-9B 使用 ESAT-S52-AW7 数据达到 75.7%，超越 GPT-4o 的 48.8% 和 Nemotron 的 51.8%。

| 模型 | 数据源 | AppWorld Test-N | AppWorld Test-C | OfficeBench 2-app |
| :--- | :--- | :--- | :--- | :--- |
| Qwen3.5-9B | Zero-shot | 25.2 | 15.4 | 68.6 |
| Qwen3.5-9B | ESAT-S52-AW7 | 75.7 | 65.7 | 83.6 |
| Qwen3.5-9B | AWT | 71.2 | 53.8 | - |
| Qwen3-8B | ESAT-S52-AW7 | 64.9 | 49.1 | 73.8 |
| Simia (Qwen3-8B) | Simia | 53.2 | 26.6 | - |

消融实验显示，使用 Gemini-3.1-Pro 作为轨迹裁判优于 GLM-5.1-FP8，前者通过更激进地剔除低质量轨迹提升了下游性能。在 AppWorld 上，Gemini 过滤后的数据使 Qwen3-8B 的 Test-N 准确率从 61.7% 提升至 64.9%。此外，ESAT 数据在未见过的 API 域（ESAT-S52）上展现出强泛化能力，Qwen3-4B 使用纯合成 API 数据训练后，Test-N 准确率从 8.7% 提升至 51.8%，超越使用真实环境数据（AWT）的 46.7%。

评估边界方面，论文未报告计算效率指标（如 Token 消耗、延迟），且模拟器在长响应（>2K tokens）下的失败率升至 23%，表明长轨迹状态维护仍是瓶颈。代码未开源，超参数细节仅部分披露，可复现性受限。

## 关联研究分析

从问题动机看，ESAT 与 Simia 均旨在解决环境构建瓶颈，但 Simia 依赖种子轨迹进行增强，而 ESAT 从零生成任务与轨迹。这一差异源于 ESAT 对 LLM 世界知识作为状态源的更强依赖，使其无需预置数据即可启动，但代价是模拟器需承担更多状态推断责任，导致长轨迹中状态漂移风险增加。Simia 的 RL 训练阶段可能部分缓解此问题，而 ESAT 仅依赖 SFT，对数据质量更为敏感。

从方法设计看，ESAT 与 ToolACE 等早期模拟工作相比，核心改进在于支持写 API 与状态一致性校验。ToolACE 仅处理读操作，无法模拟状态变化，导致生成的轨迹缺乏长程依赖。ESAT 引入同应用历史上下文与 LLM 裁判反馈机制，将模拟器从静态响应生成器升级为动态状态维护者。然而，ESAT 未探索模拟器与真实环境的混合训练策略，当 API 行为复杂或状态空间巨大时，纯 LLM 模拟的保真度是否足以支撑复杂任务，论文未给出量化对比。

## 总结

ESAT 解决了 API 调用智能体训练数据依赖可执行环境的规模化瓶颈，通过 LLM 模拟状态变化实现了无环境数据生成。其核心贡献在于将轨迹合成转化为轻量级规格问题，验证了纯合成数据在复杂多步任务中的有效性，Qwen3.5-9B 在 AppWorld Test-N 上达到 75.7%，超越 GPT-4o 基线。然而，模拟器在长响应下的状态漂移（失败率 23%）及跨域泛化的边界条件仍未完全量化。当 API 状态空间复杂度超过 LLM 世界知识的覆盖范围时，纯模拟数据的保真度是否足以支撑高难度任务，论文未提供充分证据。
