# HuggingFace最新推荐论文 ｜AREX: Towards a Recursively Self-Improving Agent for Deep Research ｜递归自改进智能体

作者：Shuqi Lu、Chaofan Li、Kun Luo 等 24 人

论文原文见 [arXiv](https://arxiv.org/abs/2607.21461)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.21461)

> 深度研究智能体需同时满足多约束条件，但现有方法仅延长搜索轨迹，无法系统性识别未解决约束并定向修正。AREX 利用发现-验证不对称性，将部分验证的答案转化为下一轮研究目标，实现递归式状态更新。通过内层研究循环与外层自改进循环的交替执行，结合自主上下文更新工具，AREX 在 BrowseComp 等基准上取得 82.5% 的准确率，显著优于同规模基线。该框架验证了递归验证作为控制信号的有效性，但其对关键步骤标注的依赖及长程记忆压缩的潜在信息损失仍存疑。

## 研究背景

当智能体面对需同时满足多个耦合约束的深度研究任务时，传统 ReAct 范式（Yao et al., 2023）的“推理-行动-观察”循环面临根本性局限：延长搜索轨迹虽能扩大探索范围，但早期错误可能持续存在，已耗尽的方向可能被重复访问，部分有效的候选答案可能被过早接受。这一困境源于长程决策中的信用分配难题——稀疏的最终奖励无法揭示哪些中间动作产生了决定性进展，导致训练效率低下且难以优化长程策略。同时，交互历史中积累的冗余观察、过时计划与冲突证据会干扰后续推理，而固定启发式上下文管理（如按 token 阈值截断）往往丢弃决策相关的负证据与未解决约束，加剧执行漂移。

现有解决方案分为两类：一类通过强化学习（RL）优化轨迹级奖励，如 Search-R1 将网络导航建模为序列决策，但轨迹级监督将所有步骤视为同等贡献，无法区分关键决策与冗余操作；另一类采用多智能体架构显式管理记忆与规划，如 WebWeaver 的双智能体框架，但系统复杂度高且依赖外部模型进行摘要压缩。AREX 的切入点在于利用深度研究任务中固有的发现-验证不对称性：发现满足所有约束的答案需导航稀疏且信息量大的搜索空间，成本高昂；而验证候选答案可分解为简单的逐约束检查，成本低廉。这一不对称性使得验证不仅能判断答案正确性，还能揭示哪些主张已获支持、哪些未解决、证据冲突何在，从而将验证转化为驱动递归改进的主动控制信号。

## 核心方法

### 递归自改进框架

AREX 将深度研究形式化为双层递归过程，区别于传统单轨迹搜索。内层研究循环执行搜索、浏览等动作，整合证据并构建临时答案；外层自改进循环基于答案级置信度分数 $s_{[k]} \in [0, 100]$ 评估临时结果。若 $s_{[k]}$ 超过阈值，答案被接受；否则，循环评估当前轨迹是否可恢复：有用发现被保留并转化为针对性目标 $q_{[k+1]}$，用于验证未支持约束、解决冲突证据或检查时间有效性。该设计解决了传统方法中“搜索更长但不保证系统性进展”的失效，使智能体能基于部分验证状态定向修正，而非盲目扩展搜索空间。

### 自主上下文更新

内层循环中，交互轨迹 $h_{t}^{[k]}$ 随时间积累冗余信息。AREX 引入 $update\_context$ 工具，由模型自主决定何时将轨迹压缩为紧凑的改进状态 $\bar{h}_{t}^{[k]}$。该状态保留已验证发现及其来源标识、当前候选、未解决约束、有效性顾虑、被拒候选及下一步计划，移除冗余观察与过时结论。设计动机在于固定启发式（如按 token 阈值触发摘要）将上下文管理视为预算控制问题，而非研究状态维护问题，可能丢弃负证据与约束满足状态。AREX 的自主更新机制使压缩状态与智能体当前研究目标对齐，避免重复访问已失效候选或丢失后续验证所需信息。

### 关键步骤监督

长程轨迹中，最终奖励无法揭示哪些中间动作产生决定性进展。AREX 识别并增加关键步骤（key steps）的训练曝光，包括证据获取、矛盾解决或错误方向修正的步骤。对于每个助手步骤 $s_{i,j}$，定义关键步骤指示器 $B_{i,j}$，仅当轨迹级结果有效时应用关键步骤奖励，避免奖励虚假的中间行为。该设计解决了轨迹级 RL 中信用分配稀疏的问题，使模型能区分决策关键步骤与常规操作，提升长程策略优化效率。

## 实验评估

AREX 在 BrowseComp、GAIA、xbench-2510、DeepSearchQA、WideSearch-en 及 HLE（工具）六个基准上评估，覆盖深度搜索、宽搜索、多约束信息获取及工具推理。基线包括前沿闭源模型（GPT-5.4、Gemini-3.1-Pro）及开源模型（Kimi-K2.6、DeepSeek-V4-Pro、Qwen3.5 系列），但未包含早期纯提示工程基线（如 ReAct 原版）。AREX-Base（122B-A10B MoE）在 BrowseComp 上取得 82.5% 准确率，GAIA 上 85.4%，WideSearch-en 上 82.0%，显著优于同规模 Qwen3.5-397B（BrowseComp 78.6%）及多数开源基线。AREX-Turbo（4B 稠密模型）在五个基准上优于 Qwen3.5-35B，验证了框架在小规模模型上的有效性。

消融实验揭示三个关键设计决策的贡献。将渐进式多轮能力训练替换为直接混合训练，BrowseComp 准确率从 82.5% 降至 77.5%，表明分阶段获取工具使用与推理能力可减少异质训练目标间的干扰。用随机步骤重放替换关键步骤聚焦监督，准确率降至 74.1%，为最大降幅，证实对决策关键步骤的额外监督比任意中间动作更有效。用标准 GRPO 替换步骤感知 RL，准确率降至 79.4%，表明步骤感知策略优化在中期训练建立主要能力后进一步细化研究策略。此外，自主上下文更新（ACU）在单轮设置下将 BrowseComp 准确率从 59.6% 提升至 71.4%，外层自改进循环在此基础上再提升 11.1 点至 82.5%，验证了递归验证机制的累积收益。

评估协议采用统一长程搜索智能体接口，包含 search、visit、update context 及 finish 工具，HLE 额外添加 python 工具。每个 episode 允许最多 300 个内层研究循环轮次和 5 个外层自改进循环操作。指标方面，WideSearch 报告 Item-F1，DeepSearchQA 报告 F1，其余基准报告准确率。论文未报告置信区间，且未提供完整代码仓库 URL，仅给出 HuggingFace 模型链接。评估边界在于：关键步骤标注依赖人工或半自动识别，未探索自动识别方法；ACU 的压缩策略可能丢失关键负证据，论文未量化此风险；实验聚焦文本搜索，未涉及多模态场景。

## 关联研究分析

从问题动机看，AREX 与 ABSeeker（Lu et al., 2026）均关注步骤级信用分配，但 ABSeeker 依赖答案回溯线索恢复中间证据，需验证答案可用性且计算开销大；AREX 则通过关键步骤标注与 RL 直接优化决策关键步骤，无需依赖最终答案的可用性，更适合开放式任务。这一差异源于任务特性：ABSeeker 适用于有明确验证答案的场景，而 AREX 的递归验证机制允许在答案未完全确定时进行部分验证，更契合深度研究中约束逐步满足的过程。

从方法设计看，AREX 与 ASearcher（ICLR 2026）均采用大规模端到端 RL，但 ASearcher 侧重数据合成（迭代修改问题、注入事实并模糊化），AREX 侧重递归验证与状态管理。ASearcher 证明端到端 RL 在长程搜索中的有效性，但缺乏对中间状态的显式管理；AREX 的自主上下文更新工具解决了长程交互中信息过载问题，使模型能在压缩状态下保持研究目标一致性。与 WebWeaver 的双智能体框架相比，AREX 将规划与验证内化为单模型的递归循环，避免了多智能体通信开销，但牺牲了显式规划的透明性。递归自改进在开放式报告生成任务上是否仍优于显式规划架构，论文未给出回答。

## 总结

AREX 解决的核心矛盾是长程深度研究中信用分配稀疏与执行漂移的耦合问题，现有方法或依赖轨迹级奖励无法区分关键步骤，或依赖固定启发式上下文管理丢失决策相关信息。AREX 抓住发现-验证不对称性这一被忽略的点，将验证转化为递归控制信号，通过内层研究循环与外层自改进循环的交替执行，结合自主上下文更新工具，实现部分验证状态的定向修正。实验证明该框架在 BrowseComp 上取得 82.5% 准确率，GAIA 上 85.4%，显著优于同规模基线。其边界在于关键步骤标注的依赖性及 ACU 压缩策略的潜在信息损失，当支持集增大或任务复杂度提升时，关键步骤的自动识别与压缩策略的鲁棒性是否仍能维持递归改进的有效性，论文未给出回答。
