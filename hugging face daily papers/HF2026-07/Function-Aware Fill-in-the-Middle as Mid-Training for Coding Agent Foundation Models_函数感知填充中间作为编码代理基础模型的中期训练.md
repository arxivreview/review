# HuggingFace最新推荐论文 ｜Function-Aware Fill-in-the-Middle as Mid-Training for Coding Agent Foundation Models ｜函数感知填充中间作为编码代理基础模型的中期训练

研究机构：加拿大滑铁卢大学、加拿大不列颠哥伦比亚大学

论文原文见 [arXiv](https://arxiv.org/abs/2607.12463)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.12463)

> 导读 大语言模型软件工程智能体（LLM Agents for Software Engineering）在解决真实仓库级问题时，常因基础模型缺乏对代理交互结构的归纳偏置，导致后训练效率低下且易引发通用能力侵蚀。现有方法多依赖合成轨迹数据直接进行后训练，忽略了预训练与后训练之间的结构性对齐空白。本文提出函数感知填充中间（Function-Aware Fill-in-the-Middle, FIM）中期训练，利用程序依赖图选择掩码目标，使模型学习函数级依赖以模拟代理的动作-观察-继续循环。该研究通过自监督目标在预训练后、代理特定数据引入前对齐基础模型，为后续代理训练提供更优起点。其价值在于验证了函数调用与代理交互的结构同构性，但跨语言泛化能力及对闭源教师模型的依赖仍是存疑之处。

## 研究背景

当编码代理在真实软件仓库中执行任务时，其核心工作流表现为一个循环：维护历史上下文、采样动作、接收外部工具返回的观测值，并基于完整轨迹继续推理。这一过程要求模型具备双向推理能力，即从调用者上下文和下游使用情况中重建被调用者的行为。然而，标准的从左到右预训练仅暴露了代码的前向生成方向，导致基础模型在代理所需的条件结构上存在系统性欠拟合。这种结构性缺失使得模型在后续代理后训练中难以高效吸收交互逻辑，且容易在长程多轮交互中陷入循环或丢失关键信息。

当前领域的主流路线聚焦于后训练阶段的数据增强，如 SWE-Gym 和 SWE-Smith 通过合成或整理代理轨迹数据来提升模型性能。这些方法假设基础模型已具备处理复杂依赖的潜力，仅通过模仿人类或大模型行为来优化策略。然而，这种范式存在两个瓶颈：一是高质量轨迹数据稀缺且标注成本高，开源模型难以通过大规模监督微调达到闭源模型水平；二是任务特定的后训练往往以牺牲非目标能力为代价，导致模型在通用代码生成或工具使用基准上的性能显著下降。本文的切入点在于填补预训练与后训练之间的空白，认为代理所需的归纳偏置已存在于普通代码中，但需要通过特定的自监督目标在中期训练阶段显式提取。

## 核心方法

### 方法参照系

本文的方法置于“训练与数据增强”路线的变体中，区别于传统的后训练数据合成，它在预训练与代理后训练之间插入了一个专用的中期训练阶段。该阶段的目标不是直接优化任务解决率，而是通过自监督目标对齐基础模型与代理相关的归纳偏置。与通用代码预训练不同，本文问题要求模型在掩码区域不仅生成代码，还需生成与最终代码一致的推理过程，以镜像代理的“思考-行动”模式。

### 函数感知 FIM 目标选择

传统随机跨度 FIM 的掩码边界在语法上是任意的，且缺乏推理监督，导致其无法有效捕捉函数级依赖。本文在目标选择环节引入程序依赖图（Program Dependency Graph, PDG）分析，通过复杂度与可推断性双重标准筛选掩码目标。设计动机在于确保掩码区域是代理相关推理的单元，而非随机的语法子树。

对于每个函数节点 $v$，复杂度得分 $\hat{H}$ 和可推断性得分 $\hat{I}$ 分别量化了函数的内在难度和从上下文恢复的可行性。最终选择得分 FIM 采用调和平均形式，并乘以难度惩罚项 $\rho$：

$$ \text{FIM}(v) = \rho(\Delta(v)) \cdot \frac{\hat{H}(v) \cdot \hat{I}(v)}{\hat{H}(v) + \hat{I}(v)} $$

该公式强制要求目标函数同时具备高复杂度和高可推断性，避免选择过于简单或完全不可恢复的噪声样本。通过设定阈值 $\tau$，仅保留得分高于阈值的函数作为掩码目标，从而在数据层面过滤掉对代理训练无益的片段。

### 链式思维增强与格式构造

在选定掩码目标后，本文在 FIM 中间跨度内嵌入链式思维（Chain-of-Thought, CoT）推理，以解决传统 FIM 缺乏推理监督的问题。设计动机在于使模型生成的推理过程与最终代码保持一致，模拟代理在采取行动前的规划步骤。

具体而言，利用 Gemini-3-Flash 生成仅基于掩码文件的推理理由和候选函数体，并通过独立评判器过滤低质量样本。最终训练样本格式化为：

$$ \text{<fim\_prefix>} \langle \text{prefix} \rangle \text{<fim\_suffix>} \langle \text{suffix} \rangle \text{<fim\_middle>} \langle \text{rationale} \rangle \langle \text{body} \rangle $$

模型被训练为在给定前后文的情况下，先生成推理理由，再生成函数体。这种格式构造将结构先验与推理监督结合，使模型在中期训练阶段即建立起“上下文-动作-观察-继续”的映射关系，为后续代理后训练奠定表示基础。

## 实验评估

实验在 SWE-Bench-Verified 和 SWE-Bench-Lite 上进行，基线覆盖 R2E-Gym 和 SWE-Smith 等主流后训练管线。主结果显示，在 Qwen2.5-Coder-7B-Instruct 上，加入 FIM 中期训练后，SWE-Bench-Verified 准确率从 15.00% 提升至 17.80%，SWE-Bench-Lite 从 11.33% 提升至 15.00%。在 14B 模型上，Verified 准确率从 26.20% 提升至 29.20%。跨管线对比显示，与 SWE-Smith 结合时，Verified 提升幅度达 +5.30 个百分点，表明该结构先验不依赖于特定后训练数据分布。

| 设置 | SWE-Bench-Verified (%) | SWE-Bench-Lite (%) | 平均 (%) |
| --- | --- | --- | --- |
| Qwen2.5-Coder-7B-Instruct + R2E-Gym | 15.00 | 11.33 | 13.17 |
| **Qwen2.5-Coder-7B-Instruct + FIM-Midtrain + R2E-Gym** | **17.80** | **15.00** | **16.40** |
| Qwen2.5-Coder-14B-Instruct + R2E-Gym | 26.20 | 18.00 | 22.10 |
| **Qwen2.5-Coder-14B-Instruct + FIM-Midtrain + R2E-Gym** | **29.20** | **22.00** | **25.60** |

消融实验揭示了函数选择算法是主要增益来源。随机掩码仅带来 13.95% 的平均准确率，而完整 PDG 选择策略达到 15.60%。移除 CoT 后，平均准确率降至 14.35%，表明 FIM 结构本身贡献了约一半的增益，CoT 蒸馏贡献了剩余部分。掩码粒度方面，80% 单函数 + 15% 双函数 + 5% 三函数的混合策略表现最优，平均准确率达 16.10%，证实了跨函数依赖训练对多文件补丁任务的必要性。

| 设置 | SWE-Bench-Verified (%) | SWE-Bench-Lite (%) | 平均 (%) |
| --- | --- | --- | --- |
| w/o mid-train (baseline) | 15.00 | 11.33 | 13.17 |
| + FIM, no CoT | 16.10 | 12.60 | 14.35 |
| + FIM, Gemini-3-Flash CoT | 17.00 | 14.20 | 15.60 |
| **Full (PDG + H + I)** | **17.00** | **14.20** | **15.60** |

评估边界方面，本文仅使用 Python 代码进行中期训练，跨语言泛化能力未直接验证。此外，CoT 生成依赖 Gemini-3-Flash，完全开源复现需同等强度的开源教师模型。尽管提供了代码和检查点，但中期训练的具体超参数和计算资源消耗未在正文中详细披露，可能影响复现精度。

## 关联研究分析

从问题动机看，本文与 SWE-Gym 和 SWE-Smith 存在显著差异。SWE-Gym 和 SWE-Smith 聚焦于后训练阶段的数据合成，通过增加轨迹数量来提升模型性能，假设基础模型已具备处理复杂依赖的潜力。本文则认为基础模型缺乏针对代理条件结构的归纳偏置，导致后训练效率低下。这种差异源于对“数据稀缺”与“结构缺失”的不同归因：前者认为数据量不足，后者认为数据分布与模型先验不匹配。本文通过中期训练显式注入结构先验，可能降低后训练对大量轨迹数据的依赖，但这一假设在数据充足场景下的增益是否递减，论文未给出回答。

从方法设计看，本文与 AST-FIM 和 GraphCoder 存在关联但侧重点不同。AST-FIM 和 GraphCoder 利用程序结构进行掩码或检索，但 AST-FIM 仍属于预训练目标，GraphCoder 属于推理时检索。本文将结构感知目标置于中期训练阶段，并嵌入 CoT 推理，使其更贴合代理的“思考-行动”模式。这种设计选择解决了传统 FIM 缺乏推理监督的问题，但引入了对教师模型的依赖。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文要解决的核心矛盾是基础模型缺乏代理交互所需的结构归纳偏置，导致后训练效率低且易引发能力侵蚀。本文抓住函数调用与代理交互的结构同构性，提出函数感知 FIM 中期训练，通过 PDG 选择掩码目标并嵌入 CoT 推理。实验证明该方法在 Qwen2.5-Coder-7B 上使 SWE-Bench-Verified 准确率提升 2.80 个百分点，并有效缓解了后训练带来的通用能力下降。本文的边界在于仅验证了 Python 代码的跨域迁移，且依赖闭源教师模型生成 CoT。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
