# HuggingFace最新推荐论文 ｜A Sovereign, Open-Source Foundation Model for German and English ｜主权全开源混合架构模型

研究机构：德国人工智能研究中心、德国达姆施塔特工业大学

论文原文见 [arXiv](https://arxiv.org/abs/2607.09424)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.09424)

> 高效开源大语言模型领域长期受困于“开放洗白”争议与长上下文推理的内存带宽瓶颈，仅公开权重的模型无法支撑科学复现，而全注意力架构在高并发下因键值缓存膨胀导致吞吐量断崖式下跌。Soofi S 通过复用 Nemotron 3 Nano 的 Mamba-MoE 混合架构并实施德语加权的全开源预训练配方，在保持每序列状态近常数的前提下，实现了主权语言性能与推理能效的双重突破。该工作验证了混合架构在长上下文部署中的结构性优势，但其性能上限仍受限于 3B 激活参数规模，且未提供针对商业许可数据的去污染审计细节。

## 研究背景

当大语言模型进入生产部署阶段，推理成本不再由参数量决定，而是由内存带宽主导：每个解码 token 需重读模型权重及批处理中所有序列的键值（Key-Value, KV）缓存。随着上下文长度扩展至数十万 token，全注意力模型的 KV 缓存成为显存瓶颈，导致吞吐量随上下文增长而急剧衰减。这一物理约束使得传统密集 Transformer 架构在长上下文、高并发场景下缺乏竞争力，而 Mamba 等状态空间模型虽能维持固定大小的递归状态，却缺乏成熟的稀疏激活机制来平衡容量与效率。

高效开源大语言模型领域的核心矛盾在于透明性、性能与成本的三角平衡。早期开放权重模型（如 LLaMA）因隐藏训练数据与配方引发“开放洗白”争议，阻碍了数据污染审计与科学复现；而全开源模型（如 OLMo）虽确立了公开数据、代码及配方的新范式，但多采用纯 Transformer 架构，在长上下文推理能效上存在固有缺陷。同时，通用多语言模型往往英语中心或能力分散，导致德语等经济权重语言的代表性不足。Soofi S 的切入点在于：通过混合 Mamba-2 与混合专家（Mixture-of-Experts, MoE）架构解决推理能效问题，并通过全链路透明的德语加权预训练配方，在主权语言性能与部署成本之间取得平衡。

## 核心方法

### 混合 Mamba-MoE 架构参照系

Soofi S 采用 Nemotron 3 Nano 参考设计，构建 52 层网络，其中 23 层为 Mamba-2 序列混合层，23 层为细粒度 MoE 层，6 层为分组查询注意力（Grouped-Query Attention, GQA）层。该架构的关键差异在于：仅 6 层 GQA 维护 KV 缓存，其余 46 层通过 Mamba-2 的固定大小递归状态处理序列混合，从而将每序列缓存大小从随上下文线性增长降至近常数。这一设计直接回应了全注意力模型在长上下文下 KV 缓存主导内存带宽的失效问题。

### 稀疏激活与状态恒定机制

MoE 层通过路由机制将每个 token 分配至 31.6B 总参数中的 3.2B 激活专家，实现“30B 容量、3B 推理成本”的解耦。Mamba-2 层利用选择性扫描机制，其状态维度固定为 128，不随序列长度扩展。该设计动机在于：传统 Transformer 的注意力计算复杂度为 $O(N^2)$，且 KV 缓存占用显存为 $O(N)$，而 Mamba-2 的递归状态更新可表示为：

$$ h_t = A h_{t-1} + B x_t $$

其中 $h_t$ 为固定维度状态，$x_t$ 为当前输入。这一公式表明，无论上下文长度 $N$ 如何增长，状态 $h_t$ 的存储开销保持恒定，从而在解码阶段避免了 KV 缓存的重复读取，从根本上缓解了内存带宽瓶颈。

### 三阶段德语加权预训练课程

预训练采用 Warmup-Stable-Decay (WSD) 学习率调度，分为三阶段：Phase 1（20T tokens）最大化数据多样性，Phase 2（5T tokens）退火至高质量数据并将德语比例上调至 15.3%，Phase 3（188B tokens）通过长度分桶上采样扩展上下文至 1M tokens。该设计动机在于：静态数据混合无法兼顾多样性与技能聚焦，而课程学习策略通过动态调整数据分布，使模型在退火阶段集中学习高价值代码、数学及德语推理数据，缩短了指令微调阶段的分布偏移。数据混合比例可形式化为：

$$ \mathcal{D}_{phase} = \sum_{i} \alpha_i D_i $$

其中 $\alpha_i$ 为各数据源 $D_i$ 的有效 token 占比。Phase 2 中德语占比从 Phase 1 的 7.2% 提升至 15.3%，这一非线性加权策略直接针对德语经济权重与现有模型英语中心化的失衡问题。

## 实验评估

实验在 15 个开源基线模型上进行，涵盖 Alia 40B、EuroLLM 22B、Apertus 70B 及 Olmo 3 32B 等欧洲主权模型，以及 Qwen3.5、Gemma 3 等国际模型。评估协议采用统一 harness，排除 GPQA 及撤回的保留基准组，确保公平性。Soofi S 在英语与德语综合基准上均位列全开源模型第一，其中德语综合得分 85.3%，英语综合得分 77.3%，显著超越 Olmo 3 32B 的 74.7% 与 75.8%。

| 基准 | Soofi S 30B-A3B | Olmo 3 32B | Apertus 70B | EuroLLM 22B |
| :--- | :--- | :--- | :--- | :--- |
| 英语综合 | 77.3 | 75.8 | 71.1 | 68.9 |
| 德语综合 | 85.3 | 74.7 | 79.4 | 76.7 |
| HumanEval | 73.8 | 63.0 | 30.2 | 39.3 |
| MBPP-DE | 84.2 | 70.8 | 50.9 | 59.4 |
| GSM8K | 86.1 | 80.7 | 65.4 | 25.1 |

在长上下文推理能效方面，Soofi S 在 40K 上下文、batch 32 条件下实现 4.82k TPS/GPU 的解码吞吐量，是 Ministral 3 14B 的 9.2 倍。吞吐量计算公式为：

$$ \text{TPS}_{agg/GPU} = \frac{B (O_{long} - O_{short})}{N_{GPU} [t(O_{long}) - t(O_{short})]} $$

其中 $O_{short}=1, O_{long}=1024$，该减法协议剔除了预填充成本，隔离了缓存带宽压力。Soofi S 的吞吐量在 4K 至 256K 上下文范围内保持近常数（4.29k 至 4.30k TPS/GPU），而密集模型吞吐量随上下文增长显著下降，验证了混合架构的结构性优势。

评估边界方面，论文未报告置信区间，且未对比 GPT-4o 等专有模型以量化绝对差距。可复现性方面，Soofi S 发布了完整训练代码、超参数及逐源数据统计，但商业许可数据 Genios 仅公开聚合统计，未提供原始文本，限制了完全复现。德语基准优势是否源于数据污染，论文未提供去污染审计细节，这一缺失在主权模型评估中构成潜在风险。

## 关联研究分析

从问题动机看，Soofi S 与 OLMo 3 同属全开源路线，但 OLMo 3 采用纯 Transformer 架构，其 KV 缓存随上下文线性增长，导致长上下文推理能效受限。Soofi S 引入 Mamba-2 层将每序列状态固定，这一架构选择并非源于数据策略差异，而是对推理物理约束的直接响应。然而，Mamba-2 在复杂多步推理任务上的表现是否优于全注意力机制，论文未提供消融实验，仅通过基准分数间接推断，这一盲区可能掩盖了混合架构在特定推理模式下的局限性。

从方法设计看，Soofi S 与 PuRo-2B 同属低成本预训练路线，但 PuRo-2B 侧重硬件适配与优化器效率，而 Soofi S 侧重架构-数据协同优化。Soofi S 的德语加权策略（15.3%）远高于 PuRo-2B 的通用数据混合，这一差异源于主权语言的经济权重约束，而非通用性能优化。然而，德语性能提升是否以牺牲英语通用能力为代价，论文未提供同参数量纯英语模型的对照实验，仅通过综合分数间接比较，这一缺失使得语言间的能力权衡无法被精确量化。

## 总结

Soofi S 旨在解决主权语言模型在透明性、性能与推理能效上的三角平衡矛盾。其切入点在于复用成熟的 Mamba-MoE 混合架构，通过固定状态机制规避 KV 缓存瓶颈，并实施德语加权的全开源预训练配方，从而在 3B 激活参数规模下实现 30B 容量模型的推理成本。实验证明，Soofi S 在德语综合基准上以 85.3% 超越 Olmo 3 32B 的 74.7%，并在 40K 上下文下实现 4.82k TPS/GPU 的吞吐量，是密集模型的 9.2 倍。然而，其性能上限受限于 3B 激活参数，在复杂推理任务上仍落后于大模型，且商业许可数据的去污染审计缺失构成主权模型评估的潜在风险。当上下文长度进一步扩展至 1M tokens 时，Mamba-2 的固定状态机制是否仍能维持推理稳定性，论文未提供长上下文下的精度衰减曲线，这一边界条件尚待验证。
