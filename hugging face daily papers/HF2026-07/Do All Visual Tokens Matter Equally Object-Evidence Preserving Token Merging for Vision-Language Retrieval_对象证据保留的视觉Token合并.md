# HuggingFace最新推荐论文 ｜Do All Visual Tokens Matter Equally? Object-Evidence Preserving Token Merging for Vision-Language Retrieval ｜对象证据保留的视觉Token合并

研究机构：韩国高丽大学

论文原文见 [arXiv](https://arxiv.org/abs/2607.04605)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.04605)

> 多向量视觉语言检索通过保留图像侧Token级嵌入实现细粒度匹配，但海量Token导致索引存储与打分延迟激增。现有压缩方法仅关注减少Token数量，却可能坍缩不同物体实例的特征，致使查询无法定位关键证据。SaMer将压缩重构为证据保留问题，利用训练时物体标注引导软分配合并，在推理时免标注地压缩至64个Token。该方法在Flickr30K上将R@1从77.0提升至82.4，但其在文档密集场景的适用性及对标注质量的依赖尚存疑。

## 研究背景

多向量检索的核心机制是延迟交互（Late Interaction）。与单向量模型将图像压缩为单一全局嵌入不同，多向量模型（如ColPali）保留图像侧数百至数千个Patch级嵌入，通过最大相似度（MaxSim）匹配查询Token与最相似的视觉Token。这种机制使检索对物体、属性和关系敏感，但代价是索引存储量与查询打分计算量随视觉Token数量线性增长。当索引规模扩大时，内存占用与I/O延迟成为大规模图像搜索与检索增强视觉问答（RAG-VQA）的主要瓶颈。

视觉Token压缩是降低上述开销的直接手段，主流路线包括剪枝（Pruning）与合并（Merging）。剪枝直接丢弃低重要性Token，合并则将相似Token聚合为质心。然而，生成式视觉语言模型（VLM）中的Token压缩旨在降低Transformer内部计算复杂度，而检索场景的压缩面临独特约束：Patch重要性是查询依赖的（Query-dependent）。同一图像中，不同查询可能依赖微小物体、特定属性或空间关系。若压缩过程错误地合并了不同实例的相似Patch，或丢弃了稀疏但关键的证据，MaxSim将无法恢复支撑匹配的Token。现有基于特征相似度的合并方法（如H-Pool）忽略了物体实例边界，导致“对象实例坍缩”（Object-Instance Collapse），即不同实例的相似特征被合并为同一表示，丢失了查询所需的区分度。SaMer的切入点在于将压缩目标从“减少冗余”转向“保留可查询证据”，通过引入物体感知约束防止跨实例合并。

## 核心方法

### 方法参照系

SaMer置于多向量检索索引压缩的通用框架下。标准流程为：视觉编码器提取Patch特征 → 投影层映射至共享检索空间 → 存储全量Token → MaxSim打分。本文的关键差异在于，压缩发生在投影层之后（Post-projector），且必须保持MaxSim接口不变。与生成式VLM中在Transformer层间动态剪枝不同，SaMer是缓存时（Cache-time）压缩，仅替换存储的图像侧表示，不修改编码器或打分规则。

### 特征-空间软分配合并

传统合并方法仅基于特征相似度聚类，导致空间上分离但特征相似的物体被错误合并。SaMer在合并距离中引入空间坐标约束，防止视觉相似但空间遥远的区域过度合并。给定$N$个投影后视觉Token $\{v_i\}$，每个Token关联空间坐标 $p_i \in [0,1]^2$。SaMer将Token分配至$K$个代表元，距离定义为特征距离与空间距离的加权和：

$$ d(i,k) = \|v_i - \mu_k\|_2^2 + \gamma \|p_i - s_k\|_2^2 $$

其中 $\mu_k, s_k$ 为第$k$个代表元的特征与空间质心，$\gamma$ 控制空间项强度。Token通过软分配权重 $a_{i,k}$ 聚合为归一化加权质心 $r_k$。这一设计确保了合并后的代表元在特征空间与空间结构上均保持局部一致性，避免了纯特征合并导致的空间语义丢失。

### 物体感知合并先验

纯特征-空间合并仍可能将不同实例的相似物体合并。SaMer在训练阶段引入物体边界框（BBox）标注作为合并先验（Merge Prior），而非辅助损失。对于每个Token，根据其空间坐标分配BBox标签 $b_i$。通过停止梯度（Stop-gradient）的硬分配估计每个代表元的BBox标签分布，并计算跨实例惩罚项：

$$ \mathcal{L}_{obj} = \sum_{i,k} a_{i,k} \cdot \mathbb{1}[b_i \neq \text{dominant}(k)] $$

该惩罚项在软分配距离中增加，降低跨实例分配的权重。推理时，SaMer无需BBox或检测器，仅执行无标注的特征-空间软分配。物体感知先验的效果通过投影层适配内化至检索空间，使压缩后的Token在MaxSim匹配中保留物体级证据。

### 投影层专用适配

小$K$压缩导致压缩表示与原检索空间不匹配。SaMer冻结视觉编码器与语言骨干，仅训练共享投影层。通过多正例InfoNCE损失优化压缩MaxSim分数：

$$ \mathcal{L} = -\log \frac{\exp(S_K(q, I^+)/\tau)}{\sum_{I \in B} \exp(S_K(q, I)/\tau)} $$

其中 $S_K$ 为基于$K$个合并Token的MaxSim分数。此适配使投影层学习生成对合并鲁棒的特征，确保压缩Token在检索空间中保持可区分性。

## 实验评估

实验在Flickr30K、MSCOCO、ImageCoDe和DocVQA上进行，基线覆盖单向量（CLIP, SigLIP2）、VLM-based（GME, VisRAG）及多向量压缩方法（H-Pool, SAP, HPC）。SaMer在ColPali与ColQwen2骨干上均取得最优性能。

| 方法 | Flickr30K R@1 | MSCOCO R@1 | ImageCoDe R@1 | DocVQA R@1 |
| :--- | :--- | :--- | :--- | :--- |
| ColPali (Full) | 77.0 | 47.4 | 5.4 | 51.0 |
| H-Pool | 73.7 | 52.5 | 5.6 | 45.0 |
| SAP | 68.3 | 44.9 | 3.8 | 40.4 |
| SaMer (w/ FT) | **82.4** | **51.6** | **5.9** | 45.7 |
| ColQwen2 (Full) | 73.6 | 43.3 | 4.7 | 53.2 |
| SaMer (w/ FT) | **79.3** | **47.5** | **5.1** | 48.8 |

SaMer在Flickr30K上将ColPali的R@1从77.0提升至82.4，显著优于最强压缩基线H-Pool（73.7）。在ImageCoDe这一组合检索基准上，SaMer同样取得最高R@1（5.9），验证了其在区分细微物体差异时的有效性。然而，在DocVQA上，SaMer（45.7）低于ColPali全量（51.0），表明对象感知合并不适用于依赖稀疏OCR文本与布局覆盖的文档场景。

消融实验显示，物体感知先验是性能增益的主要来源。仅使用特征-空间合并（无物体先验）时，Flickr30K R@1为80.4；加入物体先验后提升至82.4。空间项单独贡献有限（R@1从80.7降至80.4），表明局部平滑性不足以替代物体身份约束。Token预算分析表明，$K=64$时R@5达到96.3，$K=512$时仅增至96.8，边际收益递减，证实少量合并Token足以保留大部分检索性能。

评估边界方面，论文未报告置信区间，且DocVQA结果暴露了方法在文本密集场景的局限。代码已开源，但物体标注依赖Flickr30KEntities训练集，未验证在无标注数据上的泛化能力。

## 关联研究分析

从问题动机看，SaMer与生成式VLM中的Token剪枝方法（如FastV, VisionZip）存在根本差异。后者基于注意力分数或显著性丢弃Token，旨在降低Transformer计算复杂度；SaMer则基于物体实例边界合并Token，旨在保留MaxSim可查询证据。这一差异源于任务特性：生成式任务中Token重要性由当前上下文决定，而检索任务中Token重要性由未来未知查询决定。SaMer的物体感知先验解决了特征合并导致的实例坍缩问题，但引入了对训练时标注的依赖。

从方法设计看，SaMer与H-Pool等纯特征池化方法形成对比。H-Pool通过模态无关的固定预算池化减少Token，但忽略了物体结构；SaMer通过物体感知软分配保留结构，但需额外标注。ToMe（Bolya et al., 2023）的软分配合并机制被SaMer借鉴，但ToMe用于生成式模型内部，SaMer用于检索索引构建。SaMer的投影层适配策略与HPC-ColPali的量化+剪枝组合不同，后者侧重编码效率，SaMer侧重表示质量。

## 总结

SaMer针对多向量检索中Token压缩导致的对象证据丢失问题，提出物体感知合并框架。其核心在于将训练时物体标注作为合并先验，防止跨实例坍缩，并通过投影层适配保持检索空间兼容性。实验表明，$K=64$时SaMer在Flickr30K上R@1达82.4，较ColPali全量提升5.4个点，同时存储减少16.09倍。然而，DocVQA结果（45.7 vs 51.0）暴露了方法在文本密集场景的失效，且物体感知先验依赖训练时标注，限制了无标注场景的应用。当查询依赖非物体级证据（如布局、文本）时，物体感知合并是否仍优于纯特征池化，论文未给出回答。
