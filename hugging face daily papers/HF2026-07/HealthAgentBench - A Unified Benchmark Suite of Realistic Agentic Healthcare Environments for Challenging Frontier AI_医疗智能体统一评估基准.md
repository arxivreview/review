> 临床智能体评估长期受限于静态问答与单一模态基准，无法反映真实工作流中多步交互与原始数据操作的复杂性。现有基准要么局限于文本对话，要么仅覆盖特定临床场景，缺乏统一的多模态可执行环境。本文通过构建包含54个任务、7个类别的终端化基准套件，强制智能体在隔离环境中自主探索并操作CT、病理切片及EHR等原始数据。该基准揭示了当前前沿模型在复杂医疗任务上的显著短板，但受限于任务规模与特定模态覆盖，其结论的普适性仍需更多实证支持。

## 研究背景

临床智能体评估的核心困境在于数据规模与模型上下文窗口的物理矛盾。真实临床工作流涉及3D CT体积、千兆像素病理切片及纵向电子健康记录（EHR），这些数据的体量远超单次提示词（Prompt）的承载极限。传统基准如MedQA仅评估基于简短临床摘要的单轮问答，无法考察智能体在数据超出上下文窗口时，通过工具调用、代码执行与环境交互进行多步推理的能力。这种评估范式的缺失，导致模型在静态考试中的高分无法转化为真实临床工作流中的可靠性。

医疗智能体评估领域已形成三条主要路线：静态问答、对话模拟与可执行环境。静态问答路线（如MedAgentBoard）侧重知识检索，对话模拟路线（如HealthBench）侧重医患沟通，而可执行环境路线（如MedAgentBench、PhysicianBench）虽引入了真实数据操作，但各自局限于单一模态或特定临床阶段。这种碎片化使得研究者难以在统一标准下比较不同智能体架构在跨模态、长程任务中的综合表现。HealthAgentBench的切入点在于整合上述路线的长处，构建一个覆盖患者全旅程、多模态且具备防作弊机制的统一评估套件，以填补当前评估体系中“端到端自主操作能力”的测量空白。

## 核心方法

### 评估范式参照系

本文问题归属于可执行环境智能体评估类别。通用流程为：提供隔离环境、最小化指令、隐藏标签与验证器。本文的关键差异在于将“终端交互”作为唯一接口，强制智能体通过代码与命令操作原始数据，而非通过预设API或自然语言对话，从而剥离提示工程技巧，直接测量原生规划与执行能力。

### 多模态任务构造与防作弊机制

设计动机在于解决现有基准中“数据泄露”与“任务简化”导致的评估失真。在任务构造上，HealthAgentBench采用“规则注入”与“基准重构”双源策略。对于EHR数据质量审计，通过向MIMIC-IV注入生理值矛盾等规则扰动生成新任务；对于EHR事件建模，将原为人类研究者设计的EHRSHOT基准重构为智能体需自主完成从数据探索到模型训练的全流程。防作弊机制通过构造性隔离实现：黄金标签与验证代码仅挂载于验证步骤，智能体容器内标识符被去标识化（如`case_NN`），且禁用网络浏览。该机制确保智能体无法通过检索外部答案或识别数据集名称来作弊，其成功必须依赖对本地原始数据的实际处理。

### 二元成功准则与成本效率评估

设计动机在于解决连续指标在跨任务比较中的不可比性。本文定义统一的二元成功准则（Binary Success Criterion），将复杂任务简化为0/1奖励。对于不同任务类型，成功阈值设定为“接近专家水平的有用解”：CT异常分类要求所有标签准确（Accuracy=1.0），病理肿瘤区域选择要求瓦片级F1 $\ge 0.90$，EHR事件建模要求AUROC达到人工工程基线（count+GBM）。

$$
\text{Success} = \mathbb{I}(\text{Metric}_{\text{task}} \ge \theta_{\text{task}})
$$

其中 $\mathbb{I}$ 为指示函数，$\theta_{\text{task}}$ 为任务特定阈值。该公式将异构指标（F1、Recall、AUROC）统一为可聚合的任务成功率（Task Success Rate, TSR）。同时，引入成本（USD）与墙钟时间（Wall-clock Time）作为辅助维度，构建帕累托前沿（Pareto Frontier），以评估智能体在性能与资源消耗间的权衡，避免仅关注准确率而忽略部署可行性。

## 实验评估

实验在10个前沿智能体（GPT-5系列、Claude系列）上进行，覆盖Codex、Claude Code、Copilot CLI三种框架，禁用网络浏览。基线审计显示，对比对象均为当前SOTA大语言模型智能体，未包含传统规则引擎或纯RAG基线，这符合评估“自主智能体”的定位，但限制了与检索增强方法的直接对比。

| Agent | Task Success Rate (%) | Cost per Task (USD) | Time per Task (min) |
| :--- | :--- | :--- | :--- |
| Codex GPT-5.5 | 42 | 2.8 | 15 |
| Copilot Opus 4.8 | 36 | 3.1 | 18 |
| Copilot GPT-5.5 | 35 | 2.6 | 18 |
| Claude Code Opus 4.8 | 32 | 4.0 | 16 |
| Codex GPT-5.4 | 28 | 1.3 | 18 |
| Claude Code Opus 4.7 | 27 | 4.8 | 16 |
| Codex GPT-5.3 | 22 | 1.0 | 14 |
| Claude Code Opus 4.6 | 19 | 4.1 | 22 |
| Claude Code Sonnet 4.6 | 17 | 2.9 | 24 |
| Codex GPT-5.4-mini | 16 | 0.6 | 16 |

核心发现是性能与成本的非线性关系。Codex GPT-5.5以42%的成功率领先，且成本（$2.8）与时间（15 min）均低于Claude Code系列。Claude Code Opus-4.7虽成功率仅27%，但成本高达$4.8，主要源于其生成大量子进程与冗长响应（输出Token数约为GPT-5.5的2倍）。这表明在医疗智能体评估中，框架架构（如Copilot CLI的多智能体委派）对性能的影响显著，GPT-5.5在Codex框架下表现优于Copilot框架（42% vs 35%），而Opus-4.8在Copilot框架下优于Claude Code（36% vs 32%）。

消融分析显示，任务类别间难度差异巨大。EHR格式转换（ETL）任务中，9/10智能体达到100%成功率，表明结构化数据操作已接近饱和；而医学影像任务（CT、X-ray、病理）成功率普遍低于30%，成为主要瓶颈。在EHR数据质量审计中，提供线索（提及表格与错误类型）使平均召回率提升0.10-0.29，但即使最强模型在无线索下仍难以达到1.0召回，说明复杂组合推理（Compositional Reasoning）仍是当前模型的短板。

评估边界方面，基准仅包含54个任务，统计显著性受限于样本量；成功准则的二元化可能掩盖部分进展（如F1=0.85与0.90均计为失败）；数据依赖MIMIC-IV等公开数据集，未涵盖私有或实时数据流。代码已开源，但环境构建依赖特定凭证与数据下载，复现成本较高。

## 关联研究分析

从问题动机看，HealthAgentBench与MedAgentBench、PhysicianBench同属可执行环境路线，但前两者聚焦于FHIR标准下的EHR记录检索与订单放置，属于“结构化数据操作”；本文则扩展至“非结构化原始数据操作”，如CT体积与病理切片。这一差异源于任务特性：EHR任务可通过SQL查询解决，而影像任务需图像处理与空间推理，后者对智能体的工具使用与多步规划能力要求更高。PhysicianBench侧重长程工作流验证，本文侧重多模态覆盖，两者互补而非替代。

从方法设计看，本文与Terminal-Bench、OSWorld等通用智能体基准共享“终端交互+最小指令”范式，但引入了医疗领域的“防作弊构造”与“专家级成功阈值”。通用基准通常允许智能体通过互联网检索答案，而本文禁用网络，强制依赖本地数据，这更贴近医疗隐私合规场景，但也可能低估了智能体在知识密集型任务（如罕见病诊断）上的能力，因为真实临床中医生可查阅指南。此外，本文未采用RAG机制，这与领域共识中“RAG缓解幻觉”的观点形成对比，暗示在可执行环境中，代码执行与数据操作可能比文本检索更关键，但这一假设在知识更新频繁的场景下是否成立，论文未给出回答。

## 总结

HealthAgentBench旨在解决医疗智能体评估中静态基准与真实工作流脱节的核心矛盾。其切入点在于构建统一的多模态可执行环境，通过终端交互与防作弊机制，剥离提示工程干扰，直接测量智能体的原生规划与执行能力。该基准包含54个任务，覆盖CT、病理、EHR等模态，采用二元成功准则与成本效率评估。实验证明，当前最强智能体Codex GPT-5.5仅达42%成功率，医学影像与复杂组合推理是主要瓶颈，且框架架构对性能影响显著。本文边界在于任务规模有限、成功准则二元化可能掩盖部分进展，且禁用网络浏览可能低估知识密集型任务表现。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
