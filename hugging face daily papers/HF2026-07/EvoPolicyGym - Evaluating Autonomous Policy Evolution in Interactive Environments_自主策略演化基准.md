# HuggingFace最新推荐论文 ｜EvoPolicyGym: Evaluating Autonomous Policy Evolution in Interactive Environments ｜自主策略演化基准

研究机构：中国科学技术大学、香港中文大学

作者：Zhilin Wang、Han Song、Runzhe Zhan 等 16 人

论文原文见 [arXiv](https://arxiv.org/abs/2607.02440)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.02440)

> 自进化智能体在开放环境中通过反馈迭代优化策略的能力难以被现有基准准确衡量，因为最终分数掩盖了盲目重试、过拟合可见反馈等轨迹级失效模式。本文切入点在于将“策略演化过程”本身作为评估对象，而非任务完成度或代码补丁质量。通过构建 EvoPolicyGym，该基准在固定交互预算下强制智能体编辑可执行策略系统，并引入隐藏验证集选择机制以隔离过拟合。这一设计填补了过程级评估空白，但当前实验仅覆盖经典强化学习环境，且缺乏与经典自进化方法的直接对比，其泛化性存疑。

## 研究背景

当智能体在交互式环境中执行任务时，其决策质量取决于策略对状态-动作映射的准确性。然而，静态预训练模型无法从部署后的交互中积累经验，导致在分布外场景中表现不佳。这种“任务隔离”特性迫使研究者引入自进化机制，使智能体能够通过反馈迭代更新内部组件。核心概念包括“可执行策略系统”（Executable Policy System），即智能体编写的、包含决策逻辑与辅助模块的代码工件；以及“预算约束”（Bounded Budget），即智能体在有限交互次数内必须完成策略优化的硬性限制。

现有评估体系存在根本性错位：SWE-bench 等基准关注代码补丁的正确性，而 Reflexion 等自进化方法关注文本反思的质量，但二者均未量化“将稀疏环境反馈转化为泛化策略”的效率。主流路线要么陷入开放式工程任务的复杂性（如规格漂移、维护质量），要么退化为单轮任务完成度评估，无法区分“通过盲目重试碰巧成功”与“通过机制理解稳健改进”。本文的切入点在于形式化“自主策略演化”（Autonomous Policy Evolution）问题，将评估对象从最终结果扩展至“预算约束下的策略演化轨迹”，从而隔离出智能体在有限信息下诊断失败、分配预算及平衡探索与利用的核心能力。

## 核心方法

### 方法参照系

本文问题可置于“交互式强化学习评估”的通用框架下，但关键差异在于：传统 RL 评估假设策略参数由优化器直接更新，而本文要求智能体以“代码编辑”形式修改策略系统，且评估指标包含过程级诊断（如预算分配效率、反馈利用率），而非仅最终回报。

### 自主策略演化协议

设计动机在于解决现有基准中“最终分数掩盖轨迹失效”的问题。在标准交互循环中，智能体 $\pi_\theta$ 在修订 $i$ 时观察工作区状态 $W_i$、反馈 $F_i$ 及剩余预算 $B_i$，生成补丁 $u_i$ 并提交策略 $P_i = \Phi(W_i)$。服务器执行沙箱 rollout 并返回反馈 $\Delta F_i$ 及消耗预算 $c_i$。该过程的形式化定义为：

$$
(W_{i+1}, F_{i+1}, B_{i+1}) = S(W_i, u_i, s_i, B_i)
$$

其中 $s_i$ 为提交命令，$S$ 为服务器算子。此公式的物理含义是：智能体的每次决策不仅改变策略代码，还消耗不可再生的交互预算，迫使其在“获取信息”与“保留资源”间做出权衡。

### 可见性边界与泛化评估

设计动机在于防止智能体过拟合可见训练反馈。协议设定严格的可见性边界：训练集反馈 $F_i$ 对智能体可见，而验证集与留出集（Held-out）数据由服务器隐藏。最终得分由服务器在优化循环结束后，基于隐藏验证集选择最佳检查点，并报告其在隐藏留出集上的平均回报：

$$
\text{Score} = \mathbb{E}_{\tau \in \mathcal{H}} \left[ R(\tau \mid P^*) \right], \quad P^* = \arg\max_{P \in \mathcal{C}} V_{\text{val}}(P)
$$

其中 $\mathcal{H}$ 为留出集，$\mathcal{C}$ 为候选检查点集合。该机制确保评估的是策略的泛化能力，而非对训练轨迹的记忆，从而量化了智能体在有限交互下将稀疏证据转化为稳健改进的效率。

## 实验评估

实验在 Core16 套件上进行，涵盖 Gym/Box2D、MuJoCo、MiniGrid 及机器人/驾驶任务，所有智能体共享 128-episode 交互预算。基线审计显示，本文仅对比不同 LLM-Harness 组合（GPT-5.5/Codex, Claude Opus 4.7/Claude Code 等），未包含 Reflexion、ExpeL 等经典自进化方法或传统 RL 算法，导致无法直接量化“代码编辑范式”相对于“参数优化范式”的增益。

| 模型 | Harness | Core16 聚合得分 | 获胜环境数 | Top-2 环境数 |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5.5 | Codex | 0.891 | 9 | 16 |
| Claude Opus 4.7 | Claude Code | 0.750 | 5 | 12 |
| MiniMax-M3 | Claude Code | 0.531 | 1 | 3 |
| DeepSeek-V4-Pro | Claude Code | 0.359 | 1 | 1 |

GPT-5.5 在全部 16 个环境中均进入前两名，其优势源于跨环境覆盖的稳定性，而非单一任务的极致性能。消融分析表明，在合成主导任务（如 CarRacing）中，GPT-5.5 与 Claude Opus 4.7 将合成编辑转化为新验证最佳的比例分别为 41% 和 48%，而 MiniMax-M3 仅为 10%，显示弱模型在结构创新上缺乏牵引力。在调优主导任务（如 BipedalWalker）中，GPT-5.5 是唯一达到正高回报步态（timeline best score 271）的智能体，其他模型在负分区间徘徊，表明参数调优的有效性依赖于先前的结构合成里程碑。

评估边界方面，本文未报告计算成本（如 token 消耗、API 延迟），且 128-episode 预算远低于标准 RL 收敛所需样本量，导致无法与传统 RL 基线公平对比。代码资源已开源（EvoPolicyGym.io），但环境适配器仅验证了 Core16 子集，更广泛的 Gymnasium 环境支持尚处于接口测试阶段。

## 关联研究分析

从问题动机看，本文与 EvoPolicyGym（Wang et al., 2026）在“过程级评估”理念上一致，但本文更强调“预算约束”作为能力测量的核心维度，而非仅关注反馈利用率。与 SWE-bench 等长程编码基准相比，本文排除了规格漂移与软件维护质量等混杂因素，将评估聚焦于“策略演化”本身，这使得结果更具可控性，但牺牲了真实工程场景的复杂性。

从方法设计看，本文借鉴了 AlphaEvolve 的进化搜索逻辑，但将搜索空间限制在“可执行策略系统”的代码结构上，而非通用程序。与 Reflexion 等文本反思方法不同，本文去除了自然语言反思环节，直接操作代码工件，这符合“工具与技能自生成”路线中“可执行技能”的共识，但忽略了文本记忆在跨任务迁移中的潜在价值。查询侧增强在数据充足时是否仍有增益，论文未给出回答，这暗示代码编辑范式可能在长程知识固化上存在盲区。

## 总结

本文要解决的核心矛盾是自进化智能体“过程能力”与“结果分数”之间的评估错位。现有方法无法区分稳健改进与盲目重试，而本文通过形式化“自主策略演化”问题，将预算约束与隐藏验证集选择机制嵌入评估协议，从而隔离出智能体在有限交互下的策略优化能力。实验证明，GPT-5.5 在 Core16 上取得 0.891 的聚合得分，且在全部 16 个环境中进入前两名，验证了该基准对模型能力的区分度。本文的边界在于仅覆盖经典 RL 环境，且缺乏与参数化自进化方法的直接对比，导致无法量化“代码编辑”相对于“权重更新”的长期稳定性优势。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
