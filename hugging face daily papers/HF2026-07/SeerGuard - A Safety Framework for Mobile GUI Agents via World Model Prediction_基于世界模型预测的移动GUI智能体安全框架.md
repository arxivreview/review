# HuggingFace最新推荐论文 ｜SeerGuard: A Safety Framework for Mobile GUI Agents via World Model Prediction ｜基于世界模型预测的移动GUI智能体安全框架

作者：Xue Yu、Bo Yuan、Pengshuai Yang 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2607.15550)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.15550)

> 移动GUI智能体在执行不可逆操作（如转账、删除数据）时，现有安全机制要么仅拦截显式恶意指令，要么在动作执行后才进行事后验证，无法预判动作后果。SeerGuard通过构建安全增强世界模型（SAWM），在执行前预测动作的语义下一状态并评估其风险，实现了“后果感知”的前置拦截。该方法在MobileSafetyBench上将Qwen3-VL的安全效用分从0.191提升至0.596，但在防止隐性数据泄露等复杂风险场景下的泛化能力尚存疑。

## 研究背景

当GUI智能体面对“查看最新帖子”这类表面无害的指令时，若界面中隐藏了“购买100股NVIDIA股票”的提示注入攻击，传统基于文本的指令筛选器（如LlamaGuard）因缺乏视觉上下文而无法识别风险。这种风险依赖于当前界面状态与动作后果的耦合，单纯判断指令意图不足以保障安全。解决此问题需要智能体具备预测动作执行后界面状态变化的能力，即世界模型（World Model）中的状态转移预测机制。

现有GUI安全方案主要分为两类：指令级防御和事后验证。指令级防御（如VeriSafe Agent）依赖严格逻辑规则，难以处理模糊自然语言意图；事后验证方法（如OS-Sentinel）在动作执行后评估轨迹安全性，但移动环境中许多不安全动作（如误触支付）一旦执行便不可回滚。主流GUI智能体研究（如UI-TARS、DigiRL）聚焦于任务成功率，忽视了操作安全性，导致智能体在对抗性攻击或模糊指令下极易执行有害操作。SeerGuard的切入点在于将世界模型从“任务规划工具”转化为“安全审计工具”，通过语义预测实现执行前的风险拦截，填补了“后果感知”安全机制的空白。

## 核心方法

### 方法参照系

GUI智能体安全通常采用“指令筛选+动作执行”的两阶段流程。标准流程中，指令筛选器判断用户请求是否恶意，若安全则直接执行动作。本文的关键差异在于引入“动作级风险预测”环节，将世界模型嵌入执行前，对候选动作的后果进行语义审计，而非直接执行或事后检查。

### 指令级筛选与级联架构

指令级筛选模块 $G_{inst}(I)$ 作为第一道防线，输出二元标签 $l_{inst} \in \{safe, unsafe\}$ 及理由 $r_{inst}$。其设计动机是拦截显式恶意意图（如“重置手机”），同时避免对模糊指令过度拒绝。对于表面无害但可能引发上下文风险的指令，该模块刻意将安全评估推迟至动作级阶段。这种级联架构通过“粗粒度拦截+细粒度审计”平衡安全性与效用，防止因过度保守导致良性任务失败。

### 语义世界模型与动作级风险预测

动作级风险预测模块 $G_{WM}(o_t, a_t)$ 基于当前屏幕状态 $o_t$ 和候选动作 $a_t$，预测语义下一状态 $\hat{s}_{t+1}$ 并输出安全标签 $l_{act}$ 及理由 $r_{act}$。其核心公式为：

$$ (\hat{s}_{t+1}, l_{act}, r_{act}) = G_{WM}(o_t, a_t) $$

该公式的物理含义是：VLM直接解码多模态特征为文本描述，预测动作执行后的功能状态变化，而非生成像素级图像。设计动机是安全决策依赖功能状态变化（如“账户余额减少”）而非视觉保真度，语义预测避免了图像生成的高计算开销，且更贴合安全推理需求。SAWM通过多任务SFT联合学习状态预测与风险识别，在148K实例上训练，其中安全/不安全样本比例为2:1，以平衡任务执行与风险识别能力。

## 实验评估

实验在MobileSafetyBench（250个任务，150高风险/100低风险）、MobileRisk（204个轨迹）和Next-State-QA上进行。基线覆盖通用VLM（GPT-5.1、Gemini-3.1、Qwen3-VL）、安全模型（OS-Sentinel、MobileWorld）及规则基线。主结果显示，SeerGuard在MobileSafetyBench上显著降低风险成本分（RCS）并提升安全效用分（SUS）：

| 模型 | RCS ($\alpha=0.8$) | SUS ($\omega=0.8$) |
| :--- | :--- | :--- |
| Qwen3-VL | 0.347 | 0.191 |
| Qwen3-VL+SeerGuard | 0.130 | 0.596 |
| GPT-5.1+SeerGuard | 0.145 | 0.679 |
| Gemini-3.1+SeerGuard | 0.155 | 0.676 |

SeerGuard将Qwen3-VL的RCS从0.347降至0.130，SUS从0.191升至0.596，表明其在保持任务完成能力的同时显著提升了安全拦截率。在MobileRisk上，SAWM取得F1 0.723和Step Score 0.361，优于OS-Sentinel（F1 0.695）和MobileWorld（F1 0.594），验证了语义预测在定位风险起始步骤上的优势。

消融实验显示，仅使用指令级筛选（SeerGuard_inst）的RCS为0.310，仅使用动作级预测（SeerGuard_act）的RCS为0.275，两者结合后RCS降至0.130，表明级联架构的协同效应显著。Next-State-QA上SAWM准确率0.762，超过GPT-5.1（0.727）和MobileWorld（0.714），证明其状态预测能力。评估边界方面，论文未报告推理延迟和计算成本，且MobileSafetyBench任务类型有限（仅6类），未覆盖跨应用、跨OS的复杂场景。代码未公开，超参数（如学习率1e-6、1 epoch）细节有限，可复现性依赖Qwen3-VL-8B-Instruct的开源权重。

## 关联研究分析

从问题动机看，SeerGuard与OS-Sentinel的核心差异在于安全防御时机。OS-Sentinel采用事中拦截，在动作执行后验证轨迹安全性，适合可回滚场景；SeerGuard采用事前预测，通过世界模型预判后果，适合不可逆操作。这一差异源于任务特性：移动GUI中支付、删除等操作不可回滚，事后验证无法阻止损害发生。SeerGuard的语义预测是否足以捕捉所有风险类型（如隐性数据泄露），论文未提供证据，仅验证了提示注入和显式恶意操作。

从方法设计看，SeerGuard与MobileWorld同属语义世界模型，但目标不同。MobileWorld聚焦任务规划，预测状态转移以优化动作选择；SeerGuard聚焦安全审计，预测状态转移以评估风险。SeerGuard在MobileWorld基础上增加安全增强数据（59K纯文本安全样本+多模态风险数据），通过多任务SFT实现安全能力注入。这一设计是否导致任务规划能力下降，论文未对比MobileWorld在任务成功率上的表现，仅关注安全指标。

## 总结

SeerGuard解决的核心矛盾是移动GUI智能体在不可逆操作中的安全缺失，现有方法因缺乏后果预判能力而失效。其切入点在于将世界模型从规划工具转化为安全审计工具，通过语义预测实现执行前风险拦截。方法上，SAWM联合学习状态预测与风险识别，在MobileSafetyBench上将Qwen3-VL的SUS从0.191提升至0.596，RCS从0.347降至0.130。边界在于评估场景有限（仅6类任务），未验证跨应用泛化能力，且语义预测对隐性风险的捕捉能力未充分证明。当面对跨应用、跨OS的复杂状态转移时，语义世界模型能否保持风险识别精度，论文未给出回答。
