> 大语言模型推理面临“能力依赖规模”与“服务成本随调用线性增长”的双重约束，传统压缩方法通过牺牲精度换取内存效率，无法在不修改权重的前提下注入新知识。本文切入点在于利用KV缓存的确定性，将其从临时状态重构为可持久化、可移植的字节精确知识载体。通过“验证-缓存-路由-移植”闭环，实现冻结模型在零额外显存下的能力跃升与推理成本断崖式下降。该方法在AIME 2025上使12B模型得分从80.0%提升至93.3%，但受限于特定GPU架构内的字节一致性，跨架构通用性存疑。

## 研究背景

自回归推理中，键值缓存（KV Cache）是输入序列、模型权重与数值精度的确定性函数。这一特性意味着，若能在预填充阶段精确捕获该状态并持久化，后续推理即可跳过重复计算，直接复用内部表示。然而，现有系统如LMCache或CacheGen仅实现近似复用或会话内临时缓存，无法保证跨进程、跨机器的比特级一致性，导致复用状态与新鲜计算存在不可忽略的数值漂移，进而混淆了“知识注入”与“数值噪声”对模型输出的影响。

领域主流路线聚焦于KV缓存的压缩与驱逐，如H2O基于注意力稀疏性丢弃低价值Token，KIVI采用非对称量化降低存储精度。这些方法的核心假设是“近似可接受”，旨在平衡内存带宽与模型精度，但均无法解决“在不训练模型的前提下，如何永久性地增加模型知识”这一根本问题。本文的切入点在于打破“压缩即损失”的范式，提出在特定数值条件下，KV状态可实现字节级精确恢复，从而将推理时的知识注入转化为一次性的磁盘写入与零成本的运行时读取。

## 核心方法

### 方法参照系

本文问题置于“系统级KV缓存复用”范畴，与PagedAttention等内存管理技术共享状态捕获与恢复的基础流程。关键差异在于，传统方法追求空间效率下的近似复用，而本文追求数值精度下的无损移植，要求恢复后的Logit向量与新鲜计算在字节层面完全一致，而非仅满足范数接近或分布相似。

### 字节精确性保证与位置约束

传统缓存复用通常容忍微小的浮点误差，但本文要求恢复状态 $S$ 产生的Logit向量 $\ell_{\text{graft}}$ 与新鲜计算 $\ell_{\text{fresh}}$ 满足字节相等。该约束的数学表达为：

$$ \text{SHA256}(\ell_{\text{graft}}) = \text{SHA256}(\ell_{\text{fresh}}) \quad \text{且} \quad D_{KL}(p_{\text{graft}} \| p_{\text{fresh}}) = 0 $$

此公式表明，不仅输出分布的Kullback-Leibler散度为零，且底层二进制表示完全一致。设计动机在于消除数值漂移对能力评估的干扰，确保模型性能提升完全归因于注入的知识而非计算误差。实验发现，仅在“自身位置”（Own-Position）即状态被捕获时的绝对位置区间内，该精确性才成立。若将状态块重定位至不同偏移量 $M$，由于旋转位置编码（RoPE）在32位浮点下三角恒等式 $\cos a \cos b + \sin a \sin b = \cos(a-b)$ 无法比特级成立，会产生约0.015的KL散度残差。该残差源于模型自身的位置敏感性，而非移植操作引入的错误，因此“自身位置”是该模型上唯一可实现字节精确的数值操作点。

### 验证-缓存-路由闭环（Galahad）

在字节精确性基础上，本文构建了Galahad学习闭环。对于模型无法独立解决的问题，首先通过额外推理生成解，经外部验证（如执行代码确认输出）后，将验证通过的KV状态作为独立块存入磁盘。检索时，系统通过单块路由（Single-Block Routing）而非扁平合并，将新查询匹配至唯一相关块并移植。这一设计解决了早期扁平前缀方案中模型因多块共存而“抓取错误条目”的失效问题。路由机制确保了移植的针对性，使得冻结模型能利用缓存的解题方法适配新实例，实现了从“记忆”到“泛化”的能力迁移。

## 实验评估

实验在Gemma-4-12B与31B模型上，使用AIME 2025与LiveBench基准，对比了厂商模型卡锚点（12B: 77.5%, 31B: 89.2%）及采样投票基线。本文未对比H2O、KIVI等压缩方法，因其目标为无损知识注入而非内存压缩，二者评估维度不同。

| 配置 | AIME 2025 准确率 (%) | 解码 Token 数/题 | 备注 |
| :--- | :--- | :--- | :--- |
| 冻结 12B (最佳推理) | 80.0 | - | 基线 |
| 采样投票阶梯 | 76.7 | ~25,000 | 高成本基线 |
| 代码路由 + 移植库 | 90.0 | ~4,360 | 本文方法 |
| 冻结 12B + 移植库 (全量) | 93.3 | - | 最终结果 |

在AIME 2025上，移植验证库使12B模型准确率从80.0%提升至93.3%，超越31B模型的89.2%。在重复性查询场景中，8道难题通过移植缓存解，仅消耗61个总解码Token（每题7.6个），相比401,026 Token的采样预算，Token消耗降低6,574倍。LiveBench留出集测试中，单块路由实现71.7%的迁移准确率，而合并所有块导致准确率降至56.7%，证实了路由机制对避免干扰的关键作用。

消融实验显示，扁平合并策略因查询稀释导致性能显著下降，验证了单块路由的必要性。此外，跨架构测试表明，H100与Blackwell GPU间字节一致性不成立，但功能迁移有效，说明字节精确性是架构内属性，跨架构仅保证功能性等价。

评估边界方面，本文依赖`GGML_DETERMINISTIC=1`等确定性配置，限制了其在非确定性生产环境中的直接适用性。代码与引擎内部为专有，仅公开输入输出哈希以供审计，复现需依赖特定引擎版本。

## 关联研究分析

从问题动机看，本文与CacheGen、LMCache等系统级复用工作同属“状态持久化”路线，但根本差异在于精度目标。CacheGen关注网络传输效率，采用有损编码；本文追求比特级精确，将KV状态视为不可变的知识资产。这一差异源于任务特性：缓存复用旨在加速重复计算，允许微小误差；而知识注入旨在扩展能力，任何数值漂移都可能掩盖真实的能力增益或引入虚假幻觉。

从方法设计看，本文与H2O等驱逐策略形成鲜明对比。H2O基于注意力稀疏性假设，动态丢弃低价值Token以节省内存，本质是“减法”；本文通过精确存储高价值验证状态，本质是“加法”。H2O的局限在于无法增加模型知识，仅能优化现有知识的访问效率；本文则通过外部验证与路由，实现了模型能力的永久性扩展。这种差异暗示，在长上下文推理中，内存效率与知识容量并非零和博弈，精确的状态管理可同时优化二者。

## 总结

本文核心矛盾在于冻结模型能力固化与推理成本高昂之间的冲突。现有压缩方法通过牺牲精度换取效率，无法在不训练的前提下注入新知识；本文凭借KV状态的确定性，在自身位置下实现字节精确移植，将知识注入转化为零成本的运行时读取。通过Galahad闭环，12B模型在AIME 2025上从80.0%提升至93.3%，且重复查询Token消耗降低6,574倍。其边界在于字节精确性受限于特定GPU架构内的浮点累积特性，跨架构仅保证功能等价。当模型规模进一步扩大或架构变更时，这种基于字节一致性的知识移植机制是否仍能保持无损，论文未给出回答。
