> 软件代理在生成幻灯片、3D场景等复杂工件时，常因缺乏可复用的程序性知识而失败。现有技能库多依赖人工编写或代理自身轨迹，未能利用教程视频等蕴含时序与视觉信息的多模态人类资源。本文提出 RESOURCE2SKILL，将视频、代码、文章蒸馏为包含文本、代码与视觉示例的层级化技能维基，并在推理时通过层级导航与语言模型选择组合技能。该框架在七个创作域上验证了多模态技能对代理性能的显著提升，但其技能库的静态构建模式与在线进化闭环的缺失，限制了其在动态环境中的长期适应性。

## 研究背景

当代理执行 Blender 场景构建或 Excel 表格操作时，其表现不仅取决于模型参数，更依赖于对特定软件 API 调用顺序、中间状态检查及故障恢复策略的掌握。这类可复用的程序性知识被称为技能。然而，自然语言文本难以完整表达视频中的动态操作时序、视觉布局变化及工具交互细节，导致纯文本技能在创意软件任务中信息表达不足。

当前技能库的构建主要依赖专家手写、代理轨迹积累或文本/代码资源挖掘。这些方法存在两个瓶颈：一是来源单一，忽略了教程视频这一蕴含丰富程序性与感知性知识的自然学习来源；二是表示扁平，缺乏对技能间层级依赖与领域结构的编码，导致大规模库中检索效率低下。RESOURCE2SKILL 的切入点在于将多模态人类资源作为技能的主要来源，并通过层级化维基结构解决检索与表示问题。

## 核心方法

### 多模态技能表示与层级维基

技能被定义为元组 $s = (p, x_{text}, x_{visual}, x_{code}, m)$，其中 $p$ 为领域分类法中的路径，$m$ 为元数据，三个内容视图互补：文本描述机制与适用性，视觉提供截图与预览，代码包含可执行片段。这种设计解决了纯文本技能无法保留视频时序与视觉布局信息的问题，使技能库成为多维度的程序性记忆。

### 资源到技能的蒸馏与质量门控

构建算子 $f_\theta$ 从资源池 $R_D$ 中提取模态特定证据（关键帧、代码区域、文本段落），并通过视觉语言模型蒸馏为技能元组。随后，领域特定谓词 $A_D$ 执行五项检查：完整性、可追溯来源、去重、模态一致性及代码可执行性。

$$
s \in \Sigma_D \iff A_D(f_\theta(r)) = \text{True}, \quad \forall r \in R_D
$$

该公式表明，只有通过质量门控的候选技能才会进入最终库 $\Sigma_D$。这一设计动机在于防止低质量或不可执行技能污染库，确保代理检索到的技能具备直接执行或适配的基础。

### 层级导航与子集选择

给定任务简报 $q$，METABROWSE 策略分两阶段选择技能。首先，词汇评分器结合技能名称、标签、适用性文本及分类法路径 $p(s)$ 缩小候选集 $C_K(q)$：

$$
\text{score}(s, q) = \text{BM25}(q, \text{metadata}(s)) + \lambda \cdot \text{path\_sim}(p(s), q)
$$

该公式通过路径相似度直接偏好位于相关子树中的技能，而非将库视为扁平列表。随后，语言模型读取候选集的结构化证据，选择一个子集进行组合。选择是子集而非排序，允许模型在无合适候选时选择零技能，避免了强制匹配导致的错误执行。

## 实验评估

实验在七个创作域（Web, Excel, Reaper, PPT, Blender, CAD, UE5）上进行，每个域包含 80 个任务简报，使用 GPT-5.5 至 GPT-5.4 Nano 四种后端。基线包括无技能代理、Claude Code 和 Codex 代理框架。主实验结果显示，RESOURCE2SKILL 在所有 28 个模型-域组合中均优于无技能基线，平均得分从 45.0% 提升至 56.8%，提升 11.9 个百分点。

| 系统 | GPT-5.5 Avg | GPT-5.4 Avg | GPT-5.4 Mini Avg | GPT-5.4 Nano Avg |
| :--- | :--- | :--- | :--- | :--- |
| W SKILLS | 56.8 | 56.8 | 51.9 | 42.8 |
| W/O SKILLS | 45.0 | 45.0 | 41.4 | 34.7 |
| CLAUDECODE-H | 50.4 | 50.4 | 46.1 | 37.4 |
| CODEX-H | 50.5 | 50.5 | 46.2 | 37.9 |

消融实验揭示了关键设计决策的价值。在表示格式上，完整多模态维基比纯文本扁平库高 2.5 至 8.2 个百分点，表明代码与视觉字段提供了纯文本无法覆盖的执行基础。在来源多样性上，移除视频源导致平均得分从 68.9% 降至 59.4%，证明视频是程序性知识的关键来源。在线获取实验显示，在标准任务集上在线获取仅提升 0.7 个百分点，但在针对离线池未覆盖能力的新颖任务集上，100 个在线技能将得分从 41.2% 提升至 62.8%，表明在线获取是有效的缺口填充机制而非性能增强器。

评估协议存在局限。非音频工件由 GPT-5.4 视觉裁判评分，Reaper 由音频裁判评分，裁判对系统标签盲测。然而，裁判模型与代理模型同属 GPT 系列，可能存在同源偏差。此外，实验未报告计算效率指标（如 Token 成本、延迟），且技能库规模在 200 个技能后趋于饱和，未探索更大规模库下的检索效率退化问题。

## 关联研究分析

从技能来源看，Voyager 和 SkillFlow 主要依赖代理自身轨迹或失败案例在线构建文本/代码技能库，而 RESOURCE2SKILL 强调从外部多模态人类资源离线蒸馏。这一差异源于任务特性：创意软件任务中的程序性知识往往以教程视频形式存在，代理自身轨迹难以覆盖所有专业操作模式。然而，RESOURCE2SKILL 缺乏基于轨迹的在线优化闭环，其技能库在构建后是静态的，无法像 SkillOpt 那样通过验证门控迭代改进技能质量。

从检索机制看，SkillDAG 使用图结构捕捉技能依赖，而 RESOURCE2SKILL 采用层级分类法加 BM25 与语言模型选择。层级结构在缩小搜索空间方面有效，但未显式建模技能间的组合依赖关系。当任务需要多个技能协同执行时，层级导航可能无法捕捉跨层级的依赖约束。此外，RESOURCE2SKILL 的质量门控 $A_D$ 是静态的，而 SkillOpt 的验证门控是动态的，后者能根据执行反馈拒绝无效编辑，前者仅能过滤构建时的低质量技能。

## 总结

RESOURCE2SKILL 解决了多模态人类资源未被有效转化为代理技能的问题，通过层级维基与多模态表示实现了离线构建与在线缺口填充的统一。实验证明，在七个创作域上，该框架比无技能代理提升 11.9 个百分点，并在 26/28 个组合中优于强代理框架基线。然而，其技能库的静态构建模式与缺乏基于执行反馈的迭代优化机制，限制了技能在动态环境中的持续进化能力。当任务分布发生漂移或新工具出现时，静态库的覆盖率与技能质量如何维持，论文未给出回答。
