> 构建具备长程交互能力的LLM智能体受限于高质量、多样化训练数据的稀缺，尤其是可执行环境与长轨迹的获取成本。现有环境合成方法将任务生成绑定于预定义的工具、仓库或技能图，导致规模受限于底物覆盖度，且新领域需重复构建基础设施。NexForge 提出需求驱动范式，从高层能力需求出发解耦任务生成与底物依赖，通过分布感知编译自动实例化可执行工作区并收集专家轨迹。该框架在终端与办公两个独立领域验证了跨域扩展能力，但仅依赖监督微调（SFT）且未涉及强化学习（RL），其合成数据在长程信用分配任务中的有效性边界尚待厘清。

## 研究背景

当智能体需要在终端执行复杂软件构建或处理办公文档时，其训练数据不仅包含任务描述，更依赖具体的文件依赖、运行时配置及长程交互轨迹。这种对“接地材料”（Grounded Materials）的强依赖使得数据生产高度劳动密集：研究者需手动确定练习内容、设计代表性任务并打包为可运行工作区。这一过程昂贵且难以规模化，构成了智能体后训练（Post-Training）的核心瓶颈。

环境合成路线旨在自动化这一过程，但主流方法如 AgentSynth、SkillSynth 等采用“底物绑定”（Substrate-bound）策略，即从预定义的仓库、工具集或技能图出发生成任务。这种范式存在三个结构性缺陷：规模受限于输入底物的覆盖范围；每个新领域需定制专属基础设施；底物本身隐含了任务分布偏差，导致合成数据反映的是工具生态而非真实世界需求。NexForge 的切入点在于将环境合成重构为“需求驱动”问题，先识别能力需求对应的任务分布，再反向确定所需的材料与运行时，从而解耦任务意图与执行环境。

## 核心方法

### 方法参照系

NexForge 置于智能体环境合成与数据生成的通用流程中。标准流程通常从特定领域资源（如代码仓库或API列表）出发，通过子任务组合或轨迹回放生成训练样本。本文的关键差异在于流程起点：不从资源出发，而是从高层能力需求（Capability Requirement）出发，将“智能体应练习什么”与“如何使其可执行”分离，实现了同一管道跨领域复用。

### 需求发现与分布感知编译

传统方法直接基于底物采样任务，导致分布由底物决定。NexForge 引入研究智能体（Research Agent）调查真实世界需求，构建加权任务需求画像 $\Phi(I)$ 和场景库 $G(I)$。任务形式 $f_i$ 定义为元组 $(t_i, d_i, \sigma_i, e_i, \ell_i, h_i)$，分别指定任务类型、交付物、源策略、运行时、语言和难度。对于每个场景 $s_j$，编译器通过兼容性过滤确定候选集 $C_{j,k}$，并按画像权重采样：

$$ f_{j,k} \sim \text{Categorical}(\Phi_k | C_{j,k}) $$

该公式确保生成的任务指令在语义上与场景兼容，避免了随机组合导致的逻辑不一致。设计动机在于解决底物绑定方法中任务分布与真实需求脱节的问题，通过显式控制分布实现数据多样性的可调节性。

### 环境实例化与轨迹蒸馏

任务指令确定后，NexForge 通过材料挖掘、蓝图规划和工作区生成三步实例化环境。研究智能体收集公开仓库或生成本地文件，规划智能体定义任务目标与依赖，实现智能体构建无特权 CPU-only Docker 环境。教师模型在固定预算下与环境交互，生成包含工具调用、观察及错误恢复的轨迹。轨迹经任务无关清洗后保留有意义的长程推理片段，无需人工标注参考答案。这一设计解决了可执行环境构建中材料可用性与任务意图冲突的问题，确保工作区忠实于编译指令，同时通过保留失败轨迹提供错误恢复信号。

## 实验评估

实验在 Terminal-Bench 2.0 和 GDPval 上进行，基线涵盖 Gemini 3.1 Pro、Claude Opus 4.6 等前沿闭源模型及 LiteCoder-Terminal、SkillSynth 等终端专用开源模型。所有模型使用 NexAU 框架评估，SFT 配置为 5 epochs、262K 上下文长度、学习率 $10^{-5}$。

| 模型 | 基座 | 数据规模 | TB 2.0 准确率 (%) | GDPval Elo |
| :--- | :--- | :--- | :--- | :--- |
| Qwen3.5-35B-A3B Base | Qwen3.5 | - | 22.5 ± 0.9 | 813 |
| + Terminal-3.6K | Qwen3.5 | 3.6K×3 | 52.0 ± 3.6 | - |
| + Terminal-43.2K | Qwen3.5 | 43.2K×1 | 58.4 | - |
| + Office-2K | Qwen3.5 | 2K×3 | - | 1338 |
| + Office-22K | Qwen3.5 | 22K×1 | - | 1384 |
| Claude Opus 4.6 | - | - | 58.0 ± 2.9 | 1400 |

Terminal-3.6K 将 Qwen3.5-35B-A3B 从 22.5% 提升至 52.0%，绝对增益 29.5 点；Office-2K 将 GDPval Elo 从 813 提升至 1338，接近 Gemini 3.1 Pro 的 1316。数据规模扩展至 43.2K 时，TB 2.0 准确率进一步升至 58.4%，与 Claude Opus 4.6 持平。

消融实验显示，移除任务形式画像（w/o profile）导致任务类型坍缩至约 3 种（Top-10 签名覆盖率 78.5%），准确率降至 40.2%；移除场景库（w/o scenario）虽扩展类型至约 16 种，但分布过于平坦，准确率为 42.7%。完整管道保持 exp(H)≈6 的有效类型数，平衡多样性与频率。DATC 兼容性过滤使指令-场景匹配率从 7.0% 提升至 81.0%，验证了分布感知编译对任务连贯性的关键作用。

评估边界方面，论文未报告计算效率指标（Token 消耗、延迟），且基线结果来自不同脚手架，可能存在协议不一致。代码未公开，仅发布 Nex-N2 模型权重，限制了框架本身的复现性。

## 关联研究分析

从问题动机看，NexForge 与 SkillSynth、AgentSynth 同属环境合成路线，但后者基于技能图或子任务组合，任务分布由底物结构决定，难以反映真实世界需求频率。NexForge 通过需求画像显式控制分布，解决了底物偏差问题，但其依赖 GPT-5.5 作为教师模型，合成轨迹的质量上限受限于教师能力，而 SkillSynth 等方法可能通过领域特定规则生成更精确的验证信号。

从方法设计看，NexForge 仅使用 SFT，未涉及强化学习（RL）。领域共识认为 RL 通过可验证奖励解决长程任务中的信用分配问题，而 SFT 依赖专家轨迹的模仿，可能无法充分学习错误恢复策略。NexForge 保留失败轨迹旨在提供错误恢复信号，但缺乏过程奖励模型（PRM）或蒙特卡洛树搜索（MCTS）等机制来细化步骤级监督。这与 AgentPro、Tool-R0 等结合 RL 的方法形成对比，后者在长程规划任务中可能具有更优的泛化能力，但训练成本更高。

## 总结

NexForge 针对智能体训练数据稀缺与底物绑定导致的扩展瓶颈，提出需求驱动范式，通过解耦任务生成与底物依赖实现跨域数据合成。该框架在终端与办公领域验证了有效性，Terminal-3.6K 数据将 Qwen3.5-35B-A3B 在 Terminal-Bench 2.0 上从 22.5% 提升至 52.0%，Office-2K 数据将 GDPval Elo 从 813 提升至 1338。其边界在于仅依赖 SFT 且未涉及 RL，合成轨迹的质量受限于教师模型能力，且缺乏对长程任务中细粒度信用分配的显式优化。当任务复杂度进一步增加，仅靠模仿学习能否替代 RL 在长程决策中的优势，论文未给出回答。
