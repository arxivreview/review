# HuggingFace最新推荐论文 ｜H^2SD: Hybrid Hindsight Self-Distillation ｜混合后见自蒸馏

研究机构：哈尔滨工业大学、复旦大学

论文原文见 [arXiv](https://arxiv.org/abs/2607.18955)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.18955)

> 强化学习中的标量奖励无法定位长思维链中具体哪个Token导致失败，造成信用分配瓶颈。现有自蒸馏方法要么直接匹配教师分布导致训练不稳定，要么仅调整更新幅度而无法纠正错误路径。本文提出根据轨迹正确性动态路由至不同蒸馏策略的混合框架。该设计在逻辑推理基准上显著优于基线，但其对二元奖励的依赖限制了在部分正确场景下的适用性。

## 研究背景

当模型在长思维链任务中生成错误推理时，强化学习仅能提供“整体失败”的标量信号，无法区分是第一步逻辑断裂还是最后一步计算失误，这种稀疏性导致策略优化陷入高方差困境。为解决此问题，On-policy Self-Distillation (OPSD) 引入特权信息（如参考答案）构建教师分布，试图提供Token级监督。然而，直接匹配教师分布会引发特权信息泄露，使模型在推理时依赖训练时不可用的信息，导致性能崩溃。

RLVR 领域的主流路线在稳定性与修正能力间存在根本权衡。GRPO 等算法通过组内相对优势估计保证训练稳定，但缺乏细粒度指导；OPSD 提供密集监督却面临分布偏移风险；RLSD 通过仅调制更新幅度避免泄露，却丧失了对错误路径的方向性修正能力。现有方法均假设所有轨迹适用同一监督机制，忽略了成功与失败轨迹在信息结构上的本质差异：成功轨迹已包含有效推理路径，失败轨迹则需要外部参考进行纠偏。

本文切入点在于识别这一被忽略的异质性。H²SD 不再统一处理所有轨迹，而是根据验证器反馈的正确性，将成功轨迹路由至幅度调制分支以精炼信用分配，将失败轨迹路由至分布匹配分支以提供方向性修正。这种条件化设计旨在结合 RLSD 的稳定性与 OPSD 的修正力，解决单一机制无法兼顾的矛盾。

## 核心方法

### 方法参照系

本文问题属于 RLVR 中的细粒度信用分配范畴。标准流程如 GRPO 使用轨迹级标量优势 $A_i$ 更新所有 Token，而 OPSD 使用教师分布 $p_T$ 直接匹配学生分布 $p_S$。本文的关键差异在于引入轨迹正确性掩码 $m$，将单一目标函数解耦为两个针对不同状态分支的子目标。

### 成功轨迹的幅度调制

对于验证器确认正确的轨迹，奖励信号已提供可靠优化方向，此时无需改变分布形态，仅需细化 Token 级贡献度。H²SD 在此分支复用 RLSD 机制，但引入 Rephrasing 指令重构教师上下文。教师模型接收学生生成的正确响应及“重述”指令，其输出概率用于计算 Token 级权重 $w_t$。

$$ \hat{A}_t = A \cdot \text{sg}(\log p_T(y_t|x, y_{<t}, \text{rephrase}) - \log p_S(y_t|x, y_{<t})) $$

该公式通过计算教师（重述条件）与学生（原始条件）对同一 Token 的对数概率差，量化特权信息对该 Token 的支持程度。正值表示该 Token 是推理关键，负值表示冗余。此设计解决了 OPSD 直接匹配导致的分布漂移，同时比标准 RLSD 更精准地识别核心推理步骤，因为 Rephrasing 指令迫使教师聚焦于逻辑本质而非表面表述。

### 失败轨迹的反向 KL 蒸馏

对于失败轨迹，标量负奖励仅能抑制错误行为，无法指示正确替代方案。H²SD 在此分支启用分布级修正，使用由 Kimi-K2.6 生成的参考 Hint 作为教师条件。Hint 包含关键中间步骤与验证器确认的最终答案，教师模型基于 Hint 生成参考分布，学生模型通过最小化反向 KL 散度向其对齐。

$$ \mathcal{L}_{\text{fail}} = D_{\text{KL}}(p_S(\cdot|x, y_{<t}) \| p_T(\cdot|x, h, y_{<t})) $$

该公式强制学生分布向包含正确推理路径的教师分布靠拢，提供了明确的纠偏方向。与 OPSD 不同，教师条件仅包含 Hint 而非完整答案，且仅在失败轨迹激活，避免了成功轨迹上的信息泄露。此设计解决了 RLSD 在失败场景下缺乏修正方向的缺陷，通过 Hint 条件化的教师分布，将外部知识转化为可学习的分布约束，引导模型从错误路径转向正确推理轨道。

## 实验评估

实验基于 Qwen3-30B-A3B-Instruct-2507，在 Sudoku、Calcudoku 和 Arrow Maze 三个逻辑推理基准上评估。基线覆盖 GRPO、OPSD、RLSD、SDPO 和 SRPO，但缺失 DAPO、GSPO 等最新 RLVR 变体，且未包含数学推理基准（如 AIME），限制了与领域 SOTA 的直接横向对比。

| 方法 | Sudoku-6×6 | Sudoku-8×8 | Calcudoku Avg | Arrow Maze Avg | Overall |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Base LLM | 24.50 | 14.00 | 35.00 | 15.60 | 22.28 |
| GRPO | 26.25 | 16.75 | 40.00 | 15.70 | 24.68 |
| RLSD | 27.75 | 15.25 | 41.00 | 15.40 | 24.85 |
| OPSD | 35.25 | 16.75 | 30.83 | 13.20 | 24.01 |
| **H²SD** | **76.50** | **57.25** | **44.00** | **24.20** | **50.49** |

H²SD 在 Overall 指标上达到 50.49%，较 Base LLM 提升 28.21 个百分点，较最强基线 RLSD 提升 25.64 个百分点。Sudoku-6×6 上 76.50% 的成绩显著优于 OPSD 的 35.25%，表明混合路由机制在复杂约束求解中有效。

消融实验验证了路由策略的必要性。当将成功与失败轨迹的更新策略互换（Reversed Routing）时，Sudoku-6×6 性能从 76.50% 骤降至 15.60%，且 Actor 熵迅速归零，证实错误监督策略会导致探索坍缩。Rephrasing 指令对成功轨迹分支贡献显著，使 Magnitude Only 策略在 Sudoku-6×6 上提升 23.75 个百分点，但对失败轨迹分支的 Reverse-KL 策略产生 2.50 个百分点的负迁移，说明重述指令仅适用于已验证正确的路径。

评估边界受限于逻辑推理任务，缺乏数学推理基准验证泛化性。代码未公开，但提供了详细超参数（如 top-100 Token 截断、Jensen-Shannon 散度 $\alpha=0.5$）。训练使用 4 节点 32 卡 H200 GPU，计算成本较高，未报告样本效率指标，难以评估其在资源受限场景下的实用性。

## 关联研究分析

从问题动机看，H²SD 与 SRPO 均基于正确性路由，但 SRPO 将成功轨迹简单路由至 GRPO，失败轨迹路由至熵加权 SDPO。H²SD 的差异在于成功轨迹分支引入 Rephrasing 指令重构教师上下文，而非直接使用原始奖励方向。这一设计源于对“成功轨迹中冗余 Token 干扰信用分配”的洞察，SRPO 未处理此问题，导致其性能低于 H²SD。根源在于 SRPO 假设奖励方向已足够精细，而 H²SD 认为即使方向正确，幅度仍需基于推理本质进行微调。

从方法设计看，H²SD 与 OPSD 同属自蒸馏框架，但 OPSD 对所有轨迹统一应用分布匹配，而 H²SD 仅在失败轨迹启用。OPSD 在 Sudoku-6×6 上仅达 35.25%，远低于 H²SD 的 76.50%，且 SDPO（OPSD 变体）甚至低于 Base LLM。这一差距表明，无条件的分布匹配在长思维链中极易引发信息泄露与训练不稳定。H²SD 通过条件化路由规避了此风险，但代价是依赖外部 Hint 生成器（Kimi-K2.6），引入了额外的模型依赖，而 OPSD 仅依赖模型自身。这种对强模型 Hint 的依赖是否会在 Hint 质量下降时导致性能退化，论文未给出回答。

## 总结

H²SD 旨在解决 RLVR 中稀疏奖励导致的 Token 级信用分配困境，抓住成功与失败轨迹在信息结构上的异质性这一被忽略点。通过条件化路由，成功轨迹采用 Rephrasing 幅度调制，失败轨迹采用 Hint 条件反向 KL 蒸馏，在 Sudoku-6×6 上实现 76.50% 的准确率，较 Base LLM 提升 52 个百分点。其边界在于依赖二元奖励与外部强模型 Hint，且仅在逻辑推理基准验证。当奖励信号变为部分正确（如代码测试通过 80%）时，H²SD 的二元路由机制是否仍能有效区分关键 Token，论文未给出回答。
