> 视觉Web智能体在真实开放网络中执行长程任务时，常因环境非平稳性与任务多样性不足而泛化能力受限。现有训练环境要么任务规模过小，要么缺乏可验证的评估信号，导致在线强化学习（Online Reinforcement Learning, RL）难以规模化。WebGym通过程序化生成近30万带评估准则的任务集，并构建异步Rollout系统，将轨迹收集速度提升4-5倍，使简单REINFORCE算法能将Qwen3-VL-8B在分布外测试集上的成功率从26.2%提升至42.9%。该工作验证了任务规模与采样效率对策略泛化的决定性作用，但其二元奖励机制在长程信用分配上的有效性仍存疑。

## 研究背景

视觉Web智能体依赖视觉-语言模型（Vision-Language Models, VLMs）解析渲染界面以执行点击、输入等动作。由于真实网页内容动态变化，同一操作序列在不同时刻可能产生不同结果，这种非平稳性要求智能体具备跨域泛化能力，而非仅记忆特定网站的交互模式。感知接地（Grounding）是动作执行的前提，即模型需将自然语言指令准确映射到截图中的像素坐标或DOM节点，而长程任务中的状态漂移则要求智能体在有限上下文窗口内保持对历史交互的记忆。

现有训练环境面临双重瓶颈：任务集规模与评估质量。WebRL、PAE-WebVoyager等早期环境虽支持RL训练，但任务多样性不足且缺乏细粒度评估准则，导致策略易过拟合于特定网站模式。与此同时，视觉Web任务的Rollout过程因浏览器模拟开销巨大，采样速度远慢于策略更新，成为RL规模化的主要瓶颈。WebGym的切入点在于同时解决这两个问题：通过LLM辅助的程序化任务构造扩展任务广度与深度，并通过异步架构消除采样与训练间的同步屏障。

## 核心方法

### 方法参照系

在线RL训练智能体的标准流程包含任务定义、Rollout采样、策略更新三个环节。传统同步RL中，策略更新需等待所有并行环境完成当前Episode，导致GPU空闲等待。WebGym的关键差异在于将任务构造与Rollout系统解耦，前者通过事实组分解实现难度梯度，后者通过异步通信实现高吞吐采样。

### 基于事实组的任务分解

任务构造环节通常依赖人工标注或简单模板，难以覆盖复杂组合任务。WebGym引入事实组（Fact Groups）概念，将每个任务的评估准则分解为多个独立事实集合，每个集合包含一个或多个可验证事实。任务难度定义为所有事实组中事实总数，分解算法通过生成满足特定条件的子集组合创建新任务：

$$
\text{Difficulty}(T) = \sum_{g \in G_T} |g|
$$

其中 $G_T$ 为任务 $T$ 的事实组集合，$|g|$ 为组 $g$ 中的事实数量。该设计确保分解后的子任务在语义上保持连贯，同时形成从原子到组合的难度梯度，解决了此前任务集缺乏难度深度的问题。

### 异步Rollout系统

Rollout采样环节通常采用同步策略，即所有环境并行执行，策略更新需等待最慢环境完成。WebGym采用异步架构，解耦采样服务器与训练节点，消除同步屏障。系统通过128个CPU和24个NVIDIA H100 GPU，在30分钟内收集1,800条平均13.2步的轨迹，实现4-5倍加速。该设计使采样吞吐量不再受限于最慢环境，而是取决于CPU集群的并行处理能力，解决了视觉Web任务中浏览器模拟开销导致的采样瓶颈。

## 实验评估

实验在WebGym自建的分布外测试集上进行，该测试集仅包含训练期间未出现的网站任务。基线对比涵盖专有模型（GPT-4o、GPT-5-Thinking）和开源模型（Qwen3-VL-Instruct-8B、Qwen3-VL-Thinking-8B），但缺失Branch-and-Browse等架构类基线，限制了与规划方法路线的横向比较。

| 模型 | 测试集成功率 (%) |
| :--- | :--- |
| Qwen3-VL-Instruct-8B (Base) | 26.2 |
| GPT-4o | 27.1 |
| GPT-5-Thinking | 29.8 |
| Qwen3-VL-Instruct-8B (RL w/ WebGym) | 42.9 |

RL训练后的Qwen3-VL-8B在分布外测试集上达到42.9%成功率，显著超越GPT-5-Thinking的29.8%，验证了大规模任务集与高效采样对策略泛化的提升作用。消融实验显示，移除记忆提示或重复惩罚会导致性能下降，表明显式记忆机制对长程任务至关重要。任务难度混合比例从偏向困难任务（2:5:3）调整为均匀采样，在中等难度测试子集上取得最高成功率，说明中等难度任务提供了更有效的训练信号。缩短训练步数上限从(15,30,45)至(10,20,30)后，成功率从38.2%提升至42.9%，表明更紧的步数预算作为正则化器，减少了低效探索轨迹，提高了信用分配效率。

评估协议仅使用二元终端奖励，缺乏对中间推理步骤的细粒度评估，可能掩盖策略在长程任务中的局部错误。代码与超参数已开源，但异步Rollout系统的硬件依赖（128 CPU + 24 H100）限制了可复现性，小规模集群下的性能衰减未报告。

## 关联研究分析

从任务构造角度看，WebGym与SynthAgent均利用LLM生成训练数据，但WebGym侧重RL训练环境，SynthAgent侧重SFT微调。WebGym通过事实组分解实现难度梯度，而SynthAgent依赖合成监督信号，前者更适合探索性策略学习，后者更适合模仿学习。这种差异源于任务特性：RL需要可验证的奖励信号，而SFT需要高质量演示轨迹。

从训练范式看，WebGym与UI-TARS同属视觉Web智能体，但UI-TARS侧重SFT，WebGym侧重RL。UI-TARS通过大规模演示数据提升接地精度，WebGym通过在线交互提升策略鲁棒性。两者形成互补：SFT提供初始策略，RL优化长程规划。WebGym未探索SFT与RL的联合训练，这可能限制了其在冷启动场景下的表现。

## 总结

WebGym解决了视觉Web智能体训练环境中任务规模与采样效率的双重瓶颈，通过事实组分解与异步Rollout系统，使简单REINFORCE算法在分布外任务上取得42.9%成功率。其边界在于二元奖励机制无法提供长程任务的细粒度信用分配，且硬件依赖限制了可复现性。当任务步数超过训练上限30步时，策略在更长程任务上的泛化能力是否衰减，论文未给出回答。
