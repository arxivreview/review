# HuggingFace最新推荐论文 ｜FlashLabs Chroma 1.0: A Real-Time End-to-End Spoken Dialogue Model with Personalized Voice Cloning ｜实时端到端语音对话中的个性化音色克隆

作者：Tanyu Chen、Tairan Chen、Kai Shen 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.11141)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.11141)

> 实时语音交互系统长期面临延迟与音色保真度不可兼得的困境，级联架构丢失副语言信息，而现有端到端模型多牺牲说话人身份以换取低延迟。Chroma 1.0 通过解耦语义推理与声学生成的双模块架构，在仅使用4B参数的前提下实现了亚秒级响应与高保真音色克隆。其核心在于利用交错令牌调度并行生成文本与声学码，并通过独立解码器细化残差向量量化层。该工作填补了开源实时对话模型中个性化语音生成的空白，但其单通道架构未涉及全双工轮替机制，且自然度指标显著落后于商业竞品，揭示了保真度与感知自然度之间的深层权衡。

## 研究背景

实时语音对话要求系统在毫秒级延迟内完成从听觉感知到语音输出的闭环，这一过程依赖神经音频编码器将连续波形映射为离散声学令牌。然而，传统自动语音识别（ASR）与大语言模型（LLM）级联管线在转录环节丢弃了说话人身份、语速及情感等副语言信息，导致输出语音缺乏个性化特征。即便引入端到端语音到语音（Speech-to-Speech, S2S）架构，现有模型如Moshi或GLM-4-Voice主要优化语义对齐，未能有效保留参考音频中的细粒度声学特征，使得多轮对话中说话人身份一致性难以维持。

当前S2S领域的主流路线分为双通道全双工架构与单通道流式生成两类。双通道架构如Moshi通过并行处理用户与系统音频流实现自然轮替，但其计算资源主要分配于交互逻辑，对音色克隆的显式条件化支持不足；单通道模型虽能实现低延迟响应，却往往将音色控制简化为全局风格嵌入，缺乏对参考音频局部声学细节的精细建模。Chroma 1.0 的切入点在于将“个性化音色克隆”作为一等公民融入实时对话架构，而非作为后处理模块。它不追求全双工的双向并行监听，而是聚焦于单说话人场景下，如何在保持实时流式生成的同时，精确复现参考音频的声学特征，从而解决现有端到端模型在语音保真度上的缺失。

## 核心方法

### 语义-声学解耦架构

Chroma 1.0 采用Reasoner-Backbone-Decoder三级流水线，将语义理解与声学生成解耦。Reasoner基于Qwen2-Audio架构，负责处理多模态输入并输出文本令牌及隐藏状态；Backbone采用1B参数的LLaMA变体，负责生成粗粒度声学码；Decoder则细化残差向量量化（Residual Vector Quantization, RVQ）剩余层。这种设计动机在于，主LLM直接预测所有8层RVQ码本会导致序列长度爆炸，增加推理延迟，而解耦架构允许Backbone仅关注语义-声学对齐，由轻量级Decoder处理细粒度声学细节。

### 交错令牌调度与并行生成

为消除文本生成完成前的等待延迟，Chroma引入1:2文本-音频令牌交错调度。在Backbone中，每个文本令牌对应两个声学码 $c_{0,t}$，形成统一的嵌入序列。该机制使得声学生成与文本生成在时间轴上同步推进，无需等待完整文本序列即可开始音频合成。其核心约束可表述为：

$$
\mathcal{L}_{backbone} = \sum_{t} \log P(c_{0,t} | \mathbf{h}_{t}^{reasoner}, c_{0,<t})
$$

其中 $\mathbf{h}_{t}^{reasoner}$ 为Reasoner输出的隐藏状态，$c_{0,t}$ 为第 $t$ 帧的粗粒度声学码。该公式表明Backbone仅依赖前序声学码与当前语义状态进行自回归预测，确保了因果对齐。这种调度策略将首令牌时间（Time-to-First-Token, TTFT）降低至146.87ms，实现了亚秒级响应。

### 参考音频条件化与残差细化

Chroma通过CSM-1B编码器将参考音频及其转录文本编码为嵌入提示，前置到Backbone输入序列中，显式条件化目标说话人的声学特征。Decoder作为独立模块，仅接收Backbone输出的隐藏状态 $h_t$ 和粗粒度码 $c_{0,t}$，在帧内自回归生成剩余RVQ层 $c_{1:t}^{[N-1]}$。其生成过程定义为：

$$
c_{i,t} \sim P(c_{i,t} | h_t, c_{0:t}^{[i-1]})
$$

其中 $i \in \{1, \dots, N-1\}$。这一设计动机在于，Decoder无需访问完整的文本历史或参考音频上下文，仅基于当前帧的语义-声学状态进行细化，从而大幅降低长上下文处理的计算开销。通过8层RVQ码本配置，系统在保持流式因果性的同时，丰富了韵律与发音细节，实现了高保真音色克隆。

## 实验评估

Chroma 1.0 在CommonVoice数据集上评估零样本音色克隆性能，在URO-Bench上评估理解与推理能力。基线覆盖包括F5-TTS、Seed-TTS等TTS模型及GLM-4-Voice、Freeze-Omni等S2S对话模型，但缺失Moshi、BayLing-Duplex等全双工专用模型的对比，限制了其在交互动态维度的可比性。在音色克隆主实验中，Chroma 1.0 取得0.81的说话人相似度（SIM），超越人类基线0.73及Seed-TTS的0.76，相对提升10.96%。

| 模型 | SIM↑ |
| :--- | :--- |
| Human Baseline | 0.73 |
| Seed-TTS | 0.76 |
| CosyVoice 3 | 0.72 |
| Chroma 1.0 | 0.81 |

在主观评估中，Chroma与ElevenLabs的对比揭示了自然度与保真度的权衡。ElevenLabs在自然度比较平均意见分（NCMOS）中以57.2%胜出，而Chroma仅获24.4%；但在说话人相似度比较平均意见分（SCMOS）中，两者分别为40.6%与42.4%，差距仅1.8个百分点。这一结果表明，Chroma在保留说话人特征方面与商业系统相当，但感知自然度存在显著差距。在延迟指标上，Chroma实现0.43的实时因子（Real-Time Factor, RTF），生成速度为实时播放的2.3倍，满足流式交互需求。

| 指标 | Chroma | ElevenLabs | Deuce |
| :--- | :--- | :--- | :--- |
| NCMOS | 24.4% | 57.2% | 18.3% |
| SCMOS | 40.6% | 42.4% | 17.0% |

评估边界方面，Chroma仅支持英语音频生成，且当前架构不支持批处理，延迟数据基于并发度1测量。代码、训练管线及4B模型权重已开源，训练配置为8块NVIDIA H200 GPU，100K步收敛于约6小时，具备较高的可复现性。然而，论文未报告置信区间，且SIM评估基于SEED-TTS-EVAL框架，可能受特定说话人分布影响。

## 关联研究分析

从方法设计看，Chroma与Moshi同属端到端S2S路线，但架构哲学截然不同。Moshi采用双通道并行架构，将语义推理与声学生成整合于单一Transformer中，通过预测未来语音活动概率实现主动轮替；Chroma则采用解耦架构，将声学细化任务剥离至独立Decoder。这一差异源于任务目标的不同：Moshi追求全双工交互的自然轮替，需实时处理双向流；Chroma聚焦单说话人音色保真，无需处理用户打断或回授。Chroma的解耦设计牺牲了语义与声学的深层耦合，可能限制了其在复杂对话语境中动态调整音色风格的能力，但换来了更低的推理延迟与更明确的音色控制路径。

从问题动机看，Chroma与Seed-TTS均关注零样本音色克隆，但应用场景存在本质差异。Seed-TTS作为离线TTS系统，可充分利用长上下文与全局风格建模，追求极致的语音质量；Chroma作为实时对话模型，必须在流式约束下平衡延迟与保真度。Chroma通过1:2交错调度与帧内自回归细化，在4B参数下实现了超越Seed-TTS的SIM，证明了实时约束下高保真克隆的可行性。然而，Chroma未涉及全双工交互中的轮替决策与中断处理，其单通道架构无法捕捉用户打断时的语义意图变化，这在复杂交互场景中可能成为瓶颈。

## 总结

Chroma 1.0 解决了实时语音对话中音色保真度与低延迟不可兼得的核心矛盾，通过语义-声学解耦架构与交错令牌调度，在4B参数下实现了0.81的SIM与146.87ms的TTFT。其创新在于将音色克隆显式条件化于参考音频嵌入，并通过独立Decoder细化RVQ层，避免了主LLM的序列长度爆炸。然而，实验显示其NCMOS仅为24.4%，显著落后于ElevenLabs的57.2%，揭示了保真度优化可能以牺牲感知自然度为代价。当参考音频包含复杂韵律变化或情感波动时，解耦架构中的Decoder能否仅凭帧内状态准确捕捉这些细粒度动态，论文未给出回答。
