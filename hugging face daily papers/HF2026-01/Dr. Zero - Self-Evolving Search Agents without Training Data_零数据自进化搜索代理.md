# HuggingFace最新推荐论文 ｜Dr. Zero: Self-Evolving Search Agents without Training Data ｜零数据自进化搜索代理

研究机构：美国伊利诺伊大学厄巴纳-香槟分校

作者：Zhenrui Yue、Kartikeya Upasani、Xianjun Yang 等 8 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.07055)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.07055)

> 开放域搜索代理在缺乏人工标注数据时难以通过自进化获得复杂推理能力，现有零数据框架因问题生成单一且计算开销巨大而失效。本文切入点在于利用外部搜索引擎作为唯一监督信号源，通过Proposer-Solver协同进化与按跳数分组的策略优化，在零数据约束下实现搜索与推理能力的内化。该框架证明了自进化足以替代人工监督，但其在多跳任务上的性能上限及长期训练稳定性仍存疑。

## 研究背景

当语言模型代理需要回答涉及多个实体关联的复杂问题时，其内部知识往往不足以支撑跨文档的证据聚合，必须依赖外部搜索引擎进行多轮检索与推理。这种“搜索-推理”交替的交互范式要求模型不仅具备语言生成能力，还需掌握工具调用策略与长程信用分配机制。然而，训练此类代理通常依赖大量人工标注的问答对，数据获取成本高昂且难以覆盖长尾分布。

自进化范式试图通过模型自主生成问题与解答来消除对人工数据的依赖。早期工作如R-Zero（Huang et al., 2025a）在数学与代码领域验证了Proposer-Solver协同进化的可行性，但将其迁移至开放域搜索场景时面临两个瓶颈：一是Proposer生成的问题倾向于简单单跳结构，缺乏难度递进性，导致Solver无法习得复杂推理能力；二是标准强化学习算法（如GRPO）在自进化中需对每个问题采样多个解答以评估难度，这种嵌套采样在多轮搜索交互中导致计算成本呈指数级增长。

Dr. Zero针对上述瓶颈，提出在严格零数据约束下，仅利用外部搜索引擎生成监督信号，通过改进的问题生成机制与高效策略优化算法，使搜索代理在开放域问答任务上达到或超越监督基线性能。

## 核心方法

### 方法参照系

本文基于Proposer-Solver自进化框架，与R-Zero等数学领域自进化方法共享“生成-求解-反馈”循环结构。关键差异在于：本文引入外部搜索引擎作为唯一知识源，并将优化目标从单一答案正确性扩展为问题难度与可解性的联合约束，同时针对多轮工具交互的高延迟特性重构了策略优化算法。

### 难度引导奖励与HRPO

Proposer训练的核心挑战在于如何量化生成问题的难度，同时避免嵌套采样带来的计算爆炸。标准GRPO需为每个问题采样 $n$ 个解答以计算基线，导致 $m$ 个问题的总 rollout 数为 $(m+1) \times n$。本文提出Hop-Grouped Relative Policy Optimization (HRPO)，将生成的问答对按跳数 $h$ 聚类，利用同跳数问题的奖励分布计算优势函数，从而将每个问题的采样次数降至1。

Proposer的奖励函数设计为难度引导形式，旨在激励生成“可解但非平凡”的问题。设 Solver 对某问题采样 $n$ 次，正确次数为 $k$，奖励定义为：

$$ r_{diff} = \frac{n - k}{n - 1} \cdot \mathbb{I}[k \neq 0, k \neq n] $$

该公式在 $k=1$ 时取得最大值，当 $k=0$（过难）或 $k=n$（过易）时奖励为0，迫使 Proposer 生成难度适中的多跳问题。

### Solver训练与协同进化

Solver 采用标准 GRPO 进行训练，利用 Proposer 生成的数据对优化搜索与推理策略。其优势函数基于组内奖励标准化计算：

$$ A_i = \frac{\mathbb{I}[y_i = \hat{y}] - \frac{1}{n}\sum_{j=1}^n \mathbb{I}[y_j = \hat{y}]}{\text{std}(\{y_j\}_{j=1}^n)} $$

Solver 的性能提升会反馈至 Proposer，使其在后续迭代中生成更复杂的问题以维持奖励信号，形成动态课程。这种协同机制避免了单一模型自博弈中的记忆化问题，通过解耦生成与求解角色，提升了泛化能力。

## 实验评估

实验在 Qwen2.5-3B/7B-Instruct 骨干上，使用 NQ、TriviaQA、PopQA（单跳）及 HotpotQA、2WikiMQA、MuSiQue、Bamboogle（多跳）七个基准进行评估。基线涵盖 Few-shot（Prompting, IRCoT, Search-o1, RAG）与 Supervised（SFT, R1, Search-R1）。Dr. Zero 是唯一零数据方法。

| 方法 | NQ | TriviaQA | PopQA | HotpotQA | 2WikiMQA | MuSiQue | Bamboogle | Average |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Qwen2.5-3B** | | | | | | | | |
| Search-R1 | 0.323 | 0.537 | 0.364 | 0.308 | 0.336 | 0.105 | 0.315 | 0.327 |
| **Dr. Zero** | **0.397** | **0.572** | **0.431** | 0.298 | 0.291 | 0.091 | 0.200 | **0.326** |
| **Qwen2.5-7B** | | | | | | | | |
| Search-R1 | 0.397 | 0.606 | 0.404 | 0.380 | 0.326 | 0.168 | 0.408 | 0.384 |
| **Dr. Zero** | **0.406** | **0.608** | **0.416** | 0.362 | **0.347** | 0.104 | 0.360 | **0.372** |

在单跳任务上，3B 模型 Dr. Zero 全面超越监督基线 Search-R1，NQ 提升 22.9%。在多跳任务上，7B 模型在 2WikiMQA 上超越 Search-R1，但在 MuSiQue 和 Bamboogle 上仍落后，平均性能约为 Search-R1 的 90%。与零数据基线 R-Zero* 相比，Dr. Zero 在多跳基准上平均提升 83.3%，验证了难度引导奖励的有效性。

消融实验显示，问题跳数比例对性能影响显著。3B 模型在 4:3:2:1（单跳:双跳:三跳:四跳）比例下表现最佳，表明小模型需更多单跳任务夯实基础；7B 模型则在更高比例多跳数据下表现更优，反映大模型具备更强的跨跳依赖解析能力。训练动态分析显示，Solver 在约 50 步内达到性能峰值，后续迭代增益递减，7B 模型在第 3 轮出现轻微性能下降，提示自进化存在稳定性瓶颈。

评估协议采用 Exact Match，搜索引擎统一为 E5 base，语料为英文维基百科。代码已开源。局限在于：未报告置信区间，多跳任务性能仍低于基于特定架构优化的 SOTA（如 EvoFSM），且仅展示 3 轮迭代，长期训练下的灾难性遗忘风险未验证。

## 关联研究分析

从问题动机看，Dr. Zero 与 R-Zero 同属零数据自进化路线，但 R-Zero 聚焦数学/代码等封闭域，问题结构单一，无需外部工具；Dr. Zero 针对开放域搜索，问题生成需依赖搜索引擎验证可解性，这导致其必须引入难度引导奖励以平衡问题多样性与求解可行性。R-Zero 的嵌套采样在数学任务中可接受，但在多轮搜索中不可行，故 Dr. Zero 提出 HRPO 替代 GRPO，这一差异源于任务交互长度的本质不同。

从方法设计看，Dr. Zero 与 Search-R1 同属搜索增强 LLM，但 Search-R1 依赖人工标注数据训练，而 Dr. Zero 完全依赖自生成数据。Search-R1 在多跳任务上表现更优，可能因其训练数据覆盖了更广泛的真实查询分布，而 Dr. Zero 的自生成问题虽经难度过滤，但仍可能存在分布偏差。此外，Dr. Zero 未对比 Reflexion 等非参数化反思方法，后者通过外部记忆实现即时修正，可能在计算效率上优于参数化自进化，但长期能力内化能力较弱。

## 总结

Dr. Zero 解决了零数据约束下搜索代理自进化的计算瓶颈与问题生成单一性问题，通过 HRPO 与难度引导奖励，使 3B 模型在单跳任务上超越监督基线 22.9%，7B 模型在多跳任务上达到监督基线 90% 的性能。其边界在于多跳任务性能仍低于架构优化 SOTA，且 3 轮迭代后出现性能平台期，7B 模型甚至出现轻微退化。当迭代次数增加至 5 轮以上时，Solver 的灾难性遗忘是否会抵消 Proposer 的难度提升收益，论文未给出回答。
