> 现有大语言模型智能体在开放环境中受限于静态工具集，无法应对分布漂移。主流自进化方法依赖离线监督或局限于单一领域，缺乏无监督下的持续适应能力。本文提出原位自进化框架，通过并行批量合成与吸收机制动态扩展工具库，实现零启动下的跨域迁移。该方法在多个基准上验证了工具进化的有效性，但其收敛性依赖任务语义的稳定性，对高度动态环境的适应性存疑。

## 研究背景

当智能体面对未见过的任务时，其预定义的工作流与上下文往往失效，此时若缺乏执行特定操作的工具，即使拥有强大的推理能力也无法完成任务。这种能力缺口被称为工具缺失，它直接导致智能体在开放环境中的执行瘫痪。为弥补这一缺口，智能体需要具备自主合成新工具的能力，但合成过程若缺乏反馈机制，极易产生冗余或错误代码，进而污染执行上下文。

自进化智能体旨在解决静态系统的脆弱性，现有路线主要分为工作流优化、参数更新与工具合成三类。工作流优化如 AFlow 生成查询特定的执行图，参数更新如 TT-SI 通过生成训练问题微调模型，但前者缺乏跨任务泛化性，后者依赖离线监督信号。工具合成路线如 Voyager 和 STELLA 实现了即时工具创建，但多局限于软件工程或生物医学等窄域，且缺乏工具复用与收敛监控机制。本文切入点在于将工具进化视为无监督下的在线学习过程，通过执行反馈的二元信号（成功/异常）驱动工具库的迭代优化，摆脱对人工标注或离线训练的依赖。

## 核心方法

### 方法参照系

本文问题可置于工具与技能自生成路线中，其标准流程为：检索现有工具 → 合成新工具 → 执行任务 → 更新工具库。与 Voyager 等单步即时更新不同，本文引入批量处理与吸收机制，将工具进化从单查询粒度提升至批次粒度，以平衡实时适应性与计算效率。

### 并行批量进化与工具吸收

针对单步进化中工具冗余导致检索空间膨胀的问题，本文提出并行批量进化策略。给定批次 $Q_t = \{q_{t,1}, \dots, q_{t,B}\}$，系统并行生成局部工具集 $P_{t,i}$，随后通过吸收机制聚类合并。具体地，聚合所有工具 $\{T_{t-1}, P_{t,1}, \dots, P_{t,B}\}$，基于功能语义相似度聚类为 $\{G_j\}$，再通过合并函数 $\Phi$ 生成紧凑工具池：

$$T_t = \Phi(\{G_j\})$$

该公式的物理含义是：通过语义聚类消除功能等价工具的冗余，保留最具代表性的实现，从而降低后续检索的认知负载。这一设计解决了单步进化中因重复生成相似工具导致的检索歧义问题，使工具库在扩展功能覆盖的同时保持精简。

### 进化通用性损失监控

为量化工具库的收敛状态，本文提出进化通用性损失（EGL）指标，定义为合成工具数与调用次数的累积比值：

$$EGL_t = \frac{\sum_{i=1}^t c_i}{\sum_{i=1}^t u_i}$$

其中 $c_i$ 和 $u_i$ 分别为第 $i$ 步的工具合成数与调用数。EGL 与工具库通用性负相关：初始阶段高 EGL 反映快速积累，随进化推进逐渐下降并趋于稳定。该指标类比训练损失，为无监督进化提供了可监控的收敛信号，解决了此前方法缺乏量化评估工具库成熟度的问题。

## 实验评估

实验在 HLE、DSQA、FSC、xBench 等五个基准上进行，基线包括 GPT-5、Gemini 3 Pro 等静态模型及增强版本。本文方法在 DSQA 上取得 73.5 的准确率，较 Gemini 3 Pro 基线（56.6）提升 16.9 点；在 FSC 上取得 65.0，较基线（49.9）提升 15.1 点。消融实验显示，纯 Python 解释器基线（无工具积累）准确率为 40.0，执行成功率 81.8%，每次调用消耗 518 tokens，而本文方法执行成功率 >99%，token 消耗显著降低，表明工具进化通过减少冗余调用提升了效率。

| --- | --- | --- | --- |
| DeepSearchQA | ZS | 73.5 | 34 |
| DeepSearchQA | WS | 74.6 | 23 |
| FinSearchComp | ZS | 65.0 | 18 |

热启动实验表明，使用 HLE 进化工具集初始化后，xSciQA 和 xDS 的新工具合成量降至 0，准确率分别提升 3.7 和 0.9 点，验证了工具库的跨域迁移能力。然而，评估协议未报告置信区间，且基线覆盖缺乏 Reflexion、EvolveR 等自进化专用方法，难以区分工具进化与骨干模型能力的贡献占比。

## 关联研究分析

从问题动机看，本文与 Voyager 同属工具自生成路线，但 Voyager 聚焦于 Minecraft 等单一环境的技能库积累，而本文强调零启动下的跨域迁移。这一差异源于任务特性：Voyager 的环境语义相对固定，工具复用率高；而本文的开放域任务语义漂移大，需通过吸收机制动态调整工具库结构。从方法设计看，本文与 Alita-G 均关注工具持久化，但 Alita-G 依赖高质量元数据支持工具选择，而本文通过执行反馈的二元信号实现自主修正，无需外部标注。这种设计选择反映了本文对无监督场景的侧重，但可能牺牲了工具选择的精细度，当任务语义高度相似时，吸收机制的聚类精度是否足够，论文未给出回答。

## 总结

本文核心矛盾在于静态工具集无法适应开放环境的分布漂移，其切入点在于将工具进化建模为无监督在线学习，通过执行反馈驱动工具库迭代。方法上，并行批量进化与吸收机制平衡了效率与冗余，EGL 指标提供了收敛监控。实验证明，工具进化在 DSQA 和 FSC 上分别提升 16.9 和 15.1 点，且热启动下新工具合成量降至 0。边界在于，EGL 收敛依赖任务语义的稳定性，当环境动态变化导致工具功能频繁失效时，吸收机制的聚类精度可能下降。当任务分布发生剧烈漂移时，EGL 指标能否及时捕捉到工具库的失效信号，论文未给出回答。
