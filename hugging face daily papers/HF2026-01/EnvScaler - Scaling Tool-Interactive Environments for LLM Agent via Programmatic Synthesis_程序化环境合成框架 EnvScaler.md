> 大语言模型智能体在长程任务中依赖外部工具交互，但真实环境访问受限、LLM模拟环境存在幻觉、人工构建沙箱难以规模化，导致高质量训练数据稀缺。现有环境合成方法或依赖预置工具集，或缺乏自动化质量评估，无法支撑大规模强化学习训练。EnvScaler 通过程序化代码生成可执行沙箱，结合双智能体迭代评估与规则化轨迹验证，实现了从文本资源到可训练环境的自动化闭环。该框架验证了合成环境对多轮多工具任务性能的显著提升，但其绝对性能仍低于当前 SOTA，且环境多样性对泛化的具体贡献机制尚未量化。

## 研究背景

当智能体需要在电商后端修改订单或管理文件系统时，它必须调用特定工具查询或更新环境状态，这一过程称为工具交互。工具交互要求智能体在长轨迹中遵守环境规则并基于反馈调整动作，但真实 API 往往存在访问限制或数据隐私问题，而 LLM 模拟环境虽可无限扩展，却因缺乏持久状态管理而产生逻辑不一致与幻觉。这种矛盾使得智能体训练缺乏稳定、可控且可验证的沙箱环境，成为制约策略优化与跨环境泛化的核心瓶颈。

主流路线分为三类：LLM 模拟环境依赖模型推理能力，虽无需构建真实系统，但无法保证多次调用间的逻辑连贯性；基于轨迹重建的环境（如 AgentScaler）依赖预置工具集或历史数据，缺乏自动化质量评估机制；纯 LLM 生成的静态轨迹无法支持智能体自主探索。EnvScaler 的切入点在于摒弃对预置工具集或环境先验的依赖，通过程序化代码直接生成包含状态、规则与工具接口的可执行沙箱，并引入双智能体迭代评估机制确保环境逻辑的可靠性，从而解决环境合成中的可扩展性与一致性难题。

## 核心方法

### 环境骨架自动化构建

环境合成通常依赖人工设计或从 API 文档逆向推导，但前者成本高且覆盖有限，后者受限于工具描述的准确性。EnvScaler 提出 SkelBuilder，从现有任务集反向推断环境主题，通过 LLM 生成状态定义、领域规则与工具操作列表，并编程实现为可执行 Python 类。该过程的关键在于将环境抽象为三元组 $E = \{F_{exec}, E_{doc}, \Sigma_{tool}\}$，其中 $F_{exec}$ 为完整逻辑实现，$E_{doc}$ 为文档，$\Sigma_{tool}$ 为工具接口集。AST 语法验证确保代码有效性，正则提取生成工具签名，形成标准化交互入口。

### 双智能体迭代评估

静态 LLM 评分无法捕捉工具执行时的动态行为偏差，导致环境逻辑缺陷在训练阶段才暴露。SkelBuilder 引入测试智能体与检查智能体构成的闭环：测试智能体随机生成正负测试用例（如调用删除工具处理不存在文件），检查智能体对比源码、返回结果与状态变化，判断行为是否符合预期。经过 $N$ 轮迭代，环境质量得分定义为：

$$
\text{score}_{env} = \frac{1}{N} \sum_{j=1}^{N} \mathbb{I}[\text{Pass}_j]
$$

其中 $\mathbb{I}[\text{Pass}_j]$ 为第 $j$ 轮测试通过指示函数。低于阈值（0.85）的环境被丢弃，确保进入训练集的环境具备高可靠性。

### 场景生成与规则化验证

环境骨架仅提供结构，缺乏初始状态与任务定义。ScenGenerator 基于环境类定义生成初始状态数据 $S_{init}$，并从中推导挑战性任务。与逆向工具调用序列生成任务不同，该方法直接提示 LLM 从 $S_0$、$\Sigma_{tool}$ 与 $E_{rule}$ 生成场景特定任务，避免多解路径导致的“真值”歧义。任务被分解为可验证条件清单，每个条件生成终态验证函数 $f_k(S_{final}) \in \{True, False\}$，轨迹奖励为：

$$
R = \frac{1}{K} \sum_{k=1}^{K} f_k(S_{final})
$$

其中 $K$ 为验证函数数量。该规则化奖励机制解决了长轨迹中最终奖励难以归因到中间步骤的信用分配难题，使强化学习训练具备可验证信号。

## 实验评估

实验在 BFCL-MT、Tau-Bench 与 ACEBench 三个基准上评估 Qwen3 系列模型（1.7B/4B/8B），基线覆盖 SFT 与 RL 两种训练范式，但缺失 ReAct 等经典提示工程基线的直接对比。主实验显示，EnvScaler 训练显著提升小模型性能：Qwen3-8B 在 BFCL-MT 上从 28.88% 提升至 37.62%（+8.74 点），Tau-Bench 从 60.00% 提升至 63.05%（+3.05 点）。

| 模型 | BFCL-MT | ACEBench-Agent | Tau-Bench |
| :--- | :--- | :--- | :--- |
| Qwen3-8B (Base) | 28.88 | 38.19 | 60.00 |
| Qwen3-8B + EnvScaler (RL) | 37.62 | 42.30 | 63.05 |
| Qwen3-4B (Base) | 25.38 | 33.44 | 55.28 |
| Qwen3-4B + EnvScaler (RL) | 29.38 | 35.15 | 61.25 |

消融实验揭示环境规模与交互模式的影响：训练环境数量从 0 增至 20 时性能提升最显著，之后边际收益递减；Non-Conv 设置（完整任务信息）在 Base/Long-Context 子集表现更优，而 Conv 设置（缺失工具/参数）在 Miss-Parm 子集得分更高，表明智能体需同时学习完整与不完整信息下的交互策略。

评估边界存在局限：BFCL-MT 上 Qwen3-8B+EnvScaler(RL) 的 37.62% 低于 Tool-R0 的 47.84%（据领域综述），Tau-Bench 的 63.05% 低于 CaveAgent 的 80.0%（据领域综述），表明合成环境训练尚未超越前沿大模型或专用 RL 框架的绝对性能。代码已开源（RUC-NLPIR/EnvScaler），但论文未报告 GPU 资源消耗与训练时长，可复现性依赖读者自行配置。

## 关联研究分析

从问题动机看，EnvScaler 与 AgentScaler 均聚焦环境合成，但 AgentScaler 依赖预置工具集或工具文档，而 EnvScaler 通过任务反向推断实现全自动挖掘，消除了对环境先验的依赖。这一差异源于任务特性：AgentScaler 面向特定工具生态的适配，而 EnvScaler 追求跨领域泛化，因此必须摆脱对固定工具集的绑定。然而，全自动挖掘是否导致环境主题分布偏差，论文未提供统计检验。

从方法设计看，EnvScaler 与 Tool-R0 均利用 RL 优化策略，但 Tool-R0 侧重工具调用策略学习，EnvScaler 侧重环境多样性与可验证性。Tool-R0 在 BFCL-MT 上取得 47.84% 的更高性能（据领域综述），可能源于其难度奖励机制对长轨迹信用分配的更精细处理，而 EnvScaler 的规则化验证函数虽提供可验证信号，但缺乏步骤级过程监督。这种差异暗示环境合成与策略优化是互补而非替代关系，EnvScaler 提供训练底座，Tool-R0 提供优化算法，两者结合可能进一步提升性能，但论文未探索此方向。

## 总结

EnvScaler 解决的核心矛盾是工具交互环境合成中的可扩展性与一致性冲突：真实环境不可访问、LLM 模拟不可靠、人工构建不可扩展。其切入点在于程序化代码生成与双智能体迭代评估的结合，前者确保环境逻辑的可控性，后者验证动态行为的一致性。通过 SkelBuilder 与 ScenGenerator，框架自动化生成 191 个环境与 7K 场景，使 Qwen3-8B 在 BFCL-MT 上提升 8.74 点。然而，实验暴露的边界在于：合成环境训练的绝对性能仍低于 Tool-R0 等专用 RL 框架，且环境多样性对跨环境泛化的具体贡献机制未量化。当训练环境与测试环境的相似度对性能影响有限时，环境数量与主题分布的何种组合能最大化泛化能力，论文未给出回答。
