# HuggingFace最新推荐论文 ｜OpenNovelty: An LLM-powered Agentic System for Verifiable Scholarly Novelty Assessment ｜可验证的新颖性评估

研究机构：复旦大学

作者：Ming Zhang、Kexin Tan、Yueyuan Huang 等 23 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.01576)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.01576)

> 同行评审中“新颖性”判断长期依赖评审员对海量文献的隐性记忆，导致评估主观且难以追溯。现有基于检索增强生成（RAG）的方法多停留在摘要级对比，无法捕捉技术细节差异，且缺乏对引用真实性的硬约束。OpenNovelty 通过贡献级全文对比与 Token 级证据验证机制，将新颖性判断转化为可追溯的证据链。该系统在 500+ ICLR 2026 投稿上的部署表明其能识别被作者忽略的相关工作，但其评估体系仍缺乏与人类评审者一致性的量化指标。

## 研究背景

新颖性评估的核心困境在于文献规模的指数级增长与评审员认知带宽的有限性之间的结构性矛盾。当评审员面对一篇论文时，需将其贡献与领域内所有潜在相关工作进行比对，这一过程称为“新颖性检索”。然而，传统人工检索受限于时间成本，往往仅覆盖高引用或知名作者的工作，导致对新兴子领域或跨学科工作的盲区。这种盲区直接引发了“引用幻觉”风险：评审员或辅助工具可能基于参数化知识生成看似合理但实际不存在的文献引用，破坏了学术诚信。

当前 LLM 辅助评审的主流路线分为两类：一类是纯生成式方法，依赖模型内部知识直接输出评审意见，虽效率高但幻觉率高；另一类是 RAG 方法，通过外部检索提供事实依据，但多数实现仅对比标题和摘要，忽略了方法论细节。AutoSurvey 等早期工作确立了“检索-大纲-生成”的结构化流程，解决了长文本连贯性问题，但未深入解决引用准确性。ALCE 基准建立了归因长文本生成的评价标准，但缺乏对“贡献级”细粒度对比的支持。OpenNovelty 的切入点在于将新颖性评估从“文本相似度匹配”转向“贡献主张的可证伪性检验”，通过强制全文对比和证据验证，解决现有方法在技术细节比对上的缺失。

## 核心方法

### 方法参照系

本文问题可置于“检索增强生成（RAG）辅助学术评审”的通用流程中，标准流程为：查询生成 → 语义检索 → 上下文整合 → 评审生成。关键差异在于，通用流程通常将检索结果作为背景知识注入提示词，由 LLM 自由生成评价；而 OpenNovelty 将检索结果作为“证据源”，要求 LLM 对每个贡献主张进行独立的、基于全文的对比分析，并输出可验证的证据片段，而非自由文本。

### 贡献级全文对比与三态判断

在标准 RAG 流程中，检索到的文档通常被截断或摘要化后输入 LLM，导致技术细节丢失。OpenNovelty 在 Phase III 引入贡献级对比机制，针对 Phase I 提取的每个贡献主张（Contribution Claim），独立检索并对比 Top-10 候选论文的全文。设计动机是解决摘要级对比无法识别“方法相似但应用场景不同”或“架构相同但算法细节不同”的细微差异。

对于每个贡献主张 $c_i$ 和候选论文 $p_j$，LLM 输出三态判断 $J(c_i, p_j) \in \{can\_refute, cannot\_refute, unclear\}$。其中 $can\_refute$ 表示候选论文提供了足以挑战新颖性的证据。该判断必须伴随从两篇论文中提取的逐字引用（Verbatim Quotes）作为证据。公式化表达为：

$$
J(c_i, p_j) = \begin{cases} can\_refute & \text{if } \exists e_t \in Q_t, e_p \in Q_p \text{ s.t. } Sim(e_t, e_p) > \tau \land Verify(e_t, e_p) = True \\ cannot\_refute & \text{otherwise} \end{cases}
$$

其中 $Q_t, Q_p$ 分别为目标论文和候选论文的全文集合，$Sim$ 为语义相似度，$Verify$ 为证据验证函数。这一设计将新颖性判断从主观评价转化为基于证据的逻辑推断，若证据缺失或验证失败，判断自动降级为 $cannot\_refute$，从而从机制上抑制幻觉。

### Token 级锚点验证与 MECE 分类法

LLM 生成的引用可能存在“看似正确但实际不存在”的幻觉，这是 RAG 系统的固有缺陷。OpenNovelty 在 Phase III 引入 Token 级锚点验证（Token-level Anchor Alignment），作为硬约束嵌入判断逻辑。设计动机是解决 CiteGuard 等事后验证方法延迟高、无法实时嵌入生成流程的问题。

验证算法计算引用片段 $e$ 在源文本 $S$ 中的置信度 $Conf(e, S)$，定义为锚点覆盖率与命中率的加权组合：

$$
Conf(e, S) = \alpha \cdot \frac{|\{t \in e \mid t \in S\}|}{|e|} + (1-\alpha) \cdot \frac{|\{t \in e \mid t \in S\}|}{|\{t \in S \mid t \in e\}|}
$$

若 $Conf(e, S) > 0.6$，则引用被视为有效。此外，为组织 Top-50 核心任务候选论文，OpenNovelty 采用 LLM 驱动的 MECE（Mutually Exclusive, Collectively Exhaustive）分类法。与传统聚类算法产生无标签距离分割不同，LLM 动态选择分类轴（如方法论、问题定义），并为每个节点生成 `scope_note` 和 `exclude_note`，确保每篇论文仅归属一个类别。这一设计解决了传统聚类在学术文献中语义边界模糊的问题，为后续对比提供结构化上下文。

## 实验评估

该论文未提供标准化的定量基准测试数据，而是以 500+ ICLR 2026 投稿的部署案例作为主要验证手段。实验设置中，系统使用 `claude-sonnet-4-5-20250929` 作为核心 LLM，Wispaper 作为语义搜索引擎。基线审计显示，论文未与 Reviewer2、EGTR-Review 等经典评审生成方法进行直接对比，也未与 CiteGuard 等引用验证工具进行性能对标，缺乏横向比较。

在过滤效率方面，论文报告了一个典型示例：从 2,328 篇原始检索结果中，经质量标志过滤（-72.9%）、范围内去重（-22.4%）和跨范围去重（-8.8%），最终保留 73 篇唯一候选论文，整体过滤率为 96.9%。这一数据表明多层过滤策略能有效控制计算成本，但仅展示了单篇论文的处理流程，未提供大规模部署下的平均延迟或吞吐量指标。

评估边界方面，论文缺乏与人类评审者新颖性评分的一致性指标（如 Pearson 相关系数或 Cohen's Kappa），无法量化系统判断与专家判断的偏差。可复现性方面，论文提供了网站链接（opennovelty.org）供查看报告，但未开源代码仓库或提供完整的超参数配置，限制了第三方复现与对比实验的可能性。

## 关联研究分析

从方法设计看，OpenNovelty 与 CiteGuard 在引用验证机制上存在显著差异。CiteGuard 采用检索增强验证，在生成后通过交互式查询验证引用真实性，属于“事后补救”策略；而 OpenNovelty 将验证作为硬约束嵌入生成逻辑，若证据未通过 Token 级验证，判断直接降级。这一差异源于任务特性：新颖性评估要求每个判断都可追溯，事后验证无法保证生成过程中的逻辑一致性。然而，OpenNovelty 的验证阈值（0.6）是经验值，未通过消融实验证明其对不同领域文献的鲁棒性，这在跨学科应用中可能成为盲区。

从问题动机看，OpenNovelty 与 SurveyG 在文献组织方式上形成对比。SurveyG 使用层级引用图捕捉论文间关系，侧重于全局拓扑结构；OpenNovelty 采用 LLM 驱动的 MECE 分类法，侧重于局部语义边界。SurveyG 的图结构依赖引用网络的质量，在稀疏引用领域效果有限；OpenNovelty 的分类法依赖 LLM 的语义理解能力，但缺乏对分类轴选择的稳定性保证。两者均未解决“动态文献流”下的实时更新问题，即当新论文发表时，如何增量更新分类法或引用图，这是当前方法共同的局限。

## 总结

OpenNovelty 旨在解决同行评审中新颖性评估的主观性与不可追溯性矛盾。其切入点在于将新颖性判断转化为基于贡献级全文对比和 Token 级证据验证的逻辑过程，通过硬约束机制抑制幻觉。系统通过四阶段流水线实现自动化，在 500+ ICLR 2026 投稿上的部署表明其能识别被作者忽略的相关工作，过滤效率达 96.9%。然而，论文未提供与人类评审者一致性的量化指标，且验证阈值的鲁棒性未经跨领域验证。当文献规模进一步扩大或领域跨度增加时，LLM 驱动的 MECE 分类法能否保持语义边界的稳定性，论文未给出回答。
