# HuggingFace最新推荐论文 ｜SmartSearch: Process Reward-Guided Query Refinement for Search Agents ｜过程奖励引导的查询精炼

研究机构：中国人民大学

作者：Tongyu Wen、Guanting Dong、Zhicheng Dou

论文原文见 [arXiv](https://arxiv.org/abs/2601.04888)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.04888)

> 智能体搜索的核心瓶颈在于中间检索查询的质量，低质查询会直接导致检索结果偏离预期，进而使后续推理陷入错误路径。现有强化学习（RL）方法多依赖最终答案的正确性作为稀疏奖励，缺乏对中间步骤的细粒度监督，导致模型无法有效优化查询生成策略。本文提出 SmartSearch，通过双层信用评估提供查询级过程奖励，并结合查询精炼机制与三阶段课程学习框架，使智能体在训练阶段内化高质量查询生成能力。该框架在单体架构下显著提升了多跳问答性能，但其对检索器本身的优化依赖外部模型，且未验证在广度搜索任务中的泛化边界。

## 研究背景

当 LLM 执行多跳推理时，若中间步骤生成的检索查询存在细微偏差（如遗漏关键限定词），检索器将返回无关文档，导致智能体基于错误证据进行推理，最终答案失效。这一现象揭示了检索增强生成（RAG）中“查询质量”与“推理正确性”的强耦合关系。传统 RAG 将检索视为静态黑盒，仅关注文档与查询的匹配度，却忽视了查询本身在动态推理过程中的演化质量。

智能体搜索（Agentic Search）试图通过迭代调用工具解决静态 RAG 的局限，但现有强化学习训练范式主要聚焦于优化推理路径或最终答案，对中间查询的质量缺乏直接监督。Search-R1 等工作采用结果奖励（Outcome Reward），仅当最终答案正确时才给予正向反馈，这种稀疏信号无法指导模型识别并修正中间步骤的低质查询。尽管部分研究引入了过程奖励（Process Reward），但多侧重于推理步骤的价值估计，而非针对检索查询本身的语义质量进行优化。本文切入点在于将查询质量作为独立优化目标，通过细粒度过程奖励与主动精炼机制，解决中间查询盲目生成导致的检索失效问题。

## 核心方法

### 方法参照系

本文基于 ReAct 框架与 Group Relative Policy Optimization (GRPO) 算法构建智能体搜索系统。标准流程中，智能体在每一步生成思考（Thought）与动作（Action，即查询），环境返回观察（Observation，即检索文档），最终生成答案。GRPO 通过比较同一查询下多条轨迹的奖励差异来优化策略，但传统奖励函数仅包含格式奖励与最终答案正确性奖励，缺乏对中间查询质量的显式建模。

### 双层信用评估与过程奖励

设计动机在于解决稀疏结果奖励无法提供中间步骤细粒度反馈的问题。本文引入双层信用评估（Dual-Level Credit Assessment）机制，为每个中间查询 $a_t$ 计算过程奖励 $S_t$。该机制包含规则评估与模型评估两部分：规则评估通过计算当前检索文档与历史文档的重叠度 $O_t$ 来检测查询新颖性，若 $O_t > K$ 则判定为冗余；模型评估通过微调后的小模型判断查询意图的必要性与检索结果的相关性。

$$ S_t = \begin{cases} 1 & \text{if } O_t \le K \land \text{LLM}_{\text{eval}}(q, a_t, H_t) = 1 \\ 0 & \text{otherwise} \end{cases} $$

该公式将查询质量量化为二元信号，同时生成文本反馈 $T_t$ 用于后续精炼。相比仅依赖最终答案的奖励，$S_t$ 提供了步骤级的即时监督，使模型能够区分“正确但低效”与“正确且高效”的轨迹。

### 查询精炼与三阶段课程学习

设计动机在于将过程奖励从被动信号转化为主动优化机制。在 Query Aware Policy Optimization 阶段，智能体生成初始轨迹 $y_0$ 后，识别其中 $S_t=0$ 的低质查询，利用文本反馈 $T_t$ 指导小模型生成精炼查询 $a'_t$，并基于 $a'_t$ 重新生成后续步骤，形成扩展轨迹集 $\{y_0, y_1, \dots, y_n\}$。这一机制改变了 GRPO 的 Rollout 策略，从独立采样转向基于精炼的序列扩展，确保对比数据的关键差异源于查询质量。

$$ r_{\text{composite}} = r_{\text{outcome}} + \gamma \cdot \frac{n_{\text{correct}} - n_{\text{wrong}}}{n_{\text{total}}} $$

该奖励函数将最终答案正确性 $r_{\text{outcome}}$ 与过程奖励（高质量查询数与低质量查询数之差）加权结合，激励模型在追求答案正确的同时优化查询过程。三阶段课程学习（SFT 筛选、DPO 对齐、GRPO 优化）逐步内化查询质量优化能力，避免了直接从零开始训练的不稳定性。

## 实验评估

实验在 2WikiMQA、HotpotQA、Bamboogle、Musique 四个知识密集型基准及 GAIA、WebWalker 两个网络探索任务上进行，基线覆盖 Prompt-based、Outcome-RL 与 Process-RL 三类方法，但缺失多智能体架构（如 M-ASK）及检索器联合优化（如 CoSearch）的对比。

| 方法 | 2WikiMQA F1 | HotpotQA F1 | Bamboogle F1 | Musique F1 | Average F1 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Search-R1 | 35.5 | 41.1 | 38.8 | 16.6 | 33.0 |
| StepSearch | 38.9 | 45.9 | 48.4 | 24.9 | 39.5 |
| SmartSearch | 52.3 | 52.4 | 56.1 | 27.8 | 47.2 |

SmartSearch 在平均 F1 上超越 StepSearch 7.7 个百分点，显著优于 Search-R1 的 14.2 个百分点，验证了查询级过程奖励的有效性。消融实验显示，移除查询精炼机制后，Stage 3 的平均 F1 从 47.2 降至 45.9，降幅 1.3 个百分点；移除过程奖励后，降幅达 2.5 个百分点，表明过程奖励对查询质量优化的贡献大于精炼机制本身。

评估边界方面，论文未报告置信区间，且所有实验基于 Qwen2.5-3B-Instruct 单一骨干模型，未验证不同规模模型下的性能差异。代码已开源，但训练数据 Asearcher-Base 的构建细节未完全披露，可能影响复现性。

## 关联研究分析

从问题动机看，SmartSearch 与 StepSearch 均关注过程奖励，但 StepSearch 侧重步骤级价值估计，通过蒙特卡洛树搜索（MCTS）评估中间动作的长期价值，而 SmartSearch 聚焦查询级语义质量，通过双层评估直接判断查询的新颖性与相关性。这一差异源于任务特性：MCTS 适用于推理路径复杂的任务，而查询质量优化更适用于检索密集型的问答任务。SmartSearch 未探索 MCTS 与查询精炼的结合，可能在推理深度较大的任务中表现受限。

从方法设计看，SmartSearch 与 CoSearch 在检索器优化上存在根本差异。CoSearch 通过联合优化检索器与智能体，使检索器适应智能体的动态查询模式；而 SmartSearch 保持检索器为静态黑盒，仅优化智能体的查询生成策略。这种设计选择降低了系统复杂度，但可能限制了检索器对智能体行为的适应性。查询侧增强在检索器固定时是否仍有增益，论文未给出回答，尤其在非结构化语料场景下，静态检索器可能成为性能瓶颈。

## 总结

SmartSearch 解决了智能体搜索中中间查询质量被忽视导致的检索失效问题，通过双层信用评估提供细粒度过程奖励，并结合查询精炼机制与三阶段课程学习，使模型在训练阶段内化高质量查询生成能力。实验表明，该方法在 HotpotQA 上取得 52.4 F1，超越 Search-R1 的 41.1 F1，验证了过程奖励在查询优化中的有效性。然而，论文仅验证了单体架构在深度问答任务中的性能，未探索多智能体协同或检索器联合优化场景，且训练数据依赖特定基准，泛化性存疑。当检索器本身存在偏差时，仅优化查询生成策略能否突破性能上限，论文未给出回答。
