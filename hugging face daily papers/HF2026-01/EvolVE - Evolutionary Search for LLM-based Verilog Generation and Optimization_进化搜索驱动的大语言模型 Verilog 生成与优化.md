# HuggingFace最新推荐论文 ｜EvolVE: Evolutionary Search for LLM-based Verilog Generation and Optimization ｜进化搜索驱动的大语言模型 Verilog 生成与优化

研究机构：国立台湾大学、新加坡南洋理工大学

作者：Wei-Po Hsin、Ren-Hao Deng、Yao-Ting Hsieh 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.18067)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.18067)

> 硬件设计自动化面临的核心矛盾是高质量 Verilog 训练数据稀缺与大语言模型顺序推理能力无法匹配硬件并发语义。现有静态微调路线受限于数据规模，而单轮生成无法从逻辑错误中恢复，导致复杂时序逻辑生成失败。EvolVE 提出将 HDL 生成重构为状态空间探索问题，通过蒙特卡洛树搜索与想法引导细化两种进化策略，结合结构化测试平台生成提供细粒度反馈，实现代码的迭代自修正。该框架在功能正确性与性能功耗面积优化上均取得显著进展，但其对开源综合工具的依赖及基准测试的工业代表性仍存疑。

## 研究背景

Verilog 作为硬件描述语言，其本质是描述由时钟同步的数千个并行操作，这种严格的并发范式与基于下一词元预测的大语言模型存在根本冲突。直接应用大语言模型生成 Verilog 常导致功能错误或不可综合代码，因为模型难以捕捉循环精确的同步语义。为解决此问题，测试平台（Testbench）成为验证生成代码功能正确性的关键基础设施，而性能、功耗与面积（PPA）则是衡量设计工业级质量的核心指标，传统人工编码难以在开发周期内同时满足这两者。

领域主流路线分为静态微调与智能体框架两类。静态微调如 RTLCoder 和 CodeV-R1 试图通过领域特定数据内化硬件知识，但受限于开源 Verilog 数据稀缺，模型在复杂模块上易产生功能幻觉。智能体框架如 REvolution 引入进化思想，但现有基准如 RTLLM v2 规模小且缺乏工业级复杂度，无法评估 PPA 优化能力。EvolVE 的切入点在于放弃对大规模训练数据的依赖，转而利用测试时计算，通过进化搜索让模型在推理阶段迭代探索设计空间，从而弥补数据稀缺与模型容量不足的瓶颈。

## 核心方法

### 进化搜索范式

EvolVE 将 Verilog 生成定义为状态空间搜索问题，节点 $N_i$ 由代码 $V_i$、分数 $S_i$ 和反馈 $F_i$ 组成。该范式的关键差异在于不依赖模型参数更新，而是通过外部评估器提供反馈，驱动模型在推理阶段进行多轮迭代。这种设计解决了静态微调在数据有限时泛化能力不足的问题，将计算资源从预训练转移至推理阶段。

### 双策略进化机制

针对探索与利用的平衡，EvolVE 设计了两种互补策略。想法引导细化（IGR）通过生成多个高层架构概念并独立细化，实现全局探索以逃离局部最优，适用于 PPA 优化。蒙特卡洛树搜索（MCTS）则利用树结构进行局部利用，通过 UCT 公式选择节点：

$$ UCT(N_{parent}, N_{child}) = \frac{Q(N_{child})}{C(N_{child})} + c\sqrt{\frac{\ln C(N_{parent})}{C(N_{child})}} $$

其中 $Q$ 为累计质量值，$C$ 为访问次数，$c$ 控制探索强度。MCTS 通过回溯传播分数，精确解决局部功能与时序约束，适用于代码生成。这种分工解决了单一策略在复杂任务上无法兼顾全局架构创新与局部逻辑修正的失效。

### 结构化测试平台生成

进化搜索的有效性依赖高质量反馈。EvolVE 提出结构化测试平台生成（STG），通过正则表达式自动分类信号为时钟/复位、控制和数据通路，并生成混合激励。对于宽度 $w \le 8$ 的控制信号，STG 生成 $2^w$ 穷举覆盖；对于更宽总线，采用约束随机采样。STG 计算连续细粒度分数 $P_{stg} \in [0, 1]$：

$$ P_{stg} = \frac{\text{passed test vectors}}{\text{total test vectors}} $$

该分数作为功能梯度，使搜索引擎能优先选择部分正确的候选，加速收敛。这一设计解决了传统二元反馈（通过/失败）无法区分近似正确与根本错误的问题，将调试成本从昂贵的 LLM 推理转移至高效的 EDA 仿真工具。

## 实验评估

实验在 VerilogEval v2、RTLLM v2 及新提出的 IC-RTL 基准上进行。基线覆盖 Gemini-2.0-Flash、GPT-OSS-120B、DeepSeek-R1-FP4 等通用模型及 REvolution 等进化方法，但缺失 RTLCoder 等专用微调模型的直接对比。

| 方法 | VerilogEval v2 Pass@300 (%) | RTLLM v2 Pass@300 (%) |
| :--- | :--- | :--- |
| DeepSeek-R1-FP4 (Baseline) | 95.5 | 86.0 |
| DeepSeek-R1-FP4-MCTS | 98.1 | 92.0 |
| REvolution (DeepSeek-V3) | 95.5 | 88.0 |
| Siliconmind-7B-MCTS | 92.3 | 88.0 |

DeepSeek-R1-FP4-MCTS 在 VerilogEval v2 上达到 98.1%，显著高于基线的 95.5% 和 REvolution 的 95.5%。在 RTLLM v2 上，MCTS 策略将 DeepSeek-R1-FP4 的性能从 86.0% 提升至 92.0%，超越 REvolution 的 88.0%。这表明进化搜索在功能正确性上优于静态生成与单轮进化。

在 IC-RTL 基准上，EvolVE 在 Huffman Coding 任务中将 PPA 乘积降低 66%，几何均值降低 17%。消融实验显示，MCTS 在功能生成上稳定性优于 IGR，而 IGR 在 PPA 优化上更具优势。例如，在 Q5_HC 任务中，MCTS 实现 26% 延迟降低，而 IGR 实现 31% 面积减少。这种差异验证了双策略分工的有效性，但也暴露了策略选择对任务类型的依赖性。

评估边界方面，IC-RTL 基准源自台湾全国集成电路竞赛，其参考实现是否代表工业界最优水平存疑。此外，STG 依赖开源工具 Yosys 和 Icarus Verilog，其综合结果与商业工具 Synopsys 可能存在差异，论文虽声称通过 PrimeTime 验证，但未提供详细对比数据。代码已开源，但超参数如 UCT 中的 $c$ 值未完全披露，影响可复现性。

## 关联研究分析

从问题动机看，EvolVE 与 REvolution 同属进化搜索路线，但 REvolution 侧重双种群算法与提示选择，而 EvolVE 引入 STG 提供细粒度连续反馈。这一差异源于对反馈稀疏性的不同处理：REvolution 依赖二元反馈，导致收敛慢；EvolVE 通过 STG 将调试成本转移至 EDA 工具，加速了进化过程。然而，STG 的细粒度反馈是否导致对特定测试向量过拟合，论文未给出回答。

从方法设计看，EvolVE 与 RTLCoder 代表不同路线。RTLCoder 通过微调内化硬件知识，而 EvolVE 主张无微调的搜索范式。在数据稀缺场景下，EvolVE 的鲁棒性更优，但在数据充足场景下，微调模型可能因参数内化而具有效率优势。EvolVE 未探索数据充足时的性能对比，这一盲区限制了其结论的普适性。

## 总结

EvolVE 解决了硬件数据稀缺与 LLM 顺序推理不匹配硬件并发语义的核心矛盾，通过进化搜索范式利用测试时计算，弥补了静态微调的瓶颈。其双策略机制与 STG 引擎在 VerilogEval v2 上实现 98.1% 通过率，在 IC-RTL 上降低 PPA 乘积 66%，证明了进化搜索在功能正确性与 PPA 优化上的有效性。然而，IC-RTL 基准的工业代表性及 STG 对开源工具的依赖限制了其结论的泛化性。当训练数据规模扩大至百万级时，进化搜索的测试时计算开销是否仍优于大规模微调，论文未给出回答。
