# HuggingFace最新推荐论文 ｜SAGE: Steerable Agentic Data Generation for Deep Search with Execution Feedback ｜基于执行反馈的可控深度搜索数据生成

研究机构：美国纽约大学

作者：Fangyuan Xu、Rujun Han、Yanfei Chen 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.18202)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.18202)

> 深度搜索智能体训练面临高质量长程问答数据稀缺且标注成本高昂的困境，现有自动合成方法常因生成器意图与实际检索步数不匹配导致数据难度不可控。SAGE 通过引入搜索智能体的执行轨迹作为反馈信号，反向迭代修正数据生成器，实现了难度可控且正确性可验证的数据合成。该方法在固定语料上训练的智能体展现出向开放搜索引擎迁移的潜力，但其对特定检索器行为的依赖性及跨域泛化上限仍存疑。

## 研究背景

训练具备多步推理能力的深度搜索智能体，核心瓶颈在于缺乏足够长且逻辑连贯的“问题-答案”对。传统检索增强生成（RAG）多依赖单跳检索，而多跳问答数据集如 HotpotQA 或 Musique 通常仅包含 2-4 步检索，且严重依赖人工标注或文档间显式链接，难以扩展至更复杂的长程任务。这种数据长度的局限直接制约了智能体在长程决策中的泛化能力，使其在面对需要 5 步以上检索的复杂问题时表现骤降。

主流解决方案分为人工构建高难度基准与自动合成训练数据两条路线。人工构建如 GAIA 或 BrowseComp 虽能定义“难”的标准，但规模小且无法用于大规模强化学习（RL）训练；自动合成方法如 WebShaper 或 WebDancer 虽能利用浏览工具生成数据，但依赖昂贵的商业 API 且难以复现。现有自动合成方法普遍存在一个未被充分解决的缺陷：数据生成器（Data Generator）在规划问题时，其预期的搜索路径往往与搜索智能体（Search Agent）实际执行的路径存在偏差，导致生成的数据要么过于简单（信息共置），要么答案错误。SAGE 的切入点正是利用搜索智能体的实际执行轨迹（Execution Trace）作为反馈，闭合数据生成的质量闭环。

## 核心方法

### 逆向生成与难度控制参照系

SAGE 基于逆向生成（Reverse Formulation）范式，即先确定答案再反推问题，以确保数据忠实于语料库。与常规流程不同，SAGE 将“目标搜索步数 $S$”作为显式难度参数输入生成器。然而，仅靠提示词控制难度是无效的，因为生成器无法预知检索工具的具体行为，导致其规划的步数与实际所需步数脱节。

### 双智能体执行反馈闭环

SAGE 的核心创新在于引入搜索智能体 $A_{search}$ 对生成数据 $ (q, a) $ 进行验证，并将执行轨迹 $T_{search}$ 反馈给数据生成器 $A_{gen}$ 进行迭代修正。这一设计解决了生成器“盲目规划”导致的难度失真问题。具体而言，系统运行 $K$ 次搜索智能体，若存在正确轨迹且最少步数 $|S_{min}| \ge S$，则判定数据有效；否则，将失败或步数不足的轨迹 $T_{search}$ 连同原始 $ (q, a) $ 输入 $A_{gen}$，要求其重新生成更复杂或更准确的问题。

该反馈机制的数学表达为：

$$
(q_{new}, a_{new}) \leftarrow A_{gen}(q_{old}, a_{old}, S, T_{gen}, T_{search})
$$

其中 $T_{search}$ 包含了搜索智能体在尝试解答 $q_{old}$ 时的所有中间推理与检索步骤。这一公式的物理含义是：数据生成器不仅知道“答案是什么”，还知道“为什么之前的问题太简单或无法解答”，从而针对性地增加问题的逻辑复杂度或修正事实错误。

### 基于轨迹的难度校准

在验证阶段，SAGE 采用“最小正确步数”作为难度代理指标。对于 $K$ 条搜索轨迹，若其中 $M$ 条轨迹答案正确，则选取步数最少的正确轨迹 $t^*$ 作为难度基准：

$$
S^* = \min_{t \in M} |Steps(t)|
$$

若 $S^* < S$，则判定数据难度不足。这一设计避免了使用平均步数带来的模糊性，直接捕捉了问题在最优解下的真实复杂度。通过多轮（$R$ 轮）迭代，SAGE 能够逐步收敛至满足目标难度 $S$ 且答案正确的高质量数据对，显著提升了合成数据的信噪比。

## 实验评估

SAGE 在 2018 年 Wikipedia 语料库上生成数据，使用 E5 作为检索器，Gemini-2.5-flash 作为生成器与搜索智能体。基线包括 NQ+HotpotQA 和 Musique 训练集，评估指标涵盖域内（In-domain）及域外（Musique, FRAMES）的问答准确率。

| 训练数据 | 骨干模型 | 域内 AVG | Musique | FRAMES |
| :--- | :--- | :--- | :--- | :--- |
| NQ + HotpotQA | Qwen-7B | 29.1 | 26.2 | 21.6 |
| Musique | Qwen-7B | 29.6 | 25.0 | 22.3 |
| SAGE (Ours) | Qwen-7B | **38.1** | **32.3** | **22.3** |

在 Qwen-7B 模型上，SAGE 训练的数据在域内平均准确率上比 NQ+HotpotQA 基线提升 9.0 个百分点，在 Musique 上提升 6.1 个百分点。这表明 SAGE 生成的数据不仅难度更高，且推理类型更均衡（如计算与时序推理占比更高），从而提升了智能体的泛化能力。

消融实验显示，反馈轮数从 0 增加到 2 时，域内性能从 33.6% 提升至 38.1%，但增加到 3 轮时性能回落至 34.1%，尽管数据难度（Avg@4）进一步降低至 79.5%。这一反直觉现象表明，单纯增加数据难度并不等同于提升模型性能，过高的难度可能超出当前模型的认知边界，导致训练信号噪声化。

评估边界方面，SAGE 主要基于固定语料库（Wikipedia），虽验证了向 Google Search 迁移的潜力（GAIA 上相对提升 50%），但未在完全开放的多模态环境中测试。代码已开源，但依赖 Gemini 2.5-flash 作为核心 LLM，复现成本较高。

## 关联研究分析

从数据生成机制看，SAGE 与 WebShaper 同属自动合成路线，但 WebShaper 依赖浏览工具获取实时信息，而 SAGE 基于固定语料库。这一差异源于任务目标的不同：WebShaper 旨在解决信息时效性问题，而 SAGE 聚焦于推理链长度的可控性。SAGE 的固定语料设定降低了 API 成本，但引入了检索分布偏移风险，即模型在 Wikipedia 上训练的检索策略可能无法完全适配 Google Search 的网页结构。

从训练范式看，SAGE 与 Search-R1 形成互补。Search-R1 解决了“如何训练”的问题，通过 RL 优化搜索策略，但其性能上限受限于训练数据的质量；SAGE 则解决了“用什么训练”的问题，通过执行反馈确保数据难度与正确性。两者结合代表了当前深度搜索智能体研究的完整闭环：高质量数据驱动 RL 训练，RL 训练又反哺数据生成的验证环节。

## 总结

SAGE 针对深度搜索智能体训练数据稀缺且难度不可控的矛盾，通过引入搜索智能体的执行轨迹作为反馈信号，实现了数据生成与验证的闭环迭代。该方法在 Qwen-7B 模型上实现了域内 38.1% 的准确率，较基线提升 9.0 个百分点，证明了执行反馈在提升数据质量上的有效性。然而，实验揭示的“难度-性能”非线性关系表明，当前方法在数据难度调控上仍缺乏精细的平衡机制。当目标步数 $S$ 超过模型当前能力边界时，如何动态调整难度阈值以避免训练信号失效，是 SAGE 框架尚未解决的具体问题。
