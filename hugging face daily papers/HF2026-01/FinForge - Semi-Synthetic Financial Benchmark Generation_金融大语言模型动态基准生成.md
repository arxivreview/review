# HuggingFace最新推荐论文 ｜FinForge: Semi-Synthetic Financial Benchmark Generation ｜金融大语言模型动态基准生成

研究机构：美国佐治亚理工学院

作者：Glenn Matlin、Akhil Theerthala、Anant Gupta 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2601.06747)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2601.06747)

> 金融领域大语言模型（Large Language Models, LLMs）评估长期受困于静态题库的数据泄露与知识滞后，导致模型在真实复杂场景下的推理能力被高估。现有基准如 FinQA 仅覆盖数值推理，缺乏对概念性金融知识的深度考察，且无法随市场动态更新。FinForge 提出一种半合成基准生成框架，通过专家策展语料与 LLM 结构化推理引擎，动态构建无污染的专家级问答集。该框架填补了动态金融评估空白，但生成器能力瓶颈与评估偏差限制了其诊断深度。

## 研究背景

金融决策支持要求模型同时具备概念理解与定量计算能力，但通用基准无法反映这种双重需求。数据污染（Data Contamination）指测试数据混入训练语料，导致模型通过记忆而非推理作答，这在动态更新的金融领域尤为致命。静态基准的固定题目极易被 LLM 预训练吸收，使得评估结果失去区分度。

现有金融 QA 基准存在显著局限：FinQA 和 TAT-QA 聚焦于表格数值推理，忽视宏观经济与监管合规等概念性知识；FinanceBench 仅含 150 题，规模过小且难度不足；FinTextQA 虽涵盖教科书内容，但要求生成式长答案，难以标准化评估。这些静态数据集无法适应金融市场的快速演变，且缺乏对模型深层推理能力的压力测试。FinForge 的切入点在于构建一个可动态更新、基于权威源验证的半合成基准，通过引入因果机制推理环节，生成需要多步逻辑与领域知识结合的复杂问题，从而突破静态题库的污染与难度天花板。

## 核心方法

### 方法参照系

FinForge 属于动态基准生成范式，区别于传统的静态数据集构建。其核心差异在于将“数据策展”与“问题合成”解耦，并引入领域特定的推理引擎，而非直接改写现有题目。标准流程通常依赖人工编写或简单 LLM 改写，而 FinForge 强调从原始文本中提取因果触发器与隐含机制，确保问题的自包含性与专家级难度。

### 因果机制推理引擎

传统问题生成往往直接基于文本表面信息，导致问题缺乏深度或依赖外部上下文。FinForge 在文档分析阶段引入四要素提取：因果关系、竞争假设、必要假设与反事实可能性。这一设计解决了此前方法中问题与源材料逻辑脱节的问题。推理引擎将非结构化文本转化为结构化答案计划，其核心逻辑可形式化为：

$$
P_{plan} = f_{extract}(D, \{C_{rel}, H_{comp}, A_{req}, C_{factual}\})
$$

其中 $D$ 为源文档，$C_{rel}$ 为因果关系，$H_{comp}$ 为竞争假设，$A_{req}$ 为必要假设，$C_{factual}$ 为反事实可能性。该公式表明，问题计划并非简单摘要，而是对文档中隐含逻辑结构的显式建模，确保生成的问题必须基于这些深层机制才能解答。

### 多阶段验证与过滤

自动生成的问题常存在歧义或事实错误，直接用于评估会引入噪声。FinForge 采用五阶段工作流，其中验证阶段使用 LM-as-a-judge 对问题进行多维评估。验证函数定义为：

$$
V(q) = \prod_{i=1}^{5} I(c_i(q))
$$

其中 $c_i$ 分别为金融相关性、自包含性、逻辑一致性、清晰度与复杂度，$I(\cdot)$ 为指示函数。只有当所有维度均满足条件时，问题才被保留。这一严格过滤机制解决了此前 LLM 生成数据中常见的“看似合理实则错误”问题，但实验显示其自动化通过率与专家评估存在显著偏差，揭示了纯自动验证在复杂金融推理中的局限性。

## 实验评估

FinForge-5k 基准包含 5,000 个专家级问答对，覆盖 11 个金融子领域。实验对比了 9 个主流开源与闭源模型，包括 Qwen 3 235B、DeepSeek V3、GPT-4o 等。基线覆盖广泛，但缺乏专用金融模型（如 FinGPT）的对比，限制了与垂直领域模型的直接比较。

| 模型 | Overall Accuracy |
| :--- | :--- |
| Qwen 3 235B | 0.771 |
| DeepSeek V3 | 0.739 |
| GPT-4o | 0.734 |
| Qwen3-Next 80B | 0.732 |
| Sonnet 4 | 0.726 |
| Llama 3.3 70B | 0.725 |
| OLMo 2 7B | 0.608 |
| OLMo 2 32B | 0.567 |
| Llama 4 Scout | 0.465 |

结果显示，Qwen 3 235B 以 0.771 的准确率领先，但所有模型均未达到 80% 的阈值，表明当前 SOTA 模型在复杂金融推理上仍有显著短板。值得注意的是，中等规模模型（如 Qwen3-Next 80B）表现接近大型专有模型，暗示模型规模并非金融推理能力的唯一决定因素。

消融实验未提供详细数据，但专家评估揭示了关键设计缺陷：在 500 个样本中，专家仅认可 70% 的问题为清晰且准确，而 LM-as-a-judge 的通过率为 100%。这一 30 个百分点的差距表明，自动化验证器缺乏评估复杂金融逻辑的精细度，可能导致基准中混入歧义题目，进而影响评估结果的可靠性。

评估边界方面，FinForge 依赖 Gemini 2.5 Flash 作为生成器，存在同源污染风险，尽管已剔除 Gemini 系模型，但生成器能力上限限制了题目难度天花板。代码已开源，但缺乏对生成过程超参数的详细披露，复现性受限于 LLM 版本更新。

## 关联研究分析

从问题动机看，FinForge 与 StockBench 同属动态基准路线，但前者聚焦知识问答，后者侧重交易执行。StockBench 通过滚动窗口回测解决前视偏差，而 FinForge 通过动态生成新题规避静态题库泄露。这种差异源于任务特性：交易评估需要时序一致性，而知识评估需要内容新颖性。FinForge 未探索将交易逻辑嵌入 QA 生成，导致其无法评估模型的序贯决策能力，这是其与 StockBench 的根本分野。

从方法设计看，FinForge 与 VERAFI 在数值推理上形成对比。VERAFI 通过神经符号验证确保计算精确性，在 FinQA 上达到 94.7% 的事实正确率。然而，FinForge 的题目涵盖概念性与定量混合任务，纯 LLM 生成的题目中模型表现不佳，暗示神经符号方法在复杂概念推理中的适用性受限。FinForge 未引入符号验证器，导致其无法区分“知识缺失”与“推理错误”，这一盲区限制了其对模型能力短板的精准诊断。

## 总结

FinForge 旨在解决金融 LLM 评估中静态基准的数据污染与知识滞后矛盾，通过半合成动态生成框架，利用专家策展语料与因果机制推理引擎，构建了无污染的专家级问答集。实验表明，当前 SOTA 模型在 FinForge-5k 上准确率最高仅为 0.771，且自动化验证与专家评估存在 30% 的偏差，暴露了 LM-as-a-judge 在复杂金融推理中的局限性。该框架的边界在于生成器能力瓶颈与验证器精度不足，当生成器无法捕捉深层金融机制时，基准的难度天花板如何突破，论文未给出回答。
