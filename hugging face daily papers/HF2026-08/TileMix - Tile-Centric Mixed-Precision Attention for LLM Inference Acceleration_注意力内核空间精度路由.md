> 长上下文推理中，密集自注意力因二次方计算量成为主要瓶颈，而现有加速手段要么牺牲精度（均匀低精度），要么牺牲连接完整性（稀疏化）。TileMix 在 FlashAttention 的分块执行框架内，将数值精度从“全局静态配置”转变为“空间动态决策”，通过位掩码在单个融合内核中混合 FP16 与 INT8 算术路径。该方法在不改变模型权重、不引入训练开销的前提下，实现了精度与吞吐的可控权衡。其价值在于证明了空间粒度精度分配的有效性，但静态路由策略对注意力分布的适应性仍存疑。

## 研究背景

长序列处理中，自注意力需计算 $L \times L$ 的分数矩阵，导致显存占用与 HBM 读写流量随序列长度平方增长。FlashAttention 通过分块（Tiling）与在线 Softmax（Online Softmax）将中间结果保留在片上 SRAM，避免了完整矩阵落地，但其算术精度通常在调用时固定。低精度量化（如 INT8）能降低算术成本，但均匀量化在长上下文 QA 任务中常导致精度显著下降，因为注意力分数分布具有局部敏感性与重尾特性。

现有加速路线存在结构性割裂：量化方法在张量或算子级别分配格式，缺乏对 $L \times L$ 分数矩阵空间维度的细粒度控制；稀疏注意力通过选择 token 交互减少计算，但改变了注意力图的连接结构，可能丢失关键信息；IO 感知内核优化数据搬运，但算术路径单一。TileMix 的切入点在于利用硬件对齐的计算块（Compute Tile）作为空间单元，在保持密集连接的前提下，于内核内部动态路由不同块组的算术精度，从而在单一执行流中融合异构数值表示。

## 核心方法

### 分块注意力与在线 Softmax 基底

TileMix 继承 FlashAttention 的执行结构：将 $Q, K, V$ 划分为 $T_m \times T_n$ 个硬件对齐块，外层循环遍历查询块，内层循环流式加载键值块并更新共享的在线 Softmax 状态 $(\tilde{m}, \tilde{z}, \tilde{O})$。该基底确保了 $O(L)$ 的显存复杂度，但传统实现中每个块遵循相同的算术路径。TileMix 的关键差异在于将“算术路径选择”嵌入内层循环的控制流，而非作为全局配置。

### 位掩码编码的空间精度路由

为解决内层循环中常数时间查找路由决策的需求，TileMix 引入分组因子 $g$，将相邻 $g$ 个键块合并为一个路由组，其宽度为 $BLOCK_{mask}^N = g \cdot BLOCK_N$。路由决策被打包为 64 位整数 $b_{hk,m}$，其中第 $g_j$ 位对应键块组 $g_j$ 的算术路径：

$$
b_{hk,m} = \sum_{g_j=0}^{T_{mask}-1} R_{hk,m,g_j} 2^{g_j}, \quad R_{hk,m,g_j} \in \{0, 1\}
$$

内核通过移位与掩码操作 $R_{hk,m,g_j} = ((b_{hk,m} \gg g_j) \& 1)$ 在常数时间内提取决策。该设计动机在于：随着上下文长度增加，若每个块独立路由，元数据开销将线性增长；分组机制使得单个 64 位字可覆盖更长的键序列，同时保持硬件对齐的计算块结构不变，实现了路由元数据的 $O(H_k T_m)$ 紧凑存储。

### 异构算术路径的共享状态融合

路由决策 $R_{hk,m,g_j}=1$ 时，分数块 $S_{n,m}$ 通过 INT8 Tensor Core 计算：

$$
S_{n,m} = \text{Rescale}_{m,n}(Q_{8,m} K_{8,n}^\top) / \sqrt{d}
$$

其中 $Q_8, K_8$ 为块级量化后的 INT8 表示，$\text{Rescale}$ 应用块缩放因子恢复至浮点域；$R_{hk,m,g_j}=0$ 时，$S_{n,m} = Q_m K_n^\top / \sqrt{d}$ 通过 FP16 路径计算。两条路径在更新共享的 $\tilde{m}, \tilde{z}, \tilde{O}$ 前均进入统一的浮点域，确保在线 Softmax 的数值一致性。这一设计解决了此前量化注意力内核中“低精度块与高精度块无法在同一 Softmax 递推中正确归一化”的问题，使得混合精度计算在数学上等价于全精度注意力，仅引入可控的量化误差。

## 实验评估

实验在 NVIDIA A100 40GB 上评估 LLaMA 3.2 3B-Instruct，基线涵盖 FP16 参考、均匀 INT8（One）、FlashAttention、稀疏方法（MInference, FlexPrefill）及 INT8 内核（SageAttention）。评估覆盖 LongEval 检索、LV-Eval QA 及 Prefill 吞吐。

| 序列长度 | FlashAttn (K tok/s) | One (K tok/s) | SpTrans75 (K tok/s) | SageAttn (K tok/s) |
| :--- | :--- | :--- | :--- | :--- |
| 1k | 17.45 | 32.27 | 33.50 | 19.91 |
| 4k | 14.33 | 29.80 | 31.80 | 19.91 |
| 8k | OOM | 27.41 | 26.61 | 18.79 |

在 4k 序列下，SpTrans75 吞吐达 31.80 K tokens/s，高于 FlashAttention 的 14.33 与 One 的 29.80，表明混合精度路由在保持密集连接的同时超越了均匀 INT8 的效率上限。

| INT8 覆盖率 | 1k 偏差 | 8k 偏差 |
| :--- | :--- | :--- |
| 0% | 7.27×10⁻⁵ | 6.84×10⁻⁵ |
| 10% | 1.19×10⁻³ | 6.32×10⁻³ |
| 25% | 2.03×10⁻³ | 6.84×10⁻³ |

数值偏差分析显示，8k 序列下 5% 至 10% 覆盖率间偏差显著跃升，表明低覆盖率区间是精度控制的关键敏感区。在 LongEval 检索任务中，SpTrans 布局在 75% INT8 覆盖率下仍保持接近 FP16 的准确率，而均匀 INT8（One）在长序列下性能急剧下降，验证了空间路由对局部敏感区域的保护效果。

评估边界受限于静态路由策略：实验仅测试了预定义的布局模板（如 SpTrans, BigBird），未探索基于注意力分数实时统计的动态路由。可复现性方面，代码已开源，但 A100 特定的内核调优参数可能限制跨硬件泛化。

## 关联研究分析

从问题动机看，TileMix 与 SageAttention 同属 INT8 注意力加速，但 SageAttention 通常采用全张量或粗粒度块量化，精度损失在长上下文 QA 中难以避免；TileMix 通过空间路由将 FP16 保留在注意力分布的关键区域（如对角线或特定布局），间接规避了均匀量化导致的数值崩溃。这一差异根源在于任务特性：长上下文检索对局部 token 交互的精度敏感，而均匀量化无法区分关键与非关键区域。

从方法设计看，TileMix 与 FlashAttention 共享 IO 感知分块框架，但 FlashAttention 的算术精度是静态配置，TileMix 将其扩展为空间动态决策。与稀疏注意力（如 MInference）相比，TileMix 不改变注意力图的连接结构，仅改变算术路径，因此保留了所有合法 token 交互。这种“精度路由”而非“连接剪枝”的策略，使得 TileMix 在需要完整上下文信息的任务（如多跳推理）中更具优势，但代价是计算量未减少，仅通过低精度算术降低延迟。

## 总结

TileMix 解决了长上下文推理中密集注意力精度与效率的矛盾，其切入点在于利用硬件对齐块作为空间单元，在内核内部动态路由 FP16/INT8 算术路径。通过位掩码编码与共享状态融合，该方法在保持密集连接的前提下，实现了 4k 序列下 31.80 K tokens/s 的吞吐，显著优于 FlashAttention 的 14.33 与均匀 INT8 的 29.80。其边界在于静态路由策略依赖预定义布局，未验证动态路由对复杂注意力分布的适应性。当注意力分布呈现非结构化重尾特性时，静态模板能否持续逼近 FP16 精度，论文未给出回答。
