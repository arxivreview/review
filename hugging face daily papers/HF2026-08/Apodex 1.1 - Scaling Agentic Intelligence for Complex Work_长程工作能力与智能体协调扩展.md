# HuggingFace最新推荐论文 ｜Apodex 1.1: Scaling Agentic Intelligence for Complex Work ｜长程工作能力与智能体协调扩展

作者：Apodex Team、B. An、B. Li 等 71 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.23283)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.23283)

> 现有智能体系统常陷入“能答对但做不完”的困境，即模型具备推理能力却缺乏在动态环境中维持状态、恢复故障并交付可验证产物的长程执行能力。传统方法依赖外部静态工作流或简单多智能体对话，无法适应任务目标的实时变更与复杂依赖管理。Apodex 1.1 提出“工作能力”概念，通过环境扩展与智能体协调扩展两个维度，将分解、委派与重规划行为内化于模型策略中。该系统在专业工作流与金融任务上达到前沿水平，但其性能增益是否完全源于模型内生能力而非系统级计算开销，仍需更严格的消融验证。

## 研究背景

当智能体处理跨文件、代码与搜索源的复杂任务时，核心挑战并非单步推理错误，而是长程状态一致性缺失。任务执行涉及异构工具调用与异步反馈，若缺乏统一的状态管理，早期错误会随轨迹延长而累积，导致最终交付物不可验证。这一困境催生了“工作能力”（Working Capability）的定义：在长时程内通过工具交互、计划修订与故障恢复，满足特定交付契约的能力。其核心单元是“完成的工作”而非孤立响应，要求系统维护工作区状态、证据溯源及分支依赖关系。

领域主流路线分为外部编排与内部策略两类。外部编排方法如 DAAO 和 GPTSwarm 通过强化学习或搜索算法动态调整代理拓扑，但依赖显式的环境反馈信号，难以处理目标中途变更的实时干预。内部策略方法如 ReAct 确立了“思考-行动”循环，但缺乏对并行分支协调与状态持久化的支持。Apodex 1.1 的切入点在于将协调行为从运行时搜索前移至训练阶段，通过构建可验证的文件、搜索与代码环境，使模型在训练中学习分解、委派与重规划，从而在运行时通过 AgentOS 维持长程状态一致性。

## 核心方法

### 任务契约与环境扩展

传统智能体评估常将提示映射至答案，而本文采用任务契约 $E = (W, W_0, q, A, T, \Omega, B, D, V_D)$ 作为基本单元。其中 $W$ 为工作区状态空间，$q$ 为归一化目标，$D$ 为交付契约，$V_D$ 为任务级验证器。该定义的关键差异在于区分了初始用户输入 $u_0$ 与目标 $q$，以及将验证器 $V_D$ 与求解器可见的工具验证器分离。环境扩展并非简单增加提示数量，而是扩展可执行任务契约的分布，涵盖文件、搜索与代码三类世界。文件世界强调权威性与转换，搜索世界关注证据对齐，代码世界侧重可执行转换。这种扩展确保了训练轨迹包含真实的工具交互、状态转移与失败恢复，而非仅文本描述。

### 智能体协调扩展与任务板机制

智能体协调扩展旨在将工作组织从静态角色分配转向动态任务流。核心创新是显式任务板（Task Board），其状态更新公式为：

$$ W_{t+1} = T(W_t, a_t), \quad o_{t+1} = \Omega(W_t, a_t, W_{t+1}) $$

其中 $a_t$ 包含子代理派发、结果收集与计划修订动作。任务板存储协调器拥有的解析状态（open, in_progress, resolved, cancelled），与运行时执行状态分离。这一设计解决了传统多智能体系统中计划状态在上下文压缩中丢失的问题。当用户干预 $u_t$ 发生时，运行时将其注入工作区，若目标 $q$ 或交付契约 $D$ 未变，则仅更新相关板项并通知子代理；若目标变更，则实例化新任务契约。这种机制允许慢速或失败分支不擦除其他分支的有效工作，实现了异步结果集成与动态重规划。

### 统一训练与执行底座

训练机制将环境扩展与协调扩展转化为模型能力。统一 SFT 混合建立共同的任务执行与协调行为，而智能体强化学习（Agentic RL）优化长时程决策。AgentOS 提供持久化运行时，维护工作区、工件、溯源与分支状态。其关键机制包括稳定三区域命名空间、只读共享挂载、外部任务板定期重注入以及单发布者租约。这些机制确保了在上下文压力、预算执行与并发交付下的状态一致性。例如，单发布者租约防止并发、未声明或过时的输出文件，通过精确清单与范围写入策略保证交付完整性。

## 实验评估

实验在专业工作、金融、科学研究、通用推理与编码基准上进行，基线覆盖 GPT-5.6、Claude-Opus-5、DeepSeek-V4 等前沿模型。Apodex 1.1 在 GDPVal 上以 Agent Team 模式取得 78.8 的胜率，较 ReAct 模式的 69.5 提升 9.3 点；在 FrontierFinance 上，Agent Team 得分 54.3，较 ReAct 的 48.7 提升 5.6 点。

| 基准 | 模式 | Apodex 1.1 | 最强基线 | 基线得分 |
| :--- | :--- | :--- | :--- | :--- |
| GDPVal | Agent Team | 78.8 | Claude-Opus-5 | 89.4 |
| FrontierFinance | Agent Team | 54.3 | GPT-5.6-Sol | 46.8 |
| APEX-Agents | Agent Team | 38.5 | Kimi-K3 (max) | 41.0 |
| FrontierScience-Research | Agent Team | 63.3 | DeepSeek-V4-Flash | 55.0 |

消融分析显示，Agent Team 模式在 FrontierSearchBench 上将零分任务比例从 ReAct 的 19.5% 降至 9.8%，平均分从 57.0 提升至 69.1，超过 GPT-5.6-Sol 的 67.4。35B 参数的 Mini 模型在 FrontierFinance 上从 33.2 提升至 50.2，表明环境扩展与协调训练可弥补参数量不足。然而，SWE-bench Verified 上 Apodex 1.1 得分为 77.7，虽高于部分基线，但低于 Claude-Opus-5 的 92.2，显示在纯代码修复任务中，系统级协调的增益可能受限于模型基础能力。

评估边界方面，论文未报告置信区间，且部分基准（如 GDPVal）为内部复现，外部可比性受限。代码与权重已开源，但 AgentOS 的超参数配置未完全披露，复现需依赖官方仓库。

## 关联研究分析

从问题动机看，Apodex 1.1 与 DAAO 的核心差异在于自适应机制的实现层级。DAAO 依赖外部变分自编码器估计查询难度，动态分配算子子集，属于运行时结构优化；而 Apodex 将分解与委派行为编码进模型权重，通过训练学习何时并行、何时串行。这种内化策略牺牲了查询级别的细粒度拓扑调整灵活性，但换取了更低的运行时推理开销与更强的状态一致性。DAAO 在 GSM8K 上取得 91.21% 的准确率，而 Apodex 在 MATH 等基准上的表现未直接对比，暗示内化策略在纯数学推理任务中可能不如显式难度估计器高效。

从方法设计看，Apodex 与 GPTSwarm 均涉及多智能体协调，但 GPTSwarm 优化代理连接拓扑，属于图结构搜索；Apodex 则优化代理协作行为与状态管理，属于策略学习。GPTSwarm 的拓扑调整依赖强化学习奖励信号，而 Apodex 的任务板机制通过显式状态跟踪实现故障隔离与恢复。这种差异源于任务特性：GPTSwarm 针对固定任务集的结构优化，而 Apodex 针对开放域长程任务的动态适应。Apodex 未探索拓扑结构的显式优化，可能限制了其在高度并行化任务中的扩展性。

## 总结

Apodex 1.1 旨在解决长程任务中状态一致性与交付可验证性的矛盾，通过环境扩展与协调扩展将工作能力内化于模型策略，而非依赖外部编排器。系统在 GDPVal 上达到 78.8 的胜率，在 FrontierFinance 上取得 54.3 分，证明了训练驱动的协调行为在专业工作流中的有效性。然而，SWE-bench Verified 上 77.7 的得分低于 Claude-Opus-5 的 92.2，暴露了模型基础能力与系统协调增益之间的边界。当任务复杂度进一步增加，内化策略是否仍能维持状态一致性而不引入新的协调开销，论文未给出回答。
