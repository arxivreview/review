# HuggingFace最新推荐论文 ｜LEGO-RL: Harness-Native Reinforcement Learning for Coding Agents ｜原生智能体强化学习框架

研究机构：华为、香港中文大学

论文原文见 [arXiv](https://arxiv.org/abs/2608.17393)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.17393)

> 智能体强化学习（Agentic RL）旨在通过可执行奖励优化长程代码修复行为，但原生智能体框架（Harness）的上下文重写与沙箱故障常导致训练-推理概率失配及奖励信号污染，使策略梯度失效。现有框架要么强制改造智能体以适配训练接口，要么缺乏对执行层完整性的防护，无法在保持原生工作流的同时实现忠实优化。LEGO-RL通过在模型API边界插入进程内代理捕获原始Token流，结合沙箱级奖励反作弊与全异步调度，在不修改智能体内部逻辑的前提下实现了大规模策略优化。该框架在SWE-bench Verified上显著提升了基座模型性能，但其序列级损失在长程信用分配上的有效性仍存疑。

## 研究背景

当智能体在代码仓库中执行多轮工具调用时，其生成的轨迹长度与复杂度远超单步推理任务。策略梯度优化要求训练器能精确重算Rollout时的对数概率，然而原生智能体框架（如Claude Code、OpenHands）会在轮次间进行上下文压缩、历史重写或重新序列化，导致训练器基于最终轨迹重建的Token序列与原始采样序列不一致。这种失配在稀疏混合专家（MoE）模型中尤为严重，因为Rollout时的专家路由决策若未在训练时重放，将直接破坏概率计算的忠实性。

智能体RL基础设施的主流路线分为两类：一类将Rollout纳入训练框架内部控制，如verl、slime，要求智能体适配框架定义的交互抽象，牺牲了原生工作流的完整性；另一类在模型API层观察交互，如Polar、rLLM，保留了智能体原生性，但缺乏对沙箱执行可靠性与奖励完整性的系统防护。前者难以支持未经改造的商业智能体，后者则面临环境崩溃、奖励黑客（Reward Hacking）及异步训练中策略陈旧性导致的信号污染问题。LEGO-RL的切入点在于，将“忠实优化”、“可靠执行”与“可观测训练”解耦为三个独立支柱，通过进程内代理解决概率重算失真，通过沙箱编排解决执行噪声，从而在不侵入智能体内部逻辑的前提下，实现大规模、高保真的策略优化。

## 核心方法

### 方法参照系

本文问题属于智能体RL基础设施构建，与通用策略梯度训练流程的关键差异在于：优化目标并非孤立响应，而是由原生智能体控制流诱导的完整轨迹行为。标准GRPO/GSPO假设训练器能访问精确的上下文与Token掩码，而原生Harness的上下文管理策略使得这一假设失效，需引入边界捕获机制。

### 进程内代理与路由重放

在模型服务边界插入进程内代理（In-Process Proxy），直接捕获Token ID、对数概率、响应掩码及MoE路由决策，而非从最终轨迹重建。设计动机是解决Harness侧历史重写导致的训练-推理概率失配。对于MoE模型，通过R3机制在训练时重放Rollout时的专家路由，确保概率计算遵循相同的路径。该机制使Rollout与训练的对数概率Pearson相关系数保持在0.998以上，p99差异低于$3 \times 10^{-3}$。

$$
\mathcal{L}_{GSPO}(\theta) = \mathbb{E} \left[ \sum_{i=1}^{G} w(\tau_i) \min \left( \sigma_i(\theta) \hat{A}_i, \text{clip}(\sigma_i(\theta), 1-\epsilon_{low}, 1+\epsilon_{high}) \hat{A}_i \right) \right]
$$

其中 $\sigma_i(\theta) = \left( \frac{\pi_\theta(\tau_i)}{\pi_{\theta_{k'}}(\tau_i)} \right)^{1/|M(\tau_i)|}$ 为序列级重要性比率，$w(\tau_i)$ 为轨迹有效性掩码。该损失函数通过序列级比率稳定长程优化，非对称裁剪边界允许更多上行探索。

### 沙箱编排与奖励完整性

在沙箱层实施阶段化防御，包括网络隔离、仓库历史隐藏及测试依赖预打包，以防止智能体通过捷径获取评分信息或环境故障污染奖励。设计动机是解决可执行验证中“正奖励不等于真实完成”的问题。通过Nydus懒加载镜像与异步调度，将环境准备与策略执行解耦，避免长尾轨迹阻塞同步批次。该机制确保仅有效轨迹参与优化，执行失败轨迹被掩码处理，防止噪声信号干扰组相对优势估计。

## 实验评估

实验在SWE-bench Verified上进行，使用Qwen3.5-35B-A3B模型，对比基线包括Qwen3.6-35B-A3B（新一代基座）与KAT-Coder-V2.5-Dev（SFT+RL后训练模型）。基线覆盖不足，未对比slime、MOLT等同类智能体RL框架，仅验证了LEGO-RL相对于基座模型的增益。

| 智能体框架 | 基座模型 (%) | LEGO-RL (%) | 增益 (pp) |
| :--- | :--- | :--- | :--- |
| OpenHands SDK | 64.0 | 70.4 | +6.4 |
| Claude Code | 62.4 | 68.2 | +5.8 |
| OpenCode | 57.2 | 66.6 | +9.4 |

LEGO-RL在三个框架上均显著优于基座，且增益幅度大于新一代基座（Qwen3.6）相对于Qwen3.5的提升（3.0-6.0 pp），表明框架优化本身具有独立价值。然而，与领域SOTA（如GVPO 84.2%）相比，绝对值仍较低，可能源于骨干模型差异或Harness原生性带来的优化损失。

消融实验显示，MoE路由重放将Rollout-训练相关性从0.9946提升至0.9993，平均Token对数概率差异从0.0062降至0.0025，证实了路由一致性对忠实优化的关键作用。轨迹终止分析表明，超时与环境设置失败占比约7%-10%，通过异步调度与阶段化超时，这些故障被有效隔离，未污染训练信号。

评估边界方面，论文未报告置信区间，且仅在单一骨干模型上验证，跨模型泛化性未知。代码与模型已开源，但沙箱环境配置复杂，复现成本较高。评估协议固定为温度0.7、200轮、200k上下文，未探索不同超参数对收敛性的影响。

## 关联研究分析

从问题动机看，LEGO-RL与slime、MOLT等框架的核心差异在于对“智能体原生性”的处理。slime等框架要求智能体适配其交互抽象，本质上是“框架适配智能体”；而LEGO-RL通过进程内代理在API层捕获原始Token，实现了“智能体适配框架”的反向兼容。这一差异的根源在于任务特性：商业智能体（如Claude Code）的内部逻辑封闭且复杂，强制改造成本高且易引入行为偏差，而API层捕获虽增加了代理开销，但保留了智能体的完整决策能力。

从方法设计看，LEGO-RL与Polar、rLLM等API观察型框架相比，增加了沙箱级奖励完整性防御与全异步调度。Polar等框架主要关注概率重算，但缺乏对执行层噪声的系统防护，导致奖励信号可能因环境故障而失真。LEGO-RL将“可靠执行”作为独立支柱，通过阶段化超时与奖励反作弊，解决了API观察型框架在大规模训练中的稳定性瓶颈。然而，LEGO-RL采用序列级GSPO损失，未引入步骤级信用分配，这与领域共识中“步骤级优于轨迹级”的观点相悖。在长程智能体任务中，序列级损失是否足以捕捉关键决策点的贡献，论文未给出明确回答。

## 总结

LEGO-RL要解决的核心矛盾是原生智能体框架的封闭性与策略梯度优化对精确概率重算需求之间的冲突。现有方法要么牺牲智能体原生性，要么缺乏执行层防护，而LEGO-RL凭借进程内代理捕获原始Token流与沙箱级奖励完整性防御，在不修改智能体内部逻辑的前提下实现了忠实优化。实验证明，该框架在SWE-bench Verified上将Qwen3.5-35B-A3B的性能从64.0%提升至70.4%（OpenHands SDK），且Rollout-训练概率相关性保持在0.998以上。其边界在于，序列级损失在长程任务中的信用分配粒度可能不足，且仅在单一骨干模型上验证。当智能体轨迹长度进一步增加时，序列级GSPO是否仍能稳定捕捉关键决策点的梯度信号，论文未给出回答。
