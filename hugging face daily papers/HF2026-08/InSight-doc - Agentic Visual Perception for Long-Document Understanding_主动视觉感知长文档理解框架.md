> 长文档理解面临高分辨率全页输入导致的计算开销与上下文腐烂问题，现有端到端或检索增强方法在精度与效率间难以兼顾。InSight-doc 将视觉分辨率视为自适应推理资源，通过无检索器的区域级裁剪与多轮交互实现粗到细的证据获取。该方法结合 SFT 与 RL 训练，在 8B 骨干上显著提升了长文档问答的准确率并降低了幻觉率。其价值在于验证了主动感知范式的有效性，但缺乏过程级奖励设计，对复杂多跳推理的泛化能力存疑。

## 研究背景

多模态大语言模型（MLLM）处理长文档时，高分辨率全页输入产生海量视觉 Token，导致注意力机制在长序列下发生稀释，引发上下文腐烂（Context Rot）。这种性能退化不仅源于计算复杂度的二次方增长，更因为无关页面信息干扰了关键证据的定位。为解决此问题，粗到细（Coarse-to-Fine）策略应运而生，其核心逻辑是先以低分辨率扫描全文定位相关区域，再对局部进行高分辨率解析，从而在 Token 预算约束下平衡信息保真度与计算成本。

现有粗到细方法主要依赖外部检索器或固定脚本，存在两大瓶颈：一是检索器引入的索引误差与额外延迟，二是页面级粒度无法支持子页面内的精细定位。InSight-doc 的切入点在于摒弃外部检索器，将视觉搜索内化为模型的多轮推理能力。它允许模型在思维链（Chain-of-Thought, CoT）中自主决定何时、何地放大，通过区域级裁剪（Region Cropping）实现比页面级检索更细粒度的证据获取，从而在统一框架内解决长文档理解中的定位与推理难题。

## 核心方法

### 方法参照系

本文问题属于多模态长文档视觉问答（VQA）中的主动感知任务。与传统的端到端 MLLM 直接处理全分辨率图像，或依赖外部检索器（RAG）选取页面不同，InSight-doc 采用 ReAct 框架，将图像裁剪工具调用嵌入推理循环，实现模型自主的视觉证据动态获取。

### 自适应视觉上下文空间构建

设计动机在于解决固定分辨率输入导致的上下文压力与信息丢失矛盾。传统方法将文档所有页面以固定分辨率输入，导致无关内容占据大量 Token 预算。InSight-doc 初始化低分辨率视觉上下文空间 $I^{(0)}_{ctx}$，模型在每一步 $t$ 通过工具调用 $zoom\_in(k, d, b | I^{(t-1)}_{ctx})$ 指定目标图像索引 $k$、区域描述 $d$ 及边界框 $b$。裁剪后的高分辨率区域 $\tilde{I}^{(t)}_{crop}$ 被追加至上下文空间：

$$I^{(t)}_{ctx} = I^{(t-1)}_{ctx} \cup \{\tilde{I}^{(t)}_{crop}\}$$

这一机制允许模型在推理过程中动态扩展视觉证据，避免一次性加载全量高分辨率图像，从而将注意力聚焦于关键区域。

### 推理成本理论界与轨迹生成

设计动机在于量化多轮交互引入的额外开销，并构建高质量训练数据。论文推导了相对序列长度与延迟的上界，证明在特定参数下，InSight-doc 的序列长度可降至基线的 7.8% 至 45.0%。对于轨迹生成，采用 InSight-o3 双智能体架构：vReasoner 生成结构化区域请求 $\langle PageID_i: Desc_i \rangle$，vSearcher 定位边界框 $\langle Box_i \rangle$。最终将双智能体轨迹合并为单模型的多模态 CoT 序列，使模型内化“何时放大、放大哪里、如何整合证据”的能力，替代外部检索器的误差累积。

## 实验评估

实验在 DUDE、MP-DocVQA、MMLongBench-Doc 和 LongDocURL 四个基准上进行，对比基线包括 Qwen3-VL-8B（端到端）、Doc-V*（检索增强）及 GPT 系列闭源模型。InSight-doc-8B (SFT+RL) 在低分辨率（r=0.25）下平均准确率达 66.9%，较基线提升 16.4 点；在 MMLongBench-Doc 上达 57.8%，超越 Doc-V* 的 42.1% 达 15.7 点。

| 方法 | MMLongBench-Doc | LongDocURL | 平均准确率 (r=0.25) |
| :--- | :--- | :--- | :--- |
| Qwen3-VL-8B | 44.5 | 48.5 | 50.5 |
| Doc-V* | 42.1 | 56.3 | - |
| InSight-doc-8B (SFT+RL) | 57.8 | 65.6 | 66.9 |

消融实验显示，SFT 阶段将证据框覆盖率从 27.5% 提升至 68.1%，而 RL 阶段进一步将覆盖率提升至 82.3%，并将冗余轨迹率从 14.1% 降至 5.8%。这表明 RL 不仅优化了定位精度，还显著改善了轨迹稳定性，减少了无效工具调用。

评估边界方面，论文使用 GPT-5-nano 作为裁判模型，但未报告置信区间。实验仅基于 8B 骨干，未验证更大规模模型的效果。代码已开源，但 RL 训练的具体超参数与奖励函数细节在正文中披露有限，复现难度中等。

## 关联研究分析

从方法设计看，InSight-doc 与 Doc-V* 的核心差异在于检索机制。Doc-V* 依赖外部检索器获取页面，存在索引误差与额外延迟；InSight-doc 通过模型自主裁剪实现无检索器设计，避免了检索侧的误差累积，但要求模型具备更强的空间定位能力。这种差异源于任务特性：长文档中证据往往分散于非相邻页面，外部检索器难以捕捉跨页面的细微视觉线索，而模型内化的主动感知能更灵活地处理这种非结构化分布。

从问题动机看，InSight-doc 与文本长上下文中的递归语言模型（RLM）存在同构性，但处理对象不同。RLM 通过递归调用处理文本子任务，InSight-doc 通过多轮裁剪处理视觉子区域。两者都试图突破固定窗口限制，但 InSight-doc 的奖励仅基于最终答案正确性，缺乏过程级监督。相比之下，文本领域的 RLVR 强调可验证奖励与过程优化，InSight-doc 未采用类似机制，这可能限制其在复杂多跳视觉推理中的泛化能力。

## 总结

InSight-doc 旨在解决长文档理解中高分辨率输入导致的计算开销与上下文腐烂矛盾。其切入点是将视觉分辨率作为自适应资源，通过无检索器的区域级裁剪实现主动感知，从而在 Token 预算约束下平衡精度与效率。实验证明，该方法在 8B 骨干上使 MMLongBench-Doc 准确率从 42.1% 提升至 57.8%，并将幻觉率降低超过 40%。然而，论文仅使用结果奖励进行 RL 训练，未显式优化中间步骤的正确性，且实验局限于 8B 模型。当文档证据极度分散且需要多跳视觉推理时，缺乏过程级监督的模型是否仍能保持稳定的定位与整合能力，论文未给出回答。
