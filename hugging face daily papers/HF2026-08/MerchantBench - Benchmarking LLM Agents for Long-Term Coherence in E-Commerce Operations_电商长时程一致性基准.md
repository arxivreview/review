研究机构：阿里巴巴集团、浙江大学

作者：Qiming Shi、Yulong Tao、Linbo Jin 等 13 人

论文原文见 [arXiv](https://arxiv.org/abs/2607.28956)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2607.28956)

> 导读 智能体评估长期聚焦于有明确终点和即时反馈的封闭任务，导致模型在需要持续决策、应对延迟反馈的真实商业场景中表现被严重高估。现有长时程基准如 Vending-Bench 和 RetailBench 虽涉及持续运营，但缺乏基于真实数据的非平稳需求动态与订单级延迟反馈机制，无法有效检验智能体在长周期内的策略维持与修正能力。MerchantBench 通过构建基于 98,843 条真实电商记录的 365 天部分可观测马尔可夫决策过程（POMDP）环境，引入混合延迟反馈机制，量化了智能体在长期运营中的“长期一致性”缺陷。该基准揭示了当前大语言模型在长时程任务中普遍存在运营衰减与战略漂移，但受限于单一垂直领域，其结论向通用智能体能力的泛化性仍存疑。

## 研究背景

当智能体执行多步任务时，早期动作会约束后续选项，且关键后果往往在多个中间决策后才显现。这种时间不对称性要求智能体不仅完成即时目标，还需在状态持续变化的环境中维持策略一致性。然而，传统评估仅关注最终输出正确性，无法捕捉中间步骤的错误累积、冗余操作或策略漂移，导致实验室分数严重高估实际部署性能。

主流长时程评估路线试图通过扩展任务时长来模拟真实场景，但存在两个关键瓶颈。一是环境静态性，如 RetailBench 使用固定目录，无法反映真实市场中商品机会集的动态变化；二是反馈即时性，多数基准假设动作后果立即可见，忽略了真实业务中上游供应商事件与下游订单结果在时间上的解耦。这种设计缺陷使得智能体无需进行因果归因或策略修正即可通过评估，掩盖了其在长时程决策中的核心缺陷。

MerchantBench 的切入点在于将电商运营建模为部分可观测决策问题，通过真实数据驱动的非平稳需求轨迹和订单级生命周期模拟，强制智能体在延迟证据积累过程中关联早期决策与后期结果。该设计直接针对“长时程任务中的状态漂移与记忆失效”这一核心问题，要求智能体在 365 天运营中持续调整产品组合、定价策略和现金流管理，从而暴露其在长期一致性上的能力边界。

## 核心方法

### 方法参照系

本文问题属于领域特定基准构建路线，但与传统单任务成功率评估不同，其核心差异在于将评估对象从“任务完成”扩展为“持续运营策略的一致性”。通用流程通常定义固定任务集并计算最终状态满足率，而本文采用 POMDP 框架，引入混合延迟反馈机制，使评估指标从单一准确率扩展为包含业务绩效、店铺可靠性和长时程活动度的多维体系。

### 订单级延迟反馈模拟

在参照系的即时反馈假设下，智能体无需处理时间不对称性。MerchantBench 通过下游订单模拟引擎，将产品级日需求转化为个体订单，每个订单经历“下单-采购-发货-交付-结算”的生命周期。关键创新在于引入混合延迟反馈：上游供应商事件（如价格变动、下架、延迟）即时可观测，而下游订单结果（如取消、退款、差评）仅在生命周期特定阶段显现。订单到达强度由公式 $\lambda_{m,i,t} = D_{i,d(t)} w_{c(i),h(t)} r_{m,t} \ell_{m,i,t} (p_{m,i,t}/p_{ref}^i)^{-\epsilon_i}$ 决定，其中 $r_{m,t}$ 为店铺评分，$\ell_{m,i,t}$ 为列表曝光因子。该设计迫使智能体在延迟证据积累过程中，将后期结果归因于早期决策，并据此修正当前策略，解决了静态基准无法检验因果归因能力的问题。

### 非平稳需求与部分可观测性

在参照系的静态环境假设下，智能体无需适应市场变化。MerchantBench 基于 1688 平台 365 天真实数据，构建包含 98,843 个产品、36,576 个供应商的目录，需求轨迹呈现 618、11.11 等季节性峰值及春节低谷。环境采用部分可观测设计，智能体仅能访问公开产品属性和已实现运营证据，而需求分布、风险参数、未来事件时间等保持潜在状态。终端目标定义为 $J(\pi) = \mathbb{E}_\pi[R(s_T)]$，其中 $R(s_T) = B_T + D_T + I_T + Q_T$ 分别为现金余额、保证金、在途资金和应收账款。该设计通过非平稳机会集和部分可观测性，强制智能体在长周期中持续识别新机会、修正失效策略，并管理现金流约束，解决了静态基准高估智能体适应性的问题。

## 实验评估

实验设置采用 8 个大语言模型（GPT-5.6 Sol、Claude Opus 4.8、Qwen3.7-Max 等）在 ReAct 和 Hermes 两种框架下各运行 3 次，共 48 次 365 天模拟。基线覆盖审计显示，对比方法仅包含规则基线和人类参与者，缺失 Plan-and-Execute 等特定规划框架及 AgentCompass 等统一基础设施基线，限制了框架效应的解耦分析。

核心数字对比显示，最佳 LLM 配置（Qwen3.7-Max+Hermes）最终净资产仅为人类基线的 27.3%，且 SWR 从人类的 100% 降至 22.2%，表明智能体在长时程中普遍存在运营衰减。

消融分析聚焦框架效应：Hermes 平均比 ReAct 产生 53.3% 更高的最终净资产和 71.5% 更高的 GMV，但 Qwen3.7-Max 在 Hermes 下的变异系数达 55.1%，远高于 GPT-5.6 Sol 在 ReAct 下的 3.3%，揭示框架收益对底层模型的强依赖性。反直觉发现是 Kimi K2.6 在 Hermes 下净资产比 ReAct 低 4.1%，表明框架优势并非普适，而是与模型特定能力耦合。

评估边界方面，指标体系包含业务绩效、店铺可靠性和长时程活动度，但缺乏计算效率维度（如 Token 消耗、延迟）。评估协议局限在于仅覆盖单一垂直领域（电商），且人类基线仅 3 人，样本量小。可复现性方面，代码已开源，但环境依赖 1688 真实数据，超参数和 GPU 配置未在正文中详细报告。

## 关联研究分析

从问题动机看，MerchantBench 与 Vending-Bench 和 RetailBench 同属长时程商业运营评估，但核心差异在于反馈机制。Vending-Bench 和 RetailBench 假设动作后果即时可见，智能体无需处理时间不对称性；而 MerchantBench 引入订单级延迟反馈，强制智能体进行因果归因和策略修正。这一差异源于任务特性：电商订单生命周期天然包含采购、物流、售后等多阶段延迟，而自动售货机或超市管理可简化为即时库存调整。论文未探索的是，当延迟反馈被简化为即时反馈时，智能体性能是否显著提升，这将直接验证延迟机制对长期一致性的贡献度。

从方法设计看，MerchantBench 与 AgentCompass 等统一基础设施路线存在根本差异。AgentCompass 旨在通过模块化组件解决评估碎片化，强调跨基准可比性；而 MerchantBench 聚焦垂直领域高保真模拟，牺牲通用性换取业务逻辑定制。这种取舍源于任务复杂度：电商运营涉及产品组合、定价、现金流、信誉等多维耦合，难以通过标准化接口抽象。论文未回答的是，MerchantBench 的 POMDP 建模是否导致评估复杂度远超通用基准，限制其在统一基础设施中的集成可能性，以及其指标体系能否被 AgentCompass 等框架直接解析和聚合。

## 总结

MerchantBench 要解决的核心矛盾是静态基准无法检验智能体在长时程、非平稳环境中的策略维持与修正能力。其切入点在于利用真实电商数据的非平稳需求轨迹和订单级延迟反馈机制，构建部分可观测决策环境，强制智能体在延迟证据积累过程中进行因果归因和策略修正。该基准通过 365 天模拟揭示了当前 LLM 智能体的两大缺陷：运营衰减（SWR 从 100% 降至 22.2%）和战略漂移（最佳配置净资产仅为人类的 27.3%）。其边界在于单一垂直领域和有限的人类基线样本，且未解耦框架效应与模型能力。当延迟反馈机制被移除或简化为即时反馈时，智能体在长期一致性上的性能差距是否显著缩小，论文未给出回答。
