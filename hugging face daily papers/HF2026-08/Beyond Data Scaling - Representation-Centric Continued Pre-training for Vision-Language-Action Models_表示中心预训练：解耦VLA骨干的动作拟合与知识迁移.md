论文原文见 [arXiv](https://arxiv.org/abs/2608.27550)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.27550)

> 视觉-语言-动作（Vision-Language-Action, VLA）模型旨在将自然语言指令映射为机器人连续控制信号，其核心瓶颈在于机器人轨迹数据的物理稀缺性与跨本体异构性。现有主流路线依赖扩大数据规模或优化动作头结构，但往往导致骨干网络过拟合于特定动作解码器，丧失通用视觉-语言先验。VLAct 提出“表示中心”的持续预训练配方，通过浅层冻结、多头连续动作共监督及统一动作空间，在固定数据预算下最大化骨干的迁移性。该方法在有限算力下实现了超越大规模工业系统的鲁棒性表现，但其对辅助数据混合比例的敏感性及长时程记忆任务的短板仍存疑。

## 研究背景

VLA 模型的泛化能力受限于机器人轨迹数据的物理采集成本与分布稀疏性。与互联网规模的图文数据不同，机器人数据需通过遥操作或仿真生成，难以覆盖物理交互空间的组合爆炸。在此约束下，预训练阶段的核心矛盾并非单纯的数据量不足，而是如何从有限轨迹中蒸馏出可迁移的视觉-动作知识。若骨干网络在预训练中过度拟合特定动作头的解码几何，其表征将丧失对新任务、新本体或新动作头的适应能力，导致下游微调效率低下。

当前 VLA 预训练主流路线存在两种典型失效模式：一是全参数更新导致 VLM 骨干的通用视觉-语言特征被机器人特定场景侵蚀；二是单一动作头（如离散 Token 或特定流匹配头）的监督信号使骨干表征“锁定”于该头的参数化空间，无法兼容其他动作生成机制。π0 等系统虽引入了流匹配机制提升控制精度，但其预训练过程仍隐含对特定动作头的依赖。VLAct 的切入点在于将 VLM 骨干视为一等设计变量，而非固定组件，通过解耦动作拟合与表示学习，构建对下游动作头无关的通用骨干。

## 核心方法

### 方法参照系

VLA 持续预训练通常遵循“VLM 骨干 + 动作头”的双系统架构，通过大规模机器人轨迹微调骨干以适配动作预测。本文问题与该通用流程的关键差异在于：不追求动作预测精度的最大化，而是优化骨干表征的通用性与跨头兼容性，要求骨干在预训练后能支持任意下游动作头的快速适配。

### 浅层保护与 VLM 先验锚定

针对全参数更新导致的 VLM 特征侵蚀，VLAct 在预训练阶段冻结视觉编码器与 LLM 下半层，仅更新上半层 LLM 与动作头。这一设计动机在于保护低层视觉处理与早期视觉-语言对齐特征，同时允许高层适应动作条件推理。为防止骨干在狭窄的机器人轨迹分布上过拟合，VLAct 引入辅助数据混合训练，将图像描述（Caption）、定位（Grounding）及空间推理数据混入预训练流。辅助数据作为表示锚点，维持可训练层在原始 VLM 工作域内的特征更新，其混合比例需平衡动作监督信号与语义保持信号，避免单一源数据主导表征漂移。

### 多头共监督与统一动作空间

单一动作头监督导致骨干表征过特化，VLAct 采用多头连续动作共监督策略，同时使用 OFT（回归）、PI（流匹配）与 GR00T（扩散风格）三种动作头进行预训练。这种多解码器约束迫使骨干暴露出可被多种动作参数化读取的通用动作信息，避免“解码器锁定”。为解决跨本体动作空间异构性，VLAct 定义 20 维统一动作布局，将 Franka 的增量末端执行器动作与 AgileX 的绝对关节角映射至共享坐标空间。对于周期性关节，引入包裹感知损失（Wrap-Aware Loss），通过角度包裹操作 $\theta_{wrap} = ((\theta + \pi) \mod 2\pi) - \pi$ 消除角度等价性歧义，确保不同本体在共享空间中的动作目标一致性。

$$
\mathcal{L}_{wrap} = \left\| \text{wrap}(\hat{a}) - \text{wrap}(a) \right\|_2^2
$$

该损失函数通过角度包裹操作处理周期性关节的边界效应，避免传统欧氏距离在 $-\pi$ 与 $\pi$ 边界处的巨大误差，从而提升跨本体动作表征的几何一致性。

## 实验评估

实验在 LIBERO-Plus、RoboTwin 2.0、VLA-Arena 及真实世界 Franka/AgileX 平台上进行，基线覆盖 π0、GR00T、OpenVLA 及工业系统 ABot-M0。VLAct 在固定骨干与下游协议下，仅改变预训练配方，验证了表示优化的独立贡献。

| 基准 | 方法 | 成功率 (%) |
| :--- | :--- | :--- |
| LIBERO-Plus | VLAct | 82.6 |
| LIBERO-Plus | Qwen3VL-OFT | 61.7 |
| RoboTwin 2.0 (Clean) | VLAct OFT | 80.5 |
| RoboTwin 2.0 (Clean) | Qwen3VL-OFT | 61.7 |
| VLA-Arena | VLAct | 54.8 |
| VLA-Arena | π0.5 | 44.3 |

VLAct 在 LIBERO-Plus 上较同骨干基线提升 20.9 个百分点，在 RoboTwin 2.0 Clean 设置下提升 18.8 个百分点，证明表示中心预训练在鲁棒性任务上的显著优势。

消融实验显示，浅层保护机制贡献了 3.7 个百分点的增益，而多头共监督中，增加 GR00T 头使 PI 头微调性能从 55.1 提升至 63.1，验证了多解码器对表征通用性的提升。统一动作空间与包裹感知损失在 RoboTwin 上带来 5.0 个百分点的增益，其中包裹损失单独贡献 1.9 个百分点。

评估边界方面，VLAct 在 RoboDojo 的 Memory 任务上得分仅为 2.37，显著低于其他维度，暴露了长时程记忆能力的短板。实验使用 16 GPU 与开源数据，代码已开源，但辅助数据混合比例未提供完整消融，且未报告计算效率指标，限制了其在资源受限场景下的部署评估。

## 关联研究分析

从问题动机看，VLAct 与 Xiaomi-Robotics-1 形成鲜明对比。后者依赖超大规模真实轨迹（10 万小时）验证数据规模定律，而 VLAct 在固定数据预算下通过表示优化实现超越。这一差异根源在于任务特性：Xiaomi-Robotics-1 追求绝对性能上限，适合算力充足场景；VLAct 则针对数据稀缺与跨本体迁移需求，其“表示中心”视角是对数据规模路线的补充而非替代。VLAct 在 RoboCasa-GR1 上以 20% 数据超越全量 GR00T-N1.6，暗示在数据有限时，表示质量比数据数量更具边际收益。

从方法设计看，VLAct 与 π0 的流匹配机制存在路线分歧。π0 将流匹配作为动作头核心，强调控制平滑性；VLAct 则将流匹配（PI/GR00T）作为多头监督之一，强调骨干表征的通用性。VLAct 发现单头流匹配监督会导致骨干过特化，而多头共监督能解耦这一效应。这一差异源于设计目标：π0 优化单一部署场景的控制精度，VLAct 优化跨场景、跨头的迁移效率。VLAct 未探索流匹配头在长时程任务中的时序一致性优势，其 Memory 任务短板可能与此相关。

## 总结

VLAct 针对 VLA 预训练中骨干过拟合特定动作头与 VLM 特征侵蚀的矛盾，提出表示中心预训练配方，通过浅层保护、多头共监督及统一动作空间，在固定数据预算下最大化骨干迁移性。实验证明其在 LIBERO-Plus 与 RoboTwin 2.0 上较同骨干基线提升 20.9 与 18.8 个百分点，验证了表示优化的独立价值。然而，其在 RoboDojo Memory 任务上的低分（2.37）暴露了长时程记忆能力的局限，且辅助数据混合比例的敏感性未充分消融。当机器人数据规模无限扩展时，表示优化的边际收益是否递减，论文未给出回答。
