# HuggingFace最新推荐论文 ｜ABSeeker: Training Long-Horizon Search Agents via Answer-Backtracked Credit Assignment ｜答案回溯信用分配

研究机构：上海交通大学

作者：Yijun Lu、Rui Ye、Jiajun Wang 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.05102)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.05102)

> 长程搜索智能体在训练时面临信用分配难题，现有方法将轨迹内所有步骤视为同等贡献，无法区分关键决策与冗余步骤。本文利用搜索任务“答案可回溯”的特性，从验证答案反向恢复中间证据线索，将稀疏的结果奖励转化为密集的步骤级监督信号。通过线索锚定步骤评分，ABC框架在SFT和RL中实现细粒度优化。该方法在4B模型上显著提升了长程搜索性能，但其对验证答案的强依赖限制了在无标准答案场景下的泛化能力。

## 研究背景

当智能体执行多步网络搜索时，其决策过程表现为一系列推理、工具调用与观察的循环，这一交互模式由ReAct范式确立。然而，在长程任务中，智能体往往需要执行数十轮检索与浏览，期间可能包含大量噪声信息或错误推理。若仅依据最终答案是否正确来评估整条轨迹，成功轨迹中的错误步骤会被错误地强化，而失败轨迹中有效的探索行为则被忽视，这种轨迹级监督的稀疏性导致模型难以学习精细的搜索策略。

长程搜索智能体的训练瓶颈在于信用分配（Credit Assignment）的粒度不足。主流方法如Search-R1采用端到端强化学习，但依赖稀疏的结果奖励，无法区分轨迹内不同步骤的贡献。近期研究如IGPO尝试基于模型似然增加分配信用，但信用随策略更新波动；CSO通过替代动作测试识别关键步骤，但仅对关键决策提供监督，其余步骤缺乏指导。这些方法均未能提供覆盖全轨迹的密集且稳定的过程监督信号。

本文的切入点在于利用搜索任务的固有特性：一旦获得验证答案，任务便具有可回溯性。通过从答案反向恢复中间证据线索，可以构建固定的评估锚点，从而对轨迹中的每一步进行独立评分。这种基于答案回溯的信用分配机制，将轨迹级的二元结果转化为步骤级的密集奖励，解决了长程训练中关键决策与冗余步骤无法区分的问题。

## 核心方法

### 方法参照系

本文问题置于智能体强化学习路线下，标准流程为基于ReAct框架生成轨迹，并使用轨迹级稀疏奖励进行SFT或RL优化。本文的关键差异在于引入了前置的“答案回溯线索恢复”阶段，将稀疏的结果奖励替换为基于中间证据线索的密集步骤奖励，从而改变策略优化的信号来源。

### 答案回溯线索恢复

传统方法直接基于最终答案进行奖励计算，忽略了中间证据的验证过程。本文提出答案回溯线索恢复（Answer-Backtracked Clue Recovery），利用验证答案 $a^*$ 反向搜索，恢复一组中间证据线索 $\mathcal{C} = \{c_1, c_2, \dots, c_K\}$。这一过程本身是一个主动的ReAct循环，恢复模型通过相同的工具调用协议从答案向查询反向追踪，确保每条线索 $c_k$ 都锚定在真实网页内容上。设计动机在于，验证答案仅指定终点，无法指导路径，而恢复的线索集定义了通往答案的有意义进展，为步骤评分提供了固定的参考基准。

### 线索锚定步骤评分

基于恢复的线索集，本文提出线索锚定步骤评分（Clue-Anchored Step Scoring），对轨迹中的每一步 $s_t$ 进行独立评估。评分器接收当前步骤、原始查询 $q$ 和完整线索集 $\mathcal{C}$，输出步骤奖励 $r_t$。每步初始基础分为1.0，根据步骤行为对线索的影响进行增量调整，最终分数裁剪至 $[0, 2.0]$ 区间：

$$
r_t = \text{clip}\left(1.0 + \sum_{j \in A_t} \Delta_j, 0, 2.0\right)
$$

其中 $A_t$ 为步骤 $t$ 中检测到的评分行为实例集合，$\Delta_j$ 为对应行为的增量。设计动机在于，该机制将稀疏的二元结果监督转化为密集的轮次级奖励，使失败轨迹中的有效步骤获得正信用，成功轨迹中的错误步骤受到惩罚，从而实现细粒度的过程监督。

## 实验评估

实验在BrowseComp、BrowseComp-ZH、GAIA-text及xbench-2505/2510上进行，基线覆盖同规模4B模型（QUEST-4B, Dr. Venus）及更大规模30B模型（Tongyi DeepResearch, OpenSeeker）。

| 基准 | 方法 | 分数 |
| :--- | :--- | :--- |
| BrowseComp | ABSeeker | 37.3% |
| BrowseComp-ZH | ABSeeker | 39.1% |
| GAIA-text | ABSeeker | 81.6% |
| xbench-2505 | ABSeeker | 77.0% |
| xbench-2510 | ABSeeker | 46.0% |

ABSeeker在BrowseComp上取得37.3%，在BrowseComp-ZH上取得39.1%，显著优于同规模4B基线，并与30B模型性能相当。启用上下文管理后，BrowseComp分数提升至55.3%，BrowseComp-ZH提升至52.9%。GAIA-text分数81.6%远高于领域综述中记录的Fathom-DeepResearch的45.47%，这一巨大差异可能源于子集定义或评估协议的不同，需进一步确认。

消融实验未提供具体数值表格，但设计决策验证表明，线索锚定步骤评分相比轨迹级监督能更有效地区分步骤质量。上下文管理带来的性能提升（BrowseComp从37.3%至55.3%）表明，长程记忆管理对搜索智能体性能有显著影响，但本文未深入探讨记忆机制的具体贡献。

评估边界方面，本文方法强依赖验证答案的存在，这在无标准答案的开放式任务中可能受限。代码与模型已开源，但超参数与GPU资源未详细报告，可复现性需依赖开源实现。GAIA-text分数与领域共识数据的巨大差异提示评估协议可能存在不一致，跨基准比较需谨慎。

## 关联研究分析

从问题动机看，本文与IGPO和CSO均针对信用分配粒度不足的问题，但解决路径不同。IGPO基于模型似然增加分配信用，信用随策略更新波动，缺乏稳定性；CSO通过替代动作测试识别关键步骤，但仅对关键决策提供监督，其余步骤缺乏指导。本文利用任务固有的可回溯性，从答案反向恢复线索，构建固定的评估锚点，避免了模型信念波动和关键步骤识别的局限性。这一差异源于任务特性：搜索任务的答案可回溯性为密集监督提供了天然基础，而通用推理任务可能缺乏这一特性。

从方法设计看，本文与Search-R1同属RL训练搜索智能体路线，但奖励信号来源不同。Search-R1依赖稀疏的结果奖励，本文通过线索锚定步骤评分生成密集的步骤级奖励。这一改进使策略优化能针对中间步骤的质量进行微调，而非仅关注最终结果。然而，本文方法对验证答案的强依赖限制了其在无标准答案场景下的应用，而Search-R1的稀疏奖励机制虽粒度粗，但无需额外线索恢复过程，在数据标注成本上可能更具优势。

## 总结

本文要解决的核心矛盾是长程搜索智能体训练中轨迹级监督的稀疏性导致信用分配粒度不足。本文抓住搜索任务“答案可回溯”的特性，通过反向恢复中间证据线索，将稀疏结果奖励转化为密集步骤级监督。ABC框架在4B模型上实现了BrowseComp 37.3%和GAIA-text 81.6%的性能，显著优于同规模基线。本文的边界在于对验证答案的强依赖，限制了其在无标准答案场景下的泛化能力。当验证答案不可用时，如何基于环境反馈或自我验证生成类似的密集步骤奖励，论文未给出回答。
