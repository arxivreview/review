# HuggingFace最新推荐论文 ｜Lost in Compression: A Controlled Cross-Lingual Audit of Extractive Prompt Compressors ｜跨语言提示压缩审计

作者：Mantas Lukauskas

论文原文见 [arXiv](https://arxiv.org/abs/2608.26175)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.26175)

> 大模型部署中，非英语语言因分词器词表偏向英语而承担 1.3–1.8 倍的 Token 成本，压缩本应缓解此负担，但现有抽取式压缩器几乎全部基于英语监督训练，其跨语言有效性从未被系统验证。本文通过固定语义内容、匹配 Token 预算的受控协议，审计了四种学习压缩器与四种确定性基线在十种语言、十一个目标模型上的表现。核心发现是：英语监督压缩器在深度压缩时产生显著的跨语言转移差距，而多语言监督可消除该差距。这一审计揭示了压缩收益的语言不对称性，但仅覆盖抽取式方法，未触及软压缩或生成式压缩的跨语言行为。

## 研究背景

当 LLM 处理长上下文时，检索文档、工具输出与对话历史往往比问题本身长数个数量级，提示压缩（Prompt Compression）通过剔除低信息量 Token 降低推理成本。最实用的路线是抽取式压缩：一个小模型决定保留哪些 Token 或句子，其余丢弃，压缩后的提示仍是纯文本，可直接用于任何 API。这一路线的代表工作包括基于困惑度的 Token 剪枝（Jiang et al., 2023）、蒸馏的 Token 分类（Li et al., 2024）以及自信息过滤。然而，这些方法的开发、训练与评估几乎全部在英语上进行，尽管子词分词器将大部分词表容量分配给英语，导致低资源语言和非拉丁文字承担持续的 Token 溢价。

抽取式压缩在英语基准上报告了强劲结果，但跨语言轴从未被审计。LLMLingua-2 使用 XLM-R 多语言骨干，但其训练监督（GPT-4 在 MeetingBank 上的蒸馏）完全是英语的；Kompress-v2 作为 Headroom 生产栈中的 ModernBERT 压缩器，同样采用英语主导的 17 域监督。XProvence 是唯一的例外，它在 16 种语言上训练，但此前未测量相对于英语的跨语言转移差距。本文的切入点在于：如果英语监督的压缩器在非英语文本上不成比例地退化，其用户将遭受双重惩罚——Token 更贵，且压缩带来的质量损失更大。

## 核心方法

### 方法参照系

抽取式压缩的标准流程是：给定原始上下文 $C$ 和保留率 $\rho$，压缩器 $f$ 输出 $C' = f(C)$，使得 $|C'| \approx \rho |C|$ 且下游任务效用 $U(C', Q) \approx U(C, Q)$。本文不训练新压缩器，而是审计现有压缩器的跨语言表现，关键差异在于引入预算匹配的确定性基线（TF-IDF、截断、随机删除、词干化+停用词移除），以隔离压缩器质量与任务难度、分词器效应及模型行为。

### 归一化上下文利用率与转移差距

设计动机：原始准确率受任务难度和语言本身影响，无法直接比较压缩效果。本文定义归一化上下文利用率（Normalized Context Utilization）：

$$
U_{\ell,c} = \frac{\text{acc}_{\ell,c} - \text{acc}_{\ell,\text{no-context}}}{\text{acc}_{\ell,\text{full}} - \text{acc}_{\ell,\text{no-context}}}
$$

其中 $\ell$ 为语言，$c$ 为条件（如 LLMLingua-2@0.33）。该公式计算在语言 $\ell$ 下，条件 $c$ 保留了“可用上下文价值”的分数。转移差距（Transfer Gap）定义为：

$$
\tau_{\ell,c} = U_{\text{EN},c} - U_{\ell,c}
$$

正值表示非英语语言相对于英语的性能损失。分母（全上下文减无上下文准确率）在各语言间可比（主模型上 25.7–31.7 个百分点），因此归一化不会系统性放大任何特定语言的噪声。

### 预算匹配与多语言监督对照

设计动机：英语监督压缩器可能在非英语文本上既选择错误又预算失控，需分离这两种失效。本文对每个项目，将确定性基线的保留率匹配到 LLMLingua-2 的实际 o200k 预算，确保方法间比较公平。同时，引入 XProvence v1（原生多语言 MIRACL 训练）和 v2（翻译 MS MARCO 训练）作为多语言监督对照，测试多语言训练是否消除转移差距。XProvence 是查询感知方法，其绝对分数与任务无关压缩器不可直接比较，但跨语言对比有效：若多语言监督消除英语-其他语言不对称，则差距源于监督数据而非架构。

## 实验评估

实验使用 Belebele 阅读理解（每语言 300 个平行项目）作为主任务，MultiEURLEX 分类和长上下文压力测试（目标段落嵌入 7 个干扰项中）作为辅助臂。基线覆盖 LLMLingua-2（XLM-R/mBERT）、Kompress-v2、XProvence v1/v2，以及四种确定性方法。缺失软压缩方法（如 GIST、ICAE），因其需要模型内部访问，不适用于商业 API 场景。

| 语言 | $\rho=0.75$ (GPT/Claude) | $\rho=0.5$ (GPT/Claude) | $\rho=0.33$ (GPT/Claude) |
| :--- | :--- | :--- | :--- |
| EN | 0.88 / 0.95 | 0.74 / 0.82 | 0.57 / 0.62 |
| LT | 0.82 / 0.82 | 0.39 / 0.51 | 0.10 / 0.24 |
| ZH | 0.62 / 0.73 | 0.20 / 0.46 | −0.03 / 0.26 |
| HI | 0.77 / 0.92 | 0.42 / 0.70 | 0.33 / 0.53 |

在 $\rho=0.33$ 时，英语保留 57–62% 的归一化上下文利用率，而立陶宛语仅 10–24%，中文降至无上下文锚点以下（$U=-0.03$），意味着压缩后的上下文比无上下文更差。确定性基线在 GPT-5.4-mini 上未达显著性，表明差距源于压缩器而非任务或分词器。XProvence v1 在 GPT 上无转移差距（均值 −0.03），但 v2 在激进阈值下删除 92% 的中文上下文，暴露翻译监督的校准失败。

消融显示，mBERT 骨干复现了 XLM-R 的差距（$\rho=0.5$ 时 7/8 语言显著，均值 +0.31），证明差距源于英语监督而非特定编码器。Kompress-v2 在中文上近乎无效（实际保留率 0.91–0.96），因其空白分词无法切分汉字。长上下文压力测试中，LLMLingua-2@0.33 使立陶宛语、拉脱维亚语、波兰语上下文降至或低于无上下文效用，而确定性词干化+停用词移除在自然预算下保留 44–66% 的效用。

评估边界：指标仅基于准确率，未报告延迟或计算开销；Claude 的拒绝行为（拒答率高达 31.3%）混淆了“退化上下文”的含义；代码已释放，但超参数和 GPU 配置未在摘要中详述。

## 关联研究分析

从问题动机看，本文与 LLMLingua-2 共享抽取式压缩框架，但 LLMLingua-2 假设多语言骨干（XLM-R）足以支撑跨语言压缩，本文证明英语监督数据是瓶颈。这一差异源于任务特性：LLMLingua-2 的评估局限于英语，未暴露跨语言失效；本文通过平行数据揭示了监督语言的不对称性。XProvence 的多语言训练消除了差距，但其查询感知设置与任务无关压缩器不可直接比较，绝对分数差异可能源于任务难度而非压缩质量。

从方法设计看，本文与 GIST、ICAE 等软压缩方法形成路线对比。软压缩将上下文映射为连续向量，理论上可保留更多语义，但需要模型内部访问，不适用于商业 API。本文聚焦抽取式方法，因其是生产环境中最实用的路线。然而，软压缩的跨语言行为未被审计，若其同样受英语监督影响，则整个压缩领域的跨语言公平性需重新评估。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文要解决的核心矛盾是：压缩本应降低非英语语言的 Token 成本，但英语监督压缩器可能加剧其质量损失。现有方法未审计跨语言轴，本文通过预算匹配的受控协议，证明英语监督压缩器在深度压缩时产生显著转移差距（$\rho=0.33$ 时 8/9 语言显著），而多语言监督可消除该差距。本文审计了四种学习压缩器和四种确定性基线，在十一种语言、十一个目标模型上验证了差距的普遍性。边界在于：仅覆盖抽取式方法，未触及软压缩；Claude 的拒绝行为混淆了部分结果；中文的失效部分源于分词器而非压缩器。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
