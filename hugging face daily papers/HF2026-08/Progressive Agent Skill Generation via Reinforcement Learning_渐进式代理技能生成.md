> 代理技能生成旨在将异构证据转化为可复用的程序性模块，但现有方法依赖启发式规则，缺乏对编辑质量的直接监督。本文指出技能价值仅体现在下游执行效果中，导致传统监督信号失效。Skill-α 将生成重构为序列编辑决策，引入回滚奖励（Rollback Reward）实现局部信用分配。该方法在统一框架下优于专用基线，但其性能高度依赖证据粒度，且未解决跨任务泛化的理论边界。

## 研究背景

当代理面对长文档或复杂轨迹时，一次性生成技能往往因上下文溢出而遗漏关键约束，且抽象、去噪与冲突消解操作相互纠缠，导致无法定位具体哪一步编辑导致了性能波动。这种全局优化的模糊性使得技能质量难以通过文本相似度评估，必须依赖下游任务的成功率作为间接反馈。然而，直接奖励最终成功率会将代理自身能力与技能贡献混淆，无法区分是技能改进还是查询简单导致的成功。

技能生成领域长期存在文档到技能与经验到技能两条割裂的路线，前者侧重规则压缩，后者侧重轨迹蒸馏，各自依赖特定的管道设计。主流方法如 Trace2Skill 和 AutoSkill 虽能产出可用技能，但缺乏统一的信用分配机制，难以从失败中精准学习。Skill-α 的切入点在于将技能生成形式化为马尔可夫决策过程，通过分解编辑动作并引入对比式奖励，解决了异构证据源下缺乏自然监督信号的核心难题。

## 核心方法

### 渐进式编辑决策

技能生成通常被视为从证据到文本的一次性映射，本文将其重构为状态空间中的序列决策问题。给定初始技能状态 $z_0$ 和证据序列 $x_{1:T}$，策略 $\pi_\phi$ 逐步采样局部编辑动作 $A_t$，更新状态 $z_t = \text{Edit}(z_{t-1}, A_t)$。这一设计动机在于解耦抽象与压缩操作，使每一步编辑仅针对单一证据单元，从而将全局优化问题降维为局部可控的决策序列，避免了长上下文下的信息丢失。

### 回滚奖励机制

直接评估编辑后技能在下游任务的表现存在归因偏差，因为成功可能源于代理基线能力而非技能改进。为此，本文引入回滚奖励，通过对比编辑前后技能在同一锚定查询 $q^{anc}_t$ 上的执行结果来分配信用。具体而言，固定工作代理 $\pi_\psi$ 分别基于原始技能 $z_{t-1}$ 和编辑后技能 $z_t$ 生成轨迹，由验证器 $V_t$ 计算差异：

$$ r_t = V_t(a^{edit}_t) - V_t(a^{ctrl}_t) $$

其中 $a^{edit}_t \sim \pi_\psi(\cdot | q^{anc}_t, z_t)$ 且 $a^{ctrl}_t \sim \pi_\psi(\cdot | q^{anc}_t, z_{t-1})$。该公式的物理含义是剥离代理固有能力的干扰，仅度量技能编辑带来的边际效用，从而为强化学习提供无偏的局部梯度信号。

### 动作空间与策略优化

编辑动作空间定义为 $\mathcal{A} = \{\text{CREATE}, \text{UPDATE}, \text{MERGE}, \text{PRUNE}, \text{NOOP}\}$，分别对应新增、修正、合并、剪枝与保持。设计动机在于显式建模技能的维护操作，防止技能库因持续累积而冗余。策略优化采用组相对策略优化（GRPO），对同一状态采样的动作组进行相对优势计算：

$$ \hat{A}_i = \frac{r_i - \text{mean}(\{r_j\})}{\text{std}(\{r_j\})} $$

通过组内归一化消除环境噪声，使策略能够区分不同编辑动作的相对优劣，而非依赖绝对奖励值，提升了在稀疏奖励场景下的收敛稳定性。

## 实验评估

实验在 CL-Bench、SpreadsheetBench 和 tau2-bench 上进行，基线覆盖文档类（Ctx2Skill, AutoSkill）和经验类（Trace2Skill, ExpeL）方法。在 GPT-4o 工作代理下，Skill-α 在 CL-Bench 平均通过率上较最强基线提升 3.3 个点，在 tau2-bench 上提升 6.7 个点。

| 方法 | CL-Bench Avg. | SpreadsheetBench | tau2-bench Avg. |
| :--- | :--- | :--- | :--- |
| NO SKILL | 21.82 | 18.00 | 33.33 |
| Trace2Skill | 15.82 | 19.00 | 41.67 |
| SkillPro | 15.50 | 15.50 | 49.17 |
| Skill-α | 20.91 | 27.50 | 55.83 |

消融实验显示，移除回滚奖励后性能骤降至接近 SFT 基线，验证了局部信用分配的关键性；移除 MERGE/PRUNE 动作导致 tau2-bench 性能下降 16.66 个点，表明技能维护操作对防止冗余累积至关重要。

| 变体 | CL-Bench Avg. | SpreadsheetBench | tau2-bench Avg. |
| :--- | :--- | :--- | :--- |
| Skill-α | 10.38 | 27.50 | 55.83 |
| w/o rollback reward | 3.68 | 17.00 | 46.67 |
| w/o MERGE/PRUNE | 4.74 | 20.00 | 39.17 |
| w/o NOOP | 9.55 | 22.00 | 53.33 |

评估边界方面，论文未报告置信区间，且跨工作代理（Claude-Sonnet-4.5）的迁移实验仅作为辅助验证。代码已开源，但训练依赖 8 块 GPU 及特定的锚定查询构建流程，复现成本较高。

## 关联研究分析

从问题动机看，Skill-α 与 SkillOpt 均关注技能优化，但 SkillOpt 侧重于基于验证门控的文档级迭代，而 Skill-α 聚焦于生成阶段的编辑级信用分配。SkillOpt 假设技能结构已存在，通过增删改操作微调；Skill-α 则从初始状态构建技能，其回滚奖励机制比 SkillOpt 的全局验证更细粒度，能定位具体哪条规则引入了错误。这种差异源于任务阶段的不同：生成阶段需要探索性编辑，优化阶段需要保守性修正。

从方法设计看，Skill-α 与 Trace2Skill 同属经验蒸馏路线，但 Trace2Skill 采用离线并行蒸馏，Skill-α 采用在线序列编辑。Trace2Skill 通过归纳压缩平滑情节怪癖，但缺乏对编辑质量的即时反馈；Skill-α 通过 GRPO 闭环优化，使生成器能根据执行结果动态调整编辑策略。然而，Skill-α 对证据粒度的敏感性（批次大小为 4 时最优）暴露了其序列决策的局限性，而 Trace2Skill 的并行结构在证据量大时可能更具鲁棒性，但牺牲了编辑的连贯性。

## 总结

Skill-α 解决了异构证据源下技能生成缺乏统一监督信号的核心矛盾，通过将生成重构为序列编辑并引入回滚奖励，实现了局部信用分配的精准化。实验证明该方法在 CL-Bench 和 tau2-bench 上显著优于专用基线，验证了渐进式编辑与对比式奖励的有效性。然而，其性能对证据批次大小高度敏感，且锚定查询的选择可能引入偏差，限制了其在动态环境中的泛化能力。当证据源包含大量噪声或冲突信息时，回滚奖励能否有效区分有效编辑与噪声干扰，论文未给出回答。
