# HuggingFace最新推荐论文 ｜PILOT in the Loop: Live Self-Improvement for Long-Horizon Agents ｜实时自进化：长程智能体的监督-执行闭环

作者：Yang Xiao、Yusong Sun、Haoyi Wu 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.26530)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.26530)

> 长程任务中，智能体在执行过程中产生的经验既可能挽救当前运行，也可能沉淀为未来可复用的技能，但现有自进化方法仅在运行结束后处理这些经验，导致即时纠错与持久化学习无法同时发生。本文指出，单智能体自修正受限于上下文污染，子智能体委托则缺乏实时干预通道，二者均无法在运行中同时实现“修正当前”与“更新未来”。PILOT 通过 Supervisor-Worker 架构，将实时转向（Live Steering）与实时自进化（Live Self-Evolution）耦合于同一执行流，在冻结骨干模型下实现了性能与效率的双重提升。其价值在于填补了“实时性”与“角色分离”的架构空白，但技能库的长期膨胀与检索精度衰减问题尚未被充分验证。

## 研究背景

长程智能体任务要求模型在状态持续变化的环境中执行多步操作，其核心挑战在于如何从交互轨迹中提取有效经验。经验通常以两种形式存在：一是即时性的策略修正，用于避免当前运行陷入死胡同；二是持久性的程序性知识，如特定工具的使用惯例或失败模式，需存入外部存储以供后续任务复用。这两种经验的时间尺度不同，前者必须在当前运行结束前生效，后者则需在运行结束后被验证并固化。

现有自进化方法主要依赖事后反思（Post-hoc Reflection），如 Reflexion 和 ExpeL，它们在任务完成后生成自然语言反思或提取教训，但无法干预已发生的执行过程。尽管 Harness 进化路线（如 DarwinX、ACE）通过更新外部脚手架提升了长期稳定性，但其更新机制仍基于完整轨迹的离线处理。这种“执行-反思-更新”的串行模式导致两个关键失效：一是当前运行中暴露的错误无法被即时纠正，造成资源浪费；二是新生成的知识无法立即在后续步骤中验证其有效性，降低了自进化的可靠性。

PILOT 的切入点在于打破这种串行依赖，提出“实时自进化”（Live Self-Improvement）范式。该范式要求自进化机制同时满足两个条件：一是实时性，即利用执行中产生的经验立即重定向当前运行；二是角色分离，即监督与执行由不同上下文承担，以避免执行细节污染诊断逻辑。这一设计直接回应了长程任务中“纠错时效性”与“知识沉淀效率”的矛盾。

## 核心方法

### 方法参照系

PILOT 属于非参数化 Harness 进化路线，其标准流程为：智能体执行任务 → 收集完整轨迹 → 离线提取经验 → 更新外部存储（技能/记忆） → 后续任务加载更新后的存储。本文的关键差异在于将“经验提取”与“存储更新”嵌入执行流内部，而非置于执行流之后，从而实现了经验对当前运行的即时反馈。

### 实时转向机制

实时转向（Live Steering）解决了单智能体自修正中“执行与诊断共享上下文”导致的注意力分裂问题。在 PILOT 中，Supervisor 通过双向实时通道与 Worker 保持连接，该通道支持五种事件：Worker 向 Supervisor 发送通知（Notification）、提问（Question）和结果（Result）；Supervisor 向 Worker 发送转向指令（Steer）或中止指令（Abort）。

$$
\text{Steer}(W_j, \xi_j) \rightarrow \text{Queue}(\text{Guidance}_{j+1})
$$

该公式表示当 Supervisor 检测到 Worker $W_j$ 的轨迹 $\xi_j$ 偏离目标时，它不直接修改当前动作，而是将指导信息加入 Worker 下一轮的输入队列。这种设计确保了当前动作的完整性，同时允许 Supervisor 在 Worker 的下一个决策点注入修正策略。Supervisor 的上下文仅保留目标、近期事件和偏差信号，而 Worker 的上下文吸收执行细节和死胡同，二者通过隔离的上下文实现功能解耦。

### 实时自进化机制

实时自进化（Live Self-Evolution）解决了离线反思中“知识无法即时验证”的问题。当 Supervisor 在实时轨迹中识别出可复用的程序（如特定工具调用序列）或失败模式时，它立即将其蒸馏为技能（Skill）或记忆（Memory），并更新持久化 Harness $H$ 为 $H'$。

$$
H' = \text{Distill}(H, \xi_{\text{live}}, \text{Feedback}_{\text{env}})
$$

该公式表示新的 Harness 状态 $H'$ 由旧状态 $H$、实时轨迹 $\xi_{\text{live}}$ 和环境反馈 $\text{Feedback}_{\text{env}}$ 共同决定。关键约束是：更新发生在任务执行期间，且仅基于实时观察，不依赖验证器（Verifier）的最终结果。只有当一轮迭代（Iteration）中所有任务完成后，验证器才决定哪些更新被保留至下一轮迭代。这种“执行中生成、迭代后筛选”的机制确保了技能库的纯净性，同时允许 Worker 在后续任务中立即加载 $H'$，形成闭环。

## 实验评估

PILOT 在 Terminal-Bench 2.0、SWE-bench Multilingual 和 SWE-bench Pro 三个长程基准上，使用 GLM-5.1 和 Kimi-K2.6 两个冻结骨干模型进行评估。基线包括 Pi、OpenCode、Hermes、Terminus-2 和 Mini-SWE-Agent，均为单智能体 Harness，未包含参数化微调基线（如 EvolveR），这限制了与参数化路线的直接对比。

| 基准 | 骨干模型 | PILOT | 最强基线 | 基线名称 | 差距 (pp) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Terminal-Bench 2.0 | GLM-5.1 | 71.9 | 66.9 | OpenCode | 5.0 |
| Terminal-Bench 2.0 | Kimi-K2.6 | 71.3 | 66.9 | Pi | 4.4 |
| SWE-bench Pro | GLM-5.1 | 54.7 | 53.7 | Mini-SWE-Agent | 1.0 |
| SWE-bench Pro | Kimi-K2.6 | 65.1 | 59.1 | Pi | 6.0 |

在自进化设置中，PILOT 在 Terminal-Bench 2.0 上的最佳通过率从迭代 0 的 66.3%（GLM-5.1）提升至 80.9%，增益 14.6 个百分点；Kimi-K2.6 从 68.5% 提升至 80.9%，增益 12.4 个百分点。相比之下，OpenCode 增益 7.9 个百分点，Pi 增益 2.3 个百分点。技能库规模从 62（GLM-5.1）增长至 83，从 50（Kimi-K2.6）增长至 81。平均输出 Token 数分别下降 42.9% 和 47.4%，每百万 Token 的成功评估次数分别提升 110.3% 和 134.0%。

消融分析显示，性能增益在 Hard 任务上最大，GLM-5.1 在 Hard 任务上额外通过 8 个任务，Kimi-K2.6 额外通过 12 个任务。这表明实时自进化对需要特定程序性知识的复杂任务贡献最大，因为这类任务难以从骨干模型中直接重构。Token 效率的提升表明，累积的 Harness 知识减少了重复推理和探索，使后续任务能更高效地复用既定程序。

评估边界方面，论文未报告置信区间，且所有实验均在隔离容器沙箱中进行，未测试高并发或资源受限场景。代码已开源，但超参数设置（如 Supervisor 的上下文窗口大小）未详细披露，可能影响复现性。此外，实验未包含参数化微调基线，无法直接比较非参数化实时进化与参数化离线进化的长期稳定性差异。

## 关联研究分析

从问题动机看，PILOT 与 Reflexion 和 ExpeL 的核心差异在于时间尺度。Reflexion 和 ExpeL 依赖完整轨迹的离线反思，其经验提取发生在任务结束后，无法干预当前运行。PILOT 将经验提取嵌入执行流，使得 Supervisor 能在 Worker 偏离目标时立即发送 Steer 指令，从而挽救当前运行。这一差异源于长程任务中“纠错时效性”的重要性：在 Terminal-Bench 2.0 等基准中，早期错误可能导致后续步骤全部失效，离线反思无法弥补这一损失。

从方法设计看，PILOT 与 DarwinX 和 ACE 的差异在于进化粒度。DarwinX 和 ACE 优化静态 Harness 组件（如提示词、技能库），其更新基于完整轨迹的离线分析。PILOT 则优化动态执行流，Supervisor 在运行中实时调整 Worker 的行为，并将实时观察到的程序性知识即时存入 Harness。这种设计使得 PILOT 能够捕捉离线方法无法获取的“中间状态”信息，如 Worker 在特定工具调用后的即时反馈。然而，这种实时性也引入了新的风险：Supervisor 的实时判断可能受限于其上下文窗口的长度，若 Worker 的执行细节过于复杂，Supervisor 可能无法准确识别偏差。

## 总结

PILOT 解决了长程智能体中“即时纠错”与“持久化学习”无法同时发生的矛盾，通过 Supervisor-Worker 架构将实时转向与实时自进化耦合于同一执行流。在 Terminal-Bench 2.0 上，PILOT 的最佳通过率提升 14.6 个百分点，平均输出 Token 数下降 42.9%，验证了实时闭环的有效性。其边界在于：实验未包含参数化微调基线，无法比较非参数化实时进化与参数化离线进化的长期稳定性；技能库的持续膨胀可能导致检索精度下降，论文未提供技能库规模与检索效率的定量关系。当技能库规模超过一定阈值时，Supervisor 的实时蒸馏过程是否会因检索延迟而降低转向的及时性，论文未给出回答。
