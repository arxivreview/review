# HuggingFace最新推荐论文 ｜FrontierChallenge: Evaluating Scientific Workflow Completion ｜科学工作流完成度基准

作者：Liangcai Su、Zhaopeng Feng、Zhuo Chen 等 16 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.24979)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.24979)

> 科学智能体评测长期聚焦于单点答案或单一领域代码，无法衡量跨域多阶段任务中“部分完成”与“完全交付”的差距。现有基准如 ScienceAgentBench 仅评估可执行分析片段，而 HLE 侧重专家知识问答，均缺乏对异构产物一致性的合同级约束。本文构建包含 300 个端到端工作流的基准，通过固定输入与多产物 Grader 量化这一差距。其价值在于揭示了高分低完成率的系统性偏差，但 97 个公开任务的领域分布不均限制了跨学科泛化结论的普适性。

## 研究背景

当智能体执行材料表征或电化学分析时，其输出并非单一数值，而是包含代码、图表、报告在内的异构产物束。若仅评估最终答案，无法区分“推理正确但代码报错”与“代码正确但结论错误”，这种评估盲区导致模型在长程任务中的可靠性无法被量化。解决此问题需引入合同级评估（Contract-level Evaluation），即定义任务交付的完整契约，要求所有产物同时满足一致性、可执行性与数值准确性，而非依赖单一指标。

科学智能体评测的主流路线存在显著瓶颈。ScienceAgentBench 等基准虽引入可执行分析，但局限于单一学科且产物单一；HLE 与 ALE 侧重专家知识或长程专业工作，却未覆盖跨域科学工作流的多产物一致性要求。这些基准无法捕捉智能体在“部分完成”状态下的具体失效模式，例如代码可运行但图表缺失，或报告结论与数据矛盾。FRONTIERCHALLENGE 的切入点在于将评估单元从“答案”或“单程序”扩展为“完整产物束”，通过固定科学输入与任务特定 Grader，量化智能体在既定目标下完成全流程的能力，从而暴露现有评测体系对“交付完整性”的忽视。

## 核心方法

### 方法参照系

本文问题属于自主科研智能体的端到端执行评测，与 ScienceAgentBench 的通用流程相似，但关键差异在于：本文不要求智能体自主设定研究目标，而是评估其在固定输入与固定目标下的工作流完成度，且评估对象为多产物束而非单一输出。

### 任务契约与固定输入

传统基准常允许智能体自行选择数据或方法，导致评估结果受路径选择影响。本文通过固定科学输入（如公开实验数据、序列资源）与明确的任务描述，消除路径不确定性，确保评估聚焦于执行能力而非规划能力。每个任务包包含任务描述、固定输入、可用工具、输出契约与评估程序，其中输出契约明确列出所有必需产物（如报告、表格、代码），确保评估的完整性。

### 合同级评估与 Pass Rate 指标

现有基准多采用部分得分或单一指标，无法区分“接近完成”与“完全交付”。本文引入 Pass Rate 作为主指标，定义为满足完整任务契约的任务比例，辅以 Avg. Score 衡量部分进度。Pass Rate 的计算基于任务特定 Grader 返回的分数 $s_{mi} \in [0, 100]$，当 $s_{mi} \geq 99.9$ 时视为完全完成：

$$
\text{Pass Rate}_m = \frac{1}{N} \sum_{i=1}^{N} \mathbb{1}[s_{mi} \geq 99.9]
$$

该公式的物理含义是：只有当所有产物（代码、图表、报告）同时满足一致性、可执行性与数值准确性时，任务才被计为通过。99.9 阈值仅吸收三次 Judge 评分平均带来的微小数值波动，不放松任何契约要求。这一设计解决了现有基准中“高分低完成率”的模糊性，使评估结果直接反映智能体的端到端交付能力，而非部分进度。

## 实验评估

实验在 97 个公开任务上进行，覆盖量子化学、分子动力学等六个领域，基线包括 GPT-5.6 Sol、Grok 4.6 等 12 个前沿模型，使用 Codex、Claude Code 等三种智能体脚手架。基线覆盖当前主流模型，但缺失早期专用科学模型（如 AlphaFold），可能低估领域专用模型的表现。

| 模型 | 脚手架 | Pass Rate (%) | Avg. Score |
| :--- | :--- | :--- | :--- |
| GPT-5.6 Sol | Codex | 20.6 | 87.9 |
| Grok 4.6 | Claude Code | 20.6 | 86.6 |
| Kimi K3 | Claude Code | 17.5 | 85.5 |
| Claude Opus 5 | Claude Code | 17.5 | 84.9 |
| GPT-5.6 Terra (max) | Codex | 15.5 | 84.7 |

核心数字对比显示，最高 Pass Rate 仅为 20.6%，而最高 Avg. Score 达 87.9，表明部分进度与完全交付之间存在显著差距。在分析化学与电化学/环境领域，Avg. Score 分别达 87.6 和 94.9，但最高 Pass Rate 仅为 4% 和 0%，进一步证实高分不等于完全交付。

消融分析显示，领域间性能差异显著：量子化学 Pass Rate 最高达 60%（Grok 4.6），而电化学/环境 Pass Rate 为 0%。失败模式分析表明，75.5% 的非通过轨迹在最终消息中包含完成语言，但实际未满足契约，说明自报告不可靠。工具错误未预测成功：94.2% 的通过轨迹至少出现一次工具错误，表明错误恢复能力是关键。

评估边界方面，97 个任务中 74 个为 Hard 难度，领域分布不均（如电化学仅 6 个任务），限制了跨学科泛化结论。代码与数据已公开，但 Grader 依赖 GPT-5.6 Sol 作为 Judge，可能存在模型偏见。

## 关联研究分析

从问题动机看，FRONTIERCHALLENGE 与 ScienceAgentBench 均关注科学智能体执行，但前者聚焦“固定目标下的完成度”，后者侧重“自主分析生成”。这一差异源于任务特性：ScienceAgentBench 评估智能体从数据到分析的能力，而本文评估智能体在既定流程中的可靠性。若智能体在固定流程中无法完成，其自主分析能力更不可靠，但本文未验证这一假设。

从方法设计看，FRONTIERCHALLENGE 与 HLE 均使用可验证任务，但前者引入多产物一致性检查，后者仅评估单一答案。这一差异源于评估目标：HLE 测试专家知识，本文测试执行可靠性。多产物一致性检查是否引入新的评估偏差（如过度惩罚部分正确但产物不一致的任务），论文未给出回答。

## 总结

FRONTIERCHALLENGE 要解决的核心矛盾是科学智能体评测中“部分完成”与“完全交付”的模糊性。现有基准无法量化这一差距，而本文通过固定输入与合同级评估，使评估结果直接反映端到端交付能力。本文构建了 300 个工作流基准，揭示最高 Pass Rate 仅 20.6%，而 Avg. Score 达 87.9，证实高分不等于完全交付。其边界在于 97 个公开任务的领域分布不均，且 Grader 依赖单一模型 Judge。当任务难度从 Hard 降至 Medium 时，Pass Rate 是否显著提升，论文未给出回答。
