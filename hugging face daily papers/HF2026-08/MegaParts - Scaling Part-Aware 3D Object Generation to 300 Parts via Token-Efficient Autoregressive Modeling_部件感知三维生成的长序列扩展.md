# HuggingFace最新推荐论文 ｜MegaParts: Scaling Part-Aware 3D Object Generation to 300 Parts via Token-Efficient Autoregressive Modeling ｜部件感知三维生成的长序列扩展

研究机构：复旦大学、同济大学

作者：Manwen Liao、Xinyu Lian、Jian Mao 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.14783)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.14783)

> 三维资产生成需从单体网格转向具备语义结构的部件级表示，以支持编辑与动画绑定。现有扩散模型在处理超过50个部件时，因全局注意力机制导致计算开销与内存占用呈指数级增长，无法应对复杂资产。MegaParts 通过引入自适应长度的向量量化（Vector Quantization, VQ）令牌化器与长上下文大语言模型（Large Language Model, LLM），将几何生成转化为结构化序列预测，实现了300个部件的规模化生成。该路线在几何保真度上超越了部分扩散基线，但仅覆盖几何属性，未解决物理接地与纹理生成问题。

## 研究背景

当三维对象被建模为单一实体时，其内部结构信息被隐式编码在连续的隐式场中，导致无法对局部部件进行独立控制或编辑。为了解决这一结构缺失问题，部件感知生成（Part-aware Generation）将对象显式分解为语义组件，但这一过程引入了新的表示挑战：如何为不同复杂度的部件分配合理的计算资源。传统的向量集（VecSet）或体素（Voxel）表示采用固定容量的潜变量池，导致几何简单的部件与复杂的部件获得相同的表示预算，造成容量浪费或细节丢失。这种固定的容量分配机制与部件感知的语义分解需求存在根本冲突，限制了模型在复杂资产上的表现。

当前主流部件感知生成方法主要依赖扩散架构，通过精心设计的局部与全局注意力机制来建模部件间关系。然而，扩散模型在长序列建模上存在固有瓶颈，随着部件数量增加，Token长度、内存使用及计算开销迅速增长，导致现有方法大多局限于50个部件以下的对象。MegaParts 的切入点在于利用自回归模型（Autoregressive Model）在长上下文处理上的优势，结合一种能根据几何复杂度动态调整Token数量的离散表示方法，从而突破部件数量与计算成本之间的规模瓶颈。

## 核心方法

### 因果自编码器与SDF建模

本文基于 Cube 架构，将双向注意力替换为全因果注意力，构建支持自适应长度Token化的向量量化自编码器（VQ-VAE）。输入为表面点集 $S = \{(p_i, f_i)\}_{i=1}^N$，编码器通过交叉注意力与因果自注意力更新潜查询，最终输出离散潜序列 $Z_q$。解码器利用因果自注意力层处理 $Z_q$，并通过查询头预测任意3D点 $x$ 的有符号距离场（Signed Distance Field, SDF）值。这种因果结构使得早期Token承载更关键的几何信息，允许截断尾部Token而不显著降低重建质量。

### 自适应长度Token化与率失真优化

为平衡几何保真度与Token效率，本文提出基于率失真理论的自适应Token预算分配机制。对于包含 $K$ 个组件的对象，全局布局表示为 $P = [a^{(1)}, \dots, a^{(K)}]$，其中每个组件描述符 $a^{(c)} = [b^{(c)}, L_c^*]$ 包含边界框中心 $m^{(c)}$、尺度 $e^{(c)}$ 及最优Token长度 $L_c^*$。最优长度通过最小化率失真目标函数确定：

$$ L_c^* = \arg \min_{L \in \{2^n\}_{n=4}^{12}} J^{(c)}(L) $$

其中 $J^{(c)}(L) = D^{(c)}(L) + \gamma R^{(c)}(L)$，$D^{(c)}(L)$ 为重建失真，$R^{(c)}(L)$ 为编码率。该机制允许简单部件仅用少量Token表示，而复杂部件保留足够容量，避免了固定预算下的容量错配。

### 长上下文自回归生成框架

在紧凑表示基础上，本文微调 Qwen3 作为生成器，将三维生成建模为统一的结构化序列预测任务。序列 $Y = [P, C]$ 首先生成所有组件的布局信息，随后自回归地生成每个组件的几何Token序列 $C = [z_1^{(1)}, \dots, z_{L_K^*}^{(K)}]$。训练采用标准下一Token预测目标：

$$ p_\theta(s | q) = \prod_{t=1}^{T} p_\theta(s_t | q, s_{<t}) $$

其中 $q$ 为包含控制信号的提示，$s$ 为序列化形状表示。通过上下文并行与张量并行策略，该框架可扩展至256k Token长度，支持300个部件的复杂对象生成。

## 实验评估

| 方法 | Part CD ($\times 10^{-2}$) ↓ | Part IoU ↑ | BBox IoU ↑ |
| :--- | :--- | :--- | :--- |
| FullPart | 8.59 | 0.41 | 0.76 |
| XPart | 8.01 | 0.52 | 0.59 |
| MegaParts | 3.01 | 0.63 | 0.94 |

在 PartObjaverse-Tiny 基准上，MegaParts 在部件级 Chamfer Distance (CD) 上取得 3.01×10⁻² 的成绩，显著优于 FullPart (8.59×10⁻²) 和 XPart (8.01×10⁻²)，同时 BBox IoU 达到 0.94，表明其在结构布局预测上的精确性。文本条件生成方面，MegaParts 的 FID 为 43.40，CLIP Score 为 0.27，优于 SAR3D (FID 94.69) 和 TRELLIS-text (FID 54.81)，验证了自回归路线在语义对齐与几何质量上的竞争力。

| 配置 | Part CD ($\times 10^{-3}$) ↓ | Part NC ↑ | Object CD ($\times 10^{-3}$) ↓ | Object NC ↑ |
| :--- | :--- | :--- | :--- | :--- |
| Ours (1024) | 0.12 | 0.93 | 1.52 | 0.89 |
| w/o phased VQ-VAE | 0.22 | 0.82 | 2.88 | 0.81 |
| w/o causal attn. | 0.22 | 0.90 | 1.92 | 0.86 |

消融实验显示，移除分阶段 VQ-VAE 训练导致部件级 CD 从 0.12×10⁻³ 恶化至 0.22×10⁻³，表明交替优化对稳定离散码本分配至关重要。移除因果注意力后，虽然部件级 CD 变化不大，但对象级 CD 从 1.52×10⁻³ 上升至 1.92×10⁻³，证实因果结构在维持全局结构一致性方面的作用。

评估协议主要依赖 PartObjaverse-Tiny 的部件级指标，缺乏对物理稳定性或动画平滑度的直接量化。论文未公开代码仓库，仅提供项目页面，且训练数据包含私有数据，限制了完全复现的可能性。此外，基线对比中未包含最新的物理接地生成方法，使得在功能资产生成维度的比较存在盲区。

## 关联研究分析

从方法设计看，MegaParts 与 Cube 共享 VQ-VAE 基础，但 Cube 采用固定长度 Token 与 GPT-2 骨干，而 MegaParts 引入自适应长度机制与 Qwen3 长上下文 LLM。这一差异源于任务规模的不同：Cube 面向单体生成，固定预算足以覆盖；MegaParts 面向多部件复杂资产，固定预算会导致简单部件浪费容量或复杂部件细节丢失。自适应率失真优化是解决这一容量错配的关键，但论文未讨论该机制在极端复杂部件（如微结构）上的收敛性，查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从问题动机看，MegaParts 与 TRELLIS 均致力于高质量三维生成，但 TRELLIS 基于稀疏体素的潜空间扩散，而 MegaParts 采用离散序列自回归。TRELLIS 的优势在于连续空间的平滑性，但在长序列下计算开销大；MegaParts 利用 LLM 的长上下文能力，将生成过程解耦为布局预测与局部几何填充，实现了规模扩展。然而，MegaParts 仅生成几何，缺乏纹理与物理属性，而 TRELLIS 等扩散方法通常联合生成外观。这种功能缺失使得 MegaParts 在直接应用于仿真或游戏引擎时，仍需后续处理步骤，其端到端的功能资产生成能力尚未得到验证。

## 总结

MegaParts 旨在解决部件感知三维生成中部件数量与计算成本之间的规模矛盾。现有扩散方法因全局注意力机制在长序列下效率低下，而本文通过自适应长度 VQ-VAE 与长上下文 LLM 的结合，将几何生成转化为结构化序列预测，实现了300个部件的规模化生成。实验表明，该方法在 PartObjaverse-Tiny 上取得 3.01×10⁻² 的部件级 CD 和 43.40 的 FID，优于主要自回归与扩散基线。然而，论文仅关注几何属性，未涉及纹理、材质或物理关系，且依赖私有数据训练，限制了通用性评估。当部件数量进一步增加至数千时，自适应 Token 预算的率失真优化是否仍能保持线性扩展效率，论文未给出回答。
