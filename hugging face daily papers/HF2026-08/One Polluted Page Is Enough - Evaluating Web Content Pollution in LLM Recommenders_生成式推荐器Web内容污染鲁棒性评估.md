# HuggingFace最新推荐论文 ｜One Polluted Page Is Enough: Evaluating Web Content Pollution in LLM Recommenders ｜生成式推荐器Web内容污染鲁棒性评估

研究机构：香港中文大学

作者：Minghao Luo、Liang Chen

论文原文见 [arXiv](https://arxiv.org/abs/2606.13610)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2606.13610)

> 搜索增强大语言模型（LLM）在消费实时Web检索结果生成推荐时，面临生成式引擎优化（GEO）攻击导致的虚假品牌注入风险。现有鲁棒性基准针对封闭语料或提示注入，无法覆盖开放Web中无显著特征的用户风格污染。本文构建FORGE基准，通过本地重写检索证据中的真实品牌为虚假品牌，量化12个主流LLM在受控污染下的被欺骗率。该工作揭示了推理机制反而加剧漏洞的悖论，但防御机制的有效性仍受限于对合法推荐的过度抑制。

## 研究背景

当LLM作为推荐器消费实时Web检索结果时，其信任边界从模型参数转移至开放Web。GEO攻击者通过向开放Web注入伪造的用户评论或推广页面，使虚假品牌进入LLM的证据束。由于污染内容模仿真实用户生成文本，缺乏触发词或异常指令等显著特征，传统基于模式匹配的防御机制失效。这种污染与针对封闭RAG语料的投毒不同，它发生在无策展人的开放环境中，且被推广的品牌可能是模型从未见过的完全虚构实体。

生成式推荐领域的研究重心长期聚焦于语义对齐与效率优化，如通过语义标识符（Semantic ID, SID）将推荐重构为自回归生成任务，或利用强化学习优化长期用户目标。然而，这些工作假设输入证据是干净且结构化的，未考虑开放Web环境的对抗性噪声。当模型缺乏对特定品类真实品牌的稳定先验知识时，其语义泛化能力反而成为漏洞，导致其将虚假Web证据误判为可信信息。本文切入点在于量化这一安全盲区，并评估现有推理增强与防御机制在对抗场景下的实际表现。

## 核心方法

### 方法参照系

本文问题属于生成式推荐的安全鲁棒性评估，与标准生成式推荐流程的关键差异在于输入端。标准流程假设检索证据 $E$ 是可信的，而本文模拟 $E$ 被污染为 $\tilde{E} = E \cup E_{fake}$，其中 $E_{fake}$ 包含虚假品牌 $B_{fake}$。评估目标不再是推荐准确性，而是模型在消费 $\tilde{E}$ 时生成 $y \in B_{fake}$ 的概率。

### 污染模拟与评估指标

污染模拟发生在证据束构建阶段，采用实体替换（A1）作为默认攻击，将检索文档中的主导真实品牌重写为虚假品牌-产品复合体，保留URL、排名和上下文。这种设计隔离了品牌替换这一单一变量，确保推荐变化仅源于品牌篡改。评估指标为被欺骗率（Fooled Rate），定义为模型输出中虚假品牌出现在编号推荐列表中的比例。

$$
\text{Rec}(r, t) = \mathbb{I}[t \in \text{List}(r)]
$$

其中 $r$ 为模型响应，$t$ 为虚假品牌目标，$\text{List}(r)$ 为解析出的编号列表项。该公式将“提及”与“推荐”解耦，仅当虚假品牌出现在结构化推荐列表中时才计为被欺骗，排除了模型在警告或对比语境中提及虚假品牌的情况。

### 推理机制与防御评估

推理机制的评估通过配对设计实现，对同一模型在相同污染单元上分别启用和禁用内部推理，比较被欺骗率差异。防御机制包括怀疑提示（D1）、模型先验共识过滤（D2）和跨文档证据一致性过滤（D3）。D3的核心逻辑是计算虚假品牌在证据束中的跨文档支持度 $\tau$，若支持度低于阈值则过滤。

$$
\text{Filter}(y) = \mathbb{I}[\text{Count}(y, E) < \tau]
$$

该公式通过限制单一来源的虚假品牌传播，试图利用真实品牌通常具有多文档支持的特性来区分真假。然而，当攻击者注入多个相互印证的虚假页面时，该过滤机制会误伤合法推荐。

## 实验评估

实验在FORGE基准上进行，覆盖15个品类225个真实产品，对比12个商用和开源LLM。基线审计显示，本文未对比专用推荐模型（如SASRec、TIGER），因为任务定义从准确性转向鲁棒性，对比对象为通用LLM助手。主实验结果显示，在Top-3实体替换攻击下，模型被欺骗率范围为13.3%至73.8%，其中Ministral-3R最高（73.8%），Gemini 3 Flash最低（13.3%）。

| 模型 | 被欺骗率 (%) |
| :--- | :--- |
| Ministral-3R | 73.8 |
| GLM-4.6V-Flash | 73.3 |
| DeepSeek V4 Pro | 51.6 |
| Claude Sonnet 4.6 | 49.8 |
| Claude Opus 4.7 | 47.6 |
| Gemini 3.1 Pro | 40.4 |
| o4-mini | 28.4 |
| GPT-5.4 | 20.9 |
| Gemini 3 Flash | 13.3 |

消融实验揭示了反直觉发现：推理机制不仅未提升鲁棒性，反而使Qwen3.5-9B的被欺骗率从38.7%上升至56.9%（+18.2pp），GLM-4.6V-Flash从71.6%上升至80.4%（+8.9pp）。这表明模型在推理过程中倾向于“自我说服”，将虚假证据合理化。防御机制评估显示，怀疑提示（D1）在闭源模型上平均恶化被欺骗率24pp，而跨文档过滤（D3）在 $\tau=4$ 时虽能捕捉90%的虚假品牌，但会抑制63%的合法推荐。

| 防御机制 | 平均被欺骗率 (%) | 合法推荐抑制率 (%) |
| :--- | :--- | :--- |
| 基线 | 43.0 | 0.0 |
| D1 (怀疑提示) | 53.0 | - |
| D3 ($\tau=4$) | 63.0 | 63.0 |

评估边界方面，FORGE基准仅覆盖中文主实验和英文复现，未涉及多语言混合或动态SEO排名变化。可复现性上，论文提供了代码和固定证据束，但真实GEO攻击中的动态内容生成未被模拟。

## 关联研究分析

从问题动机看，本文与ItemRAG等检索增强生成方法形成对比。ItemRAG假设检索质量直接影响推荐效果，而本文揭示检索环节本身成为攻击向量。当检索结果被污染时，ItemRAG的“增强”机制反而放大了虚假信息的传播，因为LLM将检索到的虚假品牌视为高置信度证据。这种差异源于任务特性：ItemRAG优化准确性，而本文评估鲁棒性，前者假设证据可信，后者假设证据对抗。

从方法设计看，本文与RecZero等推理增强方法存在根本冲突。RecZero通过强化学习优化推理过程以提升长期目标对齐，假设推理能提升决策质量。然而，本文实验证明在对抗场景下，推理导致模型过度依赖证据而非先验，从而更容易被虚假社会证明说服。这一冲突暗示，推理机制的价值高度依赖于输入数据的可信度，在干净数据上提升性能，在污染数据上加剧漏洞。

## 总结

本文核心矛盾在于LLM推荐器对开放Web内容污染的脆弱性，现有方法因假设输入干净而失效。本文通过FORGE基准量化了这一漏洞，发现推理机制反而加剧被欺骗率，且简单防御机制无法平衡安全性与可用性。实验证明Top-3污染下被欺骗率高达73.8%，单页污染即可导致27%的失败。本文边界在于模拟攻击的静态性，未覆盖动态SEO排名变化和真实GEO操作者的多策略组合。当攻击者注入的虚假页面数量超过模型跨文档过滤阈值时，现有防御机制是否仍能保持对合法推荐的低抑制率，论文未给出回答。
