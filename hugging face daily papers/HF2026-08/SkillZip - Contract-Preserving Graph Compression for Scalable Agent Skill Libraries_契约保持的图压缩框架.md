> 代理技能库在规模扩张后面临检索粒度失配与上下文预算冲突的双重困境。现有方法将技能作为不可分割的包进行检索，或在压缩时丢失执行契约，导致上下文冗余或执行失败。本文提出 SkillZip，通过章节级程序图与契约保持的宏压缩，在库层面实现持久化可执行压缩。该框架在检索精度与结构保真度上显著优于基线，但其对静态契约定义的依赖限制了在开放环境中的适应性。

## 研究背景

当代理执行复杂任务时，其依赖的程序性知识往往分散在多个技能包中，且存在大量重叠的子过程。这种重叠导致整包检索时加载了大量无关上下文，而简单的文本压缩又可能模糊前置条件或验证器钩子，使得压缩后的技能在执行时出现依赖断裂。解决这一矛盾需要一种既能暴露内部复用结构，又能保证执行契约完整性的表示单元。

技能库的规模化使得“相关性-效用差距”成为核心瓶颈。主流路线如 SkillDAG 采用图结构路由，但仅在检索后构建执行图，库本身仍为文档式存储，导致重复子过程在每个任务中被重新发现与验证。文本压缩路线如 SkillReducer 虽降低了 Token 开销，但保留了文本语义而非执行契约，无法保证压缩后的子图在依赖闭合与验证器可达性上的完整性。SkillZip 的切入点在于将操作粒度从“技能包”下沉至“带契约的章节”，并在库层面预先压缩为可逆的宏节点，使检索、压缩与执行针对同一对象。

## 核心方法

### 章节级程序图构建

传统技能检索以包为单位，无法区分包内不同功能段落的复用价值。SkillZip 引入 Sec2Graph 机制，将每个技能包分解为类型化的章节节点，每个节点携带执行角色、输入输出签名、资源依赖及验证条件。这一设计解决了整包检索导致的“复用粒度失配”，使系统能够仅加载任务所需的共享子过程，而非整个技能包。章节节点通过类型化依赖边连接，形成程序技能图，其中依赖边明确标记了“需要”、“绑定”、“验证”等关系，确保了子图在执行时的依赖闭合性。

### 契约保持的宏压缩

在章节图基础上，MotifZip 执行契约保持的压缩。其核心在于仅当重复子图的边界签名、依赖闭合、验证器可达性及源扩展性均被保留时，才将其提升为可移植的宏节点。宏节点 $M_g: I_g \Rightarrow O_g$ 压缩了连接子图 $g=(V_g, E_g)$，其展开规则 $M_g \Rightarrow (V_g, E_g, \chi_g)$ 保证了压缩的可逆性。这一机制解决了文本压缩中“语义接近但契约不等价”的问题，例如两个相似的加载子过程若连接不同的验证器，MotifZip 会阻止其合并，从而避免执行时的逻辑冲突。

### 执行感知的增量维护

静态压缩无法适应技能库的动态演化。ReZip 机制利用执行轨迹证据增量更新宏字典。当新技能引入重复子过程时，ReZip 将其匹配至现有宏或提升为新的宏；当执行轨迹显示某宏频繁触发验证失败或下游修复时，ReZip 会增加其水合细节、拆分或退役该宏。这一设计解决了“一次性压缩器无法识别后期才变得可复用的子过程”的问题，使压缩结构随执行证据积累而动态调整，保持了压缩库与执行现实的对齐。

## 实验评估

实验在 SkillsBench 与 ALFWorld 上进行，基线包括 SkillDAG（图检索）、Text Compression（文本压缩）及 Raw Graph（原始图）。SkillZip 在 SkillsBench 上实现了 3.46 倍的压缩比，同时保持了 99.2% 的依赖保持率（DPR）和 98.7% 的验证器可达性（VR）。在 ALFWorld 上，SkillZip 较 SkillDAG 提升了 12.2 点的任务成功率。

| 组件变体 | Ret@1 (%) | Token 数 | DPR (%) | VR (%) |
| :--- | :--- | :--- | :--- | :--- |
| Full SkillZip | 73.6 | 1,941 | 99.2 | 98.7 |
| w/o MotifZip | 71.8 | 2,967 | 100.0 | 100.0 |
| w/o dependency closure | 72.1 | 1,653 | 82.3 | 92.6 |
| w/o verifier constraint | 72.8 | 1,668 | 94.9 | 76.4 |

消融实验显示，移除依赖闭合约束导致 DPR 从 99.2% 降至 82.3%，移除验证器约束导致 VR 从 98.7% 降至 76.4%，表明契约保持是压缩有效性的关键。移除全局章节救援使 Ret@1 降至 68.2%，说明局部扩展可能遗漏有用章节。禁用自适应水合虽保持 DPR 和 VR，但 Token 使用量增加 33.3%，验证了按需展开的必要性。

评估边界方面，论文未报告置信区间，且未与 RL 类基线（如 Skill1）直接对比任务成功率。代码未公开，超参数细节有限，可复现性依赖对章节分解自动化程度的假设。

## 关联研究分析

从问题动机看，SkillZip 与 SkillDAG 均关注依赖感知检索，但 SkillDAG 在检索后构建执行图，而 SkillZip 在库层面预压缩。这一差异源于 SkillZip 对“持久化可执行压缩”的追求，旨在避免重复子过程在每个任务中被重新发现。然而，预压缩是否牺牲了动态任务对非标准路径的适应性，论文未给出回答。

从方法设计看，SkillZip 借鉴了图压缩领域的 MDL 与语法替换技术，但引入了“契约保持”的新约束。与 SkillReducer 等文本压缩方法相比，SkillZip 保留了执行接口与验证钩子，而非仅优化 Token 预算。这一设计解决了文本压缩中“语义接近但契约不等价”的失效，但依赖于静态契约定义，在开放环境中可能面临契约演化挑战。

## 总结

SkillZip 解决了技能库规模化后的检索粒度失配与上下文预算冲突矛盾。其切入点在于将操作粒度下沉至带契约的章节，并在库层面实现持久化可执行压缩。通过 Sec2Graph、MotifZip 与 ReZip 机制，SkillZip 在 SkillsBench 上实现了 3.46 倍压缩比与 99.2% 依赖保持率。其边界在于对静态契约定义的依赖，以及未与 RL 类基线的直接对比。当技能库中的子过程契约随执行反馈动态演化时，预压缩的宏节点如何保持与执行现实的对齐，论文未给出回答。
