作者：Haoning Wang、Mingxun Zhang、Chenyue Yu 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.07346)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.07346)

> 智能体评估长期受困于基准与执行框架的强耦合，导致无法区分模型能力与脚手架效应。现有基础设施或依赖侵入式适配器破坏轨迹保真度，或缺乏端到端编排能力。A2E 通过 Agent Task Protocol (ATP) 解耦基准与框架，结合 OpenTelemetry 标准化轨迹采集与生命周期对齐评估，实现了轻量级、无侵入的 Harness 级审计。该方案在工程上验证了框架对性能的独立影响，但其评估指标的可扩展性边界及跨模型泛化能力仍存疑。

## 研究背景

当智能体在动态环境中执行多步任务时，其最终输出正确性往往掩盖了中间推理、工具调用及状态管理中的系统性缺陷。这种“结果导向”的评估盲区源于智能体系统架构的复杂性：底层大语言模型（LLM）仅负责生成，而系统提示、工具接口、上下文管理及执行策略由外部执行框架（Harness）决定。Harness 并非简单的代码包装器，它直接干预了模型的决策路径与资源消耗，使得仅评估模型参数无法反映部署系统的真实能力。

当前评估基础设施面临严重的碎片化困境。Inspect AI 等系统虽支持基准编排，但通过特定适配器集成外部 Harness 时，可能修改生成参数或调用路径，导致轨迹保真度下降且维护成本高昂；Phoenix 等基于 OpenInference 的系统提供了标准化观测，却缺乏任务编排与结果验证能力，需用户自行整合。这种“编排”与“观测”的割裂，使得跨基准、跨框架的横向对比难以复现。A2E 的切入点在于构建一个最小侵入的底层基座，通过协议解耦与标准化追踪，将基准执行、轨迹采集与多维评估统一在单一栈中，从而量化 Harness 对智能体行为的独立贡献。

## 核心方法

### 方法参照系

智能体评估通常遵循“基准加载-代理执行-结果评分”流程，但传统方法将基准逻辑与框架逻辑混同于适配器中。A2E 的关键差异在于引入中间协议层，将“任务定义”与“执行实现”彻底分离，并基于执行生命周期而非单一结果进行指标注册。

### Agent Task Protocol (ATP)

ATP 位于 Task Layer，旨在消除基准与 Harness 之间的成对适配需求。其核心对象包括 `TaskInput`（存储指令、状态、预期输出）、`AgentBinding`（提供工具模式与提示构建）及 `AgentRunner`（执行任务并返回 `TaskTrace`）。通过 ATP，基准适配器只需生成标准任务对象，而 Harness 适配器负责将其映射为原生框架调用，二者通过统一接口交互。这种解耦使得新增基准或框架仅需编写单向适配器，避免了 $O(M \times N)$ 的成对集成复杂度。ATP 并非网络协议，而是内部软件接口，其设计动机是解决现有框架中基准特定设置细节与实验流水线耦合导致的维护瓶颈。

### Lifecycle-Aligned Evaluation

评估层将指标注册到特定的执行阶段与细粒度维度，而非仅关注最终答案。评估维度分为过程级（推理、行动）、结果级（答案正确性、任务完成）及生命周期级（效率、安全）。对于每个 Harness $h$ 在基准 $B$ 上的表现，A2E 计算综合得分 $Q_h$，该得分基于归一化后的成功率 $\hat{S}_h$ 与 Token 消耗 $\hat{T}_h$ 到“甜点”（高准确率、低消耗）的距离：

$$ Q_h = 1 - \sqrt{\frac{\hat{T}_h^2 + (1 - \hat{S}_h)^2}{2}} $$

该公式量化了性能与效率的帕累托权衡。此外，Monitor Layer 基于 OpenTelemetry Span 记录执行轨迹，将框架特定的模型调用、工具执行映射为语义化的 Span 树，保留了操作的因果结构与时间边界，使得评估器能区分“规划错误”与“执行错误”，并支持基于数据库的增量评估，无需重跑代理即可应用新指标。

## 实验评估

实验在 23 个基准与 9 种 Harness（如 LangGraph, CrewAI, Agno）的网格上进行，使用 GLM-5.2 作为统一 API 模型以隔离框架效应。基线覆盖主流开源框架，但未包含无 Harness 的纯模型基线，限制了框架贡献的绝对量化。

| 维度 | LangGraph (成功) | CrewAI (失败) |
| :--- | :--- | :--- |
| 正确性得分 | 1.0 | 0.0 |
| 总 Token 消耗 | 10,122 | 96,704 |
| LLM 调用次数 | 4 | 9 |
| 工具调用次数 | 3 | 5 |
| 成本 (USD) | 0.0051 | 0.0430 |

在 τ3-bench 同一任务上，LangGraph 以 10,122 tokens 完成任务，而 CrewAI 消耗 96,704 tokens 且失败，Token 消耗差异达 9.6 倍。这一极端案例揭示了框架在状态管理与策略选择上的巨大方差。跨基准分析显示，成功率差距在 GDPVal 达 0.20，MMLU-Pro 达 0.30，τ3-bench 达 0.66。正确性指标在 9 个 Harness 间的跨度仅为 0.57–0.68，而规划（plan_hall 0.28–0.84）与工具使用（tool_inv 0.12–0.91）指标跨度显著更大，证明仅看最终结果会掩盖框架间的实质性差异。

评估边界受限于固定模型（GLM-5.2）下的框架对比，未验证不同模型对框架敏感性的差异。代码已开源，但 23 个基准的具体版本与采样种子（默认 40 任务）在文中未完全列出，复现时需严格对齐数据集版本。

## 关联研究分析

从问题动机看，A2E 与 AgentCompass 均致力于解决评估碎片化，但 A2E 更强调“最小侵入”与轨迹保真度。AgentCompass 侧重模块化脚本组合，而 A2E 通过 ATP 协议在底层解耦，避免了适配器对原生执行路径的修改。这一差异源于 A2E 对“Harness 效应”的量化需求：若适配器改变了生成参数，框架间的性能差异将无法归因于框架逻辑本身，而是混杂了接口适配的噪声。

从方法设计看，A2E 与 CORE 在过程评估上形成互补。CORE 侧重利用确定性有限自动机对动作路径进行算法级标注，而 A2E 侧重基础设施层面的标准化轨迹采集与多维指标注册。A2E 的 Lifecycle-Aligned Evaluation 提供了指标的组织框架，但缺乏 CORE 那样的细粒度路径验证算法。A2E 的 Span 树结构虽保留了因果关系，但其评估指标（如 plan_goal_alignment）仍依赖 LLM-as-Judge，可能存在评判偏差，而 CORE 的自动机方法在逻辑一致性上更具确定性。

## 总结

A2E 解决了智能体评估中基准与框架耦合导致的不可复现性与归因模糊问题。通过 ATP 协议解耦与 OpenTelemetry 标准化轨迹，它实现了轻量级的 Harness 级审计，证明了框架选择对性能与效率的独立影响（如 τ3-bench 上 9.6 倍的 Token 差异）。然而，其实验局限于单一模型（GLM-5.2），且评估指标的可扩展性依赖于 LLM 评判的准确性。当模型能力显著提升时，框架间的性能方差是否会收敛至统计噪声水平，从而使得基于框架的优化边际收益递减，A2E 未提供跨模型梯度的验证数据。
