# HuggingFace最新推荐论文 ｜ClawGym II: Exploring Black-Box RL on Agent Harness ｜黑盒智能体强化学习

研究机构：中国人民大学

作者：Huatong Song、Fei Bai、Ming Yang 等 20 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.16798)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.16798)

> 通用智能体在长程任务中依赖复杂的执行框架（Harness）进行工具调用与状态管理，但现有强化学习（RL）方法多假设轨迹完整且环境白盒，难以直接适配不透明、碎片化的黑盒执行流。本文切入点在于将 Harness 视为黑盒引擎，通过前缀树重构碎片化调用并引入混合 Harness 训练，实现策略优化与执行逻辑的解耦。该框架在 Qwen3-30A3B 上验证了黑盒 RL 的稳定性与有效性，但其对辅助轨迹的丢弃策略及跨 Harness 泛化的理论边界仍存疑。

## 研究背景

当智能体在复杂工作区执行长程任务时，模型不再直接操作环境，而是通过 Harness 这一中间层协调工具调用、上下文压缩与错误重试。Harness 将模型动作 $a_t$ 转化为环境状态更新 $(W_{t+1}, o_{t+1}, c_{t+1}) = \mathcal{H}(W_t, c_t, a_t)$，使得交互轨迹由模型与 Harness 共同决定。这种黑盒特性导致模型调用呈现碎片化、分叉与冗余特征，传统基于完整轨迹的 RL 算法无法直接处理这种非结构化数据，且推理引擎与训练引擎间的数值差异会引入 Off-policy 偏差，破坏训练稳定性。

主流 Agentic RL 路线如 AgentRL 与 VeRL 侧重于异步解耦与资源调度，假设轨迹在生成过程中是连续且可完整捕获的。然而，在生产级 Harness（如 Claude Code、OpenClaw）中，内部控制流不透明，模型调用被上下文管理、子智能体调度与故障重试机制切割，导致直接优化这些碎片化调用会破坏长程依赖结构并重复训练共享历史。本文针对这一“黑盒轨迹重构”与“训练-推理一致性”的核心矛盾，提出统一框架，旨在不修改 Harness 内部逻辑的前提下，实现通用智能体的稳定优化。

## 核心方法

### 方法参照系

标准 Agentic RL 流程假设模型与环境交互产生完整轨迹 $\tau$，直接基于 $\tau$ 计算优势函数并更新策略。本文的关键差异在于：Harness 作为黑盒，仅暴露离散的模型调用 $(x_i, y_i)$，而非连续轨迹，且调用间存在共享前缀与分支结构，需先重构为可训练的多轮轨迹。

### 前缀树轨迹重构

针对碎片化调用导致的结构破坏，本文在 Serving Proxy 拦截所有模型调用后，构建 Rollout 级前缀树 $T$。每个调用 $x_i$ 挂载到累积历史构成其最长前缀的节点上，恢复 Harness 引入的非模型内容（如工具输出）。根到叶路径定义候选轨迹，通过过滤死叶（重试产生的无效分支）、丢弃过度分叉任务（防止噪声信号）及排除辅助轨迹（子智能体/压缩轨迹，避免奖励广播歧义），保留主智能体有效轨迹。该设计解决了直接优化碎片调用导致的重复训练与信用分配模糊问题，确保梯度更新仅作用于主任务解决路径。

### 树结构策略优化与一致性保持

在重构后的树结构上，本文适配 PPO 与 GRPO 进行优化。对于 GRPO，优势函数基于组内奖励归一化：

$$ \hat{A}_i = \frac{R_i - \mu_q}{\sigma_q + \epsilon}, \quad \mu_q = \frac{1}{G}\sum_{j=1}^{G} R_j, \quad \sigma_q = \sqrt{\frac{1}{G}\sum_{j=1}^{G}(R_j - \mu_q)^2} $$

该公式利用组内相对奖励消除价值函数估计偏差，适用于黑盒场景下难以获取精确状态价值的情形。为消除推理引擎 $\pi_{rollout}$ 与训练引擎 $\pi_{old}$ 间的数值差异，引入 Token 级重要性采样校正：

$$ w_t = \min\left(\exp\left(\log \pi_{old}(a_t|s_t) - \log \pi_{rollout}(a_t|s_t)\right), \bar{c}\right) $$

此机制通过截断阈值 $\bar{c}$ 平衡偏差与方差，确保训练序列与生成序列在 Token 层面严格一致，防止 Off-policy 偏差导致训练崩溃。

## 实验评估

实验基于 ClawGym-Bench 与 PinchBench，使用 Qwen3-30A3B 作为骨干，对比 OpenClaw 与 Claude Code 两种 Harness 下的黑盒 RL 效果。基线覆盖单 Harness 训练模型，但未对比白盒 SOTA 方法（如 Stronger-MAS）或纯 SFT 基线，限制了横向可比性。

| 方法 | 骨干 | Harness | ClawGym-Bench Pass@1 提升 | PinchBench Pass@1 提升 |
| :--- | :--- | :--- | :--- | :--- |
| ClawII-OC-30A3B | Qwen3-30A3B | OpenClaw | +9.98 | +11.71 |
| ClawII-CC-30A3B | Qwen3-30A3B | Claude Code | +14.81 | +17.28 |

Claude Code 下的提升幅度显著高于 OpenClaw，表明 Harness 复杂度与任务类型对 RL 增益有显著影响。混合 Harness 训练模型性能达到或超越单 Harness 模型，验证了跨环境联合优化的有效性。

消融实验显示，前缀树过滤策略（丢弃死叶与过度分叉）对训练稳定性至关重要，但论文未量化各过滤规则对最终性能的独立贡献。混合 Harness 训练在 JobBench 与 OfficeQA 上保持一致增益，但未报告计算开销对比，无法评估其相对于单 Harness 训练的样本效率。

评估协议采用代码验证与 Rubric 评分混合，Rubric 部分依赖 GPT-5.4 作为裁判，存在评估器偏差风险。论文未提供代码与超参数细节，且未报告置信区间，数值比较需谨慎。黑盒 RL 的泛化性仅在特定 Harness 组合上验证，缺乏在未见 Harness 上的测试。

## 关联研究分析

从轨迹处理看，本文与前缀树构建方法（如 Tree-GRPO）不同，后者针对白盒环境中的树搜索扩展，而本文处理黑盒 Harness 导致的被动分叉与冗余。Tree-GRPO 假设模型主动探索生成树结构，而本文的树结构是 Harness 执行逻辑的副产品，需通过过滤机制提取有效信号。这一差异源于任务特性：白盒环境中模型控制探索路径，黑盒环境中 Harness 控制执行流，导致轨迹结构不可控。

从优化目标看，本文与 CoPRIS 均处理 Off-policy 偏差，但 CoPRIS 通过并发控制部分 Rollout 实现，而本文通过 Token 级重要性采样校正。CoPRIS 侧重系统级吞吐量优化，本文侧重算法级一致性保持。混合 Harness 训练与多智能体协同（如 Stronger-MAS）存在本质区别：前者是单模型在多环境下的联合优化，后者是多模型协作解决单一任务。Mix-Harness 是否等价于多智能体协作的理论依据不足，其增益可能源于环境多样性而非协作机制。

## 总结

本文核心矛盾在于黑盒 Harness 的碎片化调用与 RL 算法对完整轨迹的依赖。切入点在于将 Harness 视为不透明执行引擎，通过前缀树重构与 Token 级一致性校正实现解耦优化。方法上，构建前缀树恢复交互结构，适配 PPO/GRPO 并引入重要性采样校正。实验证明在 Qwen3-30A3B 上，黑盒 RL 在 ClawGym-Bench 提升 9.98-14.81 点，且训练稳定。边界在于辅助轨迹被完全丢弃，可能丢失子智能体协作的潜在信号；混合 Harness 训练的泛化性仅在同构任务上验证。当 Harness 引入更复杂的动态子智能体调度时，前缀树过滤策略是否会导致关键探索信号丢失，论文未给出回答。
