# HuggingFace最新推荐论文 ｜DataSpace: Benchmarking Data Agents for Verifiable Analytics over Heterogeneous Workspaces ｜异构工作区数据智能体基准

研究机构：清华大学

作者：Boyan Li、Zhuowen Liang、Yupeng Xie 等 14 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.03451)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.03451)

> 数据智能体在真实组织环境中需从分散于数据库、长文档及视频中的异构证据生成完整分析结果，但现有基准多局限于单一模态或片段式答案，无法验证智能体跨模态对齐与完整表格输出的能力。DataSpace 通过执行接地的构建流水线将 Text-to-SQL 实例转化为包含六种模态的跨语言工作区，强制智能体返回可确定性验证的完整表格结果。该基准揭示了多模态集成与连接操作是当前模型的主要瓶颈，但其固定智能体接口的评估协议是否掩盖了特定架构对异构数据的适配优势，仍存疑。

## 研究背景

当智能体面对一个包含 SQLite 数据库、90 页 PDF 报告及 8 分钟视频的工作区时，它必须自主发现数据源、对齐实体与单位，并执行多步计算以生成完整表格。这一过程涉及工作区发现（Workspace Discovery），即从预定义文件中识别相关证据；以及跨模态对齐（Cross-Modality Alignment），即统一不同格式（如视频中的阈值与数据库中的数值）的语义表示。若缺乏对完整内存状态的感知，智能体易基于错误假设继续执行，导致“静默失败”。

现有基准如 Spider 2.0 聚焦企业级 SQL 工作流，但预定义了相关数据库；LongDA 评估长文档导航，但输出多为事实性短答案。这些设置未能统一异构证据发现、完整表格输出契约与确定性评估语义。DataSpace 的切入点在于将任务契约固定为“完整表格结果”，要求智能体在跨语言、多模态工作区中自主整合证据，并通过执行 SQL 生成参考答案，填补了从片段生成到完整结果验证的评估空白。

## 核心方法

### 任务形式化与评估协议

DataSpace 将数据智能体任务形式化为工作区求解器：给定自然语言问题 $q_i$ 和任务局部工作区 $W_i$，智能体需返回完整表格结果 $\hat{Y}_i$。工作区 $W_i$ 包含结构化工件 $W_i^{str}$（CSV, JSON, SQLite）、文档工件 $W_i^{doc}$（Markdown, PDF）及媒体工件 $W_i^{med}$（视频）。评估采用确定性协议，通过语义感知的列对齐与值规范化，确保等价表示被接受而错误输出被拒绝。

$$
b_i = (x_i, Y_i, c_i), \quad s_i = 1[\hat{Y}_i \equiv_{c_i} Y_i]
$$

该公式定义了任务记录 $b_i$ 及二元得分 $s_i$，其中 $c_i$ 为评估配置，$\equiv_{c_i}$ 表示在配置 $c_i$ 下的等价性。配置 $c_i$ 记录每列的语义类型、数值精度及行序要求，确保评估不依赖 LLM 裁判，实现客观接地。

### 执行接地的基准构建流水线

DataSpace-Builder 通过四阶段流水线将 Text-to-SQL 实例转化为异构工作区任务。首先，跨语言转换（Cross-Language Transformation）联合迁移问题、数据库状态及可执行 SQL，确保实体名称在问题与数据中一致。其次，约束感知关系采样（Constraint-Aware Relational Sampling）保留主键、外键及谓词值，生成任务局部数据库 $D_s$ 并通过执行 SQL 获取候选参考答案 $Y_s$。

$$
D_s = \text{Sample}(D_c; \psi, C_s), \quad Y_s = \text{Exec}(D_s, \sigma_c)
$$

该公式描述了采样策略 $\psi$ 与保护集 $C_s$ 如何生成任务局部数据库 $D_s$，并通过执行转换后的 SQL $\sigma_c$ 获得参考答案 $Y_s$。保护集 $C_s$ 包含从 SQL AST 提取的谓词值与边界值，防止采样破坏连接路径或条件有效性。最后，模态路由与工件渲染（Modality Routing & Artifact Rendering）将表格数据渲染为 CSV、PDF 或视频，其中视频通过证据原子（Evidence Atoms）从 SQL 与结果中推导，实现查询条件到视觉场景的映射。

## 实验评估

实验设置涵盖六个前沿多模态模型（Grok 4.5, GPT-5.6 Sol 等）及五个智能体框架（Grok Build, Claude Code 等），基线覆盖通用 LLM 与专用智能体框架，但缺失 Data Interpreter 等专用数据科学智能体的直接对比，因其接口不兼容视频输入与表格输出契约。

| 方法 | 年份 | Task Accuracy (%) |
| --- | --- | --- |
| Grok 4.5 | 2026-07 | 66.34 |
| GPT-5.6 Sol | 2026-07 | 64.63 |
| Kimi K3 | 2026-07 | 53.41 |
| MiMo-V2.5 | 2026-04 | 39.27 |
| Claude Sonnet 5 | 2026-06 | 32.93 |
| MiniMax M3 | 2026-06 | 28.54 |

Grok 4.5 在 DataSpace-Agent 固定框架下取得最高准确率 66.34%，显著领先于 MiniMax M3 的 28.54%。固定 MiMo-V2.5 时，Grok Build 框架达到 46.34%，而 Smolagents 仅为 30.98%，显示框架选择产生 15.36 个百分点的差距。

消融分析显示，多模态任务在所有骨干模型上均比单模态任务低 1.8–14.0 个百分点，连接操作（Join）导致准确率下降 9.7–19.8 个百分点。Grok 4.5 的 136 个失败案例中，52.2% 源于答案物化错误（如列缺失或多余），22.8% 源于任务意图误解。这些发现表明，跨模态集成与关系计算是当前模型的主要瓶颈，而非单一模态理解能力。

评估边界方面，DataSpace 包含 410 个任务，规模较小可能导致方差较大；评估协议固定智能体接口，未探索不同架构对异构数据的适配差异；代码与数据集已开源，但视频渲染与专家审查流程的复现成本较高。

## 关联研究分析

从问题动机看，DataSpace 与 DataCross 均关注跨模态异构数据，但 DataCross 强调“僵尸数据”激活与洞察生成，评估维度包括事实性、完整性与洞察性；DataSpace 则强制“完整表格”输出，评估更偏向工程验证而非开放探索。这一差异源于任务特性：DataSpace 源自 Text-to-SQL 实例，天然具备确定性参考答案，而 DataCross 面向开放式分析，缺乏统一输出契约。DataSpace 的确定性评估协议是否限制了智能体在模糊任务中的表现，论文未给出回答。

从方法设计看，DataSpace 与 Spider 2.0 均基于 SQL 工作流，但 Spider 2.0 预定义相关数据库，而 DataSpace 要求智能体自主发现证据源。DataSpace 通过约束感知采样保留关系完整性，避免了 Spider 2.0 中常见的连接路径断裂问题。然而，DataSpace 的视频渲染依赖 SQL AST 推导证据原子，可能遗漏非结构化视频中的隐含信息，这一局限在跨模态对齐中尤为突出。

## 总结

DataSpace 旨在解决异构工作区中智能体生成完整可验证表格结果的评估缺失问题。其切入点在于将 Text-to-SQL 实例转化为多模态工作区，通过执行 SQL 生成参考答案，实现确定性评估。该基准包含 410 个跨语言任务，最佳模型 Grok 4.5 达到 66.34% 准确率，揭示多模态集成与连接操作是主要瓶颈。其边界在于固定智能体接口，未探索架构对异构数据的适配差异，且任务规模较小。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
