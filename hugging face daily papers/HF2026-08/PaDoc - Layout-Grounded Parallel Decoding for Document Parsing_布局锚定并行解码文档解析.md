研究机构：清华大学

作者：Hao Yu、Jiabo Zhan、Kang Liu 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2608.06146)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.06146)

> 文档解析旨在将页面图像转化为保留阅读顺序与语义的结构化数据，但主流端到端视觉语言模型（VLM）将布局与内容串行化为单一自回归序列，导致解码深度随区域内容总量线性增长，严重制约推理效率。现有解耦式方法虽暴露区域级并行性，却因裁剪区域并重复视觉编码而割裂页面全局上下文。PaDoc 通过前缀条件分解，在共享页面图像前缀上构建布局分支结构，实现单模型内的并行解码。该方法在保持顶级解析精度的同时，将吞吐量提升 67.4% 至 118%，但其在极端复杂版式下的鲁棒性边界尚待验证。

## 研究背景

文档解析的核心挑战在于平衡结构重建精度与推理效率。当 VLM 采用自回归解码时，因果注意力机制强制模型在生成下一个布局区域前必须完成当前区域的全部内容，这种人工序列依赖使得解码路径长度等于所有区域内容长度之和。为打破此瓶颈，研究者引入条件互信息框架，通过区域特定内容充分性假设与裁剪充分性假设，论证了区域间内容在给定页面图像与局部布局下的独立性，从而为并行解码提供了理论依据。

主流端到端解析方法如 Donut 与 Nougat 虽统一了输出空间，却继承了串行执行语义，在密集表格或长文本页面上效率骤降。解耦式流水线如 Dolphin-v2 与 PaddleOCR-VL-1.5 通过布局引导实现区域级并行，但裁剪操作导致视觉上下文碎片化，且重复的视觉预填充增加了数据移动开销。PaDoc 的切入点在于保留完整页面图像作为共享视觉前缀，仅通过改变布局前缀长度来区分不同内容分支，从而在单模型内同时实现全局上下文保留与区域级并行解码。

## 核心方法

### 前缀条件分解

文档解析的目标分布可分解为布局预测与内容识别两个因子。传统裁剪式两阶段方法将内容条件设为区域裁剪图像 $X_k$，导致视觉前缀无法复用。PaDoc 将条件替换为共享前缀 $(X, B_{\le k})$，其中 $X$ 为完整页面图像，$B_{\le k}$ 为截至当前区域的布局前缀。这一改动消除了裁剪带来的预处理开销，使所有内容分支共享同一视觉编码，仅布局前缀长度不同。

$$
p^*(b_{1:N}, y_{1:N} | x) = \prod_{k=1}^{N} p^*(b_k | x, b_{<k}) \prod_{k=1}^{N} p^*(y_k | x, b_{\le k})
$$

该公式表明，布局流与内容分支在相同前缀下可并发解码，逻辑解码深度从所有区域内容长度之和降至最长布局-内容路径。

### 祖先注意力与打包变长实现

为实现上述分解，PaDoc 构建有向无环图，其中布局节点 $B_k$ 的祖先集为 $\{X, B_{<k}\}$，内容节点 $Y_k$ 的祖先集为 $\{X, B_{\le k}\}$。训练时，每个节点仅关注其祖先及自身因果历史，防止内容节点泄露至未来布局或兄弟内容。直接实现祖先掩码需存储 $S \times S$ 稠密张量，无法利用 FlashAttention。PaDoc 将其转化为变长因果注意力问题：布局流为单一因果序列，内容分支 $Y_k$ 的查询关注虚拟键值序列 $[X, B_{\le k}, Y_k]$，仅收集共享前缀的键值行，避免二次方掩码存储。

$$
\text{Anc}(Y_k) = \{X, B_{\le k}\}, \quad \text{Anc}(B_k) = \{X, B_{<k}\}
$$

该注意力模式在标准下一 token 训练目标下复现了并行图结构，无需辅助预测头或损失函数，使单模型训练与并行推理在架构上统一。

## 实验评估

实验在 OmniDocBench v1.6 的 1,651 页上评估布局分析与端到端解析质量，并在 384 页子集上测试单 A800 GPU 下的服务效率。基线覆盖 Dolphin-v2、PaddleOCR-VL 1.5、MinerU2.5-Pro 等解耦系统，以及 Qianfan-OCR、DeepSeek-OCR-2 等端到端 VLM，但缺失纯检测器基线如 DETR 变体。PaDoc 在端到端组内取得 94.24 Overall 分数，Text Edit 0.038 与 Formula CDM 95.59 均为最佳，布局 F1 达 91.1，精度与解耦系统持平。

| 方法 | 参数量 | Overall | Text Edit | Formula CDM |
| :--- | :--- | :--- | :--- | :--- |
| PaDoc (Ours) | 2.1B | 94.24 | 0.038 | 95.59 |
| PaddleOCR-VL 1.5 | 1.0B | 94.5 | - | - |
| Dolphin-v2 | 3.8B | - | - | - |
| Qianfan-OCR | 4.7B | - | - | - |

效率测试显示，PaDoc 在 16 至 256 并发下均为最快端到端解析器，相比同骨干 Sequential SFT 基线，吞吐量提升 67.4% 至 118%，P95 延迟降低 39.2% 至 54.9%。尽管参数量 2.1B 大于 1.0B 的 HunyuanOCR-1.5，PaDoc 在所有并发级别下均超越其性能，验证了并行解码在质量-效率权衡上的优势。

评估边界方面，论文未报告置信区间，94.24 与 94.5 的微小差距统计显著性未知。代码开源，但 vLLM 后端实现依赖请求级前缀缓存，实际部署中分支长度不均衡可能引入调度开销，论文未提供该场景下的延迟分布细节。

## 关联研究分析

从问题动机看，PaDoc 与 Dolphin-v2 均利用布局引导实现并行，但 Dolphin-v2 依赖裁剪区域独立识别，视觉上下文被割裂；PaDoc 通过共享页面图像前缀保留全局信息，其差异根源在于任务特性：文档解析需捕捉跨区域引用与章节层级，裁剪式方法在此类结构上易产生语义断裂。PaDoc 的共享前缀设计是否足以应对极端复杂版式中的长程依赖，论文未提供消融实验。

从方法设计看，PaDoc 借鉴 APAR 的祖先注意力机制，但将其从文本推理分支迁移至视觉布局分支。APAR 处理抽象树结构，而 PaDoc 需将并行结构锚定在视觉布局实例上，同时共享页面级上下文。这一迁移的关键在于变长实现避免稠密掩码，但论文未对比密集 SDPA 与 Flex Attention 基线的具体性能差距，仅提及附录 C 有比较，主文未展示。

## 总结

PaDoc 解决的核心矛盾是端到端 VLM 的串行解码瓶颈与解耦方法的视觉上下文碎片化。其切入点在于利用条件互信息推导前缀条件分解，在共享页面图像上构建布局分支，使单模型内并行解码成为可能。方法通过祖先注意力与打包变长实现，在标准训练目标下复现并行结构，无需辅助头。实验证明其在 OmniDocBench 上取得 94.24 Overall 与 91.1 布局 F1，吞吐量提升 67.4% 至 118%。边界在于评估未覆盖极端物理畸变场景，且分支长度不均衡下的调度开销未量化。当文档包含大量嵌套表格或跨页引用时，共享前缀的注意力稀释效应是否导致布局预测误差传播至内容分支，论文未给出回答。
