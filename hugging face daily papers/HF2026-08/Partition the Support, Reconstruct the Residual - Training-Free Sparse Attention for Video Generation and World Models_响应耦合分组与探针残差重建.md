# HuggingFace最新推荐论文 ｜Partition the Support, Reconstruct the Residual: Training-Free Sparse Attention for Video Generation and World Models ｜响应耦合分组与探针残差重建

研究机构：美国德州农工大学

论文原文见 [arXiv](https://arxiv.org/abs/2608.18484)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2608.18484)

> 视频生成模型与物理世界模型在处理长时空序列时，二次自注意力成为推理瓶颈，现有训练-free稀疏方法仅关注行级注意力集中度，忽略了查询共享路由时的支持集膨胀与跳过交互的残差误差。本文指出行级稀疏度无法决定可执行块稀疏算子的支持需求，且保留的注意力质量不决定后softmax误差，从而提出SparsePR框架。该框架通过响应耦合分组构建可执行查询与K/V组，并利用少量精确探针行校准调用特定的仿射残差修正。SparsePR在22%-26%的执行对密度下实现了1.48×-2.61×的端到端加速，但其在不同模型架构下的泛化边界及探针预算的最优分配策略尚存疑问。

## 研究背景

视频扩散Transformer（DiT）在处理高分辨率、长时长视频时，时空token序列长度急剧增加，导致自注意力计算复杂度呈二次方增长，成为推理的主要瓶颈。为加速预训练模型，训练-free稀疏注意力方法应运而生，其核心在于不修改模型权重，仅通过动态选择计算块来降低FLOPs。然而，现有方法如SVG2、SVOO等主要依赖语义聚类或交替聚类来组织token，这些方法假设查询在激活空间中的邻近性等同于路由行为的相似性，即邻近的查询需要相似的K/V支持集。这一假设在视频生成任务中往往失效，因为查询的语义邻近性并不保证其在注意力响应几何上的对齐，导致共享路由下的支持集密度远高于单行稀疏度，造成计算资源浪费或精度损失。

稀疏注意力算子的性能不仅取决于保留了哪些交互，还取决于如何处理被跳过的交互。传统方法通常采用硬丢弃（hard drop）或简单的块级近似，忽略了被跳过交互对输出残差的贡献。本文发现，在共享路由场景下，查询分组后的支持集密度（pooled support）显著高于单查询支持密度，且保留的注意力质量（retained mass）与后softmax输出误差之间不存在单调关系。这意味着，仅基于行级注意力集中度或保留质量来设计稀疏策略，无法准确预测稀疏算子的实际误差。因此，需要一种能够同时考虑共享路由支持集膨胀与残差可表示性的稀疏注意力框架，以在有限计算预算下实现高精度的视频生成加速。

## 核心方法

### 块稀疏注意力算子参照系

块稀疏注意力通过将查询和K/V token分组，并选择特定的查询-K/V组对进行精确计算，来实现稀疏性。标准流程包括：构建查询与K/V分区、选择路由策略（即哪些组对需要计算）、以及处理跳过交互的规则。本文的关键差异在于，它不将稀疏性视为行级属性，而是将其视为由分区几何、路由策略和残差处理共同决定的可执行算子属性。现有方法如SVG2使用语义聚类构建分区，SVOO使用交替聚类，但均未显式建模分区几何对残差可表示性的影响，也未利用精确探针行来校准跳过交互的误差。

### 响应耦合分组

响应耦合分组（Response-Coupled Partitioning）旨在构建可执行的查询和K/V组，使得共享路由下的支持集最小化。设计动机是解决语义聚类中查询邻近性不等于路由相似性的问题，即邻近查询可能要求不同的K/V支持集。该方法采用单次非对称耦合路径：首先，从当前注意力调用中采样$M_s$个查询行$Q_s$，定义键响应度量$M_K = Q_s^\top Q_s$。键$k_j$在响应坐标下的表示为$\phi_K(k_j) = F_K^\top k_j$，其中$F_K$是$M_K$的前$r_K$个特征向量，按特征值平方根缩放。对$\phi_K(k_j)$应用k-means聚类得到配对的K/V组$G_{KV}$。接着，计算每个K/V组在原始键空间中的质心，中心化后堆叠为$\bar{K}$，形成查询响应度量$M_Q = \bar{K}^\top \bar{K} / (C_k d)$。查询$q_i$在响应坐标下的表示为$\phi_Q(q_i) = F_Q^\top q_i / \max(\|F_Q^\top q_i\|_2^2/r_Q, \epsilon)$，其中$F_Q$是$M_Q$的前$r_Q$个特征向量。对$\phi_Q(q_i)$聚类得到查询分区$G_Q$。这种耦合设计确保了查询分组基于其对K/V组的响应几何，而非激活空间的邻近性，从而降低了共享路由下的支持集膨胀。

### 探针拟合残差重建

探针拟合残差重建（Probe-Fitted Residual Reconstruction）旨在修正稀疏输出与稠密输出之间的残差，解决硬丢弃导致的后softmax误差问题。设计动机是保留的注意力质量不决定输出误差，需要直接测量并修正残差。该方法选择$M$个探针查询行（分层采样自查询组），精确计算其稠密注意力输出$O_{dense}^p$和稀疏输出$O_{sp}^p$，得到残差$R_p = O_{dense}^p - O_{sp}^p$。将残差建模为稀疏输出的仿射函数：$R_i \approx b + x_i B$，其中$x_i = O_{sp}^i$。通过加权最小二乘拟合$B_\lambda = \arg\min_B \|W^{1/2}(\bar{R}_P - \bar{X}_P B)\|_F^2 + \lambda\|B\|_F^2$，其中$W$是查询组覆盖权重，$\lambda$是岭回归系数。为防止过拟合，利用探针残差的前$r$个右奇异向量$\Psi_r$限制仿射映射的输出子空间：$\hat{R}_i = \mu_R + \bar{x}_i B_\lambda \Psi_r \Psi_r^\top$。最终输出为$O_i = O_{sp}^i + \hat{R}_i$（非探针行）或$O_{dense}^i$（探针行）。这种在线校准机制无需离线训练，且探针计算开销仅占总延迟的1.1%，实现了高精度的残差修正。

## 实验评估

实验在H100 GPU上使用BF16精度，评估了HunyuanVideo-13B、Wan2.2-I2V-A14B、Cosmos-Predict2.5-14B和Cosmos3-Nano-16B四个模型。基线包括SpargeAttn、SVG2、SVOO和SVG-EAR，覆盖了在线块选择、语义聚类、交替聚类等主流训练-free稀疏路线，但未对比基于蒸馏或端到端训练的稀疏方法（如VSA、VEDA），这可能限制了与训练式方法的公平比较。

## 关联研究分析

从问题动机看，SparsePR与SVG2（Yang et al., 2026）和SVOO（Luo et al., 2026）的核心差异在于对稀疏性本质的理解。SVG2和SVOO假设查询在激活空间中的邻近性足以确定路由行为，因此使用语义聚类或交替聚类构建分区。然而，SparsePR指出，在视频生成任务中，查询的语义邻近性不等于响应几何的相似性，导致共享路由下的支持集膨胀。这一差异源于任务特性：视频时空序列的长程依赖和条件预测机制使得查询的注意力分布高度动态，静态或基于激活的聚类无法捕捉这种动态性。SparsePR通过响应耦合分组直接建模查询对K/V组的响应几何，从而更准确地预测共享路由的支持需求。

从方法设计看，SparsePR与PISA（Li et al., 2026b）和Sol-Attn（Li et al., 2026a）在残差处理上存在根本区别。PISA和Sol-Attn使用块级泰勒展开或路由代理分数来近似跳过交互的贡献，这些方法假设残差具有局部平滑性或可被低阶多项式近似。SparsePR则利用少量精确探针行在线拟合仿射残差映射，不依赖离线训练或局部平滑假设。这种设计使得SparsePR能够适应不同调用中的残差分布变化，尤其适用于条件预测任务中注意力结构随输入变化的场景。然而，探针拟合的计算开销和探针数量的选择可能影响其在超大规模序列上的可扩展性，论文未对此进行详细分析。

## 总结

SparsePR旨在解决视频生成模型中训练-free稀疏注意力的精度-速度权衡问题，其核心矛盾在于行级注意力集中度无法决定可执行块稀疏算子的支持需求与残差误差。现有方法如SVG2和SVOO基于激活空间聚类，忽略了共享路由下的支持集膨胀和残差可表示性，导致在复杂任务中精度损失。SparsePR通过响应耦合分组构建基于响应几何的分区，并利用探针拟合残差重建在线校准跳过交互的误差，从而在22%-26%的执行对密度下实现了1.48×-2.61×的端到端加速，同时保持了接近稠密模型的生成质量。然而，论文仅在四个特定模型上验证了方法的有效性，未探讨探针预算在不同序列长度和注意力头数下的最优分配策略，也未分析响应耦合分组在超大规模时空序列中的计算开销是否会被稀疏加速收益抵消。当序列长度进一步增加时，探针拟合的仿射假设是否仍然成立，论文未给出回答。
