# HuggingFace最新推荐论文 ｜Think Anywhere in Code Generation ｜任意位置思考机制

研究机构：北京大学、阿里巴巴集团

作者：Xue Jiang、Tianyu Zhang、Ge Li 等 11 人

论文原文见 [arXiv](https://arxiv.org/abs/2603.29957)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2603.29957)

> 代码生成中的推理资源分配长期受限于“前置思考”范式，该范式在实现阶段暴露的突发复杂性面前失效，且无法根据局部难度动态调整计算量。本文切入点在于将推理触发点从固定的起始位置解耦至任意Token位置，通过冷启动监督学习建立语法结构，再借助可验证奖励强化学习让模型自主探索最优思考位置。实验表明该机制在四个主流基准上取得同骨干最优，但仅验证了单函数任务，其向仓库级复杂工程的泛化能力仍存疑。

## 研究背景

当大语言模型（LLM）处理复杂算法题时，通常先在内部思维块完成全局规划，再输出代码。这种前置思考（Upfront Thinking）范式假设问题复杂度在规划阶段已完全暴露，但实际编码中，边界条件处理或索引越界等错误往往在实现过程中才显现。由于前置思考无法在代码生成中途插入新的推理步骤，模型只能依赖初始规划，导致逻辑漏洞无法被及时修正。此外，代码各部分的难度分布极不均匀，样板代码与核心算法决策所需的计算资源差异巨大，固定长度的前置思考无法实现按需分配。

现有推理增强方法如思维链（CoT）和交错思考（Interleaved Thinking）试图缓解此问题，但前者仍属前置思考变体，后者虽允许中途思考却强制固定步长交替，引入不必要的计算开销且无法聚焦高难度片段。后训练方法如CodeRL+虽利用执行反馈优化代码，但均沿用前置思考架构，未解决推理位置僵化的根本矛盾。本文针对这一瓶颈，提出THINK-ANYWHERE机制，允许模型在代码生成的任意Token位置基于即时上下文自主触发推理，实现计算资源的动态精准分配。

## 核心方法

### 生成序列形式化定义

本文方法参照系为基于强化学习的代码生成后训练流程，标准做法是在生成代码前完成完整推理轨迹。本文的关键差异在于将推理块嵌入代码序列内部，打破推理与生成的严格时序分离。模型生成混合序列 $\mathbf{y}$，其形式化为：

$$ \mathbf{y} = \langle \text{think} \rangle s \langle / \text{think} \rangle c_{[1]} h_{[1]} c_{[2]} h_{[2]} \dots c_{[M]} h_{[M]} c_{[M+1]} $$

其中 $s$ 为初始思考块，$c_{[i]}$ 为代码段，$h_{[i]}$ 为嵌入代码中的 `<thinkanywhere>` 思考块。最终可执行代码 $c$ 通过移除所有思考块获得。该设计动机在于解除推理位置对生成流程的刚性约束，使模型能根据局部复杂度动态决定何时介入深度思考。

### 冷启动与语义感知初始化

冷启动阶段旨在教会模型触发思考的语法结构，但仅靠监督学习无法让模型判断何处需要思考。为解决多Token分隔符带来的语义歧义与预测路径过长问题，本文引入专用触发Token变体（THINK-ANYWHERE*），并采用语义感知初始化策略。新Token嵌入向量由语义意图与结构角色两部分组成：

$$ \mathbf{e}_{\langle ta \rangle} = \frac{1}{2} \mathbf{e}_{\text{"think anywhere"}} + \frac{1}{2} \mathbf{e}_{\langle \text{im\_start} \rangle} $$

该公式将“任意位置思考”的语义内容与已有分隔符的结构行为融合，使新Token在预训练阶段即具备模式切换边界特性。冷启动分两阶段执行：先冻结模型参数仅训练嵌入层与LM头，再联合LoRA适配器微调。此设计动机在于避免随机初始化Token在有限后训练数据下无法学习有效表征的问题，为后续强化学习提供稳定的语法基础。

### 分层奖励强化学习

冷启动仅建立语法能力，无法让模型自主发现最优思考位置。本文采用组相对策略优化（GRPO）算法，设计分层奖励函数驱动模型探索。奖励函数由结构奖励 $R_{\text{struct}}$ 与正确性奖励 $R_{\text{correct}}$ 门控组合：

$$ R(y) = \alpha R_{\text{struct}} + (1-\alpha) R_{\text{correct}}, \quad \alpha=0.1 $$

其中 $R_{\text{struct}} \in \{0,1\}$ 验证输出是否包含初始思考块及至少一个代码内嵌思考块，$R_{\text{correct}} \in \{0,1\}$ 通过执行测试用例评估功能正确性。该设计动机在于通过低权重的结构约束确保模型保持按需思考行为，同时以高权重的执行结果引导模型发现真正有效的思考位置，避免模型为获取结构奖励而滥用思考块。

## 实验评估

实验基于Qwen2.5-Coder-7B-Instruct骨干，使用14K编程问题训练，评估涵盖HumanEval、MBPP、LeetCode、LiveCodeBench四个基准，采用pass@1指标。基线覆盖推理增强方法（CoT、Self-Planning、Interleaved Thinking）与后训练方法（OlympicCoder、CodeRL+等），但未对比OpenAI o3等前沿闭源模型，因骨干规模差异导致绝对分数不可比。

| 方法 | LeetCode | LiveCodeBench | HumanEval | MBPP | Average |
|---|---|---|---|---|---|
| Base Model | 50.6 | 34.3 | 88.4 | 70.7 | 61.0 |
| GRPO | 67.3 | 36.0 | 88.6 | 81.7 | 68.4 |
| CodeRL+ | 63.3 | 36.9 | 90.9 | 76.2 | 66.8 |
| THINK-ANYWHERE | 69.4 | 37.2 | 91.5 | 82.9 | 70.3 |

THINK-ANYWHERE平均分70.3%，较基线提升9.3%，超越最强后训练基线CodeRL+的66.8%。在LiveCodeBench上，其37.2%的成绩虽远低于领域综述中OpenAI o3的67.60%，但在同骨干下显著优于GRPO的36.0%，验证了动态思考机制在防污染基准上的有效性。

| 消融变体 | Pass@1 | Δ vs. Full |
|---|---|---|
| THINK-ANYWHERE | 69.4 | – |
| Only Cold Start | 47.9 | -21.5 |
| Only RLVR | 63.4 | -6.0 |
| Line-level Thinking | 67.2 | -2.2 |
| No Upfront Thinking | 66.6 | -2.8 |
| Padding Thinking | 67.6 | -1.8 |

消融显示仅冷启动导致性能暴跌21.5%，证明监督学习无法替代强化学习对思考位置的探索；行级思考比Token级低2.2%，验证了任意位置触发的必要性。去除前置思考仅降2.8%，表明主要增益来自代码内嵌思考而非初始规划。Padding Thinking降1.8%但未回退至基线，暗示模型在填充Token时仍进行隐式推理。

评估边界方面，实验仅覆盖单函数任务，未涉及多文件仓库级场景；HumanEval上91.5%的高分可能受数据污染影响，削弱了静态基准的区分度；代码与超参数已开源，使用8块A100 GPU训练，可复现性良好。

## 关联研究分析

从问题动机看，本文与Interleaved Thinking同属交错推理路线，但后者强制固定步长交替，导致简单代码段也消耗推理资源，而本文通过RLVR让模型自主决定触发点，解决了计算资源浪费问题。这一差异源于任务特性：代码生成中难度分布极不均匀，固定步长无法适应局部复杂性波动，而按需触发能精准聚焦高熵位置。

从方法设计看，本文与CodeRL+同属RL后训练框架，但CodeRL+侧重执行语义对齐，奖励函数聚焦代码正确性，而本文引入结构奖励约束思考行为，解决了纯结果奖励下模型可能忽略推理过程的问题。这种设计差异暗示，在代码生成中，推理位置的选择与代码正确性同等重要，仅优化结果无法保证模型具备可解释的决策过程。

## 总结

本文核心矛盾在于前置思考范式无法应对代码实现阶段的突发复杂性，且无法按局部难度分配计算资源。切入点在于将推理触发点解耦至任意Token位置，通过冷启动建立语法结构、RLVR探索最优位置，实现按需思考。实验证明该机制在四个基准上取得同骨干最优，平均分70.3%较基线提升9.3%，且在1.5B小模型上提升达13.9%。边界在于仅验证单函数任务，HumanEval高分可能受污染影响，且专用Token变体因后训练数据有限未完全发挥潜力。当任务扩展至多文件仓库级场景时，任意位置思考机制能否有效处理跨文件依赖与全局上下文，论文未给出回答。
