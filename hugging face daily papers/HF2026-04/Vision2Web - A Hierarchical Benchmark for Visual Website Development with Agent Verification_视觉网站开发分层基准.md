> 多模态编码智能体在端到端网站构建中的评估长期受限于任务碎片化与验证机制缺失，现有基准仅覆盖局部代码修复或静态单页生成，无法诊断长程规划与跨模态推理的系统性缺陷。Vision2Web 通过三级分层任务设计与工作流代理验证范式，将评估从孤立功能点扩展至全栈系统交付。该基准揭示了当前 SOTA 模型在复杂交互与状态管理上的显著性能断层，但其依赖 GUI 智能体进行自我验证的机制引入了新的可靠性风险。

## 研究背景

当编码智能体尝试从 UI 原型生成完整网站时，其核心困境在于视觉布局与功能逻辑的解耦失效。视觉接地（Grounding）要求模型将像素级原型映射为 DOM 结构，而长程规划则需在多页面间维持状态一致性。若接地误差累积，后续的功能交互必然偏离预期；反之，若缺乏对历史交互状态的准确记忆，智能体在跨模块导航中易陷入逻辑死锁。这种感知与规划的强耦合，使得单一维度的优化无法保证端到端系统的可用性。

现有评估体系存在结构性盲区。SWE-Bench 等基准聚焦于增量式 Issue 修复，仅考察局部代码编辑能力，无法评估从零构建系统的综合能力；Design2Code 等多模态基准则局限于静态单页复现，忽略了动态交互与后端逻辑。主流路线的瓶颈在于任务定义与验证机制的脱节：任务往往缺乏明确的层级结构，导致失败归因困难；验证多依赖单元测试或像素对比，前者难以覆盖复杂交互，后者无法捕捉语义级视觉差异。Vision2Web 的切入点在于将网站开发形式化为分层序贯决策过程，并引入结构化工作流约束代理行为，以解决评估的可复现性与细粒度诊断问题。

## 核心方法

### 分层任务形式化

本文问题属于端到端软件生成评估，与通用基准的关键差异在于强制多模态输入与全栈交付。Vision2Web 将任务划分为静态网页、交互式前端、全栈网站三级，每级构建于前一级能力之上。这种分层设计旨在解耦视觉理解、交互逻辑与系统架构能力，使失败模式可被定位至特定开发阶段。

### 工作流代理验证

传统单元测试在多样化实现中易失效，而自由探索的代理验证缺乏可复现性。Vision2Web 提出工作流代理验证范式，将端到端测试形式化为有向依赖图 $G=(V, E)$，其中节点 $v_i$ 代表自包含的验证子程序，边 $e_{ij}$ 编码状态依赖。每个功能验证节点定义为三元组 $n_i = \langle O_i, A_i, V_i \rangle$，其中 $O_i$ 为测试目标，$A_i$ 为约束动作序列，$V_i$ 为验证准则。该设计通过显式建模 $A_i$ 限制代理探索空间，防止其偏离预期路径或利用未定义行为，从而在保持交互灵活性的同时确保评估的确定性。

### 双维评分机制

视觉保真度评估需超越像素级相似度，捕捉组件级语义一致性。视觉验证节点定义为 $n_i = \langle P_i \rangle$，其中 $P_i$ 为目标原型。VLM 裁判对渲染页面与原型进行组件级对比，依据预设视觉准则分配保真度分数。整体视觉分数（VS）计算为所有原型块级分数的平均值：

$$ VS = \frac{1}{|P|} \sum_{p \in P} \frac{1}{|B_p|} \sum_{b \in B_p} s(b, p) $$

其中 $s(b, p)$ 为组件 $b$ 在原型 $p$ 下的保真度得分。该公式将全局视觉一致性分解为局部组件评估，避免了整体像素对比对布局微小偏移的过度敏感，同时提供了可解释的细粒度诊断指标。

## 实验评估

实验在 OpenHands 与 Claude Code 框架下评估 8 个多模态模型，覆盖 193 个任务。基线覆盖 Claude、GPT、Gemini 等主流闭源模型，但缺失 WebArena 等导航基准中的专用智能体方法，如 Branch-and-Browse，导致无法直接对比导航与生成能力的迁移效应。

| 模型 | 静态网页 (Avg) | 交互前端 (VS/FS) | 全栈网站 (VS/FS) |
| :--- | :--- | :--- | :--- |
| Claude-Opus-4.5 | 53.4 | 46.5 / 66.7 | 38.4 / 57.6 |
| Gemini-3-Pro-Preview | 55.8 | 29.7 / 40.7 | 11.7 / 22.6 |
| GPT-5 | 49.6 | 23.9 / 61.4 | 18.3 / 49.7 |
| Seed-1.8-VL | 1.3 | 7.5 / 33.9 | 0.0 / 0.0 |

Claude-Opus-4.5 在全栈任务中保持最高性能，但 VS 从静态阶段的 53.4 降至 38.4，FS 从 66.7 降至 57.6，表明长程规划与视觉一致性随复杂度增加而显著衰减。Gemini-3-Pro-Preview 在静态阶段表现最优（55.8），但在全栈任务中 VS 骤降至 11.7，暴露其在多页面协调与状态管理上的严重缺陷。Seed-1.8-VL 在全栈任务中完全失败（VS=0, FS=0），验证了当前模型在处理复杂系统级依赖时的能力断层。

消融分析显示，设备形态与原型复杂度对性能有系统性影响。桌面端得分最高，平板与移动端得分低 10–20%，且原型图像高度增加导致视觉分数进一步下降。功能类别中，导航与认证得分较高，而状态管理、CRUD 操作与文件媒体操作得分显著偏低，表明持久状态跟踪与跨组件数据流仍是主要瓶颈。

评估边界受限于代理验证的可靠性。GUI 智能体验证器的节点级准确率为 87.2%，剩余误差主要源于模型推理幻觉。该指标虽高，但在全栈任务的长依赖链中，单节点错误可能级联传播，导致最终分数失真。此外，论文未报告计算效率指标，如推理延迟与内存占用，限制了其在实际部署场景中的可复现性评估。

## 关联研究分析

从问题动机看，Vision2Web 与 Design2Code 共享 UI-to-Code 的核心目标，但后者局限于单页静态生成，无法评估交互逻辑与后端集成。Vision2Web 将任务扩展至全栈系统，引入了状态管理与跨页面协调维度，这一差异源于真实网站开发的复杂性，而非单纯的数据规模扩大。然而，Vision2Web 未探索合成数据增强对长尾场景的覆盖效果，而 Design2Code 依赖真实网页快照，两者在数据分布偏差上的影响均未量化。

从方法设计看，Vision2Web 借鉴 WebVoyager 的代理执行协议，但将目标从导航改为测试验证。WebVoyager 依赖线性 ReAct 循环，而 Vision2Web 采用结构化工作流约束代理行为，这一改动旨在解决自由探索导致的评估不可复现性问题。然而，结构化工作流可能限制代理发现非预期功能路径的能力，导致评估覆盖度不足。WebVoyager 的线性轨迹在长程任务中易出现错误累积，Vision2Web 通过工作流解耦缓解了这一问题，但牺牲了代理的自主探索潜力，这种取舍在复杂系统评估中的最优平衡点尚不明确。

## 总结

Vision2Web 旨在解决多模态编码智能体在端到端网站构建中评估碎片化与验证不可复现的矛盾。其切入点在于将网站开发形式化为分层序贯决策，并通过工作流代理验证约束评估过程，使失败归因可定位至特定开发阶段。实验表明，Claude-Opus-4.5 在全栈任务中 VS/FS 为 38.4/57.6，显著低于静态阶段，揭示了长程规划与视觉一致性的系统性衰减。该基准的边界在于依赖 GUI 智能体进行自我验证，87.2% 的节点准确率在长依赖链中可能引发级联误差，导致最终分数失真。当工作流复杂度增加至全栈系统级别时，代理验证的幻觉率是否随依赖链长度呈非线性增长，论文未给出回答。
