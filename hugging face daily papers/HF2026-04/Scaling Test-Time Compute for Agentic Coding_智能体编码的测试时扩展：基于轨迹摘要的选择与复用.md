# HuggingFace最新推荐论文 ｜Scaling Test-Time Compute for Agentic Coding ｜智能体编码的测试时扩展：基于轨迹摘要的选择与复用

研究机构：美国华盛顿大学、美国纽约大学

作者：Joongwon Kim、Wannan Yang、Kelvin Niu 等 16 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.16529)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.16529)

> 长程智能体编码任务中，每次尝试产生的是包含大量噪声的交互轨迹，而非可直接比较的短答案，导致传统测试时扩展方法失效。本文指出核心瓶颈在于“表示”：原始轨迹无法被有效选择和复用。作者将每条轨迹压缩为结构化摘要，并以此为基础构建递归小组投票（RTV）进行并行选择、并行-蒸馏-精炼（PDR）进行顺序复用。该框架在前沿模型上稳定提升了智能体编码基准的性能，但其依赖LLM-as-Judge的可靠性，且未量化摘要信息丢失对最终准确率的负面影响。

## 研究背景

当智能体在bash环境中执行多步编码任务时，其输出不再是单一的代码片段，而是由思考、命令执行、错误日志和中间状态交织而成的长轨迹。这种轨迹长度可达数百步，且包含大量低价值的重复终端输出和死胡同探索。直接将这些轨迹作为测试时扩展（Test-Time Scaling, TTS）的操作对象面临两个难题：一是轨迹过长，超出上下文窗口或导致比较时的注意力稀释；二是轨迹中的关键信号（如假设、失败模式）被噪声淹没，使得基于轨迹的直接聚合或精炼难以准确捕捉有效信息。

通用推理领域的TTS研究已确立并行采样与顺序精炼两条主线，但主要假设模型输出是紧凑且可直接比较的（如数学答案或短代码）。在智能体编码场景中，这一假设被打破：轨迹的异构性和长度使得传统的多数投票或最佳N选择策略失效。现有方法如Self-Consistency依赖答案分布的模态天花板，无法处理长轨迹的细微差异；而过程奖励模型（PRM）在开放域代码任务上校准成本高且存在偏差。本文的切入点是将TTS问题重构为“表示、选择与复用”问题，通过引入结构化摘要作为中间接口，解耦轨迹生成与轨迹利用。

## 核心方法

### 方法参照系

本文问题属于并行采样与顺序精炼的混合范式，但关键差异在于操作对象从“原始输出”变为“轨迹摘要”。通用TTS流程直接对模型输出进行聚合或条件生成，而本文在生成与利用之间插入一个摘要化步骤，将长轨迹转换为紧凑的结构化工件，作为后续选择和复用的统一接口。

### 结构化摘要作为表示接口

原始轨迹 $R_i$ 包含动作 $A_i$ 和观察 $O_i$ 的交错序列，直接比较或复用效率低下。本文引入摘要函数，将 $R_i$ 转换为结构化摘要 $S_i$：

$$ S_i = \text{Summarize}(R_i, P_{\text{sum}}) $$

其中 $P_{\text{sum}}$ 是摘要提示词。该设计解决了长轨迹噪声掩盖有效信号的问题：摘要保留关键假设、决策、进度和失败模式，丢弃低价值细节，使 $S_i$ 成为有界且可比较的对象。实验表明，使用摘要进行并行聚合比直接使用原始轨迹在最终轮次中表现更优，因为摘要在消除“简单”对后，使剩余候选的细微差异更易被识别。

### 递归小组投票（RTV）

并行选择阶段，本文提出RTV替代全局排序。给定 $N$ 条摘要 $\{S_1, ..., S_N\}$，RTV通过递归小组比较选择最优轨迹。每轮 $r$ 将群体分为大小为 $G$ 的小组，对每组 $j$ 应用比较提示 $P_{\text{comp}}$ 并聚合 $V$ 票：

$$ S_{[r], j}^{\text{selected}} = \text{Aggregate}\left( \bigcup_{g \in \text{group}_j} \text{Vote}(S_{[r], j, g}, P_{\text{comp}}, V) \right) $$

选中的摘要进入下一轮，直至仅剩一条。该设计解决了长轨迹全局排序的困难：递归小组比较将全局决策分解为局部决策，避免了单次比较中注意力分散的问题。实验显示，$G=2$（成对比较）和 $V=8$（投票数）的组合优于 $G=16$（全局比较）或 $V=1$（单票），表明局部决策的可靠性随投票数增加而提升，且在 $V=8$ 后边际收益递减。

### 并行-蒸馏-精炼（PDR）

顺序复用阶段，本文将PDR适配到智能体场景。迭代 $t+1$ 的每条轨迹 $R_i^{[t+1]}$ 条件于从迭代 $t$ 中选出的 $K$ 条摘要 $\{S_{i_1}^{[t]}, ..., S_{i_K}^{[t]}\}$：

$$ R_i^{[t+1]} = \text{Rollout}(P_{\text{in}}, \text{Concat}(S_{i_1}^{[t]}, ..., S_{i_K}^{[t]}), E) $$

其中 $E$ 是初始化的bash环境。该设计解决了单轨迹精炼的信息不足问题：多条摘要提供多样化的先前经验，使新轨迹能交叉验证假设并避免重复错误。实验表明，使用 $K=4$ 条摘要（无论随机或RTV选择）均优于单轨迹精炼，且RTV选择的摘要使更多任务进入“4/4通过”的高质量精炼上下文，从而提升迭代1的通过率。

## 实验评估

实验在SWE-Bench Verified（500题）和Terminal-Bench v2.0（88题）上进行，使用Claude-4.5-Opus、Gemini-3.1-Pro等五个前沿模型，主实验配置为 $N=16$、$T=2$、$K=4$、$G=2$、$V=8$。基线仅为单尝试（Iter 0），未对比BoM、Logit Averaging等经典聚合方法，也未与PRM-based方法直接比较，限制了横向可比性。

| 模型 | SWE-Bench Verified (Iter 0 → Final) | Terminal-Bench v2.0 (Iter 0 → Final) |
|---|---|---|
| Claude-4.5-Opus | 70.94% → 77.60% | 46.95% → 59.09% |
| Gemini-3.1-Pro | 72.25% → 76.60% | 52.49% → 64.77% |
| Claude-4.5-Sonnet | 67.41% → 75.60% | 40.62% → 56.82% |
| Gemini-3-Flash | 70.79% → 76.00% | 37.93% → 48.86% |
| GPT-5-0825 | 61.41% → 69.80% | 31.32% → 38.64% |

主结果显示，PDR+RTV在所有模型和基准上均带来一致提升，Terminal-Bench v2.0的绝对增益（+7.32%至+16.20%）大于SWE-Bench Verified（+4.35%至+8.39%），可能与后者任务方差更大、长轨迹选择更关键有关。

消融实验验证了三个关键设计决策：(1) 摘要优于原始轨迹作为比较对象，尤其在RTV最终轮次；(2) 递归小组比较（$G=2$）优于全局比较（$G=16$），且投票数 $V$ 从1增至8时性能显著提升，$V>8$ 后收益递减；(3) 多轨迹精炼（$K=4$）优于单轨迹精炼，且RTV选择的摘要使“4/4通过”上下文比例从52.8%（随机）提升至62%（Claude-4.5-Sonnet），直接驱动迭代1通过率单调上升。反直觉发现是：迭代1的失败轨迹数量也增加（如Claude-4.5-Opus从73/500增至94/500），表明RTV在低成功率任务上可能保留不足4个成功候选，导致精炼上下文质量下降，但净收益仍为正。

评估边界方面，论文未报告置信区间，且LLM-as-Judge的准确性受基础设施故障影响（如Gemini-3.1-Pro的API失败率），可能低估其选择性能。代码未公开，超参数（如 $P_{\text{sum}}$、$P_{\text{comp}}$ 的具体内容）未详细披露，限制了可复现性。

## 关联研究分析

从问题动机看，本文与Self-Consistency（Wang et al., 2023）共享并行采样思想，但Self-Consistency假设答案空间离散且可直接投票，而本文处理连续轨迹空间，必须引入摘要化步骤以解决表示问题。这一差异源于任务特性：智能体编码的轨迹长度和噪声水平远超短答案，使得直接投票失效。从方法设计看，本文与PDR（Madaan et al., 2025）共享顺序精炼框架，但PDR原始版本针对短文本生成，本文将其适配到多步交互环境，并引入RTV进行并行选择，形成“选择-复用-选择”的闭环。这一扩展解决了PDR在长轨迹上信息复用不足的问题，但引入了对LLM-as-Judge的依赖，其可靠性在开放域代码任务上尚未得到充分验证。

## 总结

本文要解决的核心矛盾是长程智能体轨迹的噪声性与TTS对可比较性的要求之间的冲突。现有方法因直接操作原始轨迹而失效，本文通过结构化摘要解耦表示与利用，使选择和复用成为可能。PDR+RTV框架在SWE-Bench Verified上将Claude-4.5-Opus从70.94%提升至77.60%，在Terminal-Bench v2.0上从46.95%提升至59.09%，证明了摘要接口的有效性。然而，实验暴露了摘要信息丢失的潜在风险：当RTV在低成功率任务上保留不足4个成功候选时，迭代1的失败率上升，表明摘要可能丢失关键细节，导致精炼上下文质量下降。当任务成功率低于25%时，摘要化表示是否仍能保留足够的区分信号以支持有效选择，论文未给出回答。
