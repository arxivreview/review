> 可控扩散方法长期以孤立系统形式存在，导致基础设施难以复用且多控制组合时冲突仲裁成本高。本文提出 Diffusion Templates，将控制能力解耦为独立插件，通过标准化接口实现跨骨干迁移与组合。该框架验证了通用接口在结构控制、属性调整等任务上的通用性，但其定量性能优势及复杂多模态控制下的鲁棒性仍缺乏充分证据。

## 研究背景

可控扩散模型的核心困境在于“能力碎片化”。当用户需要同时控制图像结构、亮度与风格时，现有方法如 ControlNet 和 LoRA 各自暴露独立的运行时钩子与参数格式。这种架构耦合使得集成新控制往往需要修改底层去噪管线，而非加载可复用模块。更严重的是，多个控制路径可能竞争同一内部激活或依赖临时融合逻辑，导致冲突解决成为手工工程问题。

主流路线分为参数高效适应（如 LoRA、DreamBooth）与显式条件路径（如 ControlNet、IP-Adapter）。前者通过低秩更新绑定概念，后者通过附加分支注入结构约束。尽管各自有效，但它们均围绕特定骨干架构与训练配方开发，缺乏统一的系统接口。这导致跨骨干迁移困难，且无法在单一生成管线中灵活调度多种控制。本文切入点在于将控制能力视为可插拔的“插件”，通过定义通用中间表示层，解耦基础模型推理与控制能力注入，从而降低集成与维护成本。

## 核心方法

### 方法参照系

本文问题属于可控扩散的系统架构优化。标准流程通常将控制模块硬编码至骨干网络（如 ControlNet 的残差分支），导致控制逻辑与生成逻辑紧耦合。本文的关键差异在于引入中间表示层，将控制能力封装为独立模型，通过标准化接口与基础管线交互，而非直接修改去噪内部逻辑。

### Template Cache 接口定义

Template Cache 是连接控制模块与基础管线的标准化接口，其格式被约束为基础扩散管线可接受的输入参数子集。这一设计解决了此前方法中控制信号格式不统一导致的集成冲突。具体而言，Cache 可采用 KV-Cache 或 LoRA 权重等形式，其中 KV-Cache 因支持序列级拼接而成为推荐载体，允许多个模板缓存直接合并后注入管线。

$$
\mathcal{C}_{merged} = \bigoplus_{i=1}^{N} \mathcal{C}_i
$$

该公式表示多个 Template Cache 通过直接拼接（$\oplus$）合并为单一缓存，无需修改基础去噪逻辑即可实现多控制联合生效。这种设计使得控制能力的组合从手工工程问题转化为简单的数据合并操作。

### Template Model 训练与执行

Template Model 是映射任意任务输入至 Template Cache 的独立模型，其架构不受限制。训练时冻结基础模型参数，仅优化新增侧分支，目标函数保持与基础模型预训练损失一致。执行时分为两阶段：`process inputs` 执行无梯度预处理以生成可缓存特征，`forward` 执行梯度相关计算以产生 Cache 输出。

$$
\mathcal{L}_{template} = \mathbb{E}_{t, \epsilon, x_0} \left[ \| \epsilon - \epsilon_\theta(x_t, t, c_{text}, \mathcal{C}_{template}) \|^2 \right]
$$

该公式表明 Template Model 的训练损失与基础扩散模型相同，仅将 Template Cache 作为额外条件输入。这种设计确保了控制能力的注入不改变基础模型的生成目标，同时通过解耦预处理与梯度计算，减少了冗余计算并提升了训练效率。

## 实验评估

实验基于 FLUX.2-klein-base-4B 骨干，使用固定随机种子 0、CFG 尺度 4 及 50 步推理。基线覆盖基础模型原生编辑能力，但缺失 ControlNet、IP-Adapter 等经典可控方法的定量对比。该论文实验数据不可得，未提供实验表格。

在图像编辑任务中，Template Model 实现了约 1.8× 的推理加速，同时保持与基础模型相当的编辑质量。这一加速源于将编辑能力从基础管线转移至独立 Template 路径，避免了长序列带来的计算开销。然而，论文未报告 FID 等标准生成质量指标，也未提供与专用超分辨率模型（如 Real-ESRGAN）的定量对比，仅定性展示其在结构控制、亮度/颜色调整、美学对齐等任务上的可行性。

评估边界主要在于缺乏定量基准与强基线对比。论文未报告置信区间，且多数结果依赖定性视觉评估。可复现性方面，代码与模型已开源，但训练细节（如具体超参数、GPU 配置）未在正文中详细披露。

## 关联研究分析

从问题动机看，ControlNet 通过附加残差分支注入结构约束，但要求修改骨干网络接口；本文则通过 KV-Cache 接口实现无侵入式控制。差异根源在于 ControlNet 将控制视为骨干的扩展，而本文将其视为独立能力单元。这种解耦使得控制模块可跨骨干迁移，但可能牺牲特定任务（如精细结构控制）的极致性能，因为通用接口无法针对特定架构优化控制信号传播路径。

从方法设计看，LoRA 通常作为固定权重更新用于风格适应，本文将其重构为可插拔的能力载体，通过 `process inputs` 接口动态生成 LoRA 权重。这一设计解决了 LoRA 在组合控制时的冲突问题，但引入了额外的预处理开销。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

本文核心矛盾是可控扩散方法的碎片化导致基础设施复用困难。切入点在于将控制能力解耦为独立插件，通过标准化 Template Cache 接口实现跨骨干迁移与组合。方法上，提出 Template Model 与 Template Pipeline 架构，支持 KV-Cache 与 LoRA 等多种载体。实验证明其在图像编辑任务上实现 1.8× 加速，并验证了多任务通用性。边界在于缺乏定量 FID 指标与强基线对比，且未探索复杂多模态控制下的冲突仲裁机制。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
