> 多模态生成模型在复杂指令与专业下游任务中表现受限，传统推理时扩展方法因上下文冗余或单步更新导致优化停滞。GEMS 通过引入分层记忆压缩与按需技能加载机制，在不修改基础模型参数的前提下突破容量上限。该框架实现了轻量级模型对顶级闭源模型的超越，但其性能增益高度依赖外部大语言模型的推理能力，且缺乏与训练式强化学习方法的直接对比。

## 研究背景

当生成模型面对包含多重约束的复杂提示词时，单次前向传播往往无法同时满足所有语义与结构要求。这种失效源于模型内部表征空间对抽象语义与像素细节的耦合，导致推理正确但执行失真。为解决此问题，推理时扩展（Inference-Time Scaling）策略通过增加计算预算换取性能提升，但现有方法多采用简单的提示词重写或随机搜索，缺乏对生成轨迹的全局把控。

多模态生成领域正从架构统一转向认知闭环，核心矛盾在于静态预训练模型的知识截止与长尾实体缺失。主流路线分为训练式优化与推理时扩展两类：前者如 UniGRPO 通过强化学习对齐世界知识，后者如 Maestro 依赖多智能体协作。然而，现有推理时框架存在两个瓶颈：一是上下文累积导致的信息冗余，二是专用下游任务框架与主流生成管线的架构割裂。GEMS 的切入点在于借鉴代码智能体（如 Claude Code）的记忆与技能机制，将生成过程重构为具备持久记忆和可扩展专家知识的自主决策循环，从而在训练-free 条件下实现复杂任务的闭环优化。

## 核心方法

### 方法参照系

GEMS 属于推理时扩展中的多智能体协作路线。标准流程通常包含提示词优化、图像生成与质量验证三个环节，但传统方法（如 Maestro）仅保留最近一步状态或最佳状态，缺乏对完整优化轨迹的全局视角，导致在长序列迭代中陷入局部最优或重复错误。

### 分层记忆压缩机制

Agent Memory 模块解决了传统上下文累积导致的 token 爆炸与信息噪声问题。该机制将迭代状态分为事实层与经验层：事实层保留提示词 $P_i$、图像 $I_i$ 和反馈向量 $V_i$ 的原始数据，确保历史准确性；经验层通过压缩器 $F_{comp}$ 将冗长的推理轨迹 $T_i$ 蒸馏为高层经验 $E_i$。记忆状态 $M_i$ 更新为混合元组序列：

$$ M_i = \{(P_k, I_k, V_k, E_k) | k \le i\} $$

这一设计使得 Refiner 在生成下一轮提示词时，既能访问客观的事实锚点，又能利用精炼的战略反思，避免了全量上下文带来的计算负担与注意力分散。

### 按需技能加载机制

Agent Skill 模块解决了专用下游任务框架难以集成到主流管线的问题。系统维护一个技能库 $S$，仅加载技能名称与描述作为轻量级清单。当 Planner 识别到用户意图匹配特定领域时，才动态获取该技能的详细指令。触发技能集合 $S_{trig}$ 定义为：

$$ S_{trig} = \{s \in S | \text{Match}(U, s) > \tau\} $$

这种渐进式暴露机制允许系统支持大规模专家库而不增加基础推理负载，用户仅需提供 Markdown 文件即可扩展新技能，实现了架构的可扩展性与低认知负荷。

## 实验评估

| 方法 | GenEval2 | WISE | DPG-Bench | Avg. (Mainstream) |
| :--- | :--- | :--- | :--- | :--- |
| Z-Image-Turbo (Original) | 31.0 | 0.57 | 85.08 | 59.35 |
| Maestro | 43.5 | 0.61 | 85.47 | 70.05 |
| CRAFT | 44.6 | 0.61 | 85.29 | 72.38 |
| GEMS (Z-Image-Turbo) | 63.5 | 0.81 | 86.01 | 74.51 |
| Nano Banana 2 | 44.6 | 0.55 | 85.23 | - |

GEMS 在 Z-Image-Turbo 上实现了主流任务平均分 14.22 的提升，其中 GenEval2 从 31.0 跃升至 63.5，显著超越 Nano Banana 2 的 44.6。基线覆盖了重写、搜索及多智能体方法，但缺失 UniGRPO 等强化学习基线，导致无法直接评估训练-free 与训练式方法的性能边界。

消融实验显示，Agent Loop 单独贡献 21.4 分（31.0 至 52.4），Agent Memory 贡献 9.0 分，Agent Skill 贡献 2.1 分。记忆配置分析表明，仅包含提示词与反馈可提升 3.4 分，加入图像再提升 3.1 分，但加入完整思维链（CoT）无显著增益，证实了冗余推理轨迹对优化过程的负面干扰。迭代分布显示，引入 Memory 和 Skill 后平均迭代次数从 3.26 降至 2.80，表明结构化信息加速了收敛。

评估协议基于五个主流基准与四个下游任务，使用 Kimi K2.5 作为 MLLM 后端。论文未报告计算成本的具体 GPU 小时数，仅定性指出 GEMS 在平均 3 张图像时优于其他方法。代码未开源，且 Qwen-Image-2512 的实验结果低于其前代版本，暗示模型版本差异可能影响基线公平性。

## 关联研究分析

从知识获取机制看，GEMS 与 ToolArtist 形成鲜明对比。ToolArtist 依赖外部搜索工具获取实时信息，解决的是知识截止问题；而 GEMS 通过内部技能库加载静态领域专家，解决的是专业任务的结构化约束问题。GEMS 的技能库本质上是硬编码的领域知识，无法应对训练数据中未出现的长尾实体，这限制了其在开放世界事实性生成中的适用性。

从优化范式看，GEMS 与 UniGRPO 代表了推理时扩展与训练时优化的两条路径。UniGRPO 通过可验证奖励直接优化模型参数，在 GenEval 上达到 0.88；GEMS 则通过外部 MLLM 的反馈驱动提示词进化，在 GenEval2 上达到 63.5。两者基准不同，难以直接比较，但 GEMS 的性能高度依赖 Kimi K2.5 的推理能力，若后端 MLLM 能力不足，其闭环优化效果将大幅衰减，这是训练-free 方法的固有脆弱性。

## 总结

GEMS 旨在解决多模态生成在复杂指令下的执行失真问题，通过分层记忆压缩与按需技能加载，在不修改基础模型参数的前提下实现了性能突破。该框架使 6B 的 Z-Image-Turbo 在 GenEval2 上超越 Nano Banana 2，证明了智能体推理对基础模型容量上限的拓展能力。然而，其性能增益依赖于外部 MLLM 的高质量反馈，且缺乏与强化学习方法的直接对比，使得训练-free 范式的性能上限难以界定。当技能库规模扩大至数百个领域时，技能检索的准确性与延迟是否会成为新的瓶颈，论文未给出回答。
