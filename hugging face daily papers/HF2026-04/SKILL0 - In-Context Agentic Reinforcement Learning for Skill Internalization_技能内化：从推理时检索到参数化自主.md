# HuggingFace最新推荐论文 ｜SKILL0: In-Context Agentic Reinforcement Learning for Skill Internalization ｜技能内化：从推理时检索到参数化自主

研究机构：浙江大学、美团

作者：Zhengxi Lu、Zhiyuan Yao、Jinyang Wu 等 10 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.02268)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.02268)

> 代理技能学习旨在通过外部程序性记忆扩展大语言模型（LLM）代理的任务执行能力，但主流“推理时增强”范式面临检索噪声、Token开销累积及能力未真正习得三重瓶颈。SKILL0 提出将技能内化作为显式训练目标，通过上下文强化学习（In-Context Reinforcement Learning, ICRL）在训练阶段注入技能、推理阶段完全移除，实现零检索自主执行。该方法结合动态课程机制逐步退火技能依赖，在 ALFWorld 和 Search-QA 上较标准 RL 基线提升 9.7% 和 6.6%，且单步 Token 成本低于 0.5k。其价值在于验证了能力从上下文向参数迁移的可行性，但绝对性能仍低于强技能增强基线，且依赖初始技能库质量。

## 研究背景

当 LLM 代理执行多步复杂任务时，需调用外部工具或遵循特定工作流，这类结构化程序性知识被称为代理技能（Agent Skill）。传统做法是在推理时从技能库检索相关技能并注入上下文，但检索噪声会引入误导性指导，且多轮交互中注入内容的 Token 开销呈线性增长，严重限制可扩展性。更根本的问题是，模型仅在执行时“阅读”技能描述，能力停留在上下文层面而非内化为模型参数，导致其无法在缺乏外部提示时自主完成任务。

该领域早期工作如 ReAct 和 Toolformer 确立了推理-行动耦合范式，但技能隐含于单次轨迹中，缺乏持久化存储。随着技能库规模扩大，ToolkenGPT 等提出检索-执行两阶段架构，SkillRL 等引入强化学习优化技能选择与利用，但均维持“推理时增强”范式。这些方法在动态环境中表现优异，却未能解决“模型未真正学习技能”的本质缺陷。SKILL0 的切入点在于：能否设计一种训练机制，使技能在训练阶段作为脚手架引导策略学习，并在推理阶段完全剥离，从而将能力固化至模型参数？

## 核心方法

### 方法参照系

SKILL0 属于技能强化学习路线，与 SkillRL 等共享技能库结构与 RL 优化框架。关键差异在于：标准流程在推理时持续检索注入技能，而 SKILL0 仅在训练 rollout 中提供技能上下文，推理时完全移除，直接优化从上下文依赖到自主执行的过渡。

### 上下文强化学习（ICRL）

ICRL 的核心是将技能注入限定于训练阶段，通过复合奖励联合优化任务成功与压缩效率。设计动机在于解决纯 RL 缺乏结构化引导导致的多步行为学习困难，以及固定技能注入导致模型无法摆脱外部依赖的问题。复合奖励定义为：

$$
\tilde{r}(\tau) = I_{\text{succ}}(\tau) + \lambda \sum_{t=1}^{T} \log(c_t)
$$

其中 $I_{\text{succ}}(\tau)$ 为轨迹成功指示器，$c_t \in (0,1]$ 为第 $t$ 步的上下文压缩比，$\lambda$ 控制任务性能与压缩效率的权衡。该公式迫使模型在保持任务成功率的同时，主动压缩交互历史与技能内容的视觉表示，为技能内化提供效率约束。训练目标采用组相对策略优化（GRPO）形式，通过组内奖励归一化计算优势函数，驱动策略向高成功、低开销方向更新。

### 动态课程学习

动态课程机制解决固定技能预算导致的分布突变问题，其设计动机在于避免技能突然移除引发的策略崩溃。该机制将训练分为 $N_S$ 个阶段，技能预算 $M(s)$ 线性衰减：

$$
M(s) = \left\lfloor \frac{N_S - s}{N_S - 1} N \right\rfloor, \quad s \in \{1, \dots, N_S\}
$$

其中 $N$ 为初始技能文件总数。每 $d$ 步评估每个技能文件 $S_k$ 的“有用性” $\Delta_k$，定义为在匹配验证子任务 $T_k$ 上，有技能与无技能条件下的准确率差：

$$
\Delta_k = \text{Acc}_{\text{w/ skill}}(k) - \text{Acc}_{\text{w/o skill}}(k)
$$

仅保留 $\Delta_k > 0$ 的技能，并按 $\Delta_k$ 降序选取前 $M(s)$ 个。该机制确保技能仅在策略仍受益时保留，当 $\Delta_k$ 趋近零时自动移除，实现能力从上下文向参数的平滑迁移。

## 实验评估

实验在 ALFWorld（3,827 个具身任务）和 Search-QA（含 NQ、HotpotQA 等 7 个数据集）上进行，基线覆盖 RL 类（GRPO、AgentOCR、EvolveR）和技能增强类（SkillRL），但缺失纯检索类（如 SkillDAG）及参数化内化类（如 LatentSkill）方法。主实验表明，SKILL0（7B）在 ALFWorld 上达 89.8%，较 AgentOCR 提升 9.7%；在 Search-QA 上达 44.4%，较 AgentOCR 提升 6.6%。

| 方法 | ALFWorld Avg (%) | Search-QA Avg (%) | ALFWorld Cost (k) | Search-QA Cost (k) |
| :--- | :--- | :--- | :--- | :--- |
| AgentOCR | 80.1 | 37.8 | 0.95 | 0.73 |
| SkillRL | 87.5 | 43.1 | 1.79 | 0.36 |
| SKILL0 | 89.8 | 44.4 | 0.41 | 0.34 |

消融实验验证了动态课程三步骤（Filter、Rank、Select）的必要性：移除 Rank 步骤导致无技能推理性能暴跌 13.7%（从 87.9% 至 62.9%），证明随机保留技能会引发策略对表面提示的依赖。验证间隔 $d$ 的敏感性分析显示，$d=5$ 时性能最优（ALFWorld 87.5%，Search-QA 49.6%），$d=20$ 时显著下降，表明高频有用性评估对稳定内化至关重要。

评估边界方面，论文未报告置信区间，且 Search-QA 中 NQ 和 HotpotQA 为域内数据，其余为域外，泛化能力评估受限。可复现性上，代码已开源，训练使用 4 张 H800 GPU，最多 180 步，超参数（如 $N_S=3$、验证集大小 1,000）明确给出。

## 关联研究分析

从问题动机看，SKILL0 与 SkillRL 同属技能强化学习路线，但 SkillRL 聚焦推理时技能选择与利用的协同优化，而 SKILL0 将技能视为训练脚手架，目标是消除推理时依赖。这一差异源于对“技能习得”本质的不同理解：SkillRL 假设技能需持续外部支持，SKILL0 则认为技能应内化为内在策略。根源在于任务特性——ALFWorld 等具身任务具有固定动作空间，技能模式易参数化；而开放域任务（如 GAIA）中技能多样性高，内化是否导致泛化下降，论文未提供证据。

从方法设计看，SKILL0 与 LatentSkill 同属内化路线，但 LatentSkill 通过 LoRA 静态微调将技能压缩至参数，而 SKILL0 通过 RL 动态退火实现渐进内化。LatentSkill 在 WebShop 上达 78.0%，但缺乏动态适应能力；SKILL0 的动态课程允许策略在不同训练阶段调整技能依赖，但依赖初始技能库质量。若初始技能库存在偏差，有用性评估可能误导内化方向，这一风险在论文局限性中提及但未量化。

## 总结

SKILL0 解决的核心矛盾是推理时技能增强的 Token 开销与能力未内化问题。其切入点在于将技能内化形式化为显式训练目标，通过 ICRL 和动态课程实现能力从上下文向参数的迁移。实验证明该方法在 ALFWorld 和 Search-QA 上较标准 RL 基线提升 9.7% 和 6.6%，且单步 Token 成本低于 0.5k。边界在于绝对性能仍低于 SkillRL 等强技能增强方法（ALFWorld 89.8% vs 87.5%，差距微弱但存在），且依赖初始技能库质量。当技能库规模扩大至数万级时，动态课程的有用性评估计算成本是否成为瓶颈，论文未给出回答。
