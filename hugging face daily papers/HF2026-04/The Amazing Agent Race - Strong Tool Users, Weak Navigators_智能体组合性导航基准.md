# HuggingFace最新推荐论文 ｜The Amazing Agent Race: Strong Tool Users, Weak Navigators ｜智能体组合性导航基准

研究机构：美国明尼苏达大学、韩国延世大学

作者：Zae Myung Kim、Dongseok Lee、Jaehyung Kim 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.10261)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.10261)

> 现有工具使用与网页导航基准将能力评估割裂，导致智能体在非线性依赖结构下的失败模式不可见。本文通过构建包含分叉-合并（Fork-Merge）结构的有向无环图（DAG）任务，强制智能体在导航与工具调用间建立耦合。实验表明，导航错误是主要瓶颈，而组合结构加剧了导航失败，揭示了线性基准的盲区。该基准提供了细粒度诊断能力，但其单一信息源（Wikipedia）与静态答案生成机制限制了向真实开放网络的泛化。

## 研究背景

当智能体执行“计算苹果创始人出生地海拔差”这类任务时，它必须从维基百科页面提取实体，调用地理编码与海拔API，并处理并行分支的结果。这一过程涉及感知接地（Grounding），即准确定位网页元素，以及规划鲁棒性，即在多步依赖中维持状态一致性。若早期导航错误，后续工具调用将基于错误输入执行，导致级联失败。

主流基准如ToolBench与WebArena分别聚焦工具调用与网页操作，但二者均假设任务结构为线性链。分析显示，现有基准55%至100%的实例为2至5步的线性序列，缺乏对分叉-合并推理的测试。这种“组合性赤字”使得智能体在真实场景中处理并行API调用与结果聚合时的脆弱性无法被检测。AAR针对此缺口，通过程序化生成DAG结构任务，将导航、工具组合与算术推理耦合在单一评估单元中。

## 核心方法

### 任务形式化与DAG结构

AAR将任务定义为有向无环图（DAG），节点为“停靠点”（Pit Stop），边为依赖关系。与线性基准不同，AAR引入“菱形模式”（Diamond Pattern），即从单一源节点分叉出两个独立工具链，再在下游合并。该设计动机在于模拟真实场景中常见的并行数据获取需求，如同时查询海拔与人口密度。

$$
\text{Diamond}(s_{\text{src}}, s_{\text{branchA}}, s_{\text{branchB}}, s_{\text{merge}}) = \begin{cases} s_{\text{branchA}} \leftarrow s_{\text{src}} \\ s_{\text{branchB}} \leftarrow s_{\text{src}} \\ s_{\text{merge}} \leftarrow \{s_{\text{branchA}}, s_{\text{branchB}}\} \end{cases}
$$

该公式定义了菱形结构的依赖关系：分支节点仅依赖源节点，合并节点依赖两个分支。这种结构强制智能体在导航至源页面后，必须正确执行两条独立工具链，并将结果聚合，任何分支的导航或工具错误都会导致最终答案失效。

### 自动化生成与污染抵抗

AAR采用八步流水线生成任务：从维基百科种子页面爬取链接，规划主题路线，实例化工具链，预验证API稳定性，插入菱形模式，执行黄金轨迹，最后将任务转化为“线索信封”（Clue Envelope）。线索信封使用迂回描述替代直接标题，确保智能体无法通过记忆直接获取答案。

$$
\text{Alignment}(C, y^*) = \frac{\sum_{i=1}^{K} \mathbb{I}(\text{clue}_i \rightarrow \text{stop}_i)}{K} \geq 0.7
$$

该公式要求线索信封与黄金轨迹的对齐度不低于0.7，且隐含代码必须等于黄金答案$y^*$。这一设计动机在于抵抗数据污染：通过实时API调用与模数运算，答案必须推导而非记忆，同时线索迂回化防止智能体利用训练数据中的维基百科标题直接跳转。

## 实验评估

实验在1,400个任务腿上评估三种智能体框架（Codex CLI、Claude Code、mini-swe-agent）与四种模型（GPT-5.4、GPT-5.4-mini、Claude Sonnet 4、GPT-OSS-120B）。基线覆盖主流代码智能体，但缺乏专用网页导航智能体（如Branch-and-Browse），限制了与领域SOTA的直接对比。

| 配置 | FA (%) | PVR (%) | RCR (%) |
| :--- | :--- | :--- | :--- |
| Codex + GPT-5.4 | 37.1 | 37.1 | 49.2 |
| Claude Code + Sonnet 4 | 37.2 | 30.7 | 34.8 |
| Codex + GPT-5.4-mini | 34.8 | 27.2 | 33.6 |

核心数字显示，最佳FA为37.2%，PVR（导航）始终低于RCR（工具使用），证实导航是主要瓶颈。从AAR-Linear到AAR-DAG，导航分数下降13至18个百分点，而工具使用分数稳定，表明组合结构加剧导航失败而非工具调用失败。

消融分析显示，难度提升导致FA单调下降（Codex + GPT-5.4从45.0%降至31.5%），PVR下降幅度（88.7%至37.1%）远大于RCR（83.6%至49.2%）。反直觉发现是，DAG任务中导航错误率增加16个百分点，但工具错误率下降5个百分点，暗示菱形结构提供了更清晰的工具调用线索，但导航复杂度显著增加。

评估边界方面，AAR仅使用Wikipedia作为导航源，缺乏真实开放网络的动态性与反爬虫机制。Live API引入时间动态性，但通过缓存黄金轨迹保证可复现性。代码与数据已开源，但缺乏与专用网页智能体的对比，且未报告计算效率指标（如推理延迟），限制了实用性评估。

## 关联研究分析

从问题动机看，AAR与GAIA最接近，但GAIA依赖人工标注的静态实例，存在数据污染风险，且评估仅限最终答案匹配。AAR通过程序化生成与实时API验证，解决了污染与细粒度诊断问题。差异根源在于任务结构：GAIA的线性链无法测试分叉-合并推理，而AAR的DAG结构强制智能体处理并行依赖，揭示了导航-工具耦合的失败模式。

从方法设计看，AAR与ToolBench均关注工具组合，但ToolBench提供所有输入，智能体无需导航。AAR将导航作为前置条件，使工具调用依赖导航结果，从而暴露了线性基准中不可见的级联错误。这一设计选择源于真实场景中信息获取与工具调用的强耦合，而非论文未探索的盲区。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但AAR的线索迂回化已部分缓解了记忆依赖问题。

## 总结

AAR要解决的核心矛盾是现有基准无法检测智能体在非线性依赖结构下的失败模式。其切入点在于通过DAG结构与实时API验证，强制导航与工具调用耦合，从而暴露线性基准的盲区。实验证明，导航错误是主要瓶颈，组合结构加剧导航失败（下降13至18个百分点），而工具使用能力相对稳定。本文的边界在于单一信息源（Wikipedia）与静态答案生成机制，限制了向真实开放网络的泛化。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
