> 通用智能体在长程任务中面临的核心矛盾是：静态工具环境无法模拟真实世界的状态依赖与组合性，而纯LLM模拟环境又因幻觉导致训练信号失真。现有环境扩展方法虽提升了规模，但缺乏利用环境反馈进行持续诊断与针对性优化的机制，导致智能体在跨环境泛化上表现不均。Agent-World通过从Web挖掘真实数据库构建1978个可执行环境，并引入“诊断-扩展”闭环自进化训练，解决了环境真实性与训练信号稀疏性的双重瓶颈。该方法在23个基准上验证了跨环境泛化的有效性，但其单智能体架构在多轮状态一致性任务上仍落后于多智能体共享状态方案，且真实Web数据的隐私与稳定性对训练可复现性的影响尚未量化。

## 研究背景

当智能体执行航班预订等复杂任务时，必须遵循“检查库存→执行预订→更新日历”的严格动作顺序，且每个动作都会修改底层环境状态。这种状态依赖性要求智能体不仅具备推理能力，还需实时追踪环境状态转移，而传统无状态或单工具设置无法支撑此类交互。解决这一问题的关键框架是部分可观测马尔可夫决策过程（POMDP），它将智能体与环境交互建模为状态、动作、观测的序列决策过程，其中环境状态需通过工具观测间接推断。

该领域要解决的核心问题是：如何在有限上下文窗口与高维工具空间中，构建具备长程规划能力、动态适应环境反馈并实现自我进化的自主智能体决策系统。主流路线分为两类：一是基于LLM模拟的环境合成，虽可扩展但易产生幻觉，偏离真实世界动态；二是基于真实API的环境构建，虽保真度高但构建成本高昂且难以规模化。现有环境扩展方法（如EnvScaler、AWM）虽提升了环境规模，但主要依赖单轮训练，缺乏利用环境反馈诊断智能体弱点并驱动针对性学习的机制，导致跨环境泛化能力不均。Agent-World的切入点在于将环境从“静态训练场”升级为“动态诊断-扩展闭环”，通过真实Web数据挖掘与持续自进化训练的结合，解决环境真实性与训练信号稀疏性的双重瓶颈。

## 核心方法

### POMDP建模与多环境参数化

Agent-World将多轮智能体交互建模为POMDP，其关键差异在于显式参数化每个环境为数据库与工具集对 $e = (D, F)$。数据库 $D$ 作为环境状态 $s_E$ 的主要载体，存储构成可变外部世界的结构化记录；工具集 $F = \{f_k\}$ 提供可执行接口，每个工具 $f \in F$ 作为可调用算子读取并可选写入数据库，从而诱导环境状态转移。这一设计将抽象的状态空间锚定到具体可执行的数据结构上，解决了传统POMDP建模中环境状态不可直接观测、难以验证的问题。

### 智能体环境-任务发现

该模块从真实世界环境主题出发，通过深度研究代理自主挖掘主题对齐的数据库与可执行工具接口。给定主题集 $\mathcal{M}$，代理 $\mathcal{G}$ 执行迭代检索与数据挖掘，利用操作系统工具进行结构化存储，生成环境数据库 $D^{(N)}(m)$。为提升数据库复杂度，引入复杂化过程 $\phi$，迭代提示代理扩展主题特定数据库：

$$D^{(n+1)}(m) = \phi(D^{(n)}(m), m, \mathcal{T}), \quad n = 0, \dots, N-1$$

该公式的物理含义是通过多轮迭代逐步丰富数据库的规模与结构，使其更贴近真实环境需求。工具接口生成后，通过编译验证与单元测试交叉验证，仅保留测试准确率 $Acc(\hat{f}; \hat{C}_f) > 0.5$ 且环境包含至少一个有效工具与测试用例的工具集 $F(m)$。这一设计解决了纯LLM生成工具缺乏可执行性与可靠性的问题，确保工具接口与数据库状态的一致性。

### 持续自进化智能体训练

该模块通过多环境强化学习在“智能体-工具-数据库”交互轨迹上训练智能体，使用可执行奖励实现状态感知监督。核心创新在于引入诊断代理 $\delta$，输入每任务失败轨迹、环境错误统计与元数据，输出弱环境集 $W^{(r)} \subseteq E_{arena}$ 与任务生成指南 $G_{guide}^{(r)}(m)$。基于诊断结果，对弱环境执行数据库复杂化 $D^{(N)}(m) \leftarrow \phi(D^{(N)}(m), \cdot)$，并生成针对性任务集 $X_{target}^{(r)}$，继续强化学习获得新策略 $\pi_{\theta}^{(r+1)}$。该闭环机制解决了现有环境扩展方法缺乏持续诊断与针对性优化的问题，使智能体策略与环境复杂度协同进化，避免单轮训练导致的泛化能力不足。

## 实验评估

实验在23个基准上进行，覆盖智能体工具使用、高级AI助手、软件工程、深度研究与通用推理。基线包括前沿专有模型（GPT-5.2 High、Claude Sonnet-4.5）、开源基础模型（DeepSeek-V3.2-685B、Qwen3-8B/14B/32B/235B-A22B）及环境扩展方法（Simulator-8B、EnvScaler-8B、AWM-8B/14B、ScaleEnv-8B）。Agent-World-8B在 $\tau_2$-Bench、BFCL V4、MCP-Mark上分别达到61.8%、51.4%、8.9%，显著优于EnvScaler-8B（37.9%、47.6%、9.5%）及Qwen3-235B-A22B（26.2%、45.4%、5.8%）。Agent-World-14B进一步提升至65.4%、55.8%、13.3%，在BFCL V4上超越DeepSeek-V3.2-685B（54.1%）。

| 方法 | $\tau_2$-Bench Avg. | BFCL V4 Avg. | MCP-Mark Avg. |
| :--- | :--- | :--- | :--- |
| Agent-World-8B | 61.8 | 51.4 | 8.9 |
| Agent-World-14B | 65.4 | 55.8 | 13.3 |
| EnvScaler-8B | 37.9 | 47.6 | 9.5 |
| Qwen3-235B-A22B | 26.2 | 45.4 | 5.8 |

自进化轮次分析显示，Agent-World-14B在两轮进化后，$\tau_2$-Bench/BFCL-V4/MCP-Mark从45.3%/52.4%/29.5%提升至50.5%/55.8%/38.1%。MCP-Mark提升幅度最大（+8.6%），表明诊断机制对状态追踪与深度交互场景尤为有效。环境规模扩展分析显示，平均得分从18.4%提升至38.5%（+20.1点），其中MCP-Mark（Postgres）从4.8%提升至19.9%，BFCL（WebSearch）从7.0%提升至47.0%，验证了环境多样性对跨环境泛化的正向影响。

评估边界方面，论文未报告置信区间，数值比较需谨慎；未对比纯提示工程基线（如ReAct），无法隔离架构贡献与骨干网络贡献；真实Web数据的隐私与稳定性对训练可复现性的影响未量化，代码与超参数细节虽提供项目页面，但环境挖掘流程的自动化程度与人工干预比例未明确披露。

## 关联研究分析

从问题动机看，Agent-World与Agent0、Tool-R0同属自进化路线，但核心差异在于环境来源。Agent0与Tool-R0依赖程序化合成环境，虽可验证但易与真实世界交互逻辑脱节；Agent-World通过Web挖掘真实数据库，将环境从“模拟”升级为“真实”，解决了合成环境保真度不足的问题。这一差异的根源在于任务特性：长程状态依赖任务对环境的真实交互逻辑要求更高，纯合成环境难以捕捉数据库状态转移的细微差别。

从方法设计看，Agent-World与EnvScaler、AWM同属环境扩展路线，但关键差异在于训练机制。EnvScaler与AWM采用单轮训练，环境扩展后直接用于RL，缺乏对智能体弱点的诊断与针对性优化；Agent-World引入诊断代理与闭环扩展，使环境复杂度与智能体能力协同进化。这一差异解决了单轮训练导致的泛化能力不均问题，但诊断代理如何量化“能力缺口”以指导任务生成，论文未给出细粒度机制，仅描述为“输入失败轨迹与错误统计”，其自动化程度与准确性对训练效率的影响尚未验证。

## 总结

Agent-World要解决的核心矛盾是真实环境稀缺与自进化训练机制缺失的双重瓶颈。现有环境扩展方法虽提升了规模，但缺乏利用环境反馈进行持续诊断与针对性优化的机制，导致智能体在跨环境泛化上表现不均。Agent-World通过Web挖掘真实数据库构建1978个可执行环境，并引入“诊断-扩展”闭环自进化训练，使智能体策略与环境复杂度协同进化。实验证明，Agent-World-14B在BFCL V4上达到55.8%，超越DeepSeek-V3.2-685B（54.1%），验证了跨环境泛化的有效性。然而，其在 $\tau_2$-Bench上61.8%的成绩仍低于多智能体共享状态架构CaveAgent的80.0%，暴露了单智能体架构在多轮状态一致性任务上的局限。当环境规模从100扩展至500时，性能提升是否呈现边际递减，以及诊断代理的自动化程度对训练效率的具体影响，论文未给出回答。
