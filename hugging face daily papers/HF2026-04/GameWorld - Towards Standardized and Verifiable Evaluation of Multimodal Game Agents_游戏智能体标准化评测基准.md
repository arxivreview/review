# HuggingFace最新推荐论文 ｜GameWorld: Towards Standardized and Verifiable Evaluation of Multimodal Game Agents ｜游戏智能体标准化评测基准

研究机构：新加坡国立大学、英国牛津大学

作者：Mingyu Ouyang、Siyuan Hu、Kevin Qinghong Lin 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2604.07429)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.07429)

> 多模态大语言模型（MLLM）作为游戏智能体时，面临动作接口异构、实时延迟耦合及结果验证主观三大瓶颈，导致现有基准无法区分决策质量与响应速度。GameWorld 通过浏览器沙箱暂停机制解耦推理延迟，并引入基于序列化游戏状态的可验证评估器，实现了确定性、可复现的标准化评测。该基准揭示了当前模型在长程任务完成上的巨大差距，但其暂停机制是否掩盖了真实部署中的时序失效问题，仍存疑。

## 研究背景

游戏环境要求智能体在动态视觉场景中持续进行感知、规划与精确控制，这与静态图形用户界面（GUI）操作存在本质差异。GUI Agent 的核心挑战在于结构化数据（如 HTML）的获取困难与跨平台泛化，而游戏环境引入了实时物理规则与不可逆后果，使得单步错误累积效应更为显著。理解本文需把握两个关键概念：一是“动作接口异构性”，即不同模型输出格式（如坐标点击 vs. 语义指令）导致评估标准不统一；二是“状态可验证性”，即通过底层游戏 API 直接读取变量而非依赖视觉启发式判断，从而消除感知噪声。

现有游戏基准如 LMGame-Bench 和 BALROG 虽提升了评测规模，但仍依赖 OCR 或 VLM-as-judge 等主观方法，且未解决实时交互中推理延迟与动作时序的耦合问题。OSWorld 等计算机使用基准证明了在线交互评估的价值，但缺乏针对游戏高频动态场景的标准化协议。GameWorld 的切入点在于构建一个“暂停-验证”闭环：通过沙箱暂停游戏执行以隔离延迟影响，同时利用游戏内部状态变量进行确定性结果判定，从而将评估焦点从“响应速度”回归到“决策质量”。

## 核心方法

### 统一控制空间与接口标准化

GUI Agent 领域通常直接评估模型输出的动作序列，但游戏场景下模型输出格式差异巨大（如 `left_click(x,y)` 与 `move_right()`）。GameWorld 定义了一个原子事件层（Unified Control Space），包含 `mouse_move`、`key_down` 等底层事件，将两种智能体接口——计算机使用智能体（CUA）和通用多模态智能体（Generalist Agent）——的输出均映射至此空间。CUA 直接输出底层控制指令，而 Generalist Agent 输出语义动作，经确定性解析器（Semantic Action Parsing）转换为底层事件。这一设计消除了接口层面的随机性，使得不同抽象层级的模型可在同一执行器下公平对比。

$$
\text{Action}_{\text{exec}} = \mathcal{P}(\text{Action}_{\text{model}})
$$

其中 $\mathcal{P}$ 为确定性解析函数，将语义动作映射为固定的底层交互命令，确保解析过程无随机性。

### 暂停沙箱与状态可验证评估

传统游戏评测常因模型推理延迟导致动作失效，混淆了“决策错误”与“时序错误”。GameWorld 引入浏览器沙箱，在模型推理期间暂停游戏执行，使分数仅反映决策质量。评估器通过注入 JavaScript 桥接层，直接读取序列化 `gameAPI` 状态（如分数、生命值、坐标），计算任务成功率（SR）和归一化进度（PG）。PG 定义为从起始分数到目标分数的归一化进展，而非最终状态，允许智能体在失败重置后保留历史最佳进度。

$$
\text{PG}_i = \frac{q_{i,\text{max}} - b_i}{\tau_i - b_i}
$$

其中 $q_{i,\text{max}}$ 为运行中观察到的最高分数，$b_i$ 为起始分数，$\tau_i$ 为目标分数。该公式量化了智能体在固定步数预算内达到的最大相对进展，避免了单次早期错误导致整个运行归零。

## 实验评估

实验在 GameWorld 基准上进行，涵盖 34 款浏览器游戏和 170 个任务，评估 18 个模型-接口对，包括 Claude-Sonnet-4.6、GPT-5.2、Qwen3-VL 系列等。基线覆盖了专有与开源模型，但缺乏专门针对游戏优化的微调模型，主要测试预训练模型的泛化能力。

| 模型 | 接口 | 总体 SR (%) | 总体 PG (%) |
| :--- | :--- | :--- | :--- |
| Gemini-3-Flash-Preview | Generalist | 21.2 | 41.9 |
| GPT-5.2 | Generalist | 20.6 | 40.6 |
| Seed-1.8 | CUA | 20.0 | 39.8 |
| Claude-Sonnet-4.6 | Generalist | 20.6 | 39.3 |
| Novice Player (Human) | - | 55.3 | 64.1 |

最佳模型 Gemini-3-Flash-Preview 的 PG 为 41.9%，远低于人类新手玩家的 64.1%，SR 仅为 21.2%，表明当前模型虽能取得部分进展，但难以可靠完成任务。重复实验显示，Qwen3-VL-30B-A3B 在 CUA 接口下的 PG 标准差为 1.1，SR 标准差为 1.2，验证了基准的稳定性。

消融分析聚焦于接口差异与实时性影响。Generalist Agent 在符号推理类游戏中表现优于 CUA，但在需要精确时序控制的游戏（如 Flappy Bird）中，CUA 因直接输出底层指令而更具优势。GameWorld-RT 变体显示，当移除暂停机制后，推理延迟成为显著瓶颈，模型性能下降幅度与推理速度正相关，证实了实时交互中“速度-正确性-时序”的紧耦合。

评估边界方面，GameWorld 仅使用浏览器游戏，未涵盖 3D 引擎或复杂物理模拟，可能低估了空间导航难度。代码与超参数已公开，但游戏 API 的定制化注入增加了复现门槛。

## 关联研究分析

从问题动机看，GameWorld 与 OSWorld 同属在线交互基准，但 OSWorld 侧重桌面应用的多步工作流，而 GameWorld 聚焦高频动态控制。OSWorld 的评估依赖任务完成状态，未显式解耦推理延迟，导致无法区分“慢但正确”与“快但错误”的决策。GameWorld 的暂停机制虽解决了延迟混淆，但可能掩盖了真实部署中因延迟导致的动作失效问题，这在 OSWorld 的静态任务中不显著，但在游戏场景中是核心挑战。

从方法设计看，GameWorld 的状态可验证评估器与 AndroidWorld 的动态交互评估有相似之处，但 AndroidWorld 依赖模拟器状态，而 GameWorld 通过 JavaScript 桥接直接读取游戏内部变量，实现了更细粒度的过程诊断。然而，AndroidWorld 支持真实应用环境，而 GameWorld 限于浏览器游戏，其泛化性受限于游戏机制的多样性。此外，GameWorld 未引入强化学习（RL）训练，仅评估预训练模型，这与 DigiRL 等通过 RL 提升长程任务性能的方法形成对比，暗示游戏智能体可能需要专门的在线学习策略以克服时序控制瓶颈。

## 总结

GameWorld 旨在解决游戏智能体评测中动作接口异构与结果验证主观的矛盾，通过暂停沙箱解耦延迟，并利用游戏 API 状态实现确定性评估。实验表明，最佳模型 PG 为 41.9%，远低于人类新手的 64.1%，揭示了当前 MLLM 在长程任务完成上的显著差距。该基准的边界在于其暂停机制可能低估了实时部署中的时序失效，且仅覆盖浏览器游戏，未涉及复杂物理环境。当模型推理延迟超过游戏帧间隔时，暂停机制下的决策质量是否仍能转化为实时环境中的有效动作，论文未给出回答。
