# HuggingFace最新推荐论文 ｜Narrative-Driven Paper-to-Slide Generation via ArcDeck ｜叙事驱动的学术论文转幻灯片生成

研究机构：美国伊利诺伊大学厄巴纳-香槟分校

论文原文见 [arXiv](https://arxiv.org/abs/2604.11969)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2604.11969)

> 学术论文转幻灯片的核心难题在于如何将密集的文本逻辑转化为具有连贯叙事流的视觉序列，现有方法因缺乏显式结构建模而陷入局部摘要或碎片化生成的困境。ArcDeck 通过引入修辞结构理论（RST）话语树与全局承诺机制，将生成任务重构为叙事重建问题。该方法利用多智能体迭代精炼大纲，在自建基准上显著提升了叙事连贯性。其价值在于提供了结构化的生成范式，但受限于单一领域数据与缺乏外部知识检索，事实准确性与泛化能力存疑。

## 研究背景

将长篇学术论文转化为幻灯片时，模型需同时处理内容提取、结构重组与视觉布局。这一过程依赖对文本修辞关系的理解，即段落间如何通过解释、阐述或并列关系构建逻辑链条。修辞结构理论（RST）为这种层级化依赖提供了形式化描述，但此前未被用于驱动视觉生成。同时，长上下文窗口导致模型在处理全文时丢失全局意图，使得局部生成的幻灯片缺乏整体叙事一致性。

现有自动幻灯片生成方法主要分为三类：直接输入全文的端到端生成、按章节独立处理的模块化生成，以及基于大纲的多智能体框架。前两类方法因缺乏全局规划，导致内容碎片化或叙事断裂；多智能体框架虽引入大纲规划，但大纲生成本身依赖一次性处理全文，难以维持细粒度的结构连贯性。这些方法的共同缺陷在于缺乏对源文档修辞结构的显式建模，无法有效保留概念间的逻辑依赖。ArcDeck 的切入点在于将 RST 话语解析作为结构先验，结合全局承诺文档，通过迭代精炼机制解决长文档叙事重构中的上下文丢失问题。

## 核心方法

### 方法参照系

本文问题属于多智能体幻灯片生成范畴，标准流程为“解析-规划-生成”。与通用流程的关键差异在于，本文在规划阶段引入了显式的修辞结构建模，而非依赖隐式的语言模型注意力机制进行内容分组。

### 话语树解析与全局承诺

传统方法直接基于文本摘要生成大纲，导致局部修辞关系在压缩过程中丢失。ArcDeck 首先通过话语解析器（Discourse Parser）为每个章节构建二元 RST 话语树，将段落视为基本话语单元（EDU），并标注核-卫星（NS）或多核（MN）关系。该过程可形式化为：

$$ T_s = \text{Parse}(P_s, \mathcal{R}) $$

其中 $P_s$ 为章节 $s$ 的段落集合，$\mathcal{R}$ 为 RST 关系集合，$T_s$ 为生成的层级化话语树。随后，承诺构建器（Commitment Builder）生成全局承诺文档，包含论文主旨、叙事脊柱与章节计划，作为后续生成的持久条件信号。这一设计解决了单一 LLM 在长文本中无法维持全局意图一致性的问题，确保幻灯片序列遵循预设的叙事逻辑。

### 叙事精炼循环

一次性大纲生成往往无法完全对齐全局承诺，导致叙事流断裂。ArcDeck 引入叙事精炼循环（Narrative Refinement Loop），由幻灯片规划器、叙事批评者与叙事判断者组成闭环。规划器基于话语树生成初始大纲，批评者依据全局承诺评估大纲的叙事流、章节平衡与冗余度，判断者决定是否需要修订。该过程迭代执行直至大纲“就绪”或达到最大迭代次数（3次）。修订过程可表示为：

$$ O_{k+1} = \text{Revise}(O_k, F_c, F_j) $$

其中 $O_k$ 为第 $k$ 轮大纲，$F_c$ 与 $F_j$ 分别为批评者与判断者的反馈。这种迭代机制通过局部修正逐步优化全局叙事连贯性，弥补了单次生成在结构规划上的不足。

## 实验评估

实验在自建 ArcBench 基准上进行，包含 100 对来自 CVPR、ICML 等顶会的论文-幻灯片对。基线覆盖 HTML 直接生成、Paper2Poster、PPTAgent 与 SlideGen 四种范式，但缺失 SlideCoder 等基于代码生成的强基线。

| 方法 | VLM-as-Judge NF (GPT-5) | VLM-as-Judge NF (Qwen3) | Pairwise Win Rate vs. SlideGen (GPT-5) |
|---|---|---|---|
| ArcDeck | 99.40 | 98.31 | 50.6 |
| SlideGen | 97.36 | 94.16 | – |
| PPTAgent | 84.86 | 80.44 | – |
| HTML | 95.22 | 94.07 | – |

ArcDeck 在叙事流（NF）指标上显著优于基线，尤其在 GPT-5 骨干下达到 99.40 分。然而，在与 SlideGen 的成对比较中，ArcDeck 胜率仅为 50.6%，表明其在视觉布局或内容覆盖上可能未全面占优。

消融实验显示，移除话语解析器导致 NF 分数从 9.70 降至 7.50，移除全局承诺降至 7.52，移除精炼循环降至 8.68。话语解析器的贡献最大，证实了显式结构建模对叙事连贯性的关键作用。精炼循环的边际收益递减，从第 1 轮到第 3 轮，NF 分数从 4.18 提升至 7.34，但胜率从 56.4% 升至 100% 后趋于平稳。

评估协议依赖 VLM-as-Judge，存在自我偏好偏差风险，且未报告置信区间。ArcBench 仅包含 AI 领域论文，缺乏跨学科验证。代码已开源，但超参数与 GPU 配置未在正文中详细披露，可复现性受限。

## 关联研究分析

从问题动机看，ArcDeck 与 SlideGen 均针对多智能体幻灯片生成，但 SlideGen 侧重视觉布局的模板匹配，而 ArcDeck 聚焦叙事逻辑的重构。这一差异源于任务特性的不同：SlideGen 假设内容已确定，重点在于视觉呈现；ArcDeck 则认为内容组织本身是核心挑战，需通过 RST 解析解决。然而，ArcDeck 未使用 RAG 技术，依赖内部解析，这与领域共识中“RAG 解决幻觉”的观点相悖。在无外部知识检索的情况下，如何保证学术事实准确性，论文未给出明确回答。

从方法设计看，ArcDeck 与 Paper2Poster 同属多智能体框架，但 Paper2Poster 依赖视觉反馈循环，而 ArcDeck 引入 RST 话语树作为结构先验。这一设计选择暗示了修辞结构在长文档生成中的潜在价值，但 RST 解析的准确性依赖于 LLM 的预训练能力，未进行独立验证。若 LLM 对修辞关系的理解存在偏差，话语树的质量将直接影响生成效果。此外，ArcDeck 的全局承诺机制与教育内容生成中的“认知对齐”框架有相似之处，但前者针对叙事流，后者针对认知层级，两者在目标函数上存在本质差异。

## 总结

ArcDeck 旨在解决学术论文转幻灯片中的叙事连贯性问题，通过 RST 话语树与全局承诺机制，将生成任务重构为叙事重建问题。该方法在 ArcBench 上实现了 99.40 的叙事流分数，显著优于基线，证明了显式结构建模的有效性。然而，其边界在于仅验证了 AI 领域数据，且缺乏 RAG 支持，事实准确性未得到充分保障。当支持集扩展到非学术文本时，RST 解析的泛化能力是否依然有效，论文未给出回答。
