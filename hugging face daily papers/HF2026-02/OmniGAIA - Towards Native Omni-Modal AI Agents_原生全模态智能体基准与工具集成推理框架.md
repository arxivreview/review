# HuggingFace最新推荐论文 ｜OmniGAIA: Towards Native Omni-Modal AI Agents ｜原生全模态智能体基准与工具集成推理框架

研究机构：中国人民大学、东南大学

论文原文见 [arXiv](https://arxiv.org/abs/2602.22897)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.22897)

> 通用人工智能助手需在真实场景中联合处理视觉、音频与语言，并依赖外部工具进行长程推理，但现有模型多局限于双模态感知，缺乏原生全模态下的工具集成推理能力。现有基准侧重短片段感知，无法评估多跳推理与多轮工具调用，导致模型在开放域任务中表现受限。本文通过事件图驱动构建全模态基准，并提出支持主动感知的工具集成推理智能体，验证了工具策略而非参数规模是性能瓶颈。该工作填补了全模态智能体评估空白，但开源模型与闭源SOTA间仍存在显著差距，且高难度任务上的推理崩溃问题未获根本解决。

## 研究背景

构建通用AI助手要求模型能同时处理视频、音频与文本，并在长上下文中进行逻辑推理。然而，当前多模态大语言模型（MLLMs）主要聚焦于视觉-语言或音频-语言的双模态交互，难以应对真实世界中模态交织的复杂场景。这种局限导致模型在面对需要跨模态证据整合与外部知识验证的任务时，缺乏必要的认知架构。

现有全模态基准如OmniBench和WorldSense主要关注短时长媒体的感知能力，忽略了长程推理与工具使用。这导致评估体系无法反映智能体在开放域中通过搜索、浏览等工具获取缺失信息的能力。同时，开源全模态模型在工具集成推理方面存在显著短板，仅增加参数规模（如560B模型）并未带来相应性能提升，表明瓶颈在于推理策略而非模型容量。

本文切入点在于构建一个原生全模态智能体基准，并设计相应的训练范式。通过引入事件图结构对齐跨模态证据，并采用工具集成推理（Tool-Integrated Reasoning, TIR）范式，本文旨在解决现有方法在长程多跳推理中证据获取不足与推理链断裂的问题，从而推动全模态智能体从被动感知向主动推理演进。

## 核心方法

### 方法参照系

本文问题属于多模态智能体推理范畴，但区别于传统单模态或双模态问答。标准流程通常依赖模型内部参数记忆进行一次性生成，而本文要求模型在长视频/音频流中动态调用外部工具（搜索、代码执行）以获取缺失证据，并基于多模态输入进行多步规划。关键差异在于引入了“主动感知”与“工具集成”机制，打破了静态输入-输出范式。

### 事件图驱动的任务构建

为生成需多跳推理的复杂任务，本文提出全模态事件图构建流程。首先，利用Gemini-3-Flash从视频、音频、图像中提取细粒度时间对齐信号（如ASR时间戳、OCR文本、场景描述）。随后，使用DeepSeek-V3.2作为代理，通过跨模态检索与外部工具扩展初始事件图，建立实体间的因果与逻辑关联。最后，通过“事件模糊化”（Event Fuzzification）将具体实体替换为类型或掩码关键属性，迫使模型遍历完整逻辑路径。该设计解决了直接查询图节点导致的任务过于简单、无法评估多跳推理能力的问题。

$$
G_{expanded} = G_{initial} \cup \{ (e_i, e_j, r_k) \mid e_i, e_j \in \mathcal{E}, r_k \in \mathcal{R}, \text{derived via } \mathcal{T}_{tool} \}
$$

此公式表示扩展后的事件图由初始图与通过工具$\mathcal{T}_{tool}$推导出的新实体关系三元组组成，确保任务包含需外部验证的逻辑链。

### 工具集成推理与主动感知

OmniAtlas采用工具集成推理范式，将智能体轨迹定义为$\tau = [(s_t, a_t, o_t)]_{t=0}^T$，其中$s_t$为推理思考，$a_t$为动作（工具调用或最终回答），$o_t$为工具返回的观察。模型根据历史交互生成下一步思考与动作，当检测到工具调用时暂停生成并执行工具，将观察追加至上下文。此外，引入主动全模态感知，允许模型通过`read_video`、`read_audio`等操作按需读取特定片段或区域，避免全量下采样导致的细节丢失。该设计解决了长媒体处理中Token开销过高与关键细节被丢弃的矛盾，使模型能聚焦于推理所需的关键证据。

$$
(s_{t+1}, a_{t+1}) = \mathcal{M}(\mathbf{x}, \tau_{1:t})
$$

此公式表示模型$\mathcal{M}$基于用户指令$\mathbf{x}$与历史轨迹$\tau_{1:t}$生成下一思考与动作，实现了推理与工具调用的动态交替。

## 实验评估

实验在OmniGAIA基准上进行，包含360个跨9个领域的任务，要求多跳推理与多轮工具使用。基线覆盖闭源SOTA（Gemini-3-Pro）与开源模型（Qwen3-Omni、LongCat-Flash-Omni）。结果显示，Gemini-3-Pro达到62.5 Pass@1，而Qwen3-Omni仅为13.3，LongCat-Flash-Omni（560B）为11.1，表明参数规模并非决定性因素。OmniAtlas将Qwen3-Omni提升至20.8，Qwen-2.5-Omni-7B从3.6提升至13.3，验证了训练范式的有效性。

| 模型 | 参数量 | Pass@1 (%) | 工具调用次数 (均值) |
| :--- | :--- | :--- | :--- |
| Gemini-3-Pro | - | 62.5 | - |
| Qwen3-Omni | 30B | 13.3 | ~0 |
| OmniAtlas-30B | 30B | 20.8 | - |
| LongCat-Flash-Omni | 560B | 11.1 | - |

消融分析显示，OmniAtlas-SFT贡献了主要增益（Qwen3-Omni: 13.3→18.9），OmniDPO进一步降低感知、工具使用与推理错误率（至20.8）。错误分析表明，工具使用无效（35.3%-91.9%）与推理错误（15.8%-79.7%）是主要失败模式，尤其在Hard任务中，开源模型工具误用率接近90%，导致推理链崩溃。Gemini-3-Pro在感知与工具使用错误率上显著低于开源模型，反映其更成熟的规划与验证能力。

评估采用LLM-as-a-Judge（DeepSeek-V3.2）判断答案等价性，报告Pass@1。局限在于缺乏置信区间报告，且Hard子集性能仍低（Gemini-3-Pro降至38.5），表明深度多跳推理仍是瓶颈。代码与数据已开源，但训练细节（如树探索深度$k=3$）可能影响复现性。

## 关联研究分析

从问题动机看，本文与GAIA（Mialon et al., 2024）同属智能体推理基准，但GAIA仅限文本模态，而OmniGAIA扩展至视频、音频与图像，强调原生全模态感知。差异根源在于任务特性：全模态输入需处理时间对齐与模态互补，而文本任务仅依赖语义连贯。本文通过事件图结构显式建模跨模态关系，解决了文本基准无法覆盖的感知-推理耦合问题。

从方法设计看，OmniAtlas与Qwen3-Omni（Xu et al., 2025b）同属全模态基础模型，但Qwen3-Omni侧重统一Token化与投影接口，缺乏工具集成推理能力。本文通过TIR范式与主动感知机制，弥补了开源模型在外部证据获取上的不足。然而，本文未探讨工具调用频率与推理深度的权衡，高工具调用次数（>10-20）并未保证成功，反而出现“thrashing”行为，这一效率问题在现有全模态智能体研究中尚未得到系统解决。

## 总结

本文核心矛盾在于开源全模态模型缺乏工具集成推理能力，导致在长程多跳任务中性能远低于闭源SOTA。切入点在于通过事件图构建复杂任务，并设计TIR范式与主动感知机制，使模型能动态获取外部证据。实验证明OmniAtlas将Qwen3-Omni从13.3提升至20.8，但Hard任务上仍仅38.5（Gemini-3-Pro），且工具误用率高达90%。边界在于主动感知虽减少Token开销，但未解决工具调用效率低下问题，且开源模型在感知基础能力上仍落后。当工具调用次数超过10次时，模型是否陷入无效探索而非有效推理，论文未给出量化回答。
