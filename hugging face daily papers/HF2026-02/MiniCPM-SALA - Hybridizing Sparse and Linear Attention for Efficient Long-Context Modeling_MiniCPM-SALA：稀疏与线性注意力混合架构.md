> 长上下文建模面临计算复杂度 $O(N^2)$ 与键值缓存（KV Cache）内存线性增长的双重瓶颈，现有稀疏或线性注意力方案均存在精度或效率缺陷。MiniCPM-SALA 通过 1:3 比例交错 InfLLM-V2 稀疏层与 Lightning Attention 线性层，结合持续训练转换范式，在保持全注意力模型通用能力的同时实现 1M token 上下文支持。该架构在单卡 A6000D 上实现 256K 序列 3.5 倍推理加速，但静态稀疏模式在极长序列下的信息保持能力仍存疑。

## 研究背景

当模型处理百万级 token 的代码库或多轮对话时，标准 Transformer 的自注意力机制因计算量随序列长度平方增长而陷入延迟困境，同时推理阶段需存储所有历史 token 的键值状态，导致内存占用线性膨胀。这一结构性冲突使得高效长上下文建模成为大语言模型（LLM）应用从问答向深度理解、代码工程及智能体任务扩展的关键障碍。

该领域的核心矛盾在于计算效率与信息保真度的权衡。稀疏注意力通过限制计算范围降低复杂度，但受限于“稀疏计算、密集存储”特性，仍需保留完整 KV Cache 以支持检索；线性注意力将复杂度降至 $O(N)$，却因固定状态导致信息过度压缩，在精确检索任务上表现不佳。MiniCPM-SALA 的切入点在于混合这两种机制，利用稀疏层的高保真检索能力与线性层的全局效率，并通过持续训练将预训练 Transformer 模型转化为混合架构，避免从头训练的高昂成本。

## 核心方法

### 混合注意力架构设计

混合架构旨在平衡检索精度与计算效率，通常采用全注意力层与高效递归层交错排列。MiniCPM-SALA 的关键差异在于采用 1:3 的固定比例，即 25% 层为 InfLLM-V2 稀疏注意力，75% 层为 Lightning Attention 线性注意力，并通过 HALO 层选择算法确定稀疏层位置而非均匀交错。

### 稀疏-线性层协同机制

稀疏层采用 InfLLM-V2，其优势在于不引入额外参数且可无缝切换密集/稀疏模式，便于继承预训练权重。线性层选用 Lightning Attention，因其功能接近标准 Softmax 注意力，有助于缓解参数适配复杂度。该设计解决了纯线性架构在长程信息处理中的精度瓶颈，同时避免了纯稀疏架构的内存膨胀问题。

$$
\text{Attention}_{\text{hybrid}} = \alpha \cdot \text{InfLLM-V2}(Q, K, V) + (1-\alpha) \cdot \text{Lightning}(Q, K, V)
$$

其中 $\alpha=0.25$ 表示稀疏层占比，该公式体现了两种注意力机制在层级的加权融合，而非单层的内部混合。

### 混合位置编码与门控机制

为平衡位置感知与长程记忆，MiniCPM-SALA 引入混合位置编码（HyPE）：线性层应用旋转位置编码（RoPE）以保留相对顺序，稀疏层移除 RoPE 以防止长距离信息衰减。此外，所有注意力层后添加输出门，通过调节信息流缓解注意力汇聚问题。

$$
\text{Output} = \text{Gate}(\text{Attention}(Q, K, V)) \odot \text{FFN}(\text{Norm}(\text{Input}))
$$

该公式表明输出门对注意力结果进行逐元素调制，确保注意力权重分布的灵活性，防止模型过度聚焦于特定 token。

## 实验评估

实验在 RULER、MRCR、NoLiMa 等长上下文基准上评估，基线包括 Qwen3-8B、Nemotron-Nano-v2-9B 等全注意力模型，但缺失纯线性/SSM 基线（如 Mamba2）。MiniCPM-SALA 在 RULER 128K 上得分 89.37，NoLiMa 128K 上得分 23.86，长上下文平均分 38.97，显著优于多数基线。

| 基准 | 序列长度 | MiniCPM-SALA | Qwen3-8B |
| :--- | :--- | :--- | :--- |
| RULER | 128K | 89.37 | 71.74 |
| NoLiMa | 128K | 23.86 | 11.25 |
| MRCR | 128K-8N | 7.54 | 7.54 |

在推理效率上，MiniCPM-SALA 在 A6000D 上 256K 序列的首 token 时间（TTFT）从 Qwen3 的 180.8s 降至 51.6s，支持 1M token 上下文，而 Qwen3-8B 在此长度下因内存溢出（OOM）失败。

消融实验显示，持续训练转换仅消耗约 2T token，相当于从头训练 MiniCPM-4.0（8T token）的 25%。架构转换阶段（HALO）仅训练线性层参数，序列长度 512，数据量 1.3B token，确保训练稳定性。长衰减训练阶段将序列长度从 4K 逐步扩展至 520K，数据量从 102.2B 降至 50.6B，学习率从 $3 \times 10^{-4}$ 衰减至 $3.75 \times 10^{-5}$。

评估边界方面，论文未报告置信区间，且 RULER 短序列（4k-16k）结果未与领域 SOTA（如 LongCat Sparse Attention 64.43）直接对比，因协议不同。代码与超参数已开源，但 1M 上下文下的检索精度随长度增加的衰减曲线未详细展示。

## 关联研究分析

从问题动机看，MiniCPM-SALA 与 Jamba 同属混合架构路线，但 Jamba 侧重从头预训练，而本文强调持续训练转换。这一差异源于任务特性：Jamba 追求架构灵活性，本文则关注工程落地成本。持续训练是否导致稀疏层与线性层协同不足，论文未给出明确回答，仅通过实验验证其有效性。

从方法设计看，本文与 InfLLM-V2 的静态稀疏模式一致，但领域共识认为动态稀疏优于静态。MiniCPM-SALA 在 1M 长度下表现优异，暗示静态稀疏在特定架构配置下可能具备足够鲁棒性，但缺乏理论支撑。与 HALO 相比，本文保留了首尾层不转换，并省略了 HALO 的最终微调步骤，转而依赖更长的持续预训练，这一设计选择对训练稳定性的影响尚未充分消融。

## 总结

MiniCPM-SALA 解决了长上下文建模中计算效率与检索精度的矛盾，通过 1:3 稀疏-线性混合架构与持续训练转换，在保持通用能力的同时实现 1M token 上下文支持。实验证明其在 256K 序列上实现 3.5 倍推理加速，RULER 128K 得分 89.37。然而，静态稀疏模式在极长序列下的信息保持能力缺乏理论保证，且缺失纯线性基线对比。当序列长度超过 1M 时，静态稀疏是否面临信息丢失，论文未给出回答。
