> 统一多模态模型在长尾知识与实时信息场景下存在认知边界，静态预训练导致其无法处理动态事件与复杂逻辑推导。现有智能体框架多局限于提示词优化或单一检索，缺乏对隐式约束的深层推理。本文提出 Mind-Brush，通过“意图分析-多模态搜索-知识推理”的协同工作流，将生成转化为动态认知过程。该框架在知识密集型任务上显著提升了开源模型性能，但其推理模块在纯逻辑任务上的增益有限，且动态路由策略缺乏消融验证。

## 研究背景

当用户指令包含训练截止后的新闻事件或复杂的几何逻辑时，传统文本到图像模型（T2I）因依赖静态参数化记忆而失效。这种失效源于“理解-生成鸿沟”，即模型虽能解析语义，但无法将抽象意图转化为符合事实的像素细节。为解决此问题，统一多模态模型（UMM）尝试在单一架构中融合理解与生成，但受限于预训练数据的时效性，其认知边界依然固化，难以应对开放世界中的长尾概念与实时动态。

当前主流的智能体生成方法主要分为两类：一类如 T2I-Copilot 和 PromptSculptor，聚焦于将简短指令细化为详细描述，但缺乏外部知识获取能力；另一类如 Think-Then-Gen，通过思维链分解生成步骤，但推理仅依赖内部化知识，无法验证实时事实。这些方法在 GenEval 等静态基准上表现尚可，但在需要主动检索和复杂推理的任务中表现脆弱。Mind-Brush 的切入点在于将生成过程重构为“思考-研究-创造”的认知闭环，通过引入外部多模态证据锚定和内部逻辑推导，弥补静态模型的认知缺口。

## 核心方法

### 认知缺口检测与动态路由

Mind-Brush 将生成任务形式化为分层序贯决策过程 $M = \langle S, A, \pi, E \rangle$。其核心在于意图分析智能体（$A_{intent}$）作为元规划器，通过 5W1H 范式解析用户指令 $I$ 和可选图像 $I_{img}$，识别出模型参数化知识之外的认知缺口 $Q_{gap}$。

$$
Q_{gap} = \{ q_i \mid q_i \notin \text{ParametricKnowledge}(I, I_{img}) \}
$$

该公式定义了认知缺口为指令中无法被内部知识直接映射的实体或逻辑依赖。设计动机在于解决固定流水线无法适应不同任务复杂度的问题，通过动态路由策略，系统根据 $Q_{gap}$ 的性质决定激活搜索分支还是推理分支，从而避免在简单任务上浪费计算资源或在复杂任务上遗漏关键证据。

### 自适应知识补全与约束生成

针对识别出的缺口，Mind-Brush 执行双引擎补全。对于分布外（OOD）实体，认知搜索智能体（$A_{search}$）生成文本查询 $Q_{txt}$ 和视觉查询 $Q_{img}$，检索事实文档 $T_{ref}$ 和参考图像 $I_{ref}$，并更新指令上下文 $I'$ 和视觉查询 $Q'_{img}$。对于逻辑推导任务，知识推理智能体（$A_{reasoning}$）基于累积证据 $E_{search} = T_{ref} \cup I_{ref}$ 执行多步思维链（CoT）推理，产出显式结论 $R_{cot}$。

$$
E = E_{search} \cup R_{cot} = (T_{ref} \cup I_{ref}) \cup R_{cot}
$$

最终证据集 $E$ 构成了逻辑一致的认知上下文。概念审查智能体（$A_{review}$）随后对 $E$ 进行去噪，将其整合为结构化主提示 $P_{master}$。这一设计解决了检索证据冗余与用户意图冲突的问题，确保生成阶段（$A_{generation}$）在严格遵循事实边界的同时，忠实还原用户的创意愿景。

## 实验评估

Mind-Brush 在 Mind-Bench、WISE 和 RISEBench 上进行了评估，基线涵盖 GPT-Image、Nano Banana Pro 等闭源 UMM 及 FLUX、Bagel 等开源模型。实验使用 Qwen-Image 作为生成骨干，GPT-5.1 作为推理骨干，并调用 Google Search API 进行检索。

| 基准 | 模型 | 整体准确率/分数 | 关键子项表现 |
| :--- | :--- | :--- | :--- |
| Mind-Bench | Mind-Brush | 0.31 | SE: 0.54, Math: 0.14 |
| Mind-Bench | Qwen-Image | 0.02 | SE: 0.02, Math: 0.02 |
| WISE | Mind-Brush | 0.78 | Phys: 0.85, Chem: 0.68 |
| WISE | Qwen-Image | 0.44 | Phys: 0.50, Chem: 0.44 |
| RISEBench | Mind-Brush | 61.5 (Instr. Reas.) | App. Consis: 79.4 |
| RISEBench | Nano Banana | 80.2 (Instr. Reas.) | App. Consis: 61.2 |

Mind-Brush 将 Qwen-Image 在 Mind-Bench 上的准确率从 0.02 提升至 0.31，在 WISE 上较 Qwen-Image 提升 25.8% WiScore。然而，在 RISEBench 的指令推理维度上，Mind-Brush 的 61.5 分低于 Nano Banana 的 80.2 分，表明其在纯逻辑推理任务上仍落后于顶级闭源模型。

消融实验显示，知识推理智能体在推理驱动任务上带来显著增益，而认知搜索智能体在知识驱动任务上提升了 0.28 的准确率。两者协同使用时，整体准确率较单一模块分别提升 0.17 和 0.06，验证了搜索与推理的互补性。但论文未提供动态路由策略与固定流水线的对比消融，无法量化动态调度带来的具体收益。

评估采用 Checklist-based Strict Accuracy (CSA) 指标，要求所有子项通过才计为正确，这一严格标准可能低估了部分正确生成的价值。实验在 8 张 NVIDIA A100 80G GPU 上完成，代码已开源，但检索 API 的调用成本和延迟未详细报告，限制了其在实时场景下的可复现性评估。

## 关联研究分析

从知识获取机制看，Mind-Brush 与 ToolArtist 同属智能体生成框架，但两者在证据整合深度上存在差异。ToolArtist 侧重通过工具调用直接解决知识缺口，而 Mind-Brush 引入了概念审查智能体对检索证据进行逻辑一致性校验。这种差异源于任务特性：Mind-Bench 中的任务往往需要结合多个分散的事实片段进行综合推理，单纯的检索拼接易导致逻辑冲突，而 Mind-Brush 的 CoT 推理模块能显式解决这些冲突。然而，这种深度整合是否在所有知识密集型任务中均优于轻量级检索，论文未给出跨基准的对比数据。

从推理范式看，Mind-Brush 与 Think-Then-Gen 均强调生成前的思考，但 Think-Then-Gen 依赖内部化知识进行逻辑推导，而 Mind-Brush 将推理建立在外部检索证据之上。这一设计使得 Mind-Brush 在实时新闻等动态任务上具有优势，但在数学几何等依赖精确逻辑推导的任务上，其表现（Math: 0.14）远低于闭源模型。这暗示外部检索证据在提供事实锚点的同时，可能引入了噪声，干扰了纯逻辑推理的连贯性。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

Mind-Brush 旨在解决统一多模态模型在长尾知识与实时信息场景下的认知边界问题。其切入点在于将生成过程从静态映射转化为动态认知工作流，通过搜索与推理的双引擎协同，弥补静态预训练模型的缺陷。实验表明，该框架将 Qwen-Image 在 Mind-Bench 上的准确率从 0.02 提升至 0.31，并在 WISE 上实现了 25.8% 的性能提升。然而，其在 RISEBench 纯推理任务上的表现仍落后于顶级闭源模型，且动态路由策略缺乏消融验证。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
