# HuggingFace最新推荐论文 ｜AutoWebWorld: Synthesizing Infinite Verifiable Web Environments via Finite State Machines ｜基于有限状态机的可验证Web环境合成

研究机构：香港科技大学、北京大学

作者：Yifan Wu、Yiran Peng、Yiyu Chen 等 15 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.14296)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.14296)

> Web GUI智能体训练的核心瓶颈在于高质量交互轨迹的稀缺与验证成本。现有在线探索或人工演示方法因底层状态不可观测，被迫依赖昂贵且不一致的外部验证器。AutoWebWorld通过有限状态机（FSM）将环境状态显式化，利用广度优先搜索（BFS）生成确定性轨迹，实现了内在可验证的数据合成。该方法以极低单条成本产出大规模数据，验证了合成数据在真实基准上的缩放定律，但其FSM抽象对真实Web动态性的简化程度仍存疑。

## 研究背景

Web GUI智能体在长程任务中面临状态漂移与验证瓶颈的双重困境。智能体执行动作后仅能获取渲染后的UI截图，而网页内部状态（如购物车数量、筛选条件）对智能体不可见。这种观测与状态的分离导致轨迹正确性无法通过环境反馈直接判定，必须引入外部验证机制。

主流数据获取路线分为在线探索与人工演示两类，二者均受限于“验证瓶颈”。在线探索（如Explorer, Fara）在真实网站执行任务，但需人工或LLM判断每步正确性，导致成本高达$0.15-$1.00/条且结果不一致；人工演示（如Mind2Web）虽质量高但规模受限。AutoWebWorld的切入点在于将验证逻辑内化于环境：通过FSM显式定义状态转移规则，使轨迹生成过程本身即包含正确性证明，从而消除对外部验证器的依赖。

## 核心方法

### 方法参照系

标准GUI轨迹合成流程为“环境交互→轨迹记录→外部验证”。本文的关键差异在于将“外部验证”替换为“环境内在验证”，即通过预定义的状态转移逻辑，使轨迹在生成时即具备可验证性，而非事后判断。

### FSM状态建模与确定性转移

传统方法将网页状态视为黑盒，本文将其形式化为马尔可夫决策过程 $M = \langle S, A, T, O \rangle$，其中内部状态 $s_t = (p_t, \sigma_t)$ 由页面ID $p_t$ 和签名 $\sigma_t$ 组成。签名 $\sigma_t$ 是页面关键配置变量（如查询文本、筛选选项）的赋值集合，其域 $D_k(p_t)$ 随页面变化。状态转移由确定性函数 $T$ 控制，动作 $a$ 的有效性由前置条件谓词 $pre(s, a)$ 决定：

$$
s_{t+1} = \begin{cases}
s_t & \text{if } pre(s_t, a_t) = 0 \\
(p', \sigma') & \text{if } pre(s_t, a_t) = 1, \text{ where } \sigma' = Init(p') \oplus Carry(\sigma_t)
\end{cases}
$$

此设计解决了此前方法中“动作有效性依赖视觉猜测”的失效，通过显式前置条件确保只有满足逻辑约束的动作才能触发状态更新，使轨迹在FSM层面天然正确。

### BFS轨迹合成与执行过滤

基于FSM，轨迹生成从随机探索转为系统性BFS搜索。BFS从初始状态 $s_0$ 出发，仅扩展满足前置条件的动作，直至达到目标状态，生成最短动作序列。每个FSM动作预定义了GUI原子操作序列（如点击、输入），通过共享的选择器命名空间映射到DOM元素。生成的候选轨迹在合成网站中通过Playwright执行，仅保留所有步骤均成功执行的轨迹：

$$
\tau_{valid} = \{ \tau \in \tau_{BFS} \mid \forall i, \text{execute}(\tau_i) = \text{success} \}
$$

此执行过滤机制消除了前端实现与FSM逻辑不匹配导致的噪声，确保最终数据集11,663条轨迹均为可复现、内在验证的正确轨迹，单条成本降至$0.04。

## 实验评估

实验在WebVoyager、Online-Mind2Web及ScreenSpot系列基准上进行，基线覆盖前沿模型（GPT-5.1, Claude-4.0-Sonnet）及开源7B模型（UI-TARS-1.5-7B, Qwen2.5-VL-7B）。主结果显示，仅用16K步合成数据训练的Ours-7B在WebVoyager上达到27.42%成功率，优于UI-TARS-1.5-7B的26.51%，且显著高于Qwen2.5-VL-7B的5.62%。

| 方法 | WebVoyager Overall (%) | ScreenSpot-V2 Overall (%) | ScreenSpot-Pro Overall (%) |
| :--- | :--- | :--- | :--- |
| Qwen2.5-VL-7B | 5.62 | 84.83 | 23.2 |
| UI-TARS-1.5-7B | 26.51 | - | - |
| Ours-7B | 27.42 | 86.16 | 27.5 |

消融实验表明，合成数据量与性能呈单调正相关。在WebVoyager上，数据量从8增至16,253时，成功率从3.92%提升至27.42%；Online-Mind2Web从1.22%提升至14.02%。接地性能方面，Ours-7B在ScreenSpot-Pro上较基线提升4.3个百分点，表明合成轨迹中的接地监督有效提升了元素定位精度。

评估边界方面，WebVoyager评估仅保留9个稳定网站以规避访问限制，可能高估在动态不稳定网站上的性能。代码已开源，但FSM生成依赖GPT-5.1，Web生成依赖Gemini3-Pro，复现成本较高。未报告推理延迟与内存占用，计算效率维度缺失。

## 关联研究分析

从问题动机看，AutoWebWorld与WebWorld同属合成环境路线，但WebWorld侧重世界模型预测以支持离线训练，而本文侧重FSM确定性验证以消除验证瓶颈。WebWorld的预测误差累积导致训练-测试差距，本文通过确定性转移避免了此问题，但代价是FSM无法建模真实Web中的异步加载与网络延迟等非确定性行为。

从方法设计看，AutoWebWorld与SynthAgent均利用合成数据，但SynthAgent依赖自动微调适应新环境，本文强调内在验证与BFS搜索。SynthAgent的合成数据可能存在分布偏差，本文通过执行过滤确保轨迹可执行性，但FSM抽象可能过度简化真实UI的复杂性。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

AutoWebWorld解决了Web GUI智能体训练中验证瓶颈与数据稀缺的矛盾，通过FSM将验证内化于环境，实现了低成本、可复现的轨迹合成。该方法以$0.04/条的成本生成11,663条验证轨迹，16K步训练即在WebVoyager上达到27.42%成功率，验证了合成数据的缩放定律。其边界在于FSM的确定性假设与真实Web的动态性存在差距，执行过滤可能丢弃具有教育价值的失败轨迹。当FSM状态空间扩展至包含异步事件与网络延迟时，BFS搜索的可行性与验证效率如何变化，论文未给出回答。
