> 智能体记忆系统长期依赖离线、查询无关的构建范式，导致计算资源浪费且可能丢弃特定查询所需的关键信息。现有运行时方案虽能按需提取，但缺乏对性能与成本权衡的显式控制机制。BudgetMem 将记忆提取模块化，通过强化学习训练的路由器在低/中/高预算层级间动态选择，实现了查询感知的成本-性能可控性。该方法在成本效率上优于基线，但绝对性能低于当前领域最高水平，其价值在于提供了可调节的权衡界面而非峰值性能突破。

## 研究背景

当智能体处理长程任务时，历史交互数据远超上下文窗口限制，必须依赖外部记忆存储。传统做法采用“构建一次，永远使用”的离线范式，即预先对历史进行压缩、摘要或索引，再在查询时检索。这种查询无关的预处理虽然简化了在线计算，但存在根本缺陷：它无法预知未来查询的具体需求，可能丢弃对特定查询至关重要的细节，同时为无关查询支付了不必要的计算成本。

该领域的核心矛盾在于：离线构建保证了检索的低延迟，但牺牲了信息保留的完整性；运行时提取保留了原始信息的完整性，但将计算压力转移至在线阶段，使得成本与延迟成为首要约束。主流路线如 Mem0 和 LightMem 均聚焦于优化离线构建的质量或检索精度，却未解决运行时提取中的成本可控性问题。工业界 LLM 系统已普遍提供分层计算控制（如推理深度、模型大小），但智能体记忆领域缺乏类似的系统化预算机制。BudgetMem 的切入点正是将这种工业界的分层控制思想迁移至记忆提取环节，通过模块化设计和强化学习路由，实现查询感知的性能-成本显式权衡。

## 核心方法

### 模块化运行时提取管道

BudgetMem 将记忆提取重构为多阶段模块化管道，区别于传统端到端或固定流程的离线构建。该管道包含过滤模块（Filter）、并行提取模块（实体/时间/主题）和摘要模块（Summary），每个模块暴露统一的预算层级接口（LOW/MID/HIGH）。设计动机在于解决离线管道中计算分配僵化的问题：通过模块化，系统可以针对查询特性动态调整各阶段的计算投入，而非对所有查询施加相同的处理强度。

### 预算层级路由策略

BudgetMem 提出三种正交的预算实现策略：实现层级（Implementation Tiering，从启发式到 BERT 再到 LLM）、推理层级（Reasoning Tiering，从直接生成到 CoT 再到多步反思）和容量层级（Capacity Tiering，从小模型到大模型）。这些策略通过不同的机制（算法复杂度、推理模式、模型规模）调节计算成本，使得路由器可以在统一的框架下比较不同维度的权衡特性。

### 强化学习路由器

路由器是一个轻量级神经网络策略 $\pi_\theta$，在每个模块调用步骤 $k$ 观察状态 $s_k$（包含查询、当前模块输入和模块描述符），输出动作 $a_k \in \{\text{LOW}, \text{MID}, \text{HIGH}\}$。路由器的优化目标为成本感知奖励函数：

$$
R = r_{\text{task}} - \lambda \cdot \alpha \cdot r_{\text{cost}}
$$

其中 $r_{\text{task}} \in [0,1]$ 为任务性能奖励，$r_{\text{cost}}$ 为归一化的提取成本，$\lambda$ 控制性能-成本权衡偏好，$\alpha$ 为方差对齐因子。该公式的物理含义是：路由器在最大化任务性能的同时，根据 $\lambda$ 的设定对计算成本施加惩罚，从而在训练过程中学习到不同预算约束下的最优层级选择策略。成本 $r_{\text{cost}}$ 通过滑动窗口分位数归一化，确保奖励尺度稳定。

## 实验评估

实验在 LoCoMo、LongMemEval 和 HotpotQA 三个基准上进行，基线包括 MemoryBank、MemoryOS、A-MEM、LangMem 和 LightMem。该论文实验数据不可得，未提供实验表格。据领域综述，BudgetMem 在性能优先模式下（$\lambda=0$）优于所有基线，例如在 LongMemEval 上 BudgetMem-CAP 的 Judge 分数为 60.50（LLaMA-70B 骨干），显著高于最强基线 LightMem 的 48.51。在 HotpotQA 上，BudgetMem-CAP 以 0.22 美元成本取得 72.08 的 Judge 分数，而 BudgetMem-REA 以更低成本 0.17 美元取得 70.83 的分数，体现了成本效率优势。

消融分析表明，路由器在不同成本权重 $\lambda$ 下表现出可解释的预算响应：当 $\lambda$ 较小时，路由器倾向于选择 MID 层级以优先保证质量；随着 $\lambda$ 增大，概率质量从高层级向低层级转移，实现受控的计算削减。这一行为验证了强化学习路由器能够根据成本压力动态调整计算分配，而非简单地全局降级或升级。

评估边界方面，论文未报告置信区间，且基线覆盖存在明显缺口：未包含知识图谱类方法（如 GAAMA）和生成式潜在记忆方法（如 MemGen），这使得在结构化推理和多跳任务上的对比不完整。可复现性方面，论文提供了代码仓库，但路由器训练细节（如 PPO 超参数、奖励函数具体实现）仅在附录中简要提及，缺乏完整的训练日志和消融细节。

## 关联研究分析

从问题动机看，BudgetMem 与 SwiftMem 均关注记忆检索的效率，但二者解决的是不同层面的瓶颈。SwiftMem 通过查询感知索引结构优化检索复杂度，将时间敏感检索从线性降低至对数级别，其核心是数据结构创新；BudgetMem 则聚焦于提取阶段的计算预算分配，其核心是策略优化。这种差异源于任务特性：SwiftMem 假设记忆已结构化存储，优化的是“找到”信息的速度；BudgetMem 假设记忆需从原始记录中提取，优化的是“构建”信息的成本。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但两者在模块化设计上的互补性暗示了未来结合索引优化与预算路由的可能性。

从方法设计看，BudgetMem 与 Mem0 代表了记忆构建的两种对立范式。Mem0 采用离线事实提取与冲突解决，强调记忆的持久性和一致性，其成本主要在构建阶段；BudgetMem 采用运行时按需提取，强调查询相关性和成本可控性，其成本分散在每次查询中。这种差异并非技术优劣，而是设计哲学的不同：Mem0 适用于查询模式稳定、记忆更新频繁的场景；BudgetMem 适用于查询模式多变、成本敏感的场景。论文未探索两种范式的混合使用，也未分析在何种查询分布下离线构建优于运行时提取，这一空白限制了其适用范围的明确界定。

## 总结

BudgetMem 解决的核心矛盾是运行时记忆提取中性能与成本的不可控性。现有离线方法无法适应查询特性，而现有运行时方法缺乏显式的权衡机制。BudgetMem 通过模块化管道和强化学习路由器，实现了查询感知的预算层级选择，在 LongMemEval 上以 60.50 的 Judge 分数超越基线 12 个点，同时在 HotpotQA 上以 0.17 美元成本取得 70.83 的分数，证明了成本效率优势。其边界在于绝对性能低于领域 SOTA（如 MemCog 的 95.8%），且未包含结构化记忆基线，限制了其在多跳推理任务上的竞争力。当查询模式高度稳定且记忆更新频繁时，离线构建的固定成本是否仍优于运行时提取的动态成本，论文未给出回答。
