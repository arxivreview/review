> GUI智能体在长程导航中因缺乏动作执行前的后果预判，常陷入错误累积或不可逆操作风险。现有文本与像素世界模型分别受限于语义抽象缺失与结构可控性不足，无法同时满足高保真视觉模拟与精确逻辑约束。Code2World将下一状态预测重构为HTML代码生成任务，通过确定性渲染实现视觉与结构的双重对齐。该范式在8B参数规模下逼近GPT-5性能，但依赖GPT-5合成数据的质量上限，且评估协议对代码生成特有的幻觉模式覆盖有限。

## 研究背景

GUI智能体执行动作时，环境反馈的延迟与不可逆性构成了长程任务的核心瓶颈。人类操作者通过心理模拟预判动作后果，而多数智能体直接执行，导致单步错误需多步修正甚至任务失败。世界模型（World Model）作为虚拟沙箱，旨在通过动作条件预测下一状态，为智能体提供前瞻性规划能力。然而，GUI界面的离散状态转换特性使得传统连续空间建模方法面临挑战：文本表示丢失空间视觉细节，像素生成难以维持细粒度结构可控性，尤其在文本密集界面中。

现有GUI世界模型研究分为两条路线。文本基方法利用大语言模型预测状态差异的自然语言描述或DOM更新，虽捕捉语义意图但缺乏视觉反馈，而视觉反馈已被证明能显著增强智能体推理能力。像素基方法采用扩散模型合成未来截图，但在连续像素空间中建模精确的离散状态转换极具难度，且难以保持细粒度结构可控性。Code2World的切入点在于利用GUI原生由程序化代码（如HTML）创建的特性，将模拟任务转化为可渲染代码生成，从而在符号层面保证结构可控性，同时通过确定性渲染实现高保真可视化。

## 核心方法

### 方法参照系

GUI世界模型的标准流程是接收当前视觉状态、动作与任务目标，预测下一视觉状态。传统方法直接在像素或文本空间优化预测器，而Code2World将预测目标从原始状态转移至底层结构表示，即HTML代码，再通过浏览器渲染引擎获得视觉状态。这一转变的关键差异在于引入确定性渲染环节，将概率性视觉生成转化为符号生成加确定性转换的两步过程。

### 可渲染代码生成范式

传统像素生成方法在连续空间中优化视觉相似度，导致结构漂移与文本渲染错误。Code2World将状态转换定义为条件生成过程，其中多模态生成器 $M_\theta$ 接收输入 $x = (I_t, a_t, G)$，输出预测HTML代码 $\hat{C}_{t+1}$，随后通过渲染引擎 $R$ 确定性生成视觉状态 $\hat{I}_{t+1} = R(\hat{C}_{t+1})$。该设计动机在于HTML作为GUI的原生表示，天然保证DOM结构完整性，避免像素生成中常见的布局畸变。通过约束根容器尺寸与语义占位符策略，生成的HTML成为自包含、无外部依赖的原子单元，确保渲染结果与原始截图坐标系精确对齐。

### 渲染感知强化学习

监督微调（SFT）仅优化代码文本似然，模型对渲染后的视觉结果保持盲态，导致生成代码在视觉保真度上存在差距。Code2World引入渲染感知强化学习（RARL），以渲染结果作为奖励信号，采用组相对策略优化（GRPO）算法。复合奖励函数定义为 $R_{total} = \lambda_1 R_{sem} + \lambda_2 R_{act}$，其中 $R_{sem}$ 通过VLM-as-Judge评估结构布局与元素对应关系，容忍风格抽象；$R_{act}$ 验证状态转换是否符合动作逻辑，惩罚视觉更新与动作意图的矛盾。该设计解决了SFT阶段代码与视觉现实脱节的问题，通过双奖励机制同时优化语义对齐与动态逻辑，使模型在保持结构可控性的同时提升视觉保真度。

## 实验评估

实验在AndroidControl（域内）与GUI-Odyssey（域外）基准上评估下一UI预测能力，基线覆盖图像生成模型（Gemini-3-Pro-Image、GPT-Image-1等）与代码生成模型（GPT-5、Claude-Sonnet-4.5、开源VLM等）。Code2World-8B在域内功能逻辑指标 $S_{ad}$ 达94.28，视觉质量指标 $S_{ele}$ 达79.44，超越参数量超10倍的开源基线，逼近GPT-5与Gemini-3-Pro-Image。域外测试中，$S_{ad}$ 维持92.73，$S_{id}$ 达78.22，显著优于开源模型的衰减幅度，验证了交互动态内化能力。

消融实验揭示训练阶段的贡献差异。SFT冷启动将 $S_{ad}$ 从59.20提升至78.45，建立HTML语法基础。仅使用视觉奖励 $R_{sem}$ 时，功能逻辑停滞甚至轻微回归，表明模型存在奖励黑客倾向，优先优化表面像素对齐而非状态转换逻辑。动作奖励 $R_{act}$ 主要提升动态逻辑，但视觉增益有限。完整Code2World结合双奖励，$S_{ad}$ 达94.28，$S_{ele}$ 达79.44，证实语义对齐与交互逻辑的协同优化对鲁棒世界模型的必要性。下游任务中，Code2World作为插件将Gemini-2.5-Flash在AndroidWorld上的成功率从41.4%提升至50.9%（+9.5%），验证了世界模型保真度与智能体性能的强相关性。

评估协议采用VLM-as-Judge框架，定义功能逻辑（$S_{ad}$、$S_{id}$）与视觉质量（$S_{ele}$、$S_{lay}$、SigLIP、DINO）双维度指标。局限在于VLM评估器在复杂逻辑判断上可能存在偏差，且未报告置信区间。数据合成依赖GPT-5，可能引入分布偏差，视觉反馈修正机制的阈值（SigLIP > 0.9）选择缺乏敏感性分析。代码开源，但超参数与GPU配置未在摘要中明确，可复现性需查阅附录。

## 关联研究分析

从问题动机看，Code2World与UI-S1同属强化学习增强路线，但优化对象存在根本差异。UI-S1优化智能体策略，通过半在线RL提升长程任务错误恢复能力，而Code2World优化环境模拟器，通过RARL提升状态预测保真度。这一差异源于任务特性：UI-S1面对的是动态环境中的决策不确定性，Code2World面对的是静态环境建模中的表示瓶颈。Code2World的插件式设计使其可独立于智能体架构，但+9.5%的提升是否源于代码生成的结构优势，还是仅因增加了推理步骤，论文未提供对照实验验证。

从方法设计看，Code2World与Video2GUI均解决数据稀缺问题，但数据源与合成逻辑不同。Video2GUI挖掘视频中的用户操作行为生成预训练轨迹，强调外部数据多样性；Code2World基于AndroidControl轨迹合成HTML，通过视觉反馈修正确保代码-截图对齐，强调内部数据质量。Code2World的GPT-5合成依赖可能限制GUI交互类型覆盖，而Video2GUI的视频解析需处理遮挡、模糊等噪声。两者在数据多样性与分布一致性间的取舍不同，Code2World更适用于结构规整的移动端界面，Video2GUI更适用于多样化场景。

## 总结

Code2World解决的核心矛盾是GUI世界模型中视觉保真度与结构可控性的不可兼得。现有文本与像素方法分别因语义缺失与结构漂移失效，而HTML作为GUI原生表示，通过确定性渲染同时满足两者。该范式将下一状态预测转化为代码生成，结合SFT冷启动与RARL双奖励优化，在8B规模下实现域内 $S_{ad}$ 94.28、域外 $S_{ad}$ 92.73的性能，并将下游智能体成功率提升9.5%。其边界在于数据合成依赖GPT-5的质量上限，且评估协议对代码生成特有的幻觉模式（如布局畸变、元素错位）缺乏细粒度诊断。当支持集扩大至更复杂的跨平台GUI时，GPT-5合成的HTML是否仍能覆盖所有交互类型，视觉反馈修正机制的阈值选择是否影响泛化能力，论文未给出回答。
