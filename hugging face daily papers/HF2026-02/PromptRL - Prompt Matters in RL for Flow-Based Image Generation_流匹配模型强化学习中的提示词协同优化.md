# HuggingFace最新推荐论文 ｜PromptRL: Prompt Matters in RL for Flow-Based Image Generation ｜流匹配模型强化学习中的提示词协同优化

研究机构：香港中文大学

作者：Fu-Yun Wang、Han Zhang、Michael Gharbi 等 5 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.01382)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.01382)

> 流匹配模型在强化学习后训练中面临探索空间坍缩与提示词过拟合的双重瓶颈，导致样本效率低下且泛化能力脆弱。现有方法将提示词视为固定输入，忽略了其作为优化变量的潜力，而本文切入点在于将语言模型嵌入强化学习循环，实现提示词与图像生成的联合进化。具体做法是训练语言模型生成语义等价但句式多样的提示词变体，与流匹配模型共享奖励信号但梯度隔离。该框架在GenEval上达到0.97，但LM与FM的梯度隔离是否限制了跨模态语义对齐的深度，仍需进一步验证。

## 研究背景

流匹配模型通过求解常微分方程实现高质量图像生成，但其确定性去噪过程导致相同提示词下输出多样性急剧下降。这种质量-多样性权衡直接削弱了强化学习探索的有效性：当生成策略趋于确定，rollout轨迹坍缩至输出空间的狭窄模式，优势估计器失去比较信息，策略改进停滞。同时，模型在训练过程中记忆提示词的表层语言模式而非底层视觉概念，面对语义等价但句式不同的测试提示词时性能崩塌，如FlowGRPO在GenEval上从0.92降至0.81。

流匹配模型的强化学习后训练已成为对齐人类偏好的标准机制，但现有方法普遍将提示词视为固定输入，仅通过随机噪声采样或规则化改写进行数据增强。这种静态处理无法解决探索悖论：模型遵循提示词越精确，生成多样性越低，RL优化陷入局部最优。PromptRL的切入点在于将提示词从固定输入转化为可学习变量，通过联合训练语言模型与流匹配模型，在扩展探索空间的同时缓解提示词过拟合。

## 核心方法

### 方法参照系

流匹配模型的强化学习通常采用GRPO算法，将去噪过程建模为马尔可夫决策过程，通过组内优势估计更新策略。标准流程中提示词作为固定条件输入，仅通过独立噪声采样实现多样性，缺乏对提示词本身的优化机制。本文的关键差异在于将提示词处理从静态预处理转化为训练时的动态策略，使语言模型成为RL循环内的可训练组件。

### 动态提示词精炼机制

传统方法使用规则化改写或同义词替换生成提示词变体，但这些技术往往无法产生语义连贯的大规模变化。PromptRL引入语言模型作为动态提示词精炼器，给定原始提示词$p_0$，语言模型$\pi_{LM}(\cdot|p_0)$生成一组精炼提示词$\{p_1, p_2, ..., p_k\}$，在保持核心语义意图的同时引入语言多样性。每个精炼提示词$p_i$与独立噪声样本$\epsilon_i \sim N(0, I)$配对，输入流匹配模型$\pi_{FM}(\cdot|p_i, \epsilon_i)$生成多样化图像。这一设计解决了规则化改写无法捕捉复杂语义关系的问题，使语言模型能够根据上下文生成更具针对性的提示词变体。

### 联合强化学习训练

语言模型与流匹配模型在架构上保持隔离，梯度不相互传播，但共享奖励信号。对于每个原始提示词$p_0^{[j]}$，生成$n$个样本：$m$个使用原始提示词，$n-m$个使用语言模型精炼的提示词。复合奖励函数定义为：

$$R(x, p) = \lambda_{Format} R_{Format}(p) + \lambda_{Gen} R_{Gen}(x, p)$$

其中$R_{Format}(p)$是二元格式奖励，要求语言模型输出符合XML标签约束的精炼提示词；$R_{Gen}(x, p)$是图像生成奖励（如GenEval组合准确性）。组内优势通过标准化计算：

$$A^{[j]}_i = \frac{R(x_i^{[j]}, p_i^{[j]}) - \mu^{[j]}}{\sigma^{[j]} + \epsilon}$$

语言模型仅使用$n-m$个精炼样本的优势进行更新，确保其学习生成优于基线的提示词变体；流匹配模型使用全部$n$个样本的优势，维持原始分布上的鲁棒性。这种选择性优势分配防止语言模型引入低质量变体，同时保证流匹配模型在训练分布上的性能。

## 实验评估

实验基于FLUX.1-dev进行T2I生成，FLUX.1-Kontext进行图像编辑，语言模型采用Qwen2.5-VL-3B-Instruct。评估覆盖GenEval（组合准确性）、OCR（文本渲染）、PickScore（人类偏好）及OmniEdit（编辑任务）。基线包括FlowGRPO、DiffusionNFT、SD3等，但缺乏GenPilot、RAISE等纯提示词优化方法在RL场景下的对比。

PromptRL在GenEval上达到0.97，OCR 0.98，PickScore 24.05，显著超越FlowGRPO的0.92/0.89/23.33。DiffusionNFT在应用提示词增强后性能下降，证实了提示词过拟合的存在。

提示词保留机制消融显示，m=2时GenEval平均分最高（0.94），m=1时性能最差（0.64），表明单个原始提示词在组内竞争中获得负优势，导致无效梯度更新。m=4时性能略降，可能源于过多原始提示词稀释了精炼变体的探索价值。

评估协议存在局限：GenEval 0.97的性能是否因推理时语言模型辅助而虚高，论文未提供无PE条件下的消融数据。代码已开源（https://github.com/G-U-N/UniRL），但训练细节如GPU数量、总训练时长未明确报告，可复现性受限。

## 关联研究分析

从问题动机看，PromptRL与GenPilot均关注提示词优化，但GenPilot将优化置于推理时，通过多智能体搜索提升单次生成质量；PromptRL将优化嵌入训练时，通过联合RL提升模型整体能力。这一差异源于任务特性：GenPilot适用于API封闭模型，无法修改模型参数；PromptRL针对可训练模型，追求长期性能提升。GenPilot在GenEval上达到0.92，PromptRL达到0.97，但前者无需训练成本，后者需要大量rollout。

从方法设计看，PromptRL与Flow-GRPO同属GRPO框架，但Flow-GRPO将提示词视为固定输入，仅通过SDE转换增加采样多样性；PromptRL引入语言模型作为动态策略，扩展了探索空间。Flow-GRPO在GenEval上达到0.92，PromptRL达到0.97，且样本效率提升2倍。这一改进源于语言模型能够生成语义连贯的提示词变体，而非随机噪声采样。DiffusionNFT采用前向加噪过程的在线RL，避免反向梯度，但存在严重的提示词过拟合，PromptRL通过联合训练缓解此问题。

## 总结

PromptRL要解决的核心矛盾是流匹配模型RL训练中的探索效率低下与提示词过拟合。现有方法将提示词视为固定输入，无法解决模型能力提升导致的行为空间坍缩，而本文通过联合训练语言模型与流匹配模型，使提示词成为可优化变量。具体做法是训练语言模型生成语义等价但句式多样的提示词变体，与流匹配模型共享奖励信号但梯度隔离。实验证明该方法在GenEval上达到0.97，OCR 0.98，样本效率提升2倍。本文的边界在于语言模型与流匹配模型的梯度隔离，可能限制了跨模态语义对齐的深度；提示词保留机制的最优值m=2依赖于组大小n=8，其他配置下的性能未充分验证。当组大小n变化时，提示词保留机制的最优m值是否保持恒定，论文未给出回答。
