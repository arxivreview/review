> 分布式大模型训练的核心瓶颈已从单纯的显存不足转向系统效率与算法灵活性的双重约束。现有 FSDP 框架采用固定分片格式，无法兼容块量化与非元素级优化器，且存在高昂的内存拷贝与通信开销。veScale-FSDP 通过引入支持任意粒度的 `RaggedShard` 分片格式、NP-hard 规划算法及零拷贝 `DBuffer` 原语，重构了 FSDP 后端。该方案在万卡集群上实现了 5-66% 的吞吐提升与 16-30% 的内存降低，但其性能增益高度依赖特定的规划启发式，在超大规模异构环境下的泛化能力尚待验证。

## 研究背景

当训练前沿模型时，参数与优化器状态需跨数千 GPU 分片以突破单卡显存限制。Fully Sharded Data Parallel (FSDP) 通过消除冗余状态成为主流选择，但其标准实现将张量按元素或行均匀切分。这种均匀切分破坏了块量化所需的完整块结构，也阻碍了 Muon 等矩阵级优化器的直接应用，迫使开发者侵入式修改模型代码或处理复杂的边界对齐逻辑。

FSDP 领域的演进始终在“灵活性”与“性能”间权衡。DeepSpeed ZeRO 与 PyTorch FSDP1 采用拼接分片，虽简化了通信但导致 AllGather 碎片化；PyTorch FSDP2 引入 DTensor 提升灵活性，却因交错内存布局产生高昂的 Copy-In/Out 开销；Megatron-FSDP 回归拼接设计以避免拷贝，但引入了显著的 Padding 膨胀。现有系统均无法同时满足结构感知训练的需求与万卡集群的生产级吞吐目标，这一矛盾在引入块量化与矩阵优化器后变得尤为尖锐。

veScale-FSDP 的切入点在于解耦分片粒度与通信效率。它不再假设分片边界必须与张量维度对齐，而是允许任意块大小的非均匀分片，并通过全局规划算法重排张量布局以最大化通信效率。这种设计使得 FSDP 能够原生支持结构感知训练，同时通过零拷贝机制消除了传统 FSDP2 的内存开销，为万卡规模的高效训练提供了新的系统范式。

## 核心方法

### 方法参照系

标准 FSDP 流程将层内张量拼接后均匀分片，或按行切分以支持 DTensor 语义。其核心假设是分片边界与张量结构无关，通信通过 AllGather 和 ReduceScatter 完成。本文的关键差异在于：分片边界必须尊重量化块或矩阵优化器的结构约束，且通信路径需避免内存拷贝以维持万卡规模下的带宽利用率。

### RaggedShard 分片格式

`RaggedShard` 是一种新的 DTensor 放置格式，支持任意分片粒度（如元素、行、块）与任意设备分布。其设计动机是解决均匀分片导致的块边界错位问题，使得块量化可在单设备内无通信完成。对于张量 $t$，其分片由块大小 $g_t$ 和块数 $u_t = e_t / g_t$ 定义，其中 $e_t$ 为张量总元素数。

$$
\text{Shard}_k(t) = \bigcup_{i \in I_k} \text{Block}_i(t), \quad \text{where } I_k \text{ is the set of block indices on device } k
$$

该公式表明，设备 $k$ 持有张量 $t$ 中一组连续或非连续块 $I_k$ 的并集。与 `Shard(0)` 不同，`RaggedShard` 允许不同设备持有不同数量的块，从而精确匹配量化块边界。这种非均匀性使得 Muon 等矩阵优化器无需跨设备同步即可在本地完成矩阵级更新，消除了因边界错位导致的额外通信开销。

### 结构感知规划算法

`RaggedShard` 的非均匀性导致通信缓冲区大小不均，引发负载不均衡与 Padding 浪费。规划算法旨在最小化统一设备缓冲区大小 $S$，同时满足块完整、张量连续与负载平衡约束。该问题被证明为 NP-hard，论文采用多项式时间动态规划启发式求解。

$$
S^* = \min_{S} \{ S \mid \forall t \in T, \text{Block}(t) \subseteq \text{Shard}_k(t) \land \text{Contiguous}(t) \land \text{LoadBalanced}(S) \}
$$

该公式的物理含义是寻找最小的缓冲区大小 $S$，使得所有张量的块完整驻留单设备、内存连续且各设备负载平衡。算法通过重排张量顺序并在张量间而非张量内插入 Padding，避免了 FSDP2 的交错拷贝与 Megatron-FSDP 的 Padding 膨胀。这一设计将通信效率从依赖硬件对齐的被动适应，转变为基于全局布局的主动优化，显著降低了万卡集群中的通信尾延迟。

## 实验评估

实验基于 NVIDIA H800 集群，对比 DeepSpeed ZeRO、PyTorch FSDP1/FSDP2 及 Megatron-FSDP，工作负载包括 LLaMA-3-70B、GPT-OSS-120B 及内部 MoE 模型。基线覆盖了当前主流 FSDP 实现，但缺乏对最新开源变体（如某些社区优化版 FSDP）的对比，可能低估了部分竞品的性能。

| 配置 | 相对吞吐量 (%) |
| :--- | :--- |
| Combined (veScale-FSDP) | 100.0% |
| Disable `DBuffer` only | 92.8% |
| Disable Planning Algorithm only | 65.4% |

消融实验显示，规划算法是性能提升的主要来源，禁用后吞吐量下降 34.6%，而禁用 `DBuffer` 仅导致 7.2% 的下降。这表明零拷贝机制虽重要，但布局优化对通信效率的影响更为显著。`RaggedShard` 本身并非性能优化，而是使块量化可用的抽象基础，禁用后系统无法运行块量化训练。

评估边界方面，论文未报告置信区间，且部分实验在 Hopper 集群进行，硬件差异可能影响结果可比性。代码已开源，但规划算法的超参数（如块大小选择）未详细披露，复现时需依赖默认配置。此外，论文未提供与 TP/PP 混合并行组合时的详细通信开销分析，仅声称可组合，这限制了其在复杂并行策略下的适用性评估。

## 关联研究分析

从问题动机看，veScale-FSDP 与 AsyncHZP 等调度优化方法存在本质差异。AsyncHZP 聚焦于通过异步调度隐藏通信延迟，解决的是时间维度的效率问题；而 veScale-FSDP 解决的是空间维度的结构对齐问题，即分片边界与算法结构的匹配。这种差异源于任务特性：AsyncHZP 适用于标准元素级优化器，而 veScale-FSDP 专为结构感知训练设计。两者并非竞争关系，而是可叠加的优化维度，但论文未验证这种组合效果，留下了性能叠加的疑问。

从方法设计看，veScale-FSDP 与 Megatron-FSDP 同属零拷贝路线，但处理 Padding 的方式截然不同。Megatron-FSDP 通过行级分片避免拷贝，但 Padding 由参数布局决定，难以全局优化；veScale-FSDP 通过规划算法主动重排张量，将 Padding 最小化。这种差异反映了从“被动适应硬件”到“主动优化布局”的范式转变。然而，规划算法的 NP-hard 性质意味着在超大规模（>100K GPU）下，启发式解的质量可能下降，论文未提供该规模下的性能衰减数据，其线性扩展性的边界尚不明确。

## 总结

veScale-FSDP 解决了 FSDP 固定分片格式与结构感知训练之间的根本冲突，通过 `RaggedShard` 抽象与规划算法实现了灵活性与性能的统一。其核心价值在于证明了非均匀分片在万卡集群下的高效可行性，5-66% 的吞吐提升与 16-30% 的内存降低验证了该设计的工程价值。然而，规划算法的启发式性质与实验规模的局限暴露了其边界：在超大规模或异构硬件下，布局优化的收益是否仍能保持线性增长，论文未给出回答。当集群规模突破十万卡时，规划算法的计算开销与通信效率之间的平衡点将如何移动，是决定该范式能否成为下一代 FSDP 标准的关键问题。
