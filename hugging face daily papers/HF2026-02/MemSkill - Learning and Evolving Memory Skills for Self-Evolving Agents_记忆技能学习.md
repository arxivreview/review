> 大语言模型代理在长程交互中面临历史记忆构建僵化、依赖人工预设操作原语的问题，导致其在分布偏移下适应性差且难以扩展。现有方法将记忆提取硬编码为固定的增删改查流程，缺乏对交互数据的动态适应能力。MemSkill 将记忆操作重构为可学习、可进化的“记忆技能”，通过强化学习优化技能选择策略，并利用大语言模型基于困难案例自动进化技能库。该方法在多个基准上验证了技能化记忆构建的有效性，但其技能库规模较小且未涉及大规模检索瓶颈，限制了其在复杂开放环境中的通用性评估。

## 研究背景

当代理处理长对话或具身任务时，需从冗长交互轨迹中提取关键信息以维持上下文连贯性。这一过程依赖记忆构建机制，即从原始文本中提炼、整合并修订结构化记忆。传统方法将记忆构建视为静态过程，依赖人工设计的操作原语（如插入、更新、删除），这些原语隐含了特定领域的人类先验假设。然而，当交互模式发生分布偏移或历史长度增加时，固定原语无法动态调整提取粒度与修订策略，导致记忆质量下降且计算效率低下。

代理记忆系统的主流路线分为两类：基于启发式模块的静态流水线与基于强化学习的动态优化。前者如 MemoryBank 和 A-MEM，通过固定规则决定何时存储及如何修订，虽实现简单但缺乏泛化能力；后者如 Memory-R1 尝试利用下游任务信号优化记忆管理，但仍局限于固定操作集合的参数调整，未触及操作本身的进化。MemSkill 的切入点在于将记忆操作本身视为可学习的抽象，提出“记忆技能”概念，即结构化的行为模板，指定在何种条件下如何转换交互轨迹为记忆。通过解耦技能选择与技能进化，MemSkill 实现了记忆构建过程对交互数据的自适应，突破了静态原语的刚性限制。

## 核心方法

### 方法参照系

MemSkill 将记忆构建问题置于“技能条件生成”框架下，区别于传统“固定操作执行”范式。其核心差异在于：传统方法在每一步执行预定义操作，而 MemSkill 将操作封装为可检索、可组合的技能，并通过闭环机制动态更新技能库。该框架包含三个核心组件：控制器（Controller）、执行器（Executor）和设计器（Designer），分别负责技能选择、记忆生成和技能进化。

### 技能条件记忆构建

控制器负责从技能库中选取与当前上下文最相关的技能子集。设计动机在于解决固定操作序列无法适应动态上下文的问题，通过语义匹配实现技能的按需组合。控制器将当前文本跨度 $x_t$ 和检索到的记忆 $M_t$ 编码为状态嵌入 $h_t$，并计算每个技能 $s_i$ 的描述嵌入 $e_i$。技能得分通过余弦相似度计算：

$$
z_{t,i} = \frac{h_t \cdot e_i}{\|h_t\| \|e_i\|}
$$

基于得分，控制器采用 Gumbel-Top-K 采样选择 $K$ 个技能，形成有序集合 $A_t$。执行器随后以 $x_t$、$M_t$ 和 $A_t$ 为条件，通过单次大语言模型调用生成结构化记忆更新。这种跨度级（Span-level）处理替代了传统的逐轮（Turn-level）处理，减少了重复调用，提升了长历史处理的效率。

### 闭环技能进化

设计器负责基于训练过程中的困难案例进化技能库。设计动机在于解决静态技能库无法覆盖新出现的失败模式的问题，通过失败驱动的技能生成实现持续改进。设计器维护一个滑动窗口困难案例缓冲区，记录查询、真值、预测及失败次数。通过 KMeans 聚类识别代表性失败模式，并利用难度分数筛选高价值案例。设计器分两阶段更新技能库：首先分析失败案例以识别缺失或错误的记忆行为，随后提出对现有技能的修订或新技能的引入。为防止性能退化，系统保留最佳技能库快照，若更新导致性能下降则回滚。进化后，控制器增加对新技能的探索偏差，促进策略对新技能的适应。

## 实验评估

MemSkill 在 LoCoMo、LongMemEval、HotpotQA 和 ALFWorld 四个基准上进行评估，基线包括 MemoryBank、A-MEM 和 MemoryOS 等静态记忆系统。实验设置中，MemSkill 使用 LLaMA3.3-70B-Instruct 和 Qwen3-Next80B-A3B-Instruct 作为基础模型，控制器初始化为轻量级多层感知机，使用 PPO 算法进行强化学习训练。在 LoCoMo 基准上，MemSkill 在 LLaMA 和 Qwen 模型下均取得最优 LLM 评判分数，表明其构建的记忆质量更高。在 ALFWorld 具身任务中，MemSkill 在 Seen 和 Unseen 子集上均达到最高成功率，验证了技能引导记忆对长程决策的支持作用。

| 变体 | LLaMA (L-J) | Qwen (L-J) |
| :--- | :--- | :--- |
| MemSkill (default) | 50.96 | 52.07 |
| w/o controller (random skills) | 45.86 | 41.24 |
| w/o designer (static skills) | 44.11 | 34.71 |
| Refine-only (no new skills) | 44.90 | 46.97 |

消融实验显示，移除控制器（随机选择技能）导致性能显著下降，证实了学习技能选择的重要性；禁用设计器（静态技能）导致更大程度的性能退化，尤其在 Qwen 模型下，表明技能进化对泛化能力的关键作用。仅允许修订而不引入新技能的“Refine-only”变体性能优于静态技能，但仍低于默认设置，说明新技能的引入提供了额外的泛化收益。

评估边界方面，MemSkill 未在 SkillsBench 等通用技能基准上验证，限制了其在大规模技能库场景下的可比性。实验未报告置信区间，且部分基线（如 MemoryOS）的具体数值在正文中缺失，仅通过图表展示，影响了精确对比。代码已开源，但超参数细节（如困难案例缓冲区大小、聚类数量）未在正文中详细列出，可能影响复现性。

## 关联研究分析

从问题动机看，MemSkill 与 Skill1 均致力于解决技能与策略的协同进化问题，但任务领域不同。Skill1 面向任务执行，通过单一策略网络协同优化技能选择、利用与蒸馏，强调端到端的强化学习信号；MemSkill 则聚焦记忆构建，将技能选择（控制器）与技能进化（设计器）解耦，前者使用强化学习，后者使用大语言模型引导的启发式更新。这种解耦设计源于记忆构建任务的特性：记忆质量难以通过单一标量奖励直接优化，而困难案例的定性分析更能指导技能内容的修订。Skill1 的端到端优化在动态环境中可能更稳定，但 MemSkill 的解耦设计在可解释性和调试便利性上具有优势，尤其适用于记忆操作需要人工审计的场景。

从方法设计看，MemSkill 与 CoEvoSkills 均采用生成-验证循环，但验证机制存在差异。CoEvoSkills 引入独立的验证器生成测试断言，通过信息隔离确保反馈的客观性；MemSkill 的设计器则基于训练过程中的困难案例聚类，利用失败频率和任务性能作为难度信号。CoEvoSkills 的验证器更侧重于技能执行结果的准确性，而 MemSkill 的设计器更侧重于记忆构建过程的适应性。这种差异反映了任务特性的不同：CoEvoSkills 处理的是可验证的代码或逻辑技能，而 MemSkill 处理的是主观性较强的记忆提取任务，后者更依赖对失败模式的定性归纳而非定量断言。

## 总结

MemSkill 旨在解决代理记忆构建中静态操作原语缺乏适应性的核心矛盾，通过将记忆操作重构为可进化的技能库，实现了记忆构建过程对交互数据的动态适应。该方法通过强化学习优化技能选择策略，并利用大语言模型基于困难案例自动进化技能内容，在 LoCoMo 和 ALFWorld 等基准上验证了其在记忆质量和任务成功率上的提升。然而，MemSkill 的技能库规模较小（初始 4 个，进化后未明确上限），且未在大规模技能库场景下评估检索瓶颈，限制了其在复杂开放环境中的通用性。当技能库规模扩大至数千级时，基于语义相似度的技能选择是否仍能高效捕捉技能间的依赖关系，论文未给出回答。
