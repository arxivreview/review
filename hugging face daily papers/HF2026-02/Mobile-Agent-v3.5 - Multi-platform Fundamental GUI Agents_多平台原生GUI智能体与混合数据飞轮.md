> 多平台GUI智能体需在桌面、移动与浏览器间执行长程任务，但真实轨迹采集成本高且跨平台泛化差。现有原生模型依赖单一平台数据或纯在线强化学习，难以兼顾数据效率与多设备稳定性。本文通过虚拟环境合成高频操作、统一思维链监督及多平台交替强化学习，构建覆盖2B至235B参数的模型家族。该方案在开源模型中取得多项基准SOTA，但绝对性能仍落后于部分闭源大模型，且合成数据与真实分布的差距未量化。

## 研究背景

GUI智能体执行任务时，需将自然语言指令映射为像素级截图上的动作序列。这一过程依赖视觉定位（Grounding）精度，而定位错误在长程任务中会累积，导致轨迹偏离。为缓解此问题，智能体需具备记忆管理与反思能力，但现有模型在跨平台场景下，因训练数据分布单一，常出现动作空间混淆与上下文丢失。

当前主流路线分为两类：一是基于提示工程的模块化框架，受限于推理延迟与错误累积，难以处理复杂工作流；二是原生模型驱动，通过监督微调（SFT）与强化学习（RL）训练端到端策略。然而，原生模型面临数据瓶颈：真实设备轨迹采集需人工标注与异常处理，成本高昂；在线RL样本效率低，且多平台混合训练易引发梯度干扰。GUI-Owl-1.5的切入点在于，通过虚拟环境合成高频原子操作数据，结合多平台交替优化策略，解决数据稀缺与训练稳定性问题。

## 核心方法

### 方法参照系

本文问题属于多平台GUI智能体的端到端训练范式。标准流程为：SFT初始化策略，随后在真实或模拟环境中进行RL优化。关键差异在于，本文未采用单一平台或纯在线RL，而是引入虚拟环境数据合成与多平台交替训练机制，以平衡数据覆盖与训练稳定性。

### 混合数据飞轮与虚拟环境合成

传统数据管道依赖真实设备轨迹，但高频原子操作（如拖拽、滚动）与复杂场景（如弹窗、验证码）难以通过自动化采集覆盖。本文通过Vibe Coding合成虚拟环境，生成包含挑战案例的GUI交互轨迹。设计动机在于，真实环境探索受限于CAPTCHA中断与反馈缺失，虚拟环境可绕过这些限制，提供可扩展的高质量轨迹。轨迹合成基于有向无环图（DAG）$G = (V, E)$，其中节点 $v_i$ 表示原子子任务，边 $(v_i, v_j)$ 表示可行状态转移。任务指令由路径 $p = (v_1, \dots, v_K)$ 上的子指令模板 $d(v_k)$ 组合而成：

$$I(p) = \text{Compose}(d(v_1), d(v_2), \dots, d(v_K))$$

该公式确保任务覆盖高频操作模式，同时通过模板实例化减少大语言模型幻觉。消融实验显示，移除虚拟环境数据导致PC-Eval性能从75.4%降至42.0%，Mobile-Eval从86.7%降至50.0%，证实虚拟环境对掌握复杂场景的关键作用。

### 多平台交替强化学习（MRPO）

多平台混合训练易引发梯度干扰，导致策略收敛不稳定。本文提出MRPO框架，采用交替多平台优化策略，即循环训练单一设备类型而非混合轨迹。设计动机在于，不同平台的动作空间与状态转移特性差异显著，混合训练会放大梯度冲突。MRPO还引入在线Rollout Buffer，当分组Rollout结果坍缩时，通过过采样轨迹并选择多样化组来维持On-policy保证。策略更新基于设备条件化策略 $\pi_\theta(a|s, d)$，其中 $d$ 为设备类型。交替优化确保跨设备泛化，同时避免单平台性能牺牲。实验表明，该策略在OSWorld-Verified上取得56.5%成功率，优于UI-TARS-2的53.1%，且2B模型性能超过参数量超10倍的UI-TARS-72B-DPO（27.1%），验证了参数效率。

## 实验评估

实验覆盖20+基准，包括OSWorld、AndroidWorld、ScreenSpot-V2等。基线涵盖闭源模型（Claude-4、Gemini-2.5-Pro）与开源模型（UI-TARS、Qwen3-VL）。主结果显示，GUI-Owl-1.5-32B-Instruct在ScreenSpot-Pro上取得80.3%准确率（含裁剪细化），超越Gemini-3-Pro的72.9%；在OSWorld-MCP上取得47.6%成功率，优于Claude-4-Sonnet的43.3%。

| 基准 | 模型 | 成功率/准确率 (%) |
| :--- | :--- | :--- |
| OSWorld-Verified | GUI-Owl-1.5-8B-Thinking | 52.9 |
| AndroidWorld | GUI-Owl-1.5-8B-Thinking | 71.6 |
| ScreenSpot-Pro | GUI-Owl-1.5-32B-Instruct (w/ crop) | 80.3 |
| OSWorld-MCP | GUI-Owl-1.5-32B-Instruct | 47.6 |

消融实验揭示，移除统一CoT合成导致OSWorld性能从52.9%降至47.4%，AndroidWorld从71.6%降至65.0%，表明步骤级观察、反思与记忆管理对长程规划至关重要。Thinking变体在WebVoyager上较Instruct变体提升12.2个百分点（69.9%至82.1%），验证了思维链对复杂任务的增益。

评估边界方面，论文未报告推理延迟与Token消耗，且虚拟环境数据与真实分布的差距未量化。代码已开源，但超参数细节（如Rollout Buffer大小）未在正文中明确列出，复现性依赖GitHub仓库的完整配置。

## 关联研究分析

从数据合成路线看，Video2GUI通过视频挖掘生成轨迹，侧重外部数据利用；GUI-Owl-1.5则通过虚拟环境合成高频操作，侧重内部数据生成。差异根源在于任务特性：视频挖掘适合覆盖多样化应用，但难以精确控制原子操作细节；虚拟环境合成可针对性生成挑战案例（如验证码），但可能引入分布偏差。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

从RL框架看，UI-S1采用半在线RL，通过补丁模块平衡稳定性与探索；GUI-Owl-1.5的MRPO则聚焦多平台交替优化，解决跨设备梯度干扰。UI-S1未涉及多平台场景，而MRPO的交替策略可能牺牲单平台收敛速度。多平台交替训练是否导致单平台性能牺牲，论文未提供细粒度对比数据。

## 总结

GUI-Owl-1.5旨在解决多平台GUI智能体中数据稀缺与训练不稳定矛盾。其切入点在于，通过虚拟环境合成高频操作数据，结合多平台交替RL，规避真实环境探索限制与梯度干扰。方法核心是混合数据飞轮与MRPO框架，前者通过DAG任务合成与虚拟环境生成高质量轨迹，后者通过交替优化与Rollout Buffer确保跨设备策略收敛。实验证明，该方案在开源模型中取得ScreenSpot-Pro 80.3%与OSWorld-MCP 47.6%的SOTA性能，且2B模型参数效率显著。边界在于，虚拟环境数据与真实分布的差距未量化，且绝对性能仍落后于部分闭源大模型。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
