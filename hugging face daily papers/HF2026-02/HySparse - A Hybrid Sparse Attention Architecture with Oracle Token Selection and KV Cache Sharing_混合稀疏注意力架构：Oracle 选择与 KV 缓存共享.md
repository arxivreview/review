> 长上下文处理中，动态稀疏注意力虽能降低计算复杂度，却因保留完整 KV 缓存而无法缓解内存瓶颈，且依赖近似代理模块导致选择精度受限。HySparse 通过在全注意力层后插入稀疏层，直接复用前序全注意力层的块级重要性索引与 KV 缓存，实现了计算与内存的双重优化。该架构在 7B 和 80B 模型上验证了以极少全注意力层替代大部分计算的有效性，但其性能高度依赖跨层 Token 显著性稳定这一经验假设，在极端动态上下文中的鲁棒性尚存疑。

## 研究背景

当序列长度扩展至数万 Token 时，标准自注意力的二次方计算复杂度与线性增长的键值缓存（KV Cache）内存占用成为大语言模型（LLM）部署的核心瓶颈。KV Cache 的内存压力直接限制了服务吞吐量与最大批处理大小，而动态稀疏注意力虽通过仅计算重要 Token 降低了浮点运算次数，却因 Token 重要性随生成过程动态变化而必须保留完整 KV Cache，导致内存瓶颈未解。此外，现有稀疏方法依赖固定模式或轻量级代理模块（如门控网络）预测 Token 重要性，这些代理本质上是近似的，在长上下文演化中易失效，且引入额外训练复杂度。

稀疏注意力领域长期存在训练-推理不匹配问题：推理时应用的启发式选择策略与训练时学习的全局依赖结构脱节，引发误差累积。主流路线分为无训练（Training-free）与可训练（Trainable）两类，前者灵活但精度受限，后者通过自蒸馏或端到端预训练对齐选择模块，但未能根本消除代理瓶颈。HySparse 的切入点在于利用 Transformer 架构中跨层 Token 显著性稳定的经验现象，将全注意力层转化为稀疏层的“Oracle”，既避免了独立代理模块的近似误差，又通过跨层 KV 共享消除了稀疏层的额外内存开销，从而在架构层面同时解决计算与内存双重瓶颈。

## 核心方法

### 方法参照系

HySparse 属于混合注意力架构，其参照系为滑动窗口注意力（Sliding Window Attention, SWA）与全注意力交替的混合模型。标准混合架构中，SWA 层仅维护局部 KV 缓存以降低内存，但缺乏全局检索能力；全注意力层具备全局依赖捕捉能力但计算与内存成本高。HySparse 的关键差异在于引入“块稀疏注意力”分支，该分支不独立计算重要性，而是复用前序全注意力层的输出，形成全-稀疏-SWA 的三元混合结构。

### Oracle 引导的块级稀疏选择

传统稀疏注意力需在注意力计算前通过独立模块预测 Token 重要性，这一环节通常依赖近似代理，导致选择精度受限于代理保真度。HySparse 将选择环节移至全注意力层内部，利用 FlashAttention 内核在计算在线 Softmax 时已产生的行最大值中间结果，以极小开销输出块级注意力分数 $S \in \mathbb{R}^{t \times \lceil t/B \rceil}$，其中 $B$ 为块大小。随后对 $S$ 执行 TopK 操作获取关键块索引 $\mathcal{I}$，该索引被后续 $N$ 个稀疏层直接复用。此设计消除了独立选择模块，使稀疏选择成为全注意力计算的副产品，确保了选择精度与全注意力一致，同时避免了代理模块的训练不稳定问题。

### 跨层 KV 共享与双分支融合

动态稀疏注意力通常需为每个稀疏层维护独立 KV 缓存以支持动态索引，导致内存开销未减。HySparse 在稀疏层中引入跨层 KV 共享机制，块稀疏注意力分支直接复用前序全注意力层产生的 Key 和 Value 张量，仅通过索引 $\mathcal{I}$ 提取对应块进行计算，从而不增加任何每层 KV 内存开销。同时，为弥补共享 KV 在局部特征表达上的不足，每个稀疏层并行运行一个独立的 SWA 分支，维护大小为 $w=128$ 的局部 KV 缓存。两分支输出经 Sigmoid 门控融合：

$$ O_{\text{final}} = \sigma(g_1) \cdot O_{\text{sparse}} + \sigma(g_2) \cdot O_{\text{swa}} $$

该公式表明，模型动态混合全局检索信息与局部连贯信息，既保留了稀疏注意力的全局覆盖能力，又通过 SWA 分支强化了短程依赖建模，解决了单一稀疏分支在局部任务上的表达力损失。

## 实验评估

实验在 7B 稠密模型（36 层，1:3 全-稀疏比）和 80B MoE 模型（49 层，1:11 全-稀疏比）上进行，基线包括全注意力（Full-Attn）和混合 SWA（Hybrid SWA）。评估覆盖 MMLU、GSM8K、HumanEval 及 Ruler 长上下文基准。基线选择聚焦于混合架构内部对比，未包含纯线性注意力（如 Mamba）或独立代理稀疏方法（如 NSA），限制了与架构重构路线的直接可比性。

| 基准 | 7B Full-Attn | 7B Hybrid SWA | 7B HySparse | 80B Full-Attn | 80B Hybrid SWA | 80B HySparse |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| MMLU (5-shot) | 56.9 | 57.6 | 58.8 | 56.1 | 61.8 | 62.2 |
| GSM8K (8-shot) | 33.3 | 35.7 | 37.9 | 53.8 | 45.3 | 54.1 |
| HumanEval (0-shot) | 25.0 | 22.0 | 23.5 | 35.4 | 31.7 | 38.4 |
| Ruler 16k | 93.0 | 91.6 | 94.1 | 93.6 | 72.7 | 90.6 |

HySparse 在 7B 模型上全面超越基线，MMLU 达 58.8，GSM8K 达 37.9。在 80B MoE 模型中，Hybrid SWA 在 16k 上下文下性能骤降至 72.7，而 HySparse 维持 90.6，接近 Full-Attn 的 93.6，验证了稀疏分支在激进混合比例下对全局检索能力的恢复作用。

消融实验显示，移除层内 SWA 分支导致 MMLU 从 58.4 降至 57.1，GSM8K 从 36.7 降至 29.7，表明局部分支对推理任务至关重要。KV 缓存共享策略中，仅对稀疏注意力分支共享（sharing only for SA）优于对 SA 和 SWA 同时共享，前者 MMLU 达 58.4，后者仅 52.8，证实 SWA 需独立 KV 以捕获局部特征，共享全注意力 KV 会损害局部表达力。

评估边界方面，论文未报告延迟（Latency）与显存占用（Memory Usage）的具体数值，仅定性声称 KV 缓存减少近 10 倍，缺乏系统级效率量化。代码未公开，超参数如 RoPE 基频调整至 640,000 的细节虽提供，但 FlashAttention 内核修改的具体实现未开源，限制了第三方复现与内核级效率验证。

## 关联研究分析

从问题动机看，HySparse 与 NSA（Yuan et al., 2025）均致力于解决可训练稀疏注意力的选择精度问题，但 NSA 通过独立压缩注意力模块端到端学习选择，而 HySparse 复用全注意力层作为 Oracle。这一差异源于对“选择信号来源”的不同假设：NSA 认为选择需独立优化，HySparse 则认为全注意力输出已包含足够显著性信息。HySparse 的设计避免了 NSA 中辅助损失或间接监督带来的训练不稳定性，但其有效性依赖于跨层显著性稳定这一前提，若上下文动态变化剧烈导致显著性漂移，Oracle 选择可能失效，论文未对此进行压力测试。

从方法设计看，HySparse 与 MHLA（Zhang et al., 2026）同属混合架构，但 MHLA 结合线性注意力与全注意力以恢复表达力，HySparse 则结合稀疏注意力与 SWA 以优化内存。MHLA 在 MMLU 上取得 51.3（据领域综述），HySparse 在 7B 模型上达 58.8，两者骨干与训练数据不同，不可直接比较。HySparse 的创新在于将 KV 缓存共享引入稀疏分支，而 MHLA 未涉及内存优化。HySparse 的块级选择（Block Size 64）相比 Token 级选择降低了索引开销，但可能牺牲细粒度 Token 区分能力，论文未对比 Token 级选择的性能损失，这一粒度权衡的边界尚不明确。

## 总结

HySparse 旨在解决动态稀疏注意力中计算降低与内存缓解脱节的核心矛盾，其切入点在于利用全注意力层作为 Oracle 并共享 KV 缓存，将稀疏选择转化为全注意力计算的副产品，从而消除独立代理模块的近似误差与额外内存开销。该方法在 7B 和 80B 模型上验证了以 1:11 全-稀疏比实现接近全注意力性能的有效性，80B 模型中仅 5 层全注意力即维持 90.6 的 Ruler 16k 分数。然而，其性能高度依赖跨层 Token 显著性稳定这一经验假设，且未报告系统级延迟与显存数据，块级选择的粒度损失也未量化。当上下文动态变化导致显著性分布剧烈漂移时，Oracle 选择的精度是否仍能维持，论文未给出回答。
