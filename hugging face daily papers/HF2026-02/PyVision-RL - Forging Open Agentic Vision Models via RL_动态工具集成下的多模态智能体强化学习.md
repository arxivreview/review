> 多模态模型在长链推理中常因视觉证据获取不足而依赖语言先验，现有静态工具集缺乏灵活性，纯动态工具则面临训练中的交互坍缩。PyVision-RL 以 Python 为原语实现图像与视频的统一动态工具调用，通过累积工具奖励与标准差排序筛选机制稳定强化学习训练。该框架在视觉搜索与数学推理基准上超越静态工具基线，并显著降低视频理解的视觉 Token 消耗，但其对工具调用有效性的验证仍局限于答案正确性，未独立量化视觉忠实度。

## 研究背景

当多模态大模型（MLLMs）处理高分辨率图像或长视频时，直接输入全量视觉数据会导致上下文窗口溢出或关键细节丢失。为解决此问题，智能体范式引入工具调用，允许模型在执行推理时主动裁剪、缩放或采样视觉区域。然而，将这一范式从文本域迁移至视觉域时，强化学习（RL）训练面临独特的稳定性挑战：模型在优化过程中倾向于减少工具调用次数，收敛至短路径、低交互的行为模式，即交互坍缩（Interaction Collapse）。

现有工具集成路线分为静态与动态两类。静态工具集预定义裁剪、缩放等操作，虽稳定但缺乏任务适应性；动态工具以 Python 解释器为原语，允许模型即时生成代码处理视觉输入，具备组合表达能力，但此前研究多依赖专有 API 或局限于图像任务，开放权重模型在视频领域的动态工具 RL 训练尚未充分探索。PyVision-RL 的切入点在于解决动态工具 RL 中的训练不稳定与交互坍缩问题，通过奖励机制与 Rollout 筛选策略，使模型在数百步训练中维持多轮工具使用能力，并将动态工具范式从图像扩展至视频。

## 核心方法

### 方法参照系

本文问题属于工具集成多模态推理，其通用流程为：模型生成推理文本与代码块，环境执行代码并返回视觉/文本结果，模型基于反馈继续推理直至输出答案。与纯文本 RL 的关键差异在于，视觉工具的执行结果（如裁剪后的图像）需重新注入模型上下文，且工具调用的有效性直接依赖视觉证据的准确性，这使得奖励信号的设计与 Rollout 质量对训练稳定性具有决定性影响。

### 累积工具奖励

在标准 GRPO 框架中，奖励仅基于最终答案正确性，导致模型在训练初期快速收敛至“少调用工具”的局部最优。PyVision-RL 在答案正确的前提下，引入与工具调用次数成正比的累积奖励，其目标函数为：

$$
R_{\text{total}} = R_{\text{acc}} + \mathbb{1}[R_{\text{acc}}=1] \cdot 0.1 \cdot n_{\text{tc}}
$$

其中 $R_{\text{acc}} \in \{0, 1\}$ 为答案正确性奖励，$n_{\text{tc}}$ 为单次 Rollout 中的工具调用总次数。该设计仅在答案正确时累加工具奖励，避免模型为获取奖励而进行无效调用。其改进价值在于，通过显式激励多轮交互，抵消了 GRPO 中因组内归一化导致的“简洁解”偏好，使模型在训练后期仍能维持较高的工具调用频率，从而支撑长程视觉推理。

### 超采样-过滤-排序 Rollout 策略

动态工具执行存在不确定性，部分 Rollout 可能因代码执行失败、超时或视觉输出无效而中断训练。此外，当组内所有 Rollout 奖励相同（如全对或全错）时，组内归一化后优势值为零，无法提供梯度信号。PyVision-RL 采用超采样-过滤-排序策略：首先超采样生成 Rollout，随后过滤掉零奖励方差组及执行失败的轨迹，最后按组内奖励标准差排序，保留标准差最高的组用于训练。该策略将标准差作为样本难度的代理指标，优先选择中等难度、信息量丰富的 Rollout，同时显著降低“正确但简洁”样本获得负优势的概率，从而稳定优化过程。

## 实验评估

实验基于 Qwen2.5-VL-7B 骨干，覆盖视觉搜索（V*, HRBench-4K/8K）、多模态推理（DynaMath, MathVerse, MathVision, WeMath）及智能体推理（TIR-Bench）基准。基线包括静态工具集（Pixel-Reasoner, Mini-o3, DeepEyes）与动态工具方法（Thyme, CodeV, CodeDance, CodeVision, DeepEyes-v2）。PyVision-Image 在视觉搜索基准上较基线提升 +10.2%（V*）、+6.5%（HRBench-4K）、+6.4%（HRBench-8K）；在多模态推理基准上，较 DeepEyes-v2 提升 +4.4%（DynaMath）、+3.1%（MathVerse）、+9.6%（WeMath）；在 TIR-Bench 上提升 +3.8%。

| 基准 | Qwen2.5-VL-7B | DeepEyes-v2 | PyVision-Image |
| :--- | :--- | :--- | :--- |
| V* | 78.5 | 83.7 | 88.7 |
| HRBench-4K | 71.6 | 75.6 | 78.1 |
| HRBench-8K | 67.9 | 72.2 | 74.3 |
| DynaMath | 53.3 | 57.2 | 61.6 |
| MathVerse | 45.6 | 52.7 | 55.8 |
| WeMath | 34.6 | 38.1 | 47.7 |
| TIR-Bench | 16.0 | - | 19.8 |

消融实验表明，移除累积工具奖励后，工具调用次数在训练初期快速下降并稳定于低值，且训练 500 步后性能落后于基线；移除标准差排序则导致早期性能下降，而保留标准差归一化项会引入持续的性能波动。最大轮次预算从 2 增至 4 时，训练 600 步后性能提升 1.93%，表明更大轮次预算提高了性能上限，但其收益在训练后期才显现。

评估协议存在局限：V* 基准仅 191 样本，采用 avg@32 指标；视频任务仅评估 VSI-Bench，缺乏长视频推理的多基准验证。代码与数据已开源，但论文未报告训练所需的 GPU 数量与总时长，可复现性依赖社区验证。

## 关联研究分析

从问题动机看，PyVision-RL 与 DeepEyes-v2 同属动态工具集成路线，但后者未解决交互坍缩问题，导致模型在 RL 训练中逐渐减少工具调用。PyVision-RL 通过累积工具奖励显式激励多轮交互，而 DeepEyes-v2 依赖最终答案奖励，其工具调用行为是隐式优化的副产品。这一差异源于任务特性：视觉搜索任务中，工具调用的有效性直接决定答案正确性，而纯文本推理中工具调用并非必要，因此动态工具 RL 需要更精细的奖励设计以维持交互行为。

从方法设计看，PyVision-RL 与 VITAL 同属智能体视频理解框架，但 VITAL 采用静态视频裁剪工具，而 PyVision-RL 采用 Python 动态工具。VITAL 的静态工具集在视频任务上提供了稳定的交互协议，但缺乏灵活性，无法适应不同查询的视觉需求；PyVision-RL 的动态工具允许模型按需采样帧，显著降低视觉 Token 消耗（5K vs 45K），但其代价是引入了代码执行的不确定性，需要通过超采样-过滤-排序策略稳定训练。这一取舍反映了动态工具范式在效率与稳定性之间的权衡，而 VITAL 的静态工具则牺牲灵活性换取训练稳定性。

## 总结

PyVision-RL 旨在解决动态工具集成多模态模型在 RL 训练中的交互坍缩与训练不稳定问题。其切入点在于，现有方法依赖最终答案奖励，无法显式激励多轮工具调用，导致模型收敛至低交互行为；PyVision-RL 通过累积工具奖励与标准差排序筛选机制，使模型在训练中维持多轮交互能力。实验表明，PyVision-Image 在 WeMath 上较 DeepEyes-v2 提升 9.6%，PyVision-Video 在 VSI-Bench 上以 5K 视觉 Token 达到 44.0% 准确率，优于 Qwen2.5-VL-7B 的 38.0%（45K Token）。其边界在于，累积工具奖励仅以答案正确性为条件，未独立验证工具调用是否真正锚定视觉证据，模型可能通过无效调用获取奖励。当工具调用次数与视觉证据利用的相关性被量化时，累积奖励是否仍能有效抑制交互坍缩，论文未给出回答。
