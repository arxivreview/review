作者：Xiaochuan Li、Ryan Ming、Pranav Setlur 等 9 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.18998)

> 导读 现有智能体基准多局限于单一领域环境，无法反映真实用户跨域、开放式的交互需求，导致模型在专用环境中的高分无法迁移至通用场景。本文提出 General AgentBench，通过统一接口整合多域工具，并系统研究测试时扩展（Test-Time Scaling, TTS）在通用智能体中的有效性边界。其核心发现是顺序扩展受限于上下文天花板，并行扩展受限于验证差距，两者均未能带来稳定的性能提升。该基准揭示了通用智能体评估的严格性，但缺乏对成本效率的量化，且未探索更复杂的自我选择机制。

## 研究背景

当智能体面对跨领域的开放任务时，其推理过程依赖于对工具池的动态选择与长程状态管理。这种交互模式要求模型不仅具备单步推理能力，还需在累积的上下文历史中维持逻辑一致性，这一过程称为长时程状态漂移。状态漂移导致智能体在长对话中丢失关键信息或偏离目标，而现有基准通常通过隔离的环境掩盖了这一现象，使得模型在专用任务中的表现高估了其在真实部署中的鲁棒性。

智能体评估领域正从静态结果导向转向动态过程导向，但评估基础设施的碎片化阻碍了跨域能力的可比性。主流路线如 AgentCompass 和 Holistic Agent Leaderboard 致力于标准化执行环境，但它们仍主要关注单一基准内的性能聚合，缺乏对通用智能体在统一工具空间下行为模式的系统性研究。本文的切入点在于构建一个强制跨域工具共享的统一框架，并引入测试时扩展作为新的评估维度，以量化智能体在增加计算资源下的性能边界。

## 核心方法

### 统一交互抽象层

通用智能体评估的标准流程通常涉及任务定义、环境实例化及结果判定。本文的关键差异在于将环境实例化从“域隔离”转变为“全局共享”。设计动机是解决现有基准中工具接口碎片化导致的结果不可比问题，通过强制智能体在统一工具池中操作，模拟真实部署中智能体需从大量工具中筛选适用工具的场景。

### 测试时扩展机制

在统一框架下，本文引入两种测试时扩展策略以研究计算资源分配对性能的影响。顺序扩展通过延长交互历史来增加推理深度，其性能 $P_{seq}(L)$ 随上下文长度 $L$ 变化，公式为：

$$ P_{seq}(L) = \frac{1}{N} \sum_{i=1}^{N} \mathbb{1}[y_i(L) = y_i^*] $$

其中 $y_i(L)$ 为长度 $L$ 下的预测，$y_i^*$ 为真实标签。该公式揭示了随着 $L$ 增加，性能并非单调上升，而是存在一个“上下文天花板”，超过该点后性能波动或下降。并行扩展通过独立采样 $K$ 条轨迹并选择最优，其理论上限为 $past@K$，实际性能取决于自我选择准确率 $P_{self}$，公式为：

$$ P_{parallel}(K) = P_{self} \times past@K $$

这一设计旨在分离生成能力与选择能力，揭示“验证差距”对实际性能的限制。

## 实验评估

实验在 General AgentBench 上进行，覆盖搜索、编码、推理和工具使用四个领域，评估了包括 GPT-5、Claude Sonnet 4.5 在内的十个前沿模型。基线审计显示，本文对比了专用环境下的基线表现，但缺乏与 AgentCompass 等统一基础设施的直接横向对比，可能限制了结果的可比性。

| 模型 | Search (Avg) | Code (Avg) | Reason (Avg) | Tool-use (Avg) |
| :--- | :--- | :--- | :--- | :--- |
| GPT-5 | 27.4 | 56.0 | 64.0 | 72.9 |
| Claude Sonnet 4.5 | 23.1 | 45.0 | 36.0 | 69.0 |
| DeepSeek-V3.2 | 30.8 | 23.8 | 33.3 | 38.3 |
| Qwen3-235B | 27.7 | 6.3 | 32.0 | 63.3 |

GPT-5 在搜索和推理领域表现最强，而 Claude Sonnet 4.5 在工具使用领域领先。从专用环境到通用环境的迁移导致平均性能下降 10%-30%，其中 Gemini 2.5-Pro 在推理领域下降超过 60%。

消融实验表明，顺序扩展在上下文长度超过 128K 时性能显著波动，而并行扩展中 $past@K$ 随 $K$ 增加而上升，但自我选择准确率 $P_{self}$ 保持平稳，导致实际性能提升有限。这一反直觉发现表明，增加采样数量并不能有效缩小验证差距，智能体缺乏可靠的自我评估机制。

评估边界方面，本文未报告 Token 成本或延迟，无法评估测试时扩展的经济可行性。代码已开源，但超参数配置（如温度 0.7）固定，未探讨不同解码策略对扩展行为的影响。

## 关联研究分析

从问题动机看，General AgentBench 与 AgentCompass 均致力于解决评估碎片化，但 AgentCompass 侧重于模块化脚本的标准化，而本文强调跨域工具共享的通用性。这一差异源于任务特性：AgentCompass 旨在聚合多基准结果，而本文旨在模拟真实用户的多域交互。然而，本文未探索工具干扰噪声对性能的影响，跨域共享是否引入了非真实的工具冲突，论文未给出回答。

从方法设计看，本文引入测试时扩展作为评估维度，与 Holistic Agent Leaderboard 的静态准确率评估形成对比。Holistic Agent Leaderboard 关注性能与成本的帕累托前沿，而本文聚焦于计算资源分配对性能的影响。这一差异揭示了通用智能体评估的新维度，但本文未结合成本分析，限制了其在实际部署中的指导意义。

## 总结

本文要解决的核心矛盾是专用基准与通用智能体能力评估之间的脱节。通过构建统一工具接口并引入测试时扩展，本文揭示了通用智能体在跨域交互中的性能边界。实验证明，从专用到通用环境的迁移导致显著性能下降，且顺序与并行扩展均受限于上下文天花板和验证差距。本文的边界在于缺乏成本效率量化，且未探索更复杂的自我选择机制。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
