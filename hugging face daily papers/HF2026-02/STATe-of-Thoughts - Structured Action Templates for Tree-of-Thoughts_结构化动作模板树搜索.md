> 推理时计算（Inference-Time Compute, ITC）方法旨在通过增加计算资源提升生成质量与多样性，但现有基于温度采样的分支机制往往导致输出同质化，且缺乏对推理过程的可解释控制。本文切入点在于将随机采样替换为离散的动作模板前缀填充，使每个分支探索语义上截然不同的推理策略。STATe通过控制器选择动作、生成器执行前缀填充、评估器引导束搜索，实现了可审计的推理时干预。该方法在多样性与质量上均优于基线，但其依赖前缀填充的机制与闭源API不兼容，且动作-结果关联仅为相关性而非因果性。

## 研究背景

当语言模型面对复杂推理任务时，简单的输入-输出映射往往因幻觉或逻辑断裂而失效。为提升鲁棒性，推理时计算（ITC）方法通过扩展推理深度（如思维链 CoT）或广度（如 Best-of-N）来分配额外计算资源。然而，Best-of-N 依赖高温度采样产生多样性，这通常导致输出聚集在少数高概率完成上，缺乏有意义的语义变异。树搜索方法如思维树（Tree of Thoughts, ToT）虽引入了分支与剪枝，但其分支机制仍基于随机采样，导致不同分支间的推理策略高度相似，且无法解释哪些决策模式驱动了最终结果的成功或失败。

现有 ITC 方法的核心瓶颈在于“隐式性”：模型在解码过程中决定“说什么”和“怎么说”，但研究者无法直接控制或观察这些高层决策。这种黑箱特性限制了 ITC 作为分析工具的价值，特别是在需要系统性探索修辞结构或内容主题的研究场景中。本文的切入点是将推理决策显式化为离散的动作模板，通过前缀填充强制模型遵循特定的推理路径，从而在保持生成质量的同时，实现了对推理过程的细粒度控制与可解释性分析。

## 核心方法

### 方法参照系

本文问题置于树搜索框架下，与 ToT 的关键差异在于分支机制。ToT 在每层通过随机采样生成候选推理步骤，而 STATe 引入控制器从预定义的动作空间中选择离散动作，通过前缀填充引导生成。这一改动将分支多样性从“随机性”转化为“结构化干预”，使每个分支对应明确的高层推理选择。

### 动作模板前缀填充机制

ToT 的分支同质化源于温度采样在语义空间中的局部性。STATe 在控制器环节引入动作模板，将高层推理选择（如修辞结构、内容主题）编码为离散动作。控制器 $C$ 基于当前状态 $s_{i-1}$ 从动作空间 $\mathcal{A}$ 中选择 $n$ 个动作：

$$
\{a_{i}^{[1]}, \dots, a_{i}^{[n]}\} = \arg\max_{\mathcal{A}' \subset \mathcal{A}, |\mathcal{A}'|=n} \sum_{a_i \in \mathcal{A}'} Q(s_{i-1}, a_i)
$$

其中 $Q$ 为动作价值估计函数。生成器 $G$ 执行动作时，将动作对应的文本前缀（如 "For example"）强制注入生成序列，确保模型输出遵循指定结构。这一设计解决了 ToT 分支间语义重叠的问题，使每个分支探索根本不同的推理策略，同时通过前缀的显式性实现了干预的可审计性。

### 动作序列归因模型

STATe 的另一个创新是将生成过程转化为序列预测问题，以量化动作序列对输出质量的影响。传统方法仅关注动作的存在性，而 STATe 引入顺序模型 M2，编码动作的位置特征与转移特征：

$$
Y_i = \alpha + \mathbf{1}_a(\tau_i)\beta + \mathbf{1}_{a,k}(\tau_i)\gamma + \mathbf{1}_{a \to a', k \to k+1}(\tau_i)\delta + \epsilon_i
$$

其中 $\mathbf{1}_{a,k}$ 指示动作 $a$ 是否出现在第 $k$ 步，$\mathbf{1}_{a \to a', k \to k+1}$ 捕获连续动作二元组。该模型揭示了动作的时序结构对输出质量的预测力，使研究者能够识别高价值动作序列，并指导搜索探索未访问的动作空间区域。

## 实验评估

实验在 NoveltyBench（创意写作）与论证生成（5 个主题）上进行。基线覆盖 I/O、CoT、ToT 及其动作空间变体，但缺失表示工程类基线（如 RepE）与 RL 微调基线。在 NoveltyBench 上，STATe 在 7 个模型、3 种温度下均取得最高多样性与质量。以 Qwen3-30B 为例，中温度下多样性 4.57（vs. ToT w/ Actions 2.76），质量 3.52（vs. 2.32）。

| 模型 | 方法 | 多样性 (T=0.7) | 质量 (T=0.7) |
|---|---|---|---|
| Qwen3-30B | ToT w/ Actions | 2.76±0.08 | 2.32±0.06 |
| Qwen3-30B | STATe | 4.57±0.13 | 3.52±0.08 |
| Gemma-3-27B | ToT w/ Actions | 3.00±0.09 | 2.67±0.06 |
| Gemma-3-27B | STATe | 4.35±0.09 | 3.46±0.10 |

消融实验显示，前缀填充是多样性增益的关键：仅将动作空间加入提示（CoT w/ Action Space）无法匹配 STATe 的性能，证实了“强制”而非“存在”驱动多样性。在论证生成中，顺序模型 M2 的 $R^2$ 达 0.76-0.80，显著优于存在性模型 M1c（0.69-0.77），表明动作顺序携带预测信息。

评估边界方面，LLM-as-a-Judge 存在长度偏差，但 STATe 的输出 token 数少于基线，排除了冗长性贡献。代码已开源，但依赖前缀填充，与 GPT、Claude 等闭源 API 不兼容。GPU 需求为 2 卡（基线 1 卡），限制了大规模部署。

## 关联研究分析

从方法设计看，STATe 与表示工程（RepE）形成鲜明对比。RepE 假设属性在激活空间中呈线性编码，通过向量编辑实现隐式控制；STATe 则使用显式文本前缀，强调可审计性。这一差异源于任务特性：RepE 适用于细粒度属性强度调节，而 STATe 聚焦于高层推理结构的离散选择。前缀填充的显式性牺牲了模型内在分布的保真度，但换来了干预的透明性，这在需要解释推理模式的场景中至关重要。

从问题动机看，STATe 与 C3TG 均涉及多目标优化，但 C3TG 解决多属性冲突（如情感与主题），STATe 解决多动作序列的协同效应。C3TG 依赖多智能体协作，计算开销高；STATe 通过束搜索与动作归因，在单次生成中实现序列优化。STATe 的局限在于仅支持单轮交互，不支持外部工具调用，这限制了其在复杂代理管道中的应用。

## 总结

STATe 解决了 ITC 方法中分支同质化与推理不可解释的矛盾，通过离散动作模板前缀填充实现了可审计的推理时控制。在 NoveltyBench 上，STATe 的多样性较 ToT w/ Actions 提升 65%（4.57 vs. 2.76），质量提升 52%（3.52 vs. 2.32）；在论证生成中，动作序列模型 M2 的 $R^2$ 达 0.76，证实了时序结构的预测力。其边界在于依赖前缀填充，与闭源 API 不兼容，且动作-结果关联仅为相关性。当动作空间维度增加时，前缀填充的上下文窗口依赖是否会导致长文本生成中的控制失效，论文未给出回答。
