# HuggingFace最新推荐论文 ｜Learning to Configure Agentic AI Systems ｜分层强化学习驱动的代理系统配置优化

研究机构：美国亚利桑那州立大学

作者：Aditya Taparia、Som Sagar、Ransalu Senanayake

论文原文见 [arXiv](https://arxiv.org/abs/2602.11574)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.11574)

LLM 智能体工作流编排旨在解决单一模型在长程复杂任务中的认知局限，核心挑战在于如何以最低计算成本动态生成适应特定查询的多智能体协作拓扑。现有方法多依赖静态模板或人工启发式，导致“一刀切”的资源分配，在简单任务上浪费算力，在复杂任务上因上下文过载而性能衰减。本文提出 ARC（Agentic Resource & Configuration learner），将代理配置视为查询级决策问题，通过分层强化学习（Hierarchical Reinforcement Learning, HRL）联合优化工作流、工具、预算与提示，实现成本-性能帕累托最优。该方法在多个基准上超越静态基线，但其在知识密集型任务上的表现揭示了结构优化与语义内容之间的张力。

## 研究背景

理解本文需厘清代理系统配置的组合爆炸特性。一个包含 3 个代理、5 种工作流模式、3 种工具及 3 档预算的系统，其结构配置空间即达 8,600 种，若加入提示选择则超过 $10^5$ 种。这种组合空间使得暴力搜索不可行，而人工调优无法覆盖开放域任务的多样性。传统方法如 ReAct 或 MetaGPT 采用固定角色与流程，虽结构稳定，但缺乏对查询难度的自适应能力，导致在简单算术题上触发昂贵的多跳推理与验证循环。

领域主流路线已从静态模板转向自动化生成。2024 年 GPTSwarm 利用强化学习优化代理间连接拓扑，2025 年 DAAO 引入变分自编码器估计查询难度以分配算子子集。然而，这些方法多聚焦于结构拓扑或算子选择，未将提示工程、工具调用与预算分配纳入统一的端到端优化框架。本文切入点在于将全栈配置（工作流、工具、预算、提示）建模为分层决策问题，通过轻量级控制器在冻结的 LLM 骨干上实现查询特定的资源调配，解决了静态系统无法适应任务难度差异导致的效率低下问题。

## 核心方法

### 分层策略架构

本文方法参照系为基于搜索的工作流优化（如 AFlow 的 MCTS），但关键差异在于将离散搜索转化为连续策略学习。ARC 将配置空间分解为结构策略 $\pi_{struct}$ 与提示策略 $\pi_{prompt}$。结构策略负责选择工作流 $\omega$、工具集 $\mathbf{t}$ 与预算 $\mathbf{b}$，提示策略负责组合具体指令。这种分层设计将联合决策 $O(|A_{struct}||A_{prompt}|)$ 转化为序贯决策，有效降低了搜索复杂度。

### 掩码强化学习与奖励塑形

针对结构策略中存在的无效配置（如 DIRECT 工作流下分配多余代理预算），本文引入动作掩码（Action Masking）。在采样阶段，根据选定的工作流 $\omega$，将不兼容动作的 logits 设为 $-\infty$，确保策略仅在可行配置空间内归一化。奖励函数 $R$ 分解为正确性、计算开销与工具利用三项：

$$
R = \mathbb{I}[\text{correct}] - \alpha \frac{n_{steps}}{T_{max}} - \beta_s \frac{n_{tokens}}{T_{max}} + R_{tool}
$$

其中 $R_{tool}$ 采用非对称设计：若工具被分配且使用，给予奖励 $\delta_1 + \delta_2 \mathbb{I}[\text{correct}]$；若分配但未使用，施加惩罚 $\delta_3$。这一设计解决了传统奖励中“工具分配”与“工具调用”脱节的问题，迫使策略精确预测 LLM 的工具调用行为，避免资源浪费。

### 精英轨迹监督微调

RL 训练后，策略仍存在随机性。本文引入 SFT 精炼阶段，从 RL 缓冲区中提取奖励高于阈值 $\tau$ 的 Top 30% 精英轨迹，对策略网络进行监督微调。该阶段仅更新轻量级策略网络，不触及 LLM 骨干，计算成本极低。SFT 通过蒸馏成功配置，降低了输出方差，提升了策略在测试集上的一致性，验证了 Theorem 3.2 中关于性能下界的保证。

## 实验评估

实验在 GSM8K、DROP、MedQA、HotpotQA 和 GAIA 五个基准上进行，对比基线包括 Grid/Greedy Search、AutoGen、DSPy、GEPA 及扁平 RL 策略。ARC 在推理任务上表现突出，GSM8K 准确率达 88.6%（Qwen 2.5 7B），较 GEPA 的 83.6% 提升 5 个百分点；在工具使用任务上，HotpotQA 准确率为 34.1%，与 AutoGen 持平，但显著优于扁平 RL 基线。

| 方法 | GSM8K (%) | DROP (%) | MedQA (%) | HotpotQA (%) | GAIA (%) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Base Model (Qwen 7B) | 37.8 | 36.4 | 49.1 | 10.1 | 6.1 |
| Grid Search | 74.0 | 54.3 | 53.1 | 27.9 | 14.45 |
| GEPA | 83.6 | 39.3 | 87.1 | 27.4 | 10.2 |
| ARC (Qwen 7B) | **88.6** | **63.9** | 64.6 | **34.1** | **6.0** |
| ARC (Gemini 2.5 FL) | **88.5** | **65.6** | **64.7** | **35.7** | **4.0** |

消融实验显示，SFT 精炼阶段带来 1-3% 的准确率提升，并提高平均奖励 5-35%。然而，在 MedQA 上，ARC（64.6%）显著低于 GEPA（87.1%），作者归因于 GEPA 使用了约 1,100 tokens 的领域特定医疗提示，而 ARC 的提示库仅为通用推理提示（约 50 tokens）。这表明在知识密集型领域，提示的语义内容可能主导结构选择，ARC 当前的原子库未针对此优化。

评估边界方面，论文未报告置信区间，且 GAIA 测试集仅使用 65 个样本训练，其余用于评估，样本量较小。代码已开源，但超参数细节（如 $\lambda$ 值）未在正文详述，复现需查阅附录。

## 关联研究分析

从问题动机看，ARC 与 DAAO 同属查询自适应路线，但优化对象不同。DAAO 通过变分自编码器估计难度，仅分配算子子集与模型路由，而 ARC 将提示组合纳入决策空间，实现了更细粒度的控制。这一差异源于任务特性：DAAO 假设工作流结构固定，仅调整资源；ARC 假设结构可变，需联合优化。然而，ARC 在 MedQA 上的劣势暗示，当任务依赖特定领域知识时，结构优化的边际收益可能低于提示内容的语义丰富度，这是 ARC 未探索的盲区。

从方法设计看，ARC 与 GPTSwarm 均利用 RL 优化代理系统，但 GPTSwarm 聚焦于代理间连接拓扑的动态调整，属于结构级优化；ARC 则聚焦于单个代理系统内部的资源配置与提示组合，属于配置级优化。GPTSwarm 的搜索空间是图结构，ARC 的搜索空间是配置向量。ARC 引入动作掩码处理无效配置，这一设计在 GPTSwarm 中未显式出现，因为图结构的无效性通常由连通性约束隐式处理。ARC 的掩码机制更适用于离散配置空间，但在连续图优化中可能面临不同的挑战。

## 总结

本文核心矛盾在于静态代理系统无法适应查询难度差异导致的计算浪费与性能衰减。ARC 抓住“全栈配置”这一被忽略的维度，通过分层 RL 将工作流、工具、预算与提示联合优化，解决了扁平 RL 在组合空间中探索效率低下的问题。实验证明 ARC 在 GSM8K 上达到 88.6% 准确率，较基线提升 5 个百分点，并在成本-性能帕累托前沿上占据优势。其边界在于知识密集型任务上提示语义内容的缺失导致性能落后于领域特定提示方法，且 GAIA 等小样本基准的评估稳定性存疑。当提示库扩展至领域特定内容时，ARC 的结构优化收益是否会被语义内容主导，论文未给出回答。
