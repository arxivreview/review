# HuggingFace最新推荐论文 ｜SkillsBench: Benchmarking How Well Agent Skills Work Across Diverse Tasks ｜代理技能效能基准

研究机构：美国俄亥俄州立大学、美国达特茅斯学院

作者：Xiangyi Li、Wenbo Chen、Yimin Liu 等 41 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.12670)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.12670)

> 代理技能旨在通过注入程序性知识提升大语言模型（LLM）代理在复杂任务中的表现，但现有研究缺乏量化技能实际增益的标准手段。主流方法聚焦于技能的生成与优化算法，却未建立隔离模型能力与技能效用的评估框架，导致无法区分性能提升源于模型本身还是外部知识。本文构建了SkillsBench，通过无技能、精选技能与自生成技能三条件对照，系统测量技能在不同模型-框架组合下的效能边界。该基准确立了技能评估的基础标准，但其静态注入设计无法反映动态进化场景下的真实效用。

## 研究背景

当LLM代理执行跨领域专业任务时，基础模型缺乏特定领域的操作流程知识，而微调成本高且牺牲泛化能力。代理技能（Agent Skill）作为包含指令、代码模板与验证逻辑的结构化包，在推理时增强代理行为而不修改模型权重。技能的有效性依赖于其程序性内容的质量，但当前领域缺乏区分技能贡献与模型基础能力的评估机制。

现有代理基准（如Terminal-Bench、SWE-bench）仅评估固定代理的任务完成能力，回答“模型X能多好地完成任务Y”，而非“技能Y对任务X的提升幅度”。这种评估缺口导致从业者无法做出技能采纳的知情决策，研究者缺乏技能设计原则的实证基础。主流技能研究路线聚焦于技能生成（如Voyager）、检索（如ToolkenGPT）与优化（如SkillOpt），但均假设技能有效，未验证其实际增益。本文切入点在于将技能作为一等评估对象，通过配对实验设计量化技能效能。

## 核心方法

### 技能定义与评估框架

本文问题属于代理增强效能评估类别，与通用代理基准的关键差异在于引入技能变量作为独立评估维度。标准代理基准测量固定配置下的任务成功率，而本文测量同一配置下不同技能条件的性能差值，从而解耦技能贡献。

### 三条件对照实验设计

设计动机：隔离模型潜在知识与外部技能注入的效应，解决“性能提升源于模型还是技能”的归因难题。本文在每个任务下执行三种条件：无技能（仅指令）、精选技能（完整技能包）、自生成技能（提示模型生成程序性知识）。自生成条件作为负对照，检验模型能否可靠地自我生成其受益的程序性知识。

$$
\Delta_{abs} = P_{with\_skills} - P_{no\_skills}
$$

该公式计算绝对增益，直接反映技能对通过率的提升幅度。

$$
g = \frac{P_{with\_skills} - P_{no\_skills}}{1 - P_{no\_skills}}
$$

归一化增益衡量向完美性能的相对改进比例，用于区分天花板效应与真实脚手架效应。高g低Δabs暗示天花板效应，高g高Δabs表明实质性支撑。

### 技能质量控制与泄漏审计

设计动机：防止技能编码任务特定解法，确保测量的是程序性指导而非答案泄露。本文实施双重控制：作者指南禁止技能包含任务特定文件名、精确命令序列或测试用例引用；CI中运行基于Claude Code Agent SDK的验证代理，检测技能-解法泄漏，失败任务被拒绝。技能必须提供任务类的程序性指导，而非特定实例的声明式答案。

## 实验评估

实验在84个跨11领域任务上评估7个模型-框架配置，产生7,308条有效轨迹。基线覆盖无技能与自生成技能，但未包含动态优化方法（如SkillOpt、SkillGrad），因本文仅测静态注入。主结果显示精选技能平均提升+16.2pp，但方差大（+13.6pp至+23.3pp），自生成技能平均-1.3pp。

| 配置 | 无技能 (%) | 精选技能 (%) | 自生成技能 (%) |
| :--- | :--- | :--- | :--- |
| Gemini CLI + Gemini 3 Flash | 31.3 | 48.7 | – |
| Claude Code + Opus 4.5 | 22.0 | 25.3 | – |
| Codex + GPT-5.2 | 30.6 | 45.3 | 21.6 |
| Claude Code + Opus 4.6 | 30.6 | 29.9 | 25.0 |
| Gemini CLI + Gemini 3 Pro | 27.6 | 44.7 | – |
| Claude Code + Sonnet 4.5 | 17.3 | 31.8 | 15.2 |
| Claude Code + Haiku 4.5 | 11.0 | 27.7 | 11.0 |
| **均值** | **24.3** | **40.6** | **21.0** |

Gemini 3 Flash + 精选技能达48.7%最高通过率，而Codex + GPT-5.2自生成技能降至21.6%（-5.6pp），显示模型无法可靠自我生成有效程序性知识。

| 技能数量 | 精选技能 (%) | 无技能 (%) | Δabs (pp) |
| :--- | :--- | :--- | :--- |
| 1个技能 | 42.2 | 24.4 | +17.8 |
| 2–3个技能 | 42.0 | 23.4 | +18.6 |
| 4+个技能 | 32.7 | 26.9 | +5.9 |

2–3个技能最优（+18.6pp），4+个技能收益骤降至+5.9pp，验证上下文溢出假设。领域差异显著：医疗+51.9pp，软件工程+4.5pp，16/84任务显示负增益（如taxonomy-tree-merge -39.3pp），表明技能可能引入冲突指导。

评估边界：指标仅含通过率与归一化增益，未报告计算效率（Token成本、延迟）；评估协议基于静态注入，无法反映动态进化场景；代码与数据集发布于skillsbench.ai，但超参数与GPU配置未在正文详述。

## 关联研究分析

从问题动机看，本文与SkillOpt、SkillGrad等动态优化方法形成互补而非竞争。SkillOpt通过验证门控迭代优化技能文档，假设技能可改进；本文则测量静态技能的初始效能，揭示16个负增益任务，暗示缺乏迭代修正的静态技能存在固有局限。差异根源在于任务特性：动态优化方法适用于技能可迭代改进的场景，而本文基准适用于技能内容固定、需评估初始效用的场景。

从方法设计看，本文与Voyager共享技能定义（代码+指令），但Voyager侧重技能生成，本文侧重效能评估。Voyager假设技能可复用，但未量化其实际增益；本文通过三条件对照证明自生成技能无效，暗示模型缺乏从具体到抽象的归纳能力。这一发现与知识库中“技能泛化与过拟合平衡”问题相关，但本文未探索动态粒度选择机制，仅验证静态注入的效能边界。

## 总结

本文核心矛盾在于技能效能缺乏标准化评估，现有方法聚焦生成与优化算法，未建立隔离模型能力与技能效用的框架。本文通过三条件对照实验设计，将技能作为一等评估对象，量化其在不同模型-框架组合下的效能边界。精选技能平均提升+16.2pp，但2–3个技能最优、16个任务负增益的发现，揭示了静态注入的固有局限。当技能内容固定且无法迭代修正时，其效能是否受限于模型对程序性知识的理解能力，而非技能本身的质量，论文未给出回答。
