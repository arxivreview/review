> 深度研究智能体在长程任务中常因线性执行逻辑陷入局部最优，导致早期规划分支被遗忘且资源浪费于重复探索。现有测试时扩展方法依赖独立轨迹的并行投票，缺乏跨轨迹的经验共享机制，无法有效整合分散的推理线索。Re-TRAC 通过递归压缩历史轨迹为结构化状态表示，并以此条件化后续推理，实现了串行经验积累与全局感知规划。该方法在前沿模型上带来显著性能提升，但其在小模型上的泛化能力依赖于特定蒸馏数据，且未验证与强化学习结合后的长期稳定性。

## 研究背景

深度研究智能体通常基于 ReAct 范式构建，该范式将推理步骤与工具调用交替执行并线性追加至上下文。当任务涉及数十万 token 的长程交互时，模型面临“灾难性遗忘”：早期制定的关键目标被中间大量的工具调用结果淹没，导致智能体无法回溯已规划的分支，陷入局部最优或冗余探索。这种线性结构使得智能体难以在长上下文中维持全局规划一致性，成为制约其解决复杂开放式任务的核心瓶颈。

当前领域主流路线分为架构优化与训练优化两类。架构派如 IterResearch 引入外部记忆结构重构任务状态，训练派如 ASearcher 依赖大规模强化学习优化策略。然而，架构派往往增加系统复杂度，训练派则需高昂计算成本且依赖验证答案。Re-TRAC 的切入点在于利用模型自身的推理能力，通过一种无训练的提示策略，将独立轨迹转化为条件依赖的序列，从而在不改变底层模型参数的前提下，解决长程探索不足与资源浪费问题。

## 核心方法

### 方法参照系

Re-TRAC 建立在标准 ReAct 框架之上，但改变了其单次线性执行的逻辑。标准流程中，每次推理尝试（rollout）均从原始查询开始，彼此独立；Re-TRAC 则引入“轨迹压缩-状态更新-递归执行”循环，使后续推理显式依赖前序轨迹的结构化摘要，从而将孤立尝试转化为渐进式搜索过程。

### 结构化状态表示生成

在每次 rollout 结束后，Re-TRAC 并非直接丢弃历史，而是通过固定压缩规范 $C$ 将轨迹 $\tau_t$ 蒸馏为结构化状态表示 $S_t$。该状态包含三个互补维度：答案与分析结论（记录最佳部分答案及关键推断）、证据基础与来源验证（追踪已咨询来源及已验证声明）、不确定性与探索轨迹（记录未解决假设、失败尝试及候选分支）。状态更新公式为：

$$ S_{t+1} = C(\tau_t, S_t) $$

这一设计解决了线性 ReAct 中早期计划被遗忘的问题，通过显式保留未探索分支，防止探索空间坍缩至单一路径，确保后续轮次能基于全局感知进行针对性搜索。

### 递归执行与经验传播

Re-TRAC 将 $S_t$ 作为初始用户消息插入系统提示之后，作为下一轮 ReAct 循环的输入。这种递归机制使得智能体在每轮开始时即知晓“已验证什么”、“未解决什么”以及“下一步重点”。与 Best-of-N 等并行方法不同，Re-TRAC 的串行特性允许模型利用前序轮次的失败经验避免重复工具调用，从而在提升覆盖率的同时降低 token 消耗。实验表明，随着轮次增加，工具调用次数与 token 使用量呈单调递减趋势，验证了该机制在减少冗余探索方面的有效性。

## 实验评估

实验在 BrowseComp、GAIA、XBench 等五个基准上进行，基线涵盖闭源模型（GPT-5, o3）及开源同规模模型（Tongyi-DeepResearch, MiniMax-M2）。Re-TRAC-30B-A3B 在 BrowseComp 上取得 53.0% 准确率，超越基线 Tongyi-DeepResearch 的 43.4% 及 MiniMax-M2-229B 的 44.0%；在 GAIA 上达到 78.2%，显著高于基线的 70.9%。

| 模型 | BrowseComp | BrowseComp-zh | GAIA | XBench | HLE |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Tongyi-DeepResearch-30B-A3B | 43.4 | 46.7 | 70.9 | 75.0 | 32.9 |
| MiniMax-M2-229B | 44.0 | 48.5 | 75.7 | 72.0 | 31.8 |
| **RE-TRAC-30B-A3B** | **53.0** | **57.3** | **78.2** | **83.0** | 31.5 |
| **RE-TRAC-4B** | **30.0** | **36.1** | **70.4** | **76.6** | **22.2** |

消融实验显示，使用自由使用提示（free-use prompt）后，o3 在 BrowseComp300 上的准确率从 54.9% 提升至 69.8%（RT@8），而多数投票（MV@8）仅达 64.3%。这表明 Re-TRAC 的递归机制比独立投票更能有效整合信息。然而，GLM-4.7 在 Best-of-N 中表现不佳，暗示其自我判断能力较弱，但 Re-TRAC 仍能提供增益，证明该方法对模型智能要求较低。

评估边界方面，论文未报告置信区间，且 GAIA 高分可能受特定子集影响。代码已开源，但小模型训练依赖 GLM-4.7 生成的 104k 样本，复现需大量计算资源。

## 关联研究分析

从方法设计看，Re-TRAC 与 IterResearch 均利用外部记忆，但前者侧重轨迹级递归压缩，后者侧重步骤级动态重构。Re-TRAC 的串行依赖结构使其能显式保留未探索分支，而 IterResearch 的独立记忆结构可能导致早期关键细节在多次迭代中丢失。这一差异源于 Re-TRAC 对“经验积累”而非“状态重置”的侧重，更适合需要全局规划的任务。

从问题动机看，Re-TRAC 与 ASearcher 代表架构派与训练派的不同路径。ASearcher 依赖大规模 RL 优化策略，需验证答案且计算成本高；Re-TRAC 作为无训练策略，直接利用模型推理能力，适用于无法进行大规模训练的场景。然而，Re-TRAC 未探索与 RL 结合的可能性，其在更复杂任务中是否仍具优势，论文未给出回答。

## 总结

Re-TRAC 旨在解决长程深度研究任务中线性 ReAct 框架导致的探索不足与资源浪费问题。其切入点在于利用模型自身推理能力，通过递归压缩轨迹为结构化状态表示，实现跨轨迹经验共享与全局感知规划。该方法在前沿模型上带来 15-20% 的性能提升，并在 30B 规模开源模型中确立 SOTA。然而，其小模型性能依赖于特定蒸馏数据，且未验证与强化学习结合后的长期稳定性。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
