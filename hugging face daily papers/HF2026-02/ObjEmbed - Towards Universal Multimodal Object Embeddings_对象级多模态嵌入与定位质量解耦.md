# HuggingFace最新推荐论文 ｜ObjEmbed: Towards Universal Multimodal Object Embeddings ｜对象级多模态嵌入与定位质量解耦

研究机构：中山大学

作者：Shenghao Fu、Yukun Su、Fengyun Rao 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.01753)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.01753)

> 多模态检索长期受困于全局图像嵌入对局部对象语义的模糊化，导致在自动驾驶、机器人等定位敏感场景中，模型无法区分“语义正确但位置错误”的候选。现有方法如 FG-CLIP 虽引入区域对比，却缺乏对边界框质量的显式建模，而开放词汇检测器受限于数据规模难以泛化。ObjEmbed 通过 MLLM 架构将对象语义与 IoU 回归解耦为独立 Token，实现单次前向传播内的对象级精准匹配。该框架在对象检测与局部检索上表现强劲，但其性能高度依赖提案生成器的召回率，且未验证在长尾分布下的鲁棒性。

## 研究背景

当检索系统面对“图中左侧的红色汽车”这类查询时，全局嵌入往往将整张图像压缩为单一向量，导致局部对象特征被背景噪声稀释。这种语义模糊化源于对比学习范式中的全局对齐假设，即假设图像与文本在整体语义层面匹配即可。然而，在细粒度任务中，对象的位置精度与语义判别同等重要，这要求模型不仅理解“是什么”，还需评估“在哪里”以及“定位有多准”。

多模态嵌入模型的主流路线分为双塔对比学习与 MLLM 统一编码两类。双塔模型如 CLIP 确立了零样本检索基线，但其模态独立编码假设导致模态间隙，且无法捕捉对象级交互；FG-CLIP 通过区域对比缓解此问题，但其对象嵌入仅用于分类，缺乏定位质量信号。开放词汇检测器如 GLIP 虽能定位，但依赖 CLIP 特征蒸馏或有限训练数据，泛化能力受限。ObjEmbed 的切入点在于利用 MLLM 的强语义理解能力，同时通过显式回归机制弥补嵌入模型在定位精度评估上的缺失，将“语义匹配”与“定位置信度”解耦为两个独立的优化目标。

## 核心方法

### 方法参照系

本文问题可置于“细粒度跨模态对齐”范畴，但与传统区域-词匹配不同，ObjEmbed 不依赖人工标注的区域-词对，而是通过提案生成器自动提取 RoI，并将定位质量作为嵌入的一部分。关键差异在于：传统方法将定位视为后处理或独立任务，而本文将 IoU 预测内嵌于嵌入生成过程，使匹配分数直接反映定位可靠性。

### 对象语义与定位质量解耦

在 MLLM 编码流程中，每个对象由两个特殊 Token 表示：`<object>` 捕获语义内容，`<iou>` 回归边界框质量。设计动机在于，单 Token 联合学习语义与定位会导致优化冲突——语义匹配倾向于模糊边界以覆盖更多区域，而定位回归要求紧致边界。解耦后，`<object>` 专注语义判别，`<iou>` 专注空间精度，二者通过乘积组合为最终匹配分数：

$$
S_{\text{match}} = S_{\text{sem}} \times S_{\text{iou}}
$$

其中 $S_{\text{sem}}$ 为对象嵌入与文本嵌入的余弦相似度，$S_{\text{iou}}$ 为 IoU 嵌入经线性头预测的 IoU 分数。该公式确保只有当语义匹配度高且定位质量高时，对象才会获得高匹配分数，有效抑制“语义正确但位置偏移”的误检。

### 单次前向传播的对象序列编码

ObjEmbed 将图像中所有对象（最多 100 个）的 RoI 特征通过 RoIAlign 提取，经对象投影器压缩为单 Token，与全局图像 Token 并行输入 LLM。设计动机在于，传统方法需对每个对象单独编码或进行自回归生成，计算开销随对象数量线性增长。本文通过序列编码，使所有对象在单次前向传播中完成嵌入生成，序列长度控制在 2000 以内，兼容 FlashAttention-2 加速。该设计将对象编码从“逐个处理”转变为“批量并行”，显著提升了推理效率，同时保持了对象间的区分性（通过 “Object i:” 提示分隔）。

## 实验评估

实验在 COCO、RefCOCO、LVIS 等 18 个基准上进行，基线覆盖传统检测器（DINO）、开放词汇检测器（GLIP、OWLv2）及 MLLM（WeDetect-Ref）。ObjEmbed-4B 在 COCO 检测任务上取得 53.0% mAP，在 RefCOCO 上取得 89.5% 平均准确率，在局部图像检索任务上比全局嵌入模型高约 20 个点。

| 方法 | COCO AP | RefCOCO Avg Acc | 局部检索 Avg |
| --- | --- | --- | --- |
| WeDetect-Ref-4B | 50.0 | 88.6 | 67.4 |
| ObjEmbed-4B | 53.0 | 89.5 | 68.5 |

消融实验显示，将分类标签从二值改为 IoU 值可提升 5.2% mAP，而解耦为两个 Token 进一步提升 3.2% mAP，验证了优化冲突假设。使用两个全局图像 Token（分别对应长短描述）比单 Token 提升 0.4 点全局检索性能，表明多粒度监督有助于平衡不同任务需求。

评估边界方面，论文未报告置信区间，且局部检索基准（如 EDIS）仅展示单一结果，缺乏与 GCL、TTE-v2 等通用 SOTA 的同协议对比。代码已开源，训练使用 16 GPU，超参数（如 $\lambda_1=1.0, \lambda_3=0.25$）已公开，可复现性良好。

## 关联研究分析

从问题动机看，ObjEmbed 与 FG-CLIP 均关注区域对齐，但 FG-CLIP 将区域嵌入仅用于分类，无法评估定位质量，导致在定位敏感任务中误检率高。ObjEmbed 通过 IoU 回归显式建模定位置信度，解决了“语义匹配但位置错误”的失效场景。这一差异源于任务特性：FG-CLIP 面向通用检索，定位精度非核心指标；而 ObjEmbed 面向对象级任务，定位质量是匹配分数的必要组成部分。

从方法设计看，ObjEmbed 与 WeDetect-Ref 共享 MLLM 骨干与提案生成器，但 WeDetect-Ref 侧重检测与指代理解，未引入全局图像嵌入，无法支持图像级检索。ObjEmbed 通过引入 `<global>` Token 与长短描述监督，实现了对象级与图像级任务的统一，但其代价是训练数据需同时包含区域与全局标注，数据构建复杂度高于纯检测任务。

## 总结

ObjEmbed 解决了多模态嵌入中对象语义与定位质量耦合导致的优化冲突，通过解耦 Token 设计使模型能同时评估“是什么”与“定位多准”。在 COCO 上 53.0% mAP 与 RefCOCO 上 89.5% 准确率的性能验证了该解耦架构的有效性，且单次前向传播编码保证了效率。然而，其性能高度依赖提案生成器的召回率，当提案缺失时模型无法编码对应对象，这一局限在长尾分布或复杂场景下可能加剧。当提案生成器的 AR 从 66.7 降至 50.0 时，ObjEmbed 的 mAP 下降幅度是否超过 10 个点，论文未给出回答。
