# HuggingFace最新推荐论文 ｜UI-Venus-1.5 Technical Report ｜统一端到端GUI智能体训练与部署

作者：Venus Team、Changlong Gao、Zhangxuan Gu 等 27 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.09082)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.09082)

> 图形用户界面智能体（GUI Agent）旨在通过像素级截图理解并操作数字设备，以摆脱对HTML或Accessibility Tree等结构化数据的依赖。现有方法在长程任务中面临步级动作正确但整体轨迹失败的精度不匹配，且多任务模型部署复杂。本文切入点在于构建一个纯端到端的统一模型，通过大规模中间训练、全轨迹在线强化学习及模型合并策略，将定位、网页与移动端导航能力整合至单一检查点。该范式在多个基准上刷新了性能上限，但其依赖的模型合并策略在静态定位任务上引入了轻微的性能折损，且在线强化学习的规模化成本仍未完全解决。

## 研究背景

GUI智能体的核心困境在于视觉定位（Grounding）的精度与长程任务中的错误累积。当模型面对复杂界面时，单步动作的微小偏差会随轨迹长度指数级放大，导致任务失败。这种“步级-轨迹级精度不匹配”源于训练数据中奖励信号的稀疏性以及训练分布与真实基准间的域偏移。为缓解此问题，领域主流路线转向强化学习（RL），但纯监督微调（SFT）难以提供足够的探索信号，而在线RL又面临高昂的环境交互成本与策略崩溃风险。

早期工作如UI-Venus-1.0依赖纯RL实现了定位与导航的SOTA，但缺乏统一的部署形态，且未解决基础GUI语义缺失导致的探索困难。随着多模态大语言模型（MLLM）视觉感知能力的突破，领域共识认为视觉输入优于结构化文本，但如何高效地将这种感知能力转化为稳定的长程决策能力仍是瓶颈。本文针对这一痛点，提出在RL之前引入大规模中间训练（Mid-Training）以建立基础GUI知识，并通过全轨迹在线RL与模型合并，实现单一模型对多平台、多任务的统一覆盖，旨在解决部署复杂性与精度不匹配的双重挑战。

## 核心方法

### 方法参照系

标准GUI智能体训练流程通常遵循“SFT初始化 -> 任务特定RL优化”的路径。本文的关键差异在于插入大规模Mid-Training阶段，并采用多任务RL后合并（Model Merging）策略，而非单任务端到端训练。这种设计将“能力获取”与“能力统一”解耦，前者通过数据规模建立语义基础，后者通过参数空间插值实现多任务兼容。

### 大规模中间训练与数据精炼

Mid-Training阶段旨在弥补通用视觉语言模型在GUI结构理解上的粒度缺失，为后续RL提供稳定的策略初始化。该阶段使用30+数据集、总计10B tokens的语料，其中语义感知占20.8%，GUI-VQA占22.1%，定位占24.8%。数据精炼采用基于Qwen3-VL-235B-A22B的教师评分机制，将样本分为高（≥7分）、中（4-6分）、低（0-3分）三类，高分保留，中分重写，低分重构或丢弃。通过递归精炼，高保真样本比例从69.7%提升至89.7%。这一设计解决了SFT阶段因数据噪声导致的策略收敛困难，使模型在进入RL前已具备基础的GUI-VQA与简单导航能力。

### 全轨迹在线强化学习与模型合并

在线RL阶段采用组相对策略优化（GRPO）算法，通过全轨迹rollout计算奖励，以解决步级奖励稀疏问题。轨迹级优势 $\hat{A}_i$ 通过组内相对分数归一化获得：

$$ \hat{A}_i = \frac{R(\tau_i, q) - \text{mean}(R(\tau_j, q))}{\text{std}(R(\tau_j, q))} $$

该公式将整条轨迹的成败信号均匀分配至每个动作步，过滤环境随机性，提供稳定的信用分配。为防止策略崩溃，引入自适应KL约束与退火熵正则化。最终，通过TIES-Merge将定位、网页、移动端三个专用模型合并为单一模型。TIES-Merge通过剪枝低幅度更新并解决符号冲突，相比线性合并显著降低了性能回退。例如，UI-Venus-1.5-30B-A3B在合并后，AndroidWorld成功率从75.5%提升至77.6%，而ScreenSpot-Pro仅下降1.4%。

## 实验评估

实验在ScreenSpot-Pro、VenusBench-GD、AndroidWorld、WebVoyager等基准上进行，基线覆盖MAI-UI、UI-TARS-1.5、Holo2、GTA1等GUI专用模型及Qwen3-VL等通用VLM。缺失MobileRL等最新在线RL基线的直接对比，可能影响对在线RL上限的判断。

| 模型 | ScreenSpot-Pro | VenusBench-GD | AndroidWorld | WebVoyager |
| :--- | :--- | :--- | :--- | :--- |
| UI-Venus-1.5-30B-A3B | 69.6 | 75.0 | 77.6 | 76.0 |
| MAI-UI-32B | 67.9 | - | - | - |
| UI-Venus-1.0-72B | 61.9 | 70.2 | - | - |
| Holo2-30B-A3B | 66.1 | 59.5 | - | - |

UI-Venus-1.5-30B-A3B在ScreenSpot-Pro（69.6%）和VenusBench-GD（75.0%）上取得SOTA，AndroidWorld成功率77.6%优于Mobile-Agent-v3等基线。消融实验显示，Mid-Training使Silhouette Score从0.235提升至0.315，表明GUI特征聚类更紧密；在线RL为2B模型带来+14.5%的AndroidWorld绝对增益，验证了动态环境交互对长程任务的关键作用。模型合并导致ScreenSpot-Pro下降1.4%，但AndroidWorld提升2.1%，表明合并过程促进了跨任务知识迁移，但牺牲了部分静态定位精度。

评估边界方面，论文未报告推理延迟与Token消耗，且多数对比基线未提供置信区间。代码与模型已开源，但Mid-Training的10B tokens数据构成细节未完全公开，限制了完全复现。

## 关联研究分析

从问题动机看，UI-Venus-1.5与UI-S1均关注长程任务中的错误恢复，但UI-S1侧重半在线RL的稳定性，通过补丁模块平衡探索与利用；本文则强调在线RL的规模化与多任务统一。UI-S1在AndroidWorld上取得72.0%，低于本文的77.6%，这可能源于本文Mid-Training阶段建立的更强基础语义，使得在线探索更高效。然而，UI-S1的半在线范式在计算成本上更具优势，本文的在线RL虽性能更高，但环境交互成本未量化，实际部署中的性价比存疑。

从方法设计看，本文与MobileRL同属在线RL路线，但MobileRL聚焦单任务优化，本文通过TIES-Merge实现多任务统一。MobileRL在AndroidWorld上达到80.2%，高于本文的77.6%，表明专用模型在动态导航上仍具优势。本文的合并策略虽简化了部署，但引入了1.4%的定位精度损失，这是否可接受取决于应用场景对静态定位精度的敏感度。此外，本文借鉴T-GRPO的全轨迹rollout思想，但T-GRPO未涉及多任务合并，本文的创新在于将轨迹级奖励与参数空间插值结合，解决了单模型多任务的能力冲突问题。

## 总结

UI-Venus-1.5旨在解决GUI智能体在长程任务中的步级-轨迹级精度不匹配与多任务部署复杂性矛盾。其切入点在于通过大规模Mid-Training建立基础GUI语义，利用全轨迹在线RL优化长程决策，并通过TIES-Merge实现单模型多任务统一。实验证明该范式在ScreenSpot-Pro（69.6%）和AndroidWorld（77.6%）上取得SOTA或接近SOTA结果。然而，模型合并导致的1.4%定位精度下降以及在线RL的高交互成本，限制了其在资源受限场景下的适用性。当支持集增大到5-shot时，查询侧增强的边际收益是否递减，论文未给出回答。
