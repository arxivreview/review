> 多轮工具调用中，小模型遭遇 API 报错后常陷入无效重试循环，导致任务彻底失败。现有强化学习将错误简化为稀疏负奖励，缺乏恢复指导，而静态合成数据集又因策略演化导致分布过时。FISSION-GRPO 通过在线拦截失败轨迹，利用微调的错误模拟器生成诊断反馈，并触发“裂变”重采样以构建密集纠正信号。该方法显著提升了小模型在复杂多轮任务中的错误恢复率，但其对模拟反馈质量的依赖及跨域泛化边界仍需进一步审视。

## 研究背景

当智能体在动态环境中执行多步工具调用时，API 返回的状态冲突或参数错误是不可避免的干扰。这种干扰要求模型具备错误恢复能力，即在观察到执行失败后，能解析反馈信息并生成正确的替代动作。然而，小语言模型（SLM）往往缺乏这种鲁棒性，它们倾向于重复无效的调用，形成幻觉重试循环，直至对话崩溃。

工具增强大语言模型的研究重心已从单轮语法正确性转向多轮工作流的可靠性。主流路线分为两类：一是基于静态合成数据集的监督微调，如 ToolACE，其通过离线构建错误-纠正对来扩展训练覆盖，但策略随训练改进而演化，导致预收集的错误分布迅速过时；二是基于可验证奖励的强化学习（RLVR），如 GRPO，其通过环境交互优化策略，但将错误视为稀疏负奖励，仅抑制失败动作而未提供纠正路径，且在组内奖励方差坍缩时导致梯度消失。FISSION-GRPO 的切入点在于将错误从“需避免的结果”转化为“可学习的经验”，通过在线策略生成与策略当前错误分布对齐的纠正监督，弥补了静态数据与稀疏奖励之间的空白。

## 核心方法

### 方法参照系

本文基于 GRPO 优化骨干，其标准流程为：对每个查询采样一组轨迹，计算组内归一化优势，更新策略。关键差异在于，标准 GRPO 仅利用原始查询分布下的采样结果，而 FISSION-GRPO 在标准探索后插入错误拦截与纠正重采样环节，形成闭环。

### 错误识别与混合反馈合成

标准 RL 中，错误仅体现为低奖励标量，无法指导具体修正。FISSION-GRPO 在 Stage 2 引入两级过滤：格式错误直接触发确定性解析器反馈；语义错误（$R_{corr} < \delta_{corr}$）则查询微调的 Error Simulator $S_\phi$。模拟器基于 Qwen3-32B 通过 SFT 训练，输入包含系统提示、对话历史、失败调用 $\tau_{err}$ 及真实调用 $\tau_{gt}$，输出非泄露的诊断字符串 $f$。该设计解决了标量惩罚无法定位具体故障点的问题，使模型能获取类似运行时错误日志的细粒度信号。

### 裂变重采样与纠正更新

Stage 3 将单个错误案例扩展为密集训练信号。对于纠正上下文 $x_{corr} = [x; \tau_{err}; f]$，采样 $G'$ 条恢复轨迹 $\{\tau'_j\}$，计算组内归一化优势：

$$ \hat{A}(\tau'_j) = \frac{R(\tau'_j) - \mu'_{R}}{\sigma'_{R} + \epsilon} $$

其中 $\mu'_{R}$ 和 $\sigma'_{R}$ 为纠正组内的奖励均值与标准差。随后使用与标准 GRPO 相同的截断代理目标优化策略。这一机制通过条件于显式反馈 $f$ 增加组内结果多样性，避免了标准探索中因同质性失败导致的优势估计失效，使模型在反馈增强上下文中显式学习恢复路径。

## 实验评估

实验在 BFCL v4 Multi-Turn、TAU-Bench 及 TAU2-Bench 上进行，基线涵盖 GRPO、DAPO、Dr.GRPO、AWPO 及 ToolACE 等 SFT/RL 方法。FISSION-GRPO 在 Qwen3 系列（1.7B/4B/8B）上均取得显著提升。

| 模型 | 方法 | BFCL v4 Multi-Turn Overall (%) | TAU-Bench Retail (%) | TAU2-Bench Telecom (%) |
| :--- | :--- | :--- | :--- | :--- |
| Qwen3-8B | GRPO | 42.75 | 35.7 | 26.0 |
| Qwen3-8B | FISSION-GRPO | 46.75 | 51.3 | 55.0 |
| Qwen3-4B | FISSION-GRPO | 40.87 | 37.4 | 42.5 |
| Qwen3-1.7B | FISSION-GRPO | 20.38 | 7.8 | 37.5 |

Qwen3-8B 在 BFCL 上较 GRPO 提升 4.0%，在 TAU-Bench Retail 上提升 15.6%。消融实验显示，错误恢复率平均提升 5.7%，其中长上下文场景提升 11.8%，而一次性成功率仅微增 1.75%，表明增益主要源于恢复能力而非基础调用能力的提升。

评估边界方面，实验仅覆盖 Qwen3 系列，未验证 Llama 等其他骨干的泛化性；Error Simulator 依赖真实调用 $\tau_{gt}$ 作为输入，在实际部署中若无法获取 ground truth，模拟器性能可能下降。代码已开源，训练使用 8×H800 GPU，超参数（如 $G=8$, $\delta_{corr}=1$）已公开，可复现性较好。

## 关联研究分析

从问题动机看，FISSION-GRPO 与 ToolACE 均关注错误恢复，但 ToolACE 依赖离线合成数据，存在策略-数据分布错位；FISSION-GRPO 通过在线裂变保持监督与当前策略错误分布对齐，解决了静态数据过时问题。然而，FISSION-GRPO 的 Error Simulator 需要 $\tau_{gt}$ 作为输入，这在真实无标注环境中不可得，而 ToolACE 的离线合成虽无此限制，但牺牲了时效性。

从方法设计看，FISSION-GRPO 与 IACM-RL 同属 RLVR 路线，但 IACM-RL 通过意图感知上下文管理优化多轮状态跟踪，而 FISSION-GRPO 聚焦于错误后的即时恢复。IACM-RL 在 BFCL Multi-Turn 上达到 64.0%（据领域综述），高于 FISSION-GRPO 的 46.75%，表明状态管理对整体性能的影响可能大于局部错误恢复。FISSION-GRPO 未对比 IACM-RL，也未探索将裂变机制与状态管理框架结合的可能性，其性能上限是否受限于缺乏全局状态追踪，论文未给出回答。

## 总结

FISSION-GRPO 针对小模型在多轮工具调用中错误恢复能力缺失的核心矛盾，通过在线拦截失败轨迹并触发裂变重采样，将稀疏负奖励转化为密集纠正信号。该方法在 Qwen3-8B 上将 BFCL v4 Multi-Turn 准确率从 42.75% 提升至 46.75%，错误恢复率提升 5.7%。其边界在于 Error Simulator 依赖真实调用作为输入，且实验仅覆盖 Qwen3 系列，未验证跨骨干泛化性。当 Error Simulator 在无 ground truth 的真实部署环境中性能衰减时，裂变机制的增益是否仍能维持，论文未给出回答。
