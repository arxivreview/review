> 多模态大模型在视觉密集任务中常因强制使用文本思维链而丢失空间细节，导致推理脆弱。现有潜在视觉推理方法虽引入连续隐状态，但采用固定推理模板与固定长度Token，无法适应异构查询需求。SwimBird通过混合自回归架构与动态Token预算，实现文本、视觉及交错模式的自适应切换。该设计在细粒度感知基准上取得领先，但其仅依赖监督微调（SFT）而非强化学习（RL）的训练范式，与领域主流共识存在显著张力，其长期推理稳定性尚待验证。

## 研究背景

多模态大模型（MLLMs）处理迷宫求解或细粒度视觉搜索时，瓶颈在于密集感知而非逻辑结构。纯文本思维链（Chain-of-Thought, CoT）迫使模型用语言描述中间视觉状态，当语言无法忠实承载空间信息时，产生模态失配（Modality Mismatch）与误差累积。为缓解此问题，潜在视觉推理方法引入连续隐状态作为“视觉思维”，但现有工作通常采用固定的推理范式（纯文本、纯视觉或固定交错），且视觉Token长度恒定。这种刚性设计导致文本中心查询被冗余视觉步骤干扰，或视觉密集查询因Token不足而丢失细节。

主流路线将多模态推理视为静态模板问题，假设单一推理模式可泛化至所有查询。然而，不同问题对内部计算格式的需求各异：部分仅需离散符号步骤，部分需潜在视觉转换，部分需视觉接地与文本推演紧密交替。SwimBird的切入点在于打破静态模板假设，提出推理模式应基于输入与演化状态动态选择。该工作将问题从“如何生成视觉思维”转化为“何时、以何种长度生成视觉思维”，通过混合自回归机制统一离散与连续生成接口，并设计数据筛选策略以支持多模式训练。

## 核心方法

### 混合自回归建模

潜在视觉推理的标准流程通常将视觉Token视为固定长度的附加序列，与文本Token分离处理。SwimBird的关键差异在于统一生成接口：文本段执行标准下一Token预测，视觉段执行下一嵌入预测。这种设计解决了固定模板无法在单一序列中灵活切换模态的问题，使模型能根据查询动态决定推理路径。

### 动态潜在Token预算与模式切换

固定长度视觉Token在高分辨率图像上容量不足，在低分辨率图像上浪费计算。SwimBird引入分辨率感知的动态Token预算，视觉编码器输出Token数受独立范围 $[N_{min}, N_{max}]$ 约束，避免激进池化丢弃细粒度证据。在推理时，模型通过生成特殊分隔符 `<|latent_start|>` 和 `<|latent_end|>` 自主决定进入视觉思维阶段及持续时长。统一训练目标为：

$$ L = \lambda_{text} L_{text} + \lambda_{vis} L_{vis} $$

其中 $L_{vis}$ 为视觉嵌入的均方误差损失，目标嵌入由同一视觉编码器编码中间思考图像得到。该公式确保视觉思维锚定在语义有意义的视觉状态上，而非随机噪声。动态预算使模型在视觉密集查询中分配更多潜在计算，在文本中心查询中避免冗余视觉步骤，从而在单一模型内平衡感知精度与逻辑效率。

## 实验评估

实验基于Qwen3-VL 8B骨干，在A100-80G GPU上以全局批大小128进行SFT，冻结视觉编码器与多模态投影器。基线覆盖文本推理（GPT-4o, Qwen2.5/3-VL）、潜在推理（Monet, LVR, SkiLa）及智能体模型（DeepEyes, Thyme）。在细粒度视觉理解基准上，SwimBird在V* Bench、HR-Bench 4K、HR-Bench 8K分别取得85.5、79.0、74.9，超越Qwen3-VL-8B-Instruct（83.8/76.5/71.3）及智能体模型Thyme（82.2/77.0/72.0）。在通用VQA与多模态推理上，SwimBird在MMStar、RealWorldQA、WeMath、DynaMath、MathVerse_MINI分别取得71.2、73.1、49.5、67.2、65.8，均优于Qwen3-VL-8B-Instruct（64.7/71.8/38.8/65.3/61.3）。

| 基准 | SwimBird | Qwen3-VL-8B-Instruct | Thyme | DeepEyesV2 |
| :--- | :--- | :--- | :--- | :--- |
| V* Bench | 85.5 | 83.8 | 82.2 | 81.8 |
| HR-Bench 4K | 79.0 | 76.5 | 77.0 | 77.9 |
| HR-Bench 8K | 74.9 | 71.3 | 72.0 | 73.8 |
| MMStar | 71.2 | 64.7 | - | - |
| WeMath | 49.5 | 38.8 | - | 38.1 |
| DynaMath | 67.2 | 65.3 | - | 57.2 |

消融实验显示，最大潜在Token预算从16增至128时，HR-Bench 4K从76.4提升至79.0，HR-Bench 8K从71.4提升至74.9，RealWorldQA从73.1提升至73.1，表明高分辨率任务对Token容量更敏感。MSE损失权重从0.1增至1.0时，HR-Bench 4K从79.0微升至79.4，HR-Bench 8K从71.8降至73.8，RealWorldQA从72.8降至71.9，显示视觉重建损失权重过高可能轻微损害文本推理性能。

评估协议缺乏对推理过程正确性的独立量化，仅依赖最终答案准确率。代码与数据集已开源，但训练细节中未报告学习率调度具体参数及收敛曲线。与领域共识相比，SwimBird仅使用SFT，未涉及强化学习（RL）或过程奖励模型（PRM），其性能优势是否源于Qwen3-VL骨干的预训练质量而非方法本身，需控制变量验证。

## 关联研究分析

从问题动机看，SwimBird与SkiLa同属潜在视觉推理路线，但SkiLa采用固定长度交错推理，SwimBird引入动态模式切换与Token预算。这一差异源于对“模态失配”根源的不同判断：SkiLa假设交错结构本身足够通用，SwimBird认为刚性结构是性能瓶颈。SkiLa在视觉密集任务上表现稳定，但在文本中心任务上可能因冗余视觉步骤干扰逻辑推理，SwimBird通过动态切换避免了这一负迁移。

从方法设计看，SwimBird与VPPO形成范式对比。VPPO通过RL过滤Token级梯度以强化视觉接地，SwimBird通过SFT筛选数据以支持多模式训练。VPPO依赖最终答案奖励的稀疏信号，SwimBird依赖中间思考图像的密集监督。这一差异暗示：在视觉密集任务中，SFT可能通过直接监督视觉状态比RL更高效地建立视觉-语言对齐，但在长链推理中，SFT缺乏对错误推理路径的惩罚机制，可能导致模型在复杂逻辑任务中产生幻觉。

## 总结

SwimBird解决的核心矛盾是固定推理模板与异构查询需求之间的不匹配。其切入点在于将推理模式选择从静态设计转化为动态决策，通过混合自回归架构统一离散与连续生成接口，并引入分辨率感知的动态Token预算。该设计在V* Bench上取得85.5，在WeMath上取得49.5，显著超越固定模板基线。然而，其仅依赖SFT的训练范式未验证在长链推理中的稳定性，且性能优势可能部分源于Qwen3-VL骨干的预训练质量。当查询复杂度进一步增加时，动态Token预算的自适应能力是否足以替代RL的过程监督，论文未给出回答。
