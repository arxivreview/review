研究机构：香港中文大学

作者：Zimu Lu、Houxing Ren、Yunqiao Yang 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.03798)

> 现有代码智能体在生成网站时普遍存在“前端有交互、后端无逻辑”的脱节现象，导致生成的应用无法处理真实数据流。FullStack-Agent 通过多智能体分工与仓库反译训练，构建了包含前端、后端及数据库三层验证的全栈生成系统。该系统在 FullStack-Bench 上实现了后端准确率 77.8%，显著优于仅关注 UI 交互的基线方法。其价值在于揭示了代码生成中“功能真实性”与“视觉完整性”的背离，但合成数据训练的泛化边界仍存疑。

## 研究背景

当用户要求构建一个具备数据持久化功能的 Web 应用时，LLM 往往能生成精美的前端界面，却难以同步构建对应的后端 API 与数据库结构。这种“前后端一致性”缺失源于 LLM 在长程代码生成中的上下文漂移：前端代码依赖后端接口定义，而后端逻辑又依赖数据库 schema，任何一环的断裂都会导致功能失效。为解决此问题，需引入全栈感知机制，即智能体不仅要理解 UI 布局，还需掌握 Next.js、NestJS 等框架的数据流向与依赖关系。

当前主流代码智能体如 WebGen-Agent 和 TDDev 主要聚焦于前端代码生成，其评估基准（如 WebGen-Bench）仅通过 GUI 代理观察 UI 反应，无法检测后端逻辑的缺失。这种评估盲区导致模型倾向于使用 Mock 数据模拟交互，掩盖了真实数据处理的缺陷。FullStack-Agent 的切入点在于将评估维度从“视觉反馈”扩展至“数据交互”，通过引入后端调试工具与数据库日志验证，强制模型生成可运行的全栈代码。

## 核心方法

### 多智能体全栈开发框架

全栈代码生成的标准流程通常由单一 LLM 线性执行，但面对复杂代码库时，单一模型难以同时维护前端 UI 状态与后端逻辑一致性。FullStack-Dev 采用分层多智能体架构，将任务解耦为规划、前端编码与后端编码三个独立角色。Planning Agent 负责生成 JSON 格式的全栈设计蓝图，明确实体关系与 API 端点；Backend Coding Agent 优先实现后端逻辑并输出 API 摘要；Frontend Coding Agent 基于该摘要构建前端。这种串行依赖确保了数据流定义的严格一致性，避免了前后端接口不匹配导致的运行时错误。

### 仓库反译与迭代自改进

传统代码智能体训练依赖人工标注轨迹，成本高且难以覆盖长尾场景。FullStack-Learn 提出仓库反译（Repository Back-Translation）机制，将 GitHub 上的真实仓库转化为智能体轨迹。其核心公式为：

$$ D_{aug} = B(A(R_{real}, M_0), M_1) $$

其中 $R_{real}$ 为真实仓库，$A(\cdot)$ 为仓库增强算子，$B(\cdot)$ 为轨迹反译算子，$M_0$ 与 $M_1$ 分别为初始与中间模型。该过程首先由 Information Gathering Agent 提取仓库摘要与用户指令，再由 Trajectory Back-Translation Agent 在空模板中复现代码，最后通过规则程序清洗原始仓库痕迹。迭代自改进策略利用 $M_1$ 生成更多增强数据，使模型在无更强教师模型的情况下实现性能提升。

### 全栈一致性验证基准

现有基准如 WebGen-Bench 仅评估前端 UI 反应，无法区分“真实数据交互”与“假象交互”。FullStack-Bench 引入三层验证机制：前端测试通过 GUI 代理检查 UI 反应，同时提取数据库日志验证数据流；后端测试通过 API 请求验证功能逻辑；数据库测试通过快照比对验证数据完整性。其前端准确率计算公式为：

$$ Acc_{FE} = \frac{N_{Yes} + 0.5 N_{Partial}}{N_{Total}} \times 100\% $$

其中 $N_{Yes}$ 与 $N_{Partial}$ 仅在数据库日志验证通过时计入。该设计强制模型生成具备真实数据持久化能力的代码，而非仅满足视觉预期的前端页面。

## 实验评估

FullStack-Bench 包含 101 条用户指令，对应 647 个前端、604 个后端及 389 个数据库测试用例。基线涵盖 WebGen-Agent、TDDev 等专用代码智能体及 OpenHands 等通用智能体。实验结果显示，FullStack-Dev 在使用 Qwen3-Coder-480B-A35B-Instruct 时，前端、后端及数据库准确率分别为 64.7%、77.8% 和 77.9%，较 SOTA 方法 WebGen-Agent 分别提升 8.7%、38.2% 和 15.9%。后端准确率显著高于前端，表明该框架有效解决了基线方法中“前端有、后端无”的结构性缺陷。

| 框架 | 模型 | FE Acc. w/ Valid DB | BE Acc. w/ Valid DB | DB Acc. | Appearance |
| :--- | :--- | :--- | :--- | :--- | :--- |
| WebGen-Agent | Qwen3-Coder-480B | 56.0 | 39.6 | 62.0 | 3.63 |
| TDDev | Qwen3-Coder-480B | 21.8 | 10.8 | 28.5 | 1.96 |
| OpenHands | Qwen3-Coder-480B | 40.4 | 12.7 | 13.6 | 1.96 |
| **FullStack-Dev** | **Qwen3-Coder-480B** | **64.7** | **77.8** | **77.9** | **3.72** |

消融实验表明，移除后端调试工具导致后端准确率从 77.8% 降至 71.7%，移除前端调试工具则使前端准确率从 64.7% 降至 51.9%。多智能体机制的移除导致所有指标下降，其中后端准确率降幅最大（77.8% 至 61.4%），验证了分层规划对复杂数据流管理的关键作用。FullStack-Learn 训练后的 30B 模型在两轮迭代后，前端、后端及数据库准确率分别提升 9.7%、9.5% 和 2.8%，证明仓库反译数据的有效性。

| 测试名称 | FE Acc. w/ Valid DB | BE Acc. w/ Valid DB | DB Acc. | Appearance |
| :--- | :--- | :--- | :--- | :--- |
| Qwen3-Coder-30B (Base) | 37.2 | 38.7 | 50.9 | 2.97 |

| **FullStack-Learn-Round2** | **46.9** | **48.2** | **53.7** | **3.40** |

评估可靠性方面，人工标注显示前端、后端及数据库测试的人机对齐准确率均超过 90%，验证了自动化评估的有效性。然而，FullStack-Bench 仅包含 101 条指令，可能无法覆盖全栈开发的长尾场景，如复杂权限管理或实时通信。代码已开源，但训练依赖 32 块 H800 GPU，复现成本较高。

## 关联研究分析

从问题动机看，FullStack-Agent 与 WebGen-Agent 的核心差异在于评估维度的扩展。WebGen-Agent 聚焦于前端 UI 的视觉保真度，其 GUI 代理仅观察页面反应，无法检测后端逻辑缺失。FullStack-Agent 引入数据库日志验证，将评估从“视觉正确性”转向“功能真实性”，这源于全栈开发中前后端数据流耦合的特性。然而，这种验证机制依赖数据库日志的完整性，若后端采用内存存储或无日志框架，该验证可能失效。

从方法设计看，FullStack-Learn 的仓库反译与 SynthAgent 的合成监督路线存在本质区别。SynthAgent 通过合成任务指令生成执行轨迹，适用于 Web 智能体交互任务；FullStack-Learn 则通过反译真实代码仓库生成开发轨迹，适用于代码生成任务。这种差异源于任务特性：代码生成需要精确的语法与结构约束，而交互任务更关注状态转移。FullStack-Learn 依赖真实仓库的结构完整性，若仓库代码质量低下或结构混乱，反译轨迹的逻辑连贯性可能受损，论文未对此类噪声数据的鲁棒性进行充分验证。

## 总结

FullStack-Agent 针对代码智能体生成网站时“前端有交互、后端无逻辑”的核心矛盾，通过多智能体分工与仓库反译训练，构建了包含前端、后端及数据库三层验证的全栈生成系统。该系统在 FullStack-Bench 上实现了后端准确率 77.8%，较 SOTA 方法提升 38.2%，证明了全栈一致性验证的有效性。然而，其训练数据依赖 GitHub 真实仓库的反译，若仓库代码质量低下或结构混乱，反译轨迹的逻辑连贯性可能受损。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
