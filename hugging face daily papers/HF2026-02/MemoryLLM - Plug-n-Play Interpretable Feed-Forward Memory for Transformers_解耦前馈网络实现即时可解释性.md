# HuggingFace最新推荐论文 ｜MemoryLLM: Plug-n-Play Interpretable Feed-Forward Memory for Transformers ｜解耦前馈网络实现即时可解释性

作者：Ajay Jaiswal、Lauren Hannah、Han-Byul Kim 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.00398)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.00398)

> 机制可解释性领域长期受困于前馈网络（FFN）输入的非解释性，导致其作为知识存储单元的功能难以被直接审计。现有逆向工程方法依赖事后激活修补与人工标注，无法在架构层面确立FFN的确定性查询空间。本文提出MemoryLLM，通过架构解耦使FFN直接读取嵌入层输出，将其转化为基于词表的离散检索记忆。该设计在保持模型性能的同时实现了FFN功能的即时可解释性，但其对推理类任务的贡献局限及预训练模型迁移可行性尚存疑。

## 研究背景

Transformer内部计算机制的逆向工程通常假设残差流是组件间通信的唯一通道，前馈网络（FFN）作为该通道上的处理单元，其输入是注意力输出与残差流的加性混合。这种混合导致FFN的输入空间随上下文动态变化，无法建立从输入到内部记忆位置的确定性映射。为突破这一瓶颈，研究者引入稀疏自编码器（SAE）与激活修补，试图从黑盒中提取单义特征并验证因果必要性，但此类方法依赖大量前向传播与人工标注，且无法消除FFN输入本身的多义性。

机制可解释性的核心矛盾在于计算效率与因果严谨性的平衡，而FFN占据模型约三分之二的参数，其功能解释的缺失构成了该矛盾的主要来源。Geva等人（2021, 2022）在GPT-2上验证了FFN作为神经键值记忆的假设，但该方法需通过校准数据集反向挖掘输入前缀，且查询空间仍为非解释性的潜在向量。本文切入点在于从源头消除FFN与注意力的纠缠，通过架构设计强制FFN仅接收静态的Token嵌入，从而将FFN解释从“事后逆向工程”转变为“架构内建属性”。

## 核心方法

### 架构解耦参照系

传统Transformer中FFN读取残差流快照，其输入 $X_L$ 包含前序层所有注意力与FFN的累积信息。本文问题与该通用流程的关键差异在于：FFN不再作为残差流上的串行处理单元，而是作为并行于注意力的独立模块，其输入被固定为嵌入层输出 $X_0$，切断了FFN对上下文的依赖。

### 上下文无关FFN计算

在标准Transformer层中，FFN输出是注意力输出与残差流的加性混合，导致FFN功能与上下文强耦合。本文在MemoryLLM中，FFN模块 $L$ 直接以Token嵌入 $X_0 \in \mathbb{R}^{[M][\times][d]}$ 为输入，计算过程为：

$$ \text{FFN}_L(X_0) = W_{Down}^L \cdot \text{SwiGLU}(W_{Up}^L X_0, W_{Gate}^L X_0) $$

该公式表明FFN输出仅由静态Token嵌入决定，与当前层及前序层的注意力状态无关。这一设计解决了此前方法中FFN输入随上下文漂移导致的记忆位置不可定位问题，使得每个Token ID对应确定的FFN内部状态，实现了查询空间的离散化与可解释性。

### TKV记忆检索框架

基于解耦架构，本文提出Token-Key-Value（TKV）框架，将FFN的 $W_{Up}$ 与 $W_{Down}$ 矩阵解释为神经检索记忆的键与值。对于查询向量 $q$，记忆检索分为两步：首先计算键系数 $c_k$，其次加权聚合值向量。键系数计算公式为：

$$ c_k = \text{SwiGLU}(q \cdot W_{Up}^T, q \cdot W_{Gate}^T) $$

该公式中 $W_{Gate}$ 作为学习到的重加权函数，决定每个记忆单元被放大或抑制的程度。检索输出 $o$ 为 $c_k$ 加权的值向量线性组合。TKV框架消除了人工挖掘输入前缀的需求，通过词表Token ID直接索引记忆位置，使得FFN的知识存储结构可被直接查询与审计。

## 实验评估

实验在C4数据集上评估困惑度（PPL），并在Lambada、ARC等基准上测试下游任务性能。基线覆盖标准Transformer（Base）与剪枝方法（Wanda、SparseGPT、Magnitude），但缺失电路发现类基线（如ACDC）。

| 模型变体 | 活跃参数 (M) | C4 PPL (150B tokens) |
| :--- | :--- | :--- |
| Base-1B | 1208M | 15.0 |
| Flex-MemoryLLM-3h2 | 704M | 15.5 |
| MemoryLLM-0h2 | 402M | 17.0 |
| Wanda (1B) | 704M | 18.0 |

Flex-MemoryLLM-3h2在704M活跃参数下PPL接近1208M参数的Base模型，且显著优于同参数量剪枝方法，表明架构解耦未牺牲模型性能。

| 任务 | Base (1208M) | Flex-MemoryLLM-2h2 (604M) | MemoryLLM-0h2 (402M) |
| :--- | :--- | :--- | :--- |
| lambada_openai | 81.30 | 81.00 | 80.70 |
| arc_challenge | 55.38 | 53.96 | 52.78 |
| hellaswag | 44.52 | 44.19 | 41.28 |

在检索类任务（Lambada）上，MemoryLLM性能接近Base，但在推理类任务（ARC、HellaSwag）上存在明显差距，验证了FFN主要承担检索功能而非逻辑推理的假设。

评估边界方面，论文未报告置信区间，且仅在从头训练的250M-1B规模模型上验证，未测试预训练大模型的迁移可行性。代码未公开，超参数细节有限，可复现性依赖作者提供的训练配方。

## 关联研究分析

从问题动机看，本文与稀疏自编码器（SAE）路线形成对立。SAE试图从黑盒激活中提取单义特征，依赖训练后的特征分解，而MemoryLLM通过架构设计使特征（Token记忆）天然存在，无需事后提取。这一差异源于任务特性：SAE适用于已训练模型的分析，而MemoryLLM适用于新模型设计。然而，SAE在预训练模型上的适用性是否优于架构解耦，论文未给出回答。

从方法设计看，本文与双流架构（如Kerce and Fox, 2026）同属“设计即可解释”路线，但MemoryLLM是双流架构的极端特例，完全分离了上下文流与记忆流。双流架构通常保留部分FFN对残差流的依赖以平衡性能，而MemoryLLM通过Flex-MemoryLLM引入中间态，将FFN参数分配给上下文感知与上下文无关模块。这种设计解决了完全解耦导致的性能损失，但Flex-MemoryLLM中上下文感知FFN的可解释性是否仍受多义性影响，论文未深入探讨。

## 总结

本文要解决的核心矛盾是FFN输入的非解释性导致其知识存储功能无法被直接审计。现有逆向工程方法依赖事后干预，无法在架构层面确立确定性查询空间，而本文通过架构解耦使FFN直接读取嵌入层输出，将FFN转化为基于词表的离散检索记忆。实验证明Flex-MemoryLLM-3h2在704M活跃参数下PPL接近1208M参数的Base模型，且在检索任务上性能接近Base。本文的边界在于FFN对推理类任务的贡献有限，且仅在从头训练的小规模模型上验证。当支持集增大到预训练大模型规模时，架构解耦是否仍能保持FFN记忆的稀疏性与可解释性，论文未给出回答。
