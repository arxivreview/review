# HuggingFace最新推荐论文 ｜Evolving from Tool User to Creator via Training-Free Experience Reuse in Multimodal Reasoning ｜无训练经验复用实现智能体自进化

作者：Xintian Shen、Jiawei Chen、Lihao Zheng 等 6 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.01983)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.01983)

> 工具增强大语言模型（Tool-Augmented LLMs）在开放环境中常面临固定工具集无法覆盖长尾任务、且一次性生成的代码缺乏持久化机制的困境。现有工具创建方法虽能动态生成代码，但工具仅服务于当前实例，无法沉淀为可复用的经验资产，导致智能体在重复任务中重复消耗计算资源。本文提出 UCT 框架，通过在线任务循环、在线构建循环与离线记忆整合三模块协同，将推理过程中的有效策略封装为持久化工具库，实现无训练条件下的智能体能力自进化。该范式在自建基准上验证了跨域泛化潜力，但其对大模型基座的依赖及缺乏标准基准对比，限制了结论的普适性。

## 研究背景

当智能体面对超出预训练知识边界的复杂计算或实时查询时，必须依赖外部工具突破静态参数化局限。工具集成推理（TIR）范式允许模型在推理中自主调用工具，但传统 TIR 依赖人工定义的工具集，难以覆盖所有子任务；而动态生成代码的方法虽解决了覆盖问题，却因缺乏持久化机制，使每次生成的工具成为“一次性消耗品”，无法在后续任务中复用。这种“用完即弃”的模式导致智能体无法从历史推理中积累能力，每次面对相似子问题时仍需重新生成并验证代码，造成计算冗余与错误累积。

主流工具增强路线在 2025 年后转向基于可验证奖励的强化学习（RLVR），通过环境反馈优化策略以提升分布外泛化能力。然而，RLVR 依赖高质量奖励信号与大量交互数据，训练成本高且存在工具滥用副作用。与此同时，工具创建研究（如 CREATOR、CRAFT）虽实现了推理时动态生成，但工具生命周期局限于单轮交互，未建立经验沉淀机制。本文切入点在于：将推理轨迹中的有效策略转化为持久化工具资产，通过无训练框架实现智能体的持续进化，规避 RL 训练的计算开销与数据依赖。

## 核心方法

### 方法参照系

本文问题属于工具编排与规划范畴，但核心差异在于工具来源的动态生成与复用。标准 TIR 流程中，工具集静态固定，模型仅负责选择与调用；本文引入“工具创建”作为动作空间的一部分，使智能体在推理中按需生成新工具，并通过记忆整合机制将临时工具转化为长期资产。

### 在线构建循环与双重验证

在线构建循环（Online Build Loop）在任务循环触发“创建工具”请求时启动，其设计动机是解决一次性生成代码缺乏质量保障的问题。该模块通过迭代式代码生成与双重验证机制，确保新工具在注册前通过运行时测试与代码评审。工具代码 $C^{[k]}$ 在第 $k$ 轮迭代中由生成模型产出，随后在沙箱环境中执行测试，并将执行结果 $R_{sandbox}$ 与代码提交至评审模型获取反馈 $R_{critic}$。迭代过程形式化为：

$$C^{[k]} = \Psi_{build}(C^{[k-1]}, R_{critic}, R_{sandbox})$$

该公式表明，新工具代码是前一轮代码、评审反馈与沙箱执行结果的函数，通过多轮迭代逐步修正边界条件与逻辑错误，直至满足注册标准。这一机制将工具创建从“单次生成”转变为“迭代优化”，显著提升了生成工具的可靠性。

### 离线记忆整合与工具库进化

离线记忆整合（Offline Memory Consolidation）模块解决工具库无序膨胀导致的检索效率下降问题。其设计动机是避免在线构建循环中执行去重与冲突解决带来的推理延迟。该模块异步执行，基于使用日志 $L$ 对工具库 $M_t$ 进行优化，状态更新方程为：

$$M_{t+1} = \Phi_{offline}(M_t, T_{gen}, L)$$

其中 $T_{gen}$ 为在线阶段生成的原始工具集，$\Phi_{offline}$ 执行组织（合并相似工具、消除冗余）与分析剪枝（废弃低使用率或高失败率工具）操作。该机制将工具库进化与在线推理解耦，确保 $M_{t+1}$ 仅保留高效用经验，降低后续任务的检索复杂度，同时不影响在线推理速度。

## 实验评估

实验在自建 TRBench（959 例）上进行，涵盖数学、科学与通用 VQA 三大领域。基线包括 Basic-CoT、Vanilla Tool、CREATOR 与 CRAFT，但缺失 RLVR 类强基线（如 Tool-R1），导致无法直接对比训练范式与无训练范式的性能差异。主实验结果显示，Qwen3-VL-235B-thinking + UCT 在数学平均准确率上达到 83.21%，较基线 60.17% 提升 23.04%；在科学领域平均准确率为 87.08%，较基线 78.75% 提升 8.33%。

| 方法 | 数学 Avg. | 科学 Avg. | 通用 Avg. | 总体 Avg. |
| :--- | :--- | :--- | :--- | :--- |
| Basic-CoT | 56.96 | 78.75 | 48.16 | 60.17 |
| CREATOR | 49.22 | 52.65 | 48.16 | 50.01 |
| CRAFT | 67.47 | 48.16 | 48.98 | 54.87 |
| Qwen3-VL + UCT | 83.21 | 87.08 | 65.71 | 78.67 |

消融实验表明，记忆整合模块（MC）对性能提升贡献显著：移除 MC 后，数学平均准确率从 83.21% 降至 77.27%，下降 5.94%；移除构建循环（BL）后，准确率降至 69.13%，下降 14.08%。这表明构建循环是性能提升的主要来源，而记忆整合通过优化工具库质量进一步巩固了收益。工具复用率数据显示，Reuse@1 达到 93.1%，表明大多数任务可直接复用已有工具，验证了经验沉淀机制的有效性。

评估边界方面，TRBench 为自建基准，与 BFCL、GAIA 等标准基准无重叠，限制了跨基准泛化验证。评估指标仅包含最终答案正确性，未报告工具调用延迟、失败恢复率等过程指标。可复现性方面，论文未提供代码 URL，且实验依赖 Qwen3-VL-235B-Thinking 大模型，未验证小模型适配性。

## 关联研究分析

从问题动机看，UCT 与 CREATOR、CRAFT 同属工具创建路线，但核心差异在于工具生命周期管理。CREATOR 与 CRAFT 生成的工具仅服务于当前实例，缺乏持久化机制，导致智能体无法从历史推理中积累能力；UCT 通过离线记忆整合将工具转化为长期资产，使智能体在重复任务中直接复用已有工具，降低计算冗余。这一差异源于任务特性：CREATOR 面向单次任务优化，而 UCT 面向长期智能体进化，后者更契合开放环境中的持续学习需求。

从方法设计看，UCT 与 Tool-R1 等 RLVR 路线形成范式对比。Tool-R1 通过强化学习优化模型参数，依赖高质量奖励信号与大量交互数据，训练成本高且存在工具滥用副作用；UCT 采用无训练框架，通过工具库自进化实现能力提升，规避了 RL 训练的计算开销与数据依赖。然而，UCT 依赖大模型基座的推理能力，未验证小模型适配性，而 RLVR 路线可通过蒸馏迁移至小模型。查询侧增强在数据充足时是否仍有增益，论文未给出回答。

## 总结

UCT 旨在解决工具增强智能体在开放环境中固定工具集覆盖不足与一次性生成代码缺乏持久化的矛盾。其切入点在于将推理经验转化为持久化工具资产，通过无训练框架实现智能体自进化，规避 RL 训练的计算开销。实验在自建 TRBench 上验证了跨域泛化潜力，数学平均准确率提升 23.04%，科学领域提升 8.33%。然而，其边界在于依赖大模型基座、缺乏标准基准对比及过程指标缺失。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
