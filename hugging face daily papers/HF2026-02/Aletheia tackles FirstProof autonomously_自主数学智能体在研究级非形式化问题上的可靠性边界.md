# HuggingFace最新推荐论文 ｜Aletheia tackles FirstProof autonomously ｜自主数学智能体在研究级非形式化问题上的可靠性边界

研究机构：谷歌DeepMind、美国布朗大学

论文原文见 [arXiv](https://arxiv.org/abs/2602.21201)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.21201)

> 大语言模型在静态基准上的高分掩盖了其推理脆弱性，现有形式化证明助手依赖机器可验证反馈，但无法覆盖开放研究级数学问题。本文切入点在于构建无人类干预的自主智能体，通过内部生成-验证闭环求解非形式化难题。具体做法是部署基于 Gemini 3 Deep Think 的 Aletheia 智能体，对 FirstProof 挑战进行 Best-of-2 采样与独立专家评估。该工作验证了纯神经推理在研究级问题上的部分可行性，但其可靠性受限于 LLM 验证器的主观性与缺乏形式化约束。

## 研究背景

当 LLM 面对研究级数学问题时，其输出往往包含看似合理但逻辑断裂的中间步骤，这一现象源于概率生成特性导致的幻觉。为抑制幻觉，主流方案引入形式化证明助手（如 Lean）提供机器可验证反馈，但该路线受限于形式化数据稀缺与语义鸿沟，难以直接应用于自然语言表述的开放数学问题。另一路线采用过程奖励模型（Process Reward Model, PRM）进行步骤级监督，但 PRM 标注成本极高且存在偏差，且通常依赖外部符号系统或静态基准，无法适配动态生成的研究级难题。

该领域核心矛盾在于：如何在无形式化验证器约束下，评估 AI 在开放研究级数学问题上的自主证明可靠性。主流形式化路线（如 DeepSeek-Prover）依赖 Lean 验证，但 FirstProof 等挑战明确要求“符合数学文献严谨性”的自然语言证明，且禁止人类介入数学内容。现有静态基准（如 GSM8K）已饱和且存在数据污染，无法反映真实推理能力。本文切入点在于利用多智能体协作架构，通过内部生成-验证闭环替代外部符号验证，并在严格自主约束下测试模型在研究级问题上的极限。

## 核心方法

### 方法参照系

本文问题属于“过程监督”与“多智能体协作”混合路线，但关键差异在于验证器为 LLM 而非符号系统，且无外部检索增强。标准流程中，生成器产生候选证明，验证器进行步骤级检查；本文将其改造为完全自主的闭环，验证器仅输出 LaTeX 代码，不引入人类数学观点。

### 生成-验证闭环与自主性约束

Aletheia 智能体采用 Generator-Verifier 架构，Generator 基于 Gemini 3 Deep Think 生成候选证明，Verifier 子代理执行独立验证。设计动机在于解决纯生成模型在长程推理中累积错误的问题，通过内部过程监督降低单点故障风险。验证器使用预定义的提取提示，要求输出符合“数学文献严谨性”的 LaTeX 代码，并判定 [CORRECT]、[WRONG] 或 [FIXABLE]。若判定为 [FIXABLE]，验证器自主生成修正版本，确保最终输出无需人工干预。该闭环的自主性约束体现在：人类专家仅评估最终输出，不参与生成或澄清过程，从而严格隔离人类数学输入。

$$
\text{Verdict} = \begin{cases}
\text{[CORRECT]} & \text{if } \forall \text{ steps } s_i, \text{LogicalConsistency}(s_i) = 1 \\
\text{[WRONG]} & \text{if } \exists \text{ step } s_j, \text{LogicalConsistency}(s_j) = 0 \land \text{Salvageable}(s_j) = 0 \\
\text{[FIXABLE]} & \text{if } \exists \text{ step } s_k, \text{LogicalConsistency}(s_k) = 0 \land \text{Salvageable}(s_k) = 1
\end{cases}
$$

该公式形式化了验证器的决策逻辑：若所有步骤逻辑一致则正确；若存在不可修复的逻辑错误则错误；若存在可修复的逻辑缺陷则标记为可修复并触发自主修正。

### Best-of-2 采样与推理成本优化

为平衡准确率与推理成本，本文采用 Best-of-2 策略，即对每个问题运行两个不同基础模型（Aletheia A 与 B）的智能体实例，选取专家评估中表现更优的解。设计动机在于单一模型存在假阳性风险，而 Best-of-2 通过多样性采样提升可靠性。推理成本作为问题难度的代理指标，P7 的推理成本超过 Erdős-1051 一个数量级，表明 Generator 与 Verifier 交互次数显著增加。该策略未引入外部检索，而是依赖模型内部推理扩展，通过增加计算预算换取逻辑一致性。

$$
\mathcal{C}_{\text{total}} = \sum_{i=1}^{2} \left( \mathcal{C}_{\text{gen}}(x_i) + \mathcal{C}_{\text{ver}}(x_i, y_i) \right)
$$

该公式表示总推理成本为两个实例的生成成本与验证成本之和，其中 $x_i$ 为问题输入，$y_i$ 为候选解。Best-of-2 策略通过并行计算两个实例，以双倍推理成本换取更高的解正确率，尤其适用于高难度问题（如 P7）。

## 实验评估

实验在 FirstProof 挑战上进行，包含 10 道研究级数学问题，协议要求完全自主生成符合文献严谨性的证明。基线审计显示，本文未与形式化证明助手（如 Lean）或静态基准（如 GSM8K）直接对比，仅进行内部 A/B 测试（Aletheia A vs B）。由于 FirstProof 为一次性挑战，缺乏标准基线，但可参照领域综述中 AIME 2024 上 OpenAI-o3 的 91.6% 准确率作为形式化问题参照，本文在研究级非形式化问题上解决 6/10 题，表明任务难度显著更高。

| 问题 | Aletheia A | Aletheia B | 专家评估 (Correct/Total) |
|---|---|---|---|
| P2 | Correct | Correct | 4/4 |
| P5 | Correct | Misinterpreted | 4/4 |
| P7 | Critically Flawed | Correct | 3/3 |
| P8 | Inadequate | Correct? | 5/7 |
| P9 | Correct | Correct | 4/4 |
| P10 | Correct | Correct | 2/2 |

核心数字对比显示，Best-of-2 策略在 6 个问题上产生可信解，但 P8 仅 5/7 专家认可，暴露 LLM 验证器在复杂几何证明上的分歧。消融分析表明，Aletheia A 在 P7 上出现关键缺陷（错误应用 Euler 特征乘性），而 Aletheia B 正确，说明基础模型差异对逻辑一致性影响显著。P10 中，Aletheia A 自主发现最优复杂度界 $O(n^2r + nr^2)$，优于 B 的 $O(qr)$，表明推理扩展能提升算法发现能力。

评估边界方面，指标仅依赖专家主观判断，缺乏量化逻辑一致性指标；协议未报告置信区间，且 P8 的分歧源于“细节缺失”而非逻辑错误，反映评估标准模糊。可复现性上，代码公开于 GitHub，但推理成本未标准化，且 Best-of-2 策略依赖特定基础模型版本，难以跨模型复现。

## 关联研究分析

从问题动机看，本文与 DeepSeek-Prover-V1.5-RL 形成鲜明对比：后者依赖 Lean 验证器提供机器可验证反馈，解决形式化证明中的逻辑一致性；本文则针对非形式化研究级问题，采用 LLM 验证器替代符号系统。差异根源在于任务特性：形式化问题有明确语法与语义约束，而研究级问题依赖自然语言严谨性，缺乏机器可验证标准。本文未探索 LLM 验证器在缺乏形式化反馈时的判断偏差量化，其可靠性依赖专家主观评估，这可能掩盖系统性盲区。

从方法设计看，本文与 NeuroProlog 的神经符号融合路线不同：NeuroProlog 集成 Prolog 符号系统实现可验证推理，本文纯神经路线依赖内部推理扩展。差异源于数据特性：NeuroProlog 针对形式逻辑任务，符号系统提供刚性约束；本文针对开放数学问题，符号系统灵活性不足。本文的 Best-of-2 策略与 Hard2Verify 的步骤级验证理念一致，但缺乏标准化基准，其验证器偏差未通过自动化步骤标注量化，导致 P8 等复杂问题评估分歧。

## 总结

本文核心矛盾在于无形式化验证器约束下评估 AI 自主证明可靠性。切入点在于利用多智能体生成-验证闭环替代外部符号验证，通过 Best-of-2 采样提升可靠性。方法上，Aletheia 智能体在严格自主约束下求解 FirstProof，验证器输出 LaTeX 代码并自主修正。实验证明 6/10 问题被解决，P10 发现最优复杂度界，但 P8 仅 5/7 专家认可，暴露 LLM 验证器主观性。边界在于缺乏量化逻辑一致性指标，且评估依赖专家判断。当 LLM 验证器在复杂几何证明中产生分歧时，其判断偏差是否可通过内部推理扩展进一步降低，论文未给出回答。
