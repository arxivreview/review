# HuggingFace最新推荐论文 ｜CoDiQ: Test-Time Scaling for Controllable Difficult Question Generation ｜可控高难问题生成

研究机构：复旦大学

作者：Zhongyuan Peng、Caijun Xu、Changyi Xiao 等 7 人

论文原文见 [arXiv](https://arxiv.org/abs/2602.01660)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.01660)

> 大语言模型（LLM）推理能力的提升受限于高质量训练数据的稀缺，尤其是具备竞赛级难度且逻辑自洽的题目。现有自动合成方法往往陷入“伪难”陷阱，即生成的题目看似复杂但实际不可解或定义模糊，且缺乏对难度的精确控制。CoDiQ 将测试时计算扩展（Test-Time Scaling, TTS）机制迁移至问题生成阶段，通过迭代演化与混合验证实现难度的单调递增与可解性保障。该方法构建了包含 44K 道竞赛级题目的语料库，验证了可控难度数据对下游推理能力的显著提升，但其依赖固定容量验证器的设计存在“验证器悖论”，限制了难度上限的突破。

## 研究背景

当 LLM 在复杂推理任务中表现不佳时，根本原因往往不是模型容量不足，而是训练数据中缺乏真正能激发深层逻辑链条的高难度样本。这种数据稀缺性导致模型在简单问题上过度思考，而在高难问题上推理链断裂。为了解决这一矛盾，研究界转向自动合成高难问题，但面临两个核心障碍：一是生成器能力上限，即模型难以生成超过其自身可靠推理能力的题目；二是可解性与复杂度的权衡，强行增加复杂度常导致逻辑一致性破裂，产生不可解的“伪难”题目。

现有主流路线分为提示驱动型与生成器训练型。提示驱动型方法（如 PromptCoT）依赖多步编排与后验过滤，计算成本高且难以规模化；生成器训练型方法（如 ScaleQuest）虽能降低边际成本，但难度控制粗糙，且有效性仍依赖人工或重型过滤。这些方法均未解决难度定义的标准化与实时控制问题。CoDiQ 的切入点在于将 TTS 从“解题”迁移至“出题”，通过增加推理 Token 预算来系统性提升题目难度，同时引入实时验证机制确保逻辑自洽，从而在规模化合成中实现难度的精细控制。

## 核心方法

### 方法参照系

CoDiQ 属于“自进化与自我训练”路线，但其核心差异在于目标函数：传统方法优化解题准确率，CoDiQ 优化出题难度与可解性的联合分布。标准流程通常采用“生成-过滤”范式，而 CoDiQ 采用“迭代演化-实时验证”范式，将难度控制内嵌于生成过程。

### 难度增强策略与迭代演化

CoDiQ 首先设计六种难度增强策略（如维度约束、数学抽象、状态爆炸等），作为 LLM 的认知脚手架，引导模型注入算法性难度而非表面修饰。在此基础上，CoDiQ Pipeline 执行迭代演化：从种子问题 $Q_0$ 开始，每轮提示模型“使其更困难”，生成 $Q_i$。为防止难度回退或逻辑崩溃，Pipeline 引入单调性约束与终止准则。若 $Q_i$ 的可解性验证失败或难度分数低于前一轮，则立即终止并保留前一轮结果。这一机制解决了传统方法中“后验过滤”导致的计算浪费与难度不可控问题，确保生成的题目序列在难度上严格单调递增。

### 混合验证与难度量化

CoDiQ 采用双通道验证机制：可解性验证与难度估计。可解性验证使用 Qwen3-32B 生成 JSON 格式响应，提取置信度分数，仅保留高置信度可解题。难度估计采用相对范式，结合 LLM 排名与 ValueNetwork (VN) 评分。VN 基于 Qwen3-8B 的隐藏状态，通过轻量级 MLP 预测正确性概率 $y \in \{0, 1\}$，其预测概率作为难度的代理指标（越低越难）。难度分数 $d_i$ 通过线性归一化映射至 $[0, 1]$：

$$
d_i = \frac{j - 1}{G - 1}
$$

其中 $j$ 为问题所属难度组索引，$G$ 为总组数。该公式将离散排名转化为连续分数，用于自适应计算预算分配。CoDiQ-Generator 通过 GRPO 算法进行强化学习，奖励函数平衡可解性置信度与难度增量 $\Delta(D)$，针对模型“能力边界”处的失败案例进行优化，从而突破零样本生成的难度上限。

## 实验评估

实验在 CoDiQ-Bench（200 道数学/代码题）上进行，基线包括 GLM-4.6、GPT-OSS-20B 及 Qwen3 系列。CoDiQ-Gen-8B 在平均难度排名（DR-AVG）上达到 62.4%，显著优于 Qwen3-32B 的 56.4% 和 GLM-4.6 的 68.5%（注：GLM-4.6 在 Direct Prompt 下表现最佳，但在 CoDiQ Prompt 下为 78.3%）。CoDiQ-Corpus 的 DR-AVG 为 87.1%，远高于 AIME 的 51.5% 和 LiveCodeBench 的 42.3%。

| 模型 | 轮数 | Token 数 | DR-LLM | DR-VN | DR(AVG) |
|---|---|---|---|---|---|
| Qwen3-32B (Direct) | 2.3 | 1239.3 | 50.6 | 54.8 | 52.7 |
| Qwen3-32B (CoDiQ) | 2.2 | 4893.6 | 63.0 | 46.5 | 54.8 |
| CoDiQ-Gen-8B | 3.4 | 7499.6 | 58.9 | 58.1 | 58.5 |
| CoDiQ-Corpus | - | - | 91.4 | 82.8 | 87.1 |

消融实验显示，移除可解性验证后，CoDiQ-Gen-8B 的难度上限超过 Qwen3-14B，但可解率随 Token 增加显著下降，验证了 RL 对齐在解耦难度与有效性方面的作用。在 8k-32k Token 预算下，CoDiQ-Gen-8B 始终优于 Qwen3-8B 的直接提示与 CoDiQ 提示版本，表明其具备更高的计算效率。

评估边界方面，CoDiQ-Bench 仅包含 200 道简单种子题，可能低估模型在高难起点下的表现。难度指标依赖 Doubao-Seed-1.8 与 VN，存在评估器偏差风险。代码已开源，但 RL 训练细节（如奖励权重）未在正文中完全披露，复现需参考附录。

## 关联研究分析

从问题动机看，CoDiQ 与 ScaleQuest 同属生成器训练路线，但 ScaleQuest 依赖后验过滤确保有效性，而 CoDiQ 将验证内嵌于迭代过程，实现了难度的实时控制。这一差异源于 CoDiQ 对“难度单调性”的严格约束，使其更适合课程学习场景，但可能限制了生成器在难度空间中的探索多样性。

从方法设计看，CoDiQ 的 ValueNetwork 与 ReProbe 均利用隐藏状态，但 ReProbe 用于步骤级验证，CoDiQ 用于整体难度预测。CoDiQ 的相对难度范式（LLM 排名+VN 评分）与领域共识中的绝对分数不同，这解决了高难题目评分饱和问题，但跨模型比较时稳定性存疑。此外，CoDiQ 的“验证器悖论”指出，固定容量验证器会丢弃超出其能力的高难有效题，这与 SAGE 等自进化框架中引入外部接地以打破镜像循环的思路形成对比，暗示动态扩展验证器能力是未来方向。

## 总结

CoDiQ 解决了高难推理数据合成中“难度控制”与“可解性保障”的矛盾，通过将 TTS 机制引入出题过程，实现了难度的单调递增与实时验证。其核心贡献在于构建了 44K 道竞赛级题目语料库，DR-AVG 达 87.1%，显著高于 AIME 的 51.5%，并验证了该数据对下游推理能力的提升。然而，CoDiQ 的边界在于其依赖固定容量验证器，导致高难有效题被误弃，且评估指标依赖特定 LLM 排名，存在偏差风险。当验证器能力无法随生成器同步扩展时，CoDiQ 的难度上限是否会被“验证器悖论”永久锁定，论文未给出回答。
