# HuggingFace最新推荐论文 ｜ArXiv-to-Model: A Practical Study of Scientific LM Training ｜科学语言模型训练的工程实证

作者：Anuj Gupta

论文原文见 [arXiv](https://arxiv.org/abs/2602.17288)

深度分析原文见 [ArxivReview](https://www.arxivreview.com/papers/arxiv_2602.17288)

> 大语言模型缩放定律旨在量化性能随资源增加的幂律关系，但现有研究多聚焦于理论推导与大规模集群优化，忽视了中小规模模型在受限算力下的工程落地细节。本文切入点在于填补从原始科学语料到可训练模型之间的“黑箱”空白，通过记录 1.36B 参数模型在双 A100 上的 24 次迭代训练过程，揭示了数据预处理对有效数据量的决定性影响。其价值在于提供了可复现的工程基准，但缺乏通用基准对比，难以评估其在通用缩放坐标系中的相对位置。

## 研究背景

当研究者试图从原始 arXiv LaTeX 源构建科学语言模型时，首先面临的是数据异构性挑战。LaTeX 归档包含多文件结构、自定义宏及符号密集内容，导致直接提取的文本噪声极高。这种噪声不仅影响数据质量，更通过 Tokenizer 的符号碎片化效应，破坏了模型对数学结构的稳定表征。因此，数据清洗与 Tokenization 策略不再是简单的预处理步骤，而是决定模型能否收敛的核心架构决策。

缩放定律领域长期关注计算最优（Compute-Optimal）下的参数与数据平衡，Chinchilla 定律确立了 $N \propto C^{0.5}, D \propto C^{0.5}$ 的资源分配范式。然而，主流研究隐含了高质量数据无限供给的假设，且多基于大规模集群环境，忽略了 I/O 瓶颈、存储限制及小模型特有的优化不稳定性。对于算力受限的研究者，如何在小规模硬件上实现稳定训练，以及如何量化预处理决策对有效数据量的影响，仍是未解的工程难题。本文正是在此背景下，通过实证研究填补了这一从理论定律到工程实践的断层。

## 核心方法

### 数据管道与有效数据量建模

标准预训练流程假设输入数据已清洗完毕，直接关注损失函数拟合。本文的关键差异在于将数据管道本身视为变量，量化了从原始归档到可用 Token 的损耗。设计动机在于解决“原始数据量”与“有效训练数据量”之间的非线性映射失效问题，即简单的文件大小无法反映实际可用的语义信息量。

$$
D_{eff} = D_{raw} \times \eta_{filter} \times \eta_{extract} \times \eta_{token}
$$

其中 $D_{raw}$ 为原始归档大小，$\eta_{filter}$ 为元数据过滤保留率，$\eta_{extract}$ 为 LaTeX 提取成功率，$\eta_{token}$ 为 Tokenizer 压缩效率。该公式揭示了有效数据量是多重损耗因子的乘积，而非线性缩放。

### 课程学习与符号稳定性优化

针对科学语料中符号密集导致的早期训练不稳定，本文引入了三阶段课程学习策略。设计动机在于解决通用 Tokenizer 在符号密集文本上的碎片化问题，以及模型在早期阶段对数学结构表征的缺失。

$$
L_{total} = \sum_{t=1}^{T} \lambda_t L_{stage}(t)
$$

其中 $\lambda_t$ 为阶段权重，$L_{stage}(t)$ 为当前阶段的交叉熵损失。第一阶段聚焦摘要与引言以建立语言流畅性，第二阶段引入定理环境以强化符号推理，第三阶段混合正文与公式以确保鲁棒性。这种分阶段暴露策略降低了梯度噪声，使模型在 768 Token 上下文长度下实现了平滑收敛。

## 实验评估

该论文实验数据不可得，未提供实验表格。实验设置基于 20GB（小数据）与 200GB（全数据）两个规模，使用 2×A100 GPU 进行训练。基线审计显示，本文仅进行了内部 Run 对比（如 Run 24 vs Run 23），缺乏与同规模通用 LLM（如 LLaMA-1.3B）或科学专用模型（如 OpenWebMath 基线）的直接对比，无法评估其相对优势。核心数字方面，最终验证损失对应的困惑度（Perplexity）约为 4.2（即 $\exp(1.438)$），表明模型在科学语料上拟合良好，但缺乏跨域泛化证据。

消融分析聚焦于数据规模对收敛稳定性的影响。20GB 数据量下，训练损失出现震荡与平台期，表明小数据导致梯度噪声过大，模型陷入记忆模式而非泛化。200GB 数据量下，损失曲线呈现平滑单调下降，梯度范数在预热后迅速稳定在 1.0 以下。这一对比证实了数据规模对优化稳定性的决定性作用，但论文未量化不同预处理策略（如去重阈值）对最终 PPL 的具体边际收益，仅定性指出 I/O 瓶颈可能比计算更先成为限制因素。

评估边界方面，指标仅依赖科学语料上的困惑度，未包含数学推理正确性、定理有效性等结构化基准，无法直接衡量模型的推理能力。可复现性上，论文提供了代码仓库，但指出大规模 LaTeX 预处理管道对存储与 I/O 的高要求可能限制精确复现。此外，训练序列长度限制在 768 Token，未充分利用 4096 Token 的架构支持，长上下文推理能力未得到验证。

## 关联研究分析

从问题动机看，本文与 Chinchilla 缩放定律（Hoffmann et al., 2022）存在显著差异。Chinchilla 关注计算最优下的参数-数据平衡，假设数据质量均匀且充足；而本文聚焦于数据受限与预处理损耗，揭示了在中小规模下，数据工程对有效数据量的影响可能超过架构缩放。这一差异源于任务特性：科学语料的符号密度与异构性使得通用缩放定律的线性假设失效，必须引入管道损耗因子。

从方法设计看，本文与 Practical Scaling Laws（Bryant and Liu, 2026）有相似之处，均关注数据受限场景下的损失分解。但 Practical Scaling Laws 侧重理论建模过拟合惩罚项，而本文侧重工程实证，通过 24 次迭代实验量化了 I/O 瓶颈与 Tokenizer 稳定性。本文未采用 µP（Maximal Update Parametrization）等自动化超参数迁移框架，而是依赖手动调优，这反映了在算力受限场景下，工程调试成本与理论优化收益之间的权衡。查询侧增强在数据充足时是否仍有增益，论文未给出回答，但其手动调优过程本身即为 µP 旨在解决的痛点提供了反面案例。

## 总结

本文要解决的核心矛盾是科学语料异构性与中小规模模型训练稳定性之间的冲突。现有缩放定律忽视了预处理损耗与 I/O 瓶颈，而本文凭借 24 次迭代实验的实证数据，揭示了有效数据量是多重损耗因子的乘积，而非线性缩放。通过三阶段课程学习与 LLaMA 架构，模型在 52.18B Token 下实现了 4.2 的困惑度，证明了数据工程在受限算力下的关键作用。本文的边界在于缺乏通用基准对比，且未量化预处理策略的具体边际收益，仅定性指出 I/O 瓶颈。当支持集增大到 5-shot 时，查询侧增强的边际收益是否递减，论文未给出回答。
