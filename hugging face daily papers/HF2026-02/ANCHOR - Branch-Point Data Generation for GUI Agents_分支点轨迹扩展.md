> 桌面GUI智能体训练数据稀缺且人工标注成本极高，现有合成方法受限于教程覆盖度或执行器能力，难以生成长程、高信号轨迹。ANCHOR从已验证的种子轨迹出发，在UI状态发生显著变化的“分支点”处生成新任务变体，通过状态锚定与步骤级过滤实现数据多样性与保真度的平衡。该方法在OSWorld和WindowsAgentArena上验证了跨平台泛化能力，但其绝对性能仍低于最新SOTA智能体，且未结合强化学习优化策略，仅依赖监督微调，其长期有效性存疑。

## 研究背景

GUI智能体依赖视觉语言模型（VLM）将自然语言指令映射为像素级动作，其性能上限受制于高质量交互轨迹数据的规模与质量。人工标注轨迹虽保真度高，但无法覆盖应用、配置与任务目标的组合空间，导致模型在分布外场景泛化能力弱。数据合成成为突破瓶颈的关键，但现有范式存在结构性缺陷：教程重放（如AgentTrek）受限于外部教程的多样性，任务驱动合成（如Explorer）则与执行器能力强耦合，失败轨迹截断导致数据偏向简单任务，且难以生成长程工作流。

桌面环境因界面复杂度高、状态空间大，轨迹生成难度高于Web或移动端，现有合成管线多集中于后者，桌面长程轨迹生成尚属空白。ANCHOR针对此空白，提出基于“分支点”的轨迹扩展框架。其核心假设是：已验证的种子轨迹中，UI状态发生显著变化的节点（如新窗口弹出、面板展开）蕴含丰富的交互可能性，从这些节点分支可系统性地生成共享前缀但目标各异的新任务，从而在避免无约束探索噪声的同时，实现任务多样性的指数级扩展。

## 核心方法

### 方法参照系

ANCHOR属于GUI轨迹合成路线，与任务驱动合成（Task-Driven Synthesis）和交互驱动探索（Interaction-Driven Exploration）并列。标准任务驱动流程为：LLM生成任务指令 → 智能体执行 → 记录轨迹。ANCHOR的关键差异在于：不从零生成任务，而是从已验证种子轨迹的特定状态节点（分支点）出发，生成条件于当前GUI上下文的新任务变体，将“任务提议”与“状态探索”解耦。

### 分支点识别与任务生成

分支点定义为轨迹中UI发生实质性状态变化的时间步 $t$，即 $s_t$ 处出现新窗口、面板或可见内容增加。设计动机在于解决任务驱动合成中“任务多样性受限于提议模型知识”的问题：通过锚定已验证前缀，新任务天然继承可靠的状态基础，避免执行器在未知状态中盲目探索。

对于种子轨迹 $\tau = (s_0, a_0, \dots, s_K)$，ANCHOR使用GPT-5.1识别3-5个分支点。在每个分支点 $s_t$，模型接收前缀摘要与当前GUI状态，生成新任务描述 $T'_{t,j}$。任务执行时，智能体从 $s_t$ 重放环境，若动作偏离原指令（如点击错误选项），模型在线修订 $T'_{t,j}$ 为语义相近的可行变体。此机制将“执行失败”转化为“任务重定义”，而非直接丢弃轨迹，提升了数据利用率。

### 步骤级过滤与去噪

分支点扩展后，轨迹仍含步骤级噪声（如误点、冗余等待）。ANCHOR引入两层过滤：(1) 前缀步骤任务条件推理过滤：对共享前缀中的每步 $k \le t$，针对每个继承任务 $T'_{t,j}$，采样 $M=10$ 个候选动作-推理对 $(\tilde{a}^{[m]}_k, \tilde{r}^{[m]}_k)$，仅保留与观测视觉变化 $s_k \to s_{k+1}$ 一致且匹配金标准动作 $a_k$ 的推理，否则丢弃该步骤监督。(2) 分支后意图一致性去噪：对 $k > t$ 的步骤，验证动作 $a_k$ 与前后截图 $s_k, s_{k+1}$ 的一致性，标记噪声步骤并排除。

$$
\mathcal{L} = \mathcal{L}_{\text{plan}} + \mathcal{L}_{\text{act}}
$$

其中 $\mathcal{L}_{\text{plan}}$ 为步骤级推理状态 $r_t$ 的预测损失，$\mathcal{L}_{\text{act}}$ 为工具调用动作 $a_t$ 的预测损失。该损失函数确保模型同时学习“为何执行”与“执行什么”，步骤级过滤通过移除不一致的 $(r_t, a_t)$ 对，防止模型过拟合到噪声操作。

## 实验评估

实验在OSWorld（Ubuntu桌面）和WindowsAgentArena（Windows 11桌面）上进行，评估三个VLM骨干：GLM-4.1V-9B、Qwen2.5-VL-7B、Qwen3-VL-8B。基线包括Zero-Shot、任务驱动合成（Task-Driven）和人工数据（AgentNet）。ANCHOR在OSWorld上对Qwen3-VL-8B取得20.56%成功率，显著高于任务驱动的17.75%和人工数据的16.35%；在WindowsAgentArena上，Qwen3-VL-8B从23.07%提升至30.76%。

| 模型 | 设置 | OSWorld成功率 (%) | WindowsAgentArena成功率 (%) |
| :--- | :--- | :--- | :--- |
| Qwen3-VL-8B | Zero-Shot | 16.82 | 23.07 |
| Qwen3-VL-8B | Task-Driven | 17.75 | 27.47 |
| Qwen3-VL-8B | ANCHOR | 20.56 | 30.76 |
| Qwen2.5-VL-7B | ANCHOR | 7.94 | 15.22 |
| GLM-4.1V-9B | ANCHOR | 7.01 | 16.30 |

消融实验显示，移除步骤级过滤与去噪后，Qwen3-VL-8B性能从20.56%降至19.15%，Qwen2.5-VL-7B从7.94%降至7.01%，表明质量控制在数据规模有限时至关重要。数据缩放分析揭示非单调性：Qwen3-VL-8B在0.3K数据时性能从16.82%降至13.08%，1K时恢复至20.56%，归因于小数据量下模型原生动作模板与合成数据格式的不匹配。跨域增强（Ubuntu+Windows）在1K数据规模下将Qwen2.5-VL-7B性能从7.94%提升至9.95%，证明平台多样性有助于学习鲁棒接地行为。

评估边界方面，论文未报告置信区间，且OSWorld子集任务数较少（如VS Code仅11个任务），导致小样本波动大。代码与模型已开源（yale-nlp/Anchor），训练使用4×NVIDIA H200 GPU，超参数细节见附录。

## 关联研究分析

从问题动机看，ANCHOR与AgentTrek（教程重放）和Explorer（任务驱动）形成互补。AgentTrek依赖外部教程，覆盖度受限于教程可用性；Explorer依赖执行器能力，失败轨迹截断导致数据偏差。ANCHOR通过“状态锚定”解耦任务多样性与执行器完美性，其分支点机制本质是将“探索”约束在已验证状态空间内，避免了交互驱动探索（如OS-Genesis）中无约束漫游产生的低信号轨迹。然而，ANCHOR的分支点识别依赖GPT-5.1的判断，是否引入模型偏见（如偏好特定UI布局）未经验证。

从方法设计看，ANCHOR与VideoAgentTrek（视频逆向工程）代表数据合成的两条路径：前者侧重桌面高保真、小样本高质量，后者侧重大规模、低成本但含噪声。ANCHOR的步骤级过滤机制（任务条件推理+意图一致性去噪）在数据规模有限时（<1K）收益显著，但VideoAgentTrek在AgentNetBench上取得69.3%成功率，表明大规模噪声数据在离线动作预测任务上可能更具优势。ANCHOR未探索RL优化策略，仅依赖SFT，这与2025年GUI-R1等工作的RLVR趋势存在差距，其数据增强效果在长程任务中的上限是否受限于SFT的过拟合特性，论文未给出回答。

## 总结

ANCHOR解决的核心矛盾是桌面GUI长程轨迹生成的多样性与保真度平衡。其切入点在于利用已验证种子轨迹的分支点作为状态锚，将任务生成约束在可靠前缀上，避免了任务驱动合成的执行器耦合与交互驱动探索的噪声问题。方法通过分支点识别、在线任务修订与步骤级过滤，生成了平均17.24步的高信号轨迹，在OSWorld上将Qwen3-VL-8B成功率从16.82%提升至20.56%，在WindowsAgentArena上从23.07%提升至30.76%。边界在于：绝对性能仍低于BEAP-Agent（28.2%），且未结合RL优化策略，仅依赖SFT。当数据规模超过1K后，步骤级过滤的边际收益是否递减，以及分支点扩展在移动端或Web端的泛化能力，论文未提供实验证据。
