## 导读

大语言模型智能体（LLM Agent）通过调用外部工具突破静态知识边界，其核心价值在于弥合模型内部推理与外部动态环境之间的鸿沟。早期研究以 ReAct 范式为主线，通过交错生成推理轨迹与执行动作，确立了“推理-行动-观察”的基础交互架构，思路简洁却受制于上下文窗口限制与长程任务中的信用分配难题。当大规模工具生态暴露出全量暴露导致的 Token 爆炸与选择低效后，研究者转向动态检索与标准化协议（如 MCP），用更精细的工具管理换取推理效率与集成兼容性。随着强化学习（RL）与合成环境的引入，领域重心从演示驱动转向自我进化，通过可验证奖励解决训练数据稀缺问题。各路线在架构复杂度、训练成本与泛化能力之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从静态编排到动态策略优化的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

大语言模型智能体领域的兴起源于模型从静态文本生成向动态环境交互的范式转变。早期研究聚焦于通过思维链（Chain-of-Thought）提升推理能力，但受限于知识冻结和无法执行动作，模型难以获取实时信息或操作外部世界。这一根本矛盾促使研究者引入“工具增强”（Tool-Augmented）架构，将 LLM 视为决策核心，通过调用外部函数（如 API、代码解释器）扩展其能力边界。工具使用（Tool Use）因此成为智能体获取实时信息和执行数字动作的核心机制，而推理-行动循环（ReAct）则确立了该领域最基础的交互架构，解决了纯推理缺乏实时反馈的问题。

问题形式化可表述为：在有限上下文窗口 $W$ 和高维工具空间 $\mathcal{T}$ 中，智能体需根据当前状态 $s_t$ 和任务目标 $g$，生成动作序列 $a_{1:T}$ 以最大化任务成功率。这一过程涉及子问题的强依赖关系：工具检索与选择是长程规划的前提，高质量合成环境是强化学习策略优化的基础，记忆机制与上下文管理则是解决长程任务上下文爆炸的关键支撑。范式边界由此清晰划分：提示工程（Prompt Engineering）侧重于静态配置与逻辑引导，而策略优化（Strategy Optimization）则通过强化学习或微调实现动态适应，后者在长程任务中展现出显著优势。

2016-2022 年，领域处于奠基阶段，核心约束是模型缺乏逻辑连贯性与环境交互能力。ReAct（Yao et al., 2022）通过交替生成推理轨迹与执行动作，奠定了现代 LLM 智能体的基础。2023 年，Toolformer（Schick et al., 2023）提出自监督学习框架，使 LLM 自主决定何时调用外部 API，开创了工具调用格式内化的研究方向。同年，Reflexion（Shinn et al., 2023）引入语言反馈机制，允许智能体从失败轨迹中学习，为在线策略优化提供了关键范式。

2024 年，约束条件发生显著变化，工具生态从单一 API 扩展至大规模异构接口，导致上下文窗口爆炸与集成碎片化问题凸显。MCP（Model Context Protocol）的出现标准化了工具接口，AutoGen（Wu et al., 2024）则推动了从单智能体向多智能体协作的架构演进。此时问题已转变为如何在标准化协议下高效编排复杂工具序列，并解决多智能体通信瓶颈。

2025-2026 年，研究重心从单纯的提示工程转向系统性优化，核心约束变为训练数据稀缺与长程任务中的信用分配难题。Agent0（Xia et al., 2025）和 Tool-R0（Acikgoz et al., 2026）提出无数据自进化框架，通过强化学习在合成环境中训练智能体，解决了高质量训练数据稀缺的瓶颈。当前形态表现为：基于 MCP 标准化接口、利用 RL 进行策略优化、并具备记忆增强与自我进化能力的通用智能体框架，旨在实现无需人工标注的持续性能提升。

**如果用一个核心问题概括该领域，那便是：如何在有限上下文窗口与高维工具空间中，构建具备长程规划能力、动态适应环境反馈并实现自我进化的自主智能体决策系统。**

## 2. 方法体系

- 2022：ReAct——奠定“推理-行动-观察”范式基础

- 2023：Toolformer——自监督学习内化工具调用格式

- 2023：Reflexion——语言反馈机制实现从失败中学习

- 2024：AutoGen——多智能体协作框架推动架构演进

- 2025：Agent0——无数据自进化框架解决训练数据稀缺

- 2026：Tool-R0——从零数据自进化的工具学习框架

- 2026：MiroFlow——高性能分层架构实现鲁棒深度研究

这条时间线勾勒了该领域方法演进的代表性节点：从 2022 年的 ReAct 奠定该领域方法基线，经 2023 年 Reflexion 的推进，到 2026 年的 Tool-R0 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 Agent框架与基础设施

Agent 框架的演进始于解决多智能体协作中的通信瓶颈与状态同步问题。早期框架如 AutoGen（Wu et al., 2024）通过定义静态角色和对话流来协调多个 LLM 实例，虽然推动了从单智能体向多智能体系统的架构演进，但基于文本消息传递的机制存在序列化开销大、状态不一致等缺陷。CaveAgent（Ran et al., 2026）针对这一短板，将 LLM 转化为有状态运行时操作符，通过运行时中介的状态流实现“通过共享状态通信”，取代了传统的“通过对话通信”，消除了序列化瓶颈，显著提升了协作的实时性和准确性。

随着任务复杂度增加，框架设计进一步向分层解耦与自动化生成方向发展。MiroFlow（Su et al., 2026）设计了三层层级架构（控制层、Agent 层、基础层），通过解耦工作流编排与 Agent 行为逻辑，提升了系统在复杂研究任务中的鲁棒性与可复现性。Youtu-Agent（Shi et al., 2025）则提出了自动化生成 Agent 配置的框架，通过 Agent Practice 模块优化提示词，以及 Agent RL 模块支持端到端强化学习，实现了从手动调参到自动化 Agent 合成的范式转变。这些框架在放弃通用性灵活性的同时，换取了特定场景下的高效性与可靠性，与工具调用优化路线形成互补，为后者提供了稳定的执行底座。

### 2.2 工具调用与选择优化

工具调用优化的核心矛盾在于大规模工具空间下的选择困难与上下文窗口限制。早期方法如 ToolLLM（Qin et al., 2024）通过合成大规模工具使用数据集并微调 LLM，确立了数据驱动的工具调用优化路线，但全量暴露工具导致 Token 成本激增。AutoTool（Jia and Li, 2025）针对这一问题，利用工具使用惯性构建有向图，通过图结构预测工具调用序列，绕过重复的 LLM 推理，显著降低了推理延迟与成本。该方法将工具选择视为图上的路径预测问题，放弃了每次重新查询 LLM 的灵活性，换取了高并发场景下的效率提升。

随着 MCP 协议的普及，工具接口标准化成为新焦点。MCP-Flow（Wang et al., 2025）设计了专门的训练和评估流程，解决了 MCP 工具生态中数据稀缺和多样性不足的问题。Dynamic System Instructions（Franko, 2025）则提出动态指令与工具暴露机制，根据当前任务状态检索并注入相关的指令片段和工具 Schema，解决了静态系统提示词占用大量上下文窗口的问题。HyperAgent（Zhai et al., 2026）进一步将工具关系建模为超图，捕获工具间的高阶依赖和组合模式，提升了多工具协作的准确性。这些方法在放弃全量暴露的简单性的同时，换取了大规模工具库下的选择准确率与推理效率，与 Agent 框架路线共同构成了智能体执行的核心能力。

### 2.3 Agent训练与强化学习

Agent 训练路线的演进源于提示工程在长程任务中的局限性，核心目标是解决信用分配难题并实现无数据自进化。Reflexion（Shinn et al., 2023）引入语言反馈机制，允许智能体在任务失败后通过自我反思生成改进策略，实现了无需梯度更新的在线策略优化。然而，这种方法难以处理复杂长轨迹中的细粒度信用分配。Agent0（Xia et al., 2025）提出无数据自进化框架，通过课程 Agent 与执行 Agent 的协同进化，利用强化学习在零人工标注数据下提升智能体的工具使用与推理能力。

Tool-R0（Acikgoz et al., 2026）进一步提出从零数据自进化的工具学习框架，通过生成器-求解器协同进化与难度奖励机制，利用强化学习在可验证奖励下提升智能体的工具调用策略。SCoRe（Lyu et al., 2025）则提出从纠正到精通的强化蒸馏范式，通过导师问题解决（MPS）将学生置于学习中心，由教师发现错误步骤并进行回滚纠正，解决了传统行为克隆的复合误差增长问题。AgentPro（2025）利用蒙特卡洛树搜索（MCTS）生成步骤级标签，训练过程奖励模型（PRM），将过程监督从数学推理扩展到自然语言推理任务。这些方法在放弃提示工程低成本的同時，换取了长程任务中的决策可靠性与泛化能力，与合成环境路线紧密耦合，依赖高质量环境提供训练信号。

### 2.4 环境合成与基准评测

环境合成路线的兴起源于真实世界 API 的稀缺性、不稳定性及数据隐私问题，核心目标是构建大规模、高保真的可执行交互环境。ToolBench（2023）构建了包含大规模真实 API 的交互式环境，解决了工具学习领域缺乏标准化评测基准的问题。然而，真实 API 的访问限制使得规模化训练难以实现。Agent-World（Dong et al., 2026）提出扩展真实世界环境合成的框架，通过深度研究管道自主挖掘主题对齐的数据库和可执行工具接口，构建可扩展的环境生态，并通过可执行奖励进行状态感知监督。

EnvScaler（Song et al., 2026）通过程序化合成扩展工具交互环境，自动生成符合环境约束的复杂数据，解决了真实环境构建成本高、扩展性差的问题。ToolVerse（Zhou et al., 2026）则解锁大规模环境和长程任务，引入回合感知相对优势估计算法，解决标准基于组 RL 在长程推理中的信用分配限制。MCP-Bench（2026）基于 MCP 服务器构建复杂真实世界任务基准，填补了标准化协议下 Agent 评测的空白。这些环境在放弃真实世界完全保真度的同时，换取了训练的可控性、可验证性与规模化能力，为强化学习路线提供了必要的基础设施，与基准评测共同构成了智能体能力评估的闭环。

### 2.5 记忆机制与经验复用

记忆机制路线旨在解决长程任务中的上下文爆炸与跨任务泛化问题，核心是通过外部记忆实现长期知识积累与经验复用。MemGPT（2024）引入操作系统启发的分层记忆架构，区分主上下文与外部存储，实现了智能体在长程任务中的动态记忆管理。BREW（Kirtania et al., 2025）提出基于经验回放与 MCTS 搜索的记忆增强框架，动态构建和精炼语义片段，通过检索历史经验指导当前规划，显著提升了智能体在长程任务中的记忆利用率与任务成功率。

AutoContext（Cai et al., 2025）提出实例级上下文学习方法，通过紧凑探索构建可复用的知识图谱，使用 TODO 森林作为核心数据结构，解决了任务级知识学习缺乏实例级事实的问题。Neural Procedural Memory（Zhao et al., 2026）则通过隐式激活转向赋能 LLM 智能体，预计算并存储历史经验的隐藏状态表示，通过检索-合成-干预管道进行干预，解决了文本-行动脱节问题。TRACE（Wu et al., 2026）提出自进化技能库，通过技能感知分组和状态条件技能编排，提升了智能体在多轮交互中的可靠性和一致性。这些方法在放弃实时计算资源的同时，换取了长程任务中的上下文效率与跨任务泛化能力，与推理规划路线互补，为决策优化提供了历史经验支撑。

### 2.6 推理规划与决策优化

推理规划路线聚焦于提升智能体在复杂环境中的决策策略，核心是解决探索不足与长程规划中的不确定性处理问题。MAXS（Zhang et al., 2026）引入元自适应探索机制，结合前瞻策略与价值估计，在推理过程中动态调整探索深度与广度，提升了智能体在复杂决策任务中的成功率并优化了计算资源分配。DORA Explorer（Gurjar et al., 2026）提出无需训练的探索增强框架，通过序列级探索导向排序（DORA）控制 LLM 的动作多样性，解决了自回归模型在决策任务中探索不足的问题。

Utility-Guided Agent Orchestration（Liu et al., 2026）提出效用引导的 Agent 编排框架，通过轻量级效用控制提升效率和可解释性，解决了现有固定工作流缺乏动态适应性的问题。Entropy-Guided Branching（Wei et al., 2026）通过计算动作空间的熵，动态决定何时分支探索，以平衡探索与利用，提升了长程工具使用任务中的决策准确性。Agentic Abstention（Luo et al., 2026）则将智能体弃权定义为序贯决策问题，解决了标准 LLM 弃权作为单轮决策的局限，增强了系统在不确定环境中的可靠性。这些方法在放弃简单贪心策略的同时，换取了复杂动态环境中的决策鲁棒性与资源效率，与工具调用优化路线共同构成了智能体执行的核心决策层。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

ReAct 范式（推理-行动-观察循环）已成为构建 LLM 智能体的事实标准基础架构，绝大多数后续工作均在此基础上进行扩展或优化。这一共识在 GAIA 和 τ-bench 等长程任务基准上得到反复验证：MiroFlow 的 75.0% 与 Youtu-Agent 的 72.8% 均大幅超越 GPT-4o 的 62.0% 基线，表明推理-行动循环在复杂任务中的核心地位（支撑证据：P26、P13）。与此相关的另一个共识是，外部工具的使用是突破 LLM 知识冻结和计算能力限制的关键，能够显著提升在数学、代码和事实查询任务上的表现。ToolBench 基准上 ToolVerse 的 45.0% 与 MCP-Flow 的 42.0% 均显著超越 ReAct 的 30.0% 基线，验证了工具增强架构的有效性（支撑证据：P39、P8）。

然而，这一共识的边界在于，仅依靠提示工程已不足以应对复杂长程任务，结合强化学习或微调进行策略优化是提升智能体性能的主流方向。BFCL 基准上 Tool-R0 的 47.84% 与 SPADE 的 41.8% 虽低于 GPT-4o 的 50.0% 基线，但在 ToolBench 等大规模工具生态中，强化学习方法展现出显著优势，表明策略优化在长程任务中的必要性（支撑证据：P25、P42、P39）。

### 3.2 观点分歧

提示工程与强化学习在长程任务优化中的主导范式之争，是领域内最核心的分歧。提示工程派认为精心设计的提示（如 ReAct, Reflexion）足以应对大多数任务，成本低且易于部署；强化学习派则认为 RL（如 Tool-R0, Agent0）通过可验证奖励和过程监督，能更有效地解决长轨迹中的信用分配问题。现有证据偏向 RL，在 GAIA 和 τ-bench 等长程任务基准上，基于 RL 的方法（如 Youtu-Agent, Tool-R0）显著优于纯提示工程基线，但 RL 的训练成本和稳定性仍是挑战，且缺乏统一的评测协议来公平比较两者在相同计算预算下的表现（支撑证据：P13、P25、P11）。

这一分歧的背后，是另一个更根本的争论：单智能体与多智能体在复杂任务处理中的最优架构。单智能体派认为通过记忆增强和动态工具检索（如 BREW, AutoContext）即可处理复杂任务，避免了多智能体通信开销；多智能体派则认为多智能体（如 AutoGen, CaveAgent）通过角色分工和并行处理，能更好地应对层级复杂任务。证据混合，在需要角色分工的任务中多智能体表现更优，但在简单工具调用任务中单智能体效率更高。CaveAgent 在 τ-bench 上 80.0% 的准确率显著领先 AgentFlux 的 58.3%，验证了共享状态机制在多轮任务中的优势，但缺乏理论指导来确定何时使用单智能体或多智能体（支撑证据：P14、P5、P12、P6）。

### 3.3 其他开放问题

当前研究面临的最紧迫工程问题是工具自动发现与动态注册。静态工具集无法适应新环境，难点在于工具描述的标准化和语义匹配精度。潜在路径包括 MCP 协议扩展、工具元数据自动富化和动态工具图构建。OpaqueToolsBench 基准上 ToolObserver 的 70.0% 准确率表明，交互式探索机制在文档质量受限的工具环境中具有显著优势，但检索精度与任务成功率之间的权衡尚未完全量化（支撑证据：P23）。

最根本的研究问题是长程信用分配与跨环境泛化。在长轨迹中，最终奖励难以准确归因到具体的中间步骤或工具调用，导致强化学习训练不稳定。AgentPro 的过程监督机制和 Tool-R0 的难度奖励机制提供了潜在解决方案，但合成环境与真实世界的差距、RL 奖励设计的稀疏性仍是核心瓶颈。此外，智能体可靠性与安全性验证缺失，缺乏系统性的方法来评估智能体在复杂动态环境中的鲁棒性，以及如何防止恶意工具或提示注入导致的资源滥用和安全风险（支撑证据：P45、P25、P32）。

已知—争议—未知认知图谱显示：ReAct 范式与工具使用的必要性是已知共识；提示工程与 RL 的主导范式、单智能体与多智能体的最优架构是核心争议；长程信用分配、跨环境泛化与安全性验证是根本未知。未来趋势将依赖于合成环境的保真度提升及自我进化机制的理论完善。

## 4. 总结与展望

LLM Agent 领域的核心矛盾在于模型内部静态知识与外部动态环境之间的鸿沟，这一矛盾驱动了从静态编排到动态策略优化的范式转变。早期方法通过 ReAct 和 Toolformer 解决了知识冻结问题，但受限于提示工程的静态配置，无法应对长程任务中的上下文爆炸和信用分配难题。随后，MCP 标准化接口与动态检索机制解决了工具生态碎片化问题，而强化学习与合成环境的结合则突破了训练数据稀缺的瓶颈，实现了智能体的自我进化。当前核心瓶颈在于如何在开放世界中实现高效、可靠且可泛化的长程决策，这一瓶颈源于合成环境与真实世界的差距、RL 奖励设计的稀疏性以及多智能体协作的理论最优性缺失。

未来可能突破的方向包括：多智能体协作与分布式推理，通过联邦学习、去中心化编排和角色分工机制解决通信开销和状态同步问题；长程记忆与状态管理，通过层次化记忆、向量数据库集成和程序性记忆蒸馏解决上下文窗口溢出和状态丢失问题；强化学习在 Agent 训练中的应用，通过过程奖励模型、自博弈训练和环境合成 RL 解决奖励稀疏性和信用分配问题。这些方向在 Agent0、Tool-R0、CaveAgent 和 BREW 等工作中已展现出初步成效，共同指向构建具备长程规划、动态适应与自我进化能力的通用智能体。对于进入该领域的研究者，最值得做的一件事是在统一骨干与统一预训练条件下，系统评估不同架构（单智能体 vs. 多智能体）与策略（提示工程 vs. 强化学习）在长程任务中的性能差异，以厘清当前分歧的根本原因。
