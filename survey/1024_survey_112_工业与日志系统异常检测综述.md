## 导读

工业与日志系统异常检测旨在从海量、非平稳且高维的数据流中识别偏离正常模式的故障或攻击行为，其核心价值在于保障分布式系统与工业物联网的可靠性与安全性。早期研究以深度序列建模为主线，通过长短期记忆网络捕捉日志时序依赖，思路简洁却受制于表示质量与长距离依赖的丢失。当跨域基准暴露出分布偏移下的性能崩溃后，研究者转向预训练时序模型与视觉语言模型，用更强的先验换取跨域鲁棒性。随着大语言模型（LLM）的引入，领域范式从黑盒预测向可解释推理跃迁，通过思维链与代码合成解决了运维信任危机，但引入了高昂的计算成本与幻觉风险。各路线在检测精度、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从几何度量到语义推理的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

工业与日志系统异常检测的兴起源于现代分布式系统、云计算及工业物联网（IIoT）规模的爆炸式增长，传统基于规则或人工监控的方法已无法应对海量、高维且动态变化的数据流。该领域的核心任务可形式化为：给定正常数据分布 $P_{normal}$ 与观测序列 $X = \{x_1, x_2, ..., x_T\}$，学习一个映射函数 $f: X \rightarrow [0, 1]$，使得 $f(x)$ 在 $x$ 偏离 $P_{normal}$ 时输出高异常分数。在日志场景中，输入通常是离散的模板序列；在工业时序场景中，输入则是连续的多变量传感器读数。这一形式化定义看似简单，实则隐含了数据分布非平稳、异常样本极度稀缺（通常占比 <5%）以及计算资源受限三大核心约束，这些约束共同决定了方法设计的边界。

问题定义并非静态，而是随着技术能力与运维需求的提升而不断演化。早期研究将异常检测简化为“正常模式的偏离”，侧重于单模态数据的统计重构或序列预测误差。然而，随着系统复杂度的增加，单纯的“检测”已无法满足运维需求，问题逐渐演变为“检测+定位+根因分析+可解释性”的综合诊断。这一转变意味着模型不仅要回答“哪里异常”，还要回答“为什么异常”以及“如何修复”。子问题之间呈现严格的层级依赖关系：日志解析与数据预处理是基础，决定了特征的质量；异常检测模型是核心，决定了检测的精度；可解释性与根因分析是上层应用需求，依赖于检测模型的输出质量；而跨域泛化与实时性约束则是贯穿所有子问题的横向挑战，不解决泛化问题，模型在新场景中失效；不解决实时性，高精度模型无法落地。

从范式边界来看，该领域正经历从黑盒深度学习向灰盒智能系统的过渡。黑盒模型（如大型 Transformer）在捕捉复杂非线性依赖方面具有优势，但缺乏可解释性，难以获得运维人员信任；白盒模型（如基于规则的方法）可解释性强，但泛化能力差且维护成本高。当前的研究热点集中在利用 LLM 增强语义理解、解决跨系统数据分布偏移、以及处理极端类别不平衡问题，旨在结合物理先验、因果推理及人类专家知识，构建兼具高精度与可审计性的系统。

回顾约束演化史，2017-2018 年是奠基期，DeepLog 与 Drain 确立了基于序列建模与日志解析的范式，解决了自动化特征提取问题，但忽视了语义信息。2020 年前后，跨域基准的出现暴露了单一系统训练模型的泛化局限，促使研究转向域适应与元学习。2021-2023 年，Transformer 架构的普及解决了长距离依赖问题，MVTec AD 等基准推动了工业视觉检测的标准化，但模型黑盒化加剧。2024-2026 年，LLM 的引入成为最新范式，RationAnomaly、CodeAD 等工作通过零样本推理与代码合成，显著提升了检测的可解释性与跨域泛化能力，同时也带来了计算成本与幻觉的新挑战。

**如果用一个核心问题概括该领域，那便是：如何在数据分布非平稳、异常样本极度稀缺且计算资源受限的工业约束下，构建兼具高精度检测、细粒度根因定位及人类可解释性的自适应智能系统。**

## 2. 方法体系

- 2017：DeepLog——利用 LSTM 建模日志序列依赖，确立序列预测范式

- 2017：Drain——在线日志解析算法，提供结构化模板基础

- 2018：MVTec AD——构建工业视觉异常检测标准基准

- 2020：Isolation Forest——高维时序数据无监督检测经典基线

- 2025：RationAnomaly——结合 CoT 与强化学习，实现可解释日志推理

- 2025：CodeAD——利用 LLM 合成检测规则代码，实现自动化监控

- 2025：MOMENT——大规模预训练时序模型，支持跨机器特征迁移

- 2026：KRONE——分层抽象架构，平衡计算效率与语义理解精度

这条时间线勾勒了该领域方法演进的代表性节点：从 2017 年的 DeepLog 奠定该领域方法基线，经 2018 年 MVTec AD 的推进，到 2026 年的 MMR-AD 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 日志异常检测

日志异常检测的起源可追溯至 2017 年 DeepLog（Xu et al., 2017）提出的基于 LSTM 的序列预测范式，该方法通过预测下一个日志事件并计算预测误差来识别异常，确立了自动化特征提取的基础。然而，DeepLog 仅捕捉时间局部依赖，忽视了日志的语义信息，且在长序列上存在梯度消失问题。针对这一局限，2023 年的 LogAnomaly 引入了语义与统计特征融合，增强了模型对日志语义偏差的敏感度，但仍未解决可解释性缺失的问题。

随着 LLM 能力的突破，2025 年出现了范式跃迁。RationAnomaly（Xu et al., 2025, P1）针对传统模型黑盒化及 LLM 幻觉问题，提出了结合思维链（CoT）监督微调与强化学习对齐（RLA）的框架。该方法通过显式建模诊断推理过程，使模型能够生成逐步的推理轨迹，从而在 BGL 数据集上取得了 0.92 的 F1 分数，显著优于 DeepLog 的 0.85 基线。其核心取舍在于以复杂的训练流程和较高的推理延迟，换取了人类可理解的根因分析与更高的检测精度。与此同时，CodeAD（Huang et al., 2025, P3）采取了截然不同的路径，它不直接输出标签，而是利用 LLM 合成可执行的检测规则代码。CodeAD 分为离线合成与在线检测两阶段，通过层次聚合聚类减少冗余计算，将自然语言理解转化为结构化规则执行。这种方法放弃了端到端的泛化能力，换取了规则的透明性与可审计性，特别适用于规则维护成本高的工业场景。

为了平衡 LLM 的高精度与高成本，2026 年的 KRONE（Ma et al., 2026, P12）提出了分层抽象架构。KRONE 通过动态实例化层级结构将日志分解为模块化序列，并在轻量级本地检测器与 LLM 推理器之间进行自适应路由。这种设计在 HDFS 数据集上达到了 0.89 的 F1 分数，接近纯 LLM 方法但效率更高。KRONE 的核心创新在于利用层级分解降低计算复杂度，同时保留关键语义信息，解决了大规模日志处理中的计算效率与语义理解平衡问题。此外，ContraLog（Dietz et al., 2026, P11）针对日志文本重复性高的特点，提出了结合对比学习与掩码语言建模的方法，通过定制化的 BPE 分词器压缩重复模板，在 HDFS 上取得了 0.91 的 F1 分数，展示了在语义表示学习上的优势。

日志检测路线与工业时序检测路线存在互补关系：前者侧重于离散事件的语义逻辑，后者侧重于连续信号的物理动态。日志检测中的 LLM 推理技术正逐渐被引入时序领域，以增强对复杂故障模式的解释能力。

### 2.2 工业时序异常检测

工业时序异常检测早期主要依赖 Isolation Forest（Liu et al., 2020）等无监督统计方法，这些方法计算效率高且无需假设数据分布，但在捕捉复杂多变量动态依赖方面存在局限。2025 年，MOMENT（Li et al., 2025, P17）的提出标志着预训练时序模型在工业领域的落地。MOMENT 通过编码器生成多变量时序数据的高维嵌入表示，实现了跨机器、跨场景的时序特征迁移，解决了工业设备数据异构导致的泛化难题。Cross-Machine AD（Li et al., 2026, P17）进一步利用 MOMENT 嵌入在嵌入空间上训练异常检测器，展示了良好的跨设备泛化能力。其代价是依赖预训练模型的计算资源，且嵌入维度较高可能增加后续分类器的训练难度。

针对动态环境下的概念漂移问题，Real-Time Adaptive AD（Raeiszadeh et al., 2026, P7）提出了结合 LSTM 与动态窗口调整机制的方法。该方法通过监测预测误差比率来检测概念漂移，并在检测到漂移时动态调整滑动窗口大小并重新训练模型。这种自适应机制避免了固定窗口导致的滞后或误报，但在重新训练过程中可能引入延迟。此外，Failure vs Domain Shift（Wojak-Strzelecka et al., 2026, P16）提出了一种区分故障与域偏移的方法，结合分布变化检测与可解释 AI（XAI），通过特征重要性变化辅助人类操作员区分良性域偏移与真实故障，提升了监控的可解释性。

在融合领域知识方面，LLM-Assisted Logic Rule Learning（Zhang and Jain, 2026, P9）利用 LLM 从历史数据中提取业务逻辑规则，并生成可执行的检测代码，应用于供应链监控场景。该方法将人类专家的业务知识转化为自动化规则，提升了检测的业务对齐度。Triplet Feature Fusion（Yasuno, 2026, P14）则探索了轻量级多模态融合，利用小基础模型生成时序嵌入，并结合文本嵌入与统计特征输入 LightGBM 分类器，在资源受限的现场部署中展示了可行性。

工业时序检测与云网系统检测在数据模态上相似，但前者更强调物理过程的因果约束，后者更强调服务拓扑的上下文依赖。时序检测中的预训练模型技术正被云网领域借鉴，以应对大规模遥测数据的异构性。

### 2.3 工业视觉多模态检测

工业视觉异常检测的标准化始于 2018 年 MVTec AD（Berntsen et al., 2018）基准的发布，该数据集确立了仅使用正常样本训练、在异常样本上测试的无监督范式。然而，传统视觉模型难以处理复杂背景与未知缺陷类型。2026 年，MMR-AD（Yao et al., 2026, P18）构建了大规模多模态异常检测基准，并提出了基于多模态大语言模型（MLLM）的 Anomaly-R1 基线模型。Anomaly-R1 基于 Qwen2.5-VL 微调，并采用强化学习进行后训练，将工业视觉检测转化为多模态问答任务，利用 MLLM 的通用推理能力处理复杂缺陷。其核心创新在于推动了从专用模型向通用多模态智能体的转变，但代价是模型参数量大，推理成本较高。

针对多模态数据融合中的“模态淹没”问题，Physic-HM（Liu et al., 2025, P6）提出了一种通过分层调制恢复物理生成逻辑的方法。该方法将传感器信号视为物理先验，通过分层调制机制调节视觉特征与传感器特征的融合权重，避免低维传感器信号被高维视觉特征淹没。在 Weld-4M 数据集上，Physic-HM 取得了 90.7 的准确率，显著优于简单融合方法。其核心创新在于引入物理约束，使模型能够理解工业过程的物理因果关系。此外，Omni-AD（2026, P31）提供了涵盖 150 个产品类别的大规模基准，定义了针对 MLLM 的语义丰富问答评估协议，推动了通用异常检测模型的研究。Contextual Inference for AD（Wilkinghoff et al., 2026, P19）则强调上下文推理，认为异常性取决于观察背景，通过对比不同上下文下的行为模式来识别异常，为理解相对异常性提供了理论框架。

视觉检测与日志检测在 LLM 应用上存在共性，均利用大模型的语义理解能力。但视觉检测更依赖物理先验与空间定位能力，而日志检测更侧重时序逻辑与因果推理。

### 2.4 云网系统异常监测

云网系统异常监测面临高维稀疏数据与分布式环境下的隐私保护挑战。2022 年 FedLog 结合时间卷积网络与联邦学习，展示了跨机构日志监控的可行性。2025 年，ClouDens（Doan et al., 2026, P27）提出了操作上下文感知的异常检测框架，通过遥测特征分解与上下文感知图建模，联合利用数值指标与上下文信息。该方法解决了孤立指标监控导致的误报问题，在 Cloud Telemetry 基准上取得了 0.94 的 F1 分数。其核心创新在于将服务拓扑等操作上下文融入数值监控，但代价是图构建与预测计算开销较大。

Reveal（Chen et al., 2025, P4）则聚焦于硬件遥测，利用 CPU、GPU、内存及网络的多层遥测信号定位硬件故障。该方法通过规则与机器学习结合的方式，实现了细粒度的硬件归因，解决了传统监控无法区分软件瓶颈与硬件故障的问题。Benchmarking Cloud Telemetry（Islam and Miranskyy, 2026, P13）统一了模型训练与评分流程，评估了 GRU、TCN、Transformer 等架构在异构数据上的表现，揭示了域偏移与规模变化对模型泛化的影响，强调了统一评估协议的重要性。Wavelet-Aware Log AD（Kong et al., 2026, P8）针对内部威胁检测，利用小波变换捕捉多分辨率时序特征，并通过分辨率自适应注意力机制区分稳定例程与异常行为，展示了多分辨率分析在细粒度用户行为分析中的价值。

云网监测与工控安全监测在数据源上均有网络流量，但前者侧重服务可用性，后者侧重安全威胁防御。云网领域的上下文感知图建模技术正被引入工控领域，以捕捉跨层级的攻击关联。

### 2.5 工控安全异常防御

工控安全异常防御针对工业控制系统（ICS）中的网络攻击与逻辑异常，强调实时性与鲁棒性。2025 年，IstGPT（Zhang et al., 2026, P24）构建了工业时空图（ISTG）并结合 LLM 进行异常检测，融合物理拓扑结构与语义理解，捕捉跨层级的攻击关联。在 SWaT 数据集上，IstGPT 取得了 0.98 的 F1 分数。其核心创新在于利用 LLM 对图节点与边进行语义增强，检测逻辑层欺骗与数据注入攻击，但代价是时空图构建复杂且 LLM 推理延迟较高。

ASTRO（Yar et al., 2026, P23）提出了基于图神经网络（GNN）与自适应时空强化优化的方法，利用 GNN 捕捉空间依赖，并通过强化学习优化时空特征提取，应对动态攻击模式。在 SWaT 数据集上，ASTRO 取得了 0.9902 的 F1 分数，略高于 IstGPT。其核心创新在于引入强化学习机制，使模型能够自适应调整对时空特征的注意力。MPNet-AE（Mohammed et al., 2026, P10）则利用 LLM 编码系统日志与自编码器，捕捉隐蔽的低频率 APT 攻击特征，在 DARPA TC 等基准上展示了高 AUC-ROC。Robustness under Contamination（Ozbek et al., 2026, P29）评估了检测模型在训练时数据污染下的鲁棒性，揭示了数据完整性对模型安全的重要性，为防御数据投毒攻击提供了实证依据。

工控安全与云网监测在图建模技术上有重叠，但工控安全更强调物理拓扑的准确性与攻击的对抗性。工控领域的 LLM 应用正从检测向根因分析与策略更新延伸。

### 2.6 表格数据异常检测

表格数据异常检测针对结构化数据，探索基于 LLM 上下文学习、规则推理及监管合规性的方法。2026 年，LLM-Detector（Nguyen et al., 2026, P28）利用 LLM 的上下文学习能力，通过提示工程合成领域特定的异常检测代码引擎，无需微调即可实现表格数据异常评分。该方法将 LLM 作为代码生成器而非直接分类器，解决了表格数据中跨特征依赖违规难以通过单一密度模型捕捉的问题。Regulation-Guided Tabular AD（2026, P30）结合数据验证与 LLM，将监管原则转化为可操作的检测想法，解决了监管规则难以直接转化为检测逻辑的问题，在金融与医疗合规监控中展示了价值。

D2H-AD（Ghajari et al., 2026, P26）提出了一种结合密度、距离度量与超维计算（HDC）的无监督方法，将数据编码为高维二进制向量，直接计算异常分数，无需迭代优化训练。该方法在实时数据流监控中展示了优势，为高维稀疏数据的快速异常检测提供了轻量级解决方案。TACTIC（Marszałek et al., 2026, P15）则基于上下文推理，将异常检测转化为上下文条件概率预测，利用模型泛化能力捕捉数据分布结构，在无监督表格检测中展示了竞争力。

表格检测与日志检测在 LLM 应用上均强调上下文学习，但表格数据更强调跨特征依赖与合规性约束。表格检测中的代码生成技术正被引入日志与视觉领域，以实现更灵活的规则定制。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

领域内最核心的共识是深度学习方法在捕捉复杂时序依赖和语义特征方面显著优于传统统计方法。这一共识在多个基准上被反复验证：在 BGL 上，RationAnomaly 的 0.92 与 ContraLog 的 0.90 均大幅超越 DeepLog 的 0.85 与 Isolation Forest 的 0.78；在 SWaT 上，ASTRO 的 0.9902 远超 LSTM 的 0.92。这表明，随着数据维度与复杂度的增加，浅层模型难以捕捉高维非线性依赖，而深度模型通过端到端学习能够更有效地提取特征。与此相关的另一个共识是无监督或半监督学习是工业异常检测的主流范式。由于获取大量标注异常数据在现实中极其困难且昂贵，绝大多数方法（如 Isolation Forest, MVTec AD 范式, ContraLog）仅利用正常数据训练，通过重构误差或密度估计检测异常。这一范式选择直接源于工业场景的数据稀缺性约束，而非技术偏好。

此外，可解释性被视为工业部署的关键需求。单纯的高准确率不足以满足运维需求，模型需要提供人类可理解的异常原因或证据。RationAnomaly 通过 CoT 生成推理轨迹，CodeAD 通过合成规则代码，均旨在解决黑盒模型带来的信任危机。这一共识反映了领域从“检测精度”向“精度+可解释性”双重目标的转变。然而，该共识的边界在于，可解释性往往以牺牲部分精度或增加计算成本为代价，如何在两者间取得平衡仍是开放问题。

### 3.2 观点分歧

关于 LLM 在异常检测中的角色，存在“核心检测器”与“辅助解释/规则生成器”的分歧。观点 A 认为 LLM 应直接输出异常标签或评分，如 TACTIC 与 Llama 2 Zero-shot；观点 B 认为 LLM 应作为辅助工具，生成检测规则代码或提供可解释性推理，如 CodeAD 与 RationAnomaly。现有证据偏向观点 B：在 BGL 上，直接检测的 Llama 2 Zero-shot 仅取得 0.75 的 F1 分数，而 RationAnomaly 通过 CoT 推理达到 0.92，ContraLog 通过对比学习达到 0.90。CodeAD 等规则生成方法在保持高精度的同时提供了可审计性，更符合工业需求。这一分歧的背后，是 LLM 幻觉问题与计算成本的权衡：直接检测对幻觉敏感且成本高，而规则生成依赖 LLM 对业务逻辑的理解，存在规则覆盖不全的风险。

另一显著分歧在于多模态融合策略：统计融合 vs 物理先验引导。观点 A 主张早期/晚期统计融合，简单拼接或加权不同模态特征；观点 B 主张物理先验引导的层级调制，如 Physic-HM。现有证据偏向观点 B：在 Weld-4M 上，Physic-HM 取得 90.7 的准确率，显著优于简单融合方法。物理引导能解决“模态淹没”问题，即低维传感器信号被高维视觉特征掩盖。然而，物理先验的提取依赖领域专家，难以自动化，且不同工业场景的物理模型差异大，缺乏通用的物理约束表示方法，这使得观点 B 的普适性受到质疑。

### 3.3 其他开放问题

最紧迫的工程问题是实时边缘部署与计算效率优化。大规模日志流处理中，LLM 推理延迟和资源消耗过高，难以满足毫秒级响应要求。KRONE 通过分层抽象与自适应路由，在 HDFS 上以 0.89 的 F1 分数接近纯 LLM 精度但效率更高，展示了混合架构的潜力。然而，路由策略的调优复杂，且 LLM 推理引擎仍需进一步优化。关键困难在于保持高精度的同时满足边缘设备的算力约束，研究路径包括轻量化模型设计（如 Tiny LLMs）、混合超维计算（如 D2H-AD）和基于缓存的嵌入复用。

最根本的研究问题是跨域泛化与少样本学习。新系统或新故障模式下标注数据稀缺，源域与目标域间的分布差异导致模型性能下降。LogAction 通过主动域适应缓解分布差距，MOMENT 通过预训练实现跨机器迁移，但两者均存在局限：域适应对分布差异敏感，预训练依赖海量数据与算力。关键困难在于缺乏针对“零样本跨域”的标准化评测，且物理先验与数据驱动的深度融合机制尚不明确。研究路径包括元学习原型网络、基于 LLM 的语义抽象以及物理信息神经网络（PINN）与异常检测的结合。

归纳“已知—争议—未知”认知图谱：已知深度模型优于统计模型，无监督是主流，可解释性不可或缺；争议在于 LLM 的最佳角色、多模态融合策略及跨域泛化路径；未知在于物理先验的自动化提取、LLM 幻觉的根治及动态概念漂移下的在线自适应机制。未来趋势将向构建人机协同、物理可信的智能异常检测生态系统演进。

## 4. 总结与展望

工业与日志系统异常检测正经历从“感知”到“认知”的范式转变，核心矛盾在于如何在数据分布非平稳、异常样本极度稀缺且计算资源受限的工业约束下，实现高精度、可解释与自适应的平衡。早期研究通过深度序列建模解决了自动化特征提取问题，但忽视了语义与可解释性；随后，Transformer 与 LLM 的引入提升了语义理解与推理能力，但带来了计算成本与幻觉风险。当前，领域正通过分层架构、物理先验融合及预训练模型，尝试在精度、效率与可解释性之间寻找新的平衡点。

未来可能突破的方向包括：一是多模态数据融合与物理先验建模，通过引入物理生成逻辑（如 Physic-HM）解决模态淹没问题，提升细粒度定位能力；二是 LLM 驱动的自动化规则生成与解释，利用 LLM 合成可执行检测代码（如 CodeAD）并进行根因分析，实现人机协同的闭环运维；三是跨域泛化与少样本学习，通过元学习与语义抽象（如 KRONE）减少对人工标注的依赖。对于进入该领域的研究者，最值得做的一件事是构建统一的、覆盖多模态与跨域场景的标准化基准，并引入计算效率与可解释性质量的量化指标，以解决当前评测碎片化与公平性缺失的问题。
