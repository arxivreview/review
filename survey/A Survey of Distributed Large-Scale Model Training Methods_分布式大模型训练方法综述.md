## 导读

分布式大模型训练（Distributed Large-Scale Model Training）旨在突破单卡显存与算力瓶颈，其核心价值在于通过多设备协同实现万亿参数模型的可行训练。早期研究以数据并行与 ZeRO 分片为主线，通过消除显存冗余解决“能不能训”的问题，思路简洁却受制于跨节点通信开销。当集群规模突破单节点容量后，张量并行与流水线并行引入，形成了混合并行范式，但通信尾延迟与硬件故障成为新瓶颈。面对十万卡集群中分钟级的平均故障间隔时间（MTBF），研究重心从吞吐量优化转向系统鲁棒性与去中心化训练，用异步容错与低通信优化换取训练连续性与资源民主化。各路线在通信效率、计算利用率与系统可靠性之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从显存解放到系统韧性的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

分布式大模型训练的兴起源于 Transformer 架构下模型参数从数十亿向万亿级跃迁，单卡显存与算力瓶颈迫使研究转向多设备协同。这一领域的核心任务可形式化为：在给定硬件拓扑 $\mathcal{H}$、网络带宽 $B$ 与故障率 $\lambda$ 约束下，寻找并行策略配置 $\mathcal{P}$ 与通信调度 $\mathcal{C}$，使得有效训练时间 $T_{eff}$ 最大化。早期以数据并行（DP）为主，随后 ZeRO 通过分片优化器状态、梯度和参数显著降低显存冗余，成为关键转折点。随着模型规模突破单节点容量，张量并行（TP）与流水线并行（PP）引入，形成了 3D/4D 混合并行范式，以平衡通信开销与计算效率。

问题定义在 2019-2021 年间经历了从“显存不足”到“通信瓶颈”的深刻变形。ZeRO 与 Megatron-LM 解决了单卡内存问题，但引入了跨设备同步开销，问题焦点从存储转移至带宽与延迟。此时，集合通信（如 AllReduce）在跨节点时成为主要瓶颈，现有重叠技术难以完全隐藏高延迟尾效应。子问题间存在严格的依赖层级：通信优化是并行策略高效执行的前提，容错机制是大规模训练持续性的基础，系统建模与仿真是上述所有优化策略验证与调优的工具支撑。

2022-2024 年，问题定义进一步扩展至异构硬件适配及互联网级低带宽环境。随着集群规模扩大和地理分散需求出现，现有并行策略假设同构高带宽网络，在异构 GPU 或互联网级低带宽下，负载不均与通信阻塞严重。DiLoCo 类低通信优化器与去中心化范式试图打破数据中心垄断，利用地理分散资源。与此同时，十万卡集群中频繁的硬件故障（MTBF 缩短至分钟级）使得容错机制成为核心议题，传统同步检查点导致大量算力浪费。

2025-2026 年，研究重心从单纯的吞吐量优化转向系统鲁棒性、异构硬件适配及去中心化训练。面对动态变化的集群状态，静态并行配置无法适应弹性需求，自动并行策略搜索（Auto-Parallelism）开始取代人工试错。当前，领域活跃度极高，研究涵盖从底层集合通信优化到上层自动并行策略搜索，旨在解决算力、通信与可靠性之间的三角矛盾。

**如果用一个核心问题概括该领域，那便是：在算力、通信带宽与系统可靠性构成的三角约束下，如何构建能够自适应硬件拓扑、网络波动及故障干扰的高吞吐、低延迟且具备自愈能力的分布式训练系统范式。**

## 2. 方法体系

- 2014：DistBelief——奠定该领域方法基线

- 2017：FedAvg——低通信同步的理论雏形

- 2019：ZeRO——消除显存冗余的标准组件

- 2019：Megatron-LM——确立 3D 并行基本范式

- 2024：DiLoCo——低带宽互联网训练里程碑

- 2025：NCCLX——超大规模集合通信基础设施

- 2025：FT-HSDP——十万卡规模容错训练系统

- 2026：Covenant-72B——互联网规模去中心化预训练

这条时间线勾勒了该领域方法演进的代表性节点：从 2014 年的 DistBelief 奠定该领域方法基线，经 2017 年 FedAvg 的推进，到 2026 年的 TawPipe 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 并行策略与调度

并行策略与调度路线的起源可追溯至 2019 年 ZeRO 与 Megatron-LM 确立的 3D 并行范式，其核心是通过分片与切分解决单卡显存不足。然而，静态配置难以适应动态硬件环境与变长序列负载，促使研究转向动态自适应与细粒度负载均衡。AsyncHZP（Bai et al., 2025, P8）针对传统 ZeRO 同步屏障限制导致的流水线利用率低下问题，提出了分层 ZeRO 并行与异步调度相结合的方法。它通过层级化组织设备组，允许不同设备组在非同步模式下执行计算和通信，从而隐藏部分通信延迟。该方法的代价是引入了更复杂的调度逻辑和潜在的收敛性风险，需要仔细调优异步窗口大小。与静态配置相比，AsyncHZP 放弃了配置稳定性，换取了对硬件波动的适应能力。

TawPipe（Wu and Chen, 2025, P11）则针对长上下文 LLM 训练中激活值通信随序列长度线性增长的问题，提出了拓扑感知的权重流水线并行方法。它利用分布式集群的层级带宽特性，通过拓扑感知的设备分组来优化权重传递路径，减少了冗余的对等（P2P）传输。其代价是依赖于集群拓扑结构的先验知识，且权重传递可能引入额外的内存压力。OptPipe（Li et al., 2025, P7）通过混合整数线性规划（MILP）求解最优的流水线调度策略，结合 AdaOffload 提供初始解以加速求解，在内存受限场景下仍能保持高性能。其代价是求解 MILP 需要一定的计算时间，且依赖于准确的性能模型。

DynaTrain（Wang et al., 2026, P32）进一步支持快速在线并行策略切换，允许在训练过程中动态调整数据、张量、流水线和专家并行策略，而无需重启训练任务。它通过并行策略状态管理器和快速切换机制，在不同并行布局之间无缝迁移模型状态。其代价是引入了状态迁移的开销和复杂性，且需要精确的并行策略兼容性检查。OptiCo（2026, P41）则利用多智能体系统自动调整并行配置，结合性能数据分析和故障诊断，动态优化数据、张量和流水线并行策略。其代价是智能体推理过程可能引入额外的延迟，且依赖高质量的性能数据输入。SlimPack（Liu et al., 2025, P6）针对变长 LLM 训练中的负载不均衡问题，通过切片级打包范式创建平衡的“MicroPacks”，缓解了混合并行系统中级联不均衡效应。其代价是打包和调度过程增加了预处理开销。

### 2.2 通信优化与压缩

通信优化与压缩路线的演进始于 2020 年 Ring-AllReduce 确立的带宽最优梯度聚合范式，随后研究聚焦于如何进一步降低带宽需求与隐藏延迟。NCCLX（Si et al., 2025, P9）针对 10 万+ GPU 规模中的通信瓶颈，引入了基于主机驱动的 CTran 框架，移植了经典 HPC 通信算法如 Brucks 和 Recursive Doubling。它优化了 AllGather 和 ReduceScatter 算法，应对跨数据中心的高延迟挑战。其代价是算法复杂度较高，且依赖于主机驱动框架的支持。与传统的 Ring-AllReduce 相比，NCCLX 放弃了简单的环形拓扑，换取了超大规模下的通信可靠性与吞吐量。

SCAPE（Zheng et al., 2026, P36）针对现代优化器（如 AdamS）的梯度分布特性，设计了对噪声更鲁棒的 Top-k 稀疏化策略，避免了传统方法在稀疏化时导致的损失尖峰。它通过基于 AdamS 一阶矩的 Top-k 掩码构建器和误差反馈机制，保持了模型性能的同时大幅降低了通信开销。其代价是稀疏化策略依赖于优化器类型，且误差反馈增加了内存占用。EDGC（Yi et al., 2025, P12）则利用梯度熵随训练收敛而逐渐降低的特性，动态调整压缩秩。它通过低秩分解压缩器和熵监控器，平衡了通信开销和模型性能。其代价是熵计算和动态调整引入了额外的计算开销。

CommFuse（Karim et al., 2026, P27）通过通信分解和融合隐藏尾延迟，将 AllGather 和 ReduceScatter 分解为对等交换，并与计算重叠。它通过 FuseAG 和 FuseRS 原语，以及秩自适应调度器，最大化计算和通信的重叠。其代价是调度逻辑复杂，且依赖于精确的计算和通信时间预测。DES-LOC（2026, P42）结合 Local SGD 和自适应优化器，通过去同步机制处理优化器状态，解决了自适应优化器在低通信场景下的收敛性问题。其代价是去同步机制可能引入额外的收敛延迟。

### 2.3 容错与稳定性

容错与稳定性路线的兴起源于 2023 年 Llama-3 训练基础设施揭示的 MTBF 随规模增加而急剧下降的现实挑战。FT-HSDP（Salpekar et al., 2026, P19）针对超大规模集群中频繁的硬件故障问题，提出了支持 10 万 GPU 规模的容错混合分片数据并行训练系统。它通过异步恢复机制和副本级容错，避免单点故障导致的全局重启。其代价是异步恢复可能引入轻微的训练进度偏差，且需要复杂的故障检测机制。与传统的同步检查点-重启策略相比，FT-HSDP 放弃了全局一致性，换取了有效训练时间的显著提升。

DeadPool（Xie et al., 2026, P35）通过零开销检查点实现热切换，在每次迭代后进行内存检查点，当节点故障时，备用节点可无缝接管角色。它无需重新初始化通信后端，直接从内存恢复模型参数和优化器状态。其代价是内存检查点占用了额外的内存资源，且热切换机制需要精确的节点状态同步。ReCoVer（Liu et al., 2026, P29）设计了副本级容错机制，允许在部分节点故障时继续训练，避免传统检查点-重启策略的高恢复开销。其代价是容错集合通信可能引入额外的通信开销。

R2CCL（Wang et al., 2025, P15）通过带外（OOB）通知路径实现双边故障感知，将故障检测时间从分钟级降低到毫秒级。其代价是引入了额外的 OOB 网络流量和监控开销。TierCheck（Han et al., 2026, P31）通过多级存储分层存储训练状态，优化检查点写入和读取性能。其代价是分层存储增加了系统复杂度。CCL-D（Gu et al., 2026, P28）通过引入细粒度内核指标，从集合通信库级别运行时状态诊断异常，实现了高覆盖率和低开销的异常检测。其代价是细粒度监控引入了额外的计算和通信开销。

### 2.4 去中心化与异构

去中心化与异构路线的探索始于 2022 年 SWARM 框架对地理分布和带宽受限环境下流水线并行协作训练的证明。Covenant-72B（Lidin et al., 2026, P25）通过互联网与无信任对等体预训练 72B LLM，结合 SparseLoCo 优化器和 Gauntlet 激励机制，实现了跨地理分布计算资源的协作训练。它证明了在缺乏专用高带宽互联的情况下，通过通信高效优化器仍可训练前沿规模模型。其代价是稀疏化和量化可能引入模型性能损失，且激励机制需要复杂的博弈论设计。与集中式训练相比，Covenant-72B 放弃了通信效率与安全性，换取了资源民主化与地理分散能力。

Agora（Avraham et al., 2026, P37）允许在互联网规模上进行无许可预训练，结合带宽高效的流水线并行分片和多方计算，利用消费者和专业 GPU 的闲置算力。其代价是互联网链路的高延迟和带宽限制可能影响训练效率，且无许可机制需要复杂的激励设计。SeedFlood（Kim and Lee, 2026, P22）利用共享随机性作为通信原语，通过零阶优化将更新表示为种子-标量对，使得通信大小独立于模型维度。其代价是零阶优化可能引入额外的收敛迭代次数。Go With The Flow（Blagoev et al., 2025, P4）将节点建模为数据节点或中继节点，通过部分同步网络进行协作训练，提升了去中心化训练对节点动态性的鲁棒性。其代价是节点动态性管理增加了系统复杂度。

### 2.5 系统建模与仿真

系统建模与仿真路线旨在解决大规模集群实验成本高昂且难以复现的问题。ASTRA-sim 3.0（Won et al., 2026, P34）通过高保真 GPU 和基础设施建模提升仿真精度，通过三层架构捕捉模型并行化、计算内核运行时和集合通信算法的细节。其代价是仿真器复杂度增加，且仿真时间可能较长。PrismLLM（Xi et al., 2026, P30）允许在少量 GPU 上模拟大规模集群的训练行为，通过高保真地复现系统运行时交互和性能异常，帮助工程师在开发阶段诊断和优化训练系统。其代价是仿真器需要精确的系统模型。

ShardMeter（Beringer et al., 2026, P39）通过建模 FSDP 和 DiLoCo 等策略的计算和通信步骤，预测训练时间，消除了配置猜测。其代价是模型需要精确的硬件和网络参数。Efficient Fine-Grained GPU Performance Modeling（Zhang et al., 2025, P5）通过专门针对计算受限矩阵乘法、内存受限归一化和网络依赖通信的回归模型，捕捉各组件的性能特性。其代价是模型校准需要大量数据。STAGE（Man et al., 2025, P13）通过符号化表示模型和并行策略，生成张量图以优化计算和通信。其代价是符号化过程可能引入额外的计算开销。

### 2.6 跨任务与多领域应用

分布式训练技术不仅应用于 LLM 预训练，还延伸至微调、强化学习及跨集群协作等场景。ScaleAcross Explorer（Li et al., 2026, P33）探索跨建筑 AI 模型训练通信优化，基于 Meta 生产经验，分析跨建筑训练的设计空间，优化通信配置。它考虑了电力、电网和冷却约束导致的建筑间距离和带宽超额订阅。其代价是跨建筑通信优化增加了系统复杂度，且依赖于精确的网络拓扑模型。Heterogeneous Low-Bandwidth Pre-Training of LLMs（Obeidi et al., 2026, P17）结合 SparseLoCo 优化器和子空间网络压缩方法，减少跨副本和副本内通信，适应了异构硬件和带宽受限环境。其代价是稀疏化和压缩可能引入模型性能损失。

Revisiting Parameter Server in LLM Post-Training（Wan et al., 2026, P18）重新审视参数服务器架构在 LLM 后训练中的应用，证明了其在特定场景下的有效性。Dual-Node NVIDIA DGX Spark over Tailscale（Iyer, 2026, P38）提供了低成本、易部署的分布式训练测试床，适用于小型实验室和安全敏感项目。其代价是桌面 GPU 的计算能力有限，且 Tailscale 连接可能引入额外的网络延迟。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

混合并行是训练前沿 LLM 的唯一可行路径，单一并行策略无法同时满足显存、通信和计算效率需求，这一共识在约 45 篇论文中得到共同支持。通信开销是分布式训练的主要瓶颈，优化集合通信算法及实现通信-计算重叠是提升吞吐量的核心手段，约 40 篇论文共同支持这一观点。与此相关的另一个共识是，大规模训练必须将容错作为一等公民，传统的同步检查点-重启机制在超大规模集群中效率低下，需引入异步或弹性机制，约 20 篇论文共同支持。ZeRO/FSDP 通过分片状态显著降低显存占用，已成为现代分布式训练框架的基础组件，约 35 篇论文共同支持。

### 3.2 观点分歧

稀疏/量化通信在长周期训练中的精度损失容忍度存在显著分歧。观点 A（SCAPE/EDGC）认为通过误差反馈和自适应压缩，稀疏通信可在保持模型性能的同时大幅降低带宽需求；观点 B（传统 DDP）认为稀疏化会累积误差，导致长周期训练性能下降。现有证据偏向观点 A 在短期（<100K steps）有效，但缺乏超大规模（>1T tokens）长周期训练的对比实验。SCAPE 在 Llama-500M 上表现良好，但在更大模型上的泛化性未验证。这一分歧的背后，是另一个更根本的争论：去中心化训练在前沿模型规模下的可行性边界。观点 A（Covenant-72B/Agora）认为通过通信高效优化器和激励机制，去中心化训练可训练前沿规模模型；观点 B（传统集中式）认为去中心化训练面临收敛漂移和拜占庭攻击风险，无法保证模型质量。Covenant-72B 证明了 72B 模型在去中心化环境下的可行性，但其评测依赖特定激励协议，且未与同等算力的集中式训练进行严格对比。

### 3.3 其他开放问题

最紧迫的工程问题是异构 GPU 集群的协同训练，现状是跨厂商通信库不兼容和硬件特性差异导致效率损失，关键困难在于运行时 API 抽象和异构感知的并行策略设计，研究路径包括内核级集成和透明化高效训练。最根本的研究问题是去中心化训练的收敛性与安全性，现状是缺乏中心协调导致参数漂移和拜占庭攻击风险，关键困难在于如何在低通信下保证收敛及验证完整性，研究路径包括稀疏梯度通信、自适应同步频率和信任机制。已知的是混合并行与容错机制的必要性，争议的是稀疏通信的长期精度影响与去中心化训练的可行性边界，未知的是自动并行配置搜索的全局最优性证明与统一形式化框架。发展趋势将从“人工调优”向“AI 自治”演进，从“数据中心垄断”向“互联网民主化”扩展。

## 4. 总结与展望

分布式大模型训练的核心矛盾已从显存限制转变为通信、计算与可靠性的动态平衡。研究者们尝试了从静态并行配置到动态自适应、从全精度同步到稀疏压缩、从同步检查点到异步热切换、从中心服务器到去中心化对等体等多种路线，但核心瓶颈仍在于如何在三角约束下最大化有效训练时间。当前，领域正处在工程优化向理论保证过渡的临界点，自动化调优和去中心化训练是两大高风险高回报方向。

未来可能突破的方向包括：实现跨数据中心甚至互联网规模的无许可去中心化训练，解决带宽受限和节点异构性导致的收敛漂移问题；开发能够自动诊断性能瓶颈并优化并行策略的智能代理系统，解决人工调参成本高且难以适应动态硬件环境的问题；构建高保真的分布式训练模拟器，解决大规模集群实验成本高昂且难以复现的问题。对于进入者而言，最值得做的一件事是构建一个统一的、支持故障注入与异构网络模拟的评测基准，以解决当前方法间公平比较困难的问题，为理论突破提供实证基础。
