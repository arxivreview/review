## 导读

多智能体系统（Multi-Agent Systems, MAS）验证与治理领域的兴起，源于大语言模型（LLM）驱动的自主智能体从单点交互向复杂协作网络的范式转移。早期研究聚焦于基于形式化逻辑的策略能力验证，旨在解决传统分布式系统中策略组合爆炸与状态空间不可扩展的问题。随着 AutoGen 等框架的普及，研究重心从静态逻辑验证转向动态运行时监控与故障归因，以应对 LLM 特有的幻觉、提示注入及协同失效问题。当前领域已进入“治理工程化”阶段，核心驱动力是解决生产环境中智能体间的信任缺失、资源失控及安全漏洞。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从几何度量到语义先验的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

多智能体系统验证与治理的核心矛盾，在于 LLM 固有的非确定性与多智能体交互的复杂涌现性之间，如何建立可证明的安全边界与可追溯的责任机制。这一矛盾并非凭空产生，而是随着智能体系统从理论模型走向生产部署逐步显化的。早期研究假设智能体行为是确定性的、可形式化描述的，且系统规模较小，因此采用交替时间逻辑（Alternating-time Temporal Logic, ATL*）等逻辑进行离线模型检查，以解决策略组合爆炸问题。然而，当 LLM 被引入作为智能体的“大脑”后，其输出的随机性、内部状态的黑箱性质以及自然语言语义的模糊性，使得传统确定性模型检查失效。

问题定义的演化清晰地反映了这一技术冲击。最初，MAS 验证旨在解决传统分布式系统中多智能体策略组合爆炸与状态空间不可扩展的问题，核心是通过形式化逻辑验证智能体联盟在对抗环境下的策略能力与协作正确性。2023-2024 年成为关键转折点，随着 LLM 驱动的智能体框架普及，问题从静态逻辑验证转向动态运行时监控，以应对 LLM 特有的幻觉、提示注入及非确定性导致的协同失效。2025-2026 年，领域进入“治理工程化”阶段，问题定义扩展至生产环境中的信任缺失、资源失控及安全漏洞，核心变为构建可解释的问责机制、去中心化声誉系统及实时错误传播阻断框架。

子问题之间存在紧密的依赖与互补关系。形式化验证提供理论正确性基础，但受限于 LLM 非确定性；运行时监控解决动态合规，但依赖故障归因来定位问题根源；安全防御与不确定性量化则是为了在开放环境中维持前两者的有效性。其中，故障归因是连接“检测异常”与“修复/问责”的关键枢纽，而语义对齐失败往往导致协调失败，进而引发安全漏洞，最终需要问责机制闭环。这种因果链决定了各子问题无法孤立解决，必须协同演进。

**如果用一个核心问题概括该领域，那便是：如何在 LLM 固有的非确定性与多智能体交互的复杂涌现性之间，建立可证明的安全边界与可追溯的责任机制，以保障高 stakes 场景下协作系统的可靠性与合规性。**

## 2. 方法体系

- 1969：Hoare逻辑——奠定程序验证中前置条件与后置条件推理的基础

- 1980：合同网协议（Contract Net Protocol）——引入通过合同进行任务分配与协调的机制

- 2002：ATL*（交替时间时序逻辑）——专门用于表达多智能体系统中智能体及其联盟的战略能力

- 2018：可扩展监督辩论（Scalable Oversight via Debate）——证明竞争性智能体间的辩论机制可用于回答PSPACE问题

- 2023：多智能体辩论（Multi-Agent Debate, MAD）——利用多个LLM智能体通过迭代辩论来交叉验证信息

- 2025：ATL*AS——一种基于自动机理论的ATL*模型检测工具

- 2025：SentinelAgent——提出意图验证的委托链机制

- 2026：TraceFix——一种基于TLA+反例的协议修复框架

这条时间线勾勒了该领域方法演进的代表性节点：从 1969 年的 Hoare逻辑 奠定该领域方法基线，经 1980 年 合同网协议（Contract Net Protocol） 的推进，到 2026 年的 TraceFix 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 形式化模型检测

形式化模型检测路线的起源可追溯至 1969 年 Hoare 逻辑对程序验证的奠基，以及 2002 年 Alur 等人提出的 ATL* 逻辑，后者专门用于表达多智能体系统中智能体及其联盟的战略能力。然而，传统显式状态枚举算法在大规模 MAS 中面临状态空间爆炸的瓶颈。ATL*AS（Garcia de Blas and Belardinelli, 2025, P9）针对这一可扩展性问题，将 ATL* 模型检测符号化归约为奇偶博弈（parity games），实现了全 ATL* 在无限迹上的首次可用实现。该方法放弃了传统显式状态枚举的直观性，换取了符号化算法在大规模系统中的可扩展性，其代价是算法实现复杂度较高，且对系统规范的形式化要求严格。

随着 LLM 生成的协议日益复杂，纯符号方法难以处理自然语言语义。TraceFix（Xia et al., 2026, P32）针对并发多智能体系统中协调失败难以调试的问题，构建了一个验证优先的闭环流程，利用 TLC 模型检测器搜索反例，并基于反例轨迹指导智能体协调协议的迭代修复。该方法放弃了离线一次性验证的简洁性，换取了从验证到调试的闭环自动化能力，其核心优势在于利用生成正确协议难但检查容易的非对称性。神经符号策略合成（Aruta et al., 2026, P38）则进一步结合神经网络与符号验证器，在庞大的组合策略空间中搜索有界自然策略，克服了显式枚举导致的指数级爆炸瓶颈，但依赖于训练数据的质量与覆盖度。

### 2.2 运行时监控与治理

运行时监控与治理路线的雏形可追溯至 1980 年的合同网协议和 1995 年的社会法律理论，旨在通过承诺与资源约束实现治理。SentinelAgent（Patil, 2026, P28）针对联邦多智能体 AI 系统中的越权操作与级联故障，形式化了委托链演算（DCC），通过 NLI 模型与嵌入模型验证智能体行为是否符合原始意图。该方法放弃了完全去中心化的灵活性，换取了细粒度的安全治理机制，其代价是验证过程引入了一定的延迟，且依赖于 NLI 模型的准确性。

Agent Contracts（Ye and Tan, 2026, P12）扩展了合同网协议以支持资源治理，定义了包含多维资源约束、时间边界与成功标准的智能体合同，并建立了守恒定律确保委托预算尊重父约束。该方法放弃了自主智能体的无限自由度，换取了形式化的资源边界治理机制，防止了无限循环与资源耗尽。上下文谱系保证（Malkapuram et al., 2025, P4）则针对关键多智能体系统中非人类身份的谱系验证，提出了一种基于 Merkle 树的不可变日志架构，弥补了传统传输层安全协议的不足，提升了智能体行为的可审计性。

### 2.3 故障归因与调试

故障归因是连接“检测异常”与“修复/问责”的关键枢纽。Famas（Ge et al., 2025, P3）将故障归因建模为频谱分析任务，通过识别导致系统失败的关键状态与动作，利用反事实推理评估每个步骤对最终结果的贡献。该方法假设故障是由单一决定性错误引起的，其代价是频谱计算的复杂度随轨迹长度增加而上升。CORRECT（Yu et al., 2025, P5）针对决定性错误定位的困难，利用算法生成的反事实数据训练 LLM，使其能够精准识别轨迹中的决定性错误步骤，显著提升了故障归因的步级准确率，但数据生成与模型训练的高成本是其主要代价。

ProMAS（Zhao et al., 2026, P26）将被动错误审计转变为主动过渡监控，通过因果流形学习提取语义位移特征，利用向量马尔可夫建模量化动作轨迹，在错误发生前预测潜在故障。该方法放弃了被动审计的低训练成本，换取了主动的风险预测能力，其代价是模型训练需要大量历史轨迹数据。基于因果推断的自动故障归因（Ma et al., 2025, P1）则构建了多粒度因果图，通过计算 Shapley 值隔离错误智能体与步骤，结合了因果推断与 LLM 推理，既捕捉了表面相关性，又通过反事实分析确定了决定性错误。

### 2.4 安全防御与攻击

安全防御与攻击路线关注 MAS 中恶意行为检测、控制流劫持防御及拜占庭容错。ControlValve（Jha et al., 2025, P8）针对控制流劫持（CFH）攻击，在编排层监控智能体行为，通过验证控制流是否符合预期路径，阻断恶意劫持尝试。该方法放弃了 LLM 微调的灵活性，换取了不依赖内部状态访问的外部监控防御，适用于现实中的多智能体场景。CP-WBFT（Zheng et al., 2025, P10）从提示层与隐藏层开发置信度探针，利用 LLM 的反思能力提取细粒度置信度信号，设计基于探针的拜占庭容错共识协议，增强了系统在部分智能体故障下的稳定性。

SentinelNet（Feng and Pan, 2025, P6）基于对比学习的动态威胁检测网络，通过对抗轨迹生成收集恶意行为样本，利用对比学习训练检测器，使其能够区分建设性与对抗性行为。MAS-FIRE（Jia et al., 2026, P22）则建立了基于架构边界的 MAS 故障分类法，采用非侵入式技术注入故障，定义了定量鲁棒性指标，为 MAS 提供了标准化的可靠性评估工具。

### 2.5 不确定性量化

不确定性量化路线旨在评估 MAS 输出结果的置信度及错误传播风险。MATU（Chen et al., 2026, P29）将多智能体交互建模为不规则张量，利用张量分解寻找低秩近似，通过重构误差衡量个体轨迹偏离共享共识的程度。该方法假设一致交互遵循低秩结构，其代价是张量分解的计算复杂度。PropUQ-MAS（Liu et al., 2026, P42）将节点不确定性分解为局部组件与级联组件，利用边缘条件独立假设与局部-传播独立假设，计算不确定性在智能体间的传播概率，适用于任意交互拓扑。

UDPO（Tang et al., 2026, P17）针对多智能体辩论中的辩论崩溃问题，定义了内部、外部与系统级不确定性指标，利用这些指标作为奖励信号，训练智能体在不确定性高时采取更保守或探索性策略。HASSUM（Knowlton et al., 2026, P41）则在层级 MAS 中，CEO 智能体根据子智能体输出的语义不确定性决定任务分配与验证策略，实现了动态的资源分配与质量控制。

### 2.6 基准与评估框架

基准与评估框架旨在量化 MAS 在协作、安全性、公平性及可靠性方面的表现。AgentCollabBench（Mazumder et al., 2026, P33）包含 900 个受控任务，通过里程碑式 KPI 与过程指标评估协作质量，揭示了通信拓扑单独解释了 7-40% 的约束存活率方差。MAS-Lab（Augé et al., 2026, P39）通过声明式智能体规范定义智能体能力与关系，并在运行时检查不变量与协调语义，填补了从原型到生产部署的验证空白。

AgentAuditor（Yang et al., 2026, P18）通过审计推理树中的分支级证据，解决多数错误案例，利用结构化分歧进行裁决。多视角故障归因基准（In et al., 2026, P27）通过 nDCG 指标评估归因排序，并引入多视角共识机制，揭示了归因结果的视角依赖性。MAS-ProVe（Venkataramani et al., 2026, P16）系统性地研究了验证策略与 MAS 架构的交互效应，揭示了自适应架构在特定验证策略下的优势。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

MAS 的可靠性是集体属性，错误会在智能体间传播并放大，因此需要专门的错误传播阻断与监控机制。这一共识在多个基准上被反复验证：PropUQ-MAS 在 Open Quiz Commons 上的 0.85 AUROC 与 CP-WBFT 在 GSM8K 拜占庭容错任务上的 95.0% Success 均表明，系统级监控与容错机制能显著提升可靠性。与此相关的另一个共识是，单一 LLM 智能体存在固有局限，多智能体协作虽能提升性能但引入了新的协调失败与安全风险，验证需从单点转向系统级。AgentCollabBench 揭示的通信拓扑对约束存活率的影响（7-40% 方差）进一步证实了协作失败往往源于信息传递而非智能体能力。

### 3.2 观点分歧

故障归因的方法论存在显著分歧：基于因果推断和频谱分析的方法（如 Famas, Abduct Act Predict）强调可解释性和数学严谨性，而基于 LLM 反事实推理和知识转移的方法（如 CORRECT）强调利用 LLM 的语义理解能力进行模式识别。现有证据显示两者在 Who&When 基准上的步级准确率相近（~47%），但因果推断方法在解释性上更优，而 LLM 方法在语义复杂场景下可能更具优势。这一分歧的背后，是另一个更根本的争论：验证的时机与粒度。离线形式化验证（如 TraceFix, ATL*AS）提供强正确性保证，应在部署前完成；在线运行时监控（如 SentinelAgent, ProMAS）适应动态环境，应在执行过程中持续进行。证据偏向“混合模式”，即离线验证核心协议，在线监控动态行为，但实时性与正确性保证之间的权衡尚未找到最优解。

### 3.3 其他开放问题

最紧迫的工程问题是实时性与资源约束的平衡。当前运行时监控方法（如 SentinelAgent）引入的延迟和计算开销限制了其在高吞吐场景中的应用，关键困难在于如何在保证低延迟的同时实时检测语义漂移和恶意行为，研究路径包括开发基于图结构的动态拓扑调整机制、引入哨兵代理进行实时流式分析。最根本的研究问题是动态治理的收敛性与偏见涌现机制。预定义的治理规则难以适应 MAS 中涌现的复杂社会动态，关键困难在于缺乏能够自动发现并演化可解释的行为宪法的理论框架，研究路径包括利用进化算法优化多智能体宪法、设计基于激励相容的治理图。已知—争议—未知认知图谱显示，形式化验证的理论基础已较成熟，但 LLM 非确定性下的扩展性仍是争议焦点；运行时监控的工程实现已有路径，但动态治理的收敛性仍是未知领域。

## 4. 总结与展望

MAS 验证与治理已从纯理论问题演变为工程与理论交织的复杂系统科学。核心矛盾在于 LLM 的灵活性/非确定性 vs. 形式化验证的确定性/可扩展性，尝试过的路线包括从纯形式化验证转向神经符号融合、从静态离线验证转向运行时监控、从单点故障检测转向系统级故障归因等。核心瓶颈在于如何在保持 LLM 生成能力的同时，通过神经符号融合与动态治理机制，实现可追溯、可审计、可容错的协作系统。

未来可能突破的方向包括：实现形式化验证与 LLM 生成的闭环集成（如 TraceFix, VERIMAP），开发资源受限与去中心化环境下的可验证协调机制（如 DAO-Agent, μACP），以及解决多智能体系统中的偏见涌现与公平性治理。对进入者最值得做的一件事是构建统一的、涵盖动态交互与多因一果现象的评测基准，以解决当前评测体系的碎片化问题，为方法比较提供公平的基础。
