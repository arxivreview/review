# A Survey of Root Cause Analysis Methods for Cloud Systems ｜云系统根因分析方法综述 ｜arxivreview

综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/Root%20Cause%20Analysis%20for%20Cloud%20Systems)

## 导读

云系统根因分析（Root Cause Analysis, RCA）旨在从复杂的故障传播网络中逆向追踪初始源头，其核心价值在于将运维从被动响应转向主动预防与自动化修复。早期研究依赖服务依赖图（SDG）与统计相关性算法，思路直观却受限于静态拓扑假设与单一模态数据的表达瓶颈。当微服务架构的复杂性导致故障跨服务级联传播后，研究者引入因果推断与图神经网络，试图在数学层面区分因果与相关，但语义理解的缺失成为新的天花板。随着大语言模型（Large Language Model, LLM）的介入，领域重心转向多智能体协作与结构化推理，通过整合日志、指标和追踪数据模拟人类专家的假设-验证过程。各路线在因果严谨性、语义灵活性与计算效率之间做出了不同取舍，由此形成当前统计推断与智能体推理并存的多元方法格局。本综述梳理这条从图遍历到因果智能的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

云系统根因分析的核心任务是在动态、多模态且存在潜在混淆变量的环境中，识别故障的初始源头并解释其传播机制。随着微服务架构的普及，应用被分解为大量独立部署的服务单元，其松耦合特性虽然提升了开发效率，却导致故障极易沿调用链跨服务传播。这种复杂性使得传统基于规则或单一模态的统计方法难以满足实时性和准确性要求，RCA 因此成为保障云系统可靠性的核心任务。形式化地看，给定一个包含 $N$ 个服务节点的有向图 $G=(V, E)$ 和多模态观测数据 $\mathcal{D} = \{M, L, T\}$（分别代表指标、日志和追踪），RCA 的目标是找到节点集合 $V$ 中的子集 $V_{root}$，使得 $V_{root}$ 是引发观测异常的最小充分原因集合。这一形式化定义隐含了三个关键假设：拓扑结构已知或可学习、观测数据无偏且完整、故障传播遵循确定的因果机制。

问题定义的演化反映了技术能力的边界扩张。早期研究将 RCA 简化为“在静态图中寻找异常节点”，核心依赖 Pearson 相关系数或 Granger 因果性，假设故障传播路径固定且指标数据足以反映系统状态。然而，这种定义忽略了非结构化日志中的语义信息，且无法处理动态拓扑变化。2020 年后，随着可观测性数据维度的爆炸，问题边界扩展至“跨模态语义对齐与深层依赖探索”，研究者开始关注如何融合异构数据以构建统一语义空间。这一转变暴露了早期方法在噪声环境下的失效：统计相关性易受潜在混淆变量干扰，导致将下游症状误判为根因。

子问题之间存在强依赖关系，构成了 RCA 的技术栈层次。多模态数据对齐是基础，若不解决指标、日志、追踪在时间粒度和语义空间上的异构性，因果图学习将缺乏高质量的输入特征。因果结构学习是核心，若无法在数学层面区分因果与相关，后续的推理过程极易陷入幻觉或浅层探索。细粒度定位（如代码级）是最终目标，它依赖于前两者的准确性，并直接决定自动化修复的可行性。此外，动态拓扑适应贯穿始终，是制约所有静态方法泛化能力的瓶颈，要求系统具备在线更新因果结构的能力。

约束演化史清晰地展示了方法如何因应环境变化而迭代。2018-2022 年是奠基期，CloudRanger 和 CIRCA 等工作确立了“图+因果”的基本范式，通过贝叶斯网络引入因果推断理论，提升了可解释性，但受限于静态拓扑假设。2023-2024 年出现转折，RCAEval 等基准的出现标准化了评测，同时 LLM 开始介入，问题核心变为“如何约束 LLM 进行结构化因果推理”。这一时期，研究者发现纯 LLM 推理在复杂拓扑中易出现事实幻觉，因此开始探索图增强与记忆机制。2025-2026 年进入“智能体增强与自我进化”阶段，PRAXIS、OpsAgent 和 OpenRCA 2.0 等工作标志着从“单次诊断”向“持续学习”和“过程级监督”的转变，重点解决 LLM 在复杂拓扑中的幻觉问题、推理深度不足以及多模态数据对齐难题。

当前形态呈现出“LLM 智能体+因果图增强+多模态融合”的混合架构。统计推断路线追求数学严谨性，通过图无关或局部因果推断提高鲁棒性；LLM 智能体路线具备强大语义能力，但需引入结构化约束以抑制幻觉；多模态融合路线解决数据输入瓶颈，为前两者提供燃料。这三条路线并非完全竞争，而是互补共存：LLM 智能体常调用因果图作为工具，或在同一任务上与纯因果方法竞争。领域的认知边界在于，如何在动态、噪声环境下实现鲁棒的因果推理与实时诊断，同时保持可解释性与自动化闭环。

**如果用一个核心问题概括该领域，那便是：如何在动态、多模态且存在潜在混淆变量的云系统环境中，构建具备因果推理能力与自我进化机制的智能体系统，实现从故障症状到代码级根因的可解释、实时且鲁棒的定位与闭环修复。**

## 2. 方法体系

- 2018：CloudRanger——基于 Pearson 相关系数构建服务依赖图，确立图遍历基础地位

- 2021：MicroRCA——利用图神经网络学习服务间依赖关系，推动数据驱动图学习

- 2022：CIRCA——将 RCA 形式化为因果贝叶斯网络干预识别问题，引入因果推断理论

- 2024：RCAEval——提供开源基准与评估框架，解决缺乏统一评测标准问题

- 2025：PRAXIS——提出 LLM 驱动的结构化遍历，结合 SDG 和 PDG 实现代码级根因分析

- 2025：OpsAgent——构建免训练数据处理器与多智能体协作框架，引入自进化机制

- 2026：OpenRCA 2.0——从结果标签转向因果过程监督，构建包含推理轨迹的评测基准

这条时间线勾勒了该领域方法演进的代表性节点：从 2018 年的 CloudRanger 奠定该领域方法基线，经 2021 年 MicroRCA 的推进，到 2026 年的 OpenRCA 2.0 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 因果推断与图建模

因果推断与图建模路线的起源可追溯至对统计相关性局限性的反思。早期方法如 CloudRanger 依赖 Pearson 相关系数，但在存在潜在混淆变量时易产生误判。CIRCA（2022）将 RCA 形式化为因果贝叶斯网络中的干预识别问题，基于调用图构建因果结构，引入了因果推断理论，提升了根因定位的可解释性，是因果 RCA 领域的重要里程碑。这一范式转变的核心动机是 SRE 对因果解释的需求，而非单纯的相关性排名。

本批论文中，CCLH（Xie et al., 2025, P4）针对早期方法在处理高阶交互时的不足，提出基于超图的级联条件学习方法。该方法利用门控循环单元和跨模态注意力机制提取实例级时间特征，构建超图以整合实例状态，设计基于实例分组关系分类法的异构超边。CCLH 采用级联诊断任务，先独立训练根因定位（RCL）任务，再引入故障类型识别（FTI）任务，通过两阶段训练策略确保 RCL 的可靠性。其取舍在于：放弃单一任务的简洁性，换取多任务间的因果连贯性，但代价是超图构建和训练的计算复杂度较高。

HyperODE-RCA（Liu et al., 2026, P12）进一步将连续时间建模与高阶关系学习结合，解决离散序列模型处理不规则观测的不足。该方法结合超图注意力网络（HyperGAT）与潜在 ODE 编码器，通过 Gumbel-Softmax 松弛的可微超边生成学习多服务依赖，捕捉协调故障中的高阶关系。潜在 ODE 编码器捕获连续时间动态，支持任意时间插值并推导异常传播速度。HyperODE-RCA 的核心创新在于利用 Transformer 交叉注意力融合多模态信号，并整合变分信息瓶颈和不变风险最小化因果充分性约束。其成功依赖于多模态数据的完整性和质量，代价是模型结构复杂，训练和推理开销较大。

StableRCA（Lin et al., 2026, P18）则代表了另一条路径：图无关的机制级根因分析。该方法无需已知全局因果图，通过筛选表现出边际分布偏移的变量，为每个候选估计局部马尔可夫毯（MB），最后根据条件分布偏移幅度对候选进行排序。StableRCA 对图错误具有强鲁棒性，在 50% 图损坏情况下仍保持竞争力，而基于图的方法性能显著下降。其取舍在于：放弃全局结构信息的利用，换取对动态拓扑和图错误的鲁棒性，但局部 MB 估计的计算成本随变量数量增加而上升。

PRIM（Lohse et al., 2026, P14）提出基于元学习的贝叶斯根因分析方法，利用 Transformer 神经过程（TNP）进行零样本推理。该方法将 RCA 重构为贝叶斯因果元学习问题，通过模拟先验拟合网络处理分布偏移，避免了显式因果发现的高成本。PRIM 在零样本推理时仅根据正常和异常数据以及异常观测位置对候选根因节点进行评分，通过贝叶斯模型平均处理图和函数机制不确定性。其成功依赖于合成先验的泛化能力，代价是元学习训练需要大量模拟数据。

Graphical Causal Reasoning（Chraim et al., 2026, P20）和 NetCause（Chraim et al., 2026, P21）则聚焦于网络基础设施。前者利用 Granger 因果性和条件独立性测试构建因果图，假设观测数据不受隐藏共同原因影响；后者提出反事实学习 RCA 方法，学习前向转移机制以支持反事实扰动查询，假设已知异构拓扑。NetCause 利用图神经网络（GNN）建模交互系统动态，通过消息传递捕捉局部交互如何产生全局行为，其核心创新在于将反事实推理应用于图时间数据，区分因果相关故障与仅时空接近的故障。

### 2.2 LLM 智能体诊断

LLM 智能体诊断路线的兴起源于对非结构化日志语义理解的迫切需求。早期 LLM 应用多为简单提示工程，但在复杂微服务拓扑中易出现浅层探索或事实错误。PRAXIS（Cui et al., 2025, P5）提出由 LLM 驱动的结构化遍历编排器，专门用于诊断代码和配置引起的云事故。其核心创新在于同时遍历服务依赖图（SDG）和 hammock-block 程序依赖图（PDG），前者提供微服务级的高层定位，后者捕捉代码级依赖以实现细粒度决策。PRAXIS 通过整合工具、可观测性数据和依赖图，统一了事故、云和程序上下文，解决了传统 ReAct 范式缺乏结构化推理和程序上下文的问题。其代价是构建和维护 PDG 的计算开销较大，且依赖高质量的代码静态分析结果。

OpsAgent（Luo et al., 2025, P3）构建了一个免训练数据处理器与多智能体协作框架，旨在实现云系统事故管理的自进化。该框架定义了异常检测（AD）、故障追踪（FT）和根因定位（RCL）等专家角色，通过编排器协调并支持迭代交叉审查，产生显式中间证据和可审计的诊断轨迹。其自进化机制结合了通过 PPO 微调的内在更新和通过智能体反思的显式经验积累。OpsAgent 刻意保持轻量化，使用 14B 参数的开源模型作为推理核心，避免了大规模闭源 LLM 的高部署成本。其取舍在于：放弃大规模模型的极致性能，换取低部署成本和持续学习能力，但 PPO 微调需要一定的计算资源，且经验积累机制需要长期的运行数据。

SpecRCA（Zhang et al., 2026, P7）提出基于假设-验证（Hypothesize-Then-Verify）的推测性 RCA 框架，利用路径并行性加速微服务故障诊断。该框架首先通过假设起草模块高效生成广泛的候选根因集合，随后由根因验证器进行细粒度验证，最后由诊断合成器聚合结果并解决不一致性。其核心创新在于利用蒸馏的小模型（如 Llama3.2-3B）进行快速假设生成，从而在保持高精度的同时大幅降低推理延迟。SpecRCA 通过并行处理多个假设路径，显著缩短了从异常检测到诊断报告生成的时间。其代价是蒸馏过程需要高质量的大模型教师数据，且并行计算可能增加瞬时资源消耗。

AMER-RCL（Zhang et al., 2026, P6）引入增强记忆与递归推理机制，解决 LLM 在微服务根因定位中过早终止递归的问题。该方法提出深度保证推理框架，包含初始推理、关键反思和最终审查三个阶段，显式强制足够的探索深度。AMER-RCL 通过 MetaAgent 生成推理步骤，并利用记忆机制存储和检索历史诊断经验，以指导当前的递归过程。其核心改进在于防止 LLM 因局部信息满足而忽略深层异常，确保对复杂调用链的彻底探索。其代价是递归深度增加会导致推理步骤增多，从而增加 LLM 调用的成本和延迟。

TopoEvo（Wang et al., 2026, P17）构建拓扑感知的自进化多智能体框架，联合进行微服务根因定位与故障类型分类。该框架包含数据预处理、依赖图构建、多模态对齐、拓扑增强推理和自进化机制五个组件。其核心创新在于利用向量量化和症状词汇进行拓扑感知增强，并通过假设-证据-测试的多智能体诊断流程提升推理质量。TopoEvo 采用层级记忆和测试时适应机制实现自进化，使系统能够根据新事故更新其内部知识库。其代价是构建和维护层级记忆需要额外的存储开销，且测试时适应可能引入一定的推理延迟。

GALA（Tian et al., 2026, P24）提出图增强 LLM 智能体，用于微服务中的根因分析和事故响应。该方法将服务依赖图直接嵌入 LLM 推理过程，通过图引导的调查算法优化探索策略。GALA+ 版本引入了并行分支、剪枝阈值和批量大小等参数，以平衡探索深度与计算效率。其核心创新在于利用图结构约束 LLM 的搜索空间，避免盲目遍历，从而提升故障传播路径的分析效率。其代价是图构建和维护需要实时拓扑监控支持，且并行分支可能增加内存占用。

STAR（Wang et al., 2026, P16）设计阶段归因的分诊与修复框架，作为微服务 RCA 智能体的过程中心可靠性层。该方法不重新解决 RCA，而是审计 RCA 轨迹，识别关键故障阶段，修复相应的阶段工件，并仅重放下游阶段以消除错误污染。STAR 包含阶段审计、快速/慢速路由、关键阶段定位、补丁重放修复和自进化修复记忆五个组件。其核心创新在于将 RCA 过程分解为可审计的阶段，并通过局部修复而非全局重算来提升鲁棒性。其代价是阶段审计需要额外的计算资源，且修复记忆的管理需要复杂的策略。

### 2.3 多模态数据融合

多模态数据融合路线旨在解决指标、日志、追踪数据格式各异且时间粒度不同的异构性问题。Multimodal Diagnostic Framework（Park, 2026, P8）提出时间序列与文本模态对齐框架，解决 LLM 处理连续数值序列的模态不匹配问题。该方法包含语义压缩技术，将时间序列片段蒸馏为单 token 抽象，同时保留模式语义。利用门控交叉注意力编码器将时间序列特征投影至语言模型潜在空间，实现模态对齐。检索增强诊断管道将对齐嵌入与历史事故知识合成，用于专家级故障归因。其核心创新在于通过语义压缩和注意力机制桥接时间序列与文本模态，使 LLM 能够理解核心故障签名。其代价是语义压缩可能损失部分时间细节。

EventADL（Pham et al., 2026, P13）构建基于事件的开盒异常检测与定位框架，利用多模态观测数据智能分析云事件流。该方法针对云事件流中的异常行为，通过联合推理指标、日志与追踪数据，实现了从异常检测到根因定位的端到端自动化。EventADL 利用结构化事件数据记录谁在何时对哪些资源执行了什么操作，捕捉 API 调用、配置变更和资源更新等操作。其核心创新在于将事件数据作为主要输入，结合多模态信号进行异常检测和定位，解决了传统方法仅关注指标或日志的局限。其代价是事件解析和关联的计算开销较大。

Anomaly Detection and Root Cause Analysis（Pham, 2026, P19）提出基于多模态可观测性数据的智能分析框架，用于微服务系统的异常检测和根因分析。该方法利用指标、日志和追踪数据，通过机器学习模型识别异常并定位根因。其核心创新在于将异常检测与 RCA 解耦，分别优化两个任务的性能。该方法假设异常应在指标中可见，并影响延迟或错误，从而简化了异常定义。其代价是解耦设计可能导致信息损失，且需要分别训练两个模型。

### 2.4 网络与基础设施 RCA

网络与基础设施 RCA 路线专注于电信网络、数据中心及边缘计算环境，结合拓扑感知、反事实学习及意图消歧，解决大规模物理与逻辑依赖网络中的故障传播与归因难题。NetCause（Chraim et al., 2026, P21）在此领域具有代表性，其反事实学习机制假设已知异构拓扑，通过反事实模拟对单个事件中的候选原因进行排序，而非估计群体级因果效应。NetCause 利用 GNN 建模交互系统动态，通过消息传递捕捉局部交互如何产生全局行为，其核心创新在于将反事实推理应用于图时间数据，区分因果相关故障与仅时空接近的故障。

MILD（Hossain and Aljoby, 2026, P11）设计多意图学习与消歧框架，用于意图驱动网络中的主动故障预测。该方法通过教师增强的 MoE 模型联合输出意图失败风险与根因分布，解决了多意图共漂移导致的根因模糊问题。MILD 利用混合目标函数训练，在运行时将风险平滑为警报，并按警报提供解释。其核心创新在于将意图保证形式化为监督学习，同时输出固定时间范围的失败风险和根因分布。其代价是 MoE 模型训练复杂度较高。

AURORA（De Silva et al., 2026, P15）提出不确定性感知的韧性微智能体，用于计算连续体中的因果可观测性。该方法结合贝叶斯网络结构学习与马尔可夫毯，在边缘受限环境下实现轻量级因果诊断。AURORA 利用 BIC 评分的爬山搜索学习 BN 结构，防止在数据稀疏的边缘设备上过拟合。其核心创新在于通过 VFE 安全界限防止错误干预，确保在灰色故障场景下的诊断可靠性。其代价是变量消除的计算复杂度较高。

The Abstention Protocol（Gaikwad and Pandey, 2026, P25）提出用于 Clos Fabric 的 RCA 协议，通过层级启发式结合多个并行配置的投票进行归因或弃权。该方法针对大规模云网络中的背景故障噪声，通过多阶段开关拓扑的故障隔离机制，区分与事故相关的故障和常规背景故障。其核心创新在于引入弃权机制，当证据不足时不强行归因，避免错误诊断。其代价是并行配置的运行开销较大。

### 2.5 基准评测与综述

基准评测与综述路线旨在解决现有评测仅关注结果而忽视推理过程的问题，提供因果过程监督、多数据集基准及领域全景梳理，指导方法研发。Goal-Driven Survey（Fang et al., 2025, P2）提出基于目标驱动的 RCA 综述，通过七目标分类法系统分析 RCA 研究。该综述定义了 RCA 的核心挑战、基本权衡和形式化框架，包括多模态数据、鲁棒性、自适应学习、实时性能、可解释性、多粒度和可操作性。其核心创新在于从目标视角组织相关工作，揭示了不同方法在特定目标上的优劣。

OpenRCA 2.0（Fang et al., 2026, P23）提出从结果标签转向因果过程监督的评测基准，构建包含推理轨迹的评估框架。该工作揭示了现有基准仅关注最终答案正确性的缺陷，通过引入因果过程评估，指导 LLM 智能体在 RCA 任务中的推理质量提升。OpenRCA 2.0 利用故障注入构建标注数据，但重点在于评估智能体的推理过程而非仅结果。其核心创新在于定义因果过程监督指标，如边缘 F1，以衡量推理的准确性。其代价是评估过程较为复杂。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

领域共识认为，微服务架构的复杂性使得传统基于规则或单一模态的 RCA 方法失效，必须结合多模态可观测性数据进行联合分析。这一共识在多个基准上被反复验证：EventADL 在 Event Data 基准上取得的 100% Top-3 准确率和 90% F1 分数，以及 Multimodal Diagnostic Framework 在六个云系统基准上的领先性能，均证明了多模态融合的有效性（支撑证据：P13、P8）。然而，该共识的边界在于，多模态融合并非万能，若模态间存在严重的时间粒度不匹配或语义冲突，融合效果可能受限。

与此相关的另一个共识是，大语言模型（LLM）及其智能体范式已成为 RCA 研究的主流方向，但在处理复杂因果推理时仍存在幻觉和深度不足的问题，需要结构化约束或图增强技术辅助。OpenRCA 2.0 显示，11 个前沿 LLM 在过程级指标上的平均 F1 仅为 34.1%，Exact Match 为 20.7%，表明纯 LLM 推理在复杂因果链上仍易出错（支撑证据：P23）。GALA 和 PRAXIS 通过引入图增强和程序依赖图，显著提升了推理深度和准确性，验证了结构化约束的必要性（支撑证据：P24、P5）。

### 3.2 观点分歧

LLM 在 RCA 中的角色是主导推理还是语义辅助，是领域内的主要分歧。观点 A 认为 LLM 应作为核心推理引擎，通过多智能体协作模拟人类 SRE 的假设-验证过程，代表方法如 OpsAgent 和 TopoEvo。观点 B 认为 LLM 仅用于解析非结构化日志和生成报告，因果推断由专用算法完成，代表方法如 StableRCA 结合 LLM 解释。现有证据偏向观点 B 在准确性上更稳定，StableRCA 在 50% 图损坏情况下仍保持竞争力，而基于 LLM 的方法在过程级指标上表现较弱（支撑证据：P18、P23）。然而，观点 A 在可解释性和处理非结构化数据上更优，OpsAgent 生成的可审计诊断轨迹更符合 SRE 的信任需求（支撑证据：P3）。这一分歧的背后，是 LLM 因果推理能力与统计模型鲁棒性之间的根本权衡。

因果图的来源是数据驱动学习还是已知拓扑/图无关，是另一个关键分歧。观点 A 主张从观测数据中学习因果图，以捕捉动态依赖关系，代表方法如 CCLH 和 HyperODE-RCA。观点 B 主张利用已知服务依赖图或采用图无关的局部因果推断，以提高鲁棒性和效率，代表方法如 GALA 和 StableRCA。在静态拓扑下，观点 A 性能更优，CCLH 在 Tianchi AIOps 基准上优于 MicroRCA；在动态或图错误场景下，观点 B 更鲁棒，StableRCA 在 50% 图损坏情况下仍保持竞争力（支撑证据：P4、P18）。这一分歧的根源在于，动态拓扑下的因果图学习缺乏理论保证，且实时学习计算成本高，难以在生产环境中大规模部署。

### 3.3 其他开放问题

最紧迫的工程问题是降低计算开销与实现实时诊断。多智能体框架和复杂因果发现算法通常伴随高延迟和高计算成本，难以满足生产环境实时性要求。SpecRCA 通过路径并行性和蒸馏小模型，显著降低了推理延迟，但代价是蒸馏过程需要高质量的大模型教师数据（支撑证据：P7）。PRIM 通过元学习避免显式因果发现的高成本，但元学习训练需要大量模拟数据（支撑证据：P14）。研究路径包括轻量级模型微调、并行化推理以及边缘计算部署。

最根本的研究问题是处理潜在混淆变量与不完整因果信息。真实云系统中存在大量未观测变量，传统因果充分性假设不成立。StableRCA 通过局部马尔可夫毯估计区分真实根因与下游效应，但对变量数量敏感（支撑证据：P18）。NetCause 通过反事实学习区分因果相关故障与仅时空接近的故障，但依赖已知拓扑（支撑证据：P21）。研究路径包括使用偏祖图（PAGs）、反事实学习以及基于马尔可夫边界的局部因果推断。

已知—争议—未知认知图谱显示，多模态融合和 LLM 智能体范式是已知的主流方向，LLM 角色和因果图来源是主要争议，动态拓扑下的实时因果发现、并发多故障分离以及代码级细粒度定位的自动化是未知领域。发展趋势将依赖于多模态对齐技术的成熟、LLM 因果推理能力的增强以及动态拓扑适应机制的创新，最终实现从“症状检测”到“自动修复”的闭环。

## 4. 总结与展望

云系统根因分析已从简单的异常检测演变为复杂的因果智能体系统，其核心矛盾在于微服务故障传播的复杂性与传统规则/统计方法的局限性之间的张力。研究者们尝试了从统计相关性到因果推断，再到 LLM 智能体推理的多种路线，但核心瓶颈仍在于如何在动态、噪声环境下实现鲁棒的因果推理与实时诊断，同时保持可解释性与自动化闭环。这一瓶颈回扣了第 1 章提出的核心问题：在动态、多模态且存在潜在混淆变量的云系统环境中，构建具备因果推理能力与自我进化机制的智能体系统，实现从故障症状到代码级根因的可解释、实时且鲁棒的定位与闭环修复。

未来可能突破的方向包括：增强 LLM 代理的因果推理能力与证据接地，通过引入结构化因果图约束、过程级监督评估（如 OpenRCA 2.0）以及检索增强生成（RAG）机制来确保诊断结论基于可观测证据；提升多模态数据融合与跨模态对齐效率，通过残差连接结构、超图学习以及时间序列与文本嵌入空间的显式对齐技术解决模态不匹配问题；实现拓扑感知与动态适应的根因定位，通过拓扑感知的自进化多智能体框架、动态阈值学习算法以及基于因果图的在线更新机制应对动态拓扑变化。对于进入该领域的研究者，最值得做的一件事是构建一个统一的动态拓扑基准，并在该基准上公平比较 LLM 智能体与因果推断方法在过程级指标上的表现，以解决当前评测体系中缺乏动态拓扑验证的缺陷。
