## 导读

大语言模型（LLMs）在广泛部署中面临越狱攻击（Jailbreak Attacks）威胁，攻击者通过构造恶意提示绕过安全对齐，诱导模型生成有害内容。早期防御依赖静态输入过滤或训练对齐，但面对自适应攻击时存在高误报率与漏检问题，难以满足实时交互需求。随着研究深入，范式从“输入过滤”转向“动态监控”与“内部表征利用”，核心挑战演变为在低延迟与低误报率约束下平衡安全拦截率与用户体验。检索增强防御（RAD）通过免重训练更新应对新攻击，解码轨迹检测利用隐藏状态实现实时拦截，生产级分类器则通过级联架构降低计算开销。各路线在表示质量、适应效率与计算成本间做出不同取舍，形成当前多元并存的方法格局。本综述梳理这条从静态过滤到动态轨迹的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

大语言模型的安全部署核心在于抵御越狱攻击，即攻击者通过修改输入以隐藏恶意意图，诱导模型生成违规内容。这一问题的形式化可定义为：在给定 $N$-way $K$-shot 的提示分布下，防御系统需最小化攻击成功率（ASR），同时保持良性查询的误报率（FRR）在可接受范围内。早期研究将问题简化为二分类任务，即判断输入是否有害，但忽略了攻击者的自适应性与多轮交互中的上下文依赖。随着攻击手段从显式恶意指令演变为编码混淆、多轮对话等隐式策略，单一静态过滤器的局限性暴露无遗，问题定义逐渐从“如何拦截有害文本”深化为“如何在资源受限下维持动态安全边界”。

子问题之间存在严格的依赖关系。内部表征的可解释性与提取是解码轨迹检测的前提，若无法准确捕捉隐藏状态中的风险信号，实时监控便无从谈起。计算开销的优化依赖于级联架构的设计，而级联架构的有效性又取决于轻量级探针的精度。若不能解决自适应攻击下的鲁棒性，动态更新机制将成为必要补充。这种依赖结构决定了方法演进的路径：先解决信号提取，再优化计算效率，最后实现动态适应。范式边界方面，基于内部表征的方法（如隐藏状态监控）仅适用于开源权重模型，而基于外部文本的方法（如检索增强）则具有通用性，但受限于数据库覆盖率。

2023 至 2024 年是领域的奠基期，Self-Reminder 与 Llama Guard 3 确立了静态过滤的基线。Self-Reminder 通过在查询中追加对齐指令强化模型责任感，揭示了提示工程在安全对齐中的局限性；Llama Guard 3 作为独立安全守护模型，代表了静态输入过滤的主流范式，但独立评估显示其在面对混淆越狱提示时存在漏检。这一时期的方法假设攻击模式相对固定，缺乏对内部状态的利用，导致在自适应攻击下 ASR 显著上升。

2025 年成为关键转折点，研究范式从“单一检测”转向“系统级权衡”。Constitutional Classifiers 确立了宪法分类器方向，但暴露了 23% 的计算开销问题，限制了部署可行性。同年，AdaSteer 与 TrajGuard 引入隐藏状态轨迹，解决了输入级检测失效后的实时监控空白。TrajGuard 发现越狱攻击会导致隐藏状态从良性区域向有害区域漂移，利用这种漂移延迟特性实现了低延迟的中断机制。这一转折标志着领域从学术探索进入工程落地阶段，重心转向安全-效用权衡。

2026 年，方法进一步细化与融合。RAD 提出检索增强防御框架，通过动态更新数据库实现免重训练更新，解决了先前 RAG 方法缺乏可控性的问题。Constitutional Classifiers++ 优化了宪法分类器架构，结合线性探针与外部分类器，将计算开销降低 40 倍以上。Borrowed Strength 则揭示了自检查防御的内在脆弱性，为防御机制改进提供了理论依据。当前形态下，领域聚焦于对抗分布偏移、白盒自适应攻击的鲁棒性，以及黑盒 API 与开源模型间的防御成本平衡。

**如果用一个核心问题概括该领域，那便是：如何在保证实时交互低延迟与低误报率的工程约束下，构建能够抵抗自适应分布偏移攻击的动态安全-效用平衡机制。**

## 2. 方法体系

- 2023：Self-Reminder——奠定该领域方法基线

- 2024：AdaSteer——利用内部表示作为自适应防御器

- 2025：Constitutional Classifiers——确立宪法分类器方向

- 2025：TrajGuard——流式隐藏状态轨迹检测框架

- 2025：RePD——检索增强提示分解过程防御

- 2026：RAD——检索增强防御框架

- 2026：Constitutional Classifiers++——优化宪法分类器架构

- 2026：Borrowed Strength——分析自检查防御脆弱性

这条时间线勾勒了该领域方法演进的代表性节点：从 2023 年的 Self-Reminder 奠定该领域方法基线，经 2024 年 AdaSteer 的推进，到 2026 年的 RAD 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 生产级分类器

生产级分类器路线起源于 2023 年的 Self-Reminder，该方法通过在用户查询中追加对齐指令来强化模型避免生成有害内容的责任感，是一种无需训练的推理时防御方法（Self-Reminder, 2023）。作为早期轻量级防御基线，它揭示了提示工程在安全对齐中的局限性，为后续更复杂的分类器架构提供了对比参照。2024 年，Llama Guard 3 基于 Llama 3 构建独立安全守护模型，用于检测输入提示是否安全，若标记为不安全则直接拒绝响应（Llama Guard 3, 2024）。它代表了静态输入过滤的主流范式，虽然部署简单，但独立评估显示其在面对混淆越狱提示时存在漏检，且结合后处理过滤会增加端到端延迟。

2025 年，Constitutional Classifiers 由 Anthropic 提出，通过训练分类器识别有害内容，但在生产环境中面临 23% 的计算开销和 0.38% 的拒绝率，限制了其部署可行性（Constitutional Classifiers, 2025）。该工作确立了宪法分类器作为对抗通用越狱的重要方向，但也暴露了计算成本与鲁棒性之间的权衡问题，激发了后续对高效级联架构的研究。2026 年，Constitutional Classifiers++ 优化了宪法分类器架构，采用交换分类器评估模型输出在对应输入上下文中的安全性，并结合级联筛选和线性探针降低计算成本（Cunningham et al., 2026, P1）。该系统通过两阶段级联和探针-分类器集成，将计算开销降低 40 倍以上，同时保持对通用越狱的高鲁棒性，实现了生产级部署的可行性。其核心取舍是增加了系统复杂性，且探针性能依赖于特定的训练技巧如加权损失。与检索增强防御相比，生产级分类器更侧重于计算效率与部署可行性，而 RAD 则侧重于动态更新能力。

### 2.2 解码轨迹检测

解码轨迹检测路线起源于 2024 年的 AdaSteer，该方法利用对齐 LLM 内部表示作为自适应越狱防御器，通过探测或引导与输入提示相关的隐藏状态来区分良性与对抗性输入（AdaSteer, 2024）。这类基于模型内部信号的方法虽然利用了内部表征，但通常依赖高维几何分数，解释性差且单独使用时误报率较高，为后续轨迹监控提供了理论基础。2025 年，TrajGuard 提出流式隐藏状态轨迹检测框架，通过监控解码过程中隐藏状态的几何分数变化来实时量化风险（Liu et al., 2026, P2）。该方法发现越狱攻击会导致隐藏状态从良性区域向有害区域漂移，利用这种漂移延迟特性实现了低延迟的中断机制，填补了输入级检测失效后的实时监控空白。

TrajGuard 的核心设计思路是利用越狱攻击导致隐藏状态从良性区域向有害区域漂移的特性，通过监控解码过程中的几何分数变化来量化风险。关键技术模块包括 SGS（流式几何监控）作为第一道防线，利用轻量级向量计算筛选潜在风险段，以及 PAIR-Judge 作为第二道防线，由安全对齐 LLM 进行语义裁决。主要改进点在于采用粗到细的层级架构，仅在 SGS 检测到持续异常时触发高成本的语义裁决，从而在保持低延迟的同时确保高精度。核心取舍是依赖参考分布的准确性，且在高度专业化领域可能需要定期重新校准中心点。与生产级分类器相比，解码轨迹检测更侧重于实时性与低延迟，但仅适用于开源权重模型，无法直接应用于黑盒 API。

### 2.3 检索增强防御

检索增强防御路线起源于 2025 年的 RePD，该方法通过检索增强提示分解过程防御越狱攻击，从数据库中检索越狱模板并构建上下文演示来分离有害查询（RePD, 2025）。作为早期 RAG 防御代表，它展示了利用外部知识库增强防御能力的潜力，但缺乏对安全-效用权衡的精细控制，为后续 RAD 框架的可控性设计提供了改进空间。同年，EDDF 从输入提示中识别越狱策略，检索预建数据库中的相似策略，并基于这些示例条件化模型以分类提示安全性（EDDF, 2025）。该方法强调了策略识别在 RAG 防御中的关键作用，但同样面临更新机制不够灵活的问题，促使研究者探索更动态的数据库更新策略。

2026 年，RAD 提出检索增强防御框架，通过检索已知攻击示例并结合集成分类来检测越狱尝试，支持通过添加新示例实现免训练更新（RAD, 2026, P4）。RAD 引入了可调决策阈值以平衡安全性与实用性，解决了先前 RAG 方法缺乏可控性的问题，成为应对新型越狱攻击的高效自适应防御方案。其核心设计思路是利用外部数据库存储已知攻击示例，通过检索相似攻击并结合集成分类器进行风险判定，从而避免模型重新训练。关键技术模块包括动态更新的攻击示例数据库、基于相似度或策略似然的重排序机制，以及用于最终概率计算的加权投票或多数投票集成策略。核心取舍是依赖数据库的覆盖范围，虽然通过添加新示例可应对新攻击，但初始数据库的质量直接影响防御效果。与解码轨迹检测相比，检索增强防御具有通用性，可应用于黑盒 API，但受限于数据库覆盖率与检索延迟。

### 2.4 自检查机制突破

自检查机制突破路线起源于 2026 年的 Borrowed Strength，该方法分析自检查防御的内在脆弱性，揭示编码与搜索组合攻击如何绕过模型自我评估机制（Zhang et al., 2026, P3）。其核心设计思路是通过将有害内容编码为代码形式，并利用搜索策略生成多个候选响应，从而绕过模型自我评估的检测机制。关键技术模块包括代码编码转换过程，将有害查询转化为看似无害的代码片段，以及 Best-of-N 搜索机制，从多个生成结果中选择最可能通过自检查的响应。主要改进点在于结合了编码混淆与搜索优化，利用了自检查机制对代码上下文理解不足以及搜索空间中的概率偏差。核心取舍是攻击过程需要多次生成和评估，增加了计算开销，且依赖于目标模型对代码语义的误解。该方法在领域进展中定位为一种揭示防御漏洞的实证工具，为改进自检查机制提供了理论依据，促使研究者关注模型在复杂上下文下的自我评估能力。与其他防御路线不同，自检查机制突破侧重于揭示现有防御的局限性，为防御机制改进提供反面参照。

### 2.5 跨任务与多领域应用

当前方法主要聚焦于文本模态的越狱防御，但在多模态、多轮对话等场景下的应用仍有限。生产级分类器与解码轨迹检测主要适用于开源权重模型，而检索增强防御具有通用性，可应用于黑盒 API。自检查机制突破则揭示了模型在复杂上下文下的自我评估能力不足，为多轮对话防御提供了启示。未来，随着多模态嵌入空间联合建模技术的发展，防御机制将扩展至图像、音频等多模态输入，实现跨模态攻击检测。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

静态输入过滤或单一安全对齐不足以应对自适应越狱攻击，需要结合动态监控或多层防御机制，这一共识在 RAD、TrajGuard、CC++ 等工作中得到共同支持（支撑证据：P1、P2、P4）。防御系统必须平衡攻击拦截率（ASR）和良性查询误报率（FRR），单一指标优化会导致系统不可用或不安全，TrajGuard 在 HarmBench 上 ASR 0.02-0.10 且 FPR 1.50% 的表现验证了这一权衡的必要性（支撑证据：P2）。利用 LLM 内部表征（如隐藏状态、激活值）进行防御比仅依赖外部文本特征更具鲁棒性和效率，能捕捉输入层面的伪装，AdaSteer 与 TrajGuard 的工作支持了这一观点（支撑证据：P2）。计算效率是生产级防御的关键约束，级联架构（轻量级初筛+高精度复核）是降低平均计算成本的有效范式，CC++ 将计算开销降低 40 倍以上验证了这一范式（支撑证据：P1）。防御机制需要具备动态更新能力，以应对新出现的攻击策略，无需重新训练整个模型，RAD 的免重训练更新机制支持了这一共识（支撑证据：P4）。解码过程中的实时监测（Streaming Detection）比生成后的后处理（Post-hoc）能更早发现异常，降低潜在危害并优化延迟，TrajGuard 的流式检测机制支持了这一观点（支撑证据：P2）。

### 3.2 观点分歧

内部表征法与外部检索法在鲁棒性与通用性上存在取舍。内部表征法（TrajGuard, AdaSteer）利用隐藏状态轨迹，精度高、延迟低，但仅限开源模型；外部检索法（RAD, EDDF）利用 RAG 机制，通用性强、可动态更新，但依赖数据库质量，延迟略高。现有证据偏向内部表征法在开源模型上的性能优势（TrajGuard ASR 0.02-0.10 vs 基线 0.20+），但 RAD 在应对未知攻击时的动态更新能力是内部表征法难以比拟的。哪种实验能定输赢：在黑盒 API 场景下的端到端防御效果对比。这一分歧的背后，是另一个更根本的争论：实时中断（Streaming）与后处理（Post-hoc）在安全性与系统复杂度上的平衡。实时中断（TrajGuard）在解码过程中监控并中断，能阻止有害内容生成，降低潜在危害；后处理（Llama Guard 3, CC++）在生成完成后检测，实现简单，但无法阻止有害内容已生成的事实。证据偏向实时中断在降低潜在危害方面的优势，但后处理在系统稳定性与兼容性上更优。哪种实验能定输赢：在高风险场景（如实时对话）下的用户感知安全性与系统崩溃率对比。

### 3.3 其他开放问题

最紧迫的工程问题是计算稀疏性优化，昂贵语义检查（如 LLM-as-Judge）导致高延迟，未来需降低防御机制的计算成本，难点在于保持检测精度的同时减少调用频率，潜在路径包括基于风险信号的稀疏触发机制与轻量级探针。最根本的研究问题是 OOD 攻击的理论鲁棒性，现有静态防御在面对分布外（OOD）攻击时鲁棒性不足，未来需开发能实时适应新型攻击模式的动态防御，难点在于实时计算开销与检测精度的平衡，潜在路径包括基于内部状态轨迹的在线监测。已知—争议—未知认知图谱显示，静态过滤不足、安全-效用权衡必要、内部表征优势为已知共识；内部表征 vs 外部检索、实时中断 vs 后处理为争议焦点；多模态扩展、黑盒 API 防御限制、OOD 攻击理论保证为未知领域。发展趋势指向系统级安全-效用权衡与动态自适应防御。

## 4. 总结与展望

大语言模型越狱防御的核心矛盾源于攻击者的自适应性与防御系统的静态性，早期静态过滤在面临编码混淆和多轮攻击时存在显著漏检，促使研究转向内部表征利用与动态监控。生产级部署要求解决计算开销与检测精度的矛盾，级联架构成为主流；自适应攻击迫使防御机制具备免重训练的动态更新能力。核心瓶颈在于如何在保证实时交互低延迟与低误报率的工程约束下，构建能够抵抗自适应分布偏移攻击的动态安全-效用平衡机制，这一瓶颈贯穿从静态过滤到动态轨迹的整个演进过程。

未来可能突破的方向包括多模态越狱防御与动态自适应防御机制。多模态越狱防御需扩展至图像、音频等多模态输入，难点在于不同模态间语义对齐与跨模态攻击检测，潜在路径包括多模态嵌入空间联合建模，RAD 与 TrajGuard 的工作共同指向了这一方向。动态自适应防御机制需开发能实时适应新型攻击模式的动态防御，难点在于实时计算开销与检测精度的平衡，潜在路径包括基于内部状态轨迹的在线监测，TrajGuard 与 CC++ 的工作共同指向了这一方向。对进入者最值得做的一件事是，在黑盒 API 场景下构建统一的端到端防御效果对比基准，以解决内部表征法与外部检索法在通用性上的分歧，为生产级部署提供实证依据。
