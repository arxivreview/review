## 导读

云边资源调度旨在动态分配计算、存储与网络资源，其核心挑战在于平衡性能、成本与能耗的多重约束。早期研究依赖启发式规则，思路简洁却难以应对非平稳工作负载引发的服务等级目标（SLO）违规。随着深度学习与强化学习（RL）的引入，领域实现了从静态配置到数据驱动自适应决策的范式转变，但黑盒特性阻碍了运维信任。大语言模型（LLM）的介入进一步将调度重构为语义理解与可解释推理问题，弥补了泛化能力不足。当前研究聚焦于“云-边-端-空”连续体下的可持续计算与隐私保护，形成多元并存的方法格局。本综述梳理这条从数值优化到语义协同的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

云边资源调度的起源可追溯至云计算对海量异构资源高效利用的需求，其初始目标是在静态、同质化环境中通过启发式规则（如 First-Fit）实现任务到资源的最优映射。这一阶段的核心假设是工作负载平稳且资源属性固定，算法设计侧重于计算复杂度与最坏情况性能的可预测性。然而，随着多租户环境与动态微服务的普及，静态预配模型逐渐失效，资源碎片化与利用率低下成为主要痛点。问题形式化通常定义为：在给定资源集合 $R$ 与任务集合 $T$ 下，寻找映射函数 $f: T \rightarrow R$，使得目标函数 $J = \alpha \cdot L + \beta \cdot C + \gamma \cdot E$ 最小化，其中 $L$、$C$、$E$ 分别代表延迟、成本与能耗，且需满足 SLO 约束 $L_i \leq \tau_i$。

子问题之间存在严格的依赖关系：底层资源感知与预测是上层调度决策的前提，SLO 保障依赖于对异构资源碎片化的有效治理，而可解释性与隐私约束则作为全局硬约束贯穿始终，限制了局部最优解的可行性。例如，任务卸载决策（Task Offloading）不仅取决于计算能力，还受限于带宽成本与数据主权，这使得单一维度的优化往往导致其他指标恶化。范式边界由此从单纯的“资源分配”扩展为“约束满足下的多目标决策”，涵盖了从边缘实时响应到云端长期规划的全栈协调。

2016-2018 年间，领域处于奠基期，研究主要围绕度量学习与原型网络在资源分类中的应用，但尚未形成统一的调度框架。2020 年前后，Autopilot 等系统引入机器学习进行垂直伸缩，标志着从静态规则向数据驱动自适应决策的转折，初步解决了动态资源分配问题。2021-2022 年，Orca 与 vLLM 通过迭代级连续批处理与 PagedAttention 机制，解决了 LLM 推理中的显存碎片化问题，确立了高效内存管理标准，为后续 AI 工作负载调度奠定了基础。

2023-2024 年，H-MAS 等分层多智能体框架出现，针对多租户 LLM 服务的非平稳负载，通过轻量级预测与运行时反馈动态平衡 SLO 违规风险与吞吐量。这一时期，强化学习（RL）成为主流，但其黑盒特性导致运维信任缺失，且泛化能力受限于训练分布。2025-2026 年，LLM 的爆发成为第二个关键转折节点，DCcluster-Opt 与 COMLLM 等工作将调度决策重构为语言条件序列决策，利用语义理解实现拓扑无关的通用化决策，同时引入碳感知与隐私约束，推动领域进入可持续计算阶段。

**如果用一个核心问题概括该领域，那便是：在动态、异构且受隐私与碳足迹约束的云边连续体中，如何实现兼顾 SLO 合规、成本效率与决策可解释性的自适应资源编排。**

## 2. 方法体系

- 2010：First-Fit/Best-Fit——基于启发式规则的资源分配算法，奠定领域基线

- 2020：Autopilot——基于机器学习的垂直伸缩系统，实现动态自适应

- 2022：Orca——首创迭代级连续批处理调度机制，提升 GPU 利用率

- 2023：vLLM——引入 PagedAttention 机制，解决显存碎片化问题

- 2024：H-MAS——分层多智能体调度框架，平衡 SLO 与吞吐量

- 2025：DCcluster-Opt——基于多智能体 LLM 框架的地理分布式数据中心调度基准

- 2025：COMLLM——基于多轮推理 LLM 的协作优化框架，实现拓扑无关卸载

- 2026：SAIR——基于上下文强化学习的多阶段 ML 管道自动伸缩系统

这条时间线勾勒了该领域方法演进的代表性节点：从 2010 年的 First-Fit/Best-Fit 奠定该领域方法基线，经 2020 年 Autopilot 的推进，到 2026 年的 SAIR 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 云资源智能调度

云资源智能调度的早期工作基于静态、同质化假设，依赖 First-Fit 等启发式算法，受限于算力与理论成熟度，无法处理动态非平稳负载。Autopilot（2020）通过机器学习预测资源需求并自动调整容器限制，实现了从静态配置到动态自适应的转变，但其核心假设是负载具有周期性，在突发流量下预测误差较大。针对这一局限，P1 提出基于 Google Cluster Data 的预测性集群负载分配模型，利用 CPU、内存及 I/O 的历史模式预测未来需求，克服了纯理论模型与实际部署间的差距。P2 进一步引入连续迁移学习与深度强化学习，解决 HPC 集群在动态环境中的适应性差问题，通过迁移学习降低新环境下的训练成本，其成功依赖于节点亲和性约束的稳定性。

随着 LLM 的引入，P30 利用 LLM 作为特征提取器与预测探针，摒弃手工特征工程，直接对复杂系统状态进行语义理解，显著提升了资源分配的环境友好性。P6 构建的 DCcluster-Opt 框架则通过 LangGraph 编排六个专业化 LLM 智能体，实现了从高层策略到低层执行的可审计控制，打破了传统 RL 黑盒模型的局限。P28 提出的 MARA 框架利用流匹配技术预测训练任务的剩余批次需求，结合多智能体强化学习进行节点分配，解决了传统调度器忽略任务剩余工作量导致的资源浪费问题。这些方法从数值优化转向语义协同，核心取舍在于以 LLM 的推理开销换取可解释性与泛化能力。

### 2.2 边缘任务卸载优化

边缘任务卸载优化旨在平衡延迟、能耗与带宽成本，早期方法多采用静态规则或简单 RL。P13 设计基于 TimeGNN 增强的混合动作多智能体强化学习框架，将时间序列预测嵌入 MARL 状态空间，使智能体能感知边缘节点电池约束与间歇性能源特性，显著延长了服务可用性。P25 提出多时间尺度潜在动作 DRL 方法，通过时间尺度分离处理快速变化的边缘负载与缓慢变化的云资源分配，解决了单一时间尺度 DRL 在异构网络中的收敛困难问题。

P19 提出的 COMLLM 框架通过语义状态序列化将动态 MEC 决策重构为语言条件序列决策问题，整合 GRPO 训练与前瞻协同模拟，使策略能感知未来拥塞效应，实现了拓扑无关的通用化决策。该方法依赖 LLM 的语义理解能力处理复杂网络状态，虽增加了推理开销，但显著提升了在动态拓扑变化环境下的卸载效率与鲁棒性。P21 则探索基于 LLM 与思维链的无人机辅助物流调度框架，将复杂的 UAV 路由与 MEC 任务卸载问题转化为 LLM 可处理的语义推理任务，支持动态重调度。这些方法与云资源调度路线互补，前者聚焦实时性敏感的边缘层，后者侧重长期成本与能耗优化。

### 2.3 边缘 AI 推理编排

边缘 AI 推理编排关注模型分区、混合并行及服务编排，旨在满足 QoE/SLO 约束并提升推理效率。Orca（2022）首创迭代级连续批处理调度机制，允许新请求动态加入正在进行的批次，消除了流水线气泡，大幅提升了 GPU 利用率。vLLM（2023）引入 PagedAttention 机制，将 KV-Cache 管理为非连续页面，解决了显存碎片化问题，确立了边缘与云端 LLM 服务的高效内存管理标准。

P7 构建的 EPARA 系统针对不同任务类型采用请求级与服务级混合分配策略，通过资源节省的信息同步机制降低通信压力，提升了边缘异构硬件下的推理 Goodput。P11 提出 QoE 感知混合并行系统，将 QoE 指标直接纳入并行策略优化目标，而非仅优化吞吐量，确保了边缘 AI 服务的个性化体验。P24 提出的 PLAIground 框架将模型选择视为运行时优化问题，根据实时卫星覆盖、带宽波动与能量预算动态选择最合适的 AI 模型，解决了连续体环境中条件持续变化导致的 SLO 违规问题。这些方法继承了 vLLM 的内存管理思想，并进一步引入语义本体与动态模型切换，以应对边缘环境的极端异构性。

### 2.4 云边预测性编排

云边预测性编排聚焦于通过时间序列预测与生成式模型实现前瞻性资源管理，解决资源冷启动问题。P9 构建结合 CNN-LSTM 预测与 MADRL 决策的框架，将预测模块与决策模块解耦，使智能体能利用未来信息优化长期奖励，克服了传统反应式调度的滞后性。P23 开发零接触预测性编排系统，利用神经架构搜索生成优化模型架构，实现了从数据获取到模型部署的全自动化，解决了云边环境中异构基础设施导致模型泛化能力差的问题。

P22 提出用于分布式计算系统的生成式马尔可夫建模框架，统一表示资源异构性、随机可用性与高维系统状态，通过稀疏分解使高维模型在模拟、推理与策略学习中保持可处理性。该方法为志愿者计算与边缘连续体系统提供了理论基础，使优化算法能更准确地评估不同调度策略在动态基础设施下的长期影响。预测性编排与无服务器资源管理路线紧密关联，前者提供前瞻状态，后者执行即时伸缩决策，二者协同以实现成本与稳定性的最优平衡。

### 2.5 无服务器资源管理

无服务器资源管理针对冷启动延迟与资源利用率矛盾，采用自适应伸缩、槽位生存预测及事件驱动机制优化 GPU 及容器资源分配。Clipper（2021）引入自适应批处理机制，通过动态调整批大小来平衡吞吐量与延迟，奠定了 ML 推理服务中资源动态调度的基础范式。LIBRA（2021）定义成本无差异点，根据请求到达率的移动平均与偏差动态划分流量，有效平衡了冷启动延迟与长期运行成本。

P18 设计基于槽位生存预测与事件驱动生命周期控制的自适应无服务器资源管理系统，利用滑动窗口聚合技术预测容器槽位的生存时间，动态调整空闲持续时间与请求等待策略，实现了高频请求场景下的亚秒级响应。P14 开发的 SAIR 系统利用 LLM 在上下文中学习历史经验并生成结构化 JSON 动作，无需离线训练即可处理动态瓶颈迁移与跨阶段耦合问题，实现了零样本自适应伸缩。P12 提出面向无服务器环境中多智能体协作推理的自适应 GPU 资源分配策略，将多智能体协作视为资源调度问题，解决了传统静态分配无法适应动态工作负载的问题。这些方法从被动响应转向主动预防，核心取舍在于以预测精度换取冷启动延迟的降低。

### 2.6 分布式协同调度

分布式协同调度探索去中心化及异构分布式系统中的资源调度，包括隐私感知编排、多目标优化及用户辅助协同推理。P10 提出的 IslandRun 系统定义计算岛概念，通过隐私分数、信任分数与成本指标构建多目标路由算法，在信任边界转换时应用隐私保护变换函数，解决了数据主权与性能成本之间的固有张力。P16 设计去中心化多智能体深度强化学习框架，将问题建模为去中心化部分可观测马尔可夫决策过程，开发轻量级 Actor-Critic 架构，仅依赖 NumPy 实现，便于在资源受限边缘设备部署。

P4 提出计算中心网络中机器学习与 CPU 调度协同优化方法，利用分布式算法平衡节点间计算负载，将 ML 训练过程与 CPU 资源调度联合优化，解决了传统方法忽略计算负载动态变化的问题。P29 提出用户辅助的协同分布式推理系统，将推理计算在专用服务器与用户设备间划分，充分利用用户闲置资源，缓解了专用服务器容量不足的问题。这些方法与边缘 AI 推理编排路线互补，前者侧重跨信任域的安全与公平，后者侧重单域内的效率与 QoE，共同构成了云边连续体的完整调度图景。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

传统启发式算法在处理动态、异构及多租户云环境时已显不足，无法有效应对实时工作负载变化，这一共识在约 10 篇论文中得到共同支持。混合架构（结合多种 AI/ML 技术，如 DRL+LLM 或 CNN+LSTM）在性能、鲁棒性及部署就绪度上通常优于单一方法，约 8 篇论文共同支持这一观点。LLM 的引入显著提升了调度系统的可解释性、语义理解能力及对未知拓扑的泛化能力，弥补了 DRL 的黑盒缺陷，约 7 篇论文共同支持。边缘计算环境在降低延迟和处理实时敏感任务方面具有不可替代的优势，但受限于资源碎片化，需与云端协同，约 9 篇论文共同支持。多目标优化（同时考虑延迟、成本、能耗、SLO）是现实场景的必然要求，单一指标优化会导致系统整体效率下降，约 11 篇论文共同支持。预测性调度（Proactive/Predictive Scheduling）优于反应式调度，通过提前预测资源需求可显著减少冷启动和 SLO 违规，约 6 篇论文共同支持。AI 工作负载（特别是 LLM 推理）对调度系统提出了新挑战，如显存管理、批次动态调整及长尾延迟，需要专用调度策略，约 5 篇论文共同支持。可持续计算（碳感知、能效优化）正从边缘议题转变为核心调度约束，尤其在地理分布数据中心中，约 4 篇论文共同支持。

### 3.2 观点分歧

LLM 作为决策代理的实时性与边缘适用性存在显著分歧。观点 A 认为 LLM 语义理解能力强，适合复杂拓扑与未知任务，应作为核心决策引擎（代表：COMLLM, DCcluster-Opt）；观点 B 认为 LLM 推理延迟高，不适合毫秒级边缘卸载，应仅用于离线规划或特征提取，实时决策仍依赖轻量级 DRL（代表：Hybrid Predictive-Heuristic, TimeGNN-Augmented MARL）。现有证据偏向观点 B 在边缘实时场景的可行性，COMLLM 虽在仿真中表现良好，但未在真实高并发边缘节点验证毫秒级响应。观点 A 在离线/准实时数据中心调度中证据更强。未定论原因在于缺乏统一的、包含真实网络抖动与硬件延迟的 Sim-to-Real 评测基准，无法准确量化 LLM 推理开销对端到端 SLO 的影响。

预测性调度与反应式调度的主导权也是另一大分歧。观点 A 主张预测性调度应为主导，通过提前预留资源降低冷启动与 SLO 违规（代表：CNN-LSTM Hybrid, Zero Touch Predictive Orchestration）；观点 B 认为预测模型在突发负载下滞后且误差大，反应式调度更稳健，应作为兜底机制（代表：LIBRA, Slot-Survival Prediction）。证据偏向混合模式，纯预测在极端突发下失效，纯反应在长期成本上劣势。Hybrid Proactive-Predictive Framework 在仿真中总奖励最高，支持混合观点。未定论原因在于预测误差与反应延迟之间的最优切换阈值缺乏理论指导，高度依赖具体工作负载特征，难以通用化。

### 3.3 其他开放问题

最紧迫的工程问题是轻量化模型与低延迟推理，需解决深度学习模型在实时云调度中因计算开销大导致的推理延迟问题，通过模型剪枝、量化及联邦学习技术，实现边缘节点上的快速本地化决策。最根本的研究问题是隐私保护与联邦学习，需在分布式边缘-云协同中解决数据集中化带来的隐私泄露风险，通过联邦学习框架实现模型参数的分布式训练与更新，避免敏感数据上传，同时保证全局模型的收敛性与预测精度。此外，Sim-to-Real 迁移与鲁棒性也是关键挑战，需缩小仿真环境与真实物理集群之间的差距，通过域随机化技术训练对硬件故障、网络抖动及测量噪声具有鲁棒性的调度策略。已知领域共识在于混合架构与预测性调度的优势，争议在于 LLM 实时性与预测-反应切换阈值，未知在于大规模生产环境的长期稳定性验证。发展趋势将指向 LLM 与 DRL 的深度融合以及 Sim-to-Real 评测体系的完善。

## 4. 总结与展望

云边资源调度已从单纯的资源分配问题演变为涵盖语义理解、隐私合规与可持续性的复杂决策系统。核心矛盾在于如何在动态、异构且受约束的环境中实现自适应资源编排，早期启发式方法因无法应对非平稳负载而失效，DRL 解决了动态性但牺牲了可解释性，LLM 弥补了语义理解与泛化缺陷但引入了推理开销。当前核心瓶颈在于 LLM 推理延迟与边缘实时性之间的张力，以及预测误差与反应延迟之间的最优切换阈值缺乏理论指导。

未来可能突破的方向包括：轻量化模型与低延迟推理，通过模型剪枝、量化及联邦学习技术实现边缘节点上的快速本地化决策（P13, P16 共同指向）；混合架构与预测-反应协同，构建预测-反应混合框架，利用预测模块提供前瞻状态，结合反应模块处理瞬时异常（P9, P14 共同指向）；隐私保护与联邦学习，通过联邦学习框架实现模型参数的分布式训练与更新，避免敏感数据上传（P10, P29 共同指向）。对进入者最值得做的一件事是构建统一的 Sim-to-Real 评测基准，包含真实网络抖动与硬件延迟，以准确量化 LLM 推理开销对端到端 SLO 的影响，从而解决当前领域最大的认知盲区。
