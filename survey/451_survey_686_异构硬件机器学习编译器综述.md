## 导读

摩尔定律失效迫使计算向 GPU、NPU 等异构硬件迁移，但软件工具链的滞后导致高性能内核开发仍高度依赖人工专家知识。早期编译器通过分离计算定义与调度策略实现自动化，却受限于搜索空间爆炸与成本模型不准，难以匹敌手写库性能。随着 Triton 等 Tile 抽象降低编程门槛，领域重心转向消除内核启动与同步开销，Mega-kernel 化成为低延迟推理的关键。近期，大语言模型（LLM）与形式化方法的引入，将问题从“搜索最优调度”重构为“生成与验证最优代码”，显著提升了跨硬件泛化能力。各路线在抽象层级、正确性保证与硬件适配性之间做出了不同取舍，形成了基础设施标准化与优化策略智能化并存的格局。本综述梳理这一从静态编译到动态智能生成的因果演进链条，为读者提供领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

异构硬件机器学习编译器的兴起，根植于硬件性能增长与软件适配能力之间的巨大剪刀差。在摩尔定律失效的背景下，CPU、GPU、NPU 及存内计算（Processing-In-Memory, PIM）等异构加速器成为提升算力的主要途径，但其指令集、内存层级与并行模型的差异，使得高性能内核开发成为一项高度专业化的工程任务。传统上，开发者需针对特定硬件手动编写 CUDA 或 OpenCL 代码，不仅耗时巨大，且难以跨平台移植，导致维护成本高昂。这一矛盾催生了对自动化编译工具链的迫切需求，旨在通过软件抽象屏蔽硬件异构性，实现“一次编写，多端部署”。

问题的形式化可归结为：给定一个张量程序（Tensor Program）$P$ 和目标硬件架构 $H$，编译器需生成一个执行计划 $\pi$，使得 $P$ 在 $H$ 上的执行性能 $Perf(P, \pi, H)$ 最大化，同时满足语义等价约束 $Sem(P) = Sem(\pi)$。这一过程涉及多个子问题的耦合：布局优化决定数据在内存中的物理排列，直接影响数据局部性；内核融合（Kernel Fusion）通过合并算子减少内存访问与启动开销；自动调度（Auto-scheduling）则搜索循环变换与并行化策略。这些子问题并非独立，而是存在严格的依赖关系——错误的布局选择会导致后续融合与调度失效，而调度策略又反过来约束了可行的布局空间。因此，编译器必须在全局视角下协调这些决策，而非孤立地优化单一环节。

范式边界在 2016-2018 年间初步确立。Halide 引入了“计算定义与调度分离”的理念，将张量操作的高层语义与底层执行策略解耦，奠定了自动调度的基础范式。随后，TVM 构建了端到端的编译栈，通过 Relay IR 和 Ansor 调度器实现了跨硬件优化，确立了静态图编译的主流地位。然而，这一范式隐含了“静态形状”与“确定性依赖”的假设，即模型结构在编译时已知且固定。当工作负载涉及动态形状或数据依赖控制流时，静态编译的局限性便暴露无遗，JIT 重编译开销成为新的瓶颈。

2020 年前后，跨域基准与 Tile 抽象的出现标志着问题定义的转折。Triton 提出基于 Tile 的编程模型，自动化处理内存合并与共享内存管理，大幅降低了 GPU 内核开发门槛。这一转变将优化粒度从循环级提升至 Tile 级，牺牲了部分底层自由度，换取了开发效率与通用性的提升。与此同时，FlashAttention 证明了特定算子的极致优化对端到端性能的关键作用，促使编译器从“通用调度”向“算子感知优化”演进。此时，问题已转变为如何在保持通用性的同时，捕获特定硬件的微观特性。

2021-2023 年，预训练模型与视觉语言模型的引入进一步改变了优化目标。随着 LLM 推理成为主流负载，动态批处理、KV Cache 管理及长序列依赖成为核心挑战。传统编译器难以处理这种运行时动态性，促使研究重心转向运行时调度与动态图编译。Torch Inductor 作为 PyTorch 2.0 的后端，通过动态字节码转换和图编译，确立了工业界高层编译的新标准。这一阶段，编译器不仅要生成代码，还需管理运行时状态，问题边界从“代码生成”扩展至“执行管理”。

2024-2025 年，LLM 与 AI for Systems 的融合成为新范式。KernelBench 等基准的引入，将评估重点从“加速比”转向“正确性与优化复杂度的权衡”。LLM 被用于生成内核代码、自动并行化及多智能体优化，其推理能力弥补了传统启发式方法在硬件知识注入上的不足。与此同时，形式化方法如 Prism 被引入，以解决 LLM 生成的语义正确性问题。这一阶段，问题定义演变为“如何在保证语义正确性的前提下，利用 AI 探索巨大的设计空间”。

2025-2026 年，领域聚焦于细粒度开销消除与新型硬件适配。Mega-kernel 化技术如 Mirage Persistent Kernel (MPK) 和 Event Tensor (ETC) 通过消除内核边界和同步屏障，解决了低延迟推理中的启动开销瓶颈。针对 AMD NPU、Qualcomm Hexagon 等新型硬件，MLIR-AIR 和 Hexagon-MLIR 构建了显式表达空间与时间结构的 IR，突破了传统线程中心模型的局限。当前形态下，编译器已演变为一个智能代理系统，集成 LLM 生成、形式化验证与动态调度，旨在实现跨异构硬件的高效、自动化部署。

**如果用一个核心问题概括该领域，那便是：如何在保证语义正确性的前提下，自动化地探索异构硬件巨大的设计空间，生成或调度出接近或超越专家手写内核性能的张量程序实现。**

## 2. 方法体系

- 2014：Halide——引入可编程调度，奠定张量编译器自动优化基础

- 2018：TVM——构建端到端编译栈，确立跨硬件优化基准

- 2019：Triton——提出 Tile 编程模型，降低 GPU 内核开发门槛

- 2022：FlashAttention——证明算子级优化对端到端性能的关键作用

- 2025：KernelBench——引入 LLM 内核生成基准，推动标准化评估

- 2025：MLIR-AIR——显式暴露空间时间结构，适配 AMD NPU 空间硬件

- 2025：Mirage Persistent Kernel (MPK)——Megakernel 化张量程序，消除内核启动开销

- 2026：TCL——基于持续学习的跨硬件优化，减少性能测量数据需求

这条时间线勾勒了该领域方法演进的代表性节点：从 2014 年的 Halide 奠定该领域方法基线，经 2018 年 TVM 的推进，到 2026 年的 TCL 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 编译器基础设施

编译器基础设施是异构硬件优化的基石，其核心任务是通过中间表示（Intermediate Representation, IR）抽象硬件差异，支持从高层框架到低层指令的模块化映射。早期工作如 TVM 和 XLA 确立了静态图编译的标准，但面对新型空间硬件（如 NPU）和动态训练负载，传统线程中心模型逐渐失效。MLIR-AIR（Wang et al., 2025, P2）针对 AMD NPU 的空间异步架构，显式暴露空间和时间执行结构作为可编程构造，允许软件精确控制计算、数据移动和任务执行。这一设计放弃了传统隐式调度的简洁性，换取了对分布式计算单元和分区内存层次的精确管理，特别适用于延迟敏感的工作负载。与之互补的是 Hexagon-MLIR（Absar et al., 2026, P13），Qualcomm 提出的 AI 编译栈采用生成式方法，将融合作为一等编译器通道，支持从 PyTorch/Triton 到 NPU 特定指令（如 HVX、TCM）的自动映射。Hexagon-MLIR 通过多阶段优化，包括并行性分析和协程代码生成，克服了传统算子库作为优化不透明屏障的局限。

在通用性方面，PolyBlocks（Bondhugula et al., 2026, P14）提出了一种基于 MLIR 的模块化基础设施，依赖轻量级仿射访问分析和解析成本模型，实现了多级平铺、融合和矩阵单元映射。PolyBlocks 的设计使得针对新芯片构建编译器时能复用大量基础设施，在 NVIDIA GPU 上匹配或超越了 Torch Inductor 和 XLA 的性能。相比之下，Nova（Suresh et al., 2026, P22）专注于深度学习训练，通过结构哈希运行时结合 JIT 编译缓解动态形状重编译开销，并在 IR 中原生编织数据并行同步。Nova 放弃了推理部署的极致优化，换取了对动态训练工作负载的支持，实现了近峰值 Tensor Core 利用率。这些基础设施共同构成了跨硬件编译的底层支撑，为上层优化策略提供了统一的抽象接口。

### 2.2 智能自动调优

智能自动调优路线利用 LLM、强化学习或世界模型等 AI 技术，探索传统启发式方法难以触及的优化空间。KernelEvolve（Liao et al., 2025, P11）是 Meta 提出的代理式内核编码系统，通过树搜索和状态机管理复杂的优化状态空间，结合 MTIA 硬件知识注入，实现了大规模异构加速器内核的自动化生成。KernelEvolve 放弃了传统搜索的可解释性，换取了对长程依赖和大量硬件知识的处理能力，在 KernelBench 上实现了 17x 的加速比。PerfDojo（Ivanov et al., 2025, P3）则提出了一种基于转换中心的自动 ML 库生成框架，强制在 IR 中执行原子化转换，确保语义保持并简化适用性约束。PerfDojo 通过这种设计，使 RL 代理专注于程序优化而非避免语义错误，显著提高了搜索效率，并支持手动与自动优化的混合工作流。

在模型规模与部署效率方面，Small Language Models as Compiler Experts（Devadiga, 2025, P9）挑战了必须使用大型专有模型的假设，利用 1B 参数级小模型进行 C/C++ 代码自动并行化。该系统采用三阶段流水线，通过探索多条推理路径（如 Tree of Thoughts）提升复杂优化任务的质量，证明了小模型在低延迟、低成本约束下的高效推理能力。KForge（Sereda et al., 2025, P4）则聚焦于多样化 AI 硬件加速器，利用 LLM 生成针对 NVIDIA、AMD、Apple 等特定硬件的高性能内核，支持 CUDA、OpenCL、Metal 等多种 DSL。KForge 通过结合 profiling 反馈，识别性能瓶颈并生成针对性优化代码，填补了云端与边缘硬件优化之间的空白。

跨硬件泛化是另一关键挑战。TCL（Shen et al., 2026, P15）提出基于持续学习的跨硬件张量程序优化框架，利用 Mamba 块构建轻量级成本模型，并通过主动学习策略将性能测量数据需求减少至 10%。TCL 支持多源平台的知识累积，避免了多任务学习带来的参数线性增长问题。Toward Compiler World Models（Pan et al., 2026, P20）则引入世界模型概念，通过学习编译器状态转换的潜在动态，在昂贵的硬件测量之前通过潜在表示空间中的滚动模拟估计候选调度质量。这些方法共同推动了从“静态搜索”向“动态智能生成”的范式转变，但需解决 LLM 生成的正确性验证与评估鲁棒性问题。

### 2.3 内核融合与调度

内核融合与调度旨在消除内核启动开销与同步屏障，提升 GPU 及多设备利用率。Mirage Persistent Kernel (MPK)（Cheng et al., 2025, P10）提出了 Megakernel 化张量程序的编译器与运行时，通过消除内核间的隐式同步，启用跨任务软件流水线，允许依赖算子重叠执行。MPK 利用现代 GPU 的异步特性（如 TMA 和 Tensor Cores），实现细粒度的计算-通信重叠，特别适用于 LLM 推理等延迟敏感工作负载。Event Tensor (ETC)（Jin et al., 2026, P16）进一步提出统一动态 Megakernel 编译的抽象，通过细粒度的事件依赖追踪实现算子间的并行执行与负载平衡。ETC 支持静态和动态调度策略，能够流水线化 GroupGEMMs 和 GEMMs，并在输入激活就绪前预取模型权重以隐藏内存延迟，打破了 CUDA Graphs 对静态输入的依赖。

在硬件资源利用方面，Tawa（Chen et al., 2025, P1）提出了一种针对现代 GPU 的自动 Warp Specialization 方法，利用异步引用解决 SIMT 模型与异构硬件单元之间的范式不匹配。Tawa 通过自动将不同任务分配给不同的 Warp，实现数据移动（TMA）和计算（Tensor Cores）的并发执行，最大化硬件利用率。与仅运行在模拟器上的先前工作不同，Tawa 在商业 GPU 上展示了可测量的加速。Resource-aware Computation-Communication Overlap（Cui and Pericas, 2026, P19）则聚焦于多 GPU 环境，通过每块共享内存分配进行占用率整形，并为集合通信内核赋予更高调度优先级，改善了重叠期间的通信进度。该方法无需侵入式硬件/软件更改，具有更高的可移植性，在 NVIDIA A40、A100、H100 和 AMD MI250X 上展示了跨供应商的通用性。这些技术共同构成了细粒度调度的核心，解决了静态编译在动态负载下的效率损失。

### 2.4 布局与内存优化

布局优化决定张量在内存或硬件资源中的物理排列方式，直接影响数据局部性和硬件指令匹配度。Tensor Seeks Layout（Eisenhofer et al., 2026, P23）提出了一种形式化布局选择方法，将 ML 程序建模为有向无环数据流图，通过全局优化问题求解最小化总成本（包括转换开销）。该方法放弃了贪心启发式的快速收敛，换取了理论保证和避免局部最优的能力，支持多种布局解释，适应不同硬件目标。Axe（Hou et al., 2026, P12）则提出了一种简单的统一布局抽象，将形状-步长模型泛化，允许步长语义化命名并绑定到不同轴（如内存、线程、设备）。Axe 支持分片（D）、复制（R）和偏移（O）操作，通过集值映射统一了从数据张量到硬件单元的映射，解决了现有布局系统在非 2 的幂次形状和分布式场景下的局限性。

针对存内计算（PIM）架构，DCC（Yang et al., 2025, P6）提出了首个针对 PIM 架构的数据中心 ML 编译器，通过联合优化数据重排策略与计算代码优化，解决内存密集型内核的数据移动瓶颈。DCC 支持多种 ML 内核和 PIM 后端，采用多层抽象设计，使编译器能够推理内存银行间的数据分布和 PIM 核心上的数据处理。系统包含耦合预测器，在编译时分析 ML 内核并训练，运行时根据输入张量维度生成优化调度。DCC 特别针对近银行 PIM 设备，如 Samsung HBM-PIM 和 SK Hynix GDDR6-AiM，利用硬件乘法和浮点单元加速 ML 内核。这些方法共同强调了布局优化对性能的巨大影响，推动了从局部启发式向全局形式化优化的转变。

### 2.5 符号化程序优化

符号化程序优化引入符号推理、超优化及形式化验证方法，对张量程序进行结构化搜索与等价性验证。Prism（Wu et al., 2026, P18）提出了一种张量程序的符号超优化框架，通过符号推理和形式化验证自动发现更优的算子实现。Prism 将张量程序表示为符号图（sGraphs），通过超优化搜索生成验证过的 sGraphs 集合，采用随机采样策略进行自动调优，避免迭代方法的长依赖链。该方法支持代数转换、数据布局和硬件特定调度决策的组合交互，发现人类直觉无法捕捉的优化机会，并通过形式化验证确保生成程序的语义正确性。

Nautilus（Zhao et al., 2026, P17）提出了一种自动调度张量编译器，通过块图调度语言和分层优化流水线，实现从高层张量表达式到低层高效 GPU 内核的自动化生成。Nautilus 的调度语言定义块图上元素的引用和转换方式，捕获高层优化如算子融合，将其他优化留给后续阶段。系统采用分层优化流水线，依次降低程序到虚拟寄存器 Tile IR (VR-Tile) 和内存访问 Tile IR (MA-Tile)，应用表达式重写和 Tile 级 SIMD 优化。Nautilus 适配现有 Tile 编译器（如 Triton、TAWA、TileLang）进行 Tile 级优化，解决了调度语言混合不同级别优化导致的自动调度困难。Library Liberation（Thangamani et al., 2025, P5）则通过编译器组合纳米内核（Nanokernels）实现竞争性 Matmul 性能，利用 MLIR 中的 Batch-Reduce GEMM (BRGEMM) 表示，将多个小矩阵乘法累积到公共输出张量，减少内存流量并自然融合元素级操作。这些方法共同展示了符号化与形式化方法在提升优化可靠性与全局最优性方面的潜力。

| 符号化程序优化 | Prism, Nautilus | 符号超优化，分层调度流水线 | 启发式方法的快速收敛 | 语义正确性，结构化搜索 | 算子实现优化，GPU 内核生成 |

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

领域内最核心的共识是编译器自动化生成是必然趋势，手动优化的内核库虽性能高但维护成本大且缺乏灵活性。这一共识在多个基准上被反复验证：KernelEvolve 的 17x 与 PerfDojo 的 6.65 均大幅超越 PyTorch Eager 的 1.0x 基线，表明自动化方法在复杂工作负载上的显著优势。与此相关的另一个共识是内核融合是减少内存访问和启动开销、提升端到端性能的最有效手段之一。MPK 的 1.5x 与 ETC 的 1.2x 加速比均源于对内核边界同步开销的消除，验证了融合技术在低延迟推理中的关键作用。此外，MLIR 等模块化 IR 基础设施是构建跨硬件编译器栈的基础，MLIR-AIR、Hexagon-MLIR 和 PolyBlocks 均基于 MLIR 构建，证明了其在后端扩展和优化组合中的灵活性。这些共识构成了当前研究的基础，但其在动态工作负载和新型硬件上的适用性仍需进一步验证。

### 3.2 观点分歧

在 LLM 生成代码的正确性保证机制上，存在测试驱动与形式化验证的分歧。测试驱动派（如 KernelEvolve、PIKE-B）通过多智能体测试和数值比较确保正确性，在 KernelBench 上展示了更高的加速比和更广的适用性。形式化验证派（如 Prism、PerfDojo）通过符号推理和等价性验证确保语义正确性，Prism 在 Attention Workloads 上实现了 2.2x 的加速，但搜索空间受限。现有证据偏向测试驱动，因为其在复杂基准上的表现更优，但形式化验证提供了更强的理论保证。这一分歧的背后，是另一个更根本的争论：布局优化策略应采用贪心启发式还是形式化全局求解。Tensor Seeks Layout 和 Axe 采用全局优化，在 Layout Selection Benchmarks 上优于贪心基线，但求解器开销大，难以在实时编译中应用。贪心方法在简单场景下足够好，但在复杂算子图上易陷入局部最优。这两种分歧共同反映了领域在“效率”与“保证”之间的权衡。

### 3.3 其他开放问题

最紧迫的工程问题是动态形状与数据依赖处理。静态编译在 LLM 服务等动态工作负载中效率损失严重，JIT 重编译开销大。关键困难在于运行时形状变化和依赖关系的复杂性，研究路径包括开发支持动态形状的编译器 IR 和运行时调度策略，如 ETC 的事件驱动抽象。最根本的研究问题是 LLM 生成代码的形式化保证自动化。LLM 生成的内核可能存在语义错误或数值不稳定，且评估框架易被“奖励黑客”利用。关键困难在于形式化验证的自动化程度低，难以处理所有硬件特定指令，研究路径包括结合强化学习约束、形式化验证和多智能体测试来增强可靠性。此外，跨硬件迁移与成本模型泛化也是重要开放问题，TCL 的持续学习机制提供了初步解决方案，但多源平台的知识累积机制仍需进一步研究。归纳“已知—争议—未知”认知图谱：已知自动化是趋势，融合是关键；争议在于正确性保证机制与布局优化策略；未知在于动态负载下的全局最优求解与 LLM 硬件知识注入的自动化。

## 4. 总结与展望

异构硬件机器学习编译器正经历从“确定性搜索”到“概率性生成”与“动态自适应”的范式重构。核心矛盾在于自动化生成的通用性与专家内核的极致性能之间的差距，这一矛盾驱动了从 Halide 的调度分离到 LLM 智能生成的演进。当前核心瓶颈在于 LLM 生成的正确性验证与动态工作负载下的全局最优求解，这限制了自动化方法在复杂场景中的可靠性与效率。

未来可能突破的方向包括：一是 LLM 与形式化验证的深度融合，结合 KernelEvolve 的代理式架构与 Prism 的符号推理，实现“生成-验证”闭环，多篇论文（P11, P18, P3）共同指向这一路径；二是动态 Megakernel 与事件驱动调度的标准化，ETC 和 MPK 的互补性表明，细粒度动态并行将成为低延迟推理的标准范式（P10, P16）；三是跨硬件持续学习机制的普及，TCL 的 Mamba 块成本模型与主动学习策略为降低新硬件适配成本提供了可行路径（P15）。对于进入该领域的研究者，最值得做的一件事是构建统一的“正确性-性能-效率”联合评估基准，以解决当前评测中方法贡献与骨干网络贡献混淆的问题，为公平比较提供基础。
