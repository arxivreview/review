综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/Ontology%20Engineering%20with%20LLMs)

## 导读

本体工程（Ontology Engineering, OE）旨在构建形式化、机器可读的领域知识表示，其核心价值在于将非结构化文本转化为可推理的逻辑结构，以支撑智能系统的语义互操作。传统方法依赖领域专家与工程师的高强度协作，存在成本高、扩展性差及维护困难的瓶颈，难以适应知识密集型领域的快速演进需求。随着大语言模型（LLM）的兴起，该领域经历了从“规则/统计驱动”向“神经符号（Neuro-symbolic）融合”的关键范式转变，LLM 凭借其强大的语义理解与生成能力，开始介入本体构建、对齐、推理及验证的全生命周期。早期工作主要利用自然语言处理（NLP）技术进行术语提取，而 2023 年后，LLM 被用于自动化本体生成，并逐步与检索增强生成（RAG）及形式化验证工具结合，以解决幻觉与逻辑不一致性问题。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从概率生成到符号约束的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

本体工程的核心目标是将领域知识转化为形式化、机器可读的结构，以便计算机系统进行推理与互操作。在 LLM 介入之前，这一过程高度依赖领域专家与本体工程师的人工协作，不仅成本高昂，且难以应对知识快速迭代的需求。2002 年，Maedche 等人确立了本体学习（Ontology Learning, OL）作为符号与统计 AI 交叉领域的核心挑战，旨在结合结构化可解释知识与数据驱动模型的灵活性。随后的 Text2Onto 等工具通过统计模式匹配从语料中提取术语及分类关系，奠定了基于 NLP 的本体学习基础，但这些方法受限于浅层语义理解，难以捕捉复杂的逻辑约束。2004 年，W3C 发布 Web 本体语言（OWL）标准，基于描述逻辑提供机器可解释的语义表示框架，成为本体工程的事实标准，但也使得逻辑一致性的验证变得至关重要。

LLM 的引入彻底改变了这一局面，但也带来了新的问题结构。2023 年，OntoGPT 类方法展示了 LLM 在零样本或少样本场景下直接生成本体元素的能力，标志着本体工程从传统 NLP 统计方法向生成式 AI 范式的重大转折。然而，LLM 本质上是概率模型，缺乏形式化约束，其生成的本体往往存在逻辑不一致性与幻觉问题。这一“概率墙”问题迫使研究重心从单纯的“本体学习”扩展至“本体工程全流程”，核心问题转变为如何在保留 LLM 语义理解与生成灵活性的同时，通过神经符号融合机制克服其概率性本质带来的逻辑缺陷。当前，研究焦点已不再局限于术语提取，而是涵盖需求驱动的扩展、复杂多本体对齐及企业级知识图谱构建，旨在实现高精度、可解释且可维护的知识系统。

从子问题依赖关系来看，本体自动构建是基础，但必须依赖本体推理扩展（验证/补全）来保证逻辑一致性；本体对齐匹配依赖于构建出的高质量本体结构，以实现跨域知识整合；本体应用集成则是前三个子问题的最终落地场景，服务于企业知识管理与特定领域知识图谱构建。这种依赖关系决定了方法演进的顺序：首先解决“如何生成”，继而解决“如何验证与修正”，最后解决“如何互操作与应用”。范式边界也随之清晰：纯生成路线牺牲逻辑严谨性换取效率，神经符号路线牺牲部分自动化程度换取可解释性与准确性，而人机协同（Human-in-the-loop）则成为平衡两者、注入领域专家知识的关键机制。

回顾约束演化史，2016-2018 年间，OOPS! 等工具通过实证分析建立语义陷阱目录，将本体错误建模为可检测的语义缺陷，为后续利用 LLM 生成能力问题（CQs）进行自动化验证提供了基准。2020 年，跨域基准的引入暴露出传统方法在域偏移下的局限性，促使研究者关注语义鲁棒性。2021-2022 年，预训练语言模型与视觉语言模型的引入开始影响本体对齐，BERTMap 等基于 Transformer 的嵌入匹配技术显著提升了匹配精度。2023-2025 年，随着 LLM 能力的爆发，研究重心迅速转向“修正”与“约束”，RAG 与形式化验证工具（如 OWL 推理机、SHACL）的结合成为主流。2025-2026 年，模块化框架（如 OntoLearner、Open Ontologies）与模型上下文协议（MCP）的出现，标志着领域进入标准化与工具化阶段，旨在降低复现门槛并支持可组合的工作流。

**如果用一个核心问题概括该领域，那便是：如何在保留大语言模型语义理解与生成灵活性的同时，通过神经符号融合机制克服其概率性本质带来的逻辑不一致与幻觉，实现形式化、可验证且可维护的本体工程全流程自动化。**

## 2. 方法体系

- 2002：Maedche OL——确立本体学习（Ontology Learning）作为符号与统计AI交叉领域的核心挑战

- 2004：OWL标准——由W3C发布Web本体语言标准，基于描述逻辑提供机器可解释的语义表示框架

- 2023：OntoGPT——利用LLM从文本中提取本体术语，标志着本体工程从传统NLP统计方法向生成式AI范式的重大转折

- 2024：BERTMap——引入基于Transformer的嵌入匹配技术，在OAEI基准中显著提升了匹配精度

- 2025：OntoAxiom——针对9个本体进行公理识别基准测试，揭示了LLM在复杂逻辑公理推断上的局限性

- 2026：OntoLearner——构建模块化Python库，提供标准化的实验基础设施，降低了LLM本体学习研究的复现门槛

- 2026：Open Ontologies——提出基于稳定匹配的对齐方法，集成MCP协议实现LLM生成OWL后的形式化验证闭环

- 2026：NeurOWL——提出基于LLM的神经符号框架，利用嵌入模型和LLM进行TBox溯因推理

这条时间线勾勒了该领域方法演进的代表性节点：从 2002 年的 Maedche OL 奠定该领域方法基线，经 2004 年 OWL标准 的推进，到 2026 年的 Open Ontologies 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 本体自动构建

本体自动构建旨在利用 LLM 从非结构化文本或需求中自动生成本体结构，涵盖多智能体协作、提示工程及端到端管道设计。早期方法如 Text2Onto 依赖统计模式匹配，而 LLM 的引入使得零样本或少样本生成成为可能。然而，单一 LLM 在处理复杂语义结构时面临上下文限制与幻觉问题。为此，研究者转向多智能体协作架构，如 P15 提出的方法，将本体构建任务分解为术语提取、关系识别及层级构建等子任务，由不同智能体负责，通过交互与反馈机制迭代优化本体一致性。该方法放弃了单模型的简洁性，换取了大规模文本处理下的构建效率与一致性，但其计算开销随智能体数量线性增长。

在企业级应用中，P9 设计了从文本到 RDF 本体的端到端构建管道，利用 LLM 提取语义并建议模式模式，实现了从原始文本到结构化本体的自动化流转。该方法假设企业数据具有语义连贯性，但可能引入 LLM 特有的幻觉错误，需后续验证步骤。针对领域特异性，P8 比较了通用预训练 LLM、少样本学习（ICL）及领域微调 LLM 在铸造领域本体构建中的表现，发现通过 ICL 和微调引入领域特定知识能显著提升术语提取准确性。其取舍在于微调需要标注数据支持，而 ICL 依赖提示词设计的精细度。此外，P6 结合 One-Shot 与 Chain-of-Thought 技术，在帕金森病监测本体工程中引入人类专家与 LLM 协作，通过迭代反馈提升本体的全面性与准确性，展示了人机协作在复杂健康领域知识表示中的有效性。P10 则反向利用本体指导生成，通过 Pydantic schema 将本体概念映射为类型化字段，利用枚举类型限制 LLM 输出，解决了生成内容缺乏结构验证的问题，但生成多样性受限于本体定义的完备性。

### 2.2 本体学习基准

本体学习基准旨在构建标准化数据集与评估框架，系统研究 LLM 在术语分类、分类法发现及公理识别等任务中的性能。P19 提出的 OntoLearner 是一个模块化 Python 库，集成术语分类、分类法发现及非分类关系提取等核心任务，采用 RAG 框架通过静态密集检索器与目标 LLM 配对，隔离生成能力以评估不同规模 LLM 的性能。该方法确立了 LLM 本体学习研究的基准规范，解决了以往研究缺乏可复现工作流的问题，但其依赖预训练的嵌入模型进行检索，可能引入检索偏差。

P5 系统评估了 LLM 在识别五种本体公理（子类、不相交、子属性、域、范围）上的能力，比较了直接提示与逐公理（AbA）两种策略，揭示了 LLM 在处理复杂逻辑约束时的局限性。其核心创新在于区分了公理识别的不同粒度，提供了细粒度的公理类型评估指标。P23 结合密集检索增强生成（RAG）与确定性词汇约束过滤策略，用于本体学习中的术语类型化与关系提取，通过限制模型输出至预定义本体词汇表，有效抑制了 LLM 的幻觉现象。其取舍在于依赖高质量的本体词汇表作为约束基础，且过滤步骤可能丢弃部分潜在有效但非标准的术语。P24 通过控制变量实验，系统研究 LLM 参数规模对本体学习任务性能的影响，量化了模型规模与本体学习精度之间的非线性关系，揭示了“更大不一定更好”的现象，为 LLM 选型提供了实证依据。

### 2.3 本体对齐匹配

本体对齐匹配旨在识别不同本体间语义等价或包含关系，解决跨本体语义互操作问题。传统方法如 BERTMap 基于 Transformer 嵌入匹配，但难以处理复杂多本体间的非等价映射。P16 提出的 Open Ontologies 系统基于稳定匹配约束，通过强制一对一分配来主导信号设计，提升本体匹配的精度，并集成 MCP 协议实现 LLM 生成 OWL 后的形式化验证与对齐闭环。该方法证明了匹配约束比信号权重更关键，解决了传统对齐方法中多对多匹配导致的歧义问题，但在异构建模风格的会议本体上召回率较低。

P1 构建的 OntoAligner 框架整合解析器、编码器及对齐器，利用知识图谱嵌入（KGE）模型进行本体对齐，将源与目标本体的三元组统一表示，通过 PyKEEN 训练低维嵌入，并利用余弦相似度计算对齐预测。该方法支持多种 KGE 模型的即插即用，提升了框架的灵活性，但对结构差异巨大的本体鲁棒性有限。P3 提出的 CMOMgen 利用模式引导的上下文学习（ICL）生成复杂映射，解决多本体间语义复杂链接的整合问题，支持多本体联合对齐，提升了知识图谱的语义完整性，但计算开销大，且依赖高质量参考映射集。P22 提出的 AgentMap 基于智能体的本体匹配框架，同时发现等价关系与包含关系，通过推理链识别概念间的层级与等价联系，提升了匹配的鲁棒性，但智能体交互复杂，且推理过程可解释性需进一步验证。

### 2.4 本体推理扩展

本体推理扩展旨在结合神经符号方法处理不完整本体推理，利用 LLM 进行本体扩展、公理补全及语义陷阱验证。P13 基于 Angluin 精确学习框架，利用 LLM 生成反例以验证候选公理，实现不完整本体的主动学习，降低了领域专家的认知负担，但依赖 LLM 生成反例的准确性。P21 提出的 OntoExtend 框架基于检索的管道，利用 LLM 根据能力问题（CQs）扩展现有本体，通过 RAG 检索相关本体元素，引导 LLM 生成缺失的本体片段，确保生成内容与现有本体建模风格一致，但依赖检索质量，且生成片段需人工或自动验证。

P20 提出的 NeurOWL 结合嵌入模型与 LLM，进行 TBox 溯因推理以补全缺失公理，利用 OnT 或 SBERT 编码本体实体，通过 LLM 预测缺失的子类关系，并限制候选集为直接父/子节点以缩小搜索空间，解决了传统溯因推理依赖人工候选集的问题，但嵌入模型需针对特定本体微调。P4 提出的 VSPO 利用 LLM 生成能力问题（CQs）来验证本体中的语义陷阱，特别是类定义与公理之间的不一致性，扩展了验证范围至属性级，但 LLM 生成的 CQs 可能包含噪声，需过滤机制。P18 结合 RAG 与小语言模型（SLM），利用形式概念分析（FCA）作为符号验证循环进行知识扩展，通过反例发现机制确保扩展知识的正确性，避免了幻觉累积，但探索过程迭代次数多，且依赖检索证据的质量。

### 2.5 本体应用集成

本体应用集成旨在将本体作为 LLM 的外部记忆或结构化约束，应用于企业知识管理、特定领域知识图谱构建及生成式任务。P12 提出端到端架构，统一本体构建、语义对齐及确定性推理，解决企业数据孤岛问题，利用 LLM 进行本体构建与对齐，并结合神经符号 AI 进行确定性推理，克服 LLM 在逻辑一致性上的“概率墙”，但架构复杂度高，且需处理多源异构数据的噪声。P7 构建的大型本体模型（LOM）融合结构化数据库与非结构化文本，通过三阶段训练管道实现指令对齐推理，4B 参数模型在复杂图推理上超越通用大模型，证明了领域专用模型的有效性，但训练数据构建成本高，且模型泛化能力需验证。

P14 将本体作为 LLM 的外部记忆层，结合向量检索与工具总线（MCP）实现混合智能系统，利用 MCP 协议连接 LLM、本体图、向量数据库及外部 API，实现结构化记忆与动态检索的协同，提升了回答的可解释性，但系统架构复杂，且需维护本体与向量库的一致性。P2 利用 LLM 从产品评论中提取部分-整体关系（Meronymy），构建简单本体以支持评论聚合与推荐，利用 Mistral-7B-Instruct 模型执行，降低了计算成本，但仅适用于特定关系类型，且依赖评论数据的丰富性。P17 提出沿本体连续体重构知识图谱的方法，利用神经符号方法适配现有 KG，通过显式映射桥接不同基础本体的不兼容性，提升了 KG 的可移植性，但映射生成复杂，且需领域专家参与验证。P11 提出的 IDEA2 通过 LLM 生成与专家验证的迭代重构，高效提取高质量能力问题（CQs），解决了 CQ 编写困难且易导致本体设计偏差的问题，提升了人机协作效率，但需专家持续参与，且重构算法需调优。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

领域最核心的共识在于 LLM 显著降低了本体构建的门槛与成本，但无法完全替代人类专家在逻辑严谨性与领域深度上的作用，人机协同是最佳实践。这一共识在约 20 篇论文中得到共同支持，如 P6 和 P11 均强调了专家在环（Human-in-the-loop）在修正 LLM 偏差、提升本体质量中的关键作用。与此相关的另一个共识是，单纯依赖 LLM 生成本体难以保证逻辑一致性，必须结合形式化验证工具（如 OWL 推理机、SHACL）或符号方法（如 FCA）进行闭环校验。P20 的 NeurOWL 和 P18 的 FCA 验证循环均体现了这一神经符号融合的必要性，通过符号引擎验证 LLM 生成的假设，确保逻辑严密性。

### 3.2 观点分歧

关于模型规模与本体学习性能的关系，存在“更大是否更好”的分歧。观点 A 认为更大规模的 LLM 具有更强的语义理解与逻辑推理能力，而观点 B 认为规模效应存在非线性，小模型结合 RAG 与领域微调在特定任务上可能优于大模型。现有证据偏向观点 B，P24 通过控制变量实验揭示了“更大不一定更好”的现象，P7 的 LOM-4B 在企业图推理任务上超越通用大模型，但证据强度中等，主要基于特定任务集的实验，未涵盖所有本体工程环节。这一分歧的背后，是另一个更根本的争论：本体对齐的核心驱动力是语义嵌入还是逻辑约束？观点 A 支持基于 Transformer/KGE 的语义嵌入匹配，观点 B 支持逻辑约束（如稳定匹配）。P16 的消融实验验证了约束的主导作用，但 P1 的 OntoAligner-KGE 在 OAEI 多个赛道上也取得了 SOTA，表明嵌入匹配在召回率上仍有优势。缺乏自适应阈值与混合模型的统一理论框架，使得这一分歧尚未定论。

### 3.3 其他开放问题

最紧迫的工程问题是缺乏统一的评估基准与可复现实验流程，任务定义（如公理识别、术语类型化）不统一，导致不同方法间的公平比较困难。P19 的 OntoLearner 和 P23 的 LLMs4OL 挑战赛正在致力于建立标准化的本体学习任务定义与数据集，但覆盖全流程（从非结构化文本到完整本体）的统一评测标准仍缺失。最根本的研究问题是如何解决非层级关系提取的瓶颈，LLM 在子类层级发现上表现较好，但在域、范围、不相交及非层级关系（如部分-整体）提取上性能显著下降。P5 的基准研究揭示了 LLM 在复杂逻辑公理推断上的局限性，如 o1 在仅基于名称列表时 F1 分数仅为 0.197。研究路径包括结合神经符号方法或约束解码来增强复杂语义关系的推理能力，以及探索混合神经符号架构与确定性推理，利用本体作为外部记忆和验证器，实现可解释、可验证且逻辑严密的推理。

## 4. 总结与展望

本体工程正经历从“人工密集”向“LLM 辅助神经符号融合”的范式转变，核心挑战不再是单纯的术语提取，而是如何在概率生成与符号约束之间建立闭环，以解决 LLM 的“概率墙”问题。早期方法假设本体构建主要是一个统计模式匹配问题，受限于算力与数据，主要依赖 NLP 技术进行术语提取，缺乏对逻辑一致性的形式化保证。2023 年引入 LLM 进行零样本本体生成后，暴露出严重的幻觉与逻辑不一致性问题，迫使研究转向神经符号融合，通过 RAG 与形式化验证闭环提升本体的逻辑一致性与事实准确性。当前，领域焦点从单一任务转向全流程的模块化集成，核心瓶颈在于非层级关系提取与端到端基准缺失，以及混合神经符号架构的最优配比。

未来可能突破的方向包括：开发端到端本体构建的综合基准，覆盖从非结构化文本到完整本体（含 T-Box 和 A-Box）的统一评测标准；解决非层级关系提取的瓶颈，研究结合神经符号方法或约束解码来增强复杂语义关系的推理能力；以及探索混合神经符号架构与确定性推理，利用本体作为外部记忆和验证器，实现可解释、可验证且逻辑严密的推理。对于进入该领域的研究者，最值得做的一件事是构建一个统一的、覆盖全流程的评测基准，并在该基准上系统研究不同规模 LLM 与 RAG 策略的组合效应，以量化“规模效应”的非线性特征，为资源受限场景下的模型部署提供实证依据。
