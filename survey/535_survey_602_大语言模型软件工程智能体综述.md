综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/LLM%20Agents%20for%20Software%20Engineering)

## 导读

大语言模型软件工程智能体（LLM Agents for Software Engineering）旨在让模型像人类开发者一样，通过工具交互与环境反馈完成仓库级代码修复与全生命周期维护，其核心价值在于突破传统自动化软件工程在处理长程依赖与非结构化需求上的瓶颈。早期研究聚焦于单函数代码补全，依赖静态文本相似度评估，思路简洁却难以应对真实仓库的复杂依赖与环境异构性。当 SWE-bench 等基准将评估转向仓库级真实 Issue 修复后，执行接地验证成为核心机制，迫使模型从一次性生成转向多轮迭代交互。随后，代理-计算机接口（Agent-Computer Interface, ACI）概念的引入，使智能体能够自主执行命令并获取反馈，实现了从静态预测到动态代理的范式转变。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从静态生成到自主进化的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

大语言模型在代码理解与生成能力上的突破，催生了软件工程智能体这一新兴领域，其初衷是解决传统自动化软件工程难以处理复杂、长程依赖及非结构化需求的问题。早期工作将代码生成视为静态文本预测任务，受限于算力与数据，主要依赖 Transformer 架构进行单函数补全，缺乏与环境交互的能力。这种范式在理想化的函数级任务上表现良好，但一旦面对真实仓库中的多文件依赖、环境配置及版本敏感性问题，其局限性便暴露无遗。因此，领域的核心问题从“如何生成正确代码”迅速演变为“如何在真实、异构且长程依赖的工程环境中实现端到端自动化交付”。

问题形式化通常遵循 N-way K-shot 范式，但在软件工程场景中，这一范式被重构为基于真实 GitHub Issue 的仓库级任务。给定一个包含代码库 $C$、问题描述 $I$ 和测试套件 $T$ 的任务实例，智能体需生成补丁 $P$，使得 $T(P(C))$ 全部通过。这一形式化确立了“执行反馈”作为核心验证机制，即代码的正确性不再由文本相似度决定，而是由沙箱环境中的实际运行结果判定。子问题间存在强依赖关系：环境配置是执行反馈的前提，执行反馈是强化学习奖励信号的基础，而记忆机制则是长程推理稳定的保障。这种因果链条决定了领域研究的优先级与演进路径。

2021 年至 2023 年间，领域处于奠基阶段。HumanEval 确立了 pass@k 评估指标，成为函数级代码生成能力评估的基础范式（Chen et al., 2021）。然而，函数级任务无法反映真实工程的复杂性。2023 年，SWE-bench 的提出标志着评估从函数级转向仓库级真实软件工程任务（Jimenez et al., 2023），它要求模型生成通过单元测试的补丁，从而确立了执行接地验证的黄金标准。这一转折迫使研究者重新审视模型能力，发现静态预测在真实工程场景中的失效，进而推动了代理架构的兴起。

2024 年是代理架构的奠基之年。SWE-agent 引入 Agent-Computer Interface 概念，通过小工具集实现 LLM 与真实仓库的迭代交互（Yang et al., 2024），奠定了现代 SWE 智能体的基础架构。同年，OpenHands 扩展了工具集，包括 IPython 服务器和 Web 浏览器，提升了智能体在复杂环境中的操作能力（Wang et al., 2024）。与此同时，Agentless 将 SWE 任务分解为模块化工作流，通过单轮可验证奖励优化各步骤，提供了稳定但缺乏灵活性的替代范式（Xia et al., 2024）。这些工作共同确立了“动态交互”作为解决长程依赖问题的核心路径。

2025 年，研究重心转向训练与数据增强，以解决高质量轨迹数据稀缺问题。SWE-Gym 引入开放训练环境，通过合成可验证任务实例提升 7B/32B 规模智能体的性能（Pan et al., 2025）。SWE-RL 将强化学习应用于 Llama 3 等模型，利用执行反馈作为奖励信号，显著提升了智能体在长程任务中的推理与决策能力（Wei et al., 2025）。这一阶段，模型从依赖提示工程向具备自主规划能力演进，强化学习成为提升泛化能力的关键手段。

2026 年，领域进入细化与融合期，关注长程推理的稳定性、多智能体协作及自我进化。Agyn 提出经理协调的工作流导向多智能体系统，在 GPT-5 家族模型上实现 72.2% 的 SWE-bench 500 解决率（Benkovich and Valkov, 2026）。Socratic-SWE 提出自进化编码智能体框架，通过轨迹衍生的智能体技能注册表实现协同进化（Xiao et al., 2026）。当前形态下，AI 正从辅助工具向具备独立工程能力的“数字员工”转变，研究热点集中在长程推理稳定性、多智能体协作架构及执行接地验证。

**如果用一个核心问题概括该领域，那便是：如何构建具备自主规划、环境交互及自我进化能力的智能体，使其能在真实、异构且长程依赖的软件工程环境中，通过执行接地验证实现从需求到可维护代码的端到端自动化交付。**

## 2. 方法体系

- 2021：HumanEval——确立函数级代码生成能力评估的基础范式

- 2023：SWE-bench——标志着评估从函数级转向仓库级真实软件工程任务

- 2024：SWE-agent——引入 Agent-Computer Interface 概念，奠定现代 SWE 智能体基础架构

- 2025：SWE-RL——将强化学习应用于 LLM，利用执行反馈作为奖励信号

- 2025：Live-SWE-agent——允许智能体在解决任务过程中动态创建和使用新工具

- 2026：Agyn——经理协调的工作流导向多智能体系统，实现高解决率

- 2026：Socratic-SWE——自进化编码智能体框架，实现生成器与求解器的协同进化

这条时间线勾勒了该领域方法演进的代表性节点：从 2021 年的 HumanEval 奠定该领域方法基线，经 2023 年 SWE-bench 的推进，到 2026 年的 Socratic-SWE 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 智能体架构设计

智能体架构设计是解决长程依赖与上下文爆炸问题的核心路线。早期工作如 SWE-agent（Yang et al., 2024）通过引入 Agent-Computer Interface，使 LLM 能够像人类开发者一样通过终端、编辑器等工具与环境交互，解决了静态预测无法处理环境状态变化的问题。其核心取舍在于以复杂的工具调用逻辑和上下文窗口压力，换取对真实仓库多轮迭代交互的支持。随后，OpenHands（Wang et al., 2024）扩展了工具集，包括 IPython 服务器和 Web 浏览器，进一步提升了智能体在复杂环境中的操作能力，但同时也增加了系统部署的复杂度。

针对单智能体在长程任务中易陷入循环或丢失关键信息的问题，多智能体协作架构应运而生。AgentForge（Kumar et al., 2026）提出执行落地多智能体 LLM 框架，将执行验证作为一级原则，包含 Planner、Coder、Tester、Debugger 和 Critic 五个角色，通过共享内存和强制 Docker 沙箱进行协调。其核心创新在于要求所有代码变更在传播前必须通过沙箱执行验证，确保正确性。该方法通过角色分解和执行反馈独立驱动性能提升，解决了现有系统模拟执行或验证可选的问题。Agyn（Benkovich and Valkov, 2026）则提出经理协调的工作流导向多智能体系统，通过明确的角色分工和工作流协调，使多个智能体能够协作解决复杂的 GitHub 问题。其设计重点在于解耦系统设计与底层模型能力，证明在 GPT-5 家族模型上，多智能体架构能实现与单智能体相当甚至更优的性能。

此外，BOAD（Xu et al., 2025）提出基于 Bandit Optimization 的智能体设计方法，旨在自动发现层级化多智能体系统。该方法将智能体发现重构为多臂老虎机问题，每个臂对应一个候选子智能体，通过迭代选择与评估优化编排器与子智能体组合。其核心创新在于避免了直接联合搜索的高昂计算成本，利用 Bandit 机制高效探索设计空间。SWE-Adept（He and Roy, 2026）则提出基于 LLM 的代理框架，用于深度代码库分析和结构化问题解决，包含定位智能体和解决智能体，两个智能体在独立的上下文窗口中运行，防止完整的搜索和编辑轨迹在单个智能体中累积。Lita（Dai et al., 2025）提出轻量级智能体，强调解耦 LLM、智能体框架和环境，追求简洁而非复杂，优先自主性而非工作流，通过减少手动脚手架，使系统更易于部署和适应不同 LLM。

| 方法 | 核心机制 | 优势 | 劣势 | 适用场景 |
|---|---|---|---|---|
| SWE-agent | ACI 单智能体交互 | 架构简洁，交互灵活 | 上下文窗口压力大 | 通用仓库级 Issue 修复 |
| AgentForge | 多智能体角色分工 + 执行验证 | 可靠性高，验证严格 | 协调开销大 | 高可靠性要求的工程任务 |
| Agyn | 经理协调工作流 | 解决率高，解耦模型能力 | 依赖强模型 | 复杂 GitHub 问题协作 |
| BOAD | Bandit 优化自动发现 | 自动化设计，计算成本低 | 依赖设计集代表性 | 智能体架构自动优化 |
| Lita | 轻量级单智能体 | 部署简单，信任模型能力 | 缺乏复杂工作流支持 | 评估模型原生代理能力 |

智能体架构设计路线与记忆与上下文管理路线存在互补关系：多智能体通过角色分工缓解单智能体上下文爆炸，而记忆机制则为多智能体提供共享经验存储，两者共同解决长程推理稳定性问题。

### 2.2 基准测试与评估

基准测试与评估路线旨在全面衡量智能体在真实软件工程环境中的能力边界。SWE-bench（Jimenez et al., 2023）作为奠基性基准，从真实 GitHub 仓库收集 2294 个任务，要求模型生成通过单元测试的补丁，标志着评估从函数级转向仓库级真实软件工程任务。其核心贡献在于确立了执行接地验证的标准，但主要关注快照式任务，忽视长期演进过程。

针对 SWE-bench 的局限，SWE-EVO（Thai et al., 2025）构建长程软件演进场景基准，评估编码智能体在长期维护中的能力。该基准关注智能体在多次迭代中控制回归的能力，定义零回归率作为关键指标，揭示了当前模型在避免回归方面的显著不足。OmniCode（Sonwane et al., 2026）提出涵盖测试生成、代码审查响应和风格修复等多样化任务的基准，包含 1794 个任务，旨在全面衡量智能体在软件开发生命周期中的能力，推动了评估从单一正确性向多维能力转变。

ABC-Bench（Yang et al., 2026）构建真实世界开发中的代理后端编码基准，评估智能体在生产级环境中的能力，关注环境配置、构建成功和端到端成功率，强调框架对性能的影响。LoCoBench-Agent（Qiu et al., 2025）提出交互式基准，用于评估长上下文软件工程中的 LLM 智能体，关注多轮交互、长上下文聚焦和工具使用模式，填补了传统单轮评估与真实多轮交互之间的差距。SWE-AGI（Zhang et al., 2026）构建规范驱动的软件构建基准，使用 MoonBit 语言评估自主智能体，要求智能体从明确需求到生成正确、健壮且可维护的代码库，评估生产级实现能力。

基准测试与评估路线为其他路线提供了统一的标尺，其演进方向从单一解决率向多维工程效用转变，为智能体架构设计和训练策略提供了反馈信号。

### 2.3 训练与数据增强

训练与数据增强路线旨在解决高质量轨迹数据稀缺问题并提升智能体在复杂任务上的泛化能力。SWE-RL（Wei et al., 2025）将强化学习应用于 Llama 3 等模型，利用执行反馈作为奖励信号，显著提升了智能体在长程任务中的推理与决策能力。其核心取舍在于以训练不稳定和计算成本高，换取自主决策能力的提升。SWE-Gym（Pan et al., 2025）引入开放训练环境，通过合成可验证任务实例解决数据稀缺问题，提升了 7B/32B 规模智能体的性能。

SWE-Protégé（Kon et al., 2026）提出后训练框架，将软件修复重构为专家-学徒协作问题，使小语言模型成为唯一决策者，同时学习选择性寻求强专家模型指导、识别停滞状态并遵循专家反馈。该方法解决了 SLM 在长程 SWE 任务中普遍存在的动作循环和低解决率问题，为低成本、低延迟的软件工程智能体提供了新路径。SWE-Hub（Zeng et al., 2026）提出统一生产系统，用于可扩展、可执行的软件工程任务生成，基于 Kubernetes 执行环境，确保高吞吐数据生产的可扩展性和隔离性，解决了高质量 SWE 数据稀缺问题。

Kimi-Dev（Yang et al., 2025）提出将 Agentless 训练作为 SWE-Agents 的技能先验，结合模块化工作流的稳定性与代理范式的灵活性，解决了代理轨迹长、上下文窗口限制和训练难度高的问题。Open-SWE-Traces（Ahmad et al., 2026）提出双模式多语言蒸馏方法，集成 MiniMax-M2.5 和 Qwen3.5-122B-A10B 等模型，通过两阶段质量过滤和规范化管道，将原始执行日志精炼为高保真语料库，用于模型蒸馏。SWE-RL Self-Play（Wei et al., 2025）提出通过自播放 SWE-RL 训练超级智能软件智能体，研究不同 bug 注入策略对下游性能的影响，解决了高质量训练数据稀缺问题。

训练与数据增强路线与智能体架构设计路线存在继承关系：强化学习依赖执行接地验证提供的奖励信号，而多智能体架构则为强化学习提供了更复杂的决策空间，两者共同推动智能体从依赖提示工程向自主进化演进。

### 2.4 记忆与上下文管理

记忆与上下文管理路线旨在解决长程任务中的上下文爆炸与语义漂移问题。SWE-MeM（Gao et al., 2026）提出学习自适应记忆管理，通过合成记忆轨迹进行课程微调，结合记忆感知 GRPO 强化学习，解决长程任务中上下文爆炸与语义漂移问题。其核心创新在于动态压缩和重组上下文，根据子任务密度和上下文预算进行主动管理。MemGovern（Wang et al., 2026）提出统一经验治理框架，将原始人类经验转化为标准化、智能体友好的经验记忆，通过经验治理构建大量经验卡片，并通过代理经验搜索实现高效利用。

Structurally Aligned Subtask-Level Memory（Shen et al., 2026）提出结构对齐的子任务级记忆，将轨迹分解为 K 个推理对齐的子任务，每个段对应离散功能单元，支持长程推理。其核心创新在于结构对齐，确保记忆与任务子任务结构一致，提升检索相关性。Context as a Tool（2026）提出将上下文管理作为工具，通过交互式工具增强智能体设计，实现动态压缩时机和内容的自适应调整，解决了现有方法缺乏灵活性、无法适应不同任务阶段的问题。PMCoder（Zhang et al., 2026）提出将规划与情景记忆耦合，识别双向计划-记忆耦合作为长程仓库修复的设计原则，通过使规划和记忆共享显式轨迹状态，其验证更新基于行为问题复现判决，而非最终补丁。

记忆与上下文管理路线与智能体架构设计路线存在互补关系：记忆机制为多智能体提供共享经验存储，缓解通信开销；而多智能体架构则为记忆机制提供了更复杂的决策场景，两者共同解决长程推理稳定性问题。

### 2.5 环境构建与配置

环境构建与配置路线旨在自动化构建可执行、可验证的多语言开发环境，解决依赖解析、构建脚本生成及环境隔离难题。MEnvAgent（Guo et al., 2026）提出可扩展多语言环境构建框架，通过环境检索和验证驱动适应机制，自动化构建可执行环境。其核心创新在于验证驱动适应，通过 EnvPatchAgent 在反馈循环中生成补丁，确保环境正确性。EvoConfig（Guo et al., 2026）提出自进化多智能体系统，用于高效自主环境配置，通过多轮交互和决策，持续修复环境配置问题，最终生成可执行 Dockerfile。

RAT（Huang et al., 2026）提出 RunAnyThing 通过完全自动化环境配置，通过自动化解析依赖、生成构建脚本和配置环境，实现任意仓库的可执行环境构建。Multi-Docker-Eval（2026）提出一个“淘金热中的铲子”基准，用于自动环境构建，评估 LLM 在自动环境构建中的效率和效果，关注 F2P（First Try Pass）和资源消耗指标。环境构建与配置路线是其他路线的基础设施，缺乏可执行环境将导致验证失效，因此自动化环境构建是提升代理鲁棒性的必要前提。

### 2.6 自我进化与优化

自我进化与优化路线旨在研究智能体在运行时或离线阶段通过轨迹分析、失败诊断及策略调整实现自我改进。Live-SWE-agent（Xia et al., 2025）提出实时自进化智能体，在解决问题时动态改进和扩展其能力，允许 LLM 在运行时生成和使用自己的工具，突破静态工具集的局限。Socratic-SWE（Xiao et al., 2026）提出自进化编码智能体，通过轨迹衍生的智能体技能实现协同进化，共享策略在生成器和求解器角色间交替，生成器构建仓库基础修复任务，求解器生成补丁。

SWE-Fuse（Wen et al., 2026）提出通过无问题轨迹学习和熵感知 RLVR 训练赋能软件智能体，构建包含 14k 验证正确轨迹的数据集，包括有和无问题描述的样本，帮助模型避免噪声描述影响。SWE-Replay（Ding and Zhang, 2026）提出高效测试时扩展，通过重放历史轨迹，利用执行反馈优化智能体决策，提升测试时性能。自我进化与优化路线与训练与数据增强路线存在继承关系：自我进化依赖强化学习提供的策略更新机制，而强化学习则为自我进化提供了优化目标，两者共同推动智能体从静态工具向动态能力演进。

### 2.7 可解释性与调试

可解释性与调试路线旨在通过轨迹可视化、失败模式分类及交互式调试工具，揭示智能体内部决策逻辑。AgentStepper（Hutter and Pradel, 2026）提出交互式调试软件开发智能体的方法，将传统调试概念适配至智能体领域，提供用户界面、后端和 API 三个主要组件，通过可视化智能体执行轨迹，允许开发者设置断点、检查变量和单步执行。XAI for Coding Agent Failures（Joshi, 2026）提出将原始执行轨迹转化为可操作见解的结构化 XAI 方法，对智能体失败进行系统化分类，自动分类并使用领域知识解释失败原因。

CodeTracer（Li et al., 2026）提出可追溯智能体状态方法，将原始执行轨迹转化为结构化、可操作的失败解释，通过演化提取、树索引和诊断三阶段管道，预测失败责任阶段、错误相关步骤和证据集。AgentLens（Sahoo et al., 2026）揭示 SWE-agent 评估中的幸运通过问题，通过过程轨迹分析评估智能体行为，关注智能体如何到达最终补丁，而非仅评估结果，识别幸运通过现象。可解释性与调试路线为其他路线提供了反馈机制，通过揭示失败原因，指导智能体架构设计和训练策略的优化。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

执行接地（Execution-Grounded）是验证 LLM 代码正确性的黄金标准，仅依赖文本生成或静态分析无法保证代码在真实环境中的功能正确性（支撑证据：P29、P3、P14）。SWE-bench 及其衍生基准已成为评估仓库级软件工程代理能力的行业标准，其解决率是衡量模型与框架进步的核心指标（支撑证据：P2、P8、P17）。长程多轮交互是 SWE 任务的本质特征，单步预测或短上下文模型无法解决复杂 Issue，必须引入代理架构以支持迭代规划与反馈处理（支撑证据：P1、P4、P24）。环境配置是代理部署与训练的关键瓶颈，缺乏可执行环境将导致验证失效，因此自动化环境构建是提升代理鲁棒性的必要前提（支撑证据：P15、P13、P30）。记忆机制对于解决长程任务中的上下文限制至关重要，通过存储和检索历史经验或代码结构，代理能显著提高重复任务效率并避免冗余推理（支撑证据：P34、P11、P21）。强化学习（RL）结合可验证奖励是提升代理自主决策能力的有效路径，相比纯监督微调，RL 能更好地利用环境反馈优化长程策略（支撑证据：P9、P3、P22）。多智能体系统通过角色分工（如规划、编码、测试）能提升复杂任务的解决率，但需精心设计协调机制以避免通信开销和冲突（支撑证据：P16、P29、P10）。当前 LLM 代理在回归测试和长期维护场景中表现不稳定，容易引入新 Bug，表明其在代码库全局一致性和变更影响分析上仍有显著不足（支撑证据：P8、P25、P31）。

与此相关的另一个共识是，评估指标正从单一的解决率向多维度的工程效用转变，SWE-EVO、OmniCode 等新基准开始关注长期维护、回归控制及全生命周期能力（支撑证据：P8、P17、P12）。

### 3.2 观点分歧

多智能体协作与单智能体+记忆架构的优劣之争是领域内的核心分歧。多智能体支持者如 Agyn（Benkovich and Valkov, 2026）和 AgentForge（Kumar et al., 2026）认为角色分工能提升复杂任务解决率，缓解上下文爆炸；单智能体+记忆支持者如 SWE-MeM（Gao et al., 2026）和 Lita（Dai et al., 2025）认为单智能体更简洁，通过记忆机制即可解决长程问题，避免通信开销。现有证据偏向多智能体在复杂任务上的解决率优势（如 Agyn 72.2% vs 单智能体基线），但缺乏在相同计算预算下的公平对比。多智能体的通信开销和协调失效问题尚未被充分量化，分歧根源在于缺乏统一的评估协议来隔离“架构复杂度”与“模型能力”的影响。

这一分歧的背后，是另一个更根本的争论：RL 奖励信号的设计。结果级奖励支持者如 SWE-RL（Wei et al., 2025）认为最终测试通过是可靠奖励，简单且无偏；过程级奖励支持者如 PMCoder（Zhang et al., 2026）和 AgentLens（Sahoo et al., 2026）认为中间步骤验证能提供更密集反馈，避免“幸运通过”。结果级奖励在 SWE-bench 上表现稳定，但易导致策略过拟合；过程级奖励在理论上更优，但设计困难，且现有过程级奖励模型的校准性（Calibration）评估不足。分歧根源在于过程级奖励模型的构建成本高，且缺乏大规模验证其有效性的实验。

### 3.3 其他开放问题

最紧迫的工程问题是环境配置的高失败率与异构性。真实仓库的依赖复杂且版本敏感，自动构建可执行环境仍频繁失败，阻碍了大规模代理训练与评估。关键困难在于依赖解析的复杂性和版本敏感性，研究路径包括基于检索增强和自进化诊断的配置方法，如 MEnvAgent（Guo et al., 2026）和 EvoConfig（Guo et al., 2026）。最根本的研究问题是长程推理中的上下文退化与遗忘。由于 SWE 任务涉及多轮交互和大量中间状态，LLM 在长轨迹中容易丢失关键信息或陷入循环。关键困难在于上下文窗口限制和语义漂移，研究路径包括记忆压缩、子任务分解及外部记忆库，如 SWE-MeM（Gao et al., 2026）和 MemGovern（Wang et al., 2026）。

已知—争议—未知认知图谱：已知执行接地是黄金标准，SWE-bench 是行业标准，长程交互是本质特征；争议多智能体 vs 单智能体+记忆，结果级 vs 过程级奖励；未知多智能体通信协议的最优设计，RL 在长程任务中的奖励传播机制，跨语言/多模态泛化。发展趋势：从“辅助工具”向“数字员工”转变，需在长程稳定性、环境鲁棒性及多智能体协作上取得突破。

## 4. 总结与展望

LLM 软件工程智能体正经历从“辅助工具”向“数字员工”的范式跃迁，其核心驱动力在于验证机制从文本相似度向执行接地的转变，以及智能体架构从静态预测向动态代理的演进。领域核心叙事从解决“写代码”到解决“做工程”，强调全生命周期自动化。关键转折包括 SWE-bench 确立执行反馈标准，ACI 确立交互范式，RL 确立自主进化路径。当前挑战集中在长程推理稳定性、环境配置瓶颈及评估指标与真实工程价值的脱节。回扣第 1 章锚点句，如何构建具备自主规划、环境交互及自我进化能力的智能体，使其能在真实、异构且长程依赖的软件工程环境中，通过执行接地验证实现从需求到可维护代码的端到端自动化交付，仍是核心问题。

未来可能突破的方向包括：多文件协调与原子补丁生成，当前 Agent 在单文件任务上表现良好，但在涉及多文件依赖和跨模块修改的复杂任务中容易失败，未来需研究更细粒度的检索机制和原子补丁策略（支撑证据：P24、P29）；长期记忆与经验复用机制，Agent 缺乏长期仓库记忆，无法有效利用历史提交和过往修复经验，未来方向包括构建结构化的经验记忆库，研究如何从历史轨迹中蒸馏可迁移的技能（支撑证据：P34、P11）；强化学习与自演化训练，依赖人类标注数据限制了 Agent 的泛化能力，未来方向包括利用自博弈和合成环境生成训练数据，通过执行反馈和奖励模型进行在线强化学习（支撑证据：P9、P32）。对进入者最值得做的一件事是，在统一骨干与统一预训练条件下，系统评估多智能体与单智能体+记忆架构在长程任务上的性能差异，以隔离架构复杂度与模型能力的影响，为领域提供公平的对比基准。
