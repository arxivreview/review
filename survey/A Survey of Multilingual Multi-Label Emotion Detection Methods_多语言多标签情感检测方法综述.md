## 导读

多语言多标签情感检测旨在从跨语言文本中识别多种共现的基本情感，其核心价值在于突破英语中心主义局限并捕捉文化特定的情感细微差别。早期研究依赖传统机器学习，难以处理隐含情感与低资源语言，性能瓶颈明显。随着 Transformer 架构的引入，跨语言迁移学习成为主流，但单一模型在类别不平衡与复杂语境下仍显不足。近期研究重心转向神经机制可解释性与细粒度证据检索，试图从黑盒分类走向白盒机制理解。各路线在数据构建、模型优化与机制解释之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从数据驱动到机制透明的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

多语言多标签情感检测的兴起源于自然语言处理从英语中心主义向包容性多语言解决方案的范式转移。早期方法依赖词典或传统机器学习，难以捕捉文本中隐含、讽刺及文化特定的情感细微差别，且在低资源语言上性能受限。核心问题定义为：给定一段多语言文本 $x$，预测其包含的情感集合 $Y \subseteq \{y_1, ..., y_k\}$，其中 $y_i$ 为 Ekman 基本情感类别（如喜悦、愤怒、恐惧等），并可能伴随强度评分或证据跨度。这一形式化定义揭示了任务的复杂性：情感并非互斥，而是共现且强度连续，传统单标签分类无法覆盖。

问题定义经历了显著演化。2020 年前后，研究聚焦于利用 Transformer 架构（如 XLM-RoBERTa）解决低资源语言的数据稀缺问题，核心矛盾是跨语言迁移效果不稳定。随后，问题扩展至多标签共现与细粒度强度评估，引入 MOS（平均意见分数）等连续值指标，以缓解二元标签对细微情感的简化。2024-2026 年间，研究重心进一步转向可解释性与机制理解，核心问题演变为如何揭示模型内部情感表征机制，并解决 LLM 在复杂语境下的鲁棒性与主观性对齐问题。子问题呈现层级依赖：低资源数据构建是基础，支撑跨语言模型训练；模型性能瓶颈催生集成与主动学习策略；黑盒特性则衍生出可解释性分析与细粒度证据检索需求。

约束演化史清晰地映射了方法的发展轨迹。2016-2018 年，Transformer 架构奠定技术基础，自注意力机制使得捕捉复杂语义成为可能。2020 年，XLM-RoBERTa 的引入标志着跨语言迁移学习的转折，低资源语言开始受益。2021 年，SpanEmo 等工作将任务重构为跨度预测，引入细粒度视角。2023-2025 年，LLM 的爆发推动了生成式解释与神经机制分析，如 CR-Fusion 和 SEER 基准的出现。当前形态表现为数据、模型与解释三者的耦合：数据路线解决资源瓶颈，模型路线解决性能瓶颈，解释路线解决可信度瓶颈。

**如果用一个核心问题概括该领域，那便是：如何在跨语言、低资源及高主观性约束下，构建兼具高精度分类能力与神经机制可解释性的情感表征体系。**

## 2. 方法体系

- 2008：Mihalcea-Strapparava Lyrics Dataset——早期歌词情感标注基线

- 2012：OPUS Parallel Corpus——多语言平行语料支撑

- 2017：Transformer Architecture——自注意力机制奠基

- 2020：XLM-RoBERTa——跨语言迁移学习首选基线

- 2021：SpanEmo——跨度预测范式引入

- 2025：Confidence-Credibility Weighted Ensemble——小模型集成超越大模型

- 2025：CR-Fusion——跨语言情感神经元识别

- 2025：SEER Benchmark——细粒度情感证据检索基准

这条时间线勾勒了该领域方法演进的代表性节点：从 2008 年的 Mihalcea-Strapparava Lyrics Dataset 奠定该领域方法基线，经 2012 年 OPUS Parallel Corpus 的推进，到 2025 年的 Working Emotion Vocabulary Analysis 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 低资源情感数据集

低资源情感数据集的构建是解决数据稀缺问题的基础路线。早期工作如 Mihalcea-Strapparava Lyrics Dataset（2008）展示了艺术语言中情感分析的复杂性，但缺乏细粒度标签。2025 年，MarathiEmoExplain（P6）构建了首个大规模马哈拉施特拉语数据集，整合情感极性、细粒度情绪标签及自然语言解释。该方法基于 L3CubeMahaSent 语料库，通过 GPT-4 辅助生成解释并由人工审核，解决了低资源语言中缺乏可解释情感资源的问题。其代价是依赖 LLM 生成可能引入偏差，且英语解释可能丢失语言特异性。EmoBench-UA（P7）则设计了基于众包平台的乌克兰语情感标注管道，通过多阶段过滤和重叠任务确保数据质量，填补了乌克兰语情感分类数据的空白。其代价是众包标注的主观性需通过质量控制机制缓解。MOS-based Lyric Emotion Benchmark（P1）采用平均意见分数方法，对歌词情感进行 0-5 分强度评分，捕捉多标签情感重叠。其代价是标注成本高，且连续分数可能掩盖离散类别边界。这些数据集为后续模型训练提供了标准基准，与模型优化路线形成互补。

### 2.2 多语言情感检测模型

多语言情感检测模型路线聚焦于跨语言泛化与性能优化。XLM-RoBERTa（2020）作为骨干网络，利用多语言预训练嵌入捕捉跨语言语义相似性，成为低资源语言情感分类的首选基线。Active Learning Multilingual Hope Detection（P2）结合主动学习与 XLM-RoBERTa，通过迭代选择模型最不确定的样本加入标注集，优化了多类别希望检测的性能。其代价是主动学习过程增加标注迭代成本，且模型依赖预训练语料的多语言覆盖度。Confidence-Credibility Weighted Ensemble（P4）提出基于置信度和可信度加权投票的小语言模型集成框架，整合 BERT、RoBERTa 等编码器模型，通过动态调整权重克服传统多数投票的局限性。该方法证明了小模型集成在情感检测上可超越大语言模型，为资源受限场景提供了高效替代方案。其代价是集成计算开销增加，且权重计算依赖验证集质量。与数据路线相比，模型路线更关注算法层面的优化，但两者共同依赖于高质量的多语言数据支撑。

### 2.3 情感可解释性分析

情感可解释性分析路线旨在揭示模型内部情感表征机制。Consistency-Regularized Fusion（CR-Fusion, P5）提出用于大型音频语言模型中多语言情感神经元识别的融合策略，通过一致性正则化筛选跨语言稳定单元。该方法揭示了多语言模型中情感表征的机制，为训练免费的跨语言情感泛化提供了理论基础。其代价是融合过程引入超参数 $\lambda$，需平衡跨语言一致性与语言特异性。Working Emotion Vocabulary Multi-task Analysis（P8）构建多任务评估框架，通过识别、表达和验证任务全面分析 LLM 对细微情感状态的理解。结合心理语言学因素如词频和习得年龄，揭示了 LLM 在情感词汇理解上的局限性。其代价是多任务评估增加实验复杂度，且心理语言学变量可能存在共线性。与模型优化路线相比，可解释性路线更关注理论深度，但实验复杂度高，难以直接应用于实际部署。

### 2.4 细粒度情感证据检索

细粒度情感证据检索路线聚焦于文本中表达情感的具体片段识别。SEER Benchmark（P3）构建基于跨度的情感证据检索基准，评估 LLM 识别文本中具体情感表达片段的能力。该基准包含单句和多句上下文任务，通过人类标注情感证据跨度，超越传统句子级标签。其代价是跨度标注成本高，且模型在长上下文和中性文本中易出现关键词固定和虚假识别。该方法揭示了 LLM 在细粒度情感定位上的局限性，为构建更可靠的情感证据识别模型提供了基准。与可解释性路线相比，证据检索更关注应用层面的定位能力，支持共情对话等精细应用。

### 2.5 跨任务与多领域应用

跨任务与多领域应用展示了情感检测技术在积极话语检测、歌词情感分析等场景的扩展。PolyHope-M 数据集（P2）涵盖英语、德语、西班牙语和乌尔都语，支持多类别希望话语识别。Pop Song Lyrics Emotion Dataset（P1）基于 MOS 方法，评估 LLM 在创造性文本情感归因上的能力。这些应用验证了核心方法在不同领域的有效性，但也暴露了领域特异性挑战，如歌词中的隐喻和文化引用。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

Transformer 架构在情感分类任务中通常优于传统机器学习方法，这一共识在多个基准上被反复验证。例如，XLM-RoBERTa 在 PolyHope-M 上的 0.80 F1 显著优于 Logistic Regression 的 0.72 F1，而 Fine-tuned RoBERTa 在 Pop Song Lyrics 上的 0.33 MAE 优于 Zero-shot Grok 的 0.50 MAE。然而，该共识的边界在于低资源或复杂语境下需结合集成或微调策略。与此相关的另一个共识是 Ekman 基本情感分类法仍是主流标签体系，但需结合强度或跨度信息以提升细粒度。MarathiEmoExplain 和 SEER 基准均引入了强度或跨度标注，反映了这一趋势。

### 3.2 观点分歧

LLM 是否真正“理解”情感状态存在显著分歧。观点 A 认为 LLM 在零样本情感检测中表现优于传统模型，具备一定的情感理解能力；观点 B 认为 LLM 在细粒度强度预测或特定情感证据定位上仍存在显著差距。现有证据偏向观点 B：在 SEER 基准中，LLaMA3.2-3B 的 F1 仅为 0.193，且在长上下文和中性文本中易出现虚假识别。Working Emotion Vocabulary Analysis（P8）揭示 LLM 在情感表达和验证上的不一致性，词频等心理语言学因素影响显著。这一分歧的背后，是跨语言情感迁移是否通用的争论。CR-Fusion（P5）通过一致性正则化筛选跨语言稳定选择性的情感神经元，揭示了部分情感神经元无法跨语言迁移的问题，支持观点 B 的语言特异性立场。

### 3.3 其他开放问题

最紧迫的工程问题是低资源语言数据稀缺与标注成本高，需探索众包与 LLM 辅助生成的平衡。关键困难在于语言间情感表达的文化差异与语义重叠，研究路径包括利用多语言预训练模型进行知识迁移、构建高质量多语言基准数据集。最根本的研究问题是多语言模型中情感表征的跨语言泛化机制不明，部分情感神经元无法跨语言迁移。研究路径包括通过一致性正则化融合策略识别跨语言不变的情感神经元，以及结合心理语言学特征分析 LLM 情感理解偏差。已知的是 Transformer 架构的有效性与 Ekman 体系的主流地位，争议的是 LLM 的情感理解深度与跨语言迁移的通用性，未知的是神经机制层面的情感表征共享原理。

## 4. 总结与展望

多语言多标签情感检测领域的核心矛盾从“数据不足”转向“机制不明”与“主观性对齐”。早期研究通过 Transformer 架构解决了跨语言迁移的基础问题，但当前瓶颈在于如何在低资源、高主观性约束下实现机制透明的精准检测。未来可能突破的方向包括：结合心理语言学特征分析 LLM 情感理解偏差（P8、P5 共同指向），以及探索音频-语言多模态模型中的情感神经元定位（P5 指向）。对进入者而言，最值得做的一件事是构建统一的多语言情感基准，涵盖强度、跨度与解释多维度，以解决当前评测体系碎片化的问题。
