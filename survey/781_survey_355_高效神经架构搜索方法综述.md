## 导读

高效神经架构搜索（Efficient Neural Architecture Search, NAS）旨在解决传统搜索策略因评估候选架构需耗费数千 GPU 天而导致的算力瓶颈，其核心在于重构“架构-性能”映射的获取成本。早期研究通过零成本代理（Zero-Cost Proxy, ZCP）利用未训练网络的统计特性预测性能，以极致的筛选速度换取了对非线性特征捕捉能力的牺牲。随着边缘部署需求激增，硬件感知 NAS 将延迟与能耗纳入优化目标，通过代理预测器替代昂贵的硬件实测，实现了从单一精度向多目标 Pareto 权衡的范式转移。近期，大语言模型（LLM）的引入突破了固定搜索空间的表达力限制，但引入了代码合法性与性能稳定性的新挑战。各路线在评估精度、空间覆盖与计算成本之间做出了不同取舍，由此形成当前评估、生成与硬件协同并存的多元方法格局。本综述梳理这条从统计启发到语义智能的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

高效 NAS 的兴起源于传统方法在评估候选架构时面临的高昂计算成本，这一瓶颈促使研究重心从“搜索策略”转向“性能评估效率”。在形式化定义上，给定搜索空间 $\mathcal{S}$ 与目标函数 $f(\cdot)$，传统 NAS 需对 $\mathcal{S}$ 中每个架构 $a$ 执行完整训练以获取 $f(a)$，其计算复杂度随空间规模指数增长。高效 NAS 的核心任务因此转变为：在极低计算预算下，建立架构结构与最终性能（含硬件资源消耗）之间的高保度映射，并据此高效定位 Pareto 最优解。这一核心任务衍生出三个相互依赖的子问题：架构表示决定了搜索上限，评估代理决定了搜索效率，硬件约束决定了应用落地边界。

问题定义的演化清晰地反映了领域对“成本”认知的深化。2016-2018 年间，以 RL-NAS 和 DARTS 为代表的奠基工作假设架构性能可通过梯度优化直接搜索，但受限于算力，DARTS 等可微分方法虽加速了搜索，仍需完整训练超网络，成本依然高昂。2020 年前后，NASWOT 和 SynFlow 的出现标志着第一个关键转折，通过统计初始化权重或激活值来预测性能，确立了 Training-Free 范式，将评估成本从 GPU 天降至毫秒级。这一转折的约束条件是：传统 NAS 评估瓶颈导致搜索空间无法扩大，急需极低成本筛选器。

2021-2023 年，问题定义从“单一精度”扩展至“硬件感知多目标”。随着边缘设备部署需求激增，仅优化精度不足以生成可部署模型，延迟、能耗与精度的 Pareto 权衡成为新核心。OFA 提出的超网络范式通过权重共享摊销训练成本，但引入了优化间隙和重训练需求。此时，代理预测器（Surrogate）被引入以替代昂贵的硬件实测，解决了硬件异构性导致的性能落差问题。这一阶段的约束变化在于：工程落地需求迫切，要求搜索目标从单目标向多目标演化。

2023-2025 年，领域进入“开放语义空间”与“LLM 增强”的新阶段。GENIUS 首次探索利用 LLM 生成任务特定的神经架构代码，验证了 LLM 在架构设计中的潜在能力。随后，CoLLM-NAS 等协作式框架通过结构化记忆与反思机制提升搜索效率，突破了传统 Cell-based 搜索空间的限制。这一转折的动机是：固定空间难以发现超越人类设计的架构，且 Cell-based 空间表达力受限。然而，LLM 的引入也带来了语法错误与性能不稳定风险，需额外验证机制。

2025-2026 年，研究焦点转向解决 ZCP 的负相关性与硬件协同设计的精细化。NCD 针对激活值 ZCP 中的负相关性问题，提出非线性校正框架；InTrain 则基于信息几何与动力系统理论量化网络优化容量，解决了传统代理指标忽略非线性影响的问题。同时，CIMNAS 等框架将硬件参数纳入搜索空间，实现软硬件联合优化。当前形态呈现出“评估-生成-硬件”三位一体的协同优化特征，LLM 作为智能引导者与 ZCP/Surrogate 作为高效评估器正在融合。

**如果用一个核心问题概括该领域，那便是：如何在极低的计算预算下，建立架构结构与最终性能（含硬件资源消耗）之间的高保度映射，并据此在开放或受限空间中高效定位 Pareto 最优解。**

## 2. 方法体系

- 2017：RL-NAS——利用循环神经网络作为控制器生成架构字符串，通过强化学习策略梯度优化验证集精度，奠定了自动化架构搜索的范式基础，但计算成本极高

- 2018：DARTS——提出可微分架构搜索，将离散操作选择松弛为连续权重优化，通过双梯度下降联合优化架构参数与网络权重，大幅降低搜索成本，成为后续可微分NAS的基石

- 2019：OFA——提出一次训练多模型部署策略，通过预训练超网络并采样子网，解决传统NAS中搜索与训练耦合导致的效率低下问题，实现了搜索与部署的解耦

- 2020：NASWOT——基于未训练网络的激活值相关性构建二进制编码，通过统计激活模式预测架构性能，开创了无需训练即可评估架构质量的零成本代理指标方向

- 2021：SynFlow——利用初始化权重与激活值的乘积计算信号流强度，通过剪枝保留高信号流路径来近似最终精度，提供了基于梯度的零成本评估新视角

- 2023：GENIUS——首次探索利用GPT-4等大语言模型生成任务特定的神经架构代码，验证了LLM在架构设计中的潜在能力，开启了LLM辅助NAS的研究热潮

- 2025：InTrain——提出内在可训练性概念，基于信息几何与动力系统理论量化网络优化容量，通过双向信息分析评估架构潜力，解决了传统代理指标忽略非线性影响的问题

- 2026：ONNX-Net——提出基于ONNX格式的通用架构表示与即时性能预测方法，利用语言模型嵌入捕捉架构语义，实现了跨架构类型的统一表示与高效预测

这条时间线勾勒了该领域方法演进的代表性节点：从 2017 年的 RL-NAS 奠定该领域方法基线，经 2018 年 DARTS 的推进，到 2026 年的 ONNX-Net 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 零成本代理评估

零成本代理（ZCP）路线的起源可追溯至 2020 年的 NASWOT，其核心假设是未训练网络的统计特性（如激活值、梯度）可线性预测最终性能。NASWOT 通过构建激活值相关性二进制编码，实现了近乎零成本的架构筛选，但这一线性假设在高非线性架构上失效，导致预测排名与真实性能排名相反，即“负相关性”问题。SynFlow 随后利用初始化权重与激活值的乘积计算信号流强度，提供了基于梯度的新视角，但仍未能根本解决非线性偏差。

针对这一瓶颈，NCD（P30）通过构建线性与非线性架构的对比实验，揭示高非线性是负相关性的根本原因，指出传统方法违反了代理设计原则中关于非线性影响的假设。NCD 引入随机激活掩码（SAM）与非线性重缩放（NIR），SAM 通过随机屏蔽激活值降低非线性干扰，NIR 则恢复线性近似的有效性。该方法严格遵循代理设计的三个原则，在子空间上应用激活值零成本代理，避免了全局非线性带来的偏差。其代价是引入了额外的掩码与重缩放计算步骤，但相比全量训练，计算开销依然极低。NCD 在 CIFAR-10/100 及 ImageNet 上显著提升了排名相关性，为训练-free NAS 提供了更可靠的评估基础。

InTrain（Zhou et al., 2026, P26）则从动态视角切入，提出内在可训练性（Intrinsic Trainability）作为评估架构潜力的新维度。该方法基于信息几何与动力系统理论，通过双向信息分析框架衡量网络对梯度信号的响应能力，捕捉了架构与优化器之间的交互效应。与传统仅关注初始化状态的代理不同，InTrain 关注网络在优化动态中的行为特征，其核心创新在于将可训练性定义为架构属性，而非依赖于特定训练轨迹。该方法在 ImageNet 等大规模数据集上优于 SynFlow、Zen-score 等现有零成本代理，特别是在高 FLOPs 预算下表现稳定。其局限性在于信息几何计算可能比简单统计量稍复杂，但仍远低于训练成本。InTrain 与 NCD 形成了互补关系：NCD 修正静态统计量的非线性偏差，InTrain 则引入动态优化潜力，二者共同推动了从静态评估向动态潜力评估的转变。

Bi-EZP（Lai et al., 2026, P27）进一步将 LLM 引入 ZCP 发现过程，提出由 LLM 引导的双层程序进化框架。该方法不直接进化架构，而是利用 LLM 生成结构化的架构评分程序，这些程序由多个基础代理指标（如 NASWOT、梯度范数等）组合而成。核心流程包括 LLM 生成候选程序描述、可执行代码门控验证、以及基于 CMA-ES 的连续参数校准。Bi-EZP 的创新点在于将代理发现过程形式化为程序进化问题，利用 LLM 的语义理解能力生成多样化的组合策略，突破了人工设计代理指标的局限性。其代价是 LLM 生成代码的调试与验证开销，但整体仍远低于训练成本。Bi-EZP 与 NCD、InTrain 的关系体现了评估路线与生成路线的融合：LLM 不再直接生成架构，而是优化评估工具本身，为 NAS 评估提供了自适应、可进化的解决方案。

### 2.2 硬件感知协同设计

硬件感知 NAS（HW-NAS）路线的兴起源于边缘设备部署对延迟、能耗与精度的多目标权衡需求。早期方法如 OFA 通过超网络范式解耦搜索与训练，但硬件评估仍依赖特定平台实测，缺乏可迁移性。PlatformX（Tu et al., 2025, P9）提出端到端可迁移的能效感知 NAS 平台，集成了内核级功耗剖析、自动搜索循环与可迁移的能耗预测模型。该平台通过基于 DVFS 设置的延迟测量、毫秒级功耗捕捉以及跨设备能耗预测器，将能耗评估从离线、设备特定的过程转化为在线、可迁移的预测任务。PlatformX 支持多目标优化，在 9.6×10^5 大小的搜索空间中高效运行，在多种边缘设备上实现了 7 GPU-days 内的搜索，显著优于传统 HW-NAS 方法。其代价是能耗预测器需要初始数据集进行训练，且对极端硬件差异的泛化能力有限。

CIMNAS（Krestinskaya et al., 2025, P5）则针对计算内存储（CIM）加速器的非理想性，提出联合优化框架。该方法同时搜索软件参数、量化策略与硬件参数，通过模拟 CIM 硬件的非理想效应（如噪声、非线性），确保搜索出的架构在实际硬件上具有鲁棒性。CIMNAS 的创新点在于将量化策略纳入搜索空间，实现了模型压缩与硬件适配的统一优化。其代价是搜索空间巨大（9.9×10^85 参数组合），需要高效的采样策略与硬件模拟器支持。CIMNAS 与 PlatformX 形成了竞争与互补关系：PlatformX 侧重通用边缘设备的可迁移预测，CIMNAS 侧重专用硬件的联合优化，前者在泛化性上占优，后者在专用硬件精度上更优。

Constraint-Guided HW-NAS（P31）提出通过梯度修改实现约束引导的搜索，将搜索空间建模为过参数化网络，通过连续架构权重与操作权重的联合优化，利用梯度下降同时优化架构选择与网络性能。核心创新在于引入约束引导机制，通过修改梯度方向确保搜索过程满足内存、计算量等硬件约束，避免无效架构的生成。该方法在 EdgeML 场景下实现了精度与硬件资源的高效平衡，其代价是梯度计算与约束投影的额外开销。SNAC-Pack（Weitz et al., 2026, P25）则针对 FPGA 等边缘设备，引入 rule4ml 作为代理模型，在全局搜索阶段估计资源利用率与延迟，避免每次评估都进行耗时的综合。SNAC-Pack 的创新点在于将代理估计嵌入搜索循环，实现了快速反馈与精确综合的平衡，特别适用于 FPGA 这种资源耦合复杂的平台。

RAM-NAS（Mao et al., 2025, P4）专门针对机器人视觉任务，引入子网互蒸馏概念，通过三明治规则采样的所有子网之间进行相互知识蒸馏，提升超网络预训练质量。核心创新在于利用三种机器人边缘硬件的数据训练延迟代理预测器，在搜索阶段估计硬件推理延迟，实现统一的多目标进化搜索。PrototypeNAS（Deutel et al., 2026, P19）则提出零样本 NAS 方法，旨在快速设计适用于微控制器单元（MCU）的深度神经网络。该方法将设计空间探索与目标数据集训练解耦，通过约束多目标优化结合零样本代理指标与 FLOPs 作为计算成本代理，在内存限制约束下搜索原型架构。PrototypeNAS 与 RAM-NAS 均体现了硬件感知路线向特定垂直领域（机器人、MCU）的细化，通过引入领域特定的代理指标与约束，提升了 NAS 在工业部署中的实用性。

### 2.3 大模型驱动搜索

大模型驱动搜索路线的起源可追溯至 2023 年的 GENIUS，其首次探索利用 GPT-4 等大语言模型生成任务特定的神经架构代码，验证了 LLM 在架构设计中的潜在能力。然而，LLM 直接生成代码存在语法错误与性能不稳定风险。CoLLM-NAS（Li et al., 2025, P6）提出协作式 LLM 框架，利用多个 LLM 角色（如架构师、评估员、反思者）进行分工协作，通过结构化记忆存储历史搜索轨迹与性能反馈，指导后续架构生成。CoLLM-NAS 的创新点在于引入协作机制与记忆模块，解决了单一 LLM 在长序列生成中的遗忘与偏差问题，提升了搜索的多样性与收敛速度。其代价是多 LLM 交互带来的通信与计算开销，但相比全量训练仍具优势。

LLM as a Tool（Yoshimura et al., 2026, P22）则提出代码挖掘树变换框架，将 LLM 作为工具而非代理用于 NAS。该方法将 DNN 架构表示为层次树，进化步骤定义为树变换，利用 LLM 生成变换操作（如模块替换、连接调整）。核心创新在于利用 LLM 的代码理解能力生成有效的树变换，同时保持架构的部署兼容性，避免了 LLM 直接生成代码的不可控性。LLM as a Tool 与 CoLLM-NAS 形成了路线分歧：前者视 LLM 为代码变换器，核心搜索逻辑仍由传统算法主导；后者视 LLM 为协作智能体，直接参与架构生成与评估。前者在稳定性与效率上表现更好，后者在新颖性上占优但失败率高。

Resource-Efficient Iterative LLM-NAS（Gu et al., 2026, P18）提出资源高效的迭代 LLM-based NAS 框架，通过反馈记忆机制提升搜索效率。该方法构建闭环流水线，包括代码生成器（LLM）、验证器与评估器、以及提示改进器（LLM），利用历史反馈记忆存储最佳代码与错误诊断。核心创新在于引入自动化故障诊断与反馈记忆，解决了 LLM 生成代码执行失败的问题，提升了搜索的鲁棒性。HypoExplore（Koo et al., 2026, P21）提出假设驱动的多智能体框架，用于视觉识别领域的自主神经架构发现。该方法维护发现状态（实验谱系与假设统计），通过选择父节点与假设集，执行实例化、执行与分析的研究循环。HypoExplore 的创新点在于引入假设驱动机制，利用结构化记忆决定探索方向与测试机制，突破了预定义搜索空间的限制，实现了开放空间下的架构发现。

LLM-NAS（Zhu et al., 2025, P7）提出 LLM 驱动的硬件感知 NAS 方法，旨在优化精度与推理延迟的权衡。该方法利用 LLM 生成架构候选，并通过延迟优化提示策略引导 LLM 生成多样化延迟范围的架构。核心创新在于利用 LLM 的语义理解能力生成符合硬件约束的架构，并通过提示工程优化搜索覆盖度，解决了传统 LLM 生成架构延迟分布不均的问题。LLM-NAS 与 CoLLM-NAS 的关系体现了 LLM 驱动路线与硬件感知路线的融合：LLM 不仅生成架构，还通过提示工程优化硬件约束下的搜索覆盖度，为边缘设备上的自动化模型设计提供了 LLM 驱动的解决方案。

### 2.4 高效搜索算法

高效搜索算法路线聚焦于加速 NAS 的优化算法与搜索策略，包括可微分松弛、进化算法改进、贝叶斯优化及分布式并行计算。PNAG（P29）提出渐进式神经架构生成方法，通过粗到细的线性生成过程重构架构，解决传统生成方法计算密集且易产生无效架构的问题。该方法将架构生成分解为多个自回归单元，每个单元代表一个完整的子架构，通过线性生成减少高维潜空间中的计算开销。核心创新在于引入约束嵌入机制，在生成过程中实时验证架构合法性，避免了后处理过滤的浪费。PNAG 与 LLM as a Tool 形成了互补关系：前者通过线性生成提升效率，后者通过树变换提升灵活性，二者均致力于解决生成过程中的无效架构问题。

Grammar-Based Sequence Alignment（Gómez Martín et al., 2025, P12）提出基于文法序列对齐的进化架构搜索方法，利用 Smith-Waterman 算法变体作为编辑距离度量与交叉算子。该方法将架构表示为文法派生树的序列化令牌，通过约束 Smith-Waterman 交叉（CSWX）实现组件级比较与子代生成。核心创新在于将序列对齐技术引入 NAS，提供了高效、灵活的架构比较与重组机制，支持复杂拓扑结构的进化。该方法在 einbase 等文法搜索空间中验证了有效性，为表达力更强的搜索空间提供了高效进化策略，推动了 NAS 向更广泛架构空间扩展。

Predictor-Free Federated NAS（Khan and Daneshtalab, 2026, P14）提出无预测器且硬件感知的联邦 NAS 方法，通过 Pareto 引导的超网络训练实现高效搜索。该方法在联邦学习场景下，利用超网络范式处理系统异构性，通过 Pareto 前沿引导子网选择，避免依赖昂贵的性能预测器。核心创新在于将 Pareto 优化与联邦学习结合，解决了非 IID 数据与硬件异构的双重挑战，无需额外预测器即可实现硬件感知搜索。RevoNAD（Chang et al., 2025, P13）提出反思式进化探索框架，用于神经架构设计（NAD），旨在合成高层架构原则为具体设计模式。该方法利用 LLM 驱动的构造性推理与结构化探索，通过设计线索记忆（inspirations）指导架构变换。RevoNAD 的创新点在于引入反思机制与线索记忆，解决了传统进化算法在高层架构设计中的盲目性问题，提升了搜索的语义理解与方向性。

Dual-Domain Representation Alignment（Zhang et al., 2026, P20）提出双域表示对齐方法，通过几何感知架构搜索桥接 2D 与 3D 视觉任务。该方法构建混合 VSS-ViT 超网络，利用状态空间动态（VSS 块）提取细粒度几何先验，平衡局部敏感性与全局语义一致性。核心创新在于引入几何感知机制，解决了权重共享范式中的表示崩溃与排名不一致问题，提升了 2D-to-3D 迁移的架构适应性。OptiProxy-NAS（Lyu et al., 2025, P1）提出基于优化代理的端到端 NAS 方法，旨在平衡搜索效率与架构质量。该方法利用优化代理作为预测器，引导架构采样，同时支持任意真实世界指标（如精度、延迟）的优化。OptiProxy-NAS 的创新点在于将优化代理与搜索策略解耦，支持灵活的目标函数定义，解决了传统代理指标单一的问题。

### 2.5 架构表示与预测

架构表示与预测路线研究架构编码、嵌入及性能预测模型，通过图神经网络、语言模型嵌入或元学习构建通用表示，提升预测器泛化能力。ONNX-Net（Qin et al., 2025, P8）提出基于 ONNX 格式的通用架构表示与即时性能预测方法，旨在解决 NAS 中架构表示限制与预测泛化问题。该方法将架构转换为 ONNX 中间表示，利用语言模型（如 ModernBERT）嵌入捕捉架构语义，实现跨架构类型（CNN、Transformer）的统一表示。ONNX-Net 的创新点在于利用 ONNX 的标准化格式与语言模型的语义理解能力，突破了传统图神经网络表示的局限，提升了预测器的泛化能力。

HyperNAS（Lv et al., 2025, P3）提出通过超网络增强架构表示的 NAS 预测器，旨在提升架构关系理解与预测准确性。该方法集成神经预测器与共享超网络，利用 GCN 编码器提取节点与细胞特征，通过全局架构编码方案聚合细胞特征以推导全局特征。HyperNAS 的创新点在于引入超网络机制，捕捉架构间的共享结构与关系，解决了传统预测器忽略架构内部依赖的问题。Meta-Learning Predictors（Deng and Xiao, 2026, P23）提出元学习预测器用于 NAS，旨在解决小样本场景下的性能预测问题。该方法利用元学习框架，从少量标注架构中学习预测器参数，实现快速适应新搜索空间或数据集。

COLE（Somu et al., 2026, P24）提出面向代码的语言模型嵌入方法，用于代理辅助 NAS。该方法将架构直接映射为 Python 类定义（PyTorch 模块），利用语言模型在软件语料上的预训练能力，捕捉架构的代码语义。COLE 的创新点在于利用代码作为原生模态，突破了传统图表示的局限，提升了语言模型在架构预测中的有效性。FGP（Kim et al., 2025, P10）提出基于生成预文本任务的神经架构编码方法，旨在学习架构内的信息流表示。该方法通过前向与反向传播随机向量（消息）模拟前向与反向传播，构建信息流代理作为预训练目标，训练架构编码器捕捉信息流特征。GraDE（Yang et al., 2026, P15）提出图扩散估计器用于 NAS 中的频繁子图发现，旨在揭示架构的基本结构属性。该方法利用图扩散模型学习架构图的分布，生成具有相似结构的样本，通过频繁子图模式发现优化效率与设计。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

领域最核心的共识在于传统基于强化学习或进化算法的 NAS 方法计算成本过高，必须引入代理评估或权重共享机制。这一共识在多个基准上被反复验证：NCD 的 0.773 与 InTrain 的 0.752 均大幅超越 NASWOT 的 0.769 和 SynFlow 的 0.741，表明代理评估在降低计算成本的同时保持了较高的预测精度。与此相关的另一个共识是硬件约束（延迟、能耗、内存）是边缘部署场景下架构设计的关键目标，仅优化精度不足以生成可部署模型。PlatformX 的 21.6 AP 与 RAM-NAS 的 21.5 AP 均显著优于 FBNet 的 20.3 AP，证明了多目标优化在硬件感知 NAS 中的必要性。

然而，该共识存在边界与反例。零成本代理（ZCPs）虽然高效，但单独使用存在精度偏差，通常需与其他方法（如超网络采样或 LLM 引导）结合使用。NCD 和 InTrain 在 NAS-Bench-201 上的优势依赖于 Cell-based 搜索空间的固定结构，而在开放搜索空间中，ZCP 的负相关性可能加剧。此外，超网络（Supernet）范式通过权重共享显著降低了搜索成本，但存在子网性能低于独立训练的问题，Constraint-Guided HW-NAS 的 94.20% 与 DARTS 的 94.00% 仅提升 0.20 个点，暗示超网络范式的性能上限已接近饱和。

### 3.2 观点分歧

零成本代理（ZCP）的理论基础存在根本分歧：静态统计量 vs 动态可训练性。观点 A（NCD, SynFlow）认为 ZCP 基于初始化状态的统计特性足以预测性能，负相关性源于非线性处理不当，可通过校正解决；观点 B（InTrain）认为静态统计量无法捕捉架构在优化过程中的动态行为，必须引入信息几何与动力系统理论量化“内在可训练性”。现有证据偏向观点 B 在高 FLOPs/复杂架构上的优越性（InTrain 在 ImageNet 上优于 SynFlow），但观点 A 在低预算/简单架构上仍具成本优势。这一分歧的背后，是另一个更根本的争论：LLM 在 NAS 中的角色是生成器还是工具？

观点 A（GENIUS, CoLLM-NAS）认为 LLM 应具备架构设计能力，作为生成器直接产出代码或引导进化，实现开放式探索；观点 B（LLM as a Tool, Bi-EZP）认为 LLM 应作为工具，仅用于代码变换、代理组合或提示优化，核心搜索逻辑仍由传统算法主导。现有证据偏向观点 B 在稳定性与效率上的可行性（LLM as a Tool 在 CIFAR-10 上达到 93.50%，且代码执行成功率高），但观点 A 在突破空间限制上潜力更大（HypoExplore 的 94.11% 领先）。分歧根源在于 LLM 的“幻觉”问题尚未根本解决，缺乏评估 LLM 生成架构“新颖性”与“有效性”平衡的标准指标。

### 3.3 其他开放问题

最紧迫的工程问题是硬件预测器的跨平台迁移与 LLM 代码的自动化验证。PlatformX 的可迁移能耗预测器在极端硬件差异上泛化能力有限，CIMNAS 的联合优化搜索空间巨大，计算成本高昂。研究路径包括构建跨平台硬件预测器、开发能效驱动的多目标 NAS 方法，以及探索硬件感知的架构压缩技术。最根本的研究问题是 Transformer 架构的高效搜索与跨域泛化。当前 NAS 方法主要聚焦于卷积神经网络，难以适应新兴的 Transformer 和混合架构需求。难点在于 Transformer 架构的复杂性和计算开销，需要开发高效的搜索算法和代理评估方法。潜在技术路径包括设计针对 Transformer 的零成本代理、开发硬件感知的 Transformer 架构搜索方法，以及探索混合架构的统一搜索空间。

已知—争议—未知认知图谱显示：已知代理评估的必要性、硬件约束的关键性、LLM 的潜力；争议 ZCP 的理论基础、LLM 的角色定位、硬件感知实现路径；未知 Transformer 高效搜索、开放空间探索-利用平衡、架构可解释性。发展趋势将向语义化、硬件协同化与开放式探索深度融合，LLM 与代理模型的融合将催生“自进化”的 NAS 系统。

## 4. 总结与展望

高效 NAS 的核心矛盾在于架构空间爆炸式增长与评估算力线性增长的失衡，这一矛盾驱动了从统计启发到语义智能的范式演进。早期工作通过零成本代理降低评估成本，中期通过硬件感知多目标优化解决部署问题，近期通过 LLM 引导突破空间限制。核心瓶颈在于代理指标的负相关性、硬件预测器的泛化性、以及 LLM 生成架构的可靠性。回扣第 1 章锚点句，如何在极低计算预算下建立高保度映射，仍是贯穿始终的主线。

未来可能突破的方向包括：扩展搜索空间以涵盖 Transformer 和混合架构，利用 LLM 增强架构搜索的多样性和效率，以及开发零成本代理以提升评估效率。这些方向需 ≥2 篇论文共同指向，如 ONNX-Net 与 COLE 均探索语言模型嵌入，PlatformX 与 CIMNAS 均聚焦硬件协同设计。对进入者最值得做的一件事是：在统一骨干与统一预训练条件下，系统评估 LLM 引导 ZCP 发现（如 Bi-EZP）与动态可训练性评估（如 InTrain）在开放搜索空间中的协同效应，以解决评估精度与空间覆盖的平衡问题。
