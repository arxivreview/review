# A Survey of Speculative Decoding for LLM Inference Acceleration ｜大语言模型投机解码加速方法综述 ｜arxivreview

综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/Speculative%20Decoding%20for%20LLM%20Inference%20Acceleration)

## 导读

大语言模型（LLM）自回归解码受限于内存带宽，导致推理延迟高企，投机解码（Speculative Decoding, SD）通过“草稿-验证”范式打破这一串行瓶颈，实现了无损加速。早期研究聚焦于独立草稿模型与目标模型的分布对齐，思路直观但受限于接受率上限。当树状验证与特征对齐技术引入后，研究者利用更强的并行能力与更深的特征耦合换取硬件利用率与接受率的提升。各路线在训练成本、部署灵活性与加速比之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从串行瓶颈到并行验证的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

大语言模型推理效率的核心矛盾在于自回归解码的串行特性与硬件内存带宽限制之间的冲突。在低并发场景下，LLM 推理主要受限于内存带宽（Memory-Bound），即数据从 HBM 加载到 GPU 缓存的时间远大于计算时间，导致算术强度不足。投机解码通过引入轻量级草稿模型并行预测候选 token，再由目标模型单次并行验证，将串行解码转化为并行验证，从而在不改变输出概率分布（无损加速）的前提下提升吞吐量。这一范式于 2023 年由 Leviathan et al. 和 Chen et al. 独立提出，标志着 LLM 加速研究从模型压缩转向推理算法优化。

问题形式化可表述为：给定目标模型 $p_t$ 和草稿模型 $p_d$，在 $N$-way $K$-shot 的解码过程中，草稿模型自回归生成长度为 $K$ 的候选序列，目标模型并行验证并应用拒绝采样，确保最终输出分布与 $p_t$ 一致。核心指标为接受长度 $\tau$，即每个草稿-验证周期中平均被接受的 token 数量，它直接决定了加速比的上限。子问题之间存在严格的依赖关系：草稿模型的质量（接受率）是基础，决定了验证阶段的有效负载；验证策略的效率依赖于草稿生成的结构（线性或树状）；系统架构优化则依赖于前两者的算法特性以最大化硬件利用率。

范式边界清晰地将投机解码与有损压缩区分开来。量化、剪枝等技术通过牺牲部分精度换取速度，而投机解码严格保证输出分布与目标模型完全一致，这是其作为“无损加速”方案的核心优势。然而，无损性也带来了约束：验证阶段必须执行完整的拒绝采样，任何对验证逻辑的修改都可能破坏无损性，这限制了验证策略的优化空间。早期研究在 2016-2018 年间已探索过基于独立预测的并行采样框架（如 Draft&Verify），但受限于仅适用于零温度贪心解码，无法保证非贪心采样下的分布一致性，因此未能成为主流。

2023 年是该领域的奠基之年，Leviathan et al. 和 Chen et al. 确立了“草稿-验证”范式，SpecInfer 引入树状验证优化硬件利用率，REST 提出基于检索的无训练加速方法，奠定了三大基础方向。2024 年，研究重心转向提升草稿质量与系统效率，EAGLE 通过特征对齐显著提升接受率，DistillSpec 提供蒸馏理论指导，BASS 优化批处理注意力，解决了早期方法在复杂任务上接受率低、GPU 利用率不足的问题。2025-2026 年，领域进入精细化与多模态扩展阶段，HASS 解决长序列稳定性，TETRIS 解决批处理级联失败，DREAM 和 SpecVLM 拓展至多模态场景，HSD 和 VIA-SD 优化验证效率，研究热点从单一文本生成扩展至长上下文、多模态及高并发场景。

这一演进过程反映了约束条件的变化：早期受限于草稿模型与目标模型的分布差异，中期受限于硬件并行利用率不足，当前则受限于长上下文显存瓶颈、多模态输入下的草稿效率以及高并发批处理中的调度复杂性。方法如何因应约束变化而演变，构成了该领域发展的主线。

**如果用一个核心问题概括该领域，那便是：如何在保持目标模型输出分布严格一致性的约束下，通过并行化验证机制最大化单位时间内的有效 Token 生成吞吐量。**

## 2. 方法体系

- 2018：Draft&Verify——提出基于独立预测与并行解码的早期并行采样框架

- 2023：Speculative Decoding——确立“草稿-验证”范式，实现无损加速

- 2023：SpecInfer——提出基于树结构的推测推理与验证系统

- 2023：REST——提出基于检索的推测解码方法

- 2024：EAGLE——提出基于特征对齐的自回归草稿模型

- 2024：DistillSpec——提出通过知识蒸馏优化草稿模型的方法

- 2025：HASS——提出和谐化推测采样方法

- 2026：VIA-SD——提出基于模型内路由的验证方法

这条时间线勾勒了该领域方法演进的代表性节点：从 2018 年的 Draft&Verify 奠定该领域方法基线，经 2023 年 REST 的推进，到 2026 年的 VIA-SD 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 草稿模型训练优化

草稿模型的质量是决定投机解码加速比的关键因素，早期研究假设草稿模型可以是独立的轻量级模型，通过知识蒸馏对齐目标模型分布。DistillSpec（Zhou et al., 2023, P2）探索了前向 KL 散度、反向 KL 散度和总变差距离等不同散度目标，发现总变差距离理论上能最大化接受率，但实践中前向 KL 散度表现更稳定，揭示了理论最优与实际性能之间的差距。该方法的代价是蒸馏过程需要额外的计算资源，且对训练数据的质量敏感，但它为草稿模型训练提供了理论指导，证明了知识蒸馏在推测解码中的有效性。

2024 年，EAGLE（Li et al., 2024, P4）针对独立小模型在复杂任务上接受率低的问题，提出基于特征对齐的自回归草稿模型。该方法利用目标模型倒数第二层的隐藏状态作为草稿模型的输入，并结合移位 token 输入以处理随机性，通过回归损失和交叉熵损失的联合训练，在特征空间和 token 空间同时对齐草稿模型与目标模型。EAGLE 放弃了模型独立性，换取了更高的接受率，其代价是增加了草稿模型的输入维度，需要额外的全连接层进行特征降维，且草稿模型与目标模型耦合更紧。这一范式转变解决了独立小模型在跨域场景下原型崩溃的问题，成为后续特征级推测解码的代表性工作。

2025 年，HASS（Zhang et al., 2024, P13）针对 EAGLE 在长序列生成中上下文不一致的问题，提出和谐化推测采样方法。该方法通过和谐化目标蒸馏和和谐化上下文对齐两个关键步骤，确保草稿模型在训练和推理阶段的行为一致，利用多步前向传播对齐草稿模型与目标模型的隐藏状态。HASS 放弃了训练过程的简洁性，换取了长序列生成中的稳定性，其代价是增加了训练过程中的前向传播次数，但这一开销在离线训练阶段是可接受的。GRIFFIN（Hu et al., 2025, P22）进一步解决了特征不一致问题，通过引入 token 引导融合（TGF）和 token 增强头（TEH）两个关键模块，系统性地解决了草稿模型中 token 与特征不一致的问题，提升了草稿 token 的准确性，同时保持了特征生成的稳定性。

与独立小模型路线相比，特征对齐路线在 MT-Bench/GSM8K 等基准上显著领先，EAGLE/HASS 的加速比（~3.5x）远高于独立小模型（~1.5x-2.0x）。然而，独立小模型在资源受限或需要频繁更新目标模型的场景下仍有优势，且特征对齐的额外计算开销在边缘设备上可能不可接受。这一路线与无训练路线形成互补：特征对齐追求高精度，无训练追求零成本。

### 2.2 无训练与检索加速

无训练与检索加速路线旨在解决草稿模型训练成本高的问题，利用外部知识库或模型内部状态生成草稿候选。REST（He et al., 2023, P3）提出基于检索的推测解码方法，利用外部数据存储库检索历史上下文中的 n-gram 作为草稿候选，无需训练额外的草稿模型。REST 放弃了通用性，换取了零训练成本，其代价是依赖外部数据集的质量和覆盖范围，且检索过程可能引入延迟。该方法特别适用于具有丰富历史数据的场景，如代码生成和翻译。

2025 年，Cacheback（Ma et al., 2025, P33）提出基于缓存表的推测解码方法，利用语言局部性原理，将最近观察到的 n-gram 存储在缓存表中，通过查询缓存表生成草稿树，无需训练额外模型。Cacheback 利用 LRU 策略更新缓存表，确保最近使用的 n-gram 优先被检索，提升了草稿生成的准确性。其代价是缓存表的内存开销，但这一开销相对于推理加速收益是可接受的。Token Recycling（Luo et al., 2024, P11）提出 token 回收机制，将被拒绝的 token 存储在一个回收池中，并在后续推测步骤中作为候选草稿使用，利用被拒绝 token 的局部相关性，减少草稿生成的计算开销，同时保持推测解码的无损性。

与特征对齐路线相比，无训练路线在 Spec-Bench 上表现稳定（~2.0x），但在开放域对话中效果有限，因为检索或缓存表难以覆盖所有可能的上下文。这一路线与特征对齐路线形成竞争：无训练路线追求部署灵活性，特征对齐路线追求加速比上限。在低资源或特定任务场景下，无训练路线更具竞争力。

### 2.3 验证策略与理论

验证策略的效率决定了硬件利用率和接受率，早期研究假设验证过程是串行的 Token 级检查。2023 年，SpecInfer（Miao et al., 2023, P1）提出基于树结构的推测推理与验证系统，通过生成多个候选分支并并行验证，最大化接受率，并引入了树注意力机制以高效处理分支验证。SpecInfer 放弃了验证逻辑的简单性，换取了 GPU 并行能力的充分利用，其代价是增加了验证过程的内存开销（KV Cache）和计算复杂度。这一范式转变解决了线性验证在低并发下 GPU 利用率低的问题，是推测解码在系统层面的重要里程碑。

2024 年，Block Verification（Sun et al., 2024, P6）提出块级验证策略，将验证过程从 token 级扩展到块级，通过并行评估多个前缀并选择最优块，减少了验证过程中的串行依赖。Multi-Draft Speculative Sampling（Khisti et al., 2024, P14）提出多草稿推测采样方法，通过规范分解和理论极限分析优化多草稿验证，提升了验证效率。2025 年，Traversal Verification（Weng et al., 2025, P28）提出遍历验证算法，证明了其在树结构推测解码中的无损性，通过遍历树节点并动态调整接受概率，解决了传统 token 级验证在树结构中的次优问题。TETRIS（Wu et al., 2025, P23）提出最优草稿 token 选择方法，通过区分序列内和序列间的 token 依赖关系，动态选择最可能被验证通过的草稿 token，最大化批处理场景下的期望输出 token 数，解决了批处理推测解码中的级联失败问题。

2026 年，HSD（Zhou et al., 2026, P35）提出分层推测解码方法，通过块级验证和 token 级验证的结合，解决了联合不可行性问题，在保持无损性的同时提升了验证效率。VIA-SD（Xian et al., 2026, P41）提出基于模型内路由的验证方法，通过动态模型内路由构建精简验证器，利用两级置信度阈值进行分层验证，解决了传统验证器计算开销大的问题。这些方法在保持无损性的前提下，进一步优化了验证效率，代表了当前验证策略的前沿。

与草稿模型训练优化路线相比，验证策略路线更关注硬件利用率和理论边界，两者相互依赖：草稿质量决定验证收益，验证策略决定硬件效率。树状验证在高并发和长序列场景下显著优于线性验证，但在内存受限场景下，线性验证仍具竞争力。

### 2.4 系统架构与硬件

系统架构优化致力于解决批处理与分布式环境下的同步与通信开销，早期研究假设单 GPU 优化即可满足需求。2024 年，BASS（Qian et al., 2024, P8）提出批处理注意力优化的推测采样方法，通过批处理矩阵乘法（Batch MatMul）优化注意力计算，解决了推测解码在批处理场景下的内存访问瓶颈，实现了高吞吐量下的低延迟推理。DSI（Timor et al., 2024, P9）提出分布式推测推理方法，将多个草稿模型分布在不同的硬件上，通过并行推测和验证，证明了其在保持无损性的同时能显著降低推理延迟。DSI 放弃了单卡实现的简洁性，换取了大规模部署下的延迟降低，其代价是增加了分布式系统的通信开销。

2025 年，EasySpec（Wu et al., 2025, P20）提出层并行推测解码方法，通过模糊推测和 bonus 校准在多 GPU 间并行化草稿生成阶段，解决了推测解码在分布式系统中的同步开销问题。PipeInfer（Butler et al., 2024, P10）提出异步流水线推测方法，通过异步执行草稿生成和验证阶段，减少了硬件空闲时间，提升了推理效率。LongSpec（Yang et al., 2025, P25）提出长上下文无损推测解码方法，通过设计常数内存使用的草稿模型架构和锚点偏移索引训练策略，实现了长上下文下的高效推测解码，解决了长上下文场景下的内存瓶颈。

与验证策略路线相比，系统架构路线更关注端到端性能和硬件利用率，两者相互依赖：验证策略决定算法特性，系统架构决定硬件效率。分布式推测推理在大规模部署下显著优于单 GPU 优化，但在小规模场景下，通信开销可能抵消加速收益。

### 2.5 多模态与特定场景

多模态与特定场景路线旨在解决视觉、音频、视频等多模态输入下的草稿对齐问题，早期研究假设文本 SD 策略可直接复用。2024 年，On Speculative Decoding for Multimodal LLMs（Gagrani et al., 2024, P7）证明仅使用语言模型作为草稿模型即可有效加速视觉-语言模型的推理，无需在草稿模型中处理图像 token，降低了多模态推测解码的复杂度。2025 年，SpecVLM（Ji et al., 2025, P31）提出基于验证器引导的 token 剪枝方法，利用目标模型的注意力信号指导草稿模型的视频 token 剪枝，减少了草稿模型的输入长度，提升了视频 LLM 的推测解码效率。DREAM（2025, P45）提出基于精炼目标特征和熵自适应交叉注意力融合的多模态推测解码方法，通过精炼目标模型的视觉特征并自适应融合到草稿模型，解决了多模态输入下草稿模型与目标模型特征不一致的问题。

2026 年，Multi-Scale Local SD（Peruzzo et al., 2026, P34）提出多尺度局部推测解码方法，利用低分辨率草稿模型进行粗到细的生成，并通过局部验证减少重采样范围，解决了图像生成中 token 不确定性高的问题。Spec-VLA（Wang et al., 2025, P30）提出针对视觉-语言-动作模型的推测解码方法，通过引入松弛接受机制，允许同义词被接受，平衡了动作生成的准确性和效率。这些方法在保持无损性的前提下，针对特定场景进行了优化，代表了当前多模态推测解码的前沿。

与文本 SD 路线相比，多模态路线更关注模态间信息压缩与对齐，两者相互依赖：文本 SD 提供基础范式，多模态路线解决特定场景问题。多模态推测解码在 VLM/Video-LLM 上显著优于直接复用文本策略，但在低资源或特定硬件下，结论尚存争议。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

LLM 推理在低并发下主要受内存带宽限制而非计算能力限制，投机解码通过增加算术强度有效缓解此瓶颈，这一共识在约 70 篇论文中得到共同支持。投机解码是一种无损加速技术，其输出分布与目标模型完全一致，区别于有损压缩或近似推理，这一共识在约 65 篇论文中得到共同支持。草稿模型的质量（接受率）是决定投机解码加速比的关键因素，提升草稿与目标模型的分布对齐是核心研究方向，这一共识在约 60 篇论文中得到共同支持。树状验证（Tree-based Verification）比线性链验证能更有效地利用 GPU 并行能力，提高硬件利用率和接受率，这一共识在约 40 篇论文中得到共同支持。知识蒸馏是训练高效草稿模型的主要手段，通过最小化草稿与目标模型分布的散度（如 KL 散度）来提升接受率，这一共识在约 35 篇论文中得到共同支持。在长上下文场景下，KV 缓存管理成为投机解码的主要挑战，需要专门的压缩或稀疏化策略以维持效率，这一共识在约 25 篇论文中得到共同支持。投机解码与批处理（Batching）存在协同效应，但需要复杂的调度策略以平衡不同序列的草稿长度和验证开销，这一共识在约 20 篇论文中得到共同支持。多模态大语言模型（MLLMs）的推理加速需要针对视觉 token 的特殊处理，如剪枝或跨模态草稿，直接复用文本 SD 策略效果有限，这一共识在约 15 篇论文中得到共同支持。

### 3.2 观点分歧

特征对齐草稿与独立小模型草稿之间的分歧是领域内的主要争论之一。特征对齐路线（如 EAGLE, HASS）利用目标模型隐藏状态，接受率高，但耦合紧，训练复杂；独立小模型路线（如 PLD, DistillSpec）部署灵活，可独立训练，但接受率相对较低，需蒸馏对齐。现有证据偏向特征对齐，在 MT-Bench/GSM8K 等基准上，EAGLE/HASS 的加速比（~3.5x）显著高于独立小模型（~1.5x-2.0x），证据强度高，基于大规模 LLM 实验。然而，独立小模型在资源受限或需要频繁更新目标模型的场景下仍有优势，且特征对齐的额外计算开销在边缘设备上可能不可接受，导致分歧未决。

树状验证与线性验证之间的分歧是另一个主要争论。树状验证路线（如 SpecInfer, TETRIS）并行验证多分支，硬件利用率高，接受概率高；线性验证路线（标准 SD）实现简单，内存开销小，适合低并发或内存受限场景。现有证据偏向树状验证，在高并发和长序列场景下，树状验证的吞吐量（Throughput）显著高于线性验证，证据强度高，基于 GPU 硬件实验。然而，树状验证的内存开销（KV Cache）在长上下文场景下可能成为瓶颈，线性验证在内存受限场景下仍具竞争力，导致分歧未决。

严格无损与松弛验证之间的分歧是第三个主要争论。严格无损路线（标准 SD, HSD）保证输出分布与目标模型完全一致，适用于通用场景；松弛/奖励引导路线（RSD, MARS）允许轻微偏差，提升特定任务效率，适用于数学、代码等任务。现有证据偏向严格无损，因为无损性是 SD 的核心优势，且在通用对话中松弛验证可能导致质量下降。但在数学推理任务中，RSD 显示效率提升（1.5x vs 1.0x），证据强度中等，基于特定任务实验。缺乏统一的“质量-效率”权衡指标，不同任务对偏差的容忍度不同，难以一概而论，导致分歧未决。

### 3.3 其他开放问题

多模态投机解码的通用性是当前的工程瓶颈，解决视觉、音频、视频等多模态输入中草稿模型与目标模型分布不匹配的问题，难点在于模态间信息压缩与对齐，潜在路径包括跨模态特征融合、模态自适应验证策略及多模态草稿模型架构设计。长上下文场景下的内存与延迟优化是另一个工程瓶颈，解决长序列生成中 KV 缓存内存爆炸和草稿模型延迟增加的问题，难点在于如何在保持无损性的同时压缩草稿侧内存，潜在路径包括滑动窗口注意力、KV 缓存压缩、锚点-偏移索引训练及混合树注意力机制。批量推理与投机解码的协同优化是第三个工程瓶颈，解决批量处理中不规则张量（ragged tensor）导致的验证效率低下问题，难点在于同步不变量维护与对齐开销，潜在路径包括跨批次调度、动态草稿 token 选择、层并行推测及分布式推测推理。

草稿模型训练与推理的对齐是当前的研究未知，解决训练目标（如 KL 散度）与推理目标（接受率）不一致导致的性能损失，难点在于容量受限草稿模型的优化，潜在路径包括直接接受率优化损失、选择性知识蒸馏、任务感知提案分布及在线学习更新。无损性与质量权衡的精细化控制是另一个研究未知，解决严格无损验证在低置信度区域导致的效率损失，难点在于如何在不牺牲生成质量的前提下放宽验证标准，潜在路径包括边际感知验证、奖励引导解码、多级验证路由及松弛接受策略。硬件感知与系统级集成是第三个研究未知，解决投机解码在异构硬件（GPU/FPGA/边缘设备）上的部署效率问题，难点在于硬件特定优化与算法的耦合，潜在路径包括硬件加速解码、CUDA 图优化、量化感知推测及边缘设备专用推理引擎。

## 4. 总结与展望

投机解码通过“草稿-验证”范式成功将 LLM 推理从内存受限转化为计算受限，实现了无损加速。核心矛盾在于如何在保持目标模型输出分布严格一致性的约束下，通过并行化验证机制最大化单位时间内的有效 Token 生成吞吐量。尝试过的路线包括独立小模型、特征对齐、无训练检索、树状验证、分布式推测、多模态适配等，核心瓶颈在于草稿模型与目标模型的分布对齐、长上下文显存瓶颈、多模态输入下的草稿效率以及高并发批处理中的调度复杂性。

未来可能突破的方向包括：多模态投机解码的通用性，解决视觉、音频、视频等多模态输入中草稿模型与目标模型分布不匹配的问题，潜在路径包括跨模态特征融合、模态自适应验证策略及多模态草稿模型架构设计；长上下文场景下的内存与延迟优化，解决长序列生成中 KV 缓存内存爆炸和草稿模型延迟增加的问题，潜在路径包括滑动窗口注意力、KV 缓存压缩、锚点-偏移索引训练及混合树注意力机制；批量推理与投机解码的协同优化，解决批量处理中不规则张量导致的验证效率低下问题，潜在路径包括跨批次调度、动态草稿 token 选择、层并行推测及分布式推测推理。对进入者最值得做的一件事是：在统一骨干与统一预训练条件下，系统评测不同路线在长上下文、多模态和高并发场景下的性能，建立统一的“质量-效率”权衡指标，为后续研究提供公平比较的基础。
