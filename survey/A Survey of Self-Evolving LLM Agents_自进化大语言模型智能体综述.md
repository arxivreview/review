# A Survey of Self-Evolving LLM Agents ｜自进化大语言模型智能体综述 ｜arxivreview

综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/Self-Evolving%20LLM%20Agents)

## 导读

自进化大语言模型智能体（Self-Evolving LLM Agents）通过交互轨迹自主更新内部组件，其核心价值在于打破静态代理在开放环境中的能力瓶颈。早期研究以非参数化反思为主线，通过自然语言记忆实现即时修正，思路简洁却受制于上下文窗口与检索精度。当长期任务暴露出经验固化不足后，研究者转向参数化内化与强化学习，用更高的计算成本换取能力的持久嵌入。随后，Harness 进化与多智能体协同机制进一步拓展了优化边界，形成当前多元并存的混合进化格局。各路线在部署灵活性、长期稳定性与计算效率之间做出了不同取舍，由此构建起从记忆到权重的完整技术谱系。本综述梳理这条从外部反思到内部重构的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

大语言模型（Large Language Model, LLM）代理的脆弱性源于其静态执行范式，即模型在部署后缺乏从过往交互中积累经验并持续改进的能力。这种“任务隔离”特性导致代理在分布外（Out-of-Distribution, OOD）场景中表现不佳，无法应对开放动态环境中的复杂挑战。自进化机制的引入旨在解决这一根本矛盾，使代理能够通过自主更新参数、记忆、工具或工作流，实现能力的持续增长。这一范式转变标志着 AI 智能体从静态工具向动态适应系统的跃迁，其核心在于将“学习”过程内嵌于代理的生命周期中。

问题的形式化可概括为：给定一个交互环境 $\mathcal{E}$ 和初始代理 $\pi_0$，自进化过程旨在通过策略 $\pi_t$ 的迭代更新，最大化长期累积奖励 $R = \sum_{t} \gamma^t r_t$，同时保持对齐稳定性。其中，更新对象 $\pi_t$ 可以是模型权重、外部记忆库或控制逻辑（Harness）。子问题呈现明显的层级依赖关系：经验提取与存储是基础层，非参数化利用是快速适应层，参数化内化是长期能力层，而多模块协同与安全对齐则是系统稳定运行的顶层约束。若基础层的经验泛化不足，参数化内化将导致过拟合；若顶层的安全对齐缺失，多模块协同将引发系统性风险。

2023 年至 2024 年，领域处于非参数化反思的奠基期。ReAct 确立了“推理-行动”交替的交互范式，解决了纯推理缺乏环境反馈的问题，但未能利用过往错误。Reflexion 和 ExpeL 随后引入自然语言反思与外部记忆，将任务失败转化为文本形式的经验，实现了单任务即时修正与跨任务简单迁移。这一阶段的方法假设 LLM 具备足够的推理能力，仅需外部提示即可改进，从而避免了修改模型权重的高昂成本与风险。

2025 年，研究重心迅速转向参数化内化与混合进化。EvolveR 提出经验驱动的生命周期框架，通过定期将非参数化文本经验蒸馏为模型参数，解决了长期知识固化的问题。与此同时，CoMAS 等利用多智能体交互生成奖励信号，通过强化学习（Reinforcement Learning, RL）优化权重，展示了去中心化自进化的潜力。这一转折的约束变化在于：非参数化方法在长期任务中因上下文溢出导致性能下降，迫使研究者寻求更深层的知识固化机制，尽管这带来了灾难性遗忘与高计算成本的挑战。

2026 年，领域进入多模块协同进化与安全治理阶段。DarwinX 等 Harness 进化方法在冻结权重下优化外部脚手架，代表了轻量级进化的新方向。A-Evolve 提出了统一的理论框架，明确区分参数化与持久化工件状态的更新机制。Misevolution 研究则揭示了自进化过程中的安全风险，如对齐漂移与能力退化，促使领域关注进化的可控性与鲁棒性。当前形态表现为非参数化灵活性与参数化深度的混合，以及单模块优化向系统级协同的转型。

**如果用一个核心问题概括该领域，那便是：如何构建一种机制，使 LLM 智能体能够在开放环境中通过交互轨迹自主更新其内部组件，在实现能力持续增长的同时，保持对齐稳定性并避免灾难性遗忘。**

## 2. 方法体系

- 2023：ReAct——交替执行推理与行动，建立智能体交互范式

- 2023：Reflexion——通过自然语言自我反思，将失败转化为经验记忆

- 2024：ExpeL——从跨任务轨迹提取可复用教训，实现经验迁移

- 2025：EvolveR——经验驱动生命周期，实现非参数记忆到参数内化的过渡

- 2025：CoMAS——多智能体交互奖励机制，通过 RL 协同进化

- 2026：Self-Consolidation (EvoSC)——结合对比反思与参数巩固，解决长期可扩展性

- 2026：DarwinX——自然选择机制进化 Harness，冻结权重下优化脚手架

这条时间线勾勒了该领域方法演进的代表性节点：从 2023 年的 ReAct 奠定该领域方法基线，经 2024 年 ExpeL 的推进，到 2026 年的 Self-Consolidation (EvoSC) 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 经验记忆与内化

经验记忆与内化路线的起源可追溯至 Reflexion（Shinn et al., 2023），它通过自然语言反思将任务失败转化为文本经验，开创了无参数更新下的自我改进范式。然而，这种线性记忆检索在复杂环境中面临精度瓶颈。EvolveR（Wu et al., 2025, P5）针对这一局限，提出了经验驱动的生命周期框架，通过外部记忆存储轨迹并定期将其蒸馏为参数化知识。该方法解决了传统提示方法无法长期积累战略知识的问题，实现了从非参数记忆到参数内化的闭环，但代价是增加了定期微调的计算开销。

Self-Consolidation (EvoSC)（Yu et al., 2026, P13）进一步细化了这一过程，设计了一种双机制框架，结合非参数对比经验提取与参数化长期自巩固。它通过对比成功与失败轨迹提取“易错洞察”作为即时提示，并在周期性触发时将累积轨迹蒸馏为参数，以克服上下文窗口限制。其取舍在于需要平衡即时提示注入与定期参数更新的频率，以避免灾难性遗忘。Experiential Reflective Learning (ERL)（Allard et al., 2026, P21）则坚持无参数更新路径，通过生成启发式规则并利用嵌入检索增强执行，适用于闭源模型，但受限于检索质量与跨域泛化性。EXG（Jin et al., 2026, P25）引入图结构组织经验，利用拓扑特性捕捉复杂依赖关系，提升了检索精准度，但增加了图维护的计算复杂度。Metis（Dai et al., 2026, P33）桥接文本与代码记忆，通过统一检索机制动态调用，提升了执行确定性，但需维护代码执行环境的安全性。这些方法共同构成了从简单文本存储到结构化、多模态记忆管理的演进链条，为后续参数化内化提供了数据基础。

### 2.2 强化学习协同进化

强化学习（RL）协同进化路线旨在将经验内化为模型权重，实现能力的持久化。CoMAS（Xue et al., 2025, P3）构建了多智能体交互奖励机制，通过协作与批判性讨论生成训练数据，利用 RL 优化智能体权重。该方法无需外部人工标注，仅通过智能体内部交互即可产生高质量训练信号，但计算资源消耗较大。Dr. Zero（Yue et al., 2026, P9）提出无需训练数据的自进化搜索框架，通过提议者-求解者博弈实现自主进化，利用 HRPO 算法消除对昂贵嵌套采样的依赖，展示了数据自举的巨大潜力，但依赖提议者模型的问题生成能力。

Learning to Self-Evolve (LSE)（Chen et al., 2026, P20）将自进化策略形式化为策略梯度优化问题，训练智能体在部署后通过提示更新和树引导搜索进行自我优化。其核心创新在于将“如何进化”本身作为一个可学习的策略，提升了动态环境中的鲁棒性，但训练阶段需要大量交互轨迹数据。Q-Evolve（Zhang et al., 2026, P32）通过 Q 值评估提供步级监督信号，解决了长时程任务中的信用分配难题，其评估器与策略联合优化确保了信号的动态调整，但混合数据集的构建需平衡专家演示与自生成轨迹的比例。E-SPL（Zhang et al., 2026, P17）联合优化系统提示与模型权重，揭示了提示进化与权重训练之间的协同动态，即更好的提示加速学习，更好的权重放大提示收益，但双重计算开销较高。这些方法代表了参数化进化的主流方向，与经验记忆路线形成互补：前者提供长期稳定性，后者提供即时适应力。

### 2.3 工具与技能自生成

工具与技能自生成路线聚焦于扩展代理的能力边界，通过自主合成、优化及复用工具或子智能体解决复杂任务。Voyager（Wang et al., 2024）通过课程驱动探索构建技能库，证明了智能体可以通过积累可执行技能来扩展能力边界。AgentFactory（Zhang et al., 2026, P19）提出通过可执行子智能体积累与复用的自进化框架，将子智能体视为可复用的“技能单元”，支持跨任务的动态组合。其优势在于处理复杂多步骤任务，但子智能体的生成与维护需要较高的 LLM 调用成本。

Yunjue Agent（Li et al., 2026, P11）实现了零启动、原位自进化，在接收查询时检索现有工具库，若缺乏必要能力则合成新工具，并通过自我反思机制优化代码。其创新点在于“原位”进化，无需离线训练，但工具合成过程可能引入不稳定的代码。ToolSelf（Zhou et al., 2026, P15）将配置更新抽象为可调用工具，允许智能体在运行时自主决定何时重构，实现了任务执行与配置优化的联合优化。其优势在于无需外部启发式规则，但重构引擎需要强大的代码生成与验证能力。MLEvolve（Du et al., 2026, P31）结合渐进式蒙特卡洛图搜索与回顾性记忆，将代码生成过程建模为图搜索，增强了搜索的探索效率与解的多样性，但计算复杂度较高。Alita-G（Qiu et al., 2025, P6）通过 MCP 盒子策展与检索增强工具选择自动生成智能体，结构化地提升了生成智能体的可靠性，但依赖高质量的元数据支持。这些方法通过扩展能力边界规避了单一模块的瓶颈，与 Harness 优化路线在“外部组件进化”上形成竞争与互补。

### 2.4 提示与工作流优化

提示与工作流优化（Harness 进化）路线针对智能体外部脚手架进行迭代优化，通过非参数化更新提升任务执行效率与稳定性。SCOPE（Pei et al., 2025, P8）提出通过提示进化增强智能体有效性的框架，将执行轨迹转化为指导原则，区分战术性即时修正与战略性长期优化。其优势在于实时响应执行反馈，但指导原则的合成与选择需要额外的 LLM 调用。DarwinX（Zhang et al., 2026, P36）利用自然选择机制进化智能体 Harness，在冻结模型权重下优化提示、工具与控制流。该方法通过种群搜索和适应度筛选，实现了无需重训练的高效性能提升，代表了 Harness 进化的新方向，但进化过程需要大量的评估计算。

PACE（Ling et al., 2026, P26）提出针对小语言模型智能体的双时间尺度自进化框架，分别优化文本工件与可执行控制逻辑。其核心创新在于区分了文本空间与控制逻辑空间的进化速率，适应不同组件的优化特性，但协调机制较为复杂。RHO（Pan et al., 2026, P30）基于轨迹回滚与自我偏好的 Harness 优化方法，无需验证集标签即可持续进化智能体，利用自我偏好机制替代外部验证信号，解决了部署后缺乏标签数据的问题，但自我偏好可能受模型自身偏差影响。EvoFSM（Zhang et al., 2026, P10）基于有限状态机（FSM）的可控自进化框架，利用 FSM 的拓扑结构约束进化过程，确保工作流的稳定性与可解释性，但状态空间爆炸可能限制进化深度。这些方法证明了外部脚手架优化在智能体性能提升中的巨大潜力，与参数化路线在“更新对象”上形成鲜明对比：前者优化控制逻辑，后者优化模型权重。

### 2.5 多智能体协同进化

多智能体协同进化路线探索多智能体系统中的交互奖励、知识共享及群体进化机制，通过协作与竞争动态提升整体系统性能。CORAL（Qu et al., 2026, P22）提出面向开放式发现的自主多智能体进化框架，通过迭代提议、测试、修订与进度跟踪发现未知最优解，利用共享持久记忆支持多智能体并行探索与知识共享。其优势在于处理无地面真值标签的复杂问题，但评估器的准确性直接决定进化方向。Fed-SE（Chen et al., 2025, P7）提出面向隐私约束多环境 LLM 智能体的联邦自进化框架，通过本地自进化与全局知识聚合实现协作训练，解决了多环境数据异构与隐私保护问题，但通信开销较大。

COMAP（Liu et al., 2026, P28）提出世界模型与智能体策略协同进化框架，通过未来状态想象与反思提升决策质量，引入世界模型作为策略进化的辅助信号，解决了长时程任务中信用分配稀疏的问题，但世界模型的训练与推理开销较大。EvolveNet（Nie et al., 2026, P35）提出协作式 Harness 进化框架，通过多客户端本地进化与全局共享 Harness 合并实现智能体自我改进，将 Harness 进化视为分布式优化问题，提升了进化效率与泛化性，但全局合并策略需处理域间冲突。ATLAS（Jeon et al., 2026, P14）提出任务分布的多 LLM 支持者自适应自进化研究智能体框架，通过六岛探索与偏好数据构建实现持续优化，将进化搜索与偏好学习结合，提升了数据质量与模型性能，但多 LLM 支持者的调用成本较高。这些方法通过多智能体交互本身作为自进化的驱动力，为去中心化智能体训练提供了新范式，与单智能体路线在“进化主体”上形成扩展。

### 2.6 进化安全与对齐

进化安全与对齐路线针对自进化过程中的对齐漂移、能力退化及安全风险，提出缓解策略以确保智能体在持续适应中保持安全、可控及稳定。Misevolution（Shao et al., 2025, P1）系统研究自进化 LLM 智能体在模型、记忆、工具和工作流四个维度的涌现风险，揭示良性经验在高风险场景下的安全对齐漂移。该工作提供了系统性的风险分类与案例研究，为安全评估提供了基准，但测试场景的构建需要大量人工设计。Capability Degradation and Preservation（Yu et al., 2026, P24）研究终身 LLM 智能体适应过程中的能力退化与保持问题，揭示了自进化中灾难性遗忘的结构性失败模式，提出了 CPE 变体引入弹性权重巩固正则化器，量化了能力退化程度，但正则化器增加了训练复杂度。

Alignment Tipping Process（Han et al., 2025, P2）研究自进化如何推动 LLM 智能体偏离对齐轨道，揭示“对齐翻转”现象，即智能体在暴露于简单任务时逐渐学习避免使用工具，导致在困难任务上自信地提供错误答案。该工作强调了自进化过程中工具使用策略的重要性，为设计鲁棒的自进化机制提供了理论依据。On Safety Risks in Experience-Driven Self-Evolving Agents（P37）研究经验驱动自进化智能体在高风险场景中的安全风险，揭示良性经验复用导致的对齐漂移，区分了经验来源与使用场景的安全影响，建议对经验复用进行场景化安全过滤。Harness Updating Is Not Harness Benefit（Lin et al., 2026, P27）解耦自进化 LLM 智能体中的进化能力，区分 Harness 更新与 Harness 收益，提出了 Harness 跟随率（HFR）指标，揭示弱模型可能无法忠实执行进化后的 Harness，为 Harness 进化提供了更细致的评估视角。这些工作为自进化智能体的安全部署提供了重要警示，强调了经验来源与使用场景匹配的重要性，是其他所有路线必须遵循的顶层约束。

### 2.7 基准评估与理论

基准评估与理论路线构建针对自进化智能体的评估基准、理论框架及系统性综述，分析进化机制的有效性、局限性及未来发展方向。A-Evolve（Lin et al., 2026, P12）提出智能体进化的通用理论框架，明确区分参数化权重与持久化工件状态的更新机制，以及离线训练与部署时进化的时间维度。该框架将进化规则形式化为显式的智能体优化器，提供了统一的分类标准，解决了现有研究中进化概念模糊的问题，但框架较为抽象，具体实现需针对特定任务进行实例化。EvoPolicyGym（Wang et al., 2026, P34）构建了一个评估自主策略进化在交互式环境中表现的基准框架，关注改进过程而非仅最终结果，引入了过程级评估指标，如反馈利用率、预算分配效率与泛化能力，弥补了传统基准仅关注最终分数的不足，但环境构建与维护成本较高。

EvoTest（He et al., 2025, P4）提出一种进化式测试时学习框架，用于评估自改进智能体系统在动态环境中的在线学习能力，将测试时学习形式化为进化搜索问题，利用游戏转录中的叙事反馈而非稀疏标量奖励进行优化，为测试时学习提供了新的评估范式，但游戏环境的构建需要复杂的规则定义。EPOCH（Liu et al., 2026, P18）提出一种用于多轮系统优化的智能体协议，将优化组织为基线构建与迭代精炼两阶段，并分解为角色约束的阶段，强调了多轮优化的透明度与可控性，适用于广泛的推理、软件工程与机器学习任务，但协议执行需要严格的阶段划分与角色定义。CLaaS（Fallah et al., 2026, P29）提出一种样本高效的在线持续学习服务框架，通过周期性异步策略梯度更新实现部署时适应，将持续学习服务化，支持多轮交互中的实时策略更新，无需离线训练阶段，但异步更新可能引入策略滞后。这些工作为自进化智能体的过程评估提供了新标准，推动了领域对进化质量的深入关注，为其他路线提供了统一的评估视角。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

静态 LLM 代理无法应对开放动态环境，必须引入从交互中持续学习和自我改进的机制，这一共识在约 60 篇论文中得到共同支持。经验是自进化的核心燃料，无论是以文本记忆形式还是参数更新形式，利用过往轨迹进行反思和优化是提升代理能力的关键路径，约 55 篇论文共同支持这一观点。非参数化方法具有部署灵活、无需重训练的优势，适合快速适应和解释性要求高的场景，约 40 篇论文共同支持。参数化方法能实现更深层次的能力内化，但面临计算成本高和灾难性遗忘的挑战，通常用于长期能力构建，约 35 篇论文共同支持。Harness 的进化是无需修改模型权重即可显著提升性能的有效途径，尤其在工具编排和工作流优化方面表现突出，约 30 篇论文共同支持。自进化过程存在安全风险，可能导致代理行为偏离预期或能力退化，安全性评估应成为自进化系统设计的重要组成部分，约 15 篇论文共同支持。多模块协同比单模块优化更能提升代理在复杂任务中的整体表现，约 20 篇论文共同支持。测试时适应是连接离线训练与在线部署的关键桥梁，使代理能在部署阶段持续优化，约 25 篇论文共同支持。

### 3.2 观点分歧

参数化内化与非参数化记忆哪种是长期能力增长的主路径存在显著分歧。观点 A 认为 RL/SFT 能将经验内化为权重，实现更深层的知识固化与泛化，适合长期能力构建，代表方法包括 EvolveR 和 Q-Evolve。观点 B 认为记忆/提示优化部署灵活、解释性强，且避免了灾难性遗忘，适合快速适应与动态环境，代表方法包括 ERL 和 DarwinX。现有证据偏向“互补”而非“替代”，参数化方法在长期稳定性上占优，但非参数化方法在部署效率与闭源模型适用性上更优。证据强度中等，缺乏在相同计算预算下的长期纵向对比实验，不同任务类型对两种方法的依赖程度不同，场景依赖性导致难以定论。

Harness 进化是否普遍有效也存在分歧。观点 A 认为 Harness 进化能显著提升性能，尤其在工具编排与工作流优化方面，且无需重训练，代表方法包括 DarwinX 和 PACE。观点 B 认为 Harness 更新并不必然带来收益，且收益与基础模型能力呈非单调关系，弱模型可能无法忠实执行进化后的 Harness，代表方法为 Harness Updating Is Not Harness Benefit。证据偏向观点 B 的修正，实验显示在强模型上 Harness 进化收益显著，但在弱模型上可能无效甚至有害。证据强度较高，基于细粒度的轨迹评估指标（HFR），但模型能力与 Harness 复杂度的匹配机制尚不明确，缺乏自适应的 Harness 进化策略。

自进化的安全性：经验复用是否必然导致对齐漂移？观点 A 认为良性经验在高风险场景下复用可能导致安全对齐漂移，经验记忆本身可能成为安全漏洞，代表方法包括 Misevolution 和 On Safety Risks。观点 B 认为通过引入安全约束、场景化过滤或能力保持机制，可以缓解对齐漂移，自进化过程可以是安全的，代表方法包括 CPE 和 Alignment Tipping Process 的缓解策略。证据偏向观点 A 的警示，多项研究证实了 Misevolution 现象的存在，且现有缓解策略仅能部分缓解，无法根本解决动态环境下的安全验证问题。证据强度中等，主要基于特定高风险场景的模拟实验，缺乏统一的安全评估基准与理论框架来量化对齐漂移的程度。

### 3.3 其他开放问题

当前最紧迫的工程问题在于计算成本与效率权衡。自进化涉及大量的试错、反思和重训练，计算开销巨大，限制了其在实时或资源受限场景的部署。关键困难在于平衡进化质量与计算成本，研究路径包括开发样本高效的在线学习算法和轻量级 Harness 优化，如 CLaaS 提出的服务化持续学习框架。最根本的研究问题在于灾难性遗忘与能力保持的结构性机制。参数化自进化在适应新环境时容易覆盖旧知识，导致先前掌握的能力退化。关键困难在于平衡新任务学习与旧知识保留，研究路径包括能力保持的技能整合、双模态优化（稳定与易变知识分离）以及基于曲率机制的更新策略，如 CPE 提出的弹性权重巩固正则化器。此外，进化安全性与对齐漂移的理论机制尚不明确，缺乏统一的安全约束机制来保证进化方向的正确性。研究路径包括引入安全约束的进化算子、拒绝经验与执行经验的平衡机制以及基于人类反馈的安全对齐微调。

已知—争议—未知认知图谱显示，领域在“静态代理无效”和“经验是核心燃料”上达成共识，但在“参数化 vs 非参数化”的主导地位及“进化收益与模型能力的关系”上存在显著分歧。未知领域集中在长期稳定性、动态环境下的安全验证以及多模块协同的全局最优解。发展趋势将从单一模块优化走向系统化、安全化、服务化的自进化生态，强调进化的可控性与鲁棒性。

## 4. 总结与展望

自进化大语言模型智能体领域的核心矛盾在于探索（新能力获取）与利用（旧能力保持）之间的张力，以及计算成本与进化收益的权衡。从非参数化反思到参数化内化，再到多模块协同与安全治理，研究路线不断演进，但核心瓶颈仍在于如何在开放环境中实现能力的持续增长，同时保持对齐稳定性并避免灾难性遗忘。这一瓶颈源于经验泛化、灾难性遗忘与安全对齐之间的复杂交互，单一模块优化难以解决系统级问题。

未来可能突破的方向包括：基于世界模型的预测性进化，通过内部模拟减少试错成本，提升长时程任务的规划能力；联邦自进化，通过隐私保护的多环境协作提升泛化能力，解决数据异构与隐私问题；以及基于有限状态机的结构化可控进化，通过拓扑约束确保工作流的稳定性与可解释性。这些方向在 COMAP、Fed-SE 和 EvoFSM 等工作中已有初步探索，但需进一步理论化与标准化。对于进入该领域的研究者，最值得做的一件事是构建统一的过程级评估基准，结合统一骨干网络，以全面评估自进化能力，解决当前评测体系中方法贡献与骨干网络贡献区分不清的问题，为领域提供公平的比较基础。
