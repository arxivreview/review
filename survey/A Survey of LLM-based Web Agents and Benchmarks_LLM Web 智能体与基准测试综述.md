## 导读

大语言模型（LLM）的推理突破使自动化处理复杂网页交互成为可能，早期基于规则脚本的方法因泛化能力差而逐渐被弃用。ReAct 框架确立了推理与行动交替的决策范式，将智能体从静态动作模仿推向动态环境适应。随着 WebArena 等基准将评估从封闭合成环境推向半真实网络，长程任务中的脆弱性与上下文爆炸问题暴露无遗。多模态大模型的引入解决了纯文本解析在复杂 UI 布局下的接地误差，而记忆机制与系统级安全防御则成为应对动态噪声与提示注入攻击的关键。当前领域正从单纯追求任务成功率转向鲁棒性、安全性与可解释性的系统平衡，形成了架构分层化与感知多模态化的方法格局。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

LLM Web 智能体领域的兴起源于对自动化处理复杂、动态网页交互任务的迫切需求。早期研究主要依赖基于规则的脚本或简单的强化学习，其核心假设是网页环境静态且可完全观测，这导致模型在面临未见过的 UI 布局或动态内容时泛化能力极差。随着 LLM 在推理与规划能力上的突破，研究重心转向利用自然语言意图直接驱动数字环境操作，旨在实现从“脚本执行”到“自主决策”的跨越。这一转变不仅降低了标注成本，更赋予了智能体处理长程、多步骤任务的潜力，但也引入了幻觉与不可控性等新挑战。

问题的形式化定义经历了从低层动作序列匹配到端到端任务完成的根本性变形。在 N-way K-shot 的少样本设定下，智能体需从少量演示中习得新网站的交互模式，但 Web 环境的开放性使得这一设定难以直接适用。当前更通用的形式是将任务定义为序贯决策过程：智能体在状态 $s_t$ 下观察网页内容（DOM 或截图），生成动作 $a_t$（如点击、输入），并接收环境反馈 $r_t$，目标是在有限步骤内最大化累积奖励或达成特定目标状态。这一形式化强调了感知接地（Grounding）与规划鲁棒性的耦合，即动作的准确性依赖于对网页元素的精确定位，而规划的连贯性则依赖于对历史状态的准确记忆。

子问题之间存在强依赖关系，构成了一个多维耦合系统。感知接地是执行的前提，若无法将自然语言指令准确映射到具体 DOM 节点或像素坐标，后续动作必然失效。记忆机制是长程规划的基础，缺乏对历史交互的有效存储与检索，智能体在步骤增多后易出现“迷失在中间”现象，导致性能急剧下降。安全防御则是上述能力在开放环境中得以部署的必要约束，若不解决提示注入等恶意操纵问题，智能体在真实网络中的自主性将转化为安全风险。这种依赖关系意味着单一维度的优化往往以牺牲其他维度为代价，例如过度强调安全隔离可能限制智能体的灵活性。

范式边界从合成环境向真实开放网络的迁移是领域发展的关键驱动力。2017 年的 MiniWoB 奠定了 Web 智能体自动化交互的基础，但其简化的合成界面无法反映真实网站的复杂性。2022 年 WebShop 引入了更真实的单域交互场景，提升了评估保真度，但仍缺乏跨域泛化能力。2023 年 ReAct 框架的提出确立了 LLM 作为智能体核心决策引擎的地位，同年 WebArena 和 Mind2Web 的发布将评估推向真实或半真实环境，揭示了智能体在长程任务中的脆弱性。2024 年 VisualWebArena 的引入解决了纯文本解析的局限，推动了多模态感知的发展。2025-2026 年，研究重心进一步转向鲁棒性、安全性与记忆机制，BrowserArena 等基准开始评估真实开放网络中的动态交互，而 MUZZLE 等红队测试框架则系统化地评估了智能体在对抗环境下的表现。

**如果用一个核心问题概括该领域，那便是：如何在开放、动态且充满对抗性噪声的真实网络环境中，构建具备长期记忆、可解释规划且能抵御恶意操纵的自主决策系统，以实现从“模拟环境中的任务执行”到“真实世界中的可靠代理”的跨越。**

## 2. 方法体系

- 2017：MiniWoB——奠定 Web Agent 自动化交互基础的早期合成基准

- 2022：WebShop——引入更真实单域交互场景的模拟电商环境

- 2023：ReAct——确立推理与行动交替范式的核心架构

- 2023：WebArena——提供自托管多域端到端评估的标准化基准

- 2024：VisualWebArena——扩展至视觉接地任务的多模态评估基准

- 2025：SynthAgent——基于合成监督实现 Web Agent 快速适应的方法

- 2026：WebWorld——用于高效训练 Web Agent 的大规模世界模型

这条时间线勾勒了该领域方法演进的代表性节点：从 2017 年的 MiniWoB 奠定该领域方法基线，经 2022 年 WebShop 的推进，到 2026 年的 WebWorld 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 智能体架构与规划

早期 Web 智能体主要依赖线性 ReAct 循环，通过交替生成推理轨迹和执行动作来增强决策的可解释性。然而，线性轨迹在长程任务中一旦早期步骤出错，后续全部失败，缺乏错误恢复机制，导致成功率随步骤数增加而急剧下降。Branch-and-Browse（He et al., 2025, P7）针对这一痛点，提出了基于树结构推理和动作记忆的 Web 探索方法。其核心创新在于维护一个树状的动作历史结构，允许智能体在遇到失败时回溯并尝试替代路径，而非线性执行。该方法结合了树搜索的全局视野和 ReAct 的局部推理，通过动作记忆避免重复无效操作，显著减少了在复杂导航中的冗余步骤。与传统的线性轨迹方法相比，它牺牲了推理效率与实时性，换取了长程任务的稳定性与可控性。

WebDART（Yang et al., 2025, P6）则从动态分解与重规划的角度解决了复杂任务中的性能崩溃问题。其核心思路是将复杂任务动态分解为一系列模块化子任务，并按顺序执行，每个子任务具有明确的提取、导航或执行目标。当子任务执行失败或环境变化时，智能体能够重新评估剩余任务并调整计划。与静态规划方法不同，WebDART 强调分解的灵活性和子任务间的互补性，确保每个子任务既可行又完整。这种动态规划策略显著提升了智能体在处理高复杂度任务时的鲁棒性，但其代价是增加了规划阶段的计算开销。

记忆机制的引入进一步提升了长程任务的表现。WebCoach（Liu et al., 2025, P11）提出了基于跨会话记忆引导的自我进化框架，通过轻量级插件层增强现有智能体的记忆能力。其核心组件包括 WebCondenser 用于压缩轨迹、外部记忆存储（EMS）用于持久化经验，以及 Coach 模块用于提供记忆感知指导。该方法通过函数调用与 Actor Agent 通信，无需修改内部工作流即可实现模型无关的性能提升。与依赖短期上下文的智能体不同，WebCoach 利用长期记忆避免重复错误，如重新访问相同链接或卡在登录门。这种记忆增强机制使智能体能够从历史交互中学习，逐步优化其在复杂 Web 环境中的导航策略，但引入了记忆投毒的安全风险。

Avenir-Web（Li et al., 2026, P18）则代表了多模态架构的前沿，提出了模仿人类经验的多模态 Web 智能体框架。其核心创新在于通过经验模仿规划（EIP）生成战略路线图和可验证的成功标准，确保任务执行的连贯性。MoGE 模块通过混合多个接地专家，解决单一模型在元素定位上的不确定性，提升了交互的鲁棒性。与通用多模态智能体不同，Avenir-Web 强调通过结构化检查表跟踪任务进度，防止长程任务中的目标偏移。这种模块化架构将推理与执行解耦，提高了系统在动态 Web 环境中的可靠性和可解释性，但增加了系统复杂度。

### 2.2 数据合成与训练

高质量多步骤交互轨迹的标注成本极高，且真实网站反爬虫限制多，难以获取大规模训练数据。SynthAgent（Wang et al., 2025, P9）针对这一问题，提出了基于合成监督的 Web 智能体适应方法。其核心流程包括在新环境中合成任务、生成轨迹、并通过自动评估筛选高质量数据用于微调。该方法无需人工介入即可使智能体适应未见过的网站，显著降低了数据收集成本和时间。与依赖人工标注的现有方法不同，SynthAgent 实现了完全自动化的环境适应流程，提升了智能体的泛化能力，但合成数据可能存在分布偏差。

WebWorld（Xiao et al., 2026, P21）则从世界模型的角度解决了真实网络交互慢、成本高且存在反爬虫限制的问题。其核心创新在于训练一个因果 LLM 作为世界模型，基于指令和历史状态动作序列预测未来状态，从而模拟真实网络交互。该方法通过最大似然估计训练专用模型，提升了状态预测的准确性和一致性，支持大规模离线训练。与基于提示的世界模型不同，WebWorld 提供了安全、可控且高效的替代方案，但世界模型预测误差会累积，导致训练-测试差距。

AutoSurfer（Faisal et al., 2026, P28）提出了通过综合浏览、学习和建模来教导 Web 智能体的方法。其核心流程包括使用 LLM 推理发现简单任务、组合逻辑连接的简单任务以合成复杂任务、以及精炼任务元组以减少幻觉。该方法将精炼后的任务元组转换为监督微调（SFT）数据集，用于训练 LLM 执行接地的 GUI 动作。与随机游走遍历不同，AutoSurfer 采用系统性探索策略，确保任务覆盖的多样性和逻辑连贯性，为 Web 智能体提供了高质量、多样化的训练数据。

Structured Distillation（Lù and Reddy, 2026, P25）则通过结构化蒸馏 Web 智能体能力以实现泛化。其核心创新在于定义 Agent-as-Annotators 框架，实例化任务定义、接地、执行、评估等六个模块，实现全自动轨迹合成。该方法通过蒸馏前沿模型的能力到小型开源模型，使小模型在 WebArena 等基准上超越大型闭源模型。与直接微调不同，它强调了结构化数据合成在能力迁移中的关键作用，提升了小模型的效率和泛化性，为部署轻量级、高性能的 Web 智能体提供了可行的技术路径。

### 2.3 安全攻击与防御

提示注入是 Web 智能体部署中面临的最严峻安全挑战，现有模型对此类攻击普遍脆弱。WAInjectBench（Liu et al., 2025, P4）提出了针对 Web 智能体提示注入检测的基准，模拟攻击者通过修改网页内容操纵智能体执行恶意动作。其核心设计区分了网站所有者和用户级攻击者，定义了不同的攻击能力和目标，如点击欺诈或敏感信息泄露。与仅关注直接提示注入的基准不同，它强调了间接注入在 Web 交互中的具体实现和后果，为评估 Web 智能体的安全鲁棒性提供了标准化的测试框架。

MUZZLE（Syros et al., 2026, P20）提出了自适应 Agentic 红队框架，用于自动发现 Web 智能体针对间接提示注入攻击的漏洞。其核心流程包括侦察阶段收集智能体行为轨迹、识别高杠杆注入面、以及自动化生成和评估攻击路径。该方法无需人工指定注入点，通过自然语言描述对抗目标，实现了非专家可用的安全评估。与手动红队测试不同，MUZZLE 实现了攻击发现的自动化和规模化，覆盖了多种智能体架构和模型，揭示了现有防御机制的盲区。

WebSentinel（Wang et al., 2026, P19）提出了检测和定位 Web 智能体提示注入攻击的方法。其核心设计包括分析页面主要目的、描述 UI 段功能，并应用类型特定的检查以检测重复元素或注入迹象。该方法通过对比页面整体意图与局部元素行为，识别出与正常流程不一致的恶意注入。与基于规则的黑白名单不同，WebSentinel 利用 LLM 的语义理解能力进行细粒度分析，提升了检测的准确性和泛化性，为 Web 智能体提供了实时的安全防护层。

ceLLMate（Meng et al., 2025, P13）则从系统级防御的角度提出了沙箱化浏览器 AI 智能体的框架。其核心设计是在浏览器 HTTP 层面强制执行由管理员、用户或网站开发者指定的策略，阻止未授权的操作。该方法假设攻击者控制不可信域名或可信域名的部分内容，利用智能体的环境权限进行攻击。与仅依赖模型对齐的防御不同，ceLLMate 提供了程序化的权限控制，确保智能体行为符合安全策略，有效限制了攻击的影响范围，但可能限制智能体的自主性与灵活性。

### 2.4 基准测试与评估

评估体系正从“静态快照匹配”向“动态过程诊断”与“对抗鲁棒性测试”转型。BrowserArena（Anupam et al., 2025, P5）构建了基于真实开放网络的智能体评估平台，通过收集用户提交的任务并运行 Arena 式头对头对比来衡量智能体性能。其核心创新在于引入步骤级人类反馈机制，能够细粒度地标注智能体轨迹中的失败点，从而揭示具体的失败模式。该方法突破了传统沙盒环境任务多样性受限的瓶颈，直接评估智能体在动态、不可控的真实网页环境中的表现，为理解当前 Web 智能体的脆弱性和多样性提供了实证基础。

ClawBench（Zhang et al., 2026, P26）设计了用于评估 AI 智能体完成日常在线任务能力的基准，涵盖订票、杂货订购和求职申请等高频场景。其核心思路是强调端到端任务完成而非中间动作序列的匹配，以反映智能体作为通用助手的实际效用。该基准整合了多个真实网站环境，要求智能体处理复杂的表单填写和多步骤工作流，模拟真实用户依赖智能体执行事务性任务的需求。这种方法论转变旨在衡量智能体是否具备成为可靠通用在线助手的潜力，而非仅在特定合成环境中表现良好。

StressWeb（Bai et al., 2026, P27）提出了用于诊断 Web 智能体在真实交互变异性下鲁棒性的基准。其核心设计包括可操作、真实、确定性、诊断性和干预性五个维度，旨在将智能体失败归因于特定组件如感知或动作选择。该方法通过改变界面语义或动态元素，观察智能体是否应用僵化的交互先验，从而揭示其在非标准场景下的脆弱性。与仅关注任务成功率的基准不同，StressWeb 提供了因果分析机制，帮助开发者理解智能体在环境动态变化时的失效原因，为提升智能体的鲁棒性提供了明确的改进方向。

WebRetriever（Dong et al., 2026, P30）提出了大规模综合基准及 NavEval 自动化评估方法，旨在解决 Web 智能体评估中导航成功与答案正确性混淆的问题。其核心创新是设计三种互补的评估协议，显式解耦导航行为和最终答案质量，并注入操作性知识以表征行为可靠性。NavEval 方法通过大规模实验达到约 90% 的人类一致性，实现了可扩展且可靠的实时评估。该方法克服了规则基评估对网页动态性脆弱和 LLM 裁判主观性的局限，提供了更精细的诊断信号，有助于区分智能体是缺乏导航能力还是缺乏推理能力。

### 2.5 应用与基础设施

VOIX（Schultze et al., 2025, P10）提出了声明式 Agent-Web 交互框架，通过引入 `<tool>` 和 `<context>` 标签让网站显式定义智能体可用的能力。其核心设计解决了智能体从人类 UI 推断操作能力的脆弱性问题，提供了可靠、可审计且隐私保护的交互接口。该方法允许开发者明确指定哪些元素可交互、哪些数据可访问，减少了智能体的猜测和错误操作。与传统的 DOM 解析不同，VOIX 通过语义化标签提供了更高层的抽象，提升了交互的效率和安全性，为构建智能体友好的 Web 基础设施提供了标准化方案。

Permission Manifests（Marro et al., 2025, P17）提出了 `agent-permissions.json` 标准，用于定义 Web 智能体在交互过程中的权限规则。其核心设计包括资源规则、行为规则和上下文规则，允许网站所有者声明智能体可执行的操作范围。该方法在浏览器接口层检查并阻止未授权交互，建立了智能体与网站之间的合规框架。与传统的 `robots.txt` 不同，它针对智能体的复杂交互行为提供了细粒度的权限控制，有助于协调智能体与 Web 生态的利益，防止智能体滥用权限，促进了负责任智能体部署的规范化。

LegalWebAgent（Tan and Benyekhlef, 2025, P12）提出了基于 LLM 的 Web 智能体以增强司法获取，帮助普通公民导航政府网站和法律表单。其核心模块包括 Ask、Browse 和 Act，分别处理信息检索、网页浏览和表单填写。该方法利用 Playwright 框架实现可靠的浏览器自动化，结合 HTML 元素和截图提供上下文给 LLM。与静态 FAQ 或简单聊天机器人不同，LegalWebAgent 能够处理动态网页和复杂表单，解决法律术语搜索和填写错误问题，展示了 Web 智能体在垂直领域解决复杂社会问题的潜力。

Web Verbs（Jiang et al., 2026, P22）提出了类型化抽象以支持 Agentic Web 上的可靠任务组合，定义标准化的操作接口。其核心设计区分了浏览器智能体（操作 DOM/截图）和 API 智能体（调用端点），提供了统一的任务组合语言。该方法通过类型化抽象减少了智能体在任务执行中的歧义和错误，提升了跨服务交互的可靠性。与自由形式的自然语言指令不同，Web Verbs 提供了结构化的操作定义，便于验证和调试，为构建复杂的 Agentic Web 应用提供了标准化的交互协议。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

基于 LLM 的智能体在复杂、动态的开放网络环境中仍远未达到人类可靠性水平，特别是在长程任务和异常处理上存在显著差距。这一共识在多个基准上被反复验证：WebArena 上 Branch-and-Browse 的 35.8% 成功率与 Online-Mind2Web 上 Avenir-Web 的 48.0% 成功率均远低于人类水平，揭示了智能体在动态环境中的脆弱性（支撑证据：P7、P18）。与此相关的另一个共识是多模态输入比单一文本输入能显著提升智能体对复杂 UI 的理解与操作准确率。Avenir-Web 在 Online-Mind2Web 上领先 TGPO 约 10 个百分点，主要归因于其混合接地专家（MoGE）模块对视觉与文本信息的融合，解决了纯文本模型在复杂布局下的定位误差（支撑证据：P18、P2）。

### 3.2 观点分歧

安全防御策略上存在模型对齐与系统级隔离的根本分歧。观点 A 主张依赖模型对齐与提示工程（如 WebSentinel），认为应提升模型识别恶意内容的能力，保持智能体灵活性；观点 B 主张依赖系统级沙箱与权限清单（如 ceLLMate），认为模型不可信，必须在浏览器层面强制执行策略。现有证据偏向观点 B，ceLLMate 等实验表明系统级策略能有效阻止未授权操作，且不依赖模型对恶意指令的理解。然而，观点 B 在复杂任务中可能因权限过严导致任务失败率上升，缺乏大规模真实环境下的效率-安全权衡数据（支撑证据：P19、P13）。

记忆架构上存在短期上下文压缩与长期外部存储的争论。观点 A 主张短期上下文压缩（如 WebCondenser），保持推理连贯性；观点 B 主张长期外部存储（如 WebCoach 的 EMS），支持跨会话学习。现有证据偏向观点 B 在长程任务中的优势，WebCoach 等实验显示外部记忆能显著减少重复错误。但观点 B 引入了记忆投毒风险（Poison Once, Exploit Forever），且检索噪声可能干扰当前任务，记忆投毒的防御机制尚未成熟（支撑证据：P11、P24）。

### 3.3 其他开放问题

最紧迫的工程问题是动态环境模拟的准确性与实时性。WebWorld 等世界模型虽支持大规模离线训练，但预测误差累积导致训练-测试差距，如何平衡模拟保真度与计算效率是核心困难。研究路径包括自适应上下文折叠与双记忆增强，以提升世界模型的鲁棒性（支撑证据：P21）。最根本的研究问题是自主性与安全性的根本冲突。智能体自主性越高，安全风险越大，现有防御机制对新型攻击的适应性不足。研究路径包括细粒度检测、沙箱隔离和权限清单标准化，需在不可信环境中实现形式化验证的安全自主决策（支撑证据：P13、P17）。

已知的是多模态与记忆机制的有效性，争议的是安全防御策略与记忆架构的最优选择，未知的是真实开放网络中的可复现性与公平比较协议。未来趋势将依赖于世界模型带来的训练效率提升、标准化交互协议带来的基础设施安全，以及细粒度评估带来的故障可诊断性。

## 4. 总结与展望

LLM Web 智能体领域已从“验证 LLM 能否操作网页”进入“构建可靠、安全、可解释的自主代理”的新阶段。核心挑战不再是单一算法的优化，而是感知、规划、记忆与安全在开放动态环境中的系统性集成。从 ReAct 的线性循环到 Branch-and-Browse 的树搜索，从纯文本解析到 Avenir-Web 的多模态融合，从人工标注到 SynthAgent 的合成监督，每一步迭代都伴随着计算成本、安全边界与泛化能力的重新权衡。当前瓶颈在于如何在开放、动态且充满对抗性噪声的真实网络环境中，实现从“模拟环境中的任务执行”到“真实世界中的可靠代理”的跨越，这一核心问题仍未完全解决。

未来突破将集中于三个方向：一是基于世界模型的离线强化学习，WebWorld 与 AutoSurfer 共同指向利用模拟环境降低真实交互成本，提升训练效率；二是标准化 Agent-Web 交互协议，VOIX 与 Web Verbs 共同指向从基础设施层面解决安全与互操作性问题，减少智能体猜测与错误；三是细粒度过程评估，StressWeb 与 WebRetriever 共同指向从端到端成功率转向步骤级诊断，定位具体故障点。对进入者而言，最值得做的一件事是在统一骨干与统一预训练条件下，构建一个涵盖安全性、鲁棒性与效率的综合评估基准，以填补当前公平比较的空白。
