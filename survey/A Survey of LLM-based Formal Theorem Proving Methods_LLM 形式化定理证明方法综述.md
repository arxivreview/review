综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/LLM-based%20Formal%20Theorem%20Proving)

## 导读

大语言模型（LLM）在形式化定理证明中的核心矛盾，在于其强大的自然语言生成能力与交互式定理证明器（ITP）严格逻辑验证之间的张力。早期研究将证明生成视为序列建模任务，通过监督微调预测战术步骤，思路简洁却受制于长程依赖下的幻觉与不可验证性。当竞赛级基准出现饱和且研究级数学暴露出搜索空间爆炸问题后，研究者引入大规模强化学习与合成数据，用验证器反馈换取策略的主动优化能力。随着智能体框架的兴起，多轮工具调用与迭代修正成为主流，以推理延迟为代价换取复杂定理的鲁棒性。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从静态生成到智能体协作的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

LLM 形式化定理证明的起源，源于对自然语言数学推理缺乏机器可验证性的根本担忧。在安全关键领域，逻辑错误不可接受，因此引入 Lean、Coq 等 ITP 内核作为最终验证环境，成为该领域不可动摇的基石。这一设定将问题从“生成看似合理的文本”转变为“生成能通过编译器验证的代码”，确立了形式化验证内核作为正确性唯一标准的范式边界。在此边界内，核心任务被形式化为：给定自然语言陈述 $C$，模型需生成形式化陈述 $C'$ 及证明序列 $\pi = (t_1, t_2, ..., t_n)$，使得 ITP 内核验证 $C' \vdash \pi$ 成立。这一过程涉及自动形式化、前提选择、战术生成与证明修复四个强依赖子问题：自动形式化是入口，前提选择通过检索大型库（如 Mathlib）降低搜索空间，战术生成执行核心推导，而证明修复则构成鲁棒性闭环。

问题定义的演化，直接驱动了方法范式的三次重大转折。2020-2022 年，领域聚焦于“如何生成证明”，GPT-f 与 PACT 等早期工作假设证明可视为序列建模，但长程依赖导致的幻觉问题使其在复杂定理上失效。2023-2024 年，随着 DeepSeek-Prover 引入大规模强化学习，问题转变为“如何在巨大搜索空间中高效导航”，验证器反馈成为策略优化的核心信号。2025-2026 年，miniF2F 等基准的饱和迫使研究转向研究级数学，问题进一步演化为“如何在长程依赖与结构复杂性中维持证明计划的一致性”，智能体框架与结构化推理成为应对这一挑战的主要手段。

约束条件的变化是理解这一演进的关键。早期受限于算力与数据规模，方法依赖静态监督微调，无法覆盖复杂证明结构。2024 年，合成数据生成与 RL 的引入解决了数据分布偏差问题，但暴露出奖励稀疏与训练不稳定的新约束。2025 年后，研究级基准（如 PutnamBench、TCS-Bench）对长程规划与前提选择提出了更高要求，单一模型生成难以应对，迫使系统架构向多智能体协作与工具调用演进。与此同时，证明的可维护性成为新约束，RL 训练产生的冗长证明难以人工审查，催生了证明重构与简化这一后处理环节。

当前领域形态，是上述约束层层叠加的结果。模型不再仅仅是“证明生成器”，而是嵌入在“数据-训练-推理-优化”闭环中的智能体组件。自动形式化、检索、生成、修复与重构形成完整工作流，每个环节都针对特定约束进行优化。这种模块化与闭环设计，使得系统能够应对从竞赛级到研究级数学的广泛任务，但也带来了系统复杂度与推理延迟的显著增加。

**如果用一个核心问题概括该领域，那便是：如何在保证机器可验证性的前提下，通过智能体协作与强化学习克服形式化证明中的长程依赖、搜索空间爆炸及数据分布偏差，实现从竞赛级到研究级数学的自动化证明。**

## 2. 方法体系

- 2020：GPT-f——将自动定理证明建模为序列生成任务，奠定神经符号定理证明基础

- 2021：PACT——提出证明工件协同训练，增强模型对证明结构语义的理解

- 2022：HyperTree Proof Search——引入超树搜索策略，确立搜索与生成结合的主流范式

- 2024：DeepSeek-Prover-V1.5——构建大规模 Lean 证明数据集并引入强化学习微调

- 2025：Ax-Prover——提出深度推理智能体框架，结合 Lean 工具链与多智能体协作

- 2025：GAR——引入生成对抗强化学习机制，动态调整定理难度

- 2026：OProver——提出统一智能体形式化定理证明框架，实现全流程自动化

- 2026：Process-Verified RL——引入过程级奖励机制，解决信用分配难题

这条时间线勾勒了该领域方法演进的代表性节点：从 2020 年的 GPT-f 奠定该领域方法基线，经 2021 年 PACT 的推进，到 2026 年的 TheoremBench 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 理论分析与检索

该路线的起源可追溯至 2020 年的 GPT-f，其将证明生成建模为序列预测，但受限于纯文本嵌入无法捕捉定理间的逻辑依赖。2021 年 PACT 通过联合优化证明步骤与中间状态表示，为后续检索增强提供了技术启示。2022 年 HyperTree 引入超树搜索，确立了搜索与生成结合的范式，但前提选择仍依赖静态检索。2025-2026 年，随着 Mathlib 规模扩大，检索精度成为瓶颈，该路线转向结构增强与理论指导。

Combining Textual and Structural Information（Petrovčič et al., 2025, P6）针对纯文本嵌入在捕捉数学关系上的局限性，引入 RGCN 在异构有向图上传播信息，精炼前提与证明状态的嵌入。该方法放弃了纯文本方法的计算效率，换取了对结构关系的显式建模，显著提升了前提选择的准确性。其成功依赖于高质量异构图构建，且 GNN 计算开销较大，适用于对检索精度要求高但计算资源充足的场景。

LeanSearch v2（Gao et al., 2026, P22）进一步将检索从单步向迭代推理转变，通过标准模式与推理模式分离，后者针对形式化定理陈述迭代草图证明策略并组装全局前提集。该方法解决了单步检索在复杂证明中不足的问题，但推理模式计算开销较大，且草图证明策略的质量直接影响检索效果。与 P6 相比，P22 更强调全局前提集的完整性，适用于长程证明任务。

Don't Eliminate Cut（Sonoda et al., 2026, P11）从理论层面证明保留切/引理机制对于处理复杂证明结构的必要性，通过对比无切与有切模型的性能差异，提供了层次化程序并非临时启发式的理论证据。Statistical Provability Theory（Sonoda et al., 2026, P12）则建立智能体定理证明的统计可证性理论框架，将证明过程建模为有限时域马尔可夫决策过程，解释了智能体组件如何协同工作以提升证明成功率。这两项工作为智能体框架的设计提供了理论指导，但理论假设较强，实际实现中需有效管理切/引理库。

Nazrin（Aniva et al., 2026, P14）提出原子战术图神经网络定理证明方法，通过定义小集合简单战术和原子化算法，降低证明搜索的动作空间复杂度。该方法解决了传统战术空间过大导致的搜索困难问题，适用于低资源场景，但原子战术集需精心设计，且 ExprGraph 构建复杂。On Multi-Step Theorem Prediction（Zhao et al., 2026, P16）则引入定理优先图作为结构先验，结合多模态检索和状态感知符号执行，解决了 LLM 在长程推理中结构漂移的问题。

### 2.2 强化学习训练

该路线的奠基工作 DeepSeek-Prover-V1.5（2024）通过构建大规模 Lean 证明数据集并引入强化学习微调，显著提升了模型在 MiniF2F 等基准上的表现，但暴露出奖励稀疏与课程学习僵化的问题。2025-2026 年，研究重心转向解决信用分配稀疏问题与提升策略稳定性。

GAR（Wang et al., 2025, P3）引入生成对抗强化学习机制，通过动态调整定理难度以匹配证明器能力，解决了传统 RL 中奖励稀疏和课程学习僵化的问题。该方法将证明器和陈述融合器作为对抗双方，通过自适应难度调整提升了模型的学习效率和泛化能力，但训练过程不稳定，需精细调节对抗强度，且生成定理的质量直接影响训练效果。

Process-Verified RL（ICLR 2026, P35）引入过程级奖励机制，在强化学习训练中显式评估每个战术步骤的正确性，解决端到端验证信号稀疏导致的信用分配难题。该方法提供了更密集的反馈信号，帮助模型学习中间步骤的正确性，提升了模型在复杂证明结构中的推理能力，但奖励计算开销较大，需解析每个战术步骤，且过程奖励的设计需与结果奖励平衡。

LongCat-Flash-Prover（Wang et al., 2026, P18）开发原生形式化推理模型，通过智能体工具集成强化学习，提升 LLM 在 Lean4 证明中的生成和修复能力。该方法结合了工具集成和强化学习，使模型能够利用外部工具反馈进行自我修正，提升了证明生成的准确性和鲁棒性，但训练数据合成过程复杂，需大量计算资源，且模型对工具调用的依赖较强。

ImProver 2（Ahuja et al., 2026, P25）提出迭代自改进语言模型，通过多轮生成和选择最佳变体提升证明质量。该方法无需人工标注，通过自监督方式提升证明质量，解决了人工演示数据稀缺的问题，但优化指标的选择对结果影响较大，且生成多个变体增加了计算开销。Self-Play Theorem Proving（Chen and Li, 2026, P27）建立自博弈定理证明算法的理论框架，分析证明器和猜想器两个协作模型的自改进能力，提供了自博弈算法的理论保证，但理论假设较强，实际实现中需确保生成定理的质量。OptProver（Li et al., 2026, P20）则挑战困惑度与下游任务性能相关性的假设，通过持续训练桥接奥林匹克数学和优化问题的形式化定理证明，揭示了困惑度指标的局限性。

### 2.3 智能体证明框架

该路线的起源可追溯至 2023 年的 Draft-Sketch-Prove，其提出草稿-草图-证明的三阶段工作流，有效缓解了直接生成形式化证明时的幻觉问题。2025-2026 年，随着研究级基准对长程规划与错误修正能力的要求提高，智能体框架成为主流，通过多智能体协作、工具调用和迭代修正提升证明成功率。

Ax-Prover（Breen et al., 2025, P4）构建基于深度推理的智能体框架，通过集成 Lean 工具链与多智能体协作机制，实现数学与量子物理领域的自动化定理证明。其核心设计思路是将通用 LLM 作为推理引擎，利用外部工具进行形式化验证和状态查询，避免专门训练证明器。该方法不依赖大规模微调，而是通过提示工程和工具增强提升通用模型的专业能力，解决了专门证明器泛化能力差的问题，但依赖高质量的工具链支持和提示设计，对底层 LLM 的推理能力有较高要求，且推理延迟相对较高。

OProver（Ma et al., 2026, P23）提出统一智能体形式化定理证明框架，整合数据构建、智能体证明和迭代训练三大组件，实现全流程自动化。其核心设计思路是通过构建 Lean 特定语料库 OPProofs，利用去重、过滤和自动形式化技术生成高质量训练数据，并通过检索记忆库和多轮交互策略，允许模型根据编译器反馈迭代修正证明。该方法将数据生成与模型训练闭环结合，通过 SFT 和迭代后训练持续提升模型性能，解决了静态数据集导致的性能瓶颈，但训练流程复杂，需维护大规模检索记忆库，且对计算资源要求较高。

Hilbert（Varambally et al., 2025, P2）设计递归构建形式化证明的系统，结合非形式化推理与形式化验证，通过子目标分解和组装实现复杂定理的证明。其核心设计思路是利用 Reasoner 模块将问题分解为更简单的子问题，生成带有 sorry 占位符的证明草图，再由 Prover 模块填充具体证明，并引入错误纠正循环提高系统的鲁棒性和成功率。该方法展示了非形式化推理在指导形式化证明中的价值，但分解过程可能引入额外的计算开销，且子目标之间的依赖关系处理较为复杂。

LAMP（Srinivasan R and Patawar, 2026, P31）构建基于 Lean 的智能体框架，利用 MCP 协议和证明修复机制，增强通用 LLM 在形式化证明中的工具使用能力。其核心设计思路是通过 MCP 标准接口连接 LLM 与 Lean 工具，使模型能够实时访问证明状态、引理搜索和错误诊断功能，并采用通用 LLM 而非专门证明器，通过工具增强提升泛化能力。该方法解决了专门模型在分布外数据上的性能下降问题，但依赖 MCP 接口的稳定性和工具调用的准确性，且推理过程涉及多次工具交互，延迟较高。

Minimal Agent（Requena et al., 2026, P15）提出最小化智能体自动定理证明方法，通过简化智能体组件和搜索策略，降低系统复杂度同时保持高性能。其核心设计思路是仅保留必要的推理和搜索工具，避免过度复杂的架构，专注于核心证明逻辑，证明了简单架构在特定任务上的有效性，揭示了智能体框架中冗余组件对性能的影响。该方法牺牲了部分复杂任务的泛化能力，换取了系统的简洁性和可解释性，适用于资源受限或特定领域的证明任务。

Code Agents for Verification（Kan et al., 2026, P32）开发基于代码智能体的自动软件验证系统，通过工作流编排和模型交互实现 Coq 证明的自动生成与修复。其核心设计思路是将证明生成视为代码生成任务，利用 Python 策略函数和 Coq harness 进行迭代验证，并引入工作流控制流，允许灵活组合不同的证明策略，并支持多轮迭代修复。该方法将代码智能体技术应用于形式化验证，为软件正确性证明提供了自动化解决方案，但依赖 Coq harness 的准确性和错误信息的完整性，且工作流设计需针对具体任务进行定制，通用性稍弱。

Gödel's Poetry（Davis, 2025, P8）构建多智能体协作系统，结合自动定理证明、定理分解和 RAG 检索，实现复杂数学定理的形式化证明。其核心设计思路是由监督智能体协调多个专用智能体，分别负责形式化、验证、证明生成和子目标提取，并引入树状结构管理证明过程，支持回溯和重构。该方法展示了多智能体协作在形式化推理中的优势，但系统架构复杂，智能体间通信开销较大，且对知识库的质量有较高要求。

### 2.4 证明优化重构

该路线的起源可追溯至 2025 年的 ProofOptimizer，其提出无需人工演示的证明简化方法，通过专家迭代和在线强化学习训练模型生成更短、更简洁的证明。2026 年，研究重心转向多目标优化与模块化重构，以解决 RL 训练产生的证明冗长难读问题。

ProofOptimizer（Gu et al., 2025, P5）提出无需人工演示的证明简化方法，通过专家迭代和在线强化学习训练模型生成更短、更简洁的证明，降低形式化证明的维护成本。其核心设计思路是利用 Goedel-Prover-V2-32B 生成大量正确证明，然后通过长度过滤和简化训练，使模型学习生成更短的正确证明。该方法无需人工标注简化示例，通过自监督方式提升证明简洁性，解决了人工演示数据稀缺的问题，但简化过程可能影响证明的可读性，且长度约束需精细调节。

Proof-Refactor（Fu et al., 2026, P28）提出将生成的形式化证明重构为模块化工件的方法，通过辅助声明提取和模块化重组，提升证明的结构化和可维护性。其核心设计思路是将证明中的辅助声明识别为中心对象，通过重构流水线将其提取为独立模块，并优化模块间的依赖关系。该方法将证明优化从长度最小化转向结构优化，提升了证明的可读性和复用性，解决了长证明难以维护的问题，但重构过程可能改变证明的逻辑流，且需确保模块化后的证明仍然正确。

Learning to Repair Lean Proofs（Wang et al., 2026, P10）提出从编译器反馈中学习修复 Lean 证明的方法，通过构建错误-修复配对数据集，训练模型自动修正编译错误。其核心设计思路是从正确证明出发，系统引入错误，记录编译器错误信息和修复目标，构建大规模错误-修复数据集 APRIL。该方法将证明修复作为独立任务，而非端到端证明生成的一部分，提升了模型对错误的敏感性和修复能力，但错误注入可能不完全反映真实错误分布，且修复模型需处理多种错误类型。

Stepwise（He et al., 2026, P17）提出神经符号证明搜索框架，用于自动系统验证，通过迭代查询微调 LLM 预测下一个证明步骤，并结合符号工具进行验证和剪枝。其核心设计思路是将证明生成视为树搜索过程，LLM 预测步骤，符号工具验证并剪枝无望分支，Sledgehammer 作为后备解决剩余目标。该方法结合了 LLM 的生成能力和符号工具的验证能力，提升了证明搜索的效率和准确性，解决了纯 LLM 生成证明的不可靠问题，但搜索过程复杂，需平衡 LLM 预测和符号验证的计算开销。

CAPRI（Woodcock et al., 2026, P34）提出契约感知证明修复方法，用于 Isabelle，通过确保自动修复在开发者授权的变更范围内，解决补丁过拟合问题。其核心设计思路是将证明修复视为契约约束下的优化问题，确保修复后的证明不仅正确，而且符合开发者的意图和变更范围。该方法引入了契约约束，解决了自动修复可能引入非预期变更的问题，提升了修复的可信度和可维护性，但契约解析复杂，需准确理解开发者意图，且修复过程受契约限制，可能降低修复成功率。

Lean Refactor（Lu et al., 2026, P24）提出多目标可控证明优化方法，通过智能体策略搜索和检索增强重构，自动缩短证明长度并提升可读性，解决 RL 训练产生的证明冗长难读问题。其核心设计思路是将证明优化视为多目标优化问题，同时考虑证明长度、可读性和正确性，通过智能体工作流协调检索、规划、重构和调试阶段。该方法引入了多目标优化和智能体协作，提升了证明优化的灵活性和效果，解决了单一目标优化的局限性，但优化过程复杂，需协调多个组件，且多目标权衡需精细调节。

### 2.5 基准评测体系

该路线的起源可追溯至 2024 年的 PutnamBench，其构建基于 Putnam 数学竞赛题目的形式化证明基准，填补了研究级数学推理评测的空白。2025-2026 年，随着 miniF2F 等基准饱和，研究重心转向更复杂、研究级的基准，以评估模型在真实场景下的推理能力、鲁棒性及泛化边界。

RLMEval（Poiroux et al., 2025, P7）构建面向研究级神经定理证明的综合评测套件，支持多版本 Lean 交互接口，解决现有基准饱和和版本兼容性问题。其核心设计思路是提供统一的 Python 接口 LeanInteract，通过手动回移最新 REPL 功能和修复 bug，支持从 v4.7.0 到 v4.19.0 的 41 个 Lean 版本。该方法解决了现有基准如 MiniF2F 饱和的问题，提供了更具挑战性的研究级任务，并确保了评测的可重复性和兼容性，但手动回移过程工作量大，且需持续维护以支持新版本的 Lean。

TheoremBench（Pham et al., 2026, P29）构建包含主定理和支撑子定理的结构化证明基准，评估模型完成内部证明结构的能力，揭示现有模型在处理复杂依赖关系时的局限性。其核心设计思路是将父定理扩展为相关实例组，包括主定理和自动提取的支撑子定理，所有实例共享定理级 ID 但保留独立声明名。该方法从单点证明评估转向结构化证明完成评估，测试模型是否能利用显式前提减少难度，并理解定理内部结构，但实例生成过程复杂，需确保子定理的正确性和相关性。

MSC-180（Li et al., 2025, P9）构建基于数学主题分类的自动形式化定理证明基准，评估 LLM 在不同数学领域的泛化能力和一致性。其核心设计思路是利用数学主题分类（MSC）系统，将定理按领域分组，并引入变异系数@k（CV@k）指标评估模型性能的一致性。该方法从纯准确率转向性能平衡评估，揭示了模型在特定领域的专长和通用性差异，为模型选择和应用提供了更细致的指导，但领域分组可能引入偏差，且 CV@k 指标对数据分布敏感。

VeriSoftBench（Xin et al., 2026, P13）构建仓库级形式化验证基准，从真实开源形式化方法开发中提取 Lean 4 证明义务，评估模型在真实场景下的推理能力。其核心设计思路是保留原始证明环境，包括项目特定抽象和跨文件依赖，而非将任务标准化到共享库设置。该方法评估模型在“野外”定理上的表现，即使用项目定义的数据类型和不变量，而非仅依赖 Mathlib，揭示了模型在真实工程场景中的局限性，但任务环境复杂，需处理项目特定依赖，且评测结果可能受代码库质量影响。

TCS-Bench（Cohen-Addad et al., 2026, P33）构建评估生成式 AI 理论计算机科学研究能力的基准，包含来自 FOCS、STOC 和 SODA 顶会论文的 300 个定理证明任务。其核心设计思路是通过掩码中间引理来动态控制任务难度，从证明主结果到证明完整论文，挑战模型的上下文依赖推理能力。该方法引入了开放式科学发现场景，要求模型理解周围上下文并生成类似同行评审证明的详细证明，超越了传统竞赛数学评测，但任务生成依赖论文质量，且难度调节可能引入不自然的任务结构。

FormalRewardBench（Uluşan et al., 2026, P21）构建形式化定理证明奖励模型基准，通过合成错误注入创建具有控制难度的评测集，评估奖励模型对形式化证明的理解能力。其核心设计思路是从正确证明出发，系统生成满足语法有效、语义合理和现实错误模式三个标准的错误变体。该方法超越了二元结果评估，提供了更细粒度的奖励信号评测，揭示了奖励模型在形式化证明中的真实理解水平，但错误注入需精心设计以反映真实错误，且评测结果受错误类型分布影响。

### 2.6 跨任务与多领域应用

智能体框架与强化学习路线在跨领域应用中展现出互补性。Ax-Prover（Breen et al., 2025, P4）在量子物理领域的成功，展示了通用 LLM 通过智能体架构在专业形式化任务中的可行性，为跨领域形式化推理提供了可扩展的范式。LongCat-Flash-Prover（Wang et al., 2026, P18）则通过原生形式化推理模型，为构建高性能、低延迟的证明系统提供了模型基础，适用于对推理速度要求较高的场景。

证明优化重构路线在库维护与软件验证中发挥关键作用。ProofOptimizer（Gu et al., 2025, P5）与 Lean Refactor（Lu et al., 2026, P24）通过自动化证明简化与重构，降低了形式化数学库的维护成本和人工审查负担，为长期库维护提供了工具支持。Stepwise（He et al., 2026, P17）与 Code Agents for Verification（Kan et al., 2026, P32）则将神经符号方法应用于系统验证与软件正确性证明，为安全关键系统的自动化验证提供了新工具。

基准评测体系为跨领域应用提供了评估基础设施。RLMEval（Poiroux et al., 2025, P7）与 TheoremBench（Pham et al., 2026, P29）通过支持多版本 Lean 与结构化证明评估，为研究级数学与真实场景下的模型比较提供了标准工具。VeriSoftBench（Xin et al., 2026, P13）与 TCS-Bench（Cohen-Addad et al., 2026, P33）则填补了仓库级验证与理论计算机科学研究能力评测的空白，为评估 AI 在科学发现与工业级项目中的潜力提供了新基准。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

形式化验证内核（如 Lean 4 编译器）是确保 LLM 生成证明正确性的唯一可靠标准，自然语言推理无法替代机器验证，这一共识在约 48 篇论文中得到共同支持。强化学习（RL）结合编译器反馈是提升 LLM 证明生成能力的关键训练范式，优于纯监督微调，约 30 篇论文共同支持这一观点，证据显示 RL 在 MiniF2F 等基准上显著提升了模型表现。与此相关的另一个共识是，Agentic 框架（多轮交互、工具调用）比单次生成能显著提升复杂定理的证明成功率，通过迭代修正克服局部错误，约 25 篇论文共同支持。前提选择（Premise Selection）和检索增强生成（RAG）对于利用大型形式化库（Mathlib）至关重要，能大幅降低证明难度，约 20 篇论文共同支持。现有主流基准（miniF2F、ProofNet）已趋于饱和，需要更复杂、研究级的基准（如 PutnamBench、Research-level）来评估前沿模型能力，约 15 篇论文共同支持。证明重构（Proof Refactoring）和简化（Simplification）是提升证明可读性和库可维护性的重要后处理步骤，且可生成合成训练数据，约 10 篇论文共同支持。LLM 对输入的形式化表述敏感，语义等价的重写会影响性能，因此鲁棒性评估和重写集成成为必要研究方向，约 8 篇论文共同支持。自博弈（Self-play）和合成数据生成是突破人工标注数据瓶颈、实现模型自我提升的有效途径，约 6 篇论文共同支持。

### 3.2 观点分歧

智能体框架的复杂度与模型原生能力的权衡是领域内的核心争论。观点 A 认为复杂智能体框架（多智能体、工具调用）是解决长程推理的必要手段，代表工作包括 Ax-Prover、OProver 和 Hilbert；观点 B 则认为原生大模型通过强化学习即可达到高性能，智能体框架增加延迟且收益递减，代表工作包括 DeepSeek-Prover-V2 和 Pythagoras-Prover。现有证据偏向观点 A 在研究级基准（PutnamBench, TCS-Bench）上，Agentic 框架通过迭代修正显著提升成功率；但在竞赛级基准（miniF2F）上，原生模型（如 Pythagoras-Prover-32B 93.03%）已接近上限，智能体框架优势不明显。证据强度中等，缺乏在同等计算预算下的公平对比，且研究级基准的评测协议尚未完全标准化，导致难以定论。

这一分歧的背后，是另一个更根本的争论：过程级奖励与结果级奖励在 RL 训练中的有效性。观点 A 认为过程级奖励（Process-Verified RL）能解决信用分配稀疏问题，提升细粒度推理能力，代表工作包括 Process-Verified RL（ICLR 2026）；观点 B 则认为结果级奖励（Outcome-based RL）更简单高效，过程奖励计算开销大且设计复杂，代表工作包括 DeepSeek-Prover-V1.5 和 GAR。现有证据偏向观点 A 在复杂证明结构上，过程奖励能提供更密集的反馈，提升模型在长程任务中的稳定性；但在简单任务上，结果级奖励已足够。证据强度较强，有 ICLR 2026 等顶会论文支持，但过程奖励的计算开销在实际大规模训练中仍是瓶颈，且过程奖励的设计高度依赖证明结构的解析，不同 ITP（Lean vs Coq）的实现差异大，缺乏通用的过程奖励设计范式。

### 3.3 其他开放问题

最紧迫的工程问题是前提选择效率与证明重构自动化。现状是 Mathlib 规模庞大，前提选择难以精准检索相关引理，导致证明搜索空间爆炸；关键困难在于库的动态演化和语义复杂性，纯文本嵌入无法有效捕捉定理间的逻辑依赖；研究路径包括结合 GNN、语义搜索和推理感知检索来优化，如 LeanSearch v2 和 Nazrin 所示。最根本的研究问题是 LLM 证明的统计可证性理论与跨领域泛化机制。现状是缺乏统一的理论框架解释智能体组件如何协同工作以提升证明成功率；关键困难在于形式化证明结构的数学建模与领域知识的形式化表示；研究路径包括建立统计可证性理论框架（如 Statistical Provability Theory）和构建领域特定形式化数据集（如 PhysLeanData）。已知的是 ITP 验证的必要性与 RL 的有效性，争议的是智能体复杂度与过程奖励的权衡，未知的是理论可证性界限与跨领域泛化机制。发展趋势是构建“数据-训练-推理-优化”闭环的智能体系统，核心问题是如何在可验证性约束下，通过理论指导和工程优化实现研究级数学的高效证明。

## 4. 总结与展望

LLM 形式化定理证明的核心矛盾，在于 LLM 的生成能力与形式化验证的严格性之间的张力。早期研究通过序列建模与监督微调尝试解决，但受限于幻觉与长程依赖失效；2024 年引入大规模强化学习，通过验证器反馈优化策略，显著提升了竞赛级基准表现，但暴露出奖励稀疏与数据分布偏差问题；2025-2026 年转向智能体框架与结构化推理，通过多智能体协作、工具调用和迭代修正克服局部错误，应对研究级数学的长程规划与前提选择挑战。核心瓶颈在于如何在可验证性约束下，通过理论指导与工程优化实现研究级数学的高效证明，这一瓶颈回扣了第 1 章锚点句所概括的核心问题。

未来可能突破的方向包括：跨领域泛化与领域特定适应，解决模型在数学之外领域（如物理、计算机科学、优化）的泛化能力不足问题，潜在路径包括构建领域特定形式化数据集（如 PhysLeanData）和持续训练框架（如 OptProver）；长程证明规划与子目标分解，解决复杂定理中多步骤推理和长程依赖维护困难的问题，潜在路径包括层次化代理框架（如 Hilbert, OProver）和子目标分解策略；证明修复与自我修正，提升模型从编译器反馈中学习并修复错误证明的能力，潜在路径包括基于编译器反馈的监督学习（如 APRIL 数据集）和迭代修复循环。对进入者最值得做的一件事，是在统一骨干与统一预训练条件下，系统评测智能体框架与原生模型在研究级基准上的性能差异，以厘清智能体复杂度的真实收益边界。
