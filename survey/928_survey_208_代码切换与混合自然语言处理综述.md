## 导读

代码切换（Code-Switching, CS）研究聚焦于多语社区中语言交替现象的建模，其核心挑战在于模型对跨语言边界识别与语义保持的双重需求。早期工作依赖语言学规则约束切换位置，思路清晰却受制于语言对组合爆炸与真实数据稀缺。随着大规模多语预训练模型兴起，研究重心转向数据驱动，PIER 指标的提出将评估焦点从整体准确率细化至切换点局部鲁棒性，揭示了模型在嵌入语言上的系统性失效。合成数据技术从音频拼接演进为基于 TTS 与大语言模型（LLM）的高质量生成，缓解了数据瓶颈但引入了自然度与计算成本的权衡。LLM 的介入不仅用于数据合成，更成为评估与调控模型 CS 理解能力的核心工具，形成了从识别到生成的全链路研究格局。本综述梳理这条从规则约束到机制调控的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

代码切换现象在多语社区中普遍存在，指在单一话语或句子中交替使用两种或多种语言。早期 NLP 系统处理此类输入时，主要依赖语言学规则（如功能头约束）与统计模型，试图通过显式规则限制混合位置以生成合法文本。然而，这种规则驱动范式在面对自发对话中的不规则切换时显得僵化，且无法覆盖语言对组合爆炸带来的数据覆盖不全问题。2018 年 SEAME 数据集的发布标志着 CS-ASR 研究进入标准化阶段，但真实 CS 数据的稀缺性与标注高成本始终是制约模型泛化能力的根本瓶颈。

问题形式化通常采用 N-way K-shot 框架的变体，但在 CS 场景中更关注语言边界处的局部性能。设输入序列 $X = \{x_1, ..., x_T\}$，其中部分片段属于矩阵语言（Matrix Language），部分属于嵌入语言（Embedded Language）。传统评估指标词错误率（WER）对整体转录质量敏感，却对切换点（Switch Points）处的错误不敏感，导致模型在嵌入语言词汇上的高错误率被掩盖。2020 年 PIER（Point-of-Interest Error Rate）指标的提出，将评估焦点限定在嵌入语言词汇（POI）上，确立了以“兴趣点”为核心的评估范式，使优化目标从整体准确率转向切换点局部鲁棒性。

子问题之间呈现强依赖关系：语言识别（LID）是前置任务，其失败直接导致下游 ASR 或信息检索任务崩溃；切换点建模是核心技术难点，决定了 PIER 指标的表现；而 LLM 的鲁棒性不足则是上述问题在生成式范式下的延伸。数据稀缺制约了模型训练，切换点识别困难决定了性能上限，LLM 行为失控则放大了这些缺陷，三者共同构成了“数据-模型-应用”的闭环依赖。范式边界由此清晰：规则方法适用于高资源、强约束场景，数据驱动方法适用于低资源、弱约束场景，而 LLM 调控方法则试图在生成端解决语义一致性。

约束演化史揭示了方法如何因应环境变化而演变。2016-2018 年，奠基阶段以规则模型与小规模统计方法为主，SEAME 数据集成为标准基准。2020 年，PIER 指标的提出与 mBERT/XLM-R 等预训练模型的引入，标志着从规则驱动向数据驱动的转折，研究者发现多语预训练不足以鲁棒建模 CS，需专门微调。2021-2023 年，合成数据技术突破，从音频拼接演进为基于 TTS 和 LLM 的高质量合成，CodeMixBench 等基准的出现将研究边界扩展至 LLM 理解与生成。2024-2026 年，方法精细化，BLoRA、SASFT 等针对性优化策略涌现，研究深入至医疗、代码理解等垂直领域，并探索未见语言对的泛化能力。

**如果用一个核心问题概括该领域，那便是：如何在数据稀缺与声学/语义混淆的双重约束下，构建对语言边界具备显式感知与鲁棒处理能力的多语模型，并实现从识别到生成的全链路自然度与准确性平衡。**

## 2. 方法体系

- 2012：Li & Fung 规则模型——基于功能头约束提出代码切换文本生成的规则方法

- 2016：Bhat et al. 合成数据方法——利用平行语料库和统计方法生成合成代码混合数据

- 2018：SEAME 数据集——构建新加坡华语-英语代码切换语音数据集

- 2020：PIER 指标——提出兴趣点错误率，专门评估代码切换词的错误

- 2023：CodeMixBench 基准——构建覆盖 18 种语言的代码混合基准

- 2025：CS-FLEURS 数据集——构建大规模多语言代码切换语音数据集

- 2025：SECT 策略——提出简化等价约束理论引导 LLM 生成语言有效的代码切换文本

- 2026：合成语音增强——提出基于 DPO 优化的 TTS 增强框架

这条时间线勾勒了该领域方法演进的代表性节点：从 2012 年的 Li & Fung 规则模型奠定该领域方法基线，经 2016 年 Bhat et al. 合成数据方法的推进，到 2026 年的合成语音增强代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 多模态语音识别

多模态语音识别是 CS 研究的核心任务，旨在提升混合语言语音处理的鲁棒性。早期方法依赖音频拼接生成合成数据，虽成本低但引入不自然韵律，导致模型学习到错误的声学边界。2025 年，CS-FLEURS 数据集（Yan et al., 2025, P2）的发布标志着合成数据进入大规模阶段，该数据集涵盖 52 种语言和 113 个代码切换语言对，利用 TTS 合成数据增强训练，证明了合成数据在提升 CS-ASR 性能上的有效性。然而，TTS 生成的语音可能存在声学不自然问题，且依赖高质量 TTS 模型。

针对声学混淆问题，TSPC 架构（Tran et al., 2025, P1）提出两阶段音素中心架构，通过统一越南语音素表示解决越南语-英语代码切换中的音素混淆问题。该方法假设不同语言语音表征存在显著语义差异，需要对齐以提升翻译质量，其代价是引入了额外的投影器模块。在训练策略上，语言平衡适应方法（Ugan et al., 2025, P6）针对嵌入语言词被矩阵语言词数量压倒的问题，提出在训练和评估中加权兴趣点（POI）的策略，将 PIER 指标引入训练过程，使模型更关注切换点的细微错误。该方法假设代码切换词对整体语义贡献更大，因此需要更高的学习优先级，其代价是引入了额外的权重超参数，且依赖准确的 POI 检测。

2026 年，合成数据质量成为新焦点。DPO 优化 TTS 增强方法（Yeo et al., 2026, P16）提出基于直接偏好优化（DPO）的 TTS 增强框架，通过强制代码切换一致性提升合成语音质量，进而微调下游 ASR 模型。该方法利用 CMI 指标评估代码切换一致性，构建偏好对以优化 TTS 模型，旨在解决传统 TTS 在代码切换场景下的不自然问题。BLoRA 适应方法（Ugan and Waibel, 2026, P17）则挑战了“更好合成数据导致更好适应”的假设，指出瓶颈在于知识整合而非数据质量，通过稀疏、不确定性感知的适应矩阵选择性整合代码切换相关知识，避免合成数据对强模型的负面影响。对比训练方法（Nguyen et al., 2026, P15）提出基于 LLM 生成近失样本的对比训练目标，鼓励模型在代码切换区域偏好正确转录，提升 ASR 模型在 CS 区域的鲁棒性。这些方法在数据增强、架构优化与训练策略上形成了互补关系，共同推动了 CS-ASR 性能的持续提升。

### 2.2 大模型能力评估

大模型能力评估旨在构建基准测试 LLM 在代码切换文本上的理解、推理及生成能力。CodeMixBench 基准（P18）覆盖 18 种语言，评估 LLM 在理解、推理和生成代码混合文本上的能力，揭示了 LLM 在混合语言输入下的性能瓶颈。该方法假设代码混合能力是 LLM 多语言能力的重要组成部分，且可以通过基准测试量化，其代价是依赖合成数据的质量，且评估过程计算开销较大。

LLM 代码切换理解评估方法（Winata et al., 2026, P10）利用多种合成数据方法生成代码切换文本，并评估九个开源模型和一个专有模型的表现，揭示了不同模型在混合语言输入下的局限性。另一项研究（P22）提出系统性评估框架，利用受约束的多步 LLM 流水线生成语言基础代码切换变体，评估 LLM 在受控代码切换下的理解能力，基于语言学理论确保切换的自然性。这些评估工作为后续模型调控提供了基准，揭示了 LLM 在 CS 处理中的系统性偏差。

### 2.3 生成与合成技术

生成与合成技术聚焦于代码切换语音合成（TTS）与文本生成，旨在提升混合语言生成的自然度与保真度。SFMS-ALR 流水线（Donepudi, 2025, P7）提出脚本优先多语言语音合成与自适应区域解析，通过脚本分割、自适应语言识别和情感感知韵律归一化，实现高质量实时代码切换语音合成。该方法利用 Unicode 脚本边界分割文本，并通过 LLM 进行自适应语言识别，选择最优语音和区域，解决了混合脚本文本的归一化问题。其假设脚本是语言识别的可靠基础，且情感感知韵律可以提升合成自然度，代价是依赖 LLM 的语言识别能力，且流水线较为复杂。

SECT 引导生成方法（Liu et al., 2025, P4）提出简化等价约束理论（SECT）引导 LLM 生成语言有效的代码切换文本，结合 TTS 生成语音-文本对以增强 CS-ASR 训练数据。该方法通过简化语言学理论中的等价约束，使 LLM 能够生成更符合真实代码切换模式的文本，避免了传统规则方法的僵化。其关键技术模块包括 LLM 提示工程和 TTS 语音合成，旨在提升合成数据的语言质量和自然度。该方法假设语言学理论可以有效约束 LLM 的生成行为，从而产生更真实的代码切换文本，代价是依赖 LLM 的语言学理解能力和 TTS 的语音质量，且生成过程较为复杂。

### 2.4 模型行为调控

模型行为调控旨在解决 LLM 非预期语言切换现象，利用稀疏自编码器分析机制并实施微调策略。SASFT 方法（P21）利用稀疏自编码器识别 LLM 中的语言特定特征，通过监督微调抑制非预期代码切换，在保持多语言能力的同时减少语言混杂。该方法首先识别语言特定特征，然后利用这些特征作为训练信号进行微调，以增强原始语言特征并抑制其他语言特征。其核心创新在于利用稀疏自编码器分析 LLM 内部机制，并实施针对性微调，假设 LLM 的非预期代码切换源于语言特定特征的激活偏差，因此可以通过特征增强来调控。代价是引入了稀疏自编码器的训练开销，且依赖特征识别的准确性。

### 2.5 下游任务应用

下游任务应用探索代码切换在信息检索、语言识别及代码理解等具体 NLP 任务中的应用。DIVERS-Bench 基准（Ojo et al., 2025, P3）评估 LID 模型在域偏移和代码切换输入下的鲁棒性，揭示了现有 LID 模型在混合语言输入上的严重性能下降。CSR-L 检索基准（P19）构建代码切换信息检索基准，评估统计、密集、交叉编码器和后期交互检索器在代码切换查询上的表现，揭示了检索系统在混合语言场景下的性能瓶颈。

代码理解框架（Havare et al., 2026, P11）提出多语言 ASR 级联框架，结合代码感知 LLM 精炼，解决语音转录错误对代码理解任务的干扰，提升多语言学习者的代码辅助体验。NUS ABC 语料库（P23）构建代码混合聊天语料库，分析代码混合与信任、自我披露等社交动态的关系，揭示了代码混合在即时通讯中的社会语言学特征。医疗对话提取方法（Baroudi et al., 2026, P12）结合说话人分离和 ASR 从 Hinglish 医疗对话中提取患者病情，解决了低资源语言代码切换语音在医疗领域的应用挑战。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

传统 WER 指标无法准确反映 CS 场景下的模型性能，PIER 或 MER 等针对切换点的指标是更有效的评估标准，这一共识在约 15 篇论文中得到共同支持。真实 CS 数据稀缺是制约 CS-ASR 和 NLP 模型发展的主要瓶颈，合成数据增强（TTS、LLM 生成、音频拼接）是必要的补充手段，约 12 篇论文共同支持这一观点。LLM 在 CS 处理中扮演双重角色：既是生成高质量合成 CS 数据的工具，也是评估和增强模型 CS 理解能力的核心组件，约 10 篇论文共同支持。语言识别（LID）在 CS 场景中极具挑战性，现有单标签 LID 模型在多语混合输入下性能显著下降，需要多标签或跨度级识别机制，约 8 篇论文共同支持。模型在 CS 区域（特别是嵌入语言词汇）的错误率远高于矩阵语言区域，表明模型对跨语言边界缺乏鲁棒性，约 9 篇论文共同支持。合成数据的质量（自然度、语言学一致性）比数量更重要，低质量合成数据可能损害模型性能，需结合语言学约束（如 Equivalence Constraint）进行生成，约 7 篇论文共同支持。端到端多语 ASR 模型（如 Whisper）在零样本 CS 任务上表现有限，需通过微调或特定架构（如音素中心）进行适配以提升性能，约 8 篇论文共同支持。

### 3.2 观点分歧

合成数据的质量与数量之争是领域内的核心分歧。观点 A（数量优先）认为，CS-FLEURS 等大规模合成数据集证明，即使存在轻微不自然，大规模数据仍能显著提升 ASR 性能。观点 B（质量优先）认为，BLoRA 指出强模型对低质合成数据敏感，需通过稀疏适应选择性整合知识，避免负面影响。现有证据偏向“质量优先”，BLoRA 在 CS-FLEURS 上优于直接微调；但大规模 TTS 实验（如 CosyVoice）也显示数量效应。定输赢的实验需在相同计算预算下，对比“高自然度小规模”与“低自然度大规模”合成数据在未见语言对上的泛化性能。分歧根源在于缺乏统一的“自然度”量化指标，且不同模型（强/弱）对数据质量的敏感度不同，场景依赖性强。

LLM 的 CS 能力是涌现属性还是需显式调控？观点 A（涌现论）认为，LLM 的多语言能力足以处理 CS，CodeMixBench 中的偏差源于评估数据分布偏差。观点 B（调控论）认为，SASFT 证明 LLM 内部存在语言特征激活偏差，需通过稀疏自编码器微调抑制非预期切换。证据偏向“调控论”，SASFT 在 CodeMixBench 上显著降低 CS Ratio；但缺乏对“为何”的深层理论解释，且调控可能损害其他能力。定输赢的实验需对比“零样本”、“通用微调”与“机制调控”在多种 CS 任务上的性能，并分析内部特征变化。分歧根源在于 LLM 内部机制黑箱，缺乏可解释性工具；且 CS 能力与多语言能力的边界模糊，难以分离评估。

### 3.3 其他开放问题

最紧迫的工程问题是 TTS 在切换边界的韵律断裂与口音不一致，可通过语音转换与自适应音素对齐解决，但计算成本高。最根本的研究问题是未见语言对（Unseen Pairs）的泛化机制不明，模型合并与元学习是潜在路径，但缺乏理论支撑。认知边界在于 LLM 内部语言特征的稀疏表示是否足以解释 CS 行为？SASFT 提供了线索，但因果机制尚不明确。已知的是合成数据必要性与切换点特殊性，争议的是合成数据质量阈值与 LLM 调控机制解释，未知的是跨语言泛化机制与 LLM 内部因果机制。发展趋势是从“识别鲁棒性”向“生成自然度”与“认知可控性”转型，核心任务仍是解决数据稀缺与边界混淆的矛盾，但解决路径已从单纯的数据堆叠转向语言学约束与模型机制的深度结合。

## 4. 总结与展望

代码切换 NLP 正处于从“识别鲁棒性”向“生成自然度”与“认知可控性”转型的关键期，核心任务仍是解决数据稀缺与边界混淆的矛盾。早期规则方法因无法覆盖语言对组合爆炸而失效，数据驱动方法虽提升了性能但受制于真实数据稀缺，合成数据技术虽缓解了数据瓶颈但引入了自然度与计算成本的权衡。核心瓶颈在于如何在保持自然度的同时实现低资源语言对的泛化，以及建立更全面的评估框架。

未来可能突破的方向包括：扩展低资源语言对覆盖，构建更多低资源、多文字系统的代码切换数据集，解决数据稀缺导致的泛化能力不足问题；提升 LLM 对代码切换文本的鲁棒性，开发专门针对代码切换结构的预训练范式或微调策略，解决模型对英语中心主义依赖和语法结构混淆问题；优化代码切换语音合成（TTS）质量，开发能保持说话人身份一致性和自然韵律的端到端或模块化 TTS 系统，解决多语言语音融合的自然度问题。对进入者最值得做的一件事是，在统一骨干与统一预训练条件下，系统评估不同合成数据策略（质量 vs. 数量）在未见语言对上的泛化性能，为领域提供可复现的基准与结论。
