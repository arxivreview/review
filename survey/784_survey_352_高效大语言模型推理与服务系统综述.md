## 导读

大语言模型（LLM）推理效率的核心矛盾在于参数规模的指数级增长与硬件资源线性扩展之间的结构性失衡，这一矛盾直接推高了云端部署的延迟、成本与能耗。早期研究聚焦于单卡内存优化与基础批处理，试图通过模型压缩或简单调度缓解显存压力，但静态批处理的僵化限制与键值缓存（KV Cache）碎片化问题很快暴露了单点优化的天花板。随着 vLLM 提出分页注意力（PagedAttention）机制，内存管理范式发生根本转变，连续批处理（Continuous Batching）由此确立为高吞吐服务的基础架构。随后，预填充（Prefill）与解码（Decode）阶段的资源特性冲突被明确识别，促使研究界引入解耦（Disaggregation）架构，通过硬件或逻辑分离消除阶段间的相互干扰。当前领域已超越单纯的单节点加速，转向异构硬件协同、多模型并发服务及系统级能效优化，旨在严格的服务等级目标（SLO）与极致成本效率之间寻求平衡。各技术路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从几何度量到语义先验的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

大语言模型推理效率问题的本质，源于 Transformer 架构中预填充与解码阶段资源特性的内在冲突，以及模型规模突破单卡物理限制后的资源分配难题。预填充阶段需要并行处理所有输入 Token，属于计算密集型任务，其性能受限于 GPU 的浮点运算能力；而解码阶段每次仅生成一个 Token，属于内存带宽密集型任务，其性能受限于从显存读取权重和 KV Cache 的带宽。这种计算密集与内存密集的本质差异，使得将两个阶段共置于同一 GPU 实例时，必然产生资源竞争：预填充的高计算负载会阻塞解码的内存访问，反之亦然。因此，如何在严格的 SLO 约束下，通过系统级的资源调度、内存管理与异构协同，最大化有效吞吐量（Goodput）并最小化单位 Token 成本，构成了该领域的核心任务。

问题定义经历了从“如何跑得快”到“如何在多约束下跑得稳且省”的深刻演化。在 2019 至 2022 年间，研究焦点集中在单节点内的内存优化与基础批处理效率，核心假设是通过压缩模型或简单批处理即可解决效率问题。然而，随着真实噪声与长尾分布数据的引入，静态批处理的僵化限制暴露无遗：长请求阻塞短请求，导致 GPU 利用率低下。此时，问题形式化为在变长输出请求下，如何动态管理请求批次以最大化 GPU 利用率。2023 至 2024 年，随着模型规模突破单卡显存限制，研究重心转向阶段解耦，识别出预填充与解码的资源冲突，引入解耦架构以消除相互干扰。问题进一步演化为如何在不同硬件或逻辑实例间分配预填充与解码任务，以平衡尾延迟与吞吐量。2025 至 2026 年，问题扩展至边缘-云协同、混合专家（MoE）动态路由开销及严格的 SLO 与能耗平衡，强调系统级全局优化而非局部加速。

子问题之间存在明确的依赖与并列关系。KV Cache 管理是基础依赖，不解决内存瓶颈则无法实现高并发，因为 KV Cache 的线性增长直接限制了并发请求数。预填充-解码解耦依赖于对内存特性的理解，只有准确识别两阶段的资源需求差异，才能设计出有效的隔离策略。能效优化与异构协同则是并列的高级目标，均建立在基础调度与内存管理之上，但受限于硬件物理边界。例如，能效优化需要在满足 SLO 的前提下降低功耗，而异构协同需要在不同硬件间分配任务以平衡延迟与成本。这些子问题相互交织，共同构成了当前复杂的服务系统优化问题。

范式边界上，需区分“模型压缩”与“系统优化”。模型压缩通过改变模型本身（如量化、剪枝）来降低计算量，而系统优化通过改变执行方式（如调度、内存管理、硬件协同）来提升效率。本文重点聚焦于系统优化，因为模型压缩往往伴随精度损失，而系统优化可以在保持模型精度的前提下显著提升效率。此外，系统优化还涉及操作系统、网络与硬件的协同，是一个多层级的优化问题。

约束演化史揭示了方法如何因应约束变化而演变。2016-2018 年，奠基阶段以 Orca 为代表，提出迭代级连续批处理调度机制，允许在解码步骤间动态插入新请求，打破了传统静态批处理的僵化限制，显著提升了 GPU 利用率与系统吞吐量，成为现代 LLM 服务系统的基础调度范式。2020 年，Transformer 架构的普及确立了基于并行计算的语言模型基础，其计算特性直接决定了后续推理优化中预填充与解码阶段在计算密集与内存密集上的本质差异。2022 年，FlexGen 提出基于 CPU-GPU-SSD 三级存储的静态离载策略，通过优化数据流调度使大模型能在单 GPU 上运行，解决了显存不足导致的部署瓶颈，为后续动态离载与内存层次优化提供了重要参考。

2023 年，vLLM 引入 PagedAttention 机制，将 KV 缓存划分为固定大小的块进行管理，借鉴操作系统虚拟内存思想解决内存碎片问题，大幅提升了并发请求下的显存利用率，成为开源 LLM 服务系统的标准基线。同年，GPTQ 提出基于二阶信息的高效权重量化算法，能够在不显著损失精度的情况下将模型压缩至 4 位，使得大模型在消费级硬件上的部署成为可能，推动了端侧推理技术的普及。2024 年，DistServe 提出预填充-解码分离架构，将计算密集的预填充阶段与内存密集的解码阶段部署在不同的 GPU 池上，消除了阶段间的资源竞争，显著改善了尾延迟与吞吐量的平衡。Sarathi-Serve 引入分块预填充（Chunked-Prefill）与无停顿（Stall-Free）批处理调度，通过将长提示分块并与解码请求混合执行，避免了长提示对短请求解码延迟的阻塞，实现了高吞吐与低延迟的兼得。

2025 年，VoltanaLLM 提出基于反馈的频率控制与状态空间路由机制，根据请求特征动态调整 GPU 频率并路由至不同功耗配置的实例，在满足 SLO 的前提下显著降低了推理能耗，开启了能效感知服务的新方向。LLMServingSim 开发了首个针对 LLM 推理服务的系统级仿真器，能够模拟异构硬件与复杂调度策略下的性能表现，填补了硬件设计与软件优化之间缺乏统一评估平台的空白。SPAD 提出针对预填充和解码阶段特性的专用芯片设计方法论，通过解耦两阶段的硬件资源需求，设计了计算与内存带宽更匹配的专用加速器，突破了通用 GPU 在特定阶段效率低下的瓶颈。2026 年，DuetServe 提出自适应 GPU 空间复用调度策略，利用 Roofline 模型预测延迟风险，动态将预填充和解码任务分配到不同的 SM 分区并行执行，进一步细化了资源隔离粒度，提升了混合负载下的 SLO 达成率。LUT-LLM 提出基于查找表（LUT）的内存计算推理架构，利用 FPGA 的 LUT 资源实现超低比特权重的并行计算，避免了传统算术单元的低效，为边缘设备提供了高能效的推理新范式。Synera 构建了设备-云协同的 LLM 服务框架，通过非均匀请求的均匀化转换与高效云调度，实现了端侧小模型与云端大模型的无缝协同，解决了单一部署模式在成本与性能上的局限。PALS 提出面向 MoE 模型的功耗感知服务系统，通过动态调整功率上限与批处理大小，在严格 QoS 约束下最大化每焦耳令牌数，解决了 MoE 模型因专家路由导致的功耗波动问题。Frontier 开发了综合且精确的 LLM 推理仿真器，能够模拟解耦架构下的复杂运行时动态，包括 KV 缓存迁移与 MoE 路由，为异构基础设施的部署决策提供了高精度的预测工具。Sangam 提出基于 Chiplet 的 DRAM-PIM 加速器，集成 CXL 接口以扩展内存容量，通过近内存计算缓解 LLM 推理中的内存墙问题，展示了新型内存架构在大规模推理中的潜力。xLLM 提出全局 KV 缓存管理与混合 EPD 分离调度策略，实现了在线-离线负载的协同调度与快速故障恢复，提升了大规模集群下的资源利用率与服务可靠性。SelectInfer 提出选择性神经元加载与计算机制，基于神经元激活稀疏性，仅加载和计算当前输入所需的核心神经元，显著减少了端侧设备的内存占用与计算开销。Blink 提出 CPU-Free 的 LLM 推理架构，将服务栈完全委托给 GPU 和 SmartNIC，通过 RDMA 实现零拷贝数据传输，消除了主机 CPU 在推理路径上的延迟瓶颈，提升了高并发下的系统效率。SweetSpot 建立了 LLM 推理能效的分析模型，通过解析输入输出序列与硬件参数的关系，预测不同配置下的能耗，为服务提供者优化能效提供了理论指导。KernelSight-LM 开发了内核级 LLM 推理仿真器，能够精确模拟 GPU SM 级别的执行细节，支持对 SLO 指标的细粒度预测，弥补了系统级仿真器在微观性能预测上的不足。CHIME 提出基于 Chiplet 的异构近内存加速架构，针对多模态 LLM 推理，利用 RRAM 的 PNM 特性优化跨模态数据传输，解决了多模态输入导致的 KV 缓存膨胀与内存瓶颈。FairBatching 提出公平性感知的批处理形成策略，在混合批处理中平衡不同请求的延迟公平性，避免了长请求对短请求的过度阻塞，提升了多租户场景下的服务质量。T-SAR 提出 CPU-only 的三元 LLM 推理架构，通过原位 SIMD ALU 重组与三元-二元分解，实现了在普通 CPU 上高效执行三元权重模型，降低了端侧推理对专用加速器的依赖。

**如果用一个核心问题概括该领域，那便是：在异构硬件与动态负载约束下，如何通过系统级的资源调度、内存管理与协同优化，在严格的服务等级目标与极致的成本效率之间找到帕累托最优解。**

### 2.1 调度与资源管理

调度与资源管理路线的核心在于通过动态批处理、KV 缓存管理与阶段分离调度，优化吞吐量、延迟及 SLO 达成率。Orca（2019）奠定了连续批处理的基础，允许在解码步骤间动态插入新请求，打破了静态批处理的僵化限制。vLLM（2023）进一步引入 PagedAttention 机制，将 KV 缓存划分为固定大小的块进行管理，借鉴操作系统虚拟内存思想解决内存碎片问题，大幅提升了并发请求下的显存利用率，成为开源 LLM 服务系统的标准基线。Sarathi-Serve（2024）引入分块预填充与无停顿批处理调度，通过将长提示分块并与解码请求混合执行，避免了长提示对短请求解码延迟的阻塞，实现了高吞吐与低延迟的兼得。

DuetServe（Gao et al., 2025, P7）针对 Sarathi-Serve 在混合负载下可能违反解码 SLO 的问题，提出了一种自适应 GPU 空间复用调度框架。其核心模块包括基于 Roofline 模型的延迟预测器与动态 SM 分区调度器。调度器首先执行常规的分块预填充策略，随后利用预测器评估当前混合批次是否可能违反解码的 TBT SLO。若预测延迟超标，系统主动激活 GPU 空间复用，将工作负载划分为解码-only 和预填充-only 两个不相交集合，并分别分配至独立的 SM 分区并行执行。这种设计解耦了解码与预填充的计算，允许解码内核独立推进，从而在保持高吞吐的同时严格满足延迟 SLO。其代价是引入了额外的调度开销与 SM 分区管理的复杂性，且依赖于 Roofline 模型对硬件特性的准确建模。该方法在混合负载场景下显著提升了 SLO 达成率，为细粒度资源隔离提供了新的技术路径。

xLLM（Liu et al., 2025, P5）构建了一个包含 xLLM-Service 与 xLLM-Engine 的双层服务架构，重点解决大规模集群下的资源调度与故障恢复问题。Service 层设计了在线-离线协同调度策略、动态 PD 分离调度策略以及混合 EPD 分离调度策略，以最大化集群整体利用率。Engine 层实现了多层流水线执行引擎，通过通信流与计算流的重叠隐藏延迟。此外，系统引入了全局 KV 缓存管理机制，支持跨实例的缓存共享与迁移，并设计了快速故障恢复架构以应对节点失效。其核心创新在于将调度策略与底层执行引擎深度耦合，实现了从全局资源分配到局部算子优化的端到端协同。该方法依赖于对集群状态的实时感知与快速决策，适用于超大规模 LLM 服务场景，提升了系统的鲁棒性与资源效率。

Flow-Controlled Scheduling（Dong and Cao, 2026, P39）提出一种具有可证明稳定性保证的 LLM 推理在线调度算法。该方法将 LLM 推理建模为离散时间下的在线优化问题，考虑 KV 缓存预算约束与请求到达分布。通过引入流控制机制，调度器动态调整请求的激活与驱逐策略，以维持队列的稳定性。其核心在于利用 Lyapunov 优化理论，推导出在未知请求长度分布下的最优调度策略，并证明了该策略在任意到达率下都能保证系统稳定。与启发式方法不同，该方法提供了严格的理论保证，避免了传统调度在高负载下可能出现的队列爆炸问题。其代价是算法实现较为复杂，且需要准确的 KV 缓存预算估计。该方法为 LLM 服务系统的稳定性设计提供了理论基础，适用于对可靠性要求极高的生产环境。

Geometry-Aware Online Scheduling（Kong et al., 2026, P48）提出一种基于几何感知的在线调度方法，从理论界限到系统实践全面优化 LLM 服务。该方法将请求的内存占用建模为随时间线性增长的几何体积，利用这一特性推导了在线调度的竞争比界限。通过设计基于体积的调度算法，系统能够更准确地预测请求未来的内存需求，从而优化批处理形成与驱逐策略。其核心创新在于将抽象的在线算法理论应用于具体的 LLM 内存管理场景，解决了传统调度忽略内存动态增长特性的问题。该方法在理论上保证了调度效率，在实践中显著降低了内存碎片与驱逐频率。其代价是调度决策的计算复杂度较高，需要高效的几何计算支持。该方法为 LLM 服务的内存管理提供了新的理论视角与实用算法。

PARS（Tao et al., 2025, P2）提出一种提示感知的低延迟 LLM 服务调度框架，包含预测器与调度器两个核心组件。预测器采用成对排序与边际排序损失进行训练，能够准确预测不同提示下的生成长度，作为任务执行时间的代理指标。调度器利用预测结果进行在线请求排序，并结合最短作业优先（SJF）策略进行批处理形成。其核心创新在于将提示内容特征纳入调度决策，解决了传统调度仅依赖请求长度或到达时间的局限性。该方法支持静态与连续批处理，并展示了跨模型泛化能力，即在一个模型上训练的预测器可迁移至其他模型。其代价是预测器的训练需要大量标注数据，且预测误差可能影响调度效果。该方法在低延迟场景下显著提升了 SLO 达成率，为智能调度提供了有效工具。

FairBatching（Lyu et al., 2025, P4）提出一种公平性感知的批处理形成策略，旨在解决混合批处理中不同请求间的延迟不公平问题。该方法在形成批处理时，不仅考虑吞吐量，还引入公平性指标，平衡长请求与短请求的等待时间。通过优化批处理中的请求组合，系统避免了长预填充请求对短解码请求的过度阻塞，确保了多租户场景下的服务质量。其核心创新在于将公平性作为调度目标之一，与效率目标进行权衡。该方法依赖于对请求延迟的精确估计与实时调整，适用于对公平性要求较高的公共服务场景。其代价是公平性约束可能略微降低整体吞吐量，且需要复杂的优化算法来求解最优批处理组合。该方法为 LLM 服务的多租户管理提供了新的设计原则。

LAPS（She et al., 2026, P24）提出一种长度感知的预填充 LLM 服务系统，通过分离长短预填充请求来消除阶段内干扰。该方法观察到长预填充是计算密集型，而短（重）预填充是内存密集型，两者混合执行会导致资源竞争与延迟波动。系统维护两个独立的实例池，分别处理短预填充和长预填充请求。控制器通过监控队列积压、SLA 偏差与 GPU 利用率，动态调整实例在两个池间的迁移，以平衡负载。其核心创新在于识别并隔离预填充阶段内部的异构负载，实现了更精细的资源管理。该方法依赖于对请求长度的准确分类与实例迁移的低开销实现。其代价是增加了系统管理的复杂性，且实例迁移可能存在短暂的延迟抖动。该方法显著稳定了 P99 延迟，提升了高并发下的服务稳定性。

Coral（Mei et al., 2026, P40）提出一种面向异构云 GPU 的成本高效多 LLM 服务系统，通过服务模板生成与优化实现资源的高效利用。该方法首先根据模型特性与延迟 SLO，生成包含 GPU 配置与模型放置策略的服务模板库。在运行时，系统根据当前负载与可用资源，从模板库中选择最优模板进行部署。其核心创新在于将服务配置抽象为模板，实现了配置的可复用性与快速切换，避免了每次部署时的实时优化开销。该方法依赖于对模型执行特性的离线分析与模板的预计算。其代价是模板库的维护成本较高，且对于非标准负载可能缺乏合适的模板。该方法在异构云环境中显著降低了服务成本，提升了资源利用率。

调度与资源管理路线与硬件架构与加速路线存在互补关系：前者通过软件调度优化资源利用，后者通过硬件设计提升计算与内存效率。两者共同构成了 LLM 推理系统优化的核心支柱。

### 2.2 边缘与端侧推理

边缘与端侧推理路线聚焦于资源受限的设备上 LLM 的高效部署，涵盖模型压缩、异构计算、内存优化及功耗管理。GPTQ（2023）提出基于二阶信息的高效权重量化算法，能够在不显著损失精度的情况下将模型压缩至 4 位，使得大模型在消费级硬件上的部署成为可能，推动了端侧推理技术的普及。FlexGen（2022）提出基于 CPU-GPU-SSD 三级存储的静态离载策略，通过优化数据流调度使大模型能在单 GPU 上运行，解决了显存不足导致的部署瓶颈，为后续动态离载与内存层次优化提供了重要参考。

LUT-LLM（He et al., 2025, P8）提出一种基于查找表（LUT）的内存计算 LLM 推理架构，专为 FPGA 平台设计。该方法利用 FPGA 的 LUT 资源存储量化后的权重，并通过内存访问实现计算，避免了传统算术单元的低效。其核心模块包括 LUT 压缩算法与内存映射策略，将三元或低比特权重分解为二进制形式，以匹配 SIMD 硬件结构。通过这种设计，系统实现了极高的计算密度与能效比，特别适合边缘设备的低功耗需求。其代价是 LUT 资源的占用较大，且对模型量化精度敏感，需要精细的量化方案来保持精度。该方法在单批次推理场景下显著优于 GPU，为边缘 AI 提供了新的硬件加速范式。

SelectInfer（Kabakibo et al., 2026, P51）提出一种选择性神经元加载与计算机制，利用 LLM 的内在稀疏性优化端侧推理。该方法识别出模型中跨任务稳定激活的核心神经元，并在推理时仅加载和计算这些神经元，忽略非激活部分。其核心模块包括神经元重要性评估器与动态加载调度器，前者基于离线分析确定核心神经元集合，后者在运行时根据输入动态调整加载策略。通过减少内存占用与计算量，系统显著提升了端侧设备的推理速度与能效。其代价是神经元选择可能引入精度损失，且需要额外的存储来维护神经元索引。该方法依赖于模型激活模式的稳定性，适用于任务分布相对固定的端侧场景。

T-SAR（Oh et al., 2025, P14）提出一种 CPU-only 的三元 LLM 推理架构，通过原位 SIMD ALU 重组实现高效计算。该方法针对三元权重（-1, 0, 1）的特性，设计了三元-二元分解算法，将三元点积转换为两个二进制点积的减法，从而匹配 SIMD 寄存器的位宽。其核心模块包括 LUT 压缩算法与 SIMD 指令优化，利用 CPU 的向量单元并行处理多个神经元。通过这种设计，系统无需专用加速器即可在普通 CPU 上实现高效的三元模型推理。其代价是算法实现复杂，且对 CPU 的 SIMD 指令集有特定要求。该方法降低了端侧推理的硬件门槛，适用于资源极度受限的移动设备。

HCInfer（Xu et al., 2026, P41）提出一种基于误差补偿的资源受限设备 LLM 推理系统，通过异构补偿流水线优化量化误差。该方法将量化误差分解为低秩矩阵，并利用 CPU 与 GPU 的异构计算能力进行补偿。其核心模块包括敏感性感知动态秩分配器与异构补偿流水线，前者根据层的重要性动态分配补偿秩，后者在 GPU 执行主计算的同时，在 CPU 执行误差补偿。通过这种协同，系统在保持高精度的同时降低了内存占用。其代价是 CPU-GPU 间的数据传输开销，且补偿计算可能增加延迟。该方法依赖于对量化误差结构的准确建模，适用于对精度要求较高的端侧场景。

MeKi（Ding et al., 2026, P30）提出一种基于内存的专家知识注入机制，通过解耦模型容量与计算成本优化 LLM 扩展。该方法将部分专家知识存储在外部内存中，推理时通过查找表（Lookup）而非矩阵乘法来访问知识。其核心模块包括 Token-Level Expert 训练与低秩特征融合机制，前者在训练阶段将专家知识编码为内存条目，后者在推理阶段将检索到的知识注入隐藏状态。通过这种设计，系统避免了在线路由的延迟与内存碎片问题，实现了高效的稀疏激活。其代价是外部内存的访问延迟，且需要重新参数化策略来优化推理速度。该方法为 MoE 模型在边缘设备上的部署提供了新途径。

FlexServe（Wu et al., 2026, P34）提出一种面向移动设备的快速安全 LLM 服务系统，通过灵活资源隔离保障模型安全与性能。该系统在安全世界中运行，利用安全内存存储模型权重与 KV 缓存，防止内核级攻击者的窃取或篡改。其核心模块包括 Flex-Mem 灵活内存管理与多模型调度器，前者动态调整内存分配以应对应用内存波动，后者协调多个 LLM 模型的驻留与预取。通过这种设计，系统在保障安全的同时实现了零停顿的模型切换。其代价是安全内存的访问速度较慢，且安全世界的资源开销较大。该方法适用于对隐私与安全要求极高的移动应用场景。

Splitwise（Younesi et al., 2025, P22）提出一种基于 Lyapunov 辅助深度强化学习的边缘-云协同 LLM 推理框架，优化层间分割与资源分配。该方法将 LLM 推理分割为边缘与云两部分，利用 DRL 智能体动态决定分割点与资源分配，以最小化端到端延迟与能耗。其核心模块包括系统模型构建与 UARA（用户关联与资源分配）优化器，前者建模计算、通信与能耗成本，后者通过多智能体 DRL 求解联合优化问题。通过这种设计，系统能够适应动态网络条件与负载变化。其代价是 DRL 训练需要大量仿真数据，且推理时的决策延迟可能影响实时性。该方法为边缘-云协同推理提供了自适应优化方案。

E2LLM（Le et al., 2026, P46）提出一种面向异构边缘/雾环境的 LLM 服务系统，通过遗传算法与动态规划优化集群部署。该方法首先收集节点计算能力与网络带宽信息，利用遗传算法寻找最优集群策略，最大化吞吐量并满足 QoS 约束。随后，利用动态规划将模型分割至集群内设备，最小化流水线并行瓶颈。其核心模块包括集群优化器与模型分割器，前者处理宏观资源分配，后者处理微观层间调度。通过这种设计，系统实现了异构环境下的负载均衡与低延迟服务。其代价是优化算法的计算复杂度较高，且需要准确的延迟剖析数据。该方法适用于分布式边缘计算场景。

边缘与端侧推理路线与分布式与云边协同路线存在继承关系：前者关注单设备或局部集群的优化，后者扩展至跨设备的协同推理。两者共同构成了 LLM 推理系统从边缘到云的全栈优化体系。

### 2.3 分布式与云边协同

分布式与云边协同路线探索跨节点、跨设备的分布式 LLM 推理架构，包括模型并行、流水线并行、推测解码及资源调度。DistServe（2024）提出预填充-解码分离架构，将计算密集的预填充阶段与内存密集的解码阶段部署在不同的 GPU 池上，消除了阶段间的资源竞争，显著改善了尾延迟与吞吐量的平衡。

Synera（Wang et al., 2025, P10）提出一种设备-云协同的 LLM 服务框架，通过非均匀请求的均匀化转换提升协同效率。该方法将设备端的小模型与云端的大模型结合，设备端执行部分预填充，云端执行剩余计算。其核心模块包括通信效率优化器与云调度器，前者通过压缩与重叠计算通信来减少传输开销，后者将非均匀请求转换为均匀的 Partial Prefill 任务，优化云端的连续批处理。通过这种设计，系统实现了端云资源的高效互补，降低了云端成本并提升了响应质量。其代价是端云间的数据传输延迟，且需要复杂的协议来保证一致性。该方法适用于多用户大规模场景，提升了系统的可扩展性。

Blink（Siavashi et al., 2026, P36）提出一种 CPU-Free 的 LLM 推理架构，将服务栈完全委托给 GPU 和 SmartNIC，消除主机 CPU 瓶颈。该方法在初始化阶段由主机加载模型并捕获 CUDA 图，随后退出推理路径。运行时，前端在 DPU 的 ARM 核心上接收请求、分词并通过 RDMA 将提示写入 GPU 内存，后端在 GPU 上执行推理并通过 RDMA 返回令牌。其核心模块包括 DPU 前端与 GPU 后端，实现了零拷贝的数据传输与低延迟的控制平面。通过这种设计，系统在高并发下保持了可预测的延迟，且兼容现有模型与 API。其代价是 DPU 资源的占用，且 RDMA 配置复杂。该方法为数据中心 LLM 服务提供了高性能、低延迟的新架构。

Collaborative LLM Inference（Koh and Yang, 2025, P6）提出一种资源感知的并行推测解码框架，优化移动边缘计算（MEC）中的端云协同。该方法将轻量级草稿模型部署在移动设备，目标模型部署在边缘服务器，通过并行推测解码加速生成。其核心模块包括用户关联与资源分配（UARA）优化器，利用多智能体深度强化学习联合优化用户与边缘服务器的关联及资源分配。通过这种设计，系统最小化了通信开销与异步延迟，提升了端到端效率。其代价是 DRL 训练复杂，且对网络稳定性敏感。该方法适用于资源受限的移动边缘场景，实现了低延迟 LLM 服务。

SPADE（Bajpai et al., 2026, P52）提出一种精确且低成本的分布式边缘云推测解码框架，利用边缘小模型生成草稿序列以减少云端调用。该方法在边缘设备运行草稿模型，生成候选令牌序列，云端大模型仅进行验证。其核心模块包括分布式推测解码引擎与验证准则，前者协调端云间的草稿生成与传输，后者基于概率分布接受或拒绝草稿令牌。通过这种设计，系统显著减少了云端计算量，降低了推理成本，同时保证了与云端大模型相同的输出精度。其代价是边缘设备的计算负载增加，且草稿生成延迟可能影响整体速度。该方法适用于成本敏感且对精度要求高的分布式推理场景。

Fast All-Reduce Communication（Singhania et al., 2025, P12）提出一种针对多节点 LLM 推理的快速 All-Reduce 通信优化方法，解决跨节点通信瓶颈。该方法系统研究了多节点推理中的通信开销，并优化了 All-Reduce 算法的实现。其核心模块包括通信库优化与并行策略调整，通过改进 Ring 与 Tree 算法的调度，减少跨节点数据传输延迟。通过这种设计，系统提升了张量并行与流水线并行在多节点环境下的效率。其代价是通信优化可能增加实现复杂度，且依赖于网络拓扑。该方法为大规模分布式 LLM 推理提供了通信层面的优化方案。

WISP（Li et al., 2026, P25）提出一种边缘分布式推测 LLM 服务系统，通过动态草稿与 SLO 感知批处理抑制浪费与干扰。该方法在边缘设备与云之间协同执行推测解码，动态调整草稿模型的选择与批处理大小。其核心模块包括动态草稿生成器与 SLO 感知调度器，前者根据边缘资源状态选择最优草稿模型，后者根据 SLO 约束调整批处理以平衡延迟与吞吐。通过这种设计，系统最大化了边缘资源利用率，同时满足了严格的延迟要求。其代价是动态调整可能引入控制开销，且对边缘设备性能敏感。该方法适用于边缘-云协同的低延迟 LLM 服务场景。

Geographically-Distributed Inference Optimization（Sun et al., 2025, P21）提出一种地理分布 LLM 推理的资源分配优化算法，解决跨地域部署的延迟与成本问题。该方法将联合优化问题分解为三个子问题：块放置、请求路由与资源分配，每个子问题独立优化。其核心模块包括鲁棒优化器与最短路径路由，前者通过鲁棒优化确定模型块在地理节点的放置，后者通过设计链路成本近似总推理时间进行请求路由。通过这种设计，系统在保证推理质量的同时最小化了平均推理时间。其代价是算法复杂度较高，且需要准确的网络延迟模型。该方法适用于全球分布式 LLM 服务场景。

StreamServe（Kumar et al., 2026, P37）提出一种自适应推测流的低延迟分离式 LLM 服务系统，协同优化路由与推测。该系统包含 StreamScheduler、FlowGuard、PipeServe-Engine 等组件，实现了请求编排、指标感知路由与分离式执行。其核心创新在于将路由决策与推测深度动态耦合，根据系统负载与请求特征调整推测策略。通过这种设计，系统在异构突发负载下实现了超加性的性能提升。其代价是系统组件间通信开销，且推测策略调整需要快速响应。该方法为分离式 LLM 服务提供了自适应优化方案，提升了尾延迟表现。

分布式与云边协同路线与硬件架构与加速路线存在竞争关系：前者通过软件协同优化跨设备效率，后者通过硬件设计提升单设备效率。两者在资源受限场景下可能形成互补，但在大规模数据中心场景下，硬件解耦可能更具优势。

### 2.4 硬件架构与加速

硬件架构与加速路线针对 LLM 推理特性进行硬件-软件协同设计，涵盖专用芯片、内存架构、编译器优化及新兴硬件。SPAD（Zhang et al., 2025, P3）提出一种针对预填充和解码阶段的专用硬件设计方法论，通过解耦两阶段的资源需求优化芯片设计。该方法基于 H100 GPU 参考设计，进行成本感知的架构设计空间探索，分别设计计算密集型预填充芯片与内存带宽密集型解码芯片。其核心模块包括预填充芯片与解码芯片，前者优化计算吞吐量，后者优化内存带宽与容量。通过这种设计，系统实现了硬件与负载特性的精确匹配，提升了能效比。其代价是芯片设计的复杂性增加，且需要动态重分配机制以应对负载变化。该方法为专用 LLM 加速器提供了设计范式。

Sangam（Kiyawat et al., 2025, P13）提出一种基于 Chiplet 的 DRAM-PIM 加速器，集成 CXL 接口以扩展内存容量并提升带宽。该方法利用 Chiplet 技术将计算逻辑与 DRAM 堆叠，通过 CXL 接口连接多个 Chiplet，形成大规模内存池。其核心模块包括 HARMONI 性能建模框架与 CXL 控制器，前者用于优化内存分配与任务映射，后者管理跨 Chiplet 的数据传输。通过这种设计，系统缓解了 LLM 推理中的内存墙问题，支持更大批处理与更长上下文。其代价是 CXL 接口的延迟，且 Chiplet 间通信开销较大。该方法为大规模 LLM 推理提供了新型内存架构。

CHIME（Chen et al., 2025, P27）提出一种基于 Chiplet 的异构近内存加速架构，专为边缘多模态 LLM 推理设计。该方法利用 RRAM 的 PNM 特性，优化多模态输入导致的 KV 缓存膨胀与跨模态数据传输。其核心模块包括 Vision Encoder、Connector 与 LLM Backbone，通过近内存计算减少数据移动。通过这种设计，系统在小批量推理场景下显著提升了性能，解决了多模态 LLM 的内存瓶颈。其代价是 RRAM 的写能耗较高，且精度受器件变异性影响。该方法为边缘多模态 AI 提供了硬件加速方案。

ZipServ（Fan et al., 2026, P35）提出一种硬件感知的无损压缩 LLM 推理系统，通过离线压缩与在线解码优化内存效率。该方法将 BF16 权重转换为并行友好的压缩表示，利用硬件特性加速解码。其核心模块包括离线压缩器与在线推理引擎，前者优化压缩格式以匹配硬件并行度，后者实现高效的运行时解码。通过这种设计，系统在保持精度的同时减少了内存占用与带宽需求。其代价是压缩/解压的计算开销，且需要硬件支持特定指令。该方法为资源受限环境提供了高效的无损压缩方案。

NorthPole（DeBole et al., 2025, P15）提出一种端到端垂直集成的低延迟能效 LLM 推理系统，基于定制神经推理芯片。该芯片包含 16x16 核心阵列，每个核心拥有独立的计算、通信、控制与内存资源，支持 8/4/2 位整数与 16 位浮点精度。其核心模块包括片上内存与帧缓冲，所有权重与激活驻留片上内存，消除外部内存访问。通过这种设计，系统实现了极高的数据局部性与能效比，适用于边缘与数据中心场景。其代价是芯片设计成本高，且容量受片上内存限制。该方法展示了垂直集成硬件在 LLM 推理中的潜力。

SMEPilot（Chen and Chen, 2026, P47）提出一种基于 Scalable Matrix Extensions（SME）的 LLM 推理优化框架，利用 CPU 矩阵扩展加速矩阵运算。该方法针对预填充与解码阶段的不同计算特性，优化 SME 指令的使用。其核心模块包括矩阵扩展调度器与带宽共享优化器，前者根据算子类型选择 SME 或向量单元，后者优化共享带宽的访问模式。通过这种设计，系统在 CPU 上实现了高效的 LLM 推理，降低了硬件成本。其代价是 SME 指令的编程复杂，且性能受 CPU 架构限制。该方法为 CPU-based LLM 推理提供了优化方案。

A-IO（Zhang et al., 2026, P38）提出一种面向内存受限 NPU 的自适应推理编排框架，解决 Ascend 910B 上的内存瓶颈。该方法通过动态调整模型大小与量化策略，适应不同上下文长度的请求。其核心模块包括系统架构与带宽守恒机制，利用 1B 小模型处理短上下文，7B 大模型处理长上下文，并通过带宽优化减少权重获取开销。通过这种设计，系统在动态请求分布下实现了 Pareto 最优性能。其代价是模型切换的延迟，且需要复杂的调度逻辑。该方法为异构 NPU 提供了自适应推理方案。

Vec-LUT（Li et al., 2025, P19）提出一种向量表查找（Vec-LUT）技术，用于边缘设备上的超低比特 LLM 并行推理。该方法利用 CPU 的向量单元并行执行 LUT 查找，加速三元或低比特权重的计算。其核心模块包括并行 LUT 内核与内存布局优化，前者将 LUT 查找向量化，后者优化内存访问模式以减少延迟。通过这种设计，系统在边缘设备上实现了高吞吐量的并行推理，适用于预填充与并行解码场景。其代价是 LUT 内存占用较大，且对向量单元性能敏感。该方法为边缘超低比特推理提供了高效内核。

硬件架构与加速路线与能效与可持续性路线存在互补关系：前者通过硬件设计提升计算与内存效率，后者通过功耗感知调度优化能效。两者共同构成了 LLM 推理系统从硬件到软件的全栈优化体系。

### 2.5 能效与可持续性

能效与可持续性路线关注 LLM 推理过程中的能耗建模、优化及环境影响，通过频率调节、功耗感知调度、模型切换及硬件协同设计，实现低碳、节能的高效推理服务。VoltanaLLM（Yu et al., 2025, P1）提出一种基于反馈的频率控制与状态空间路由的能效 LLM 服务系统。该方法根据请求特征（如输入输出长度）动态调整 GPU 频率，并将请求路由至不同功耗配置的实例。其核心模块包括频率控制器与状态空间路由器，前者利用反馈机制实时调整频率以平衡延迟与能耗，后者根据系统状态选择最优实例。通过这种设计，系统在满足 SLO 的前提下显著降低了推理能耗。其代价是频率调整的延迟，且需要准确的功耗模型。该方法为能效感知 LLM 服务提供了细粒度控制方案。

PALS（Hankendi et al., 2026, P44）提出一种面向 MoE 模型的功耗感知 LLM 服务系统，通过动态调整功率上限与批处理大小优化能效。该方法针对 MoE 模型专家路由导致的功耗波动，设计了功耗感知的调度策略。其核心模块包括功率上限控制器与批处理优化器，前者根据 QoS 约束动态调整 GPU 功率上限，后者优化批处理大小以最大化每焦耳令牌数。通过这种设计，系统在严格 QoS 下提升了能效，解决了 MoE 模型的功耗管理难题。其代价是功率调整的响应延迟，且需要精确的功耗监测。该方法为 MoE 模型的能效优化提供了新方案。

SweetSpot（Cavagna et al., 2026, P31）提出一种 LLM 推理能效的分析模型，通过解析输入输出序列与硬件参数的关系预测能耗。该方法建立了能耗与序列长度、批处理大小、硬件配置之间的数学关系，避免了昂贵的实测。其核心模块包括能效解析器与优化建议器，前者计算不同配置下的能耗，后者推荐最优配置。通过这种设计，系统为服务提供者提供了低成本的能效预测工具。其代价是模型假设的局限性，且需要准确的硬件参数。该方法为 LLM 推理的能效优化提供了理论指导。

Understanding Efficiency（Delavande et al., 2026, P29）提出一种 LLM 推理能耗的系统性研究框架，分析量化、批处理与服务策略对能耗的影响。该方法通过实验量化了不同配置下的能耗，揭示了输入输出长度、批处理大小与硬件选择对能耗的非线性影响。其核心模块包括能耗测量工具与数据分析框架，前者利用硬件遥测数据精确测量能耗，后者分析数据以识别优化机会。通过这种设计，系统为 LLM 推理的能效优化提供了实证基础。其代价是实验成本高，且结果依赖于特定硬件。该方法为能效研究提供了全面的数据支持。

Pimp My LLM（Zine et al., 2026, P32）提出一种基于变异性建模的 LLM 推理超参数调优方法，优化能效与性能。该方法利用特征模型描述推理配置空间，通过变异性建模预测不同配置下的性能与能耗。其核心模块包括配置空间建模器与超参数优化器，前者构建配置依赖关系，后者搜索最优配置。通过这种设计，系统避免了穷举测试，快速找到能效最优配置。其代价是建模的复杂性，且需要准确的性能预测。该方法为 LLM 推理的自动化调优提供了高效方案。

TokenPowerBench（Niu et al., 2025, P18）提出一种 LLM 推理功耗基准测试工具，系统测量不同配置下的功耗。该方法集成了性能与功耗测量，支持多种硬件与模型配置，提供了标准化的功耗评估框架。其核心模块包括功耗测量器与基准测试引擎，前者利用高精度设备测量功耗，后者执行标准化工作负载。通过这种设计，系统为 LLM 推理的能效比较提供了可靠数据。其代价是测量设备成本高，且测试时间长。该方法为能效研究提供了标准化基准。

Intelligence per Watt（Saad-Falcon et al., 2025, P11）提出一种本地 AI 智能效率度量方法，评估本地 LLM 的能效与性能平衡。该方法定义了“每瓦智能”指标，结合任务准确率与能耗，评估本地 LLM 的综合效率。其核心模块包括智能效率计算器与本地 LLM 评估器，前者计算每瓦智能指标，后者在本地设备上运行 LLM 并测量能耗。通过这种设计，系统为本地 AI 部署提供了能效评估标准。其代价是本地设备性能差异大，且评估结果受任务影响。该方法为本地 AI 的能效优化提供了新视角。

ModeSwitch-LLM（Sunesh et al., 2026, P45）提出一种轻量级相位感知控制器，实现单 GPU 上的跨模式 LLM 推理。该方法根据请求类型（短交互、长生成、重复前缀等）动态切换推理模式（如量化、推测解码、前缀缓存）。其核心模块包括模式选择器与切换控制器，前者根据请求特征选择最优模式，后者管理模式切换以降低开销。通过这种设计，系统在不同负载下实现了最优能效与性能。其代价是模式切换的延迟，且需要准确的请求分类。该方法为单 GPU LLM 服务提供了自适应能效优化方案。

能效与可持续性路线与仿真与基准测试路线存在互补关系：前者通过优化策略降低能耗，后者通过仿真与基准测试提供能效评估工具。两者共同构成了 LLM 推理系统从优化到评估的完整闭环。

### 2.6 仿真与基准测试

仿真与基准测试路线开发 LLM 推理系统的性能仿真器、基准测试工具及分析框架，用于预测延迟、吞吐量、能耗及资源需求，支持系统配置优化、硬件选型及部署决策。LLMServingSim（2025）开发了首个针对 LLM 推理服务的系统级仿真器，能够模拟异构硬件与复杂调度策略下的性能表现，填补了硬件设计与软件优化之间缺乏统一评估平台的空白。

LLMServingSim2.0（Cho et al., 2025, P9）提出一种统一的异构硬件与服务技术 LLM 推理仿真器，支持大规模分布式服务模拟。该方法建模了调度器、内存模型、前缀缓存管理器与实例配置，能够模拟异构 GPU、TPU 与 NPU 环境。其核心模块包括系统级仿真引擎与硬件抽象层，前者模拟请求到达、批处理与 KV 缓存动态，后者抽象不同硬件特性。通过这种设计，系统为硬件设计与软件优化提供了统一评估平台。其代价是仿真精度与速度的权衡，且需要复杂的配置。该方法填补了 LLM 服务仿真领域的空白。

Frontier（Feng et al., 2026, P43）提出一种综合且精确的 LLM 推理仿真器，专注于解耦架构下的运行时动态模拟。该方法能够模拟 KV 缓存迁移、MoE 路由与异构设备协作，捕捉时间相关的性能变化。其核心模块包括运行时动态模拟器与 SLO 预测器，前者模拟请求队列、批处理与内存压力，后者预测 TTFT 与 TPOT。通过这种设计，系统为部署决策提供了高精度预测。其代价是仿真复杂度较高，且需要详细的硬件参数。该方法为解耦架构的优化提供了有力工具。

KernelSight-LM（Yao et al., 2026, P49）提出一种内核级 LLM 推理仿真器，精确模拟 GPU SM 级别的执行细节。该方法建模了 SM 阵列、L2 缓存与 HBM，支持对算子执行与内存访问的细粒度模拟。其核心模块包括内核执行模拟器与 SLO 指标计算器，前者模拟 CUDA 内核的调度与执行，后者计算 TTFT、TPOT 与吞吐量。通过这种设计，系统弥补了系统级仿真器在微观性能预测上的不足。其代价是仿真速度慢，且实现复杂。该方法为内核优化与 SLO 预测提供了精确工具。

Bench360（Stuhlmann et al., 2025, P16）提出一种 360 度本地 LLM 推理基准测试工具，覆盖任务、工作负载、后端与指标。该方法标准化了输入输出，支持多种任务（摘要、QA、Text-to-SQL）与工作负载（单流、批处理、服务器）。其核心模块包括任务引擎、工作负载控制器、后端抽象层与指标收集器，前者执行任务，后者测量延迟、吞吐、内存与能耗。通过这种设计，系统为本地 LLM 部署提供了全面评估框架。其代价是配置复杂，且需要多种后端支持。该方法为本地 LLM 优化提供了标准化基准。

AIConfigurator（Xu et al., 2026, P23）提出一种多框架 LLM 服务配置快速优化工具，利用机器学习预测配置性能。该方法针对 TRT-LLM、vLLM、SGLang 等框架，构建了配置-性能预测模型，避免穷举测试。其核心模块包括配置空间探索器与性能预测器，前者生成候选配置，后者预测吞吐量与延迟。通过这种设计，系统快速找到最优配置，降低了调优成本。其代价是预测模型的训练数据需求，且对未知配置泛化能力有限。该方法为多框架 LLM 服务提供了自动化调优方案。

Comparative Analysis of LLM Serving Systems（Kolluru, 2025, P17）提出一种 vLLM 与 HuggingFace TGI 的性能对比研究框架，评估不同服务系统的特性。该方法在多种模型与负载下测量吞吐量、延迟、内存与可扩展性，揭示了 PagedAttention 与连续批处理的影响。其核心模块包括基准测试引擎与性能分析器，前者执行标准化测试，后者分析性能瓶颈。通过这种设计，系统为服务系统选型提供了实证依据。其代价是实验成本高，且结果依赖于特定硬件。该方法为 LLM 服务系统比较提供了全面数据。

LLMServingSim 2.0（Cho et al., 2026, P33）提出一种统一异构与分离式 LLM 服务基础设施仿真器，支持 PIM/PNM 等新兴硬件。该方法建模了复杂运行时动态，包括队列形成、批处理波动与 KV 缓存迁移，捕捉时间相关的性能变化。其核心模块包括运行时动态模拟器与异构设备协作引擎，前者模拟请求到达与调度，后者模拟不同硬件间的协作。通过这种设计，系统为异构基础设施的部署决策提供了高精度预测。其代价是仿真复杂度较高，且需要详细的硬件参数。该方法为新兴硬件的 LLM 服务优化提供了工具。

Charon（Yang et al., 2026, P42）提出一种统一且细粒度的大规模 LLM 训练与推理仿真器，支持并行策略与网络拓扑优化。该方法构建了基于图的计算图，模拟前向与反向传播，并应用优化与分析。其核心模块包括图前端、多引擎后端与设计探索器，前者构建计算图，后者搜索最优配置。通过这种设计，系统为大规模 LLM 系统的配置优化提供了工具。其代价是仿真精度与速度的权衡，且需要复杂的配置。该方法为训练与推理的统一仿真提供了新方案。

仿真与基准测试路线与其他所有路线存在支撑关系：前者通过仿真与基准测试提供评估工具，后者通过优化策略提升性能。两者共同构成了 LLM 推理系统从设计到验证的完整闭环。

### 2.7 跨任务与多领域应用

LLM 推理系统的应用场景已从单一的文本生成扩展至多模态、多任务及多领域。在文本生成领域，ShareGPT 与 LMSYS-Chat-1M 等基准数据集被广泛用于评估系统的吞吐量、延迟及 SLO 达成率。在长文本处理领域，LongBench 数据集用于评估长上下文场景下的内存管理、注意力机制效率及能耗。在数学推理领域，GSM8K 与 MATH 数据集用于评估 LLM 的数学推理能力，常作为投机解码、边缘推理及模型压缩后的精度验证基准。在常识推理领域，HellaSwag、PIQA、ARC-Challenge、BoolQ 与 Winogrande 等数据集用于评估 LLM 在物理世界常识理解、科学常识、逻辑推理及上下文理解上的零样本性能，是模型压缩和边缘部署精度的常用指标。在文本摘要领域，CNN/DailyMail 数据集用于评估 LLM 的文本摘要生成质量（ROUGE/BLEU），常用于验证分布式推理或投机解码在生成任务上的性能。

这些应用场景对推理系统提出了不同的优化需求。例如，长文本处理对内存管理提出了更高要求，需要高效的 KV 缓存压缩与分层存储策略；数学推理对精度提出了更高要求，需要避免量化与剪枝带来的精度损失；多模态处理对内存带宽提出了更高要求，需要近内存计算与异构加速技术。因此，LLM 推理系统的设计需要综合考虑不同应用场景的需求，实现性能、精度与能效的平衡。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

LLM 推理的预填充阶段是计算密集型，而解码阶段是内存带宽密集型，两者资源需求截然不同，这一共识在约 30 篇论文中被共同支持。KV Cache 的管理效率是决定 LLM 服务吞吐量和并发能力的核心瓶颈，PagedAttention 等内存优化技术已成为现代推理引擎的标准配置，这一共识在约 25 篇论文中被共同支持。连续批处理相比静态批处理能显著提升 GPU 利用率，是处理变长输出请求的必要机制，这一共识在约 20 篇论文中被共同支持。将预填充和解码阶段解耦能有效消除资源竞争，提升整体系统的好吞吐量和 SLO 达标率，这一共识在约 15 篇论文中被共同支持。量化是降低推理成本和内存占用的最有效手段之一，低比特部署在精度损失可控的前提下具有显著优势，这一共识在约 18 篇论文中被共同支持。边缘-云协同推理需要在通信开销、计算延迟和隐私保护之间进行精细权衡，单一设备或纯云端部署均非最优解，这一共识在约 12 篇论文中被共同支持。MoE 架构虽然扩展了模型容量，但引入了显著的路由开销和内存碎片化问题，需要专门的并行策略和调度机制来优化，这一共识在约 10 篇论文中被共同支持。推理能耗已成为数据中心运营成本的主要部分，能效优化与性能优化同等重要，需纳入系统设计考量，这一共识在约 8 篇论文中被共同支持。

### 3.2 观点分歧

预填充-解码解耦的最佳粒度是硬件级还是软件级，存在显著分歧。硬件级解耦（如 DistServe, SPAD）主张将两阶段部署在不同 GPU 或专用芯片上，以彻底消除干扰；软件级解耦（如 DuetServe, Sarathi-Serve）主张在单 GPU 内通过 SM 分区或时间片调度实现逻辑隔离，以降低成本。现有证据偏向硬件级解耦在大规模数据中心场景中的性能上限优势（Goodput 更高），但软件级解耦在边缘/单卡场景更具可行性。证据强度中等，因为缺乏在相同硬件预算下的严格对比实验。测量工具盲区在于现有基准测试往往固定硬件配置，未考虑“总成本”约束，需要设计“成本-性能”帕累托前沿实验，比较在相同预算下两种方案的 SLO 达成率。

能效优化的优先级是性能优先还是能效优先，也存在显著分歧。性能优先（传统观点）认为能效是次要指标，应最大化吞吐量，通过规模效应降低单位成本；能效优先（VoltanaLLM, PALS）认为在严格 SLO 下，动态降频和功耗感知调度可显著降低能耗，且不影响性能。VoltanaLLM 等实验证明在满足 SLO 前提下可节能 30%+，但部分研究指出动态频率调整可能引入尾延迟抖动。证据偏向能效优先在长期运营成本上的优势，但缺乏对极端负载下 SLO 违反率的长期追踪。场景依赖在于能效收益高度依赖于负载特征（如请求长度分布），需要建立统一的“能效-延迟”联合基准，并在多种真实负载下验证动态调度的鲁棒性。

MoE 架构的推理优化是静态并行还是动态路由，同样存在显著分歧。静态并行（传统 TP/PP）假设专家负载均匀，采用固定的并行策略；动态路由（PALS, MeKi）主张根据实时专家激活情况动态调整并行策略或负载均衡。静态并行在负载均匀时效率最高，但在真实对话数据中，专家激活高度动态，导致负载不均和通信开销激增。证据偏向动态路由在真实场景下的必要性，但动态调度的开销（如路由决策延迟）尚未被充分量化。测量工具盲区在于现有仿真器对 MoE 动态路由的建模精度不足，需要开发支持细粒度专家激活模拟的仿真器，并测量动态调度决策本身的延迟开销。

### 3.3 其他开放问题

当前领域面临从“工程优化”向“理论保证”跨越的挑战。工程问题（如更高效的 All-Reduce 通信）已有明确路径，而研究问题（如动态负载下的最优资源分配理论、MoE 路由的能耗建模）仍缺乏统一框架。异构硬件与软件栈的协同设计是解决 GPU、NPU、FPGA 及 CPU 矩阵扩展在 LLM 推理中性能瓶颈的关键，难点在于不同硬件架构的内存带宽与计算特性差异巨大，需通过编译器自动调优、内核级优化及硬件感知调度实现跨平台的高效部署。预填充与解码阶段的解耦与自适应调度是解决两阶段计算特性导致的资源冲突的核心，难点在于动态负载下的实时资源分配与 KV Cache 迁移开销，未来方向包括细粒度 SM 分区、层间调度及基于 SLO 的自适应路由。边缘-云协同推理与模型分割是解决边缘设备算力与内存受限问题的关键，难点在于网络波动下的延迟稳定性与通信开销，需结合 Lyapunov 优化、强化学习及投机解码技术，实现模型层或注意力头的动态分割
