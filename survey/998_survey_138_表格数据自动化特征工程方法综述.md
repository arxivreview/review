综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/Automated%20Feature%20Engineering%20for%20Tabular%20Data)

## 导读

表格数据（Tabular Data）在金融、医疗及工业领域占据核心地位，其预测性能高度依赖特征工程（Feature Engineering, FE），而人工设计特征耗时且难以规模化。自动化特征工程（Automated Feature Engineering, AutoFE）旨在通过算法替代人工，早期研究以基于预定义算子库的组合搜索为主线，思路高效却受制于语义理解的缺失。当大语言模型（LLM）被引入后，问题定义从“在固定算子空间中搜索”转变为“利用语义理解生成可执行代码”，用更强的先验换取特征的可解释性与业务对齐。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从算子搜索到语义生成的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

表格数据因其结构化、异构及语义稀疏的特性，使得传统深度学习难以直接超越树模型（如 XGBoost），而树模型的性能高度依赖特征工程。传统 FE 依赖领域专家手动设计，耗时且难以规模化，导致自动化特征工程（AutoFE）成为 AutoML 的关键瓶颈。该领域的核心问题可形式化为：给定原始表格数据 $X$ 和标签 $y$，自动学习一个特征变换函数 $\phi$，使得下游模型 $f(\phi(X))$ 在验证集上的性能指标（如 ROC-AUC 或 RMSE）最大化，同时满足计算效率与可解释性约束。这一形式化揭示了 AutoFE 与模型架构选择、超参数调优之间的依赖关系：特征工程往往比模型调优对最终性能的影响更大，但其特征空间的设计又受限于下游模型的归纳偏置。

在子问题层面，AutoFE 包含特征生成、特征选择、鲁棒性保障与评估验证四个相互依赖的环节。特征生成是基础，依赖于搜索或生成策略（算子组合 vs LLM 代码生成）；特征选择依赖于生成产生的候选池，需在多样性与计算效率间权衡；鲁棒性与可解释性是对生成质量的约束性要求，尤其在医疗、金融等高利害领域；评估基准则是验证上述所有子问题有效性的外部依赖。若不解决生成环节的语义有效性，鲁棒性与可解释性便无从谈起。这种依赖结构决定了 AutoFE 不能被视为孤立的数据预处理步骤，而是与模型训练紧密耦合的迭代优化过程。

2015 年至 2019 年间，AutoFE 处于奠基阶段，核心假设是特征变换可由有限数学原语组合而成。Deep Feature Synthesis（DFS）通过定义关系路径和数学原语，自动从关系型数据库中生成跨表特征，奠定了“扩展-缩减”（Expand-and-Reduce）范式的基础。Cognito 采用贪心搜索策略探索特征变换空间，展示了启发式搜索替代人工设计的可行性，但在大规模特征空间中效率受限。AutoFeat 引入非线性特征变换并采用 L1 正则化线性模型进行特征选择，突破了早期仅依赖线性组合的限制，证明了非线性交互在表格数据中的重要性。这一时期的方法高效但缺乏语义理解，生成的特征往往缺乏业务含义，难以被领域专家信任。

2023 年标志着范式转变的转折点，LLM 的引入使问题定义从“在固定算子空间中搜索”转变为“利用语义理解生成可执行代码”。CAAFE 首次提出利用 LLM 的自然语言理解和代码生成能力，从数据集描述中合成具有语义意义的特征交互，解决了传统方法缺乏领域知识融入和特征可解释性差的痛点。OpenFE 提出两阶段剪枝策略，通过 FeatureBoost 评估候选特征的增量效用，高效地从大规模候选池中筛选高质量特征，成为当前表格数据特征工程领域最广泛采用的基线系统之一。这一转变不仅提升了特征的可解释性，还引入了幻觉、代码执行安全风险及高昂的 Token 计算成本等新约束。

2024 年至 2025 年，研究焦点转向鲁棒性与协同优化。FeatLLM 通过少样本学习增强 LLM 的上下文学习能力，展示了 LLM 在零样本或少样本设置下自动化特征工程的潜力，但其输出的一致性和鲁棒性受到开放生成性质的限制。FAMOSE 首次将 ReAct（Reasoning and Acting）范式应用于 AutoFE，通过智能体自主探索、生成和精炼特征，并集成特征选择与评估工具，利用 LLM 上下文窗口记录迭代过程中的成功与失败特征，显著提升了在大规模分类和回归任务中的鲁棒性。TopoFE 结合进化算法与 LLM，采用拓扑感知的进化搜索在特征程序空间中搜索，提高了特征搜索的收敛速度和全局优化能力。

2026 年，领域进入精细化与标准化阶段，研究重心转向多智能体协作、因果引导及记忆增强机制。CAFE 结合因果发现（NOTEARS）与多智能体强化学习，引导特征工程保留与目标结果的因果关系，解决了传统基于统计相关性的特征在分布偏移下脆弱的问题。LATTEArena 构建了首个针对 LLM 驱动表格特征工程的标准化评估框架，定义了提示构建、特征优化模块和评估指标，解决了现有研究缺乏统一成本感知评估标准的问题。SymboLLM-FE 结合符号回归与 LLM，生成数学上可解释且计算高效的特征公式，实现了效率与可解释性的平衡。当前形态呈现出以 LLM 为引擎、以验证反馈为闭环、以因果稳定性为鲁棒性保障的新研究生态。

**如果用一个核心问题概括该领域，那便是：如何在保证计算效率与特征可解释性的前提下，利用语义理解能力（LLM）替代或增强传统统计搜索，以构建对分布漂移鲁棒且具备业务因果稳定性的自动化特征生成与选择闭环。**

## 2. 方法体系

- 2015：Deep Feature Synthesis——奠定“扩展-缩减”范式基础

- 2019：AutoFeat——引入非线性变换与 L1 正则化选择

- 2023：CAAFE——首次利用 LLM 生成语义特征

- 2023：OpenFE——提出两阶段剪枝策略的高效基线

- 2025：FAMOSE——引入 ReAct 范式实现迭代探索

- 2026：CAFE——结合因果发现与多智能体强化学习

- 2026：SymboLLM-FE——结合符号回归与 LLM 生成可解释公式

这条时间线勾勒了该领域方法演进的代表性节点：从 2015 年的 Deep Feature Synthesis 奠定该领域方法基线，经 2016 年 Cognito 的推进，到 2026 年的 SymboLLM-FE 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 进化与搜索优化

进化与搜索优化路线的起源可追溯至 2015 年的 Deep Feature Synthesis（DFS），它通过定义关系路径和数学原语，自动从关系型数据库中生成跨表特征，随后利用模型性能进行特征选择。DFS 奠定了 AutoFE 中“扩展-缩减”范式的基础，解决了人工特征工程难以扩展至多表关联场景的问题，是后续许多基于算子库的特征生成系统的先驱。2016 年的 Cognito 采用贪心搜索策略探索特征变换空间，展示了通过启发式搜索替代人工设计特征的可行性，但其搜索效率在大规模特征空间中受限，为后续引入更复杂的搜索算法提供了对比基线。2019 年的 AutoFeat 引入非线性特征变换（如多项式、对数等）并采用 L1 正则化线性模型进行特征选择，有效增强了线性模型的预测能力同时保持特征的可解释性，突破了早期仅依赖线性组合的限制，成为后续许多特征工程系统评估非线性交互效果的基准方法。

随着 LLM 的引入，进化与搜索优化路线发生了范式转变，从固定算子库搜索转向 LLM 引导的程序进化。SymboLLM-FE（Cheng et al., 2026, P22）结合符号回归与 LLM 的两阶段协作流水线，生成数学可解释特征。第一阶段利用计算高效的符号回归发现显式数学公式，第二阶段由 LLM 注入领域先验进行精炼和优化。该方法解决了传统 AutoFE 特征不可解释和纯 LLM 方法迭代成本高、易幻觉的矛盾，其代价是符号回归的搜索空间限制以及 LLM 精炼阶段的计算开销。TopoFE（Li and Ramakrishnan, 2026, P19）采用拓扑感知的 LLM 引导自动化特征工程，利用饱和触发的转移机制，将 Oracle 评估集中在高效用区域，减少收敛所需的代数。该方法解决了固定算子库表达力有限、无法捕捉跨变量语义推理的问题，同时通过进化选择弥补 LLM 提案质量的不足，其代价是进化搜索的计算复杂度和对评估预算的依赖。

SCOPE-FE（Park et al., 2026, P12）旨在解决 OpenFE 中候选生成的计算爆炸问题，通过特征聚类将二元算子限制在簇内对，显著减少无关特征对的生成，并利用可靠性评分稳定初始候选排名。该方法解决了传统扩展-缩减方法中 $O(d^2)$ 候选生成导致的内存和时间开销问题，其代价是聚类策略可能丢失跨簇的潜在交互特征。EFE（Taga et al., 2026, P17）将特征变换视为可执行 Python 程序的进化优化框架，从恒等变换开始，LLM 作为变异算子提出修改后的程序，评估器检查可执行性和泄漏并评分。该方法解决了传统特征工程难以处理时序结构约束和不可逆变换的问题，其代价是程序进化搜索的计算成本和 LLM 提示工程的复杂性。Feature Generation Using LLMs（Nourbakhsh et al., 2026, P18）利用进化算法优化 LLM 生成的特征程序，通过适应度函数评估下游模型性能，解决了单一 LLM 生成缺乏全局优化视角的问题，其代价是进化过程的迭代次数多，计算资源消耗大。

| 方法 | 生成引擎 | 搜索策略 | 核心优势 | 主要代价 | 适用场景 |
|---|---|---|---|---|---|
| SymboLLM-FE | LLM + 符号回归 | 两阶段协作 | 数学可解释性、高效计算 | 符号回归空间限制、LLM 开销 | 需透明决策逻辑的场景 |
| TopoFE | LLM + 进化算法 | 拓扑感知进化 | 收敛速度快、跨模型迁移 | 计算复杂度高、依赖评估预算 | 大规模特征空间搜索 |
| SCOPE-FE | LLM + 算子库 | 结构化控制 | 减少候选爆炸、稳定排名 | 可能丢失跨簇交互 | 大规模表格数据 |
| EFE | LLM + 进化算法 | 程序进化 | 处理时序约束、可逆变换 | 计算成本高、提示工程复杂 | 结构化数据预处理 |
| Feature Generation Using LLMs | LLM + 进化算法 | 全局搜索 | 避免局部最优 | 迭代次数多、资源消耗大 | 需全局最优特征组合 |

进化与搜索优化路线与 LLM 代理协同机制路线的竞争在于：前者通过结构化搜索控制计算成本，后者通过语义探索提升特征创新性。两者在 2026 年呈现出融合趋势，如 TopoFE 和 EFE 均结合了 LLM 生成与进化搜索，体现了“语义引导 + 结构优化”的混合范式。

### 2.2 LLM 代理协同机制

LLM 代理协同机制路线的起源可追溯至 2023 年的 CAAFE，它首次提出利用 LLM 的自然语言理解和代码生成能力，从数据集描述中合成具有语义意义的特征交互，标志着 AutoFE 从基于固定算子库的搜索范式向基于语义理解的生成范式转变。2024 年的 FeatLLM 通过少样本学习增强 LLM 的上下文学习能力，展示了 LLM 在零样本或少样本设置下自动化特征工程的潜力，但其输出的一致性和鲁棒性受到开放生成性质的限制，促使后续研究关注如何评估和诊断 LLM 生成特征的可靠性。

FAMOSE（Burghardt et al., 2026, P7）基于 ReAct 范式构建的智能体框架，通过思考、行动和观察循环自主探索特征空间。系统集成了 Python 代码编译器、元数据生成器和特征评估工具，使 LLM 能够执行代码并获取即时反馈。其核心创新在于利用上下文窗口记录迭代过程中的特征发现与评估历史，形成隐式的少样本提示，引导后续生成更具创新性的特征。该方法放弃了传统的固定算子库限制，转而依赖 LLM 的代码生成能力和试错学习机制，其代价是依赖 LLM 的代码执行环境安全性以及评估预算。MALMAS（Dong et al., 2026, P11）是记忆增强的 LLM 多智能体系统，协调专门化智能体进行特征生成与精炼，包含角色特定的智能体，并共享程序性、反馈性和概念性记忆。其关键技术模块包括记忆检索机制，允许智能体在生成新特征时参考历史成功经验和失败教训，解决了单一 LLM 策略在复杂表格数据中探索能力有限的问题，其代价是增加了系统复杂度和记忆管理的计算开销。

FELA（Ouyang et al., 2025, P2）面向工业事件日志数据的多智能体进化系统，利用 LLM 代理协同构建最优特征变换，系统由 Idea Agents、Code Agent、Critic 等角色组成，通过序列协作实现从概念提出到代码实现再到评估的闭环。其核心创新在于引入进化机制和知识注入，允许代理从长期协作记忆和短期特征记忆中学习，并结合 Web 搜索和业务利益相关者知识，解决了传统表格特征工程无法处理序列上下文的问题，其代价是系统架构复杂，依赖高质量的外部知识源。Rogue One（Bradland et al., 2025, P3）是知识驱动的协作 LLM 多智能体框架，包含 Scientist、Extractor 和 Tester 三个专门化智能体，通过迭代协作发现、生成和验证预测特征，并引入丰富的定性反馈机制和“洪水-剪枝”策略。其关键技术在于集成检索增强生成（RAG）系统，主动融入外部领域知识，确保生成的特征不仅统计有效且语义有意义，解决了现有 LLM 方法作为单体生成器缺乏多样化学习信号和外部知识整合的问题，其代价是 RAG 系统的构建和维护成本，以及多智能体通信的延迟。

nMAS Heart-Failure Pipeline（Shimgekar et al., 2026, P20）基于证据链接的多智能体系统，用于心脏衰竭特征工程，工作流包括 Achievability Agent 检查数据可用性，Query Parser 路由请求，以及规则/LLM 混合提取层。其核心创新在于将指南基于的临床推理编码到显式评分标准中，并保留从每个特征到其支持证据和源记录的可追溯性，解决了临床数据中特征工程缺乏审计链接和临床依据的问题，确保生成的复合变量符合医学指南，其代价是依赖高质量的临床指南评分标准和复杂的证据追踪机制。LeJOT-AutoML（Ma et al., 2026, P9）是 LLM 驱动的特征工程框架，针对 Databricks 作业执行时间预测，系统包含 Feature Analyzer Agent (FAA)、Feature Extraction Agent (FExA) 和 Feature Evaluation Agent (FEvA)。FAA 利用 RAG 从日志、领域知识库和元数据存储中提出结构化特征列表，FExA 通过 MCP 工具链生成提取程序，其核心改进在于引入代码完成检查器和数据泄漏检查器作为安全门，确保生成代码的可执行性和无泄漏性，解决了企业 ML 工作流中手动特征工程滞后于工作负载漂移的问题，其代价是依赖复杂的 MCP 工具链和严格的沙箱环境。

| 方法 | 生成引擎 | 搜索策略 | 核心优势 | 主要代价 | 适用场景 |
|---|---|---|---|---|---|
| FAMOSE | LLM + ReAct | 迭代探索 | 鲁棒性强、创新性高 | 依赖代码执行安全、评估预算 | 大规模分类和回归 |
| MALMAS | LLM + 多智能体 | 记忆增强 | 长期记忆、协作精炼 | 系统复杂度高、记忆开销 | 复杂表格数据 |
| FELA | LLM + 多智能体 | 进化机制 | 处理序列上下文、知识注入 | 架构复杂、依赖外部知识 | 工业事件日志 |
| Rogue One | LLM + 多智能体 | RAG + 洪水-剪枝 | 语义有意义、可测试假设 | RAG 成本高、通信延迟 | 科学发现场景 |
| nMAS Heart-Failure | LLM + 多智能体 | 证据链接 | 可审计、符合医学指南 | 依赖临床指南、证据追踪 | 高风险医疗领域 |
| LeJOT-AutoML | LLM + 多智能体 | MCP 工具链 | 实时适应、无泄漏 | 依赖 MCP 工具链、沙箱 | 云资源优化 |

LLM 代理协同机制路线与进化与搜索优化路线的互补在于：前者通过多智能体协作和记忆机制提升特征生成的语义有效性和鲁棒性，后者通过结构化搜索控制计算成本。两者在 2026 年呈现出融合趋势，如 FELA 结合了多智能体协作与进化机制，体现了“语义协作 + 结构进化”的混合范式。

### 2.3 因果与鲁棒性增强

因果与鲁棒性增强路线的起源可追溯至 2024 年的 FeatLLM，它通过少样本学习增强 LLM 的上下文学习能力，展示了 LLM 在零样本或少样本设置下自动化特征工程的潜力，但其输出的一致性和鲁棒性受到开放生成性质的限制，促使后续研究关注如何评估和诊断 LLM 生成特征的可靠性。2025 年的 Multi-level Diagnosis and Evaluation（Lim and Yoon, 2025, P1）针对 LLM 生成特征的鲁棒性，提出多层诊断与评估框架，基于领域专业知识的三个基本方面：识别关键变量、特征-特征关系和特征-目标关系。其核心创新在于引入变量描述和样本的扰动测试，检查 LLM 是否能一致地排名正确变量，从而评估其鲁棒性，解决了现有 LLM 特征工程方法输出不一致、不可靠且缺乏系统性评估的问题，其代价是评估过程需要额外的扰动实验和人工标注基准。

CAFE（Malarkkan et al., 2026, P6）结合因果发现与多智能体强化学习，第一阶段利用 NOTEARS 学习因果图，将特征按与目标的关系分组，提供软归纳指导；第二阶段使用因子化多智能体策略探索变换空间。其核心创新在于将因果结构作为先验，通过概率选择和奖励塑形引导搜索，而非刚性约束，解决了传统基于统计相关性的特征在分布偏移下脆弱的问题，提升了模型在机制保持协变量偏移下的泛化能力，其代价是因果发现阶段的计算开销和对因果假设的依赖。SIGMA（Zheng et al., 2026, P21）是 SHAP 引导的隐式轨迹生成，用于无元数据的 LLM-based AutoFE，系统首先通过 SHAP 值将特征分为顶级、有用和弱组，利用噪声阈值动态调整分组。其核心创新在于引入 EXIT 机制控制上下文大小，并通过隐式轨迹生成引导 LLM 关注当前特征空间的盲点，解决了 LLM 在缺乏元数据时注意力分散和上下文窗口限制的问题，提高了特征生成的针对性和效率，其代价是 SHAP 计算的成本和分组策略的敏感性。

| 方法 | 生成引擎 | 搜索策略 | 核心优势 | 主要代价 | 适用场景 |
|---|---|---|---|---|---|
| Multi-level Diagnosis | LLM | 扰动测试 | 系统性评估鲁棒性 | 需额外扰动实验、人工标注 | LLM 特征可靠性评估 |
| CAFE | LLM + 因果发现 | 多智能体强化学习 | 分布漂移鲁棒性、透明度 | 因果发现开销、依赖因果假设 | 高利害工业场景 |
| SIGMA | LLM + SHAP | 隐式轨迹生成 | 无元数据引导、针对性强 | SHAP 计算成本、分组敏感性 | 无元数据场景 |

因果与鲁棒性增强路线与 LLM 代理协同机制路线的竞争在于：前者通过因果结构提供稳定性保障，后者通过多智能体协作提升语义有效性。两者在 2026 年呈现出融合趋势，如 CAFE 结合了因果发现与多智能体强化学习，体现了“因果引导 + 智能体协作”的混合范式。

### 2.4 领域知识融合应用

领域知识融合应用路线的起源可追溯至 2023 年的 CAAFE，它首次提出利用 LLM 的自然语言理解和代码生成能力，从数据集描述中合成具有语义意义的特征交互，解决了传统方法缺乏领域知识融入和特征可解释性差的痛点。2026 年的 MedFeat（Zhang et al., 2026, P8）是模型感知且可解释性驱动的特征工程，针对临床表格预测，系统结合 LLM 的领域知识与下游模型特性，通过反馈机制生成具有临床依据的特征。其核心创新在于引入模型感知模块，根据下游模型（如逻辑回归或 XGBoost）的需求调整特征的非线性程度和交互类型，解决了通用 LLM 特征工程缺乏临床验证和模型适配性的问题，确保特征既符合医学指南又能被特定模型有效利用，其代价是依赖高质量的临床领域知识库和模型反馈循环。

Eureka（Li et al., 2026, P13）面向企业 AI 云资源需求预测的智能特征工程，系统包含 Eureka Expert（领域专家 LLM）、LLM Feature Factory 和 Self-Evolving Alignment Engine。其核心创新在于通过监督微调（SFT）和组相对策略优化（GRPO）嵌入领域知识和业务逻辑，将特征工程形式化为条件生成问题，解决了通用 LLM 在稀疏历史和波动模式（如 GPU 资源突发需求）下缺乏语义理解的问题，其代价是领域专家标注数据的需求和微调的计算成本。EAFD（Sakhno et al., 2026, P10）是桥接潜在表示与可解释特征的事件序列特征发现框架，系统利用预训练编码器生成嵌入，并通过 LLM 生成器提出确定性可解释特征。其核心创新在于引入对齐分数（Alignment Score）和下游效用分数（Downstream Utility Score），分别评估特征对嵌入信息的解释能力和对下游任务的互补性，解决了传统 AutoFE 独立于嵌入空间、无法评估冗余性和互补性的问题，其代价是依赖预训练编码器质量和双目标优化的复杂性。

FEST（Khurana et al., 2026, P15）通过自进化桥接专家知识与自动化特征工程，系统支持发现模式和专家种子模式，利用双流生成（语义和确定性特征）、语义去重和树引导进化。其核心创新在于实现生成-去重-验证的闭环，利用决策树提供特征重要性信号指导迭代剪枝和特征库进化，解决了单次生成器冗余和虚假特征的问题，同时确保特征符合专家文档化的标准，其代价是语义嵌入和聚类计算的开销。

| 方法 | 生成引擎 | 搜索策略 | 核心优势 | 主要代价 | 适用场景 |
|---|---|---|---|---|---|
| MedFeat | LLM + 领域知识 | 模型感知反馈 | 临床依据、模型适配 | 依赖临床知识库、反馈循环 | 临床表格预测 |
| Eureka | LLM + SFT/GRPO | 条件生成 | 嵌入领域知识、业务逻辑 | 需专家标注、微调成本 | 云资源需求预测 |
| EAFD | LLM + 预训练编码器 | 双目标优化 | 桥接潜在表示、可解释 | 依赖编码器质量、优化复杂 | 事件序列数据 |
| FEST | LLM + 专家知识 | 自进化闭环 | 符合专家标准、可审计 | 语义嵌入、聚类开销 | 高风险领域 |

领域知识融合应用路线与 LLM 代理协同机制路线的互补在于：前者通过领域知识注入提升特征的专业性和可信度，后者通过多智能体协作提升特征生成的鲁棒性。两者在 2026 年呈现出融合趋势，如 MedFeat 结合了领域知识与模型感知反馈，体现了“领域知识 + 模型适配”的混合范式。

### 2.5 基准评估与协同优化

基准评估与协同优化路线的起源可追溯至 2023 年的 OpenFE，它提出两阶段剪枝策略，通过 FeatureBoost 评估候选特征的增量效用，高效地从大规模候选池中筛选高质量特征，成为当前表格数据特征工程领域最广泛采用的基线系统之一。2026 年的 TabPrep（Tschalzev et al., 2026, P14）填补表格基准中特征工程缺口的通用方法，系统识别现代模型仍遗漏的结构模式，并引入模式驱动的特征生成器。其核心创新在于将特征工程视为显式表示结构模式以补偿模型归纳偏置的方法，而非仅作为数据预处理，关键技术模块包括针对特定操作家族（如目标编码、非线性变换）的基准就绪生成器，解决了现有基准缺乏数据集无关的特征工程基线、导致峰值性能评估不完整的问题，其代价是生成器需要针对特定结构模式定制。

LATTEArena（Hao et al., 2026, P16）是 LLM 驱动表格特征工程的评估框架，系统定义了 LATTE 形式化定义，包含提示构建、特征优化模块和评估指标。其核心创新在于提供标准化的评估 harness，支持不同 LLM 特征工程方法的直接比较，并引入成本感知评估，解决了现有研究缺乏统一评估标准、难以量化性能变化技术驱动因素的问题，其代价是框架的复杂性和对标准化提示模板的依赖。CoFEH（Xu et al., 2026, P5）是 LLM 驱动的特征工程与协作贝叶斯超参数优化，系统采用四步迭代循环：动态优化器选择、模块执行（FE 使用 MCTS，HPO 使用 BO）、评估和奖励反馈。其核心创新在于联合优化特征工程和超参数空间，利用 PUCB 规则动态决定执行 FE 还是 HPO，解决了传统 AutoML 中特征工程和超参数优化独立进行、缺乏协同的问题，其代价是联合搜索空间的复杂性和计算开销。

FEAML（Gao et al., 2025, P4）是桥接结构化数据和 LLM 的多标签任务特征工程框架，系统将自然语言请求翻译为代码，实现自动预处理和特征生成。其核心创新在于针对多标签分类场景，利用 LLM 的语义理解能力生成适合多标签输出的特征表示，解决了现有 LLM 特征工程主要关注单标签任务、在多标签领域探索有限的问题，其代价是多标签特征生成的复杂性和评估指标的多样性。

| 方法 | 生成引擎 | 搜索策略 | 核心优势 | 主要代价 | 适用场景 |
|---|---|---|---|---|---|
| TabPrep | 模式驱动生成器 | 结构模式识别 | 补偿模型归纳偏置 | 需针对特定模式定制 | 表格 ML 基准 |
| LATTEArena | LLM | 成本感知评估 | 标准化比较、可复现 | 框架复杂、依赖提示模板 | LLM 特征工程评估 |
| CoFEH | LLM + 贝叶斯优化 | 联合优化 | 特征与超参数协同 | 搜索空间复杂、开销大 | 端到端 ML 管道 |
| FEAML | LLM | 多标签特征生成 | 扩展多标签任务 | 生成复杂、评估多样 | 多标签表格学习 |

基准评估与协同优化路线与其他路线的互补在于：前者通过标准化评估和协同优化提升方法的公平性和端到端性能，后者通过具体方法实现特征生成和选择。两者在 2026 年呈现出融合趋势，如 LATTEArena 为 LLM 特征工程方法提供了标准化评估框架，CoFEH 实现了特征工程与超参数优化的协同，体现了“标准化评估 + 协同优化”的混合范式。

### 2.6 跨任务与多领域应用

跨任务与多领域应用是 AutoFE 方法在实际部署中的关键挑战。在临床领域，MedFeat 和 nMAS Heart-Failure Pipeline 展示了 LLM 特征工程在医疗场景下的可解释性与性能，解决了通用 LLM 特征工程缺乏临床验证和模型适配性的问题。在工业领域，FELA 和 LeJOT-AutoML 展示了 LLM 特征工程在事件日志和云资源优化场景中的实时适应能力，解决了传统表格特征工程无法处理序列上下文和工作负载漂移的问题。在金融领域，EAFD 和 FEST 展示了 LLM 特征工程在事件序列和品牌分类场景中的可解释性与鲁棒性，解决了传统 AutoFE 独立于嵌入空间、无法评估冗余性和互补性的问题。

在基准评估方面，TabPrep 和 LATTEArena 为表格 ML 基准和 LLM 特征工程评估提供了标准化框架，解决了现有基准缺乏数据集无关的特征工程基线、难以直接比较不同 LLM 特征工程方法的问题。在协同优化方面，CoFEH 实现了特征工程与超参数优化的联合优化，解决了传统 AutoML 中特征工程和超参数优化独立进行、缺乏协同的问题。在多标签任务方面，FEAML 扩展了 LLM 特征工程的应用范围，证明了其在复杂多输出任务中的有效性，为多标签表格学习提供了新的自动化路径。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

特征工程对表格数据模型性能的影响往往超过模型架构选择或超参数调优，这一共识在多个基准上被反复验证：FAMOSE 的 1.0±0.0 与 TopoFE 的 0.999±0.000 均大幅超越经典 OpenFE 的 0.999±0.001 和 AutoFeat 的 0.977±0.025（支撑证据：P7、P19、P12）。与此相关的另一个共识是 LLM 在特征工程中主要作为语义推理和代码生成引擎，而非端到端的预测模型，这一观点在 CAAFE、FAMOSE、MALMAS 等工作中得到一致体现（支撑证据：P7、P11、P3）。

多智能体协作（Multi-Agent）通过分工和反馈循环能显著提升特征生成的质量和鲁棒性，这一共识在 FELA、Rogue One、nMAS Heart-Failure Pipeline 等工作中得到验证（支撑证据：P2、P3、P20）。特征的可解释性在医疗、金融等高利害领域是部署的必要条件，而非可选属性，这一共识在 MedFeat、nMAS Heart-Failure Pipeline 等工作中得到体现（支撑证据：P8、P20）。基于统计相关性的特征在分布漂移场景下表现脆弱，因果引导的特征工程更具泛化潜力，这一共识在 CAFE 的工作中得到初步验证（支撑证据：P6）。

### 3.2 观点分歧

LLM 语义生成与进化/统计搜索在精度与效率上的优劣是领域内的核心分歧。LLM 派认为 LLM 生成的特征具有语义意义，能捕捉复杂业务逻辑，长期看更具泛化潜力（代表：CAAFE, FAMOSE）；搜索派认为进化算法或结构化搜索（如 OpenFE, TopoFE）在固定评估预算下精度更稳定，计算成本更可控，且无幻觉风险（代表：OpenFE, TopoFE）。现有证据显示，在 UCI 等经典基准上，TopoFE 和 SymboLLM-FE 的精度（0.999）略高于或持平于 FAMOSE（1.0，但方差大），且计算成本更低。但在需要可解释性的临床场景，MedFeat（LLM+领域知识）表现更优。证据强度中等，缺乏大规模工业场景的长期对比。

这一分歧的背后，是另一个更根本的争论：因果引导特征与统计相关特征在分布漂移下的鲁棒性之争。因果派认为因果不变性特征在分布漂移下更稳定，能提升模型泛化能力（代表：CAFE）；统计派认为统计相关特征在数据充足且分布稳定时精度更高，因果发现本身存在不确定性，可能引入偏差（代表：OpenFE, AutoFeat）。CAFE 在因果引导任务上表现优于 FAMOSE（0.684 vs 0.679），且理论支持因果稳定性。但因果发现依赖 NOTEARS 等算法，其可靠性受数据质量和样本量限制，现有实验多在合成或小型数据集上进行。证据强度较弱，缺乏大规模真实世界分布漂移的验证。

### 3.3 其他开放问题

最紧迫的工程问题是降低 LLM 计算成本，优化多智能体通信效率，构建标准化 RAG 知识库。现状是 LLM 特征工程的 Token 成本高昂，多智能体通信延迟显著，RAG 知识库构建和维护成本高。关键困难在于 LLM 的计算成本难以直接换算为传统计算时间，且多智能体通信效率受限于 LLM 的上下文窗口。研究路径包括引入更高效的 LLM 骨干网络、优化多智能体通信协议、构建标准化 RAG 知识库。

最根本的研究问题是如何量化 LLM 生成特征的解释性，如何在部分可观测性下学习可靠因果结构，如何实现特征工程与超参数优化的真正端到端协同。现状是缺乏统一的解释性量化评估指标，因果结构学习的可靠性受数据质量和样本量限制，联合搜索空间复杂度指数级增长。关键困难在于解释性缺乏统一标准，因果发现依赖数据质量，联合优化缺乏理论保证。研究路径包括结合人类专家研究进行多面评估、将因果图作为软归纳偏置而非刚性约束、开发更高效的协同优化算法（如贝叶斯优化）。

已知—争议—未知认知图谱显示：已知 LLM 特征工程在可解释性和语义有效性上占优，争议在于 LLM 语义生成与进化/统计搜索在精度与效率上的优劣、因果引导特征与统计相关特征在分布漂移下的鲁棒性，未知如何量化 LLM 生成特征的解释性、如何在部分可观测性下学习可靠因果结构、如何实现特征工程与超参数优化的真正端到端协同。发展趋势是向“语义-因果-计算”深度融合的智能系统演进，实现高效、鲁棒且可解释的自动化特征工程。

## 4. 总结与展望

AutoFE 领域的核心矛盾从“搜索效率”转变为“语义有效性”与“计算成本”的平衡，这一矛盾驱动了从算子搜索到语义生成的范式重构。早期工作（如 DFS, AutoFeat）假设特征变换可由有限数学算子组合而成，受限于算力与理论，采用贪心或 L1 正则化搜索，虽高效但缺乏语义理解，难以处理复杂业务逻辑。CAAFE（2023）抛弃固定算子库，引入 LLM 进行语义驱动的特征代码生成，获得了特征的语义可解释性和领域知识融入能力，但引入了 LLM 幻觉风险、代码执行安全风险及高昂的 Token 计算成本。FAMOSE（2025）引入 ReAct 范式和多智能体协作，放弃单一 LLM 一次性生成，转向迭代式探索与验证，通过上下文记忆和反馈循环显著提升了特征生成的鲁棒性和创新性，缓解了幻觉问题，但系统复杂度增加，迭代次数增多导致总计算时间延长。TopoFE（2025）结合进化算法与 LLM，放弃纯 LLM 随机生成，采用拓扑感知的进化搜索，提高了特征搜索的收敛速度和全局优化能力，但进化搜索的计算开销大，需要大量的评估预算。CAFE（2026）引入因果发现（NOTEARS）作为先验，放弃纯统计相关性驱动的特征选择，增强了特征在分布漂移下的鲁棒性和模型的泛化能力，但因果发现阶段计算开销大，且依赖因果假设的正确性。SymboLLM-FE（2026）结合符号回归与 LLM，放弃纯 LLM 生成不透明代码，转向生成显式数学公式，实现了特征的高效计算和数学可解释性，但符号回归搜索空间受限，LLM 精炼阶段仍有计算开销。

未来可能突破的方向包括：开发更严格的解释性量化评估指标，如概念对齐分数和反事实解释保真度，以客观比较 LLM 生成特征的可解释性（支撑证据：P8、P20）；探索混合优化策略，结合 LLM 驱动的逻辑结构生成与高效数值方法（如坐标下降）进行参数调优，以弥合自动特征工程与全规模 AutoML 之间的差距（支撑证据：P5、P16）；增强因果推理在自动特征工程中的应用，开发在部分可观测性和流式环境下的鲁棒因果发现机制（支撑证据：P6、P21）。对进入者最值得做的一件事是：在统一骨干与统一预训练条件下，构建包含成本感知、分布漂移测试和解释性量化的标准化评估基准，以公平比较不同 AutoFE 方法的性能与效率。
