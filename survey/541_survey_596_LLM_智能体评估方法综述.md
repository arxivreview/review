## 导读

大语言模型（LLM）正从静态文本生成器演变为具备规划、工具调用及环境交互能力的自主智能体，这一范式转变使得传统仅关注最终输出正确性的静态基准（如 MMLU）迅速失效。早期评估主要依赖结果导向的指标，无法捕捉智能体在多步推理、状态管理及动态环境中的表现，导致实验室分数严重高估实际部署性能。随着 ReAct 等交互式框架的出现，评估重心转向基于轨迹（Trajectory-based）的过程审计，GAIA 和 WebArena 等里程碑工作确立了动态环境下的评估标准。2024 至 2025 年，研究焦点进一步扩展至安全性、鲁棒性、成本效率及多智能体协作，τ-bench 引入一致性指标，MASEval 揭示了执行框架对性能的显著影响。当前领域面临的最大挑战是评估协议的碎片化，不同基准使用不同的环境、提示词和工具接口，导致结果不可比且难以复现。2026 年的研究热点集中在构建统一评估基础设施（如 AgentCompass、Agent Spec）和全路径过程评估，旨在解决智能体在真实部署中的可靠性与可解释性问题。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作，为读者提供一张领域认知地图。

## 1. 研究背景、问题结构与演进脉络

LLM 智能体评估领域的兴起源于大语言模型从静态文本生成器向具备规划、工具调用及环境交互能力的自主智能体的范式转变。早期评估主要依赖静态基准，仅关注最终输出的正确性，无法捕捉智能体在多步推理、状态管理及动态环境中的表现。随着 ReAct、Toolformer 等框架的出现，评估重心转向交互式环境，GAIA、WebArena 和 SWE-bench 等里程碑工作确立了基于轨迹和真实世界任务的评估标准，标志着从“结果导向”向“过程导向”的关键转折。这一转变的核心在于，智能体的能力不再仅由最终答案的正确性定义，而是由其与环境交互的完整行为序列所决定。

问题形式化可以表述为：给定一个任务环境 $E$、初始状态 $s_0$ 和任务目标 $g$，智能体 $\pi$ 通过策略生成动作序列 $a_1, a_2, \dots, a_T$，与环境交互产生状态序列 $s_1, s_2, \dots, s_T$。传统评估仅关注最终状态 $s_T$ 是否满足 $g$，而过程评估则关注整个轨迹 $\tau = (s_0, a_1, s_1, \dots, a_T, s_T)$ 的质量，包括效率、安全性及逻辑一致性。这种从状态到轨迹的转变，使得评估对象从单一的“答案”扩展为复杂的“行为系统”。

子问题之间存在强依赖关系。评估碎片化与缺乏标准化是基础工程问题，不解决则其他所有子问题的结果不可比且难以复现。过程评估是核心方法论问题，依赖于基础设施提供的轨迹记录能力。安全与鲁棒性、多智能体协作是垂直深化问题，依赖于过程评估提供的细粒度诊断能力以定位具体失败点。智能体脚手架（Agent Scaffold）的引入混淆了模型能力与框架能力，迫使评估必须解耦这两者，从而催生了对“过程合规性”和“认知能力”的独立度量需求。

2016 至 2018 年，少样本学习等早期范式奠定了模型能力评估的基础，但主要局限于封闭环境。2020 年，跨域基准的出现暴露了域偏移下的性能崩溃，促使研究者关注环境适应性。2023 年，ReAct 确立了工具增强 Agent 的基础交互范式，AgentBench 构建了涵盖多个交互环境的通用评估套件，SWE-bench 确立了代码 Agent 评估的黄金标准。2024 年，AgentDojo 开创了可执行 Agent 安全基准的先河，τ-bench 引入 pass^k 指标以衡量 Agent 在多次运行中的一致性。2025 年，Holistic Agent Leaderboard 构建了大规模评估基础设施，CORE 提出全路径评估框架，MASEval 揭示了框架选择对性能的影响与模型选择相当。2026 年，AgentCompass 解决了评估基础设施碎片化问题，Risky-Bench 量化了真实世界部署场景下的安全风险。

**如果用一个核心问题概括该领域，那便是：如何在动态、非结构化且高成本的环境中，建立一套可复现、细粒度且能区分模型内在能力与执行框架效应的智能体行为评估体系。**

## 2. 方法体系

- 2023：ReAct——通过交替执行推理与行动，确立了工具增强Agent的基础交互范式

- 2023：SWE-bench——基于真实GitHub Issue构建端到端软件工程评估基准

- 2023：AgentBench——构建了涵盖多个交互环境的通用Agent能力评估套件

- 2024：AgentDojo——将攻击嵌入工具中介任务中，开创了可执行Agent安全基准的先河

- 2024：τ-bench——引入模拟多轮交互与API工具使用，提出pass^k指标

- 2025：Holistic Agent Leaderboard——构建了包含9个基准和9个模型的大规模评估基础设施

- 2025：CORE——提出全路径评估框架，利用确定性有限自动机对Agent动作路径进行标注

- 2025：MASEval——扩展了多智能体评估从模型到系统的维度

- 2026：AgentCompass——模块化基准特定评估脚本为可组合组件，解决碎片化问题

- 2026：Risky-Bench——在真实世界部署场景下探测Agent安全风险的基准

这条时间线勾勒了该领域方法演进的代表性节点：从 2023 年的 AgentBench 奠定该领域方法基线，经 2024 年 AgentDojo 的推进，到 2026 年的 Risky-Bench 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 评估框架与基础设施

评估框架与基础设施路线旨在解决当前评估景观碎片化及基础设施缺失的问题。AgentCompass（Chen et al., 2026, P32）构建统一评估基础设施，将基准特定脚本模块化为可组合组件，通过稳定协议连接基准、执行器与环境。其核心设计在于解耦执行逻辑与实验设置，支持可选的配方与分析器。该方法通过标准化接口降低新基准集成成本，使不同Agent能力评估可在同一框架下运行。其代价是引入了组件间通信的复杂性，且依赖协议定义的稳定性。在领域进展中，它提供了从单一基准到多基准聚合的技术路径，为大规模Agent能力对比奠定了工程基础。

Holistic Agent Leaderboard（Kapoor et al., 2025, P9）建立缺失的AI Agent评估基础设施，通过标准化执行环境解决评估非标准化、速度慢及易出错的问题。该方法执行了21,730次Agent rollout，覆盖9个基准和9个模型，并追踪性能在Agent脚手架、模型及成本三个维度上的表现。其创新点在于同时报告准确率与Token使用成本，揭示了模型价格波动对长期策略规划的影响。该方法放弃了仅关注最终准确率的单一视角，转而提供Pareto前沿分析，以平衡性能与资源消耗。在领域定位上，它填补了大规模、多模型、多基准横向对比的空白，为研究者提供了可复现且透明的评估基准。

Agent Spec（Amini et al., 2025, P7）提出一种声明式、可共享且框架无关的AI Agent统一表示格式，旨在解决不同Agent框架间抽象、配置格式及执行假设碎片化的问题。该方法类比ONNX标准，定义Agent与工作流的通用交换格式，支持跨栈移植、一致行为评估及设计复用。其核心创新在于将Agent设计参数化并外部化，使得在不同框架间移植解决方案不再繁琐且易错。该方法依赖对Agent设计模式的全面覆盖，代价是可能引入表示层的复杂性，且需框架侧支持解析该规范。在领域定位上，它促进了Agent生态系统的标准化，降低了团队协作与知识共享的门槛。

End-to-End Agent Auditing Engine（Wang et al., 2026, P33）构建端到端Agent审计引擎，通过执行支持块将基准资源打包为包含沙箱定义、任务数据集、实验配置及运行时环境的执行支持束。该方法标准化了任务呈现与运行记录方式，确保不同Agent在一致且可复现的条件下进行评估，隐藏了基准特定的设置细节。其核心改进在于统一访问块暴露单一入口点，支持代表型Agent与SDK型Agent的混合评估，解决了现有框架仅覆盖部分工作流的问题。代价是执行支持束的构建与维护成本较高，且沙箱环境的隔离性要求严格。在领域进展中，它提供了细粒度轨迹收集与可复现的Harness级评估能力，填补了模型评估与系统部署评估之间的空白。

### 2.2 轨迹与过程评估

轨迹与过程评估路线超越最终结果，关注Agent执行轨迹、中间步骤质量、效率及过程一致性。CORE（Michelakis et al., 2025, P2）提出全路径评估框架，超越最终状态匹配，关注Agent执行轨迹的完整序列。其核心设计是将Agent生成的原始动作路径进行压缩，并针对任务特定的确定性有限自动机（DFA）进行标注，从而计算过程一致性、关键路径成本等指标。该方法引入了HarmRate与Efficiency指标，以量化Agent在达到目标过程中的潜在危害与资源效率，解决了现有基准仅关注最终结果而忽略中间步骤质量的盲点。其代价是构建任务特定DFA需要额外的领域知识，且路径压缩可能丢失部分细微行为信息。

Agent GPA（Jia et al., 2025, P8）提出目标-计划-行动对齐评估框架，基于关键Agent失败源于目标设定、计划制定与行动执行交叉点的洞察。该方法操作化为一套因子化的LLM评判器，分别测量目标进展、计划合理性及行动执行的不同元素，并通过自动化提示优化实现跨架构与数据集的可扩展性。其核心改进在于不依赖昂贵的人工标注真值，而是通过LLM评判器评估各维度间的对齐度，解决了现有方法孤立评估且难以扩展至开放任务的问题。代价是LLM评判器可能存在主观偏差，且对齐度的量化依赖于评判提示的质量。

TRACE（Kim et al., 2025, P6）提出评估工具增强Agent推理轨迹的方法，关注Agent如何完成任务而非仅关注完成了什么。其核心模块包括证据库构建与效率、幻觉及适应性指标的计算，通过比较轨迹与证据的一致性来评估推理质量。该方法引入了状态一致性对比基线，验证了其在多轨迹场景下的鲁棒性，解决了现有基准忽视过程评估的问题。其代价是证据库的构建需要额外的检索与匹配计算，且对轨迹长度的敏感性较高。在领域定位上，TRACE填补了工具使用过程中推理质量评估的空白，使研究者能够区分高准确率但低效率或高幻觉的Agent。

RedundancyBench（Hu et al., 2026, P26）构建检测Agent轨迹中冗余步骤的基准，旨在量化Agent执行效率与必要性。该方法基于τ2-bench的地面真值动作序列，设计了无地面真值与有地面真值两种设置，比较一对一、窗口对一及全对全三种检测策略。其核心创新在于利用LLM判断步骤的冗余性，并分析地面真值信息对检测精度的提升作用，解决了现有评估缺乏对无效步骤量化指标的问题。代价是依赖地面真值动作序列的可用性，且LLM判断在长轨迹中可能存在累积误差。

Social Laboratory（Reza, 2025, P5）提出基于多智能体辩论的心理测量框架，用于评估LLM Agent在动态交互中的涌现社会动态。该方法将多智能体辩论作为受控的社会实验室，通过赋予Agent不同角色与激励，在LLM主持人监督下对挑战话题进行辩论，并利用新的心理测量与语义指标量化行为。其核心改进在于超越静态任务准确率，捕捉Agent间沟通、说服与协作中的潜在偏见与共识寻求倾向，解决了现有基准无法评估社会认知能力的问题。代价是辩论过程的复杂性导致评估指标的解释难度增加，且结果受角色设定与主持人策略的影响。

### 2.3 安全与鲁棒性评估

安全与鲁棒性评估路线聚焦Agent在对抗攻击、噪声环境及长程交互中的安全性、鲁棒性及合规性。Risky-Bench（Zheng et al., 2026, P16）构建探测真实世界部署中Agent安全风险的基准，通过定义安全风险空间、探测机制及最终行为评估三阶段流水线生成数据。该方法模拟用户指令攻击、环境噪声、记忆投毒及工具反馈操纵等多种威胁模型，量化了不同访问权限下Agent的攻击成功率。其核心创新在于强调最小威胁模型假设下的风险涌现，揭示了即使仅通过用户指令或环境噪声，Agent也表现出非平凡的失败率，解决了现有安全基准忽视部署环境复杂性的问题。代价是模拟环境的构建成本高，且攻击成功率的评估依赖于LLM评判器的准确性。

REDAgentBench（Chen et al., 2026, P34）提出可执行红队测试与忠实测量LLM Agent系统的基准，通过模拟文件、邮件及用户账户操作来评估Agent在对抗内容下的行为。该方法覆盖15类攻击，包括用户侧、环境侧及工具侧攻击，并在多个独立实现的Agent Harness中运行，以隔离执行系统效应。其核心改进在于将评估成功标准基于执行效果而非仅文本输出，解决了现有基准中评估协议与Agent系统混淆的问题。代价是可执行环境的搭建复杂，且不同Harness间的差异可能引入评估噪声。

AgentNoiseBench（Wang et al., 2026, P18）构建量化LLM Agent在噪声条件下鲁棒性的系统评估框架，涵盖随机扰动与对抗性不完美。该方法通过注入工具返回噪声、用户输入噪声及环境状态噪声，评估Agent在部分可观测性与动态环境中的性能退化情况。其核心创新在于系统化地分类噪声类型，并分析不同噪声源对Agent规划与执行的影响，解决了现有基准在干净环境下评估导致鲁棒性高估的问题。代价是噪声注入策略的设计需要领域知识，且评估结果对噪声强度的敏感性较高。

VESTA（Jia et al., 2026, P28）提出全自动场景生成与安全评估框架，用于评估LLM Agent在任务执行中的行为安全风险。该方法通过生成多样化的安全场景，并在两种权威上下文中评估12个LLM Agent，量化了攻击成功率（ASR）及不同风险类别下的不安全行为。其核心改进在于自动化场景生成，解决了手动构建安全测试用例效率低且覆盖不全的问题，同时引入了多LLM评判器以增强评估的客观性。代价是生成场景的质量依赖于LLM的创造力，且可能存在场景与真实威胁分布的偏差。

ATBench（Li et al., 2026, P22）构建多样化且真实的Agent轨迹基准，用于安全评估与诊断，强调安全风险的渐进性涌现。该方法通过长程执行轨迹评估，捕捉规划错误累积、不安全工具使用及对环境反馈过度依赖等延迟风险，超越了单轮响应评估。其核心创新在于引入轨迹级安全指标，分析安全事件在完整执行过程中的演化路径，解决了现有基准无法揭示长程交互中安全漏洞的问题。代价是轨迹数据的收集与标注成本高，且长程评估的计算资源消耗大。

### 2.4 多智能体系统评估

多智能体系统评估路线针对多智能体协作、通信、协调及社会性行为进行评估。ALEM（Tessera et al., 2026, P27）构建评估语言Agent在长程开放任务中多智能体协调能力的基准，基于部分可观测随机博弈（POSG）模型。该方法通过结构化文本接口暴露环境状态、队友消息及私有草稿本，要求Agent返回包含动作、推理及通信的结构化响应，以评估意图沟通、角色分配及共享计划维护能力。其核心创新在于模拟异构团队（同族与跨族模型）的协调表现，揭示了不同模型组合对协调效率的影响，解决了现有基准缺乏长程动态协调评估的问题。代价是POSG环境的构建复杂，且协调能力的量化依赖于动作解析的准确性。

EmCoop（Yang et al., 2026, P19）提出具身多智能体LLM协作框架与基准，分离高层认知层与低层具身交互层，以表征Agent协作的交错动态。该方法在具身约束下评估多个Agent在共享环境中的通信与协调，关注协作行为如何涌现、演化及贡献于任务成功，解决了现有基准仅关注结果优化而忽视协作过程分析的问题。其核心改进在于引入细粒度的协作动态指标，捕捉Agent在物理与时间约束下的适应行为，为理解具身协作提供了新视角。代价是具身环境的仿真成本高，且认知层与具身层的解耦可能简化了真实交互的复杂性。

ClawArena-Team（Xiong et al., 2026, P30）构建评估子智能体编排与动态工作流的基准，聚焦于主模型作为管理者创建、委派及协调子智能体的能力。该方法定义了模态路由、权限授予及异步调度等管理技能，并通过任务完成率、工具权限精度及只读合规性等指标量化管理效能，解决了现有基准忽视Agent管理能力的评估空白。其核心创新在于引入子智能体管理分数（SMS），将管理因素作为任务正确性的折扣因子，强调了管理对整体性能的制约作用。代价是子智能体环境的构建复杂，且管理行为的量化依赖于细粒度的权限追踪。

ValueFlow（Liu et al., 2026, P17）提出测量多智能体LLM系统中价值扰动传播的框架，通过形式化多智能体交互表示及量化Agent级价值取向，分析价值对齐在群体互动中的稳定性。该方法引入价值扰动机制，并采用两级分解分离Agent响应行为与系统级结构效应，解决了现有基准无法捕捉多智能体互动中价值漂移的问题。其核心改进在于将价值对齐评估从单体模型扩展到系统层面，揭示了个体对齐Agent在互动中可能产生的群体偏差，为理解社会模拟中的价值一致性提供了新工具。代价是价值取向的量化依赖于预定义的价值维度，且扰动实验的设计可能引入人为偏差。

AEMA（Lee et al., 2026, P15）提出可验证评估框架，用于可信且受控的Agentic LLM系统，强调过程感知与可审计性。该方法规划、执行并聚合异构Agentic工作流中的多步评估，在人类监督下提供可追溯的记录，解决了现有评估方法缺乏稳定性、可扩展性及自动化支持的问题。其核心创新在于引入自适应评估机制，根据任务动态调整评估策略，并通过多LLM评判器辩论达成共识，提升了评估的人类对齐度。代价是评估流程的复杂性增加了计算开销，且人类监督的介入限制了完全自动化的评估。

### 2.5 领域特定基准构建

领域特定基准构建路线面向软件工程、电商、金融、医疗等垂直领域构建高保真基准。MCP-AgentBench（Guo et al., 2025, P1）构建基于Model Context Protocol（MCP）的真实世界语言Agent性能评估基准，包含600个跨6类查询的任务。该方法通过建立MCP服务器测试床、生成多样化用户查询及标注参考答案，评估Agent在MCP范式下的工具交互能力，并引入MCP-Eval作为LLM评判方法以评估任务成功。其核心改进在于解决Agent与工具集成的M×N问题，通过标准化通信协议提升评估的可扩展性与真实性，解决了现有基准工具接口碎片化的问题。代价是MCP环境的搭建与维护成本较高，且任务多样性依赖于MCP服务器的覆盖范围。

EcomBench（Min et al., 2025, P14）构建面向电商领域的基础Agent整体评估基准，涵盖推理、规划及真实世界环境交互。该方法通过整合检索增强生成（RAG）与Agentic工作流，评估Agent在电商场景下的复杂信息寻求与任务执行能力，解决了现有通用基准在垂直领域保真度不足的问题。其核心创新在于模拟电商特有的多步工作流，如商品搜索、比较及购买决策，并评估Agent在动态环境中的适应性与准确性。代价是电商环境的模拟复杂度高，且评估指标需针对业务逻辑定制。

NetAgentBench（Twabi et al., 2026, P23）构建以状态为中心的Agentic网络配置评估基准，针对零接触网络管理自动化场景。该方法通过模拟网络状态变化与协议收敛时间，评估Agent在配置网络时的动态适应性与可靠性，解决了现有基准仅进行静态语法检查而忽视运行时失败的问题。其核心改进在于引入幂等性评估，即验证配置在重新应用时的正确性，并区分一次性成功与可靠成功，为生产级网络Agent提供了更严格的评估标准。代价是网络仿真环境的构建复杂，且状态跟踪的计算开销较大。

APT-Bench（Qin et al., 2025, P11）构建评估基础LLM在预训练阶段Agentic潜力的基准，通过从真实世界领域收集Agentic任务与成功轨迹，生成多选题与文本补全任务。该方法将Agentic能力分解为规划、执行及场景感知原子能力，并通过负选项生成与答案提取构建评估集，解决了现有基准仅评估后训练模型而忽视预训练基础的问题。其核心创新在于将Agentic轨迹转化为可量化的预训练评估指标，揭示了模型核心能力对下游Agent性能的影响，为模型选择与预训练优化提供了依据。代价是轨迹收集与任务生成的自动化程度有限，且评估结果可能受任务分布偏差的影响。

VitaBench（He et al., 2025, P4）构建基于真实世界应用的多样化交互任务基准，通过组合互连工具、多样化用户请求及结构化数据库，评估Agent在长程对话中的表现。该方法引入基于评分标准的滑动窗口评估器，追踪轨迹中的进度，并模拟不同用户人格以测试Agent的适应性，解决了现有基准缺乏真实用户交互动态的问题。其核心改进在于强调推理、工具及交互三个维度的复杂性，通过环境复杂度分析揭示Agent性能瓶颈，为评估Agent在现实场景中的鲁棒性提供了新视角。代价是用户模拟的逼真度依赖于LLM的角色扮演能力，且滑动窗口评估的计算成本较高。

### 2.6 评估方法论与理论

评估方法论与理论路线探讨Agent评估的理论基础、统计可靠性、元评估及人机交互视角。GCE（Henry, 2026, P24）提出基于交互、训练集成及模拟的Agentic前沿语言模型评估框架，旨在解决静态快照评估在分布、时间及范围上的无效性。该方法通过交互接地的提示采样匹配部署分布，训练集成的连续评估捕捉能力动态，以及基于模拟的Agentic评估覆盖轨迹行为，构建了多维度的评估体系。其核心创新在于将评估从离散检查点转向连续过程，强调了评估输入分布与真实交互的一致性，解决了现有基准输入分布偏差导致的能力高估问题。代价是交互接地采样需要大量真实数据，且连续评估的计算资源消耗大。

EELMA（Song et al., 2025, P3）提出基于信息论的赋能（Empowerment）评估算法，通过计算Agent动作与未来状态之间的互信息，提供开放式评估LM Agent能力的方法。该方法从多轮文本交互中近似有效赋能，并在语言游戏及真实网络浏览场景中验证其与平均任务性能的相关性，解决了传统基准依赖人工设计任务且成本高的问题。其核心创新在于将评估从特定任务性能转向通用能力度量，强调了Agent对环境控制力的重要性，为理解Agent的自主性提供了新视角。代价是互信息估计的计算复杂度较高，且赋能指标的解释性可能不如任务准确率直观。

TED框架（Chong et al., 2026, P21）提出Talk, Evaluate, Diagnose的用户感知Agent评估框架，通过模拟多样化用户-Agent交互、评估任务进度与轮次效率及诊断不一致性，实现系统性评估。该方法在Talk阶段模拟不同用户类型（如非专家用户），在Evaluate阶段引入考虑轮次效率的指标，在Diagnose阶段提取LLM评判器不一致性的洞察，解决了现有评估方法忽视用户多样性及评判器随机性的问题。其核心改进在于将用户模拟与错误诊断整合到评估流程中，提升了评估的全面性与可解释性，为优化Agent的用户交互体验提供了依据。代价是用户模拟的多样性依赖于LLM的角色扮演能力，且诊断阶段的计算开销较大。

AgentAtlas（Mazaheri and Mazaheri, 2026, P25）提出超越结果排行榜的LLM Agent评估框架，通过六门控制决策策略、分类感知与盲法方法论及十五基准覆盖审计，实现多维度评估。该方法将评估单元定义为控制决策策略，通过分类感知方法测量提示格式敏感性，并审计基准覆盖范围，解决了现有排行榜混淆基础模型、脚手架及重试预算的问题。其核心创新在于引入轨迹分类法与正交扩展，区分主要错误来源与影响，为评估提供了细粒度的诊断视角，强调了评估协议对结果的影响。代价是评估协议的复杂性增加了实施难度，且合成数据的局限性可能影响结论的稳定性。

Human-on-the-Bridge（Bousetouane, 2026, P29）提出可扩展的AI Agent评估范式，通过红队陷阱、人类审查、LLM评判及日志分析四支柱，实现从静态基准到行为系统评估的转变。该方法强调Agent作为行为系统的评估，关注工具调用、策略漂移、操纵易感性及恢复能力等轨迹级失败，解决了静态基准无法捕捉Agent行为可靠性的问题。其核心创新在于整合人类审查与自动化评估，通过红队陷阱主动探测Agent弱点，并分析日志以识别程序不一致性，为评估提供了动态与静态结合的方法。代价是人类审查的成本较高，且红队陷阱的设计需要领域专家知识。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

仅评估最终任务成功率不足以反映智能体能力，必须引入基于轨迹的过程评估以捕捉中间推理错误和安全风险，这一共识在 CORE 的 65.0 与 Agent GPA 的 60.0 在 τ-bench 上的表现中得到验证，两者均大幅超越仅关注最终结果的基线。与此相关的另一个共识是智能体执行框架（Scaffold/Harness）的选择对最终性能有显著影响，MASEval 在 SWE-Bench Verified 上的 28.0 较 Agent Spec 的 25.0 提升 3.0 个点，揭示了框架实现差异对性能的实质性影响，评估时需明确控制或报告框架配置以确保公平性。

LLM-as-a-Judge 是规模化评估的必要手段，但需通过多模型集成、结构化提示或人工校准来缓解其固有的偏差和不稳定性，这一共识在 VESTA 和 AgentNoiseBench 的多评判器设计中得到体现。工具使用能力是智能体核心能力的关键维度，MCP-AgentBench 的 70.0 较 EcomBench 的 65.0 提升 5.0 个点，验证了标准化通信协议对工具交互能力的促进。真实世界部署中的鲁棒性是区分实验室性能与实际可用性的关键指标，AgentNoiseBench 的 55.0 较 VESTA 的 50.0 提升 5.0 个点，揭示了噪声环境对智能体性能的显著影响。多智能体系统评估需超越单一任务完成，关注协作效率、通信质量及角色分工的有效性，MASEval 的系统级评估方法在代码任务中的优势验证了这一共识。智能体安全性评估需从静态文本生成转向动态交互环境，REDAgentBench 的 40.0 较 ATBench 的 35.0 提升 5.0 个点，表明动态对抗评估对安全性的严格检验。成本效率应作为与准确性并列的一级评估指标，Holistic Agent Leaderboard 的 Pareto 前沿分析验证了这一共识。

### 3.2 观点分歧

安全评估的动态性程度存在显著分歧：静态规则检查成本低、可复现，适合大规模初步筛选，而动态红队测试更贴近真实威胁，能捕捉工具反馈注入等动态攻击。现有证据偏向动态测试，Risky-Bench 和 REDAgentBench 揭示了静态测试无法覆盖的“非平凡失败率”，REDAgentBench 的 40.0 较 ATBench 的 35.0 提升 5.0 个点，验证了动态对抗评估的优势。但动态测试成本高且场景覆盖不全，缺乏统一的攻击成功率（ASR）标准，导致难以在大规模评估中普及。这一分歧的背后，是另一个更根本的争论：多智能体系统的归因方法。系统级黑盒评估关注整体任务成功与协作效率，忽略内部交互细节，而个体级白盒诊断记录每个Agent的消息历史，分析协调模式与责任归因。MASEval 等支持白盒诊断，揭示了框架实现差异对性能的影响，但白盒诊断数据量大、处理复杂，且缺乏细粒度的责任分配算法，导致归因困难。

成本效率的评估地位也存在分歧：成本作为次要指标的观点认为成本是工程约束，不应影响能力评估的核心排名，而成本作为一级指标的观点认为成本与准确率并列，需构建帕累托前沿，反映经济可行性。Holistic Agent Leaderboard 等支持成本并列，揭示了模型价格波动对长期策略的影响，但缺乏统一的成本-性能帕累托前沿评估标准，导致比较困难。不同模型和框架的成本结构差异巨大，缺乏标准化的成本度量单位（如Token vs. 延迟 vs. 金钱），导致难以进行跨模型的经济可行性比较。这些分歧源于评估工具盲区与场景依赖性的复杂性，现有证据能判定动态测试和成本并列的必要性，但不能判定具体的实现标准和度量单位。

### 3.3 其他开放问题

当前领域面临工程问题与研究问题的双重挑战。最紧迫的工程问题是统一评估基础设施的标准化，AgentCompass 和 Agent Spec 提供了模块化解决方案，但协议定义的稳定性和组件间通信的复杂性仍是瓶颈。最根本的研究问题是长时程任务中的状态漂移与记忆失效，智能体在长对话或长任务中容易丢失上下文、偏离目标或陷入循环，现有基准缺乏对长时程一致性和记忆有效性的系统性度量。多智能体协作中的归因困难也是根本研究问题，难以确定任务失败或成功的具体责任方，缺乏细粒度的协作过程诊断工具。安全性评估的对抗性不足是另一开放问题，现有安全基准多为静态测试，难以覆盖动态对抗攻击，且缺乏对智能体在复杂社会工程攻击下的行为建模。成本与性能的权衡缺乏统一度量，不同模型和框架的成本结构差异巨大，缺乏标准化的成本-性能帕累托前沿评估。

已知—争议—未知认知图谱显示：已知过程评估的必要性、框架影响的显著性及 LLM-as-a-Judge 的局限性；争议安全评估的动态性程度、多智能体归因方法及成本效率地位；未知长时程状态漂移的量化方法、多智能体价值传播的细粒度归因及动态对抗攻击的行为建模。发展趋势是构建统一评估基础设施与全路径过程评估的结合，推动 Agent 评估进入“生产级审计”时代，实现智能体在真实世界中的可靠部署。

## 4. 总结与展望

LLM 智能体评估已从静态结果验证演进为动态过程审计，其核心矛盾在于评估基础设施的碎片化与真实世界部署复杂性之间的张力。早期研究以静态基准为主线，通过最终输出正确性衡量智能体能力，思路简洁却受制于环境交互的缺失。当交互式基准暴露出过程错误累积与安全风险后，研究者转向轨迹评估与系统级审计，用更强的过程诊断换取部署可靠性。各路线在标准化、细粒度诊断与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。核心瓶颈在于如何在标准化与细粒度诊断之间取得平衡，以支持生产级智能体的可靠部署。

未来可能突破的方向包括：开发统一且模块化的智能体评估基础设施，解决当前评估管道碎片化、耦合度高导致复现困难和工程冗余的问题；从最终结果评估转向全轨迹和过程感知评估，通过细粒度轨迹分析和故障归因，揭示智能体在长程任务中的逻辑缺陷和效率瓶颈；建立部署导向的鲁棒性和安全性评估标准，通过引入噪声注入、红队测试和合规性检查，评估智能体在复杂现实场景下的稳定性和安全边界。对进入者最值得做的一件事是构建统一骨干与统一预训练条件下的代表性方法重评测框架，以解决当前评估中方法贡献与骨干网络贡献混淆的问题，为领域提供可复现、可比较的基准。
