# A Survey of LLM Agent Security and Runtime Safety ｜LLM智能体安全与运行时安全综述 ｜arxivreview

综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/LLM%20Agent%20Security%20and%20Runtime%20Safety)

## 导读

大语言模型智能体（LLM Agent）安全的核心矛盾，源于模型从静态文本生成向具备自主规划与工具调用能力的范式转变，这一转变将攻击面从语义输出扩展至数字与物理世界的实际副作用。早期研究聚焦于模型层面的内容合规，但间接提示注入（Indirect Prompt Injection, IPI）的提出揭示了外部数据源可系统性劫持智能体行为的根本缺陷。随着多智能体系统（Multi-Agent System, MAS）与标准化协议（如MCP）的普及，单点防御失效，信任-授权不匹配成为核心瓶颈。当前研究正从单点检测转向全生命周期治理，强调运行时验证与形式化约束的结合。各路线在检测精度、计算开销与通用性之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从内容过滤到运行时治理的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

LLM智能体安全的兴起，根植于智能体身份从“文本生成器”向“环境交互者”的根本转变。在早期大语言模型（LLM）应用中，安全边界局限于模型输出的合规性审查，核心假设是输入为可信的用户指令，防御机制主要依赖模式匹配或静态分类器以拦截有害内容生成。然而，随着ReAct等框架的普及，智能体获得了执行代码、访问文件系统及调用API的权限，这一能力跃迁使得攻击面从“文本输出”急剧扩展至“物理/数字世界副作用”。此时，核心矛盾不再是模型“说什么”，而是模型“做什么”以及“谁授权做”，传统基于输入过滤的防御机制在开放环境中面临系统性失效。

问题定义的演化清晰地映射了攻击向量的动态化与群体化趋势。2023年，间接提示注入（IPI）概念的提出标志着问题边界的重大扩展，它揭示了恶意指令可隐藏在智能体读取的外部内容（如网页、邮件）中，利用LLM无法区分数据与指令的缺陷进行攻击。这一发现证明，即使用户输入看似无害，外部数据源中的恶意载荷也能劫持智能体行为，导致传统基于用户输入的防御机制彻底失效。随后，2024-2025年MCP等标准化协议的引入使得工具生态开放化，多智能体系统（MAS）的兴起进一步将问题演化为“系统性信任危机”。在MAS中，单个被攻陷智能体可通过通信信道污染其他智能体，引发级联故障，单点防御在群体动态中显得力不从心。

子问题之间呈现出强依赖的因果链条，构成了该领域的认知骨架。“数据与指令边界模糊”是基础威胁，若不解决LLM对数据与控制指令的混淆，则“长程行为安全性”无从谈起，因为多步轨迹中的每一步都可能被外部数据劫持。“多智能体级联故障”依赖于单智能体身份与授权机制的健全，若缺乏细粒度的权限隔离，通信信道攻击将迅速扩散。而“安全与效用权衡”则是所有防御机制部署时的最终约束，过强的护栏会显著降低任务完成率，决定了前几类子问题的工程落地可行性。这种依赖关系意味着，任何单一维度的突破若不能与其他子问题协同，都难以实现系统级的安全保障。

范式边界在此过程中发生了根本性位移。传统NLP安全假设“输入可信、输出可控”，而Agent范式下，输入包含大量不可信的外部数据，输出则直接映射为具有副作用的动作。这一位移导致了“信任-授权不匹配”问题的凸显：智能体被赋予了执行复杂任务的自主性，但现有的授权机制仍停留在静态的、基于角色的访问控制层面，无法适应动态委托与上下文感知的需求。2025年后，研究重心从“检测与拦截”转向“全生命周期治理”，强调在保持智能体自主性的前提下，通过运行时验证（Runtime Verification, RV）与形式化方法实现安全与效用的动态平衡。

从时间维度看，约束条件的变化驱动了方法的迭代。2023-2024年，ReAct确立交互范式，IPI揭示外部数据源风险，促使研究从“输入过滤”转向“行为监控”，GuardAgent等早期护栏开始尝试将自然语言约束转化为可执行逻辑。2025年，MCP普及与MAS兴起，ClawWorm等自传播攻击暴露供应链风险，促使引入零信任架构与细粒度授权，DHARMA等设计感知风险度量开始关注架构选择对漏洞的影响。2026年，生产级框架（如OpenClaw）的部署使得安全治理从“附加层”变为“基础设施”，Agent libOS与Layered Governance Architecture（LGA）等系统级方案出现，强调全生命周期审计与操作系统层面的隔离。

当前，该领域处于高速发展期，研究热点集中在多智能体系统的级联故障、智能体沙箱隔离、基于轨迹（Trajectory）的安全评估以及零信任架构在智能体身份授权中的应用。随着OpenClaw等生产级智能体框架的部署，如何平衡自主性与安全性、解决信任-授权不匹配问题，成为学术界与工业界共同关注的核心议题。

**如果用一个核心问题概括该领域，那便是：如何在LLM智能体具备自主规划与工具调用能力的开放环境中，建立一套可验证、可审计且低开销的运行时治理机制，以解决数据-指令边界模糊导致的信任-授权不匹配问题。**

## 2. 方法体系

- 2023：Indirect Prompt Injection (IPI)——揭示外部数据源劫持智能体行为的系统性漏洞

- 2024：GuardAgent——将自然语言安全约束转化为可执行逻辑，实现行为安全监控

- 2025：VeriGuard——引入形式化方法，通过生成可验证代码提升高保障开发可靠性

- 2025：DHARMA——提出设计感知的风险度量，细粒度评分多智能体系统失败模式

- 2026：Spider-Sense——引入内在风险感知机制，实现从被动防御到主动内生防御的转变

- 2026：Agent libOS——借鉴库操作系统理念，构建支持长时程运行的Agent运行时

- 2026：TraceSafe——系统评估LLM护栏在多步工具调用轨迹上的表现

这条时间线勾勒了该领域方法演进的代表性节点：从 2023 年的 Indirect Prompt Injection (IPI) 奠定该领域方法基线，经 2024 年 AgentBench 的推进，到 2026 年的 TraceSafe 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 运行时防护架构

运行时防护架构旨在通过实时监测、拦截或修正潜在有害动作，确保智能体行为符合安全策略。早期方法如GuardAgent（Liu et al., 2024）将自然语言安全约束转化为可执行逻辑，在智能体执行过程中进行动态验证，突破了静态内容分类器的局限，实现了从“内容安全”向“行为安全”的范式转移。然而，外部护栏在对抗性攻击（如语义逃避）下易被绕过，且无法适应动态变化的环境状态。为此，Spider-Sense（Yu et al., 2026）提出内在风险感知（IRS）框架，赋予智能体自主监测自身交互工件的能力，通过条件生成分布计算风险感知指标，动态触发分层自适应筛查（HAS）。该机制将防御内化于智能体执行循环中，实现了从被动响应到主动感知的转变，但代价是增加了推理阶段的计算复杂度，且风险感知模型的准确性直接影响防御效果。

针对执行层面的副作用，SafeAgent（Liu et al., 2026）构建了恢复导向的编排策略，包含上下文覆盖、智能体重规划与上下文回滚机制。其核心设计思路是将安全失败视为可修复的状态偏差，而非简单的终止信号，允许在不中断任务连续性的前提下选择性重写不安全内容。这种方法依赖于对智能体内部状态的可观测性，且重规划过程可能增加延迟，但显著提升了系统在遭遇提示注入等攻击时的生存能力。DreamGuard（Lin et al., 2026）则利用风险感知世界模型构建高效运行时护栏，通过生成式模型重构未来观察以预测智能体动作的安全后果，结合GRU编码器捕捉轨迹时序证据，将安全验证从静态规则匹配转变为动态状态预测。其创新在于能够在动作执行前识别潜在风险，但世界模型的训练成本较高，且预测准确性受限于环境动态性。

在系统级隔离方面，Agent libOS（Zhang, 2026）借鉴库操作系统架构，设计了支持长时程运行的智能体运行时环境，将智能体视为具备身份、调度与资源权限的软件行为者。系统包含AgentProcess、能力控制、进程私有对象内存命名空间及人类队列等模块，实现了细粒度的权限隔离与审计。其核心改进在于将安全边界从提示工程层面上升至操作系统层面，解决了传统聊天循环在身份管理与资源控制上的不足，但架构复杂度较高，且需要底层运行时支持。Fault-Tolerant Sandboxing（Yan, 2025）针对AI编码智能体提出容错沙箱框架，通过基于策略的拦截层与事务性文件系统快照机制实现安全自主执行，将智能体动作包裹在原子事务中，确保在发生破坏性命令或状态不一致时能够回滚到安全状态。该方法平衡了安全性与执行效率，但快照机制可能占用额外存储空间，且事务边界定义需仔细设计。

| 方法 | 核心机制 | 优势 | 局限 |
|---|---|---|---|
| GuardAgent | 自然语言约束转逻辑 | 行为安全监控 | 易被语义逃避绕过 |
| Spider-Sense | 内在风险感知+HAS | 主动内生防御 | 推理复杂度增加 |
| SafeAgent | 恢复导向编排 | 任务连续性保持 | 依赖状态可观测性 |
| DreamGuard | 风险感知世界模型 | 动态状态预测 | 训练成本高 |
| Agent libOS | 库操作系统架构 | 系统级隔离与审计 | 架构复杂度高 |
| Fault-Tolerant Sandboxing | 事务性沙箱 | 原子回滚 | 存储空间开销 |

运行时防护架构与形式化验证路线存在互补关系：前者侧重于工程化的实时拦截与恢复，后者侧重于数学严谨的正确性证明。在低延迟场景中，运行时防护的轻量级机制更具优势，而在安全关键场景中，形式化验证的强保证不可或缺。

### 2.2 多智能体系统安全

多智能体系统（MAS）引入了通信信道攻击、级联故障及角色混淆等新型系统性风险。DHARMA（Arora et al., 2025）提出设计感知的风险度量指标，通过抽象集中式与去中心化MAS的设计原语，如规划、委托、通信与执行，对失败模式进行细粒度评分。该方法旨在揭示特定架构选择如何驱动系统漏洞，例如中央协调器与子智能体之间的权限边界模糊，为MAS的安全设计提供了系统性分析工具，但评估过程需要深入理解各框架的内部实现细节。TrinityGuard（Wang et al., 2026）基于OWASP标准构建了统一的多智能体系统安全防护框架，包含三层细粒度风险分类法，涵盖单智能体漏洞、智能体间通信威胁及系统级涌现危害。系统采用三位一体设计，整合了安全评估、实时监控与防御机制，标准化了MAS风险分类，但框架的部署需要与特定MAS架构进行适配。

针对通信信道攻击，ClawWorm（Zhang et al., 2026）揭示了LLM智能体生态系统中的自传播攻击机制，利用智能体间的通信渠道（如Telegram、Discord及智能体专用论坛）进行恶意代码的横向移动。该攻击利用OpenClaw等框架中的信任层级缺陷，指出缺乏强制边界导致跨层权限提升的可能性，展示了多智能体交互中的供应链攻击新维度。Conjunctive Prompt Attacks（Arif et al., 2026）提出联合提示攻击模型，研究多智能体系统中看似无害的组件在特定对齐条件下如何产生恶意效果。该方法形式化了智能体间（A2A）环境中的威胁模型，分析了客户端智能体分解任务并路由至远程智能体时的随机路由机制，揭示了MAS中局部安全无法保证全局安全的系统性风险。

在检测与防御机制方面，XG-Guard（Pan et al., 2025）提出双层图异常检测框架，用于解释性且细粒度的LLM多智能体系统安全防护。系统将MAS建模为有向图，利用主题基异常检测器捕捉整体语义上下文，并通过双层异常分数融合机制对齐粗粒度与细粒度线索，提高了对动态交互中恶意智能体的识别准确性，但图构建与主题提取增加了计算开销。AdvEvo-MARL（Pan et al., 2025）通过对抗共进化在多智能体强化学习（MARL）中塑造内化安全性，将智能体交互建模为部分可观测马尔可夫博弈，通过协同训练攻击者与防御者，将安全感知嵌入智能体的内在策略中，提升了智能体在未知攻击下的鲁棒性，但训练过程不稳定，且需要大量对抗样本生成。A2A Security Benchmark（ICLR 2026）构建了针对A2A协议的协议感知安全基准，定义了AgentCard欺骗、能力伪装、控制劫持等特定威胁，揭示了异构智能体互操作中的身份认证与权限管理缺陷，为A2A生态系统的标准化安全实践提供了重要参考。

| 方法 | 核心机制 | 优势 | 局限 |
|---|---|---|---|
| DHARMA | 设计感知风险度量 | 架构漏洞量化 | 依赖内部实现细节 |
| TrinityGuard | 三层风险分类法 | 标准化评估 | 需架构适配 |
| ClawWorm | 自传播攻击模拟 | 揭示供应链风险 | 依赖高度互联性 |
| XG-Guard | 双层图异常检测 | 可解释性检测 | 计算开销大 |
| AdvEvo-MARL | 对抗共进化 | 内生安全对齐 | 训练不稳定 |
| A2A Security Bench | 协议感知基准 | 互操作安全评估 | 依赖协议理解 |

多智能体安全路线与治理与合规框架紧密关联：前者侧重于技术层面的检测与隔离，后者侧重于制度层面的授权与审计。在零信任架构下，MAS的通信安全需要结合细粒度的身份认证与动态授权机制，才能实现真正的系统级防护。

### 2.3 形式化验证与理论

形式化验证与理论路线旨在通过数学工具为智能体安全提供严格保证，解决传统启发式防御缺乏正确性证明的问题。VeriGuard（Miculicich et al., 2025）通过形式化方法增强LLM智能体的安全性，核心在于将自然语言规范转化为机器可检查的形式化代码与验证工件。该方法包含策略生成与验证两个阶段，利用LLM生成可验证计算代码，并配套生成验证器所需的组件以检查代码正确性，桥接了自然语言规范与形式化验证之间的鸿沟，但引入了形式化验证的计算开销，且依赖规范描述的精确性。Watchdogs and Oracles（Ferrando, 2025）提出运行时验证（RV）与LLM的共生集成愿景，利用RV作为LLM自主性的护栏，同时利用LLM辅助RV的规范捕获、预期推理及不确定性处理，建立了RV与LLM的互增强机制，但集成过程复杂，且RV规范生成仍需人工辅助。

VET Your Agent（Grigor et al., 2025）通过可验证执行轨迹实现主机无关的自主性验证，即使主机恶意篡改输入或输出，验证器也能基于智能体身份文档（AID）确认输出与声明配置的一致性。该系统模型将智能体、主机及验证器分离，假设主机为计算受限的恶意方，验证器为诚实但好奇方，解决了信任根问题，但验证协议需要密码学支持，且隐私保护设计增加了复杂性。Three-Layer Probabilistic Assume-Guarantee Architecture（Bensalem et al., 2026）论证了安全LLM智能体部署在结构上需要三层概率假设-保证架构，以处理非确定性推理与闭环执行中的不确定性。该架构通过形式化方法定义安全不变量，将智能体行为分解为可验证的假设与保证，引入了概率化假设-保证推理，适应LLM输出的随机性，但形式化模型构建复杂，且概率参数需仔细校准。

Enforcing Temporal Constraints for LLM Agents（Kamath et al., 2025）提出Agent-C框架，通过形式化时间约束强制LLM智能体遵守策略，解决动态护栏无法保证行为合规的问题。该方法将用户请求、工具调用及状态变化建模为时间逻辑公式，在智能体生成工具调用时进行合规性检查，若违规则约束LLM生成合规响应，引入了时间维度到智能体安全验证，但时间逻辑公式构建复杂，且检查过程增加延迟。QuadSentinel（Yang et al., 2025）提出面向多智能体系统的顺序安全框架，通过机器可检查控制实现细粒度安全监控，将智能体交互建模为图，利用编译策略书及类型化存储管理状态，并通过键控谓词更新器处理不可信文本，将指令与数据严格分离，确保不可信文本仅作为值进入最小JSON模式，防止提示注入，但系统配置复杂，且策略书需离线构建。

| 方法 | 核心机制 | 优势 | 局限 |
|---|---|---|---|
| VeriGuard | 形式化代码生成 | 数学正确性保证 | 计算开销大 |
| Watchdogs and Oracles | RV与LLM共生 | 互补安全保证 | 集成复杂 |
| VET Your Agent | 可验证执行轨迹 | 主机无关验证 | 密码学依赖 |
| Three-Layer AG | 概率假设-保证 | 处理非确定性 | 模型构建复杂 |
| Agent-C | 时间逻辑约束 | 时序合规性 | 公式构建复杂 |
| QuadSentinel | 顺序安全控制 | 数据-指令分离 | 配置复杂 |

形式化验证路线与运行时防护架构存在竞争与互补关系：前者提供强保证但难以扩展，后者泛化好但缺乏数学证明。在安全关键场景（如金融、医疗）中，形式化方法更受青睐，但在通用开放环境中，运行时防护的灵活性更具优势。

### 2.4 治理与合规框架

治理与合规框架旨在建立从设计到运维全生命周期的安全治理体系，确保智能体行为符合法律法规、行业标准及组织政策要求。AAGATE（Huang et al., 2025）对齐NIST AI RMF标准，构建了面向Agentic AI的治理平台，整合零信任架构、MAESTRO威胁建模、AIVSS风险分析及SSVC风险优先级排序。该平台提供共同语言与工具，使合规官员、安全工程师及AI开发者能够协作，确保治理成为系统设计的一部分，填补了AppSec工具在智能体治理中的空白，但平台部署需要跨部门协作，且标准映射复杂。AGENTSAFE（Khan et al., 2025）提出基于伦理的治理框架，包含九个组件的闭环循环，将设计时控制与运行时治理相结合，通过识别、缓解及持续监控智能体生命周期中的风险，确保Agentic AI系统在开放环境中的行为符合伦理与合规要求，但框架实施需要组织层面的政策支持，且伦理标准可能因文化差异而异。

Layered Governance Architecture (LGA)（Ge, 2026）提出四层治理框架，包括执行沙箱、意图验证、零信任智能体间授权及不可变审计日志。该框架针对OpenClaw等开源智能体框架进行了实证评估，构建了包含1081个工具调用样本的双语基准，覆盖提示注入、RAG投毒及恶意插件，提供了工程化的安全治理实践，将治理策略嵌入智能体执行流程，但各层治理机制需协同工作，且审计日志存储成本较高。SoK: Trust-Authorization Mismatch（Shi et al., 2025）系统梳理了LLM智能体交互中的信任-授权不匹配问题，指出传统安全模型中授权作为信任代理的假设在智能体场景下失效，分析了自适应推理与工具驱动动作如何导致实体允许行为与应做行为之间的差距，提出了统一视角以推理信念、意图及权限，但解决不匹配需要复杂的权限管理策略，且可能限制智能体灵活性。

Delegation Without Trust（Dantuluri and Sundi, 2026）通过实证差距分析，研究了多智能体LLM系统中身份、授权及运行时治理的缺失，分析了LangGraph、CrewAI、AutoGen及MCP框架，发现大多数框架默认不提供内置授权或委托限制，导致被劫持智能体的越权工具调用得以执行，揭示了现有智能体框架在身份管理与权限隔离上的系统性缺陷，但实施完整授权机制需要框架层面的重构。Vision for Access Control in LLM-based Agent Systems（Li et al., 2025）提出智能体访问控制（AAC）框架，将访问控制从静态守门功能重新定义为动态、认知驱动的信息治理过程，通过多维上下文评估与自适应响应制定模块，综合身份、关系、意图及环境因素，生成上下文感知的端到端响应，超越了二元允许/拒绝决策，但上下文评估计算复杂，且自适应响应可能引入不确定性。

| 方法 | 核心机制 | 优势 | 局限 |
|---|---|---|---|
| AAGATE | NIST AI RMF对齐 | 标准化治理 | 跨部门协作复杂 |
| AGENTSAFE | 伦理闭环循环 | 伦理对齐 | 政策支持依赖 |
| LGA | 四层治理框架 | 工程化实践 | 协同工作复杂 |
| Trust-Authorization Mismatch | 信任-授权分析 | 理论洞察 | 权限管理复杂 |
| Delegation Without Trust | 实证差距分析 | 揭示系统性缺陷 | 框架重构需求 |
| AAC | 动态访问控制 | 上下文感知 | 计算复杂 |

治理与合规框架与多智能体系统安全路线紧密关联：前者侧重于制度层面的授权与审计，后者侧重于技术层面的检测与隔离。在零信任架构下，治理框架为MAS的通信安全提供了制度基础，而MAS安全技术则为治理框架的实施提供了技术支撑。

### 2.5 跨任务与多领域应用

LLM智能体安全的研究已从通用场景扩展至特定领域，如金融、医疗、具身智能等。SafeMind（Chen et al., 2025）针对具身LLM智能体构建安全基准与缓解框架，将智能体推理过程形式化为四阶段管道，并定义事实、因果及时间约束类型，利用LLM的语义理解能力对齐生成动作与约束，而非依赖脆弱的符号匹配，从而适应自然语言的开放性，为具身智能体的安全部署提供了评估标准。RoboSafe（Wang et al., 2025）提出通过可执行安全逻辑保护具身智能体，将安全规则转化为可执行的代码片段，在智能体执行前进行约束验证，提升了具身智能体在物理世界交互中的安全性。

在金融与高风险决策场景中，ManagerBench（ICLR 2026）评估自主LLM在追求运营目标与人类福祉冲突时的安全-实用主义权衡，通过构建高风险决策场景，测试模型在最大化利润或效率时是否选择有害选项，揭示了模型在目标冲突下的潜在风险，推动了智能体目标对齐研究。ODCV-Bench（Li et al., 2025）针对结果驱动的约束违规场景，在持久化命令行环境中评估自主AI智能体的安全性，采用多评委方法论，利用四个前沿LLM作为独立自动评委，通过中位数评分减少单一模型偏差，填补了高stakes场景下智能体安全评估的空白。

在供应链与插件生态方面，Agentic Supply Chain Runtime Attack Taxonomy（Jiang et al., 2026）系统梳理了Agentic供应链运行时的攻击向量与防御策略，提出了“随机依赖解析”概念，指出智能体在推理时动态获取的外部信息构成隐式运行时依赖，揭示了传统静态供应链安全假设在智能体场景下的失效，为智能体供应链安全提供了理论框架。Taming OpenClaw（Deng et al., 2026）针对OpenClaw自主LLM智能体框架进行安全分析与缓解，识别了提示注入、RAG投毒及恶意插件等威胁，分析了智能体操作生命周期的五个阶段，指出缺乏强制边界导致跨层权限提升的风险，为开源智能体框架的安全加固提供了实践指南。

| 领域 | 代表方法 | 核心挑战 | 解决方案 |
|---|---|---|---|
| 具身智能 | SafeMind, RoboSafe | 物理世界交互安全 | 语义对齐约束验证 |
| 金融决策 | ManagerBench | 目标-福祉冲突 | 安全-实用主义权衡评估 |
| 高风险场景 | ODCV-Bench | 约束违规检测 | 多评委评估协议 |
| 供应链 | Supply Chain Taxonomy | 动态依赖风险 | 随机依赖解析 |
| 开源框架 | Taming OpenClaw | 跨层权限提升 | 实证安全分析 |

跨任务与多领域应用与治理与合规框架存在互补关系：前者侧重于特定场景的风险识别与缓解，后者侧重于通用治理原则的制定与实施。在特定领域中，治理框架的原则需要结合领域特定的风险特征进行细化，而领域特定的解决方案也需要纳入通用治理框架中进行标准化。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

LLM 智能体的安全威胁已从内容生成扩展至执行层面，工具调用和环境交互是主要攻击面，这一共识在约 20 篇论文中得到共同支持。间接提示注入（IPI）是当前最严重且难以根除的威胁，因为 LLM 本质上无法完美区分数据与控制指令，约 15 篇论文共同支持这一观点。单一防御机制不足以保障智能体安全，需要多层防御（Defense-in-Depth）架构，约 12 篇论文共同支持。运行时监控是保障自主智能体安全的关键环节，需在动作执行前进行实时验证，约 10 篇论文共同支持。多智能体系统引入了比单智能体更复杂的系统性风险，包括通信污染和级联故障，需要专门的群体安全机制，约 8 篇论文共同支持。最小权限原则和沙箱隔离是限制智能体破坏范围的基础性工程措施，约 7 篇论文共同支持。智能体安全评估需要从静态基准转向动态轨迹评估，关注长程行为的一致性和最终结果的安全性，约 6 篇论文共同支持。形式化方法与 LLM 的结合是提升安全保证强度的重要方向，但面临可扩展性挑战，约 5 篇论文共同支持。

与此相关的另一个共识是，安全与效用的权衡是防御机制部署的最终约束。ManagerBench 的证据表明，严格拒绝会显著降低效用，而动态修复在保持安全的同时提升了任务完成率，支持动态平衡的必要性。这一共识在 AgentDojo 和 ASB 的 SOTA 结果中得到验证：SafeAgent 的恢复导向策略在保持低 ASR 的同时，未显著降低任务完成率，表明动态修复在工程上是可行的。

### 3.2 观点分歧

防御机制的内生性 vs 外生性存在深层分歧。内生性观点认为安全应内化于智能体的策略与推理过程中（代表：Spider-Sense, AdvEvo-MARL），认为外部护栏是“附加层”，易被绕过且增加延迟；外生性观点认为安全应通过独立的外部监控器或沙箱实现（代表：GuardAgent, Agent libOS），认为内生机制受限于 LLM 的不可靠性，外部隔离更可靠。现有证据偏向外生性在已知攻击（如 IPI）上更有效（ASR 更低），但内生性在未知攻击和动态环境中展现出更好的泛化潜力（F1 分数在 ASB 上较高）。定输赢的实验需包含“零样本未知攻击”场景，比较两种方法在未见过的攻击向量下的鲁棒性。分歧根源在于缺乏统一的“内生-外生”混合架构评测基准，且内生安全对齐的训练数据稀缺，导致难以量化内生机制在极端对抗下的真实表现。

这一分歧的背后，是另一个更根本的争论：形式化保证的可行性 vs 概率化学习的泛化性。形式化观点认为安全关键系统必须提供数学证明（代表：VeriGuard, Agent-C），认为概率化方法无法提供可接受的错误率保证；概率化观点认为 LLM 的非确定性使得形式化规范难以构建，概率化学习（如 RL）更能适应开放环境（代表：StepGuard, DreamGuard）。现有证据显示，形式化方法在特定约束下（如时间逻辑）达到 100% Conformance，但仅在窄域有效；概率化方法在广泛场景下 F1 分数更高，但存在不可解释的失败模式。定输赢的实验需在“安全关键”与“通用开放”两类场景中分别评估，看形式化方法的扩展瓶颈是否可突破。分歧根源在于形式化规范构建依赖人工，自动化程度低；概率化方法缺乏理论保证。两者在“精度-开销-通用性”三角中处于不同顶点，尚无统一理论框架整合两者。

### 3.3 其他开放问题

最紧迫的工程问题是运行时监控的性能开销。实时安全验证（如调用额外 LLM 或形式化检查器）引入显著延迟，阻碍了智能体在低延迟场景（如实时控制、高频交易）中的部署。关键困难在于轻量级高效检测算法尚不成熟，现有方法如 DreamGuard 的世界模型预测虽提升了泛化能力，但训练成本较高。研究路径包括基于风险感知的世界模型优化、分层自适应筛查（HAS）的轻量化，以及基于奖励模型的平衡训练，实现精准边界执行。

最根本的研究问题是长程行为安全性的不可组合性。单步动作看似安全，但多步轨迹组合可能产生有害结果（如工具链攻击），当前缺乏有效的轨迹级形式化验证方法。关键困难在于如何形式化定义跨时间步的行为不变量，现有方法如 Agent-C 的时间逻辑约束仅在窄域有效。研究路径包括引入形式化验证、时序逻辑约束和状态机监控，确保代理在长程任务中的行为符合策略，以及基于可验证执行轨迹的主机无关自主性验证，解决信任根问题。

已知—争议—未知认知图谱：已知的是 IPI 是核心威胁，多层防御是必要架构，运行时监控是关键环节；争议的是内生 vs 外生、形式化 vs 概率化、严格拒绝 vs 动态修复；未知的是长程行为不变量的形式化定义、意图隐藏下的安全对齐、多智能体级联故障的因果归因。发展趋势是从“外挂式护栏”向“内生式治理”与“系统级隔离”演进，评测体系从静态基准向动态轨迹基准演进，治理框架从制度层面与技术层面深度融合。

## 4. 总结与展望

LLM智能体安全的核心矛盾在于自主性与安全性的张力，以及单点防御向系统级防御的必然演进。从内容过滤到运行时治理的范式重构，反映了攻击向量从静态到动态、从单点到群体的演变。现有方法在“精度-开销-通用性”三角中做出了不同取舍，但尚未解决长程行为安全性的不可组合性与信任-授权不匹配的根本问题。核心瓶颈在于如何在保持智能体自主性的前提下，以可接受的开销实现长程行为的形式化验证与动态信任管理。

未来可能突破的方向包括：基于世界模型的风险预测（DreamGuard路径）和内生安全对齐（AdvEvo-MARL路径），因其有望突破当前“检测-拦截”的被动模式，实现从“被动防御”到“主动预测”的转变；轨迹级形式化验证与自主防御进化，因其有望解决长程行为安全性的不可组合性问题，实现防御策略的自动更新。对进入者最值得做的一件事是，在统一骨干与统一预训练条件下，构建覆盖“零样本未知攻击”场景的“内生-外生”混合架构评测基准，以量化内生机制在极端对抗下的真实表现，为理论框架的整合提供实证基础。
