## 导读

共指消解（Coreference Resolution, CR）旨在识别文本中指向同一实体的提及并构建实体簇，其核心价值在于维持篇章连贯性与支撑下游实体追踪任务。早期研究聚焦于中等长度新闻语料的高精度匹配，随着应用场景向长文档、多语言及专业领域扩展，问题定义从单纯的统计匹配演变为在资源约束下处理语义稀疏性与歧义性的复杂推理。当 Transformer 的二次复杂度暴露出内存瓶颈后，研究者引入分段、缓存驱逐及增量聚类策略，以牺牲部分全局上下文换取大规模文本的处理能力。与此同时，大语言模型（LLM）的引入并非取代传统监督模型，而是通过混合范式弥补其在提及边界检测上的短板，并增强对零提及与歧义的处理能力。各路线在计算效率、语义鲁棒性与泛化性之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从局部匹配到全局语义的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

共指消解是自然语言处理中理解篇章连贯性的基础任务，其核心目标是从文本中识别指向同一实体的提及（Mentions）并构建共指簇（Coreference Clusters）。在形式化定义上，给定一段文本 $T$，CR 任务旨在将提及集合 $M = \{m_1, m_2, ..., m_n\}$ 划分为若干簇 $C = \{c_1, c_2, ..., c_k\}$，使得同一簇内的提及指向同一实体，不同簇间的提及指向不同实体。这一过程通常分解为提及提取（Mention Extraction）与提及聚类（Mention Clustering）两个子任务，前者负责识别潜在提及边界，后者负责计算提及对之间的共指概率。两者之间存在严格的依赖关系：提及检测的精度直接决定后续聚类效果，检测错误会直接传播至聚类阶段，导致实体轨迹的断裂或错误合并。此外，在省略主语或宾语的语言（如中文、土耳其语）中，隐含的零提及（Zero Mention）需通过上下文推断，进一步增加了提及提取的难度。

早期研究依赖规则与统计方法，2017 年 Lee 等人提出的端到端神经网络模型标志着范式转变，确立了提及检测与聚类联合训练的基础架构。随后，SpanBERT 等预训练模型的引入使 CR 在 OntoNotes 等基准上达到接近人类水平的性能。然而，这一阶段的问题定义隐含了两个关键假设：文本长度可控且语言单一。随着应用场景从新闻语料向书籍级长文本、跨文档新闻聚合及多语言文学文本扩展，这些假设逐渐失效。长文档处理面临 Transformer 自注意力机制的二次复杂度导致的内存溢出问题，跨文档共指则面临缺乏局部上下文线索的语义稀疏性挑战，多语言场景则暴露出形态复杂性（如希伯来语的代词附着）对标准基于词边界假设的冲击。

2016 至 2018 年间，领域处于奠基阶段，核心矛盾是精度与模型复杂度的平衡。Lee et al. (2017) 的 Coarse-to-Fine 框架通过两阶段联合训练确立了现代神经 CR 的基础范式，解决了早期分离式流水线中提及与聚类信息割裂的问题。2019 年，Icoref 引入增量式指代消解策略，通过维护历史提及缓存解决长文本内存瓶颈，为后续长文档处理奠定技术基础。这一时期的方法主要聚焦于单文档内的局部匹配，尚未充分应对超出模型上下文窗口的文本。

2020 至 2021 年，问题定义发生第一次重大转折，从“固定窗口”转向“长文档处理”。LitBank 等长文本基准的出现暴露了标准 Transformer 在内存上的瓶颈，核心矛盾从精度转向内存效率与全局信息保留的平衡。LongDoc 提出基于有界内存神经网络的长文档指代消解方法，通过分段处理与上下文传递机制平衡效率与性能。2021 年，Dual-Cache 设计结合 LRU 与 LFU 的双缓存驱逐策略，优化长文本指代消解中的内存管理，提升了增量聚类在大规模文本中的稳定性。这一阶段的方法通过牺牲部分全局上下文信息换取内存效率，是工程上的必要妥协。

2022 至 2024 年，研究重心向多语言与跨文档扩展。2022 年，CorefUD 启动多语言指代消解语料库统一计划，将不同语言的指代标注标准化为 CoNLL-U 格式，填补了多语言指代消解数据基础设施的空白。2023 年，Seq2Seq 探索序列到序列生成式指代消解方法，展示了生成式范式在指代消解中的潜力。2024 年，Maverick 提出轻量级 Transformer 指代消解模型，通过多专家评分器与高效编码策略实现 SOTA 性能，成为后续长文本与 LLM 混合架构的核心基线。这一时期的方法开始关注语义稀疏性问题，但主要依赖增强表示或时间/语义约束，在缺乏显式线索时性能仍显著低于单文档场景。

2025 至 2026 年，领域进入 LLM 增强与混合范式阶段。2025 年，xCoRe 提出跨上下文指代消解架构，统一解决长文档与跨文档指代消解问题；CorefInst 提出基于指令微调的多语言指代消解方法，利用 LLM 的指令跟随能力处理零提及与多语言指代。2026 年，MEIC-DT 提出内存高效增量聚类方法，引入双阈值约束机制与统计感知驱逐策略；CohTP 提出时间一致性跨文档事件指代消解框架，利用时间约束减少候选搜索空间。这一阶段的核心矛盾变为 LLM 在提及边界检测上的局限性与推理优势的结合，以及歧义检测与消解的权衡。

**如果用一个核心问题概括该领域，那便是：如何在计算资源受限且语义线索稀疏的复杂文本环境中，构建鲁棒的实体轨迹以维持篇章与跨篇章的语义连贯性。**

## 2. 方法体系

- 2017：Coarse-to-Fine——提出端到端监督神经指代消解框架，确立了现代神经指代消解的基础范式

- 2019：Icoref——引入增量式指代消解策略，解决长文本内存瓶颈

- 2020：LongDoc——提出基于有界内存神经网络的长文档指代消解方法

- 2021：Dual-Cache——设计结合 LRU 与 LFU 的双缓存驱逐策略

- 2024：Maverick——提出轻量级 Transformer 指代消解模型，成为后续混合架构的核心基线

- 2025：xCoRe——提出跨上下文指代消解架构，统一解决长文档与跨文档问题

- 2025：CorefInst——提出基于指令微调的多语言指代消解方法

- 2026：MEIC-DT——提出内存高效增量聚类方法，引入双阈值约束机制

这条时间线勾勒了该领域方法演进的代表性节点：从 2017 年的 Coarse-to-Fine 奠定该领域方法基线，经 2019 年 Icoref 的推进，到 2026 年的 MEIC-DT 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 长文本与跨文档指代

长文本与跨文档指代消解是应对 Transformer 二次复杂度瓶颈的核心路线。2017 年 Lee et al. (2017) 的 Coarse-to-Fine 框架确立了端到端联合训练的基础范式，但受限于固定窗口，难以处理超出上下文窗口的文本。2019 年 Icoref 引入增量式策略，通过维护历史提及缓存解决内存瓶颈，为长文档处理奠定技术基础。2020 年 LongDoc 提出基于有界内存神经网络的长文档指代消解方法，通过分段处理与上下文传递机制平衡效率与性能，解决了 Transformer 二次复杂度问题。2021 年 Dual-Cache 设计结合 LRU 与 LFU 的双缓存驱逐策略，优化长文本指代消解中的内存管理，提升了增量聚类在大规模文本中的稳定性。

xCoRe（P8）针对传统方法无法跨越离散上下文进行指代消解的局限，提出一种端到端的跨上下文指代消解架构，旨在统一处理长文档与跨文档场景。该方法将问题分解为三个核心阶段：上下文内提及提取、上下文内提及聚类以及跨上下文集群合并。在提及提取阶段，采用基于 Maverick 的流水线，通过预测起始位置与条件结束位置来识别提及跨度，并引入句末正则化策略以缩小搜索空间。聚类阶段利用多专家架构，根据提及对的语言学类型分配专用评分器，通过双线性交互计算指代分数。跨上下文合并阶段则负责整合不同文档或长文本片段中的集群。该架构通过多任务目标联合训练，理论上可处理长达 25,000 个 token 的输入。其核心创新在于将长文档与跨文档指代消解视为同一问题，避免了分段处理带来的性能损失，但依赖 Maverick 等轻量级模型作为底层技术，牺牲了一定的模型容量以换取可扩展性。

MEIC-DT（P11）专门针对长文本指代消解中的内存瓶颈问题，提出一种内存高效的增量聚类方法。该方法基于轻量级 Transformer，引入双阈值约束机制来调节 Transformer 的输入规模，从而在严格预定义内存预算下保持竞争性性能。首先，设计统计感知驱逐策略，利用训练与推理阶段信息可用性的差异，在受限缓存空间中保留关键指代集群，避免传统 LRU 或 LFU 策略导致的语义表示压缩。其次，引入内部正则化策略，限制每个集群中的提及数量，确保仅选择最具代表性的提及进行计算。其核心取舍在于牺牲部分全局上下文信息以换取内存效率，依赖统计特征进行集群重要性评估。MEIC-DT 在保持高性能的同时显著降低了内存占用，解决了现有方法在长文本处理中因内存溢出而失效的问题，与 xCoRe 的全局统一架构形成互补，前者侧重资源受限环境下的效率优化，后者侧重大规模文本的统一处理。

CohTP（P10）针对跨文档场景中缺乏直接词汇与上下文线索的挑战，提出一种融入时间一致性的跨文档事件指代消解框架。该方法首先构建并精炼时间事件图，利用微调的 NLI 模型预测事件对之间的时间关系，并通过边感知图神经网络（EA-GNN）传播时间信息以解决局部预测错误与逻辑不一致。随后，基于精炼后的时间图将事件划分为时间连贯的片段，通过限制指代预测在时间一致的片段内进行，从本质上消除不可能的指代链接并显著减少候选搜索空间。其核心创新在于显式建模时间约束，将时间信息作为指代消解的先验知识。CohTP 在跨文档事件指代消解中展现了显著优势，特别适用于新闻聚合与事件追踪等下游应用，与 xCoRe 和 MEIC-DT 的通用实体共指形成差异，前者聚焦于事件共指的时间敏感性，后者聚焦于实体共指的通用性。

### 2.2 大模型指代消解方法

大模型指代消解方法旨在结合小模型精度与大模型推理能力，突破传统架构局限。2023 年 Seq2Seq 探索序列到序列生成式指代消解方法，展示了生成式范式在指代消解中的潜力，但受限于提及边界检测精度。2024 年 Maverick 提出轻量级 Transformer 指代消解模型，成为后续长文本与 LLM 混合架构的核心基线。2025 年 CorefInst 提出基于指令微调的多语言指代消解方法，利用 LLM 的指令跟随能力处理零提及与多语言指代。2026 年 ImCoref-CeS 提出 LLM 检查-分割器优化框架，结合轻量级神经模型与 LLM 推理能力，通过提及过滤与集群重构机制，在保持效率的同时提升指代消解精度。

ImCoref-CeS（P7）旨在解决监督神经模型在域外数据上生成过多无效提及的问题，提出一种结合轻量级神经模型与大语言模型推理能力的指代消解优化框架。该方法首先采用轻量级桥接模块（LBM）进行长文本编码，通过 [SEP] token 的隐藏表示调制相邻段落的表示，建立语义链接以缓解分段处理的信息损失。其次，引入双仿射增强的提及检测机制，提升提及边界识别的准确性。核心创新在于 LLM 检查-分割器（Checker-Splitter）模块，其中 LLM 检查器负责过滤无效提及并评估集群质量，分割器则重新分组提及以确保集群内指代一致性与集群间排他性。其核心取舍在于依赖 LLM API 的推理延迟与成本，但通过过滤机制减少了 LLM 调用的频率。ImCoref-CeS 在保持高效推理的同时显著提升了指代消解精度，为混合架构设计提供了新范式，展示了小模型与大模型协同工作的潜力，与 CorefInst 的独立 LLM 范式形成竞争，前者侧重混合架构的鲁棒性，后者侧重指令微调的泛化性。

CorefInst（Arslan et al., 2025, P2）旨在解决传统任务特定模型泛化能力差且无法利用解码器 LLM 的问题，提出一种基于指令微调的大语言模型多语言指代消解方法。该方法将指代消解任务转化为指令跟随任务，通过精心设计的指令、掩码输入与输出格式，使 LLM 能够链接显性提及与零提及。核心创新在于受控推理策略，该策略仅预测替换 MASK token 的集群编号，而保持句子其他部分不变，从而减少计算负载并维持文本结构一致性。在推理过程中，模型按顺序预测每个 MASK token 的集群编号，利用先前决策作为上下文，确保指代链接的连贯性。该方法采用 LoRA 微调与 4 位量化技术，在 Llama、Gemma 和 Mistral 等模型上实现高效训练。其核心取舍在于依赖指令工程的质量，且受控推理策略限制了模型对文本结构的修改能力。CorefInst 在多语言指代消解中展现了强大能力，特别是处理零提及与跨语言泛化，为利用 LLM 进行多语言 NLP 任务提供了有效范式，降低了多语言指代消解的数据与计算门槛，与 ImCoref-CeS 的混合架构形成互补，前者侧重多语言泛化，后者侧重域外鲁棒性。

BioCoref（Salem et al., 2025, P3）旨在评估大语言模型在无任务特定微调情况下的生物医学指代消解能力，提出一种针对生物医学领域指代消解的基准评估方法。该方法对比了基于 SpanBERT 的跨度模型与多种生成式 LLM 在生物医学 PubMed 文章上的表现。核心设计包括四种提示策略：局部提示、上下文提示、缩写感知提示与实体感知提示，以应对生物医学文本中密集的技术术语、频繁缩写与复杂指代表达。对于跨度模型，采用分块策略处理长文档，并通过凝聚聚类基于余弦相似度分组提及。对于 LLM，通过精心设计的提示引导模型识别指代关系，特别关注缩写与实体名称的消歧。该方法揭示了 LLM 在生物医学指代消解中的潜力与局限，指出表面字符串相似性在生物医学文本中指导作用有限，需依赖上下文与语义线索。其核心贡献在于建立了生物医学指代消解的评估基准，填补了该领域 LLM 评估的空白，为生物医学 NLP 研究提供了重要参考，展示了 LLM 在专业领域指代消解中的应用前景与挑战，与通用 LLM 方法形成差异，前者聚焦于领域特定知识的整合，后者聚焦于通用推理能力的利用。

Correct-Detect（Shore et al., 2025, P1）旨在探究 LLM 在解决指代歧义与检测歧义之间的权衡，提出一种评估大语言模型在指代消解中平衡性能与歧义性的实证研究框架。该方法利用 AmbiCoref 数据集，包含无歧义与有歧义的句子对，通过不同提示策略（如 REFLECT、BASIC、CoT、WSC）评估 LLM 的表现。核心创新在于引入“正确无歧义”（Correct Unamb）与“检测歧义”（Detect Ambig）两个指标，分别衡量模型在无歧义句子上的准确性与在有歧义句子上的歧义检测能力。研究发现，过度指令化（如 REFLECT 提示）会引入偏差，降低模型在无歧义案例上的准确性，而基础提示（BASIC）与思维链（CoT）提示在准确性上表现最佳。该方法揭示了 LLM 在指代消解中倾向于过度自信地解决歧义，除非明确提示表达不确定性。其核心贡献在于提供了诊断 LLM 指代消解行为的新视角，强调了歧义检测与准确性之间的权衡关系，为 LLM 在指代消解任务中的可靠应用提供了重要见解，指出在高风险场景中需结合歧义检测机制以提升鲁棒性，与 CorefInst 和 ImCoref-CeS 的性能导向形成差异，前者聚焦于行为诊断与鲁棒性评估，后者聚焦于性能提升。

### 2.3 多语言与领域数据集

多语言与领域数据集旨在解决现有数据在语言多样性、领域术语及文体覆盖上的不足。2022 年 CorefUD 启动多语言指代消解语料库统一计划，将不同语言的指代标注标准化为 CoNLL-U 格式，填补了多语言指代消解数据基础设施的空白。2025 年 GOLEMcoref 构建多语言虚构文学指代消解数据集，涵盖中文、荷兰语、英语等，包含完整长篇小说，解决了现有基准在文体与长度上的局限。2026 年 Hebrew CR Benchmark 构建希伯来语指代消解基准与评估协议，针对形态复杂语言设计原始文本、自动分词与金标准分词三种评估条件，揭示形态复杂度对指代消解的影响。2026 年 SOMD 2026 发布科学软件提及跨文档指代消解共享任务，聚焦软件名称、版本标识符等特定实体类型，填补了科学领域软件指代消解的基准空白。

GOLEMcoref（P9）旨在解决现有基准在语言多样性、文体覆盖与文本长度上的不足，提出一个多语言虚构文学指代消解数据集。该数据集涵盖中文、荷兰语、英语和印尼语的当代粉丝小说，包含短文本与长文本，提供完整的人物弧线与叙事结构。核心创新在于包含零回指（zero anaphora）标注，并定义了角色提及的类型学，包括专有名词、代词、特定名词短语、泛指、隐喻表达等。数据集构建过程严格遵循伦理准则，排除包含明确性内容的作品，并控制文本长度在 200 至 13,000 词之间，确保标注可行性。通过多样化粉丝小说来源，确保叙事世界、角色与场景的多样性。该数据集为文化分析提供了完整的人物弧线与叙事贡献视角，弥补了 OntoNotes 等新闻文本基准在文学体裁上的缺失。GOLEMcoref 为多语言长文本指代消解研究提供了重要资源，推动了文学文本指代消解的发展，特别适用于研究长距离依赖与对话中的指代现象，与 CorefUD 的新闻语料形成互补，前者侧重文学体裁与零提及，后者侧重新闻语料与多语言覆盖。

Hebrew CR Benchmark（Greenfeld and Tsarfaty, 2026, P5）旨在解决形态丰富语言中提及边界与指代消解交织的挑战，提出一个希伯来语指代消解基准与评估协议。该基准针对希伯来语的代词附着语素与形态堆叠现象，设计了三种输入条件：原始文本、自动分词与金标准分词，以隔离形态复杂度对下游性能的影响。核心创新在于评估协议，允许 LLM 在原始文本上直接处理，而神经编码器则需在分词文本上评估，反映了不同架构对分词依赖性的差异。数据集包含金标准提及标注，并支持零样本与少样本提示评估。通过比较不同分词条件下的错误模式，揭示提及类型分布（特别是代词比例）与聚类成功率的变化。该基准填补了希伯来语指代消解研究基础设施的空白，为形态丰富语言的 NLP 研究提供了重要参考。Hebrew CR Benchmark 为评估 LLM 在形态复杂文本中的能力提供了新框架，推动了多语言指代消解在低资源语言中的发展，特别适用于研究分词与指代消解的交互作用，与 GOLEMcoref 的文学语料形成差异，前者聚焦于形态复杂性，后者聚焦于文体多样性。

SOMD 2026（Alkan et al., 2026, P4）旨在解决科学文献中软件实体指代消解的标准化评估需求，提出一个科学软件提及跨文档指代消解共享任务。该任务聚焦于软件名称、缩写、版本限定字符串与 URL 引用等特定实体类型，这些类型在科学文本中具有高度表面规则性但存在跨文档歧义。核心创新在于首次将跨文档指代消解应用于软件提及，填补了该实体类型在指代消解研究中的空白。任务设计包括检测软件提及及其语义关系，并解决跨文档中同一软件实体在不同表面形式下的指代链接问题。通过共享任务形式，促进社区对科学软件指代消解方法的探索与比较。该基准强调了软件提及在研究可重复性与大规模元分析中的重要性，为科学 NLP 提供了新方向。SOMD 2026 为科学领域指代消解研究提供了标准化平台，推动了软件提及检测与消歧技术的发展，特别适用于生物信息学与计算科学等依赖软件工具的领域，与通用实体共指基准形成差异，前者聚焦于特定实体类型与领域知识，后者聚焦于通用实体与通用推理。

### 2.4 语义增强评估体系

语义增强评估体系旨在解决传统统计指标缺乏可解释性与语义诊断能力的问题。2026 年 CNER-Eval 提出基于概念与命名实体识别的语义增强评估框架，通过标签传播技术将语义类别映射到指代集群，提供可解释的错误诊断与数据增强指导。这一路线的出现反映了领域对评估指标可解释性不足的关注，传统指标（MUC/B3/CEAF）仅关注统计匹配，无法揭示模型在特定语义类别上的系统性失败。

CNER-Eval（Gatti et al., 2026, P6）旨在解决传统统计指标缺乏可解释性与语义诊断能力的问题，提出一种基于概念与命名实体识别（CNER）的语义增强指代消解评估框架。该方法通过两步标签传播技术，将 CNER 语义标签叠加到指代消解输出上，首先通过提及分配将 CNER 标签映射到非代词提及，然后通过集群传播将标签扩展到代词提及，实现指代集群的完整语义覆盖。核心创新在于利用 CNER 的统一标签库存，涵盖命名实体与名词概念，克服了传统 NER 仅覆盖命名实体的局限，提供了更丰富的语义类别（如 GROUP、MEDIA、EVENT 等）。通过语义增强的评估，揭示模型在特定语义类别上的系统性失败模式，如人物中心叙事链与事件相关指代的性能差异。该方法还展示了如何利用语义诊断指导目标数据增强，提升域外性能。CNER-Eval 为指代消解评估提供了可解释性反馈，促进了模型优化与数据策略的改进，为领域迁移与错误分析提供了新工具，特别适用于多领域指代消解模型的诊断与改进，与 CoNLL-F1 等统计指标形成互补，前者侧重语义诊断与可解释性，后者侧重整体性能评估。

### 2.5 跨任务与多领域应用

跨任务与多领域应用展示了 CR 方法在不同场景下的适应性与局限性。BioCoref（P3）在生物医学领域的应用揭示了 LLM 在专业术语与缩写处理上的挑战，表明通用模型难以适应领域特定知识，需领域特定微调或知识增强。SOMD 2026（P4）在科学软件领域的应用强调了软件提及在研究可重复性与大规模元分析中的重要性，推动了软件提及检测与消歧技术的发展。Hebrew CR Benchmark（P5）在形态复杂语言中的应用揭示了分词与指代消解的交互作用，为低资源语言 NLP 研究提供了新框架。GOLEMcoref（P9）在文学体裁中的应用弥补了新闻文本基准在文体上的缺失，推动了长距离依赖与对话中指代现象的研究。这些应用表明，CR 方法需针对特定领域的术语、文体及语言特征进行适配，通用模型在域外场景下的泛化能力有限。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

端到端联合训练（提及提取+聚类）优于分离式流水线，能更好地捕捉提及与聚类间的依赖关系，是当前主流架构。这一共识在多个基准上被反复验证：xCoRe 的三阶段架构与 MEIC-DT 的增量聚类均基于联合训练范式，在 LitBank 和 CorefUD 上均取得 SOTA 性能（支撑证据：P8、P11、P2）。与此相关的另一个共识是监督式神经网络模型在计算效率和标准基准性能上仍优于纯生成式 LLM 方法，特别是在提及检测精度上。ImCoref-CeS 的混合架构设计正是基于这一共识，利用监督模型进行提及检测，LLM 进行聚类纠错（支撑证据：P7、P3）。Transformer 的二次复杂度是长文档 CR 的主要瓶颈，必须引入分段、缓存或增量机制才能处理书籍级或长篇新闻文本，这一共识在 LitBank 基准上得到充分验证，MEIC-DT 的双阈值约束机制与 Dual-cache 的缓存驱逐策略均基于此（支撑证据：P11、P10）。

### 3.2 观点分歧

LLM 在 CR 中的角色是独立模型还是混合架构组件，存在显著分歧。观点 A 认为 LLM 应作为独立模型，通过指令微调直接执行 CR，代表方法为 CorefInst；观点 B 认为 LLM 应作为混合架构中的纠错器或聚类器，与监督模型协同工作，代表方法为 ImCoref-CeS。现有证据偏向观点 B，ImCoref-CeS 在保持效率的同时提升了精度，而 CorefInst 虽在多语言上表现好，但受限于指令工程。实验表明，监督模型在提及检测上仍优于 LLM，混合范式能弥补这一短板（支撑证据：P7、P2）。这一分歧的背后，是另一个更根本的争论：模型应追求高置信度消解还是可靠地识别歧义。观点 A 认为模型应尽可能消解歧义，追求高 CoNLL-F1；观点 B 认为模型应可靠地识别歧义，输出“不知道”，以提升鲁棒性。Correct-Detect 研究表明，过度指令化（如 REFLECT）会降低无歧义案例的准确性，而基础提示（BASIC）在准确性上表现最佳。现有证据表明，高置信度消解与歧义检测之间存在权衡，但尚无方法能同时优化两者（支撑证据：P1）。

### 3.3 其他开放问题

最紧迫的工程问题是长文本内存效率与性能的平衡。现状是 MEIC-DT 等方法通过双阈值约束机制在严格内存预算下保持高性能，但牺牲了部分全局上下文信息。关键困难在于缺乏在严格内存预算下评估全局信息保留程度的指标，且不同文本类型对全局上下文的依赖程度不同。研究路径包括开发更精细的缓存驱逐策略与全局信息保留评估指标。最根本的研究问题是 LLM 在歧义处理中的行为机制。现状是 LLM 倾向于过度自信地消解歧义，难以区分“可消解”与“真正歧义”的情况。关键困难在于缺乏统一的歧义评估协议，且“歧义”的定义在主观与客观层面存在差异。研究路径包括设计新的评估协议，鼓励模型在不确定时输出“不知道”，以及改进提示工程以增强歧义感知。已知—争议—未知认知图谱显示，领域在端到端训练、监督模型优势、Transformer 瓶颈等方面达成共识，在 LLM 角色、歧义处理、长文本全局信息保留等方面存在争议，在零提及跨语言泛化、跨上下文统一框架、语义可解释性等方面仍属未知。发展趋势是构建“高效长文本处理 + LLM 增强推理 + 多语言适配”的混合架构，核心问题是如何在资源约束下平衡精度、效率与泛化性，并解决歧义检测与消解的权衡。

## 4. 总结与展望

共指消解已从单一的文本处理任务演变为涵盖长文本、多语言、LLM 增强及语义评估的复杂系统。其核心矛盾在于如何在计算资源受限且语义线索稀疏的复杂文本环境中，构建鲁棒的实体轨迹以维持篇章与跨篇章的语义连贯性。早期研究聚焦于中等长度新闻语料的高精度匹配，随着应用场景向长文档、多语言及专业领域扩展，问题定义从单纯的统计匹配演变为在资源约束下处理语义稀疏性与歧义性的复杂推理。方法演进遵循“解决瓶颈-引入新约束-再优化”的螺旋上升路径，而非线性替代。长文本路线通过分段与缓存策略牺牲部分全局上下文以换取内存效率，LLM 路线通过混合范式弥补监督模型在边界检测上的不足，多语言路线通过专门的数据集与评估协议揭示形态复杂性对标准 CR 假设的挑战。核心瓶颈在于计算效率、语义鲁棒性与泛化性之间的平衡，以及歧义检测与消解的权衡。

未来可能突破的方向包括：多语言与零提及处理，利用 LLM 进行指令微调及开发专门处理零提及的解码器模型，CorefInst 与 GOLEMcoref 共同指向这一方向；长文本内存效率与性能平衡，开发双阈值约束机制、统计感知驱逐策略和内部正则化策略，MEIC-DT 与 xCoRe 共同指向这一方向；LLM 在共指消解中的鲁棒性与歧义处理，设计新的评估协议鼓励模型在不确定时输出“不知道”，Correct-Detect 与 ImCoref-CeS 共同指向这一方向。对进入者最值得做的一件事是：在统一骨干与统一预训练条件下，构建跨上下文共指消解的统一框架，并引入语义增强评估指标以诊断模型在特定语义类别上的系统性失败，从而在资源约束下实现精度、效率与泛化性的最优平衡。
