综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/GUI%20Understanding%20and%20Grounding)

## 导读

GUI 定位（GUI Grounding）旨在将自然语言指令映射至屏幕特定像素坐标或边界框，是 GUI 智能体执行点击、拖拽等原子操作的基础能力。早期研究依赖 HTML 或无障碍树等结构化元数据，但受限于平台兼容性与信息缺失，难以实现跨平台通用性。2024 年 SeeClick 等里程碑工作确立了纯视觉驱动的范式，通过大规模截图-文本-坐标数据微调，实现了跨平台的通用定位能力。随后，研究重心从单纯的坐标预测转向应对高分辨率、密集布局下的细粒度感知瓶颈，涌现出以 UI-TARS、UGround 为代表的基础模型，以及基于强化学习的推理增强策略。2025-2026 年，领域进入精细化与鲁棒性探索阶段，研究热点集中于测试时缩放、注意力机制对齐、不确定性量化及多视角推理，试图在不增加训练成本的前提下提升定位精度。当前，该领域已成为 AGI 实现计算机操作能力的核心组件，研究正从单一点击定位向拖拽、状态预测及复杂交互序列扩展。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

GUI 定位问题的本质是语义空间到像素空间的非刚性映射，其核心挑战在于多模态大语言模型（MLLMs）缺乏原生空间感知能力。早期研究试图通过解析 HTML 或无障碍树（Accessibility Tree）等结构化元数据来定位元素，这种方法在特定平台上有效，但不同操作系统（如 macOS 与 Windows）的结构差异巨大，且元数据常缺失关键视觉信息，导致跨平台泛化能力极差。随着 MLLMs 在视觉感知与语言理解上的突破，领域范式发生了根本性转变：从依赖结构化元数据转向纯视觉驱动，即直接通过截图和自然语言指令预测坐标。这一转变确立了 GUI 定位作为 GUI 智能体核心原子能力的地位，问题形式化通常定义为：给定截图 $I$ 和指令 $T$，预测目标元素的边界框 $B$ 或中心点 $P$，即 $f(I, T) \rightarrow \{B, P\}$。

在纯视觉范式确立后，问题定义迅速从“跨平台兼容性”演变为“细粒度感知”。随着评测基准从通用界面转向高分辨率专业软件（如 4K 屏幕下的 CAD 或开发工具），VLM 视觉编码器的分辨率限制暴露无遗。模型难以在像素级准确区分相邻的小图标或密集文本，导致定位失败。此时，子问题之间呈现出严格的依赖关系：细粒度感知是解决高分辨率定位的前提，指令理解决定了感知目标的准确性，而不确定性量化则依赖于前两者的置信度输出，用于最终的风险控制。若不解决感知模糊，语义映射将失效；若不解决风险感知，错误定位在高风险场景下将导致不可逆后果。

2023 年至 2024 年是领域的奠基期。OmniParser 提出了纯视觉的 GUI 元素解析框架，通过视觉编码器将像素转换为结构化 Token，摆脱了对底层结构信息的依赖，为后续纯视觉 GUI 智能体奠定了感知基础。2024 年，ScreenSpot 基准的发布揭示了通用多模态模型在细粒度视觉定位上的显著短板，确立了 GUI 定位作为独立研究领域的地位。同年，SeeClick 通过大规模 GUI 数据预训练，证明了领域特定预训练对端到端任务成功率的提升作用，确立了“定位预训练”范式，推动了从通用 VLM 向专用 GUI VLM 的转型。

2025 年成为关键转折年，研究重心从“能否定位”转向“如何可靠定位”。ScreenSpot-Pro 基准扩展了评估场景至高解析度专业应用，揭示了模型在小元素密集界面中的性能退化问题，直接催生了针对高分辨率界面定位技术的研发。GUI-Spotlight 提出自适应迭代聚焦细化机制，通过动态执行裁剪与缩放工具以缩小视觉范围，解决了高分辨率屏幕下小目标定位难的问题。与此同时，UI-Actor 引入无坐标定位范式，利用注意力头直接生成视觉 Patch 的注意力权重，避免了离散坐标生成的误差累积，为基于注意力的 GUI 定位提供了新的架构思路。

2026 年，领域进入精细化与鲁棒性探索阶段，研究热点集中于测试时缩放、注意力机制对齐、不确定性量化及多视角推理。DRS-GUI 提出动态区域搜索框架，结合 UI 感知器和 MCTS 动作规划器，通过 Focus、Shift、Scatter 三种感知动作探索候选区域，实现了“搜索-预测”范式。SafeGround 引入不确定性校准机制，通过分布感知的不确定性量化捕获空间分散度，使模型能够识别高风险动作并选择弃权或咨询外部知识，增强了 GUI 智能体在不可逆操作场景下的安全性。ZonUI-3B 和 FocusUI 则分别从训练效率和推理效率入手，通过单卡训练流水线和位置保持的视觉 Token 选择策略，降低了部署门槛，推动了端侧 GUI 智能体的发展。

当前，该领域活跃度极高，已成为 AGI 实现计算机操作能力的核心组件。研究正从单一点击定位向拖拽、状态预测及复杂交互序列扩展，致力于构建可靠、可解释且具备风险感知能力的 GUI 智能体。方法演进不再仅仅是精度的堆叠，而是精度、效率与安全性的多维平衡。

**如果用一个核心问题概括该领域，那便是：如何在缺乏原生空间感知能力的多模态大语言模型中，构建一种兼具高分辨率细粒度感知能力、指令语义鲁棒性及操作风险可控性的视觉-空间映射机制。**

## 2. 方法体系

- 2023：OmniParser——提出纯视觉的GUI元素解析框架，奠定感知基础

- 2024：ScreenSpot——构建大规模GUI定位基准，确立研究地位

- 2024：SeeClick——通过大规模GUI数据预训练，确立定位预训练范式

- 2024：UI-R1——引入基于规则的强化学习框架，提升低资源场景性能

- 2025：GUI-Spotlight——提出自适应迭代聚焦细化机制，解决高分辨率小目标定位

- 2025：UI-Actor——引入无坐标定位范式，利用注意力权重定位可操作区域

- 2025：ZonUI-3B——设计单卡训练高效流水线，实现轻量化模型部署

- 2026：DRS-GUI——提出动态区域搜索框架，实现“搜索-预测”范式

- 2026：SafeGround——引入不确定性校准机制，增强高风险场景安全性

- 2026：FocusUI——提出位置保持的视觉Token选择策略，提升推理效率

- 2026：ScreenVLM——基于文档转标记VLM架构，实现完整屏幕解析

这条时间线勾勒了该领域方法演进的代表性节点：从 2023 年的 OmniParser 奠定该领域方法基线，经 2024 年 ScreenSpot 的推进，到 2026 年的 ScreenVLM 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 自适应视觉聚焦

自适应视觉聚焦路线旨在解决高分辨率密集布局下的细粒度定位失败问题，其核心思想是通过动态裁剪、缩放或迭代搜索缩小视觉范围，提升定位精度与效率。该路线的起源可追溯至对 VLM 视觉编码器分辨率限制的认知，早期方法如 SeeClick 虽通过预训练提升了通用定位能力，但在 4K 专业软件中仍面临小目标混淆的瓶颈。GUI-Spotlight（Lei et al., 2025, P4）针对这一短板，提出了自适应迭代聚焦细化框架。该方法维护一个图像注册表，记录每次裁剪后的图像及其相对于原图的偏移量，并维护包含文本描述和图像的消息历史。在推理过程中，模型根据当前历史决定执行工具动作（如裁剪、缩放）或停止并输出相对坐标。通过迭代执行工具，模型逐步缩小视觉范围，将全局搜索转化为局部精确定位。最终，模型返回的相对坐标通过注册表中的偏移量映射回原图绝对坐标。这种机制允许模型在高分辨率屏幕上动态调整视野，有效缓解了小目标因分辨率不足导致的定位失败问题。其核心优势在于无需重新训练模型，仅通过推理时的迭代交互即可提升定位精度，适用于多种现有 VLM 骨干网络。

随着迭代聚焦机制的成熟，研究进一步转向更复杂的搜索策略。DRS-GUI（Liu et al., 2026, P19）提出动态区域搜索框架，将 GUI 定位视为预测前的准备阶段，旨在识别可靠的推理区域。该方法包含 UI 感知器和 MCTS 动作规划器两个协同模块，UI 感知器解析当前区域的结构化 UI 元素并提供语义线索。规划器调度 Focus、Shift、Scatter 三种区域级动作，生成候选视图并构建区域搜索树。通过区域质量奖励函数，模型动态搜索并修正感知范围，直到找到最合适的语义相关区域。随后，基础 MLLM 在该特定区域内执行最终的坐标预测。这种“搜索-预测”范式减少了视觉冗余，避免了单阶段方法中因逐步裁剪导致的误差累积。该方法特别适用于元素密集且布局复杂的高分辨率界面，通过主动探索提升了定位的鲁棒性。与 GUI-Spotlight 的线性迭代不同，DRS-GUI 引入了树状搜索结构，牺牲了部分推理效率以换取更优的全局视野选择，两者在精度与计算成本之间做出了不同的取舍。

### 2.2 推理增强定位

推理增强定位路线利用思维链、多步推理、反馈修正或不确定性量化，引导模型进行可解释的视觉定位，减少幻觉并提升鲁棒性。该路线的早期探索包括 UI-R1（2024），其引入基于规则的强化学习（RL）框架，利用可验证的奖励信号优化 GUI 动作预测，展示了 RL 在低资源场景下的高效性。然而，RL 的训练复杂度较高，且奖励函数设计依赖人工规则。UI-Ins（Chen et al., 2025, P6）针对自由形式推理在 GUI 定位任务中可能降低性能的问题，提出了多视角指令作为推理（Instruction-as-Reasoning）的两阶段训练框架。该方法首先构建高质量数据管道，解决数据质量问题和指令多样性未被充分利用的挑战。核心算法允许模型将多样化指令作为推理路径，并在推理过程中选择最佳分析视角。通过强化学习阶段，模型学习如何根据指令语义调整推理策略，而非进行自由形式的推理。实验表明，结构化的指令推理比自由 CoT 更有效，因为 GUI 任务需要精确的空间对齐而非发散性思维。该方法强调了指令在 GUI 定位中的核心作用，通过提升模型对指令语义的理解来增强定位准确性。

在推理增强的另一分支中，不确定性量化成为提升可靠性的关键。SafeGround（Wang et al., 2026, P12）提出不确定性感知框架，通过校准使 GUI 定位模型能够进行风险感知预测。该方法利用分布感知的不确定性量化方法，捕获随机样本输出的空间分散度，以评估预测的可靠性。通过校准过程，SafeGround 推导具有统计保证的假发现率（FDR）控制的测试时决策阈值。当预测不确定性超过阈值时，模型选择弃权或咨询外部知识，避免执行高风险动作。这种机制特别适用于不可逆操作场景，如支付审批，增强了 GUI 智能体的安全性。该方法不改变基础模型的架构，而是作为后处理模块集成，提升了现有定位模型的可靠性。其核心贡献在于将不确定性校准引入 GUI 定位，解决了模型“过度自信”导致的错误操作问题。与 UI-Ins 侧重于推理路径的结构化不同，SafeGround 侧重于预测结果的置信度评估，两者在提升鲁棒性的路径上形成了互补：前者优化“如何思考”，后者优化“何时信任”。

### 2.3 高效轻量模型

高效轻量模型路线探索小参数模型、视觉 Token 压缩及单卡训练策略，旨在降低计算成本，实现端侧部署或高效推理的 GUI 定位能力。该路线的兴起源于大规模 GUI 数据标注成本高企以及端侧设备算力受限的现实约束。ZonUI-3B（2026, P28）设计了单卡训练的高效流水线，通过两阶段微调策略（平台通用+分辨率适应）和去重数据构建，实现了 3B 小模型在消费级 GPU 上的高效训练。该方法证明了轻量化模型在 GUI 定位任务上的可行性，降低了部署门槛，推动了端侧 GUI 智能体的发展。其核心贡献在于降低了 GUI 定位模型的训练门槛，证明了标准监督微调在适当数据支持下足以实现强定位性能。

在推理效率方面，FocusUI（Ouyang et al., 2026, P10）提出位置保持的视觉 Token 选择策略，通过查询引导的显著性评分筛选关键视觉 Token 以加速推理。该方法在视觉 Patch 嵌入输入 LM 解码器前，计算 Patch 特征与指令 Token 嵌入的显著性分数，选择 Top-K 索引。随后，使用 POSPAD（Position-Preserving Adaptation）细化序列，保留位置连续性，生成紧凑的视觉序列。这种机制在保持定位精度的同时大幅减少输入 Token 数量，降低了计算成本。方法兼容现有 VLM 架构，无需修改解码器结构，可直接应用于 Qwen2.5-VL 等模型。其核心贡献在于解决了视觉 Token 冗余问题，为资源受限设备上的高效 GUI 定位提供了可行方案。与 ZonUI-3B 侧重于训练阶段的效率不同，FocusUI 侧重于推理阶段的 Token 压缩，两者共同构成了从训练到部署的全链路轻量化方案，为 GUI 智能体的普及化应用奠定了基础。

### 2.4 基准与数据构建

基准与数据构建路线致力于构建涵盖多平台、复杂交互或特定场景的 GUI 定位数据集与评估基准，用于系统性评估模型性能及发现能力短板。该路线是领域发展的驱动力，ScreenSpot 系列基准的发布直接推动了从通用 VLM 向专用 GUI VLM 的转型。VenusBench-GD（Zhou et al., 2025, P9）提出多平台 GUI 定位综合基准，涵盖多样化定位任务，用于系统性评估 MLLM 的代理能力。该基准包含基本和高级定位任务，揭示了模型在抽象语义概念和空间定位上的弱点。通过分层评估协议，VenusBench-GD 提供了更细粒度的性能分析，帮助识别模型在不同任务类型上的表现差异。

随着交互类型的扩展，基准构建也向复杂操作和垂直领域延伸。DragOn（Bout et al., 2026, P22）提出基于拖拽的 GUI 交互基准和数据集，评估模型在执行拖拽、调整大小和旋转等复杂交互时的定位精度。该基准包含四种任务类型，每种 250 个示例，验证集公开，测试集私有用于跨模型比较。通过设置严格的容差（如目标边界框尺寸的 5%），DragOn 区分了模型在精确意图理解上的能力。MedSPOT（Shakeel et al., 2026, P15）则针对临床 GUI 环境，评估模型在医疗软件中的多步定位能力，揭示了通用多模态模型在结构化临床界面中的严重性能退化。这些新基准填补了复杂交互与垂直领域的空白，暴露了现有模型在长程依赖和领域特定知识上的缺陷，为后续方法研究提供了明确的改进方向。

### 2.5 界面感知与解析

界面感知与解析路线研究对 GUI 界面结构、元素语义及状态变化的深层理解，包括完整屏幕解析、控件检测及界面状态转换推理。该路线超越了单纯的坐标预测，旨在为下游规划任务提供更丰富的语义上下文。ScreenVLM（Gurbuz et al., 2026, P14）基于文档转标记 VLM 架构，将截图转换为序列化的结构化屏幕表示（ScreenTag），实现完整屏幕解析。该方法利用轻量级解码器生成结构化输出，增强了模型对界面元素角色和空间关系的理解。通过标准自回归训练，模型学习将图像编码为少量视觉 Token，条件化解码器生成结构化输出。这种设计避免了重型新架构，利用预训练检查点的归纳偏置，自然迁移到 UI 领域。

UI-UG（Yang et al., 2025, P3）则提出统一的 MLLM 用于 UI 理解和生成，通过多任务学习增强模型对界面结构和语义的综合能力。该方法结合 UI 理解（如元素定位、布局解析）和 UI 生成（如代码生成、设计评估）任务，利用共享的多模态表示提升整体性能。在定位任务中，使用 GRPO 奖励函数，结合 IoU 奖励和格式奖励，优化模型输出。方法强调理解与生成的协同，通过多任务训练提升模型对 UI 动态的把握。与 ScreenVLM 侧重于结构化解析不同，UI-UG 侧重于理解与生成的统一框架，两者在界面感知的深度与应用广度上形成了互补，共同推动了 GUI 智能体从“能点击”向“懂界面”的演进。

### 2.6 跨任务与多领域应用

GUI 定位技术正从单一的点击任务向拖拽、文本选择、滑块操作等复杂交互扩展，并深入医疗、金融等垂直领域。Beyond Clicking（Liao et al., 2025, P11）提出通过文本拖拽迈向通用 GUI 定位的研究，将定位任务从单点点击扩展到坐标对预测。该方法聚焦于文本拖拽能力，要求模型预测起始和结束坐标，以执行文本选择操作。通过研究拖拽任务，揭示了模型在空间关系理解和多坐标预测上的挑战。GUIrilla（Garkot et al., 2025, P5）则提出可扩展的桌面 UI 自动探索框架，旨在解决桌面环境缺乏统一结构表示和数据收集困难的问题。该方法针对 macOS 等缺乏虚拟支持的平台，设计了专门的自动化工程，可靠地解析和交互。通过构建层次树结构，记录 UI 状态、可访问性树和截图，GUIrilla 实现了大规模桌面 UI 数据的自动收集。这些工作不仅扩展了 GUI 定位的任务定义，也丰富了训练数据的来源，推动了跨平台 GUI 智能体的发展。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

纯视觉驱动方法优于依赖结构化元数据（如 HTML/无障碍树）的方法，这一共识在约 30 篇论文中得到共同支持。其核心依据在于纯视觉方法具有更好的平台通用性和鲁棒性，摆脱了不同操作系统结构差异带来的限制。ScreenSpot-v2 上 GUI 专用模型（如 UI-TARS-7B 的 89.5%）对通用模型（GPT-4o 的 18.3%）的压倒性优势，以及 ScreenSpot-Pro 上专用模型（GUI-AIMA-3B 的 61.5%）对通用模型（GPT-4o 的 1.4%）的巨大差距，均验证了纯视觉范式在细粒度感知上的有效性。与此相关的另一个共识是，测试时缩放（Zoom-in）和迭代裁剪是提升高分辨率界面定位精度的有效且无需训练的策略，约 15 篇论文共同支持。GUI-Spotlight 和 DRS-GUI 等方法通过迭代聚焦显著提升了 4K 屏幕下的定位精度，证明了该策略在缓解小目标混淆问题上的普适性。

强化学习（RL）结合基于规则的奖励函数能显著提升模型在复杂场景下的定位性能，且数据效率高于纯监督微调，这一共识由约 12 篇论文支持。UI-R1 和 GUI-C² 等工作展示了 RL 在低资源场景下的高效性，为 GUI 智能体提供了超越监督微调的训练新路径。指令的清晰度和具体性直接决定定位成功率，模糊指令需通过细化或推理转化为视觉特征描述，约 10 篇论文共同支持。UI-Ins 的实验表明，结构化指令推理比自由 CoT 更有效，验证了指令语义在定位任务中的核心作用。模型内部注意力机制蕴含丰富的空间定位信息，可作为坐标预测的替代或辅助信号，约 8 篇论文支持。GUI-Actor 等无坐标定位范式展示了注意力图在空间相关性表达上的优势，为坐标生成提供了新的架构思路。

### 3.2 观点分歧

推理机制的选择是当前领域的主要分歧之一：自由形式思维链 vs 结构化指令推理。观点 A 认为自由形式 CoT 能增强模型的空间推理能力，早期部分 RL 工作持此观点；观点 B 认为结构化指令推理（Instruction-as-Reasoning）更有效，自由 CoT 可能引入噪声，UI-Ins（Chen et al., 2025, P6）持此观点。UI-Ins 实验表明，在 ScreenSpot-Pro 上，结构化推理比自由 CoT 性能更稳定。证据强度中等，主要基于特定数据集的对比实验。分歧根源在于缺乏统一的评测协议来分离“推理深度”与“指令清晰度”的贡献，不同模型架构对 CoT 的敏感度不同，需更多跨架构实验。

坐标表示的离散性与连续性是另一个根本性争论：离散文本 Token vs 连续注意力/回归头。观点 A 认为离散文本 Token 兼容现有 LLM 架构，易于微调，是主流方法；观点 B 认为离散化导致量化误差，应使用注意力图或连续回归头，GUI-Actor（2025）等无坐标范式持此观点。GUI-Actor 展示了无坐标定位的可行性，但在复杂布局下的泛化能力尚未经过大规模基准（如 ScreenSpot-Pro）的严格验证。证据强度较弱，多为概念验证。分歧根源在于连续坐标生成与 LLM 自回归解码机制存在根本冲突，如何高效集成连续回归头而不破坏语言模型特性仍是技术难题。

### 3.3 其他开放问题

最紧迫的工程问题是推理效率与精度的权衡。高精度定位往往需要多次推理或高分辨率输入，导致延迟增加，当前研究致力于通过视觉 Token 剪枝和高效裁剪策略优化推理速度。FocusUI（Ouyang et al., 2026, P10）和 ZonUI-3B（2026, P28）分别从推理和训练阶段入手，降低了计算成本，但在极端高分辨率（4K+）和复杂交互（拖拽）场景下，小模型的迭代推理是否仍能保持精度优势尚待验证。最根本的研究问题是复杂交互序列的状态理解缺失。现有方法多关注单步点击，缺乏对界面状态转换和长程依赖的理解，导致多步任务中错误累积，需结合状态预测和轨迹学习。MedSPOT（Shakeel et al., 2026, P15）和 DragOn（Bout et al., 2026, P22）等基准的发布揭示了这一缺陷，但现有模型在长时序工作流中的状态漂移问题仍未解决。

已知的是，纯视觉范式、测试时缩放和 RL 数据效率已成为领域共识；争议的是推理机制的具体形式和坐标表示的离散/连续选择；未知的是如何在资源受限条件下实现鲁棒、可解释且具备风险感知能力的 GUI 定位，以及如何在长时序交互中保持状态一致性。未来发展趋势将从单步点击向多步顺序交互演进，从云端大模型向端侧高效部署扩展，从静态截图理解向动态界面状态预测深化。

## 4. 总结与展望

GUI 定位领域的核心矛盾在于多模态大语言模型缺乏原生空间感知能力与 GUI 智能体对高精度、低延迟、高可靠性定位需求之间的张力。从依赖结构化元数据到纯视觉驱动，再到推理增强与不确定性量化，研究路线经历了三次范式跃迁，但核心瓶颈仍未完全解决：高分辨率下的细粒度感知模糊、坐标生成的离散性误差、以及复杂交互序列中的状态漂移。这些瓶颈限制了 GUI 智能体在高风险、高复杂度场景中的可靠部署。

未来可能突破的方向包括：一是从单步点击定位向多步顺序交互与状态感知定位演进，通过引入时序依赖建模和状态空间逻辑，结合强化学习或序列监督提升持续交互的鲁棒性，这一方向由 MedSPOT 和 DragOn 等基准的发布共同指向；二是实现训练-free 或低资源的高效推理增强，探索基于不确定性量化、注意力重校准和工具增强感知的推理时优化策略，在不增加训练数据的前提下提升定位精度，这一方向由 SafeGround 和 FocusUI 等工作共同指向。对于进入该领域的研究者，最值得做的一件事是在统一骨干网络与统一预训练数据条件下，系统性地评测不同推理增强策略（如结构化指令推理 vs 自由 CoT）在高分辨率基准（如 ScreenSpot-Pro）上的性能差异，以剥离模型规模效应，明确推理机制本身的贡献。
