综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/Prompt%20Engineering%20and%20Optimization)

## 导读

提示词工程（Prompt Engineering）旨在通过设计自然语言输入引导大语言模型（LLM）产生预期输出，其核心价值在于以零参数更新的方式适配新任务。早期研究依赖思维链（Chain-of-Thought, CoT）等启发式技巧激发推理能力，但人工设计面临主观性强与不可扩展的瓶颈。随着自动优化框架的出现，提示词被重构为可学习的离散变量，然而这一转变暴露了模型对表面形式的高度敏感性。为应对鲁棒性危机，研究重心转向形式化与系统化，提出声明式语言与跨模型迁移机制。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前多元并存的方法格局。本综述梳理这条从几何度量到语义先验的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

提示词工程的兴起源于大语言模型从静态参数调整向动态自然语言交互的范式转移。在上下文学习（In-Context Learning, ICL）范式确立后，提示词成为连接用户意图与模型能力的唯一控制接口，其设计质量直接决定了下游任务的性能上限。早期研究聚焦于通过少样本（Few-Shot）和思维链等启发式技巧激发模型推理能力，核心假设是精心设计的文本能线性引导模型内部推理。然而，这种“人工艺术”式的方法存在显著瓶颈：设计过程主观性强、难以规模化，且对模型版本更新极度敏感。当模型架构从解码器-only向更复杂的注意力机制演进时，提示词中微小的措辞或顺序变化往往导致性能剧烈波动，这一现象被称为提示词敏感性（Prompt Sensitivity）。

问题定义的演化并非线性，而是随着约束条件的变化而重构。2022-2023年，随着自动提示优化（Automatic Prompt Optimization, APE）框架的出现，问题从“如何写好提示”转变为“如何算法化地搜索最优离散变量”。这一阶段将提示词视为代码，利用进化算法或文本梯度进行迭代优化。然而，自动化搜索在提升峰值性能的同时，加剧了提示词对特定训练分布的过拟合，导致在未见数据上的泛化能力下降。2024-2025年，研究重心转向鲁棒性，揭示出因果注意力机制对提示词顺序的依赖以及语义欠定（Underspecification）导致的性能波动。此时，问题进一步演化为“如何构建抗漂移、语义等价的稳定提示”。

子问题之间存在强依赖关系，构成了领域的认知边界。提示词敏感性是自动化优化的主要障碍，因为黑盒搜索往往陷入局部最优，产生“脆弱”的提示词；形式化与编程则是解决敏感性与跨模型迁移的潜在终极方案，通过结构约束消除歧义；人机交互则是形式化落地的用户侧接口。这种依赖关系决定了方法路线的取舍：追求性能上限的自动优化路线往往牺牲鲁棒性，而追求可验证性的形式化路线则牺牲自然语言的灵活性。当前，领域正迈向系统工程化，致力于构建可复用、可验证、抗漂移的提示词基础设施。

**如果用一个核心问题概括该领域，那便是：如何在自然语言的固有歧义性与LLM内部表示的表面形式依赖之间，构建一种既具备人类可读性又具备机器可验证性的提示词控制接口，以实现跨模型、跨任务的稳定行为引导。**

## 2. 方法体系

- 2020：Few-Shot Learning——奠定上下文学习基础范式

- 2022：APE (Automatic Prompt Engineer)——开创自动化提示搜索先河

- 2023：PromptBreeder——实现提示词的自动演化

- 2024：TextGrad——定义文本梯度驱动迭代修订

- 2025：UCL (Universal Conditional Logic)——提出形式化提示语言

- 2026：TextReg——缓解提示分布过拟合问题

这条时间线勾勒了该领域方法演进的代表性节点：从 2020 年的 Few-Shot Learning 奠定该领域方法基线，经 2022 年 APE (Automatic Prompt Engineer) 的推进，到 2026 年的 TextReg 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 自动提示优化

自动提示优化路线旨在替代人工试错，将提示词视为可学习变量进行黑盒搜索。该路线的奠基工作 APE（Zhou et al., 2022, P25）利用 LLM 生成并迭代优化自然语言指令，开创了自动化提示搜索的先河，其核心取舍在于放弃人工直觉以换取自动化效率，但导致提示词对特定措辞过拟合。针对 APE 在复杂任务中泛化能力不足的问题，TextGrad（Yuksekgonul et al., 2024, P35）借鉴深度学习优化思想，定义文本梯度以驱动提示词的迭代修订，实现了黑盒 LLM 的高效自动优化，其代价是依赖外部评估器的准确性，且优化过程缺乏因果解释。

为进一步提升优化效率与多目标平衡，GEPA（P25）结合遗传算法与帕累托前沿优化，在多维目标下搜索最优提示，实现了提示优化的多目标平衡与高效收敛。然而，黑盒优化普遍面临可解释性不足的缺陷，Causal-Inspired Edit-Level Analysis（Gong and Wen, 2026, P35）引入因果推断框架，量化特定编辑特征对性能提升的贡献，区分相关性与因果性，为设计更有效的自动化优化策略提供了理论指导。此外，RGoT（Riesen and von Niederhäusern, 2026, P34）将图思维范式与强化学习结合，实现提示结构的自适应生成与优化，提升了复杂推理任务的自动化水平，其代价是训练策略网络需要大量交互数据。

| 方法 | 年份 | 核心机制 | 优势 (Gain) | 劣势 (Cost) |
| :--- | :--- | :--- | :--- | :--- |
| APE | | 迭代生成与评估 | 自动化效率 | 过拟合特定措辞 |
| TextGrad | | 文本梯度优化 | 高效黑盒优化 | 缺乏因果解释 |
| GEPA | | 遗传-帕累托优化 | 多目标平衡 | 计算复杂度增加 |
| RGoT | | 强化学习策略 | 自适应结构生成 | 训练数据需求大 |

### 2.2 提示敏感性与鲁棒性

提示敏感性与鲁棒性路线旨在诊断并缓解模型对提示词微小变化的依赖。该路线的早期工作 PromptBench（P42）建立了统一的提示敏感性评估基准，系统量化了措辞、格式等微小变化对模型输出的影响，揭示了 LLM 行为的脆弱性。针对训练时策略的局限性，Prompt-Robust Training（Sadrieh and Štefánik, 2026, P42）探索多样化提示训练以构建提示不变性，其核心发现是现有方法虽能提升平均性能，但无法完全消除最佳与最差提示间的性能差距。

为深入理解敏感性机制，Causal Attention Limitation Analysis（Ok and Lee, 2026, P17）揭示因果注意力机制在多选问答中的信息瓶颈问题，指出 QOC 顺序中因果掩码阻止选项 token 关注上下文，从而降低性能。Shared Lexical Task Representations（Yang et al., 2026, P29）通过激活补丁实验发现共享词汇任务头在正确与错误答案中的激活差异，将行为敏感性追溯到内部表示层面。在优化层面，TextReg（Fu et al., 2026, P33）引入正则化文本空间优化，通过分解任务梯度与正则化信号，缓解提示分布过拟合问题，增强提示在未见数据上的稳定性，其代价是正则化强度的选择需要额外调参。

### 2.3 提示词形式化与编程

提示词形式化与编程路线旨在将提示词提升为具备类型系统与编译特性的代码单元。该路线的奠基工作 DSPy（Khattab et al., 2023, P26）提出声明式编程模型，将提示工程抽象为模块化的优化问题，支持自动合成、测试和修订指令，实现了提示的可复现与可组合。针对 DSPy 在复杂逻辑控制上的局限，UCL（Mikinka, 2025, P16）提出形式化提示语言，引入指示函数机制和结构开销验证，将提示工程提升为具备编译特性的编程范式，其核心是定义通用提示方程，通过 Lagrangian 优化平衡提示质量与结构复杂度。

为增强提示的结构化与安全性，LLMON（Hind et al., 2026, P24）设计 LLM 原生标记语言，利用结构和语义增强 LLM 接口，明确区分指令、数据和角色，解决自然语言提示中边界模糊的问题。NIGHTJAR（Cheng et al., 2025, P14）提出统一提示与程序状态的框架，实现自然语言编程与精确计算的互操作，允许 LLM 代理直接访问和修改程序状态，减少幻觉。PromptMN（Dovdon, 2026, P36）设计伪提示编程语言，定义关键词集与功能簇，通过显式语法约束模型行为，解决自由文本提示的歧义与不可复现问题。

### 2.4 提示词结构与设计原则

提示词结构与设计原则路线旨在探索提示词的内部结构及其对模型行为的影响。该路线的早期工作 CoT（Wei et al., 2022, P34）通过引入中间推理步骤的提示策略，显著提升了 LLM 在算术和符号推理任务上的表现，成为后续复杂推理提示设计的基石。针对 CoT 在复杂逻辑问题上的局限，Tree-of-Thoughts（Yao et al., 2023, P34）将推理过程建模为树状搜索结构，支持分支探索与回溯，扩展了线性 CoT 的局限性。

为标准化提示设计，PICCO Framework（Cook, 2026, P28）提出包含 Persona、Instructions、Context、Constraints、Output 的结构化提示架构，为提示设计提供了标准化的参考模板。针对提示欠定问题，Underspecification Management（P43）借鉴软件工程需求工程方法，通过需求验证器识别提示中的模糊行为，建立需求与验证器的闭环，确保提示覆盖所有关键行为边界。此外，Emotional Stimuli Analysis（Patel et al., 2026, P27）量化情感强度，揭示适度情感可提升真实性，但极端情感可能损害准确性，丰富了提示结构的非语言要素研究。

### 2.5 人机交互与提示辅助

人机交互与提示辅助路线旨在降低非专家用户的提示设计门槛。该路线的早期工作 PromptPilot（Gutheil et al., 2025, P4）构建交互式界面，辅助用户生成和优化提示，提供实时反馈和建议，降低非专家用户的提示设计门槛。针对用户意图模糊问题，DiscoverLLM（Kim et al., 2026, P19）提出从执行意图到发现意图的训练框架，利用用户模拟器生成合成对话，通过奖励函数优化模型，使其能主动发现用户潜在意图。

为提升提示的多样性与创意性，PromptHelper（Kim et al., 2026, P18）构建提示推荐系统，基于语义多样性生成上下文相关的后续提示建议，辅助非专家用户探索创意空间并澄清意图。Data-Prompt Co-Evolution（Lee and Kahng, 2025, P6）提出数据与提示协同演化方法，通过增长测试集来细化 LLM 行为，将提示工程视为持续迭代过程，解决“未知未知”问题。

### 2.6 提示词安全与对抗

提示词安全与对抗路线旨在研究提示词在安全场景下的应用。该路线的早期工作 Diffusion LLM Adversary（Lüdke et al., 2025, P11）利用扩散语言模型作为生成先验，通过条件采样高效生成对抗性提示，实现了针对黑盒 LLM 的低成本越狱攻击。针对系统提示遵循问题，SyRuP（Kim et al., 2026, P38）提出通过奖励引导预测增强系统提示遵循的方法，在解码阶段利用奖励模型预测，引导生成过程严格遵循系统提示约束，提升行为一致性。

为量化提示价值，LLM-Relative Kolmogorov-Complexity（Pass, 2026, P41）提出基于 LLM 相对柯尔莫哥洛夫复杂度的提示价值评估方法，定义提示对最终产物的贡献为算法互信息，利用 Levin 复杂度衡量提示的信息增益，量化提示的经济价值。

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

提示词设计是决定 LLM 下游任务性能的关键因素，其重要性不亚于模型架构或参数规模，这一共识在多个基准上被反复验证：GEPA 的 100.00 与 EGO-Prompt 的 12.61 F1 Gain 均大幅超越手工基线（支撑证据：P25、P9）。与此相关的另一个共识是 LLM 对提示词的微小变化表现出高度敏感性，这种敏感性是系统部署的主要可靠性风险，PromptBench 的系统性评估揭示了措辞、格式等微小变化对模型输出的显著影响（支撑证据：P42）。

### 3.2 观点分歧

黑盒自动优化与白盒形式化设计哪种范式更适合复杂系统，是领域内的核心分歧。黑盒优化路线（如 TextGrad）认为自然语言的丰富性使得形式化语法难以覆盖所有创意场景，能发现人类意想不到的“魔法提示”；而白盒形式化路线（如 UCL）认为黑盒优化产生的提示是“黑箱”且“脆弱”的，形式化语法提供可验证性、可组合性与长期可维护性。现有证据偏向形式化在“约束满足”与“跨模型迁移”上的优势（UCL 100% Constraint Satisfaction vs. 黑盒的波动），但在“开放生成”与“创意任务”上，黑盒优化仍具竞争力。这一分歧的背后，是另一个更根本的争论：鲁棒性的来源是模型内在不变性（训练时）还是提示外在正则化（推理时）？训练时方法（如 Prompt-Robust Training）能提升平均性能，但无法完全消除极值差距；推理时方法（如 TextReg）能缓解过拟合，但可能牺牲峰值性能。现有证据强度较弱，因为两者常结合使用，难以单独归因。

### 3.3 其他开放问题

最紧迫的工程问题是提示词工程的可扩展性与标准化缺失，缺乏统一的提示词语法和版本控制机制，导致工程实践碎片化。声明式提示词语言和治理框架（如 UCL、PromptMN）正在填补这一空白，但用户接受度与学习成本仍是主要障碍。最根本的研究问题是提示敏感性的机制解释与内部表示分析，深入理解 LLM 为何对提示措辞敏感，特别是从注意力机制和内部表示层面。难点在于黑盒模型内部状态的可解释性有限，潜在路径包括研究词汇任务头、因果注意力限制以及提示对嵌入空间的重塑效应。已知的是提示词是性能关键变量且存在敏感性风险，争议的是优化范式与鲁棒性来源，未知的是敏感性的内部机制与跨模型迁移的理论基础。发展趋势是向形式化基础设施演进，构建可复用、可验证、抗漂移的提示词工程体系。

## 4. 总结与展望

提示词工程领域的核心矛盾在于自然语言的固有歧义性与 LLM 内部表示的表面形式依赖之间的张力。从启发式技巧到自动优化，再到形式化基础设施，各路线在表示质量、适应效率与计算成本之间做出了不同取舍。当前核心瓶颈在于缺乏统一的“提示语义等价”度量，导致跨模型比较困难，且模型更新频繁导致结论时效性短。未来可能突破的方向包括：跨模型提示迁移与鲁棒性（如 PromptBridge、NLD-P），解决提示在模型更新或切换时性能下降的问题；提示分布外泛化与过拟合缓解（如 TextReg），解决提示优化过程中对训练数据过拟合导致在未见任务上性能下降的问题；提示敏感性的机制解释与内部表示分析（如 Shared Lexical Task Representations），深入理解 LLM 为何对提示措辞敏感。对于进入者，最值得做的一件事是构建统一的“提示语义等价”度量基准，以解决跨模型比较困难的问题，为领域提供标准化的评估工具。
