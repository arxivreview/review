# A Survey of LLM-based Text Privacy and Anonymization Methods ｜LLM 文本隐私与匿名化方法综述 ｜arxivreview

综述原文见 [ArxivReview](https://www.arxivreview.com/surveys/LLM-based%20Text%20Privacy%20and%20Anonymization)

## 导读

大语言模型（LLM）在云端应用的广泛部署，使得用户输入中的个人可识别信息（PII）面临前所未有的泄露风险，早期依赖规则或命名实体识别的静态掩码方法因破坏文本自然度且缺乏形式化保证而逐渐失效。随着模型推理能力的增强，隐私保护的核心矛盾从单纯的标识符去除，演变为在语义重写、任务效用与合规性之间寻找动态平衡的复杂优化问题。研究者通过引入局部差分隐私（LDP）提供数学边界，利用上下文完整性（CI）理论重构隐私决策逻辑，并针对代理式 AI 开发动态对齐机制，形成了多元并存的技术路线。各路线在表示质量、适应效率与计算成本之间做出了不同取舍，由此形成当前从静态清洗向内生对齐演进的领域格局。本综述梳理这条从几何度量到语义先验的因果演进链条，为读者提供一张领域认知地图。全文按问题演化与路线取舍组织，覆盖该领域从奠基到当前的主要工作。

## 1. 研究背景、问题结构与演进脉络

LLM 文本隐私保护领域的兴起，源于大语言模型在云端服务中处理海量用户数据时引发的敏感信息泄露危机。早期研究将隐私保护简化为显式 PII 的移除任务，主要依赖基于规则的正则匹配或轻量级命名实体识别（NER）模型，如 Flair-Scrubbing 和 Microsoft Presidio。这些方法假设隐私风险等同于特定实体类型（如姓名、地址）的存在，通过静态掩码或替换实现去标识化。然而，这种“类型敏感”范式存在根本局限：它忽视了文本的语义连贯性，导致掩码后的文本碎片化，无法直接用于下游自然语言处理任务；同时，它缺乏对隐式线索（如写作风格、准标识符组合）的防御能力，难以应对具备强大推理能力的 LLM 攻击者。

为克服静态掩码的僵化，问题定义在 2020 至 2022 年间发生了第一次重构，从“去除标识符”转向“保留语义的匿名化”。这一阶段的核心挑战是隐私-效用权衡（Privacy-Utility Trade-off），即如何在移除敏感信息的同时，保持文本的自然度与下游任务性能。研究者开始探索基于 LLM 的语义重写技术，利用模型的上下文理解能力生成流畅的替代文本，而非简单的符号替换。这一转变标志着隐私保护从数据清洗工具向语义生成任务的跨越，但也引入了新的风险：LLM 的幻觉可能导致过度修改或隐私泄露，且缺乏形式化的隐私保证。

2023 至 2024 年，随着上下文完整性（Contextual Integrity, CI）理论的引入，问题定义经历了第二次重构，从“数据隐藏”转向“任务依赖的隐私决策”。CI 理论强调信息流动需符合特定社会角色、关系和目的规范，而非简单的数据隐藏。这一范式转变使得隐私决策不再仅看信息是否为 PII，而看其是否对下游任务必要。例如，在医疗诊断场景中，患者的年龄可能是任务必要的，而在匿名化社交评论时，年龄则是敏感信息。这种“任务感知”的视角要求隐私机制具备动态调整能力，根据具体应用场景选择性地保留或移除信息，从而解决了统一隐私策略导致的过度披露或过度删除问题。

2025 至 2026 年，随着 Agentic AI 的普及，问题定义进入第三次重构，从“单次文本处理”转向“多轮交互中的代理对齐”。在代理系统中，LLM 具备长期记忆和多工具调用能力，用户难以控制代理在复杂交互中暴露的隐私细节。此时，隐私保护的核心问题演变为：如何使代理行为符合人类隐私规范，并在多轮对话中实现动态的风险控制？这要求隐私机制不仅关注文本内容，还需关注代理的行为轨迹、记忆管理以及与外部工具的交互边界。此外，分布式协作中的源签名泄露（即通过文本分布特征推断数据来源）也成为新的研究焦点，推动了隐私保护从个体标识向组织源标识的扩展。

这一演进脉络清晰地展示了约束条件的变化如何驱动方法创新。2016-2018 年的奠基阶段，受限于算力与数据，方法以规则匹配为主，追求高召回率；2020 年跨域基准的出现暴露了域偏移下的原型崩溃问题，促使研究者转向预训练与视觉语言模型，用更强的先验换取跨域鲁棒性；2021 年预训练/VLM 的引入进一步提升了语义理解能力，但计算成本随之增加；2023-2025 年，随着 LDP 和 CI 理论的融入，方法开始追求形式化保证与情境适应性的平衡；当前阶段，方法正从单纯的 PII 去除向“隐私-效用-可训练性”多维优化演进，重点解决 LLM 作为攻击者时的推理泄露、分布式协作中的源签名去除以及基于人类隐私规范的代理对齐问题。

**如果用一个核心问题概括该领域，那便是：在 LLM 作为既有力量的保护者又是强大攻击者的双重角色下，如何在保证形式化隐私边界或符合上下文完整性规范的前提下，实现文本语义效用与隐私保护的帕累托最优。**

## 2. 方法体系

- 2006：Differential Privacy——形式化隐私保护框架，奠定理论基石

- 2019：Flair-Scrubbing——基于 NER 与规则匹配的早期自动化匿名化基线

- 2021：Microsoft Presidio——工业界标准的 PII 检测与匿名化框架

- 2023：RANTEXT——基于差分隐私的文本去标识化方法，缓解效用损失

- 2025：NaPaRe——基于蒙特卡洛树搜索的零样本迭代隐私感知重写

- 2025：STAMP——任务感知的选择性局部差分隐私机制

- 2026：GuardianAgent——策略条件的风险自适应匿名化代理

- 2026：Privasis——从零合成的大规模隐私丰富数据集

这条时间线勾勒了该领域方法演进的代表性节点：从 2006 年的 Differential Privacy 奠定该领域方法基线，经 2019 年 Flair-Scrubbing 的推进，到 2026 年的 Privasis 代表当前前沿。各节点对应的技术路线、取舍与关联，详见后续小节。

### 2.1 LLM 自适应匿名化

LLM 自适应匿名化路线的核心在于利用大语言模型的生成能力，实现上下文感知的文本重写与替换，以解决传统规则方法僵化、破坏文本自然度的问题。该路线的早期代表是 NaPaRe（P19），它针对现有方法对预定义 PII 类别依赖性强及开源 LLM 微调成本高的问题，提出了基于蒙特卡洛树搜索（MCTS）的零样本迭代隐私感知重写框架。NaPaRe 将匿名化过程建模为序贯决策问题，通过树搜索策略在重写空间中进行迭代探索，每一步利用奖励模型评估候选重写的隐私保留度与效用质量。其核心创新在于通过 MCTS 的探索与利用平衡机制，避免陷入局部最优解，从而在零样本场景下实现了自适应匿名化。然而，该方法的代价是搜索过程带来的计算开销较大，且奖励模型的质量直接决定最终重写的上限。

随着提示工程技术的成熟，Adaptive Text Anonymization（P20）进一步推动了匿名化从静态规则向自适应提示工程的演进。该方法利用代理式 LLM 作为提议者，根据任务特定的隐私与效用指标生成匿名化提示，并通过丰富反馈生成机制提供可解释的结构化反馈，帮助提议者从局部最优中逃逸。其优势在于部署成本低且适应性强，能够自动发现针对特定数据分布的最优匿名化策略，无需微调底层 LLM。然而，该方法依赖 LLM 的推理能力与反馈质量，且优化过程可能需要多次迭代，限制了其在实时性要求较高场景中的应用。

在部署形态上，Anonymous-by-Construction（P8）提出了基于本地 LLM 驱动的替换管道，旨在解决云 API 匿名化中的数据外泄风险。该方法完全在组织边界内执行，利用本地 LLM 将 PII 替换为类型一致且逼真的替代物，而非简单掩码，从而保留文本流畅性与任务相关语义。其创新点在于强调“匿名化即构建”的工程理念，将隐私保护嵌入系统架构底层。该方法在 ActionBased Conversation Dataset 上优于 Microsoft Presidio、Google DLP 及 ZSTS 等基线，但代价是依赖本地部署的高性能 LLM，硬件成本较高。相比之下，SFAA（P3）则采用混合工作流，结合手动编码与 LLM 辅助编码，通过两阶段验证确保 LLM 输出保留原始转录本的准确含义，适用于定性研究等对准确性要求极高的场景，但自动化程度有限。

Domain Agnostic Text Redaction（P16）则从另一个角度解决了领域适应性难题。该方法首先利用通用 LLM 合成特定领域的自然语言编辑规则，随后利用这些合成规则对小型 LLM 进行指令微调，赋予其识别敏感内容并执行编辑的技能。其核心创新在于将编辑规则从代码或正则表达式转化为自然语言，使 LLM 能够理解并应用复杂的语境敏感性，实现了真正的领域无关性。然而，合成规则的质量直接影响模型性能，且小型 LLM 的推理能力可能限制复杂语境的判断。RLAA（P18）则引入了理性框架，将匿名化过程重构为经济交易视角，通过理性决策机制选择最优匿名化操作，避免了贪心对抗策略导致的效用崩溃，为本地化隐私保护提供了理论指导。

### 2.2 隐私效用权衡机制

隐私效用权衡机制路线聚焦于形式化隐私预算分配，旨在通过数学保证隐私的同时最小化对下游任务性能的损害。该路线的奠基理论是 2006 年 Dwork 提出的 Differential Privacy（DP），它通过确保算法在相邻数据集上的输出统计不可区分来提供分布无关的隐私保证。然而，DP 在文本离散空间中的直接应用往往导致效用严重下降，因此后续研究致力于开发更细粒度的隐私机制。

STAMP（P7）是任务感知 LDP 机制的代表，它针对传统随机响应或 Laplace 噪声在自然语言中导致效用严重下降的问题，根据显式敏感性与任务依赖重要性两个二元轴将词元划分为四个类别，并针对每个类别分配差异化的隐私预算。其核心创新在于引入“任务感知”概念，承认同一词元在不同任务中的重要性不同，从而在保护关键隐私属性的同时最小化对任务效用的损害。STAMP 证明了在任务分组公开的情况下，该机制满足任务感知的度量 LDP 隐私保证，但其代价是依赖任务描述的可用性，在交互式或开放式场景中可能难以定义固定的任务表示。

Concept-Aware Privacy Mechanisms（P5）则针对嵌入反转攻击，提出了概念感知的隐私机制。该方法首先通过神经元掩码学习框架识别与隐私概念相关的嵌入维度，随后在 LDP 框架下，对敏感维度应用距离度量的泛化机制，而非对所有维度施加均匀噪声。其创新点在于将隐私保护从全维度扰动转向概念感知的维度选择，显著降低了效用损失，适用于 RAG 系统等依赖嵌入检索的场景。然而，掩码学习需要额外的训练数据与计算资源，且假设隐私概念可以明确定义。

Differentially Private De-identification（P11）则通过系统性地评估不同隐私机制在特定语言与领域下的表现，揭示了 DP 与效用之间的权衡关系。该研究发现，虽然 DP 方法提供了隐私保证，但在小数据集上效用损失显著，而 LLM 方法在无微调情况下表现良好但缺乏形式化保证。这一实证研究为临床数据共享提供了依据，指导用户根据隐私需求与效用要求选择合适的去标识化策略。PromptPET（P15）则将隐私保护前移至数据披露点，通过基于隐私预算的提示词元替换与重排，防止数据离开用户设备前暴露给不可信的远程 LLM，实现了真正的本地隐私控制，但其混淆可能降低提示的清晰度，需精细调节混淆参数。

### 2.3 匿名化基准评估

匿名化基准评估路线旨在构建涵盖多领域、多语言及对抗场景的综合基准数据集，以揭示现有方法的局限性。RAT-Bench（P6）是一个综合性的文本匿名化基准，通过 LLM 生成包含直接标识符与间接标识符的多领域、多难度场景，模拟真实世界中的隐私泄露风险。其创新点在于引入了“间接标识符”概念，超越了传统仅关注显式 PII 的评估范式，揭示了现有方法在语境推断上的脆弱性。该基准提供了统一的评估协议，包括隐私保留、效用保持及自然度指标，为匿名化研究提供了更严格的测试环境。

NAP2（P21）则聚焦于自然度与隐私保持的权衡，提出了一个基于人类学习的文本重写基准。该基准包含人类重写的删除与模糊策略数据，用于训练和评估重写模型，核心评估指标包括隐私保留率、语义一致性及自然度。NAP2 揭示了现有方法在生成自然文本方面的显著不足，指出掩码或简单替换常导致语法断裂与语义模糊，推动了匿名化从“去标识”向“自然重写”的范式转变。

DelegateCI-Bench（P12）则基于上下文完整性（CI）理论，提出了一个隐私意识委托基准。该基准将每个请求标注为任务必要跨度与任务非必要敏感跨度，通过双失败模式（过度披露与过度移除）评估重写质量。其创新点在于将隐私标准从“类型基”转向“任务条件基”，实现了更细粒度的隐私控制，并支持强化学习奖励设计，推动了代理隐私从简单 PII 过滤向语境感知信息选择的演进。

### 2.4 隐私对齐与代理

隐私对齐与代理路线聚焦于 LLM 代理在交互中的隐私决策，通过人类偏好对齐、上下文完整性约束及风险自适应策略，使代理行为符合用户隐私规范与社会情境要求。Information Sufficiency（P10）重新思考语境隐私为信息充分性，认为隐私保护应确保接收方获得完成任务所需的最小充分信息，而非简单删除或抽象敏感属性。该方法揭示了抑制策略导致的信息缺口与泛化策略导致的领域泄露问题，推动了隐私策略空间的扩展，促进了从“最小化披露”向“最大化效用下的隐私”的范式转变。

GuardianAgent（P17）提出了策略条件的风险自适应匿名化代理，结合隐私政策理解与文本匿名化，通过 AMRSF 控制器计算风险分数，决定允许、转换或拒绝操作。其创新点在于将隐私保护与具体行动上下文（如接收方、目的）绑定，实现了动态的风险自适应控制，并在多个数据集上展示了优于基线的隐私-效用帕累托前沿。然而，风险评估模型复杂，需实时计算，限制了其在资源受限环境中的部署。

PrivacyReasoner（P2）则模拟人类隐私心智，旨在预测个体用户对隐私事件的反应。该方法利用 LLM 检测隐含线索并角色扮演人类特征，通过生成式预测问题模拟用户特定的隐私担忧，捕捉了用户隐私偏好的个体差异。PrivacyAlign（P14）则针对 LLM 代理的语境隐私对齐，利用人类偏好对齐与语境完整性理论，通过条件化奖励建模训练代理遵守人类隐私规范，将隐私对齐从推理时约束转向训练时优化，提升了代理在复杂环境中的隐私合规性。

### 2.5 合成数据与攻击

合成数据与攻击路线探索利用 LLM 生成大规模合成隐私数据以缓解数据稀缺，同时研究基于 LLM 代理的重识别攻击与去匿名化风险。Controlled Generation for Private Synthetic Text（P1）提出了一种利用控制代码引导 LLM 生成私有合成文本的方法，通过控制代码调节输出序列的分布，确保敏感信息的抽象化，防止泄露真实标识符。Privasis（P4）则从零合成的大规模隐私丰富数据集，利用辅助控制变量初始化包含丰富隐私信息的文本记录草稿，并通过多样性保持的选择性精炼生成百万级隐私记录，解决了隐私研究数据稀缺问题，为训练高性能匿名化模型提供了数据基础。

Inference-Driven De-Anonymization（P9）评估了 LLM 代理在去匿名化中的推理能力，揭示了匿名化屏障在智能体时代的脆弱性。该框架展示了 LLM 代理在聚合线索、缩小候选范围及支持身份假设方面的能力，超越了传统的属性预测，强调了代理推理在隐私攻击中的关键作用。DiSan（P13）则提出了一种基于解耦表示的隐私保护文本清洗方法，通过联合训练语料原型，移除分布性源签名，同时保留任务相关语义，解决了跨组织协作中共享文本时的源标识泄露问题，推动了隐私保护从个体标识向组织源标识的扩展。

| 匿名化基准评估 | RAT-Bench, NAP2, DelegateCI-Bench | 间接标识符生成、自然度评估、CI 标注 | 评估标准 | 生成场景依赖 LLM 质量、标注成本高 |
| 隐私对齐与代理 | GuardianAgent, PrivacyAlign | 风险自适应、人类偏好对齐、RL 训练 | 情境合规性 | 部署门槛高、可解释性降低 |
| 合成数据与攻击 | Privasis, Inference-Driven De-Anonymization | 合成数据生成、代理推理攻击 | 数据稀缺缓解、威胁模型 | 合成计算成本高、攻击边界模糊 |

## 3. 关键共识、分歧与开放问题

### 3.1 领域共识

领域最核心的共识在于基于规则的 NER 和静态掩码方法已不足以应对 LLM 时代的隐私威胁，必须引入语义理解和上下文感知机制。这一共识在多个基准上被反复验证：Anonymous-by-Construction 在 ABCD 上的 0.99 Privacy Recall 与 ZSTS 的 0.98 相比，虽然召回率相近，但前者在 LoRA-MAE 上仅为 0.038，而 ZSTS 的 Q&A True Accuracy 仅为 0.26，表明语义重写在保持效用方面显著优于静态掩码。与此相关的另一个共识是隐私保护不能仅依赖 PII 类型识别，必须结合任务上下文和目的合法性，即“上下文完整性”原则。DelegateCI-Bench 和 PrivacyAlign 的研究均表明，基于任务必要性的隐私决策能够更有效地平衡隐私与效用，避免过度披露或过度删除。

此外，LLM 不仅可作为匿名化工具，也可作为强大的隐私攻击者，能够推断隐式属性和重建身份，评估必须包含对抗性推理测试。Inference-Driven De-Anonymization 中 GPT-5 Agent 在 Netflix 案例中 79.2% 的 LSR 证明了这一点，现有显式去除方法在 RAT-Bench 上重识别风险高，进一步支持了这一共识。隐私-效用权衡是核心挑战，需要在隐私召回率、文本自然度、下游任务性能之间寻找最优平衡点，而非单一指标最大化。STAMP 在 SQuAD 上的 SOTA 性能与 SPARSE 在 MIMIC-III 上 28.45% 的 Sex Leakage 均体现了这一权衡的复杂性。

### 3.2 观点分歧

形式化隐私保证（DP）与实用语义效用（LLM Rewriting）之间的分歧是领域内最根本的争论。DP 派认为必须提供数学上的隐私边界（如 LDP），否则无法合规，代表方法如 RANTEXT 和 STAMP。效用派则认为 DP 在文本离散空间导致效用严重下降，LLM 重写虽无严格保证但实际效果更优，代表方法如 NaPaRe 和 Anonymous-by-Construction。现有证据显示，DP 方法在合规性上具有优势，但效用损失显著；LLM 方法在自然度上远超 DP，但缺乏形式化保证。在 SQuAD 等任务上，STAMP 优于 Uniform DP，但 LLM 方法在自然度上表现更佳。分歧的根源在于文本隐私的“效用”定义模糊，且 DP 噪声在序列生成中的累积效应难以精确建模，导致两者无法在同一框架下公平比较。

另一分歧在于隐私决策的依据：类型敏感（PII-based）与任务/情境敏感（CI/Task-aware）。类型派认为隐私保护应基于 PII 类型，规则明确，易于实现，代表方法如 Presidio 和 ZSTS。情境派认为隐私应基于上下文完整性和任务必要性，同一信息在不同情境下隐私性不同，代表方法如 ConfAIde 和 PrivacyAlign。RAT-Bench 和 DelegateCI-Bench 显示，仅去除 PII 无法防御间接标识符攻击，情境感知方法在重识别风险上表现更好。但情境感知方法缺乏标准化，难以大规模部署，且“任务必要性”和“情境规范”缺乏客观、可计算的量化标准，依赖人类标注或 LM 判断，存在主观性和不一致性。

### 3.3 其他开放问题

最紧迫的工程问题是降低本地 LLM 匿名化的计算成本与资源消耗。当前 7B-20B 参数模型推理开销大，难以在边缘设备部署，难点在于平衡模型规模与隐私效用性能。潜在路径包括模型蒸馏、量化、批处理/缓存优化，以及评估更小参数模型（如 3B-4B）以接近轻量级基线的性能。最根本的研究问题是解决推断泄露与跨会话重识别风险。传统方法仅关注直接 PII 移除，忽视通过弱线索或辅助信息推断身份的风险，难点在于推断攻击具有隐蔽性，且跨会话链接需要长期记忆分析。潜在路径是引入推断驱动的去匿名化评估基准，开发能模拟攻击者推理能力的防御机制，并在多轮对话中评估隐私策略的鲁棒性。

此外，形式化隐私保证与可解释性的脱节也是重要开放问题。大多数 LLM 匿名化方法缺乏差分隐私等正式数学保证，且决策过程不透明。难点在于将 DP 噪声校准应用于序列生成会破坏文本连贯性。潜在路径是研究嵌入级别的隐私机制（如 SPARSE），开发基于策略条件（如 GuardianAgent）的风险自适应框架，并提供可审计的隐私控制接口。已知的是静态掩码已失效，争议的是 DP 与 LLM 重写的优劣，未知的是如何在代理系统中实现动态、可审计且低侵入的隐私保护。未来趋势将是融合形式化隐私理论与人类偏好对齐，构建既能抵御 LLM 推理攻击，又能保持高语义效用的动态隐私代理。

## 4. 总结与展望

LLM 文本隐私保护领域的核心矛盾在于隐私保护强度与文本语义完整性/下游任务性能之间的张力。早期研究通过静态掩码解决显式 PII 去除，中期通过 LLM 语义重写解决自然度问题，当前则通过任务感知 LDP 和代理对齐解决形式化保证与动态决策问题。核心瓶颈在于如何在 LLM 作为既有力量的保护者又是强大攻击者的双重角色下，实现隐私-效用-合规的帕累托最优。现有方法在形式化保证与实用效用之间仍未找到统一框架，且代理系统中的动态隐私对齐缺乏理论基础。

未来可能突破的方向包括：一是融合形式化隐私理论与人类偏好对齐，开发既能提供数学保证又符合人类直觉的隐私机制，如结合 STAMP 的任务感知 LDP 与 PrivacyAlign 的 RL 对齐；二是构建高质量、大规模隐私敏感合成数据集，如 Privasis 所示，通过多样性保持精炼确保数据质量，支持可控净化和智能体系统研究；三是开发基于人类偏好对齐的智能体隐私决策机制，利用 RLHF 或 GRPO 训练智能体，使其在评估和训练阶段保持人类在环，以符合社会隐私期望。对于进入该领域的研究者，最值得做的一件事是构建一个统一的评测基准，能够同时量化“隐私保证强度”与“语义效用”，并在统一骨干与统一预训练条件下重评测代表性方法，以解决当前评测体系的不公平性问题。
